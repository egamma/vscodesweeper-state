# Issue #1307 — Catching unhandled exceptions when starting language server by LanguageClient

[https://github.com/microsoft/vscode-languageserver-node/issues/1307](https://github.com/microsoft/vscode-languageserver-node/issues/1307)

## Summary

The reported startup rejections are now handled on main and in client 11.0.0. The Node client also exposes a stderr stream hook, covering the request to collect startup diagnostics without scraping the entire output channel.

## Change summary

Make initialization failures catchable without orphaned startup or cleanup rejections, and expose server stderr separately for failure diagnostics.

## Best solution

Treat the report as completed by the startup-promise fix and the failed-initialization cleanup fix at https://github.com/microsoft/vscode-languageserver-node/commit/49328700438f0f66ff228bb2eb8728b41d88aafc. Extensions can catch start() and collect stderr through LanguageClientOptions.stdioOptions.stderr rather than overriding stop() or extracting the whole output channel.
