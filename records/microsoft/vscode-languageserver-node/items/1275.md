# Issue #1275 — Tuple members should be optionally named 

[https://github.com/microsoft/vscode-languageserver-node/issues/1275](https://github.com/microsoft/vscode-languageserver-node/issues/1275)

## Summary

Optional tuple-member names remain unsupported in the meta model and its generator. Keep this team-authored, On Deck request open; the maintainer's question about consuming languages and a suitable representation remains unresolved.

## Change summary

Allow tuple members to carry optional semantic names, such as inclusiveStart and exclusiveEnd, in the generated protocol meta model.

## Best solution

Agree on an optional tuple-member naming contract for meta-model consumers, then support it consistently in tools/src/metaModel.ts, the TypeScript extraction and serialization path, and protocol/metaModel.schema.json. Preserve unnamed tuples and their existing wire representation.
