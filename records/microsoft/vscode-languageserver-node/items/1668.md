## Summary

Keep this open and route with depends on VS Code: the libraries delegate workspace edits to VS Code, and the discussion identifies editor/model disposal as the unresolved undo/redo boundary. No verified fix or canonical issue covers the reported unopened-document case.

## Change summary

Preserve redo after undoing a language-server workspace edit to an unopened document, including the reported loss after restarting VS Code with a non-active document.

## Best solution

Establish whether VS Code's workspace-edit undo/redo service loses redo when the affected text model is disposed, using equivalent edits through LSP and directly through vscode.workspace.applyEdit. Resolve the unopened-document behavior in microsoft/vscode and distinguish it from persistence across application restarts; retain this report until its full scope is accounted for.
