# Issue #440 — Add signatureHelp/resolve support, because signature help takes too long with multiple overloads

[https://github.com/microsoft/vscode-languageserver-node/issues/440](https://github.com/microsoft/vscode-languageserver-node/issues/440)

## Summary

Keep open with the existing depends on VS Code label: active-signature context now addresses the selection-preservation portion, but lazy documentation resolution when navigating overloads remains unsupported. The linked editor request was declined, not implemented; that does not justify a judgment close of this team-authored, accepted request.

## Change summary

Resolve documentation lazily for the selected signature instead of computing it for every overload, and preserve the user's selected overload when typing.

## Best solution

Retain activeSignatureHelp context for selection preservation, and have the maintainer decide whether to revisit the declined editor capability at https://github.com/microsoft/vscode/issues/65003. Full lazy resolution would require an agreed protocol contract in microsoft/language-server-protocol and corresponding client/provider and server support here; active-only documentation is a partial workaround, not completion.
