# Issue #1336 — Add support for `NotebookEdit` in `WorkspaceEdit`

[https://github.com/microsoft/vscode-languageserver-node/issues/1336](https://github.com/microsoft/vscode-languageserver-node/issues/1336)

## Summary

Keep this team-authored protocol tracking item open: current WorkspaceEdit types and conversion still cannot express notebook structural edits. The related VS Code formatting tracker explicitly leaves the LSP work here, and the protocol design remains unsettled.

## Change summary

Allow language servers to return notebook structural edits through WorkspaceEdit, including creating, deleting, and reordering cells.

## Best solution

Agree on notebook edit and cell-creation semantics, including preservation of existing cell state, with microsoft/language-server-protocol as the likely home for standardization; then implement the agreed contract in types/, protocol/, and client/ conversion. Coordinate formatting integration with https://github.com/microsoft/vscode/issues/204544 without conflating a new formatting provider with the broader workspace-edit capability.
