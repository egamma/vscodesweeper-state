# Issue #293 — activation onCommand leads to 'command x not found' if using executeCommandProvider

[https://github.com/microsoft/vscode-languageserver-node/issues/293](https://github.com/microsoft/vscode-languageserver-node/issues/293)

## Summary

Keep this accepted request open: the client still has no constructor-time command registration, which the maintainer proposed. Current VS Code waits for command-triggered activation, however, so returning or awaiting client.start() during activation should be evaluated before deciding what additional API is necessary.

## Change summary

Allow a server-provided command to execute successfully on the invocation that first activates its extension, rather than requiring a second invocation.

## Best solution

Establish the cold-activation behavior with current VS Code and an activation function that returns the client's startup promise. If early registration remains necessary, define client-side support in client/ that preserves server capability registration and command cleanup without requiring extensions to build their own forwarding feature.
