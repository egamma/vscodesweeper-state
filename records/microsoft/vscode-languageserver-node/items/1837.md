# Issue #1837 — Notebook dependent-cell diagnostic refresh is serialized at 500 ms per cell

[https://github.com/microsoft/vscode-languageserver-node/issues/1837](https://github.com/microsoft/vscode-languageserver-node/issues/1837)

## Summary

The dependent-cell delay remains directly traceable in current client source: each background pull waits 500 ms and completes before the next timer starts. Keep this open as a client performance bug; the related notebook-reordering issue and downstream upgrades do not resolve this scheduling defect.

## Change summary

Refresh diagnostics for dependent notebook cells promptly after a cell edit instead of accumulating a separate 500 ms delay per cell.

## Best solution

The diagnostic feature in client/ should refresh eligible dependent cells in the edited notebook without a per-cell timer penalty, while preserving ordinary background-document throttling and request lifecycle safeguards. The supplied integration reproduction provides a concrete acceptance threshold of ten dependent-cell pulls within one second.
