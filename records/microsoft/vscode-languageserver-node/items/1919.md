# Issue #1919 — A server that dies during a write is never restarted: the writer's stream error has no count, and closed() is skipped while stopping

[https://github.com/microsoft/vscode-languageserver-node/issues/1919](https://github.com/microsoft/vscode-languageserver-node/issues/1919)

## Summary

The current source still permits a write-side transport error to permanently stop the client instead of restarting the crashed server. Keep this open: the linked open PR improves body-write error reporting but explicitly leaves the reported restart failure unresolved.

## Change summary

Restore automatic server restart when a server crashes during a client write, while preserving explicit application shutdown and restart limits.

## Best solution

Review https://github.com/microsoft/vscode-languageserver-node/pull/1946 as a partial improvement, and resolve the remaining interaction between JSON-RPC transport errors and language-client shutdown. A write-side server crash should reach the normal restart policy without making an application-requested stop restart the server.
