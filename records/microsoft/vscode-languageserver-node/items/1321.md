[https://github.com/microsoft/vscode-languageserver-node/issues/1321](https://github.com/microsoft/vscode-languageserver-node/issues/1321)

## Summary

Keep open as an accepted Bun runtime-support request. Existing launch options allow alternative executables and the thread reports stdio success, but neither establishes complete Bun compatibility; no verified implementing commit or open duplicate was found.

## Change summary

Support running JavaScript language servers under Bun from the VS Code language client.

Establish a supported Bun configuration and compatibility boundary across client launching, server initialization, JSON-RPC transport, and shutdown. ## Plan brief

- **Likely files:** `client/src/node/main.ts`, `server/src/node/main.ts`, `jsonrpc/src/node/main.ts`, `client-node-tests/src/integration.test.ts`, `client-node-tests/src/servers/startStopServer.ts`
- **Validation:** In a writable implementation checkout with a specified Bun version, launch the startStopServer fixture through the VS Code client using NodeModule.runtime and stdio; require initialize, foo.command execution, shutdown, and process exit to complete within explicit timeouts. Repeat with IPC if included in the agreed support contract, and retain passing Node.js transport and lifecycle checks.
- **Behavior:**

  > Extension authors should be able to run a JavaScript language server under Bun while retaining VS Code language-client functionality. A supported configuration must initialize successfully, exchange requests and responses, and shut down without hanging or leaving the server process running. Acceptance should identify the supported Bun versions and transports and verify those configurations against a minimal server. Existing Node.js configurations must retain their behavior.
- **Trace:**

  > client/src/node/main.ts already accepts NodeModule.runtime and Executable.command, so choosing another executable is not itself the missing API. Its runtime branch constructs transport-specific arguments and uses Node-side stream or IPC adapters; the executable branch does not support IPC. server/src/node/main.ts:_createConnection selects the corresponding process streams or IPC adapters, and jsonrpc/src/node/main.ts implements IPC through message events and process.send. The stdio success reported in https://github.com/microsoft/vscode-languageserver-node/issues/1321 establishes only partial coverage; https://github.com/microsoft/vscode-eslint/issues/1709 records an initialization stall and explicitly delegates the general runtime issue here. No current Bun execution was attempted, so the precise incompatibility and whether it resides in these libraries or Bun remain unresolved. Preserve Node.js behavior and avoid treating application-specific ESLint or Vue failures as library defects without a minimal reproduction.
- **Open decisions:**
  - Does supported Bun operation require Node-compatible IPC, or is a documented stdio-only configuration sufficient for the initial support contract?
