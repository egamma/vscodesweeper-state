# Issue #1879 — Re-registering file watchers with the same ID will leak the previous registration

[https://github.com/microsoft/vscode-languageserver-node/issues/1879](https://github.com/microsoft/vscode-languageserver-node/issues/1879)

## Summary

The current client still loses ownership of the previous watchers when a registration ID is reused, leaving their watchers and listeners active. Keep this team-authored issue open: the resource leak is confirmed independently of the unresolved reject-versus-replace contract.

## Change summary

Prevent repeated dynamic file-watcher registrations with the same ID from leaking the previous watchers and listeners.

## Best solution

Ensure client/ retains correct ownership and cleanup of every watcher when registration IDs collide. The maintainer should settle whether duplicate registrations are rejected or replace the existing registration; any broader protocol-contract clarification belongs in microsoft/language-server-protocol.
