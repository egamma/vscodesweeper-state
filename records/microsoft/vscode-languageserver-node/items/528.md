# Issue #528 — Client never sets `partialResultToken` and only sets `workDoneToken` during `initialize`

[https://github.com/microsoft/vscode-languageserver-node/issues/528](https://github.com/microsoft/vscode-languageserver-node/issues/528)

## Summary

Progress support has advanced since the report, but references and workspace symbols still do not request or consume partial results. Keep this accepted Backlog request open with its existing depends on VS Code label; the linked editor streaming request enables, rather than completes, the implementation here.

## Change summary

Wire request-scoped work-done progress and partial-result tokens into language-client features so servers can report progress and deliver results incrementally.

## Best solution

Retain the existing server-initiated work-done progress and workspace-diagnostic partial-result support, while distinguishing those from the remaining per-request integration. Coordinate references and workspace-symbol streaming with https://github.com/microsoft/vscode/issues/105870, then implement token allocation, progress handling, and incremental provider delivery in client/ as the editor API permits.
