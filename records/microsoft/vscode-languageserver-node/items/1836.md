# Issue #1836 — Notebook cell reordering does not invalidate pulled diagnostics

[https://github.com/microsoft/vscode-languageserver-node/issues/1836](https://github.com/microsoft/vscode-languageserver-node/issues/1836)

## Summary

The pure-reorder diagnostic invalidation gap remains in current client source: the notebook change handler neither pulls existing cells nor triggers dependency refresh when only structure.array changes. Keep this open as a client bug; the supplied regression test gives a concrete validation target.

## Change summary

Refresh pulled diagnostics after notebook cells are reordered without changing their text or document URIs.

## Best solution

Make the client's notebook diagnostic handling refresh affected existing cells after a structural reorder, following delivery of notebookDocument/didChange and respecting diagnostic pull configuration and provider matching. Keep the scheduler-performance work in https://github.com/microsoft/vscode-languageserver-node/issues/1837 separate; faster scheduling alone cannot supply the missing reorder trigger.
