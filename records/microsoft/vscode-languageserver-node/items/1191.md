# Issue #1191 — WorkDoneProgressCancelNotification is not using the given cancellation strategy

[https://github.com/microsoft/vscode-languageserver-node/issues/1191](https://github.com/microsoft/vscode-languageserver-node/issues/1191)

## Summary

Keep open: server-initiated progress cancellation still bypasses the configured cancellation strategy, leaving synchronous servers dependent on a custom workaround. This team-authored Backlog request has neither a verified implementing fix nor an open canonical owning the same work.

## Change summary

Allow cancellation of long-running commands through server-initiated progress to honor custom cancellation strategies, including shared-memory cancellation.

## Best solution

Establish a supported cancellation contract across client progress handling, server progress reporters, and JSON-RPC strategies so cancellation remains observable while a synchronous server is busy. Preserve ordinary notification-based progress cancellation and distinguish progress-token lifetime from request-id lifetime; adding a request cancellation token alone does not satisfy server-initiated progress cancellation.

## Evidence

- **current progress cancellation path:** client/src/common/progressPart.ts: ProgressPart.begin sends WorkDoneProgressCancelNotification with the progress token when the UI cancellation token fires. server/src/common/progress.ts: WorkDoneProgressServerReporterImpl constructs an ordinary CancellationTokenSource, and ProgressFeature cancels it only when its notification handler runs; neither path invokes the configured cancellation strategy.
- **request-oriented strategy boundary:** jsonrpc/src/common/connection.ts: CancellationSenderStrategy.enableCancellation accepts a RequestMessage, and request handling creates sources through CancellationReceiverStrategy. jsonrpc/src/common/sharedArrayCancellation.ts: SharedArraySenderStrategy associates buffers with request ids and embeds $cancellationData in requests; SharedArrayReceiverStrategy reads that request data. Supporting progress cancellation requires more than passing a string progress token to sendCancellation.
- **existing capability check:** client/src/common/client.ts exposes connectionOptions.cancellationStrategy, middleware.executeCommand, middleware.sendRequest, middleware.sendNotification, middleware.handleWorkDoneProgress, and sendRequest with a CancellationToken. These permit custom request cancellation or custom interception, but do not provide a built-in strategy-backed source for a server-created progress reporter. client/src/common/executeCommand.ts still sends ExecuteCommandRequest without a cancellation token.
- **discussion establishes the actual use case:** https://github.com/microsoft/vscode-languageserver-node/issues/1191#issuecomment-1432941179 explains that the goal is cancelling a running command through server-created progress, not independently cancelling progress while leaving the command running. https://github.com/microsoft/vscode-languageserver-node/issues/1191#issuecomment-1624444065 confirms the synchronous-server problem; https://github.com/microsoft/vscode-languageserver-node/issues/1191#issuecomment-1624483989 describes a custom dispatcher workaround, not a library implementation.
