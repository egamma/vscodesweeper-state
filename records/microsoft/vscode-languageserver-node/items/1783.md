# Issue #1783 — dynamic registration of watchedFiles does not respect files outside workspace

[https://github.com/microsoft/vscode-languageserver-node/issues/1783](https://github.com/microsoft/vscode-languageserver-node/issues/1783)

## Summary

Out-of-workspace watching is already supported through a relative glob pattern with an external baseUri. The reported string pattern uses VS Code's workspace-only watcher behavior; answer with the supported registration shape and close as a usage question.

## Change summary

Receive watched-file notifications for a configured file outside the opened workspace.

## Best solution

Keep the existing watcher API and register the external file with globPattern: { baseUri: "file:///home/outside-project", pattern: "watched-file.txt" }, retaining kind: 7. This uses the client's existing relative-pattern support without requiring a library or VS Code change.

- **Proposed comment:**

  > Thanks for the report. VS Code's file-watcher API limits string glob patterns to opened workspace folders, even when the string is an absolute path. For a file outside the workspace, use a relative-pattern object in your existing registration:
  > 
  > ```json
  > {
  >   "globPattern": {
  >     "baseUri": "file:///home/outside-project",
  >     "pattern": "watched-file.txt"
  >   },
  >   "kind": 7
  > }
  > ```
  > 
  > The language client already supports this form and converts the URI base into a VS Code `RelativePattern`, which enables watching outside the workspace. Use the external directory's URI string as `baseUri`; the workspace does not need to include that directory.
