# Issue #1398 — How to support CompletionItemKind#Color in LSP client completion?

[https://github.com/microsoft/vscode-languageserver-node/issues/1398](https://github.com/microsoft/vscode-languageserver-node/issues/1398)

## Summary

Keep this accepted request open and add depends on VS Code: the client already forwards Color completion items and their detail, but color-swatch rendering is delegated to VS Code. The maintainer-linked core issue is related, not a canonical that fully resolves the request for a reliable interpretation contract.

## Change summary

Clarify how clients should obtain the actual color represented by CompletionItemKind.Color and display a matching completion swatch.

## Best solution

Establish a reliable color-value contract rather than requiring clients to infer colors from names or arbitrary text, coordinating protocol guidance in microsoft/language-server-protocol with VS Code rendering. Follow https://github.com/microsoft/vscode/issues/166201 and https://github.com/microsoft/language-server-protocol/issues/2082 as related work, retaining this issue for any resulting client or protocol adoption.

## Evidence

- **Maintainer-established boundary:** https://github.com/microsoft/vscode-languageserver-node/issues/1398#issuecomment-1883064787 explains that VS Code itself interprets hexadecimal values in the completion detail property to render the swatch. https://github.com/microsoft/vscode-languageserver-node/issues/1398#issuecomment-1883128882 links the related core issue.
- **Existing capability check:** client/src/common/completion.ts: SupportedCompletionItemKinds includes Color, fillClientCapabilities advertises it, and CompletionItemFeature registers a VS Code completion provider. client/src/common/protocolConverter.ts:539-545 maps protocol kinds to VS Code kinds; asCompletionItem at lines 569-609 copies detail and kind without parsing color names or hexadecimal strings.
- **Middleware is only a workaround:** client/src/common/client.ts:340-373 includes CompletionMiddleware in Middleware and exposes LanguageClientOptions.middleware. client/src/common/completion.ts exposes provideCompletionItem and resolveCompletionItem hooks, which can modify the returned detail, but do not supply a dedicated color-value contract or control VS Code's swatch renderer.
- **Related core issue is not a duplicate:** https://github.com/microsoft/vscode/issues/166201 is verified open and concerns completion previews disappearing when mixed hex and non-hex variables are present. Fixing that rendering scenario would not by itself explain or standardize how arbitrary LSP clients obtain a completion's color value.
- **Related protocol proposal:** https://github.com/microsoft/language-server-protocol/issues/2082 is verified open and proposes standardizing a hexadecimal color at the end of completion documentation. It is related but uses documentation rather than the detail convention described here, and does not establish an adopted client implementation. types/src/main.ts:2310-2352 currently describes kind as selecting an editor icon and detail as human-readable additional information.
