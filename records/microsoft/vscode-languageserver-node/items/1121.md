# Issue #1121 — Reduce number of d.ts files and types published in packages

[https://github.com/microsoft/vscode-languageserver-node/issues/1121](https://github.com/microsoft/vscode-languageserver-node/issues/1121)

## Summary

The declaration-packaging gap remains: current publish configurations still emit declarations per source file, and the package excludes neither those declarations nor internal utility declarations. Keep this accepted On Deck request open; export restrictions and stripInternal provide partial protection, not the requested consolidation.

## Change summary

Consolidate published TypeScript declarations and expose a deliberately defined public API rather than declarations for every implementation module.

## Best solution

Provide compact, self-contained declaration entry points for the packages while preserving supported imports and public types. Start with vscode-languageclient's common, node and browser entry points, agree which exposed types are contractual, and measure declaration count and bytes before extending the approach to other modules.

## Evidence
