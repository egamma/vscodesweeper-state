# Issue #781 — Support for server->client batch requests?

[https://github.com/microsoft/vscode-languageserver-node/issues/781](https://github.com/microsoft/vscode-languageserver-node/issues/781)

## Summary

Batch-message support remains absent, and the maintainer explicitly accepted exploring it at the library level. Keep this accepted On Deck request open: the linked spec issue enables protocol support but does not own the implementation work here.

## Change summary

Support server-to-client JSON-RPC batch messages containing multiple requests and notifications.

## Best solution

Resolve the LSP compatibility contract alongside https://github.com/microsoft/language-server-protocol/issues/988, then implement the agreed batch handling in jsonrpc/ and any necessary client/server integration. Distinguish standalone JSON-RPC support from LSP adoption, since the subsequent spec clarification explicitly excludes batch messages.

## Plan brief

- **Likely files:** `jsonrpc/src/common/messages.ts`, `jsonrpc/src/common/connection.ts`, `jsonrpc/src/common/messageReader.ts`, `jsonrpc/src/node/test/connection.test.ts`, `client/src/common/client.ts`
- **Validation:** End the plan with runnable JSON-RPC connection tests covering one framed array containing multiple requests and notifications, dispatch of each member, response aggregation under the chosen contract, notification-only batches, and unchanged single-message behavior. If LSP adoption is included, define client/server compatibility checks against the agreed specification.
- **Behavior:**

  > A server sends multiple JSON-RPC requests and notifications in one transport payload, but the current connection does not dispatch the members. The desired enhancement is supported batch processing with explicit response semantics, while preserving existing single-message behavior. Acceptance must distinguish standalone JSON-RPC support from LSP use, because LSP currently excludes batch messages.
- **Trace:**

  > jsonrpc/src/common/messageReader.ts forwards a decoded payload directly to the connection callback. In jsonrpc/src/common/connection.ts, handleMessage tests the payload as one request, notification or response; the predicates in jsonrpc/src/common/messages.ts do not recognize arrays. LanguageClientOptions.middleware and connectionOptions.messageStrategy provide interception but not a complete native batch contract. The maintainer accepted library-level support in https://github.com/microsoft/vscode-languageserver-node/issues/781#issuecomment-868274031 while reserving the protocol decision. https://github.com/microsoft/language-server-protocol/issues/988 remains open, and https://github.com/microsoft/language-server-protocol/pull/1651 subsequently clarified that LSP excludes batch messages. Preserve ordinary dispatch, cancellation and response behavior; uncertainty starts at the intended public batch API and whether LSP adoption belongs in this change.
- **Open decisions:**
  - Should this enhancement provide standalone vscode-jsonrpc batch support only, or also include LSP client/server adoption contingent on a specification change?
  - What public sending and receiving contract should batch support expose, including how callers receive responses to multiple requests?

## Evidence

- **maintainer acceptance:** https://github.com/microsoft/vscode-languageserver-node/issues/781#issuecomment-868272998 explains that batch requests were deliberately omitted and expresses interest in supporting them. https://github.com/microsoft/vscode-languageserver-node/issues/781#issuecomment-868274031 accepts adding library-level support while leaving protocol compatibility unresolved. The feature-request label and On Deck milestone also record accepted work, barring a decline close.
- **current dispatch lacks batch support:** jsonrpc/src/common/messageReader.ts:252-253 forwards each decoded transport payload as one message. jsonrpc/src/common/connection.ts:766-775 dispatches that payload through Message.isRequest, Message.isNotification and Message.isResponse, otherwise invoking handleInvalidMessage. Those predicates in jsonrpc/src/common/messages.ts:509-528 inspect a single object's method, id, result or error; a JSON array of requests is not unpacked into its constituent messages.
- **existing-capability check:** client/src/common/client.ts:309-383 exposes per-feature middleware, general sendRequest/sendNotification middleware and connectionOptions.messageStrategy, but no native batch API. The messageStrategy hook can intercept dispatch; it does not itself supply JSON-RPC batch-response aggregation or an LSP interoperability contract, so it is not complete coverage of the request.
- **spec dependency is not a duplicate:** Verified https://github.com/microsoft/language-server-protocol/issues/988 is open and proposes request batching through transaction-like notifications or JSON-RPC batches. Shipping that specification work would still require implementation in this repository, and its motivating client-to-server optimization is not identical to this server-to-client report.
- **subsequent specification clarification:** https://github.com/microsoft/language-server-protocol/pull/1651 merged on 2023-01-27 and added an explicit statement to the LSP 3.18 specification that JSON-RPC batch messages are unsupported. This clarifies the conformance question but does not implement the accepted library enhancement or establish a later maintainer decision declining it.
- **canonical and PR search:** Read the linked spec discussion and searched repository issues using batch, batching, batch requests and JSON-RPC batch terminology. No other open issue owning this implementation request was identified; searches for referencing PRs and batch-request PRs found no open implementation candidate.
