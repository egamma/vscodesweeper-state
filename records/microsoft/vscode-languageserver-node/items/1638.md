# Issue #1638 — VS Code reports errors for semantic tokens that include newlines, should be stripped by the client?

[https://github.com/microsoft/vscode-languageserver-node/issues/1638](https://github.com/microsoft/vscode-languageserver-node/issues/1638)

## Summary

Keep open: the client still forwards token lengths unchanged, so the requested built-in truncation remains missing. The maintainer has identified performance as the next investigation, and neither the closed editor report nor the open specification clarification owns the remaining client work.

## Change summary

Truncate semantic tokens at the end of their starting line before forwarding them to VS Code, avoiding errors for LSP token lengths that include line endings.

## Best solution

Evaluate document-aware normalization in client/ across full, range and delta semantic-token responses, preserving result IDs and delta correctness while measuring per-token overhead. Retain the published single-line truncation behavior rather than requiring every extension to implement its own workaround.

- **No built-in truncation:** client/src/common/protocolConverter.ts:1424-1445 constructs SemanticTokens and SemanticTokensEdit objects by copying token arrays into Uint32Array. These conversions receive no document and do not alter token lengths.
