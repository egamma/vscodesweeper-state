# Issue #778 — Passing arguments to vscode command in code action from non-js language server

[https://github.com/microsoft/vscode-languageserver-node/issues/778](https://github.com/microsoft/vscode-languageserver-node/issues/778)

## Summary

Keep open: middleware supports extension-side argument conversion, but the requested built-in conversion remains absent. This team-authored Backlog request is protected from judgment closes, and the related open issues do not fully own its remaining work.

## Change summary

Allow non-JavaScript language servers to invoke VS Code navigation commands from code actions using JSON/LSP arguments without custom extension-side conversion.

## Best solution

Clarify the supported command and argument contracts in coordination with https://github.com/microsoft/language-server-protocol/issues/642 before deciding whether client/ should supply built-in adapters. Until then, retain middleware or custom command wrappers as workarounds, not as fulfillment of the automatic-conversion request.

- **Current conversion gap:** client/src/common/protocolConverter.ts:1000-1004, asCommand, copies item.arguments unchanged into the VS Code command. It does not reconstruct URI, position, or location arguments or specialize editor.action.goToLocations.

These hooks permit custom argument conversion, but neither they nor uriConverters provide automatic conversion of the opaque arguments copied by asCommand.
