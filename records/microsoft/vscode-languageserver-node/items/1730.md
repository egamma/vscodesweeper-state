# Issue #1730 — after `LanguageClient.restart()`, editor does not pull diagnostics for new opened files

[https://github.com/microsoft/vscode-languageserver-node/issues/1730](https://github.com/microsoft/vscode-languageserver-node/issues/1730)

## Summary

Keep open: the report supplies concrete restart/reopen steps and a trace showing missing diagnostic requests while document synchronization continues. Current main recreates notification emitters and diagnostic providers during restart, but those lifecycle changes do not conclusively resolve this failure; the supplied steps suffice to retest.

## Change summary

After LanguageClient.restart(), newly opened documents stop receiving pull diagnostics even though their document synchronization notifications continue.

## Best solution

Restore automatic diagnostic pulls for matching documents opened after restarting the same client instance. Reproduce the reported sequence against current client/ code and determine where the reopened document stops reaching the diagnostic requestor; recreating the entire downstream client is a workaround, not the desired library behavior.
