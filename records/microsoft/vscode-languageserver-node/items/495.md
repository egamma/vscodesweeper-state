## Summary

Keep open: the discussion established an accepted request for interoperable reference CodeLens actions, beyond the existing extension-specific workaround. An open spec proposal addresses the protocol contract, but implementation work would still remain here.

## Change summary

Allow reference CodeLens actions to work through a standardized protocol contract without each extension supplying its own command handler or argument-conversion middleware.

## Best solution

Coordinate the reference-action contract and capability negotiation with https://github.com/microsoft/language-server-protocol/issues/788, then implement the agreed types, capabilities and VS Code reference-view integration here. Retain this issue for that implementation work; shipping the spec proposal alone would not satisfy it.
