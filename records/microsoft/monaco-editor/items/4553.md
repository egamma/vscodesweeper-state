# Issue #4553 — [Bug] "No suggestions." shown when suggestions are provided at end of current token

[https://github.com/microsoft/monaco-editor/issues/4553](https://github.com/microsoft/monaco-editor/issues/4553)

## Summary

This is the intended completion-filtering behavior: invoking suggestions explicitly does not bypass filtering against the text covered by each item's range. The existing `range` and `filterText` APIs cover providers that need different behavior.

## Change summary

Show all completion items invoked by a keyboard shortcut even when they do not match the current token.

## Best solution

Keep the existing filtering semantics and configure each completion item with an appropriate zero-width or replacement `range` and corresponding `filterText` for the provider's desired behavior.

- **Proposed comment:**

  > Thanks for the report and playground example. Completion items returned by a provider are still filtered against the text covered by their `range`; invoking suggestions explicitly does not disable that filtering. Because `range` is omitted here, Monaco derives it from the current word, so items that do not match that text can be filtered out.
  > 
  > For providers that should show unrelated items, supply a suitable zero-width or replacement `range` and, when replacing existing text, a matching `filterText`. This established pattern is demonstrated in https://github.com/microsoft/monaco-editor/issues/1889#issuecomment-605085329 and https://github.com/microsoft/monaco-editor/issues/1889#issuecomment-642809145. A later retest also reports that the example works on the latest version, so this can be closed as designed.
