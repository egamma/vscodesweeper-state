# Issue #1312 — Go to line for Custom Line Numbers Problem

[https://github.com/microsoft/monaco-editor/issues/1312](https://github.com/microsoft/monaco-editor/issues/1312)

## Summary

Custom line-number rendering still does not make those labels usable in the built-in Go to Line picker. Keep this accepted Backlog request open: the capability remains missing, and no matching open canonical was found.

## Change summary

Allow Go to Line to resolve custom displayed line labels instead of requiring physical model line numbers.

## Best solution

Decide whether the VS Code editor core should expose an opt-in custom-label navigation contract, including how ambiguous labels resolve, while preserving default numeric navigation. Monaco would inherit that capability through its core release pipeline.

- **Current navigation limitation:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/quickAccess/browser/gotoLineQuickAccess.ts: AbstractGotoLineQuickAccessProvider.parsePosition parses input with parseInt, clamps it against model.getLineCount(), and constructs model positions. It does not resolve the custom lineNumbers callback's labels; Roman-numeral input therefore cannot select the corresponding line.
- **Core ownership:** src/features/gotoLine/register.js imports the monaco-editor-core standalone provider. https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/quickAccess/standaloneGotoLineQuickAccess.ts registers Ctrl+G and subclasses AbstractGotoLineQuickAccessProvider without adding custom-label resolution.
