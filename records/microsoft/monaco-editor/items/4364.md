# Issue #4364 — [Bug] [Vite] Worker error when call 'setCompilerOptions()'

[https://github.com/microsoft/monaco-editor/issues/4364](https://github.com/microsoft/monaco-editor/issues/4364)

## Summary

The reproduction replaces all compiler options with {}, removing allowNonTsExtensions and excluding the extensionless model from TypeScript's program. The thread already identifies the configuration solution; this is not a Vite worker-loading defect.

## Change summary

Calling setCompilerOptions({}) causes diagnostics for the default extensionless TypeScript model to fail with 'Could not find source file'.

## Best solution

Preserve existing compiler defaults when overriding individual settings, or explicitly retain allowNonTsExtensions: true for extensionless models. Close as an answered configuration question.

- **Proposed comment:**

  > Thanks for the reproduction. `setCompilerOptions` replaces the entire options object, so passing `{}` removes `allowNonTsExtensions: true`, which is needed for the default extensionless model URI (`inmemory://model/1`). The worker loads, but TypeScript excludes that model from its program.
  > 
  > The merge approach identified above preserves the defaults; preferably use `setCompilerOptions({ ...getCompilerOptions(), ...compilerOptions })` on `typescriptDefaults`, or explicitly include `allowNonTsExtensions: true`. Closing as an answered configuration question. Further usage questions belong on StackOverflow: https://stackoverflow.com/questions/tagged/monaco-editor.
