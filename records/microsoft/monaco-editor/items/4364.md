# Issue #4364 — [Bug] [Vite] Worker error when call 'setCompilerOptions()'

[https://github.com/microsoft/monaco-editor/issues/4364](https://github.com/microsoft/monaco-editor/issues/4364)

## Summary

This is a configuration question rather than a worker defect: `setCompilerOptions` replaces the complete option set, and the reproduction removes Monaco's required default `allowNonTsExtensions: true`.

## Change summary

Calling `typescriptDefaults.setCompilerOptions({})` causes diagnostics for Monaco's extensionless in-memory model to fail with “Could not find source file.”

## Best solution

Preserve the existing compiler defaults when changing individual options, as shown in the confirmed workaround, or explicitly include `allowNonTsExtensions: true`.

- **Proposed comment:**

  > Thanks for the report. `setCompilerOptions` replaces the complete compiler-options object; it does not merge with Monaco's defaults. Passing `{}` removes `allowNonTsExtensions: true`, so TypeScript excludes the extensionless `inmemory://model/1` source. Please preserve the defaults when overriding individual values:
  > 
  > ```js
  > const defaults = monaco.languages.typescript.typescriptDefaults;
  > defaults.setCompilerOptions({
  >   ...defaults.getCompilerOptions(),
  >   ...compilerOptions,
  > });
  > ```
  > 
  > Since this is a usage question rather than a worker defect, further integration questions belong on StackOverflow under https://stackoverflow.com/questions/tagged/monaco-editor.
