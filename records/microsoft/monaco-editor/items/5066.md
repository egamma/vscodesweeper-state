# Issue #5066 — Use LSP for CSS/JSON/HTML language features

[https://github.com/microsoft/monaco-editor/issues/5066](https://github.com/microsoft/monaco-editor/issues/5066)

## Summary

Keep open: the native LSP client exists, but CSS, JSON and HTML still register providers through the bespoke adapters this request seeks to remove. This team-authored Backlog item retains distinct, unfinished migration work.

## Change summary

Migrate bundled CSS, JSON and HTML language features to Monaco's native LSP client and retire their shared custom adapters.

## Best solution

Complete the migration in Monaco's language workers and mode registrations while preserving language defaults, feature configuration and language-specific behavior. Coordinate with the worker-transport work, but retain this issue as the owner of the CSS/JSON/HTML adoption.

## Evidence

- **Existing capability versus adoption:** src/index.ts exports the lsp namespace, and monaco-lsp-client/src/index.ts exports MonacoLspClient and createTransportToWorker. MonacoLspClient.createFeatures() supplies standard language-feature adapters, but availability does not complete migration of the bundled languages.
- **Remaining custom integration:** src/languages/features/css/cssMode.ts, json/jsonMode.ts and html/htmlMode.ts still import ../common/lspLanguageFeatures and directly register its CompletionAdapter, HoverAdapter and other providers. The issue's linked file has moved to src/languages/features/common/lspLanguageFeatures.ts; its implementation remains.
- **Compatibility boundary:** json/jsonMode.ts adds JSONDiagnosticsAdapter schema-reset behavior and maintains separate tokenization; json/jsonWorker.ts exposes custom doValidation/doComplete worker methods. Replacing shared adapters requires integrating these existing contracts, not merely exporting an LSP client.

Its changed files cover LSP infrastructure and a sample, not the bundled CSS/JSON/HTML migration; no open PR referencing this issue was found.
