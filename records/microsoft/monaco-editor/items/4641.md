# Issue #4641 — [Bug] Adding backtick to close open string adds two backticks instead of one

[https://github.com/microsoft/monaco-editor/issues/4641](https://github.com/microsoft/monaco-editor/issues/4641)

## Summary

The reported asymmetry remains in the current editor core: single and double quotes suppress autoclosing after a word character, while backticks do not. The existing under-discussion and editor-autoclosing routing remains appropriate until the intended behavior is decided.

## Change summary

Typing a backtick after existing text inserts an autoclosing pair instead of the single closing backtick produced for other quote characters.

## Best solution

Decide in the vscode editor core whether the word-character suppression should include backticks, then add cursor autoclosing tests covering all three quote characters. Any behavioral fix belongs in microsoft/vscode and will flow into Monaco with a subsequent release.
