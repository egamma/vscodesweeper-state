# Issue #4641 — [Bug] Adding backtick to close open string adds two backticks instead of one

[https://github.com/microsoft/monaco-editor/issues/4641](https://github.com/microsoft/monaco-editor/issues/4641)

## Summary

Keep open for a decision on backtick autoclosing in custom languages. Current upstream source explains the reported asymmetry, but the maintainer's tentative by-design response does not establish that it should be declined.

## Change summary

Typing a closing backtick after an existing word should insert one backtick rather than an additional pair.

## Best solution

Settle whether backticks should receive the same after-word suppression as single and double quotes for this custom-language configuration. Any editor-behavior change belongs in the microsoft/vscode editor core and would reach Monaco through a subsequent release.

  > Thanks for the reproduction. The editor currently suppresses automatic pairing after a word for single and double quotes, but not backticks, which explains this difference in your custom language. Disabling quote autoclosing would also disable opening-pair insertion, so it is not equivalent to the requested behavior. This needs a decision on the intended backtick behavior; any change would belong in the VS Code editor core: https://github.com/microsoft/vscode/issues.
