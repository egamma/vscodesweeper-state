# Issue #5202 — [Bug] Monaco Editor prevents <td> from shrinking in table-layout: auto (Standard Table Layout)

[https://github.com/microsoft/monaco-editor/issues/5202](https://github.com/microsoft/monaco-editor/issues/5202)

## Summary

The gap remains in the current editor core: Monaco assigns pixel widths to its rendered view while automatic layout only reacts after the container changes size, preserving the intrinsic-sizing cycle demonstrated by the playground. Route this to editor rendering rather than closing it.

## Change summary

Allow an automatically laid-out editor inside an auto-layout table cell to shrink without the editor's current pixel width forcing table overflow.

## Best solution

Adjust the vscode editor-core DOM sizing so the rendered editor does not impose its stale width on the host's intrinsic sizing, while preserving horizontal scrolling and overflow widgets. Add an auto-layout table-cell regression case and let the fix flow into Monaco with a subsequent release.
