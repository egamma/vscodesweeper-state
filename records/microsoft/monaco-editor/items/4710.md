# Issue #4710 — [Bug] `lightbulb` for `CodeAction` Not Showing When Text Has Only One Line

[https://github.com/microsoft/monaco-editor/issues/4710](https://github.com/microsoft/monaco-editor/issues/4710)

## Summary

The bundled editor core still sends the single-line lightbulb into the glyph margin even when glyphMargin is disabled, hiding the inline widget. Route this confirmed placement defect to editor-contrib; the related VS Code report was closed without an identified fix.

## Change summary

Keep the code-action lightbulb visible for a single unindented line when the glyph margin is disabled.

## Best solution

Fix the fallback placement in microsoft/vscode's LightBulbWidget.update so an unavailable glyph margin does not swallow the lightbulb, then bring the fix into Monaco through a release cut. Enabling glyphMargin is a workaround, not coverage of the requested configuration.

- **Current bundled source:** package.json pins vscodeRef to c132f72ae9f5ff80093e7d722c36f03755865b20. At https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/contrib/codeAction/browser/lightBulbWidget.ts, LightBulbWidget.update takes the first-and-only-line branch when indentation provides no space. With no competing glyph decoration, it calls renderGutterLightbub() and returns this.hide(), without checking EditorOption.glyphMargin. Together with the placement branch, this traces the reported configuration's missing visible fallback without executing the playground.
