# Issue #322 — Setting content for "gutter" / non-isWholeLine decorations

[https://github.com/microsoft/monaco-editor/issues/322](https://github.com/microsoft/monaco-editor/issues/322)

## Summary

Keep open: current APIs provide custom glyph-margin DOM widgets, but not the wider, independently styled per-line gutter requested here. The newer related request does not meet the re-review canonical bar, and the existing editor-core routing is appropriate.

## Change summary

Support dynamic, individually styled gutter content for per-line addresses and opcodes without repurposing line numbers or changing document text.

## Best solution

Design a supported, width-aware gutter content API in the VS Code editor core that Monaco can expose, preserving independent styling, hover content, and reliable updates. Use this older accepted request to track the remaining capability alongside the newer related report.

## Evidence

- **Requested scope and workaround limitations:** https://github.com/microsoft/monaco-editor/issues/322 requests per-line address/opcode content in an expanded gutter. The author's follow-ups require smaller fonts and hover text and document width and refresh limitations of the lineNumbers workaround; the January 2025 member comment supports genuine gutter functionality.
- **Existing public capabilities:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts exposes IGlyphMarginWidget.getDomNode(), addGlyphMarginWidget(), and layoutGlyphMarginWidget(). IModelDecorationOptions still exposes linesDecorationsClassName rather than line-decoration content; InjectedTextOptions.content injects text into the text view, not a dedicated gutter.
- **Glyph widgets do not cover arbitrary gutter width:** At the checkout's package.json vscodeRef, https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/browser/viewParts/glyphMargin/glyphMargin.ts#L402-L417 sizes widgets to glyphMarginWidth divided by the lane count and positions them in glyph lanes. Custom DOM therefore supplies part of the request, but does not provide the expanded line-decoration gutter needed for long opcode text.
- **Newer related request is not a canonical:** https://github.com/microsoft/monaco-editor/issues/4785 is open and requests custom per-line gutter data, but was created in December 2024, has no milestone, comments, or reactions, and provides no evidence of project ownership sufficient to supersede this older re-reviewed Backlog item.
- **Closed historical report:** https://github.com/microsoft/monaco-editor/issues/267 covers gutter text and line-number refresh limitations, but is closed and cannot be a duplicate canonical. Its closing comment, https://github.com/microsoft/monaco-editor/issues/267#issuecomment-1433410112, states openness to a PR rather than an implemented solution.
- **Implementation boundary:** README.md states that Monaco is generated from VS Code sources. The relevant gutter rendering code is upstream in src/vs/editor/browser/viewParts/glyphMargin/glyphMargin.ts, not Monaco-owned source; the current editor-core label already routes this correctly.
