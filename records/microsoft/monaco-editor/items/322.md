# Issue #322 — Setting content for "gutter" / non-isWholeLine decorations

[https://github.com/microsoft/monaco-editor/issues/322](https://github.com/microsoft/monaco-editor/issues/322)

## Summary

Keep open as the oldest well-described tracker for first-class per-line gutter content. Current glyph-margin widgets allow arbitrary DOM but remain lane-sized widgets and do not provide the requested wide, decoration-backed gutter text API.

## Change summary

Provide styled, hoverable, dynamically updated per-line text or content in a configurable gutter.

## Best solution

Add a general per-line gutter content API in the vscode editor core supporting width, styling, hover, model-tracked positioning, and explicit invalidation, then carry it into Monaco. This looks like open-for-PR material after API design agreement; the newer https://github.com/microsoft/monaco-editor/issues/4785 should be consolidated into this canonical issue.

## Vision fit

- **Fit:** rejected
- **Reason:** A generalized gutter API can benefit Monaco, but editor rendering behavior must be designed and implemented in the vscode editor core rather than as Monaco-only behavior.
- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources with some shims around services the code needs to make it run in a web browser."
