# Issue #4856 — [Bug] Rust raw strings with `br` or `cr` prefix are not treated as raw strings

[https://github.com/microsoft/monaco-editor/issues/4856](https://github.com/microsoft/monaco-editor/issues/4856)

## Summary

The defect remains in the current Rust grammar: br and cr prefixes are consumed as identifiers, so their strings enter escaped-string handling. Route to the basic-language tokenizer owner; this is Monaco-owned grammar code, not VS Code editor-core behavior.

## Change summary

Rust raw byte strings and raw C strings are highlighted as escaped strings, allowing backslashes to incorrectly extend highlighting past the closing quote.

## Best solution

Make the bundled Rust grammar recognize raw byte and C-string literals with the same raw-content and delimiter semantics as ordinary raw strings. Add focused tokenization coverage; this is bounded community-PR material.
