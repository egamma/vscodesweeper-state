# Issue #4341 — [Feature Request] Number of undo / redo available (in the stack)

[https://github.com/microsoft/monaco-editor/issues/4341](https://github.com/microsoft/monaco-editor/issues/4341)

## Summary

The public API does not expose accurate undo/redo counts. Route this request to editor-api and undo-redo; the related requests do not clearly own its full API contract.

## Change summary

Expose the number of available undo and redo operations so embedders can display accurate history counters.

## Best solution

Consider a supported per-model history-count API in the VS Code-derived editor core that respects edit grouping and redo invalidation. Existing undo-stop notifications and VS Code history-UI requests inform the design but do not fully cover this embedder API.

## Vision fit

- **Fit:** aligned
- **Reason:** A supported model API fits Monaco's role as an embeddable editor without requiring an application-level history UI.
- **Evidence:** The vision identifies API surface as the aligned form of embedder capabilities and requires editor-core changes to follow VS Code's sources.

## Evidence

- **Existing capability check:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts exposes getAlternativeVersionId(), pushStackElement(), and popStackElement(), but no undo/redo count accessor. Version identity and explicit grouping controls do not report available history depth.
- **Internal capability is not public API:** https://github.com/microsoft/vscode/blob/main/src/vs/platform/undoRedo/common/undoRedo.ts defines IUndoRedoService.getElements(resource), including past and future elements. This internal service is not a supported Monaco model API; README.md states that only monaco.d.ts is versioned and other internals may break.
- **Related API request:** Verified open: https://github.com/microsoft/monaco-editor/issues/1691 requests notification when an undo stop is created to coordinate multiple editors. Its comments describe monkey-patching and private-field inspection, not a supported undo/redo count API. Notifications alone do not cover both available counts.
- **Related upstream UI request:** Verified open: https://github.com/microsoft/vscode/issues/100717 requests visible history, counters, or availability indicators in VS Code. It does not explicitly request the public Monaco API needed by this report, so it is related rather than a verified duplicate.
- **Ownership:** src/editor.ts re-exports monaco-editor-core/esm/vs/editor/editor.api, and README.md explains that Monaco is generated from VS Code sources. The history API change belongs in the upstream editor core, not Monaco's language workers or packaging.
