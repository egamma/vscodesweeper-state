# Issue #1984 — Monarch definition of shell language breaks bash syntax highlighting with some command substitutions 

[https://github.com/microsoft/monaco-editor/issues/1984](https://github.com/microsoft/monaco-editor/issues/1984)

## Summary

The reported highlighting leak remains traceable in the current shell grammar: command substitution ends at a parenthesis inside quoted awk code, leaving the closing quote to start a multiline string. Keep this issue as the existing canonical; its grammars routing is correct.

## Change summary

Shell command substitutions containing quoted parentheses incorrectly cause subsequent commands and functions to be highlighted as strings.

## Best solution

Correct command-substitution boundary handling in src/languages/definitions/shell/shell.ts so quoted parentheses do not terminate the substitution or leak string state into following lines. This is Monaco-owned grammar work, with a focused tokenization regression suitable for a community contribution.

- **Behavior:**

  > A shell command substitution containing quoted awk code such as $(echo "WORD" | awk '{print tolower($0)}') must not end at the parenthesis inside that quoted code. After the substitution closes, subsequent echo commands, function declarations, and comments must retain their normal token categories rather than becoming a multiline string. A quoted literal containing parentheses inside a substitution must likewise leave following lines correctly highlighted. Existing ordinary strings, variables, and simple substitutions must continue to work.

## Evidence

- **Current source trace:** In src/languages/definitions/shell/shell.ts, parameters sends $( to parameterBodyParen. Its /[^#:%*@\-!_)]+/ rule consumes quotes and opening parentheses as variable text, and /[)]/ pops at the first closing parenthesis. For the reporter's $(echo "WORD" | awk '{print tolower($0)}'), that is the parenthesis in tolower($0), not the substitution terminator. Back in root, the remaining single quote enters stringBody, which persists across subsequent lines.
- **Executable regression harness:** src/languages/definitions/shell/shell.test.ts already exercises shell tokens, but its substitution cases contain no quoted closing parentheses. src/languages/definitions/test/testRunner.ts tokenizes each multiline sample with editor.tokenize and checks exact token offsets/types using assert.deepStrictEqual, making the reported cross-line leak directly testable.
