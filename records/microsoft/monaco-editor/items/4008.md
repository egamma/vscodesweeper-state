# Issue #4008 — [Bug] Returning true from the callback registered with registerEditorOpener could lead to undesirable highlighting

[https://github.com/microsoft/monaco-editor/issues/4008](https://github.com/microsoft/monaco-editor/issues/4008)

## Summary

Keep open: current VS Code source still converts a handled custom opener into the source editor, then applies destination highlighting without checking that its model matches the destination. The maintainer accepted a contribution, and no verified canonical or fixing commit was found.

## Change summary

Returning true from a custom editor opener can highlight destination coordinates in the unchanged source model.

## Best solution

Ensure symbol-navigation highlighting applies only to an editor displaying the destination resource, preserving legitimate same-model navigation highlights. The change belongs in microsoft/vscode's generated editor sources, not the TypeScript worker in this repository.
