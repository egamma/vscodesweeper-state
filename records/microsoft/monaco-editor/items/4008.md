# Issue #4008 — [Bug] Returning true from the callback registered with registerEditorOpener could lead to undesirable highlighting

[https://github.com/microsoft/monaco-editor/issues/4008](https://github.com/microsoft/monaco-editor/issues/4008)

## Summary

Still present in the current vscode-derived editor core: a successful custom opener returns the source editor, after which go-to-definition applies the target range highlight without confirming that editor displays the target model. Route this confirmed custom-opener bug to editor-api.

## Change summary

Handling a go-to-definition request through registerEditorOpener can apply the destination highlight to the source model.

## Best solution

Update the vscode editor core's go-to-symbol flow to create the highlight only when the editor returned by openCodeEditor displays the requested resource, preserving registerEditorOpener's handled-request contract without decorating an unrelated model.
