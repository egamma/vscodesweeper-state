[https://github.com/microsoft/monaco-editor/issues/5430](https://github.com/microsoft/monaco-editor/issues/5430)

The playground demonstrates a current crash originating in the bundled vscode-css-languageservice. Keep this open as upstream work until the language service handles an empty :nth-child() safely and Monaco consumes the fix.

## Change summary

Hovering an invalid empty :nth-child() selector throws from the CSS worker instead of returning hover information safely.

## Best solution

  > Thanks for the focused playground reproduction. This traces to the bundled vscode-css-languageservice: its selector-specificity hover code handles `:nth-child` when the parse node has children, but then reads `childElements[1].getText()` without ensuring that expression exists. Monaco's CSS worker delegates hover calculation directly to that service, so this should remain open as an upstream issue until the language service guards the malformed selector and Monaco consumes the resulting release.
