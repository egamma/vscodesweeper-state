# Issue #4638 — [Bug] `CompletionItem.range` has a default but is marked as required in the typings

[https://github.com/microsoft/monaco-editor/issues/4638](https://github.com/microsoft/monaco-editor/issues/4638)

## Summary

The published declaration still requires range while documenting a default, and current editor-core source supplies that default when range is missing. Route this API-contract mismatch to editor-api; no verified canonical or fixing commit was found.

## Change summary

Allow typed completion providers to omit CompletionItem.range and use the documented default.

## Best solution

Reconcile the provider-facing type with the documented default in the VS Code-derived editor API, while preserving the required normalized range used internally. The explicit-range playground pattern is a workaround, not coverage of the requested omission.

## Evidence

- **Published contract mismatch:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts declares range: IRange | CompletionItemRanges without an optional marker, immediately below documentation describing its default. A typed completion item omitting range therefore fails the declared contract.
- **Current runtime fallback:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/suggest/browser/suggest.ts: provideSuggestionItems computes defaultRange from model.getWordAtPosition(position), then onCompletionList executes if (!suggestion.range) { suggestion.range = defaultRange; } before constructing the internal CompletionItem.
- **Upstream type ownership:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages.ts still declares CompletionItem.range as required. The checkout's build/build-monaco-editor.ts copies generated build/amd/out/types.d.ts into the published monaco.d.ts; this is a VS Code-derived contract, not a bundled language-worker defect.
- **Existing workaround and related report:** website/src/website/data/playground-samples/extending-language-services/completion-provider-example/sample.js constructs an explicit range using model.getWordUntilPosition(position). https://github.com/microsoft/monaco-editor/issues/1352 is closed and concerns updating that example, not permitting omission in typings; it is not a duplicate canonical.
- **Canonical search:** Searches in microsoft/monaco-editor for CompletionItem with range, required, and mandatory, and in microsoft/vscode for CompletionItem.range and optional completion ranges, found no verified open issue owning this same typing mismatch.
