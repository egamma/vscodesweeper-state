## Summary

Editor localization is now documented, but that does not cover the requested JSON diagnostic translations. Keep this request open for a supported worker-localization integration and example.

## Change summary

  > Embedders need a supported non-AMD example that localizes JSON diagnostics as well as editor UI. A JSON document containing a trailing comma should produce a translated diagnostic under the documented locale setup. The default English experience and diagnostic locations must remain unchanged.
- **Trace:**

  > README.md documents editor-core nls loading, while build/shared.mjs packages editor-core translation resources. WorkerManager._getClient in src/languages/features/json/workerManager.ts sends no locale or translation resources, and JSONWorker in src/languages/features/json/jsonWorker.ts creates vscode-json-languageservice without localization configuration. src/languages/features/json/json.worker.ts is the worker entry point. The upstream parser uses @vscode/l10n, a separate mechanism from editor-core nls; this establishes the integration boundary, not a verified runtime result. Determine whether a documented custom worker can satisfy the request or a supported public configuration is necessary. Preserve JSON validation semantics and avoid expanding this work to other language workers. Related editor-only localization discussion: https://github.com/microsoft/monaco-editor/issues/1514.
- **Open decisions:**
  - Should JSON diagnostic localization be supported through a documented custom-worker setup or through a public Monaco configuration contract?
  - Should embedders supply JSON translation bundles, or should Monaco ship supported translations alongside editor resources?

- **Existing capability is partial:** README.md's Localization section documents loading an ESM nls script before the editor. build/shared.mjs:getNlsFiles copies monaco-editor-core translation resources, but neither provides a JSON language-service localization example.
