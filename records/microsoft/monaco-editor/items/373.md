# Issue #373 — Provide straight-forward zoneWidget API

[https://github.com/microsoft/monaco-editor/issues/373](https://github.com/microsoft/monaco-editor/issues/373)

## Summary

The requested convenience API remains absent: Monaco exposes the lower-level view-zone and overlay-widget primitives, while ZoneWidget remains an internal VS Code editor-core class. The existing workaround does not fulfill the maintainer-endorsed API request.

## Change summary

Expose a supported, straightforward API for creating widgets that combine a view zone with a synchronized overlay across the editor gutter.

## Best solution

Design and expose a supported ZoneWidget-style abstraction in the VS Code editor core so Monaco inherits it through its generated API, preserving the existing lower-level primitives for custom implementations.

## Vision fit

- **Fit:** aligned
- **Reason:** A reusable API for an existing editor-core abstraction supports Monaco's role as the browser-facing form of the VS Code editor.
- **Evidence:** The README describes Monaco as “generated straight from VS Code's sources,” making a shared editor-core API preferable to a Monaco-only implementation.

## Evidence

- **current public API:** The published Monaco 0.56.0 declarations at https://unpkg.com/monaco-editor@0.56.0/monaco.d.ts expose IViewZone and ICodeEditor.changeViewZones, but no ZoneWidget abstraction.
- **internal implementation:** ZoneWidget remains an exported editor-core implementation in https://github.com/microsoft/vscode/blob/0858530751c7bee77f9e4179b1993ab0763c64b7/src/vs/editor/contrib/zoneWidget/browser/zoneWidget.ts, but it is not exported from the standalone editor API.
- **maintainer intent:** The maintainer comment at https://github.com/microsoft/monaco-editor/issues/373#issuecomment-307023168 identifies multiple use cases and explicitly says a straightforward ZoneWidget API should be provided.
- **workaround only:** https://github.com/microsoft/monaco-editor/issues/373#issuecomment-419905293 demonstrates manually synchronizing a view zone and overlay widget; this solves individual usage but does not provide the requested supported abstraction.
