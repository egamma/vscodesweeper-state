# Issue #5001 — [Bug] monaco.editor.addEditorAction() doesn't add actions to the command palette

[https://github.com/microsoft/monaco-editor/issues/5001](https://github.com/microsoft/monaco-editor/issues/5001)

## Summary

Global action registration still omits command-palette discovery, but the maintainer questions whether this API promises that behavior. Keep the request open for an API-contract decision; the related VS Code report was closed back to this issue, not fixed.

## Change summary

Make actions registered through monaco.editor.addEditorAction() discoverable in every editor's command palette.

## Best solution

Decide whether global and instance action registration should provide equivalent palette discovery. If accepted, implement the behavior in the VS Code standalone editor sources; per-instance addAction() offers a workaround but does not cover the global registration contract.

- **Proposed comment:**

  > Thanks for explaining the distinction between actions and commands. The current global API registers keybindings and optional context-menu entries, while command-palette discovery uses editor-instance actions. Calling addAction() on each editor provides palette discovery, but does not cover your request for global registration. This needs a decision on the intended API contract; any implementation would live in the VS Code standalone editor sources. The related report https://github.com/microsoft/vscode/issues/267798 was closed as a duplicate of this issue, not as a fix.
