# Issue #4867 — [Bug] `setSelections` from `codeEditorWidget` doens't allow `IRange` objects

[https://github.com/microsoft/monaco-editor/issues/4867](https://github.com/microsoft/monaco-editor/issues/4867)

## Summary

The rejection matches the published API, but accepting ranges directly remains an unimplemented consistency enhancement. Classify it as a feature request and route to editor-api; any implementation belongs in the VS Code editor core.

## Change summary

Allow setSelections to accept an array of ranges, matching setSelection's range overloads.

## Best solution

Consider extending the shared VS Code editor API to accept ranges while preserving direction for existing selections. Explicit conversion with Selection.fromRange already supports the selection operation, but does not provide the requested direct range-array acceptance.

- **Proposed comment:**

  > Thanks for the report and the example. The current API accepts ranges in setSelection, but setSelections requires ISelection objects, so this is an API consistency enhancement rather than a violation of its declared contract. For now, your example can use myEditor.setSelections(selections.map(range => monaco.Selection.fromRange(range, monaco.SelectionDirection.LTR))). Accepting ranges directly would require a change in the shared VS Code editor core: https://github.com/microsoft/vscode/issues.
