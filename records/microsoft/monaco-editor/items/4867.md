# Issue #4867 — [Bug] `setSelections` from `codeEditorWidget` doens't allow `IRange` objects

[https://github.com/microsoft/monaco-editor/issues/4867](https://github.com/microsoft/monaco-editor/issues/4867)

## Summary

This is a valid editor API enhancement rather than a bug: `setSelections` intentionally accepts only oriented `ISelection` values, while `setSelection` also normalizes an `IRange`. The asymmetry remains on current vscode main and should be considered in the editor API.

## Change summary

Allow `setSelections` to accept ranges and normalize them to forward selections, matching the convenience provided by `setSelection`.

## Best solution

Consider adding an `IRange`-accepting overload and normalization in the vscode editor core's `CodeEditorWidget.setSelections`; until then, embedders can convert each range to `monaco.Selection`. This looks suitable for an `open for PR` decision by the editor API owner.
