# Issue #4628 — [Feature Request] ESM build that can be loaded from CDNs

[https://github.com/microsoft/monaco-editor/issues/4628](https://github.com/microsoft/monaco-editor/issues/4628)

## Summary

Keep open: a browser-ready ESM distribution with automatic cross-origin worker loading remains distinct from fixing CSS imports. Current packaging and worker defaults cover parts of the request, but do not establish the requested build-free, CDN-hosted experience.

## Change summary

Provide an official ESM entry point usable directly from a CDN, including styles and workers, without an application build or manual MonacoEnvironment configuration.

## Best solution

Design a supported CDN-ready distribution in Monaco's packaging layer, coordinating its stylesheet handling with https://github.com/microsoft/monaco-editor/issues/5067. Retain this issue's explicit cross-origin, automatic-worker acceptance requirement rather than treating browser-compatible imports alone as completion.

## Plan brief

- **Likely files:** `build/esm/rollup.config.mjs`, `build/esm/rollup-url-to-module-plugin/index.mjs`, `build/shared.mjs`, `src/internal/common/workers.ts`, `package.json`, `docs/integrate-esm.md`, `test/smoke/smoke.test.ts`
- **Validation:** Serve a plain HTML page on one origin and the proposed published ESM artifacts on another with suitable CORS headers. Without bundling, an AMD loader, or application-defined MonacoEnvironment hooks, verify editor styling, plaintext link detection, JSON suggestions, CSS diagnostics, HTML hover, and TypeScript completion; check for worker-origin, module-loading, and asset errors. Preserve existing bundler smoke scenarios.
- **Behavior:**

  > An embedder can import a supported Monaco ESM entry point from a separate-origin CDN and create an editor in plain HTML without an application build step. Required styles, fonts, editor workers, and bundled language workers load without application-specific worker URL mapping. Acceptance must exercise worker-backed language features, not only render editor text.
- **Trace:**

  > build/esm/rollup.config.mjs preserves modules and CSS imports, while build/shared.mjs selects and maps the published entry points. src/internal/common/workers.ts:getWorker already supports descriptor-provided worker creation, and the JSON WorkerManager supplies a relative module-worker URL; the Rollup URL plugin emits that worker chunk. This is partial automatic-loading support, not proof of separate-origin loading. The remaining design spans stylesheet delivery, the supported entry point, and cross-origin worker bootstrapping. Coordinate with https://github.com/microsoft/monaco-editor/issues/5067 without dropping this issue's broader CDN requirement. Preserve existing bundler entry points and explicit embedder worker overrides; editor-core behavior changes are outside this packaging task.
- **Open decisions:**
  - Should the supported CDN experience be a separate opt-in browser entry point or package, or a changed contract for the existing default ESM entry point?
  - What browser and content-security-policy requirements will the zero-configuration cross-origin worker experience support?
  - Should the browser entry point install styles automatically into the document, or expose an explicit initialization contract that also supports shadow roots?
