# Issue #2348 — Importing JSON in Typescript file results in error

[https://github.com/microsoft/monaco-editor/issues/2348](https://github.com/microsoft/monaco-editor/issues/2348)

## Summary

Keep open: the current TypeScript worker integration still does not automatically expose JSON editor models as typed imports. No verified fix or qualifying duplicate was found, and this team-authored request is protected from judgment closes.

## Change summary

Support importing JSON editor models into TypeScript models with inferred types when resolveJsonModule is enabled.

## Best solution

Provide typed JSON-model imports through Monaco's language-worker integration in src/languages/features/typescript, preserving JSON editing and reflecting model changes. Address both model synchronization and JSON script classification rather than suppressing diagnostics or requiring conversion to TypeScript.

## Evidence

- **Requested behavior and discussion:** https://github.com/microsoft/monaco-editor/issues/2348 supplies complete playground code with resolveJsonModule enabled, a JSON model, and a successful TypeScript-model import as a control. Subsequent commenters report the same limitation; the author describes converting JSON to TypeScript as a workaround.
- **Existing capability check:** src/languages/features/typescript/register.ts exposes resolveJsonModule, addExtraLib, and setEagerModelSync. These do not establish automatic, live JSON-model import support: extra libraries are separately registered source content, while eager synchronization is language-filtered.
- **Model synchronization boundary:** src/languages/features/typescript/workerManager.ts, WorkerManager._getClient, filters eagerly synchronized models by model.getLanguageId() === this._modeId. JSON models therefore do not enter the TypeScript worker through this path. DiagnosticsAdapter in languageFeatures.ts likewise registers validation for its selected language.
- **Worker host limitation:** src/languages/features/typescript/tsWorker.ts reads files only from synchronized mirror models, bundled libraries, or extra libraries. TypeScriptWorker.getScriptKind handles ts, tsx, js, and jsx, but has no JSON branch and falls back to JavaScript or TypeScript. The exposed compiler option alone does not cover the requested integration.
- **Canonical search:** GitHub searches for JSON imports, resolveJsonModule, and JSON modules found no verified canonical owning this request. https://github.com/microsoft/monaco-editor/issues/4627 is open but concerns JavaScript imports into TypeScript, was created in 2024, and has no milestone or reactions; it fails the stronger duplicate bar for this older, re-reviewed JSON report.
- **Downstream workaround is not a fix:** https://github.com/eclipse-dirigible/dirigible/issues/3168 is closed, but its body explicitly links this unresolved Monaco limitation and recommends @ts-ignore for TypeScript JSON imports. That suppresses an error rather than providing inferred JSON types.
