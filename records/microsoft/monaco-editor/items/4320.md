# Issue #4320 — [Feature Request] Make `setExtraLibs` and `addExtraLib` async

[https://github.com/microsoft/monaco-editor/issues/4320](https://github.com/microsoft/monaco-editor/issues/4320)

## Summary

The synchronization gap remains on main: extra-lib mutations return before the deferred event and worker update complete. Route this feature request to the TypeScript multifile area.

## Change summary

Provide an awaitable way to know when added or replaced TypeScript extra libraries are available in the worker.

## Best solution

Expose a backward-compatible synchronization barrier that resolves after `WorkerManager` has awaited `updateExtraLibs`, preserving `addExtraLib`'s disposable contract while allowing callers to safely invoke worker APIs immediately afterward.

## Evidence

- **deferred synchronization:** `src/languages/features/typescript/register.ts:682-690` defers `onDidExtraLibsChange` with `setTimeout(..., 0)`, so both mutation methods return before synchronization begins.
- **worker update:** `src/languages/features/typescript/workerManager.ts:46-57` asynchronously obtains the worker proxy and calls `updateExtraLibs`, but that promise is not exposed to callers and the proxy call itself is not awaited.
- **related work:** https://github.com/microsoft/monaco-editor/issues/3465 tracks stale results from consecutive `setExtraLibs` calls, but it does not own the broader request for an awaitable synchronization contract.
