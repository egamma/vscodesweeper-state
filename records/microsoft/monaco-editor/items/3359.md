# Issue #3359 — Make `onDropIntoEditor` api public

[https://github.com/microsoft/monaco-editor/issues/3359](https://github.com/microsoft/monaco-editor/issues/3359)

## Summary

The public API remains asymmetric: Monaco 0.56.0 exposes the dropIntoEditor option but omits both onDropIntoEditor and a public document-drop provider. The maintained feature request should remain open and route to the editor contribution area.

## Change summary

Expose a supported API for intercepting external drops and supplying custom content at the indicated editor position.

## Best solution

Add a stable custom-drop API in the vscode editor core and let it flow into Monaco, preferably a provider API that receives the position and data transfer and can replace the default edit. This is suitable for a community PR following maintainer agreement on the API shape.

- **Fit:** aligned
- **Reason:** A supported drop customization API lets browser embedders integrate through Monaco's API instead of depending on an internal editor event.
- **Evidence:** The vision describes embedders integrating through the API and identifies tracking the vscode editor core as a durable theme.
