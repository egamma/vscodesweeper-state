# Issue #3470 — [Feature Request] update hover messages

[https://github.com/microsoft/monaco-editor/issues/3470](https://github.com/microsoft/monaco-editor/issues/3470)

## Summary

The requested two-stage hover is supported by registering separate providers for immediate Content A and asynchronous Content B. This is an existing-capability question rather than missing functionality.

## Change summary

Display immediate hover content while additional content is calculated, then include the delayed result in the same hover.

## Best solution

Use two registerHoverProvider registrations covering the same range: one returns Content A immediately, and the other resolves Content B asynchronously. No new streaming or hover-update API is needed for this two-stage scenario.

  > Thanks for the context. The two-provider approach suggested above supports this scenario: register one hover provider that returns Content A immediately and another that returns a promise resolving to Content B, both covering the same range. The hover incorporates provider results as they become available, so Content A can appear before Content B finishes while the hover remains open. This does not require updating an already-returned hover object.
