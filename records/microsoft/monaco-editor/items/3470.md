# Issue #3470 — [Feature Request] update hover messages

[https://github.com/microsoft/monaco-editor/issues/3470](https://github.com/microsoft/monaco-editor/issues/3470)

## Summary

The existing hover-provider API already supports this scenario: separate fast and slow providers run concurrently, and their results are added to the hover as each resolves.

## Change summary

Allow an initially rendered hover to gain additional asynchronously computed content.

## Best solution

Register two hover providers for the language: one that immediately returns Content A and another that asynchronously returns Content B. The editor progressively merges their results without requiring a mutable hover API.

- **Reason:** The capability follows the shared VS Code editor-core behavior rather than introducing Monaco-specific hover semantics.

- **Proposed comment:**

  > Thanks for the request. This is already supported by registering two hover providers for the same language: have one return Content A immediately and let the other asynchronously resolve Content B. The editor runs the providers concurrently and updates the accumulated hover as each result arrives; while a provider remains pending, it can also display a Loading... state. The relevant editor-core flow is in https://github.com/microsoft/vscode/blob/8a531921d0ad22d9fa5d686a2be2e40e037af6c5/src/vs/editor/contrib/hover/browser/getHover.ts and https://github.com/microsoft/vscode/blob/8a531921d0ad22d9fa5d686a2be2e40e037af6c5/src/vs/editor/contrib/hover/browser/hoverOperation.ts. Closing because the existing API covers the requested behavior.
