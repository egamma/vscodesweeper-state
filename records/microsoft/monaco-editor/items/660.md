# Issue #660 — Control what actions are shown in Command Palette (F1) and how they are ordered?

[https://github.com/microsoft/monaco-editor/issues/660](https://github.com/microsoft/monaco-editor/issues/660)

## Summary

Keep open: supported control over palette filtering and ordering remains missing. The linked workaround modifies a private provider, and the older filtering request does not cover this issue's ordering requirement.

## Change summary

Allow embedders to choose which commands appear in F1 and control their ordering, including promoting frequently used commands.

## Best solution

Define supported filtering and ordering controls in the VS Code standalone editor core, then expose them through Monaco's public API. Preserve the existing default ordering for embedders that do not customize it.

- **Public capability check:** Inspected https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts. IActionDescriptor exposes precondition and contextMenuOrder, but contextMenuOrder controls the context menu, not F1; no public palette-filter or palette-order option was found.
- **Current core behavior:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/quickAccess/standaloneCommandsQuickAccess.ts constructs the provider with showAlias:false and obtains picks through getCodeEditorCommandPicks. https://github.com/microsoft/vscode/blob/main/src/vs/platform/quickinput/browser/commandsQuickAccess.ts sorts by recent use, then other ranking criteria and name. Recent-use ordering is not configurable frequency-based ordering.
- **Related issue does not own full scope:** https://github.com/microsoft/monaco-editor/issues/135 is open and older, but requests hiding commands for disabled features, not controlling command ordering. https://github.com/microsoft/monaco-editor/issues/683 requests custom quick-open workflows rather than customization of the existing F1 list.
