# Issue #660 — Control what actions are shown in Command Palette (F1) and how they are ordered?

[https://github.com/microsoft/monaco-editor/issues/660](https://github.com/microsoft/monaco-editor/issues/660)

## Summary

A real API gap remains: Monaco prioritizes recently used commands automatically, but it exposes no supported way to filter built-in palette actions or provide custom ranking. The existing quick-pick and feature-request labels already route it correctly.

## Change summary

Expose control over which actions appear in the Command Palette and how they are ordered.

## Best solution

Add a supported filtering and ranking API in the vscode standalone command-palette provider, which Monaco inherits, rather than requiring embedders to patch an internal prototype. Preserve the existing recently-used ordering as the default.

## Vision fit

- **Fit:** aligned
- **Reason:** A supported customization API fits Monaco's role as an embeddable browser editor whose hosts integrate through public APIs.
- **Evidence:** The vision states that embedders integrate Monaco via its API, while the editor itself is generated from VS Code sources.

- **unsupported workaround:** The workaround linked in the discussion patches StandaloneCommandsQuickAccessProvider.prototype.getCommandPicks through an internal ESM module rather than a supported Monaco API: https://github.com/microsoft/monaco-editor/issues/135#issuecomment-1937091073
