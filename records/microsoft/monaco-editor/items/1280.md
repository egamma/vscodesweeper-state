# Issue #1280 — How can I customize context menu? I want to delete 'Go to definition' and others,and add my own meun.

[https://github.com/microsoft/monaco-editor/issues/1280](https://github.com/microsoft/monaco-editor/issues/1280)

## Summary

Keep open: adding custom actions is supported, but selectively removing built-in context-menu entries still lacks a public API. Maintainers explicitly consolidated matching requests into this issue, which remains the canonical accepted feature request.

## Change summary

Provide supported context-menu customization that removes unwanted built-in entries while retaining custom actions.

## Best solution

Design a public, per-editor mechanism for selecting or filtering built-in context-menu entries in the VS Code-derived editor core, then expose it through Monaco. Preserve this issue as the canonical request rather than treating private monkey-patching as supported coverage.

## Evidence

- **Maintainer-confirmed API gap:** https://github.com/microsoft/monaco-editor/issues/1280#issuecomment-459507645 explicitly states that no API accomplishes selective removal and suggests accessing private MenuRegistry internals.
- **Existing capabilities cover only part of the request:** website/src/website/data/playground-samples/interacting-with-the-editor/adding-an-action-to-an-editor-instance/sample.js demonstrates addAction with contextMenuGroupId and contextMenuOrder. The pinned core declarations at https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/monaco.d.ts expose these fields, addAction returning IDisposable, and a boolean contextmenu option; they do not expose selective removal of built-in entries. Disposing an added action or disabling the entire menu does not satisfy the central ask.
- **Current implementation boundary:** src/features/contextmenu/register.js imports the generated monaco-editor-core contextmenu contribution. In https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/contrib/contextmenu/browser/contextmenu.ts, lines 163–195, private _getMenuActions obtains registered menu groups and converts their actions without an embedder-supplied item filter.
- **This issue is the established canonical:** Maintainers closed https://github.com/microsoft/monaco-editor/issues/1567 as a duplicate of this issue at https://github.com/microsoft/monaco-editor/issues/1567#issuecomment-1458190468, and likewise closed https://github.com/microsoft/monaco-editor/issues/982 at https://github.com/microsoft/monaco-editor/issues/982#issuecomment-1458193135. Canonical searches found no verified open issue owning the same removal request; https://github.com/microsoft/monaco-editor/issues/1947 requests adding submenus, a different capability.
- **Workarounds are not public API coverage:** https://github.com/microsoft/monaco-editor/issues/1280#issuecomment-2099873176 filters built-in actions by monkey-patching private _getMenuActions; https://github.com/microsoft/monaco-editor/issues/1280#issuecomment-2420136963 applies the same workaround to retain only Copy. These demonstrate continuing demand, not a supported implementation.
