# Issue #4473 — [Feature Request] completionItems with insertText having quotes can have extra quotes in the front

[https://github.com/microsoft/monaco-editor/issues/4473](https://github.com/microsoft/monaco-editor/issues/4473)

## Summary

The existing completion API can avoid the extra quote by making the item's replacement range include the already-typed quote. Because this is a team-authored feature request, the protected-item rule bars an as-designed or question close.

## Change summary

Make quoted snippet completions replace an already-typed opening quote instead of retaining it and inserting another.

## Best solution

Have the completion provider inspect the character before the word and extend `CompletionItem.range.startColumn` to include a compatible opening quote. Any request for automatic provider-independent quote handling belongs in the VS Code editor core rather than Monaco-specific code.

  > Thanks for the playground example. `CompletionItem.range` controls which existing text is replaced when the completion is accepted. Here, `getWordUntilPosition` starts at the `t`, so the preceding quote remains outside the range. The provider can inspect the character before that word and move `startColumn` back by one when it is a quote that should be replaced; the inserted snippet can then retain its own quotes without producing a duplicate.
