# Issue #4326 — [Bug] wordBasedSuggestions set to "off" but still seeing content-based suggestions in json

[https://github.com/microsoft/monaco-editor/issues/4326](https://github.com/microsoft/monaco-editor/issues/4326)

## Summary

The suggested "test" comes from JSON language completions, not the editor's word-based provider. Existing configuration controls JSON completions and automatic triggering, so this is a configuration question rather than a broken wordBasedSuggestions setting.

## Change summary

Suppress suggestions inferred from other JSON properties despite wordBasedSuggestions being off.

## Best solution

Explain the distinction between word-based and JSON language completions. Disable automatic trigger-character suggestions if only popup suppression is wanted, or disable the JSON completion provider if no JSON completions are wanted.

- **Proposed comment:**

  > Thanks for the report and example. The "test" suggestion comes from the JSON language service, which suggests values previously used for the same property name. `wordBasedSuggestions: 'off'` disables the editor's generic word suggestions, not language-provider completions.
  > 
  > To stop automatic popups, also set `suggestOnTriggerCharacters: false` alongside `quickSuggestions: false`; manually requested completions remain available. To disable the built-in JSON completions entirely, use `jsonDefaults.setModeConfiguration({ ...jsonDefaults.modeConfiguration, completionItems: false })` with your JSON language defaults. This applies to all JSON editors using those defaults, while preserving their other language features.
  > 
  > Closing as a configuration question. Further usage questions can go to https://stackoverflow.com/questions/tagged/monaco-editor.

## Evidence

- **Exact suggestion source:** https://github.com/microsoft/vscode-json-languageservice/blob/main/src/services/jsonCompletion.ts: doComplete calls getSchemaLessValueCompletions without a schema. That method visits properties with the same key and collects their values, explaining why the earlier "b": "test" supplies "test" for the second b value.
- **Monaco integration:** src/languages/features/json/jsonWorker.ts: JSONWorker.doComplete forwards the parsed document to vscode-json-languageservice.doComplete independently of wordBasedSuggestions. src/languages/features/json/jsonMode.ts registers this separate completion provider with space, colon, and quotation-mark trigger characters.
- **Existing configuration:** src/languages/features/json/register.ts exposes jsonDefaults.setModeConfiguration and ModeConfiguration.completionItems. Setting completionItems to false disables the built-in JSON completion provider; spreading the existing modeConfiguration preserves the other JSON features. https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts documents suggestOnTriggerCharacters as the independent control for automatic trigger-character popups.
- **Maintainer precedent:** https://github.com/microsoft/monaco-editor/issues/1980#issuecomment-687240926 explains that language-service completions are forwarded independently of wordBasedSuggestions. That example concerns JavaScript, but the inspected JSON worker establishes the same provider boundary here.

Neither owns this report's configuration question, so neither is a duplicate target.
