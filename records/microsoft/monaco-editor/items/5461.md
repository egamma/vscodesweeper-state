# Issue #5461 — [Bug] Monaco "vs" theme for SQL language does not meet minimum color contrast issue threshold for .mtk4 and mtk18

[https://github.com/microsoft/monaco-editor/issues/5461](https://github.com/microsoft/monaco-editor/issues/5461)

## Summary

The contrast defect remains in the current source: SQL strings and operators in the built-in vs theme fall below 4.5:1. Classify and route to accessibility and editor theming; no verified canonical owns both affected token types.

## Change summary

SQL strings and operators in the built-in vs theme need foreground colors meeting WCAG AA text contrast.

## Best solution

Correct the SQL token colors in the VS Code standalone editor theme source and bring that fix into a Monaco release. Preserve SQL tokenization; a custom theme is an interim workaround, not resolution of the default-theme defect.

- **Proposed comment:**

  > Thanks for the report and the SQL example. The current built-in `vs` theme still assigns `string.sql` and `operator.sql` colors with contrast ratios of approximately 4.00:1 and 3.64:1 against its background, below 4.5:1. These colors are defined in the VS Code standalone editor source, so the fix belongs in https://github.com/microsoft/vscode/issues and would reach Monaco through a subsequent release. In the meantime, `monaco.editor.defineTheme` can override those token colors without changing SQL tokenization.
