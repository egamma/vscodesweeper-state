# Issue #4058 — [Bug] monaco.editor.colorize ignores DocumentSemanticTokensProvider

[https://github.com/microsoft/monaco-editor/issues/4058](https://github.com/microsoft/monaco-editor/issues/4058)

## Summary

The capability remains absent from the current editor core, and a maintainer explicitly classified this newer request as a feature and placed it in Backlog after an earlier equivalent request was declined. The existing routing is appropriate, so this should remain open.

## Change summary

Make monaco.editor.colorize apply registered document semantic tokens in addition to lexical tokenization.

## Best solution

Extend the vscode standalone colorizer in src/vs/editor/standalone/browser/colorizer.ts to obtain and theme semantic tokens, likely through a temporary model, while preserving the existing lexical-only path. This appears suitable for a community PR but requires editor-core design work in microsoft/vscode.
