# Issue #3448 — [Bug] monaco.editor.tokenize does not return correct results

[https://github.com/microsoft/monaco-editor/issues/3448](https://github.com/microsoft/monaco-editor/issues/3448)

## Summary

The missing public tokenizer-readiness mechanism is already tracked by an older open issue with the same observable problem: editor.tokenize requires timeout-based initialization. Consolidate this report's TypeScript example and internal-API clarification there.

## Change summary

Provide a supported way to await tokenizer initialization before calling monaco.editor.tokenize.

## Best solution

Resolve the public readiness contract tracked in https://github.com/microsoft/monaco-editor/issues/2885 so callers can obtain tokens without arbitrary delays or internal imports; the core API work belongs in microsoft/vscode.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/monaco-editor/issues/2885 is OPEN and was created on 2022-01-10, before this report. Its body explicitly describes calling editor.tokenize in tests and relying on timeouts because no readiness hook or promise is available—the same reporter-observable initialization problem.
- **Discussion establishes remaining scope:** https://github.com/microsoft/monaco-editor/issues/3448 documents successful tokenization after a delay. The maintainer suggested awaiting TokenizationRegistry.getOrCreate, then clarified that the registry is exposed only through internal vs/editor/common/languages, not the public languages namespace. The issue was reopened after that clarification.
- **Current core behavior:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneEditor.ts lines 372–400 show tokenize calling TokenizationRegistry.getOrCreate without awaiting it, then immediately retrieving support; absent support falls back to nullTokenize. This explains why a cold call can lack meaningful tokens while subsequent calls succeed.
- **Existing capabilities do not cover readiness:** https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts declares tokenize as synchronous Token[][] and colorize as Promise<string>, which returns HTML rather than tokens. onLanguage and onLanguageEncountered signal language association or encounter, not completed tokenizer initialization.
- **Checkout corroborates asynchronous initialization:** src/languages/definitions/_.contribution.ts registers an asynchronous tokens-provider factory. src/languages/definitions/test/testRunner.ts awaits loadLanguage and timeout(0) before editor.tokenize. src/editor.ts re-exports the generated monaco-editor-core API; these internal helpers are not a public readiness contract.
