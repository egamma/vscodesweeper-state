# Issue #3906 — [Bug] Runtime theme change produces incorrect strings highlighting inside of colorize element

[https://github.com/microsoft/monaco-editor/issues/3906](https://github.com/microsoft/monaco-editor/issues/3906)

## Summary

The defect remains in the current vscode-derived editor core: colorized DOM retains numeric token classes from the old color map, while a runtime theme change replaces their global CSS meanings. The existing tokenization routing and Backlog milestone remain appropriate.

## Change summary

Changing the global theme after calling colorizeElement gives previously colorized string tokens incorrect colors.

## Best solution

Fix the vscode editor core so colorizeElement output is regenerated or otherwise remapped when the standalone token color map changes, then consume that fix in the next Monaco release.
