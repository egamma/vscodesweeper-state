# Issue #1498 — Allow changing the wordBasedSuggestions via configuration service

[https://github.com/microsoft/monaco-editor/issues/1498](https://github.com/microsoft/monaco-editor/issues/1498)

## Summary

Configuration-service updates are supported today, but that does not establish that the unwanted JavaScript suggestions are suppressed. Keep this accepted request open: the TypeScript completion path remains separate, and the related report does not satisfy the stronger duplicate bar for this re-reviewed item.

## Change summary

Allow disabling unwanted JavaScript word-like completions through the wordBasedSuggestions configuration.

## Best solution

Distinguish Monaco's configurable word provider from TypeScript's JavaScript fallback completions, then establish how embedders should control the latter without hiding legitimate completions. Coordinate the remaining language-service behavior with https://github.com/microsoft/monaco-editor/issues/2136 while preserving this older accepted report.

  > Thanks for the report. Current Monaco supports wordBasedSuggestions: 'off' through both construction options and updateOptions, but JavaScript can also receive word-like completions directly from the TypeScript language service. Those are a separate path, so configuration forwarding alone does not resolve the behavior shown here. The related discussion at https://github.com/microsoft/monaco-editor/issues/2136 helps identify that distinction; this request should remain open until the remaining JavaScript behavior is addressed.

## Evidence

- **Original diagnosis:** https://github.com/microsoft/monaco-editor/issues/1498#issuecomment-564629610 identifies configuration-service reads rather than ordinary editor-option reads; the preceding commenter confirmed the JavaScript-specific symptom.
- **Existing configuration capability:** Current upstream src/vs/editor/standalone/browser/standaloneCodeEditor.ts exposes IGlobalEditorOptions.wordBasedSuggestions and calls updateConfigurationService in construction and updateOptions. src/vs/editor/standalone/browser/standaloneServices.ts forwards recognized options as editor.* configuration keys. Sources: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneCodeEditor.ts and https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneServices.ts.
- **Shipped API and provider boundary:** CHANGELOG.md records global-option typings in v0.19.1 and the change to wordBasedSuggestions: 'off' | 'currentDocument' | 'matchingDocuments' | 'allDocuments' in v0.45.0. The current core word provider returns no completions for 'off': https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/services/editorWorkerService.ts. These capabilities do not control every language-service completion.
- **Separate JavaScript completion path:** In the checkout, src/languages/features/typescript/tsWorker.ts calls the TypeScript language service's getCompletionsAtPosition with undefined preferences. src/languages/features/typescript/languageFeatures.ts maps all returned entries and converts Kind.warning to CompletionItemKind.File, without consulting wordBasedSuggestions. https://github.com/microsoft/monaco-editor/issues/1980#issuecomment-687240926 explains that similar JavaScript suggestions originate in TypeScript, not Monaco's word provider.
- **Related issue is not a qualifying canonical:** https://github.com/microsoft/monaco-editor/issues/2136 is currently open and its discussion demonstrates unwanted JavaScript member suggestions despite wordBasedSuggestions being disabled. However, it was created in September 2020, after this June 2019 report, has no milestone or body upvotes, and its retrieved discussion identifies no open implementation PR. It therefore does not clear the re-reviewed-item canonical ownership bar.
- **Partial workaround:** https://github.com/microsoft/monaco-editor/issues/1980#issuecomment-961363847 suggests suggest.showFiles: false. The checkout's warning-to-File mapping explains that workaround, but filtering an entire completion kind is not equivalent to controlling the requested word-based behavior.
