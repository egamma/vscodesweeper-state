# Issue #4722 — [Feature Request]Support replace the decoration with customized dom element

[https://github.com/microsoft/monaco-editor/issues/4722](https://github.com/microsoft/monaco-editor/issues/4722)

## Summary

Keep this request open and route it to editor-api: existing content widgets and injected text do not provide a range-replacement API accepting arbitrary DOM while preserving the underlying text. No verified open canonical covers the same request.

## Change summary

Allow a text range to display a custom DOM element instead of its underlying model text, like CodeMirror's markText replacedWith option.

## Best solution

Have the VS Code editor-core maintainers assess a supported range-replacement contract, including layout, cursor movement, selection, and accessibility. Any accepted capability should flow into Monaco through its generated editor API rather than a Monaco-only rendering fork.

- **Pinned decoration API:** package.json pins vscodeRef c132f72ae9f5ff80093e7d722c36f03755865b20. In https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/common/model.ts, IModelDecorationOptions.before/after inject text adjacent to a range, and InjectedTextOptions.content is a single-line string; these options do not accept a replacement HTMLElement.
- **Existing DOM widgets are partial coverage:** website/src/website/data/playground-samples/interacting-with-the-editor/listening-to-mouse-events/sample.js demonstrates addContentWidget with getDomNode and position-based placement. https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/editorBrowser.ts defines IContentWidget as an HTMLElement anchored near a position, not a text-range replacement contract.
