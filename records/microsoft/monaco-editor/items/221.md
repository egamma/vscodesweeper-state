# Issue #221 — Auto complete for HTML -- add the close tag

[https://github.com/microsoft/monaco-editor/issues/221](https://github.com/microsoft/monaco-editor/issues/221)

## Summary

Automatic HTML closing-tag insertion remains missing from the current HTML integration. Keep this accepted request open: existing completion APIs and community workarounds do not provide the built-in behavior the maintainer endorsed.

## Change summary

Automatically insert the matching HTML closing tag when the user types > to finish an opening tag.

## Best solution

Provide VS Code-style tag closing in Monaco's HTML language integration, with correct cursor placement and handling of void elements. This remains suitable community-PR work; decide the configuration and default behavior before implementation.

- **Fit:** aligned
- **Reason:** This brings the bundled HTML experience closer to VS Code through Monaco-owned language integration.
- **Evidence:** The vision identifies behavior parity with VS Code and the bundled JSON/CSS/HTML/TypeScript language experiences as durable themes.

## Plan brief

- **Likely files:** `src/languages/features/html/htmlMode.ts`, `src/languages/features/html/htmlWorker.ts`, `src/languages/features/html/register.ts`
- **Validation:** In an HTML playground editor, type <div followed by > and verify <div></div> with the cursor between the tags and no suggestion acceptance required. Repeat with attributes and a multiline opening tag; verify <br> and <div /> do not acquire closing tags, undo/redo preserves edits, and any disabling configuration prevents insertion.
- **Behavior:**

  > Completing an HTML opening tag by typing > should automatically insert its matching closing tag and leave the cursor between them. The insertion should not require accepting a completion suggestion. Acceptance checks cover ordinary tags, attributes, multiline opening tags, void and self-closing elements, and undo/redo. Preserve non-HTML editing behavior; JSX/XML support and synchronized renaming are separate requests.
- **Trace:**

  > The maintainer endorsed the > trigger and porting HTML client functionality in https://github.com/microsoft/monaco-editor/issues/221#issuecomment-422441595 and https://github.com/microsoft/monaco-editor/issues/221#issuecomment-422686804. Current src/languages/features/html/htmlMode.ts registers providers through setupMode; HTMLCompletionAdapter omits > from its triggers. HTMLWorker.doComplete in src/languages/features/html/htmlWorker.ts calls the HTML language service, while the shared CompletionAdapter returns suggestions rather than automatic edits. src/languages/features/html/register.ts defines HTML defaults and configuration without a tag-closing option. These source reads establish the integration gap, but no browser execution was performed and the historical VS Code tagClosing.ts URL now returns 404. Preserve shared completion behavior and keep related matching-tag editing at https://github.com/microsoft/monaco-editor/issues/527 outside this feature's scope.
- **Open decisions:**
  - Should automatic HTML tag closing be enabled by default, and what public configuration should let embedders disable or opt into it?
