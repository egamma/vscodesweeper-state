# Issue #4405 — [Bug] Background color does not seems to be working on monaco.editor.defineTheme rules section.

[https://github.com/microsoft/monaco-editor/issues/4405](https://github.com/microsoft/monaco-editor/issues/4405)

## Summary

Token background styling is an intentionally unsupported editor-core capability already tracked by the older, open microsoft/vscode issue. Consolidate this report there rather than treating it as a separate Monaco theme defect.

## Change summary

Support per-token background colors supplied through monaco.editor.defineTheme rules.

## Best solution

Implement token background rendering in the shared VS Code editor core through https://github.com/microsoft/vscode/issues/3429, preserving selection and decoration backgrounds, then deliver that capability through a Monaco release.

## Evidence

- **Maintainer explanation:** https://github.com/microsoft/vscode/issues/3429#issuecomment-192353247 explains that token backgrounds were disabled because they conflicted with selection and word-highlighting decorations. https://github.com/microsoft/vscode/issues/3429#issuecomment-323300738 confirms that supporting them requires additional work.
- **Current source corroboration:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages/supports/tokenization.ts exposes and parses ITokenThemeRule.background, but generateTokensCSSForColorMap at lines 413–425 emits foreground color and font-style classes, not token background classes. The exposed property alone does not provide rendered background support.
- **Related Monaco reports:** https://github.com/microsoft/monaco-editor/issues/4462 is open and repeats the identical defineTheme symptom, with independent confirmations. https://github.com/microsoft/monaco-editor/issues/586 was closed for lacking a reproducible example, not because a fix landed; it is not a valid duplicate target.
