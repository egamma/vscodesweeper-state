# Issue #135 — Remove unused commands from the all command list

[https://github.com/microsoft/monaco-editor/issues/135](https://github.com/microsoft/monaco-editor/issues/135)

## Summary

A real capability gap remains: Monaco has no supported API or automatic feature-aware filtering for command-palette entries. The issue is already correctly classified and remains the oldest focused report for this behavior.

## Change summary

Hide command-palette actions for editor features disabled through configuration.

## Best solution

Implement feature-aware command visibility in the vscode editor core so disabled contributions such as folding do not appear in Monaco's command palette. This looks suitable for a community PR, while the broader customization request remains tracked separately by https://github.com/microsoft/monaco-editor/issues/660.

## Evidence

- **current implementation:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/quickAccess/standaloneCommandsQuickAccess.ts obtains palette entries from getCodeEditorCommandPicks without exposing an embedder filtering API.
- **action filtering:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/quickAccess/browser/commandsQuickAccess.ts lists every action returned by the active editor's getSupportedActions; feature-option-aware visibility would therefore need to be expressed in the vscode editor core.
- **workaround limitation:** https://github.com/microsoft/monaco-editor/issues/135#issuecomment-1937091073 filters commands by monkey-patching StandaloneCommandsQuickAccessProvider.prototype.getCommandPicks, demonstrating demand but not a supported API.
