# Issue #2605 — Use native approach to load web workers

[https://github.com/microsoft/monaco-editor/issues/2605](https://github.com/microsoft/monaco-editor/issues/2605)

## Summary

The central request remains partially open. v0.56.0 added native module-worker factories for the four bundled language services, but current ESM documentation and samples still require embedders to configure MonacoEnvironment for the editor worker.

## Change summary

Make Monaco's ESM entry points create their workers through native module-worker imports without requiring embedders to maintain a label-to-worker mapping.

## Best solution

Complete the v0.56 worker modernization by providing a native default for the editor worker while preserving MonacoEnvironment as an override, then update the ESM documentation and bundler samples. This is suitable for continued tracking here and likely open-for-PR material.

## Vision fit

- **Fit:** aligned
- **Reason:** Removing manual worker wiring advances Monaco's ESM-first packaging and mainstream bundler integration direction.
- **Evidence:** The v0.56.0 CHANGELOG describes supported, tree-shakeable ESM entry points, while v0.53.0 directs users away from AMD and toward ESM with modern bundlers.
