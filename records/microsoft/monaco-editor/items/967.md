[https://github.com/microsoft/monaco-editor/issues/967](https://github.com/microsoft/monaco-editor/issues/967)

## Summary

Keep open: the registration pattern remains documented, but navigation to HTTP-hosted extra-library models is not verified on current Monaco. The worker and definition adapter have evolved since 0.13.1; the supplied setup and contrasting hover/peek behavior suffice for a targeted retest, not a closure.

## Change summary

Go to Definition fails and Peek Definition displays the wrong source when an extra library and its model use an absolute HTTP URL.

## Best solution

Ensure definition navigation resolves the registered library model without losing its URL scheme or authority. First compare the TypeScript worker's returned filename with the registered model URI; if the resulting location is correct, investigate navigation and peek resolution in the VS Code editor core.
