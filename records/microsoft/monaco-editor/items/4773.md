## Summary

Verified duplicate of the open transformed-container positioning issue: both reports describe fixed overflow widgets displaced by the ancestor's offset. Consolidate this report's marker-hover reproduction and filter-only trigger into the canonical issue.

## Change summary

Fixed overflow widgets appear far from their anchors when an editor ancestor has a CSS transform or filter.

## Best solution

Track the shared positioning defect in https://github.com/microsoft/monaco-editor/issues/2793, retaining this report's static transform, filter-only trigger, and top/left spacing details. Any positioning fix belongs in the VS Code editor core; the documented overflowWidgetsDomNode workaround is not a fix for the default configuration.

## Evidence

- **Verified open canonical:** https://github.com/microsoft/monaco-editor/issues/2793 is open and labeled bug. Its reproduction enables fixedOverflowWidgets inside a transformed ancestor and shows widgets displaced by the container's horizontal offset. https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-998750348 explicitly extends the reproduction to hovering as well as typing.
- **Same underlying defect, additional trigger:** https://github.com/microsoft/monaco-editor/issues/4773 provides complete JavaScript, HTML, CSS, and a v0.52.0 playground link: hovering markers produces offsets that vary with the ancestor's top/left spacing. Either transform: translate(0px) or filter: drop-shadow(...) triggers the failure, without requiring animation. These properties establish a containing block for fixed descendants, matching the canonical's positioning problem.
- **Diagnosis and workaround:** https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-999337740 diagnoses fixed descendants being positioned relative to transformed parents and gives overflowWidgetsDomNode outside that subtree as a workaround. https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-2913390145 reports continued displacement in v0.52.2; this is historical confirmation, not a current-version retest.
