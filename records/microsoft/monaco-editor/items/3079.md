# Issue #3079 — [Bug] CSS Property value not highlighted when colon followed with newline

[https://github.com/microsoft/monaco-editor/issues/3079](https://github.com/microsoft/monaco-editor/issues/3079)

## Summary

The current CSS grammar still fails to recognize a declaration whose colon ends the line, leaving subsequent strings unhighlighted. Keep this accepted bug open; the defect is localized in Monaco's own language definition.

## Change summary

CSS string values lose syntax highlighting when a declaration's colon is immediately followed by a newline, including inside HTML style elements.

## Best solution

Correct declaration recognition in src/languages/definitions/css/css.ts so multiline values receive normal CSS tokens, while preserving existing selector handling. The existing grammar tests provide a bounded community-PR path.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/monaco-editor/issues/3079 supplies a complete HTML sample containing grid-template-areas: followed immediately by a newline and the strings "abc" and "hi"; the expected result is string highlighting.
- **Current grammar defect:** src/languages/definitions/css/css.ts, tokenizer.selectorbody, recognizes declarations with [*_]?@identifier@ws:(?=(\s|\d|[^{;}]*[;}])). On the line grid-template-areas:, the lookahead has no following character or terminator to match, so the tokenizer never enters @rulevalue. selectorbody has no string rule; the following quoted lines therefore receive the default empty token instead of string.css.
