# Issue #3079 — [Bug] CSS Property value not highlighted when colon followed with newline

[https://github.com/microsoft/monaco-editor/issues/3079](https://github.com/microsoft/monaco-editor/issues/3079)

## Summary

The highlighting defect remains traceable on current main, and the issue already has the correct CSS and basic-languages routing labels.

## Change summary

CSS string values are not highlighted when a declaration's colon is immediately followed by a newline.

## Best solution

Update the CSS Monarch tokenizer in src/languages/definitions/css/css.ts to recognize a declaration colon at end of line and enter the rule-value state, then add a multiline regression case to css.test.ts.

## Evidence

- **current source:** src/languages/definitions/css/css.ts:88-124 only enters @rulevalue when the declaration regex's post-colon lookahead finds whitespace, a digit, or content ending in ';' or '}' on the same tokenized line. A colon at end of line fails that lookahead, so following quoted lines remain in @selectorbody, which has no string rule.
- **missing regression coverage:** src/languages/definitions/css/css.test.ts covers ordinary declarations and escaped multiline strings but has no declaration whose colon ends one line and whose value begins on the next.
- **confirmed historical reproduction:** A maintainer demonstrated the broken highlighting in Monaco v0.36.1 at https://github.com/microsoft/monaco-editor/issues/3079#issuecomment-1466322080.
