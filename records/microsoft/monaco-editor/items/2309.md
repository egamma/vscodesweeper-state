# Issue #2309 — Control markers rendering in minimap

[https://github.com/microsoft/monaco-editor/issues/2309](https://github.com/microsoft/monaco-editor/issues/2309)

## Summary

A real API gap remains: diagnostic markers are rendered in the minimap unconditionally, while the current minimap options provide no control for suppressing or customizing them. The existing editor-minimap routing is appropriate.

## Change summary

Allow embedders to disable or customize how diagnostic markers appear in the minimap.

## Best solution

Add a general marker/diagnostic minimap visibility control in the VS Code editor core, then inherit it in Monaco during a release cut. This appears suitable for an editor-minimap design decision and potentially an open-for-PR contribution once the API shape is agreed.

## Vision fit

- **Fit:** rejected
- **Reason:** The capability fits the editor, but implementing Monaco-only editor behavior would conflict with the generated-from-VS-Code architecture; the API should originate in the VS Code editor core.
- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources," making the VS Code editor core the appropriate implementation location.
