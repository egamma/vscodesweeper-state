# Issue #4956 — Can CompletionItem support parameter control for showing or hiding details, without requiring selection to display？

[https://github.com/microsoft/monaco-editor/issues/4956](https://github.com/microsoft/monaco-editor/issues/4956)

## Summary

The requested control already exists: completion types/details can be displayed in every suggestion row through `CompletionItem.detail` and the `suggest.showInlineDetails` editor option, which defaults to enabled.

## Change summary

Allow custom completion items to show their type or detail text before the item is selected.

## Best solution

Populate `CompletionItem.detail` and leave `suggest.showInlineDetails` enabled; reserve `documentation` for the expanded, selection-specific details pane.

- **Fit:** aligned
- **Reason:** The existing editor option provides the API-based customization expected for Monaco embedders while preserving parity with the VS Code editor core.
- **Evidence:** The vision describes Monaco as generated from VS Code sources and says embedders integrate through its API.

- **Proposed comment:**

  > Thanks for the request. This is already supported by putting the type text in `CompletionItem.detail` and leaving `suggest.showInlineDetails` enabled (it defaults to `true`), for example `editor.updateOptions({ suggest: { showInlineDetails: true } })`. The `documentation` field belongs to the expanded details pane and is shown for the focused suggestion, while `detail` is rendered inline in the suggestion rows.
