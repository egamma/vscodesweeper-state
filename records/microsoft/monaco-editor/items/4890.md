# Issue #4890 — [Bug] setModelMarkers() with MarkerSeverity.Hint only underlines the first letter, regardless of the endColumn value

[https://github.com/microsoft/monaco-editor/issues/4890](https://github.com/microsoft/monaco-editor/issues/4890)

## Summary

This is intentional VS Code editor-core behavior rather than a Monaco defect: ordinary hint markers are deliberately rendered as a short dotted indicator regardless of the supplied end position.

## Change summary

Render a Hint marker across its complete range instead of limiting its underline to the range start.

## Best solution

Keep Monaco aligned with the VS Code editor core. The short hint indicator is by design; its range-clamping behavior could be clarified in the marker API documentation.

- **Proposed comment:**

  > Thanks for the report and the playground reproduction. This is intentional behavior inherited from the VS Code editor core: ordinary Hint markers have their decoration range shortened to `startColumn + 2` so they render as a compact dotted indicator, regardless of the supplied `endColumn` (https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/common/services/markerDecorationsService.ts#L190-L200). Monaco should remain aligned with VS Code here, so this can be closed as designed. The range-clamping behavior would be useful to clarify in the marker API documentation.
