# Issue #4717 — [Feature Request] Implement Cedar policy language by default

[https://github.com/microsoft/monaco-editor/issues/4717](https://github.com/microsoft/monaco-editor/issues/4717)

## Summary

Cedar validation remains a language-support request: existing tokenization, marker APIs, and LSP integration do not supply a Cedar validator. Keep open for a scope decision; the extension-loading question has a documented answer, but that does not resolve the requested language support.

## Change summary

Provide Cedar policy-language diagnostics without requiring embedders to implement its grammar and validation rules themselves.

## Best solution

Decide whether Monaco should bundle Cedar support or document integration with a separately supplied Cedar parser or language server. Diagnostics should originate from that language implementation, rather than bracket heuristics or direct execution of a VS Code extension.

- **Reason:** Cedar diagnostics through language-service integration fit the library's extensibility direction, although direct VS Code extension execution does not.
