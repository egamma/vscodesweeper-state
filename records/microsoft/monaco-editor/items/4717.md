# Issue #4717 — [Feature Request] Implement Cedar policy language by default

[https://github.com/microsoft/monaco-editor/issues/4717](https://github.com/microsoft/monaco-editor/issues/4717)

## Summary

This is an integration question rather than a missing Monaco behavior: VS Code extensions cannot run directly in Monaco, and the Cedar extension depends on the VS Code extension host.

## Change summary

Provide Cedar validation and diagnostics in a Monaco-based web application without reimplementing the language rules.

## Best solution

Integrate Cedar's browser-compatible parser or WASM package in the embedding application and convert its diagnostics to Monaco markers with `editor.setModelMarkers`; the existing VS Code extension cannot be loaded directly.

## Vision fit

- **Fit:** rejected
- **Reason:** Directly loading the Cedar VS Code extension conflicts with Monaco's deliberate browser-library boundary and lack of an extension host.
- **Evidence:** The README states that VS Code extensions do not work in Monaco and describes Monaco as a browser library generated from VS Code sources.

  > Thanks for the context. VS Code extensions cannot be loaded directly into Monaco; this is documented in the FAQ in README.md, and the Cedar extension at https://github.com/cedar-policy/vscode-cedar depends on the VS Code extension host rather than exposing a browser-compatible language server. For a web integration, the Cedar validation logic needs to run in your application and its diagnostics can then be converted to Monaco markers with `editor.setModelMarkers`. Integration questions are handled on StackOverflow under the `monaco-editor` tag: https://stackoverflow.com/questions/tagged/monaco-editor.
