# Issue #5221 — [Bug] onEnterRules fails with 'Javascript'

[https://github.com/microsoft/monaco-editor/issues/5221](https://github.com/microsoft/monaco-editor/issues/5221)

## Summary

The current source still allows JavaScript's asynchronously loaded configuration to replace the custom onEnterRules registered immediately after editor creation. Route this initialization-order defect to languages-basic and editor-api; no verified canonical or fixing commit was found.

## Change summary

Custom JavaScript onEnterRules stop applying when the built-in language configuration loads afterward.

## Best solution

Ensure built-in configuration loading in src/languages/definitions/_.contribution.ts preserves explicit embedder overrides regardless of initialization timing, while retaining unspecified JavaScript defaults. Coordinate with the VS Code standalone configuration API if resolving precedence requires upstream support.
