# Issue #4571 — [Bug] colorizeElement method doesn't color the whole text if domNode has more than one #text child

[https://github.com/microsoft/monaco-editor/issues/4571](https://github.com/microsoft/monaco-editor/issues/4571)

## Summary

The defect remains in the current VS Code standalone editor source: colorizeElement reads only the first text node and replaces the entire element's contents, discarding subsequent text nodes. Keep this report open and route it to editor-api; the fix belongs in microsoft/vscode.

## Change summary

colorizeElement drops text from subsequent adjacent text-node children instead of highlighting the complete text.

## Best solution

Correct text extraction in the VS Code standalone Colorizer so adjacent text nodes survive colorization, then deliver the change through Monaco's generated editor core. No verified open canonical was found for this specific truncation behavior.
