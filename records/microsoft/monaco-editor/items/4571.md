# Issue #4571 — [Bug] colorizeElement method doesn't color the whole text if domNode has more than one #text child

[https://github.com/microsoft/monaco-editor/issues/4571](https://github.com/microsoft/monaco-editor/issues/4571)

## Summary

The defect remains in the current vscode editor core: colorizeElement reads only firstChild.nodeValue before replacing the element contents, so subsequent text nodes are necessarily omitted. Route this confirmed bug to tokenization.

## Change summary

Make colorizeElement preserve and colorize all text represented by the target element rather than only its first child.

## Best solution

Update src/vs/editor/standalone/browser/colorizer.ts in microsoft/vscode to obtain the complete intended text before rendering, with coverage for multiple adjacent text nodes; the fix will flow into Monaco through the normal editor-core release cut.
