# Issue #4657 — [Feature Request]. Accessibility. Update accessibility support in Monaco editor to VSCode's support.

[https://github.com/microsoft/monaco-editor/issues/4657](https://github.com/microsoft/monaco-editor/issues/4657)

## Summary

A maintainer previously declined the same request because bundling accessibility sounds would increase Monaco's bundle size. Current VS Code source still deliberately registers a no-op accessibility-signal service for the standalone editor.

## Change summary

Add configurable VS Code-style accessibility sounds for editor events such as errors and warnings.

## Best solution

Keep sound assets out of Monaco's default bundle while preserving editor-core accessibility-signal call sites so embedders that need sounds can provide their own service implementation.

## Vision fit

- **Fit:** rejected
- **Reason:** Bundling VS Code's sound assets conflicts with Monaco's lean browser-library boundary and its preference for embedder-provided integration.
- **Evidence:** The vision guardrail says to keep the package lean and favor documented integration points over growing the default bundle.
