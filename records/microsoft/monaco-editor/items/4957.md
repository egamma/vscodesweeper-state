# Issue #4957 — [Bug] UTF-8 unicode characters break editor.setSelection()

[https://github.com/microsoft/monaco-editor/issues/4957](https://github.com/microsoft/monaco-editor/issues/4957)

## Summary

The example uses Unicode character counts where Monaco expects UTF-16 code-unit columns. The selection endpoint falls inside the emoji's surrogate pair and is intentionally normalized; this is API usage guidance rather than a defect.

## Change summary

The reporter expects columns 5–6 to select an emoji and columns 7–8 to select the following number.

## Best solution

Keep the existing coordinate contract and explain that the emoji occupies columns 5–7, while the number occupies columns 8–9. Use model.getPositionAt() when converting JavaScript string offsets to editor positions.
