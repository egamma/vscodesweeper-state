# Issue #4957 — [Bug] UTF-8 unicode characters break editor.setSelection()

[https://github.com/microsoft/monaco-editor/issues/4957](https://github.com/microsoft/monaco-editor/issues/4957)

## Summary

The observed behavior is intentional: Monaco columns are UTF-16 code-unit boundaries, and positions inside a surrogate pair are normalized to the start of that pair.

## Change summary

Treat an emoji as one column when selecting text through editor.setSelection().

## Best solution

Keep the existing UTF-16 coordinate semantics. Select the bomb with columns 5–7 and the number with columns 8–9.

  > Thanks for the report and playground example. Monaco positions use UTF-16 code-unit boundaries. The bomb emoji occupies columns 5–7, so `{ startColumn: 5, endColumn: 6 }` ends inside its surrogate pair; the editor intentionally normalizes that endpoint back to column 5. Use columns 5–7 to select the emoji, or 8–9 to select the number. This is the intended editor API behavior, so I’m closing this as designed.
