# Issue #5314 — [Bug] Why versions of marked and dompurify are fixed?

[https://github.com/microsoft/monaco-editor/issues/5314](https://github.com/microsoft/monaco-editor/issues/5314)

## Summary

Keep open for human security-sensitive triage. Dependency ranges cannot safely solve the reported warning while Monaco bundles specific versions of DOMPurify and marked; the broader unbundled-package design remains under discussion.

## Change summary

Allow semver ranges for DOMPurify and marked so npm can select patched transitive versions without waiting for a Monaco rebuild.

## Best solution

Continue updating the bundled sanitizer through the vscode-derived editor core, while resolving https://github.com/microsoft/monaco-editor/issues/5067 with an unbundled ESM distribution whose external dependencies can safely use ranges.

- **Proposed comment:**

  > Thanks for the report. The exact versions are intentional because Monaco currently bundles those specific DOMPurify and marked versions; changing only the package manifest to a range would not update the code shipped in Monaco and could give a false impression that the sanitizer was patched. The architectural work needed to support ranged external dependencies is tracked in https://github.com/microsoft/monaco-editor/issues/5067, while the current DOMPurify vulnerability updates are tracked in https://github.com/microsoft/monaco-editor/issues/5248.
