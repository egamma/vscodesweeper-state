- **Maintainer diagnosis and accepted direction:** https://github.com/microsoft/monaco-editor/issues/2264#issuecomment-752274000 explains that Ctrl+V generates a browser paste event whereas the custom menu requires programmatic clipboard access. The maintainer reproduced a Feature Policy rejection and proposed hiding Paste when access is permanently restricted.
- **Existing capability does not cover the request:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/clipboard/browser/clipboard.ts defines supportsPaste using navigator.clipboard availability, Firefox detection, and queryCommandSupported('paste'); its menu condition is editor writability, not iframe clipboard policy. Paste delegates to IClipboardService.readText(), so the inspected default behavior does not implement permission-aware hiding.
- **Standalone clipboard code path:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneServices.ts registers BrowserClipboardService as IClipboardService. In https://github.com/microsoft/vscode/blob/main/src/vs/platform/clipboard/browser/clipboardService.ts, readText() calls getActiveWindow().navigator.clipboard.readText(), logs failures, and returns an empty string; this does not make a policy-blocked menu paste equivalent to native Ctrl+V.

Parent-window clipboard access is not a general solution for cross-origin embedding.
