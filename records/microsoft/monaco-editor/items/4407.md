# Issue #4407 — [Feature Request] Close peek problem/definition window programmatically

[https://github.com/microsoft/monaco-editor/issues/4407](https://github.com/microsoft/monaco-editor/issues/4407)

## Summary

Programmatic dismissal already exists, but the discussion identifies a remaining limitation: the close command steals editor focus, while focus-preserving dismissal requires accessing an internal controller. Keep the public-API request open and route it to editor-api.

## Change summary

Provide an API to dismiss problem or definition peek widgets programmatically on application events.

## Best solution

Retain the existing close commands and decide whether to expose supported, focus-preserving dismissal without requiring internal contribution methods. Controller behavior belongs in the microsoft/vscode editor core, with any public Monaco API exposure coordinated here.

## Evidence

- **Existing capability and limitation:** The March 2025 comment on https://github.com/microsoft/monaco-editor/issues/4407 reports successful dismissal through editor.trigger('', 'closeMarkersNavigation', {}), but notes that it focuses the editor. The alternative uses editor.getContribution('editor.contrib.markerController').close(false).
- **Current controller behavior:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/gotoError/browser/gotoError.ts registers closeMarkersNavigation with handler x => x.close(); close(focusEditor = true) cleans up the widget and focuses the editor unless false is supplied. The command does not forward a focus option, and onDidChangeModel already invokes cleanup.
- **Public API boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts exposes trigger(source, handlerId, payload) and generic getContribution<T extends IEditorContribution>(id), but does not declare a dedicated peek-close method or the marker controller's close(false) contract.
- **Definition peek:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/gotoSymbol/browser/peek/referencesController.ts similarly provides internal closeWidget(focusEditor = true), while closeReferenceSearch invokes closeWidget() without a focus argument.
- **Earlier guidance, not an open canonical:** https://github.com/microsoft/monaco-editor/issues/2688 is closed. Its maintainer response, https://github.com/microsoft/monaco-editor/issues/2688#issuecomment-937897937, recommends editor.trigger('anything', 'closeMarkersNavigation', {}); it establishes the existing command but does not address focus-preserving dismissal.
- **Related report is distinct:** https://github.com/microsoft/monaco-editor/issues/5294 is open and concerns unhandled cancellation rejections during cross-file peek navigation, not the public dismissal API requested here. Searches for peek/API and closeMarkersNavigation found no verified open canonical owning the remaining request.
