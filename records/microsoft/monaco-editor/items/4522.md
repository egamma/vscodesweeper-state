# Issue #4522 — [Feature Request] How to introduce hover functionality on demand

[https://github.com/microsoft/monaco-editor/issues/4522](https://github.com/microsoft/monaco-editor/issues/4522)

## Summary

This asks how to conditionally provide hover content, rather than identifying a missing capability. Existing hover-provider APIs support conditional results and registration on demand.

## Change summary

Show custom variable hover information only when the application's breakpoint condition permits it.

## Best solution

Use the existing provider contract: return null when the breakpoint condition is false, or register and dispose the provider as needed. No library change is established by this report.

  > Thanks for the context. For conditional hover content, your existing provider can return `null` when `breakpointFlag.value` is false; the commented guard in your example already follows that pattern. Alternatively, register the provider when needed and call `.dispose()` on the returned registration to remove it. These control your custom provider, not other providers registered for the language.
