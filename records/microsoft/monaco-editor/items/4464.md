## Summary

Keep this request open and route it to TypeScript: the public compiler-option enums still omit exports-aware resolution modes, although the bundled TypeScript supports them. Neither full coverage of the requested behavior nor a matching canonical issue was verified.

## Change summary

Support package.json conditional exports and mapped subpath typings for packages registered through addExtraLib or setExtraLibs.

## Best solution

First distinguish the missing public configuration surface from the separately reported worker serialization failure.

- **Behavior:**

  > Embedders should be able to configure exports-aware TypeScript resolution through supported public APIs. Packages supplied as extra libraries should resolve root and mapped subpath imports to their declaration files without requiring barrel files or physical dist paths in imports. Language features must complete without worker serialization errors. Legacy main and typings packages should retain their existing behavior.
- **Trace:**

  > register.ts copies a restricted set of TypeScript enums, while the bundled typescriptServices.d.ts declares modern resolution modes and package-exports options. setCompilerOptions passes configuration through workerManager.ts to TypeScriptWorker.getCompilationSettings; TypeScriptWorker.readFile and fileExists expose extra-library contents to the language service. This establishes a public configuration gap, not a conclusive failure of all runtime exports resolution. The reporter's later direct-import DataCloneError may involve worker-returned language-service objects; tsWorker.ts:getCompletionsAtPosition returns CompletionInfo directly, but the failing RPC has not been identified.
