# Issue #5260 — [Bug] Tooltips do not work with webcomponents

[https://github.com/microsoft/monaco-editor/issues/5260](https://github.com/microsoft/monaco-editor/issues/5260)

## Summary

Verified duplicate of the older, open shadow-DOM hover issue: both identify the same mouseHandler containment check and the same composedPath workaround.

## Change summary

Tooltips fail inside web components because document-level mouse events are retargeted to the shadow host.

## Best solution

Consolidate on https://github.com/microsoft/monaco-editor/issues/3409 and fix shadow-aware mouse-leave detection in the VS Code editor core; preserve this report's ESM fork workaround there.

- **Exact matching failure:** https://github.com/microsoft/monaco-editor/issues/3409#issuecomment-2868006322 identifies the identical ESM mouseHandler.js containment check and the exact e.target-to-e.composedPath()[0] replacement reported here.
- **Current upstream source:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/controller/mouseHandler.ts still installs a document-level mousemove listener that checks viewDomNode.contains(e.target) and calls _onMouseLeave when false. For an editor inside a shadow root, the retargeted host is outside viewDomNode, explaining premature hover dismissal.
- **Fork is not an official fix:** https://github.com/microsoft/monaco-editor/issues/5260#issuecomment-4322774881 reports a fix in https://github.com/node-projects/monaco-editor-esm, not in official Monaco. The canonical's earlier implementation attempt, https://github.com/microsoft/vscode/pull/166240, is closed and unmerged.
