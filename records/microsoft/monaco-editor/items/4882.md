# Issue #4882 — https://github.com/ajaxorg/ace/issues/5797

[https://github.com/microsoft/monaco-editor/issues/4882](https://github.com/microsoft/monaco-editor/issues/4882)

## Summary

Python syntax checking is intentionally an integration concern rather than a bundled Monaco language worker. Monaco provides Python tokenization and native LSP APIs for connecting a Python language server.

## Change summary

Bundle a Python worker that performs syntax checking like Monaco's JavaScript and TypeScript workers.

## Best solution

Keep Python syntax checking outside the default package and connect an appropriate Python language server through Monaco's exported `lsp` APIs. The existing Python definition should remain responsible for basic language registration and tokenization.

## Vision fit

- **Fit:** rejected
- **Reason:** Bundling another language service conflicts with Monaco's browser-library boundary, while external language features are expected to integrate through LSP.
- **Evidence:** The vision describes Monaco as a browser library rather than an app platform and identifies native LSP support as the path for language features beyond the bundled workers.

- **Proposed comment:**

  > Thanks for the request. Monaco includes Python tokenization, but a Python syntax checker requires a separate Python language service and is not planned as another bundled worker. Monaco now exports native LSP client APIs through its `lsp` namespace; connecting an appropriate Python language server there is the supported direction, consistent with the earlier guidance in https://github.com/microsoft/monaco-editor/issues/421. Closing this as outside the scope of the built-in language workers.

- **current Python support:** `src/languages/definitions/python/register.ts` registers Python extensions and loads its basic language definition, but does not define a Python validation worker.

- **existing guidance:** The earlier Python worker discussion at https://github.com/microsoft/monaco-editor/issues/421 directs embedders to connect a Python language server rather than adding a bundled worker.
- **maintainer precedent:** In https://github.com/microsoft/monaco-editor/issues/2836#issuecomment-995989382, a Monaco maintainer similarly directed custom language-service integration to a language client.
