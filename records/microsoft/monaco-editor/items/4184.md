## Plan brief

- **Validation:** Compare production TypeScript worker byte sizes before and after the change, checking the reported 4 MB threshold. Verify DOM and WebWorker completions and diagnostics, including CanvasDrawPath APIs, with their respective compiler library configurations.
- **Behavior:**

  > The TypeScript worker contains overlapping declaration text that contributes to a browser-extension file-size constraint. Reduce redundant storage without removing supported library environments or changing completions and diagnostics. Acceptance requires measuring the built worker rather than assuming that repeated declarations account for enough bytes to reach the reported limit.
- **Trace:**

  > Current src/languages/features/typescript/lib/lib.ts embeds CanvasDrawPath separately in lib.dom.d.ts and lib.webworker.d.ts. build/importTypescript.ts::importLibs serializes whole library files independently, while src/languages/features/typescript/tsWorker.ts::_getScriptText serves their contents by filename. These are distinct TypeScript library contexts, so textual overlap alone does not establish that declarations can be deleted. The trace establishes redundant storage but not a semantics-preserving representation or achievable worker size. The importer still names src/language/typescript/lib while checked-in consumers live under src/languages/features/typescript; establish the active generation path before proceeding. Preserve library selection and public worker behavior. Downstream context: https://github.com/ergofriend/Quiqsearch/issues/13 and https://github.com/arnoudkooi/SN-Utils/issues/437.

## Evidence

Repeated declaration text is embedded data, not necessarily duplicated executable code; deleting declarations indiscriminately could change language-service behavior.
