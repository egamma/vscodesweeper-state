# Issue #608 — Provider APIs and addCommand don't work well together

[https://github.com/microsoft/monaco-editor/issues/608](https://github.com/microsoft/monaco-editor/issues/608)

## Summary

The provider/command scope mismatch is addressed by monaco.editor.registerCommand, shipped in v0.22.0. Providers can reference one explicitly named global command across multiple editors without changing editor.addCommand.

## Change summary

Allow globally registered providers to reference a stable command identifier that works across editor instances.

## Best solution

Use monaco.editor.registerCommand once with a shared ID, and return that ID in provider commands. Close as completed while retaining editor.addCommand for editor-local commands.

## Vision fit

- **Fit:** aligned
- **Reason:** A shared command registration API supports browser embedders through the public API without introducing an extension host.
- **Evidence:** Layer 1 identifies API surface and language-worker integration as the aligned form of extending the browser library.

  > Thanks for the report. This is now supported through `monaco.editor.registerCommand(id, handler)`, added in https://github.com/microsoft/vscode/commit/7c937a7a383ca131c5e36811d4440878c97a1191 and shipped in Monaco v0.22.0. Register the shared handler once with a chosen ID, then use that ID in the CodeLens provider's `command.id` for all editors. The handler receives a services accessor before the command arguments. This addresses the scope mismatch without requiring per-editor command IDs, so this can be closed as completed.
