# Issue #3468 — [Bug] monaco.languages.Command.id should be typed as optional

[https://github.com/microsoft/monaco-editor/issues/3468](https://github.com/microsoft/monaco-editor/issues/3468)

## Summary

The typing gap remains on current main: CodeLens renders a command title without a command ID as non-clickable text, while the shared Command interface still requires an ID. The existing feature-request and editor-core routing remain appropriate.

## Change summary

Represent non-clickable CodeLens labels without requiring a fictitious command ID.

## Best solution

Model the CodeLens-specific display-only command shape in the vscode editor core without weakening the ID requirement for executable commands globally, then inherit that API change in Monaco.

- **Fit:** aligned
- **Reason:** Accurate API typing for supported editor behavior improves Monaco's browser-embedding surface while preserving parity with the vscode-derived editor core.
- **Evidence:** The vision identifies Monaco as generated from VS Code sources and states that embedders integrate through its API.

## Evidence
