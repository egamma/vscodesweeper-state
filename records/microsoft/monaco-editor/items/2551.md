# Issue #2551 — Support Pure Javascript/Typescript Expression

[https://github.com/microsoft/monaco-editor/issues/2551](https://github.com/microsoft/monaco-editor/issues/2551)

## Summary

Keep this accepted request open and route it to typescript: the bundled language service still lacks an expression-only mode. The maintainer-linked wrapper request is closed, and its workarounds do not establish that this capability shipped.

## Change summary

Provide JavaScript and TypeScript expression-only editing rather than treating input as a complete script.

## Best solution

Design expression-context support in Monaco's bundled TypeScript language integration, preserving useful language features without requiring hidden wrapper text. Settle the public configuration and statement-handling contract before implementation.

- **Reason:** Expression-context support extends the bundled language experience through an embedder-facing integration rather than adding app-platform functionality.

## Plan brief

- **Likely files:** `src/languages/features/typescript/register.ts`, `src/languages/features/typescript/tsMode.ts`, `src/languages/features/typescript/tsWorker.ts`, `src/languages/features/typescript/languageFeatures.ts`
- **Validation:** Use a playground sample for both JavaScript and TypeScript: accept arithmetic and object-literal expressions in expression context, handle declarations and multiple statements according to the agreed contract, preserve completion and diagnostic positions, and leave ordinary script models unchanged.
- **Behavior:**

  > Embedders need an editing context for a JavaScript or TypeScript expression rather than a complete script. Object literals should be interpreted as expressions, with useful completion and correctly positioned diagnostics. Acceptance should cover arithmetic, object literals, invalid expressions, and unchanged ordinary script editing. The public configuration and whether statements are diagnosed or prevented remain to be agreed.
- **Trace:**

  > src/languages/features/typescript/tsMode.ts initializes javascript and typescript language services. In tsWorker.ts, TypeScriptWorker::_getScriptText returns model text unchanged, getScriptSnapshot exposes that text, and getScriptKind selects JS/TS variants rather than an expression context. register.ts provides extra libraries, diagnostic filtering and a custom-worker hook, but none is a turnkey expression-only mode. languageFeatures.ts::DiagnosticsAdapter requests syntactic and semantic diagnostics from the worker. https://github.com/microsoft/monaco-editor/issues/1661 discusses broader wrapping workarounds, while https://github.com/saltcorn/saltcorn/issues/3779 supplies a concrete object-expression use case. Preserve ordinary script behavior and keep wrapper text out of user-visible content; no implementation or runtime validation was performed.
- **Open decisions:**
  - Should expression context be exposed through the proposed javascript.expression/typescript.expression language IDs or through configuration on existing language modes?
  - Should expression-only editing diagnose statements while allowing their entry, or actively prevent non-expression input?
