# Issue #5519 — ESM build evaluates in one ~250 ms long task; the AMD build splits it up

[https://github.com/microsoft/monaco-editor/issues/5519](https://github.com/microsoft/monaco-editor/issues/5519)

## Summary

Route to ESM: existing modular imports partially address loading cost but do not provide the requested scheduling guidance or finer editor-core entry points. The reported measurements support investigating this migration gap, not treating it as already solved.

## Change summary

Provide supported finer-grained or staged ESM loading that reduces uninterrupted main-thread evaluation during migration from AMD.

## Best solution

Document a measured, bundler-aware staged-loading pattern in docs/integrate-esm.md without promising a universal task-duration bound. If the remaining editor import requires finer core boundaries, that work belongs in microsoft/vscode and must flow into Monaco's supported exports.
