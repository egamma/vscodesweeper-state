# Issue #4499 — [Bug] loadForeignModule error after I use editor with language json

[https://github.com/microsoft/monaco-editor/issues/4499](https://github.com/microsoft/monaco-editor/issues/4499)

## Summary

The supplied reproduction needs Next.js worker-configuration guidance rather than a Monaco fix: it passes a webpack plugin to next-compose-plugins and selects no language workers.

## Change summary

Switching from Groovy to JSON and back produces loadForeignModule errors in the supplied Next.js application.

## Best solution

Register MonacoWebpackPlugin in the application's client webpack configuration and include the JSON and TypeScript workers required by JSON and JavaScript. Track a Monaco defect separately if the failure persists with correctly configured workers.

  > Thanks for the reproduction. In next.config.js, MonacoWebpackPlugin is passed to next-compose-plugins instead of being registered in webpack's plugins array, and languages: [] excludes the language workers. Register it through Next.js's client webpack configuration and include json and typescript if you use JSON and JavaScript; JavaScript shares the TypeScript worker.
