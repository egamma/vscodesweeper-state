# Issue #3587 — [Bug] Problem using Monaco 'wordWrapColumn', editor scrolls outside of view

[https://github.com/microsoft/monaco-editor/issues/3587](https://github.com/microsoft/monaco-editor/issues/3587)

## Summary

Keep open: the supplied playground and browser-specific steps suffice to retest, and the suspected textarea focus mechanism remains in the VS Code sources pinned by current Monaco main. Input handling has moved since the report, but current browser behavior was not verified and no fix or same-symptom canonical was established.

## Change summary

Focusing or typing on a long line with wordWrapColumn unexpectedly scrolls the editor's overflow guard horizontally, moving content out of view.

## Best solution

Resolve unintended horizontal scrolling in the VS Code editor-core textarea focus path while preserving accessible wrapping and intentional editor scrolling, then deliver the change through Monaco's core update. Retest the existing sample in Chrome and Safari, including overflow-hidden ancestors; the proposed overflow-clip workaround is incomplete.

## Evidence

- **Concrete reproduction and historical confirmation:** https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-1441530602 supplies a simplified playground without web components: clicking causes the Chrome failure; typing at the end of line 4 triggers it in Safari; Firefox works. A maintainer confirmed the original defect at https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-1441465573. These are historical confirmations, not a current-version retest.
- **Focus and horizontal-scroll diagnosis:** https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-1450728048 identifies textarea.focus() revealing the caret in a wide textarea and reports that forcing width to zero prevents the failure. https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-1441839842 reports that resetting .overflow-guard.scrollLeft restores the display.
- **Mechanism remains in the adopted core:** package.json pins vscodeRef c132f72ae9f5ff80093e7d722c36f03755865b20. At https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/browser/controller/editContext/textArea/textAreaEditContextInput.ts#L784-L791, setSelectionRange still calls textArea.focus() without preventScroll and restores parents through saveParentsScrollTop/restoreParentsScrollTop. Those helpers only preserve scrollTop, not scrollLeft: https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/base/browser/dom.ts#L1422-L1437. This supports the diagnosis but does not establish current browser reproduction.
- **Accessible wrapping constrains a fix:** https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts#L564-L577 intentionally sizes the textarea to the wrapping column when accessibility support is not disabled, so an unconditional zero-width workaround could change screen-reader behavior.
- **Workaround is explicitly partial:** https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-2176623924 provides a v0.50.0 playground with overflow: clip, then explains that overflow-hidden ancestors may still scroll and asks about preventScroll. A maintainer previously invited a PR at https://github.com/microsoft/monaco-editor/issues/3587#issuecomment-1465790097; the thread supports addressing the defect rather than declining it.
- **Canonical search:** Searches covering wordWrapColumn, overflow-guard, textarea scrolling, and focus scrolling found no verified same-symptom canonical. https://github.com/microsoft/monaco-editor/issues/4042 is open and shares the focus call, but reports vertical page jumps when programmatically refocusing an offscreen editor in Safari, not horizontal overflow during wrapped-line editing. The supplied candidates https://github.com/microsoft/monaco-editor/issues/4689, https://github.com/microsoft/monaco-editor/issues/4491, and https://github.com/microsoft/monaco-editor/issues/1858 concern line rendering, ghost-text wrapping, and view-zone positioning respectively, not this observable failure.
