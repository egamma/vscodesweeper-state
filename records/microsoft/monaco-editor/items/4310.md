# Issue #4310 — [Bug] Loading monaco via require doesn't always respect urlArgs parameter

[https://github.com/microsoft/monaco-editor/issues/4310](https://github.com/microsoft/monaco-editor/issues/4310)

## Summary

Keep open: the supplied AMD sample and network symptoms suffice to retest, but the worker-loading implementation changed after the reports and current behavior is unverified. The newer related issue covers worker 404s, not the full cache-busting problem reported here.

## Change summary

AMD loading inconsistently applies urlArgs, omitting or duplicating cache-busting parameters and reportedly producing malformed language-worker URLs.

## Best solution

Retest the supplied configuration against the current AMD packaging, covering worker URLs and localization requests rather than only initial editor assets. Retain this broader report unless its full scope is verified resolved; versioned distribution paths are the maintainer-suggested workaround, while ESM is the supported migration direction.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/monaco-editor/issues/4310 supplies an HTML configuration using the bundled loader, urlArgs: "v=0.35.0", and a JavaScript editor. Reported requests duplicate the parameter on workerMain.js and omit it on simpleWorker.nls.js.
- **Later corroboration:** https://github.com/microsoft/monaco-editor/issues/4310#issuecomment-2967439255 reports malformed tsWorker.js URLs with the same configuration in June 2025. This corroborates historical failure but does not establish reproduction on current main.
- **Related issue is narrower:** Verified https://github.com/microsoft/monaco-editor/issues/4925 is open. Its Monaco 0.52.2 sample and https://output.jsbin.com/fiyupox target language-worker 404s with an injected /vs/bas path segment; it does not establish coverage of omitted localization parameters or duplicated worker parameters.
- **Current implementation differs:** build/amd/src/editor.main.ts now installs MonacoEnvironment.getWorker and bootstraps workers through Blob URLs and importScripts. build/amd/plugin.js rewrites worker imports, and build/amd/vite.config.mjs produces AMD bundles. These changes prevent assuming that the older workerMain/defaultWorkerFactory symptoms remain unchanged; no build or browser reproduction was performed.
- **Loader and support boundary:** build/amd/src/loader.js retains urlArgs handling in _addUrlArgsToUrl and moduleIdToPaths. README.md deprecates AMD, and CHANGELOG.md records significant AMD changes and withdrawal of support in 0.53.0; neither establishes that this accepted bug was fixed.
- **Maintainer workaround:** https://github.com/microsoft/monaco-editor/issues/4310#issuecomment-1878410700 suggests putting the Monaco version in distribution paths. The thread contains no confirmation that this resolves every reported request or a maintainer decision declining the defect.
