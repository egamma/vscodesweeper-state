# Issue #2521 — Can't override default autocomplete suggestions

[https://github.com/microsoft/monaco-editor/issues/2521](https://github.com/microsoft/monaco-editor/issues/2521)

## Summary

Keep open: disabling all built-in completions does not cover selectively replacing a library suggestion while preserving other JavaScript completions. Current source exposes no direct replacement hook, and the canonical search found no verified duplicate.

## Change summary

Allow custom library completions to replace corresponding built-in suggestions rather than appearing alongside them.

## Best solution

Define a supported customization contract for JavaScript/TypeScript completions that preserves unrelated built-in suggestions. Start with Monaco's language adapter; any generic precedence rule between independent completion providers belongs in the VS Code editor core.

## Plan brief

- **Likely files:** `src/languages/features/typescript/register.ts`, `src/languages/features/typescript/tsMode.ts`, `src/languages/features/typescript/languageFeatures.ts`
- **Validation:** Run the supplied Facts.next() example in the playground: completion after Facts. must show one customized next entry inserting next(), while unrelated built-in JavaScript completions remain available. Without customization, existing completion behavior must remain unchanged.
- **Behavior:**

  > The supplied JavaScript example adds a Facts.next() declaration and a custom completion for the same member, producing competing suggestions. The requested capability lets the embedder replace that member's completion, including its insertion text and documentation, without losing unrelated built-in completions. Acceptance should cover a single customized next entry, insertion of next(), preservation of unrelated suggestions, and unchanged behavior when customization is absent.
- **Trace:**

  > src/languages/features/typescript/tsMode.ts registers SuggestAdapter when ModeConfiguration.completionItems is enabled; this setting controls the whole provider. SuggestAdapter.provideCompletionItems in src/languages/features/typescript/languageFeatures.ts maps worker entries directly and uses entry.name for both label and insertion text. Custom worker subclasses are supported by tsWorker.ts, but their results still pass through this mapping. These observations establish the existing customization boundary, not a current runtime reproduction. https://github.com/microsoft/monaco-editor/issues/4228 concerns related worker-entry metadata but is not a duplicate. Preserve default completion behavior and unrelated language features; generic arbitration between independent providers is outside this repository's editor-core ownership.
- **Open decisions:**
  - Should the supported contract customize entries within the bundled JavaScript/TypeScript provider, or allow separately registered providers to replace its matching entries? The latter requires an editor-core contract in microsoft/vscode.
