Keep this TypeScript performance improvement open: current main still scans mirror models for each script lookup, and the discussion supplies an independently reported optimization. Existing library-registration APIs do not establish that repeated completion delays with thousands of models are resolved.

## Change summary

Reduce repeated IntelliSense latency when thousands of TypeScript source or declaration models are loaded.

## Best solution

Improve model-lookup scalability in Monaco's TypeScript worker while preserving model updates and URI matching. Evaluate the reported indexed-lookup approach with the VS Code worker-context boundary in mind, comparing repeated completion requests with and without mirrored declaration models.

- **Discussion confirms continuing demand:** A maintainer confirmed reproduction and questioned the additional createModel calls at https://github.com/microsoft/monaco-editor/issues/3355#issuecomment-1348810987. A separate embedder reported the same problem on v0.52.0 and supplied a two-part lookup optimization at https://github.com/microsoft/monaco-editor/issues/3355#issuecomment-2756951382; neither establishes a current-version runtime reproduction.
- **Current lookup path:** src/languages/features/typescript/tsWorker.ts:65–115 still enumerates mirror models in getScriptFileNames and linearly scans them in _getModel, called by getScriptVersion and _getScriptText. This retains the identified scaling concern, but source inspection alone does not establish current completion timings.
- **Existing-capability check:** src/languages/features/typescript/register.ts documents addExtraLib and setExtraLibs for declarations not opened as editor documents. workerManager.ts passes these libraries to the worker independently of eager model synchronization. Avoiding redundant declaration models is a useful comparison, not coverage of the request to handle thousands of actual source models efficiently.
- **Cross-repository boundary:** The supplied patch changes both Monaco's TypeScript worker and the VS Code-derived editor worker. https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/services/editorWebWorker.ts currently exposes getMirrorModels on IWorkerContext, not the patch's getMirrorModelMap API; the patch is not evidence of an adopted upstream fix.
- **Canonical search:** Searches for bulk-model, IntelliSense, performance, and mirror-model lookup reports found no verified canonical for the same recurring completion delay. The older open https://github.com/microsoft/monaco-editor/issues/1300 requests notification when extra-library processing finishes, not faster repeated completions with many models, so it does not satisfy the re-review duplicate bar.
