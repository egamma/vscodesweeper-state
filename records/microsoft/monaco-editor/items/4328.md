# Issue #4328 — [Bug] Unable to access redirected JSON Schema URL

[https://github.com/microsoft/monaco-editor/issues/4328](https://github.com/microsoft/monaco-editor/issues/4328)

## Summary

The failure is caused by the schema host's redirect response lacking CORS permission, not by Monaco's redirect handling. Browser security prevents Monaco and vscode.dev from following that response, while VS Code Desktop is unaffected.

## Change summary

Loading a JSON schema fails when its URL redirects without allowing cross-origin browser requests.

## Best solution

The schemas.wp.org server should include an appropriate Access-Control-Allow-Origin header on its redirect response. Embedders can meanwhile use the final raw.githubusercontent.com schema URL directly.

- **Proposed comment:**

  > Thanks for the detailed reproduction. The JSON worker uses the browser's standard `fetch`, and the initial 301 response from https://schemas.wp.org/trunk/theme.json currently lacks an `Access-Control-Allow-Origin` header. Browsers therefore block the redirect before reaching the CORS-enabled raw.githubusercontent.com response; Monaco cannot bypass that browser restriction. The schema host needs to allow cross-origin requests on the redirect, or the final https://raw.githubusercontent.com/WordPress/gutenberg/trunk/schemas/json/theme.json URL can be used directly.

## Evidence

- **current source:** src/languages/features/json/jsonWorker.ts:11-15 loads enabled schemas through the browser's standard fetch(url), which follows redirects but cannot bypass CORS.
- **redirect response:** A current request to https://schemas.wp.org/trunk/theme.json returns HTTP 301 to https://raw.githubusercontent.com/WordPress/gutenberg/trunk/schemas/json/theme.json without an Access-Control-Allow-Origin header.
- **destination response:** The redirected raw.githubusercontent.com response returns HTTP 200 with Access-Control-Allow-Origin: *, explaining why the final URL works when used directly.
- **environment boundary:** The report reproduces in Monaco and vscode.dev but works in VS Code Desktop, matching browser CORS enforcement rather than an editor-specific failure.
