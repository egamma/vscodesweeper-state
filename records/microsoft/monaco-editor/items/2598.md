# Issue #2598 — Bug: some actions are missing, including cut/copy/paste/undo/redo/etc.

[https://github.com/microsoft/monaco-editor/issues/2598](https://github.com/microsoft/monaco-editor/issues/2598)

## Summary

Keep open: command execution exists, but the requested action lookup and standalone command-palette coverage remain missing in current VS Code sources. Browser clipboard shortcuts are deliberately delegated to the browser, so the missing shortcut labels are a separate presentation concern.

## Change summary

Expose basic clipboard and undo/redo commands consistently through editor actions, the command palette, and context-menu shortcut labels.

## Best solution

Resolve the action-versus-command discoverability gap in the VS Code standalone editor sources, while preserving browser-native clipboard handling. Existing trigger/addAction APIs offer partial workarounds, not complete coverage of this request.

## Evidence

- **Existing capability and remaining gap:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts populates _actions from getEditorActions(); getAction() only looks in that map. trigger() also dispatches registered commands, so command execution does not imply availability through getAction().
- **Clipboard registration and shortcuts:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/clipboard/browser/clipboard.ts registers CutAction, CopyAction and PasteAction as MultiCommand instances, not EditorAction instances. Their kbOpts are undefined in browsers, explicitly to preserve browser handling and avoid security prompts.
- **Standalone palette gap:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/quickAccess/standaloneCommandsQuickAccess.ts uses getCodeEditorCommandPicks() and supplies no additional command picks. https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/quickAccess/browser/commandsQuickAccess.ts builds those picks from getSupportedActions(); clipboard MenuId.CommandPalette registrations therefore do not establish standalone palette coverage.
- **Undo and redo capability:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/coreCommands.ts implements Undo and Redo as commands that invoke model.undo()/redo(), rather than editor actions. Existing execution paths do not satisfy the requested action discoverability.
- **Referenced report is not a canonical:** https://github.com/microsoft/monaco-editor/issues/2195 is closed. Its discussion confirms the earlier missing-action symptoms and provides an addAction workaround at https://github.com/microsoft/monaco-editor/issues/2195#issuecomment-711471692. A closed report cannot serve as a duplicate target; searches for clipboardCutAction, getAction and undo/actions found no verified open canonical owning this request.
- **Repository boundary:** README.md states that Monaco is generated from VS Code sources. The inspected action registry, clipboard registrations and standalone palette live in microsoft/vscode, not this checkout; no browser reproduction was executed.
