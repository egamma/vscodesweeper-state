# Issue #4794 — [Bug]  applyEdits nonsupport undoed

[https://github.com/microsoft/monaco-editor/issues/4794](https://github.com/microsoft/monaco-editor/issues/4794)

## Summary

This is expected API behavior rather than a Monaco defect: `ITextModel.applyEdits` bypasses the undo stack. Undoable changes should use `editor.executeEdits`, with `editor.pushUndoStop` where an explicit undo boundary is needed.

## Change summary

Make a programmatic model edit undoable with the editor's normal undo command.

## Best solution

Use `editor.executeEdits` for this editor-attached model and add `pushUndoStop` before or after the operation as appropriate; retain `applyEdits` for changes that should not enter the undo stack.

- **Proposed comment:**

  > Thanks for the report and example. `model.applyEdits` intentionally does not add an entry to the undo stack; its second argument computes and returns inverse edits rather than making the operation undoable. For a model attached to this editor, use `myEditor.executeEdits(...)`, with `myEditor.pushUndoStop()` before or after it when you need an explicit undo boundary. This distinction is also explained in https://github.com/microsoft/monaco-editor/issues/192#issuecomment-247984157. For further usage questions, please use the StackOverflow `monaco-editor` tag: https://stackoverflow.com/questions/tagged/monaco-editor.

## Evidence

- **documented API distinction:** A maintainer explains the supported distinction at https://github.com/microsoft/monaco-editor/issues/192#issuecomment-247984157: use `editor.executeEdits` when undo should work, `model.pushEditOperations` for a detached model, and `model.applyEdits` when the undo stack is not needed.
- **current editor-core implementation:** Current source at https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/model/textModel.ts shows `applyEdits` applying changes directly through `_doApplyEdits`, while `pushEditOperations` records them through the undo/redo command manager.
