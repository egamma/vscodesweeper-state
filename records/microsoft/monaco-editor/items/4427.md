# Issue #4427 — [Feature Request] Add support for X position of a line decoration

[https://github.com/microsoft/monaco-editor/issues/4427](https://github.com/microsoft/monaco-editor/issues/4427)

## Summary

The API still lacks per-decoration horizontal placement for overlapping line-decoration bars. Route to editor-api; the existing glyph lanes and related gutter requests do not fully cover this request.

## Change summary

Allow overlapping license-range decorations to appear side by side at independently specified horizontal positions in the line-decoration gutter.

## Best solution

Evaluate a supported horizontal-placement contract for line decorations in the microsoft/vscode editor core, inherited by Monaco. Preserve the distinction between line decorations and glyph-margin lanes rather than treating migration to glyphs as complete coverage.

## Evidence

- **Requested capability:** https://github.com/microsoft/monaco-editor/issues/4427 describes overlapping license ranges rendered with linesDecorationsClassName and requests independent X offsets so all colored bars remain visible.
- **Existing API does not cover placement:** The published declarations at https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts expose lineDecorationsWidth as the width of the shared strip between line numbers and content. IModelDecorationOptions.linesDecorationsClassName has no per-decoration horizontal-position field; glyphMargin.position selects GlyphMarginLane in a different gutter region.
- **Current renderer:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/viewParts/linesDecorations/linesDecorations.ts: LinesDecorationsOverlay.prepareRender constructs one common inline left and width from layoutInfo and applies it to every rendered decoration. _getDecorations carries class names, ranges, tooltips and zIndex, but no individual X offset. CSS customization is not a supported placement API.
- **Canonical search:** Verified open https://github.com/microsoft/monaco-editor/issues/322 requests custom gutter content, while https://github.com/microsoft/monaco-editor/issues/4785 requests per-line custom visualizations. Neither reports the same overlapping-bar placement problem required for a duplicate close of this re-reviewed item; the latter is also newer.
- **Related but distinct upstream work:** Verified open https://github.com/microsoft/vscode/issues/179725 concerns glyph-margin icons, breakpoint lanes, overflow and click handling, not independently positioned linesDecorationsClassName bars. It is related design context, not a verified canonical for this request.
- **Implementation boundary:** The checkout README.md states that Monaco is generated from VS Code sources. The relevant renderer lives in microsoft/vscode, not this repository's language workers, packaging or website.
