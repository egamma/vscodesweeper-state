# Issue #2036 — Support middle-clicks in the opener service

[https://github.com/microsoft/monaco-editor/issues/2036](https://github.com/microsoft/monaco-editor/issues/2036)

## Summary

The requested mouse-button context remains missing: middle-click link activation exists, but opener callbacks cannot distinguish it from other activation. Route to editor-api; the relevant implementation lives in the VS Code sources.

## Change summary

Expose the activating mouse button to link openers so embedders can handle middle-clicks differently.

## Best solution

Consider an optional activation context for link openers in the VS Code editor core and standalone API, preserving existing callbacks and keyboard activation. Existing middle-click activation does not satisfy the request to distinguish buttons.

## Evidence

- **Existing API does not cover the request:** CHANGELOG.md records registerLinkOpener in v0.37.0. In https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneEditor.ts, ILinkOpener.open accepts only a URI, and registerLinkOpener forwards only that resource.
- **Mouse context is not forwarded:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/links/browser/links.ts recognizes middle-click activation when mouseMiddleClickAction is openLink, but onEditorMouseUp passes only openToSide and fromUserGesture to openLinkOccurrence. Its openerService.open options contain no mouse-button information.
- **Service contract:** https://github.com/microsoft/vscode/blob/main/src/vs/platform/opener/common/opener.ts defines OpenInternalOptions and OpenExternalOptions without a button property. fromUserGesture identifies user activation, not which button initiated it.
