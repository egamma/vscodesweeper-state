# Issue #2036 — Support middle-clicks in the opener service

[https://github.com/microsoft/monaco-editor/issues/2036](https://github.com/microsoft/monaco-editor/issues/2036)

## Summary

A real API gap remains: current editor code can trigger links on middle-click, but registered link openers receive only the URI and cannot distinguish the originating mouse button. Route this to editor-api; the implementation belongs in the vscode editor core.

## Change summary

Expose the mouse button used to activate a link to custom link-opener handlers.

## Best solution

Extend the vscode editor-core opener API with activation metadata and forward the middle-button state from the link gesture through `links.ts` to registered `ILinkOpener` callbacks. Monaco will inherit that API in a subsequent release.

## Vision fit

- **Fit:** rejected
- **Reason:** The capability is relevant to embedders, but this editor-core API must land in microsoft/vscode rather than evolve independently in Monaco.
- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources with some shims around services the code needs to make it run in a web browser."
