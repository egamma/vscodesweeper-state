# Issue #5168 — [Bug] Keyboard input cannot be performed normally when certain browser plugins are present

[https://github.com/microsoft/monaco-editor/issues/5168](https://github.com/microsoft/monaco-editor/issues/5168)

## Summary

The regression coincides with Monaco adopting Chrome's EditContext API; Vimium does not recognize an element backed by EditContext as editable and consequently handles its keystrokes. Keep this open as an upstream compatibility issue while Vimium adds EditContext-aware editable detection.

## Change summary

Vimium intercepts normal typing after Monaco switched from a textarea to the browser's EditContext input API.

## Best solution

Vimium should treat a focused element with an attached EditContext as editable and enter insert mode; embedders can use the `editContext: false` editor option as a temporary compatibility workaround.

  > Thanks for the report and the version comparison. This tracks the editor's switch to Chrome's EditContext API: the focused input host is now a div with an attached EditContext rather than a textarea. Vimium's current editable-element detection only recognizes input, textarea, contenteditable, and select elements, so it does not enter insert mode for this standard input surface.
