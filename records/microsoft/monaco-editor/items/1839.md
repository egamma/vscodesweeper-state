# Issue #1839 — Add better support for imports suggestion

[https://github.com/microsoft/monaco-editor/issues/1839](https://github.com/microsoft/monaco-editor/issues/1839)

## Summary

The requested auto-import support is still absent, but the broader issue covering this exact TypeScript language-service capability was explicitly closed as not planned. The documented ambient-module and package.json patterns remain the available workarounds.

## Change summary

Offer auto-import suggestions for ordinary external-module declarations registered through addExtraLib without requiring ambient module wrappers.

## Best solution

Keep the current TypeScript worker behavior consistent with the decision in https://github.com/microsoft/monaco-editor/issues/2582 and use explicit ambient module declarations or package metadata when configuring extra libraries.

- **Proposed comment:**

  > Thanks for the report and the investigation. The current TypeScript worker still calls the language service without the module-export completion preferences, so ordinary external-module declarations are not offered as auto-import suggestions. Enabling those preferences and applying the resulting import edits is the same work discussed in https://github.com/microsoft/monaco-editor/issues/2582, which was closed as not planned. Given that decision, the supported approaches remain explicit `declare module` wrappers or registering appropriate package metadata alongside the declarations, so I’m closing this as out of scope.
