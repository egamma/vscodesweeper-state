# Issue #3273 — [Bug] Custom theme is reset when another Monaco bundle is loaded

[https://github.com/microsoft/monaco-editor/issues/3273](https://github.com/microsoft/monaco-editor/issues/3273)

## Summary

Keep open: independently bundled Monaco copies still generate overlapping global theme selectors, and existing theme APIs do not provide bundle-specific scoping. This team-authored request has no verified fix or same-symptom canonical that warrants closing it.

## Change summary

Support theme isolation so loading a second Monaco bundle does not overwrite an existing bundle's custom colors.

## Best solution

Establish supported stylesheet isolation for independently bundled editors, with the behavior change landing in microsoft/vscode's standalone editor theme service. Preserve this report separately from requests for different themes within one shared Monaco runtime.

## Evidence

- **Concrete reproduction:** https://github.com/kycutler/multiple-monaco-bug contains separate webpack entries indexA.js and indexB.js. The first defines a red-token custom theme; the second independently imports Monaco and creates an editor with the default theme. The issue reports the first editor's colors being overwritten when the second bundle loads.
- **Current source mechanism:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts initializes each StandaloneThemeService with the light theme, installs a document-level monaco-colors stylesheet for regular containers, and emits shared .monaco-editor selectors. https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages/supports/tokenization.ts generates unscoped .mtk${i} color selectors, allowing independently bundled services to collide.
- **Existing capability boundary:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts exposes defineTheme, setTheme and useShadowDOM, but no theme-selector prefix parameter. The current standalone theme service supports containers embedded in shadow DOM; that requires a different embedding structure and does not isolate the report's ordinary document containers.
