# Issue #3273 — [Bug] Custom theme is reset when another Monaco bundle is loaded

[https://github.com/microsoft/monaco-editor/issues/3273](https://github.com/microsoft/monaco-editor/issues/3273)

## Summary

A real integration gap remains: independently bundled Monaco instances still inject unscoped token and theme rules into the same document, allowing the newest bundle to override existing editors. No existing isolation API or canonical issue was found, and the team-authored request should remain open.

## Change summary

Provide supported CSS/theme isolation so separately bundled Monaco instances cannot reset or override one another's themes.

## Best solution

Add a supported theme-style scoping mechanism in the vscode standalone theme service, likely around `src/vs/editor/standalone/browser/standaloneThemeService.ts`, and carry it into Monaco through the normal source-generation pipeline. It should isolate generated token classes and color rules without requiring consumers to rewrite Monaco's stylesheet.
