# Issue #2984 — [Feature Request]  Provide API to leave snippet mode

[https://github.com/microsoft/monaco-editor/issues/2984](https://github.com/microsoft/monaco-editor/issues/2984)

## Summary

An existing command exits snippet mode, but it changes selection semantics compared with the reported cancel() workaround. Keep the public-API request open and route it to editor-api to decide whether that distinction needs supported coverage.

## Change summary

Expose a supported API for leaving snippet mode without accessing an untyped editor contribution.

## Best solution

Document the existing leaveSnippet command for Escape-equivalent cancellation and decide whether supported cancellation must also preserve all selections, as the reporter's workaround does. Any additional editor API should originate in the VS Code editor core.

  > Thanks for the context. You can avoid accessing the contribution with `editor.trigger('api', 'leaveSnippet', undefined)` when snippet support is loaded. This invokes Escape-style cancellation and retains only the primary selection, whereas your current `cancel()` call preserves all selections. That distinction leaves a supported cancellation API worth considering; its implementation belongs in the VS Code editor core.
