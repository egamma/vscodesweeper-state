# Issue #4714 — [Bug] DiffEditor does not emit dispose event

[https://github.com/microsoft/monaco-editor/issues/4714](https://github.com/microsoft/monaco-editor/issues/4714)

## Summary

The missing disposal notification remains identifiable in current VS Code editor-core source: the diff editor inherits an event emitter that is disposed without being fired. Route to diff-editor; the related memory-leak report does not establish a duplicate of this observable symptom.

## Change summary

Calling diffEditor.dispose() should notify listeners registered through diffEditor.onDidDispose().

## Best solution

Restore the diff editor's disposal notification in microsoft/vscode's editor core and carry the correction into a Monaco release. Preserve child-editor cleanup and editor-service deregistration; listening to a child editor is only a workaround.

## Evidence

- **Concrete trigger:** https://github.com/microsoft/monaco-editor/issues/4714 provides a v0.52.0 playground link and complete code: create a diff editor, subscribe to onDidDispose, then call dispose() after three seconds; the expected console message is absent.
- **Current upstream source:** Read https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/delegatingEditorImpl.ts: DelegatingEditor registers a private _onDidDispose emitter and exposes its event, but never fires it and does not override dispose(). DiffEditorWidget extends this class and likewise has no disposal override or event firing in https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts.
- **Disposal chain:** https://github.com/microsoft/vscode/blob/main/src/vs/base/common/lifecycle.ts defines Disposable.dispose() as marking the object disposed and disposing its store. Consequently the registered event emitter is cleaned up without emitting the diff editor's notification. DiffEditorWidget separately registers removeDiffEditor(this) as cleanup, so deregistration does not provide the missing event.
- **Recent workaround:** The 2026-10-12 comment in https://github.com/microsoft/monaco-editor/issues/4714 recommends subscribing to getOriginalEditor().onDidDispose() or getModifiedEditor().onDidDispose(); this bypasses, rather than repairs, the diff editor's own event.

Searches for onDidDispose and diff disposal events found no verified canonical matching this re-reviewed item's symptom.
