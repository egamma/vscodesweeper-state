# Issue #5404 — [Bug] Unable to import "monaco-editor/min/vs/editor/editor.main.css"

[https://github.com/microsoft/monaco-editor/issues/5404](https://github.com/microsoft/monaco-editor/issues/5404)

## Summary

The v0.56.0 export-map reorganization removed access to the stylesheet used by Shadow DOM integrations. The regression remains on main and should be routed to ESM packaging and Shadow DOM integration.

## Change summary

Restore a supported way to import Monaco's complete editor stylesheet for injection into a ShadowRoot.

## Best solution

Expose the generated editor stylesheet through a supported package export and update the ESM Shadow DOM sample to use it. This belongs in Monaco's packaging/build configuration rather than the vscode editor core.

## Evidence

- **regression commit:** https://github.com/microsoft/monaco-editor/commit/558bbbcc1619da88d466bd64856f337a5604e43c changed package.json exports from the unrestricted "./*": "./*" mapping to JavaScript-only ESM mappings; this shipped through https://github.com/microsoft/monaco-editor/pull/5155 in v0.56.0.
- **current source:** package.json on main still maps "./*" to "./esm/vs/*.js", so the requested CSS subpath is redirected as JavaScript rather than exported as a stylesheet.
- **documented integration:** samples/legacy/browser-amd-shadow-dom/index.html:37-40 imports editor.main.css into the ShadowRoot, and test/manual/shadow-dom.html:28-46 likewise documents that editor CSS must be moved into the shadow root.
- **maintainer precedent:** https://github.com/microsoft/monaco-editor/issues/3017#issuecomment-1463973643 explicitly instructs Shadow DOM embedders to include the CSS in the web component; removing access to that CSS breaks the documented workaround.
- **related work:** https://github.com/microsoft/monaco-editor/issues/886 and https://github.com/microsoft/monaco-editor/issues/5067 track broader ESM CSS-loading strategies, but neither specifically owns restoration of a supported aggregate stylesheet export after v0.56.0.
