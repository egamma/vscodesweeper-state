# Issue #2796 — provide typescript.preferences.importModuleSpecifierEnding setting from vscode for monaco editor

[https://github.com/microsoft/monaco-editor/issues/2796](https://github.com/microsoft/monaco-editor/issues/2796)

## Summary

The requested import-ending preference remains absent from Monaco's public TypeScript configuration and completion pipeline. Related import-support issues do not establish a same-symptom canonical or a decision specifically declining this setting.

## Change summary

Expose a TypeScript preference controlling whether automatically generated imports include a JavaScript file extension.

## Best solution

Decide whether to expose importModuleSpecifierEnding through Monaco's bundled TypeScript configuration and honor it when generating import edits. This belongs in the Monaco-owned TypeScript integration, not the generated editor core; broader auto-import support must also be accounted for.

- **Public configuration gap:** src/languages/features/typescript/register.ts:302–392 exposes compiler, diagnostics, worker, mode, and inlay-hint configuration, but no import-ending preference. The InlayHintsOptions interface at lines 176–184 contains only hint settings.
- **Preference is not adopted:** src/languages/features/typescript/workerManager.ts passes compiler options, extra libraries, customWorkerPath, and inlayHintsOptions to the worker. tsWorker.ts:256–279 passes undefined completion options and preferences to getCompletionsAtPosition and getCompletionEntryDetails; the requested preference is not used.
- **Auto-import integration boundary:** src/languages/features/typescript/languageFeatures.ts:509–526 resolves completion details into label, kind, detail, and documentation without translating completion code actions into import edits. Exposing the preference alone would not establish working built-in auto-import generation.

Its closure comment at https://github.com/microsoft/monaco-editor/issues/2582#issuecomment-1459996460 declines that broader request without specifically addressing importModuleSpecifierEnding; it is neither an open duplicate target nor conclusive scope precedent for this narrower API.
