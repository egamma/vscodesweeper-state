# Issue #5386 — [Feature Request] Editor Canvas Padding

[https://github.com/microsoft/monaco-editor/issues/5386](https://github.com/microsoft/monaco-editor/issues/5386)

## Summary

A real API gap remains: current editor padding supports only top and bottom spacing, while wrapping options constrain text without centering or horizontally padding the canvas. Route this editor-core request to the API, rendering, and diff-editor owners.

## Change summary

Add horizontal canvas padding or a maximum text-area width that centers editor content between the gutters and scrollbar.

## Best solution

Add a generic maximum content-width or horizontal-padding option in the VS Code editor core, with layout calculations that preserve gutters, scrollbars, overlays, and both sides of a diff editor; it would then flow into Monaco with a release cut. This looks suitable for an editor-core design discussion before being marked open for PR.

## Evidence

- **current API gap:** Current VS Code editor-core declarations in https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts define IEditorPaddingOptions with only top and bottom fields; there are no left/right padding fields.
- **existing options do not cover request:** The same source exposes wordWrap/wordWrapColumn for line wrapping and revealHorizontalRightPadding for cursor reveal, but neither centers or constrains the rendered text canvas between the gutter and scrollbar.
- **related precedent:** https://github.com/microsoft/vscode/issues/40841 requested a maximum editor width and was closed in favor of the workbench-level centered layout tracked by https://github.com/microsoft/vscode/issues/15684; that workbench feature does not provide Monaco embedders with the requested editor API.
