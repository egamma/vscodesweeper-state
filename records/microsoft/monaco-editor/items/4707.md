# Issue #4707 — [Feature Request] Diff Editor Treats All Modified Lines as only "Added" or "Deleted", not "Modified"

[https://github.com/microsoft/monaco-editor/issues/4707](https://github.com/microsoft/monaco-editor/issues/4707)

## Summary

Route to diff-editor: existing decorations partially support the requested appearance, but do not expose independent modified-line styling. No verified same-symptom canonical or qualifying implementation was found.

## Change summary

Allow modified lines to have muted backgrounds while entirely added or deleted lines retain stronger highlighting.

## Best solution

Establish whether line/text theme colors cover the desired appearance, particularly when additions and replacements share a diff hunk. Any remaining semantic styling capability belongs in the microsoft/vscode diff-editor core and would reach Monaco through a release cut.

## Evidence

- **Requested distinction:** https://github.com/microsoft/monaco-editor/issues/4707 requests separate visual treatment for replacements and genuinely new lines; changing insertedLineBackground and removedLineBackground reportedly hides new-line backgrounds. No sample or discussion establishes which diff mappings produce that outcome.
- **Existing capability and limitation:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/components/diffEditorDecorations.ts applies the same line-add/delete background decorations to nonempty changed ranges. When the opposite range is empty, it additionally applies whole-line text decorations; otherwise it decorates innerChanges. Thus pure additions already receive stronger text-color coverage, but the background styling is not independently classified as modified versus added.
- **Theme controls:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/registrations.contribution.ts assigns char-insert/char-delete to whole-line addition/deletion decorations. https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/widget/diffEditor/style.css maps those classes to insertedTextBackground/removedTextBackground, separately from insertedLineBackground/removedLineBackground. This provides partial existing coverage, not proof that every requested case is satisfied.
