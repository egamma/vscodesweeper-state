# Issue #4676 — [Feature Request] Event listener for when findController is opened/closed

[https://github.com/microsoft/monaco-editor/issues/4676](https://github.com/microsoft/monaco-editor/issues/4676)

## Summary

The supported editor API still lacks a find-widget visibility event. Internal state notifications offer a workaround, but do not fully satisfy the request for a supported listener; route to the editor API and find areas.

## Change summary

Expose find-widget visibility changes so an external toggle stays synchronized with keyboard shortcuts and widget controls.

## Best solution

Consider a supported visibility notification in the VS Code-derived editor API. The existing find-state event provides the underlying signal, but exposing a stable public contract requires an editor-core API decision.

  > Thanks for the clear use case. The internal state uses `isRevealed`, rather than `isVisible`: in `onFindReplaceStateChange`, `event.isRevealed` indicates that visibility changed, and `state.isRevealed` gives the resulting open/closed value. That may help your current integration, but it relies on find-controller internals rather than a supported public API. Keeping the request open for a supported visibility notification; that API change would belong in the VS Code-derived editor core.
