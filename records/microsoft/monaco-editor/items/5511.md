## Summary

The theme-inheritance defect remains traceable in current VS Code sources, with independent downstream confirmations. Keep this report open: the related reports do not own the same work, and the open Node-RED PR is an application workaround rather than a library fix.

## Change summary

Monaco 0.57.0 context menus lose their themed background and shadow when fixedOverflowWidgets is enabled.

## Best solution

Restore standalone context-menu theme inheritance in the VS Code sources Monaco bundles, preserving fixed-overflow positioning and shadow-DOM isolation, then ship the correction in Monaco. Follow the linked downstream workaround PR without treating it as completion of this library defect.

- **Current theme-inheritance gap:** https://github.com/microsoft/vscode/blob/main/src/vs/base/browser/ui/contextview/contextview.ts creates a .shadow-root-host without a theme-bearing class and places .context-view.monaco-component inside its shadow root. https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts emits color variables under .monaco-editor, .monaco-diff-editor, .monaco-component; that document-level selector cannot match the shadow-root descendant or the unclassified outer host.
