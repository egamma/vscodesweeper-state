# Issue #5511 — [Bug] 0.57.0: context menu has no background when `fixedOverflowWidgets` is true

[https://github.com/microsoft/monaco-editor/issues/5511](https://github.com/microsoft/monaco-editor/issues/5511)

## Summary

Keep open: independent downstream confirmations support this context-menu theming regression, and current upstream source retains the reported inheritance gap. An open downstream workaround PR references this issue; neither that workaround nor the older Apple-device report establishes an upstream resolution.

## Change summary

With fixedOverflowWidgets enabled, context menus lose their theme background and shadow because their shadow host no longer inherits Monaco's color variables.

## Best solution

Restore theme-variable inheritance for fixed-overflow context menus in the standalone editor sources in microsoft/vscode, preserving overflow positioning and shadow isolation, then ship the correction through Monaco's core update. Keep this upstream report open while downstream applications evaluate temporary workarounds.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/monaco-editor/issues/5511 supplies a version-pinned playground, minimal code, right-click steps, and computed-style comparisons: 0.57.0 with fixedOverflowWidgets=true places the shadow host outside .monaco-editor, leaving --vscode-menu-background undefined; 0.56.0 and fixedOverflowWidgets=false retain the background.
- **Current upstream path:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/contextmenu/browser/contextmenu.ts passes useWindowContainerForShadowRoot when shadow DOM and fixedOverflowWidgets are enabled. https://github.com/microsoft/vscode/blob/main/src/vs/platform/contextview/browser/contextViewService.ts selects layoutService.getContainer(); https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneLayoutService.ts returns the active editor's outer getContainerDomNode(). These paths were read directly.
- **Theme inheritance boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts scopes color variables to .monaco-editor, .monaco-diff-editor, and .monaco-component. https://github.com/microsoft/vscode/blob/main/src/vs/base/browser/ui/contextview/contextview.ts constructs a .shadow-root-host without those classes, consistent with the reporter's diagnosis and the comment that adding monaco-component restores the background.
- **Independent confirmation and open PR:** https://github.com/node-red/node-red/pull/6038 is open, explicitly references this issue, and reports confirming the 0.57 transparent-menu defect and a useShadowDOM=false workaround in Chrome. It adds Monaco's theme class to the embedding container, fixing those applications rather than Monaco itself.
