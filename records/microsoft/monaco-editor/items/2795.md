# Issue #2795 — Support loading ESM workers natively as module Workers

[https://github.com/microsoft/monaco-editor/issues/2795](https://github.com/microsoft/monaco-editor/issues/2795)

## Summary

Current main explicitly supports module workers, so this is no longer a wholly missing capability. Keep open pending a focused review of the original importScripts failure: no verified fix has been connected to that exact configuration.

## Change summary

Allow ESM editor and language workers to run as module workers without invoking classic-worker-only importScripts.

## Best solution

Use the existing module-worker integration rather than introduce another worker mechanism, and establish whether the original ESM-output configuration has any remaining incompatibility. Any residual editor-core startup fix belongs in microsoft/vscode; packaging and language-worker fixes belong here.

## Evidence

- **Existing capability:** src/internal/common/workers.ts creates module workers for MonacoEnvironment.getWorkerUrl; src/languages/features/typescript/workerManager.ts supplies new Worker(new URL('./ts.worker?esm', import.meta.url), { type: 'module' }). docs/integrate-esm.md and test/smoke/parcel/index.js also demonstrate module-worker integration. These checks were source inspection, not executed reproductions.
- **Startup adoption:** src/deprecated/editor/editor.worker.ts and src/internal/common/initialize.ts call monaco-editor-core/esm/vs/editor/editor.worker.start. The current upstream start implementation constructs the worker server directly: https://github.com/microsoft/vscode/blob/main/src/vs/editor/editor.worker.start.ts.
- **Guard does not invoke importScripts:** The current counterpart of the reported editorSimpleWorker guard only assigns globalThis.monaco = createMonacoBaseAPI(); it does not call importScripts: https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/services/editorWebWorker.ts. The guard alone therefore does not explain the reported exception.
- **Historical implementation lead:** Dereferenced https://github.com/microsoft/vscode/commit/fdc8d882e2bb6875d0d1e42d58ebe2f106d119f2: defaultWorkerFactory.ts adds module-worker construction and replaces bootstrap importScripts with await import in ESM mode. This establishes substantial implementation progress, but was not conclusively connected to the reporter's direct-worker failure.
- **Remaining conditional compatibility:** src/languages/features/typescript/tsWorker.ts still calls self.importScripts when customWorkerPath is supplied. The original report does not establish that this option was used, so this cannot be assumed to be its root cause.
- **Canonical search:** https://github.com/microsoft/monaco-editor/issues/886 is open but primarily tracks native CSS/asset imports. https://github.com/microsoft/monaco-editor/issues/4741 is open and specifically tracks the webpack plugin's cross-origin importScripts bootstrap. Neither was verified to own the original direct-module-worker configuration.
