# Issue #4031 — [Feature Request] Get theme styles

[https://github.com/microsoft/monaco-editor/issues/4031](https://github.com/microsoft/monaco-editor/issues/4031)

## Summary

A supported API gap remains: current Monaco exposes colorization and theme mutation, but not the generated token CSS. The reported workaround depends on private services and fields, so the existing feature request should remain open under tokenization.

## Change summary

Expose the active theme's generated token CSS for use with Monaco's colorized HTML outside the editor.

## Best solution

Add a supported standalone-editor API in the vscode editor core that returns the current token CSS, backed by the existing color-map CSS generator rather than private `_themeCSS` access. This is suitable for a focused community contribution, with the API flowing into Monaco through its normal vscode source generation.

## Evidence

- **current public API:** Current vscode editor-core source exposes `colorize`, `colorizeElement`, `defineTheme`, and `setTheme`, but no API for retrieving generated theme CSS: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneEditor.ts
- **private implementation:** The active CSS remains stored in private `StandaloneThemeService._themeCSS`; it is generated from the token color map with `generateTokensCSSForColorMap`: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts
- **existing generator:** The editor core already has the exact generator for `.mtk*` declarations, but it is not surfaced through Monaco's standalone API: https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages/supports/tokenization.ts
- **related request:** https://github.com/microsoft/monaco-editor/issues/3302 remains open but requests per-call theme selection and inline styles, not access to the active theme stylesheet, so it does not own this issue's full scope.
