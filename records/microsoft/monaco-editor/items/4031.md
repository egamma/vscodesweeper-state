# Issue #4031 — [Feature Request] Get theme styles

[https://github.com/microsoft/monaco-editor/issues/4031](https://github.com/microsoft/monaco-editor/issues/4031)

## Summary

Keep open: retrieving generated token CSS remains a public-API gap, and the reporter's private-field workaround is not supported coverage. The existing tokenization label is appropriate; no verified canonical owns this same request.

## Change summary

Expose the generated theme CSS for token classes used by the editor and colorization APIs.

## Best solution

Consider a supported API for retrieving token CSS matching colorized output, without requiring access to private editor services. Its implementation belongs in the VS Code standalone editor sources that Monaco bundles.

## Evidence

- **Existing-capability check:** package.json pins vscodeRef c132f72ae9f5ff80093e7d722c36f03755865b20. Its public declarations expose colorize, colorizeElement, defineTheme, setTheme, and setColorMap, but no getter for generated theme CSS or the resolved color map: https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/monaco.d.ts.
- **Generation remains internal:** At the pinned revision, StandaloneThemeService._updateThemeOrColorMap calls generateTokensCSSForColorMap with the resolved token color map, stores the result in private _themeCSS, and writes styles into DOM elements. This supplies styles internally, not the requested supported retrieval API: https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/standalone/browser/standaloneThemeService.ts#L382-L421.
- **Reporter workaround:** The discussion at https://github.com/microsoft/monaco-editor/issues/4031 accesses _codeEditorService._themeService._themeCSS through an any cast and slices from .mtk1. That bypasses the public contract rather than satisfying the API request.
- **Related request is distinct:** Verified https://github.com/microsoft/monaco-editor/issues/3302 is open and older, but requests per-call theme selection and inline styles in colorize output. It does not own this report's observable requirement to retrieve CSS declarations; it fails the re-review same-symptom duplicate bar.
- **Concrete consumer:** Merged https://github.com/compiler-explorer/compiler-explorer/pull/5161 explicitly references this request because its print view needs Monaco style definitions for syntax highlighting. That application PR is not a Monaco implementation or fixing PR.
