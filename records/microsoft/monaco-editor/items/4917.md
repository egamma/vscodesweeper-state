# Issue #4917 — Rust: Hexadecimal literals with underscores after hex letters not highlighted correctly

[https://github.com/microsoft/monaco-editor/issues/4917](https://github.com/microsoft/monaco-editor/issues/4917)

## Summary

The defect remains in the current Rust Monarch grammar: its hexadecimal rule permits only one trailing underscore rather than separators throughout the literal. Route this confirmed basic-language tokenization bug for a focused regex and regression-test fix.

## Change summary

Highlight complete Rust hexadecimal literals containing underscore separators after hexadecimal letters.

## Best solution

Update the hexadecimal-number rule in `src/languages/definitions/rust/rust.ts` to accept underscores throughout the digits, then add regression cases such as `0x01_02_0a_0b` and `0xFF_AA_BB_CC` to `rust.test.ts`.

## Evidence

- **current source:** `src/languages/definitions/rust/rust.ts:356` on current main still uses `/(0x[\da-fA-F]+)_?(@intSuffixes)?/`; unlike the adjacent binary and octal rules, its digit class excludes internal underscores.
- **test gap:** `src/languages/definitions/rust/rust.test.ts:180-185` tests only `0xFA_01i32` and has no case with another hexadecimal letter after an internal underscore, so it does not cover the reported tokenization break.
- **confirmed workaround:** Compiler Explorer merged https://github.com/compiler-explorer/compiler-explorer/pull/7766, replacing this exact Monaco rule in a local language mode with `/(0x[0-9a-fA-F_]+)(@intSuffixes)?/` to resolve https://github.com/compiler-explorer/compiler-explorer/issues/7645.
