# Issue #5152 — Deprecate Monaco Editor Webpack Plugin

[https://github.com/microsoft/monaco-editor/issues/5152](https://github.com/microsoft/monaco-editor/issues/5152)

## Summary

Keep open: this team-authored migration remains incomplete. Tree-shakeable entry points and cross-bundler worker plugins now provide much of the replacement, but Monaco still documents and ships the webpack plugin without marking it deprecated.

## Change summary

Replace the Monaco-specific webpack plugin with portable feature-selection and worker-entry mechanisms, then deprecate the plugin.

## Best solution

Complete worker self-discovery for the editor worker, document the supported ESM URL plugins for webpack, Rollup, Vite, and esbuild, and migrate samples before formally deprecating the webpack plugin. The existing tree-shakeable registration entry points should remain the feature-selection mechanism.

## Vision fit

- **Fit:** aligned
- **Reason:** Removing a Monaco-specific webpack integration in favor of tree-shakeable ESM entry points and narrowly scoped cross-bundler worker handling directly advances the project's packaging and ESM direction.
- **Evidence:** The v0.56.0 CHANGELOG documents supported, tree-shakeable ESM entry points, while the durable themes explicitly include packaging and bundler integration.
