# Issue #3893 — [Bug] `ITextModel.pushEditOperations()` ignores the `cursorStateComputer`

[https://github.com/microsoft/monaco-editor/issues/3893](https://github.com/microsoft/monaco-editor/issues/3893)

## Summary

This is intended API behavior: `pushEditOperations` invokes the cursor-state computer and returns its result, but a text model cannot apply selections to an attached editor. Use `editor.executeEdits` when the resulting selection should be applied.

## Change summary

Make `ITextModel.pushEditOperations()` move the attached editor cursor to the selection returned by `cursorStateComputer`.

## Best solution

Preserve the model/editor separation and use `IStandaloneCodeEditor.executeEdits()` with its end-cursor-state argument when editing an editor. Model-only callers can consume the selection returned by `pushEditOperations()` themselves.

- **Proposed comment:**

  > Thanks for clarifying the reproduction. This is working as designed: a text model can be attached to zero, one, or multiple editors, so `model.pushEditOperations()` cannot choose an editor whose selection should change. The callback is invoked, and its result is returned by `pushEditOperations()` and recorded for undo/redo; it is not applied to an editor selection. When targeting an editor, please use `editor.executeEdits(source, edits, endCursorState)`, which applies the resulting selection through that editor's view model. This model/editor distinction is also explained in https://github.com/microsoft/monaco-editor/issues/1811#issuecomment-582612219.
