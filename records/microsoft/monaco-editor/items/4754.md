# Issue #4754 — [Feature Request] Allow using SharedWorker instead of Worker (for TypeScript)

[https://github.com/microsoft/monaco-editor/issues/4754](https://github.com/microsoft/monaco-editor/issues/4754)

## Summary

The existing worker customization hooks do not provide supported cross-tab sharing of one TypeScript language service. Route this request to typescript; no verified canonical owns the same capability.

## Change summary

Allow same-origin tabs with shared extra libraries to reuse a TypeScript language service through SharedWorker instead of allocating one dedicated worker per tab.

## Best solution

Evaluate opt-in cross-tab sharing in Monaco's TypeScript worker integration, including model isolation and connection lifetimes. Any required changes to the underlying editor worker protocol belong in microsoft/vscode.

## Vision fit

- **Fit:** aligned
- **Reason:** Reducing duplicated language-service resources through an embedder integration capability fits the bundled language experiences and browser-library boundary.
- **Evidence:** Layer 2 identifies bundled TypeScript workers as a durable theme; layer 1 favors documented integration points serving embedders.

## Evidence

- **Requested capability:** https://github.com/microsoft/monaco-editor/issues/4754 requests one TypeScript language service across same-origin tabs with identical extra libraries, reporting approximately 150 MB per dedicated worker.
- **Existing customization is partial:** src/internal/common/workers.ts exposes MonacoEnvironment.getWorker returning Worker | Promise<Worker>, then calls postMessage directly on that object. src/languages/features/typescript/register.ts exposes customWorkerPath, but no SharedWorker transport option. These hooks allow customization, not built-in cross-tab service sharing.
- **Worker and service lifecycle:** src/languages/features/typescript/workerManager.ts creates a dedicated Worker and synchronizes local editor models. src/languages/features/typescript/ts.worker.ts and src/internal/common/initialize.ts initialize through self.onmessage, not SharedWorker connection ports. TypeScriptWorker in src/languages/features/typescript/tsWorker.ts creates a language service per instance and obtains files from its worker context's mirror models; adapting transport alone does not establish one safely shared service.
- **Related report is not a canonical:** Verified open https://github.com/microsoft/monaco-editor/issues/3019 concerns missing JSON worker exports. Its author describes a custom SharedWorker integration, but that narrower export defect does not own supported TypeScript language-service sharing across tabs.
- **Canonical search:** GitHub searches for SharedWorker and shared TypeScript workers found no verified open canonical with the same requested capability. Closed https://github.com/microsoft/monaco-editor/issues/2820 concerns missing TypeScript worker exports after an upgrade, not native cross-tab sharing.
