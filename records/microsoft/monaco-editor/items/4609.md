# Issue #4609 — [Feature Request] 

[https://github.com/microsoft/monaco-editor/issues/4609](https://github.com/microsoft/monaco-editor/issues/4609)

## Summary

This remains a valid accessibility API gap: editor options support `ariaLabel` and `ariaRequired`, but not an embedder-controlled invalid state. Route it to accessibility and editor API ownership.

## Change summary

Allow embedders to expose an invalid Monaco editor value through `aria-invalid`.

## Best solution

Add an `ariaInvalid` editor option in the vscode editor core and reflect it on the editor input element, including dynamic changes through `updateOptions`; the embedding application should determine validity rather than deriving it automatically from diagnostic markers. Monaco can inherit the API with the next source update.
