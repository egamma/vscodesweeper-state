# Issue #5328 — [Bug] Accessibility Bug: Broken Focus Management After Closing Search Pop-up Modal

[https://github.com/microsoft/monaco-editor/issues/5328](https://github.com/microsoft/monaco-editor/issues/5328)

## Summary

Returning focus to an embedding application's Search button would change the find widget's explicit editor-focus behavior. Keep this request open for accessibility review; no verified canonical covers that dismissal behavior.

## Change summary

Restore keyboard focus to the invoking Search button when the find widget closes.

## Best solution

Evaluate external-invoker focus restoration in the microsoft/vscode editor core while preserving editor focus for ordinary keyboard-invoked Find. Establish the embedding application's Search-button invocation path before deciding whether it needs application-level handling or a supported editor API.

## Evidence

- **Current dismissal behavior:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/find/browser/findWidget.ts: the Close button's onTrigger sets isRevealed to false; _onStateChanged calls _hide(true), whose focusTheEditor branch explicitly calls this._codeEditor.focus(). SimpleButton invokes the same trigger for Enter and Space. This matches the reported focus destination rather than demonstrating lost DOM focus.
- **Existing-capability check:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts: IEditorFindOptions exposes search, selection, history, layout, looping, and closeOnResult options, but no external-invoker focus-restoration option. The inspected dismissal path does not restore an external Search button.
