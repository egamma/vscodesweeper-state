[https://github.com/microsoft/monaco-editor/issues/1879](https://github.com/microsoft/monaco-editor/issues/1879)

## Summary

Keep open: current packaging provides ESM exports but does not explicitly mark the emitted JavaScript as modules, so it does not establish coverage of the requested native Node import. The maintainer favored retaining one package; no verified open canonical or concrete implementing commit was found.

## Change summary

Allow native Node ESM imports of language configuration and grammar exports without a custom loader.

## Best solution

Resolve whether the successor monaco-editor package supports native Node imports of individual language definitions, preserving the maintainer's single-package preference. If supported, provide explicit module-format metadata and a documented import path without requiring a custom loader.

- **Package migration:** https://github.com/microsoft/monaco-languages is archived; its current README states that it has merged into https://github.com/microsoft/monaco-editor. The original package path therefore needs to be distinguished from successor-package support.
- **Existing capability and remaining gap:** Current package.json defines import/require conditional exports but no type field. build/build-monaco-editor.ts copies that manifest into the distribution, while build/esm/rollup.config.mjs emits ES-format .js files without an esm/package.json declaring type: module. Conditional exports select files but do not themselves declare those files' module format.
- **Language import boundary:** src/languages/definitions/python/python.ts still exports conf and language, but imports languages from src/editor.ts, which re-exports monaco-editor-core/esm/vs/editor/editor.api. Modern browser-oriented language modules are not proven equivalent to the reporter's standalone Node import.
