# Issue #732 — Support JavaScript intellisense inside HTML

[https://github.com/microsoft/monaco-editor/issues/732](https://github.com/microsoft/monaco-editor/issues/732)

## Summary

Keep open: the bundled HTML language service still lacks JavaScript IntelliSense delegation for script blocks. Existing JavaScript APIs do not cover this integration, and the verified VS Code reference addresses only external-script references, not the full request.

## Change summary

Provide JavaScript IntelliSense inside HTML script blocks, including access to supplied module content.

## Best solution

Design embedded JavaScript language-service support in Monaco's HTML worker and completion adapter, preserving HTML completions and defining how script blocks and supplied modules share context. This belongs in the bundled language integration, not a language-agnostic editor-core change.

## Plan brief

- **Likely files:** `src/languages/features/html/htmlWorker.ts`, `src/languages/features/html/htmlMode.ts`, `src/languages/features/html/register.ts`, `src/languages/features/typescript/tsWorker.ts`, `src/languages/features/typescript/workerManager.ts`
- **Validation:** Use a playground HTML model to request JavaScript completions inside a script block and HTML completions outside it. Check completion replacement ranges after multiline HTML prefixes, updates after editing script content, and imported List.of suggestions with an explicitly supplied List.js module according to the agreed module contract.
- **Behavior:**

  > An HTML editor should provide JavaScript-aware suggestions inside script blocks without losing HTML suggestions elsewhere. Completion edits must target the correct positions in the original HTML document and reflect subsequent edits. The initial supported semantic scope must be agreed: globals alone, shared inline-script declarations, and imported modules are distinct acceptance cases. For supported modules, supplied List.js content should allow suggestions for List.of inside the importing script block.
- **Trace:**

  > HTMLCompletionAdapter in src/languages/features/html/htmlMode.ts uses HTMLWorker.doComplete in src/languages/features/html/htmlWorker.ts, which delegates directly to vscode-html-languageservice without embedded JavaScript processing. src/languages/features/html/register.ts has no option enabling that integration. The TypeScript registration exposes worker access and additional-source APIs, but src/languages/features/typescript/tsMode.ts installs suggestions for javascript/typescript models rather than HTML regions. The maintainer explanation at https://github.com/microsoft/monaco-editor/issues/2015#issuecomment-694715944 establishes that semantic delegation belongs to the outer language provider; Monarch highlighting is not a semantic workspace. Preserve existing HTML behavior and do not introduce generic editor-core provider switching. The unresolved boundary is how embedded content receives semantic context and module sources; https://github.com/microsoft/vscode/issues/26338 is a related external-reference request, not a full-scope canonical.
- **Open decisions:**
  - Should the initial feature provide only JavaScript globals, or also share declarations across classic script blocks while keeping module-script scopes separate?
  - For imported or referenced modules, should content come exclusively from embedder-supplied models and libraries, or should the library expose an explicit module-loading contract?

## Evidence

HTMLWorker.doComplete in src/languages/features/html/htmlWorker.ts parses the HTML document and calls vscode-html-languageservice.doComplete; this path does not delegate script content to the TypeScript worker.
- **Existing-capability check:** src/languages/features/html/register.ts exposes formatting, HTML suggestion/data configuration, and provider toggles, but no embedded JavaScript integration option. src/languages/features/typescript/register.ts exposes addExtraLib, setEagerModelSync, and getJavaScriptWorker; src/languages/features/typescript/tsMode.ts registers JavaScript suggestions for the javascript language, not HTML script regions.
