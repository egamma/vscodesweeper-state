# Issue #4555 — editor Suggest whether the Widget can be inserted into the body or under the specified element

[https://github.com/microsoft/monaco-editor/issues/4555](https://github.com/microsoft/monaco-editor/issues/4555)

## Summary

The requested external suggestion-widget container already exists as overflowWidgetsDomNode, available since Monaco 0.21.0. Treat this as configuration guidance rather than a missing feature.

## Change summary

Allow suggestions to render under a specified external element instead of being clipped by the editor's overflow-hidden ancestors.

## Best solution

Use overflowWidgetsDomNode with a dedicated, appropriately styled host outside the clipping ancestor and fixedOverflowWidgets: true for viewport-relative placement. No new editor API is needed for the requested container selection.

- **Proposed comment:**

  > Thanks for the report. Monaco already supports this through the `overflowWidgetsDomNode` constructor option, available since 0.21.0. When creating the editor, pass a dedicated host outside the `overflow: hidden` ancestor and set `fixedOverflowWidgets: true`. Give the host the `monaco-editor` class so widget styles apply, and position it at the viewport's top-left with an appropriate z-index. For a dialog, keep the host in the dialog's visible layer but outside its clipping content container.

## Evidence

- **Capability predates the report:** The checkout's CHANGELOG.md, under 0.21.0 (2020-09-21), documents: 'New overflowWidgetsDomNode constructor option to pass in a parent for overflowing widgets.' This predates https://github.com/microsoft/monaco-editor/issues/4555 by almost four years.
- **Public construction option:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/config/editorConfiguration.ts declares IEditorConstructionOptions.overflowWidgetsDomNode?: HTMLElement and documents placement inside an external DOM node. IStandaloneEditorConstructionOptions inherits it in https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneCodeEditor.ts.
- **Suggestion widget follows the external host:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/suggest/browser/suggestWidget.ts defines SuggestContentWidget.allowEditorOverflow = true. ViewContentWidgets.addWidget places it in overflowingContentWidgetsDomNode, and https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/view.ts lines 294-299 append that container to the supplied overflowWidgetsDomNode rather than the editor.
- **Positioning and styling guidance:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/viewParts/contentWidgets/contentWidgets.ts uses fixed positioning for overflowing widgets when fixedOverflowWidgets is enabled. https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-999337740 demonstrates this option together with an external host bearing the monaco-editor class.
- **Related issue is not a canonical duplicate:** Verified open https://github.com/microsoft/monaco-editor/issues/2793 concerns incorrect offsets in translated containers, including reports using fixedOverflowWidgets. This report asks for external container selection and does not describe that separate positioning defect; no duplicate close is warranted.
