# Issue #3996 — [Feature Request] Support for getting colorization ranges

[https://github.com/microsoft/monaco-editor/issues/3996](https://github.com/microsoft/monaco-editor/issues/3996)

## Summary

Keep open: the existing tokenization API provides token offsets and types, not resolved CSS properties for text ranges. A maintainer explicitly welcomed contributions, and no verified canonical owns this request.

## Change summary

Expose theme-resolved syntax-colorization ranges without generating HTML, enabling use with the CSS Custom Highlight API.

## Best solution

Provide a supported range-and-style API alongside colorize, with the implementation and API declarations developed in the VS Code sources Monaco inherits. This remains community-contribution material under the maintainer's stated direction.

## Evidence

- **Existing capability does not cover the request:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts declares colorize as Promise<string>, colorizeModelLine as string, and tokenize as Token[][]. Token exposes offset, type, and language, but no resolved CSS properties. The corresponding declarations in https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts retain this distinction.
- **Logical tokens precede theme resolution:** The checkout's CHANGELOG.md:1560 explicitly describes monaco.editor.tokenize as returning logical tokens before theme matching, unlike monaco.editor.colorize. Deriving token boundaries alone therefore does not satisfy the requested range-to-style mapping.
- **Maintainer accepted the direction:** https://github.com/microsoft/monaco-editor/issues/3996#issuecomment-1576386831 calls this a reasonable feature request and welcomes PRs while noting resource constraints. A decline close would contradict that position.
- **Canonical search:** Searches for colorize ranges, custom highlight, token styles, and tokenization API found no verified same-scope canonical. https://github.com/microsoft/monaco-editor/issues/3627 requests worker-based colorize execution, not range-and-style output, so it does not absorb this request.
- **Implementation boundary:** README.md:84 states that Monaco is generated from VS Code sources. The standalone editor colorization API belongs to that inherited source boundary, not the language-worker implementations in this checkout.
