# Issue #4248 — [Feature Request] Request for Editor.focus method optional params support

[https://github.com/microsoft/monaco-editor/issues/4248](https://github.com/microsoft/monaco-editor/issues/4248)

## Summary

The requested capability remains absent from the current editor API, and the issue is already routed to editor-core. The related Safari issue is narrower and does not own this broader request for caller-controlled focus options.

## Change summary

Allow callers to pass browser FocusOptions such as preventScroll and focusVisible through Editor.focus to the editor's internal focus target.

## Best solution

Extend the vscode editor-core focus contract to accept optional FocusOptions and propagate them through CodeEditorWidget, View, and both edit-context implementations; Monaco will receive the API in a subsequent source cut. This looks suitable for a community PR after the API shape and behavior across the textarea and native EditContext paths are agreed.

## Evidence

- **focus implementation:** In the same revision, src/vs/editor/browser/controller/editContext/textArea/textAreaEditContextInput.ts calls textArea.focus() without FocusOptions and separately saves/restores ancestor scroll positions, while src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts exposes focus(): void. There is no caller-controlled FocusOptions path.
