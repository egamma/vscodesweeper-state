# Issue #2882 — [Feature Request] Add keybinding labels to Cut / Copy / Paste in right click meny

[https://github.com/microsoft/monaco-editor/issues/2882](https://github.com/microsoft/monaco-editor/issues/2882)

## Summary

The missing labels are intentional browser behavior: Monaco does not register Cut, Copy, or Paste keybindings because browsers handle them natively and command bindings can trigger security prompts. Desktop VS Code differs because its native runtime registers those commands.

## Change summary

Display platform keybinding labels beside Cut, Copy, and Paste in Monaco's editor context menu.

## Best solution

Keep the browser context menu consistent with the current clipboard design, leaving these labels absent unless actual command keybindings are registered; native VS Code's labels should not be copied into Monaco independently.

- **Proposed comment:**

  > Thanks for the report and the additional investigation. This is intentional for browser-based editor instances: the shared editor core does not register Cut, Copy, or Paste keybindings outside the native runtime because browsers already handle those shortcuts and command bindings can produce clipboard security prompts. That design is documented in https://github.com/microsoft/vscode/issues/108349 and remains explicit in https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/clipboard/browser/clipboard.ts. Desktop VS Code shows the labels because its native runtime registers the corresponding commands; the temporary labels in Monaco 0.46.0/0.47.0 resulted from the platform-detection problem rather than the intended browser behavior. Closing this as designed.
