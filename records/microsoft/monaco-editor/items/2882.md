# Issue #2882 — [Feature Request] Add keybinding labels to Cut / Copy / Paste in right click meny

[https://github.com/microsoft/monaco-editor/issues/2882](https://github.com/microsoft/monaco-editor/issues/2882)

## Summary

Keep open: browser clipboard shortcuts are intentionally not registered as editor commands, but displaying their native shortcut hints remains a distinct improvement. The reported appearance in v0.46.0 was subsequently reversed, not a durable fix.

## Change summary

Display platform-appropriate shortcut labels beside Cut, Copy, and Paste in the editor context menu.

## Best solution

Consider display-only hints for native clipboard shortcuts in the VS Code-derived editor core, preserving browser-handled clipboard behavior and permission handling. Registering replacement command bindings is not equivalent to that outcome.

- **Proposed comment:**

  > Thanks for the context. The missing labels follow the browser clipboard design documented in https://github.com/microsoft/vscode/issues/108349: default clipboard command bindings are omitted so browsers handle the shortcuts without additional permission prompts. Displaying the native shortcut hints without changing that handling remains a separate improvement; the labels reported in v0.46.0 did not persist in v0.48.0. This would need consideration in the shared VS Code editor core.

## Evidence

- **Thread establishes an unresolved request:** https://github.com/microsoft/monaco-editor/issues/2882 includes reports that labels appeared in v0.46.0/v0.47.0 alongside incorrect platform detection, then disappeared in v0.48.0 when platform detection was corrected.
- **Current upstream registration:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/clipboard/browser/clipboard.ts gives CutAction, CopyAction, and PasteAction kbOpts only when platform.isNative is true. Its comments explicitly preserve browser-handled shortcuts to avoid security prompts.
- **Shortcut display path:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/contextmenu/browser/contextmenu.ts supplies getKeyBinding through _keybindingFor(action), which calls lookupKeybinding(action.id). Native browser shortcuts therefore do not automatically supply menu labels.
- **Existing capability is a workaround:** website/src/website/data/playground-samples/interacting-with-the-editor/adding-a-keybinding-to-an-existing-command/sample.js demonstrates monaco.editor.addKeybindingRules. This registers command bindings rather than providing display-only hints, so it does not preserve the requested native handling unchanged.
- **Upstream rationale is not a duplicate:** https://github.com/microsoft/vscode/issues/108349 is closed and documents intentionally leaving browser clipboard command bindings blank. It explains the implementation constraint but does not resolve whether native shortcut hints can be displayed independently.
- **Related application fix and canonical search:** https://github.com/Automattic/simplenote-electron/pull/3316 is merged but explicitly re-adds bindings in the embedding application; it is not a Monaco fix. Searches for clipboard/context-menu shortcut labels found no verified open canonical owning this request.
