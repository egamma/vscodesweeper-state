# Issue #1735 — Feature request: Syntax highlighting support for Mustache

[https://github.com/microsoft/monaco-editor/issues/1735](https://github.com/microsoft/monaco-editor/issues/1735)

## Summary

Keep open: the bundled Handlebars grammar covers common Mustache expressions, but does not provide dedicated Mustache registration or JSON-template highlighting. The existing grammars routing is appropriate; no matching canonical was verified.

## Change summary

Provide built-in Mustache syntax highlighting, including the JSON-template use case raised in the discussion.

## Best solution

Define the supported Mustache syntax and host-language scope, then provide a documented, tested grammar in Monaco's language definitions. Preserve ordinary JSON behavior rather than treating template expressions as standard JSON.

- **Behavior:**

  > Embedders should be able to select documented Mustache highlighting without authoring a tokenizer themselves. Common variables, unescaped expressions, sections and comments should receive appropriate highlighting alongside supported host content. The discussion explicitly requests JSON templates containing "message": {{data}}. Acceptance checks must cover the chosen host formats while preserving existing Handlebars and ordinary JSON behavior; template-aware diagnostics are not implied by a syntax-highlighting request.
- **Trace:**

  > The checkout owns language definitions, so this feature need not change the generated VS Code editor core. src/languages/definitions/handlebars/handlebars.ts already handles common brace expressions through handlebarsInSimpleState, handlebarsInEmbeddedState and handlebarsRoot, but its outer states are HTML-oriented. Its register.ts exposes only the Handlebars identity and extensions. src/languages/features/json/jsonMode.ts registers JSON tokenization and diagnostics independently, so Handlebars selection is not JSON-template support. The existing testTokenization harness in src/languages/definitions/test/testRunner.ts checks editor.tokenize results against explicit expected tokens. The uncertainty is the supported host-format and public language-selection contract, not whether custom token providers are possible. https://github.com/microsoft/monaco-editor/issues/4662 tracks a separate Handlebars coloring regression and must not be treated as the canonical for this request.
- **Open decisions:**
  - Should built-in Mustache support cover standalone/HTML templates, JSON templates, or both?
  - Should embedders select a dedicated Mustache language identity, host-specific template identities, or an explicitly expanded Handlebars contract?

## Evidence

- **Existing capability and limits:** src/languages/definitions/handlebars/handlebars.ts recognizes double/triple-brace expressions, sections and comments, but its surrounding tokenizer is HTML-oriented. src/languages/definitions/handlebars/register.ts registers only handlebars, .handlebars and .hbs, not Mustache.
- **Custom grammar workaround:** website/src/website/data/playground-samples/extending-language-services/custom-languages/sample.js demonstrates languages.register and setMonarchTokensProvider. These APIs enable an embedder-written grammar, but do not supply the requested built-in Mustache support.
- **JSON boundary:** src/languages/features/json/jsonMode.ts separately registers JSON tokenization through createTokenizationSupport(true) and JSON worker diagnostics. Selecting the HTML-oriented Handlebars grammar does not preserve JSON syntax highlighting around "message": {{data}}.
- **Demand and partial workaround:** https://github.com/microsoft/monaco-editor/issues/1735 has eight upvotes and several interested commenters. The supplied Monarch snippet explicitly targets a custom Mustache library; two later commenters request JSON-template highlighting.
- **Canonical search:** Searches for Mustache, Handlebars and JSON/template-language support found no verified canonical owning this request. https://github.com/microsoft/monaco-editor/issues/4662 is open but concerns a triple-brace coloring regression in existing Handlebars support, not missing Mustache language support, so it is not a duplicate target.
