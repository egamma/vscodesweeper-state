# Issue #2380 — Cannot change locale in monaco-typescript

[https://github.com/microsoft/monaco-editor/issues/2380](https://github.com/microsoft/monaco-editor/issues/2380)

## Summary

The localization gap remains on current main: Monaco accepts TypeScript's `locale` compiler option but does not load localized diagnostic messages into the worker. This older issue should remain the canonical report.

## Change summary

Allow embedders to localize TypeScript and JavaScript diagnostic messages alongside the Monaco editor UI.

## Best solution

Add an official worker configuration API for supplying TypeScript's localized diagnostic-message map and initialize it before creating the language service in `src/languages/features/typescript/tsWorker.ts`. This appears suitable for a community PR, with documentation and a localization sample.

## Evidence

- **current worker gap:** `src/languages/features/typescript/register.ts` exposes `CompilerOptions.locale`, but `workerManager.ts` passes only compiler options and `tsWorker.ts` creates the language service without loading localized diagnostic messages.
- **underlying capability:** `src/languages/features/typescript/lib/typescriptServices.js` contains TypeScript's `setLocalizedDiagnosticMessages` implementation, but Monaco's public declarations and worker configuration do not expose a supported way to supply its message map.
- **canonical search:** The only later matching open report, https://github.com/microsoft/monaco-editor/issues/4125, requests the same TypeScript diagnostic localization support; this 2021 issue is the older report and already carries both `typescript` and `i18n` routing labels.
- **workaround is not coverage:** The discussion links the third-party `monaco-editor-typescript-locales` package as a workaround explicitly pending official Monaco support, so the central API and integration request remains.
