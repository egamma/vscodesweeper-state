# Issue #5128 — [Feature Request] Add documentSelector to MonacoLspClient

[https://github.com/microsoft/monaco-editor/issues/5128](https://github.com/microsoft/monaco-editor/issues/5128)

## Summary

The requested filtering remains missing: MonacoLspClient has no documentSelector option, and synchronization ignores registration selectors. Route to editor-api for a scoped design discussion; the contributor's proposed dynamic-registration filtering addresses only part of the request.

## Change summary

Allow MonacoLspClient to synchronize only models matching an intended document selector instead of every Monaco model.

## Best solution

Provide document-selection support in monaco-lsp-client with an explicit contract for client configuration, static synchronization, and dynamic registrations. Resolve that contract with the interested contributor before implementation; no verified canonical or fixing PR was found.

## Plan brief

- **Likely files:** `monaco-lsp-client/src/adapters/LspClient.ts`, `monaco-lsp-client/src/adapters/TextDocumentSynchronizer.ts`, `monaco-lsp-client/src/adapters/LspCapabilitiesRegistry.ts`, `monaco-lsp-client/src/adapters/languageFeatures/common.ts`
- **Validation:** Use a recording LSP server with matching and nonmatching models created both before and after initialization. Verify only selected models send didOpen/didChange/didClose under static and dynamic synchronization; check selector language, scheme and pattern, overlapping registrations, unregistration, and unchanged behavior when no client selector is configured.
- **Behavior:**

  > An embedder should be able to restrict which Monaco models a language-server client synchronizes. Existing and newly created nonmatching models must not send synchronization notifications, while matching models retain their expected open/change/close lifecycle. Acceptance checks should cover static capabilities and dynamic registrations, selector fields, and registration removal. Clients without an explicit restriction should preserve the agreed compatibility behavior.
- **Trace:**

  > MonacoLspClientOptions in monaco-lsp-client/src/adapters/LspClient.ts exposes no document selector. TextDocumentSynchronizer registers for textDocumentDidChange but ignores its options, enumerates all models, subscribes to all new models, and starts ManagedModel notifications unconditionally. Its _started guard and empty registration disposables mean filtering must account for multiple registrations and removal, not only initial enumeration. LspCapabilitiesRegistry converts static synchronization into registrations with documentSelector: null. LspDiagnosticsFeature demonstrates partial selection support, but matchesDocumentSelector in languageFeatures/common.ts checks language only and is shared with diagnostics. This code is Monaco-owned, not generated VS Code editor core; unrelated synchronization formats and language-feature behavior should remain outside the change unless the agreed selector contract requires otherwise. The contributor's proposal is recorded at https://github.com/microsoft/monaco-editor/issues/5128#issuecomment-6377743733; uncertainty starts at the client-versus-server selection contract.
- **Open decisions:**
  - Should a client-configured documentSelector restrict every server registration, or serve only as the fallback when static capabilities or dynamic registrations provide no selector?

## Evidence

- **Missing client capability:** monaco-lsp-client/src/adapters/LspClient.ts defines MonacoLspClientOptions with allowedLocalCommands only and constructs TextDocumentSynchronizer without document-selection configuration.
- **Synchronization path:** monaco-lsp-client/src/adapters/TextDocumentSynchronizer.ts ignores the textDocumentDidChange registration argument, manages every existing and newly created model, and sends didOpen/didChange through ManagedModel. Its _started guard also ignores subsequent registrations, and registration disposal does nothing.
- **Existing support is partial:** LspCapabilitiesRegistry.ts maps static textDocumentSync to documentSelector: null. LspDiagnosticsFeature.ts filters pull-diagnostic models using matchesDocumentSelector, but common.ts:347–365 checks language only, not scheme or pattern. Neither mechanism supplies client-level synchronization filtering.
