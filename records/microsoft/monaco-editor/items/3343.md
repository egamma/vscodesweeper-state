## Summary

The bundled compiler has advanced to TypeScript 5.9.3, but the discussion also requests embedder-controlled compiler versions, which the current API does not directly provide. Keep open for a decision on that remaining capability rather than treating a dependency update as completion.

## Change summary

Update the bundled TypeScript compiler and let embedders select the compiler version used for language features.

The historical version-update request is addressed, but the remaining public-contract decision belongs to Monaco's TypeScript worker integration.

- **Behavior:**

  > Embedders want newer TypeScript language features without being constrained to the compiler pinned by their Monaco release. Current main already advances the bundled version to 5.9.3; the remaining goal is an explicit supported way to choose a compiler independently. If accepted, demonstrate version-dependent diagnostics with two compiler versions and preserve the default bundled behavior.
- **Trace:**

  > register.ts exposes the bundled version and customWorkerPath, but no independent compiler selector. WorkerManager._getClient forwards worker options and constructs the TypeScript worker; tsWorker.ts imports the vendored compiler and calls ts.createLanguageService(this). Its custom factory receives the existing compiler and library map, so substantial custom worker work is not equivalent to the requested selection capability. These are Monaco-owned language integration paths, not generated VS Code editor-core behavior. Preserve existing default worker behavior and avoid conflating this request with the separate LSP conversion at https://github.com/microsoft/monaco-editor/issues/5065. The trace establishes the current boundary; it does not establish compatibility with arbitrary compiler versions.
- **Open decisions:**
  - Should Monaco support selecting a TypeScript compiler independently of its release-pinned bundle, or retain bundled-version updates and document external integration alternatives?
  - If independent selection is supported, which compiler versions and associated standard-library combinations are part of the supported public contract?

## Evidence

- **Bundled version:** src/languages/features/typescript/lib/typescriptServicesMetadata.ts exports typescriptVersion = "5.9.3" on current main, newer than the 4.7 and 5.1 thresholds discussed in https://github.com/microsoft/monaco-editor/issues/3343. This establishes version advancement, not execution-based confirmation of each reported diagnostic.
- **Remaining capability:** The January 2024 comment explicitly requests manually selecting the TypeScript version. src/languages/features/typescript/register.ts exposes a version string and WorkerOptions.customWorkerPath, but no compiler-version selector. tsWorker.ts imports the vendored compiler and initializes its language service with ts.createLanguageService(this).
- **Existing customization is partial:** WorkerManager._getClient in src/languages/features/typescript/workerManager.ts forwards customWorkerPath. tsWorker.ts invokes customTSWorkerFactory(TypeScriptWorker, ts, libFileMap), supplying the existing compiler and libraries; this is a custom worker extension point, not a turnkey compiler-version selection API. Its importScripts dependency also limits applicability to module workers.
- **Linked implementation history:** https://github.com/microsoft/monaco-editor/pull/3350 is closed and unmerged. https://github.com/microsoft/monaco-editor/pull/4305 merged a TypeScript 5.4.5 update in May 2024, corroborating later compiler updates but not implementing version selection.
