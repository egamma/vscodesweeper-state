# Issue #134 — Error: ruby: trying to pop an empty stack in rule

[https://github.com/microsoft/monaco-editor/issues/134](https://github.com/microsoft/monaco-editor/issues/134)

## Summary

The Ruby tokenizer can still underflow its Monarch state stack on valid block-form conditionals used within expressions. The defect remains traceable on current main and is already routed to the grammars area.

## Change summary

Valid Ruby containing an expression such as an assignment from a multiline `if` can make tokenization throw while processing the closing `end` statements.

## Best solution

Correct the Ruby Monarch state handling in `src/languages/definitions/ruby/ruby.ts` so expression-form conditionals open a matching state instead of being treated as line modifiers, and add the reduced consecutive-`end` example to `ruby.test.ts` as a regression test.

## Evidence

- **source trace:** At current main revision ca1b42dc896b99db78e1c743256e8654e12cea2d, `src/languages/definitions/ruby/ruby.ts` lines 265-275 classify every non-line-leading `if` as `@modifier`; the modifier state is popped at the next line, so an expression-form `if` such as `sep = if sep_cond` never contributes a state for its later `end`.
