# Issue #1458 — Support selection clipboard in linux via mouse wheel

[https://github.com/microsoft/monaco-editor/issues/1458](https://github.com/microsoft/monaco-editor/issues/1458)

## Summary

Keep this accepted feature request open: browser-based Linux primary-selection support remains distinct from ordinary clipboard copying. No verified open canonical or fixing commit was found.

## Change summary

Preserve the entire selected text when pasting with the middle mouse button on Linux, rather than inserting truncated text containing ellipses.

## Best solution

Establish full Linux primary-selection support in the browser editor through the VS Code editor and clipboard integration, then carry it into Monaco. Retest the original large-selection scenario on current Chrome; ordinary Ctrl+C copying is a workaround, not coverage of the requested behavior.

## Evidence

- **Requested interaction:** https://github.com/microsoft/monaco-editor/issues/1458 describes selecting more than 40 lines in Chrome on Linux and middle-clicking, which pastes only fragments separated by ellipses. The reporter distinguishes this from desktop VS Code behavior.
- **Maintainer ownership:** https://github.com/microsoft/monaco-editor/issues/1540#issuecomment-564608510 explicitly states that Linux selection clipboard support is missing and directs tracking to this issue. The feature-request label and Backlog milestone also record accepted work.
- **Different clipboard paths:** https://github.com/microsoft/monaco-editor/issues/1540#issuecomment-564890025 explains that the hidden textarea contains abbreviated text for performance, whereas Ctrl+C supplies the full selection through the clipboard event. The Firefox Ctrl+C problem was separately resolved by enabling clipboard events: https://github.com/microsoft/monaco-editor/issues/1540#issuecomment-564965841.
- **Existing capability checked:** The published API at https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts exposes selectionClipboard, defaulting to true. However, https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneServices.ts registers BrowserClipboardService, and https://github.com/microsoft/vscode/blob/main/src/vs/platform/clipboard/browser/clipboardService.ts implements typed clipboard reads and writes only in memory; the option does not establish native Linux primary-selection integration.
- **Canonical search:** Selection-clipboard searches found this issue and closed related reports, not an open replacement. https://github.com/microsoft/monaco-editor/issues/5556 is open but concerns reverse-selection copying in Firefox on Windows, not Linux middle-button pasting. https://github.com/microsoft/monaco-editor/issues/1943 reports stale primary-selection contents rather than truncation and is closed; its Chromium confirmations do not establish correct copying of selections exceeding 40 lines.
- **Implementation boundary:** The checkout README states that Monaco is generated from VS Code sources. Editor input and clipboard behavior therefore requires investigation in microsoft/vscode rather than a patch to Monaco's language workers or packaging.
