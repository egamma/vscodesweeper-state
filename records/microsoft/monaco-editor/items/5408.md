The related context-menu report independently confirms missing radii, but its transparent-background regression is a different symptom, not a duplicate canonical.

- **Current standalone source:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts: StandaloneThemeService._updateThemeOrColorMap builds CSS variables from colorRegistry.getColors(), emitting only resolved colors on .monaco-editor, .monaco-diff-editor, and .monaco-component. It contains no size-registry enumeration or corner-radius token generation.
- **Missing tokens have separate definitions:** https://github.com/microsoft/vscode/blob/main/src/vs/platform/theme/common/sizes/baseSizes.ts registers cornerRadius.small, cornerRadius.medium, cornerRadius.large, and cornerRadius.xLarge through registerSize, with pixel defaults. These are size tokens, not entries in the color registry enumerated by the standalone theme service.
- **Independent observation and distinct related issue:** https://github.com/microsoft/monaco-editor/issues/5511 was verified open. Its reproduction reports missing --vscode-cornerRadius-* in both 0.56.0 and 0.57.0, with computed context-menu radius 0px. Its central defect is instead a transparent menu background with fixedOverflowWidgets:true in 0.57.0; that narrower regression does not own this report's missing-token scope.
