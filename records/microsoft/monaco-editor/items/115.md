# Issue #115 — Is there an initialized or ready event?

[https://github.com/microsoft/monaco-editor/issues/115](https://github.com/microsoft/monaco-editor/issues/115)

## Summary

Keep open: editor creation and language activation events do not guarantee that asynchronous language providers are ready. The existing APIs only partially cover this accepted request, and no qualifying duplicate was found.

## Change summary

Provide a reliable readiness notification so embedders can invoke language-dependent actions after initialization without timing workarounds.

## Best solution

Define which initialization stages a readiness contract guarantees, distinguishing editor creation, language-provider registration, worker availability, and embedder-loaded assets. Coordinate any public editor event with the VS Code standalone editor API; Monaco's asynchronous language registration must participate for initial formatting to work reliably.

## Evidence

- **Existing creation event is partial coverage:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneEditor.ts implements onDidCreateEditor through codeEditorService.onCodeEditorAdd; it does not await language-provider or worker initialization. https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts documents onDidCreateEditor as creation notification and onLanguage as first model association, not readiness.
- **Asynchronous language initialization:** src/languages/features/json/register.ts invokes getMode().then(mode => mode.setupMode(jsonDefaults)) from languages.onLanguage('json'). Formatting providers are subsequently registered in setupMode/registerProviders in src/languages/features/json/jsonMode.ts; getWorker rejects with 'JSON not registered!' before setup. These language-specific mechanisms do not provide the requested general readiness notification.
- **Discussion establishes the remaining gap:** https://github.com/microsoft/monaco-editor/issues/115 includes reports that scroll/layout workarounds are unreliable, a suggested onDidCreateEditor workaround, and a July 2025 request for readiness encompassing dependencies. The issue has 37 upvotes and is accepted in Backlog; replacing the old action name with editor.action.formatDocument does not establish provider readiness.
- **Related issue is not a qualifying canonical:** https://github.com/microsoft/monaco-editor/issues/2885 is open but concerns readiness before editor.tokenize in unit tests.
