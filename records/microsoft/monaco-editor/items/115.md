# Issue #115 — Is there an initialized or ready event?

[https://github.com/microsoft/monaco-editor/issues/115](https://github.com/microsoft/monaco-editor/issues/115)

## Summary

A real API gap remains: editor creation is observable, but asynchronous language-provider readiness is not. Keep this older, broader request open as the canonical readiness issue.

## Change summary

Expose an event or promise that lets embedders wait until an editor's language features are registered and ready.

## Best solution

Expose an awaitable language-feature readiness API rather than tying readiness to rendering, scrolling, or layout events. The generic provider-registry surface likely belongs in the vscode editor core, with Monaco's asynchronous language-worker registration wired into it; https://github.com/microsoft/monaco-editor/issues/2885 can then consolidate here.

## Vision fit

- **Fit:** aligned
- **Reason:** A stable readiness API improves integration with Monaco's bundled language workers without adding app-level behavior.
- **Evidence:** The vision identifies bundled language experiences as a durable theme and states that embedders integrate through the API and language workers.
