# Issue #5382 — [Bug] Cut Event from context menu has event type 'copy'

[https://github.com/microsoft/monaco-editor/issues/5382](https://github.com/microsoft/monaco-editor/issues/5382)

## Summary

Current editor-core source confirms that a context-menu cut under EditContext deliberately executes the browser's copy command before applying the internal cut, exposing a misleading `copy` DOM event. The issue should remain open and route to editor clipboard handling.

## Change summary

Selecting Cut from Monaco's context menu emits a `copy` DOM event instead of a `cut` event.

## Best solution

Address the EditContext cut workaround in the vscode editor core so embedders can distinguish cut from copy without breaking clipboard population, then pull that change into a Monaco release.

  > Thanks for the report and the playground link. The current editor-core implementation confirms this behavior: the EditContext cut path executes `document.execCommand('copy')` to populate the clipboard, then applies the cut internally (https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/contrib/clipboard/browser/clipboard.ts). That exposes a `copy` event to embedders even though the selected action was Cut. This belongs in the vscode editor core and should remain tracked until a core fix reaches a Monaco release.
