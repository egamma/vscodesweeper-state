## Evidence

- **Current-source defect:** In src/languages/definitions/shell/shell.ts, parameters enters parameterBodyParen on `$(`. That state does not recognize quoted strings: its catch-all consumes opening quotes, and its closing-parenthesis rule pops at the `)` inside the reporter's sed expression `([^:/]+)`. The later single quote is consequently interpreted in root as an opening string, corrupting subsequent highlighting.
- **Open implementation candidate:** https://github.com/microsoft/monaco-editor/pull/5443 was verified OPEN and explicitly says `Fixes #5231`. Its diff changes parameterBodyParen to recognize strings and parameters, replaces string-closing @popall with @pop, and adds the reported sed command followed by DIR_NAME as a regression case. The author reports fail-before/pass-after results; no tests were executed during this read-only review.
- **Older matching report:** https://github.com/microsoft/monaco-editor/issues/1984 was verified OPEN. Its reproduction also produces incorrect highlighting on subsequent lines after `$()` contains a quoted expression with parentheses. https://github.com/microsoft/monaco-editor/issues/1984#issuecomment-634391169 describes the same premature parenthesis termination and ensuing string-state corruption. Consolidation is deferred because this issue has an open fixing PR.
- **Ownership and reproduction:** The issue supplies a v0.55.1 playground link and complete Shell sample, and reports correct behavior in vscode.dev. The defective rules are in this repository's Shell language definition, not the generated VS Code editor core.
