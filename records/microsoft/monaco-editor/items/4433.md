# Issue #4433 — [Feature Request]  The monaco editor gets the configuration of the registration language

[https://github.com/microsoft/monaco-editor/issues/4433](https://github.com/microsoft/monaco-editor/issues/4433)

## Summary

A real API gap remains: registered language metadata is public, but the original language configuration and Monarch definition cannot be retrieved through a supported API for extension.

## Change summary

Expose a supported way to retrieve and extend a built-in language's configuration and Monarch keywords.

## Best solution

Provide or document a supported copy-and-override path for bundled definitions such as C++, preserving the original `LanguageConfiguration` and `IMonarchLanguage` before passing extensions to `setLanguageConfiguration` and `setMonarchTokensProvider`. A generic getter would likely belong in the vscode standalone-language API; a Monaco-specific alternative could use supported language-definition exports.

- **Evidence:** The v0.56.0 CHANGELOG documents supported, tree-shakeable entry points for individual language definitions, while bundled language experiences are a durable project theme.
