# Issue #4949 — [Bug] Undo / Redo does not account for decorations

[https://github.com/microsoft/monaco-editor/issues/4949](https://github.com/microsoft/monaco-editor/issues/4949)

## Summary

Decoration-aware undo history and hooks for a custom history are new capabilities, not broken supported behavior. Maintainers have declined both capabilities in the linked Monaco report and this reporter's subsequent VS Code request.

## Change summary

Make decoration changes undoable independently of text edits and expose history hooks for coordinating custom undo/redo.

## Best solution

Retain the existing text-edit history contract and close against the established decline decisions. Reconsidering decoration history or public history hooks would require a new decision in the shared VS Code editor core.

## Vision fit

- **Fit:** rejected
- **Reason:** Changing the shared undo contract belongs in the VS Code editor core rather than a Monaco-only implementation.
- **Evidence:** The README states that Monaco is generated straight from VS Code's sources; the vision identifies shared editor behavior as the product boundary.
