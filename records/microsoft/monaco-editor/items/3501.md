# Issue #3501 — [Bug] Cannot load `monaco-editor` esm module within Deno for bundling to the client.

[https://github.com/microsoft/monaco-editor/issues/3501](https://github.com/microsoft/monaco-editor/issues/3501)

## Summary

The gap remains: current editor-core ESM code still accesses browser globals during module evaluation, preventing server-side loading in Deno. The existing feature-request, integration, and help-wanted routing matches the maintainer's stated willingness to accept a contribution.

## Change summary

Allow the Monaco ESM package to be loaded during Deno server-side bundling without evaluating browser-only feature checks.

## Best solution

Make browser capability detection lazy or environment-safe in the VS Code editor core, then flow that change into Monaco. This is suitable for a community PR, with Deno import coverage demonstrating that loading the module does not require a DOM.
