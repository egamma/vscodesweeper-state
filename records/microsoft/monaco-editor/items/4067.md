# Issue #4067 — [Feature Request] Expose TypeScript formatting options

[https://github.com/microsoft/monaco-editor/issues/4067](https://github.com/microsoft/monaco-editor/issues/4067)

## Summary

The requested configuration remains missing: built-in TypeScript/JavaScript formatting still hardcodes language-specific options. Keep this correctly labeled request open for an API decision; the older request is closed and cannot serve as a duplicate canonical.

## Change summary

Expose TypeScript/JavaScript-specific formatting settings through the language defaults instead of hardcoding them.

## Best solution

Provide supported formatting configuration for the bundled TypeScript and JavaScript providers while preserving current defaults. Decide whether this is an additive formatting-options API or a consolidated options interface before implementation in Monaco's language integration.

## Plan brief

- **Likely files:** `src/languages/features/typescript/register.ts`, `src/languages/features/typescript/languageFeatures.ts`, `src/languages/features/typescript/tsMode.ts`
- **Validation:** In the playground, configure brace placement for TypeScript and JavaScript, run Format Document and Format Selection, and trigger on-type formatting. Verify configured behavior, unchanged behavior without configuration, and preservation of tabSize/insertSpaces settings.
- **Behavior:**

  > Embedders should be able to configure language-specific formatting behavior used by the built-in TypeScript and JavaScript providers. Acceptance should include configurable opening-brace placement for functions and control blocks across document, range and on-type formatting. Existing applications without configuration must retain current formatting behavior, including their tab and space settings.
- **Trace:**

  > FormatHelper._convertOptions in src/languages/features/typescript/languageFeatures.ts constructs hardcoded TypeScript formatting settings from generic FormattingOptions. FormatAdapter and FormatOnTypeAdapter pass that result to worker formatting methods; src/languages/features/typescript/tsMode.ts registers these adapters with only the worker accessor. LanguageServiceDefaults in register.ts has no formatting-settings surface, although TypeScriptWorker exposes low-level methods accepting formatting options and tsWorker.ts forwards them to the language service. HTML and CSS register.ts files provide Options.format precedent. This is Monaco-owned configuration plumbing, not a missing TypeScript formatter capability or a vscode editor-core change. Preserve existing formatting defaults and unrelated compiler/diagnostic behavior. The closed predecessor https://github.com/microsoft/monaco-editor/issues/88 provides history, not an open canonical; uncertainty starts at the public API shape proposed in https://github.com/microsoft/monaco-editor/issues/4067.
- **Open decisions:**
  - Should language-specific formatting configuration be exposed through an additive defaults API, or through a consolidated Options interface that deprecates existing separate configuration methods?

## Evidence

- **Existing-capability check:** src/languages/features/typescript/languageFeatures.ts:955–978, FormatHelper._convertOptions, accepts generic tab/space settings but hardcodes language-specific settings, including both PlaceOpenBraceOnNewLine options to false. FormatAdapter and FormatOnTypeAdapter use this conversion.
- **Public API gap and workaround:** src/languages/features/typescript/register.ts exposes compiler, diagnostics, worker, inlay-hint and mode configuration, but no language-default formatting configuration. Its TypeScriptWorker formatting methods accept FormatCodeOptions through any-typed arguments; calling these manually does not configure the built-in formatting providers. tsWorker.ts:341–372 already forwards those options to the TypeScript language service.
