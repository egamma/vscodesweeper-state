# Issue #3049 — [Bug] DiffEditor shows overloads because of duplicated definitions

[https://github.com/microsoft/monaco-editor/issues/3049](https://github.com/microsoft/monaco-editor/issues/3049)

## Summary

Keep open: independent language-service contexts for the two diff snapshots remain a meaningful gap. Shared-model analysis is established behavior, but the existing bug classification prevents an as-designed decline.

## Change summary

Prevent JavaScript definitions in one diff snapshot from appearing as definitions or overloads in the other snapshot.

## Best solution

Decide whether Monaco's JavaScript/TypeScript integration should support independent analysis contexts for comparison snapshots, while preserving normal cross-file language features. Disposing either model is not a suitable workaround for a diff that needs both snapshots visible.

- **Current shared-service architecture:** src/languages/features/typescript/workerManager.ts caches one worker client per language and synchronizes requested resources into it. src/languages/features/typescript/tsWorker.ts creates one TypeScript language service; getScriptFileNames() includes all synchronized non-library models, and definition, hover and signature requests delegate to that service without diff-snapshot isolation.
- **Established behavior:** https://github.com/microsoft/monaco-editor/issues/990#issuecomment-411356841 explicitly explains that models participate in the same language service without isolation. https://github.com/microsoft/monaco-editor/issues/1083#issuecomment-432751320 likewise describes one service for all TypeScript models. These explain the architecture, not a fix for simultaneous diff snapshots.
- **Existing-capability boundary:** src/languages/features/typescript/register.ts exposes diagnostics-only visibility filtering and a customWorkerPath extension point, not a dedicated diff-snapshot isolation setting. Module-scoped source or a bespoke worker is not equivalent to isolating the reporter's unchanged plain-script snapshots.
