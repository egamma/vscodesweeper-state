# Issue #4855 — [Bug] Paste does not work with Electron 34

[https://github.com/microsoft/monaco-editor/issues/4855](https://github.com/microsoft/monaco-editor/issues/4855)

## Summary

Keep open: multiple reporters confirmed Electron paste failures and the same workaround. The editor now uses triggerPaste, but its browser fallback remains platform.isWeb-gated; the existing Electron version, failing command and patch suffice to retest, and current resolution is not verified.

## Change summary

Context-menu paste and Ctrl/Cmd+V fail in Monaco embedded in Electron 34 when the native command fails and the browser clipboard fallback is skipped.

## Best solution

Ensure the VS Code-derived paste action supports Electron-hosted Monaco without assuming VS Code's native clipboard service is available. Retest both keyboard and context-menu paste with a visible Node process, preserving clipboard permissions and paste metadata.

## Evidence

- **Confirmed historical failure:** https://github.com/microsoft/monaco-editor/issues/4855 records Electron 34.3.3 with Monaco 0.52.2, execCommand('paste') returning false, independent confirmation in Obsidian without an iframe, and successful workarounds removing the platform.isWeb guard. The report was reopened after the initial iframe explanation proved insufficient.
- **Electron trigger:** https://github.com/electron/electron/pull/45277 changes dom_paste_enabled and javascript_can_access_clipboard from true to false. This explains the native-command failure but does not establish that Monaco's fallback omission is intended.
- **Current derived source:** package.json pins vscodeRef c132f72ae9f5ff80093e7d722c36f03755865b20. https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/contrib/clipboard/browser/clipboard.ts calls clipboardService.triggerPaste, then reads clipboard text only under platform.isWeb. Current upstream BrowserClipboardService.triggerPaste returns undefined, while platform.ts classifies a visible Node process as native. The generated Monaco runtime and Electron configuration were not executed, so this is not a current reproduction.
- **Upstream tracking is not verified duplicate coverage:** https://github.com/microsoft/vscode/issues/239228 is open and older, but its editor-clipboard task is already checked complete. Its discussion addresses VS Code's native-host paste integration; it does not establish ownership of the remaining Electron-hosted Monaco fallback failure.
- **Older related report:** https://github.com/microsoft/monaco-editor/issues/4438 is open and traces context-menu paste failure to platform.isWeb becoming false with a webpack process polyfill. It does not establish coverage of this report's Electron 34 keyboard-paste failure, so the stronger re-review duplicate bar is not met. https://github.com/microsoft/monaco-editor/issues/5014 instead reports an unknown productService error from Paste as Text.
- **Application workaround is not a library fix:** https://github.com/freelensapp/freelens/pull/1216 merged a dedicated application paste handler based on this issue. That workaround does not prove a Monaco fix landed.
