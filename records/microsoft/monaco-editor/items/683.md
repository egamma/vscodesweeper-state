# Issue #683 — Expose quick-open functionality

[https://github.com/microsoft/monaco-editor/issues/683](https://github.com/microsoft/monaco-editor/issues/683)

## Summary

A real API gap remains: Monaco registers its command-palette feature but exposes no supported API for presenting custom quick-pick entries. The existing internal-service and DOM workarounds do not satisfy the request.

## Change summary

Expose a supported quick-open or quick-pick API that actions can use for custom selectable command lists and multi-step input.

## Best solution

Add a typed, supported quick-input facade to the standalone editor API in the vscode editor core, then expose it through Monaco so embedders can show custom picks without importing internal services or manipulating DOM elements.

## Vision fit

- **Fit:** aligned
- **Reason:** A stable embedder-facing API fits Monaco's role as a browser library integrated through APIs while preserving parity with the vscode-derived editor core.
- **Evidence:** The README guardrail says Monaco is generated from VS Code sources and that embedders integrate through its API; this request seeks such an API rather than app-level functionality.
