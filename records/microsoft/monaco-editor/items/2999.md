# Issue #2999 — [Feature Request] enable retention of size of docs popup 

[https://github.com/microsoft/monaco-editor/issues/2999](https://github.com/microsoft/monaco-editor/issues/2999)

## Summary

The requested persistence remains missing: the documentation popup retains its resized dimensions only within a completion session. Route to suggest; the change belongs in the VS Code editor core.

## Change summary

Persist user-resized completion documentation popup dimensions so embedders can restore them through storage.

## Best solution

Support storing and restoring documentation popup dimensions in the VS Code suggest-details implementation, while preserving viewport constraints. Monaco should inherit that capability through its editor-core release pipeline.

## Evidence

- **Remaining capability gap:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/suggest/browser/suggestWidgetDetails.ts: SuggestDetailsOverlay.onDidResize assigns the completed resize to _userSize without a storage call; hide(sessionEnded=true) clears _userSize.
- **Existing persistence covers a different widget:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/suggest/browser/suggestWidget.ts: PersistedWidgetSize stores the completion list's dimensions under suggestWidget.size/... through IStorageService. SuggestDetailsOverlay is constructed separately and does not use that persistence.
- **Existing-option check:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts: ISuggestOptions exposes no documentation-popup dimension persistence option. shareSuggestSelections concerns selection memory, and fitWidthToDetails concerns inline-detail width rather than documentation popup retention.
