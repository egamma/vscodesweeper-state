## Change summary

- **Proposed comment:**

  > Thanks for the report. As explained above, TypeScript compares instance members rather than class names. Because Test<T> is empty and never uses T in a member, Test<number> and Test1 are both compatible with Test<string>, so these calls correctly produce no errors. Defining Test<T> with a member such as `value!: T` makes both reported calls incompatible with that overload. See https://www.typescriptlang.org/docs/handbook/type-compatibility.html#generics.
