# Issue #4329 — Provide configuration for deleting trigger characters after providing pop-up lists

[https://github.com/microsoft/monaco-editor/issues/4329](https://github.com/microsoft/monaco-editor/issues/4329)

## Summary

The requested replacement is already supported through CompletionItem.range; this is an API-configuration question rather than a missing capability. An earlier report confirms that including the trigger character in the replacement range solves the same problem.

## Change summary

Accepting an @-triggered suggestion should replace the trigger character and leave only the selected text.

## Best solution

Use the existing completion replacement range to include @, with filterText matching the prefixed input and insertText containing only the desired output. No new provider option is needed for the supplied example.

- **Proposed comment:**

  > Thanks for the example. This is already supported through each suggestion's `range`, which controls the text replaced on acceptance; `triggerCharacters` controls when suggestions are requested, and `replaceTriggerChar` is not a supported option. For your example immediately after typing `@`, return `{ label: 'test', kind: monaco.languages.CompletionItemKind.Text, insertText: 'test', filterText: '@test', range: new monaco.Range(position.lineNumber, position.column - 1, position.lineNumber, position.column) }`. This includes `@` in the replacement while inserting only `test`; if you also allow typing a prefix, extend the range from that same `@` through the prefix. The same approach was confirmed in https://github.com/microsoft/monaco-editor/issues/2530#issuecomment-861781923, so this can be closed as an API-usage question. Further usage questions belong on https://stackoverflow.com/questions/tagged/monaco-editor.

## Evidence

- **Existing API contract:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages.ts defines CompletionItem.range as the text replaced by the completion, insertText as the inserted content, and filterText as the filtering string. CompletionItemProvider has triggerCharacters but no replaceTriggerChar property.
- **Repository example:** website/src/website/data/playground-samples/extending-language-services/completion-provider-example/sample.js supplies an explicit range on every suggestion. The sample in https://github.com/microsoft/monaco-editor/issues/4329 omits range and uses a string instead of a CompletionItemKind enum value.
- **Same behavior resolved previously:** https://github.com/microsoft/monaco-editor/issues/2530#issuecomment-861781923 confirms that extending the completion range to include the trigger character fixed unwanted prefix preservation. This closed issue is supporting precedent, not an open duplicate canonical.
- **Maintainer explanation:** https://github.com/microsoft/monaco-editor/issues/2530#issuecomment-873011148 explains that preserving trigger characters is appropriate for most languages and asks whether setting the range resolved the report.
- **Thread clarification:** https://github.com/microsoft/monaco-editor/issues/4329#issuecomment-2617923793 reports that replaceTriggerChar does not work; the earlier comment proposes that property rather than identifying an existing supported option.
