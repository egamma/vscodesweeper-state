# Issue #3623 — [Feature Request] addKeybindingRule(s) for individual editor instances

[https://github.com/microsoft/monaco-editor/issues/3623](https://github.com/microsoft/monaco-editor/issues/3623)

## Summary

The public API still lacks instance-scoped keybinding rules. The discussion provides a workaround, but it requires globally replacing bindings and reconstructing their conditions, so it does not fully cover the request.

## Change summary

Allow embedders to disable or override existing keybindings for selected editor instances without affecting other editors.

## Best solution

Consider an instance-scoped keybinding-rule API in the standalone editor sources in microsoft/vscode, preserving other editors' bindings and conditions. Retain the context-key workaround as interim guidance.

- **Fit:** aligned
- **Reason:** Instance-scoped configuration supports multiple embedded editors through the public API without introducing an application-level feature.
- **Evidence:** The values and guardrails identify API integration as the appropriate extension point for a browser editor library.

## Evidence

- **Existing API boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts declares addKeybindingRule(s) at namespace scope; IStandaloneCodeEditor exposes addCommand, createContextKey and addAction, but no instance-scoped keybinding-rule method.
- **Shared registration path:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneEditor.ts:197-218 forwards addKeybindingRule(s) to StandaloneServices.get(IKeybindingService).addDynamicKeybindings without an editor-instance parameter.
- **Workaround is partial coverage:** https://github.com/microsoft/monaco-editor/issues/3623#issuecomment-1472578786 supplies a v0.36.1 playground example that removes the quick-fix binding globally, recreates its shortcut and when condition, and gates it with editor2.createContextKey. This demonstrates an alternative pattern, not an instance-local removal API.
- **Checkout examples:** website/src/website/data/playground-samples/interacting-with-the-editor/adding-a-keybinding-to-an-existing-command/sample.js uses global monaco.editor.addKeybindingRules. The adding-a-command-to-an-editor-instance/sample.js example combines editor.addCommand with custom context keys; it does not provide scoped removal of existing bindings.
- **Canonical search:** Searches for instance-specific bindings, disabling shortcuts and addKeybindingRules found no verified open canonical for this request. https://github.com/microsoft/monaco-editor/issues/2157 is open but concerns removed private dynamic-command APIs and disabling actions, not the same observable requirement of changing one editor without affecting another.
