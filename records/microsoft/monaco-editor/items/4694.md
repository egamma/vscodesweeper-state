## Summary

Keep open: the Electron/Node AMD-loading failure has multiple historical confirmations, but no verified fix or matching canonical. AMD packaging changed substantially after the report; the supplied version boundary, environment, and stack identify the flow to retest, not proof of resolution.

## Change summary

Updating from Monaco 0.50.0 to 0.51.0 breaks editor loading through Node require in Electron with a globalDefine TypeError.

## Best solution

Establish whether current packaging still fails on the Electron/Node loading path before treating this regression as resolved. Prefer migration to supported ESM integration; any further AMD compatibility work needs a maintainer decision because AMD support was explicitly discontinued.

- **Reported regression:** https://github.com/microsoft/monaco-editor/issues/4694 reports failure loading min/vs/editor/editor.main.js through loader.js::_createAndEvalScript in Electron with Node require, starting in 0.51.0. Four commenters report the same error; one explicitly confirms that reverting to 0.50.0 restores functionality. These are historical, not current-version reproductions.
- **Current loading path:** build/amd/src/loader.js:363–371 selects the Node script loader for Electron unless preferScriptTags is enabled. Lines 603–625 evaluate modules with vm.Script and pass a local AMD define function into the evaluated wrapper. build/amd/vite.config.mjs now generates AMD modules through Vite/Rollup; source inspection alone does not verify this Electron runtime failure.

That establishes the supported integration direction, but does not identify a commit fixing the reported globalDefine failure.
