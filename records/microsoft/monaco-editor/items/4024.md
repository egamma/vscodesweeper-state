# Issue #4024 — API for collapsing ranges

[https://github.com/microsoft/monaco-editor/issues/4024](https://github.com/microsoft/monaco-editor/issues/4024)

## Summary

Programmatic folding is available, but retrieving collapsed ranges still requires private contribution state. Keep this accepted Backlog request open for the remaining public-API gap; no verified open canonical owns the same request.

## Change summary

Provide a supported API to retrieve collapsed ranges and restore folding after externally refreshing editor content.

## Best solution

Define a supported collapsed-range inspection and restoration contract in the VS Code-derived editor API. Preserve existing folding commands and whole-view-state restoration; neither currently provides public access to collapsed-range data.

## Evidence

- **Remaining request:** In https://github.com/microsoft/monaco-editor/issues/4024, the reporter confirmed programmatic folding works, then asked how to retrieve collapsed regions. The maintainer explicitly answered that no API existed for retrieval.
- **Current public API:** Read https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts and https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts. Both expose saveViewState(), restoreViewState(), trigger(), and registerFoldingRangeProvider(), but no public collapsed-range getter. contributionsState remains an untyped or opaque contribution map; providers supply foldable ranges, not current collapse state.
- **Private state boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/folding/browser/folding.ts retains the internal FoldingStateMemento.collapsedRegions field and uses foldingModel.getMemento()/applyMemento() for view-state persistence. This supports whole-state restoration without establishing a public collapsed-range contract.
- **Partial implementation:** https://github.com/microsoft/vscode/pull/201315 is merged and fixes forwarding action arguments, enabling editor.trigger(null, 'editor.fold', { selectionLines: [1] }). It does not implement collapsed-range retrieval.
- **Canonical search:** Searched Monaco and VS Code reports for folding APIs, collapsed ranges, and folding state. https://github.com/microsoft/monaco-editor/issues/4307 is closed and covers command documentation only; https://github.com/microsoft/monaco-editor/issues/1311 is closed and addresses whole-view-state persistence. Neither is an open canonical for this public range-access request.
- **Repository ownership:** The checkout's src/editor.ts re-exports monaco-editor-core/esm/vs/editor/editor.api, and src/features/folding/register.js imports the upstream folding contribution. The remaining editor API change belongs in microsoft/vscode, not Monaco's language workers or packaging.
