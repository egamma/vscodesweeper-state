# Issue #4515 — [Feature Request] Does monao-editor support the jupyter-notebook?

[https://github.com/microsoft/monaco-editor/issues/4515](https://github.com/microsoft/monaco-editor/issues/4515)

## Summary

Notebook UI support is outside Monaco's text-editor library boundary, matching the maintainer's not-planned decision on the earlier notebook feature request.

## Change summary

Provide Jupyter-style notebook creation and LSP 3.17 notebook support in Monaco Editor.

## Best solution

Keep notebook orchestration, cells, outputs, and execution in the embedding application, using Monaco models and editors for cell text. LSP notebook synchronization alone does not supply a notebook UI.

## Vision fit

- **Fit:** rejected
- **Reason:** A complete notebook is an app-level feature rather than editor-library functionality.
- **Evidence:** The vision describes Monaco as “a browser library, not an app platform” and says embedders integrate through its API and language services.

- **Proposed comment:**

  > Thanks for the request. Monaco provides the text-editor models and views that an embedder can use for notebook cells, but it does not provide the surrounding notebook UI, cell orchestration, outputs, or execution environment. LSP 3.17 notebook synchronization defines protocol messages; it does not create that application surface. The equivalent notebook feature request was previously closed as not planned in https://github.com/microsoft/monaco-editor/issues/2526, so this is outside Monaco's scope.

- **library boundary:** README.md describes Monaco models as text content and editors as views of those models; it does not expose a notebook application surface.
- **current LSP boundary:** monaco-lsp-client/src/adapters/TextDocumentSynchronizer.ts synchronizes text models only. Protocol notebook types exist in monaco-lsp-client/src/types.ts, but MonacoLspClient does not implement notebook lifecycle or UI support.
