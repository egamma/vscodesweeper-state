# Issue #4179 — [Feature Request] API to get the rightmost offset of the column

[https://github.com/microsoft/monaco-editor/issues/4179](https://github.com/microsoft/monaco-editor/issues/4179)

## Summary

A real API gap remains: the current editor API exposes a column's left offset but not its rendered width or right edge, and querying the next column is unreliable across wrapped view lines. The existing feature-request and editor-core labels route it correctly.

## Change summary

Expose a supported API for obtaining the rendered right edge or width of a column, including at line-wrap boundaries.

## Best solution

Add a rendered horizontal-range API in the vscode editor core, likely alongside `getOffsetForColumn` in `src/vs/editor/browser/editorBrowser.ts`, and expose it through `src/vs/monaco.d.ts`; Monaco would receive it in a subsequent release cut.

## Evidence

- **current public API:** At current vscode main, `ICodeEditor.getOffsetForColumn` returns only a left offset, `getWidthOfLine` covers the whole line, and `getScrolledVisiblePosition` returns only top, left, and height: https://github.com/microsoft/vscode/blob/9d3a9fa38aa0f19d3eda05524f0d50cd4c913130/src/vs/monaco.d.ts#L6404-L6436
- **implementation boundary:** `View.getOffsetForColumn` converts the model position to a view position and returns only `visibleRange.left`, so the public API discards the rendered character range needed to handle a wrap boundary: https://github.com/microsoft/vscode/blob/9d3a9fa38aa0f19d3eda05524f0d50cd4c913130/src/vs/editor/browser/view.ts#L681-L692
- **canonical search:** The related Monaco issue https://github.com/microsoft/monaco-editor/issues/2126 addresses only obtaining a column's left offset through `getOffsetForColumn`; it does not cover the right-edge behavior requested here, and no broader open canonical was found.
