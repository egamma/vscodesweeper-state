# Issue #4179 — [Feature Request] API to get the rightmost offset of the column

[https://github.com/microsoft/monaco-editor/issues/4179](https://github.com/microsoft/monaco-editor/issues/4179)

## Summary

The public APIs still do not expose a column's right edge on its original wrapped row. Keep this request open: the existing editor-core label is appropriate, and no matching open canonical was found.

## Change summary

Expose a supported API for a column's rightmost horizontal offset, including at soft-wrap boundaries.

## Best solution

Consider a wrap-aware column-geometry API in the microsoft/vscode editor core, then expose it through Monaco's generated API. Existing position-offset methods do not cover the requested right-edge measurement.

## Evidence

- **Requested boundary case:** https://github.com/microsoft/monaco-editor/issues/4179 requests the right edge of a column on its wrapped row and explicitly explains why getOffsetForColumn(line, column + 1) fails at the row boundary.
- **Shipped API check:** https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts documents getOffsetForColumn as a left-offset method; getScrolledVisiblePosition returns top, left and height, but no width or right edge. Neither method accepts wrap-position affinity.
- **Current core implementation:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/view.ts: getOffsetForColumn converts the supplied model position to a view position and returns visibleRange.left, without an affinity parameter. getLineWidth measures the view row containing the model line's final column, not the row containing an arbitrary target column, so the newer getWidthOfLine API does not satisfy this request.
- **Related report is not a canonical:** https://github.com/microsoft/monaco-editor/issues/2126 is closed and asks for left-offset coordinates, answered by getOffsetForColumn. It does not cover this report's right-edge measurement at a soft-wrap boundary. Searches for offset APIs, wrapped positions and right-edge geometry found no matching open canonical.
- **Ownership:** README.md states that the editor is generated from VS Code sources. The relevant implementation is in microsoft/vscode's editor core, not this checkout's language workers, packaging or website.
