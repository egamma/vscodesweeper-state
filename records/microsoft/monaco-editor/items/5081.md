# Issue #5081 — [Bug] 🐞 Bug: Chrome on macOS loses editor focus after moving window between Retina and non-Retina displays (Space key scrolls the page instead of inserting a space)

[https://github.com/microsoft/monaco-editor/issues/5081](https://github.com/microsoft/monaco-editor/issues/5081)

## Summary

The Chromium EditContext focus defect remains actionable: it has an independent confirmation, affects both Chrome and Brave, and disabling EditContext consistently avoids it. The existing editor-core label routes it correctly, and no canonical issue or fixing commit was found.

## Change summary

Moving a focused editor between macOS displays with different device-pixel ratios causes Chromium to route Space to the page instead of the editor.

## Best solution

Confirm the dual-DPR transition in a bare current-version playground, then fix the vscode editor core's EditContext focus handling so display changes preserve text focus. Disabling `editContext` is a useful workaround but should not be the permanent solution.
