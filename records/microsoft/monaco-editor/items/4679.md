# Issue #4679 — [Bug] Firefox 131: Selection issues when Monaco is in shadow dom 

[https://github.com/microsoft/monaco-editor/issues/4679](https://github.com/microsoft/monaco-editor/issues/4679)

## Summary

Keep open: current VS Code editor-core source still omits shadow-root hit-testing options and dereferences potentially null results. An explicitly linked upstream fix PR remains open, so completion must wait for that work.

## Change summary

Mouse selection and editing selected text fail in Firefox when Monaco is embedded in shadow DOM, with related null hit-result errors during selection.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/313960, then carry the editor-core fix into a Monaco release. Verify both shadow-DOM selection and dragging beyond the editor before resolving this report.

## Evidence

- **Current source:** Read https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/controller/mouseTarget.ts: MouseTargetFactory._doHitTestWithCaretPositionFromPoint calls ownerDocument.caretPositionFromPoint with only coordinates, then immediately accesses hitResult.offsetNode. It supplies neither shadowRoots nor a null guard; doHitTest selects this path when caretRangeFromPoint is unavailable.
- **Diagnosis and workaround:** https://github.com/microsoft/monaco-editor/issues/4679#issuecomment-2347327592 diagnoses Firefox 131's shadow-root options requirement. https://github.com/microsoft/monaco-editor/issues/4679#issuecomment-2406284453 reports successful project-level patching by passing the editor's shadow root.
- **Later confirmations:** https://github.com/microsoft/monaco-editor/issues/4679#issuecomment-3564090288 reports the null offsetNode error in Firefox 145 using the Monaco v0.55.1 playground. https://github.com/microsoft/monaco-editor/issues/4679#issuecomment-3649022792 independently confirms errors when mouse selection crosses the scrollable editor boundary.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/313960 is open and unmerged and explicitly references this issue. Its diff adds shadowRoots options and an UnknownHitTestResult fallback for null caret results in the reported method. The open-PR rule requires keeping this issue open.
- **Canonical ownership:** https://github.com/microsoft/vscode/issues/234253 is closed, and https://github.com/microsoft/vscode/issues/234253#issuecomment-2531140459 explicitly redirects it to this Monaco issue as the duplicate canonical. The open https://github.com/microsoft/monaco-editor/issues/4527 describes out-of-editor selection errors but does not cover the central shadow-DOM selection failure, so it cannot absorb this report's full scope.
