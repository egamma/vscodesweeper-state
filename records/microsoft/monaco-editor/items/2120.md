# Issue #2120 — How to customize CompletionItemKind icon

[https://github.com/microsoft/monaco-editor/issues/2120](https://github.com/microsoft/monaco-editor/issues/2120)

## Summary

The team has explicitly declined this exact completion-icon customization API in subsequent Monaco and VS Code items. Current editor-core APIs still derive the icon exclusively from CompletionItemKind, with CSS overrides remaining the available workaround.

## Change summary

Allow completion providers to supply custom icons instead of using the fixed icon associated with CompletionItemKind.

## Best solution

Keep the existing CompletionItemKind-to-icon contract and use targeted suggest-widget CSS overrides when an embedder needs different imagery; do not add the previously declined per-item icon API.

## Vision fit

- **Fit:** rejected
- **Reason:** A Monaco-specific completion rendering API conflicts with the generated-from-VS-Code model after the corresponding editor-core proposal was declined.
- **Evidence:** The vision states that Monaco is “generated straight from VS Code's sources” and that Monaco-only editor behavior generally must land in the VS Code editor core first.

  > Thanks for the request. The same custom completion-item icon API was considered in https://github.com/microsoft/monaco-editor/issues/2654 and https://github.com/microsoft/vscode/pull/113313, and the team declined both as out of scope. Completion icons remain derived from `CompletionItemKind`; for Monaco-specific customization, the available workaround is to override the suggest widget's `.suggest-icon` / codicon CSS as described in https://github.com/microsoft/vscode/issues/223340#issuecomment-2529524242. Closing this consistently with those decisions.
