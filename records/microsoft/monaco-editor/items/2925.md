# Issue #2925 — [Feature Request] Triggering Snippets with Keybindings

[https://github.com/microsoft/monaco-editor/issues/2925](https://github.com/microsoft/monaco-editor/issues/2925)

## Summary

Keep open and route to editor-api: snippets can be inserted through an internal contribution, but the thread identifies a typing limitation and the current public API still lacks direct snippet insertion or completion-provider keybindings.

## Change summary

Allow predefined snippets to be inserted through keyboard shortcuts using a supported API.

## Best solution

Provide a supported, typed snippet-insertion entry point that embedders can invoke from addAction callbacks. The insertion contract belongs in the VS Code-derived editor API; Monaco can document its registration and shortcut integration.

## Vision fit

- **Fit:** aligned
- **Reason:** A supported snippet API strengthens browser embedding without introducing an extension host or framework-specific behavior.
- **Evidence:** The values layer identifies API surface as the aligned way to expose editor capabilities to embedders while preserving the generated-from-VS-Code boundary.

## Evidence

- **Existing capability and limitation:** The September 2025 comment on https://github.com/microsoft/monaco-editor/issues/2925 reports successful insertion through getContribution('snippetController2').insert(), but requires a handwritten TypeScript assertion because the contribution declaration exports no type. This supplies a workaround, not a supported completion-provider keybinding contract.
- **Current Monaco registration:** src/features/snippet/register.js imports the core snippet contribution for side effects; src/features/snippet/register.d.ts contains only export { }. src/editor.ts re-exports the core editor API rather than defining a public snippet insertion API.
- **Public API check:** https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/monaco.d.ts exposes addAction and generic getContribution, but no typed SnippetController or insertSnippet API. CompletionItemProvider declares triggerCharacters and completion callbacks, not keybindings. This is the VS Code revision recorded in the checkout's package.json.
- **Core implementation:** https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/contrib/snippet/browser/snippetController2.ts implements SnippetController2.insert and registers placeholder-navigation and snippet-exit commands, but does not register editor.action.insertSnippet.
- **Closed precedent is not a canonical:** https://github.com/microsoft/monaco-editor/issues/342 is closed. Its maintainer comment, https://github.com/microsoft/monaco-editor/issues/342#issuecomment-1433427490, accepted the contribution workaround but explicitly invited new reports of limitations. The typing limitation reported here prevents treating that decision as full coverage.
- **Canonical search:** Searches for snippet keybindings, shortcuts, and insertSnippet found no verified open canonical owning this request. https://github.com/microsoft/monaco-editor/issues/2984 concerns leaving snippet mode, not inserting snippets with shortcuts, so it is related rather than a duplicate.
