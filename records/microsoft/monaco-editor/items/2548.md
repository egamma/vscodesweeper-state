# Issue #2548 — PHP mode doesn't support HTML completions

[https://github.com/microsoft/monaco-editor/issues/2548](https://github.com/microsoft/monaco-editor/issues/2548)

## Summary

A real capability gap remains: PHP has embedded HTML tokenization but no built-in rich-language integration for HTML or JavaScript completions. The existing help-wanted classification supports keeping this open and routing it to the HTML/basic-languages owners.

## Change summary

Provide HTML attribute and embedded JavaScript completions while editing PHP documents.

## Best solution

Add PHP-aware outer-language completion handling that delegates HTML and JavaScript regions appropriately, following the embedded-language architecture described in https://github.com/microsoft/monaco-editor/issues/2015. The existing help-wanted status makes this suitable for a community PR.

## Evidence

- **current tokenizer:** src/languages/definitions/php/php.ts tokenizes HTML and embeds JavaScript/CSS, but src/languages/definitions/php/register.ts only registers the PHP language definition and does not install completion providers.
- **existing partial API:** src/languages/features/html/register.ts exposes registerHTMLLanguageService for additional language IDs, providing an opt-in HTML-service workaround, but PHP is not registered by default and this does not provide the requested embedded JavaScript completion behavior.
- **architecture precedent:** In https://github.com/microsoft/monaco-editor/issues/2015, the maintainer explains that rich features for embedded regions must be coordinated by the outer language provider rather than inferred language-agnostically from Monarch tokens.
