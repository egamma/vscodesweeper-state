# Issue #5065 — Use LSP for TypeScript language features

[https://github.com/microsoft/monaco-editor/issues/5065](https://github.com/microsoft/monaco-editor/issues/5065)

## Summary

Keep open: native LSP client support has shipped, but the bundled TypeScript integration still uses its custom worker interface and adapters. This team-authored Backlog issue remains the tracker for the migration and worker-size goal.

## Change summary

Move TypeScript language features to standard LSP integration and target a minified TypeScript implementation below 5 MB.

## Best solution

Migrate the bundled TypeScript/JavaScript language integration to an LSP-speaking implementation consumed by Monaco's standard client, with an explicit compatibility policy for existing worker APIs and language defaults. Establish a reproducible minification measurement for the below-5-MB goal; native client availability alone does not complete either requirement.

## Evidence

- **Existing capability does not complete migration:** CHANGELOG.md records native LSP support and typed client/transport APIs, and monaco-lsp-client/README.md describes a generic LSP client. However, src/languages/features/typescript/tsMode.ts::setupMode still creates WorkerManager and registers TypeScript-specific SuggestAdapter, QuickInfoAdapter, DiagnosticsAdapter, and other providers.
- **Current custom protocol:** src/languages/features/typescript/workerManager.ts::_getClient creates a MonacoWebWorker<TypeScriptWorker> and obtains its proxy; tsWorker.ts::TypeScriptWorker implements the custom interface and constructs ts.createLanguageService(this). register.ts still publicly exposes TypeScriptWorker and getTypeScriptWorker.
- **Maintainer distinguishes infrastructure from completion:** https://github.com/microsoft/monaco-editor/issues/5065#issuecomment-3559099944 explicitly says the LSP changes would ship but this ticket remained open, and identifies TypeScript-Go/WASM availability as the TypeScript team's responsibility.
- **Canonical ownership:** https://github.com/microsoft/monaco-editor/issues/5061 is closed with a maintainer comment tracking its worker-size request here. https://github.com/microsoft/monaco-editor/issues/5066 is open but explicitly excludes TypeScript and links here for that work. The LSP canonical search found no verified broader duplicate, and an open-PR search for 5065 returned none.
- **Size goal remains unverified:** https://github.com/microsoft/monaco-editor/issues/5065#issuecomment-3559192237 reports a 7 MB esbuild-minified worker in v0.55.0. https://github.com/microsoft/monaco-editor/issues/5065#issuecomment-3571690356 estimates repeated copyright strings contribute only about 80 KB. These are historical measurements; no current bundle measurement was performed.
