# Issue #5582 — [Bug] Rust scientific-notation literals without an exponent sign are split into identifiers

[https://github.com/microsoft/monaco-editor/issues/5582](https://github.com/microsoft/monaco-editor/issues/5582)

## Summary

The current Rust tokenizer still requires an exponent sign, incorrectly splitting valid unsigned-exponent literals. Keep this open while the explicitly linked fix PR is reviewed and merged.

## Change summary

Recognize Rust scientific-notation literals as numeric tokens whether their exponent has an explicit sign or not.

## Best solution

Review and land https://github.com/microsoft/monaco-editor/pull/5585, preserving signed exponents and existing suffix handling. This fix belongs in Monaco's bundled Rust language definition, not the VS Code editor core.

## Evidence

- **Current source confirms the defect:** In src/languages/definitions/rust/rust.ts, tokenizer.numbers requires [eE][+-][\d_]+ in its exponent rule. For 1e3, 1.5e3 and 2E10f64 this rule fails; the following numeric rules consume the mantissa, and root's identifier rule consumes the exponent tail. Signed controls match the exponent rule.
- **Open implementation candidate:** Verified https://github.com/microsoft/monaco-editor/pull/5585 is OPEN, has no merge commit, and explicitly states Fixes #5582. It proposes making the exponent sign optional and adds Rust tokenizer regression and control cases. An open linked PR blocks closing and competing agent implementation.
- **Related report is a distinct defect:** https://github.com/microsoft/monaco-editor/issues/5583 is open but concerns C# requiring a decimal point before recognizing an exponent, including signed exponents. Rust's defect instead requires an exponent sign even with a fractional mantissa, so the C# report does not own this work.
- **Concrete reproduction supplied:** https://github.com/microsoft/monaco-editor/issues/5582 supplies runnable playground code, exact token offsets, signed controls, and reported checks on Monaco 0.57.0 and 0.58.0-dev-20261111. The source trace independently confirms the reported classification failure without executing the playground.
