- **Verified open canonical:** https://github.com/microsoft/monaco-editor/issues/2793 is OPEN, was created in 2021, and tracks incorrectly offset widgets with fixedOverflowWidgets:true inside translated containers. Its discussion explicitly includes hovering as a trigger and identifies transformed ancestors as the containing block for fixed-position widgets.
- **Same root cause:** This report places the editor after a 200px spacer inside an ancestor with transform:translateZ(0px), enables fixedOverflowWidgets:true, and observes a displaced hover. The canonical's translateX(0) endpoint also leaves a transformed containing block; animation is not necessary to produce that coordinate mismatch.
- **Current upstream source trace:** Read https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/viewParts/contentWidgets/contentWidgets.ts: Widget constructs overflowing widgets with position:fixed, _layoutBoxInPage returns viewport-relative absoluteAboveTop/absoluteBelowTop and absoluteAboveLeft, and render applies those coordinates directly. https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/view.ts lines 294–299 keeps overflowing widgets beneath the editor when overflowWidgetsDomNode is omitted. A transformed ancestor therefore changes their containing block without corresponding coordinate compensation; this was source inspection, not a browser execution.
- **Maintainer ownership and workaround:** https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-998839170 identifies the VS Code content-widget positioning code and welcomes a PR. https://github.com/microsoft/monaco-editor/issues/2793#issuecomment-999337740 describes placing overflowWidgetsDomNode outside the transformed subtree as a workaround, not a landed fix.
