# Issue #380 — Add flag to Disable Worker

[https://github.com/microsoft/monaco-editor/issues/380](https://github.com/microsoft/monaco-editor/issues/380)

## Summary

Keep open: disabling link detection is supported, but it does not establish a general worker-disable capability covering editor services and rich languages. The accepted request still has a meaningful gap, and no qualifying duplicate canonical was found.

## Change summary

Provide a supported way to prevent worker creation when embedding Monaco as a read-only viewer.

## Best solution

Define a supported worker-free viewing contract covering editor-core services and bundled language workers, including which features become unavailable. Core changes belong in microsoft/vscode, coordinated with Monaco's language-worker configuration; preserve this accepted request until that contract is covered.

## Evidence

- **Accepted scope:** https://github.com/microsoft/monaco-editor/issues/380 remains open in Backlog with feature-request, editor-api, help wanted, and open for PR. The maintainer distinguished core-worker triggers from additional rich-language workers; subsequent comments request a broader disable flag, including for Cypress testing.
- **Existing capability is partial:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/config/editorOptions.ts declares links?: boolean separately from readOnly. In https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/links/browser/links.ts, LinkDetector.computeLinksNow returns when EditorOption.links is false. This disables link computation, not all worker-backed features.
- **Core boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/services/editorWorkerService.ts registers worker-backed link and word-completion providers and creates its worker through WorkerManager and EditorWorkerClient. A general worker policy therefore extends beyond this repository's language-worker factory.
- **Monaco worker configuration:** src/internal/common/workers.ts requires MonacoEnvironment.getWorker to return Worker or Promise<Worker>, then calls postMessage on the result; returning undefined is not a supported disable mechanism. src/languages/features/typescript/workerManager.ts independently creates language workers, while register.ts and tsMode.ts expose per-feature mode configuration rather than a universal worker-off flag.
- **Canonical search:** Searches for disabling workers found https://github.com/microsoft/monaco-editor/issues/4795, which is open but newer, has no milestone, and concerns JavaScript worker loading and CDN configuration. Its reporter explicitly says returning undefined still fails: https://github.com/microsoft/monaco-editor/issues/4795#issuecomment-2572768685. It does not qualify as a canonical for this older, accepted request.
