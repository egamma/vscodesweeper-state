# Issue #4829 — [Bug] StorageService override doesn't see the onDidChangeValue function

[https://github.com/microsoft/monaco-editor/issues/4829](https://github.com/microsoft/monaco-editor/issues/4829)

## Summary

The error comes from the supplied storage override returning undefined where an event function is required. This is an integration question about implementing an internal service contract, not a Monaco defect.

## Change summary

An older storage-service override throws during editor creation after upgrading to Monaco 0.52.2.

## Best solution

Update the override to implement the storage service contract expected by the bundled editor, including callable events that return disposables. Preserve the editor's existing event-subscription behavior rather than accommodating an incomplete override.

- **Proposed comment:**

  > Thanks for the report and the example. The function exists, but `onDidChangeValue() {}` returns `undefined`. The editor calls `onDidChangeValue(...)(listener)`, so this method must return an event-registration function that itself returns a disposable, as defined in https://github.com/microsoft/vscode/blob/1.96.0/src/vs/platform/storage/common/storage.ts.
  > 
  > For a deliberately non-emitting stub, that shape is `onDidChangeValue() { return () => ({ dispose() {} }); }`. This addresses the reported exception, but the remaining override methods must also satisfy the storage interface; an empty implementation can disable other editor behavior. These internal service contracts are not covered by Monaco's public API compatibility guarantee.
  > 
  > Closing this as an integration question rather than an editor bug. Further usage questions belong at https://stackoverflow.com/questions/tagged/monaco-editor.
