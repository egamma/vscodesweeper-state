# Issue #4337 — [Bug] Suggestion widget width is not commensurate with content width 

[https://github.com/microsoft/monaco-editor/issues/4337](https://github.com/microsoft/monaco-editor/issues/4337)

## Summary

The requested content-aware sizing and public width bounds remain absent from the current editor core. This is an editor enhancement rather than broken existing behavior, so it should remain open and route to the suggest area.

## Change summary

Make the suggestion widget fit its content in narrow editors and optionally expose minimum and maximum width controls.

## Best solution

Implement content-aware default sizing in the vscode suggest widget, constrained by the editor viewport, and decide there whether public minimum and maximum width options are appropriate. The change would then flow into Monaco with an editor-core update.

## Evidence

- **current sizing logic:** Current vscode main uses a fixed 430px default and 220px minimum in src/vs/editor/contrib/suggest/browser/suggestWidget.ts; it caps oversized widgets but does not automatically shrink the normal widget to its content: https://github.com/microsoft/vscode/blob/6f8e3b5eb0cd060fc24a3d41042d39090caadc3b/src/vs/editor/contrib/suggest/browser/suggestWidget.ts#L822-L928
- **existing option is insufficient:** The recently added fitWidthToDetails option is internal, defaults to false, and only grows the widget for inline details; it neither shrinks short-content widgets nor exposes minimum/maximum widths: https://github.com/microsoft/vscode/commit/0ab4910b94e14bea6555fc6c11c1a9fca389952a
- **related request:** https://github.com/microsoft/monaco-editor/issues/1632 also documents the absence of a public suggestion-width API, but asks for expansion of long entries rather than owning this report's content-fitting behavior.
