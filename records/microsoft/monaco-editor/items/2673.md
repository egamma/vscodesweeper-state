# Issue #2673 — Manage multiple locales

[https://github.com/microsoft/monaco-editor/issues/2673](https://github.com/microsoft/monaco-editor/issues/2673)

## Summary

Keep open: documented localization selects a language before loading Monaco, rather than switching an initialized editor. The newer runtime-switching request describes the same capability but does not meet the stronger canonical-ownership bar for this re-reviewed issue.

## Change summary

Allow users to dynamically change the editor's interface language to match their preferences.

## Best solution

Define runtime interface-language switching with the VS Code-derived localization layer, then expose supported Monaco integration without requiring a page reload. Retain this older request and consider consolidating the newer matching report into it.

## Evidence

- **Existing capability is initialization-only:** README.md, Localization, instructs embedders to load the corresponding nls.messages language script before the main editor script. build/amd/src/nls.messages-loader.js similarly selects config['vs/nls'].availableLanguages['*'] while loading; neither documents runtime switching.
- **Public API check:** The published declarations at https://github.com/microsoft/monaco-editor/blob/gh-pages/node_modules/monaco-editor/monaco.d.ts expose no interface-locale switching API. setModelLanguage changes the model's programming language; allowedLocales controls Unicode highlighting, not interface translations.
- **Matching newer request is not a qualifying canonical:** https://github.com/microsoft/monaco-editor/issues/4669 is open and explicitly requests changing locale after initialization. It was created in 2024, has one upvote versus this issue's three, no milestone, and no linked implementation in its discussion. The maintainer's comment acknowledges a feature request, not project ownership sufficient to supersede this older re-reviewed item.
- **Older related issues cover different behavior:** https://github.com/microsoft/monaco-editor/issues/1514 concerns loading localized ESM builds, with a 2025 comment demonstrating an NLS import before editor initialization. https://github.com/microsoft/monaco-editor/issues/2720 concerns localization examples and JSON diagnostic translations. Neither owns switching an already initialized editor.
- **Shared localization boundary:** https://github.com/microsoft/vscode/blob/main/src/vs/nls.ts reads the global NLS message table through getNLSMessages() and lookupMessage(). This shared infrastructure is relevant to runtime switching; a Monaco loader change alone does not establish that existing interface strings refresh.
