# Issue #5563 — [Bug] Background tokenizer throws "deadline is undefined" when the page has a non-spec requestIdleCallback shim (Safari 27 / iOS WKWebView)

[https://github.com/microsoft/monaco-editor/issues/5563](https://github.com/microsoft/monaco-editor/issues/5563)

## Summary

Keep open as a resilience request for nonconforming idle-callback shims. Current upstream source confirms the failure path, but does not establish a native Safari defect or identify what injects the shim.

## Change summary

Allow background tokenization to continue when an injected requestIdleCallback shim invokes callbacks without an IdleDeadline.

## Best solution

Have the vscode core maintainers decide whether the shared idle scheduler should tolerate missing deadlines while preserving normal scheduling and cancellation. Any accepted hardening belongs in microsoft/vscode and would reach Monaco through a subsequent editor-core release cut.

The native branch passes runner directly to requestIdleCallback at line 1568, so the supplied cb => setTimeout(cb) shim delivers no deadline.
- **Confirmed failure path:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/model/textModelTokens.ts#L463-L501 passes the callback argument into _backgroundTokenizeWithDeadline and immediately calls deadline.timeRemaining() at line 482. An undefined argument therefore throws before tokenization executes.
- **Existing-capability check:** The scheduler's existing fallback constructs a valid IdleDeadline only when either idle global is absent or not a function. Its current public signature provides no option to normalize a missing deadline from an installed shim; the fallback does not cover this request.
