# Issue #4365 — [Bug] DiffEditor updateOptions theme is not recognized by typescript

[https://github.com/microsoft/monaco-editor/issues/4365](https://github.com/microsoft/monaco-editor/issues/4365)

## Summary

The typing mismatch remains: the standalone diff editor implements theme updates, but its public interface inherits updateOptions without the global options. Route to editor-api; the declaration originates in the VS Code sources.

## Change summary

DiffEditor.updateOptions accepts theme at runtime but rejects it in TypeScript.

## Best solution

Align the standalone diff editor's public updateOptions contract with its implemented global options in microsoft/vscode, then carry the generated declarations into Monaco. monaco.editor.setTheme('vs-dark') is an existing typed workaround, not a fix for the reported signature mismatch.

- **Runtime implementation:** https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneCodeEditor.ts: StandaloneDiffEditor.updateOptions accepts IDiffEditorOptions & IGlobalEditorOptions and explicitly calls the standalone theme service's setTheme when newOptions.theme is a string. IStandaloneCodeEditor already declares its corresponding global-options intersection, whereas IStandaloneDiffEditor does not. This directly explains the reporter's excess-property error.

However, current source explicitly implements theme in standalone updateOptions, so the historical guidance does not establish that this declaration mismatch is intentional.
