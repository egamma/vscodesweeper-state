# Issue #1691 — Expose undo stops in API?

[https://github.com/microsoft/monaco-editor/issues/1691](https://github.com/microsoft/monaco-editor/issues/1691)

## Summary

The public API still cannot observe undo-stack boundaries, and multiple embedders report relying on private monkey-patching. The request remains valid and should be routed to the undo-redo owner alongside editor-api.

## Change summary

Expose when an undo-stack element is created so applications can coordinate undo across multiple embedded editors.

## Best solution

Add a public undo-stack boundary event or equivalent observable API in the VS Code editor core, with semantics that exclude empty push operations, and let it flow into Monaco. This is reasonable open-for-PR material once the API contract is agreed.

## Vision fit

- **Fit:** aligned
- **Reason:** A stable API for coordinating embedded editors supports Monaco's role as a browser library integrated by host applications.
- **Evidence:** The vision states that embedders integrate through Monaco's API and that editor behavior and APIs follow the VS Code editor core.

## Evidence

- **current API gap:** Current VS Code main exposes changes, versionId, isUndoing, isRedoing, and isFlush on IModelContentChangedEvent, but no undo-stack-boundary field: https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/textModelEvents.ts
- **implementation boundary:** EditStack.pushStackElement closes the latest edit element without emitting a public event, and it can do nothing when no edit element exists: https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/model/editStack.ts
- **continued demand:** Two commenters independently report patching pushStackElement and private undo-redo internals; the newer https://github.com/microsoft/monaco-editor/issues/4341 requests undo/redo counts for the same missing observability but is narrower than this issue.
- **distinct related work:** https://github.com/microsoft/monaco-editor/issues/239 and https://github.com/microsoft/monaco-editor/issues/686 concern serializing/restoring the entire undo stack, not observing stack-element boundaries, so neither supersedes this request.
