# Issue #2742 — Font Icons not loading after upgrading css-loader version to 6.0.0

[https://github.com/microsoft/monaco-editor/issues/2742](https://github.com/microsoft/monaco-editor/issues/2742)

## Summary

The underlying incompatibility remains in the current webpack samples: they still combine css-loader 5 with deprecated file-loader rules, so upgrading to css-loader 6 would reintroduce the confirmed duplicate-font corruption. The issue is already routed correctly and remains suitable for a community PR.

## Change summary

Update the webpack samples to support css-loader 6 without corrupting the codicon font.

## Best solution

Migrate the Webpack 5 sample configurations from file-loader to `type: 'asset/resource'`, then upgrade their css-loader dependency; retain the documented file-loader fallback only for Webpack 4. This is well-scoped `open for PR` material.

## Evidence

- **current source:** samples/package.json still pins `css-loader` to `^5.2.7`, while the Webpack samples—including samples/browser-esm-webpack/webpack.config.js—still process `.ttf` files with `file-loader` despite using Webpack 5.
- **confirmed root cause:** A maintainer confirmed that css-loader 6.2.0 with file-loader emitted both the real font and a second `.ttf` containing JavaScript; the upstream report https://github.com/webpack-contrib/css-loader/issues/1354 documents migration to Webpack asset modules as the resolution.
- **partial workaround:** https://github.com/microsoft/monaco-editor/commit/8830766c431f704f31269514c60441d8ab8b5680 only downgraded the samples to css-loader 5.2.7, so it avoided rather than implemented the requested css-loader 6 support.
- **documented solution:** https://github.com/microsoft/monaco-editor/commit/d0010709380c2f7976dec7966a45e8c34c103b3d updated webpack-plugin/README.md to use `type: 'asset/resource'` for Webpack 5, while retaining file-loader solely for Webpack 4.
