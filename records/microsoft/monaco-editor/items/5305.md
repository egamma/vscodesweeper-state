# Issue #5305 — [Feature Request] Support workspace configuration in MonacoLspClient

[https://github.com/microsoft/monaco-editor/issues/5305](https://github.com/microsoft/monaco-editor/issues/5305)

## Summary

A supported workspace-configuration API remains missing from MonacoLspClient. The merged Stan playground integration demonstrates concrete demand and currently works around the gap by accessing private client internals.

## Change summary

Support workspace configuration requests, dynamic configuration registration, and configuration-change notifications in MonacoLspClient.

## Best solution

Provide a typed embedder-facing configuration contract in monaco-lsp-client that answers section/scoped configuration requests and communicates settings changes. Agree on the public API before implementation; the existing protocol definitions and capability registry provide supporting infrastructure.

## Vision fit

- **Fit:** aligned
- **Reason:** Workspace settings support strengthens the native LSP integration and bundled language experience without adding an application platform.
- **Evidence:** The durable theme 'Interoperability with the language-server world' explicitly includes first-class LSP client support.

## Plan brief

- **Likely files:** `monaco-lsp-client/src/adapters/LspClient.ts`, `monaco-lsp-client/src/adapters/LspCapabilitiesRegistry.ts`, `monaco-lsp-client/src/types.ts`, `monaco-lsp-client/src/index.ts`
- **Validation:** Use a mock LSP transport to inspect initialize capabilities, request multiple configuration sections and scope URIs, register/unregister workspace/didChangeConfiguration, and verify settings changes produce the agreed notification payload and registration behavior.
- **Behavior:**

  > Embedders can supply language-server settings through a supported typed MonacoLspClient API without accessing private internals. Servers can request configuration by section and scope URI, with responses corresponding to request items in order. Configuration-change dynamic registration and subsequent settings notifications work according to the agreed contract. Clients that do not supply configuration support retain existing behavior.
- **Trace:**

  > MonacoLspClient in monaco-lsp-client/src/adapters/LspClient.ts builds initialize capabilities from LspCapabilitiesRegistry and installs language features, but currently installs no configuration feature. monaco-lsp-client/src/types.ts already contains the request, notification, configuration-item, and registration definitions; generic registration handling exists in LspCapabilitiesRegistry.ts. The package entry point exports the client and its options but no supported configuration hook. https://github.com/flatironinstitute/stan-playground/pull/358 demonstrates the gap through a private-connection workaround for Stan's warnPedantic setting. The uncertainty is the public contract for supplying scoped settings and signaling changes, not the availability of protocol primitives. Keep this work in the Monaco-owned LSP client and preserve unrelated editor and language-feature behavior.
- **Open decisions:**
  - Should embedders provide a configuration resolver receiving section and scopeUri, a client-owned settings map, or both?
  - Should settings changes be signaled through an explicit client method or an embedder-provided change event, and what payload and registration-filtering contract should that API guarantee?

## Evidence

- **Public API gap:** monaco-lsp-client/src/adapters/LspClient.ts exposes only allowedLocalCommands in MonacoLspClientOptions. Its connection and capability registry are private, and createFeatures() installs no workspace-configuration feature. monaco-lsp-client/src/index.ts exports no supported configuration extension API.
- **Protocol infrastructure is not capability coverage:** monaco-lsp-client/src/types.ts defines workspaceDidChangeConfiguration, workspaceConfiguration, ConfigurationItem.section/scopeUri, and configuration registration options. LspCapabilitiesRegistry supports generic dynamic registration, but no client feature advertises or handles configuration requests or exposes settings-change notifications.
- **Verified downstream demand:** https://github.com/flatironinstitute/stan-playground/pull/358 is merged. Its gui/src/app/components/FileEditor/stanLsp.ts explicitly references https://github.com/microsoft/monaco-editor/issues/5305, advertises both requested capabilities, answers workspace/configuration, and sends settings changes for warnPedantic. The workaround subclasses MonacoLspClient and accesses private _connection under @ts-expect-error.
- **Canonical search:** Repository searches for workspace configuration, didChangeConfiguration, and MonacoLspClient found no open issue owning the same requested capability and no open configuration PR. The downstream merged PR supplies a workaround, not an implementation in Monaco.
