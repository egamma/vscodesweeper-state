# Issue #4497 — [Feature Request] Can we have a predicate to decide if a completion popup should be displayed?

[https://github.com/microsoft/monaco-editor/issues/4497](https://github.com/microsoft/monaco-editor/issues/4497)

## Summary

The existing completion-provider contract already supports contextual suppression: inspect the model, position, and context in `provideCompletionItems`, then return an empty completion list when suggestions should not appear.

## Change summary

Add a predicate that decides whether the completion popup should appear in the current syntactic context.

## Best solution

Keep contextual filtering inside `provideCompletionItems`, returning `{ suggestions: [] }` before performing expensive completion work when the cursor is in a declaration. Use `quickSuggestionsDelay` if the automatic invocation delay needs adjustment.

## Vision fit

- **Fit:** rejected
- **Reason:** A separate Monaco-only editor-core hook is unnecessary and would diverge from the generated VS Code editor API.
- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources with some shims around services the code needs to make it run in a web browser."
