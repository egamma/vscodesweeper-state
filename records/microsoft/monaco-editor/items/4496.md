# Issue #4496 — [Bug] Safari: non-https site reports `undefined is not an object (evaluating 'navigator.clipboard.write')`

[https://github.com/microsoft/monaco-editor/issues/4496](https://github.com/microsoft/monaco-editor/issues/4496)

## Summary

Still present in the current VS Code editor core: Safari installs the clipboard workaround unconditionally, and its input handler calls `navigator.clipboard.write` without checking whether the secure-context-only API exists. Route this to Safari clipboard handling.

## Change summary

Typing in Monaco on an insecure HTTP origin in Safari throws because the WebKit clipboard workaround calls an unavailable Clipboard API.

## Best solution

Guard the WebKit workaround in `src/vs/platform/clipboard/browser/clipboardService.ts` so it is not installed or invoked when `navigator.clipboard.write` is unavailable, allowing `writeText` to reach its existing `execCommand('copy')` fallback. The editor-core fix belongs in microsoft/vscode and will flow into Monaco.
