# Issue #5026 — [Bug] Infinite loop during `colorize()` in `MonarchTokenizer.getLoadStatus` when nesting languages

[https://github.com/microsoft/monaco-editor/issues/5026](https://github.com/microsoft/monaco-editor/issues/5026)

## Summary

The defect remains in the current vscode editor core: `getLoadStatus()` recursively traverses embedded Monarch tokenizers without cycle detection, so mutually embedded languages recurse until the stack is exhausted. The existing grammars and tokenization labels already route it correctly.

## Change summary

Prevent `colorize()` from overflowing the stack when two Monarch languages embed each other.

## Best solution

Add cycle detection while traversing embedded tokenizers in `src/vs/editor/standalone/common/monarch/monarchLexer.ts` in microsoft/vscode, then bring that editor-core fix into the next Monaco release.

## Evidence
