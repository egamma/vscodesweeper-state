The October 2026 comment confirms an unhandled cancellation rejection on Monaco 0.57.0, and current VS Code source retains the implicated asynchronous reaction. Route to inline completions; no fix or same-symptom canonical was verified.

## Change summary

- **Current-version confirmation:** https://github.com/microsoft/monaco-editor/issues/4767#issuecomment-6421359786 reports three fresh-page reproductions on Monaco 0.57.0 with Chromium on Linux. Triggering then immediately hiding the suggestion consistently produces an unhandled Canceled rejection; the trigger action itself resolves and the buffer remains unchanged.
- **Current editor-core path:** Read https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/inlineCompletions/browser/controller/inlineCompletionsController.ts: InlineCompletionsController.playAccessibilitySignalAndReadSuggestion still awaits timeout(50, cancelOnDispose(store)) and waitForState with the disposal token, without cancellation handling.
- **Unhandled rejection mechanism:** Read https://github.com/microsoft/vscode/blob/main/src/vs/base/common/observableInternal/utils/runOnChange.ts: runOnChangeWithStore clears the previous store and invokes cb without consuming its returned Promise. In https://github.com/microsoft/vscode/blob/main/src/vs/base/common/async.ts, timeout rejects with CancellationError when its token is canceled.
