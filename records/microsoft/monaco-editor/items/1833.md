# Issue #1833 — Semantic highlighting does not appear to work (due to theming)

[https://github.com/microsoft/monaco-editor/issues/1833](https://github.com/microsoft/monaco-editor/issues/1833)

## Summary

Basic semantic-token coloring now has a public sample, but modifier-aware theming remains incomplete: current standalone theme matching treats modifiers as ordered dotted prefixes. Keep this accepted issue open for the remaining limitation identified by the maintainer.

## Change summary

Semantic tokens should receive theme styling, including rules that select their modifiers.

## Best solution

Complete modifier-aware semantic theme matching in the VS Code standalone editor core while preserving existing token-type rules. This issue should retain the remaining work rather than be closed for the basic coloring sample.

## Evidence

- **Maintainer-defined remaining scope:** https://github.com/microsoft/monaco-editor/issues/1833#issuecomment-774156946 explicitly says theme rules provide partial support but cannot fully select semantic token modifiers, so the issue is not fully done.
- **Existing public capability:** website/src/website/data/playground-samples/extending-language-services/semantic-tokens-provider-example/sample.js registers a semantic provider, enables 'semanticHighlighting.enabled', and defines token-type rules plus type.static and class.static rules. This covers basic coloring without private theme-service overrides, but does not establish complete modifier selection.
- **Current source limitation:** Verified https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneThemeService.ts: StandaloneTheme.getTokenStyleMetadata calls tokenTheme._match([type].concat(modifiers).join('.')). In https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages/supports/tokenization.ts, ThemeTrieElement.match follows consecutive dotted segments and falls back immediately when a segment is missing. Consequently, a type.static rule does not match type.declaration.static when declaration precedes static; styling depends on modifier order rather than modifier membership.
- **Partial fix does not close the full report:** https://github.com/microsoft/monaco-editor/issues/1833#issuecomment-588278112 reports a configuration-change event fix for the separately created model case. The later maintainer comment explicitly retains unfinished theming work; the merged sample PR https://github.com/microsoft/monaco-editor/pull/2103 is documentation of partial support, not proof of full resolution.
- **Canonical search:** Open semantic-highlighting searches found no verified canonical for modifier-aware standalone theming. https://github.com/microsoft/monaco-editor/issues/2872 requests a TypeScript/JavaScript semantic provider, while https://github.com/microsoft/monaco-editor/issues/2647 requests multiple Monarch tokens per capturing group; neither owns this reporter-observable theming limitation.
