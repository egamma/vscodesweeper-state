# Issue #1833 — Semantic highlighting does not appear to work (due to theming)

[https://github.com/microsoft/monaco-editor/issues/1833](https://github.com/microsoft/monaco-editor/issues/1833)

## Summary

The original complete failure was partially addressed, but the maintainer-confirmed theming gap remains on current main: standalone themes still approximate semantic-token styling through ordinary token rules rather than supporting VS Code's full semantic-token selectors.

## Change summary

Provide complete standalone-editor theming for semantic token types and modifiers, matching VS Code's semantic highlighting behavior.

## Best solution

Implement full semantic-token theme selectors in the vscode editor core's standalone theme service, expose them through `IStandaloneThemeData`, and let the change flow into Monaco. The playground example should then document type, modifier, and language-specific styling without internal APIs.
