# Issue #5233 — [Bug] Java syntax highlighting does not handle unicode escape sequences

[https://github.com/microsoft/monaco-editor/issues/5233](https://github.com/microsoft/monaco-editor/issues/5233)

## Summary

The defect remains in the current Java Monarch tokenizer: Unicode escapes inside comments are never interpreted or flagged, allowing executable Java text to be highlighted as a comment. Keep this security-sensitive report open and route it to basic language support.

## Change summary

Java highlighting should account for or visibly flag early-processed Unicode escapes that can terminate comments before Java tokenization.

## Best solution

Update the Java tokenizer in src/languages/definitions/java/java.ts to recognize security-relevant Unicode escapes in comments, with tokenization tests covering escaped line terminators and comment delimiters. If faithfully emulating Java's pre-tokenization translation is incompatible with Monarch's line model, visually flagging these sequences is the appropriate minimum.

## Evidence

- **current source:** src/languages/definitions/java/java.ts:214-219 tokenizes a line comment with /\/\/.*$/ and therefore marks everything after // as comment text, including \\u000a and the executable text following it.
- **escape handling:** src/languages/definitions/java/java.ts:149 and 237-249 recognize Unicode escapes only while tokenizing string and multiline-string states; the comment and javadoc states at lines 221-234 have no Unicode-escape handling.
- **upstream reproduction:** https://github.com/compiler-explorer/compiler-explorer/issues/4223 contains the same Java example and directs the defect to Monaco's Java tokenizer; that issue remains open.
- **security sensitivity:** The reported mismatch can visually conceal executable Java code inside text highlighted as a comment, so the issue should remain open for human handling under the security-sensitive keep-open rule.
