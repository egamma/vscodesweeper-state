# Issue #4147 — [Bug] Decorations cannot appear after inline completions

[https://github.com/microsoft/monaco-editor/issues/4147](https://github.com/microsoft/monaco-editor/issues/4147)

## Summary

A real API gap remains: injected text at the same position has no public ordering control, so an embedder cannot reliably place an `after` decoration after inline-completion ghost text. The existing feature-request and editor-core routing is appropriate.

## Change summary

Allow decorations to specify that their injected text should render after inline-completion ghost text at the same model position.

## Best solution

Design an explicit injected-text ordering or affinity API in the VS Code editor core and honor it when sorting same-position injections; Monaco will inherit that capability in a subsequent release.

## Vision fit

- **Fit:** aligned
- **Reason:** A general-purpose ordering API supports Monaco's browser-embedding model without introducing framework-specific behavior.
- **Evidence:** The vision states that embedders integrate through Monaco's API and that editor behavior follows the VS Code editor core.

## Evidence
