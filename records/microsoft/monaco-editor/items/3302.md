# Issue #3302 — [Feature Request] Colorizing with a specific theme

[https://github.com/microsoft/monaco-editor/issues/3302](https://github.com/microsoft/monaco-editor/issues/3302)

## Summary

The capability remains missing: `colorize` accepts only `tabSize`, while theme selection is limited to `colorizeElement` and changes the shared theme service. The existing feature-request and tokenization routing remains appropriate.

## Change summary

Allow `monaco.editor.colorize` to render HTML for a specified theme, including simultaneous independently themed code blocks.

## Best solution

Extend the vscode standalone colorizer API to accept a theme without changing the global theme service and emit inline or safely scoped token styles. This is suitable for a community PR in the vscode editor core, with the API subsequently flowing into Monaco.

## Evidence

- **current API:** Current vscode source defines `IColorizerOptions` with only `tabSize`; only `IColorizerElementOptions` adds `theme`: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/colorizer.ts
- **global theme behavior:** `Colorizer.colorizeElement` calls the shared `themeService.setTheme(theme)`, while `Colorizer.colorize` receives no theme service and renders token classes rather than theme-specific inline styles: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/colorizer.ts
