# Issue #5294 — [Bug] Uncaught (in promise) Canceled: Canceled when navigating cross-file from peek widget

[https://github.com/microsoft/monaco-editor/issues/5294](https://github.com/microsoft/monaco-editor/issues/5294)

## Summary

The unhandled cancellation remains possible in the current VS Code editor core: the references controller creates a promise chain without handling rejection from its asynchronous success path. Keep this open and route it to the editor contribution owner.

## Change summary

Cross-file navigation from a references peek widget produces an unhandled cancellation rejection that can fail strict test runners.

## Best solution

Handle expected cancellation at the end of the references-controller promise chain in the VS Code editor core, then bring that fix into Monaco through the next release cut. Review the remaining uncaught WordHighlighter `_run()` calls under the same cancellation scenario.

## Evidence

- **related confirmed fix:** https://github.com/microsoft/vscode/commit/6e000836b2c1b8e635be1fe8bfcd63de2d082d4c fixed the same unhandled-cancellation pattern for several WordHighlighter `runDelayer.trigger()` calls by attaching `.catch(onUnexpectedError)`.
