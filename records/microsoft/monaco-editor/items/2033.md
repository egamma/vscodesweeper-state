# Issue #2033 — require auto-complete doesn't suggest module name for module definitions without declare module syntax

[https://github.com/microsoft/monaco-editor/issues/2033](https://github.com/microsoft/monaco-editor/issues/2033)

## Summary

The open, older imports-suggestion issue already tracks the central request: module-name completion for extra libraries without explicit declare module wrappers. Consolidate this report there, preserving its JavaScript require example and referenced-declaration use case.

## Change summary

Support module-name suggestions and external library typings in JavaScript require calls without rewriting declarations into declare module wrappers.

## Best solution

Track unwrapped external-module discovery in https://github.com/microsoft/monaco-editor/issues/1839, carrying over the atob require example and lodash reference-file requirement. Distinguish that capability from loading genuinely global declarations, which the existing playground sample already demonstrates.

## Evidence

- **Verified open canonical:** https://github.com/microsoft/monaco-editor/issues/1839 is open and predates this report. Its body contrasts successful module-name suggestions for addExtraLib declarations wrapped in declare module with missing suggestions for unwrapped exported declarations, explicitly requesting support without rewriting them.
- **Matching central problem:** https://github.com/microsoft/monaco-editor/issues/2033 supplies an export = declaration registered as ts:filename/facts.d.ts and expects atob suggestions inside require. This is the JavaScript/CommonJS instance of the canonical's unwrapped external-module discovery request; the sample supplies no explicit mapping from facts.d.ts to the package name atob.
- **Canonical discussion covers external typings:** https://github.com/microsoft/monaco-editor/issues/1839#issuecomment-662344459 specifically discusses @types declarations lacking module wrappers. https://github.com/microsoft/monaco-editor/issues/1839#issuecomment-1913169234 suggests registering package metadata and node_modules paths; this is a reported workaround, not a verified fix for the present sample.
- **Current implementation boundary:** src/languages/features/typescript/tsWorker.ts includes extra libraries in getScriptFileNames, reads their registered paths through readFile/fileExists, and delegates getCompletionsAtPosition to the bundled TypeScript service. Registration does not itself assign an arbitrary declaration file a package name.
- **Global declarations are a separate supported pattern:** website/src/website/data/playground-samples/extending-language-services/configure-javascript-defaults/sample.js registers declare class Facts through addExtraLib and uses Facts.next() without an import. This addresses the commenter's global-declaration question, but does not make an export = module global or establish automatic loading of referenced declaration files.
