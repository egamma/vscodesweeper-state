# Issue #4798 — [Bug] Monarch: Markdown syntax highlighting: continuation lines of list items rendered as code blocks

[https://github.com/microsoft/monaco-editor/issues/4798](https://github.com/microsoft/monaco-editor/issues/4798)

## Summary

The current Markdown grammar still highlights four-space or tab-indented list continuations as code because it retains no list context. Route this to the bundled grammar owners; the identical older report was closed for inactivity, not fixed, and cannot serve as a duplicate canonical.

## Change summary

Markdown list continuation lines and paragraphs receive code-block highlighting when indented four spaces or one tab.

## Best solution

Correct list-context handling in src/languages/definitions/markdown/markdown.ts so continuation content receives appropriate Markdown highlighting while genuine indented code remains distinguishable. This is Monaco-owned grammar work with an existing tokenization test harness and prior maintainer willingness to accept a PR.

## Evidence

- **Current source confirms the trigger:** In src/languages/definitions/markdown/markdown.ts, language.tokenizer.root matches list markers with /^\s*([\*\-+:]|\d+\.)\s/ and emits only 'keyword', without transitioning to a list state. The following /^(\t|[ ]{4})[^ ].*$/ rule emits 'string' for the reporter's '    continuation of item2' and similarly indented paragraph after a blank line. Neither rule accounts for the preceding list item's content indentation.
- **Closed predecessor is not a canonical:** https://github.com/microsoft/monaco-editor/issues/2489 describes the same four-space/tab continuation symptom. A maintainer acknowledged the bug and welcomed a PR at https://github.com/microsoft/monaco-editor/issues/2489#issuecomment-857678579; it was closed for inactivity with an invitation to refile at https://github.com/microsoft/monaco-editor/issues/2489#issuecomment-1459974047, not closed as fixed or declined.
- **Canonical and implementation search:** Read-only searches for Markdown list highlighting and open Markdown issues/PRs found no open canonical owning this continuation-line defect or linked implementation candidate. The other open Markdown reports concern different observable symptoms.

Existing cases cover list markers but not continuation lines or continuation paragraphs.
