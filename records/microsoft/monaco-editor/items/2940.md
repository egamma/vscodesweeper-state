# Issue #2940 — [Bug] Disable highlighting of unicode characters option doesn't work.

[https://github.com/microsoft/monaco-editor/issues/2940](https://github.com/microsoft/monaco-editor/issues/2940)

## Summary

The ineffective hover action remains in the bundled editor core: it updates the standalone configuration service, not the editor's highlighting options. The documented API workaround does not resolve the misleading UI, and the maintainer explicitly requested disabling that UI in standalone editors.

## Change summary

Selecting “Disable highlighting of ambiguous characters” from the Unicode hover leaves the character highlighted.

## Best solution

Carry out the maintainer's direction to suppress the unsupported settings interaction in standalone editors while retaining Unicode explanations and API-based configuration. This change belongs in the microsoft/vscode editor core and should flow into Monaco through a subsequent release.

## Evidence

- **Maintainer direction:** The discussion at https://github.com/microsoft/monaco-editor/issues/2940 includes a MEMBER's February 4, 2022 explanation that standalone settings changes do not persist and that this hover message should be disabled for standalone editors. This is an accepted UI defect, not a request to disable all Unicode highlighting.
- **Bundled code path:** package.json pins vscodeRef to c132f72ae9f5ff80093e7d722c36f03755865b20; src/features/unicodeHighlighter/register.js imports the generated monaco-editor-core Unicode highlighter. At https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/contrib/unicodeHighlighter/browser/unicodeHighlighter.ts, the hover still appends the Adjust settings command, and DisableHighlightingOfAmbiguousCharactersAction.runAction calls IConfigurationService.updateValue rather than editor.updateOptions.
- **Current source trace:** At https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/standalone/browser/standaloneServices.ts, StandaloneConfigurationService.updateValue now updates in-memory configuration and emits a service event. However, https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/standalone/browser/standaloneCodeEditor.ts shows that StandaloneEditor applies editor options through construction/updateOptions, without subscribing to those configuration-service changes; UnicodeHighlighter listens to editor option changes. The hover write therefore does not change the active highlighting option.
- **Workaround versus remaining defect:** The February 18, 2022 example and February 2, 2023 comment at https://github.com/microsoft/monaco-editor/issues/2940 demonstrate unicodeHighlight: { ambiguousCharacters: false } at editor creation. That configures highlighting successfully but does not repair or remove the ineffective hover action.
- **Canonical search:** Searches for Unicode, ambiguous characters, standalone configuration, and Adjust settings found no verified open canonical for this defect. https://github.com/microsoft/vscode/issues/316619 is open but describes a different symptom: the settings picker flashes or fails to open near the top of the viewport, rather than a selected setting failing to change standalone highlighting.
