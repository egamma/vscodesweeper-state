# Issue #3378 — [Bug] Cannot disable suggestions for only one editor on page

[https://github.com/microsoft/monaco-editor/issues/3378](https://github.com/microsoft/monaco-editor/issues/3378)

## Summary

The per-editor configuration gap remains on current main: `wordBasedSuggestions` is explicitly global, so configuring one standalone editor updates the shared configuration used by every instance. Route this as an editor API and suggestion feature request rather than a bug.

## Change summary

Allow word-based suggestions to be enabled and scoped independently for each editor instance on the same page.

## Best solution

Make word-based suggestion configuration editor- or model-scoped in the vscode editor core so one editor can use suggestions while another disables them. Until then, `wordBasedSuggestions: "currentDocument"` prevents words from other models appearing, but does not provide independent enablement.

  > Thanks for the report and the multi-editor example. This is still an API limitation: `wordBasedSuggestions` is currently a global standalone-editor option, so changing it for one editor updates the shared configuration used by the others. `wordBasedSuggestions: "currentDocument"` can keep each editor's word suggestions limited to its own model, but independently disabling the feature for one instance requires editor- or model-scoped configuration in the vscode editor core.

## Evidence

- **global option:** Current vscode source declares `wordBasedSuggestions` under `IGlobalEditorOptions`, documented as options applying to all editors: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneCodeEditor.ts
- **shared configuration:** Each standalone editor passes its global options to the shared configuration service, whose `updateValues` writes one configuration model without a resource override: https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneCodeEditor.ts and https://github.com/microsoft/vscode/blob/main/src/vs/editor/standalone/browser/standaloneServices.ts
- **partial existing capability:** The word-completion provider supports `currentDocument`, which limits candidates to the active model but still reads the shared configuration: https://github.com/microsoft/vscode/blob/main/src/vs/editor/browser/services/editorWorkerService.ts
- **related API issue:** https://github.com/microsoft/monaco-editor/issues/1498 records the same configuration-service limitation, but does not clearly own the broader requirement for different values across simultaneous editor instances.
