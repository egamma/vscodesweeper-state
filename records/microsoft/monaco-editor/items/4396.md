# Issue #4396 — [Feature Request] Option to keep glyphs position without changes

[https://github.com/microsoft/monaco-editor/issues/4396](https://github.com/microsoft/monaco-editor/issues/4396)

## Summary

A real editor API gap remains: decoration stickiness controls growth at range edges but cannot pin a glyph to an absolute line number. Route this feature request to the editor API area.

## Change summary

Provide a decoration option that keeps a glyph at its original line number when edits move the associated text.

## Best solution

Decide in the vscode editor core whether decorations should support an absolute-position range behavior. Until then, embedders can listen to model-content changes and reset the decorations collection to the desired line.

## Evidence

- **current API:** The current vscode-derived API at https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts exposes four TrackedRangeStickiness values, all governing growth at range edges; none preserves an absolute line coordinate.
- **established semantics:** A maintainer explains at https://github.com/microsoft/monaco-editor/issues/442#issuecomment-306867160 that decorations are live-tracked and flow with edited text.
- **available workaround:** The current IEditorDecorationsCollection supports replacing its ranges, and the editor exposes onDidChangeModelContent, allowing an embedder to reapply the glyph at line 3 after edits; this is a workaround rather than the requested declarative option.
- **canonical search:** Searches across open microsoft/monaco-editor and microsoft/vscode issues found no broader open issue owning absolute-position decoration behavior.
