- **Trace:**

  > Current main's src/languages/definitions/register.all.ts has no MATLAB registration, and repository searches found no MATLAB or Octave grammar. Neighboring languages use registerLanguage in register.ts and lazy-load their tokenizer; src/languages/definitions/julia/julia.test.ts shows the shared testTokenization harness. The custom-language playground demonstrates that embedders can supply a Monarch tokenizer, but that is not bundled support. src/languages/definitions/objective-c/register.ts already claims .m, so automatic association is a public-behavior boundary rather than an incidental implementation detail. The discussion at https://github.com/microsoft/monaco-editor/issues/1577 suggests MATLAB/Octave and existing grammar sources, but does not settle compatibility or association policy. Keep this work in Monaco-owned language definitions; no editor-core change is established as necessary.
- **Open decisions:**
