# Issue #3615 — [Bug] Incorrect `[contenthash]` for filename for worker scripts from monaco-editor-webpack-plugin

[https://github.com/microsoft/monaco-editor/issues/3615](https://github.com/microsoft/monaco-editor/issues/3615)

## Summary

The webpack plugin still hashes only the worker entry file, so changes to bundled dependencies can retain the same worker URL. Keep this issue open while the existing fix candidate is reviewed.

## Change summary

Worker filename content hashes should change whenever the emitted worker bundle changes.

## Best solution

Review https://github.com/microsoft/monaco-editor/pull/4140 so emitted worker filenames reflect bundled content and MonacoEnvironment resolves those same filenames. The dependency-provider proposal does not fix this behavior.

## Evidence

- **Current source confirms the defect:** webpack-plugin/src/index.ts:getWorkerFilename supplies only fs.readFileSync(resolveMonacoPath(entry, monacoEditorPath)) to loaderUtils.interpolateName. Changing an imported dependency without changing the entry therefore cannot change the interpolated content hash.
- **Emission and runtime URL path:** createLoaderRules embeds the prematurely calculated filename in MonacoEnvironment.getWorkerUrl; createPlugins passes that filename to AddWorkerEntryPointPlugin. webpack-plugin/src/plugins/AddWorkerEntryPointPlugin.ts:getCompilerHook uses it as the child compiler's output filename, with the hash placeholder already replaced before bundling.
- **Open implementation candidate:** https://github.com/microsoft/monaco-editor/pull/4140 was verified OPEN and explicitly references this issue. It proposes deferring filename resolution until webpack computes worker asset hashes; an open referencing PR requires keeping the issue open.
- **Recent independent confirmation:** https://github.com/microsoft/monaco-editor/pull/5573 was verified OPEN. Its body reports that changing an imported worker dependency changes the bundle without changing its filename with either loader-utils provider, and explicitly states that the proposal does not fix this issue.
- **Maintainer-supported work:** The discussion at https://github.com/microsoft/monaco-editor/issues/3615 includes another affected embedder and a maintainer welcoming a PR. The issue already carries bug, webpack-plugin, and open for PR labels.
