It documents the same observable failure: command substitution causes a closing quote to be interpreted as an opening quote, corrupting subsequent shell highlighting.
- **Canonical diagnosis:** https://github.com/microsoft/monaco-editor/issues/1984#issuecomment-634391169 explains that parentheses inside command substitution terminate the variable token prematurely, leaving the closing quote to open an unterminated string. https://github.com/microsoft/monaco-editor/issues/1984#issuecomment-635446396 identifies the shell grammar's command-substitution state.
- **Current-source trace:** In src/languages/definitions/shell/shell.ts, parameters enters parameterBodyParen for $(). That state consumes quotes and nested opening parentheses as variable text, then pops at the first closing parenthesis. In this report's realpath/dirname expression, the inner dirname closing parenthesis therefore ends the outer state prematurely; the following double quote enters dblStringBody, which remains active past the outer closing parenthesis and into the following fi line.
- **Report-specific evidence:** https://github.com/microsoft/monaco-editor/issues/2899 supplies the complete nested realpath/dirname sample and homepage-demo instructions. The maintainer acknowledged the incorrect final quote and welcomed a PR; the reporter confirmed that the quote appears unfinished.
