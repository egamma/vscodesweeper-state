# Issue #3627 — [Feature Request] Support web-worker based monaco.editor.colorize

[https://github.com/microsoft/monaco-editor/issues/3627](https://github.com/microsoft/monaco-editor/issues/3627)

## Summary

Worker-safe standalone colorization remains a real capability gap: the current public colorize API still requires a document. The related iframe-styling request covers a different symptom and is not a duplicate canonical.

## Change summary

Support running standalone colorize and tokenize APIs in web workers without requiring window or document, avoiding main-thread blocking for large highlighting workloads.

## Best solution

Evaluate a worker-safe standalone API in the VS Code-derived editor sources, keeping DOM insertion and theme-style installation on the embedding page. Retain this request until that contract covers both colorize and tokenize; queueing main-thread calls is only a workaround.

At https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/standalone/browser/standaloneEditor.ts, colorize obtains the standalone theme service and unconditionally calls registerEditorContainer(mainWindow.document.body) before invoking Colorizer.colorize.
- **Existing capabilities do not cover worker execution:** The same standaloneEditor.ts exports tokenize, but from the browser-oriented standalone module rather than a worker-safe entry point. https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/base/browser/window.ts initializes mainWindow directly from window. Existing colorize and tokenize methods therefore do not establish the requested DOM-independent public contract.
- **Partial modernization is not full coverage:** https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/base/browser/trustedTypes.ts now uses globalThis.trustedTypes, addressing the example's direct window.trustedTypes concern. However, the public colorize path still accesses document.body, and https://github.com/microsoft/vscode/blob/c132f72ae9f5ff80093e7d722c36f03755865b20/src/vs/editor/standalone/browser/colorizer.ts still performs its line-tokenization/rendering loop synchronously.
- **Discussion and workaround:** In https://github.com/microsoft/monaco-editor/issues/3627, the author proposes queueing small blocks with setTimeout to yield between colorize calls, then explicitly extends the request to tokenize. Yielding between blocks does not provide worker execution or move a single large colorization operation off the main thread.
