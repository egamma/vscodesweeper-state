# Issue #3627 — [Feature Request] Support web-worker based monaco.editor.colorize

[https://github.com/microsoft/monaco-editor/issues/3627](https://github.com/microsoft/monaco-editor/issues/3627)

## Summary

The worker-safe colorization gap remains on current main: the public `colorize` API explicitly registers styles against `mainWindow.document.body`. The issue is already correctly classified and is the broader report relative to the later style-target request.

## Change summary

Provide supported worker-safe colorization and tokenization APIs so large code blocks can be processed without blocking the UI thread or requiring DOM globals.

## Best solution

Add a supported worker-safe entry point in the vscode standalone editor core that separates tokenization and HTML generation from theme CSS registration, then expose it through Monaco's tree-shakeable ESM surface. This looks suitable for a community PR, but the editor-core portion should land in `microsoft/vscode` first.

## Vision fit

- **Fit:** aligned
- **Reason:** A worker-safe, DOM-independent API supports Monaco's browser-library boundary and its current emphasis on modular ESM entry points.
- **Evidence:** Monaco v0.56.0 reorganized its ESM modules into "supported, tree-shakeable entry points" via https://github.com/microsoft/monaco-editor/pull/5155.
