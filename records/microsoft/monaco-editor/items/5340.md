# Issue #5340 — [Bug] [LSP] MonacoLspClient never disposes its language-feature registrations

[https://github.com/microsoft/monaco-editor/issues/5340](https://github.com/microsoft/monaco-editor/issues/5340)

## Summary

The provider-disposal gap remains in current source. Keep this issue open while the explicitly linked implementation candidate is reviewed; closing it before that PR merges would be premature.

## Change summary

MonacoLspClient leaves language providers registered after session teardown, causing stale hover and code-action requests on subsequent sessions.

## Best solution

Review https://github.com/microsoft/monaco-editor/pull/5339 and establish client teardown that releases its language-feature registrations. Repeated teardown and recreation should leave only the active client's providers, without accumulated Loading entries.
