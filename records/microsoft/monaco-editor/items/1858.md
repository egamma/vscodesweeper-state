# Issue #1858 — View Zones move to wrong position

[https://github.com/microsoft/monaco-editor/issues/1858](https://github.com/microsoft/monaco-editor/issues/1858)

## Summary

The reported stale-position path remains in the current VS Code editor core: whitespace recomputation still derives the zone position from the original `IViewZone.afterLineNumber`. The issue is already correctly routed to `editor-core` and should remain open.

## Change summary

View zones that move with text can jump back to their original absolute line after wrapping, folding, or another layout change recomputes whitespace.

## Best solution

Fix view-zone anchoring in the VS Code editor core at `src/vs/editor/browser/viewParts/viewZones/viewZones.ts`, preserving the tracked model position when whitespace properties are recomputed; Monaco will receive the change in a subsequent source update.
