# Issue #5076 — [Bug] LanguageConfiguration autoClosingPairs' notIn field doesn't work for variable/variable.source classes

[https://github.com/microsoft/monaco-editor/issues/5076](https://github.com/microsoft/monaco-editor/issues/5076)

## Summary

Arbitrary token classes in notIn are an unsupported capability, not broken existing behavior. Maintainers explicitly declined the same Markdown-code-block request in an earlier issue, providing direct precedent for an out-of-scope close.

## Change summary

Allow variable and variable.source tokens to suppress angle-bracket auto-closing through autoClosingPairs.notIn.

## Best solution

Retain the existing standard-token restriction and apply the established Monaco scope decision. Close with an explanation that custom token-class exclusions were previously considered and declined.

  > Thanks for the report and the playground example. `autoClosingPairs.notIn` recognizes the standard token categories `string`, `comment`, and `regex`, not arbitrary highlighting classes such as `variable` or `variable.source`.
