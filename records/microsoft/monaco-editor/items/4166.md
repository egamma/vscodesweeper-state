# Issue #4166 — [Bug] setExtraLibs does only work with relative paths

[https://github.com/microsoft/monaco-editor/issues/4166](https://github.com/microsoft/monaco-editor/issues/4166)

## Summary

Keep open: existing APIs support explicit declaration-file paths and compiler mappings, but do not automatically interpret a bare extra-library filePath as an import alias. The reporter's workaround does not satisfy the requested automatic handling.

## Change summary

Allow extra libraries registered under bare names such as myLib to resolve corresponding imports without manually rewriting their virtual paths.

## Best solution

Decide whether the Monaco TypeScript integration should offer automatic bare-name registration, with explicit compatibility rules for existing file paths. This belongs in the bundled TypeScript registration and worker integration, rather than the VS Code editor core.
