# Issue #4166 — [Bug] setExtraLibs does only work with relative paths

[https://github.com/microsoft/monaco-editor/issues/4166](https://github.com/microsoft/monaco-editor/issues/4166)

## Summary

A real capability gap remains: extra libraries require TypeScript-resolvable virtual file URIs, while Monaco has no import-map-aware mapping for bare module specifiers. The existing feature and TypeScript area labels already route it correctly.

## Change summary

Allow TypeScript extra libraries to satisfy bare imports resolved through browser import maps without requiring embedders to rewrite their paths as Monaco virtual URIs.

## Best solution

Add an explicit module-specifier-to-virtual-file mapping for the TypeScript worker, or document and test an equivalent compiler `paths` configuration if it fully covers import maps. The likely implementation surface is `src/languages/features/typescript/register.ts` and `src/languages/features/typescript/tsWorker.ts`; this looks suitable for a community PR.
