# Issue #2850 — [Bug] imports of a preloaded extraLib inside another extraLib fail

[https://github.com/microsoft/monaco-editor/issues/2850](https://github.com/microsoft/monaco-editor/issues/2850)

## Summary

This is standard TypeScript module scoping rather than an extraLib loading defect: the top-level import makes the second declaration file a module, so its namespace is not global.

## Change summary

Allow a global namespace declaration in one extraLib to reference types exported by another extraLib.

## Best solution

Keep Monaco's existing TypeScript behavior and express the declaration using `declare global`, or reference the exported type as `import('sausage.js').Sausage` without a top-level import.

- **Proposed comment:**

  > Thanks for the report and the reduced example. Both extra libraries are being loaded; the difference comes from TypeScript declaration semantics. A top-level `import` makes the second declaration file a module, so `SausageFactory` is scoped to that module rather than added globally.
  > 
  > You can either wrap the namespace in `declare global { ... }`, or keep the file global and write the return type as `import('sausage.js').Sausage` without a top-level import. TypeScript documents these patterns at https://www.typescriptlang.org/docs/handbook/declaration-merging.html#global-augmentation and https://www.typescriptlang.org/docs/handbook/modules/reference.html#import-types.
