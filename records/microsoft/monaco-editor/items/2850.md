# Issue #2850 — [Bug] imports of a preloaded extraLib inside another extraLib fail

[https://github.com/microsoft/monaco-editor/issues/2850](https://github.com/microsoft/monaco-editor/issues/2850)

## Summary

The sample matches TypeScript's module-scoping rules rather than an extraLib loading failure; global augmentation supports the requested separation. Keep open because the existing bug label bars a judgment close without a later maintainer decision in this thread.

## Change summary

Make a global namespace in one extraLib reference types imported from another extraLib.

## Best solution

Retain the separate extraLibs and top-level import, but declare SausageFactory inside declare global. A maintainer should resolve the existing bug classification in light of this supported pattern rather than change TypeScript's module-scoping behavior.

- **Proposed comment:**

  > Thanks for the report and the example. A top-level import makes the second extraLib a TypeScript module, so SausageFactory is module-local rather than global. Keep the import and place the namespace inside `declare global { namespace SausageFactory { function newSausage(): SausageLib.Sausage; } }`. This preserves separate libraries and access to the imported types. The same pattern was confirmed in https://github.com/microsoft/monaco-editor/issues/2456#issuecomment-838917401; generated global variables can also go inside that block.
