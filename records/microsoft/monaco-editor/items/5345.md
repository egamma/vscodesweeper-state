# Issue #5345 — [Bug] The language files of nls.messages in the npm package have two `.js` extensions: monaco-editor/min/vs/nls.messages.zh-cn.js.js

[https://github.com/microsoft/monaco-editor/issues/5345](https://github.com/microsoft/monaco-editor/issues/5345)

## Summary

The doubled localization-file extension was eliminated by the packaging reorganization shipped in v0.56.0. Localization assets now use min/vs/nls/lang/zh-cn.js rather than the old nls.messages filenames.

## Change summary

Prevent localization payloads from being packaged with a doubled .js.js extension.

## Best solution

Treat this as fixed in v0.56.0 and later, documenting the replacement localization path rather than restoring the obsolete filename.

## Evidence

- **Trigger and root cause:** The reporter inspected v0.55.0/v0.55.1 and found nls.messages.zh-cn.js.js. The v0.55.1 build/shared.mjs getNlsEntryPoints retained the source filename's .js extension, while the AMD output callback appended another .js.
- **Concrete fixing diff:** https://github.com/microsoft/monaco-editor/commit/558bbbcc1619da88d466bd64856f337a5604e43c removes localization files from getNlsEntryPoints, extracts the locale with /nls\.messages\.(?<lang>.+)\.js/, and constructs nls/lang/<locale>.js assets. Its build/amd/vite.config.mjs generateBundle emits these explicit filenames, bypassing the callback that appended the second extension; its nls.messages-loader.js switches requests to vs/nls/lang/<locale>.
- **Current-source trace:** Current build/shared.mjs getNlsFiles constructs nls/lang/zh-cn.js, build/amd/vite.config.mjs emits it as an asset with that exact filename, and build/amd/src/nls.messages-loader.js requests vs/nls/lang/${requestedLanguage}. The reported double-extension generation path no longer exists.
- **First shipped release:** CHANGELOG.md attributes the module reorganization to https://github.com/microsoft/monaco-editor/pull/5155 under v0.56.0. GitHub reads of the v0.56.0 build files confirm adoption, and https://unpkg.com/monaco-editor@0.56.0/min/vs/nls/lang/zh-cn.js returns the Chinese localization payload.
