# Issue #2145 — Links inside escaped strings consider ending `\` as part of the link 

[https://github.com/microsoft/monaco-editor/issues/2145](https://github.com/microsoft/monaco-editor/issues/2145)

## Summary

Keep this enhancement open and route it to editor-core: current link detection still treats quotes as single-character delimiters without recognizing their escape sequences. The team consolidated the related escaped-quote report here, so this issue remains the tracking item.

## Change summary

Make automatic link detection recognize escaped quote delimiters without including the closing backslash or prematurely truncating URLs containing escaped quotes.

## Best solution

Address escape-aware link boundaries in microsoft/vscode's shared editor link detector, then carry the change into Monaco through a release cut. Preserve this issue's trailing-backslash example and the related embedded-quote variant as acceptance cases.

- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources"; the durable themes include tracking the VS Code editor core.

## Evidence

- **Reported behavior and maintainer diagnosis:** https://github.com/microsoft/monaco-editor/issues/2145 includes a complete JavaScript playground snippet where the detected URL ends in a backslash. The maintainer explains that detection records the opening quote and terminates at the next matching quote; the reporter requests multi-character opening sequences.
- **Current shared detector:** Read https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages/linkComputer.ts via the GitHub API. LinkComputer.computeLinks stores one linkBeginChCode and terminates on a matching quote without checking escaping. Backslash is neither a termination character nor a character trimmed by _createLink, so the original snippet's closing escape backslash remains in the URL.
- **Existing capability does not cover the request:** https://github.com/microsoft/vscode/blob/main/src/vs/monaco.d.ts exposes languages.registerLinkProvider and LinkProvider.provideLinks for custom URL ranges and targets. This allows an embedder-specific implementation, but does not make built-in detection escape-aware; the links editor option only enables or disables detection.
- **Related report consolidated into this issue:** https://github.com/microsoft/monaco-editor/issues/2170 is closed. Its maintainer comment explicitly says to track the escaped-quote variant in this issue: https://github.com/microsoft/monaco-editor/issues/2170#issuecomment-702640468. It is not an open duplicate canonical.
