# Issue #4404 — [Bug] Regex without anchor `^` in the tokenizer rule matches only the beginning of the string

[https://github.com/microsoft/monaco-editor/issues/4404](https://github.com/microsoft/monaco-editor/issues/4404)

## Summary

The sample demonstrates Monarch's intended sequential matching, not a tokenizer defect: the plain-text rule consumes the entire indented line before the link rule can match again. This is a tokenizer-configuration question.

## Change summary

Recognize custom markdown-like links after preceding text in a Monarch tokenizer.

## Best solution

Keep Monarch's current-position matching semantics and adjust the custom plain-text rule to stop before potential link starts, with a fallback for unmatched braces. Rule ordering alone cannot prevent a successful plain-text match from consuming later links.

- **Proposed comment:**

  > Thanks for the report and the sample. Monarch tries rules at the current token position; omitting `^` does not make a rule search ahead. An explicit `^` additionally restricts a rule to the beginning of the source line.
  > 
  > On the indented line, the link rule fails at the first space, then `/[^<&]+/` consumes the entire line, including the link. Putting the link rule first therefore cannot help once that plain-text match succeeds. To recognize links after other text, make the plain-text rule stop before `{` and provide a fallback for braces that do not begin a valid link.
  > 
  > This follows the documented tokenizer behavior: https://microsoft.github.io/monaco-editor/monarch.html. Configuration questions belong on StackOverflow's monaco-editor tag: https://stackoverflow.com/questions/tagged/monaco-editor.
