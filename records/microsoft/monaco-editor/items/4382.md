# Issue #4382 — [Bug] Syntax Highlighting Issue with Regex Containing Backtick in JavaScript

[https://github.com/microsoft/monaco-editor/issues/4382](https://github.com/microsoft/monaco-editor/issues/4382)

## Summary

Still present on main: Monaco's shared JavaScript/TypeScript Monarch tokenizer rejects an unescaped slash inside a regular-expression character class while identifying the literal, causing the later backtick to start a template string. Route this to basic-language tokenization.

## Change summary

JavaScript syntax highlighting breaks after a regular-expression character class containing both an unescaped slash and a backtick.

## Best solution

Update the regular-expression opener detection in src/languages/definitions/typescript/typescript.ts to recognize character classes and permit `/` within them, then add JavaScript and TypeScript tokenization regressions using the reported expression.

## Evidence

- **current source:** src/languages/definitions/typescript/typescript.ts:244-247 identifies a regex with `([^\\/]|\\.)+`, which rejects every unescaped `/`, including one inside a character class. JavaScript imports this tokenizer from the TypeScript definition.
- **failure path:** Because the opener check fails, the tokenizer remains in its common state, where src/languages/definitions/typescript/typescript.ts:280 interprets the reported backtick as the start of `string_backtick`; this accounts for the subsequent incorrect highlighting.
- **language specification:** ECMAScript's RegularExpressionClassChar production excludes only `]` and `\\`, so an unescaped `/` is permitted inside a character class: https://tc39.es/ecma262/multipage/ecmascript-language-lexical-grammar.html#sec-literals-regular-expression-literals
- **reproduction:** The issue provides a v0.46.0 playground reproduction at https://microsoft.github.io/monaco-editor/playground.html?source=v0.46.0 showing the same tokenizer failure, and the relevant opener rule remains unchanged on current main.
