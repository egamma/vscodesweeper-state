# Issue #2498 — `ViewImpl`  follow the open–closed principle

[https://github.com/microsoft/monaco-editor/issues/2498](https://github.com/microsoft/monaco-editor/issues/2498)

## Summary

The requested view-part extensibility remains absent: current VS Code source still constructs Margin and Minimap directly and keeps its view-part collection private. Keep this accepted Backlog request open; the public extension-point decision belongs in the VS Code editor core.

## Change summary

Allow embedders to compose or extend built-in view parts such as Margin and Minimap without modifying editor source.

## Best solution

Evaluate a supported extension contract in the VS Code editor core for concrete customization scenarios that existing widgets, decorations, and minimap options cannot cover. Any accepted capability should flow into Monaco through its generated API rather than a Monaco-only fork of View.
