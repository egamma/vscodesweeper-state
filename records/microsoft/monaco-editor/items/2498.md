# Issue #2498 — `ViewImpl`  follow the open–closed principle

[https://github.com/microsoft/monaco-editor/issues/2498](https://github.com/microsoft/monaco-editor/issues/2498)

## Summary

The requested extension point remains absent: current editor-core source still constructs private margin and minimap view parts directly. The issue is already correctly classified and accepted into the Backlog, with no verified canonical duplicate.

## Change summary

Provide a supported composition or extension mechanism for replacing editor view parts such as the margin and minimap.

## Best solution

Design the extension seam in the VS Code editor core, likely through supported factories or registrations rather than exposing the private view-parts array, and let it flow into Monaco with the next source update. Existing widget APIs cover additions but not replacement of the margin or minimap.

## Vision fit

- **Fit:** rejected
- **Reason:** A Monaco-only hook into private editor internals conflicts with the generated-from-VS-Code model; the capability should first become a supported VS Code editor-core API.
- **Evidence:** The README states that Monaco is "generated straight from VS Code's sources with some shims around services the code needs to make it run in a web browser."
