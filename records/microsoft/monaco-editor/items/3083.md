# Issue #3083 — The global window object is polluted after monaco-editor initialization

[https://github.com/microsoft/monaco-editor/issues/3083](https://github.com/microsoft/monaco-editor/issues/3083)

## Summary

The global `define` is intentional when using Monaco's AMD loader; the supported global-free solution is the ESM build. AMD is now deprecated, so changing its module-registration behavior is not planned.

## Change summary

Avoid exposing the AMD loader's `define` function on `window` because it interferes with other UMD-aware libraries.

## Best solution

Use the ESM package directly, including configuring community wrappers such as `@monaco-editor/react` to use the imported `monaco-editor` module instead of their default AMD CDN loader.

## Vision fit

- **Fit:** rejected
- **Reason:** Changing the deprecated AMD loader conflicts with Monaco's ESM-first packaging direction, while the ESM build already provides the requested global-free integration.
- **Evidence:** The README says AMD support is deprecated and will be removed, and CHANGELOG v0.53.0 directs consumers to migrate to ESM.

- **Proposed comment:**

  > Thanks for the report and follow-up context. A global `define` is part of loading Monaco through its AMD loader; loading Monaco through ESM does not create that global. The AMD build is now deprecated and retained only for backward compatibility, so the supported resolution is to import `monaco-editor` through ESM. For `@monaco-editor/react`, the workaround documented in this thread—importing `monaco-editor` and passing it to `loader.config({ monaco })`—avoids its default AMD CDN loader. Closing this as designed because the ESM integration already provides the requested global-free behavior.
