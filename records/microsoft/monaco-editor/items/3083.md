# Issue #3083 — The global window object is polluted after monaco-editor initialization

[https://github.com/microsoft/monaco-editor/issues/3083](https://github.com/microsoft/monaco-editor/issues/3083)

## Summary

The global define is intentional for AMD loading; the maintainer identified ESM as the supported way to avoid it, and a later commenter confirmed that approach resolves their conflict.

## Change summary

Avoid installing window.define during Monaco initialization so unrelated UMD libraries do not detect an AMD environment.

## Best solution

Use the documented ESM integration rather than changing AMD loader semantics. For @monaco-editor/react, configure its loader with the imported Monaco module instead of its default CDN-based AMD loading.

- **Fit:** aligned
- **Reason:** Avoiding AMD globals through existing ESM integration matches the project's modern packaging direction.
- **Evidence:** The vision's packaging theme favors ESM integration; README.md and CHANGELOG.md document AMD deprecation and migration to ESM.
