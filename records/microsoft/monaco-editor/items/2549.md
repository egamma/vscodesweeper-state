# Issue #2549 — Can't get @types type definitions to work correctly

[https://github.com/microsoft/monaco-editor/issues/2549](https://github.com/microsoft/monaco-editor/issues/2549)

## Summary

The underlying URI-encoding defect remains visible on current main: TypeScript model filenames are again serialized with encoding, so `@types` becomes `%40types` before reaching the language service. The issue is already routed correctly and should remain open.

## Change summary

External package declarations under node_modules/@types should resolve normally and produce package-name imports instead of encoded or relative paths.

## Best solution

Preserve URI correctness for other special characters while passing TypeScript a filesystem/module-resolution representation that retains the literal `@types` path. The fix belongs in the TypeScript worker's model filename and lookup handling under src/languages/features/typescript/tsWorker.ts.
