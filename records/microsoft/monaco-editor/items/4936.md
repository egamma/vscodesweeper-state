# Issue #4936 — [Feature Request] Minimap background color improvements

[https://github.com/microsoft/monaco-editor/issues/4936](https://github.com/microsoft/monaco-editor/issues/4936)

## Summary

A real minimap capability gap remains: current APIs support section headers and colored range decorations, but not automatic function-boundary segmentation. This is generated editor-core behavior and should be routed to the minimap area while the product decision is made in microsoft/vscode.

## Change summary

Automatically divide the minimap into colored function-sized regions to improve structural navigation.

## Best solution

Design this in the VS Code editor core as an optional minimap mode backed by document symbols, then inherit it in a subsequent Monaco release. Embedders can approximate it today by resolving functions and applying colored minimap decorations, but that does not provide the requested built-in behavior.

## Vision fit

- **Fit:** rejected
- **Reason:** A Monaco-only editor behavior conflicts with the generated-from-VS-Code model; the feature would fit only if implemented in the shared VS Code editor core.
- **Evidence:** The README guardrail states that Monaco is “generated straight from VS Code's sources,” making behavior parity with the VS Code editor the specification.

## Evidence

- **decoration API:** `IModelDecorationMinimapOptions` accepts a color and Inline/Gutter position for caller-supplied ranges, but it has no function segmentation option: https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/common/model.ts
- **current implementation:** The section-header contribution detects configured comments and regions and renders header decorations; it does not derive function ranges from document symbols: https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/contrib/sectionHeaders/browser/sectionHeaders.ts
- **release history:** Monaco's CHANGELOG documents minimap section headers in v0.48.0 and `sectionHeaderLetterSpacing` in v0.50.0, but no automatic function-region coloring.
