# Issue #4818 — [Bug] In peek view 'Go to references' is not navigating to the specific file editor when double click on the specfic references.

[https://github.com/microsoft/monaco-editor/issues/4818](https://github.com/microsoft/monaco-editor/issues/4818)

## Summary

Cross-model reference navigation is intentionally delegated to the embedding application. Monaco 0.41.0 already provides `monaco.editor.registerEditorOpener` for switching the model or opening the target in an application-managed editor.

## Change summary

Double-clicking a cross-file reference should navigate to the corresponding file editor.

## Best solution

Keep the current embedder-controlled behavior and register an editor opener that selects the target model or application tab and applies the supplied position or range.

## Vision fit

- **Fit:** rejected
- **Reason:** Automatic file-editor navigation belongs to the embedding application, while Monaco exposes an API-neutral hook rather than owning tabs or application navigation.
- **Evidence:** The vision describes Monaco as a browser library rather than an app platform and says embedders integrate through its API.

- **Proposed comment:**

  > Thanks for the report. Cross-model navigation is intentionally left to the embedding application because Monaco does not own its file tabs or model lifecycle. Monaco 0.41.0 includes `monaco.editor.registerEditorOpener`, introduced in 0.38.0 through https://github.com/microsoft/vscode/pull/177064; its callback receives the target URI and position/range so your application can select the corresponding editor or call `setModel`. The default behavior of not replacing the attached model is therefore as designed.

## Evidence

- **documented API:** Current `src/vs/monaco.d.ts` documents `registerEditorOpener` and explicitly states that the default is to do nothing when opening a model other than the attached one: https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/monaco.d.ts#L1157-L1180
- **available in reported version:** CHANGELOG.md lists `registerEditorOpener` as new in Monaco 0.38.0; the report uses the later 0.41.0 release.
- **implementation rationale:** https://github.com/microsoft/vscode/pull/177064 explains that automatic model replacement would be harmful for many embedders and provides an example that switches models inside `openCodeEditor`; it merged as https://github.com/microsoft/vscode/commit/663faf188b12c084ebe84233b8ee006b3285bd35.
- **distinct related report:** https://github.com/microsoft/monaco-editor/issues/5294 concerns an unhandled cancellation after cross-file navigation succeeds, so it does not own this request.
