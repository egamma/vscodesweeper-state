# Issue #4907 — [Bug] editor.foldLevel1 does not fold first region if it's the first line

[https://github.com/microsoft/monaco-editor/issues/4907](https://github.com/microsoft/monaco-editor/issues/4907)

## Summary

This is intentional fold-command behavior: Fold Level excludes any region containing the current cursor, which initially sits on line 1. The leading newline workaround moves the first region away from that cursor.

## Change summary

Make programmatic Fold Level 1 collapse a first-line region even when it contains the editor cursor.

## Best solution

Keep the shared VS Code folding semantics. Embedders that need every top-level region collapsed should place the cursor on a line outside all folding regions before running `editor.foldLevel1`.

  > Thanks for the clear playground examples. This is the intended behavior of the shared VS Code folding command: `editor.foldLevel1` passes the current cursor line as a blocked line, and level folding excludes any region containing it (https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/contrib/folding/browser/folding.ts#L1034-L1044 and https://github.com/microsoft/vscode/blob/18ebe6515d696f52fa3172fa3d5d878ac8424e78/src/vs/editor/contrib/folding/browser/foldingModel.ts#L402-L410). The cursor initially sits on line 1, so the first region remains open; adding the newline works because line 1 is then outside that region. For automatic folding, move the cursor to a line outside the folding regions before running the action.
