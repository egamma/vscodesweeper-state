# Issue #631 — Launch as http://localhost instead of http://127.0.0.1?

[https://github.com/microsoft/vscode-livepreview/issues/631](https://github.com/microsoft/vscode-livepreview/issues/631)

## Summary

Launching previews as localhost while preserving live reload remains unsupported in current source. This is a maintainer-accepted Backlog feature with concrete third-party integration use cases, and the canonical search found no older open issue owning the same request.

## Change summary

Support opening previews at http://localhost rather than http://127.0.0.1 while retaining working live reload.

## Best solution

Provide a supported localhost launch option through src/connectionInfo/ that keeps preview URLs, injected reload endpoints, and server origin checks consistent. Preserve loopback-only binding and existing remote forwarding behavior; changing the address manually or adding response headers does not satisfy the request.

## Evidence

- **Maintainer-accepted work:** The maintainer explicitly accepted localhost launching as a backlog feature and suggested enabling it when livePreview.hostIP is 127.0.0.1: https://github.com/microsoft/vscode-livepreview/issues/631#issuecomment-2070845787. The current feature-request label and Backlog milestone reflect that decision.
- **Existing-capability check:** package.json contributes.configuration and contributes.commands expose no separate launch-hostname option. livePreview.hostIP defaults to 127.0.0.1, and src/connectionInfo/connectionManager.ts implements _validHost with net.isIPv4; localhost is rejected and replaced with DEFAULT_HOST both initially and on configuration changes. Connection.constructLocalUri in src/connectionInfo/connection.ts constructs URLs directly from that host.
- **Response headers do not cover the request:** package.nls.json defines livePreview.httpHeaders as extra server response headers. These do not change the preview's hostname or supply the localhost referring origin required by the reporter's FontAwesome integration. The discussion also provides a payment-provider sandbox use case and reports that manually substituting localhost loses live reload: https://github.com/microsoft/vscode-livepreview/issues/631.
- **Live-reload integration boundary:** src/server/serverUtils/HTMLInjector.ts derives the injected HTTP and WebSocket addresses from Connection's resolved URIs. In src/server/wsServer.ts, WSServerWithOriginCheck.shouldHandle checks the request origin against the resolved HTTP origin or a webview origin. Supporting localhost therefore requires consistent connection and origin handling, not merely changing the visible browser address.
- **Canonical and implementation search:** Repository issue searches for localhost, hostname, and host name found no older open report owning this launch-hostname request. The body-linked https://github.com/microsoft/vscode-livepreview/issues/145 is closed and concerns configuring the served base path, not choosing localhost. The open https://github.com/microsoft/vscode-livepreview/pull/861 concerns forwarded addresses in dev containers, a distinct remaining task; no relevant open implementation PR was identified.
