# Issue #631 — Launch as http://localhost instead of http://127.0.0.1?

[https://github.com/microsoft/vscode-livepreview/issues/631](https://github.com/microsoft/vscode-livepreview/issues/631)

## Summary

This remains a valid, maintainer-accepted feature request: current `main` only accepts IPv4 values for `livePreview.hostIP` and consequently advertises `127.0.0.1` rather than `localhost`. No existing setting, canonical issue, or linked PR delivers the requested hostname behavior.

## Change summary

Allow locally hosted previews and their live-reload WebSocket to use `localhost` as the browser-facing hostname instead of `127.0.0.1`.

## Best solution

Separate the server's binding address from its browser-facing hostname in `src/connectionInfo/`: continue binding HTTP and WebSocket servers to the configured loopback IP, but optionally construct both advertised URLs with `localhost`, including origin validation and injected live-reload URLs. Add connection tests covering matching HTTP and WebSocket authorities so changing the browser URL does not break reload.

## Vision fit

- **Fit:** aligned
- **Reason:** Configurable host behavior and reliable live refresh are established server-lifecycle themes, and this closes a practical integration gap without turning Live Preview into an application server.
- **Evidence:** The durable themes explicitly include host configuration through `livePreview.hostIP` and live-refresh correctness; the README positions Live Preview as a local server plus preview for plain web projects.

## Evidence

- **maintainer acceptance:** A maintainer confirmed that no localhost-launch setting exists and explicitly accepted supporting localhost as a backlog feature in https://github.com/microsoft/vscode-livepreview/issues/631#issuecomment-2070712074.
- **current source gap:** `src/connectionInfo/connectionManager.ts` imports Node's `isIPv4` and `_validHost()` returns only `isIPv4(host)`, so `livePreview.hostIP: "localhost"` is rejected and reset to `DEFAULT_HOST` (`127.0.0.1`).
- **shared advertised hostname:** `src/connectionInfo/connection.ts` constructs both HTTP and WebSocket URIs from `this.host`, while `src/server/httpServer.ts` and `src/server/wsServer.ts` also bind using that value. - **existing setting does not cover request:** `package.json` exposes `livePreview.hostIP` with default `127.0.0.1`; `livePreview.httpHeaders` only adds response headers in `src/server/httpServer.ts` and cannot change the browser's URL, Referer, cookie domain, or third-party origin allowlist.
