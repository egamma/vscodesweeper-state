# Issue #631 — Launch as http://localhost instead of http://127.0.0.1?

[https://github.com/microsoft/vscode-livepreview/issues/631](https://github.com/microsoft/vscode-livepreview/issues/631)

## Summary

This remains a valid, maintainer-accepted feature request: current main still requires `livePreview.hostIP` to be an IPv4 address and constructs preview and reload URLs from that address, so users cannot launch as `localhost` while retaining live reload. No other open issue or PR owns the request.

## Change summary

Allow locally hosted previews and their live-reload WebSocket connection to use `localhost` rather than `127.0.0.1`.

## Best solution

Support `localhost` as a loopback-only preview authority, either through a dedicated setting or when `livePreview.hostIP` is `127.0.0.1`, while keeping the HTTP and WebSocket authorities consistent and preserving remote-host restrictions. The implementation belongs primarily in `src/connectionInfo/`, with corresponding preview URL, origin-validation, and integration-test coverage.

- **Evidence:** The durable themes explicitly include server lifecycle and configuration through `livePreview.hostIP`, while the product promise is to host a local server and preview the served project.

## Evidence

- **current source gap:** `src/connectionInfo/connectionManager.ts` imports Node's `isIPv4`, and `_validHost` returns only `isIPv4(host)`; therefore `livePreview.hostIP: "localhost"` is rejected and reset to the default `127.0.0.1`.
- **shared HTTP and WebSocket authority:** `src/connectionInfo/connection.ts` constructs local HTTP and WebSocket base URIs as `http://${this.host}:${port}`. `src/editorPreview/previewManager.ts` likewise launches integrated and external previews using `connection.host`, explaining why manually replacing the browser URL with `localhost` loses live reload.
- **accepted backlog request:** In https://github.com/microsoft/vscode-livepreview/issues/631, a maintainer confirmed that no setting currently provides this behavior and explicitly accepted supporting localhost as a backlog feature; the issue remains open with the `feature-request` label and Backlog milestone.
- **confirmed use cases:** Multiple commenters on https://github.com/microsoft/vscode-livepreview/issues/631 independently identify domain allowlists, payment sandboxes, cookies, and third-party resources that distinguish `localhost` from `127.0.0.1`; one commenter confirmed that changing the browser URL works but breaks the WebSocket reload connection.
- **canonical search:** Repository searches for open issues and pull requests mentioning `localhost`, `127.0.0.1`, and `hostIP` found no broader open item or implementation PR that owns this launch-authority request.
