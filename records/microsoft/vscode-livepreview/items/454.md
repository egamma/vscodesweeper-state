# Issue #454 — Live preview reloads on editor changes even when not visible

[https://github.com/microsoft/vscode-livepreview/issues/454](https://github.com/microsoft/vscode-livepreview/issues/454)

## Summary

Current `main` still reloads every connected preview after qualifying editor changes without checking whether the bundled preview panel is visible. This is a confirmed extension-side gap, and the team-authored issue should remain open.

## Change summary

Avoid reloading and re-executing a page in an embedded Live Preview tab while that tab is hidden.

## Best solution

Track the visibility of the bundled webview through its panel lifecycle, suppress its automatic reloads while hidden, and perform one refresh when it becomes visible again. Preserve reload behavior for visible previews and external-browser clients; separately determine whether VS Code's Integrated Browser exposes enough lifecycle information for equivalent behavior on the current default path.

  > Thanks for the report. This still reproduces from the current source for the bundled preview: the webview retains its context while hidden, editor changes lead to a refresh of every server grouping, and the WebSocket server sends `reload` to every connected client without consulting the panel's visibility. https://github.com/microsoft/vscode-livepreview/issues/457 tracks the related prerequisite of identifying whether an injected client belongs to an embedded preview, but it does not replace the visibility-gating behavior requested here. The fix should defer reloads for the hidden bundled panel and refresh once when it becomes visible again, without suppressing external-browser refreshes.

## Evidence

- **source reproduction:** `src/updateListener.ts` handles every qualifying `onDidChangeTextDocument` event by firing `shouldRefreshPreviews`; `src/manager.ts` responds by refreshing every server grouping, with no preview-visibility condition.
- **unconditional client reload:** `src/server/wsServer.ts` sends a `reload` command to every connected WebSocket client, and `media/injectScript.js` handles that command by calling `window.location.reload()` without checking document or panel visibility.
- **hidden webview remains active:** `src/editorPreview/previewManager.ts` creates the bundled preview with `retainContextWhenHidden: true`, while neither `PreviewManager` nor `BrowserPreview` registers `WebviewPanel.onDidChangeViewState`; therefore a hidden panel remains connected and receives the broadcast reload.
- **related prerequisite, not duplicate:** https://github.com/microsoft/vscode-livepreview/issues/457 tracks making the injected script aware of whether it belongs to an embedded webview and explicitly names visibility-aware refreshing as a possible use, but awareness alone would not implement this issue's required suppression and deferred refresh behavior.
