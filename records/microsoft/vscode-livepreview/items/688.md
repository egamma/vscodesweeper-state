# Issue #688 — Incorrect Content-Type header for XHTML files

[https://github.com/microsoft/vscode-livepreview/issues/688](https://github.com/microsoft/vscode-livepreview/issues/688)

## Summary

Current main still reproduces the defect in source: when an open XHTML document has VS Code's `html` language ID, `ContentLoader.getFileStream` replaces the MIME-derived `application/xhtml+xml` value with `text/html`. The only referenced fixing PR was closed without merging, so a real serving-correctness gap remains.

## Change summary

Preserve the `application/xhtml+xml` response type for XHTML documents while continuing to inject the live-refresh script.

## Best solution

Update `src/server/serverUtils/contentLoader.ts` so HTML-language documents retain an XHTML MIME type when appropriate while ordinary HTML and untitled HTML still receive `text/html`; add an HTTP-level regression test that verifies both the XHTML Content-Type and live-refresh injection.
