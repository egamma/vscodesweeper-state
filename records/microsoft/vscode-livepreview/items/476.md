# Issue #476 — [Feature request] Allow setting multiple preferred Server Roots as one string

[https://github.com/microsoft/vscode-livepreview/issues/476](https://github.com/microsoft/vscode-livepreview/issues/476)

## Summary

Keep open: current main still accepts only one server-root path, and the explicitly linked implementation PR remains open. That PR includes a maintainer-supported configuration direction and an unresolved root-switching problem, so the request is neither implemented nor ready for closure.

## Change summary

Support ordered preferred server roots, including '.' for the previewed file's directory, with workspace-root fallback when no candidate exists.

## Best solution

Review and resolve https://github.com/microsoft/vscode-livepreview/pull/581, following the maintainer's preference for a string-or-array setting with documented precedence. Before landing, resolve the reported stale-root behavior when switching previewed files so candidate selection and the running server consistently use the intended root.

## Evidence

- **Existing capability does not cover the request:** package.json declares livePreview.serverRoot as a resource-scoped string. package.nls.json describes one workspace-relative path with workspace-root fallback, while livePreview.defaultPreviewPath only selects the initial file. None of the declared commands provides ordered root selection.
- **Current source treats the value as one path:** src/utils/pathUtil.ts, PathUtil.GetValidServerRootForWorkspace, joins the entire serverRoot string to workspace.uri.fsPath and checks that single path's existence. It neither iterates preferred candidates nor resolves '.' against the previewed file's directory.
- **Open implementation candidate blocks closure:** https://github.com/microsoft/vscode-livepreview/pull/581 is verified OPEN and explicitly references this issue in its body and closingIssuesReferences. Its proposed changes cover package.json, package.nls.json, src/utils/pathUtil.ts, and src/utils/settingsUtil.ts.
- **Maintainer-supported configuration direction:** The changes-requested review on https://github.com/microsoft/vscode-livepreview/pull/581 prefers a setting accepting either a string or an array instead of parsing a delimited string. https://github.com/microsoft/vscode-livepreview/pull/581#issuecomment-1856736891 additionally asks that first-entry precedence be documented.
- **Unresolved implementation behavior:** https://github.com/microsoft/vscode-livepreview/pull/581#issuecomment-1857070596 reports that switching from dist/index.html to publish/index.html still serves dist's content until the server is stopped, with similar problems for dynamically resolved '.'. This is evidence against treating the open proposal as completed.
- **Canonical-search result:** https://github.com/microsoft/vscode-livepreview/issues/155 is closed and requests only a single configurable root, not ordered alternatives. A repository search for server-root issues surfaced https://github.com/microsoft/vscode-livepreview/issues/425 about nonexistent-root handling, which does not own this request's remaining work; no verified older same-scope canonical was established.
