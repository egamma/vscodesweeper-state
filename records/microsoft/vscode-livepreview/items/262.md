# Issue #262 — Not correctly checking if websocket server is occupied before using it

[https://github.com/microsoft/vscode-livepreview/issues/262](https://github.com/microsoft/vscode-livepreview/issues/262)

## Summary

The WebSocket port-collision defect remains in current source: startup checks only the HTTP candidate, and WebSocket collision recovery replaces the server without attaching its listeners. Keep this team-authored issue open; no verified fix or qualifying canonical duplicate was found.

## Change summary

Handle an occupied WebSocket port reliably instead of assuming the port immediately after the available HTTP port is usable.

## Best solution

Make server startup in src/server/serverGrouping.ts and src/server/wsServer.ts complete reliably when the HTTP port is free but its following port is occupied, with the final WebSocket endpoint supporting live reload. Preserve the existing connection-origin and randomized-path protections; sharing a listener across paths is not necessary to satisfy the collision-handling requirement.
