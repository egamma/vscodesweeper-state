# Issue #262 — Not correctly checking if websocket server is occupied before using it

[https://github.com/microsoft/vscode-livepreview/issues/262](https://github.com/microsoft/vscode-livepreview/issues/262)

## Summary

Current source still mishandles an occupied WebSocket port: the retry creates a replacement server without attaching its event handlers, leaving server startup unresolved. This team-authored issue remains necessary, and no later commit explicitly referencing it was found.

## Change summary

Ensure Live Preview detects or recovers correctly when the WebSocket port adjacent to the selected HTTP port is already occupied.

## Best solution

Make WebSocket startup retry through one shared initialization path that attaches the connection, error, and listening handlers on every attempt, then add a server test that occupies the initial WebSocket port and verifies startup completes on another port with a working reload connection.
