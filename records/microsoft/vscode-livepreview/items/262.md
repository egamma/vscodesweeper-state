# Issue #262 — Not correctly checking if websocket server is occupied before using it

[https://github.com/microsoft/vscode-livepreview/issues/262](https://github.com/microsoft/vscode-livepreview/issues/262)

## Summary

Current main still checks only the prospective HTTP port before assigning the following port to the WebSocket server. The WebSocket collision fallback creates a replacement server without restoring its listeners, leaving startup unresolved; this team-authored issue should remain open for a targeted fix.

## Change summary

Ensure the WebSocket listener does not claim an occupied port and that server startup recovers correctly from WebSocket port collisions.

## Best solution

Select an available HTTP/WebSocket port pair in `src/server/serverGrouping.ts`, or make `WSServer` retry through a shared server-construction path that attaches all required listeners on every attempt. Add an integration test that occupies the initial WebSocket port and verifies `openServer()` resolves with a reachable listener on another port.
