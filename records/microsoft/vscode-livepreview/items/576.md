# Issue #576 — Support for SPA

[https://github.com/microsoft/vscode-livepreview/issues/576](https://github.com/microsoft/vscode-livepreview/issues/576)

## Summary

Keep open: the reporter accepted the maintainer's narrower proposal for a configurable fallback file, and current main still returns its generated error page for missing paths. No verified open canonical owns this request; the Backlog milestone and maintainer-proposed change also rule out a scope-based decline.

## Change summary

Allow a configured HTML fallback file to be served for nonexistent URL paths so simple SPAs can use non-hash routes.

## Best solution

Evaluate the configurable missing-path fallback proposed in the discussion within src/server/httpServer.ts and the content-loading/settings surfaces, rather than promising full application-server support. Preserve existing behavior when unconfigured and have a maintainer review the serving-boundary implications before implementation.

- **Missing behavior on current main:** In src/server/httpServer.ts, _serveStream calls writePageNotFound() and returns when PathUtil.FileExistsStat(absoluteReadPath) reports a missing path. writePageNotFound() sends status 404 using ContentLoader.createPageDoesNotExist(), which generates a fixed error page in src/server/serverUtils/contentLoader.ts. The index.html behavior applies to existing directories, not arbitrary SPA routes.
