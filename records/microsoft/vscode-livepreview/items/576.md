# Issue #576 — Support for SPA

[https://github.com/microsoft/vscode-livepreview/issues/576](https://github.com/microsoft/vscode-livepreview/issues/576)

## Summary

A real product gap remains: current `main` returns Live Preview's generated 404 page for unknown routes and provides no configurable fallback document. The maintainer and reporter agreed that serving a configured HTML file for missing paths would satisfy the request, and the Backlog milestone permits this accepted feature request to remain open.

## Change summary

Add a configurable fallback HTML document for unresolved URLs so client-side SPA routes can load the application entry point.

## Best solution

Add a resource-scoped setting such as the proposed `livePreview.fileNotFoundFilepath`, validate that it resolves to a file within the server root, and have `src/server/httpServer.ts` serve that document when a requested path does not exist. Preserve the normal 404 response when the setting is absent or invalid, and cover both behaviors in `src/test/suite/serverGrouping.test.ts`.

## Vision fit

- **Fit:** unclear
- **Reason:** A narrowly configured fallback document supports serving correctness for static projects, but SPA routing also approaches the application-server functionality that the README says is outside Live Preview's primary use case.
- **Evidence:** The durable themes include serving correctness, while the README says Live Preview is most useful for projects where a server is not already created and specifically points away from apps using frameworks such as React or Angular.
