## Change summary

Opening an embedded preview silently fails when remote port 3000 is occupied, while choosing a free configured port restores operation.

## Evidence

- **Concrete reproduction and workaround:** https://github.com/microsoft/vscode-livepreview/issues/815 identifies Live Preview 0.4.18 on Remote - SSH with Ubuntu 24.04, an occupied remote port 3000, the embedded-preview command, and recovery after setting livePreview.portNumber to 3900. These details suffice for a targeted retest without requesting the same information again.
- **Automatic fallback already intended:** package.nls.json describes livePreview.portNumber as an initial port that increments until a free port is found. ServerGrouping.openServer in src/server/serverGrouping.ts calls _findFreePort before starting HTTP and WebSocket servers; HttpServer._startHttpServer in src/server/httpServer.ts also increments the HTTP port on EADDRINUSE. This establishes intended recovery, not successful recovery in the reported environment.
- **Startup and diagnostics trace:** ServerGrouping.openServer awaits both server starts before calling _connected; pending-workspace cleanup occurs only after the awaits succeed. Unknown HTTP/WebSocket startup errors are sent to telemetry and console.log before rejecting without an error value. Connection.connected in src/connectionInfo/connection.ts subsequently resolves both forwarded URIs before firing onConnected. These are investigation points, not proof of which stage failed here.
