# Issue #815 — Silent failure when default port (3000) is already in use — no error notification or Output channel entry

[https://github.com/microsoft/vscode-livepreview/issues/815](https://github.com/microsoft/vscode-livepreview/issues/815)

## Summary

The reported workaround strongly implicates port-collision handling, but current source is explicitly intended to find the next free port and retry an EADDRINUSE bind. The silent failure therefore needs the extension-host error and details about adjacent ports before the failing path can be identified.

## Change summary

Starting an internal preview in a Remote - SSH session silently fails when the configured HTTP port is occupied instead of selecting another port or reporting the startup error.

## Best solution

Make server startup reliably settle on an available HTTP/WebSocket port pair in `src/server/serverGrouping.ts`, `src/server/httpServer.ts`, and `src/server/wsServer.ts`, and surface any terminal startup failure through a VS Code error notification or diagnostic channel. First establish whether the hang occurs in the free-port probe, the HTTP retry, the WebSocket startup, or remote URI resolution using the extension-host console and the occupancy of ports 3000–3002.

## Evidence

- **reported isolation:** The report provides concrete Remote - SSH steps on Live Preview 0.4.18 and says changing only `livePreview.portNumber` from occupied port 3000 to free port 3900 makes Show Preview work immediately.
- **intended collision behavior:** `package.nls.json` documents `livePreview.portNumber` as an initial port that is incremented until a free port is found; `src/server/serverGrouping.ts` calls `_findFreePort` before starting HTTP on the selected port and WebSocket on the following port.
- **startup paths need diagnosis:** `src/server/httpServer.ts` retries on EADDRINUSE by incrementing the HTTP port, while `src/server/wsServer.ts` constructs a replacement WebSocket server after EADDRINUSE without attaching the original replacement's listening/error handlers. The supplied case does not establish which branch is reached or whether ports 3001 or 3002 are also occupied.
- **no verified canonical:** The nearest open report, https://github.com/microsoft/vscode-livepreview/issues/561, concerns an internal preview that fails even though the server logs that it successfully started on port 3000; it does not own this report's port-collision startup failure.
