# Issue #750 — Live preview cannot open pages if the containing folder has a "#" in the name

[https://github.com/microsoft/vscode-livepreview/issues/750](https://github.com/microsoft/vscode-livepreview/issues/750)

## Summary

Current `main` leaves `#` unescaped when constructing preview paths, causing browsers to interpret part of a file or folder name as a URL fragment. The directly linked open fixing PR requires this issue to remain open until that implementation is reviewed and merged.

## Change summary

Correctly encode `#` characters in preview URLs so files and folders containing them can be served and opened.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/857, which replaces segment-level `encodeURI`/`decodeURI` usage in `src/utils/pathUtil.ts` and adds focused regression coverage for leading and embedded `#` characters. Keep the issue open until the PR is merged and verified.

## Evidence

- **source-confirmed defect:** `PathUtil.EscapePathParts` in `src/utils/pathUtil.ts` applies `encodeURI` separately to each path segment. `encodeURI` intentionally preserves `#`, so a generated preview URL such as `my#folder/index.html` is interpreted by the browser as a path followed by a fragment rather than as the requested filesystem path.
- **affected URL construction:** `src/infoManagers/endpointManager.ts` uses `PathUtil.EscapePathParts` while constructing served endpoints, and `src/editorPreview/pageHistoryTracker.ts` uses it for preview navigation addresses, directly exposing the incorrect encoding to preview URLs.
- **open fixing PR:** https://github.com/microsoft/vscode-livepreview/pull/857 is open, references and closes this issue, changes path-segment encoding to `encodeURIComponent`/`decodeURIComponent`, and adds regression tests in `src/test/suite/pathUtil.test.ts` for folder names with embedded and leading `#` characters.
- **distinct related issue:** https://github.com/microsoft/vscode-livepreview/issues/855 concerns Windows backslash normalization and duplicated directory-index path segments, not the URL-fragment handling defect reported here, so it is not a canonical duplicate.
