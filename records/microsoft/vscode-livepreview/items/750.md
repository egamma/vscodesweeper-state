# Issue #750 — Live preview cannot open pages if the containing folder has a "#" in the name

[https://github.com/microsoft/vscode-livepreview/issues/750](https://github.com/microsoft/vscode-livepreview/issues/750)

## Summary

Current source confirms that Live Preview leaves `#` unescaped in URL path segments, causing browsers to interpret the remainder as a fragment rather than send it to the server. Keep the issue open because the directly linked fix PR is still open.

## Change summary

Encode `#` characters in preview URLs so files and containing folders with hashes in their names can be served correctly.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/857, which changes segment encoding in `src/utils/pathUtil.ts` and adds regression coverage for hashes in the middle and at the beginning of folder names. Close the issue only after that implementation merges.

## Evidence

- **source-confirmed defect:** `PathUtil.EscapePathParts` in `src/utils/pathUtil.ts` applies `encodeURI` separately to each path segment. `encodeURI` deliberately does not encode `#`, so generated preview paths containing it are interpreted as URLs with fragments; callers include endpoint construction in `src/infoManagers/endpointManager.ts` and bundled-preview navigation in `src/editorPreview/pageHistoryTracker.ts`.
- **open fixing PR:** https://github.com/microsoft/vscode-livepreview/pull/857 is open, references this issue with `Fixes #750`, changes `encodeURI`/`decodeURI` to `encodeURIComponent`/`decodeURIComponent`, and adds regression tests for `my#folder/index.html` and `#folder/index.html`.
- **canonical search:** The open keyword search found this issue itself but no broader open canonical for hash characters. https://github.com/microsoft/vscode-livepreview/issues/855 concerns encoded Windows backslashes and duplicated directory segments, a distinct path-normalization mechanism.
