# Issue #148 — Feature request: Add option to provide a wrapper html page (with additional css or js files included)

[https://github.com/microsoft/vscode-livepreview/issues/148](https://github.com/microsoft/vscode-livepreview/issues/148)

## Summary

This remains a valid, unscheduled feature request: Live Preview can serve a hand-written wrapper as a workaround, but it has no setting, command, or templating mechanism that automatically inserts the currently previewed snippet into that wrapper. No related item was provided that owns the remaining work, and the Backlog milestone does not justify closure.

## Change summary

Allow a workspace setting or per-snippet directive to select an HTML wrapper that injects the snippet at a placeholder while loading the wrapper's CSS and JavaScript.

## Best solution

Keep the request open for a maintainer product decision, then implement an explicit preview-template mechanism in the server/content-loading path with clear placeholder, path-resolution, script-injection, reload, and error semantics. The design should preserve normal file serving and treat wrapper paths as workspace-root-constrained input rather than requiring users to maintain a wrapper script with a hard-coded snippet path.
