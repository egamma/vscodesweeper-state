# Issue #539 — Embedded vs Internal Preview documentation inconsistency

[https://github.com/microsoft/vscode-livepreview/issues/539](https://github.com/microsoft/vscode-livepreview/issues/539)

## Summary

The terminology inconsistency remains on current main: the command says “Internal Browser,” while the README and configuration use “Embedded Preview,” and newer settings additionally distinguish VS Code's Integrated Browser from the bundled browser. This team-authored polish item still represents distinct documentation work and should remain open.

## Change summary

Standardize the user-facing terminology for embedded, internal, integrated, and external preview modes across commands, settings, and documentation.

## Best solution

Define a consistent vocabulary that separates preview location (“Embedded Preview”) from renderer (“VS Code Integrated Browser” or “bundled Live Preview browser”), then update the command title, README, and setting descriptions together. Keep https://github.com/microsoft/vscode-livepreview/issues/537 linked as related capability documentation rather than treating it as the owner of this terminology cleanup.

- **Evidence:** The vision identifies beginners as a primary audience and “Where the preview opens” as a durable theme, including embedded versus external and Integrated Browser versus bundled webview distinctions.
