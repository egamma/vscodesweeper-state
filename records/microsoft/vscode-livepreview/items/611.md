# Issue #611 — Live Preview does not resolve file when html extension is not provided.

[https://github.com/microsoft/vscode-livepreview/issues/611](https://github.com/microsoft/vscode-livepreview/issues/611)

## Summary

Current main still requires an exact file path or a directory containing index.html; it does not try an .html extension when an extensionless path is missing. The issue must remain open because PR https://github.com/microsoft/vscode-livepreview/pull/671 is an open implementation candidate that explicitly references it.

## Change summary

Add configurable extensionless URL resolution so a request such as /page can serve page.html.

## Best solution

Review and complete https://github.com/microsoft/vscode-livepreview/pull/671, including tests covering extensionless paths, trailing-slash behavior, query strings, and precedence when both a directory and an HTML file could match. The setting proposed by the PR should also be contributed through package.json so users can configure or disable the fallback.

## Vision fit

- **Fit:** aligned
- **Reason:** Extensionless HTML resolution improves the local server's serving correctness without expanding the bundled browser or turning Live Preview into an application server.
- **Evidence:** The durable serving-correctness theme explicitly covers what URL a file receives, relative-link behavior, directory indexes, and path handling; the README positions Live Preview as a local server for plain web projects.
