# Issue #711 — Live preview script injected into comment

[https://github.com/microsoft/vscode-livepreview/issues/711](https://github.com/microsoft/vscode-livepreview/issues/711)

## Summary

Current main still searches the entire document with a permissive tag regular expression, so a head-like string inside an earlier comment captures the injection. Keep the issue open because https://github.com/microsoft/vscode-livepreview/pull/746 is an open implementation candidate addressing this exact defect.

## Change summary

Ensure the live-reload script is injected into the document structure rather than into comments or similarly misleading text.

## Best solution

Review and complete https://github.com/microsoft/vscode-livepreview/pull/746, adding focused coverage for head-like text in comments and for `<header>` when `<head>` is omitted. The injection logic belongs in `src/server/serverUtils/contentLoader.ts`, with regression coverage in the server test suite.

## Evidence

- **current source reproduces defect:** `src/server/serverUtils/contentLoader.ts` implements `_injectIntoFile` by searching the entire contents with `<${tag}[^>]*>` for `head`, `body`, `html`, and `!DOCTYPE`; it therefore accepts the first `<head>` substring even when that substring is inside an HTML comment.
- **additional false match:** The same expression does not require whitespace or `>` after the tag name, so `<header>` also matches the `head` search when no earlier real `<head>` exists, as documented in https://github.com/microsoft/vscode-livepreview/issues/711#issuecomment-2807935577.
- **open implementation PR:** https://github.com/microsoft/vscode-livepreview/pull/746 is open and explicitly references issue 711. Its patch replaces the whole-document insertion-tag search with an anchored scan that consumes leading whitespace, comments, DOCTYPE, html, and head/body tags.
- **test gap:** The open PR modifies only `src/server/serverUtils/contentLoader.ts`; its author reports being unable to run or add tests, so regression cases for comments and `<header>` remain necessary before landing.
