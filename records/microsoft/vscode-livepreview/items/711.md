## Evidence

- **Exact failing source path:** In src/server/serverUtils/contentLoader.ts:359-386, ContentLoader._injectIntoFile searches the entire document with new RegExp(`<${tag}[^>]*>`, 'g'), trying 'head' first. For the reporter's <!-- <head></head> --> preamble, the first match ends inside the comment and the subsequent concatenation inserts the script there. The same expression also accepts <header> as a head match.
- **Server-owned behavior:** ContentLoader.getFileStream in src/server/serverUtils/contentLoader.ts:298-338 invokes _injectIntoFile for both open HTML documents and injectable files read from disk. The incorrect placement occurs before browser rendering, so switching to VS Code's Integrated Browser does not repair this code path.
- **Open implementation candidate:** https://github.com/microsoft/vscode-livepreview/pull/746 is verified OPEN with mergedAt null and explicitly references https://github.com/microsoft/vscode-livepreview/issues/711. Its diff replaces the whole-document tag search with a sequential preamble scan. The PR describes missing tests and a limitation involving > inside quoted attributes; it is a candidate, not a landed fix.
