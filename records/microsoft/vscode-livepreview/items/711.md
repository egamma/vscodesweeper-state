# Issue #711 — Live preview script injected into comment

[https://github.com/microsoft/vscode-livepreview/issues/711](https://github.com/microsoft/vscode-livepreview/issues/711)

## Summary

The defect is directly reproducible from the current injection logic: it searches the entire document with a permissive `<head[^>]*>` expression, so a head-like tag inside a comment is selected. Keep the issue open because the referenced fix PR is still open and needs review and tests.

## Change summary

Place the live-reload script at the actual document head rather than inside comments or after similarly named elements such as `<header>`.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/746 after adding focused coverage for comments containing `<head>`, omitted head elements followed by `<header>`, and ordinary doctype/html/head structures. The fix belongs in `src/server/serverUtils/contentLoader.ts`, where injection placement is currently determined.

## Evidence

- **current source confirms defect:** `src/server/serverUtils/contentLoader.ts` defines insertion tags in preference order and `_injectIntoFile` searches the complete contents using `new RegExp(`<${tag}[^>]*>`, 'g')`; the first `<head>` text inside `<!-- <head></head> -->` therefore supplies `lastIndex`, causing the script to be inserted inside the comment.
- **related malformed match:** The same expression accepts `<header>` because it does not require whitespace or `>` immediately after the tag name, corroborating the additional concrete case in https://github.com/microsoft/vscode-livepreview/issues/711#issuecomment-2807935577.
- **open implementation candidate:** https://github.com/microsoft/vscode-livepreview/pull/746 is open and changes `ContentLoader._injectIntoFile` to consume only valid document-preamble constructs from the beginning, explicitly addressing issue 711 and the comment/header false matches.
- **no canonical duplicate:** The other open injection issues found, https://github.com/microsoft/vscode-livepreview/issues/204 and https://github.com/microsoft/vscode-livepreview/issues/457, concern excluding files from injection and changing injected-script behavior respectively; neither owns this injection-placement defect.
