# Issue #789 — Support vscode files.associations setting

[https://github.com/microsoft/vscode-livepreview/issues/789](https://github.com/microsoft/vscode-livepreview/issues/789)

## Summary

This is a valid, still-unimplemented request to honor VS Code's effective HTML language association consistently. Current main recognizes associated HTML files in editor and context-menu enablement, but several live-reload paths still classify files solely by their physical extension.

## Change summary

Allow files mapped to the HTML language through `files.associations`, such as `*.phtml`, to receive the same preview and live-reload behavior as `.html` files.

## Best solution

Keep the request open as a feature request and make HTML/injection eligibility use VS Code's resolved language ID where available, with a consistent strategy for files requested before they are open. The command enablement, response MIME type, script injection, WebSocket refresh classification, and bundled-preview title handling should agree.
