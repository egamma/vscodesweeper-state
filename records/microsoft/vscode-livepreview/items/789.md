# Issue #789 — Support vscode files.associations setting

[https://github.com/microsoft/vscode-livepreview/issues/789](https://github.com/microsoft/vscode-livepreview/issues/789)

## Summary

The requested editor workflow is already supported: preview actions depend on the HTML language identifier, not the filename extension, and open HTML documents receive HTML serving and live-reload injection. The supplied files.associations mapping therefore covers the central ask without a new setting.

## Change summary

Enable Live Preview for nonstandard filename extensions associated with the HTML language through files.associations.

## Best solution

Keep the existing language-based preview enablement and explain how to use files.associations with the Show Preview command. Distinguish this supported open-editor workflow from serving associated files that are not open in the editor, where the server still uses filename-based detection.

- **Proposed comment:**

  > Thanks for the suggestion. Live Preview already enables its preview actions by the file's VS Code language mode rather than its extension. With `"files.associations": { "*.phtml": "html" }`, open the `.phtml` file and confirm the language mode in the status bar is HTML, then use the preview icon or `Live Preview: Show Preview (Internal Browser)` (`livePreview.start.internalPreview.atFile`). The server also treats that open HTML document as HTML and adds live refresh. This covers enabling preview for the associated file; files served without being open in the editor still use filename-based detection.

## Evidence

- **Existing language-based enablement:** package.json contributes.menus enables the editor-title preview action with editorLangId == html and the editor/explorer context actions with resourceLangId == html. The internal and external preview commands likewise use editorLangId == html, so they are not restricted to .html or .htm filenames.
- **Associated open documents are served as HTML:** src/server/serverUtils/contentLoader.ts, ContentLoader.getFileStream, matches requested paths against vscode.workspace.textDocuments. For a matching document whose languageId is html, it injects the reload script and sets ContentType to text/html regardless of the filename extension.
- **Command path has no extension gate:** src/extension.ts registers livePreview.start.preview.atFile and livePreview.start.internalPreview.atFile through Manager.openPreviewAtFileUri. In src/manager.ts, openPreviewAtFileUri and _handleOpenFile resolve the selected file and server without imposing an HTML filename-extension restriction.
- **Coverage boundary:** For files not present in vscode.workspace.textDocuments, ContentLoader.getFileStream instead uses mime.getType(readPath) and isFileInjectable. src/utils/utils.ts recognizes .html, .htm, .xhtml and extensionless paths for injection, not arbitrary files.associations mappings. This limitation does not prevent enabling preview for the associated file opened in the editor, which is the reported request.
- **Canonical search:** Repository issue searches for associations, phtml, file types, language, and custom extensions found no verified older open issue owning this request. https://github.com/microsoft/vscode-livepreview/issues/688 concerns XHTML Content-Type handling, not the same preview-enablement symptom.
