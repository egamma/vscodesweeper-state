# Issue #506 — Create a launch.json configuration for live preview

[https://github.com/microsoft/vscode-livepreview/issues/506](https://github.com/microsoft/vscode-livepreview/issues/506)

## Summary

Keep open: Live Preview supports command-driven external debugging, but does not contribute a launch configuration for the requested F5 workflow. Existing settings and server tasks provide pieces of the workflow, not the requested project-level debugging integration.

## Change summary

Support a Live Preview launch.json workflow that starts the server and external JavaScript debugging with F5, including an optional build task and a configured HTML output file.

## Best solution

Define a project-level debugging workflow that coordinates Live Preview server startup, the actual served URL, and the existing JavaScript debugger, while allowing a preLaunchTask and an explicit HTML target. Keep existing command-driven previews and live-refresh behavior intact; this is extension-side integration work, not an Integrated Browser rendering request.

## Plan brief

- **Likely files:** `package.json`, `package.nls.json`, `src/extension.ts`, `src/manager.ts`, `src/editorPreview/previewManager.ts`, `src/task/serverTaskProvider.ts`, `README.md`
- **Validation:** In a minimal HTML/JavaScript workspace, invoke the proposed F5 workflow without manually starting the server or assigning a custom keybinding; verify the external debugger attaches, console.log appears in Debug Console, and a breakpoint binds. Repeat with a preLaunchTask that generates a configured HTML output file, and with port 3000 occupied to confirm the browser uses the actual server URL. Verify existing command-driven debugging and configured auto-refresh still work.
- **Behavior:**

  > Users should be able to start a Live Preview external debugging session through VS Code's normal F5 workflow rather than repeatedly invoking the command palette or installing a custom keybinding. A project configuration should support running a build task before opening a selected HTML output file. The resulting browser must use the running server's actual address, attach the JavaScript debugger, and expose console output and breakpoints. Existing preview commands and automatic refresh must retain their behavior.
- **Trace:**

  > package.json currently contributes preview commands, settings, and a Live Preview task, but no debugger contribution. src/extension.ts routes livePreview.start.externalDebugPreview.atFile through Manager.openPreviewAtFileUri; src/editorPreview/previewManager.ts:launchFileInExternalBrowser builds the URL and delegates debugging to extension.js-debug.debugLink. src/task/serverTaskProvider.ts provides server-logging tasks rather than a Live Preview launch-configuration contract. Existing livePreview.debugOnExternalPreview and defaultPreviewPath settings do not connect F5 to server startup. The design must establish the supported launch entry point and target-selection contract while preserving current commands, server address resolution, and refresh semantics; it must not reimplement the JavaScript debugger or change the served-file boundary. The related https://github.com/microsoft/vscode-livepreview/issues/258 is closed and only documents the command-based workaround.
- **Open decisions:**
  - Should the supported F5 experience include automatic debugging of the active HTML file without launch.json, or require a generated or checked-in project launch configuration?
  - For a launch configuration without an explicit HTML target, should the preview follow the active editor or livePreview.defaultPreviewPath?
