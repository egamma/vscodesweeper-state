# Issue #893 — livePreview.serverRoot pointing at an existing subfolder leaves the server with no root (404 "No Server Root", paths resolved against the drive root)

[https://github.com/microsoft/vscode-livepreview/issues/893](https://github.com/microsoft/vscode-livepreview/issues/893)

## Summary

The current startup path can discard the workspace when an existing serverRoot subfolder is configured, producing the reported rootless server. Keep this open: the failure is in the extension's startup and workspace selection, not the embedded browser.

## Change summary

Starting Live Preview with an existing serverRoot subfolder should serve that folder rather than create a rootless server.

## Best solution

Correct the startup target and workspace selection in src/manager.ts while preserving intentional loose-file handling and server-root containment. A blank defaultPreviewPath should open the configured server root; with index.html present, GET / should serve that file, and /sub/page2.html should return 200.

## Evidence

- **Concrete server-side reproduction:** https://github.com/microsoft/vscode-livepreview/issues/893 provides Windows and extension versions, an existing-folder layout, startup steps, curl responses, and an unset-setting control. The HTTP failure occurs independently of either embedded browser.
- **Startup loses the workspace:** package.json maps Start Server to livePreview.start; src/extension.ts invokes Manager.openPreview(). In src/manager.ts:302-335, a blank defaultPreviewPath is joined to the workspace with ignoreFileRoot=true, producing the workspace directory rather than the configured subfolder. _handleOpenFile at lines 516-522 calls _shouldUseWorkspaceForFile; lines 552-577 reject that directory because it is outside the configured subfolder and select the undefined-workspace grouping.
- **Reported responses follow from the rootless connection:** src/connectionInfo/connection.ts returns undefined rootURI/rootPath for an undefined workspace. src/server/httpServer.ts:59-60 converts that to an empty basePath; lines 205-207 return No Server Root for GET /, and subsequent requests join their pathname to the empty basePath before the loose-file lookup fails. This explains the missing workspace prefix without assuming that retaining serverRoot verbatim itself causes the failure.
- **Documented intended behavior:** package.nls.json settings.serverRoot explicitly supports an existing workspace-relative subfolder. Returning an empty prefix for a nonexistent folder in src/utils/pathUtil.ts:208-211 does not remove the workspace from a Connection. Separately, src/server/httpServer.ts serves index.html when present, so successful GET / need not produce the directory listing requested in the report.
