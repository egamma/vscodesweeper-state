# Issue #213 — Project breaks on unplanned "update-path" messages

[https://github.com/microsoft/vscode-livepreview/issues/213](https://github.com/microsoft/vscode-livepreview/issues/213)

## Summary

The requested escape hatch remains unimplemented: current main still injects `update-path` messages for embedded-preview navigation, while the existing reload controls do not suppress those messages. A maintainer explicitly accepted this as a feature request in the Backlog, and no open canonical issue owns the work.

## Change summary

Provide a way to prevent Live Preview's injected `update-path` messaging, potentially together with finer-grained exclusions for automatic reloads, when those messages conflict with the hosted application.

## Best solution

Preserve the navigation and history protocol needed by the embedded preview while preventing it from colliding with application message handlers, preferably through a narrowly scoped opt-out or a protocol isolation mechanism in `media/injectScript.js` and the bundled preview. The team should first decide whether to support this compatibility option for the legacy bundled browser now that the Integrated Browser is the default.

## Vision fit

- **Fit:** rejected
- **Reason:** The request primarily expands compatibility controls for the bundled webview browser, while the current direction treats that browser as a fallback and moves embedded-preview behavior to VS Code's Integrated Browser.
- **Evidence:** The vision states that "the server is the product; the browser is increasingly VS Code's" and that requests to grow the bundled webview browser run against the current direction.
