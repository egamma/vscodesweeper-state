# Issue #213 — Project breaks on unplanned "update-path" messages

[https://github.com/microsoft/vscode-livepreview/issues/213](https://github.com/microsoft/vscode-livepreview/issues/213)

## Summary

The existing reload controls do not suppress the embedded preview's `update-path` messages, and a maintainer explicitly retained this as a feature request. The default Integrated Browser now avoids this iframe-specific path, but the bundled preview remains available, so the request is not implemented or obsolete.

## Change summary

Provide a way to prevent or constrain the bundled embedded preview's injected `update-path` messages when they interfere with the hosted application.

## Best solution

Decide whether the bundled preview remains supported for this scenario; if so, isolate or optionally disable its page-to-parent messaging in `media/injectScript.js` while preserving the navigation and history behavior handled by `media/main.js` and `src/editorPreview/browserPreview.ts`. The existing auto-refresh controls should remain separate because they do not govern this message bridge.

## Vision fit

- **Fit:** rejected
- **Reason:** The request changes the bundled webview browser integration, while the project's current direction makes VS Code's Integrated Browser the default and treats the bundled browser as a fallback.
- **Evidence:** The vision guardrail states that "The server is the product; the browser is increasingly VS Code's," and identifies the bundled webview browser as the fallback rather than the future.

## Evidence

- **maintainer decision:** A maintainer confirmed that `update-path` is required for embedded-preview links and history, that disabling auto-refresh does not stop it, and explicitly kept the issue open as a feature request: https://github.com/microsoft/vscode-livepreview/issues/213#issuecomment-1198694192
- **current message path:** `media/injectScript.js` posts `update-path` to `window.parent` on page load and in response to `setup-parent-listener`; `media/main.js` forwards it to the extension, and `src/editorPreview/browserPreview.ts` uses it to record the loaded page and title.
- **existing controls are partial:** `livePreview.autoRefreshPreview` supports `Never`, and `data-server-no-reload` prevents `reloadPage()` in `media/injectScript.js`, but neither condition gates `postParentMessage()` or the `update-path` messages.
- **no canonical found:** Open-issue searches for `update-path`, parent messaging, and disabling reload found only https://github.com/microsoft/vscode-livepreview/issues/213; https://github.com/microsoft/vscode-livepreview/issues/276 concerns reloads caused by adding a workspace root and does not own this message-suppression request.
- **default path changed but fallback remains:** `livePreview.useIntegratedBrowser` defaults to `true` in `package.json`, so current default previews do not use this bundled iframe bridge; setting it to `false` still selects the code path implicated by the request.
