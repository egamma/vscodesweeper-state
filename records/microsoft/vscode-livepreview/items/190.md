# Issue #190 — Make Live Preview work on the web

[https://github.com/microsoft/vscode-livepreview/issues/190](https://github.com/microsoft/vscode-livepreview/issues/190)

## Summary

Browser-only static-project preview remains unimplemented: the extension still requires Node.js and excludes virtual workspaces. Keep this team-authored, maintainer-backed request open; related reports do not own its full vscode.dev/github.dev scope.

## Change summary

Enable live preview of static HTML/CSS/JS projects in vscode.dev and github.dev without a local or remote Node.js extension host.

## Best solution

Validate a browser-compatible prototype that reads project resources through VS Code's virtual filesystem and supports relative assets and live refresh without an HTTP server process. This requires extension-side work beyond choosing the Integrated Browser; establish feasibility and the file-serving boundary before committing to a production architecture.

## Evidence

- **Current extension cannot run browser-only:** package.json declares only main: ./out/extension.js, has no browser entry point, and sets capabilities.virtualWorkspaces to false. webpack.config.js targets node. These remain concrete barriers to the requested vscode.dev/github.dev workflow.
- **Serving still depends on Node.js:** src/server/httpServer.ts imports Node http and fs, creates an http.Server in _createServer(), and listens on a host and port in _startHttpServer(). src/server/serverUtils/contentLoader.ts uses fs.createReadStream(), fs.statSync(), and fs.readdir() rather than a browser-compatible virtual-filesystem serving path.
- **Existing-capability check:** Read all contributed commands and configuration in package.json and their descriptions in package.nls.json. livePreview.useIntegratedBrowser changes the embedded preview surface, while livePreview.serverRoot and the start/preview commands configure or launch the existing server; none supplies browser-only execution or virtual-workspace support. SettingUtil.shouldUseIntegratedBrowser() in src/utils/settingsUtil.ts checks the setting and availability of a VS Code command, not a replacement serving backend.
- **Maintainer-backed protected request:** https://github.com/microsoft/vscode-livepreview/issues/190 is MEMBER-authored, labeled feature-request, and assigned Backlog. The supplied discussion records a maintainer deferring it for capacity and another supporting its educational use; four body upvotes provide additional demand. Age and the absence of subsequent implementation do not justify declining it.

It therefore fails both the scope test and the older-canonical requirement for this re-reviewed item.
