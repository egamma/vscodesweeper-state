# Issue #883 — Agents window with SSH workspace runs Live Preview locally on Windows and cannot find Linux files

[https://github.com/microsoft/vscode-livepreview/issues/883](https://github.com/microsoft/vscode-livepreview/issues/883)

## Summary

Thanks for the detailed investigation. The listener and process checks point to an Agents-window extension-host/filesystem mismatch, likely involving VS Code core rather than Integrated Browser rendering; the report already provides sufficient steps for a maintainer to investigate, and no verified canonical or fix supports closing it.

## Change summary

An SSH-backed Agents workspace starts Live Preview on Windows, where the server interprets a Linux resource path as a local Windows path and returns a 404.

## Best solution

Establish in microsoft/vscode whether Agents SSH sessions provide a remote extension host and what workspace/editor URI contract locally running extensions receive. Live Preview should serve the resource through a supported execution/filesystem arrangement, or clearly explain the unsupported combination before starting a misleading local preview; an extension-side diagnostic may be appropriate even if hosting support belongs to core.

## Evidence

- **Concrete hosting evidence:** https://github.com/microsoft/vscode-livepreview/issues/883 identifies the Windows listener as the Agents window's local extension-host process, reports no Linux listener or remote extension host in the Agents-only session, and contrasts this with successful remote activation and a Linux listener in a regular Remote SSH editor.
- **Current source explains the local-path failure:** src/connectionInfo/connection.ts exposes rootURI.fsPath as Connection.rootPath; src/editorPreview/previewManager.ts also reduces the selected file to file.fsPath. src/server/httpServer.ts joins the server root and request path using Node path.join and checks existence through PathUtil.FileExistsStat, which uses fs.promises.stat in src/utils/pathUtil.ts. These operations target the executing extension host's filesystem, not a remote URI provider.
- **Serving versus rendering boundary:** src/server/serverUtils/contentLoader.ts reads workspace content through PathUtil.FileRead and fs.createReadStream. The reported server-generated File not found page, together with successful access through a standalone Linux server and SSH forwarding, points to resource access/hosting rather than a page-rendering defect in the Integrated Browser. The actual Agents workspace URI scheme and authority remain unverified.
- **Related issue is not a verified duplicate:** https://github.com/microsoft/vscode-livepreview/issues/489 is open and requests Remote Repositories support. A maintainer confirms native Node filesystem use at https://github.com/microsoft/vscode-livepreview/issues/489#issuecomment-1491141753. That provides relevant filesystem background, but does not establish ownership of Agents SSH extension hosting or the requested unsupported-scenario diagnostic.
- **Capability and canonical checks:** package.json declares virtualWorkspaces: false and contains no explicit extensionKind or Agents-specific support declaration. Searches for Agents reports in microsoft/vscode-livepreview and Agents SSH/extension-host reports in microsoft/vscode did not establish an open canonical owning this exact remaining work; the hosting limitation cannot be verified from this extension checkout alone.
