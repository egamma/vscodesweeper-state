# Issue #716 — Not running in Virtual Workspace?

[https://github.com/microsoft/vscode-livepreview/issues/716](https://github.com/microsoft/vscode-livepreview/issues/716)

## Summary

This is a support question about the extension's declared workspace limitations and debugging command, both of which have clear answers in the manifest and README. A normal folder opened from the Mac filesystem is not a virtual workspace and supports Live Preview.

## Change summary

Explain what the virtual-workspace warning means and how to debug a locally stored web project with Live Preview.

## Best solution

Keep virtual workspaces unsupported because Live Preview requires filesystem paths and runs a server for the workspace files. Users should open a locally stored project folder and run `Live Preview: Show Debug Preview` for external-browser JavaScript debugging.

- **Proposed comment:**

  > Thanks for asking. A virtual workspace is one whose files are provided through a virtual filesystem rather than as ordinary files available to the VS Code extension host. Live Preview cannot run there because it needs filesystem access to host the project through its server. This does not mean macOS is unsupported: if your project is saved locally, open its folder in the desktop version of VS Code. To debug its browser-side JavaScript, open the Command Palette and run `Live Preview: Show Debug Preview`; this launches the external-browser preview with the built-in JavaScript debugger attached.
