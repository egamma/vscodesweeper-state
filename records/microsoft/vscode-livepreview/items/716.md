# Issue #716 — Not running in Virtual Workspace?

[https://github.com/microsoft/vscode-livepreview/issues/716](https://github.com/microsoft/vscode-livepreview/issues/716)

## Summary

This is a support question about the documented Virtual Workspace limitation rather than a defect. Live Preview requires a filesystem-backed workspace so it can host the files through its local server; opening the project as a normal local folder enables the preview and debugging commands.

## Change summary

Clarify what the Virtual Workspace warning means and how to use Live Preview's debugging support on macOS.

## Best solution

Keep the filesystem-backed workspace requirement and explain that the project must be cloned or downloaded and opened as a local folder. JavaScript debugging can then be started with the `Live Preview: Show Debug Preview` command.

  > Thanks for asking. A Virtual Workspace is a workspace provided through a virtual filesystem rather than a normal folder available to VS Code's filesystem. Live Preview cannot run there because it needs to start a local server and host the workspace files.
  > 
  > On your Mac, download or clone the project to your computer and open its folder with **File > Open Folder**. You can then preview it normally, or run **Live Preview: Show Debug Preview** from the Command Palette to open an external preview with JavaScript debugging attached.
