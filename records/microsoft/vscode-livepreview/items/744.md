# Issue #744 — Live Preview omits initial slash of URL pathname if `livePreview.openPreviewTarget` is "External Browser" and `livePreview.serverRoot` ends with a slash.

[https://github.com/microsoft/vscode-livepreview/issues/744](https://github.com/microsoft/vscode-livepreview/issues/744)

## Summary

The trailing-slash case remains in the current URL-construction path: the workspace-relative filename loses its leading separator and is concatenated directly after the port. Keep this report open; the related malformed-URL report is newer and cannot replace it under the re-review rules.

## Change summary

Opening an external preview with livePreview.serverRoot set to /public/ produces a malformed URL instead of http://127.0.0.1:3000/index.html.

## Best solution

Make external preview URLs independent of whether the configured server root ends with a separator, preserving the existing server-root containment rules. Address the connection-to-preview path contract in src/connectionInfo/connection.ts and src/editorPreview/previewManager.ts, coordinating the overlapping trailing-separator case with https://github.com/microsoft/vscode-livepreview/issues/840 without absorbing that issue's distinct absolute-URL behavior.
