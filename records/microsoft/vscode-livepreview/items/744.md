# Issue #744 — Live Preview omits initial slash of URL pathname if `livePreview.openPreviewTarget` is "External Browser" and `livePreview.serverRoot` ends with a slash.

[https://github.com/microsoft/vscode-livepreview/issues/744](https://github.com/microsoft/vscode-livepreview/issues/744)

## Summary

The malformed external-preview URL is reproducible from current source: a trailing slash in `livePreview.serverRoot` makes `relativePath()` return `index.html` without a leading slash, which is concatenated directly onto `http://127.0.0.1:3000`. The issue remains necessary because current `main` still contains this path and no canonical issue or linked fix is identified.

## Change summary

Ensure external-browser preview URLs retain the separator between the server authority and pathname when `livePreview.serverRoot` ends with `/`.

## Best solution

Normalize the preview-relative pathname in `src/utils/pathUtil.ts` so it always starts with exactly one `/`, regardless of whether `livePreview.serverRoot` has a trailing separator, while preserving existing workspace, loose-file, and encoded-path behavior. Add a regression case to `src/test/suite/pathUtil.test.ts` for `/public/` plus `/public/index.html` and verify the resulting external URL is `http://127.0.0.1:3000/index.html`.
