# Issue #817 — When used with DevContainers the Forwarded Address should be used

[https://github.com/microsoft/vscode-livepreview/issues/817](https://github.com/microsoft/vscode-livepreview/issues/817)

## Summary

The Integrated Browser launch path still passes the container's host and port directly instead of the forwarded address, so this is an extension-side URL-resolution defect. Keep the issue open while the explicitly linked implementation candidate is reviewed.

## Change summary

Open Dev Container previews at VS Code's forwarded address rather than assuming the container's loopback address and port are reachable from the host browser.

## Best solution

Review https://github.com/microsoft/vscode-livepreview/pull/861 against the Integrated Browser launch path in src/editorPreview/previewManager.ts, ensuring the resolved address preserves the requested page and browser-reuse behavior. Confirm automatic forwarding in a Dev Container with a different host-side port before considering the full request satisfied.

## Evidence

- **Current source bypasses the forwarded address:** In src/editorPreview/previewManager.ts, PreviewManager.launchFileInEmbeddedPreview constructs http://${connection.host}:${connection.httpPort}${path}?vscode-livepreview=true and passes it directly to INTEGRATED_BROWSER_COMMAND. When the container's port is forwarded to a different host-side port, this branch still opens the container-side port.
- **Forwarding resolution already exists elsewhere:** src/connectionInfo/connection.ts implements Connection.resolveExternalHTTPUri using vscode.env.asExternalUri, and Connection.connected resolves both HTTP and WebSocket addresses. The Integrated Browser launch branch does not consume that resolved HTTP address; the defect is in extension-side integration, not established as a core browser defect.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode-livepreview/pull/861 is OPEN and explicitly says 'Fixes #817'. It changes src/editorPreview/previewManager.ts and src/test/suite/preview.test.ts to use the forwarded address, including the concrete case of container port 3000 mapping to host port 3001. An open linked PR requires keeping this issue open.
- **Scope and canonical search:** The reporter's follow-up also asks whether forwarding happens automatically, so address selection alone should not be assumed to settle the entire request. A repository search for forwarded-address reports found no verified older canonical owning this same symptom; remote-tunnel 401 reports are not sufficient evidence of the same defect.
