# Issue #817 — When used with DevContainers the Forwarded Address should be used

[https://github.com/microsoft/vscode-livepreview/issues/817](https://github.com/microsoft/vscode-livepreview/issues/817)

## Summary

Current `main` bypasses VS Code's forwarded URI when opening the Integrated Browser, so a Dev Container port mapped to a different host address opens the wrong URL. The linked open PR directly addresses this defect, which requires keeping the issue open until that implementation is reviewed and merged.

## Change summary

Open Integrated Browser previews through the VS Code-resolved forwarded address instead of the container-local host and port.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/861, which changes `src/editorPreview/previewManager.ts` to resolve the HTTP endpoint through `Connection.resolveExternalHTTPUri()` while preserving the requested path, forwarded query parameters, and preview-reuse marker.

## Evidence

- **current source defect:** `src/editorPreview/previewManager.ts` constructs the Integrated Browser URL directly from `connection.host` and `connection.httpPort`, so it never uses the externally resolved address for this preview path.
- **forwarding support already available:** `src/connectionInfo/connection.ts` implements `Connection.resolveExternalHTTPUri()` using `vscode.env.asExternalUri`, but the Integrated Browser branch does not currently call it.
- **open fixing PR:** https://github.com/microsoft/vscode-livepreview/pull/861 is open, references this issue with `Fixes #817`, changes the Integrated Browser path to use `resolveExternalHTTPUri()`, and adds a regression test for a remote port forwarded to a different host address.
