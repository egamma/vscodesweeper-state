# Issue #146 — Changing the port breaks reloading

[https://github.com/microsoft/vscode-livepreview/issues/146](https://github.com/microsoft/vscode-livepreview/issues/146)

## Summary

The WebSocket intentionally uses the port after the HTTP port, so port 81 is expected when the configured preview port is 80. However, the maintainer-confirmed startup failure remains actionable: current source can leave WebSocket retry failures without a user-facing error and fail to finish server startup.

## Change summary

Changing to a custom HTTP port can leave live reload disconnected without clearly reporting that the adjacent WebSocket port failed to start.

## Best solution

Keep the separate HTTP and WebSocket ports, but make WebSocket port allocation and retry handling reliable in `src/server/wsServer.ts` and `src/server/serverGrouping.ts`, and surface an actionable error when no WebSocket endpoint can be opened. Coordinate this with the related port-collision work in https://github.com/microsoft/vscode-livepreview/issues/262 without treating that narrower collision report as proven to cover every possible failure here.

## Evidence

- **intended port relationship:** `src/connectionInfo/connectionManager.ts` initializes the WebSocket port as `portNumber + 1`, and `src/server/serverGrouping.ts` starts the HTTP server on the selected free port and the WebSocket server on `freePort + 1`; therefore an HTTP preview on port 80 intentionally connects its reload socket on port 81.
- **maintainer confirmation:** A maintainer confirmed that the adjacent WebSocket port is intentional but that the failed connection and silent server failure are still an issue: https://github.com/microsoft/vscode-livepreview/issues/146#issuecomment-1341790496.
- **current failure path:** In `src/server/wsServer.ts`, an unrecognized listen error is written only with `console.log` before rejecting, while the `EADDRINUSE` branch replaces the WebSocket server without attaching the connection, error, and listening handlers to the replacement. Consequently the startup promise can remain unresolved and `Connection.connected()` does not refresh the injected script with a successfully selected endpoint.
- **related but not verified duplicate:** Open issue https://github.com/microsoft/vscode-livepreview/issues/262 specifically tracks failure to check whether the WebSocket port is occupied. This report does not establish that occupation was its trigger and additionally records the silent-failure behavior, so the remaining-work test for a duplicate is not conclusively met.
