## Summary

Configurable cross-origin access needs a maintainer decision: existing custom response headers do not override the server's origin checks. Keep this open under the security-sensitive hard rule, with the earlier CORS scope decision available as precedent for human review.

## Change summary

Add CORS configuration allowing requests from all origins or selected domains.

## Best solution

Have a maintainer assess the requested cross-origin access policy against the earlier decision in https://github.com/microsoft/vscode-livepreview/issues/332#issuecomment-1245806606. Any supported policy must account for both response headers and origin authorization in src/server/httpServer.ts; adding headers alone does not deliver the requested capability.

HttpServer._serveStream in src/server/httpServer.ts merges these into writeHead, but independently returns 401 when a supplied Origin differs from the resolved server origin. Custom Access-Control-Allow-Origin headers therefore do not provide the requested cross-origin access policy.
- **Earlier maintainer scope decision:** https://github.com/microsoft/vscode-livepreview/issues/332 is closed and requested a CORS toggle for accessing locally served resources from another origin. At https://github.com/microsoft/vscode-livepreview/issues/332#issuecomment-1245806606, a maintainer declined external-client access on scope and safety grounds. This is relevant precedent, not an open duplicate canonical.
