# Issue #766 — Add CORS setting

[https://github.com/microsoft/vscode-livepreview/issues/766](https://github.com/microsoft/vscode-livepreview/issues/766)

## Summary

Live Preview already supports wildcard or specific-origin CORS response headers through `livePreview.httpHeaders`, which the server applies to every response. Because a dedicated CORS control could widen access to locally served files and is security-sensitive header handling, this should remain open for a maintainer to decide whether safer dedicated behavior or documentation is still needed.

## Change summary

Add a dedicated setting for allowing cross-origin access from all origins or selected domains.

## Best solution

Confirm whether `livePreview.httpHeaders` fully covers the intended use case; if it does, document an `Access-Control-Allow-Origin` example rather than adding a redundant setting. If the request includes origin allowlists, dynamic origin reflection, or preflight handling beyond static headers, define that behavior and its security boundary before changing `src/server/httpServer.ts`.

  > Thanks for the request. Live Preview can already add CORS response headers through `livePreview.httpHeaders`; for example, `"livePreview.httpHeaders": { "Access-Control-Allow-Origin": "*" }`, or replace `*` with a specific origin such as `https://example.com`. Those would need a more specific design because allowing broader access can expose files served from the workspace.

## Evidence

- **existing capability:** `package.json` contributes `livePreview.httpHeaders` as an object setting for extra HTTP response headers, so users can configure `Access-Control-Allow-Origin` as `*` or as a specific origin.
- **server implementation:** `src/utils/settingsUtil.ts` loads `livePreview.httpHeaders`, and `src/server/httpServer.ts` spreads those values into every `res.writeHead(...)` call, including error and content responses.
- **implementation precedent:** The completed header-configurability work in https://github.com/microsoft/vscode-livepreview/issues/375 documents the existing settings form; a maintainer later also pointed to `livePreview.httpHeaders` as the potential CORS mechanism in https://github.com/microsoft/vscode-livepreview/issues/631#issuecomment-2070350732.
- **security boundary:** Allowing arbitrary origins can expose files served from the workspace to external web content; the earlier dedicated CORS request records that concern at https://github.com/microsoft/vscode-livepreview/issues/332#issuecomment-1245806606.
