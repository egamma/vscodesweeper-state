# Issue #766 — Add CORS setting

[https://github.com/microsoft/vscode-livepreview/issues/766](https://github.com/microsoft/vscode-livepreview/issues/766)

## Summary

Live Preview already supports static CORS response headers through `livePreview.httpHeaders`, but the report may be requesting higher-level behavior such as origin allowlists or preflight handling. Because CORS changes affect the security boundary of the local file server, a maintainer should confirm the intended remaining scope rather than closing this automatically.

## Change summary

Add dedicated CORS configuration supporting unrestricted or origin-specific cross-origin access to files served by Live Preview.

## Best solution

Document `livePreview.httpHeaders` as the existing solution for simple static CORS headers, then determine whether a dedicated setting should validate origins and handle CORS preflight requests in `src/server/httpServer.ts`. Any broader implementation should preserve the secure default of not permitting cross-origin access.

## Evidence

- **existing static-header capability:** `package.json` contributes the object-valued `livePreview.httpHeaders` setting, while `src/utils/settingsUtil.ts` loads it and `src/server/httpServer.ts` spreads those values into every response. Users can therefore set `Access-Control-Allow-Origin` to `*` or a specific origin today.
- **possible remaining behavior:** `src/server/httpServer.ts` applies configured headers generically but contains no dedicated CORS policy, origin allowlist validation, or explicit OPTIONS preflight handling, so the broad request may not be fully covered by the existing setting.
- **feature provenance:** `CHANGELOG.md` records `livePreview.httpHeaders` in stable release 0.4.8 as part of https://github.com/microsoft/vscode-livepreview/issues/375, where the maintainer accepted customizable HTTP headers.
- **security-sensitive precedent:** The earlier CORS request https://github.com/microsoft/vscode-livepreview/issues/332 documents the concern that cross-origin access can expose files served from the workspace; that decision predates the generic header setting but remains relevant to a dedicated CORS policy.
