# Issue #530 — [Feature request] Auto preview active opened file

[https://github.com/microsoft/vscode-livepreview/issues/530](https://github.com/microsoft/vscode-livepreview/issues/530)

## Summary

Following the active HTML editor remains an unimplemented, maintainer-accepted feature request. Existing settings do not provide it, and the matching open request found is newer, so it cannot replace this re-reviewed issue.

## Change summary

Automatically navigate the preview when the active HTML file changes, with an additional requested action to open the previewed page in the editor.

## Best solution

Plan editor-to-preview following through the extension's command and preview-management layers, including the Integrated Browser path without stealing editor focus. Decide separately whether preview-to-editor navigation is included; retain the maintainer's exclusion of configurable non-HTML preview support.

- **Behavior:**

  > While following is enabled, switching from editing A.html to B.html should update the preview to B.html without another Show Preview command or loss of editor focus. Acceptance checks should distinguish switching documents from refreshing the current document and preserve normal manual navigation when following is disabled. The reporter also requests an explicit action to open the currently previewed local HTML page in the editor; whether that ships with following remains undecided. Configurable support for non-HTML preview buttons is excluded by the maintainer's response.
- **Trace:**

  > src/extension.ts registers explicit preview commands that call Manager.openPreviewAtFileUri in src/manager.ts; that method samples the active editor when invoked, rather than subscribing to editor changes. The current Integrated Browser call reuses matching preview URLs, but its behavior under automatic navigation, including focus retention, has not been verified. package.json and src/utils/settingsUtil.ts have refresh and initial-file settings but no following policy. Preserve server-root resolution, file-serving boundaries, and existing manual preview commands; this request does not require growing the bundled browser or changing the injected reload script.
