# Issue #530 — [Feature request] Auto preview active opened file

[https://github.com/microsoft/vscode-livepreview/issues/530](https://github.com/microsoft/vscode-livepreview/issues/530)

## Summary

The accepted two-way synchronization request remains unimplemented: Live Preview can open the active file on command, but it neither follows active-editor changes nor opens the previewed page in the editor. This older, maintainer-triaged issue is the best canonical for the same active-file request later reported in https://github.com/microsoft/vscode-livepreview/issues/695.

## Change summary

Optionally keep the preview synchronized with the active HTML editor and provide a way to open the currently previewed local page in the code editor.

## Best solution

Keep this issue as the canonical request for opt-in editor-to-preview synchronization and, where supported, preview-to-editor navigation; consolidate https://github.com/microsoft/vscode-livepreview/issues/695 into it. The implementation should prioritize the default Integrated Browser path, while treating bundled-browser support separately if necessary; configurable non-HTML preview remains outside this issue based on the maintainer's scope decision.

## Vision fit

- **Fit:** aligned
- **Reason:** Synchronizing the active document with the preview improves the core server-and-preview workflow and the approachable default experience without turning the extension into an application server.
- **Evidence:** The durable themes explicitly include where the preview opens, including the Integrated Browser versus bundled webview, while the values describe the product as a local server plus preview and identify beginners as a primary audience.

## Evidence

- **maintainer scope:** A repository member explicitly accepted the preview-following-active-file and possibly active-file-following-preview portions as a feature request, while declaring non-HTML preview support out of scope.
- **capability gap:** package.json contributes livePreview.defaultPreviewPath, livePreview.openPreviewTarget, and livePreview.useIntegratedBrowser, but no setting for following the active editor; src/extension.ts registers explicit preview commands and contains no vscode.window.onDidChangeActiveTextEditor listener.
- **one-shot active-file behavior:** src/manager.ts openPreviewAtFileUri resolves vscode.window.activeTextEditor only when the preview command is invoked; it does not subscribe to subsequent editor changes.
- **reverse synchronization absent:** For the bundled browser, media/main.js forwards page navigation as update-path and src/editorPreview/browserPreview.ts records it through WebviewComm, but no path opens the corresponding workspace document with vscode.window.showTextDocument.
- **canonical search:** The newer open issue https://github.com/microsoft/vscode-livepreview/issues/695 asks for the preview to update when focus switches to another HTML file. Shipping this issue's editor-to-preview behavior would fully satisfy that newer request, so #530 is the older, already-triaged canonical.
- **existing capability does not cover request:** livePreview.autoRefreshPreview controls when content changes reload the current page; it does not change the preview URL when the active editor switches to another file.
