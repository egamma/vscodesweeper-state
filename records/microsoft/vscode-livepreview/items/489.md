# Issue #489 — Support Remote Repositories

[https://github.com/microsoft/vscode-livepreview/issues/489](https://github.com/microsoft/vscode-livepreview/issues/489)

## Summary

Remote Repositories support remains missing: the manifest disables virtual workspaces, and workspace content loading still depends on native filesystem paths. Keep this team-authored request open; the related web-support request does not own the same desktop workflow.

## Change summary

Allow users to preview existing HTML files and their relative assets from GitHub Remote Repositories in VS Code desktop without cloning the repository or installing Git.

## Best solution

Support provider-backed workspace URIs throughout preview launch, content loading, asset resolution, and live refresh while retaining native access for extension-owned resources. Coordinate with https://github.com/microsoft/vscode-livepreview/issues/190, but preserve this desktop request as distinct from running the extension in a browser-only extension host.

## Vision fit

- **Fit:** aligned
- **Reason:** Previewing existing plain HTML projects without a local clone advances approachable previewing and serving correctness without turning the extension into an application server.
- **Evidence:** Layers 1–2 identify beginners as a primary audience and serving correctness, relative-link resolution, and remote environments as durable themes.

## Evidence

- **Current capability remains disabled:** package.json explicitly declares capabilities.virtualWorkspaces: false. Its contributed commands and settings, including livePreview.serverRoot and livePreview.useIntegratedBrowser, provide no way to enable provider-backed workspace access; changing the preview browser does not remove this restriction.
- **Native filesystem dependency:** src/server/serverUtils/contentLoader.ts uses PathUtil.FileRead for unopened injectable files, fs.createReadStream and fs.statSync for other assets, and fs.readdir for directory listings. src/utils/pathUtil.ts implements FileExistsStat and FileRead with fs.promises.stat/readFile and derives workspace paths from uri.fsPath. These paths do not preserve virtual filesystem provider access.
- **Live-refresh adoption also remains:** src/updateListener.ts limits onDidChangeTextDocument refresh handling to file and untitled URI schemes. Supporting Remote Repositories requires extension-side integration beyond merely making the preview browser display a URL.
- **Maintainer-confirmed ownership:** https://github.com/microsoft/vscode-livepreview/issues/626#issuecomment-2021541442 explicitly states that GitHub Repositories is unsupported and tracks progress in this issue. The reporter's desktop, no-Git workflow and the distinction between workspace content and extension resources are established in https://github.com/microsoft/vscode-livepreview/issues/489#issuecomment-1491141729 and https://github.com/microsoft/vscode-livepreview/issues/489#issuecomment-1491183717.
- **Canonical search:** Verified https://github.com/microsoft/vscode-livepreview/issues/190 is open and older, but it requests browser-hosted vscode.dev/github.dev execution through a service-worker approach, not the same desktop Remote Repositories workflow. Searches also found https://github.com/microsoft/vscode-livepreview/issues/715 and https://github.com/microsoft/vscode-livepreview/issues/716, both newer virtual-workspace reports; neither can replace this older, re-reviewed item.
- **Distinct remote-hosting report:** https://github.com/microsoft/vscode-livepreview/issues/883 is open and describes local Windows extension execution against an SSH-backed Agents workspace, explicitly distinguishing that scenario from Remote Repositories. It is related filesystem evidence, not a canonical for this request.
