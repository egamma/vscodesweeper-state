# Issue #402 — Warn users if external browser opens invalid URL

[https://github.com/microsoft/vscode-livepreview/issues/402](https://github.com/microsoft/vscode-livepreview/issues/402)

## Summary

The failure remains traceable on current `main`: the bundled preview passes a scheme-less address unchanged to the external-browser helper and ignores whether VS Code opened it successfully. This team-authored Backlog issue should remain open; the Integrated Browser becoming the default reduces its reach but does not fix the bundled-browser path.

## Change summary

Provide feedback, or normalize the address, when a scheme-less URL entered in the bundled preview cannot be opened externally.

## Best solution

In `src/editorPreview/browserPreview.ts`, validate or normalize host-like URL-bar input before handing it to the external browser, and surface a clear error when opening fails. `src/utils/externalBrowserUtils.ts` should await and propagate the result of `vscode.env.openExternal` or the custom-browser command so callers can report failure.
