# Issue #49 — [ Question ] What about PHP files preview?

[https://github.com/microsoft/vscode-livepreview/issues/49](https://github.com/microsoft/vscode-livepreview/issues/49)

## Summary

PHP execution remains an unimplemented, actively requested capability, and this issue is the established canonical for it. Although PHP would push Live Preview beyond its documented static-server scope, there is no maintainer decision declining the request, so it should remain open for a product decision.

## Change summary

Add support for executing and live-previewing PHP projects rather than serving PHP source files as static content.

## Best solution

Decide whether Live Preview should remain a static-file server or gain an explicit PHP integration. If accepted, define a constrained runtime model—such as launching a user-configured PHP server and connecting Live Preview's refresh behavior to it—rather than treating `.php` files as ordinary static responses.

## Vision fit

- **Fit:** rejected
- **Reason:** Executing PHP would turn Live Preview toward an application-server role, while the documented product direction focuses on projects that do not already require a server.
- **Evidence:** The README says, "This extension is most useful for projects where a server is not already created," and the vision identifies PHP and other server-side execution as beyond the extension's current static-server guardrail.
