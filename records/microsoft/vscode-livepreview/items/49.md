# Issue #49 — [ Question ] What about PHP files preview?

[https://github.com/microsoft/vscode-livepreview/issues/49](https://github.com/microsoft/vscode-livepreview/issues/49)

## Summary

PHP execution remains an unimplemented, clearly tracked feature request. This issue is the canonical request, is assigned to Backlog, and has accumulated sustained community interest, so it should remain open for an explicit maintainer scope decision rather than being closed for age or current product positioning.

## Change summary

Add support for previewing PHP projects by executing PHP files rather than serving their source as static content.

## Best solution

Decide whether Live Preview should support a configurable PHP runtime or a more general external application-server integration, likely involving the server startup and URL-launch flow rather than the browser implementation. If application-server support is intentionally declined, document that PHP must run under a separate server and that its URL can be opened in VS Code's Integrated Browser.

## Vision fit

- **Fit:** rejected
- **Reason:** Executing PHP would expand Live Preview from a static local server into an application-server workflow, which runs against the README's stated positioning even though the final scope decision belongs to maintainers.
- **Evidence:** The README says the extension is most useful for projects where a server is not already created and directs projects with their own server to VS Code's Integrated Browser; the vision likewise identifies application-server functionality as outside the extension's current direction.
