# Issue #721 — Mulitple Previews not working Correctly

[https://github.com/microsoft/vscode-livepreview/issues/721](https://github.com/microsoft/vscode-livepreview/issues/721)

## Summary

Keep open: reliably opening independent previews for side-by-side comparison remains distinct from the current command's preview-reuse behavior. The previously designated tracking issue is closed, and the move to the Integrated Browser does not establish that Live Preview's commands now deliver this workflow.

## Change summary

Allow users to reliably open multiple independent embedded previews alongside their corresponding source editors without replacing the existing preview.

## Best solution

Establish a supported way to open an additional preview through Live Preview's Integrated Browser integration while preserving the existing reuse workflow. Confirm the reporter's browser implementation before deciding whether the remaining work is the extension's launch policy in src/editorPreview/previewManager.ts or browser behavior owned by microsoft/vscode.

- **Requested workflow:** https://github.com/microsoft/vscode-livepreview/issues/721 describes opening another preview replacing or revealing the existing one even with grouped or locked editors; the central request is independent previews for comparing code, not separate HTTP servers.
- **Current extension launch policy:** src/editorPreview/previewManager.ts, PreviewManager.launchFileInEmbeddedPreview, passes reuseUrlFilter: '**?vscode-livepreview=true' when opening the Integrated Browser. In the bundled-browser branch it reveals and navigates this.currentPanel whenever that panel exists, rather than creating another panel. These are explicit extension-side reuse paths; the Integrated Browser switch alone does not prove the requested command workflow is implemented.
- **Existing-capability check:** Read package.json contributes.configuration and contributes.commands and the relevant descriptions in package.nls.json. livePreview.useIntegratedBrowser selects the browser implementation, livePreview.openPreviewTarget selects embedded versus external preview, and livePreview.portNumber selects the server's initial port; none exposes a create-additional-preview option. The embedded preview command reaches the reuse logic in PreviewManager.
- **Previous tracking decision:** https://github.com/microsoft/vscode-livepreview/issues/625#issuecomment-2009981384 explicitly identifies https://github.com/microsoft/vscode-livepreview/issues/531 as the tracker for multiple Live Preview tabs.
