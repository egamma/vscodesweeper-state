# Issue #721 — Mulitple Previews not working Correctly

[https://github.com/microsoft/vscode-livepreview/issues/721](https://github.com/microsoft/vscode-livepreview/issues/721)

## Summary

Current main intentionally reuses a single embedded preview for both the bundled webview and the default Integrated Browser path. Opening independent previews for side-by-side comparison remains an unsupported feature request with no open canonical issue, so it should stay open and be classified as `feature-request`.

## Change summary

Allow multiple independent embedded preview tabs so different pages can be viewed beside their corresponding editors.

## Best solution

Make preview reuse configurable or add an explicit command that opens a new Integrated Browser preview rather than passing the global Live Preview reuse filter. Maintainers should decide separately whether the legacy bundled browser needs multi-panel support; the current issue can serve as the canonical request because the earlier tracker was closed.

- **Proposed comment:**

  > Thanks for the report and the comparison use case. Live Preview currently reuses one embedded preview: the bundled browser keeps a single panel, and the current Integrated Browser path also asks VS Code to reuse the existing Live Preview tab. There is no `livePreview.*` setting or command that forces a second independent embedded preview, so using separate external-browser tabs is the available workaround today. I suggest keeping this open as the feature request for independently opening multiple previews.

## Auto-fix candidate

- **Auto-fixable:** no

## Evidence

- **current bundled-browser behavior:** src/editorPreview/previewManager.ts stores only one `currentPanel`; `launchFileInEmbeddedPreview` reveals that panel instead of creating another. src/test/suite/preview.test.ts explicitly asserts that repeated launches use the same panel.
- **current Integrated Browser behavior:** src/editorPreview/previewManager.ts invokes the Integrated Browser with `reuseUrlFilter: '**?vscode-livepreview=true'`, causing Live Preview launches for different pages to reuse a matching tab. This behavior was introduced by https://github.com/microsoft/vscode-livepreview/pull/800.
- **no existing capability:** The commands and `livePreview.*` configuration in package.json provide embedded/external preview selection and Integrated Browser selection, but no command or setting for creating an additional independent embedded preview.
- **historical tracking:** The exact earlier request https://github.com/microsoft/vscode-livepreview/issues/625 was redirected to https://github.com/microsoft/vscode-livepreview/issues/531. That issue was later closed after `window.open(..., '_blank')` moved to the Integrated Browser, but it does not establish that manual Live Preview commands can open multiple independent previews.
- **scope precedent allows reconsideration:** https://github.com/microsoft/vscode-livepreview/issues/84 was closed as not planned in 2022, but the maintainer explicitly said the feature could be reconsidered for a valid use case; this report supplies the concrete side-by-side comparison use case.
