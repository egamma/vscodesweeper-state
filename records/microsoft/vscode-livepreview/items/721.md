# Issue #721 — Mulitple Previews not working Correctly

[https://github.com/microsoft/vscode-livepreview/issues/721](https://github.com/microsoft/vscode-livepreview/issues/721)

## Summary

This is a valid, currently unsupported request for multiple simultaneous embedded previews. Current main still deliberately reuses one preview, while the previous tracker for this request was closed after the move to the Integrated Browser, so this issue should remain open as the current extension-side feature request.

## Change summary

Allow multiple Live Preview pages to remain open simultaneously, ideally pairing separate editor groups with separate preview tabs.

## Best solution

Add an explicit way to open a new Integrated Browser preview instead of always reusing the existing Live Preview tab, while preserving reuse as the default behavior. Maintainers should separately decide whether the legacy bundled browser behind `livePreview.useIntegratedBrowser: false` remains singleton-only.

## Vision fit

- **Fit:** aligned
- **Reason:** Supporting multiple previews through VS Code's Integrated Browser improves the extension's browser integration without expanding the legacy bundled browser.
- **Evidence:** The durable “Where the preview opens” theme includes Integrated Browser integration, and the vision guardrail says the extension should build on core platform surfaces rather than grow its bundled browser.

  > Thanks for the clear use case. Multiple pages can share the same Live Preview server and port, so a second port is not required; the limitation is currently the preview UI. Live Preview still reuses one embedded preview: the bundled browser keeps a single panel, and the current Integrated Browser path also asks VS Code to reuse the existing Live Preview tab. The earlier request at https://github.com/microsoft/vscode-livepreview/issues/625 was tracked through https://github.com/microsoft/vscode-livepreview/issues/531, but that tracker has since been closed. I suggest keeping this issue open to track an explicit “open in a new preview tab” option for the Integrated Browser.

## Evidence

- **current Integrated Browser behavior:** `src/editorPreview/previewManager.ts` invokes `workbench.action.browser.open` with `reuseUrlFilter: '**?vscode-livepreview=true'`, causing all URLs opened through Live Preview to reuse one Integrated Browser tab.
- **current bundled-browser behavior:** `PreviewManager` is explicitly documented as a singleton, stores only `currentPanel`, and calls `currentPanel.reveal(...)` instead of creating another panel. `src/test/suite/preview.test.ts` asserts that repeated launches use the same panel.
- **no existing setting:** `package.json` provides `livePreview.openPreviewTarget` and `livePreview.useIntegratedBrowser`, but no setting or command for creating another simultaneous embedded preview; changing the port is unrelated because multiple pages can share one server.
- **prior exact request:** https://github.com/microsoft/vscode-livepreview/issues/625 requested multiple side-by-side Live Preview windows and was closed in favor of https://github.com/microsoft/vscode-livepreview/issues/531.
- **former canonical is closed:** https://github.com/microsoft/vscode-livepreview/issues/531 was closed after the Integrated Browser became the default. Because it is no longer open and current extension code still forces tab reuse, it cannot serve as a duplicate target for this remaining extension-side behavior.
