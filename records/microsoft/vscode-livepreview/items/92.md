# Issue #92 — Remember already opened previews in external browser

[https://github.com/microsoft/vscode-livepreview/issues/92](https://github.com/microsoft/vscode-livepreview/issues/92)

## Summary

External preview launches still have no extension-side mechanism to reuse an already-open tab for the same file. This accepted Backlog request remains distinct from embedded-preview reuse, and the canonical search found no older open issue owning the same request.

## Change summary

Reuse an existing external-browser preview for a file instead of opening another tab each time its preview command is invoked.

## Best solution

Determine whether the external-browser launch integrations can reliably reuse or focus a preview for the same URL, including reopening it after the user closes the tab. The relevant boundary is src/editorPreview/previewManager.ts and src/utils/externalBrowserUtils.ts; embedded-browser reuse does not satisfy this request.

- **Fit:** aligned
- **Reason:** Avoiding duplicate external preview tabs improves the existing external-browser workflow without expanding the extension into an application server or a bundled browser.
- **Evidence:** Layer 2, “Where the preview opens,” identifies external-browser preview and its launch settings as a durable product theme.

## Evidence

- **External launch path:** src/editorPreview/previewManager.ts, PreviewManager.launchFileInExternalBrowser, constructs the URL on each invocation and dispatches either extension.js-debug.debugLink or ExternalBrowserUtils.openInBrowser. It does not track already-open external previews.
- **No external tab reuse mechanism:** src/utils/externalBrowserUtils.ts, ExternalBrowserUtils.openInBrowser, delegates each request to vscode.env.openExternal or js-debug-companion.launch. There is no existing-tab lookup, retained browser-tab handle, or reuse option in this helper.
- **Existing-capability check:** Read contributes.configuration and contributes.commands in package.json and the descriptions in package.nls.json. livePreview.customExternalBrowser selects a browser, livePreview.debugOnExternalPreview controls debugging, and livePreview.openPreviewTarget selects embedded versus external preview; none provides external-tab reuse. The reuseUrlFilter in PreviewManager.launchFileInEmbeddedPreview applies only to VS Code's Integrated Browser.
- **Related issue is not a canonical:** https://github.com/microsoft/vscode-livepreview/issues/99 is closed, newer than this issue, and concerns retaining multiple embedded previews rather than preventing duplicate external-browser tabs. Its maintainer response at https://github.com/microsoft/vscode-livepreview/issues/99#issuecomment-1341775058 declines multiple embedded windows, not external-tab reuse.
- **Canonical search:** Repository issue searches for external browser tabs, browser reuse, browser, and tabs found no verified older open canonical for the same external-tab duplication symptom. The checkout is shallow, so its limited history was not treated as proof that no historical implementation exists.
