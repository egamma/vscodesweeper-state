# Issue #92 — Remember already opened previews in external browser

[https://github.com/microsoft/vscode-livepreview/issues/92](https://github.com/microsoft/vscode-livepreview/issues/92)

## Summary

The external-preview path still launches the URL on every request without tracking an existing browser tab, and no setting provides reuse semantics. This remains a valid Backlog feature request; the related embedded-preview issue concerns a distinct implementation and does not own this work.

## Change summary

Reuse or navigate an existing external-browser preview tab instead of opening another tab for a file that is already being previewed.

## Best solution

Define the desired reuse scope—same file, same server, or any Live Preview tab—and determine which launch modes can support it. The default-browser path currently uses `vscode.env.openExternal`, which exposes no tab handle, while custom and debug launches use js-debug commands; implementation may therefore require an opt-in browser-debug integration or be limited to launch modes that can identify an existing target.

## Evidence

- **current external launch behavior:** `src/editorPreview/previewManager.ts` constructs the preview URL on every `launchFileInExternalBrowser` call and invokes either `ExternalBrowserUtils.openInBrowser` or `extension.js-debug.debugLink`; it stores no external tab or target identity.
- **default browser API:** `src/utils/externalBrowserUtils.ts` delegates default-browser launches to `vscode.env.openExternal(vscode.Uri.parse(target))`, with no reuse filter or browser-tab handle.
- **existing-capability check:** `package.json` provides `livePreview.openPreviewTarget`, `livePreview.customExternalBrowser`, and `livePreview.debugOnExternalPreview`, but none controls external-tab reuse. The Integrated Browser's `reuseUrlFilter` in `src/editorPreview/previewManager.ts` applies only to embedded previews.
- **related issue is distinct:** https://github.com/microsoft/vscode-livepreview/issues/99 requested multiple simultaneous embedded webview previews and was declined with reference to the embedded-window rationale in https://github.com/microsoft/vscode-livepreview/issues/84; neither issue would deliver reuse of an external-browser tab.
