# Issue #92 — Remember already opened previews in external browser

[https://github.com/microsoft/vscode-livepreview/issues/92](https://github.com/microsoft/vscode-livepreview/issues/92)

## Summary

The requested external-browser tab reuse is not implemented on current main and no open canonical issue owns it. The issue is already correctly classified as a Backlog feature request and should remain open for a product and implementation decision.

## Change summary

Reuse an existing external-browser preview for a file instead of opening another browser tab whenever that file is previewed again.

## Best solution

Define external-preview reuse semantics and implement them in `src/editorPreview/previewManager.ts` and `src/utils/externalBrowserUtils.ts` where the selected browser integration can identify or control an existing tab. The default `vscode.env.openExternal` path cannot itself identify previously opened tabs, so support may require a controlled browser/debug session or a suitable VS Code platform capability.

## Vision fit

- **Fit:** aligned
- **Reason:** External-browser preview is an established Live Preview workflow, and avoiding duplicate tabs would improve that supported experience without expanding the extension into an application server or duplicating the Integrated Browser.
- **Evidence:** The durable theme "Where the preview opens" explicitly includes external preview, custom external browsers, and debug preview using js-debug.
