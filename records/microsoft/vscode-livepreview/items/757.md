# Issue #757 — Auto refresh refreshes when any editor in the current window changes

[https://github.com/microsoft/vscode-livepreview/issues/757](https://github.com/microsoft/vscode-livepreview/issues/757)

## Summary

Current main intentionally refreshes for every changed file or untitled text document when `On All Changes in Editor` is selected, and no source-scoped mode exists. This is a valid, distinct feature request that should remain open and be classified as `feature-request`.

## Change summary

Add an auto-refresh mode that reloads only when the document associated with the preview changes, ignoring edits in unrelated editors.

## Best solution

Define whether “source” means only the previewed HTML document or also its CSS, scripts, and other dependencies, then add a separate `livePreview.autoRefreshPreview` enum value and filter `UpdateListener` events accordingly. Preserve the existing all-editor and saved-file modes; coordinate with the broader configurable-ignore request at https://github.com/microsoft/vscode-livepreview/issues/548 without treating it as a substitute for this source-scoped mode.

## Vision fit

- **Fit:** aligned
- **Reason:** Controlling which edits trigger reloads directly advances the extension's durable live-refresh behavior while keeping the change within its server and refresh orchestration.
- **Evidence:** The vision identifies live refresh—including whether reload occurs on change or save and which edits should trigger it—as a durable theme.

## Evidence

- **current source behavior:** `src/updateListener.ts` lines 41-49 handles the workspace-wide `onDidChangeTextDocument` event and calls `_refreshPreview()` for every changed file or untitled document when `_reloadOnAnyChange` is true; it does not compare the changed URI with the previewed document.
- **global refresh wiring:** `src/manager.ts` lines 267-270 subscribes to the single `UpdateListener` event and refreshes browser groupings without passing preview-source identity into the listener.
- **existing capability gap:** `package.json` exposes only `On All Changes in Editor`, `On Changes to Saved Files`, and `Never` for `livePreview.autoRefreshPreview`. The saved-file option reduces edit-time reloads but does not provide the requested source-only behavior.
- **canonical search:** Open issue https://github.com/microsoft/vscode-livepreview/issues/548 requests configurable ignored paths for the saved-file watcher. That is related but does not fully own this request: an ignore list does not inherently identify the document associated with each active preview, and the existing issue specifically concerns the save-based mode.
