# Issue #757 — Auto refresh refreshes when any editor in the current window changes

[https://github.com/microsoft/vscode-livepreview/issues/757](https://github.com/microsoft/vscode-livepreview/issues/757)

## Summary

The request for a narrower auto-refresh scope is already owned by the open watch-files settings request at https://github.com/microsoft/vscode-livepreview/issues/233. That canonical covers restoring configurable file selection so unrelated editor changes do not refresh the preview.

## Change summary

Add an auto-refresh mode that reacts only to changes in the relevant source editor rather than every changed text document in the VS Code window.

## Best solution

Restore a configurable refresh scope under https://github.com/microsoft/vscode-livepreview/issues/233, allowing users to select the source files or globs that should trigger refresh while retaining support for linked CSS, scripts, and generated files. The implementation should filter editor-change events before refreshing every active server grouping.

- **Reason:** Controlling which source changes trigger a reload directly advances Live Preview's durable live-refresh theme and reduces disruption in mainstream multi-file projects.
- **Evidence:** The public vision identifies live refresh—including which edits should trigger it and the livePreview.autoRefreshPreview setting—as a durable area of investment.

## Evidence

- **current source behavior:** In src/updateListener.ts:41-50, workspace.onDidChangeTextDocument triggers a refresh for every changed file or untitled document when livePreview.autoRefreshPreview is "On All Changes in Editor"; it does not check the active editor, served files, or the current preview.
- **global refresh fan-out:** src/manager.ts:545-549 responds to the listener by refreshing every active ServerGrouping, so an unrelated editor change can reload all running previews.
- **no existing narrower mode:** package.json:214-221 and src/utils/settingsUtil.ts:31-35 expose only "On All Changes in Editor", "On Changes to Saved Files", and "Never"; none limits editor-triggered refreshes to selected source files.
- **verified canonical:** The open Backlog feature request https://github.com/microsoft/vscode-livepreview/issues/233 explicitly tracks reimplementing the removed watch-files setting, and its discussion includes the same problem of unrelated files causing constant refreshes.
- **same configurable-scope mechanism:** The prior watch-files implementation at https://github.com/microsoft/vscode-livepreview/commit/6145f489ddb447182afa780759b94f4f0aa35119 added livePreview.watchFiles as a glob and used it to filter onDidChangeTextDocument events. Restoring that capability under the canonical would fully provide the requested source-only refresh scope.
