# Issue #757 — Auto refresh refreshes when any editor in the current window changes

[https://github.com/microsoft/vscode-livepreview/issues/757](https://github.com/microsoft/vscode-livepreview/issues/757)

## Summary

Keep open: the requested source-editor-only refresh mode is not available, and current source deliberately broadcasts changes from any file or untitled editor. Older related requests concern configurable watch filters or hidden previews, not the same source-editor-specific behavior.

## Change summary

Add an auto-refresh mode that responds to changes in the preview's source editor while ignoring unrelated editors.

## Best solution

Define how a preview identifies its source document and provide an optional refresh scope through src/updateListener.ts and the manager/server refresh pipeline, preserving the existing all-editor mode. Coordinate with https://github.com/microsoft/vscode-livepreview/issues/233 and https://github.com/microsoft/vscode-livepreview/issues/548 without treating static watch filters as equivalent to tracking a preview's source editor.

- **Behavior:**

  > Users should be able to keep automatic refresh for the document they are previewing without triggering reloads while editing unrelated documents. The existing all-editor mode must remain available and retain its behavior. Acceptance checks should cover a previewed HTML document, an unrelated editor, linked assets, and multiple previews, with source association and asset behavior settled before implementation.
- **Trace:**

  > src/updateListener.ts UpdateListener listens globally to workspace.onDidChangeTextDocument and emits shouldRefreshPreviews without document identity. src/manager.ts subscribes to that event and _refreshBrowsers() refreshes every server grouping; src/server/serverGrouping.ts refresh() reaches src/server/wsServer.ts refreshBrowsers(), which broadcasts to every client. The manifest and settings accessor provide timing modes but no source-document scope. Source inspection establishes that the capability is absent; no runtime verification was performed. Preserve existing all-editor behavior and avoid changing serving boundaries or injected-script behavior. Related watch-filter work is tracked at https://github.com/microsoft/vscode-livepreview/issues/233 and https://github.com/microsoft/vscode-livepreview/issues/548, but does not settle preview-specific source association.
- **Open decisions:**
  - Does 'source editor' mean the document originally used to launch a preview or the document currently displayed after navigation, and should simultaneous previews each follow their own source?
  - Should the new mode reload only for edits to that HTML document, or also for linked CSS and JavaScript documents?

## Evidence

- **Existing capabilities do not cover the request:** package.json contributes.configuration exposes only 'On All Changes in Editor', 'On Changes to Saved Files', and 'Never' for livePreview.autoRefreshPreview. The command declarations and package.nls.json contain no source-editor-specific refresh command; livePreview.previewDebounceDelay controls timing, not scope.
- **Current extension-owned refresh path:** src/updateListener.ts registers workspace.onDidChangeTextDocument and refreshes for any nonempty change in a file or untitled document when the all-changes mode is enabled, without checking its relationship to a preview. src/manager.ts wires shouldRefreshPreviews to _refreshBrowsers(), which refreshes every server grouping; src/server/wsServer.ts refreshBrowsers() broadcasts reload to all connected clients. This behavior originates in the extension, not the Integrated Browser.
- **Per-page opt-out is not selective refresh:** media/injectScript.js reloadPage() honors data-server-no-reload by blocking automatic reload entirely. It cannot retain refresh for source-editor edits while suppressing unrelated-editor edits.
- **Older related requests are not verified canonicals:** Verified https://github.com/microsoft/vscode-livepreview/issues/233 and https://github.com/microsoft/vscode-livepreview/issues/548 are open. The former requests restored watch-file configuration; the latter requests ignore filters for saved-file watcher events. Neither establishes the requested source-editor-associated mode. https://github.com/microsoft/vscode-livepreview/issues/454 is also open but concerns refreshing an invisible preview, a different observable condition. These do not satisfy the re-reviewed item's same-symptom duplicate bar.
- **Maintainer context supports configurability:** In https://github.com/microsoft/vscode-livepreview/issues/653#issuecomment-2374471722, a maintainer explains that arbitrary workspace files can affect the page and supports explicit ignore configuration. That supports keeping broad refresh behavior available, not declining an optional narrower mode.
