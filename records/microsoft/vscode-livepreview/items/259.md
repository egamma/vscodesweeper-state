# Issue #259 — Command for re-opening live preview editor

[https://github.com/microsoft/vscode-livepreview/issues/259](https://github.com/microsoft/vscode-livepreview/issues/259)

## Summary

The command palette now has `Live Preview: Show Preview`, but current source still does not preserve the closed preview's address: disposing the bundled panel clears `currentPanel`, while the Integrated Browser path records no panel or last URL. Reopening therefore depends on the active editor or default path rather than restoring the preview that was closed, so the underlying lifecycle gap remains.

## Change summary

Provide a reliable command that reopens the most recently closed Live Preview editor at its previous page.

## Best solution

Retain the last preview URI and associated server grouping independently of the browser tab, then have `livePreview.start.preview.atFile` restore that target when no preview is open. The behavior should work for both the default Integrated Browser path and the bundled browser without depending on the active text editor.

## Evidence

- **existing command is incomplete:** `package.json` contributes `livePreview.start.preview.atFile` as `Live Preview: Show Preview`, and `src/extension.ts` routes it to `Manager.openPreviewAtFileUri`; this provides an entry point but not restoration of the closed preview.
- **closed target is discarded:** In `src/editorPreview/previewManager.ts`, the panel disposal listener sets `currentPanel = undefined`; the previous `currentAddress` is owned by that disposed `BrowserPreview` and is not retained elsewhere.
- **fallback selects another target:** In `src/manager.ts`, `openPreviewAtFileUri` can reuse `currentAddress` only while an active `currentPanel` exists. After closure it instead selects `vscode.window.activeTextEditor`, or falls through to `_openPreviewWithNoTarget`, so it cannot reliably restore the page that was closed.
- **Integrated Browser path also lacks restoration state:** `src/editorPreview/previewManager.ts` executes the Integrated Browser command and returns without creating or recording a `currentPanel`; reopening therefore also derives its URL from the active/default file rather than retained preview state.
- **canonical search:** Searches for open vscode-livepreview issues about reopening or showing a closed preview found no open issue that clearly owns this same remaining work.
