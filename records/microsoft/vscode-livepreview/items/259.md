# Issue #259 — Command for re-opening live preview editor

[https://github.com/microsoft/vscode-livepreview/issues/259](https://github.com/microsoft/vscode-livepreview/issues/259)

## Summary

The reopening gap remains on current main: after the preview and other editors are closed, the running server's status-bar action opens the Live Preview command list, but no preview-opening command is visible without an active HTML editor.

## Change summary

Provide a command that reopens the embedded preview while its Live Preview server is still running, without requiring an open HTML editor or editor-history restoration.

## Best solution

Expose an embedded-preview command whenever `LivePreviewServerOn` is true and have it reopen the running server's last preview URL, or its root if no previous URL is retained. The command contribution belongs in `package.json`; retaining the last closed preview target may require a small change in `src/editorPreview/previewManager.ts` or `src/manager.ts`, and it should work for both the Integrated Browser and bundled-browser paths.

## Evidence

- **command visibility:** `package.json` contributes `livePreview.start.internalPreview.atFile` as “Show Preview (Internal Browser)”, but its Command Palette entry is gated by `editorLangId == html && !notebookEditorFocused`; the generic `livePreview.start.preview.atFile` command is explicitly hidden with `when: false`. With no HTML editor open, neither provides the requested reopening action.
- **status-bar path:** `src/server/serverUtils/statusBarNotifier.ts` keeps the running server visible and makes the status-bar item execute `workbench.action.quickOpen` with `>Live Preview: `, but that filtered palette still obeys the manifest conditions and therefore does not expose the internal-preview command in the reported state.
- **closed-preview state:** `src/editorPreview/previewManager.ts` clears `currentPanel` when the webview is disposed while retaining the server for the configured keep-alive period. It does not retain a separate last-preview target that a reopen command could restore.
- **related command fix is narrower:** https://github.com/microsoft/vscode-livepreview/issues/303 added command visibility while the preview webview itself is focused; it does not cover the state after that webview and the other file editors have been closed.
- **existing workaround is incomplete:** https://github.com/microsoft/vscode-livepreview/issues/638 documents reopening an HTML file and using its Show Preview action or assigning a shortcut, but that does not provide the requested command while no HTML editor is open.
