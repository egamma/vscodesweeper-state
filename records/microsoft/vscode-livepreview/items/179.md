# Issue #179 — Live Preview "Host IP" setting does not support IPv6 addresses

[https://github.com/microsoft/vscode-livepreview/issues/179](https://github.com/microsoft/vscode-livepreview/issues/179)

## Summary

IPv6 hosting remains unsupported on current main: host validation explicitly accepts only IPv4, and local URL construction does not bracket IPv6 literals. The initial implementation was reverted after the reporter demonstrated that validation alone was insufficient; this accepted Backlog request remains necessary.

## Change summary

Support IPv6 addresses in livePreview.hostIP throughout server binding, preview URL generation, and live-reload connections.

## Best solution

Deliver end-to-end IPv6 support across src/connectionInfo/ and the HTTP/WebSocket server integration, preserving existing IPv4 behavior and host-access protections. Accepting IPv6 in the setting alone is insufficient; preview URLs and live reload must work with an IPv6 loopback address.

## Evidence

- **Existing capability remains IPv4-only:** package.json exposes livePreview.hostIP with default 127.0.0.1, but src/connectionInfo/connectionManager.ts imports net.isIPv4 and _validHost returns isIPv4(host). Both initial configuration and subsequent host changes reject IPv6 and fall back to DEFAULT_HOST. The configuration and command surfaces provide no alternative IPv6 mode.
- **End-to-end work remains:** src/connectionInfo/connection.ts, Connection.constructLocalUri, directly interpolates the host into http://${this.host}:${port} without IPv6-literal brackets. Both resolveExternalHTTPUri and resolveExternalWSUri use this method. HTTP and WebSocket binding also consume Connection.host, so changing validation alone does not establish working IPv6 preview and reload.
- **Initial fix was insufficient and reverted:** In https://github.com/microsoft/vscode-livepreview/issues/179, the reporter supplied a recording showing continued failure in 0.2.10. The maintainer subsequently confirmed that IPv6 required more than setting validation and reverted the change in 0.2.11. CHANGELOG.md independently records both the 0.2.10 addition and the 0.2.11 revert.
- **Related merged PR does not implement the request:** https://github.com/microsoft/vscode-livepreview/pull/257 is merged, but its stated scope is per-workspace servers for multi-root support and it fixes a different issue. Current ConnectionManager validation still rejects IPv6, so this PR is not evidence of completion.
- **Canonical search:** Repository issue searches for IPv6 and host IP found no verified older canonical owning this request. https://github.com/microsoft/vscode-livepreview/issues/333 concerns IPv4 wildcard binding to 0.0.0.0 and is newer; it does not qualify as a duplicate target for this re-reviewed IPv6 request.
- **Preserve accepted work:** The issue is classified feature-request in Backlog, and the maintainer explicitly accepted further IPv6 work after the failed initial implementation. Neither age nor the deliberate validation restriction supports a decline close.
