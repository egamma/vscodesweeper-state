# Issue #179 — Live Preview "Host IP" setting does not support IPv6 addresses

[https://github.com/microsoft/vscode-livepreview/issues/179](https://github.com/microsoft/vscode-livepreview/issues/179)

## Summary

IPv6 remains explicitly unsupported on current main: host validation accepts only IPv4, and several URL-construction and request-validation paths assume an IPv4-style authority. The request is still necessary and correctly belongs in the Backlog as a feature request.

## Change summary

Allow `livePreview.hostIP` to accept IPv6 addresses and use them correctly for HTTP, WebSocket, embedded-preview, and external-preview URLs.

## Best solution

Implement IPv6 consistently across `src/connectionInfo/`, `src/server/`, and `src/editorPreview/`: accept valid IPv6 hosts, construct URI authorities with the required brackets, and validate IPv6 Host and Origin headers correctly. Add connection and preview tests covering at least the `::1` loopback address rather than changing validation alone.

- **Evidence:** The durable themes explicitly include “Server lifecycle and configuration — the port and host (`livePreview.portNumber`, `livePreview.hostIP`)”.

  > Thanks for the detailed proposal and the earlier verification. This remains a real gap on current `main`: `ConnectionManager` still validates `livePreview.hostIP` with `net.isIPv4`, and the connection, preview, and HTTP request-checking paths also construct or compare authorities in an IPv4-oriented form. Supporting IPv6 therefore needs coordinated handling of bracketed HTTP/WebSocket authorities and Host/Origin validation, not only a validator change. Keeping this open as the Backlog feature request for that work.

## Evidence

- **current validation:** `src/connectionInfo/connectionManager.ts` imports `isIPv4` from Node's `net` module and `_validHost` returns only `isIPv4(host)`, so every IPv6 value is rejected and replaced with the default host.
- **IPv4-shaped URI construction:** `src/connectionInfo/connection.ts` constructs local addresses as `http://${this.host}:${port}`; `src/editorPreview/previewManager.ts` uses the same interpolation for Integrated Browser and external-browser URLs. An IPv6 literal requires a bracketed authority such as `http://[::1]:3000`.
- **server request checks:** `src/server/httpServer.ts` compares incoming Host and Origin headers against IPv4-oriented host strings, while both HTTP and WebSocket servers bind directly to `connection.host`; complete support therefore extends beyond replacing the validator.
- **explicit revert:** `CHANGELOG.md` records IPv6 support in 0.2.10 and its reversion in 0.2.11 under issue 179. The revert commit is https://github.com/microsoft/vscode-livepreview/commit/44f2bd5e2fea4622e2de02d523b94cfea6d316da.
- **related PR does not implement it:** Merged https://github.com/microsoft/vscode-livepreview/pull/257 reorganized connection management for multiple workspace servers but retained IPv4-only validation; it does not satisfy the IPv6 request.
- **canonical search:** A current search found no other open IPv6 issue in microsoft/vscode-livepreview. Open issue https://github.com/microsoft/vscode-livepreview/issues/631 requests the distinct ability to launch with the `localhost` hostname and does not own IPv6 support.
