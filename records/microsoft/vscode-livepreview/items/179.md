# Issue #179 — Live Preview "Host IP" setting does not support IPv6 addresses

[https://github.com/microsoft/vscode-livepreview/issues/179](https://github.com/microsoft/vscode-livepreview/issues/179)

## Summary

IPv6 support remains an explicit gap on current main. The first attempted fix was rejected by the reporter's retest and reverted; current validation and URL construction still support only IPv4, with no open canonical issue or PR owning the remaining work.

## Change summary

Support IPv6 literals end to end in the `livePreview.hostIP` setting, server binding, and generated HTTP and WebSocket URLs.

## Best solution

Keep the raw IPv6 address for Node server binding while using a shared URI/authority builder that brackets IPv6 literals wherever the extension constructs HTTP or WebSocket URLs. Update validation in `src/connectionInfo/connectionManager.ts`, audit the host-dependent paths in `src/connectionInfo/connection.ts`, `src/editorPreview/`, and `src/server/`, and add IPv4/IPv6 connection and preview URL tests.

## Vision fit

- **Fit:** aligned
- **Reason:** IPv6 support strengthens the extension's existing host configuration and server-lifecycle surface without turning it into a broader application server.
- **Evidence:** The durable server lifecycle and configuration theme explicitly includes the configured host through `livePreview.hostIP`, while serving correctness includes generating usable URLs for the selected server endpoint.

  > Thanks for the detailed proposal and follow-up testing. This remains a real feature gap on current `main`: `ConnectionManager` still validates with `net.isIPv4`, and several HTTP and WebSocket addresses are assembled from the host directly, so IPv6 support requires both accepting the address and formatting IPv6 URL authorities correctly. ## Evidence

- **current validation:** `src/connectionInfo/connectionManager.ts` imports `isIPv4` from Node's `net` module and `_validHost` returns `isIPv4(host)`, so every IPv6 literal is still rejected and replaced by the default host.
- **remaining URL work:** `src/connectionInfo/connection.ts` and `src/editorPreview/previewManager.ts` construct addresses as `http://${host}:${port}`. IPv6 literals require bracketed URL authorities, confirming the maintainer's observation that changing validation alone does not deliver the feature.
- **failed fix lifecycle:** The initial fix commit https://github.com/microsoft/vscode-livepreview/commit/9b05c6b919623c8547049db00598317ab3f7a1ff closed the issue, but it was reopened after the reporter reproduced another failure. The project then deliberately reverted IPv6 support in https://github.com/microsoft/vscode-livepreview/commit/44f2bd5e2fea4622e2de02d523b94cfea6d316da, documented in `CHANGELOG.md` for version 0.2.11.
