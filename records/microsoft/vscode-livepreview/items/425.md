# Issue #425 — Consider respecting server root even if the directory doesn't exist

[https://github.com/microsoft/vscode-livepreview/issues/425](https://github.com/microsoft/vscode-livepreview/issues/425)

## Summary

Keep open: current source still deliberately falls back to the workspace root when the configured server root does not exist. This accepted polish request would make configuration mistakes easier to diagnose; neither a fix nor a verified canonical duplicate was found.

## Change summary

Honor an explicitly configured livePreview.serverRoot even when its directory does not exist, instead of silently substituting the workspace root.

## Best solution

Make server-root resolution in src/utils/pathUtil.ts and its connection consumers preserve the configured root rather than serving the workspace root when that directory is missing. Keep the resulting failure understandable to the user and update the setting description and tests to match the agreed behavior.

## Evidence

- **Fallback reaches preview and connection selection:** src/connectionInfo/connectionManager.ts:94-100 passes that resolved prefix into Connection. src/manager.ts:558-560 treats an empty prefix as permitting the workspace to serve the preview. This is extension-owned root selection, independent of which embedded browser renders the page.
- **Intentional existing behavior, requested polish:** src/test/suite/pathUtil.test.ts explicitly asserts that a nonexistent serverRoot returns ''. package.nls.json settings.serverRoot explicitly documents fallback to the workspace root, and package.json exposes no alternative missing-directory policy.
