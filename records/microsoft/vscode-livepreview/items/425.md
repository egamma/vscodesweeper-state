# Issue #425 — Consider respecting server root even if the directory doesn't exist

[https://github.com/microsoft/vscode-livepreview/issues/425](https://github.com/microsoft/vscode-livepreview/issues/425)

## Summary

Current main still deliberately replaces a nonexistent configured server root with the workspace root. The requested behavior remains unimplemented, has no canonical issue, and is already accepted in the On Deck milestone as a serving-configuration polish item.

## Change summary

Keep `livePreview.serverRoot` authoritative when its target directory does not exist instead of silently serving from the workspace root.

## Best solution

Preserve the configured root in `PathUtil.GetValidServerRootForWorkspace` and the connection/file-routing paths that consume it, so an invalid root produces an explicit missing-path outcome rather than exposing the workspace root. Update the setting description and `pathUtil.test.ts` to reflect the new behavior.

## Evidence

- **behavior remains tested:** `src/test/suite/pathUtil.test.ts` contains `returns no root if serverRoot does not exists`, which asserts that a missing configured directory produces `''`; current main therefore has not implemented the requested behavior.
- **documented existing semantics:** `package.nls.json` says that when the `livePreview.serverRoot` directory does not exist, the setting defaults to the workspace root. The linked test-plan item documents the same fallback as the original expected behavior: https://github.com/microsoft/vscode/issues/172071.
