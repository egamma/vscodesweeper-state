# Issue #733 — images doesn't load when i use live preview in a vite project

[https://github.com/microsoft/vscode-livepreview/issues/733](https://github.com/microsoft/vscode-livepreview/issues/733)

## Summary

This is an expected difference between Live Preview's static file server and Vite's development server, not a defect in Live Preview. Vite resolves its public assets and build pipeline, whereas Live Preview serves URLs directly from the configured workspace root.

## Change summary

A Vite project's absolute background-image URL does not load through Live Preview even though Vite's development and production builds resolve it.

## Best solution

Run the project's Vite development server and open its URL in VS Code's Integrated Browser. If Live Preview must be used, the image must exist at the path represented by `/img/png/bg-header.png` under the effective `livePreview.serverRoot`, but this does not replace Vite's asset processing.

- **Proposed comment:**

  > Thanks for the report. This happens because Live Preview is a static file server and does not run Vite's asset-processing or public-directory mapping. The leading slash in `url('/img/png/bg-header.png')` makes Live Preview look for `img/png/bg-header.png` directly under the effective workspace root (or `livePreview.serverRoot`), while Vite's development server resolves the URL according to the Vite project layout.
  > 
  > For a Vite project, the intended setup is to run `npm run dev` and open the Vite URL in VS Code's Integrated Browser. If you want to keep using Live Preview instead, make sure the image exists at that exact path beneath the configured server root, but Vite-specific processing will still not be available.

## Evidence

- **documented product boundary:** README.md states that Live Preview is most useful for projects where a server is not already created and directs projects with their own development server to VS Code's Integrated Browser.
- **static path resolution:** src/server/httpServer.ts resolves each requested URL against the Live Preview server base path, while src/server/serverUtils/contentLoader.ts reads the resulting file directly from the filesystem; there is no Vite asset transformation or public-directory mapping.
- **path-specific behavior:** The working img element uses a relative `img/gif/duckling.gif` URL, while the failing Tailwind class contains the root-relative `/img/png/bg-header.png` URL. Under Live Preview that leading-slash URL is looked up from the effective workspace or `livePreview.serverRoot`, whereas Vite can map it through its own public asset handling.
