# Issue #354 — Feature request: support viewing of shared Live Share servers in the Live Preview embedded browser

[https://github.com/microsoft/vscode-livepreview/issues/354](https://github.com/microsoft/vscode-livepreview/issues/354)

## Summary

Live Share guests remain unable to activate Live Preview because current main still declares virtual workspaces unsupported. This is a valid, unresolved collaboration feature request, and no broader open issue or implementation currently owns it.

## Change summary

Allow Live Share participants to open a server shared by the session host in Live Preview's embedded preview.

## Best solution

Design a guest mode that obtains the host's shared or forwarded server URL through supported Live Share or VS Code APIs and opens it in VS Code's Integrated Browser without starting another server or reading the virtual workspace through Node filesystem APIs. Full virtual-workspace support would instead require broader URI-based filesystem changes and should be treated as a separate architectural option.

## Vision fit

- **Fit:** aligned
- **Reason:** Using VS Code platform facilities to make a host-provided preview available in a remote collaboration session fits the extension's server-and-preview purpose and its durable investment in remote environments.
- **Evidence:** The vision identifies remote and cloud environments as a durable theme and says the extension should build on core platform surfaces; this request is for integration with Live Share's shared-server capability rather than duplicating that capability.

## Evidence

- **unsupported on current main:** `package.json` still sets `capabilities.virtualWorkspaces` to `false`, so the extension remains disabled for a Live Share guest's virtual workspace.
- **local-filesystem assumptions:** Current implementation paths use local filesystem semantics: `src/server/serverUtils/contentLoader.ts` serves content through `fs.createReadStream` and `fs.statSync`, while `src/utils/pathUtil.ts`, `src/connectionInfo/connection.ts`, and preview management rely on `Uri.fsPath`. Enabling the full server in a virtual workspace is therefore not a manifest-only change.
- **existing browser setting is insufficient:** `livePreview.useIntegratedBrowser` changes which embedded browser displays a URL, but it does not override the virtual-workspace capability declaration or provide Live Share guests with the host's shared server URL.
- **canonical search:** The only other open virtual-workspace result, https://github.com/microsoft/vscode-livepreview/issues/716, is a later general support question with no Live Share shared-server requirements; it does not own this issue's specific remaining work.
