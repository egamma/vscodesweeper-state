# Issue #204 — Add ignore file for injected script

[https://github.com/microsoft/vscode-livepreview/issues/204](https://github.com/microsoft/vscode-livepreview/issues/204)

## Summary

This remains a valid server-configuration request: current main still injects the reload script into every extensionless filesystem file and provides no path-based injection or MIME override. The related issue #548 concerns which file changes trigger reloads, so it does not own this distinct response-transformation behavior.

## Change summary

Allow workspace paths such as extensionless mock API endpoints to opt out of script injection and optionally specify their response MIME type.

## Best solution

Add a resource-scoped path or glob mapping for injection and MIME overrides, then apply it consistently when serving files and when deciding whether navigation targets are injectable. The implementation likely belongs in `src/server/serverUtils/contentLoader.ts`, the shared injectability logic in `src/utils/utils.ts`, and the `livePreview.*` configuration surface in `package.json`.

## Evidence

- **current source behavior:** `src/utils/utils.ts:isFileInjectable` still returns true for every path without a file extension, while `src/server/serverUtils/contentLoader.ts:getFileStream` injects the reload script whenever that helper returns true.
- **no existing capability:** `package.json` exposes settings including `livePreview.autoRefreshPreview`, `livePreview.serverRoot`, and `livePreview.httpHeaders`, but no setting excludes paths from script injection or assigns per-path MIME types.
- **distinct related issue:** The open https://github.com/microsoft/vscode-livepreview/issues/548 requests exclusions from the workspace file watcher so unrelated edits do not reload previews. Shipping that request would not prevent `getFileStream` from modifying the extensionless response described here.
- **existing workaround is incomplete:** Marking an open document as plaintext avoids injection only while that document remains open; `getFileStream` resumes path-based injectability for filesystem files that are not open, and renaming the mock endpoint would change the URL being tested.
