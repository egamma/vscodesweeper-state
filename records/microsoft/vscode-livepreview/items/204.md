# Issue #204 — Add ignore file for injected script

[https://github.com/microsoft/vscode-livepreview/issues/204](https://github.com/microsoft/vscode-livepreview/issues/204)

## Summary

The requested path-based injection and MIME-type controls remain absent on current main, while extensionless files are still unconditionally treated as injectable. This is a valid, correctly classified server-configuration request in the On Deck holding milestone, with no canonical issue that owns the same work.

## Change summary

Allow workspace paths such as extensionless mock API endpoints to opt out of live-reload script injection and optionally specify their response MIME type.

## Best solution

Add a resource-scoped glob or path-mapping setting for injection exclusion and optional content-type overrides, then consult it when serving files in `src/server/serverUtils/contentLoader.ts` and when determining navigation injectability in `src/server/wsServer.ts`. Keep auto-refresh watcher exclusions separate because https://github.com/microsoft/vscode-livepreview/issues/548 addresses which file changes trigger reloads, not whether served responses are modified.

## Evidence

- **current injection behavior:** `src/utils/utils.ts:isFileInjectable` still returns true for every path without a file extension, and `src/server/serverUtils/contentLoader.ts:getFileStream` consequently reads those files and prepends the injected script.
- **existing settings do not cover request:** `package.json` contributes no injection-ignore or path-specific MIME setting. `livePreview.httpHeaders` only supplies response headers globally, and the documented `data-server-no-reload` body attribute disables refreshing for an HTML page rather than preventing response injection.
- **related issue is distinct:** https://github.com/microsoft/vscode-livepreview/issues/548 requests ignore patterns for the workspace file watcher in `src/updateListener.ts`; shipping it would not stop `getFileStream` from modifying extensionless responses, so it fails the remaining-work test for a canonical duplicate.
