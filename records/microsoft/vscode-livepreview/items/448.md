# Issue #448 — Allow query parameters in preview path setting

[https://github.com/microsoft/vscode-livepreview/issues/448](https://github.com/microsoft/vscode-livepreview/issues/448)

## Summary

This remains a valid, maintainer-acknowledged feature request: current main still converts `livePreview.defaultPreviewPath` and `livePreview.start.preview.atFileString` input into filesystem URIs, losing the distinction between a path and its query string. No other open issue found in the canonical search owns this remaining work.

## Change summary

Allow a preview target to include URL query parameters through the default preview setting or a command used to open the preview.

## Best solution

Add the maintainer-proposed address-oriented command, such as `livePreview.start.preview.atAddress`, and carry its path plus query through `src/manager.ts` and the preview-opening pipeline without treating the query as part of the filesystem path. The command should work for the normal Show Preview flow while retaining the existing path-only commands for compatibility.

## Vision fit

- **Fit:** aligned
- **Reason:** Opening a server-backed preview at a precise address fits the durable preview-opening and serving-correctness themes without expanding Live Preview into an application server or duplicating browser functionality.
- **Evidence:** The vision identifies both “Serving correctness” and “Where the preview opens” as durable themes, including correct URL construction and the embedded-versus-external preview surface.

## Evidence

- **maintainer acceptance:** A repository member explicitly called this a valid use case and proposed an address-oriented command analogous to `livePreview.start.preview.atFileString`; the issue is also assigned to the On Deck holding milestone.
- **current source gap:** `src/manager.ts` still passes `livePreview.defaultPreviewPath` to `openPreviewAtFileString`, which constructs the target using `vscode.Uri.joinPath`; `src/editorPreview/previewManager.ts::_fileUriToPath` then derives the served path from `file.fsPath`, with no preservation of `file.query`.
- **existing capability check:** `package.json` and `src/extension.ts` contribute and register `livePreview.start.preview.atFileString`, but no `atAddress` command exists. The existing command accepts a filesystem path rather than an address containing a query.
- **server query support:** `src/server/httpServer.ts` deliberately parses incoming request URLs with `vscode.Uri.parse` and preserves query strings during directory redirects, so the missing capability is in constructing and carrying the initial preview address rather than serving queried requests.
- **related implementation:** https://github.com/microsoft/vscode-livepreview/issues/388 delivered the path-string command referenced by the maintainer, but it is closed and covers absolute or relative filenames, not address/query input; it is therefore neither an open canonical nor complete coverage of this request.
