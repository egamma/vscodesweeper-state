# Issue #448 — Allow query parameters in preview path setting

[https://github.com/microsoft/vscode-livepreview/issues/448](https://github.com/microsoft/vscode-livepreview/issues/448)

## Summary

This remains a valid, unimplemented feature request: current main still interprets `livePreview.defaultPreviewPath` and `livePreview.start.preview.atFileString` exclusively as filesystem paths, discarding any query component before constructing the preview URL. The existing `feature-request` classification and On Deck milestone are appropriate.

## Change summary

Allow an initial preview target to include URL query parameters through `livePreview.defaultPreviewPath` and a string-address command usable by tasks or other extensions.

## Best solution

Add an address-aware path through `src/manager.ts` and `src/editorPreview/previewManager.ts` that resolves the filesystem portion for workspace/server selection while preserving the query string for embedded, Integrated Browser, external, and debug preview URLs. When using the Integrated Browser, merge the internal `vscode-livepreview=true` marker with the supplied parameters rather than appending a second `?`; a dedicated command such as the maintainer-suggested `livePreview.start.preview.atAddress` would avoid changing the filesystem-only contract of `atFileString`.

## Vision fit

- **Fit:** aligned
- **Reason:** Parameterized startup URLs extend the existing server-preview workflow without turning Live Preview into an application server or duplicating browser functionality.
- **Evidence:** The durable themes explicitly include serving correctness, `livePreview.defaultPreviewPath`, and where the preview opens; the README positions the product as a local server used to preview web projects.

## Evidence

- **maintainer acceptance:** A repository member explicitly called this a valid use case and suggested adding an address-taking command analogous to `livePreview.start.preview.atFileString`: https://github.com/microsoft/vscode-livepreview/issues/448#issuecomment-1426427631
- **current setting behavior:** On current main, `Manager.openPreview()` reads `livePreview.defaultPreviewPath` and passes it to `openPreviewAtFileString`; that method joins the entire value onto a workspace URI or tests it as a filesystem path (`src/manager.ts`). It has no parsing or preservation of URL query parameters.
- **query is discarded downstream:** `PreviewManager._fileUriToPath()` derives the served path from `file.fsPath` (`src/editorPreview/previewManager.ts`), so URI query data cannot reach the generated preview address. The Integrated Browser branch then unconditionally appends `?vscode-livepreview=true`, which would also need proper parameter merging.
- **existing capability is insufficient:** `package.json` still defines `livePreview.defaultPreviewPath` as a file path setting and contributes only `livePreview.start.preview.atFileString`; no address-oriented command exists. The referenced https://github.com/microsoft/vscode-livepreview/issues/388 implemented absolute/relative filename input, not URL query support.
- **canonical search:** Repository searches for query parameters, search params, preview addresses, and `atAddress` found no other open issue owning this request; the only matching open result was https://github.com/microsoft/vscode-livepreview/issues/448 itself.
