# Issue #149 — New feature request: select element 

[https://github.com/microsoft/vscode-livepreview/issues/149](https://github.com/microsoft/vscode-livepreview/issues/149)

## Summary

This remains the maintainer-designated canonical request for selecting or highlighting a preview element and revealing its HTML source in the editor. Current main can open webview DevTools but has no preview-to-source selection protocol, and the newer #391 is a narrower version of the same direction rather than a canonical that supersedes this issue.

## Change summary

Add element inspection that maps an element selected in the preview back to its HTML source and selects or reveals that source in the editor.

## Best solution

Define this integration for the default VS Code Integrated Browser path rather than adding substantial new functionality only to the legacy bundled webview. This likely requires an Integrated Browser inspection or selection API in microsoft/vscode plus extension-side URL/source mapping and editor reveal logic; retain #149 as the canonical request while that product and API boundary is decided.

## Vision fit

- **Fit:** rejected
- **Reason:** Growing an inspector inside the bundled preview conflicts with the direction of handing browser functionality to VS Code's Integrated Browser, although an integration built on a core API could still preserve the requested editor workflow.
- **Evidence:** The vision states that “the server is the product; the browser is increasingly VS Code's” and identifies the bundled webview browser as a fallback rather than the future.
