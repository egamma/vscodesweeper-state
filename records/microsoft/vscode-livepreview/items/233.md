# Issue #233 — watch files settings

[https://github.com/microsoft/vscode-livepreview/issues/233](https://github.com/microsoft/vscode-livepreview/issues/233)

## Summary

Configurable watch-file selection remains missing, and a maintainer explicitly accepted reconsidering the removed feature. Keep this request open: the existing refresh settings do not select files, and the related ignore-setting request is newer and does not cover its full scope.

## Change summary

Restore configurable file watching so users can select which file changes trigger preview refreshes rather than refreshing for unrelated changes.

## Best solution

Design file-selection semantics for the extension-owned UpdateListener, covering generated-file workflows without changing which files the HTTP server serves. Coordinate the overlapping exclusion request at https://github.com/microsoft/vscode-livepreview/issues/548 while retaining this older request's broader watch-file scope.

## Vision fit

- **Fit:** aligned
- **Reason:** Controlling which file changes trigger refresh directly improves the extension's core live-refresh capability for plain web projects and generated assets.
- **Evidence:** Layer 2 identifies live refresh, including which edits should trigger it, as a durable theme; layer 1 places the server and live refresh within the extension's own product boundary.

## Plan brief

- **Likely files:** `src/updateListener.ts`, `src/utils/settingsUtil.ts`, `package.json`, `package.nls.json`, `src/test/suite/`
- **Validation:** Add VS Code integration cases under src/test/suite/ and run them through npm test in an implementation workspace: selected generated-file changes trigger refresh, excluded unrelated changes do not, unset configuration preserves existing behavior, and configuration changes take effect. Include out-of-workspace coverage if that scope is accepted.
- **Behavior:**

  > Users should be able to control which file changes trigger Live Preview refreshes without disabling refresh altogether. Selected generated HTML/CSS updates should refresh the page, while unrelated changes outside the selected scope should not. Leaving the new configuration unset should preserve existing behavior. Acceptance must cover the agreed editor-change and saved-file modes and explicitly document whether externally generated files outside workspace folders are supported.
- **Trace:**

  > src/updateListener.ts owns refresh triggers: its constructor watches '**', subscribes separately to text-document changes, and fires shouldRefreshPreviews after debouncing. File-system callbacks currently apply refresh-mode and user-data checks but no configurable selection; _reloadIfOutOfWorkspace handles editor-originated events rather than arbitrary external writes. src/manager.ts consumes the event and refreshes preview groupings. package.json, package.nls.json, and src/utils/settingsUtil.ts expose refresh timing and modes but no file-selection configuration. The maintainer's removed-feature explanation is in https://github.com/microsoft/vscode-livepreview/issues/233, and https://github.com/microsoft/vscode-livepreview/issues/235#issuecomment-1344932048 establishes the external-generation limitation. Coordinate exclusion semantics with https://github.com/microsoft/vscode-livepreview/issues/548, which is related rather than a valid canonical here. Keep HTTP serving boundaries, script injection, and browser rendering unchanged; this work concerns refresh triggers only.
- **Open decisions:**
  - Should the public configuration support inclusion patterns, exclusion patterns, or both, and what selection applies when it is unset?
  - Should configurable watching support externally generated files outside workspace folders, or be limited to selecting workspace files?
  - Should file selection govern both editor-change and saved-file refresh modes, or only saved-file watching?
