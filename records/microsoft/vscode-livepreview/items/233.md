# Issue #233 — watch files settings

[https://github.com/microsoft/vscode-livepreview/issues/233](https://github.com/microsoft/vscode-livepreview/issues/233)

## Summary

The requested watch-file scope remains absent from current main, and a maintainer explicitly retained this as a feature request after removing the earlier implementation because of incorrect behavior with external watch scripts. The related ignore-setting request covers unwanted workspace reloads but would not fully restore positive watch globs or watching generated files outside the workspace.

## Change summary

Provide configurable file patterns that determine which file changes trigger Live Preview refreshes, including changes made by external build/watch scripts.

## Best solution

Add a well-defined include/exclude glob configuration to the update-listener path, covering workspace files and explicitly configured generated files without refreshing for unrelated changes. Coordinate the exclusion behavior with https://github.com/microsoft/vscode-livepreview/issues/548, while retaining this issue for the broader positive watch-scope and external-file requirements.

  > Thanks for the additional context. This remains a valid feature request: current Live Preview watches the workspace broadly and does not expose a `livePreview.watchFiles` or equivalent scope setting. https://github.com/microsoft/vscode-livepreview/issues/548 tracks the related request to ignore files that should not cause reloads, but this issue is broader because positive watch patterns are also relevant to generated files and external watch scripts. ## Evidence

- **maintainer intent:** A maintainer stated that the feature had been removed because it was buggy with external watch scripts and classified this issue as a feature request to potentially reimplement it better.
- **current source gap:** src/updateListener.ts constructs vscode.workspace.createFileSystemWatcher('**') and refreshes for matching create, change, and delete events; it has no configurable include or exclude pattern.
- **settings gap:** package.json contributes livePreview.autoRefreshPreview and livePreview.previewDebounceDelay, but no livePreview.watchFiles or equivalent scope setting; src/utils/settingsUtil.ts likewise exposes no watch-file configuration.
- **existing controls are insufficient:** livePreview.autoRefreshPreview controls when refreshes occur, while data-server-no-reload disables automatic reload for an entire page; neither selects which changed files should trigger a reload.
- **related but not duplicate:** https://github.com/microsoft/vscode-livepreview/issues/548 requests an ignore list for unrelated workspace changes. That would address the latest comment here but would not necessarily provide positive watch globs or cover externally generated out-of-workspace files, so it does not own this issue's full remaining work.
- **historical implementation:** https://github.com/microsoft/vscode-livepreview/pull/74 introduced livePreview.watchFiles, while https://github.com/microsoft/vscode-livepreview/issues/51 documents that its initial interaction with external Sass watch scripts refreshed too early; the later broad watcher implementation came through https://github.com/microsoft/vscode-livepreview/pull/309.
