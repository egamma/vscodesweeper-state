# Issue #431 — Show progress while external browser is starting

[https://github.com/microsoft/vscode-livepreview/issues/431](https://github.com/microsoft/vscode-livepreview/issues/431)

## Summary

The requested launch feedback is still absent on current main: external-preview commands start the server and dispatch the browser launch without creating any VS Code progress UI or waiting for the browser's first HTTP request. This is also a team-authored Backlog feature request, with no verified duplicate or implementing commit, so it should remain open.

## Change summary

Show progress in VS Code from invocation of an external-preview command until the launched browser requests the preview page.

## Best solution

Add bounded, cancellable progress around the external-preview launch flow, beginning in `src/server/serverGrouping.ts` or `src/manager.ts` and completing when `src/server/httpServer.ts` receives the matching initial page request. Include a timeout or other terminal condition so a failed browser launch cannot leave progress displayed indefinitely.

## Evidence

- **no progress lifecycle:** `src/utils/externalBrowserUtils.ts` only dispatches `vscode.env.openExternal` or `js-debug-companion.launch`, and the current `src/` tree contains no use of `vscode.window.withProgress` or `ProgressLocation`.
- **request observation:** `src/server/httpServer.ts` owns incoming HTTP request handling, but the external-preview launch path does not currently connect the first matching request to any user-visible progress state.
