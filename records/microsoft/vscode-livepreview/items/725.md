# Issue #725 — Add https server config

[https://github.com/microsoft/vscode-livepreview/issues/725](https://github.com/microsoft/vscode-livepreview/issues/725)

## Summary

HTTPS is not available through the current configuration or server implementation, and no open canonical issue owns this request. This is a valid but scope-expanding feature request that should remain open and be classified as `feature-request` for a maintainer decision.

## Change summary

Allow Live Preview's local server to use HTTPS with user-provided certificates and private keys.

## Best solution

If accepted, add an explicit opt-in TLS configuration with clear certificate/key validation and startup errors, then update the HTTP server, live-reload WebSocket, generated `https`/`wss` URLs, and remote URI handling together. Because certificate paths and trust behavior widen the server's security-sensitive configuration surface, the design needs maintainer review rather than an isolated server-factory change.

## Vision fit

- **Fit:** rejected
- **Reason:** HTTPS would move Live Preview toward a more general-purpose application-server surface, which the stated product guardrails identify as outside its current direction, although no maintainer decision establishes it as out of scope.
- **Evidence:** The public vision describes Live Preview as a server for plain projects without an existing application server and explicitly lists HTTPS among requests that push it toward becoming a general dev server and therefore require a maintainer scope decision.

## Evidence

- **capability absent:** `package.json` contributes settings for `livePreview.portNumber`, `livePreview.hostIP`, and `livePreview.httpHeaders`, but no HTTPS, certificate, or key setting; `src/utils/settingsUtil.ts` likewise contains no TLS configuration.
- **plain HTTP implementation:** `src/server/httpServer.ts` imports Node's `http` module and `_createServer()` unconditionally calls `http.createServer`; there is no `https.createServer` path or certificate loading.
- **cross-cutting protocol handling:** `src/connectionInfo/connection.ts` constructs local URIs with an `http://` scheme, while `src/server/wsServer.ts` creates a separate unsecured WebSocket server and `src/editorPreview/webviewComm.ts` constructs a `ws://` URL, so complete HTTPS support requires coordinated URL and live-reload changes.
- **canonical search:** The only other open certificate-related report found, https://github.com/microsoft/vscode-livepreview/issues/843, concerns a remote-tunnel 401 under corporate TLS interception; it has a distinct trigger and would not deliver configurable HTTPS serving for this issue.
