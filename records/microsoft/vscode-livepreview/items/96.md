# Issue #96 — Live Preview from remote container should "just work"

[https://github.com/microsoft/vscode-livepreview/issues/96](https://github.com/microsoft/vscode-livepreview/issues/96)

## Summary

This team-authored feature request remains necessary: Live Preview still relies on VS Code's automatic port forwarding without registering attributes that suppress its notification, while the required core API-finalization work remains open. The prior implementation was closed unmerged because it depended on the proposed API, so there is no factual basis for closing the protected issue.

## Change summary

Make Live Preview start transparently in remote containers without a port-forwarding notification that can open a redundant browser preview.

## Best solution

Once the port-attributes API is finalized in microsoft/vscode, register a provider for Live Preview's dynamically selected HTTP and WebSocket ports and mark their automatic forwarding as silent. The implementation belongs around the server port lifecycle in `src/server/`; core supplies the enabling API, but this repository must adopt it.
