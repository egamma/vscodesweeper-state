# Issue #96 — Live Preview from remote container should "just work"

[https://github.com/microsoft/vscode-livepreview/issues/96](https://github.com/microsoft/vscode-livepreview/issues/96)

## Summary

The unwanted port-forwarding notification remains unresolved: the linked implementation was closed without merging because it depended on a proposed VS Code API, and that API-finalization issue is still open. This team-authored Backlog item should remain open for the extension-side adoption work once the core capability is stable.

## Change summary

Suppress the automatic port-forwarding notification for Live Preview's HTTP and WebSocket ports so remote-container preview opens without inviting the user to create a redundant browser preview.

## Best solution

Once microsoft/vscode finalizes the port-attributes provider API, register Live Preview's dynamically selected HTTP and WebSocket ports for silent forwarding in the server lifecycle. The core issue enables that work but does not replace the required extension-side integration.
