# Issue #96 — Live Preview from remote container should "just work"

[https://github.com/microsoft/vscode-livepreview/issues/96](https://github.com/microsoft/vscode-livepreview/issues/96)

## Summary

Keep open: suppressing redundant port-forwarding notifications remains an extension-integration request with an explicitly documented core API dependency. The attempted implementation was closed without merging, and current source contains no port-attributes provider; the Integrated Browser default does not establish that this request is complete.

## Change summary

Starting Live Preview in a remote container should open the intended preview without a redundant forwarding notification whose Preview action opens another browser.

## Best solution

Coordinate with https://github.com/microsoft/vscode/issues/115616 on supported port-notification control, then integrate that capability with Live Preview's actual server ports while preserving forwarding and opening only the intended preview. The core API enables this work but does not own the remaining extension-side adoption.
