# Issue #862 — Embedded Live Preview Console Does Not Work

[https://github.com/microsoft/vscode-livepreview/issues/862](https://github.com/microsoft/vscode-livepreview/issues/862)

## Summary

The inactive Output channel is a leftover from the bundled preview and should not appear for the default Integrated Browser path. An open PR explicitly fixes this issue, so it must remain open while that implementation is reviewed.

## Change summary

Avoid showing the inactive Embedded Live Preview Console unless the legacy bundled preview is actually used.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/867, which lazily creates the console only for the legacy bundled preview and directs Integrated Browser users to Developer Tools while preserving the channel for `livePreview.useIntegratedBrowser: false`.

## Evidence

- **current source:** `src/editorPreview/previewManager.ts` currently creates `Embedded Live Preview Console` in the `PreviewManager` constructor before deciding whether `livePreview.useIntegratedBrowser` routes the preview to VS Code's Integrated Browser; therefore the inactive channel appears even when the legacy `BrowserPreview` is never created.
- **maintainer confirmation:** A repository member states that the Output channel is left over from the old preview experience and that Integrated Browser users should use Developer Tools.
- **open implementation PR:** https://github.com/microsoft/vscode-livepreview/pull/867 is open, explicitly says `Fixes #862`, moves output-channel creation to the legacy-preview path, updates the README guidance, and adds lifecycle regression tests.
- **existing fallback:** `package.json` defaults `livePreview.useIntegratedBrowser` to true, but `src/editorPreview/browserPreview.ts` still forwards console messages to the Output channel for users of the legacy preview, so the channel should be conditional rather than removed unconditionally.
