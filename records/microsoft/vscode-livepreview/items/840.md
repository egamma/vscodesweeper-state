# Issue #840 — Live Preview can generate malformed URLs for absolute links and workspace paths

[https://github.com/microsoft/vscode-livepreview/issues/840](https://github.com/microsoft/vscode-livepreview/issues/840)

## Summary

The current source contains the reported string-concatenation behavior, but no concrete product flow has been shown to supply either problematic input, and the reporter subsequently said the network-drive scenario no longer reproduces. The maintainer's request for product reproduction steps remains unanswered, so current-version steps and browser-path details are needed.

## Change summary

Prevent absolute HTTP(S) addresses from receiving a Live Preview host prefix and ensure workspace-relative preview paths retain a slash after the port.

## Best solution

First reproduce either malformed URL through the product on a current release, recording the exact network workspace path and whether `livePreview.useIntegratedBrowser` is enabled. If confirmed, normalize the workspace-relative path in `src/connectionInfo/connection.ts` and, for the bundled-browser case, distinguish absolute URLs in `src/editorPreview/webviewComm.ts`, with focused regression tests for the actual triggering flow.

- **product trigger unconfirmed:** The bundled preview normally receives paths from `PreviewManager._fileUriToPath`, while the default Integrated Browser path bypasses `WebviewComm.constructAddress`. The issue does not provide the concrete UI actions or link/navigation flow that caused an absolute URL to reach that method.
