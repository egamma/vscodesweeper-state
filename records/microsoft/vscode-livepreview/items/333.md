# Issue #333 — Allow setting host IP to 0.0.0.0

[https://github.com/microsoft/vscode-livepreview/issues/333](https://github.com/microsoft/vscode-livepreview/issues/333)

## Summary

Keep this open as a confirmed request to support wildcard binding while retaining a reachable client-facing address for HTTP and live-refresh WebSocket connections. A maintainer explicitly left the issue open for `0.0.0.0`, and current source still uses one host value for both server binding and generated client URLs.

## Change summary

Allow Live Preview to bind its HTTP and WebSocket servers to all network interfaces so external devices continue receiving live refresh without users selecting a particular LAN address.

## Best solution

Separate the server bind address from the advertised HTTP and WebSocket addresses in `src/connectionInfo/`: bind to `0.0.0.0`, but generate reachable client URLs and validate request origins using an appropriate external or request host. Because this exposes the server beyond loopback, the design should preserve the existing HTTP host/origin and WebSocket origin protections and be reviewed by a maintainer.

## Evidence

- **maintainer-confirmed gap:** A repository member stated that `0.0.0.0` was not supported and explicitly left https://github.com/microsoft/vscode-livepreview/issues/333 open for that capability; the reporter subsequently confirmed that a concrete `192.168.*.*` address works and narrowed the request to binding all interfaces.
- **current source:** `src/connectionInfo/connectionManager.ts` accepts IPv4 values through `net.isIPv4`, while `src/server/httpServer.ts` and `src/server/wsServer.ts` bind directly to `Connection.host`. `src/connectionInfo/connection.ts::constructLocalUri` also embeds that same host in the URI passed to `vscode.env.asExternalUri`, so there is no separate bind address and client-facing address.
- **live-refresh dependency:** `src/server/serverUtils/HTMLInjector.ts` injects the resolved HTTP and WebSocket authorities into every preview page, and `src/server/wsServer.ts` restricts WebSocket origins to the resolved external HTTP origin. Supporting a wildcard bind therefore requires choosing a reachable advertised host rather than merely accepting `0.0.0.0` as a setting.
- **no canonical duplicate:** The open candidates address distinct remaining work: https://github.com/microsoft/vscode-livepreview/issues/179 concerns IPv6 syntax and URL handling, while https://github.com/microsoft/vscode-livepreview/issues/462 concerns authentication through a remote tunnel. Neither would fully deliver wildcard local-interface binding for external devices.
- **existing-capability check:** `package.json` exposes `livePreview.hostIP` as a single string setting with default `127.0.0.1`; there is no separate setting or command for binding all interfaces while advertising a reachable LAN address.
