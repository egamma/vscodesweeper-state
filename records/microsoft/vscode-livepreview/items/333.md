# Issue #333 — Allow setting host IP to 0.0.0.0

[https://github.com/microsoft/vscode-livepreview/issues/333](https://github.com/microsoft/vscode-livepreview/issues/333)

## Summary

Keep open: the reporter confirmed that explicit LAN addresses work, leaving the maintainer-accepted request for wildcard binding across interfaces. Current source does not provide end-to-end wildcard-address support; non-loopback exposure also requires human review under the security-sensitive keep-open rule.

## Change summary

Support live preview and live refresh across available network interfaces with livePreview.hostIP set to 0.0.0.0, without repeatedly configuring a specific LAN address.

## Best solution

Define supported wildcard-binding behavior in src/connectionInfo/ and src/server/, distinguishing the server's listening address from client-reachable HTTP and WebSocket addresses while preserving request authorization. Treat tunnel authentication reports as related but separate work rather than making them the canonical for this request.

## Evidence

- **Scope clarified in discussion:** In https://github.com/microsoft/vscode-livepreview/issues/333, the maintainer explicitly left wildcard-address support open on 2022-12-12. On 2022-12-17, the reporter confirmed that a specific LAN IP works and clarified the remaining need: multiple interfaces and changing LAN addresses. This supports classifying the remaining ask as a feature request despite the existing bug label.
- **Existing capability does not cover the central ask:** package.json contributes.configuration exposes livePreview.hostIP with default 127.0.0.1, but no separate listening-address and advertised-client-address settings. ConnectionManager._validHost in src/connectionInfo/connectionManager.ts accepts IPv4 syntax, while Connection.constructLocalUri in src/connectionInfo/connection.ts directly reuses that configured host in HTTP and WebSocket URI construction. Accepting 0.0.0.0 as a setting is therefore not evidence of complete wildcard-interface support.
- **Client connectivity remains coupled to the configured host:** src/server/serverUtils/HTMLInjector.ts constructs one injected WebSocket URL from the connection's resolved wsURI. src/server/httpServer.ts checks request Host and Origin against the configured or resolved authority, and WSServerWithOriginCheck.shouldHandle in src/server/wsServer.ts checks the resolved HTTP origin. These paths do not establish support for clients reaching a wildcard-bound server through different LAN interface addresses.
- **Canonical search:** Repository searches for 0.0.0.0, host, and interface found no verified canonical owning the remaining wildcard-binding request. https://github.com/microsoft/vscode-livepreview/issues/179 is open and older, but concerns IPv6 rather than the same observable symptom. https://github.com/microsoft/vscode-livepreview/issues/631 concerns localhost URL naming, and https://github.com/microsoft/vscode-livepreview/issues/462 concerns remote-tunnel HTTP 401 responses; neither owns this request.
- **Related report is not a duplicate target:** https://github.com/microsoft/vscode-livepreview/issues/627 is closed and describes blank previews improved by changing ports. Its maintainer comments link this request as a possible related improvement, not as evidence that wildcard-interface support was implemented.
