# Issue #333 — Allow setting host IP to 0.0.0.0

[https://github.com/microsoft/vscode-livepreview/issues/333](https://github.com/microsoft/vscode-livepreview/issues/333)

## Summary

The original LAN-address concern was resolved by the reporter, leaving a confirmed request to support `0.0.0.0` so one server can listen on all available interfaces. A maintainer explicitly kept the issue open for that work, so it should remain open and be reclassified from bug to feature request.

## Change summary

Allow `livePreview.hostIP` to bind the server to `0.0.0.0` while preserving a usable browser and live-refresh address.

## Best solution

Add an explicit all-interfaces binding mode in the server and connection-info path: bind the HTTP/WebSocket servers to `0.0.0.0`, but derive an actual reachable host or forwarded URI for preview and reload URLs, and retain automatic selection of an available port. Treat the later tunnel 401 reports separately because authentication and VS Code port forwarding may have a different root cause.
