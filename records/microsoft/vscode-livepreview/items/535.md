# Issue #535 — External browser can't be found after renaming browser executable

[https://github.com/microsoft/vscode-livepreview/issues/535](https://github.com/microsoft/vscode-livepreview/issues/535)

## Summary

Keep open: the external-browser launch delegates to js-debug-companion, whose current source still reuses a persisted executable path without checking that it exists. The report already supplies concrete rename-and-launch steps; the Integrated Browser transition does not address this external-browser path.

## Change summary

External Firefox preview should recover when the application is renamed after its executable location has been cached.

## Best solution

Resolve stale executable discovery in microsoft/vscode-js-debug-companion so a moved browser is rediscovered rather than repeatedly launched from its old path. Live Preview already invokes that launch command, so the primary fix belongs in the companion; using the system-default browser is only a workaround.

This matches the reported rename-back trigger; no runtime reproduction was performed.
