# Issue #535 — External browser can't be found after renaming browser executable

[https://github.com/microsoft/vscode-livepreview/issues/535](https://github.com/microsoft/vscode-livepreview/issues/535)

## Summary

The failure remains present in the current browser-launch path: Live Preview delegates custom-browser launches to vscode-js-debug-companion, which persists the discovered executable path and does not invalidate it when spawning that path fails with ENOENT. Keep this open because no fixing commit or open canonical issue currently owns the report.

## Change summary

Re-discover a configured external browser after its executable is renamed instead of repeatedly launching a stale cached path.

## Best solution

Update `BrowserSpawner` in `microsoft/vscode-js-debug-companion` to validate a cached executable path before launch, or clear the cache and retry discovery after an ENOENT spawn failure. Live Preview can continue delegating through `js-debug-companion.launch`; an extension-side fallback would only mask the stale cache.
