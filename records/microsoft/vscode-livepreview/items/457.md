# Issue #457 — Injected script should be aware of whether it's inside webview or not

[https://github.com/microsoft/vscode-livepreview/issues/457](https://github.com/microsoft/vscode-livepreview/issues/457)

## Summary

The requested embedded-preview awareness remains incomplete on current main: the injected client avoids console overrides outside an iframe, but still performs WebSocket, navigation, link, keyboard, and reload setup without establishing that it is connected to a Live Preview panel. This team-authored debt item should remain open.

## Change summary

Initialize the injected client differently for embedded and ordinary browser contexts, including avoiding unnecessary browser setup and suppressing refreshes while the associated preview panel is not visible.

## Best solution

Add an explicit initialization or handshake between `media/injectScript.js` and the bundled preview in `src/editorPreview/`, then gate panel-specific listeners and behavior on that state. Coordinate the visibility-driven reload behavior with https://github.com/microsoft/vscode-livepreview/issues/454 without folding this broader initialization debt into that narrower bug.

## Evidence

- **partial context detection:** `media/injectScript.js` currently guards only the console overrides with `window.parent !== window`; `onLoad()` still unconditionally opens the WebSocket and installs link, hover, and keyboard listeners.
- **reload remains unconditional:** `media/injectScript.js` handles every WebSocket `reload` command by calling `reloadPage()`, which checks only the `data-server-no-reload` attribute and does not track whether an associated preview panel is visible.
- **server broadcasts to all clients:** `src/server/wsServer.ts` implements `refreshBrowsers()` by sending a reload command to every connected client, without embedded-panel identity or visibility state.
- **related issue is narrower:** The open https://github.com/microsoft/vscode-livepreview/issues/454 specifically tracks reloads while an internal preview is not visible; it does not cover this issue's broader request to avoid all unnecessary embedded-only initialization in ordinary browser windows.
