# Issue #843 — Live Preview 401 on remote tunnel with corporate MITM proxy: cert mismatch when host is 127.0.0.1

[https://github.com/microsoft/vscode-livepreview/issues/843](https://github.com/microsoft/vscode-livepreview/issues/843)

## Summary

The certificate-handling diagnosis points to VS Code's dev-tunnel or system proxy path rather than Live Preview: this extension serves plain HTTP on 127.0.0.1 and delegates creation of the forwarded HTTPS URL to `vscode.env.asExternalUri`. Keep this distinct from the extension-side Host-header problem in https://github.com/microsoft/vscode-livepreview/issues/462 unless server logs show that Live Preview itself generated the 401.

## Change summary

Make a Live Preview HTTP server reachable through a VS Code remote tunnel when a corporate TLS-intercepting proxy is active.

## Best solution

Determine which layer returns the 401 by comparing the browser trace with the `Live Preview` server-logging task. If no corresponding 401 reaches `src/server/httpServer.ts`, the end state belongs in microsoft/vscode's port-forwarding/dev-tunnel handling: its local HTTP connection must bypass interception or correctly handle the corporate trust configuration; Live Preview should not add a certificate-validation bypass for its plain-HTTP server.
