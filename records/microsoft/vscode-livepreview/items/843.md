# Issue #843 — Live Preview 401 on remote tunnel with corporate MITM proxy: cert mismatch when host is 127.0.0.1

[https://github.com/microsoft/vscode-livepreview/issues/843](https://github.com/microsoft/vscode-livepreview/issues/843)

## Summary

The reported certificate interception occurs in VS Code's tunnel or the corporate proxy path, not in Live Preview's plain-HTTP server, so an extension-side certificate-policy setting cannot address the stated root cause. Keep this security-sensitive report open while determining whether the 401 comes from tunnel ingress or Live Preview's separate Host/Origin validation.

## Change summary

Allow a Live Preview server bound to loopback to remain accessible through a VS Code remote tunnel when a corporate TLS-intercepting proxy is present.

## Best solution

Identify the component emitting the 401 from its response headers and the Live Preview server log. If tunnel ingress rejects the intercepted certificate, the correction belongs in microsoft/vscode's port-forwarding or tunnel integration; if Live Preview emits the response, consolidate the extension-side Host/Origin work with https://github.com/microsoft/vscode-livepreview/issues/462 without weakening certificate or origin validation.

## Evidence

- **separate extension-side 401 path:** src/server/httpServer.ts returns 401 when the incoming Host or Origin differs from the value produced by resolveExternalHTTPUri; that known tunnel problem remains tracked in https://github.com/microsoft/vscode-livepreview/issues/462.
