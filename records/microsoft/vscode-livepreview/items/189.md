# Issue #189 — Video not loading in Safari due to missing byte-range support

[https://github.com/microsoft/vscode-livepreview/issues/189](https://github.com/microsoft/vscode-livepreview/issues/189)

## Summary

The defect remains on current main: Live Preview advertises byte-range support but ignores the request's Range header, always streams the complete file with status 200, and never returns Content-Range. This prevents clients such as Safari from performing the partial requests required for reliable video playback.

## Change summary

Add HTTP byte-range request support so Safari can load and seek video served by Live Preview.

## Best solution

Implement validated single-range handling in src/server/httpServer.ts and the file-streaming path: parse Range safely, return 206 with Content-Range and the selected Content-Length, create a bounded file stream, and return 416 for invalid or unsatisfiable ranges. Add an integration test in src/test/suite/serverGrouping.test.ts covering partial media responses while preserving normal full-file responses.

## Evidence

- **range requests ignored:** In src/server/httpServer.ts:126-303, _serveStream never reads req.headers.range; successful files always receive status 200 and the complete stream is piped to the response.
- **full-file stream only:** In src/server/serverUtils/contentLoader.ts:298-347, non-injectable files use fs.createReadStream(readPath) without start/end bounds and report the full fs.statSync(readPath).size as ContentLength.
- **misleading advertised capability:** src/utils/constants.ts:40 sets the default Accept-Ranges response header to bytes, but no code produces a 206 Partial Content response or a Content-Range header.
- **no existing implementation owner:** Repository searches for "byte range" and "content range" found only https://github.com/microsoft/vscode-livepreview/issues/189 and no open implementing pull request or broader canonical issue; the cross-reference from https://github.com/microsoft/vscode-livepreview/issues/574 is unrelated CSS content.
- **existing capability is insufficient:** livePreview.httpHeaders can alter response headers, but adding Accept-Ranges cannot select a byte interval, produce a bounded stream, or change the response to 206, so it does not satisfy the request.
