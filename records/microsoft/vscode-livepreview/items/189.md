# Issue #189 — Video not loading in Safari due to missing byte-range support

[https://github.com/microsoft/vscode-livepreview/issues/189](https://github.com/microsoft/vscode-livepreview/issues/189)

## Summary

The defect remains present on current main: Live Preview advertises byte-range support but ignores the request's Range header, returns the entire file with status 200, and never sends Content-Range. This is a confirmed server-side correctness bug and should remain open.

## Change summary

Serve partial byte ranges for media files so browsers such as Safari can load and seek video from the Live Preview server.

## Best solution

Implement HTTP single-range handling in src/server/httpServer.ts and src/server/serverUtils/contentLoader.ts: validate the requested range, return 206 with Content-Range and the selected Content-Length, stream only that file segment, and return 416 for an unsatisfiable range. Add an integration-level server test covering valid, suffix, and invalid Range requests without changing HTML injection behavior.

## Evidence

- **full-file stream only:** In src/server/serverUtils/contentLoader.ts, getFileStream creates fs.createReadStream(readPath) without start/end offsets and sets ContentLength to the complete fs.statSync(readPath).size.
- **misleading advertised capability:** src/utils/constants.ts and package.json configure Accept-Ranges: bytes by default, but the server has no corresponding 206, Content-Range, range validation, or 416 implementation.
