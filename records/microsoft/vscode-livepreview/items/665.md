# Issue #665 — !doctype is case-sensitive

[https://github.com/microsoft/vscode-livepreview/issues/665](https://github.com/microsoft/vscode-livepreview/issues/665)

## Summary

The case-sensitivity defect remains on current main: the injection-point regex is case-sensitive, so a lowercase `<!doctype>` is not recognized and the reload script can be inserted before it, changing the document's parsing mode. This is a confirmed extension-side bug and should remain open.

## Change summary

Recognize lowercase and mixed-case HTML doctypes when choosing where to inject the Live Preview reload script.

## Best solution

Make the HTML insertion-point detection in `src/server/serverUtils/contentLoader.ts` case-insensitive while ensuring tags inside comments are not selected, and add focused tests covering lowercase and mixed-case doctypes. Coordinate the parser-level fix with https://github.com/microsoft/vscode-livepreview/issues/711, which exposes a distinct flaw in the same injection routine.

## Evidence

- **current source:** `src/server/serverUtils/contentLoader.ts` defines the fallback insertion tag as `!DOCTYPE`, then `_injectIntoFile` constructs `new RegExp(`<${tag}[^>]*>`, 'g')` without the case-insensitive flag. Consequently, lowercase or mixed-case doctypes do not match.
- **observable consequence:** When no earlier recognized `head`, `body`, or `html` tag is found, `_injectIntoFile` leaves `tagEnd` at 0 and prepends the injected script before the doctype. A doctype no longer at the beginning of the HTML document can alter standards/quirks-mode rendering, matching the reported visual difference.
- **related but distinct report:** https://github.com/microsoft/vscode-livepreview/issues/711 remains open and reports tags inside comments being selected by the same whole-document regex search. Its proposed parser-like scan would also recognize doctypes case-insensitively, but its trigger and required regression coverage are distinct, so it is not a safe duplicate canonical for this issue.
- **existing tests:** The HTML fixtures under `test-workspace/` use uppercase `<!DOCTYPE html>`; the checkout contains no regression case for lowercase or mixed-case doctypes.
