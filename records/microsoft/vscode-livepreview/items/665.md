# Issue #665 — !doctype is case-sensitive

[https://github.com/microsoft/vscode-livepreview/issues/665](https://github.com/microsoft/vscode-livepreview/issues/665)

## Summary

Current source confirms that live-reload script placement treats HTML tag names case-sensitively. The broader, better-diagnosed injection-placement issue https://github.com/microsoft/vscode-livepreview/issues/711 owns this defect and already has an open implementation that explicitly handles DOCTYPE case-insensitively, so this report can be consolidated into it.

## Change summary

Recognize lowercase and mixed-case HTML doctype declarations when choosing where to inject the live-reload script.

## Best solution

Track the robust HTML preamble and injection-position fix in https://github.com/microsoft/vscode-livepreview/issues/711 and review https://github.com/microsoft/vscode-livepreview/pull/746, ensuring the final tests include lowercase and mixed-case doctypes as evidence carried over from this report.

## Evidence

- **source-confirmed defect:** In src/server/serverUtils/contentLoader.ts, ContentLoader._insertionTags contains `!DOCTYPE`, and _injectIntoFile constructs each search expression with only the `g` flag. Consequently `<!doctype html>` does not match the fallback doctype expression, causing the injected script to be placed before the declaration when no earlier lowercase head/body/html tag is found.
- **canonical issue:** The open issue https://github.com/microsoft/vscode-livepreview/issues/711 tracks unreliable live-reload script placement in the same _injectIntoFile implementation. Its diagnosis proposes scanning the HTML preamble and matching the doctype case-insensitively.
- **same remaining work:** The open implementation https://github.com/microsoft/vscode-livepreview/pull/746 replaces the same insertion loop with an ordered preamble scan and uses `<!DOCTYPE\s[^>]*>` with the `i` flag. Landing that work would fully address this report without a separate code path.
