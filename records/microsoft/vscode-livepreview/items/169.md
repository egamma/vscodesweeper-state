# Issue #169 — Add some of the capabilities from Brackets

[https://github.com/microsoft/vscode-livepreview/issues/169](https://github.com/microsoft/vscode-livepreview/issues/169)

## Summary

This team-authored Backlog item is an umbrella for several distinct Brackets-style capabilities and must remain open. Maintainers split live highlighting and editor-preview navigation into separate open issues, while current main still performs full-page reloads rather than Brackets-style CSS hot replacement.

## Change summary

Add coordinated browser-editor features such as selector highlighting, navigation from preview elements to source, follow-along scrolling, and CSS updates without a full page reload.

## Best solution

Use https://github.com/microsoft/vscode-livepreview/issues/149 for selector highlighting and https://github.com/microsoft/vscode-livepreview/issues/214 for preview-to-source navigation and follow-along behavior, while retaining this umbrella until the remaining CSS hot-update scope receives a product decision or its own canonical issue. Any new browser-editor integration should build on VS Code's Integrated Browser rather than expanding the bundled fallback browser, with extension-side work limited to the server and coordination protocol.

## Vision fit

- **Fit:** unclear
- **Reason:** CSS hot updating advances the durable live-refresh theme, but growing browser-side highlighting and source navigation inside the bundled preview conflicts with the direction of handing embedded-browser capabilities to VS Code core.
- **Evidence:** The vision identifies “Live refresh” as a durable theme while stating that “The server is the product; the browser is increasingly VS Code's” and that the bundled webview is a fallback rather than the future.
