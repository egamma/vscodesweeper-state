# Issue #214 — Follow along scroll?

[https://github.com/microsoft/vscode-livepreview/issues/214](https://github.com/microsoft/vscode-livepreview/issues/214)

## Summary

Keep this open as the maintainer-selected canonical request for synchronized scrolling and preview-to-editor selection. Current main has no setting or implementation for either capability, while maintainers have repeatedly closed newer reports as duplicates of this issue.

## Change summary

Synchronize scrolling and text or element selection between the HTML editor and its live preview.

## Best solution

Retain this issue as the canonical product request and first determine an architecture that works with the default Integrated Browser, rather than adding a feature only to the legacy bundled webview. The likely extension-side work would coordinate editor reveal and selection with page events from the injected client; if the Integrated Browser does not expose the necessary integration, the missing platform capability should be tracked in microsoft/vscode while this issue continues to own adoption in Live Preview.

## Vision fit

- **Fit:** unclear
- **Reason:** Editor-to-preview synchronization could improve the preview workflow, but implementing it by expanding the bundled browser would conflict with the direction toward VS Code's Integrated Browser, whose available integration surface is not established here.
- **Evidence:** The vision says that "the server is the product; the browser is increasingly VS Code's" and identifies convergence on the Integrated Browser as a current direction, while still treating where the preview opens as a durable theme.
