# Issue #214 — Follow along scroll?

[https://github.com/microsoft/vscode-livepreview/issues/214](https://github.com/microsoft/vscode-livepreview/issues/214)

## Summary

Keep this as the canonical request for synchronized source/preview scrolling and selection. Current settings do not provide it, and maintainers explicitly directed the broader Brackets discussion and three later reports here.

## Change summary

Synchronize HTML editor scrolling and text selection with the corresponding content in the rendered preview.

## Best solution

Retain this issue as the follow-along synchronization tracker and establish an integration design compatible with VS Code's Integrated Browser rather than expanding only the bundled browser. This requires source-to-rendered-content correspondence and extension-side editor integration; changing the preview browser alone does not deliver the request.

## Vision fit

- **Fit:** aligned
- **Reason:** Connecting source edits to their rendered result improves the preview workflow, provided the design builds on the Integrated Browser rather than creating a competing browser surface.
- **Evidence:** Layer 1 describes a server-plus-preview product and the guardrail 'Build on core platform surfaces'; layer 2 identifies preview integration as a durable theme.

## Evidence

- **Existing-capability check:** Read all contributes.commands and contributes.configuration entries in package.json and their package.nls.json descriptions. livePreview.autoRefreshPreview and livePreview.previewDebounceDelay control reload timing, not editor-to-preview scrolling or selection; livePreview.useIntegratedBrowser selects the browser, not synchronization. No contributed command provides the requested behavior.
- **Current source boundary:** src/editorPreview/previewManager.ts, PreviewManager.launchFileInEmbeddedPreview, hands the Integrated Browser a URL, openToSide and reuseUrlFilter, without source positions or selection information. media/injectScript.js handles reloads, navigation, console forwarding, keyboard events and find, but contains no source-to-DOM synchronization. Searching src/ and media/ found no editor visible-range or selection-change subscriptions implementing follow-along behavior.
- **Older umbrella explicitly delegates this work:** https://github.com/microsoft/vscode-livepreview/issues/169 is open and older, but its body requests several Brackets capabilities rather than this same scrolling behavior. The maintainer explicitly states 'Follow-along scroll tracked in #214' at https://github.com/microsoft/vscode-livepreview/issues/169#issuecomment-1344899393, so it is not a duplicate canonical for this re-reviewed item.
- **Verified canonical direction:** Maintainers closed later synchronization requests in favor of this issue: https://github.com/microsoft/vscode-livepreview/issues/593#issuecomment-1892883822, https://github.com/microsoft/vscode-livepreview/issues/629#issuecomment-2070297182 and https://github.com/microsoft/vscode-livepreview/issues/642#issuecomment-2166957227. These are evidence that this issue owns the work, not alternative duplicate targets.
- **Related but narrower work:** https://github.com/microsoft/vscode-livepreview/issues/149 remains open and requests selecting HTML source through an element-inspection interaction. It does not cover follow-along scrolling, and the maintainer distinguishes highlighting from scrolling in https://github.com/microsoft/vscode-livepreview/issues/169#issuecomment-1199815098.

That describes a different extension, not an existing Live Preview setting or a fix in this repository.
