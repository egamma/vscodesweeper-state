## Summary

The stale-content symptom and unregistering workaround are useful, but the report lacks a reproducible service-worker setup and identifies neither the browser nor the affected versions. Ask for those details before attributing this to the extension's server, browser-managed state, or VS Code core.

## Change summary

Previewed resources show previously cached service-worker content instead of the current project's files until the worker is manually unregistered.

## Best solution

Establish the worker's registration scope, the reused preview URL, and whether a direct HTTP request returns current content while the preview remains stale. That comparison determines whether work belongs in the extension's serving or preview integration, VS Code's Integrated Browser, or guidance about project-owned service workers; do not automatically unregister project workers without establishing the intended behavior.
