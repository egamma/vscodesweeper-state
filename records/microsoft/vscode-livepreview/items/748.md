# Issue #748 — Preview Server Serves Stale Content from Service Worker Cache

[https://github.com/microsoft/vscode-livepreview/issues/748](https://github.com/microsoft/vscode-livepreview/issues/748)

## Summary

This matches a documented historical problem where a service worker registered by one preview controlled later content on the same origin, but neither report confirms the behavior on a current Live Preview and VS Code version. The default embedded-preview implementation has since changed to VS Code's Integrated Browser, so a current retest and identification of the active browser are needed before deciding whether work remains here or in VS Code core.

## Change summary

Prevent a service worker registered during an earlier preview from returning stale cached resources for a later file or workspace using the same preview origin.

## Best solution

Reproduce the same cross-file or cross-workspace sequence with the current default Integrated Browser and separately with `livePreview.useIntegratedBrowser: false`. If it remains limited to the bundled browser, decide whether `src/editorPreview/` should expose a cache-clearing reload or isolate preview origins; if it occurs only in the Integrated Browser, the browser lifecycle and service-worker handling belong in `microsoft/vscode` under `browser-integration`.
