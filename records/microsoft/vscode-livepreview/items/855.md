# Issue #855 — Live Preview generates incorrect directory index URLs using encoded backslashes (%5Cfolder%5Cpath)

[https://github.com/microsoft/vscode-livepreview/issues/855](https://github.com/microsoft/vscode-livepreview/issues/855)

## Summary

Current source conclusively reproduces the Windows URL-separator defect. Keep the issue open because the directly linked fix, https://github.com/microsoft/vscode-livepreview/pull/856, is still under review.

## Change summary

Generate directory-index hrefs with URL-style forward slashes instead of native Windows path separators that become `%5C` after encoding.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/856, which changes only the URL-path join to `path.posix.join` while preserving native joining for filesystem paths. Ensure its regression coverage fails against the old implementation on Windows or through an equivalent cross-platform simulation before merging.

## Evidence

- **source-confirmed defect:** In `src/server/serverUtils/contentLoader.ts`, `createIndexPage` currently computes `relativeFileWithChild` with `path.join(relativePath, childFile)` and then passes it to `encodeURI`. On Windows, joining `/apps` and `folder` produces a backslash-separated path, which encoding turns into the reported `%5Capps%5Cfolder` href.
- **filesystem and URL paths conflated:** The adjacent `absolutePath = path.join(readPath, childFile)` correctly represents a native filesystem path, but `relativeFileWithChild` is emitted into an HTML href and therefore requires POSIX URL separators.
- **open fixing PR:** https://github.com/microsoft/vscode-livepreview/pull/856 explicitly references and closes this issue, changes `relativeFileWithChild` to use `path.posix.join`, leaves the filesystem join unchanged, and adds `src/test/suite/contentLoader.test.ts`. Because the PR remains open, the issue must remain open.
- **corroborating reports:** The reporter identified the same Windows directory-index symptom in the still-open https://github.com/microsoft/vscode-livepreview/issues/762 and https://github.com/microsoft/vscode-livepreview/issues/795; the linked PR also identifies these as sharing the same root cause.
