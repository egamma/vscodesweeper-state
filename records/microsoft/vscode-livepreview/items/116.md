# Issue #116 — Responsive Layouts - Like Devices (sm, md, lg, xl) & Viewport dimensions

[https://github.com/microsoft/vscode-livepreview/issues/116](https://github.com/microsoft/vscode-livepreview/issues/116)

## Summary

This remains a valid responsive-design request, but embedded previews now use VS Code's Integrated Browser by default, making viewport emulation and dimension display core browser capabilities rather than extension-owned UI. Keep the issue open for maintainer routing; the newer related request is narrower and does not supersede this canonical issue.

## Change summary

Add responsive viewport presets and show the embedded preview's current viewport dimensions without requiring DevTools.

## Best solution

VS Code's Integrated Browser should provide the viewport-emulation UI, including configurable breakpoint or device presets and visible dimensions; microsoft/vscode#326713 already tracks custom presets but does not clearly cover the always-visible dimension indicator. The extension should continue handing its served URL to the Integrated Browser rather than duplicating browser tooling in `src/editorPreview/`.

## Vision fit

- **Fit:** rejected
- **Reason:** Growing the extension's bundled browser with responsive-development tooling conflicts with the direction of handing embedded browser capabilities to VS Code core.
- **Evidence:** The vision states that "the server is the product; the browser is increasingly VS Code's" and identifies convergence on the Integrated Browser as the current direction.
