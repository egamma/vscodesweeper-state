# Issue #795 — The folder link is incorrect in Windows 11

[https://github.com/microsoft/vscode-livepreview/issues/795](https://github.com/microsoft/vscode-livepreview/issues/795)

## Summary

Windows directory-index links still use native backslashes in the current source, producing incorrectly encoded URLs instead of working nested-folder links. Keep this open while the explicitly linked implementation candidate is reviewed; it has not merged.

## Change summary

Generated directory-index links should open the correct nested folder on Windows rather than return a 404.

## Best solution

Review https://github.com/microsoft/vscode-livepreview/pull/856 against the reported nested-folder URL and the related Windows reports. Directory-index hrefs should use URL separators on every platform while filesystem lookup and server-root containment retain their existing behavior.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode-livepreview/issues/795 reports that following a second-level folder link on Windows 11 returns 404; the intended destination is http://127.0.0.1:3000/cmake-build-wasm/webassembly.
- **Current-source defect:** src/server/httpServer.ts passes the decoded request URLPathName to ContentLoader.createIndexPage. In src/server/serverUtils/contentLoader.ts:208-227, createIndexPage uses native path.join(relativePath, childFile) to construct hrefs, then encodeURI; on Windows this produces percent-encoded backslashes instead of URL separators. Lines 237-244 append a slash but do not correct those separators. This is server-generated markup, independent of which browser displays it.
- **Open implementation candidate:** https://github.com/microsoft/vscode-livepreview/pull/856 is verified open and unmerged. Its body explicitly identifies this issue as sharing the root cause; its diff replaces the href-building path.join with path.posix.join, preserves the filesystem join, and proposes a directory-index regression test. The open linked PR requires keeping this issue open.
- **Related reports and duplicate limits:** https://github.com/microsoft/vscode-livepreview/issues/855 is open and documents encoded-backslash directory-index links on Windows 11, but was created on 2026-08-22, after this issue, so it cannot be the canonical for this re-reviewed item. https://github.com/microsoft/vscode-livepreview/issues/762 is older and open, reporting %5C-corrupted paths, but also mentions a separate Mobile Live Preview extension; its text alone does not conclusively establish the same directory-index trigger.
