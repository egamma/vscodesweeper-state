# Issue #795 — The folder link is incorrect in Windows 11

[https://github.com/microsoft/vscode-livepreview/issues/795](https://github.com/microsoft/vscode-livepreview/issues/795)

## Summary

The broken second-level directory links are reproducible from current source: directory-index URLs are built with the platform-dependent `path.join`, producing backslashes that `encodeURI` turns into `%5C` on Windows. Keep the issue open because https://github.com/microsoft/vscode-livepreview/pull/856 is an open fix that explicitly references this report.

## Change summary

Generate valid forward-slash URLs for nested folders in directory index pages on Windows.

## Best solution

Review and land https://github.com/microsoft/vscode-livepreview/pull/856, which changes the URL-path join in `ContentLoader.createIndexPage` to `path.posix.join` while preserving native `path.join` for the filesystem path, and adds a directory-link regression test.

## Evidence

- **current source defect:** `src/server/serverUtils/contentLoader.ts` lines 209-220 build `relativeFileWithChild` with `path.join(relativePath, childFile)` and then pass it to `encodeURI`. On Windows, the native join inserts backslashes into this URL path, which are encoded as `%5C` and produce the reported invalid link.
- **confirmed issue cluster:** The newer, detailed report https://github.com/microsoft/vscode-livepreview/issues/855 reproduces the same directory-index failure on Windows 11, including `%5C` separators and duplicated path segments, and explicitly identifies this issue as the same problem.
- **open fixing PR:** https://github.com/microsoft/vscode-livepreview/pull/856 explicitly references issues 855, 762, and 795. Its diff changes only the URL join to `path.posix.join`, leaves the filesystem join native, and adds `src/test/suite/contentLoader.test.ts` coverage asserting forward-slash links without `%5C`; the PR remains open.
