# Issue #325 — Add option to hide the address bar

[https://github.com/microsoft/vscode-livepreview/issues/325](https://github.com/microsoft/vscode-livepreview/issues/325)

## Summary

The bundled preview still renders an unconditional URL input and offers no setting to hide it, so the requested capability remains unimplemented. The issue is correctly classified as a feature request, but it now applies only to the legacy bundled browser and needs a maintainer scope decision rather than a judgment close.

## Change summary

Add a boolean option that hides the bundled embedded preview's address bar to provide more page space.

## Best solution

Decide whether customization of the fallback browser remains supported; if so, add a narrowly scoped `livePreview.*` setting and conditionally hide the URL input in `src/editorPreview/webviewComm.ts` without removing navigation controls. The default Integrated Browser's chrome belongs to `microsoft/vscode` and should not be customized from this extension.

## Vision fit

- **Fit:** rejected
- **Reason:** The request expands the bundled webview browser, while the current direction is to use VS Code's Integrated Browser and retain the bundled implementation only as a fallback.
- **Evidence:** The vision guardrail states that the server is the product and the browser is increasingly VS Code's; current `package.json` defaults `livePreview.useIntegratedBrowser` to true.

## Evidence

- **capability absent:** `package.json` defines `livePreview.openPreviewTarget` and `livePreview.useIntegratedBrowser` but has no setting controlling address-bar visibility.
- **current bundled UI:** `src/editorPreview/webviewComm.ts` unconditionally emits the bundled preview header and `<input id="url-input" class="url-input">`; `media/vscode.css` makes `.url-input` consume the remaining toolbar width.
- **default preview path:** `src/editorPreview/previewManager.ts` delegates embedded previews to the Integrated Browser whenever `SettingUtil.shouldUseIntegratedBrowser()` is true, and `livePreview.useIntegratedBrowser` currently defaults to true. The requested extension-side option therefore affects only users who opt into the bundled browser.
- **canonical search:** The only other open address-bar issue found, https://github.com/microsoft/vscode-livepreview/issues/114, requests predictive URL suggestions rather than hiding the address bar; implementing it would not satisfy this request.
