## Evidence

- **historical symptom:** The original reporter said the issue began suddenly and later resolved without an intentional change. A second reporter confirmed on VS Code 1.84.2 and Live Preview 0.4.11 that the server was running on port 3000 and reachable externally while every internal Show Preview action silently failed; a third reporter reported the same internal-only symptom on NixOS in October 2025.
- **current browser ambiguity:** Current `src/editorPreview/previewManager.ts` has two distinct internal-preview paths: with `livePreview.useIntegratedBrowser` enabled it executes VS Code's Integrated Browser command, while disabling it creates this extension's `BrowserPreview` webview. `package.json` and `src/utils/settingsUtil.ts` now default this setting to true, so the historical reports do not identify the code path used by the current default.
- **server launch path:** `src/server/serverGrouping.ts` records a pending embedded launch before starting the server and fires `onShouldLaunchEmbeddedPreview` after the connection reports success. The report that 127.0.0.1:3000 worked externally indicates a different failure from the occupied-port case tracked at https://github.com/microsoft/vscode-livepreview/issues/815.
- **missing current diagnostics:** No commenter has supplied an exact current VS Code and extension version, the value of `livePreview.useIntegratedBrowser`, a comparison with that setting toggled, or an error from Developer Tools for the latest occurrence.
