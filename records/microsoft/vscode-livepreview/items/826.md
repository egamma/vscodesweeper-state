# Issue #826 — Clarify in the README how this relates to the new built-in feature to preview HTML files

[https://github.com/microsoft/vscode-livepreview/issues/826](https://github.com/microsoft/vscode-livepreview/issues/826)

## Summary

The README now links to VS Code's Integrated Browser, but it still does not directly explain when users should choose the built-in HTML preview versus Live Preview's server-backed workflow. This remains a valid product-positioning discussion rather than a completed documentation request.

## Change summary

Clarify Live Preview's value beyond VS Code's built-in HTML preview and decide whether the extension should remain positioned as a distinct server-based tool.

## Best solution

Add a short comparison near the README introduction explaining that the built-in feature covers simple HTML viewing, while Live Preview provides a local HTTP server, live refresh, server-root and relative-link handling, directory serving, external-browser debugging, logging, and multi-root or workspace-less workflows. Maintainers should separately decide whether the overlap warrants deprecation; the open remote-workspace limitation in VS Code's Integrated Browser argues against assuming complete replacement today.

## Vision fit

- **Fit:** aligned
- **Reason:** Clarifying the distinction reinforces the stated direction that the server is Live Preview's product while browser rendering increasingly belongs to VS Code core.
- **Evidence:** The README describes Live Preview as "An extension that hosts a local server for you to preview your web projects on!", while the durable themes identify live refresh, serving correctness, server lifecycle, external-browser debugging, and remote environments as its differentiating responsibilities.
