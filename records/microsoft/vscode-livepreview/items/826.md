# Issue #826 — Clarify in the README how this relates to the new built-in feature to preview HTML files

[https://github.com/microsoft/vscode-livepreview/issues/826](https://github.com/microsoft/vscode-livepreview/issues/826)

## Summary

The README describes the extension's server features and links to the Integrated Browser, but still does not explain when to choose Live Preview over built-in HTML previewing. Keep this documentation and positioning request open; neither the related documentation issues nor the linked core remote-support issue owns that work.

## Change summary

Explain Live Preview's added value over built-in HTML previewing and clarify whether users should continue installing it.

## Best solution

Add explicit README guidance distinguishing built-in HTML viewing from Live Preview's local HTTP server, live refresh, configurable server root, logging, and external-browser debugging, while explaining that the extension can itself use the Integrated Browser. Any recommendation to deprecate the extension needs a maintainer product decision rather than an inference from overlapping preview commands.

## Evidence

- **Documentation gap remains:** README.md opens with the local-server description and links to the Integrated Browser for projects that already have a server. Its feature sections describe live refresh, server logging, external debugging, and multi-root support, but neither the introduction nor FAQ compares Live Preview with built-in HTML file previewing or answers the installation/deprecation question.
- **Existing-capability check:** package.json contributes.configuration and package.nls.json expose livePreview.useIntegratedBrowser, livePreview.autoRefreshPreview, livePreview.serverRoot, and external-browser settings; contributes.commands includes livePreview.runServerLoggingTask and external-debug preview commands. These establish concrete material for the requested comparison, but settings and commands do not supply the missing README guidance.
- **Browser integration boundary:** src/editorPreview/previewManager.ts:launchFileInEmbeddedPreview constructs an HTTP URL for an already-started server and passes it to INTEGRATED_BROWSER_COMMAND. src/utils/settingsUtil.ts:shouldUseIntegratedBrowser checks the setting and command availability, and package.json defaults livePreview.useIntegratedBrowser to true. Live Preview's server and VS Code's browser are therefore complementary, not mutually exclusive.
