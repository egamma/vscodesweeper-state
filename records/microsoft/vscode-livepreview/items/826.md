# Issue #826 — Clarify in the README how this relates to the new built-in feature to preview HTML files

[https://github.com/microsoft/vscode-livepreview/issues/826](https://github.com/microsoft/vscode-livepreview/issues/826)

## Summary

A real documentation and product-positioning gap remains: the README mentions the Integrated Browser but does not directly compare VS Code's built-in static-file preview with Live Preview's server, live-refresh, remote, external-browser, and debugging capabilities. Whether the overlap warrants deprecation is a maintainer product decision, so the issue should remain open for discussion.

## Change summary

Clarify when users should choose Live Preview instead of VS Code's built-in HTML preview and decide whether the extension should remain supported.

## Best solution

Add a short comparison near the top of README.md explaining that the built-in feature covers straightforward HTML viewing while Live Preview supplies a local server, live refresh, server-root behavior, external-browser debugging, logging, and remote-oriented workflows. Maintainers should separately decide the extension's long-term status rather than implying deprecation solely from the overlapping static-file workflow.

## Vision fit

- **Fit:** aligned
- **Reason:** Clarifying the boundary between the extension's server value and VS Code's browser surface supports the stated direction of keeping the server as the product while building on the Integrated Browser.
