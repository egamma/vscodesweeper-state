# Issue #702 — Javascript injected in non-html/javascript files

[https://github.com/microsoft/vscode-livepreview/issues/702](https://github.com/microsoft/vscode-livepreview/issues/702)

## Summary

The extension still injects its reload script into extensionless files served from disk, corrupting JSON responses. The older, open issue https://github.com/microsoft/vscode-livepreview/issues/204 reports this exact symptom and owns the same work.

## Change summary

Prevent HTML script injection from invalidating JSON served from files without a .json extension.

## Best solution

Consolidate this report into https://github.com/microsoft/vscode-livepreview/issues/204, retaining the requirement that extensionless JSON responses remain intact. That issue already documents the same serving path and response corruption, not merely a related live-refresh preference.

## Evidence

- **Verified older canonical with identical symptom:** https://github.com/microsoft/vscode-livepreview/issues/204 is currently open and was created on 2022-02-25, before this report. Its body describes fetching JSON from an extensionless file at /api/sensors/foo/airPressure and receiving a script element prepended to 1.653. This matches the observable corruption reported here and satisfies the stronger duplicate bar for a re-reviewed item.
- **Current source confirms the reported trigger:** src/utils/utils.ts:50-56, isFileInjectable(), returns true for a filename without an extension. In src/server/serverUtils/contentLoader.ts:327-333, getFileStream() applies _injectIntoFile() to such files when no matching editor document is open. _injectIntoFile() inserts the reload script at the beginning when no HTML insertion tag exists, making an otherwise valid JSON response invalid.
- **Response transformation, not on-disk data loss:** ContentLoader.getFileStream() builds an injected response buffer and returns it to src/server/httpServer.ts for streaming; this path does not overwrite the source file. MIME lookup falls back to text/plain, but injection eligibility is decided separately by the filename.
- **Canonical owns the remaining work:** https://github.com/microsoft/vscode-livepreview/issues/204 explicitly seeks to preserve extensionless JSON responses without changing request URLs or keeping files open in the editor. Addressing that reported behavior would fully satisfy this issue; this report adds no distinct trigger or separate required behavior.
