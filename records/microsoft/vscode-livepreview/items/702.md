# Issue #702 — Javascript injected in non-html/javascript files

[https://github.com/microsoft/vscode-livepreview/issues/702](https://github.com/microsoft/vscode-livepreview/issues/702)

## Summary

Current source confirms that every extensionless filesystem file is treated as injectable, so an extensionless JSON response is modified with the live-reload script while still being served as text/plain. This is a real, currently unfixed server correctness defect and should remain open as a bug.

## Change summary

Do not inject the Live Preview client script into extensionless files that contain non-HTML content, such as JSON API responses.

## Best solution

Change the server's injectability decision so the absence of a filename extension alone does not cause non-HTML content to be modified, while retaining support for genuinely extensionless HTML routes. The configurable exclusion and MIME mapping proposed in https://github.com/microsoft/vscode-livepreview/issues/204 may be a useful implementation vehicle, but it is not a duplicate because requiring users to configure every affected endpoint would not automatically correct this behavior.

- **corrupting path:** src/server/serverUtils/contentLoader.ts:304-335 assigns an unknown extensionless file the fallback Content-Type `text/plain`, then calls _injectIntoFile() whenever isFileInjectable(readPath) is true; _injectIntoFile() prepends the script when no HTML insertion tag is found.
