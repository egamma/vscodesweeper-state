# Issue #5949 — Show files with conflicts next to resolve conflicts

[https://github.com/microsoft/vscode-pull-request-github/issues/5949](https://github.com/microsoft/vscode-pull-request-github/issues/5949)

## Summary

The gap remains on main: the merge-status card shows only a generic conflict message, while determining filenames requires an expensive GitHub comparison request. Keep this upstream-dependent feature routed to the review and description-page areas.

## Change summary

Show the names or count of conflicting files beside the Resolve conflicts action so users can assess the work before starting.

## Best solution

Expose conflict filenames through an efficient GitHub API and display them in the merge-status section of the PR description page. Until then, avoid eagerly running the extension's expensive and incomplete comparison path merely to populate the preview.

## Vision fit

- **Fit:** aligned
- **Reason:** Giving users conflict details before entering resolution improves the extension's native in-editor review workflow.
- **Evidence:** The durable vision themes explicitly include the review flow and PR lifecycle accuracy, while the product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code."
