# Issue #6799 — Deleting a branch auto-closes any PRs targeting the deleted branch

[https://github.com/microsoft/vscode-pull-request-github/issues/6799](https://github.com/microsoft/vscode-pull-request-github/issues/6799)

## Summary

A real gap remains for stacked pull requests: the extension deletes the remote ref directly, unlike GitHub.com's richer branch-deletion flow, so dependent PRs are closed instead of retargeted. The accepted On Deck request should remain open and route to the GitHub integration area.

## Change summary

Preserve stacked pull requests by retargeting PRs based on a merged branch before deleting that branch remotely.

## Best solution

Before deleting a merged PR's remote head branch, detect open pull requests whose base is that branch and offer or perform retargeting to the merged PR's base branch, with explicit error handling if any PR cannot be updated. This belongs in the GitHub API deletion flow around src/github/githubRepository.ts and src/github/pullRequestReviewCommon.ts.

## Evidence

- **shared extension flow:** src/github/pullRequestReviewCommon.ts routes both interactive and automatic remote-head deletion through folderRepositoryManager.deleteBranch(item), so the current direct-ref behavior affects both deletion paths.
- **API behavior confirmation:** https://github.com/microsoft/vscode-pull-request-github/issues/6799#issuecomment-2884274866 independently reports that deleting the ref through gh's API command also closes PRs targeting the deleted branch, supporting that GitHub.com's UI performs additional orchestration rather than a plain ref deletion.
