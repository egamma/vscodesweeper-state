# Issue #6799 — Deleting a branch auto-closes any PRs targeting the deleted branch

[https://github.com/microsoft/vscode-pull-request-github/issues/6799](https://github.com/microsoft/vscode-pull-request-github/issues/6799)

## Summary

The requested GitHub.com parity remains missing: remote branch deletion does not retarget dependent PRs. Route this accepted On Deck feature to the review and GitHub integration areas; no verified canonical or fixing commit was found.

## Change summary

Retarget dependent pull requests before deleting a merged parent branch so their existing discussions and reviews remain accessible.

## Best solution

Preserve dependent PRs when deleting a merged parent branch from the description view, matching GitHub.com's behavior for the reported default-branch scenario. Establish safe behavior when dependent PRs cannot be retargeted before remote deletion.

- **Behavior:**

  > Deleting a merged parent branch from the PR description view must preserve dependent pull requests in the reported single-repository GitHub.com workflow. After A→main merges and A is deleted, the existing B→A PR should target main and remain open without requiring recreation. Its existing discussion and review history should remain attached to the same PR. Failure to retarget must produce the maintainer-agreed, explicit deletion behavior.
- **Trace:**

  > PullRequestOverviewPanel.deleteBranch delegates to PullRequestReviewCommon.deleteBranch in src/github/pullRequestReviewCommon.ts. performBranchDeletion handles remoteHead by calling FolderRepositoryManager.deleteBranch, which delegates to GitHubRepository.deleteBranch in src/github/githubRepository.ts; that method directly deletes heads/<parent branch> through git.deleteRef with no dependent-PR handling. PullRequestModel.updateBaseBranch exists in src/github/pullRequestModel.ts, but its current caller is the manual description-view base-change action, not deletion. The independent gh report at https://github.com/microsoft/vscode-pull-request-github/issues/6799#issuecomment-2884274866 corroborates service-side closure semantics; current live API behavior was not executed. Preserve existing local-branch, remote-removal, and worktree cleanup behavior. Planning must establish dependent-PR discovery and API constraints, including what the user sees if retargeting is denied or partially fails.
- **Open decisions:**
