## Plan brief

- **Likely files:** `src/env/node/net.ts`, `src/env/browser/net.ts`, `src/github/credentials.ts`
- **Validation:** With HTTPS_PROXY unset and direct outbound connections blocked, configure http.proxy to a controlled HTTP proxy and verify that both REST repository requests and GraphQL PR queries succeed through it. Repeat against an Enterprise endpoint and verify that removing the proxy setting preserves ordinary direct-network behavior.
- **Behavior:**

  > Users on networks requiring a proxy should be able to configure VS Code's http.proxy and use the extension without separately configuring HTTPS_PROXY. Both REST and GraphQL requests must work through the configured proxy for GitHub.com and Enterprise. Acceptance should exercise a proxy-only network and also confirm unchanged behavior when no proxy is configured.
- **Trace:**

  > src/env/node/net.ts exports an agent initialized from HTTPS_PROXY, without explicitly consulting VS Code configuration. src/github/credentials.ts:createHub supplies that agent to Octokit; its GraphQL link instead uses cross-fetch without an explicit agent, and src/env/browser/net.ts exports undefined. Source inspection does not establish how VS Code's runtime proxy interception affects either transport, so diagnosis starts with reproducing the proxy-only scenario and distinguishing extension API failures from built-in authentication failures. Preserve existing direct connections and browser behavior; built-in authentication's SOCKS5 failure is separately tracked at https://github.com/microsoft/vscode/issues/241201.
