# Issue #4291 — Comments creation is failing silently, with the illusion of "Pending" comments that saved on the server

[https://github.com/microsoft/vscode-pull-request-github/issues/4291](https://github.com/microsoft/vscode-pull-request-github/issues/4291)

## Summary

Still present on main: after comment creation fails, saving the retained temporary comment can silently perform no retry, leaving review text only in memory. Route to the comments/review owners rather than closing against the narrower VS Code progress issue.

## Change summary

Failed review-comment creation can leave an apparently pending comment in memory whose subsequent save does not reach GitHub.

## Best solution

Handle `TemporaryComment` in `ReviewCommentController.editComment` by retrying creation, as `PullRequestCommentController.editComment` already does, while preserving the draft and presenting a durable failure/progress state. Continue the platform-level progress affordance in https://github.com/microsoft/vscode/issues/168431.

## Evidence

- **source-reproducible silent retry:** On current main, src/view/reviewCommentController.ts:920-944 accepts a temporary comment at runtime but only acts when it is a GHPRComment; saving a TemporaryComment therefore returns without an API call or error.
- **optimistic state and failure path:** src/view/reviewCommentController.ts:747-751 inserts a TemporaryComment before the GitHub mutation, while lines 847-864 retain it in editing mode after creation fails. src/github/prComment.ts:148-185 confirms this object is an optimistic, in-memory representation labeled Pending.
- **working counterpart:** src/view/pullRequestCommentController.ts:433-458 explicitly handles TemporaryComment by calling createOrReplyComment, demonstrating the missing retry branch in ReviewCommentController.
- **partial upstream work:** https://github.com/microsoft/vscode/issues/168431 remains open and tracks a platform progress affordance for optimistic comments, but it does not own the extension-side no-op save path.
- **confirmed impact:** The reporter reproduced the loss twice with debug logging, and additional commenters independently reported losing hours of review comments.
