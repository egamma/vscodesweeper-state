# Issue #4291 — Comments creation is failing silently, with the illusion of "Pending" comments that saved on the server

[https://github.com/microsoft/vscode-pull-request-github/issues/4291](https://github.com/microsoft/vscode-pull-request-github/issues/4291)

## Summary

Keep open and route to comments/review: current source still permits unsaved temporary comments to look like server-backed pending comments, and the checked-out review's Save path ignores them. The original missing notification remains unexplained; related issues do not establish a fix or qualifying duplicate.

## Change summary

Failed review-comment creation leaves misleading pending comments in memory, risking loss of review text.

## Best solution

Make server-saving, server-saved pending, and failed comments distinguishable, with a working recovery path that preserves unsaved text. Diagnose the original silent failure separately, coordinating any core progress API work with https://github.com/microsoft/vscode/issues/168431.

- **Likely files:** `src/github/prComment.ts`, `src/view/reviewCommentController.ts`, `src/view/pullRequestCommentController.ts`, `src/commands.ts`, `src/test/view/reviewCommentController.test.ts`
- **Validation:** Extend the existing ReviewCommentController tests to reject comment creation, retain the text, invoke Save on the retained temporary comment, and verify a server retry or an explicit failure rather than silent success. Manually exercise delayed and rejected creation during an ongoing review, including reply attempts and recovery, and compare saved comments with GitHub.
- **Behavior:**

  > An optimistically displayed review comment must not imply it has been saved on GitHub while creation is still running or has failed. Failed creation must retain the user's text and expose its unsaved state. Saving a retained failed comment must either persist it or visibly report failure, never silently do nothing. Server-backed pending review comments must retain their existing review-submission semantics.
- **Trace:**

  > TemporaryComment in src/github/prComment.ts uses the same Pending label and Draft state as server-backed review comments. ReviewCommentController.createOrReplyComment retains temporary text in editing mode after rejection, but ReviewCommentController.editComment accepts work only for GHPRComment; pr.saveComment in src/commands.ts nevertheless dispatches retained TemporaryComment instances there. PullRequestCommentController has a different temporary-save path that attempts creation against a thread already containing temporary comments, so both review surfaces need examination. The original missing creation notification and suspected SSO expiry are not established by this trace. Preserve optimistic rendering and normal pending-review behavior; authentication changes are outside the diagnosed scope. https://github.com/microsoft/vscode/issues/168431 tracks core progress support, not a complete replacement for this extension issue.
- **Open decisions:**
  - What user-visible indicator should distinguish comments still saving or failed to save from server-backed pending review comments while retaining optimistic rendering?
