# Issue #4291 — Comments creation is failing silently, with the illusion of "Pending" comments that saved on the server

[https://github.com/microsoft/vscode-pull-request-github/issues/4291](https://github.com/microsoft/vscode-pull-request-github/issues/4291)

## Summary

The misleading failure state remains possible on current main: an optimistic comment is labeled "Pending" before the GitHub request completes, with no distinct in-progress state or durable recovery. Route this to comments/review while coordinating the progress UI with the open VS Code core issue.

## Change summary

Failed or stalled review-comment creation can leave an in-memory comment looking like a server-backed pending comment, causing drafted review text to be lost.

## Best solution

Ensure optimistic comments are visibly distinguished from server-backed drafts until creation succeeds, and preserve or recover their text when creation fails or stalls. The extension should also surface and log the failure reliably, while the progress affordance is coordinated through https://github.com/microsoft/vscode/issues/168431.

## Evidence

- **current optimistic state:** src/github/prComment.ts documents TemporaryComment as an immediate optimistic replacement and assigns it the same visible "Pending" label used for draft comments, without a separate in-progress or failed state.
- **current creation path:** src/view/reviewCommentController.ts and src/view/pullRequestCommentController.ts add the TemporaryComment before awaiting createReviewThread/createCommentReply. Rejected requests show a notification and return the temporary comment to editing mode, but there is no timeout, persistence, or durable failure marker for a request that remains unresolved.
- **confirmed impact:** The original reporter reproduced the loss with debug logging, and additional users reported the same loss after long reviews through https://github.com/microsoft/vscode-pull-request-github/issues/4291#issuecomment-2273665391.
- **upstream dependency:** https://github.com/microsoft/vscode/issues/168431 remains open and explicitly tracks the VS Code comments API/UI support needed to show progress for optimistic comments; it does not resolve the extension-side creation failure or recovery behavior.
- **not fully covered by later fix:** https://github.com/microsoft/vscode-pull-request-github/commit/99da81500d941883b881d9f8aa8d6a47bc5e8e01 added a modal data-loss warning to startReview failures, but did not add progress, persistence, timeout handling, or equivalent modal handling to the general createOrReplyComment path.
