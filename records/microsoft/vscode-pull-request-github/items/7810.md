# Issue #7810 — When using the extension with a GHE environment with submodules, extension does not load PRs properly

[https://github.com/microsoft/vscode-pull-request-github/issues/7810](https://github.com/microsoft/vscode-pull-request-github/issues/7810)

## Summary

Keep open: mixed GitHub Enterprise and GitHub.com submodule workspaces remain a recognized unsupported credential scenario. The ignore-submodules setting is a workaround, not support for both repositories.

## Change summary

Support loading GitHub Enterprise pull requests when the workspace also contains a GitHub.com submodule requiring different credentials.

## Best solution

Authenticate and resolve each repository through its remote's provider in the repository-management flow, allowing GitHub.com and Enterprise sessions to coexist in one workspace. Preserve `githubPullRequests.ignoreSubmodules` as an opt-out rather than requiring it.
