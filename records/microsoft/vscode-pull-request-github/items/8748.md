# Issue #8748 — Continuously trying to push changes (and fail)

[https://github.com/microsoft/vscode-pull-request-github/issues/8748](https://github.com/microsoft/vscode-pull-request-github/issues/8748)

## Summary

The prompts follow the branch's configured tracking relationship: `stage-test` still tracks `github/master`, so Git and the extension both report it as one commit ahead even though a separate `github/stage-test` ref was pushed. Maintainer precedent confirms that the extension intentionally relies on the configured upstream to determine whether a branch is published.

## Change summary

Avoid repeatedly offering to push a branch when its commit was manually pushed to a same-named remote branch without updating the branch's tracking upstream.

## Best solution

Keep the tracking-upstream behavior and configure `stage-test` to track `github/stage-test`, either while pushing with `git push --set-upstream github stage-test` or afterward with `git branch --set-upstream-to=github/stage-test stage-test`. Detecting independently pushed, untracked remote refs would be a separate creation-flow polish request.
