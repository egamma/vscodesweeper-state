# Issue #8748 — Continuously trying to push changes (and fail)

[https://github.com/microsoft/vscode-pull-request-github/issues/8748](https://github.com/microsoft/vscode-pull-request-github/issues/8748)

## Summary

Still present on main: the creation flow mistakes commits ahead of a differently named tracked base branch for unpushed commits, then repeats a push that cannot change that ahead count. Route this to the git area.

## Change summary

Creating a pull request repeatedly offers to push a branch that was already pushed under its local name but still tracks the remote base branch.

## Best solution

In `src/github/createPRViewProvider.ts` and the retry path in `src/github/folderRepositoryManager.ts`, determine whether the selected head ref exists on the intended GitHub remote instead of treating `Branch.ahead` relative to a differently named upstream as evidence of unpushed commits. Avoid recursively retrying PR creation when a push leaves the relevant state unchanged.

## Evidence

- **source reproduction:** `src/github/createPRViewProvider.ts:1449-1475` fetches the configured upstream and treats any positive `compareBranch.ahead` as unpushed. For `stage-test` tracking `github/master`, that count describes commits ahead of `master`, even after `stage-test` has been pushed.
- **retry loop:** `src/github/folderRepositoryManager.ts:1743-1757` handles GitHub's `No commits between` response by checking the same `HEAD.ahead` value, calling `repository.push()`, and recursively retrying `createPullRequest(params)`. With `push.default=current`, the push does not change the branch's `github/master` tracking relationship, so the condition remains true.
- **related issue search:** https://github.com/microsoft/vscode-pull-request-github/issues/8676 documents the related mistake of treating a differently named tracked base branch as the feature branch's remote counterpart, but it concerns stale PR association rather than this PR-creation and push-retry path, so it is not a canonical duplicate.
