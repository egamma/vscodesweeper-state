# Issue #8969 — Approve and resolve act on the wrong folder when a repository and its worktrees are open in one window

[https://github.com/microsoft/vscode-pull-request-github/issues/8969](https://github.com/microsoft/vscode-pull-request-github/issues/8969)

## Summary

Both wrong-folder paths remain in current main: overview approval selects the first matching remote, and review-thread handling ignores repository ownership. Route to review and git; the proposed fix was closed without merging.

## Change summary

Approval and conversation resolution must use the originating repository when multiple open worktrees share a GitHub remote.

## Best solution

Preserve repository ownership through description-panel selection and review-thread dispatch so approval checks the correct checkout and resolving a conversation updates its editor. Use the withdrawn PR's diagnosis as a reference, while preserving genuine remote-head mismatch protection.
