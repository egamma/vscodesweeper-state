# Issue #2186 — Option to disable automatic PR detection

[https://github.com/microsoft/vscode-pull-request-github/issues/2186](https://github.com/microsoft/vscode-pull-request-github/issues/2186)

## Summary

Keep open: existing controls mitigate individual symptoms but do not disable automatic PR detection globally or exclude the user's own PRs. The review area should decide the opt-out behavior.

## Change summary

Allow users to disable automatic PR detection, optionally only for PRs they authored.

## Best solution

Provide an automatic-review opt-out that lets users keep working on their own PR branches without unwanted commenting gutters or pull prompts, while retaining deliberate PR review. Decide whether the control includes an author-based exclusion alongside a global off mode.

## Plan brief

- **Likely files:** `package.json`, `package.nls.json`, `src/common/settingKeys.ts`, `src/view/reviewManager.ts`
- **Validation:** With open PRs authored by the signed-in user and another user, switch to their branches through Git and reload VS Code. Verify the chosen policy controls automatic review activation, commenting gutters, and pull prompts; verify default behavior and deliberate PR checkout remain consistent with the agreed contract.
- **Behavior:**

  > Checking out a branch associated with the user's own open PR currently activates review features even when the user only wants to continue development. Users should be able to opt out of this automatic activation without disabling the extension or listing every branch individually. Acceptance checks should cover own and other-authored PRs, branch switching, window reload, commenting gutters, and update prompts. Default behavior should remain unchanged for users who do not opt out.
- **Trace:**

  > ReviewManager.validateState in src/view/reviewManager.ts resolves PR metadata for the checked-out branch and activates review state before registering commenting and checking branch updates. Its early ignoredPullRequestBranches check matches exact names and has a remote/fork restriction; its useReviewMode checks concern only closed and merged PRs. package.json and package.nls.json confirm that neither setting provides a general or author-based opt-out. githubPullRequests.pullBranch and comment expansion controls address separate symptoms rather than the activation policy. The maintainer acknowledged a possible full autodetection setting in https://github.com/microsoft/vscode-pull-request-github/issues/408#issuecomment-1169907634. Preserve PR discovery in the tree and existing behavior for users retaining automatic review; uncertainty is the opt-out contract and how it interacts with deliberate PR checkout.
- **Open decisions:**
  - Should the opt-out offer both a global off mode and an exclude-my-PRs mode, or only a global off mode?
  - When automatic review is disabled, should an explicit PR checkout temporarily enter review mode, and should that explicit choice survive a window reload?

## Evidence

- **Remaining capability gap:** package.json:381–410 and package.nls.json:63–65 define githubPullRequests.useReviewMode for closed and merged PRs; open PRs always use review mode. There is no global off or author-exclusion option.
- **Branch-specific workaround:** githubPullRequests.ignoredPullRequestBranches is declared in package.json:450–458. src/view/reviewManager.ts:637–644 compares exact branch names, with an additional remote/fork condition, then clears review state. This is not a wildcard or author-based opt-out and requires maintaining individual branch names.
- **Separate symptom controls:** githubPullRequests.pullBranch = "never" suppresses update prompts through src/github/folderRepositoryManager.ts:2924–2939. githubPullRequests.commentExpandState = "collapseAll" and pr.collapseAllComments collapse threads rather than disable automatic review activation or remove the commenting gutter.
- **Current activation path:** src/view/reviewManager.ts:619–805, ReviewManager.validateState, resolves the checked-out branch's PR, checks closed/merged state, assigns activePullRequest, checks branch updates, and registers commenting. This path has no author-based exclusion.
