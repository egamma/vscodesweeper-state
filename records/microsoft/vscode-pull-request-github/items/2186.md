# Issue #2186 — Option to disable automatic PR detection

[https://github.com/microsoft/vscode-pull-request-github/issues/2186](https://github.com/microsoft/vscode-pull-request-github/issues/2186)

## Summary

A meaningful gap remains: users can suppress review mode for named branches and separately disable pull prompts or editor commenting, but there is no global automatic-detection switch or rule excluding PRs authored by the current user. Route this established request to the review and UX areas.

## Change summary

Add a setting to disable automatic PR detection globally or for pull requests authored by the current user.

## Best solution

Extend review-mode detection in `src/view/reviewManager.ts` with an explicit policy setting such as enabled, disabled, or exclude-authored, while preserving explicit PR checkouts. The setting should prevent automatic review activation—and therefore its pull prompt and gutter UI—without requiring users to maintain a branch-name list.

- **Evidence:** The durable themes explicitly include “The review flow,” while the product promise is to “Review and manage your GitHub pull requests and issues directly in VS Code.”

## Evidence

- **current detection path:** `src/view/reviewManager.ts` automatically resolves the checked-out branch's PR and activates it; the only early exclusion checks `githubPullRequests.ignoredPullRequestBranches` for an exact branch-name match, with no global or current-author condition.
- **existing setting is partial:** `package.json` defines `githubPullRequests.ignoredPullRequestBranches` as an array of branch names, and `package.nls.json` says it prevents review mode on those branches. It does not support disabling all detection or excluding PRs based on authorship.
- **review-mode setting is partial:** `githubPullRequests.useReviewMode` only controls closed and merged PR states; its description explicitly says open pull requests always use review mode, so it cannot satisfy this request for open PRs authored by the user.
- **maintainer precedent:** In https://github.com/microsoft/vscode-pull-request-github/issues/408#issuecomment-1169907634, the maintainer identified branch exclusions and VS Code's commenting toggle as workarounds but explicitly left adding a setting to disable all PR autodetection as the next option if those did not solve the workflow.
