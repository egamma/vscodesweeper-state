# Issue #2186 — Option to disable automatic PR detection

[https://github.com/microsoft/vscode-pull-request-github/issues/2186](https://github.com/microsoft/vscode-pull-request-github/issues/2186)

## Summary

A real capability gap remains: current settings can ignore named branches or hide editor comments, but cannot disable automatic detection globally or exclude the user's own pull requests.

## Change summary

Allow users to disable automatic pull-request detection entirely or exclude pull requests they authored.

## Best solution

Extend the review-mode configuration and the detection path in src/view/reviewManager.ts with explicit automatic-detection modes such as enabled, disabled, and exclude-authored, while preserving review mode after an explicit PR checkout.

- **Fit:** aligned
- **Reason:** Giving authors control over automatic review mode improves the extension's established in-editor review workflow without replacing a VS Code core surface.
- **Evidence:** The durable themes explicitly include “The review flow” and working with real-world repository workflows.

## Evidence

- **open PRs remain automatic:** package.nls.json documents that open pull requests always use review mode, while package.json's githubPullRequests.useReviewMode setting only configures closed and merged pull requests.
- **branch ignore is narrower:** githubPullRequests.ignoredPullRequestBranches accepts individual branch names; src/view/reviewManager.ts compares entries exactly with the current branch name, so it provides neither a global off mode nor an author-based exclusion.
- **comment toggle is partial:** The Comments: Toggle Editor Commenting command can hide gutter commenting, but it does not prevent automatic PR detection, review-mode initialization, or pull-update prompts.
- **maintainer precedent:** In https://github.com/microsoft/vscode-pull-request-github/issues/408#issuecomment-1169907634, the maintainer described the branch-ignore and comment-toggle workarounds and explicitly left open the possibility of a setting that disables all PR autodetection.
- **canonical search:** Repository issue searches found no open broader canonical; this older issue remains the clearest owner of global and author-aware automatic-detection control.
