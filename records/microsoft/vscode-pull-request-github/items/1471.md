# Issue #1471 — Create predefined text for Description page comment field

[https://github.com/microsoft/vscode-pull-request-github/issues/1471](https://github.com/microsoft/vscode-pull-request-github/issues/1471)

## Summary

Reusable approval wording remains unsupported in the description-page comment field. Keep this request as the canonical discussion; the related Saved Replies request was explicitly consolidated here.

## Change summary

Allow inserting predefined approval text into the description-page comment field, as with GitHub Saved Replies.

## Best solution

Provide reusable text insertion into the editable review comment before submission. Decide whether this uses local templates, existing GitHub Saved Replies, or both, incorporating the related request for access to saved replies.

## Plan brief

- **Likely files:** `webviews/components/comment.tsx`, `webviews/common/context.tsx`, `src/github/pullRequestOverview.ts`, `src/commands.ts`, `package.json`
- **Validation:** In a PR description page, insert predefined approval wording, edit it before submission, and verify the submitted approval contains the exact resulting text. Verify insertion alone does not submit a review and ordinary manual comment entry still works.
- **Behavior:**

  > Users need to reuse prescribed approval wording without leaving the PR description page or retyping it. Inserting reusable text should leave it editable before approval and must not submit the review by itself. Acceptance checks should cover exact text preservation, editing before submission, and unchanged manual commenting.
- **Trace:**

  > webviews/components/comment.tsx implements AddComment using pendingCommentText and a textarea; submitAction reads its value and sends it through approve. webviews/common/context.tsx forwards approval text to the extension, and src/github/pullRequestOverview.ts handles submission. src/commands.ts registers pr.focusDescriptionInput as navigation only, while review.approveDescription submits text rather than inserting it. The contributed settings and commands contain no reusable-comment capability. Preserve existing review submission, draft text, and manual entry behavior. The related request at https://github.com/microsoft/vscode-pull-request-github/issues/6820 was consolidated into https://github.com/microsoft/vscode-pull-request-github/issues/1471 and specifically asks to access existing GitHub Saved Replies; uncertainty begins at which text source the product should support.
- **Open decisions:**
  - Should reusable approval text come from locally configured templates, the user's existing GitHub Saved Replies, or both?
