# Issue #6198 — Show files w/ updates in sidebar

[https://github.com/microsoft/vscode-pull-request-github/issues/6198](https://github.com/microsoft/vscode-pull-request-github/issues/6198)

## Summary

A real gap remains: the extension detects that a checked-out PR branch is behind, but the changes tree does not identify which files are affected by the incoming commits. Route this review-workflow request to the tree and git owners.

## Change summary

Decorate files in the pull-request changes sidebar when newer remote commits modify them and need to be pulled locally.

## Best solution

When the active PR branch is behind its upstream, compare the local HEAD with the remote PR head and propagate the resulting file set into the changes tree, decorating affected file nodes until the branch is updated.

- **Evidence:** The durable themes explicitly include “The review flow” and “Working with real-world repo shapes,” while the product promise is to review and manage pull requests directly in VS Code.

## Evidence

- **existing branch detection:** src/github/folderRepositoryManager.ts detects branch.behind > 0 and offers to pull, but only presents a PR-level notification; it does not calculate or expose the affected files.
- **missing file indicator:** src/view/fileTypeDecorationProvider.ts decorates pull-request file nodes only with their overall PR change status (M/A/D/R), while src/view/treeNodes/fileChangeNode.ts contains no state for files changed between the local and remote PR heads.
- **partial existing capability:** The pr.showDiffSinceLastReview command and PullRequestModel.showChangesSinceReview can filter files changed since the viewer's latest submitted review, but that baseline is not the checked-out local commit and therefore does not cover unpulled updates.
- **canonical search:** https://github.com/microsoft/vscode-pull-request-github/issues/6700 requests folder-level unified diffs, a different capability that does not own per-file incoming-update indicators.
