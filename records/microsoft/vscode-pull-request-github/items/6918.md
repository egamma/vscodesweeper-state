# Issue #6918 — Sticky PR/Issue headers when scrolling

[https://github.com/microsoft/vscode-pull-request-github/issues/6918](https://github.com/microsoft/vscode-pull-request-github/issues/6918)

## Summary

Partially implemented on main: a compact sticky header now preserves status, title, number, and copy-link access, but the requested checkout and refresh actions still scroll away. Keep the remaining work open and route it to the description-page UX area.

## Change summary

Keep a compact PR or issue header, including key actions such as checkout and refresh, visible while scrolling.

## Best solution

Extend the responsive sticky header in webviews/components/stickyHeader.tsx with the applicable checkout and refresh actions from webviews/components/header.tsx while retaining its compact layout at narrow widths.

## Vision fit

- **Fit:** aligned
- **Reason:** This improves the native PR description and review workflow by keeping frequently used actions available without leaving the editor.
- **Evidence:** The durable themes explicitly include the review flow and the description page webview, while the product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code."
