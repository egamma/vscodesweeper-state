# Issue #6596 — Sub-issues

[https://github.com/microsoft/vscode-pull-request-github/issues/6596](https://github.com/microsoft/vscode-pull-request-github/issues/6596)

## Summary

A real capability gap remains on current main: the extension neither retrieves nor represents GitHub parent/sub-issue relationships. Keep the request open and route it across the issues tree and description surfaces.

## Change summary

Display parent and child issue relationships in the issues tree, issue details, and hover UI, and allow authorized users to edit those relationships.

## Best solution

Extend the GitHub issue data layer to retrieve parent and child relationships, expose them through IssueModel and the webview context, and render navigable hierarchy in the issues tree, description sidebar, and issue hover. Relationship mutations should respect GitHub permissions and API availability, including Enterprise capability differences.

- **Fit:** aligned
- **Reason:** Native sub-issue hierarchy and editing directly advance the extension's established issues, trees, and in-editor workflow themes.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and the durable themes explicitly include issues integration and "Trees, queries, and views."

## Evidence

- **data-model gap:** The Issue interfaces in src/github/interface.ts and src/github/graphql.ts model labels, projects, milestones, assignees, and issue type, but contain no parent or sub-issue relationship fields.
- **tree gap:** src/issues/issuesView.ts creates every issue as TreeItemCollapsibleState.None and supports grouping only by repository or milestone, so it cannot present a parent-child hierarchy.
- **details and hover gap:** src/github/issueOverview.ts sends labels, projects, milestone, and assignees to the webview without hierarchy data; src/github/markdownUtils.ts builds issue hover content from the title, body, labels, and comments without a parent issue.
- **no existing capability:** The githubIssues settings and commands declared in package.json provide configurable queries and repository/milestone grouping but no setting or command for viewing or editing sub-issues.
- **canonical search:** Repository searches for "sub-issues", "sub issues", and "parent issue" found only https://github.com/microsoft/vscode-pull-request-github/issues/6596, and no open pull request was found implementing it.
