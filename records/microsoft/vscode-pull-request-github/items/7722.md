[https://github.com/microsoft/vscode-pull-request-github/issues/7722](https://github.com/microsoft/vscode-pull-request-github/issues/7722)

## Summary

Still actionable on current builds: several users independently exhaust the GitHub GraphQL quota during ordinary PR reviews, and recent debug logs show a burst of more than 180 pull-request fetches. Keep this open as the best-diagnosed report and route it to the GitHub/GraphQL performance area.

## Change summary

Normal pull-request review activity generates excessive GraphQL requests and exhausts the user's GitHub API quota, preventing further review work.

## Best solution

Identify and coalesce the repeated pull-request refreshes in the GitHub integration layer, reuse cached models where freshness is unnecessary, and suspend or defer additional queries when GitHub reports an exhausted quota. Preserve explicit refresh behavior while preventing background activity from consuming the reviewer's quota.

- **uncached fetch path:** src/github/githubRepository.ts:getPullRequest defaults useCache to false, executes the full PullRequest GraphQL query, and catches quota failures only after the request has been attempted; the source does not establish which upstream caller is producing the full burst.
