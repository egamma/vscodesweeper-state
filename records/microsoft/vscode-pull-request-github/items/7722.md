# Issue #7722 — Fetching pull request with query failed: HttpError: API rate limit exceeded

[https://github.com/microsoft/vscode-pull-request-github/issues/7722](https://github.com/microsoft/vscode-pull-request-github/issues/7722)

## Summary

Still present on main: notification refresh can launch dozens of concurrent pull-request GraphQL queries and continues the fan-out after GitHub reports that the user's API limit is exhausted. The supplied current pre-release logs reproduce this behavior, so the issue no longer needs basic information and should be routed for performance work.

## Change summary

Reviewing pull requests becomes unusable after the extension rapidly exhausts or continues querying against the user's GitHub GraphQL rate limit.

## Best solution

Bound and deduplicate notification-model resolution in `src/notifications/notificationsManager.ts` and `src/notifications/notificationsProvider.ts`, reuse cached PR models where possible, and stop or defer the remaining fan-out when GitHub reports rate exhaustion.

## Evidence

- **current-version reproduction:** The debug log in https://github.com/microsoft/vscode-pull-request-github/issues/7722#issuecomment-4094340101 comes from extension version 0.133.2026031904 and shows one notification refresh launching roughly 44 PullRequest queries concurrently, followed by repeated `API rate limit already exceeded` failures.
- **current source:** `src/notifications/notificationsManager.ts` resolves every fetched notification through an unbounded `Promise.all`; `src/notifications/notificationsProvider.ts` resolves each PR and may fetch it a second time when its notification is newer than the cached model.
- **request handling:** `src/github/loggingOctokit.ts` limits only concurrent extension calls with a 140-slot bulkhead; GitHub rate-limit errors do not cancel or defer the other requests already launched by the notification fan-out.
- **canonical search:** Open issue https://github.com/microsoft/vscode-pull-request-github/issues/4655 concerns processing queued requests after the extension's internal concurrency threshold is hit, while https://github.com/microsoft/vscode-pull-request-github/issues/8621 combines connection timeouts with a later request-volume report; neither owns the full notification-driven GraphQL exhaustion documented here.
