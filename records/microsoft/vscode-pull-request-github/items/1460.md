# Issue #1460 — plugin should switch to least privelege permissions

[https://github.com/microsoft/vscode-pull-request-github/issues/1460](https://github.com/microsoft/vscode-pull-request-github/issues/1460)

## Summary

The least-privilege gap remains on current main: the extension still requires the broad `repo` and `workflow` OAuth scopes for its normal session. This permission-scope concern is security-sensitive and must remain open for a human-owned architecture decision.

## Change summary

Use narrower GitHub permissions by default and gracefully disable features that require scopes the user has not granted.

## Best solution

Coordinate the extension's authentication flow with VS Code's built-in GitHub Authentication provider and GitHub's available token models, then introduce capability-based scope requests and graceful degradation without breaking private-repository workflows. The design should document which extension features require each elevated scope and request optional scopes only when those features are used.
