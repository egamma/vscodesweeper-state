# Issue #192 — Checkout process should better handle slower speeds

[https://github.com/microsoft/vscode-pull-request-github/issues/192](https://github.com/microsoft/vscode-pull-request-github/issues/192)

## Summary

The reported race no longer exists on current main: the Checkout control remains disabled until the extension-host checkout command completes and replies.

## Change summary

Keep the Checkout button disabled until a slow pull-request checkout and corresponding UI update finish.

## Best solution

Retain the current request-scoped busy state in the PR header, which prevents a second checkout while the first request remains pending.
