# Issue #7303 — Expect `Expand All` or `Reexpand All` option

[https://github.com/microsoft/vscode-pull-request-github/issues/7303](https://github.com/microsoft/vscode-pull-request-github/issues/7303)

## Summary

Keep open: this team-authored Backlog request identifies a real gap in the tree-view controls. Current main exposes VS Code's built-in Collapse All action but provides no corresponding expand, restore, or disabled-state behavior.

## Change summary

Add an Expand All or restore-previous-expansion action after collapsing the pull-request or issue tree, or disable Collapse All when the tree is already collapsed.

## Best solution

Pursue the generic expand/restore capability in VS Code's tree-view platform, tracked by https://github.com/microsoft/vscode/issues/174770, while retaining this issue for the extension-specific PR and issue view UX. If core does not provide the complete toolbar behavior, add a bounded extension action that restores the saved expansion state without recursively loading an unbounded tree.

## Evidence

- **current implementation:** src/view/prsTreeDataProvider.ts and src/issues/issueFeatureRegistrar.ts create the PR and issue TreeViews with showCollapseAll: true, delegating the visible Collapse All action to VS Code's TreeView platform.
