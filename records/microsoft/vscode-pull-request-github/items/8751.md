# Issue #8751 — Finding how to submit pending review comments is VERY hard

[https://github.com/microsoft/vscode-pull-request-github/issues/8751](https://github.com/microsoft/vscode-pull-request-github/issues/8751)

## Summary

Review submission remains difficult to discover when automatic layout changes are disabled: current source still hides the review sidebar in that configuration. The discussion supplies the relevant setting and logs; the focus-stealing fixes do not resolve this remaining usability gap.

## Change summary

Make pending-review submission discoverable without requiring automatic layout changes or finding the full PR description.

## Best solution

Provide an obvious review-submission entry point when githubPullRequests.focusedMode is false, while preserving the user's choice not to change layouts automatically. Decide the intended sidebar or command-palette experience before implementation.

## Plan brief

- **Likely files:** `package.json`, `package.nls.json`, `src/view/reviewManager.ts`, `src/commands.ts`, `src/view/reviewCommentController.ts`
- **Validation:** With one GitHub repository and a checked-out PR, set githubPullRequests.focusedMode=false and create pending comments. Verify the agreed entry point is discoverable and submits those comments without requiring manual discovery of the full description. Verify terminal commits, external branch switches, and background polling do not unexpectedly change layout or steal focus.
- **Behavior:**

  > Users who disable automatic PR layout changes must still have a discoverable way to submit pending review comments. The current review sidebar disappears in this configuration, and the existing comment-widget action opens the full description. Acceptance requires an agreed submission entry point that works with focusedMode=false while preserving the user's layout and focus preferences.
- **Trace:**

  > ReviewManager.updateFocusedViewMode in src/view/reviewManager.ts derives github:focusedReview directly from githubPullRequests.focusedMode. package.json uses that context to gate github:activePullRequest, so disabling layout changes also hides the review pane. The existing pr.openReview command is excluded from the command palette and requires a comment-thread handler; ReviewCommentController.openReview opens the description and scrolls to its review section. https://github.com/microsoft/vscode-pull-request-github/pull/8826 addresses polling-triggered focus changes, not this visibility dependency. Preserve review submission semantics and do not reintroduce automatic focus changes. The remaining uncertainty is the intended user-facing submission surface, not the configuration trigger.
- **Open decisions:**
  - Should disabling automatic layout changes leave the Review Pull Request sidebar available, or should submission instead be made discoverable through a separate command or inline entry point?
