# Issue #8741 — Implement automated Pull Request prioritization system

[https://github.com/microsoft/vscode-pull-request-github/issues/8741](https://github.com/microsoft/vscode-pull-request-github/issues/8741)

## Summary

A real feature gap remains: the extension can prioritize GitHub notifications, including PR notifications, but it does not score the full incoming PR queue using change size, affected areas, or diff-derived risk. Route this to the review and notifications owners for product and implementation scoping.

## Change summary

Add automated scoring and ordering of incoming pull requests by review complexity, affected code areas, regression risk, size, and impact.

## Best solution

Extend the existing prioritization architecture in `src/notifications/` or introduce an equivalent PR-tree service that can rank all relevant incoming PRs, not only notification threads. The scorer should consume change metadata such as file areas and diff size, present understandable reasoning, and let maintainers opt into the resulting order without replacing customizable PR queries.
