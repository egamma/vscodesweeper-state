# Issue #8741 — Implement automated Pull Request prioritization system

[https://github.com/microsoft/vscode-pull-request-github/issues/8741](https://github.com/microsoft/vscode-pull-request-github/issues/8741)

## Summary

A related Copilot-based priority score already exists for GitHub notifications, but it does not cover the full request: it prioritizes unread notifications rather than the complete incoming-PR queue and does not inspect changed files or code areas. Route the remaining feature gap to the notifications and chat owners.

## Change summary

Automatically rank incoming pull requests using review complexity, affected code areas, regression risk, size, and impact.

## Best solution

Reuse the existing notifications priority pipeline in `src/notifications/` while adding PR diff metadata such as additions, deletions, and changed paths, then decide whether the ranked surface should remain the Notifications view or cover a repository's complete PR queue.
