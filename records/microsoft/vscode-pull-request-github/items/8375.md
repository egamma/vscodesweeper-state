# Issue #8375 — Closing and reopening of multidiff editor not always needed

[https://github.com/microsoft/vscode-pull-request-github/issues/8375](https://github.com/microsoft/vscode-pull-request-github/issues/8375)

## Summary

Keep open: current `main` still unconditionally closes a matching multidiff editor during PR checkout, even when its URI-backed contents have already refreshed correctly. This team-authored Backlog item records a remaining review-flow polish opportunity.

## Change summary

Avoid closing and reopening an existing PR multidiff editor when its resources update correctly after checking out the PR again.

## Best solution

Refine `_closeOutdatedMultiDiffEditors` in `src/view/reviewManager.ts` to inspect the multidiff's `textDiffs` and preserve the existing tab when its resources still represent the refreshed PR; close it only when the baseline or resource set is genuinely obsolete. Add focused tests covering both the reusable and stale-editor cases.
