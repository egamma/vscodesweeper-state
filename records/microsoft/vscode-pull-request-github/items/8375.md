# Issue #8375 — Closing and reopening of multidiff editor not always needed

[https://github.com/microsoft/vscode-pull-request-github/issues/8375](https://github.com/microsoft/vscode-pull-request-github/issues/8375)

## Summary

Keep open: current code still closes matching multidiff tabs without checking whether their contents actually became outdated. This team-authored follow-up requests preserving an already-correct editor; neither an existing setting nor a verified canonical covers that improvement.

## Change summary

Avoid closing and reopening a PR's multidiff editor when its existing diff has already updated correctly.

## Best solution

Preserve the existing multidiff editor when its comparison remains valid after checkout, while retaining stale-left-side protection. Establish the safe-reuse conditions in the review manager and multidiff-opening path before changing the behavior.
