# Issue #8375 — Closing and reopening of multidiff editor not always needed

[https://github.com/microsoft/vscode-pull-request-github/issues/8375](https://github.com/microsoft/vscode-pull-request-github/issues/8375)

## Summary

The noisy close-and-reopen behavior remains on main: every matching multidiff tab is closed unconditionally during PR editor upgrades. Route this accepted Backlog request to the review and UX areas.

## Change summary

Keep an existing PR multidiff editor open when its resources update correctly instead of closing and recreating it.

## Best solution

Refine `ReviewManager._upgradePullRequestEditors` to retain a matching `TabInputTextMultiDiff` when its resources already represent the refreshed PR, closing it only when the base or resource set is genuinely stale.

- **Fit:** aligned
- **Reason:** Reducing disruption while refreshing an in-editor PR diff directly improves the extension's core review workflow.
- **Evidence:** The durable themes explicitly include “The review flow,” while the product promise is to “Review and manage your GitHub pull requests and issues directly in VS Code.”
