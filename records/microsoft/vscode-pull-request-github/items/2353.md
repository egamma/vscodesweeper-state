# Issue #2353 — View Pull Request in the Context Menu

[https://github.com/microsoft/vscode-pull-request-github/issues/2353](https://github.com/microsoft/vscode-pull-request-github/issues/2353)

## Summary

A meaningful gap remains: current commands open known or active PRs, but do not discover the latest PR responsible for an arbitrary code line. Route this request to the git and GitHub integration areas; no matching canonical was verified.

## Change summary

Provide an editor context-menu action that opens the latest pull request that changed the selected code line.

## Best solution

Provide line-to-PR navigation using Git history and GitHub commit associations, preserving existing active-PR navigation. Establish historical PR selection and unavailable-result behavior before implementation.

- **Fit:** aligned
- **Reason:** Discovering the PR behind a code line brings GitHub development context directly into the editor.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," building on VS Code's git platform.

## Plan brief

- **Likely files:** `package.json`, `src/commands.ts`, `src/github/githubRepository.ts`
- **Validation:** In a GitHub test repository with two merged PRs changing different lines of one file, invoke the action on each line from the default branch and confirm it opens the corresponding historical PR rather than an active PR. Include a commit with multiple PR associations and a line with no associated PR to verify the agreed selection and unavailable-result behavior.
- **Behavior:**

  > From an ordinary repository file, users can invoke an editor context-menu action to reach the latest PR that changed the selected line, without checking out that PR. Lines last changed by different PRs must navigate independently. Validate historical merged PRs as well as the agreed behavior when a commit has multiple or no associated PRs.
- **Trace:**

  > package.json currently contributes editor sharing actions and a review suggestion action, but no line-to-PR discovery action. In src/commands.ts, pr.openPullRequestOnGitHub opens a supplied model or chooses an activePullRequest; this is not historical navigation. src/issues/userCompletionProvider.ts demonstrates repository.blame availability, but its use extracts author names only. src/integrations/gitlens/gitlensImpl.ts registers creation integration only, despite an open-PR context type being declared. The unresolved trace is selected-line attribution through Git history into GitHub PR associations, including repository identity and result selection; this review did not establish that algorithm or API contract. Preserve existing active-PR commands, permalink behavior, and author completions.
- **Open decisions:**
  - When the line's last-changing commit is associated with multiple PRs, should navigation automatically choose the latest merged PR targeting the current branch, or present a PR chooser?
