## Evidence

- **canonical issue:** https://github.com/microsoft/vscode-pull-request-github/issues/8899 is open and tracks the same persistent PR-overview failure after transient GET /user or repository-metadata errors, with a confirmed in-session recovery after replacing the rejected cached promises.
- **current-user cache:** On current main, src/github/credentials.ts setCurrentUser assigns github.currentUser and github.isEmu from one getAuthenticated promise; a rejection remains stored for the lifetime of that hub, while getCurrentUser returns the same promise without retrying.
- **metadata cache:** On current main, src/github/githubRepository.ts getMetadata assigns the request promise to _metadata and rethrows failures without clearing it, so subsequent metadata requests reuse the rejected promise.
- **affected view:** src/github/pullRequestOverview.ts updateItem awaits getCurrentUser and repository-derived operations in its initialization Promise.all, so either cached rejection prevents the PR overview from initializing.
- **unique environment detail:** This report identifies the initial timeout trigger as a Windows 11 machine using Wi-Fi for internet while a 192.168.* embedded-device Ethernet connection is active; unplugging that connection restores API connectivity.
