# Issue #8600 — Open Github Action checks in Github Actions extension

[https://github.com/microsoft/vscode-pull-request-github/issues/8600](https://github.com/microsoft/vscode-pull-request-github/issues/8600)

## Summary

This remains a valid integration request: current main always treats each check's Details target as a web link, and no setting selects the GitHub Actions extension. Route it to the description-page area for an interoperability decision.

## Change summary

Allow PR check Details links to open the corresponding workflow run in the GitHub Actions VS Code extension, with browser fallback.

## Best solution

Define a supported URL- or run-ID-based entry point with the GitHub Actions extension, then let the PR description page invoke it when configured and installed while retaining the existing browser behavior as the default fallback.

## Vision fit

- **Fit:** aligned
- **Reason:** Keeping workflow investigation inside VS Code advances the extension's native, in-editor pull-request review experience without duplicating the Actions UI.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and the durable themes include the description page and PR lifecycle checks.

## Evidence

- **current implementation:** webviews/components/merge.tsx renders each status check's Details action as a direct <a href={s.targetUrl}> link; src/github/githubRepository.ts supplies the GitHub check run detailsUrl as targetUrl.
- **existing settings check:** package.json contains no githubPullRequests setting for selecting where check or workflow links open, and the current checkout contains no integration with GitHub.vscode-github-actions.
- **companion capability:** The GitHub Actions extension currently contributes commands including github-actions.explorer.openRun and github-actions.workflow.run.open, but its package manifest does not document a URL-based cross-extension invocation contract; coordination may therefore be needed before wiring the Details link to it.
- **related precedent:** https://github.com/microsoft/vscode-pull-request-github/issues/4815 was closed after a maintainer pointed to the GitHub Actions extension as the owner of workflow-run presentation. This request respects that boundary by asking only for navigation into that extension rather than duplicating its UI.
- **distinct from related issue:** https://github.com/microsoft/vscode-pull-request-github/issues/5805 concerned showing workflow summaries inside the Actions panel and was closed as belonging to another extension; it does not track navigation from PR check details.
