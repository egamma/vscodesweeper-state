# Issue #8848 — PR loading takes time and is not optimized for gigantic PR with 1500+ files

[https://github.com/microsoft/vscode-pull-request-github/issues/8848](https://github.com/microsoft/vscode-pull-request-github/issues/8848)

## Summary

Thanks for the report. Large pull requests still encounter an eager, multi-stage loading path on current main, and a second user independently confirmed the slowdown; this should remain open and be routed to performance and review.

## Change summary

Opening and previewing a pull request with more than 1,500 changed files takes an impractically long time.

## Best solution

Profile and make large-PR initialization incremental so the file tree becomes usable before every file, patch, review comment, and viewed-state page has loaded. The likely boundary spans file retrieval in src/github/loggingOctokit.ts and src/github/pullRequestModel.ts plus review initialization in src/view/reviewManager.ts.
