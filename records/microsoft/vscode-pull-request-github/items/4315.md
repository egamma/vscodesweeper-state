# Issue #4315 — Commit wise reviews

[https://github.com/microsoft/vscode-pull-request-github/issues/4315](https://github.com/microsoft/vscode-pull-request-github/issues/4315)

## Summary

Commit-wise commenting and editable historical checkouts remain missing; this issue is the established consolidation target. Route to review and git for a complete design rather than the rejected partial-commenting approach.

## Change summary

Support reviewing and commenting on individual PR commits with local checkout for editing and language-tool navigation.

## Best solution

Provide reliable PR review comments anchored to the selected commit, including files changed again afterward, and a safe local-checkout workflow for historical revisions. Preserve ordinary PR-head reviews and avoid introducing commenting that works only for some historical files.

- **Reason:** Commit-wise review with local language tooling advances the native in-editor review workflow.

## Plan brief

- **Likely files:** `src/view/treeNodes/commitNode.ts`, `src/view/treeNodes/fileChangeNode.ts`, `src/view/reviewCommentController.ts`, `src/github/pullRequestModel.ts`, `src/view/reviewManager.ts`, `src/github/folderRepositoryManager.ts`, `src/commands.ts`, `package.json`
- **Validation:** Review a PR with multiple commits, including an added file and a file changed again in a later commit. Verify comments from each historical diff retain the intended commit and line on GitHub, pending review submission remains correct, and local checkout enables editing and language navigation. Verify switching commits protects uncommitted edits and returning to the PR head restores the normal review workflow.
- **Behavior:**

  > Reviewers should browse each PR commit and comment on its changed files, including files modified again in later commits, without comments silently targeting another revision. Historical revisions should be available locally for editing, language navigation and trying suggestions. Acceptance must cover historical added files, later-modified files, pending review submission, protected local edits and return to the PR head. Comment availability must not depend on whether the file happens to remain unchanged afterward.
- **Trace:**

  > CommitNode.getChildren in src/view/treeNodes/commitNode.ts already constructs commit-specific review URIs. GitFileChangeNode.alternateCommand in src/view/treeNodes/fileChangeNode.ts opens historical virtual diffs rather than checking out their revisions. ReviewCommentController.provideCommentingRanges matches against PR file-change revisions, while PullRequestModel.createReviewThread has no selected-commit argument in its GraphQL thread mutation. Existing PR-head commenting and checkout behavior must remain intact. https://github.com/microsoft/vscode-pull-request-github/pull/8867 was closed unmerged because allowing comments only on unchanged historical files was considered confusing; use its diagnosis as context, not its restricted behavior as acceptance. REST use was accepted in https://github.com/microsoft/vscode-pull-request-github/issues/2793#issuecomment-1505527836, but the complete interaction among commit anchoring, pending reviews and historical checkout still needs tracing.
- **Open decisions:**
  - Should opening a historical commit automatically switch the working tree, as requested in the issue body, or should historical browsing remain non-mutating until the reviewer explicitly chooses checkout?

## Evidence

- **Existing capability does not cover the request:** src/view/treeNodes/commitNode.ts:getChildren already exposes each commit's changed files. src/view/treeNodes/fileChangeNode.ts:GitFileChangeNode.alternateCommand opens historical review URIs with vscode.diff and substitutes a local file only for the current commit; it does not check out historical commits. package.json exposes pr.copyCommitHash on commit nodes, and src/commands.ts registers it as a clipboard operation, not checkout.
- **Commenting boundary:** src/view/reviewCommentController.ts:provideCommentingRanges and findMatchedFileChangeForReviewDiffView match review documents against existing PR file-change revisions rather than arbitrary historical commits. src/github/pullRequestModel.ts:createReviewThread supplies path, line and side to AddReviewThread without a selected commit identifier. Browsing commit diffs therefore does not provide the requested complete commit-anchored review workflow.
- **Partial implementation was declined, not landed:** https://github.com/microsoft/vscode-pull-request-github/pull/8867 and https://github.com/microsoft/vscode-pull-request-github/pull/8866 are closed with merged=false. Neither PR proves implementation on main.

This issue has 28 upvotes, an On Deck milestone and a recent offer to contribute.
