# Issue #8836 — `Close` and `Comment` buttons should be the same as GitHub

[https://github.com/microsoft/vscode-pull-request-github/issues/8836](https://github.com/microsoft/vscode-pull-request-github/issues/8836)

## Summary

A real issue-description UX gap remains on main: the extension places a single `Close Issue` action to the left of `Comment`, while GitHub presents comment first and a split close action with selectable outcomes. The existing close path can post entered text, but it does not expose GitHub's close-reason choices or matching button layout.

## Change summary

Align the issue comment form's button order and close-action choices with GitHub's `Comment` and split close controls.

## Best solution

Update the issue description webview's comment actions to put `Comment` before a split close control, then carry the selected completed/not-planned/duplicate reason through the issue close API path while preserving the existing ability to submit entered text when closing.

## Evidence

- **current UI:** webviews/components/comment.tsx renders the standalone `Close Issue` button before the right-aligned comment action and exposes only `Comment` in ISSUE_COMMENT_METHODS; there is no split close-reason menu.
- **current close behavior:** webviews/components/comment.tsx passes the textarea value to close(), and src/github/issueOverview.ts creates that comment before calling the model's generic close operation. This partially supports closing with entered text but does not represent GitHub's completed, not-planned, or duplicate choices.
- **layout:** webviews/common/common.css makes `.comment-actions-right` grow and right-align its contents, leaving the separately rendered close button on the opposite side as reported.
- **related request:** https://github.com/microsoft/vscode-pull-request-github/issues/3568 is open and asks for the narrower comment-and-close workflow, but it does not own this report's broader button-order and close-reason requirements, so it is not a valid duplicate canonical.
- **existing capability check:** The contributed settings and current webview implementation contain no setting or command that changes the issue close-button layout or selects a GitHub close reason.
