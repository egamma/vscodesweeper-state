# Issue #5752 — Allow search-ing on only the content of the PR

[https://github.com/microsoft/vscode-pull-request-github/issues/5752](https://github.com/microsoft/vscode-pull-request-github/issues/5752)

## Summary

Keep this as the canonical request for PR-scoped code search and route it to review. Existing queries and diff-opening commands do not provide both requested search scopes; the related report was explicitly consolidated into this issue.

## Change summary

Provide search across files modified by a PR and a separate scope restricted to changed lines, including at least additions.

## Best solution

Provide discoverable PR-specific file and changed-line search scopes using the extension's PR change metadata and VS Code's search/editor surfaces. Establish how results distinguish added and deleted content without including unchanged lines in the diff-only scope.

## Plan brief

- **Likely files:** `package.json`, `src/commands.ts`, `src/github/pullRequestModel.ts`, `src/common/diffHunk.ts`, `src/view/inMemPRContentProvider.ts`
- **Validation:** Review a PR containing added, deleted and unchanged occurrences of one search term, plus an occurrence in an untouched file. File-scoped search must exclude the untouched file while retaining matches elsewhere in modified files; diff-scoped search must exclude unchanged lines and find additions. Verify the chosen deleted-line behavior and navigation to the correct file and revision.
- **Behavior:**

  > Reviewers need two search scopes: complete contents of files modified by the selected PR, and only the PR's changed lines. The changed-line scope must include added code; searching deleted code is also requested as a desirable capability. Matches in untouched files must not appear, and unchanged lines must not appear in the diff-only scope. Results should navigate to the relevant file and revision.
- **Trace:**

  > src/github/pullRequestModel.ts supplies PR file changes through getFileChangesInfo and fileChanges. Its openChanges method invokes vscode.changes, while pr.openAllDiffs in src/commands.ts opens individual diffs; neither supplies an explicit changed-line search scope. src/common/diffHunk.ts records addition, deletion and context lines with old/new positions, and src/view/inMemPRContentProvider.ts supplies virtual PR file content. The remaining uncertainty is the user-facing search integration across workspace files and virtual PR documents, not whether change metadata exists. The platform limitation discussed at https://github.com/microsoft/vscode-pull-request-github/issues/6240#issuecomment-2377374284 must be reassessed during design. Preserve existing workspace search and PR-list query semantics; https://github.com/microsoft/vscode-pull-request-github/issues/6240 was closed into this canonical request.
- **Open decisions:**
  - Should PR scopes appear in VS Code's Search view, the multi-diff editor, or a dedicated PR search surface?
  - Should the initial diff scope search additions only, or also deletions with results clearly identifying the old revision?
  - Should file-scoped search use the PR head revision consistently, or the working-tree contents when the PR is checked out?
