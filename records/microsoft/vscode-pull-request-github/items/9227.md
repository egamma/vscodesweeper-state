# Issue #9227 — Show the open PR for a linked worktree’s upstream branch when the local branch has a different name

[https://github.com/microsoft/vscode-pull-request-github/issues/9227](https://github.com/microsoft/vscode-pull-request-github/issues/9227)

## Summary

The requested capability remains missing: current main deliberately skips upstream PR discovery for differently named, unassociated linked-worktree branches. Keep this open for a review/git product decision; the linked implementation attempt was closed without merging.

## Change summary

Make an open PR discoverable from a linked worktree tracking its head branch under a different local name.

## Best solution

Expose the uniquely matching open upstream-head PR for review without restoring stale closed-PR associations. Decide whether discovery should automatically associate the local branch or present the upstream PR separately, then cover both active-branch discovery and first-activation behavior.
