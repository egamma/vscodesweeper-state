# Issue #7891 — PR Functionality Unresponsive

[https://github.com/microsoft/vscode-pull-request-github/issues/7891](https://github.com/microsoft/vscode-pull-request-github/issues/7891)

## Summary

Verified duplicate: the extension's inability to recover after connectivity returns is already tracked by the older, open offline-recovery issue. This report adds useful evidence that refresh commands do not recover from VPN-related timeouts and subsequent GraphQL failures.

## Change summary

Make pull-request functionality recover after transient connectivity failures without requiring a full VS Code window reload.

## Best solution

Consolidate recovery work in https://github.com/microsoft/vscode-pull-request-github/issues/2713, including reconnecting or safely recreating failed state when connectivity returns and making refresh commands trigger meaningful recovery.

## Vision fit

- **Fit:** aligned
- **Reason:** Resilient recovery preserves the extension's core in-editor GitHub workflow when its connection to GitHub is temporarily interrupted.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and the durable web-and-remote theme calls for reliable behavior in remote environments.
