# Issue #505 — Ability to filter PR commits by commit-hash range

[https://github.com/microsoft/vscode-pull-request-github/issues/505](https://github.com/microsoft/vscode-pull-request-github/issues/505)

## Summary

Arbitrary commit-range review remains missing: current commands offer all changes or changes since the last review, not selectable endpoints. The linked implementation was closed without merging, and neither related open issue owns this request's full scope.

## Change summary

Allow reviewers to select a commit-hash range within a pull request and inspect its combined changes.

## Best solution

Provide selectable comparison endpoints for the PR changes tree and file diffs while preserving existing all-changes and since-last-review behavior. Coordinate with the base-selection work without dropping this request's ability to stop before the PR head.

- **Fit:** aligned
- **Reason:** Selecting review ranges supports iterative, in-editor review without returning to GitHub.com.
- **Evidence:** The vision identifies the review flow and native in-editor reviewing as durable product themes.

## Plan brief

- **Likely files:** `package.json`, `src/commands.ts`, `src/github/pullRequestModel.ts`, `src/view/treeNodes/commitNode.ts`, `src/view/treeNodes/pullRequestNode.ts`, `src/view/reviewManager.ts`
- **Validation:** On a PR with several commits, select a range ending before the PR head and verify the changes tree and file diffs match that comparison, excluding later commits. Verify single-commit selection and that restoring all changes or changes since the last review preserves existing behavior.
- **Behavior:**

  > Reviewers need to inspect the combined changes from a chosen range of PR commits, including ranges that end before the current head. Single-commit selection must remain possible, and changing the selection must keep the changes tree and opened diffs consistent. Existing all-changes and since-last-review views must continue to work. The thread additionally asks about excluding commits brought in from main; whether that includes noncontiguous selection needs agreement.
- **Trace:**

  > src/commands.ts registers pr.showDiffSinceLastReview and pr.showDiffAll as boolean toggles on PullRequestModel. PullRequestModel.getRawFileChangesInfo in src/github/pullRequestModel.ts chooses either the PR base or latest review SHA and passes the current PR head into compareCommits; no arbitrary endpoints are represented on this path. CommitNode.getChildren in src/view/treeNodes/commitNode.ts supplies individual-commit browsing, not aggregated range selection. The proposed base-only design at https://github.com/microsoft/vscode-pull-request-github/issues/4618 and its closed, unmerged implementation at https://github.com/microsoft/vscode-pull-request-github/pull/8968 are useful prior analysis, not shipped coverage. Historical-head behavior needs tracing through tree refresh, editor content, and review-comment handling before implementation; preserve existing full-PR review behavior and do not assume individual-commit commenting or automatic checkout is part of this request.
- **Open decisions:**
  - Should selection support only contiguous commit ranges, or also exclude individual interior commits as requested in the follow-up?
