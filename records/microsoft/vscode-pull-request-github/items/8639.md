# Issue #8639 — Request for `>GitHub Pull Requests: Forget Pull Request`

[https://github.com/microsoft/vscode-pull-request-github/issues/8639](https://github.com/microsoft/vscode-pull-request-github/issues/8639)

## Summary

The requested cleanup workflow already exists through the resolved pull request's “Delete Branch...” action: it checks out and optionally pulls the configured post-done branch before deleting the selected local branch.

## Change summary

Add a command that checks out and pulls the default branch, then deletes the current branch after a pull request was merged on GitHub.

## Best solution

Keep the existing “Delete Branch...” action as the supported cleanup path rather than adding a second command for the same operation. With `githubPullRequests.postDone` set to `checkoutDefaultBranchAndPull`, selecting the local branch there performs the requested checkout, pull, and deletion sequence.

- **Reason:** Post-merge local cleanup supports the extension's goal of managing the GitHub pull-request workflow directly within VS Code.

  > Thanks for the detailed workflow and source pointers. This is already available from the pull request description after the PR is shown as merged: choose **Delete Branch...** and leave **Delete local branch** selected. The separate `githubPullRequests.deleteBranchAfterMerge` setting is only needed for automatic deletion when merging through the extension.
