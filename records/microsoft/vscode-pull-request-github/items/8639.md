# Issue #8639 — Request for `>GitHub Pull Requests: Forget Pull Request`

[https://github.com/microsoft/vscode-pull-request-github/issues/8639](https://github.com/microsoft/vscode-pull-request-github/issues/8639)

## Summary

A real capability gap remains: the existing checkout command switches and optionally pulls, but deliberately refuses to delete the current user's PR branch. Route this feature request to the git and UX areas.

## Change summary

Provide an explicit post-merge cleanup action that checks out and updates the default branch, then safely deletes the user's previous local PR branch.

## Best solution

Add an explicit command or opt-in post-done action that reuses `checkoutDefaultBranch()` and permits safe cleanup of the user's own branch after confirming the PR is merged or closed. Keep the current non-destructive behavior as the default.

## Evidence

- **current command behavior:** `pr.exit` in `src/commands.ts` checks out the configured done branch and then calls `cleanupAfterPullRequest`; `package.json` exposes it as "Checkout Default Branch".
- **source gap:** `src/github/folderRepositoryManager.ts` explicitly returns from `cleanupAfterPullRequest()` when the pull request author is the current user, so the command cannot delete the reporter's own branch.
- **existing settings incomplete:** `githubPullRequests.postDone` can checkout and pull, while `githubPullRequests.deleteBranchAfterMerge` is invoked after a successful merge performed through the extension; neither covers cleanup after merging on GitHub.
- **related request:** https://github.com/microsoft/vscode-pull-request-github/issues/8436 requests deleting a local branch immediately after PR creation, whereas this issue requests explicit cleanup after an external merge; the distinct timing and safety conditions leave separate product behavior to decide.
