# Issue #3462 — Support PR comments in notebooks

[https://github.com/microsoft/vscode-pull-request-github/issues/3462](https://github.com/microsoft/vscode-pull-request-github/issues/3462)

## Summary

Notebook-cell PR commenting remains an unmet, maintainer-accepted request. Keep this extension integration issue open alongside the related VS Code API work; displaying existing comments upstream does not fully cover creating comments in notebook diffs.

## Change summary

Allow reviewers to create PR comments on notebook code lines or cells in the notebook diff editor.

## Best solution

Resolve notebook-position mapping and commenting API support in microsoft/vscode, then integrate notebook-diff comment creation and display into this extension while preserving GitHub's file-line anchors.

- **Reason:** Notebook commenting extends the native in-editor review workflow to a widely used document format.
- **Evidence:** The product promises to review and manage GitHub pull requests directly in VS Code; the durable review-flow theme includes in-editor commenting, built on core platform surfaces.

## Plan brief

- **Likely files:** `src/view/treeNodes/pullRequestNode.ts`, `src/view/pullRequestCommentControllerRegistry.ts`, `src/view/reviewCommentController.ts`, `src/github/utils.ts`
- **Validation:** In a PR modifying an ipynb code cell, open the notebook diff, create a line or cell comment, submit it, and reopen the review. Verify that the comment retains the intended notebook location and corresponding GitHub file-line anchor; ordinary text-file commenting must remain unchanged.
- **Behavior:**

  > Reviewers cannot create PR comments on code lines or cells in notebook diffs. The completed feature should allow creating, submitting, and reopening comments at the intended notebook location while retaining valid GitHub anchors. Verify both browsing a PR and reviewing a checked-out PR, without changing ordinary text-file commenting.
- **Trace:**

  > src/view/treeNodes/pullRequestNode.ts::provideCommentingRanges and src/view/reviewCommentController.ts::provideCommentingRanges operate on file diff-hunk ranges. src/view/pullRequestCommentControllerRegistry.ts routes PR document providers, while src/github/utils.ts::createVSCodeCommentThreadForReviewThread creates URI/range-based threads without notebook mapping. The upstream discussion at https://github.com/microsoft/vscode/issues/214017 identifies the unresolved contract between core commenting, notebook serializers, and comment providers. Its display-focused request is related but does not replace this creation-focused extension issue. Planning must establish the available platform contract and its adoption requirements before treating this as a bounded extension implementation.
- **Open decisions:**
  - What public notebook-position mapping contract should connect serializers, VS Code commenting, and PR providers so notebook-cell locations and GitHub backing-file ranges can be translated in both directions?
