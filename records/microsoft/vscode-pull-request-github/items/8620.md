# Issue #8620 — Support line-level review progress within a PR diff

[https://github.com/microsoft/vscode-pull-request-github/issues/8620](https://github.com/microsoft/vscode-pull-request-github/issues/8620)

## Summary

Line-level review progress remains a real capability gap; existing Viewed commands operate on whole files. Route to review and UX for feedback on the contributor's prototype before an upstream PR.

## Change summary

Allow reviewers to mark selected diff ranges as reviewed and retain local progress for each PR revision.

## Best solution

Decide whether to accept local range-level progress, using the contributor's prototype to evaluate marker placement, accessibility, supported diff views, and revision-state retention. Preserve GitHub's separate file-level Viewed semantics.

## Vision fit

- **Fit:** aligned
- **Reason:** Local progress markers support reviewing large pull requests directly in the editor.
- **Evidence:** The public vision names in-editor review and the review flow as durable themes, anchored by the promise to review and manage GitHub pull requests directly in VS Code.

## Evidence

- **Existing capability does not cover the request:** package.json declares githubPullRequests.hideViewedFiles, pr.markFileAsViewed, pr.unmarkFileAsViewed, and pr.resetViewedFiles, but no viewedLines settings or selected-range Viewed commands. src/commands.ts:1801–1868 passes file paths to PullRequestModel.markFiles; src/github/pullRequestModel.ts:2348–2400 sends GitHub file-level Viewed mutations, not locally persisted line ranges.
- **Related review command:** src/commands.ts:1199–1201 registers pr.showDiffSinceLastReview by setting showChangesSinceReview. Comparing changes since a submitted review does not record partial progress through selected lines within the current revision.
- **Contributor-owned implementation candidate:** The October 11 comment on https://github.com/microsoft/vscode-pull-request-github/issues/8620 requests interaction and marker-placement feedback. Verified https://github.com/oja-dev/vscode-pull-request-github/pull/1 is open, unmerged, and targets the contributor's fork, not this repository. Its body describes opt-in gutter markers and workspaceState persistence per PR revision, file, and diff side; gutter coexistence remains unverified.
- **Canonical search:** Searches for line-level, reviewed lines, and review progress found no verified canonical owning this capability. https://github.com/microsoft/vscode-pull-request-github/issues/3514 concerns automatically marking entire files on open; https://github.com/microsoft/vscode-pull-request-github/issues/5931 concerns whole-file Viewed actions in the multi-file diff editor. Neither reports the same requested range-level progress.
- **History limitation:** The checkout is shallow with one available commit, so local history cannot establish exhaustive fix provenance. The inspected current settings and command implementations still expose file-level rather than line-level progress.
