# Issue #6700 — Folder diff view

[https://github.com/microsoft/vscode-pull-request-github/issues/6700](https://github.com/microsoft/vscode-pull-request-github/issues/6700)

## Summary

A real capability gap remains: the extension supports a unified diff for an entire pull request and recursive folder viewed-state controls, but cannot open a folder-scoped unified diff. Route this review workflow request to the tree-views and review areas.

## Change summary

Add a folder action that opens a unified diff containing only changed files beneath that folder.

## Best solution

Add a folder-level Open Changes command to `DirectoryTreeNode` and filter its descendant file-change models before invoking `vscode.changes`, reusing the existing PR-wide multi-diff implementation in `src/github/pullRequestModel.ts`.

## Evidence

- **current implementation:** `PullRequestModel.openChanges` in `src/github/pullRequestModel.ts` passes every PR change model to `vscode.changes`; it provides no path or subset parameter.
- **folder capability gap:** `src/view/treeNodes/directoryTreeNode.ts` builds folder hierarchies and recursively manages viewed-state checkboxes, but defines no command for opening its descendant files as a multi-diff.
- **command surface:** `package.json` contributes `pr.openChanges` only for pull-request and description nodes, while folder nodes have no corresponding context-menu or inline action.
