# Issue #6700 — Folder diff view

[https://github.com/microsoft/vscode-pull-request-github/issues/6700](https://github.com/microsoft/vscode-pull-request-github/issues/6700)

## Summary

A meaningful review-flow gap remains on current main: folders can be marked viewed as a group, but the multi-diff editor can only be opened for the entire pull request. Route this feature request to the review and tree-view owners.

## Change summary

Add a folder action that opens the multi-diff editor with only the pull-request changes beneath that folder.

## Best solution

Add an Open Changes action to DirectoryTreeNode that recursively collects its file-change descendants and passes only those changes to a generalized PullRequestModel.openChanges implementation. Preserve the existing whole-PR command and folder checkbox behavior.

## Evidence

- **current multi-diff scope:** src/github/pullRequestModel.ts:1601-1621 implements PullRequestModel.openChanges by calling getChangeModels and passing every returned change to vscode.changes; it has no folder or subset parameter.
- **missing folder action:** src/view/treeNodes/directoryTreeNode.ts defines folder hierarchy, sorting, and viewed-state checkboxes but no command for opening the folder's descendants in a multi-diff editor; package.json exposes pr.openChanges only for pull-request and description tree items.
- **partial existing capability:** src/view/treeNodes/treeUtils.ts recursively processes DirectoryTreeNode descendants when its checkbox changes, so marking a whole folder viewed is already supported, but this does not provide the requested folder-scoped Open Changes view.
- **canonical search:** The closest open issue, https://github.com/microsoft/vscode-pull-request-github/issues/5931, concerns marking or collapsing reviewed files inside the multi-diff editor and does not own the distinct request to construct a folder-filtered multi-diff.
