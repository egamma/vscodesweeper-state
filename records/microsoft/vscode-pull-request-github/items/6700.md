# Issue #6700 — Folder diff view

[https://github.com/microsoft/vscode-pull-request-github/issues/6700](https://github.com/microsoft/vscode-pull-request-github/issues/6700)

## Summary

Folder-scoped multi-file diffs remain missing on main; existing folder checkboxes cover bulk marking, but not reviewing a folder's changes together. Route this independently supported request to review and explorer.

## Change summary

Provide an Open Changes action on PR folders that opens a consolidated diff containing only that folder's changed files.

## Best solution

Extend the native PR review experience with a folder-scoped multi-diff while preserving whole-PR Open Changes and existing folder viewed-state controls. Settle how the new view interacts with hidden viewed files before implementation.

  > A reviewer can open a PR folder's changed files together in the same multi-file diff experience used by whole-PR Open Changes. - **Trace:**

  > PullRequestModel.openChanges in src/github/pullRequestModel.ts constructs URI tuples for all PR change models and invokes vscode.changes. The pr.openChanges registration in src/commands.ts and its package.json menu conditions accept PR-level contexts rather than DirectoryTreeNode. DirectoryTreeNode stores recursive children and compresses single-child directory chains; TreeUtils.processCheckboxUpdates already handles bulk folder viewed-state changes. FilesCategoryNode.getChildren filters viewed files before constructing directory nodes when githubPullRequests.hideViewedFiles is enabled, so displayed descendants can differ from all changed files under a folder. No execution was performed in the read-only checkout. Preserve existing whole-PR behavior and viewed-state semantics; https://github.com/microsoft/vscode-pull-request-github/issues/5931 is related multi-diff viewed-state work, not a canonical for this feature.
- **Open decisions:**
  - When githubPullRequests.hideViewedFiles is enabled, should folder Open Changes include every changed file under that folder, or only the files currently visible in the tree?
