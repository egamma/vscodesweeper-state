# Issue #7983 — Permalinks in feature branches on forks should fallback to upstream main for unmodified lines

[https://github.com/microsoft/vscode-pull-request-github/issues/7983](https://github.com/microsoft/vscode-pull-request-github/issues/7983)

## Summary

A real permalink capability gap remains on main: remote selection requires the generated commit to exist on an upstream branch and does not compare the selected lines with upstream content. The request should remain open and be routed to the git and issues areas.

## Change summary

Generate durable upstream permalinks for unchanged selections on fork feature branches, optionally searching an ordered set of preferred long-lived branches.

## Best solution

Extend the permalink selection path in src/issues/util.ts to compare the selected file range against ordered upstream refs and use an upstream commit when the range is unchanged, while retaining the fork commit for modified content. Coordinate the configurable default-branch portion with https://github.com/microsoft/vscode-pull-request-github/issues/4765, which overlaps but does not cover the requested automatic range-aware fallback.

- **original behavior:** https://github.com/microsoft/vscode-pull-request-github/issues/1781 was completed by https://github.com/microsoft/vscode-pull-request-github/pull/1816 using the convention that the current commit must exist upstream; a maintainer later confirmed that requirement in https://github.com/microsoft/vscode-pull-request-github/issues/1781#issuecomment-1690663388.
