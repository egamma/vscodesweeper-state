# Issue #7983 — Permalinks in feature branches on forks should fallback to upstream main for unmodified lines

[https://github.com/microsoft/vscode-pull-request-github/issues/7983](https://github.com/microsoft/vscode-pull-request-github/issues/7983)

## Summary

The requested selection-aware upstream fallback is not implemented: current permalinks choose a repository containing the selected commit, not an upstream revision containing unchanged lines. Route to the issues/git areas; the related default-branch request does not cover this full behavior.

## Change summary

Prefer upstream default or configured long-lived branches for unchanged selected code, retaining fork links when that code is modified.

## Best solution

Define selection-aware upstream linking in src/issues/util.ts, preserving accurate line anchors and distinguishing immutable permalinks from moving branch links. Coordinate with the default-branch linking request without treating it as coverage for content-aware fallback.

## Plan brief

- **Likely files:** `src/issues/util.ts`, `src/issues/issueFeatureRegistrar.ts`, `package.json`, `package.nls.json`
- **Validation:** Use a fetched upstream repository and a divergent published fork branch. Select unchanged lines, including lines shifted by insertions elsewhere, and verify the upstream URL resolves to the exact selected content; select modified lines and verify fork fallback. Exercise configured default/release-branch preference and confirm existing head-link behavior remains unchanged.
- **Behavior:**

  > Users sharing unchanged code from a fork feature branch should receive an accurate upstream link when that code exists on a preferred long-lived branch. Code unavailable unchanged upstream should retain a fork link. Acceptance checks must cover shifted line numbers, modified selections, and ordered default/release-branch preference. The resulting URL must display the selected content, not merely reuse its local line numbers.
- **Trace:**

  > src/issues/issueFeatureRegistrar.ts registers the permalink and head-link commands separately. In src/issues/util.ts, createSinglePermalink selects a commit and getBestPossibleUpstream delegates to getUpstream, whose remote lookup requires branches containing that commit; this cannot detect unchanged selections on divergent commits. createSingleGitHubLink instead builds a moving current-branch URL. No configuration supplies ordered content-aware fallback branches. The existing upstream behavior is documented at https://github.com/microsoft/vscode-pull-request-github/issues/1781#issuecomment-1690663388; https://github.com/microsoft/vscode-pull-request-github/issues/4765 is related but narrower. Preserve existing head-link semantics and accurate anchors; uncertainty starts at whether the enhanced permalink remains immutable or intentionally follows an upstream branch.
- **Open decisions:**
  - Should upstream fallback produce an immutable commit-SHA permalink selected from the preferred branch, or a moving branch-name link, and should that behavior alter the existing permalink command or be opt-in?

## Evidence

- **Current permalink path:** src/issues/issueFeatureRegistrar.ts registers issue.copyGithubPermalink and delegates to permalink generation. In src/issues/util.ts:305–360, createSinglePermalink normally selects HEAD.commit and emits /blob/<commitHash>; getUpstream at lines 135–214 searches remote branches using contains: commitHash. Neither path compares the selected lines with upstream content or remaps line numbers.
- **Existing capabilities do not cover the request:** package.json declares issue.copyGithubPermalink and issue.copyGithubHeadLink. src/issues/util.ts:429–464 implements head links using the current branch and getSimpleUpstream. The configuration surface has no ordered permalink fallback-branch list; githubPullRequests.overrideDefaultBranch changes a default branch, while githubPullRequests.remotes controls PR-fetch remotes, not selection-aware link resolution.
- **Earlier upstream support is narrower:** https://github.com/microsoft/vscode-pull-request-github/issues/1781 is closed, and https://github.com/microsoft/vscode-pull-request-github/pull/1816 is merged. The maintainer explains at https://github.com/microsoft/vscode-pull-request-github/issues/1781#issuecomment-1690663388 that upstream selection requires fetched upstream history containing the current HEAD commit. This does not cover unchanged selections on a divergent feature branch.
- **Closest open request is not a canonical:** https://github.com/microsoft/vscode-pull-request-github/issues/4765 is open in On Deck and requests an explicit default-branch link command; its discussion also requests remote selection. - **Branch deletion premise needs clarification:** Current createSinglePermalink emits commit-SHA URLs, unlike the feature-branch URL described in the report. Branch-name URLs are produced by createSingleGitHubLink. The upstream preview/accessibility goal remains unmet even though branch deletion alone does not establish a defect in the permalink command.
