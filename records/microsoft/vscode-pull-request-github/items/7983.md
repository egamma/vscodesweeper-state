# Issue #7983 — Permalinks in feature branches on forks should fallback to upstream main for unmodified lines

[https://github.com/microsoft/vscode-pull-request-github/issues/7983](https://github.com/microsoft/vscode-pull-request-github/issues/7983)

## Summary

A real permalink gap remains for fork feature branches: current selection considers whether the entire feature commit exists upstream, not whether the selected lines are unchanged. Route this to the git area.

## Change summary

Prefer durable upstream permalinks for unchanged selected lines while retaining fork links for modified content.

## Best solution

Enhance the permalink selection in src/issues/util.ts to compare the selected content against configured long-lived upstream branches, then link to an immutable upstream commit containing that content. Preserve the current fork commit when the selection differs upstream.

- **Fit:** aligned

## Evidence

- **current source:** src/issues/util.ts:135-206 selects a remote only by asking which configured remote branch contains the complete commitHash; it does not compare the selected lines or file content with upstream branches.
- **permalink construction:** src/issues/util.ts:328-359 derives one commit hash from HEAD or the file log and uses that same hash with the selected remote, so a fork-only feature commit cannot fall back based on unchanged lines.
- **existing capability check:** package.json exposes Copy GitHub Permalink and Copy GitHub Head Link, but no setting or command for preferred permalink branches. The open https://github.com/microsoft/vscode-pull-request-github/issues/4765 requests an explicit default-branch link, which is only partial coverage and does not provide this issue's conditional unchanged-line fallback.
- **prior implementation:** https://github.com/microsoft/vscode-pull-request-github/pull/1816 implemented upstream selection when the current commit exists there; this request extends that behavior to selections unchanged from another upstream commit.
