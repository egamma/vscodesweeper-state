# Issue #6165 — Unclear behavior when having two changes, one inside a comment and one outside

[https://github.com/microsoft/vscode-pull-request-github/issues/6165](https://github.com/microsoft/vscode-pull-request-github/issues/6165)

## Summary

Keep open as team-authored review-flow polish. The behavior is intentional given file-level checkout constraints, but the mixed-success workflow remains unclear and the Backlog milestone preserves it for a future UX decision.

## Change summary

When only some working-tree changes can be converted into review suggestions, the converted changes remain in the local diff without an option to revert them.

## Best solution

Improve the partial-conversion experience in `src/view/reviewManager.ts`, either by safely reverting converted hunks rather than whole files or by making the warning explicitly explain why all local changes are retained.
