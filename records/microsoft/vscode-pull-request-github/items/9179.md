## Evidence

- **Repository-selection defect:** src/github/repositoriesManager.ts:205–234, getManagerForFile, sorts managers by root-path length but returns a manager matching the PR URI's remoteName at lines 223–224 without checking the document path. Multiple unrelated repositories with origin therefore collide; selection need not be repository B.
- **Content-provider collision:** src/view/inMemPRContentProvider.ts stores, reads, and disposes providers solely by numeric PR number. tryRegisterNewProvider resolves that number against the selected manager's remote and closes over its PR/file changes; readFile can also reuse an already registered provider from another repository. This directly supports the reported wrong PR and missing-content outcome.
- **URI identity:** src/common/uri.ts:35–44 and 461–490 show that PRUriParams contains prNumber and remoteName but no repository identity. toPRUri does preserve the source document path, which the remote-name shortcut currently bypasses.
- **Open implementation candidate:** https://github.com/microsoft/vscode-pull-request-github/pull/9190 was verified OPEN and explicitly declares Fixes #9179. It addresses folder selection and repository-scoped provider caching, but expressly excludes persisted selection and window-reload restoration. An open linked fixing PR bars a completed close and competing agent work.
- **Related but not duplicate:** https://github.com/microsoft/vscode-pull-request-github/issues/8969 was verified OPEN. It concerns approval against another worktree's HEAD and resolving threads through another controller, not separate repositories' identically numbered PR content or persisted restoration; it does not own this report's full scope.
