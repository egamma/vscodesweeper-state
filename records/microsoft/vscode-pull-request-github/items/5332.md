# Issue #5332 — Clicking PR title looses focus

[https://github.com/microsoft/vscode-pull-request-github/issues/5332](https://github.com/microsoft/vscode-pull-request-github/issues/5332)

## Summary

Keep open and route through the upstream/vscode lane: the inconsistent first-click focus behavior remains on main, but the extension lacks the VS Code API needed to preserve focus conditionally without compromising screen-reader accessibility.

## Change summary

Opening a pull request description with a single mouse click moves focus from the PR tree into the newly created webview instead of retaining tree focus.

## Best solution

VS Code should expose either the active accessibility mode or suitable webview-opening/click-modifier semantics to extensions. The description-opening path can then retain tree focus for an ordinary mouse click while moving focus for keyboard activation and screen-reader users.

## Vision fit

- **Fit:** aligned

## Evidence

- **maintainer diagnosis:** The discussion establishes that pr.openDescription cannot receive tree click modifiers or use vscode.open because it opens a webview; maintainers also confirmed that extensions cannot dynamically read the accessibilityModeEnabled context value.
- **reopened state:** The issue was reopened on 2024-03-20 after the earlier out-of-scope close, and then moved to Backlog because the conditional accessibility behavior requires new VS Code API.

- **partial prior behavior change:** https://github.com/microsoft/vscode-pull-request-github/commit/dc489e1ac028c27369da71cd81aeb147f7f4bb39 introduced preserveFocus for revealing an existing description panel, but creation of the initial webview still follows the focus-taking path.
