# Issue #7049 — Support filtering the files view to only show files with comments

[https://github.com/microsoft/vscode-pull-request-github/issues/7049](https://github.com/microsoft/vscode-pull-request-github/issues/7049)

## Summary

A real capability gap remains: the pull-request changes tree can hide files marked as viewed, but it cannot filter the hierarchy to files containing review comments. Keep the request open and route it to the review/tree-view owners.

## Change summary

Add a filter to the pull-request files tree that preserves the directory hierarchy while showing only files with comments.

## Best solution

Add a comments-only toggle for the Files category in the pull-request changes tree, filtering file nodes using the pull request's current review threads while preserving both tree and flat layouts. The filter should refresh when review threads or comments change and coexist predictably with the existing hide-viewed-files filter.

- **Evidence:** The durable themes explicitly include both "The review flow" and "Trees, queries, and views," while the product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code."

## Evidence

- **current tree behavior:** src/view/treeNodes/filesCategoryNode.ts builds the Files hierarchy from ReviewModel.localFileChanges and filters only on ViewedState when githubPullRequests.hideViewedFiles is enabled; it has no comments-only filter.
- **comment data available:** src/view/treeNodes/fileChangeNode.ts already associates each file node with pull-request comments and reviewThreadsCache by file path, so the requested filter has an extension-owned data source.
- **existing capability is partial:** package.json exposes githubPullRequests.hideViewedFiles, described as hiding files marked as viewed. That requires manual viewed-state management and does not cover the central request to identify files with comments.
- **candidate canonical rejected:** https://github.com/microsoft/vscode-pull-request-github/issues/4315 is open but requests commit-wise reviewing and editable commit checkouts; it does not own filtering the PR files hierarchy by comments.
- **linked core issue is distinct:** https://github.com/microsoft/vscode/issues/252168 concerns the Comments view losing populated comments after an extension-host restart and is closed; it does not track this files-tree filtering capability.
