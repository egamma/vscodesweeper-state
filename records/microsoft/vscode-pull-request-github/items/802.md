# Issue #802 — Deal with a force-pushed PR branch

[https://github.com/microsoft/vscode-pull-request-github/issues/802](https://github.com/microsoft/vscode-pull-request-github/issues/802)

## Summary

Still present on current main: divergent PR branches are offered a generic pull without detecting a force-push or offering a safe reset path. Keep this oldest, team-authored On Deck issue open as the canonical report and route it to the git area.

## Change summary

Handle force-pushed checked-out PR branches without merging the obsolete local history into the rewritten remote branch.

## Best solution

In `FolderRepositoryManager.checkBranchUpToDate`, distinguish fast-forward updates from divergent histories. Preserve normal pull for fast-forwards, but for divergence offer a clearly destructive, guarded reset to the PR head while protecting dirty working trees and local-only commits.
