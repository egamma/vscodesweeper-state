# Issue #802 — Deal with a force-pushed PR branch

[https://github.com/microsoft/vscode-pull-request-github/issues/802](https://github.com/microsoft/vscode-pull-request-github/issues/802)

## Summary

Still present on current main: after detecting that a checked-out PR branch is behind, the extension offers an ordinary pull without distinguishing a force-pushed, divergent history. The resulting merge conflict leaves a common review workflow requiring manual Git recovery, so this should remain open and be classified as a bug.

## Change summary

Handle force-pushed PR branches without merging the obsolete local history into the rewritten remote branch.

## Best solution

In the PR branch-update path in `src/github/folderRepositoryManager.ts`, distinguish fast-forward updates from divergent histories after fetching. Keep ordinary pull for fast-forwards, but for divergence provide a clearly destructive, confirmed reset-to-PR-head action while protecting local changes and commits; the existing open issue https://github.com/microsoft/vscode-pull-request-github/issues/1466 should be consolidated into this older canonical.
