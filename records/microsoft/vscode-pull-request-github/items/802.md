# Issue #802 — Deal with a force-pushed PR branch

[https://github.com/microsoft/vscode-pull-request-github/issues/802](https://github.com/microsoft/vscode-pull-request-github/issues/802)

## Summary

The update notification still invokes an ordinary pull without handling rewritten branch history or offering a guarded reset. Keep this accepted, team-authored report open and route it to git; an open PR targets the same notification flow.

## Change summary

Updating a force-pushed PR branch should avoid conflicting obsolete commits and offer an explicitly confirmed way to match the remote without silently losing local work.

## Best solution

Provide safe handling of rewritten PR history in FolderRepositoryManager's update-notification flow, preserving local work unless the user explicitly agrees to discard it. Review the overlapping implementation candidate at https://github.com/microsoft/vscode-pull-request-github/pull/8228 against this report's local-commit safety requirements before considering the issue resolved.
