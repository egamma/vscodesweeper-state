# Issue #5163 — Allow "Files Changed" in new PR to diff against file on disk

[https://github.com/microsoft/vscode-pull-request-github/issues/5163](https://github.com/microsoft/vscode-pull-request-github/issues/5163)

## Summary

The pre-creation preview still compares read-only branch snapshots, not editable files on disk. Route this accepted feature request to review and git; the earlier merged refactor did not deliver the requested behavior, and no verified canonical covers it.

## Change summary

Allow editing local files against the proposed PR base from Files Changed before creating or pushing a PR.

## Best solution

Provide a working-tree-backed comparison for the checked-out branch in the PR creation preview, so users can refine branch changes without first creating a draft PR. Preserve read-only historical comparisons and distinguish local edits from changes actually included in the eventual PR.

- **Reason:** Editing branch changes before creating a PR advances the native in-editor review and checkout workflow.

## Plan brief

- **Likely files:** `src/view/compareChangesTreeDataProvider.ts`, `src/view/createPullRequestDataModel.ts`, `src/view/treeNodes/fileChangeNode.ts`, `src/view/gitHubContentProvider.ts`
- **Validation:** With a checked-out feature branch containing committed changes and additional uncommitted edits, open Create Pull Request without creating a PR. Open Files Changed, verify the right side displays local contents, edit and save, and confirm the actual workspace file changes without an automatic commit or push. Repeat with an unpublished branch, and verify historical commit comparisons remain read-only.
- **Behavior:**

  > Before creating a PR, users should be able to compare their checked-out branch changes against the proposed base and edit the actual local files from Files Changed. Saving an edit must update the workspace file without requiring a draft PR or automatically committing or pushing. Both published and unpublished local branches should support the workflow, while historical commit comparisons remain read-only.
- **Trace:**

  > CompareChangesFilesTreeProvider in src/view/compareChangesTreeDataProvider.ts chooses GitHub or local branch comparisons through CreatePullRequestDataModel.getCompareHasUpstream. Both paths construct GitHubFileChangeNode in src/view/treeNodes/fileChangeNode.ts, whose vscode.diff command uses virtual snapshot URIs on both sides. src/view/gitHubContentProvider.ts reads branch snapshots and reports them read-only, with an explicit reference to https://github.com/microsoft/vscode-pull-request-github/issues/5163. The model lists committed branch differences rather than working-tree differences, so enabling editing alone would not establish what the creation preview represents. Preserve commit-node history and comparisons of branches that are not checked out; do not enable API commits or automatic staging as a substitute for editing files on disk. https://github.com/microsoft/vscode-pull-request-github/pull/5804 supplies related infrastructure but predates the reopen and does not complete this feature.
- **Open decisions:**
  - Should Files Changed become a live base-to-working-tree list that includes files changed only locally, or retain the committed PR file list with a clearly identified local-edit comparison mode?

## Evidence

- **Current preview remains snapshot-based:** src/view/treeNodes/fileChangeNode.ts:428–473 constructs GitHubFileChangeNode diffs with githubpr or gitpr URIs on both sides, including a headBranch snapshot rather than a repository file URI. src/view/gitHubContentProvider.ts returns FilePermission.Readonly in both ChangesContentProvider.stat and GitContentProvider.stat; the former explicitly links this issue as deferred work.
- **Working-tree contents are not the comparison source:** src/view/createPullRequestDataModel.ts gitFiles uses repository.diffBetween(baseRemote/baseBranch, compareBranch), while gitHubFiles obtains the GitHub branch comparison. GitContentProvider.readFile reads repository.show(branch, file), not the current file on disk.
- **Existing capabilities do not cover the request:** package.json provides githubPullRequests.quickDiff for checked-out PRs and githubPullRequests.createDefaultBaseBranch for base selection, but neither enables editable pre-creation disk comparisons. src/commands.ts:2156–2190 registers review.diffWithPrHead and review.diffLocalWithPrHead against an existing GitFileChangeNode.pullRequest; the latter compares PR head with local contents, not the proposed base before a PR exists.
- **Prior implementation and reopen:** https://github.com/microsoft/vscode-pull-request-github/pull/5804 merged on 2024-03-04 and describes its GitHub API commit method and creation-model refactor as originally part of this request. The issue timeline records reopening on 2024-03-22, so that earlier implementation cannot justify a completed close.

None reports the same editable pre-creation file comparison requested here.
