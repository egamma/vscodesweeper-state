# Issue #2895 — [feature request]: Allow specific repositories to create issue branch on fork even when you have push access

[https://github.com/microsoft/vscode-pull-request-github/issues/2895](https://github.com/microsoft/vscode-pull-request-github/issues/2895)

## Summary

The requested fork option remains missing: starting work only offers to create a fork when upstream push permission is absent. Route to issues and git for a product decision; existing branch settings do not cover this preference.

## Change summary

Allow starting work on an issue through a fork even when the user can push to the upstream repository.

## Best solution

Provide an explicit fork choice or repository-scoped preference in the start-working flow, retaining current behavior by default. Distinguish local branch creation from the remote used to publish it.

- **Reason:** This supports native issue workflows for contributors who prefer forks despite having upstream write access.

## Evidence

- **Permission-gated fork option:** src/github/folderRepositoryManager.ts:3022–3067, findUpstreamForItem, sets needsFork only for Read, Triage, or Unknown permissions when no writable fork remote is configured. Write, Maintain, and Admin permissions do not trigger a fork offer.
- **Start-working call site:** src/issues/issueFeatureRegistrar.ts:835–894, doStartWorking, calls tryOfferToFork only when needsFork is true. issue.startWorkingBranchPrompt uses the same flow and changes the branch-name prompt, not the fork policy.
- **Existing capabilities are partial:** package.json and package.nls.json expose githubIssues.useBranchForIssues, githubIssues.issueBranchTitle, and githubIssues.workingBaseBranch for branch creation, naming, and base selection. githubPullRequests.remotes controls fetched remotes, and githubPullRequests.upstreamRemote controls adding upstream for existing forks; none requests fork creation despite upstream write access. findUpstreamForItem recognizes an already-configured writable fork, but that requires prior setup.
- **Local versus remote branches:** src/issues/currentIssue.ts, createOrCheckoutBranch, creates or checks out a local branch using manager.repository.createBranch(branch, true). Fork creation and remote configuration are separate operations in folderRepositoryManager.ts; the missing capability is an explicit fork workflow, not local branch creation itself.
