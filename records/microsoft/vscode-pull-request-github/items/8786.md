# Issue #8786 — Repeatedly asked to sign in again using GitHub

[https://github.com/microsoft/vscode-pull-request-github/issues/8786](https://github.com/microsoft/vscode-pull-request-github/issues/8786)

## Summary

Still present on main: every qualifying 401 or “Bad credentials” response forces a modal re-authentication, with only a 60-second cooldown, so an outage or persistently unreachable Enterprise server can repeatedly block the user. This is an extension-owned authentication error-handling defect and should remain open.

## Change summary

Transient or persistent GitHub authentication failures repeatedly trigger a modal sign-in flow that does not restore service and can recur across every open workspace.

## Best solution

Refine the centralized authentication-error path in `src/github/credentials.ts` and `src/github/loggingOctokit.ts` so it distinguishes a genuinely stale session from transient service or connectivity failures, and suppresses repeated forced sign-in after cancellation or an unsuccessful re-authentication. Preserve automatic recovery for actually revoked credentials while using a non-modal error state for unavailable GitHub or Enterprise endpoints.

## Evidence

- **source reproduction:** `src/github/loggingOctokit.ts` classifies every REST status 401, GraphQL network status 401, and matching error message as an authentication error; `RateLogger.logApiError` forwards each such failure to the credential store.
- **repeated modal path:** `CredentialStore.handleAuthError` in `src/github/credentials.ts` calls `initialize(..., { forceNewSession: { detail: reason } })`; its suppression expires after `AUTH_ERROR_COOLDOWN_MS = 60_000`, allowing the same persistent failure to reopen the modal indefinitely.
- **introducing change:** https://github.com/microsoft/vscode-pull-request-github/commit/a0d196e06bcb9c300f0ccc53888fc77bd7e547c7 introduced centralized forced re-authentication on API 401 responses shortly before the report; the behavior remains in current main.
- **independent confirmations:** The thread contains numerous confirmations on extension versions 0.148.0 and 0.152.0, including repeated prompts after GitHub's incident was reported mitigated and a reproducible Enterprise case whenever its server is unreachable off VPN.
- **related incident:** A maintainer attributed the narrower same-day report to a GitHub incident at https://github.com/microsoft/vscode-pull-request-github/issues/8785#issuecomment-4691227962, but later reports here demonstrate that the extension's repeated-modal behavior also persists outside that incident.
