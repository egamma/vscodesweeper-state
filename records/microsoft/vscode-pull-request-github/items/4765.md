# Issue #4765 — Allow copying a github link to the default branch

[https://github.com/microsoft/vscode-pull-request-github/issues/4765](https://github.com/microsoft/vscode-pull-request-github/issues/4765)

## Summary

A real capability gap remains on current main: existing commands target a commit or the checked-out branch, not the repository's default branch. Keep the On Deck request open and route it to the GitHub-link and git owners.

## Change summary

Add a command for copying a GitHub file link that targets the repository's default branch and, where applicable, its upstream repository.

## Best solution

Add a distinct default-branch link command and share provider alongside the permalink and HEAD variants, resolving the appropriate GitHub remote and its `default_branch` metadata without changing the semantics of the existing commands. The command should support the same file, selection, and context-menu surfaces as the current link commands.

## Vision fit

- **Fit:** aligned
- **Reason:** Reliable links to canonical upstream code strengthen the extension's in-editor GitHub workflow and support real-world fork and multi-remote repository shapes.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and the durable themes explicitly include working with forks and multi-remote setups.

## Evidence

- **existing commands:** package.json contributes `issue.copyGithubPermalink` and `issue.copyGithubHeadLink` across editor, file, and explorer sharing menus, but contributes no default-branch link command or corresponding setting.
- **current behavior:** src/issues/shareProviders.ts implements `GitHubPermalinkShareProvider` with a commit hash and `GitHubHeadLinkShareProvider` with `getHEAD`; `getHEAD` uses the current local branch whenever one is checked out and consults GitHub's `default_branch` only in detached-HEAD state.
- **legacy command path:** src/issues/util.ts similarly builds HEAD links from `repository.state.HEAD.name`, falling back to remote `default_branch` only when no current branch name exists, so it does not provide the requested explicit default-branch behavior.
- **canonical search:** No broader open canonical was found. https://github.com/microsoft/vscode-pull-request-github/issues/7983 concerns automatic permalink fallback for unchanged lines on forks, which is related but does not own this request for an explicit default-branch link command.
