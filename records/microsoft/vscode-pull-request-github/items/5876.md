# Issue #5876 — Issues, go to linked code functionality is wonky.

[https://github.com/microsoft/vscode-pull-request-github/issues/5876](https://github.com/microsoft/vscode-pull-request-github/issues/5876)

## Summary

Keep open and route to issues: current code still uses fixed permalink line numbers for local navigation, which does not follow moving TODOs. The maintainer acknowledged the limitation and suggested improving link generation for locally changed files.

## Change summary

Make issue-to-code navigation useful for TODOs created before committing and moved by subsequent edits.

## Best solution

Define how TODO-created issues should navigate to evolving local code while preserving GitHub permalinks as historical references. Include the maintainer's suggested handling of locally changed files; suppressing misleading links alone would not address navigation after TODOs move.

- **Fit:** aligned
- **Reason:** Reliable navigation between TODO comments and issues supports the extension's native in-editor issues workflow.
- **Evidence:** The durable issues-integration theme explicitly includes todo-comment code actions and issue hovers.

## Plan brief

- **Likely files:** `src/issues/issueFeatureRegistrar.ts`, `src/issues/issueLinkLookup.ts`, `src/issues/util.ts`
- **Validation:** Create an issue from a TODO in a locally modified tracked file, inspect its generated body, then insert lines above the TODO and invoke issue.goToLinkedCode. Verify navigation follows the agreed local-versus-historical contract, and repeat with committed code and a TODO that has been removed.
- **Behavior:**

  > Issues created from TODOs should provide understandable code references when the TODO is not yet published and when later edits move it. GitHub permalinks remain references to committed snapshots, not live local positions. Acceptance checks should cover an uncommitted TODO, a committed TODO moved by inserted lines, and a removed TODO, with navigation and fallback behavior agreed by the maintainer.
- **Trace:**

  > src/issues/issueFeatureRegistrar.ts registers issue.goToLinkedCode to openCodeLink and inserts the created issue number or URL into the originating TODO. Its createTodoIssueBody quotes locally changed TODO text but still appends a permalink from src/issues/util.ts:createSinglePermalink. src/issues/issueLinkLookup.ts:findCodeLinkLocally resolves the repository and file, then uses the permalink's original line numbers without consulting its commit hash or the TODO reference. This explains why local edits leave navigation at the old location. Preserve the historical meaning of GitHub permalinks and unrelated permalink-sharing commands. The maintainer's suggested omission of links for changed files is recorded at https://github.com/microsoft/vscode-pull-request-github/issues/5876#issuecomment-2034259152; the unresolved boundary is whether local navigation should follow the issue-bearing TODO or the historical snapshot.
- **Open decisions:**
  - Should Go to Linked Code follow the current TODO containing the issue reference, or open the permalink's historical code when local positions have changed?
  - For TODOs not yet published, should the issue retain a historical permalink alongside quoted local context, or omit that permalink; what navigation fallback should users receive when no current TODO remains?

## Evidence

- **maintainer direction:** https://github.com/microsoft/vscode-pull-request-github/issues/5876#issuecomment-2034259152 confirms the reported behavior is currently expected, explains that GitHub permalinks require published code, and suggests omitting links when files have local changes. This is an acknowledged improvement opportunity, not grounds for a decline close.
- **current navigation:** src/issues/issueLinkLookup.ts: findCodeLinkLocally extracts the permalink's original line numbers and returns them unchanged for the working-tree file; openCodeLink selects that range. It does not use the captured commit hash to map positions or locate the TODO's inserted issue reference.
- **creation behavior:** src/issues/issueFeatureRegistrar.ts: createTodoIssueBody quotes the TODO when the file appears in workingTreeChanges, but still appends createSinglePermalink's result. src/issues/util.ts: createSinglePermalink constructs a commit-based URL with the supplied line range; it does not provide an evolving local anchor.
- **existing capability check:** package.json declares githubIssues.createIssueTriggers, githubIssues.createInsertFormat, issue.createIssueFromSelection, and issue.goToLinkedCode. documentation/IssueFeatures.md documents permalink creation and insertion of the issue number into the TODO. These support creating and identifying issues, but neither the settings nor the traced navigation command cover moved TODO locations.
- **canonical search:** Searches for permalink, TODO, and uncommitted-code reports found no verified canonical with the same observable symptom. https://github.com/microsoft/vscode-pull-request-github/issues/3966 is an older open Backlog request about TODO issue-creation UI, not stale local navigation; https://github.com/microsoft/vscode-pull-request-github/issues/7983 concerns fork/upstream permalink selection, a different problem.
