# Issue #8716 — Use same UI for checkout in worktree as built-in VS Code worktree feature

[https://github.com/microsoft/vscode-pull-request-github/issues/8716](https://github.com/microsoft/vscode-pull-request-github/issues/8716)

## Summary

The requested UI consistency remains missing: PR worktree checkout still opens a save dialog, whereas built-in Git offers an editable worktree-path input. Route to git and ux; the merged default-directory improvement does not cover this request.

## Change summary

Use the built-in Git-style worktree destination input for PR checkout instead of immediately opening the operating-system dialog.

## Best solution

Make PR worktree destination selection consistent with built-in Git while preserving PR-specific branch selection, cancellation, and checkout behavior. Evaluate whether the built-in picker can be shared without invoking its separate branch-selection flow.

## Evidence

- **Current extension flow:** src/github/worktree.ts, checkoutPRInWorktree, unconditionally calls vscode.window.showSaveDialog with 'Select Worktree Location' before fetching and creating the worktree. src/commands.ts routes both pr.pickInWorktree and pr.pickInWorktreeFromDescription through this function.
- **Existing-capability check:** package.json contributes both PR worktree commands but no destination-picker setting. githubPullRequests.defaultDeletionMethod.selectWorktree controls cleanup, not creation UI; neither command offers the requested input.
- **Built-in comparison:** https://github.com/microsoft/vscode/blob/main/extensions/git/src/commands.ts: _createWorktree calls getWorktreePath, which uses window.createInputBox with an editable default path and an optional destination-browse button. The extension's src/api/api.d.ts exposes createWorktree options but no standalone destination-picker API.
- **Related change is partial:** https://github.com/microsoft/vscode-pull-request-github/pull/8711 is merged and groups destinations under <repo>.worktrees/pr-<number>. Current src/github/worktree.ts contains that default but still uses showSaveDialog, so it does not implement UI parity.
- **Canonical and implementation search:** Repository issue searches for worktree and worktree dialog found no other open report owning this destination-input request. An open-PR search for 8716 returned no results; the supplied timeline also contains no linked implementation.
