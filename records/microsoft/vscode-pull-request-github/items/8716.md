# Issue #8716 — Use same UI for checkout in worktree as built-in VS Code worktree feature

[https://github.com/microsoft/vscode-pull-request-github/issues/8716](https://github.com/microsoft/vscode-pull-request-github/issues/8716)

## Summary

The UI inconsistency remains on current main: PR worktree checkout uses a native save dialog, while VS Code's built-in Git command provides an editable Quick Input with an inline folder picker. This is valid worktree-flow polish and should be routed to the git and UX areas.

## Change summary

Use the built-in-style editable path picker instead of the native system dialog when checking out a pull request into a worktree.

## Best solution

Make the PR checkout flow use the same Quick Input path experience as VS Code's Git worktree command while retaining the PR-specific branch selection and default path. Prefer a reusable Git extension API if VS Code exposes one; otherwise mirror the focused path-picker behavior in src/github/worktree.ts without invoking the full branch-selection command.
