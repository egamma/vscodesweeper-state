# Issue #4655 — Continues to process queued requests after rate limit has been hit

[https://github.com/microsoft/vscode-pull-request-github/issues/4655](https://github.com/microsoft/vscode-pull-request-github/issues/4655)

## Summary

Still present on main: exhausting the extension's concurrency bulkhead neither establishes a cooldown nor suppresses repeated notifications. The overflow path can continue issuing requests, so this should remain open and route to the GitHub/performance owners.

## Change summary

Stop processing repeated refresh requests and avoid repeated notifications after the extension's internal API concurrency limit is reached.

## Best solution

Add shared flood-state handling in `src/github/loggingOctokit.ts` that coalesces the warning and temporarily rejects or cancels additional refresh-generated API work, then resets safely after outstanding requests drain or a defined cooldown expires.
