# Issue #4655 — Continues to process queued requests after rate limit has been hit

[https://github.com/microsoft/vscode-pull-request-github/issues/4655](https://github.com/microsoft/vscode-pull-request-github/issues/4655)

## Summary

Still present on current main: reaching the internal concurrency limit rejects each additional request independently, repeatedly shows the notification, and does not cancel or pause requests already in flight. This team-authored backlog issue should remain open.

## Change summary

After repeated refreshes hit the internal API-request limit, outstanding work continues and the same rate-limit notification appears multiple times.

## Best solution

Coalesce or cancel overlapping tree refresh work and treat a request flood as one episode, showing one notification and suppressing further API work until the active workload drains. The limiter behavior is in `src/github/loggingOctokit.ts`, while preventing concurrent refreshes may require separating or coordinating the PR tree model and `vscode.TreeView` refresh lifecycle.
