# Issue #2201 — Allow to see commits of a PR without checking out to it

[https://github.com/microsoft/vscode-pull-request-github/issues/2201](https://github.com/microsoft/vscode-pull-request-github/issues/2201)

## Summary

The requested capability remains missing on current main: an unchecked-out PR expands directly to its aggregate file changes, while commit and per-commit file nodes are available only in the separate checked-out PR changes view. Keep this original feature request open and route it to the tree/review owners.

## Change summary

Show a PR's commits and each commit's changed files in the PR list without requiring the PR to be checked out.

## Best solution

Extend the unchecked-out PR tree in `src/view/treeNodes/pullRequestNode.ts` with a commit grouping that reuses the remote commit and changed-file support in `CommitsNode` and `CommitNode`, without requiring a local checkout. The design should preserve convenient access to the existing aggregate file list.

## Evidence

- **current PR-list behavior:** `src/view/treeNodes/pullRequestNode.ts` implements `PRNode.getChildren()` by resolving and returning only aggregate file-change nodes; it does not create a `CommitsNode` or any commit-level children.
- **existing partial capability:** `src/view/treeNodes/repositoryChangesNode.ts` adds both `FilesCategoryNode` and `CommitsNode`, but `src/view/prChangesTreeDataProvider.ts` populates that view through the active review-mode pull request, so this does not provide the requested commit tree for an unchecked-out PR in the PR list.
- **reusable implementation:** `src/view/treeNodes/commitsCategoryNode.ts` obtains commits through `PullRequestModel.getCommits()`, and `src/view/treeNodes/commitNode.ts` obtains each commit's files through `getCommitChangedFiles()`, showing that the remote-data building blocks already exist.
- **original canonical:** Closed issues https://github.com/microsoft/vscode-pull-request-github/issues/2594 and https://github.com/microsoft/vscode-pull-request-github/issues/2716 were explicitly consolidated into this issue by maintainers; the newer open https://github.com/microsoft/vscode-pull-request-github/issues/4315 requests a broader commit-wise review workflow, so it is not a better canonical for closing this original request.
- **unmerged implementation attempt:** https://github.com/microsoft/vscode-pull-request-github/pull/2245 referenced and attempted to fix this issue but was closed without merging, so it does not establish implementation on main.
