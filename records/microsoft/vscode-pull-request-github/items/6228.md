# Issue #6228 — Plugin does not work with SSH aliases for SSH remotes

[https://github.com/microsoft/vscode-pull-request-github/issues/6228](https://github.com/microsoft/vscode-pull-request-github/issues/6228)

## Summary

The gap remains on main for Enterprise configurations where the SSH transport hostname differs from the web/API hostname. The remote is resolved to the SSH endpoint and then incorrectly probed as an HTTPS GitHub endpoint.

## Change summary

SSH aliases can prevent the extension from discovering and authenticating Enterprise repositories, particularly when SSH and API services use different hostnames.

## Best solution

Separate the resolved SSH transport host from the configured Enterprise web/API host in remote discovery. Add coverage for multi-pattern SSH aliases and configurations where `github-enterprise.uri` differs from the SSH `HostName`.

## Evidence

- **current source:** src/common/protocol.ts resolves an SSH alias through ~/.ssh/config but stores its HostName as Protocol.host; src/common/protocol.ts:135-143 then normalizes that transport host into an HTTPS URL.
- **API probing path:** src/authentication/githubServer.ts:63-73 recognizes github-enterprise.uri only when its authority equals the parsed remote host; otherwise it probes the parsed host over HTTPS, matching the reported lookup failure when the SSH and API hosts differ.
- **confirmed configuration:** A second reporter confirmed the behavior on extension 0.112.0 and explained that the web/API hostname deliberately does not serve SSH; setting github-enterprise.uri did not resolve it: https://github.com/microsoft/vscode-pull-request-github/issues/6228#issuecomment-3039925283
- **existing support is incomplete:** SSH alias resolution was introduced by https://github.com/microsoft/vscode-pull-request-github/pull/621 and repaired by https://github.com/microsoft/vscode-pull-request-github/commit/17575c0978c7400cb00fbe3f7bac8fa422b2ec60, but current tests cover aliases resolving to the same GitHub hostname, not distinct SSH and API endpoints.
