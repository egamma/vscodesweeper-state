- **Behavior:**

  > Repositories cloned using SSH aliases should be recognized without changing their git remotes or temporarily removing SSH configuration. Verify both the multi-name Enterprise Host stanza and managed-account aliases. Git operations must retain their configured SSH transport and identity selection. - **Trace:**

  > src/common/remote.ts parses repository URLs through Protocol, after independently resolving gitconfig insteadOf substitutions. Protocol.parseSshProtocol calls src/env/node/ssh.ts resolve; its default resolver reads ~/.ssh/config once and delegates matching to src/env/browser/ssh.ts resolverFromConfig. Basic alias tests exist, so the original configuration failure has not been conclusively diagnosed. Protocol.normalizeUri converts the resolved SSH hostname into an HTTPS host, which computeAllGitHubRemotes sends to GitHubManager.isGitHub; github-enterprise.uri only recognizes a matching authority, not a separate transport host. Preserve git remote URLs, SSH identity behavior, and existing insteadOf support. https://github.com/microsoft/vscode-pull-request-github/issues/4551 concerns the separate gitconfig substitution path, not proof of completion here.
- **Open decisions:**
  - When an Enterprise repository's SSH hostname differs from its HTTPS API hostname, what explicit association should the extension honor so it discovers the correct server without treating unrelated remotes as Enterprise repositories?
