# Issue #6228 — Plugin does not work with SSH aliases for SSH remotes

[https://github.com/microsoft/vscode-pull-request-github/issues/6228](https://github.com/microsoft/vscode-pull-request-github/issues/6228)

## Summary

A real gap remains on main: SSH aliases are parsed, but the resolved SSH transport hostname is also used as the HTTPS/API hostname, which breaks Enterprise configurations where those endpoints differ. Route this to the git, Enterprise, and authentication areas rather than closing it as already supported.

## Change summary

Repositories cloned through SSH host aliases are not recognized when the alias or its resolved transport hostname differs from the GitHub web/API hostname.

## Best solution

Separate SSH transport-host resolution from GitHub API-host selection: use SSH configuration to identify the repository while honoring the configured Enterprise URI for API and authentication requests. Add regression coverage for both ordinary aliases and Enterprise installations with distinct SSH and API endpoints.

## Evidence

- **source trace:** src/common/protocol.ts resolves an SSH alias through src/env/node/ssh.ts, assigns the resulting HostName to Protocol.host, and normalizeUri() then constructs an HTTPS URI from that same host. A transport-only SSH HostName is therefore incorrectly treated as the GitHub API host.
- **coverage gap:** src/test/common/protocol.test.ts covers aliases only when HostName resolves directly to github.com; it has no case where the SSH transport hostname and web/API hostname differ.
- **confirmed configuration:** https://github.com/microsoft/vscode-pull-request-github/issues/6228#issuecomment-3030497171 confirms the failure on extension 0.112.0 where the web/API hostname does not serve SSH, reports that github-enterprise.uri does not correct the association, and documents a configuration-dependent workaround.
- **established intent:** The extension intentionally added SSH-config alias handling in https://github.com/microsoft/vscode-pull-request-github/commit/aed3cd926587ae48f31b629b7de6c5d2350f6b2e and repaired it in https://github.com/microsoft/vscode-pull-request-github/commit/17575c0978c7400cb00fbe3f7bac8fa422b2ec60, so alias support is existing intended behavior rather than a new capability.
- **canonical search:** The only open repository issue found for the central SSH-alias problem is https://github.com/microsoft/vscode-pull-request-github/issues/6228; the related https://github.com/microsoft/vscode-pull-request-github/issues/6095 is closed and describes broader SSH/authentication symptoms without owning this specific host-resolution gap.
