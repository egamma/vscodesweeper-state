# Issue #6950 — Lost, overridden or misplaced pending comments

[https://github.com/microsoft/vscode-pull-request-github/issues/6950](https://github.com/microsoft/vscode-pull-request-github/issues/6950)

## Summary

The reported loss and reassignment of pending review comments is serious and has multiple independent confirmations, but no current-version reproduction, logs, or deterministic sequence identifies which synchronization path is failing. Additional diagnostics are needed before the extension-side defect can be isolated.

## Change summary

Pending review comments can disappear, exchange contents, duplicate, or move between lines and files, particularly while requests are delayed or the pull request head changes.

## Best solution

Preserve each optimistic pending comment's identity through delayed and out-of-order API responses and PR-head refreshes, rather than reconciling it only by a mutable file path and mapped line. Add regression coverage that delays concurrent AddReviewThread responses and updates the PR head while multiple draft comments are pending.

## Evidence

- **independent confirmations:** Three additional users reported the behavior through June 2026, but none supplied extension/VS Code versions, logs, or a reproducible sequence that confirms it on the current release.
- **current reconciliation path:** src/view/reviewCommentController.ts stores optimistic additions in _pendingCommentThreadAdds and associates an arriving API thread by repository-relative path plus a line remapped through the current diff. That makes delayed responses during head or working-tree changes a plausible risk, but source inspection alone does not prove the reported cross-file and content-swapping behavior.
- **API sequencing:** src/github/pullRequestModel.ts:createReviewThread queries the pending review ID separately for every comment before issuing AddReviewThread, while controller calls may run concurrently. The report lacks GitHub Pull Request output showing the mutation ordering or Enterprise response errors needed to confirm this mechanism.
- **related reports are not canonical:** Open issue https://github.com/microsoft/vscode-pull-request-github/issues/8374 concerns displayed line-side placement, while https://github.com/microsoft/vscode-pull-request-github/issues/7556 concerns an unsaved editor draft being discarded after merge; neither owns the broader pending-comment synchronization and data-loss scenario here.
