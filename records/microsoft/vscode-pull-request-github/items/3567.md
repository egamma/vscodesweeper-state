# Issue #3567 — Selecting Revert Selected Ranges in Github pull request plane seems weird

[https://github.com/microsoft/vscode-pull-request-github/issues/3567](https://github.com/microsoft/vscode-pull-request-github/issues/3567)

## Summary

A real capability gap remains: the built-in Git command operates against working-tree-to-HEAD diffs and is unsuitable for PR diffs, while the extension still has no PR-aware selected-range revert command. Route this existing feature request to the review and git areas.

## Change summary

Provide a safe way to revert selected ranges in a pull-request diff to the PR's base branch.

## Best solution

Add an extension-owned command for PR diff editors that maps the selected ranges against the pull request's base commit and updates the working file accordingly, with context restrictions that make its PR-specific semantics clear.

- **Fit:** aligned
- **Reason:** A PR-aware range-revert operation strengthens the extension's native in-editor review workflow without attempting to replicate a GitHub website surface.
- **Evidence:** The durable themes explicitly include the review flow and the git plumbing needed for real-world pull-request workflows; the product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code."
