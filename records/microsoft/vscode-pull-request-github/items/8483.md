# Issue #8483 — Open existing issue as raw markdown file

[https://github.com/microsoft/vscode-pull-request-github/issues/8483](https://github.com/microsoft/vscode-pull-request-github/issues/8483)

## Summary

A real capability gap remains: existing issue descriptions can only be edited in the overview webview's textarea, so editor-native capabilities such as Copilot completions are unavailable. Route this to the issues and description-page owners.

## Change summary

Allow an existing issue's raw Markdown description to be opened and edited in a normal VS Code text editor.

## Best solution

Add an editor-backed command for existing issue descriptions that loads the raw Markdown and saves changes through the existing IssueModel edit path, while preserving permission checks and refreshing the overview after a successful update.

- **Evidence:** The public product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and issues integration is identified as a durable investment area.

## Evidence

- **current edit surface:** webviews/components/comment.tsx implements description editing with an HTML textarea in EditComment; this is a webview control rather than a VS Code text document and therefore does not provide the requested editor-native completion experience.
- **existing update path:** src/github/issueOverview.ts handles editDescription by passing the submitted webview text to IssueModel.edit, so the API update mechanism exists but is not exposed through an editor-backed document.
- **creation-only editor:** src/issues/issueFeatureRegistrar.ts creates a Schemes.NewIssue text document for composing new issues, but package.json exposes no corresponding command or setting for opening an existing issue body as editable Markdown.
- **canonical search:** The open https://github.com/microsoft/vscode-pull-request-github/issues/6606 concerns creating pull-request descriptions in a full editor, while https://github.com/microsoft/vscode-pull-request-github/issues/5382 concerns Markdown preview support; neither owns the requested existing-issue editing workflow.
