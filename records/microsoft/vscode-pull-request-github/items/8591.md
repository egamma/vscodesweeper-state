# Issue #8591 — Auto-refresh PR comments when they are visible

[https://github.com/microsoft/vscode-pull-request-github/issues/8591](https://github.com/microsoft/vscode-pull-request-github/issues/8591)

## Summary

A real comment-refresh gap remains on current main: visible inline threads and the Comments view do not trigger polling for remote replies. Keep the request open and route it to the comments/review owners.

## Change summary

Automatically refresh PR comments at a configurable interval while their inline threads or the Comments view are visible.

## Best solution

Add visibility-aware polling for the active pull request's review-thread cache, using a configurable interval and avoiding requests while neither inline comments nor the Comments view are visible. Preserve the existing manual refresh command as an immediate fallback.

- **Evidence:** The durable themes explicitly include "The review flow — in-editor commenting" and resolved-thread handling, while the product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code."

## Evidence

- **current refresh path:** src/commands.ts registers pr.refreshComments as a manual command that reinitializes review-thread caches; no timer or visibility listener invokes this path.
- **polling does not cover replies:** src/view/reviewManager.ts polls every 5–30 minutes, but hasNewPullRequests() compares only maximum PR numbers. A new reply on an existing PR does not change that value, so the poll does not refresh its comments.
- **existing setting is insufficient:** package.json declares githubPullRequests.webviewRefreshInterval, but its implementation is used by src/github/issueOverview.ts for overview webviews and does not refresh editor comment threads or the VS Code Comments view.
