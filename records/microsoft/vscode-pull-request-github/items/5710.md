# Issue #5710 — Resolve Conversation with Commit

[https://github.com/microsoft/vscode-pull-request-github/issues/5710](https://github.com/microsoft/vscode-pull-request-github/issues/5710)

## Summary

The commit-linked resolution workflow remains missing, and the team proposed an alternative the reporter accepted. Route to comments/review and settle whether the later multi-conversation, next-commit proposal belongs in the initial scope.

## Change summary

Associate review-conversation resolution with a fixing commit by automatically posting its SHA and resolving the selected conversation or conversations.

## Best solution

Provide commit-linked conversation resolution without replacing VS Code's existing commit flow. Start from the accepted existing-commit picker proposal, with a maintainer decision on whether deferred batch resolution should also be included.

## Plan brief

- **Likely files:** `package.json`, `package.nls.json`, `src/commands.ts`, `src/view/reviewCommentController.ts`, `src/view/pullRequestCommentController.ts`, `src/github/pullRequestModel.ts`
- **Validation:** In a test PR containing multiple commits and unresolved conversations, invoke the agreed action and verify the intended conversation receives exactly one reply containing the chosen fixing SHA and becomes resolved; unrelated conversations remain unchanged. Cancel selection and verify no reply or resolution occurs. Exercise both checked-out review and browse modes. If deferred batch resolution is accepted, mark two conversations, commit through SCM, and verify both reference that commit while conversations in another PR remain unchanged.
- **Behavior:**

  > Users should be able to associate a fixing commit with a review conversation without manually copying its SHA and separately resolving the thread. The accepted workflow selects an existing PR commit, posts 'Resolved with <commit sha>', and resolves that conversation while retaining the normal SCM commit flow. Cancellation must leave the conversation unchanged, and unrelated conversations must not be affected. The reporter later requested marking several conversations for the next commit; whether that additional workflow is included requires a maintainer scope decision.
- **Trace:**

  > src/commands.ts registers pr.resolveReviewThread and dispatches to the handler returned by resolveCommentHandler; the current path has no commit-selection step. ReviewCommentController.resolveReviewThread and PullRequestCommentController.resolveReviewThread can create a supplied reply before resolving the GitHub thread. PullRequestModel.getCommits retrieves the PR's commit list, already used by CommitsCategoryNode. package.json exposes ordinary resolution in conversation menus but no commit-linked action. The language-model resolution tool only resolves by threadId and does not cover commit annotation. Preserve the ordinary resolve action, existing SCM commit behavior, and separation between PRs. The accepted flow is documented in https://github.com/microsoft/vscode-pull-request-github/issues/5710#issuecomment-1991397726; uncertainty begins with the later deferred multi-conversation proposal and its public interaction contract.
- **Open decisions:**
  - Should the initial feature provide only the accepted existing-commit picker, or also allow marking multiple conversations for automatic resolution with the next SCM commit?

## Evidence

- **Accepted product direction:** The maintainer proposed selecting an existing PR commit, posting 'Resolved with <commit sha>', and resolving the conversation; the reporter accepted that compromise. The maintainer subsequently invited implementation using that flow: https://github.com/microsoft/vscode-pull-request-github/issues/5710#issuecomment-1991397726. This acceptance rules out a decline close.
- **Later scope proposal:** In the supplied May 8, 2025 comment, the reporter requested marking multiple conversations for resolution on the next SCM commit. The provided discussion contains no maintainer acceptance of this expanded workflow; it is distinct from the previously accepted existing-commit picker.
- **Existing capability does not cover the request:** package.json contributes pr.resolveReviewThread to conversation menus, but no commit-selection or next-commit resolution action. src/commands.ts:1277–1333 routes ordinary resolution through threadAndText and the comment handler without choosing a commit or generating a SHA reply. githubPullRequests.commentExpandState and githubPullRequests.defaultCommentType control presentation and comment submission, not commit-linked resolution.
- **Available technical primitives:** src/view/reviewCommentController.ts:888–905 and src/view/pullRequestCommentController.ts:530–544 support creating a supplied reply before resolving a thread. src/github/pullRequestModel.ts:1532–1549 retrieves commits for the specific PR, and src/view/treeNodes/commitsCategoryNode.ts already consumes that list. These primitives exist, but the requested user-facing orchestration does not.
- **Automation is only partial coverage:** src/lm/tools/resolveReviewThreadTool.ts exposes github-pull-request_resolveReviewThread with a threadId input and directly resolves the thread. It neither selects a fixing commit nor posts a commit-linked reply, so it addresses part of the final comment's automation interest without satisfying the central request.
