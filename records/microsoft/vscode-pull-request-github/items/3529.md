# Issue #3529 — "Start working on issue" should appear in command palette

[https://github.com/microsoft/vscode-pull-request-github/issues/3529](https://github.com/microsoft/vscode-pull-request-github/issues/3529)

## Summary

The requested command remains absent from current main. The existing start-working commands require issue context and are explicitly hidden from the command palette, while the only implementation attempt closed without merging.

## Change summary

Add a command-palette action that accepts an issue number or URL and starts work without requiring the issue to appear in a configured query.

## Best solution

Add a palette-visible command in package.json and implement it in src/issues/issueFeatureRegistrar.ts by selecting the repository, prompting for an issue number or URL, resolving the IssueModel, and passing it to the existing doStartWorking flow. Consolidate the newer identical request at https://github.com/microsoft/vscode-pull-request-github/issues/4636 into this older Backlog item.

- **Reason:** This improves the native issue workflow by letting users move directly from a GitHub notification to working on that issue inside VS Code.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," and issues integration is a durable investment theme.
