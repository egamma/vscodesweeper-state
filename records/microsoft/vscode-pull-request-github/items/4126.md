# Issue #4126 — Ability to customise the repositories shown in the 'Pull Requests' and 'Issues' sections

[https://github.com/microsoft/vscode-pull-request-github/issues/4126](https://github.com/microsoft/vscode-pull-request-github/issues/4126)

## Summary

A real customization gap remains for large multi-repository workspaces: current main offers neither extension-specific repository exclusion nor explicit ordering across both trees. Route this to the tree-view area.

## Change summary

Allow users to hide or reorder repositories shown at the root of the Pull Requests and Issues trees.

## Best solution

Add workspace-scoped repository visibility and ordering configuration, then apply it consistently when constructing root nodes in `src/view/prsTreeDataProvider.ts` and `src/issues/issuesView.ts`. This should affect these views without requiring repositories to be disabled globally through VS Code's Git settings.

## Evidence

- **current PR tree:** `src/view/prsTreeDataProvider.ts:566-594` maps every GitHub-backed folder manager directly to a root `WorkspaceFolderNode`; there is no visibility filter or configurable sort.
- **current ordering:** `src/github/repositoriesManager.ts:127-149` orders detected repositories using workspace-folder insertion order, without a user-defined repository order.
- **partial Issues behavior:** `src/issues/issuesView.ts:201-220` now hides repositories only when all issue queries return no matches, implementing the narrower https://github.com/microsoft/vscode-pull-request-github/issues/8474 rather than selective user customization.
- **existing settings gap:** `package.json` exposes `githubPullRequests.queries` and `githubIssues.queries`, but neither setting controls which workspace repository roots are displayed or their order. The maintainer-supported `git.ignoredRepositories` workaround in https://github.com/microsoft/vscode-pull-request-github/issues/5906 disables Git repository detection more broadly and does not cover view-specific ordering.
