# Issue #2713 — Recover from being offline

[https://github.com/microsoft/vscode-pull-request-github/issues/2713](https://github.com/microsoft/vscode-pull-request-github/issues/2713)

## Summary

The recovery gap remains on current main: the existing PR and issue refresh commands reload query data but do not retry repository discovery after an offline startup. Keep the request open and route it to the GitHub and tree-view owners.

## Change summary

Allow the extension to recover its pull-request and issue views after connectivity returns without reloading the entire VS Code window.

## Best solution

Add a reconnect or full-refresh path that calls `RepositoriesManager.refreshRepositories()` before refreshing the PR and issue data, and expose it through the existing view refresh controls or a shared command. This should retry remote resolution while preserving the rest of the extension host.

## Vision fit

- **Fit:** aligned
- **Reason:** Recovering GitHub-backed views without restarting VS Code supports the extension's core in-editor GitHub workflow and the durable trees, queries, and views theme.
- **Evidence:** The product promise is to "Review and manage your GitHub pull requests and issues directly in VS Code," with trees, queries, and views identified as a durable investment area.

## Evidence

- **PR refresh is partial:** `src/view/prsTreeDataProvider.ts` registers `pr.refreshList`, but the command only clears `PrsTreeModel` caches and refreshes query results; it does not call `RepositoriesManager.refreshRepositories()` to retry remote discovery.
- **issue refresh is partial:** `src/issues/issueFeatureRegistrar.ts` implements `issue.refresh` through `StateManager.refreshCacheNeeded()`, which refreshes issue data for already-known folder managers rather than reinitializing repositories.
- **recovery API exists but is not exposed here:** `src/github/repositoriesManager.ts` defines `refreshRepositories()` by rerunning `FolderRepositoryManager.updateRepositories(false, true)`, while `src/extension.ts` invokes it for authentication-session changes; no corresponding connectivity recovery command or listener was found.
- **canonical search:** Repository issue searches found no other open issue owning reconnection after offline startup. https://github.com/microsoft/vscode-pull-request-github/issues/706 concerns suppressing offline errors rather than recovering once connectivity returns.
