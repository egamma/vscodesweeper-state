# Issue #2713 — Recover from being offline

[https://github.com/microsoft/vscode-pull-request-github/issues/2713](https://github.com/microsoft/vscode-pull-request-github/issues/2713)

## Summary

Keep open: existing refresh commands do not establish recovery from offline startup without reloading VS Code. Later maintainer discussion confirms the recovery gap, but the related report does not establish an exact duplicate of this startup-and-both-views scenario.

## Change summary

Allow PR and issue data to recover after starting VS Code offline and reconnecting, without reloading the whole window.

## Best solution

Provide reliable extension-local recovery that retries initialization and restores both views after connectivity returns. Coordinate with the related connectivity work while retaining offline startup as an explicit acceptance scenario.

- **Reason:** Recovering the native PR and issue views preserves the extension's central in-editor GitHub workflow.

- **Behavior:**

  > Starting VS Code offline currently leaves the reporter's PR and issue views loading even after connectivity returns; issue refresh does not recover them. Users should be able to restore both views without restarting VS Code or unrelated extensions. Acceptance must cover offline startup followed by reconnection, repeated recovery, and retries while still offline.
- **Trace:**

  > pr.refreshList in src/view/prsTreeDataProvider.ts clears query caches and refreshes tree results, while issue.refresh in src/issues/issueFeatureRegistrar.ts delegates to StateManager.refreshCacheNeeded. PR rendering is gated on repository initialization, and src/issues/stateManager.ts waits for RepositoriesLoaded during authenticated initialization. RepositoriesManager.refreshRepositories and FolderRepositoryManager.updateRepositories form a separate initialization path. Source inspection establishes these boundaries but does not prove which network failure prevents progress. Preserve existing queries, authentication sessions, and unrelated extension state.
