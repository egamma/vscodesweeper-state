# Issue #2713 — Recover from being offline

[https://github.com/microsoft/vscode-pull-request-github/issues/2713](https://github.com/microsoft/vscode-pull-request-github/issues/2713)

## Summary

The offline-recovery gap remains on current main: existing refresh commands reload view data but do not re-resolve repositories after offline startup. Keep the accepted On Deck request open and route it to the PR tree, issues, and GitHub integration areas.

## Change summary

Allow the extension to recover its PR and issue views after VS Code starts offline and connectivity later returns, without reloading the window.

## Best solution

Add a unified recovery path that reruns repository resolution through RepositoriesManager, then refreshes the PR tree, issue state, and related GitHub-backed views. It could be exposed as a command and invoked automatically when a failed request later succeeds.

## Evidence

- **PR refresh limitation:** src/view/prsTreeDataProvider.ts registers pr.refreshList, but the command only clears the PR model cache and calls refreshAllQueryResults; it does not invoke RepositoriesManager.refreshRepositories to retry remote resolution.
- **issue refresh limitation:** src/issues/issueFeatureRegistrar.ts implements issue.refresh by marking the issue cache for refresh, without reinitializing repositories that failed to resolve during offline startup.
- **available recovery primitive:** src/github/repositoriesManager.ts exposes refreshRepositories(), which reruns FolderRepositoryManager.updateRepositories, but the view refresh commands are not wired to it.
