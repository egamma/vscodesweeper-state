# Issue #8484 — Selecting `Approved` from the dropdown should not auto submit

[https://github.com/microsoft/vscode-pull-request-github/issues/8484](https://github.com/microsoft/vscode-pull-request-github/issues/8484)

## Summary

The review dropdown still submits immediately. Earlier maintainer decisions explain that behavior, but do not resolve this report's alternative request for clearer styling; route the remaining UX decision to review and ux.

## Change summary

Make selecting a review type defer submission, or visually distinguish the immediate-submit menu from a selection-only dropdown.

## Best solution

Make the narrow review control clearly communicate whether choosing an option submits the review. The team should evaluate the styling alternative against the existing intentional immediate-submit behavior before changing submission semantics.

- **Reason:** Clear review controls support a predictable native in-editor review experience.

## Evidence

- **Current review behavior:** webviews/components/contextDropdown.tsx opens a VS Code context menu in narrow layouts. webviews/components/comment.tsx supplies review command contexts; src/github/activityBarViewProvider.ts registers review.approve and its approvePullRequestCommand calls doReviewCommand with ReviewType.Approve. This is an action menu, not a pending review-type selector.
- **Existing-capability check:** The package.json configuration surface exposes no setting to defer submission when selecting a review type. githubPullRequests.defaultCommentType chooses single-comment versus review mode, not dropdown submission semantics. ContextDropdown spreads actions into buttons above 375 pixels, but that does not cover the requested narrow-layout behavior.
- **Merge comparison:** webviews/components/merge.tsx:MergeSimple uses Dropdown. The review control instead uses ContextDropdown, confirming the distinction behind the reporter's comparison.
