# Issue #8819 — Missing documentation: corporate proxy and enterprise certificate configuration for GHE environments

[https://github.com/microsoft/vscode-pull-request-github/issues/8819](https://github.com/microsoft/vscode-pull-request-github/issues/8819)

## Summary

The documentation gap remains on current main: neither the README nor the wiki FAQ explains corporate proxy, private-CA, safe TLS, or SSO configuration. The request should remain open and route to the Enterprise and authentication owners, with the broader proxy implementation tracked separately.

## Change summary

Add corporate GitHub Enterprise setup and troubleshooting documentation covering proxies, custom certificate authorities, safe TLS handling, SSO authorization, and air-gapped limitations.

## Best solution

Add a Corporate/Enterprise Setup section to README.md or the linked wiki that accurately documents the extension's current HTTPS_PROXY behavior, supported certificate-trust mechanisms, SSO authorization behavior, log-based troubleshooting, and known air-gapped limitations. Clearly distinguish current support from the unresolved VS Code http.proxy integration tracked by https://github.com/microsoft/vscode-pull-request-github/issues/701, and explicitly discourage disabling TLS verification.

## Evidence

- **documentation gap:** README.md only states that GitHub Enterprise is supported and points to the wiki FAQ; it contains no proxy, custom-CA, TLS troubleshooting, SSO-authorization, or air-gapped deployment guidance. The current wiki Home.md likewise only lists supported Enterprise versions and general OAuth information.
- **current proxy behavior:** src/env/node/net.ts creates the extension's HTTPS agent from process.env.HTTPS_PROXY and otherwise uses Node's global HTTPS agent; src/github/credentials.ts and src/authentication/githubServer.ts pass that agent to Octokit and host-detection requests. No use of VS Code's http.proxy or http.systemCertificates settings was found.
- **separate proxy work:** https://github.com/microsoft/vscode-pull-request-github/issues/701 remains open and specifically tracks reading VS Code's http.proxy setting. It covers only part of this broader documentation request, so it is not a canonical duplicate.
- **SSO behavior:** src/github/credentials.ts contains an explicit SAML reauthorization path, while https://github.com/microsoft/vscode-pull-request-github/issues/8818 documents the maintainer position that authorized OAuth tokens do not normally refresh and repeated invalidation may be organization policy. This is useful material for accurate troubleshooting guidance.
