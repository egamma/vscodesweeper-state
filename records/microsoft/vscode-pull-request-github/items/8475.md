# Issue #8475 — Manage ISSUES / PROJECTS

[https://github.com/microsoft/vscode-pull-request-github/issues/8475](https://github.com/microsoft/vscode-pull-request-github/issues/8475)

## Summary

A meaningful issue-management gap remains: the extension can assign issues to Projects v2, but it cannot edit project fields such as Status or set an issue type during creation. The broader request is not fully owned by any open canonical, so it should remain open and be routed to the issues and GitHub integration areas.

## Change summary

Manage organization projects and edit issue metadata such as project Status and issue Type without leaving VS Code.

## Best solution

Extend the issue creation and overview flows to edit supported Projects v2 fields, beginning with Status, while keeping full project-board replication as a separate product-scope decision. Coordinate the issue-type creation portion with https://github.com/microsoft/vscode-pull-request-github/issues/8817 rather than implementing that subset independently.

- **Evidence:** The README promise is: "Review and manage your GitHub pull requests and issues directly in VS Code."

## Evidence

- **existing partial support:** Current main supports selecting organization/repository Projects v2 and adding or removing an issue from them through src/github/folderRepositoryManager.ts, src/github/issueOverview.ts, src/github/issueModel.ts, and webviews/components/sidebar.tsx.
- **remaining project-field gap:** src/github/issueModel.ts only uses addProjectV2ItemById/remove mutations for project membership; the issue overview exposes project selection but no mutation or UI for Projects v2 fields such as Status.
- **remaining issue-type gap:** src/github/graphql.ts and src/github/utils.ts read an issue's issueType, but the creation parameters assembled in src/issues/issueFeatureRegistrar.ts contain title, body, assignees, labels, and milestone without an issue type.
- **related open issue:** https://github.com/microsoft/vscode-pull-request-github/issues/8817 is open and specifically tracks setting issue type during creation. It owns that subset, but not project-field editing or organization-project management, so it is too narrow to be the canonical for this broader report.
- **scope precedent:** https://github.com/microsoft/vscode-pull-request-github/issues/2021 was closed as out of scope in 2020 for general GitHub Projects support, but current main has since added Projects v2 membership management; that old blanket decision does not clearly settle the narrower metadata-editing request.
