# Issue #5835 — PR files should be sorted "naturally", like VS Code file explorer

[https://github.com/microsoft/vscode-pull-request-github/issues/5835](https://github.com/microsoft/vscode-pull-request-github/issues/5835)

## Summary

The requested natural ordering remains absent on current main. This team-authored Backlog feature should remain open for implementation.

## Change summary

Sort numbered files in the pull-request file list using the natural ordering available in VS Code's Explorer.

## Best solution

Adopt VS Code Explorer-compatible natural filename comparison in the PR file tree and flat-list sorting paths, while deciding explicitly which Explorer sorting settings should also apply.

## Evidence

- **current tree sorting:** src/view/treeNodes/directoryTreeNode.ts sorts directory and file labels with direct string comparisons, so numeric filename segments are ordered lexicographically rather than naturally.
- **current flat sorting:** src/view/treeNodes/filesCategoryNode.ts sorts flat paths with compareIgnoreCase; src/common/utils.ts implements that comparator character-by-character without numeric-segment handling.
- **existing setting:** package.json exposes githubPullRequests.fileListLayout with only flat and tree values; no setting or command provides natural filename sorting.
- **related request:** https://github.com/microsoft/vscode-pull-request-github/issues/8575 remains open but primarily requests files-first ordering, so it does not replace this issue as a canonical owner for natural numeric sorting.
- **core reference:** The maintainer discussion points to VS Code Explorer's sorting implementation at https://github.com/microsoft/vscode/blob/5b6444d082b6ab25a7c301e55a26d4701722d783/src/vs/workbench/contrib/files/browser/views/explorerViewer.ts#L937-L1062.
