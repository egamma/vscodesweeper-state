# Issue #5835 — PR files should be sorted "naturally", like VS Code file explorer

[https://github.com/microsoft/vscode-pull-request-github/issues/5835](https://github.com/microsoft/vscode-pull-request-github/issues/5835)

## Summary

The requested Explorer-style natural ordering remains absent on current main: both tree and flat PR file layouts use character-wise sorting. This team-authored Backlog polish item should remain open for implementation.

## Change summary

Sort numbered files and directories naturally in the PR file list, consistent with VS Code Explorer ordering.

## Best solution

Use an Explorer-compatible natural comparator for file and directory names in both PR file-list layouts, with tests covering numeric filename segments such as file2 before file10. The implementation should consider the Explorer sorting settings identified in the maintainer discussion rather than changing only one layout.

- **Evidence:** The durable themes explicitly include “Trees, queries, and views” and “The review flow,” while the product promise is to review and manage pull requests directly in VS Code.

## Evidence

- **current flat sorting:** src/view/treeNodes/filesCategoryNode.ts sorts flat-layout paths with compareIgnoreCase; src/common/utils.ts implements that comparator character by character without numeric-segment handling.
- **existing configuration:** package.json exposes githubPullRequests.fileListLayout and githubPullRequests.hideViewedFiles but no setting or command that supplies natural file ordering, so the central request is not already covered.
