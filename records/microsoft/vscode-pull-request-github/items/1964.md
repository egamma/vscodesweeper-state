# Issue #1964 — Clean up TODO comment after issue closed

[https://github.com/microsoft/vscode-pull-request-github/issues/1964](https://github.com/microsoft/vscode-pull-request-github/issues/1964)

## Summary

Keep open: the extension still lacks a reminder for TODOs referencing closed issues. The maintainer-supported diagnostic approach remains unimplemented; the linked implementation PR was closed without merging.

## Change summary

Notify users when a TODO references a closed GitHub issue so they can review and remove obsolete comments.

## Best solution

Provide editor diagnostics for TODOs referencing closed issues, following the maintainer's suggested warning approach without automatically deleting source comments. Establish activation and issue-state refresh behavior before implementing the document-validation lifecycle.

- **Behavior:**

  > Users should be reminded when a TODO in an open editor references a closed GitHub issue. The maintainer's proposed experience is a diagnostic warning, not automatic deletion. Open issues must not produce closed-issue warnings, and source text must remain unchanged. Acceptance checks should cover warning removal after editing and state changes under the agreed refresh behavior.
- **Trace:**

  > IssueTodoProvider.findTodoInLine in src/issues/issueTodoProvider.ts skips lines already containing an issue reference, and its only action creates a new issue. IssueFeatureRegistrar.initialize registers that provider and IssueHoverProvider, but no TODO diagnostics. IssueHoverProvider uses src/issues/util.ts:getIssue, which resolves references through repository remotes and a shared per-repository LRU cache; cached state is not necessarily freshly fetched. Preserve existing issue creation, hover behavior, and repository resolution semantics. https://github.com/microsoft/vscode-pull-request-github/pull/8230 is a closed, unmerged implementation lead, not shipped functionality. The remaining design boundary is when validation becomes active and when GitHub state changes become visible in diagnostics.
- **Open decisions:**
  - Should closed-issue TODO warnings be enabled by default or require explicit user opt-in?
  - Should warnings track GitHub closure and reopening while the document remains open, or update only on defined editor or refresh events?
