# Issue #6711 — Closed PRs get associated with new branches of the same name

[https://github.com/microsoft/vscode-pull-request-github/issues/6711](https://github.com/microsoft/vscode-pull-request-github/issues/6711)

## Summary

Verified duplicate of the active, better-diagnosed stale-PR-association issue. Current source can still associate a branch with an old closed PR, and the resulting metadata can cause the branch-cleanup command to select the wrong branch for deletion.

## Change summary

A newly created branch can inherit an association with a closed PR that previously used the same branch name, producing duplicate metadata and unsafe branch-cleanup behavior.

## Best solution

Consolidate the remaining work in https://github.com/microsoft/vscode-pull-request-github/issues/8676 and change PR discovery so a tracked upstream cannot cause a closed PR to be persisted as the branch association; cleanup should also remove or replace stale duplicate metadata safely.

- **current source:** src/view/reviewManager.ts:getUpstreamUrlAndName supplies branch.upstream.name to checkGitHubForPrBranch, while src/github/githubRepository.ts:getPullRequestForBranch still falls back to prs[0] when no open PR exists. PullRequestGitHelper.associateBranchWithPullRequest then persists that result to git config.
- **cleanup impact:** src/github/folderRepositoryManager.ts:getBranchDeletionItems reads github-pr-owner-number values and marks a branch as legacy when every associated PR is closed, so a stale closed-PR association can place a newly created branch in the deletion flow.
- **insufficient earlier fixes:** The first attempted fix, https://github.com/microsoft/vscode-pull-request-github/commit/45a6f0877815e062f2588ca295208fa0410f4ce7, explicitly closed this issue before it was reopened.
