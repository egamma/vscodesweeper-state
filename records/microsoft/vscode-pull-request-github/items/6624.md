# Issue #6624 — [Feature Request] Add the "only files owned by you" filter.

[https://github.com/microsoft/vscode-pull-request-github/issues/6624](https://github.com/microsoft/vscode-pull-request-github/issues/6624)

## Summary

The CODEOWNERS file filter remains missing on current main. The linked implementation PR was closed without merging; route this supported request to the review and explorer areas.

## Change summary

Add a filter that shows only changed PR files owned by the authenticated user according to CODEOWNERS.

## Best solution

Provide an optional ownership filter in the PR changes tree that follows GitHub's CODEOWNERS semantics and preserves existing file layouts and viewed-file filtering. Use the closed draft as design context, not as a completed implementation.

- **Fit:** aligned
- **Reason:** Ownership filtering helps reviewers navigate large pull requests without leaving the editor.

Verify that enabling the filter shows the authenticated user's owned changed files, disabling restores all files, and both flat/tree layouts compose with hide-viewed filtering; also verify the agreed behavior when ownership cannot be resolved.
- **Behavior:**

  > Reviewers should be able to restrict a PR's changed-file list to files they own according to GitHub CODEOWNERS semantics. Turning the filter off must restore the ordinary list. Acceptance checks cover direct-user and team ownership, overlapping rules, flat and tree layouts, and composition with the existing viewed-file filter. The behavior when ownership information is unavailable must be explicit.
- **Trace:**

  > FilesCategoryNode.getChildren() in src/view/treeNodes/filesCategoryNode.ts currently applies only the hide-viewed filter before constructing either layout. package.json and src/commands.ts expose layout and viewed-file controls but no ownership control. GitHubRepository.getAuthenticatedUser() provides identity, while getOrgTeams() lists organization teams and repository associations, not authenticated-user membership. No CODEOWNERS parser or ownership-filter path was found on main. https://github.com/microsoft/vscode-pull-request-github/pull/8542 is a closed, unmerged draft with a candidate parser and integration approach; its author explicitly said it needed more thought. Preserve existing layout and viewed-file behavior, and do not treat team enumeration as proof of membership. The design uncertainty begins with reliable ownership resolution and the user-visible fallback when that resolution is incomplete.
- **Open decisions:**
  - When CODEOWNERS or team membership cannot be resolved, should the ownership filter remain unavailable, show an explicit incomplete-results state, or leave all files visible with an explanation?
