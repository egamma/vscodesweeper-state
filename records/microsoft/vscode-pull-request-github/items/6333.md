# Issue #6333 — Notifications View - Show read notifications and other notification filtering

[https://github.com/microsoft/vscode-pull-request-github/issues/6333](https://github.com/microsoft/vscode-pull-request-github/issues/6333)

Keep open: current main still lists only unread notifications and offers no read-state or repository filtering. This team-authored, accepted request is itself the canonical issue to which maintainers have consolidated related reports.

- **Behavior:**

  > Users can revisit read notifications in the Notifications view and distinguish them from unread entries. Users can filter notification activity, including restricting it to a repository, rather than relying on unrelated PR or issue search queries. Acceptance checks should cover mixed read states across two repositories, filter persistence according to the agreed contract, pagination, refresh, and read/done actions. Existing unread PR notification badges must retain their meaning.
- **Trace:**

  > NotificationsProvider.getNotifications in src/notifications/notificationsProvider.ts requests the authenticated user's notifications with all: false and no repository scope. NotificationsFeatureRegister in src/notifications/notificationsFeatureRegistar.ts exposes actions and sorting, while its configuration command only opens extension settings. NotificationsDecorationProvider currently decorates priority scores.
