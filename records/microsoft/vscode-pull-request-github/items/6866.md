# Issue #6866 — Support comment reactions in webviews

[https://github.com/microsoft/vscode-pull-request-github/issues/6866](https://github.com/microsoft/vscode-pull-request-github/issues/6866)

## Summary

The requested interaction remains missing: issue and PR webviews display reactions but cannot add or remove them. Keep this accepted feature open and route it to comments and the description page.

## Change summary

Allow users to add and remove emoji reactions on comments in issue and PR editors.

## Best solution

Make comment reactions interactive in both webview editors, preserving GitHub reaction semantics and existing read-only displays. Existing in-editor reaction mutations provide useful prior art, but issue-comment handling and webview state updates still need design.

## Plan brief

- **Likely files:** `webviews/components/comment.tsx`, `webviews/common/context.tsx`, `src/github/issueOverview.ts`, `src/github/pullRequestOverview.ts`, `src/github/issueModel.ts`, `src/github/pullRequestModel.ts`
- **Validation:** In both issue and PR editors, add a reaction to a comment with no existing reactions, remove your own reaction, and verify counts and viewer state against GitHub after refresh. Cover the interaction with webview component tests and mocked host mutation checks; verify mutation errors are visible and other users' reactions remain unchanged.
- **Behavior:**

  > Users can add and remove their own GitHub-supported emoji reactions on comments directly in issue and PR webview editors. Comments without existing reactions must also support adding one. Counts and the user's reacted state should agree with GitHub after successful changes and refresh. Failures should be visible without presenting an unsuccessful mutation as completed.
- **Trace:**

  > webviews/components/comment.tsx renders reactions through CommentBody and CommentReactions, but the latter contains only display elements and excludes zero-count entries. Neither src/github/issueOverview.ts nor src/github/pullRequestOverview.ts dispatches a reaction mutation message. PullRequestModel.addCommentReaction and deleteCommentReaction already mutate GitHub reactions, but their local cache update targets review-thread comments; issue timeline state and viewer reaction state need further tracing. ReviewCommentController.toggleReaction supplies native-editor prior art, not webview coverage. Preserve native editor commenting, existing reaction displays and unrelated comment actions. The maintainer explicitly reserved modifiable reactions for this issue at https://github.com/microsoft/vscode-pull-request-github/issues/6880#issuecomment-2841914153.
- **Open decisions:**
  - Should adding a reaction use a dedicated comment action with an emoji picker, with existing reaction badges acting as toggles, or a different interaction consistent across issue and PR editors?
