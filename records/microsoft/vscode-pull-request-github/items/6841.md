# Issue #6841 — Issues - create an issue does not use the new web view

[https://github.com/microsoft/vscode-pull-request-github/issues/6841](https://github.com/microsoft/vscode-pull-request-github/issues/6841)

## Summary

The gap remains on current main: the Issues view title action still opens the markdown-based creation editor rather than the issue webview. This is a team-authored feature request in Backlog, with no factual fix or duplicate supporting closure.

## Change summary

Use the issue webview, rather than a temporary markdown document, when creating an issue from the Issues view title action.

## Best solution

Add a creation mode to the issue webview that supports repository and template selection plus title, body, assignee, label, milestone, and project fields, then route `issue.createIssue` to that mode while preserving creation from source TODOs where appropriate.

## Evidence

- **current command path:** package.json contributes `issue.createIssue` to the `issues:github` view title, and src/issues/issueFeatureRegistrar.ts registers that command directly to `createIssue()`.
- **gap on main:** src/issues/issueFeatureRegistrar.ts still ends `createIssue()` with `makeNewIssueFile(...)`; that helper creates and opens a `newissue:/NewIssue.md` virtual markdown document.
- **webview boundary:** src/github/issueOverview.ts constructs `IssueOverviewPanel` around an existing issue identity and number, so the current webview has no corresponding unsaved-issue creation path.
- **feature origin:** The issue was filed while testing https://github.com/microsoft/vscode-pull-request-github/issues/6831 after the existing-issue webview landed in https://github.com/microsoft/vscode-pull-request-github/pull/6767; that work did not cover issue creation.
