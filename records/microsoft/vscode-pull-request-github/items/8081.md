# Issue #8081 — Don't show completion kinds with emoji picker

[https://github.com/microsoft/vscode-pull-request-github/issues/8081](https://github.com/microsoft/vscode-pull-request-github/issues/8081)

## Summary

The unwanted kind icon remains, but suppressing it requires VS Code core support rather than an extension-only change. Route this through the upstream/vscode lane while preserving the emoji-picker use case.

## Change summary

Show emoji completions in comment editors without a completion-kind icon preceding each emoji.

## Best solution

Add an iconless completion-item capability to the VS Code completion API and suggest widget, then have src/view/emojiCompletionProvider.ts opt into it. The likely platform work belongs in microsoft/vscode; no open canonical issue was found.

## Evidence

- **extension implementation:** src/view/emojiCompletionProvider.ts constructs every emoji as vscode.CompletionItemKind.Text, which accounts for the visible text-kind icon; package.json exposes no setting or command that suppresses it.
- **VS Code API limitation:** The VS Code CompletionItem API documents that the editor chooses an icon from CompletionItem.kind: https://github.com/microsoft/vscode/blob/main/src/vscode-dts/vscode.d.ts
- **core rendering behavior:** VS Code's suggest-widget renderer always applies an icon for ordinary completion items, and CompletionItemKinds.toIcon falls back to the property icon when the kind is absent: https://github.com/microsoft/vscode/blob/main/src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts and https://github.com/microsoft/vscode/blob/main/src/vs/editor/common/languages.ts
