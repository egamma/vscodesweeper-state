# Issue #8180 — Provide easier enablement for settings

[https://github.com/microsoft/vscode-pull-request-github/issues/8180](https://github.com/microsoft/vscode-pull-request-github/issues/8180)

## Summary

A real workflow-polish gap remains: setting-dependent error messages can name the setting without offering a direct way to open or enable it. Routing this team-authored papercut to the chat and UX areas rather than making a judgment close.

## Change summary

Provide direct Settings UI links or inline chat actions when a workflow is blocked by a disabled setting.

## Best solution

Give setting-dependent errors a contextual action that opens the exact setting in the Settings UI, and use an inline enablement action where the chat API supports one. Reuse the existing `workbench.action.openSettings` interaction pattern rather than requiring users to copy setting IDs manually.
