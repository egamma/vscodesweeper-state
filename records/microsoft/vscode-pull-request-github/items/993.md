# Issue #993 — Better experience for non-matching reivewiers/labels

[https://github.com/microsoft/vscode-pull-request-github/issues/993](https://github.com/microsoft/vscode-pull-request-github/issues/993)

## Summary

Keep open: the label and reviewer pickers still lack explicit feedback for unmatched input. The linked implementation was closed without merging, and the upstream API request does not replace the extension-side adoption work.

## Change summary

Provide clear feedback when a user enters a nonexistent label or reviewer and accepts the picker.

## Best solution

Deliver contextual feedback in the description page's label and reviewer pickers while preserving legitimate selection changes. Coordinate with microsoft/vscode's QuickPick API work rather than treating that platform capability as completion of this extension request.

- **Fit:** aligned
- **Reason:** Clear selection feedback improves the native, in-editor PR management experience.
- **Evidence:** The public product promise is to review and manage GitHub pull requests directly in VS Code; durable themes include description-page usability and the review flow.

## Plan brief

- **Likely files:** `src/github/issueOverview.ts`, `src/github/quickPicks.ts`, `src/github/pullRequestOverview.ts`, `package.json`
- **Validation:** In a PR description, open label and reviewer selection separately, type a nonexistent value, and accept; verify explicit feedback explains that the typed value was not selected. Repeat with existing selections, valid additions, intentional removals, and cancellation to verify those workflows remain usable.
- **Behavior:**

  > Entering a nonexistent label or reviewer must not leave the user uncertain whether that value was added. Feedback should make the selection outcome clear without implying that arbitrary typed text creates a label or requests a reviewer. Acceptance checks must cover unmatched input both with and without existing selections, alongside valid additions, intentional removals, and cancellation.
- **Trace:**

  > IssueOverviewPanel.addLabels in src/github/issueOverview.ts accepts selectedItems without examining the filter text. reviewersQuickPick in src/github/quickPicks.ts constructs the reviewer picker, and changeReviewers in src/github/pullRequestOverview.ts applies its selected users and removals. Neither path supplies explicit unmatched-input feedback. https://github.com/microsoft/vscode-pull-request-github/pull/8224 attempted selection-state prompts but was closed unmerged; its review identifies a platform API direction, not a landed solution. https://github.com/microsoft/vscode/issues/187863 remains an enabling API request rather than a canonical for the extension behavior. The remaining uncertainty is which supported feedback surface is available and whether selection-state messaging adequately explains unmatched text; preserve intentional empty selections and existing reviewer/label update semantics.
- **Open decisions:**
  - Should feedback specifically identify unmatched typed input, or is a general selection-state prompt sufficient, including when existing labels or reviewers remain selected?
