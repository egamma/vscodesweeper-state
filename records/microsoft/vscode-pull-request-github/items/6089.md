# Issue #6089 — Adding a comment is always associated with a review

[https://github.com/microsoft/vscode-pull-request-github/issues/6089](https://github.com/microsoft/vscode-pull-request-github/issues/6089)

## Summary

The distinction between discussion comments and review comments remains missing from the PR comment forms. Route to the description-page and comments areas; the later clarification about immediate inline comments does not resolve the original request.

## Change summary

Allow posting a normal PR discussion comment without creating or submitting a review.

## Best solution

Expose a discussion-comment action in the PR description and active-PR views, using GitHub's issue-comment semantics while preserving explicit review submission. Decide how that action should coexist with a pending review.

## Vision fit

- **Fit:** aligned
- **Reason:** Posting ordinary PR discussion comments supports managing GitHub pull requests directly in VS Code and preserving GitHub's comment semantics.
- **Evidence:** The product promise is "Review and manage your GitHub pull requests and issues directly in VS Code," with fidelity to GitHub's semantics as a durable guardrail.

## Plan brief

- **Likely files:** `webviews/components/comment.tsx`, `webviews/common/context.tsx`, `src/github/pullRequestOverview.ts`, `src/github/activityBarViewProvider.ts`, `src/github/issueModel.ts`, `package.json`
- **Validation:** On a test PR, post a discussion comment from both the description page and active-PR view, first without a pending review and then with one. Verify GitHub records an issue comment, no new review is created, and any pending review remains pending. Verify explicit review submission and immediate inline comments retain their existing behavior.
- **Behavior:**

  > Users need to post a normal PR discussion comment rather than a review summary, including for automation that watches issue-comment events. The finished experience must distinguish discussion posting from review submission. A discussion comment must appear in GitHub's conversation as an issue comment without creating or submitting a review. Existing inline-comment and explicit review workflows must remain available.
- **Trace:**

  > AddComment and AddCommentSimple in webviews/components/comment.tsx currently send their Comment action through PullRequestContext.submit in webviews/common/context.tsx. Both PR host providers map that action to PullRequestModel.submitReview(Comment), which creates a review when none exists. IssueModel.createIssueComment already provides the distinct discussion-comment API, and the activity-bar provider has a pr.comment handler that the inspected forms do not use. The defaultCommentType setting and pr.createSingleComment command only govern immediate versus pending inline review comments. Preserve those semantics and explicit approval/request-changes actions. The maintainer acknowledged the missing distinction at https://github.com/microsoft/vscode-pull-request-github/issues/6089#issuecomment-2223220680; uncertainty remains around the user-facing default and availability during a pending review.
- **Open decisions:**
  - Should the existing Comment action post a discussion comment by default, or should discussion posting be a separate action alongside the current review-comment action?
  - Should discussion posting remain available while a review is pending, independently of submitting that review?
