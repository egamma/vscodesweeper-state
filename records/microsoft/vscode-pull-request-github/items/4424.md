# Issue #4424 — support for easily jump to next/previous file

[https://github.com/microsoft/vscode-pull-request-github/issues/4424](https://github.com/microsoft/vscode-pull-request-github/issues/4424)

## Summary

Keep this request open and route it to review UX: existing commands do not cover image-diff navigation or marking a file viewed and advancing. Related issues cover narrower behaviors, and the team explicitly consolidated automatic advancement into this issue.

## Change summary

Provide keyboard and toolbar navigation between changed files, including images, with an action to mark the current file viewed and advance to the next unviewed file.

## Best solution

Provide predictable file-level navigation and a mark-viewed-and-advance action in the review experience while preserving ordinary navigation without changing viewed state. Coordinate multidiff support with https://github.com/microsoft/vscode-pull-request-github/issues/7608 rather than replacing this broader request.

## Plan brief

- **Likely files:** `src/commands.ts`, `src/view/treeNodes/fileChangeNode.ts`, `package.json`, `package.nls.json`
- **Validation:** Review a PR containing several text and image changes: invoke next/previous file navigation without changing viewed state, then mark a file viewed and advance to the next unviewed file in review order. Check previously viewed files, first/last-file boundaries, and preservation of existing text-hunk navigation; separately verify the agreed multidiff behavior.
- **Behavior:**

  > Users reviewing a PR should be able to navigate changed files using keyboard shortcuts or toolbar actions, including when the active diff contains images. Navigation alone must not mark files viewed. A combined action should mark the current file viewed and advance to the next unviewed file predictably, rather than relying on whichever tab VS Code activates after closing a tab. Acceptance includes mixed text/image changes, already-viewed files, and first/last-file boundaries.
- **Trace:**

  > src/commands.ts registers pr.goToNextDiffInPr and pr.goToPreviousDiffInPr with registerDiffInformationCommand; goToNextPrevDiff accepts only TabInputTextDiff, finds a modified text editor, and navigates hunks before crossing files in a checked-out PR. package.json also restricts command-palette visibility to text diff editors. pr.markFileAsViewed closes matching text tabs and records viewed state but does not select a successor; FileChangeNode.markFileAsViewed only records state. Existing hideViewedFiles and fileAutoReveal settings do not provide advancement. Preserve existing hunk-navigation semantics and viewed-state behavior outside the new workflow. https://github.com/microsoft/vscode-pull-request-github/issues/7608 owns the multidiff-specific extension; https://github.com/microsoft/vscode-pull-request-github/issues/5092 concerns retaining marked tabs. Planning starts at the public contract for file navigation and its relationship to existing hunk commands, not at whether these capability gaps exist.
- **Open decisions:**
  - Should next/previous file navigation be separate commands and toolbar actions, or should the existing next/previous diff commands acquire file-level behavior for non-text editors?
  - When marking the last unviewed file, should the combined action open the PR description, remain on that file, or offer navigation back to the beginning?
