# Issue #7944 — Support using `pushRemote` and `merge` to detect the PR of a branch

[https://github.com/microsoft/vscode-pull-request-github/issues/7944](https://github.com/microsoft/vscode-pull-request-github/issues/7944)

## Summary

Verified duplicate: the open, better-diagnosed canonical tracks the same incorrect use of a branch's merge/upstream ref as its PR head branch. It includes current-version reproductions and owns the remaining fix.

## Change summary

Use `pushRemote` and the local branch name when identifying a branch's pull request instead of treating its configured merge target as the PR head.

## Best solution

Consolidate on https://github.com/microsoft/vscode-pull-request-github/issues/8676 and change branch-to-PR detection so a local branch tracking a differently named upstream is not associated with that upstream branch's PR; the implementation should account for `branch.<name>.pushRemote` and the local branch's remote head name.
