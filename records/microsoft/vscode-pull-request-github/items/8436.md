# Issue #8436 — Support "Branch auto delete" without having to press "merge" in the webview

[https://github.com/microsoft/vscode-pull-request-github/issues/8436](https://github.com/microsoft/vscode-pull-request-github/issues/8436)

## Summary

A real post-creation cleanup gap remains: the extension can check out the default branch after creating a PR, but it does not delete the now-published local feature branch. This team-authored Backlog request should remain open for a product and implementation decision.

## Change summary

Add an opt-in post-create action that publishes the PR branch, checks out the default branch, and deletes the local feature branch.

## Best solution

Extend `githubPullRequests.postCreate` with an explicit cleanup option implemented in `src/view/reviewManager.ts`: after successful PR creation, confirm the head branch is available remotely, check out the PR repository's default branch, and safely delete only the local head branch. Keep this distinct from merge-time remote-branch deletion so creating a PR cannot inadvertently delete its GitHub head branch.

- **merge-only behavior:** `githubPullRequests.deleteBranchAfterMerge` is consumed by the merge paths in `src/github/pullRequestOverview.ts` and `src/github/activityBarViewProvider.ts`; it does not cover creation followed by later merging elsewhere.
