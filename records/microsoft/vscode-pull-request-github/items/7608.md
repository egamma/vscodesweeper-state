# Issue #7608 — Support next/prev diff in multidiff editor

[https://github.com/microsoft/vscode-pull-request-github/issues/7608](https://github.com/microsoft/vscode-pull-request-github/issues/7608)

## Summary

The multidiff navigation gap remains on current main. This team-authored Backlog request should stay open and be routed to the review and UX areas.

## Change summary

Allow the existing next/previous PR diff commands to navigate within the multidiff editor.

## Best solution

Extend the navigation implementation in src/commands.ts to recognize PR multidiff tabs and move through their file and hunk entries, while preserving the existing text-diff behavior. Update the command enablement in package.json and add focused command tests for forward, backward, and boundary navigation.

## Evidence

- **current source gap:** src/commands.ts registers pr.goToNextDiffInPr and pr.goToPreviousDiffInPr with registerDiffInformationCommand, while goToNextPrevDiff explicitly rejects every active tab that is not vscode.TabInputTextDiff; a vscode.TabInputTextMultiDiff therefore produces the reported error.
- **command enablement:** package.json enables both navigation commands only when activeEditor == workbench.editors.textDiffEditor, so the commands are not integrated with the multidiff editor surface.
- **multidiff path:** src/github/pullRequestModel.ts opens PR changes through vscode.changes, confirming that the extension intentionally uses the multidiff editor for this workflow.
- **intentional follow-up:** In https://github.com/microsoft/vscode-pull-request-github/issues/4424#issuecomment-3189510716, the maintainer confirms that the commands do not support multidiff and says a separate issue will track that support; https://github.com/microsoft/vscode-pull-request-github/issues/7608 was then linked as that tracker.
