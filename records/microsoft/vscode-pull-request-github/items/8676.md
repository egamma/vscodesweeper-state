# Issue #8676 — `checkGitHubForPrBranch` associates branches with stale closed PRs via their tracked upstream (e.g. branches tracking `origin/dev`)

[https://github.com/microsoft/vscode-pull-request-github/issues/8676](https://github.com/microsoft/vscode-pull-request-github/issues/8676)

## Summary

Still present on current main after the partial fix in https://github.com/microsoft/vscode-pull-request-github/pull/8727: a differently named tracked upstream can resolve to a closed PR and be persisted as the local branch's association. Routing to the git and review areas with a confirmed reproduction and the remaining source path.

## Change summary

Prevent local branches tracking shared base refs such as `origin/dev` from being associated with unrelated closed PRs whose head ref used that upstream name.

## Best solution

In the branch-discovery paths, avoid persisting a closed PR when the local branch name differs from its tracked upstream ref, while preserving discovery of open PRs and legitimate same-name closed-branch associations. Cover both `ReviewManager.checkGitHubForPrBranch` and first-activation branch association with regression tests.
