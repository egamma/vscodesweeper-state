# Issue #2080 — multithreaded/--concurrency support?

[https://github.com/microsoft/vscode-eslint/issues/2080](https://github.com/microsoft/vscode-eslint/issues/2080)

## Summary

Keep this accepted request open: ESLint's multithreading operates across files through lintFiles, whereas editor validation uses lintText. Existing options can pass concurrency through, but that does not parallelize the LSP's document validation or establish a benefit for the reported GraphQL workload.

## Change summary

Explore using ESLint's multithreaded linting to improve language-server performance, including GraphQL plugins that inspect other project files.

## Best solution

Evaluate whether a supported ESLint API can improve the server's in-memory document validation without sacrificing unsaved-buffer correctness, and measure the GraphQL workload before choosing an integration. The CLI lint task already accepts --concurrency, but it is not a replacement for interactive LSP validation.
