# Issue #2080 — multithreaded/--concurrency support?

[https://github.com/microsoft/vscode-eslint/issues/2080](https://github.com/microsoft/vscode-eslint/issues/2080)

## Summary

This remains a valid performance feature request, but ESLint's concurrency support is designed for linting multiple files while the extension currently submits one document at a time through `lintText`. The existing `eslint.options` pass-through can supply the constructor option, but it does not make the current single-document validation path concurrent.

## Change summary

Allow the language server to take advantage of ESLint's multithreaded concurrency support, particularly for plugins that perform project-wide analysis.

## Best solution

Keep this in Backlog while investigating whether `server/` can safely batch compatible document validations into a multi-file ESLint operation without losing unsaved editor content, per-resource settings, cancellation, or diagnostic freshness. If ESLint concurrency cannot accelerate `lintText`, document that limitation rather than exposing a setting that appears effective but is not.

## Evidence

- **current validation path:** `server/src/eslintServer.ts` handles a document diagnostic request by resolving that document's settings and calling `ESLint.validate`; `server/src/eslint.ts` then invokes `eslintClass.lintText` once with that document's current in-memory content.
- **existing option pass-through:** `package.json` defines `eslint.options` as the options object passed to the ESLint class, and `server/src/eslint.ts` merges those settings into the constructor options in `withClass`. This can forward `concurrency`, but the extension still supplies only one document to `lintText`.
- **ESLint concurrency model:** ESLint's announcement at https://eslint.org/blog/2025/08/multithread-linting/ describes workers processing multiple files simultaneously and says the largest gains occur when linting hundreds or thousands of files; that does not directly match the extension's one-document `lintText` calls.
- **distinct project-aware use case:** The follow-up at https://github.com/microsoft/vscode-eslint/issues/2080#issuecomment-3762951387 identifies graphql-eslint duplicate-operation analysis, which scans across GraphQL files even when the editor validates one focused document.
