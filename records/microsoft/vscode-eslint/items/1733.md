# Issue #1733 — Feature Request: enable the "eslint.format.enable" setting by default.

[https://github.com/microsoft/vscode-eslint/issues/1733](https://github.com/microsoft/vscode-eslint/issues/1733)

## Summary

The formatter is intentionally opt-in because enabling it globally would register ESLint alongside other formatting providers and change behavior for users who prefer TypeScript, Prettier, or another formatter. The maintainer has confirmed this design and its breaking-change implications, so the current default should remain.

## Change summary

Enable `eslint.format.enable` by default, or remove the setting and always expose ESLint as a formatter.

## Best solution

Keep ESLint formatting opt-in and continue directing users who want it to enable `eslint.format.enable` and select `dbaeumer.vscode-eslint` as their language-specific default formatter. Any remaining discoverability or missing-feedback work can be handled separately by https://github.com/microsoft/vscode-eslint/issues/1739.

## Vision fit

- **Fit:** rejected
- **Reason:** Automatically enabling the formatter would interfere with the user's chosen formatting pipeline and conflict with the extension's guardrail of integrating through VS Code's existing editor surfaces rather than taking ownership of them.
- **Evidence:** The vision says to "Build on core platform surfaces" and identifies formatting integration as a VS Code surface; it also treats the workspace's configuration as the user's to own.
