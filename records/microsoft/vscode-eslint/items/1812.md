# Issue #1812 — Extension can't find typescript-eslint parser with yarn's pnpm linker installation layout

[https://github.com/microsoft/vscode-eslint/issues/1812](https://github.com/microsoft/vscode-eslint/issues/1812)

## Summary

Keep this reopened, team-authored feature request open: current main still recognizes legacy TypeScript parsers by matching their resolved filesystem paths, so Yarn v4's pnpm-linker layout can evade probing. ESLint 9 flat config avoids this particular heuristic, but that does not resolve the documented legacy-config gap.

## Change summary

Make automatic TypeScript validation probing recognize parsers installed through Yarn v4's pnpm linker without requiring explicit eslint.validate entries.

## Best solution

In server/src/eslint.ts, replace or extend the legacy parser-path heuristic with detection that is robust to package-manager-specific realpaths, and cover the Yarn v4 pnpm-linker layout with a server test. Preserve `eslint.validate` as the explicit opt-in path, while confirming whether the supplied reproduction still fails with ESLint 9 under legacy configuration.
