# Issue #1812 — Extension can't find typescript-eslint parser with yarn's pnpm linker installation layout

[https://github.com/microsoft/vscode-eslint/issues/1812](https://github.com/microsoft/vscode-eslint/issues/1812)

## Summary

The current server still identifies TypeScript support in legacy configurations using parser-path regular expressions that do not match Yarn's `nodeLinker: pnpm` virtual-store layout. The explicit `eslint.validate` setting is an effective workaround, but it does not eliminate the automatic-probing compatibility gap; this team-authored, reopened Backlog issue should remain open.

## Change summary

Make automatic TypeScript validation detection work when Yarn's pnpm linker resolves `@typescript-eslint/parser` through a virtual-store path that omits the usual scoped package directory segments.

## Best solution

Update the probing logic in `server/src/eslint.ts` so supported parser detection does not depend on a package manager's physical directory layout, while retaining `eslint.validate` as an explicit override. Cover Yarn's pnpm-linker realpath in server tests and confirm separately whether ESLint 9 flat config already avoids the affected legacy-config branch.
