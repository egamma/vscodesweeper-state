# Issue #1812 — Extension can't find typescript-eslint parser with yarn's pnpm linker installation layout

[https://github.com/microsoft/vscode-eslint/issues/1812](https://github.com/microsoft/vscode-eslint/issues/1812)

## Summary

Keep open: current main still rejects the reported Yarn pnpm-linker parser path during legacy-config probing. Explicit eslint.validate is a confirmed workaround and flat-config probing avoids this dependency, but neither establishes that automatic detection for the original setup is fixed.

## Change summary

Automatically recognize TypeScript parser support with Yarn's pnpm linker without requiring explicit language validation settings.

## Best solution

Make automatic TypeScript probing in server/ independent of package-store directory naming while preserving supported legacy configurations. Determine the intended legacy-support boundary with the maintainer; ESLint 9 flat-config behavior should be evaluated separately from the original ESLint 8 reproduction.
