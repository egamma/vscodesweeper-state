# Issue #1727 — Prefer to use node from environment

[https://github.com/microsoft/vscode-eslint/issues/1727](https://github.com/microsoft/vscode-eslint/issues/1727)

## Summary

This remains an accepted feature request: current main still uses the bundled runtime by default, while the maintainer supports considering environment Node selection for trusted workspaces. The security-sensitive runtime boundary requires human design judgment, so the issue must remain open.

## Change summary

Prefer a project or environment-selected Node runtime for ESLint, with a safe fallback, instead of requiring eslint.runtime to be configured for every workspace or remote.

## Best solution

Add an explicit runtime-selection strategy in client/ that can use `node` from the workspace environment in trusted workspaces and fall back to VS Code's bundled runtime when unavailable, while preserving the bundled runtime in untrusted workspaces. The setting name, migration behavior, multi-root semantics, and security boundary need maintainer agreement before implementation.
