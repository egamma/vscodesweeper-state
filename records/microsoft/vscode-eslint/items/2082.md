# Issue #2082 — Extension should report config file errors

[https://github.com/microsoft/vscode-eslint/issues/2082](https://github.com/microsoft/vscode-eslint/issues/2082)

## Summary

Current main reports invalid ESLint configurations through the document's language status indicator and the ESLint output channel. The maintainer has explicitly identified that presentation as the recommended VS Code behavior, so adding a separate notification or config-file diagnostic is not planned.

## Change summary

Make invalid flat-config errors visible through a notification or a diagnostic attached to the ESLint configuration file.

## Best solution

Keep the existing language-status presentation, with the ESLint output channel providing the detailed error. Config-file diagnostics would additionally require reliable source locations from ESLint, which are not generally available for runtime configuration errors.

## Vision fit

- **Fit:** aligned
- **Reason:** Making configuration failures legible advances the extension's configuration-resolution and diagnostic-presentation themes, although the project has chosen the language status indicator as the appropriate UI.
- **Evidence:** The vision says that making an existing configuration's failure mode legible is squarely in scope and identifies configuration resolution and diagnostic presentation as durable themes.
