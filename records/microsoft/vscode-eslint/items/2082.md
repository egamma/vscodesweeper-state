# Issue #2082 — Extension should report config file errors

[https://github.com/microsoft/vscode-eslint/issues/2082](https://github.com/microsoft/vscode-eslint/issues/2082)

## Summary

The extension has partial handling for configuration failures, but current main only recognizes a few legacy error-message shapes and otherwise exposes the failure through the output channel and language-status severity. Flat-config InvalidConfigError failures can therefore remain too easy to miss, so the requested user-facing reporting remains a real gap.

## Change summary

Surface invalid ESLint configuration errors prominently, ideally as a notification or a diagnostic attached to the relevant eslint.config file.

## Best solution

Extend the server-side configuration-error classification in `server/src/eslint.ts` to recognize structured flat-config errors without relying solely on legacy message regexes, then carry an actionable message and config-file location to the client. Show a notification when no reliable source range exists; publish a config-file diagnostic only when ESLint provides enough location information to avoid misleading highlighting.
