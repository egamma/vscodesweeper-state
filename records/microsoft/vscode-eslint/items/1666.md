# Issue #1666 — Use from CLI?

[https://github.com/microsoft/vscode-eslint/issues/1666](https://github.com/microsoft/vscode-eslint/issues/1666)

## Summary

This remains a valid feature request: the extension's long-lived ESLint server cannot currently be reused by lint-staged or another CLI process, and the existing lint task starts a separate ESLint command instead. The maintainer confirmed the capability does not exist, and no canonical issue was found.

## Change summary

Allow command-line tools such as lint-staged to reuse the running VS Code ESLint server and avoid paying ESLint startup and configuration-loading costs again.

## Best solution

Keep this as the canonical request and assess a supported external interface in the client/server integration, including server discovery, document synchronization, result reporting, lifecycle, and access boundaries. The interface should preserve normal standalone ESLint behavior when VS Code or its language server is unavailable.
