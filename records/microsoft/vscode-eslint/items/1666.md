# Issue #1666 — Use from CLI?

[https://github.com/microsoft/vscode-eslint/issues/1666](https://github.com/microsoft/vscode-eslint/issues/1666)

## Summary

This remains a valid feature request: the extension has no supported way for lint-staged or another CLI process to reuse its running ESLint language server, and the existing lint task starts a separate ESLint command instead. No broader canonical issue owns this server-reuse request.

## Change summary

Expose a command-line integration that lets pre-commit tooling lint files through the already-running VS Code ESLint server rather than initializing ESLint again.

## Best solution

Design a supported bridge or persistent service interface around the language server through which external tools can request validation of on-disk files, with explicit handling for server lifecycle, workspace selection, unsaved editor state, workspace trust, and error reporting. This likely spans the client/server boundary rather than the existing task provider, which launches an independent ESLint process.

## Evidence

- **maintainer confirmation:** A maintainer confirmed that there is currently no way to do this: https://github.com/microsoft/vscode-eslint/issues/1666#issuecomment-1592753593
- **current server lifecycle:** client/src/client.ts creates the language server as a VS Code LanguageClient using TransportKind.ipc; there is no contributed command or external CLI entry point for lint-staged to connect to that process.
- **existing task is not coverage:** client/src/tasks.ts constructs a vscode.ShellExecution for `${command} ${lintTaskOptions}`, and package.json documents eslint.lintTask.command/options as command-line ESLint settings. This starts an independent CLI invocation rather than reusing the running language server.
- **server protocol surface:** server/src/eslintServer.ts exposes document synchronization, diagnostics, and editor-oriented execute commands over its LSP connection, but no command for an external process to submit a set of on-disk files for linting.
- **canonical search:** The closest open report, https://github.com/microsoft/vscode-eslint/issues/1844, requests ESLint cache use during on-save validation. It is narrower and does not own the requested external CLI-to-server integration.
