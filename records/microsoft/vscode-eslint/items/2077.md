# Issue #2077 — Server side workingDirectory.mode auto detection is incomplete

[https://github.com/microsoft/vscode-eslint/issues/2077](https://github.com/microsoft/vscode-eslint/issues/2077)

## Summary

The current auto-detection logic conclusively treats every package.json as a project root, leaving a real gap for common monorepo layouts. Keep the issue open because https://github.com/microsoft/vscode-eslint/pull/2076 is an open implementation candidate that explicitly closes it.

## Change summary

Improve automatic working-directory inference so nested package manifests do not override repository-level legacy ESLint configuration, using lockfiles and workspace markers as stronger root indicators.

## Best solution

Review and land https://github.com/microsoft/vscode-eslint/pull/2076 after covering nested-package, lockfile-root, flat-config, and no-lockfile fallback cases in the server's working-directory tests; close the issue only after that implementation merges.
