# Issue #2077 — Server side workingDirectory.mode auto detection is incomplete

[https://github.com/microsoft/vscode-eslint/issues/2077](https://github.com/microsoft/vscode-eslint/issues/2077)

## Summary

Current main still treats every `package.json` as a project root during automatic working-directory detection, creating the reported monorepo limitation. The directly linked fixing PR remains open, so the issue must stay open while that implementation is reviewed.

## Change summary

Improve `workingDirectory.mode: auto` so nested package manifests do not override the actual ESLint project root in monorepos.

## Best solution

Review and land https://github.com/microsoft/vscode-eslint/pull/2076 with coverage for nested `package.json` files, lockfile-based roots, flat-config precedence, and the no-lockfile fallback; keep the issue open until that PR or a replacement implementation merges.
