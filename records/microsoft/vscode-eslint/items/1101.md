# Issue #1101 — More visibility for workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/1101](https://github.com/microsoft/vscode-eslint/issues/1101)

## Summary

This remains an accepted, unimplemented discoverability improvement for monorepos. The current extension supports opt-in automatic working-directory inference, but it does not detect likely monorepo misconfiguration and offer to add the appropriate setting.

## Change summary

Detect workspaces that likely need `eslint.workingDirectories` and proactively offer a suitable configuration.

## Best solution

Add conservative monorepo detection around the server's working-directory resolution, then present a client-side confirmation before writing an `eslint.workingDirectories` workspace setting. Preserve `location` as the default so existing workspaces do not silently change behavior.

## Vision fit

- **Fit:** aligned
- **Reason:** Making working-directory inference discoverable directly advances the extension's stated support for multi-folder and monorepo configuration without overriding the workspace's choices.
- **Evidence:** The durable configuration-resolution theme explicitly includes `eslint.workingDirectories`, multi-root workspaces, and monorepo layouts; `agents.md` also states the goal to support multiple workspace folders and dynamic working-directory inference.
