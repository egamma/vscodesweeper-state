# Issue #1101 — More visibility for workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/1101](https://github.com/microsoft/vscode-eslint/issues/1101)

## Summary

The discoverability gap remains: current settings can select or infer a working directory, but the extension does not detect likely monorepo misconfiguration and offer to add an appropriate setting. The maintainer explicitly accepted that direction, and no open canonical issue or linked implementation supersedes this request.

## Change summary

Detect workspaces that likely need `eslint.workingDirectories` and proactively offer an appropriate configuration instead of requiring users to diagnose subtle monorepo failures.

## Best solution

Keep the safe `location` default, add server-side detection for likely monorepo layouts, and have the client present a confirmation before writing a suggested `eslint.workingDirectories` value. Detection should avoid changing behavior automatically and should account for both flat and legacy configuration layouts.
