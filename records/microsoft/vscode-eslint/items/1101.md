# Issue #1101 — More visibility for workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/1101](https://github.com/microsoft/vscode-eslint/issues/1101)

## Summary

The discoverability gap remains on current main: `eslint.workingDirectories` supports explicit, pattern, and automatic modes, but the extension does not proactively detect likely monorepo misconfiguration or offer suitable settings. The maintainer explicitly accepted that direction while rejecting a risky default change, so this remains a valid Backlog feature request.

## Change summary

Detect workspaces likely to require `eslint.workingDirectories` and proactively explain or offer an appropriate configuration.

## Best solution

Add conservative server-side workspace scanning for nested project/config indicators, then use a client-facing confirmation flow to explain the detected working-directory risk and optionally write an explicit `eslint.workingDirectories` setting. Preserve `mode: location` as the default and avoid changing configuration without user confirmation.
