# Issue #1460 — Problems should not dissapear on file close

[https://github.com/microsoft/vscode-eslint/issues/1460](https://github.com/microsoft/vscode-eslint/issues/1460)

## Summary

The requested persistent closed-file diagnostics are part of the broader, older workspace-linting request tracked by https://github.com/microsoft/vscode-eslint/issues/91. Current source still provides diagnostics only for open documents, and the maintainer explicitly identified a workspace diagnostic provider as the required implementation.

## Change summary

Keep ESLint problems for closed files, including diagnostics initially contributed by a whole-workspace lint task, until the files change.

## Best solution

Consolidate the request into https://github.com/microsoft/vscode-eslint/issues/91 and implement an opt-in workspace diagnostic provider there, with performance safeguards. Preserve this report's important edge case: opening and closing a file must not discard a still-current diagnostic previously produced by a workspace lint task.

- **Evidence:** The public architecture goals include supporting multiple workspace folders and dynamic working-directory inference, while the vision identifies diagnostic presentation and performance/responsiveness as durable themes.
