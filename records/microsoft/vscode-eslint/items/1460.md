# Issue #1460 — Problems should not dissapear on file close

[https://github.com/microsoft/vscode-eslint/issues/1460](https://github.com/microsoft/vscode-eslint/issues/1460)

## Summary

This remains an extension-side feature gap: current main provides document diagnostics only and explicitly disables workspace diagnostics, so closing a file can remove its ESLint problems. The existing whole-workspace lint task is useful but does not provide the requested persistent diagnostic lifecycle.

## Change summary

Add an optional mode that retains ESLint problems for closed files, including results originally produced by a whole-workspace lint task, until the files change or are revalidated.

## Best solution

Implement an opt-in workspace diagnostic provider in the client/server integration, with a falsy default and explicit performance guidance. It should lint or retain results for closed workspace files, invalidate them when relevant files or configuration change, and avoid adding unconditional background work for existing users.
