# Issue #91 — How to lint all files in project?

[https://github.com/microsoft/vscode-eslint/issues/91](https://github.com/microsoft/vscode-eslint/issues/91)

## Summary

The extension now supports user-triggered whole-workspace linting through its contributed task, but it still validates only opened files interactively. This issue remains the open canonical request for automatic project-wide diagnostics and is intentionally parked in Backlog.

## Change summary

Provide project-wide linting so problems from unopened files are available without manually opening each file or running a separate task.

## Best solution

Keep the contributed `eslint: lint whole folder` task as the explicit, performance-safe workflow while deciding whether automatic project-wide diagnostics can be added without unconditional full-workspace validation. If pursued, the behavior belongs primarily in `client/` task or activation orchestration, with diagnostics continuing to use VS Code's problem-matcher or language-server surfaces.

## Evidence

- **existing manual capability:** `package.json` defines `eslint.lintTask.enable`, `eslint.lintTask.command`, and `eslint.lintTask.options`; the setting description says it contributes a task for linting the whole workspace.
- **current implementation:** `client/src/tasks.ts` constructs the `eslint: lint whole folder` task, runs the configured ESLint command against `.` by default, and attaches the `$eslint-stylish` problem matcher.
- **documented behavior boundary:** `README.md` states that interactive validation lints an individual file only and directs users who want the whole workspace linted to enable `eslint.lintTask.enable` and run the contributed task.
- **maintainer direction:** In https://github.com/microsoft/vscode-eslint/issues/91#issuecomment-603123966, the maintainer says a user-triggered task is currently the right approach because caching does not avoid validating every file.
- **canonical status:** https://github.com/microsoft/vscode-eslint/issues/307 and https://github.com/microsoft/vscode-eslint/issues/506 were closed as duplicates of this issue when reporters requested project-level or continuously updated whole-directory linting; no broader open canonical was found.
- **remaining gap:** The contributed task provides an explicit full scan, but it does not make the language server continuously validate all unopened files; that distinction is repeatedly clarified in the issue discussion.
