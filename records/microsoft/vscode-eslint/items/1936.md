# Issue #1936 — ESLint Configuration Update in VSCode - support custom file names.

[https://github.com/microsoft/vscode-eslint/issues/1936](https://github.com/microsoft/vscode-eslint/issues/1936)

## Summary

The supplied reproduction demonstrates a real capability gap: the extension reloads when the top-level flat-config file changes, but not when a module imported by that configuration changes. Current main still has fixed watcher patterns and no setting for additional configuration dependencies, so this accepted Backlog request remains necessary.

## Change summary

Allow users to specify additional ESLint configuration files or globs whose changes should clear cached configuration and trigger revalidation.

## Best solution

Add a resource-scoped `eslint.*` setting for extra configuration file globs, create corresponding watchers in `client/src/client.ts`, and route their events through the existing server-side configuration-cache clearing and revalidation path in `server/src/eslintServer.ts`.
