# Issue #1936 — ESLint Configuration Update in VSCode - support custom file names.

[https://github.com/microsoft/vscode-eslint/issues/1936](https://github.com/microsoft/vscode-eslint/issues/1936)

## Summary

This remains a valid feature request: the extension reloads configuration when recognized top-level ESLint config files change, but it cannot detect arbitrary modules imported by those files. The existing Backlog milestone and feature-request/help-wanted labels appropriately preserve the work.

## Change summary

Allow users to configure additional files or glob patterns whose changes invalidate ESLint configuration and trigger revalidation.

## Best solution

Add a resource-scoped `eslint.*` setting for additional configuration dependency globs, create corresponding file-system watchers in `client/src/client.ts`, and pass their change events through the existing configuration-cache invalidation path in `server/src/eslintServer.ts`.

## Evidence

- **current watcher scope:** `client/src/client.ts` registers file-system watchers only for standard `.eslintrc*` names, `eslint.config.{js,mjs,cjs,ts,mts,cts}`, `.eslintignore`, and `package.json`; no existing setting accepts additional config dependency files or globs.
- **existing invalidation path:** `server/src/eslintServer.ts` handles watched-file changes by clearing rule metadata and ESLint settings before revalidating documents, so the missing capability is identifying additional files that should enter this path.
- **maintainer direction:** The maintainer concluded that configurable support for files whose changes should cause the server to re-fetch configuration is the plausible solution: https://github.com/microsoft/vscode-eslint/issues/1936#issuecomment-2428471853.
