# Issue #1936 — ESLint Configuration Update in VSCode - support custom file names.

[https://github.com/microsoft/vscode-eslint/issues/1936](https://github.com/microsoft/vscode-eslint/issues/1936)

## Summary

Keep open: custom config files and imported configuration modules still fall outside the extension's fixed file-watcher patterns. The reporter supplied a concrete example, and the maintainer explicitly suggested configurable refresh triggers; renaming the entry-point config does not satisfy that remaining request.

## Change summary

Automatically refresh ESLint diagnostics when user-selected custom configuration files or imported rule configuration modules change, without requiring a manual server restart.

## Best solution

Provide resource-scoped configuration-refresh triggers in the extension while preserving standard config watching and workspace-owned ESLint behavior. Establish whether watched-file revalidation also reloads imported CommonJS and ESM modules, since detecting a change alone may not overcome module caching.

## Vision fit

- **Fit:** aligned
- **Reason:** Recognizing changes to a workspace's split ESLint configuration improves configuration resolution and editor fidelity without overriding the project's lint rules.
- **Evidence:** The durable configuration-resolution theme and the guardrail that the workspace owns its ESLint configuration support making custom configuration changes effective in the editor.
