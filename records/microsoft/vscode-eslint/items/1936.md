# Issue #1936 — ESLint Configuration Update in VSCode - support custom file names.

[https://github.com/microsoft/vscode-eslint/issues/1936](https://github.com/microsoft/vscode-eslint/issues/1936)

## Summary

Thanks for the detailed reproduction. This remains a valid feature request: the extension watches recognized top-level ESLint configuration files but cannot detect changes to arbitrary modules imported by those files, and no existing setting covers that gap.

## Change summary

Allow users to specify additional files or glob patterns whose changes should invalidate cached ESLint configuration and refresh diagnostics.

## Best solution

Add a resource-scoped `eslint.*` setting for additional configuration-dependency file globs, create corresponding watchers in `client/`, and route their events through the existing server-side cache clearing and diagnostic refresh path. Preserve the current standard-config watchers as defaults.

## Evidence

- **confirmed source gap:** `client/src/client.ts` registers file-system watchers only for `.eslintrc*`, `eslint.config.{js,mjs,cjs,ts,mts,cts}`, `.eslintignore`, and `package.json`; arbitrary modules imported by a flat config are not watched.
- **refresh path already exists:** `server/src/eslintServer.ts` handles watched-file changes by clearing ESLint settings and rule caches and requesting a diagnostic refresh, so additional configured watchers could reuse the established invalidation path.
- **no existing capability:** `package.json` exposes 40 `eslint.*` settings, including `eslint.options` and `eslint.useFlatConfig`, but none configures additional watched files or configuration dependencies.
- **maintainer direction:** The maintainer proposed adding configuration through which users define which file changes should cause the server to fetch configuration again: https://github.com/microsoft/vscode-eslint/issues/1936#issuecomment-2428471853
- **concrete use case:** The reporter supplied a reproduction where changing `globals/globalsWebPPLJs.mjs`, imported by the top-level flat config, has no effect until restart, while editing the top-level config refreshes immediately: https://github.com/microsoft/vscode-eslint/issues/1936#issuecomment-2413731067
