[https://github.com/microsoft/vscode-eslint/issues/2060](https://github.com/microsoft/vscode-eslint/issues/2060)

## Summary

The incorrect `error` classification is confirmed: ESLint writes debug messages to stderr, which the LSP client maps to the output channel's error level. Keep the issue open because draft PR https://github.com/microsoft/vscode-eslint/pull/2212 is the active fix and is waiting for the required LSP-library API.

## Change summary

Classify ESLint debug messages as informational output and avoid duplicate timestamps while preserving genuine stderr errors.

## Best solution

Complete and land https://github.com/microsoft/vscode-eslint/pull/2212 after a `vscode-languageclient` release exposes the required `stdioOptions` API, using that supported API to route ESLint debug stderr output without reclassifying genuine server errors.
