# Issue #2060 — VS Code ESLint@3.0.16 --debug option

[https://github.com/microsoft/vscode-eslint/issues/2060](https://github.com/microsoft/vscode-eslint/issues/2060)

## Summary

The debug stream is reproducibly misclassified because ESLint writes informational debug messages to stderr and the language client forwards stderr through the output channel's error level. Keep the issue open because draft PR https://github.com/microsoft/vscode-eslint/pull/2212 explicitly fixes it and references this issue.

## Change summary

Display ESLint namespace debug messages as informational output without duplicate timestamps while preserving error-level handling for genuine server errors.

## Best solution

Update the draft implementation in https://github.com/microsoft/vscode-eslint/pull/2212 to use the configurable stream-handler API merged in https://github.com/microsoft/vscode-languageserver-node/pull/1839 once available in a published language-client version, then review and land the extension-side integration and its focused tests.
