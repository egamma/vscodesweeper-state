# Issue #2060 — VS Code ESLint@3.0.16 --debug option

[https://github.com/microsoft/vscode-eslint/issues/2060](https://github.com/microsoft/vscode-eslint/issues/2060)

## Summary

The ESLint debug stream is incorrectly presented as error output with duplicate timestamps, and the maintainer traced this to stderr handling in the LSP client. Keep the issue open because draft PR https://github.com/microsoft/vscode-eslint/pull/2212 explicitly fixes it and has not merged.

## Change summary

Present ESLint debug messages at info level and avoid duplicate timestamps in the VS Code ESLint output channel.

## Best solution

Update and review https://github.com/microsoft/vscode-eslint/pull/2212 using the `stdioOptions` API now available from the merged LSP-library change, then close this issue when that implementation lands.
