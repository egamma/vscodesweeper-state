# Issue #1229 — File exists, but `ENOENT: no such file or directory...` reported.

[https://github.com/microsoft/vscode-eslint/issues/1229](https://github.com/microsoft/vscode-eslint/issues/1229)

## Summary

The exact uncaught `fs.realpathSync.native` failure was fixed after this report: the server now catches realpath errors and continues with the original file path, so an ENOENT or Windows long-path failure no longer silently stops linting.

## Change summary

Files with paths that make `fs.realpathSync.native` throw are not linted even though they exist and ESLint can lint them from the command line.

## Best solution

Keep the current fallback in `server/src/paths.ts`, which preserves path normalization when available but passes the original path to ESLint when realpath resolution fails. Close this report as fixed beginning with the 2.4.1 pre-release, also included in stable 2.4.2.
