## Summary

The unhandled `fs.realpathSync.native` failure has been fixed: the server now catches realpath errors and continues with the original file path instead of silently losing linting.

## Change summary

Prevent existing files, particularly those with Windows paths beyond the legacy MAX_PATH limit, from losing ESLint diagnostics when native realpath reports ENOENT.

## Best solution

Treat the issue as fixed in extension 2.4.2 and later by the realpath fallback added in commit d8214448aa1ba338c84184239bfee66cea24fbaa.
