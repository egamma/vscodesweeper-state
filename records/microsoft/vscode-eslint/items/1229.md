# Issue #1229 — File exists, but `ENOENT: no such file or directory...` reported.

[https://github.com/microsoft/vscode-eslint/issues/1229](https://github.com/microsoft/vscode-eslint/issues/1229)

## Summary

The extension no longer lets `fs.realpathSync.native` failures prevent linting: the merged fix catches the exception and falls back to the original file path. That directly addresses the reported silent ENOENT failure and shipped in version 2.4.1.

## Change summary

Prevent realpath failures for existing long-path or otherwise unresolved files from silently stopping ESLint validation.

## Best solution

Keep the current fallback in `server/src/paths.ts`, which preserves the original URI-derived path whenever native realpath resolution fails, and close this report as fixed in 2.4.1.
