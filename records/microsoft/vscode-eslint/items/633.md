# Issue #633 — Lint whole folder task ignores workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/633](https://github.com/microsoft/vscode-eslint/issues/633)

## Summary

The gap remains on current main: the contributed lint task always runs once from the workspace-folder root and never reads `eslint.workingDirectories`. This issue is also the established canonical for subsequent reports, while both attempted fixes were closed without merging.

## Change summary

Make the lint-whole-folder task honor `eslint.workingDirectories`, running ESLint from each applicable configured directory.

## Best solution

Refactor the task provider in `client/src/tasks.ts` to contribute a task for each applicable working directory, with each task's `cwd` and ESLint binary resolved from that directory. The implementation should handle the setting's string, directory, pattern, and mode forms without shell-specific command chaining; if a single run-all entry remains desirable, it should orchestrate the individual tasks through VS Code's task API.

## Evidence

- **current source:** `client/src/tasks.ts` reads only `eslint.lintTask.command` and `eslint.lintTask.options`, creates one task per VS Code workspace folder, and sets `ShellExecutionOptions.cwd` to the workspace-folder root; it never reads `eslint.workingDirectories`.
- **setting semantics:** `package.json` documents `eslint.workingDirectories` as controlling how ESLint working directories are computed and supports strings plus directory, pattern, and mode objects, but the separate `eslint.lintTask.*` implementation does not consume it.
