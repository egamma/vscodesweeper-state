# Issue #633 — Lint whole folder task ignores workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/633](https://github.com/microsoft/vscode-eslint/issues/633)

## Summary

The gap remains on current main: the generated lint task always runs once from the workspace-folder root and never reads `eslint.workingDirectories`. This issue is the established canonical for adding working-directory-aware lint tasks and should remain open.

## Change summary

Make the lint-whole-folder task honor `eslint.workingDirectories`, running ESLint from each applicable configured directory.

## Best solution

Update `client/src/tasks.ts` to contribute a distinct task for each concrete working directory, with that directory as the task's `cwd`, and provide a shell-independent way to run all generated tasks when needed. The implementation should preserve the existing single workspace-root task when no working directories are configured and account for the setting's string, directory, pattern, and mode forms.

## Evidence

- **current source gap:** `client/src/tasks.ts` constructs exactly one task per workspace folder in `FolderTaskProvider.getTask()`, sets `ShellExecutionOptions.cwd` to `this.workspaceFolder.uri.fsPath`, and reads only `eslint.lintTask.command` and `eslint.lintTask.options`; it never reads `eslint.workingDirectories`.
- **maintainer intent:** The maintainer explicitly agreed that honoring the setting makes sense and proposed contributing one task per working directory: https://github.com/microsoft/vscode-eslint/issues/633#issuecomment-467440435
- **canonical status:** The maintainer closed the concrete subproject-cwd report https://github.com/microsoft/vscode-eslint/issues/1296 as a duplicate of this issue, confirming that #633 owns this remaining work.
- **multi-root confirmation:** The maintainer also closed https://github.com/microsoft/vscode-eslint/issues/1758 as a duplicate of this issue after a report that the lint task selected the wrong folder in a multi-root workspace.
- **unmerged implementation attempt:** https://github.com/microsoft/vscode-eslint/pull/1861 attempted the feature but closed without merging. Its review identified that chaining shell commands was incompatible with some PowerShell versions and would stop after the first ESLint nonzero exit, leading to the preferred design of separate tasks per working directory.
- **existing capability check:** `eslint.lintTask.command` and `eslint.lintTask.options` can customize the generated command, but neither changes its workspace-root `cwd` or generates tasks for entries in `eslint.workingDirectories`; no current setting covers the central request.
