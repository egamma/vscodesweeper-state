# Issue #633 — Lint whole folder task ignores workingDirectories setting

[https://github.com/microsoft/vscode-eslint/issues/633](https://github.com/microsoft/vscode-eslint/issues/633)

## Summary

The lint task still runs once from the workspace-folder root and does not read `eslint.workingDirectories`. The maintainer accepted the requested behavior, and subsequent reports were closed as duplicates of this issue, so #633 remains the canonical open feature request.

## Change summary

Make the lint-whole-folder task honor `eslint.workingDirectories` so monorepo projects are linted from their configured working directories.

## Best solution

Update `client/src/tasks.ts` to expose a task for each enumerable working directory and, if an aggregate action is retained, invoke those tasks through VS Code's task APIs rather than shell-specific command chaining. The implementation should preserve the existing workspace-folder task when no applicable working-directory configuration is present and account explicitly for string, directory, pattern, and mode forms.

## Vision fit

- **Reason:** Honoring configured working directories in the lint task advances the extension's established configuration-resolution and task/CLI-parity themes for multi-project workspaces.
- **Evidence:** The stated architecture goal is to "Support multiple workspace folders and dynamic working-directory inference," while the durable themes explicitly include configuration resolution and tasks/CLI parity.

## Evidence

- **current source gap:** `client/src/tasks.ts`, in `FolderTaskProvider.getTask`, always sets `ShellExecutionOptions.cwd` to the workspace-folder path and reads only `eslint.lintTask.command` and `eslint.lintTask.options`; it never reads `eslint.workingDirectories`.
- **setting remains separate:** `package.json` still defines `eslint.workingDirectories` independently from `eslint.lintTask.enable`, `eslint.lintTask.command`, and `eslint.lintTask.options`; no lint-task setting currently provides equivalent per-working-directory execution.
- **accepted direction:** The maintainer stated in the issue that honoring the setting makes sense and proposed contributing one task per working directory.
- **unmerged implementation attempt:** https://github.com/microsoft/vscode-eslint/pull/1861 attempted the feature but was closed without merging after review identified shell portability and command short-circuiting problems; the maintainer then suggested separate tasks per working directory plus an aggregate command.
- **canonical ownership:** https://github.com/microsoft/vscode-eslint/issues/1296 and https://github.com/microsoft/vscode-eslint/issues/1758 were closed by the maintainer as duplicates of #633, while the open-issue search found no separate open report owning this narrower working-directory task behavior.
