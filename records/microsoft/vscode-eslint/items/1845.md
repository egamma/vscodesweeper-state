# Issue #1845 — Worth using `NODE_COMPILE_CACHE` when detecting node v22+

[https://github.com/microsoft/vscode-eslint/issues/1845](https://github.com/microsoft/vscode-eslint/issues/1845)

## Summary

The requested compile-cache support remains a real extension-side performance feature: current main can pass Node arguments and set NODE_ENV, but it provides no NODE_COMPILE_CACHE setting or automatic activation. The existing Backlog placement and feature-request classification remain appropriate.

## Change summary

Enable Node's module compile cache for the ESLint language server when running on a compatible Node.js version, automatically or through an opt-in setting.

## Best solution

Keep this as an opt-in performance feature until its benefit and cache-location behavior are measured, then implement it in the client-side server launch configuration with an explicit compatibility check for the selected `eslint.runtime`. Automatic enablement should avoid assuming that VS Code's bundled runtime and a user-configured runtime have the same Node version.
