# Issue #1845 — Worth using `NODE_COMPILE_CACHE` when detecting node v22+

[https://github.com/microsoft/vscode-eslint/issues/1845](https://github.com/microsoft/vscode-eslint/issues/1845)

## Summary

The requested Node compile-cache integration remains absent from the current extension, and the maintainer confirmed that `eslint.execArgv` cannot configure an environment-only feature. This is a valid performance feature request already accepted into Backlog.

## Change summary

Automatically enable Node's on-disk module compile cache when the ESLint server runs on Node 22 or newer, potentially with a setting to control it.

## Best solution

In `client/src/client.ts`, configure a suitable extension-managed `NODE_COMPILE_CACHE` directory when spawning a compatible ESLint server runtime, with an explicit opt-out if needed for workflows such as precise V8 coverage. The implementation should account for a custom `eslint.runtime` and avoid changing behavior on unsupported Node versions.

## Evidence

- **current spawn configuration:** `client/src/client.ts` in `createServerOptions` supports `eslint.runtime`, `eslint.execArgv`, and the special-purpose `eslint.nodeEnv`, but only adds `DEBUG` and `NODE_ENV` to the server environment; it contains no `NODE_COMPILE_CACHE` handling.
- **existing settings do not cover the request:** `package.json` documents `eslint.execArgv` as runtime arguments and `eslint.nodeEnv` specifically as the value of `NODE_ENV`; neither provides the compile-cache environment variable requested here.
- **maintainer confirmation:** The discussion confirms that `eslint.execArgv` does not enable this environment-variable-only Node feature, correcting the initial suggested workaround.
- **Node capability:** https://github.com/nodejs/node/commit/4d77fd2c469cb32a5b06308f08290afd685f99be implements `NODE_COMPILE_CACHE` for automatic on-disk code caching and documents both its potential startup benefit and its V8 coverage caveat.
- **canonical search:** https://github.com/microsoft/vscode-eslint/issues/1401 is an older open request for passing arbitrary environment variables to the ESLint server and could provide a manual configuration mechanism, but it does not own this issue's central request for automatic Node-version-aware compile-cache activation.
