# Issue #1845 — Worth using `NODE_COMPILE_CACHE` when detecting node v22+

[https://github.com/microsoft/vscode-eslint/issues/1845](https://github.com/microsoft/vscode-eslint/issues/1845)

## Summary

The requested compile-cache optimization remains absent from current main, and the existing `eslint.execArgv` setting cannot enable an environment-variable-only feature. This is a valid, correctly classified performance feature request in the Backlog.

## Change summary

Enable Node's module compile cache for the ESLint language server when it runs on a compatible Node version, possibly behind a setting.

## Best solution

Benchmark language-server startup and validation with the compile cache, then conditionally enable it for supported Node runtimes using an extension-owned cache directory. The implementation likely belongs in the client-side server launch configuration, with a setting added only if automatic enablement is not considered safe.
