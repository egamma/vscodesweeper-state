# Issue #1655 — Customize error/warning message in VSCode

[https://github.com/microsoft/vscode-eslint/issues/1655](https://github.com/microsoft/vscode-eslint/issues/1655)

## Summary

Keep this accepted request open: the extension still flattens configuration-error messages and selectively displays notifications using message-pattern matching. Existing settings do not provide the requested multiline presentation or relief from long pnpm path prefixes, and the related formatting requests do not own this work.

## Change summary

Improve presentation of custom ESLint configuration errors so multiline messages remain visible in notifications and long pnpm paths do not obscure the actionable explanation.

## Best solution

Design readable configuration-error presentation in server/src/eslint.ts, preserving useful details in the ESLint output channel and preventing message formatting alone from determining notification eligibility. Agree on how notifications balance the custom explanation against configuration-path context, then verify the reported custom Error case.

Acceptance should compare ordinary and customized errors under identical conditions and verify the agreed notification presentation without increasing repeated-notification noise.
- **Trace:**

  > The request concerns exceptions thrown while loading ESLint configuration, not rule-diagnostic hover formatting. server/src/eslintServer.ts dispatches validation exceptions through ESLint.ErrorHandlers.single. In server/src/eslint.ts, tryHandleConfigError identifies selected configuration failures by matching error.message, while getMessage replaces newlines with spaces; unmatched errors reach showErrorMessage, which logs them without a popup.
