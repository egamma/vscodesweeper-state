# Issue #1655 — Customize error/warning message in VSCode

[https://github.com/microsoft/vscode-eslint/issues/1655](https://github.com/microsoft/vscode-eslint/issues/1655)

## Summary

The customization gap remains on current main: configuration-error messages are flattened before display, and errors outside a few recognized shapes only update ESLint's status and output rather than opening a notification. This is an accepted Backlog feature request with no broader canonical issue or existing setting that covers both multiline presentation and pnpm path cleanup.

## Change summary

Allow ESLint configuration errors to retain useful custom formatting in notifications and avoid obscuring their message with long package-manager paths.

## Best solution

Refine error presentation in `server/src/eslint.ts` so logging preserves full technical detail while notifications receive a concise, readable message, with an explicit decision about supported multiline formatting and path shortening. Tests should cover custom configuration errors and pnpm-style paths before changing the current normalization behavior.

- **existing-capability check:** The configuration surface in `package.json` has no setting for customizing configuration-error notification text. `eslint.problems.shortenToSingleLine` only shortens the underlined diagnostic range and does not format these notifications.
