# Issue #1655 — Customize error/warning message in VSCode

[https://github.com/microsoft/vscode-eslint/issues/1655](https://github.com/microsoft/vscode-eslint/issues/1655)

## Summary

A real presentation gap remains for customized ESLint configuration errors: current main normalizes newlines and recognizes only several exact error-message shapes before showing a notification. No existing setting or verified canonical issue covers this request, so the Backlog feature request should remain open.

## Change summary

Make customized ESLint configuration errors reliably appear as readable notifications, preserving useful formatting and reducing distracting package-manager paths.

## Best solution

Refactor the server-side configuration-error handling in `server/src/eslint.ts` so classification does not depend on exact newline and path formatting, then generate a concise notification while retaining the complete error in the ESLint output channel. The design should define which formatting is safe to preserve rather than exposing unrestricted notification styling.

## Evidence

- **current source:** `ErrorHandlers.getMessage` in `server/src/eslint.ts` still replaces every newline with a space, while `tryHandleConfigError` recognizes only three specific multiline message patterns and shows an information notification only after one of those patterns yields a filename.
- **unhandled fallback:** When a customized error does not match those patterns, `showErrorMessage` in `server/src/eslint.ts` writes it to the connection console and returns an error status without displaying the configuration-error notification, matching the reported disappearance mechanism.
- **existing-capability check:** `package.json` provides diagnostic severity customization through `eslint.rules.customizations` and output access through `eslint.showOutputChannel`, but no setting or command controls configuration-error message formatting or notification visibility.
- **canonical search:** The closest open reports, https://github.com/microsoft/vscode-eslint/issues/1719 and https://github.com/microsoft/vscode-eslint/issues/1887, concern formatting and links in lint-diagnostic hover tooltips, not configuration-load errors or notifications; neither owns this issue's remaining work.
- **maintainer direction:** The maintainer's comment suggested revisiting the extension's message generation and specifically questioned whether replacing newlines with spaces is still necessary, supporting an extension-side improvement rather than an upstream-only request.
