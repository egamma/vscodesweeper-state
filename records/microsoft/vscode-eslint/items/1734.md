# Issue #1734 — A change to eslint.debug requires VSCode restart if the ESLint server was already running

[https://github.com/microsoft/vscode-eslint/issues/1734](https://github.com/microsoft/vscode-eslint/issues/1734)

## Summary

Current source confirms that the restart command reuses server options captured when the language client was first created, so changing `eslint.debug` cannot update the server's `DEBUG` environment variable. This is a client lifecycle bug rather than a feature request and should remain open.

## Change summary

Make an ESLint server restart apply the current `eslint.debug` setting without requiring a full VS Code restart.

## Best solution

Update the client restart path so launch-affecting settings such as `eslint.debug` are read again and fresh server options are used when the server process is recreated. Automatically restarting when the setting changes is optional; the explicit `ESLint: Restart ESLint Server` command must at least apply the new value.

## Evidence

- **captured server options:** In client/src/client.ts, ESLintClient.create constructs the LanguageClient once with `createServerOptions(context.extensionUri)`; that function immediately reads `eslint.debug` and conditionally sets `env.DEBUG`.
- **restart reuses client:** In client/src/extension.ts, the normal `eslint.restart` command calls `client.restart()` without disposing and recreating the LanguageClient, so `createServerOptions` is not called again and the updated setting is not reflected in the child-process environment.
- **independent confirmation:** A second reporter confirmed that manually restarting the ESLint server did not enable debug mode, while restarting the entire editor did.
- **maintainer diagnosis:** The maintainer identified the likely defect in https://github.com/microsoft/vscode-eslint/issues/1734: the debug environment variable is not recomputed on server restart.
