# Issue #1734 — A change to eslint.debug requires VSCode restart if the ESLint server was already running

[https://github.com/microsoft/vscode-eslint/issues/1734](https://github.com/microsoft/vscode-eslint/issues/1734)

## Summary

Current main still captures `eslint.debug` only when constructing the language client, so the existing restart command relaunches the server with stale process options. The maintainer confirmed that a server restart should be sufficient, making the manual-restart failure an extension bug rather than only a feature request.

## Change summary

Changing `eslint.debug` after activation is not reflected by the ESLint server, even after running the extension's restart command.

## Best solution

Update the client lifecycle in `client/src/client.ts` and `client/src/extension.ts` so restarting the ESLint server recomputes process-launch settings such as `eslint.debug`, `eslint.runtime`, `eslint.execArgv`, and `eslint.nodeEnv`. Automatically restarting when `eslint.debug` changes can remain a separate UX decision; the existing manual restart must at least apply the current settings.
