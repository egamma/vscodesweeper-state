# Issue #1225 — eslint.nodePath only works with absolute paths in multi module vscode workspaces

[https://github.com/microsoft/vscode-eslint/issues/1225](https://github.com/microsoft/vscode-eslint/issues/1225)

## Summary

The requested capability remains absent: current main still resolves a relative `eslint.nodePath` against each containing workspace folder. The maintainer explicitly reopened and reclassified the issue as a feature request with `help wanted`, so it should remain in the Backlog.

## Change summary

Allow a shared, repository-relative `eslint.nodePath` in multi-root workspaces without requiring an absolute machine-specific path or per-folder settings.

## Best solution

Preserve the existing workspace-folder-relative behavior for compatibility, but add an explicit opt-in way to resolve `eslint.nodePath` from the multi-root workspace file or another shared project base. This would require defining the setting behavior in `package.json`, passing the selected base through `client/src/client.ts` and the shared settings type, and applying it during module resolution in `server/src/eslint.ts`.

## Evidence

- **current implementation:** `server/src/eslint.ts:982-988` copies `settings.nodePath` and, when it is relative, joins it with `workspaceFolderPath`; therefore the same `.code-workspace` value is resolved separately for each workspace folder rather than from the repository or workspace-file directory.
- **setting surface:** `package.json` defines `eslint.nodePath` as a single `machine-overridable` string and documents only that it is added when resolving the ESLint module; there is no setting for choosing a workspace-file or common-project resolution base.
- **confirmed behavior:** The reproduction in https://github.com/microsoft/vscode-eslint/issues/1225#issuecomment-881111989 confirms that `.yarn/sdks` is resolved from each workspace folder and that a depth-adjusted path such as `../../.yarn/sdks` works, matching the current source path.
