# Issue #1225 — eslint.nodePath only works with absolute paths in multi module vscode workspaces

[https://github.com/microsoft/vscode-eslint/issues/1225](https://github.com/microsoft/vscode-eslint/issues/1225)

## Summary

This is a still-relevant request for a portable project-root-relative `eslint.nodePath` in Yarn monorepos that use multi-root workspaces. Current behavior is intentional, but the existing absolute-path and per-folder workarounds do not satisfy the central request, and the Backlog plus `feature-request`/`help wanted` classification supports keeping it open.

## Change summary

Allow a shared multi-root `.code-workspace` file to locate a monorepo-root Yarn SDK without embedding an absolute machine-specific path.

## Best solution

Preserve the existing workspace-folder-relative meaning of `eslint.nodePath` to avoid a breaking change, while adding an explicit portable way to resolve the path from the monorepo or workspace-file root. This would require coordinated setting-schema, client configuration, shared settings, and server resolution changes rather than silently changing the current setting's base directory.

- **resource-scoped retrieval:** `client/src/client.ts:719` retrieves `eslint.nodePath` from the configuration associated with each resource, and `client/src/client.ts:741-744` sends that resource's workspace folder to the server.
- **existing setting limitation:** `package.json:83-90` defines `eslint.nodePath` as a single machine-overridable string and documents only that it is used for module resolution; it provides no project-root base or variable mechanism.
- **confirmed multi-root distinction:** The reproduction repository linked in the discussion demonstrates that `.yarn/sdks` works for a single-root workspace but is resolved from each child folder in a multi-root workspace; another participant independently confirmed the same resolution behavior.
