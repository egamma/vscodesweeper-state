# Issue #1911 — Support for `typescript-eslint` v8's parser `projectService`

[https://github.com/microsoft/vscode-eslint/issues/1911](https://github.com/microsoft/vscode-eslint/issues/1911)

## Summary

The confirmed `projectService` behavior is a specific instance of the broader cross-file state invalidation problem already tracked by the open issue https://github.com/microsoft/vscode-eslint/issues/1774. The upstream reload workaround reduces one symptom but does not provide the durable watcher and revalidation integration requested here.

## Change summary

Keep typescript-eslint's long-lived project service synchronized when files or directories are created, without requiring an ESLint server restart.

## Best solution

Consolidate this reproduction and the later configuration-specific confirmations into https://github.com/microsoft/vscode-eslint/issues/1774, where the extension-side watcher/revalidation behavior and any required ESLint or parser API can be designed together without duplicating the performance-sensitive work.
