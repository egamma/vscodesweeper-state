# Issue #1898 — Restarting an extension when that extension's output is selected in the "Output" pane should not change which extension is selected in the "Output" pane.

[https://github.com/microsoft/vscode-eslint/issues/1898](https://github.com/microsoft/vscode-eslint/issues/1898)

## Summary

The requested output-channel continuity remains unimplemented on current main. The restart path still lets the language client own the channel lifecycle, and a directly targeted fix attempt was closed without merging, so this accepted Backlog request should remain open.

## Change summary

Keep the ESLint output channel selected and avoid forcing the Output pane into focus when the ESLint language server restarts.

## Best solution

Have the client retain a shared ESLint output channel across `LanguageClient.restart()` calls so restarting does not dispose and recreate the selected channel. Preserve focus by default; the separate opt-in request to reveal output on restart remains tracked by https://github.com/microsoft/vscode-eslint/issues/2205.
