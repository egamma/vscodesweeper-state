# Issue #1739 — Improve error message / feedback when a file can't be linted with ESLint when in probing mode

[https://github.com/microsoft/vscode-eslint/issues/1739](https://github.com/microsoft/vscode-eslint/issues/1739)

## Summary

The requested diagnostic remains absent on current main: probing deliberately suppresses user-facing errors and reports probe failure to the client without recording why. The maintainer accepted a non-disruptive informational log as useful, so this remains a valid Backlog feature request.

## Change summary

Record helpful output-channel information explaining why ESLint probing rejected a file, without displaying disruptive notifications for files users do not expect to lint.

## Best solution

Enhance the probing path in `server/src/eslint.ts` to log a concise informational reason when ESLint cannot be loaded, no applicable configuration is found, the file is ignored, or the required parser support is absent. Preserve silent probing in the UI, avoid inventing a fallback configuration, and keep the existing client cleanup behavior after `eslint/probeFailed`.
