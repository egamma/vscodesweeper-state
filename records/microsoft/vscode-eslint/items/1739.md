# Issue #1739 — Improve error message / feedback when a file can't be linted with ESLint when in probing mode

[https://github.com/microsoft/vscode-eslint/issues/1739](https://github.com/microsoft/vscode-eslint/issues/1739)

## Summary

The requested probing feedback remains a valid, accepted feature gap: current main records that probing failed but still does not provide a useful reason in the ESLint output channel. The existing feature-request and Backlog classification remain appropriate.

## Change summary

Add non-disruptive output explaining why ESLint probing rejected a file and how common causes such as a missing ESLint installation, configuration, or parser can be resolved.

## Best solution

Keep probing silent from notifications while writing a concise informational entry to the ESLint output channel that identifies the failed file and, where determinable, the failure category and relevant remediation. Do not invent or fall back to a default ESLint configuration.

## Vision fit

- **Fit:** aligned
- **Reason:** Making configuration and probing failures legible improves configuration resolution without overriding the workspace-owned ESLint setup or disturbing users with notifications.
- **Evidence:** The durable configuration-resolution theme covers locating the correct ESLint installation and configuration, while the guardrails explicitly place discoverability and legible configuration failures in scope.
