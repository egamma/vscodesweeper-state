# Issue #1814 — Feature request: Provide a way to control files fixed during onCodeActionsSave (e.g., ignorePatterns)

[https://github.com/microsoft/vscode-eslint/issues/1814](https://github.com/microsoft/vscode-eslint/issues/1814)

## Summary

The requested capability is now implemented: `eslint.codeActionsOnSave.options` passes a separate ESLint options object when computing fixes on save, allowing `ignorePatterns` or an alternate config to limit which files are fixed.

## Change summary

Allow fix-on-save to exclude files independently of normal ESLint validation, without maintaining a separate rule allowlist.

## Best solution

Use `eslint.codeActionsOnSave.options` with ESLint's `ignorePatterns` option, or with `overrideConfigFile` when a dedicated save-time configuration is preferable. The implementation first shipped in extension release 3.0.16.

## Vision fit

- **Fit:** aligned
- **Reason:** Providing save-specific ESLint options strengthens the extension's established fix-on-save and configuration-resolution surfaces while continuing to delegate ignore semantics to the workspace's ESLint library.
- **Evidence:** The durable themes explicitly include fixes and code actions, especially fix-on-save scope, and the guardrails state that the workspace owns its ESLint configuration.
