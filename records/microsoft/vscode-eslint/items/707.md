# Issue #707 — Quick Fix for CRLF to LF does not work

[https://github.com/microsoft/vscode-eslint/issues/707](https://github.com/microsoft/vscode-eslint/issues/707)

## Summary

The quick fix remains a confirmed extension bug: ESLint returns edits that replace line delimiters, but the server converts them to ordinary LSP text ranges even though VS Code normalizes document EOLs, making CRLF-to-LF edits ineffective and potentially turning LF-to-CRLF edits into blank lines. The issue is correctly retained in On Deck while the extension decides how to implement document-wide EOL conversion.

## Change summary

Make ESLint quick fixes that change line endings convert the document's EOL mode correctly instead of doing nothing or introducing blank lines.

## Best solution

Handle line-ending fixes as an all-or-nothing document operation, likely by coordinating the server's ESLint-fix detection with a client-side VS Code EOL change rather than representing each delimiter replacement as a normal LSP TextEdit. Preserve an explicit path for files intentionally containing mixed line-ending test data.
