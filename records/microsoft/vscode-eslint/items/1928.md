# Issue #1928 — Configuration to use a formatter

[https://github.com/microsoft/vscode-eslint/issues/1928](https://github.com/microsoft/vscode-eslint/issues/1928)

## Summary

The extension still has no facility for applying an ESLint output formatter to editor diagnostics, and the maintainer confirmed that limitation. Native bulk-suppression support now provides a related option for ESLint 10.1+, but it does not cover this ESLint 8.24 formatter's date-based `.lint-todo` workflow, so a meaningful gap remains.

## Change summary

Allow editor validation to honor a formatter such as `@lint-todo/eslint-formatter-todo`, suppressing tracked violations until their configured error dates.

## Best solution

Keep the request open while deciding whether the server should expose a general result-processing integration or explicitly support baseline suppression workflows. Any implementation should preserve the direct ESLint diagnostic path while addressing capabilities not covered by `eslint.bulkSuppression.*`, particularly older ESLint versions and expiration-based suppressions.
