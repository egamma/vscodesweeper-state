# Issue #1928 — Configuration to use a formatter

[https://github.com/microsoft/vscode-eslint/issues/1928](https://github.com/microsoft/vscode-eslint/issues/1928)

## Summary

The extension still cannot apply an arbitrary ESLint formatter to editor diagnostics. Current bulk-suppression support overlaps with the underlying large-codebase workflow but requires ESLint 10.1 or newer and `eslint-suppressions.json`, so it does not satisfy this ESLint 8.24 `.lint-todo` request.

## Change summary

Allow a formatter-backed lint-todo baseline to suppress VS Code diagnostics until each recorded violation becomes due.

## Best solution

Keep this in the backlog while deciding on a structured server-side integration for custom suppression baselines; arbitrary ESLint formatters produce presentation text rather than diagnostic records, so formatter selection alone may not provide a reliable mapping. The existing lint task remains a manual CLI workaround, while projects able to upgrade can evaluate the newer `eslint.bulkSuppression.*` support.
