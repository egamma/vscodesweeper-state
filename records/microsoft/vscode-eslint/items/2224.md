# Issue #2224 — Disable rule quick fixes insert JS-style comments into Markdown files

[https://github.com/microsoft/vscode-eslint/issues/2224](https://github.com/microsoft/vscode-eslint/issues/2224)

## Summary

The defect is conclusively present on current main: Markdown is absent from the language defaults, causing both line-level and file-level disable actions to emit JavaScript comments. Keep the issue open while the directly linked fixing PR is reviewed.

## Change summary

Use valid HTML comment syntax when disable-rule quick fixes are invoked for Markdown documents.

## Best solution

Review and land https://github.com/microsoft/vscode-eslint/pull/2225, which adds Markdown comment metadata and makes line-disable actions fall back to block comments when a language has no line-comment syntax; retain this issue until that implementation merges.

## Evidence

- **current source:** server/src/languageDefaults.ts has no `markdown` entry; `getLineComment('markdown')` therefore returns `//` and `getBlockComment('markdown')` returns `['/*', '*/']`.
- **affected actions:** server/src/eslintServer.ts uses those defaults in `createDisableLineTextEdit` and `createDisableFileTextEdit`, so current main emits JavaScript-style comments for both reported Markdown quick fixes.
- **open fixing PR:** https://github.com/microsoft/vscode-eslint/pull/2225 is open, references this issue with `Fixes #2224`, and changes server/src/languageDefaults.ts and server/src/eslintServer.ts to use HTML block comments for Markdown and fall back to block syntax when no line-comment syntax exists.
