# Issue #2088 — Request: add quick-fix action for adding same-line disables, i.e. `// eslint-disable-line`

[https://github.com/microsoft/vscode-eslint/issues/2088](https://github.com/microsoft/vscode-eslint/issues/2088)

## Summary

The existing `eslint.codeAction.disableRuleComment.location` setting provides a global same-line mode, but it does not provide the requested per-occurrence choice between same-line and preceding-line actions. The issue remains a valid feature request and is not a duplicate of the automatic JSX-context detection requested in https://github.com/microsoft/vscode-eslint/issues/1074.

## Change summary

Offer a separate quick fix that inserts `eslint-disable-line`, allowing users to choose the disable-comment location for each diagnostic.

## Best solution

Keep the global location setting as the default preference, while having `server/src/eslintServer.ts` expose distinct same-line and separate-line code actions so users can override that preference when context requires it. The action identifiers or parameters must distinguish the two edits rather than storing both under the current single rule-based change key.

## Vision fit

- **Fit:** aligned
- **Reason:** A context-sensitive rule-disable action directly advances the extension's established investment in rich code actions and correct JSX/TSX handling.
- **Evidence:** `agents.md` states the goal to "Provide rich code actions (fix all, rule disable, suggestions) and formatting integration" and to handle language contexts where possible.
