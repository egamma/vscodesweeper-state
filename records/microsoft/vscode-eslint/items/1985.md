# Issue #1985 — Could not find config file. - at assertConfigurationExists

[https://github.com/microsoft/vscode-eslint/issues/1985](https://github.com/microsoft/vscode-eslint/issues/1985)

## Summary

Keep this open as the canonical feature request for limiting validation to explicitly configured working directories. The maintainer accepted the gap, the reporter supplied a reproduction, and current source still falls back to normal validation when a document is outside every configured directory.

## Change summary

Allow users to prevent ESLint validation for files outside the paths matched by `eslint.workingDirectories`.

## Best solution

Add an explicit, behavior-safe way for the client to disable validation when a document matches none of the configured working-directory entries, while preserving the existing fallback behavior by default. The setting contract belongs in `package.json` and shared settings, document selection in `client/src/client.ts`, and any required enforcement in `server/src/eslint.ts`.

## Evidence

- **maintainer decision:** The maintainer explained in https://github.com/microsoft/vscode-eslint/issues/1985#issuecomment-2750354183 that working directories are selected by path-prefix matching, confirmed that the requested mapping is unsupported, and explicitly kept the issue open as a feature request.
- **current source behavior:** `client/src/client.ts` reads `eslint.workingDirectories` and sets `settings.workingDirectory` only when the document path starts with a configured directory or matches a configured pattern; an unmatched root file leaves it undefined rather than disabling validation.
- **server fallback:** `server/src/eslint.ts` treats an undefined resolved working directory as location mode, derives a candidate from the workspace folder, and proceeds with ESLint resolution and validation. This explains why root files still trigger ESLint's config lookup.
- **existing setting does not cover request:** `package.json` describes directory entries as selecting a working directory when a file path starts with that directory; it provides no option to exclude unmatched documents. `eslint.validate` is language-based and cannot express package-root boundaries.
- **canonical status:** The maintainer closed https://github.com/microsoft/vscode-eslint/issues/1998 as a duplicate of this issue, while https://github.com/microsoft/vscode-eslint/issues/2030 concerns loading a specific config from a dependency and does not own the broader unmatched-directory behavior.
- **reproduction supplied:** The reporter supplied https://github.com/Edenomics/next-expo-turborepo with concrete steps and showed that removing the root config reproduces the config lookup for root files; the CLI also reports no root config when deliberately invoked there.
