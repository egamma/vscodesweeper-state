# Issue #1985 — Could not find config file. - at assertConfigurationExists

[https://github.com/microsoft/vscode-eslint/issues/1985](https://github.com/microsoft/vscode-eslint/issues/1985)

## Summary

Keep this accepted feature request open: `eslint.workingDirectories` selects a working directory for files whose paths match, but it does not act as an allowlist that disables ESLint for unmatched root files. The maintainer explicitly confirmed that limitation and retained this issue in Backlog.

## Change summary

Allow monorepos to restrict ESLint validation to configured working directories so files outside those directories are not probed for a configuration.

## Best solution

Add an explicit working-directory allowlist mode, or equivalent resource-scoped setting, that leaves validation off when a document matches none of the configured directories. The client should make that decision before the server calls ESLint configuration APIs, while preserving the current prefix-based working-directory selection as the default.

## Vision fit

- **Fit:** aligned
- **Reason:** Restricting validation to configured monorepo roots directly supports the extension's configuration-resolution and multi-workspace goals without overriding the workspace's ESLint configuration.
- **Evidence:** The durable themes include configuration resolution for monorepos through `eslint.workingDirectories`, and the stated architecture goal is to "Support multiple workspace folders and dynamic working-directory inference."

## Evidence

- **maintainer decision:** The maintainer confirmed that working directories are selected from the document path, that a directory not prefixed by that path cannot currently be used, and explicitly kept this open as a feature request: https://github.com/microsoft/vscode-eslint/issues/1985#issuecomment-2750354183
- **current matching behavior:** In `client/src/client.ts`, configured `directory` entries are selected only when `filePath.startsWith(directory)`, while pattern entries must match the document path; when no entry matches, `settings.workingDirectory` remains undefined rather than disabling validation.
- **validation path:** In `server/src/eslint.ts`, probe validation calls `eslintClass.isPathIgnored(filePath)` even when no configured working directory matched, which lets ESLint search for a root configuration and emit the reported `Could not find config file` error.
- **existing setting is not an allowlist:** The `eslint.workingDirectories` schema in `package.json` describes how working directories are computed and provides directory, pattern, and inference modes, but no mode that disables ESLint for documents outside all matches.
- **canonical search:** The later https://github.com/microsoft/vscode-eslint/issues/1998 was closed by the maintainer as a duplicate of this issue, reinforcing #1985 as the canonical report. The open https://github.com/microsoft/vscode-eslint/issues/2030 concerns selecting a flat config stored in `node_modules`, a distinct remaining mechanism.
