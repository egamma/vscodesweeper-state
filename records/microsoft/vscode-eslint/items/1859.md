# Issue #1859 — When the user provides eslint.options, remove the requirement for a eslint.config.js file

[https://github.com/microsoft/vscode-eslint/issues/1859](https://github.com/microsoft/vscode-eslint/issues/1859)

## Summary

The existing `eslint.options` setting already supports config-file-free operation through ESLint's `overrideConfigFile: true` constructor option, so no extension mode or synthesized file is needed.

## Change summary

Allow formatting from configuration supplied entirely through `eslint.options` when no `eslint.config.js` exists.

## Best solution

Keep passing `eslint.options` through unchanged and configure `overrideConfigFile: true` alongside `baseConfig`; ESLint then skips configuration-file discovery and uses the supplied configuration.

## Vision fit

- **Fit:** rejected
- **Reason:** Having the extension manufacture a configuration file would unnecessarily duplicate ESLint's existing configuration mechanism and weaken the boundary that leaves configuration semantics to workspace ESLint.
- **Evidence:** The vision states that the extension integrates the ESLint library installed in the workspace and that the workspace owns its ESLint configuration.

- **Proposed comment:**

  > Thanks for the context. `eslint.options` is passed directly to the ESLint constructor, and ESLint already provides an option for this case. Set `overrideConfigFile` to `true` alongside the supplied configuration:
  > 
  > ```json
  > "eslint.options": {
  >   "overrideConfigFile": true,
  >   "baseConfig": {
  >     "rules": {
  >       // rules here
  >     }
  >   }
  > }
  > ```
  > 
  > With `overrideConfigFile: true`, ESLint does not search for an `eslint.config.js`, so an empty placeholder file should not be necessary.

## Auto-fix candidate

## Evidence

- **existing extension capability:** `package.json` documents `eslint.options` as the object of options passed to ESLint, and `server/src/eslint.ts` constructs `newOptions` directly from `settings.options` in `ESLint.withClass()` before creating the ESLint instance.
- **ESLint API:** The ESLint Node.js API documents `overrideConfigFile: true` as disabling configuration-file search and provides a `lintText` example combining it with an inline configuration: https://eslint.org/docs/latest/integrate/nodejs-api
- **maintainer boundary:** The maintainer noted at https://github.com/microsoft/vscode-eslint/issues/1859#issuecomment-2160345107 that the configuration-file expectation comes from ESLint rather than enforcement by the extension.
