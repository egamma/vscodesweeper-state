# Issue #1859 — When the user provides eslint.options, remove the requirement for a eslint.config.js file

[https://github.com/microsoft/vscode-eslint/issues/1859](https://github.com/microsoft/vscode-eslint/issues/1859)

## Summary

ESLint already provides the requested no-config mode through `overrideConfigFile: true`, and the extension passes `eslint.options` directly to the ESLint constructor. This can therefore be resolved as a configuration question rather than requiring an extension change.

## Change summary

Allow rules supplied through `eslint.options.baseConfig` to work without creating an `eslint.config.js` file.

## Best solution

Keep the extension's transparent handling of ESLint constructor options and configure `eslint.options.overrideConfigFile` as `true` alongside `baseConfig`; ESLint will then skip configuration-file discovery and use the supplied configuration.

## Vision fit

- **Fit:** rejected
- **Reason:** Automatically synthesizing or inferring configuration in the extension would duplicate ESLint's configuration policy instead of faithfully passing through the workspace's chosen ESLint options.
- **Evidence:** The vision says that "The extension uses the ESLint library installed in the opened workspace folder" and that the workspace owns its ESLint version and configuration; ESLint's documented constructor option already controls whether configuration-file lookup occurs.

- **Proposed comment:**

  > Thanks for the request. The extension passes `eslint.options` through to ESLint, and ESLint already has an option for this case. You can disable configuration-file lookup while retaining your in-memory base configuration:
  > 
  > ```json
  > "eslint.options": {
  >   "overrideConfigFile": true,
  >   "baseConfig": {
  >     "rules": {
  >       // rules here
  >     }
  >   }
  > }
  > ```
  > 
  > With `overrideConfigFile: true`, ESLint does not search for an `eslint.config.js` file. This behavior is documented in the ESLint Node.js API: https://eslint.org/docs/latest/integrate/nodejs-api#-new-eslintoptions

## Evidence

- **existing extension capability:** `client/src/client.ts` reads the complete `eslint.options` object into the resource-scoped settings, and `server/src/eslint.ts` copies `settings.options` into the options passed to the ESLint class constructor without requiring a configuration file itself.
- **ESLint API:** The ESLint Node.js API documents `overrideConfigFile: true` as disabling configuration-file search and shows it together with an in-memory configuration: https://eslint.org/docs/latest/integrate/nodejs-api#-new-eslintoptions
- **maintainer boundary:** The maintainer noted in https://github.com/microsoft/vscode-eslint/issues/1859#issuecomment-2160345107 that the configuration-file expectation comes from ESLint rather than enforcement by the extension.
