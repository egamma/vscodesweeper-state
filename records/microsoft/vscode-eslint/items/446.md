# Issue #446 — Add option to auto-disable if no `.eslintrc`

[https://github.com/microsoft/vscode-eslint/issues/446](https://github.com/microsoft/vscode-eslint/issues/446)

## Summary

This remains an accepted, unscheduled feature request: current activation probing limits validation but still starts the language server, and no setting automatically suppresses startup when a workspace has no ESLint installation or configuration.

## Change summary

Add an opt-in way to avoid starting ESLint automatically for workspaces that do not use it.

## Best solution

Add an off-by-default, resource-scoped activation option that can reliably gate server startup without duplicating ESLint's evolving configuration-discovery rules, accounting for multi-root workspaces and global installations. The existing manual workspace disablement should remain the fallback.

## Vision fit

- **Fit:** aligned
- **Reason:** Avoiding unnecessary language-server startup in unrelated workspaces advances the extension's stated lazy-activation and responsiveness goals, provided configuration discovery remains delegated to ESLint where possible.
- **Evidence:** The architecture goal says to "Defer activation until needed," while the guardrails emphasize adapting to the workspace's ESLint installation and configuration rather than reimplementing ESLint semantics.

## Evidence

- **current activation path:** package.json activates the extension on `onStartupFinished`; client/src/extension.ts delays real activation until an open document passes the language validator, but realActivate() then creates and starts the language client without checking for a workspace-local ESLint dependency or configuration.
- **probing is not startup suppression:** client/src/client.ts handles failed probing and missing ESLint libraries only after the client/server has started. Its NoConfigRequest and NoESLintLibraryRequest handlers report the condition and recommend the manual `Disable ESLint` command.
- **existing settings do not cover the request:** package.json exposes `eslint.enable`, `eslint.validate`, `eslint.probe`, and `eslint.workingDirectories`, but none conditionally disables activation based on whether ESLint is installed or configured. `eslint.probe` controls which language IDs are probed, not whether the server starts.
- **maintainer direction:** In https://github.com/microsoft/vscode-eslint/issues/446, the maintainer welcomed a contribution, explained that configuration discovery must not become a duplicate of ESLint's lookup rules, and stated that any such behavior must be optional and disabled by default.
- **canonical search:** Searches for open issues concerning automatic disabling, missing ESLint installations, package.json gating, and suppressing server startup found no separate open canonical. https://github.com/microsoft/vscode-eslint/issues/1739 concerns feedback after probing fails, not preventing server startup.
