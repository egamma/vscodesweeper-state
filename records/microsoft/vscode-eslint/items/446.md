# Issue #446 — Add option to auto-disable if no `.eslintrc`

[https://github.com/microsoft/vscode-eslint/issues/446](https://github.com/microsoft/vscode-eslint/issues/446)

## Summary

A real capability gap remains: the extension activates when a supported document opens even if the workspace has neither an ESLint dependency nor usable configuration. The existing manual disablement and working-directory features do not provide the requested opt-in automatic behavior.

## Change summary

Add an opt-in mode that avoids starting the ESLint language server for workspaces that do not use ESLint.

## Best solution

Keep this as an opt-in, default-off feature and use a narrowly defined signal such as a resolvable workspace ESLint dependency, rather than independently reproducing ESLint's evolving configuration lookup rules. The activation decision belongs in `client/`, with the setting declared in `package.json` and propagated through the shared settings surface as needed.

## Vision fit

- **Fit:** aligned
- **Reason:** Avoiding unnecessary language-server startup directly supports the extension's stated lazy-activation and editor-responsiveness goals.
- **Evidence:** `agents.md` lists "Defer activation until needed" as an architectural goal, while the vision identifies editor responsiveness and avoiding unconditional work as guardrails.

## Evidence

- **current activation path:** `client/src/extension.ts` activates the full client through `realActivate(context)` whenever `Validator.check` considers an opened document eligible; this check uses `eslint.validate`/`eslint.probe`, not the presence of a workspace ESLint dependency or configuration.
- **existing setting is manual:** `package.json` exposes `eslint.enable`, but it is a general enable/disable setting rather than an automatic dependency/configuration gate; `client/src/extension.ts` also describes it as deprecated in favor of VS Code's manual extension-disablement feature.
- **partial failure handling:** `client/src/client.ts` handles `NoConfigRequest` only after the language client is running, logs that the file will not be validated, and suggests the manual `Disable ESLint` command. This does not satisfy the request to avoid starting the server.
- **maintainer direction:** The maintainer accepted that a guarded implementation could be considered behind an off-by-default flag, while rejecting a hard-coded `.eslintrc` search because it would duplicate ESLint's configuration-discovery rules.
