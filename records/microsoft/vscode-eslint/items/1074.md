# Issue #1074 — doesn't apply right fix comment in jsx/tsx context

[https://github.com/microsoft/vscode-eslint/issues/1074](https://github.com/microsoft/vscode-eslint/issues/1074)

## Summary

Thanks for the report. The accepted On Deck request remains necessary: current main chooses disable-comment syntax from the document language and configured line/block style, without determining whether the diagnostic is inside JSX.

## Change summary

Make disable-rule quick fixes emit JSX-safe comments such as `{ /* eslint-disable-next-line ... */ }` when a diagnostic occurs inside JSX or TSX markup.

## Best solution

Keep this as the canonical request and implement context-aware comment generation in the server, likely by using the configured ESLint parser's ESTree to determine whether the diagnostic is within a JSX node before constructing the text edit. Preserve the existing behavior for ordinary JavaScript and TypeScript contexts and for non-JSX languages.

- **Evidence:** The architecture goals explicitly include providing rich code actions, including rule-disable actions, and transparently supporting ESLint parsers and TypeScript/JavaScript configurations.

## Evidence

- **current source gap:** On current main, server/src/eslintServer.ts createDisableLineTextEdit and createDisableSameLineTextEdit select comment markers only through LanguageDefaults using textDocument.languageId and eslint.codeAction.disableRuleComment.commentStyle; neither function inspects the syntax node at the diagnostic location.
- **TSX and JSX defaults:** server/src/languageDefaults.ts maps both javascriptreact and typescriptreact to `//` line comments and `/* */` block comments for the entire document, so it cannot distinguish JavaScript statements from JSX markup within the same file.
- **maintainer solution direction:** The maintainer identified parsing with the configured ESLint parser and walking the ESTree parent chain to detect JSXElement context as the preferred editor-independent approach: https://github.com/microsoft/vscode-eslint/issues/1074#issuecomment-1206470902
- **canonical status:** A later report covering the same context-insensitive disable-comment behavior was manually closed as a duplicate of this issue, confirming this issue as the canonical tracker: https://github.com/microsoft/vscode-eslint/issues/2029#issuecomment-3011955189
- **related fix is narrower:** https://github.com/microsoft/vscode-eslint/pull/2042 only changed the fallback block marker for unknown document languages; it did not add JSX/TSX syntax-context detection and therefore does not implement this request.
- **existing setting is insufficient:** eslint.codeAction.disableRuleComment.commentStyle can globally select line or block syntax, but it cannot choose JSX-safe wrapping based on the diagnostic's location within a mixed JavaScript/JSX or TypeScript/TSX document.
