# Issue #1843 — Separate options per working directory

[https://github.com/microsoft/vscode-eslint/issues/1843](https://github.com/microsoft/vscode-eslint/issues/1843)

## Summary

The extension still cannot associate different `eslint.options` values with individual working directories. This is a valid monorepo feature request already classified and accepted into Backlog, with no open canonical found that owns the same capability.

## Change summary

Allow each configured working directory in a monorepo to use its own ESLint options, such as a distinct `overrideConfigFile`.

## Best solution

Extend the working-directory configuration model so an entry can provide directory-specific ESLint options, then select and merge those options when `client/src/client.ts` resolves the working directory for each document. Preserve the existing workspace-level `eslint.options` behavior as the default and define precedence for the most-specific matching directory.

## Evidence

- **maintainer confirmation:** The maintainer confirmed at https://github.com/microsoft/vscode-eslint/issues/1843#issuecomment-2095459911 that separate options are currently unavailable because VS Code settings are scoped per workspace folder.
- **current settings schema:** `package.json` defines `eslint.options` as one resource-scoped object, while `eslint.workingDirectories` entries support only mode, directory or pattern matching, and cwd behavior; there is no per-entry options field.
- **current resolution path:** `client/src/client.ts` reads `eslint.options` once into the document settings before independently selecting the matching working directory. `$shared/settings.ts` likewise models `options` and `workingDirectory` as separate properties.
- **existing workaround is incomplete coverage:** The reporter can place a consistently named forwarding config in every package, but that requires extra package-local files and does not provide the requested directory-specific `eslint.options` capability.
- **canonical search:** Open searches for `overrideConfigFile`, `eslint.options` with monorepos, and working-directory options found no issue owning this same request. https://github.com/microsoft/vscode-eslint/issues/1936 concerns watching imported custom config files for changes, not selecting different options per directory.
