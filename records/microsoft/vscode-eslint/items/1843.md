# Issue #1843 — Separate options per working directory

[https://github.com/microsoft/vscode-eslint/issues/1843](https://github.com/microsoft/vscode-eslint/issues/1843)

## Summary

This is a confirmed capability gap: eslint.options can vary only at VS Code's resource-setting scope, while eslint.workingDirectories selects only a directory and cannot attach directory-specific ESLint options. The reporter has a workaround, but the requested first-class monorepo support remains unimplemented and is appropriately retained in Backlog.

## Change summary

Allow each configured ESLint working directory to supply its own options, such as a package-specific overrideConfigFile.

## Best solution

Design a backward-compatible extension to eslint.workingDirectories that can associate ESLint options with each directory or pattern, then carry the selected options through client/src/client.ts and $shared/settings.ts into server-side ESLint construction. Existing directory-only entries and workspace-folder settings must continue to behave unchanged.
