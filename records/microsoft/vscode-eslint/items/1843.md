# Issue #1843 — Separate options per working directory

[https://github.com/microsoft/vscode-eslint/issues/1843](https://github.com/microsoft/vscode-eslint/issues/1843)

## Summary

Keep this accepted Backlog request open: working-directory selection still cannot supply different ESLint options to packages within one workspace folder. The reporter's shared-name wrapper workaround does not deliver that capability, and no verified canonical owns the remaining work.

## Change summary

Allow packages in a single workspace folder to use distinct ESLint options, including different overrideConfigFile values, per working directory.

## Best solution

Provide an explicit way to associate ESLint options with working directories while preserving existing workspace-folder defaults and ESLint's configuration semantics. This belongs in the extension's settings schema and client configuration resolution, with the resolved per-resource options passed through to the server.
