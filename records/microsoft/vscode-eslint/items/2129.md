# Issue #2129 — ESLint plugin breaks when using `eslint-plugin-react-hooks`

[https://github.com/microsoft/vscode-eslint/issues/2129](https://github.com/microsoft/vscode-eslint/issues/2129)

## Summary

The follow-up supplies concrete reproduction steps and narrows the problem to whole-folder task diagnostics, not ordinary editor linting. The task uses VS Code's built-in stylish problem matcher, whose single-line parsing cannot consume the multiline React Hooks messages shown in the supplied log; keep this open with depends-on-vscode rather than request the same information again.

## Change summary

Whole-folder lint tasks should preserve diagnostic counts and rule codes when React Hooks rules emit multiline messages, without losing subsequent violations.

## Best solution

Resolve multiline stylish-output handling in microsoft/vscode's task problem matcher, or establish an extension-side formatter/matcher alternative that preserves the same diagnostics. The general multiline matcher request at https://github.com/microsoft/vscode/issues/9635 is an enabling dependency, not a verified duplicate; supporting the ESLint-specific output still needs to be established.
