# Issue #2129 — ESLint plugin breaks when using `eslint-plugin-react-hooks`

[https://github.com/microsoft/vscode-eslint/issues/2129](https://github.com/microsoft/vscode-eslint/issues/2129)

## Summary

The clarified report concerns the whole-folder task, not normal editor validation. That task feeds ESLint's multiline stylish output to VS Code's built-in `$eslint-stylish` problem matcher, whose single-line diagnostic pattern loses rule codes and subsequent diagnostics when a rule emits a multiline message; this should remain open and be routed through `depends-on-vscode`.

## Change summary

Running `eslint: lint whole folder` records only a fraction of ESLint's diagnostics when eslint-plugin-react-hooks emits multiline messages, while per-file language-server validation works correctly.

## Best solution

Update VS Code's built-in `$eslint-stylish` problem matching so a multiline ESLint message remains one diagnostic and parsing resumes correctly for following results. The extension already references that matcher by name from `client/src/tasks.ts`, so a core matcher correction should flow through without changing lint-result semantics here; https://github.com/microsoft/vscode/issues/9635 is a related capability issue but does not by itself own this ESLint-specific integration work.
