[https://github.com/microsoft/vscode-eslint/issues/1597](https://github.com/microsoft/vscode-eslint/issues/1597)

## Summary

Keep open: automatically showing a ruler derived from ESLint's max-len configuration remains an extension-side feature. The linked VS Code request supplies an enabling API, not the ESLint integration, and the existing depends-on-vscode label correctly records that dependency.

## Change summary

Automatically display an editor ruler at the configured max-len column while ESLint is active.

## Best solution

Retain this issue for the ESLint-specific integration, dependent on https://github.com/microsoft/vscode/issues/111251. Once an appropriate editor API is available, the server would resolve the applicable rule value and the client would contribute the corresponding ruler without overwriting user-owned ruler settings.
