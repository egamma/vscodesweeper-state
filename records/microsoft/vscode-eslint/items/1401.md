# Issue #1401 — Possible to pass environment variables to eslint server?

[https://github.com/microsoft/vscode-eslint/issues/1401](https://github.com/microsoft/vscode-eslint/issues/1401)

## Summary

The extension still supports only inherited process variables plus the dedicated `eslint.nodeEnv` setting; there is no way to provide arbitrary, project-specific variables such as `API_TOKEN` to the ESLint server. This remains a valid accepted feature request in the Backlog.

## Change summary

Allow projects to supply arbitrary environment variables to the ESLint language-server process so plugins can authenticate to external services.

## Best solution

Add a secure, machine-scoped mechanism in the client server-launch path for supplying selected environment variables without requiring VS Code itself to be launched from a specially configured shell or encouraging credentials to be committed in workspace settings. The design should account for workspace trust and secret handling before exposing a general environment map.

## Evidence

- **current launch behavior:** `client/src/client.ts` creates the language-server environment in `createServerOptions`; it explicitly adds only `DEBUG` and `NODE_ENV`, with all other variables available only through inheritance from the VS Code process.
- **existing capability is narrower:** `package.json` defines `eslint.nodeEnv` solely as the value of `NODE_ENV`; `eslint.runtime` selects the Node executable and `eslint.execArgv` supplies runtime arguments, so none covers an arbitrary variable such as `API_TOKEN`.
- **maintainer confirmation:** The maintainer confirmed that the only available workaround is to define the variable in a shell and launch VS Code from that shell: https://github.com/microsoft/vscode-eslint/issues/1401#issuecomment-1009770840
- **related request is not canonical:** https://github.com/microsoft/vscode-eslint/issues/1425 concerns variable interpolation inside `eslint.options` values and was routed to VS Code core; it does not provide or track arbitrary environment variables for the server process.
- **accepted backlog item:** The issue remains open in the Backlog milestone with `feature-request` and `help wanted`, indicating an accepted but unscheduled extension-side capability.
