# Issue #1401 — Possible to pass environment variables to eslint server?

[https://github.com/microsoft/vscode-eslint/issues/1401](https://github.com/microsoft/vscode-eslint/issues/1401)

## Summary

The extension still supports only `NODE_ENV`, not arbitrary per-project environment variables such as the requested API token. The Backlog milestone and existing `feature-request` and `help wanted` labels indicate that this is an accepted but unimplemented extension-side capability.

## Change summary

Allow a workspace to provide project-specific environment variables to the ESLint language-server process so plugins can authenticate to external services.

## Best solution

Add an extension-owned, resource-scoped mechanism in `package.json` and `client/src/client.ts` for supplying or securely referencing arbitrary environment variables when starting each workspace's ESLint server. The design should avoid encouraging API keys to be committed in `.vscode/settings.json` and preserve inherited process variables.

## Evidence

- **current capability is narrower:** `package.json` contributes `eslint.nodeEnv`, but no setting for arbitrary environment variables; its description limits it to the value of `NODE_ENV`.
- **server startup path:** `client/src/client.ts` `createServerOptions()` constructs the language-server environment with only the extension's debug variable and `NODE_ENV`, then passes that environment through `ServerOptions`; there is no path for `API_TOKEN` or another project-defined variable.
- **maintainer disposition:** The maintainer confirmed that launching VS Code from a shell containing the variable was the only known workaround: https://github.com/microsoft/vscode-eslint/issues/1401#issuecomment-1009770840. The issue remains in Backlog with `feature-request` and `help wanted`.
