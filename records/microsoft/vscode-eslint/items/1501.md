# Issue #1501 — Cannot use "Format Modified Lines" command or modifications formatOnSaveMode

[https://github.com/microsoft/vscode-eslint/issues/1501](https://github.com/microsoft/vscode-eslint/issues/1501)

## Summary

The requested range-limited formatting remains unsupported on current main because the extension still receives ESLint's whole-file fix output. The existing `feature-request` and `upstream` labels accurately capture the open capability gap.

## Change summary

Allow ESLint formatting and fix-on-save to affect only source-control-modified lines through VS Code's modified-lines formatting features.

## Best solution

ESLint first needs an API capable of producing fixes for a requested range without applying interacting fixes elsewhere; the extension could then register range formatting in `server/src/eslint.ts` and pass the requested range through the formatting handler in `server/src/eslintServer.ts`. Keep this issue as the extension-side adoption request so that upstream support does not leave the VS Code integration work untracked.

## Vision fit

- **Fit:** rejected
- **Reason:** The desired editor integration is useful, but the central missing capability is selective autofixing in ESLint itself rather than behavior this extension can faithfully provide from whole-file fix output.
- **Evidence:** The vision states that "ESLint's output is the spec; the extension's job is fidelity to it" and that the extension integrates the workspace-installed ESLint rather than defining lint or fix semantics.

## Evidence

- **current formatter registration:** `server/src/eslint.ts` registers only `DocumentFormattingRequest` with `DocumentFormattingRegistrationOptions`; it does not register a document-range formatting request.
- **whole-file fix path:** `server/src/eslintServer.ts` handles `onDocumentFormatting` by calling `computeAllFixes`, which passes the complete document text to `eslintClass.lintText` with `fix: true` and converts the resulting whole-document output into edits without accepting a requested range.
- **existing settings do not cover request:** `package.json` exposes `eslint.format.enable` and code-actions-on-save controls for mode, rules, and options, but none limits formatting or fixes to source-control-modified lines.
