# Issue #1501 — Cannot use "Format Modified Lines" command or modifications formatOnSaveMode

[https://github.com/microsoft/vscode-eslint/issues/1501](https://github.com/microsoft/vscode-eslint/issues/1501)

## Summary

The requested modified-lines formatting remains unsupported because the extension invokes ESLint's whole-document fix operation and exposes only document formatting. The existing `feature-request` and `upstream` classification is accurate, so this Backlog item should remain open.

## Change summary

Support VS Code's Format Modified Lines command and modifications-based format-on-save mode when ESLint is the configured formatter.

## Best solution

ESLint would first need a reliable range-scoped fix API or semantics that preserve rule interactions; the extension could then register an LSP document-range formatter in `server/src/eslint.ts` and handle it in `server/src/eslintServer.ts`. Until that capability exists, whole-document formatting should remain unchanged.

- **current formatter capability:** Current main registers only `DocumentFormattingRequest` in `server/src/eslint.ts`; there is no `DocumentRangeFormattingRequest` or range-formatting handler.
- **whole-document implementation:** `computeAllFixes` in `server/src/eslintServer.ts` passes the complete document text to `eslintClass.lintText` with `fix: true`, then diffs the complete fixed output against the original content. The formatting handler supplies no range.
- **existing settings do not cover request:** `eslint.format.enable` enables whole-document formatting, while `eslint.codeActionsOnSave.mode` supports only `all` and `problems`; neither setting limits fixes to version-control-modified lines.
