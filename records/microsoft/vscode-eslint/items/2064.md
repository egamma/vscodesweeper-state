# Issue #2064 — FEAT: Use ESLint extension without auto run

[https://github.com/microsoft/vscode-eslint/issues/2064](https://github.com/microsoft/vscode-eslint/issues/2064)

## Summary

Keep open: formatter-only operation without automatic linting remains unsupported. Hiding diagnostics or disabling fix-on-save does not satisfy the reporter's explicit requirement to stop background validation.

## Change summary

Allow explicitly requested ESLint formatting without automatically linting documents on typing or saving.

## Best solution

Provide an opt-in manual-only workflow that preserves formatter availability while preventing automatic diagnostic validation, with existing onType and onSave behavior unchanged. Define whether explicit revalidation should also be available in that mode.

- **Reason:** Separating explicit formatting from automatic validation advances the extension's formatting integration and editor-responsiveness goals without changing workspace rule semantics.

## Plan brief

- **Likely files:** `package.json`, `$shared/settings.ts`, `client/src/client.ts`, `server/src/eslint.ts`, `server/src/eslintServer.ts`, `README.md`
- **Validation:** Use a trusted workspace with a fixable ESLint rule and ESLint configured as the default formatter. In the proposed manual-only mode, opening, focusing, editing, and saving a document with format-on-save and save code actions disabled must not trigger diagnostic linting or show ESLint squiggles; explicitly invoking Format Document must still apply the expected ESLint fixes. Verify the chosen explicit-revalidation contract and confirm existing onType and onSave workflows remain unchanged.
- **Behavior:**

  > The reporter wants ESLint available as a formatter without automatically linting while developing. The current severity and save-action workarounds do not meet that requirement because background validation continues. In an opt-in manual-only workflow, opening, focusing, typing, and ordinary saving must not trigger diagnostic linting, while explicit Format Document must still apply ESLint fixes. Existing automatic workflows must retain their current behavior.
- **Trace:**

  > package.json and $shared/settings.ts expose only onType and onSave run modes. ESLintClient.createClientOptions in client/src/client.ts enables diagnostic pulls on change, save, and focus, with eligibility determined by eslint.run and Validator.check; the server diagnostic handler in server/src/eslintServer.ts then invokes ESLint.validate. Disabling validation is not a formatter-only workaround: ESLint.resolveSettings in server/src/eslint.ts registers formatting only for Validate.on documents, and computeAllFixes also requires that eligibility. Severity customization acts on ESLint results after linting rather than suppressing execution. The maintainer acknowledges the missing capability at https://github.com/microsoft/vscode-eslint/issues/2064#issuecomment-3199539681. The remaining design question is the public behavior of explicit validation in the new workflow; preserve workspace ESLint rules, document eligibility checks, and existing automatic-mode defaults.
- **Open decisions:**
  - Should manual-only mode expose diagnostic validation through eslint.revalidate, or should it remain strictly formatter-only with no ESLint diagnostics even after that command?
