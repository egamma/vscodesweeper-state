# Issue #2064 — FEAT: Use ESLint extension without auto run

[https://github.com/microsoft/vscode-eslint/issues/2064](https://github.com/microsoft/vscode-eslint/issues/2064)

## Summary

The requested formatter-only mode remains unsupported on current main: `eslint.run` permits only on-type or on-save diagnostics, while `eslint.format.enable` does not disable background validation. The existing Backlog and feature-request classification is appropriate.

## Change summary

Allow ESLint to remain available as a manually invoked formatter without automatically validating documents on type or save.

## Best solution

Add a disabled or manual diagnostic mode to `eslint.run` and carry it through the shared settings and client diagnostic-pull filtering, while continuing to synchronize eligible documents and serve explicit formatting requests when `eslint.format.enable` is enabled.

## Vision fit

- **Fit:** aligned
- **Reason:** Separating automatic diagnostics from explicit formatting supports the extension's formatting integration while avoiding unwanted background lint work.
- **Evidence:** The stated architectural goals include providing formatting integration, and the vision identifies editor responsiveness and avoiding unconditional work as product guardrails.

## Evidence

- **maintainer confirmation:** The maintainer stated on 2025-08-19 that formatter-only operation is currently not possible, and the issue was classified as a feature request with help wanted in the Backlog milestone.
- **missing run mode:** `package.json` defines `eslint.run` with only `onSave` and `onType`; `$shared/settings.ts` likewise declares `RunValues` as `'onType' | 'onSave'`, so there is no manual or disabled validation value.
- **diagnostic scheduling:** `client/src/client.ts` enables diagnostic pulls on change, save, and focus, filtering on-type versus on-save requests solely through the two existing `eslint.run` values.
- **formatter path is distinct:** `eslint.format.enable` only enables ESLint as a formatter, and `server/src/eslintServer.ts` handles explicit document-formatting requests through `computeAllFixes(..., AllFixesMode.format)`; it does not provide a setting that suppresses automatic diagnostics.
- **canonical search:** The related open https://github.com/microsoft/vscode-eslint/issues/1811 requests an extension-wide enable/disable command, which would also disable formatting and therefore does not own this narrower formatter-without-diagnostics capability.
