# Issue #1811 — Feature request: bring back enable/disable eslint command

[https://github.com/microsoft/vscode-eslint/issues/1811](https://github.com/microsoft/vscode-eslint/issues/1811)

## Summary

A real capability gap remains: current main offers no ESLint enable/disable command, and the maintainer explicitly accepted this request into Backlog with `feature-request` and `help wanted`. VS Code's restart-free extension disablement reduces the urgency but does not provide the requested single-command toggle.

## Change summary

Restore commands that let users temporarily enable or disable ESLint without navigating through the Extensions panel.

## Best solution

Keep the accepted request in Backlog and implement a lightweight command-based toggle in `client/`, defining whether it controls workspace extension enablement or only ESLint diagnostics. The latter would better serve the reporter's temporary, pre-commit workflow without repeatedly disabling the extension.
