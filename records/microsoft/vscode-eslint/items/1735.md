# Issue #1735 — Feature Request: print *something* when this plug-in is involved in a VS Code "Format Document" command

[https://github.com/microsoft/vscode-eslint/issues/1735](https://github.com/microsoft/vscode-eslint/issues/1735)

## Summary

The existing protocol trace provides an opt-in troubleshooting mechanism, but it does not satisfy the request for a concise indication that ESLint handled a Format Document invocation. The maintainer opposed enabling verbose tracing by default, while leaving this feature request accepted in Backlog, so the remaining product decision should stay open.

## Change summary

Emit a concise output-channel message by default when ESLint participates in a VS Code Format Document operation.

## Best solution

Decide whether formatting participation should be visible through a low-noise message distinct from full protocol tracing, then add that signal around the server's document-formatting path if its diagnostic value outweighs default output noise. The existing trace setting should remain the opt-in mechanism for detailed LSP traffic.
