# Issue #1735 — Feature Request: print *something* when this plug-in is involved in a VS Code "Format Document" command

[https://github.com/microsoft/vscode-eslint/issues/1735](https://github.com/microsoft/vscode-eslint/issues/1735)

## Summary

The existing trace setting provides opt-in protocol diagnostics, but it does not satisfy the request for concise, default confirmation when ESLint actually handles Format Document. The request remains a distinct, valid formatter-observability improvement despite the maintainer's concern about enabling verbose tracing by default.

## Change summary

Emit a concise message in the ESLint output channel whenever ESLint handles a VS Code Format Document request, without requiring verbose debugging or protocol tracing.

## Best solution

Add a lightweight informational log to the successful formatting path in `server/src/eslintServer.ts`, without enabling full protocol tracing or `eslint.debug` by default. It should identify that ESLint handled the document while avoiding messages when another formatter handled the request or ESLint never registered as a provider.
