# Issue #1735 — Feature Request: print *something* when this plug-in is involved in a VS Code "Format Document" command

[https://github.com/microsoft/vscode-eslint/issues/1735](https://github.com/microsoft/vscode-eslint/issues/1735)

## Summary

The existing trace setting provides verbose diagnostic output but does not satisfy the request for a concise, default indication that ESLint handled Format Document. The issue remains a valid formatter-observability request in the Backlog.

## Change summary

Emit a concise ESLint output-channel message when the extension handles a VS Code Format Document request, without requiring debug or protocol tracing.

## Best solution

Add a low-noise informational entry from the server formatting path, ideally identifying the formatted resource and outcome without enabling full LSP tracing. Keep this distinct from `eslint.trace.server`, which should remain an opt-in debugging facility.
