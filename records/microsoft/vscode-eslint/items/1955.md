# Issue #1955 — fixTypes requires meta.docs.url?

[https://github.com/microsoft/vscode-eslint/issues/1955](https://github.com/microsoft/vscode-eslint/issues/1955)

## Summary

The extension still discards rule metadata without a documentation URL, causing fixTypes filtering to omit otherwise eligible fixes. Keep this scheduled issue open: the maintainer accepted relaxing that requirement, and the Next milestone independently bars a close.

## Change summary

Allow fixTypes filtering to recognize a rule's metadata type even when meta.docs.url is absent.

## Best solution

Separate rule-type metadata availability from documentation-link eligibility in server/. Rules with a selected meta.type should retain their quick fixes without a documentation URL, while rules lacking a URL should not offer a documentation action.

At lines 1329–1333, ESLint.validate records a fix under eslint.options.fixTypes only when RuleMetaData.getType returns a selected type. Consequently, a rule with type='layout' but no documentation URL loses its recorded quick fix despite layout being selected.

This matches the trigger described in https://github.com/microsoft/vscode-eslint/issues/1955. Source: https://github.com/Stuk/eslint-plugin-header/blob/main/lib/rules/header.js.
- **Documentation consumer must remain consistent:** server/src/eslintServer.ts:692–701 currently uses RuleMetaData.hasRuleId to offer 'Show documentation'; lines 830–834 retrieve the URL before opening it. Broadening metadata capture alone would therefore expose a documentation action that does nothing for URL-less rules.
