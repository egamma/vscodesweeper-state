# Issue #1955 — fixTypes requires meta.docs.url?

[https://github.com/microsoft/vscode-eslint/issues/1955](https://github.com/microsoft/vscode-eslint/issues/1955)

## Summary

The `docs.url` requirement still prevents `fixTypes` from recognizing otherwise valid rule metadata, and the maintainer has confirmed that the restriction can be relaxed. The issue is scheduled in the `Next` milestone, which independently requires keeping it open.

## Change summary

Allow `eslint.options.fixTypes` to preserve fixes from rules that declare `meta.type` but omit `meta.docs.url`.

## Best solution

Update `RuleMetaData.capture` in `server/src/eslint.ts` to retain valid rule metadata independently of whether it has a documentation URL, while leaving `getUrl` optional and preserving existing URL-based code actions. Add coverage showing that a fixable rule with `meta.type` and no `meta.docs.url` remains available when filtered through `fixTypes`.
