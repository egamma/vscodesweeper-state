# Issue #1955 — fixTypes requires meta.docs.url?

[https://github.com/microsoft/vscode-eslint/issues/1955](https://github.com/microsoft/vscode-eslint/issues/1955)

## Summary

The limitation remains on current main: rule metadata is cached only when `meta.docs.url` exists, so `fixTypes` cannot recognize otherwise valid rule types. The maintainer agreed this can be relaxed, and the assigned `Next` milestone requires keeping the issue open.

## Change summary

Allow `eslint.options.fixTypes` to preserve fixes from rules that declare `meta.type` but omit `meta.docs.url`.

## Best solution

Update `RuleMetaData.capture` in `server/src/eslint.ts` to retain usable rule metadata independently of whether a documentation URL exists, while continuing to expose documentation actions only when a URL is present. Add server coverage for a fixable rule with `meta.type` and no `meta.docs.url`.
