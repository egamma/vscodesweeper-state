# Issue #1774 — ESLint does not re-compute cross-file information on file changes

[https://github.com/microsoft/vscode-eslint/issues/1774](https://github.com/microsoft/vscode-eslint/issues/1774)

## Summary

Keep open: focus-triggered validation and the revalidate command provide partial mitigation, but do not automatically refresh other open files after a dependency changes. The maintainer-supported request remains unresolved across both typed rules and non-TypeScript cross-file rules.

## Change summary

Refresh dependent files' ESLint diagnostics when another file changes, without restarting the server or imposing excessive background linting.

## Best solution

Design performance-bounded cross-file diagnostic refresh in the extension's client/server integration, distinguishing re-running rules from invalidating parser or plugin caches. Retain this issue for the general refresh capability; project-service file registration and upstream dependency-reporting APIs are related work, not replacements.

- **Behavior:**

  > Changing one file can leave diagnostics in other open files based on obsolete cross-file information. The desired capability is automatic refresh of affected diagnostics without requiring a server restart, manual revalidation, or focusing each dependent file. Acceptance must cover both adding and clearing diagnostics, including a non-TypeScript cross-file rule. Frequent edits and autosave must respect an agreed responsiveness and refresh-latency contract.
- **Trace:**

  > client/src/client.ts:createClientOptions enables diagnostic pulls on change, save, and focus, but watches only configuration-related files for filesystem-triggered global refresh. server/src/eslintServer.ts advertises interFileDependencies: false; its diagnostic handler validates only the requested document, while configuration watcher events request diagnostic refresh. server/src/eslint.ts:ESLint.validate delegates to eslintClass.lintText, so revalidation and parser/plugin cache invalidation are distinct concerns. client/src/extension.ts already provides eslint.revalidate, and focus refresh is documented in README.md, but those mechanisms only partially address the requested automatic behavior. The maintainer discussion at https://github.com/microsoft/vscode-eslint/issues/1774#issuecomment-1914487528 leaves dependency detection and refresh policy unsettled. Preserve workspace-owned rule semantics and avoid assuming TypeScript captures all cross-file consumers. https://github.com/microsoft/vscode-eslint/issues/1911 concerns a separate new-file registration failure and must not be treated as the canonical for this work. Current source was inspected without running the reproduction; the planning session should establish which representative parser/plugin configurations respond to revalidation alone.
- **Open decisions:**
  - Should automatic cross-file refresh update all open files' Problems entries after dependency changes, or is refresh when a dependent file gains focus the intended supported guarantee?
  - Which changes should trigger cross-file refresh—unsaved edits, saves, external filesystem changes—and what maximum delay and autosave throttling behavior are acceptable?
  - Should the capability apply automatically across cross-file plugins, or require opt-in or dependency metadata when safe automatic detection is unavailable?
