# Issue #1774 — ESLint does not re-compute cross-file information on file changes

[https://github.com/microsoft/vscode-eslint/issues/1774](https://github.com/microsoft/vscode-eslint/issues/1774)

## Summary

The extension now revalidates files when focused and provides a manual command to revalidate all open files, but it still does not automatically refresh dependent files after another file changes. This broader cross-file invalidation request remains a valid, accepted Backlog feature with no canonical issue that supersedes it.

## Change summary

Automatically refresh diagnostics in open files whose cross-file lint information may have become stale after another file changes.

## Best solution

Keep the existing focus and manual-refresh safeguards, then implement a bounded invalidation strategy across `client/` and `server/` once ESLint or plugins can expose dependency information; absent that API, the maintainer must choose a throttled open-file refresh policy that preserves editor responsiveness. This issue should remain the canonical tracker for the ecosystem-wide behavior, while narrower `projectService` cases such as https://github.com/microsoft/vscode-eslint/issues/1911 remain separate.
