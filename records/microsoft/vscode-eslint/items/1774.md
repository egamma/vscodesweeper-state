# Issue #1774 — ESLint does not re-compute cross-file information on file changes

[https://github.com/microsoft/vscode-eslint/issues/1774](https://github.com/microsoft/vscode-eslint/issues/1774)

## Summary

The cross-file refresh gap remains on current main: the server explicitly declares that diagnostics have no inter-file dependencies, while focus-based and manual revalidation only partially mitigate stale results. The issue should remain open for a performance-bounded extension-side refresh design.

## Change summary

Recompute diagnostics for other affected open files when a file change invalidates cross-file information used by ESLint rules or parsers.

## Best solution

Add a client/server refresh strategy that can invalidate affected open documents without unconditionally linting every file after every change, ideally using dependency information exposed by ESLint or plugins when available and a carefully throttled fallback otherwise. Preserve the existing focus refresh and `eslint.revalidate` command as manual recovery paths rather than treating them as full coverage.
