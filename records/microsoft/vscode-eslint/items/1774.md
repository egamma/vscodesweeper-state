# Issue #1774 — ESLint does not re-compute cross-file information on file changes

[https://github.com/microsoft/vscode-eslint/issues/1774](https://github.com/microsoft/vscode-eslint/issues/1774)

## Summary

Thanks for the detailed investigation. A real extension-side capability remains: cross-file rules can leave diagnostics stale because ESLint does not expose file dependencies or invalidation signals, while the extension's current focus refresh and manual revalidation command are only mitigations; keep the request open and record its upstream dependency.

## Change summary

Revalidate affected open documents when a file change invalidates cross-file information used by ESLint rules.

## Best solution

Establish an ESLint or plugin API that identifies affected files or signals invalidation, then have the client/server integration watch those dependencies and selectively refresh diagnostics without restarting ESLint or re-linting every open file. Preserve the existing manual `eslint.revalidate` command and focus refresh as fallbacks.

## Evidence

- **upstream API dependency:** The discussion identifies the missing ESLint dependency-registration API and references the upstream proposal at https://github.com/eslint/eslint/issues/15583; that proposal is closed and therefore is not a duplicate target.
- **existing manual mitigation:** package.json registers `eslint.revalidate` as "Revalidate all open files", and client/src/extension.ts:164-166 implements it by requesting a document-diagnostic refresh. This requires explicit user action and does not satisfy automatic cross-file invalidation.
- **existing focus mitigation:** client/src/client.ts:464-467 enables diagnostic pulls on focus, which refreshes a file when revisited but does not proactively clear stale diagnostics in other open files or the Problems view.
- **watcher scope:** client/src/client.ts currently synchronizes file events only for ESLint configuration, ignore, and package files; server/src/eslintServer.ts:292-300 responds to those watched changes by clearing settings and metadata. It does not watch arbitrary rule dependencies.
