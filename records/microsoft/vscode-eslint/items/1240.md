# Issue #1240 — Reporting errors from node_module and no way to suppress/disable (also ignores .eslintignore)`

[https://github.com/microsoft/vscode-eslint/issues/1240](https://github.com/microsoft/vscode-eslint/issues/1240)

## Summary

The command-line reproduction produces the same configuration-loading failure before ESLint applies ignore rules, and ESLint maintainers confirmed this as a legacy eslintrc defect. The issue should remain open but be routed as upstream because the extension delegates ignore and configuration resolution to the workspace's ESLint library.

## Change summary

Avoid reporting configuration-loading errors when an opened file under node_modules should be excluded by ESLint's ignore rules.

## Best solution

ESLint would need to determine that a file is ignored before loading its legacy eslintrc configuration. An extension-side hard-coded node_modules exclusion would diverge from ESLint and prevent intentional validation, while `eslint.onIgnoredFiles` cannot suppress configuration-loading failures.
