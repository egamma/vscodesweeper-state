# Issue #1240 — Reporting errors from node_module and no way to suppress/disable (also ignores .eslintignore)`

[https://github.com/microsoft/vscode-eslint/issues/1240](https://github.com/microsoft/vscode-eslint/issues/1240)

## Summary

Keep open with upstream classification: the discussion established that ESLint loads a dependency's legacy configuration before honoring ignores, and the same failure occurs from the CLI. The linked upstream issue was declined rather than fixed, so it supports neither a duplicate nor a completed close.

## Change summary

Avoid configuration-loading errors when an ignored node_modules file belongs to a dependency with its own eslintConfig.

## Best solution

ESLint owns the legacy configuration-versus-ignore ordering, documented in https://github.com/eslint/eslint/issues/14686. Retain this accepted item for a maintainer decision on whether an extension-side exclusion mechanism is warranted; flat-config migration is a possible alternative, not evidence that the reported legacy workflow is fixed.
