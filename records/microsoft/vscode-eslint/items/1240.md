# Issue #1240 — Reporting errors from node_module and no way to suppress/disable (also ignores .eslintignore)`

[https://github.com/microsoft/vscode-eslint/issues/1240](https://github.com/microsoft/vscode-eslint/issues/1240)

## Summary

ESLint confirmed that legacy config resolution can fail inside node_modules before its ignore check runs. The upstream fix was declined, while the extension still exposes that failure when such a document is opened, so this should remain open with upstream routing while an extension-side mitigation is considered.

## Change summary

Avoid reporting ESLint configuration-loading errors for ignored files under node_modules, or provide a way to suppress validation for those paths.

## Best solution

Add an extension-side guard in the server's document-validation path that avoids resolving or linting files under node_modules when they are ignored, without changing validation for explicitly included workspace files. This mitigation is still relevant because eslint/eslint declined to modify legacy eslintrc resolution.

## Evidence

- **confirmed upstream behavior:** ESLint contributors reproduced the failure and confirmed that a node_modules package containing eslintConfig is resolved before ignore handling: https://github.com/eslint/eslint/issues/14686#issuecomment-877592115
- **upstream decision:** The ESLint team declined to change legacy eslintrc resolution because that subsystem was frozen during the transition to flat config: https://github.com/eslint/eslint/issues/14686#issuecomment-946270625
- **current extension path:** server/src/eslint.ts still calls eslintClass.isPathIgnored(filePath) while resolving document settings and reports an error if that call throws; validation later calls lintText with the document file path. The node_modules check in findWorkingDirectory only prevents directory probing and does not disable document validation.
- **existing setting limitation:** eslint.onIgnoredFiles only controls ignored-file warnings through warnIgnored; it cannot suppress a configuration-resolution exception that occurs before ESLint determines the file is ignored.
- **canonical search:** No open vscode-eslint issue found by searches for node_modules and ignored-file configuration errors owns this same remaining work; https://github.com/microsoft/vscode-eslint/issues/1814 concerns the distinct mechanism of limiting files changed by code actions on save.
