# Issue #2030 — Loading flat config from the node_modules fails

[https://github.com/microsoft/vscode-eslint/issues/2030](https://github.com/microsoft/vscode-eslint/issues/2030)

## Summary

The configuration passes ESLint's `-c` option through `eslint.execArgv`, but that setting configures the Node runtime rather than ESLint. The existing `eslint.options.overrideConfigFile` setting provides the requested custom flat-config path, so this is a configuration question rather than an extension defect.

## Change summary

Use a flat ESLint configuration exported by a dependency in `node_modules` without creating a root-level symlink.

## Best solution

Keep the existing settings behavior and configure `eslint.options.overrideConfigFile` with the absolute path to the dependency's `eslint.config.js`; reserve `eslint.execArgv` for Node runtime flags.

  > Thanks for the detailed context. `eslint.execArgv` passes arguments to the Node runtime that hosts the ESLint server, so `-c` there is not forwarded to ESLint. Please pass the config through the ESLint class options instead:
  > 
  > ```json
  > {
  >   "eslint.useFlatConfig": true,
  >   "eslint.options": {
  >     "overrideConfigFile": "/Users/daniel/dev/helia/node_modules/aegir/eslint.config.js"
  >   }
  > }
  > ```
  > 
  > An absolute path is appropriate here. This is separate from https://github.com/microsoft/vscode-eslint/issues/1985, which concerns working-directory selection rather than explicitly choosing a config file.
