# Issue #2030 — Loading flat config from the node_modules fails

[https://github.com/microsoft/vscode-eslint/issues/2030](https://github.com/microsoft/vscode-eslint/issues/2030)

## Summary

The config path is being supplied through `eslint.execArgv`, which passes arguments to the Node runtime rather than to ESLint. The supported configuration is `eslint.options.overrideConfigFile`, so this is a configuration question rather than an extension defect.

## Change summary

Configure the extension to load a flat ESLint configuration exported by a dependency under `node_modules`.

## Best solution

Keep the existing settings behavior and configure `eslint.options` with an absolute `overrideConfigFile` path. The extension already forwards that option unchanged to ESLint's class API.

  > Thanks for the detailed context. `eslint.execArgv` is for arguments passed to the Node runtime that hosts the ESLint server, not ESLint CLI arguments such as `-c`. To select this config through the ESLint class API, use:
  > 
  > ```json
  > {
  >   "eslint.useFlatConfig": true,
  >   "eslint.options": {
  >     "overrideConfigFile": "/Users/daniel/dev/helia/node_modules/aegir/eslint.config.js"
  >   }
  > }
  > ```
  > 
  > With an absolute path, this does not depend on `eslint.workingDirectories`. This is also distinct from https://github.com/microsoft/vscode-eslint/issues/1985, which concerns assigning files to a working directory that is not a prefix of their path.

## Evidence

- **runtime argument semantics:** `package.json` documents `eslint.execArgv` as additional arguments passed to the Node runtime, with heap-size configuration as its example; `client/src/client.ts` passes it as `ServerOptions.options.execArgv` when launching the language server.
- **existing configuration setting:** `README.md` documents `eslint.options: { "overrideConfigFile": "..." }` as the supported way to point the ESLint class API at a custom configuration file.
- **option forwarding:** `client/src/client.ts` reads `eslint.options` into the per-resource settings, and `server/src/eslint.ts` copies those options into `newOptions` before constructing the workspace's ESLint class.
- **terminal confirmation:** The issue reports that `npx eslint -c /Users/daniel/dev/helia/node_modules/aegir/eslint.config.js packages/ipns/src/` works, supporting that the config itself is valid and the problem is which extension setting receives the path.
