# Issue #795 — Support specifying the shell to use for Lint task to avoid problems with bash under Windows.

[https://github.com/microsoft/vscode-eslint/issues/795](https://github.com/microsoft/vscode-eslint/issues/795)

## Summary

The contributed ESLint task can already be customized through `tasks.json` with `options.shell`, and the thread confirms that selecting `cmd.exe` there resolves the Windows/Git Bash conflict. This is now a task-configuration question rather than missing extension functionality.

## Change summary

Allow the workspace lint task to use a Windows-compatible shell when the integrated terminal defaults to Git Bash, Cygwin, or WSL.

## Best solution

Keep the task provider using VS Code's standard `ShellExecution` and configure the generated ESLint task's shell through `tasks.json`; this uses the platform's task customization surface without adding a redundant `eslint.lintTask.shell` setting.

  > Thanks for the report and the follow-up investigation. VS Code's task customization now provides the needed configuration directly: add an `eslint` task entry to `.vscode/tasks.json` and set `options.shell`, as shown in https://github.com/microsoft/vscode-eslint/issues/795#issuecomment-1152778571. For Git Bash on Windows, selecting `cmd.exe` with `args: ["/d", "/c"]` lets the contributed lint task execute the discovered `.cmd` binary without using the integrated terminal's default shell. Since the shell can be selected through the standard task configuration, no additional ESLint setting is needed.
