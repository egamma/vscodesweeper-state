# Issue #795 — Support specifying the shell to use for Lint task to avoid problems with bash under Windows.

[https://github.com/microsoft/vscode-eslint/issues/795](https://github.com/microsoft/vscode-eslint/issues/795)

## Summary

The generated lint task still uses VS Code's default shell without specifying a shell executable, so the reported Git Bash/MSYS incompatibility remains. The maintainer identified the underlying shell/path handling as a VS Code task-system concern, so this should remain open and be classified with `depends-on-vscode`.

## Change summary

Allow the generated ESLint whole-folder task to select a Windows-compatible shell instead of passing a Windows command path to the user's POSIX-style default shell.

## Best solution

VS Code's task system should reliably reconcile command paths with the selected shell; meanwhile, the extension should retain the documented `tasks.json` `options.shell` customization path. If an extension-specific convenience is desired, it would require a setting in `package.json` wired through `client/src/tasks.ts` to `ShellExecutionOptions`, rather than changing ESLint execution semantics.

## Evidence

- **current implementation:** `client/src/tasks.ts` still constructs the generated task with `new vscode.ShellExecution(...)`; its `ShellExecutionOptions` supplies only `cwd`, so it does not select or override the shell executable.
- **settings surface:** `package.json` exposes `eslint.lintTask.enable`, `eslint.lintTask.command`, and `eslint.lintTask.options`, but no setting for the generated task's shell. The command setting can provide a shell-compatible command in a particular environment, but it does not solve shell selection across environments.
- **maintainer routing:** The maintainer states in https://github.com/microsoft/vscode-eslint/issues/795#issuecomment-551915693 that the underlying problem is in VS Code and that the extension can provide only a workaround.
- **available workaround:** https://github.com/microsoft/vscode-eslint/issues/795#issuecomment-1152782773 demonstrates that users can customize the contributed ESLint task in `.vscode/tasks.json` with `options.shell.executable` and `options.shell.args`.
- **no valid duplicate target:** The referenced VS Code issue https://github.com/microsoft/vscode/issues/38381 is closed and concerns a path-separator variable rather than fully owning shell selection for contributed tasks, so it cannot serve as a canonical duplicate.
