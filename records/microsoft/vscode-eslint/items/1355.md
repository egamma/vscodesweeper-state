# Issue #1355 — ESLint can't be used as a formatter until the ESLint server is fully initialized.

[https://github.com/microsoft/vscode-eslint/issues/1355](https://github.com/microsoft/vscode-eslint/issues/1355)

## Summary

The initialization race remains on current main: ESLint registers as a formatter only after asynchronous per-document configuration, library resolution, probing, and ignored-path checks complete. The issue should remain open because no existing setting removes that temporary unavailability and no canonical issue owns the same work.

## Change summary

Make ESLint available to Format Document immediately instead of briefly reporting that no formatter exists while the extension initializes the document.

## Best solution

Change the client/server formatter lifecycle so an enabled ESLint formatter can accept the initial request while document capability probing completes, without advertising ESLint for files that ultimately cannot be linted. This likely requires coordinated initialization behavior rather than a configuration workaround.

## Evidence

- **maintainer confirmation:** In https://github.com/microsoft/vscode-eslint/issues/1355, the maintainer confirmed that formatting fails because the ESLint server has not fully activated, described the dynamic capability decision as a chicken-and-egg problem, and explicitly retained the issue for improvement.
- **current source path:** server/src/eslint.ts resolveSettings() still waits for workspace configuration, ESLint module resolution, validation probing, and ESLintClass.isPathIgnored() before dynamically registering DocumentFormattingRequest for the document.
- **request cannot bridge registration delay:** server/src/eslintServer.ts handles onDocumentFormatting by calling computeAllFixes(), but VS Code cannot send that request until the dynamic formatting provider has been registered; the initial Format Document action can therefore observe no provider.
- **existing capability check:** eslint.format.enable enables formatter registration but does not register it eagerly or provide a way to wait for initialization. Code actions on save and pressing Save are workarounds mentioned in the thread, not coverage of the requested Format Document behavior.
- **canonical search:** The closest open issues, https://github.com/microsoft/vscode-eslint/issues/1735 and https://github.com/microsoft/vscode-eslint/issues/1739, concern formatter logging and probing feedback rather than making the formatter available during initialization; neither would fully satisfy this report.
