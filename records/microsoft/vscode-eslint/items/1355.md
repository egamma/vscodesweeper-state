# Issue #1355 — ESLint can't be used as a formatter until the ESLint server is fully initialized.

[https://github.com/microsoft/vscode-eslint/issues/1355](https://github.com/microsoft/vscode-eslint/issues/1355)

## Summary

Current main still registers ESLint as a formatter only after asynchronously resolving the document's configuration, ESLint library, validation eligibility, and ignored-file status, leaving a startup window where VS Code cannot select it. The maintainer explicitly retained this Backlog issue to improve that behavior, and no open canonical issue or implementation PR was found.

## Change summary

Make ESLint formatting available, or defer the formatting request safely, while the language server is still resolving whether the opened document can be formatted.

## Best solution

Keep the issue as the canonical extension-side startup race and improve the server/client formatter-registration lifecycle so an immediate Format Document request does not fail while eligibility is being resolved. The implementation must preserve per-document configuration and ignored-file checks rather than advertising formatting indiscriminately.
