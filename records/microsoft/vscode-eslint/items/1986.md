## Summary

Keep open: multiple reporters demonstrated that a PNPM-installed workspace lints successfully from the CLI but fails to resolve plugins in the extension. The thread already supplies a minimal repository and explains why an npm-initialized Codespace can mask the failure; neither a current fix nor an eligible canonical was established.

## Change summary

Resolve ESLint plugins consistently with the PNPM CLI when peer dependencies are installed without public hoisting.

Use the supplied reproduction to isolate the PNPM CLI-versus-server resolution environment, then address the extension-side invocation discrepancy without changing ESLint's plugin semantics or requiring redundant dependencies. Public hoisting is a confirmed workaround, not completion of the requested CLI parity.
