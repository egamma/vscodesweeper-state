# Issue #1986 — Issues with PNPM module resolution

[https://github.com/microsoft/vscode-eslint/issues/1986](https://github.com/microsoft/vscode-eslint/issues/1986)

## Summary

The issue remains necessary: multiple pnpm 10 installations reproduce plugin-resolution failures while the same workspace succeeds through `pnpm eslint`, and the earlier close was reversed after the Codespace comparison was found to have used npm. The available reproduction and logs are sufficient to keep investigating rather than requesting the same information again.

## Change summary

Make ESLint library execution inside the extension resolve pnpm-installed peer dependencies consistently with ESLint launched through pnpm.

## Best solution

Determine which module-resolution environment pnpm supplies to `pnpm eslint` and reproduce the relevant behavior when the server loads the workspace ESLint library, without requiring projects to hoist every ESLint peer dependency. This likely belongs in the server-side library-loading path, but the solution must account for pnpm versions and avoid changing npm or yarn resolution.

## Evidence

- **reproduction repository:** https://github.com/angryermine/vscode-eslint-pnpm is an available minimal repository pinned to pnpm 10.21.0 with ESLint 8.57.1 and eslint-config-airbnb 19.0.4; its lockfile installs the config's peer plugins while its root manifest does not list them directly.
- **independent confirmations:** Several commenters reproduced missing eslint-plugin-react-hooks or eslint-plugin-jsx-a11y resolution after a pnpm 10 install on Windows, WSL, and macOS, while command-line ESLint continued to work.
- **Codespace discrepancy explained:** The initial failed maintainer reproduction used dependencies installed automatically with npm; a commenter then removed node_modules, reinstalled with pnpm, and demonstrated the failure. The issue was reopened on 2025-12-10 after its earlier needs-info close.
- **current loading path:** server/src/eslintServer.ts loads the resolved workspace ESLint module through a plain Node require, while server/src/eslint.ts resolves the ESLint library path through vscode-languageserver Files.resolve. Neither path launches ESLint through pnpm or imports pnpm's command environment.
- **nodePath limitation:** package.json documents eslint.nodePath only as a path used when resolving the ESLint module, and server/src/eslint.ts uses it as input to Files.resolve before loading that module; it does not set process.env.NODE_PATH for subsequent plugin resolution.
- **no canonical duplicate:** Repository searches for pnpm module resolution, pnpm plugins, peer dependencies, NODE_PATH, and command-line divergence found no other open vscode-eslint issue owning this work; issue https://github.com/microsoft/vscode-eslint/issues/1355 concerns formatter availability during server initialization and is unrelated.
