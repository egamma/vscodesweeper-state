# Issue #2057 — Measure rule performance through VSCode ESLint

[https://github.com/microsoft/vscode-eslint/issues/2057](https://github.com/microsoft/vscode-eslint/issues/2057)

## Summary

This is a valid, still-unimplemented feature request: `eslint.options` can already enable ESLint's stats collection, but the server neither models nor exposes the resulting per-rule timing data. The Backlog milestone and existing `feature-request` and `help wanted` labels support leaving it open.

## Change summary

Expose or log the per-file and per-rule performance statistics returned by ESLint when stats collection is enabled.

## Best solution

Extend the server-side ESLint result model in `server/src/eslint.ts` to consume `LintResult.stats` and present it through the existing ESLint output channel, initially gated by `eslint.options.stats`. A custom executable wrapper should not be necessary because the extension already invokes ESLint through its Node.js API.
