[https://github.com/microsoft/vscode-eslint/issues/2057](https://github.com/microsoft/vscode-eslint/issues/2057)

## Summary

Keep open: current main accepts ESLint options but does not surface per-rule performance statistics. The explicitly linked implementation PR is still open, so this issue should remain open pending its review and merge.

## Change summary

Expose ESLint's per-rule execution timing data inside VS Code so users can identify slow rules without a separate CLI run.

## Best solution

Review https://github.com/microsoft/vscode-eslint/pull/2248 as the implementation candidate for collecting stats in server/, transporting them through $shared/, and displaying them in client/. Preserve opt-in collection through eslint.options and compatibility with ESLint versions that do not provide stats.
