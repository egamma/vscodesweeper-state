# Issue #1997 — respect estlint-suppressions.json

[https://github.com/microsoft/vscode-eslint/issues/1997](https://github.com/microsoft/vscode-eslint/issues/1997)

## Summary

Bulk-suppression support is implemented and shipped: the extension can apply `eslint-suppressions.json`, optionally display suppressed violations at a configurable severity, and use a custom suppression-file location.

## Change summary

Add VS Code ESLint support for ESLint's bulk-suppression file and control how suppressed violations appear in the editor.

## Best solution

Close as completed and direct users to `eslint.bulkSuppression.*` on ESLint 10.1 or newer; users who want suppressed violations completely hidden can pass `applySuppressions: true` through `eslint.options`, while the dedicated settings support configurable visibility.

  > Thanks for the report and discussion. Bulk-suppression support has now shipped in stable version 3.0.34. With ESLint 10.1 or newer, use `eslint.bulkSuppression.enable` to apply the suppression file and surface suppressed violations at the severity selected by `eslint.bulkSuppression.severity`; `eslint.bulkSuppression.location` supports a non-default file path. If suppressed violations should be hidden entirely, `eslint.options` can pass `applySuppressions: true` without enabling their diagnostic display. The implementation landed in https://github.com/microsoft/vscode-eslint/commit/9d33f02b2ddaadc55f7f30dfd2338ccca12dc798. The fix shipped in release/3.0.34.
