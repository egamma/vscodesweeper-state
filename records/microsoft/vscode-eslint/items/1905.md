# Issue #1905 — ESLint server only looks at first entry in `context.only` array sent along with `textDocument/codeAction`

[https://github.com/microsoft/vscode-eslint/issues/1905](https://github.com/microsoft/vscode-eslint/issues/1905)

## Summary

The client-side routing bug was fixed in Zed, but the agreed server-hardening request remains unimplemented on current main: the ESLint server still examines only the first requested code-action kind. The existing feature-request label and Backlog milestone accurately represent this localized robustness improvement.

## Change summary

Handle every code-action kind in `CodeActionContext.only` so a supported ESLint action is recognized in any array position and unrelated requests never produce ESLint quick fixes.

## Best solution

Update `connection.onCodeAction` in `server/src/eslintServer.ts` to inspect the complete `context.only` array, return the requested ESLint fix-all action when its supported kind appears anywhere, and return no actions when a non-empty filter contains only unsupported kinds. Add coverage for mixed supported/unsupported kinds and unsupported-only requests in `server/src/tests/eslint.test.ts`.
