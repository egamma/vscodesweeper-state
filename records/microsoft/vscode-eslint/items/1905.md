# Issue #1905 — ESLint server only looks at first entry in `context.only` array sent along with `textDocument/codeAction`

[https://github.com/microsoft/vscode-eslint/issues/1905](https://github.com/microsoft/vscode-eslint/issues/1905)

## Summary

The triggering behavior was a Zed client bug, which Zed fixed, but the maintainer agreed that the ESLint server could handle unsupported or mixed code-action requests more robustly. Current main still inspects only the first `context.only` entry and can misclassify returned quick fixes, so the backlog enhancement remains valid.

## Change summary

Make the language server evaluate the complete `context.only` array and avoid returning ESLint quick fixes under an unrelated requested code-action kind.

## Best solution

Update the code-action filtering in `server/src/eslintServer.ts` to match supported actions against every requested kind and return no action for unsupported-only requests, without weakening the advertised capability boundary. Add a server regression test covering mixed and unsupported `context.only` arrays.
