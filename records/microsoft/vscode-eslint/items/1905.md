# Issue #1905 — ESLint server only looks at first entry in `context.only` array sent along with `textDocument/codeAction`

[https://github.com/microsoft/vscode-eslint/issues/1905](https://github.com/microsoft/vscode-eslint/issues/1905)

## Summary

The Zed-side capability-filtering bug has been fixed, but the agreed server-hardening request remains valid and is still present on current main. The existing feature-request label and Backlog milestone accurately capture this as accepted, unscheduled robustness work.

## Change summary

Handle every requested code-action kind in `CodeActionContext.only` and avoid returning unrelated ESLint actions when none of the requested kinds is supported.

## Best solution

Update `server/src/eslintServer.ts` to match all entries in `params.context.only` against the server's supported quick-fix and ESLint fix-all kinds, returning no actions when there is no match, and add protocol-level coverage for mixed supported and unsupported arrays.
