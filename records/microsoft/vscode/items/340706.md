# Issue #340706 — Tooltips for Search option controls are not accessible using the keyboard:A11y_VisualStudioCode_Search_Use of color

[https://github.com/microsoft/vscode/issues/340706](https://github.com/microsoft/vscode/issues/340706)

## Summary

Thanks for the report. Toggle tooltips (Match Case, Whole Word, etc.) appear to be mouse-hover only, so sighted keyboard users get no visible label on focus. This is a plausible accessibility gap that needs a maintainer decision on the fix, so it stays open.

## Change summary

Tooltips on the Search view option toggles are shown only on mouse hover, not when the control receives keyboard focus.

## Best solution

Show the toggle's hover on keyboard focus, or expose it through a keyboard shortcut, in the shared Toggle widget, so every consumer benefits.

## Plan brief

- **Validation:** Manually tab to a Search toggle and confirm its label is visible without mouse hover; ideally add a toggle unit test.
- **Behavior:**

  > When a Search option toggle receives keyboard focus, its name and shortcut should be perceivable by sighted keyboard users, for example as a hover shown on focus. Mouse hover behavior and screen reader labels stay unchanged.
- **Trace:**

  > Toggle in src/vs/base/browser/ui/toggle/toggle.ts uses getBaseLayerHoverDelegate().setupDelayedHover, which is pointer-driven. Uncertainty starts at whether other widgets already show hover on focus and how a focus hover should be dismissed. Do not change the aria-label behavior.
- **Open decisions:**
  - Should the toggle hover appear automatically on keyboard focus, or only via an explicit shortcut?
  - Should this apply to the shared Toggle widget everywhere, or only to the Search view?
