# Issue #331814 — Large pet cannot be grabbed without instant death

[https://github.com/microsoft/vscode/issues/331814](https://github.com/microsoft/vscode/issues/331814)

## Summary

Traced a real geometry bug in the chat pet's grow/drag mechanic: once the pet is scaled large enough, dropping it can never satisfy the platform-landing check, so it always falls and 'dies' — the grow feature effectively becomes unusable past a certain size. Kept open for a maintainer to pick the right fix (cap max scale vs. rework the landing check), since the author is a team member and no fix has landed yet.

## Change summary

Growing the chat pet (the 'chat.pet.grow' action, no upper scale cap in `getChatPetScale`) to a large size and then picking it up/dropping it (via `_startDrag`/`_beginFall`) always results in the pet falling off and dying, instead of landing back on the chat input.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts, either cap `getChatPetScale`'s growth so `_getDisplaySize()` never exceeds the vertical space between the window top and the platform, or change `getChatPetFallTarget`'s landing test (currently requires the full bounding box, `petTop + petHeight <= platformTop`, to sit above the platform) so it doesn't become geometrically unsatisfiable for oversized pets — e.g. testing overlap/center position rather than requiring the whole scaled box to fit above the input row.

## Evidence

- **no scale cap:** src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts:765-766 `getChatPetScale` only clamps to `CHAT_PET_MIN_SCALE` (0.4); there is no maximum, so the 'Grow' action (line ~1858, `chat.pet.grow`) can scale the pet indefinitely.
- **landing check:** getChatPetFallTarget (chatPetWidget.ts:870-877) requires `petTop + petHeight <= platformTop` to count as landing on the platform; petHeight comes from `_getDisplaySize()` = `CHAT_PET_SOURCE_SIZE / 2 * scale` (line ~1959), so it grows with scale.
- **drag clamp forces failure:** `_setDragPosition` (chatPetWidget.ts:1557-1574) clamps `top` to `minimumTop = movementBounds.top - overlayBounds.top`, i.e. the pet can't be dragged above the visible window. Once `petHeight` (scaled) exceeds the vertical space between the window top and the platform, `top + petHeight` can never be `<= platformTop` while `top` stays within the clamp — so `_beginFall` (line 1768) always resolves `landsOnPlatform: false` and `_completeFall` (line 1822-1830) sets `_isDead` on every drop, matching the reported 'instant death' when the pet is grown large and grabbed.
- **test coverage baseline:** src/vs/workbench/contrib/chat/test/browser/widget/chatPetWidget.test.ts:1655-1672 exercises getChatPetFallTarget only at fixed 48x48 size; there's no test covering large `petHeight` values, so this scale interaction wasn't caught.
