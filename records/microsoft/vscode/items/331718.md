# Issue #331718 — Support auto model selection in .agent.md based on task complexity

[https://github.com/microsoft/vscode/issues/331718](https://github.com/microsoft/vscode/issues/331718)

## Summary

Keep open for the existing community-review process: Copilot Auto routing now covers part of the motivation, but custom-agent capability and cost policies over BYOK models remain unsupported. The older routing proposals examined do not own this full request, and two upvotes do not justify prematurely ending its 60-day review.

## Change summary

Allow custom agents to select models dynamically using task complexity, context size, tool and modality requirements, and cost preferences instead of static model ordering.

## Best solution

Design a custom-agent routing contract that builds on existing Auto behavior while explicitly addressing BYOK eligibility, capability requirements, cost metadata, and fallback safety. Decide whether routing is invocation-only or can change during an agent run before committing to a public frontmatter schema.

- **Validation:** End the plan with deterministic routing fixtures covering simple versus complex tasks, tool-calling and image requirements, context limits, unavailable models, and no qualifying model. Verify the approved fallback behavior and that agents without a policy retain existing explicit-model, ordered-list, and BYOK inheritance behavior; if per-round routing is selected, include the offered search → implement → verify → fail → recover trajectory.
- **Behavior:**

  > Custom agents currently choose an explicit model or the first available entry in a static preference list, which cannot adapt a BYOK model choice to the invocation's needs. The requested outcome is a declarative policy that chooses an eligible model according to capabilities and an agreed cost/quality objective. Acceptance should cover tools, images, context limits, model availability, and the approved no-match behavior while preserving existing behavior for agents without a policy. The discussion additionally proposes adapting model choice during the run, which is not yet an agreed requirement.
- **Trace:**

  > customAgentAttributes in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts documents static ordered model preferences and has no policy attribute. RunSubagentTool.resolveSubagentModel in src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts gives explicit call-time selection precedence, then resolves agent preferences, with conditional Copilot Auto defaults and a fixed-model multiplier constraint. Existing Auto profiles live in extensions/copilot/src/platform/endpoint/common/autoModeTiers.ts, and AutoV2Fetcher in extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts delegates selection to the Copilot service rather than selecting across BYOK providers. The trace establishes these boundaries, not a complete cross-provider design or a reliable common cost-ranking contract. Preserve current explicit selections and non-policy fallback behavior; coordinate with https://github.com/microsoft/vscode/issues/306717 and https://github.com/microsoft/vscode/issues/325844 without treating either as a canonical duplicate.
- **Open decisions:**
  - Is the policy evaluated only at invocation, or may the runtime switch models between rounds of the same agent run?
  - When no model satisfies mandatory capability constraints, should the invocation fail explicitly or permit fallback to an otherwise incompatible model from the existing model list?
  - How should cost-optimal selection behave when providers lack comparable pricing metadata: require user-supplied ordering, exclude those models, or use a documented non-cost fallback?
