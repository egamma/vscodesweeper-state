# Issue #170702 — In read only editor, screen reader cursor movement doesn't trigger line to be read

[https://github.com/microsoft/vscode/issues/170702](https://github.com/microsoft/vscode/issues/170702)

## Summary

Team-authored accessibility bug with no commit referencing #170702 found on main. The cursor-change handler (`onCursorStateChanged`) does call `writeNativeTextAreaContent('selection changed')` which should update screen reader content regardless of readonly state, but without executing the scenario the fix status is uncertain — keeping open.

## Change summary

In read-only editors (e.g. output panel), moving the cursor with a screen reader does not cause subsequent lines to be read aloud after the initial focus line.

## Best solution

Investigate whether the current `onCursorStateChanged` → `writeNativeTextAreaContent` path actually produces the correct ARIA announcements in read-only editors. The issue may be that cursor movement keys are swallowed or that the textarea content update doesn't trigger a screen reader announcement in readonly mode. The fix likely lives in `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts` or the screen reader content strategy.
