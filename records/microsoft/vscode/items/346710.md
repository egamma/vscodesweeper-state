## Summary

## Change summary

Integrated-browser proxy traffic during Codespaces window reload can attempt unauthenticated tunnel connections and coincide with remote reconnection failure.

## Best solution

Ensure browser tunnel startup honors remote authentication readiness without disrupting the window's management or extension-host connection. Diagnose the reload failure separately from connection-volume and restored-tab behavior, which current main already partially addresses.

- **Behavior:**

  > Reloading a Codespaces window with a proxied integrated-browser page open must not prevent the workspace from reconnecting. For a server requiring authentication, browser tunnel connections must not proceed with placeholder credentials while connection data is becoming ready. Validate management and extension-host reconnection alongside browser traffic, and compare proxy-enabled and disabled runs. Connection reuse and restored-session behavior are secondary observations, not substitutes for reproducing the cancellation.
- **Trace:**

  > RemoteAuthorityResolverService.getConnectionData reads the token override map even when a resolved authority already carries a token; AbstractRemoteAgentService publishes the environment token after its environment request completes. NodeExtHostBrowserTunnelProxy._setConnection accepts this descriptor, and MutableAddressProvider considers the endpoint sufficient to release waiting connections. connectRemoteAgentTunnel eventually sends the zero-token fallback when that descriptor has no token. The unresolved boundary is whether these rejected browser tunnels cause the window connection failure or merely coincide with it. Preserve legitimate tokenless remote configurations, existing authentication enforcement, and non-browser connection semantics. Current TunnelProxy already has HTTP keep-alive pooling, and BrowserViewWorkbenchService applies proxy configuration during session resolution. https://github.com/microsoft/vscode/issues/331909 and https://github.com/microsoft/vscode/pull/331912 provide related readiness work, not established duplicates or a fix for this issue.
