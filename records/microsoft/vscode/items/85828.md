# Issue #85828 — [css] Support for SVG 2 CSS Properties

[https://github.com/microsoft/vscode/issues/85828](https://github.com/microsoft/vscode/issues/85828)

## Summary

Keep open: this accepted Backlog feature request has 23 community upvotes and documents a real remaining gap in validation of SVG properties used from CSS. The available per-language `lint.validProperties` settings suppress warnings as a workaround but do not provide built-in SVG 2 property knowledge.

## Change summary

Recognize SVG properties such as `x`, `y`, `cx`, `cy`, `r`, `d`, and baseline/vector-effect properties when they are used in CSS, SCSS, or Less.

## Best solution

Update the CSS language service's property data and validation coverage from authoritative SVG/CSS specifications, then consume the resulting language-service release in VS Code. Preserve `css.lint.validProperties`, `scss.lint.validProperties`, and `less.lint.validProperties` as escape hatches for properties absent from the built-in data.

User-configured `lint.validProperties` entries and the existing unknown-property severity settings must continue to work.
- **Trace:**

  > VS Code's built-in CSS language feature consumes the CSS language service, while the issue's observable failure is its property validator rejecting SVG properties used through CSS. The existing `css.lint.validProperties`, `scss.lint.validProperties`, and `less.lint.validProperties` settings are confirmed workarounds, not built-in support. Related https://github.com/microsoft/vscode/issues/147804 overlaps but is closed, and the previously cited fix for this issue was refuted; do not reuse it. The investigation should establish the authoritative SVG property set in the language-service data, add validation coverage there, and identify the VS Code dependency adoption point without weakening unknown-property linting globally.
- **Open decisions:**
  - Should built-in recognition cover every SVG presentation/geometry attribute that specifications permit as a CSS property, or only the interoperable subset supported across target browsers?
  - Should browser-specific support differences affect whether a property is recognized, or should recognition follow the SVG/CSS specification while compatibility guidance remains separate?
