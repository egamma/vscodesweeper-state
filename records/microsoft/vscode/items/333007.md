# Issue #333007 — Discover chats created by other Codex clients without reconnecting the remote tunnel

[https://github.com/microsoft/vscode/issues/333007](https://github.com/microsoft/vscode/issues/333007)

## Summary

Thanks for the detailed report — tracing the Codex agent-host discovery path on main confirms the gap: chat discovery only runs once per process activation and is never re-armed by a poll, focus event, or the refresh action, so a peer connected over a tunnel genuinely won't see a sibling client's new thread until it reconnects.

## Change summary

Agent Window (Codex provider) does not discover chats created by other Codex clients sharing the same remote session storage until the tunnel is disconnected and reconnected.

## Best solution

Add a re-trigger path for Codex's `onDidDiscoverChats`/`_emitCodexChats` (e.g. on chat-list focus or the explicit refresh action) in src/vs/platform/agentHost/node/codex/codexAgent.ts, mirroring the 'explicit trigger' pattern Copilot already has via its migrate-legacy toggle — per the agentHost AGENTS.md, discovery today is a one-shot memoized attempt with no periodic or focus-driven re-arm.
