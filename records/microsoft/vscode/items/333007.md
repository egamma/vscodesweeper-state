# Issue #333007 — Discover chats created by other Codex clients without reconnecting the remote tunnel

[https://github.com/microsoft/vscode/issues/333007](https://github.com/microsoft/vscode/issues/333007)

## Summary

Well-diagnosed and confirmed against the code: Agent Host's chat discovery runs one memoized initial pass per provider and is not re-armed by ordinary list refreshes, so a Codex thread created by another client isn't picked up until the tunnel reconnects (which forces re-initialization). This is a real architectural gap worth routing to the agent-host owners.

## Change summary

Agent Window (via Agent Host's Codex provider) should discover threads created by other Codex clients sharing the same session storage without requiring a full tunnel reconnect.

## Best solution

Extend `_emitCodexChats`/`onDidDiscoverChats` in src/vs/platform/agentHost/node/codex/codexAgent.ts so `thread/list` is re-polled or re-triggered on a reasonable interval or focus/refresh event, rather than only once per connection lifetime as documented in src/vs/platform/agentHost/AGENTS.md §3a ("the only later trigger is an explicit one").
