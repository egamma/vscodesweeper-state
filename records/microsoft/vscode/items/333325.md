# Issue #333325 — Export changes of a session in the Chat panel

[https://github.com/microsoft/vscode/issues/333325](https://github.com/microsoft/vscode/issues/333325)

## Summary

This is a valid, currently unimplemented chat-editing feature request. Route it to the chat agent-editing area for a product decision on export scope and format.

## Change summary

Add a Chat panel action that exports the file changes made during an editing session as a portable text file.

## Best solution

Provide a session-specific export action alongside the existing Keep, Undo, and View All Edits controls, using the editing session's baseline and current snapshots rather than the repository-wide SCM state. The resulting format and whether accepted edits remain included need to be decided before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chatRepoInfo.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingActions.test.ts`

- **Behavior:**

  > A user can export changes attributable to the active chat editing session from the Chat panel. The exported text identifies each changed file and records its before/after hunks, including file creation and deletion according to the chosen format. Changes unrelated to that chat session are excluded. Existing Keep, Undo, View All Edits, and Export Chat behavior remains unchanged.
- **Trace:**

  > The relevant toolbar actions are registered in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts. The active IChatEditingSession already exposes session-scoped differences through `getDiffsForFilesInSession()` in src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts; IEditSessionEntryDiff carries original, modified, optional frozen modified snapshot, and creation/deletion metadata. The existing public export in src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts exports conversation JSON only. src/vs/workbench/contrib/chat/browser/chatRepoInfo.ts demonstrates unified-diff formatting, but its current flow reads repository-wide SCM state for an internal zip export and must not be used as a proxy for session ownership. Keep transcript export and repository diagnostic export semantics outside this change.
- **Open decisions:**
  - Should export include only currently unresolved edits, or the full session history including edits already kept and shown through View Previous Edits?
  - Should the output be an apply-compatible unified patch or a human-readable text report, especially for created, deleted, renamed, binary, and notebook files?
