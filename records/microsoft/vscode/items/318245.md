# Issue #318245 — Add “Save to Workspace” action for Copilot-generated plan files

[https://github.com/microsoft/vscode/issues/318245](https://github.com/microsoft/vscode/issues/318245)

## Summary

Keep open: current source has generic Save As and an experimental Save Artifact action, but neither establishes a discoverable, default export action for the internally stored plans described here. The older related requests cover different observable behavior and do not meet the re-review duplicate bar.

## Change summary

Provide a discoverable action that copies a Copilot-generated plan from internal session storage into a user-selected workspace file.

## Best solution

Make the existing plan content directly exportable to a workspace location without regenerating it through an agent or requiring users to locate internal storage. Reconcile this with the existing artifact-saving surface rather than introducing a separate export mechanism unnecessarily.

Verify the destination content matches the viewed plan, the internal source remains intact, cancellation writes nothing, and no additional agent turn is required; cover ordinary-file and memory-backed artifacts in targeted export tests.
- **Behavior:**

  > A user can preserve an already generated Copilot plan in the project without locating VS Code's internal storage or asking an agent to recreate the document. The action presents a destination choice and copies the currently viewed plan content while retaining the session's original plan. Acceptance includes exact content preservation, cancellation without a destination file, and no extra model request. The action must be discoverable in the agreed default plan surface.
- **Trace:**

  > PlanAgentProvider in extensions/copilot/src/extension/agents/vscode-node/planAgentProvider.ts persists plans through the memory tool, while its Open in Editor handoff requests a newly created untitled file through an agent. ChatArtifactPillSource and ChatArtifactsWidget already expose Save Artifact and share saveChatArtifact, but non-image artifact pills are behind the experimental, default-off chat.artifacts.enabled setting. ChatMemoryFileResource in common/chatArtifactExtraction.ts encodes memory references with the chat-memory-file scheme; opening resolves these through github.copilot.chat.tools.memory.resolveMemoryFileUri, whereas the inspected export helper reads its source URI directly. Planning should first establish whether this export path handles the reported memory-backed plan and which viewer opens it under default settings. Preserve internal plan storage and existing implementation handoffs; automatic relocation of all plans is outside this request. https://github.com/microsoft/vscode/issues/272930 concerns automatic storage, and https://github.com/microsoft/vscode/pull/339189 explicitly leaves plan-mode rules unchanged.
- **Open decisions:**

## Evidence

- **Current planning behavior:** extensions/copilot/src/extension/agents/vscode-node/planAgentProvider.ts instructs the Plan agent to persist /memories/session/plan.md through the memory tool. Its Open in Editor handoff instead invokes an agent with a createFile prompt targeting an untitled plan-${camelCaseName}.prompt.md file; this is not a direct export of the stored file.
- **Existing export capability and limits:** src/vs/workbench/contrib/chat/browser/chatArtifactPillSource.ts exposes chatArtifacts.save, labeled Save Artifact. saveChatArtifact opens a destination dialog and reads/writes the artifact content. However, non-image artifacts are gated by chat.artifacts.enabled, registered as experimental and default false in browser/chat.shared.contribution.ts. The helper reads the original artifact URI directly, while opening memory artifacts separately resolves their chat-memory-file URI; this inspection does not establish reliable coverage of the reporter's memory-backed plan path.
- **Generic workaround:** src/vs/workbench/contrib/files/browser/fileCommands.ts registers workbench.action.files.saveAs with saveAs: true. This offers a workaround for a plan opened as a normal text editor, but does not establish a plan-specific action in the clickable chat item or plan viewer requested by https://github.com/microsoft/vscode/issues/318245.
- **Older related requests are not verified duplicates:** Verified open: https://github.com/microsoft/vscode/issues/272930 requests automatic persistence and a configurable plan directory; https://github.com/microsoft/vscode/issues/287667 reports an Open in Editor destination/permissions problem; https://github.com/microsoft/vscode/issues/275981 requests clearer handoff naming and a different file extension.
