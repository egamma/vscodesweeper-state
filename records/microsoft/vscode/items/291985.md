# Issue #291985 — Bug: Enabled terminal.integrated.altClickMovesCursor alters entire Windows 11 system behavior for Ctrl-C hotkey

[https://github.com/microsoft/vscode/issues/291985](https://github.com/microsoft/vscode/issues/291985)

## Summary

The `altClickMovesCursor` setting is purely an xterm.js terminal-widget option scoped to VS Code's integrated terminal DOM — it registers no global hotkeys and has no mechanism to affect other Windows applications. The reported system-wide Ctrl-C interference is almost certainly a misattribution (likely a conflicting extension or background process).

## Change summary

Reporter claims the `terminal.integrated.altClickMovesCursor` setting causes system-wide Ctrl-C misbehavior in other Windows apps when VS Code runs in the background.

## Best solution

Close as not reproducible — the setting passes a boolean to the xterm.js widget's options object and has zero interaction with Win32 hotkey APIs or clipboard. If the reporter still experiences the issue, investigating installed extensions (29 listed, including several AI agents) or other background processes would be the correct path.
