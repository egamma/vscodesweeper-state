# Issue #282902 — Remove "up/down arrow to navigate message history" feature from chat textarea

[https://github.com/microsoft/vscode/issues/282902](https://github.com/microsoft/vscode/issues/282902)

## Summary

Keep this open under discussion: bare Up/Down still activates chat history on current main, and the keybinding workaround does not address the requested default. With 39 upvotes, an assignee, and unresolved maintainer disagreement about the intended interaction, this needs a product decision rather than a judgment close.

## Change summary

Change chat composer navigation so ordinary Up/Down caret movement does not unexpectedly replace an active draft with prompt history.

## Best solution

Use a deliberate modified shortcut such as Alt+Up/Down for chat history while preserving normal multiline caret navigation for bare arrows, and continue preserving the complete draft and attachments whenever history navigation occurs.

## Evidence

- **current behavior:** src/vs/platform/history/browser/contextScopedHistoryWidget.ts still registers `history.showPrevious` and `history.showNext` with bare UpArrow and DownArrow as their primary bindings, with Alt+Up/Down as secondary bindings.
- **chat trigger:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts enables backward history navigation at line 1, column 1 and forward navigation at the model's last position, so bare arrows still replace the visible chat input at those boundaries.
- **draft preservation:** Current main mitigates loss through ChatInputPart.showPreviousValue/showNextValue and ChatHistoryNavigator.overlay in src/vs/workbench/contrib/chat/common/widget/chatWidgetHistoryService.ts, which retain the active input state for restoration; this does not resolve the request to change the default gesture.
