# Issue #329283 — [Agent Host BYOK] Responses reasoning continuation loses its stateful marker

[https://github.com/microsoft/vscode/issues/329283](https://github.com/microsoft/vscode/issues/329283)

## Summary

Detailed report of a plausible regression in the very recently merged Agent Host BYOK Responses bridge (PR #328146, merged 2026-07-31), but I could not conclusively pin the exact failure point in the multi-hop marker round-trip from source alone — asking for a captured request/response log to localize it.

## Change summary

For Agent Host BYOK models using the OpenAI Responses API, the `stateful_marker` (previous_response_id) is sometimes lost between the initial response and a tool-call continuation, causing five deterministic retries and a hard failure instead of one clean request or a clear diagnostic.

## Best solution

Trace the marker hand-off end-to-end across `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts` (`_toChatMessages`/`_decodeStatefulMarker`) and `src/vs/platform/agentHost/node/copilot/byokResponsesTranslation.ts` (`prepareResponse`/`responsesRequestToBridge`) for the tool-call continuation path specifically, ideally with a captured request/response log from the reporter, then add a regression test covering reasoning+tool-call continuation before landing a fix. If confirmed dropped, also consider failing fast with a clear diagnostic instead of 5 retries as the reporter suggests.
