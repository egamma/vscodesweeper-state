# Issue #346859 — Share agent host sessions between the Agents Window and WSL, SSH and Dev Container editor windows

[https://github.com/microsoft/vscode/issues/346859](https://github.com/microsoft/vscode/issues/346859)

## Summary

Keep open: current source explicitly excludes WSL, SSH, and Dev Container sessions from cross-window handoff. The related tunnel implementation and test plan identify this as separate follow-up work, not an already completed capability.

## Change summary

Allow the same remote agent session to open in both the Agents Window and its WSL, SSH, or Dev Container editor window.

## Best solution

Establish shared agent-host session ownership across these remote editor and Agents windows, then support revealing the exact session in either direction. Preserve existing local and tunnel handoff behavior and remote filesystem boundaries.

- **Behavior:**

  > A session created in a WSL, SSH, or Dev Container editor window can be opened as the same conversation in the Agents Window, and vice versa. Opening the other window must reveal the requested session rather than only its folder or an unsupported-session notification. Continuing the conversation must retain its history and remote execution environment. Existing local and tunnel handoff behavior remains unchanged.
- **Trace:**

  > resolveAndOpenRemoteSession in src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts explicitly rejects non-tunnel remotes. The reverse helper, getEditorWindowSessionResource in src/vs/workbench/contrib/sessions/browser/openInVSCodeUtils.ts, likewise supports only tunnel-backed remote sessions. src/vs/server/node/serverServices.ts already supports explicit upstream bridge endpoints, but its default path starts a separate lazy agent host; sharing a machine or translating session schemes does not unify those registries. https://github.com/microsoft/vscode/pull/346290 supplies the narrower tunnel precedent, and https://github.com/microsoft/vscode/issues/346565 explicitly reserves this issue for the remaining remote kinds. The trace establishes the gap but not the complete launcher changes needed across SSH, WSL, and container startup. Preserve exact backend session identity, owning-connection URI mapping, and existing local/tunnel behavior; do not treat removal of the handoff guards alone as implementation.
