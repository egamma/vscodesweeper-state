# Issue #206735 — `Vscode.Window.onDidCloseTerminal` not invoked even terminal is halted in a specific case

[https://github.com/microsoft/vscode/issues/206735](https://github.com/microsoft/vscode/issues/206735)

## Summary

Keep open: moving a terminal editor between groups removes its disposal-event forwarding, and the visible-editor recovery path does not restore that forwarding. This explains the missing onDidCloseTerminal event and the later macOS confirmation; the defect is not confined to WSL.

## Change summary

Ensure extensions receive onDidCloseTerminal when a terminal is actually closed after moving its editor between groups.

## Best solution

Preserve terminal identity and lifecycle notifications across editor-group moves, with exactly one close notification when the terminal subsequently exits or is explicitly closed. The bounded ownership path is in TerminalEditorService, not in the OCaml extension or Remote-WSL.

## Evidence

- **Confirmed report:** The discussion at https://github.com/microsoft/vscode/issues/206735 identifies moving the terminal as the necessary trigger, reports the same failure with two extensions, and includes an independent February 2026 macOS reproduction using Terminal: Create New Terminal in Editor Area followed by moving and closing it.
- **Move triggers editor close:** src/vs/workbench/browser/parts/editor/editorGroupView.ts, doMoveOrCopyEditorAcrossGroups, opens the same editor in the destination and then closes it in the source with EditorCloseContext.MOVE. This is an editor-location change, not terminal disposal.
- **Disposal forwarding is lost:** In src/vs/workbench/contrib/terminal/browser/terminalEditorService.ts, the onDidCloseEditor handler calls _removeInstance without checking the close context. _removeInstance disposes _instanceDisposables, including the instance.onDisposed forwarding installed by _registerInstance. The onDidVisibleEditorsChange recovery path only restores _editorInputs and instances; it does not restore these listeners.
- **API notification depends on that forwarding:** TerminalService._forwardInstanceHostEvents in src/vs/workbench/contrib/terminal/browser/terminalService.ts forwards the editor host's onDidDisposeInstance. MainThreadTerminalService._onTerminalDisposed in src/vs/workbench/api/browser/mainThreadTerminalService.ts sends $acceptTerminalClosed, which fires the public event in src/vs/workbench/api/common/extHostTerminalService.ts. TerminalService._initInstanceListeners has a separate disposal listener for cleanup, but it does not emit the missing notification.
- **Canonical search:** GitHub searches for onDidCloseTerminal and terminal move/disposal events found no verified open canonical. https://github.com/microsoft/vscode/issues/47816 concerns Windows environment refresh, not terminal lifecycle events. https://github.com/microsoft/vscode/issues/152785 concerns explicit session detachment and is closed, so it cannot serve as a duplicate target.
