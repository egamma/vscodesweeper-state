# Issue #185565 — Accessibility: Cannot turn off audio cues on a language level

[https://github.com/microsoft/vscode/issues/185565](https://github.com/microsoft/vscode/issues/185565)

## Summary

Language-specific control of editor accessibility sounds remains unsupported in current source. Keep this accepted Backlog request open; the renamed signal settings do not deliver the requested Markdown override.

## Change summary

Allow error-line accessibility sounds to be disabled for Markdown while remaining enabled for other languages.

## Best solution

Support language-specific enablement for editor-associated accessibility signals using the triggering document's language, while preserving existing global defaults and unrelated signals. Decide the supported settings and modality scope before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts`, `src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts`, `src/vs/workbench/contrib/accessibilitySignals/browser/editorTextPropertySignalsContribution.ts`
- **Validation:** Verify with error diagnostics in Markdown and another language: globally enable accessibility.signals.lineHasError.sound, disable it only for Markdown, and navigate onto error lines in each document. Markdown must remain silent while the other language sounds; switching editors, changing a document's language, and updating the override must take effect without reloading. Confirm unchanged behavior without language overrides and for unrelated signals.
- **Behavior:**

  > Users can disable the error-on-line sound for Markdown without disabling it for other languages. The language-specific setting applies to the document that produced the editor signal. With no override, existing global settings and screen-reader-dependent defaults remain unchanged. Acceptance includes navigating onto error lines in two languages and observing correct behavior after editor switches and language changes.
- **Trace:**

  > The current successor to audioCues.lineHasError is accessibility.signals.lineHasError, registered in src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts with RESOURCE scope rather than LANGUAGE_OVERRIDABLE. AccessibilitySignalService in src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts resolves settings through observableConfigValue without document or language overrides and caches enablement without either context. EditorTextPropertySignalsContribution in src/vs/workbench/contrib/accessibilitySignals/browser/editorTextPropertySignalsContribution.ts possesses the triggering model but does not convey its context when checking or playing error-line signals. These source paths establish missing capability, not a regression in previously supported behavior. Preserve global enablement, existing sound timing, and non-editor signals; do not infer their language from whichever editor happens to be active. The unresolved product boundary is which editor-associated settings and modalities should support language overrides. Related report: https://github.com/microsoft/vscode/issues/185565.
- **Open decisions:**
  - Should language overrides initially cover only diagnostic editor signals, or all editor-associated signals such as breakpoints and folded areas?
  - Should language overrides control both sound and announcement modalities, or only sounds as requested?

## Evidence

The supplied comments from meganrogge and hediet indicate this probably never worked, supporting the existing feature-request classification rather than a regression.
- **Existing capability does not cover the request:** src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts registers accessibility.signals.lineHasError at lines 399–414 under ConfigurationScope.RESOURCE, inherited from the configuration node at line 145. Neither that property nor signalFeatureBase declares LANGUAGE_OVERRIDABLE. The current setting offers sound and announcement controls, but not language-specific enablement.
