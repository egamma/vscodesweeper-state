# Issue #337167 — Launch skill should compile before opening the OSS Agents window

[https://github.com/microsoft/vscode/issues/337167](https://github.com/microsoft/vscode/issues/337167)

## Summary

Real, traceable bug in the shared prelaunch flow: `ensureCompiled()` in build/lib/preLaunch.ts only checks whether a top-level `out/` directory exists, so a partially-built tree (e.g. client compiled via `transpile-client` but `extensions/*/out` missing) is treated as fully compiled and the compile step is skipped, which is exactly the failure this issue describes for the Agents window launch.

## Change summary

The launch skill's normal prelaunch flow doesn't reliably ensure OSS sources are compiled before opening the Agents window, forcing a manual follow-up compile.

## Best solution

Make `ensureCompiled()` in build/lib/preLaunch.ts detect a stale/partial build (e.g. also check that built-in extensions under extensions/*/out exist, not just top-level `out/`) so `npm run compile` runs whenever any required output is missing, instead of relying on a single top-level existence check.

## Plan brief

- **Likely files:** `build/lib/preLaunch.ts`
- **Validation:** Manually verify: populate `out/` (e.g. via `npm run transpile-client`) without building `extensions/*/out`, then run `node build/lib/preLaunch.ts` and confirm it now triggers `npm run compile` instead of skipping it.
- **Trace:**

  > `ensureCompiled()` in build/lib/preLaunch.ts (called from .agents/skills/launch/scripts/launch.sh's normal prelaunch flow) currently only checks `exists('out')`; it needs to also detect when built-in extensions or other required outputs are missing/stale even though top-level `out/` exists, so the OSS Agents window launch doesn't fail with missing compiled modules. Do not change the `--skip-prelaunch` fast path or the electron/node_modules provisioning steps in the same file.
- **Open decisions:**
  - Should the staleness check be a cheap existence check on a few known subdirectories (e.g. extensions/*/out), or a more general incremental check (timestamps/marker file) that also covers future similar gaps?
  - Should this extra check apply to every `npm run compile`-based caller of preLaunch.ts, or only the Agents-window launch path?

## Evidence

- **root cause in source:** build/lib/preLaunch.ts `ensureCompiled()` only does `await exists('out')` and skips `npm run compile` entirely if that one directory exists, regardless of whether extensions or other outputs are current.
- **documented failure mode:** .agents/skills/launch/SKILL.md troubleshooting section already names this exact scenario: '"Built-in extension fails to load..." - extensions weren't compiled... A common cause: you ran npm run transpile-client... which populated out/ but not extensions/*/out/, so preLaunch's "is out/ missing?" check skipped the compile.'
- **invocation path:** .agents/skills/launch/scripts/launch.sh calls `node build/lib/preLaunch.ts` directly during the normal (non `--skip-prelaunch`) flow (line 242), so this shared function is exactly what runs before the Agents window launch described in the issue.
