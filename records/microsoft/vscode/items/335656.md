- **Behavior:**

  > Typing a search term into the Agents window folder/workspace picker should also surface recent folders whose *parent* path segment matches the term, not only folders whose own name matches. Acceptance: searching a common parent directory name (e.g. a user or projects folder) returns the child folders nested under it, ranked sensibly alongside direct name matches.
- **Trace:**

  > The recent-workspace filtering path in src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts currently filters/searches based on the workspace's own folder path (see the path-segment handling around line 1066 and the various .filter() chains over recentWorkspaceEntries); there is no logic that expands matching to ancestor path segments. The issue references #335538 as related prior work on this same picker. Boundary: scope this to the recent/local folder search path, not the remote provider filter (filterPlaceholder 'Search Remote') or the general quick-pick filtering elsewhere.
- **Open decisions:**
  - Should parent-folder matches be ranked below, above, or interleaved with direct name matches?
  - How many ancestor levels should be searched (immediate parent only, or the full path)?
  - Should this apply only to local recent workspaces, or also to remote/container workspace entries?
