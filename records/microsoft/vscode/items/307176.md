# Issue #307176 — TUI `Shift+Enter` causes SEND request instead of newline

[https://github.com/microsoft/vscode/issues/307176](https://github.com/microsoft/vscode/issues/307176)

## Summary

VS Code's terminal correctly forwards Shift+Enter to the running program via the kitty keyboard protocol (enabled by default since 1.99). The codex TUI interprets Shift+Enter as 'send' — that's the application's design choice, not a VS Code bug.

## Change summary

Shift+Enter in the integrated terminal sends a submit/send action in the codex TUI instead of inserting a newline.

## Best solution

This is working as designed: the `terminal.integrated.enableKittyKeyboardProtocol` setting (default `true`) enables programs to distinguish Shift+Enter from Enter. The reporter should either set `terminal.integrated.enableKittyKeyboardProtocol: false` to get legacy behavior, or file the issue with the codex CLI (which they already have at openai/codex#16445) to handle the key differently.

  > Thanks for the report. This is working as designed — VS Code's terminal now supports the [kitty keyboard protocol](https://sw.kovidgoyal.net/kitty/keyboard-protocol/) (enabled by default via `terminal.integrated.enableKittyKeyboardProtocol`), which lets programs in the terminal distinguish modifier+key combinations like Shift+Enter from plain Enter.   >

  > 
  > Alacritty and iTerm2 also support this protocol, so the behavior difference you see may be because codex doesn't request the enhanced mode in those terminals (or they handle negotiation differently).
