# Issue #340829 — Copilot agent can overwrite newer workspace files from a stale chat session

[https://github.com/microsoft/vscode/issues/340829](https://github.com/microsoft/vscode/issues/340829)

## Summary

Thanks for the detailed report. A stale chat session overwriting newer workspace content is a plausible data-loss path. Two commenters report similar behavior, but the steps are not deterministic and I did not trace the edit-application path in source. No older issue clearly owns the same symptom, so this stays open.

## Change summary

An old agent chat session overwrote newer on-disk file contents across multiple files without a stale-content warning or conflict check.

## Best solution

Make agent edit application verify the file's current version or content against what the session last read. On mismatch, rebase the edit or show a conflict/diff and ask before replacing. Start by tracing the chat editing session's write path to see why stale content can be applied.

  > When an agent edit targets a file whose current contents differ from what the session last observed, the edit must not silently overwrite them.
