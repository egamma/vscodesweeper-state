## Evidence

- **Confirmed destructive behavior:** https://github.com/microsoft/vscode/issues/340829#issuecomment-6736051228 documents repeated overwrites in Insiders 1.146.0: three complete files matched older Agent/session snapshots byte-for-byte while the current Git ref remained unchanged. - **Independent confirmation:** https://github.com/microsoft/vscode/issues/340829#issuecomment-6148165946 reports losing edits made outside VS Code or in another session when accepting chat changes. The reporter later acknowledged uncertainty about the precise sequence; the hash-guard explanations from another commenter are hypotheses, not established diagnoses.
- **Current source hazard:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts:_initEntries passes restoreToDisk=true for pending Modified snapshots. chatEditingModifiedDocumentEntry.ts:restoreFromSnapshot forwards snapshot.current to chatEditingTextModelChangeService.ts:resetDocumentValues, which replaces the full live model range without a freshness comparison. This substantiates a text-review overwrite path, not every reported Agent Host sequence.
- **Open partial implementation:** https://github.com/microsoft/vscode/pull/343109 is verified OPEN with no merge commit and explicitly references this issue without closing it. It proposes preserving newer text during review restoration and using normal save-conflict handling on acceptance; explicit checkpoint restoration, notebooks, and provider/model-generated stale replacements are excluded.
- **Canonical search:** https://github.com/microsoft/vscode/issues/344973 concerns blocked Keep/dismiss actions rather than silent overwrites; https://github.com/microsoft/vscode/issues/262313 concerns failed explicit checkpoint restoration. https://github.com/microsoft/vscode/issues/341433 reports overlapping stale-edit symptoms but is younger, has no milestone or upvotes, and does not qualify as this re-reviewed item's canonical.
