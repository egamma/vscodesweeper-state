# Issue #337782 — Show effort level on subagent pill hover, if configured in Task tool call.

[https://github.com/microsoft/vscode/issues/337782](https://github.com/microsoft/vscode/issues/337782)

## Summary

Fresh, team-filed polish request for the subagent pill hover; the underlying model-name hover already exists, but it's unclear where 'effort configured by the mainagent' would be sourced from for a subagent's Task tool call, so this needs a short design pass before implementation.

## Change summary

Show the configured reasoning effort level (not just the model name) on hover of a subagent pill, when the main agent configured one for the Task tool call.

## Best solution

Extend ChatSubagentContentPart's hover tooltip (currently only showing model name) to also surface an effort/reasoning-level value once it's clear where that value is captured on the subagent tool invocation data.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts`, `src/vs/workbench/contrib/chat/common/model/chatProgressTypes/chatToolInvocation.ts`
- **Validation:** A test in chatSubagentContentPart.test.ts asserting the hover tooltip includes an effort line when the subagent's tool-specific data carries an effort value.
- **Behavior:**

  > When a subagent (Task tool) invocation is configured with an explicit effort/reasoning level, hovering its pill shows that level alongside the model name; when no effort was configured, the hover is unchanged.
- **Trace:**

  > ChatSubagentContentPart.extractSubagentInfo (chatSubagentContentPart.ts ~line 203) reads modelName off toolInvocation.toolSpecificData and appends a 'Model: {0}' hover line at ~line 915; there is no analogous 'effort' property on IChatSubagentToolInvocationData or produced by runSubagentTool.ts today. The open question is where the Task tool call's effort configuration is set/available (a new tool parameter vs. inherited model config) before this can be wired into toolSpecificData the same way modelName is.
- **Open decisions:**
  - Where does 'effort configured in the Task tool call' come from — a new explicit parameter on the subagent/Task tool invocation, or the main agent's current reasoningEffort model setting at invocation time?
  - Should the hover always show effort when present, or only when it differs from a default/inherited value?
