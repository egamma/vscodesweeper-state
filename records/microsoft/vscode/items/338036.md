# Issue #338036 — New Copilot SDK harness ignores chat.permissions.default and starts with Manual permissions

[https://github.com/microsoft/vscode/issues/338036](https://github.com/microsoft/vscode/issues/338036)

## Summary

Team-authored issue (pamelafox, MEMBER), so a judgment close (e.g. *as-designed) is barred even though the code suggests this split is intentional; two other users confirmed the same symptom, and the architecture needs a maintainer call on whether to unify the settings or better communicate the split.

## Change summary

Agent-host sessions created via the new Copilot SDK harness ignore `chat.permissions.default` and start in Manual/Default permissions instead of the user's configured auto-approve default.

## Best solution

A maintainer should decide whether agent-host/Copilot-SDK-harness sessions should also honor `chat.permissions.default` (mapping it into the `chat.defaultConfiguration.approvals` slot the way `_getInitialConfig`/`_initialNewSessionConfig` already seed values), or whether the split is intentional and should instead be surfaced to users (e.g. deprecation notice / migration prompt pointing at `chat.defaultConfiguration`).

## Evidence

- **intentional split, workbench chat path:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostUntitledProvisionalSessionService.ts:1078-1118 `_getInitialConfig()` seeds `SessionConfigKey.AutoApprove`/`Mode` only from `ChatConfiguration.DefaultConfiguration` (`chat.defaultConfiguration`); its own doc comment states 'The local-only `chat.permissions.default` setting is NOT used.'
- **intentional split, Agents/Sessions window path:** src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:4806-4830 `_initialNewSessionConfig()` likewise seeds approvals from `chat.defaultConfiguration` with an explicit comment: 'The local-only `chat.permissions.default` setting is intentionally NOT consulted here.'
- **setting scope:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:751 registers `chat.permissions.default` with description 'Controls the default permissions picker mode for new local chat sessions' — i.e. scoped to the legacy (non-agent-host) chat implementation, not the new SDK harness.
- **dialog copy confirms the split:** src/vs/workbench/contrib/chat/common/chatPermissionWarnings.ts:137-140: '...local chat uses `chat.permissions.default` (the default), while agent-host sessions pass `chat.defaultConfiguration`.'
- **multiple confirmations:** Two other users (Y-Sindo, carozozo) confirmed the same symptom on 1.140.0 in the comments, suggesting this will affect more users as the Copilot SDK harness becomes the default path (see `chat.defaultToCopilotHarness`).
