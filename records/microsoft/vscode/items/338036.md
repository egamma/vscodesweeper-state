# Issue #338036 — New Copilot SDK harness ignores chat.permissions.default and starts with Manual permissions

[https://github.com/microsoft/vscode/issues/338036](https://github.com/microsoft/vscode/issues/338036)

## Summary

Confirmed from source: the agent-host/Copilot SDK harness session-creation path deliberately does not consult `chat.permissions.default` (only `chat.defaultConfiguration.approvals`), so the report is accurate, not a misunderstanding — but since the author is a VS Code team member, this is protected from a judgment close (`*as-designed`) under the hard keep-open rule, and the thread (including a flicker report) suggests the current scoping is itself the bug they want addressed.

## Change summary

New agent-host (Copilot SDK harness) sessions ignore `chat.permissions.default: autoApprove` and start in Manual permissions instead.

## Best solution

Either extend `_initialNewSessionConfig` in baseAgentHostSessionsProvider.ts to map `chat.permissions.default` into the agent-host approvals seed (as #315381 reportedly did for the `openNewSessionSidebar` path), fitting it into the existing policy > remembered > `chat.defaultConfiguration` precedence chain, or make the local-only scoping of `chat.permissions.default` explicit in its description/UI everywhere it's surfaced so users aren't misled into expecting it to apply to harness sessions.
