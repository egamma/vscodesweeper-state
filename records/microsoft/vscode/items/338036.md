# Issue #338036 — New Copilot SDK harness ignores chat.permissions.default and starts with Manual permissions

[https://github.com/microsoft/vscode/issues/338036](https://github.com/microsoft/vscode/issues/338036)

## Summary

Traced in source: the new agent-host (Copilot SDK harness) session-creation path explicitly does not consult `chat.permissions.default` by design — it seeds approvals only from `chat.defaultConfiguration` — which matches the reported symptom exactly, but author is a VS Code MEMBER so a judgment-based `*as-designed` close isn't available here; this needs a maintainer decision on whether that split is correct or should be reconciled, so it stays open.

## Change summary

A new agent-host session created via the new Copilot SDK harness starts in Manual permissions even when `chat.permissions.default` is set to `autoApprove`, instead of inheriting that setting.

## Best solution

A maintainer should decide whether the SDK-harness/agent-host session seed in `_initialNewSessionConfig` (baseAgentHostSessionsProvider.ts) and `_getInitialConfig` (agentHostUntitledProvisionalSessionService.ts) should also read `chat.permissions.default` as a fallback for parity with local chat, or whether the setting's description should instead be clarified/deprecated for this harness so users aren't misled into expecting it to apply.

- **Behavior:**

  > A new agent-host (Copilot SDK harness) session should start with the permission level the user expects from their configured defaults. Today, setting `chat.permissions.default: autoApprove` has no effect on these sessions — they always start in Manual/Default permissions unless `chat.defaultConfiguration.approvals` is also set. The maintainer needs to decide: either (a) the harness should also honor `chat.permissions.default` as a fallback so existing user configuration isn't silently ignored, or (b) the setting description/docs should make the scope limitation explicit so users configure `chat.defaultConfiguration` instead, with acceptance criteria chosen accordingly.
- **Trace:**
