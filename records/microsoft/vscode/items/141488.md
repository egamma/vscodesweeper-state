## Summary

Still present on main: the 200ms setTimeout workaround in cli.ts is the only mitigation, and watchFileContents still lacks a proper flush/drain mechanism. Valid debt item, correctly labeled help-wanted.

## Change summary

The CLI file watcher for verbose/status output may cut off data because cancellation races with pending reads when the main process exits.

## Best solution

Refactor watchFileContents in src/vs/platform/files/node/watcher/nodejs/nodejsWatcherLib.ts to perform a final drain read of remaining file contents upon cancellation (as bpasero suggested), eliminating the fragile 200ms timeout in src/vs/code/node/cli.ts.
