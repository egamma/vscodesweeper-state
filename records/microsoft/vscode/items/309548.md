# Issue #309548 — [Unhandled Error] Cannot resolve canonical URI

[https://github.com/microsoft/vscode/issues/309548](https://github.com/microsoft/vscode/issues/309548)

## Summary

Still reproduces on current main: `getCanonicalURI` in both `extensionHostManager.ts` and `lazyCreateExtensionHostManager.ts` throws when the proxy is null, even though the return type is `Promise<URI | null>` and the caller already handles null results gracefully. The suggested fix (return null instead of throwing) has not landed. Thousands of users are affected across every recent stable release.

## Change summary

Extension host manager throws an unhandled error when resolving canonical URIs if the extension host proxy is null (disposed or failed to start), instead of returning null as the return type permits.

## Best solution

Change `throw new Error('Cannot resolve canonical URI')` to `return null` in `extensionHostManager.ts:420` and `lazyCreateExtensionHostManager.ts:185`. The caller in `nativeExtensionService.ts:335-340` already iterates results and skips nulls, so this is safe. The `nativeExtensionService.ts:332` throw (no local process extension hosts at all) may also deserve a softer fallback, but the two proxy-null sites are the telemetry hotspots.
