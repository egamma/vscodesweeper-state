# Issue #196582 — Comments sync/resume is flaky and has unexpected UX

[https://github.com/microsoft/vscode/issues/196582](https://github.com/microsoft/vscode/issues/196582)

## Summary

Keep open: current Cloud Changes settings provide shutdown/reload automation, not the requested background continuity for draft comments. The source still couples restoring workspace state to file changes, and no verified canonical owns the full request.

## Change summary

Make draft PR comments transfer reliably between machines without unrelated file edits or repeated Store/Resume commands.

## Best solution

Support comment-only workspace-state transfer in core Cloud Changes, with a maintainer-agreed background synchronization contract. Preserve existing working-file transfer behavior and define how concurrent draft edits on two machines are reconciled.

- **Behavior:**

  > After enabling the feature, a user drafting a PR comment on one machine should be able to continue that draft on another without editing an unrelated file or repeatedly invoking Store/Resume. Draft replies should retain their thread association. Acceptance must cover comment-only transfer and the agreed automatic synchronization lifecycle, while preserving existing working-file transfer behavior.
- **Trace:**

  > CommentService collects pending drafts on storageService.onWillSaveState and consumes external workspace-storage changes in src/vs/workbench/contrib/comments/browser/commentService.ts. WorkspaceStateSynchroniser.sync in src/vs/workbench/contrib/editSessions/common/workspaceStateSync.ts flushes and uploads user-target workspace state. In src/vs/workbench/contrib/editSessions/browser/editSessions.contribution.ts, storeEditSession uploads workspace state but skips the edit-session record when no files changed; resumeEditSession requires such a record and returns before applying workspace state when generated file changes are empty. Existing autoStore and autoResume settings operate on shutdown and reload, rather than live synchronization. The issue's testing context at https://github.com/microsoft/vscode/issues/193104 corroborates the manual-flow problem, but runtime reliability was not tested in this read-only review. Preserve explicit working-file transfer and its conflict protections; uncertainty begins at the automatic comment-sync lifecycle and concurrent-draft contract.
- **Open decisions:**
  - Should draft comments synchronize while both windows remain open, or only at defined handoff events such as window close and workspace opening?
  - Should enabling Cloud Changes also enable automatic draft-comment synchronization, or should that require separate consent?
  - When the same draft is edited on both machines, what user-visible reconciliation behavior should preserve the competing edits?
