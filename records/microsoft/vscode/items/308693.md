# Issue #308693 — Model picker broken rendering when other models opened on startup

[https://github.com/microsoft/vscode/issues/308693](https://github.com/microsoft/vscode/issues/308693)

## Summary

Still reproduces on main: the model picker's submenu panel uses getBoundingClientRect() for positioning, and during early startup the anchor/parent rects can be zero, placing the submenu at the top-left corner. No fix has landed since the report.

## Change summary

Model picker submenu renders at the top-left corner when opened immediately on startup before layout is complete.

## Best solution

Guard the submenu positioning in ActionListWidget._showSubmenuForElement (src/vs/platform/actionWidget/browser/actionList.ts) to defer or skip rendering when the anchor's bounding rect is zero (not yet laid out). The model picker action item's _getAnchorElement already checks document.contains, but it doesn't guard against a zero-rect element that is technically in the DOM but not yet laid out.
