# Issue #147651 — Treat numbers as separate word / parts, including decimal points

[https://github.com/microsoft/vscode/issues/147651](https://github.com/microsoft/vscode/issues/147651)

## Summary

Keep this accepted Backlog request open: current word navigation still lacks the requested numeric boundaries and decimal grouping. The related camel-case fix covers a narrower case, and no verified open canonical absorbs this request.

## Change summary

Support configurable numeric word and word-part boundaries, with digit-surrounded decimal punctuation grouped for whole-word operations.

## Best solution

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/core/wordCharacterClassifier.ts`, `src/vs/editor/common/cursor/cursorWordOperations.ts`, `src/vs/editor/contrib/wordOperations/test/browser/wordOperations.test.ts`, `src/vs/editor/contrib/wordPartOperations/test/browser/wordPartOperations.test.ts`
- **Validation:** Extend the existing word and word-part command suites to assert cursor stops, selection ranges, and deletion results in both directions for 123rem, 1.23rem, and 1,23rem under each agreed mode. In the requested enabled mode, whole-word navigation must preserve the decimal number while word-part navigation exposes the punctuation boundaries. Verify disabled-mode compatibility and existing camel-case, separator, whitespace, and multicursor behavior.
- **Behavior:**

  > The request is to navigate, select, and delete numeric runs independently of adjacent text such as CSS units. Its examples require a boundary at 123|rem in both directions and whole-word movement from |1.23rem to 1.23|rem. Word-part movement should instead expose the successive stops 1|.23rem, 1.|23rem, and 1.23|rem, with analogous comma behavior. Acceptance must cover movement, selection, and deletion in both directions, plus a compatibility mode retaining existing behavior; the shipping defaults remain a product decision.
- **Trace:**

  > Whole-word operations use WordCharacterClassifier and WordOperations in src/vs/editor/common/core/wordCharacterClassifier.ts and src/vs/editor/common/cursor/cursorWordOperations.ts. The classifier distinguishes regular characters, whitespace, and configured separators; digits and lowercase letters share the regular class, and punctuation has no digit-surrounded exception. _moveWordPartLeft/Right adds camel-case, underscore, and dash stops, and WordPartOperations combines those candidates with whole-word boundaries. Existing command tests use testRepeatedActionAndExtractPositions and pipe-position expectations in the wordOperations and wordPartOperations browser suites. https://github.com/microsoft/vscode/pull/147074 fixed digit-before-uppercase camel-case movement but does not satisfy this request. Preserve that fix and unrelated editor behavior; do not assume navigation changes should alter language word definitions, completion, or whole-word search. The trace establishes the missing capability, while numeric syntax and default-mode compatibility remain undecided.
- **Open decisions:**
  - Should numeric boundaries and decimal grouping change the default editing behavior as requested, or remain opt-in for compatibility?
  - Should both dot and comma always group between digits, or should decimal grouping follow a selected locale or language convention?
  - What numeric forms are included beyond the supplied examples: only digit runs with one decimal mark, or also signs, exponents, and thousands separators?
