# Issue #302002 — Image Carousel: Add context menu on right-click

[https://github.com/microsoft/vscode/issues/302002](https://github.com/microsoft/vscode/issues/302002)

## Summary

Keep open: Images Preview still lacks image context-menu actions, and another team member explicitly requested copying images or their paths. The related open reports are newer and cannot replace this re-reviewed, team-authored request.

## Change summary

Provide a right-click context menu on carousel images with useful actions such as Copy Path and Copy Image.

## Best solution

Provide standard, keyboard-accessible image actions in ImageCarouselEditor, using the original image resource rather than its temporary display URL. Agree on the initial action set and availability for in-memory images, coordinating with the newer copy/save and remote-download requests.

Verify Copy Path returns the original resource path for URI-backed images, data-only images follow the agreed availability rules, and existing navigation and zoom remain unchanged; include clipboard assertions for any agreed Copy Image action.
- **Behavior:**

  > Images Preview currently offers navigation and zoom but no image context menu. Users should be able to right-click an image and discover the agreed image actions, with equivalent keyboard access. Copy Path, when available, must refer to the original image resource rather than a temporary blob URL. Acceptance covers URI-backed and in-memory images, correct action targeting after navigation, and unchanged navigation and zoom behavior.
- **Trace:**

  > ImageCarouselEditor.buildSlideshow in src/vs/workbench/contrib/imageCarousel/browser/imageCarouselEditor.ts creates the main image and thumbnail buttons; its listeners cover navigation and zoom, not context-menu actions. updateCurrentImage selects an ICarouselImage from _flatImages, and _loadBlobUrl renders both URI-backed and in-memory entries through temporary blob URLs. ICarouselImage in imageCarouselTypes.ts does not require a uri, so path actions cannot assume every image is a file. imageCarousel.contribution.ts exposes Explorer entry points but no viewer-local image actions. Preserve existing navigation, zoom, video playback, and blob-cache lifetimes; the request does not require redesigning collection construction. Coordinate overlapping work with https://github.com/microsoft/vscode/issues/329065 and remote-specific requirements at https://github.com/microsoft/vscode/issues/336296. The remaining uncertainty is the initial user-visible action set and how unavailable source-path actions appear for data-only images.
- **Open decisions:**
  - Which actions are in the initial carousel context menu: Copy Path and Copy Image only, or also Save, Open, and Reveal?
  - For images without an original URI, should source-path actions be hidden or shown disabled?
