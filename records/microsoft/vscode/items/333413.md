# Issue #333413 — Newly added `configurationSchema` property does not appear in the model-settings dropdown until a config write (chat session snapshot stale; hover shows it)

[https://github.com/microsoft/vscode/issues/333413](https://github.com/microsoft/vscode/issues/333413)

## Summary

Traced to a real gap in `ChatInputModelSelectionController.reconcileModelListChange`: when the model list changes but the currently selected model's identifier is still present, the code returns early without refreshing the cached metadata object, so a provider that re-registers the *same* model id with an updated `configurationSchema` leaves the input widget holding a stale schema until an unrelated write elsewhere forces a resync.

## Change summary

A model's newly added `configurationSchema` property does not appear in the chat input's settings dropdown until an explicit config write happens, even though the live model-picker hover already shows it.

## Best solution

In `reconcileModelListChange` (src/vs/workbench/contrib/chat/browser/widget/input/chatInputModelSelectionController.ts), when `shouldResetOnModelListChange` returns false because the identifier is still present, still refresh `_currentModel` to the pool's current metadata object (by identity/schema diff) instead of leaving the old snapshot in place — this keeps the schema-driven `_getConfigProperty`/`_buildItems` path in modelPickerConfiguration.ts in sync with the live `ILanguageModelsService` metadata that the hover already reads.
