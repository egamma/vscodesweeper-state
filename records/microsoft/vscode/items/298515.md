# Issue #298515 — inlineChat.defaultModel schema validation fails when models are updated.

[https://github.com/microsoft/vscode/issues/298515](https://github.com/microsoft/vscode/issues/298515)

## Summary

The rename-sensitive setting remains on current main: its enum is populated dynamically, but stored values and runtime matching still depend on model display names. Keep this open; dynamic registration and runtime fallback already exist, but neither preserves a preference across a display-name change.

## Change summary

Prevent model catalog changes from invalidating an inline-chat model preference or losing its association with an otherwise available model.

## Best solution

Give inline-chat model preferences a rename-resistant identity while retaining readable picker labels and compatibility with existing settings. Settle the persisted-value and unavailable-model validation contract before implementation; preserve the existing fallback when a model is genuinely unavailable.

## Evidence

- **Current schema reproduces the rename failure:** src/vs/workbench/contrib/inlineChat/browser/inlineChatDefaultModel.ts registers inlineChat.defaultModel as a string with enum: InlineChatDefaultModel.modelIds. Its contribution does not enable storageFormat: 'vendorAndId', so the shared contribution uses display-name-based qualified values.
- **Dynamic registration already exists but does not preserve old values:** In src/vs/workbench/contrib/chat/browser/defaultModelContribution.ts, DefaultModelContribution subscribes to onDidChangeLanguageModels, clears and rebuilds the enum arrays, and notifies the configuration registry. The default storage format calls ILanguageModelChatMetadata.asQualifiedName; replacing a model's name therefore removes the old configured string from the enum. The report's hardcoded-enum diagnosis is inaccurate, but the resulting validation failure follows directly from this path.
- **Runtime preference also depends on the display name:** src/vs/workbench/contrib/chat/common/languageModels.ts defines asQualifiedName as `${metadata.name} (${metadata.vendor})`. matchesQualifiedName accepts that exact string or, for Copilot, the current bare display name. ChatInputPart.switchModelByQualifiedName in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts uses this matching, so a former display name cannot select the renamed model.
- **Fallback is already implemented:** InlineChatController.#applyModelDefaults in src/vs/workbench/contrib/inlineChat/browser/inlineChatController.ts tries the configured qualified name, logs a warning when it cannot match, and falls back to the vendor default. This prevents selection failure from blocking inline chat, but does not remove schema diagnostics or retain the intended model preference.
- **Stable storage has existing infrastructure, not inline-chat adoption:** DefaultModelContribution already supports storageFormat: 'vendorAndId', with separate display labels and ambiguity filtering. src/vs/workbench/contrib/chat/test/browser/defaultModelContribution.test.ts covers this format. InlineChatDefaultModel and its runtime qualified-name resolver have not adopted it, so its availability alone does not establish a fix.
