# Issue #84620 — Git Merge Resolve Dialog

[https://github.com/microsoft/vscode/issues/84620](https://github.com/microsoft/vscode/issues/84620)

## Summary

A real gap remains in the inline conflict-marker workflow: resolving the final marker does not offer to mark the Git file resolved. The newer Merge Editor has an explicit Complete Merge action that stages the file, but that only partially covers this request.

## Change summary

Offer to mark a Git file resolved after its final merge conflict is resolved.

## Best solution

When the inline merge-conflict workflow detects that the last conflict in a Git-unmerged file has been resolved, offer a clear completion action that stages the file, while preserving the Merge Editor's existing Complete Merge behavior.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/commandHandler.ts`, `extensions/merge-conflict/src/documentTracker.ts`, `extensions/git/src/commands.ts`, `extensions/git/package.json`
- **Validation:** Create a Git conflict, resolve its final marker through both an inline Accept action and manual editing, and verify that VS Code offers to mark the file resolved; accepting must stage that file, declining must leave it unstaged, and the Merge Editor's existing Complete Merge flow must remain unchanged.
- **Behavior:**

  > After the final conflict in a Git-unmerged file is resolved outside the Merge Editor, VS Code should offer to mark that file resolved. Accepting the offer stages the file; declining leaves it unstaged. This must work for both inline conflict actions and manual marker removal without affecting ordinary files containing marker-like text. The existing Merge Editor Complete Merge workflow must remain unchanged.
- **Trace:**

  > The inline workflow is implemented in extensions/merge-conflict/src/commandHandler.ts, where accept commands edit conflict ranges, and extensions/merge-conflict/src/documentTracker.ts, where `DocumentMergeConflictTracker` scans documents for remaining markers. These paths have no Git staging integration when the final marker disappears. The separate Merge Editor path is already complete: `CommandCenter.acceptMerge` in extensions/git/src/commands.ts invokes `mergeEditor.acceptMerge` and stages the result through `repository.add([uri])`; extensions/git/package.json exposes that action only for merge-result editors. The boundary is the inline final-conflict transition for files Git still considers unmerged—do not change normal document saves or the existing Merge Editor completion semantics. The related open report is https://github.com/microsoft/vscode/issues/250857.

## Evidence

- **inline conflict path:** extensions/merge-conflict/src/commandHandler.ts removes conflict markers through the accept-current, accept-incoming, accept-both, and accept-all commands, while extensions/merge-conflict/src/documentTracker.ts detects remaining markers; neither path offers Git completion or staging when the count reaches zero.
- **partial existing capability:** extensions/git/src/commands.ts:1829-1852 implements `git.acceptMerge`: the Merge Editor's Complete Merge action accepts the result and then calls `repository.add([uri])`. This is contributed only for the Merge Editor in extensions/git/package.json, so it does not cover inline/manual conflict resolution.
- **maintainer direction:** https://github.com/microsoft/vscode/issues/84620#issuecomment-553302201 specifically points to the merge-conflict extension, which already probes conflict markers, as the likely owner of final-conflict detection.
- **continuing gap:** https://github.com/microsoft/vscode/issues/250857 is a newer open report that confirms files resolved through inline/SCM Accept All actions still are not staged without using the Merge Editor. It is narrower and newer than this issue, so it is supporting evidence rather than a canonical duplicate.
- **implemented subset:** Commit https://github.com/microsoft/vscode/commit/983fc7a6b6c9da3272219ab00a59ce5146a8afbf introduced the Merge Editor's Git completion button and staging behavior, but did not add final-conflict handling to the inline merge-conflict extension.
