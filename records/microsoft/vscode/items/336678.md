# Issue #336678 — Session fails to create worktree, but is still displayed as worktree

[https://github.com/microsoft/vscode/issues/336678](https://github.com/microsoft/vscode/issues/336678)

## Summary

Verified duplicate: the older open issue https://github.com/microsoft/vscode/issues/336353 already tracks sessions that continue after worktree creation fails while the UI remains in a worktree/pending state.

## Change summary

After worktree initialization fails and the agent falls back to the original workspace, the session still displays a worktree icon.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/336353 and make the effective workspace state authoritative after initialization, so a fallback session displays its real folder and branch rather than a pending worktree.
