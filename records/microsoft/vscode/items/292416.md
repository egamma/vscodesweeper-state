# Issue #292416 — Ignore import reference when going to reference

[https://github.com/microsoft/vscode/issues/292416](https://github.com/microsoft/vscode/issues/292416)

## Summary

Keep open: current reference navigation does not offer import/alias filtering, and the discussion supports reference-kind metadata rather than permanently discarding those results. The older reference-kind proposal is related, but does not report the same observable navigation symptom required to close this re-reviewed item as a duplicate.

## Change summary

Allow Go to References to ignore import/alias references so a symbol with one actual usage can navigate directly to that usage.

## Best solution

Support distinguishing and filtering reference kinds while retaining access to all references, following the direction discussed in the thread. Coordinate the shared reference-provider contract with https://github.com/microsoft/vscode/issues/74237, and settle how filtering affects direct navigation versus the complete references list.

- **Behavior:**

- **Trace:**

  > TypeScriptReferenceSupport.provideReferences in extensions/typescript-language-features/src/languageFeatures/references.ts forwards locations and only supports declaration exclusion. ReferenceContext and ReferenceProvider in src/vscode-dts/vscode.d.ts carry no reference-kind contract. getReferencesAtPosition in src/vs/editor/contrib/gotoSymbol/browser/goToSymbol.ts has a narrow declaration-compaction rule, while editor.gotoLocation.multipleReferences changes presentation rather than filtering. - **Open decisions:**
