[https://github.com/microsoft/vscode/issues/321083](https://github.com/microsoft/vscode/issues/321083)

## Summary

The report belongs in VS Code, but the static-registration prompt does not establish that DCR discovery was skipped: the same prompt appears after registration fails. Request current-build logs and the PROD/DEV metadata differences before identifying a core defect or proposing a close.

## Change summary

Adding the production iManage MCP server during declarative-agent setup prompts for static OAuth registration instead of completing DCR.

## Best solution

VS Code's MCP OAuth flow should automatically register when the discovered authorization server supports and accepts DCR. Establish whether production fails during metadata discovery or registration, then address the demonstrated client defect or server incompatibility without bypassing metadata validation.
