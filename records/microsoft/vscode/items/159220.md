# Issue #159220 — Support empty workspaces edit sessions

[https://github.com/microsoft/vscode/issues/159220](https://github.com/microsoft/vscode/issues/159220)

## Summary

Empty-workspace Cloud Changes remain unsupported: current source explicitly excludes them and references this issue. Keep this accepted, team-authored Backlog request open; the existing commands and settings do not cover it, and no qualifying canonical was found.

## Change summary

Support storing and restoring edit sessions containing files such as images when no folder or workspace is open.

## Best solution

Extend Cloud Changes to preserve supported file content from empty windows and restore it without requiring an existing workspace folder. First settle how those files are identified and presented on restoration; the current storage and resume contracts are folder-based.

- **Behavior:**

  > The reporter opened insiders.vscode.dev without a workspace, created an image, and could not store that work as an edit session. The desired capability is to preserve and later recover supported file content from such an empty window through Cloud Changes. Acceptance should include a byte-preserving image round trip between empty windows and unchanged behavior for existing folder-backed sessions. Which resource types qualify and how restored files appear remain product decisions.
- **Trace:**

  > EditSessionsContribution.resumeEditSession in src/vs/workbench/contrib/editSessions/browser/editSessions.contribution.ts explicitly returns for WorkbenchState.EMPTY and references https://github.com/microsoft/vscode/issues/159220. Its storeEditSession path enumerates SCM changes and requires an associated workspace folder, so removing the resume restriction alone would not deliver the request. The EditSession contract in src/vs/workbench/contrib/editSessions/common/editSessions.ts stores changes under folders with relative paths; WorkspaceStateSynchronizer.sync in src/vs/workbench/contrib/editSessions/common/workspaceStateSync.ts likewise skips folderless state. Binary file encoding already exists in the store path, but this does not supply discovery or restoration semantics for empty-window resources. Preserve existing folder identity matching and folder-backed behavior, and keep chat-session history out of scope. https://github.com/microsoft/vscode/issues/167524 confirms this capability was separate from its welcome-text correction.
- **Open decisions:**
  - Which empty-window resources should Cloud Changes preserve: untitled editor content, independently opened files, or both, and does the initial scope include binary images?
  - Should resuming an empty-window session reopen its content as untitled resources in an empty window, or require the user to choose a destination folder?
