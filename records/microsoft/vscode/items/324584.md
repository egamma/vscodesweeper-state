# Issue #324584 — Show some tooltip about why the setting can't be edited

[https://github.com/microsoft/vscode/issues/324584](https://github.com/microsoft/vscode/issues/324584)

## Summary

Real, small UX gap confirmed in current code: the grayed-out input control for a policy-managed or Agents-window-readonly setting has no hover explanation of its own — only the small scope-indicator label above it does, and that's easy to miss.

## Change summary

Add a tooltip directly on the disabled setting control explaining why it can't be edited, not just on the small indicator label above it.

## Best solution

In src/vs/workbench/contrib/preferences/browser/settingsTree.ts, wherever a control is disabled via `setEnabled(!dataElement.hasPolicyValue && !dataElement.isAgentsWindowReadOnly)` (InputBox/SelectBox/IncludeExcludeWidget render paths), also attach a hover/title on the control itself reusing the existing `policyDescription` / `agentsWindowReadOnlyDescription` strings from settingsEditorSettingIndicators.ts, so the explanation isn't only discoverable via the separate indicator label.
