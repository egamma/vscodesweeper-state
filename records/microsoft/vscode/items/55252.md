# Issue #55252 — [folding] provide non-selection aware fold level command 

[https://github.com/microsoft/vscode/issues/55252](https://github.com/microsoft/vscode/issues/55252)

## Summary

The requested non-selection-aware fold-level command remains absent on current main. A maintainer previously endorsed parallel commands with clearer labels, and the related implementation PR was closed only for inactivity, so the feature request should remain open.

## Change summary

Provide fold-level commands that can fold every range at a level, including the range containing the current cursor or selection.

## Best solution

Follow the maintainer-reviewed command design from https://github.com/microsoft/vscode/pull/117991: preserve the existing command IDs and keybindings for selection-aware behavior, clarify their labels, and add unbound fold-level commands that include the selected region.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Add focused editor-folding tests that invoke both command variants with the cursor inside a target-level region, then run `./scripts/test.sh --grep "Fold Level"`; the inclusive command must fold that region while the existing command must keep it visible.
- **Behavior:**

  > Users can invoke a fold-level command that folds every region at the requested level, including the region containing the cursor or selection. The existing command IDs and default keybindings retain their selection-aware behavior so user keybindings do not change semantics. Command Palette labels clearly distinguish the selection-aware and inclusive variants, and no default keybinding is added for the new variants.
- **Trace:**

  > FoldLevelAction.invoke in src/vs/editor/contrib/folding/browser/folding.ts always passes getSelectedLines(editor) into setCollapseStateAtLevel. The helper in src/vs/editor/contrib/folding/browser/foldingModel.ts already supports inclusive behavior when its blockedLineNumbers argument is empty, and foldingModel.test.ts covers both empty and populated blocked-line arrays. The maintainer-reviewed design is recorded in https://github.com/microsoft/vscode/pull/117991#issuecomment-802696971; that PR was closed for inactivity rather than rejected. Preserve existing editor.foldLevel1 through editor.foldLevel7 IDs and their keybindings, and do not change Fold All or unrelated folding semantics. The remaining planning work is to identify an action-level test seam that proves command registration, labels, and selection handling rather than merely retesting the model helper.

## Evidence
