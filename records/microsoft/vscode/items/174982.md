# Issue #174982 — No Search Diff editor for Notebooks

[https://github.com/microsoft/vscode/issues/174982](https://github.com/microsoft/vscode/issues/174982)

## Summary

Keep open: notebook search results still bypass Replace Preview, so the requested notebook-aware diff remains missing. The existing search setting does not cover notebooks, and no verified canonical or fixing commit was found.

## Change summary

Provide a replacement-preview diff when selecting notebook search matches, comparable to the preview available for text files.

## Best solution

Extend search replacement previews to show notebook cell changes before applying them, while preserving notebook navigation and excluding read-only rendered content. Establish the notebook preview's presentation contract before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/searchView.ts`, `src/vs/workbench/contrib/search/browser/replaceService.ts`, `src/vs/workbench/contrib/search/browser/notebookSearch/notebookSearchModel.ts`
- **Validation:** With search.useReplacePreview enabled, search an open notebook containing the same term in multiple editable cells, enter replacement text, and select a result. Verify a before/after preview appears without modifying the notebook, follows replacement-text changes, and predicts the subsequently applied edits; verify read-only output matches remain non-replaceable and ordinary text-file previews remain unchanged.
- **Behavior:**

  > Selecting a notebook search result while replacement preview is enabled currently opens the notebook without showing the proposed replacement diff. Users should be able to inspect the notebook cell changes before applying replacements. Previewing must not modify or save notebook content, and read-only rendered/output matches must remain non-replaceable. Ordinary text-file preview behavior must remain unchanged.
- **Trace:**

  > SearchView.shouldOpenInNotebookEditor and SearchView.onFocus in src/vs/workbench/contrib/search/browser/searchView.ts explicitly route notebook matches away from ReplaceService.openReplacePreview. The ordinary preview in src/vs/workbench/contrib/search/browser/replaceService.ts creates an original/modified resource diff and resolves text models, whereas actual notebook replacements target cell URIs through createEdits and save through the notebook model resolver. This establishes that enabling the existing setting or removing the routing exclusion alone does not establish a notebook-aware preview contract. https://github.com/microsoft/vscode/issues/179922 acknowledges the missing surface; https://github.com/microsoft/vscode/issues/174724 supplies the original search/replace workflow. Preserve cell-aware edits, read-only match restrictions, and existing text-file behavior. The unresolved product boundary is whether previewing a selected result presents its cell or the notebook's combined replacement changes.
- **Open decisions:**
  - Should selecting a notebook search match show a focused cell-level replacement diff or a notebook-wide preview of all pending replacements?

## Evidence

- **Current source confirms the gap:** src/vs/workbench/contrib/search/browser/searchView.ts:2224–2236: shouldOpenInNotebookEditor recognizes notebook matches and notebook resources; onFocus explicitly excludes those resources from replaceService.openReplacePreview and calls open instead.
