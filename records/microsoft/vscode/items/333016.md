# Issue #333016 — Agents window: Can only select Copilot models

[https://github.com/microsoft/vscode/issues/333016](https://github.com/microsoft/vscode/issues/333016)

## Summary

Real, still-open gap in the Agents window model picker, but the root cause is unsettled — the reporter says the model list is capped to org-selected Copilot models even when picking Claude, while a commenter reports a related-but-different symptom (BYOK/OpenRouter models registered but never surfacing at all). Neither reproduction is confirmed against current main, and it overlaps a cluster of open BYOK/model-catalog issues without a clear single canonical.

## Change summary

In the Agents window, the model picker only offers models an org has enabled for Copilot, instead of the full set of models available for another selected provider (e.g. Claude/BYOK).

## Best solution

Needs a maintainer decision on whether org Copilot-model policy should scope non-Copilot/BYOK providers at all, then a fix in the agent-host model catalog plumbing (copilotAgent.ts's `_refreshByokModels`/`_publishModels` and the BYOK bridge registry) so BYOK-registered models actually reach the picker.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`
- **Validation:** A confirmed repro (with a real BYOK/Claude provider configured) showing the picker's model list before and after the fix, plus an agent-host test asserting BYOK models registered via the bridge registry appear in the published model list regardless of org Copilot-model policy.
- **Behavior:**

  > When a user selects a non-Copilot provider (e.g. Claude via BYOK) in the Agents window, the model picker should offer the models actually available to that provider/account, not the subset an org has enabled for Copilot. Acceptance: with a BYOK provider configured and enabled, its registered models appear in the picker regardless of the org's Copilot model policy.
- **Trace:**

  > copilotAgent.ts merges `_capiModels` (Copilot's org-governed catalog) with `_byokModels` (populated from `_byokBridgeRegistry.getModels()` in `_refreshByokModels`, gated by the `chat.agentHost.byokModels.enabled` config) in `_publishModels()`. The reporter's complaint suggests Copilot org policy is scoping the whole picker rather than just the Copilot portion; the commenter's report suggests the BYOK merge itself isn't surfacing models even when enabled. Do not touch the CAPI/org-policy path itself — the boundary is scoping/merge logic for non-Copilot model sources. Related: https://github.com/microsoft/vscode/issues/333802, https://github.com/microsoft/vscode/issues/325738, https://github.com/microsoft/vscode/issues/335143.
- **Open decisions:**
  - Should org-configured Copilot model policy ever restrict model choice for a non-Copilot provider (e.g. Claude, BYOK) in the Agents window, or should those providers always show their own full model list?
  - Is the commenter's 'BYOK models registered but never appear in picker' the same defect as the reporter's 'model list capped to Copilot org policy', or a separate bug in the BYOK bridge registry?
