# Issue #336707 — Agent does not change its working directory when asked

[https://github.com/microsoft/vscode/issues/336707](https://github.com/microsoft/vscode/issues/336707)

## Summary

Current main explicitly records this as a known Agent Host defect: workspace-conversion-capable providers omit the `set_workspace` tool from workspaceless sessions. The existing conversion path is implemented, but the agent cannot invoke it, so this team-authored issue should remain open.

## Change summary

A workspaceless agent session ignores an explicit request to change its working directory because the workspace-attachment tool is unavailable to the agent.

## Best solution

Ensure `set_workspace` is advertised to workspaceless Copilot and Codex sessions whenever their provider supports workspace conversion, including after session registration and provider tool materialization. Preserve the existing trust, isolation, confirmation, conversation-history, and continuation behavior.
