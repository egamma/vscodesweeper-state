## Evidence

Its German and subsequently reported AZERTY cases cover the same observable failure as this Nordic-layout report.
- **confirmed reproduction and workaround:** https://github.com/microsoft/vscode/issues/197823#issuecomment-2794889956 confirms number-row AltGr combinations being captured as Alt shortcuts on a Samsung S9 Ultra in stable 1.99.2 and Insiders 1.100.0; keyboard.dispatch=keyCode did not help. https://github.com/microsoft/vscode/issues/197823#issuecomment-3909263079 independently reports that removing Alt+Digit bindings restores character input.
- **maintainer-established consolidation:** https://github.com/microsoft/vscode/issues/271402 reports AltGr+9 switching editor tabs rather than inserting a symbol on Android Chrome in 1.105.0. A maintainer explicitly marked it duplicate of the selected canonical at https://github.com/microsoft/vscode/issues/271402#issuecomment-3563101307.
- **current source boundary:** src/vs/base/browser/keyboardEvent.ts preserves the browser's altKey and reads AltGraph separately. src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts:993 and fallbackKeyboardMapper.ts preserve altKey during resolution; WorkbenchKeybindingService._registerKeyListeners in src/vs/workbench/services/keybinding/browser/keybindingService.ts prevents default input when dispatch handles a shortcut. This is consistent with the canonical's diagnosed interception, but does not independently establish the Samsung browser's current event payload.
- **unique evidence retained:** https://github.com/microsoft/vscode/issues/197826 supplies a Nordic keyboard on Samsung SM-X710, Android 13, Samsung Browser 23 / Chromium 115, and VS Code 1.84.1: AltGr+2 fails to insert @ while AltGr+E inserts €. This adds an affected layout and browser configuration, not evidence of separate remaining work.
