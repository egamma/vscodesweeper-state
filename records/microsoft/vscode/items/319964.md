# Issue #319964 — Restoring Settings from Remote Throws 412 error

[https://github.com/microsoft/vscode/issues/319964](https://github.com/microsoft/vscode/issues/319964)

## Summary

The supplied recording and Settings Sync log confirm that restoring historical data fails with 412 responses, and current main still has an unhandled precondition race in the restore path. This should remain open as a bug and be routed to Settings Sync.

## Change summary

Restoring any historical Settings Sync resource can update local data but fail to restore the remote state when the server reports a concurrent update.

## Best solution

Historical restore should tolerate a concurrent remote update while preserving the selected snapshot as the requested end state, leaving local, remote, and last-synchronized data coherent for settings, UI state, extensions, and the other supported resources.

## Evidence

- **confirmed reproduction:** The attached Settings Sync log records 412 failures for both globalState and settings on 2026-06-05, including a settings failure immediately after `Settings: Updated local settings`; the reporter also supplied a recording of the restore steps.
- **current source path:** src/vs/workbench/contrib/userDataSync/browser/userDataSyncViews.ts invokes IUserDataSyncService.replace for the Restore command, which reaches AbstractSynchroniser.replace in src/vs/platform/userDataSync/common/abstractSynchronizer.ts.
- **unhandled race on main:** AbstractSynchroniser.replace reads the latest remote ref and calls applyResult once with force=false. Resource implementations such as settingsSync.ts and globalStateSync.ts POST with that ref, but replace has no PreconditionFailed retry equivalent to AbstractSynchroniser.performSync, so an intervening auto-sync or another client update propagates the observed 412.
- **existing test precedent:** src/vs/platform/userDataSync/test/common/synchronizer.test.ts already tests that normal synchronization fetches latest data and retries after a simulated 412, but there is no corresponding replace/restore coverage.
