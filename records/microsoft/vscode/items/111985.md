# Issue #111985 — SVG icons look different than codicons

[https://github.com/microsoft/vscode/issues/111985](https://github.com/microsoft/vscode/issues/111985)

## Summary

Keep open: custom SVG action icons still lack an opt-in mechanism to inherit the foreground color like codicons, and the earlier rendering PR was closed because it would recolor existing colored icons. The api-proposal label independently prohibits a cleanup close; the API owners should resolve the compatibility contract.

## Change summary

Allow custom SVG action icons to inherit theme and interaction-state foreground colors so they match neighboring codicons.

## Best solution

Define a backward-compatible, opt-in contract for foreground-following SVG icons and carry it through command contributions and action rendering, preserving existing multicolor icons. Existing ThemeIcon references are an alternative for named glyphs, not a solution for arbitrary SVG assets.

- **previous implementation and compatibility constraint:** https://github.com/microsoft/vscode/pull/111995 is closed and unmerged. Its diff replaced background-image rendering with currentColor-backed SVG masks. https://github.com/microsoft/vscode/pull/111995#issuecomment-742097868 explains that this would break icons using color and requires an API opt-in/out; discussion was explicitly returned to this issue.
- **current rendering path:** Current HEAD, src/vs/platform/actions/browser/menuEntryActionViewItem.ts, MenuEntryActionViewItem._updateItemClass: ThemeIcon entries receive themed CSS classes, whereas URI icons use label.style.backgroundImage with light/dark asset selection. Theme changes refresh that selection, but this path does not make arbitrary SVG fills inherit the surrounding foreground.
- **existing capability check:** src/vs/workbench/services/actions/common/menusExtensionPoint.ts registers command icons as a file path, a light/dark path pair, or a ThemeIcon reference such as $(zap); handleCommand resolves those alternatives. src/vscode-dts/vscode.d.ts documents ThemeIcon as a named-icon reference. These options support themed glyphs or separate image assets, but do not expose foreground-following rendering for an arbitrary supplied SVG.
