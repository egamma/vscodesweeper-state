Team-authored (COLLABORATOR) polish request confirmed in source: the automation blueprint validation error messages (e.g. "The property '{0}' is missing or invalid.") give no pointer to documentation for valid schema values, so keeping this open is correct regardless of the team-authored protection.

## Change summary

When an invalid automation blueprint (e.g. wrong `schedule.kind`) is imported, the resulting error message doesn't link to documentation explaining valid values.

## Best solution

In src/vs/sessions/contrib/sessions/browser/views/automationsView.ts, extend the invalidField/unsupportedSchedule error messages (or the surrounding notification) to include a link to the automation schema documentation once such docs exist; this is a UX polish decision for the sessions/automations area owner.
