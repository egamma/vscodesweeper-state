# Issue #335883 — Error when invalid automation is imported could point to docs

[https://github.com/microsoft/vscode/issues/335883](https://github.com/microsoft/vscode/issues/335883)

## Summary

Confirmed on main: importing a `kind: daily` automation with the old cron-only schema throws a bare 'schedule.kind is missing or invalid' error with no pointer to valid values or docs. This is a team-authored (collaborator) request, so it stays open regardless; the remaining work is picking what to link to and/or listing valid kinds inline.

## Change summary

The automation import error for an invalid `schedule.kind` gives no guidance on valid values or where to find documentation.

## Best solution

Improve `automationBlueprint.invalidField` handling in automationsView.ts / automationBlueprint.ts to either enumerate the valid `schedule.kind` values in the message or link to an automations schema doc, once a doc target is decided.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts`, `src/vs/sessions/contrib/sessions/browser/views/automationsView.ts`
- **Validation:** Once the approach is chosen: a test asserting the rendered error message for an invalid `schedule.kind` includes either the valid kind values or the doc link/URL.
- **Behavior:**

  > Importing an automation with an invalid `schedule.kind` should give the user enough information to fix it — either the set of valid values (e.g. `cron`) or a link to documentation describing the schema. Today it only says the property 'is missing or invalid' with no further guidance.
- **Trace:**

  > AutomationBlueprintParseError('invalidField', 'schedule.kind') is thrown in src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts when `kind !== 'cron'`, and rendered generically by the 'invalidField' case in src/vs/sessions/contrib/sessions/browser/views/automationsView.ts. No existing doc-link mechanism exists in that view to extend. Related: https://github.com/microsoft/vscode/issues/336848 (clarifying which files can be imported as automations) touches the same general onboarding/discoverability gap but is a different symptom, not a duplicate.
- **Open decisions:**
  - Should the error message enumerate the valid `schedule.kind` values inline, link out to a documentation page, or both?
  - If linking to docs, what is the canonical automation schema doc URL to reference?

## Evidence

- **current error:** src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts throws AutomationBlueprintParseError('invalidField', 'schedule.kind') when kind !== 'cron', with no reference to valid values.
- **message rendering:** src/vs/sessions/contrib/sessions/browser/views/automationsView.ts renders this as "The property '{0}' is missing or invalid." with no doc link or enumerated values — confirms the reported behavior on current main.
- **no doc infra found:** No existing 'learn more' / docs URL pattern exists in automationsView.ts to reuse, so a target doc/URL still needs to be decided.
