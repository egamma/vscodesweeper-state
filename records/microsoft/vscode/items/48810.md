# Issue #48810 — Does the watch view support auto completions?

[https://github.com/microsoft/vscode/issues/48810](https://github.com/microsoft/vscode/issues/48810)

## Summary

The requested completion support for watch-expression input remains a real gap, has 33 community upvotes, and is intentionally retained in the Backlog. No older issue with the same observable symptom is identified as a valid canonical for this re-reviewed item.

## Change summary

Provide debugger completions while users type expressions in the Watch view.

## Best solution

Give the Watch expression input editor-like language support and request completions through the active debug session, matching the useful completion behavior already available for Debug Console and conditional-breakpoint expressions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/watchExpressionsView.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`
- **Validation:** Add or extend debugger UI tests to verify that editing a Watch expression requests and displays completions while preserving add, rename, accept, cancel, and evaluation behavior.
- **Behavior:**

  > While adding or editing an expression in the Watch view, users receive context-appropriate completion suggestions from the active debugger, comparable to completion support in other debugger expression inputs. Accepting a suggestion updates the expression without prematurely submitting it; Enter still commits and evaluates the expression, and Escape still cancels editing. Existing Watch operations and behavior for debug adapters without completion support remain unchanged.
- **Trace:**

  > The issue discussion establishes that the Watch expression input is not currently an editor-capable input, while Debug Console and breakpoint-condition flows already offer completion behavior. The likely boundary is the Watch expression editing path in src/vs/workbench/contrib/debug/browser/watchExpressionsView.ts and the existing debugger completion plumbing used by editor/debug contributions. Preserve the Debug Adapter Protocol contract and existing Watch expression add/rename/evaluation semantics. https://github.com/microsoft/vscode/issues/190525 is a newer related item and cannot be the canonical duplicate for this re-reviewed issue; https://github.com/microsoft/vscode/issues/160373 describes a separate breakpoint-completion failure.
- **Open decisions:**
  - Should Watch completion be limited to debugger-provided expression suggestions, or should the input expose the broader editor suggestion experience for the selected stack frame's language?
  - Should completion trigger automatically while typing, only on explicit invocation, or follow the active language's editor suggestion settings?
