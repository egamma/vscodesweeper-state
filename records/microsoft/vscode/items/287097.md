# Issue #287097 — Search does not work in workspaces having names

[https://github.com/microsoft/vscode/issues/287097](https://github.com/microsoft/vscode/issues/287097)

## Summary

The supplied comma-bearing workspace name still fails in the current search parser. An older issue and open PR cover the commenter's parentheses case, but neither covers the reporter's comma-delimited name, so this report remains necessary.

## Change summary

Make Find in Folder correctly scope searches to workspace folders whose descriptive names contain punctuation.

## Best solution

Preserve literal workspace-folder names throughout include-pattern generation and parsing while retaining intentional glob and multiple-pattern syntax. Coordinate the parentheses case with the existing PR and retain this issue for the uncovered comma case.

## Evidence

- **Exact reporter trigger remains broken:** In src/vs/workbench/services/search/common/queryBuilder.ts:690–729, resolveResourcesForSearchIncludes generates ./ followed by the workspace folder's display name; escapeGlobPattern escapes only ?, *, [, and ]. The reporter's name therefore retains both commas. SearchView._searchWithIncludeOrExclude in src/vs/workbench/contrib/search/browser/searchView.ts joins these strings into the include field, and QueryBuilder.parseSearchPaths calls splitGlobPattern, which splits on commas at lines 644–647. The first segment becomes './Mx009 - Project 009'; expandOneSearchPath cannot match that against the full folder name and throws 'Workspace folder does not exist'. This is a source trace, not an executed reproduction.
- **Display names are intentionally supported:** QueryBuilder.expandOneSearchPath matches workspace folder.name and resolves it to folder.uri at src/vs/workbench/services/search/common/queryBuilder.ts:495–513. The existing 'include ./foldername' test in src/vs/workbench/services/search/test/browser/queryBuilder.test.ts:790–815 verifies that an alias different from the physical directory name resolves correctly. The defect is punctuation parsing, not a general assumption that display names are physical paths.
- **Discussion corroborates a second punctuation failure:** The supplied April 21 comment reports that removing parentheses from a workspace name restores searching. Current splitGlobFromPath at src/vs/workbench/services/search/common/queryBuilder.ts:613–635 treats parentheses as glob characters before workspace-name resolution; './foo (bar)' is split into path './' and a glob portion, losing the intended root selection.
- **Older related issue is only partial coverage:** Verified https://github.com/microsoft/vscode/issues/273517 is open and was created on 2025-10-27, before this report. Its reproduction concerns Find in Folder on named workspace roots containing parentheses, producing unscoped results or a missing-folder error. It covers the commenter's symptom, but does not establish ownership of the reporter's separate comma-tokenization failure, so it does not satisfy the full-scope duplicate bar for this re-reviewed item.
- **Related implementation remains open and does not fix commas:** https://github.com/microsoft/vscode/pull/273519 is open and references https://github.com/microsoft/vscode/issues/273517. Its inspected diff moves glob/path splitting relative to workspace-name matching in queryBuilder.ts, but leaves splitGlobPattern's earlier comma splitting unchanged. It is neither a landed fix nor complete coverage of this report.
