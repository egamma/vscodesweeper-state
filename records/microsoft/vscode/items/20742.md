# Issue #20742 — Allow to create multi-cursor with keyboard

[https://github.com/microsoft/vscode/issues/20742](https://github.com/microsoft/vscode/issues/20742)

## Summary

Keep this accepted, reopened request open: built-in commands still do not support freely navigating one cursor while retaining and selectively toggling other cursor positions. The extension workaround is useful, but does not complete the built-in request; a maintainer has also explicitly consolidated a related report here.

## Change summary

Provide keyboard-only placement and removal of arbitrary cursors without moving the other cursors, including after multi-cursor editing.

## Best solution

Design an accessible keyboard mark-and-move workflow in the editor that preserves existing multi-cursor commands and supports selectively changing the cursor set after editing. Use the demonstrated extension workflow as design evidence, not as proof that the accepted core request is complete.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/multicursor/browser/multicursor.ts`, `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/contrib/multicursor/test/browser/multicursor.test.ts`, `src/vs/editor/test/browser/controller/cursorMoveCommand.test.ts`
- **Validation:** The plan should culminate in automated editor tests and a keyboard-only acceptance check: mark three nonadjacent positions using arrow navigation, edit at all three, then remove one and add another without moving the remaining positions. Existing insert-cursor-above/below, ordinary multi-cursor movement, and mouse cursor toggling must remain unchanged.
- **Behavior:**

  > Users can navigate with the keyboard and mark arbitrary cursor positions without moving previously marked positions. They can activate the collected cursors for editing, then selectively remove or add a cursor using keyboard navigation while retaining the other positions. Acceptance must cover nonadjacent lines and columns, continued editing after changing the cursor set, and preservation of existing multi-cursor interactions.
- **Trace:**

  > InsertCursorAbove and InsertCursorBelow in src/vs/editor/contrib/multicursor/browser/multicursor.ts add vertical cursors from existing states; CursorMoveImpl and CursorMoveBasedCommand in src/vs/editor/browser/coreCommands.ts move the entire cursor set. CreateCursor in that file can toggle an explicitly supplied position but requires args.position and provides no parked-cursor navigation lifecycle. Source inspection establishes the capability gap, not a bounded defect in those commands. The design trace stops at how independently retained positions participate in editor movement, document edits, and selection lifecycle; those consumers have not been exhaustively traced. Preserve existing command semantics and mouse behavior. The extension discussion at https://github.com/srares13/keyboard-cursors-and-selections/issues/7 supplies workflow evidence, while https://github.com/microsoft/vscode/issues/201466#issuecomment-3645901727 identifies this issue as the tracking destination.

## Evidence

- **Existing commands do not cover the request:** src/vs/editor/contrib/multicursor/browser/multicursor.ts:46-147 registers editor.action.insertCursorAbove and editor.action.insertCursorBelow, which add cursors vertically from the existing cursor states. In src/vs/editor/browser/coreCommands.ts:589-690, cursorMove and ordinary arrow movement operate on all cursor states, rather than independently navigating one cursor while parking the others.
- **createCursor is not a keyboard marking mode:** src/vs/editor/browser/coreCommands.ts:892-953 registers createCursor, requires args.position, and returns without one. Its explicit-position add/remove behavior does not supply independent keyboard navigation or inactive cursor markers. The multiCursor settings in src/vs/editor/common/config/editorOptions.ts cover modifier, overlap merging, paste, and cursor limits, not a mark-and-move mode.
- **Discussion establishes the full requirement and workaround:** In https://github.com/microsoft/vscode/issues/20742, comments 12-13 establish that initial cursor collection alone is insufficient: users also need to add or remove an individual cursor after editing without moving the others. Comments 20-25 identify srares13.kcs as a working extension alternative. https://github.com/srares13/keyboard-cursors-and-selections/issues/7#issuecomment-2058997136 explicitly explains how its inactive selections support those requirements.
- **Maintainer identifies this issue as the tracking destination:** https://github.com/microsoft/vscode/issues/201466 is closed, and https://github.com/microsoft/vscode/issues/201466#issuecomment-3645901727 says to track its createCursor keyboard concern in https://github.com/microsoft/vscode/issues/20742. This supports retaining this issue rather than treating the closed related report as a canonical or a fix.
