# Issue #330239 — github.copilot.git.repository not populated for self-hosted GitHub Enterprise Server remotes with custom domains

[https://github.com/microsoft/vscode/issues/330239](https://github.com/microsoft/vscode/issues/330239)

## Summary

Confirmed on current main: `getGithubRepoIdFromFetchUrl` only recognizes `github.com`/`*.ghe.com`, so `getOrderedRepoInfosFromContext` yields nothing for a custom-domain GHES remote and `remoteUrl` (hence `github.copilot.git.repository`) is silently dropped, exactly as reported. An open PR already fixes this and cites the issue, so it stays open pending review/merge rather than being closed.

## Change summary

`github.copilot.git.repository` (and legacy `copilot_chat.repo.remote_url`) is never populated for self-hosted GitHub Enterprise Server remotes on custom domains, because the OTel repo-URL resolver gates on a `github.com`/`ghe.com` host allowlist.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/330284, which reworks `workspaceOTelMetadata.ts`/`gitService.ts` to emit a host-agnostic `remoteUrl` for OTel (keeping the existing GitHub/ADO-only `repoId` resolution untouched for API-facing consumers) and adds 20 tests covering GHES, GitLab, Bitbucket Server, and loopback/local-path exclusions; the PR itself documents that `github.copilot.github.org` will remain unset for custom-domain GHES (no `github-enterprise.uri` plumbing), which matches the reporter's stated tolerance in their follow-up comment.

## Evidence

- **root cause on main:** extensions/copilot/src/platform/git/common/gitService.ts:244-265 `getGithubRepoIdFromFetchUrl` hard-gates on `const topLevelUrls = ['github.com', 'ghe.com']`; `getOrderedRepoInfosFromContext` (lines 115-122) only yields a remote when this or the ADO resolver matches, so a custom GHES host yields nothing.
- **downstream effect:** extensions/copilot/src/platform/otel/common/workspaceOTelMetadata.ts `buildWorkspaceMetadata` sets `remoteUrl` only from that (empty) `repoInfo`, while `headBranchName`/`headCommitHash` are read directly off `repoContext` with no host check — matching the branch/commit-vs-repository asymmetry described in the issue.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/330284 ("fix: populate OTel repository attributes for non-GitHub git remotes") is open, contains `Fixes #330239`, and reworks the same two files to add a host-agnostic fallback `remoteUrl` while leaving `repoId` resolution (GitHub API/PR/coding-agent call sites) untouched.
- **reporter follow-up:** The reporter's only comment flags that `github.copilot.github.org` may still be unpopulated after the PR for custom GHES — the PR body explicitly acknowledges and accepts this as out of scope, and the reporter already said that's acceptable.
