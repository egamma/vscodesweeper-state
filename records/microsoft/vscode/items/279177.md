# Issue #279177 — Possible memory leak in debounce

[https://github.com/microsoft/vscode/issues/279177](https://github.com/microsoft/vscode/issues/279177)

## Summary

Still reproduces on main: the `debounce` decorator in `src/vs/base/common/decorators.ts` never clears the pending `setTimeout` or stored result on disposal, so disposed objects using `@debounce` (like `ChildProcessMonitor`) retain references and leak. No fix has landed.

## Change summary

The `debounce` decorator stores intermediate results and timers on `this` without clearing them on disposal, causing memory leaks for Disposable classes that use it.

## Best solution

The decorator should clear `this[timerKey]` and `this[resultKey]` when the host object is disposed. Since `ChildProcessMonitor` and many other consumers extend `Disposable`, a disposal hook (or switching callers to a disposable-aware debounce utility like `Debouncer`) would fix the leak. Alternatively, each `@debounce` call site could register its own cleanup — but a decorator-level fix in `src/vs/base/common/decorators.ts` is cleaner.
