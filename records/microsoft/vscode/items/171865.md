# Issue #171865 — Line scrolling stops at folded regions

[https://github.com/microsoft/vscode/issues/171865](https://github.com/microsoft/vscode/issues/171865)

## Summary

The folded-region scrolling blocker remains in current source, and an open PR explicitly addresses it. Keep this issue open while that implementation candidate is reviewed.

## Change summary

Downward editorScroll commands using by: "line" stop advancing when the viewport reaches a collapsed region.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/322302 once its handling of folded regions, end-of-file folds, and revealCursor behavior is satisfactory, preserving model-line scrolling semantics rather than requiring the wrappedLine workaround.

## Evidence

- **Current source confirms the blocker:** src/vs/editor/browser/coreCommands.ts:1375-1393, EditorScrollImpl._computeDesiredScrollTop, adds the requested model-line count to the first visible model line, then converts the target with the default convertModelPositionToViewPosition mapping. When that target falls inside a collapsed region whose header is at the viewport top, it resolves back to that header, so repeated downward commands compute the same scroll offset.
- **Hidden-line mapping:** src/vs/editor/common/viewModel/viewModelLines.ts:859-895 defaults belowHiddenRanges to false and walks backward from hidden model lines to a visible line. This directly explains the reporter's editorScroll trigger; the scroll calculation does not request forward mapping.
- **Independent confirmation and workaround:** The supplied discussion at https://github.com/microsoft/vscode/issues/171865 includes confirmation on VS Code 1.79.2 with all extensions disabled, successful scrollLineDown behavior, and a by: "wrappedLine" workaround subsequently confirmed by another commenter. Current coreCommands.ts handles wrappedLine through a pixel delta, unlike the model-line conversion used for line; that workaround does not repair the requested command behavior.
- **Open implementation candidate:** GitHub inspection verified https://github.com/microsoft/vscode/pull/322302 is OPEN with mergedAt null and explicitly says Fixes #171865. Its description identifies the same hidden-line mapping defect and proposes forward resolution for downward targets, with an end-of-file guard. It is not a landed fix and precludes a competing agent implementation.
- **Canonical search:** An open-issue search for scroll folded returned this issue and reports of distinct symptoms, with no verified older canonical owning the same keyboard-scroll blocker. https://github.com/microsoft/vscode/issues/299125 is closed after an unanswered information request and describes touchpad scrolling in both directions, not this command-specific folded-region defect; it is not a duplicate target.
