# Issue #156842 — Restarting a Debug Adapter doesn't reset the Visual Studio Interface

[https://github.com/microsoft/vscode/issues/156842](https://github.com/microsoft/vscode/issues/156842)

## Summary

The confirmed bug remains present on current main: adapter-managed restart sends the DAP request but does not invalidate the previous threads, call stacks, or variable state. The existing `bug` and `debug` labels route it correctly, so it should remain open.

## Change summary

A successful DAP `restart` request leaves the Variables and Call Stack views populated with state from the previous debuggee.

## Best solution

Treat a successful adapter-managed restart as an execution-state transition: invalidate the old thread and stack-frame model so Variables and Call Stack clear, then allow subsequent adapter events to populate the restarted process.
