# Issue #72630 — Yank back killed text `ctrl+y` stopped working

[https://github.com/microsoft/vscode/issues/72630](https://github.com/microsoft/vscode/issues/72630)

## Summary

The missing macOS Ctrl+K/Ctrl+Y kill-and-yank behavior is already covered by the older, open issue https://github.com/microsoft/vscode/issues/3684. Its discussion explicitly includes restoring killed text with Ctrl+Y and preserving a separate kill buffer, satisfying the stronger duplicate bar for this re-reviewed item.

## Change summary

Support macOS-style Ctrl+Y restoration of text removed with Ctrl+K in the editor.

## Best solution

Consolidate the kill-and-yank work under https://github.com/microsoft/vscode/issues/3684, preserving this report's requirement that a kill buffer is distinct from ordinary clipboard paste and its Better Kill Ring workaround.

## Evidence

- **Verified older open canonical:** Read the complete body and discussion of https://github.com/microsoft/vscode/issues/3684 using gh issue view. It is currently OPEN and was created on 2016-03-03, before this report's 2019-04-20 creation.
- **Same observable symptom:** https://github.com/microsoft/vscode/issues/3684#issuecomment-217449273 explicitly describes macOS Ctrl+K placing text in a kill ring and Ctrl+Y pasting it back, contrasting this with VS Code's behavior. https://github.com/microsoft/vscode/issues/3684#issuecomment-268929996 further describes Ctrl+K deleting rather than retaining recoverable text. This is the same editor kill-and-yank failure, not merely a related keyboard-shortcut request.
- **Canonical includes separate-buffer requirement:** Although the canonical title mentions the clipboard, https://github.com/microsoft/vscode/issues/3684#issuecomment-505197759 explicitly requests a buffer-local kill ring so killing and yanking do not overwrite the system clipboard. Its discussion therefore covers the distinction raised by partap in this report, rather than owning only a clipboard-cut subset.
- **Current built-in behavior:** src/vs/editor/contrib/linesOperations/browser/linesOperations.ts:830-841 binds macOS Ctrl+K to deleteAllRight. The shared deletion path at lines 735-741 replaces the selected ranges with empty text and executes the edits without retaining their contents in a kill buffer. Searches of the editor and code-editor contributions found no yank or kill-ring implementation; ordinary editor.action.clipboardPasteAction in src/vs/editor/contrib/clipboard/browser/clipboard.ts is not separate-buffer yank.
- **Discussion and workaround:** The supplied discussion records rebornix explaining that Ctrl+Y was not bound, users distinguishing yank from clipboard paste, and an extension workaround at https://marketplace.visualstudio.com/items?itemName=wdawson.better-kill-ring acknowledged positively by another commenter. This supports a missing capability, not an established built-in regression or evidence that an extension caused the problem.
