## Evidence

- **Same observable symptom:** https://github.com/microsoft/vscode/issues/3684#issuecomment-217449273 explicitly describes macOS Ctrl+K saving text to a kill ring and Ctrl+Y pasting it back, explaining that VS Code needs this behavior. https://github.com/microsoft/vscode/issues/3684#issuecomment-474645191 also reports being unable to paste the supposedly cut text. This meets the re-reviewed-item requirement of an older canonical describing the same observable failure.
- **Canonical covers separate-buffer semantics:** https://github.com/microsoft/vscode/issues/3684#issuecomment-505197759 explicitly requests a buffer-local kill ring rather than the system clipboard. The canonical discussion therefore covers this report's distinction between yank and ordinary paste, not merely a narrower clipboard-cut request.
- **Existing capability does not satisfy request:** In src/vs/editor/contrib/linesOperations/browser/linesOperations.ts, DeleteAllRightAction binds macOS Ctrl+K to deleteAllRight; AbstractDeleteAllToBoundaryAction replaces the deleted ranges with empty strings without saving them to a kill buffer. In src/vs/editor/contrib/clipboard/browser/clipboard.ts, editor.action.clipboardPasteAction binds ordinary paste to Cmd+V. These built-in commands do not provide the requested kill-and-yank pair.
- **Workarounds and ownership:** https://github.com/microsoft/vscode/issues/72630#issuecomment-923873331 confirms Ctrl+K is bound to Delete All Right and supplies a macro workaround. https://github.com/microsoft/vscode/issues/72630#issuecomment-1317715761 identifies the wdawson.better-kill-ring extension, welcomed in the following comment. These are workarounds, not evidence that an extension caused the missing built-in behavior.
