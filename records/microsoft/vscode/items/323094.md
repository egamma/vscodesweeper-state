# Issue #323094 — AGENTS.md discovery still runs `rg --no-ignore --follow` over the whole tree (regression sibling of #304676)

[https://github.com/microsoft/vscode/issues/323094](https://github.com/microsoft/vscode/issues/323094)

## Summary

The expensive search path remains on current main when the opt-in nested AGENTS.md setting is enabled: it uses the legacy `workspace.findFiles` API, which disables local ignore files by default and follows the user's symlink setting. The feature is off by default, as the maintainer noted, but enabling it can still trigger the reported pnpm traversal pathology.

## Change summary

Nested AGENTS.md discovery can repeatedly traverse ignored dependency trees and followed symlinks, causing extreme CPU usage in large pnpm workspaces.

## Best solution

Keep nested AGENTS.md discovery opt-in, but define search semantics that avoid unbounded dependency and symlink traversal while preserving intentional nested instruction discovery; the implementation should use the newer file-search API with explicit ignore and symlink behavior and ensure refreshes do not overlap.

Root-level AGENTS.md behavior remains unchanged.
- **Trace:**

  > `AgentInstructionsLocator.listNestedAgentMDs` in `extensions/copilot/src/platform/promptFiles/vscode-node/agentInstructionsLocator.ts` gates discovery on both AGENTS.md settings and then calls legacy `vscode.workspace.findFiles('**/AGENTS.md', undefined, ...)`. In `src/vs/workbench/api/common/extHostWorkspace.ts`, that legacy API disables local ignore files by default, while `src/vs/workbench/services/search/common/queryBuilder.ts` inherits `search.followSymlinks`; together these produce the reported expensive search. The newer https://github.com/microsoft/vscode/issues/328122 has a different `**/*` command signature and is not a canonical duplicate. Keep the scope to nested AGENTS.md discovery: do not alter root instruction discovery or general workspace-search defaults.
- **Open decisions:**
  - Should nested AGENTS.md discovery always honor local ignore files, or must it retain a documented way to discover instructions inside ignored directories?
  - Should nested discovery categorically avoid following symlinks, or should workspace symlink settings remain observable for explicitly linked source trees?
  - Should concurrent refresh requests share one in-flight discovery result, or is cancellation plus a short cache the intended user-visible refresh behavior?
