# Issue #330280 — Agents window: Remote workspace folders cannot be attached as chat context

[https://github.com/microsoft/vscode/issues/330280](https://github.com/microsoft/vscode/issues/330280)

## Summary

Detailed, well-diagnosed report: folder context attachment (drag-and-drop and the Files & Folders picker) fails specifically for remote workspaces opened in the standalone Agents window, confirmed independently across both Remote-WSL and Remote Tunnels topologies with trace logs; individual files work fine, only folders fail. Worth routing to the Agents window/chat-context owners rather than closing.

## Change summary

In the standalone Agents window, folders from a remote (WSL or Tunnels) workspace cannot be attached as chat context via drag-and-drop or the Files & Folders picker, while individual remote files attach successfully.

## Best solution

Have the Agents window/chat-attachment owners trace why folder attachment diverges from file attachment for remote (agent-host) resources — the WSL trace shows a resourceResolve call against a bare file:// URI instead of the expected vscode-agent-host:// scheme, and the Tunnels trace shows no resolve request is even emitted for folder drags, suggesting the drag/picker code path treats directories differently (and possibly incorrectly derives/loses the remote scheme) before resource resolution begins.
