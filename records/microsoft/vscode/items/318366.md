# Issue #318366 — "Open Recent" / "Select to open" (CTRL+R) shows incorrect results - it doesn't consider the file/dir title

[https://github.com/microsoft/vscode/issues/318366](https://github.com/microsoft/vscode/issues/318366)

## Summary

The reported ordering remains in current source, but it follows an explicitly chosen recency-preserving behavior rather than a broken comparator. Keep this open for a decision on prioritizing name matches without losing the recent picker's grouping and recency guarantees.

## Change summary

Prioritize folder, workspace, and file name matches over matches found only in their parent paths when filtering Open Recent.

## Best solution

Agree on a filtered-history ranking contract that gives meaningful name matches priority while retaining folders/workspaces versus files grouping and predictable recency within equivalent matches. Reconcile that contract with the contrasting recency-first expectation in https://github.com/microsoft/vscode/issues/247164 before changing shared picker behavior.
