# Issue #218229 — SCM Graph - high contract line types

[https://github.com/microsoft/vscode/issues/218229](https://github.com/microsoft/vscode/issues/218229)

## Summary

Keep open: current graph rendering still lacks non-color distinctions between ordinary swimlanes, and reference badges do not identify the branch associated with every historical commit. The older high-contrast issue overlaps with stroke patterns but does not own this report's full branch-identification request.

## Change summary

Make SCM graph lanes distinguishable without relying on color and provide meaningful branch or reference context for historical commits.

## Best solution

Design a consistent non-color lane-identification mechanism in the SCM graph, coordinated with the high-contrast work. Define what branch context can reliably be presented without implying that Git records a commit's original branch.

- **Behavior:**

  > Users should be able to distinguish SCM graph ancestry lanes without relying exclusively on color. The report also asks for understandable branch context when inspecting a historical commit that has no branch badge. Acceptance should cover a multi-branch graph with merges, high-contrast presentation, and commits reachable from multiple references. Any displayed context must accurately describe available reference or ancestry information rather than inventing an original branch.
- **Trace:**

  > Ordinary ancestry edges are rendered by renderSCMHistoryItemGraph through createPath and drawVerticalLine in src/vs/workbench/contrib/scm/browser/scmHistory.ts; these paths currently encode color but no lane-specific pattern. The dashed circle is specific to incoming/outgoing markers and does not satisfy this request. ISCMHistoryItemGraphNode in src/vs/workbench/contrib/scm/common/history.ts carries id and color, while optional history-item references support badges and hover labels in scmHistoryViewPane.ts and toHistoryItemHoverContent. The existing data does not establish a commit's original branch, and the row accessibility label contains only message and author. Coordinate the stroke-design discussion with https://github.com/microsoft/vscode/issues/218227 without assuming it owns the branch-context requirement. Preserve ancestry topology, existing reference filtering, and the meaning of incoming/outgoing markers; uncertainty begins at the user-visible lane identity and branch-context semantics.
- **Open decisions:**
  - Should non-color lane distinctions be available in every theme or only high-contrast presentation, and what user-visible identity should remain stable as lanes shift through merges?
  - For commits without a reference badge, should branch context describe containing references, graph ancestry association, or another explicitly defined concept, and how should ambiguity between multiple branches be presented?
