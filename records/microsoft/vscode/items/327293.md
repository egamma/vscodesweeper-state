# Issue #327293 — Notebook editor shows stale cell source during Copilot notebook edits

[https://github.com/microsoft/vscode/issues/327293](https://github.com/microsoft/vscode/issues/327293)

## Summary

Keep open for a focused notebook synchronization investigation. The supplied steps and notebook suffice to retest against current main, but source inspection does not establish where the reported 1.130.0 flow fails or demonstrate a subsequent fix.

## Change summary

An open notebook can display stale cell source after Copilot edits or an external .ipynb rewrite, requiring reopening to synchronize.

## Best solution

Ensure successful notebook edits reach the open cell model and execution uses the displayed source; external changes to a clean notebook should refresh it without reopening. Diagnose dirty-state and file-change delivery first, preserving unsaved edits rather than unconditionally replacing them with disk content.
