# Issue #242328 — CustomTextEditor does not support the isReadonly flag and icon (small lock)

[https://github.com/microsoft/vscode/issues/242328](https://github.com/microsoft/vscode/issues/242328)

## Summary

Valid feature request from a team member. The CustomDocument API still lacks an isReadonly flag on current main — a partial readonly-capability plumbing attempt was reverted in June 2026 (44189f93340), confirming this gap remains open.

## Change summary

Allow CustomEditorProvider to dynamically set/unset a readonly flag on CustomDocument, showing the lock icon and toggling editability at runtime.

## Best solution

Add an `isReadonly` property (or an `onDidChangeReadonly` event) to the CustomDocument API surface so that CustomEditorProvider can dynamically toggle read-only state, including the tab lock icon. The plumbing reverted in commit 44189f93340 is a starting point — the review feedback that caused the revert should guide a second attempt. Likely touches: `src/vs/workbench/api/common/extHostCustomEditors.ts`, `src/vs/workbench/api/browser/mainThreadCustomEditors.ts`, `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts`, and the `vscode.d.ts` API surface.
