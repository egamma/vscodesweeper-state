# Issue #338156 — Terminal throughput is limited by the flow control window and 5 ms output batching

[https://github.com/microsoft/vscode/issues/338156](https://github.com/microsoft/vscode/issues/338156)

## Summary

Well-diagnosed performance proposal confirmed against current main: the 5 ms trailing-edge buffer timer and 100,000-char HighWatermarkChars are unchanged, so the reported throughput ceiling still applies. The reporter's own two proposed changes trade off differently for local vs. shared/remote connections, which is a maintainer decision, not an agent one.

## Change summary

Local terminal bulk output throughput is capped by a 5 ms trailing-edge buffer flush and a 100,000-char flow-control watermark in the pty host, well below what the renderer/pty host could otherwise sustain.

## Best solution

A maintainer should decide whether to adopt a leading-edge flush in TerminalDataBufferer and/or raise HighWatermarkChars (possibly scoped to local-only terminals, since the watermark's comment notes the remote connection is shared infrastructure) — the reporter's vtebench measurements make a strong case but the remote tradeoff needs explicit sign-off.
