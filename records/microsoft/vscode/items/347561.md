# Issue #347561 — Remote-SSH eagerly downloads a newer Agent Host Server before reusing the installed editor Server

[https://github.com/microsoft/vscode/issues/347561](https://github.com/microsoft/vscode/issues/347561)

## Summary

The startup dependency remains in current source: ordinary remote editing awaits supervisor readiness, which first awaits a channel-latest server download. Keep this open for the eager-provisioning behavior, distinct from the related timeout and disabled-AI reports.

## Change summary

Opening an ordinary Remote-SSH workspace requires preparing a newer Agent Host Server before checking the installed, client-matching editor server.

## Best solution

Allow the installed, client-matching editor server to open the workspace independently of channel-latest Agent Host Server preparation. Preserve agent connectivity without making its download a prerequisite for ordinary editing.

## Plan brief

- **Likely files:** `cli/src/commands/agent_host.rs`, `cli/src/commands/tunnels.rs`, `cli/src/tunnels/control_server.rs`, `cli/src/tunnels/agent_host.rs`
- **Validation:** With a matching editor server installed, no running supervisor, and the channel-latest Agent Host Server absent, stall its download and reconnect using remote.SSH.useExecServer. Verify the workspace opens without waiting for that download or the supervisor timeout, then verify agent connectivity still works when preparation can complete.
- **Behavior:**

  > An ordinary Remote-SSH workspace must open using its installed, client-matching editor server without waiting for a newer Agent Host Server to download. This must also hold when that download stalls or fails and no agent session has been requested. Subsequent agent use must remain functional, and editor-server version matching must remain unchanged.
- **Trace:**

  > command_shell in cli/src/commands/tunnels.rs supplies a shared ensure_supervisor_running future. handle_serve in cli/src/tunnels/control_server.rs awaits that future to populate agentHostProxy before checking or starting the editor server. run_supervisor in cli/src/commands/agent_host.rs awaits channel-latest resolution and download before binding its sidecar and signaling readiness; AgentHostManager::get_latest_release in cli/src/tunnels/agent_host.rs selects channel-latest independently of the editor commit. The source establishes the dependency, but the lifecycle contract for making the bridge available independently of backend preparation still needs design and regression validation. Preserve explicit agent-host startup, subsequent agent connections, and editor commit selection. Related but narrower reports are https://github.com/microsoft/vscode/issues/346518 and https://github.com/microsoft/vscode/issues/328397.
