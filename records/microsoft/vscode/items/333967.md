# Issue #333967 — Cannot drag and drop a session from a custom group back to its workspace group

[https://github.com/microsoft/vscode/issues/333967](https://github.com/microsoft/vscode/issues/333967)

## Summary

Real gap confirmed in source: the Sessions list drag-and-drop controller has resolvers for pinning and for adding a session to a custom group, but none for the reverse move (dropping a grouped session back onto its workspace section), so that drop silently does nothing.

## Change summary

Dragging a session that was moved into a custom group back onto its original workspace-grouped section does not move it back (drop is rejected/no-op).

## Best solution

In src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, add a drop-target resolver (alongside `resolveAddToGroupTarget`/`resolvePinTarget`, ~line 2097) that recognizes a grouped session being dropped on its workspace section header or on an already-ungrouped session in that section, and wires it to a new delegate call that mirrors the existing `sessions.removeFromGroup` context-menu action (`this._sessionGroupsService.removeFromGroup(session.sessionId)`, ~line 3798-3802); also relax `canReorderOnto` (~line 3462) so a grouped session can reorder onto an ungrouped workspace-section target when that's the intended drop.

## Evidence

- **no reverse-move resolver:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts defines `resolvePinTarget` (line 2064) and `resolveAddToGroupTarget` (line 2097) for moving sessions into a section, but no symmetric resolver exists for dropping a grouped session back onto its workspace section — `onDragOver`/`drop` (lines 1976-2044) fall through to `resolveReorderTarget`, which only matches `isSessionItem` targets.
- **reorder blocked across group boundary:** `canReorderOnto` (line 3462) requires `getGroupOfSession(dragged) === getGroupOfSession(target)`, so dropping a grouped session onto a workspace-only (ungrouped) session also fails, blocking the only other plausible drop path back to the workspace section.
- **existing non-drag path:** A working equivalent already exists via context menu: `sessions.removeFromGroup` action calls `this._sessionGroupsService.removeFromGroup(session.sessionId)` (line ~3798-3802), confirming the underlying service operation exists — only the drag-and-drop wiring is missing.
