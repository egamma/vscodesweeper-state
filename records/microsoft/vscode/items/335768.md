# Issue #335768 — Want PR form info to be preserved if I click out of focus

[https://github.com/microsoft/vscode/issues/335768](https://github.com/microsoft/vscode/issues/335768)

## Summary

Real, well-scoped UX request confirmed in code: clicking outside the Create PR form fully disposes the widget, so the AI-generated title/description and the user's edit are lost on reopen. Team-authored and brand new, so it stays open for a maintainer/product decision on how to preserve state.

## Change summary

When the Create Pull Request form loses focus (without explicit Cancel), the generated title/description and any user edits should be preserved instead of discarded.

## Best solution

In src/vs/sessions/contrib/changes/browser/createPullRequestContextView.ts, the click-outside path in `onDOMEvent` calls `this.close()`, which clears `this.view` and disposes the `CreatePullRequestWidget` (and its `titleInput`/`descriptionInput`) entirely; a fresh widget with no memory of prior state is built on next `show()`. The fix likely needs to cache the last title/description (and `titleEdited`/`descriptionEdited` flags) at the `CreatePullRequestContextView` level and re-seed a new widget's `initialDraft`/inputs from that cache when reopened for the same creation, distinguishing an implicit blur-close from an explicit Cancel.
