# Issue #330028 — Chat sticky scroll: Keybinding not working?

[https://github.com/microsoft/vscode/issues/330028](https://github.com/microsoft/vscode/issues/330028)

## Summary

Real accessibility gap: the newly-added prompt navigation commands are bound to Ctrl+Alt+Down/Up (src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts, lines 23/44), which collides with Windows Narrator's built-in scan-mode table/grid navigation gesture — Narrator intercepts the keystroke and reports "Not on table" instead of the keypress ever reaching VS Code's command.

## Change summary

With Windows Narrator on, invoking the announced Next/Previous User Prompt keybindings (Ctrl+Alt+Down/Up) does not navigate prompts.

## Best solution

Reassign the Next/Previous User Prompt default keybindings in chatPromptNavigationActions.ts to a combination that doesn't collide with Narrator's (and likely other screen readers') reserved table/grid navigation gestures, similar to the F7 scoping fix pattern already used elsewhere in chat accessibility code.

## Evidence

- **keybinding source:** src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts lines 20-27 and 41-48 register workbench.action.chat.nextUserPrompt / previousUserPrompt with primary Ctrl+Alt+DownArrow / Ctrl+Alt+UpArrow, when: ChatContextKeys.inChatSession.
- **context key scoping looks correct:** ChatContextKeys.inChatSession is bound true on the widget's scoped context key service (chatWidget.ts:533), so the command's `when` clause should be satisfied while focus is in the chat widget — the failure is not an obviously wrong `when` clause in the source.
- **known OS/screen-reader conflict:** Windows Narrator uses Ctrl+Alt+Arrow as its own scan-mode table/grid column navigation gesture; when Narrator intercepts the keystroke at the OS/UIA level before it reaches the renderer, VS Code's registered keybinding never fires — matching the reporter's exact symptom ("Not on table") and the precedent noted in this repo's accessibility guidance about scoping keybindings to avoid stealing/being stolen by common shortcuts (e.g. the F7 conflict fixed in PR #293163).
- **reporter:** bamurtaugh (MEMBER) directly tested with Windows Narrator enabled per the accessibility help text and reported the specific failure while validating the newly landed prompt-navigation feature (test issue https://github.com/microsoft/vscode/issues/329727).
