# Issue #262767 — UX to delegate specific TODOs to coding agent

[https://github.com/microsoft/vscode/issues/262767](https://github.com/microsoft/vscode/issues/262767)

## Summary

Per-item delegation remains missing from the chat TODO widget. Keep this accepted, team-authored request open for a planning-mode design decision; the verified related requests are newer and do not qualify as duplicate canonicals.

## Change summary

Provide an affordance on individual agent-generated TODOs to delegate their work to a coding agent without manually composing a prompt.

## Best solution

Provide a planning-oriented, accessible per-TODO delegation experience that carries enough conversation context to scope the selected task correctly. Settle the confirmation and task-scope contract before wiring it into the existing chat delegation flow.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatTodoListWidget.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts`, `src/vs/workbench/contrib/chat/common/tools/chatTodoListService.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatTodoListWidget.test.ts`
- **Validation:** After the interaction contract is chosen, add targeted chatTodoListWidget tests for per-item action visibility and the selected-task payload. Manually generate several TODOs in a planning conversation, invoke delegation for one using both pointer and keyboard, and verify that the resulting prompt/context identifies that item, follows the chosen confirmation behavior, and does not request implementation of unrelated TODOs.
- **Behavior:**

  > Users should be able to initiate delegation of a specific agent-generated TODO directly from its chat-list entry rather than typing the item into a separate prompt. The delegated request must identify the selected work and retain enough planning context to make it actionable. The affordance must be keyboard accessible and respect the agreed planning-mode visibility and confirmation contract. Acceptance includes selecting one item from a multi-item plan without unintentionally requesting implementation of the entire list.
- **Trace:**

  > TodoListRenderer and ChatTodoListWidget in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatTodoListWidget.ts render title/status rows and list-level expansion and clearing, with no per-item delegation path. IChatTodo in src/vs/workbench/contrib/chat/common/tools/chatTodoListService.ts stores only id, title, and status, so the selected row alone is not a complete work brief. CreateRemoteAgentJobAction.run in src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts already gathers the input prompt, attached context, and conversation history for session handoffs, but does not select a TODO. The discussion at https://github.com/microsoft/vscode/issues/262767 favors planning integration and raises insufficient item context; uncertainty starts at the user-visible scope and confirmation contract. Preserve existing whole-session delegation and TODO status/clear semantics; nested TODO editing and bulk multi-agent orchestration are separate requests, including https://github.com/microsoft/vscode/issues/282818.
- **Open decisions:**
  - Should the per-item action be available only during planning, as suggested in the discussion, or also on TODO lists generated during active implementation?
  - Should invoking delegation prepare an editable prompt for user confirmation or immediately create a coding-agent request?
  - Should delegation request only the selected TODO, or allow the receiving agent to include prerequisite work from the surrounding plan?
