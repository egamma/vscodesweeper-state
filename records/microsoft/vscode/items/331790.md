# Issue #331790 — Copilot edit tools report success even when the underlying FileSystemProvider.writeFile fails

[https://github.com/microsoft/vscode/issues/331790](https://github.com/microsoft/vscode/issues/331790)

## Summary

Verified in source: the internal edit tool (vscode_editFile_internal) and the chat-editing save path never check whether the underlying save actually succeeded before reporting the edit as done, so a FileSystemProvider.writeFile rejection is silently swallowed for agent-driven edits.

## Change summary

Copilot edit tools report 'file edited successfully' even when the custom FileSystemProvider's writeFile() throws and the save never persists.

## Best solution

Have EditTool.invoke in editFileTool.ts (and the equivalent notebook path) surface the outcome of the save triggered in ChatEditingModifiedDocumentEntry.acceptAgentEdits / _doAccept, instead of unconditionally returning success once isCurrentlyBeingModifiedBy flips back to false; this likely needs a small state flag or thrown/observed error propagated from ITextFileService.save() up through the entry into the tool result.

## Evidence

- **tool unconditionally reports success:** src/vs/workbench/contrib/chat/common/tools/builtinTools/editFileTool.ts lines 113-137: EditTool.invoke waits only for `currentFile.isCurrentlyBeingModifiedBy` to flip false via an autorun, then always returns `{ content: [{ kind: 'text', value: 'The file was edited successfully' }] }` — it never inspects whether the triggered save succeeded.
- **save result is discarded:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts lines 256-261: acceptAgentEdits calls `await this._textFileService.save(this.modifiedModel.uri, { reason: SaveReason.AUTO, skipSaveParticipants: true })` but does not check the return value (ITextFileService.save resolves to undefined on failure rather than throwing) or feed it back to the tool/entry state.
- **second save path also swallows errors:** same file, lines 265-282 (`_doAccept`): the explicit post-accept save is wrapped in `try { ... } catch { // ignored }`, another point where a FileSystemProvider rejection is dropped rather than surfaced.
