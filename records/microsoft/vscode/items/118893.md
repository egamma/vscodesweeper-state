# Issue #118893 — Using key commands to scroll to top or bottom of document does not incorporate editor.paddingTop and editor.paddingButtom

[https://github.com/microsoft/vscode/issues/118893](https://github.com/microsoft/vscode/issues/118893)

## Summary

Still reproduces on main: when `cursorTop`/`cursorBottom` commands reveal line 1 or the last line, the reveal logic scrolls to the line's vertical offset (which includes paddingTop) but doesn't scroll further to expose the padding area itself. Mouse scrolling works because the scroll range allows scrollTop=0.

## Change summary

Keyboard commands to go to top/bottom of document ignore `editor.paddingTop` and `editor.paddingBottom`, pinning the first/last line at the viewport edge instead of showing the configured padding.

## Best solution

In `_computeScrollTopToRevealRange` (src/vs/editor/browser/viewParts/viewLines/viewLines.ts), when the cursor is on the first or last line, account for editor padding by extending the reveal box to include the padding area — e.g. set `boxStartY = 0` when revealing line 1 with paddingTop, and extend `boxEndY` by paddingBottom when revealing the last line.
