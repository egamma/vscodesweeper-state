# Issue #118893 — Using key commands to scroll to top or bottom of document does not incorporate editor.paddingTop and editor.paddingButtom

[https://github.com/microsoft/vscode/issues/118893](https://github.com/microsoft/vscode/issues/118893)

## Summary

The bug remains source-reproducible on current main: the buffer-boundary cursor commands minimally reveal the destination line, which scrolls past configured top or bottom editor padding. The issue is already routed to the appropriate editor command area and should remain open for a bounded fix.

## Change summary

Make the cursor-top and cursor-bottom commands scroll to the document boundary while preserving configured editor padding.

## Best solution

Have the buffer-boundary navigation commands move the cursor as today but scroll to the corresponding document boundary, including configured padding; cover both normal and selection variants with editor command tests.

- **Behavior:**

  > With nonzero `editor.padding.top` or `editor.padding.bottom`, invoking cursorTop or cursorBottom must move the cursor to the first or last buffer position and scroll maximally in that direction so the corresponding padding remains visible. The selection variants must retain their existing selection semantics while producing the same boundary scroll position. Navigation and reveal behavior away from these four buffer-boundary commands must remain unchanged.
- **Trace:**

  > TopCommand and BottomCommand in src/vs/editor/browser/coreCommands.ts move the cursor correctly, then call the generic `IViewModel.revealAllCursors`. That method in src/vs/editor/common/viewModel/viewModelImpl.ts emits a Simple reveal, and `_computeScrollTopToRevealRange` in src/vs/editor/browser/viewParts/viewLines/viewLines.ts performs minimum scrolling around the destination line. Because line offsets already include top padding and total content height includes bottom padding in src/vs/editor/common/viewLayout/linesLayout.ts, minimum revealing places the boundary line at the viewport edge instead of exposing the padding. Keep the change scoped to cursorTop, cursorTopSelect, cursorBottom, and cursorBottomSelect; do not alter generic reveal behavior or ordinary cursor movement. https://github.com/microsoft/vscode/issues/63663 concerns centered-layout padding and does not absorb this defect.

## Evidence

- **current command path:** In src/vs/editor/browser/coreCommands.ts, TopCommand and BottomCommand move to the first or last buffer position and then call `viewModel.revealAllCursors(args.source, true)`, whose third argument defaults to minimalReveal=false.
- **source reproduction:** src/vs/editor/common/viewModel/viewModelImpl.ts routes `revealAllCursors` through VerticalRevealType.Simple. In src/vs/editor/browser/viewParts/viewLines/viewLines.ts, `_computeScrollTopToRevealRange` computes the first-line offset including top padding, then minimum-scroll logic can set the viewport to that offset, placing the line at the viewport edge and scrolling the padding out of view; the equivalent last-line calculation leaves bottom padding below the viewport.
- **padding model:** src/vs/editor/common/viewLayout/linesLayout.ts includes `_paddingTop` in line offsets and both `_paddingTop` and `_paddingBottom` in total content height, so the padding exists in the scroll model but the cursor commands do not request the document's minimum or maximum scroll position.
- **suggested related issue:** https://github.com/microsoft/vscode/issues/63663 is open but requests top and bottom padding for centered editor layout; it does not own this narrower defect in cursorTop/cursorBottom scrolling and is not a valid duplicate canonical.
