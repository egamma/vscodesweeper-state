# Issue #316235 — Feature Request - Ability to specify OAuth scopes in the MCP config for static client registration

[https://github.com/microsoft/vscode/issues/316235](https://github.com/microsoft/vscode/issues/316235)

## Summary

The requested scope-selection capability remains missing, but the older, open MCP Auth Scope Selection issue already owns it. Both reports describe VS Code requesting all advertised scopes and authorization failing because some scopes are not permitted.

## Change summary

Allow MCP configuration to specify OAuth scopes instead of automatically requesting all advertised scopes, including when using a statically registered client.

## Best solution

Consolidate explicit MCP scope selection in https://github.com/microsoft/vscode/issues/249663, preserving this report's static-client configuration requirement and the GitHub Spaces example where demand-driven scope escalation never occurs.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/249663 is OPEN and was created on 2025-05-23, before this issue's 2026-05-13 creation. Its body requests selecting a subset of OAuth scopes because VS Code requests all scopes by default and token requests are blocked by Conditional Access policies.
- **Re-review duplicate bar:** The canonical and this report share the same observable failure in remote MCP authentication: requesting the full advertised scope set causes authorization to fail. Static client registration and Splunk identify a specific instance of that broader scope-selection request, rather than a different capability.
- **Maintainer interest:** https://github.com/microsoft/vscode/issues/249663#issuecomment-2905551413 explains the existing metadata fallback and expresses willingness to provide scope-selection UI, subject to human-readable scope descriptions. The canonical remains an active feature request, not a declined precedent.
- **Existing capability does not cover configuration:** src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts defines the remote-server oauth schema with clientId and enterpriseManaged, but no scopes property, and rejects additional properties. src/vs/workbench/api/browser/mainThreadMcp.ts resolves scopes from authentication details, protected-resource metadata, then authorization-server metadata. src/vs/workbench/api/common/extHostMcp.ts supports server-provided WWW-Authenticate scope challenges; that is not a user-configurable scope override.
- **Additional discussion preserved:** https://github.com/microsoft/vscode/issues/316235#issuecomment-5404487710 adds a GitHub Copilot Spaces case requiring read:org, reports silent partial results that never trigger step-up, and requests explicit scopes for built-in providers as well as static clients. The cited fallback still exists in authenticateMcp-related code in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts: GitHub MCP resources use options.scopes even when empty. These details should accompany consolidation rather than be treated as resolved.
- **Other candidates are different work:** https://github.com/microsoft/vscode/issues/248775 concerns mapping authorization servers to authentication providers; https://github.com/microsoft/vscode/issues/282456 concerns authenticating registry discovery queries. Neither owns explicit scope selection for MCP server connections.
