# Issue #252294 — Handle 'removed' BreakpointEvent for instruction breakpoints

[https://github.com/microsoft/vscode/issues/252294](https://github.com/microsoft/vscode/issues/252294)

## Summary

The reported synchronization defect remains in current main: adapter-originated removal events never resolve or remove instruction breakpoints. Keep this issue open; the related closed reports do not establish a fix or an eligible duplicate canonical.

## Change summary

Remove an existing instruction breakpoint from VS Code when its debug adapter sends a matching DAP BreakpointEvent with reason 'removed'.

## Best solution

Honor adapter-originated instruction-breakpoint removals in the debug session event path so the Breakpoints panel and disassembly decorations stay synchronized. Keep this bounded to removal of existing breakpoints, independently of public extension API support or broader instruction-breakpoint creation and change events.
