## Evidence

- **Existing capability:** The command workbench.action.openProcessExplorer is registered in src/vs/workbench/contrib/processExplorer/browser/processExplorer.contribution.ts. ProcessMainService.resolveProcesses in src/vs/platform/process/electron-main/processMainService.ts requests remote diagnostics with includeProcesses: true; src/vs/server/node/remoteAgentEnvironmentImpl.ts obtains them through listProcesses(process.pid). The current renderer displays element.load and element.mem rather than substituting zero for remote processes.
- **Concrete partial fix:** https://github.com/microsoft/vscode/commit/9ffb3c46815da639d120888f2cdff061c336f1b0, committed 2025-05-08T10:32:36Z, changes src/vs/base/node/ps.ts from storing raw mem to mem: isWindows ? mem : (totalMemory * (mem / 100)). It also replaces client-platform-dependent memory conversion in the Process Explorer renderer with element.mem / ByteSize.MB. These diff lines address the reporter's Windows-client/Ubuntu-server memory-zero trigger: Linux percentages were previously interpreted as bytes by the Windows renderer. They do not change CPU sampling.
- **CPU boundary:** src/vs/base/node/ps.ts obtains Linux process information from ps and recalculates CPU usage over a one-second interval through cpuUsage.sh. src/vs/workbench/contrib/processExplorer/browser/processExplorerControl.ts renders load.toFixed(0). This establishes existing CPU support, but source inspection alone does not establish why the reporter saw zero or demonstrate correct readings under their SSH workload; no executable reproduction was performed.
- **Maintainer-selected canonical:** https://github.com/microsoft/vscode/issues/197601 reports the same remote memory-zero symptom, includes confirmation with a Codespace and another report on 1.96.4, and was closed as a duplicate of this issue. The consolidation decision is explicit at https://github.com/microsoft/vscode/issues/197601#issuecomment-2857724891.
- **Canonical search:** Open related reports were inspected. https://github.com/microsoft/vscode/issues/134475 concerns WSL CPU discrepancies and does not clearly own this report's SSH CPU-and-memory scope. https://github.com/microsoft/vscode/issues/211212 concerns remote memory zeros in Process Explorer and code --status, but does not own the CPU requirement. Neither establishes a broader canonical that absorbs this issue.
