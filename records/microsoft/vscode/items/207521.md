# Issue #207521 — If a URI contains an authority component, then the path component must either be empty or begin with a slash ("/") character

[https://github.com/microsoft/vscode/issues/207521](https://github.com/microsoft/vscode/issues/207521)

## Summary

Still a real, unresolved class of bug on main — a prior proposed fix commit was independently refuted, and this item has been reopened/kept open since. I traced at least one genuinely unguarded URI.from(...) construction on main that matches the authority+path precondition for exactly this UriError, but the ~2 years of varied reports (split terminal, explorer right-click, WSL default-distro mismatch, long task focus, Copilot chat in WSL) suggest more than one call site may be at fault, so this isn't yet a single bounded fix.

## Change summary

Creating/splitting a terminal (often involving a remote/WSL workspace folder or an authority-bearing cwd URI) intermittently throws 'If a URI contains an authority component, then the path component must either be empty or begin with a slash' and the terminal action fails.

## Best solution

Audit and guard every place that spreads an authority-bearing URI (e.g. `{ ...folder.uri, path }`) when constructing a new URI for terminal cwd resolution — src/vs/workbench/contrib/terminal/browser/terminalActions.ts's `resolveWorkspaceFolderCwd` (around line 1703) builds `URI.from({ ...folder.uri, path: resolvedCwdConfig })` without the leading-slash guard that `terminalService.ts`'s `_splitTerminal` already applies (lines 1202-1204) — apply the same normalization there and confirm no other terminal cwd-URI constructor is missing it.
