# Issue #328188 — Local chat session missing from Sessions list after Windows restart

[https://github.com/microsoft/vscode/issues/328188](https://github.com/microsoft/vscode/issues/328188)

## Summary

Real, traceable bug: the local chat session index for empty windows is APPLICATION-scoped (shared across all empty windows) but each ChatSessionStore instance loads it once into an in-memory cache and never re-reads before flushing, so one empty window's flush silently overwrites another's newly-added entries — matching the reported symptom (session content on disk, index entry gone).

## Change summary

A local (empty-window) chat session's file content and Copilot transcript survive on disk after a Windows restart, but its entry disappears from the Sessions list index, hiding it from all filters including Archived.

## Best solution

In ChatSessionStore (src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts), stop treating the persisted index as a single in-memory cache that gets blindly overwritten on flush — re-read/merge the latest persisted APPLICATION-scope index (or otherwise reconcile concurrent writers) before writing back, so a second empty window's flush can't clobber entries just added by another window.

## Evidence

- **shared storage scope:** getIndexStorageScope() (chatSessionStore.ts:432-436) returns StorageScope.APPLICATION when the workspace is an empty window, and the storageRoot for empty windows is the same globalStorageHome/emptyWindowChatSessions path (chatSessionStore.ts:70-73) for every empty window — so multiple simultaneously open empty windows share the same index key.
- **never-refreshed cache:** internalGetIndex() (chatSessionStore.ts:548-588) loads the index from storage once and caches it in this.indexCache; every subsequent write/flush (writeSession, flushIndex, updateAndFlushIndexSync) mutates and re-serializes this same stale in-memory object without re-reading storage first, so a later flush from one window instance overwrites entries another window instance added in the meantime.
- **narrow flush triggers:** storeSessions()/saveState() (chatServiceImpl.ts:339-360) that update+flush the index run only on IStorageService onWillSaveState, explicit setChatSessionTitle, or model disposal — not on every message — so a stale cached index from one window can persist for a while before it flushes.
