# Issue #332117 — Markdown editor lets you edit a staged file, and then shows text that is not actually staged

[https://github.com/microsoft/vscode/issues/332117](https://github.com/microsoft/vscode/issues/332117)

## Summary

Traced and confirmed on main: the WYSIWYG Markdown editor's edit/read-only toggle is a UI-only memento default, never checked against whether the underlying resource is actually writable, so it lets users type into a staged-revision (`git:` scheme, readonly filesystem) document and the edit lands in the shared in-memory text model.

## Change summary

Toggling the Markdown editor from Locked to Editing on a staged (`git:` scheme) revision accepts typed edits that never reach the staged content, silently diverging the editor's shown text from what `git diff --cached` reports.

## Best solution

In extensions/markdown-language-features/src/preview/markdownEditorProvider.ts, gate the editable/readonly state (and the `edit` message handler) on `vscode.workspace.isWritableFileSystem(document.uri.scheme)` so the pill can't be flipped to Editing (and typed edits are rejected) on a readonly-filesystem resource, matching how the plain text editor already behaves for the same `git:` URIs.

## Evidence

- **readonly toggle is memento-only:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts line ~763 sets the webview's initial `readonly` state from `this.#globalState.get(#readonlyStateKey, true)` — a global last-used default, with no check of the document's actual writability.
- **edit handler applies unconditionally:** The `case 'edit':` handler (lines ~304-323) builds a `vscode.WorkspaceEdit` and calls `vscode.workspace.applyEdit(edit)` regardless of whether the resource is writable.
- **git: scheme is a readonly filesystem provider:** extensions/git/src/fileSystemProvider.ts:57 registers `workspace.registerFileSystemProvider('git', this, { isReadonly: true, ... })` — staged/index content for a diff view is served from this readonly `git:` URI, which is why the plain text editor already blocks typing there.
- **bulk edit service has no readonly guard:** src/vs/workbench/contrib/bulkEdit/browser/bulkTextEdits.ts performs no `isReadonly()`/writable-filesystem check before pushing edit operations, so `vscode.workspace.applyEdit` silently succeeds against the readonly-backed model when the caller doesn't gate it itself (as the standard code editor does via its own readonly UI state, but this custom editor does not).
- **API available for the fix:** `vscode.workspace.isWritableFileSystem(scheme)` (src/vscode-dts/vscode.d.ts:9876) is the exact primitive the extension needs and isn't currently consulted anywhere in markdownEditorProvider.ts.
