# Issue #332117 — Markdown editor lets you edit a staged file, and then shows text that is not actually staged

[https://github.com/microsoft/vscode/issues/332117](https://github.com/microsoft/vscode/issues/332117)

## Summary

Traced on main: the built-in Markdown Editor (`vscode.markdown.editor`, extensions/markdown-language-features) never consults the resource's actual read-only state — the Locked/Editing pill is just a remembered global preference (`MarkdownEditorProvider.#readonlyStateKey`, default `true`) — so edits on a genuinely read-only resource (a staged git revision, a read-only file, etc.) are applied via `vscode.workspace.applyEdit` with no permission check, exactly mirroring the already-fixed multi-diff editor bug in issue #199251.

## Change summary

Reopening a staged Markdown file's diff with the Markdown Editor and switching to Editing mode lets you type into the read-only staged revision, silently mutating the in-memory document without ever touching the actual staged content.

## Best solution

In markdownEditorProvider.ts, resolve the resource's read-only state (e.g. via vscode.workspace.fs.stat(document.uri) and FilePermission.Readonly, mirroring how the core text/diff editors resolve readonly for the same git/staged resources) when initializing the webview and when handling the 'edit' message, and force Locked / reject edits for read-only resources regardless of the remembered global pill state — the same class of fix already shipped for the multi-diff editor in https://github.com/microsoft/vscode/issues/199251.

## Evidence

- **readonly is a UI preference, not a permission check:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts line ~763 sends `readonly: this.#globalState.get(MarkdownEditorProvider.#readonlyStateKey, true)` to the webview — a remembered user toggle (see the 'setReadonly' message handler around line 278), not derived from the document/resource's actual read-only status.
