# Issue #228418 — SCM Graph - Make 'Auto' mode select multiple remotes

[https://github.com/microsoft/vscode/issues/228418](https://github.com/microsoft/vscode/issues/228418)

## Summary

Keep open: Auto can display multiple remotes when the configured base differs from the tracking branch, but it still does not automatically choose both origin and upstream for the reported fork setup. The reporter's configuration workaround and persisted manual selection reduce the friction without delivering that automatic selection.

## Change summary

Make SCM Graph Auto mode automatically include relevant branches from both origin and upstream in a fork-based workflow.

## Best solution

Have the SCM/Git owner decide whether Auto should recognize fork workflows and include the upstream base alongside the tracked origin branch without per-branch configuration. Preserve explicit manual filters and distinguish this automatic-selection request from the related proposal for a manual merge-base action.

## Evidence

- **Reporter-confirmed workaround:** The November 28 comment on https://github.com/microsoft/vscode/issues/228418 says changing branch.main.vscode-merge-base from origin/main to upstream/main makes Auto show the desired references. This confirms existing multi-remote capability through explicit configuration, not automatic discovery of the desired upstream.
- **Current Auto selection:** src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:1393-1410, _resolveHistoryItemFilter, selects historyItemRef, historyItemRemoteRef, and historyItemBaseRef for Auto. It does not enumerate remotes to select both origin and upstream automatically.
- **Base selection explains the limitation:** extensions/git/src/historyProvider.ts:121-158 derives the remote reference from HEAD.upstream and includes the base reference only when it differs from that tracking branch. extensions/git/src/repository.ts:1774-1815, getBranchBase, first honors branch.<name>.vscode-merge-base, then uses reflog information or the default remote branch. An origin/main base with an origin/main tracking branch therefore adds no upstream/main reference.
- **Existing settings and persistence:** src/vs/workbench/contrib/scm/browser/scm.contribution.ts:385-416 registers graph pagination, badge, and incoming/outgoing settings, not an automatic multi-remote selection policy. scmHistoryViewPane.ts:1437-1450 persists explicit reference filters under scm.graphView.referencesFilter.
