# Issue #329143 — "Scroll to explore" affordance is unclear and seems buggy

[https://github.com/microsoft/vscode/issues/329143](https://github.com/microsoft/vscode/issues/329143)

## Summary

Team-authored report about confusing/buggy UX in the recently-added subagent tool-confirmation carousel; traced the code path in current main and the ambiguity is real, so routing to the chat area rather than closing.

## Change summary

The agent-name link ("— explore") in the tool confirmation carousel, tooltip-labeled "Scroll to {agentName}", is unclear/inconsistent about whether it scrolls to the subagent, opens a new chat, or does something else.

## Best solution

Clarify and make consistent the revealSubagent behavior in chatListRenderer.ts (maybeRouteSubagentToolToCarousel) and chatToolConfirmationCarouselPart.ts: in the Agents/Sessions window it opens a new chat via CHAT_OPEN_AGENT_HOST_CHAT_COMMAND_ID, but elsewhere it just does domNode.scrollIntoView while the tooltip always defaults to "Scroll to {0}" — the label and the actual action can diverge, which is exactly what the recording shows; align the label with whichever action actually runs.
