# Issue #334697 — Search: case modifiers fail on empty or short regex captures

[https://github.com/microsoft/vscode/issues/334697](https://github.com/microsoft/vscode/issues/334697)

## Summary

Traced and confirmed on current main: the Search view's case-operation replacement logic mishandles empty/short capture groups (leaking literal `\u` text, and throwing a TypeError for stacked modifiers past a capture's length). A fixing PR from the same reporter is already open, so this should stay open pending that PR's review rather than being auto-fixed or closed.

## Change summary

Search view's Preserve/case-modifier replace (`\u`, `\U`, `\l`, `\L`) produces literal escape text or throws when a numbered capture is empty, unmatched, or shorter than the number of stacked case operations.

Review and land the linked PR https://github.com/microsoft/vscode/pull/334698, which reportedly fixes replaceWithCaseOperations in src/vs/workbench/services/search/common/replace.ts with six new regression tests; close this issue once that PR merges.

## Evidence

- **unmatched-capture bug:** src/vs/workbench/services/search/common/replace.ts:114-118 — `const replacement = firstMatch[parseInt(money.slice(1))]; if (!replacement) { newReplaceString += fullMatch; continue; }` treats an empty string the same as undefined, so a participating-but-empty or non-participating group leaves the literal `\u$1` text in the output instead of an empty replacement.
- **stacked-modifier bug:** src/vs/workbench/services/search/common/replace.ts:123-141 — the `for (; i < caseOps.length; i++)` loop calls `replacement[i].toUpperCase()`/`.toLowerCase()` without checking `i < replacementLen`, so more case ops than capture characters (e.g. `\u\u\u$1` on a 2-char capture) reads `replacement[2]` (undefined) and throws.
