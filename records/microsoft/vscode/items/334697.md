# Issue #334697 — Search: case modifiers fail on empty or short regex captures

[https://github.com/microsoft/vscode/issues/334697](https://github.com/microsoft/vscode/issues/334697)

## Summary

Confirmed in source: ReplacePattern.replaceWithCaseOperations treats an empty capture as falsy (emitting a literal `\u`) and doesn't bound the case-op loop to the capture length (throwing on short captures). An open PR already fixes this, so the right move is reviewing/landing that PR rather than closing the issue now.

## Change summary

Search view's Replace-in-Files case modifiers (\u/\U/\l/\L) mishandle empty-string captures (emit literal `\u`) and throw a TypeError on captures shorter than the number of stacked case operations.

## Best solution

Land the fix in the linked PR (or an equivalent one) in src/vs/workbench/services/search/common/replace.ts: distinguish 'capture didn't participate' (undefined) from 'capture matched empty string' (falsy but defined), and clamp the per-character case-op loop to replacement.length so it never indexes past the end.

## Evidence

- **empty-capture bug:** src/vs/workbench/services/search/common/replace.ts:115 `if (!replacement)` treats an empty-string capture (falsy) the same as an unmatched (undefined) capture, so it appends the literal case-op marker (`\u`) instead of nothing.
- **short-capture crash:** src/vs/workbench/services/search/common/replace.ts:127-138 index `replacement[i]`/`.toUpperCase()` per case-op character without checking `i < replacementLen`; once `i` exceeds the capture length this reads `undefined` and throws `TypeError: Cannot read properties of undefined (reading 'toUpperCase')`, matching the reporter's stacked-modifier repro.
- **no existing fix on main:** git log on replace.ts shows no recent commit touching this logic; the buggy paths are unguarded on current main.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/334698 ("Fix search replacement case operations on short and empty captures") is open and appears to target exactly this defect.
