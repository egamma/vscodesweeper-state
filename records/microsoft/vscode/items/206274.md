# Issue #206274 — `explorer.upload` fails when a file is selected

[https://github.com/microsoft/vscode/issues/206274](https://github.com/microsoft/vscode/issues/206274)

## Summary

The defect remains source-reproducible on current main: `explorer.upload` passes the selected file itself as the upload destination, while neighboring file actions correctly resolve a selected file to its parent directory. This team-authored issue should remain open for a bounded file-explorer fix.

## Change summary

Make `explorer.upload` upload into the selected file's parent directory rather than treating the file as a directory.

## Best solution

Resolve the upload destination consistently with New File and native paste: use a selected directory directly, a selected file's parent directory, and the workspace root when there is no selection.

## Evidence

- **current source defect:** In src/vs/workbench/contrib/files/browser/fileActions.ts, `uploadFileHandler` obtains `explorerService.getContext(false)` and passes `context[0]` directly to `BrowserFileUpload.upload`, without checking whether the selected ExplorerItem is a directory.
- **failing path:** src/vs/workbench/contrib/files/browser/fileImportExport.ts uses the supplied target's resource as `parentResource`; therefore a selected file such as `foo.txt` produces an upload destination beneath `foo.txt`, matching the reported `foo.txt/foo.txt` failure.
- **established neighboring behavior:** The New File flow in src/vs/workbench/contrib/files/browser/fileActions.ts already resolves `stat.isDirectory ? stat : (stat.parent || explorerService.roots[0])`, and native paste similarly targets `element.isDirectory ? element : element.parent`.
- **confirmed impact:** The reporter supplied a standalone reproduction in https://github.com/vritant24/vscode-upload-file-repro, and the later report https://github.com/microsoft/vscode-edu-extension/issues/2734 confirms the same behavior remains reproducible and points back to this issue as the owning VS Code defect.
