# Issue #287929 — I hope to add the ability to directly drag and drop files or folders into the chat box.

[https://github.com/microsoft/vscode/issues/287929](https://github.com/microsoft/vscode/issues/287929)

## Summary

Keep open under discussion: VS Code already accepts Explorer file drops as chat attachments, but the clarified request is for a drop to insert an explicit inline file reference in one action, plus persistent context across chats. Those remaining interaction and persistence semantics are not covered by the existing attachment behavior.

## Change summary

Make dropped files or folders directly usable as explicit inline chat references and allow selected context to persist across chats.

## Best solution

Chat owners should separate the two asks, then decide whether Explorer drops over the input insert a visible inline reference or remain attachments, and define an explicit, user-controlled lifetime for persistent context.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/chatDragAndDrop.ts`, `src/vs/workbench/contrib/chat/common/chatModel.ts`
- **Validation:** Add or extend chat input drag-and-drop tests to verify the chosen visible representation for dropped files and folders, then exercise two new chat sessions to verify the agreed persistence lifetime and removal behavior.
- **Behavior:**

  > Dropping a file or folder from the Explorer onto the chat input should make that resource explicitly referenceable in the same user action, without requiring a second `#` selection. The prompt must clearly communicate which dropped resource is being discussed when several resources are present. If persistent context is included in scope, users must be able to see and remove retained context, and its lifetime across new chats must match the maintainer-approved design. Existing drag-to-attach behavior and agent access to attachments must remain functional.
- **Trace:**

  > The current observable behavior, confirmed in the issue comments, is that an Explorer drop adds the file to the attachment list above the input; the reporter's gap starts at how that attachment is represented or referred to inside the prompt. The likely bounded entry points are the chat input and drag-and-drop handlers under src/vs/workbench/contrib/chat/browser, while cross-chat retention reaches the chat model or persistence layer under src/vs/workbench/contrib/chat/common. Treat inline drop references and persistent context as separable acceptance tracks; do not remove the existing attachment path or make context persist invisibly. https://github.com/microsoft/vscode/issues/164 is related only at the general drag/drop level and is not the same reporter-observable chat behavior.
- **Open decisions:**
  - Should a drop insert an editable inline file reference at the cursor, retain the attachment chip with an automatically generated textual reference, or expose both representations?
  - Should persistent context apply to new chats within the current workspace only, or also survive reloads and reopenings?
  - Should files and folders share the same inline-reference semantics, including how a folder's scope is shown to the user?
