# Issue #72514 — index.js/index.ts file should show at top of file picker when searching for the name of the directory

[https://github.com/microsoft/vscode/issues/72514](https://github.com/microsoft/vscode/issues/72514)

## Summary

Keep this accepted, well-supported request open: default Quick Open scoring still gives filename matches priority over directory-entry files. Custom labels offer a useful configurable alternative, but do not establish that automatic directory-entry ranking has been delivered.

## Change summary

Rank index.js/index.ts files prominently when Quick Open is searched using their containing directory's name.

## Best solution

Provide deterministic directory-entry discovery in Quick Open without requiring users to know the entry filename. Decide the supported naming conventions and customization contract, building on existing custom-label support while preserving ordinary filename search and history behavior.

- **Behavior:**

  > Searching a directory name or its prefix in Quick Open should make that directory's entry file easy to discover without knowing its filename. The original request asks for index.ts and index.js to rank similarly to a file named after the directory; the discussion also requests analogous treatment for framework entry files such as +page.svelte. Acceptance must establish deterministic ordering against ordinary filename matches and other files in the same directory. Existing explicit custom labels and direct filename/path searches must remain usable.
- **Trace:**

  > AnythingQuickAccessProvider in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts retrieves physical-path candidates through getFileSearchResults, converts them through createAnythingPick, and ranks them through getAdditionalPicks using compareItemsByFuzzyScore. Without a custom label, createAnythingPick uses the basename, so index.ts receives description/path matching rather than the filename-match boost in src/vs/base/common/fuzzyScorer.ts. CustomEditorLabelService already supports dirname templates, and those names participate in Quick Open scoring; this is a configurable alternative, not automatic recognition. Candidate retrieval is capped before picker scoring, so visible ranking alone may not cover large projects. Preserve existing custom-label semantics, ordinary file navigation, history controls, and other consumers of the shared scorer. https://github.com/microsoft/vscode/issues/27317 is related ranking coordination, while https://github.com/microsoft/vscode/issues/130734 documents the existing custom-label capability. The unresolved boundary is which entry conventions receive recognition and whether that recognition affects ranking only or displayed names too.
- **Open decisions:**
  - Which directory-entry conventions should receive automatic recognition: index.js/index.ts only, a broader built-in set, or conventions explicitly declared by users or extensions?
  - Should directory-entry recognition affect Quick Open ranking only, or also its displayed labels independently of the existing editor custom-label setting?
  - When a directory entry and a directly matching filename both qualify, should they have equivalent relevance or should one take precedence?
