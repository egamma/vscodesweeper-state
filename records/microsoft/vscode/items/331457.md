# Issue #331457 — terminal-suggest: PATH is resolved once at activation, so a replaced PATH directory stops updating completions until reload

[https://github.com/microsoft/vscode/issues/331457](https://github.com/microsoft/vscode/issues/331457)

## Summary

Confirmed by reading the current source: `watchPathDirectories()` in `extensions/terminal-suggest/src/terminalSuggestMain.ts` reads `env.PATH` and `stat`s each entry exactly once at activation, with no re-check or re-read afterward, so a `PATH` directory that gets replaced in place (common with installer updates) leaves completions stuck on stale cached state until a window reload.

## Change summary

terminal-suggest's PATH directory watchers are established once at activation and never revisited, so directories replaced in place (or added later) stop updating completions until the window is reloaded.

## Best solution

This needs a maintainer/area-owner decision among the approaches the reporter already listed (periodic re-stat/re-watch, re-reading PATH on shell-integration activation, treating onDidDelete as a re-resolve signal, or deduplicating watches across windows) — it's a legitimate gap in `watchPathDirectories()`, not a one-line patch, so it should be routed to whoever owns terminal-suggest to pick and implement one of those designs.
