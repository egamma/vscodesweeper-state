# Issue #343077 — Large Codex chat restore stalls in JSON-RPC buffering and accessibility Markdown block counting

[https://github.com/microsoft/vscode/issues/343077](https://github.com/microsoft/vscode/issues/343077)

## Summary

Both reported sources of unnecessary CPU work remain in current main: fragmented JSON-RPC messages repeatedly rescan their accumulated prefix, and accessibility block counting performs full inline Markdown tokenization. Keep this open; the source supports bounded improvements without requiring the private transcript, although the reported end-to-end timings and bundled-SDK behavior remain unverified.

## Change summary

Avoid repeated JSON-RPC prefix processing and unnecessary inline Markdown parsing when restoring large Codex conversations.

## Best solution

Make fragmented-message reception scale with incoming payload size and generate accessibility block counts without unnecessary inline parsing. Preserve transport ordering, error handling, existing accessibility labels, and visible Markdown rendering; validate the two hotspots independently before measuring application-wide restoration.
