# Issue #285153 — Network proxy setting not inherit when start vscode from desktop launcher bar icon on Ubuntu.

[https://github.com/microsoft/vscode/issues/285153](https://github.com/microsoft/vscode/issues/285153)

## Summary

The report describes a real difference in proxy variable availability between desktop-launched and CLI-launched VS Code on Ubuntu, but lacks detail on how the proxy was configured — shell config vs GNOME system settings UI — which is critical to determine whether this is a VS Code issue or an expected Linux desktop environment behavior.

## Change summary

When VS Code is launched from a desktop launcher on Ubuntu, the integrated terminal does not inherit `http_proxy`/`https_proxy` environment variables that are available when launching from a terminal.

## Best solution

Clarify how the proxy was configured (shell profile vs GNOME gsettings). VS Code already spawns a login shell (`-i -l`) via `src/vs/platform/shell/node/shellEnv.ts` to resolve the environment on desktop launch. If the proxy vars are only set through GNOME's system Settings UI (gsettings/dconf) and not exported in shell config files, then VS Code's login shell won't see them — this would be expected behavior and the workaround is to set `http.proxy` in VS Code settings or export proxy vars in `.bashrc`/`.profile`. If the vars are in shell config and still missing, there may be a real resolution bug worth investigating.

Terminal emulators like gnome-terminal may set proxy vars from gsettings during their own initialization, which would explain why they're available in a Ctrl+Alt+T terminal but not in VS Code's spawned login shell.
