# Issue #337535 — AgentHost: Provide an interactive way to install sandbox pre-reqs similar to local sandboxing

[https://github.com/microsoft/vscode/issues/337535](https://github.com/microsoft/vscode/issues/337535)

## Summary

Fresh, team-authored feature request (opened by a VS Code MEMBER hours before review) proposing an interactive sandbox-prerequisite install flow for Agent Host, mirroring the existing local terminal-sandbox experience. It's already correctly labeled `agent-host`; team-authored items are protected from judgment closes and this is a legitimate, unresolved design ask, so it stays open.

## Change summary

Add an interactive, guided flow for detecting and installing missing Agent Host sandbox prerequisites, similar to the existing local sandboxing install experience.

## Best solution

Design how the existing local sandbox prerequisite-install UX (ChatSandboxPrerequisiteConfirmationSubPart, wired to TerminalSandboxEngine's dependency-status checks) can be extended or reused for Agent Host's cloud/remote sandbox engine (AgentHostSandboxEngine / ISandboxHelperService), since Agent Host sessions may run in environments (containers, remote, cloud) where the install semantics differ from a local machine.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/agentHostSandboxEngine.ts`, `src/vs/platform/agentHost/node/copilot/sandboxConfigForSdk.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatSandboxPrerequisiteConfirmationSubPart.ts`, `src/vs/platform/sandbox/common/terminalSandboxEngine.ts`
- **Validation:** A test confirming that, given a simulated missing-prerequisite status from ISandboxHelperService in an Agent Host session, the install flow surfaces the same confirmation/progress/retry UX as the local terminal sandbox path and re-enables sandboxing on success.
- **Behavior:**

  > When Agent Host sandbox prerequisites are missing for a session, the user sees an explicit, consent-gated 'Install' action (mirroring the local sandbox flow), progress and errors for the install, and prerequisites are re-checked afterward so sandboxing can proceed without repeating setup. A manual-install path must remain available. Acceptance: this works across every platform Agent Host sandboxing supports, and failures name the specific missing prerequisite with recovery guidance.
- **Trace:**

  > The local chat flow (chatSandboxPrerequisiteConfirmationSubPart.ts) already renders an interactive install/apply-fix confirmation driven by dependency-status results from ISandboxHelperService feeding TerminalSandboxEngine. Agent Host's AgentHostSandboxEngine (agentHostSandboxEngine.ts) wires the same TerminalSandboxEngine into Agent Host sessions but has no equivalent surfaced install action today. The uncertainty starts at design: whether Agent Host sessions (which may run remotely/in containers/cloud) can or should perform the same in-place interactive install as a local machine, what consent/UI surface applies when there's no local chat widget context, and how per-platform prerequisite differences are enumerated — none of this is settled in the issue or the code.
- **Open decisions:**
  - Can Agent Host reuse the existing chat confirmation UI (ChatSandboxPrerequisiteConfirmationSubPart) as-is, or does a remote/cloud Agent Host session need a different surface for consent and progress?
  - Which platforms/environments (local Agent Host vs. remote/cloud/container-hosted sessions) are in scope for automated installs versus manual-install-only fallback?
  - What is the enumerated set of Agent Host sandbox prerequisites per platform, and does it match or diverge from the local terminal sandbox's dependency list?

## Evidence

- **existing local flow:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatSandboxPrerequisiteConfirmationSubPart.ts implements an interactive 'Install' / 'Apply Fix and Retry' confirmation UI for missing local terminal sandbox dependencies, backed by TerminalSandboxEngine (src/vs/platform/sandbox/common/terminalSandboxEngine.ts) and ISandboxHelperService dependency-status checks.
- **agent host sandbox engine:** src/vs/platform/agentHost/node/copilot/agentHostSandboxEngine.ts bridges Agent Host session environment data into the same shared TerminalSandboxEngine, but no equivalent interactive prerequisite-install flow is wired up for Agent Host sessions today — this is a genuine, unimplemented gap distinct from the local chat flow.
