## Summary

Keep this as the existing PHP/Emmet upstream tracking issue. The upstream report remains open, current source still has PHP-unaware angle-bracket handling, and maintainers have consolidated later reports here; no verified fix or older same-symptom canonical was found.

## Change summary

Prevent PHP comparison operators such as <= and >= from incorrectly disabling or restoring HTML Emmet expansion.

## Best solution

Resolve PHP-aware parsing with the Emmet parser upstream and ensure VS Code's abbreviation-location validation respects PHP syntax rather than treating comparison operators as HTML delimiters. Preserve this issue as the VS Code tracking point, including the minimal comment-based reproduction.
