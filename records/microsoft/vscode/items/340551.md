## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/317187 is OPEN and reports the same observable problem: LanguageModelChatProvider models show zero token usage despite receiving valid backend usage. Its expected result explicitly requests a documented provider usage part, metadata, or equivalent supported mechanism, covering this issue's central ask.
- **Existing implementation candidates:** https://github.com/microsoft/vscode/pull/319686 is OPEN, proposes LanguageModelUsagePart and stream plumbing, and identifies https://github.com/microsoft/vscode/issues/317187 as its fixing target. The canonical's timeline also lists the OPEN proposal https://github.com/microsoft/vscode/pull/320550. Neither is evidence of a completed fix.
- **Existing capability is partial:** src/vscode-dts/vscode.proposed.chatProvider.d.ts has no typed usage response part. However, extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts already parses the internal 'usage' data-part convention, and extensions/copilot/src/extension/intents/node/toolCallingLoop.ts:1969-1986 forwards successful fetch usage through stream.usage(). The thread's blanket claim that the panel always drops usage is therefore outdated, but an internal convention does not supply the requested public contract.
- **Payload and context-window distinctions:** extensions/copilot/src/platform/networking/common/openai.ts:90-93 requires numeric prompt_tokens, completion_tokens, and total_tokens for the endpoint usage decoder; the issue's abbreviated payload omits total_tokens. chatContextUsageWidget.ts:375-432 also resolves the context limit from model metadata, with reported contextUsage as an alternative, so the comment claiming the limit can only arrive through the undocumented data part is not accurate.
- **Additional evidence to preserve:** https://github.com/microsoft/vscode/issues/340551#issuecomment-6288028088 independently reports an OpenAI-compatible gateway and status-bar workaround. https://github.com/microsoft/vscode/issues/340551#issuecomment-6290416127 adds the Agents-window loopback-proxy case and a 31,460-token example. These extend the same missing provider-usage contract rather than establish a separate root cause.
