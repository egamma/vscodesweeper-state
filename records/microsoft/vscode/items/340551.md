## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/317187 is OPEN and was created on 2026-05-18. Its body describes the same observable symptom: extension-contributed LanguageModelChatProvider models show zero usage despite receiving backend token counts, and explicitly requests a documented LanguageModelUsagePart, response metadata, or equivalent reporting mechanism.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/319686 is OPEN, declares Fixes for https://github.com/microsoft/vscode/issues/317187, and proposes LanguageModelUsagePart plus extension-host/workbench transport and Copilot endpoint consumption. It is an implementation candidate, not evidence that the feature has shipped.
- **Discussion connects the reports:** The supplied comments on https://github.com/microsoft/vscode/issues/340551 explicitly identify https://github.com/microsoft/vscode/pull/319686 as covering the provider API gap. The Agents-window comment asks that the same usage surface also reach the BYOK loopback proxy; it does not establish a distinct root cause.
- **Existing capability is partial:** Current extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts:242-310 already decodes LanguageModelDataPart with CustomDataPartMimeTypes.Usage and returns reportedUsage rather than always returning zero. However, extensions/copilot/src/platform/networking/common/openai.ts:90-93 requires numeric total_tokens as well as prompt_tokens and completion_tokens, so the payload described in this report without total_tokens does not satisfy that guard.
- **Agent-host path and remaining contract gap:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts:143-146,430-439 already decodes usage data parts using prompt_tokens, completion_tokens, and optional reasoning_tokens without requiring total_tokens. src/vscode-dts/vscode.proposed.chatProvider.d.ts:152,176-178 exposes data parts but no LanguageModelUsagePart. These are inconsistent implementations of the same provider-usage boundary, not proof of a completed end-to-end fix.
