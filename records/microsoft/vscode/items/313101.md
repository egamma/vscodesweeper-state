[https://github.com/microsoft/vscode/issues/313101](https://github.com/microsoft/vscode/issues/313101)

## Summary

A real discoverability gap remains: current main has experiment-gated, once-per-user new-session tours, but no general, durable documentation entry point for Agents Window users. This member-authored item is parked in Backlog and must remain open absent an explicitly referencing fix or verified duplicate.

## Change summary

Provide first-run guidance, durable documentation entry points, and contextual discovery for useful but subtle Agents Window features.

## Best solution

Design a cohesive Agents Window learning path that combines restrained first-run onboarding with a durable Help/documentation entry point and contextual guidance for features such as diff feedback. Settle placement, persistence, and dismissal behavior before implementation so guidance remains discoverable without crowding the primary session workflow.

- **Behavior:**

  > New Agents Window users should encounter concise guidance that explains the essential session concepts without displacing the primary prompt workflow. Returning users should have a durable, keyboard-accessible way to reopen Agents documentation, while contextual guidance should make subtle actions such as submitting feedback from a diff discoverable when relevant. Acceptance should verify the chosen show-once or dismissal semantics, continued documentation access after onboarding, AI-feature gating, and accessible naming and keyboard operation.
- **Trace:**

  > Current first-run behavior is registered through src/vs/sessions/contrib/onboardingTours/browser/onboardingTours.contribution.ts. The tours in browser/tours/newSessionViewTour.ts and newSessionViewV3Tour.ts are experiment-gated and share NEW_SESSION_ONBOARDING_SEEN_KEY, so they teach only selected new-session concepts and are not a durable help surface. Existing general documentation links appear mainly in unavailable or policy-blocked states, while sessionTypePicker.ts owns the provider picker implicated by the narrower https://github.com/microsoft/vscode/issues/308601 and https://github.com/microsoft/vscode/issues/312808 reports. Preserve the calm, prompt-first new-session hierarchy, existing AI-feature gates, and current provider-selection behavior; the uncertainty starts at which persistent surface owns Help and how progressive feature guidance should be timed.
- **Open decisions:**
  - Should Agents documentation remain permanently available from a global Help/account/title-bar menu, or primarily live within the new-session surface?
  - Should first-run guidance disappear automatically after its first completed use, remain until explicitly dismissed, or be replayable from the durable Help entry point?
  - Should this effort cover only foundational session concepts, or also define progressive contextual guidance for subtle post-session features such as diff feedback?
