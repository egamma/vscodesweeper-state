# Issue #168662 — Git - The `git submodule deinit` command is not reflected in the GUI

[https://github.com/microsoft/vscode/issues/168662](https://github.com/microsoft/vscode/issues/168662)

## Summary

Still reproduces on main: submodule repositories opened by the git extension are never closed when `git submodule deinit` removes them — the `checkForSubmodules` callback only opens new submodule repos but never removes stale ones. The `help wanted` label is already applied, and the issue is a valid polish/bug.

## Change summary

Running `git submodule deinit` in the terminal does not remove the deinitialized submodule from the Source Control Repositories view until a full window reload.

## Best solution

Add logic in `extensions/git/src/model.ts` (around the `checkForSubmodules` callback, ~line 786) to compare the current set of opened submodule repositories against the parent's refreshed `repository.submodules` list, and close/dispose any repositories whose submodule path is no longer present. The `statusListener` on repository change already triggers `checkForSubmodules` — the same callback should also handle removals.
