# Issue #323941 — Integrated Browser+Agent: `open_browser_page` tool call fails with ERROR: Access to 127.0.0.1 is blocked by network domain policy

[https://github.com/microsoft/vscode/issues/323941](https://github.com/microsoft/vscode/issues/323941)

## Summary

Confirmed bug on main: the `normalizeDomain` function in domainMatcher.ts rejects IP addresses and `localhost` when used as allowed-domain patterns (the well-known-suffix heuristic filters them out), making it impossible to allowlist local addresses.

## Change summary

The `open_browser_page` tool and other agent network tools cannot access localhost/127.0.0.1 even when explicitly added to `chat.agent.allowedNetworkDomains`, because the domain matching rejects IP addresses and bare hostnames as patterns.

## Best solution

Fix `normalizeDomain` (or `matchesDomainPattern`) in `src/vs/platform/networkFilter/common/domainMatcher.ts` to recognize IP addresses (IPv4 numeric octets) and bare hostnames like `localhost` as valid domain patterns even when `fromUrl` is false. The well-known-suffix heuristic should not apply to entries that are clearly IP addresses or single-label hostnames.
