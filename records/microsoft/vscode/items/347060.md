# Issue #347060 — Scroll bar not easily selectable in multi-tab chat container

[https://github.com/microsoft/vscode/issues/347060](https://github.com/microsoft/vscode/issues/347060)

## Summary

Keep open: current source explicitly limits the chat-tab scrollbar to a 3px target. The earlier scrolling fix provides dragging, but does not address this team-authored follow-up about acquiring the control.

## Change summary

Make the overflowing chat-tab scrollbar easier to acquire and drag with a mouse.

## Best solution

Provide a comfortably operable scrollbar target in ChatCompositeBar while preserving tab layout and existing scrolling behavior. Resolve whether that improvement applies by default or follows the editor's existing scrollbar-sizing preference.

Cover Connected/Pill styles and compact/default heights, retain hiding when tabs fit, and manually confirm acquisition with overflowing chat tabs.
- **Behavior:**

  > When multiple chat tabs overflow their container, users should be able to acquire and drag the horizontal scrollbar without precision targeting a 3px strip. The control should remain quiet when unnecessary and preserve tab activation, wheel scrolling, and existing tab-row heights. Acceptance includes pointer hit-testing and successful dragging across the agreed usable target in both tab styles and height modes.
- **Trace:**

  > ChatCompositeBar in src/vs/workbench/contrib/sessions/browser/parts/chatCompositeBar.ts creates a ScrollableElement with horizontalScrollbarSize: 3 and synchronizes its scroll position with the native tabs container. ScrollableElement defaults the slider thickness to the track thickness, and HorizontalScrollbar applies those dimensions directly. The browser test in src/vs/sessions/test/browser/chatCompositeBar.test.ts explicitly expects a 3px scrollbar and confirms dragging only from its center. The editor's workbench.editor.titleScrollbarSizing preference already supports easier mouse acquisition, but ChatCompositeBar does not consume it. Preserve shared scrollbar defaults and unrelated editor consumers; the remaining uncertainty is the chat surface's default versus preference-controlled sizing contract. The previous scrolling resolution at https://github.com/microsoft/vscode/issues/327606 is context, not a resolution of this acquisition problem.
- **Open decisions:**
  - Should chat tabs provide a larger pointer target by default, or preserve the compact default and honor workbench.editor.titleScrollbarSizing for users requesting a larger scrollbar?
