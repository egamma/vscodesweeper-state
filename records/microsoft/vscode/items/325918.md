# Issue #325918 — Swipe to navigate option to go to previous editor location instead of previous 'page'

[https://github.com/microsoft/vscode/issues/325918](https://github.com/microsoft/vscode/issues/325918)

## Summary

A real capability gap remains: trackpad swipes can only cycle recently used editors, while Go Back and Go Forward navigate location history. The older mouse-shortcut customization issue is related but does not report the same observable behavior, so the stronger re-review duplicate bar is not met.

## Change summary

Allow macOS swipe gestures to invoke editor location-history navigation instead of only cycling recently used editors.

## Best solution

Provide a backward-compatible choice of swipe navigation target, preserving the existing recently-used-editor behavior while allowing users to select Go Back and Go Forward location history.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/common/editor.ts`, `src/vs/workbench/browser/parts/editor/editor.ts`
- **Validation:** On macOS with Swipe Between Pages enabled, verify that the selected swipe mode traverses cursor/navigation locations in both directions, that the existing mode still cycles recently used editors, and that disabling `workbench.editor.swipeToNavigate` leaves swipes unhandled by VS Code.
- **Behavior:**

  > Users who enable swipe navigation can choose whether horizontal swipes cycle recently used editors or traverse the same location history as Go Back and Go Forward. Both directions must follow the selected mode consistently. Existing users must retain a defined, backward-compatible default, and disabling swipe navigation must continue to remove VS Code's swipe handling.
- **Trace:**

  > The macOS-only `workbench.editor.swipeToNavigate` setting is registered as a boolean in src/vs/workbench/browser/workbench.contribution.ts and represented in editor options in src/vs/workbench/common/editor.ts and src/vs/workbench/browser/parts/editor/editor.ts. CodeWindow.registerSwipeListener in src/vs/platform/windows/electron-main/windowImpl.ts receives Electron's `swipe` event and hard-codes the recently-used-editor commands. The requested location-history commands already exist in src/vs/workbench/browser/parts/editor/editorActions.ts as `workbench.action.navigateBack` and the forward counterpart. No swipe-specific test was found, so the plan must establish validation for Electron's native macOS event path. Keep mouse buttons four and five, keyboard navigation, and non-macOS behavior outside the change.
- **Open decisions:**
  - When an existing user has `workbench.editor.swipeToNavigate: true` and no new mode configured, should swipes preserve the current recently-used-editor behavior or switch to location-history navigation?

## Evidence

- **existing setting:** src/vs/workbench/browser/workbench.contribution.ts:388-393 registers `workbench.editor.swipeToNavigate` as a boolean, so there is no setting for selecting location-history navigation.
