# Issue #325918 — Swipe to navigate option to go to previous editor location instead of previous 'page'

[https://github.com/microsoft/vscode/issues/325918](https://github.com/microsoft/vscode/issues/325918)

## Summary

Valid, unimplemented request: the macOS trackpad swipe gesture is hardcoded to previous/next recently-used editor rather than Go Back/Go Forward, and no setting lets users choose the latter — routing to the editor-navigation area for a maintainer decision.

## Change summary

Bind the three-finger trackpad swipe gesture to 'Go Back'/'Go Forward' (editor location history) instead of 'previous/next recently used editor'.

## Best solution

Either add an option (or repurpose `workbench.editor.swipeToNavigate`) so the Electron 'swipe' handler in src/vs/platform/windows/electron-main/windowImpl.ts (registerSwipeListener, lines ~1149-1161) can trigger `workbench.action.navigateBack`/`workbench.action.navigateForward` instead of always calling `workbench.action.openPreviousRecentlyUsedEditor`/`openNextRecentlyUsedEditor` — this is a scoped, maintainer-owned behavior/config decision, not a bug fix.

## Evidence

- **current swipe binding:** src/vs/platform/windows/electron-main/windowImpl.ts registerSwipeListener() (lines 1149-1161) maps swipe 'left'/'right' to workbench.action.openPreviousRecentlyUsedEditor / openNextRecentlyUsedEditor, not Go Back/Go Forward — confirmed via git log -S showing this has been the behavior since the setting `workbench.editor.swipeToNavigate` was introduced (commit 97e7e43d).
- **unrelated existing setting:** workbench.editor.mouseBackForwardToNavigate (src/vs/workbench/services/history/browser/historyService.ts, onMouseDownOrUp) already binds mouse buttons 4/5 to goBack()/goForward(), addressing the second commenter's mouse-side-button scenario, but this is a distinct mechanism from the macOS native trackpad 'swipe' event the issue is about.
- **no config for requested behavior:** workbench.editor.swipeToNavigate (src/vs/workbench/browser/workbench.contribution.ts line 373) only toggles the swipe feature on/off; it offers no way to change the target command to Go Back/Forward.
