# Issue #94034 — Search for ignored sync settings or extensions

[https://github.com/microsoft/vscode/issues/94034](https://github.com/microsoft/vscode/issues/94034)

## Summary

Keep open: current search filters do not expose effective Settings Sync inclusion or exclusion for settings and extensions. A maintainer supported this direction; the existing ignore-list settings are a workaround, not coverage of the requested search experience.

## Change summary

Allow searching settings and installed extensions by whether they are ignored by Settings Sync, with an inverse view for synchronized items.

## Best solution

Provide discoverable sync-state filters in the Settings editor and Extensions view, consistent with their existing sync context-menu actions. Clarify whether the inverse filter means eligible for synchronization or actually present in synchronized data.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`, `src/vs/workbench/contrib/preferences/browser/settingsSearchMenu.ts`, `src/vs/workbench/contrib/extensions/common/extensionQuery.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsViews.ts`
- **Validation:** Exercise both search surfaces with one normally synchronized item, one explicitly ignored item, and one default-ignored item with an explicit inclusion override. Confirm the ignored filter matches effective context-menu state, text search narrows the results, and changing sync inclusion updates membership. Validate the inverse against the agreed meaning and preserve existing filter behavior.
- **Behavior:**

  > Users can find settings and installed extensions excluded from Settings Sync without inspecting configuration arrays or checking each item individually. Results reflect effective exclusion, including defaults and explicit overrides, and remain usable with text search and existing context-menu actions. The discussion also requests an inverse view of synchronized items; its meaning must be settled before acceptance criteria for that view are finalized.
- **Trace:**

  > Settings query parsing and tag matching live in src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts, with discoverable filter actions in settingsSearchMenu.ts; neither currently derives sync-state search membership. Extension query suggestions live in src/vs/workbench/contrib/extensions/common/extensionQuery.ts, while ExtensionsListView in extensionsViews.ts classifies and filters local queries. Existing per-item state is already surfaced by SyncIgnoredWidget through isExtensionIgnoredToSync, and IgnoredExtensionsManagementService.getIgnoredExtensions accounts for defaults and inclusion overrides. Preserve synchronization policy, configuration formats, and existing context-menu behavior; this request concerns finding items, not changing what syncs. The narrower declined request at https://github.com/microsoft/vscode/issues/132682 is relevant context but does not resolve the full scope of https://github.com/microsoft/vscode/issues/94034. Source inspection establishes the missing filters, not the intended meaning of an inverse query.
- **Open decisions:**
  - Should the inverse filter show items eligible for synchronization under current configuration, or only items actually present in synchronized data?
