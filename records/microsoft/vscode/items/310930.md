# Issue #310930 — Stabilize `vscode.proposed.tunnels` API: enabling named portless tunnel aliases for AI-assisted devcontainer workflows

## Summary

Well-documented request to stabilize the ~4-year-old `vscode.proposed.tunnels` API. The API remains proposed-only on current main, no stabilization work has landed, and the issue has passed the community upvote threshold into the Backlog. Keeping open for the API team to evaluate.

## Change summary

Graduate the `vscode.proposed.tunnels` API (specifically `workspace.openTunnel` and named tunnel aliases) to the stable extension API surface.

## Best solution

The API team (@alexr00) should evaluate `vscode.proposed.tunnels` for stabilization — at minimum `openTunnel` + `TunnelOptions.label` for named portless aliases. The existing proposed API in `src/vscode-dts/vscode.proposed.tunnels.d.ts` is mature and largely unchanged since creation; the main decision is scope (full surface vs. subset) and whether the tunnel factory / remote authority resolver coupling is ready for stable. Related open issue https://github.com/microsoft/vscode/issues/115616 (port exclusion API) is in the same API area and tagged `api-finalization`.
