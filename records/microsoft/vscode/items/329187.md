# Issue #329187 — Allow Windows native title bar colors to follow VS Code theme colors

[https://github.com/microsoft/vscode/issues/329187](https://github.com/microsoft/vscode/issues/329187)

## Summary

The exact mapping requested — titleBar.* theme colors driving Electron's titleBarOverlay — already exists in current source for the default custom title bar with Window Controls Overlay; it's intentionally NOT applied when the fully native OS title bar is used, since that chrome is outside VS Code's control by design.

## Change summary

Requests that VS Code's titleBar.activeBackground/activeForeground/inactive* theme colors be reflected in the native Windows title bar (Electron titleBarOverlay), instead of the overlay staying gray.

## Best solution

Nothing to build — the capability already ships: keep pointing users at the default custom title bar (window.titleBarStyle: custom, the default) where theme colors already drive Electron's setTitleBarOverlay(); the fully-native title bar path (window.titleBarStyle: native) intentionally has no overlay to theme, since it's genuine OS chrome.

  > Thanks for the detailed investigation! This mapping already exists on current `main`: with the default custom title bar (Window Controls Overlay), `titleBarPart.updateStyles()` reads the computed `titleBar.activeBackground`/`activeForeground`/inactive* colors and forwards them to Electron's `setTitleBarOverlay()` via `nativeHostService.updateWindowControls()` (see `src/vs/workbench/electron-browser/parts/titlebar/titlebarPart.ts` and `src/vs/platform/windows/electron-main/windowImpl.ts`).
  > 
  > The overlay stays uncolored only when `window.titleBarStyle` is set to `native` — in that mode there's no VS Code-drawn overlay at all, just genuine OS chrome, which is out of the theme system's reach by design. If you were seeing gray with the default custom title bar rather than `native`, it'd help to confirm on the latest Insiders build, since this syncing logic has been evolving. Closing as already covered by existing behavior — feel free to reopen with your exact `window.titleBarStyle` setting if the default custom title bar still doesn't pick up your colors.

## Evidence

- **theme colors computed:** src/vs/workbench/browser/parts/titlebar/titlebarPart.ts around lines 849-870 sets `this.element.style.backgroundColor`/`.color` from TITLE_BAR_ACTIVE_BACKGROUND/FOREGROUND and TITLE_BAR_INACTIVE_BACKGROUND/FOREGROUND — exactly the tokens the reporter lists.
- **synced to native overlay:** src/vs/workbench/electron-browser/parts/titlebar/titlebarPart.ts lines 252-271: `updateStyles()` reads those same computed style values and calls `nativeHostService.updateWindowControls({ backgroundColor, foregroundColor })` whenever `useWindowControlsOverlay(configurationService)` is true.
- **Electron API call:** src/vs/platform/windows/electron-main/windowImpl.ts lines 405-446 (`updateWindowControls`) calls `win.setTitleBarOverlay({ color: effectiveBackgroundColor, symbolColor: effectiveForegroundColor, height })` on Windows/Linux — the same API the reporter's proof-of-concept patched manually.
- **gate condition:** src/vs/platform/window/common/window.ts lines 332-349: `useWindowControlsOverlay()` returns false when `hasNativeTitlebar(configurationService)` is true — i.e. the overlay-coloring path is deliberately skipped only when the user has opted into the fully native title bar (window.titleBarStyle: native), where there is no VS Code-drawn overlay to color at all.
- **initial window creation also themed:** src/vs/platform/windows/electron-main/windows.ts lines 210-235 sets the initial `options.titleBarOverlay.color/symbolColor` from `themeMainService.getWindowSplash()`/`getBackgroundColor()` at window creation, before the runtime sync kicks in.
