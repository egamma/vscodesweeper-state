# Issue #248532 — cellOutput leak

[https://github.com/microsoft/vscode/issues/248532](https://github.com/microsoft/vscode/issues/248532)

## Summary

Still reproduces on main: `toolbarAttached` is checked but never set to `true` after `_attachToolbar()`, so the autorun re-attaches the toolbar on every visibility change, leaking menu-service event listeners. An open PR (#253761) addresses this but has not merged.

## Change summary

Notebook cell output toolbar is re-attached on every visibility toggle because `toolbarAttached` is never set to `true`, leaking event listeners.

## Best solution

Set `toolbarAttached = true` after calling `_attachToolbar()` and reset it to `false` when clearing toolbar disposables, so attachment happens exactly once per visibility cycle. Review and land (or supersede) the open PR https://github.com/microsoft/vscode/pull/253761 which targets this exact fix.

## Evidence

- **source trace:** In src/vs/workbench/contrib/notebook/browser/view/cellParts/cellOutput.ts, line 70 declares `private toolbarAttached = false;` and line 216 checks `if (visible && !this.toolbarAttached)` — but `toolbarAttached` is never set to `true` anywhere in the file, so the guard is ineffective and `_attachToolbar()` runs on every autorun cycle.
- **open PR:** https://github.com/microsoft/vscode/pull/253761 — open, unmerged PR that fixes this exact issue by setting `toolbarAttached = true` after attachment and resetting on clear.
- **leak mechanism:** Each `_attachToolbar()` call (line 349) adds a `menu.onDidChange` listener to `toolbarDisposables`, but because the autorun re-enters, listeners accumulate without limit — matching the stack trace at event.ts:927.
