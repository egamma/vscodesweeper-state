# Issue #335217 — Explorer must stay standalone when no folder is opened: "No Folder Opened" view is missing `canMoveView`

[https://github.com/microsoft/vscode/issues/335217](https://github.com/microsoft/vscode/issues/335217)

## Summary

Confirmed on current main: `createEmptyViewDescriptor()` in explorerViewlet.ts omits `canMoveView`, unlike its sibling `createExplorerViewDescriptor()`, which blocks dragging the No Folder Opened view into other containers — a clear, small, localized fix.

## Change summary

The 'No Folder Opened' Explorer view cannot be dragged into another view container (e.g. merged with Terminal/SCM/Search in the Panel) because it is missing the `canMoveView` flag that its Folders-view counterpart has.

## Best solution

Add `canMoveView: true` to `createEmptyViewDescriptor()` in src/vs/workbench/contrib/files/browser/explorerViewlet.ts, matching `createExplorerViewDescriptor()`, so the empty-view container's movability is consistent with the populated Explorer.
