# Issue #332145 — `run_in_terminal` automatically embeds image paths from stdout without an aggregate limit, causing renderer OOM

[https://github.com/microsoft/vscode/issues/332145](https://github.com/microsoft/vscode/issues/332145)

## Summary

Confirmed on current main: the run_in_terminal tool's image extraction has a per-file size cap but no aggregate count/byte limit and no opt-out setting, so any command that prints many image-like paths (e.g. git status in a repo with many small images) can embed dozens of base64 images per turn, bloating chat session state until the renderer runs out of memory.

## Change summary

run_in_terminal automatically embeds every image path it finds in terminal stdout, with no limit on total count/bytes and no setting to disable it, risking renderer OOM.

## Best solution

Add an aggregate image-count/byte budget (and ideally a `chat.tools.terminal.extractImagesFromOutput` opt-out setting, defaulting more conservatively) to `_extractImagesFromOutput` in runInTerminalTool.ts, and scan the post-compaction output rather than the full raw terminal result.
