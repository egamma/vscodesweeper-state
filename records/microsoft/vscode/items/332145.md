# Issue #332145 — `run_in_terminal` automatically embeds image paths from stdout without an aggregate limit, causing renderer OOM

[https://github.com/microsoft/vscode/issues/332145](https://github.com/microsoft/vscode/issues/332145)

## Summary

Confirmed on current main: `_extractImagesFromOutput` in runInTerminalTool.ts enforces only a per-file 5 MiB cap with no limit on the number of images or total attached bytes, so any command that prints many image-like paths (e.g. `git status` in an asset-heavy repo) can balloon the tool result and crash the renderer. This is a real, unrouted bug that needs a maintainer/area owner.

## Change summary

The built-in `run_in_terminal` tool auto-embeds every image path it finds in stdout with no aggregate count/byte limit, letting ordinary commands attach dozens of images and OOM the renderer.

## Best solution

Add an aggregate image-count and/or total-byte cap (and ideally a setting to disable extraction entirely, e.g. `chat.tools.terminal.extractImagesFromOutput`) inside `_extractImagesFromOutput` in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts, so accidental path matches from arbitrary command output can't attach unbounded image data.
