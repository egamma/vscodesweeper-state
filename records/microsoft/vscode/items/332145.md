# Issue #332145 — `run_in_terminal` automatically embeds image paths from stdout without an aggregate limit, causing renderer OOM

[https://github.com/microsoft/vscode/issues/332145](https://github.com/microsoft/vscode/issues/332145)

## Summary

Confirmed on main: `_extractImagesFromOutput` in runInTerminalTool.ts caps only per-file size (5 MiB) with no cap on image count or aggregate bytes, and it scans the full raw terminal output rather than the post-compaction text — a command like `git status` in an asset-heavy repo can attach dozens of images and balloon the serialized task state, leading to renderer OOM. No existing setting disables this, and no test covers the function at all.

## Change summary

The run_in_terminal tool auto-embeds every image path it finds in stdout with no aggregate count/byte limit, risking renderer OOM from ordinary commands like `git status`.

## Best solution

Add an aggregate byte/count cap (and ideally an opt-out setting, e.g. `chat.tools.terminal.extractImagesFromOutput`) to `_extractImagesFromOutput` in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts, and scan the post-compaction output rather than the full raw terminal output.
