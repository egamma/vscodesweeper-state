# Issue #332145 — `run_in_terminal` automatically embeds image paths from stdout without an aggregate limit, causing renderer OOM

[https://github.com/microsoft/vscode/issues/332145](https://github.com/microsoft/vscode/issues/332145)

## Summary

Confirmed on current main: `_extractImagesFromOutput` in runInTerminalTool.ts caps only per-file size (5 MiB), with no aggregate-byte or image-count limit, and scans the raw uncompacted output — matching the reporter's exact trace. This is a real, unrouted correctness/resource gap.

## Change summary

The run_in_terminal tool auto-embeds every image-looking path in terminal stdout with no aggregate or count limit, letting commands like `git status` balloon tool results and OOM the renderer.

## Best solution

Add an aggregate byte cap and/or a max image count to `_extractImagesFromOutput` in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts, and consider scanning the post-compaction output instead of the raw `terminalResult`; a setting to disable extraction entirely is also reasonable but the aggregate cap is the minimum fix.
