# Issue #263584 — VSC merge editor will not work properly for files added in both branches

[https://github.com/microsoft/vscode/issues/263584](https://github.com/microsoft/vscode/issues/263584)

## Summary

Still broken on current main and now traced: for an add/add (AA) conflict git has no stage-1 blob, so the merge editor's base model fails to load and is replaced by a synthetic in-memory model — which makes the `mergeEditorBaseUri` context key `inmemory://…` and silently disables the git extension's "Complete Merge" button. Team-authored bug in the Backlog milestone, so it stays open; worth a planning session because the whole-file-conflict half is a product decision.

## Change summary

A file added in both branches (add/add conflict) opens in the merge editor with the whole file marked as conflicting and no way to finish via the "Complete Merge" button.

## Best solution

Make both-added conflicts a first-class merge-editor case: give the base a real (git-scheme, empty-blob) resource instead of silently falling back to an untitled in-memory model, so the git extension's `git.acceptMerge` when-clause matches and "Complete Merge" appears — and decide whether an add/add conflict should keep showing the whole file as one conflict or present only the lines git actually marked.

  > Thanks for the precise repro — it reproduces from the source on current main, and the two symptoms have the same root cause.
  > 
  > - For a both-added (AA) conflict git records no stage 1, so the merge editor's base (`toGitUri(uri, ':1')`, extensions/git/src/uri.ts) can't be read and the git file system provider raises `FileNotFound`.
  > - `WorkspaceMergeEditorModeFactory.createInputModel` catches that and substitutes an empty, URI-less in-memory model. That empty base is why the whole file shows up as current/incoming.
  > - It also means `mergeEditorBaseUri` becomes `inmemory://model/N`, and the git extension gates "Complete Merge" on `mergeEditorBaseUri =~ /^(git|file):/` — hence no button.
  > 
  > As a workaround until this is fixed, "Merge Editor: Complete Merge" from the Command Palette (or Ctrl+Enter) still works.

## Evidence

- **no base blob for AA:** extensions/git/src/uri.ts:57 `toMergeUris()` builds the merge-editor base as `toGitUri(uri, ':1')`. For a both-added conflict git records no stage 1, so extensions/git/src/fileSystemProvider.ts:231 `repository.buffer(':1', path)` throws and the provider raises `FileSystemError.FileNotFound()` (line 241).
- **silent in-memory base fallback:** src/vs/workbench/contrib/mergeEditor/browser/mergeEditorInputModel.ts:297-316 catches that rejection (`onUnexpectedError`) and substitutes `this._modelService.createModel('', …)` — a model with no URI, so it gets an auto-generated `inmemory://model/N` URI. An empty base is also exactly why the whole file is rendered as current/incoming, matching the report.
- **that is what disables the button:** src/vs/workbench/contrib/mergeEditor/browser/view/mergeEditor.ts:260 sets `ctxMergeBaseUri` from `model.base.uri.toString()` — i.e. the `inmemory:` fallback — while extensions/git/package.json:2842 gates `git.acceptMerge` ("Complete Merge", package.nls.json:161) on `isMergeResultEditor && mergeEditorBaseUri =~ /^(git|file):/ && mergeEditorResultUri in git.mergeChanges`. The scheme check fails, so the floating button (src/vs/workbench/browser/codeeditor.ts:176, `MenuId.EditorContent`) is never rendered, regardless of what the user accepts.
- **unfixed on main:** At 959031245ebb1fe077e0d512e1397c0ae82006e4 (2026-10-10) `git log --since=2025-08-01 -- src/vs/workbench/contrib/mergeEditor extensions/git/src/fileSystemProvider.ts` shows no related change, and no commit references #263584.
- **AA does reach the merge editor:** extensions/git/src/repository.ts:541 and :3230 route `Status.BOTH_ADDED` ('AA') into the merge group and the merge editor, so the entry point is intentional — only the base resource is unhandled.
- **partial workaround:** `mergeEditor.acceptMerge` is `f1: true` (src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts:620-634), so "Merge Editor: Complete Merge" still works from the Command Palette / Ctrl+Enter — only the button is missing.
