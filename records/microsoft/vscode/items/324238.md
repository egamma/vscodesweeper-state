# Issue #324238 — Agent Host: Using Codex harness shows prompt for computer use

[https://github.com/microsoft/vscode/issues/324238](https://github.com/microsoft/vscode/issues/324238)

## Summary

The macOS AppleScript/automation permission prompt ("...wants to control 'Codex Computer Use'") is raised by the Codex CLI's own app-server process, which VS Code merely spawns and pipes JSON-RPC to — nothing in the agent host code launches AppleScript or a 'Computer Use' helper app itself.

## Change summary

Using the Codex harness in the Agent Host pops a macOS system dialog asking to allow AppleScript control of a 'Codex Computer Use' app, even for a plain text exchange with no computer-use action.

## Best solution

This is rooted in the downloaded Codex CLI (`codex app-server`, launched from src/vs/platform/agentHost/node/codex/codexLaunchConfig.ts via agentSdkDownloader.ts) apparently starting or registering a 'Codex Computer Use' automation helper unconditionally on macOS; the fix belongs in the Codex CLI itself (only enable/probe computer-use when the feature is actually requested), with VS Code only needing to track/upgrade the codex CLI version once that's addressed upstream. If Codex's app-server exposes a config flag to disable computer-use capability advertisement (see ComputerUseRequirements/allowLockedComputerUse in the generated protocol types), the agent host could also pass that off by default until the harness's computer-use tool is actually enabled.
