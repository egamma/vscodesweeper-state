# Issue #245540 — Disable the dependency extension installation

[https://github.com/microsoft/vscode/issues/245540](https://github.com/microsoft/vscode/issues/245540)

## Summary

Keep open: the supplied logs prove same-version dependency deletion and reinstallation, and current source retains the remote local-download path that causes it. This is a core extension-management defect, not merely a request to bypass required dependencies.

## Change summary

Installing Black Formatter followed by Pylint remotely reinstalls their already-installed Python dependencies and can leave Python unusable.

## Best solution

Make remote local-download dependency installation reuse already-satisfied dependencies rather than treating them as explicit VSIX reinstalls. Preserve required dependency installation and deliberate extension updates or reinstalls; a blanket workspace dependency opt-out is not necessary to resolve this defect.

- **Current remote fallback retains the trigger:** src/vs/workbench/services/extensionManagement/electron-browser/remoteExtensionManagementService.ts:65-115: doInstallFromGallery falls back to downloadAndInstall after gallery/download errors. downloadAndInstall enumerates workspace dependencies and packs without excluding installed dependencies, then calls downloadCompatibleAndInstall for each. The installed list determines only the download operation; each dependency still reaches super.install with a VSIX URI.
- **Current source explains deletion and restart error:** src/vs/platform/extensionManagement/node/extensionManagementService.ts:1096-1104: InstallExtensionInProfileTask.doRun deletes an existing same-version extension when the source is a VSIX URI and throws 'Please restart VS Code before reinstalling {0}' if deletion fails. keepExisting affects extraction at lines 387-392, not this preceding deletion.
- **Normal dependency resolution establishes expected behavior:** src/vs/platform/extensionManagement/common/abstractExtensionManagementService.ts:656-659 filters already-installed extensionDependencies before fetching them. The remote local-download path does not apply this installed-dependency exclusion.
- **Discussion distinguishes transport from repeated installation:** https://github.com/microsoft/vscode/issues/245540#issuecomment-3049837587 explains that remote.SSH.localServerDownload controls server delivery, not extension installation. https://github.com/microsoft/vscode/issues/245540#issuecomment-3101903396 clarifies that downloads succeed but dependencies install twice; https://github.com/microsoft/vscode/issues/245540#issuecomment-3430849463 reports persistence in 1.105.1.
- **Existing controls do not resolve the reported defect:** remote.downloadExtensionsLocally selects the affected local-download path rather than disabling dependencies. The CLI --do-not-include-pack-dependencies option is registered in src/vs/platform/environment/node/argv.ts and propagated by src/vs/server/node/remoteExtensionHostAgentCli.ts; it is not a workspace setting or evidence that sequential GUI installation preserves existing dependencies.
