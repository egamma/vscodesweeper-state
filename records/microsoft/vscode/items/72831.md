# Issue #72831 — FileSystemWatcher fires events to extensions before text documents are updated

[https://github.com/microsoft/vscode/issues/72831](https://github.com/microsoft/vscode/issues/72831)

## Summary

The race condition is still present on current main: file watcher events fire to extensions before the text document model is refreshed from disk, and `ensureDocumentData` returns the stale cached copy. No fix has been implemented; the discussion about the right API shape (e.g. a new document-changed-on-disk event) remains unresolved.

## Change summary

FileSystemWatcher events reach extensions before the cached TextDocument model reflects the on-disk change, causing openTextDocument to return stale content.

## Best solution

Introduce an API-level solution — either a new `onDidChangeTextDocumentOnDisk` event that fires after the model is synced, or a mechanism in the file-event dispatch path that ensures open documents are refreshed before extension-facing watcher events are emitted. The fix likely touches `src/vs/workbench/api/browser/mainThreadFileSystemEventService.ts` (event dispatch ordering) and/or `src/vs/workbench/api/common/extHostDocuments.ts` (cache invalidation).
