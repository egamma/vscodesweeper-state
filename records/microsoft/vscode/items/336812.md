# Issue #336812 — PreToolUse hook "ask" creates an unanswerable confirmation for tools declaring presentation: "hidden", hanging the session

[https://github.com/microsoft/vscode/issues/336812](https://github.com/microsoft/vscode/issues/336812)

## Summary

Confirmed on current main: a PreToolUse `ask` preserves a tool's hidden presentation while creating and awaiting confirmation, leaving the affected chat turn blocked with no reachable approval UI. This is distinct from the related deny-visibility request and should remain open for a bounded fix.

## Change summary

Ensure a hook-forced confirmation remains answerable when the tool normally uses hidden presentation.

## Best solution

A PreToolUse `ask` must override any presentation state that would hide the pending confirmation, while tools without hook-forced confirmation retain their existing presentation behavior.

- **Behavior:**

  > When a PreToolUse hook returns `ask`, the pending tool confirmation must be visible and answerable even if the tool normally declares hidden presentation. Approving it must allow execution to continue, and denying it must cancel normally rather than leaving the turn pending. Tools without a hook-forced confirmation must retain their existing hidden behavior.
- **Trace:**

  > In src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts, `resolveAutoConfirmFromHook` adds confirmation messages for `ask` but leaves `IPreparedToolInvocation.presentation` unchanged. `ChatToolInvocation` in src/vs/workbench/contrib/chat/common/model/chatProgressTypes/chatToolInvocation.ts therefore enters `WaitingForConfirmation` with hidden presentation, after which the service awaits confirmation. The chat renderer and agent-session approval model both filter hidden invocations, so no UI can resolve that wait. Existing hook tests in src/vs/workbench/contrib/chat/test/browser/tools/languageModelToolsService.test.ts cover forced confirmation but not hidden presentation. Keep the boundary to hook-forced `ask`; do not change ordinary hidden-tool rendering or the separate deny-visibility behavior tracked by https://github.com/microsoft/vscode/issues/325742.

- **blocking path:** The same service constructs a `ChatToolInvocation` and awaits `IChatToolInvocation.awaitConfirmation`; src/vs/workbench/contrib/chat/common/model/chatProgressTypes/chatToolInvocation.ts copies the unchanged presentation while entering `WaitingForConfirmation`.
