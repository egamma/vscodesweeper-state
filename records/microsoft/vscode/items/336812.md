# Issue #336812 — PreToolUse hook "ask" creates an unanswerable confirmation for tools declaring presentation: "hidden", hanging the session

[https://github.com/microsoft/vscode/issues/336812](https://github.com/microsoft/vscode/issues/336812)

## Summary

Confirmed from source: `resolveAutoConfirmFromHook`'s 'ask' branch builds `confirmationMessages` and awaits confirmation but never clears `presentation`, so a tool declaring `presentation: 'hidden'` (e.g. `copilot_fetchWebPage`) gets a confirmation that is awaited but never rendered — the turn hangs until the user interrupts. This is a real, reproducible-from-code hang, distinct from the deny-visibility issue it references.

## Change summary

A PreToolUse hook returning permissionDecision 'ask' for a tool whose prepareInvocation sets presentation: 'hidden' creates a confirmation with no UI surface, deadlocking the turn.

## Best solution

In `resolveAutoConfirmFromHook`'s 'ask' branch (both the fresh-confirmation and prepend-to-existing paths), clear/override `preparedInvocation.presentation` so the forced confirmation is guaranteed to render, matching the reporter's suggested fix.

The turn should never stall with an unrenderable pending confirmation; confirming or denying should behave exactly as it does for any other hook-forced 'ask'. Acceptance: a test invoking a hidden-presentation tool under a hook 'ask' decision reaches WaitingForConfirmation with presentation no longer 'hidden', and confirming it completes the invocation normally.
- **Trace:**

  > Root cause is in resolveAutoConfirmFromHook (src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts, lines ~877-931): the 'ask' branch mutates preparedInvocation.confirmationMessages (both when building fresh messages and when prepending to an existing tool's own confirmation) but never touches preparedInvocation.presentation. Downstream, ChatToolInvocationPart.ts line 138 returns immediately without building any DOM when toolInvocation.presentation === 'hidden', so the confirmation built at languageModelToolsService.ts line 674-678 is awaited (awaitConfirmation) but has no UI surface — the tool_call hangs until the user interrupts. The fix must only affect the case where the hook forces 'ask' on an otherwise-hidden invocation; it must not change presentation for 'allow'-decided or no-hook-decision invocations, nor alter the existing hidden-tool-invocation rendering for cases with no pending confirmation.
