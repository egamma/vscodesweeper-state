# Issue #313085 — `files.exclude` cannot match filenames with trailing CR (macOS `Icon\r`) because `parsePattern` calls `.trim()`

[https://github.com/microsoft/vscode/issues/313085](https://github.com/microsoft/vscode/issues/313085)

## Summary

Confirmed in current source: Explorer passes `files.exclude` expressions to the shared glob parser, whose unconditional `String.trim()` removes a terminal CR before matching. The report is actionable and should remain open as a bounded glob correctness bug.

## Change summary

Allow `files.exclude` glob patterns to match filenames ending in CR or other intentional trailing whitespace.

## Best solution

Preserve intentional trailing filename characters in glob patterns while retaining any compatibility-required handling of incidental surrounding spaces, with focused parser tests covering terminal CR and ordinary patterns.
