## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/browser/terminalProcessManager.ts`, `src/vs/workbench/contrib/terminal/browser/remotePty.ts`, `src/vs/platform/terminal/node/terminalProcess.ts`
- **Validation:** On Windows, run the same fixed CPU workload in a local integrated terminal and over Remote-SSH to Linux, comparing elapsed time and CPU utilization while foregrounded, unfocused, and minimized. Repeat with minimal and continuous output; monitor remote utilization independently of the affected terminal. Acceptance requires no reproducible focus-dependent throughput collapse while preserving bounded output buffering and correct PTY pause/resume behavior.
- **Behavior:**

  > The report describes CPU-intensive workloads slowing dramatically when the Windows VS Code window loses focus or is minimized, then recovering immediately when foregrounded. Local integrated terminals and Remote-SSH Linux workloads are both affected; continuous output reportedly mitigates the problem. Terminal computation should not suffer a substantial focus-dependent throughput collapse. First reproduce and quantify the minimal-output and continuous-output cases, then verify the same workloads retain their throughput across focus transitions without breaking output delivery.
- **Trace:**

  > Ordinary workbench window creation in src/vs/platform/windows/electron-main/windowImpl.ts does not apply the backgroundThrottling=false setting used for sessions windows; windows.ts additionally supports an explicit noBackgroundThrottling override. TerminalInstance._writeProcessData acknowledges process data through the xterm write callback, TerminalProcessManager buffers acknowledgements, and TerminalProcess pauses/resumes the PTY using unacknowledged-character watermarks. RemotePty forwards the same acknowledgement mechanism to the remote terminal channel. These paths identify investigation boundaries, but do not conclusively explain why minimal output is worse than continuous output. Reproduce on Windows before selecting a cause, distinguish unfocused from minimized states, and preserve existing flow-control protections. The webview timer report at https://github.com/microsoft/vscode/issues/232788 does not establish a shared terminal defect or duplicate.
