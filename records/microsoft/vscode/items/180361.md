# Issue #180361 — Notebook keyboard shortcuts inconsistent

[https://github.com/microsoft/vscode/issues/180361](https://github.com/microsoft/vscode/issues/180361)

## Summary

This is a known interaction design question about notebook focus state when output has focus. The single-letter keybindings (A, B, DD) come from the jupyter-keymap extension and rely on `NOTEBOOK_CELL_LIST_FOCUSED` + `!inputFocused` context, which doesn't hold when focus is inside the output webview. Already labeled under-discussion and notebook-commands — appropriate to leave open for the team to decide on the desired behavior.

## Change summary

Single-letter Jupyter-style keyboard shortcuts (A, B, DD) don't work when a notebook cell output area has focus.

## Best solution

The notebook team should decide whether output-focused state should still allow cell-level navigation shortcuts (A/B/DD from jupyter-keymap) to fire, or whether the current behavior — where output focus is a distinct mode that captures keyboard input — is intentional. If they want parity, the keybinding when-clauses for these actions would need to also match `notebookOutputFocused`.
