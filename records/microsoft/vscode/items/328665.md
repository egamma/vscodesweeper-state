# Issue #328665 — agentHost: request trust before provisional rebind creates a backend

[https://github.com/microsoft/vscode/issues/328665](https://github.com/microsoft/vscode/issues/328665)

## Summary

Verified in the checkout: `AgentHostSessionListController.newChatSessionItem` calls `tryRebind` (creating the real backend and provisional resource) before `AgentHostSessionHandler._invokeAgent` performs its `_ensureWorkspaceTrust` gate — matching the reported ordering exactly. This is a real, well-diagnosed pre-consent access concern with a concrete fix plan; keeping open regardless since it's team-authored and touches workspace-trust security boundaries.

## Change summary

Agent Host can provision a real backend for a selected target folder (which may probe folder-scoped config/plugin files) before interactive workspace trust is requested on first Send.

## Best solution

Implement the author's proposed shared `ensureAgentHostWorkingDirectoryTrust` helper and call it from `newChatSessionItem` in agentHostSessionListController.ts before `tryRebind`/graduation, keeping `_ensureWorkspaceTrust` in agentHostSessionHandler.ts as defense-in-depth for non-Editor-Window paths.
