# Issue #140226 — Dispatch a chord keybinding again if it is not followed by a second part

[https://github.com/microsoft/vscode/issues/140226](https://github.com/microsoft/vscode/issues/140226)

## Summary

The requested fallback remains absent: current chord handling discards an incomplete sequence after its timeout rather than invoking the matching single-key command. Keep this open for a decision on fallback semantics and accessible timing; existing precedence rules explain the original conflict but do not satisfy the evolved request.

## Change summary

Allow a single-key command to execute when a higher-precedence chord sharing its prefix is not completed.

## Best solution

Define whether incomplete chords should optionally fall back to a matching shorter command, including timing and cancellation behavior, before changing the shared keybinding dispatcher. Preserve existing keybinding precedence and accessibility unless an explicit product decision changes them.

Retain the existing precedence tests and manually check the extensions-disabled terminal scenario from the report.
- **Behavior:**

  > A higher-precedence chord currently makes a matching single-key command unavailable, even when the user never completes the chord. The requested capability is to retain access to the shorter command while still allowing the longer sequence. Acceptance must cover incomplete sequences and completed chords without accidentally executing both commands. Timing and cancellation behavior need agreement before implementation.
- **Trace:**

  > KeybindingResolver.resolve in src/vs/platform/keybinding/common/keybindingResolver.ts chooses the highest-precedence context-matching rule before determining whether more keys are needed. AbstractKeybindingService._doDispatch enters chord mode for MoreChordsNeeded; _scheduleLeaveChordMode expires it after a hardcoded five-second threshold, and _leaveChordMode clears the sequence without a fallback command. Existing tests in src/vs/platform/keybinding/test/common/abstractKeybindingService.test.ts establish that giving the shorter command precedence instead disables the longer chord. Terminal routing settings do not supply the missing fallback. The maintainer discussion at https://github.com/microsoft/vscode/issues/140226#issuecomment-1013000869 identifies timing accessibility as a constraint. The unresolved boundary is the user-visible fallback contract, not where to place the implementation; raw character replay and modifier-release schemes mentioned later are distinct extensions of the central request.
- **Open decisions:**
  - Should incomplete-chord fallback be opt-in or change the default, and should it invoke only an existing shorter command or also replay otherwise-unbound input?
  - Should fallback use the existing five-second timeout or a separately configurable interval that accommodates slower chord entry?
  - Should an unrelated next key cancel fallback, execute the shorter command before processing that key, or follow another explicitly defined behavior?
