# Issue #343575 — Copilot harness (now default) silently lacks run_in_terminal; agents fall back to a separate shell and fail where Local works

[https://github.com/microsoft/vscode/issues/343575](https://github.com/microsoft/vscode/issues/343575)

## Summary

Keep open: the reported harness switch breaks an existing prepared-terminal workflow, and neither existing shell settings nor the related non-TTY issue fully covers it. Current main has client-tool forwarding and an optional persistent-shell override, but their behavior against the supplied reproduction remains unverified; the report provides sufficient steps to retest without requesting more information.

## Change summary

Switching new chats to the Copilot harness silently removes the terminal behavior required by existing custom agents, alongside confusing migration and agent-discovery differences.

## Best solution

Establish the supported prepared-terminal workflow in the Copilot harness and make any capability difference explicit before users encounter command failures. Document the existing harness-selection controls and distinguish MCP configuration migration from whether a server is currently available.
