# Issue #343575 — Copilot harness (now default) silently lacks run_in_terminal; agents fall back to a separate shell and fail where Local works

[https://github.com/microsoft/vscode/issues/343575](https://github.com/microsoft/vscode/issues/343575)

## Summary

Keep open for integrated-terminal parity or an explicit capability explanation. Current settings provide partial alternatives, but neither a separate persistent shell nor changing the default harness satisfies shared access to an already-prepared terminal.

## Change summary

Provide shared integrated-terminal execution in the Copilot harness, or clearly disclose the limitation and explain migration status and Local-default controls.

## Best solution

Establish a supported contract for agents and users sharing terminal state, with visible capability differences wherever parity is unavailable. Clarify effective versus migrated MCP configuration and document the existing harness-selection controls without presenting them as terminal parity.
