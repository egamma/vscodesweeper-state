# Issue #50291 — Intellisense tooltip with filter category like Visual Studio

[https://github.com/microsoft/vscode/issues/50291](https://github.com/microsoft/vscode/issues/50291)

## Summary

Keep open: existing settings hide completion kinds, but do not provide interactive category filtering inside the suggestion popup. This remains the established consolidation point, with 98 upvotes and a product-design decision still outstanding.

## Change summary

Allow users to narrow the active IntelliSense suggestion list by completion kind through category controls and keyboard commands.

## Best solution

Design an accessible, keyboard-operable category filter within the editor suggestion widget, preserving existing configured exclusions and completion ranking. Settle its visibility and filter lifetime with the maintainer before implementation.

- **Validation:** Add targeted completion-model/controller tests using mixed methods, properties, classes, folders and snippets: selecting a category narrows matching results, clearing it restores eligible results, and configured exclusions remain honored. Run the affected suites with scripts/test.sh --run selectors. Manually verify keyboard-only and screen-reader operation in an active suggestion popup, including the agreed reset behavior.
- **Behavior:**

  > Users can narrow an open IntelliSense list by completion kind without editing workspace settings or leaving the editor. Category selection must coexist with typed-text filtering, preserve normal ordering within the remaining results, and provide a clear way to return to all eligible suggestions. Keyboard operation must be scoped to the active suggestion popup, with accessible category names and selection state. Acceptance includes mixed-kind results, an empty selected category, configured kind exclusions, and the agreed behavior when the popup closes and reopens.
- **Trace:**

  > SuggestModel.createSuggestFilter in src/vs/editor/contrib/suggest/browser/suggestModel.ts derives an exclusion set from editor.suggest.show* settings; trigger constructs CompletionOptions using that set. CompletionModel._createCachedState in src/vs/editor/contrib/suggest/browser/completionModel.ts performs cached text scoring and ordering, including incremental filtering, but has no interactive category selection state. SuggestWidget and SuggestWidgetStatus own the popup and menu-based status surface; suggestController.ts registers popup commands and context-scoped keybindings. Preserve configured exclusions, provider behavior, text matching, completion acceptance and existing ranking; enabling a category must not resurrect suggestions already excluded by configuration. The remaining uncertainty is product behavior for control visibility, selection semantics and lifetime, not whether static settings already satisfy the request. https://github.com/microsoft/vscode/issues/18639 and https://github.com/microsoft/vscode/issues/62386 were consolidated into this issue.
- **Open decisions:**
  - Should category controls be visible by default, opt-in, or revealed on demand within the suggestion popup?
  - Should users select one category at a time or combine multiple categories?
  - Should category selection reset when the popup closes or persist across subsequent completion sessions?

## Evidence
