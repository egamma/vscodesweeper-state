# Issue #241174 — Ctrl+Shift+C does not open external terminal on Linux snap

[https://github.com/microsoft/vscode/issues/241174](https://github.com/microsoft/vscode/issues/241174)

## Summary

Real snap-specific bug actively being fixed: the snap launcher sets GTK_PATH (line 254 of electron-launch), which poisons the library search path for external terminal binaries like gnome-terminal. An open PR (#298237) by a team member upgrades the snap to core22 and explicitly lists this issue in its Fixes.

## Change summary

Ctrl+Shift+C fails to open an external terminal when VS Code is installed as a snap on Linux, because the snap's GTK_PATH export causes a GLIBC symbol lookup error in gnome-terminal.

## Best solution

Land https://github.com/microsoft/vscode/pull/298237, which upgrades the snap base to core22 and addresses the GTK_PATH / library mismatch that prevents external terminals from launching. The core22 upgrade eliminates the stale core20 library paths that cause the symbol lookup failure.

## Evidence

- **root cause in source:** resources/linux/snap/electron-launch line 254 appends $SNAP/usr/lib/$ARCH/gtk-3.0 to GTK_PATH; when external processes like gnome-terminal inherit this, they load incompatible snap-bundled libraries (core20's libpthread) instead of system ones, causing the GLIBC_PRIVATE symbol lookup error.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/298237 by dmitrivMS (team member) explicitly lists 'Fixes #241174'; it upgrades the snap to core22 base and registers VS Code with update-alternatives.
- **reporter confirmation:** Reporter confirmed the issue persists on VS Code 1.109.5 snap in comment 5; unset GTK_PATH is a working workaround per comment 2.
- **related issue:** https://github.com/microsoft/vscode/issues/179958 tracked the same GTK_PATH interference for snap external terminal launching.
