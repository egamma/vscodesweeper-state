# Issue #339742 — Replacement of queued messages does not seem to work

[https://github.com/microsoft/vscode/issues/339742](https://github.com/microsoft/vscode/issues/339742)

## Summary

Fresh, specific bug report on a new cross-chat message queue feature; a collaborator independently confirmed seeing the same stale-queued-message behavior, so this is a real, reproduced defect that needs a maintainer's diagnosis of the queue-replacement path.

## Change summary

Replacing a queued cross-chat message (via send_message) reports success in the UI, but the peer chat still receives/executes the original, un-replaced queued message.

## Best solution

Trace the queue-replace flow for cross-session send_message requests (likely in agentHostSessionHandler.ts's queuedMessages handling and/or the server-side protocol reducer) to find why a replacement doesn't propagate to the peer chat before the message is dispatched.
