# Issue #335763 — Testing: Discrepancy in rendered UI compared to TPI description

[https://github.com/microsoft/vscode/issues/335763](https://github.com/microsoft/vscode/issues/335763)

## Summary

Team-authored test-plan discrepancy report with clear screenshots and version info (1.138.0-insider, Linux) showing the harness picker adds the Dev Container designation but the workspace picker trigger doesn't — a real, if cosmetic, label-sync gap in the sessions workspace picker. No fix commit exists yet, so this stays open per the team-authored hard-keep-open rule.

## Change summary

When a Dev Container is selected, the harness/isolation picker shows a '[<workspace> Dev Container]' designation, but the workspace picker trigger keeps the plain workspace name instead of gaining the '- Dev Container' suffix the test plan describes.

## Best solution

Trace both label paths together — sessionWorkspacePicker.ts's `_getWorkspaceLabel`/`_renderTriggerLabel` (which does apply a '- Dev Container' suffix, but only down the `reflectsWorkspace` branch, falling back to plain `workspace.label` for the `isSelectedCategory` branch) and the harness/isolation picker's own label source — then either fix the workspace trigger to consistently apply the suffix, or correct the test-plan wording if the current split display is intentional.
