# Issue #339168 — Finalize `LanguageModelChatInformation.statusIcon`

## Summary

Keep open for an API-owner finalization decision: statusIcon remains proposed, and the stable API does not cover the requested model-status indication. The related provider-identity icon request addresses a different capability and is not a duplicate.

## Change summary

Finalize LanguageModelChatInformation.statusIcon so stable-API language model providers can display model-health indicators with explanatory tooltips.

- **Behavior:**

  > A language model provider using only stable API declarations should be able to supply an optional model-status icon and explanatory tooltip without changing the model's identity. Status changes announced through onDidChangeLanguageModelChatInformation should update the relevant model-selection surfaces. Acceptance includes stable-only compilation and visible status updates in the picker and management editor; tooltip independence and icon-color behavior must first be agreed with API owners.
- **Trace:**

  > LanguageModelChatInformation.statusIcon exists only in src/vscode-dts/vscode.proposed.chatProvider.d.ts, while tooltip is already stable in src/vscode-dts/vscode.d.ts. ExtHostLanguageModels forwards the icon into metadata, and getModelPickerIcon in modelProviderIcons.ts prioritizes it over provider branding. Both getModelHoverContent and ModelNameColumnRenderer.renderModelElement in chatModelsWidget.ts condition tooltip text on statusIcon being present. The rendering implementation therefore exists, but its stable contract remains missing. Keep provider-identity customization separate: https://github.com/microsoft/vscode/issues/339167 requests different functionality. The uncertainty is API-owner approval and the tooltip/color semantics identified by the reporter, not whether an existing implementation alone constitutes finalization.
- **Open decisions:**
  - Should statusIcon now become a supported stable LanguageModelChatInformation property?
  - Should the management editor display the stable tooltip independently of statusIcon, or retain the current coupling?
  - Should status-icon rendering honor ThemeIcon.color, or should the stable contract explicitly document that color is ignored?
