# Issue #330277 — [Error] unhandlederror-InstantiationService has been disposed

[https://github.com/microsoft/vscode/issues/330277](https://github.com/microsoft/vscode/issues/330277)

## Summary

Real, confirmed bug: an async use-after-dispose race in the Settings editor search path throws when the editor is closed while `onConfigUpdate`/`triggerSearch` awaits are in flight. A fix PR already exists and is open but unmerged, so this should stay open pending that PR landing rather than being closed now.

## Change summary

SettingsEditor2's async onConfigUpdate/triggerSearch resumes after being disposed and calls instantiationService.createInstance on the now-disposed service, throwing 'InstantiationService has been disposed'.

## Best solution

Land the existing fix at https://github.com/microsoft/vscode/pull/330344, which adds disposed-guards at the async re-entry points in onConfigUpdate, triggerSearch, and searchWithProvider (settingsEditor2.ts) before touching instantiationService.createInstance.
