# Issue #332437 — Terminal sticky scroll shows wrong command

[https://github.com/microsoft/vscode/issues/332437](https://github.com/microsoft/vscode/issues/332437)

## Summary

Keep open: current source can display preceding output instead of the executed command, and an open fixing PR already owns the implementation attempt. Review that PR before considering this resolved.

## Change summary

Terminal sticky scroll can pin unrelated output rather than the command responsible for the visible output.

## Best solution

Ensure the sticky overlay retains the executed command when preceding prompt rows exceed its height limit. Review https://github.com/microsoft/vscode/pull/332438 for that behavior while preserving ordinary multiline prompts and commands.

Output arriving between command completion and the next prompt can therefore inflate promptRowCount and trigger the overlay defect; this is the scenario diagnosed in the linked PR. This conclusion is from source inspection, not runtime execution.
