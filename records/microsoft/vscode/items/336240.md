# Issue #336240 — Agent host logs an error when releasing sampling interest during shutdown

[https://github.com/microsoft/vscode/issues/336240](https://github.com/microsoft/vscode/issues/336240)

## Summary

Confirmed cleanup-ordering bug in the agent host, and an open PR already fixes it — this should stay open until that PR lands rather than being closed now.

## Change summary

Agent-host session shutdown logs an error because sampling-interest release is attempted after the SDK session has already been disposed.

## Best solution

Land https://github.com/microsoft/vscode/pull/336242 (or an equivalent fix) so the sampling interest is released before the SDK session wrapper is disposed, instead of in a disposable registered after it.

## Evidence

- **source confirms root cause:** In src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts (initializeSession, ~lines 2470-2479), the releaseInterest cleanup is registered via `this._register(toDisposable(...))` before `this._wrapper = this._register(wrapper)`. Since DisposableStore disposes in LIFO order, the wrapper (and its underlying SDK session) is torn down before the releaseInterest call runs, so the RPC call hits an already-gone session — matching the reported 'Session not found for sessionId' error.
- **linked fix PR:** Open PR https://github.com/microsoft/vscode/pull/336242 ('agentHost: release sampling interest before disconnect') targets exactly this ordering issue and has not yet merged.
- **reporter diagnosis:** benibenj's comment on 2026-09-19 traces the same two-lifetime root cause (SDK session vs. outer agent-host object) and confirms it's a cleanup-ordering bug, not a real turn failure.
