# Issue #329648 — create_session picks the wrong provider when two agents advertise the same model

[https://github.com/microsoft/vscode/issues/329648](https://github.com/microsoft/vscode/issues/329648)

## Summary

Detailed, well-diagnosed team-authored bug report already assigned to milestone 1.136.0 — a real scheduling milestone, so this stays open regardless of how thoroughly it's already been analyzed; no fix commit yet references this issue.

## Change summary

create_session/create_chat can route a child session to the wrong agent (or throw) when two agents advertise models with colliding names/ids or when a model's `provider` field doesn't map to a registered agent (Codex's models carry non-agent provider values like `openai`/`chatgpt`).

## Best solution

Fix resolveModel in src/vs/platform/agentHost/node/shared/sessionServerTools.ts to prefer models scoped to the calling session's own agent before falling back to a cross-agent flat search, and normalize Codex's IAgentModelInfo.provider to a real registered agent id (codex) as Claude already does via _meta.modelGroupId, per the report's own analysis.
