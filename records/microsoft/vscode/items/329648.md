# Issue #329648 — create_session picks the wrong provider when two agents advertise the same model

[https://github.com/microsoft/vscode/issues/329648](https://github.com/microsoft/vscode/issues/329648)

## Summary

Thoroughly verified against current main: model resolution flattens all agents' models into one list and matches on id-or-name in registration order, so Copilot's entries always win on name collisions, and Codex's models carry a non-agent `provider` value ('copilot' or a picker-provider string) that breaks routing entirely on lookup. Routing to the agent-host area for a fix.

## Change summary

create_session/create_chat can route to the wrong agent (or throw) when resolving a model by name, because getModels()/resolveModel() ignore which agent actually owns a model.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts and shared/sessionServerTools.ts, make resolveModel prefer the calling session's own agent's models before falling back to a flattened cross-agent list, and fix Codex's model entries (codex/codexAgent.ts) to stamp the real registered provider id ('codex') instead of 'copilot'/pickerProvider, moving the picker grouping into _meta as Claude already does.
