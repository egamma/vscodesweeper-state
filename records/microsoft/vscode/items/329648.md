# Issue #329648 — create_session picks the wrong provider when two agents advertise the same model

[https://github.com/microsoft/vscode/issues/329648](https://github.com/microsoft/vscode/issues/329648)

## Summary

Real, carefully traced bug in agent-host session creation with a milestone already assigned (1.134.0), so it stays open for scheduled work regardless of author association.

## Change summary

create_session/create_chat can route a child session to the wrong agent (or throw) when two agents advertise models with colliding names/ids or non-agent provider tokens.

## Best solution

Fix resolveModel/getModels in src/vs/platform/agentHost/node/shared/sessionServerTools.ts and src/vs/platform/agentHost/node/agentService.ts to key model lookup by (agent, id) instead of a flattened first-match list, and normalize Codex's IAgentModelInfo.provider (src/vs/platform/agentHost/node/codex/codexAgent.ts:1380,1431) to a registered agent id rather than 'copilot'/'openai'/'chatgpt', mirroring how Claude keeps provider:'claude' and pushes the picker token into _meta.modelGroupId.

- **getModels flattening:** src/vs/platform/agentHost/node/agentService.ts:858-865 pushes every provider's models into one array in registration order with no per-agent grouping, confirming the ordering-dependent collision.
- **provider stamping:** sessionServerTools.ts:601 (`const provider = args.model?.provider ?? defaults?.provider;`) copies the resolved model's own provider field into the new session config, so a mismatched model.provider silently redirects the session.
- **Codex non-agent provider tokens:** src/vs/platform/agentHost/node/codex/codexAgent.ts:1380 and :1431 stamp provider: 'copilot' or a picker token ('openai'/'chatgpt') that is not one of the registered agent ids ('copilotcli','claude','codex'), which would make agentService.ts's provider lookup (~line 1190-1200: 'No agent provider registered for: ...') throw even without any name collision.
