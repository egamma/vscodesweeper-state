# Issue #329648 — create_session picks the wrong provider when two agents advertise the same model

[https://github.com/microsoft/vscode/issues/329648](https://github.com/microsoft/vscode/issues/329648)

## Summary

Real, unfixed bug confirmed on current main by tracing the source; the issue also carries a real milestone (1.135.0) and is team-authored, both of which bar a close regardless — this stays open for a fix.

## Change summary

create_session/create_chat model resolution flattens all agents' models into one list and matches the first id-or-name hit, so requesting a model by name can silently route the session to the wrong agent (or, for Codex, throw because its model.provider isn't a registered agent id).

## Best solution

Fix resolveModel (sessionServerTools.ts) to prefer a match scoped to the calling/target agent's own provider before falling back to a global id/name search, and fix codexAgent.ts to stop stamping IAgentModelInfo.provider with non-registered ids ('copilot', 'openai', 'chatgpt', etc.) — keep the picker-grouping token in _meta the way Claude does.
