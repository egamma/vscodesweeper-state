# Issue #237087 — [Accessibility, Mouse]: When using the mouse to navigate a menu, the content behind the menu is reported to the screen reader.

[https://github.com/microsoft/vscode/issues/237087](https://github.com/microsoft/vscode/issues/237087)

## Summary

Keep open: reading content behind an open Help menu is distinct from the general mouse-tracking failure previously proposed as a duplicate. Chromium/NVDA provider behavior has changed since the report, but the supplied Windows, NVDA, and Mouse Enhancement steps suffice to retest; source inspection cannot establish the current spoken result.

## Change summary

NVDA mouse tracking announces obscured background content while the pointer navigates an open Help menu on a non-editor page.

## Best solution

Make screen-reader mouse hit testing respect the visible menu rather than expose obscured background content. First reproduce on Windows and distinguish VS Code menu behavior from native accessibility-provider or NVDA add-on behavior before assigning the implementation boundary.
