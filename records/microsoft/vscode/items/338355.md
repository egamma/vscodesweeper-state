# Issue #338355 — Side-by-side chats should have a close button

[https://github.com/microsoft/vscode/issues/338355](https://github.com/microsoft/vscode/issues/338355)

## Summary

Fresh, well-scoped UX polish for the still-prototype Agents window side-by-side chat panels: closing a chat pane is currently reachable only via the right-click context menu / toolbar overflow, not a visible inline close button, which is a reasonable ask given VS Code's own editor-tab convention.

## Change summary

When chat groups are arranged side by side without a visible tab strip, there is no inline close (×) button on the pane — users must use the context menu to close it.

## Best solution

Surface the existing `sessions.chatCompositeBar.close` (CloseChatAction, already wired with a `Codicon.closeSmall` icon and `SessionActiveChatIsClosableContext`) as a primary/navigation toolbar action on non-tabbed chat group headers, mirroring how editor tabs show an inline close button, rather than only in `Menus.SessionHeaderContext` / the toolbar overflow.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/sessionsActions.ts`, `src/vs/sessions/browser/parts/chatGroupsView.ts`, `src/vs/sessions/browser/parts/chatGroupView.ts`
- **Validation:** Manual check: with two chats arranged side by side (no tab strip), each pane's header shows a visible close (×) affordance that invokes CloseChatAction without needing the context menu.
- **Behavior:**

  > When chat panes are shown side by side without a tab strip, each pane should expose a visible close affordance (not just a context-menu entry) so users can close that chat directly, consistent with how editor groups/tabs expose inline close buttons. Existing keybindings (Ctrl/Cmd+W) and the context menu entry should keep working unchanged.
- **Trace:**

  > CloseChatAction (id sessions.chatCompositeBar.close, src/vs/sessions/contrib/sessions/browser/sessionsActions.ts ~line 850) already exists with a close icon and is wired into Menus.SessionChatTab, Menus.SessionBarToolbar ('secondary/4_pin' — overflow group), and Menus.SessionHeaderContext (right-click). The gap is that non-tabbed group headers (tabsVisible=false in ChatGroupsView, src/vs/sessions/browser/parts/chatGroupsView.ts) have no primary/navigation-group toolbar entry for this action. Do not touch the tab-strip case (already has inline close) or the keybinding/context-menu behavior — only add/adjust a menu contribution for the no-tab-strip header. Related design work: https://github.com/microsoft/vscode/issues/325220.
- **Open decisions:**
  - Should the close button always be visible on the pane header, or only on hover (mirroring editor tabs)?
  - Should this placement be coordinated with the pending side-by-side arrangement affordance study in #325220, or shipped independently now?

## Evidence

- **existing close command:** src/vs/sessions/contrib/sessions/browser/sessionsActions.ts registers CloseChatAction (id sessions.chatCompositeBar.close) with icon Codicon.closeSmall, menu entries in Menus.SessionChatTab (tab navigation), Menus.SessionBarToolbar (group 'secondary/4_pin', i.e. overflow), and Menus.SessionHeaderContext (right-click context menu) — no primary/navigation toolbar entry for the no-tab-strip case.
- **side-by-side grid model:** src/vs/sessions/browser/parts/chatGroupsView.ts implements chat groups arranged in a grid (like editor groups) with a per-group `tabsVisible` flag; when a group has a single chat and no tab strip, the only close entry point is the context menu, matching the reporter's video.
- **related umbrella:** https://github.com/microsoft/vscode/issues/325220 tracks broader 'clearer affordance for arranging chat panels side by side' UX work (prototype variants + user study) but does not itself cover the missing close button; it's a design umbrella, not a canonical duplicate of this specific ask.
