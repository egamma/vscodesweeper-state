# Issue #137143 — Language Packs add a line to Command Palette

[https://github.com/microsoft/vscode/issues/137143](https://github.com/microsoft/vscode/issues/137143)

## Summary

Keep this accepted request open: current source still enables English secondary labels automatically for localized installations, without a user-facing override. The maintainer explicitly accepted an option, so the intentional default is not grounds for an as-designed close.

## Change summary

Allow users of language packs to obtain a single-line Command Palette by hiding English secondary labels or displaying commands only in English.

## Best solution

Provide an opt-in compact presentation in the workbench Command Palette while preserving the existing bilingual default. Settle whether the option affects only secondary-label visibility or also command language and English-name search.

- **Behavior:**

  > Language-pack users currently see localized command names with distinct English names on a second line, reducing the number of visible commands. The requested option should allow a single-line palette without requiring the entire application to switch to English. Existing bilingual presentation remains the default. Acceptance must cover localized global and editor commands, commands whose original and translated names coincide, command execution, and the agreed English-name search behavior.
- **Trace:**

  > CommandsQuickAccessProvider in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts selects showAlias solely from Language.isDefaultVariant(); its configuration path has no user override. Global picks retain original titles/categories as commandAlias, and editor picks retain editorAction.alias. AbstractCommandsQuickAccessProvider in src/vs/platform/quickinput/browser/commandsQuickAccess.ts independently matches aliases in _getPicks and exposes them as secondary detail in toCommandPick, establishing that visibility and search are separate concerns. Configuration declarations live in src/vs/workbench/browser/workbench.contribution.ts and src/vs/workbench/browser/quickaccess.ts. Preserve default bilingual behavior, command identity, execution, keybindings, history, and non-command quick-access providers. The maintainer accepted an option at https://github.com/microsoft/vscode/issues/137143#issuecomment-985564832, but the record does not settle whether it is presentation-only, changes search, or provides English-only labels. https://github.com/microsoft/vscode/issues/50836 concerns custom aliases and is not a duplicate.
- **Open decisions:**
  - Should the option hide English secondary labels while retaining localized labels and English-name search, or should it also offer English-only command labels or disable English-name matching?
