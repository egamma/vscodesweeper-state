# Issue #198434 — Find and Replace in Jupyter Notebooks

[https://github.com/microsoft/vscode/issues/198434](https://github.com/microsoft/vscode/issues/198434)

## Summary

Still reproducible on main: notebook find-and-replace does not respect cursor position and snaps back after a single replacement. The `replaceOne` flow in the find widget does not advance the current match index after the text edit, and the match recomputation can lose the user's position.

## Change summary

Notebook find-and-replace always starts from the first match in the file instead of the cursor position, and after clicking Replace, the selection snaps back to the first match.

## Best solution

Fix the `replaceOne` flow in `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts` to advance `_currentMatch` to the next match after a successful replacement, similar to how the standard editor find widget works. The `find({previous: false})` call after replace should also seed the initial position from the focused cell rather than index 0 when `_currentMatch` is -1.
