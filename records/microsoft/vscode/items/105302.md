# Issue #105302 — Hover not showing on inline decorations

[https://github.com/microsoft/vscode/issues/105302](https://github.com/microsoft/vscode/issues/105302)

## Summary

Keep open: the inline-decoration hover failure was corroborated during Metals integration, and neither the related extension-side fix nor the inspected current hover path establishes that it is resolved. The supplied example is sufficient to retest; current mouse hit-testing needs confirmation before implementation.

## Change summary

Show a decoration's hover message when the pointer is over its injected after-content, including when ordinary source text follows it.

## Best solution

Make hover targeting consistently associate visible after-content with its owning decoration without requiring an enlarged source range. First confirm the supplied case against current editor hit-testing, then preserve ordinary language hovers and end-of-line decoration behavior.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/mouseTarget.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/contrib/hover/browser/contentHoverWidgetWrapper.ts`, `src/vs/editor/contrib/hover/browser/contentHoverComputer.ts`, `src/vs/editor/contrib/hover/test/browser/contentHover.test.ts`
- **Validation:** Use an extension-host development window to apply the supplied zero-length after-content decoration to a line containing text beyond character 5. Hover across the rendered decoration and verify that 'test message' appears; repeat at end of line and verify neighboring source-token language hovers remain intact. The planning session should identify an automated regression check for the observed mouse-target-to-decoration path.
- **Behavior:**

  > An extension supplies a zero-length decoration with after-content text and a hover message. Hovering the visible decoration should expose that message even when ordinary source text follows its insertion point. The same behavior should remain available at end of line, without extending the decoration across unrelated source text. Ordinary language hovers on neighboring source tokens must remain functional.
- **Trace:**

  > The original example and the Metals integration PR at https://github.com/scalameta/metals/pull/2103 establish the historical failure. AbstractCodeEditorService renders the after-content through afterContentClassName and ::after CSS. ContentHoverWidgetWrapper derives a hover anchor from the mouse target; ContentHoverComputer._getLineDecorations filters by the anchor's source range before MarkdownHoverParticipant reads hoverMessage. The unresolved point is how current MouseTargetFactory maps pointer positions across this CSS-generated content when another source character follows. Confirm that mapping before identifying the bounded fix; do not replace the extension decoration API with inlay hints or change unrelated source-hover semantics. The closed report at https://github.com/microsoft/vscode/issues/112733 concerns an invalid payload and does not settle this case.
