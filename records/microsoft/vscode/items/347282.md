# Issue #347282 — [GB Cert][VS Code]: The output GB18030 string contains corrupted characters, such as ▶ in the Terminal panel.

[https://github.com/microsoft/vscode/issues/347282](https://github.com/microsoft/vscode/issues/347282)

## Summary

The supplied string includes private-use Powerline characters that the terminal intentionally renders as symbols, including a filled triangle. An existing setting disables this substitution and uses the configured font instead.

## Change summary

Display the supplied GB18030 test string using font-provided glyphs rather than terminal Powerline symbols.

## Best solution

Keep the documented default behavior and use "terminal.integrated.customGlyphs": false for font-based rendering of the test string. The selected font must provide the desired private-use glyphs; disabling substitution cannot supply missing font coverage.

  > Thanks for the report. The supplied string includes private-use characters such as U+E0B0, which the terminal intentionally draws as a Powerline triangle. Set "terminal.integrated.customGlyphs": false and reopen the terminal to use the configured font instead. That font must contain the desired private-use glyphs; otherwise they may appear as missing-glyph boxes. This behavior is documented and was also verified in https://github.com/xtermjs/xterm.js/issues/6292#issuecomment-6591529893.

- **Documented behavior and existing control:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:598-609 documents custom rendering for Powerline private-use characters U+E0A0–U+E0D4, enabled by default. src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:933-974 passes terminal.integrated.customGlyphs to the WebGL addon.
- **Verified precedent:** https://github.com/xtermjs/xterm.js/issues/6292#issuecomment-6591529893 closes the same GB18030/private-use substitution behavior as designed after Windows verification.
