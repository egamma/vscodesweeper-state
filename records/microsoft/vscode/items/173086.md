# Issue #173086 — [html] format on paste removes whitespace

[https://github.com/microsoft/vscode/issues/173086](https://github.com/microsoft/vscode/issues/173086)

## Summary

This remains necessary as upstream HTML formatter work: a maintainer confirmed that range formatting can remove whitespace needed by the surrounding content, and the current built-in HTML extension still delegates that operation to vscode-html-languageservice. No open canonical or issue-specific fix was found.

## Change summary

Preserve semantic whitespace when HTML format-on-paste formats a pasted range, including whitespace within or adjacent to string and text content.

## Best solution

Correct range formatting in microsoft/vscode-html-languageservice so pasted fragments retain whitespace that is semantically required by their surrounding HTML, add a regression test matching this report, and then consume the updated language-service package in the built-in HTML extension.

## Evidence

- **maintainer diagnosis:** The maintainer confirmed that format-on-paste formats only the pasted range and can remove whitespace without knowing that the surrounding document requires it: https://github.com/microsoft/vscode/issues/173086#issuecomment-1413390567.
- **current code path:** extensions/html-language-features/server/src/modes/formatting.ts passes the paste range to htmlMode.format, and extensions/html-language-features/server/src/modes/htmlMode.ts delegates directly to htmlLanguageService.format.
- **upstream formatter:** The current formatter implementation in https://github.com/microsoft/vscode-html-languageservice/blob/main/src/services/htmlFormatter.ts expands or trims whitespace around the requested range before passing the fragment through html_beautify; ownership of the reported whitespace transformation is therefore in the language-service dependency.
- **related precedent:** https://github.com/microsoft/vscode/issues/26297 reported the same observable loss of a separating space inside an HTML class value, but it is closed and its 2017 fix predates this 2023 report, so it cannot serve as an open duplicate canonical or prove the newer case resolved.
