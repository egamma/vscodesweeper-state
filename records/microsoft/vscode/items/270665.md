# Issue #270665 — Refactor noValidationMessage to be prompt

[https://github.com/microsoft/vscode/issues/270665](https://github.com/microsoft/vscode/issues/270665)

## Summary

The requested cleanup remains outstanding: current main still uses noValidationMessage in QuickInput and implements prompt separately in its subclasses. Keep this maintainer-authored backlog item open; the merged QuickPick prompt PR supplied the original capability, not this follow-up refactor.

## Change summary

Replace the base class's noValidationMessage abstraction with prompt handling that gives each quick-input implementation its appropriate default.

## Best solution

Give the shared quick-input abstraction coherent prompt semantics, with no default prompt for QuickPick, QuickTree, or QuickWidget and InputBox retaining its localized input guidance and custom prompt behavior. Preserve validation-message precedence and existing public prompt behavior.
