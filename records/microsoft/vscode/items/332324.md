# Issue #332324 — Dictation replaces or deletes the correct visible transcript after Stop, even with llmCleanup disabled

[https://github.com/microsoft/vscode/issues/332324](https://github.com/microsoft/vscode/issues/332324)

## Summary

The reporter did unusually thorough source-level tracing, and I independently confirmed the same code paths on current main: beginFinalize() clears interim styling immediately, then the async final transcript unconditionally replaces the whole previously-shown region via LiveTranscriptInserter.update(), and the local transcription backend clears _partialText on every is_final event regardless of whether the final text actually captured that content. This is a real, still-open defect; a maintainer has only asked for a repro GIF so far and it's too fresh to close.

## Change summary

After pressing Stop, dictation can silently drop or replace visible transcript text because the finalize path unconditionally overwrites the previously-inserted region with a possibly shorter/different backend transcript, independent of the llmCleanup setting.

## Best solution

In src/vs/workbench/contrib/chat/browser/speechToText/dictationSession.ts, the finalize step (finalizeDictation / LiveTranscriptInserter.update) should reconcile the final transcript against the already-visible interim text (e.g. only apply the final replacement if it doesn't shrink/drop content, or merge rather than blindly replacing the whole anchor..end range) and src/vs/platform/localTranscription/node/localTranscriptionService.ts should not discard _partialText content that never made it into a final segment.
