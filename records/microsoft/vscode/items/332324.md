# Issue #332324 — Dictation replaces or deletes the correct visible transcript after Stop, even with llmCleanup disabled

[https://github.com/microsoft/vscode/issues/332324](https://github.com/microsoft/vscode/issues/332324)

## Summary

This is a real, source-confirmed bug: dictated text visibly disappears or gets overwritten after Stop, independent of the llmCleanup setting, and it's now backed by a video and a second independent reproduction with trace logs.

## Change summary

Stopping dictation can silently delete or replace part of the transcript the user already saw and expected to be kept.

## Best solution

In src/vs/workbench/contrib/chat/browser/speechToText/dictationSession.ts, finalizeDictation()/LiveTranscriptInserter.update() should reconcile the backend's final transcript with the already-visible interim text (e.g. only append/replace the delta) rather than blindly replacing the whole tracked range with whatever stopAndTranscribe() returns, and the backend accumulators (localTranscriptionService.ts addFinal/`_partialText = ''`, and the MAI cloud path) should not discard interim text before it has a confirmed final replacement.

## Evidence

- **beginFinalize clears interim styling but not text:** dictationSession.ts lines ~221-230: beginFinalize() sets `_finalized = true` and clears `_processingDecorations` immediately on Stop, matching the reporter's described grey→white transition.
- **update() replaces whole tracked range:** LiveTranscriptInserter.update() (dictationSession.ts ~138-170) always replaces `Range.fromPositions(this._anchor, this._end)` with the new cumulative text, so a shorter/different final string deletes previously-visible content — confirmed by reading the code directly.
- **backend clears partial text on every final segment:** localTranscriptionService.ts ~562-579: `_consume()` calls `this._accumulator.addFinal(text, ...)` then unconditionally `this._partialText = ''`, discarding any interim tail even if the final text is empty or shorter.
- **independent confirmation:** Comment from ShokiTokunaga on 2026-08-25 reproduces the same class of bug with the MAI Cloud backend and attached trace logs, and cosmicnet posted a screen recording (comment on 2026-08-25) showing the transcript vanish ~2 seconds after Stop.
