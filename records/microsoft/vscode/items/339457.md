# Issue #339457 — Unable to delete a model/model group from "Chat: Manage Language Models"

[https://github.com/microsoft/vscode/issues/339457](https://github.com/microsoft/vscode/issues/339457)

## Summary

Traced the defect in source: for BYOK provider groups whose vendor has no `configuration` schema, the Manage Language Models actions column renders zero actions — including Delete — even though the underlying removeLanguageModelsProviderGroup API works regardless of a configuration schema. This is a real, bounded gap, not something fixed on main.

## Change summary

The 'Chat: Manage Language Models' view shows no Delete action for some model/model groups, so the user cannot remove them from the UI.

## Best solution

Always offer a Delete action for an existing provider group row in chatModelsWidget.ts's actions column, instead of gating the whole action set (including Delete) behind `vendor.configuration` being truthy.

- **Trace:**

  > ActionsColumnRenderer.renderVendorElement() in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts (~line 1021) branches on `vendorEntry.vendor.configuration` vs `vendorEntry.vendor.managementCommand` with no fallback; createProviderGroupActions() (~line 918) early-returns `[]` when there's no `configuration` object at all, so Delete (built at ~line 958) never gets created for such vendors. languageModels.ts (~line 1352) confirms configuration-less vendors can still have real, user-created groups (comment cites multi-instance Ollama-style setups) backed by `removeLanguageModelsProviderGroup`, which has no configuration dependency. ## Evidence

- **gated delete action:** src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts: createProviderGroupActions() (lines ~918-975) returns `[]` immediately when `vendor.configuration` is undefined (line ~925-928), and it is the only place a 'deleteAction' (Codicon.trash, calling languageModelsService.removeLanguageModelsProviderGroup) is created.
- **caller gating:** ActionsColumnRenderer.renderVendorElement() (lines ~1021-1039) only calls createProviderGroupActions when `vendorEntry.vendor.configuration` is truthy; otherwise it only checks `vendor.managementCommand` for a 'Manage...' action — if neither is set, `actionBar.setActions([], [])` leaves the row with zero actions.
- **configuration-less groups are real:** src/vs/workbench/contrib/chat/common/languageModels.ts lines ~1348-1364 explicitly handle 'vendors without a configuration schema' that still have named groups with per-model settings, with a code comment citing 'multiple Ollama servers' as the motivating case — so such deletable groups legitimately exist with `vendor.configuration === undefined`.
- **removal API is configuration-agnostic:** removeLanguageModelsProviderGroup(vendorId, groupName) in languageModels.ts has no dependency on a configuration schema, so there's no backend reason to withhold the Delete action for these vendors.
