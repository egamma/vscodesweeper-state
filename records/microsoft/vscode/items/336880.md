# Issue #336880 — Extension signature verification fails with "Untrusted" / Internal Code 36

[https://github.com/microsoft/vscode/issues/336880](https://github.com/microsoft/vscode/issues/336880)

## Summary

Real, well-diagnosed report, but the actual verification logic lives outside this repo (the native @vscode/vsce-sign module and the Windows/DigiCert certificate chain), which VS Code's ExtensionSignatureVerificationService just invokes — this is an upstream/infra problem, not a core code defect, and it matches a growing cluster of nearly identical open reports.

## Change summary

Extension installs from the Marketplace fail with 'Untrusted' (Internal Code 36) because vsce-sign reports the DigiCert code-signing chain as 'NotValidForUsage', even though Windows itself builds the same chain successfully.

## Best solution

Route to the extensions/marketplace signing owners to investigate the vsce-sign certificate-chain validation (chain status 'NotValidForUsage') against the current DigiCert Trusted G4 code-signing CA — likely a vsce-sign or certificate-infrastructure issue, not something fixable in src/vs/platform/extensionManagement.
