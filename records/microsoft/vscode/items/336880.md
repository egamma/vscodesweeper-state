# Issue #336880 — Extension signature verification fails with "Untrusted" / Internal Code 36

[https://github.com/microsoft/vscode/issues/336880](https://github.com/microsoft/vscode/issues/336880)

## Summary

Well-diagnosed report of a real signature-verification false positive; the actual chain-validation logic lives in the bundled `@vscode/vsce-sign` native module, not in this repo, so this stays open as an upstream issue rather than something to close or fix directly here.

## Change summary

Extension installs on Windows fail with 'Untrusted' (Internal Code 36) because the bundled vsce-sign verifier rejects a DigiCert code-signing chain that Windows itself validates fine, blocking installation of any extension.

## Best solution

Track this against the `@vscode/vsce-sign` dependency (currently 2.0.6 per build/package-lock.json) — the chain-status mismatch (Windows: None vs vsce-sign: NotValidForUsage) needs to be root-caused and fixed in that native module/its bundled CA logic, then picked up here via a version bump.
