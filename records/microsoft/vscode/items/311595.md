# Issue #311595 — Add `requestTimeout` option for MCP server tool calls

[https://github.com/microsoft/vscode/issues/311595](https://github.com/microsoft/vscode/issues/311595)

## Summary

The requested per-server tool-call timeout remains missing from the current MCP configuration and request path. Keep this open for product discussion; neither the related timeout reports nor the lack of upvotes establishes a valid closing reason.

## Change summary

Allow an MCP server configuration to specify a tool-call deadline so an unresponsive server does not indefinitely block the agent.

## Best solution

Evaluate an opt-in per-server tool-call timeout with an explicit timeout result that the agent can handle, while preserving existing behavior when omitted. Settle its interaction with long-running MCP tasks and cancellation before implementation; model-provider request timeouts are a separate request.

- **Current request path:** In src/vs/workbench/contrib/mcp/common/mcpServerRequestHandler.ts, callTool awaits sendRequest for tools/call and can subsequently await an MCP task result. sendRequest forwards a cancellation token to JsonRpcProtocol without a timeout argument; its timeoutMs documentation does not correspond to an implemented parameter. src/vs/base/common/jsonRpcProtocol.ts tracks pending requests and cancellation but supplies no request timer.
- **Different timeout surfaces:** The 30-second mcpServerRequestTimeout in src/vs/platform/mcp/common/mcpGalleryService.ts applies to gallery requests, not tool invocation. Server-startup waits and task TTL handling likewise do not provide the requested configurable tool-call deadline.
