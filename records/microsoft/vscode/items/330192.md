# Issue #330192 — Enable extensions for VS Code Agents Window to allow Terraform syntax highlighting 

[https://github.com/microsoft/vscode/issues/330192](https://github.com/microsoft/vscode/issues/330192)

## Summary

The Agents Window already runs declarative, code-free extensions — including grammar/language contributions used for syntax highlighting — since PR #314415 (merged May 2026, well before this report); only extensions that ship executable code (`main`/`browser`) are blocked by design, with an opt-in `extensions.supportAgentsWindow` override for those. A pure Terraform syntax-highlighting extension should already work there.

## Change summary

Requests that extensions be enabled in the Agents Window so Terraform files get syntax highlighting there.

## Best solution

Point the reporter at installing a declarative (grammar-only, no `main`/`browser`) Terraform syntax-highlighting extension, which `ExtensionManifestPropertiesService.canExecuteOnSessionsWindow` (src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts) already permits in the Agents Window; if their preferred Terraform extension bundles a language server (code), that remains blocked by the sandboxing design and would need the `extensions.supportAgentsWindow` opt-in.

## Vision fit

- **Reason:** Agent security/sandboxing for the Agents Window is an explicit current-priority workstream, and this architecture (declarative-only by default, opt-in override for code) is exactly that tradeoff already implemented.
- **Evidence:** Current priorities: agent security workstream covers sandboxing for local agents so approvals get less painful without sacrificing security.

## Evidence

- **allowed contribution points:** src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts defines SESSIONS_WINDOW_ALLOWED_CONTRIBUTION_POINTS including 'grammars' and 'languages'; canExecuteOnSessionsWindow() returns true for any manifest with no `main`/`browser` whose contribution points are all in that set.
- **shipped well before report:** This logic was introduced by PR https://github.com/microsoft/vscode/pull/314415 ('Add extension support in sessions window and disable certain themes'), merge commit e475904a539464f19370356ab17a7c367ae1b755, merged 2026-05-05 — over three months before this Aug 11, 2026 issue (reported against 1.132.0).
- **test coverage:** src/vs/workbench/services/extensions/test/common/extensionManifestPropertiesService.test.ts asserts a themes-only (no-code) manifest returns canExecuteOnSessionsWindow === true, while one with `main` returns false — confirming declarative extensions like grammar/language contributions are enabled by design.
- **opt-in override:** EXTENSIONS_SUPPORT_AGENTS_WINDOW ('extensions.supportAgentsWindow', renamed from supportSessionsWindow in PR https://github.com/microsoft/vscode/pull/315265) lets a user force-enable a specific code-bearing extension if they accept the tradeoff.
