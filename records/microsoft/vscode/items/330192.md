# Issue #330192 — Enable extensions for VS Code Agents Window to allow Terraform syntax highlighting 

[https://github.com/microsoft/vscode/issues/330192](https://github.com/microsoft/vscode/issues/330192)

## Summary

A real gap remains: users can manually opt `hashicorp.terraform` into the Agents Window, but it is disabled there by default, so Terraform language and grammar contributions are not available automatically. The Backlog milestone records maintainer acceptance, and no older open canonical owns this specific behavior.

## Change summary

Make Terraform syntax highlighting available in the Agents Window without requiring a manual extension-support override.

## Best solution

Installed Terraform extensions should provide their declarative language and grammar contributions in the Agents Window without requiring users to enable unsupported runtime behavior manually. Maintainers should decide whether that means selectively loading safe declarative contributions or allowing the complete HashiCorp extension after compatibility validation.

## Plan brief

- **Likely files:** `src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts`, `src/vs/workbench/services/extensions/test/common/extensionManifestPropertiesService.test.ts`, `src/vs/workbench/services/extensionManagement/test/browser/extensionEnablementService.test.ts`
- **Validation:** Add focused extension-manifest and enablement tests for the chosen contract, then open an installed-extension-backed `.tf` file in the Agents Window and verify Terraform tokenization works without `extensions.supportAgentsWindow`, while unsupported executable contributions remain unavailable if that is the selected boundary.
- **Behavior:**

  > When the HashiCorp Terraform extension is installed, opening a `.tf` or `.tfvars` file in the Agents Window should provide Terraform language identification and syntax highlighting without a manual `extensions.supportAgentsWindow` entry. The normal editor experience must remain unchanged. Acceptance must also verify that the selected compatibility boundary does not unintentionally expose extension capabilities that the Agents Window does not support.
- **Trace:**

  > `ExtensionManifestPropertiesService.canExecuteOnSessionsWindow` in `src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts` permits declarative language and grammar extensions but rejects manifests containing `main` or `browser` entry points. The HashiCorp Terraform manifest at https://github.com/hashicorp/vscode-terraform/blob/main/package.json contains both executable entry points and the required `languages` and `grammars`, so the whole extension is disabled unless the user adds the existing override. Tests in `src/vs/workbench/services/extensions/test/common/extensionManifestPropertiesService.test.ts` and `src/vs/workbench/services/extensionManagement/test/browser/extensionEnablementService.test.ts` explicitly preserve that all-or-nothing behavior. The uncertainty begins at the public compatibility boundary: whether the Agents Window may consume safe declarative contributions from an otherwise-disabled extension, or whether Terraform must opt the complete extension into execution. Keep unrelated extension contribution points and standard-editor enablement behavior out of scope.
- **Open decisions:**
  - Should the Agents Window load only Terraform's declarative language and grammar contributions while keeping its executable host code disabled, or require the complete extension to declare Agents Window compatibility?
  - If complete extension execution is required, should compatibility be enabled by VS Code policy or only through an explicit declaration from the Terraform extension?

## Evidence

- **current gate:** `src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts` allows declarative `languages` and `grammars`, but `canExecuteOnSessionsWindow` rejects any extension with a `main` or `browser` entry point unless explicitly overridden or declared compatible.
- **Terraform manifest:** https://github.com/hashicorp/vscode-terraform/blob/main/package.json contributes Terraform languages and TextMate grammars but also has executable `main` and `browser` entry points and does not declare the Agents Window capability, so current VS Code disables it by default.
- **existing workaround:** `extensions.supportAgentsWindow` can opt `hashicorp.terraform` in manually; its registration in `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts` says entries set to `true` are enabled despite the environment gate. https://github.com/microsoft/vscode/pull/315265 shows this capability predates the report, so it is a workaround rather than a later implementation of the request.
