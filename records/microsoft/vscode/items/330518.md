# Issue #330518 — [Insiders] "Steer with Message" appears to terminate an active agent run instead of continuing it

[https://github.com/microsoft/vscode/issues/330518](https://github.com/microsoft/vscode/issues/330518)

## Summary

Fresh, well-documented report against the Copilot agent-host harness. Tracing the steering-turn logic in copilotAgentSession.ts shows a real fragility: the steering message is only promoted into its own turn if the SDK's echoed `user.message` content exactly string-matches the buffered steering text; if it doesn't match (trimming, normalization, attachments, etc. by the SDK), the message silently falls through as an ordinary turn with no log or fallback, matching the reporter's transcript exactly.

## Change summary

Using "Steer with Message" while an agent is mid-tool-call appears to just replace the response instead of interrupting/continuing the active tool workflow, and the transcript shows no steering/interruption metadata at all.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, `_takeMatchingPendingSteering` (called from the `onUserMessage` handler around line 3674) matches purely on exact text equality between the buffered `PendingMessage` and the SDK-echoed `user.message` content, with no logging or fallback when no match is found. An agent-host/chat area owner should confirm whether the Copilot CLI SDK can echo steering content non-verbatim, and if so add a fallback (e.g. FIFO match) or at least diagnostic logging so silent steering failures are observable and fixable.
