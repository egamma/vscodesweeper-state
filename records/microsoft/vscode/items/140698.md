# Issue #140698 — [html] Improve `html.autoCreateQuotes` to handle manually typed quotes

[https://github.com/microsoft/vscode/issues/140698](https://github.com/microsoft/vscode/issues/140698)

## Summary

This team-authored Backlog request remains open because manually typed quotes can still race with asynchronous HTML quote insertion, and the thread identifies an unresolved editor API limitation rather than a completed fix or verified duplicate.

## Change summary

Make `html.autoCreateQuotes` coexist with manually typed quotes so fast typing does not produce duplicated or misplaced quotes.

## Best solution

Resolve the editor-side snippet/application behavior tracked by https://github.com/microsoft/vscode/issues/146171, then let the built-in HTML extension treat a manually typed quote as overtyping the pending auto-inserted quote without disturbing the attribute value or cursor.

## Plan brief

- **Likely files:** `extensions/html-language-features/client/src/autoInsertion.ts`, `src/vs/workbench/api/browser/mainThreadEditor.ts`
- **Validation:** Add an editor/HTML integration test that types `<div class="asd">` character-by-character with `html.autoCreateQuotes` enabled and asserts the final text contains one quote pair with `asd` inside it; also verify typing without manual quotes still auto-inserts the pair.
- **Behavior:**

  > With `html.autoCreateQuotes` enabled, typing an HTML attribute value character-by-character, including the user's own opening and closing quotes, must produce exactly one quote pair around the value. Automatic quote insertion must continue to work when the user omits the quotes. Acceptance covers both fast manual typing and the existing auto-insertion flow without cursor displacement or duplicated quotes.
- **Trace:**

  > The built-in HTML extension initiates quote insertion from `extensions/html-language-features/client/src/autoInsertion.ts`. The issue thread traces the problematic application path into `insertSnippet` handling in `src/vs/workbench/api/browser/mainThreadEditor.ts` and identifies https://github.com/microsoft/vscode/issues/146171 as the blocking editor-side work. The failure is timing-sensitive: extension insertion may arrive after the user has already typed quotes or attribute text. Preserve normal snippet behavior and HTML auto-insertion for users who do not type quotes; the uncertainty starts at how pending asynchronous edits should interact with intervening user input.
- **Open decisions:**
  - When user input arrives before an asynchronous quote insertion is applied, should the insertion be rebased to overtype matching user-entered quotes, or cancelled whenever the document version has changed?
