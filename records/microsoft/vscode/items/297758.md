# Issue #297758 — forks from the same convo all look the same

[https://github.com/microsoft/vscode/issues/297758](https://github.com/microsoft/vscode/issues/297758)

## Summary

Current main still assigns the same `Forked: <source title>` label to every fork of a conversation, leaving multiple forks visually indistinguishable. This team-authored test finding should remain open while the fork-labeling UX is designed.

## Change summary

Make multiple forks from the same chat conversation distinguishable in the session UI.

## Best solution

Give each fork a stable, recognizable display identity that preserves its relationship to the source conversation while distinguishing its branch point from sibling forks.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatForkActions.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatForkActions.test.ts`
- **Validation:** Extend the `ForkConversationAction` tests to create two forks from one titled source conversation and assert that their displayed titles are distinct while both retain recognizable source-conversation context.
- **Behavior:**

  > Creating multiple forks from the same conversation must produce session entries that users can distinguish from one another. Each entry should still communicate which source conversation it belongs to, and its identity should remain stable when revisiting the session. Acceptance should cover sibling forks created at different checkpoints and repeated forks of an already-forked conversation.
- **Trace:**

  > `ForkConversationAction.run` in `src/vs/workbench/contrib/chat/browser/actions/chatForkActions.ts` serializes a new session and assigns `customTitle` from only the source title in both the `/fork` and checkpoint paths. Consequently, sibling forks receive identical labels even though their session IDs, creation dates, and retained request ranges differ. The existing suite in `src/vs/workbench/contrib/chat/test/browser/actions/chatForkActions.test.ts` exercises fork creation but does not compare sibling display identities. Preserve the cloned-history boundaries and model-context behavior tested by https://github.com/microsoft/vscode/issues/297207; the unresolved point is only what user-visible information should distinguish branches.
- **Open decisions:**
  - Should sibling forks be identified by their branch-point prompt, by an ordinal or time-based suffix, or by another user-visible branch label?
  - Should a fork of an already-forked conversation preserve the original conversation title, the immediate parent title, or an explicit ancestry indicator?
