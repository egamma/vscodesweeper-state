# Issue #209123 — VSCode Web - Safari - File drag and drop in explorer panel

[https://github.com/microsoft/vscode/issues/209123](https://github.com/microsoft/vscode/issues/209123)

## Summary

A prior review's implemented-on-main close (citing commit 7248ff1c) was refuted by independent review, so this stays open; current source shows `.monaco-drag-image` in src/vs/base/browser/ui/dnd/dnd.css already carries global default background/color/outline, yet the issue is specifically that Safari renders the drag pill blank while Chrome does not — a global CSS default wouldn't explain a browser-specific discrepancy, so the underlying Safari-only root cause bpasero flagged ('bizarre as to why Safari behaves like that') still looks unresolved.

## Change summary

In VS Code Web on Safari, dragging a file in the Explorer shows a blank/invisible drag handle (missing color/background) instead of the file-name pill Chrome shows, even though the drop target still highlights correctly.

## Best solution

Needs a maintainer or contributor with access to Safari to re-test current main and trace why `setDragImage`/`applyDragImage` (src/vs/base/browser/dnd.ts, src/vs/base/browser/ui/list/listView.ts#L1247) renders without color specifically in Safari despite the CSS defaults now present in dnd.css; likely a Safari-specific quirk in how it paints an off-screen/body-appended drag image rather than a pure CSS specificity gap.
