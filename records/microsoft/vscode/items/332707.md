# Issue #332707 — Agent Host: clean-env agent spawn on Windows strips APPDATA/ProgramFiles/ComSpec etc., breaking dotnet/NuGet and gh in agent sessions

[https://github.com/microsoft/vscode/issues/332707](https://github.com/microsoft/vscode/issues/332707)

## Summary

Confirmed in current main: `buildSubprocessEnv` in `claudeSdkOptions.ts` builds a sparse proxied-mode env that only forwards `HOME`/`USERPROFILE` from the parent process, so on Windows every other OS-contract variable (`APPDATA`, `ProgramFiles`, `ComSpec`, `PATHEXT`, etc.) is missing from Claude agent subprocess spawns — exactly the `dotnet`/NuGet/`gh` breakage reported.

## Change summary

On Windows, Claude agent sessions (proxied/default transport) spawn with a stripped environment missing APPDATA/ProgramFiles/ComSpec/PATHEXT and other standard Windows variables, breaking dotnet/NuGet restores and gh CLI auth inside agent shells.

## Best solution

Extend the proxied branch of `buildSubprocessEnv` (src/vs/platform/agentHost/node/claude/claudeSdkOptions.ts, lines ~382-391) to forward the standard Windows system/user-profile variables the same way HOME/USERPROFILE are forwarded today, matching the issue's suggested allowlist (APPDATA, LOCALAPPDATA, ProgramData, ProgramFiles(+x86), ComSpec, PATHEXT, SystemRoot, SystemDrive, windir, OS, NUMBER_OF_PROCESSORS, PROCESSOR_*, COMPUTERNAME, PUBLIC, ALLUSERSPROFILE, DriverData) without weakening the existing VSCODE_*/ELECTRON_*/ANTHROPIC_API_KEY stripping.
