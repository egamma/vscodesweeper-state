# Issue #265301 — When WSL is closed / crashes, all open instances of VSCode have to be closed completely - reload window and attempting to reconnect fails

[https://github.com/microsoft/vscode/issues/265301](https://github.com/microsoft/vscode/issues/265301)

## Summary

This is a reproducible Remote Development WSL reconnection defect, so the thread should remain open and be transferred to the VS Code-owned microsoft/vscode-remote-release tracker rather than closed as extension-caused.

## Change summary

After WSL terminates, Reconnect Now and Reload Window repeatedly reuse a dead connection, forcing users to close every VS Code window before the session can recover.

## Best solution

Transfer the issue to microsoft/vscode-remote-release and consolidate its deterministic WSL-termination reproduction with https://github.com/microsoft/vscode-remote-release/issues/4536. The WSL resolver and shared daemon should discard stale server addresses and tokens after the distro restarts, allowing reconnection without terminating every VS Code window.
