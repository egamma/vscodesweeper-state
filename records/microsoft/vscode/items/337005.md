# Issue #337005 — Agents WSL: sandbox toggle shows off when session inherits an enabled remote host default

[https://github.com/microsoft/vscode/issues/337005](https://github.com/microsoft/vscode/issues/337005)

## Summary

Thanks for the detailed report. The code path you describe is still on main. For a session whose sandbox selection is default, the picker falls back to the local `chat.agent.sandbox.enabled` setting, so a WSL or remote host default of on can show as off.

## Change summary

The Agents window sandbox toggle ignores the connected remote host's sandbox default for sessions that inherit it, and shows the local VS Code setting instead.

## Best solution

Make the toggle and the permissions label take their inherited default from the connected host's effective sandbox setting, not the renderer's local configuration. An explicit per-session on/off selection should keep taking precedence.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/providers/agentHost/browser/agentHostPermissionPickerDelegate.ts`, `src/vs/platform/agentHost/browser/agentHostSandboxToggle.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`
- **Validation:** Add a unit test in src/vs/sessions/contrib/providers/agentHost/test/browser/agentHost/agentHostPermissionPickerDelegate.test.ts. It should assert that the toggle is checked when the session selection is default, the host reports sandboxing on, and the local setting is off. It must fail before the change and pass after.
- **Behavior:**

  > When an Agents window session connected to a remote host has no explicit sandbox selection, the Sandboxing for terminal toggle and the permissions label reflect the host's effective sandbox setting, not the local renderer setting. Explicit on/off per-session selections, managed policy and dev container behavior are unchanged. Acceptance: with the host default on and the local setting off, a default session shows the toggle on.
- **Trace:**

  > AgentHostPermissionPickerDelegate.sandboxEnabled falls back to sandboxConfirmedEnabled, which reads the host's last successful sandbox application via baseAgentHostSessionsProvider.getSessionSandboxEnabled. That value is absent for inherited-default sessions, so getSandboxToggle supplies `globalEnabled` from the local configuration and getAgentHostSandboxToggleState uses it. Where the uncertainty starts: whether the host already publishes its effective default to the client (for example in session `_meta`) or needs to start doing so. The host side is under src/vs/platform/agentHost/node (agentConfigurationService.ts, sessionFlagsContribution.ts).
- **Open decisions:**
  - Should the host publish its effective sandbox state for inherited-default sessions to the client, or should the client read the host's root configuration?
  - Should the unknown-state case (an older host that publishes nothing) keep falling back to the local setting?

## Evidence

- **fallback chain:** In src/vs/sessions/contrib/providers/agentHost/browser/agentHostPermissionPickerDelegate.ts, `sandboxEnabled` returns true for `on`, false for `off`, and otherwise `sandboxConfirmedEnabled`. `getSandboxToggle()` then passes `globalEnabled` from the local `_configurationService.getValue(AgentSandboxEnabledSettingId)`. `getAgentHostSandboxToggleState` in src/vs/platform/agentHost/browser/agentHostSandboxToggle.ts computes `checked = sessionEnabled ?? (managedEnabled || globalEnabled)`, so the local value decides the result.
- **confirmed state gap:** `sandboxConfirmedEnabled` comes from `getSessionSandboxEnabled` in baseAgentHostSessionsProvider.ts, which reads the host's last successful sandbox application from session `_meta`. A session that has never applied a selection, i.e. one inheriting the default, has no such entry, so `sessionEnabled` is undefined and the local setting is used. I traced this in the source and did not run it.
- **reporter's controlled comparison:** With the host default on and the local setting off, a `default` session shows the toggle off, `on` shows on, and `off` shows off. Only the inherited case is wrong.
