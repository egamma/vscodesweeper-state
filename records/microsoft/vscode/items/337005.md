# Issue #337005 — Agents WSL: sandbox toggle shows off when session inherits an enabled remote host default

[https://github.com/microsoft/vscode/issues/337005](https://github.com/microsoft/vscode/issues/337005)

## Summary

Team-authored (MEMBER) bug report with a source-level confirmation of the root cause; not fixed on main and already under active maintainer discussion, so this stays open — no close criteria apply.

## Change summary

The Agents window's 'Sandboxing for terminal' toggle shows off for a WSL-connected session that inherits its enabled sandbox default from the remote host, instead of reflecting the host's actual sandbox state.

## Best solution

Have AgentHostPermissionPickerDelegate.getSandboxToggle derive `globalEnabled` from the remote agent host's effective sandbox configuration for the connected session/host, rather than the renderer's local `_configurationService.getValue(settingId)`, when the session's sandbox selection is unspecified/default.
