# Issue #99276 — Tasks: Pick folder for user tasks in multi-root-workspaces

[https://github.com/microsoft/vscode/issues/99276](https://github.com/microsoft/vscode/issues/99276)

## Summary

Keep open: current source still associates user tasks with the first workspace folder, without offering the requested folder selection. This accepted On Deck request has 30 upvotes, and no verified older canonical or landed fix was found.

## Change summary

Let users choose which workspace folder a user task executes in when multiple roots are open.

## Best solution

Provide workspace-folder selection when launching a user task in a multi-root workspace, without requiring workspace-specific edits to globally reusable tasks. Settle whether the selection changes only the working directory or the task's full folder-resolution context before implementation.

- **Behavior:**

  > A user task launched in a multi-root workspace should offer a choice of the workspace folder in which it executes rather than silently using the first root. The choices should reflect the current workspace without requiring the global user task to hard-code its folders. Acceptance checks should cover selecting each root, cancelling without execution, and preserving single-root and explicitly configured working-directory behavior. The contract for folder-dependent variable resolution must be agreed before implementation.
- **Trace:**

  > AbstractTaskService._getAFolder in src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts selects the first workspace folder; _computeWorkspaceTasks passes it to _computeUserTasks and TaskConfig.parse. User-task construction in src/vs/workbench/contrib/tasks/common/taskConfiguration.ts records that folder in the task source, and CustomTask.getWorkspaceFolder in src/vs/workbench/contrib/tasks/common/tasks.ts returns it. TerminalTaskSystem._executeCommand uses it for variable resolution and terminal execution, while _resolveOptions defaults cwd to ${workspaceFolder}. Existing options.cwd and configured pickString inputs provide partial workarounds, not a dynamic workspace-root selector. Preserve global user-task definitions, folder-scoped task behavior, and no-workspace execution; the uncertainty is whether selection replaces only cwd or the broader folder context used by variables and configuration. https://github.com/microsoft/vscode/issues/120133 addresses different provider/default-build behavior and does not resolve this request.
- **Open decisions:**
  - Should the chosen workspace folder determine only the default working directory, or also the task's folder-resolution context, including ${workspaceFolder} and resource-scoped configuration?
