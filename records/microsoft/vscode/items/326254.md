# Issue #326254 — Copilot Chat otel.captureContent:false not honored on spans — chat spans carry full prompts/system instructions/responses (copilot-chat 0.57.0 in core)

[https://github.com/microsoft/vscode/issues/326254](https://github.com/microsoft/vscode/issues/326254)

## Summary

Confirmed in source: the span-attribute writes for chat content bypass the `captureContent` gate entirely, while the log-record path (genAiEvents.ts) correctly checks it — this is a real, localized bug worth fixing.

## Change summary

`github.copilot.chat.otel.captureContent: false` is honored for OTel log/metric events but not for span attributes, so full prompts, system instructions, tool args/results, and responses still land on chat spans.

## Best solution

Gate the span attribute writes in chatMLFetcher.ts (USER_REQUEST, SYSTEM_INSTRUCTIONS, INPUT_MESSAGES, TOOL_DEFINITIONS, OUTPUT_MESSAGES) and toolsService.ts (TOOL_CALL_ARGUMENTS, TOOL_CALL_RESULT) behind `this._otelService.config.captureContent`, mirroring the existing `if (otel.config.captureContent)` check already used in genAiEvents.ts:56 for the log-record path.
