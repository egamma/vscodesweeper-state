# Issue #308852 — Agents App: Changes are still in the panel even after running merge

[https://github.com/microsoft/vscode/issues/308852](https://github.com/microsoft/vscode/issues/308852)

## Summary

Keep open as a post-merge UX improvement: the remaining changes represent an intentional remote comparison, but the thread establishes that local completion and the remaining push step are confusing. This team-authored issue has no verified fixing commit or qualifying duplicate.

## Change summary

Make the Changes panel clearly distinguish locally committed or merged work from changes still awaiting a push.

## Best solution

Make successful local commit and merge outcomes understandable in the Agents Window, including why Branch Changes can remain and what action remains. Preserve the distinction between local integration and remote synchronization; decide whether explicit status alone suffices or the default changeset should also change.

- **Behavior:**

  > After a successful local merge or commit, users must be able to tell that the operation completed and understand why changes may still appear. Cover both worktree Merge Changes and folder /commit flows when local commits have not been pushed. Any retained diff must communicate its comparison scope and the relevant remaining action. A local-only action must not implicitly push merely to make the panel look clean.
- **Trace:**

  > The thread at https://github.com/microsoft/vscode/issues/308852 identifies a comparison-scope mismatch rather than failed Git integration. AgentHostChangesetService._resolveBranchBaseBranch resolves the baseline, and AgentHostGitService._resolveBranchMergeBaseCommit prefers an available remote-tracking branch, so the Branch Changes diff can survive a local merge. AgentHostMergeOperationHandler.invoke performs local commit/merge, records the outcome, refreshes state, and returns a completion message without pushing. The Changes catalogue already has branch descriptions and an Uncommitted Changes alternative; SessionSyncChangesContribution exposes counted sync controls for eligible folder sessions. What remains uncertain is whether these surfaces sufficiently explain the post-operation state in both reported flows and whether the default scope should change. Coordinate with https://github.com/microsoft/vscode/issues/336620 without replacing this narrower report. Preserve local-versus-remote action boundaries and unrelated session/checkpoint diff semantics.
- **Open decisions:**
  - Should successful local commit or merge retain the selected Branch Changes view with explicit completion and remaining-step status, or switch the default presentation to a clean local/uncommitted view?
