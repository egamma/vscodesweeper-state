# Issue #330912 — Invalid model in .prompt.md file blocks sending and subsequent messages

[https://github.com/microsoft/vscode/issues/330912](https://github.com/microsoft/vscode/issues/330912)

## Summary

Traced a real hang on main: an unmatched `model:` value in a prompt file's frontmatter leaves the chat input's programmatic model request pending forever, so the request that triggered it never completes and the widget appears stuck for later sends too. Correctly labeled `bug`/`chat-customizations` already, so this stays keep-open rather than route-to-area.

## Change summary

An invalid/unmatched `model` field in a .prompt.md frontmatter, used via a slash command, blocks the chat request and prevents sending further messages.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/input/chatInputModelSelectionController.ts, `requestProgrammaticSelection`/`_reconcilePendingProgrammaticSelection` should resolve `false` (instead of staying pending indefinitely) once the model catalog is settled and the requested qualified name still has no match, so an invalid `model:` in a prompt file fails gracefully instead of hanging the request.

## Evidence

- **hang path:** chatWidget.ts `_applyPromptMetadata` (around line 3893) calls `return this.input.requestModelByQualifiedName(model);` and `_acceptInput` (chatWidget.ts:3236) does `await this._applyPromptFileIfSet(...)`, so the whole accept-input flow blocks on this promise.
- **unresolved promise:** chatInputPart.ts:1302 `requestModelByQualifiedName` calls `_requestProgrammaticLanguageModel`, which calls `ChatInputModelSelectionController.requestProgrammaticSelection` (chatInputModelSelectionController.ts:150). That method only resolves the returned promise inside `_reconcilePendingProgrammaticSelection` (line 516) when `intent.resolveModel()` finds a match; for a name like `does-not-exist` that never matches any model, `resolveModel()` returns undefined every time (line 526-528: `if (!model) return false;`), so `_pendingProgrammaticSelection` is left set and the promise never resolves or rejects.
- **no fallback/timeout:** No timeout or 'catalog settled, still no match, resolve false' fallback exists in that reconciliation path — it only re-runs when `subscribeToModelChanges` fires (constructor line 79-82) or when another selection action explicitly clears it (e.g. `beginConversationSwitch`, `initialize`, `resetToDefault`).
- **no prior fix:** `git log` on chatInputModelSelectionController.ts shows the latest commit (e782f88c) is unrelated to model resolution/timeouts.
