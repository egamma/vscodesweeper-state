# Issue #342637 — [Worktree Cleanup] Clicking on a session removed it from the list

[https://github.com/microsoft/vscode/issues/342637](https://github.com/microsoft/vscode/issues/342637)

## Summary

Keep open: opening a cleanup row activates its session, and the cleanup table deliberately excludes active sessions when reloaded. Those rules explain the disappearance, but leave a real inspect-and-return usability gap; the report provides sufficient steps to evaluate it.

## Change summary

Allow users to inspect a session from Worktree Cleanup and return without losing track of that session or its cleanup options.

## Best solution

Provide a stable inspect-and-return workflow in the cleanup editor without weakening active-session cleanup protection. Decide whether inspection should avoid activating the session or whether inspected, protected sessions should remain visible with an understandable path back to cleanup eligibility.

- **Behavior:**

  > Inspecting a session from Worktree Cleanup currently makes its row disappear on returning because inspection activates the session. Users should be able to review session context and return to a comprehensible cleanup workflow without losing the inspected item's identity or status. Active and otherwise protected sessions must not become cleanup-eligible merely because they were inspected. Acceptance should cover pointer and keyboard inspection and returning to the cleanup editor.
- **Trace:**

  > SessionWorktreeCleanupEditor creates a session-title link that calls ISessionsService.openSession. SessionsService._openSession reaches _showSession and _activate, making that session active. SessionWorktreeCleanupService._withCleanupState recomputes eligibility even when measurements are cached, and _getCleanupState classifies the inspected session as active. When the cleanup editor reloads through setInput, renderRows lists only eligible entries, explaining the disappearance without implying deletion. The boundary is the cleanup inspection and presentation workflow; preserve normal session-opening behavior elsewhere and existing cleanup protections. https://github.com/microsoft/vscode/issues/342633 is related visibility-design context, not a settled solution to inspection. The remaining uncertainty is the intended user-visible inspection model, not the cause of the filtering.
- **Open decisions:**
  - Should cleanup inspection preview session context without activating the session, or open it normally and retain a visible protected row with a clear route back to cleanup eligibility?
