# Issue #335819 — Delete is disabled for an automation with a running session without explanation

[https://github.com/microsoft/vscode/issues/335819](https://github.com/microsoft/vscode/issues/335819)

## Summary

Confirmed in source: the Delete menu action for automations is gated behind `AutomationCardCanDeleteContext` (set false while the automation has a running session), with no tooltip or explanatory affordance when disabled. Team-authored, freshly filed, and no fix exists on main yet, so this stays open for the sessions/automations owners.

## Change summary

Delete is silently disabled on an automation's overflow menu while its session is running, with no tooltip, message, or way to proceed.

## Best solution

In src/vs/sessions/contrib/sessions/browser/views/automationsView.ts, either allow delete with a confirmation that stops the running session first, or keep it disabled but surface why (e.g. a disabled-state tooltip/title explaining the session must finish, similar to the existing `showAutomationsDisabled` dialog pattern used when automations are globally disabled).
