# Issue #332107 — Rendered Markdown in Source Control injects diff markup into Mermaid code blocks, causing parse errors

[https://github.com/microsoft/vscode/issues/332107](https://github.com/microsoft/vscode/issues/332107)

## Summary

Confirmed in source: the Markdown-preview diff view injects raw `<span data-diff-start/end>` markers directly into the document text before parsing, with no awareness of fenced code blocks, so the markers land inside Mermaid (and likely any) code fences as literal text and break the fenced content's own parser.

## Change summary

Rendering a changed Markdown file as a diff in the Markdown Preview injects diff-marker spans into Mermaid code blocks, causing a Mermaid parse error instead of a rendered diagram.

## Best solution

In `injectInnerChangeMarkers` (extensions/markdown-language-features/src/preview/documentRenderer.ts), track fenced code block ranges while walking lines and skip marker injection for any line inside a fence (markers can't usefully highlight inside a code block anyway, since that content is rendered verbatim); a related report (https://github.com/microsoft/vscode/issues/332119) shows the same root cause corrupting tables, so the fix should be general to any line whose rendering is sensitive to raw injected HTML, not Mermaid-specific.
