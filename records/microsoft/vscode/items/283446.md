# Issue #283446 — GitHub Copilot summarization is too simplistic, losing crucial semantics

[https://github.com/microsoft/vscode/issues/283446](https://github.com/microsoft/vscode/issues/283446)

## Summary

Keep open for an evaluation-led improvement to semantic retention across compactions, as the maintainer explicitly supported investigating. Current prompts and transcript recovery address parts of the request, but do not establish that architectural decisions, constraints, and complete plans survive repeated summarization.

## Change summary

Improve Copilot conversation compaction so enduring decisions, reasoning, identifiers, and active plans remain accurate across repeated summaries.

## Best solution

Evaluate repeated-compaction fidelity using the reported planning and ticket-retention scenarios, then improve Copilot's context management based on measured results. Preserve authoritative decisions without treating brainstorming as commitments or reconstructed file contents as verified facts.

- **Likely files:** `extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx`, `extensions/copilot/src/extension/prompts/node/agent/simpleSummarizedHistoryPrompt.tsx`, `extensions/copilot/src/extension/prompts/node/agent/test/summarization.spec.tsx`
- **Validation:** Create repeatable model-backed evaluations that compact a conversation multiple times and then request its complete A/B plan, original ticket identifier, deferred-caching constraint, and separately attributed plan-file contents. Measure omissions and fabricated commitments across representative models; use the existing Agent Summarization unit suite for prompt/history plumbing, not as proof of semantic quality.
- **Behavior:**

  > Long-running Copilot discussions should retain agreed decisions, active plan sections, enduring identifiers, and explicit deferrals through repeated compaction. Discussing section B must not erase still-active section A. Summaries must distinguish hypothetical ideas from accepted commitments and must not conflate separate plan files. Acceptance requires repeated-compaction evaluations of these scenarios, including accurate continuation afterward.
- **Trace:**

  > ConversationHistorySummarizationPrompt and SummaryPrompt in extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx already request structured decisions and continuation context, while emphasizing recent operations. ConversationHistory replaces earlier rounds with an existing summary, and SimpleSummarizedHistory supplies a truncating fallback. ConversationHistorySummarizer.summarizeHistory appends a pointer to the original transcript when available, providing a recovery mechanism rather than guaranteed retention. Existing tests in extensions/copilot/src/extension/prompts/node/agent/test/summarization.spec.tsx use a StaticChatMLFetcher, so they cannot establish real-model semantic fidelity. The maintainer requested scenario/model evaluations at https://github.com/microsoft/vscode/issues/283446#issuecomment-3698298943. Preserve existing context-budget and recovery behavior; the uncertainty is which retention contract and measured strategy should replace or augment today's summarization, not whether every idea in the reporter's proposed architecture must ship.
- **Open decisions:**
  - Which information should receive explicit retention priority across compactions, and should users be able to mark additional conversation content as authoritative?
  - Should omitted historical details be recovered automatically during continuation, or only when the agent identifies a need to consult the transcript?
