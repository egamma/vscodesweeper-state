## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageDetails.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/viewPane/chatContextUsageWidget.test.ts`, `extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts`, `extensions/copilot/src/extension/byok/node/openAIEndpoint.ts`
- **Validation:** On a current build, compare displayed counts with provider-reported usage across two successive OpenRouter requests, an agent turn with multiple model calls, and compaction followed by another response. Switch to a model with a different context limit before sending another request and verify the denominator changes; click the indicator and verify the details remain stable. Add regression coverage in the context-usage widget suite and the relevant provider suite once the remaining failing path is identified.
- **Behavior:**

  > Context-window details should show the selected model's effective limit and the latest available usage without retaining obsolete counts after newer usage arrives. Model switching should update the limit before the next request while preserving the distinction between existing usage and newly measured usage. Successive OpenRouter requests and post-compaction responses should update the meter when fresh usage is supplied. Opening the details should not cause a delayed flicker or collapse.
- **Trace:**

  > ChatInputPart forwards model changes to ChatContextUsageWidget.setSelectedModel and attaches the widget to the latest request. The widget subscribes to response changes, computes counts from response.usage, and exposes an observable that ChatContextUsageDetails renders reactively. Current source already contains selected-model denominator handling, and https://github.com/microsoft/vscode/pull/298273 addressed the delayed-hover race. The unresolved boundary is whether provider and compaction paths deliver accurate, refreshed usage to the response model; the OpenRouter confirmation followed the hover fix. Preserve current selected-model/configured-context semantics and last-response accounting rather than introducing speculative cumulative estimates. Related provider gaps are described in https://github.com/microsoft/vscode/issues/313458 and https://github.com/microsoft/vscode/issues/340551, but their equivalence to this report has not been established.

In src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts, setSelectedModel recomputes the denominator using the selected model while retaining the last response's usage numerator. The original lack of denominator updates is therefore no longer the current source behavior.

ChatContextUsageDetails subscribes reactively to the resulting observable. These paths can refresh supplied usage, but do not establish that every provider supplies fresh counts after compaction or subsequent requests; runtime/provider verification remains necessary.

It improves window-size calculation but does not demonstrate resolution of stale OpenRouter usage.
