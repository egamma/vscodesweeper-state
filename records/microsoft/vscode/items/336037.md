# Issue #336037 — [Snap/XWayland] Fcitx5 McBopomofo IME popup is displaced from sidebar input on mixed-DPI monitors

[https://github.com/microsoft/vscode/issues/336037](https://github.com/microsoft/vscode/issues/336037)

## Summary

Well-documented but highly environment-specific report (Snap-packaged VS Code forced into XWayland + Fcitx5 + mixed-DPI monitors) whose root cause is IME candidate-window positioning in Chromium/Electron's XIM integration, not VS Code's own code — VS Code has no custom IME popup placement logic, so this stays open as upstream rather than closing.

## Change summary

Fcitx5/McBopomofo IME popup appears far from the actual caret when the official Snap build runs under XWayland on a mixed-DPI (100%/200%) monitor setup; a native-Wayland launch with Wayland IME flags fixes it, but the Snap's electron-launch script forces `--ozone-platform=x11`.

## Best solution

No VS Code core code path owns IME candidate-window coordinate translation under XIM/XWayland — that logic lives in Chromium/Electron and the GTK/Fcitx5/kimpanel stack. The actionable VS Code-side lever is packaging: reconsider whether the Snap's `electron-launch` should keep hard-coding `--ozone-platform=x11` (related to the reporter's linked #329142), which would let affected users opt into the already-confirmed native-Wayland workaround.
