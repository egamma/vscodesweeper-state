- **Behavior:**

  > A comment box in the agent-feedback overlay can be dragged to any position within the editor viewport and continues to scroll with the reading view. Its anchored range is unchanged by the move. A dashed line is drawn from the box to its anchored range, and hovering the box highlights that range. Acceptance: dragging updates only the box's rendered position, not its data-anchor; the pointer line always terminates at the correct line even after scroll/reflow.
- **Trace:**

  > AgentFeedbackEditorWidget (src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackEditorWidget.ts) computes an IOverlayWidgetPosition per widget (`_position`, set around line 989) and layout()/`_updateReservedWidth` logic (lines ~961-1090) reflows boxes based on anchored lines — there is no stored user override for position, and the existing `.agent-feedback-widget-arrow` (line 174) is a static CSS triangle, not a dynamic leader line to the anchor. The boundary: do not change how the anchor range itself is computed or stored (agentFeedbackModel.ts) — only how the box is drawn/positioned and how a line connects box-to-anchor. Where uncertainty starts: whether the leader line is an SVG overlay layer, a CSS-only diagonal, or a canvas draw, and whether the drag offset persists per-session or resets on reload.
- **Open decisions:**
