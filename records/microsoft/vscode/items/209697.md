# Issue #209697 — Improvements to in-editor view of code coverage

[https://github.com/microsoft/vscode/issues/209697](https://github.com/microsoft/vscode/issues/209697)

## Summary

Keep open: current coverage decorations still insert execution counts before source text and attach coverage hovers to statement regions. The inline-toggle discoverability concern is partly addressed by existing editor controls, but the broader readability improvements remain relevant and have maintainer support.

## Change summary

Improve coverage readability by preserving visual indentation, supporting full-line highlighting for line-only coverage, and making coverage hovers informative without obscuring source or competing with language hovers.

## Best solution

Finish the coverage presentation polish in the testing editor contribution, preserving statement-level precision and useful branch information while keeping source code visually primary. Agree on the remaining hover and line-highlighting behavior before implementation, reusing the existing inline-toggle controls.

Manually compare aligned if/closing-brace lines and Python indentation with inline coverage off and on, verify the agreed full-width highlighting behavior, and check language hovers, branch details, and inline-toggle discoverability.
- **Behavior:**

  > Coverage should support reading source rather than distort its apparent indentation or place redundant information over it. Numeric execution counts should not break alignment between otherwise aligned source lines. Line-only coverage should have an agreed consistent presentation per file, without losing precision in files carrying statement ranges. Useful branch details and language documentation should remain discoverable, and toggling inline coverage should not require a tooltip that obscures source.
- **Trace:**

  > CodeCoverageDecorations.apply in src/vs/workbench/contrib/testing/browser/codeCoverageDecorations.ts attaches countBadge through target.before and coverage descriptions through target.hoverMessage for statement and branch ranges. CoverageDetailsModel normalizes and partitions ranges, while tidyLocation expands Position locations to line end; there is no per-file full-line background selection. The coverage classes and badge styling are in browser/media/testing.css, and browser tests currently primarily snapshot CoverageDetailsModel ranges. Existing testing.toggleInlineCoverage editor-title/command-palette registration and CoverageToolbarWidget already provide toggle controls, so the original gutter-tooltip complaint should be reassessed against those controls rather than assumed unchanged. Preserve provider data, statement/branch precision, coverage calculations, and noncoverage editor behavior. The maintainer discussion at https://github.com/microsoft/vscode/issues/209697#issuecomment-2043375468 establishes interest but leaves the final interaction design unsettled.
- **Open decisions:**
  - Should coverage descriptions appear only on coverage-specific badges and branch indicators, or should any coverage information remain in ordinary source-text hovers?
  - For files containing only line coverage, should full-width line backgrounds replace range highlighting, and what visible behavior should apply to files mixing line and statement locations?
