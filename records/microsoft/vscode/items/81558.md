# Issue #81558 — Expanding semantic theming to support semantically embedded languages for colorization

[https://github.com/microsoft/vscode/issues/81558](https://github.com/microsoft/vscode/issues/81558)

## Summary

A real extension-API gap remains: semantic tokens cannot associate individual ranges with an embedded language. This older, broader request should remain the canonical design discussion.

## Change summary

Allow semantic colorization providers to identify dynamically embedded-language ranges so those ranges receive appropriate language-aware highlighting.

## Best solution

Design a deterministic, host-controlled mechanism for styling embedded-language ranges without asynchronously changing typing behavior. The outer language provider should retain ownership while being able to reuse an embedded language's tokenization or theme semantics.

## Evidence

- **current API gap:** src/vscode-dts/vscode.d.ts:4253-4303 defines semantic-token legends and builder entries using only ranges, token types, and modifiers; an individual token cannot carry a language identifier.
- **static embedding only:** extensions/razor/package.json:33-42 maps TextMate scopes to embedded language IDs statically, which does not cover the dynamic semantic boundaries described here.
- **design constraint:** https://github.com/microsoft/vscode/issues/86329#issuecomment-562095761 explains that asynchronous semantic tokens must not redefine language boundaries because typing behavior would become nondeterministic, and recommends that the outer language own and merge embedded semantic tokens.
- **related remaining work:** https://github.com/microsoft/vscode/issues/163292 is open but addresses injected grammar scopes being overwritten by semantic tokens, a narrower overlap problem that does not fully absorb this dynamic embedded-language API request.
