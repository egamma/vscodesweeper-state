# Issue #328700 — Extension host crashes on startup in 1.130 and 1.131; createProxyAuthorizationLookup named export not found in @vscode/proxy-agent (works fine on 1.129)

[https://github.com/microsoft/vscode/issues/328700](https://github.com/microsoft/vscode/issues/328700)

## Summary

Real, still-open regression: the exact CJS named-import pattern that crashes the extension host is unchanged on current main, so this needs a source fix rather than a close.

## Change summary

Extension host crash-loops on startup in 1.130/1.131 because a static named ESM import of `createProxyAuthorizationLookup` from the CommonJS package `@vscode/proxy-agent` throws `SyntaxError: Named export ... not found`.

## Best solution

Fix the ESM/CJS interop in src/vs/workbench/api/node/proxyResolver.ts and src/vs/platform/agentHost/node/agentHostProxyResolver.ts by importing `@vscode/proxy-agent` as a namespace (`import * as proxyAgent from '@vscode/proxy-agent'`) and destructuring the needed functions at runtime instead of statically naming them, since Node's cjs-module-lexer cannot reliably detect exports buried in `@vscode/proxy-agent`'s long chained `exports.a = exports.b = ... = void 0;` assignment.
