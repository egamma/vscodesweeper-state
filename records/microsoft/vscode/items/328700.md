# Issue #328700 — Extension host crashes on startup in 1.130 and 1.131; createProxyAuthorizationLookup named export not found in @vscode/proxy-agent (works fine on 1.129)

[https://github.com/microsoft/vscode/issues/328700](https://github.com/microsoft/vscode/issues/328700)

## Summary

Well-evidenced crash-loop regression in the extension host (`createProxyAuthorizationLookup` ESM/CJS interop failure importing `@vscode/proxy-agent`), confirmed independently by two reporters across 1.130/1.131/1.134 on Linux with extensions disabled and a fresh temp profile — routing to the agent-host/extension-host owners rather than closing.

## Change summary

Extension host crashes in a loop on startup because Node's ESM import of the named export `createProxyAuthorizationLookup` from the CommonJS `@vscode/proxy-agent` package fails.

## Best solution

Area owners should determine why cjs-module-lexer/Node's static named-export detection fails for `@vscode/proxy-agent` specifically inside the packaged extensionHostProcess.js (src/vs/platform/agentHost/node/agentHostProxyResolver.ts and src/vs/workbench/api/node/proxyResolver.ts both import this named export) — e.g. a stale/mismatched node_modules copy in certain installs, or a difference between the declared `^0.44.0` semver range and what's actually bundled — and either pin/re-bundle the dependency correctly or switch to a default-import + destructure pattern that doesn't rely on static named-export detection.
