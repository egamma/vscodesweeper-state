# Issue #345810 — Feature Request: Improve Queue Management in Local Harness

[https://github.com/microsoft/vscode/issues/345810](https://github.com/microsoft/vscode/issues/345810)

## Summary

Keep open: current queue controls do not cover the requested non-drag reordering, and editing still removes and requeues the message. The related collapse/expand request does not cover both requirements.

## Change summary

Provide alternatives to drag-and-drop queue reordering and preserve a queued message's position when editing it.

## Best solution

Provide keyboard-accessible queue reordering in the chat message actions and preserve execution order when saving an edited queued message. Coordinate with the related collapse/expand request without treating it as coverage for this broader issue.

## Evidence

- **Existing reordering capability:** src/vs/workbench/contrib/chat/browser/widget/chatPendingDragAndDrop.ts implements drag-based reordering within each queue kind through ChatPendingDragController._reorder and IChatService.setPendingRequests. This covers the existing drag interaction, not the requested alternative controls.
- **Existing commands and setting:** src/vs/workbench/contrib/chat/browser/actions/chatQueueActions.ts defines queue, steer, edit, removal, and immediate-send actions, but no move-up/down or first/last actions. The RequestQueueingDefaultAction configuration in browser/chat.shared.contribution.ts selects queue versus steer as the default submission action, not queue position.
- **Edit position path:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:4035-4040 removes the edited pending request and retains its queue kind without retaining its index. ChatService.queuePendingRequest calls ChatModel.addPendingRequest; src/vs/workbench/contrib/chat/common/model/chatModel.ts:2951-2971 appends ordinary queued requests. This explains the reported movement to the end.
- **Related request is narrower:** https://github.com/microsoft/vscode/issues/326123 requests collapsing long queued messages to make the queue easier to manage. Its body does not request explicit movement actions or preservation of position after editing, so it cannot absorb this issue's full scope.
