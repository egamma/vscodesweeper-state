# Issue #309992 — Chat Sessions Controller : resource alias never removed once registered

## Summary

Valid tech-debt item filed by a team member: the `_resourceAliases` map in chatSessions.contribution.ts grows monotonically and is never pruned. The code explicitly documents the alias as 'intentionally permanent' but provides no cleanup path on session disposal. No fix has landed.

## Change summary

The `registerSessionResourceAlias` mapping is never removed, causing the `_resourceAliases` map to grow unbounded across the workbench lifetime.

## Best solution

Add cleanup of the `_resourceAliases` entry when a session is fully disposed — likely in or near `clearMaterializedSessionResource` in `src/vs/workbench/contrib/chat/browser/chatSessions/chatSessions.contribution.ts`, gated on the session no longer needing option lookups.
