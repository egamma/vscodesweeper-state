# Issue #149440 — Add reverse relative variable to snippets

[https://github.com/microsoft/vscode/issues/149440](https://github.com/microsoft/vscode/issues/149440)

## Summary

Keep this accepted feature request open: current snippet variables do not directly provide the reverse relative path, and no matching open canonical was identified. It has 25 community upvotes and already qualified for the Backlog.

## Change summary

Add a snippet variable providing the reverse of the existing workspace-relative file path.

## Best solution

Define the reverse path's origin and destination with concrete examples, then provide a predictable snippet variable in the existing variable-resolution infrastructure. Preserve existing path variables and specify behavior for multi-root workspaces and files outside a workspace.

- **Validation:** After agreeing on examples, add resolver tests in src/vs/editor/contrib/snippet/test/browser/snippetVariables.test.ts and run scripts/test.sh --run src/vs/editor/contrib/snippet/test/browser/snippetVariables.test.ts. Cover root-level and nested files, Windows/POSIX paths, multi-root selection, and the agreed outside-workspace behavior; retain existing variable expectations.
- **Behavior:**

  > Snippet authors want a first-class reverse relative path variable instead of deriving parent-directory traversal through transforms. Agree on its exact output for a file such as /workspace/src/components/file.ts before implementation, since the report's direction labels conflict with the existing variable's meaning. Acceptance should cover root-level and nested files, platform separators, and explicit behavior when no containing workspace folder exists. Existing snippet variables must retain their current outputs.
- **Trace:**

  > KnownSnippetVariableNames and ModelBasedVariableResolver in src/vs/editor/contrib/snippet/browser/snippetVariables.ts expose RELATIVE_FILEPATH but no reverse equivalent. RELATIVE_FILEPATH delegates to ILabelService.getUriLabel with relative and noPrefix options; WorkspaceBasedVariableResolver independently resolves WORKSPACE_FOLDER, including the workspace configuration directory for multi-root workspaces. The resolver tests in src/vs/editor/contrib/snippet/test/browser/snippetVariables.test.ts provide the existing path-variable validation surface. https://github.com/microsoft/vscode/issues/37570 supplies historical context and transformation workarounds, but is closed and does not establish the requested reverse contract. The remaining uncertainty is product semantics, not whether the named variable already exists; preserve all existing variable behavior.
- **Open decisions:**
  - For /workspace/src/components/file.ts in workspace /workspace, should the new variable yield ../../ from the containing directory back to the workspace, or a different path? Confirm with explicit root-level and nested-file examples.
  - In multi-root workspaces, should the destination be the file's containing workspace folder or the workspace configuration directory, and what should the variable resolve to when the file has no containing workspace folder?

## Evidence

- **Existing capability:** src/vs/editor/contrib/snippet/browser/snippetVariables.ts lists RELATIVE_FILEPATH in KnownSnippetVariableNames; ModelBasedVariableResolver resolves it through getUriLabel(model.uri, { relative: true, noPrefix: true }). There is no REVERSE_RELATIVE_FILEPATH entry or reverse-path resolver.
- **Related variables and workarounds:** ModelBasedVariableResolver also provides TM_DIRECTORY and TM_FILEPATH; WorkspaceBasedVariableResolver provides WORKSPACE_FOLDER. These supply path components, not a direct reverse relative path. Variable transforms can construct parent traversals, but that is an indirect workaround rather than the requested first-class variable.
- **Existing validation surface:** src/vs/editor/contrib/snippet/test/browser/snippetVariables.test.ts contains 'Add RELATIVE_FILEPATH snippet variable #114208', covering relative paths in a single-folder workspace and absolute-path fallback without a workspace, including platform-specific separators.

Its discussion includes parent-traversal workarounds, while https://github.com/microsoft/vscode/issues/37570#issuecomment-767676813 confirms RELATIVE_FILEPATH, not a reverse variable.
