- **Current source mechanism:** src/vs/workbench/browser/layout.ts:1675–1679 creates the workbench grid with proportionalLayout disabled; layout():1753–1766 forwards the current client dimensions. In src/vs/base/browser/ui/splitview/splitview.ts:841–876, layout() resizes from current item sizes. resize():1241–1327 overwrites those sizes subject to constraints rather than retaining their previous preferred widths. The editor has High layout priority while both sidebar parts have Low priority, so constrained sidebars can shrink and subsequent expansion is absorbed by the editor. This confirms the shrink-then-expand mechanism from source, not the Windows monitor event sequence itself.
