# Issue #331579 — NES 402 handler resets the Copilot token in an unbounded loop (quota latch never engages)

[https://github.com/microsoft/vscode/issues/331579](https://github.com/microsoft/vscode/issues/331579)

## Summary

Verified on main: the 402 handler's latch condition tests the wrong quota field (`isCompletionsQuotaExceeded` reads free-tier code-completions quota, not the NES quota that produced the 402), so the guard is unsatisfiable and the token reset repeats every request instead of once — a real, well-diagnosed bug worth routing to the NES/authentication owners.

## Change summary

The NES 402 handler's quota latch never engages because it checks the wrong quota field, causing an unbounded per-request Copilot token reset loop for affected users.

## Best solution

Fix the latch in extensions/copilot/src/platform/nesFetch/node/completionsFetchServiceImpl.ts (and the analogous branch in extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts) to key off the quota/response that actually produced the 402 rather than `isCompletionsQuotaExceeded`, drop the unconditional `isFreeUser &&` gate so paid users are covered, and add a hard cap/backoff so a non-latching guard can never spin at request rate — this needs a product decision on which quota field and backoff policy to use, so it's best owned by the NES/auth maintainers rather than an automated fix.
