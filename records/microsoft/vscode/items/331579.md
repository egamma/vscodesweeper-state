# Issue #331579 — NES 402 handler resets the Copilot token in an unbounded loop (quota latch never engages)

[https://github.com/microsoft/vscode/issues/331579](https://github.com/microsoft/vscode/issues/331579)

## Summary

Source-verified on current main: the 402 handler's quota latch checks `isCompletionsQuotaExceeded` (free-tier code-completions quota) instead of the quota that actually produced the NES 402, so the guard is unsatisfiable and the token reset never latches — this is a real, localized bug worth fixing.

## Change summary

The NES fetch service's 402 handler resets the Copilot token on every request instead of once, because its quota-latch guard tests the wrong quota field.

## Best solution

Fix the guard in completionsFetchServiceImpl.ts to latch on the quota/condition that actually produced the 402 (not `limited_user_quotas.completions`), drop the `isFreeUser &&` prefix so paid users are covered, and add a cap/backoff as a safety net; the same shape in chatMLFetcher.ts (lines ~1677, 2197-2200, 2270) should get the same review.
