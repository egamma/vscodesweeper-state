# Issue #345472 — Agents: SSH host whose first connection fails is saved anyway, and its draft ignores Enter

[https://github.com/microsoft/vscode/issues/345472](https://github.com/microsoft/vscode/issues/345472)

## Summary

Keep open: current source persists a new SSH host before connection succeeds and silently rejects submission when the selected remote cannot send. The team-authored report has actionable steps; no verified fixing commit or same-symptom canonical was identified.

## Change summary

Prevent failed first-time SSH setup from leaving an unexplained, unusable draft and provide readable connection-failure recovery.

## Best solution

Make failed SSH onboarding recoverable and ensure disconnected drafts visibly explain why submission is unavailable while preserving unsent text. Agree whether never-connected hosts should be removed or retained with explicit recovery before changing persistence semantics.
