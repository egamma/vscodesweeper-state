# Issue #330811 — Chat: add a per-chat auto-scroll mode with limited streaming preview

[https://github.com/microsoft/vscode/issues/330811](https://github.com/microsoft/vscode/issues/330811)

## Summary

This remains a distinct, actionable chat UX request: current main can preserve a manually changed position and provides Scroll to Bottom, but has no per-session reading mode, bounded response preview, or configurable streaming motion. Route it to the chat area for product design rather than closing it as a duplicate.

## Change summary

Add a per-chat choice between following streamed output and showing only the beginning of each new response while preserving a stable reading position.

## Best solution

Provide a session-scoped reading/follow control that reveals the start of each new response, preserves the viewport after the preview limit, and retains an accessible Jump to Latest action. Coordinate its precedence with the global hard opt-out requested in https://github.com/microsoft/vscode/issues/312626.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`
- **Validation:** Add targeted ChatWidget and ChatListWidget tests covering per-session mode restoration, bounded streaming preview, manual scrolling, Jump to Latest, and reduced-motion behavior; run scripts/test.sh --grep 'ChatWidget|ChatListWidget'.
- **Behavior:**

  > Each chat session can independently use Follow Latest or Reading mode. Reading mode brings the beginning of each newly requested response into view, stops moving after the selected preview limit, and leaves further navigation to the user; Follow Latest continues tracking streamed output. Jump to Latest remains keyboard-accessible, and animated following respects reduced-motion preferences. Switching chats must restore each session's selected mode and transcript position without changing quick chat or inline chat unintentionally.
- **Trace:**

  > The transcript scroll path is split between ChatWidget and ChatListWidget: ChatWidget scrolls to the end on addRequest and during layouts of a rendering response, while ChatListWidget._withPersistedAutoScroll keeps a bottom-anchored transcript following content-height changes. ChatListWidget already owns the localized, ARIA-labelled Scroll to Bottom affordance and AutoScrollHolds for temporary suppression. ChatWidget.getViewState/restoreViewState currently records scrollTop and isAtBottom, and ChatViewPane caches that state by session resource. IChatWidgetViewOptions.autoScroll is supplied by hosts and is not a per-session user control. Existing accessibility help is in src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts and must describe any new keyboard-operable mode. Keep host-specific defaults and existing manual-scroll preservation intact; https://github.com/microsoft/vscode/issues/312626 is related global-preference work, not a canonical duplicate.
- **Open decisions:**
  - Does the session-scoped mode override a future global hard opt-out from https://github.com/microsoft/vscode/issues/312626, or does the global opt-out constrain every session?
  - What constitutes the preview limit for mixed Markdown, reasoning, and tool content: rendered visual lines, prose lines, or the first content block?
  - Does Jump to Latest perform a one-time reveal while retaining Reading mode, or also switch the session back to Follow Latest?

## Evidence

- **current behavior:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts calls scrollToEnd when a request is added and continues following a rendering response while the list is at the bottom; src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts preserves bottom-following through _withPersistedAutoScroll.
- **existing affordance:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts provides a keyboard-accessible, ARIA-labelled Scroll to Bottom button whenever the transcript is not at the bottom, but no persistent reading/follow mode.
- **no existing configuration:** Current chat configuration registrations expose sticky-scroll and fixed-height thinking controls, while IChatWidgetViewOptions.autoScroll in src/vs/workbench/contrib/chat/browser/chat.ts is a host option rather than a user- or session-selectable mode.
- **related request:** https://github.com/microsoft/vscode/issues/312626 is older and open with 19 upvotes, but asks for a global unconditional auto-scroll opt-out. It does not cover this report's per-chat state, limited initial preview, Jump to Latest semantics, or reduced-motion-aware smooth following, so it does not meet the stronger re-review duplicate bar.
- **existing state boundary:** ChatWidget.getViewState/restoreViewState and the per-resource cache in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts already preserve transcript position per session, but the stored state contains only scrollTop/isAtBottom.
