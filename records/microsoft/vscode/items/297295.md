# Issue #297295 — Yolo: Improve security disclaimer

[https://github.com/microsoft/vscode/issues/297295](https://github.com/microsoft/vscode/issues/297295)

## Summary

The warning still needs security-focused UX polish on current main: both relevant dialogs permit immediate enablement without an explicit risk acknowledgement, and the global warning retains the awkward inline documentation link. The issue is accepted in the Backlog and no canonical issue or fixing PR owns the remaining work.

## Change summary

Improve the `/yolo` and global auto-approve warnings with clearer risk language, better documentation linking, and potentially an explicit acknowledgement before enablement.

## Best solution

Use consistent warning copy across the current Bypass Approvals and legacy global-auto-approve paths, make the documentation link a clearly labeled Learn More action, and require an intentional acknowledgement if maintainers choose that safeguard. Preserve the underlying permission and persistence semantics.
