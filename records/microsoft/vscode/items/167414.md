# Issue #167414 — Git - pull rebase is stuck after merge conflict using submodules

[https://github.com/microsoft/vscode/issues/167414](https://github.com/microsoft/vscode/issues/167414)

## Summary

Keep open: current source still misses an interrupted rebase inside a submodule whose .git is a file, so committing resolved conflicts does not take the rebase-continuation path. The issue is already correctly routed to git.

## Change summary

Recognize an interrupted rebase inside a submodule and allow it to continue after conflicts are resolved.

## Best solution

The built-in Git extension should detect rebase state in the repository's actual Git metadata directory, preserving normal repository behavior and allowing resolved submodule rebases to continue through Source Control.

With the reported .git file, those child paths cannot resolve; the read failure is caught and returned as undefined.
- **Observable consequence:** extensions/git/src/repository.ts:3038-3065 assigns that result to rebaseCommit during status refresh.
