# Issue #342633 — [Worktree Cleanup] I want to view all worktrees, not just those that are more recent than 7 days old

[https://github.com/microsoft/vscode/issues/342633](https://github.com/microsoft/vscode/issues/342633)

## Summary

Keep open: the current Worktree Cleanup editor still displays only cleanup-eligible worktrees, so viewing the complete inventory remains a real gap. The assigned 1.145.0 release milestone also requires preserving the owner's scheduling decision.

## Change summary

Allow users to view and manage all agent-session worktrees together, with older inactive worktrees distinguished as cleanup recommendations.

## Best solution

Provide a complete agent-session worktree inventory in the Worktree Cleanup editor, distinguishing visibility from cleanup eligibility and explaining excluded or unavailable entries. Preserve protections for active, running, waiting-for-input, and pinned sessions rather than making every visible worktree automatically eligible for removal.

- **Existing capability does not cover the request:** src/vs/sessions/contrib/sessionInputBanners/browser/sessionWorktreeCleanupEditor.ts defines MINIMUM_AGE_OPTIONS as [7, 15, 30, 60, 90]. Its renderRows() filters this.worktrees to cleanupState === 'eligible', renders only that subset, and hides the table when it is empty. The existing inactivity selector has no all-worktrees option.
- **Scan count and displayed inventory differ:** In src/vs/sessions/contrib/sessionInputBanners/browser/sessionWorktreeCleanupService.ts, _measureWorktrees() counts worktrees across sessions with workTreeUri values before eligibility classification. _getWorktrees() excludes unmeasured and archived entries, and the editor subsequently excludes all noneligible entries. This explains why the scan and displayed counts can differ, but does not establish the exact cause of the reporter's 71-versus-28 counts.
- **Product boundary:** SessionWorktreeCleanupService._getCleanupState() explicitly distinguishes active, running, needsInput, pinned, recent, archived, untitled, error, unavailable, and eligible states. Those distinctions support separating inventory visibility from permission to clean up; lowering the age threshold alone would not deliver the full request.
- **Testing context:** https://github.com/microsoft/vscode/issues/342065 is the linked, completed Worktree Cleanup usability test plan. It calls for eligible, active, pinned, and recent sessions and requires protected worktrees to remain intact. It is testing context, not an open canonical feature request or proof that this inventory request was implemented.
