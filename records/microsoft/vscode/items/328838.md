# Issue #328838 — Clicking on "Open in Agents" on a Claude session opens the Agents Window but not the session

[https://github.com/microsoft/vscode/issues/328838](https://github.com/microsoft/vscode/issues/328838)

## Summary

Real, freshly-filed bug from a team member during active testing of the Claude agent-host harness; traced the handoff code path and the failure mode (silent session-resolution timeout) matches the reported symptom, and it lines up with unfinished work already tracked in an open umbrella issue.

## Change summary

Clicking 'Open in Agents' on a Claude agent-host session opens the Agents Window, briefly shows the target session, then falls back to a blank new-chat view instead of the actual session.

## Best solution

Fix belongs in the Agents-window session handoff/listing path: `resolveAndOpenSession`/`waitForSessionAvailable` in src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts silently abort if `sessionsManagementService.getSession(sessionResource)` never returns the target, which matches this symptom if the Claude agent-host session isn't yet listed by the Agents window's session provider. This is the same gap tracked as the unchecked 'Display Multi-root Sessions in Agents Window' item in https://github.com/microsoft/vscode/issues/321651 (open, actively worked, assigned to the multi-root/harness workstream) — route this bug there for the fix.
