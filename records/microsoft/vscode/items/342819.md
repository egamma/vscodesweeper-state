# Issue #342819 — Allow staging selection-bound review comments from the regular editor and submitting them together to the current chat

[https://github.com/microsoft/vscode/issues/342819](https://github.com/microsoft/vscode/issues/342819)

## Summary

Keep open as a feature request: selection attachments and existing specialized feedback workflows do not establish support for staging selection-bound comments in an ordinary editor's current chat draft. Related reports cover different behavior and do not justify consolidation as a duplicate.

## Change summary

Collect editable, selection-bound feedback across files in the current chat draft and submit it once explicitly, preserving code context and flagging stale anchors.

## Best solution

Evaluate a shared workbench editor-to-chat feedback workflow that preserves each comment's selection and snapshot without starting execution until submission. Reuse existing review infrastructure where appropriate, while preserving explanation-only intent and avoiding a dependency from workbench into the Sessions layer.

## Evidence

- **Existing selection capability is partial:** src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts:298–386 registers workbench.action.chat.attachSelection. Its ordinary-editor path calls widget.attachmentModel.addFile(activeUri, range); it does not collect feedback text bound to that attachment or provide comment editing and stale-anchor handling.
- **Regular-workbench feedback is specialized:** src/vs/workbench/contrib/chat/browser/planReviewFeedback/planReviewFeedbackEditorOverlay.ts restricts its feedback toolbar to resources for which isActivePlanReview returns true. In planReviewFeedbackService.ts, _addFeedback requires an existing plan-review registration, so this capability does not establish general multi-file code-review staging.
- **Agents-window functionality is not equivalent coverage:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackEditorActions.ts provides agentFeedbackEditor.action.submit and session-scoped navigation/clearing. agentFeedback.contribution.ts contributes its chat-input submission action with IsSessionsWindowContext; this is the specialized workflow the reporter explicitly distinguishes from the requested regular-editor/current-draft experience.
- **Related editor-window bug is distinct:** https://github.com/microsoft/vscode/issues/336428 is open and concerns missing command handlers when an agent-host tool asks to reveal existing review comments. It does not own creating and batching user-authored selection feedback in an ordinary chat draft.
- **Related review discussion is not a canonical duplicate:** https://github.com/microsoft/vscode/issues/339363 is open and collects feedback about granular acceptance/reversion and Keep/Undo controls. That scope does not establish ownership of this request's comment-authoring, draft-staging, snapshot, and stale-anchor behavior.
