# Issue #321151 — Make extensions trusted publishers configurable, to optionally include Microsoft, GitHub and Open AI in delayed auto-update

[https://github.com/microsoft/vscode/issues/321151](https://github.com/microsoft/vscode/issues/321151)

## Summary

This accepted Backlog request remains necessary: current main still unconditionally exempts product-defined trusted publishers from the configurable auto-update delay. The existing trusted-publisher management command controls installation prompts, not these update-delay exemptions.

## Change summary

Allow users and administrators to configure which trusted extension publishers bypass delayed automatic updates, including choosing no exemptions.

## Best solution

Provide user- and policy-manageable control over which product-trusted publishers bypass `extensions.autoUpdateDelay`, supporting an empty exemption list while preserving the current Microsoft, GitHub, and OpenAI defaults for users who do not configure it.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/contrib/extensions/common/extensions.ts`, `src/vs/workbench/services/extensionManagement/common/extensionManagementService.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsWorkbenchService.test.ts`
- **Validation:** Extend `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsWorkbenchService.test.ts` to verify that an explicitly empty configured exemption list subjects a product-trusted publisher to `extensions.autoUpdateDelay`, while the unconfigured default continues to bypass the delay.
- **Behavior:**

  > Users and managed environments can control which trusted publishers bypass delayed automatic extension updates. An explicitly empty list causes updates from Microsoft, GitHub, OpenAI, and other product-trusted publishers to observe `extensions.autoUpdateDelay`; leaving the setting unconfigured preserves current defaults. Existing per-extension auto-update controls and installation trust prompts must retain their documented behavior unless the chosen public contract deliberately unifies them.
- **Trace:**

  > `ExtensionsWorkbenchService.getAutoUpdateDelayRemaining` delegates the exemption decision to `isFromTrustedPublisher`, which reads `IProductService.trustedExtensionPublishers` directly. The similarly named `Manage Trusted Extension Publishers` command operates through `IWorkbenchExtensionManagementService.getTrustedPublishers`, which exposes only user-trusted publishers stored under `extensions.trustedPublishers`; product defaults remain unconditionally trusted in `ExtensionManagementService.isPublisherTrusted`. Thus current main has two separate trust paths, and neither lets users remove product publishers from the auto-update exemption. Keep the scope limited to publisher exemption semantics for delayed auto-updates; https://github.com/microsoft/vscode/issues/321136 separately owns minimum release age for manual and fresh installs.
- **Open decisions:**
  - Should the existing installation-publisher trust list become the single public source for auto-update-delay exemptions, or should delayed updates expose a separate configurable exemption list so installation trust and update security can differ?

## Evidence

- **current source:** `ExtensionsWorkbenchService.getAutoUpdateDelayRemaining` in `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts` returns zero whenever `isFromTrustedPublisher` matches `IProductService.trustedExtensionPublishers`; that method reads only the product-defined list and exposes no user or policy override.
- **current test:** `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsWorkbenchService.test.ts` has a test named `test getAutoUpdateDelayRemaining returns 0 for a trusted publisher`, confirming that product-trusted publishers still bypass the delay on current main.
- **existing command is distinct:** `workbench.extensions.action.manageTrustedPublishers` in `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts` only displays publishers returned from user storage. `ExtensionManagementService.isPublisherTrusted` in `src/vs/workbench/services/extensionManagement/common/extensionManagementService.ts` always accepts product defaults before consulting that storage, so the command cannot remove product-defined trust or affect the auto-update path.
