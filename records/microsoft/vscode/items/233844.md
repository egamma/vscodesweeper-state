# Issue #233844 — Tab With Problems - Improve Accessibility for Colorblind People

[https://github.com/microsoft/vscode/issues/233844](https://github.com/microsoft/vscode/issues/233844)

## Summary

Keep open for the maintainer-supported diagnostic icon beside the tab filename. Current source provides numeric problem badges, but not the explicit problem icon agreed in the discussion; the existing accessibility and tab labels already route this correctly.

## Change summary

Make tabs with diagnostics recognizable without distinguishing their text color from source-control decorations.

## Best solution

Provide a recognizable diagnostic icon next to the tab filename, following the maintainer-supported direction rather than replacing the file-type icon. Decide how it coexists with the existing problem count and source-control badges while preserving their information.

- **Behavior:**

  > A user who cannot distinguish diagnostic and source-control text colors should recognize a tab with diagnostics at a glance. The discussion supports a diagnostic icon next to the filename, rather than replacing the file-type icon. Existing file identity and tab actions must remain usable.
- **Trace:**

  > MarkersDecorationsProvider.provideDecorations in src/vs/workbench/contrib/markers/browser/markersFileDecorations.ts reads errors and warnings and returns a numeric count plus severity color. MultiEditorTabsControl in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts forwards decoration settings to resource labels, with badges suppressed for compact sticky tabs. Resource labels in src/vs/workbench/browser/labels.ts consume shared decorations, while DecorationRule in src/vs/workbench/services/decorations/browser/decorationsService.ts renders text or ThemeIcon badges and combines providers. This establishes that numeric non-color cues exist, but the requested diagnostic icon does not. The maintainer-supported placement is recorded at https://github.com/microsoft/vscode/issues/233844#issuecomment-2485725171. Keep unrelated file-label surfaces and source-control information unchanged unless the maintainer explicitly approves a broader design; uncertainty remains around the icon's coexistence with the current count badge.
- **Open decisions:**
