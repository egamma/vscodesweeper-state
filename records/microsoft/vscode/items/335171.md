# Issue #335171 — Workspace should not need to be "trusted" to create a terminal

[https://github.com/microsoft/vscode/issues/335171](https://github.com/microsoft/vscode/issues/335171)

## Summary

Workspace Trust intentionally gates terminal creation because shells can execute arbitrary code based on folder contents (e.g. shell hooks, rc files); this is documented, and a setting already exists to opt out, so it's as-designed rather than a bug.

## Change summary

Requester wants terminal creation to not require workspace trust, arguing cd/launching a terminal never executes folder-controlled code.

## Best solution

Point to the existing `terminal.integrated.allowInUntrustedWorkspace` setting (already covers this exact scenario) and the workspace trust docs; no code change needed.

  > Thanks for the report. This is intentional: Workspace Trust blocks terminal creation by default because many shells run rc/hook scripts based on the current working directory, which can execute attacker-controlled code without the user realizing it. If you're confident your shell setup is safe, you can opt out via `terminal.integrated.allowInUntrustedWorkspace` (see https://code.visualstudio.com/docs/editing/workspaces/workspace-trust#_terminal). Closing as as-designed, but feel free to reopen if there's a concrete gap the setting doesn't cover.
