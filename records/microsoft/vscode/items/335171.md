# Issue #335171 — Workspace should not need to be "trusted" to create a terminal

[https://github.com/microsoft/vscode/issues/335171](https://github.com/microsoft/vscode/issues/335171)

## Summary

This is intentional, documented workspace trust behavior with an existing opt-out setting, not a bug — a contributor already pointed to the docs and setting, and the reporter acknowledged it.

## Change summary

Requests that VS Code not require workspace trust before creating a terminal, arguing that launching a shell doesn't itself execute untrusted code.

## Best solution

Keep the current design: terminal creation is deliberately gated by workspace trust (see `_trust()` in terminalInstance.ts), with `terminal.integrated.allowInUntrustedWorkspace` as the documented opt-out for users confident their shell won't auto-execute code from cwd contents.

- **Proposed comment:**

  > Thanks for the report and the follow-up. This is intentional, documented behavior: terminal creation is gated by workspace trust because many shells can execute code automatically based on the contents of the current working directory (e.g. via `.bashrc`, direnv, etc.), so VS Code treats it conservatively by default. For users confident their shell won't do this, `terminal.integrated.allowInUntrustedWorkspace` is the documented opt-out (see https://code.visualstudio.com/docs/editing/workspaces/workspace-trust#_terminal). Closing as as-designed, but feel free to open a separate issue if you feel the dialog wording is misleading.
