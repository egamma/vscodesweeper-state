# Issue #291359 — Show matching identifiers during search

[https://github.com/microsoft/vscode/issues/291359](https://github.com/microsoft/vscode/issues/291359)

## Summary

Keep open: current main still filters models by identifiers without displaying the matching identifier, and the maintainer explicitly accepted making that match transparent. This team-authored feature request is parked in Backlog and has a concrete remaining UI gap.

## Change summary

Show the model identifier responsible for a search result when the visible model name does not explain the match.

## Best solution

When a model remains in the filtered list because its identifier matched, expose that identifier alongside the display name and highlight the matching characters while retaining the compact name-first presentation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/media/chatModelsWidget.css`, `src/vs/workbench/contrib/chat/test/browser/chatManagement/chatModelsWidget.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatManagement/chatModelsViewModel.test.ts`
- **Validation:** Add a browser widget test using a model named `Cucumber (Preview)` with identifier `robin-alpha`: searching for `ra` must keep the model visible, expose and highlight the matching identifier, and leave ordinary name matches and the unfiltered row presentation unchanged.
- **Behavior:**

  > A model returned solely because its identifier matches the search must visibly explain that result without requiring a hover. For example, searching `ra` may return `Cucumber (Preview)` because its identifier is `robin-alpha`; the row must expose that identifier and identify the matching characters. Name-based filtering, provider filtering, capability filtering, and the presentation with no active search must remain unchanged.
- **Trace:**

  > The Manage Language Models search is implemented by `ChatModelsViewModel.filterModels` and `ModelItemMatches` in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts. The view model already computes and preserves `modelIdMatches`, including the contiguous `r`/`a` match described in https://github.com/microsoft/vscode/issues/291359#issuecomment-3818928876. `ModelNameColumnRenderer.renderModelElement` in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts consumes only `modelNameMatches`; the identifier appears only in its delayed hover. The boundary is presentation transparency: do not alter the existing fuzzy/contiguous filtering semantics or expose unrelated hidden model metadata.
- **Open decisions:**
  - Should the identifier appear only when it contributes to the match and the display name does not, or whenever identifier text matches during an active search?
