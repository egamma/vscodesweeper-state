# Issue #350568 — Can't open terminal pane when VSCode is started in a folder that no longer exists

[https://github.com/microsoft/vscode/issues/350568](https://github.com/microsoft/vscode/issues/350568)

## Summary

Keep open as a terminal recovery feature request: current code explicitly rejects nonexistent starting directories, but does not offer the requested automatic fallback for a deleted workspace.

## Change summary

Allow an integrated terminal to start in the remote user's home directory when its default workspace directory no longer exists.

## Best solution

Provide a recovery path for ordinary terminals whose implicitly selected workspace directory has disappeared, while preserving meaningful errors for explicitly configured starting directories. This belongs in the core terminal launch flow, rather than requiring a WSL extension transfer.
