# Issue #304014 — Running `/fork` has no acknowledgement UX and creates multiple chat sessions

[https://github.com/microsoft/vscode/issues/304014](https://github.com/microsoft/vscode/issues/304014)

## Summary

Keep this reopened Backlog item open for the fork UX discussion the maintainer accepted. Current source provides checkpoint-button progress feedback, but the `/fork` path remains silent and repeated completed forks can retain identical titles; the related open requests do not own the full scope.

## Change summary

Make successful `/fork` operations perceptible and make the resulting conversations distinguishable, so users do not repeat the command because it appears ineffective.

## Best solution

Agree on a consistent, accessible acknowledgement and fork-identification experience in the shared chat UI, including forks of already-forked conversations. Preserve intentional creation of independent conversations rather than treating repeated completed forks as an underlying session-creation bug.

- **Behavior:**

  > Running `/fork` should make it clear that a new conversation was created and that the user is now viewing it, including when the source was itself a fork. Creating independent conversations is intentional; this work addresses acknowledgement and identification rather than removing that capability. Acceptance should include visible and screen-reader feedback, repeated forks, preserved source history, and parity with checkpoint-based forking.
