# Issue #306357 — Preferences: Open User Settings (JSON) opens in a new local window instead of the current Remote SSH window (regression in 1.99)

[https://github.com/microsoft/vscode/issues/306357](https://github.com/microsoft/vscode/issues/306357)

## Summary

The regression traces to the modal editor expansion in commit 44c142b1d5b (March 2026), which removed the `isTextual` guard that previously bypassed `MODAL_GROUP` for JSON settings editors. On current main, `getEditorGroupFromOptions` still returns `MODAL_GROUP` for command-palette-invoked settings JSON when `workbench.editor.useModal` is at its default `'some'`. In Remote SSH, this modal overlay likely manifests as a new local window rather than an in-window overlay. The bug is still present and needs triage.

## Change summary

Opening User Settings (JSON) via the Command Palette in a Remote SSH window opens a new local VS Code window instead of an in-window editor tab, regressed in 1.99.

## Best solution

Investigate how `MODAL_GROUP` / the modal editor part interacts with Remote SSH windows. Either the modal overlay should work within the remote window (most likely fix in the modal editor part), or the preferences service should fall back to `ACTIVE_GROUP` when running in a remote context. The relevant code is in `src/vs/workbench/services/preferences/browser/preferencesService.ts` (`getEditorGroupFromOptions`) and `src/vs/workbench/browser/parts/editor/modalEditorPart.ts`.
