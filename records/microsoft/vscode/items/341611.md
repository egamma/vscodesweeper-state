## Change summary

## Best solution

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotConnectors.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/copilotConnectorsService.ts`
- **Validation:** Unit tests for classification of structured scope errors, check failures and availability states, plus a test that a known requirement survives a failed follow-up status read.
- **Behavior:**

  > When a Connector cannot be used because of a missing permission, VS Code explains which of four cases applies: missing GitHub scope, external service consent, status check failed, or Connectors unavailable. It offers only the matching recovery (authorize the same account, Connect/Reconnect, retry, or none). Chat stays usable throughout and nothing prompts automatically. The requirement clears only on current authoritative runtime evidence.
- **Trace:**

  > The gap is in the reconcileCopilotConnectors helper (copilotConnectors.ts), which catches runtime failures and logs them. Structured data (connector_insufficient_scope, ConnectorStatus.authorizationRequirement, availability) is never retained or exposed. CopilotAgentSession.refreshConnectors and CopilotConnectorsService.authorize already exist and should be reused. The boundary is that scope failures must never be classified from message text or a generic 403, and a different account must never be authorized. This trace comes from the issue body only; I did not verify it against the code in this review. The UI placement and remote recheck design are where the uncertainty starts.
