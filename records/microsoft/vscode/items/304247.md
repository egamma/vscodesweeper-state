# Issue #304247 — Azure sign-in and Cosmos DB connection fail on macOS 26 (Tahoe) with PacProxyAgent crash

[https://github.com/microsoft/vscode/issues/304247](https://github.com/microsoft/vscode/issues/304247)

## Summary

The reporter confirmed that the failure persisted in 1.113 and isolated it to existing VS Code global storage: a temporary profile and clearing globalStorage restored Azure authentication. The issue should remain open because no specific corrupt state or code path has been identified, and deleting all global storage is an unsafe workaround rather than a product fix.

## Change summary

Azure authentication and Cosmos DB connections can fail repeatedly when persisted VS Code user state becomes incompatible or corrupt, while a clean profile works.

## Best solution

Identify the specific authentication or extension state that triggers the network failure, then make its owner detect and recover from invalid persisted state without requiring users to delete all global storage. The next useful evidence would be a sanitized comparison of relevant globalStorage entries between the failing profile and a working temporary profile.
