# Issue #182744 — Undo/Redo <input /> is not working in vscode.CustomTextEditorProvider

[https://github.com/microsoft/vscode/issues/182744](https://github.com/microsoft/vscode/issues/182744)

## Summary

Still reproduces on main: the custom editor's undo/redo implementation (priority 105) always takes precedence over the webview's own handler (priority 100), so native undo in webview `<input>` elements triggers document-level undo instead. The issue is correctly labeled and in Backlog with `help wanted`.

## Change summary

Undo/redo in `<input>` elements inside a CustomTextEditorProvider webview triggers the document-level undo/redo instead of the input's native undo.

## Best solution

The webview's undo handler needs to detect when focus is on a native input/textarea element inside the webview iframe and let the browser handle it natively, rather than always deferring to the custom editor's document-level undo. The fix likely involves `src/vs/workbench/contrib/customEditor/browser/customEditors.ts` (the priority-105 handler) or the webview-side script that receives the `execCommand` message, to distinguish input-focused undo from document undo.
