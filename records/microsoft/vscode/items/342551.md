# Issue #342551 — Consistent Copy Link in editor tab context menus

[https://github.com/microsoft/vscode/issues/342551](https://github.com/microsoft/vscode/issues/342551)

## Summary

Keep this focused deliverable open: existing chat and GitHub file-sharing commands provide partial coverage, not a consistent cross-editor Copy Link action. The parent story explicitly delegates this work here, and the team-authored request has no verified fixing commit or duplicate.

## Change summary

Provide a consistent, context-targeted Copy Link action across supported document, chat, GitHub issue/PR, and multi-diff editor tabs.

## Best solution

Define the supported editor/link contracts alongside the link-support audit, then deliver consistent tab-menu discovery and canonical links for those targets. Preserve the existing Agent Host chat implementation and keep its separate menu-availability follow-up outside this feature.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/share/common/share.ts`, `src/vs/workbench/contrib/share/browser/share.contribution.ts`, `src/vs/workbench/contrib/share/browser/shareService.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts`, `src/vs/workbench/browser/parts/editor/editorCommandsContext.ts`, `extensions/github/package.json`, `extensions/github/src/shareProviders.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatCopyActions.test.ts`
- **Validation:** For each supported editor type, invoke Copy Link on an inactive tab while an unrelated editor is active, inspect the clipboard target, and reopen it through the applicable sources and handlers in https://github.com/microsoft/vscode/issues/342545. Verify preserved identity and navigation context, explicit unavailable behavior without unrelated clipboard writes, and unchanged existing chat behavior. Retain the focused Chat editor Copy Link regression suite and add equivalent context-targeting checks for newly supported types.
- **Behavior:**

  > Supported link-addressable editor tabs expose a consistently named and discoverable Copy Link action. Invoking it on an inactive tab copies that tab's canonical, reopenable target rather than the active editor or an incidental UI resource. Meaningful target identity and supported navigation context survive reopening. Unsupported or unavailable targets have explicit behavior and never copy an unrelated target. Acceptance includes end-to-end checks against the agreed support matrix and preservation of existing chat-link behavior.
- **Trace:**

  > CopyChatSessionLinkAction in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts already implements context-aware Agent Host chat copying using resolveCommandsContext and has focused tests in src/vs/workbench/contrib/chat/test/browser/actions/chatCopyActions.test.ts. GitHub document links have a separate command and Share submenu contribution in extensions/github/package.json, with provider logic in extensions/github/src/shareProviders.ts. The generic share contribution uses the active editor, while ShareService.getShareActions currently returns no menu actions; neither establishes the requested cross-editor contract. The source trace establishes fragmented existing capabilities, but not canonical link support for every proposed editor type. https://github.com/microsoft/vscode/issues/342545 owns the support audit, and https://github.com/microsoft/vscode/issues/342050 explicitly retains this issue as a focused deliverable. Reuse the completed chat behavior from https://github.com/microsoft/vscode/issues/342121; its active-editor menu restriction remains separate work at https://github.com/microsoft/vscode/issues/342552.
- **Open decisions:**
  - Which document, GitHub issue/PR, and multi-diff editor targets are supported initially, with which canonical link forms, prerequisites, and preserved navigation context?
  - For unsupported or temporarily unavailable targets, should Copy Link be absent, disabled, or report an explicit explanation when invoked?
  - For mixed multi-selected editor types, what is the observable clipboard and failure contract when only some selected targets have usable links?

## Evidence

- **Focused issue, not a duplicate of its parent:** https://github.com/microsoft/vscode/issues/342050 was verified open. Its breakdown explicitly assigns consistent editor-tab Copy Link to https://github.com/microsoft/vscode/issues/342551 and says focused issues should own individual deliverables; the broader navigation story is not a replacement for this issue.
- **Existing chat capability covers only one target family:** src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts registers workbench.action.chat.copySessionLink for Agent Host chat editors. CopyChatSessionLinkAction.run resolves invocation context through resolveCommandsContext, preserves backend session identity and peer-chat context, and rejects unavailable or uncreated sessions before writing the clipboard. https://github.com/microsoft/vscode/issues/342121 is closed and records its completion through https://github.com/microsoft/vscode/pull/341095; this does not complete the broader request.
- **Existing document sharing is partial coverage:** extensions/github/package.json contributes github.copyVscodeDevLinkWithoutRange to editor/title/context/share under GitHub-repository prerequisites. extensions/github/src/shareProviders.ts provides Copy vscode.dev Link for file resources backed by GitHub repositories. Neither surface establishes a uniform Copy Link contract for chats, issue/PR views, and multi-diff editors.
- **Generic sharing is not the requested tab action:** src/vs/workbench/contrib/share/browser/share.contribution.ts registers workbench.action.share behind workbench.experimental.share.enabled, which defaults to false, and resolves its target from the active editor. ShareService.getShareActions in src/vs/workbench/contrib/share/browser/shareService.ts returns an empty array. These paths do not provide the requested context-targeted, cross-editor action.
- **Support contracts remain an explicit dependency:** https://github.com/microsoft/vscode/issues/342545 was verified open. It requests an end-to-end support matrix distinguishing supported, unsupported, and failing link forms, including document locations, sessions, GitHub targets, and commit multi-diffs; source inventory alone is not evidence that copied links reopen correctly.
- **Reusable context and regression foundations:** src/vs/workbench/browser/parts/editor/editorCommandsContext.ts resolves explicit group/editor arguments and multi-selected tabs. src/vs/workbench/contrib/chat/test/browser/actions/chatCopyActions.test.ts already covers inactive target selection, session identity, provisional sessions, multiple links, and unchanged clipboard contents on unavailable targets. Inspection was read-only; no runtime validation was performed.
