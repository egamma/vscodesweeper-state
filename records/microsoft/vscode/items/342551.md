# Issue #342551 — Consistent Copy Link in editor tab context menus

[https://github.com/microsoft/vscode/issues/342551](https://github.com/microsoft/vscode/issues/342551)

## Summary

Keep open: the existing Agent Host chat action and provider-specific sharing commands do not deliver consistent Copy Link behavior across editor types. The parent story explicitly delegates this deliverable to this issue rather than superseding it.

## Change summary

Provide a consistent editor-tab Copy Link action that resolves the invoked target and preserves its canonical identity and navigation context.

## Best solution

Define the supported editor/link contract, then provide consistent Copy Link discovery and context resolution across those editors while reusing the completed chat implementation. Validate reopening against the linked support matrix and keep the separate chat visibility bug outside this feature's scope.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/share/common/share.ts`, `src/vs/workbench/contrib/share/browser/share.contribution.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts`, `src/vs/workbench/contrib/files/browser/fileActions.contribution.ts`, `extensions/github/package.json`
- **Validation:** For each agreed supported editor type, invoke Copy Link on an inactive tab while a different target is active, paste and reopen the result, and verify target identity and represented navigation context. Repeat for unavailable targets and confirm no unrelated or unusable link reaches the clipboard; exercise existing multi-selected chat behavior and the applicable matrix from https://github.com/microsoft/vscode/issues/342545.
- **Behavior:**

  > Users should find a consistently named Copy Link action for editor types with an explicitly supported, reopenable target link. Invoking it on an inactive tab must copy that tab's target, not the active editor's target, and preserve meaningful identity and represented navigation context. Unsupported or unavailable targets must have understandable behavior without copying an unrelated or unusable link. Acceptance includes reopening copied links across the agreed support matrix and preserving existing chat behavior.
- **Trace:**

  > CopyChatSessionLinkAction in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts already resolves invoked editor context, supports multiple selected chats, and constructs identity-preserving links; this is reusable completed work from https://github.com/microsoft/vscode/pull/341095. The general sharing contribution in src/vs/workbench/contrib/share/browser/share.contribution.ts offers provider-specific menus and an active-editor-based Share command, while IShareableItem in src/vs/workbench/contrib/share/common/share.ts represents a resource URI and optional selection. File path commands and GitHub link commands provide narrower existing capabilities, not the requested common contract. The trace establishes partial coverage but not canonical link representations for every requested editor type; that boundary must be settled with https://github.com/microsoft/vscode/issues/342545. Preserve existing specialized sharing commands and chat link identity semantics; the chat active-editor visibility restriction remains separately tracked at https://github.com/microsoft/vscode/issues/342552.
- **Open decisions:**
  - Which document, chat, GitHub issue/PR, and multi-diff editor types and prerequisites are included in the initial supported contract, and which target identity and navigation context must each copied link preserve?
  - For unsupported or temporarily unavailable targets, should Copy Link be hidden, disabled with an explanation, or report an explicit error when invoked?

## Evidence

- **Existing chat capability is partial coverage:** src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts registers workbench.action.chat.copySessionLink in MenuId.EditorTitleContext for Agent Host/remote chat resources. CopyChatSessionLinkAction.run uses resolveCommandsContext, preserves session and peer-chat identity through buildOpenSessionLinkUri, and reports unavailable or uncreated sessions; it is not a cross-editor action.
- **Existing sharing surface does not satisfy the request:** src/vs/workbench/contrib/share/browser/share.contribution.ts exposes provider actions through share submenus and gates registration on workbench.experimental.share.enabled, which defaults to false. Its workbench.action.share command derives its target and selection from the active editor; this does not establish the requested invoked-tab, canonical-link contract.
- **Other built-in commands cover narrower cases:** src/vs/workbench/contrib/files/browser/fileActions.contribution.ts contributes Copy Path and Copy Relative Path to tab menus, while extensions/github/package.json declares github.copyVscodeDevLink, github.copyVscodeDevLinkFile, and github.copyVscodeDevLinkWithoutRange. These provide paths or GitHub-specific links, not one consistent action across documents, chats, issue/PR views, and multi-diff editors.

Its scope is Agent Host chat editor context menus, not the broader feature requested here.
