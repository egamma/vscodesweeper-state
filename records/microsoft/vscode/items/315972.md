## Evidence

- **environment isolation:** The report reproduces with extensions disabled on KDE Plasma 6.6/NVIDIA 595.71.05, while the same VS Code build works with `--ozone-platform=x11`.
- **GPU initialization:** Native Wayland reports GPU0 as VENDOR=0x0000, DEVICE=0x0000 with GPU compositing and OpenGL disabled; X11 detects the RTX 3090 and enables acceleration.
- **upstream boundary:** The failure began after a system update, and the reporter cites other NVIDIA/KWin graphical failures on that system. VS Code 1.119.0 used Electron 39.8.8 according to package.json at commit 8b640eef5a6c6089c029249d48efa5c99adf7d51.
- **related upstream diagnosis:** https://github.com/microsoft/vscode/issues/282662 documents a similar native-Wayland black screen that a maintainer traced to Chromium's DRM render-node detection, but its hardware and workaround differ, so it is not a confirmed canonical duplicate.
- **distinct related report:** https://github.com/microsoft/vscode/issues/280464 tracks NVIDIA/Wayland blank startup after Electron 38 with explicit VA-API GPU-process errors; this report lacks those errors and followed an NVIDIA/system update, so the shared root cause is not yet established.
