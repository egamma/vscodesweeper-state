# Issue #241683 — Failure to use code.cmd --install-extension <valid extension id> behind authenticating proxy server

[https://github.com/microsoft/vscode/issues/241683](https://github.com/microsoft/vscode/issues/241683)

## Summary

Valid bug: the CLI `--install-extension` path uses Node.js `RequestService` which does not handle HTTP 407 proxy authentication (Kerberos/NTLM), unlike the Electron UI path that delegates to Chromium's `net.request` with built-in proxy auth negotiation. The reporter confirmed a 407 response from an authenticating proxy. No fix on current main.

## Change summary

CLI `--install-extension` fails with 'Extension not found' behind an authenticating proxy because the Node.js request path does not negotiate Kerberos/NTLM credentials on HTTP 407.

## Best solution

The CLI's `RequestService` (instantiated in `src/vs/code/node/cliProcessMain.ts`) needs to handle 407 responses by invoking Kerberos/NTLM negotiation — either by calling `lookupKerberosAuthorization()` on 407 and retrying, or by wiring up `@vscode/proxy-agent` with auth support in the CLI path. The `lookupAuthorization` method currently returns `undefined` in the node implementation. Additionally, the CLI should respect `http_proxy`/`https_proxy` environment variables even when `http.proxy` is set, per documented behavior.
