# Issue #241683 — Failure to use code.cmd --install-extension <valid extension id> behind authenticating proxy server

[https://github.com/microsoft/vscode/issues/241683](https://github.com/microsoft/vscode/issues/241683)

## Summary

The CLI still lacks automatic proxy authentication on its request path, and a Marketplace HTTP 407 is converted into a misleading extension-not-found result. The environment-variable precedence complaint is separate: current documentation explicitly makes those variables a fallback when http.proxy is unset.

## Change summary

Allow CLI extension installation through a Kerberos-authenticating proxy and accurately report proxy authentication failures.

## Best solution

Bring CLI proxy authentication into parity with the working desktop installation flow and preserve actionable authentication errors. Retain the documented precedence of explicit http.proxy settings over environment variables.
