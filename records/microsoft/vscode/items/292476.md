# Issue #292476 — Do not auto-install Github Copilot on Remote

[https://github.com/microsoft/vscode/issues/292476](https://github.com/microsoft/vscode/issues/292476)

## Summary

Keep open: existing settings control connection-time installation and extension placement, but do not establish the requested consent and uninstall guarantee across Copilot setup. The current setup path still requests installation on both local and remote servers; the reported memory exhaustion is supporting impact, not this request's proposed fix.

## Change summary

Require explicit consent before installing Copilot remotely and preserve the user's choice after a remote uninstall.

## Best solution

Establish a consistent remote-installation choice honored by connection-time extension installation and Copilot setup, without requiring users to disable local Copilot or make the remote extensions directory unwritable. Agree on consent persistence and uninstall semantics before implementation.

- **Behavior:**

  > The reporter wants local Copilot use without silently deploying Copilot to a remote host. Connecting, reloading, reconnecting, or submitting a chat prompt must not override a declined remote-installation choice. An explicit remote uninstall must have defined, durable consequences for later automatic installation. Acceptance should cover both connection-time installation and chat setup; diagnosing the reported memory growth is separate work.
- **Trace:**

  > ChatSetupController.doInstall() in src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupController.ts requests installEverywhere for the configured chat extension. ExtensionsWorkbenchService in src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts selects missing installations across installable servers, while ExtensionManagementService.getInstallableExtensionManagementServers() uses extension-kind placement. remote.defaultExtensionsIfInstalledLocally governs connection-time defaults, whereas remote.extensionKind governs placement; neither registration establishes a remembered remote-consent contract. The reporter configured GitHub.copilot, while current setup installs the product-configured chat extension, so establish the exact extension identities and triggers before attributing an override failure. Preserve explicitly requested remote installs and local Copilot functionality; do not broaden this into memory-leak remediation. Related demand appears at https://github.com/microsoft/vscode/issues/277875 and https://github.com/microsoft/vscode/issues/248248, but neither establishes the full requested contract.
- **Open decisions:**
  - Should consent be remembered per remote host, per workspace, or globally for remote connections?
  - Should uninstalling Copilot remotely prohibit subsequent automatic installation until an explicit remote install, even when the user later invokes chat setup?
  - Should a first remote installation require confirmation by default, or should an existing explicit installation preference authorize it?
