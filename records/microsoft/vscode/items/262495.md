# Issue #262495 — Remove the 'Keep' button in Chat Agent mode and use standard save behavior

[https://github.com/microsoft/vscode/issues/262495](https://github.com/microsoft/vscode/issues/262495)

## Summary

Keep open: removing individual Keep/Undo controls does not establish the requested standard save semantics, and current source still separates saving from accepting chat edits. This team-authored Backlog request has 29 upvotes and maintainer support; no verified older canonical or issue-referencing fix establishes completion.

## Change summary

Make agent edits behave like ordinary workspace edits, respecting configured save behavior without a separate Keep/Undo acceptance state.

## Best solution

Establish ordinary save and undo semantics for agent edits while preserving intentional change review and safe source-action execution. Resolve the review and formatting contract with maintainers before treating UI removal or timed auto-acceptance as completion.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedFileEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`
- **Validation:** The plan should define executable editing-service tests for files.autoSave off and enabled: agent edits must follow the agreed ordinary-save contract, format-on-save must run at the agreed save boundary, and no separate Keep action may be required. Include manual acceptance checks covering subsequent agent edits after formatting, two sessions editing one file, and deleting an agent-created file without an unrelated chat action restoring it.
- **Behavior:**

  > Agent edits should have the same persistence meaning as ordinary workspace edits, without a second acceptance operation after saving. Saving and auto-save should respect the user's settings, and source actions must not unexpectedly run later because an old chat is accepted. Review must remain understandable without introducing a hidden persistence state. Acceptance checks should cover manual saving, auto-save, format-on-save, subsequent agent edits, and interactions with another chat or external file changes.
- **Trace:**

  > ChatEditingModifiedDocumentEntry.acceptAgentEdits() saves completed edits while skipping save participants, whereas _doAccept() separately keeps the changes and may force an explicit save. ChatEditingModifiedFileEntry retains Modified/Accepted/Rejected state and implements chat.editing.autoAcceptDelay through the same acceptance operation; ChatEditingSession retains snapshots and restoration. These establish that timed acceptance is not equivalent to the requested ordinary-save contract, but the applicability of these paths across current agent-session implementations still needs mapping. The maintainer discussion at https://github.com/microsoft/vscode/issues/262495#issuecomment-3207201167 identifies accumulated review and source-action timing as unresolved constraints. https://github.com/microsoft/vscode/issues/339363 documents newer UI removal, not proof that persistence semantics changed; https://github.com/microsoft/vscode/pull/262885 covers only staging and committing. Preserve ordinary manual-edit behavior and intentional review capabilities; the later commenter's disk-versus-buffer policy is not an approved expansion of this request.
- **Open decisions:**
  - Should ordinary-save semantics replace the review acceptance model for all agent sessions, or be an explicitly selectable mode?
  - What change-review and explicit rollback behavior should remain once saving no longer requires a separate Keep decision?
  - When ordinary saving runs formatting or source actions during an agent turn, what user-visible behavior should apply if the agent's subsequent edits target the pre-format contents?
