# Issue #262495 — Remove the 'Keep' button in Chat Agent mode and use standard save behavior

[https://github.com/microsoft/vscode/issues/262495](https://github.com/microsoft/vscode/issues/262495)

## Summary

Thanks for the detailed proposal. The central request remains unresolved on current main, has substantial demand and maintainer support, and is a protected team-authored Backlog item; it should remain open while the review and save-participant semantics are designed.

## Change summary

Replace Chat Agent's separate Keep/Undo ownership state with ordinary workspace edits governed by standard save, auto-save, and undo behavior.

## Best solution

Converge on direct workspace edits governed by normal save and auto-save settings, while preserving useful review through non-owning diffs or checkpoints that cannot restore stale chat snapshots over newer work.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedFileEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingService.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingActions.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingSessionStorage.test.ts`
- **Validation:** Extend the ChatEditingService and chat editing action tests to assert that completed agent edits have no undecided Keep/Undo state, follow configured save behavior, and cannot restore stale snapshots; run `scripts/test.sh --grep 'ChatEditingService'` plus the relevant action and storage suites.
- **Behavior:**

  > Agent edits should behave like ordinary workspace edits rather than entering a separate chat-owned Keep/Undo state. Saving and auto-saving must follow the user's normal file settings, and closing or reopening a chat must not replay stale content over newer workspace changes. Users must still have a clear way to inspect agent changes, and ordinary editor or source-control undo/revert workflows must remain available. Acceptance should cover manual save, auto-save, external or multi-chat edits, session reload, and save participants such as formatting.
- **Trace:**

  > Current agent edits enter ModifiedFileEntryState.Modified in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts; src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts turns that state into pending UI, and src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts exposes Keep/Undo commands. Accepting an entry invokes save behavior and save participants, while ChatEditingSession persists snapshots and can restore modified content, so this is more than a removable button. `chat.editing.autoAcceptDelay` merely resolves the same state after a timer and therefore does not satisfy direct editing. The reported boundary includes text files, created/deleted files, notebooks, external tool edits, and session restoration; checkpoint-based historical review should not be removed accidentally. Related stale-state failures are tracked separately, including https://github.com/microsoft/vscode/issues/313703 and https://github.com/microsoft/vscode/issues/284873.
- **Open decisions:**
  - After Keep/Undo is removed, should chat retain any persistent per-session baseline or changed-file timeline for review, or should review be derived only from current workspace/source-control state and explicit checkpoints?
  - When agent edits are streamed, should configured save participants run immediately under normal save/auto-save timing, or only at a stable edit boundary to avoid formatters and source actions interfering with subsequent agent edits?

## Evidence

- **current source:** Current main still implements a distinct pending state: src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts registers Keep and Undo actions, while src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts exposes pending entries through hasUndecidedChatEditingResourceContextKey.
- **save behavior:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts saves with save participants when `_doAccept()` runs, so Keep remains behaviorally distinct from the agent edit and from the user's configured save timing.
