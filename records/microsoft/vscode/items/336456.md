## Evidence

- **verified canonical:** https://github.com/microsoft/vscode/issues/278443 was created on 2025-11-19 and is currently open. Its reproduction describes the same GNOME-environment notification on Linux Mint, and its expected behavior explicitly says the message should not assume GNOME when a keyring is unavailable. This encompasses the Cinnamon wording complaint.
- **warning source:** In src/vs/workbench/services/secrets/electron-browser/secretStorageService.ts, NativeSecretStorageService.notifyOfNoEncryption selects the 'You're running in a GNOME environment' message using isGnome(provider). src/vs/platform/encryption/common/encryptionService.ts defines that predicate over gnome_any, gnome_libsecret, and gnome_keyring storage backends, not desktop environments.
- **desktop detection is separate:** src/vs/platform/encryption/electron-main/encryptionMainService.ts obtains the provider from Electron safeStorage.getSelectedStorageBackend(). Meanwhile, src/vs/base/common/desktopEnvironmentInfo.ts already recognizes XDG_CURRENT_DESKTOP=X-Cinnamon as CINNAMON; the notification does not consult that detection.
- **reporter update:** https://github.com/microsoft/vscode/issues/336456#issuecomment-5702009580 reports that the warning no longer appears with visual-studio-code-bin version 1.138, without gnome-keyring installed. The reporter could not retest the Arch Code - OSS package because its downloads returned 404. This does not establish that the remaining warning text was fixed.
- **distinct related issue:** https://github.com/microsoft/vscode/issues/187338 concerns failure to use an installed keyring, rather than misleading Cinnamon/GNOME identification. The wording-specific scope of https://github.com/microsoft/vscode/issues/278443 makes it the appropriate canonical.
