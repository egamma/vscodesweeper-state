# Issue #332870 — BYOK Chat Completions: historical reasoning_content dropped across turns (Custom Endpoint & extension providers; Kimi K3 / GLM / DeepSeek)

[https://github.com/microsoft/vscode/issues/332870](https://github.com/microsoft/vscode/issues/332870)

## Summary

Still reproduces on main: the historical-thinking gate in toolCalling.tsx unconditionally excludes chat-completions, and groupThinkingParts() drops id-less thinking parts, so BYOK/extension-contributed thinking models lose reasoning_content across turns exactly as described.

## Change summary

BYOK Chat Completions models (Kimi K3, GLM, DeepSeek thinking mode) and extension-contributed providers silently drop reasoning_content from prior turns, breaking or degrading models that require it to be echoed back.

## Best solution

Extend the historical-thinking gate in toolCalling.tsx to include chat-completions endpoints that declare thinking support (following the existing supportsAdaptiveThinking precedent for the messages API), and add an id fallback so groupThinkingParts()/extChatEndpoint.ts don't drop id-less thinking parts.
