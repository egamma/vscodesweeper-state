# Issue #336405 — No sound is played in "About" dialog or when closing not saved file since 1.136

[https://github.com/microsoft/vscode/issues/336405](https://github.com/microsoft/vscode/issues/336405)

## Summary

Keep this open as a likely Electron/GTK regression affecting native dialog sounds on Ubuntu Wayland. The reporter's two-machine reproduction and Electron version comparison support upstream investigation, but the suspected change is not yet proven responsible.

## Change summary

Native About and unsaved-file confirmation dialogs stopped playing system sounds after upgrading from VS Code 1.135.0 to 1.136.0.

## Best solution

Restore native dialog sound behavior in the Electron/GTK path and adopt the upstream correction in VS Code. First isolate the regression between Electron 42.8.1 and 42.10.0 rather than adding a separate VS Code beep that could duplicate native sounds.

## Evidence

- **Confirmed reporter reproduction:** https://github.com/microsoft/vscode/issues/336405#issuecomment-5696916265 reports identical failures on two Ubuntu 24.04 Wayland machines, from both launcher and terminal. The issue also reports reproduction with all extensions disabled and persistence through VS Code 1.138.0.
- **Dependency isolation:** The same comment identifies Electron 42.8.1 in the working VS Code 1.135.0 build and Electron 42.10.0 in the affected 1.136.0 build, with Chromium unchanged at 148.0.7778.280. This supports an Electron regression but does not establish the exact offending commit.
- **Current native dialog boundary:** src/vs/workbench/electron-browser/parts/dialogs/dialogHandler.ts: NativeDialogHandler.about and confirm delegate to nativeHostService.showMessageBox. src/vs/platform/dialogs/electron-main/dialogMainService.ts: DialogMainService.showMessageBox forwards the normalized options to electron.dialog.showMessageBox; src/vs/platform/dialogs/electron-main/dialogMainUtils.ts does not introduce sound suppression. These paths establish native dependency ownership, not a source-only reproduction of the missing sound.
- **Verified upstream lead, not a fix:** https://github.com/electron/electron/pull/52410 is a merged backport of https://github.com/electron/electron/pull/52238. Its shell/browser/ui/message_box_gtk.cc diff changes GetGtkUiPlatform from the active LinuxUi singleton to ui::GetLinuxUiTheme(ui::SystemTheme::kGtk), with pointer checks. It fixes a crash and contains no explicit sound restoration; its responsibility for this regression remains unconfirmed.
- **Canonical search:** The supplied lead https://github.com/microsoft/vscode/issues/40239 was verified open but concerns enabling and disabling extensions through configuration, not native dialog sounds. An additional open-issue search for dialog sound did not identify a matching canonical; no verified duplicate supports closing this re-reviewed report.
