# Issue #313533 — Support explicit `[\`symbolName\`](path/to/file.py)` symbol links and deprecate optimistic backtick matching

[https://github.com/microsoft/vscode/issues/313533](https://github.com/microsoft/vscode/issues/313533)

## Summary

This team-authored feature request remains open: the explicit `[\`symbol\`](path)` linkification via `SymbolLinkifier` is implemented and was improved in PR #314864, but the second half — deprecating optimistic backtick matching (`InlineCodeSymbolLinkifier`) — has not been done. The `InlineCodeSymbolLinkifier` is still registered and active in `conversationFeature.ts`.

## Change summary

Shift chat symbol links from optimistic bare-backtick matching to explicit `[\`symbolName\`](path)` links rendered as pill widgets, and deprecate the false-positive-prone optimistic approach.

## Best solution

The `SymbolLinkifier` already handles the explicit `[\`symbol\`](path)` pattern. The remaining work is to deprecate/remove `InlineCodeSymbolLinkifier` from `extensions/copilot/src/extension/linkify/vscode-node/inlineCodeSymbolLinkifier.ts` and its registration in `conversationFeature.ts`, gated behind model readiness to reliably emit explicit links. PR #314281 and #314864 advanced the explicit-link path but did not touch the deprecation.
