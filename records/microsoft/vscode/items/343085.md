# Issue #343085 — Add model invoked to edittelemetry.editsources.details telemetry event as well as to the sourcekey field

[https://github.com/microsoft/vscode/issues/343085](https://github.com/microsoft/vscode/issues/343085)

## Summary

The requested attribution is still missing: edit-survival telemetry records the selected model, Auto tier, and fusion model, but not the actual model invoked. Existing response telemetry does not cover the requested per-model edit grouping.

## Change summary

Include the actual invoked model in editTelemetry.editSources.details and its sourceKey so Auto-routed edits can be measured separately.

## Best solution

Carry actual model provenance from the response that produced each edit into edit-source metadata and the details event, preserving selected-model attribution separately. Different invoked models within one reporting window should retain distinct source groups without relying on request-level joins.

- **Source grouping does not distinguish invoked models:** src/vs/editor/common/textModelEditSource.ts: EditSources.chatApplyEdits records $modelId, $autoTier, and $fusionModel; TextModelEditSource.toKey(1) builds the telemetry grouping key from that metadata. - **Emission confirms the remaining gap:** src/vs/workbench/contrib/editTelemetry/browser/telemetry/editSourceTrackingImpl.ts: getDetailsGroupingKey and sendTelemetry group by source metadata and emit sourceKey: repr.toKey(1), modelId: repr.props.$modelId, autoTier, and fusionModel. The requested invoked-model dimension is absent from both grouping and payload.
