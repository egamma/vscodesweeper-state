# Issue #301044 — Feature request: Add newChat option to agent handoffs and a command to invoke prompt files programmatically

[https://github.com/microsoft/vscode/issues/301044](https://github.com/microsoft/vscode/issues/301044)

## Summary

This team-authored request identifies a real gap in multi-agent workflow orchestration: handoffs cannot intentionally start a fresh chat while preserving an explicit prompt payload. It should remain open for a product/API decision rather than receiving a judgment close.

## Change summary

Allow an agent handoff or programmatic prompt-file invocation to begin a fresh chat session with the target agent, model, tools, and prompt.

## Best solution

Define one supported orchestration contract that can create a fresh chat and transfer an explicit prompt payload, then let handoffs and prompt-file commands use that contract without depending on workspace files. The design should preserve an intentional user transition and avoid enabling hooks to launch unbounded autonomous chat chains.

## Plan brief

- **Likely files:** `extensions/copilot/src`, `src/vs/workbench/contrib/chat`
- **Validation:** Add an integration scenario that invokes a handoff configured for a fresh chat, verifies a distinct chat session is created with the selected target agent and exact generated prompt, and confirms existing handoffs without the option continue in the current session.
- **Behavior:**

  > A workflow author can explicitly request that a handoff start a fresh chat with the selected target agent and a defined prompt payload. The new session must not inherit prior conversational turns, while workspace artifacts remain available through normal workspace access. Existing handoffs must continue in the current chat by default. The accepted design must also define whether and how prompt-file commands or lifecycle hooks can initiate the same transition.
- **Trace:**

  > The supplied report establishes that current `.agent.md` handoffs continue in the same chat and that `.prompt.md` files can be selected manually but cannot be invoked as a fresh-session handoff. The confirming comment establishes that an in-memory generated prompt, not only a workspace prompt file, is part of the desired contract. Investigation should trace handoff metadata parsing and dispatch in extensions/copilot/src together with chat-session creation and command registration under src/vs/workbench/contrib/chat. Preserve current handoff behavior when the new capability is not requested, and do not treat https://github.com/microsoft/vscode-copilot-release/issues/14161 as the owning tracker because Copilot Chat is now in core. The uncertainty begins at the public workflow contract: whether this is a handoff-only flag, a general prompt invocation command, or both, and what automation safeguards apply.
- **Open decisions:**
  - Should a fresh-session transition be exposed only as handoff metadata, as a generally invocable command for prompt files and generated prompts, or through both surfaces?
  - What state is transferred to the new session beyond the target agent and prompt payload, such as model/tool selections and attachments?
  - May lifecycle hooks invoke and send a fresh chat without an explicit user action, or must the transition require confirmation to prevent unintended autonomous chains?
