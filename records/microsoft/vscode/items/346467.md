# Issue #346467 — Agents window: feature-branch "lanes" with nested worktree sessions that branch from, merge into, and run alongside their parent

[https://github.com/microsoft/vscode/issues/346467](https://github.com/microsoft/vscode/issues/346467)

## Summary

Keep open as a feature request: current source already supports some nested-worktree and session-targeted task workflows, but not the complete parent-branch integration experience. The related design issues do not own the same full request, so they are not verified duplicate targets.

## Change summary

Support persistent feature-branch lanes with isolated child runs, safe integration into the feature worktree, and worktree-targeted launching.

## Best solution

Design the remaining parent-branch and integration contracts around existing nested chats, branch selection, and session-aware task execution rather than introducing a parallel session model. Coordinate with the existing parallel-work design discussions while retaining this report's distinct parent-targeted merge and launch requirements.

- **Behavior:**

  > A feature lane supports planning in its feature worktree and isolated implementation runs based on the feature's intended local state. Integrating a child updates the feature worktree, not the primary checkout, and refuses a dirty destination without leaving it mid-merge after conflicts. Users can run or debug the selected worktree without opening another editor window. Acceptance must distinguish capabilities already available through nested-session branch selection and session-targeted tasks from the remaining inheritance, integration, and debugger requirements.
- **Trace:**

  > createSessionInputSchema and applyCreateSessionTool in src/vs/platform/agentHost/node/shared/sessionServerTools.ts already support current-session chats with isolated working directories but expose no base-branch argument. src/vs/platform/agentHost/node/shared/worktreeIsolation.ts now preserves the selected commitish rather than applying the reported blanket remote preference. AgentHostMergeOperationHandler.invoke in src/vs/platform/agentHost/node/agentHostMergeOperationHandler.ts targets the primary checkout, not another feature worktree selected through session parentage. RunScriptAction dispatches session/chat-targeted tasks, and AgentHostSessionTaskRunner already resolves their cwd and workspaceFolder accordingly; debugger retargeting remains outside the established trace. Preserve provider-neutral session ownership, existing explicit branch choices, ordinary task behavior, and cleanup safety. Coordinate design with https://github.com/microsoft/vscode/issues/322931 and https://github.com/microsoft/vscode/issues/336620 without treating either as a duplicate canonical.
- **Open decisions:**
  - Should a feature lane be an ordinary session containing nested chats, or a distinct persistent branch-level container with its own lifecycle?
  - Should worktree-targeted debugging reuse the selected worktree's configuration or the originating workspace's configuration, and should switching targets stop only the related application launch or other active debug sessions too?
