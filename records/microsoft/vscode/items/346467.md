# Issue #346467 — Agents window: feature-branch "lanes" with nested worktree sessions that branch from, merge into, and run alongside their parent

[https://github.com/microsoft/vscode/issues/346467](https://github.com/microsoft/vscode/issues/346467)

## Summary

Keep open for design: existing nested chats, session-aware tasks, and merge actions provide parts of this workflow, but do not establish feature-branch parentage and safe child-to-parent integration. The related design issues overlap without owning the full request.

## Change summary

Support persistent feature-branch lanes with isolated child runs, parent-targeted integration, and worktree-aware launching.

## Best solution

Define feature-lane branch and lifecycle semantics using the existing session/chat model, then address parent-targeted integration and launch/debug gaps incrementally. Reuse session-aware task execution rather than introducing a second worktree task mechanism.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/shared/sessionServerTools.ts`, `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`, `src/vs/platform/agentHost/node/agentHostMergeOperationHandler.ts`, `src/vs/sessions/contrib/chat/browser/runScriptAction.ts`, `src/vs/sessions/contrib/terminal/browser/agentHostSessionTaskRunner.ts`
- **Validation:** Plan acceptance around a repository with local-only feature commits and a stale origin counterpart: create two isolated children, verify their starting commits, integrate into the feature without changing master, reject a dirty parent, and leave the parent out of merge state after a conflict. Verify task/debug launches use the selected worktree and exercise switching from an already running launch.
- **Behavior:**

  > A feature lane retains a feature branch while isolated child runs start from its local work and integrate back into that feature rather than master. Dirty parents block integration, and conflicts must not leave the parent mid-merge. Users can run or debug a selected worktree without opening another editor window, with explicit handling of an already running launch. Preserve existing independent-session and ordinary workspace workflows.
- **Trace:**

  > create_session in src/vs/platform/agentHost/node/shared/sessionServerTools.ts already distinguishes current-session chats from independent sessions and supports worktree selection, but has no base-branch input. WorktreeIsolation in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts passes the selected branch directly to Git, unlike the remote-preference implementation described in the report. AgentHostMergeOperationHandler in src/vs/platform/agentHost/node/agentHostMergeOperationHandler.ts targets the primary checkout, not an arbitrary parent feature worktree. AgentHostSessionTaskRunner already runs tasks against a chat's working directory and resolves workspaceFolder there; debug-launch equivalence was not established. Existing nested-chat and custom-group presentation should not be confused with durable Git integration parentage. Coordinate with https://github.com/microsoft/vscode/issues/322931 and https://github.com/microsoft/vscode/issues/336620 without treating those broader design discussions as duplicate ownership.
- **Open decisions:**
  - Does a feature lane use the existing session-wide archive and lifecycle contract, or must child runs remain independently archivable and restorable?
  - Should launch/debug worktree selection be scoped to Agents-window actions, or also change the ordinary editor window's Run and Debug and Run Task surfaces?
