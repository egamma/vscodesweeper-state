# Issue #343475 — Feature Request: Add hooks for confirmation prompt and response-received events in VS Code Copilot Agent

[https://github.com/microsoft/vscode/issues/343475](https://github.com/microsoft/vscode/issues/343475)

## Summary

Keep open as a feature request: current VS Code notification settings do not expose script hooks for these events. The existing Stop hook partially supports completion reminders, but does not cover confirmation notifications or the requested focus-aware notification semantics.

## Change summary

Expose confirmation-needed and response-received hooks for custom reminder scripts, respecting the existing notification modes.

## Best solution

Provide a supported notification-hook contract for VS Code agent sessions that lets users supply their own reminder transport without bundling a mobile-push integration. Define its relationship to the existing notification settings and Stop hook before implementation.

## Evidence

- **Existing notification capability:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.notifyWindowOnConfirmation and chat.notifyWindowOnResponseReceived with off, windowNotFocused, and always modes. These settings configure OS notifications, not custom script execution.
- **Notification execution path:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts observes requestNeedsInput transitions and completed-response busy-to-idle transitions. _notifyIfNeeded and _notifyIdleIfNeeded apply configuration and window-focus checks before calling _hostService.showToast; neither dispatches a user hook.
- **Target-specific hook support:** src/vs/workbench/contrib/chat/common/promptSyntax/hookTypes.ts lists Stop, PreToolUse, and other lifecycle hooks for Target.VSCode, but no Notification or PermissionRequest event. Notification and permissionRequest metadata exists separately for Target.GitHubCopilot, which does not establish support in the VS Code target.
- **Partial workaround is not full coverage:** extensions/copilot/src/extension/intents/node/toolCallingLoop.ts invokes executeStopHook during stopping and can continue the loop afterward. A Stop script can provide a completion-related reminder, but it is not the notifier's completed-response event, supplies no confirmation-needed event, and does not apply the two notification settings' focus gating.
