# Issue #333447 — Remote-SSH: Agent Session changed-file diff opens working-tree side as local Windows path, not vscode-remote:// URI

[https://github.com/microsoft/vscode/issues/333447](https://github.com/microsoft/vscode/issues/333447)

## Summary

Traced a real, still-open bug in the agent-host URI wrapper: `wrapAgentHostUri` (src/vs/platform/agentHost/common/agentHostUri.ts) unwraps any `file:` URI back to a plain local path whenever `connectionAuthority === 'local'`, but the ambient agent-host connection is *always* authority `'local'` — even in a Remote-SSH window, where (per the file's own doc comment) 'the ambient host is itself remote'. That mismatch is exactly the symptom reported: a working-tree diff URI for a remote file resolves as a bare local Windows path instead of `vscode-remote://ssh-remote+<host>/...`.

## Change summary

Opening the working-tree side of an Agent Session's changed-file diff over Remote-SSH fails because the client treats a remote POSIX file path as a local Windows path instead of a `vscode-remote://` URI.

## Best solution

Fix `wrapAgentHostUri`'s `local`-passthrough optimization (src/vs/platform/agentHost/common/agentHostUri.ts, `AMBIENT_AGENT_HOST_AUTHORITY`/`toAgentHostUri`) so it only skips wrapping when the ambient host is genuinely same-machine, not merely authority `'local'` — the ambient authority is reused for the remote window-bridge case too (see the doc comment on `AMBIENT_AGENT_HOST_AUTHORITY` in agentHostConnectionsService.ts). This likely needs the caller (e.g. `AgentHostResponseFileChangesProvider`/`agentHostProtocolClient.ts`) to also know whether the ambient connection is itself remote, so it's a multi-call-site fix, not a one-line patch.
