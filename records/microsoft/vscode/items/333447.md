# Issue #333447 — Remote-SSH: Agent Session changed-file diff opens working-tree side as local Windows path, not vscode-remote:// URI

[https://github.com/microsoft/vscode/issues/333447](https://github.com/microsoft/vscode/issues/333447)

## Summary

Keep open: current source still allows the changed-file provider to return a remote host's file URI as a local resource. Changeset ownership and remote transport code have changed since the report, but the supplied steps suffice to retest; no verified fix or eligible older duplicate was found.

## Change summary

Agent-session changed-file diffs on Windows over Remote-SSH fail because the working-tree resource loses its remote filesystem identity.

## Best solution

Make changed-file diffs preserve the owning remote workspace's resource identity while keeping checkpoint snapshots readable through the Agent Host. Investigate the immutable-snapshot watch warning separately rather than treating it as the cause of the working-tree failure.

- **Trace:**

  > AgentHostSessionHandler constructs AgentHostResponseFileChangesProvider using the connection and a separate connectionAuthority; AgentHostChatContribution supplies the local authority even when its service represents an editor remote host. In agentHostResponseFileChanges.ts, changesetEditToEntryDiff and _fileEditToEntryDiff use toAgentHostUri for modified resources; wrapAgentHostUri preserves raw file URIs under the local authority. EditorRemoteAgentHostTransport maps working directories but not changeset file-edit payloads, while EditorRemoteAgentHostServiceClient exposes a distinct connection-owned mapper. This identifies a plausible current failure path, but the complete remote subscription-to-editor flow has not been executed and the correct identity boundary must be confirmed before changing it. Preserve opaque snapshot content references, local session behavior, and connections to other Agent Hosts; do not globally reinterpret every file URI using the active SSH authority. The newer corroborating report is https://github.com/microsoft/vscode/issues/334464; retain this older issue rather than closing it into that report.
