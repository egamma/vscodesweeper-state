# Issue #333447 — Remote-SSH: Agent Session changed-file diff opens working-tree side as local Windows path, not vscode-remote:// URI

[https://github.com/microsoft/vscode/issues/333447](https://github.com/microsoft/vscode/issues/333447)

## Summary

Traced a real, plausible root cause on main: the AgentHost URI wrapper assumes the in-window agent host and the client always share a machine/OS, which is false in a Remote-SSH window, so the working-tree side of an agent-session diff leaks an unwrapped `file:` URI to the client and gets resolved as a local path.

## Change summary

Opening the working-tree side of an agent-session changed-files diff over Remote-SSH fails because the URI is treated as a local Windows path instead of a `vscode-remote://` resource.

## Best solution

In src/vs/platform/agentHost/common/agentHostUri.ts, `wrapAgentHostUri` short-circuits and returns the original `file:` URI unchanged whenever `connectionAuthority === LOCAL_AGENT_HOST_AUTHORITY` ('local'), per the documented assumption that 'the in-process agent host... always runs on the same machine... as the client' (see the doc comment on `LOCAL_AGENT_HOST_AUTHORITY`). That assumption breaks when the whole window is itself a Remote-SSH window: the 'local' in-window agent host then runs on the remote host, not the client's Windows machine, so its `file:` URIs need remote-authority translation but get passed through raw. `localAgentHostSessionsProvider.ts` already injects `IWorkbenchEnvironmentService` (used today only for `isSessionsWindow`); a fix likely needs to consult `environmentService.remoteAuthority` in `_diffUriMapper()`/`wrapAgentHostUri` so a local-authority agent host running inside a remote window still gets its file URIs wrapped/translated to the window's actual remote authority instead of being treated as same-machine.

## Evidence

- **server-side URI construction:** src/vs/platform/agentHost/node/agentHostGitService.ts:1503-1518 (parseGitDiffRawNumstat) builds `afterFileUri = URI.joinPath(repositoryRoot, change.newPath)` from a plain `URI.file(repositoryRootPath)` root (line 130) and sends `afterFileUri.toString()` as the working-tree `after.uri` — a scheme-`file` URI with no authority, backslashes only appearing once the client mis-resolves it.
- **client-side mapping bypass:** src/vs/platform/agentHost/common/agentHostUri.ts:wrapAgentHostUri — `if (connectionAuthority === 'local' && originalUri.scheme === Schemas.file) { return originalUri; }` unconditionally skips wrapping for the in-window agent host, based on the LOCAL_AGENT_HOST_AUTHORITY doc comment's assumption that it 'always runs on the same machine... as the client', which does not hold for a Remote-SSH window.
- **call site:** src/vs/sessions/contrib/providers/agentHost/browser/localAgentHostSessionsProvider.ts:519-522 `_diffUriMapper()` always passes the literal `LOCAL_AGENT_HOST_AUTHORITY`, and the class already injects `IWorkbenchEnvironmentService` (currently only for `isSessionsWindow`) that could expose `remoteAuthority`.
- **prior related fix:** Reporter cites the older, closed https://github.com/microsoft/vscode/issues/166937 for classic SCM 'WorkingTree' diffs over Remote-SSH — same symptom family, different (now-fixed) code path; this is the newer Agent Sessions changed-files diff, unaffected by that old fix.
