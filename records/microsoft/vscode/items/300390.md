# Issue #300390 — Inline suggestions violate context exclusion on VS Code start

[https://github.com/microsoft/vscode/issues/300390](https://github.com/microsoft/vscode/issues/300390)

## Summary

The startup bypass remains source-reproducible for `.copilotignore`: initialization runs asynchronously without blocking activation, allowing completion checks against an empty local-ignore cache. This is security-sensitive because excluded content may be disclosed, so it requires human handling and must remain open.

## Change summary

Prevent inline completions from using excluded files before organization and `.copilotignore` rules finish loading at startup.

## Best solution

Make exclusion readiness a prerequisite for completion requests, either by awaiting `IIgnoreService.init()` or by conservatively denying requests until initialization settles. The content-exclusion owners should also decide whether failed remote-policy fetches must fail closed.

## Evidence

- **startup race on main:** `extensions/copilot/src/extension/extension/vscode/extension.ts:104-108` starts `IIgnoreService.init()` explicitly without blocking activation, while `BaseIgnoreService.init()` asynchronously searches for and reads `.copilotignore` files.
- **completion gate:** `extensions/copilot/src/extension/completions-core/vscode-node/lib/src/prompt/completionsPromptFactory/cascadingPromptFactory.ts:244-250` immediately trusts `isCopilotIgnored`; before initialization completes, the local ignore map has no rules and the document is allowed.
- **corroborating race fix:** The unmerged draft https://github.com/microsoft/vscode/pull/308814 contains deterministic tests for an intermittent content-exclusion bypass and commit 708647f0d83c81f66e59762901f3d2d6b244c85d, but that commit is not an ancestor of current main.
- **remaining fail-open behavior:** Current `extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts:188-245` returns `false` when remote rules fail to load; merged https://github.com/microsoft/vscode/pull/328268 explicitly documents that fail-open behavior as preserved.
- **protected handling:** The report concerns excluded source being sent to a model, which is potential data exposure and therefore falls under the security-sensitive hard keep-open rule.
