# Issue #350156 — Expose the sash double-click sizing of the Side Bar (and Panel) as a command that can be bound to a key

[https://github.com/microsoft/vscode/issues/350156](https://github.com/microsoft/vscode/issues/350156)

## Summary

Keep open: the sash's preferred-size behavior exists, but no equivalent bindable command was found. The related requests concern persistent widths and maximizing, not keyboard access to content-aware sizing.

## Change summary

Expose the existing sash double-click sizing behavior through keyboard-bindable workbench commands.

## Best solution

Provide commands that match the existing preferred-size behavior without changing mouse interaction or adding default keybindings. Preserve the distinction between content-based widths and the Panel's existing proportional preferred height.

## Evidence

- **Existing sash behavior:** src/vs/base/browser/ui/grid/grid.ts:714–744, Grid.onDidSashReset, tries adjacent views' preferredWidth/preferredHeight and otherwise distributes sibling sizes.
- **Preferred-size semantics:** SidebarPart.preferredWidth in src/vs/workbench/browser/parts/sidebar/sidebarPart.ts and AuxiliaryBarPart.preferredWidth in src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarPart.ts use the active composite's getOptimalWidth(), with a 300-pixel minimum. PanelPart in src/vs/workbench/browser/parts/panel/panelPart.ts has similar preferred-width logic, but its preferred height is 40% of the main container height, not content fitting.
- **Existing commands do not cover the request:** src/vs/workbench/browser/actions/layoutActions.ts:1199–1263 implements increaseViewSize using fixed 60-pixel increments; increaseViewWidth explicitly targets the editor. Searches found no registrations for the proposed reset-size commands or an equivalent preferred-size command.
- **Related requests are distinct:** Read the bodies and discussions of https://github.com/microsoft/vscode/issues/158603 and https://github.com/microsoft/vscode/issues/340915, both open. The former requests configurable and remembered per-view widths; the latter requests Primary Side Bar maximization. Neither owns exposing sash preferred-size behavior as a command.
