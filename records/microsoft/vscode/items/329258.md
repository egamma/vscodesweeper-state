# Issue #329258 — Can't create Sandbox on Windows when BaseContainer is velocity-gated and bfscfg.exe is unavailable

[https://github.com/microsoft/vscode/issues/329258](https://github.com/microsoft/vscode/issues/329258)

## Summary

Real, confirmed limitation: Windows sandboxing depends on `@microsoft/mxc-sdk` (pinned at 0.6.1 in package.json) which lacks the Tier 3 (AppContainer) fallback when required velocity/BFS capabilities aren't present, and a team member confirmed Windows sandboxing needs an Insider Windows build not yet GA'd (expected September). Root cause is external (the SDK dependency and unshipped Windows OS capability), so this stays open rather than closing.

## Change summary

On Windows, enabling the experimental agent sandbox fails with E_NOTIMPL when BFS/velocity-gated features are unavailable and the user can't install bfscfg.exe (not admin), instead of falling back to the AppContainer backend.

## Best solution

Track upstream: update `@microsoft/mxc-sdk` past 0.6.1 (package.json line 111) once a version with the Tier 3 fallback is available, and/or wait for the Windows GA capabilities mentioned by the maintainer; keep open under the existing `agent-sandbox` label until then.
