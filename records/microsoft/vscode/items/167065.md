# Issue #167065 — Allow multiple extensions to contribute to the same remote explorer view

[https://github.com/microsoft/vscode/issues/167065](https://github.com/microsoft/vscode/issues/167065)

## Summary

Team-authored architectural debt request to decouple the remote explorer from its current command-based hack. No commits reference this issue and the remote explorer code on main still does not support multiple extensions contributing to the same view — the work remains undone.

## Change summary

Allow multiple extensions to contribute their own tree views to the same remote explorer view ID, replacing the current hack that calls commands across extensions.

## Best solution

Implement multi-extension contribution support in the remote explorer core code (`src/vs/workbench/contrib/remote/browser/remote.ts`), then update Remote SSH and Remote Tunnels extensions to register their own tree views independently. This eliminates the cross-extension command dependency and simplifies maintenance.
