# Issue #332087 — Agent host: responses render only at turn end because the optimistic turn start is never retired

[https://github.com/microsoft/vscode/issues/332087](https://github.com/microsoft/vscode/issues/332087)

## Summary

The defect remains source-reproducible on current main, but two open VS Code PRs and an upstream protocol PR already address it. Keep the issue open while maintainers review and land the preferred fix.

## Change summary

Agent-host responses receive streaming deltas but remain visually empty until turn completion because a stranded optimistic turn start repeatedly clears the rendered response parts.

## Best solution

Review and land a replay-safe solution from https://github.com/microsoft/vscode/pull/332122 or https://github.com/microsoft/vscode/pull/334011, including the subscription-level regression test; the latter should follow the generated-protocol workflow through https://github.com/microsoft/agent-host-protocol/pull/433.

## Evidence

- **source-reproducible path:** On current main, src/vs/platform/agentHost/common/state/agentSubscription.ts keeps optimistic actions pending and only promotes a pending ChatTurnStarted for terminal actions; _recomputeOptimistic then replays every pending action over confirmed state.
- **destructive reducer replay:** src/vs/platform/agentHost/common/state/protocol/channels-chat/reducer.ts handles every ChatTurnStarted by replacing activeTurn with a new turn whose responseParts is empty, without guarding an already-active or completed turn ID.
- **open direct fix:** https://github.com/microsoft/vscode/pull/332122 is open, references this issue with Fixes #332087, promotes the pending start on the first backend action naming the turn, and adds a regression test for streamed response visibility.
- **open replay-safety fix:** https://github.com/microsoft/vscode/pull/334011 is open and makes ChatTurnStarted idempotent with reducer and subscription tests; its generated reducer change is proposed upstream in the open https://github.com/microsoft/agent-host-protocol/pull/433.
