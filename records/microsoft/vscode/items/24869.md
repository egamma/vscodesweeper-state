# Issue #24869 — [json] option to format code with leading commas

[https://github.com/microsoft/vscode/issues/24869](https://github.com/microsoft/vscode/issues/24869)

## Summary

A real JSON-formatting capability remains missing on current main. The original global, all-language setting is not compatible with VS Code's formatter-provider architecture, but the maintainer explicitly accepted a JSON-scoped contribution and the issue is already correctly routed.

## Change summary

Add a formatter option that places commas at the beginning of subsequent lines, originally proposed globally but subsequently scoped to JSON.

## Best solution

Implement comma-first output as a JSON-specific formatter option in the JSON formatting stack, expose it through a `json.format.*` setting, and leave other languages to their respective formatter providers.

## Plan brief

- **Likely files:** `extensions/json-language-features/package.json`, `extensions/json-language-features/package.nls.json`, `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add upstream `vscode-json-languageservice` formatter tests covering comma-first objects, arrays, nesting, and unchanged default output, then run that repository's formatter test suite; add or extend VS Code JSON extension tests to verify the new setting reaches the formatting options.
- **Behavior:**

  > JSON and JSON-with-comments users can opt into comma-first formatting. With the option enabled, commas separating multiline object properties and array elements begin the following item's line; with it disabled, existing formatting output remains unchanged. Nested structures and range formatting follow the same selected style, while syntax and comment handling remain valid.
- **Trace:**

  > VS Code declares JSON formatter settings in extensions/json-language-features/package.json, reads them in client/src/jsonClient.ts, and forwards server-relevant configuration through server/src/jsonServer.ts. `jsonServer.ts:onFormat` delegates to `vscode-json-languageservice`, whose src/utils/format.ts currently forwards a limited option set to jsonc-parser; neither layer represents comma placement. The maintainer discussion at https://github.com/microsoft/vscode/issues/24869 settles the product boundary: this must remain JSON-specific rather than becoming a global editor formatter setting. Planning must establish the upstream formatter/jsonc-parser API change and its coordinated consumption here without changing formatter behavior for other languages.

## Evidence

- **current settings:** extensions/json-language-features/package.json currently exposes `json.format.enable` and `json.format.keepLines`, but no comma-placement setting.
- **formatter path:** extensions/json-language-features/server/src/jsonServer.ts:onFormat forwards formatting to `vscode-json-languageservice`, currently augmenting the LSP options only with `keepLines`; the upstream formatter at https://github.com/microsoft/vscode-json-languageservice/blob/main/src/utils/format.ts forwards tab size, spaces, final newline, EOL, and keep-lines options to jsonc-parser, with no comma-first option.
