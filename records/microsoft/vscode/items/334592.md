# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Confirmed gap on main: `ICustomAgent` (src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts) has no `reasoningEffort` field and `runSubagentTool.ts` resolves `modelConfiguration` purely from the picker/parent model, ignoring any `.agent.md` `reasoning-effort`. A maintainer has since said the local harness will soon be replaced by the Copilot/Agent-Host harness and new local-harness features have no priority, so this is deprioritized rather than declined — it stays open under the community upvote process (Backlog Candidates, clock just started).

## Change summary

The local VS Code chat harness (runSubagent / direct custom-agent invocation) doesn't honor the `reasoning-effort` frontmatter in `.agent.md` files, unlike the Copilot Agent Host path which already does.

## Best solution

Add an optional `reasoningEffort` field to `ICustomAgent`, parse it from the `.agent.md` frontmatter, and merge it into the resolved `modelConfiguration` in `runSubagentTool.ts` (and the direct-invocation path) with precedence: explicit override > agent-declared effort > parent/picker config > model default — but given the maintainer's stated plan to replace the local harness, this may not be worth prioritizing unless the harness deprecation timeline slips.
