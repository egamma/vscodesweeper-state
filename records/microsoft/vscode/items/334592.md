# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Confirmed on main: `ICustomAgent` (src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts) has no `reasoningEffort` field, and `runSubagentTool.ts` resolves `modelConfiguration` purely from `modeModelId`, so the local harness genuinely ignores a custom agent's declared `reasoning-effort` while the Agent Host path honors it. However, a maintainer (aeschli) has since said the Local harness is being replaced by the GitHub harness and new local-harness features have no priority, so this stays in the community Backlog Candidates process rather than being scheduled.

## Change summary

Local VS Code chat harness ignores the `reasoning-effort` frontmatter in custom `.agent.md` files (unlike the Copilot Agent Host path), so subagents run at the parent session's reasoning effort instead of the agent's declared one.

## Best solution

If the local harness gets this feature, add `reasoningEffort` to `ICustomAgent` and merge it into the resolved `modelConfiguration` in `runSubagentTool.ts` (and the direct-agent-selection path) with the precedence the reporter proposes — but per the maintainer's comment this is deprioritized pending the Local→GitHub harness migration, so it likely stays parked in Backlog Candidates rather than being implemented.
