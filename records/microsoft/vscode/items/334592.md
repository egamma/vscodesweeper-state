# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Confirmed gap in source: `ICustomAgent` (src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts) has no `reasoningEffort` field, and `runSubagentTool.ts` resolves `modelConfiguration` from the picker/session model rather than the custom agent's declared `reasoning-effort`, so the report is accurate. A maintainer has explicitly deprioritized new local-harness work (the local harness is slated for replacement by the Copilot harness), and the issue is in its Backlog Candidates upvote window (13/20, within the 60-day clock) — it should stay open as under-discussion rather than be closed for being quiet, per the re-reviewed item staying open.

## Change summary

The local VS Code chat harness ignores the `reasoning-effort` frontmatter property in custom `.agent.md` files when invoking the agent directly or via `runSubagent`, unlike the Copilot Agent Host path which honors it.

## Best solution

Add an optional `reasoningEffort` field to `ICustomAgent` (parsed from the `.agent.md` frontmatter) and merge it into the resolved `modelConfiguration` in `runSubagentTool.ts` and the direct-agent-selection path, with precedence: explicit per-invocation override > custom-agent `reasoning-effort` > picker/session configuration > model default — but a maintainer should first confirm this is worth doing given the stated local-harness deprecation plan.
