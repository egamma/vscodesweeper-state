# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Well-traced gap: `reasoning-effort` is a documented, validated `.agent.md` header attribute, but it's never surfaced past validation in the local harness — confirmed on main that `PromptHeader` has no `reasoningEffort` getter, `promptsServiceImpl.ts`'s `ICustomAgent` construction doesn't read it, and `runSubagentTool.ts` builds `modelConfiguration` purely from the picker-selected model with no merge point for an agent-declared effort.

## Change summary

Local `runSubagent`/custom-agent execution should honor a custom agent's declared `reasoning-effort`, matching the Copilot Agent Host path, instead of always inheriting the parent session's reasoning effort.

## Best solution

Add a `reasoningEffort` getter to `PromptHeader` (promptFileParser.ts), thread it through `ICustomAgent` in promptsServiceImpl.ts's header-to-agent mapping (around line 1761-1769), and merge it into the resolved `modelConfiguration` in runSubagentTool.ts (~line 373) as well as the direct agent-picker invocation path, per the precedence order the reporter proposed (explicit override > agent-declared effort > picker/session > model default).
