# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Confirmed in source: `ICustomAgent` (src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts) has no `reasoningEffort` field, and `runSubagentTool.ts` line 373 builds `modelConfiguration` purely from `getModelConfiguration(modeModelId)`, never merging a custom agent's declared `reasoning-effort`. The frontmatter key is parsed only for validation/autocomplete (`promptFileParser.ts` line 75, `promptFileAttributes.ts` line 123), not carried into execution — so the local harness silently drops it while the Copilot Agent Host path (per the issue, #329263) honors it. This is a real, valid inconsistency worth routing to the chat/agents owners.

## Change summary

The local VS Code chat harness ignores a custom agent's declared `reasoning-effort` frontmatter value (both for direct agent selection and `runSubagent` invocation), instead always using the parent session's model configuration.

## Best solution

Add `reasoningEffort` to `ICustomAgent`/the prompt header parsing, and merge it into the resolved `modelConfiguration` in runSubagentTool.ts (and the equivalent direct-agent-selection path) with the precedence order the issue proposes: explicit override > agent-declared effort > picker/session > model default.
