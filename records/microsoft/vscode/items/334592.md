# Issue #334592 — Local harness should honor `reasoning-effort` from custom `.agent.md` files

[https://github.com/microsoft/vscode/issues/334592](https://github.com/microsoft/vscode/issues/334592)

## Summary

Confirmed on current main: the local runSubagent path builds modelConfiguration purely from the picker/parent model (languageModelsService.getModelConfiguration(modeModelId)) and never consults the custom agent's declared reasoning-effort, so the declarative property is silently ignored on this path while the Copilot Agent Host path honors it — a real cross-harness inconsistency worth fixing.

## Change summary

The local VS Code chat harness (runSubagent / direct custom-agent invocation) doesn't apply the reasoning-effort value declared in a custom .agent.md file's frontmatter, unlike the Copilot Agent Host path.

## Best solution

Add a reasoningEffort getter to PromptHeader in promptFileParser.ts (the reasoning-effort constant already exists at line 75 but isn't exposed), thread it into ICustomAgent in promptsService.ts, and merge it into the resolved modelConfiguration at runSubagentTool.ts:373 (and the equivalent direct-picker invocation path) with the precedence the reporter proposes.
