# Issue #346215 — [Feature Request] Allow Third-Party Extensions to Use VS Code's Built-in Desktop Notifications

[https://github.com/microsoft/vscode/issues/346215](https://github.com/microsoft/vscode/issues/346215)

## Summary

The public API gap remains: extension messages use workbench notifications, while native desktop notifications are exposed internally. Keep this request open for API-owner consideration; the earlier requests were closed for insufficient votes, not because the capability shipped or was explicitly rejected.

## Change summary

Expose native desktop notifications to extensions, including local delivery from remote extension hosts and click handling in the originating window.

## Best solution

Have API owners assess a minimal extension-facing notification contract backed by the existing host infrastructure, with explicit user controls, activation semantics, and remote/web behavior before implementation.

- **Fit:** aligned
- **Reason:** A shared notification API would enable extensions to provide consistent desktop integration without duplicating platform-specific implementations.

## Evidence

- **Existing public capability does not cover the request:** src/vscode-dts/vscode.d.ts exposes window.showInformationMessage and MessageOptions with modal/detail options, but no native-notification option. MainThreadMessageService._showMessage in src/vs/workbench/api/browser/mainThreadMessageService.ts routes extension messages through INotificationService.notify, not the native toast API.
- **Reusable internal desktop infrastructure:** src/vs/platform/native/electron-main/nativeHostMainService.ts:1457 onward implements showToast using Electron Notification, returning support, click, and action results. ChatWindowNotifier in src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts:125–229 calls IHostService.showToast and explicitly focuses the target window and opens the session on interaction. Native delivery exists, but exposing it to arbitrary extensions remains additional API work.
- **Earlier matching request was not implemented:** https://github.com/microsoft/vscode/issues/263009 requests desktop notifications through an extension API, explicitly including remote extensions. It is closed; https://github.com/microsoft/vscode/issues/263009#issuecomment-3440586278 states that closure followed insufficient community upvotes, not a fix or a substantive scope decision.
- **Second predecessor and community interest:** https://github.com/microsoft/vscode/issues/293062 is also closed following the voting period, as documented at https://github.com/microsoft/vscode/issues/293062#issuecomment-4196277093. It has 10 body upvotes and a comment requesting notifications for Codex. Neither closed predecessor is a valid duplicate canonical.
- **Related requests cover only portions:** https://github.com/microsoft/vscode/issues/251621 asks to confirm agent requests directly from notifications; https://github.com/microsoft/vscode/issues/243616 asks for extension-driven window focus. Neither request alone owns the full public desktop-notification API proposed here. An open-issue title search for notification and API returned no canonical candidate.
