# Issue #346215 — [Feature Request] Allow Third-Party Extensions to Use VS Code's Built-in Desktop Notifications

[https://github.com/microsoft/vscode/issues/346215](https://github.com/microsoft/vscode/issues/346215)

## Summary

The requested public extension API remains missing: internal desktop notifications exist, but extension messages do not use that infrastructure. Keep this open for API-owner consideration; no verified open canonical absorbs the request.

## Change summary

Expose native desktop notifications to extensions, including local delivery from remote extension hosts and click-to-focus or command handling.

## Best solution

Have API owners assess a minimal extension-facing notification contract backed by the existing host notification service, with explicit user controls, originating-window handling, and remote-host semantics.

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.d.ts exposes window.showInformationMessage and MessageOptions with modal/detail options, not an OS-notification option. Searches across stable/proposed declarations and src/vs/workbench/api found no showToast, systemNotification, desktopNotification, or nativeNotification exposure.
- **Extension messages remain workbench notifications:** src/vs/workbench/api/browser/mainThreadMessageService.ts routes nonmodal $showMessage calls through INotificationService.notify and modal calls through IDialogService.prompt; neither path invokes the host desktop-toast service.
- **Reusable internal infrastructure:** src/vs/workbench/services/host/electron-browser/nativeHostService.ts:251 implements showToast using the native host with a browser-notification fallback. src/vs/platform/native/electron-main/nativeHostMainService.ts:1457 creates Electron notifications and returns click/action results. These internal facilities are not a public extension contract.
- **Focus and preferences are caller responsibilities:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts checks chat notification settings and window focus before calling IHostService.showToast, then explicitly focuses the target window and opens the session on interaction. Reusing the low-level toast method alone would not supply all requested extension behavior.
- **Related requests and canonical search:** https://github.com/microsoft/vscode/issues/263009 requests desktop notifications usable by remote extensions; https://github.com/microsoft/vscode/issues/293062 requests OS-level extension notifications. The supplied context identifies both as closed for insufficient upvotes, not an architectural rejection. Public open-issue searches for desktop notifications/extensions and OS notifications/API found no matching open canonical beyond this issue.
