# Issue #268179 — NES retry on no-edit shouldn't send a request if the edit window size doesn't change

[https://github.com/microsoft/vscode/issues/268179](https://github.com/microsoft/vscode/issues/268179)

## Summary

Keep open: the reported short-file condition is sufficient to retest, but current NES retry handling now uses cursor prediction and does not conclusively reproduce the original window-expansion retry. No issue-referencing fix or eligible older canonical was established for this team-authored report.

## Change summary

Avoid sending a redundant NES retry after a no-edit response when the effective edit window cannot expand near the end of a file.

## Best solution

Establish whether the current NES path can still resend an unchanged effective edit window after a no-edit result, and eliminate that redundant request if present. Preserve useful retries targeting a different location or file.
