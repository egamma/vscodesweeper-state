# Issue #268179 — NES retry on no-edit shouldn't send a request if the edit window size doesn't change

[https://github.com/microsoft/vscode/issues/268179](https://github.com/microsoft/vscode/issues/268179)

## Summary

Still present on main: the retry-on-no-edit path can issue a redundant request when the edit window is clamped to the document end and expanding nLinesBelow produces an identical window. No fix commit found.

## Change summary

NES retry on no-edit sends a redundant request when the edit window size cannot grow because there are fewer lines below the cursor than the requested expansion.

## Best solution

In the retry path that sets `expandedEditWindowNLines`, add a guard comparing the resulting edit window range against the previous one and skip the request when they are equal. The fix belongs in `extensions/copilot/src/extension/xtab/node/xtabProvider.ts` (around `computeEditWindowLinesRange`) or in the caller that constructs the retry request.
