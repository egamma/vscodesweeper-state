# Issue #329738 — Proposal: Native DAP Proxy filtering for ambiguous Scope Watch Expressions

[https://github.com/microsoft/vscode/issues/329738](https://github.com/microsoft/vscode/issues/329738)

## Summary

The reporter is asking VS Code core to adopt a 'native DAP proxy' for filtering ambiguous watch expressions, but they've already built and shared a working extension implementing exactly this using the existing, stable `registerDebugAdapterTrackerFactory`/`onWillReceiveMessage` API — so no core change is needed; this belongs as an extension, which is exactly what they built.

## Change summary

Add a built-in DAP tracker proxy that rewrites Evaluate requests to prefer local-frame scope over outer/global scope when a watch expression's identifier is ambiguous.

## Best solution

Publish the reporter's own extension (https://github.com/parseRcDw6942/my-work) to the Marketplace — it already uses `vscode.debug.registerDebugAdapterTrackerFactory` and `DebugAdapterTracker.onWillReceiveMessage` (both public, stable API in src/vscode-dts/vscode.d.ts) to intercept and rewrite Evaluate requests, which fully covers the described use case without any core change.
