# Issue #205993 — Support hyperlinks in problem matchers of task output

[https://github.com/microsoft/vscode/issues/205993](https://github.com/microsoft/vscode/issues/205993)

## Summary

Keep this accepted feature request open: task problem matchers still cannot supply clickable documentation links, although diagnostic renderers already support them. The request has 34 upvotes and belongs in the existing tasks backlog; no verified older canonical issue was found.

## Change summary

Allow task problem matchers to attach clickable guidance links to diagnostics in the Problems view and editor.

## Best solution

Expose documentation links through problem-matcher configuration using the existing linked diagnostic-code capability, preserving plain-text messages and existing matcher behavior. Settle the configuration contract before implementation; general Markdown rendering need not be part of the initial feature.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/common/problemMatcher.ts`, `src/vs/workbench/contrib/tasks/test/common/problemMatcher.test.ts`
- **Validation:** After agreeing the configuration contract, add parser and matcher tests in src/vs/workbench/contrib/tasks/test/common/problemMatcher.test.ts and run scripts/test.sh --run src/vs/workbench/contrib/tasks/test/common/problemMatcher.test.ts. Manually run a task emitting a diagnostic with a documentation URL and verify the link opens from both the Problems view and editor hover; existing plain-text matchers must remain unchanged.
- **Behavior:**

  > Task-generated problems should provide clickable guidance links in both the Problems view and the editor diagnostic hover, comparable to linked ESLint rule names. A matcher author must be able to supply the link through task configuration rather than a separate diagnostic-producing extension. Existing matchers, diagnostic locations, severity, and plain-text messages must retain their behavior. Acceptance includes matching a sample task diagnostic and opening its configured documentation link from both surfaces.
- **Trace:**

  > In src/vs/workbench/contrib/tasks/common/problemMatcher.ts, fillProblemData captures code and message as strings, and getMarkerMatch forwards data.code directly to marker.code. The ProblemPattern schema exposes integer capture indices but no link-target configuration. IMarkerData in src/vs/platform/markers/common/markers.ts already supports { value, target } codes, and the Problems tree/table and MarkerHoverParticipant already render that form as a hyperlink. Thus the missing capability is in task matcher configuration and marker construction, not the absence of a shared diagnostic link renderer. Preserve existing matcher semantics and avoid assuming arbitrary Markdown rendering is required. https://github.com/microsoft/vscode/issues/55253 concerns related source diagnostics rather than documentation links. The remaining uncertainty is the public configuration contract for supplying the target and label.
- **Open decisions:**
  - Should the initial configuration support a documentation URL captured from task output, a static URL supplied by the matcher author, or both?
  - Should guidance links use diagnostic code labels only, or must diagnostics without a captured code also support a separately configured link label?
