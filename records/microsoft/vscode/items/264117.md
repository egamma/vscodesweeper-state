# Issue #264117 — "Remove keybinding" can delete the wrong keyboard shortcut

[https://github.com/microsoft/vscode/issues/264117](https://github.com/microsoft/vscode/issues/264117)

## Summary

The wrong-entry deletion remains reproducible from current source: user keybindings are matched by command and when clause without considering args. Keep this open while the existing fixing PR is reviewed; the issue already has the correct area label.

## Change summary

Removing a keyboard shortcut can delete an earlier user keybinding with the same command and when clause but different arguments.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/337863 so removing or editing a user keybinding targets the selected arguments-bearing entry and preserves its siblings.

## Evidence

- **Current-source defect:** In src/vs/workbench/services/keybinding/common/keybindingEditing.ts, findUserKeybindingEntryIndex returns the first entry matching command and normalized when, without comparing args. removeUserKeybinding deletes that returned array index. Selecting a later terminal sendSequence entry with different args therefore deletes the earlier matching entry.
- **Selected-entry call path:** src/vs/workbench/contrib/preferences/browser/keybindingsEditor.ts:265-269 passes the selected entry's ResolvedKeybindingItem to keybindingEditingService.removeKeybinding. The selection reaches the service correctly; the service's incomplete matching loses the distinction.
- **Existing open fixing PR:** https://github.com/microsoft/vscode/pull/337863 was verified OPEN with no merge commit. Its body explicitly says Fixes #264117 and describes comparing args in findUserKeybindingEntryIndex, with a regression test in src/vs/workbench/services/keybinding/test/browser/keybindingEditing.test.ts. This is an existing implementation candidate, not a landed fix.
- **Independent confirmation:** The discussion on https://github.com/microsoft/vscode/issues/264117 includes a second user's confirmation on VS Code 1.110.1 under Linux and an attached video, extending the original macOS report.
- **Canonical search:** An open-issue search for keybinding, args, and remove returned this report and other differently scoped requests; no verified older canonical owning the same wrong-entry deletion was established.
