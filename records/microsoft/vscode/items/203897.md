# Issue #203897 — Should dispose code actions after auto-running AI action?

[https://github.com/microsoft/vscode/issues/203897](https://github.com/microsoft/vscode/issues/203897)

## Summary

The code-action lifetime question remains unresolved on current main. The attempted fix was reverted after causing regressions, and a maintainer subsequently asked for this issue to be taken forward, so there is no basis for closing it.

## Change summary

Determine the safe lifetime of a CodeActionSet after automatically running the sole AI code action, and dispose it without disrupting commands that launch longer-lived UI.

## Best solution

Define ownership through the AI lightbulb application path so the action set is eventually disposed exactly when its command no longer depends on it, with regression coverage for commands that open a quick pick or otherwise continue interacting with the action.

## Evidence

- **current source:** On current main, src/vs/editor/contrib/codeAction/browser/codeActionController.ts transfers ownership through CodeActionModel.takeCodeActions, stores automatically triggered actions in `_activeCodeActions`, and `showCodeActionsFromLightbulb` awaits the single AI action before returning without explicitly disposing that set. The set is therefore retained until `_activeCodeActions` is replaced or the controller is disposed.
- **attempted fix:** https://github.com/microsoft/vscode/pull/203936 added `actions.dispose()` after applying or selecting a code action, including the AI lightbulb path.
- **reverted fix:** https://github.com/microsoft/vscode/pull/205508 reverted that disposal because it was premature for actions that opened additional UI. The regressions included https://github.com/microsoft/vscode/issues/204606 and https://github.com/microsoft/vscode/issues/205498.
- **maintainer direction:** After the reopen, a maintainer explicitly asked another maintainer to take the issue in https://github.com/microsoft/vscode/issues/203897#issuecomment-2533096668, confirming that the lifetime question remained active.
