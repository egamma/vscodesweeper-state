# Issue #330555 — Tips show while loading

[https://github.com/microsoft/vscode/issues/330555](https://github.com/microsoft/vscode/issues/330555)

## Summary

Real flicker in the Agents window: switching to a loading session briefly shows the getting-started tip before it resolves. Traced a plausible race in the code but the exact fix boundary needs more investigation, so this stays open and routed to the area.

## Change summary

Switching to another session while it is still loading briefly flashes the getting-started tip, which then disappears once the session finishes loading.

## Best solution

Investigate the timing between ChatWidget#setModel (src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts) — which synchronously re-evaluates `isGettingStartedTipEligible`/`updateChatViewVisibility` on session switch when the new view model still has 0 transcript items — and the session's 'Getting ready' status autorun in src/vs/sessions/contrib/chat/browser/chatView.ts (`_setupGettingReadyStatus`), which asynchronously sets `transcriptProgressActive` (used to suppress the welcome/tip state) only after its own autorun tick. Gating tip eligibility on the session's `loading` state directly (already available via `session.loading` in newChatWidget.ts) rather than solely on `transcriptProgressActive` would likely close the race window.

## Evidence

- **tip rendering path:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts `updateChatViewVisibility()` (around line 1217) calls `renderGettingStartedTipIfNeeded()` whenever `onDidChangeItems` fires, and `isGettingStartedTipEligible()` (line 1348) returns true whenever the view model has 0 items and `transcriptProgressActive` is false.
- **session switch trigger:** `ChatWidget.setModel` (line ~2429) synchronously creates a fresh `ChatViewModel` with 0 items on session switch and fires `onDidChangeItems`, before the new session's transcript is populated.
- **async loading signal:** src/vs/sessions/contrib/chat/browser/chatView.ts `_setupGettingReadyStatus` (line 261) is the mechanism that eventually sets `transcriptProgressActive` via `setTranscriptProgress`, but it runs in a separate autorun keyed off `_currentChatResourceObs`/`_currentSessionObs`/`chatModel`, which can lag behind the synchronous `setModel` call — explaining the brief tip flash before it disappears.
