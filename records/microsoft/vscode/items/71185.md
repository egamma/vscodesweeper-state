# Issue #71185 — Accessibility service not firing onDidChangeAccessibilitySupport

[https://github.com/microsoft/vscode/issues/71185](https://github.com/microsoft/vscode/issues/71185)

## Summary

Still an upstream Chromium limitation on Windows — the `accessibility-support-changed` event only detects enablement of assistive tech, not disablement. VS Code's code at `src/vs/code/electron-main/app.ts:466` still relies on this Electron/Chromium event unchanged, so the issue persists.

## Change summary

VS Code does not detect when a screen reader is turned off on Windows, requiring a full restart to revert accessibility-mode behaviors.

## Best solution

Track the upstream Chromium bug (https://bugs.chromium.org/p/chromium/issues/detail?id=1015906) for a fix. Alternatively, VS Code could implement a polling fallback or a manual toggle, but the root cause is in Chromium's assistive-technology detection on Windows.
