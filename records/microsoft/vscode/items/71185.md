# Issue #71185 — Accessibility service not firing onDidChangeAccessibilitySupport

[https://github.com/microsoft/vscode/issues/71185](https://github.com/microsoft/vscode/issues/71185)

## Summary

Keep open as an unresolved upstream Windows accessibility issue. Current main still relies on Electron and Chromium to report when accessibility support is disabled, and neither source nor history shows a later fix; this team-authored Backlog item also cannot receive a judgment close.

## Change summary

Disabling NVDA on Windows does not notify VS Code that accessibility support changed, leaving list keyboard navigation in screen-reader mode until a full restart.

## Best solution

Chromium should detect assistive-technology disablement on Windows and propagate the changed state through Electron's `accessibility-support-changed` event; VS Code's existing main-to-renderer bridge can then restore normal list navigation without restarting.
