# Issue #349800 — Worktree Cleanup on a background SSH host can remove worktrees used by another agent host on that machine

[https://github.com/microsoft/vscode/issues/349800](https://github.com/microsoft/vscode/issues/349800)

## Summary

Keep open: the reporter confirmed cross-host removal, and current cleanup guards consult only the receiving host's ownership records. Protecting shared filesystem worktrees requires accounting for ownership outside that host's session database.

## Change summary

Prevent background SSH worktree cleanup from removing a checkout used by another agent host on the same machine.

## Best solution

Ensure managed-worktree inventory and removal distinguish genuinely unused worktrees from worktrees owned by another host, including a final safety check before deletion. Preserve cleanup of genuinely abandoned worktrees without treating missing local session metadata as proof of abandonment.
