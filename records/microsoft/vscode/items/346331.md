# Issue #346331 — Support running and managing VS Code workspace tasks from Agents

[https://github.com/microsoft/vscode/issues/346331](https://github.com/microsoft/vscode/issues/346331)

## Summary

Keep open as a feature request: existing Agents run actions provide partial task support, but do not establish the requested agent-accessible workspace-task lifecycle. The earlier as-designed decision explains today's behavior without explicitly declining this optional integration.

## Change summary

Allow Agents sessions to discover, run, inspect, stop, and rerun workspace tasks through VS Code's task system while retaining terminal execution.

## Best solution

Evaluate optional, session-scoped task integration that preserves task-system readiness detection, output visibility, manual takeover, and existing approval controls. Establish supported workspace and provider boundaries before committing to editor-chat parity.

## Evidence

- **Existing capability and limitation:** src/vs/sessions/contrib/chat/browser/sessionsTasksService.ts exposes task discovery, creation, and execution for session run actions, including tasks marked inAgents. These internal service methods are not themselves agent-callable tools.
- **Task tools excluded from Sessions tool set:** src/vs/workbench/contrib/chat/browser/tools/clientToolSetsContribution.ts registers vscodeTasks, containing createAndRunTask, runTask, and getTaskOutput, only when workspaceService.isSessionsWindow is false. This does not provide the requested tools in Agents.
- **Different execution semantics:** src/vs/sessions/contrib/terminal/browser/agentHostSessionTaskRunner.ts resolves task entries into shell commands and sends them to agent-host terminals. src/vs/sessions/contrib/chat/browser/workbenchSessionTaskRunner.ts delegates to ITaskService only for eligible workspace folders; its fallback capability does not establish full task-system support for agent-host sessions.
- **Related discussion:** https://github.com/microsoft/vscode/issues/345949#issuecomment-6665289126 states that Agents intentionally uses terminal commands. The reporter subsequently identified this issue as the feature-request follow-up in https://github.com/microsoft/vscode/issues/345949#issuecomment-6666162293. The closed bug is not an open duplicate canonical, and its explanation does not explicitly reject optional task integration.
