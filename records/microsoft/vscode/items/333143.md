# Issue #333143 — Chat session history intermittently lost/truncated after closing VS Code (possibly related to closing while a chat is open)

[https://github.com/microsoft/vscode/issues/333143](https://github.com/microsoft/vscode/issues/333143)

## Summary

Thanks for the detailed diagnostic write-up. I traced a plausible mechanism in the chat session storage code (a compaction 'replace' write firing against an in-memory model that can be empty at dispose time), but I can't confirm from source alone that this is what actually happened here — no commenter has reproduced it, and it's explicitly intermittent, so this needs a bit more info before it can be actioned.

## Change summary

Long-running chat session history is intermittently truncated to an empty initial snapshot after closing VS Code, especially around closing while a chat session is open.

## Best solution

Worth having the chat-persistence owners look at src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts (writeSession, ~lines 349-396) and objectMutationLog.ts write() (~lines 410-420): the first write for a ChatModel with no dataSerializer always does a full 'replace' with whatever is currently in memory, and chatServiceImpl.ts's willDisposeModel handler (~lines 285-301) will call storeSessions() on a model with 0 in-memory requests as long as it has a customTitle — clobbering any longer persisted history if the model is empty/not-yet-hydrated at that moment. Confirming whether that race can actually occur (e.g. during the child-window flow the reporter mentions) would settle this.
