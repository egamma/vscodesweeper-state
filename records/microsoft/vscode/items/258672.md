# Issue #258672 — Auto imports don't work in python repl

[https://github.com/microsoft/vscode/issues/258672](https://github.com/microsoft/vscode/issues/258672)

## Summary

Python terminal completions still lack auto-import support: the current adapter carries completion labels and documentation but not the additional edits needed to import a symbol. Keep this request open under the existing Python and terminal-suggest labels; no verified duplicate or fixing commit was found.

## Change summary

Support the required Python import when accepting an auto-import completion in the terminal REPL.

## Best solution

Extend Python terminal completion acceptance so a suggested symbol's required import is reflected in the running interpreter, not merely its virtual document. Establish the execution semantics first, preserving the existing distinction between accepting a suggestion and running a command.

Verify the agreed acceptance/submission behavior with Tab and Enter, including terminal.integrated.suggest.runOnEnter='never', and verify ordinary completions remain unchanged.
- **Behavior:**

  > Accepting a Python terminal auto-import completion currently inserts the suggested name without making its required import available. The finished feature should allow the accepted expression to run successfully without a separate manual import. Its behavior must respect an explicitly agreed distinction between accepting a completion and executing Python code. Acceptance must verify the actual interpreter state, not only the virtual language-service document.
- **Trace:**

  > LspCompletionProviderAddon.provideCompletions in src/vs/workbench/contrib/terminalContrib/suggest/browser/lspCompletionProviderAddon.ts converts language-service suggestions into terminal completion metadata without additionalTextEdits. TerminalCompletionItem.resolve in terminalCompletionItem.ts only updates documentation and detail. acceptSelectedSuggestion in terminalSuggestAddon.ts inserts inputData or the label and separately honors runOnEnter; the LSP adapter supplies no import-bearing inputData. LspTerminalModelContentProvider maintains a virtual document from prompt input and successful commands, but changes there do not execute in the interpreter. These paths establish the missing capability without executing the checkout. The boundary is integrated-terminal Python completion; ordinary shell suggestions and the separate native Python REPL are not the requested surface. https://github.com/microsoft/vscode/issues/258293 establishes the original terminal/Pylance testing context. The unresolved product question is when and how import execution should occur relative to completion acceptance and command submission.
- **Open decisions:**
  - Should accepting an auto-import completion execute its import immediately, or should the import remain visible pending input and execute only when the user submits the expression, especially when terminal.integrated.suggest.runOnEnter is 'never'?
