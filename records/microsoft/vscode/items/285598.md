# Issue #285598 — GitHub Copilot continually restarts extension host; chat prompt does not produce anything, and deletes chat debug history

[https://github.com/microsoft/vscode/issues/285598](https://github.com/microsoft/vscode/issues/285598)

## Summary

This remains a reproducible long-chat crash requiring chat performance investigation. The extension host repeatedly becomes unresponsive and terminates as conversation history grows, while no older open issue owns the same observable symptom and no applicable fix is evident on current main.

## Change summary

Prevent long-running Copilot conversations from exhausting or blocking the extension host, restarting it, and aborting submitted prompts.

## Best solution

Profile extension-host allocations while repeatedly submitting and compacting a large imported conversation, identify the retained or repeatedly reconstructed history responsible for the growth, and add a long-history memory regression check. The process-local nature of Debug Chat history should remain unchanged; preserving it across a genuine extension-host restart is separate from preventing the crash.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts`, `extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts`
- **Validation:** Import or generate a large chat fixture comparable to a 24,000+ line exported transcript, repeatedly submit requests and run `/compact` while monitoring the extension-host process, and verify that memory remains bounded, the host does not restart, and each request completes or reports an explicit error.
- **Behavior:**

  > Submitting a prompt or `/compact` in a long-running Copilot conversation must not make the extension host unresponsive or terminate it. The request must either complete normally or surface an explicit request error without restarting unrelated extensions. Repeated requests against a large conversation must have bounded extension-host memory growth.
- **Trace:**

  > The issue contains extension-host logs showing an unresponsive process followed by unexpected termination and automatic restart, repeatedly reproduced as chat history grows across many stable versions. On current main, extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts passes the full `context.history` into `ChatParticipantRequestHandler`, whose constructor calls `addHistoryToConversation` in extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts; that function walks the entire history and may reconstruct every prior response. This is the first concrete pressure boundary, but the record does not establish whether the failure is transient full-history expansion, retained `Conversation` objects, prompt construction, or another extension-host allocation. The renderer persistence problem in https://github.com/microsoft/vscode/issues/285251 and Copilot CLI listing OOM fixed by https://github.com/microsoft/vscode/pull/332408 are related but distinct. Do not broaden the work to persisting Debug Chat records across extension-host processes or to renderer-only freezing.

## Evidence

- **confirmed crash:** The reporter captured `Extension host ... is unresponsive`, followed by `terminated unexpectedly` and automatic restart, and reproduced the failure across versions 1.109.5 through 1.135.0 as conversations grew to roughly 20,000–60,000 copied Markdown lines.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/285598#issuecomment-3711928684 explains that Debug Chat data exists only for the current extension-host process and concludes that the reported UI resets and lost debug entries point to a crashing extension host.
- **independent corroboration:** https://github.com/microsoft/vscode/issues/328335 reports `Worker terminated due to reaching memory limit: JS heap out of memory` in long conversations and includes an independent confirmation, supporting a continuing long-chat extension-host memory problem.
- **current source path:** extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts passes the complete `context.history` into every `ChatParticipantRequestHandler`; extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts then iterates that history in `addHistoryToConversation` and reconstructs prior request/response turns. This is a concrete profiling boundary but does not by itself prove the retained allocation.
- **related fixes are insufficient:** The closed https://github.com/microsoft/vscode/issues/285251 concerned renderer freezes while persisting large sessions. The newer https://github.com/microsoft/vscode/pull/332408, commit add165ca944ac2cd60b1f0267f1bc3ba5d0b1093, bounded Copilot CLI session-listing fan-out; it does not address ordinary local-chat history processing, and this issue was reported again after that PR merged.
- **canonical search:** The older https://github.com/microsoft/vscode/issues/281743 and closed https://github.com/microsoft/vscode/issues/285251 concern broader unresponsiveness or renderer persistence stalls, not the same long-history extension-host termination. Newer issues such as https://github.com/microsoft/vscode/issues/294050 and https://github.com/microsoft/vscode/issues/328335 cannot be canonicals for this re-reviewed older report.
