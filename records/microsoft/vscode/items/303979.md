# Issue #303979 — Reveal Active File in Explorer does nothing — TreeError [DebugRepl] Tree input not set

[https://github.com/microsoft/vscode/issues/303979](https://github.com/microsoft/vscode/issues/303979)

## Summary

The defect remains source-reproducible on current main: workspace-folder lookup uses a URI tree whose path-casing comparator can change after insertion, invalidating lookups for mixed-case remote roots. This should stay open for a lifecycle-safe fix.

## Change summary

Reveal Active File in Explorer silently fails for some folders in a multi-root Remote-SSH workspace when filesystem path-casing capabilities become known after workspace initialization.

## Best solution

Keep the renderer's URI-keyed workspace-folder index consistent when filesystem-provider registration or capability changes alter path-casing semantics, so `getWorkspaceFolder`, breadcrumbs, and Explorer reveal continue recognizing every configured root. The fix should also address the always-true comparison in `UriIdentityService` without changing normal reveal behavior for resources outside the workspace.

## Plan brief

- **Likely files:** `src/vs/platform/workspace/common/workspace.ts`, `src/vs/platform/workspace/test/common/workspace.test.ts`, `src/vs/platform/uriIdentity/common/uriIdentityService.ts`, `src/vs/platform/uriIdentity/test/common/uriIdentityService.test.ts`, `src/vs/workbench/services/configuration/browser/configurationService.ts`
- **Validation:** Add a workspace unit test with several mixed-case remote roots: construct the workspace while path casing matters, switch the supplied casing rule to ignore case as provider registration would, then assert `getFolder` resolves files beneath every root. The test must fail on current main and pass while existing workspace and URI-identity tests remain green.
- **Behavior:**

  > In a multi-root remote workspace, every configured folder must remain recognized after the remote filesystem provider registers and establishes case-insensitive path semantics. Breadcrumbs must remain workspace-relative, and Reveal Active File in Explorer View must open the Explorer and select the active file for every root. Resources genuinely outside the workspace must retain the existing fallback behavior.
- **Trace:**

  > `Workspace` in `src/vs/platform/workspace/common/workspace.ts` inserts folders into a `TernarySearchTree` using a callback backed by `UriIdentityService`. `UriIterator.reset` in `src/vs/base/common/ternarySearchTree.ts` reevaluates that callback on later lookups, while `UriIdentityService` changes its cached answer when filesystem providers register; the pre-existing tree is not rebuilt, so mixed-case ordering can become invalid. The provider-change handler also compares the new value to itself, preventing its intended canonical-URI cleanup. The resulting `getFolder` miss makes `isInsideWorkspace` false in the reveal command path in `src/vs/workbench/contrib/files/browser/fileCommands.ts`. The uncertainty begins at the safe lifecycle boundary: the plan must enumerate URI-keyed indexes that survive provider capability changes and avoid a narrow fix that leaves equivalent stale indexes elsewhere; do not alter outside-workspace reveal semantics or Remote-SSH ownership.

## Evidence

- **confirmed current source defect:** `src/vs/platform/workspace/common/workspace.ts` constructs `foldersMap` with the mutable `ignorePathCasing` callback at lines 343-404, while `getFolder` later queries the existing tree without rebuilding it when that callback's result changes.
- **mutable tree ordering:** `src/vs/base/common/ternarySearchTree.ts` `UriIterator.reset` evaluates `_ignorePathCasing(key)` for each operation. Changing the callback result after mixed-case keys were inserted therefore changes path comparison semantics without restoring the tree's ordering invariant.
- **provider transition:** `src/vs/platform/uriIdentity/common/uriIdentityService.ts` recomputes cached path-casing behavior on filesystem-provider registration/capability changes. Its handler also contains `newIgnorePathCasingValue === newIgnorePathCasingValue`, an always-true comparison that prevents the intended cache cleanup.
- **observable command path:** `src/vs/workbench/contrib/files/browser/fileCommands.ts` only opens and selects in Explorer when `IWorkspaceContextService.isInsideWorkspace(uri)` succeeds, so the failed workspace lookup directly produces the reported silent no-op.
- **confirmed reproduction and workaround:** The reporter's update at https://github.com/microsoft/vscode/issues/303979#issuecomment-4972935712 reproduces the problem on 1.128.1, supplies a minimal mutable-comparator model reproduction, and reports that lowercasing all 14 remote workspace URI paths restores breadcrumbs and Explorer reveal.
- **no canonical duplicate:** The open candidates https://github.com/microsoft/vscode/issues/316440 and https://github.com/microsoft/vscode/issues/330874 are newer reports about asynchronous compressed File Explorer tree races with different observable errors and root causes; they do not satisfy the stronger re-review duplicate bar.
