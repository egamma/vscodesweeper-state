# Issue #159110 — Fonts that print underscore beyond a cell's height don't render anything in the DOM renderer

[https://github.com/microsoft/vscode/issues/159110](https://github.com/microsoft/vscode/issues/159110)

## Summary

Keep this as the VS Code tracking issue for the unresolved xterm.js DOM-renderer clipping problem. The upstream report remains open, and current VS Code still uses the affected renderer when GPU acceleration is disabled or unavailable.

## Change summary

Preserve visible underscores in the terminal DOM renderer when a font draws them below the cell boundary.

## Best solution

Resolve glyph clipping in xterm.js without introducing unwanted overlap between terminal rows, then adopt the fix in VS Code. Font changes and increased line height are workarounds, not coverage of the requested behavior.

## Evidence

- **Verified upstream ownership:** https://github.com/xtermjs/xterm.js/issues/4067 is currently open and describes exactly the missing underscores with Droid Sans Mono and DejaVu Sans Mono. The issue's December 2024 comment explicitly identifies this upstream tracker.
- **Current VS Code renderer path:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:630-645 disables the WebGL renderer when terminal.integrated.gpuAcceleration is off; lines 973-975 explicitly fall back to the DOM renderer when WebGL loading fails. The affected surface has not been removed.
- **Upstream clipping mechanism:** Current upstream src/browser/renderer/dom/DomRenderer.ts:151-156 assigns each row a fixed cell height and line height, then sets overflow to hidden. This remains consistent with clipping glyphs drawn below the cell boundary; source inspection is not a live rendering reproduction.
- **Independent confirmations and canonical direction:** https://github.com/microsoft/vscode/issues/158497#issuecomment-1223694568 reports disappearing underscores specifically in the DOM renderer with DejaVu Sans Mono. https://github.com/microsoft/vscode/issues/158497#issuecomment-1226453212 explicitly separates this problem from the subsequently fixed WebGL black-block defect and directs it to this issue.
- **Later reports consolidated here:** https://github.com/microsoft/vscode/issues/211933#issuecomment-2532465612 and https://github.com/microsoft/vscode/issues/261173#issuecomment-3179965604 close later reports as duplicates of this issue. They support retaining this issue as the canonical VS Code report, not closing it against those closed satellites.
- **Workarounds do not establish a fix:** https://github.com/microsoft/vscode/issues/211933#issuecomment-2139485330 identifies GPU acceleration, increased terminal.integrated.lineHeight, and a different terminal.integrated.fontFamily as workarounds. https://github.com/microsoft/vscode/issues/211933#issuecomment-2194278556 reports that lineHeight 1.1 was insufficient. Current configuration still exposes line height and font family, but neither guarantees visible underscores with the original font and cell geometry.
- **Related upstream scope:** https://github.com/xtermjs/xterm.js/issues/5240 remains open for clipping tall glyphs at the top of DOM-renderer cells and links back to upstream issue 4067 for bottom clipping. It is related work, not an older canonical reporting the same observable symptom for this re-reviewed issue.
