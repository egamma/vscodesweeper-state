# Issue #5394 — Add support for mixed tab/spaces indentation

[https://github.com/microsoft/vscode/issues/5394](https://github.com/microsoft/vscode/issues/5394)

## Summary

A substantial gap remains after the partial implementation: VS Code can display separate tab and indentation widths but cannot generate tab-plus-space indentation. With 67 upvotes and a Backlog milestone, this should remain the canonical request under discussion.

## Change summary

Support detecting, producing, and converting indentation that uses fixed-width tabs plus spaces for the remainder.

## Best solution

Add a mixed indentation mode that advances by `editor.indentSize` while replacing complete `editor.tabSize` columns with tabs. Apply it consistently to Enter, Tab, block shifting, normalization, detection, conversion, and the indentation status UI; this issue should absorb the overlapping work in https://github.com/microsoft/vscode/issues/42740.

## Evidence

- **current configuration:** src/vs/editor/common/config/editorConfigurationSchema.ts exposes separate tab and indent sizes, but `editor.insertSpaces` remains a boolean, allowing only spaces or tabs rather than a mixed mode.
- **current source gap:** src/vs/editor/common/core/misc/indentation.ts normalizes using `indentSize` alone, while src/vs/editor/common/commands/shiftCommand.ts chooses either repeated spaces or repeated tabs; neither path generates tabs at `tabSize` boundaries with spaces for the remainder.
- **current confirmation:** https://github.com/microsoft/vscode/issues/5394#issuecomment-4016281941 reports the remaining behavior in 2026: rendering can be configured manually, but Enter and automatic indentation still treat a hard tab as one logical indentation level.
