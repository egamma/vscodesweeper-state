# Issue #5394 — Add support for mixed tab/spaces indentation

[https://github.com/microsoft/vscode/issues/5394](https://github.com/microsoft/vscode/issues/5394)

## Summary

Keep open: independent tab display and indentation sizes exist, but editing still lacks the requested mode that emits as many physical tabs as possible followed by remainder spaces. The maintainer explicitly reopened this issue for that remaining gap; current source confirms it is not covered by the existing settings.

## Change summary

Support editing, detecting, and converting indentation that combines fixed-width physical tabs with smaller logical indentation steps.

## Best solution

Provide an opt-in mixed-indentation mode in the editor core that preserves logical indentation columns while generating physical tabs plus remainder spaces consistently across typing, Enter, indent/outdent, and conversion. Retain this issue as the older report of that requirement and agree on configuration and detection semantics before implementation.

- **Validation:** Plan acceptance checks with tab width 8 and logical indent widths 2 and 4. Starting from an empty line, repeated indentation must produce spaces until column 8, then a tab, then a tab plus remainder spaces; outdent must reverse the sequence. Verify Enter preserves or increases the visual indentation correctly, conversion preserves content columns, and existing spaces-only and tabs-only modes remain unchanged. Extend src/vs/editor/test/browser/commands/shiftCommand.test.ts for the indent/outdent sequence and include runnable Enter, conversion, and detection checks in the agreed plan. No tests were executed in the read-only checkout.
- **Behavior:**

  > Users must be able to edit files whose logical indentation advances by two or four columns while physical tabs occupy eight-column tabstops. In the selected mixed mode, leading indentation uses as many tabs as fit, followed by remainder spaces, without changing the intended visual columns. Tab, Enter, and indent/outdent must preserve this convention rather than replacing it with spaces-only or full-tab-width indentation. The request also includes detection and conversion; existing indentation modes must retain their current behavior.
- **Trace:**

  > The independent editor.tabSize and editor.indentSize settings address display and spaces-based indentation but not mixed-output editing. ShiftCommand.shiftIndent and unshiftIndent select either spaces at logical indent stops or tabs at physical tab stops. normalizeIndentation in src/vs/editor/common/core/misc/indentation.ts receives only indentSize and insertSpaces, and its callers in TextModel and CursorConfiguration feed multiple editing paths, including Enter. guessIndentation exposes tabSize and insertSpaces rather than a distinct mixed-indentation policy; conversion actions also select the existing boolean modes. The remaining work crosses shared editor indentation behavior, so the trace does not establish a bounded single-path fix. Preserve existing defaults and keep elastic tabstops and language-aware smart-tab alignment outside this request. The earlier partial implementation, https://github.com/microsoft/vscode/pull/155450, predates the explicit reopening; https://github.com/microsoft/vscode/issues/42740 is related but newer.
- **Open decisions:**
  - What public configuration selects mixed indentation while preserving compatibility with editor.insertSpaces and existing editor configurations?
  - Should automatic indentation detection activate mixed mode, or should it require explicit opt-in, and how should ambiguous files be treated?

## Evidence

- **Reopened for the unresolved requirement:** In the supplied discussion for https://github.com/microsoft/vscode/issues/5394, the author of https://github.com/microsoft/vscode/pull/155450 acknowledged that the PR did not fully address mixed indentation. A maintainer explicitly reopened the issue on 2022-11-28 because replacing as many spaces as possible with tabs remained unsupported. The merged PR therefore cannot justify closing this reopened issue.
- **Existing settings provide only partial coverage:** src/vs/editor/common/config/editorConfigurationSchema.ts registers editor.tabSize, editor.indentSize, editor.insertSpaces, and editor.detectIndentation. Independent sizes allow eight-column tabs to display alongside two- or four-space indentation, but insertSpaces remains boolean; these settings do not select the requested mixed-output behavior.
- **Current indentation generation lacks the requested mode:** src/vs/editor/common/commands/shiftCommand.ts: ShiftCommand.shiftIndent and unshiftIndent generate only spaces at indentSize stops when insertSpaces is true, or only tabs at tabSize stops when false. Neither branch advances by a smaller logical indent while emitting maximum physical tabs plus remainder spaces.
- **Normalization is also coupled to logical indent width:** src/vs/editor/common/core/misc/indentation.ts: normalizeIndentation accepts indentSize and insertSpaces but no independent physical tab width. Its helper both expands existing tabs and constructs output using indentSize. TextModel.normalizeIndentation and CursorConfiguration.normalizeIndentation call this helper, and cursorTypeEditOperations.ts uses normalization throughout Enter handling. Supporting the request requires more than a display-setting change.
- **Existing commands do not maintain mixed indentation during editing:** src/vs/editor/contrib/indentation/browser/indentation.ts provides editor.action.indentationToTabs and editor.action.indentationToSpaces, but those conversions switch insertSpaces to false or true respectively. ChangeTabDisplaySize changes rendering width, not the indentation-generation policy. These are partial tools, not a persistent mixed-indentation mode.
