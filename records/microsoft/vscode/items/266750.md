# Issue #266750 — "inherit" instructions in profiles

[https://github.com/microsoft/vscode/issues/266750](https://github.com/microsoft/vscode/issues/266750)

## Summary

The requested inheritance control remains missing from the Profiles editor even though the underlying profile model already supports inheriting the default profile's prompt storage. The request is bounded and already marked team-low-hanging, but the UI scope should be settled before implementation.

## Change summary

Allow non-default profiles to use the default profile's Copilot instructions and related prompt customizations through the Profiles settings view.

## Best solution

Expose the existing `ProfileResourceType.Prompts` inheritance capability in the Profiles editor, using `useDefaultFlags.prompts` so selected profiles resolve the default profile's `promptsHome` rather than duplicating files.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts`, `src/vs/platform/userDataProfile/common/userDataProfile.ts`
- **Validation:** Add focused Profiles editor model coverage that selects the new AI customization resource, persists `useDefaultFlags.prompts`, and verifies the resulting profile resolves `promptsHome` to the default profile; run the matching suite with `./scripts/test.sh --grep "User Data Profiles"`.
- **Behavior:**

  > A non-default profile exposes an AI customization resource in its Profiles contents view. Selecting “Use Default Profile” for that resource makes the profile consume the default profile's applicable Copilot instruction/customization files; selecting profile-specific content keeps an independent profile directory. Existing inheritance choices for settings, keybindings, tasks, MCP servers, snippets, and extensions remain unchanged.
- **Trace:**

  > `ProfileResourceType.Prompts` and `useDefaultFlags.prompts` already exist in src/vs/platform/userDataProfile/common/userDataProfile.ts, where `toUserDataProfile` redirects `promptsHome` to the default profile. Prompt discovery reads `currentProfile.promptsHome` in src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts and promptsServiceImpl.ts. The missing surface is the profile-content list and label mapping in userDataProfilesEditorModel.ts and userDataProfilesEditor.ts. Keep workspace-level instruction discovery and unrelated profile resources unchanged. The uncertainty is whether the row should represent every customization stored under `promptsHome` or only instructions/custom agents named by the report.
- **Open decisions:**
  - Should the Profiles editor expose one inherited “Prompts” or “AI Customizations” resource covering everything under `promptsHome`, or a narrower control limited to instructions and custom agents?

## Evidence

- **inheritance primitive exists:** src/vs/platform/userDataProfile/common/userDataProfile.ts defines `ProfileResourceType.Prompts`; `toUserDataProfile` maps `promptsHome` to the default profile when `useDefaultFlags.prompts` is true.
- **Profiles UI gap:** src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts lists Settings, Keybindings, Tasks, MCP, Snippets, and Extensions as profile content resources but omits `ProfileResourceType.Prompts`; src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts likewise has no title/rendering case for it.
- **runtime consumption:** src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts and promptsServiceImpl.ts resolve user customizations from `IUserDataProfileService.currentProfile.promptsHome`, so the existing profile flag controls the relevant discovery root.
- **existing foundation:** https://github.com/microsoft/vscode/commit/3daef561713d9cd25d26d2ba96984b795fbf7b28 introduced profile-specific `promptsHome` storage and the `prompts` default-profile flag, but did not expose it in the Profiles editor.
- **canonical search:** https://github.com/microsoft/vscode/issues/278850 and https://github.com/microsoft/vscode/issues/290374 are newer related reports and cannot be canonicals for this re-reviewed item; https://github.com/microsoft/vscode/issues/15909 concerns settings-file composition rather than profile-level AI customization inheritance.
