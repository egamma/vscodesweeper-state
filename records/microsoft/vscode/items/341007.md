# Issue #341007 — Copilot Connectors: new chat waits for shared-client restart while another chat is active

[https://github.com/microsoft/vscode/issues/341007](https://github.com/microsoft/vscode/issues/341007)

## Summary

Thanks for the detailed report. The deferral path described is still present on current main, and the report includes live-state confirmation and recovery. It stays open for a design decision on avoiding or surfacing the shared-client restart wait.

## Change summary

A new Copilot chat blocks in prepareTurn while a shared-client restart is deferred behind an unrelated active chat after Copilot Connector auth changes.

## Best solution

Refresh connector authentication without restarting the client shared across windows, or at least surface the real wait reason and provide a safe way forward instead of showing it as reasoning.
