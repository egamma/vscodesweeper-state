# Issue #308530 — Update fails with OS error 32 when renaming Code.exe (file locked by child process)

[https://github.com/microsoft/vscode/issues/308530](https://github.com/microsoft/vscode/issues/308530)

## Summary

The inno_updater.exe rename step lacks retry logic for transient file locks — the issue remains valid on current main despite related fixes (COM surrogate termination in c2a42605f78). The core defect is in the Rust-based inno_updater binary whose source lives outside this repo.

## Change summary

Windows update fails with OS error 32 (ERROR_SHARING_VIOLATION) when inno_updater tries to rename Code.exe while a child process holds a lock.

## Best solution

Add retry-with-backoff logic to the rename step in the inno_updater Rust source (analogous to `renameWithRetry` in `src/vs/base/node/pfs.ts`), or pre-emptively terminate/detach known lock-holding child processes before the rename — similar to what c2a42605f78 does for COM surrogates but generalized to other child processes.
