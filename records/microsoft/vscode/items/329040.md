# Issue #329040 — Chat requests fail silently when tool definitions exceed the model's context budget (`budget=1`)

[https://github.com/microsoft/vscode/issues/329040](https://github.com/microsoft/vscode/issues/329040)

## Summary

Traced the exact defect on main: when aggregate tool-definition tokens exceed the model's context budget, agentIntent.ts silently clamps to a 1-token message budget instead of surfacing an actionable error, so the request is still dispatched and fails invisibly downstream. Real, reproducible-from-source bug that should route to the Copilot Chat agent/prompt area for a fix.

## Change summary

When registered MCP/tool definitions alone exceed the model's context budget, Copilot Chat computes budget=1, dispatches the request anyway, and the chat turn fails with no error shown and nothing logged below Trace level.

## Best solution

In agentIntent.ts's buildPrompt, add an explicit guard right after computing baseBudget/toolTokens (around the `messageBudget = Math.max(1, ...)` clamp at line 741): when toolTokens already meets or exceeds baseBudget, throw a descriptive error (mirroring the existing `Unable to build prompt, modelMaxPromptTokens = ...` pattern at line 842) instead of silently proceeding with a 1-token budget, so the user sees an actionable message like the one they proposed.
