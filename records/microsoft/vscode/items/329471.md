# Issue #329471 — VS Code silently exits after several days of continuous use on macOS — ptyHost heartbeat failure immediately before process death

[https://github.com/microsoft/vscode/issues/329471](https://github.com/microsoft/vscode/issues/329471)

## Summary

Strong match to the already-diagnosed main-process OOM leak in https://github.com/microsoft/vscode/issues/329843: heavy, long-running integrated-terminal output (here, a multi-day AI CLI session) leaks into the main process via the unbuffered `localPty` ProxyChannel, silently killing the whole app with no dialog and no OS crash record — exactly what's reported here. The ptyHost heartbeat warnings are a side-effect of the main process being starved right before the OOM abort, not a separate cause.

## Change summary

VS Code's main process disappears entirely after several days of heavy integrated-terminal use, with no crash dialog and no crash report, preceded by ptyHost heartbeat warnings.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/329843, which pinpoints the root cause (main-process `Event.buffer` accumulation on the `localPty` ProxyChannel, confirmed still present on current main at src/vs/code/electron-main/app.ts:1429) and proposes registering `unbufferedEvents: ['onProcessData']` or bounding the buffer.

## Evidence

- **current code confirms the gap:** src/vs/code/electron-main/app.ts:1429 — `ProxyChannel.fromService(accessor.get(ILocalPtyService), disposables)` is registered with no `unbufferedEvents` option, matching #329843's claim on current main.
- **ptyHost warning is non-fatal on its own:** src/vs/platform/terminal/node/ptyHostService.ts `_handleHeartbeatFirstTimeout`/`_handleHeartbeatSecondTimeout` only log and fire `_onPtyHostUnresponsive`; they do not terminate the main process, so the heartbeat warning 13s before death is a symptom of main-process starvation, not a separate causal path.
- **symptom match:** Reporter's incident: entire app vanished after a multi-day session with a long-running CLI (Codex) in the integrated terminal, no VS Code crash notification, no macOS Console crash report — identical presentation to #329843's description of a crashpad-intercepted heap-OOM abort.
- **corroborating comment:** Comment from aldookware on this issue independently reports jetsam/OOM kills tied to VS Code helper processes under heavy AI-CLI terminal usage over multi-day sessions, reinforcing the memory-pressure theory.
