# Issue #329471 — VS Code silently exits after several days of continuous use on macOS — ptyHost heartbeat failure immediately before process death

[https://github.com/microsoft/vscode/issues/329471](https://github.com/microsoft/vscode/issues/329471)

## Summary

This matches the well-documented main-process OOM-crash signature tracked in the open canonical issue https://github.com/microsoft/vscode/issues/234393 (open fix PR https://github.com/microsoft/vscode/pull/323980, not yet merged): heavy long-running integrated-terminal output silently accumulates in the main process until it hits V8's ~4 GB heap ceiling and aborts with no crash dialog and no OS crash record — on macOS specifically, Crashpad intercepts the V8 fatal-OOM abort (EXC_BREAKPOINT), which is exactly the `chrome_crashpad_handler` / `mach_vm_read` log line this report captured with no `.ips` report.

## Change summary

VS Code's main process silently disappears after several days of heavy integrated-terminal use on macOS, preceded by ptyHost heartbeat warnings, with no crash dialog or OS crash record.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/234393 (root-cause bug, fix in-flight as https://github.com/microsoft/vscode/pull/323980, which adds `disableEventBuffering` to stop the main process from buffering unconsumed `onProcessData` events on the `localPty` channel) rather than tracking this as a separate report; nothing distinct remains here once that PR lands.
