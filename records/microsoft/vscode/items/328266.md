# Issue #328266 — Cmd+Delete in inline "Ask a question" hover deletes the last chat turn instead of editing the focused input

[https://github.com/microsoft/vscode/issues/328266](https://github.com/microsoft/vscode/issues/328266)

## Summary

The destructive shortcut remains incorrectly active for focused DOM inputs on current main, and the open linked PR directly addresses the missing focus guard. Keep the issue open while that human-owned fix is reviewed.

## Change summary

Prevent Cmd+Delete in the focused inline Ask a Question input from undoing the latest chat request or restoring a checkpoint.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/330054, which adds the general input-focus guard to the destructive chat keybindings and regression coverage for their keybinding resolution.

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts, RemoveAction and RestoreCheckpointAction bind Cmd+Backspace on macOS while checking `EditorContextKeys.textInputFocus.negate()` but not the global `inputFocus` context, so a focused DOM input can leave the destructive chat keybinding enabled.
- **focus tracking:** src/vs/platform/contextkey/browser/contextKeyService.ts updates `InputFocusedContext` from whether the active element is an editable input; this is the missing condition for the inline input described by the reporter.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/330054 is open, references this issue with `Closes #328266`, adds `InputFocusedContext.toNegated()` to the affected chat-editing keybindings, and adds keybinding-resolution regression tests. Its current state is review-required rather than merged.
