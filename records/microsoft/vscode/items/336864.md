# Issue #336864 — Copilot CLI plugin discovery watches unrelated runtime database writes and republishes unchanged plugins

[https://github.com/microsoft/vscode/issues/336864](https://github.com/microsoft/vscode/issues/336864)

## Summary

Confirmed on current main: `AbstractAgentPluginDiscovery._refreshPlugins()` (agentPluginServiceImpl.ts) unconditionally calls `this._plugins.set(plugins, undefined)` with no equality check, and `CopilotCliAgentPluginDiscovery.start()` watches the parent `.copilot` directory non-recursively without filtering events to plugin-relevant paths — so unrelated writes (e.g. `data.db`, `platform-cache.db`) trigger rediscovery and republish a new array reference even when content is unchanged, which then fans out through `PromptsService.watchPluginPromptFilesForType`'s unguarded autoruns into repeated `CustomizationsDebugLogContribution` snapshots. This is a real, well-diagnosed perf bug that stays open for a fix.

## Change summary

Copilot CLI plugin discovery's directory watcher and refresh/publish/consumer chain lack change detection, so unrelated `~/.copilot` database writes cause repeated, unchanged-state rediscovery, prompt-change events, and debug-log snapshots that waste renderer CPU.

## Best solution

Add change detection somewhere in the pipeline — either filter the non-recursive watcher events to plugin-relevant paths in `CopilotCliAgentPluginDiscovery.start()`, or compare the newly discovered `plugins` array against the previous one (the file already imports `equals` from `objects.js` but never uses it for this) before calling `_plugins.set()` in `_refreshPlugins()` — so unchanged inventories don't propagate through `PromptsService`'s autoruns or `CustomizationsDebugLogContribution`'s logging.
