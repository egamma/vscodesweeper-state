# Issue #346625 — Webview closed during a load blocks later webviews: dead requests hold the service worker resource queue

[https://github.com/microsoft/vscode/issues/346625](https://github.com/microsoft/vscode/issues/346625)

## Summary

Keep open: current source confirms that queued requests retain stale webview clients and consume permits after disposal, blocking subsequent panels. The additional stranded-stream symptom needs diagnosis before choosing a complete fix that preserves the resource limit.

## Change summary

Closing a resource-heavy webview during loading leaves requests occupying the shared service-worker queue and prevents later webviews from loading.

## Best solution

Ensure disposed webviews cannot retain queued requests or active resource permits, while preserving the 32-body concurrency protection for healthy loads. Diagnose abandoned response and cache streams rather than adopting a timeout that permits unbounded healthy transfers.
