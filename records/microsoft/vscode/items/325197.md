# Issue #325197 — "Error: No lowest priority node found (path: iie) at lxt" when having too little "maxInputTokens"

[https://github.com/microsoft/vscode/issues/325197](https://github.com/microsoft/vscode/issues/325197)

## Summary

Still open and still unhandled on main: when a BYOK/custom-endpoint model has a small context window, prompt rendering throws the internal prompt-tsx error "No lowest priority node found" and chat surfaces it verbatim, with no actionable message about the context budget. Nothing in the repository handles or translates that error today, and two independent reporters confirmed it after the original report.

## Change summary

Chat requests against a small-context model (e.g. a local LM Studio / Foundry Local model with maxInputTokens of 3k–15k) fail with the opaque internal error "No lowest priority node found (path: …)" instead of an actionable "prompt doesn't fit the model's context window" message.

## Best solution

Make the chat request path fail gracefully for small context windows: catch the prompt-tsx budget-exhaustion error in the Copilot prompt rendering/request path (extensions/copilot/src/extension/prompts/node/base/promptRenderer.ts and the intent request handler) and surface a localized, actionable error naming the model's input-token budget — and, ideally, shrink or drop the tool list so agent mode degrades rather than hard-fails.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/prompts/node/base/promptRenderer.ts`, `extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts`, `extensions/copilot/src/extension/byok/common/byokProvider.ts`
- **Validation:** A unit test in the Copilot prompt-renderer suite that renders an agent-mode prompt against an endpoint with a tiny maxInputTokens (e.g. 4096 with the standard tool set) and asserts a localized, context-window-specific error is produced instead of the raw prompt-tsx 'No lowest priority node found' message.
- **Behavior:**

  > When a configured chat model's input-token budget is too small to hold the fixed prompt scaffolding (system prompt plus tool definitions), sending a chat message must fail with a clear, localized message naming the problem — the prompt does not fit the model's context window, with the configured maxInputTokens — rather than the internal 'No lowest priority node found (path: …)' error. Reporters hit this with custom endpoints configured in chatLanguageModels.json at 3k–15k input tokens; one reports Agent mode failing where Ask mode still works, another reports even a fresh, attachment-free Ask conversation failing at a 4,224-token window. Acceptance: with such an endpoint configured, chat shows the actionable error (or, if the chosen design degrades instead, the request succeeds with a reduced tool/context set); behavior for normal-sized context windows is unchanged.
- **Trace:**

  > The error text is thrown by @vscode/prompt-tsx (pinned at ^0.4.0-alpha.8 in extensions/copilot/package.json) from removeLowestPriorityChild during _getFinalElementTree, i.e. the renderer runs out of prunable nodes before the prompt fits the budget. In this repo the call path is PromptRenderer.render / RendererIntentInvocation.buildPrompt in extensions/copilot/src/extension/prompts/node/base/promptRenderer.ts, invoked from the intent request handler in extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts; a repository-wide grep shows no code catching or translating that error, and the only context-window user messaging is the per-attachment 'not sent to the model due to context window limitations' notice at defaultIntentRequestHandler.ts:226-235. The budget itself is derived and clamped for custom endpoints in extensions/copilot/src/extension/byok/common/byokProvider.ts, with no minimum and no check that the irreducible scaffolding fits. The boundary: do not change prompt budgeting for normal-sized models or the BYOK context-window derivation semantics covered by extensions/copilot/src/extension/byok/common/test/byokProvider.spec.ts. Uncertainty starts at whether the fix belongs here or upstream in @vscode/prompt-tsx (a typed budget-exhaustion error would make the translation clean) and whether small-context models should hard-fail or degrade. Related leads: https://github.com/microsoft/vscode/issues/322299 and https://github.com/microsoft/vscode/issues/279219.
- **Open decisions:**
  - Should a model whose context window cannot hold the fixed scaffolding fail with an actionable error, or should Copilot degrade the request (drop/trim tool definitions, disable agent mode) so it still succeeds?
  - Should BYOK/custom-endpoint configuration validate maxInputTokens up front (a minimum, or a warning at configuration time in chatLanguageModels.json) rather than only failing at request time?
  - Should the budget-exhaustion error be typed upstream in @vscode/prompt-tsx so the extension can translate it reliably, or matched here in the Copilot request path?

## Evidence

- **no handling on main:** A repository-wide grep for 'No lowest priority node found' across all .ts/.tsx files returns no matches — the string comes from the @vscode/prompt-tsx dependency (extensions/copilot/package.json pins "@vscode/prompt-tsx": "^0.4.0-alpha.8") via removeLowestPriorityChild, and no code in this repo catches or translates it into a user-facing message.
- **render path:** PromptRenderer.render / RendererIntentInvocation.buildPrompt in extensions/copilot/src/extension/prompts/node/base/promptRenderer.ts delegate straight to the prompt-tsx BasePromptRenderer without guarding against an impossible budget; the only context-window-aware user messaging that exists is the per-attachment notice in extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts:226-235.
- **budget derivation:** extensions/copilot/src/extension/byok/common/byokProvider.ts derives and clamps contextWindow, maxInputTokens and maxOutputTokens for custom endpoints, but imposes no floor and no check that the fixed prompt scaffolding (system prompt + tool definitions) fits — exactly the failure the reporters hit.
- **independent confirmations:** Comment on 2026-09-02 reports the same failure at 15k max input tokens in Agent mode (Ask mode works); comment on 2026-09-08 reports it with Foundry Local 0.10.3 / Qwen2.5-Coder-1.5B at a 4,224-token window even in a fresh Ask conversation with no attachments.
- **related lead (unverified):** https://github.com/microsoft/vscode/issues/322299 ("Custom endpoint crashes with 'No lowest priority node found' under context limits and silently ignores plain-text apiKey") and https://github.com/microsoft/vscode/issues/279219 ("optimizing tool selection: no lowest priority node found") look like the same prompt-budget failure from other triggers; GitHub reads were unavailable in this environment, so I could not verify which should be the canonical. A maintainer should consolidate these three.
- **in scope:** Copilot Chat ships from this repository (extensions/copilot), so this is a microsoft/vscode issue, not an extension problem.
