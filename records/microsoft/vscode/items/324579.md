# Issue #324579 — Setting input should fail earlier

[https://github.com/microsoft/vscode/issues/324579](https://github.com/microsoft/vscode/issues/324579)

## Summary

Real UX gap in the still-in-testing Copilot OTel enterprise-policy feature: policy-gated `chat.agentHost.otel.*` / `github.copilot.chat.otel.*` settings are only rejected on save instead of being disabled up front, and the async nature of policy resolution in the code supports this being a genuine timing issue rather than user error.

## Change summary

Settings that are locked by an enterprise/account policy let the user type and submit a value, only failing after submission instead of disabling the input immediately.

## Best solution

Ensure the Settings UI reflects `hasPolicyValue` for these OTel settings before the user can start editing — likely means making the settings tree wait for/react promptly to `AccountPolicyService`'s async `onDidChange` (src/vs/vs/platform/policy/common/policy.ts) instead of racing the initial render in settingsTree.ts, and/or surfacing the pending state while the account-side managed-settings policy is still resolving.
