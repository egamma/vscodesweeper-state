# Issue #324579 — Setting input should fail earlier

[https://github.com/microsoft/vscode/issues/324579](https://github.com/microsoft/vscode/issues/324579)

## Summary

Keep open: current source still allows editing policy-managed object settings before rejecting the submitted value. This team-authored report has a concrete settings-renderer gap, and no verified fix or same-symptom canonical was found.

## Change summary

Prevent users from entering values for settings that organization policy already makes unchangeable.

## Best solution

Policy-managed object settings should communicate their locked state before input and prevent ineffective add/edit actions, consistently with scalar and array settings. Preserve authoritative policy enforcement when a write is attempted.
