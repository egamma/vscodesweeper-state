# Issue #336459 — Add 'partial' option to `TreeItemCheckboxState` for a tri-state checkbox in `TreeItem`

[https://github.com/microsoft/vscode/issues/336459](https://github.com/microsoft/vscode/issues/336459)

## Summary

Genuine, unimplemented public-API request: `TreeItemCheckboxState` and the underlying checkbox model (`ITreeItemCheckboxState.isChecked`, `TreeItemCheckbox` in checkbox.ts) are boolean-only on current main, with no partial/indeterminate state. No canonical duplicate found; stays open as a real API design question.

## Change summary

Add a 'partial'/indeterminate value to `TreeItemCheckboxState` so a parent tree item can show a dash-style checkbox when only some children are checked.

## Best solution

Design the new enum value plus propagation semantics (does the extension set partial explicitly, or is it auto-computed from children?) before implementing — this is a public API surface change, not a pure UI tweak.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypes.ts`, `src/vs/workbench/browser/parts/views/checkbox.ts`, `src/vs/workbench/common/views.ts`
- **Validation:** A test in the tree-view checkbox suite asserting a tree item with the new partial state renders the indeterminate/dash toggle.
- **Behavior:**

  > A `TreeItem`'s checkbox can be set to a new 'partial'/indeterminate state, rendered as a dash-style checkbox (as already exists in the base Checkbox/Toggle control), so a parent whose children are only partially checked can visually reflect that. Fully checked/unchecked items are unaffected.
- **Trace:**

  > TreeItemCheckboxState (vscode.d.ts ~line 12453, mirrored in extHostTypes.ts:1668) is a 2-value enum; the render path in checkbox.ts's TreeItemCheckbox.render()/createCheckbox() only reads a boolean `isChecked` from ITreeItemCheckboxState (views.ts). Precedent cited by the reporter (PR https://github.com/microsoft/vscode/pull/257297) added a dash-codicon toggle capability to the base Checkbox control already, so the rendering primitive likely exists — the gap is plumbing a third state through the extension API and ITreeItem model. Boundary: do not change existing Checked/Unchecked semantics or the checkbox click/toggle interaction for binary items.
- **Open decisions:**
  - Is 'partial' settable directly by extensions, or auto-computed by the tree view from children's checkbox states?
  - Should clicking a partial checkbox force it to Checked, Unchecked, or cycle, and does that fire onDidChangeCheckboxState?
  - Should partial be a new TreeItemCheckboxState enum value or a separate property alongside the existing boolean state?

## Evidence

- **current enum:** src/vscode-dts/vscode.d.ts TreeItemCheckboxState only has Unchecked=0/Checked=1 (line ~12453); mirrored in src/vs/workbench/api/common/extHostTypes.ts:1668.
- **renderer is boolean-only:** src/vs/workbench/browser/parts/views/checkbox.ts TreeItemCheckbox.render() sets `this.toggle.checked = node.checkbox.isChecked` — no partial/indeterminate concept exists in the toggle model.
