# Issue #337378 — The "Ask Question" box in Agents Window steals scroll focus

[https://github.com/microsoft/vscode/issues/337378](https://github.com/microsoft/vscode/issues/337378)

## Summary

Fresh (0-day-old), team-authored bug report with a clear repro and screenshot; no fix exists on main yet, so this stays open per the team-authored protection and the lack of any citable fix commit.

## Change summary

In the Agents Window, once the mouse cursor enters the response-selection 'Ask Question' box, scrolling the chat transcript stops working until the cursor leaves the box again.

## Best solution

Fix in src/vs/sessions/contrib/chat/browser/responseSelectionSideChatController.ts / feedbackInputWidget.ts so wheel input over the absolutely-positioned 'Ask Question' overlay still reaches (or forwards to) the transcript's own scroll handling, instead of being swallowed by the overlay.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/responseSelectionSideChatController.ts`, `src/vs/sessions/contrib/agentFeedback/browser/feedbackInputWidget.ts`
- **Validation:** Manually reproduce in the Agents Window: select response text to show the 'Ask Question' box, move the cursor into the box, and confirm mouse-wheel scroll again scrolls the transcript instead of doing nothing.
- **Behavior:**

  > With the 'Ask Question' overlay showing over a selected response, scrolling the mouse wheel while the cursor is anywhere over that overlay should scroll the underlying chat transcript exactly as it would outside the overlay. Currently, once the cursor crosses into the overlay's bounds, wheel scroll stops affecting the transcript at all. Acceptance: scrolling with the cursor over the box moves the transcript the same amount as scrolling just outside it, with no dead zone.
- **Trace:**

  > The 'Ask Question' input (`FeedbackInputWidget`) is appended directly onto `this._widget.domNode` and absolutely positioned over the transcript via `style.top`/`style.left` in `responseSelectionSideChatController.ts` (`_reposition()`, ~lines 283-326). The transcript itself scrolls via a virtualized list that 'scrolls by transform' and doesn't fire native DOM scroll events (comment at lines 159-162), implying its own wheel-to-scroll handling is likely bound to the list's internal DOM node rather than the outer widget node the overlay sits on top of — plausible cause of the wheel input being swallowed once the pointer is over the overlay. No wheel listener or forwarding code was found in either file. The boundary: any fix should be confined to how wheel/pointer events over this specific overlay reach transcript scrolling; it must not change scroll-hold behavior (`_updateAutoScrollHold`) or selection highlighting, which are unrelated and already working.
- **Open decisions:**
  - Should wheel input over the box always scroll the transcript (full pass-through), or should the textarea itself scroll internally first when its own content overflows, only forwarding once the textarea has no more room to scroll?

## Evidence

- **overlay is absolutely positioned atop the transcript:** responseSelectionSideChatController.ts appends `this._input.domNode` (a FeedbackInputWidget) directly onto `this._widget.domNode` and repositions it with `style.top`/`style.left` (lines 129, 325-326), i.e. it floats on top of the virtualized transcript rather than living inside its scroll flow.
- **transcript scroll is custom, not native overflow:** A comment at lines 159-162 notes 'the transcript is a virtualized list that scrolls by transform, so it never fires a DOM scroll event' and the controller instead listens to `this._widget.onDidScroll` / a capture-phase `scroll` listener — consistent with a monaco-style custom wheel/scroll handler that could stop being reached once the pointer is over the floating overlay instead of the list's own scrollable node.
- **no dedicated wheel-forwarding logic found:** grep for `wheel`/`scroll` in responseSelectionSideChatController.ts and feedbackInputWidget.ts shows no wheel listener or pointer-events handling that would explicitly pass wheel input from the overlay through to the transcript's scroll machinery.
