# Issue #209137 — Consider notebook status `window.title` property

[https://github.com/microsoft/vscode/issues/209137](https://github.com/microsoft/vscode/issues/209137)

## Summary

Notebook activity is still missing from the window title. The linked implementation attempt was closed without merging because it needed a different architectural approach; this team-authored accessibility request should remain open.

## Change summary

Expose important notebook execution and kernel activity in the window title so screen reader users can discover it without navigating the toolbar.

## Best solution

Provide localized notebook activity information through a contribution-compatible title mechanism, preserving the existing screen reader optimization controls. Settle which notebook states the title should communicate before reviving the implementation.

Add focused title-generation coverage for the agreed transitions.
- **Behavior:**

  > Screen reader users should be able to discover important notebook activity from the window title instead of navigating to the toolbar. The title must track the agreed notebook states and remove obsolete activity information when those states end or the active editor changes. Existing title customization and screen reader optimization controls must retain their intended behavior. Acceptance should cover execution start, completion, interruption, editor switching, and disabled optimization.
- **Trace:**

  > WindowTitle.getWindowTitle() in src/vs/workbench/browser/parts/titlebar/windowTitle.ts currently supports resource-decoration state but no notebook activity. Notebook execution state is available through INotebookExecutionStateService; _updateForExecution() in src/vs/workbench/contrib/notebook/browser/viewParts/notebookEditorWidgetContextKeys.ts distinguishes notebook-level execution from cell executions. https://github.com/microsoft/vscode/pull/284152 attempted an execution-only title indication but was closed unmerged after architectural feedback; it is evidence of maintainer interest, not a landed fix or an active competing implementation. WindowTitle.registerVariables() and the SCM contribution in src/vs/workbench/contrib/scm/browser/activity.ts provide existing extensibility context. Preserve the boundary that workbench titlebar code cannot depend on notebook contrib code, and do not treat editor-scoped context keys as the authoritative execution model. The remaining product uncertainty is whether the original request extends beyond executing cells to notebook-level kernel activity and other toolbar-relevant states.
- **Open decisions:**
  - Should the title report only executing cells, or also notebook-level kernel activity when no cell execution is tracked?
  - Should notebook activity appear automatically under accessibility.windowTitleOptimized, through an opt-in window.title variable, or both?
