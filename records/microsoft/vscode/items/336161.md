# Issue #336161 — Agent Host fails to start when XDG_RUNTIME_DIR is unavailable in WSL

[https://github.com/microsoft/vscode/issues/336161](https://github.com/microsoft/vscode/issues/336161)

## Summary

Still reproduces on main: createRandomIPCHandle() in ipc.net.ts unconditionally uses XDG_RUNTIME_DIR if the env var is set, with no check that the directory actually exists or is usable, so a stale pointer (e.g. after a WSL reboot before systemd recreates /run/user/1000) causes EACCES and the agent-host/session list to fail to load. A fix was proposed in PR #336162 but it was closed without merging.

## Change summary

Agent Host fails to start when XDG_RUNTIME_DIR points to a non-existent/inaccessible directory (e.g. after a WSL reboot), because createRandomIPCHandle() doesn't validate the directory before using it.

## Best solution

Add an existence/access check (statSync + accessSync, or similar) before using XDG_RUNTIME_DIR in createRandomIPCHandle(), falling back to tmpdir() when the directory is missing or unusable — essentially what the closed PR #336162 proposed; land an equivalent fix in src/vs/base/parts/ipc/node/ipc.net.ts.
