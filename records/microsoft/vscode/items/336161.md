# Issue #336161 — Agent Host fails to start when XDG_RUNTIME_DIR is unavailable in WSL

[https://github.com/microsoft/vscode/issues/336161](https://github.com/microsoft/vscode/issues/336161)

## Summary

Keep open: current source still fails when the configured runtime directory is unavailable, and the linked patch was closed without merging. Maintainer discussion identifies a matching WSL runtime-directory lifecycle problem; whether VS Code should tolerate that environment remains unsettled.

## Change summary

Allow agent-host startup to recover when XDG_RUNTIME_DIR points to an unavailable directory instead of leaving saved sessions inaccessible in the UI.

## Best solution

Resolve the runtime-directory lifecycle failure tracked in https://github.com/microsoft/WSL/issues/13562. If maintainers accept additional VS Code resilience, recover from the actual bind failure with a bounded fallback that keeps the server and client endpoint consistent, rather than adding synchronous filesystem prechecks.
