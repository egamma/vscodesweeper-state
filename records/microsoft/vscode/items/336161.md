# Issue #336161 — Agent Host fails to start when XDG_RUNTIME_DIR is unavailable in WSL

[https://github.com/microsoft/vscode/issues/336161](https://github.com/microsoft/vscode/issues/336161)

## Summary

Confirmed on main: createRandomIPCHandle() in ipc.net.ts unconditionally prefers XDG_RUNTIME_DIR without checking the directory actually exists, so a stale env var after a WSL reboot causes EACCES and the agent host/session list fails to load. An open PR (#336162) already targets this fix, so the issue should stay open pending review/merge rather than being closed or assigned to an agent.

## Change summary

Agent host session list fails to load because createRandomIPCHandle() trusts a stale XDG_RUNTIME_DIR that no longer exists after a WSL reboot, instead of falling back to tmpdir() like it does when the variable is unset.

## Best solution

Land the fix in the open PR (or an equivalent one) that makes createRandomIPCHandle() verify XDG_RUNTIME_DIR is a usable directory before preferring it over tmpdir(), falling back the same way it does today when the variable is unset.
