# Issue #296786 — Custom Foundry Local models do not appear in VS Code Copilot Chat model picker

[https://github.com/microsoft/vscode/issues/296786](https://github.com/microsoft/vscode/issues/296786)

## Summary

A confirmed repro exists (comment 1's minimal `registerLanguageModelChatProvider` extension showing a third-party model never reaching the inline picker), and the generic root cause — `isUserSelectable` being treated as falsy when omitted — was merged in PR #316469 (commit 74465a46…, shipped 1.121.0). That exact commit was refuted by the prior review, and a still-open follow-up PR (#316843, 'Fix language model picker visibility', unmerged) plus a fresh July report (comment 7) show the picker-visibility problem for third-party/BYOK providers like Foundry Local/AI Toolkit isn't fully resolved, so this stays open rather than re-citing the refuted commit.

## Change summary

Custom/third-party language models (e.g. Foundry Local via the AI Toolkit extension) registered through the public `languageModelChatProvider` API don't appear in the Copilot Chat model picker even though they're reachable via the API.

## Best solution

Land or supersede the open PR https://github.com/microsoft/vscode/pull/316843 (persisted picker-visibility toggle + `chatLanguageModels.json` overrides, explicit-`false`-only hiding) and confirm it covers the Foundry Local/AI Toolkit case from comment 7; also clarify whether agent-mode's tool-calling capability requirement (raised in comment 2) is separately filtering these models as designed.
