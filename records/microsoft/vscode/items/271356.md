# Issue #271356 — Support maximizing the panel when justified

[https://github.com/microsoft/vscode/issues/271356](https://github.com/microsoft/vscode/issues/271356)

## Summary

Keep open: this remains an accepted Backlog feature request for maximizing a justified panel, and the three referenced implementation PRs are closed without a merged fix. The older toggle request is related but does not report the same observable limitation, so it does not meet the stronger duplicate bar for this re-reviewed issue.

## Change summary

Allow the panel, including the integrated terminal panel, to be maximized when it is justified to the left or right rather than centered.

## Best solution

Extend panel maximization in the workbench layout so side-justified panels can occupy the available editor area without breaking grid restoration, preserving the chosen alignment when toggling maximization.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/parts/panel/panelPart.ts`
- **Validation:** Add or extend workbench layout tests to maximize and restore the panel under centered, left-justified, and right-justified configurations, asserting editor visibility, panel dimensions, alignment preservation, and grid restoration.
- **Behavior:**

  > When the panel is justified to the left or right, users can toggle panel maximization as they can with a centered panel. Maximization uses the available workbench area without corrupting the grid, and restoring returns the editor and panel to their prior sizes and alignment. Existing centered-panel maximization and ordinary panel resizing remain unchanged.
- **Trace:**

  > The request belongs to the workbench layout and panel contribution, with likely control paths in src/vs/workbench/browser/layout.ts and src/vs/workbench/browser/parts/panel/panelPart.ts. Three linked closed implementation attempts show the work is non-trivial: https://github.com/microsoft/vscode/pull/278549 explicitly identifies grid-layout breakage with non-center alignment, while https://github.com/microsoft/vscode/pull/288038 and https://github.com/microsoft/vscode/pull/288597 attempted the requested support but did not land. The boundary is panel maximization and restoration for justified layouts; centered behavior, unrelated sidebar positioning, and single-view maximization tracked at https://github.com/microsoft/vscode/issues/47661 must not regress or be conflated with this request.
- **Open decisions:**
  - For left- and right-justified layouts, should maximizing the panel hide the editor completely or preserve any minimum editor strip required by the workbench grid contract?
  - When maximization is toggled off after alignment or window-size changes, should restoration use the exact pre-maximized geometry or the most recent valid size for the current alignment?
