# Issue #336246 — Removing link reference from chat input does not reflect in pills

[https://github.com/microsoft/vscode/issues/336246](https://github.com/microsoft/vscode/issues/336246)

## Summary

Traced this on current main: GitHub issue/PR links pasted into the chat input are attached as plain (non-range-bound) attachments, so nothing removes the pill when the user later deletes the link text from the input — a real, still-open gap in the newly landed pill feature.

## Change summary

Deleting a pasted GitHub issue/PR link from the chat input text does not remove the corresponding attachment pill.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts, the GitHub-link paste path (PasteTextProvider.provideDocumentPasteEdits, ~line 400-420) calls createCustomPasteEdit with plain `context` and no `inlineReference`, unlike the copied-context/symbol-reference path which passes `{ inlineReference: { text, range } }` so the attachment tracks a decoration and disappears when that range is deleted. Extending the GitHub-link path to bind each attachment to its matched URL range (supporting multiple simultaneous links, since createCustomPasteEdit's `inlineReference` currently only handles a single-context case) would fix this properly.
