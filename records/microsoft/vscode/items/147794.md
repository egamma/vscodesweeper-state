# Issue #147794 — SCM - screenreader not reading git commit formatting warnings

[https://github.com/microsoft/vscode/issues/147794](https://github.com/microsoft/vscode/issues/147794)

## Summary

Keep open: current source still lacks automatic spoken feedback for commit-message length warnings in the Source Control input. The warnings now use editor diagnostics rather than the original validation popup, so fixing the popup alone would not address this report.

## Change summary

Make commit-message formatting warnings, including the number of characters over the configured limit, available to screen reader users while editing.

## Best solution

Provide accessible feedback for Git's commit-length diagnostics in the embedded SCM editor, preserving configurable thresholds and avoiding repeated announcements during continuous typing. Validate the actual spoken message with NVDA and Orca before treating the issue as resolved.

## Evidence

- **Reported trigger and maintainer response:** https://github.com/microsoft/vscode/issues/147794 describes typing an overlong commit-message line and receiving a visual warning without spoken feedback, tested with NVDA and Orca. The supplied 2022-04-21 maintainer comment acknowledges the report and promises investigation; it does not confirm a fix.
- **Current formatting-warning producer:** extensions/git/src/diagnostics.ts: GitCommitInputBoxDiagnosticsManager.onDidChangeTextDocument creates Warning diagnostics covering overlong lines, with messages such as '{0} characters over {1} in current line'. It publishes these through DiagnosticCollection rather than SourceControlInputBox.validateInput.
- **Reproduction configuration:** extensions/git/package.json registers git.inputValidation with default false, git.inputValidationLength with default 72, and git.inputValidationSubjectLength with default 50. A current reproduction must enable validation and distinguish the subject-line threshold from the body-line threshold.
- **Popup is no longer the relevant formatting path:** extensions/git/src/repository.ts: Repository.validateInput currently returns warnings for a huge repository or changing a rebase commit message, not line length. src/vs/workbench/contrib/scm/browser/scmInput.ts: SCMInputWidget.renderValidation renders those separate validation messages without a live announcement, but changing it alone would miss the reported formatting warnings.
- **Automatic diagnostic feedback misses SCM input:** src/vs/workbench/contrib/accessibilitySignals/browser/editorTextPropertySignalsContribution.ts selects its editor through IEditorService.activeTextEditorControl. SCMInputWidget constructs a separate embedded CodeEditorWidget with an explicit contribution list and isSimpleWidget: true; focusing that input does not make it the workbench's active text editor. Consequently, its formatting diagnostics do not enter this automatic warning-signal path. The generic warning signals also announce 'Warning' or 'Warning on Line', not the diagnostic's excess-character message.
- **Existing accessibility help does not cover the warning:** src/vs/workbench/contrib/scm/browser/scmAccessibilityHelp.ts presents repository state, commit-message text and navigation guidance, but does not include formatting diagnostics or their messages. This does not supply the requested automatic feedback.
