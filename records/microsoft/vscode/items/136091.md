# Issue #136091 — Default text editor tab appears when applying edits to the document through custom text editor

[https://github.com/microsoft/vscode/issues/136091](https://github.com/microsoft/vscode/issues/136091)

## Summary

The duplicate-tab trigger is addressed on current main: the untitled working-copy handler now recognizes an existing custom text editor, preventing the dirty-file tracker from opening another text-editor tab. The behavior-changing commit landed after this issue was reopened.

## Change summary

Editing an untitled document through Cat Scratch unexpectedly opens a second default text-editor tab, whose closure disposes the custom editor's document.

## Best solution

Treat the duplicate-tab defect as completed by commit 131fadee2b35ad00e7ec2347598a75e6211861c5, which makes the existing custom editor satisfy the working-copy lookup before another editor is opened.

A custom text editor wrapping that resource is consequently recognized as already open. The change is present in the checkout and was merged through https://github.com/microsoft/vscode/pull/315365.
- **Exact current-main flow:** Source-only reproduction tracing followed the first edit into TextFileEditorTracker's untitled.onDidChangeDirty listener in src/vs/workbench/contrib/files/browser/editors/textFileEditorTracker.ts. ensureDirtyTextFilesAreOpened calls workingCopyEditorService.findEditor(model) before opening a default editor. WorkingCopyEditorService.findEditor invokes registered handlers' isOpen methods; the corrected untitled handler now matches CustomEditorInput.resource and excludes the resource from openEditors. Thus the reported duplicate-tab path no longer reaches editor creation. No runtime execution was performed.
