CPU and memory values must be identifiable rather than omitted or presented as ambiguous numbers. Automatic updates must not make rows or context menus impossible to read, and process disappearance must leave navigation usable. Acceptance includes the reported NVDA desktop and Firefox scenarios, while preserving existing process actions and sighted-user updates.
- **Trace:**

  > The reopened report has owner-confirmed keyboard failures and an independent NVDA/Firefox reproduction at https://github.com/microsoft/vscode/issues/121851#issuecomment-1361610659 and https://github.com/microsoft/vscode/issues/121851#issuecomment-1361669637. Current ProcessRenderer.renderElement displays four fields, while ProcessAccessibilityProvider.getAriaLabel in src/vs/workbench/contrib/processExplorer/browser/processExplorerControl.ts supplies only element.name; the shared list accessibility renderer installs it as aria-label. ProcessExplorerControl.update refreshes children through Delayer(1000), with PID-based identities, and focus only calls tree.domFocus. Opening now runs through ProcessExplorerEditor and an auxiliary editor window, so historical focus and speech behavior cannot be assumed unchanged.
