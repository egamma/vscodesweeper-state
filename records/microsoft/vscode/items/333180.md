# Issue #333180 — Agent host (Codex): every auto-approved action posts its approval rationale into the transcript

[https://github.com/microsoft/vscode/issues/333180](https://github.com/microsoft/vscode/issues/333180)

## Summary

Confirmed in source: `_handleGuardianWarning` in codexAgent.ts forwards every guardian-review notification verbatim as a `SystemNotification`, with no filter on approve/deny, unlike the sibling `_handleGuardianReviewCompleted` which explicitly returns early unless `status === 'denied'`. Worth fixing, but the correct filter isn't obvious from the protocol alone.

## Change summary

On the Auto-review permissions preset, every auto-approved Codex action posts its full approval rationale as a standalone transcript entry, drowning out the actual assistant response on turns with many tool calls.

## Best solution

Filter `_handleGuardianWarning` (src/vs/platform/agentHost/node/codex/codexAgent.ts, ~line 3633) so routine auto-approvals don't produce a `SystemNotification` part, mirroring the denial-only filter already in `_handleGuardianReviewCompleted`. The exact boundary needs a maintainer/Codex-protocol call: `GuardianWarningNotification` (protocol/generated/v2/GuardianWarningNotification.ts) carries only a free-text `message` and `threadId`, no structured decision field, so distinguishing 'this was just an auto-approval' from a genuine warning would mean parsing message text — fragile — unless the app-server can be asked to emit a decision field.
