# Issue #333542 — Unactionable MCP Error State

[https://github.com/microsoft/vscode/issues/333542](https://github.com/microsoft/vscode/issues/333542)

## Summary

Team-authored UX request (sbatten, MEMBER) about the MCP error state not surfacing the actual error or clear recovery actions in the chat UI; hard keep-open rule applies to team-authored issues and no fix commit references this issue number.

## Change summary

When an MCP server enters the error state, the UI (e.g. the chat MCP tools indicator) doesn't clearly show the error message or offer actionable recovery steps.

## Best solution

In src/vs/workbench/contrib/mcp/browser/mcpCommands.ts, the error-state indicator and quick pick already expose 'Show Output' and 'Start Server' actions, but per the discussion this isn't discoverable/actionable enough from the error indicator itself — consider surfacing the actual error message inline and making the recovery actions (show output, restart, re-auth) more prominent directly from the error affordance; a second data point in the comments (silent filtering via chat.mcp.allowedServers with zero diagnostics) suggests a related but distinct gap worth a visible notice when a server is policy-filtered.
