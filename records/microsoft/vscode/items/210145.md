# Issue #210145 — Add ignore extension setting

[https://github.com/microsoft/vscode/issues/210145](https://github.com/microsoft/vscode/issues/210145)

## Summary

A real capability gap remains: VS Code has fixed ignore-file names and manual watcher exclusions, but no mechanism for extensions to contribute additional ignore files. Route this backlog request to the file-watcher area.

## Change summary

Allow extensions to contribute ignore-file names whose rules VS Code applies to file watching.

## Best solution

Design a shared watcher-ignore mechanism under the file-watcher service that supports `.gitignore`, `.ignore`, and extension-contributed formats without requiring users to duplicate rules in `files.watcherExclude`. Coordinate it with the narrower work tracked by https://github.com/microsoft/vscode/issues/62725.

## Vision fit

- **Fit:** aligned
- **Reason:** An extension-driven mechanism can reduce unnecessary filesystem work while keeping ecosystem-specific behavior outside the core defaults.
- **Evidence:** Public values: “Performance trumps functionality” and “The power lives in extensions.”

## Evidence

- **current watcher configuration:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers `files.watcherExclude` as manually configured glob patterns; its defaults contain only selected Git and Mercurial metadata paths.
- **partial existing capabilities:** The same contribution file exposes `explorer.excludeGitIgnore`, but only for hiding `.gitignore` entries in Explorer. Search separately documents support for only `.gitignore` and `.ignore` in src/vs/workbench/contrib/search/browser/search.contribution.ts.
- **related canonical work:** https://github.com/microsoft/vscode/issues/62725 remains open and tracks applying `.gitignore` to the file watcher, but it does not cover arbitrary extension-contributed ignore formats such as `.npmignore` or `.hgignore`.
- **implementation attempt:** The open draft https://github.com/microsoft/vscode/pull/246661 explores Git-specific watcher exclusion for another issue; it does not implement the extension contribution mechanism requested here.
