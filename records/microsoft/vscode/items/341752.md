# Issue #341752 — API: Allow revealing a text document without expanding its editor group while preserving focus

[https://github.com/microsoft/vscode/issues/341752](https://github.com/microsoft/vscode/issues/341752)

## Summary

Keep open as a public API feature request: current source deliberately restores the target group with preserveFocus, but exposes no supported per-operation opt-out. Existing internal behavior distinguishes preserving group activation from restoring group size, so the requested capability is a genuine API gap rather than a request to change the default.

## Change summary

Allow extensions to reveal and select a text document, including an existing background tab, without moving keyboard focus or expanding its editor group.

## Best solution

Have the extension API owners assess an opt-in reveal capability that preserves group dimensions while bringing the requested tab to the front. Preserve the existing preserveFocus restoration behavior for callers that do not opt in.

## Evidence

- **Public API gap:** src/vscode-dts/vscode.d.ts:824-852 defines TextDocumentShowOptions with viewColumn, preserveFocus, preview, and selection, but no group-restoration control. src/vs/workbench/api/common/extHostTextEditors.ts:65-85 and extHost.protocol.ts:338-344 likewise expose no independent restoration option.
- **Intentional existing behavior:** src/vs/workbench/api/browser/mainThreadEditors.ts:242-254 explicitly maps preserveFocus to EditorActivation.RESTORE. Its comment cites https://github.com/microsoft/vscode/issues/79633 as the reason to restore without making the group active, supporting classification as an opt-in feature request rather than a regression in preserveFocus.
- **Reported minimum-size trigger matches source:** The reporter describes revealing a source tab while its group is at minimum width and the webview retains focus. src/vs/workbench/browser/parts/editor/editorGroupView.ts:1226-1282 handles RESTORE by calling groupsView.restoreGroup; editorPart.ts:772-785 expands the group when its width equals minimumWidth or its height equals minimumHeight. This explains the reported threshold without requiring focus to move.
- **Internal capability is not a public alternative:** editorGroupView.ts:1235-1238 handles EditorActivation.PRESERVE without activating or restoring the group, independently of selecting an editor within it. That activation option is not exposed by TextDocumentShowOptions. The vscode.open command also converts its options through TextEditorOpenOptions.from in src/vs/workbench/api/common/extHostTypeConverters.ts:1561-1576, which does not forward activation; its background option opens inactive rather than satisfying the requested foreground-tab reveal.
- **Existing-capability check:** Inspected editor command registrations and workbench editor configuration registrations. No supported per-operation group-restoration switch was found. The proposed customTextEditorNavigation API targets navigation inside the custom editor panel, not revealing a separate text editor while preserving that group's dimensions.
