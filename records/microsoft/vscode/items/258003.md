# Issue #258003 — "Save As" dialog box sometimes corrupts the file extension 

[https://github.com/microsoft/vscode/issues/258003](https://github.com/microsoft/vscode/issues/258003)

## Summary

Keep open for investigation at the Electron/Windows native-dialog boundary. VS Code supplies compound-extension filters, but the reported filename change happens inside the native dialog; no verified fix or same-symptom canonical was found.

## Change summary

Switching the Windows Save As file type away from Prompt leaves '.prompt' in the filename instead of replacing the complete '.prompt.md' suffix.

## Best solution

Establish whether Electron or the Windows save dialog owns compound-extension replacement, then track a fix that changes Untitled-1.prompt.md to Untitled-1.conf when switching to Properties. Preserve compound-extension filters and avoid stripping legitimate filename components after the dialog returns.

## Evidence

- **Exact reported trigger:** https://github.com/microsoft/vscode/issues/258003 describes Windows 11, VS Code Insiders 1.103.0, and Electron 37.2.3: selecting Prompt produces Untitled-1.prompt.md, then selecting Properties produces Untitled-1.prompt.conf. This occurs before saving; file-content corruption is not reported.
- **Area-owner assessment:** https://github.com/microsoft/vscode/issues/258003#issuecomment-3153294006 identifies Electron as the likely owner because all observed behavior occurs within the native file dialog.
- **Current filter construction:** src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts, getPickFileToSaveDialogOptions, constructs filters from languageService.getExtensions and trims surrounding dots without splitting compound suffixes. src/vs/workbench/contrib/chat/common/promptSyntax/config/promptFileLocations.ts still defines PROMPT_FILE_EXTENSION as '.prompt.md'.
- **Current native-dialog boundary:** src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts, pickFileToSave and toNativeSaveDialogOptions, forwards filters and the initial path to nativeHostService.showSaveDialog. src/vs/platform/dialogs/electron-main/dialogMainService.ts, showSaveDialog, awaits electron.dialog.showSaveDialog and only normalizes the returned path on macOS. These paths contain no VS Code handler for filename changes while switching native-dialog filters.
- **Canonical search:** Related searches found https://github.com/microsoft/vscode/issues/203384, verified open, but it reports macOS omitting extensions longer than four characters when clicking an existing file. It does not report Windows retaining part of a compound extension when switching file types, so it does not satisfy the same-observable-symptom duplicate bar for this re-reviewed item.
- **Verification limits:** Read-only source inspection establishes the native-dialog ownership boundary, not whether current Electron on Windows still exhibits the behavior. No native Windows reproduction was executed, and no concrete fixing commit was identified.
