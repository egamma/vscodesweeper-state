# Issue #311784 — Agents Insiders cannot start Azure DevOps MCP server

[https://github.com/microsoft/vscode/issues/311784](https://github.com/microsoft/vscode/issues/311784)

## Summary

The central gap remains on current main: the Agents/Copilot harness explicitly rejects MCP input and command variables rather than collecting or forwarding their values. This team-authored issue has no linked fix, open PR, or verified canonical, so it should remain open for design and implementation.

## Change summary

Allow an MCP server used by Agents to obtain its declared promptString inputs instead of failing or being excluded from delivery.

## Best solution

Support resolving declared MCP prompt inputs before an MCP configuration is delivered to an Agent session, with clear prompting and appropriately scoped storage for ordinary and secret values. Marketplace installation and existing .vscode/mcp.json configurations should lead to a startable server rather than an invalid configuration or compatibility rejection.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/mcp/browser/mcpCommandsAddConfiguration.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupport.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLocalCustomizations.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostMcpServerSupport.test.ts`, `src/vs/workbench/contrib/mcp/test/browser/mcpConfigurationEntryPoints.test.ts`
- **Validation:** Add focused tests showing that an Agent-session MCP server with promptString inputs receives concrete resolved values and is delivered, then run scripts/test.sh --grep "Agent Host MCP server support|current agent session resolves MCP input variables".
- **Behavior:**

  > Installing or enabling an MCP server for an Agent session must support its declared promptString inputs. The user is prompted at the chosen lifecycle point, submitted values are used to start the server, and password inputs are not exposed as plain-text configuration. Cancellation must leave the server stopped without writing a partial configuration. MCP servers without interactive variables must retain their existing delivery and startup behavior.
- **Trace:**

  > The reported configuration reaches the Agent path with unresolved ${input:ado_org} and ${input:ado_domain} expressions. resolveMcpConfigurationForSync in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupport.ts rejects input and command expressions before calling the non-interactive resolver, causing .vscode/mcp.json servers to be marked NotDelivered; collectNonPluginMcpServers in agentHostLocalCustomizations.ts therefore cannot bundle them. The direct installation path in src/vs/workbench/contrib/mcp/browser/mcpCommandsAddConfiguration.ts independently rejects inputs when the destination is the current Agent session. Existing VS Code MCP input resolution and storage live behind the MCP registry and should be assessed for reuse, especially for password values. Keep support scoped to declared MCP inputs; do not broaden this work to arbitrary command-variable execution or unrelated partially supported launch properties.
- **Open decisions:**
  - Should Agent-bound MCP inputs be requested during installation/addition, on the first server start, or when an existing configuration is first delivered to a session?
  - Are resolved values persisted globally through VS Code's MCP input storage, scoped to the Agent session, or requested again for each session, particularly for password inputs?
