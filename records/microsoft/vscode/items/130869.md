# Issue #130869 — Adjust auto-highlighting of the cursor position to the setting at select.

[https://github.com/microsoft/vscode/issues/130869](https://github.com/microsoft/vscode/issues/130869)

## Summary

Still valid on current main: the textual highlight provider uses `model.getWordAtPosition()` (language word definition) and hardcoded `USUAL_WORD_SEPARATORS` for matching, ignoring the user's `editor.wordSeparators` setting. CJK text without space delimiters highlights entire paragraphs. No fix or duplicate found.

## Change summary

Word highlighting at cursor position should respect the `editor.wordSeparators` setting so that CJK text (Japanese, Chinese, etc.) highlights individual words rather than entire paragraphs.

## Best solution

The textual highlight provider (`src/vs/editor/contrib/wordHighlighter/browser/textualHighlightProvider.ts`) should accept and use the `editor.wordSeparators` option instead of `USUAL_WORD_SEPARATORS` when calling `findMatches` (line 37), and ideally use a word-boundary computation that respects those separators when determining the word at cursor. The `wordSeparators` string is already threaded through the highlighter pipeline — it just needs to reach the textual provider.
