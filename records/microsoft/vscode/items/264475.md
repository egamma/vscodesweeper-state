# Issue #264475 — View changes button in working set should be a toggle?

[https://github.com/microsoft/vscode/issues/264475](https://github.com/microsoft/vscode/issues/264475)

## Summary

Current main still implements the working-set change actions as one-way navigation, while the issue proposes a stateful toggle consistent with editor-title diff actions. This remains valid chat UX polish, but the aggregate action's return target needs a maintainer decision before implementation.

## Change summary

Make the working-set aggregate and per-file change actions toggle between reviewing edits and the corresponding normal editor state.

## Best solution

Give working-set change actions clear, state-aware behavior: when their diff is active, invoking the same action should return to a predictable normal editor state, with labels and tooltips reflecting the current action. Settle what “View All Edits” returns to before applying the same interaction model to the per-file controls.

- **Behavior:**

  > Working-set change controls should communicate and perform the action appropriate to the current editor state. From a normal file, invoking a per-file control opens its change review; invoking it again while that review is active returns to the normal file. The aggregate control should follow an explicitly chosen equivalent rule for the multi-file review. Labels, tooltips, focus behavior, Keep/Undo state, and working-set collapse behavior must remain coherent across both transitions.
- **Trace:**

  > ChatEditingShowChangesAction in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts unconditionally calls IChatEditingSession.show(). The completed parent UX work at https://github.com/microsoft/vscode/issues/260175 names this issue as a follow-up. Keep the boundary to navigation and action presentation; do not alter edit acceptance, undo, working-set contents, or collapse behavior.
- **Open decisions:**
  - When the aggregate “View All Edits” multi-diff is already active, should a second invocation restore the previously active editor, open one selected changed file normally, or close the multi-diff without choosing a file?
  - Should both the aggregate and per-file controls adopt toggle semantics, or should toggling be limited to per-file reviews where the normal-file destination is unambiguous?
