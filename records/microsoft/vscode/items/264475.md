# Issue #264475 — View changes button in working set should be a toggle?

[https://github.com/microsoft/vscode/issues/264475](https://github.com/microsoft/vscode/issues/264475)

## Summary

The working-set actions still open changes rather than toggle back to files; the existing editor-level toggle only partially covers the request. Keep this open for a UX decision, particularly on what toggling the multi-file view should restore.

## Change summary

Consider making the working-set per-file and all-changes buttons toggle between changes and regular file editors.

## Best solution

Agree on consistent, reversible navigation between chat edits and file editors, including an explicit return destination for the all-edits view. The existing editor-level toggle provides a useful precedent, but does not settle the working-set interaction.

Confirm that navigation never accepts, rejects, or modifies the edits and that the existing editor-level Toggle Diff command remains functional.
- **Behavior:**

  > The working-set file action opens a diff, while View All Edits opens the session multi-diff; invoking them again does not provide a corresponding return to regular file editing. The proposed improvement is a reversible interaction consistent with the existing editor-level diff toggle, but the reporter explicitly requests discussion rather than asserting that toggling is already intended. Acceptance must define the second activation for both a single-file diff and a multi-file review, including the destination when multiple editors are open. Navigation must not change edit acceptance or file contents.
- **Trace:**

  > In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts, OpenFileInDiffAction opens the selected resource and invokes its editor integration with toggleDiff(undefined, true), forcing diff display. ChatEditingShowChangesAction delegates to ChatEditingSession.show() in chatEditingSession.ts, which returns when its multi-diff pane is visible or opens/reactivates that pane otherwise. The existing chatEditor.action.toggleDiff in chatEditingEditorActions.ts delegates without a forced show argument; ChatEditingCodeEditorIntegration.toggleDiff in chatEditingCodeEditorIntegration.ts then chooses diff or regular editor based on editor state. These source paths establish the current interaction without executing the UI. Preserve edit acceptance/rejection semantics and unrelated editor groups. The closed working-set cleanup https://github.com/microsoft/vscode/issues/260175 explicitly spawned this follow-up and does not settle its design.
- **Open decisions:**
  - Should the working-set file and all-edits actions become toggles, or remain navigation commands with the return action confined to the editor?
  - If View All Edits becomes a toggle, should its second activation restore the previously active editor or open a particular modified file, and should the multi-diff tab remain open?
