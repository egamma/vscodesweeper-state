# Issue #334271 — Agent sessions: MCP servers requiring promptString inputs or OAuth fail silently — tools absent with no surfaced error or support documentation

[https://github.com/microsoft/vscode/issues/334271](https://github.com/microsoft/vscode/issues/334271)

## Summary

Real, previously-reviewed gap: MCP servers needing interactive input (promptString/OAuth) apparently fail silently in agent sessions with no surfaced error, and reporter suspects a broader gap in MCP support there; no fix commit found on main and a related issue (#335528) tracks persistent surfacing of MCP auth problems but is not older/narrower enough to be a clean duplicate, so this stays open.

## Change summary

Agent sessions silently drop MCP servers that require interactive input (promptString) or OAuth, with no error surfaced and no docs on what MCP support exists there.

## Best solution

Surface a clear, non-silent signal in the agent-session UI when an MCP server can't activate (pending input/unauthorized), and document current MCP support scope for agent sessions; a maintainer should scope whether pre-resolving inputs from secret storage is also in scope, likely touching src/vs/workbench/contrib/mcp/common/mcpRegistry.ts and the agent-host session bootstrap path.

- **Validation:** A test or manual check confirming an agent session surfaces a visible error/status when an MCP server fails to activate due to unresolved promptString input or missing OAuth, rather than silently omitting its tools.
- **Behavior:**

  > When an MCP server configured for a workspace requires an interactive promptString input or OAuth that hasn't been resolved, starting an agent session should not silently omit that server's tools with no signal. Instead the session should surface that the server is unavailable and why (pending input/unauthorized), and/or documentation should state what MCP support exists in agent sessions. Editor chat's working behavior (prompting for input) is the baseline to compare against.
- **Trace:**

  > MCP server activation and input resolution flows through src/vs/workbench/contrib/mcp/common/mcpRegistry.ts; grep found no branch there that special-cases a non-interactive (agent-host/background) surface to skip prompting and instead report an error — the current code appears to assume an interactive UI is always available to resolve `${input:...}` values. The boundary: do not change resolution behavior for interactive editor chat, only add a failure path for headless/agent contexts. Related: https://github.com/microsoft/vscode/issues/335528 (narrower, UI persistence of MCP auth errors only).
- **Open decisions:**
