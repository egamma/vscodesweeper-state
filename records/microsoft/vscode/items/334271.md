# Issue #334271 — Agent sessions: MCP servers requiring promptString inputs or OAuth fail silently — tools absent with no surfaced error or support documentation

[https://github.com/microsoft/vscode/issues/334271](https://github.com/microsoft/vscode/issues/334271)

## Summary

Fresh, well-diagnosed report with real substance: I traced the agent-host MCP path and found no `${input:...}`/promptString resolution anywhere in src/vs/platform/agentHost/node, while OAuth-gated servers do have a partial surfacing mechanism (McpServerStatus.AuthRequired) that promptString-gated servers never reach — so at least the promptString-input case genuinely fails without any signal today.

## Change summary

MCP servers requiring an interactive `${input:...}` promptString or OAuth on activation silently fail to register their tools in Copilot agent sessions, with no error surfaced and no documentation of what's supported.

## Best solution

Extend the existing McpServerStatus surfacing (Ready/Error/AuthRequired/Stopped, see src/vs/platform/agentHost/node/shared/mcpCustomizationController.ts) with an input-needed state analogous to AuthRequired for promptString-gated servers, or resolve inputs from secret storage non-interactively before agent-session startup; document current agent-session MCP support in the interim.
