# Issue #334271 — Agent sessions: MCP servers requiring promptString inputs or OAuth fail silently — tools absent with no surfaced error or support documentation

[https://github.com/microsoft/vscode/issues/334271](https://github.com/microsoft/vscode/issues/334271)

## Summary

Well-documented, plausible gap: the agent-host session provider does have MCP server state machinery (Starting/Ready/AuthRequired/Error) with diagnostics logged per server, but those diagnostics go to a hidden output channel by default and there's no equivalent of the workbench's interactive `resolveWithInteraction` for `${input:...}` promptString variables in the headless agent-session path, matching the reporter's 'silent failure' description; already assigned to a maintainer, so routing rather than closing.

## Change summary

MCP servers needing an interactive promptString input or first-use OAuth silently fail to activate in Copilot agent sessions, with no error surfaced and no documented support boundary.

## Best solution

Either surface the MCP server's AuthRequired/Error state proactively in the agent-session UI (not just the hidden per-server output channel in AbstractAgentHostCustomizationService/agentHostCustomizationService.ts) and/or add a pre-resolution path for `${input:...}` promptString variables (e.g. via secret storage) for the headless session path, then document what MCP activation modes agent sessions support.
