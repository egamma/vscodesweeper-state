# Issue #320292 — Agent Window: Applying patches hangs forever

[https://github.com/microsoft/vscode/issues/320292](https://github.com/microsoft/vscode/issues/320292)

## Summary

Well-diagnosed hang in the Agents window when write-permission locks for external edits are never released during multi-file edits. The reporter traced the root cause to leaked locks in chatEditingSession.ts and filed PR #326067. The team's suggestion to use agentHost doesn't resolve it (the reporter confirms it affects agentHost-enabled sessions too). No fix has been merged on main. The `info-needed` label is outdated — the reporter has provided extensive diagnostics including event logs, root-cause analysis, and a fix PR.

## Change summary

Agent window hangs indefinitely when applying multi-file patches because write-permission locks in the external-edit flow are never released.

## Best solution

Review and either merge or incorporate the fix from https://github.com/microsoft/vscode/pull/326067 (or implement an equivalent safeguard in the agentHost path). The core issue is that `startExternalEdits` in `chatEditingSession.ts` acquires per-resource locks via `_streamingEditLocks.queue()` that are only released when `stopExternalEdits` completes — if the permission flow stalls or an error occurs before `stopExternalEdits`, the locks leak and the session hangs permanently. A timeout safety net and proper error-path lock cleanup are needed.

## Evidence

- **root cause traced in source:** In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts lines 669-745, `startExternalEdits` acquires per-resource locks via `_streamingEditLocks.queue()` that block until `releaseLock.p` resolves. These are only released in `stopExternalEdits` (line 848). If `stopExternalEdits` is never called (e.g. permission flow stalls), the locks leak and all subsequent writes to those resources hang forever.
- **reporter's detailed analysis:** Comment 10 provides a systematic analysis of 929 permission requests: all 7 orphaned (never-answered) requests were write-kind, and each correlates with a session hang. The pattern is deterministically reproducible on cancel+retry.
- **open community PR:** https://github.com/microsoft/vscode/pull/326067 — 'fix: agent hang from leaked external-edit lock' — filed by the reporter, still open.
- **related closed issue:** https://github.com/microsoft/vscode/issues/316053 was closed as insiders-released with the same symptoms but the underlying lock-leak path remains unguarded on current main.
- **no fix on main:** git log shows no commits referencing #320292, #326067, or the external-edit lock leak. The vulnerable code path in chatEditingSession.ts is unchanged.
