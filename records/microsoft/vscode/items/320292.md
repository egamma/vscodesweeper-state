# Issue #320292 — Agent Window: Applying patches hangs forever

[https://github.com/microsoft/vscode/issues/320292](https://github.com/microsoft/vscode/issues/320292)

## Summary

Keep open: the multi-file external-edit tracking defect remains visible in current source, and the reporter supplied a deterministic retry reproduction and diagnostic logs. The linked fixing PR is still open; the disagreement about Agent Host coverage needs resolution, not a timeout close.

## Change summary

Multi-file agent patches can leak an external-edit lock, leaving subsequent writes waiting indefinitely and requiring a window restart.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/326067 against the supported session implementations, establishing whether the reported Agent Host configuration reaches the same faulty path. Every file tracked by one tool call should finish its external-edit lifecycle without stranding subsequent writes.

## Evidence

- **Confirmed reproduction and diagnostics:** https://github.com/microsoft/vscode/issues/320292#issuecomment-4985371607 reports 929 permission requests versus 922 completions, with all seven unanswered requests being writes. Cancel-and-retry deterministically completes reads and then stalls on the first write.
- **Current-source tracking defect:** extensions/copilot/src/extension/chatSessions/copilotcli/node/permissionHelpers.ts:353-356 calls trackEdit(toolCall.toolCallId, [editFile], stream) for individual files. extensions/copilot/src/extension/chatSessions/common/externalEditTracker.ts stores only one deferred completion per editKey using Map.set; another file under the same tool call overwrites the previous completion. completeEdit retrieves and completes only the remaining entry.
- **Lock and completion path:** extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSession.ts:1585 completes tracking once per toolCallId. src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts:673-747 queues per-resource streaming-edit locks and holds them until stopExternalEdits releases them. An overwritten tracking completion leaves its operation outstanding, so a subsequent write to that resource cannot acquire its lock.
