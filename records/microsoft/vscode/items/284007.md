## Evidence

- **Verified older canonical with the same symptom:** https://github.com/microsoft/vscode/issues/237774 is OPEN and was created on 2025-01-13, before this report. Its reproduction enters a search term, enables Find in Selection, then selects multiple lines: the widget reports one match and retains the old count after subsequent selection changes. It also reports the search widget modifying the editor selection. These are the same reporter-observable failures, not merely related find functionality.
- **Current source retains a changed scope:** src/vs/editor/contrib/find/browser/findWidget.ts:230-234 only updates the selection-toggle button on cursor selection changes; focusing the find input calls _updateSearchScope, which submits the current selection at lines 855-883. In src/vs/editor/contrib/find/browser/findState.ts:254-264, FindReplaceState.change treats a new range as unchanged when an existing range differs from it. For one cached match range and a newly selected multiline range, this comparison prevents updating searchScope, explaining why refocusing the find input still searches the cached match.
- **Reporter confirmation and unique evidence:** In https://github.com/microsoft/vscode/issues/284007, the reporter confirmed the problem on 1.107 and described the differently colored cached scope. A second commenter described the retained-search-string sequence on VSCodium 1.109.21026, where only one occurrence is found and clearing both inputs before reopening provides a workaround. These details should accompany consolidation.
- **Related report independently confirms the same behavior:** The reporter explicitly linked https://github.com/microsoft/vscode/issues/250617, which remains OPEN. Its maintainer-authored confirmation at https://github.com/microsoft/vscode/issues/250617#issuecomment-3712271358 describes the selection retained when Find in Selection is enabled and subsequent selections failing to change it.
- **Open implementation candidate, not a landed fix:** https://github.com/microsoft/vscode/pull/331038 is OPEN with no merge timestamp and explicitly fixes https://github.com/microsoft/vscode/issues/237774. It proposes correcting the inverted searchScope comparison. This supports reviewing the existing candidate under the canonical issue, not claiming this defect is already fixed.
