# Issue #17977 — Preserve undo/redo buffer when saving a file "as" or untitled file

[https://github.com/microsoft/vscode/issues/17977](https://github.com/microsoft/vscode/issues/17977)

## Summary

Preserving undo/redo across Save As remains an unmet capability on current main: the target receives the source text, not its edit history. This accepted request has 26 upvotes and maintainer support; the related serialization and restart-persistence issues do not replace it.

## Change summary

Preserve both undo and redo history when Save As changes a file's URI, including the first save of an untitled document.

## Best solution

Make the destination document retain the source's edit history and cursor-history position after a successful Save As. Establish safe semantics for existing destination histories and multi-document undo groups without changing ordinary saves or requiring disk-persistent undo.

- **Behavior:**

  > After Save As to a different URI, the destination retains the source document's undo and redo history at the same history position. In particular, undoing edits before Save As must not prevent redoing those edits afterward. This applies to an existing file and to the first save of an untitled document. Ordinary saves, cancellation, and failed Save As operations must preserve their existing behavior.
- **Trace:**

  > AbstractTextFileService.doSaveAsTextFile in src/vs/workbench/services/textfile/browser/textFileService.ts resolves a target model and transfers a text snapshot through ModelService.updateModel, without transferring edit-stack elements. ModelService's history restoration in src/vs/editor/common/services/modelService.ts is keyed to reopening the same resource. SingleModelEditStackElement and MultiModelEditStackElement in src/vs/editor/common/model/editStack.ts retain model/resource associations, while IUndoRedoService indexes histories by resource. The supplied maintainer discussion distinguishes history transplantation from createSnapshot/restoreSnapshot. The remaining uncertainty is the observable treatment of an existing destination history and grouped edits involving other documents. Keep restart persistence, decorations, tokenization cloning, and unrelated rename behavior outside this request.
- **Open decisions:**
  - When Save As overwrites a destination with its own edit history, should the source history replace that history, or should undo retain a transition back to the destination's previous contents?
  - When source history includes a multi-document edit, should undo from the saved destination retain the original cross-document grouping or operate only on the destination document?
