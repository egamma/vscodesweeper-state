# Issue #344674 — Webview documents are cancelled when the webview frame runs in its own renderer process (Blocked vscode-webview request)

[https://github.com/microsoft/vscode/issues/344674](https://github.com/microsoft/vscode/issues/344674)

## Summary

Keep open: current main still contains the reported process-ID restriction, and the reload/restart scenario and logs provide enough information to retest. The source confirms the cancellation condition, but not that Electron supplies the asserted frame in the affected Windows scenario; changing this request-admission boundary also requires human review.

## Change summary

Extension webviews can remain blank after reload when their document requests are rejected because the requesting frame uses a different renderer process.

## Best solution

Ensure legitimate webview document reloads work across renderer-process boundaries while preserving isolation from unauthorized embedded content. Confirm the requesting frame and its ownership on Windows before accepting any broader admission rule in src/vs/code/electron-main/app.ts.
