# Issue #344674 — Webview documents are cancelled when the webview frame runs in its own renderer process (Blocked vscode-webview request)

[https://github.com/microsoft/vscode/issues/344674](https://github.com/microsoft/vscode/issues/344674)

## Summary

Keep open: current main retains the process-ID restriction described in the report. The supplied reload scenario and logs suffice for retesting, but Electron's frame assignment and the claimed service-worker trigger remain unverified.

## Change summary

Webview document reloads can be cancelled when their requesting frame runs outside the main window's renderer process, leaving the view blank.

## Best solution

Establish which requesting frames legitimate webview reloads use, then support those loads in the main-process request filter while preserving its isolation guarantees. The proposed ancestor-based authorization needs human security review rather than acceptance solely because it removes the blocking symptom.
