# Issue #267396 — Ability to copy or export output of chat

[https://github.com/microsoft/vscode/issues/267396](https://github.com/microsoft/vscode/issues/267396)

## Summary

The underlying copy and export commands exist, but the requested discoverable toolbar or session-list entry remains absent. This team-authored request should stay open while the chat UX owners decide which visible surface should expose it.

## Change summary

Expose a discoverable action for copying or exporting an entire chat thread from the chat response toolbar or chat sessions UI.

## Best solution

Make whole-thread copy or export directly discoverable from an appropriate chat surface without overcrowding every response toolbar; the chat team should choose between the active-chat toolbar/menu and a per-session action in the sessions list.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts`
- **Validation:** Add or update chat action/menu tests to assert that the chosen visible surface exposes the whole-thread action for an eligible chat session while existing Copy, Copy All, and Export Chat command behavior remains available.
- **Behavior:**

  > Users can discover a direct action for copying or exporting the complete current chat without first knowing its Command Palette command or opening the content context menu. The action operates on the intended chat session and preserves the existing whole-thread output semantics. Existing per-message Copy, context-menu Copy All, and Command Palette export behavior remain available.
- **Trace:**

  > `workbench.action.chat.export` is registered in src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts as an F1 command without a menu contribution. `workbench.action.chat.copyAll` is registered in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts only for `MenuId.ChatContext`, while the response footer contains the per-message Copy action. Session-list actions use `MenuId.AgentSessionsContext` and `MenuId.AgentSessionItemToolbar` in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts. The boundary is discoverability and placement: do not redefine export formats or the contents copied by Copy All; those have separate follow-up issues, including https://github.com/microsoft/vscode/issues/276629.
- **Open decisions:**
  - Should the discoverable whole-thread action appear on the active chat surface, in each session's actions, or both?
  - Should the visible entry invoke Copy All, Export Chat, or present both operations in a submenu?

## Evidence

- **current command surface:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts registers `workbench.action.chat.export` with `f1: true` but no menu contribution, so Export Chat is available through the Command Palette rather than the requested visible surface.
- **current copy surface:** src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts registers `workbench.action.chat.copyAll` only in `MenuId.ChatContext`; the response footer exposes per-message Copy through `MenuId.ChatMessageFooter`, not whole-thread Copy All.
