# Issue #158433 — Option to prevent quickpicks from dismissing other quickpicks

[https://github.com/microsoft/vscode/issues/158433](https://github.com/microsoft/vscode/issues/158433)

## Summary

Keep open: current quick input still dismisses the preceding input, and no general opt-in protection was found. The launch-specific workaround does not satisfy this team-authored Backlog request; compatibility and arbitration semantics need a maintainer decision.

## Change summary

Allow independent concurrent workflows to request quick picks or input boxes without cancelling one another's pending user input.

## Best solution

Define an opt-in non-interrupting quick-input contract shared by core and extensions, preserving existing replacement behavior for callers that do not opt in. Resolve the public behavior before implementing it in the quick-input controller and extension API bridge.
