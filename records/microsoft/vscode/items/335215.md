# Issue #335215 — Agents window: external agent sessions are only discovered at startup; add refresh/rediscovery

[https://github.com/microsoft/vscode/issues/335215](https://github.com/microsoft/vscode/issues/335215)

## Summary

Traced this in src/vs/platform/agentHost/node/agentService.ts: external-session discovery for a provider only runs once at startup (via `_setupChatDiscoveryForProvider` -> `_startChatDiscovery` gated on `_runWhenStartupSettled`), or when the external-sessions mode transitions from fully-hidden to shown (line ~749). Once external sessions are already visible, further mode changes only call `_queueSessionListReconciliation`/`_reconcileExternalSessions`, which reconciles already-registered sessions but never re-scans the provider's on-disk catalog — matching the reporter's log evidence exactly (no repeated `discovery for provider` line). The existing `agentSessionsViewer.refresh` command (`RefreshAgentSessionsViewerAction` -> `control.refresh()` -> `agentSessionsService.model.resolve(undefined)`) also just re-resolves the model from already-known state, not a fresh discovery pass, so there is genuinely no way to surface a session created after launch short of restarting VS Code.

## Change summary

External agent sessions (e.g. a Claude Code CLI session started in a terminal) are discovered only once at Agent Host startup; sessions created afterward never appear until VS Code is restarted, and neither the External filter toggle nor the existing refresh button re-triggers discovery.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts, either wire the existing 'Refresh Agent Sessions' action to also invoke `_startChatDiscovery` for each registered provider (cheapest fix, matches the reporter's first ask), and/or add periodic or file-watcher-driven rediscovery of the known external session catalogs so sessions surface without a manual action.
