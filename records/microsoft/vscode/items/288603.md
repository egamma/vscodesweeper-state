## Evidence

- **Exact failing source path:** In src/vs/editor/contrib/linesOperations/browser/linesOperations.ts, AbstractCaseAction.run passes the selected text directly to SnakeCaseAction._modifyText. That method only inserts underscores at lower-to-upper and acronym boundaries before lowercasing. Neither regex matches 'hello-this-is-kebab-case', so editor.action.transformToSnakecase returns the original text unchanged.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/288817 is currently OPEN with mergedAt null and explicitly states 'Fixes #288603'. Its described changes add hyphen handling to SnakeCaseAction and a kebab-to-snake test. This is an existing contributor-owned implementation lane, not a completed fix.
- **Discussion and workaround:** The discussion at https://github.com/microsoft/vscode/issues/288603 identifies the linesOperations implementation and tests, and distinguishes the working TextMate snippet transform. Current src/vs/editor/contrib/snippet/browser/snippetParser.ts confirms that FormatString._toSnakeCase replaces whitespace and hyphens with underscores; this separate snippet path does not fix the command. The reporter also supplies kebab-to-camel-to-snake as a workaround.
- **Existing regression-test boundary:** src/vs/editor/contrib/linesOperations/test/browser/linesOperations.test.ts exercises SnakeCaseAction on camel case, acronyms, Unicode, existing underscores, and multiline source. Its multiline expected output preserves the hyphen in 'utf-8', so review of the linked PR should account for that existing punctuation behavior.
