# Issue #339955 — MCP migration writes `type: "local"` to workspace .mcp.json, which VS Code can't read, so the servers disappear

[https://github.com/microsoft/vscode/issues/339955](https://github.com/microsoft/vscode/issues/339955)

## Summary

Confirmed on main: the MCP migration writes `type: "local"` via `toCopilotMcpServerConfiguration`, but `normalizeMcpServerConfiguration` in pluginParsers.ts only recognizes `McpServerType.LOCAL` ('stdio') or untyped-with-command, not the literal string 'local', so migrated workspace servers are silently dropped. There is already an open fixing PR, so this should stay open pending that merge rather than close.

## Change summary

MCP server migration writes `.mcp.json` entries with `type: "local"`, which the workspace config reader doesn't recognize, causing migrated stdio servers to disappear from Customizations and agent sessions.

## Best solution

Land https://github.com/microsoft/vscode/pull/340034 (or an equivalent fix) so `parseWorkspaceRootMcpConfiguration`/`normalizeMcpServerConfiguration` maps the Copilot `'local'` type to `McpServerType.LOCAL` ('stdio'), matching what `fromCopilotMcpServerConfiguration` already does elsewhere.
