# Issue #339955 — MCP migration writes `type: "local"` to workspace .mcp.json, which VS Code can't read, so the servers disappear

[https://github.com/microsoft/vscode/issues/339955](https://github.com/microsoft/vscode/issues/339955)

## Summary

Confirmed on current main: the MCP migration writes Copilot's `type: "local"` format to workspace `.mcp.json` via `toCopilotMcpServerConfiguration`, but `parseWorkspaceRootMcpConfiguration` calls `normalizeMcpServerConfiguration` directly (not `fromCopilotMcpServerConfiguration`), so `local` isn't mapped to `stdio` and migrated servers vanish. An open PR (#340034) already targets exactly this fix, so this stays open pending that merge rather than closing or being assigned to an agent.

## Change summary

After migrating workspace MCP servers, the written `.mcp.json` uses `type: "local"`, which the workspace reader rejects, so migrated stdio servers disappear from Customizations and agent sessions.

## Best solution

Land https://github.com/microsoft/vscode/pull/340034 (and/or https://github.com/microsoft/vscode/pull/340181), which makes the workspace `.mcp.json` reader accept the Copilot `local` type the migration writes, restoring migrated servers.

## Evidence

- **enum mapping:** src/vs/platform/mcp/common/mcpPlatformTypes.ts defines `McpServerType.LOCAL = 'stdio'`, so a raw `type: 'local'` string doesn't match it.
- **migration writer:** src/vs/workbench/contrib/chat/browser/aiCustomization/mcpServerCustomizationMigration.ts:586 calls `toCopilotMcpServerConfiguration`, which (src/vs/platform/mcp/common/mcpCopilotConfiguration.ts:29-36) emits `type: 'local'` for stdio servers.
- **reader gap:** src/vs/platform/mcp/common/mcpWorkspaceConfiguration.ts:99 (`parseWorkspaceRootMcpConfiguration`) calls `normalizeMcpServerConfiguration` directly on raw JSON, skipping `fromCopilotMcpServerConfiguration` (mcpCopilotConfiguration.ts:49-54), which is the only place that remaps `type: 'local'` to `McpServerType.LOCAL`/'stdio' before normalizing — so the migrated entry is silently dropped.
- **open fix PR:** https://github.com/microsoft/vscode/pull/340034 ("mcp: read migrated local servers from workspace configuration") and a follow-up https://github.com/microsoft/vscode/pull/340181 are already open against this exact issue.
- **related tracking:** https://github.com/microsoft/vscode/issues/340179 tracks verifying backwards compatibility of migrated MCP servers with the local harness, consistent with this same root cause.
