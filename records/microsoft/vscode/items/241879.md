# Issue #241879 — `git.diagnosticsCommitHook.Sources` doesn't document valid keys

[https://github.com/microsoft/vscode/issues/241879](https://github.com/microsoft/vscode/issues/241879)

## Summary

Still valid on main: the setting description for `git.diagnosticsCommitHook.sources` does not explain that keys are diagnostic source names (the `Diagnostic.source` string, e.g. `"ts"`, `"eslint"`), not glob patterns. An open PR (https://github.com/microsoft/vscode/pull/312589) is already addressing this.

## Change summary

The `git.diagnosticsCommitHook.sources` setting description does not document that valid keys are diagnostic source names (e.g. `ts`, `eslint`), leading users to try glob patterns like `*.ts` which silently fail.

## Best solution

Land or iterate on the open PR https://github.com/microsoft/vscode/pull/312589, which clarifies the setting description. The fix is in `extensions/git/package.nls.json` — the description should state that keys are exact `Diagnostic.source` strings (or `*` for a wildcard) and give concrete examples like `"ts"`, `"eslint"`.
