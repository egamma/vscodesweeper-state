# Issue #195011 — Language specific settings for ipynb (jupyter-notebook) files [feature-request].

[https://github.com/microsoft/vscode/issues/195011](https://github.com/microsoft/vscode/issues/195011)

## Summary

Keep open: existing notebook settings cover final-newline insertion and most editor options, but not the full request for notebook-specific settings overrides. The remaining whitespace-setting gap is concrete, and the accepted Backlog request has 48 upvotes.

## Change summary

Allow notebook-specific settings without changing the settings for ordinary files using the same cell language.

## Best solution

Provide a coherent notebook-specific override mechanism that also covers save-time whitespace settings, preserving independent settings for ordinary files. Build on notebook.editorOptionsCustomizations and notebook.insertFinalNewline rather than treating the already-addressed newline regression as the entire request.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts`, `src/vs/workbench/contrib/notebook/browser/viewModel/cellEditorOptions.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts`, `src/vs/workbench/contrib/notebook/common/notebookCommon.ts`
- **Validation:** In one workspace containing a Python file and a Python notebook, verify independent notebook versus text-file line height, trailing-whitespace trimming, final-newline trimming, and final-newline insertion on explicit save and autosave. Check that existing notebook.editorOptionsCustomizations and notebook.insertFinalNewline configurations retain their behavior.
- **Behavior:**

  > Users should be able to configure notebook cells independently of ordinary files using the same language in the same workspace and profile. Existing notebook.editorOptionsCustomizations already covers most editor options, while notebook.insertFinalNewline handles the original newline-insertion problem. The remaining capability must also address notebook-specific save-time whitespace preferences. Acceptance includes independent behavior for a Python notebook and a .py file without switching profiles or changing their language identities.
- **Trace:**

  > Local codeCell.ts constructs CellEditorOptions using notebookEditor.getBaseCellEditorOptions(viewCell.language). The missing files were inspected through GitHub's read-only main-branch contents API: BaseCellEditorOptions._computeEditorOptions merges notebook.editorOptionsCustomizations editor.* entries over language settings, while notebook save participants read files.trimTrailingWhitespace and files.trimFinalNewlines directly and read notebook.insertFinalNewline separately. https://github.com/microsoft/vscode/pull/197671 deliberately addressed only final-newline insertion. Preserve those existing settings and ordinary text-editor behavior. The unresolved boundary is the public scope and precedence of a broader notebook override mechanism, not whether notebook-only lineHeight is already possible. https://github.com/microsoft/vscode/issues/35350 is related configuration work, but does not establish a duplicate for this notebook-specific report.
- **Open decisions:**
  - Should broader overrides apply to all notebook editors, or support separate notebook types such as Jupyter?
  - How should notebook-specific overrides interact with cell-language overrides and existing notebook.editorOptionsCustomizations and notebook.insertFinalNewline settings?
