- **Behavior:**

  > A diagnostic belonging to a deleted TypeScript file must not remain in the Problems view. Diagnostics for a transient TypeScript document must disappear when that document is disposed and must not reappear from obsolete results. Recheck the original deletion flow and externally removed merge-tool temporary files while preserving valid diagnostics for other files. Closing an editor tab must be distinguished from disposal of its backing document.
- **Trace:**

  > BufferSyncSupport.onDidCloseTextDocument calls closeResource, which removes pending work and fires onDelete; TypeScriptServiceClient subscribes and clears DiagnosticsManager's published and cached entries. Thus current source already implements a cleanup path, and the reported failure was not conclusively reproduced by inspection. Incoming diagnostics pass through asynchronous TypeScriptServiceClientHost.diagnosticsReceived and LanguageProvider.diagnosticsReceived into DiagnosticsManager.updateDiagnostics; their ordering relative to disposal is an investigation lead, not a proven race. Establish whether the failing document actually closes, whether cleanup receives the same resource identity, and whether diagnostics arrive afterward. Preserve legitimate project diagnostics and do not generalize the other-language comments into a shared root cause without evidence. https://github.com/microsoft/vscode/issues/201878#issuecomment-1881623825 confirms that restarting the server is not the intended solution.
