# Issue #182126 — TS problems stick around in problems view even after file is closed/deleted

[https://github.com/microsoft/vscode/issues/182126](https://github.com/microsoft/vscode/issues/182126)

## Summary

Still reproduces on main: when a tab is closed via the TabResourceTracker path, only pending diagnostic requests are cancelled — existing diagnostics in the DiagnosticCollection are not cleared. The deleteAllDiagnosticsInFile call only fires through onDidCloseTextDocument, which may not fire promptly (or at all for deleted files).

## Change summary

TypeScript diagnostics persist in the Problems panel after the associated file is closed or deleted.

## Best solution

In the TabResourceTracker.onDidChange handler (bufferSyncSupport.ts ~line 502), also call diagnosticsManager.deleteAllDiagnosticsInFile for each closed resource, not just delete from pendingDiagnostics. This ensures diagnostics are cleared from the Problems panel when a tab is closed, even if the underlying TextDocument isn't fully released yet.
