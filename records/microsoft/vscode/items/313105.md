# Issue #313105 — Agents: Recent project remains in new session dropdown after X

[https://github.com/microsoft/vscode/issues/313105](https://github.com/microsoft/vscode/issues/313105)

## Summary

Team-authored bug that appears to still reproduce on main — the workspace picker's dismiss (X) for recent projects does not persist across picker reopens. Keeping open per team-author policy.

## Change summary

Dismissing a recent project from the new-session workspace picker via the X button does not persist; the project reappears when the picker is reopened.

## Best solution

In `sessionWorkspacePicker.ts`, the `_removeVSCodeRecentWorkspace` path calls `removeRecentlyOpened` which should update the cache via `onDidChangeRecentlyOpened`, but the picker items are rebuilt from the refreshed `_vsCodeRecentFolderUris` each time. The fix likely needs to ensure the dismiss is reflected in the cached `_vsCodeRecentFolderUris` immediately (or that the async reload completes before the picker re-renders). The `_removeRecentWorkspace` (own-recents) path writes to storage synchronously and should persist — verify which path is hit for the reported scenario.
