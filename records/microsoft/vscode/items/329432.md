# Issue #329432 — fix: surface filtered LM responses as LanguageModelError (fixes #329425)

[https://github.com/microsoft/vscode/issues/329432](https://github.com/microsoft/vscode/issues/329432)

## Summary

Verified in current main: the `result.type !== ChatFetchResponseType.Success` block in `languageModelAccess.ts` has explicit branches for ExtensionBlocked/QuotaExceeded/RateLimited but none for Filtered/PromptFiltered, so those fall through to a generic `throw new Error(result.reason)` — matching the unhandlederror telemetry noise reported in the linked issue #329425. The fix is small, localized, and clearly scoped; no PR has landed yet (the linked branch on a fork never became an actual PR).

## Change summary

Filtered LM responses (RAI content filtering) throw a bare `Error` instead of a typed `vscode.LanguageModelError.Blocked`, producing unhandlederror telemetry noise.

## Best solution

Add explicit `Filtered`/`PromptFiltered` branches in the `result.type !== Success` block of `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`, throwing `vscode.LanguageModelError.Blocked(getFilteredMessage(result.category, false))`, consistent with the sibling ExtensionBlocked/QuotaExceeded/RateLimited branches — this removes the unhandlederror noise while still surfacing filtering to consuming extensions via the documented API.
