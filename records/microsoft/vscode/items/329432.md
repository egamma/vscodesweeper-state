# Issue #329432 — fix: surface filtered LM responses as LanguageModelError (fixes #329425)

[https://github.com/microsoft/vscode/issues/329432](https://github.com/microsoft/vscode/issues/329432)

## Summary

Confirmed on main: `CopilotLanguageModelWrapper._provideLanguageModelResponse` in languageModelAccess.ts has no branch for `ChatFetchResponseType.Filtered`/`PromptFiltered` and falls through to a bare `throw new Error(result.reason)`, unlike the sibling ExtensionBlocked/QuotaExceeded/RateLimited branches which throw typed `LanguageModelError`s — this is a real, well-scoped bug worth fixing.

## Change summary

Filtered LM responses (RAI content filtering) surface as a generic unhandled `Error` instead of a typed `vscode.LanguageModelError.Blocked`, producing extension-host telemetry noise.

## Best solution

Add explicit `Filtered`/`PromptFiltered` branches in the `result.type !== Success` block in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts, throwing `vscode.LanguageModelError.Blocked(getFilteredMessage(result.category, false))`, mirroring the existing ExtensionBlocked/QuotaExceeded handling.
