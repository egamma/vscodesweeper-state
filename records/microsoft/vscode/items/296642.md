# Issue #296642 — Different cloud and background options when delegating from local vs new empty chat

[https://github.com/microsoft/vscode/issues/296642](https://github.com/microsoft/vscode/issues/296642)

## Summary

Keep open: current main still deliberately hides the model and agent pickers while delegation is pending, and Copilot CLI handoff carries the source session's model rather than allowing a target-model choice. This team-authored issue remains the canonical discussion for that delegation parity gap.

## Change summary

Make target-specific options, especially model selection, consistent between a new agent session and delegation from an existing local chat.

## Best solution

Define a consistent handoff contract that lets users choose the target agent provider and an applicable target model before submitting, while keeping local-only agent controls hidden and treating MCP/tool configuration as separate provider-specific work.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/browser/actions/chatContinueInAction.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/delegationSessionPickerActionItem.test.ts`
- **Validation:** Add an input/delegation test that selects Copilot CLI as the pending target, chooses a model different from the source session model, submits the handoff, and asserts that the created target session receives the chosen target model while local-only agent controls remain absent.
- **Behavior:**

  > Delegating an existing local chat to Copilot CLI or another supported target should expose the target choices that are relevant to that target, including an applicable model picker. A user must be able to plan with one model and choose a different implementation model before submitting the handoff. Local-only custom-agent controls must remain hidden, and provider capabilities that do not exist must not be simulated. Acceptance should compare the new-session and delegation paths for the same target and verify that the selected target model reaches the created session.
- **Trace:**

  > The delegation target is stored by `ChatInputPart.setPendingDelegationTarget` in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts. In src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts, both `OpenModelPickerAction` and `OpenModePickerAction` are hidden whenever `ChatContextKeys.hasPendingDelegationTarget` is true. Submission then enters `SubmitAction.handleDelegation`, which invokes `CreateRemoteAgentJobAction`; for Copilot CLI, src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts currently seeds the imported session with the source widget's selected model. The boundary is delegation configuration: do not unify unrelated provider semantics, restore the local custom-agent picker for remote targets, or fold MCP/tool configuration into this work. https://github.com/microsoft/vscode/issues/300904 confirms that this issue owns the target-model requirement; https://github.com/microsoft/vscode/issues/291521 remains the broader visual-language discussion.
- **Open decisions:**
  - When the source and target both support models, should delegation default to the source model when compatible, the target's normal default, or require an explicit target-model choice?
  - Should the delegation UI expose only target model selection, or every target-specific control available in a newly created session, excluding the separately scoped MCP/tool configuration?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts registers the model and agent pickers with `ChatContextKeys.hasPendingDelegationTarget.negate()`, explicitly hiding both while a delegation target is pending.
- **handoff behavior:** src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts derives `importConversationModel` from `widget.input.selectedLanguageModel` and passes it into the Copilot CLI session, so current main carries the source model rather than exposing an independent target-model selection.
