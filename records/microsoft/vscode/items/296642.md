# Issue #296642 — Different cloud and background options when delegating from local vs new empty chat

[https://github.com/microsoft/vscode/issues/296642](https://github.com/microsoft/vscode/issues/296642)

## Summary

Keep open: current source still hides the model picker when a delegation target is pending, so creation and delegation do not offer equivalent target options. The author clarified that this flow-dependent difference is the concern; related issues do not own the same full scope.

## Change summary

Offer equivalent supported model and provider options when starting a new agent session directly or delegating an existing local conversation.

## Best solution

Make delegation expose the destination's supported configuration and carry those selections into the new session, without exposing irrelevant local-agent controls. Decide separately what tool configuration Copilot CLI supports; do not impose local per-tool semantics on Claude or compete with its existing delegation PR.

- **Behavior:**

  > Users should have the same supported destination configuration when creating an agent session directly or delegating a local conversation to that destination. Model selection must affect the destination session rather than merely changing the source conversation. Controls that belong only to the local agent must not appear as destination configuration. Tool configuration should reflect the destination's actual supported contract, not imply capabilities it lacks.
- **Trace:**

  > DelegationSessionPickerActionItem._run forwards the chosen provider to ChatInputPart.setPendingDelegationTarget, which sets the pending-target context key, locks the widget to the coding agent, and refreshes session pickers. OpenModelPickerAction explicitly hides its menu contribution in that pending state; OpenModePickerAction does the same, already addressing the reported irrelevant local-agent dropdown. ConfigureToolsAction requires an unlocked widget and operates on the local selectedToolsModel, so its absence is not resolved by exposing the existing action without establishing destination semantics. The model picker delegate and model configuration store also have source-session persistence behavior that must remain isolated from destination choices. The uncertainty starts at the supported tool-configuration contract and end-to-end delivery of destination selections, not at whether the model menu is currently hidden. Preserve provider capability distinctions and existing source-session state. https://github.com/microsoft/vscode/issues/300904 consolidates model-delegation demand here; Claude delegation remains separately owned by https://github.com/microsoft/vscode/issues/300531 and https://github.com/microsoft/vscode/pull/318232.
- **Open decisions:**
  - What supported tool-configuration contract should Copilot CLI expose consistently in both creation flows: individual tool selection, MCP-server selection, or no session-level tool control?
