# Issue #320749 — Git: detect newly added worktrees without requiring window reload

[https://github.com/microsoft/vscode/issues/320749](https://github.com/microsoft/vscode/issues/320749)

## Summary

Automatic worktree discovery still has a concrete failure on current main: stale administrative entries can exceed the discovery limit and permanently disconnect subsequent discovery. Route this to Git; the broader metadata-watching behavior also needs investigation.

## Change summary

Detect externally created Git worktrees in Source Control without reloading the window, including when stale worktree metadata is present.

## Best solution

Make enabled worktree discovery respond reliably to administrative metadata changes and remain functional after temporarily exceeding its limit. Preserve detection opt-in, discovery limits, intentional repository hiding, and watcher performance safeguards.

- **Behavior:**

  > With automatic worktree detection enabled, a worktree created externally should appear in Source Control Repositories without restarting Git or reloading the window. Existing detection opt-in, intentional hiding, and discovery limits remain respected.
- **Trace:**

  > Model.checkForWorktrees in extensions/git/src/model.ts uses Repository.worktrees and permanently disposes the shared onDidRunGitStatus listener when its count exceeds git.detectWorktreesLimit. Repository._updateModelState in extensions/git/src/repository.ts continues updating that list, but without the Model listener it does not trigger repository discovery. BaseRepository.getWorktreesFS in extensions/git/src/git.ts enumerates administrative entries without checking their referenced paths, confirming the failure described at https://github.com/microsoft/vscode/issues/320749#issuecomment-5014661871. Separately, DotGitWatcher watches the Git-directory first level through extensions/git/src/watch.ts and watches an upstream ref, but does not explicitly watch the worktrees metadata directory. The uncertainty is actual metadata-event delivery and sequencing across supported platforms, particularly when that directory already exists; establish that path and its regression harness before implementation. Do not broaden recursive watching of worktree contents, alter intentional Copilot-worktree hiding, or change default detection settings; https://github.com/microsoft/vscode/issues/305926 documents the performance concern with extensive worktree watching.
