# Issue #285587 — explorer.autoReveal false and focusNoScroll is broken.

[https://github.com/microsoft/vscode/issues/285587](https://github.com/microsoft/vscode/issues/285587)

## Summary

The `focusNoScroll` regression remains visible in current source: opening or focusing the Explorer can explicitly reveal the active item and change the scroll position despite the setting's contract. The reported `false` case is not explained by those paths and should be reproduced separately.

## Change summary

Opening the Explorer after restart scrolls to the active file even when `explorer.autoReveal` is disabled or set to `focusNoScroll`.

## Best solution

Ensure Explorer activation and focus preserve the existing tree scroll position for `focusNoScroll` while retaining active-file selection, and verify that `false` neither selects nor reveals the active file. Cover both modes with Explorer view regression tests without changing normal `true` behavior or explicit Reveal in Explorer commands.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/views/explorerView.ts`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`
- **Validation:** Add targeted ExplorerView tests that preserve `tree.scrollTop` when the view becomes visible or receives focus with `explorer.autoReveal` set to `focusNoScroll` or `false`, while asserting that `focusNoScroll` still selects the active file and existing `true` behavior still reveals it.
- **Behavior:**

  > With `explorer.autoReveal: focusNoScroll`, opening or focusing the Explorer may update selection to the active file but must preserve the user's tree scroll position. With `explorer.autoReveal: false`, it must preserve both the current selection behavior and scroll position rather than revealing the active file. Normal `true` behavior and explicit Reveal in Explorer commands must continue to scroll to their target.
- **Trace:**

  > The setting contract is registered in src/vs/workbench/contrib/files/browser/files.contribution.ts. In ExplorerView, the body-visibility callback calls `selectActiveFile(true)`, overriding `focusNoScroll`; `selectActiveFile` forwards that value through IExplorerService, and `selectResource` calls `tree.reveal` for `true`. ExplorerView.focus also checks `_autoReveal` only for truthiness, so the string `focusNoScroll` reaches another explicit `tree.reveal`. The `false` value bypasses both explicit reveals, so reproduce that branch and determine whether restored IAsyncDataTreeViewState, focus restoration, or another caller changes the scroll position. Keep explicit reveal commands and `autoReveal: true` outside the behavioral change. The original no-scroll contract is documented at https://github.com/microsoft/vscode/issues/23902.
