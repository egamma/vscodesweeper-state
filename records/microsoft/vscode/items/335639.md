# Issue #335639 — Microsoft authentication keeps using an expired refresh token after successful sign-in

[https://github.com/microsoft/vscode/issues/335639](https://github.com/microsoft/vscode/issues/335639)

## Summary

Well-documented bug with a matching open fix PR already filed by the reporter and assigned to a maintainer — this should stay open and be tracked via the linked PR, not closed.

## Change summary

MSAL's SilentFlow retries a rejected (invalid_grant) family refresh token indefinitely because the extension's cache persistence isn't updated on MSAL's in-memory removal of that token, even though a valid application refresh token exists for the same account — breaking recovery after Microsoft sign-in (e.g. Settings Sync staying signed out).

## Best solution

Review and land https://github.com/microsoft/vscode/pull/335641, which persists MSAL's in-memory token removal before a single silent retry in CachedPublicClientApplication.acquireTokenSilent (extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts); close this issue once that PR merges, citing its commit.
