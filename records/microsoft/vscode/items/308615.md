# Issue #308615 — Setting for update frequency

[https://github.com/microsoft/vscode/issues/308615](https://github.com/microsoft/vscode/issues/308615)

## Summary

Keep this accepted, well-supported request open: current settings do not provide a configurable update reminder interval. A maintainer has proposed a bounded reminder-period option rather than an LTS channel; its user-visible semantics still need agreement.

## Change summary

Allow users to reduce update interruptions with a configurable reminder or update cadence instead of being prompted for every release.

## Best solution

Develop the maintainer-proposed reminder-period control in the existing update infrastructure, retaining manual Check for Updates and explicitly deciding how security/recovery releases bypass deferral. Do not imply support for older release channels or expand this into an LTS commitment.

Run the targeted suites using scripts/test.sh once implementation is authorized; no tests or builds were run during this read-only review.
- **Behavior:**

  > Users want fewer update interruptions without disabling automatic updates indefinitely. A maintainer proposed a default or 2/3/4-week reminder period, with manual Check for Updates remaining available and possible exceptions for security/recovery releases. Acceptance must cover the selected timing semantics across restarts, unchanged default behavior, and the agreed critical-release exception. This must not imply that older versions receive extended servicing.
- **Trace:**

  > src/vs/platform/update/common/update.config.contribution.ts provides update.mode none/manual/start/default but no cadence setting. AbstractUpdateService.scheduleAccordingToMode and scheduleCheckForUpdates in src/vs/platform/update/electron-main/abstractUpdateService.ts govern startup and hourly automatic checks; checkForUpdates separately handles explicit checks and metered connections. UpdateTitleBarContribution.onStateChange in src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts exposes available updates without a configurable deferral, while its 30-day constant applies only to disabled-update reminders. The update.check command in src/vs/workbench/contrib/update/browser/update.ts invokes an explicit check. The proposed product boundary is recorded at https://github.com/microsoft/vscode/issues/308615#issuecomment-4808281226; uncertainty begins with what the reminder interval measures and whether it affects notification alone or update acquisition. Preserve existing update-mode and managed-policy behavior, and leave unrelated update stability bugs and release-channel changes outside this request.
- **Open decisions:**
  - Does the interval defer only update reminders, or also automatic checking, downloading, or installation?
  - Is the reminder interval measured from the last reminder, the last installed update, or availability of a new release, and do subsequent releases reset it?
  - Which security/recovery releases bypass the interval, and should that exception be mandatory?
