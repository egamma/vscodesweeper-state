# Issue #178184 — Difference in hover sequence results between run-time and test-time

[https://github.com/microsoft/vscode/issues/178184](https://github.com/microsoft/vscode/issues/178184)

## Summary

The ordering mismatch remains in current source: the hover command returns results in provider completion order, while the UI sorts them by provider priority. This explains the reported timing-dependent results without requiring a difference in the test runtime.

## Change summary

Make vscode.executeHoverProvider return hover results in the same provider-priority order used by the hover UI, independently of provider response timing.

## Best solution

Make the completed hover-command result deterministic and consistent with the UI's provider ordering, while preserving concurrent provider execution and incremental UI rendering. Cover providers resolving in reverse priority order with a regression test.
