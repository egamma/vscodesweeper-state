# Issue #308786 — [GitHub Copilot Chat] Allow flexible UI positioning: movable input box (top/bottom) and free-floating chat panel

[https://github.com/microsoft/vscode/issues/308786](https://github.com/microsoft/vscode/issues/308786)

## Summary

The detachable-window portion is already supported, but a maintainer confirmed that positioning the main Chat input at the top is not. The remaining request is a valid, source-confirmed UI preference that should stay open for product scoping.

## Change summary

Allow users to place the main Copilot Chat composer at either the top or bottom of the Chat surface.

## Best solution

Expose the existing top-input layout capability as a supported preference for the main Chat view, while preserving bottom placement as the default and defining how the preference applies to Chat editors and follow-up prompts.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/constants.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`
- **Validation:** Add a ChatWidget browser test that renders each supported preference and asserts the composer is ordered before or after the transcript as configured, then verify the default remains bottom-positioned.
- **Behavior:**

  > Users can choose whether the main Chat composer appears above or below the transcript, with bottom remaining the default. The selected placement must remain stable when switching sessions and resizing or moving the Chat view. Floating or detaching the Chat surface is already supported and is outside this remaining work. Acceptance includes verifying both placements and unchanged default behavior.
- **Trace:**

  > ChatWidget reads `IChatWidgetViewOptions.renderInputOnTop` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts and already has separate DOM-order branches; Quick Chat enables the top branch in widgetHosts/chatQuick.ts. The panel host in widgetHosts/viewPane/chatViewPane.ts and Chat editor host in widgetHosts/editor/chatEditor.ts currently omit that option, while chat.shared.contribution.ts registers no corresponding user preference. The top branch also does not append `ChatSuggestNextWidget` in the same way as the bottom branch, so follow-up placement is an observable design question. Keep detachable-window behavior out of scope because the maintainer confirmed it already exists.
- **Open decisions:**
  - Should the top/bottom preference affect only the panel Chat view requested here, or also Chat editors?
  - When the composer is at the top, should suggested follow-up prompts remain adjacent to the newest transcript response or move beside the composer?
