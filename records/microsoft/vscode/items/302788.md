# Issue #302788 — Cannot tell which file is which in VS Code File Comparison tool ("select for compare", "compare with selected")

[https://github.com/microsoft/vscode/issues/302788](https://github.com/microsoft/vscode/issues/302788)

## Summary

Keep open as a request for clearer per-side file identification. Current source provides a combined comparison title, not individual pane headers; the matching newer report cannot serve as this re-reviewed item's duplicate canonical.

## Change summary

Show an unmistakable file name or path above each side of an Explorer file comparison.

## Best solution

Provide restrained, readable file identification associated with each comparison pane, including enough path information to distinguish identically named files. Coordinate the product design with the existing per-side toolbar proposal without treating that broader design discussion as a verified duplicate.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/textDiffEditor.ts`, `src/vs/workbench/common/editor/diffEditorInput.ts`, `src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts`
- **Validation:** The plan should end with a runnable UI check: use Select for Compare and Compare with Selected on differently named files, then on identically named files in different directories; verify each side can be identified without inspecting contents or hovering. Repeat after swapping sides and at a narrow editor width, and verify existing editing and comparison behavior remains unchanged.
- **Behavior:**

  > Explorer comparisons currently require users to associate a combined title with the two panes. Users should be able to identify the file displayed on each side directly, without opening another editor or inspecting a changed line. Acceptance checks should cover different file names, identical names in different directories, and correct identity after swapping sides. Labels must remain understandable when available width is limited.
- **Trace:**

  > The comparison command in src/vs/workbench/contrib/files/browser/fileCommands.ts assigns the selected resource to original and the second resource to modified, so ordering is not the defect. DiffEditorInput.computeLabels in src/vs/workbench/common/editor/diffEditorInput.ts supplies combined names and titles. TextDiffEditor.createEditorControl creates DiffEditorWidget directly, whose original and modified containers have no per-file header in the inspected source. Preserve comparison ordering, editability, and diff computation. https://github.com/microsoft/vscode/issues/183758 proposes a broader per-side label/action surface for save conflicts; https://github.com/microsoft/vscode/issues/317967 corroborates this specific identification problem but is newer. The remaining uncertainty is the intended visibility and scope of the new identification surface, not the file mapping.
- **Open decisions:**
  - Should per-file identification be visible by default across ordinary text diff editors, or be limited to comparisons between distinct files such as the Explorer workflow?
  - Should this request introduce file-identification labels alone, or adopt the shared per-side label-and-action surface proposed in https://github.com/microsoft/vscode/issues/183758?
