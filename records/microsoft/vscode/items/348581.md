# Issue #348581 — Fast-exiting background tasks still lose diagnostics after completion

[https://github.com/microsoft/vscode/issues/348581](https://github.com/microsoft/vscode/issues/348581)

## Summary

Keep open: current source can mark diagnostics already delivered by the running background task for deletion during exit cleanup. The earlier fix waits for pending lines but does not prevent this remaining cleanup failure.

## Change summary

Preserve all collected diagnostics when a fast-exiting background task completes, including repeated runs.

## Best solution

Ensure background collector finalization retains diagnostics produced by the current run while still removing stale diagnostics from previous runs. Cover partially processed output and repeated execution using a real MarkerService.

## Evidence

- **Current-source cleanup defect:** src/vs/workbench/contrib/tasks/common/problemCollectors.ts:616-622 calls recordResourcesToClean for every owner before awaiting linesProcessed. recordResourcesToClean snapshots currently published markers, including diagnostics already delivered during this run. Only subsequently processed matches remove resources from that cleanup set; AbstractProblemCollector.done then reports markers and deletes the remaining cleanup resources.
- **Reported symptom follows the source:** WatchingProblemCollector.processLineInternal publishes qa-a.txt when processing switches to qa-b.txt. If done snapshots markers after that switch, qa-a.txt is scheduled for deletion although its current-run matches have already been processed. If both files are already published on a repeated run, finalization can remove both. The delivered-marker cache does not protect published resources from cleanAllMarkers.
- **Unterminated end-pattern path:** The reported output ends with End without a newline. src/vs/workbench/contrib/terminal/browser/xterm/lineDataEventAddon.ts emits normal lines on line feed and flushes the last line on disposal. src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1012-1018 removes its line listener before awaiting collector.done, so finalization must preserve diagnostics even without receiving the end pattern.
