# Issue #348581 — Fast-exiting background tasks still lose diagnostics after completion

[https://github.com/microsoft/vscode/issues/348581](https://github.com/microsoft/vscode/issues/348581)

## Summary

Keep open: current source still allows background-task completion cleanup to delete diagnostics published by that same run. The existing regression test does not detect marker removal.

## Change summary

Preserve all collected diagnostics when a fast-exiting background task completes, including repeated runs.

## Best solution

Make background collector finalization preserve the completed run's diagnostics while still removing obsolete diagnostics from earlier runs. Cover actual marker retention across completion and reruns with the real MarkerService.

## Evidence

- **Current source defect:** src/vs/workbench/contrib/tasks/common/problemCollectors.ts:616-621 records currently published resources for cleanup before awaiting linesProcessed(). If those resources' diagnostic lines have already been processed, they are not subsequently removed from the cleanup set. AbstractProblemCollector.done() then reports markers and calls cleanAllMarkers(), deleting those resources.
- **Completed-cycle failure:** WatchingProblemCollector.tryFinish() publishes the final resource and clears marker caches. If done() starts after that cycle finishes, it schedules the newly published resources for deletion, while the cleared caches contain nothing to restore. This provides a concrete path to all diagnostics disappearing.
- **Production call path:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:998-1018 queues terminal lines through processLine() and awaits watchingProblemMatcher.done() on process exit. Awaiting finalization does not prevent the cleanup-set defect inside done().
