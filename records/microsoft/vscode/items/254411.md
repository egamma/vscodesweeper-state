# Issue #254411 — Add setting to show tree view item icons without hover effect in Activity Bar

[https://github.com/microsoft/vscode/issues/254411](https://github.com/microsoft/vscode/issues/254411)

## Summary

Keep this accepted feature request open: custom tree-row actions still appear only on hover, selection, or focus, and existing visibility settings do not cover all tree items. The request has 22 upvotes and was explicitly promoted to Backlog; no qualifying canonical duplicate was identified.

## Change summary

Provide an option to keep tree-item inline action icons visible without hovering, selecting, or focusing each row.

## Best solution

Offer an opt-in visibility preference for custom tree-item inline actions while retaining the current reveal-on-interaction default. Settle the preference's scope so it remains consistent with existing header-action and Source Control settings.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/parts/views/treeView.ts`, `src/vs/workbench/browser/parts/views/media/views.css`
- **Validation:** In a custom TreeDataProvider view with multiple rows contributing inline actions, enable the agreed preference and move the pointer outside the tree: actions on unselected, unfocused rows must remain visible. Disable it and verify the current hover/selection/focus behavior returns. Check live preference changes, action invocation, keyboard navigation, narrow layouts, and horizontal scrolling.
- **Behavior:**

  > Users can opt into seeing available inline actions on tree items without hovering, selecting, or focusing those items. The existing reveal-on-interaction behavior remains the default. Enabling the preference must not change which commands are available or their invocation context, and disabling it restores current visibility behavior. Acceptance includes multiple inactive rows, keyboard access, and constrained tree layouts.
- **Trace:**

  > TreeRenderer.renderTemplate in src/vs/workbench/browser/parts/views/treeView.ts creates each item's .actions container and ActionBar; renderElement populates it using menus.getResourceActions([node]). src/vs/workbench/browser/parts/views/media/views.css currently hides these containers except on hovered, selected, or focused rows, with additional positioning rules for horizontal scrolling. workbench.view.alwaysShowHeaderActions controls view headers through ViewPane, while scm.alwaysShowActions is Source Control-specific, so neither covers this request. Preserve menu eligibility, action context, accessible labels, and the current default visibility behavior. https://github.com/microsoft/vscode/issues/254411 establishes demand for an optional always-visible mode; the remaining product choice is its scope and relationship to existing visibility preferences.
- **Open decisions:**
  - Should the preference apply uniformly to all custom tree views, or be selectable per view, and should Source Control continue to follow its separate scm.alwaysShowActions setting?
