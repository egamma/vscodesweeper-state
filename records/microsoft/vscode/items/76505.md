# Issue #76505 — [json] format on save should remove last trailing comma in JSON with json-language-features

[https://github.com/microsoft/vscode/issues/76505](https://github.com/microsoft/vscode/issues/76505)

## Summary

Keep this accepted Backlog request open: the built-in JSON formatting path still lacks comma repair. The older automatic-comma request concerns typing and completion, not the same format-on-save behavior, so it does not meet the stronger duplicate bar for this re-reviewed item.

## Change summary

Make built-in JSON formatting on save remove trailing commas and insert missing separators in otherwise recoverable JSON.

## Best solution

Provide a built-in, save-compatible way to repair unambiguous JSON comma errors while preserving comments and document content. The JSON owner should decide whether syntax repair belongs in formatting itself or an explicit fix-all save action, and establish the JSONC trailing-comma policy.

## Plan brief

- **Likely files:** `extensions/json-language-features/server/src/jsonServer.ts`, `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/package.json`
- **Validation:** In a writable implementation workspace, save the issue's exact malformed array with the built-in JSON provider and the selected save mechanism; verify the missing separator is inserted and the final trailing comma removed. Also check nested objects, comments, already-valid JSON, and JSONC trailing commas against the agreed policy, with automated coverage for the resulting edits.
- **Behavior:**

  > The reporter wants saving through built-in JSON support to repair missing separators and trailing commas, not merely adjust whitespace or report diagnostics. The supplied three-string array should retain all three values and become valid JSON with separators between values and no final trailing comma. Valid documents and comments must retain their content. Acceptance must include the exact issue example and the maintainer-selected behavior for JSONC.
- **Trace:**

  > In extensions/json-language-features/client/src/jsonClient.ts, updateFormatterRegistration forwards range-formatting requests to the server. In extensions/json-language-features/server/src/jsonServer.ts, onFormat delegates directly to languageService.format; the inspected code-action paths offer sorting and schema-related fixes, not comma repair. The language service formatter delegates to jsonc-parser, whose inspected formatter changes inter-token whitespace rather than comma tokens. Any implementation may therefore involve the language-service dependency as well as the built-in extension; its precise boundary is not yet established. Preserve existing comments, valid-document formatting, and unrelated syntax rather than extending this request into arbitrary malformed-JSON recovery. https://github.com/microsoft/vscode/issues/69545 is related typing/completion work, not a verified duplicate; https://github.com/zardoy/vscode-fix-all-json/issues/13 provides an external implementation lead.
- **Open decisions:**
  - Should ordinary Format Document and format-on-save repair syntax, or should comma repair require an explicit built-in fix-all action configured to run on save?
  - Should JSONC trailing commas be preserved when permitted by the document configuration, or should the selected repair behavior normalize them away?
