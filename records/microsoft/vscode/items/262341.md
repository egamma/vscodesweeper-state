# Issue #262341 — Update tool confirmation actions

[https://github.com/microsoft/vscode/issues/262341](https://github.com/microsoft/vscode/issues/262341)

## Summary

Keep open for UX design: current main has improved the original confirmation flow, but it still does not consistently provide the proposed discoverable approval scopes and collaborative rejection/steering behavior. This is also a team-authored Backlog request with maintainer support for further exploration, so a judgment close is barred.

## Change summary

Redesign chat tool-confirmation actions so approval scopes are discoverable and rejecting a tool can steer the agent toward another approach without ending the flow.

## Best solution

Use a consistent confirmation model across generic and terminal tools with an explicit one-shot approval, readily discoverable session/workspace approval choices, keyboard access, and a negative action whose steering semantics are clear without terminating the chat.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatToolConfirmationSubPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolConfirmationSubPart.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatToolActions.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatConfirmationWidget.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`
- **Validation:** Extend the chat confirmation widget/list-renderer tests to assert the agreed primary and secondary labels, dropdown scopes, keyboard actions, and resulting tool-confirmation reason; manually verify the same interaction for generic and terminal tool confirmations.
- **Behavior:**

  > Tool confirmations should make the immediate approval, remembered approval scopes, and rejection path understandable without requiring users to discover an unlabeled dropdown. Keyboard users must be able to reach the same actions. Rejecting a tool should follow the maintainer-selected steering behavior without unexpectedly terminating the overall chat flow. Generic and terminal confirmations should use consistent terminology except where their distinct approval capabilities require otherwise.
- **Trace:**

  > Generic confirmations are assembled by AbstractToolConfirmationSubPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts, with labels and approval options supplied by ToolConfirmationSubPart. Terminal confirmations have a separate button path in chatTerminalToolConfirmationSubPart.ts, and their scoped approval entries come from runInTerminalHelpers.ts. chatToolActions.ts defines the shared accept and skip commands and keyboard bindings. The existing Skip work tracked by https://github.com/microsoft/vscode/issues/259534 addresses continuing after rejection, but not this issue's broader discoverability and steering design. Preserve confirmation policy, risk messaging, and the meaning of existing stored approval scopes; the work is about the user-facing action model rather than weakening security boundaries.
- **Open decisions:**
  - Should the negative action immediately skip the tool and continue the agent, or focus the chat input and wait for explicit steering text before continuing?
  - Which remembered approval scope should be visible as a primary action, and which scopes should remain in the dropdown across generic and terminal tools?
  - Should the visible labels be uniform across all tool types, or may terminal confirmations retain specialized wording for command-specific approval rules?

## Evidence

- **current generic UI:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts builds a primary approval action plus a secondary “Skip” action and can promote a session-scoped approval, while chatToolConfirmationSubPart.ts labels the one-shot action “Allow Once”.
- **current terminal UI:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolConfirmationSubPart.ts still presents “Allow” and “Skip” with additional approvals in a dropdown; src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/runInTerminalHelpers.ts supplies session, workspace, and persistent approval choices.
