# Issue #151284 — Dragging terminals tabs should group and ungroup them

[https://github.com/microsoft/vscode/issues/151284](https://github.com/microsoft/vscode/issues/151284)

## Summary

The requested tab-list gestures remain missing: current drag-and-drop rearranges terminals or groups without joining or ungrouping them. The list-widget prerequisite is complete, but terminal-specific drop semantics still need agreement; this team-authored, accepted request should remain open.

## Change summary

Allow dragging terminal tabs onto other tabs to group them and dragging split terminals out of their group to ungroup them.

## Best solution

Define distinguishable tab-body and insertion-edge drop behaviors in the terminal tabs list so grouping and ungrouping coexist predictably with rearrangement. Preserve the existing keyboard and context-menu alternatives.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`, `src/vs/workbench/contrib/terminal/browser/terminalGroupService.ts`
- **Validation:** After agreeing on drop semantics, manually create two independent terminals, group them through a tab-body drop, extract one through the agreed outside-group gesture, and reorder intact groups through insertion-edge drops. Check that feedback predicts each result, existing join/unsplit commands remain functional, and file drops onto terminal tabs retain their current behavior.
- **Behavior:**

  > Users expect dragging one terminal tab onto another to show both terminals together in a split group, and dragging a split tab out of its group to make it independent. Today those gestures only rearrange instances or whole groups. The finished interaction must clearly distinguish grouping, extraction, and rearrangement before release of the mouse button. Acceptance includes preserving existing join/unsplit commands and unrelated file-drop behavior.
- **Trace:**

  > TerminalTabsDragAndDrop in src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts receives targetSector but ignores it in both feedback and drop execution. Local terminal drops reach TerminalGroupService.moveGroup or moveGroupToEnd; moveGroup preserves group membership, whereas separate joinInstances and unsplitInstance operations already exist. Shared list infrastructure exposes insertion effects and target sectors, corroborated by https://github.com/microsoft/vscode/issues/200745, so the infrastructure blocker is resolved. The uncertainty is the user-visible meaning of edge and outside-group drops, especially whether dragging one split extracts it or moves its entire group. https://github.com/microsoft/vscode/issues/192152 documents this ambiguity and was consolidated into the present issue. Keep scope on panel terminal-tab arrangement; preserve file drops, cross-window attachment, process lifetimes, and explicit grouping commands.
- **Open decisions:**
  - When a single split terminal is dropped between groups or into empty list space, should it become an independent terminal, or should its entire existing group move? How should users invoke the other operation?
