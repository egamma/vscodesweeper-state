## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/333503 is open and predates this report. Its reproduction explicitly describes an auxiliary window losing focus upon Alt release; subsequent modifier actions fail because focus has left the window. The reporter reaffirmed the behavior at https://github.com/microsoft/vscode/issues/333503#issuecomment-5479607269.
- **Shared current-source cause:** src/vs/base/browser/dom.ts:1912-2019 implements one ModifierKeyEmitter singleton that listens across registered windows. src/vs/base/browser/ui/menu/menubar.ts:118 subscribes the menu to that singleton; onModifierKeyToggled at lines 927-955 focuses the menu after an Alt press/release without checking the originating window. The FOCUSED branch at lines 734-754 directly focuses its menu button. This explains the auxiliary-window focus loss independently of Test Explorer.
- **Webview-specific entry path:** src/vs/workbench/contrib/webview/browser/webviewElement.ts:744-771 accepts authenticated keyboard events from the active webview and redispatches them on its owning window, feeding the same global modifier listener. The standalone Alt path is source-reproducible; the intermittent desktop Alt+Tab event ordering was not executed or independently confirmed.
- **Distinct evidence to preserve:** https://github.com/microsoft/vscode/issues/342368 supplies an extensions-disabled Markdown-preview reproduction on Ubuntu GNOME/X11, xprop timestamps showing activation moving to the main window, and window.customMenuBarAltFocus=false as a workaround. These extend the canonical's Windows report with another entry path into the shared focus defect.
- **Other linked reports:** https://github.com/microsoft/vscode/issues/54047 is closed and concerns historical Alt+Tab menu activation; https://github.com/microsoft/vscode/issues/306072 is closed and concerns dropdown dismissal in detached chat windows. Neither is an eligible open duplicate target.
