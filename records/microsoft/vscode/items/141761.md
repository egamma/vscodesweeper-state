# Issue #141761 — Some default shortcuts don't work with non-english layout: `cmd + .`, etc

[https://github.com/microsoft/vscode/issues/141761](https://github.com/microsoft/vscode/issues/141761)

## Summary

A real gap remains on current main: macOS/Linux mapping provides physical-key fallbacks for missing Latin letters but not punctuation such as period, brackets, or backquote. This issue should remain the focused discussion for missing-symbol fallbacks while the broader layout-specific keybinding design remains tracked separately.

## Change summary

Keep default punctuation-based shortcuts usable when a non-Latin keyboard layout does not produce the bound symbol from its usual physical key.

## Best solution

Make default punctuation shortcuts remain accessible on layouts that lack the bound character, while preserving layout-native shortcuts and user bindings when the character is available or a conflict exists. A maintainer should choose between conflict-aware missing-symbol fallbacks and layout-specific defaults before implementation.

- **Behavior:**

  > With a non-Latin input source active, default punctuation shortcuts remain reachable when that layout has no practical mapping for the bound character. Layouts that do produce the character through a different key or modifier retain their layout-native shortcut semantics, and explicit user bindings continue to take precedence. Acceptance should cover Quick Fix on period plus representative bracket and backquote bindings across Russian and existing Western-layout fixtures.
- **Trace:**

  > Default Quick Fix is registered with `KeyCode.Period` in src/vs/editor/contrib/codeAction/browser/codeActionCommands.ts. MacLinuxKeyboardMapper in src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts synthesizes scan-code mappings when Latin letters A–Z are absent, but not when punctuation is absent; the checked-in Russian fixture demonstrates that Period produces `ю` and has no period key-code mapping. The boundary is the cross-layout keybinding mapping behavior: do not globally reinterpret all punctuation as fixed physical keys because the maintainer examples show that German, French, and Dvorak users expect layout-derived bindings. https://github.com/microsoft/vscode/issues/1240 tracks the broader layout-specific-default mechanism, while https://github.com/microsoft/vscode/issues/151900 was consolidated here for the narrower missing-symbol fallback problem.
- **Open decisions:**
  - Should missing punctuation use conflict-aware physical-key fallbacks, or should this wait for layout-specific default keybindings from https://github.com/microsoft/vscode/issues/1240?
  - Which symbols qualify for fallback beyond period, brackets, and backquote, and how is a layout determined to lack a usable mapping?
  - When both a layout-derived binding and an English-position fallback could resolve, what precedence preserves user-defined and layout-native shortcuts?

## Evidence

- **current source gap:** src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts creates physical scan-code overrides only for missing Latin letters A–Z; it has no equivalent missing-symbol fallback for period, brackets, or backquote.
- **Russian mapping:** src/vs/workbench/services/keybinding/test/node/linux_ru.txt records the Period scan code as producing `ю`, with no `KeyCode.Period` combination, while dispatch remains `[Period]`; default `KeyCode.Period` bindings therefore do not resolve from that physical key.
- **default binding:** src/vs/editor/contrib/codeAction/browser/codeActionCommands.ts still registers Quick Fix as `KeyMod.CtrlCmd | KeyCode.Period`, so current main retains the reported mismatch.
- **maintainer assessment:** The maintainer discussion identifies two legitimate designs: missing-character physical-key fallbacks for layouts such as Russian, or keyboard-layout-specific defaults tracked by https://github.com/microsoft/vscode/issues/1240. It also explains why converting every binding to a physical scan code would break expected German, French, and Dvorak behavior.
- **canonical cluster:** https://github.com/microsoft/vscode/issues/151900 was consolidated into this issue by a maintainer because missing backquote on non-English layouts requires the same fallback decision. That makes this issue the focused canonical for missing punctuation rather than a disposable duplicate of the broader https://github.com/microsoft/vscode/issues/1240.
- **current confirmations:** Later comments report the same class of failure with Turkish, Brazilian ABNT2, and Russian layouts, including a 2026 macOS confirmation; the central problem remains active beyond the original example.
