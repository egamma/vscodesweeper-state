# Issue #321941 — Agents: Showing irrelevant changes when created a branch from non main branch

[https://github.com/microsoft/vscode/issues/321941](https://github.com/microsoft/vscode/issues/321941)

## Summary

A real gap remains: Agents compares an existing branch against the repository default branch when no session-specific baseline was persisted, and there is no user-facing override.

## Change summary

Allow an Agents session created from a non-default branch to use that branch as its Changes baseline.

## Best solution

Add a base-branch selector to the Agents Changes surface, persist the selection as `agentHost.diffBaseBranch`, and recompute branch changes and associated review operations from that baseline.

## Evidence

- **current baseline behavior:** `src/vs/platform/agentHost/node/agentHostGitService.ts` computes `baseBranchName` from `refs/remotes/origin/HEAD`, so a branch created from `release` is still compared with the default branch.
- **changeset resolution:** `src/vs/platform/agentHost/node/agentHostChangesetService.ts` uses persisted `agentHost.diffBaseBranch` metadata when available, otherwise falling back to the Git-state default branch.
- **missing override:** `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts` persists the baseline during managed worktree creation, but no configuration or command registration exposes an override for an already-existing branch.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/277255 concerns the agent's `get_changed_files` tool API, not the Agents window Changes baseline, so it does not absorb this UI/session requirement.
