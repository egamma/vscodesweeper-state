# Issue #321941 — Agents: Showing irrelevant changes when created a branch from non main branch

[https://github.com/microsoft/vscode/issues/321941](https://github.com/microsoft/vscode/issues/321941)

## Summary

Keep open: independent confirmations, including a recent maintainer reproduction, show unrelated integration-branch changes attributed to the session. Current source still falls back to the repository default branch; the related newer reports do not supersede this issue.

## Change summary

Agents Branch Changes uses the repository default branch instead of the intended non-default base, inflating change counts and causing expensive diff processing.

## Best solution

Make the Agents comparison baseline reflect the intended branch relationship and expose the effective comparison clearly. Settle precedence between the PR target, recorded branch point, tracking upstream, and an explicit override before changing shared base-resolution behavior.

- **Behavior:**

  > Opening a feature branch based on a non-default release or integration branch must not attribute that base branch's unrelated history to the session. A fresh branch with no additional edits should show no changes against its intended base; a stacked branch should show only its own changes. The effective baseline should be understandable and remain consistent across reopening the session. Acceptance must distinguish a branch's PR target from its same-name tracking upstream so publishing commits does not accidentally hide changes that the chosen comparison is intended to show.
- **Trace:**

  > AgentHostGitService._computeSessionGitState in src/vs/platform/agentHost/node/agentHostGitService.ts defaults the baseline to refs/remotes/origin/HEAD when no configured base is supplied. - **Open decisions:**
