# Issue #218248 — Dragging text upwards triggers scrolling far too early

[https://github.com/microsoft/vscode/issues/218248](https://github.com/microsoft/vscode/issues/218248)

## Summary

The issue remains necessary: current main still handles selected-text dragging through an API reveal path rather than the editor's dedicated edge-scrolling path, consistent with the demonstrated premature upward scrolling. No fixing commit, linked PR, or canonical issue owns this defect.

## Change summary

Dragging selected editor text upward starts scrolling while the pointer is still far from the top edge.

## Best solution

Make selected-text drag auto-scroll use the same viewport-edge threshold and directional behavior as ordinary mouse selection, without changing text-drop semantics or scrolling while the pointer remains safely inside the viewport.

- **Behavior:**

  > Dragging selected text within a long editor must not vertically scroll while the pointer remains well inside the viewport. Auto-scroll should begin only in equivalent edge regions at the top and bottom, with direction and speed based on distance from that edge. Moving versus modifier-copying the selected text and dropping within the original selection must retain their existing behavior.
- **Trace:**

  > MouseDownOperation._onMouseDownThenMove in src/vs/editor/browser/controller/mouseHandler.ts separates selected-text drag-and-drop from ordinary selection dragging: the former emits onMouseDrag, while the latter starts TopBottomDragScrolling for OUTSIDE_EDITOR targets. DragAndDropController._onEditorMouseDrag in src/vs/editor/contrib/dnd/browser/dnd.ts forwards the target to showAt, which calls ICodeEditor.revealPosition on every eligible move. CodeEditorWidget.revealPosition marks this as an API reveal, and ViewLines._computeScrollTopToRevealRange applies reveal padding independently of the pointer's edge distance. The issue video demonstrates the resulting early upward scroll. Preserve DragAndDropCommand behavior, modifier-copy semantics, horizontal dragging, ordinary selection auto-scroll, and non-empty drop-indicator rendering; uncertainty begins at reproducing the exact event-coordinate sequence and choosing a testable boundary between drag targeting and edge scrolling.
