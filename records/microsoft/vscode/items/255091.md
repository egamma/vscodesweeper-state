# Issue #255091 — Add option to exclude search with git submodules

[https://github.com/microsoft/vscode/issues/255091](https://github.com/microsoft/vscode/issues/255091)

## Summary

Keep this accepted Backlog request open: current search exclusions require explicit patterns or ignore-file entries and do not provide automatic exclusion of Git submodules. The request has 23 upvotes, and no verified canonical issue or landed implementation was found.

## Change summary

Allow users to exclude Git submodule contents from search automatically while retaining ordinary files alongside those submodules.

## Best solution

Provide an opt-in, submodule-aware search exclusion capability that preserves searches of neighboring first-party files without requiring a manually maintained path list. Settle its persistence and search-surface scope before implementation, keeping existing search behavior unchanged when disabled.

- **Behavior:**

  > Users can opt out of searching Git submodule contents without enumerating submodule paths manually. Submodules at unrelated depths are excluded while ordinary files under the same parent directories remain searchable. Existing explicit exclusions and ignore-file behavior remain effective, and searches retain their current behavior when the new capability is disabled. Acceptance uses a mixed-content repository to verify both exclusion and retention, plus the persistence and search surfaces chosen during planning.
- **Trace:**

  > Search configuration is registered in src/vs/workbench/contrib/search/browser/search.common.contribution.ts; QueryBuilder.getFolderQueryForRoot in src/vs/workbench/services/search/common/queryBuilder.ts combines configured exclusions with search-path exclusions. getRgArgs in src/vs/workbench/services/search/node/ripgrepTextSearchEngine.ts consumes those exclusions as negative globs, without submodule discovery in the inspected path. The Git extension already reads .gitmodules through Repository.getSubmodules and parseGitmodules in extensions/git/src/git.ts, with metadata exposed by RepositoryState.submodules in extensions/git/src/api/git.d.ts. The unresolved integration boundary is how that metadata becomes available to search, including when Git repositories have not been opened by the extension. Preserve existing defaults and do not substitute broad parent-directory exclusions. https://github.com/microsoft/vscode/issues/255091 owns this specific request; the older exclusion-negation and nested-settings reports do not absorb it.
- **Open decisions:**
  - Should the opt-in be a persistent workspace/resource setting, a per-search toggle, or both?
  - Should submodule exclusion affect only full-text Search, or also file search in Quick Open and other consumers of shared search configuration?
