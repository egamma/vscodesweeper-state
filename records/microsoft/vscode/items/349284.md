# Issue #349284 — **Feature Request: Add Confirmation Dialog Before Closing VS Code to Prevent Accidental Loss of Work**

[https://github.com/microsoft/vscode/issues/349284](https://github.com/microsoft/vscode/issues/349284)

## Summary

The existing window.confirmBeforeClose setting already provides the requested confirmation, including when clicking Close with all files saved.

## Change summary

Ask for confirmation before closing VS Code, regardless of whether files have unsaved changes.

## Best solution

Use "window.confirmBeforeClose": "always" to enable the existing confirmation rather than adding another dialog or setting.

## Vision fit

- **Fit:** aligned
- **Reason:** Preventing accidental window closure fits workbench UX, and the existing setting delivers it without additional UI.
- **Evidence:** Values: Simple, uniform UI and UI interactions. Durable theme: Workbench & core UX.

  > Thanks for the request. This is already available: set **Window: Confirm Before Close** to **always** in Settings, or add `"window.confirmBeforeClose": "always"` to your settings.json. VS Code will then ask for confirmation when you click the Close (X) button, even when all files are saved; Cancel keeps the window open.

## Evidence

- **Mouse-close behavior:** src/vs/workbench/electron-browser/window.ts:490–521 handles ShutdownReason.CLOSE. With window.confirmBeforeClose set to always, it requests confirmation without checking dirty files or requiring keyboard modifiers, and vetoes shutdown when confirmation is declined.
- **Existing dialog:** src/vs/workbench/browser/window.ts:205–229 implements confirmOnShutdown, asking whether to close the window or exit and returning the confirmation result. The setting is independent of unsaved-file protection.
