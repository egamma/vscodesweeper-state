# Issue #326138 — "Run C/C++ File" fails in PowerShell if path has spaces (missing & call operator)

[https://github.com/microsoft/vscode/issues/326138](https://github.com/microsoft/vscode/issues/326138)

## Summary

This is a bug in the C/C++ extension's (ms-vscode.cpptools) "Run C/C++ File" and debug-launch command construction, not in VS Code core — the cpptools extension ships and is maintained in its own repository (microsoft/vscode-cpptools), which has no presence in this checkout. Per the Microsoft-owned-extension convention, this should be moved to that tracker rather than closed and re-filed.

## Change summary

When running a compiled C/C++ binary via the cpptools 'Run C/C++ File' button in a PowerShell terminal, the extension sends the executable path as a bare quoted string instead of prefixing it with the PowerShell call operator (&), so PowerShell echoes the path instead of executing it when the path contains spaces.

## Best solution

Move this issue to microsoft/vscode-cpptools, where the 'Run C/C++ File' command-string construction (the run-without-debugging code path, as opposed to the debug launch path that already uses &) actually lives; a maintainer there needs to add the & operator when quoting paths for PowerShell shells.
