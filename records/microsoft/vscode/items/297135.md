[https://github.com/microsoft/vscode/issues/297135](https://github.com/microsoft/vscode/issues/297135)

## Change summary

Show elapsed billing-cycle progress alongside premium-request usage so users can judge whether their remaining allowance is on pace to last until reset.

## Best solution

Enhance the existing Premium requests quota indicator with an accessible representation of elapsed cycle time that remains visually distinct from request consumption and uses the quota's actual reset timestamp.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts`, `src/vs/workbench/contrib/chat/browser/chatStatus/media/chatStatus.css`, `src/vs/workbench/contrib/chat/test/browser/chatStatusDashboard.test.ts`
- **Validation:** Extend the chat status dashboard unit tests with fixed quota and reset timestamps, asserting that Premium requests exposes both the consumed percentage and the expected elapsed-cycle information while existing reset labels and other quota indicators remain unchanged.
- **Behavior:**

  > The Premium requests status communicates both allowance consumption and progress through the current billing cycle, using the quota's actual reset time when available. Users must be able to distinguish the two measures without relying on color alone, and assistive technology must receive equivalent localized text. Existing request counts, reset labels, hover/focus behavior, and non-premium quota indicators remain intact.
- **Trace:**

  > The Premium requests path is selected in ChatStatusDashboard.renderUsageContent in src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts and passed to createQuotaIndicator. That helper currently displays the used percentage, optionally swaps to used/total on hover or focus, and sizes a single `.quota-bit` from consumption; formatQuotaResetLabel separately exposes the reset date. Styling is in src/vs/workbench/contrib/chat/browser/chatStatus/media/chatStatus.css, with coverage in src/vs/workbench/contrib/chat/test/browser/chatStatusDashboard.test.ts. The boundary is the premium-request presentation: do not reinterpret quota accounting, alter billing state, or change unrelated chat/completions indicators. Related issue https://github.com/microsoft/vscode/issues/277684 proposed a more prescriptive color-coded version but is closed; https://github.com/microsoft/vscode/issues/252230 is a broader billing meta rather than a same-symptom canonical.
- **Open decisions:**
  - Should elapsed-cycle progress appear as a second visual marker within the existing bar or as adjacent textual information, so users cannot confuse time elapsed with requests consumed?
  - Should the comparison communicate only neutral elapsed time, or also provide an explicit on-pace/over-pace status without relying on color?
