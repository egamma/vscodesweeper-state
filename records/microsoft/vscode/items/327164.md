# Issue #327164 — Agents session disappears after switching away from a failed session with an active fork

[https://github.com/microsoft/vscode/issues/327164](https://github.com/microsoft/vscode/issues/327164)

## Summary

Well-diagnosed real bug confirmed in current-main source: `_aggregateChatSummaries` in agentHostStateManager.ts checks the error chat before the in-progress chat, contradicting the documented `NeedsInput > InProgress > other` precedence in SESSIONS.md, so a running peer/fork chat can't promote a session out of `Error` status. It's already correctly labeled and milestoned, so it stays open for a maintainer/PR to land the precedence fix.

## Change summary

When a session's default chat has errored but an actively-running forked/peer chat exists, the aggregated session status stays `Error` instead of promoting to `InProgress`, so the session vanishes from the sidebar once Failed sessions are filtered out and the user switches away.

## Best solution

Swap the precedence check in `_aggregateChatSummaries` (src/vs/platform/agentHost/node/agentHostStateManager.ts, lines ~1611-1620) to `InputNeeded > InProgress > Error` per SESSIONS.md, and add a regression test alongside the existing multi-chat aggregation tests in agentHostStateManager.test.ts covering an errored default chat with a running peer.
