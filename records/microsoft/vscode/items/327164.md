# Issue #327164 — Agents session disappears after switching away from a failed session with an active fork

[https://github.com/microsoft/vscode/issues/327164](https://github.com/microsoft/vscode/issues/327164)

## Summary

The defect remains source-reproducible on current main: session aggregation gives an errored chat precedence over a concurrently running peer, after which the Sessions list hides that session when it is no longer active. This team-authored Backlog bug should remain open for a focused status-aggregation fix and regression test.

## Change summary

Keep a session with an actively running fork visible and marked In Progress even when its default chat previously failed.

## Best solution

Make the aggregate session status follow the issue's accepted precedence of Input Needed, then In Progress, then Error, while preserving session metadata flags. Add coverage for an errored default chat with a peer transitioning through In Progress back to completion.
