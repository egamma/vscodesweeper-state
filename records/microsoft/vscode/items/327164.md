# Issue #327164 — Agents session disappears after switching away from a failed session with an active fork

[https://github.com/microsoft/vscode/issues/327164](https://github.com/microsoft/vscode/issues/327164)

## Summary

Confirmed against current main: the reported precedence bug is real and unfixed — this is a well-diagnosed, correctly-routed papercut that should just get the small precedence fix and a regression test.

## Change summary

When a session's default chat has errored but a peer/fork chat is actively running, the aggregate session status stays Error instead of promoting to InProgress, so the session vanishes from the Sessions sidebar as soon as the user navigates away while Failed sessions are filtered out.

## Best solution

Swap the precedence check order in `AgentHostStateManager._aggregateChatSummaries` (src/vs/platform/agentHost/node/agentHostStateManager.ts) to `InputNeeded > InProgress > Error`, matching the documented contract in src/vs/sessions/SESSIONS.md, and add a regression test mirroring the existing idle-default-chat peer test but with an errored default chat.
