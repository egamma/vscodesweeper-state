# Issue #326913 — Renderer killed by macOS kernel - "The window terminated unexpectedly (reason: 'killed', code: '9')"

[https://github.com/microsoft/vscode/issues/326913](https://github.com/microsoft/vscode/issues/326913)

## Summary

Well-diagnosed, actively-investigated bug: renderer windows are SIGKILLed by the macOS kernel due to Mach port-space exhaustion, confirmed independently by two users with kernel logs, minidumps, and live port traces; a VS Code collaborator is actively engaged and just asked for a fresh trace, so this should stay open pending that data.

## Change summary

On macOS (Tahoe 26+), VS Code renderer processes are periodically SIGKILLed by the kernel after their Mach port count bursts to the ~267k per-task cap, coinciding with macOS `memorystatus` idle-exit sweeps.

## Best solution

Keep open for the ongoing investigation in src/vs/platform Electron/IPC layer (likely a Mach port leak triggered by mojo/IPC reconnection during the OS idle-exit sweep); a related mach-port-exhaustion fix already landed in https://github.com/microsoft/vscode/pull/329210 for the integrated-browser/attachments path, but the second reporter's logs (comment from MartyHarris365) show this case does not involve the integrated browser, so a distinct root cause likely remains to be traced once the requested `--trace` capture comes back.
