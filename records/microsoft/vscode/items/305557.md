# Issue #305557 — Try New Default Themes resets after confirmation

[https://github.com/microsoft/vscode/issues/305557](https://github.com/microsoft/vscode/issues/305557)

## Summary

Keep open: current source contains a configuration-overwrite path that produces the reported dark-preview-to-light transition when automatic color-scheme detection is enabled and the system is light. The reporter's configuration is not confirmed, but the command's acceptance defect is traceable and no verified duplicate or fixing commit was found.

## Change summary

Accepting VS Code Dark in Try New Default Themes should retain the selected theme rather than switch to light.

## Best solution

Make acceptance preserve the selected theme using semantics consistent with Preferences: Color Theme, without undoing that selection through subsequent preferred-theme updates. Preserve cancellation restoration and existing automatic system-theme switching behavior.

- **Validation:** On a light system with window.autoDetectColorScheme enabled, run Try New Default Themes, preview the dark entry, and press Enter; the accepted theme must remain dark after configuration updates settle and after reload. Repeat with a dark system and the light entry, with automatic detection disabled, and with Escape to verify cancellation restoration. Establish an automated command-level regression test covering the acceptance and effective-setting result; the existing WorkbenchThemeService suite currently tests configuration helpers rather than this action.
- **Behavior:**

  > Try New Default Themes previews the highlighted theme, and Enter applies and persists the accepted choice rather than reverting it through later configuration writes. This holds when the selected theme differs from the detected system appearance. Escape restores the previous theme. Acceptance should remain consistent with Preferences: Color Theme, and normal subsequent system-appearance changes must retain their existing behavior.
- **Trace:**

  > The acceptance handler for workbench.action.tryNewDefaultThemes in src/vs/workbench/contrib/themes/browser/themes.contribution.ts first calls setColorTheme(theme, 'auto') and then writes both preferred theme defaults. ThemeConfiguration.getColorThemeSettingId in src/vs/workbench/services/themes/common/themeConfiguration.ts targets the current system scheme's preferred setting when detection is active, so accepting dark on a light system initially writes dark into the preferred-light key. The command subsequently overwrites that key with the default light theme, and WorkbenchThemeService.installConfigurationListener and restoreColorTheme apply the overwritten value. QuickPick.show in src/vs/platform/quickinput/browser/quickInput.ts populates selectedItems before Enter acceptance, ruling out the cancellation branch for that path. The acceptance and cancellation contract is documented in https://github.com/microsoft/vscode/issues/303489. The reporter's actual detection settings remain unknown, and no runtime reproduction was performed. Keep the scope within this command's persistence behavior; do not redesign host detection or ordinary theme-picker semantics. The existing WorkbenchThemeService tests expose configuration fakes but no command-level acceptance harness, so the planning session should establish that regression validation.
