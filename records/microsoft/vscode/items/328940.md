Team-authored bug report with a clearly identified root cause in the experimental Markdown editor's CSS (hidden fence markers still occupying inline layout); the referenced code (`packages/markdown-editor/src/view/editor.css`, `themes/vscode-default.css`) doesn't exist in this checkout — the in-tree `markdown-editor-src` prototype is much simpler and has no fence-marker logic yet — so this can't be verified against current main, and as a MEMBER-authored issue it's protected from judgment closes anyway.

## Change summary

In the experimental Markdown editor, short fenced code blocks reserve full four-line height even when only two lines are visible and fences are hidden, because hidden fence markers keep `display: inline` layout boxes plus 16px padding on all sides.

## Best solution

Once the `markdown-editor` package/paths cited in the report land in this repo, adjust the hidden-fence CSS so inactive short blocks size to their visible content rather than reserving space for both invisible fence lines, while still avoiding layout shift on activation where reasonably possible — likely a follow-up to the layout-stability work in #327538.
