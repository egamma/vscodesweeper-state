# Issue #327261 — Don't silently swallow "failed to delete" Worktree error

[https://github.com/microsoft/vscode/issues/327261](https://github.com/microsoft/vscode/issues/327261)

## Summary

Keep open: archive-time worktree removal failures still reach only the logs, and the existing management surface does not expose the failed cleanup. The author explicitly leaves the presentation choice open, so this needs a small product decision before implementation.

## Change summary

Make failed worktree removal after marking a session as Done visible to the user instead of discoverable only in output logs.

## Best solution

Expose the final cleanup failure with the affected worktree and useful diagnostic, while preserving existing archive and data-preservation semantics. Decide whether immediate notification, persistent management status, or both should carry that information.
