# Issue #86146 — Custom editor webviews should not be recreated on rename

[https://github.com/microsoft/vscode/issues/86146](https://github.com/microsoft/vscode/issues/86146)

## Summary

The proposed `customEditorMove` API exists and is wired up for CustomTextEditorProvider, but it remains un-finalized and the TODO notes it still needs to be extended to non-text CustomEditor. This issue is the canonical tracker for that work — keeping open.

## Change summary

Custom editor webviews are destroyed and recreated on file rename instead of being preserved, requiring a finalized API for extensions to opt into move handling.

## Best solution

Finalize the `customEditorMove` proposed API (currently in `src/vscode-dts/vscode.proposed.customEditorMove.d.ts`) and extend it to cover `CustomReadonlyEditorProvider`/`CustomEditorProvider` in addition to `CustomTextEditorProvider`. The plumbing in `mainThreadCustomEditors.ts` and `extHostCustomEditors.ts` already exists for the text variant.
