# Issue #86146 — Custom editor webviews should not be recreated on rename

[https://github.com/microsoft/vscode/issues/86146](https://github.com/microsoft/vscode/issues/86146)

## Summary

Keep open: this is an api-proposal tracking issue, and current source still exposes rename preservation only through a proposed CustomTextEditorProvider method, with general custom-editor support explicitly unfinished. Partial implementation does not complete the proposal.

## Change summary

Preserve custom-editor webviews and their transient state when the underlying file is renamed.

## Best solution

Have the API owners settle rename semantics for text-backed and custom-document editors, then complete and finalize the preservation API. Include the reported non-default-editor fallback in that assessment so preserving state does not silently switch editor types.
