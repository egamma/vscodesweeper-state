# Issue #339912 — Clicking the comparison group behaves differently than a session with sub sessions

[https://github.com/microsoft/vscode/issues/339912](https://github.com/microsoft/vscode/issues/339912)

## Summary

Team-authored UX observation about the Agents Window (sessions) comparison-group row: clicking the group selects the first participant in the list, which the author themselves flags as unintuitive and floats an alternative design for (making the parent/group row act as the judge/status indicator). This is an open design question raised by a maintainer, not a settled fix — hard keep-open rules apply regardless.

## Change summary

Clicking a session comparison group behaves inconsistently/unintuitively compared to a regular session with sub-sessions — it selects the first item in the list with no hover affordance, and the reporter suggests the group row might instead act purely as a 'judge/waiting on completion' indicator.

## Best solution

A maintainer should decide the intended comparison-group click/hover semantics (e.g., should the row itself be non-interactive and show aggregate status, or should it expand/select consistently with a normal session group) in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, then implement accordingly.
