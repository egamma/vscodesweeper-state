# Issue #278164 — Need better way to invoke MCP prompt

[https://github.com/microsoft/vscode/issues/278164](https://github.com/microsoft/vscode/issues/278164)

## Summary

The central request remains unimplemented: MCP prompt arguments are still collected outside the chat composer, and the resolved prompt is inserted without being submitted. The issue is correctly routed and should remain open; the older related requests cover different observable behavior.

## Change summary

Allow users to invoke an MCP prompt with inline named arguments and submit its resolved output directly from chat.

## Best solution

Provide a composer-native MCP prompt invocation flow that accepts arguments and can resolve and submit the resulting prompt without a separate Quick Pick interaction. Define the invocation syntax and submission behavior before implementation, while preserving the existing interactive argument workflow.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts`
- **Validation:** With a test MCP server exposing a prompt with a required string argument, invoke it from the composer with a value containing spaces and verify the server receives that exact value without a Quick Pick. Verify the agreed submission behavior, cancellation and resolution-error handling, and continued operation of the existing interactive argument picker.
- **Behavior:**

  > Users currently leave the composer to supply MCP prompt arguments and must separately submit the resolved prompt. The requested outcome is an explicit composer-native invocation containing named arguments that resolves the MCP prompt and submits its output. Acceptance should cover exact argument preservation, elimination of the external argument-entry steps for complete inline invocations, and exactly one submission under the agreed interaction.
- **Trace:**

  > The mcpPromptSlashCommands completion provider in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts invokes StartParameterizedPromptAction when a completion is accepted. That action collects values through McpPromptArgumentPick.createArgs(), calls prompt.resolve(), attaches returned resources, and replaces the composer text without submitting it. McpPromptArgumentPick in src/vs/workbench/contrib/mcp/browser/mcpPromptArgumentPick.ts supports text, command output, files, and server completions; preserve that existing interactive functionality. The trace establishes the current local workbench path, not support across other chat providers. https://github.com/microsoft/vscode/issues/251746 concerns completion presentation, while https://github.com/microsoft/vscode/issues/251747 concerns automatic context attachment; neither absorbs this request.
- **Open decisions:**
  - Should inline arguments use the proposed parenthesized named-argument syntax or another composer-native format, and what quoting and escaping contract should users rely on?
  - Should an explicit inline invocation resolve and submit on the user's initial Send action, or present the resolved output for confirmation before submission?
