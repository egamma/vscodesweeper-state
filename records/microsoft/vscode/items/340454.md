# Issue #340454 — Watermark keeps `Open Chat` after chat is disabled

[https://github.com/microsoft/vscode/issues/340454](https://github.com/microsoft/vscode/issues/340454)

## Summary

Confirmed in source: the empty-editor watermark only re-renders on its own setting or workbench-state change, never on context-key changes, and `cachedWhen` is checked before any live re-evaluation and only refreshed at shutdown — so `Open Chat` lingers after `chatSetupHidden`/`chatSetupDisabledInWorkspace` flip (e.g. via `chat.disableAIFeatures`).

## Change summary

The watermark keeps showing the `Open Chat` entry for the rest of the session after chat is disabled, because it never re-filters entries when the gating context key changes.

## Best solution

In EditorGroupWatermark, listen for onDidChangeContext (scoped to keys the current entries depend on) and re-render, and update cachedWhen from the live evaluation at that same moment instead of only at shutdown.
