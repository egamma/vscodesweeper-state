# Issue #336321 — Agents should not use the browser to work around authentication or tooling failures

[https://github.com/microsoft/vscode/issues/336321](https://github.com/microsoft/vscode/issues/336321)

## Summary

Legitimate, specific ask to harden the browser tool's prompt guidance so agents don't fall back to an authenticated browser session when a CLI/tool hits an auth or access failure — current tool descriptions (e.g. openBrowserTool.ts) have no such guardrail text, so the gap is real, but this is a prompt/policy change rather than a code defect, and no maintainer has weighed in on exact wording yet.

## Change summary

Add explicit system-prompt wording telling agents not to use the browser tool as a workaround when an intended CLI/tool fails due to authentication or access issues.

## Best solution

Add the suggested guardrail language to the browser tool's modelDescription (src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts and any related browser tools like navigateBrowserTool.ts/runPlaywrightCodeTool.ts) so the model is told to stop and ask the user rather than silently switching to an authenticated browser session; this is a prompt-wording decision best made by whoever owns agent tool prompts.
