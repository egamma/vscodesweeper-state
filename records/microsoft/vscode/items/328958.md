# Issue #328958 — Windows taskbar Jump List offers to pin `.code-workspace` entries as folders instead of workspace files

[https://github.com/microsoft/vscode/issues/328958](https://github.com/microsoft/vscode/issues/328958)

## Summary

Traced the Windows jump list code: `updateWindowsJumpList` in workspacesHistoryMainService.ts already builds `--file-uri` args for real `.code-workspace` entries (via `isRecentWorkspace`) versus `--folder-uri` for plain folders, so the reported 'pin opens the folder, not the workspace file' claim doesn't match current source. However, every jump list entry — folder or workspace — is hardcoded to `iconPath: 'explorer.exe' // simulate folder icon`, so workspace entries genuinely have no distinguishing icon, which is a real, verifiable rough edge and likely the actual root of the report.

## Change summary

On Windows, the taskbar jump list's 'Recent Folders & Workspaces' entries for `.code-workspace` files look and behave like folder entries instead of workspace entries.

## Best solution

The open action logic is already correct (uses `--file-uri` for workspaces); the real remaining gap is that `updateWindowsJumpList` (src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts, ~line 432) assigns the same `explorer.exe` icon to every entry regardless of type. Giving workspace entries a distinct icon (or at least confirming with the reporter that pinning truly opens the folder rather than just looking like one) would resolve the discrepancy; needs an owner in the Windows/OS-integration area to decide on an icon resource and re-test the actual pin behavior on Windows.
