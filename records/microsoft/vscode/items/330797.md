# Issue #330797 — Automatically add "copilot-terminal-output" folder to Copilot chat sandbox file access

[https://github.com/microsoft/vscode/issues/330797](https://github.com/microsoft/vscode/issues/330797)

## Summary

Real, traceable gap: the agent's own large-output feature writes to a cache-home folder that the terminal sandbox's read allow-list doesn't include, so the model gets blocked doing exactly what the tool told it to do. Worth routing to the sandbox/terminal area rather than closing.

## Change summary

Requests that the sandbox automatically allow read access to the `copilot-terminal-output` cache folder so the agent can inspect large tool output without a permission prompt.

## Best solution

Extend the sandbox's read allow-list (alongside the existing workspace-storage read root mechanism) to include `cacheHome/copilot-terminal-output`, so files written by LargeOutputFileWriter are always readable inside the sandbox.

## Evidence

- **output writer:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/largeOutputFileWriter.ts writes truncated tool output to `URI.joinPath(this._environmentService.cacheHome, 'copilot-terminal-output')` and tells the model to read it via readFile/grep.
- **sandbox read paths:** src/vs/platform/sandbox/common/terminalSandboxEngine.ts builds allow-read paths from _getSandboxRuntimeReadPaths(), _getWorkspaceStorageReadPaths() (workspaceStorageHome), and configured allow-lists (lines ~935-948); cacheHome/copilot-terminal-output is not one of these sources, so it falls outside the default allow list.
- **existing precedent:** terminalSandboxService.ts._resolveWorkspaceStorageReadRoot() already shows the pattern used to grant a non-workspace read root to the sandbox — the same approach could add the copilot-terminal-output cache folder.
