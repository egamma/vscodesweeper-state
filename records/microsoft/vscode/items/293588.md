# Issue #293588 — Feature request: Enhance the GitHub Copilot integration to allow users to spawn multiple simultaneous Chat/CLI instances directly into the editor area with automated, intelligent layout distribution.

[https://github.com/microsoft/vscode/issues/293588](https://github.com/microsoft/vscode/issues/293588)

## Summary

A real capability gap remains: VS Code can open individual Chat Editors and apply predefined editor layouts, but no command creates a requested number of independent sessions and distributes them automatically. No older open canonical owning this workflow was found, so the request should remain open for product and UX decisions.

## Change summary

Add commands and Chat-header UI for spawning multiple Chat or Copilot CLI sessions as editor tabs and arranging them into an appropriate editor-group layout.

## Best solution

Provide one coordinated multi-session action that creates distinct sessions and applies predictable layouts for common counts, while preserving existing editor content according to an explicit product policy. The design should also account for the multiple-Chat-Editor targeting problem tracked at https://github.com/microsoft/vscode/issues/308944.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts`, `src/vs/workbench/browser/parts/editor/editorActions.ts`, `src/vs/workbench/browser/parts/editor/editorCommands.ts`
- **Validation:** Exercise the resulting action with counts 2, 3, and 4 and verify that it creates that many distinct sessions, places each in the selected editor-group topology, and follows the chosen policy for pre-existing editor groups and editors.
- **Behavior:**

  > Users can request multiple independent Chat or Copilot CLI sessions from a command and an appropriate Chat-header entry point. Counts 2, 3, and 4 produce predictable side-by-side, asymmetric three-pane, and 2x2 arrangements respectively, with every pane hosting a distinct usable session. Existing editors and groups follow an explicitly chosen preservation policy rather than being displaced unpredictably. Creating multiple sessions must not change the behavior of the existing single-session New Chat actions.
- **Trace:**

  > Single Chat Editor creation is registered in src/vs/workbench/contrib/chat/browser/actions/chatActions.ts; `workbench.action.openChatToSide` creates one ChatEditorInput and opens it in SIDE_GROUP. The Chat view's New Chat split menu is assembled in src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts and likewise has no count-based entry. Predefined group topologies already exist independently in src/vs/workbench/browser/parts/editor/editorActions.ts and are applied through LAYOUT_EDITOR_GROUPS_COMMAND_ID in editorCommands.ts. No current action coordinates session creation with those layouts. Multiple existing Chat Editors also have a targeting defect tracked separately at https://github.com/microsoft/vscode/issues/308944; the plan should establish whether that must land first or be covered by the new workflow. Do not alter ordinary editor-layout commands or single-chat creation semantics.
- **Open decisions:**
  - Should the action replace and reflow the current editor-group layout, or preserve existing groups and add the requested Chat Editors around them?
  - Should the requested count always create the current/default session provider, or should users choose between standard Chat, local sessions, and Copilot CLI before creation?
  - Does the requested count include already-open Chat Editors, and what maximum count should the UI accept?

## Evidence

- **current chat capability:** src/vs/workbench/contrib/chat/browser/actions/chatActions.ts registers single-session actions such as `workbench.action.openChatToSide`; each invocation constructs one ChatEditorInput and calls IChatWidgetService.openSession for one editor group.
- **current layout capability:** src/vs/workbench/browser/parts/editor/editorActions.ts registers separate predefined layouts, including `workbench.action.editorLayoutTwoColumns`, `workbench.action.editorLayoutTwoRowsRight`, and `workbench.action.editorLayoutTwoByTwoGrid`, backed by `LAYOUT_EDITOR_GROUPS_COMMAND_ID`. No current action composes these layouts with creation of N chat sessions.
- **header surface:** src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts contributes the Chat view's split New Chat menu through MenuId.ChatNewMenu, but its actions create one session and expose no instance-count workflow.
