# Issue #117013 — [json] NPM package for vscode-json-languageserver not sync'd with VSCode releases

[https://github.com/microsoft/vscode/issues/117013](https://github.com/microsoft/vscode/issues/117013)

## Summary

The packaging gap remains on current main: VS Code still advertises the JSON language server as an installable npm package, but version 1.3.4 has not advanced since February 2021 despite continuing source and dependency changes. This older issue should remain the canonical place to decide the package's release and versioning model.

## Change summary

Publish maintained, versioned releases of vscode-json-languageserver in step with VS Code development, or extract it into a separately released project.

## Best solution

Define an owned release policy for vscode-json-languageserver, then automate versioning, packaging, smoke testing, and npm publication on that cadence while retaining traceability from each package version to its source revision.

## Plan brief

- **Likely files:** `extensions/json-language-features/server/package.json`, `extensions/json-language-features/server/README.md`
- **Validation:** The plan should end with a release-pipeline dry run that creates the npm tarball, installs it in a clean temporary project, launches its declared vscode-json-languageserver binary over a supported transport, and verifies that the published version maps to the intended source revision.
- **Behavior:**

  > External consumers can install a maintained vscode-json-languageserver release whose version and source revision are identifiable. Published releases include the server and dependency updates intended by the selected release policy, without requiring consumers to extract files from a VS Code checkout. The package's declared CLI entry point remains installable and runnable, and its documentation states the supported cadence and versioning contract.
- **Trace:**

  > The package is rooted at extensions/json-language-features/server/package.json and is still versioned 1.3.4; npm metadata shows that same version was published on 2021-02-22. The source package now depends on substantially newer language-service and LSP packages, while extensions/json-language-features/server/README.md continues to advertise npm installation for third-party editors. The package has a prepublishOnly compile hook, but repository searches found no automated npm publication path. https://github.com/microsoft/vscode/issues/321437 confirms the stale-package symptom remains visible in 2026 and should consolidate into this older issue. The uncertainty starts at the public release contract and ownership model; the plan must not assume that every VS Code build should become an npm release or that extraction into another repository is required.
- **Open decisions:**
  - Should vscode-json-languageserver follow stable VS Code releases, publish independently when server-facing changes land, or use another documented cadence?
  - What semantic-versioning contract should external consumers receive when VS Code-internal server code or its public dependencies change?
  - Should the package remain built from the VS Code monorepo, or move to a separately owned repository and release pipeline?

## Evidence

- **current package source:** extensions/json-language-features/server/package.json remains at version 1.3.4 while declaring current dependencies including vscode-json-languageservice ^6.0.0-next.4 and vscode-languageserver ^10.1.1.
- **published package:** npm metadata reports 1.3.4 as the latest vscode-json-languageserver version, published on 2021-02-22; no later package version exists.
- **documented public consumption:** extensions/json-language-features/server/README.md still instructs external consumers to install vscode-json-languageserver globally and use its command-line entry point.
- **missing automation:** Current repository searches find the server's prepublishOnly compile hook but no release workflow or npm publish step for this package.
