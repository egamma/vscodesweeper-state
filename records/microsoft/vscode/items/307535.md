## Change summary

A maximized Windows window retains its maximized state but fails to fill the screen after the display resolution increases.

## Best solution

Confirm the resolution-increase sequence on current Windows builds and isolate whether stale bounds originate in VS Code window handling or Electron. The finished behavior should keep a maximized window fitted to the updated display work area without requiring a restore/maximize cycle.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/native/electron-main/nativeHostMainService.ts`
- **Validation:** On Windows, set a lower display resolution, maximize VS Code, then increase that same display's resolution without restoring the window. Verify that the window remains maximized and fills the new work area, excluding the taskbar; compare native and custom title bars and an Electron minimal reproduction to establish ownership.
- **Behavior:**

  > A maximized VS Code window should continue filling the display work area when that display's resolution increases. The reported failure leaves the restore icon visible but retains a smaller window footprint. Acceptance is a Windows resolution-change check showing updated maximized bounds without manually restoring and maximizing again. Ordinary restored windows and existing monitor-reconnection behavior must remain unchanged.
- **Trace:**

  > BaseWindow in src/vs/platform/windows/electron-main/windowImpl.ts forwards Electron maximize/unmaximize events and applies initial maximization through BrowserWindow.maximize(). Its specialized display-added handling is gated by enableRDPDisplayTracking and reapplies saved maximized bounds for RDP reconnection; it does not prove coverage of metrics changes on an existing display. NativeHostMainService in src/vs/platform/native/electron-main/nativeHostMainService.ts publishes display-change notifications, but inspection has not established the origin of the reported stale native bounds. Begin with the report's Windows resolution-increase sequence; uncertainty starts at whether Electron updates the native maximized bounds correctly. https://github.com/microsoft/vscode/issues/202517 is a related mixed-monitor sleep report, not a confirmed canonical. Preserve restored-window sizing, fullscreen semantics, and RDP restoration; do not broaden this into general multi-monitor redesign.
