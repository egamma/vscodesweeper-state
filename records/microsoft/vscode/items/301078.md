# Issue #301078 — Include remote execution context in Copilot's <environment_info>

[https://github.com/microsoft/vscode/issues/301078](https://github.com/microsoft/vscode/issues/301078)

## Summary

Valid feature request: the Copilot prompt system includes OS name (via `IEnvService.OS`) but does not surface `IEnvService.remoteName` (which wraps `vscode.env.remoteName`) in the LLM context. The remote kind is already available in the extension's env service — it just isn't wired into the prompt templates. No duplicate found.

## Change summary

Request to include remote execution context (SSH, WSL, Dev Container, Codespaces, tunnel) in Copilot's prompt context so the LLM avoids suggesting GUI or desktop-only actions on headless remotes.

## Best solution

Extend the prompt templates in `extensions/copilot/src/extension/prompts/node/panel/` (at minimum `panelChatBasePrompt.tsx` and `vscode.tsx`) to include `envService.remoteName` alongside the existing OS line — e.g. 'The user is connected to a remote environment (ssh).' — so the model can avoid GUI-only suggestions. The data is already available via `IEnvService.remoteName`; only the prompt wiring is missing.
