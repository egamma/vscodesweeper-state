# Issue #297210 — Prompt files should allow me to select latest model with wildcard

[https://github.com/microsoft/vscode/issues/297210](https://github.com/microsoft/vscode/issues/297210)

## Summary

This remains an intentional backlog feature request: current main accepts only exact model display names, while the thread leaves the public selector syntax and category semantics open for design.

## Change summary

Allow prompt files to select the latest model in a family, such as Sonnet or Codex, without hardcoding a versioned display name.

## Best solution

Define stable prompt-file model selectors that survive model-version and display-name changes, while preserving exact qualified names and ordered fallback lists. The model owner should first choose between family aliases, wildcard syntax, and capability categories, including deterministic behavior when several available models match.

- **Behavior:**

  > A prompt file can name a stable model selector such as the latest Sonnet or Codex without embedding a versioned display name. The selector resolves deterministically among currently available, user-selectable models, and an ordered model list still falls back to its next entry when no model matches. Existing exact model names and vendor-qualified names retain their current behavior. Acceptance tests must cover catalog version changes, multiple matches, no match, and exact-name compatibility.
- **Trace:**

  > Prompt metadata is parsed as a string or ordered string array and reaches ChatWidget._applyPromptMetadata in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts. That method calls ChatInputPart.requestModelByQualifiedName, whose lookup in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts delegates to ILanguageModelChatMetadata.matchesQualifiedName in src/vs/workbench/contrib/chat/common/languageModels.ts; the matcher currently accepts only exact display names. Prompt validation and completion independently expose the same exact-name contract through promptValidator.ts and promptHeaderAutocompletion.ts. The experiment selector aliases in src/vs/workbench/contrib/chat/common/expPayload.ts are a separate matching path and do not provide prompt-header aliases. Preserve ordered fallback, user-selectability filtering, agent-mode suitability checks, and exact qualified-name compatibility; the uncertainty begins at the public selector vocabulary and how competing matches are ranked.
- **Open decisions:**
  - Should the public prompt-file contract use wildcard family patterns, stable provider-defined aliases such as sonnet/codex, capability categories such as fast/coding, or some supported combination?
  - When multiple available models match a selector, which user-observable ordering defines "latest" and how are preview variants treated?
  - Should aliases be globally defined by VS Code, supplied by each model provider, or scoped by vendor to avoid collisions?
