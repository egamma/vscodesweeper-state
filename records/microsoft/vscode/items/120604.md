# Issue #120604 — Allow app icon to be configured

[https://github.com/microsoft/vscode/issues/120604](https://github.com/microsoft/vscode/issues/120604)

## Summary

Keep open: choosing the native application icon remains distinct from existing icon-theme settings, and this accepted Backlog request has 106 upvotes. Related reports already direct users here; no verified open canonical or completed implementation was found.

## Change summary

Allow users to select the native application icon from a curated set, particularly to improve recognition in the macOS Dock.

## Best solution

Decide whether to offer a small, opt-in set of recognizable application icons, with selection preserved across updates. Establish the supported platforms and whether selection affects only the running application's Dock icon or also its installed application identity before implementation.

## Plan brief

- **Likely files:** `build/lib/electron.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/native/electron-main/nativeHostMainService.ts`, `src/vs/workbench/electron-browser/desktop.contribution.ts`
- **Validation:** After scope is agreed, manually select each supported icon and verify the intended native surface changes, persists through restart and an application update, and returns to the default when reset. Verify unsupported platforms and existing file/product icon themes remain unchanged.
- **Behavior:**

  > Users want to choose a recognizable native application icon from a curated set rather than repeatedly replacing installed resources. The macOS Dock is the central reported surface, with several commenters describing difficulty distinguishing its icon from other applications. Acceptance should establish that selection changes the agreed native surfaces, persists through restart and updates, and can be reset without changing file or product icon themes.
- **Trace:**

  > build/lib/electron.ts packages resources/darwin/code.icns as the macOS application icon. Searches found no Dock icon-selection path or corresponding contribution setting; existing icon-theme registrations in src/vs/workbench/services/themes/common/themeConfiguration.ts cover workbench icons instead. CodeWindow in src/vs/platform/windows/electron-main/windowImpl.ts selects a separate fixed icon for Windows Agents windows, demonstrating a native window-icon boundary but not the requested configurable application identity. Native host integration in src/vs/platform/native/electron-main/nativeHostMainService.ts and desktop settings in src/vs/workbench/electron-browser/desktop.contribution.ts are investigation entry points, not an established implementation boundary. https://github.com/microsoft/vscode/issues/120612 already consolidates the old-icon request here. Preserve the default brand, existing icon themes, and application grouping unless the maintainer explicitly expands scope; the Windows per-instance application-ID proposal is additional scope, not necessary to satisfy the original Dock request.
- **Open decisions:**
  - Should the first supported scope be macOS only, or should icon selection be available across desktop platforms?
  - Should selection change only the running application's Dock icon, or also the installed application's Finder and launcher icon?
  - Which curated alternatives should be offered, and should the selection apply installation-wide or separately to profiles or windows?
