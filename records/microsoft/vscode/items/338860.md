# Issue #338860 — Option to disable fallback to external LLM models

[https://github.com/microsoft/vscode/issues/338860](https://github.com/microsoft/vscode/issues/338860)

## Summary

Keep this request open: the inspected model-selection controls do not provide an enforced local-provider-only boundary, and the report raises a potential client-code exposure concern requiring human review. It is already correctly routed and remains within its backlog-candidate community-review window.

## Change summary

Provide an opt-out from automatic model fallback, ideally restricting Copilot requests to explicitly permitted local model providers.

## Best solution

Provide a fail-closed provider restriction that prevents requests from switching to an external model when the permitted local model is unavailable, with a clear unavailable-model message. The owner should define its enforcement scope across chat and auxiliary model requests; choosing a default or hiding picker entries must not be presented as a privacy guarantee.

- **Existing default is not a restriction:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.defaultModel as the starting model for new conversations, explicitly allowing subsequent switching. - **Fallback remains in current source:** In src/vs/workbench/contrib/chat/browser/widget/input/chatInputModelSelectionController.ts, reconcileModelListChange() calls selectDefault() when the current selection disappears without a matching replacement. _defaultModel() prefers the declared default, then a non-BYOK model.
