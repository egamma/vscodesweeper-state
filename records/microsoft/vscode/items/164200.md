# Issue #164200 — Splitting editor triggers two layouts of existing editor

[https://github.com/microsoft/vscode/issues/164200](https://github.com/microsoft/vscode/issues/164200)

## Summary

The redundant layout remains on current main: adding a view with distribute sizing first calls `relayout`, then `distributeViewSizes`, which calls `relayout` again. This accepted On Deck performance debt should remain open.

## Change summary

Avoid laying out existing editor views twice when splitting an editor group with distributed sizing.

## Best solution

Ensure a distributed add performs one layout using the final distributed sizes, while preserving sizing, visibility, priority, and layout behavior for all other split-view operations.
