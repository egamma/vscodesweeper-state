# Issue #164200 — Splitting editor triggers two layouts of existing editor

[https://github.com/microsoft/vscode/issues/164200](https://github.com/microsoft/vscode/issues/164200)

## Summary

Still present on main: the addView path with distribute sizing calls relayout() followed by distributeViewSizes(), triggering two layouts of the existing editor. No fix commit found.

## Change summary

Splitting an editor triggers two redundant layout calls on the original editor, the first with incorrect dimensions.

## Best solution

In src/vs/base/browser/ui/splitview/splitview.ts, skip the initial relayout() when the sizing type is 'distribute', since distributeViewSizes() will immediately redo the layout with correct sizes. The fix is localized to the addView method (~line 1212–1218).
