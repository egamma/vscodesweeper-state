## Summary

Real, traceable contrast issue rooted in the shared input.placeholderForeground token (50% opacity of foreground), and the predecessor issue already saw maintainer disagreement over the fix direction without a settled decision — keeping this open rather than closing it.

## Change summary

Placeholder text in the MCP elicitation "Enter Your Answer" input has contrast below the WCAG 1.4.3 4.5:1 threshold in Light and Dark (2026) themes.

## Best solution

A maintainer/accessibility owner needs to pick a direction: raise input.placeholderForeground contrast globally (affecting all inputs) or move the elicitation field to a persistent visible label instead of relying on placeholder text — the predecessor issue shows this tradeoff was debated but never resolved.

Acceptance: contrast measured against WCAG 1.4.3 passes in both themes via an automated contrast tool.
- **Trace:**

  > input.placeholderForeground is a single global token (src/vs/platform/theme/common/colors/inputColors.ts:48-50) defined as `transparent(foreground, 0.5)` for both Light and Dark — flat 50% opacity, which is why it often falls under 4.5:1. The elicitation input (chatElicitationContentPart.ts) uses standard input styling with no local override. The predecessor issue https://github.com/microsoft/vscode/issues/321135 already surfaced the core tension — increasing contrast may make placeholder text harder to distinguish from real input — and the team left it open as sev3 without resolving that tension. Do not change the token in isolation without addressing that concern; scope is the placeholder color token and/or elicitation-specific markup, not the whole input styling system.
- **Open decisions:**
  - Should contrast be raised globally on the input.placeholderForeground token, or should the elicitation field instead use a persistent visible label rather than relying on placeholder text?
