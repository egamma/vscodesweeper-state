# Issue #296100 — Allow specifying the agent type for hooks

[https://github.com/microsoft/vscode/issues/296100](https://github.com/microsoft/vscode/issues/296100)

## Summary

Valid feature request from a team member: hooks currently have no mechanism to filter by session/agent type (e.g. background vs local), so a SessionStart hook runs unconditionally. The capability does not exist on current main. Keeping open as a team-authored feature request.

## Change summary

Allow hook definitions to specify which agent/session types they apply to, so hooks like SessionStart can run only for background sessions or only for local sessions.

## Best solution

Extend the hook schema (in `hookSchema.ts` / `hookTypes.ts`) and the hook resolution pipeline to support an optional `sessionTypes` or `agentTypes` filter on each hook command entry, similar to how `sessionTypes` already works for contributed prompt files in `chatPromptFilesContribution.ts`. The filtering would be applied at hook collection time based on the current session's type.

## Vision fit

- **Reason:** Hooks are part of the agent customization surface, and making them configurable per session type directly supports the current agent-experience priorities.
- **Evidence:** Aligns with current agent host and harness priorities — hooks are a core part of the agent workflow, and session-type filtering improves the agent customization model.
