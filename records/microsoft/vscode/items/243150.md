# Issue #243150 — Improve `Select for Compare`

[https://github.com/microsoft/vscode/issues/243150](https://github.com/microsoft/vscode/issues/243150)

## Summary

A real diff-editor clarity gap remains: current main includes both parent paths, but separates them from the repeated filenames in a way that makes the left/right association difficult to scan. The issue already has appropriate UX, polish, and diff-editor routing and should remain open for a label-format design decision.

## Change summary

Make comparisons between same-named files clearly associate each file's parent path with its left or right diff side.

## Best solution

Give the diff tab a clear, compact hierarchy in which each same-named file remains visibly associated with its disambiguating path and side, while preserving useful truncation in narrow tabs.

## Plan brief

- **Likely files:** `src/vs/workbench/common/editor/diffEditorInput.ts`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`, `src/vs/workbench/test/browser/parts/editor/diffEditorInput.test.ts`
- **Validation:** Add focused editor-label tests for two resources with identical basenames and different parent directories, then verify in a component fixture or manual workbench check that each path remains unambiguously associated with its left or right side at both normal and constrained tab widths.
- **Behavior:**

  > When two files with the same basename are opened through Select for Compare, the diff tab must make it immediately clear which parent path belongs to the left side and which belongs to the right side. The ordering must remain consistent with the original and modified editors. Labels must remain useful when tab width is constrained, and comparisons with distinct filenames or explicitly supplied titles must retain their established behavior.
- **Trace:**

  > Select for Compare reaches COMPARE_RESOURCE_COMMAND_ID in src/vs/workbench/contrib/files/browser/fileCommands.ts and opens an untyped diff with original and modified resources. ResourceEditorInput in src/vs/workbench/common/editor/resourceEditorInput.ts exposes each basename as its name and each parent directory as its description. DiffEditorInput.computeLabels in src/vs/workbench/common/editor/diffEditorInput.ts combines the two names with `↔`, but combines the two paths separately with ` - ` after shortening, which leaves the left/right relationship visually indirect. MultiEditorTabsControl.computeTabLabels and shortenTabLabels in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts determine how the name and description are finally presented and truncated. Preserve original/modified ordering, explicit preferred labels, and unrelated duplicate-tab disambiguation. The uncertainty starts at the user-visible representation: whether each path is paired inline with its filename or the existing name/description hierarchy gains a clearer side association.
- **Open decisions:**
  - Should each side's path be paired inline with its filename, or should the existing tab name/description hierarchy be retained with a clearer visual association between each path and diff side?
  - Under constrained tab width, which information should remain visible first: both basenames, the distinguishing path segments, or one complete side label?

## Evidence

- **current compare path:** src/vs/workbench/contrib/files/browser/fileCommands.ts:200-228 opens Select for Compare results as raw `original` and `modified` resources without a custom title or description.
- **current label construction:** src/vs/workbench/common/editor/diffEditorInput.ts:77-149 renders identical basenames as `{name} ↔ {name}`, while the shortened parent directories are placed separately in the description as `{left path} - {right path}`. Both paths therefore exist, but their association with the two repeated names is only positional.
- **resource labels:** src/vs/workbench/common/editor/resourceEditorInput.ts:108-177 supplies the basename as the name and parent directories as short, medium, and long descriptions, confirming that current main has the information needed to disambiguate the files.
