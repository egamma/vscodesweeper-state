# Issue #39152 — Git - Support git subtree

[https://github.com/microsoft/vscode/issues/39152](https://github.com/microsoft/vscode/issues/39152)

## Summary

Keep this accepted feature request open: current Git commands still do not provide subtree add, pull, push, or subtree-aware synchronization. Its 88 upvotes support the existing Backlog placement, and no verified canonical absorbs the requested capability.

## Change summary

Expose Git subtree add, pull, and push operations and optionally synchronize configured subtrees when synchronizing the parent repository.

## Best solution

Provide subtree operations through the built-in Git experience, with explicit subtree targets and opt-in synchronization that preserves ordinary repository behavior. A maintainer should settle target persistence and synchronization semantics before implementation; the later merge-editor failure is separate work.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/git.ts`
- **Validation:** Use disposable local parent and upstream repositories to verify subtree add imports the selected prefix, pull incorporates an upstream change, and push exports subtree changes without unrelated parent files. Verify ordinary Git Sync remains unchanged with subtree synchronization disabled; with it enabled, verify the agreed target selection, ordering, and conflict/failure behavior. No execution was performed during this read-only review.
- **Behavior:**

  > Users want to add, pull, and push Git subtrees from the existing Git command experience rather than manually issuing each operation in a terminal. They also request an option to synchronize subtree repositories when synchronizing the parent repository. Acceptance should demonstrate correct prefix-specific imports and exports using local repositories, and unchanged parent-only synchronization when the option is disabled. Automatic synchronization must expose its targets and failures according to the maintainer-approved contract.
- **Trace:**

  > extensions/git/package.json declares the existing Git commands, but searches across extensions/git found no subtree command, setting, or implementation. Commands._sync and Commands.sync in extensions/git/src/commands.ts pass the current HEAD to Repository.sync; Repository._sync in extensions/git/src/repository.ts derives ordinary remote branch targets and performs pull followed by conditional push. The underlying Git execution layer is extensions/git/src/git.ts. The trace establishes the missing capability, but not how subtree prefix, remote, and branch associations should persist or how multiple subtree operations should interact with parent synchronization. Preserve existing ordinary Git and submodule behavior, and do not broaden the request to git-subrepo support merely because a commenter suggested it. https://github.com/microsoft/vscode/issues/262916 tracks a distinct merge-editor failure and is not an implementation or duplicate target for this request.
- **Open decisions:**
  - Should subtree prefix, remote, and branch targets be supplied for each operation, or persisted for reuse; if persisted, should they be shared with the repository or remain user-local?
  - For opt-in synchronization, which configured subtrees participate, in what order relative to the parent pull/push, and should a subtree conflict or failure stop all remaining synchronization?
