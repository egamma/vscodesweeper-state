# Issue #120370 — Can not select text in markdown cell

[https://github.com/microsoft/vscode/issues/120370](https://github.com/microsoft/vscode/issues/120370)

## Summary

Keep open: current source still makes rendered Markdown cells draggable and explicitly disables text selection under the default configuration. Disabling notebook drag-and-drop is a partial workaround, but the discussion reports additional selection/copy problems, and no verified older canonical or complete fix was found.

## Change summary

Allow users to select and copy text from rendered notebook Markdown cells without entering edit mode or inadvertently dragging the cell.

## Best solution

Provide a reliable selection-and-copy interaction for rendered Markdown in the notebook webview while retaining a discoverable way to move cells. A maintainer should settle whether text selection becomes the default within rendered content or requires an explicit modifier.

- **Behavior:**

  > Users need to select and copy part of a rendered notebook Markdown cell without entering edit mode. With notebook drag-and-drop enabled by default, dragging across its text currently initiates cell dragging rather than text selection. The chosen interaction must preserve the selection after mouse release and copy only the selected rendered text, including text in code blocks. Cell movement must remain available through the agreed drag interaction, and disabling drag-and-drop must continue to prevent cell reordering.
- **Trace:**

  > MarkupCell in src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts applies toggleDragDropEnabled to the whole preview element, adding both the draggable class and HTML draggable attribute. The generated stylesheet in src/vs/workbench/contrib/notebook/browser/view/renderers/backLayerWebView.ts explicitly sets user-select:none on that class, conclusively explaining the original default selection blocker without executing the application. MarkupCellDragManager in webviewPreloads.ts handles the resulting drag events, and cellDnd.ts supplies the surrounding notebook drag infrastructure. notebook.dragAndDropEnabled defaults to true in notebook.contribution.ts; false removes the preview's drag state but is only a partial workaround according to the thread. The later partial-selection clipboard complaints require a separate interaction trace before claiming they share the same cause. Preserve edit-mode behavior, ordinary cell selection, renderer support, and the existing drag-disable contract. https://github.com/microsoft/vscode/issues/201143 already consolidates its selection complaint here; https://github.com/microsoft/vscode/issues/242209 concerns a different clipboard-command error.
- **Open decisions:**
  - Should ordinary dragging across rendered Markdown select text, with cell movement reserved for a handle or margin, or should whole-preview cell dragging remain the default with a documented modifier for text selection?
