# Issue #336206 — Activity Bar container can remain pinned but invisible in a Remote-SSH workspace

[https://github.com/microsoft/vscode/issues/336206](https://github.com/microsoft/vscode/issues/336206)

## Summary

Filed by a team member with a precise, code-cited analysis; tracing the current source confirms the described gap between pinned and workspace-visible state, so this stays open for a maintainer to pick the reconciliation approach.

## Change summary

A view container can be pinned (profile-level) while its workspace-level `visible` state is false, and toggling pin/select does not restore visibility, leaving the Activity Bar icon permanently absent in that workspace.

## Best solution

Reconcile `pinned`/`visible` in src/vs/workbench/browser/parts/paneCompositeBar.ts and compositeBar.ts's `CompositeBar.pin()`/`CompositeBarModel.setPinned()` — either force `visible: true` when a container is (re)pinned, or explicitly reconcile stored `pinned: true` with workspace visibility for containers with active views; the exact semantics are a maintainer product call given the profile/workspace state split.
