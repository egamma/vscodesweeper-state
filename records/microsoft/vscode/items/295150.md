# Issue #295150 — Default model for compaction

[https://github.com/microsoft/vscode/issues/295150](https://github.com/microsoft/vscode/issues/295150)

## Summary

The requested model control remains absent on current main: foreground, manual, and background compaction use the active chat endpoint. This older re-reviewed issue should remain open as the canonical request; the same-scope https://github.com/microsoft/vscode/issues/320346 was filed later and cannot replace it as the duplicate target.

## Change summary

Add a configurable default language model for conversation compaction so summarization need not consume the active premium model.

## Best solution

Provide a dedicated model-picker setting for conversation compaction and apply it consistently to manual `/compact`, foreground overflow recovery, and background compaction. Preserve current behavior when unset, and define a safe fallback when the configured model cannot fit the conversation being summarized.

- **Behavior:**

  > Users can select a default language model for conversation compaction. The configured model is used consistently for explicit `/compact`, foreground overflow compaction, and background compaction, while leaving the setting unset preserves existing active-model behavior. Compaction must not silently lose conversation content when the configured model has a smaller context window than the conversation. Existing enablement and threshold settings continue to behave unchanged.
- **Trace:**

  > The active endpoint enters `AgentIntentInvocation` through `EditCodeIntent.invoke` in `extensions/copilot/src/extension/intents/node/editCodeIntent.ts`. In `extensions/copilot/src/extension/intents/node/agentIntent.ts`, foreground summarization creates `PromptRenderer` with `this.endpoint`, while `_startBackgroundSummarization` renders and sends directly through that same endpoint. `extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx` also bases prompt sizing, model-specific normalization, and the request on its endpoint prop. Core already has dynamic model-setting infrastructure in `src/vs/workbench/contrib/chat/browser/defaultModelContribution.ts`, with Plan and Explore agent examples nearby, but no compaction-specific setting exists. Keep the boundary to model selection and context compatibility: do not change summary contents, trigger thresholds, transcript persistence, or ordinary chat model selection. The related https://github.com/microsoft/vscode/issues/320346 is the newer same-symptom report and should be consolidated into this older request rather than replacing it.
- **Open decisions:**
  - When the configured compaction model cannot fit the conversation to be summarized, should VS Code fall back to the active model, automatically choose another compatible model, or stop with an actionable error?
