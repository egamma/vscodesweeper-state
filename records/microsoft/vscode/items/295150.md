# Issue #295150 — Default model for compaction

[https://github.com/microsoft/vscode/issues/295150](https://github.com/microsoft/vscode/issues/295150)

## Summary

A real gap remains: current compaction uses the active request endpoint rather than a configurable compaction model. The request is already accepted in the Backlog and needs a product decision about model selection and context-window compatibility.

## Change summary

Allow users to choose the default language model used for manual and automatic conversation compaction.

## Best solution

Provide an explicit, discoverable compaction-model policy, either by wiring compaction to `chat.utilityModel` or adding a dedicated setting. Define safe behavior when the configured model cannot accept the conversation's current context, without changing the model used for subsequent chat turns.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/agentIntent.ts`, `extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx`, `extensions/copilot/src/extension/intents/node/test/agentSummarizeCommand.spec.ts`, `extensions/copilot/src/extension/prompts/node/agent/test/summarization.spec.tsx`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/common/constants.ts`
- **Validation:** Add targeted compaction tests that configure a model distinct from the active chat model and assert the compaction request uses the configured endpoint, preserves the active model for the next turn, and follows the chosen behavior when the configured model's prompt budget is too small.
- **Behavior:**

  > Users can configure which model performs conversation compaction without changing the model selected for normal chat turns. Both explicit `/compact` and automatic compaction should follow the documented policy. The experience must handle a configured model whose context window cannot accommodate the pre-compaction conversation without silently dropping required context or switching subsequent chat turns.
- **Trace:**

  > `AgentIntent.handleSummarizeCommand` resolves the current request endpoint and supplies it to `SummarizedConversationHistory`. `ConversationHistorySummarizer.getSummary` then renders and submits the compaction request through that same endpoint; background compaction in `AgentIntent` likewise uses the active endpoint. VS Code already exposes `chat.utilityModel` and `chat.utilitySmallModel`, but this path does not resolve those utility families, so the existing settings are only a neighboring capability. Keep ordinary chat model selection and post-compaction continuation semantics unchanged. Related issues https://github.com/microsoft/vscode/issues/296038 and https://github.com/microsoft/vscode/issues/338298 describe distinct error and post-compaction behaviors rather than owning this request.
- **Open decisions:**
  - Should compaction use the existing `chat.utilityModel` setting or a dedicated compaction-model setting?
  - When the configured compaction model has a smaller usable context window than the conversation, should VS Code fall back to the active model, decline compaction with an actionable message, or use a documented staged strategy?
