# Issue #251187 — Re-think the Chat view welcome

[https://github.com/microsoft/vscode/issues/251187](https://github.com/microsoft/vscode/issues/251187)

## Summary

Keep this open as the active design discussion for Chat's empty state. Several phases shipped, but maintainers subsequently proposed a different hierarchy and identified an empty side-by-side state, so no merged change conclusively completes the broader request.

## Change summary

Redesign the agent-mode Chat welcome state so the input and useful session affordances lead while branding, explanatory copy, icons, and disclaimers recede.

## Best solution

Settle one cohesive empty-state hierarchy across stacked and side-by-side session layouts: the chat input should lead, recent sessions and concise guidance should support it, and required first-use disclosures should not dominate returning users. Once that direction is agreed, track any bounded implementation pieces separately and close this design umbrella manually.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chatViewWelcome.css`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsControl.ts`
- **Validation:** Manually open a fresh agent-mode Chat with zero and multiple prior sessions, with the sessions control stacked and positioned left/right, at narrow and wide widths; verify that the primary action remains clear, required disclosures remain available, and no supported layout produces an unexplained blank region.
- **Behavior:**

  > An empty agent-mode Chat should feel calm and focused: the user can immediately identify where to begin, while recent sessions and concise guidance remain discoverable without competing with the input. The experience must remain coherent for first-use and returning users and when the sessions control is stacked or positioned beside Chat. Required legal or AI disclosures must remain available without dominating the returning-user state.
- **Trace:**

  > The standard empty state is assembled by ChatWidget.getWelcomeViewContent in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts and rendered by ChatViewWelcomePart in src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts, with layout in src/vs/workbench/contrib/chat/browser/widget/media/chatViewWelcome.css. ChatViewPane in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts separately controls AgentSessionsControl visibility and orientation. PRs https://github.com/microsoft/vscode/pull/253689 and https://github.com/microsoft/vscode/pull/264255 delivered earlier phases, but commit 335383fa28c329c8a055367349bce6ab946dec71 later removed embedded history as sessions moved to the dedicated control. The uncertainty begins at the final product hierarchy: maintainers have proposed bottom-aligned content and keyboard hints, reported a blank side-by-side state, and have not settled how persistent welcome content and required disclosures should coexist. Preserve provider-specific local/background/cloud identity and do not fold the separate local-session clarity work from https://github.com/microsoft/vscode/issues/282697 into this redesign without an explicit scope decision.
- **Open decisions:**
  - After first use, should returning users see a compact New Chat welcome with guidance, or only the input and sessions except when no prior sessions exist?
  - Across stacked and side-by-side session layouts, which elements should lead and remain visible: the input, recent sessions, a New Chat heading, keyboard hints, or provider identity?
  - Where should required AI, telemetry, terms, and privacy disclosures appear so first-use obligations are met without making them permanent dominant welcome content?
