## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/290088 reports an error after Clone Repository → GitHub sign-in on Fedora 43 with Hyprland 0.53.1, including with extensions disabled. Its os_crypt log says 'Password storage detected desktop environment: (unknown)' despite XDG_CURRENT_DESKTOP and XDG_SESSION_DESKTOP being Hyprland.
- **Verified older canonical:** https://github.com/microsoft/vscode/issues/187338 is currently OPEN and was created on 2023-07-08, before this report. Its original report concerns failure to select an installed Linux keyring during GitHub authentication, and its discussion explicitly includes Hyprland configurations.
- **Exact symptom and maintainer ownership:** https://github.com/microsoft/vscode/issues/187436 describes Hyprland producing the identical 'Password storage detected desktop environment: (unknown)' log and missing-keyring notification. In https://github.com/microsoft/vscode/issues/187436#issuecomment-1631059471, a maintainer explicitly directs automatic desktop detection evidence to https://github.com/microsoft/vscode/issues/187338; https://github.com/microsoft/vscode/issues/187436#issuecomment-1631172821 confirms that tracker owns environment-specific detection work in Electron.
- **Hyprland evidence already collected:** https://github.com/microsoft/vscode/issues/187338#issuecomment-1631350328 reports Hyprland with KWallet and successful explicit password-store selection. https://github.com/microsoft/vscode/issues/187338#issuecomment-2981281764 reports Hyprland with successful gnome-libsecret selection. These cover the same automatic-selection failure, not merely a neighboring authentication problem.
- **Current source boundary:** src/vs/platform/encryption/electron-main/encryptionMainService.ts delegates encryption availability and backend selection to Electron safeStorage.isEncryptionAvailable() and getSelectedStorageBackend(). src/vs/workbench/services/secrets/electron-browser/secretStorageService.ts displays the missing-keyring message. src/mainImpl.ts supports an explicit password-store override, but that workaround does not implement automatic Hyprland detection. No fixed-on-main claim or runtime reproduction is made.
