# Issue #336072 — Cursor moves inconsistently

[https://github.com/microsoft/vscode/issues/336072](https://github.com/microsoft/vscode/issues/336072)

## Summary

The attached keybindings select different navigation modes for the two directions, explaining the inconsistent punctuation stops. This is intentional command behavior, not evidence that the bindings are incorrectly implemented.

## Change summary

Make Ctrl+Left and Ctrl+Right stop consistently at word boundaries.

## Best solution

Keep the existing command semantics and use cursorWordStartLeft alongside the reporter's cursorWordStartRight binding, including the corresponding selection commands. Explain that these navigate editor-defined word and separator starts, not every JavaScript regex \b match.

- **Proposed comment:**

  > Thanks for the report and the keybindings file. Your Ctrl+Right binding uses `cursorWordStartRight`, but Ctrl+Left still uses the default `cursorWordLeft`, which intentionally skips some single-character separators. To use matching word-start navigation, bind Ctrl+Left to `cursorWordStartLeft` and Ctrl+Shift+Left to `cursorWordStartLeftSelect`, using the same `when` condition as your right-arrow bindings.
  > 
  > These commands navigate editor-defined word and separator starts; they are not defined as stopping at every regex `\b` match, including word ends before whitespace. The difference shown by these bindings is expected behavior.

In src/vs/editor/common/cursor/cursorWordOperations.ts:224–241, WordStartFast explicitly skips a single separator followed by a regular character, whereas WordStart returns that separator's start. Thus moving left across punctuation can skip a stop that the customized right command retains.
