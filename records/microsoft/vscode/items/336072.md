# Issue #336072 — Cursor moves inconsistently

[https://github.com/microsoft/vscode/issues/336072](https://github.com/microsoft/vscode/issues/336072)

## Summary

This is intentional: on Windows/Linux, Ctrl+Right is bound to `cursorWordEndRight` (stops at word *end*) while Ctrl+Left is bound to `cursorWordStartLeft`/`cursorWordLeft` (stops at word *start*) — an asymmetric-by-design pair, not a bug in the word-boundary logic.

## Change summary

Ctrl+Right stops at every word boundary (`\b`) but Ctrl+Left only stops at boundaries followed by a word character (`\b\w`), which the reporter expects to be symmetric.

## Best solution

Keep the existing default keybindings — the asymmetry (`WordEnd` going right, `WordStart` going left) is intentional and matches common OS/editor navigation conventions; a user who wants symmetric-only word-start (or word-end) navigation in both directions can rebind Ctrl+Left/Ctrl+Right to `cursorWordEndLeft`/`cursorWordStartRight` explicitly.
