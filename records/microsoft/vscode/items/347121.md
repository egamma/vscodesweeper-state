## Evidence

- **Current extension-host defect:** src/vs/workbench/api/common/extHostCustomEditors.ts:543-551 awaits backupCustomDocument and unconditionally calls entry.updateBackup without checking cancellation. At lines 83-85, updateBackup deletes the retained backup before replacing it. Thus completing cancelled A after B deletes B and retains A.
- **Recovery metadata remains on B:** src/vs/workbench/api/browser/mainThreadCustomEditors.ts:960-980 cancels the previous pending operation and accepts backup metadata only for the current pending state. This protects metadata ownership but does not prevent the extension host from deleting B when A returns.
- **Reported reproduction:** https://github.com/microsoft/vscode/issues/347121 documents a scheduler-driven service-level reproduction at bc922197bf3432ed7ab3d21a8d3cd8fbbc3c79f8: persisted backup ID B, available backup A, deleted backup B. The traced current source independently supports that recovery-data-loss path; no tests were executed during this read-only review.
