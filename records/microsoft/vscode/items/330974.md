# Issue #330974 — Automations: automation created via chat may select unavailable model causing run failure

[https://github.com/microsoft/vscode/issues/330974](https://github.com/microsoft/vscode/issues/330974)

## Summary

Team-authored bug already correctly labeled `bug` + `automations`; source shows no validation of model availability when automations are created via chat, matching the report. Keeping open for the automations team to design the fix (picker restriction, fallback model, or creation-time warning).

## Change summary

Chat/agent-created automations can select a model that isn't available on the agent host, so the automation later fails to run.

## Best solution

In the automation creation flow (src/vs/workbench/contrib/chat/common/automations/automationService.ts / automationRunner.ts), either restrict the model picker to models known available on the target agent host, or validate/record a fallback modelId with a clear warning surfaced at creation time; related widget-input work in https://github.com/microsoft/vscode/issues/330701 may share root cause.
