# Issue #135234 — Bug of recognizing a JavaScript comment instead of URL

[https://github.com/microsoft/vscode/issues/135234](https://github.com/microsoft/vscode/issues/135234)

## Summary

Still present on main: the HTML grammar's inline JS embedding for event handler attributes incorrectly treats `://` inside JS string literals as a `//` comment start, causing URLs in onclick attributes to be mis-highlighted. A team member confirmed the root cause. The upstream TextMate HTML grammar hasn't fixed it either.

## Change summary

URLs containing `://` inside inline JavaScript in HTML event handlers (e.g. `onclick`) are incorrectly highlighted because the grammar treats `//` as a JS comment start even inside JS string literals.

## Best solution

Fix the event-handler JS embedding patterns in `extensions/html/syntaxes/html.tmLanguage.json` (or via the update-grammar script that patches the upstream TextMate grammar) so that `//` inside JS string literals within HTML attributes is not treated as a comment. Alternatively, file upstream at https://github.com/textmate/html.tmbundle and pull the fix.

## Evidence

- **member confirmation:** alexr00 (MEMBER) confirmed: 'Seems like an issue with how we include javascript within the html grammar.'
- **root cause in grammar:** In extensions/html/syntaxes/html.tmLanguage.json, the event-handler JS embedding has patterns that match `//` as comment.line.double-slash.js before checking whether the content is inside a JS string literal. The match pattern `([^\n"/]|/(?![/*]))+` followed by a `//` comment begin rule means `://` in a URL string triggers a false comment.
- **upstream grammar:** Grammar version is https://github.com/textmate/html.tmbundle/commit/0c3d5ee54de3a993f747f54186b73a4d2d3c44a2 — the upstream has the same issue.
- **no fix on main:** git log since 2021-10-01 on html.tmLanguage.json shows only one change (commit 45324363153, Dec 2022) which fixed a different issue (#160549). The event-handler comment detection patterns remain unchanged.
