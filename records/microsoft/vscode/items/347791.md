# Issue #347791 — Need terminal profile support for Copilot harness

[https://github.com/microsoft/vscode/issues/347791](https://github.com/microsoft/vscode/issues/347791)

## Summary

Keep open: existing Agent Host shell selection and initialization provide partial support, but do not deliver terminal-profile parity for project-specific environment variables and shell arguments in the Copilot harness.

## Change summary

Allow Copilot harness command execution to use configured terminal profiles, including project-specific environment and shell settings.

## Best solution

Provide supported terminal-profile semantics for Copilot shell execution, reusing existing profile configuration where appropriate. Preserve the distinction between selecting a shell executable, applying profile environment and arguments, and loading shell startup files.

## Evidence

- **Referenced feature has a different execution path:** https://github.com/microsoft/vscode/issues/253945 is closed and its discussion identifies chat.tools.terminal.terminalProfile.osx and https://github.com/microsoft/vscode/pull/265683 as support for the local agent's terminal tool. That does not establish equivalent support in the Copilot harness.
- **Existing shell selection is partial:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostTerminalContribution.ts resolves terminal.integrated.agentHostProfile.<os> with default-profile fallback, but _resolveDefaultShell returns only profile.path. Profile environment and arguments are not forwarded through this contribution.
- **Custom terminal override does not supply full profiles:** src/vs/platform/agentHost/common/copilotCliConfig.ts defines chat.agentHost.customTerminalTool.enabled as an opt-in override, disabled by default and unsupported on Windows. src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts enforces that platform restriction; AgentHostTerminalManager.createTerminal constructs its environment from process.env and generates shell arguments independently of the resolved terminal profile.
- **Initialization capability is not profile parity:** chat.agentHost.shellTool.initScript.enabled enables startup-file loading and selected Python-environment activation. src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostShellInitSynchronizer.ts and src/vs/platform/agentHost/common/shellInitScript.ts generate Bash or PowerShell initialization, but do not consume terminal-profile env or args; remote-development and Agents-window publication also have explicit restrictions.
- **Reporter workaround:** The author's supplied comment on https://github.com/microsoft/vscode/issues/347791 describes asking Copilot to load a project .env before execution. This is a manual workaround, not evidence that configured terminal profiles are honored.
- **Related items do not establish duplication:** The available discussion at https://github.com/microsoft/vscode/issues/289657 concerns Windows/WSL terminal selection; https://github.com/microsoft/vscode/issues/346123 requests broader execution control and observability. Neither establishes ownership of this precise profile-parity request. GitHub CLI access was unavailable and unauthenticated API searches were rate-limited, so no canonical duplicate was verified.
