# Issue #283144 — Quick question widget cannot be repositioned like other quick pick widgets

[https://github.com/microsoft/vscode/issues/283144](https://github.com/microsoft/vscode/issues/283144)

## Summary

Quick Chat still lacks the draggable surface available to ordinary quick pickers. Keep this maintainer-authored, accepted request open: the related discoverability issue addresses a different symptom, and the older Copilot request was explicitly consolidated here.

## Change summary

Allow users to drag and reposition Quick Chat, including near the bottom of the window, like other quick input widgets.

## Best solution

Give Quick Chat a usable repositioning affordance integrated with the shared quick input positioning behavior, while preserving text selection, chat actions, and height resizing. Plan the interaction contract for custom widget drag areas before implementing it.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/chatQuick.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Extend the quick input browser suite with a custom-widget drag interaction that changes position while excluded interactive elements remain usable. Manually open workbench.action.openQuickChat, drag the agreed affordance toward the bottom, submit a question, select response text, resize with the sash, and confirm ordinary command-palette dragging still works.
- **Behavior:**

  > Users can reposition Quick Chat by dragging, including placing it near the bottom to free space above. The interaction should be consistent with ordinary quick input positioning. Typing, selecting chat text, invoking toolbar actions, and resizing chat height must remain independent of repositioning. Acceptance includes moving the widget through the agreed drag affordance and retaining those existing interactions.
- **Trace:**

  > QuickChatService.open in src/vs/workbench/contrib/chat/browser/widgetHosts/chatQuick.ts embeds a custom container through IQuickWidget.widget. QuickWidget.update in src/vs/platform/quickinput/browser/quickInput.ts hides unused built-in chrome, while QuickInputDragAndDropController in src/vs/platform/quickinput/browser/quickInputController.ts accepts drag starts only from its fixed title-bar and header areas. IQuickWidget in src/vs/platform/quickinput/common/quickInput.ts has no custom drag-area contract. Existing top/center alignment commands provide partial placement but not the requested dragging interaction. Keep ordinary picker drag behavior, chat text interaction, and the height sash unchanged. The uncertainty is which user-visible part of Quick Chat should initiate dragging and how its accessibility counterpart should work. https://github.com/microsoft/vscode/issues/248391 concerns discoverability of existing picker dragging, not this missing capability; https://github.com/microsoft/vscode-copilot/issues/137 was consolidated into this issue.
- **Open decisions:**
  - Should Quick Chat expose a dedicated drag handle or header, or make existing noninteractive padding draggable?
  - What keyboard-accessible repositioning should accompany dragging: the existing top/center alignment actions, or additional placement options such as bottom alignment?
