# Issue #318754 — Notifications: Allow richer content formatting beyond plain text

[https://github.com/microsoft/vscode/issues/318754](https://github.com/microsoft/vscode/issues/318754)

## Summary

Keep open for notification design consideration: existing severity icons and progress bars cover part of the request, but inline text hierarchy and multi-step indicators remain unsupported. The verified older requests cover narrower capabilities, not this proposal's full scope.

## Change summary

Allow optional notification formatting with multi-step progress indicators, semantic icons or accents, and differentiated text styles.

## Best solution

Agree on a restrained, theme-consistent notification content model that improves hierarchy without allowing arbitrary styling or increasing distraction. Coordinate with the existing backtick and newline requests, preserving accessible textual equivalents for any visual indicators.

## Evidence

- **Existing capability and remaining gap:** src/vs/workbench/browser/parts/notifications/notificationsViewer.ts: NotificationTemplateRenderer.renderSeverity renders a standard severity icon, and renderProgress handles notification progress. NotificationMessageRenderer.render creates text nodes and links from message.linkedText.nodes, rather than bold/muted text or structured step indicators. These existing affordances partially address recognition but do not satisfy the full request.
- **Notification contract and settings:** src/vs/platform/notification/common/notification.ts documents literal message rendering with explicitly authored links; INotificationProgressProperties exposes infinite, total, and worked, not individual steps. Inspection of workbench *.contribution.ts registrations found notification positioning controls but no setting enabling the requested richer content.
