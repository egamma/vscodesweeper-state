# Issue #324531 — Uncommitted changes are in just "Changes view"

[https://github.com/microsoft/vscode/issues/324531](https://github.com/microsoft/vscode/issues/324531)

## Summary

Keep open for clarification of Changes-view terminology and review semantics in folder-based sessions. Current source explains why uncommitted files can appear in a reviewable branch changeset, but that does not resolve this team-authored UX concern.

## Change summary

Make the Changes view distinguish uncommitted working-tree changes from reviewable branch changes clearly when a session uses a folder rather than an isolated worktree.

## Best solution

Make the selected comparison scope and the meaning of Viewed clear in the Agents Changes view without implying that branch changes contain only committed files. The area owner should settle whether folder sessions need different defaults or clearer wording; the existing Uncommitted Changes selector addresses filtering but not the entire reported confusion.
