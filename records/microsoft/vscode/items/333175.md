# Issue #333175 — Remote agent host keeps running an old build after the server updates

[https://github.com/microsoft/vscode/issues/333175](https://github.com/microsoft/vscode/issues/333175)

## Summary

Well-diagnosed, filed today by a maintainer with concrete logs and code references confirming both defects on current main; no fix has landed yet, so this stays open for the agent host owners to act on.

## Change summary

On Remote-SSH, if the window/extension-host server build and the agent host server build diverge (same protocol version but different commit), the client connects to a stale agent host: it can throw instead of deferring migration, and if the old server folder was deleted it fails dynamic imports (e.g. `yazl`) while staying alive in a broken state, breaking chat and blocking Export Agent Host Debug Logs.

## Best solution

Two concrete follow-ups per the report: (1) have `cli/src/tunnels/agent_host_registry.rs` track the build commit (not just schema/protocol version/quality) and refuse to reuse a mismatched-commit host; (2) implement `restartAgentHost` in `editorRemoteAgentHostServiceClient.ts` (currently stubbed) so users can recover without SSHing in to kill the process by hand.
