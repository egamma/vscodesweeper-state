# Issue #333175 — Remote agent host keeps running an old build after the server updates

[https://github.com/microsoft/vscode/issues/333175](https://github.com/microsoft/vscode/issues/333175)

## Summary

Team-authored bug report (hard keep-open rule applies regardless), and it also holds up on inspection: the remote agent host endpoint registry has no build-commit tracking and the client-side `restartAgentHost()` is a genuine no-op stub for remote connections, exactly as described — this is a real, unfixed reliability gap in the agent-host lifecycle.

## Change summary

A remote SSH/tunnel session can end up talking to an agent host process launched from an old, since-deleted server build while the window/extension host runs the current build, causing connect failures, broken dynamic imports, unexportable debug logs, and no way to restart the stale host from the UI.

## Best solution

Two concrete follow-ups the report already scopes: (1) have `cli/src/tunnels/agent_host_registry.rs`'s endpoint entries record the build commit alongside `schema_version`/`protocol_version`/`quality` so a client refuses to reuse a host from an older commit; (2) implement `restartAgentHost()` in `src/vs/workbench/services/agentHost/browser/editorRemoteAgentHostServiceClient.ts` (currently a no-op stub) so a remote host can be restarted from the UI instead of requiring manual SSH intervention.
