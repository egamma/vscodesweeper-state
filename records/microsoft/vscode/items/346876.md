- **Same observable symptom:** Both reports lose the added workspace root from Explorer because its own ignore pattern matches its name. This report adds macOS 26.7.2, VS Code 1.145.2, disappearance on expansion, reappearance after reload, and partial visibility when opening a file; these refine the same defect rather than establish separate work.
- **Current source confirms root matching:** At checkout 89b3c5772fc17363e5458261c3326469420de5ec, FilesFilter.processIgnoreFile and filter in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts load .gitignore on traversal and trigger refiltering. isGitIgnored looks up the root's own IgnoreFile and passes the absolute root path without exempting the root. In src/vs/workbench/services/search/common/ignoreFile.ts, gitignoreLineToGlob converts foo to **/foo; parseIgnoreFile accepts equality with the ignore directory. The basename matcher in src/vs/base/common/glob.ts then matches /path/foo, excluding the root.

Its description addresses folders matching their own ignore patterns and states that workspace folders are never hidden. This is pending work, not evidence of a landed fix.
