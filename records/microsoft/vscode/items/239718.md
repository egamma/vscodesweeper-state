# Issue #239718 — Git - The .gitignore file does not respect exclusions when opening a remote repository

[https://github.com/microsoft/vscode/issues/239718](https://github.com/microsoft/vscode/issues/239718)

## Summary

The report is about a Remote Repository (vscode-vfs://github/) opened via 'Open Remote Repository', where `.gitignore` decoration/filtering is provided by the VS Code-team-owned GitHub Repositories extension, not by core — proposing a move to microsoft/vscode-remote-release rather than any close.

## Change summary

In a remote (virtual) GitHub repository, files re-included via `!` negation lines in `.gitignore` are still shown as ignored/excluded in the Explorer.

## Best solution

Move the issue to microsoft/vscode-remote-release so the GitHub Repositories (RemoteHub) owners can fix negation handling in the virtual-workspace ignore evaluation; if they determine core's ignore parsing is implicated, src/vs/workbench/services/search/common/ignoreFile.ts is where the `!`-handling hack lives and it can come back here.

## Evidence

- **no core gitignore decoration:** `rg ignoredResourceForeground src/vs` returns no matches — core has no gitignore-based file decoration provider. The greyed-out Explorer entries in the screenshot therefore come from an extension's FileDecorationProvider, not from the workbench.
- **built-in git extension cannot be the source here:** extensions/git/src/decorationProvider.ts (GitIgnoreDecorationProvider) obtains ignore state via `repository.checkIgnore(paths)`, i.e. the `git` CLI against a real on-disk repository. That path does not run for a `vscode-vfs://github/` virtual workspace, so the ignore state shown in a Remote Repository is produced by the GitHub Repositories (RemoteHub) extension.
- **owning tracker:** Remote Repositories / RemoteHub is a VS Code-team-owned extension tracked in microsoft/vscode-remote-release, so the correct handling is a transfer that preserves the thread, not a `*caused-by-extension` close.
- **core ignore parsing, for reference only:** src/vs/workbench/services/search/common/ignoreFile.ts handles `!` lines with an explicitly self-described "slight hack" (lines containing `!` are stripped and parsed as a separate include expression), and lines ending in `/` are excluded from the file-level pass. That code backs search and the opt-in `explorer.excludeGitIgnore` setting (off by default, and it hides rather than greys entries), so it does not explain this report — but it is the place to look if the remote-repositories owners trace it back to core.
- **verification limit:** The implicated extension source is not in this checkout and no reproduction against a virtual GitHub workspace was possible read-only, so the exact faulty matcher could not be pinpointed; the routing judgment rests on the core-side elimination above.
