# Issue #269748 — spawn xterm ENOENT

[https://github.com/microsoft/vscode/issues/269748](https://github.com/microsoft/vscode/issues/269748)

## Summary

Still reproduces on main: `LinuxExternalTerminalService.getDefaultTerminalLinuxReady()` uses `process.env.COLORTERM` (often `truecolor`) and `process.env.TERM` (often `xterm-256color`) as terminal executable names in the fallback chain, causing ENOENT when spawning. The fallback logic needs to validate that these env var values are actual executable programs, not capability descriptors.

## Change summary

Opening an external terminal on Linux fails with `spawn truecolor ENOENT` or `spawn xterm ENOENT` because environment variable values are used as executable names without validation.

## Best solution

Fix the fallback chain in `LinuxExternalTerminalService.getDefaultTerminalLinuxReady()` to not use `COLORTERM` as a terminal executable (it's a capability descriptor like `truecolor`, never a program name), and to validate `TERM` values with a `which`/`command -v` check before using them. The `COLORTERM` branch should likely be removed entirely from the fallback.
