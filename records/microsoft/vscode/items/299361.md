# Issue #299361 — Windows ZIP (Portable Mode): launching Code.exe with missing `data\` folder silently exits (no error/UI)

[https://github.com/microsoft/vscode/issues/299361](https://github.com/microsoft/vscode/issues/299361)

## Summary

The reported silent startup failure needs investigation, but a missing data folder intentionally selects normal, non-portable operation rather than preventing launch. Request current-build logs and an isolated user-data comparison before attributing the failure to portable-mode detection.

## Change summary

Launching the Windows ZIP build without a neighboring data folder reportedly exits silently, while creating that folder allows startup.

## Best solution

Preserve the ZIP build's ability to launch without portable mode and identify why normal startup fails on the reporter's machine. If a startup failure is confirmed, address its cause and missing diagnostic rather than automatically enabling portable mode.

## Evidence

- **Report and workaround:** https://github.com/microsoft/vscode/issues/299361 reports the failure on Windows 11 Home with versions 1.98.2 and 1.110.0, including with extensions disabled. Creating data changes the outcome, but no logs, independent confirmation, or current-build reproduction are provided.
- **Portable-mode detection:** src/bootstrap-node.ts, configurePortable(), enables portable mode only when the portable data path exists and the product has no target field. Otherwise it deletes VSCODE_PORTABLE and returns isPortable: false; there is no missing-data exit in this path.
- **Normal startup path:** src/mainImpl.ts calls configurePortable(), then getUserDataPath(), and sets Electron's userData path. In src/vs/platform/environment/node/userDataPath.ts, absence of VSCODE_PORTABLE selects VSCODE_APPDATA, an explicit --user-data-dir, or the normal Windows application-data location. Creating data therefore changes the profile location as well as portable-mode status; the workaround alone does not establish the root cause.
- **Documented behavior:** https://code.visualstudio.com/docs/setup/portable documents creating data as the step that enables portable mode, not as a prerequisite for launching a Windows ZIP distribution.
- **Canonical search:** Read the open candidates https://github.com/microsoft/vscode/issues/200202 and https://github.com/microsoft/vscode/issues/122951: they concern a logged renderer launch failure and sandboxed webview failures, respectively, without evidence connecting them to this report. Also read https://github.com/microsoft/vscode/issues/232894, which concerns portable mode being ignored despite an existing data folder. Searches for portable/data and ZIP/startup reports did not establish a canonical owning this specific failure.
