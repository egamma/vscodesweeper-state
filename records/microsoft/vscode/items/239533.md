# Issue #239533 — Allow controlling default stop/disconnect when using debugger

[https://github.com/microsoft/vscode/issues/239533](https://github.com/microsoft/vscode/issues/239533)

## Summary

The requested control remains missing: current toolbar registrations still choose Disconnect for attach sessions and expose Stop as an alternate. Keep this team-authored request open; the related reports do not provide an eligible duplicate target.

## Change summary

Allow an attach-based debugging workflow to make Stop the primary action instead of Disconnect, potentially remembering the user's choice.

## Best solution

Provide a deliberate way for attach-based workflows to prefer Stop while retaining Disconnect and respecting adapter termination capabilities. First settle whether this is an explicit configuration/adapter preference or a remembered user choice, including its persistence scope.

- **Behavior:**

  > Python terminal debugging can require an attach session even when stopping the debuggee is the desired primary operation. Today Disconnect remains primary and Stop requires an alternate interaction. The finished behavior should let this workflow prefer Stop without removing Disconnect or offering unsupported termination. Acceptance must cover the selected preference's scope and persistence while preserving existing defaults for sessions that do not opt in.
- **Trace:**

  > debugToolBar.ts registers the primary Stop/Disconnect actions directly against CONTEXT_FOCUSED_SESSION_IS_ATTACH and gates their alternates on CONTEXT_TERMINATE_DEBUGGEE_SUPPORTED. createDisconnectMenuItemAction builds the dropdown around that already-selected primary action; ViewModel in common/debugViewModel.ts obtains session classification through isSessionAttach in common/debugUtils.ts. The same toolbar registrations feed docked and command-center surfaces, and debugViewlet.ts and callStackView.ts reuse the dropdown helper. Source inspection confirms the missing preference, not a failure of the existing explicit Stop command. Preserve launch/attach protocol semantics and capability restrictions; changing which action is primary must not redefine session ownership or address the separate DAP-request issue at https://github.com/microsoft/vscode/issues/143991. The newer compound-specific report at https://github.com/microsoft/vscode/issues/239645 is related but is not a canonical for this re-reviewed item.
- **Open decisions:**

  - If the choice is remembered, should it apply per debug configuration, per debugger type, or across the workspace, and should it survive a window reload?
