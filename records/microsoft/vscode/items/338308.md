# Issue #338308 — Renaming a chat session from the sessions list is not persisted (renaming from the session title works)

[https://github.com/microsoft/vscode/issues/338308](https://github.com/microsoft/vscode/issues/338308)

## Summary

Confirmed source-level bug: renaming from the sessions list only updates the in-memory session index and never flushes it to storage, so the rename is silently lost unless the session's chat model happens to still be live in memory.

## Change summary

Renaming a chat session from the Agent Sessions list does not persist the new title, while renaming via the open session's title bar does.

## Best solution

Fix `ChatSessionStore.setSessionTitle` in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts to call `await this.flushIndex()` after mutating the index entry, matching sibling mutators like `deleteSession`/`clearAllSessions` that already do this.

- **code path:** RenameAgentSessionAction.runWithSessions (agentSessionsActions.ts:770-793) and the title-bar rename both funnel into ChatServiceImpl.setChatSessionTitle (chatServiceImpl.ts:424-437), which calls model.setCustomTitle(title) only if the session's ChatModel is currently loaded in `_sessionModels`, and otherwise falls back to `this._chatSessionStore.setSessionTitle(localSessionId, title)`.
- **missing flush:** ChatSessionStore.setSessionTitle (chatSessionStore.ts:510-517) mutates `index.entries[sessionId].title` in memory but never calls `this.flushIndex()`, unlike `deleteSession` (line 493-498) and `clearAllSessions` (line 500-508) which explicitly call `await this.flushIndex()` after mutating the same index.
- **why the model-loaded path works:** ChatServiceImpl.saveState() (chatServiceImpl.ts:360-377) rebuilds and flushes the index only for currently-loaded ('live') models via `updateAndFlushIndexSync`, reading `session.customTitle` off the live model (chatSessionStore.ts:868-870) — this is why renaming while the session is open (live model) persists, while renaming a non-loaded session from the list (index-only path) does not get flushed at all.
