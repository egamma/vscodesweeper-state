# Issue #228286 — Disabling "Use Tab Stops" should be respected in more indentation contexts

[https://github.com/microsoft/vscode/issues/228286](https://github.com/microsoft/vscode/issues/228286)

## Summary

Keep open: current source still applies tab-stop alignment in single-cursor Tab insertion and automatic indentation independently of editor.useTabStops. The related reports do not establish an open canonical covering this request's full scope.

## Change summary

Extend editor.useTabStops=false to preserve fixed-width relative indentation when pressing Tab and entering a new block.

## Best solution

Make the disabled-tab-stops behavior consistent across line indentation, single-cursor Tab, and automatic block indentation, while preserving existing behavior when the setting is enabled. Review the interaction with language-provided indentation before extending the setting's contract.

Run the targeted cursor suite through scripts/test.sh when implementation is authorized; no tests were run during this read-only review.
- **Behavior:**

  > With spaces, a four-space indentation size, and Use Tab Stops disabled, the reporter expects relative four-space increments rather than alignment to absolute multiples of four. Enter after the two-space-indented C block opener should produce six leading spaces. With Auto Indent set to keep, Enter followed by Tab should likewise move from column 3 to column 7, matching Indent Line. Existing behavior with Use Tab Stops enabled must remain unchanged.
- **Trace:**

  > TabOperation.getCommands sends an empty selection through whitespace-line indentation inference and then _replaceJumpToNextIndent; the latter unconditionally uses modular arithmetic for space insertion. EnterOperation._enter has separate language-enter-action and full-autoindent paths, both connected to normalization or shift helpers that lack useTabStops. The shared normalizer interprets tabs as visual stops, so changing it globally could affect consumers beyond the reported actions; the consumer boundary was not fully enumerated in this review. ShiftCommand.getEditOperations already has setting-dependent line-indent behavior, providing a comparison rather than full coverage. https://github.com/microsoft/vscode/issues/63388 covers related block-selection behavior but is not a verified canonical for both requested contexts. No runtime reproduction was attempted under the read-only constraint.
- **Open decisions:**
  - Should disabling Use Tab Stops also reinterpret indentation tabs supplied by language on-enter rules as fixed-width relative increments, or should language-supplied indentation retain its existing tab-stop semantics?
