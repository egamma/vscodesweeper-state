# Issue #330650 — Auxiliary window sometimes fails to restore after being maximized on multi-monitor setup

[https://github.com/microsoft/vscode/issues/330650](https://github.com/microsoft/vscode/issues/330650)

## Summary

This remains a credible cross-platform restoration bug: multiple users confirm that a previously maximized auxiliary window can be omitted on the first restart, while a second restart restores it. Current source still contains the affected persistence and cross-process restoration path, and no canonical issue or fixing commit was found.

## Change summary

Restore maximized auxiliary windows reliably, preserving their maximized state and monitor placement across VS Code restarts.

## Best solution

Diagnose the persisted auxiliary-window state and Electron window-creation sequence across the editor-parts renderer and auxiliary-window main-process services, then make first-launch restoration deterministic without changing normal auxiliary-window creation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorParts.ts`, `src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts`, `src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts`, `src/vs/platform/auxiliaryWindow/electron-main/auxiliaryWindowsMainService.ts`, `src/vs/platform/auxiliaryWindow/electron-main/auxiliaryWindow.ts`
- **Validation:** On Windows 11 and Ubuntu 24.04, repeatedly create and maximize an auxiliary editor window, close VS Code normally, and reopen the same workspace; verify on every first relaunch that the auxiliary window appears maximized, with non-maximized restoration unchanged and monitor placement preserved where supported.
- **Behavior:**

  > A maximized auxiliary editor window must be restored on the first reopening of its workspace, not only after a second restart. Its maximized state should be preserved, and restoration must work on both Windows 11 and Ubuntu 24.04 with single- and multi-monitor configurations. Non-maximized auxiliary windows must continue restoring reliably, and opening files from Explorer must remain functional after restoration.
- **Trace:**

  > EditorParts.createState() in src/vs/workbench/browser/parts/editor/editorParts.ts combines the editor-part state with NativeAuxiliaryWindow.createState(), while restoreState() recreates every saved part concurrently through createAuxiliaryEditorPart(). NativeAuxiliaryWindow in src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts tracks maximize state asynchronously and serializes AuxiliaryWindowMode.Maximized. BrowserAuxiliaryWindowService.openWindow() converts this to window-maximized=yes; AuxiliaryWindowsMainService.computeWindowStateAndOverrides() decodes it, and platform/auxiliaryWindow/electron-main/auxiliaryWindow.ts applies the resulting state after claiming the Electron BrowserWindow. The report indicates an intermittent failure somewhere along this persistence, creation, registration, or state-application sequence; source inspection does not isolate which stage loses the first launch. Keep ordinary auxiliary-window creation, non-maximized restoration, and unrelated tab-drag behavior out of scope.

## Evidence

- **independent confirmations:** The reporter reproduced the failure on Windows 11 and Ubuntu 24.04, including with one monitor, and two other users confirmed it across versions 1.133.0 and 1.134.0: https://github.com/microsoft/vscode/issues/330650#issuecomment-5309816369, https://github.com/microsoft/vscode/issues/330650#issuecomment-5313285293, and https://github.com/microsoft/vscode/issues/330650#issuecomment-5424917525.
