# Issue #330650 — Auxiliary window sometimes fails to restore after being maximized on multi-monitor setup

[https://github.com/microsoft/vscode/issues/330650](https://github.com/microsoft/vscode/issues/330650)

## Summary

Fresh, detailed report (0 days old) of an auxiliary window restore issue tied to maximize state and multi-monitor/scaling setups; no maintainer or commenter confirmation yet, so this needs the area owner's eyes rather than a close.

## Change summary

On a 3-monitor mixed-DPI setup, a maximized auxiliary ('floating') window sometimes fails to restore (or restores unmaximized/on the wrong monitor) on the next VS Code launch, on both Windows and Ubuntu/Wayland.

## Best solution

Route to whoever owns auxiliary window persistence/restore in src/vs/platform/auxiliaryWindow/electron-main/ and src/vs/platform/windows/electron-main/windowsStateHandler.ts; the reporter's own note that maximize-state save/restore is the trigger, combined with the code comment about auxiliary windows never showing maximized initially 'to reduce flicker' (auxiliaryWindow.ts, near the show/maximize probe), suggests a race between window-state persistence and the deferred maximize/display placement across multiple monitors with different scale factors — worth a maintainer reproduction on real multi-monitor hardware before deciding whether it's a Windows/Electron-specific display-placement bug or a state-save timing issue.
