# Issue #10064 — Git - Support git-bash ssh agent for Windows

[https://github.com/microsoft/vscode/issues/10064](https://github.com/microsoft/vscode/issues/10064)

## Summary

Keep open: built-in SSH passphrase prompts address part of the original discussion, but automatic reuse of a Git Bash SSH agent remains distinct from prompting or inheriting a manually prepared environment. The accepted Backlog request has 30 upvotes, and no qualifying older canonical or concrete fixing commit was established.

## Change summary

Let Windows Git integration reuse a Git Bash SSH agent without requiring users to launch VS Code from Git Bash or manually export its environment.

## Best solution

Provide a supported way for the built-in Git integration to reuse an existing Git Bash agent when VS Code starts normally on Windows. Settle agent discovery and lifecycle expectations first, preserving explicitly configured SSH environments and existing passphrase prompting.

## Plan brief

- **Likely files:** `extensions/git/src/main.ts`, `extensions/git/src/git.ts`, `extensions/git/src/askpass.ts`, `extensions/git/package.json`
- **Validation:** On Windows, start a Git Bash ssh-agent and load a passphrase-protected key, then launch VS Code independently without manually exporting agent variables. Verify SCM fetch, pull, and push reuse that agent without repeated passphrase prompts; repeat with an explicitly inherited agent, an unavailable agent, and agent restart to confirm the agreed fallback and lifecycle behavior.
- **Behavior:**

  > Windows users should be able to reuse an existing Git Bash SSH agent for built-in SCM operations without launching VS Code from the authenticated shell or manually exporting its environment. With a loaded key, fetch, pull, and push should not repeatedly request its passphrase. Explicitly configured agent environments must continue to work, and absent or stale agents must follow a clearly agreed fallback. Acceptance requires a Windows check covering independent VS Code startup, repeated Git operations, and agent restart.
- **Trace:**

  > The original reporter starts Git Bash, enters the key passphrase, and launches VS Code using `code`, as documented at https://github.com/microsoft/vscode/issues/6202#issuecomment-236861431. In extensions/git/src/main.ts, createModel supplies Askpass, GitEditor, and IPC environment values to Git; Git.spawn in extensions/git/src/git.ts merges these with process.env. Askpass.handleSSHAskpass in extensions/git/src/askpass.ts already supplies passphrase prompts, matching the improvements described at https://github.com/microsoft/vscode/issues/13680#issuecomment-1254808568, but prompting is not agent discovery. The inspected Git path does not locate an independently started Git Bash agent. Preserve existing SSH environment overrides, HTTPS authentication, and passphrase fallback; Remote-SSH integration is separate. Uncertainty begins at how VS Code should select an agent it did not inherit and whether it should own any agent lifecycle; actual Windows behavior still needs validation.
- **Open decisions:**
  - Should independently launched VS Code discover a running Git Bash agent automatically, or require an explicit user opt-in or agent selection?
  - Should VS Code only reuse an existing agent, or also start one when none is available, and what should the user experience be when an agent becomes stale or restarts?
