# Issue #277754 — Default worktree location has no write permission in dev container

[https://github.com/microsoft/vscode/issues/277754](https://github.com/microsoft/vscode/issues/277754)

## Summary

Keep open: the current CLI isolation path still selects a sibling worktree directory outside the mounted repository, which fails when /workspaces is not writable. A safe default needs a persistence decision with the Git and Dev Containers owners; changing permissions alone does not address the maintainer's concerns.

## Change summary

Starting an isolated Copilot CLI session inside a Dev Container fails because the default worktree directory is outside the writable workspace mount.

## Best solution

Provide a writable, persistent worktree location for CLI isolation in an existing Dev Container without automatically exposing unrelated host directories. Coordinate the Git/Copilot location policy with Dev Containers ownership before choosing the default.

- **Trace:**

  > ChatSessionWorktreeService._createWorktree in extensions/copilot/src/extension/chatSessions/vscode-node/chatSessionWorktreeServiceImpl.ts supplies a branch but no path to GitServiceImpl.createWorktree in extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts. Interactive path selection in extensions/git/src/commands.ts is a separate surface and does not settle the first-use CLI default. Uncertainty starts at the persistent storage and mount policy, not branch naming or Git invocation; preserve ordinary local defaults and do not broaden host mounts automatically. https://github.com/microsoft/vscode/issues/293884 is related configuration work, while https://github.com/microsoft/vscode/issues/316940 is a newer, distinct environment report.
- **Open decisions:**
