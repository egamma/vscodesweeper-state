# Issue #336642 — Contrast issue in Restristed Mode banner in Quiet Light Theme?

[https://github.com/microsoft/vscode/issues/336642](https://github.com/microsoft/vscode/issues/336642)

## Summary

Confirmed via source: Quiet Light's explicit `list.activeSelectionForeground` (#6c6c6c) and `list.activeSelectionBackground` (#c4d9b1) combine through the generic banner fallback formula to produce ~2.15:1 contrast in the Restricted Mode banner, well under WCAG AA — a real theme-specific contrast bug, not a generic banner defect.

## Change summary

The Restricted Mode banner text is low-contrast gray-on-green in the built-in Quiet Light color theme.

## Best solution

Add explicit `banner.background`/`banner.foreground` (or adjust the selection colors feeding the banner defaults) in extensions/theme-quietlight/themes/quietlight-color-theme.json so the computed banner colors clear WCAG AA contrast.

  > BANNER_BACKGROUND/BANNER_FOREGROUND (src/vs/workbench/common/theme.ts:277-286) derive from list.activeSelectionBackground/Foreground when a theme doesn't override banner colors directly. Quiet Light (extensions/theme-quietlight/themes/quietlight-color-theme.json:492,495) sets those selection colors to #6c6c6c/#c4d9b1, and darken(#c4d9b1,0.3) against #6c6c6c computes to ~2.15:1 contrast — confirmed by manual color-math, not by running the app. The fix should scope to Quiet Light's theme JSON (or a targeted banner color override) and must not alter list.activeSelectionForeground/Background's appearance for actual list/tree selection highlighting, which uses the same tokens.
