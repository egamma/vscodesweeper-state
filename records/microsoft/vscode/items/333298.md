# Issue #333298 — Support pagination for automations run history

[https://github.com/microsoft/vscode/issues/333298](https://github.com/microsoft/vscode/issues/333298)

## Summary

Keep open: automation history still renders every eligible run, unlike the session sidebar's bounded-list behavior. This team-authored request remains an identifiable gap; no qualifying fix or older canonical duplicate was found.

## Change summary

Bound the initially rendered automation run history and allow users to reveal additional runs.

## Best solution

Provide incremental history disclosure in AutomationHistorySection, consistent with the session list, while preserving date grouping, keyboard focus, live updates, and run actions. Settle the disclosure behavior with the maintainer before implementation.

- **Trace:**

  > AutomationHistorySection.render in src/vs/sessions/contrib/sessions/browser/views/automationsView.ts filters eligible runs, groups the entire collection by date, and sends all group sessions through updateGroupSessions. layoutSessionList sizes each SessionsFlatList to its full content height, so the shared tree component does not itself constrain this history surface. In src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, limitSessionsForList provides the sidebar's bounded initial list and Show More/Show Less behavior, but expansion reveals all remaining sessions rather than successive pages. The feature request is https://github.com/microsoft/vscode/issues/333298; the newer navigation request https://github.com/microsoft/vscode/issues/341090 addresses a distinct behavior.
