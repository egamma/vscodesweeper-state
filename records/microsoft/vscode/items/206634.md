# Issue #206634 — Be able to make the panel take only the half of the editor with

[https://github.com/microsoft/vscode/issues/206634](https://github.com/microsoft/vscode/issues/206634)

## Summary

A real layout capability remains missing: the Panel can be positioned and aligned relative to the overall editor area, but it cannot occupy the space beneath only a subset of editor groups. The existing `under-discussion` and `layout` classification is appropriate, and no eligible older open canonical owns the same request.

## Change summary

Allow the bottom Panel to span only selected editor groups so another editor group can retain the full window height.

## Best solution

Support a resizable Panel region that can share the editor grid with selected editor groups while preserving the unified Terminal, Output, Problems, and Debug Console container. The design should define how users choose the groups it spans and how that relationship survives layout changes and reloads.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/parts/editor/editorPart.ts`, `src/vs/workbench/browser/parts/panel/panelActions.ts`, `src/vs/base/browser/ui/grid/gridview.ts`
- **Validation:** Create a three-column editor layout, place the bottom Panel beneath only the first two columns, resize both relevant sashes, reload the window, and verify the third editor remains full-height while existing whole-width Panel positions and alignments continue to work.
- **Behavior:**

  > Users with multiple editor groups can size the bottom Panel so it occupies the area below only a chosen subset of adjacent groups; editor groups outside that span retain the full available height. The entire Panel remains one container, including Terminal, Output, Problems, and Debug Console. Resizing must be direct and predictable, and the resulting arrangement should restore after reload without changing existing Panel layouts for users who do not opt into the new arrangement.
- **Trace:**

  > The outer workbench grid is created in `src/vs/workbench/browser/layout.ts`, where `panelPartView` and the complete `editorPartView` are sibling views. Individual editor groups are managed by the nested editor grid in `src/vs/workbench/browser/parts/editor/editorPart.ts`, so current `setPanelPosition` calls can place the Panel only relative to the entire editor part. Panel alignment commands in `src/vs/workbench/browser/parts/panel/panelActions.ts` alter alignment against sidebars but do not enter the editor-group grid. The same limitation appears in the closed historical requests https://github.com/microsoft/vscode/issues/57029 and https://github.com/microsoft/vscode/issues/11472. Preserve the unified Panel container and all existing position/alignment behavior; the uncertainty begins at how an outer workbench part should relate to selected nodes of the nested editor grid.
- **Open decisions:**
  - Should the Panel span an explicitly selected set of adjacent editor groups, or behave as another freely placeable cell in the editor grid?
  - When editor groups are added, removed, or rearranged, should the Panel retain a fixed geometric region or remain attached to the originally selected groups?
  - Should partial-width Panel placement be persisted as part of the workspace layout, profile layout, or only the current window session?

## Evidence

- **current source limitation:** `src/vs/workbench/browser/layout.ts` constructs `panelPartView` and `editorPartView` as separate top-level workbench-grid views; `setPanelPosition` moves the Panel only above, below, left, or right of the entire `editorPartView`, so it cannot share a row with individual editor groups.
- **existing capability does not cover request:** `src/vs/workbench/browser/parts/panel/panelActions.ts` exposes four Panel positions and left, center, right, or justify alignment. `adjustPartPositions` in `src/vs/workbench/browser/layout.ts` uses alignment to change the Panel's relationship with the sidebars, not to constrain it to selected editor groups.
- **older related issue:** https://github.com/microsoft/vscode/issues/57029 requested free Panel placement among editor grids and contains essentially the same layout example, but it is closed and therefore cannot serve as a duplicate canonical; its closure discussion did not identify a still-open canonical.
- **broader historical request:** https://github.com/microsoft/vscode/issues/11472 asked to dock editors, views, and panels anywhere, but it was closed after editor-grid support shipped even though the current source still keeps the Panel outside the editor-group grid.
- **confirmed use case:** A later commenter independently described the same need: keep the primary sidebar, editor area, and secondary sidebar visible while placing the Panel beneath only part of that layout.
