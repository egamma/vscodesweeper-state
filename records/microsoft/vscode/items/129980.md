# Issue #129980 — the default value of `editor.autoClosingDelete` should be "always"

[https://github.com/microsoft/vscode/issues/129980](https://github.com/microsoft/vscode/issues/129980)

## Summary

Keep this open under discussion: current main still defaults `editor.autoClosingDelete` to `auto`, and changing a broadly applied editor default requires product feedback rather than a bug fix. No open canonical issue was found that owns this default-value decision.

## Change summary

Change the default value of `editor.autoClosingDelete` from `auto` to `always` so adjacent bracket and quote pairs are consistently deleted together.

## Best solution

Retain the configurable `always` option while the editor owners decide whether its consistency benefits outweigh the aggressive deletion that prompted the safer `auto` default; any default change should be supported by broader user feedback and compatibility analysis.

## Evidence

- **current semantics:** src/vs/editor/common/cursor/cursorDeleteOperations.ts:75-149 deletes any adjacent recognized pair for `always`, but for `auto` additionally requires the closing character to remain in the editor's `autoClosedCharacters` tracking.
- **design provenance:** https://github.com/microsoft/vscode/issues/118270 documents that `auto` was deliberately introduced after unconditional pair deletion removed existing closing characters too aggressively; the maintainer described it as matching auto-closing overtype behavior.

- **existing capability:** Users who prefer unconditional adjacent-pair deletion can already set `editor.autoClosingDelete` to `always`; this is a workaround for individuals but does not satisfy the request to change behavior for all new users.
