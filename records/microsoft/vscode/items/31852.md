# Issue #31852 — multiCursorModifier should be ctrlCmd by default for *nix users

[https://github.com/microsoft/vscode/issues/31852](https://github.com/microsoft/vscode/issues/31852)

## Summary

Keep open: Ctrl-click multicursor is configurable, but the requested Unix default remains Alt-click. Switching the setting also moves link activation to Alt-click, so it does not fully resolve the window-manager conflict; the thread calls for mouse customization.

## Change summary

Make mouse multicursor usable by default on Unix desktops where Alt-click is reserved for moving windows.

## Best solution

Agree on a Linux mouse-gesture policy that avoids window-manager conflicts without making link activation unusable. Evaluate the default change alongside independent mouse customization, preserving existing explicit user settings.

- **Behavior:**

  > On Linux desktops that reserve Alt-click for window movement, the default multicursor gesture cannot reach the editor. Selecting editor.multiCursorModifier='ctrlCmd' enables Ctrl-click multicursor but moves editor and terminal link activation to Alt-click. The desired outcome is a usable default gesture policy without transferring the same conflict to navigation. Acceptance must cover multicursor and link activation together, preserve explicit user choices, and follow the maintainer's decision on platform scope.
- **Trace:**

  > The current registration in src/vs/editor/common/config/editorOptions.ts defaults editor.multiCursorModifier to 'alt' and already supports 'ctrlCmd'. ToggleMultiCursorModifierAction provides the setting swap in src/vs/workbench/contrib/codeEditor/browser/toggleMultiCursorModifier.ts. createOptions in src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts and the terminal link modifier checks in terminalLink.ts and terminalLinkManager.ts deliberately choose the opposite modifier. Source inspection establishes the coupling, not a live window-manager reproduction. The thread recommends real mouse customization, related to https://github.com/microsoft/vscode/issues/3130; independent terminal activation is also requested in https://github.com/microsoft/vscode/issues/302645. The unresolved boundary is the observable default policy, not which helper implements it; do not assume all Unix desktops have the same reserved gestures or overwrite explicit settings.
- **Open decisions:**
  - Should the default change on Linux only, or should the existing cross-platform default remain while mouse gestures become independently configurable?
  - If Linux multicursor defaults to Ctrl-click, what default editor and terminal link gestures should avoid the same Alt-click window-manager conflict?
