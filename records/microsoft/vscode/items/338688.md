# Issue #338688 — Expose Modern UI / layout density state to webviews

[https://github.com/microsoft/vscode/issues/338688](https://github.com/microsoft/vscode/issues/338688)

## Summary

Keep open: current webview styling does not expose effective Modern UI or layout-density state, and the exported size tokens do not adapt to those settings. The remaining decision is the extension-facing contract: explicit state markers or adaptive semantic tokens.

## Change summary

Let webview content match native Modern UI styling and density through a built-in, synchronized CSS contract.

## Best solution

Define a supported webview styling contract that follows the workbench's effective appearance without extension-specific configuration relays. Resolve the thread's state-marker versus adaptive-token question while preserving existing fixed spacing and typography ramps.

- **Validation:** With a webview view beside a native view, verify the agreed CSS contract on initial creation and after toggling workbench.experimental.modernUI, window.density.layout and workbench.experimental.modernUIUppercaseViewHeaders without reloading or extension configuration relays. Repeat after recreating the webview and changing the color theme; confirm existing theme, accessibility and fixed-token behavior remains compatible.
- **Behavior:**

  > Webview authors currently receive fixed design tokens but cannot use CSS alone to follow the effective Modern UI and layout-density styling of neighboring native views. Provide a supported contract that reflects the effective appearance on initial load and subsequent changes without each extension forwarding settings. Acceptance must cover Modern UI disabled and enabled, default and compact density, uppercase-header preferences, and webview recreation. Existing webview theme and accessibility styling must remain compatible.
- **Trace:**

  > WebviewThemeDataProvider in src/vs/workbench/contrib/webview/browser/themeing.ts exports fixed size defaults and does not invalidate its cached data for the relevant appearance settings. WebviewElement.style() in src/vs/workbench/contrib/webview/browser/webviewElement.ts forwards that data, and applyStyles() in src/vs/workbench/contrib/webview/browser/pre/index.html installs theme and accessibility state but no appearance or density markers. ModernUIContribution.update() and applyTo() in src/vs/workbench/contrib/modernUI/browser/modernUI.contribution.ts apply effective classes to native containers, gating compact and uppercase-header state on enablement. Existing spacing tokens in src/vs/platform/theme/common/sizes/baseSizes.ts have fixed-ramp semantics, so adapting their numeric meaning would affect an existing extension-facing contract. The unresolved boundary is whether extensions consume explicit effective state or semantic styling values; preserve unrelated native layout, theme and accessibility behavior. https://github.com/microsoft/vscode/issues/334285 is related design context, not a verified duplicate.
- **Open decisions:**
  - Should the supported webview CSS contract expose effective Modern UI, density and uppercase-header state, adaptive semantic styling tokens, or both?
  - If adaptive tokens are chosen, which native styling roles should they cover, and should existing fixed-ramp tokens retain their current meanings?

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/webview/browser/themeing.ts: WebviewThemeDataProvider exports theme identity, colors, fixed size tokens and editor font settings. Its configuration-change listener watches editor font settings and accessibility.underlineLinks, not Modern UI, layout density or uppercase view headers.
- **Webview transport and body styling:** src/vs/workbench/contrib/webview/browser/webviewElement.ts: style() sends styles, activeTheme, themeId, themeLabel, reduceMotion and screenReader. src/vs/workbench/contrib/webview/browser/pre/index.html: applyStyles() installs theme and accessibility classes and theme identity attributes, but no Modern UI or density state.
- **Effective native state:** src/vs/workbench/contrib/modernUI/browser/modernUI.contribution.ts: ModernUIContribution.update() applies compact and uppercase-header classes only when Modern UI is enabled; applyTo() targets workbench containers. src/vs/workbench/browser/workbench.contribution.ts registers the existing appearance settings, but they do not provide the requested automatic webview CSS integration.

WebviewThemeDataProvider resolves size defaults against the color theme, without density input; existing tokens therefore supply building blocks rather than effective pane styling.
