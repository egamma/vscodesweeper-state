# Issue #345407 — Background terminal completion notification is silently dropped when shell integration capabilities are not available yet

[https://github.com/microsoft/vscode/issues/345407](https://github.com/microsoft/vscode/issues/345407)

## Summary

The silent notification-registration failure remains in current source: missing command detection permanently bypasses background monitoring and completion listeners. Keep this open; the report supplies concrete reproduction steps and controlled timeout comparisons.

## Change summary

Background terminal commands lose completion notifications when shell integration is unavailable during notification registration.

## Best solution

Make background notification tracking tolerate delayed shell integration and explicitly report unavailable completion tracking. Define a safe no-integration fallback that does not mistake a quiet, still-running command for a completed command.

## Evidence

- **Confirmed registration defect:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts:2998–3009: _registerCompletionNotification reads TerminalCapability.CommandDetection once; when absent, it disposes outputMonitor and returns without logging or subscribing to later capability availability.
- **Background call path:** runInTerminalTool.ts:2353–2383 invokes registration from finally for background executions, then disposes the invocation store. The completion listener and terminal-disposal notification listener at approximately lines 3185–3298 are both below the missing-capability return.
- **Reporter evidence and workaround:** https://github.com/microsoft/vscode/issues/345407 provides Windows PowerShell reproduction steps, timeout logs, and an A/B comparison: terminal.integrated.shellIntegration.timeout=20000 allows notification delivery, whereas the default timeout loses notifications. The -NoProfile control also fails, so blaming conda alone would not explain the report.
- **Fallback boundary:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy/noneExecuteStrategy.ts:execute uses idle/prompt heuristics and returns no exit code. ActiveTerminalExecution.start in runInTerminalTool.ts resolves completionPromise from that strategy result; therefore using that promise or output silence as definitive command completion requires care.
- **Partial existing mitigation:** toolTerminalCreator.ts:_waitForShellIntegration waits for capability readiness, and refreshShellIntegrationQuality upgrades capabilities already present. Neither repairs a notification registration that has already returned; increasing the timeout is a workaround, not coverage of delayed or permanently missing integration.

- **Scope of confirmation:** Read-only source inspection conclusively confirms the silent registration loss, but does not independently establish why the reporter's execution ID disappears. No builds or runtime reproduction were performed.
