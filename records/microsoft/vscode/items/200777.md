# Issue #200777 — Preserve terminal cwd when reviving process

[https://github.com/microsoft/vscode/issues/200777](https://github.com/microsoft/vscode/issues/200777)

## Summary

Keep open: PowerShell process revival still has a source-confirmed path that restores the initial directory instead of the last working directory. The existing revival setting and the related shellIntegration.cwd fix do not resolve that path.

## Change summary

Preserve the last PowerShell working directory when recreating a persistent terminal after closing and reopening VS Code.

## Best solution

Revived PowerShell terminals should start in their last filesystem working directory, with terminal persistence retaining the necessary directory state. Preserve working Bash restoration and distinguish process revival from reconnecting to an existing process.

- **Behavior:**

  > After changing a PowerShell terminal's filesystem location and closing its VS Code window, reopening the workspace must recreate the terminal in that last location, not the workspace root. Restored history alone does not satisfy this requirement: Get-Location in the newly running shell must agree with the pre-close location. Validate Windows and macOS, and preserve existing Bash restoration and reload/reconnection behavior.
- **Trace:**

  > PtyService.serializeTerminalState obtains processDetails through _buildProcessDetails, whose cwd comes from PersistentTerminalProcess.getCwd and ultimately TerminalProcess.getCwd. PowerShell separately emits its filesystem location in shellIntegration.ps1, and ShellIntegrationAddon records it, but the inspected process-metadata path does not use that state. The macOS implementation instead uses lsof, so this trace does not conclusively explain PowerShell's reported macOS behavior. _buildProcessDetails also serves attachment metadata, and shell integration distinguishes trusted from untrusted cwd updates; preserve those existing contracts while establishing the persistence boundary.
