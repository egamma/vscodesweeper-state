# Issue #200777 — Preserve terminal cwd when reviving process

[https://github.com/microsoft/vscode/issues/200777](https://github.com/microsoft/vscode/issues/200777)

## Summary

Still reproduces on main: when a terminal is revived after window close, the `ProcessPropertyType.InitialCwd` event overwrites the restored `_cwd` with the workspace root, discarding the user's actual working directory. A WIP branch exists but was never merged; rwoll committed to fixing it in Nov 2025 but no fix has landed.

## Change summary

Terminal revive process resets the current working directory to the workspace root instead of preserving the cwd the user had navigated to before closing.

## Best solution

Guard the InitialCwd property handler so it does not overwrite `_cwd` when the terminal is reconnecting from a persistent session that already carries a valid cwd (the fix meganrogge and Tyriar discussed: use `??=` or check whether `attachPersistentProcess.cwd` was already set). Likely files: `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts` (the `ProcessPropertyType.InitialCwd` handler around line 1537) and possibly `src/vs/platform/terminal/common/xterm/shellIntegrationAddon.ts` for the CwdDetection serialization meganrogge described.
