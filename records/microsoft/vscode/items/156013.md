# Issue #156013 — I can't scroll screen using Windows Ink

[https://github.com/microsoft/vscode/issues/156013](https://github.com/microsoft/vscode/issues/156013)

## Summary

This accepted Backlog request remains necessary: current desktop editor input handling has no path that pans editor content for a Windows Ink pen drag. It has 24 community upvotes and no verified canonical issue, so it should remain open for an explicit desktop stylus interaction design.

## Change summary

Allow users to scroll editor content by dragging with a Windows Ink pen.

## Best solution

Define and implement Windows desktop pen-drag semantics in the editor pointer handling, allowing natural viewport scrolling without unintentionally replacing intentional text-selection behavior.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/pointerHandler.ts`, `src/vs/base/browser/touch.ts`
- **Validation:** Add an editor browser input test that dispatches a Windows-style pen drag and verifies the chosen scroll-versus-selection contract, then manually verify vertical and horizontal panning with a Windows Ink device while confirming mouse, touch, and scrollbar behavior remain unchanged.
- **Behavior:**

  > On Windows, dragging the editor viewport with a Windows Ink pen supports scrolling according to the interaction chosen by the maintainer. Vertical and horizontal movement update the corresponding editor scroll positions, and releasing the pen ends the gesture cleanly. Mouse selection, touch scrolling, scrollbar dragging, and the chosen mechanism for pen text selection remain unchanged. Acceptance includes an automated pointer-input test and a manual check on Windows Ink hardware.
- **Trace:**

  > Editor input is constructed by PointerHandler in src/vs/editor/browser/controller/pointerHandler.ts. PointerEventHandler distinguishes mouse, touch, and pen, but is selected only for phones; its touch branch calls viewLayout.deltaScrollNow while its pen branch performs text selection. Desktop chooses TouchHandler or MouseHandler, and Gesture in src/vs/base/browser/touch.ts is driven by touch events rather than generic pen pointer movement. Commit cab772fcfe98bff9f8ae5fe91e44c6a395a6b969 establishes mobile pen selection, and 57c5c8801d7dc8f41af17c16ac07efd077abfbcc establishes the current phone-only boundary. The plan must preserve mouse, touch, mobile stylus, and scrollbar behavior while determining the intended Windows-specific pen gesture.
- **Open decisions:**
  - Should an unmodified Windows pen drag scroll the editor, or should pen dragging continue to select text with scrolling exposed through a modifier or pen-button gesture?
  - Should the Windows pen-scrolling behavior apply only to the text editor viewport or consistently to other Monaco scrollable surfaces?

## Evidence

- **accepted demand:** The issue has 24 upvotes, carries the feature-request label and Backlog milestone, and https://github.com/microsoft/vscode/issues/156013#issuecomment-1378168582 confirms that it passed the community upvote threshold.
- **current desktop path:** src/vs/editor/browser/controller/pointerHandler.ts selects PointerEventHandler only for iOS/Android phones; desktop environments use TouchHandler when TouchEvent exists, otherwise MouseHandler. Neither desktop path translates a pointerType='pen' drag into viewLayout.deltaScrollNow.
- **existing platform distinction:** Commit cab772fcfe98bff9f8ae5fe91e44c6a395a6b969 added pen-drag text selection to PointerEventHandler for mobile, while commit 57c5c8801d7dc8f41af17c16ac07efd077abfbcc subsequently restricted that handler to phones. This leaves desktop pen scrolling unresolved and shows that scrolling versus selection is a deliberate interaction choice.
- **canonical search:** Repository searches for Windows Ink, stylus scrolling, and pen scrolling found no open issue owning this request. Closed https://github.com/microsoft/vscode/issues/36492 concerns Windows interpreting pen input as touch versus mouse, and does not track editor viewport scrolling.
