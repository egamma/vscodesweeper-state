# Issue #322695 — Missing search experience for multi-diff editor

[https://github.com/microsoft/vscode/issues/322695](https://github.com/microsoft/vscode/issues/322695)

## Summary

Still a real gap on current main: the multi-diff editor has no find experience of its own, so Cmd+F falls through to the focused inner diff editor and only searches that one file. Team-authored and unfixed — keep open and route to the diff-editor area.

## Change summary

Cmd+F in the multi-diff editor opens the single-editor find widget instead of searching across all diffs shown in the multi-diff editor.

## Best solution

Add a multi-diff-level find experience in src/vs/editor/browser/widget/multiDiffEditor (a widget owned by MultiDiffEditorWidgetImpl that searches across all document items, including items not yet materialized by the virtualized scroll view, and reveals/navigates matches), rather than relying on the inner diff editor's find controller.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidgetImpl.ts`, `src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidget.ts`, `src/vs/editor/browser/widget/multiDiffEditor/virtualizedItemManager.ts`, `src/vs/editor/browser/widget/multiDiffEditor/compressedVirtualizedScrollView.ts`
- **Validation:** A multi-diff editor test that opens a multi-diff input with several documents, triggers find for a term present in a document that is not currently scrolled into view, and asserts the match is counted and revealed.
- **Behavior:**

  > With focus in the multi-diff editor, the find action searches across every document shown in that multi-diff editor, not just the focused inner diff. Matches from all files are counted, navigating between matches scrolls the containing file into view and highlights the match, and matches in files that have not yet been rendered are still found. The existing single-file find behavior inside a focused inner diff editor must not regress. Acceptance: find from the multi-diff editor reports matches across files and next/previous navigation crosses file boundaries.
- **Trace:**

  > The multi-diff editor widget (src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidget.ts and multiDiffEditorWidgetImpl.ts) contributes no find widget or find controller — verified by grepping the whole multiDiffEditor folder, where the only `find` hits are `findDocumentDiffItem` and array lookups. As a result Cmd+F is handled by the focused inner DiffEditorWidget's find controller and is scoped to that file, exactly as the issue's video shows. The hard constraint is virtualization: items are materialized on demand through virtualizedItemManager.ts and compressedVirtualizedScrollView.ts, so a cross-document find must work against the models in multiDiffEditorViewModel.ts rather than fanning out to live editor find controllers. Boundary: do not change single-diff find behavior, the inner DiffEditorWidget find controller, or the virtualization/scroll contracts. Related: https://github.com/microsoft/vscode/issues/204076 covers focus/hasFocus on the same widget and may matter for where the find widget takes keyboard focus.
- **Open decisions:**
  - Does Cmd+F in the multi-diff editor always search all documents, or only when the multi-diff container (not an inner editor) has focus, leaving inner-editor find as today?
  - Is the find UI a single multi-diff-level widget with an aggregate match count, or the existing per-editor widget plus cross-file next/previous navigation?
  - Does find cover both sides of each diff (original and modified) and documents filtered out of the current view, or only the visible modified side?

## Evidence

- **no find support on main:** src/vs/editor/browser/widget/multiDiffEditor/ contains no find widget or find controller; the only `find` occurrences in multiDiffEditorWidget.ts / multiDiffEditorWidgetImpl.ts are `findDocumentDiffItem` and array `find`/`findIndex` lookups. Cmd+F therefore reaches the focused inner DiffEditorWidget's find controller, which is scoped to that one file.
- **virtualization constraint:** multiDiffEditorWidgetImpl.ts drives items through compressedVirtualizedScrollView.ts / virtualizedItemManager.ts, so not every document has a live editor — a cross-document find cannot simply fan out to inner find controllers.
- **team-authored, no fix:** Filed by a VS Code team member (alexdima); no fix commit references this issue and no PR is linked, so the gap remains.
- **related, not duplicate:** https://github.com/microsoft/vscode/issues/204076 (multi-diff `focus`/`hasFocus`) touches the same widget but is a different observable gap; nothing in the candidate list reports this symptom.
