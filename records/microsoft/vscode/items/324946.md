# Issue #324946 — Use QuickPick for the blocked sessions context view

[https://github.com/microsoft/vscode/issues/324946](https://github.com/microsoft/vscode/issues/324946)

## Summary

This team-authored debt remains present on current main: the blocked-sessions surface still uses a custom context view and SessionsFlatList rather than QuickPick. Keep it open, but plan the migration around the approval, Fix CI, and ignore actions added after the issue was filed.

## Change summary

Replace the custom blocked-sessions context view with a shared QuickPick-based experience.

## Best solution

Use an anchored QuickPick that reactively lists blocked sessions and provides standard filtering, keyboard navigation, focus handling, and accessibility while preserving the blocked-session actions users currently perform without first opening a session.

- **Validation:** Exercise updated component-fixture scenarios for one, many, mixed, approval, and failing-CI blocked sessions; verify keyboard filtering and selection, Escape dismissal with focus restoration, reactive item updates, and every retained item or bulk action.
- **Behavior:**

  > Activating the title-bar blocked-sessions indicator opens a searchable QuickPick containing the current blocked sessions in most-recently-updated order. Keyboard and pointer users can identify and open a session, dismiss the picker with Escape, and use whichever approval, Fix CI, and ignore actions the maintainer chooses to retain directly in the picker. The list updates while open as blocked-session state changes, and standard QuickPick focus, filtering, styling, and accessibility behavior apply.
- **Trace:**

  > SessionsTitleBarWidget._showBlockedSessions in src/vs/sessions/contrib/sessions/browser/sessionsTitleBarWidget.ts currently owns an IContextViewService surface and creates BlockedSessionsList. BlockedSessionsList in src/vs/sessions/contrib/sessions/browser/blockedSessionsList.ts wraps SessionsFlatList, custom header menus, sizing, content-height events, and per-row action handling. IQuickPick in src/vs/platform/quickinput/common/quickInput.ts supports anchoring, filtering, reactive item replacement, header buttons, item buttons, and background acceptance, but not the custom multi-line approval and CI rows as currently rendered. The migration must preserve BlockedSessionsIndicatorModel as the source of blocked and ignored state and must not alter the underlying session-classification behavior. Existing component fixtures cover the rich rows, but the record does not settle which of those actions must remain inline in the QuickPick.
- **Open decisions:**
  - Must the QuickPick preserve the complete multi-line pending-command preview and direct Allow action, or should selecting such an item open the session for approval?
  - Which Fix CI, per-session ignore, bulk-ignore, and Show All actions must remain directly available in the QuickPick rather than requiring navigation to another surface?
