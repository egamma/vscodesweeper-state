# Issue #313485 — Make Copilot Autopilot request-error retry count configurable

[https://github.com/microsoft/vscode/issues/313485](https://github.com/microsoft/vscode/issues/313485)

## Summary

The requested setting remains absent on current main, and a maintainer explicitly accepted the request and said it would be added. Keep this Backlog feature request open for implementation.

## Change summary

Add a user/workspace setting that controls how many request-error retries Copilot performs in auto-approve and Autopilot modes, including allowing zero retries.

## Best solution

Expose the existing retry cap as a bounded Chat setting, preserve three retries by default, and have ToolCallingLoop honor the configured value in both auto-approve and Autopilot modes. The behavior for deterministic BadRequest responses should be decided explicitly rather than treating every currently retryable response identically by accident.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `extensions/copilot/src/extension/intents/node/toolCallingLoop.ts`, `extensions/copilot/src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts`
- **Validation:** Extend the ToolCallingLoop Autopilot unit suite to verify the default limit remains three, zero disables retries, and a custom configured limit is enforced in both autoApprove and autopilot permission modes.
- **Behavior:**

  > Users can configure the maximum number of automatic request-error retries used by Copilot auto-approve and Autopilot sessions. The default remains three to preserve existing behavior, while zero disables automatic retries and positive values set the cap. The configured count is reflected accurately in retry logging and progress behavior, without changing the separate `chat.agent.maxRequests` turn limit.
- **Trace:**

  > ToolCallingLoop in extensions/copilot/src/extension/intents/node/toolCallingLoop.ts owns the retry counter, checks it in `shouldAutoRetry`, and currently compares and logs against the static `MAX_AUTOPILOT_RETRIES = 3`. The class already has IConfigurationService, so the setting can be consumed without a new service boundary. Core Chat settings, including the separate `chat.agent.maxRequests`, are registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. Existing retry-limit coverage is in extensions/copilot/src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts. Preserve the existing exclusions for rate limits, quota exhaustion, cancellation, off-topic responses, refusals, and inaccessible vision attachments; do not conflate this cap with agent/tool-call iteration limits.
- **Open decisions:**
  - Should the configured count govern every response currently considered retryable, including generic BadRequest responses, or should deterministic BadRequest failures be excluded unconditionally while the setting controls only transient failures?
