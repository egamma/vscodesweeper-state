# Issue #334809 — OS notification "Allow" confirms only one request when multiple confirmations are pending in the same turn

[https://github.com/microsoft/vscode/issues/334809](https://github.com/microsoft/vscode/issues/334809)

## Summary

Traced and confirmed in current source: the OS notification's 'Allow' action confirms only the first pending tool invocation and gives no signal that other confirmations remain, matching the report exactly. This is a real gap needing a maintainer/UX decision on the remedy, so routing to the chat area rather than auto-fixing.

## Change summary

When multiple tool confirmations are pending in one turn, the OS notification only ever offers/handles one 'Allow', silently leaving the rest unconfirmed with no indication anything remains.

## Best solution

In chatWindowNotifier.ts, either surface a remaining-confirmation count, switch the action to 'Open Session'/'Allow All' when more than one confirmation is pending, or have _confirmAllow drain all pending confirmations instead of returning after the first — a maintainer should pick the intended UX before implementing.

## Evidence

- **single-confirm bug:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts:255-269 `_confirmAllow` iterates `lastResponse.response.value` and calls `state.confirm(...)` on the first WaitingForConfirmation/WaitingForPostApproval part it finds, then `return`s — never confirming subsequent pending tool invocations.
- **no pending-carousel detection for multi-tool case:** `_isQuestionCarouselPending` (line 304) only checks for `questionCarousel` parts; when several `toolInvocation` parts are simultaneously awaiting confirmation there is no carousel, so the button stays labeled 'Allow' (line 180-182) and `_confirmAllow` silently drops the rest.
- **no remaining-state signal:** After `_confirmAllow` succeeds the code returns immediately (line 191-193) without checking whether `requestNeedsInput` is still true, so the notification and window badge give the user no way to notice more confirmations are pending.
