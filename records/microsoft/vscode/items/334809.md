# Issue #334809 — OS notification "Allow" confirms only one request when multiple confirmations are pending in the same turn

[https://github.com/microsoft/vscode/issues/334809](https://github.com/microsoft/vscode/issues/334809)

## Summary

Confirmed in source: when multiple confirmations are pending in the same turn, the OS notification's Allow action confirms only the first tool invocation and then suppresses further notification, leaving the user unaware that other confirmations are still pending.

## Change summary

With chat.notifyWindowOnConfirmation set to always/windowNotFocused, the OS notification's Allow button only resolves one of several simultaneously-pending tool confirmations, and no further signal appears for the rest.

## Best solution

In ChatWindowNotifier._confirmAllow (src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts), after confirming one pending invocation, check whether further confirmations remain for the session and, if so, either re-notify, change the toast action to 'Open Session'/'Allow All', or fall through to opening the session instead of returning early — the requestNeedsInput autorun only fires on a false→true transition so nothing re-prompts today.
