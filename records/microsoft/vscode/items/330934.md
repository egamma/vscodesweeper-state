# Issue #330934 — Setting to fully disable copilot advertisements

[https://github.com/microsoft/vscode/issues/330934](https://github.com/microsoft/vscode/issues/330934)

## Summary

Keep open: a maintainer explicitly accepted that promotional notifications should support type-level opt-out and Do Not Disturb, while current main still bypasses those controls. The newer notification-unification issue is related, but cannot be the duplicate canonical for this re-reviewed older report.

## Change summary

Provide a persistent way to disable all model promotional notifications and make them respect VS Code's Do Not Disturb preference.

## Best solution

Integrate model promotions with the workbench notification preference model so users can mute the promo type and global Do Not Disturb suppresses its in-chat and closed-chat surfaces, while retaining per-promotion dismissal.

- **Reason:** Using the established notification controls for Chat promotions advances consistent workbench interactions without adding another isolated preference model.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatPromoNotification.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputNotificationService.ts`, `src/vs/workbench/services/notification/common/notificationService.ts`, `src/vs/workbench/browser/parts/notifications/notificationsCommands.ts`, `src/vs/workbench/contrib/chat/test/browser/chatPromoNotification.test.ts`
- **Validation:** Extend the ChatPromoNotificationContribution tests to verify that an eligible promo is hidden when its notification type is muted and while global Do Not Disturb is active, then reappears when those filters are disabled without losing existing per-promo dismissal behavior.
- **Behavior:**

  > Users can disable promotional model notifications as a category without disabling Chat or unrelated notifications. Global Do Not Disturb also suppresses promotional banners and closed-chat promo affordances. Re-enabling the category restores eligible promotions, while promotions individually dismissed by the user remain dismissed. Existing model selection and non-promotional Chat notices remain unchanged.
- **Trace:**

  > Model promotions are collected and registered by ChatPromoNotificationContribution in src/vs/workbench/contrib/chat/browser/chatPromoNotification.ts through the independent IChatInputNotificationService defined in src/vs/workbench/contrib/chat/browser/widget/input/chatInputNotificationService.ts. That path currently considers session eligibility and chat.dismissedPromoIds but never the global or per-source filters maintained by NotificationService in src/vs/workbench/services/notification/common/notificationService.ts. The existing chat.closedPromoNotification setting only governs ChatStatusPromo on the Copilot icon and does not govern the in-chat notification. The maintainer direction is recorded at https://github.com/microsoft/vscode/issues/330934#issuecomment-5419348171, and the broader cross-surface design is tracked by the newer https://github.com/microsoft/vscode/issues/332650. Preserve in-chat placement, session scoping, and per-promo dismissal; do not turn this into a provider-disable control or suppress quota/error notifications.

## Evidence

- **maintainer direction:** https://github.com/microsoft/vscode/issues/330934#issuecomment-5419348171 records the maintainer decision that promo notifications should permit type-level opt-out and follow the existing Do Not Disturb preference.
- **current promo path:** src/vs/workbench/contrib/chat/browser/chatPromoNotification.ts registers eligible model promos directly with IChatInputNotificationService and checks only session visibility and per-promo dismissal; it does not consult INotificationService filters or a global promo opt-out.
- **partial existing setting:** chat.closedPromoNotification in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts controls only the Copilot-icon popup while Chat is closed. Its "none" value does not suppress the in-chat banner produced by ChatPromoNotificationContribution, so it does not satisfy the central request.
- **existing notification controls:** src/vs/workbench/services/notification/common/notificationService.ts persists global and per-source Do Not Disturb filters, while src/vs/workbench/browser/parts/notifications/notificationsCommands.ts exposes the corresponding global and by-source commands.
- **related design issue:** https://github.com/microsoft/vscode/issues/332650 is open and proposes unifying promo, usage, and tip controls with the notification service. It was created after this issue, so under the stronger re-review duplicate rule it cannot be the canonical duplicate for this older report.
