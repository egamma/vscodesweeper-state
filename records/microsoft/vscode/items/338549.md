# Issue #338549 — Sandbox on Ubuntu 26 with network disabled rejects even pwd command

[https://github.com/microsoft/vscode/issues/338549](https://github.com/microsoft/vscode/issues/338549)

## Summary

Fresh (1-day-old) team-authored bug report from a VS Code collaborator actively testing the new sandbox feature (follow-up to #338294); a maintainer already asked for details and got them, so this stays open for investigation rather than needs-info or any close — team-authored issues are protected from judgment closes and there is no fix commit yet.

## Change summary

With the agent sandbox enabled and network access disabled, even trivial commands like `pwd`/`ls` fail with EPERM because Bubblewrap's own setup issues an RTM_NEWADDR netlink call to configure the loopback interface, and the sandbox's network restriction blocks that call too.

## Best solution

The sandbox/seccomp policy that blocks network syscalls when 'disable network' is requested needs to special-case (or otherwise allow) Bubblewrap's own loopback-interface setup (the RTM_NEWADDR netlink message), so that basic commands still run inside a network-disabled sandbox on distros like Ubuntu 26.
