# Issue #243578 — 'Next Result' in document should be higher priority than 'Next Result' in search panel

## Summary

Keep open: current source explains how a custom F3 search binding can override document Find, but does not establish a core defect or a landed fix. The reported sequence supplies enough steps to retest; current defaults still use separate keys, and the reporter's precise binding and installed keymaps remain unverified.

## Change summary

When F3 is shared between workspace search and document Find, active document Find should take precedence over retained workspace search results.

## Best solution

Establish a context-scoped shared-key configuration that gives active document Find precedence while preserving workspace-result navigation outside that mode. Determine whether this needs a search/keymap change or is already handled by appropriate user binding conditions; preserve explicit user-override precedence in the general keybinding resolver.
