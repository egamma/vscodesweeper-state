# Issue #34621 — Unify indentation and formatting APIs

[https://github.com/microsoft/vscode/issues/34621](https://github.com/microsoft/vscode/issues/34621)

## Summary

The API gap remains: Reindent Lines still uses language indentation rules independently of formatting providers. The older formatter-backed indentation exploration is relevant, but does not clearly absorb this broader request to unify the APIs.

## Change summary

Unify indentation and formatting capabilities so indentation-only operations can benefit from formatter-quality language understanding without changing other content.

## Best solution

Define an indentation-only contract that language providers can support consistently across reindent and automatic indentation, preserving non-leading content and support for incomplete code. Coordinate that design with https://github.com/microsoft/vscode/issues/19847 rather than treating ordinary document formatting as equivalent.

- **Validation:** The plan should define executable editor tests using the issue's TSX example: indentation-only operations produce the agreed nesting while preserving every line's non-leading content. Include incomplete selections, unavailable providers, and existing format/reindent behavior; current indentation tests live in src/vs/editor/contrib/indentation/test/browser/indentation.test.ts.
- **Behavior:**

  > Users currently receive different indentation from Format Document and Reindent Lines because the operations use independent language capabilities. The goal is consistent language-aware indentation without allowing indentation-only operations to rewrite content after the leading whitespace. Acceptance must cover the reported nested TSX example, incomplete code, and languages without an applicable provider. Existing full-formatting commands must retain their broader formatting behavior.
- **Trace:**

  > ReindentLinesAction and ReindentSelectedLinesAction in src/vs/editor/contrib/indentation/browser/indentation.ts call getReindentEditOperations in src/vs/editor/contrib/indentation/common/indentation.ts, which exclusively uses language-configuration indentation rules. Automatic indentation also consults indentRulesSupport in src/vs/editor/common/languages/autoIndent.ts, whereas document formatting selects and invokes formatting providers in src/vs/editor/contrib/format/browser/format.ts. The public contracts remain separate in src/vscode-dts/vscode.d.ts. Existing format-on-type and format-on-paste settings invoke formatting rather than supplying a shared indentation-only contract. The older open exploration https://github.com/microsoft/vscode/issues/19847 documents unreliable whitespace-range formatting and incomplete-code concerns; coordinate the design there without assuming its conditional formatter-adoption scope resolves full API unification. No execution was performed; the source establishes the architectural gap, not whether the historical TSX output remains identical.
- **Open decisions:**
  - Should providers expose an explicit indentation-only capability, or should existing formatting contracts gain an indentation-only mode with a guarantee that non-leading content remains unchanged?
  - Which operations should adopt the shared capability: explicit reindent commands only, or automatic indentation during typing, paste, and line movement as well?
  - What observable fallback should apply when a provider cannot handle incomplete code or the requested range: existing language indentation rules or no indentation adjustment?
