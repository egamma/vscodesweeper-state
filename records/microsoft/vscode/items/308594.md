# Issue #308594 — Allow removal of image messages from context window.

[https://github.com/microsoft/vscode/issues/308594](https://github.com/microsoft/vscode/issues/308594)

## Summary

Keep open as a feature request for removing historical screenshots without rolling back agent edits. Current image-count filtering does not provide that control, and the related image-resizing request does not cover its full scope.

## Change summary

Allow users to remove image content from an existing chat's model context while preserving conversation progress and agent-authored files.

## Best solution

Provide a supported way to exclude historical image content from subsequent requests without undoing file edits or discarding intervening conversation. Coordinate with image-limit handling, but retain the distinction between preventing oversized-image failures and giving users control over existing screenshot history.

## Evidence

- **Requested recovery behavior:** https://github.com/microsoft/vscode/issues/308594 reports a many-image request rejected for dimensions exceeding 2000 pixels. The April 9 comment explains that tool screenshots accumulate and rolling back to the last user message can undo agent-authored files; the October 6 comment supplies a repeated-large-screenshot scenario but does not confirm current persistence.
- **Existing capability and limitation:** extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts calls validateAndFilterImages during createRequestBody. extensions/copilot/src/platform/endpoint/node/imageLimits.ts filters oldest historical images only when their count exceeds maxImages, preserves current-turn images, and throws when that turn alone exceeds the count limit. This is automatic count management, not user-directed removal or enforcement of the reported dimension threshold.
- **Rollback is not equivalent:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts explicitly warns that request removal can remove subsequent requests and undo edits. That recovery path does not satisfy the requested preservation of agent work.
- **Older related request, not full-scope canonical:** https://github.com/microsoft/vscode/issues/308148 is open and reports the same 2000-pixel API error, but requests automatic image downscaling. It does not own selective removal of existing historical screenshots while preserving conversation and files, so it does not absorb this re-reviewed request.
- **Other recovery work has different triggers:** https://github.com/microsoft/vscode/issues/311732 concerns MIME-mismatched tool images. https://github.com/microsoft/vscode/pull/331430 targets inaccessible uploaded attachment URLs and explicitly limits recovery to vision_attachment_not_accessible. Neither establishes coverage of oversized screenshot history or the requested removal control.
- **Provided cross-reference:** https://github.com/microsoft/vscode/issues/323088 is closed and concerns disabling tool definitions through Configure Tools and tool virtualization. Its discussion acknowledges existing tool-selection capabilities, not removal of image results already stored in conversation history.
