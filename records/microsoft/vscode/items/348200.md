# Issue #348200 — Agent host: first message after restoring a session disconnects and resumes the SDK session (clientPluginsChanged), ~1.7 s on a large session

[https://github.com/microsoft/vscode/issues/348200](https://github.com/microsoft/vscode/issues/348200)

## Summary

The unnecessary first-send restart remains supported by current source and an independent Windows reproduction. Address both history hydration and passive Canvas inventory; fixing history alone leaves another eager-resume path.

## Change summary

Restoring a Copilot agent-host session starts its SDK runtime before client customizations arrive, causing another disconnect/resume on the first message.

## Best solution

Restore saved history and preserve passive Canvas discovery without prematurely starting an execution runtime. The first send should use the published client customizations in its initial resume, while genuine configuration changes retain their existing refresh behavior.
