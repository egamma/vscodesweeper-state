# Issue #306370 — Entire session lost when selecting workspace

[https://github.com/microsoft/vscode/issues/306370](https://github.com/microsoft/vscode/issues/306370)

## Summary

This remains a source-reproducible bug: the standard Open Folder path reloads the window without invoking the workspace-transition event that migrates local chat sessions. A newer independent report confirms the same empty-window-to-folder failure on VS Code 1.135.0.

## Change summary

Opening a folder in the current window after starting a chat in an empty window makes that session inaccessible from the resulting workspace.

## Best solution

Preserve and restore the active local chat when Open Folder reuses an empty window, while retaining the existing workspace-scoped history behavior. Consolidate the newer report at https://github.com/microsoft/vscode/issues/333885 into this older issue and add coverage for the actual Open Folder reload path.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/workspaceActions.ts`, `src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts`, `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts`
- **Validation:** Add a workbench integration test that starts and persists a local chat in an empty window, follows the standard Open Folder same-window path, and verifies after reload that the session remains listed and can be reopened.
- **Behavior:**

  > A local chat started in an empty window must remain accessible after the user opens a folder in that same window. The active conversation and its history entry must survive the reload, while opening the folder in a separate window must preserve the existing empty-window session as well. Acceptance requires exercising the standard Explorer/File > Open Folder flow rather than only the add-folder or enterWorkspace flow.
- **Trace:**

  > OpenFolderAction in src/vs/workbench/browser/actions/workspaceActions.ts calls IFileDialogService.pickFolderAndOpen. The Electron implementation in src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts delegates directly to INativeHostService.pickFolderAndOpen, bypassing IWorkspaceEditingService.enterWorkspace and therefore onDidEnterWorkspace. ChatSessionStore in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts migrates empty-window sessions only from that event, so the reloaded folder window selects its workspace-scoped storage without receiving the prior session. Commit https://github.com/microsoft/vscode/commit/7393b0ec6071aca9ba95635a36588affb09db549 covers live workspace-ID transitions but not this native reload path; preserve its copy-not-move semantics and do not merge histories across unrelated workspaces.

## Evidence

- **current source path:** src/vs/workbench/browser/actions/workspaceActions.ts routes OpenFolderAction through IFileDialogService.pickFolderAndOpen; src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts then calls INativeHostService.pickFolderAndOpen directly. This path does not call IWorkspaceEditingService.enterWorkspace.
- **migration gap:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts migrates sessions only from IWorkspaceEditingService.onDidEnterWorkspace. That event is fired by enterWorkspace, so it does not cover the standard native Open Folder window-reload path.
- **prior partial fix:** Commit https://github.com/microsoft/vscode/commit/7393b0ec6071aca9ba95635a36588affb09db549 fixed https://github.com/microsoft/vscode/issues/289653 by migrating sessions during onDidEnterWorkspace, but it does not change the native Open Folder path described here.
- **independent current confirmation:** https://github.com/microsoft/vscode/issues/333885 reports the same observable behavior with explicit steps on VS Code 1.135.0: a chat started in an empty window disappears after Open Folder reuses that window, while the session remains visible from a new empty window.
- **no subsequent fix:** History after the 1.135.0 confirmation contains no relevant change to ChatSessionStore or the workspace-opening path, and no pull request references https://github.com/microsoft/vscode/issues/333885.
