# Issue #223606 — Auto indent issue: Lua multiline quotes `[[...]]` conflict with #210641 which removes brackets before passing text to indent rules

Consolidate this report into the older, still-open Lua indentation issue. Its discussion already documents the exact `if s == [[then]]` failure and bracket-stripping diagnosis, alongside incorrect indentation caused by string and comment contents.

## Change summary

## Evidence

- **Verified older canonical and identical symptom:** https://github.com/microsoft/vscode/issues/199223 is OPEN and was created on 2023-11-27, before this report. https://github.com/microsoft/vscode/issues/199223#issuecomment-2245272237 explicitly describes `if s == [[then]]` incorrectly indenting because the rule receives `if s == then`. This meets the re-review requirement of an older canonical with the same observable symptom.
- **Canonical scope:** https://github.com/microsoft/vscode/issues/199223#issuecomment-2244707897 covers both false-positive indentation from keywords in strings and false-negative indentation from comment contents or comment markers inside strings. https://github.com/microsoft/vscode/issues/199223#issuecomment-2247951065 also includes `local s = [[then]]` among its negative indentation cases.
- **Current source confirms the remaining defect:** src/vs/editor/common/languages/supports/indentationLineProcessor.ts, IndentationLineProcessor.getProcessedTokens, still removes configured brackets from String, RegEx and Comment tokens with `text.replace(bracketsRegExp, '')`. extensions/lua/language-configuration.json declares square brackets and keyword-based indentation rules. Consequently `if s == [[then]]` becomes `if s == then`, which matches the increase rule, while `if s == --[[then]] then` becomes `if s == --then then`, which the rule rejects. ProcessedIndentRulesSupport passes that processed text into indentation evaluation.
- **Closed implementation attempt, not a landed fix:** https://github.com/microsoft/vscode/pull/230632 explicitly attempted to fix both reports but is CLOSED and unmerged. In https://github.com/microsoft/vscode/pull/230632#issuecomment-2857806041, the maintainer rejected dynamically extracted keyword filtering because of compatibility risks for other language configurations and identified Tree-sitter indentation as a possible future direction.
- **Evidence to preserve:** https://github.com/microsoft/vscode/issues/223606#issuecomment-2252075743 identifies the `if"true"then` token-boundary hazard. https://github.com/microsoft/vscode/issues/223606#issuecomment-2253720009 proposes whitespace replacement and warns about all-string/comment lines and getPrecedingValidLine; these are useful constraints for the canonical issue, not an approved implementation.
