# Issue #314768 — Bug: diffEditor.wordWrap setting ignored in side-by-side "Resolve in merge editor" during cherry-pick

[https://github.com/microsoft/vscode/issues/314768](https://github.com/microsoft/vscode/issues/314768)

## Summary

The merge editor currently inherits ordinary editor wrapping settings rather than diffEditor.wordWrap. Keep this open as a configuration-consistency improvement: the source establishes that distinction, but not a maintainer decision rejecting the requested behavior.

## Change summary

Allow side-by-side merge-conflict panes to honor diffEditor.wordWrap independently of ordinary editor wrapping.

## Best solution

Have the merge-editor owner decide whether its comparison panes should follow diffEditor.wordWrap, including which setting governs the editable result pane. Preserve independent ordinary-editor wrapping rather than treating a global editor.wordWrap change as complete coverage of this request.

  > Thanks for the report. The merge editor currently uses `editor.wordWrap`, whereas the regular diff editor uses `diffEditor.wordWrap`. Setting `editor.wordWrap` to `off` controls wrapping in the merge editor too, but also changes ordinary editors, so it does not fully cover your request for an independent comparison preference. Keeping this open for the merge-editor owner to consider that consistency improvement.
