Add automated provider/result-rendering checks for description propagation and results without descriptions.
- **Behavior:**

  > Semantic search results should communicate why a code location is relevant to the natural-language query, rather than relying solely on a source fragment such as 'const api...'. Descriptions should be concise and specific to the result. Selecting a described result must still navigate to the correct code location, and ordinary text search must retain its existing presentation.
- **Trace:**

  > SearchPanelPrompt in extensions/copilot/src/extension/prompts/node/panel/searchPanelPrompt.tsx currently requests only file/query pairs. SemanticSearchTextSearchProvider.provideAITextSearchResults consumes those pairs for ranking, and reportSearchResults emits TextSearchMatch2 objects containing source previews. The workbench renderer in src/vs/workbench/contrib/search/browser/searchResultsView.ts displays those previews; the inspected AITextSearchProvider contract has no per-match description facility. The unresolved boundary is how generated descriptions coexist with source previews and travel through the provider-to-workbench result contract. Preserve result locations, ranking, and ordinary text-search behavior. https://github.com/microsoft/vscode/issues/284494 concerns heading-level cleanup and does not own this per-result feature.
- **Open decisions:**
  - Should the generated description replace the visible source-preview label or appear alongside it, and how should results without a description appear?
  - Should per-match descriptions be an optional capability of the AI search-provider result contract, or remain specific to the built-in Copilot integration?
