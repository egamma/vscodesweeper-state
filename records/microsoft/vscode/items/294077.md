- **Verified open canonical:** https://github.com/microsoft/vscode/issues/284417 is currently OPEN. Its scope includes remote read_file failures, outside-workspace errors, and create/edit failures when Copilot runs locally. https://github.com/microsoft/vscode/issues/284417#issuecomment-4261158357 diagnoses both Windows separator conversion and the platform-independent reconstruction of remote paths as file URIs; the latter covers this report.
- **Current source corroboration:** extensions/copilot/src/extension/tools/node/readFileTool.tsx invokes resolveToolInputPath; extensions/copilot/src/extension/tools/node/toolUtils.ts calls resolveFilePath without a predominant scheme. extensions/copilot/src/platform/prompts/common/promptPathRepresentationService.ts defaults that scheme to file and returns URI.file for absolute POSIX paths. Thus the canonical's URI-identity failure also applies on macOS when the tool runs locally; Windows separators are not required. No code was executed.
- **Discussion workaround:** https://github.com/microsoft/vscode/issues/294077#issuecomment-4242816703 reports success with the workaround at https://github.com/microsoft/vscode/issues/265804#issuecomment-3324914629, which places Copilot on the workspace extension host through remote.extensionKind. This corroborates the same local-versus-remote execution boundary, but is not evidence of a landed fix.
