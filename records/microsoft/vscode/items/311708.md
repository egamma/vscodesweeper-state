# Issue #311708 — [Error] unhandlederror-potential listener LEAK detected, popular — textModel / chatEditingModifiedNotebookEntry

[https://github.com/microsoft/vscode/issues/311708](https://github.com/microsoft/vscode/issues/311708)

## Summary

Still reproduces on main: the listener leak is caused by a race condition in `createInsertedCellDiffInfo` which calls `resolveCellModel` twice for the same cell URI concurrently, creating duplicate model references. The culprit commit (6cf846ce, PR #309093) that removed disposal of session references exacerbates the accumulation.

## Change summary

A listener LEAK is detected on `_languageConfigurationService.onDidChange` because notebook chat editing creates duplicate TextModel references per cell via concurrent calls to `resolveCellModel`.

## Best solution

Fix the double call in `createInsertedCellDiffInfo` (lines 755 and 769) by caching the promise from the first `resolveCellModel` call and reusing it for the `ObservablePromise`. Additionally, make `resolveCellModel` properly deduplicate concurrent async calls for the same URI (e.g. store the pending promise in the map instead of only the resolved model).
