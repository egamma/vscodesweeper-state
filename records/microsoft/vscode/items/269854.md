# Issue #269854 — NES doesn't render when jumping to next problem with F8

[https://github.com/microsoft/vscode/issues/269854](https://github.com/microsoft/vscode/issues/269854)

## Summary

Keep open: current source still suppresses next edit suggestions while the F8 problem peek is open. This accepted, team-authored request needs a coexistence design; existing display settings do not deliver it.

## Change summary

Make next edit suggestions discoverable and usable while navigating diagnostics with F8, without overlapping the problem peek.

## Best solution

Provide a non-overlapping NES presentation during problem navigation, with an explicit interaction for revealing or accepting the suggestion. Settle the compact presentation and peek-dismissal behavior before changing the editor's suppression policy.

- **Behavior:**

  > F8 problem navigation currently makes an available next edit suggestion disappear until the diagnostic peek closes. The intended improvement is to keep that suggestion discoverable and actionable without overlapping diagnostic content. Acceptance must cover the selected compact presentation, its keyboard interaction, and restoration of normal suggestion rendering when the peek closes. Ordinary problem navigation and suggestion acceptance outside this interaction must remain unchanged.
- **Trace:**

  > F8 invokes editor.action.marker.nextInFiles and MarkerController.navigate in src/vs/editor/contrib/gotoError/browser/gotoError.ts, which shows MarkerNavigationWidget from gotoErrorWidget.ts. That widget extends PeekViewWidget; src/vs/editor/contrib/peekView/browser/peekView.ts increments observableCodeEditor.openedPeekWidgets on construction and decrements it on disposal. InlineCompletionsModel in src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts returns undefined for inline edits whenever this count is positive, before inlineSuggestionsView.ts and inlineEditsView.ts can render them. Existing collapsed and long-distance settings do not overcome that gate. The discussion at https://github.com/microsoft/vscode/issues/269854 establishes that removing suppression alone produces overlapping UI; uncertainty begins at the replacement presentation and reveal interaction. Keep unrelated peek consumers and normal diagnostic navigation outside the chosen scope, and do not assume all peek widgets should acquire the same behavior.
- **Open decisions:**
  - While the F8 diagnostic peek remains open, should NES appear as a collapsed indicator, a long-distance preview, or alongside a redesigned compact diagnostic widget?
  - When the user invokes the suggestion's reveal or jump interaction, should the diagnostic peek close, remain visible in a coordinated layout, or defer full suggestion rendering until it closes?
