# Issue #334764 — Forked Skill subagents are invisible: no correlation handle from the tool call to the agent id

[https://github.com/microsoft/vscode/issues/334764](https://github.com/microsoft/vscode/issues/334764)

## Summary

Well-diagnosed gap confirmed directly in source: `SUBAGENT_TOOL_NAMES` in `claudeSubagentRegistry.ts` really is `new Set(['Task', 'Agent'])`, so a forked `Skill` call never gets a subagent chat channel, and the reporter is right that simply adding `Skill` to that set wouldn't help because none of the three resolver strategies can currently map a forked-skill tool call to its agent id.

## Change summary

Forked Skill subagents (e.g. `/code-review`) run as real Claude subagents but never surface as a subagent chat channel/card in the UI, so the parent chat narrates over content the user never sees.

## Best solution

This needs a maintainer decision on the correlation-handle approach (append the SDK's synthetic `agentId:` suffix to forked Skill results if the SDK supports it, or thread an agent id through to `SessionMessage`/a new lookup strategy) — belongs in `src/vs/platform/agentHost/node/claude/claudeSubagentRegistry.ts` and `claudeSubagentResolver.ts`, alongside the existing `TextSuffixStrategy`/`PromptMatchStrategy`/`ResultMatchStrategy` chain.

- **resolver chain gaps:** src/vs/platform/agentHost/node/claude/claudeSubagentResolver.ts defines TextSuffixStrategy (scans for the SDK's synthetic `agentId: <hex>` suffix), PromptMatchStrategy (matches on a `prompt` input field), and a placeholder NativeStrategy — none of which a Skill tool call (input `{skill: 'code-review'}`, no synthetic suffix in its own result text) can satisfy, corroborating the reporter's analysis of why naively adding 'Skill' to the set would create unresolvable entries.
