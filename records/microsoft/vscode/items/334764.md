# Issue #334764 — Forked Skill subagents are invisible: no correlation handle from the tool call to the agent id

[https://github.com/microsoft/vscode/issues/334764](https://github.com/microsoft/vscode/issues/334764)

## Summary

Well-diagnosed, source-verified gap: forked Skill subagents never get a subagent channel because `SUBAGENT_TOOL_NAMES` in claudeSubagentRegistry.ts only contains 'Task'/'Agent', so their work is silently invisible in the UI. Keeping open for a maintainer to pick between the two fix approaches the author outlines.

## Change summary

Forked Skill-tool subagent runs (e.g. `/code-review`) produce no subagent chat channel/card and no correlation handle from the parent tool call to the spawned agent id, so their work is invisible in the UI even though the assistant narrates over it.

## Best solution

Extend `SUBAGENT_TOOL_NAMES` (src/vs/platform/agentHost/node/claude/claudeSubagentRegistry.ts:21) to cover forked `Skill` calls, but only alongside a working correlation strategy — either have the SDK append the same synthetic `agentId: <hex>` suffix to forked Skill results so `TextSuffixStrategy` resolves them, or expose the agent id directly on the tool result / `SessionMessage` and add a matching lookup strategy in claudeSubagentResolver.ts. Note there is also an existing (undocumented by the reporter) `ResultMatchStrategy` in that file that compares result text to subagent transcripts — worth checking whether it already covers Skill calls before building a new strategy.
