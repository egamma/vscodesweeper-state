# Issue #324335 — GitHub Copilot "Response Contained No Choices" Using BYOK - Ollama, OpenRouter.ai

[https://github.com/microsoft/vscode/issues/324335](https://github.com/microsoft/vscode/issues/324335)

## Summary

Real, actively-investigated bug: multiple independent BYOK users (Ollama, OpenRouter, on-prem vLLM) hit 'Response contained no choices' when streaming ends without a usable finish reason; the triage bot's auto-duplicate to the generic #253136 'request failed' meta-issue was disputed by the reporter and doesn't match — no maintainer fix is visible on main.

## Change summary

Copilot Chat sometimes aborts BYOK requests with 'Response contained no choices' even though the backing model server streamed valid content, blocking chat usage entirely for affected users.

## Best solution

Have the extension team investigate stream termination handling in extensions/copilot/src/platform/networking/node/stream.ts (processSSEInner/finishSolutions) and chatMLFetcher.ts's success-finish-reason check — particularly the ClientIterationDone/ClientDone paths, which are excluded from `successFinishReasons` — against the concrete vLLM/Ollama traces users have attached, since comment 11 shows a case where a direct replay got a valid finish_reason:'stop' that VS Code still treated as no-choices.
