# Issue #324335 — GitHub Copilot "Response Contained No Choices" Using BYOK - Ollama, OpenRouter.ai

[https://github.com/microsoft/vscode/issues/324335](https://github.com/microsoft/vscode/issues/324335)

## Summary

Real BYOK bug confirmed across multiple providers (Ollama, OpenRouter) and by multiple users. The fallthrough path in chatMLFetcher.ts produces the 'Response contained no choices' error when streaming responses from third-party model servers end without a recognized finish reason. Several related open issues exist but this one adds unique Fiddler-captured HTTP payloads and multi-provider confirmation; keeping open as it carries the most actionable diagnostic data for the BYOK streaming path.

## Change summary

BYOK chat sessions with Ollama and OpenRouter fail with 'Response contained no choices' when the model server's streaming response ends without a finish reason the Copilot extension recognizes.

## Best solution

Harden the streaming response parser in `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts` (the `getResult` fallthrough at line ~1932) and `extensions/copilot/src/platform/networking/node/stream.ts` to gracefully handle edge cases from non-standard OpenAI-compatible providers — e.g. empty choices arrays, missing finish_reason fields, or protocol interruptions at end-of-stream. The Fiddler traces attached to this issue should inform which response shapes need coverage. Consolidate with https://github.com/microsoft/vscode/issues/313215 and https://github.com/microsoft/vscode/issues/318235 once a fix lands.

## Evidence

- **source trace:** The error originates at extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts line ~1932–1937: the `getResult` method falls through to `RESPONSE_CONTAINED_NO_CHOICES` when no completion has a recognized successful finish reason. The constant is defined in extensions/copilot/src/platform/chat/common/commonTypes.ts:116.
- **stream parser:** extensions/copilot/src/platform/networking/node/stream.ts line ~393 logs 'Unexpected response with no choices or error' when a streamed JSON chunk has neither choices nor an error field — common with non-standard OpenAI-compatible servers.
- **multi-provider confirmation:** Reporter reproduced with both Ollama (local) and OpenRouter.ai (cloud vLLM), and a second user (TheRealBecks) confirmed on Linux. A third commenter (Slion) linked the llama.cpp streaming protocol interruption issue: https://github.com/ggml-org/llama.cpp/pull/24202#issuecomment-5013471302
