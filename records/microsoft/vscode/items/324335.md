# Issue #324335 — GitHub Copilot "Response Contained No Choices" Using BYOK - Ollama, OpenRouter.ai

[https://github.com/microsoft/vscode/issues/324335](https://github.com/microsoft/vscode/issues/324335)

## Summary

Real, repeatedly-confirmed bug affecting BYOK streaming (Ollama, OpenRouter, vLLM, on-prem endpoints): the client gives up with 'Response contained no choices' even though the backend generated a valid response, because the stream never reaches a recognized success finish reason. Already correctly labeled bug/model-byok; a bot's earlier duplicate-close to the generic meta issue was rightly disputed by the reporter and shouldn't be revisited.

## Change summary

Using BYOK providers (Ollama, OpenRouter, vLLM/custom endpoints), chat requests intermittently fail with 'Response contained no choices' / 'Sorry, your request failed', discarding an otherwise valid model response.

## Best solution

Investigate extensions/copilot/src/platform/networking/node/stream.ts and extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts (around the successFinishReasons check at chatMLFetcher.ts:1895-1943) for cases where a stream ends without ever setting a recognized finish reason (e.g. a trailing spec-compliant empty-choices usage chunk, or a mid-stream disconnect after content was already accumulated as diagnosed in comment https://github.com/microsoft/vscode/issues/324335#issuecomment- by TjWheeler) and make the parser tolerant of those, so already-generated content isn't discarded.

## Evidence

- **no-choices fallback:** extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts:1895-1943 returns ChatFetchResponseType.Unknown/RESPONSE_CONTAINED_NO_CHOICES whenever no completion has finishReason in {Stop, ClientTrimmed, FunctionCall, ToolCalls} — this is the exact error text and stack (`_provideLanguageModelResponse`) reported.
- **stream parser:** extensions/copilot/src/platform/networking/node/stream.ts handles `choices: []` chunks (introduced by vLLM's spec-compliant trailing usage-only chunk) by looping zero times, which on my read looks harmless — so the precise trigger for content being lost is not fully pinned down from source alone; needs live tracing against a BYOK backend to confirm.
- **detailed community diagnosis:** Comment by TjWheeler (2026-08-06) traces a 100%-reproducible vLLM case via the Chat Debug View: model generates valid content (finish_reason: stop, completion_tokens: 21) but VS Code records empty content, pointing at the custom-endpoint stream handler.
- **multiple independent confirmations:** TheRealBecks, rahbari, congard, and Slion all report the same 'Response contained no choices' failure across different BYOK backends (Ollama, OpenRouter with Opus 5/Nemotron 3, on-prem vLLM) and VS Code versions 1.127.0-1.130.0.
- **disputed bot duplicate:** vs-code-engineering[bot] proposed duplicate of https://github.com/microsoft/vscode/issues/253136, a broad generic 'Sorry, your request failed' meta bucket covering many unrelated causes (preview-model outages, service disruption) — the reporter correctly objected since this is BYOK-specific across multiple providers, and no maintainer has since agreed with the duplicate.
