Many of the originally requested policies have been implemented (AllowedExtensions, ExtensionsAutoUpdate, ExtensionGalleryServiceUrl, etc.), but the issue has evolved into a discussion about Intune/ADMX deployment failures (0x20101 errors) caused by Windows CSP restrictions on the registry path — an upstream platform limitation. ## Change summary

Request for additional enterprise Group Policy settings and working Intune ADMX deployment for VS Code.

## Best solution

The remaining gap is Intune ADMX compatibility (the Windows CSP blocks the VS Code registry path). VS Code should either coordinate with the Windows/Intune team to allowlist the registry path, document the workaround (pre-creating the registry folder or using remediation scripts), or consider whether the settings sync disable policy and mandatory extensions list are still missing. The Intune deployment issue itself is tracked partly in https://github.com/microsoft/vscode/issues/281840.
