# Issue #320027 — More visibility into boundary between "short context cost" and "long context cost" in meter

[https://github.com/microsoft/vscode/issues/320027](https://github.com/microsoft/vscode/issues/320027)

## Summary

The cost-tier boundary remains absent from the current context meter, while a maintainer has already solicited design input on the request. The related billing issues do not meet the stronger duplicate bar because they address billing explanation broadly rather than this same meter-visibility symptom.

## Change summary

Show chat context usage relative to the token threshold where long-context pricing begins.

## Best solution

When a selected model has a genuine long-context surcharge, expose its default-tier threshold in the always-visible context indicator and identify the active pricing tier accessibly. The compact visual treatment should be settled with the chat UX owner before implementation.

- **Behavior:**

  > For a model with distinct default and long-context pricing, users can see at a glance where current context usage sits relative to the pricing boundary without opening the details hover. Existing percentage, output-reserve, warning, and session-cost behavior remains intact.
- **Trace:**

  > The compact meter is ChatContextUsageWidget and CircularProgressIndicator in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts; it currently receives a selected context-window denominator and renders only the resulting percentage. The upstream model path already distinguishes default and long windows in src/vs/platform/agentHost/common/agentModelConfiguration.ts and distinct prices in agentModelPricing.ts. The boundary is the existing context-usage UI and its data contract: do not alter billing calculation, model selection, compaction behavior, or models without a surcharge. The uncertainty starts at the compact, always-visible representation and its accessible equivalent.
- **Open decisions:**
