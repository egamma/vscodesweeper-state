# Issue #330006 — Security: vulnerable dependency image-size (CVE-2025-71329/71330) — maintained drop-in available

[https://github.com/microsoft/vscode/issues/330006](https://github.com/microsoft/vscode/issues/330006)

## Summary

This is a security-sensitive dependency report, so per policy it stays open for a human to evaluate rather than being auto-closed — but the technical basis is weak: VS Code's emmet extension pins `image-size` at `~1.0.0` (extensions/emmet/package.json), and the cited CVEs (JXL/HEIF/ICNS parser infinite loops) affect parser code added in later 1.x/2.x releases, so v1.0.0 likely never executes the vulnerable code paths.

## Change summary

Reporter asks VS Code to replace the `image-size` dependency in the emmet extension with an unofficial fork (`image-size-next`) to avoid two DoS CVEs affecting image-size up to 2.0.2.

## Best solution

A maintainer should verify whether image-size@1.0.0 actually contains the vulnerable JXL/HEIF/ICNS parsing code (search history at github.com/image-size/image-size for when those formats were added); if not affected, this can be declined as not applicable. Regardless, adopting an unaudited, newly-created fork authored by the same person filing the report is not something to do without independent vetting — this looks like it may be a self-promotional security-advisory campaign (the reporter's username matches the fork's GitHub author) rather than a vetted remediation path.
