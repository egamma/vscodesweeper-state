# Issue #225613 — `cursorTop` and `cursorBottom` (Command+UP/DOWN) occasionally stop working in source editors

[https://github.com/microsoft/vscode/issues/225613](https://github.com/microsoft/vscode/issues/225613)

## Summary

This is the same intermittent Command+Up/Down interception already tracked by the verified open canonical issue https://github.com/microsoft/vscode/issues/200259. Consolidate there, preserving this report's TS/JS editor context and keyboard trace.

## Change summary

Command+Up/Down intermittently invokes widget navigation instead of moving the caret to the beginning or end of a source editor.

## Best solution

Track the remaining focus-state defect in https://github.com/microsoft/vscode/issues/200259 so editor cursor commands remain available when no navigable widget container actually has focus.

- **Maintainer consolidation precedent:** https://github.com/microsoft/vscode/issues/201154 reports cmd+arrow being hijacked by widget navigation and links the same originating PR, https://github.com/microsoft/vscode/pull/187077. - **Current source boundary:** src/vs/workbench/browser/actions/widgetNavigationCommands.ts still registers widgetNavigation.focusPrevious/focusNext on CtrlCmd+UpArrow/DownArrow using navigableContainerFocused and list-focus/boundary conditions. NavigableContainerManager maintains that context from grouped focus/blur events. This matches the reported interception mechanism, but source inspection alone does not establish the intermittent trigger or a completed fix.
