# Issue #203003 — Test runners in vscode are much slower than pycharm

[https://github.com/microsoft/vscode/issues/203003](https://github.com/microsoft/vscode/issues/203003)

## Summary

Multiple independent reports, including a March 2026 comparison of 858 seconds versus 87 seconds, confirm substantial large-suite overhead and UI stalls. The Backlog milestone does not block continued investigation, and the issue is already routed appropriately.

## Change summary

Running large Python test suites through VS Code's Testing UI is substantially slower and more resource-intensive than running the same suites directly.

## Best solution

Profile the Python test adapter and core Testing API pipeline separately, then batch or coalesce per-test state, duration, output, and tree updates where they dominate runtime. Add a large-suite benchmark covering execution time and workbench responsiveness, coordinating any generic Testing UI work with https://github.com/microsoft/vscode/issues/238241.

## Evidence

- **independent confirmations:** Reports across Windows, WSL, and native Linux describe slowdowns ranging from roughly 2× to 25×, including reproducible public projects and suites exceeding 500 tests.
- **current confirmation:** https://github.com/microsoft/vscode/issues/203003#issuecomment-4045685174 reports 15,652 tests taking 858.1 seconds through VS Code versus 87 seconds in its integrated PowerShell terminal, while the workbench, Pylance, and file search become intermittently unresponsive.
- **core update path:** src/vs/workbench/api/common/extHostTesting.ts sends an RPC for every TestRun.started/passed/failed state mutation; src/vs/workbench/contrib/testing/common/testResult.ts then refreshes computed state and duration and emits UI-facing changes for each update.
- **related generic defect:** https://github.com/microsoft/vscode/issues/238241 remains open and identifies frequent test-tree state and duration updates as a major bottleneck for thousands of tests, but it does not conclusively account for all Python-specific execution overhead reported here.
- **maintainer signal:** https://github.com/microsoft/vscode/issues/203003#issuecomment-1912402838 records a maintainer acknowledging performance improvement ideas and planning further investigation.
