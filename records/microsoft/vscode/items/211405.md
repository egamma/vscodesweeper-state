# Issue #211405 — onDidChangeTabGroups not fired when switching focus between floating window and main window

[https://github.com/microsoft/vscode/issues/211405](https://github.com/microsoft/vscode/issues/211405)

## Summary

Still a real gap on current main: `MainThreadEditorTabs` only reacts to editor-group *model* events, and moving focus between an auxiliary (floating) window and the main window never produces one, so no tab-group update is sent to the extension host. Team-authored bug in the Backlog milestone with no fix commit — keep open.

## Change summary

`vscode.window.tabGroups.onDidChangeTabGroups` does not fire when focus moves between a floating editor window and the main window, even though the active tab group changes.

## Best solution

Have `MainThreadEditorTabs` also listen to `IEditorGroupsService.onDidChangeActiveGroup` (which `EditorParts` already fires on part focus) and run its `_onDidGroupActivate` path so the newly active group is pushed to the extension host via `$acceptTabGroupUpdate`.

  > Root cause: `MainThreadEditorTabs` (src/vs/workbench/api/browser/mainThreadEditorTabs.ts) learns about group activation only through `editorService.onDidEditorsChange` -> `_updateTabsModel` case `GroupModelChangeKind.GROUP_ACTIVE` -> `_onDidGroupActivate`, which calls `this._proxy.$acceptTabGroupUpdate`; the ext-host side then fires `onDidChangeTabGroups` (src/vs/workbench/api/common/extHostEditorTabs.ts, `$acceptTabGroupUpdate` around line 359). ## Evidence

- **event source gap:** src/vs/workbench/api/browser/mainThreadEditorTabs.ts constructor subscribes only to `editorService.onDidEditorsChange` (plus onDidAddGroup/onDidRemoveGroup); active-group handling runs through `_updateTabsModel` case `GroupModelChangeKind.GROUP_ACTIVE` -> `_onDidGroupActivate`. It never subscribes to `IEditorGroupsService.onDidChangeActiveGroup`.
- **no model event on cross-window focus:** `EditorPart.doSetGroupActive` (src/vs/workbench/browser/parts/editor/editorPart.ts) only calls `group.setActive(true)` — the source of `GroupModelChangeKind.GROUP_ACTIVE` in src/vs/workbench/common/editor/editorGroupModel.ts `setGroupActive()` — when `this._activeGroup !== group`. Switching windows does not change the active group *within* a part, so no GROUP_ACTIVE is emitted and `editorService.onDidEditorsChange` (fired only from per-group model listeners, src/vs/workbench/services/editor/browser/editorService.ts `registerGroupListeners`) stays silent.
- **signal that is available but unused:** src/vs/workbench/browser/parts/editor/editorParts.ts `registerEditorPartListeners` fires `_onDidActiveGroupChange` on `part.onDidFocus` when more than one part exists — exactly the floating-vs-main focus switch — but nothing in mainThreadEditorTabs consumes it.
