# Issue #130344 — GitHub - Add Github Enterprise support for Git VCS provider

[https://github.com/microsoft/vscode/issues/130344](https://github.com/microsoft/vscode/issues/130344)

## Summary

The requested integration is still missing: Enterprise authentication exists, but the built-in GitHub credential provider still accepts only github.com. Keep this accepted Backlog request open in the GitHub area.

## Change summary

Let built-in Git operations obtain credentials from GitHub Enterprise authentication, including compatibility with servers that lack the workflow OAuth scope.

## Best solution

Connect the built-in GitHub credential provider to the authentication session for the configured Enterprise instance matching the Git remote. Preserve github.com behavior and avoid requiring OAuth scopes unsupported by older Enterprise servers.

- **Authentication and scope boundary:** extensions/github/src/auth.ts: getSession requests the github authentication provider, not github-enterprise, with repo, workflow, user:email, and read:user scopes. The Enterprise integration and older-server scope compatibility requested in https://github.com/microsoft/vscode/issues/130344 are not covered by this path.
- **Existing settings do not satisfy the request:** extensions/github/package.json registers github.gitAuthentication as an enablement toggle, not an Enterprise selector. extensions/github-authentication/README.md documents github-enterprise.uris and account selection, but configuring Enterprise authentication does not bypass the github.com-only credential-provider check.
- **Git credential consumption:** extensions/git/src/askpass.ts: Askpass.handleAskpass invokes registered credential providers for HTTPS username requests and caches returned credentials for the password request. The GitHub provider supplies nothing for Enterprise hosts, leaving the generic input prompt unless another credential mechanism handles authentication.
