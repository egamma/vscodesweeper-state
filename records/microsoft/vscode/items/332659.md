# Issue #332659 — Next/Previous word selection does not respect newlines correctly

[https://github.com/microsoft/vscode/issues/332659](https://github.com/microsoft/vscode/issues/332659)

## Summary

Confirmed intentional behavior in cursorWordOperations.ts: moveWordRight/moveWordLeft deliberately skip past leading whitespace and land on the next word's start/end rather than stopping at the line boundary. The reporter frames this as a longstanding, by-design quirk and asks for an opt-out setting rather than claiming a bug, so this is a feature request, not a defect.

## Change summary

Ctrl+Left/Right word navigation skips past the newline and any next-line indentation instead of stopping at the start/end of the line, with no setting to change this.

## Best solution

This is a maintainer/product call: either add a setting to make word navigation stop at line boundaries before jumping into the next word, or close as *as-designed if the team confirms the current cross-line word-skip is intentional and matches other editors' word-navigation semantics closely enough. Belongs in src/vs/editor/common/cursor/cursorWordOperations.ts (moveWordRight/moveWordLeft) plus a new editor.* configuration option if pursued.
