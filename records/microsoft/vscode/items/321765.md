# Issue #321765 — Custom agent frontmatter is not automatically loaded on VSCode startup.

[https://github.com/microsoft/vscode/issues/321765](https://github.com/microsoft/vscode/issues/321765)

## Summary

The startup discovery bug remains current: the reporter reconfirmed it on 1.137 after a merged cancellation-cache fix intended to address this issue. Keep it open for a deeper diagnosis of the workspace-dependent discovery and cached-mode startup sequence.

## Change summary

After restarting or reloading VS Code, some workspace custom agents retain incomplete metadata until their `.agent.md` files are saved again.

## Best solution

Make initial custom-agent discovery publish a complete metadata snapshot and ensure the startup refresh replaces persisted chat modes with that snapshot. First capture the still-failing startup sequence because the existing cancellation regression test does not cover the reporter's remaining trigger.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`, `src/vs/workbench/contrib/chat/common/customizationHarnessService.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/service/promptsService.test.ts`, `src/vs/workbench/contrib/chat/test/common/chatModeService.test.ts`
- **Validation:** Add a regression test that reproduces the diagnosed restart/reload sequence with multiple custom agents and asserts that every agent's description, model, tools, and invocation visibility reach ChatModeService without a file-change event; run it with `./scripts/test.sh --grep "custom agent startup discovery"`.
- **Behavior:**

  > After VS Code starts or the window reloads, every valid workspace custom agent is immediately available with its complete frontmatter metadata. Selecting an agent applies its configured model and tools, while agents marked `user-invocable: false` do not appear in the user-facing picker but remain available where model invocation permits. Saving an unchanged agent file must not be necessary to obtain correct metadata. Existing behavior for malformed, disabled, or genuinely canceled discoveries remains unchanged.
- **Trace:**

  > Custom-agent metadata is produced by `PromptsService.computeAgentDiscoveryInfo` in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts and shared through `CachedPromise`. `ChatModeService` in src/vs/workbench/contrib/chat/common/chatModes.ts first revives persisted modes, then asynchronously refreshes them through `CustomizationHarnessServiceBase.getCustomAgents` in src/vs/workbench/contrib/chat/common/customizationHarnessService.ts. Commit cc293c6ea513f0c68132c4007028d5b03b69beb2 made cancellation reject discovery rather than cache partial results and added a two-file retry test, but the reporter reproduced the bug afterward on 1.137. The uncertainty starts at identifying which workspace/startup event still yields an incomplete discovery or prevents the complete result from replacing persisted mode data. Preserve normal file-watcher refresh, malformed-file handling, session-type filtering, and non-user-invocable subagent availability.
