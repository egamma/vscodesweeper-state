## Evidence

- **existing behavior:** src/vs/platform/windows/electron-main/windowsMainService.ts shouldOpenNewWindow(): on Linux/Windows, `default` (the setting is neither 'on' nor 'off') opens files in a new window unless the context is DIALOG or MENU, or the open comes from the integrated terminal. That matches the request: CLI and Explorer open a new window, Ctrl+O reuses the window.
- **macOS gap:** On macOS only OpenContext.DOCK (Finder or Dock) opens in a new window under `default`. A command-line open is not covered.
- **setting docs:** src/vs/workbench/browser/workbench.contribution.ts lists `default` as 'Files will open in a new window unless picked from within the application (e.g. via the File menu)'. The reporter only mentions `on` and `off`, so they may not have tried it.
- **dialogs:** src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts forces a new window only when the setting is `on`, so `default` leaves the native dialog open-in-current-window.
