# Issue #179079 — Jupyter Notebook (VS Code) warning about "bogus" screen size.

[https://github.com/microsoft/vscode/issues/179079](https://github.com/microsoft/vscode/issues/179079)

## Summary

The warning matches a documented WSL terminal-dimension defect rather than a notebook rendering defect. Keep this open as upstream until current WSL behavior is confirmed or corrected.

## Change summary

Starting Spark from a Jupyter kernel under WSL emits a bogus 131072x1 screen-size warning.

## Best solution

WSL should return no terminal or sensible dimensions for processes launched with redirected standard streams. After an upstream correction, verify the SparkSession scenario with current WSL and Jupyter versions.

  > Thanks for the report. This matches the WSL terminal-dimension behavior documented in https://github.com/microsoft/WSL/issues/10701: processes launched with redirected streams can receive a 1x1 terminal size, which causes `ps`/procps to emit the 131072x1 warning. VS Code already suppresses the same warning in its own process-enumeration path, but that workaround does not cover `ps` launched by Spark. Keeping this tracked as an upstream issue pending confirmation with current WSL and Jupyter versions.

## Evidence

- **upstream diagnosis:** https://github.com/microsoft/WSL/issues/10701 documents the exact warning and traces it to WSL returning a 1x1 TIOCGWINSZ result when launched without a console or with redirected output; procps converts that into the reported 131072x1 warning.
- **VS Code precedent:** https://github.com/microsoft/vscode/issues/145354 investigated the same warning; a terminal maintainer reported that VS Code does not set the PTY to 131072x1 and identified WSL or process execution as the likely owner.
- **current source:** src/vs/base/node/ps.ts:223-228 still contains a narrow workaround that suppresses this warning only for VS Code's own process enumeration. It does not control the ps invocation initiated during Spark startup.
