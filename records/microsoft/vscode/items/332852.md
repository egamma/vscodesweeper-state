# Issue #332852 — Search query persistence is inconsistent across file switches

[https://github.com/microsoft/vscode/issues/332852](https://github.com/microsoft/vscode/issues/332852)

## Summary

Traced in the source: CommonFindController's `onDidChangeModel` handler (src/vs/editor/contrib/find/browser/findController.ts) deliberately resets `matchCase`, `wholeWord`, `isRegex`, `preserveCase`, and `searchScope` on a file switch, but intentionally leaves `searchString` untouched — the find term is bound to the editor widget instance (shared across tabs in the same pane), not the file, so it carries over by design.

## Change summary

The find widget keeps the previous file's search term when switching to a different file instead of resetting or using a per-file term.

## Best solution

Keep current behavior — the find term is intentionally sticky to the editor widget so users can quickly repeat a search across files; this mirrors common editor/browser find behavior. If per-file memory is genuinely wanted, that would need a new opt-in behind `editor.find.*` settings rather than a bug fix.
