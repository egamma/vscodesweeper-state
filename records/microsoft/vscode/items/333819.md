# Issue #333819 — Confirmation request is shown in wrong chat

[https://github.com/microsoft/vscode/issues/333819](https://github.com/microsoft/vscode/issues/333819)

## Summary

Real bug with a traced root cause: when two chat widgets (e.g. the main chat view and the agent-sessions welcome page opened via `workbench.startupEditor: agentSessionsWelcomePage`) show the same session resource, `ChatWidgetService.getWidgetBySessionResource` returns the first matching widget by `.find()`, so a confirmation can resolve to the wrong widget/location.

## Change summary

A tool/agent confirmation for an ongoing chat session is rendered in the agent-sessions welcome page instead of the chat view the user is actively using.

## Best solution

Extend widget resolution so content parts route confirmations to the widget that actually rendered them (e.g. propagate location through `IChatContentPartRenderContext` and filter `getWidgetBySessionResource` by location), matching the approach already sketched in the closed PR https://github.com/microsoft/vscode/pull/333838, which was closed unmerged.
