# Issue #337824 — Model picker jumps around when the selection changes

[https://github.com/microsoft/vscode/issues/337824](https://github.com/microsoft/vscode/issues/337824)

## Summary

Team-authored, same-day bug report; a hard keep-open rule applies regardless (no fix commit exists yet to satisfy the mechanical-close bar for team-authored issues). The reordering mechanism is traceable in the model-picker code, but the actual fix needs a product decision about ordering stability.

## Change summary

In the chat model picker, selecting a different model causes the list of items to reorder/jump, so the picker isn't stable under the cursor across selections.

## Best solution

Decide whether the picker's item order should be computed once per open (a stable snapshot) versus recomputed live on every selection change, then adjust modelPickerItemSections.ts's promoted/recent placement accordingly.

- **Behavior:**

  > When the chat model picker is open and the user changes the selected model (e.g. via arrow keys or click), the list of items should not visually reorder/jump — items should stay in the same relative position so the picker remains stable under the cursor. Acceptance: a test confirms item order is unaffected by a selection change within the same picker session.
- **Trace:**

  > appendPromotedModels() in modelPickerItemSections.ts promotes the current options.selectedModelId (line 270-273) and the first 3 options.recentModelIds (line 274) into a 'Promoted' section that appears above the general/other model sections. Because selectedModelId changes on every selection, a model not previously in that section gets pulled in, shifting the whole list. Confirmed by reading the code; no related fix commit found via git log. The boundary: don't touch the pinned-models section (appendPinnedModels, line ~212) or the deterministic name/vendor sorting used elsewhere — those are unrelated and working as intended. Where uncertainty starts: whether the desired fix is to freeze the full item list as a snapshot for the picker's open lifetime, or to keep live promotion but suppress re-sorting motion for already-visible items.
- **Open decisions:**
  - Should the model picker's overall item order be frozen as a snapshot for the duration the picker stays open (recomputed only on next open), or should it keep updating live based on the newly selected model but avoid moving items that are already visible?
  - If frozen, should the current selection still get any special highlight/scroll behavior without changing list order?
