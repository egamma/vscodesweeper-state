# Issue #239748 — Sort installed extensions by "Last Released"

[https://github.com/microsoft/vscode/issues/239748](https://github.com/microsoft/vscode/issues/239748)

## Summary

The requested sort remains absent on current main, while the marketplace metadata needed to represent “Last Released” already exists. This is accepted Backlog work with supporting demand and no open canonical issue, so it should remain open for extensions-area design.

## Change summary

Allow installed extensions to be sorted by the marketplace date of their latest release rather than their local installation/update timestamp.

## Best solution

Add a Last Released sort for installed extensions using marketplace release metadata, with defined behavior for pre-release channels and extensions whose marketplace metadata is unavailable. Keep local Updated Date sorting distinct because it represents installation state rather than publisher activity.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/common/extensionQuery.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsViews.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsViews.test.ts`
- **Validation:** Add an ExtensionsListView unit test for `@installed @sort:lastReleasedDate` that orders fixtures by gallery `lastUpdated` and covers the maintainer-selected behavior for missing metadata and stable versus pre-release channels.
- **Behavior:**

  > Users viewing installed extensions can sort by the date each extension was last released in the marketplace. This remains distinct from Updated Date, which reflects when the local installation changed, and from Published Date, which reflects initial publication. Reinstalling an old extension must not make it appear recently released. The resulting order must be deterministic for extensions without marketplace metadata and for extensions offering stable and pre-release versions.
- **Trace:**

  > Query suggestions are defined in src/vs/workbench/contrib/extensions/common/extensionQuery.ts, while ExtensionsListView.show maps sort names and ExtensionsListView.sortExtensions orders local results in src/vs/workbench/contrib/extensions/browser/extensionsViews.ts. The Sort By menu is registered in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts. Marketplace `IGalleryExtension.lastUpdated` already exists and is displayed as “Last Released” by ExtensionEditor.renderMarketplaceInfo in src/vs/workbench/contrib/extensions/browser/extensionEditor.ts; installed extensions are associated with gallery records by ExtensionsWorkbenchService.syncInstalledExtensionsWithGallery. Preserve the existing meanings of `publishedDate` and `updateDate`, and do not expand this issue into repository-archive or abandonment scoring. Related display requests https://github.com/microsoft/vscode/issues/41404 and https://github.com/microsoft/vscode/issues/70736 are closed and do not own this remaining sort capability.
- **Open decisions:**
  - Should Last Released use the latest release across all channels, or the latest release in the user's selected stable/pre-release channel?
  - Where should installed extensions without current marketplace release metadata appear in the ordering?
