# Issue #273381 — Git - repository with directory junction does not mark changed files inside that junction as modified without reloading extensions

[https://github.com/microsoft/vscode/issues/273381](https://github.com/microsoft/vscode/issues/273381)

## Summary

Real bug: the Git extension's file system watcher (via Parcel watcher) does not detect changes inside Windows directory junctions that point outside the repository root, because the watcher only monitors the real path of the repo root and doesn't follow junctions into external directories. The issue is correctly labeled and milestoned; no fix has landed on main.

## Change summary

Files inside a Windows directory junction within a Git repository are not marked as modified until VS Code is reloaded, because the file watcher doesn't follow junctions pointing outside the repo root.

## Best solution

The fix likely needs to happen in the file watcher layer (src/vs/platform/files/node/watcher/parcel/parcelWatcher.ts) or the Git extension's repository watcher setup (extensions/git/src/repository.ts). The watcher would need to detect junctions/symlinks inside the watched tree and set up additional watch requests for their targets. This is a long-standing limitation of file-system-level watchers — Parcel watcher already acknowledges it at line 702-703: 'the Parcel watcher does not allow to recursively watch symbolic links.'
