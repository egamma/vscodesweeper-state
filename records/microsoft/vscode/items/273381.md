# Issue #273381 — Git - repository with directory junction does not mark changed files inside that junction as modified without reloading extensions

[https://github.com/microsoft/vscode/issues/273381](https://github.com/microsoft/vscode/issues/273381)

## Summary

Keep open: the current Git refresh path depends on recursive file events that do not follow junctions nested inside the repository. Initial status scanning explains why reopening restores the missing decorations; no verified fix or same-symptom canonical was found.

## Change summary

Saved changes to tracked files beneath an in-repository Windows directory junction should update Git status and Explorer decorations without restarting VS Code.

## Best solution

Make the built-in Git integration refresh tracked junction descendants reliably while preserving the file-watching API's existing symlink semantics. First establish Windows coverage for target changes and junction-path attribution, rather than changing shared recursive watching indiscriminately.

- **Trace:**

  > Repository construction in extensions/git/src/repository.ts creates a recursive watcher at repository.root; working-tree events invoke onFileChange and eventually status(). The file-watching API explicitly does not follow nested symbolic links, and ParcelWatcher normalizes only the requested root, leaving an external junction target outside this watch coverage. Model.openRepository in extensions/git/src/model.ts independently runs initial status, while GitDecorationProvider rebuilds its cache on onDidRunGitStatus, explaining the reload recovery.
