# Issue #345860 — MCP OAuth: when one window re-registers after a 401/403, every other window's dynamic auth provider breaks (TokenStore set to undefined, "reading 'map'"), sends no token and gets 401 until reloaded

[https://github.com/microsoft/vscode/issues/345860](https://github.com/microsoft/vscode/issues/345860)

## Summary

The reported token-store corruption is present on current main: deleting a dynamic provider's secret propagates undefined into an array-valued observable. Keep this open; the detailed multi-window reproduction and matching source establish an actionable core authentication defect.

## Change summary

Prevent dynamic OAuth provider removal in one window from corrupting token stores and blocking MCP authentication in other windows.

## Best solution

Ensure deleted token storage produces a valid empty-session state throughout the authentication bridge, with subsequent session reads and token updates remaining usable without reloading. Preserve existing registration and authorization behavior; automatic adoption of another client's registration is a separate enhancement.
