# Issue #345860 — MCP OAuth: when one window re-registers after a 401/403, every other window's dynamic auth provider breaks (TokenStore set to undefined, "reading 'map'"), sends no token and gets 401 until reloaded

[https://github.com/microsoft/vscode/issues/345860](https://github.com/microsoft/vscode/issues/345860)

## Summary

Keep open: current source confirms that deleting shared OAuth credentials sends undefined into another window's TokenStore, breaking session reads and subsequent authentication. The supplied reproduction is complete, and the reviewed related reports concern different failures.

## Change summary

Prevent MCP OAuth re-registration or provider removal in one window from poisoning authentication state in other windows.

## Best solution

Treat deleted token storage as a valid no-session state throughout the dynamic authentication event path, keeping existing windows capable of authenticating again without reloading. Automatic adoption of a replacement client registration is a separate enhancement, not required to eliminate the exception.
