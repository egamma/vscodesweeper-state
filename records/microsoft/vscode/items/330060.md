# Issue #330060 — Clicking on a file that's getting generated shows an error

[https://github.com/microsoft/vscode/issues/330060](https://github.com/microsoft/vscode/issues/330060)

## Summary

The current source still exposes the reported race: clicking a streaming new-file pill before its diff is available tries to open the not-yet-created on-disk resource. This team-authored issue should remain open while the intended click behavior during that interval is decided.

## Change summary

Clicking a newly created file's edit pill while chat is still generating its patches shows a file-opening error.

## Best solution

Make streaming new-file pills avoid an error before the file or diff becomes available, either by opening the live editing model or by withholding activation until there is a valid target; preserve normal-editor opening for completed creates and diff-editor opening for existing-file edits.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatEditPillElement.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatMarkdownContentPart.test.ts`
- **Validation:** Add a ChatMarkdownContentPart regression test that activates a streaming newly-created-file pill before diffObservable yields a diff and verifies the chosen behavior completes without attempting to open an unavailable resource or surfacing an error; retain coverage for completed creates and existing-file diffs.
- **Behavior:**

  > While chat is creating a new file, activating its visible file-edit pill must not show a file-not-found or editor-opening error. The chosen interaction should remain consistent for mouse and keyboard activation. Once the create has usable content, the file should open normally; edits to existing files should retain their diff behavior.
- **Trace:**

  > CollapsedCodeBlock in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts registers every pill as activatable immediately. showDiff opens this.uri when currentDiff is undefined, but render only assigns currentDiff after getEntryDiffBetweenStops yields a usable result; during early streaming, a new file may not yet exist on disk. The empty-original fallback shared through src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatEditPillElement.ts only runs when currentDiff already exists, so it does not cover this race. Prior work in https://github.com/microsoft/vscode/pull/321776 and https://github.com/microsoft/vscode/pull/323086 must remain intact: completed creates open normally and genuine modifications open as diffs. Do not broaden the change to unrelated chat links or post-completion editor selection.
- **Open decisions:**
  - During the interval before a generated file has a usable diff or on-disk resource, should activating its pill open the live editing model, or should the pill remain visibly busy but non-activatable until opening is valid?
