# Issue #162018 — Cell context menu should use NotebookCell as context like the cell toolbar

[https://github.com/microsoft/vscode/issues/162018](https://github.com/microsoft/vscode/issues/162018)

## Summary

The cell-container context menu still forwards a different argument from the cell toolbar, so extension commands expecting NotebookCell remain incompatible. Keep this accepted notebook bug open; distinguish the container menu from the embedded editor menu when settling the command contract.

## Change summary

Make notebook cell commands work consistently when invoked from the cell toolbar or the cell-container context menu.

## Best solution

Give cell-container actions enough context to operate on the clicked cell, consistently with the toolbar, while preserving the URI contract for ordinary editor context-menu commands. Confirm whether the thread's agreement to tolerate heterogeneous arguments also applies to the container menu before changing extension-visible arguments.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`, `src/vs/workbench/contrib/notebook/browser/view/cellParts/cellToolbars.ts`, `src/vs/workbench/contrib/notebook/browser/controller/coreActions.ts`, `src/vs/workbench/api/common/extHostNotebook.ts`
- **Validation:** Use a development extension contributing a command to notebook/cell/title that records its argument and accesses the target cell. Invoke it from the toolbar and by right-clicking cell chrome, including an inactive cell; verify the agreed argument contract and correct target. Separately verify that ordinary embedded-editor context-menu commands retain URI arguments.
- **Behavior:**

  > An extension command contributed to the cell title menu can operate on the intended cell when invoked from either its toolbar or its cell-container context menu. Today those entry points deliver incompatible arguments. Acceptance must cover the clicked cell even when another cell is active, and preserve ordinary editor context-menu behavior. The container argument contract must be agreed before implementation.
- **Trace:**

  > NotebookEditorWidget.showListContextMenu forwards only { from: 'cellContainer' } for MenuId.NotebookCellTitle, whereas CellTitleToolbar.didRenderCell supplies the cell and notebook editor with MarshalledId.NotebookCellActionContext. ExtHostNotebookController's argument processor converts the latter into the public NotebookCell but leaves the container marker unchanged. Built-in NotebookCellAction.run can fall back to active-editor context, which does not provide equivalent argument conversion for extension commands. The author distinguishes cell chrome from embedded editor menus at https://github.com/microsoft/vscode/issues/162018#issuecomment-1360160174; the final maintainer response accepts heterogeneous arguments at https://github.com/microsoft/vscode/issues/162018#issuecomment-1360400253. Preserve the ordinary editor URI contract and avoid broad editor-menu changes. The remaining uncertainty is whether the final compatibility decision intended to cover the container menu as well.
- **Open decisions:**
  - Should cell-container menu commands receive the same NotebookCell argument as cell-toolbar commands, or should container invocation retain a distinct, explicitly supported argument contract?

## Evidence

- **Current container-menu mismatch:** src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts:1031-1033 routes list context-menu events to showListContextMenu. At lines 1072-1085, that method opens MenuId.NotebookCellTitle with shouldForwardArgs enabled but supplies only { from: 'cellContainer' }; it supplies neither the clicked cell nor a notebook-cell marshalling identifier.
- **Toolbar and extension argument conversion:** src/vs/workbench/contrib/notebook/browser/view/cellParts/cellToolbars.ts:202-222 supplies cell, notebookEditor, and MarshalledId.NotebookCellActionContext to the title toolbar. src/vs/workbench/api/common/extHostNotebook.ts:91-114 converts that marked argument into cell.apiCell and otherwise returns the argument unchanged. MenuItemAction.run in src/vs/platform/actions/common/actions.ts:651-664 forwards the supplied arguments to the command. Thus an extension command receives NotebookCell from the toolbar but the unconverted marker object from the container menu.
