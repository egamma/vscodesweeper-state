# Issue #170474 — Unable to resolve nonexistent file '<REDACTED: user-file-path>'

[https://github.com/microsoft/vscode/issues/170474](https://github.com/microsoft/vscode/issues/170474)

## Summary

The expected file-not-found error is suppressed only by a deliberately temporary message-string workaround; current main still records that a scalable error-identity solution is needed. This team-authored, On Deck bug therefore remains open.

## Change summary

Expected file-operation failures lose their FileOperationError identity before global telemetry handling and are reported as unexpected errors.

## Best solution

Preserve a stable expected/no-telemetry identity for file-operation errors across the path into BaseErrorTelemetry, then remove the localized message-string filter while retaining suppression of expected file failures.

## Plan brief

- **Likely files:** `src/vs/platform/telemetry/common/errorTelemetry.ts`, `src/vs/base/common/errors.ts`, `src/vs/platform/files/common/files.ts`, `src/vs/workbench/browser/workbench.ts`

- **Behavior:**

  > Expected file-operation failures, including resolving or reading a file that no longer exists, must not be reported as unexpected-error telemetry even after crossing an error serialization or global-handler boundary. Suppression must be based on stable error identity rather than localized message text. Genuine unexpected errors must continue to produce telemetry.
- **Trace:**

  > IFileService produces FileOperationError instances in src/vs/platform/files/common/fileService.ts, but the issue's forced reproduction showed that the instance reaches the global workbench handler as a plain Error. BaseErrorTelemetry in src/vs/platform/telemetry/common/errorTelemetry.ts currently suppresses intact FileOperationError instances and also uses the temporary `Unable to read file` substring workaround from https://github.com/microsoft/vscode/pull/173070. Generic error serialization in src/vs/base/common/errors.ts preserves an explicit marker only for ErrorNoTelemetry; FileOperationError in src/vs/platform/files/common/files.ts has no equivalent marker. The uncertainty starts at the path that strips the FileOperationError prototype before workbench error handling. Preserve behavior for unexpected errors and do not broaden suppression based on arbitrary file-related message text.
