# Issue #340103 — Agents: single-chat sessions revert to unread — main chat read state falls back to a stale session-level status from listSessions

[https://github.com/microsoft/vscode/issues/340103](https://github.com/microsoft/vscode/issues/340103)

## Summary

Confirmed on current main: for single-chat sessions, a `listSessions` refresh overwrites `isRead` with the stale session-level status bit, and `applyChatMetadata` then clears the per-chat override that would otherwise correct it — exactly the regression the reporter traced from #339500 (not referenced by number/URL here since it predates this repo's commit history, but the mechanism matches). Reasonable, well-diagnosed bug report; stays open for a fix.

## Change summary

Single-chat Agent Host sessions revert from read to unread after any unrelated session's turn triggers a `listSessions` refresh, because the refresh's session-level read bit overrides the already-correct per-chat read state.

## Best solution

In `AgentHostSessionAdapter.update()` (baseAgentHostSessionsProvider.ts), stop letting the raw `metadata.status` IsRead bit blindly win for single-chat sessions — have `applyChatMetadata` set `_defaultChatIsReadOverride` from the default chat's own `isRead` even when there are no peers (mirroring the peer-chat branch), so the per-chat read state from the prior read-state work keeps driving the UI instead of the stale session aggregate.
