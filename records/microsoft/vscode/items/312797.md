# Issue #312797 — [Regression] [Error] unhandlederror-command 'workbench.userDataSync.actions.turnOn' not found

[https://github.com/microsoft/vscode/issues/312797](https://github.com/microsoft/vscode/issues/312797)

## Summary

The defect remains source-reproducible on current main: the Agents window exposes the Settings Sync button but does not load the contribution that registers its command. This older report should remain the canonical issue for the identical, newer https://github.com/microsoft/vscode/issues/327308.

## Change summary

Clicking "Backup and Sync Settings" in the Agents window Settings editor executes an unregistered command and throws an unhandled error.

## Best solution

Decide whether the Agents window supports Settings Sync, then make the Settings header consistent with that decision: a visible button must successfully start sync, while an unsupported capability must not be offered.

## Plan brief

- **Likely files:** `src/vs/sessions/sessions.common.main.ts`, `src/vs/sessions/sessions.desktop.main.ts`, `src/vs/sessions/sessions.web.main.ts`, `src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts`
- **Validation:** Launch the Agents window with Settings Sync disabled, open Settings, activate "Backup and Sync Settings", and verify either that the supported setup flow opens without a command-not-found error or that the button is absent when sync is intentionally unsupported; repeat for the applicable desktop and web entry points.
- **Behavior:**

  > The Agents window must never offer a Settings Sync control whose command is unavailable. If Settings Sync is supported, activating "Backup and Sync Settings" must open the normal setup flow without an unhandled error. If it is unsupported, the Settings editor must not display that control. Existing Settings Sync behavior in the normal VS Code workbench must remain unchanged.
- **Trace:**

  > In src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts, SettingsEditor2 creates SyncControls when IUserDataSyncWorkbenchService is enabled and enablement can be toggled; SyncControls then executes `workbench.userDataSync.actions.turnOn`. That command is registered by UserDataSyncWorkbenchContribution through src/vs/workbench/contrib/userDataSync/browser/userDataSync.contribution.ts. The Sessions entry points load the sync workbench, enablement, and platform services but not that browser contribution, so the visible control reaches an absent command on current main. Desktop telemetry confirms the path, while src/vs/sessions/sessions.web.main.ts has the same service/contribution mismatch and should be considered when settling scope. Do not alter normal-workbench Settings Sync behavior or unrelated Settings editor controls. The newer identical report https://github.com/microsoft/vscode/issues/327308 should consolidate into this issue rather than replace it as canonical.
- **Open decisions:**
  - Should the Agents window support and expose the full Settings Sync setup flow on desktop and web, or should Settings Sync controls be hidden there?
