# Issue #104816 — Not able to turn Settings Sync on after changing github password

[https://github.com/microsoft/vscode/issues/104816](https://github.com/microsoft/vscode/issues/104816)

## Summary

Keep open: current GitHub authentication still returns persisted OAuth sessions without checking whether their tokens have been revoked. Settings Sync now offers another sign-in option, but that does not establish that the confirmed stale-token recovery defect is fixed.

## Change summary

Settings Sync should recover from GitHub credentials invalidated by a password change or OAuth app revocation instead of continuing to offer an unusable session.

## Best solution

Make confirmed-invalid GitHub OAuth sessions stop appearing as usable accounts and let Settings Sync obtain fresh authorization. Preserve valid sessions during temporary network failures and choose a validation policy that does not make frequent authentication lookups unnecessarily expensive.

## Plan brief

- **Likely files:** `extensions/github-authentication/src/github.ts`, `extensions/github-authentication/src/githubServer.ts`, `extensions/github-authentication/src/test/github.test.ts`, `src/vs/workbench/services/userDataSync/browser/userDataSyncWorkbenchService.ts`
- **Validation:** Add provider regression coverage using a persisted OAuth session with account metadata and an authoritative GitHub 401 response: the invalid session must cease being offered and recovery must permit fresh authorization. Cover transient network failure separately to ensure valid credentials are retained. Manually authorize GitHub, revoke the OAuth app while VS Code remains open, then enable Settings Sync and verify recovery without deleting OS credentials.
- **Behavior:**

  > After GitHub invalidates an OAuth token, Settings Sync must not repeatedly treat the corresponding cached session as usable. The user must be able to authorize again and enable synchronization without manually deleting stored credentials. Temporary network failures must not sign the user out or erase otherwise valid credentials. Validate both an already-running window and reopening VS Code after revocation; the current additional-account sign-in option must remain available.
- **Trace:**

  > GitHubSessionEngine.getSessions in extensions/github-authentication/src/github.ts reads _persistedSessionsPromise and calls stillGood, which accepts persisted sessions without checking remote token validity. readSessions also skips getUserInfo when stored account metadata exists, so reopening the window does not inherently validate those sessions. UserDataSyncWorkbenchService.getAccounts consumes those sessions, and doSignIn reuses the selected session ID; onDidAuthFailure resets Sync's selection without removing the provider session. The current multiple-account registration already improves the old picker limitation and must be preserved. The unresolved boundary is how authoritative invalidation reaches shared provider state without destructive handling of temporary failures or costly validation on every frequent lookup. The issue's revocation variant is confirmed at https://github.com/microsoft/vscode/issues/104816#issuecomment-2173891780; the account-switching report at https://github.com/microsoft/vscode/issues/104595 is not equivalent.
- **Open decisions:**
  - What recovery timing should users expect after server-side revocation: detecting invalid credentials before offering the cached account, or allowing the attempted operation to reject them and then immediately offering fresh authorization?

## Evidence

- **Confirmed trigger:** The reporter receives HTTP 401 after changing their GitHub password and selecting the existing account when enabling Settings Sync. A maintainer independently confirms the OAuth app revocation variant at https://github.com/microsoft/vscode/issues/104816#issuecomment-2173891780.
- **Current source retains invalid persisted sessions:** In extensions/github-authentication/src/github.ts:703-746, readSessions calls GitHubServer.getUserInfo only when stored account metadata is absent. getSessions at lines 307-332 passes cached sessions through stillGood; at lines 485-498, a persisted session has no transient entry and is accepted without remote validation. Revoking an ordinary persisted OAuth token therefore does not cause this lookup path to remove it.
- **Settings Sync recovery boundary:** src/vs/workbench/services/userDataSync/browser/userDataSyncWorkbenchService.ts:getAccounts builds account choices from authenticationService.getSessions, and doSignIn reuses the selected account's session ID. onDidAuthFailure clears Settings Sync's current session ID but does not invalidate the provider's persisted OAuth session.
- **Partial improvement is not full coverage:** extensions/github-authentication/src/extension.ts registers supportsMultipleAccounts: true. UserDataSyncWorkbenchService.createQuickpickItems consequently offers another GitHub sign-in even when an account exists, addressing the historical absence of a sign-in choice but not the stale-session validity problem.
- **Previously rejected duplicate:** https://github.com/microsoft/vscode/issues/104595 is closed and concerned switching accounts, not invalid credentials. This issue was explicitly reopened to test the password-change scenario at https://github.com/microsoft/vscode/issues/104816#issuecomment-841304414.
- **Related report consolidates here:** https://github.com/microsoft/vscode-pull-request-github/issues/2209 was closed in favor of this issue. Its maintainer identified token validity checking as the shared missing behavior at https://github.com/microsoft/vscode-pull-request-github/issues/2209#issuecomment-979367138; later reports describe recovery after manually removing cached credentials.
- **Canonical search:** Searches for revoked GitHub authentication and Settings Sync 401 reports found no verified older canonical with the same observable symptom. The older open https://github.com/microsoft/vscode/issues/104008 concerns revoking an individual extension's local access and delivering authentication events, not recovering Settings Sync after GitHub invalidates its OAuth token.
