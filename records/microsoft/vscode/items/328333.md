# Issue #328333 — Even if there’s no updated version available, VS Code still tries to update.

[https://github.com/microsoft/vscode/issues/328333](https://github.com/microsoft/vscode/issues/328333)

## Summary

The reporter's framing matches real code: `Win32UpdateService.postInitialize()` runs `collectGarbage()` unconditionally on every startup when background/fast updates are enabled, regardless of whether an actual update is available — that GC pass spawns `inno_updater.exe --gc` to prune old versioned install folders, and it is that cleanup (not a genuine update) that throws the 'DeleteFile failed; Access denied' dialog when a file like `d3dcompiler_47.dll` in an old version folder is still locked (by a lingering process, GPU helper, or AV). A second reporter confirms the same symptom.

## Change summary

On Windows, the background update/GC pass repeatedly shows an installer 'Access denied' dialog for a locked DLL in an old versioned folder, even though no new version is actually being installed, and it recurs on every launch if the user closes the dialog.

## Best solution

Make the background `collectGarbage()` path (src/vs/platform/update/electron-main/updateService.win32.ts) resilient to locked files during old-version cleanup — e.g. have inno_updater's `--gc` mode skip/retry silently without surfacing an interactive installer dialog for a background maintenance task, since the current UX treats routine GC the same as a failed install.
