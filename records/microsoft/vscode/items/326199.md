# Issue #326199 — VS Code does not connect to tunnel after updating

[https://github.com/microsoft/vscode/issues/326199](https://github.com/microsoft/vscode/issues/326199)

## Summary

Verified duplicate of the open canonical tunnel version-mismatch issue #228407, which tracks the same problem — tunnel connection fails with 'Client refused: version mismatch' after updating the client while the server-side CLI hasn't updated yet.

## Change summary

Remote tunnel connection fails with 'Client refused: version mismatch' after updating VS Code on the client, because the server-side tunnel CLI still runs the old commit.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/228407 which already tracks this tunnel version-mismatch problem with team engagement (connor4312). The root cause is the strict commit equality check in `remoteExtensionHostAgentServer.ts` (line 337–341) — when the client updates but the server CLI hasn't, the commits diverge. The immediate workaround is to update the tunnel CLI on the server side.
