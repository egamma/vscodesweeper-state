# Issue #348832 — Agent host ignores http.noProxy (even "*"): Copilot runtime requests go through http.proxy and get blocked (1.146.0, Windows)

[https://github.com/microsoft/vscode/issues/348832](https://github.com/microsoft/vscode/issues/348832)

## Summary

Keep open for cross-profile proxy configuration interference, not wildcard matching. The reporter's two-window reproduction is consistent with current source: each window forwards its configuration into shared host-global state.

## Change summary

Opening another profile can overwrite the shared agent host's proxy exclusions and break Copilot requests in an unchanged window.

## Best solution

Make the shared local agent host's networking configuration deterministic across profiles so opening or editing another window cannot silently change existing windows' routing. Settle application-wide versus profile-specific networking semantics before implementing the ownership change.
