# Issue #285427 — Reference folder task in multi-root workspace

[https://github.com/microsoft/vscode/issues/285427](https://github.com/microsoft/vscode/issues/285427)

## Summary

Keep this accepted request open: workspace task dependencies still cannot explicitly target tasks in individual workspace folders. It has 22 upvotes and was promoted to Backlog; the verified related requests do not provide an open canonical covering the same capability.

## Change summary

Allow a task defined in a .code-workspace file to depend on existing folder-level tasks, including extension-provided tasks.

## Best solution

Provide an explicit, unambiguous folder-qualified dependency reference for workspace compound tasks, reusing folder task definitions rather than copying commands into the workspace file. Settle the public reference syntax before implementation and preserve existing unqualified dependency resolution.

- **Behavior:**

  > A task defined in a .code-workspace file should compose existing tasks from explicitly selected workspace folders without duplicating their commands or extension task definitions. Identically labeled tasks in different folders must remain distinguishable, and configured extension-provided tasks must be usable as dependencies. Existing unqualified dependsOn references and their execution ordering must retain their behavior. Acceptance includes successful composition across two folders and an actionable diagnostic when an explicit folder reference cannot be resolved.
- **Trace:**

  > TaskDependency.from and uriFromSource in src/vs/workbench/contrib/tasks/common/taskConfiguration.ts bind workspace-file dependency references to the workspace configuration URI, including typed task identifiers. The dependsOn schema in src/vs/workbench/contrib/tasks/common/jsonSchema_v2.ts has no documented folder-qualified reference contract. AbstractTaskService._createResolver in src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts indexes tasks by scope URI, and TerminalTaskSystem._executeTask passes each dependency's URI and identifier into that resolver. The Run Task picker aggregates scope groups separately, explaining why manual task selection already works without satisfying the requested declarative composition. Preserve existing scope isolation for unqualified references, task-provider resolution, and dependency execution semantics; general folder-to-folder references and workspace-local extension task definitions are outside this request. The same-request predecessors https://github.com/microsoft/vscode/issues/185084 and https://github.com/microsoft/vscode/issues/84800 closed on vote thresholds, whereas https://github.com/microsoft/vscode/issues/93149 tracks defining extension tasks directly in workspace files. The remaining uncertainty is the user-facing reference format and how it identifies workspace folders.
- **Open decisions:**
  - What public dependsOn reference format should identify a workspace folder and its task, and should the folder identity use its workspace name, relative path, or another explicit selector?
