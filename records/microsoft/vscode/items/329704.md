# Issue #329704 — Extra */ inserted on typing /** */

[https://github.com/microsoft/vscode/issues/329704](https://github.com/microsoft/vscode/issues/329704)

## Summary

Traced this in the source: the auto-closing containment check for JSDoc `/**` … ` */` pairs assumes the pre-existing closer immediately follows the cursor, but when the existing `*/` is separated by extra whitespace (as in the repro's manually typed `/*  */`), the containment check fails and the full ` */` gets appended again — a real, still-open bug.

## Change summary

Typing `*` to turn `/*  */` into `/**  */` (JSDoc) inserts a redundant extra `*/` instead of just widening the opener.

## Best solution

Fix belongs in AutoClosingOpenCharTypeOperation.getAutoClosingPairClose in src/vs/editor/common/cursor/cursorTypeEditOperations.ts — the `isContainedPairPresent` check (`lineAfter.startsWith(containedPairClose)`) needs to tolerate whitespace between the cursor and the existing closer before deciding whether to suppress the redundant close; needs a maintainer/owner to weigh the right heuristic since a naive change could affect other contained-pair cases (e.g. bracket pairs).

## Evidence

- **code path:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts, AutoClosingOpenCharTypeOperation.getAutoClosingPairClose (lines ~220-286): when typing the 3rd `*` to form `/**`, `_findContainedAutoClosingPair` finds the `/*`→`*/` pair as contained within `/**`→` */`; `isContainedPairPresent` is computed via `lineAfter.startsWith(containedPairClose)` which requires `*/` to immediately follow the cursor.
- **root cause:** With the repro's literal `/*  */` (two spaces before `*/`), `lineAfter` is `"  */"` which does NOT start with `"*/"`, so `isContainedPairPresent` is false and the full `" */"` close is appended on top of the existing `*/`, producing `/**  */  */`.
- **pair config:** extensions/typescript-basics/language-configuration.json defines the JSDoc pair as { "open": "/**", "close": " */" }, confirming the ` */` (leading space) is the exact close string driving this logic.
