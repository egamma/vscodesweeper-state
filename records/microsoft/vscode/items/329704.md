# Issue #329704 — Extra */ inserted on typing /** */

[https://github.com/microsoft/vscode/issues/329704](https://github.com/microsoft/vscode/issues/329704)

## Summary

Traced this conclusively in the auto-closing pair logic: the JS/TS language configuration defines `/**` -> ` */` as an auto-closing pair, and `AutoClosingOpenCharTypeOperation.getAutoClosingPairClose` only inspects the single character immediately following the cursor (via `_isBeforeClosingBrace`/`shouldAutoCloseBefore`) to decide whether to skip auto-closing. When a space precedes an already-existing `*/`, that check passes and a redundant ` */` gets inserted even though a valid closing sequence already exists further along the line — exactly the reported `/** */  */` outcome.

## Change summary

Typing `*` right after `/*` in an existing `/*  */` comment (to make it `/**  */`) inserts a spurious extra `*/`.

## Best solution

Extend the auto-close redundancy check in `AutoClosingOpenCharTypeOperation.getAutoClosingPairClose` (src/vs/editor/common/cursor/cursorTypeEditOperations.ts) so it also recognizes an already-present close sequence separated only by intervening auto-close-before whitespace, not just an immediately adjacent one — this is the same class of check `_isBeforeClosingBrace` already does for single-char brackets, just not for multi-char comment pairs with a leading space in their close text.
