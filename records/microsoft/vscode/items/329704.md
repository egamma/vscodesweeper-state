# Issue #329704 — Extra */ inserted on typing /** */

[https://github.com/microsoft/vscode/issues/329704](https://github.com/microsoft/vscode/issues/329704)

## Summary

Traced a real gap in the autoclosing-pair logic: when typing `*` to turn `/*  */` into `/** */`, the docComment autoclose pair (`/**` → ` */`) fires again because the existing `*/` is separated from the cursor by more than one space, so the adjacency check misses it while the whitespace-based `shouldAutoCloseBefore` check still allows the close-before-space heuristic to pass — producing a duplicated `*/`.

## Change summary

Typing `*` right after `/*` to upgrade an existing `/*  */` block comment into a JSDoc `/** */` comment inserts an extra, duplicate `*/`.

## Best solution

Fix `AutoClosingOpenCharTypeOperation` in src/vs/editor/common/cursor/cursorTypeEditOperations.ts so the pre-existing `*/` later on the line (with arbitrary intervening whitespace) is detected before auto-inserting another ` */`, not just an immediately-adjacent one; add a regression test alongside the existing 'autoClosingPairs - multi-character autoclose' test in cursor.test.ts.

## Evidence

- **language config:** extensions/typescript-basics/language-configuration.json defines the autoClosingPair { open: "/**", close: " */" } (lines 68-74), which is what triggers when the second `*` is typed.
- **gating logic:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts lines 228-244: the loop only suppresses auto-close when `_isBeforeClosingBrace` finds the close text immediately adjacent (line 345-355, `lineAfter.startsWith(x.close)`); when there are two spaces before the existing `*/` instead of one, that check fails and `shouldAutoCloseBefore(' ')` (true, since ' ' is in the default `autoCloseBefore` whitelist, extensions/typescript-basics/language-configuration.json line 132) lets the close proceed anyway, inserting a second ` */`.
- **no existing test coverage:** src/vs/editor/test/browser/controller/cursor.test.ts 'autoClosingPairs - multi-character autoclose' (line 5355) only covers typing `*` at the end of an empty `/*`, never mid-line before a pre-existing `*/`; git log on the file shows no related fix on main.
