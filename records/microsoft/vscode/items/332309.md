# Issue #332309 — Markdown editor: in "Open as Preview", Find is unreachable until the preview is clicked, and the Edit > Find menu never works

[https://github.com/microsoft/vscode/issues/332309](https://github.com/microsoft/vscode/issues/332309)

## Summary

Traced in the checkout: the Edit > Find menu item runs `actions.find` (src/vs/editor/contrib/find/browser/findController.ts), a `MultiEditorAction` that only operates on an `ICodeEditor` and is a no-op when a webview-based Markdown preview is the active editor — this matches the reporter's step 6 observation exactly. Ctrl+F is instead handled by a separate webview-only command (`editor.action.webvieweditor.showFind` in src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts) gated on `activeEditor == WebviewEditor.ID` and `EditorContextKeys.focus` being false, which plausibly explains the click-dependent behavior if the 'Open as Preview' toolbar button retains focus without properly registering the webview as focused first.

## Change summary

After using 'Open as Preview', neither Ctrl+F nor Edit > Find opens the Find widget until the webview is manually clicked, and Edit > Find never works at all in the preview.

## Best solution

This is a core webview/editor-action gap, not a markdown-extension bug: `actions.find` (src/vs/editor/contrib/find/browser/findController.ts) needs to fall back to `IWebview.showFind()` for webview-based editors (mirroring `editor.action.webvieweditor.showFind` in webviewCommands.ts), and/or the markdown preview webview panel needs to reliably receive focus on reveal so the existing Ctrl+F webview binding fires without an extra click. Best routed to the webview/editor-core area for a maintainer decision rather than fixed purely in extensions/markdown-language-features.

- **Webview find keybinding:** src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts:19-39 gates Ctrl+F for webviews on `activeEditor == WebviewEditor.ID` AND `EditorContextKeys.focus` negated plus `KEYBINDING_CONTEXT_WEBVIEW_FIND_WIDGET_ENABLED`; if the preview panel isn't yet the recognized active/focused editor right after the toolbar click, the binding won't fire until a click supplies focus.
