# Issue #332309 — Markdown editor: in "Open as Preview", Find is unreachable until the preview is clicked, and the Edit > Find menu never works

[https://github.com/microsoft/vscode/issues/332309](https://github.com/microsoft/vscode/issues/332309)

## Summary

Reproduces in the code: the Edit > Find menu item is bound to `actions.find` (StartFindAction in src/vs/editor/contrib/find/browser/findController.ts), a MultiEditorAction that only operates on an ICodeEditor via CommonFindController — it has no fallback to the webview find command, so it no-ops whenever a webview/markdown-preview editor is active, regardless of focus. The Ctrl+F symptom is separately explained by src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts and overlayWebview.ts: the webview's find-related context keys are bound to a scoped context key service tied to the webview's DOM container, which is only the 'active' context for keybinding dispatch once that container actually has DOM focus — hence Ctrl+F works only after the extra click.

## Change summary

After opening a Markdown file with 'Open as Preview', Ctrl+F only opens Find once the preview has been clicked, and the Edit > Find (and Edit > Replace) menu items never open Find at all.

## Best solution

Two related but distinct gaps to route to the webview/editor owners: (1) make `actions.find`/`actions.replace` (or the Edit menu handlers) fall back to the active webview's find command when no code editor is focused, so the menu isn't a dead end for webview-based editors; (2) consider whether the webview panel should call `.focus()`/take DOM focus when shown via 'Open as Preview' so its scoped find context keys are live for Ctrl+F immediately, similar in spirit to the workaround already tracked for https://github.com/microsoft/vscode/issues/58668.

## Evidence

- **Edit > Find binding:** src/vs/editor/contrib/find/browser/findController.ts:565-593 registers StartFindAction as a MultiEditorAction bound to MenuId.MenubarEditMenu group '3_find'; its implementation calls CommonFindController.get(editor) and returns false/no-ops when there is no active ICodeEditor, which is the case when a webview (markdown preview) is the active editor.
- **Webview find command exists separately:** src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts defines ShowWebViewEditorFindWidgetAction ('editor.action.webvieweditor.showFind') with its own Ctrl+F keybinding gated on `webviewActiveContextKeyExpr` and `KEYBINDING_CONTEXT_WEBVIEW_FIND_WIDGET_ENABLED`; it is not wired to the Edit > Find menu item at all.
- **Focus-dependent context keys:** src/vs/workbench/contrib/webview/browser/overlayWebview.ts:160-172 binds `_findWidgetEnabled`/`_findWidgetVisible` to a scoped context key service tied to the webview's own container, which explains why the Ctrl+F keybinding (evaluated relative to the currently DOM-focused element) only resolves correctly once the user clicks into the preview.
- **Related known issue:** The code already documents a related, older focus/context-key workaround at https://github.com/microsoft/vscode/issues/58668 in the same webviewCommands.ts file, suggesting this general class of webview-focus/context-key gap is a recognized rough edge.
