# Issue #238656 — Allow customization of editor tab height and editor tab bar scrollbar height

[https://github.com/microsoft/vscode/issues/238656](https://github.com/microsoft/vscode/issues/238656)

## Summary

A real customization gap remains: current main offers only default/compact tab heights and default/large title scrollbars. The earlier issue explicitly invited a separate request for larger tabs, so this should remain open for a product decision rather than be treated as implemented or duplicate.

## Change summary

Allow users to make editor tabs and the tab-bar scrollbar taller than the existing presets, potentially through numeric sizing.

## Best solution

Choose an accessibility-conscious sizing contract for editor tabs—either a bounded larger preset or controlled numeric scaling—while preserving compact/default behavior. Keep the existing large scrollbar option unless evidence shows that its 10-pixel size is still insufficient, and avoid unnecessary per-component configuration sprawl.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/common/editor.ts`, `src/vs/workbench/browser/parts/editor/editorTabsControl.ts`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`, `src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css`, `src/vs/workbench/test/browser/parts/editor/multiEditorTabsControl.test.ts`
- **Validation:** Extend the editor tab control tests to assert the chosen larger/custom tab height and scrollbar size, including wrapped tabs, while retaining the existing default and compact height expectations.
- **Behavior:**

  > Users who need larger pointer targets can increase the editor-tab height beyond the current default and increase the tab-bar scrollbar to an accessible size. Existing default and compact layouts remain unchanged unless the new option is selected, including wrapped tabs and single-tab title controls. The selected sizing must remain usable across supported tab layouts and themes.
- **Trace:**

  > Current configuration is limited to `window.density.editorTabHeight: 'default' | 'compact'` in src/vs/workbench/browser/workbench.contribution.ts and the matching `IEditorPartOptions.tabHeight` union in src/vs/workbench/common/editor.ts. EditorTabsControl in src/vs/workbench/browser/parts/editor/editorTabsControl.ts converts those modes to fixed classic and Modern UI heights and publishes `--editor-group-tab-height` for the tab CSS. MultiEditorTabsControl separately maps `workbench.editor.titleScrollbarSizing` to fixed 3- or 10-pixel scrollbars. Existing tests in src/vs/workbench/test/browser/parts/editor/multiEditorTabsControl.test.ts cover default and compact tab heights. The prior implementation at https://github.com/microsoft/vscode/issues/42253 addressed compact tabs only; preserve that behavior and avoid changing unrelated editor sizing.
- **Open decisions:**
  - Should larger tabs be exposed as another bounded density preset, or should users receive a numeric height setting with documented limits?
  - Should the existing shared title-scrollbar setting continue to size both tab and breadcrumb scrollbars, or should tab-bar sizing become independently configurable?

## Evidence

- **current tab capability:** Current main registers `window.density.editorTabHeight` with only `default` and `compact` in src/vs/workbench/browser/workbench.contribution.ts; src/vs/workbench/browser/parts/editor/editorTabsControl.ts maps these to fixed heights rather than accepting a user-defined or larger value.
- **current scrollbar capability:** Current main already provides `workbench.editor.titleScrollbarSizing` with `default` and `large`; src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts defines those scrollbar sizes as 3 and 10 pixels respectively. This partially covers the request but does not provide arbitrary sizing.
- **predecessor discussion:** The closed predecessor https://github.com/microsoft/vscode/issues/42253 delivered compact tabs, but a maintainer said larger tabs were not then planned and explicitly requested a separate issue to measure that need: https://github.com/microsoft/vscode/issues/42253#issuecomment-1748234383.
- **not a duplicate:** https://github.com/microsoft/vscode/issues/42253 is closed and its implemented compact-height work does not satisfy this request for taller or freely configurable controls; its discussion specifically anticipated this follow-up.
- **demand and scheduling:** The issue has one community upvote and is assigned to the Backlog holding milestone. That supports retaining it for discussion but does not establish a particular sizing design or urgency.
