# Issue #337015 — Workspace picker doesn't show dev container when using `New` button

[https://github.com/microsoft/vscode/issues/337015](https://github.com/microsoft/vscode/issues/337015)

## Summary

Freshly filed, already correctly labeled dogfooding bug (bug/containers/agents-window/agent-host) with a plausible root cause traced in the current source; keeping it open for a maintainer to confirm the fix approach.

## Change summary

Pressing 'New' from an active Dev Container (WSL) session no longer shows 'Dev Container' in the pre-populated workspace picker label.

## Best solution

Track dev-container state for already-created sessions (not just new-session drafts) so `newChatWidget.ts`'s sync-from-active-session path can correctly detect and re-show the Dev Container label when starting a new session from an existing dev-container session.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/providers/agentHost/browser/devContainerAgentHostSessionsProvider.ts`, `src/vs/sessions/contrib/chat/browser/newChatWidget.ts`, `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`
- **Validation:** A provider/newChatWidget test asserting that after a session using a Dev Container is created, pressing 'New' re-populates the workspace picker with `preferDevContainer: true` (and the picker label shows 'Dev Container') for that workspace.
- **Behavior:**

  > When the currently active session is running in a Dev Container (regardless of provider — local, WSL, SSH, or tunnels per the linked #336716 test matrix), pressing the 'New' button and having the workspace picker pre-populate from that session should keep showing '<workspace> - Dev Container' in the picker, not silently fall back to the plain workspace label.
- **Trace:**

  > `_syncWorkspacePickerDevContainerMode` in newChatWidget.ts asks `provider.isDevContainerEnabled(activeSession.sessionId)` to decide `preferDevContainer`. In devContainerAgentHostSessionsProvider.ts, `isDevContainerEnabled` only consults the `_devContainerDrafts` Set, which is populated while a session is still a new-session draft and is explicitly deleted from that set in `deleteNewSession` once the draft becomes a real session (lines 396-402). So for any already-created session, the check always returns false, and `sessionWorkspacePicker.ts`'s `_getWorkspaceLabel` never appends the 'Dev Container' suffix. The boundary: don't change how new-session drafts track dev-container preference (that flow works, per existing tests); the gap is specifically querying an already-created session's dev-container state. Related test coverage exists in devContainerAgentHostSessionsProvider tests but none cover querying `isDevContainerEnabled` post-creation. Ref: https://github.com/microsoft/vscode/issues/336716 (the test issue this was filed against).
- **Open decisions:**
  - Should dev-container state for a created session be tracked in the provider (a new persistent set separate from `_devContainerDrafts`) or derived externally from the session's workspace/connection metadata?
  - Does this need to work uniformly across the local, WSL, SSH, and tunnel dev-container flows named in #336716, or is a per-provider fix acceptable?

## Evidence

- **sync path:** src/vs/sessions/contrib/chat/browser/newChatWidget.ts:672-681 `_syncWorkspacePickerDevContainerMode` computes `preferDevContainer` via `provider.isDevContainerEnabled?.(activeSession.sessionId)` when the 'New' flow re-populates the picker from the active session.
- **isDevContainerEnabled scope:** src/vs/sessions/contrib/providers/agentHost/browser/devContainerAgentHostSessionsProvider.ts:131-133 `isDevContainerEnabled(sessionId)` only checks the `_devContainerDrafts` Set, which tracks in-progress new-session drafts.
- **draft cleared on creation:** Same file, `deleteNewSession` (lines 396-402) deletes the sessionId from `_devContainerDrafts` once a draft resolves into a real session — so calling `isDevContainerEnabled` with an already-created session's id (as the 'New' handoff does) will always return false, dropping the 'Dev Container' label.
- **label logic:** src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts:2046-2050 `_getWorkspaceLabel` only appends '- Dev Container' when `_selectedDevContainerFolderUri` is set, which is only set when `preferDevContainer` is true.
