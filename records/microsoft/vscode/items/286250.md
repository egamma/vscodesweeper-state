Team-authored bug confirmed reproducible by the reporter with detailed steps and acknowledged as a known issue by roblourens. No fix commit referencing this issue found on main — keeping open.

## Change summary

Kicking off multiple agent sessions in succession causes new sessions to stop appearing in the sessions list, and completed sessions get stuck showing as in-progress.

## Best solution

Investigate and fix the chat sessions service change-event pipeline so that rapid successive session creation doesn't cause the sessions list to stop updating. The root cause likely involves the service's event-driven refresh path dropping or deadlocking under concurrent session creation. The sessions view and chat sessions service code in `src/vs/workbench/contrib/chat/browser/` and `src/vs/sessions/` are the likely areas.
