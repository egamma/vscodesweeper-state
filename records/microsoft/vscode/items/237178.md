# Issue #237178 — Please add an option to have word wrap toggled off for every editor by default

[https://github.com/microsoft/vscode/issues/237178](https://github.com/microsoft/vscode/issues/237178)

## Summary

Keep open: the editor owner manually reopened this after the automated upvote-threshold close and moved it to the Backlog. Current main still couples the configured wrap mode to the initial state, so the requested column-based toggle behavior remains unavailable.

## Change summary

Allow editors to open with wrapping disabled while Alt+Z enables the configured `wordWrapColumn` or `bounded` mode for that editor.

## Best solution

Separate the wrap mode used when toggled on from whether wrapping starts enabled, while preserving Alt+Z as transient per-editor behavior. Product design should also decide whether remembering that transient state across sessions belongs in this issue or a follow-up.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** With `editor.wordWrapColumn` set to 80 and the selected wrap mode set to `wordWrapColumn`, open a file and verify it starts unwrapped; press Alt+Z and verify it wraps at column 80; press Alt+Z again and verify it returns to unwrapped. Repeat with `bounded` and confirm existing `editor.wordWrap` behavior remains unchanged when the new option is not enabled.
- **Behavior:**

  > Users must be able to configure column-based or bounded wrapping as the mode used by Toggle Word Wrap while having newly opened editors start unwrapped. Alt+Z should enable that configured mode for the current editor and disable it on the next invocation. Existing configurations must retain their current initial and toggle behavior unless the user opts into the new behavior. Whether per-file state survives a restart must be decided explicitly.
- **Trace:**

  > The editor options in src/vs/editor/common/config/editorOptions.ts encode enabled state and wrap mode together in `editor.wordWrap`. ToggleWordWrapAction in src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts inspects the effective wrapping column and writes an in-memory per-model `wordWrapOverride` restricted to `on` or `off`; from an `off` configuration, the enabled state consequently means viewport wrapping. The same file documents that transient state is stored in memory for a particular model, which does not satisfy the separate comment requesting persistence across sessions. Historical reports https://github.com/microsoft/vscode/issues/128133 and https://github.com/microsoft/vscode/issues/38303 establish the prior extension-based workaround, while the manual reopen and Backlog assignment on the current issue establish that core consideration is now intentional. The boundary is the editor wrapping configuration and toggle state model; unrelated wrapping layout and rendering behavior must remain unchanged.
- **Open decisions:**
  - Should the new behavior be represented by an independent initial-enabled setting, a configured toggle target, or another `editor.wordWrap` mode?
  - Should the requested state be transient per model, restored per file across sessions, or should persistence be tracked separately?
  - How should the option interact with language-specific settings and accessibility-driven wrapping overrides?
