# Issue #237178 — Please add an option to have word wrap toggled off for every editor by default

[https://github.com/microsoft/vscode/issues/237178](https://github.com/microsoft/vscode/issues/237178)

## Summary

Keep open in the Backlog: the requested initial-off, column-based toggle mode remains absent on current main, and a maintainer deliberately reopened the issue and promoted it from Backlog Candidates to Backlog after the automated close.

## Change summary

Allow editors to open with wrapping disabled while Alt+Z enables the configured `wordWrapColumn` or `bounded` wrapping strategy.

## Best solution

Separate the editor's initial wrapping state from its enabled wrapping strategy, preserving the configured column or bounded mode when Alt+Z turns wrapping on. Maintainers should also decide whether the per-file toggle state survives window restarts.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts`, `src/vs/workbench/contrib/codeEditor/test/browser/toggleWordWrap.test.ts`
- **Validation:** Add and run a targeted Toggle Word Wrap unit test proving that an editor configured for column wrapping can open unwrapped, toggle to the configured column, and toggle back off without changing existing `editor.wordWrap` behavior.
- **Behavior:**

  > Users can select `wordWrapColumn` or `bounded` as the wrapping strategy while having newly opened editors start unwrapped. Pressing Alt+Z enables that configured strategy rather than viewport wrapping, and pressing Alt+Z again disables wrapping. Existing behavior remains unchanged unless the new configuration is selected. Acceptance covers initial state, both toggle transitions, and existing `off`, `on`, `wordWrapColumn`, and `bounded` configurations.
- **Trace:**

  > The public modes are registered in src/vs/editor/common/config/editorOptions.ts, where `off` simultaneously means initially disabled and no configured column-based enabled mode. ToggleWordWrapAction in src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts records only an `on` or `off` transient override; starting from `off` therefore toggles to viewport wrapping. ToggleWordWrapController applies that override through `wordWrapOverride2`, while the effective wrapping computation in editorOptions.ts uses the configured strategy only when the override is `inherit`. The issue's exact behavior was confirmed by a maintainer at https://github.com/microsoft/vscode/issues/237178#issuecomment-3760096536. Keep diff-editor synchronization and existing wrap modes unchanged; persistence beyond the current in-memory model property is a separate scope decision.
- **Open decisions:**
  - Should the public configuration be a separate initial-enabled boolean, a distinct default-off wrapping mode, or a broader separation between enabled state and wrapping strategy?
  - Should a file's toggled wrapping state persist across window restarts, as requested in the discussion, or remain an in-memory per-model state?
