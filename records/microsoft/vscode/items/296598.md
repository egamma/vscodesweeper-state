# Issue #296598 — MCP gateway: Support MCP elicitations

[https://github.com/microsoft/vscode/issues/296598](https://github.com/microsoft/vscode/issues/296598)

## Summary

Core gateway session plumbing now exists, but the Copilot gateway wrapper still omits the session resource. Keep this team-authored request open: partial implementation does not establish completion, and no qualifying older duplicate was found.

## Change summary

Support user-input elicitations from MCP servers exposed through the Claude integration's gateway, associated with the originating chat session.

## Best solution

Ensure gateway-backed tool elicitations reach the originating chat and return the user's response to the MCP server. First establish the current Claude consumer path and whether it adopts the existing session-aware gateway API; keep native Claude SDK elicitation separate from gateway-owned elicitation.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/mcp/vscode/mcpServiceImpl.ts`, `extensions/copilot/src/platform/mcp/vscode/test/mcpService.spec.ts`, `src/vs/workbench/contrib/mcp/common/mcpGatewayToolBrokerChannel.ts`, `src/vs/workbench/contrib/mcp/browser/mcpElicitationService.ts`
- **Validation:** Extend the existing McpService Vitest suite to verify session identity reaches the gateway API independently for two resources. Then use @modelcontextprotocol/server-everything through the current Claude gateway integration to request form elicitation, submit answers, and cancel another request; verify the correct chat receives the prompt and the MCP tool receives the corresponding result. Do not count native SDK elicitation as gateway validation.
- **Behavior:**

  > An MCP server installed in VS Code and exposed through the Claude gateway can request user input during tool execution. The prompt belongs to the originating chat session, and submitting or cancelling it returns the corresponding result to the server. Verify session isolation with two chats and preserve existing behavior for gateway clients without chat context.
- **Trace:**

  > The workbench gateway API already accepts chatSessionResource, and McpGatewayChannel forwards it to McpGatewayToolBrokerChannel, whose tool-call context reaches McpServer and McpElicitationService. Commit https://github.com/microsoft/vscode/commit/a08bf15bf52d523c2cb2ddb7c5b4feb833417f6e introduced this core plumbing for https://github.com/microsoft/vscode/issues/307962. However, extensions/copilot/src/platform/mcp/vscode/mcpServiceImpl.ts still discards its resource argument when calling lm.startMcpGateway(). The trace has not established which current Claude consumer uses this wrapper, so diagnosis must first establish the live gateway path and distinguish it from native SDK callbacks discussed in https://github.com/microsoft/vscode/issues/299011. Preserve gateway lifecycle, per-resource caching, and no-session fallback; do not broaden this into tool-selection UX or native SDK elicitation work.
