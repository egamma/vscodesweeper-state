# Issue #336431 — "Change Completions Model" is missing

[https://github.com/microsoft/vscode/issues/336431](https://github.com/microsoft/vscode/issues/336431)

## Summary

The command exists in source ("Change Completions Model", `github.copilot.chat.openModelPicker` in extensions/copilot/package.json) but its enablement/registration is gated behind the `extensionUnification` rollout state and `hasMultipleModels` — so it legitimately doesn't surface for users not yet in that rollout or without multiple completion models. This looks like a staged-rollout/entitlement gap rather than a straightforward missing feature, so it stays open for the completions team to confirm intended behavior for this cohort.

## Change summary

The 'Change Completions Model' command described in GitHub's docs and settings UI does not appear in the command palette for some users.

## Best solution

Completions team should confirm whether the reporter's account/build is meant to have `extensionUnification` and multiple models available; if not, docs should clarify staged rollout, or the command's enablement/registration path should be reviewed for correctness — this isn't a straightforward core code fix.

- **registration gated:** extensions/copilot/src/extension/completions/vscode-node/completionsCoreContribution.ts:57-62 only calls `registerUnificationCommands` (which wires up the model picker command) when `extensionUnification` is true, itself derived from `unificationStateObservable`.
- **unification is a rollout flag:** src/vs/workbench/services/inlineCompletions/common/inlineCompletionsUnification.ts shows `extensionUnification` computed from experimentation-service feature flags (`extensionUnificationEnabled`) and a setting `chat.extensionUnification.enabled`, i.e. a staged experiment, not a static capability.
- **hasMultipleModels gate:** extensions/copilot/src/extension/completions-core/vscode-node/extension/src/modelPicker.ts:51-53 — `hasMultipleModels()` returns false unless the user's plan/entitlement exposes more than one completion model, matching GitHub's docs note that the picker only appears with multiple models available.
- **settings entry present:** extensions/copilot/package.json:3426-3429 confirms the related setting `github.copilot.selectedCompletionModel` exists on main, so the settings half of the report is not the issue — only the command visibility is in question.
