# Issue #192861 — [Bug] Opening new editor from a diff editor resets the location

[https://github.com/microsoft/vscode/issues/192861](https://github.com/microsoft/vscode/issues/192861)

## Summary

Keep this accepted diff-editor request open: the current Open Active Diff Side command still does not transfer the selected location into the standalone editor. The linked history issue concerns a different navigation operation, and the newer cursor-preservation report is not an eligible canonical for this re-reviewed item.

## Change summary

Preserve the selected line when opening the focused side of a diff as a standalone editor.

## Best solution

Have the core diff-editor command open the selected original or modified resource at its current selection, including historical versions supplied by extensions. Preserve existing side-selection behavior and address back/forward history separately.

## Evidence

- **Existing capability and remaining gap:** src/vs/workbench/browser/parts/editor/diffEditorCommands.ts registers workbench.action.compareEditor.openSide with Ctrl/Cmd+K, Shift+O and delegates to DiffEditorCommandsService.openActiveDiffSide. In src/vs/workbench/browser/parts/editor/diffEditorCommandsService.ts, that method chooses activeEditor.original when the original editor has text focus, otherwise activeEditor.modified, then calls editorService.openEditor(editor) without reading or forwarding the focused side's selection or view state.
- **Standalone resource opening:** src/vs/workbench/browser/parts/editor/textResourceEditor.ts, AbstractTextResourceEditor.setInput, restores the standalone resource's saved view state and applies explicit editor options when supplied. The diff-side command supplies no location options, so it cannot guarantee opening at the selected diff line; a fresh standalone view can start at the top. This is source inspection, not an executed reproduction.
