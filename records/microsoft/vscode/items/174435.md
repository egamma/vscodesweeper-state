# Issue #174435 — Add an option to show a watermark in the editor

[https://github.com/microsoft/vscode/issues/174435](https://github.com/microsoft/vscode/issues/174435)

## Summary

Keep this accepted feature request open: existing title and theme customization do not provide a persistent workspace-identifying watermark behind editor content. It has 27 upvotes and continued interest; the supported customization scope needs a maintainer decision.

## Change summary

Allow an optional text or image watermark behind editor content to help users distinguish client repositories.

## Best solution

Define an opt-in, workspace-specific identity treatment for populated text editors that preserves readability and editing interactions. Decide whether configurable text is sufficient or whether images and other surfaces belong in the supported contract before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/parts/editor/editorGroupWatermark.ts`
- **Validation:** After scope is agreed, open two workspaces with distinct configured identifiers and documents in split editors; verify each approved editor surface shows the correct watermark, switching documents retains workspace identity, disabling the option restores current rendering, and typing, selection, scrolling, and high-contrast readability remain unaffected. For approved image support, also verify the agreed positioning and opacity behavior.
- **Behavior:**

  > Users editing repositories for different clients need a prominent workspace-specific identity cue visible while documents are open. Window titles and profile colors are partial alternatives, not coverage of the requested watermark. An approved treatment must be optional, distinguish independently configured workspaces, and preserve text readability and normal editor interactions. Acceptance should cover split editors, document switching, disabling the treatment, and accessibility-sensitive themes.
- **Trace:**

  > The existing EditorGroupWatermark in src/vs/workbench/browser/parts/editor/editorGroupWatermark.ts renders fixed empty-editor shortcuts under workbench.tips.enabled; its configuration description in src/vs/workbench/browser/workbench.contribution.ts confirms that boundary. It is instantiated by EditorGroupView, while populated text-editor views and overlay widgets are managed by CodeEditorWidget in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts. No editor.watermark registration was found in the inspected configuration or editor browser sources. Preserve existing empty-editor tips and title-bar customization; neither should be repurposed in a way that changes their established behavior. Agents chat backgrounds documented at https://github.com/microsoft/vscode/issues/333232 are a separate surface. The remaining uncertainty is the supported product contract: text versus images, positioning controls, and which editor types are covered; the terminal suggestion is not an established requirement.
- **Open decisions:**
  - Should the supported watermark be workspace-identifying text only, or also user-selected images with opacity and font customization?
  - Should the first version cover populated text editors only, or also diff, embedded, and terminal surfaces?
  - Should placement use a fixed set of anchors including center, or expose arbitrary positioning offsets as proposed?
