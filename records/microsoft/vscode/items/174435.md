# Issue #174435 — Add an option to show a watermark in the editor

[https://github.com/microsoft/vscode/issues/174435](https://github.com/microsoft/vscode/issues/174435)

## Summary

Keep this accepted feature request open: current watermark and window-title settings do not provide a persistent client identifier behind an open editor. It has 27 upvotes and renewed interest; no verified canonical or completed implementation was found.

## Change summary

Provide an optional, configurable text or image watermark behind editor content to distinguish client repositories.

## Best solution

Design a restrained, opt-in workspace-identification surface that remains visible while editing without obscuring code or interfering with input. Settle whether the supported contract includes images, language-specific overrides, and terminals before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/parts/editor/editorGroupWatermark.ts`, `src/vs/workbench/browser/parts/editor/media/editorgroupview.css`
- **Validation:** After the supported scope is agreed, open two client workspaces with different configured identifiers and keep text files open in each. Verify each identifier remains visible while typing, scrolling, resizing, and splitting editors; it must not intercept selection or input, and disabling it must restore the existing appearance. Check light, dark, and high-contrast themes, plus reload persistence and any agreed language overrides.
- **Behavior:**

  > Users editing repositories for different clients need a prominent, persistent identifier inside the editing surface rather than only in the window title. The requested watermark can contain text or an image with configurable placement and opacity; language-specific settings and terminal coverage are suggested but not settled. Acceptance requires the agreed identifier to remain visible with a file open, distinguish configured workspaces, and leave editing interactions and readability intact. The default experience must remain unchanged.
- **Trace:**

  > The existing EditorGroupWatermark in src/vs/workbench/browser/parts/editor/editorGroupWatermark.ts is an empty-group command-hint surface, not an overlay on an active text editor. Its stylesheet, src/vs/workbench/browser/parts/editor/media/editorgroupview.css:119-121, explicitly hides it for nonempty groups. window.title in src/vs/workbench/browser/workbench.contribution.ts already supports workspace, profile, and repository identifiers, but only in the title surface. Editor options are registered in src/vs/editor/common/config/editorOptions.ts; no editor.watermark registration was found there. These are investigation starting points, not an established rendering implementation path. Preserve existing empty-editor hints, title behavior, editing input, and the default unadorned editor. https://github.com/microsoft/vscode/issues/31308 is related workspace-orientation work, not a canonical for this request. Uncertainty starts at the public customization contract and supported surfaces.
- **Open decisions:**
  - Should the initial supported content be workspace-identifying text only, or also user-supplied images?
  - Should the watermark be workspace-wide, or support per-language and per-editor identifiers?
  - Should the supported surface be text editors only, or also integrated terminals and other editor types?
  - Should positioning use a small set of supported anchors, including center, or expose arbitrary offsets and font styling?
