## Evidence

- **Concrete regression report:** https://github.com/microsoft/vscode/issues/246519 identifies VS Code 1.99.2, Remote-SSH 0.119.0, macOS 15.3.1, and Ubuntu 16.04.7 with the documented custom-sysroot workaround. SSH connects successfully, GitHub requests fail with getaddrinfo EBUSY api.github.com, terminal ping/nslookup succeed, and reverting to VS Code 1.97 restores functionality.
- **Maintainer-linked upstream lead:** The maintainer links https://github.com/nodejs/help/issues/2390. Its explanation at https://github.com/nodejs/help/issues/2390#issuecomment-570887373 places this error at operating-system DNS resolution; subsequent comments discuss file-descriptor exhaustion but also report cases without it. This is a diagnostic lead, not proof of this report's root cause or a canonical duplicate.
- **Custom runtime boundary:** resources/server/bin/code-server-linux.sh sets the bundled Node binary's rpath and interpreter using VSCODE_SERVER_CUSTOM_GLIBC_PATH and VSCODE_SERVER_CUSTOM_GLIBC_LINKER, then starts server-main.js with that binary. Successful system utilities therefore do not establish that the patched Node process resolves names successfully.
- **Documented support boundary:** https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions documents the 1.99 Linux prerequisite change and calls the custom-sysroot approach a technical workaround rather than an officially supported usage scenario. This limits certainty but does not establish a decline close for an issue already classified as a bug.
- **Current authentication implementation:** extensions/github-authentication/package.json declares the built-in authentication extension as ui-first with workspace support. extensions/github-authentication/src/node/fetch.ts selects among Electron fetch, Node fetch, and Node HTTP/S, with optional fallbacks. Neither the execution location in the reported setup nor successful resolution through these implementations is established by inspection.
