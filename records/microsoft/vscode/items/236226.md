# Issue #236226 — Should View use `canToggleVisibility`

[https://github.com/microsoft/vscode/issues/236226](https://github.com/microsoft/vscode/issues/236226)

## Summary

This team-authored workbench consistency review remains necessary: current main still prevents hiding several listed views, while the discussion settles only that Explorer and Popular should remain protected. The related merged PR predates this issue and changed four different views, so it is not an implementing fix for this item.

## Change summary

Review core view registrations and allow visibility toggling except where hiding a view creates a known discoverability or recovery problem.

## Best solution

Have the remaining view owners decide whether Comments, Chat, Search, and Test Results require permanent visibility, then make their registrations consistent with those decisions while retaining the documented protections for Explorer, Popular Extensions, and Sync Conflicts.

- **Validation:** For every owner-approved toggleable view, verify through its View menu and title context menu that it can be hidden and restored; verify Explorer, Popular Extensions, and Sync Conflicts remain protected, and run the targeted workbench views unit tests.
- **Behavior:**

  > Core views should expose visibility toggling consistently unless hiding one creates a documented discoverability or recovery problem. Explorer and Popular Extensions must remain non-hideable based on the owner discussion, and Sync Conflicts remains the proposed protected exception. Acceptance requires each approved view to be hideable and recoverable through normal workbench UI while protected views continue to omit or disable the hide action.
- **Trace:**

  > `IViewDescriptor.canToggleVisibility` is consumed by `ViewDescriptorService` to enable toggle/hide actions and by `ViewContainerModel` to persist and apply hidden state. Current registrations still disable it for Comments, Chat, Search, Popular Extensions, Test Results, Explorer, and Sync Conflicts; the old Edits view has since been removed. The thread settles Explorer and Popular Extensions but contains no owner decision for Comments, Chat, Search, or Test Results. The earlier https://github.com/microsoft/vscode/pull/235846 changed Terminal, Debug Console, Problems, and Output only and predates this issue. Keep the scope to registration policy and visibility behavior; do not redesign view-container persistence or recovery mechanisms.
- **Open decisions:**
  - Should Comments, Chat, Search, and Test Results each be user-hideable, or does any one require permanent visibility because users cannot reliably recover it?
  - Should Sync Conflicts remain non-hideable and non-movable as proposed, or should its conditional activation be considered sufficient recovery?
