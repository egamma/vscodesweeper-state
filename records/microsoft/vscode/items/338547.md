# Issue #338547 — SCM Repositories view repeatedly refreshes and re-expands on startup with many worktree repositories

[https://github.com/microsoft/vscode/issues/338547](https://github.com/microsoft/vscode/issues/338547)

## Summary

Confirmed on current main: the Repositories view's non-explorer-mode `updateRepository` falls through to a full `updateChildren()` refresh, and the `historyItemRef` autorun isn't gated on explorer mode, exactly as described. An open PR (#338592) already fixes both, so this should stay open pending review/merge of that PR rather than being closed now.

## Change summary

With many worktree repositories open, the SCM Repositories view repeatedly collapses/re-expands and fully re-renders the tree during startup because redundant full refreshes fire per worktree repository.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338592, which gates the historyItemRef subscription on explorer mode and removes the redundant full-tree refresh for child repository updates in non-explorer mode.

## Evidence

- **root cause confirmed:** src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts lines 646-655: the historyItemRef autorun reads only `historyProvider`, not `explorerEnabledConfig`, so it fires updateRepository() for every worktree ref change regardless of mode.
- **redundant refresh confirmed:** Same file, lines 775-785 (updateRepository): in non-explorer mode (explorerEnabledConfig === false) a child repository (parentId !== undefined) calls updateParentRepository() and then falls through to the unconditional `await this.updateChildren()` at line 786, causing a full recursive refresh per child event.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/338592 is open and applies exactly the two-line diff described in the issue (gate historyItemRef on explorerEnabled; add early return after updateParentRepository).
