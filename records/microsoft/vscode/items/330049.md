# Issue #330049 — Agents Window: "2 issues" button should close dropdown list if already open

[https://github.com/microsoft/vscode/issues/330049](https://github.com/microsoft/vscode/issues/330049)

## Summary

Confirmed in source: the issue/PR count pill's click handler always opens the list picker without checking whether it's already open, so a second click is a no-op that leaves the dropdown showing instead of toggling it closed.

## Change summary

Clicking the "2 issues" (or PR-count) pill a second time while its dropdown is open should close the dropdown instead of leaving/reopening it.

## Best solution

In OpenIssueActionViewItem.onDidClickButton (src/vs/sessions/contrib/github/browser/issueActions.ts) and the equivalent PR pill (pullRequestActions.ts), track whether the sticky hover this button opened is currently visible and call hoverService.hideHover() instead of re-showing it on a second click.

  > The session-header "N issues"/"N Pull Requests" pill does not toggle its dropdown closed on a second click. In src/vs/sessions/contrib/github/browser/issueActions.ts, `OpenIssueActionViewItem.onDidClickButton()` (around line 157) calls `this._showIssuePicker(issues)` whenever there is more than one issue, with no check for whether the picker it previously opened is still visible. Underlying cause: `IHoverService._createHover` in src/vs/platform/hover/browser/hoverService.ts (lines 279-282) silently no-ops (returns undefined, hover stays open) when the new hover's computed identity matches the currently shown hover's identity — it never hides the existing hover, so a second click has no visible effect and the dropdown appears to 'reopen' rather than close. Fix by tracking, in each action view item, whether its own sticky hover (the one created by `_showIssuePicker`/`_showPullRequestPicker`) is still the currently-displayed hover when the button is clicked again, and if so call `this._hoverService.hideHover()` and return instead of calling the show-picker method again — mirroring how a typical toggle-button dropdown behaves. Do not change the underlying `_createHover` identity-matching logic in hoverService.ts itself, since other callers may rely on its current no-op-on-same-identity behavior; keep the fix scoped to the two action view items. Add a unit test (near the existing tests for these action view items, or a new small test) that simulates two consecutive `onDidClickButton()` calls with multiple issues/PRs present and asserts the hover is shown once and then hidden on the second click, not re-shown.
