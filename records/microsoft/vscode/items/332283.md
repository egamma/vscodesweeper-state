# Issue #332283 — using different set of memory file connecting via remote ssh

[https://github.com/microsoft/vscode/issues/332283](https://github.com/microsoft/vscode/issues/332283)

## Summary

Plausible but under-specified: Copilot's repo/session memory is stored under the extension's workspace storage (extensions/copilot/src/extension/tools/node/memoryTool.tsx and resolveMemoryFileUriTool.tsx use IVSCodeExtensionContext.storageUri), which VS Code keys by remote authority + workspace path — if the reporter is reaching the same remote folder through two different SSH connection identities, they'd legitimately get two separate storage folders. The report doesn't say enough to confirm that's what's happening versus a genuine storage bug, so this needs clarification rather than a close.

## Change summary

Copilot's project/repo memory file differs between remote-SSH sessions to the same remote workspace instead of being shared.

## Best solution

Ask the reporter exactly how they connect in each 'session' (same SSH host alias/config each time, or different aliases/folders resolving to the same physical path?). If it's the latter, this is inherent to how workspace storage keys on remote authority + path (extensions/copilot/src/extension/tools/node/resolveMemoryFileUriTool.tsx, memoryTool.tsx use extensionContext.storageUri) and belongs to the storage-scoping design, not a simple fix; if it's the same authority/path, that would point to an actual regression worth tracing further in the remote storage resolution path.
