# Issue #90426 — Add ability for before decorations to indent (stretch across) word wrapped lines

[https://github.com/microsoft/vscode/issues/90426](https://github.com/microsoft/vscode/issues/90426)

## Summary

The editor still cannot apply a before decoration as indentation across continuation view lines. This accepted Backlog request should remain open for design of a dedicated decoration API and wrapping behavior.

## Change summary

Allow a decoration prefix, such as GitLens blame annotations, to reserve the same horizontal space on every visual line produced by word wrapping.

## Best solution

Provide a supported editor decoration API for line prefixes whose width participates in wrapping and is repeated on continuation view lines, allowing extensions to render annotations without relying on CSS pseudo-elements.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/common/viewModel/inlineDecorations.ts`, `src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts`, `src/vs/editor/test/browser/viewModel/viewModelDecorations.test.ts`
- **Validation:** Add a focused editor view-model test that decorates a word-wrapped logical line and asserts the chosen prefix appears with equal reserved width on its first and continuation view lines, while an ordinary before decoration retains its existing behavior; run it through scripts/test.sh with a test-title grep.
- **Behavior:**

  > Extensions can attach a visual prefix to a logical line and request that the prefix reserve equal horizontal space on every visual line created by word wrapping. The prefix must participate in wrap-width calculation so continuation text remains aligned, including after viewport or wrapping-column changes. Existing before and after decoration behavior must remain compatible unless an extension opts into the new contract.
- **Trace:**

  > Extension decoration attachments originate in src/vscode-dts/vscode.d.ts, are converted by `ThemableDecorationAttachmentRenderOptions.from` in src/vs/workbench/api/common/extHostTypeConverters.ts, and become model decoration classes through `DecorationTypeOptionsProvider` in src/vs/editor/browser/services/abstractCodeEditorService.ts. `InlineModelDecorationsComputer.getDecorations` in src/vs/editor/common/viewModel/inlineDecorations.ts currently emits `beforeContentClassName` only at the projected range's starting view line. The wrapping pipeline in src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts accounts for injected text but has no contract for repeating a logical-line prefix across continuation lines. The existing wrapped-line assertion in src/vs/editor/test/browser/viewModel/viewModelDecorations.test.ts confirms the current limitation. Preserve existing decoration rendering and cursor behavior for extensions that do not opt into the new API.
- **Open decisions:**
  - Should the public contract extend decoration attachments with an opt-in wrapped-line prefix mode, or introduce a dedicated line-prefix API with distinct layout semantics?

## Evidence

- **maintainer direction:** A maintainer stated that this requires new editor API and moving blame annotations away from inline decorations; the issue is accepted in the Backlog milestone.
- **current source:** src/vs/editor/common/viewModel/inlineDecorations.ts only emits `beforeContentClassName` at `viewRange.startLineNumber`, so no prefix is generated for subsequent wrapped view lines.
- **current test contract:** src/vs/editor/test/browser/viewModel/viewModelDecorations.test.ts explicitly asserts that a before decoration has no inline decorations on later wrapped view lines.
- **confirmed limitation:** https://github.com/microsoft/vscode/issues/170023 was closed as a duplicate after a maintainer confirmed that left-padding wrapped lines is not achievable through the current text-decoration API and linked this issue as the canonical request.
- **canonical search:** The open https://github.com/microsoft/vscode/issues/3932 concerns elastic tabstops rather than repeated decoration prefixes, so it does not absorb this request.
