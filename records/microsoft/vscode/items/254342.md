# Issue #254342 — ERR_CERT_COMMON_NAME_INVALID

[https://github.com/microsoft/vscode/issues/254342](https://github.com/microsoft/vscode/issues/254342)

## Summary

The certificate error is real, but the strongest evidence identifies incorrect DNS CNAME caching in affected dnsmasq/Pi-hole-based resolvers rather than a VS Code defect. Keep this canonical network issue open while affected users update their DNS resolver and confirm whether any cases remain with correct DNS answers.

## Change summary

Copilot requests intermittently resolve to the wrong GitHub endpoint and receive a certificate whose name does not match the requested Copilot hostname.

## Best solution

Affected DNS forwarders should incorporate the upstream dnsmasq cache fix from https://github.com/pi-hole/FTL/commit/345efc10a841063049242935b6bf37adecfaed0f. Retain this issue as the VS Code network canonical until reports with corrected resolver versions establish whether a separate product-side defect remains; VS Code must not bypass hostname verification.

## Evidence

- **independent network reproduction:** A commenter reproduced the failure outside VS Code with OpenSSL: api.individual.githubcopilot.com returned a github.com certificate. Their DNS trace simultaneously showed the incorrect stale answer `api.individual.githubcopilot.com CNAME github.com`, then returned the correct Copilot CNAME chain minutes later.
- **upstream root cause:** https://github.com/pi-hole/FTL/commit/345efc10a841063049242935b6bf37adecfaed0f fixes a dnsmasq negative-record caching bug that can associate a CNAME with the wrong target. The upstream report https://github.com/pi-hole/FTL/issues/2590 documents the incorrect cached CNAME behavior and confirmation that the patched build stopped reproducing it.
- **affected resolver confirmation:** Multiple reports use Pi-hole or network appliances likely backed by dnsmasq. The Pi-hole-specific certificate report https://github.com/pi-hole/pi-hole/issues/6197 is labeled `dnsmasq bug`, and users reported improvement after installing the development build containing the cache fix.
- **canonical issue:** Maintainers consolidated later reports such as https://github.com/microsoft/vscode/issues/271898 and https://github.com/microsoft/vscode/issues/279566 into this issue, so it remains the appropriate microsoft/vscode record for residual confirmations.
