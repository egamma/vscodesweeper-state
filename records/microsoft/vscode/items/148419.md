# Issue #148419 — Loaded scripts view should use label service

[https://github.com/microsoft/vscode/issues/148419](https://github.com/microsoft/vscode/issues/148419)

## Summary

The debt remains on current main: Loaded Scripts still converts URI-like source paths into display labels and then splits those labels back into structural tree segments. No older canonical issue or completed replacement was found, so the existing debug backlog item should remain open.

## Change summary

Separate URI/path structure from display-label formatting when constructing the Loaded Scripts tree.

## Best solution

Define the intended hierarchy for file, workspace-relative, URL, and custom-scheme sources, then use URI/path-aware operations for structural segments while reserving the label service for presentation where its output will not be reparsed.

- **Behavior:**

  > Loaded Scripts groups each debug-adapter source according to its URI or path structure, without reparsing a human-readable label as a path. Workspace sources retain their workspace-relative hierarchy, absolute local paths retain platform-appropriate presentation, and URL or custom-scheme sources remain navigable without formatter decorations becoming tree nodes. Existing source-opening behavior and ordering remain unchanged. Acceptance should cover file paths, multi-root workspaces, HTTP URLs, and a formatted non-file URI.

Keep source identity, source opening, category ordering, and tree compression behavior outside the cleanup.
