# Issue #320342 — Allow users to hide extension-contributed `viewsWelcome` content (welcome view)

[https://github.com/microsoft/vscode/issues/320342](https://github.com/microsoft/vscode/issues/320342)

## Summary

This is a valid, currently unmet request for user control over extension-contributed welcome content. It is already routed to the correct workbench area, and no older issue with the same observable symptom was found, so it should remain open as a feature request.

## Change summary

Allow users to suppress selected or all extension-contributed `viewsWelcome` content without disabling the contributing extension.

## Best solution

Provide a consistent core-managed suppression mechanism for extension-contributed welcome entries, preserving the extension's other functionality and persisting the user's choice globally.

- **rendering path:** ViewWelcomeController in src/vs/workbench/browser/parts/views/viewPane.ts obtains all registered descriptors and filters them only through each descriptor's `when` expression before rendering.
- **missing provenance and preference:** IViewContentDescriptor and ViewsRegistry in src/vs/workbench/common/views.ts store content, conditions, grouping, ordering, and enablement but no contributing extension identifier or user-hidden state.
- **distinct earlier work:** https://github.com/microsoft/vscode/issues/35462 addressed globally hiding contributed views themselves and was closed after view visibility became user-configurable; it did not cover individual `viewsWelcome` content attached to a built-in view.
