# Issue #209017 — Notebook diff not compatible with readonly files from TextDocumentContentProvider - only checks IFileService for a IFileSystemProvider

[https://github.com/microsoft/vscode/issues/209017](https://github.com/microsoft/vscode/issues/209017)

## Summary

Notebook resources intentionally require a filesystem provider; `TextDocumentContentProvider` only supplies textual documents. The supported solution is a readonly `FileSystemProvider`, so this can close as designed.

## Change summary

Allow notebook diffs to load their readonly side from a `TextDocumentContentProvider` scheme.

## Best solution

SCM extensions that expose historical resources should register a correct readonly `FileSystemProvider`; this supports notebook serializers, custom editors, images, and text editors through one resource abstraction.

## Vision fit

- **Fit:** rejected
- **Reason:** Bridging a text-only provider into non-text notebook resources would weaken the uniform filesystem abstraction already available to extensions.
- **Evidence:** Public values emphasize simple, uniform interactions and that “The power lives in extensions.”

- **Proposed comment:**

  > Thanks for the detailed investigation. This behavior is intentional: `TextDocumentContentProvider` supplies string content for readonly `TextDocument`s, while notebooks and other custom editors consume resources through serializers and the filesystem abstraction. For SCM revision resources that need to work with notebook diffs, the supported approach is to register a `FileSystemProvider` with `isReadonly: true`. That also preserves support for non-text resources and other extensions consuming the scheme, so I believe this can be closed as designed.

## Evidence

- **API contract:** `src/vscode-dts/vscode.d.ts:1841-1871` defines `TextDocumentContentProvider` as returning a string used to create a readonly `TextDocument`, not an arbitrary notebook resource.
- **supported API:** `src/vscode-dts/vscode.d.ts:14504-14524` supports registering a `FileSystemProvider` with `isReadonly: true`.
- **current implementation:** `src/vs/workbench/contrib/notebook/browser/services/notebookServiceImpl.ts:186-194` still accepts notebook resources only when their scheme is supported by `IFileService` (apart from internal and untitled schemes).
- **maintainer direction:** https://github.com/microsoft/vscode/issues/209017#issuecomment-2136774596 states that SCM original states should be served through a filesystem provider because that supports the full range of editors.
