# Issue #209017 — Notebook diff not compatible with readonly files from TextDocumentContentProvider - only checks IFileService for a IFileSystemProvider

[https://github.com/microsoft/vscode/issues/209017](https://github.com/microsoft/vscode/issues/209017)

## Summary

Keep open for the documentation improvement agreed in the discussion, rather than adding notebook support to TextDocumentContentProvider. Current source preserves the intended filesystem-provider boundary, but the published guidance still does not clearly explain it to SCM extension authors.

## Change summary

Clarify that TextDocumentContentProvider supplies text editors, while notebook and custom-editor revision resources require a FileSystemProvider, which can be readonly.

## Best solution

Document the provider boundary in the API reference and virtual-document/SCM guides, preserving the existing notebook architecture. Explain how readonly filesystem providers support historical notebook resources without implying that all providers must permit writes.
