# Issue #206401 — Consider to move `NotebookContribution` off blocking startup

[https://github.com/microsoft/vscode/issues/206401](https://github.com/microsoft/vscode/issues/206401)

## Summary

The requested cleanup remains outstanding: NotebookContribution is still registered at BlockStartup, although editor-triggered contribution instantiation is available. Keep this focused follow-up open; the closed parent checklist does not establish completion.

## Change summary

Avoid eagerly instantiating NotebookContribution on the blocking startup path when notebook functionality is not needed.

## Best solution

Make notebook-specific initialization demand-driven while preserving undo/redo grouping before the first notebook edit, including nonstandard notebook entry points. First establish whether editor creation covers all consumers of the contribution's registrations.
