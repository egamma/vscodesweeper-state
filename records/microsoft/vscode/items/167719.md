[https://github.com/microsoft/vscode/issues/167719](https://github.com/microsoft/vscode/issues/167719)

## Summary

Keep this exploration open: current main still uses string-backed text buffers, while the discussion establishes that large-file reading does not itself require ArrayBuffer storage. The landed safeguards address particular heap-intensive operations, not the entire exploration; exploration items are protected from closure.

## Change summary

Explore ArrayBuffer-backed editor text storage to reduce heap pressure and support larger editing workloads.

## Best solution

Preserve the existing PieceTree implementation while documenting which large-edit workloads remain unsafe after the landed safeguards. Any renewed backing-store work should demonstrate a measurable benefit over external strings and settle the cost of line-content access and worker synchronization before changing the storage contract.
