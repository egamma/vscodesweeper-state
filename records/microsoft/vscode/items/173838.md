# Issue #173838 — Exception when moving views around

[https://github.com/microsoft/vscode/issues/173838](https://github.com/microsoft/vscode/issues/173838)

## Summary

Still reproduces on current main: `getOverlayBounds()` in viewPaneContainer.ts accesses the last pane's element without guarding for an empty panes array, throwing when all views have been moved out of a container and a drag enters the now-empty container.

## Change summary

Moving all views out of a view container and then dragging a view back into it throws a TypeError because the overlay bounds calculation assumes at least one pane exists.

## Best solution

Guard `getOverlayBounds()` in `src/vs/workbench/browser/parts/views/viewPaneContainer.ts` (around line 405) to handle the case where `this.panes` is empty — fall back to the full parent bounds when there are no panes. The earlier fix attempt (PR #198526, deregistering the container) was reverted because it caused regressions; the simpler approach is to make `getOverlayBounds` resilient to an empty panes array.

- **Fix prompt:**

  > In src/vs/workbench/browser/parts/views/viewPaneContainer.ts, the `getOverlayBounds` closure (line ~403) computes overlay drop bounds by reading `this.panes[this.panes.length - 1].element.getBoundingClientRect()` (line 405). When all views have been moved out of a view container, `this.panes` is empty, so `this.panes[-1]` is `undefined` and `.element` throws 'Cannot read properties of undefined (reading "element")'. The fix: guard the `getOverlayBounds` function — when `this.panes.length === 0`, fall back to using the full `parent.getBoundingClientRect()` for all bounds (top, bottom, left, right) instead of computing from the last pane. Do NOT deregister the view container when the last view moves (that approach was tried in PR https://github.com/microsoft/vscode/pull/198526 and reverted due to regressions in https://github.com/microsoft/vscode/issues/199537). Also consider adding an early return in the `onDragEnter` handler (line 426) when `this.panes.length === 0` to skip overlay creation entirely when the container is empty — this would prevent the stale icon issue described in the bug as well. Validate with a unit test that triggers drag-enter on an empty ViewPaneContainer and asserts no exception is thrown.
