# Issue #338445 — Terminal created with `location: { parentTerminal }` is not split when parent has a numeric ID

[https://github.com/microsoft/vscode/issues/338445](https://github.com/microsoft/vscode/issues/338445)

## Summary

The numeric-parent lookup defect remains in current main. Keep this issue open while the explicitly linked fixing PR is reviewed; the older report documents the same observable failure.

## Change summary

Creating a terminal with an already-open parentTerminal opens a separate group instead of splitting beside the parent.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338451 so parentTerminal works with both temporary string identifiers and numeric instance identifiers. Coordinate resolution with https://github.com/microsoft/vscode/issues/205254, which reports the same failure.

## Evidence

- **Current source confirms the defect:** src/vs/workbench/api/browser/mainThreadTerminalService.ts:181–185, _deserializeParentTerminal, converts the parent identifier to a string and looks exclusively in _extHostTerminals. That map is populated with temporary extension-host string identifiers in $createTerminal; a numeric parent misses the lookup and produces an undefined location.
- **Numeric identifier transition:** src/vs/workbench/api/common/extHostTerminalService.ts:534–542 serializes the parent's current _id. At lines 637–646, $acceptTerminalOpened replaces an extension-created terminal's temporary identifier with its numeric instance identifier, establishing the exact failure path after the reporter's wait.
- **Existing identifier-aware lookup:** src/vs/workbench/api/browser/mainThreadTerminalService.ts:132–137, _getTerminalInstance, already distinguishes temporary string identifiers from numeric identifiers and resolves the latter through _terminalService.getInstanceFromId. The parent-deserialization path does not use this behavior.
