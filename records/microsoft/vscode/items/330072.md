# Issue #330072 — Agent Host logs an error when a local commit is not on GitHub

[https://github.com/microsoft/vscode/issues/330072](https://github.com/microsoft/vscode/issues/330072)

## Summary

Team-authored, well-diagnosed bug: current main's `_makeGHAPIRequest` in agentHostOctoKitService.ts treats every non-ok HTTP status as an operational error, so GitHub's expected 422 'No commit found for SHA' response (for a local/unpushed commit) logs a spurious error plus a follow-up warning instead of being treated as 'no pull request found'.

## Change summary

Agent Host logs an error and warning when looking up a pull request for a commit that hasn't been pushed to GitHub, because the 422 'No commit found for SHA' response is treated as a failure rather than an expected 'not found' result.

## Best solution

In `findPullRequestByHeadSha` (or `_makeGHAPIRequest`), special-case the commit-pulls route's 422 'No commit found for SHA' response so it resolves to no pull request (info/trace log at most) instead of throwing/logging an error, while leaving other GitHub API failures to surface as before.
