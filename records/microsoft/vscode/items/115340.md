- **Behavior:**

  > Markdown currently receives different visual representations in notebook Outline and Go to Symbol when file icons are enabled; the author also identifies the cell language picker. Equivalent Markdown entries should follow an agreed, consistent icon policy across these surfaces. Acceptance should cover themes with file icons and the no-file-icons fallback, while navigation, filtering, and language selection remain unchanged.
- **Trace:**

  > OutlineEntry.icon supplies Codicon.markdown for markup cells, and NotebookOutlineRenderer.renderElement uses that product icon because its file-icon branch is restricted to code cells. NotebookQuickPickProvider.getQuickPickElements instead uses language file-icon classes for every non-symbol entry when hasFileIcons is true. ChangeCellLanguageAction.showLanguagePicker independently derives file-icon classes from synthetic language resources. These source paths explain the theme-dependent discrepancy without executing the UI. The discussion at https://github.com/microsoft/vscode/issues/115340 supports consistency but leaves the preferred icon source unresolved. Keep code-cell execution indicators, code-symbol icons, and existing navigation behavior outside the change.
- **Open decisions:**
  - Should Markdown entries across these notebook surfaces follow the active file-icon theme, or use the Markdown product icon consistently even when file icons are enabled?
