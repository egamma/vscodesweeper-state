# Issue #304113 — Expose images preview in image editor toolbar?

[https://github.com/microsoft/vscode/issues/304113](https://github.com/microsoft/vscode/issues/304113)

## Summary

Keep open: the image editor still lacks the requested Images Preview toolbar entry point, and a maintainer explicitly supported improving its discoverability. Existing Explorer and chat entry points do not cover that request.

## Change summary

Expose an action in the image editor toolbar that opens the displayed image in Images Preview.

## Best solution

Provide a discoverable, keyboard-accessible Images Preview action for the active built-in image editor without replacing the default image viewer. Settle whether it opens only the current image or a sibling-image collection before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/imageCarousel/browser/imageCarousel.contribution.ts`, `src/vs/workbench/contrib/imageCarousel/test/browser/imageCarousel.contribution.test.ts`, `extensions/media-preview/package.json`, `extensions/media-preview/src/imagePreview/index.ts`
- **Validation:** Verify an image opened in the built-in image editor exposes a labeled Images Preview toolbar action, operable by keyboard and mouse, that opens the active image with the agreed collection scope. Add targeted action/menu tests covering active-editor resource selection when Explorer selection differs, and confirm existing Explorer and chat entry points retain their behavior.
- **Behavior:**

  > Users viewing an image in the built-in image editor should be able to discover and open Images Preview from the editor toolbar. The action must target the displayed image even if a different file is selected in Explorer, and must be keyboard-accessible with a descriptive label. Opening images normally must continue to use the existing default viewer. Acceptance includes the agreed collection contents, initial selection of the displayed image, and unchanged existing Explorer and chat entry points.
- **Trace:**

  > extensions/media-preview/package.json registers imagePreview.previewEditor and its editor/title actions; those actions currently switch SVG files between text and the ordinary image preview. src/vs/workbench/contrib/imageCarousel/browser/imageCarousel.contribution.ts registers two Images Preview commands but no editor-toolbar entry. OpenImagesInCarouselFromExplorerAction.run depends on IExplorerService.getContext(true), collecting siblings for a single selected image, so its existing selection semantics cannot be assumed to target the active image editor. OpenImageInCarouselAction.run accepts either a collection or single-image data, and the contribution tests already cover Explorer collection construction. The remaining uncertainty is the toolbar action's collection scope, not whether the entry point is wanted. Preserve the default viewer and existing callers; image markup is future discussion, not part of this request. https://github.com/microsoft/vscode/issues/304204 is related Reopen Editor With work, not a duplicate canonical.
- **Open decisions:**
  - Should the toolbar open only the displayed image, or all supported sibling images with the displayed image initially selected?
