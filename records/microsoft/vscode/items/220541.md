# Issue #220541 — Git - Stage Selected Range Bug with Path Capitalisation

[https://github.com/microsoft/vscode/issues/220541](https://github.com/microsoft/vscode/issues/220541)

## Summary

Thanks for the detailed report. The reporter gave a step-by-step repro (rename a folder's case, then stage a selected range) and a second user hit a similar case. Nothing on main appears to address it, so this stays open in the Backlog.

## Change summary

'Stage Selected Ranges' creates a duplicate index entry with the wrong path casing when a folder's case differs between the working tree and the git index, on case-insensitive Windows.

## Best solution

When staging a range, resolve the repository-relative path with the casing git knows (the index or HEAD entry) instead of the casing of the opened document URI. A fix would go in the Repository.stage path used by _stageChanges in extensions/git/src/commands.ts.
