# Issue #324353 — lnk windows files

[https://github.com/microsoft/vscode/issues/324353](https://github.com/microsoft/vscode/issues/324353)

## Summary

Windows shortcut target resolution remains missing from the file-opening path. Keep this request open: the older declined issue concerns sidebar navigation, and the newer workspace-shortcut report covers only a subset of this request.

## Change summary

Resolve a Windows .lnk target when invoking Open with Code instead of opening the shortcut itself, including targets accessible through a WSL UNC path.

## Best solution

Make an explicit product decision about shortcut resolution at the Windows launch boundary, distinguishing shell-invoked opening from editing a shortcut file directly. If accepted, opening the resolved target should retain existing file, folder, workspace, and UNC handling without requiring automatic WSL reopening.
