# Issue #336763 — Markdown file drag opens file instead of inserting link, regardless of Shift

[https://github.com/microsoft/vscode/issues/336763](https://github.com/microsoft/vscode/issues/336763)

## Summary

Detailed, fresh report (0 days old, no maintainer or independent-user confirmation yet) about an asymmetry between dropping a folder vs. a Markdown file into the editor with drop-into-editor settings enabled; I traced the two relevant code paths (the workbench-level drop-into-editor overlay and the markdown extension's drop provider) but could not conclusively confirm the described folder-vs-file asymmetry without running the build, and the reporter explicitly hasn't tried with extensions disabled yet.

## Change summary

With editor.dropIntoEditor.enabled and markdown.editor.drop.enabled="always" set, dragging a workspace .md file into a Markdown source editor always opens the file instead of inserting a Markdown link, even while holding Shift, whereas dragging a folder correctly inserts a link.

## Best solution

If reproduced, the fix likely lives in the interaction between the workbench editor-group drop overlay (src/vs/workbench/browser/parts/editor/editorDropTarget.ts, which decides open-vs-drop-into-editor based on e.shiftKey and the active editor's CanDropIntoEditor capability) and the markdown extension's ResourcePasteOrDropProvider (extensions/markdown-language-features/src/languageFeatures/copyFiles/dropOrPasteResource.ts) — worth confirming whether file resources are being routed through ResourcesDropHandler.handleDrop (opening them) before the in-editor drop providers get a chance, unlike folders.
