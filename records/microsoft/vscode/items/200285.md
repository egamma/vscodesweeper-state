# Issue #200285 — Cannot Save Jupyter Notebook on SSH Disconnect

[https://github.com/microsoft/vscode/issues/200285](https://github.com/microsoft/vscode/issues/200285)

## Summary

This remains a current, repeatedly confirmed data-loss bug: disconnecting the remote extension host removes the notebook serializer required to save or export dirty notebooks. Keep it open and prioritize a disconnect-safe save path.

## Change summary

Preserve or export unsaved Jupyter notebook changes after an SSH connection drops.

## Best solution

Ensure dirty notebook data remains serializable in the local workbench after the remote extension host disconnects, either through a local serializer fallback or a disconnect-safe backup/export path in the notebook working-copy layer.

- **data-loss impact:** Users report notebooks being emptied or unsaved contents becoming inaccessible, including https://github.com/microsoft/vscode/issues/200285#issuecomment-2272458650 and https://github.com/microsoft/vscode/issues/200285#issuecomment-2311717011.
- **source path:** extensions/ipynb/src/ipynbMain.ts registers the `jupyter-notebook` serializer through the extension host; extensions/ipynb/package.json permits workspace-host execution, so an SSH host loss removes that implementation.
- **failure mechanism:** src/vs/workbench/contrib/notebook/browser/services/notebookServiceImpl.ts removes disposed serializer providers and `withNotebookDataProvider` then throws the reported `NO provider registered for view type` error. src/vs/workbench/contrib/notebook/common/notebookEditorModel.ts still requires that provider for serialization and saving.
- **no completed fix:** No linked fixing PR or commit references https://github.com/microsoft/vscode/issues/200285, and the current main source retains the failing provider-dependent path.
