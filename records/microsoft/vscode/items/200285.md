# Issue #200285 — Cannot Save Jupyter Notebook on SSH Disconnect

[https://github.com/microsoft/vscode/issues/200285](https://github.com/microsoft/vscode/issues/200285)

## Summary

Keep open: multiple reporters confirm that SSH disconnection prevents recovering unsaved notebook edits, with reported loss of work through June 2026. Current source still makes local Save As depend on an available notebook serializer; no verified fixing commit or older canonical was found.

## Change summary

Allow unsaved Jupyter notebook edits to be saved locally when the remote SSH connection and notebook serializer become unavailable.

## Best solution

Provide a connection-independent recovery path for the live notebook model that preserves unsaved cells, outputs, and metadata in a usable local notebook. This belongs in core notebook serialization and working-copy recovery, with the built-in ipynb serializer involved, rather than being redirected solely to Jupyter.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/common/notebookEditorModel.ts`, `src/vs/workbench/contrib/notebook/browser/services/notebookServiceImpl.ts`, `src/vs/workbench/api/browser/mainThreadNotebook.ts`, `src/vs/workbench/services/workingCopy/common/fileWorkingCopyManager.ts`, `extensions/ipynb/package.json`, `extensions/ipynb/src/ipynbMain.ts`, `src/vs/workbench/contrib/notebook/test/browser/notebookEditorModel.test.ts`
- **Validation:** In a Remote-SSH workspace, edit an .ipynb notebook, interrupt the connection until its serializer is unavailable, and save a local recovery copy without reconnecting or reloading. Reopen that copy locally and verify unsaved cell sources, outputs, and metadata. Establish automated coverage for provider loss during snapshot/local recovery in the notebook working-copy tests, and verify normal connected saves remain unchanged.
- **Behavior:**

  > After an SSH connection fails, unsaved changes in an already-open Jupyter notebook must remain recoverable locally without restoring the remote extension host. Recovery must preserve the current notebook contents rather than copying the last saved remote file. Acceptance requires reopening the recovered notebook locally and finding the unsaved cell sources, outputs, and metadata intact. Ordinary connected Save and Save As behavior must remain unchanged.
- **Trace:**

  > NotebookEditorModel.saveAs delegates to FileWorkingCopyManager.doSaveAs, which snapshots the resolved source before resolving the destination. NotebookFileWorkingCopyModel.snapshot calls NotebookService.createNotebookTextDocumentSnapshot, which requires withNotebookDataProvider and then invokes the extension-backed serializer. Missing registration produces the exact error in https://github.com/microsoft/vscode/issues/200285; an existing registration still forwards serialization through the extension-host proxy in MainThreadNotebooks. The built-in ipynb extension registers this serializer and prefers the workspace host. This establishes the recovery dependency, but the precise SSH failure lifecycle and an appropriate offline serialization contract still need investigation. Preserve generic notebook-format contracts and connected saves; do not assume an arbitrary notebook model can be exported correctly as ipynb.
- **Open decisions:**
  - Should connection-independent recovery preserve ordinary Save As semantics, or provide a separate recovery-copy operation with explicitly different guarantees?
  - Should offline recovery be guaranteed specifically for built-in ipynb notebooks, or introduce a recovery contract for other extension-provided notebook formats as well?
