# Issue #321469 — orphaned agent window session created when marked done too early

[https://github.com/microsoft/vscode/issues/321469](https://github.com/microsoft/vscode/issues/321469)

## Summary

Team-filed bug about a race condition where marking a new agent-window session as done before it fully initializes creates an orphaned, unresponsive session entry. No fix commit references this issue; it remains open and should be routed to the agents-window area.

## Change summary

Marking a new agent-window session as done before it finishes initializing produces an orphaned session that cannot be opened or closed.

## Best solution

The session archival flow (mark-as-done / archive) needs to handle the case where the session hasn't fully initialized yet — either by blocking the action until initialization completes, or by cleaning up the partially-created session. Likely files are in src/vs/sessions/services/sessions/browser/sessionsManagementService.ts and the archive action in src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts.
