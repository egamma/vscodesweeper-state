# Issue #338959 — /vscode-pet is no longer showing up.

[https://github.com/microsoft/vscode/issues/338959](https://github.com/microsoft/vscode/issues/338959)

## Summary

This is the intended persisted “on the run” state rather than a defect. The pet can be restored by clicking it during its brief appearance, which activates the built-in Come Back behavior.

## Change summary

Restore a VS Code pet that was sent “on the run” and now disappears after briefly appearing.

## Best solution

Use the existing Come Back interaction: enable the pet with `/vscode-pet`, then click it when it briefly appears to clear the persisted on-the-run state.

## Evidence

- **persisted state:** src/vs/workbench/contrib/chat/browser/chatPetService.ts stores `chat.vscodePet.onTheRun` at application scope, independently of whether `/vscode-pet` has enabled the pet.
- **slash command behavior:** src/vs/workbench/contrib/chat/browser/chatSlashCommands.ts registers `/vscode-pet` as an enablement toggle only; it does not reset the persisted on-the-run state.
- **restore interaction:** The click handler in src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts detects `onTheRun` and calls `setOnTheRun(false)`. The same widget also exposes the context-menu action as “Come Back.”
- **intentional hiding:** src/vs/workbench/contrib/chat/browser/widget/media/chatPet.css moves `.chat-pet-button.on-the-run` behind the input, and https://github.com/microsoft/vscode/pull/332381 deliberately fixed the layering so an on-the-run pet remains hidden rather than overlapping the input.
