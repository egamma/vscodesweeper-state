# Issue #338959 — /vscode-pet is no longer showing up.

[https://github.com/microsoft/vscode/issues/338959](https://github.com/microsoft/vscode/issues/338959)

## Summary

Confirmed on current main: a contributor's detailed analysis (scale-dependent hit target vs. fixed run-state translation offset, plus /vscode-pet not clearing the onTheRun state) checks out against the actual source, so the pet can become permanently hidden with no obvious recovery path besides an undocumented command.

## Change summary

After putting the chat pet "on the run", it cannot be reliably brought back — the exposed hit area to click-to-restore is too small or nonexistent (especially after shrinking the pet), and the /vscode-pet slash command doesn't clear the persisted onTheRun state so the pet flashes and re-hides.

## Best solution

Fix chatPetWidget.ts / chatPet.css so the on-the-run state always preserves a clickable minimum hit area regardless of scale, and make the /vscode-pet command (or an explicit reset) clear the persisted chat.vscodePet.onTheRun state.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chatPet.css`
- **Validation:** A test or manual check confirming: (1) after Go on the Run at a shrunk scale, the pet's hit area remains clickable above the chat input; (2) running /vscode-pet after Go on the Run restores the pet without a flash-then-hide.
- **Behavior:**

  > After a user selects "Go on the Run" from the pet's context menu, the pet must remain clickable (a sufficient hit area above the chat input) at every supported scale so clicking it restores normal behavior via setOnTheRun(false). Separately, running the /vscode-pet slash command while the pet is on the run should reliably restore it — not just flash briefly before hiding again. Acceptance: clicking the visible strip at default and shrunk scales restores the pet; /vscode-pet keeps the pet visible afterward.
- **Trace:**

  > _setScale (chatPetWidget.ts, ~line 2614) sizes the button to CHAT_PET_SOURCE_SIZE/2 * scale, but the on-the-run CSS rule (chatPet.css line 329) applies a fixed translateY(var(--vscode-spacing-size400)) regardless of scale, so smaller scales push the whole button behind the chat input, eliminating the click target entirely; at default scale only a sliver is exposed and current layout doesn't route pointer events to it. Separately, chatPetService.onTheRun (read/set throughout chatPetWidget.ts) is not cleared by the /vscode-pet command, so the pet reappears then re-hides. Boundary: do not change the pet's rendering/animation pipeline or other context-menu actions (e.g. Reset Size) — this is isolated to the on-the-run positioning/offset and the slash-command's interaction with the persisted state. Refs: analysis in https://github.com/microsoft/vscode/issues/338959#issuecomment (comment by chryw, 2026-10-05).
- **Open decisions:**
  - Should the on-the-run offset scale with pet size (so the hit area is always proportionally visible), or should a minimum fixed hit area be guaranteed regardless of scale?
  - Should running /vscode-pet while on-the-run simply clear the onTheRun state (always bring the pet back), or should it only re-render without changing the persisted state?

## Evidence

- **scale vs fixed offset:** _setScale in src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts sets button width/height to displaySize = CHAT_PET_SOURCE_SIZE/2 * scale (around line 2614), while src/vs/workbench/contrib/chat/browser/widget/media/chatPet.css line 329 applies a fixed translateY(var(--vscode-spacing-size400)) for the on-the-run state — confirmed both exist on current main, matching the commenter's analysis.
- **onTheRun persistence:** chatPetService.onTheRun is read/toggled throughout chatPetWidget.ts (e.g. lines 2522-2529, 2491); no code path ties the /vscode-pet slash command to clearing this state, consistent with the reported flash-then-hide symptom.
- **workaround exists:** The 'Reset Size' action (chat.pet.resetSize, chatPetWidget.ts line 2518) resets scale to CHAT_PET_DEFAULT_SCALE and is only enabled when scale differs from default — a commenter confirmed running 'Reset Pet Size' via the command palette restores visibility, which is consistent with the shrink-related hit-area bug.
