# Issue #340376 — Dialog Cancel Button Misplaced for >2 Options on Linux/Mac

[https://github.com/microsoft/vscode/issues/340376](https://github.com/microsoft/vscode/issues/340376)

## Summary

Traced and confirmed on current main: the Linux/macOS branch of rearrangeButtons() in dialog.ts inserts the Cancel button at a fixed index-1 position before reversing, which misplaces it whenever there are 3+ buttons, instead of moving it to the end like the Windows branch already does.

## Change summary

For dialogs with more than 2 non-cancel buttons on Linux/macOS custom dialogs, the Cancel button renders in the wrong (second) position instead of leading the row.

## Best solution

In src/vs/base/browser/ui/dialog/dialog.ts rearrangeButtons(), replace `buttonMap.splice(1, 0, cancelButton)` with `buttonMap.push(cancelButton)` (mirroring the Windows branch) so that after `.reverse()` the Cancel button ends up leading, matching GNOME HIG/macOS HIG guidance for both the 2-button and N-button cases.
