# Issue #333483 — Agents - session provenance information rendering

[https://github.com/microsoft/vscode/issues/333483](https://github.com/microsoft/vscode/issues/333483)

## Summary

The provenance link remains confined to the originating request or the Sessions-list hover; current main does not expose it in the active session header. This team-authored Backlog feature request should remain open while the persistent presentation is designed.

## Change summary

Make a delegated session's origin persistently visible and accessible without scrolling to its first request.

## Best solution

Provide an always-visible provenance affordance in the Agents Window session header that identifies and opens the exact source session or chat, while keeping ordinary session titles and rename behavior clear.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/sessionHeaderBar.ts`, `src/vs/sessions/browser/parts/media/chatCompositeBar.css`, `src/vs/sessions/test/browser/sessionHeader.test.ts`
- **Validation:** Extend the SessionHeader browser tests to verify that a session with creation provenance has a persistent, keyboard-accessible source affordance that opens the exact source, while a normal session remains unchanged and inline rename still works.
- **Behavior:**

  > A session created from another session keeps its origin visible and reachable while the user scrolls through the transcript. Activating the provenance affordance opens the exact source session or chat. Sessions without creation provenance and existing title-renaming behavior remain unchanged, and the affordance is keyboard and screen-reader accessible.
- **Trace:**

  > The transcript-level source link is rendered by `ChatRequestOriginPart` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatRequestOriginPart.ts and therefore scrolls away with the originating request. `SessionHeaderBar._updateHeader` in src/vs/sessions/browser/parts/sessionHeaderBar.ts currently reads status and active-chat title only, despite `ISession.createdBySession` exposing the creator session, chat, and turn. The Sessions list already resolves this metadata into a creator link through `getCreatorHoverData` in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, establishing that navigation is possible. Keep request-level provenance, ordinary session headers, and rename semantics intact; the uncertainty starts at how persistent provenance should compose with the editable header title.
- **Open decisions:**
  - Should persistent provenance appear inline with the editable title, as secondary header metadata, or as another always-visible header affordance?

## Evidence

- **current request rendering:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatRequestOriginPart.ts renders "Sent by another session" as a link attached to an individual request, matching the report's need to scroll back to that request.
- **current header gap:** src/vs/sessions/browser/parts/sessionHeaderBar.ts `_updateHeader` renders only the active chat title and status; it does not read `session.createdBySession` or render creation provenance.
- **available model data:** src/vs/sessions/services/sessions/common/session.ts exposes observable `ISession.createdBySession` with session, chat, and turn provenance, so the required information is already available to Sessions-owned UI.
- **partial existing affordance:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts `getCreatorHoverData` exposes a Created by link through the Sessions-list hover, but this is not an always-visible affordance in the active session title/header.
