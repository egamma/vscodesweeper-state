# Issue #17281 — Add support for capture groups in onEnterRules

[https://github.com/microsoft/vscode/issues/17281](https://github.com/microsoft/vscode/issues/17281)

## Summary

Capture-group substitution remains missing: current onEnterRules test regexes but return appendText literally. Keep this team-authored, accepted request open; the discussion establishes interest but leaves product-contract questions to resolve.

## Change summary

Allow onEnterRules appendText to reuse regex capture groups, including comment prefixes and their internal indentation.

## Best solution

Define a backward-compatible declarative capture-reference contract for onEnterRules, then support preserving captured comment prefixes without entering snippet mode. Keep general cursor alignment, capture transformations, and nested-language indentation separate unless maintainers explicitly expand the scope.

- **Behavior:**

  > A language configuration should be able to reuse matched text in its Enter action, so continuing an indented line comment preserves both its prefix and whitespace after that prefix. The reported example should produce a new line containing '//     ' with the caret after that text, rather than inserting '$1'. Pressing Enter must not enter snippet mode. Acceptance must cover the agreed capture-reference semantics and preserve existing literal-text and indentation behavior outside that contract.
- **Trace:**

  > OnEnterSupport.onEnter in src/vs/editor/common/languages/supports/onEnter.ts evaluates three optional regex contexts using boolean tests and returns the configured action unchanged. The language-configuration extension point accepts appendText as a literal string, and getEnterAction plus cursorTypeEditOperations carry it into the inserted text without expansion. This establishes the missing capability from source; no execution was performed. The discussion settles $1-style syntax and excludes snippet mode, but the later maintainer comment asks for more discussion about the feature's scope. https://github.com/microsoft/vscode/issues/66235 concerns broader cursor alignment and is not resolved by simple capture reuse; nested-language indentation and transformations should not be assumed part of this request. The existing OnEnter and cursor suites provide validation surfaces once the observable contract is agreed.
- **Open decisions:**
  - Should this contract permit arbitrary captured text, as the proposed $1 syntax implies, or be restricted to whitespace/indentation as raised in the later maintainer discussion?
  - When existing appendText contains literal dollar-number text, how should extensions opt into capture substitution or escape literals so adoption does not silently change their output?
