# Issue #185362 — Allow extensions to opt-out of having a "contextualTitle" for a view

[https://github.com/microsoft/vscode/issues/185362](https://github.com/microsoft/vscode/issues/185362)

## Summary

Still a valid gap: extensions cannot opt out of the contextualTitle prefix when views are moved out of their default container. A team member (alexr00) expressed intent to backlog it, and it has 5 upvotes but hasn't reached the 20-upvote threshold.

## Change summary

Allow extensions to set contextualTitle to null or empty to prevent the container name prefix when a view is dragged out of its home.

## Best solution

In `src/vs/workbench/api/browser/viewsExtensionPoint.ts` line 523, allow `contextualTitle` to be explicitly set to empty string (or a sentinel) so that `containerTitle` can be left unset, which would skip the prefix logic in `viewPane.ts` line 631. The schema validation at line 614 would need to accept null/empty. This is a small, localized change in the tree-views/extension-point area.
