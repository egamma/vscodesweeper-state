# Issue #185362 — Allow extensions to opt-out of having a "contextualTitle" for a view

[https://github.com/microsoft/vscode/issues/185362](https://github.com/microsoft/vscode/issues/185362)

## Summary

The requested opt-out remains absent on current main, and a maintainer explicitly accepted the direction before the issue was placed in the Backlog. Keep it open for an extension-contribution API design decision.

## Change summary

Allow an extension-contributed view to suppress the source-container prefix that is added after users move the view elsewhere.

## Best solution

Add an explicit, documented opt-out to the `views` contribution contract while preserving the current container-name fallback for extensions that do not opt out. A moved opted-out view should retain its own title without a source-container prefix.

## Plan brief

- **Likely files:** `src/vs/workbench/api/browser/viewsExtensionPoint.ts`, `src/vs/workbench/browser/parts/views/viewPane.ts`, `src/vs/workbench/common/views.ts`
- **Validation:** Add a workbench test covering two contributed views moved outside their original container: the default view retains `<container>: <view>`, while an opted-out view renders only `<view>`.
- **Behavior:**

  > Extension authors can explicitly declare that a contributed view does not need source-container context after a user moves it. An opted-out moved view displays its own title without a `<home container>:` prefix. Views that omit the new declaration retain today's contextual-title behavior, including explicit string titles and the original-container fallback.
- **Trace:**

  > The `views` contribution schema and `IUserFriendlyViewDescriptor` are defined in src/vs/workbench/api/browser/viewsExtensionPoint.ts. During registration, line 523 uses a truthy `contextualTitle` or falls back to the original container title, so there is no representable opt-out state. ViewPane.calculateTitle in src/vs/workbench/browser/parts/views/viewPane.ts adds that value as a prefix whenever a view is outside its default container. `IViewDescriptor.containerTitle` in src/vs/workbench/common/views.ts is already optional, so the rendering path distinguishes an absent title; the uncertainty is the public JSON contribution contract, not the reported behavior. Preserve existing behavior for all contributions that do not explicitly opt out.
- **Open decisions:**
  - What public contribution shape should represent the opt-out—an explicit null value, a boolean property, or another schema form—while remaining backward-compatible with existing string `contextualTitle` values?
