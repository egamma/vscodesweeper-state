# Issue #206255 — Adopt Editor Hover for lightbulb / Editor Code Actions

[https://github.com/microsoft/vscode/issues/206255](https://github.com/microsoft/vscode/issues/206255)

## Summary

The requested hover adoption remains unimplemented on current main: the inline lightbulb still uses the native DOM `title`, while the gutter decoration provides no editor-hover message. This maintainer-authored request is already correctly routed to editor code actions and should remain open.

## Change summary

Replace the native lightbulb and sparkle tooltip with VS Code's editor-hover experience.

## Best solution

Give both inline and gutter lightbulb variants a consistent editor hover containing the existing action description and keybinding, while preserving click behavior and accessible labeling.

## Plan brief

- **Validation:** Manually trigger ordinary, preferred-fix, and AI lightbulb variants in both inline and glyph-margin positions; hovering each must show the editor-style tooltip with the correct label/keybinding, never a simultaneous native tooltip, while click behavior and keyboard/screen-reader labeling remain unchanged.
- **Behavior:**

  > Hovering any visible lightbulb or sparkle code-action icon should show the standard editor-hover presentation rather than a native browser tooltip. The hover must retain the existing action description and applicable keybinding text for ordinary, preferred-fix, and AI variants. Both inline and glyph-margin placements must behave consistently, without duplicate tooltips or changes to invoking code actions.
- **Trace:**

  > LightBulbWidget in src/vs/editor/contrib/codeAction/browser/lightBulbWidget.ts computes a shared LightBulbInfo but splits rendering between an inline content widget and a glyph-margin model decoration. `_updateLightBulbTitleAndIcon` currently writes `info.title` to the DOM `title`, conclusively leaving the native-tooltip path in place. `_updateGutterDecorationOptions` supplies icon and lane metadata but no `glyphMarginHoverMessage`; that message is consumed by src/vs/editor/contrib/hover/browser/glyphHoverComputer.ts. The boundary is tooltip presentation: do not alter code-action discovery, icon selection, placement, click coordinates, menu invocation, or accessible action naming. https://github.com/microsoft/vscode/issues/208987 is a later duplicate of this request; https://github.com/microsoft/vscode/issues/205737 is related hover-adoption work for a different editor action.
