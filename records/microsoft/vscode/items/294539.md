# Issue #294539 — cant update

[https://github.com/microsoft/vscode/issues/294539](https://github.com/microsoft/vscode/issues/294539)

## Summary

Keep open: commenters independently confirmed that Restart to Update exits without applying the update or reopening VS Code. Their steps and logs support investigation; neither a verified fix nor an older canonical covering this silent failure was established.

## Change summary

Windows updates can repeatedly offer Restart to Update without installing the pending version or relaunching VS Code.

## Best solution

Establish where the Windows update handoff fails and ensure a requested update either installs and relaunches successfully or reports an actionable failure. Distinguish this silent restart loop from installer extraction hangs and explicit executable-replacement errors.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.win32.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`
- **Validation:** On Windows with an update available, record the installed commit, select Restart to Update, and verify that VS Code relaunches with the offered commit and no longer offers that same update. Capture main.log and installer/updater logs across the attempt, and exercise both user and system installations because the discussion reports both.
- **Behavior:**

  > Windows users report that selecting Restart to Update closes VS Code without reopening it or advancing the installed version; reopening manually offers the same update again. Successful completion must install the offered version and relaunch VS Code. An unsuccessful installation must provide an actionable failure rather than silently repeating the update offer. Acceptance requires checking the installed commit before and after the restart, not merely observing that VS Code exits.
- **Trace:**

  > The discussion at https://github.com/microsoft/vscode/issues/294539 confirms the symptom historically, but no current-source reproduction was established. In src/vs/platform/update/electron-main/updateService.win32.ts, Win32UpdateService.handleRelaunch accepts a Ready update and delegates to doQuitAndInstall, which either releases the background installer's update flag or launches the installer with the runcode task. Current source also has versioned-update recovery in postInitialize, so begin by determining which path an affected installation uses and correlate main-process shutdown with installer logs. Preserve the distinction between this silent failure and the extraction/PowerShell hang discussed at https://github.com/microsoft/vscode/issues/317896. The similar later report at https://github.com/microsoft/vscode/issues/296791 is useful supporting evidence, not an eligible duplicate target for this re-reviewed item. Do not assume antivirus, extensions, or user-install scope is causal without reproducing the dependency.
