# Issue #91293 — [folding] context menu on expand/collapse arrow

[https://github.com/microsoft/vscode/issues/91293](https://github.com/microsoft/vscode/issues/91293)

## Summary

The requested folding-indicator context menu remains absent on current main, and later reports were explicitly consolidated into this older issue by a maintainer. This should remain open as the canonical request while the desired menu scope is decided.

## Change summary

Right-clicking an editor folding arrow should offer convenient folding actions such as Fold All and Unfold All.

## Best solution

Provide a context menu specifically for folding indicators that exposes the appropriate existing folding commands without changing left-click, middle-click, line-number, or glyph-margin behavior.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/contextmenu/browser/contextmenu.ts`, `src/vs/workbench/contrib/codeEditor/browser/editorLineNumberMenu.ts`, `src/vs/platform/actions/common/actions.ts`
- **Validation:** Launch Code OSS with a foldable document, right-click an expanded and a collapsed folding indicator, verify the approved folding menu appears and its actions affect the intended ranges, then confirm left-click, Shift-click, middle-click, line-number menus, and glyph-margin menus retain their existing behavior.
- **Behavior:**

  > Right-clicking a folding indicator opens a folding-specific context menu rather than doing nothing. The menu exposes the maintainer-approved set of existing folding operations and applies them to the intended line, range, or document scope. Existing mouse gestures and other gutter context menus remain unchanged.
- **Trace:**

  > FoldingController in src/vs/editor/contrib/folding/browser/folding.ts recognizes folding indicators as GUTTER_LINE_DECORATIONS, but its mouse path accepts only left and middle buttons. ContextMenuController in src/vs/editor/contrib/contextmenu/browser/contextmenu.ts rejects gutter targets, while EditorLineNumberContextMenu in src/vs/workbench/contrib/codeEditor/browser/editorLineNumberMenu.ts accepts line numbers and the glyph margin but not line decorations. The folding commands themselves already exist in folding.ts. The uncertainty begins at the public menu surface: later duplicates ask for both document-wide and range-relative actions, whereas the original report names collapse-all and expand-all. Preserve existing folding gestures and unrelated gutter menus.
- **Open decisions:**
  - Should the folding-indicator menu contain only document-wide Fold All and Unfold All actions from the original request, or also expose range-relative operations such as recursive, sibling, and child folding requested by the consolidated reports?

## Evidence

- **current source gap:** src/vs/editor/contrib/folding/browser/folding.ts handles folding indicators as MouseTargetType.GUTTER_LINE_DECORATIONS for left and middle clicks, but does not handle right-click context menus.
- **context-menu boundary:** src/vs/editor/contrib/contextmenu/browser/contextmenu.ts only shows the general editor menu for content text, content empty space, or the textarea; src/vs/workbench/contrib/codeEditor/browser/editorLineNumberMenu.ts handles GUTTER_LINE_NUMBERS and GUTTER_GLYPH_MARGIN, not folding indicators in GUTTER_LINE_DECORATIONS.
- **existing commands:** src/vs/editor/contrib/folding/browser/folding.ts already registers editor.foldAll, editor.unfoldAll, recursive folding, marker-region folding, and related actions; the missing capability is the requested invocation surface.
- **canonical status:** A maintainer explicitly closed https://github.com/microsoft/vscode/issues/128184, https://github.com/microsoft/vscode/issues/115417, and https://github.com/microsoft/vscode/issues/179832 as duplicates of this issue.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/60670 requests folding controls at the end of a range, not a right-click menu. The open https://github.com/microsoft/vscode/issues/225411 is newer and concerns general context-menu organization, so neither meets the stronger duplicate bar for this re-reviewed item.
