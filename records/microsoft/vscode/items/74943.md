# Issue #74943 — [json] Override/disable json-schema for package.json

[https://github.com/microsoft/vscode/issues/74943](https://github.com/microsoft/vscode/issues/74943)

## Summary

This remains a valid, well-supported feature request: user-configured JSON schema associations are additive and cannot suppress a matching built-in or extension-contributed schema. With 24 community upvotes and a Backlog milestone, it should remain open for design discussion rather than be closed for age.

## Change summary

Allow a workspace or user schema association to override or disable an automatically contributed JSON schema for matching files such as package.json.

## Best solution

Define an explicit precedence or exclusion mechanism in the JSON language-feature schema-association contract so users can replace selected built-in or extension contributions without disabling unrelated validation. Coordinate the behavior with the JSON language service and preserve multi-schema composition unless an association is explicitly excluded.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/package.json`, `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts`
- **Validation:** Add integration coverage with one extension-contributed schema and one user `json.schemas` association targeting the same file, then verify the maintainer-selected override or exclusion semantics while preserving normal composition for non-overriding associations.
- **Behavior:**

  > Users need a supported way to stop a matching built-in or extension-contributed schema from validating a particular JSON file and apply their chosen schema instead. A custom schema for a non-Node `package.json` must not be combined with the npm package schema when the user explicitly selects replacement behavior. Existing projects that rely on multiple matching schemas should retain their current composition unless they opt into the new behavior.
- **Trace:**

  > The issue demonstrates that user `json.schemas` associations and extension `jsonValidation` contributions are accumulated, so identical file matches produce merged validation rather than precedence. The npm extension contributes the package.json schema, while the JSON language-feature client forwards configured and contributed associations to the language service. https://github.com/microsoft/vscode/issues/209023 is a newer related request to suppress a specific extension contribution, not an eligible canonical for this re-reviewed older issue. The boundary is schema-association selection and transport; YAML-extension-specific matching and changes to schema contents are outside this issue.
- **Open decisions:**
  - Should an explicit user association replace every contributed schema matching that file, or should users name individual contributed associations to exclude?
  - Should replacement or exclusion apply at user, workspace, and folder scopes with normal configuration precedence, or be restricted to workspace/folder scope?
  - How should the contract distinguish intentional replacement from the existing behavior where multiple schemas are composed?
