# Issue #170347 — iPad: Cmd-C Cmd-X shortcuts for copying the current line don't work

[https://github.com/microsoft/vscode/issues/170347](https://github.com/microsoft/vscode/issues/170347)

## Summary

This is a WebKit/Safari bug on iPadOS where the browser does not fire the `copy` clipboard event when Cmd-C is pressed with no text selected. VS Code relies on the browser's native clipboard events — there is no fix in VS Code's own code, and the reporter has filed it with Apple (FB11920278). Tracked under the broader iPad evaluation issue.

## Change summary

Cmd-C and Cmd-X with no selection fail to copy/cut the current line on iPadOS because Safari does not fire the clipboard event.

## Best solution

This is blocked on Apple fixing the WebKit bug (FB11920278). A potential VS Code workaround could intercept the keyboard shortcut directly and use the Clipboard API, but that is complex and fragile. Best tracked as part of https://github.com/microsoft/vscode/issues/170498 (Evaluate iPad support). If Apple resolves the WebKit bug, this resolves automatically.

## Evidence

- **upstream bug:** The reporter's own investigation (comment 1) shows that Safari on iPadOS does not fire the `copy` DOM event on a textarea when no text is selected, unlike desktop Safari. This is a WebKit platform bug, not a VS Code bug.
- **Apple feedback:** Reporter filed Apple Feedback Assistant ticket FB11920278 for the Safari inconsistency.
- **code path:** VS Code's clipboard handling relies on the browser's native `copy` event (src/vs/editor/browser/controller/editContext/textArea/textAreaEditContextInput.ts:688 registers a DOM `copy` listener). If the browser never fires this event, VS Code has no opportunity to intercept the copy.
