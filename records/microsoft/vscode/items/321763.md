# Issue #321763 — tcsh/csh shell integration

[https://github.com/microsoft/vscode/issues/321763](https://github.com/microsoft/vscode/issues/321763)

## Summary

Keep this accepted feature request open: current source still lacks native tcsh/csh shell integration, and its 58 upvotes exceed the backlog threshold. Related reports do not establish an older canonical covering the same requested capability.

## Change summary

Provide native tcsh/csh terminal shell integration so command execution, completion, and exit status are available to VS Code and agent tools.

## Best solution

Design tcsh/csh support within the existing terminal shell-integration protocol, preserving user startup configuration and reliably reporting command boundaries and exit status. Evaluate agent shell identification separately, since integration alone does not guarantee shell-correct generated commands.

## Plan brief

- **Likely files:** `src/vs/platform/terminal/node/terminalEnvironment.ts`, `src/vs/platform/terminal/node/terminalProcess.ts`, `src/vs/code/node/cli.ts`, `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`, `src/vs/platform/terminal/test/node/terminalEnvironment.test.ts`, `src/vs/workbench/contrib/terminal/test/browser/xterm/shellIntegrationAddon.test.ts`
- **Validation:** Extend the getShellIntegrationInjection suite in src/vs/platform/terminal/test/node/terminalEnvironment.test.ts for the agreed shells and launch modes. In an interactive tcsh terminal, verify shell integration activates, successful and failing commands report their actual exit status, multiline input does not complete prematurely, and user startup files and environment remain intact; repeat for csh if included. Exercise an agent terminal command to verify completion and output delivery, independently checking shell-syntax selection.
- **Behavior:**

  > Users whose development environment requires tcsh currently cannot obtain the native shell integration available for bash, fish, pwsh, and zsh. The desired experience reports command execution, completion, and exit status without requiring a switch away from the user's shell or disrupting their startup environment. Acceptance should cover successful and failing commands, multiline input, and agent access to command output and completion. The supported contract for ancestor csh must be explicit, and shell integration must not be presented as automatically correcting model-generated shell syntax.
- **Trace:**

  > getShellIntegrationInjection in src/vs/platform/terminal/node/terminalEnvironment.ts has no tcsh/csh branch and returns UnsupportedShell for both; the bundled integration scripts likewise contain no implementation for them. The shellIntegration.enabled configuration advertises only existing supported shells, and src/vs/code/node/cli.ts rejects tcsh/csh in --locate-shell-integration-path. ShellIntegrationAddon already provides the receiver-side protocol, while TerminalProcess separately recognizes csh but not tcsh in its shell-type map. The trace establishes the missing capability, not whether tcsh and ancestor csh offer sufficiently equivalent hooks for reliable lifecycle reporting; that feasibility and support boundary need investigation. Preserve existing supported-shell behavior, user startup semantics, and protocol trust handling, and distinguish lifecycle integration from agent syntax generation. https://github.com/microsoft/vscode/issues/239631 concerns related shell-type/API work rather than owning this full request; https://github.com/microsoft/vscode/issues/328434 requests separate buffering and environment-inheritance behavior.
- **Open decisions:**
  - Should the initial supported contract cover tcsh only, or both tcsh and ancestor csh, given potentially different command-lifecycle hook capabilities?
