## Change summary

Prevent prompt-clearing SIGINT events from being reported as the exit status of an agent's subsequently executed terminal command.

## Best solution

Ensure terminal-tool results belong to the requested command, preserving genuine program exit code 130 while excluding prompt cancellation and previous-command completion. Review https://github.com/microsoft/vscode/pull/291861 against the mitigations already on main, then retest the recorded powerlevel10k configurations before deciding whether further work remains.

## Evidence

- **Confirmed reproduction:** https://github.com/microsoft/vscode/issues/271897#issuecomment-3414255202 records macOS 15.7.1, powerlevel10k revision 8fa10f4, and agent commands ls, sleep 5, and ls && sleep 5. Prompt-height-two, instant-prompt, and another combined configuration produced SIGINT-related incorrect sleep exit codes; this separate issue was created for that finding.
- **Reported impact and prompt distinction:** The January 30 explanation in https://github.com/microsoft/vscode/issues/271902 distinguishes powerlevel10k forwarding status 130 from canceled prompt input. The March 5 report describes agents retrying successful commands after receiving an apparent interruption. https://github.com/romkatv/powerlevel10k/issues/2934#issuecomment-4062810213 recommends distinguishing actual command execution using zsh preexec/precmd hooks rather than inferring it from status alone.
- **Current execution path:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1055-1061 still sends Ctrl+C before runCommand when prompt input is nonempty. RichExecuteStrategy.execute subscribes to completion before calling runCommand and excludes the previously executing command by marker identity. That mitigation does not itself prove that idle-prompt cancellation events from the reported powerlevel10k configurations cannot be mistaken for the requested command.
- **Related landed mitigation, not a proven complete fix:** https://github.com/microsoft/vscode/commit/8eaab1c0893e29a5d7105a39b4e9deddb1f23655 adds previous-command filtering in basicExecuteStrategy.ts and richExecuteStrategy.ts and changes basic execution to clear idle input with Ctrl+U instead of Ctrl+C. Current source contains these mitigations, but the inspected diff does not demonstrate resolution of the original powerlevel10k test cases; no completed-close provenance is established.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/291861 is OPEN and unmerged. It proposes correcting input tracking and completion-listener timing for successful commands reported as exit 130, references https://github.com/microsoft/vscode/issues/291871, and that issue was explicitly closed as a duplicate of this investigation at https://github.com/microsoft/vscode/issues/291871#issuecomment-3823815377. Agent readiness must remain none while this implementation candidate is open.
