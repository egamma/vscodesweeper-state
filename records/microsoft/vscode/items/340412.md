# Issue #340412 — NativeEditContext: Enter from a composing Android keyboard corrupts the new line

[https://github.com/microsoft/vscode/issues/340412](https://github.com/microsoft/vscode/issues/340412)

## Summary

Thanks for the detailed report. The code path matches the analysis: the EditContext text window is rebuilt from the caret's line on every selection change, so a composing Android keyboard (Gboard 12.4) ends up with offsets that point into a different line. It stays open. It is distinct from #338890, which is the older, related issue.

## Change summary

On Android with a composing keyboard, Enter corrupts the new line and Backspace after Enter at column 1 does nothing, because the NativeEditContext text window moves out from under the keyboard.

## Best solution

Keep the EditContext text window anchored at its start line after edits the keyboard made itself, and move it only on other caret changes. Also let a keyboard Backspace over a line break join lines in the composition path. Coordinate with the fix for #338890, since both touch nativeEditContext.ts.
