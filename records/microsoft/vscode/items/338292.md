# Issue #338292 — Copilot asks for node_modules read access if using pnpm global virtual store

[https://github.com/microsoft/vscode/issues/338292](https://github.com/microsoft/vscode/issues/338292)

## Summary

Traced in source: when a workspace-relative path (e.g. node_modules/pkg/package.json) resolves via symlink to a target outside the workspace, getFileExternalConfirmation takes the workingDir.getFolder branch and calls getWorkspaceFileExternalConfirmation, which never consults additionalReadAccessPaths — so configuring that setting with the pnpm global store path cannot suppress the prompt, exactly matching the reporter's experience.

## Change summary

Copilot repeatedly prompts for node_modules read access when pnpm's global virtual store symlinks packages outside the workspace, and the additionalReadAccessPaths workaround doesn't help.

## Best solution

In extensions/copilot/src/extension/tools/node/toolUtils.ts, have the symlink-resolution path (getWorkspaceFileExternalConfirmation / isExternalSymlinkedFile, called from getFileExternalConfirmation around line 244-246) also check the resolved realPath against additionalReadAccessPaths when options.readOnly is set, so a configured global store path suppresses the prompt the way the setting's docs imply.
