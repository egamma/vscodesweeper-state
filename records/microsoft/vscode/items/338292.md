# Issue #338292 — Copilot asks for node_modules read access if using pnpm global virtual store

[https://github.com/microsoft/vscode/issues/338292](https://github.com/microsoft/vscode/issues/338292)

## Summary

Traced the actual defect in current source: when pnpm's global virtual store puts node_modules as a symlink resolving outside the workspace, the external-file confirmation path resolves the real path and finds it outside the workspace, but never re-checks that resolved real path against `github.copilot.chat.additionalReadAccessPaths` — so the reporter's documented workaround genuinely cannot help, exactly as they observed.

## Change summary

Copilot repeatedly prompts for node_modules read access when pnpm's `virtualStoreType: global` symlinks packages outside the workspace, and the `additionalReadAccessPaths` setting doesn't suppress the prompt.

## Best solution

In `getWorkspaceFileExternalConfirmation` (extensions/copilot/src/extension/tools/node/toolUtils.ts), after resolving the symlink's real path and finding it outside the workspace, also check that resolved path against `ConfigKey.AdditionalReadAccessPaths` before deciding `needsConfirmation` — so the existing setting actually covers symlinked node_modules stores as documented.
