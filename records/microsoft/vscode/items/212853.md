# Issue #212853 — Can't click on links in streaming chat response

[https://github.com/microsoft/vscode/issues/212853](https://github.com/microsoft/vscode/issues/212853)

## Summary

Still reproducible on main in the default rendering path: the full DOM re-render during progressive streaming replaces anchor elements between mousedown and mouseup, losing the click event. The experimental incremental renderer (IncrementalDOMMorpher) would fix this via DOM diffing, but it's disabled by default.

## Change summary

Links in streaming chat responses are visually detected (appear blue) but are not clickable until the response finishes, because DOM replacement between mousedown and mouseup drops the click event.

## Best solution

Either enable the incremental DOM morpher by default (which preserves existing DOM nodes during streaming and inherently fixes this) or implement the mousedown/mouseup tracking workaround suggested in comment 11 for the legacy rendering path. The fix lives in `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts` and the markdown content part.

## Evidence

- **root cause traced:** Comment 10 by roblourens explains: clicking an element at the moment it's removed from the DOM (between mousedown and mouseup during progressive re-render) causes the click event to be totally lost. Confirmed with https://codepen.io/roblourens/pen/ExzJKdo in comment 14.
- **incremental renderer is experimental:** IncrementalDOMMorpher (added in commit 00a718eb5c9, April 2026) does DOM diffing that would fix this, but `chat.experimental.incrementalRendering.enabled` defaults to `false` in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts.
- **default path still re-renders fully:** In chatListRenderer.ts doIncrementalRender(), the non-incremental code path calls diff+renderChatContentDiff which replaces DOM nodes, reproducing the original issue.
- **partial fix reverted:** PR #215907 (Don't clear disposables too early) was reverted in commit 83b92b5e974; the deeper DOM-replacement issue was never addressed in the default path.
