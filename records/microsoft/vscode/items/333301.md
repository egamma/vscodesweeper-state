# Issue #333301 — MAI Cloud dictation keeps only the last few seconds in Japanese when Show Transcript is enabled

[https://github.com/microsoft/vscode/issues/333301](https://github.com/microsoft/vscode/issues/333301)

## Summary

Fresh, well-documented regression from the just-merged PR #332970 (merge commit b7f76c1a31, fixing #332324): with Show Transcript on, Japanese/Chinese MAI Cloud dictation keeps only a short tail after stopping, and with it off the original 60-second truncation reappears. Needs routing to the dictation/chat owner for further diagnosis — not a close.

## Change summary

MAI Cloud dictation in Japanese/Chinese loses most of the transcript on stop: only the last few seconds survive when Show Transcript is on, and the original ~60s truncation returns when it's off.

## Best solution

Route back to the author of the recently merged fix (PR https://github.com/microsoft/vscode/pull/332970, commit b7f76c1a312bccf8e408c485a5c0746bb27b1205) to investigate two things: (1) `selectFinalDictationTranscript` in chatSpeechToTextService.ts uses a plain `.startsWith()` prefix check between the live and backend transcripts — if the live transcript itself is a rolling/truncated window for CJK text (as the reporter describes even mid-dictation), that check fails and the function falls back to the short live text instead of the full backend transcript; and (2) whether the backend-side truncation behind the original #332324 report is still present for the OFF case, meaning that fix may not have addressed the true root cause. Needs a live-audio repro with actual CJK dictation to pin down whether the rolling window originates in the MAI Cloud transcription events or the client accumulation logic.
