# Issue #333301 — MAI Cloud dictation keeps only the last few seconds in Japanese when Show Transcript is enabled

[https://github.com/microsoft/vscode/issues/333301](https://github.com/microsoft/vscode/issues/333301)

## Summary

Genuine, well-diagnosed regression in MAI Cloud dictation for Japanese/Chinese: the reporter provided a video and trace log, and the client code confirms the mechanism — already correctly labeled bug/upstream/dictation, so this just needs a fix, not a triage change.

## Change summary

With MAI Cloud dictation, enabling Show Transcript causes only the last few seconds of Japanese/Chinese dictation to survive after stopping, while disabling it reverts to the older ~60s truncation bug (#332324); the final transcript should not depend on the Show Transcript setting.

## Best solution

In chatSpeechToTextService.ts, `_emitTranscript`/`_handleMaiTranscription` unconditionally trust `e.text` as the full cumulative transcript (line ~902, `this._finalizedText = text`), but for some languages MAI Cloud appears to send a rolling interim window in `text` while leaving `committed` empty — the reporter's own suggested defensive check (don't let the live/interim text overwrite the accumulated transcript when `committed` is empty, and prefer the longer backend final) is a reasonable starting point, but the right fix depends on confirming MAI's actual interim-transcript contract per language, which needs a maintainer/backend-owner decision.
