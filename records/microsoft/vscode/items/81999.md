# Issue #81999 — The result of proxyResolver.request is wrong

[https://github.com/microsoft/vscode/issues/81999](https://github.com/microsoft/vscode/issues/81999)

## Summary

Still reproduces on main: the `@vscode/proxy-agent` URL-detection heuristic (`url && url.searchParams`) misclassifies an options object that carries URL-derived properties as a URL, causing `method` and other request options to be lost. The issue is team-authored and remains valid.

## Change summary

When an extension passes an options object with `searchParams` to `https.request()`, the proxy resolver's argument-parsing heuristic misidentifies it as a URL, discarding `method` and other non-URL properties.

## Best solution

Fix the URL-detection heuristic in `@vscode/proxy-agent` (`createHttpPatch`) to use a more reliable check — e.g., `url instanceof URL` or checking the constructor — rather than duck-typing on `searchParams`. The fix belongs in the `microsoft/vscode-proxy-agent` repo.
