# Issue #81999 — The result of proxyResolver.request is wrong

[https://github.com/microsoft/vscode/issues/81999](https://github.com/microsoft/vscode/issues/81999)

## Summary

The faulty overload discrimination still exists in the current @vscode/proxy-agent source: an options object containing `searchParams` is treated as a URL, causing the request options to be lost. Keep this team-authored Backlog issue open while the dependency is corrected and updated in VS Code.

## Change summary

Preserve the method and other request options when `http.request` or `https.request` receives an options object that happens to contain a `searchParams` property.

## Best solution

Correct the request-overload detection in microsoft/vscode-proxy-agent so only actual URL arguments enter the URL branch, add a regression test using an options object with `method: 'POST'` and `searchParams`, then consume the fixed package in VS Code.
