# Issue #333639 — New plugin view keeps resetting to the top

[https://github.com/microsoft/vscode/issues/333639](https://github.com/microsoft/vscode/issues/333639)

## Summary

Team-authored bug filed hours ago describing the new plugin/MCP browsing view losing scroll position while the user scrolls; tracing the source shows the home/browse card surface is a plain DOM node that gets fully torn down and rebuilt (`DOM.clearNode` + re-append) on every refresh, which resets scrollTop — a plausible root cause for the reported symptom, but not yet confirmed by running the UI.

## Change summary

The plugin/MCP customization list view (aiCustomization plugin browsing UI) keeps snapping back to the top while the user scrolls with the mousewheel, and its scrollbar isn't styled like the rest of the workbench.

## Best solution

In src/vs/workbench/contrib/chat/browser/aiCustomization/pluginListWidget.ts, preserve and restore the `.plugin-card-scroll` scrollTop across `renderPluginHome`/`renderBrowseMarketplaceCards`/`updateSearchResultsList` rebuilds (all of which do `DOM.clearNode(this.cardContainer)` then re-append fresh content), and give the scroll container a themed scrollbar (e.g. via a Monaco `DomScrollableElement`/existing scrollbar styling utility) instead of the native unstyled one.
