# Issue #295181 — GitHub Copilot Chat: Org-wide custom agents from .github-private only appear from one org when user belongs to multiple orgs (regression in VS Code 1.109)

[https://github.com/microsoft/vscode/issues/295181](https://github.com/microsoft/vscode/issues/295181)

## Summary

Multi-organization agent aggregation remains missing: current discovery explicitly selects one preferred organization, and existing tests enforce that behavior. Keep this open as a capability request requiring design review; the reported 1.109 regression is not established by the available history.

## Change summary

Make accessible organization-defined custom agents available across multiple GitHub organizations instead of showing agents from only one preferred organization.

## Best solution

Provide multi-organization custom-agent discovery without making workspace order determine which organization's agents are available. Preserve organization-specific instruction scoping and avoid restoring the duplicate-agent and excessive-request problems documented in the original implementation discussion.

  > A signed-in user with access to distinct custom agents in two organizations should be able to discover and select agents from both organizations. Acceptance includes the reported two-organization setup, reversed workspace order, and no duplicate entries for the same source agent.
- **Trace:**

  > GitHubOrgCustomAgentProvider.provideCustomAgents obtains one organization through GitHubOrgChatResourcesService.getPreferredOrganizationName and reads only that organization's agent cache. The service's computePreferredOrganizationName prioritizes the first workspace folder, then the first Copilot-token organization, then one user organization; startPolling also uses that singular result. Existing tests deliberately assert these selection semantics, so the source establishes a missing aggregation capability rather than an accidental deviation from the present contract. GitHubOrgInstructionsProvider shares the service and must retain its instruction-scoping behavior. The historical discussion at https://github.com/microsoft/vscode/issues/274341#issuecomment-3627855505 identifies discovery-request scaling, and https://github.com/microsoft/vscode/issues/287074 records the previous duplicate-agent failure. - **Open decisions:**
