# Issue #131203 — Make horizontal cursor scroll padding configurable

[https://github.com/microsoft/vscode/issues/131203](https://github.com/microsoft/vscode/issues/131203)

## Summary

Keep open: horizontal cursor-reveal padding still lacks a supported user setting. The maintainer explicitly reopened this request after confirming that scrollBeyondLastColumn does not cover it, and the current source preserves that distinction.

## Change summary

Allow users to configure horizontal surrounding space maintained when cursor movement scrolls the editor.

## Best solution

Provide a supported horizontal cursor-surrounding-space setting in the editor configuration and reveal path, preserving existing defaults. Settle its units and left/right semantics before implementation; the vertical capability already exists.

- **Behavior:**

  > Users can configure horizontal space surrounding the cursor when keyboard navigation causes horizontal scrolling. Changing the value must affect cursor reveal, not merely add scrollable space beyond the line. Acceptance checks exercise arrow-key movement in both directions and End on a long unwrapped line, with distinct configured values. Existing vertical cursorSurroundingLines behavior and the default horizontal experience remain unchanged.
- **Trace:**

  > ViewLines._computeScrollLeftToReveal in src/vs/editor/browser/viewParts/viewLines/viewLines.ts computes visible bounds and expands non-minimal reveals with a fixed left margin and the internal revealHorizontalRightPadding option on the right. That option is declared in src/vs/editor/common/config/editorOptions.ts without a schema, and editorConfigurationSchema.ts only registers schema-bearing options as user settings. Separately, ViewLayout uses scrollBeyondLastColumn to compute scrollable width, confirming the reporter's distinction. The maintainer accepted that distinction and reopened https://github.com/microsoft/vscode/issues/131203. The remaining uncertainty is the public setting contract, not whether vertical padding already exists. Preserve minimal-reveal behavior, existing defaults, vertical navigation, and independent beyond-last-column scrolling.
- **Open decisions:**
  - Should horizontal surrounding space be expressed in character widths, as requested, or in pixels like the existing internal right-padding option?
  - Should one setting establish symmetric left/right surrounding space, or should users be able to configure the two sides independently?
