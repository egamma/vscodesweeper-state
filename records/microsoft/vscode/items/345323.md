# Issue #345323 — Agent Host: provide a portable way for extension-contributed agent hooks to locate extension resources

[https://github.com/microsoft/vscode/issues/345323](https://github.com/microsoft/vscode/issues/345323)

## Summary

Keep open as a supported resource-resolution request, rather than a promise to propagate extension-host environment changes. Current source preserves agent hook commands but does not establish a portable contributing-extension resource root.

## Change summary

Provide or document a portable way for extension-contributed agent hooks to invoke bundled scripts across local and remote execution.

## Best solution

Establish a documented resource-location contract for extension-contributed agents, including resource availability on the executing host. Assess existing plugin-root conventions before introducing another mechanism, without propagating arbitrary extension-host environment variables.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/service/extensionPromptFileService.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/syncedCustomizationBundler.ts`, `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`, `src/vs/platform/agentPlugins/common/pluginParsers.ts`
- **Validation:** Using the issue's contributed-agent example, invoke PreToolUse with scripts under two different extension installation paths, including paths with spaces, then repeat with a remote Agent Host. The supported mechanism must execute the bundled script without a hard-coded installation path or extension-host environment inheritance; existing explicit env overrides and agent-specific hook isolation must remain unchanged.
- **Behavior:**

  > An extension author can use a documented mechanism for an agent hook to locate scripts shipped with that extension. Moving or updating the extension must not require rewriting installation-specific paths. The mechanism must define how resources become available when the Agent Host executes remotely. Acceptance covers the reported PowerShell PreToolUse example, paths containing spaces, and unchanged explicit hook environment behavior.
- **Trace:**

  > ExtensionPromptFileService retains the contributing extension description when registering agent files. SyncedCustomizationBundler copies agent definitions individually and records extension provenance, but only skill directories receive recursive resource copying. In copilotPluginConverters.ts, getCustomAgentHooks and toSdkCustomAgents forward frontmatter hooks without resolving extension resources. Existing pluginParsers.ts root interpolation applies to plugin-context hooks through hookSchema.ts and is relevant prior art, not proven coverage for this agent path. Preserve process isolation, hook enablement, agent-specific hook separation, and connection-owned URI boundaries. Uncertainty starts at the supported author-facing root/resource contract and how remote hosts acquire the required resources; https://github.com/microsoft/vscode/issues/345323 does not select those semantics.
- **Open decisions:**
  - Should extension-contributed agent hooks use the existing plugin-root authoring contract, or expose a distinct contributing-extension resource contract?
  - For remote execution, which bundled resources are made available to the Agent Host, and what supported behavior applies when the contributing extension is installed only on the client?
