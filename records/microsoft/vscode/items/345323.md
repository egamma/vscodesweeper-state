# Issue #345323 — Agent Host: provide a portable way for extension-contributed agent hooks to locate extension resources

[https://github.com/microsoft/vscode/issues/345323](https://github.com/microsoft/vscode/issues/345323)

## Summary

Keep open: existing plugin-root interpolation does not establish a portable resource-location contract for extension-contributed agent hooks. This team-authored request needs a supported local/remote resource contract, not propagation of arbitrary extension-host environment changes.

## Change summary

Provide or document a portable way for extension-contributed agent hooks to invoke scripts bundled with their contributing extension.

## Best solution

Define and document an extension-scoped resource-location contract that resolves to files accessible on the executing Agent Host, including remote hosts. Reuse existing plugin-root conventions where appropriate without confusing a synthesized bundle root with the contributing extension's installation directory.

Acceptance must also exercise the reported PreToolUse PowerShell hook locally and with a remote Agent Host, without activation-time process.env mutation or machine-specific absolute paths.
- **Behavior:**

  > An extension-contributed agent hook can invoke its bundled script through a documented, portable authoring contract. The same contribution continues to work after the extension installation location changes and when hook execution occurs on a remote Agent Host. Resources from different contributing extensions remain distinguishable. Existing explicit hook environment maps and ordinary plugin-root behavior remain unchanged.
- **Trace:**

  > ExtensionPromptFileService retains contributing-extension metadata when registering prompt files. SyncedCustomizationBundler._bundle flattens ordinary agent files into a synthesized package but recursively includes supporting resources only for skills. In copilotPluginConverters.ts, getCustomAgentHooks extracts authored frontmatter and toSdkCustomAgents forwards it without extension-root resolution. pluginParsers.ts already supplies plugin-root interpolation, but that identifies a plugin package rather than necessarily the original extension, and does not make omitted scripts available remotely. The trace establishes the distinction between locating a resource and delivering it; it does not establish an existing end-to-end extension-resource contract. Preserve process isolation, existing hook semantics, and host/client URI ownership. The requested behavior is recorded at https://github.com/microsoft/vscode/issues/345323.
- **Open decisions:**
  - What supported authoring contract should identify resources belonging to the contributing extension: an extension-root placeholder/environment variable or an explicit resource declaration?
  - For remote Agent Hosts, must bundled resources be declared and materialized on the executing host, or is support limited to extensions already installed alongside that host?
