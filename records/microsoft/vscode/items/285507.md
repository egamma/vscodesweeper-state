# Issue #285507 — Detect adding files to git index made via the command line and auto keep

[https://github.com/microsoft/vscode/issues/285507](https://github.com/microsoft/vscode/issues/285507)

## Summary

Keep open: command-line staging updates SCM but does not trigger the chat-edit acceptance performed by VS Code's staging action. Neither the existing auto-accept setting nor the verified older related issues covers this CLI-specific gap.

## Change summary

Automatically keep pending chat edits when their files are staged through the command line, matching full-file staging in SCM.

## Best solution

Make externally detected full-file staging acknowledge the corresponding pending chat edits without accepting unrelated or subsequently unstaged edits. Keep partial-hunk acceptance coordinated with the separate partial-staging request.

- **Validation:** In a focused VS Code window with git.autorefresh enabled and chat.editing.autoAcceptDelay set to 0, generate and save pending chat edits in two files. Run git add for only one file through the terminal, wait for SCM to refresh, and verify that only that file's edits become kept, matching the SCM + action. Repeat status refresh and introduce a new unstaged edit to ensure an already-staged file does not cause unrelated edits to be accepted. Establish automated coverage using the Git extension smoke-test harness and a chat-editing session.
- **Behavior:**

  > Staging a complete file through command-line Git should keep its corresponding pending chat edits just as staging that file through the SCM + action does. Pending edits in other files must remain pending. Refreshing SCM without a new staging action must not accept newly generated unstaged edits. Validate with timed auto-accept disabled so the result is attributable to staging rather than the countdown.
- **Trace:**

  > Repository.add in extensions/git/src/repository.ts explicitly invokes _chat.editSessions.accept after the Git add operation; the command in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts accepts the supplied resources across editing sessions. External index changes instead pass through DotGitWatcher, Repository.onFileChange, status refresh, and _updateResourceGroupsState, which update SCM without invoking that acceptance command. The integration gap is established in current source, but reliably distinguishing newly staged content from an existing staged entry plus later unstaged edits still needs diagnosis. Preserve existing autorefresh, focus, and repository-size behavior, and do not broaden acceptance to every file already present in the index. Partial-hunk acceptance is separately discussed at https://github.com/microsoft/vscode/issues/274100; it is related work, not a duplicate canonical. extensions/git/src/test/smoke.test.ts already provides real Git operations and SCM-state checks, but combined chat-session coverage remains to be established.
