# Issue #332618 — Markdown preview emits duplicate heading ids when a heading matches a generated suffix

[https://github.com/microsoft/vscode/issues/332618](https://github.com/microsoft/vscode/issues/332618)

## Summary

Confirmed real bug: the slug builder's dedupe map only records base slugs, never the generated `-N` suffix, so a base slug that later collides with an already-emitted suffixed id gets handed out twice. An open PR (#332628) already targets exactly this fix, so this should stay open for that PR to be reviewed and merged rather than closed or auto-fixed here.

## Change summary

Markdown preview heading-id slugifier can emit two elements with the same id when a heading's base slug collides with a previously auto-generated `-N` suffix (e.g. headings `Foo`, `Foo-1`, `Foo` both produce `foo-1`).

## Best solution

Land https://github.com/microsoft/vscode/pull/332628, which fixes `createBuilder` in extensions/markdown-language-features/src/slugify.ts to also register generated suffixed ids in the dedupe map so later collisions advance to a free id, matching github-slugger semantics.

## Evidence

- **source trace:** extensions/markdown-language-features/src/slugify.ts `createBuilder()`: on collision it computes `this.fromHeading(slug.value + '-' + existingSlugEntry.count)` and returns it directly without calling `entries.set(...)` for that derived slug, so the derived id is never itself recorded as taken.
- **traced repro:** Manually traced headings Foo, Foo-1, Foo: 1) 'foo' -> entries={foo:0}; 2) 'foo-1' -> entries={foo:0, foo-1:0}; 3) 'foo' again -> count becomes 1, returns fromHeading('foo-1') = 'foo-1', colliding with heading 2's id — matches the reporter's observed output exactly.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/332628 ('Markdown preview: make heading slug dedupe collision free') is open and targets this exact function; not yet merged into main (git log on slugify.ts shows no related recent commit).
