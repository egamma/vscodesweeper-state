# Issue #74585 — Make `editor.gotoLocation.multiple: "goto"` state UX more discoverable 

[https://github.com/microsoft/vscode/issues/74585](https://github.com/microsoft/vscode/issues/74585)

## Summary

Peek-less navigation still advertises its active state through a status-bar message, so the discoverability concern remains. Keep this open for a UX decision that balances first-use guidance against repeated interruptions.

## Change summary

Make the active multi-result navigation state and its F12 cycling shortcut easier to discover when using goto mode.

## Best solution

Provide discoverable, unobtrusive guidance for peek-less symbol navigation without changing its navigation semantics. Settle whether clearer settings wording is sufficient or whether first-use guidance near the editor is warranted, accounting for the maintainer's concern about recurring messages.

- **Behavior:**

Guidance should not repeatedly interrupt experienced users. Acceptance must cover first use, repeated navigation, and unchanged F12 cycling and Escape cancellation; the exact guidance policy requires a maintainer decision.
- **Trace:**

  > SymbolNavigationAction._onResult in src/vs/editor/contrib/gotoSymbol/browser/goToCommands.ts registers the result set with SymbolNavigationService.put for goto mode. In src/vs/editor/contrib/gotoSymbol/browser/symbolNavigation.ts, _showMessage provides result position and the cycling keybinding solely through INotificationService.status, which the workbench renders in the status bar. Preserve existing navigation, cancellation, and peek-mode semantics; uncertainty begins at whether and how additional first-use guidance should appear.
- **Open decisions:**
