# Issue #194117 — Cannot undo file deletions from a WorkspaceEdit

[https://github.com/microsoft/vscode/issues/194117](https://github.com/microsoft/vscode/issues/194117)

## Summary

Confirmed bug, still present on main. When a file is deleted via WorkspaceEdit API, the undo element is pushed with the deleted file's URI as its resource, but since the file's editor is closed upon deletion, the user has no way to trigger undo for that resource — the undo/redo service needs a resource context that no longer exists.

## Change summary

File deletions performed via the WorkspaceEdit API cannot be undone because the undo element's resource (the deleted file) has no open editor to serve as the undo trigger.

## Best solution

The undo/redo element for a WorkspaceEdit file deletion needs to be accessible without requiring the deleted file's editor to be open. Either the undo element should be associated with a broader resource (e.g., the workspace root or the parent folder), or there should be a global undo mechanism that can reach workspace-scoped undo elements not tied to any open editor. The fix likely involves `src/vs/workbench/contrib/bulkEdit/browser/bulkFileEdits.ts` and possibly the undo/redo service's element retrieval logic.
