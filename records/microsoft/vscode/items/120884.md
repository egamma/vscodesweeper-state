# Issue #120884 — Code screen will move up after write a unimported package method and undo

[https://github.com/microsoft/vscode/issues/120884](https://github.com/microsoft/vscode/issues/120884)

## Summary

A real editor undo/redo gap remains on current main: text edits preserve cursor selections but not viewport state, so undoing imports inserted above the cursor can leave the visible code displaced. The issue is already accepted in the Backlog and correctly routed to undo-redo.

## Change summary

Preserve a useful editor viewport position when undoing or redoing edits that insert or remove lines above the cursor.

## Best solution

Make undo/redo retain the user's code context when line-changing edits alter the viewport, including additional import edits, while defining how historical viewport restoration interacts with deliberate scrolling after an edit.

## Plan brief

- **Likely files:** `src/vs/editor/common/model/editStack.ts`, `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/editor/contrib/suggest/browser/suggestController.ts`, `src/vs/editor/test/browser/widget/codeEditorWidget.test.ts`
- **Validation:** Add an editor widget test that applies an additional edit inserting lines above the visible cursor, performs undo and redo, and asserts the chosen viewport anchoring behavior without changing the existing cursor restoration behavior.
- **Behavior:**

  > Accepting a completion that inserts imports above the current code and then undoing it must not progressively displace the visible code context. Repeating completion and undo should leave the user anchored consistently rather than moving the viewport by the number of inserted lines. Existing text, cursor-selection, and redo behavior must remain intact.
- **Trace:**

  > The confirmed path starts in src/vs/editor/contrib/suggest/browser/suggestController.ts, where additionalTextEdits are applied under StableEditorScrollState. Undo then runs through the editor command to ITextModel.undo(), whose SingleModelEditStackData in src/vs/editor/common/model/editStack.ts records text changes and before/after cursor selections but no scroll or viewport state. CodeEditorWidget in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts already exposes saveViewState/restoreViewState, but model undo has no editor-view association. The boundary is ordinary code-editor undo/redo: do not alter extension-provided import edits, text undo grouping, or non-editor undo providers. Related closed reports such as https://github.com/microsoft/vscode/issues/92640 establish similar demand but do not provide a shipped fix or an open canonical issue.
- **Open decisions:**
  - When the user scrolls after making an edit, should undo restore the historical viewport from the edit or preserve the user's newer viewport while compensating only for inserted or removed lines?
  - Should viewport restoration preserve the exact historical scroll position or preserve the cursor's relative vertical position within the viewport?
