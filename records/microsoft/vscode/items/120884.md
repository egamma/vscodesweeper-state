# Issue #120884 — Code screen will move up after write a unimported package method and undo

[https://github.com/microsoft/vscode/issues/120884](https://github.com/microsoft/vscode/issues/120884)

## Summary

Keep open as an editor undo/redo feature request: a maintainer reproduced the viewport drift and identified the missing behavior as restoring scroll position through undo. The Backlog milestone permits cleanup review but does not establish a factual close, and no canonical issue or fixing change is cited.

## Change summary

Record and restore the editor viewport scroll position when undoing completion edits that insert import lines above the visible code.

## Best solution

Define viewport restoration semantics for undo/redo, then integrate scroll state with the editor undo/redo path so reverting additional completion edits does not leave the viewport displaced while ordinary content scrolling remains unaffected.

## Plan brief

- **Likely files:** `src/vs/editor/common/model/editStack.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/editor/contrib/suggest/browser/suggestController.ts`
- **Validation:** Add or extend an editor integration test that accepts a completion with additional import edits above the viewport, undoes it, and asserts that both the model content and pre-acceptance viewport position are restored; redo should produce a defined, symmetric viewport result.
- **Behavior:**

  > Accepting a completion that inserts import lines above the current code must not cause cumulative viewport drift when the action is undone. After undo, the original document content and visible viewport should be restored; repeating accept and undo must leave the same lines visible each time. Ordinary user scrolling and undo of edits that do not affect the viewport should retain their existing behavior.
- **Trace:**

  > The maintainer-confirmed flow begins in the suggest controller, where accepting a completion applies the primary edit plus additional import edits. In the reported Go case those edits insert two lines above the current location and suggestion handling advances scrollTop by two line heights; undo removes the model lines but the undo/redo state does not restore the previous viewport, leaving the screen displaced. The likely boundary spans suggestion application in src/vs/editor/contrib/suggest/browser/suggestController.ts, editor view state in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts, and model undo elements in src/vs/editor/common/model/editStack.ts. The behavior also reproduces with Python auto-imports, so the solution must remain language-agnostic and must not special-case an extension.
- **Open decisions:**
  - Should scroll position be stored in the general text-model undo stack, or should the code editor restore view state around undo/redo independently of model history?
  - How should viewport restoration behave when the same text model is attached to multiple editors or when the user scrolls manually after the edit but before undo?
  - Should redo restore the post-edit viewport symmetrically, and which edit operations should capture viewport state?
