# Issue #286547 — running (multiple) background agents using the copilot chat

[https://github.com/microsoft/vscode/issues/286547](https://github.com/microsoft/vscode/issues/286547)

## Summary

Keep open: a maintainer confirmed that background subagents are desirable and that no existing issue covered this request. The newer related coordination issue cannot be the duplicate canonical under the re-review policy.

## Change summary

Allow a chat agent to launch multiple background subagents in parallel, including independently scoped work across repositories in a multi-root workspace.

## Best solution

Design agent-initiated background delegation with explicit per-child workspace or repository scope, bounded parallelism, lifecycle visibility, and consolidated results in the parent conversation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat`, `src/vs/platform/agentHost`
- **Validation:** Add an end-to-end agent-host scenario in which a parent turn starts at least two independently scoped child tasks, confirms they overlap in execution, and reports each child's completion and result to the parent without mixing repository scope.
- **Behavior:**

  > From one Copilot chat request, the active agent can delegate independent work to multiple background agents and run those tasks concurrently. Each child is scoped to the intended repository or workspace folder, remains visible and controllable to the user, and returns its result to the parent without contaminating another child's context. Acceptance should cover both parallel work across folders in a multi-root workspace and multiple independent children in one folder, including partial failure or cancellation.
- **Trace:**

  > The issue establishes a product gap rather than a defect: the existing flow can delegate a manually scoped task, but the parent agent cannot autonomously fan independent work out to parallel background agents. The relevant architecture spans chat-side tool or command exposure and agent-host child-session orchestration under src/vs/workbench/contrib/chat and src/vs/platform/agentHost. https://github.com/microsoft/vscode/issues/331521 should inform the child-session coordination model, but it is newer and does not replace this re-reviewed issue as a canonical. Preserve explicit user visibility and control; do not turn arbitrary slash commands into unrestricted model actions or silently merge repository scopes.
- **Open decisions:**
  - Must the user explicitly approve each child launch, or may the parent agent autonomously create children within a configured concurrency limit?
  - How are repository or workspace-folder scopes presented and enforced for each child when one request spans a multi-root workspace?
  - Which child lifecycle controls and outcomes must be visible in the parent chat, including cancellation, partial failure, and result consolidation?
