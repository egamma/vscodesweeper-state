# Issue #345646 — MCP local (stdio) servers from ~/.copilot/mcp-config.json fail with spawn ENOENT on Windows client + Remote WSL

[https://github.com/microsoft/vscode/issues/345646](https://github.com/microsoft/vscode/issues/345646)

## Summary

The current source still converts the remote home directory into a client-platform path before launching discovered stdio servers. Keep this open while the linked fix proposal is reviewed and merged.

## Change summary

Preserve remote home-directory paths when starting stdio MCP servers discovered on a Linux remote from a Windows client.

- **Current discovery defect:** src/vs/workbench/contrib/mcp/common/discovery/nativeMcpDiscoveryAdapters.ts passes { cwd: homedir } from ClaudeDesktopMpcDiscoveryAdapter.adaptFile and CopilotMpcDiscoveryAdapter.adaptFile. - **Failing launch path:** src/vs/base/common/uri.ts:636-658 implements client-platform fsPath conversion, replacing slashes with backslashes on Windows. src/vs/workbench/api/node/extHostMcpNode.ts:103-120 treats that string as relative on Linux, joins it beneath home, and passes the resulting nonexistent working directory to spawn; an existing executable can consequently fail with ENOENT.

Its fetched description explicitly says Fixes microsoft/vscode issue 345646 and proposes URI-backed defaultCwd for Claude Desktop, Copilot, Cursor, and Windsurf, with unchanged trust nonces.
