## Evidence

- **Reported behavior and workaround:** https://github.com/microsoft/vscode/issues/304446 reports repeated failures on macOS with zsh, VS Code 1.112.0 and Copilot Chat 0.40.1. The author's follow-up confirms recurring occurrences with a standard zsh setup; writing the message to a file and using git commit -F succeeds. Neither the body nor the supplied comment includes the exact failing tool command.
- **Current input path:** All three execution strategies in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy request bracketed paste on macOS: richExecuteStrategy.ts:178-179, basicExecuteStrategy.ts:222-223 and noneExecuteStrategy.ts:95-96. TerminalInstance.sendText in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1404-1419 adds paste delimiters only when the terminal reports bracketed-paste mode enabled, normalizes newlines and writes the input. This trace establishes a mitigation, not reproduction or resolution of the reported command.
- **Relevant landed mitigation:** https://github.com/microsoft/vscode/commit/5a791c66df14380b290733af553722f3497c95d2 introduced bracketed-paste execution on 2026-03-23. Its diff passes the paste flag from the execution strategies and forwards it through TerminalInstance.runCommand to sendText. It explicitly fixes https://github.com/microsoft/vscode/issues/296955, whose confirmed macOS multiline-input corruption could lose closing quotes. This is a plausible explanation here, but the missing command and payload size prevent establishing the same cause.
- **Later multiline change is not proof for this report:** https://github.com/microsoft/vscode/commit/cdfcb3840676b91089318618a62b283b0866b24e extends bracketed-paste requests to multiline commands on other platforms and preserves multiline input in send_to_terminal. Its execution-strategy diffs retain the already-existing macOS condition, so those changes alone do not prove this macOS run_in_terminal report fixed.
- **Canonical search:** Read https://github.com/microsoft/vscode/issues/304928, https://github.com/microsoft/vscode/issues/315694 and https://github.com/microsoft/vscode/issues/338117, and searched open reports for zsh commit and dquote symptoms. The first reports commit-message corruption without a verified shared cause; the second reports a similar continuation-prompt hang but does not establish the same cause; the third concerns missing command output. No verified open canonical owns this exact defect.
- **Hang mitigation is not quoting repair:** A maintainer on https://github.com/microsoft/vscode/issues/315694#issuecomment-4444280400 points to https://github.com/microsoft/vscode/pull/315885. That merged PR promotes silent synchronous commands to background after an idle timeout; it does not repair malformed or corrupted shell input and therefore cannot substantiate a completed close here.
