# Issue #347477 — Agents Window: drag sessions from the session list into the chat input to add them as context

[https://github.com/microsoft/vscode/issues/347477](https://github.com/microsoft/vscode/issues/347477)

## Summary

Keep open: session-list drags do not supply the chat-reference payload that the input accepts. This team-authored request is scheduled for 1.147.0, which independently rules out a close proposal.

## Change summary

Allow dragging a session from the Agents Window session list into a chat input to attach it as context.

## Best solution

Make session-list drags offer usable session context alongside their existing placement behavior, consistent with chat-tab references. Coordinate the context semantics with the related Attach to Chat request without treating its different interaction as duplicate coverage.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/workbench/contrib/sessions/browser/dnd.ts`, `src/vs/workbench/contrib/sessions/browser/parts/chatCompositeBar.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatReferenceDrop.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatReferenceDrop.test.ts`
- **Validation:** Add focused session-list drag tests demonstrating that a supported session row supplies context accepted by the chat input. Verify attachment creation, existing self-reference and cross-host rejection, drag-end cleanup, and unchanged session placement; manually drag a session row into another supported chat input.
- **Behavior:**

  > Dragging a session row into a supported chat input should add context identifying that session rather than move or open it. Existing session-list organization and pane-placement gestures must remain unchanged. Acceptance should cover a successful attachment and clear rejection of unsupported targets without misleading drop feedback.
- **Trace:**

  > SessionsListDragAndDrop.onDragStart in src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts emits placement payloads only. ChatCompositeBar in src/vs/workbench/contrib/sessions/browser/parts/chatCompositeBar.ts already supplies chat-reference data through fillChatReferenceDragData in browser/dnd.ts. ChatDragAndDrop accepts that separate payload, while resolveChatReferenceDropEntry restricts references to distinct chats belonging to the same agent host. Thus existing tab attachment support does not deliver the requested list gesture. Preserve placement behavior and the backend/client resource distinction. The unresolved boundary is whether session attachment should retain the existing same-host chat-reference scope or represent a broader session link; coordinate with https://github.com/microsoft/vscode/issues/333607 and the related link-pill work at https://github.com/microsoft/vscode/pull/347577.
- **Open decisions:**
  - Should session-list attachment initially support only the existing same-agent-host chat-reference targets, or must it also work across providers and agent hosts as a session link?
