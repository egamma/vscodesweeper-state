# Issue #348474 — [Agents Window][SSH] Remote agent host ignores proxy settings; server download fails silently and registration times out

[https://github.com/microsoft/vscode/issues/348474](https://github.com/microsoft/vscode/issues/348474)

## Summary

Keep open: the current SSH bootstrap does not forward configured HTTP proxies, and its standalone-launch path discards command results while waiting for registration. A longer cold-install deadline exists, but does not address the missing proxy configuration or explain startup failures.

## Change summary

Agents Window SSH connections fail behind required outbound proxies and obscure the underlying server-download failure.

## Best solution

Provide supported remote-bootstrap proxy configuration and actionable startup diagnostics in the core Agents SSH implementation. Decide the supported setting contract before implementation; increasing the registration timeout alone does not resolve an unreachable download endpoint.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/sshRemoteAgentHost.ts`, `src/vs/platform/agentHost/electron-browser/sshRemoteAgentHostServiceImpl.ts`, `src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts`, `src/vs/platform/agentHost/node/sshRemoteAgentHostHelpers.ts`, `src/vs/platform/agentHost/test/node/sshRemoteAgentHostService.test.ts`, `src/vs/platform/agentHost/test/node/sshRemoteAgentHostHelpers.test.ts`
- **Validation:** Extend the SSH service/helper suites to cover configured proxy propagation and startup failures. End-to-end acceptance: with a cached CLI, no remote proxy environment, and downloads reachable only through a configured proxy, connect successfully; with an unavailable proxy, show an actionable download/startup error rather than only a registration timeout. Include a tcsh login-shell host and an unchanged no-proxy scenario.
- **Behavior:**

  > An Agents Window SSH connection must support downloading its server on a host whose outbound HTTPS requires an explicitly configured proxy, without editing shell startup files. A failed download or startup must produce an actionable diagnostic rather than only an unexplained warning or registration timeout. Verify both cached-CLI and first-install paths, preserve ordinary direct connections, and cover the reported tcsh environment.
- **Trace:**

  > SSHConnectionFactory._augmentConfig forwards no HTTP proxy configuration, and ISSHAgentHostConfig has no corresponding bootstrap contract. SSHRemoteAgentHostService._connect builds its dedicated launch through buildAgentHostSpawnCommand; sshExec supplies neither proxy environment nor configuration to the remote CLI. The dedicated launch ignores nonzero exit status and drops resolved output while waitForNewStandaloneEndpoint polls independently. A newly installed CLI gets a longer registration allowance, but the reporter's reused CLI retains the short default. Existing runtime HTTP proxy support elsewhere in the agent host does not supply configuration before this bootstrap completes. Preserve endpoint reuse, detached-process lifetime, and SSH transport proxy behavior; the linked handshake reports concern different stages.
- **Open decisions:**
  - Should remote bootstrap honor remote.SSH.httpProxy/remote.SSH.httpsProxy, introduce a dedicated Agents SSH setting, or use http.proxy, and what precedence and per-host behavior should users expect?
