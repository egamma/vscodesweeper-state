# Issue #278364 — Monaco editor hijacks all input context menus

[https://github.com/microsoft/vscode/issues/278364](https://github.com/microsoft/vscode/issues/278364)

## Summary

Still reproduces on current main: TextInputActionsProvider registers its context menu listener on layoutService.mainContainer (which defaults to document.body), so any <input> or <textarea> on the page gets the VS Code context menu instead of the native one. There is an undocumented workaround (calling e.preventDefault() on the input's own contextmenu event, since line 85 checks e.defaultPrevented), but the default behavior is problematic for workbench embedders.

## Change summary

TextInputActionsProvider hijacks context menus on all input/textarea elements under document.body, not just those belonging to VS Code, breaking embedders who place non-VS Code inputs alongside the workbench.

## Best solution

Scope the context menu listener more tightly — either to known VS Code-owned containers rather than the entire mainContainer, or add a DOM attribute / CSS class opt-out mechanism so embedders can exclude their own inputs. The fix lives in src/vs/workbench/browser/actions/textInputActions.ts, registerListeners method. At minimum, document the e.preventDefault() workaround.
