# Issue #298292 — Chat input area has no independent font size setting

[https://github.com/microsoft/vscode/issues/298292](https://github.com/microsoft/vscode/issues/298292)

## Summary

Current main still hard-codes the chat input editor to 13px, so the requested independent font-size control remains a real accessibility gap. This is the oldest open focused report and should remain open as the canonical issue for several newer matching reports.

## Change summary

Add an independent setting for the font size used while composing messages in the chat input editor.

## Best solution

Provide an independently configurable chat-input font size that updates open composers immediately and scales their line height and layout without changing response text, code blocks, or the rest of the workbench.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/chatInputPart.test.ts`
- **Validation:** Add a browser unit test that constructs the chat input with a non-default input font size, verifies the editor option and one-line layout use it, changes the setting, and verifies the existing editor updates without affecting `chat.fontSize` or `chat.editor.fontSize`; manually confirm large values do not clip text in panel, editor, and compact chat inputs.
- **Behavior:**

  > Users can enlarge or reduce text in the chat prompt editor independently of chat responses, code blocks, editor text, and global workbench zoom. Changing the setting updates already-open chat inputs without requiring a reload. The composer must preserve readable line spacing and avoid clipping at supported sizes across panel, editor, and compact input presentations. Existing typography remains unchanged when the setting is left at its default.
- **Trace:**

  > The prompt editor is constructed in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts with a hard-coded 13px font size and 20px line height. The same class derives its one-line and minimum heights from that fixed line-height constant and already has a configuration-change listener that calls `inputEditor.updateOptions`. Settings are registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts; existing `chat.fontSize` controls message text, while `chat.editor.*` is mapped to code-block result editors through src/vs/workbench/contrib/chat/browser/widget/chatOptions.ts. Preserve those existing scopes and global zoom behavior. Newer matching reports https://github.com/microsoft/vscode/issues/299198 and https://github.com/microsoft/vscode/issues/324962 should consolidate here rather than define separate behavior.
- **Open decisions:**
  - Should the initial public input-typography surface expose only font size as requested, or also font family and weight to match the existing `chat.editor.*` setting family?

## Evidence

- **current source gap:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts:3461-3468 constructs the prompt editor with `options.fontSize = 13` and a fixed 20px line height; no input-font configuration is consulted.
- **existing settings do not cover input:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.fontSize` for messages and `chat.editor.fontSize` for code blocks, while src/vs/workbench/contrib/chat/browser/widget/chatOptions.ts applies the latter only to `resultEditor`.
- **live-update path:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts:1190-1226 already updates editor options for selected configuration changes, but has no branch for input typography.
- **matching demand:** Newer open reports https://github.com/microsoft/vscode/issues/299198 and https://github.com/microsoft/vscode/issues/324962 describe the same independently unconfigurable chat-input font size, making this older open issue the strongest canonical candidate.
- **older report:** The earlier exact report https://github.com/microsoft/vscode/issues/282826 was closed automatically after the backlog-candidate voting window, not because the capability existed or maintainers rejected its design.
- **broader issue is not equivalent:** https://github.com/microsoft/vscode/issues/519 requests configurable workbench typography generally; changing all workbench text would not satisfy this issue's central requirement to resize only the chat input.
