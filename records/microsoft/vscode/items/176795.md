# Issue #176795 — Variables within a configuration snippet defined in package.json file are not being allowed

[https://github.com/microsoft/vscode/issues/176795](https://github.com/microsoft/vscode/issues/176795)

## Summary

The requested literal insertion is already supported through the JSON language service's intentional `^` plain-text marker. The syntax is poorly documented, but the current behavior is by design rather than a debug configuration defect.

## Change summary

Allow debugger configuration snippets to insert a literal `${command:...}` expression without interpreting it as snippet syntax.

## Best solution

Keep the existing plain-text marker behavior and use `"program": "^\"\\${command:debugger.getPaths}\""` in the contributed snippet. Its discoverability could be improved separately in the debugger contribution-point documentation.

- **Proposed comment:**

  > Thanks for the report and the follow-up investigation. `configurationSnippets` use JSON-schema default-snippet syntax, where a leading `^` intentionally marks the remainder as raw snippet text; for this case, use `"program": "^\"\\${command:debugger.getPaths}\""`, which inserts `"program": "${command:debugger.getPaths}"`. This behavior was introduced explicitly in https://github.com/microsoft/vscode-json-languageservice/commit/e573b8b2b7ec077417e1b85e3df82780740fa38f, so closing as designed, though the syntax could be documented more clearly.

## Evidence

- **intentional capability:** https://github.com/microsoft/vscode-json-languageservice/commit/e573b8b2b7ec077417e1b85e3df82780740fa38f explicitly introduced `^` to mark plain text in default snippets and added a completion test for that behavior.
- **current source:** The current vscode-json-languageservice `JSONCompletion.getInsertTextForSnippetValue` still strips a leading `^` and emits the remainder without JSON-stringifying it; VS Code consumes this service for the `defaultSnippets` populated from debugger `configurationSnippets` in `src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts`.
- **confirmed workaround:** The reporter and another user confirmed that `"process": "^\"\\${command:pickRemoteProcess}\""` produces the desired literal `${command:pickRemoteProcess}` value.
