# Issue #335836 — Unnecessary settings for Agents window editor word wrap?

[https://github.com/microsoft/vscode/issues/335836](https://github.com/microsoft/vscode/issues/335836)

## Summary

Keep open for a settings-design decision: the additional Agents word-wrap controls still exist and introduce a separate override layer. This team-authored feedback cannot be declined as a support question, and no qualifying fix or canonical duplicate was established.

## Change summary

Clarify or eliminate the overlap between Agents-scoped editor word-wrap preferences and the dedicated sessions word-wrap settings.

## Best solution

Provide one understandable configuration model for Agents editor wrapping, with explicit inheritance and precedence. Decide whether ordinary Agents-scoped editor settings should own this behavior or whether independently experimentable sessions settings remain necessary.

- **Behavior:**

  > The Agents window exposes both ordinary scoped word-wrap settings and dedicated sessions word-wrap settings, leaving users uncertain which controls their editors. The finished experience should make the effective setting and inheritance understandable for regular, diff, and multi-diff editors. Settings Editor changes and Word Wrap menu actions must agree, persist consistently, and leave normal editor-window preferences unaffected. Treatment of existing sessions-specific values and independent experimental defaults requires a maintainer decision before implementation.
- **Trace:**

  > SessionsDiffEditorLayoutContribution in src/vs/sessions/contrib/editor/browser/diffEditor.sessions.contribution.ts applies sessions-specific wrap options directly to visible editors. DiffEditorOptionsService observes and writes those settings, while toggleSessionsWordWrap in src/vs/sessions/contrib/changes/browser/changesViewActions.ts resolves inherit using editor.wordWrap. Separately, TextDiffEditor.computeConfiguration in src/vs/workbench/browser/parts/editor/textDiffEditor.ts translates ordinary diffEditor.wordWrap into diffWordWrap, and the Sessions configuration service supports scoped configuration layers. The dedicated settings and their independent auto experiments are explicitly requested by https://github.com/microsoft/vscode/issues/335228 and asserted in the existing editor contribution tests. The unresolved boundary is the intended public configuration model, not which helper implements it. Preserve independent regular/diff behavior, multi-diff support, and normal-window preferences; enum expansion in https://github.com/microsoft/vscode/issues/335837 is separate work.
- **Open decisions:**
  - Should ordinary Agents-scoped editor.wordWrap and diffEditor.wordWrap become the authoritative controls, or should dedicated sessions settings remain to support independent experiment defaults?
  - If the dedicated settings remain, should inherit follow the corresponding scoped editor setting, including diffEditor.wordWrap for diffs, or retain the current shared editor.wordWrap inheritance?
  - If the dedicated settings are retired, how should existing explicit sessions values be preserved or migrated so users do not unexpectedly change wrapping behavior?
