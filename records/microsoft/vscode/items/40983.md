# Issue #40983 — Suggestion: Use RegEx classes in "editor.wordSeparators" settings

[https://github.com/microsoft/vscode/issues/40983](https://github.com/microsoft/vscode/issues/40983)

## Summary

A real capability gap remains: current main accepts only a literal list of separator characters. Keep this Backlog request open for design discussion rather than closing it for age or low engagement.

## Change summary

Allow regular-expression character classes in `editor.wordSeparators` instead of requiring every separator character to be listed explicitly.

## Best solution

Define a backward-compatible pattern syntax for word classification, including Unicode and invalid-pattern behavior, then assess its performance across navigation, selection, highlighting, and whole-word search before implementation in the editor word classifier.
