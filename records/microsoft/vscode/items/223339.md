- **Behavior:**

  > The Kusto integration wants to show suggestions after accepting a completion without initially selecting another item. Current explicit invocation selects an item even when automatic-selection settings disable selection. Acceptance should cover the agreed followup behavior while preserving default explicit keyboard invocation and normal navigation and acceptance.
- **Trace:**

  > In src/vs/editor/contrib/suggest/browser/suggestController.ts, TriggerSuggestAction.run reads only the auto argument, and SuggestController.triggerSuggest defaults to manual operation. The onDidSuggest handler applies selectionMode only to automatic sessions. The completion-command special case in _insertSuggestion retriggers automatically, matching the workaround suggested in https://github.com/microsoft/vscode/issues/223339. The older discussion at https://github.com/microsoft/vscode/issues/151336#issuecomment-1305435239 also identifies the auto argument. In src/vs/editor/contrib/suggest/browser/suggestModel.ts, automatic and manual states have distinct behavior, including manual result freezing, so their equivalence should not be assumed. The unresolved boundary is whether this integration needs manual-session behavior with independently disabled initial selection or can use the existing automatic followup contract; default Ctrl+Space behavior must remain unchanged.
- **Open decisions:**

- **Existing programmatic alternative:** TriggerSuggestAction.run accepts { auto: true }, which makes selectionMode applicable. The earlier maintainer explanation explicitly recommends this argument: https://github.com/microsoft/vscode/issues/151336#issuecomment-1305435239.
