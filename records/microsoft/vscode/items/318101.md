# Issue #318101 — Improve Azure OpenAI URL Handling in the BYOK Provider

[https://github.com/microsoft/vscode/issues/318101](https://github.com/microsoft/vscode/issues/318101)

## Summary

The defect is confirmed on current main: Azure BYOK URL resolution and API-key header logic only recognize `openai.azure.com`, missing sovereign-cloud and Foundry host families. An open PR (#318102) already targets this issue — it should be reviewed and landed rather than duplicated.

## Change summary

Azure BYOK URL handling does not recognize sovereign-cloud hosts (`.azure.us`) or Foundry hosts (`cognitiveservices.azure.*`, `services.ai.azure.*`), causing incorrect URL expansion and wrong auth headers for those endpoints.

## Best solution

Review and land the open PR https://github.com/microsoft/vscode/pull/318102 which targets this issue. The fix needs to widen the host-family matching in `resolveAzureUrl()` (extensions/copilot/src/extension/byok/vscode-node/azureProvider.ts, line 41) to cover `*.openai.azure.*`, `*.cognitiveservices.azure.*`, and `*.services.ai.azure.*`, and similarly widen the `api-key` header check in `customEndpointProvider.ts` (line 269) beyond `openai.azure`.
