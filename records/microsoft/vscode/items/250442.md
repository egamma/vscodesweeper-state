# Issue #250442 — MCP sample confirmation should reuse LM confirmation logic

[https://github.com/microsoft/vscode/issues/250442](https://github.com/microsoft/vscode/issues/250442)

## Summary

Still valid: MCP sampling confirmation remains a separate custom dialog flow (IDialogService + session-scoped maps in McpSamplingService) and has not been unified with the extension LM access confirmation logic. Active design discussion among team members about the right granularity (per-model vs. per-extension, during-chat vs. outside-chat) is ongoing.

## Change summary

Unify MCP server sampling confirmation with the existing extension language model access confirmation flow instead of maintaining two separate consent mechanisms.

## Best solution

Evolve the existing LM access confirmation mechanism (used for extensions) to accommodate MCP sampling's stricter requirements (per-model granularity, during-chat vs. outside-chat distinction, cost awareness). This would consolidate the two consent surfaces into one coherent UX, as discussed in the thread. The MCP sampling service (src/vs/workbench/contrib/mcp/common/mcpSamplingService.ts) currently owns its own dialog-based flow that should eventually delegate to a shared confirmation service.
