# Issue #315032 — Subagent fails to resolve custom OAI model although available for main agent

[https://github.com/microsoft/vscode/issues/315032](https://github.com/microsoft/vscode/issues/315032)

## Summary

The failure was independently reproduced on September 1 with another extension-provided BYOK model, and the later report describes the same main-model-versus-subagent discrepancy. Current main contains the BYOK bridge but lacks coverage proving that a bridged model can be selected by a Copilot SDK subagent, so the issue should remain open.

## Change summary

Allow a custom OpenAI-compatible or extension-provided BYOK model that works as the main agent model to be resolved and used by subagents.

## Best solution

Make the Copilot agent-host subagent model resolver consume the same bridged BYOK model catalog and provider configuration as the main session, then add an integration test that launches a subagent pinned to a bridged BYOK model and verifies that model actually handles the request.

Models that cannot run subagents must not be advertised as available for that selection.
- **Trace:**

  > RunSubagentTool in src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts resolves model names through the workbench language-model service and forwards the selected identifier.
