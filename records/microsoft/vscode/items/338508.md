# Issue #338508 — Terminal-completion auto-turn loses custom agents and subagent invocation tool

[https://github.com/microsoft/vscode/issues/338508](https://github.com/microsoft/vscode/issues/338508)

## Summary

Thanks for the unusually detailed diagnostics. I traced two concrete mechanisms in the terminal-completion continuation path that are consistent with the reported tool/agent loss, so this stays open as a real bug rather than a close.

## Change summary

An automatic chat turn triggered by a background terminal command's completion notification can run with a reduced tool set and zero discovered custom agents, stranding a pending subagent handoff.

## Best solution

Make the automatic terminal-completion/steering continuation in RunInTerminalTool refresh (or at least not regress) the currently-available tools and custom agents instead of pinning to the prior turn's `userSelectedTools` snapshot, and stop skipping the `customizationsIndexUpdate` drift block for system-initiated messages when agents/skills have changed since the conversation started.

## Evidence

- **tool set pinned to prior turn:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts ~L3032-3047: `_registerCompletionNotification` builds `sendOptions` from `sessionRef.object.lastRequest` and sets `sendOptions.userSelectedTools = constObservable(lastRequest.userSelectedTools)` before calling `this._chatService.sendRequest(...)` for the input-needed, command-completed, and terminal-exited notifications (each passes `isSystemInitiated: true`). This forwards whatever tool-enablement snapshot the previous real user turn had, rather than the live/current tool set.
- **agents/skills drift skipped for system-initiated turns:** extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx L486-490: `AgentUserMessage.render()` returns `<UserMessage>{this.props.request}</UserMessage>` immediately when `isSystemInitiated` is true, before the `customizationsIndexUpdate` (`<CustomizationsIndexUpdate>`, L535) that would otherwise surface newly-available `<agents>`/`<skills>`/`<instructions>` since the frozen system prompt snapshot. The nearby comment at L242-243 explicitly calls out 'the active mode swapping which subagent entry is listed in `<agents>`' as the scenario this drift mechanism exists for — exactly what the system-initiated path bypasses.
