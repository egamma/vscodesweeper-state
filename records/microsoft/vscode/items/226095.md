# Issue #226095 — Transparent image grid isn't intuitive

[https://github.com/microsoft/vscode/issues/226095](https://github.com/microsoft/vscode/issues/226095)

## Summary

The transparency checkerboard still scales with the image in current source, making background squares look like image content. The earlier fix was reverted for regressions, so this reopened issue remains necessary.

## Change summary

Keep the image preview transparency grid at a consistent visual size while zooming the image.

## Best solution

Make the transparency indicator remain visually independent of image magnification in the built-in media preview, while preserving fit-to-window sizing and correct background alignment through repeated zooming and scrolling.

## Plan brief

- **Likely files:** `extensions/media-preview/media/imagePreview.css`, `extensions/media-preview/media/imagePreview.js`
- **Validation:** In an image-preview webview, open a small transparent PNG and compare checkerboard tile dimensions at 100%, 200%, and 500%: the grid must retain its visual size while the image grows. Repeat zoom in/out and scrolling to verify alignment, then open an image larger than the viewport and select Whole Image to verify the entire image fits. Exercise light and dark themes and an SVG without intrinsic dimensions. The plan should establish an executable browser rendering check for these cases.
- **Behavior:**

  > Zooming a transparent image must magnify its content without magnifying the transparency checkerboard. The checkerboard must remain aligned with the displayed image through repeated zooming and scrolling. Whole Image must continue fitting large images within the viewport, and existing raster and SVG sizing behavior must remain intact. Acceptance includes consistent checkerboard tile dimensions across numeric zoom levels in light and dark themes.
- **Trace:**

  > extensions/media-preview/media/imagePreview.css:34-45 assigns the checkerboard background and its fixed CSS size to the image itself. updateScale in extensions/media-preview/media/imagePreview.js:141-175 applies CSS zoom to that same element, conclusively preserving the reported scaling mechanism. The script also handles scale-to-fit, intrinsic-size probing, SVG fallback sizing, scroll anchoring, and restored zoom state; these are compatibility boundaries, not additional feature work. https://github.com/microsoft/vscode/pull/226505 attempted a separate background container but was reverted after the fit-to-window and alignment regressions in https://github.com/microsoft/vscode/issues/229019 and https://github.com/microsoft/vscode/issues/228263. ## Evidence

- **Current source confirms the reported trigger:** extensions/media-preview/media/imagePreview.css:34-45 places the 16px transparency background directly on the img element. extensions/media-preview/media/imagePreview.js:141-175 implements numeric zoom by assigning image.style.zoom = scale without compensating the background size, so zooming magnifies the checkerboard along with the image.
- **Merged fix does not establish completion:** https://github.com/microsoft/vscode/pull/226505 moved the checkerboard into a separate div, but the maintainer explicitly announced its revert at https://github.com/microsoft/vscode/pull/226505#issuecomment-2361469594.
