# Issue #144115 — runTest is not honoring the launchArg '--new-window'

[https://github.com/microsoft/vscode/issues/144115](https://github.com/microsoft/vscode/issues/144115)

## Summary

Keep open pending reproduction of the sequential test launches. Current startup and extension-host code explicitly handle empty test windows, and window/profile handling has evolved since the report; the supplied sequence is sufficient to retest, but no fixing commit or canonical duplicate was established.

## Change summary

A second runTests invocation with --new-window and no workspace argument restores the folder used by the preceding test run.

## Best solution

Ensure sequential extension test launches honor the requested workspace: a launch without a workspace argument and with --new-window should start empty, while an explicit folder argument should open that folder. First reproduce using the same isolated test user-data directory and distinguish startup restoration from reuse of an existing extension-development window.
