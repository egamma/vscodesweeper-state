## Evidence

- **detail flow:** openMigrationItem -> openCustomization -> openMigrationCustomization (aiCustomizationManagementEditor.ts:2120) routes MCP items to showEmbeddedMcpDetail, which immediately calls `void this.refreshCustomizationMigrationInfo()` (line 5022) right after setting viewMode='mcpDetail' — a candidate race with the dashboard re-render.
- **reactive refresh:** An autorun at aiCustomizationManagementEditor.ts:1126-1132 re-reads `mcpService.servers`/`readDefinitions()` and calls refreshCustomizationMigrationInfoFromMcpChange() on any change, which could re-render the dashboard/detail state while the MCP detail editor is focused.
- **editor construction:** The definition viewer is a full CodeEditorWidget with `{ isSimpleWidget: false }` (embeddedMcpServerDetail.ts:647-670), same as the main prompt/skill editor, so this alone doesn't explain the MCP-specific difference — further tracing needed.
- **working comparator:** The Prompt-to-Skills path uses showEmbeddedEditor/viewMode='editor' (aiCustomizationManagementEditor.ts:3987) and does not call refreshCustomizationMigrationInfo() on open, unlike the MCP path — a plausible but unconfirmed differentiator.
