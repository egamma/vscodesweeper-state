# Issue #275212 — Thinking section expand from 5 lines to infinite lines does not work

[https://github.com/microsoft/vscode/issues/275212](https://github.com/microsoft/vscode/issues/275212)

## Summary

The compact live-thinking state remains unresolved on current main: fixed scrolling still exposes up to 200px, while the alternatives show either zero lines or the full live content. Keep this under discussion until the intended default and interaction are chosen.

## Change summary

Provide a compact one- or two-line live preview of the current thinking text that can still expand to the full content.

## Best solution

Settle on a compact live-preview behavior that keeps the latest reasoning snippet visible without letting secondary progress content dominate the response, while retaining deliberate full expansion. The chat-response owners should decide whether this replaces the fixed-scrolling default or becomes its collapsed state.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatThinkingContent.css`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatThinkingContentPart.test.ts`
- **Validation:** Extend the ChatThinkingContentPart tests and component fixture coverage to verify the chosen compact height while streaming, full expansion after activation, and unchanged collapsed/completed behavior.
- **Behavior:**

  > While an agent is thinking, the response should present a compact live preview of the latest reasoning text instead of occupying a five-line-or-larger block. The user must be able to expand that preview to the complete thinking content, and the compact state must continue following the newest streamed content. Completed and explicitly collapsed thinking must retain the behavior selected by the existing presentation model.
- **Trace:**

  > The active default is chat.agent.thinkingStyle=fixedScrolling in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. ChatThinkingContentPart caps its streaming viewport with THINKING_SCROLL_MAX_HEIGHT=200 and auto-scrolls it to the latest content; chatThinkingContent.css also hides the header while streaming, preventing a compact/full toggle then. Collapsed mode starts with no rendered body, while CollapsedPreview starts fully expanded and collapses only after thinking completes, so neither supplies the requested compact live preview. Keep the change within chat-response thinking presentation: do not alter reasoning content, provider behavior, or completed-response semantics unrelated to the selected design.
- **Open decisions:**
  - Should the fixed-scrolling default become a one-line or two-line live preview?
  - While streaming, should activating the thinking header toggle directly between the compact preview and the full content?
  - Should the compact live preview replace fixedScrolling globally, or be represented as a distinct presentation mode while fixedScrolling retains its current behavior?
