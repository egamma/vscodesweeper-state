# Issue #341943 — automations: mobile workspace picker sheet does not refresh when cloud eligibility resolves

[https://github.com/microsoft/vscode/issues/341943](https://github.com/microsoft/vscode/issues/341943)

## Summary

The report matches current main. The mobile sheet gets a one-time snapshot from `_buildMobileItems()`, and nothing refreshes it afterwards. The desktop `updateItems` refresh is gated on `actionWidgetService.isVisible`.

## Change summary

The mobile workspace picker sheet in the automations dialog does not refresh its rows when cloud eligibility resolves after the sheet opens.

## Best solution

Await pending cloud targets for local checkouts before snapshotting, or let the open mobile sheet update its rows reactively from the eligibility autorun.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/automations/browser/automationDialog.ts`, `src/vs/sessions/contrib/chat/browser/mobile/mobileWorkspacePickerSheet.ts`
- **Validation:** Open the mobile picker before eligibility resolves, then resolve it and verify the row becomes selectable without reopening the sheet.
- **Behavior:**

  > If cloud eligibility resolves while the mobile workspace picker sheet is open, the affected row becomes selectable without closing and reopening the sheet. The desktop picker behaves as it does today.
- **Trace:**

  > `showReadyMobilePicker` awaits `waitForWorkspaceTargets` and then snapshots `_buildMobileItems()`. The sheet API takes a plain array, so it cannot react to later changes. The eligibility autorun in `setCloudConfiguration` only refreshes the desktop action widget. Desktop behavior and the existing picker dispatch must stay unchanged.

## Evidence

- **snapshot:** `showReadyMobilePicker` in src/vs/sessions/contrib/automations/browser/automationDialog.ts (~L2744) passes `this._buildMobileItems()` once to `showMobileWorkspacePickerSheet`.
- **desktop-only refresh:** The eligibility autorun (~L2426-2437) only calls `updateItems` when `actionWidgetService.isVisible` and the trigger has `aria-expanded=true`, so the mobile sheet is never refreshed.
- **partial wait:** `waitForWorkspaceTargets` (~L2449) waits only for items where `isGitWorkspace(folderUri)` is true, and it is not clear this covers a local checkout with a pending cloud target. I did not run the picker, so the exact interaction is unconfirmed.
