## Summary

Same root cause as the older, already-flagged issue #320626: NES network-fetch failures (ChatFetchResponseType.NetworkError) get rethrown from NextEditProvider and reported via onUnexpectedError instead of being treated as ordinary connectivity failures. Proposing this be consolidated as a duplicate of the earlier, better-tracked report.

## Change summary

NES (next-edit-suggestions) network failures such as ERR_NAME_NOT_RESOLVED are surfacing as 'unhandled error' telemetry instead of being handled as expected connectivity failures.

## Best solution

Fix this once on the canonical issue https://github.com/microsoft/vscode/issues/320626 (already carries the *fix label): in extensions/copilot/src/extension/inlineEdits/node/nextEditProvider.ts (~line 494) NoNextEditReason.FetchFailure/Unexpected are rethrown as raw errors, which extensions/copilot/src/extension/inlineEdits/vscode-node/inlineCompletionProvider.ts then feeds into raceAndAll(..., onUnexpectedError) (extensions/copilot/src/extension/inlineEdits/vscode-node/raceAndAll.ts) — network-caused ChatFetchResponseType.NetworkError/Failed/Unknown results should not reach onUnexpectedError, which per its own doc comment in util/vs/base/common/errors.ts is meant only for genuine product bugs, not network/user-input issues.
