[https://github.com/microsoft/vscode/issues/349059](https://github.com/microsoft/vscode/issues/349059)

## Summary

Move this recovery-workflow request to microsoft/vscode-remote-release, where Dev Containers is maintained. The report describes preserved volume contents but no convenient way to resume after a failed rebuild; it should not be closed as third-party extension behavior.

Allow reopening an existing development volume after a failed container rebuild without cloning again or copying its contents to the host.

Have the Dev Containers owners assess recovery directly from an existing volume, preserving uncommitted contents and allowing the broken configuration to be corrected before rebuilding.
