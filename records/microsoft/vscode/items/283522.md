Keep open as an upstream KDE/Wayland menu integration issue. Electron has an open fix candidate, but it has not merged; the native-title-bar workaround does not resolve all reported configurations.

## Change summary

Restore KDE global menu integration that stopped working after upgrading VS Code from 1.106.3 to 1.107.0.

## Evidence

- **Confirmed regression:** https://github.com/microsoft/vscode/issues/283522#issuecomment-3659404241 reports failure on openSUSE Plasma 6.5.4 under Wayland after upgrading to 1.107.0, with functionality restored by downgrading to 1.106.3. Other commenters independently report the same failure.
- **Workarounds are conditional:** https://github.com/microsoft/vscode/issues/283522#issuecomment-3669309409 reports that code --ozone-platform=x11 works. Setting window.titleBarStyle to native helped one commenter, but https://github.com/microsoft/vscode/issues/283522#issuecomment-5594026491 explicitly reports that it does not work on Kubuntu 26.04 with Wayland; October comments also report continued failure.
- **Current source boundary:** src/vs/platform/menubar/electron-main/menubar.ts:375-399 installs the application menu through Electron's Menu.setApplicationMenu(). src/vs/platform/window/common/window.ts:230-262 separately gates native menus by title-bar and menu style. This source inspection identifies the Electron integration boundary, but does not constitute a runtime reproduction or prove resolution.
- **Upstream issue and pending fix:** https://github.com/electron/electron/issues/34335 remains open and reports missing global menus in Wayland-only sessions. https://github.com/electron/electron/pull/54629 is OPEN with mergedAt null; its description identifies registration using a Wayland widget ID as an X window ID and proposes associating the exported menu with the Wayland toplevel instead. This is a concrete upstream implementation candidate, not a landed fix.
