# Issue #116827 — [FR] Settings to make find-and-replace work like Notepad++

[https://github.com/microsoft/vscode/issues/116827](https://github.com/microsoft/vscode/issues/116827)

## Summary

Keep this accepted, 26-upvote request open: existing settings cover automatic selection scope on opening and disabling search-term seeding, but not the full selection-preserving workflow or exact multiline selection boundaries. A maintainer explicitly consolidated an older selection-update request here; no verified older open canonical owns the complete request.

## Change summary

Support a find-and-replace configuration that preserves the editor selection, follows selection changes, confines replacements to exact selection boundaries, and retains the search term.

## Best solution

Design an opt-in selection-preserving workflow in the editor find controller, widget, and model that fulfills the five requested behaviors together. Reuse the existing automatic-scope and search-seeding settings, preserving current behavior for users who have not opted in.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/find/browser/findController.ts`, `src/vs/editor/contrib/find/browser/findWidget.ts`, `src/vs/editor/contrib/find/browser/findModel.ts`, `src/vs/editor/contrib/find/test/browser/findController.test.ts`, `src/vs/editor/contrib/find/test/browser/findModel.test.ts`
- **Validation:** Add targeted FindController and FindModel tests for automatic scope on opening, unchanged search text, exact partial-multiline replacement boundaries, selection preservation, and selection-driven scope refresh. Run those suites through scripts/test.sh with targeted selectors in an implementation workspace; manually exercise Ctrl+H, change the selected region with the widget open, and repeat Replace All to verify the integrated workflow and unchanged default behavior.
- **Behavior:**

  > An opt-in configuration should deliver all five requested behaviors together: opening Ctrl+H uses the current selection as scope without replacing the existing search term, selection changes refresh that scope, and replacements affect only the exact selected characters. Find-and-replace actions must not replace the user's selected region with a found match. Acceptance includes selections starting and ending partway through different lines, repeated replacements in different selected regions, and unchanged behavior outside the opt-in configuration.
- **Trace:**

  > EditorFind in src/vs/editor/common/config/editorOptions.ts already exposes automatic selection scope, search-term seeding, and cursor movement while typing. FindController._start in src/vs/editor/contrib/find/browser/findController.ts updates scope on opening; FindWidget in src/vs/editor/contrib/find/browser/findWidget.ts refreshes scope on input focus but its editor-selection listener only updates the toggle button. FindModelBoundToEditorModel.research in src/vs/editor/contrib/find/browser/findModel.ts expands multiline scopes to whole lines, while _setCurrentFindMatch replaces the editor selection with a match. These source paths establish the remaining capability gaps without executing the editor. Keep existing default find navigation, regex behavior, and users' current settings compatible. The maintainer consolidated the older scope-update request here at https://github.com/microsoft/vscode/issues/95356#issuecomment-1349936066; the newer https://github.com/microsoft/vscode/issues/306294 is related rather than a canonical replacement. The unresolved product boundary is how an active match and single-match replacement should behave when the user's scope selection remains intact.
- **Open decisions:**
  - In the opt-in selection-preserving workflow, how should Find Next/Previous indicate the active match, and should Replace act on that independently tracked match while leaving the scope selection intact?
