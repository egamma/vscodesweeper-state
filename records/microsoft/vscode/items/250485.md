# Issue #250485 — Bug: removing suggested attachment with keyboard doesn't work

[https://github.com/microsoft/vscode/issues/250485](https://github.com/microsoft/vscode/issues/250485)

## Summary

Keep open as accepted chat-input polish: keyboard removal works with Delete or Backspace, but current main exposes that shortcut to screen readers and accessibility help rather than visibly in the attachment tooltip. The team-authored issue and existing polish classification also rule out second-guessing it with an as-designed close.

## Change summary

Make the keyboard command for removing a chat attachment discoverable to users who initially added the suggested attachment with Enter or Space.

## Best solution

Expose the Delete/Backspace removal shortcut in the hover or tooltip for deletable chat attachments while preserving Enter and Space for opening or activating the attached resource.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts`
- **Validation:** With a deletable file attachment focused in chat, verify its visible hover identifies Delete and Backspace as removal commands; verify Delete and Backspace remove it while Enter or Space retains the existing open/activation behavior, and confirm the ARIA label and Chat Accessibility Help remain accurate.
- **Behavior:**

  > A keyboard user who encounters an attached chat context item can discover from its visible hover how to remove it. Delete and Backspace remove a deletable attachment, while Enter and Space retain their existing open or activation behavior. Attachments that cannot be deleted must not advertise the removal shortcut, and existing screen-reader guidance must remain accurate.
- **Trace:**

  > AbstractChatAttachmentWidget in src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts creates the attachment element and clear button. appendDeletionHint currently adds '(Delete)' only to the ARIA label, attachClearButton handles both Delete and Backspace, and the clear button title only says 'Remove from context'; FileAttachmentWidget otherwise delegates its hover title to ResourceLabels. Chat Accessibility Help already documents both removal keys in src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts. Preserve resource opening on Enter or Space and limit the scope to discoverability for attachments whose supportsDeletion path creates a clear button. The related hover-styling discussion at https://github.com/microsoft/vscode/issues/250490 is adjacent but does not own this keyboard-discovery behavior.
- **Open decisions:**
  - Should the visible Delete/Backspace hint appear in the hover for the whole attachment pill, only in the remove button tooltip, or in both surfaces?
