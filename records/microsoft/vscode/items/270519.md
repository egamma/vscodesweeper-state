- **Current source confirms flattening:** In src/vs/workbench/contrib/search/browser/searchActionsCopy.ts, copyAllCommand passes only folder matches and the label service to allFolderMatchesToString, without consulting searchView.isTreeLayoutViewVisible. folderMatchToString recursively joins child text without folder headers or depth indentation, while fileMatchToString always emits a URI label and match previews indented by two spaces. - **Tree layout is presentation state:** src/vs/workbench/contrib/search/browser/searchView.ts uses isTreeLayoutViewVisible to choose between folderMatch.matches() and folderMatch.allDownstreamFileMatches(); searchResultsView.ts also uses it when rendering resource labels. The clipboard serialization does not use this existing layout state.
