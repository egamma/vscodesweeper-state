# Issue #335132 — [Chat] Avoid misleading repeated repository-root traces in multi-root workspaces

[https://github.com/microsoft/vscode/issues/335132](https://github.com/microsoft/vscode/issues/335132)

## Summary

Traced and confirmed in current main: `findParentRepoFolders` in `extensions/copilot/src/platform/promptFiles/vscode-node/agentInstructionsLocator.ts` always logs "No repository root found" when the walk-up loop breaks, even when it broke because `seen.has(parent)` was true (an already-processed ancestor), which is misleading and noisy in large multi-root workspaces.

## Change summary

In multi-root workspaces with `chat.useCustomizationsInParentRepositories` enabled, a misleading "No repository root found" trace is logged for every sibling folder once an ancestor repo root has already been discovered, even though the root is retained and customizations remain discoverable.

## Best solution

Only log the "No repository root found" message when the walk genuinely reaches the filesystem/user-home boundary without finding a root; skip (or use a distinct message for) the case where the loop stops because `seen.has(parent)` is true, in `findParentRepoFolders` (agentInstructionsLocator.ts lines ~209-218).
