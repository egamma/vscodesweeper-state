# Issue #16998 — Add SmartIndent capability

[https://github.com/microsoft/vscode/issues/16998](https://github.com/microsoft/vscode/issues/16998)

## Summary

Keep open: existing indentation rules and formatting providers do not provide language-aware caret placement on empty lines without inserting whitespace. The older virtual-space request is related infrastructure, not a verified duplicate of this extensibility request.

## Change summary

Allow language services to determine the caret's indentation on empty lines reached by mouse or keyboard, without inserting whitespace.

## Best solution

Design language-aware empty-line caret placement together with virtual-space support, retaining this issue for the language-service contract. Settle whether the initial contract covers only empty-line navigation or also Enter and comment-continuation behavior.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/cursor/cursorMoveCommands.ts`, `src/vs/editor/common/cursor/cursorMoveOperations.ts`, `src/vs/editor/common/model/textModel.ts`
- **Validation:** The plan should establish automated cursor and extension-contract checks: in an indented block with a truly empty line, clicking to the right of the expected indent and navigating vertically from a nonzero column place the caret at the language-provided indent while document text and dirty state remain unchanged; clicking before the expected indent preserves the requested line-start behavior.
- **Behavior:**

  > A language extension can determine the expected indentation when the caret reaches an empty line. Clicking beyond that indentation or navigating vertically from a nonzero column places the caret at the expected visual column without inserting whitespace. Clicking before the expected indentation retains the reporter's requested line-start behavior. Acceptance must cover mouse and keyboard navigation and verify that navigation alone does not edit the document.
- **Trace:**

  > LanguageConfiguration in src/vscode-dts/vscode.d.ts supplies indentationRules and onEnterRules, while OnTypeFormattingEditProvider supplies text edits after typing; neither expresses the requested navigation-time virtual caret position. CursorMoveCommands.moveTo validates positions through TextModel._validatePosition, which clamps them to existing line content; MoveOperations.vertical preserves a desired visible column but does not ask a language indentation provider. This establishes an editor-model and extension-contract boundary, not a small indentation-rule fix. https://github.com/microsoft/vscode/issues/13960 tracks related virtual-space infrastructure but does not replace this language-aware contract. Preserve existing formatting and ordinary navigation behavior outside the agreed feature scope. The unresolved product boundary is whether the first contract handles only empty-line navigation or also the Enter and comment-continuation scenarios discussed at https://github.com/microsoft/vscode/issues/16998.
- **Open decisions:**
  - Should the initial extension contract cover only indentation-aware empty-line navigation, or also Enter handling and comment-continuation behavior?
  - Should language-aware virtual indentation be available independently of general virtual space, or only when a broader virtual-space mode is enabled?
