# Issue #187716 — "unable to get local issuer certificate" attempting to install extensions into dev container by code-server on dev container build

[https://github.com/microsoft/vscode/issues/187716](https://github.com/microsoft/vscode/issues/187716)

## Summary

This remains a source-reproducible Dev Containers/remote-server certificate bug and should be moved to the VS Code team's microsoft/vscode-remote-release tracker. An older open issue there reports the same CLI-versus-GUI extension-installation failure, so the transferred report can be consolidated without losing its Dev Container build evidence.

## Change summary

Extension installation during Dev Container startup fails behind a TLS-inspecting corporate proxy because the remote code-server command does not trust the configured corporate root CA.

## Best solution

Move this issue to microsoft/vscode-remote-release and consolidate it with https://github.com/microsoft/vscode-remote-release/issues/2393. The remote server's startup extension-installation path should use the applicable host or remote trusted certificates consistently with interactive installation.

## Evidence

- **current source path:** src/vs/server/node/remoteExtensionsScanner.ts invokes ExtensionManagementCLI.installExtensions for --install-extension during server startup; the gallery requests flow through the remote RequestService registered by src/vs/server/node/serverServices.ts.
- **certificate gap:** src/vs/platform/request/node/requestService.ts builds requests with getProxyAgent, while src/vs/platform/request/node/proxy.ts configures proxy routing and rejectUnauthorized but does not add host or remote system CAs. RequestService.loadCertificates exists, but the startup gallery-request path does not consume it.
- **host-proxy boundary:** src/vs/server/node/extensionHostConnection.ts forwards --use-host-proxy to the extension host, and src/vs/workbench/api/node/proxyResolver.ts loads additional certificates there; that does not cover extension downloads performed by code-server before the extension host starts.
- **confirmed workaround:** The reporter and multiple commenters confirmed that NODE_EXTRA_CA_CERTS resolves the failure, matching the current source path's reliance on Node's certificate environment.
- **owner tracker:** https://github.com/microsoft/vscode-remote-release/issues/2393 is open, predates this report, and describes the same observable symptom: command-line remote extension installation fails with "unable to get local issuer certificate" while GUI installation succeeds behind a corporate proxy.
- **related core issue:** https://github.com/microsoft/vscode/issues/34385 is older and open but broadly tracks local XHR/proxy failures rather than this Dev Container remote-server startup path, so it does not meet the stronger same-symptom duplicate bar for this re-review.
