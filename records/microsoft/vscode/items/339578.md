# Issue #339578 — Azure DevOps MCP Server disconnects and fails often

[https://github.com/microsoft/vscode/issues/339578](https://github.com/microsoft/vscode/issues/339578)

## Summary

Fresh, well-documented report (not yet triaged beyond the auto-applied 'new release' label) of the Azure DevOps remote MCP server losing its connection with 401s; the attached log shows a real failure in the OAuth token-refresh path, not just a flaky network blip, so this needs an MCP/auth-team look rather than a close.

## Change summary

A remote HTTP MCP server (Azure DevOps) using OAuth repeatedly disconnects with 401 errors during agent sessions, sometimes requiring a full account sign-out/sign-in to recover.

## Best solution

An MCP/authentication owner should look at why a failed silent token refresh (the attached log shows 'User did not consent to login' / MSAL 'user_canceled' right before the 401 and disconnect) leaves the connection in a dead state that users can't recover from except by removing and re-adding their account — either surface an explicit re-auth prompt at that point or make the reconnect path retry authentication instead of just erroring out.

## Evidence

- **attached log:** azure-devops-mcp-server-log.txt shows: 'Error getting token from server metadata: Error: User did not consent to login.' followed by 'Scopes changed from [...] to undefined, updating', then 'ClientAuthError: user_canceled', then 'Connection state: Error 401 status sending message to https://mcp.dev.azure.com/<org>'. The server then restarts cleanly, re-discovering 43 tools, suggesting the failure is specifically in token refresh/consent, not transport.
- **code path:** src/vs/workbench/api/common/extHostMcp.ts `_addAuthHeader` (around line 754) calls `$getTokenFromServerMetadata`/`$getTokenForProviderId` with `errorOnUserInteraction`; src/vs/workbench/api/browser/mainThreadMcp.ts (`_getSessionForProvider`, ~line 404) requests sessions with `silent: errorOnUserInteraction`. When silent renewal fails for a reason other than `UserInteractionRequiredError` (e.g. the MSAL 'user_canceled'/consent errors seen in the log), the code only logs a warning and proceeds without a token, producing the 401 rather than surfacing a clear re-auth path.
- **related but distinct:** https://github.com/microsoft/vscode/issues/311784 (cannot start the ADO MCP server) and https://github.com/microsoft/vscode/issues/321249 (OAuth scope/resource conflict with Entra) are adjacent but describe different symptoms — one is startup failure, the other a specific AADSTS error — neither is a verified duplicate of this mid-session disconnect/401 report.
