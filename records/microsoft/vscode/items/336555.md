## Evidence

- **Confirmed version-dependent failure:** https://github.com/microsoft/vscode/issues/336555#issuecomment-5732363464 reports a controlled comparison using the same machine, MCP configuration, GitLab 18.11.11-ee endpoint, and stored OAuth credentials: bundled @github/copilot 1.0.84-4 and 1.0.84-9 fail, while standalone 1.0.85 and 1.0.86 succeed. This independently confirms the symptom with a Copilot Enterprise subscription, beyond the original Codex subscription report.
- **Likely upstream trigger:** The same comment provides a bare HTTP 401 response without WWW-Authenticate and runtime logs showing OAuthChallenge with an empty header. It also reports successful refresh of an expired token with 1.0.86. Fallback discovery of /.well-known/oauth-protected-resource is the commenter's hypothesis, not a verified upstream source change.
- **Current runtime adoption path:** Current package.json and package-lock.json use @github/copilot-sdk 1.0.19-preview.0 with matching platform runtime packages. src/vs/platform/agentHost/node/copilot/copilotRuntimePaths.ts resolves copilot-runtime from those packages; copilotAgent.ts passes the selected executable to RuntimeConnection.forStdio when constructing CopilotClient. The historical CLI version pin is therefore not a reliable description of current main.
- **Credential ownership has changed:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts explicitly sets mcpOAuthTokenStorage to 'in-memory' and installs onMcpAuthRequest. copilotAgentSession.ts handles that callback in _handleMcpAuthRequest and constructs resource metadata in _protectedResourceFromMcpAuthRequest. Standalone CLI keychain success does not establish that this current VS Code callback path succeeds against the reported GitLab challenge.
- **Fix provenance remains unverified:** The checkout has shallow history, and the available history search found no commit referencing this issue or the GitLab OAuth failure. No referencing PR was returned by the PR search. Neither the changed dependency packaging nor a newer version establishes the specific behavioral fix; the upstream leads https://github.com/github/copilot-cli/issues/4662 and https://github.com/github/copilot-cli/issues/4203 could not be read through the available authenticated or public access.
- **Canonical search:** https://github.com/microsoft/vscode/issues/336498 is closed and cannot serve as a duplicate canonical. The older open https://github.com/microsoft/vscode/issues/326116 concerns Claude SDK authentication support, not the demonstrated Copilot runtime version regression; https://github.com/microsoft/vscode/issues/335457 reports GitLab SSO failure without identifying MCP or this challenge behavior. Neither establishes the same observable symptom required for a duplicate close of this re-reviewed item.
