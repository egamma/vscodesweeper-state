# Issue #184142 — Custom editors should not allow to make edits after extension host restart

[https://github.com/microsoft/vscode/issues/184142](https://github.com/microsoft/vscode/issues/184142)

## Summary

Still reproducible on main: custom editors have no mechanism to turn readonly or notify the user after an extension host restart actually proceeds. The only guard is a veto on `onWillStop`, which doesn't cover crashes or forced restarts.

## Change summary

Custom editors remain editable after an extension host restart but lose their extension connection, leading to silent data loss.

## Best solution

After an extension host restart or crash, custom editors should detect the disconnection and either become readonly or show an overlay explaining what happened. The fix likely lives in `src/vs/workbench/contrib/customEditor/common/customTextEditorModel.ts` and the non-text custom editor model, listening for `onDidChangeExtensionsStatus` or a post-restart signal.
