[https://github.com/microsoft/vscode/issues/336090](https://github.com/microsoft/vscode/issues/336090)

## Summary

Plausible, specific report with clear repro steps and a second user confirming it in the comments; I traced the context-usage widget's visibility logic in chatContextUsageWidget.ts (visibility requires both `response.usage` and a resolvable `languageModelsService.lookupLanguageModel(modelId)` context window) but could not conclusively pin down why that resolution fails specifically for signed-out BYOK sessions in the Agents window, so this needs a maintainer/owner to trace the BYOK model-metadata or usage-reporting path further.

## Change summary

The context-window usage ring in the Agents window composer never renders for BYOK models when the user is signed out of GitHub, even though it works for first-party models.

## Best solution

An owner of the Agents window / BYOK model plumbing should trace why `ChatContextUsageWidget.updateFromResponse` (src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts) never gets both a `usage` payload and a resolvable context window for signed-out BYOK sessions — likely either the BYOK model's `maxInputTokens`/`maxOutputTokens` metadata isn't registered yet, or the agent's usage-update protocol event isn't wired for the signed-out/native BYOK code path (see src/vs/platform/agentHost/node/copilot/copilotAgent.ts's `_byokModels` handling).
