# Issue #323420 — Slash command completions should indicate the source of each command

[https://github.com/microsoft/vscode/issues/323420](https://github.com/microsoft/vscode/issues/323420)

## Summary

Keep open: current Agent Host completions display command descriptions, but do not consistently identify command provenance. This team-authored request still has a concrete gap; the related namespaced-skill report covers truncation, not source attribution.

## Change summary

Identify the source of slash commands in Copilot Agent Host completion suggestions.

## Best solution

Provide a consistent, readable source indicator alongside command names and descriptions, using authoritative provenance where available. Agree on the displayed source categories and unknown-source behavior before extending the host-to-workbench completion contract.

- **Behavior:**

  > Typing / in a Copilot Agent Host session should let users distinguish native commands from contributed commands without interpreting command descriptions or guessing from names. Source information should remain distinguishable from the command's purpose, including when names overlap. Command filtering, insertion and execution should retain their existing behavior. Completions from hosts that omit provenance must remain usable without falsely attributing their source.
- **Trace:**

  > AgentHostSessionHandler.provideChatInputCompletions requests host completions and maps their attachments through _toChatInputCompletionItem. AgentHostInputCompletions._buildItem then presents command and skill names with descriptions, but no explicit provenance. CopilotSlashCommandCompletionProvider has runtime command kinds, while AgentHostSkillCompletionProvider has customization container information; only a skill flag and some plugin-qualified names survive as partial distinctions. The metadata interfaces in common/meta/vscode/agentCompletionAttachmentMeta.ts do not expose a general source contract. The unresolved boundary is which authoritative origin information is available for each contribution category and what users should see when it is absent. Preserve opaque host identities, compatibility with conforming hosts lacking optional metadata, and existing command dispatch and customization enablement. https://github.com/microsoft/vscode/issues/312129 concerns name truncation and is related UI context, not a duplicate.
- **Open decisions:**
  - Should the indicator show broad categories such as Built-in, Plugin, MCP and Custom, concrete contributor names, or both?
  - When a host supplies no authoritative provenance, should the completion omit the indicator or explicitly show an unknown source?
