# Issue #111025 — [html] HTML line wrapping on paste occurs before auto-indenting

[https://github.com/microsoft/vscode/issues/111025](https://github.com/microsoft/vscode/issues/111025)

## Summary

The defect remains source-reproducible on current main: HTML range formatting wraps the isolated pasted text before applying its surrounding indentation, so a later document format can wrap it again. Keep this open for an explicit range-formatting behavior decision and regression coverage.

## Change summary

HTML format-on-paste wraps long text without accounting for its nesting indentation, producing output that changes again on the next full-document format.

## Best solution

Make HTML range formatting stable in nested content: formatting the pasted range followed by formatting the full document should not reflow the text again, while full-document `html.format.wrapLineLength` behavior remains unchanged.

## Plan brief

- **Likely files:** `extensions/html-language-features/server/src/htmlServer.ts`, `extensions/html-language-features/server/src/modes/htmlMode.ts`, `extensions/html-language-features/server/src/modes/formatting.ts`, `extensions/html-language-features/server/src/test/formatting.test.ts`
- **Validation:** Extend extensions/html-language-features/server/src/test/formatting.test.ts with a nested HTML range using `wrapLineLength`, assert that range formatting followed by full-document formatting is idempotent, and run `npm test --prefix extensions/html-language-features/server`.
- **Behavior:**

  > With `editor.formatOnPaste` enabled and a nonzero `html.format.wrapLineLength`, pasting long text inside nested HTML must not produce wrapping based on column zero and then indent those lines afterward. Formatting the complete document immediately afterward must leave the pasted text unchanged. Full-document line wrapping must continue honoring `html.format.wrapLineLength`.
- **Trace:**

  > The client range provider in extensions/html-language-features/client/src/htmlClient.ts sends pasted and manually selected ranges through DocumentRangeFormattingRequest. In extensions/html-language-features/server/src/htmlServer.ts, both range and document requests enter `onFormat`; the range is forwarded through modes/formatting.ts to `getHTMLMode().format` in modes/htmlMode.ts with the same HTML format settings. The language service formats only the selected substring using `wrapLineLength`, then prefixes each resulting line with the computed surrounding indent, reproducing the ordering diagnosed in https://github.com/microsoft/vscode/issues/111025#issuecomment-732018856. The boundary is HTML range formatting: document formatting and unrelated embedded CSS/JavaScript formatting must remain unchanged. The uncertainty starts at the public behavior of manual Format Selection because the provider receives the same range-formatting request as format-on-paste and no request-origin signal.
- **Open decisions:**
  - Should `html.format.wrapLineLength` be disabled for every HTML range-formatting request, including manual Format Selection, or should range formatting retain wrapping while accounting for the range's existing indentation?
