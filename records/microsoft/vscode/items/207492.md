# Issue #207492 — Extension-contributable top-level menus

[https://github.com/microsoft/vscode/issues/207492](https://github.com/microsoft/vscode/issues/207492)

## Summary

A real extension-API gap remains on current main: extensions can populate selected menu locations but cannot contribute a new top-level menubar entry. The existing under-discussion, titlebar, and menus routing is appropriate while maintainers decide whether extension-owned top-level menus fit the workbench UX.

## Change summary

Allow extensions to contribute a top-level menu alongside File, Edit, and Go for prominently exposing important commands.

## Best solution

If extension-owned menubar surface is accepted, provide a constrained contribution point with defined ordering, collision, visibility, mnemonic, and keyboard-accessibility behavior so extensions cannot make the primary menu unpredictable.
