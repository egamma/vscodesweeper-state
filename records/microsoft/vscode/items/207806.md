# Issue #207806 — settings files.exclude does not recognize .vscode folder

[https://github.com/microsoft/vscode/issues/207806](https://github.com/microsoft/vscode/issues/207806)

## Summary

Verified duplicate: the open canonical issue tracks the same request to keep specific paths visible when a broader `files.exclude` pattern matches them.

## Change summary

Allow `.vscode` to remain visible when `*.*` excludes it and the more specific `.vscode` entry is set to `false`.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/869 and design negated or include-exception semantics for `files.exclude`; that broader work fully covers the `.vscode` case reported here.

## Evidence

- **same behavior:** The canonical's example `{ "**/*": true, "**/Scripts": false }` has the same observable result and required capability as this report's `{ "*.*": true, ".vscode": false }`; only the folder name and broad pattern differ.
- **current source semantics:** In `src/vs/base/common/glob.ts`, `parseExpressionPattern` returns `NULL` when an entry is `false`, meaning that exact pattern is disabled rather than treated as an inclusion overriding another matching pattern. `FilesFilter` in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` parses the complete `files.exclude` expression through this path.
- **related design discussion:** https://github.com/microsoft/vscode/issues/134415 discusses adding negated glob support specifically to address the examples tracked by https://github.com/microsoft/vscode/issues/869.
