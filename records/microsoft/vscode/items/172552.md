# Issue #172552 — removing `editor.defaultFormatter` with "Settings" shows red error popup

[https://github.com/microsoft/vscode/issues/172552](https://github.com/microsoft/vscode/issues/172552)

## Summary

Still reproduces on main: selecting "None" in the settings editor for `editor.defaultFormatter` in a language-specific override writes `null`, which triggers the invalid-type error in the settings UI. The validation logic at `getInvalidTypeError` is correct, but the issue lies in how the settings editor handles writing/displaying `null` enum values in language overrides. An open PR (#181204) exists but has not been merged.

## Change summary

Selecting "None" for `editor.defaultFormatter` in a language-specific settings scope triggers an invalid type error popup.

## Best solution

Review and land the fix from https://github.com/microsoft/vscode/pull/181204 (or a corrected version). The root cause is in the settings editor's enum renderer interacting with the configuration validation — when `null` is written as a language override value and the root setting has no explicit value, the validation path in `settingsTree.ts` (line ~2542) incorrectly classifies it as an invalid type, falling through to the complex template which shows the error. The fix should ensure `null` enum values are properly handled in language-specific override contexts.
