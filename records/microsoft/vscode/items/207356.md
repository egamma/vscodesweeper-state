# Issue #207356 — Create Compound Debug Launches Dynamically

[https://github.com/microsoft/vscode/issues/207356](https://github.com/microsoft/vscode/issues/207356)

## Summary

A real API gap remains: extensions can start and observe debug sessions, but cannot dynamically group independently started sessions or synchronize their pause, continue, stop, and terminate operations. The older linked request covers synchronized pausing for multi-target debugging, not this broader dynamic grouping API, and this team-authored Backlog item must remain open.

## Change summary

Add a VS Code debug API for dynamically grouping independently started sessions and coordinating their lifecycle operations.

## Best solution

Design a public debug-session group abstraction that supports adding sessions after launch and defines coordinated pause, continue, stop, and terminate behavior, while aligning its synchronization semantics with https://github.com/microsoft/vscode/issues/137953.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHostDebugService.ts`, `src/vs/workbench/api/browser/mainThreadDebugService.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/debug/browser/debugService.ts`, `src/vs/workbench/contrib/debug/browser/debugSession.ts`, `src/vs/workbench/contrib/debug/common/debugCompoundRoot.ts`
- **Validation:** Add API and debug-service tests that start independent mock sessions, group them dynamically, add a late session, and verify the agreed pause, continue, stop, terminate, disposal, and partial-failure semantics.
- **Behavior:**

  > An extension can create a debug-session group without declaring every member in launch.json and can add independently started sessions as they appear. A configured lifecycle event affecting one member coordinates the corresponding operation across the group. Membership, late joining, member termination, unsupported operations, and group disposal have documented deterministic behavior. Existing static compounds, parent-child sessions, and ungrouped debug sessions retain their current behavior.
- **Trace:**

  > The stable API in src/vscode-dts/vscode.d.ts exposes individual DebugSession objects, lifecycle events, startDebugging, stopDebugging, and a parentSession relationship, but no dynamic group abstraction. startDebugging crosses extHostDebugService.ts, extHost.protocol.ts, and mainThreadDebugService.ts into DebugService. Static compounds are resolved in DebugService.startDebugging from ICompound.configurations; stopAll creates a DebugCompoundRoot, which debugSession.ts uses only to cascade termination. The requested pause/continue synchronization overlaps https://github.com/microsoft/vscode/issues/137953, but dynamic membership and the public extension contract remain distinct. Preserve existing static-compound, parent-child, test-run, and single-session lifecycle semantics; uncertainty begins at the public group's state, failure, and lifetime contract.
- **Open decisions:**
  - When a running session joins a group whose members are already paused, should it be paused immediately or participate only in future coordinated operations?
  - If a member does not support an operation or an adapter request fails, should the group operation fail, continue best-effort for the remaining members, or remove that member?
  - When the creating extension disposes the group or the original member terminates, should membership dissolve without affecting live sessions, persist until all members terminate, or trigger a coordinated stop?

## Evidence

- **current public API:** src/vscode-dts/vscode.d.ts exposes debug.startDebugging, stopDebugging, session lifecycle events, and DebugSessionOptions.parentSession, but no session-group type, membership operation, or group lifecycle controls.
- **static compound boundary:** src/vs/workbench/contrib/debug/browser/debugService.ts creates compounds only from the configurations declared up front in ICompound.configurations; src/vs/workbench/contrib/debug/common/debug.ts defines that static configuration shape.
- **limited existing coordination:** src/vs/workbench/contrib/debug/common/debugCompoundRoot.ts and debugSession.ts coordinate termination only for compounds configured with stopAll; they do not dynamically attach existing sessions or synchronize pause and continue.
- **related request:** https://github.com/microsoft/vscode/issues/137953 is open and older, but it asks to pause all processes when one process breaks in multi-target debugging. It does not own the broader public API and dynamic-membership requirement here, so it does not satisfy the stronger duplicate bar for this re-reviewed item.
