# Issue #228848 — "go back" (Ctrl+Alt+-) goes berserk after search

[https://github.com/microsoft/vscode/issues/228848](https://github.com/microsoft/vscode/issues/228848)

## Summary

The defect remains on main: automatic find-result selections can populate navigation history, causing Go Back to revisit seemingly unrelated matches. The issue is already routed to editor find and should remain open.

## Change summary

Prevent automatic cursor movements during editor find from polluting Go Back history.

## Best solution

Distinguish automatic find-on-type selections from explicit result navigation, then omit or coalesce only the automatic movements in the workbench navigation stack while preserving Next Match history entries.

## Evidence

- **current source:** src/vs/editor/contrib/find/browser/findModel.ts calls `_editor.setSelection(match)` while moving to a match, and `editor.find.cursorMoveOnType` defaults to true in src/vs/editor/common/config/editorOptions.ts.
- **history path:** src/vs/workbench/browser/parts/editor/textEditor.ts treats the default `api` selection source as USER and considers movements of 10 or more lines DIFFERENT; src/vs/workbench/services/history/browser/historyService.ts then adds those selections to the Go Back stack.
- **prior diagnosis:** https://github.com/microsoft/vscode/issues/20435 documents the same root cause: Find changes selections through the API and those changes enter navigation history. It was closed for backlog management rather than by a fix.
- **prior requested behavior:** https://github.com/microsoft/vscode/issues/127236 specifically requests coalescing cursorMoveOnType entries while retaining explicit Next Match entries; it was closed by the feature-request upvote process and has no fixing PR.
