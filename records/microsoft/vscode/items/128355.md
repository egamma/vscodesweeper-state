# Issue #128355 — Support font family picker in settings

[https://github.com/microsoft/vscode/issues/128355](https://github.com/microsoft/vscode/issues/128355)

## Summary

Keep open: installed-font suggestions are now available in settings.json, but the graphical Settings editor still lacks the requested editable font picker. The older monospace-font request is related, but its discussion explicitly distinguishes its scope from this issue.

## Change summary

Offer installed font families in an editable Settings dropdown while continuing to accept arbitrary font names and comma-separated fallback lists.

## Best solution

Complete graphical Settings support for optional font-family suggestions without turning installed fonts into a validation whitelist. Preserve freeform values and Settings Sync compatibility, using the existing font enumeration support where available.

- **Reason:** Making existing font settings discoverable without sacrificing freeform entry improves the consistency and clarity of the core Settings experience.

Verify keyboard selection and freeform editing, and confirm settings remain editable when local font enumeration is unavailable.
- **Behavior:**

  > Graphical Settings should offer installed font-family suggestions while allowing manual entry. Selecting a suggestion must update the setting, and values containing unavailable fonts or comma-separated fallbacks must remain valid for cross-machine use. Cover editor and terminal font settings without regressing existing settings.json completions. When local font enumeration is unavailable, freeform editing must remain usable.
- **Trace:**

  > The merged partial implementation at https://github.com/microsoft/vscode/pull/214572 explicitly excludes graphical Settings support. Current src/vs/base/browser/fonts.ts exposes getFonts and Electron-only getFontSnippets; editor.contribution.ts and terminal configuration registration adopt the snippet provider. Graphical string settings still use AbstractSettingTextRenderer and SettingTextRenderer in src/vs/workbench/contrib/preferences/browser/settingsTree.ts, with model classification in settingsTreeModels.ts; the text renderer currently reserves Up/Down for Settings-list navigation. The remaining work involves the suggestion metadata-to-renderer contract and editable-picker interaction, not discovering whether a font enumeration API exists. Preserve arbitrary string values, fallback ordering, Settings Sync compatibility, and existing JSON completions. https://github.com/microsoft/vscode/issues/22917 separately tracks monospace-specific suggestions and should not be assumed to absorb this issue.
- **Open decisions:**
  - For an existing comma-separated fallback list, should choosing a font replace the whole value or edit only the current font-family entry?
