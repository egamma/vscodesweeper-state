# Issue #346512 — Markdown Editor does not support Ctrl+Insert / Shift+Insert for copy/paste

[https://github.com/microsoft/vscode/issues/346512](https://github.com/microsoft/vscode/issues/346512)

## Summary

Keep open to investigate clipboard-shortcut parity in the built-in Markdown Editor. Windows already has these bindings globally, but their registration does not establish that they work through the rich editor's separate keyboard and clipboard pipeline.

## Change summary

Support Ctrl+Insert for copying and Shift+Insert for pasting text in the Markdown Editor on Windows.

## Best solution

Make both shortcuts perform the same operations as Ctrl+C and Ctrl+V in the built-in rich Markdown Editor, preserving selection, clipboard formatting, and undo behavior. First establish where the existing host bindings stop reaching the editor.

Compare with Ctrl+C/Ctrl+V, verify exactly one insertion and undo, and repeat in the ordinary text editor to check host-binding parity.
- **Behavior:**

  > In the built-in Markdown Editor on Windows, Ctrl+Insert should copy selected text and Shift+Insert should paste clipboard text at the caret or replace the selection. Their results should match Ctrl+C and Ctrl+V respectively, without duplicate insertion. Existing clipboard formatting, paste handling, and undo behavior should remain unchanged.
- **Trace:**

  > Windows clipboard aliases already exist in src/vs/editor/contrib/clipboard/browser/clipboard.ts. Focused webviews receive those commands through overrideCommandForWebview in src/vs/workbench/contrib/webview/browser/webview.contribution.ts and the execCommand handler in src/vs/workbench/contrib/webview/browser/pre/index.html. That shell recognizes Shift+Insert as a clipboard chord but does not similarly recognize Ctrl+Insert. The rich Markdown editor constructs dependency-owned EditorController with local and forwarded keyboard profiles in extensions/markdown-language-features/markdown-editor-src/editor.ts; ImagePasteController delegates clipboard integration to AsyncClipboardStrategy. The trace cannot establish how those profiles handle Insert chords because the dependency source is absent, and no runtime reproduction was attempted. Start by reproducing https://github.com/microsoft/vscode/issues/346512 and locating the interruption; preserve ordinary editor bindings and other webview consumers.

## Evidence

- **existing capability:** src/vs/editor/contrib/clipboard/browser/clipboard.ts registers Windows Ctrl+Insert for editor.action.clipboardCopyAction and Shift+Insert for editor.action.clipboardPasteAction. This covers ordinary text-editor bindings, not proof of successful operations in the rich Markdown Editor.
- **distinct Markdown surface:** extensions/markdown-language-features/markdown-editor-src/editor.ts constructs EditorController from @vscode/markdown-editor with vscodeLocalKeyboardProfile, vscodeHostKeyboardProfile, and ImagePasteController. extensions/markdown-language-features/package.json pins that dependency to 0.0.2-153; its implementation is not available in this checkout.
- **host clipboard bridge:** src/vs/workbench/contrib/webview/browser/webview.contribution.ts forwards CopyAction and PasteAction to the focused webview. src/vs/workbench/contrib/webview/browser/pre/index.html then executes the corresponding clipboard command in the content document.
- **shortcut handling asymmetry:** In src/vs/workbench/contrib/webview/browser/pre/index.html, isCopyPasteOrCut recognizes Ctrl/Cmd+C/V/X and Shift+Insert, but not Ctrl+Insert. On Electron recognized clipboard chords have their native default prevented before forwarding. This is an investigation lead, not conclusive proof of the reported two-shortcut failure.
- **report and verification limits:** https://github.com/microsoft/vscode/issues/346512 reports both shortcuts failing in Markdown Editor on Windows with VS Code 1.145.2.
