# Issue #319574 — VS Code Agents App - New sessions claims to not have tool access

[https://github.com/microsoft/vscode/issues/319574](https://github.com/microsoft/vscode/issues/319574)

## Summary

The reporter supplied repeatable steps, screenshots, and later confirmed the first-turn refusal still occurred on stable. Current main has a separate pull-request snapshot workflow, but the ordinary pasted-link path still enters the Cloud Agent request pipeline and there is no evidence that its tool-awareness problem was fixed.

## Change summary

A new Agents Window Cloud Agent session incorrectly claims it cannot access GitHub tools on its first turn, then performs the same request after the user reminds it that tools are available.

## Best solution

Ensure the Cloud Agent's first request receives and recognizes its available GitHub capabilities so a pasted pull-request URL can be reviewed without a corrective follow-up. Keep regular VS Code Chat and explicit pull-request-picker behavior unchanged.

- **Behavior:**

  > A newly created Agents Window Cloud Agent session must handle a first-turn request that requires GitHub access, such as reviewing a pull-request URL. It must not claim that GitHub tools are unavailable when those capabilities are enabled, and must not require the user to remind it about its tools. Acceptance is a successful first-turn attempt with the relevant capability visible in the request/debug evidence, while ordinary VS Code Chat continues to behave as before.
- **Trace:**

  > The report reproduces only in the Agents Window and succeeds on the next turn after a corrective instruction, indicating that capability awareness or first-request construction differs from regular Chat. The Cloud first-turn path is CopilotChatSessionsProvider._sendFirstChat in src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts, which sends built-in Agent mode with default permissions through IChatService. The extension-side Cloud provider in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts supplies repository, model, and agent options, while the exact GitHub tool publication or remote-service prompt boundary is not established by the checkout. The explicit pull-request workflow in src/vs/sessions/contrib/github/browser/pullRequestPicker.ts attaches a complete snapshot, but it is a separate path and must not be treated as proof that pasted URLs work. Keep the investigation scoped to Cloud Agent first-turn behavior; do not alter the unsupported Local harness or regular Chat tool selection.
