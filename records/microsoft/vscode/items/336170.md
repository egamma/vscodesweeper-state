# Issue #336170 — Agents Web: Active Agent Host omitted when Dev Tunnels account contains more than five tunnels

[https://github.com/microsoft/vscode/issues/336170](https://github.com/microsoft/vscode/issues/336170)

## Summary

Fresh, well-documented, team-authored report; tracing `browserTunnelAgentHostService.ts` confirms `listTunnels()` calls the Dev Tunnels management client with no pagination handling and no result limit/sort logic, consistent with the reported behavior of only surfacing a subset of tunnels when an account has many records.

## Change summary

Agents web discovery omits an active Agent Host tunnel when the Dev Tunnels account has more than five tunnels, apparently only consuming the first page/subset of results without prioritizing active connections.

## Best solution

In `src/vs/sessions/contrib/providers/remoteAgentHost/browser/browserTunnelAgentHostService.ts` (`listTunnels`), either follow pagination in the Dev Tunnels management client response or explicitly request/sort so tunnels with active `hostConnections` are not dropped in favor of stale zero-connection tunnels; this needs someone with visibility into the actual `@microsoft/dev-tunnels-management` SDK response shape to confirm whether it returns a continuation token.
