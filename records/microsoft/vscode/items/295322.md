# Issue #295322 — Add Support for Pasting Images and Referencing Files in GitHub Copilot's Ask Questions Input Box

[https://github.com/microsoft/vscode/issues/295322](https://github.com/microsoft/vscode/issues/295322)

## Summary

This remains a real gap on current main: the Ask Questions carousel accepts only textual answers, while image and file attachment handling is limited to the main chat input. Route it to the chat input/tool owners for a product and payload-contract decision.

## Change summary

Allow users to paste images and reference files when answering Copilot's structured clarifying questions.

## Best solution

Give Ask Questions answers attachment capabilities consistent with the main chat composer, with explicit per-question ownership and a tool-result representation that lets the model consume file and image context safely.

- **Behavior:**

  > While answering an Ask Questions prompt, users can paste an image or reference a workspace file and submit it as context for the relevant question. Attachments remain associated with the intended answer while navigating between questions and are visible in the submitted summary. The agent receives usable attachment context together with selected or free-text answers. Existing text-only, single-select, multi-select, skip, and accessibility behavior remains unchanged.
- **Trace:**

  > ChatQuestionCarouselPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts renders InputBox and HTMLTextAreaElement controls rather than the model-backed composer used by normal chat input. IChatQuestionAnswerValue in src/vs/workbench/contrib/chat/common/chatService/chatService.ts and IQuestionAnswer in src/vs/workbench/contrib/chat/common/tools/builtinTools/askQuestionsTool.ts carry only strings, and convertCarouselAnswers serializes only selected/freeText/skipped fields. Existing image and file paste behavior is implemented through IChatPasteTargetService and ChatPasteProvidersFeature in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts, which is registered for chatInputSchemes and therefore does not reach carousel controls. The boundary is the structured-question answer path: preserve normal chat composer behavior and all existing question types, navigation, validation, voice, terminal, and auto-reply semantics.
- **Open decisions:**
  - Are attachments scoped to one question answer, shared across the whole questionnaire, or selectable between those scopes?
  - Should referenced files be submitted as live workspace references or immutable snapshots, and how should that distinction be shown to the user?
  - How should image and file content be represented in the model-facing Ask Questions result while preserving attachment limits and consent behavior from the main chat composer?

## Evidence

- **current carousel UI:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts renders text answers with InputBox and plain HTMLTextAreaElement controls; it does not create a chat input model, register an IChatPasteTarget, or expose attachment UI.
- **answer contract:** src/vs/workbench/contrib/chat/common/chatService/chatService.ts defines IChatQuestionAnswerValue only as strings or select-answer objects whose freeformValue is a string, so question answers cannot currently carry file or image entries.
- **tool result contract:** src/vs/workbench/contrib/chat/common/tools/builtinTools/askQuestionsTool.ts converts answers to selected: string[] and freeText: string | null, then returns that JSON as text; no attachment metadata or binary/reference content reaches the model.
- **existing attachment capability:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts implements image and attachment paste providers through IChatPasteTargetService, but ChatPasteProvidersFeature registers them only for chatInputSchemes. The carousel's DOM inputs are outside that path.
- **canonical search:** A repository-wide GitHub issue search for Ask Questions attachments, images, files, and references found no older open issue with the same requested behavior; https://github.com/microsoft/vscode/issues/295322 remains the only matching request.
