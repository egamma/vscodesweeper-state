# Issue #344706 — Copilot LM API: Responses HTTP request ID is lost when the stream ends after reasoning

[https://github.com/microsoft/vscode/issues/344706](https://github.com/microsoft/vscode/issues/344706)

## Summary

The diagnostic correlation defect remains present in current main: a reasoning event followed by graceful EOF produces no completion, and the final classifier consequently loses the supplied HTTP request ID. Keep this open; the linked external PR mitigates empty responses but does not fix correlation preservation in VS Code.

## Change summary

Preserve an available HTTP request ID in failed Copilot Responses results when the stream ends without an accepted terminal completion.

## Best solution

Carry actual HTTP correlation independently of emitted completions through Copilot's fetch result and final classification, so failed requests remain identifiable in diagnostics. Preserve the existing failure classification and do not accept truncated frames or fabricate successful completions.
