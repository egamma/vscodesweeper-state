# Issue #331852 — [regression] Paste in chat changed functionality; now unusable; regresses months of fixes

[https://github.com/microsoft/vscode/issues/331852](https://github.com/microsoft/vscode/issues/331852)

## Summary

Traced this on current main: it's exactly as reported — `PasteTextProvider.provideDocumentPasteEdits` in chatPasteProviders.ts creates a 'Pasted Text Attachment' for any Ctrl+V paste of 1000+ chars (`pastedTextArtifactMinLength`), and `PasteHtmlProvider` explicitly yields to `chat.attach.text` for that case, so Markdown paste no longer happens inline once text is long. This is a deliberate, tested design change, but it silently overrides the standard Ctrl+V / Shift+Ctrl+V paste semantics with no discoverable keybinding to opt out, which is a legitimate regression report worth an area owner's look.

## Change summary

Since 1.134, pasting text of 1000+ characters into the chat input via Ctrl+V (or Shift+Ctrl+V) always creates a non-editable 'Pasted Text Attachment' instead of inserting the text/Markdown inline, and there is no simple keystroke to get the old paste-as-Markdown or paste-as-plain-text behavior back.

## Best solution

A chat maintainer should weigh in on whether the long-paste-to-attachment behavior should be opt-in (e.g. via a dedicated command/keybinding as the reporter suggests) rather than silently overriding Ctrl+V for pastes over pastedTextArtifactMinLength, and whether the existing `editor.pasteAs.preferences` escape hatch should be surfaced/documented for chat specifically.
