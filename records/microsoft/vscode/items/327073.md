# Issue #327073 — Chat Sessions panel: multi-select + Delete only removes one session instead of all selected

[https://github.com/microsoft/vscode/issues/327073](https://github.com/microsoft/vscode/issues/327073)

## Summary

Confirmed live on main: the context-menu multi-select fallback in agentSessionsControl.ts uses `selection.includes(session)` (object-identity check) which can miss the right-clicked session, collapsing the action to a single-item delete. An open PR (#327321) already fixes this with `Fixes #327073`, so the issue stays open pending merge rather than being closed now.

## Change summary

In the Chat Sessions panel, Shift-click multi-select followed by right-click → Delete only deletes one session instead of all selected sessions.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/327321, which replaces the identity-based `selection.includes(session)` check in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsControl.ts with URI-based matching and fixes the same fallback path shared by Archive and other BaseAgentSessionAction subclasses.

## Evidence

- **root cause on main:** src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsControl.ts:721-724 builds `sessions: selection.length > 1 && selection.includes(session) ? selection : [session]` — `selection.includes(session)` is a reference-identity check against `getSelection()`, which can fail to match the right-clicked item, causing a silent fallback to a single-session array.
- **consuming action:** src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts DeleteAgentSessionAction.runWithSessions (line ~730) and BaseAgentSessionAction.run (line ~413) just operate on whatever `sessions` array the context menu builder passed — no independent bug there, all traceable to the marshalling in agentSessionsControl.ts.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/327321 ('fix: delete all selected chat sessions from multi-select', Fixes #327073) replaces the identity check with URI-based selection matching via a new agentSessionMultiSelect.ts helper, adds unit tests, and is still open/unmerged as of this review — the fix file does not exist on current main (`git log` shows no history for agentSessionMultiSelect.ts).
