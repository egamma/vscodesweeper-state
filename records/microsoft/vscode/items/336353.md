[https://github.com/microsoft/vscode/issues/336353](https://github.com/microsoft/vscode/issues/336353)

## Summary

Keep open: worktree-failure handling changed after this report, but the session hover still derives pending state from requested isolation rather than an explicit creation outcome. The supplied Windows steps suffice to retest; neither the related fix nor the newer umbrella establishes that this team-authored report is complete.

## Change summary

Worktree-isolated sessions can appear to run indefinitely with a pending worktree indicator and no effective path or branch.

## Best solution

Ensure execution and session location presentation agree on the resolved workspace: successful creation exposes the effective directory and branch, while failure stops execution and leaves no misleading creation-in-progress state. Retest the reported Windows flow against the landed failure-handling changes before deciding which remaining state-projection behavior needs correction.
