# Issue #305344 — Show terminal tool explanation in UI

[https://github.com/microsoft/vscode/issues/305344](https://github.com/microsoft/vscode/issues/305344)

## Summary

Keep open: current main partially supports descriptive terminal-card text for Agent Host commands, but the built-in terminal tool still drops its required explanation and goal after confirmation. The team-authored request leaves a small user-visible design decision about which description should headline completed commands.

## Change summary

Show the terminal tool's readable explanation or goal prominently instead of relying on a truncated command in the running and completed UI.

## Best solution

Give terminal tool cards a concise model-provided purpose as their prominent headline while preserving the full command and execution state as inspectable details, consistently across built-in and Agent Host sessions.

- **Validation:** Add terminal-card unit or component-fixture coverage with a long command and distinct explanation and goal, then verify the chosen purpose text remains readable in running and completed/collapsed states while the complete command remains available when expanded.
- **Behavior:**

  > Terminal tool activity should present a concise human-readable purpose prominently, rather than making users infer intent from a truncated command. The running and completed/collapsed states should follow the same presentation rule, and the full command must remain available for inspection. Agent Host and built-in terminal calls should behave consistently when equivalent descriptive metadata is available.
- **Trace:**

  > The built-in run-in-terminal schema in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts requires `explanation` and `goal`, but preparation uses them only in confirmation and does not retain them in `IChatTerminalToolInvocationData`. That data type already has an `intention` field, populated from `tc.intention` by `buildTerminalToolSpecificData` in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts. ChatTerminalToolProgressPart forwards `intention` to ChatTerminalThinkingCollapsibleWrapper, which displays it alongside the command; without it, the wrapper uses Running/Ran and truncates the command at 50 characters. Preserve command inspection, skipped/background status semantics, confirmation content, and existing Agent Host behavior. The uncertainty starts at choosing which built-in field supplies the visible purpose and how that purpose shares the collapsed row with command/status information.
- **Open decisions:**
  - Should the prominent terminal-card purpose use the tool's goal, its one-sentence explanation, or a defined combination/fallback between them?
  - In the collapsed running and completed states, should the purpose replace the current Running/Ran command headline or appear alongside a separately presented command and status?
