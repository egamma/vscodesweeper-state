# Issue #176161 — Quit VSCode when last window is closed on MacOS

[https://github.com/microsoft/vscode/issues/176161](https://github.com/microsoft/vscode/issues/176161)

## Summary

Keep this accepted feature request open: current main still keeps macOS running after the last window closes, with no option covering the requested automatic quit. It has 42 upvotes and explicit maintainer support; the earlier equivalent request is closed and cannot serve as a duplicate target.

## Change summary

Provide an option to quit VS Code on macOS when its last window is closed.

## Best solution

Offer an opt-in macOS last-window quit setting while preserving the current default. Define its shutdown and session-restoration semantics before implementation so it cooperates with existing save vetoes, hot exit, and window restoration.

## Plan brief

- **Likely files:** `src/vs/workbench/electron-browser/desktop.contribution.ts`, `src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts`, `src/vs/platform/windows/electron-main/windowsStateHandler.ts`
- **Validation:** On macOS, verify that the disabled option preserves background residency; with it enabled, closing one of two windows keeps the app running and closing the final window quits. Repeat with unsaved editors and relevant hot-exit settings, verify that cancelling a save prompt prevents closure, then relaunch with window.restoreWindows set to all and check the agreed restoration behavior. Include an auxiliary-window case and confirm Windows/Linux behavior is unchanged.
- **Behavior:**

  > Users can opt into quitting VS Code on macOS when they close its last window instead of needing a separate Cmd+Q action. The default continues to allow the app to run without windows, and closing a nonfinal window does not quit the app. Save cancellation must remain effective, and reopening must follow the agreed session-restoration semantics. Acceptance includes clean and dirty editors, multiple windows, auxiliary windows, and unchanged Windows/Linux behavior.
- **Trace:**

  > LifecycleMainService.registerListeners in src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts deliberately suppresses electron.app.quit() on macOS window-all-closed unless quit was explicitly requested; registerWindow similarly suppresses shutdown when its window counter reaches zero. The existing workbench.action.quit, window.restoreWindows, and window.closeWhenEmpty registrations in src/vs/workbench/electron-browser/desktop.contribution.ts do not cover automatic application termination. Ordinary close uses UnloadReason.CLOSE, while an explicit quit changes the unload reason, and WindowsStateHandler in src/vs/platform/windows/electron-main/windowsStateHandler.ts persists state according to that lifecycle ordering. Source inspection confirms the capability gap, but no runtime checks were performed in this read-only review. Preserve existing defaults, save vetoes, and non-macOS behavior; do not expand this into general workspace-restoration redesign. Maintainer support is recorded at https://github.com/microsoft/vscode/issues/25811#issuecomment-1455001152; the equivalent https://github.com/microsoft/vscode/issues/157263 was closed for insufficient votes, not completed.
- **Open decisions:**
  - When enabled, should closing the final macOS window retain ordinary window-close semantics before quitting, or behave like Cmd+Q for unsaved-editor hot exit and session restoration?

## Evidence

- **Current lifecycle behavior:** src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts:300-312 handles window-all-closed by calling electron.app.quit() only when _quitRequested is already true or the platform is not macOS. Lines 468-474 likewise exclude ordinary macOS last-window closure from shutdown. The requested configurable behavior remains absent from this path.
- **Existing-capability check:** src/vs/workbench/electron-browser/desktop.contribution.ts registers workbench.action.quit with Cmd+Q, window.restoreWindows for startup restoration, and window.closeWhenEmpty for closing an empty folderless window. None makes the native close button automatically quit the application after its last window closes; window.confirmBeforeClose in src/vs/workbench/browser/workbench.contribution.ts only controls confirmation.
- **Explicit maintainer support:** https://github.com/microsoft/vscode/issues/25811#issuecomment-1455001152 answers this reporter's exact quit-on-last-window question: no setting exists, but a feature request is welcome and such a setting makes sense for users coming from Windows/Linux. The older closed restoration issue therefore does not establish a rejection of this request.
- **Earlier equivalent request:** https://github.com/microsoft/vscode/issues/157263 requests the same macOS option but is CLOSED. Its closing comment at https://github.com/microsoft/vscode/issues/157263#issuecomment-1269243327 cites insufficient community upvotes, not implementation or a product-scope rejection.
- **Canonical search:** Repository issue searches for quit plus last window, windows are closed, and mac found no verified older open issue owning this request. The supplied lead https://github.com/microsoft/vscode/issues/134336 is open but concerns restoring multiple windows after Ubuntu/GNOME bulk closure, not optional macOS application termination.
- **Accepted community demand:** https://github.com/microsoft/vscode/issues/176161 has the Backlog milestone, the keep label, 42 body upvotes, and several supporting comments. The complete repository triage policy at https://github.com/microsoft/vscode/wiki/Issues-Triaging describes Backlog as accepted work and promotion after 20 community upvotes.
- **Workarounds do not cover the built-in request:** The discussion names Swift Quit and Supercharge as external workarounds, while Cmd+Q remains the built-in explicit quit action. These do not provide the requested VS Code preference; the latest project-context solicitation supplies no fixing or duplicate evidence.
- **Shutdown and restoration boundary:** LifecycleMainService.registerWindow processes ordinary closure through unload(window, UnloadReason.CLOSE), whereas unload selects UnloadReason.QUIT when _quitRequested is true. src/vs/platform/windows/electron-main/windowsStateHandler.ts distinguishes onBeforeCloseWindow from onBeforeShutdown and retains lastClosedState. Planning must establish whether the opt-in closure is an ordinary close followed by quit or has explicit-quit semantics for unsaved editors and restoration.
