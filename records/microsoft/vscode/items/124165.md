# Issue #124165 — Workspace Trust - restricted mode banner accessibility improvements

[https://github.com/microsoft/vscode/issues/124165](https://github.com/microsoft/vscode/issues/124165)

## Summary

Keep open: current source supports Escape returning from banner actions, but Escape on the banner itself still does not dismiss it, and Shift+Tab can restore the action instead of retaining focus on the banner. This team-authored, accepted accessibility cleanup is only partially addressed.

## Change summary

Make restricted-mode banner keyboard navigation return focus to the banner and allow Escape to dismiss it when the banner itself is focused.

## Best solution

Complete the remaining keyboard behavior in BannerPart while preserving arrow-key action navigation and the existing dismissal callback. Retain the working navigation announcement and Enter/Space activation rather than treating those already-supported behaviors as outstanding defects.

## Evidence

- **Escape dismissal remains missing:** In src/vs/workbench/browser/parts/banner/bannerPart.ts, workbench.banner.focusBanner binds Escape under BannerFocused and always calls BannerPart.focus(). That method resets focusedActionIndex and focuses the container; it never calls close(). Therefore Escape with the banner container already focused cannot dismiss it, matching the final unchecked requirement.
- **Shift+Tab focus restoration:** BannerPart.createContentArea() restores the selected action whenever the banner container receives focus and focusedActionIndex is not -1. Arrow navigation sets that index. Banner actions are constructed through Link with tabIndex: -1, but src/vs/platform/opener/browser/link.ts subsequently sets enabled = true, which changes their tabIndex to 0. Shift+Tab from the first action can therefore focus the container only for its focus listener to send focus straight back to the action.
- **Partial existing coverage:** BannerPart's Escape binding already returns action focus to the container. WorkspaceTrustUXHandler.getBannerItemAriaLabels() in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts includes 'Use navigation keys to access banner actions.' Link explicitly activates on both Enter and Space, so the July 2021 Space-activation comment is not an unhandled-key defect in the current implementation.

Its maintainer explanation at https://github.com/microsoft/vscode/issues/125097#issuecomment-852241017 establishes intentional arrow-key navigation rather than separate Tab stops; it does not settle Escape dismissal or the focus-restoration defect.
