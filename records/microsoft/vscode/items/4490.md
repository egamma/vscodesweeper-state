# Issue #4490 — Macro recording

[https://github.com/microsoft/vscode/issues/4490](https://github.com/microsoft/vscode/issues/4490)

## Summary

Keep this well-supported Backlog request open: built-in command sequencing does not provide interactive macro recording. The discussion establishes continuing demand for deterministic record-and-replay editing, including environments where third-party extensions are restricted.

## Change summary

Provide interactive recording and playback of editing inputs, comparable to keyboard macros in Notepad++ or Vim.

## Best solution

Define a lightweight native record/stop/replay workflow for ordinary text editing, with explicit capture boundaries and predictable playback. Treat manually authored command sequences and third-party macro extensions as partial alternatives, not completion of this request.

## Plan brief

- **Likely files:** `src/vs/platform/commands/common/commands.ts`, `src/vs/workbench/services/commands/common/commandService.ts`, `src/vs/workbench/contrib/commands/common/commands.contribution.ts`
- **Validation:** The plan should establish a runnable acceptance scenario: start recording, type and navigate to transform one line, stop recording, and replay on subsequent lines; verify identical ordered transformations, exclusion of recording-control commands, and unchanged behavior outside recording. Include asynchronous-command ordering and the agreed undo behavior in the validation contract.
- **Behavior:**

  > Users want to start recording, perform an ordinary keyboard-driven editing sequence, stop, and replay that sequence without manually writing command JSON or installing a third-party extension. The supplied discussion includes disposable macros that transform successive lines and emphasizes deterministic local execution. Acceptance must demonstrate that replay applies the same editing operations at the new cursor position, in order, without capturing the recording controls. The first design should distinguish the essential temporary record/replay workflow from optional saved macros or a scripting language.
- **Trace:**

  > RunCommands in src/vs/workbench/contrib/commands/common/commands.contribution.ts already executes explicit command sequences but does not capture user interactions. ICommandService in src/vs/platform/commands/common/commands.ts exposes execution events; CommandService._tryExecuteCommand in src/vs/workbench/services/commands/common/commandService.ts emits its did-execute event before asynchronous completion, so event observation alone does not establish faithful replay. Targeted source inspection found no macro recording commands in the inspected editor and keybinding areas; no execution or build was performed. The trace has not established whether ordinary command events cover all relevant text input, composition, and navigation paths. Preserve existing runCommands behavior and normal editing outside recording. https://github.com/microsoft/vscode/issues/871 concerns authored command sequences, while https://github.com/microsoft/vscode/issues/4490 owns the interactive recording request.
- **Open decisions:**
  - Should the initial recording contract cover text-editor typing and navigation only, or also workbench actions and extension commands?
  - Should replay undo as one operation or preserve the undo boundaries of the recorded edits?
  - Should the initial feature retain only the latest temporary recording, or also expose named saved recordings and repeat-count playback?
