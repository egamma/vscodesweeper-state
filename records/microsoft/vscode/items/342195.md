# Issue #342195 — Prevent copilot from starting subagents

[https://github.com/microsoft/vscode/issues/342195](https://github.com/microsoft/vscode/issues/342195)

## Summary

The missing checkbox is real, but current main provides an advanced tool-exclusion setting that can disable the Copilot harness's task tool. Propose answering the configuration question rather than treating the Local harness's runSubagent checkbox as a working solution.

## Change summary

Prevent Copilot from delegating work to subagents that may use a different model from the selected conversation model.

## Best solution

Explain the existing chat.agentHost.copilot.modelCapabilityOverrides excludedTools control, including its launch/resume semantics and exclusions for the separate subagent tools. Do not conflate disabling delegation with configuring which models subagents use.

- **Proposed comment:**

  > Thanks for the context. You're right that the Copilot harness's built-in tools do not have the same checkboxes as Local's `runSubagent` tool. There is an advanced, experimental setting for excluding them: in User Settings JSON, configure `"chat.agentHost.copilot.modelCapabilityOverrides": { "*": { "excludedTools": ["builtin:task", "builtin:execution_subagent", "builtin:search_code_subagent"] } }`. Merge this with any existing capability overrides rather than replacing them; a model-specific `excludedTools` entry takes precedence over the wildcard entry.
  > 
  > Also set `chat.agentHost.copilot.executionSubagent.enabled` and `chat.copilot.searchSubagent.enabled` to `false` to turn off those separately configured subagent features. Start a new Copilot conversation afterward, because tool filters are applied when a session launches or resumes. These controls disable delegation tools; they do not force subagents to use the conversation's selected model.
