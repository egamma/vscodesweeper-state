# Issue #211719 — Default keybinds using `Ctrl+Alt+[Key]` do not work on windows

[https://github.com/microsoft/vscode/issues/211719](https://github.com/microsoft/vscode/issues/211719)

## Summary

Keep open: current source still assigns a Ctrl+Alt letter shortcut on Windows, contradicting the wiki's stated default-keybinding policy. Related reports confirm the character-versus-shortcut conflict; neither the AltGr setting nor the verified related issues fully resolves this report's default-binding and documentation scope.

## Change summary

Resolve Windows Ctrl+Alt default-shortcut conflicts on character-producing layouts and make the keyboard documentation agree with shipped defaults.

## Best solution

Settle whether Windows defaults should avoid character-producing Ctrl+Alt combinations or whether the documented guarantee should change, then reconcile the secondary-sidebar binding and documentation accordingly. Preserve access to layout-specific characters rather than treating AltGr remapping as a complete solution.

- **Behavior:**

Acceptance must check both command invocation and continued entry of layout-specific characters; enabling a setting that sacrifices those characters is not complete coverage.
- **Trace:**

The wiki at https://github.com/microsoft/vscode/wiki/Keybinding-Issues still says Windows defaults avoid Ctrl+Alt+[Key]. keyboard.mapAltGrToCtrlAlt defaults to false, and WindowsKeyboardMapper.resolveKeyboardEvent optionally folds AltGraph into Ctrl+Alt. - **Open decisions:**

## Evidence

- **Current default remains inconsistent with documentation:** src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarActions.ts registers ToggleAuxiliaryBarAction, command workbench.action.toggleAuxiliaryBar, with primary KeyMod.CtrlCmd | KeyMod.Alt | KeyCode.KeyB and no Windows override. The actual shortcut is Ctrl+Alt+B, not the Ctrl+Alt+J stated in the report.
- **Wiki still contains the reported guarantee:** https://github.com/microsoft/vscode/wiki/Keybinding-Issues states under 'Troubleshoot generic Keybindings' that VS Code does not contain Windows Ctrl+Alt+[Key] defaults because they might produce vital characters. Its suggested custom bindings are a workaround, not a correction to the conflicting default or documentation.
- **Introduction verified, not a fix:** https://github.com/microsoft/vscode/commit/0abffa493ce7486bbf07679ff694a718bee1a853 added the CtrlCmd+Alt+B registration to auxiliaryBarActions.ts.
