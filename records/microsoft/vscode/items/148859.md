# Issue #148859 — Disable bracket pair colorization via color theme

[https://github.com/microsoft/vscode/issues/148859](https://github.com/microsoft/vscode/issues/148859)

## Summary

Theme-controlled disabling remains a real gap: the existing boolean setting is not theme-controlled, and color overrides retain the cumbersome workaround described in the report. Keep this accepted Backlog request open for a decision on the theme contract and user-setting precedence.

## Change summary

Allow a color theme to disable bracket pair colorization only while that theme is active, without overriding each bracket color.

## Best solution

Provide a supported theme-level opt-out that preserves ordinary syntax colors and restores normal bracket colorization when switching themes. Settle its interaction with explicit user preferences before implementation; changing the default for every existing theme is a separate, broader decision.

Confirm ordinary syntax colors remain visible, normal colorization returns on theme switch, explicit user true/false settings follow the agreed precedence, and bracket/indentation guides remain unchanged.
- **Behavior:**

  > A theme author should be able to opt out of bracket pair colorization without specifying every bracket foreground color. While that theme is active, brackets should retain their ordinary syntax colors rather than becoming invisible. Switching to another theme should restore that theme's normal behavior without rewriting user settings. Acceptance must cover nested brackets, unexpected closing brackets, theme switching and the agreed precedence of explicit user settings. This request does not by itself authorize changing defaults for all existing themes or disabling indentation and bracket guides.
- **Trace:**

  > BracketPairColorization in src/vs/editor/common/config/editorOptions.ts defines a boolean editor option, and ModelService in src/vs/editor/common/services/modelService.ts derives model enablement from editor configuration. ColorizedBracketPairsDecorationProvider creates decorations based on that model option; its theming participant filters transparent palette colors and handles unexpected brackets separately. The theme schema and _loadColorTheme in colorThemeData.ts contain no corresponding bracket enablement contract, although semanticHighlighting provides an existing example of theme metadata. These paths establish the gap without executing the editor. https://github.com/microsoft/vscode/issues/148859#issuecomment-1120809180 supports the goal, but the thread does not settle the representation or user-preference precedence. Preserve unrelated guide behavior and avoid treating the closed global-default request at https://github.com/microsoft/vscode/issues/148977 as a duplicate.
- **Open decisions:**
  - Should themes express the opt-out through explicit theme metadata or through a documented bracket-color sentinel, and does it also suppress unexpected-bracket coloring?
  - Should a theme opt-out override an explicit user setting enabling colorization, or act only as a theme-provided default that users can override?
