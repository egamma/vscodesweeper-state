# Issue #103527 — Move panel to statusbar - as icon who show popup panel

[https://github.com/microsoft/vscode/issues/103527](https://github.com/microsoft/vscode/issues/103527)

## Summary

A real layout gap remains: current main can hide, reposition, or visually float the Panel, but cannot present it as a status-bar-triggered overlay that leaves the editor layout unchanged. The request earned 42 upvotes and was promoted to the Backlog, so it should remain open for product and interaction design.

## Change summary

Add a status bar affordance that opens Panel views in a popup overlay instead of permanently reserving workbench grid space.

## Best solution

Design an optional overlay mode for the Panel that preserves the existing docked modes, does not resize the editor area, and provides accessible keyboard, focus, dismissal, and resizing behavior.

## Vision fit

- **Fit:** aligned
- **Reason:** The request advances the durable workbench-layout theme by giving users a more flexible, space-efficient way to access core Panel views.
- **Evidence:** Durable theme: “Workbench & core UX — layout flexibility.” It also supports the value of simple, uniform UI interactions if implemented as a coherent Panel mode rather than separate behavior for individual views.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/services/layout/browser/layoutService.ts`, `src/vs/workbench/browser/parts/panel/panelPart.ts`, `src/vs/workbench/browser/parts/panel/panelActions.ts`, `src/vs/workbench/browser/parts/statusbar/statusbarPart.ts`
- **Validation:** Add targeted workbench layout tests proving that opening the overlay Panel does not change the editor grid dimensions and that closing, focus restoration, Escape dismissal, and the existing docked Panel modes behave as designed; include a keyboard and screen-reader manual check of the status bar trigger.
- **Behavior:**

  > Users can invoke the Panel from a status bar affordance and see it above the editor without shrinking or moving the editor area. Existing top, bottom, left, and right docked Panel modes remain available and unchanged. The overlay must be fully operable by keyboard, expose an appropriate accessible name and state, dismiss predictably, and restore focus to the invoking control or previous workbench element.
- **Trace:**

  > The Panel is currently a grid-owned part created by `WorkbenchLayout.createWorkbenchLayout` in src/vs/workbench/browser/layout.ts. `TogglePanelAction` and the position actions in src/vs/workbench/browser/parts/panel/panelActions.ts only toggle grid visibility or choose top, bottom, left, or right. `AbstractPaneCompositePart.layout` in src/vs/workbench/browser/parts/paneCompositePart.ts confirms that Modern UI's “floating panels” are inset card styling over dimensions supplied by the grid, not overlays. The work must preserve current docking, maximization, view-container movement, and layout persistence semantics; https://github.com/microsoft/vscode/issues/10952 is related only to automatic reveal behavior, while https://github.com/microsoft/vscode/issues/299869 explored a broader draggable dialog mode.
- **Open decisions:**
  - Should the status bar expose one affordance for the currently active Panel view, or separate affordances for selectable Panel view containers?
  - Which observable interactions dismiss the overlay: explicit toggle and Escape only, focus loss, or pointer departure as well?
  - Should overlay mode, size, and the last selected Panel view persist per workspace, globally, or only for the current window session?

## Evidence

- **community demand:** The issue has 42 community upvotes, and the triage bot confirmed promotion to the Backlog at https://github.com/microsoft/vscode/issues/103527#issuecomment-699735063.
- **current layout path:** On current main, src/vs/workbench/browser/layout.ts:createWorkbenchLayout installs the Panel as a SerializableGrid view, and src/vs/workbench/browser/parts/panel/panelActions.ts only exposes visibility plus top, bottom, left, and right positions. Showing the Panel therefore still participates in the workbench grid.
- **existing capability is partial:** The `workbench.experimental.modernUI` setting in src/vs/workbench/browser/workbench.contribution.ts describes the Panel as a visually floating card. Its implementation in src/vs/workbench/browser/parts/paneCompositePart.ts only applies insets and card styling to the grid-managed part; it is not a popup overlay and does not satisfy the central request.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/10952 concerns automatic terminal reveal and timeout-based hiding, not a status-bar-triggered overlay. The newer https://github.com/microsoft/vscode/issues/299869 proposed a broader draggable dialog mode but was closed by the community upvote process, so it cannot be a duplicate canonical; this older Backlog item remains the best owner for its specific interaction.
