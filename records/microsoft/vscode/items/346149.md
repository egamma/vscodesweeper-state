# Issue #346149 — Disabling a Copilot CLI-installed plugin in VS Code also disables it in Copilot CLI; no way to hide CLI plugins in VS Code only

[https://github.com/microsoft/vscode/issues/346149](https://github.com/microsoft/vscode/issues/346149)

## Summary

Keep open: runtime-owned plugin toggles explicitly change global Copilot enablement, while the requested VS Code-only exclusion is a separate capability. Existing discovery settings and collision handling do not fully cover that isolation requirement.

## Change summary

Allow independently installed plugin copies to coexist without duplicate contributions in VS Code or disabling the CLI installation.

## Best solution

Provide a clear VS Code-only exclusion or equivalent identity-based deduplication that preserves standalone CLI enablement. Coordinate with the installation migration work without assuming migration alone resolves independent per-tool selection.

CopilotCliAgentPluginDiscovery in agentPluginServiceImpl.ts:1001-1007 calls setPluginEnabled with scope 'global'; src/vs/platform/agentHost/node/copilot/copilotAgent.ts:3538-3572 implements that through client.rpc.plugins.enable/disable. This is explicit runtime ownership, not a VS Code-local exclusion.
- **Existing settings do not supply isolation:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:1426-1448 registers chat.plugins.enabled for all plugin integration and chat.pluginLocations for configured discovery paths. ConfiguredAgentPluginDiscovery skips false entries and redundant CLI-cache paths, but CopilotCliAgentPluginDiscovery independently reads runtime inventory; those path entries are not an exclusion list for native CLI installations.
- **Partial collision handling:** src/vs/workbench/contrib/chat/common/plugins/agentPluginEnablement.ts groups canonical identities, but marketplace installations can use github:/marketplace: identities while CLI marketplace paths use copilot-cli-marketplace:. Direct GitHub installations have additional matching support; this is not universal cross-installation deduplication or an independent VS Code enablement scope.

It addresses installation adoption and duplicate forwarding, not the same observable requirement of excluding a CLI installation only in VS Code.
