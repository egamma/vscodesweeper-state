# Issue #328764 — Experimental `modernUI` switched on by itself

[https://github.com/microsoft/vscode/issues/328764](https://github.com/microsoft/vscode/issues/328764)

## Summary

The reported behavior traces to a real mechanism: `editor.experimental.modernUI` (actually `workbench.experimental.modernUI`, registered with `experiment: { mode: 'auto' }` in workbench.contribution.ts) is periodically re-fetched from an A/B assignment service and applied via `registerDefaultConfigurations` in configurationService.ts's `processExperimentalSettings`/`shouldOverride`. This is a deliberate opt-in-by-experiment design, but the reporter's experience — an experimental setting they explicitly turned off reappearing enabled with a 'Recently changed' badge — suggests a real gap in how default-tier experiment overrides interact with a user's earlier explicit toggle; a contributor independently suspects the same A/B mechanism and asks for an opt-out.

## Change summary

The experimental `workbench.experimental.modernUI` setting, which the user explicitly disabled, turned itself back on in a later window, apparently via a live A/B experiment.

## Best solution

Have the workbench/settings owners confirm whether an explicit user-set value for an `experiment: { mode: 'auto' }` setting can be silently reintroduced by the auto-refetch path in `src/vs/workbench/services/configuration/browser/configurationService.ts` (`processExperimentalSettings`/`shouldOverride`), and consider the contributor's suggestion of a way to opt out of configuration experiments entirely.
