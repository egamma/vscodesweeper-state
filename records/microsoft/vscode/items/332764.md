# Issue #332764 — VSCode server LEAKs server-main.js process.

[https://github.com/microsoft/vscode/issues/332764](https://github.com/microsoft/vscode/issues/332764)

## Summary

Confirmed on main: `serve_web.rs`'s idle-timeout shutdown still uses `child.kill()`, which only terminates the shim process and leaks the reparented `server-main.js` node process, the same defect already fixed for the agent-host path via `kill_tree`. This is a real, well-diagnosed bug that should be routed for a fix.

## Change summary

`code serve-web`'s idle-timeout shutdown leaks the underlying `server-main.js` node process because it only kills the shell shim, not the whole process tree.

## Best solution

Apply the same fix already used in `cli/src/tunnels/agent_host.rs::kill_running_server` — replace the bare `child.kill()` at cli/src/commands/serve_web.rs:941 with `kill_tree(pid)` (falling back to `child.kill()` if the process tree doesn't die within a timeout), matching the pattern and comment already documented there.

  > In cli/src/commands/serve_web.rs, the idle-timeout branch inside `start_version`'s `tokio::select!` loop (around line 941) calls `let _ = child.kill().await;` to stop the server. Because the server is launched via `new_script_command(&executable)` (cli/src/util/command.rs:101), which on non-Windows just execs the script directly but the script itself is a shell wrapper (`bin/code-server...`) that forks `node out/server-main.js` as a child, `child.kill()` only kills the shell shim; the node process gets reparented to PID 1 and is leaked, as confirmed by the reporter's process tree. This is the exact same defect already fixed in cli/src/tunnels/agent_host.rs's `kill_running_server` (lines ~578-609), which replaced `child.kill()` with `kill_tree(pid)` from cli/src/util/command.rs (`kill_tree` walks and kills the whole descendant process tree; see cli/src/util/command.rs:216-223 for unix and :216-218 for windows). Fix the idle-timeout branch in serve_web.rs to call `kill_tree(child.id().unwrap())` instead of (or before falling back to) `child.kill()`, mirroring agent_host.rs's pattern: kill the tree, then bound-wait on `child.wait()` and escalate to `child.kill()` only if the process doesn't exit within a short timeout. Do not change the counter/kill_timer reset logic or the stdout/stderr line-forwarding loop — only the shutdown mechanism in the `_ = &mut kill_timer =>` arm. Add a unit test analogous to `kill_tree_terminates_full_descendant_tree` in cli/src/util/command.rs that spawns a shim-like process tree, triggers the idle-timeout kill path, and asserts no descendant PIDs remain alive afterward — it should fail before the fix (leaked node child) and pass after. Related: https://github.com/microsoft/vscode/issues/319516 and the fix pattern in https://github.com/microsoft/vscode/blob/main/cli/src/tunnels/agent_host.rs.
