# Issue #251747 — Enable Auto-Attach for MCP Prompts / Embedded Resources

[https://github.com/microsoft/vscode/issues/251747](https://github.com/microsoft/vscode/issues/251747)

## Summary

This remains a valid, actively supported feature request: MCP prompts and resources still need an explicit, user-controlled path into persistent chat instructions. The related reports are newer than this re-reviewed issue and therefore cannot serve as duplicate canonicals.

## Change summary

Allow users to pin or automatically include selected MCP prompts and resources as persistent chat context or custom instructions.

## Best solution

Add an explicit pin or reference mechanism that lets users opt selected MCP prompts or resources into custom instructions without enumerating every server resource on every request. The design should preserve parameterized MCP prompts and define persistence, refresh, trust, and token-budget behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat`, `src/vs/platform/mcp`
- **Validation:** Add integration coverage with a test MCP server showing that an explicitly selected resource or prompt is included in subsequent chat context, updates predictably, and unselected server resources are neither enumerated nor attached.
- **Behavior:**

  > Users can explicitly select an MCP prompt or resource for persistent use as chat instructions, without copying it into the workspace. Selected content is available on subsequent relevant chat requests, while unselected MCP resources are not automatically enumerated or attached. Parameterized prompts have a defined invocation experience, and unavailable or changed server content is surfaced rather than silently reused. Acceptance should cover persistence, refresh, removal, and token/context behavior.
- **Trace:**

  > The issue discussion establishes that automatic discovery by enumerating every resource on every request is not feasible, while a pin action is acceptable product direction. The relevant boundary spans MCP prompt/resource discovery and the chat custom-instructions pipeline under src/vs/platform/mcp and src/vs/workbench/contrib/chat; preserve existing local `.prompt.md` and `.instructions.md` matching behavior and avoid implicit reads from every configured server. https://github.com/microsoft/vscode/issues/291004 is related but newer and broader around agent accessibility, so it is not a duplicate canonical under the re-review rule. The implementation trace must first settle how an MCP reference is persisted, refreshed, parameterized, and represented to users.
- **Open decisions:**
  - Should users pin a concrete MCP resource, reference an MCP prompt that is invoked for each request, or support both as distinct instruction sources?
  - Is the selection persisted per workspace, per profile, or globally?
  - When a selected prompt requires parameters, should values be fixed when pinned, requested per chat, or supplied through configuration?
  - Should selected remote content be refreshed on every chat request, cached for the session, or refreshed explicitly, and how should unavailable content be surfaced?
  - What trust and token-budget controls should apply before remotely supplied MCP content is inserted into chat context?
