# Issue #339535 — Problems retains obsolete marker view models after hidden diagnostic updates

[https://github.com/microsoft/vscode/issues/339535](https://github.com/microsoft/vscode/issues/339535)

## Summary

Team-authored bug with a confirmed root cause and an open fixing PR (#339538) already assigned to the author — keep open until that PR merges; no close is appropriate yet.

## Change summary

Problems view leaks thousands of obsolete marker view models (renderer heap growth) when diagnostics are replaced while the panel is hidden and the sorted-resource cache was previously invalidated.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/339538, which reorders disposal in MarkersView.reInitialize() to dispose/clean up marker view states before resetting the markers model, so the resource enumeration used for cleanup isn't empty.

## Evidence

- **root cause confirmed in source:** src/vs/workbench/contrib/markers/browser/markersView.ts reInitialize(): disposables push `toDisposable(() => this.markersModel.reset())` before the later-registered `toDisposable(() => this.markersModel.resourceMarkers.forEach(... this.markersViewModel.remove(resourceMarker.resource)))`; disposables run in registration order so the model is reset (emptied) before the per-resource viewModel cleanup enumerates its (now empty) resourceMarkers, leaking markersViewModel entries for obsolete resources.
