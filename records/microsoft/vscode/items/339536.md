# Issue #339536 — Markdown diff line marking repeatedly scans all mapped elements

[https://github.com/microsoft/vscode/issues/339536](https://github.com/microsoft/vscode/issues/339536)

## Summary

Confirmed real perf defect in the markdown preview's diff-line marking, with a fix already proposed in an open PR authored by the reporter — keeping this open until that PR lands rather than closing early.

## Change summary

Marking added/deleted diff lines in the built-in Markdown preview rescans the full mapped-element array from the start for every changed line, causing multi-hundred-ms blocking on documents with many paragraphs.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339545, which avoids the repeated full-array scan in markChangedLines/getElementsForSourceLine.

## Evidence

- **source trace:** extensions/markdown-language-features/preview-src/index.ts markChangedLines() calls getElementsForSourceLine() once per changed line; scroll-sync.ts getElementsForSourceLine() iterates `lines` from index 0 on every call instead of continuing from the previous position, giving O(n*m) behavior for n changed lines over m mapped elements.
- **no fix on main:** git log on extensions/markdown-language-features/preview-src/scroll-sync.ts shows no change addressing this; the most recent commit (5e86c7c4) is unrelated.
