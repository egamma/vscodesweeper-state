# Issue #90611 — Git - Git does not show gutters unless file is opened from changed files tab

[https://github.com/microsoft/vscode/issues/90611](https://github.com/microsoft/vscode/issues/90611)

## Summary

Keep open: multiple reporters reproduced the missing Git gutters when the workspace URI and Git's canonical repository path differ because of casing or symlink resolution, and a maintainer confirmed the URI mismatch as the underlying cause. The issue is accepted in the Backlog, and the previously cited fix was refuted; no verified newer fix or older same-symptom canonical is established.

## Change summary

Git diff gutter decorations and repository tracking fail when Explorer opens a file through a differently cased or symlinked path than the canonical path returned by Git.

## Best solution

Make source-control resource matching robust when Git canonicalizes repository paths differently from the workspace URI, while preserving VS Code's intentional support for opening folders through logical symlink paths. Coordinate the Git extension's repository/resource mapping with the workbench URI identity behavior rather than requiring users to reopen via a canonical path.

## Plan brief

- **Likely files:** `extensions/git/src/model.ts`, `extensions/git/src/repository.ts`, `src/vs/platform/uriIdentity/common/uriIdentity.ts`, `src/vs/workbench/services/workspaces/browser/abstractWorkspaceEditingService.ts`
- **Validation:** On Windows with a case-mismatched on-disk/tracked path, and on Linux or Remote-SSH with a workspace opened through a parent symlink, edit a tracked file opened from Explorer and assert that the Git gutter appears without reopening it from Source Control and that only one editor identity exists for the file.
- **Behavior:**

  > Opening a repository through a logical symlink path, or opening a Windows file whose path casing differs from Git's tracked spelling, must not disconnect that file from Git status and diff decorations. A tracked edit opened from Explorer should immediately show the same gutter decorations as the same file opened from Source Control, and VS Code must not open two editor identities for the same underlying file. Existing intentional preservation of logical symlink paths must not be silently removed without an explicit product decision.
- **Trace:**

  > The issue thread confirms that Explorer/file-system resources may use a logical or differently cased URI while the Git CLI resolves the repository and changed paths canonically. The Git extension then compares and refreshes resources across identities that VS Code treats as distinct, so opening from Source Control works while opening from Explorer does not; maintainer diagnosis is at https://github.com/microsoft/vscode/issues/90611#issuecomment-1105291866. The likely path spans Git repository/resource mapping in extensions/git/src/model.ts and extensions/git/src/repository.ts plus URI identity/workspace opening behavior in src/vs/platform/uriIdentity/common/uriIdentity.ts and the workspace services. Preserve valid remote URI semantics and the intentional logical-symlink behavior associated with https://github.com/microsoft/vscode/issues/18837; do not solve the bug by globally realpathing every resource without deciding that contract. https://github.com/microsoft/vscode/issues/130082 is a related newer canonical-path option request, not a duplicate canonical for this re-reviewed issue.
- **Open decisions:**
  - Should VS Code preserve the logical workspace URI and make SCM providers reconcile it with canonical repository paths, or offer/enable canonicalization at workspace-open time for affected environments?
  - If logical and canonical URIs resolve to the same file, should the editor globally coalesce them into one resource identity, or should equivalence remain scoped to source-control integration to avoid changing URI semantics for other extensions?

## Evidence

- **confirmed reproductions:** The reporter reproduced the casing mismatch on VS Code 1.43 Insiders and Git for Windows 2.24; independent commenters later reproduced the same observable missing-gutter behavior with symlinked paths on WSL, Linux, Remote-SSH, and workspace files.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/90611#issuecomment-1105291866 explains that VS Code file-system event URIs can retain a symbolic path while Git resolves the repository to its canonical path, leaving the Git extension with mismatched resource identities and preventing diff-decoration refreshes.
