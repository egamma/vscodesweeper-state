# Issue #230136 — [json] Add support for extensions associating JSON schemas with documents dynamically (via API)

[https://github.com/microsoft/vscode/issues/230136](https://github.com/microsoft/vscode/issues/230136)

## Summary

Keep open: the requested dynamic document-to-schema association remains a real extension API gap, and a maintainer has identified activation and ownership constraints that require API design. The open implementation PR must be reviewed or closed before another implementation lane starts.

## Change summary

Allow extensions to associate JSON schemas with documents programmatically based on document content or other runtime conditions.

## Best solution

Review and either land or close https://github.com/microsoft/vscode/pull/239701, ensuring the API avoids eager `*` activation and a hard dependency on `json-language-features`; the preferred design should support programmatic contributions to `jsonValidation` or an equivalent decoupled registry.

- **preferred architecture:** The maintainer suggested a general mechanism for extensions to programmatically provide contribution-point entries such as `jsonValidation`, preserving the existing decoupling also used by YAML.
- **open implementation:** https://github.com/microsoft/vscode/pull/239701 is an open PR titled “Add API to json language features” and references this issue; policy requires keeping the issue open while that human-owned implementation candidate remains open.

- **existing capability boundary:** Static associations remain available through the `jsonValidation` contribution point, while schema contents can be supplied dynamically through VS Code content or file-system providers; neither covers choosing a schema for an arbitrary document at runtime.
