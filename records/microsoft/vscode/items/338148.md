# Issue #338148 — Pty host parses all terminal output a second time, even with persistent sessions disabled

[https://github.com/microsoft/vscode/issues/338148](https://github.com/microsoft/vscode/issues/338148)

## Summary

Current source confirms unconditional headless parsing even for nonpersistent terminals, so the performance concern remains actionable. Keep this open for terminal-owner design work: avoiding that cost must account for replay and shell-integration state, not only persistence.

## Change summary

Reduce the pty host's continuous second parsing of terminal output, particularly when persistent sessions are disabled.

## Best solution

Make terminal recording costs proportional to the replay and persistence capabilities actually required, without regressing terminal output or command metadata. Establish the supported replay contract before choosing between an opt-out path and deferred recording; assess the additional desktop IPC subscription separately.
