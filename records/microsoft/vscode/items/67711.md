# Issue #67711 — Reveal in sidebar by double-click breadcrumb

[https://github.com/microsoft/vscode/issues/67711](https://github.com/microsoft/vscode/issues/67711)

## Summary

Keep open: current breadcrumbs still lack the requested direct reveal gesture, and the existing reveal command only provides a workaround. This accepted Backlog request has 21 upvotes; the related newer report cannot replace it under the re-review rules.

## Change summary

Allow double-clicking a file or folder breadcrumb to reveal that resource in VS Code's Explorer while automatic reveal remains disabled.

## Best solution

Provide deliberate, resource-specific reveal from native breadcrumbs without enabling automatic Explorer tracking. Settle whether the double-click behavior is default or opt-in, and coordinate with the related breadcrumb context-menu work without expanding this request into a general context-menu feature.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/breadcrumbs/breadcrumbsWidget.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbs.ts`, `src/vs/workbench/test/browser/parts/editor/breadcrumbsControl.test.ts`
- **Validation:** In a development workbench with explorer.autoReveal=false, open a workspace file and invoke the agreed gesture on both its file breadcrumb and an ancestor folder breadcrumb. Each must reveal the selected resource in the Explorer without enabling automatic reveal; switching editors afterward must leave Explorer selection unchanged. Verify ordinary single-click picker navigation, symbol navigation and split-editor behavior remain unchanged, with targeted breadcrumb tests for the chosen interaction.
- **Behavior:**

  > Users who disable automatic Explorer reveal need an intentional way to reveal the exact file or ancestor folder shown in native breadcrumbs. The requested interaction is double-clicking that breadcrumb, revealing it in VS Code's Explorer rather than the operating system's file manager. Acceptance must cover both file and folder resources, leave explorer.autoReveal disabled, and preserve ordinary breadcrumb navigation outside the agreed gesture.
- **Trace:**

  > BreadcrumbsWidget._onClick in src/vs/base/browser/ui/breadcrumbs/breadcrumbsWidget.ts forwards click events into selection. BreadcrumbsControl._onSelectEvent and _revealInEditor in src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts lead to pickers or editor navigation, not Explorer selection. The existing revealInExplorer command in src/vs/workbench/contrib/files/browser/fileCommands.ts already handles explicit resource reveal, while breadcrumbs.ts contains no double-click reveal option. The remaining product uncertainty is whether this gesture becomes default behavior or requires opting in. Preserve single-click pickers, symbol navigation and automatic-reveal settings; general context menus and operating-system file-manager integration are outside this request. Related work is https://github.com/microsoft/vscode/issues/56494; the same reveal need is also reported in the newer https://github.com/microsoft/vscode/issues/224898.
- **Open decisions:**
  - Should double-click-to-reveal be enabled by default, or should users explicitly opt in while the default breadcrumb interaction remains unchanged?

## Evidence

- **Current interaction:** src/vs/base/browser/ui/breadcrumbs/breadcrumbsWidget.ts:87,371–380 registers click handling and forwards clicks into focus and selection; it contains no dedicated double-click reveal behavior. In src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts, _onSelectEvent opens a breadcrumb picker, while _revealInEditor opens files in editors or advances the folder picker, not the Explorer.
- **Existing capability does not cover the gesture:** The revealInExplorer command in src/vs/workbench/contrib/files/browser/fileCommands.ts:317–351 accepts a resource, opens the Explorer and calls explorerService.select(uri, 'force'). This supplies the underlying reveal capability, but breadcrumbs do not invoke it for the requested gesture; the breadcrumbs configuration in src/vs/workbench/browser/parts/editor/breadcrumbs.ts provides no corresponding option.
