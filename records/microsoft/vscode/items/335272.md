# Issue #335272 — Copilot doesn't use model reasoning definitions and defaults when used via OpenRouter

[https://github.com/microsoft/vscode/issues/335272](https://github.com/microsoft/vscode/issues/335272)

## Summary

Confirmed in source: OpenRouter's per-model `reasoning.supported_efforts`/`default_effort` data isn't consulted — `resolveModelCapabilities` in openRouterProvider.ts hard-codes `['low', 'medium', 'high']` whenever a model merely supports the `reasoning`/`reasoning_effort` parameter. An open PR from the reporter already targets this fix, so it should stay open pending review/merge rather than being closed now.

## Change summary

The Thinking Effort dropdown for OpenRouter models uses a fixed low/medium/high list instead of the model's actual supported efforts and default effort reported by OpenRouter's models API.

## Best solution

Land https://github.com/microsoft/vscode/pull/335276 (or an equivalent fix) so `resolveModelCapabilities` in extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts reads the model's `reasoning.supported_efforts`/`default_effort` from the OpenRouter models response instead of assuming a fixed low/medium/high list.
