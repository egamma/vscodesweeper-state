# Issue #339795 — Markdown preview opened via a #fragment link always jumps back to that fragment when the tab is re-shown

[https://github.com/microsoft/vscode/issues/339795](https://github.com/microsoft/vscode/issues/339795)

## Summary

The fragment remains embedded in the preview's HTML after initial navigation, causing tab restoration to prioritize it over the saved reading position. Keep this report open: the older scroll-position reports do not establish ownership of this fragment-specific defect.

## Change summary

A Markdown preview opened through a heading fragment repeatedly returns to that heading instead of preserving subsequent scrolling across tab switches.

## Best solution

Treat fragment navigation as a one-time navigation intent in the built-in Markdown preview, while preserving the latest reading position on subsequent reveals. Explicitly following another fragment link must still navigate to its target.
