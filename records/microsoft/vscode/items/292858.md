# Issue #292858 — Colour picker ranges are not tracked correctly on document edits, resulting in corrupt edits

[https://github.com/microsoft/vscode/issues/292858](https://github.com/microsoft/vscode/issues/292858)

## Summary

The stale-range defect remains in current main: color decorations move with document edits, but the picker receives the original provider range and can replace unrelated text before color information refreshes. Keep this open; the supplied reproduction and source trace identify a bounded editor-color-picker fix.

## Change summary

Keep color-picker replacement ranges aligned with document edits while updated document-color information is pending.

## Best solution

Make opening and applying the color picker use the color's current document range during provider-refresh delays, preserving unrelated text and existing color-presentation behavior.

The content-change listener schedules recomputation without updating those cached ranges.
