Current main already supports AI-generated branch names and a Merge action, but the reviewed path does not establish the full commit–merge–optional-cleanup workflow requested here. ## Change summary

Give background CLI sessions task-readable branch/worktree names and a composed action to commit, merge into the original checkout, and optionally clean up the worktree.

## Best solution

Reuse the existing AI naming and merge capabilities rather than introduce parallel controls. Define a clear completion workflow that identifies the target branch, preserves recoverability, and makes optional worktree cleanup explicit, coordinated with the existing cleanup request.

- **Behavior:**

  > Background CLI sessions should have an identity users can associate with their task and a discoverable way to integrate completed work into the intended original branch without manually coordinating several Git operations. Current main already provides AI-generated branch names and an agent-driven Merge action, so the plan must first identify what remains missing in the reporter's normal VS Code workflow. Acceptance should cover uncommitted session changes, the actual target branch, unrelated local edits, and optional cleanup. Cleanup must not discard work after failed integration, and its effect on continuing the session must be explicit.
