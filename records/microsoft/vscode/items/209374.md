# Issue #209374 — OSC hyperlinks are not restored properly on reconnect

[https://github.com/microsoft/vscode/issues/209374](https://github.com/microsoft/vscode/issues/209374)

## Summary

Still a valid open bug — OSC 8 hyperlinks lose their activation (click-to-open) after terminal reconnect/window reload. The TerminalRecorder replays raw data including escape sequences so links appear visually, but the xterm link handler does not rebind them. No fix commit references this issue.

## Change summary

OSC 8 hyperlinks rendered in the terminal become non-functional after a window reload or terminal reconnect, even though the text still appears.

## Best solution

Ensure the xterm instance re-parses OSC 8 escape sequences from the replayed buffer data on reconnect so that the link handler is properly bound. The fix likely involves how the replay data flows through xterm's parser — the raw escape sequences are present in the TerminalRecorder data but xterm's OscLinkProvider may not re-register links from replayed content. The fix would be in the terminal reconnection/replay path in `src/vs/platform/terminal/node/ptyService.ts` (buffer replay) and/or the link provider setup in `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts`.
