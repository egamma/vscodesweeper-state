# Issue #158064 — Turn quick access prefixes into blocks so that they can be easily cleared

[https://github.com/microsoft/vscode/issues/158064](https://github.com/microsoft/vscode/issues/158064)

## Summary

Keep open: quick access still treats prefixes as editable text rather than removable blocks. Maintainers endorsed this direction and explicitly retained this issue to track it; the remaining interaction choices need design agreement.

## Change summary

Offer quick access prefix completion and represent active prefixes as blocks that Backspace can remove atomically.

## Best solution

Provide a consistent, keyboard-accessible mode affordance in quick access that supports prefix discovery and atomic removal without disrupting query editing. Settle the block's presentation and query behavior with the maintainer before implementation in the shared quick input and quick access paths.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickAccess.ts`, `src/vs/platform/quickinput/browser/quickInputBox.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/helpQuickAccess.ts`, `src/vs/platform/quickinput/common/quickInput.ts`
- **Validation:** After design agreement, manually open Quick Access, discover and select a multi-character provider prefix, enter and edit a query, then Backspace at the prefix boundary and verify that the entire mode block is removed in one action with the agreed query behavior. Repeat for '>', '@', and '?' as applicable, including paste, keyboard-only navigation, and screen-reader mode announcements; ordinary non-quick-access Quick Picks must retain their existing text-editing behavior.
- **Behavior:**

  > Quick access prefixes should be discoverable through completion and become a distinct active-mode block rather than ordinary query characters. Backspace at the mode boundary should remove the entire block in one action, including multi-character prefixes. Query text must remain normally editable, and changing or removing a mode must follow an agreed rule for preserving that text. Acceptance must cover keyboard-only use, accessible identification of the mode, and unchanged behavior for ordinary Quick Picks.
- **Trace:**

  > QuickAccessController in src/vs/platform/quickinput/browser/quickAccess.ts stores prefix and query together in picker.value, selects only the query initially, and recreates the picker when a changed value resolves to another provider. QuickInputBox in src/vs/platform/quickinput/browser/quickInputBox.ts wraps a FindInput text input, while src/vs/platform/quickinput/browser/quickInputController.ts constructs that shared input. HelpQuickAccessProvider in src/vs/platform/quickinput/browser/helpQuickAccess.ts already lists providers under '?' and supports exact-prefix switching, but does not supply the requested general completion or token editing. Preserve provider filtering, value restoration, existing query editing, and ordinary Quick Pick behavior; the shared input is not exclusively a quick access surface. https://github.com/microsoft/vscode/issues/155458#issuecomment-1265744208 explicitly retains this issue for prefix pills, and https://github.com/microsoft/vscode/pull/187620 concerns chat rather than this path. The unresolved boundary is the user-facing token presentation and how completion, mode removal, and subsequent query text interact.
- **Open decisions:**
  - Should the active block display the original prefix glyph or a friendly mode name, and should it expose a clickable removal control?
  - Should every registered quick access prefix, including '?', use the block interaction, or only a defined set of modes?
  - When a mode block is removed or replaced while query text remains, should that query be preserved in the new mode or cleared?
  - How should prefix completion be offered and accepted without interfering with ordinary file-query typing?
