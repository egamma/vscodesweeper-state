# Issue #158064 — Turn quick access prefixes into blocks so that they can be easily cleared

[https://github.com/microsoft/vscode/issues/158064](https://github.com/microsoft/vscode/issues/158064)

## Summary

Keep open: current quick access still treats prefixes as editable text, not removable blocks. Maintainers explicitly retained this issue as the tracker for prefix pills; existing provider help and chat slash-command blocks do not satisfy the request.

## Change summary

Offer quick-access prefix completion and represent active prefixes as blocks that Backspace removes atomically.

## Best solution

Provide a lightweight, keyboard-accessible mode token in core quick access, with discoverable prefix completion and atomic removal. Settle the token labeling and query-preservation behavior with a maintainer before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickAccess.ts`, `src/vs/platform/quickinput/browser/quickInputBox.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/helpQuickAccess.ts`, `src/vs/platform/quickinput/common/quickAccess.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** After agreeing the interaction contract, manually open Quick Open, discover and activate both symbolic and multi-character prefixes, enter and edit a query, then clear the active prefix using Backspace. Verify atomic removal, the agreed query-preservation result, correct provider switching, keyboard-only operation, and understandable screen-reader mode announcements. Add automated quick-input coverage for the agreed value, selection, and deletion behavior.
- **Behavior:**

  > Quick access should help users discover and complete mode prefixes and present an active prefix as a distinct removable block. Removing a multi-character prefix must not require deleting its characters individually. Query editing must remain predictable, and removing or switching the mode must follow an agreed query-preservation contract. The interaction must be keyboard-accessible and communicate the active mode to screen readers without making the picker visually busy.
- **Trace:**

  > QuickAccessController in src/vs/platform/quickinput/browser/quickAccess.ts currently carries prefix and query in one picker.value string, derives filtering by removing descriptor.prefix.length, and changes providers when that string matches a different registration. QuickInputBox in src/vs/platform/quickinput/browser/quickInputBox.ts delegates text editing to FindInput; QuickInputController handles input focus and ARIA state. HelpQuickAccessProvider offers a selectable prefix list but no mode-token editing contract. Preserve existing provider routing, query filtering, picker acceptance, and unrelated extension quick picks. https://github.com/microsoft/vscode/issues/155458#issuecomment-1265744208 explicitly leaves prefix pills tracked here; https://github.com/microsoft/vscode/pull/187620 is chat-only prior art, not a quick-access implementation. The uncertainty starts at the user-visible token label, completion interaction, and what happens to an existing query when its mode token is removed.
- **Open decisions:**
  - Should the active token display the literal prefix, a friendly mode name, or the literal prefix with the name available on focus or hover?
  - When a mode token is removed while a query remains, should that query be preserved and interpreted by the default file provider, or should the input be cleared?
  - Should prefix completion appear directly during ordinary Quick Open typing, or be offered through an explicit mode-selection interaction?
