# Issue #341445 — Windows background update: hung CodeSetup .tmp installer accumulates win32k sent-message backlog and makes the whole system's input laggy over time

[https://github.com/microsoft/vscode/issues/341445](https://github.com/microsoft/vscode/issues/341445)

## Summary

Keep open: the background installer's message-starving wait loop remains on current main, and an independent commenter supplies a confirmed cross-application hang with a runnable reproducer. The reported desktop-latency correlation is compelling, but its precise win32k mechanism remains unproven.

## Change summary

Keep the Windows background installer responsive to window messages while it waits for VS Code to exit.

## Best solution

Ensure the pending-update wait in build/win32/code.iss does not block window-message processing, while preserving cancellation, shutdown handling, and update-on-exit behavior.

## Evidence

- **Current source confirms the blocking wait:** build/win32/code.iss:1840-1859, CurStepChanged(ssPostInstall), publishes the ready mutex and then repeatedly calls CheckForMutexes and Sleep(1000) until VS Code exits. The loop checks cancellation but contains no message dispatch.
- **Default user-setup execution path:** src/vs/platform/update/electron-main/updateService.win32.ts:326-330 automatically calls doApplyUpdate after download for user installations when update.enableWindowsBackgroundUpdates is enabled; lines 432-456 launch the silent installer with /update, /sessionend, /cancel, and /nocloseapplications. src/vs/platform/update/common/update.config.contribution.ts:66-72 defaults the background-update setting to true.
- **Independent confirmed reproduction:** https://github.com/microsoft/vscode/issues/341445#issuecomment-6572028955 includes a wait-chain trace from Hike.exe through synchronous SendMessage to the sleeping installer thread, a hung hidden TWizardForm window, installer logs, and a PowerShell WM_FONTCHANGE broadcast reproducer. The broadcast returns immediately after VS Code exits. This review inspected source without executing the Windows reproduction.
- **Measured impact and uncertainty:** https://github.com/microsoft/vscode/issues/341445 reports Ussm paged-pool usage falling from 221 MB to 1 MB and mouse-hook p90 latency falling from roughly 150 ms to 0.4 ms after terminating the VS Code and Cursor installers.
