# Issue #253573 — Show an action in MCP Server Editor allowing user to know about the installed MCP Server

[https://github.com/microsoft/vscode/issues/253573](https://github.com/microsoft/vscode/issues/253573)

## Summary

The onboarding affordance remains absent on current main, and the member discussion establishes a desired direction but leaves the user-visible launch behavior unsettled. This team-authored Backlog request should stay open for that design decision.

## Change summary

Add an MCP Server Editor action that explains how to use an installed server through Chat.

## Best solution

Provide an installed-server onboarding experience that starts the server before asking Chat to explain its available tools. A maintainer should first settle whether this is an explicit “Explain Usage in Chat” action or an automatic post-install experience, and whether Chat opens as a view or editor.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/mcp/browser/mcpServerActions.ts`, `src/vs/workbench/contrib/mcp/browser/mcpServerEditor.ts`, `src/vs/workbench/contrib/mcp/test/browser/mcpConfigurationEntryPoints.test.ts`
- **Validation:** Add a browser unit test covering the chosen onboarding entry point: it is unavailable for uninstalled servers, available or triggered after installation, starts the installed server, and opens Chat with an explanation request grounded in that server's tools; retain the existing MCP configuration-entry-point tests.
- **Behavior:**

  > After an MCP server is installed, users can discover how to use it through a clearly named Chat onboarding affordance. Invoking the experience starts the server so the explanation can reference its available tools, then opens Chat in the presentation chosen by the maintainer and submits the explanation request. Uninstalled servers must not expose the installed-server affordance, and existing install, enablement, and management actions must remain unchanged.
- **Trace:**

  > The MCP Server Editor action bar is assembled in src/vs/workbench/contrib/mcp/browser/mcpServerEditor.ts from action classes in src/vs/workbench/contrib/mcp/browser/mcpServerActions.ts. Current InstallAction.run installs and starts the server, while getContextMenuActions supplies installed-server management actions; neither path contains the requested Chat explanation entry point. The earlier experiment in https://github.com/microsoft/vscode/pull/253169 opened a partial Agent-mode Chat prompt after installation, but that behavior is absent from current main and predates this issue. Keep the change within MCP onboarding and Chat invocation: do not alter general Chat startup behavior, server installation semantics, or unrelated MCP management actions. The uncertainty begins at the user-visible trigger and Chat presentation discussed in https://github.com/microsoft/vscode/issues/253573#issuecomment-3033946719.
- **Open decisions:**
  - Should explanation be launched only through an explicit “Explain Usage in Chat” action, or automatically after a successful server installation?
  - Should the explanation open in the existing Chat view or in a Chat editor?

## Evidence

- **current source:** src/vs/workbench/contrib/mcp/browser/mcpServerEditor.ts constructs the editor action bar from install, uninstall, enable/disable, and manage actions; it has no usage-explanation action.
- **installed actions:** getContextMenuActions in src/vs/workbench/contrib/mcp/browser/mcpServerActions.ts exposes start/stop, configuration, model-access, sampling, resource, and uninstall actions for installed servers, but no action that opens Chat to explain usage.
- **install path:** InstallAction.run in src/vs/workbench/contrib/mcp/browser/mcpServerActions.ts installs and starts the server but does not open or submit an explanatory Chat prompt, so the central onboarding gap remains on current main.
- **related implementation:** https://github.com/microsoft/vscode/pull/253169 merged before this issue was filed and implemented an automatic partial Chat prompt after installation; it does not reference or close this issue, and its prompt behavior is no longer present in the current InstallAction.
- **design discussion:** https://github.com/microsoft/vscode/issues/253573#issuecomment-3033946719 supports the label “Explain Usage in Chat” and starting the server on install, but still contrasts automatic Chat opening with a less disruptive action and suggests opening Chat in an editor.
