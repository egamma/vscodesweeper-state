# Issue #152869 — Support virtual desktops on windows

[https://github.com/microsoft/vscode/issues/152869](https://github.com/microsoft/vscode/issues/152869)

## Summary

Keep this accepted, well-supported request open: current window persistence does not record Windows virtual-desktop assignments. The older restoration report overlaps the original request, but does not cover the additional desktop-local window reuse that a maintainer explicitly associated with this issue.

## Change summary

Support restoring VS Code windows to their Windows virtual desktops, preserving relevant desktop state, and avoiding cross-desktop window reuse when opening files.

## Best solution

Provide Windows virtual-desktop-aware window persistence and selection through a supported native or Electron integration. Coordinate the restoration work with https://github.com/microsoft/vscode/issues/146915 without losing this issue's desktop-local reuse requirement.

- **Validation:** On Windows 11, distribute three workspace windows across separate virtual desktops, use File > Exit, and relaunch before and after an OS restart; verify each window returns to its assigned desktop. From another desktop, run code with a file under the agreed reuse policy and verify no unintended desktop switch. Check the agreed behavior for all-desktops windows and deleted desktops, alongside existing geometry and workspace restoration.
- **Behavior:**

  > The primary goal is to restore each workspace window to its previous Windows virtual desktop after an application exit, update restart, or computer restart. Existing workspace, editor and window geometry restoration must remain intact. The discussion also requests preservation of all-desktops window state and desktop-local file-opening behavior. Acceptance must include multi-desktop restoration and explicit checks of the agreed reuse and missing-desktop behavior.
- **Trace:**

  > WindowsStateHandler in src/vs/platform/windows/electron-main/windowsStateHandler.ts persists workspace identity and the UI state returned by CodeWindow.serializeWindowState. IWindowState in src/vs/platform/window/electron-main/window.ts contains geometry, mode, zoom and display, but no virtual-desktop identity; the current serialization path consequently cannot restore that assignment. File selection in WindowsMainService and windowsFinder.ts uses workspace matching and last-active selection without a desktop filter. The native integration boundary remains unresolved: https://github.com/electron/electron/issues/37494 tracks Electron restoration support, while the supplied discussion identifies Windows IVirtualDesktopManager as an available OS mechanism. Preserve non-Windows behavior and existing workspace restoration. https://github.com/microsoft/vscode/issues/146915 overlaps restoration, whereas https://github.com/microsoft/vscode/issues/168058#issuecomment-1337900338 explicitly associates desktop-local reuse with this issue.
- **Open decisions:**
  - Should desktop-local selection apply only to ordinary CLI file opens, or also override workspace matching and explicit --reuse-window requests?
  - Should the initial capability preserve 'Show this window on all desktops' state as well as individual desktop assignments?
