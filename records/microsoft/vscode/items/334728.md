# Issue #334728 — chat.useCustomizationsInParentRepositories does not discover customizations through Git worktree .git files

[https://github.com/microsoft/vscode/issues/334728](https://github.com/microsoft/vscode/issues/334728)

## Summary

Confirmed on current main: findParentRepoFolders in promptFilesLocator.ts (and its mirror in agentInstructionsLocator.ts) only treats `.git` as a repo root when it is a directory, so a git worktree's `.git` file (a `gitdir:` pointer to the common repo's `.git/worktrees/<name>`) is never recognized and the walk-up returns nothing — matching the reporter's diagnosis exactly. No fix has landed since the prior review (2026-09-20); still open, no PR yet.

## Change summary

chat.useCustomizationsInParentRepositories fails to discover .github customizations from the enclosing repo root when the workspace folder is inside a git worktree, because worktree .git files (gitdir pointers) aren't resolved the way submodule .git files are.

## Best solution

Extend findParentRepoFolders (both copies) to detect a worktree .git file, read its `gitdir:` pointer, strip the trailing `/worktrees/<name>` to get the common repo dir, and treat that common dir's parent as the repo root — reusing the same resolution approach already implemented in chatContinueInAction.ts's resolveGitRemoteNwo.
