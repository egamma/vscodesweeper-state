# Issue #334728 — chat.useCustomizationsInParentRepositories does not discover customizations through Git worktree .git files

[https://github.com/microsoft/vscode/issues/334728](https://github.com/microsoft/vscode/issues/334728)

## Summary

Traced and confirmed in current source: `findParentRepoFolders` in promptFilesLocator.ts only recognizes a repo root when `.git` is a directory, so it never resolves a worktree's `.git` file (a `gitdir:` pointer), and the same pointer-resolution logic already exists elsewhere in the codebase for reuse — this is a real, well-diagnosed gap worth fixing.

## Change summary

chat.useCustomizationsInParentRepositories fails to walk up to and discover customizations at a Git worktree's root, because the parent-repo-root detection only recognizes `.git` as a directory, not as a worktree's `gitdir:` pointer file.

## Best solution

In findParentRepoFolders (src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts) and its mirror in extensions/copilot/src/platform/promptFiles/vscode-node/agentInstructionsLocator.ts, when `.git` is a file, read and resolve its `gitdir:` pointer (as chatContinueInAction.ts's resolveGitRemoteNwo already does) to recognize the folder as a repo root too, rather than only accepting `.git` as a directory.

- **Fix prompt:**

  > In src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts, `findParentRepoFolders` (around lines 135-163) stats `joinPath(current, '.git')` and only treats the folder as a repo root when `gitStat?.isDirectory === true` (line 141). For a Git worktree, `.git` is a text file containing `gitdir: <path>/.git/worktrees/<name>` rather than a directory, so this check always fails and the walk-up never finds the worktree root, silently returning `[]` and disabling `chat.useCustomizationsInParentRepositories` for any subfolder of a worktree. Fix by extending the check: when the `.git` stat exists but is not a directory, read its contents via `this.fileService.readFile`, parse the `gitdir:` pointer (trim + strip the `gitdir:` prefix), and treat `current` as a valid repo root in that case too (no need to resolve the common dir — we only need to know this folder IS a repo root, not to resolve the pointer further, since we already have `current`). Mirror the identical change in extensions/copilot/src/platform/promptFiles/vscode-node/agentInstructionsLocator.ts, which duplicates this logic. Model the gitdir-parsing on the existing helper `resolveGitRemoteNwo` in src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts (lines ~69-93), which already reads a `.git` file and extracts the `gitdir:` value. Do not change the walk-up loop structure, the trust check, or the directory-based repo-root path — only add the file-based (worktree) branch. Add a unit test that mocks `IFileService.stat`/`readFile` to simulate a worktree `.git` file and asserts `findParentRepoFolders` now returns the worktree root, whereas before the fix it returned `[]`. Related: https://github.com/microsoft/vscode/issues/334728 references the earlier submodule fix in PR #332893 (issue https://github.com/microsoft/vscode/issues/329169), which added the walk-past-`.git`-file behavior but did not add gitdir-pointer resolution.
