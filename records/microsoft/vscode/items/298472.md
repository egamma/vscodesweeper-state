# Issue #298472 — PreToolUse 'continue' blocks tool but doesn't terminate loop

[https://github.com/microsoft/vscode/issues/298472](https://github.com/microsoft/vscode/issues/298472)

## Summary

Still reproduces on main: a PreToolUse hook returning `continue: false` with a `stopReason` correctly blocks the individual tool (via `deny` decision) but does not terminate the overall agent loop. The `HookAbortError` thrown by `processHookResults` propagates from the Copilot extension path, but in the VS Code core path (`languageModelToolsService.ts`), the hook result is mapped to a `permissionDecision: 'deny'` which only blocks one tool call — it never signals the agentic loop to stop iterating.

## Change summary

PreToolUse hook's `continue: false` blocks the tool but doesn't stop the agent loop from continuing to process further tool calls.

## Best solution

When a PreToolUse hook returns `continue: false` with a `stopReason`, the tool invocation pipeline should propagate a loop-termination signal (not just a per-tool deny). In the Copilot extension path, the `HookAbortError` already handles this, but in the VS Code core `LanguageModelToolsService` the `IExternalPreToolUseHookResult` only carries `permissionDecision` — it needs a new field or mechanism to signal that the entire turn should be aborted, not just one tool call blocked.
