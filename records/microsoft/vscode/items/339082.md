# Issue #339082 — [Critical] VS Code causes uncontrollable, continuous right-click spam system-wide, requiring force quit to stop

[https://github.com/microsoft/vscode/issues/339082](https://github.com/microsoft/vscode/issues/339082)

## Summary

The reporter traced the trigger to a third-party extension (Marketplace Switcher), but then raised a genuine security/sandbox-escape question — how an extension can hijack OS-level mouse input system-wide until force-quit — and a VS Code maintainer explicitly said someone from the team needs to take this on. Per the hard keep-open rule for sandbox/security concerns, this stays open rather than being closed as caused-by-extension.

## Change summary

An installed extension triggered continuous, uncontrollable system-wide right-click spam that could only be stopped by force-quitting VS Code, raising a question about extension host privilege boundaries.

## Best solution

A VS Code team member should assess whether this is simply expected behavior of the desktop extension host (extensions run with full Node/OS access, unlike web extensions) — in which case this could be documented/closed as as-designed — or whether there's a legitimate hardening opportunity (e.g. a runaway-extension input-flood kill switch). Until that assessment happens, keep open; if confirmed as-designed, a maintainer can close citing the desktop extension host's trust model.
