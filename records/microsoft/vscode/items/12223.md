# Issue #12223 — Possibility to display line endings in text area

[https://github.com/microsoft/vscode/issues/12223](https://github.com/microsoft/vscode/issues/12223)

## Summary

Keep this accepted, well-supported request open: current editor whitespace rendering still does not mark logical line endings. The related issues do not provide an older canonical covering the same request, and mixed-ending status reporting is complementary rather than a replacement.

## Change summary

Provide optional inline line-ending markers so users can inspect whitespace and distinguish actual newlines from visual wrapping.

## Best solution

Provide an opt-in editor presentation of logical line endings, distinct from soft wraps. Decide explicitly whether it displays the model's normalized EOL type or also promises visibility into original mixed endings, since the latter requires addressing information lost during text-buffer normalization.

- **Behavior:**

  > Users can optionally see line-ending markers in the text editor, allowing actual line breaks to be distinguished from visual wrapping without disabling wrapping. Markers must not imply a newline on an unterminated final line, and disabling the feature must preserve the existing presentation. LF, CRLF, empty-line and wrapped-line cases need explicit acceptance checks. Whether markers identify original mixed terminators or the normalized document EOL remains a product scope decision.
- **Trace:**

  > Whitespace._applyRenderWhitespace in src/vs/editor/browser/viewParts/whitespace/whitespace.ts only renders spaces and tabs; the alternate rendering path lives in src/vs/editor/common/viewLayout/viewLineRenderer.ts. PieceTreeBase.getLineContent strips EOL characters, so control-character rendering cannot reveal logical terminators merely by recognizing CR/LF code points. PieceTreeTextBufferFactory.create in src/vs/editor/common/model/pieceTreeTextBuffer/pieceTreeTextBufferBuilder.ts normalizes mixed endings by default, making original-terminator fidelity a separate model concern. Existing editor.renderFinalNewline affects the final line number only. Preserve editing, serialization and existing disabled-state rendering unless a maintainer explicitly expands scope. https://github.com/microsoft/vscode/issues/127 concerns normalization, and https://github.com/microsoft/vscode/issues/119025 concerns mixed-ending status reporting; neither replaces this inline-display request.
- **Open decisions:**
  - Should inline markers represent logical breaks using the normalized document EOL, or must they distinguish each original LF, CRLF and CR terminator in mixed-ending files?
  - Should newline visibility be a separate opt-in setting, or become part of existing renderWhitespace modes, changing what users currently see when those modes are enabled?
