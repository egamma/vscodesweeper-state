# Issue #342876 — Provide authoritative harness identification for enterprise migration and MCP configuration

[https://github.com/microsoft/vscode/issues/342876](https://github.com/microsoft/vscode/issues/342876)

## Summary

Keep open as a feature request: existing identity prompts and internal provider metadata do not establish a consistent, machine-readable Local-versus-Copilot runtime contract for troubleshooting skills. The linked model-name issue is related but does not establish duplicate coverage.

## Change summary

Expose authoritative active-harness identity to agents and skills, ideally through a runtime API, so enterprise MCP migration guidance can select the correct configuration.

## Best solution

Define a host-sourced harness identity contract shared by Local and Copilot sessions, with documented model/skill access and a decision on programmatic exposure. Keep harness identity separate from model identity, configuration capabilities, and credential handling; identity alone must not imply MCP authentication support.
