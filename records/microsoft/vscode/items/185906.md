  > When an installed extension fails during activation, the `extensionActivationError` telemetry event includes the version of that extension in addition to its identifier and error. The value must correspond to the extension instance that attempted activation. Existing activation behavior and user-facing error handling remain unchanged.
- **Trace:**

  > The failure callback reaches `AbstractExtensionService._onDidActivateExtensionError` in src/vs/workbench/services/extensions/common/abstractExtensionService.ts. The service owns a `LockableExtensionDescriptionRegistry` and already calls `_registry.getExtensionDescription(...)` elsewhere, but the issue does not define the telemetry value when that lookup cannot resolve the failing identifier. Keep the scope to activation-error telemetry; do not change activation sequencing, runtime-error telemetry, or displayed error messages.
- **Open decisions:**
  - When the failing extension identifier cannot be resolved in the registry, should `extensionVersion` be omitted, emitted as an empty value, or use another bounded sentinel in the telemetry contract?
