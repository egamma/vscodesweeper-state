# Issue #205620 — Unable to login using the new Fine-grained PATs, even with all open permissions

[https://github.com/microsoft/vscode/issues/205620](https://github.com/microsoft/vscode/issues/205620)

## Summary

Keep open: the built-in GitHub authentication provider still validates PATs against classic OAuth scopes, and the maintainer-approved explanation for unsupported fine-grained tokens is also missing. The issue is already correctly routed and remains accepted Backlog work.

## Change summary

Support fine-grained GitHub PATs in eligible authentication flows, with an explicit explanation while they remain unsupported.

## Best solution

Deliver the maintainer-agreed unsupported-token explanation in GitHub authentication, then establish permission-validation semantics for fine-grained PAT support. Preserve the existing distinction between PAT-eligible clients and official VS Code GitHub.com authentication; the later Copilot least-privilege concern needs human assessment rather than silently bypassing scope validation.

That helper reads only X-OAuth-Scopes and returns an empty list when the header is absent. Nonempty classic scope requests consequently reach the same scope-mismatch error; no fine-grained permission validation or github_pat_ explanation exists in this path.
- **Maintainer-approved direction:** https://github.com/microsoft/vscode/issues/205620#issuecomment-1955685043 explicitly accepts informing users that fine-grained PATs are unsupported and identifies better support as future work. This rules out declining the request merely because classic PATs currently work.

This matches the maintainer's explanation; the original stack trace belongs to the built-in github-authentication provider, not necessarily the GitHub Pull Requests extension.
