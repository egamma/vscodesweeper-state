# Issue #338539 — Last turn changes don't show in parent chat after child chat has run

[https://github.com/microsoft/vscode/issues/338539](https://github.com/microsoft/vscode/issues/338539)

## Summary

Team-authored bug report (dogfood test of #338222) with a clear screenshot-backed repro: the parent session's 'last turn changes' summary shows empty after a cross-repo subagent finishes edits. No fix commit references this issue yet, so it stays open regardless.

## Change summary

After a subagent chat makes edits in a different repo, the parent session's edit-stats summary for the last turn shows no changes even though the subagent's chat window shows edits happened.

## Best solution

Trace how per-turn diff aggregation (aggregateChatEditDiffs in chatEditStatsButton.ts) is fed from a subagent's cross-repo edits (via chatSubagentContentPart.ts / the agent-host subagent progress adapters) and fix the stitching so cross-repo diffs surface in the parent's turn summary, or intentionally decide how cross-repo changes should be represented if not merged.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatEditStatsButton.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSubagentProgress.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`
- **Validation:** After the diagnosis, add/extend a test asserting that when a subagent's edits touch resources under a different workspace root than the parent, the parent turn's aggregated diff (added/removed/resources) is non-empty and reflects those edits.
- **Behavior:**

  > When a user asks the agent to spawn a subagent chat that edits files in a different repo (workspace root) than the parent session, the parent session's 'last turn' edit-stats summary should reflect those changes once the subagent completes, matching what's visible in the subagent's own chat transcript. Currently the summary shows 0 additions/removals for that turn.
- **Trace:**

  > aggregateChatEditDiffs() in chatEditStatsButton.ts merges per-resource diff intervals across sources by matching originalURI/modifiedURI snapshot chains; the subagent path (chatSubagentContentPart.ts, using IRunSubagentToolInputParams and CHAT_OPEN_AGENT_HOST_CHAT_COMMAND_ID) and the agent-host progress adapters (agentHostSubagentProgress.ts, stateToProgressAdapter.ts) are what surface a subagent's edits into the parent's content parts. The repro (issue #338539, filed while testing #338222) is cross-repo specifically, suggesting the diff source for the subagent's edits either isn't collected, or is collected but keyed/filtered against the wrong workspace root before reaching aggregateChatEditDiffs. Do not change the intra-repo (same workspace) diff aggregation, which appears to work per the issue's framing ('actual' vs 'expected' contrast is specific to cross-repo).
