# Issue #314084 — Multiline line commit messages

[https://github.com/microsoft/vscode/issues/314084](https://github.com/microsoft/vscode/issues/314084)

## Summary

The examples reflect Git's subject/body separator convention, not lost newlines in VS Code. GitHub Desktop inserts a blank line between its summary and description fields; entering that same separator in VS Code produces the corresponding message structure.

## Change summary

Make a commit title and description appear consistently when creating and viewing commits in VS Code and GitHub Desktop.

## Best solution

Keep VS Code's free-form commit input without automatically rewriting messages. Explain that a title and description must be separated by a blank line, whereas two consecutive nonempty lines belong to the same Git subject.

- **Proposed comment:**

  > Thanks for the report. Git treats everything before the first blank line as the commit title. GitHub Desktop adds that blank line between its summary and description fields; VS Code's commit input accepts the complete message as entered.
  > 
  > For the same title and description in both applications, enter this in VS Code:
  > 
  > ```text
  > Main line
  > 
  > Sub line.
  > ```
  > 
  > Without the blank line, both lines belong to the title, which explains the combined summary in Desktop. This follows Git's documented message format: https://git-scm.com/docs/git-commit#_discussion.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/314084 compares Desktop's separate summary and description with two consecutive nonempty lines entered in VS Code. These are different raw message structures: 'Main line\n\nSub line.' versus 'Main line\nSub line.'. There are no comments establishing an additional defect.
- **VS Code preserves the input:** extensions/git/src/commands.ts:2576–2611, commitWithAnyInput, takes repository.inputBox.value and passes it through smartCommit. extensions/git/src/git.ts:2082–2089 passes the supplied message as options.input to git commit --file -. It does not flatten internal newlines or insert a subject/body separator. The intervening repository.ts commit path leaves the message unchanged with the default git.addAICoAuthor setting of 'off'.
- **Git's documented convention:** https://git-scm.com/docs/git-commit#_discussion documents that text up to the first blank line is treated as the commit title. The documentation source at https://github.com/git/git/blob/master/Documentation/git-commit.adoc explicitly recommends a short summary followed by a blank line and a description.
- **Desktop formatting and display:** https://github.com/desktop/desktop/blob/development/app/src/lib/format-commit-message.ts constructs the message as `${summary}\n\n${description || ''}\n`, deliberately separating its fields with a blank line. https://github.com/desktop/desktop/blob/development/app/src/lib/git/log.ts reads history using Git's %s summary and %b body fields, explaining why consecutive nonempty lines appear together in the summary.
