# Issue #158679 — Git - no-verify option for git push command

[https://github.com/microsoft/vscode/issues/158679](https://github.com/microsoft/vscode/issues/158679)

## Summary

Keep this accepted Git feature request open: current Push and Sync paths still provide no option to skip pre-push hooks. The commit-only settings do not cover the request, as the maintainer acknowledged when reopening it.

## Change summary

Provide an opt-in way to use git push --no-verify from the built-in Push and Sync actions.

## Best solution

Support deliberate pre-push hook bypass in the built-in Git extension for both Push and Sync, while preserving hook execution by default. Settle whether bypass is a per-operation action or a persistent preference before implementation.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/git.ts`
- **Validation:** In a disposable local repository with a local bare remote, install a pre-push hook that records invocation and exits unsuccessfully. Confirm ordinary Push and Sync invoke the hook and fail; explicitly selected bypass operations succeed without invoking it. For Sync, also verify incoming changes are still pulled normally. Repeat ordinary operations afterward to verify the agreed persistence behavior.
- **Behavior:**

  > Users can deliberately skip local pre-push hooks from the built-in Git Push action and the push phase of Sync. Existing commit-only no-verify settings do not currently provide that capability. Ordinary operations should continue running hooks by default, and bypass must not imply force push or bypass remote-side checks. Acceptance uses a failing local pre-push hook to distinguish ordinary execution from bypass, and checks that Sync retains its pull behavior. The activation and persistence semantics must be agreed before implementation.
- **Trace:**

  > Push flows through CommandCenter._push in extensions/git/src/commands.ts, Repository._push in extensions/git/src/repository.ts, and the low-level Repository.push in extensions/git/src/git.ts. PushOptions and both repository layers have no hook-bypass parameter, and the final push argument builder never emits --no-verify. Sync takes a separate CommandCenter._sync route into Repository._sync, which pulls before invoking the shared _push path. The existing git.allowNoVerifyCommit and git.confirmNoVerifyCommit settings govern commits only. Preserve default hook execution, commit semantics, force/lease protections, and Sync pull/rebase behavior. The supplied thread at https://github.com/microsoft/vscode/issues/158679 explicitly expands the requested surface to Push and Sync and records the maintainer reopening after commit-only advice. Uncertainty starts at whether bypass is a one-operation choice or persistent preference, not at whether the capability is missing.
- **Open decisions:**
  - Should hook bypass be an explicit per-operation Push/Sync action, or a persistent preference that changes subsequent Push/Sync operations?
