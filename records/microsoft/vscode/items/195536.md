# Issue #195536 — Use state service to cache machine / sqmId in `serverServices.ts`

[https://github.com/microsoft/vscode/issues/195536](https://github.com/microsoft/vscode/issues/195536)

## Summary

The startup debt remains on current main: the remote server resolves machine, SQM, and device identifiers directly on every process startup without using persistent state. The existing state and telemetry helpers provide the required caching primitives, so this remains bounded implementation work.

## Change summary

Persist remote-server telemetry identifiers so subsequent server startups do not repeatedly resolve them from the operating system.

## Best solution

Initialize the existing state service during remote-server startup and use persisted telemetry identifiers while preserving the current fallback behavior when no cached value exists.
