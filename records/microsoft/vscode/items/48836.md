# Issue #48836 — Surface customized task proper in the API.

[https://github.com/microsoft/vscode/issues/48836](https://github.com/microsoft/vscode/issues/48836)

## Summary

Keep open: current task serialization preserves the provider's definition, but still does not expose the original provided task with a separate customization reference. This is accepted, team-authored API debt; neither a qualifying fix nor an older canonical owning the same work was established.

## Change summary

Represent a customized task in the extension API as the original provided task with a reference to its tasks.json customization.

## Best solution

Have the task API owner define a backward-compatible contract that distinguishes the original provided task from its customization, then carry that distinction through task conversion. Preserve the existing ability to fetch and execute customized tasks.
