# Issue #279377 — Copilot Chat renderer enters infinite loop when model returns only reasoning_text without content

[https://github.com/microsoft/vscode/issues/279377](https://github.com/microsoft/vscode/issues/279377)

## Summary

Issue carries the `important` label (hard keep-open). The progressive renderer has seen significant changes since the report (commit 40983a98183 rewrote the initial-render detection to use `renderData` presence instead of `contentUpdateTimings.lastWordCount`), which likely mitigates the overflow path, but a direct fix for reasoning_text-only responses causing the loop has not been explicitly verified.

## Change summary

The Copilot Chat progressive renderer enters an infinite loop when a model returns only `reasoning_text` deltas without `content`, causing the word count to overflow to MAX_SAFE_INTEGER and the render timer to spin at ~50ms indefinitely.

## Best solution

Confirm whether the progressive rendering rework in commit 40983a98183 (July 2026, which replaced `contentUpdateTimings.lastWordCount` checks with `renderData` presence checks in `getDataForProgressiveRender`) resolves the infinite-loop trigger for reasoning_text-only responses. If not, add a guard in `doNextProgressiveRender` or `getNextProgressiveRenderContent` that detects zero renderable content across ticks and stops the timer. The fix belongs in `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`.

## Evidence

- **reported code path:** The overflow to MAX_SAFE_INTEGER was logged via `getNextProgressiveRenderContent` in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts, where the old `getDataForProgressiveRender` checked `contentUpdateTimings.lastWordCount === 0` to decide immediate rendering.
- **related fix (post-report):** Commit 40983a98183 (July 2026, https://github.com/microsoft/vscode/commit/40983a98183) rewrote the initial-render detection to use `element.renderData !== undefined` instead of `contentUpdateTimings.lastWordCount`, which changes the overflow trigger path — but was not explicitly aimed at reasoning_text-only responses.
- **current code:** Current `getDataForProgressiveRender` (line 2081) checks `shouldRenderInitialProgressiveContentImmediately(isComplete, hasMarkdownParts, renderData !== undefined)` — when there are no markdown parts (reasoning_text only), hasMarkdownParts is false, so it falls to the rate-based path instead of the MAX_SAFE_INTEGER branch. This may avoid the specific overflow, but the timer loop still runs every 50ms with no content to render.
