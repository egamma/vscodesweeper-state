# Issue #188535 — Allow navigation between output cells in notebooks in the accessible view

[https://github.com/microsoft/vscode/issues/188535](https://github.com/microsoft/vscode/issues/188535)

## Summary

Keep open: the current notebook accessible-view provider still omits next/previous navigation callbacks, so the requested capability remains missing. The existing area labels are appropriate, and no verified older canonical owns this work.

## Change summary

Allow users to navigate between notebook cells' outputs without leaving Accessible View.

## Best solution

Expose notebook output navigation through the existing Accessible View navigation commands, preserving output text conversion and keyboard focus continuity. Settle navigation boundaries and focus restoration before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts`, `src/vs/workbench/contrib/notebook/browser/notebookAccessibilityHelp.ts`, `src/vs/workbench/contrib/notebook/browser/viewModel/cellOutputTextHelper.ts`
- **Validation:** Use a notebook containing three code cells with distinct text outputs, interleaved markdown and an output-free code cell. Open Accessible View on the middle output and invoke its next/previous commands; verify output order, agreed handling of empty cells and boundaries, continued Accessible View focus, and agreed notebook focus after Escape. Verify that multiple outputs within one cell retain their existing text representation.
- **Behavior:**

  > Users should be able to read successive notebook cells' outputs using Accessible View's next/previous commands without closing and reopening the view. Navigation must preserve readable output text and keep keyboard interaction inside Accessible View. Acceptance checks should cover forward/backward traversal, cells without readable output, notebook boundaries, and focus restoration when the view closes.
- **Trace:**

  > NotebookAccessibleView is registered in src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts. Its getAccessibleOutputProvider in notebookAccessibleView.ts captures one selected cell's output and supplies neither navigation callback, although AccessibleContentProvider and the Accessible View service already support them. getAllOutputsText in browser/viewModel/cellOutputTextHelper.ts aggregates a single cell's outputs; preserve its MIME handling and stream aggregation. The current close callback returns focus to the original selection, so introducing navigation raises an observable focus-restoration choice. Keep dynamic output updates and cell-index announcements separate: https://github.com/microsoft/vscode/issues/195581 and https://github.com/microsoft/vscode/issues/189362 cover those requests. The separate REPL provider intentionally presents the most recent execution output and should not acquire notebook traversal implicitly.
- **Open decisions:**
  - Should traversal skip cells without readable output, and should reaching the first or last eligible cell stop or wrap?
  - After navigating to another cell's output, should closing Accessible View focus that cell or return to the cell from which the view was opened?

## Evidence

- **Missing capability on current main:** src/vs/workbench/contrib/notebook/browser/notebookAccessibleView.ts:getAccessibleOutputProvider reads the initially selected cell, captures its getAllOutputsText result, and constructs AccessibleContentProvider without provideNextContent or providePreviousContent. Its onClose callback restores the original selection's focus.
- **Existing navigation infrastructure:** src/vs/platform/accessibility/browser/accessibleView.ts:AccessibleContentProvider accepts optional provideNextContent/providePreviousContent callbacks. src/vs/workbench/contrib/accessibility/browser/accessibleView.ts:next, previous, and _updateContextKeys use those callbacks to render neighboring content and enable navigation. Generic navigation therefore does not supply the missing notebook behavior automatically.
- **Existing notebook behavior is only partial coverage:** src/vs/workbench/contrib/notebook/browser/notebookAccessibilityHelp.ts documents moving between cells in the notebook itself. That requires leaving Accessible View and does not satisfy navigation within it. src/vs/workbench/contrib/notebook/browser/viewModel/cellOutputTextHelper.ts:getAllOutputsText aggregates outputs within one cell, rather than navigating between cells.
- **Related reports are not duplicate canonicals:** https://github.com/microsoft/vscode/issues/189362 is open but requests cell-index announcements, while https://github.com/microsoft/vscode/issues/195581 is open but requests live output updates. Both are newer and cover different observable behavior. The former reports navigation working in a July 2023 Insiders build, but the current provider lacks the necessary callbacks.

The open-PR search for 188535 returned no results. Local history is shallow, and no issue-referencing fix commit was established.
