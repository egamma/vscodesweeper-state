# Issue #300696 — Feature Request: Expose Current Integrated Browser URL to Extensions

[https://github.com/microsoft/vscode/issues/300696](https://github.com/microsoft/vscode/issues/300696)

## Summary

Current main exposes live browser URLs and navigation-state events through the proposed browser API, but the requested stable API remains unavailable. Keep this api-proposal tracking issue open for the API owners to finalize; related discussions explicitly designate it as the general browser API tracker.

## Change summary

Expose the current navigated URL of integrated browser tabs through a supported extension API, including inactive tabs and multi-group layouts.

## Best solution

Finalize a supported browser-tab API covering live URL queries and state-change notifications, using the existing proposed BrowserTab.url, window.browserTabs, and window.onDidChangeBrowserTabState surface as the starting point. Retain this issue until the API owners settle and finalize that contract.

## Evidence

- **Existing capability is proposed, not stable:** src/vscode-dts/vscode.proposed.browser.d.ts declares BrowserTab.url, window.browserTabs, window.activeBrowserTab, and window.onDidChangeBrowserTabState. These browser APIs are absent from src/vscode-dts/vscode.d.ts, and src/vs/workbench/api/common/extHost.api.impl.ts guards their access with checkProposedApiEnabled(extension, 'browser'). This does not yet satisfy the request for a stable API.
- **Live URL propagation exists:** src/vs/workbench/contrib/browserView/common/browserEditorInput.ts forwards model navigation through onDidChangeLabel and reads the current model URL. MainThreadBrowsers._track and _toDto in src/vs/workbench/api/browser/mainThreadBrowsers.ts forward that URL to the extension host; ExtHostBrowserTab.update in src/vs/workbench/api/common/extHostBrowsers.ts updates the exposed URL. Tracking is not restricted to the active editor.
- **Protected API tracking issue:** https://github.com/microsoft/vscode/issues/300696 carries api-proposal. Under the review policy, implementing a proposed API does not complete its tracking issue; finalization or abandonment belongs to the API owners.
- **Related proposal points here:** https://github.com/microsoft/vscode/issues/300319 is open and concerns browser control/debugging through CDP. Its body says to see https://github.com/microsoft/vscode/issues/300696 for general browser APIs, so it is not a replacement canonical for this request.
- **Maintainer-established canonical:** In https://github.com/microsoft/vscode/issues/308407#issuecomment-5195937151, a maintainer identifies this issue as the general browser API tracker and closes the narrower duplicate-tab request in its favor. The comment explicitly warns that invoking internal commands is not a supported API.
- **Accepted community demand:** The issue has 26 community upvotes and was promoted to Backlog on March 23, 2026. The fully read triage policy at https://github.com/microsoft/vscode/wiki/Issues-Triaging describes Backlog as accepted work and the 20-upvote promotion process; inactivity alone does not justify closing this accepted proposal.
