# Issue #309368 — `TerminalSandboxService.checkForSandboxingPrereqs` re-runs on every command rewrite

[https://github.com/microsoft/vscode/issues/309368](https://github.com/microsoft/vscode/issues/309368)

## Summary

Valid debt item: while the engine already caches dependency checks and config paths (via `_sandboxDependencyStatus` and `_sandboxConfigPath`), the top-level `checkForSandboxingPrereqs` still re-evaluates `_isSandboxConfiguredEnabled` and `getSandboxConfigPath` logic on every call rather than using event-driven invalidation as proposed. The team member filed this intentionally.

## Change summary

Replace per-call re-evaluation in `checkForSandboxingPrereqs` with a cached result invalidated only on configuration or workspace-folder changes.

## Best solution

Add a `_cachedPrereqResult` field to `TerminalSandboxEngine` that is populated on first call and invalidated via `onDidChangeConfiguration` (sandbox settings) and `onDidChangeWorkspaceFolders`. The rewriter's call with `forceRefresh: false` would then return the cached result instantly after the first invocation.
