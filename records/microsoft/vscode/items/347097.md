# Issue #347097 — Does the agent window have to stay open for the chat window to?

[https://github.com/microsoft/vscode/issues/347097](https://github.com/microsoft/vscode/issues/347097)

## Summary

Chat windows currently close explicitly with their owning workbench; keeping them open independently would change that lifecycle contract. Keep this collaborator-authored request open for a product decision rather than closing it as designed.

## Change summary

Allow a detached chat window to remain usable after its parent Agents window closes.

## Best solution

Decide whether chat windows should support an independent lifetime, including ownership of their sessions, editors, and terminals after the Agents window closes. Treat this as a window-lifecycle capability rather than a missing layout option.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chatWindow/browser/chatWindowService.ts`, `src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts`, `src/vs/sessions/contrib/chatWindow/browser/sessionsChatWindowProvider.ts`
- **Validation:** Open a session in a chat window with a file editor and terminal, close only the owning Agents window, and verify the agreed lifetime behavior. If independence is supported, confirm the surviving window can send messages, edit and save files, and use its terminal; separately verify application quit and restart restoration.
- **Behavior:**

  > The reporter expects a detached chat window to remain open when its parent Agents window closes. Today both close together. A lifecycle decision should establish whether the detached window remains fully usable independently, while distinguishing parent-window closure from application quit and reload.
- **Trace:**

  > ChatWindowService._openWindow in src/vs/workbench/contrib/chatWindow/browser/chatWindowService.ts creates an auxiliary window and registers it in the window's DisposableStore. An explicit onDidShutdown listener disposes that store when the owning workbench shuts down; BrowserAuxiliaryWindowService.open then closes the underlying window on disposal. The sessions.chatWindows.enabled setting controls entry points and restoration, not lifetime independence. The relevant test plan, https://github.com/microsoft/vscode/issues/346773, describes substantial editor and terminal functionality but does not settle independent ownership. This is not established as a broken existing contract, and removing a shutdown listener alone would not demonstrate that the surviving window's services remain available.
- **Open decisions:**
  - Should closing the owning Agents window preserve fully usable chat windows, or should chat windows retain their current dependent lifetime?
  - If chat windows survive, should closing the last chat window also end the retained Agents workbench, or leave it available for subsequent reopening?
