## Summary

Team-authored bug report — keeping open per policy. The issue describes stale branch/worktree state after worktree deletion: the deleted branch remains listed and selecting it produces a fatal git error. No fix commit found referencing this issue, and the bug appears to still be present on main.

## Change summary

After deleting a git worktree, the old branch remains listed in the branch picker and selecting it causes a fatal 'not a git repository' error.

## Best solution

The git extension's branch/worktree list (likely in `extensions/git/src/model.ts` or `extensions/git/src/repository.ts`) needs to refresh or invalidate cached branch data when a worktree is deleted — either by watching for worktree removal events or by re-querying branches on the next list request. The error path when picking a stale branch should also surface a user-friendly message rather than silently failing.
