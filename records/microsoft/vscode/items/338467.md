# Issue #338467 — Give the Agents Window a separate Windows taskbar group

[https://github.com/microsoft/vscode/issues/338467](https://github.com/microsoft/vscode/issues/338467)

## Summary

Keep open: current source distinguishes the Agents Window icon but does not provide a separate Windows taskbar identity. The related icon and window-switching issues do not cover the requested grouping behavior.

## Change summary

Give Agents Windows a Windows taskbar group separate from regular VS Code project windows.

## Best solution

Provide a distinct Windows shell identity for Agents Windows while preserving regular editor grouping and portable-install isolation. Settle how the separate group behaves when pinned and relaunched before implementation.

## Plan brief

- **Likely files:** `src/vs/code/electron-main/app.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`
- **Validation:** On Windows, open two regular project windows and an Agents Window from the same installation; verify the editor windows share one taskbar group and Agents Windows use another. Exercise activation, pin/unpin, relaunch from the pinned Agents entry, and simultaneous installed/portable instances against the agreed shell behavior.
- **Behavior:**

  > Agents Windows should appear in a Windows taskbar group separate from regular VS Code windows, allowing direct switching without choosing among project windows. Regular editor windows should retain their existing grouping behavior. Acceptance includes distinct grouping when both surfaces are open and predictable activation, pinning, and relaunch behavior. Portable installations must retain their isolation from installed VS Code.
- **Trace:**

  > CodeApplication.startup in src/vs/code/electron-main/app.ts sets a process-wide product AppUserModelID, with a portable-install suffix. CodeWindow creation in src/vs/platform/windows/electron-main/windowImpl.ts already distinguishes isSessionsWindow for its Windows icon, but the inspected native window code does not assign a separate shell identity. The existing icon work therefore does not establish taskbar separation. Related https://github.com/microsoft/vscode/issues/315734 concerns Switch Window branding, not grouping. The remaining design uncertainty is the user-visible shell contract for a separately grouped Agents Window, particularly pinned shortcuts and relaunch; preserve normal editor grouping and portable-install identity boundaries.
- **Open decisions:**
  - Should the separate Agents taskbar group support an independently pinned shortcut that always relaunches the Agents Window, or is separate grouping of running windows the intended scope?
