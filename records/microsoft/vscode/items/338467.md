# Issue #338467 — Give the Agents Window a separate Windows taskbar group

[https://github.com/microsoft/vscode/issues/338467](https://github.com/microsoft/vscode/issues/338467)

## Summary

Legitimate, newly filed request that a maintainer has already routed internally (deepak1556 -> dmitrivMS, who confirms 'people are asking'); it's in Backlog (a holding-bin milestone) but under active maintainer attention, so it stays open — no reason to close a 1-day-old, maintainer-engaged request.

## Change summary

Give the Agents Window its own Windows taskbar group (a distinct AppUserModelID) instead of grouping with regular VS Code project windows.

## Best solution

Give the Agents Window its own win32 AppUserModelID (set per-BrowserWindow via Electron's setAppUserModelId) distinct from the main product's global one set in src/vs/code/electron-main/app.ts, likely requiring a new product.json field and possibly a companion Windows shell/taskbar icon so grouping renders correctly.

## Plan brief

- **Likely files:** `src/vs/code/electron-main/app.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/base/common/product.ts`, `product.json`
- **Validation:** A manual check on Windows: launch the Agents Window alongside a regular VS Code project window and confirm they appear as separate taskbar groups; no automated test currently covers taskbar grouping.
- **Behavior:**

  > On Windows, the Agents Window should appear as its own distinct taskbar group, separate from regular project/editor windows, so users can switch to it directly even with several project windows open. Regular VS Code windows keep their existing taskbar grouping unaffected.
- **Trace:**

  > src/vs/code/electron-main/app.ts (around line 708) calls the single global `app.setAppUserModelId(win32AppUserModelId)` for the whole Electron process at startup; there is no per-BrowserWindow AppUserModelID override anywhere in src/vs/platform/windows/electron-main or src/vs/sessions today. Electron's BrowserWindow exposes a per-window `setAppUserModelId` API (Windows-only) that could be called when creating the Agents Window specifically. Boundary: must not change the AppUserModelID for regular project windows, and any new identifier likely needs a matching Windows Start Menu/shortcut registration to avoid a broken taskbar icon.
- **Open decisions:**
  - Should the Agents Window's AppUserModelID be a new product.json field, or derived from the existing win32AppUserModelId with a suffix?
  - Does giving it a separate AppUserModelID require a companion Windows installer/shortcut registration (jump list, icon) to render correctly, or is setting it on the BrowserWindow alone sufficient?
  - Should this apply uniformly across Stable/Insiders/Portable builds the same way the existing AppUserModelID does?

## Evidence

- **current implementation:** src/vs/code/electron-main/app.ts:708-710 sets a single, process-wide app.setAppUserModelId(productService.win32AppUserModelId) for the whole app — there is no per-window override for the Agents Window today, confirming the gap the reporter describes.
- **no existing per-window handling:** grep across src/vs/sessions and src/vs/platform/windows/electron-main finds no AppUserModelID/session-specific taskbar-grouping code, so this would be new work, not something already shipped.
