# Issue #230089 — `editor.fontLigatuers`  doesn't wotk if the string is long

[https://github.com/microsoft/vscode/issues/230089](https://github.com/microsoft/vscode/issues/230089)

## Summary

VS Code's own code imposes no length limit on the fontLigatures string — it passes the value directly to CSS font-feature-settings. The ~150 byte ceiling the reporter hits is likely a Chromium/Electron parsing limitation in the font-feature-settings CSS property, making this an upstream issue. Keeping open for further investigation since the root cause is not conclusively traced.

## Change summary

Long font-feature-settings strings (>~150 bytes) are silently ignored by the rendering engine, so complex font ligature/variant configurations don't apply.

## Best solution

Investigate whether this is a Chromium bug in CSS font-feature-settings parsing for long values. If confirmed upstream, file a Chromium bug and track it. A possible VS Code-side workaround could be splitting the value or applying features via @font-face, but that would be speculative without confirming the root cause.
