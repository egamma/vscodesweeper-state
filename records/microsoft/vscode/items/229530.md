# Issue #229530 — Semantic tokens types do not override "standard token type" and "font style"

[https://github.com/microsoft/vscode/issues/229530](https://github.com/microsoft/vscode/issues/229530)

## Summary

The issue has two distinct parts: (1) semantic tokens not overriding 'standard token type' — this is by design, as the merge mask in `addSparseTokens` intentionally excludes `TOKEN_TYPE_MASK`; (2) font style (italic) not being overridden despite the scope inspector showing it struck through — contributor RedCMD confirms the font style override gap is a real oversight. The font style display bug is still present on current main.

## Change summary

When a semantic token overrides a TextMate 'comment' scope, the standard token type remains 'Comment' and the italic font style from the theme's comment styling is not overridden, even though the scope inspector's strikethrough suggests it should be.

## Best solution

The standard-token-type behavior is intentional (it drives bracket matching and typing behavior on the render thread). The font style not being overridden when a semantic token is present — while the inspector UI implies it is — is the actionable bug. The fix likely involves the merge logic in `src/vs/editor/common/tokens/sparseTokensStore.ts` (`addSparseTokens`) and possibly the scope inspector display in `src/vs/workbench/contrib/codeEditor/browser/inspectEditorTokens/inspectEditorTokens.ts`. Either the font style should actually be overridden when a semantic token is active, or the inspector should stop showing the strikethrough that implies it is.
