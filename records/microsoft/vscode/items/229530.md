# Issue #229530 — Semantic tokens types do not override "standard token type" and "font style"

[https://github.com/microsoft/vscode/issues/229530](https://github.com/microsoft/vscode/issues/229530)

## Summary

The rendering behavior is intentional, but a narrower inspector bug remains on current main: it strikes through an entire TextMate rule when semantic highlighting overrides only its foreground, incorrectly implying that the rule's font style was also discarded.

## Change summary

Make the token inspector accurately distinguish TextMate properties retained in the final style from properties overridden by semantic highlighting.

## Best solution

Update the Inspect Editor Tokens presentation in `inspectEditorTokens.ts` to show overrides per property rather than striking through the complete TextMate rule. Preserve the existing merge semantics: standard token type remains TextMate-derived, and semantic font attributes override TextMate attributes only when explicitly defined by semantic token styling.

## Evidence

- **property-level merge:** `src/vs/editor/common/tokens/sparseTokensStore.ts` builds `bMask` from explicit `SEMANTIC_USE_*` flags. It does not include `TOKEN_TYPE_MASK`, and it replaces each font-style bit only when the corresponding semantic style is explicitly defined.
- **semantic style encoding:** `src/vs/editor/common/services/semanticTokensProviderStyling.ts` sets `SEMANTIC_USE_ITALIC`, `SEMANTIC_USE_BOLD`, `SEMANTIC_USE_UNDERLINE`, and `SEMANTIC_USE_STRIKETHROUGH` only when the semantic token style defines that property; a semantic token type alone does not reset inherited TextMate font styles.
- **inspector defect:** `src/vs/workbench/contrib/codeEditor/browser/inspectEditorTokens/inspectEditorTokens.ts` wraps the complete rendered TextMate rule in an `<s>` element whenever `semForeground` exists, even though the row and override apply only to `foreground`. This reproduces the misleading strike-through reported in the screenshot.
- **discussion:** The latest technical clarification at https://github.com/microsoft/vscode/issues/229530#issuecomment-2459034466 agrees that the standard token type is behaving as intended while identifying the crossed-out font-style presentation as an inspector oversight.
