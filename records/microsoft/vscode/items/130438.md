# Issue #130438 — Disassembly view: migrate to use WorkbenchList

[https://github.com/microsoft/vscode/issues/130438](https://github.com/microsoft/vscode/issues/130438)

## Summary

The requested migration remains necessary: current main still uses WorkbenchTable with horizontal scrolling explicitly disabled. This team-authored Backlog item has no merged fix or suitable duplicate, so it should remain open for a redesigned implementation.

## Change summary

Migrate the disassembly editor from WorkbenchTable to WorkbenchList so long instructions can scroll horizontally while the breakpoint gutter remains visible.

## Best solution

Use the workbench list infrastructure to support horizontal scrolling while preserving a fixed breakpoint gutter, source-code alignment, variable row heights, incremental instruction loading, and existing breakpoint interactions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/disassemblyView.ts`
- **Validation:** Using a debug adapter that supports disassembly, open the Disassembly editor with source display enabled and instructions wider than the viewport; verify horizontal scrolling exposes the full instruction, the breakpoint gutter remains visible, source and instruction rows remain aligned, breakpoint toggling still works, and scrolling near either end continues loading instructions.
- **Behavior:**

  > The Disassembly editor allows users to horizontally scroll instructions that exceed the viewport width. The breakpoint gutter remains visible and interactive while instruction content scrolls. Interleaved source lines retain their intended alignment, and variable-height rows, selection, accessibility, incremental loading, and instruction-breakpoint behavior continue to work.
- **Trace:**

  > DisassemblyView.createEditor in src/vs/workbench/contrib/debug/browser/disassemblyView.ts currently creates a WorkbenchTable with two renderers and `horizontalScrolling: false`. The table also supplies variable row heights for interleaved source text, while BreakpointRenderer and InstructionRenderer divide the fixed gutter from scrollable instruction content. The unmerged attempts https://github.com/microsoft/vscode/pull/133703 and https://github.com/microsoft/vscode/pull/135604 show that a one-file WorkbenchList migration is plausible, but they did not resolve content-width measurement, source indentation, or keeping the breakpoint gutter visible during horizontal scrolling. Preserve the disassembly data model, debug-adapter requests, incremental loading, breakpoint semantics, and source-file resolution; the planning uncertainty is confined to the list row DOM/layout and its validation strategy.
