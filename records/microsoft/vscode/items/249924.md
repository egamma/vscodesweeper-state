# Issue #249924 — A way to distinguish inputfocus between rename file and find in explorer?

[https://github.com/microsoft/vscode/issues/249924](https://github.com/microsoft/vscode/issues/249924)

## Summary

A real customization gap remains on current main: Explorer rename cancellation is handled directly by the input's Escape listener and is not exposed as a command that another key can invoke. The older related issue concerns Escape keybinding dispatch rather than this report's observable need to bind rename cancellation to a different key, so it does not meet the stronger duplicate bar.

## Change summary

Expose enough Explorer rename state and command support to let one custom key cancel an active filename rename without also closing an open tree-find widget.

## Best solution

Provide a keybindable Explorer rename-cancellation command with a context condition identifying an active rename input, allowing custom bindings to prioritize rename cancellation over `list.closeFind`.

## Evidence

- **current source:** In src/vs/workbench/contrib/files/browser/views/explorerViewer.ts, the rename input's KEY_DOWN listener directly calls `done(false, true)` only when it receives `KeyCode.Escape`; no rename-cancellation command is invoked.
- **existing find command:** src/vs/workbench/browser/actions/listCommands.ts registers `list.closeFind` under `treeFindOpen`, so a custom key can close tree find but has no corresponding command for cancelling the active Explorer rename.
- **related issue distinction:** https://github.com/microsoft/vscode/issues/174877 is older and open, but reports that an Escape keybinding executes after the hard-coded rename cancellation. This issue instead asks to invoke rename cancellation from a different custom key while tree find remains open; the reporter-observable symptoms and required capabilities are not the same.
- **maintainer confirmation:** https://github.com/microsoft/vscode/issues/249924#issuecomment-2922683184 confirms that there is no command to close the rename widget and that Escape is hard-coded.
