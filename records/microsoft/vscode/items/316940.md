# Issue #316940 — Agent Host Incorrectly Constructs Git Worktree Path, Creating Directory in Wrong Location

[https://github.com/microsoft/vscode/issues/316940](https://github.com/microsoft/vscode/issues/316940)

## Summary

The `getCopilotWorktreesRoot` function intentionally uses a sibling-directory convention (`<repo>.worktrees` next to the repo root), but when the repository root is the user's home directory (e.g. `/home/jarvismark1`), the sibling lands in `/home/` where the user lacks write permissions. This is a real edge case worth keeping open.

## Change summary

Agent host creates git worktree directory as a sibling to the repo root, which fails with EACCES when the repo root is the user's home directory because the sibling lands in a directory the user cannot write to.

## Best solution

Add a guard in `getCopilotWorktreesRoot` (or its callers in `copilotAgent.ts`) for the edge case where the computed worktrees root lands in an unwritable location — e.g. fall back to `<repoRoot>/.worktrees` (inside the repo) when the sibling directory's parent is not user-writable, or when the repo root is a filesystem root or home directory.
