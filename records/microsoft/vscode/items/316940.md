# Issue #316940 — Agent Host Incorrectly Constructs Git Worktree Path, Creating Directory in Wrong Location

[https://github.com/microsoft/vscode/issues/316940](https://github.com/microsoft/vscode/issues/316940)

## Summary

Keep open: current source still places worktrees beside the repository, which targets an unwritable /home directory when the repository root is the user's home. An open PR explicitly references this issue and proposes a fix; it has not merged.

## Change summary

Prevent Agent Host worktree creation from failing with EACCES when the repository root is the user's home directory.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/334994 so home-root repositories can create isolated worktrees in a writable location while ordinary repositories retain their existing layout.

## Evidence

- **Current path construction:** src/vs/platform/agentHost/common/worktreePaths.ts:getWorktreesRoot returns URI.joinPath(repositoryRoot, '..', `${basename(repositoryRoot.fsPath)}.worktrees`). For repositoryRoot /home/jarvismark1, this deterministically produces /home/jarvismark1.worktrees, matching the reported error. Its documentation explicitly describes a sibling directory, so the general layout is intentional rather than a universal missing-separator typo.
- **Failing creation flow:** src/vs/platform/agentHost/node/shared/worktreeIsolation.ts:1034–1059 computes getWorktreesRoot(repositoryRoot) and calls fs.mkdir(worktreesRoot.fsPath, { recursive: true }) before adding the worktree. The pull-request checkout path repeats this at lines 1136–1140. Neither path selects an alternate root for a home-directory repository. This source trace confirms the reported target; no runtime reproduction or filesystem changes were performed.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/334994 was verified OPEN with no merge commit. Its body includes Fixes #316940 and proposes .git/vscode-worktrees for home-root repositories, with related provenance handling and tests. An unmerged implementation candidate is not evidence of a completed fix.
- **Related request is not a duplicate:** https://github.com/microsoft/vscode/issues/293884 was verified open and requests configurable worktree directory patterns. That is distinct from the permission failure here. The reporter rejected the connection on August 30, and the original commenter acknowledged the misunderstanding on August 31.
- **Workaround does not cover current path:** Creating ~/.worktrees, as suggested in the issue body, does not create the sibling directory selected by getWorktreesRoot and therefore does not address the traced mkdir target.
