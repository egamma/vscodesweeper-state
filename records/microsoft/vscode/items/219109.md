# Issue #219109 — Strings in editor build use unicode escape sequences.

[https://github.com/microsoft/vscode/issues/219109](https://github.com/microsoft/vscode/issues/219109)

## Summary

Keep open for the engineering owner's assessment: the original min/dev build split is gone, but current Monaco localization output explicitly escapes non-ASCII characters. Neither that removal nor the current serialization policy establishes completion of this team-authored size concern.

## Change summary

Avoid unnecessarily bloated Unicode-escaped strings in generated Monaco localization JavaScript.

## Best solution

Reconcile the localization-size concern with the current ASCII serialization contract before changing the build. The owner should determine whether compact localization output remains a requirement for the ESM distribution; removing escapes alone would contradict the current serializer's documented behavior.
