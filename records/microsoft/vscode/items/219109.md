# Issue #219109 — Strings in editor build use unicode escape sequences.

[https://github.com/microsoft/vscode/issues/219109](https://github.com/microsoft/vscode/issues/219109)

## Summary

Current main intentionally emits these Unicode escapes, but this team-authored Backlog issue cannot receive a judgment close. It should remain open until the build owners decide whether the original artifact-size concern is superseded by the newer ASCII-loading rationale.

## Change summary

Avoid the expanded Unicode escape representation in generated Monaco editor NLS JavaScript bundles.

## Best solution

Reconcile this issue with the intentional ASCII serialization introduced by https://github.com/microsoft/vscode/pull/336100. If avoiding wide script representations outweighs the small generated-size increase, the author or build owner should close this issue as superseded; otherwise the desired size/runtime tradeoff needs to be redefined.
