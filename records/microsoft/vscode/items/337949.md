# Issue #337949 — Support Markdown Stylesheets in the New Markdown Editor

[https://github.com/microsoft/vscode/issues/337949](https://github.com/microsoft/vscode/issues/337949)

## Summary

Verified gap: the new custom Markdown Editor's HTML generation only links its own editor.css and never resolves the user-configured markdown.styles setting, unlike the Markdown Preview which does. Real, bounded request worth keeping open.

## Change summary

Apply the `markdown.styles` setting's user stylesheets to the new custom Markdown Editor, not just the Markdown Preview.

## Best solution

Extend MarkdownEditorProvider#getHtml (extensions/markdown-language-features/src/preview/markdownEditorProvider.ts) to read markdown.styles and markdownExtensions.contributions.previewStyles and inject corresponding <link> tags into the editor webview HTML, mirroring documentRenderer.ts's #getSettingsOverrideStyles/#addStyles logic used by the Preview.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/src/preview/markdownEditorProvider.ts`, `extensions/markdown-language-features/src/preview/documentRenderer.ts`
- **Validation:** A test/manual check confirming that with `markdown.styles` set to a CSS file, opening a .md file in the custom Markdown Editor renders with that stylesheet applied, matching the Preview's behavior for the same file.
- **Trace:**

  > MarkdownEditorProvider#getHtml (extensions/markdown-language-features/src/preview/markdownEditorProvider.ts, ~line 1029) builds the webview HTML with only `editor.css`; it never reads vscode.workspace.getConfiguration('markdown').get('styles') or contributionProvider.contributions.previewStyles. The Preview equivalent lives in documentRenderer.ts (~lines 199-237, #addStyles/#getSettingsOverrideStyles), which resolves those and injects <link> tags, plus preview.ts surfaces load failures via an 'unloadedStyles' message. Boundary: don't change Preview's own style pipeline; only extend the editor's HTML generation to add equivalent <link> tags scoped to the editor's CSP (style-src already includes webview.cspSource).
- **Open decisions:**
  - Should user-provided markdown.styles CSS apply to the entire rich editor surface (including editor chrome) or be scoped only to rendered markdown content, given the editor is editable rather than static preview HTML?
  - Should contributed extension preview styles (contributions.previewStyles) also apply to the rich editor, or only the user's own markdown.styles?

## Evidence

- **editor HTML lacks styles:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts #getHtml (~line 1029) only links 'editor.css' via styleUri; no reference to the markdown.styles setting or user contributed preview styles.
- **preview applies styles:** extensions/markdown-language-features/src/preview/documentRenderer.ts lines ~199-237 (#addStyles/#getSettingsOverrideStyles) resolves config.styles (markdown.styles) and contributionProvider.contributions.previewStyles and injects <link> tags; extensions/markdown-language-features/src/preview/preview.ts surfaces an 'unloadedStyles' warning for markdown.styles, confirming Preview-only wiring.
