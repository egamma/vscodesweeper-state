# Issue #229500 — SCM Graph - Picked wrong repo not from active editor

[https://github.com/microsoft/vscode/issues/229500](https://github.com/microsoft/vscode/issues/229500)

## Summary

The bug appears still present on main: the SCM Graph's auto-mode repository selection uses `latestChangedValue([firstRepository, graphRepository])`, where `firstRepository` is a one-shot observable that resolves to the first registered repo. At initialization in a multi-root workspace, this fires before the active-editor-derived `graphRepository` updates, so the graph can pick the wrong repo regardless of which editor is active.

## Change summary

In a multi-root workspace, the SCM Graph in 'auto' mode picks the first registered repository instead of the one matching the active editor.

## Best solution

Fix the initialization race in `SCMTreeViewPaneViewModel` (scmHistoryViewPane.ts ~line 1152–1167): the `firstRepository` one-shot should not override the active-editor repository once it's available. Consider making `firstRepository` a fallback that only applies when `graphRepository` hasn't resolved yet, rather than a competing signal in `latestChangedValue`.
