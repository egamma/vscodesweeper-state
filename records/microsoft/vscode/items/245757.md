# Issue #245757 — Feature Request: Expose Command Trigger Source (Keyboard vs Mouse vs Menu)

[https://github.com/microsoft/vscode/issues/245757](https://github.com/microsoft/vscode/issues/245757)

## Summary

This broad command-observation API has been explored and declined repeatedly because of performance, internal-argument leakage, and exposing UI implementation details. The additional trigger-source metadata does not overcome those established concerns.

## Change summary

Expose extension API metadata identifying whether commands were invoked through a keybinding, mouse action, command palette, or API.

## Best solution

Keep command trigger provenance internal and address concrete scenarios through focused core contributions or narrowly scoped APIs that avoid broadcasting every command and its UI origin to extensions.

## Vision fit

- **Fit:** rejected
- **Reason:** A global command interception surface carrying UI-origin details conflicts with the lightweight, performance-first extension boundary.
- **Evidence:** Public values: “Performance trumps functionality” and extensions have deliberately limited UI choices.

This API direction has been explored before in https://github.com/microsoft/vscode/issues/78091 and https://github.com/microsoft/vscode/issues/135616.
