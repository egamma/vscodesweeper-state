# Issue #248051 — Explorder: Exclude Git Ignore didn't hornor .gitignore file in ancestor folder

[https://github.com/microsoft/vscode/issues/248051](https://github.com/microsoft/vscode/issues/248051)

## Summary

Verified duplicate: the older open issue https://github.com/microsoft/vscode/issues/189951 reports the same observable failure when a subfolder is opened and the applicable `.gitignore` is above the workspace root.

## Change summary

Explorer fails to hide files ignored by a repository-level `.gitignore` when the opened workspace is a descendant folder.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/189951 and ensure its fix loads applicable ancestor `.gitignore` files for workspace roots; this report contributes confirmation that the defect also occurs on Windows.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/189951 is open, predates this report, and describes the same reporter-observable symptom: `explorer.excludeGitIgnore` does not apply a repository `.gitignore` above the opened subfolder.
- **source confirmation:** In `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `FilesFilter.updateConfiguration` initializes an empty ignore tree per workspace root, while `filter` calls `processIgnoreFile` only for `.gitignore` entries encountered inside that Explorer tree. An ancestor `.gitignore` outside the workspace is therefore never loaded.
- **maintainer precedent:** A maintainer closed https://github.com/microsoft/vscode/issues/172482 as a duplicate of https://github.com/microsoft/vscode/issues/189951, explicitly identifying the same root cause: the Explorer filter misses ancestor `.gitignore` files above the workspace root.
