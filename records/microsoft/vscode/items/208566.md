# Issue #208566 — Support to file issue from the extensions page

[https://github.com/microsoft/vscode/issues/208566](https://github.com/microsoft/vscode/issues/208566)

## Summary

A real gap remains on current main: extension details expose an external Issues link but no action that continues into VS Code's issue reporter with that extension selected. The accepted Backlog request should remain open while the Marketplace-only behavior is decided.

## Change summary

Allow users to start a preselected extension issue report directly from an extension's details editor.

## Best solution

Expose a Report Issue action from extension details that preserves the selected extension and honors its configured issue-reporting destination. Define whether Marketplace-only extensions receive that action or retain only the external Issues link.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts`, `src/vs/workbench/contrib/extensions/common/reportExtensionIssueAction.ts`, `src/vs/workbench/contrib/issue/browser/issueService.ts`
- **Validation:** Open the details editor for an installed extension, invoke the new reporting entry point, and verify the Issue Reporter opens with that extension selected and uses its configured internal or external reporting destination; also verify the agreed behavior on an uninstalled Marketplace extension.
- **Behavior:**

  > An extension's details editor provides a direct way to report an issue for that extension. Invoking it preserves the selected extension in the Issue Reporter and respects an extension's configured external reporting URL. Existing extension management actions and the Resources links remain available. Acceptance must cover installed extensions and the agreed behavior for Marketplace-only extensions.
- **Trace:**

  > The extension header action bar is assembled in src/vs/workbench/contrib/extensions/browser/extensionEditor.ts from `ExtensionAction` implementations in extensionsActions.ts. A reusable `ReportExtensionIssueAction` exists in src/vs/workbench/contrib/extensions/common/reportExtensionIssueAction.ts, but it accepts `IExtensionDescription` and is currently instantiated only by Running Extensions editors. Extension details instead render an external Issues resource from `IExtension.supportUrl`. `WorkbenchIssueService.openReporter` in src/vs/workbench/contrib/issue/browser/issueService.ts currently resolves extension reporting data from installed or loaded extensions, which is where certainty ends for Marketplace-only detail pages. Preserve the existing Help > Report Issue flow and external issue-URL handling; https://github.com/microsoft/vscode/issues/21376 documents that older, separate capability.
- **Open decisions:**
  - Should Report Issue appear only for installed extensions, or also for Marketplace-only extension details?
  - For an uninstalled extension with a support URL, should the action enter VS Code's Issue Reporter or open the extension's external issue destination directly?

## Evidence

- **current extension editor:** src/vs/workbench/contrib/extensions/browser/extensionEditor.ts renders an external "Issues" resource from `extension.supportUrl`, while its header action bar contains install, update, enablement, and management actions but no issue-reporting action.
- **existing partial capability:** src/vs/workbench/contrib/extensions/common/reportExtensionIssueAction.ts already opens `IWorkbenchIssueService.openReporter` with an `extensionId`, but current references are confined to the Running Extensions editors rather than the extension details editor.
- **installed-extension boundary:** src/vs/workbench/contrib/issue/browser/issueService.ts builds reporter extension data from `IExtensionManagementService.getInstalled()` and resolves the legacy reporting path through loaded extensions, so Marketplace-only detail pages require an explicit product decision.
- **older related request:** https://github.com/microsoft/vscode/issues/21376 was closed after Help > Report Issue gained extension selection. That provides a separate entry point but does not satisfy this issue's extension-details-page request, and the closed issue cannot serve as a duplicate canonical.
