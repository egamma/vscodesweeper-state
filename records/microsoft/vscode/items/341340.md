# Issue #341340 — Flaky CLI test: github_environment_waits_for_remote_readiness_and_forwards_bootstrap

[https://github.com/microsoft/vscode/issues/341340](https://github.com/microsoft/vscode/issues/341340)

## Summary

Thanks for the detailed report. The race is still present on main: the fake server in the test prints the ready line and exits immediately, so `child.wait()` can win the `tokio::select!` over the stdout read. The test needs a small fix.

## Change summary

The CLI test github_environment_waits_for_remote_readiness_and_forwards_bootstrap fails intermittently because its fake server exits right after printing the ready line.

## Best solution

Keep the fake server alive after the ready line with `read ignored`, as the sibling tests do, and kill it explicitly with `kill_running_server()` before awaiting the server task. Optionally, make `run_server` treat a ready line that arrives just before process exit as ready.
