# Issue #194886 — Screencast Mode doesn't reflect raw key strokes when input method is enabled

[https://github.com/microsoft/vscode/issues/194886](https://github.com/microsoft/vscode/issues/194886)

## Summary

The defect remains in current main: Screencast Mode explicitly renders IME composition data and suppresses the corresponding keydown events, so it shows composed text instead of the raw keystrokes promised by the keyboard option.

## Change summary

Screencast Mode should display raw physical keystrokes while a macOS CJK input method is composing text.

## Best solution

Make the Screencast Mode keyboard overlay preserve raw-key reporting during IME composition without disrupting composition, Backspace, Enter, or other non-character key handling.

- **Behavior:**

  > With Screencast Mode enabled, typing through a macOS CJK input method must show the raw keys pressed rather than replacing them with the evolving composed string. The editor must continue composing and committing the intended CJK text normally. Backspace, Space, Enter, shortcuts, and non-IME typing must retain their existing overlay behavior.
- **Trace:**

  > ToggleScreencastModeAction in src/vs/workbench/browser/actions/developerActions.ts registers both keydown and composition listeners. Its compositionupdate listener assigns `e.data` to the overlay, while the keydown listener returns before normal key-label rendering when `e.key` is `Process` or a CJK character; this conclusively explains the report on current main. The behavior originated in the IME fixes around commit c55579415ad9a330ec8bf5dc04f50551fab119f5, and there is no dedicated Screencast Mode test covering this path. The boundary is the keyboard-overlay event interpretation: editor IME input behavior and normal keybinding display must not change. Planning should first capture the actual macOS event sequence and establish a repeatable manual or browser-level regression check.
