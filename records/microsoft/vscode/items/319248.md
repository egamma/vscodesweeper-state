# Issue #319248 — Mermaid diagram re-renders on every token during Copilot Chat streaming response

[https://github.com/microsoft/vscode/issues/319248](https://github.com/microsoft/vscode/issues/319248)

## Summary

Still reproduces on main: the mermaid code block rendered via ChatOutputCodeBlockPart is reused across streaming updates (hasSameContent check exists), but doRenderMarkdown clears and rebuilds the DOM on each token, causing the webview element to be removed/reinserted and the mermaid SVG to reinitialize. No fix has landed since the report.

## Change summary

Mermaid diagrams in Copilot Chat streaming responses visibly re-render on every incoming token after the code block is closed, causing continuous flicker until the stream ends.

## Best solution

Add a content-hash short-circuit so that a closed, unchanged mermaid ChatOutputCodeBlockPart is not detached from the DOM during incremental streaming updates. The fix belongs in the doRenderMarkdown / incremental-morpher path in chatMarkdownContentPart.ts — either skip DOM reinsertion for reused output code blocks, or have the IncrementalDOMMorpher preserve stable output-code-block subtrees during morphing. The related issues (https://github.com/microsoft/vscode/issues/316964, https://github.com/microsoft/vscode/issues/316977, https://github.com/microsoft/vscode/issues/317083) cover different mermaid flicker scenarios and remain open.
