# Issue #331517 — Automations should not rename themselves

[https://github.com/microsoft/vscode/issues/331517](https://github.com/microsoft/vscode/issues/331517)

## Summary

Team-authored bug report (benvillalobos, MEMBER) with a detailed self-diagnosis of the automations naming issue but no fix landed yet; hard keep-open rule applies since there's no fix commit referencing this issue.

## Change summary

Automation run names in the Agents Window history view get overwritten by an agent's first-turn chat rename because the view now renders the session's live title instead of the automation's own name.

## Best solution

Implement one of the two short-term options the reporter outlined: have AutomationHistorySection render the automation's own name instead of the session's live title (src/vs/sessions/contrib/sessions/browser/views/automationsView.ts / sessionsList.ts), or propagate an automation marker through ISessionsManagementService into Agent Host session state so AgentHostSessionTitleController.seedTitleFromFirstMessage can suppress renaming for automations.
