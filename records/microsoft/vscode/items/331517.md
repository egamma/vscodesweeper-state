## Summary

Team-authored, freshly filed issue describing a real, unresolved gap in the Automations/Agent Host session-naming flow; the cited files exist as described and no fix has landed yet, so this stays open and routed to the right area.

## Change summary

Automation run names in the history view get overwritten by a later agent-driven chat rename, since the flat session list renders the session's live title rather than the automation's original name.

## Best solution

Implement one of the two short-term options the author outlines in src/vs/sessions/contrib/sessions/browser/views/automationsView.ts (render the automation name in the history row) or plumb an automation marker through ISessionsManagementService into Agent Host session state and check it in AgentHostSessionTitleController.seedTitleFromFirstMessage before the code base migrates automations fully into Agent Host.
