# Issue #318997 — Remote agent sessions started via UI running in the background (detach VSCode)

[https://github.com/microsoft/vscode/issues/318997](https://github.com/microsoft/vscode/issues/318997)

## Summary

Keep this accepted request open: current main has substantial remote Agent Host lifetime support, but that alone does not establish the requested editor-sidebar workflow with native context and tools. It has 23 upvotes, and no verified older canonical or concrete completing commit was found.

## Change summary

Allow agent sessions started from an SSH-connected editor's chat UI to continue remotely after the local window closes and be reattached later.

## Best solution

Build on the existing remote Agent Host infrastructure to provide the requested workflow within the editor, rather than requiring a separate Agents Window or CLI. First establish which parts already work end to end and settle the behavior of client-dependent tools while the editor is disconnected.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHost.contribution.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts`, `src/vs/server/node/serverAgentHostManager.ts`, `src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts`, `src/vs/platform/agentHost/node/sshRemoteAgentHostHelpers.ts`, `src/vs/platform/agentHost/node/agentSideEffects.ts`
- **Validation:** In an SSH-connected editor using a VPN-reachable host, start a long-running agent task from the editor chat sidebar with attached file context, close the local window, and confirm remote progress continues beyond the idle grace period. Reopen the same workspace and verify reattachment to the same conversation with its intervening output and changes. Separately exercise a client-dependent tool and a permission request across disconnect/reconnect against the agreed behavior.
- **Behavior:**

  > The reporter wants to start an agent from the chat sidebar of an existing SSH-connected editor, close the local window, and let the remote work continue without a separate Agents Window or manually launched CLI. Reconnecting should expose the same conversation and the work performed while disconnected. File and editor context available before detaching should remain useful to the session. Acceptance must distinguish autonomous remote work from operations that require a connected editor or user approval.
- **Trace:**

  > The editor's agentHost.contribution.ts already instantiates remote Agent Host integration after restoration, subject to agentHostEnablementService in agentHostChatContribution.ts. ServerAgentHostManager tracks active sessions and holds a server-lifetime token independently of renderer proxy connections. The dedicated SSH path in sshRemoteAgentHostService.ts uses buildAgentHostSpawnCommand from sshRemoteAgentHostHelpers.ts, whose host has independent idle-timeout lifetime. These paths establish substantial infrastructure, not proof that the reporter's existing chat mode, native tools, and context work through detach. AgentSideEffects removes provider active-client contributions when a client leaves, so tool availability and pending interactions are a remaining contract boundary. Preserve existing session identities, permissions, and ordinary attached-editor behavior; universal terminal/task/debug persistence is outside this request and belongs to the younger related https://github.com/microsoft/vscode/issues/320044. The first planning step is to verify the exact editor-sidebar flow before deciding whether any implementation gap remains.
- **Open decisions:**
  - When a detached session needs an editor-only tool, should it wait for reattachment or explicitly report that the capability is unavailable and continue with supported remote tools?
