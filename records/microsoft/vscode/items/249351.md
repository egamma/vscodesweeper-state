[https://github.com/microsoft/vscode/issues/249351](https://github.com/microsoft/vscode/issues/249351)

## Summary

Keep open: current Git integration still overrides the repository's untracked-files configuration, and the linked implementation PR was closed without merging. The request has 28 upvotes and was accepted into Backlog; no verified open duplicate owns the same behavior.

## Change summary

Add an opt-in git.untrackedChanges mode that follows the repository's status.showUntrackedFiles setting.

- **Behavior:**

  > Users can opt into following the current repository's untracked-files configuration instead of duplicating it in VS Code settings. With status.showUntrackedFiles=no, untracked files disappear while tracked modifications remain visible; when untracked files are enabled, the requested presentation matches the working-tree group used by mixed. Existing mixed, separate, and hidden behavior and the default remain unchanged. Acceptance must cover configuration changes followed by refresh, nested untracked paths, staging, and counts, with the agreed inheritance semantics tested explicitly.
- **Trace:**

  > extensions/git/package.json currently exposes only three git.untrackedChanges values. Repository.getStatus in extensions/git/src/repository.ts reads the scoped setting and forwards it to Repository.getStatus in extensions/git/src/git.ts, whose status invocation always forces -uno or -uall. Resource grouping and badge counting in repository.ts, staging and commit logic in commands.ts, and package.json menu conditions also distinguish mixed from the other modes. https://github.com/microsoft/vscode/pull/331149 contains an unmerged implementation lead and a focused regression-test proposal; it is closed, not an active competing PR. The boundary is untracked-file configuration and its existing SCM consumers, not bare-repository discovery or the worktree-path problems in https://github.com/microsoft/vscode/issues/77215. The unresolved product boundary is whether inheritance means Git's effective configuration and native normal/all behavior or only repository-local visibility with mixed's existing file-level enumeration.
- **Open decisions:**
  - Should the new mode follow Git's effective status.showUntrackedFiles configuration, including global values and Git's default when unset, or consult only repository-local configuration?
  - When Git uses normal rather than all, should VS Code preserve Git's directory-level untracked presentation or continue enumerating individual untracked files as mixed does today?
