# Issue #307942 — Contents in extra windows can be rendered out-of-view

[https://github.com/microsoft/vscode/issues/307942](https://github.com/microsoft/vscode/issues/307942)

## Summary

The screenshots and keyboard-focus behavior provide a credible reproduction of an extension-editor layout bug in extra windows. Current source still contains the installed-only layout and clipping conditions that can hide the action row, so this should remain open and route to the extensions area.

## Change summary

Installed extension pages moved to an extra window can clip the Disable, Uninstall, and Settings action row below the visible header until keyboard focus reveals it.

## Best solution

Make the installed-extension header and action row size correctly in auxiliary windows while preserving the current main-window layout, responsive wrapping, and keyboard accessibility.

The report and screenshots confirm the auxiliary-window symptom, but static inspection does not explain the window-specific geometry difference; diagnosis should begin by comparing computed header, details, and action-bar dimensions in the main and auxiliary windows. ## Evidence

- **reported reproduction:** The issue provides exact steps and comparative screenshots from VS Code 1.114.0 on Windows: the installed-extension actions are visible in the main window, clipped in an extra window, and revealed when Tab moves focus to them.
- **source correlation:** src/vs/workbench/contrib/extensions/browser/extensionEditor.ts creates the action bar inside the extension header and applies `list-layout` only when `ExtensionState.Installed`, matching the report's installed-versus-uninstalled distinction.
- **clipping path:** src/vs/workbench/contrib/extensions/browser/media/extensionEditor.css gives both `.extension-editor > .header` and its `.details` child `overflow: hidden`, while the action container can wrap and changes display under `.list-layout`; this provides a direct mechanism for a vertically displaced action row to be clipped.
- **related symptom:** https://github.com/microsoft/vscode/issues/271260 documented the same out-of-view-on-focus symptom in a different auxiliary-window surface, but it was closed because those particular inline-chat buttons were removed; it does not own or resolve the extension-editor defect.
