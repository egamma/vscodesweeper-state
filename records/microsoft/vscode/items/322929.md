# Issue #322929 — Give parallel sessions and agents more prominent visual identity

[https://github.com/microsoft/vscode/issues/322929](https://github.com/microsoft/vscode/issues/322929)

## Summary

Keep this research-backed request open: current main provides subagent details and session status notifications, but these do not establish that parallel agents are consistently distinguishable or that stalls become visible. The existing area labels are appropriate; the remaining work needs a maintainer-led design decision.

## Change summary

Make concurrent sessions and subagents visually attributable, with glanceable activity states and visible failure or stall indications.

## Best solution

Build on the existing session status and subagent presentation surfaces to provide consistent, accessible identity and activity cues across parallel work. Agree on the identity scope and stall semantics before implementation, rather than treating colour coding alone as the solution.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/browser/sessionSubagentsPill.ts`, `src/vs/sessions/browser/sessionStatusIcon.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/browser/sessionsWindowNotifier.ts`
- **Validation:** After choosing the design, exercise two parallel sessions with multiple similarly named subagents, interleaved activity, a confirmation wait, completion and an explicit error. Verify that each output and state is attributable without inspecting logs, that child details are keyboard-accessible, and that identity remains understandable in high-contrast themes and with a screen reader. Exercise the agreed stall threshold and notification settings separately; long-running productive work must not be reported as failed.
- **Behavior:**

  > Users working across concurrent sessions and subagents should be able to identify who produced an output and understand whether work is running, waiting, completed or failed without parsing logs. Identity must remain understandable without relying exclusively on colour, and users should be able to inspect an individual agent's activity. Acceptance should exercise similarly named agents with interleaved activity and independent state transitions. Stall signalling requires an agreed definition that distinguishes lack of observable progress from a confirmed failure.
- **Trace:**

  > ChatSubagentContentPart already extracts agent metadata and builds toolbar context containing activity, confirmations, timing and model information; it opens a child chat when available or exposes inline details otherwise. createSessionSubagentsPillData currently partitions direct subagents using an isActive boolean and a shared agent icon. SessionStatusIcon and the sessions list provide session/chat status presentation, while SessionsWindowNotifier conditionally announces session-level needs-input, completion and error transitions. This establishes partial capability, not a source-confirmed defect or proof that the research goal is satisfied. Preserve provider-neutral Sessions ownership, existing notification preferences and accessible navigation; inactivity must not be equated with failure without a product contract. Coordinate with https://github.com/microsoft/vscode/issues/326533 and https://github.com/microsoft/vscode/issues/325362, which cover related activity and attention design but do not replace this older report.
- **Open decisions:**
  - Should identity distinguish individual session/agent instances, agent roles, or both, and should that identity persist when users reopen a session?
  - Which identity and state cues should remain visible in the parent transcript versus requiring expansion or opening a child chat?
  - What observable condition constitutes a stall, and should it produce an in-product indicator, an OS notification, or both under the existing notification preferences?
