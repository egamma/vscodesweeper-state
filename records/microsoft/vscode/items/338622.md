# Issue #338622 — chat.subagents.useRichRendering is nonfunctional

[https://github.com/microsoft/vscode/issues/338622](https://github.com/microsoft/vscode/issues/338622)

## Summary

Confirmed from source: `chat.subagents.useRichRendering` is not registered as a settings-schema entry anywhere and is never read by `chatSubagentContentPart.ts` — the only reference in the whole repo is a test literally titled 'should use pills for every harness even with the obsolete dropdown preference', which asserts rich pills render unconditionally regardless of the setting's value. The reporter's claim that the setting is nonfunctional is accurate, but whether that's an intentional (rich rendering now always-on) design or an unintentional dead setting/regression needs a maintainer call; the separate complaint about missing subagent reasoning/thinking visibility is plausible but not something I could confirm or refute from source alone.

## Change summary

chat.subagents.useRichRendering has no effect on whether subagents render as rich pills, and subagent reasoning/thinking is reportedly never shown regardless of the setting.

## Best solution

A maintainer should decide whether to formally deprecate/remove the now-inert `useRichRendering` setting (rich pills are unconditional per the current test suite) and separately verify whether subagent reasoning/thinking is actually surfaced anywhere (e.g. via the pill's expanded view or 'open chat' action) for Auto/BYOK models — if not, that's the real gap to track.
