# Issue #321240 — Support `file://` URLs in the integrated browser in remote workspaces

[https://github.com/microsoft/vscode/issues/321240](https://github.com/microsoft/vscode/issues/321240)

## Summary

Keep open: current source still limits HTML editor associations to local files and explicitly reports that file URLs bypass the remote connection. This is accepted Backlog work, deliberately separated from the completed remote HTTP/HTTPS support.

## Change summary

Allow HTML files in remote workspaces, including WSL, to open directly in the integrated browser.

## Best solution

Provide remote HTML preview through the integrated browser, including editor associations and relative page resources, while preserving local-file behavior and workspace trust boundaries. Plan the remote resource-loading contract before implementation.

- **Reason:** Making an existing editor capability work consistently in remote workspaces advances remote development and uniform UI interactions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/browserView.contribution.ts`, `src/vs/workbench/contrib/browserView/electron-browser/features/browserTabManagementFeatures.ts`, `src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts`, `src/vs/workbench/contrib/browserView/electron-browser/features/browserRemoteFeatures.ts`, `src/vs/platform/browserView/electron-main/browserSession.ts`, `src/vs/platform/browserView/electron-main/browserSessionRemote.ts`
- **Validation:** In trusted Remote SSH and WSL workspaces, open an HTML file through Open With and an editor association; verify that the document and relative CSS, JavaScript, and image resources come from the remote workspace. Check the agreed address-bar file-URL behavior, unchanged local preview, and enforcement of the agreed remote trust boundary. These checks were not executed during this read-only review.
- **Behavior:**

  > Users should be able to preview an HTML file stored in a remote workspace directly in the integrated browser, including through editor associations. Relative page resources should resolve against that remote document rather than an identically named local path. Acceptance should cover Remote SSH and WSL, preserve local previews, and maintain workspace trust restrictions. The meaning of manually entered file URLs in a remote window must be agreed before implementation.
- **Trace:**

  > BrowserEditorResolverContribution and OpenFileInIntegratedBrowserAction currently accept only Schemas.file resources. BrowserSession.configure resolves file requests through local paths, while BrowserSessionRemote applies an Electron network proxy rather than a remote filesystem provider. BrowserViewWorkbenchService._getTrustedFileRoots also collects only local file roots; enabling remote editor associations alone would therefore not deliver remote preview. The maintainer explicitly split this work from remote HTTP/HTTPS support at https://github.com/microsoft/vscode/issues/293229#issuecomment-4696518638. Preserve existing local-file behavior and trust enforcement; the trace has not established a remote document/subresource transport or its complete consumer set.
- **Open decisions:**
  - In a remote workspace, should manually entered file:// URLs refer to the remote filesystem or retain their current local meaning, with remote document previews represented separately?
