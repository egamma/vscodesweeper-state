# Issue #242568 — Support outline for multi-file diff editors

[https://github.com/microsoft/vscode/issues/242568](https://github.com/microsoft/vscode/issues/242568)

## Summary

Keep open: current Outline integration exposes symbols from the active inner diff, not a list of all files in the multi-diff editor. The linked search-editor bugs concern a different behavior, and the related mobile-navigation request is newer than this re-reviewed issue.

## Change summary

Provide an outline listing the files contained in a multi-file diff editor.

## Best solution

Expose the multi-diff editor's file collection through the existing Outline navigation surface, allowing users to reveal a selected file without leaving the multi-diff editor. Settle whether file entries replace or organize the active file's symbol outline before implementation.

- **Reason:** Reusing the Outline surface for changeset navigation supports consistent navigation and focused code review without introducing a separate permanent view.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditor.contribution.ts`, `src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditor.ts`, `src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts`, `src/vs/workbench/services/outline/browser/outline.ts`, `src/vs/workbench/services/outline/browser/outlineService.ts`
- **Validation:** Add a targeted Outline integration test with a multi-diff input containing several files: verify the file entries, select a non-active file and assert that the same multi-diff editor reveals it, then update the resource collection and assert that entries refresh. Manually verify keyboard navigation and the agreed symbol-outline behavior.
- **Behavior:**

  > An active multi-file diff editor should offer an Outline listing its constituent files, so users can locate a file without scrolling through every diff. Selecting a file should reveal its diff while retaining the multi-diff editor. Acceptance should cover multiple files, collapsed diffs, changing file collections and keyboard navigation. The relationship between file entries and the existing symbol outline must be agreed before implementation.
- **Trace:**

  > MultiDiffEditor.getControl in src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditor.ts returns the active DiffEditorWidget. DocumentSymbolsOutlineCreator in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts therefore builds symbols from that diff's modified editor, not from the whole collection. MultiDiffEditorInput in src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts exposes observable resources, and MultiDiffEditor._applyOptions already supports revealing a resource within the editor. OutlineService selects the first matching creator; the IOutline contract also includes tree, quick-pick and breadcrumbs data sources, so their intended behavior needs consideration. Preserve ordinary text/diff outlines, individual-file opening and existing change navigation. The search-editor failures at https://github.com/microsoft/vscode/issues/234803 and https://github.com/microsoft/vscode/issues/154348 are separate; https://github.com/microsoft/vscode/issues/268226 supplies related narrow-screen navigation requirements.
- **Open decisions:**
  - Should Outline show only files for a multi-diff editor, or retain document symbols nested beneath file entries?
  - Should the file collection also appear in breadcrumbs and outline quick-pick navigation, or is this request limited to the Outline pane?
