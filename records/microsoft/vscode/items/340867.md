# Issue #340867 — Copilot chat selects an unexpected primary project in a multi-root workspace

[https://github.com/microsoft/vscode/issues/340867](https://github.com/microsoft/vscode/issues/340867)

## Summary

Keep open as a request for clearer session-project control: current folder selection is intentionally separate from active-file context, and existing pickers do not fully cover the requested inspect, override, or disable workflow. The related multi-root tracking issue informs the design but does not establish that this report's full scope is already owned.

## Change summary

Make Copilot session project selection explicit and predictable in multi-root workspaces, preserve sibling-folder access, and retain a reliable non-editing inquiry workflow.

## Best solution

Define a discoverable session-project contract that distinguishes the process working directory from active-file context and accessible workspace roots. Coordinate with the existing multi-root work, while assessing the Ask/Plan concern separately for the reporter's selected harness.

- **Trace:**

  > SessionOptionGroupBuilder provides an explicit Folder selector but can fall back to the first repository option rather than the active file. These source paths establish existing semantics, not which harness produced the reporter's observation. https://github.com/microsoft/vscode/issues/321651 documents intentional first-root selection and ongoing multi-root work, so coordinate with that design rather than treating active-file context as proof of a broken contract. - **Open decisions:**
