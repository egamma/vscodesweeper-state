# Issue #47770 — Select editor text via touch

[https://github.com/microsoft/vscode/issues/47770](https://github.com/microsoft/vscode/issues/47770)

## Summary

Finger-driven text selection remains a meaningful gap: current touch handlers scroll rather than select, and the merged stylus support does not satisfy this request. Keep this supported Backlog item open; the verified related reports are newer and do not provide an eligible canonical for this re-review.

## Change summary

Allow finger dragging on editor text to select it while dragging on empty editor space scrolls.

## Best solution

Provide a coherent finger-selection interaction in the editor input layer while retaining reliable touch scrolling and existing pen and mouse behavior. Agree on the selection-versus-scroll gesture contract before implementation, using this issue as the established request rather than folding it into a newer platform-specific report.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/pointerHandler.ts`, `src/vs/base/browser/touch.ts`
- **Validation:** After agreeing on the gesture contract, check on a Windows touchscreen that finger input can select a chosen range in the main editor without WSL or an auxiliary window, while the designated scroll gesture still scrolls without changing selection. Repeat in an auxiliary editor window and an iPad browser; verify mouse dragging and pen selection remain unchanged. Add targeted input-handler tests for selection-versus-scroll dispatch under the agreed gestures.
- **Behavior:**

  > Users should be able to select an arbitrary editor text range using a finger without requiring a keyboard, pen, remote connection, or detached editor window. The reporter requests dragging on text to select and dragging on empty editor space to scroll. Acceptance must cover both selection and scrolling in the ordinary editor, with existing mouse and pen interactions preserved. Alternative gesture proposals in the discussion require a product decision rather than silently replacing the requested behavior.
- **Trace:**

  > In src/vs/editor/browser/controller/pointerHandler.ts, PointerHandler chooses PointerEventHandler on supported mobile platforms, TouchHandler when TouchEvent is available, and otherwise MouseHandler. PointerEventHandler.onChange distinguishes touch scrolling from pen selection, while TouchHandler.onChange always scrolls; neither touch path implements the requested text-versus-empty-space distinction. Gesture.onTouchMove in src/vs/base/browser/touch.ts emits change events carrying initialTarget, coordinates, and movement deltas, and the shared gesture layer also provides scrolling inertia. https://github.com/microsoft/vscode/pull/198578 improves pen selection only, not finger selection. The latest auxiliary-window workaround at https://github.com/microsoft/vscode/issues/47770#issuecomment-5383244455 is evidence of inconsistent behavior, not a verified general solution. Preserve unrelated gesture consumers, normal mouse selection, pen support, and touch scrolling; broader sidebar and context-menu requests in the comments are outside the central editor-selection scope. Source inspection establishes the missing capability, but device behavior was not executed.
- **Open decisions:**
  - Should finger selection use the reporter's text-versus-empty-space drag rule, or a distinct selection gesture such as long-press-and-drag with ordinary dragging reserved for scrolling?

## Evidence

- **Current input behavior:** In src/vs/editor/browser/controller/pointerHandler.ts, PointerEventHandler.onChange scrolls for pointer type 'touch' and dispatches selection gestures only for 'pen'; _onMouseDown skips touch input. TouchHandler.onChange also scrolls unconditionally, without distinguishing text from empty space. These paths do not implement the requested finger-drag selection.
- **Existing-capability check:** Inspection of src/vs/editor/common/config/editorOptions.ts and editor selection commands found no touch-selection mode delivering the requested interaction. Smart selection in src/vs/editor/contrib/smartSelect/browser/smartSelect.ts expands semantic ranges, but does not provide arbitrary finger-drag selection; commenters already identify Expand Selection as an awkward workaround.
- **Merged PR is partial coverage:** https://github.com/microsoft/vscode/pull/198578 is merged. Its diff adds _dispatchGesture(event, true) for pen movement while retaining scrolling for touch movement, and its description explicitly distinguishes pen support from future touch-only selection. It therefore does not complete this issue.
- **Recent workaround is not full coverage:** https://github.com/microsoft/vscode/issues/47770#issuecomment-5383244455 reports selection in VS Code 1.134.0 only after connecting to WSL and tearing an editor into another window, with scrolling and empty-space inconsistencies. This does not satisfy intuitive selection in the ordinary editor window.
