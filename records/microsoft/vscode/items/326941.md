# Issue #326941 — Chat: a fallback/automatic model (Auto) is persisted into session/draft input-state as if user-selected

[https://github.com/microsoft/vscode/issues/326941](https://github.com/microsoft/vscode/issues/326941)

## Summary

The bug is confirmed on current main: `_syncInputStateToModel()` unconditionally persists the current model into session and draft stores with no gate on whether the selection was user-initiated or a fallback. The existing `_userExplicitlySelectedModel` flag and `isUserAction` parameter are not consulted by this write path. Team-authored, no fixing commit referencing this issue — keeping open.

## Change summary

A fallback/automatic model (e.g. Auto) is persisted into session input-state and empty-session draft mementos as if it were the user's explicit selection, because `_syncInputStateToModel` has no provisional/user-action gate.

## Best solution

Gate the `selectedModel` written by `_syncInputStateToModel` on whether the current model is provisional — use the existing `_userExplicitlySelectedModel` flag or `_provisionalModelId` / `selectionReason` from `ChatModelSelectionModel` to either skip writing the model field when it's a fallback, or flag it as non-authoritative in the persisted state. The fix belongs in `chatInputPart.ts` around line 1765 (the `getCurrentInputState()` → `setState` path).
