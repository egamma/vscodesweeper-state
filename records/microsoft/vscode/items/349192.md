# Issue #349192 — Chat: choose a preferred default model from the model picker

[https://github.com/microsoft/vscode/issues/349192](https://github.com/microsoft/vscode/issues/349192)

## Summary

Keep open: chat.defaultModel already provides an explicit starting preference, but the inspected model picker does not expose setting or clearing that preference globally or per repository. The related requests overlap with default selection, without establishing a canonical that covers this picker-specific experience.

## Change summary

Expose global and repository-scoped preferred defaults in the model picker without changing them when selecting a model for one conversation.

## Best solution

Provide discoverable set-and-clear preference controls in the existing model picker, preserving conversation choices, custom-agent overrides, and managed defaults. Decide whether these preferences remain VS Code-specific or intentionally share configuration with the CLI.

- **Validation:** Verify that a global preference seeds new conversations, a repository preference takes precedence only there, a one-conversation switch does not rewrite either preference, and clearing preferences restores fallback behavior. Cover custom-agent and managed-default precedence alongside the existing chatInputModelSelectionController tests.
- **Behavior:**

  > Users can explicitly set or clear a preferred starting model from the model picker globally or for the current repository. Repository preferences override global preferences, while ordinary model selections affect only their conversation. With no preference, existing fallback behavior remains unchanged. Custom-agent model overrides and organization-managed defaults retain their established precedence.
- **Trace:**

  > chat.defaultModel is already registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. ChatInputModelSelectionController.configuredDefaultToSeed distinguishes starting defaults from choices made within a conversation, and _configuredModel prioritizes managed defaults. TabbedModelPicker._applyModelSelection currently delegates a conversation selection through context.onSelect; its inspected context and actions contain no scoped preference-editing operation. Related requests are https://github.com/microsoft/vscode/issues/320715 and https://github.com/microsoft/vscode/issues/340300, but neither retrieved body establishes a duplicate covering the picker experience. The unresolved boundary is whether preference edits also change CLI defaults; the CLI configuration integration itself was not traced. Preserve existing conversation-selection and policy semantics rather than treating a preferred default as a model lock.
- **Open decisions:**
  - Should setting or clearing a preference in VS Code also change the CLI's defaults through shared Copilot configuration, or should the preference remain VS Code-specific?
