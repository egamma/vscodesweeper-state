# Issue #75627 — Extensions using the "type" command (for ex. Vim) have poor performance due to being single-threaded with other extensions

[https://github.com/microsoft/vscode/issues/75627](https://github.com/microsoft/vscode/issues/75627)

## Summary

Still a valid, high-demand feature request (272 upvotes). VS Code added `extensions.experimental.affinity` as a user-configurable mitigation and a proposed `extensionAffinity` API for extension authors, but the core ask — automatic isolation or prioritization for type-handling extensions — remains unimplemented. The issue serves as the canonical tracker (issue #291394 was closed as a duplicate of this one).

## Change summary

Extensions using the `type` command (e.g. Vim) share the extension host event loop with all other extensions, causing input lag when any extension blocks the thread.

## Best solution

Finalize the `extensionAffinity` proposed API and consider automatic isolation for extensions that override the `type` command, so keystroke-handling extensions run in a dedicated extension host without requiring user configuration. The existing `extensions.experimental.affinity` setting is a useful interim workaround but places the burden on users.
