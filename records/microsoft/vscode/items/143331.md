# Issue #143331 — [Test UX]: testing time is confusing when running in parallel

[https://github.com/microsoft/vscode/issues/143331](https://github.com/microsoft/vscode/issues/143331)

## Summary

Keep open under the existing under-discussion and testing labels: suite durations still sum child durations, so parallel execution can display substantially more than elapsed time. The thread leaves the preferred timing semantics unresolved, and no verified older canonical was found.

## Change summary

Make suite and file timings meaningful for parallel tests rather than displaying an unexplained sum of individual test durations.

## Best solution

Agree on the meaning of aggregate timings in the Testing view, distinguishing accumulated test duration from elapsed execution time. If interval-based timing is chosen, establish the reporting contract needed to calculate it accurately rather than inferring parallelism from duration values alone.
