# Issue #231968 — Should be able to type in account type

[https://github.com/microsoft/vscode/issues/231968](https://github.com/microsoft/vscode/issues/231968)

## Summary

Keep open: the account pickers still do not turn a typed account name into a sign-in request. A maintainer supported the improvement but identified an unresolved provider API contract; this team-authored Backlog item needs that decision, not a decline close.

## Change summary

Allow users to enter an account name in the authentication quick pick and sign in with that account.

## Best solution

Support typed account names in the authentication account-selection flow while preserving existing-account selection. Establish how a name-only sign-in hint is represented for authentication providers without pretending it is an account with a known unique ID.

## Plan brief

- **Likely files:** `src/vs/workbench/services/authentication/browser/authenticationExtensionsService.ts`, `src/vs/workbench/contrib/authentication/browser/actions/manageAccountPreferencesForExtensionAction.ts`, `src/vs/workbench/services/authentication/common/authentication.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** Exercise the account picker with two existing accounts: enter a previously unseen account name and confirm the provider receives the agreed name-only sign-in representation; complete authentication and verify the returned account becomes the preference. Repeat existing-account selection and cancellation, and use a test provider that relies on account.id to check compatibility. These are proposed acceptance checks, not checks executed during this read-only review.
- **Behavior:**

  > Users can enter the name of an account they want to authenticate with in the account quick pick, rather than having that input only filter existing choices. Accepting a new name should initiate authentication with that account intent, and successful authentication should use the provider-returned account identity. Existing-account selection, cancellation, and preference updates must retain their behavior. Acceptance must include a provider that uses account IDs, not only GitHub and Microsoft.
- **Trace:**

  > AuthenticationExtensionsService.selectSession in src/vs/workbench/services/authentication/browser/authenticationExtensionsService.ts constructs existing-account rows and a generic new-account row; its acceptance path forwards the selected row's account, never the typed value. ManageAccountPreferenceForExtensionActionImpl in src/vs/workbench/contrib/authentication/browser/actions/manageAccountPreferencesForExtensionAction.ts similarly accepts selected items and creates a new session without a typed account hint. The public account structure in src/vscode-dts/vscode.d.ts requires a unique id as well as a label. The maintainer explicitly identified this compatibility question at https://github.com/microsoft/vscode/issues/231968#issuecomment-2433562531. The uncertainty is how a provider should receive a name when no authoritative account ID exists; preserve provider-issued identities and existing account-selection semantics.
- **Open decisions:**
  - What provider-facing contract should represent a typed account name without a known account ID: a distinct name-only sign-in hint, or an explicitly documented account representation supported by providers?

## Evidence

This supports further design rather than declining the request.
- **Existing capability does not cover typed sign-in:** In src/vs/workbench/services/authentication/browser/authenticationExtensionsService.ts, selectSession builds rows for existing accounts and 'Sign in to another account'. Its acceptance handler passes the selected row's account to createSession; it does not use the quick pick's typed value to identify a new account.
- **Account-preference command remains selection-only:** src/vs/workbench/contrib/authentication/browser/actions/manageAccountPreferencesForExtensionAction.ts registers _manageAccountPreferencesForExtension. _createQuickPick accepts selectedItems, and _accept starts new-account authentication without an account hint. 'Use a new account...' is a workaround for initiating sign-in, not coverage of entering the desired account name directly.
- **Public contract remains relevant:** src/vscode-dts/vscode.d.ts still requires both id and label on AuthenticationSessionAccountInformation. AuthenticationProviderSessionOptions.account represents the account being requested, so treating arbitrary typed text as an identified account requires a compatibility decision.
