# Issue #201884 — TabInputWebview viewType comment is inaccurate/unclear or there is a bug in viewType

[https://github.com/microsoft/vscode/issues/201884](https://github.com/microsoft/vscode/issues/201884)

## Summary

Still reproduces on main: `TabInputWebview.viewType` exposes the internal `mainThreadWebview-` prefix, contradicting the documented contract that it maps to `WebviewPanel.viewType`. The related docs-only PR #312590 was closed without merging; the runtime fix (stripping the prefix) is still needed.

## Change summary

`TabInputWebview.viewType` returns a value prefixed with `mainThreadWebview-` instead of the bare `WebviewPanel.viewType` string, breaking extensions that compare the two.

## Best solution

Strip the `mainThreadWebview-` prefix in `mainThreadEditorTabs.ts` when building the `WebviewEditorInput` DTO (line ~165), so `TabInputWebview.viewType` matches `WebviewPanel.viewType` as documented. This is a behavioral fix — a docs-only approach was already rejected (PR #312590 closed). Needs care: extensions relying on the prefixed form today could break, so a release note may be warranted.
