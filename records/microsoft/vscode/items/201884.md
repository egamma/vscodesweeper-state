[https://github.com/microsoft/vscode/issues/201884](https://github.com/microsoft/vscode/issues/201884)

## Summary

The tab API still exposes the internal mainThreadWebview- prefix instead of the documented panel viewType. The documentation-only PR was closed without merging, with maintainer direction to fix the runtime behavior instead.

## Change summary

Make TabInputWebview.viewType match WebviewPanel.viewType without leaking the internal main-thread prefix.

## Best solution

Honor the existing public API contract when exposing webview tab inputs, while preserving internal editor identifiers, serializer matching, and custom-editor behavior. The maintainer has already settled the runtime-versus-documentation question.
