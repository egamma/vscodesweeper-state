# Issue #172349 — Tabs do not align to tab stops when emoji are used

[https://github.com/microsoft/vscode/issues/172349](https://github.com/microsoft/vscode/issues/172349)

## Summary

The alignment bug remains relevant on current main: tab width is calculated from UTF-16 code-unit columns rather than the emoji glyph's rendered width. A maintainer later confirmed the behavior and identified unresolved DOM/GPU renderer consistency concerns.

## Change summary

Tabs following emoji can end before the visual tab stop, leaving subsequent text misaligned with neighboring lines.

## Best solution

Make tab-stop placement account for the rendered width of emoji graphemes while keeping DOM and GPU rendering consistent. The existing full-width-character option does not cover supplementary emoji, so maintainers should first decide whether this becomes default behavior or an opt-in grid-width mode.

## Evidence

- **confirmed reproduction:** The issue includes deterministic text and screenshot evidence, and a VS Code maintainer later stated that they had also encountered the emoji/CJK alignment behavior in https://github.com/microsoft/vscode/issues/221145#issuecomment-2604683455.
- **current source:** src/vs/editor/common/viewLayout/viewLineRenderer.ts computes each tab from `visibleColumn`, while ordinary UTF-16 code units each increment that column by one; the surrogate pair for 👋 is therefore counted independently of the glyph's actual pixel width.
- **existing option gap:** The `editor.fullwidthCharacterWidth` option in src/vs/editor/common/config/editorOptions.ts only forces classified full-width characters into two cells, while tests in src/vs/editor/test/common/viewLayout/viewLineRenderer.test.ts explicitly leave supplementary and emoji sequences intact.
- **renderer constraint:** Discussion in https://github.com/microsoft/vscode/issues/221145#issuecomment-2604683455 notes that forcing emoji to the grid is easier in the GPU renderer but could look inconsistent when lines fall back to DOM rendering.
- **canonical search:** The related open issue https://github.com/microsoft/vscode/issues/221145 tracks the broader WebGPU renderer project and references this defect, but it does not own or replace the specific remaining tab-alignment work.
