# Issue #195539 — Allow to disable atomic writes for user data

[https://github.com/microsoft/vscode/issues/195539](https://github.com/microsoft/vscode/issues/195539)

## Summary

Keep open: current source preserves settings files that are themselves symlinks, but still enforces atomic replacement for ordinary user-data files without a user-facing opt-out. The remaining hard-link/inode-preservation request was explicitly accepted by maintainers and is not covered by the linked symlink fix.

## Change summary

Allow users to disable atomic writes for user data so saving settings and keybindings can preserve hard links and file identity.

## Best solution

Provide an explicit opt-out for user-data atomic writes while retaining atomic writes by default and explaining the reduced protection against interrupted saves. Settle the control's application-versus-profile scope before implementation; following symlink targets atomically is separate work and does not preserve hard links.
