# Issue #195539 — Allow to disable atomic writes for user data

[https://github.com/microsoft/vscode/issues/195539](https://github.com/microsoft/vscode/issues/195539)

## Summary

Keep open: current main still unconditionally enables atomic writes for key user-data files, and the existing symlink safeguard does not cover reverse symlinks or hard links.

## Change summary

Provide an opt-out from atomic writes for user settings, keybindings, tasks, and extension metadata so inode-based links can be preserved.

## Best solution

Retain atomic writes as the data-safe default, but provide a clearly documented opt-out for users who accept the corruption risk and need inode-preserving writes. The implementation belongs around `FileUserDataProvider.enforceAtomicWriteFile`, with coverage for hard links and reverse-symlink workflows.
