# Issue #343309 — Agent Host BYOK Responses bridge mints rs_byok_* reasoning IDs for items that carry upstream encrypted_content, causing 400 "item_id did not match" on replay

[https://github.com/microsoft/vscode/issues/343309](https://github.com/microsoft/vscode/issues/343309)

## Summary

Keep open: current source can pair a newly minted reasoning ID with unchanged provider ciphertext, supporting the reported replay failure. The linked open PR is an implementation candidate, not evidence that the issue is resolved.

## Change summary

Prevent the Agent Host BYOK Responses bridge from replaying provider reasoning ciphertext under a replacement item ID.

## Best solution

Review and, if correct, land https://github.com/microsoft/vscode/pull/343310 so provider ciphertext retains its original item identity or is omitted when that identity cannot be preserved. Preserve the existing synthetic reasoning-metadata behavior and verify both streaming and non-streaming output.

That synthetic metadata case is distinct from opaque provider ciphertext and must remain supported.
