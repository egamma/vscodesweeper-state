# Issue #343309 — Agent Host BYOK Responses bridge mints rs_byok_* reasoning IDs for items that carry upstream encrypted_content, causing 400 "item_id did not match" on replay

[https://github.com/microsoft/vscode/issues/343309](https://github.com/microsoft/vscode/issues/343309)

## Summary

The bridge still pairs newly minted reasoning IDs with unchanged provider ciphertext on current main. Keep this open while the existing fix candidate is reviewed; its presence is not evidence that the fix has landed.

## Change summary

Prevent BYOK reasoning-history replay failures caused by replacing the reasoning item ID without removing its ID-bound provider ciphertext.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/343310 so translated reasoning items preserve valid upstream ID/ciphertext pairs and never attach provider ciphertext to replacement IDs, while retaining local reasoning-metadata compatibility.

Its publicly readable review describes changes to the exact translation path and a regression test preventing minted IDs from retaining provider ciphertext. This is an existing implementation candidate, not a merged fix or duplicate canonical.
- **Compatibility boundary:** src/vs/platform/agentHost/test/node/byokResponsesTranslation.test.ts:306-349 explicitly expects a minted rs_byok_* ID to retain the local vscode-reasoning-metadata: marker. That compatibility case differs from opaque provider ciphertext and must remain supported.
