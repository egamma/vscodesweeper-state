# Issue #330305 — Automations: run stays in 'running' state when runner is interrupted by app shutdown

[https://github.com/microsoft/vscode/issues/330305](https://github.com/microsoft/vscode/issues/330305)

## Summary

Team-authored bug report (benvillalobos, MEMBER) filed 0 days ago with no fix commit yet, so per the hard keep-open rules for team-authored items this stays open regardless of how plausible the analysis is; the described race is consistent with the current code but there's an existing stale-run-recovery mechanism that may already cover part of the scenario, so the exact remaining gap needs confirmation.

## Change summary

When an automation run's runner is disposed or interrupted (e.g. app shutdown) before reaching a terminal state, the run row can stay stuck at 'running' forever instead of transitioning to 'failed'.

## Best solution

Confirm whether AutomationScheduler's existing dispose()/_runCts.cancel() path and startStaleRunRecovery (providerAutomationService.ts) already close this gap for most shutdown cases, then add a finally/dispose guard in AutomationRunner._runOnceInner (or _runOnce) so any run claimed via recordRunStart is unconditionally finalized to 'failed' if the runner exits without reaching a terminal update — this is the fix the reporter already sketched.
