# Issue #338171 — The tab icon is missing if the filename is 'git', regardless of its extension.

[https://github.com/microsoft/vscode/issues/338171](https://github.com/microsoft/vscode/issues/338171)

## Summary

Confirmed real bug: a maintainer traced it to the connected-tab width-compression calculation, and current main still has the flaw — for very short filenames the ellipsized-first-grapheme estimate exceeds the actual full-name width, so the tab is wrongly marked narrow and hides the icon. No fix has landed yet.

## Change summary

In the (modernUI) connected tabs layout, very short filenames like 'git.sh' lose their file-type icon because the tab is incorrectly classified as too narrow.

## Best solution

Fix layoutConnectedTabLabels() in multiEditorTabsControl.ts so the minimum-width estimate never exceeds the actual rendered width of the full name for short names — e.g. cap the ellipsis-based estimate at the true full-name width before comparing to tab.offsetWidth.

- **Behavior:**

  > In connected/compressed tab mode, a tab for a short filename (e.g. 'git.sh', 'it.sh', 'iii.sh') must not be marked as too narrow to show its file-type icon, as long as its actual rendered width is enough to fit the full un-ellipsized name. Longer names that are genuinely too narrow (e.g. because the tab has shrunk below the full name's width) should still show the ellipsis and hide the icon as today. Acceptance: a new regression test opening 'git.sh' at a width that comfortably fits the full name shows the icon (no 'connected-tab-narrow' class), and existing connected-tab width/compression tests continue to pass.
- **Trace:**

  > layoutConnectedTabLabels() in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts (~lines 2120-2158) computes minimumNameWidth from only the first grapheme of the name plus a rendered ellipsis glyph (via measureConnectedTabText), then flags a tab narrow when tab.offsetWidth < minimum + 22. For very short names the ellipsized first-grapheme-plus-ellipsis string can render wider than the actual full name, so the estimate overshoots and the tab is wrongly flagged narrow, triggering the CSS in connectedEditorTabs.css (lines 455-457) that hides the icon. This was introduced by the connected-tab compression work in PR #335605 (https://github.com/microsoft/vscode/pull/335605) and is still present on main as of commit 4fbdaab4a53c8de8b80aaa740ef4cbb16defccf7. Boundary: do not change the overall narrow/compression strategy for genuinely long names or the badge/suffix measurement logic — only correct the case where the ellipsis-based estimate can exceed the true full-name width for short names.
