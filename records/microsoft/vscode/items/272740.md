# Issue #272740 — [folding] [json] Show number of collapsed array/object items

[https://github.com/microsoft/vscode/issues/272740](https://github.com/microsoft/vscode/issues/272740)

## Summary

This remains a valid, well-supported feature request: 28 community upvotes qualify it for the Backlog, and the cited earlier reports are closed, so neither can serve as a duplicate canonical. The existing folding-count request concerns folded lines rather than JSON array items or object properties.

## Change summary

Show the number of contained array items or object properties in the placeholder for a collapsed JSON range.

## Best solution

Extend editor folding placeholders through the JSON language contribution so collapsed JSON arrays and objects can display a computed item or property count, while preserving the generic folding presentation for other languages. A maintainer should first decide whether this belongs in JSON-specific folding metadata or a general custom-placeholder contract.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingDecorations.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add folding tests for collapsed JSON arrays and objects that verify the placeholder reports the correct immediate item/property count, including empty and nested containers, while non-JSON folding placeholders remain unchanged.
- **Behavior:**

  > When a JSON array or object is collapsed, its visible folding placeholder should communicate the number of immediate array items or object properties it contains. Empty, nested, and multiline containers need defined, consistent output, and expanding the range must restore the document without changing its text. Folding presentation for languages that do not provide semantic counts must remain unchanged.
- **Trace:**

  > The request spans generic editor folding presentation under src/vs/editor/contrib/folding/browser and JSON-specific language support under extensions/json-language-features. Existing generic folded-range behavior can count lines, but the requested value is semantic: immediate array elements or object members, which requires JSON structure awareness rather than deriving a count from line ranges. The older open request https://github.com/microsoft/vscode/issues/130250 covers folded-line counts, not this observable behavior; the two reporter-linked predecessors are closed. Keep the scope to collapsed JSON container placeholders and do not redefine generic line-fold counts or document text.
- **Open decisions:**
  - Should the displayed count include only immediate array elements/object properties, or all recursively nested values?
  - Should semantic placeholder text be supplied by the JSON folding provider through a general folding contract, or should the editor derive it only for JSON?
  - What exact placeholder should be shown for empty containers and singular versus plural counts?
