# Issue #19847 — Explore using formatters for indentation adjustment when formatters are available

[https://github.com/microsoft/vscode/issues/19847](https://github.com/microsoft/vscode/issues/19847)

## Summary

Keep this exploration open: current reindent commands still use language indentation rules, not registered formatters. Selection-only reindentation now exists, but the central formatter-backed, indentation-only capability remains missing and needs a provider-contract decision.

## Change summary

Explore using registered formatters to adjust leading indentation without applying unrelated formatting changes.

## Best solution

Establish an indentation-only provider contract and fallback behavior that preserve non-leading whitespace and remain useful for incomplete selections. Coordinate that design with https://github.com/microsoft/vscode/issues/34621 without closing this older exploration into the newer API-unification request.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/indentation/browser/indentation.ts`, `src/vs/editor/contrib/indentation/common/indentation.ts`, `src/vs/editor/common/languages.ts`, `src/vs/editor/contrib/format/browser/formatActions.ts`, `src/vs/editor/contrib/indentation/test/browser/indentation.test.ts`
- **Validation:** After the contract is agreed, add targeted indentation tests using controlled providers: formatter-backed indentation changes only leading whitespace, preserves internal alignment, respects the agreed selection boundary, and follows the agreed fallback when a provider cannot handle incomplete syntax. Run those tests through scripts/test.sh with the relevant test-file selector; include a provider-call-count check to prevent per-line whole-document formatting.
- **Behavior:**

  > Users should be able to obtain language-aware indentation without accepting unrelated formatting changes. Deliberate alignment and all content after leading indentation must remain unchanged. Whole-document and selected-line behavior must have explicit boundaries, and incomplete selections must retain a usable, defined fallback. Acceptance checks should cover a registered formatter, missing indentation rules, a formatter that declines incomplete syntax, and preservation of internal whitespace.
- **Trace:**

  > ReindentLinesAction and ReindentSelectedLinesAction in src/vs/editor/contrib/indentation/browser/indentation.ts both call getReindentEditOperations in src/vs/editor/contrib/indentation/common/indentation.ts. That helper depends exclusively on language indentation rules and returns no edits when those rules are missing. Formatting remains a separate path in src/vs/editor/contrib/format/browser/formatActions.ts; the provider contracts in src/vs/editor/common/languages.ts offer no indentation-only mode and permit range expansion. This establishes the gap without executing the editor. The discussion documents both unreliable whitespace-only formatting and formatters that require parseable selections, so replacing reindentation with ordinary formatting would not satisfy the request. Preserve existing formatting commands and non-leading whitespace; coordinate the contract discussion with https://github.com/microsoft/vscode/issues/34621. Uncertainty begins at the public provider contract and when formatter-backed behavior should take precedence over existing indentation rules.
- **Open decisions:**
  - Should indentation-only support be an explicit provider capability, or should existing formatting providers participate without opting into a new contract?
  - Should formatter-backed indentation take precedence whenever supported, or only when language indentation rules are unavailable?
  - What selection-boundary and fallback guarantees should apply when a formatter expands the requested range or cannot process incomplete syntax?
