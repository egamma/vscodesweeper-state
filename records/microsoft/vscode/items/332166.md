# Issue #332166 — Allow renaming or moving a project folder while persisting history for Copilot chats (re-file of #313970)

[https://github.com/microsoft/vscode/issues/332166](https://github.com/microsoft/vscode/issues/332166)

## Summary

A real gap remains: current chat persistence is keyed to workspace identity, and its migration path only handles an in-process workspace transition, not a folder moved or renamed outside VS Code. The younger cross-workspace request overlaps but cannot serve as the canonical duplicate for this re-reviewed, older issue.

## Change summary

Preserve and recover Copilot chat sessions when a project folder changes path, and provide supported global or portable history semantics.

## Best solution

Decouple chat-session ownership from an absolute workspace-storage identifier by retaining durable project-association metadata, with a supported relink flow when automatic matching is uncertain. Coordinate that model with global discovery and an explicit cross-device sync or export/import contract rather than treating each workspace storage bucket as an isolated history.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`
- **Validation:** Extend src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts with the selected persistence contract: create a session under one workspace identity, simulate the supported move/relink flow to a changed folder identity, and assert that the session remains discoverable and loadable without duplicating or deleting the original data.
- **Behavior:**

  > Moving or renaming a project folder must not make its previously saved Copilot chat sessions disappear. When VS Code can establish the project's identity confidently, the sessions are associated with the new location automatically; otherwise users have a supported way to find and relink orphaned sessions. The chosen design must define whether history is visible outside the current workspace and how users carry it between machines, without silently exposing or writing conversation data into a repository.
- **Trace:**

  > ChatSessionStore in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts stores folder-window sessions beneath workspaceStorageHome using the current workspace ID. Its handleWorkspaceTransition path copies session files when IWorkspaceEditingService.onDidEnterWorkspace reports both old and new identifiers, but a folder moved between launches starts with only the new identity and cannot use that path. ChatServiceImpl.transferChatSession can transfer a known loaded local Chat-view session, not discover an orphaned source bucket. The plan should coordinate with https://github.com/microsoft/vscode/issues/334228, which owns broader cross-workspace discovery but is younger than this issue, and must preserve existing session retention, privacy, profile separation, and explicit single-session transfer behavior.
- **Open decisions:**
  - Should moved projects be matched automatically through repository or content identity, or only through an explicit user-selected relink flow when their absolute path changes?
  - Should sessions become globally discoverable across workspaces by default, remain workspace-filtered with an optional all-workspaces view, or only be exposed through manual relinking?
  - For cross-device portability, should the supported contract use Copilot session sync, explicit export/import, or an opt-in project-local artifact, and what conversation data may leave machine-local profile storage?

## Evidence

- **current storage boundary:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts constructs folder-window storage under workspaceStorageHome/<workspaceId>/chatSessions, so history remains coupled to the workspace identifier.
- **partial migration only:** ChatSessionStore.handleWorkspaceTransition migrates files only when IWorkspaceEditingService.onDidEnterWorkspace fires. That covers an in-process workspace transition but does not discover the previous workspace bucket after an external folder rename or move.
- **existing transfer mechanism:** src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts exposes transferChatSession for a known loaded local Chat-view session and destination workspace, but this does not recover sessions that became undiscoverable after the source path changed.
- **related global-history work:** https://github.com/microsoft/vscode/issues/334228 is open and proposes globally discoverable cross-workspace history, including folder moves, but it was created after this re-reviewed issue and therefore does not meet the stronger duplicate-canonical age requirement.
- **closed precedent is incomplete:** https://github.com/microsoft/vscode/issues/257143 was closed out of scope and covered project-portable storage, but it does not settle this issue's broader supported rename/relink and global-history alternatives with specific maintainer reasoning.
- **prior discussion:** https://github.com/microsoft/vscode/issues/313970 contains additional requests for cross-machine portability and workspace-independent discovery; it was closed only by the feature-request upvote process rather than by a product decision.
