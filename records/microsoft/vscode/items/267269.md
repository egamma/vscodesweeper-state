# Issue #267269 — Prompt, Instructions and Chat mode Sharing between profiles

[https://github.com/microsoft/vscode/issues/267269](https://github.com/microsoft/vscode/issues/267269)

## Summary

A real gap remains on current main: prompt storage is profile-specific and the underlying model supports inheriting the Default Profile's prompts, but the Profiles editor does not expose that option. The issue is accepted in the Backlog and the younger AI-first profile work explicitly includes prompts and instructions, so it should remain open for a product decision on sharing semantics.

## Change summary

Allow prompts, instructions, and chat modes/custom agents to be shared across selected VS Code profiles instead of manually copied.

## Best solution

Expose AI customizations as profile content with an explicit sharing model, likely building on the existing `ProfileResourceType.Prompts` and `useDefaultFlags.prompts` infrastructure. A maintainer should first decide whether profiles inherit one Default Profile collection or can reference independently selected shared collections, and whether prompt, instruction, and agent files share as one unit.

## Plan brief

- **Likely files:** `src/vs/platform/userDataProfile/common/userDataProfile.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts`, `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts`, `src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts`
- **Validation:** Create two non-default profiles, configure the chosen sharing behavior, add prompt, instruction, and agent files through one profile, and verify after switching profiles that shared files appear while profile-specific files remain isolated; reload the window and repeat to verify persistence.
- **Behavior:**

  > Users can intentionally share prompts, instructions, and custom agents/chat modes across profiles without manually copying files. Switching profiles exposes the selected shared customizations while preserving any content meant to remain profile-specific. The sharing choice persists across reloads and does not change workspace-scoped customization discovery. Acceptance should cover prompt, instruction, and agent files in at least two profiles.
- **Trace:**

  > `IUserDataProfile.promptsHome` in `src/vs/platform/userDataProfile/common/userDataProfile.ts` is the user customization root consumed by `PromptFilesLocator`; `useDefaultFlags.prompts` already permits a profile to resolve that root to the Default Profile. The Profiles editor model currently lists Settings, Keyboard Shortcuts, Tasks, MCP, Snippets, and Extensions but omits the existing `ProfileResourceType.Prompts`, and its copy/import flows omit prompts as well. The boundary is user-profile customization storage and profile management: workspace `.github` customizations and extension-contributed customizations must remain unchanged. Existing location settings remain a useful external-folder mechanism, not a substitute for explicit profile sharing. Related design work is tracked in https://github.com/microsoft/vscode/issues/270130, but that issue is younger and cannot absorb this re-reviewed report as a duplicate.
- **Open decisions:**
  - Should sharing mean inheriting the entire Default Profile customization collection, or may profiles select an independently managed shared collection?
  - Should prompts, instructions, and custom agents/chat modes be shared as one profile resource or controlled independently?

## Evidence

- **profile-specific storage:** `src/vs/platform/userDataProfile/common/userDataProfile.ts` defines `IUserDataProfile.promptsHome`; `toUserDataProfile` normally assigns each profile its own `prompts` directory, while `useDefaultFlags.prompts` aliases it to the Default Profile's directory.
- **current discovery path:** `src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts` discovers user agents, instructions, and prompts from `currentProfile.promptsHome`, confirming that switching profiles changes the user customization source.
- **missing profile UI:** `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditorModel.ts` omits `ProfileResourceType.Prompts` from the resource list and copy flags, while `src/vs/workbench/contrib/userDataProfile/browser/userDataProfilesEditor.ts` has no Prompts title/rendering case. The existing backend flag therefore is not a user-facing sharing control.
- **partial workaround:** `chat.promptFilesLocations`, `chat.instructionsFilesLocations`, and `chat.agentFilesLocations` can point profiles at a common external folder, but require configuration and external folder management rather than providing profile-native sharing.
- **related product work:** The open https://github.com/microsoft/vscode/issues/270130 explicitly references this issue and plans profile contents for prompts and instructions. It was created after this re-reviewed issue, so it is related design work rather than a valid duplicate canonical.
- **newer related report:** https://github.com/microsoft/vscode/issues/290374 requests broader profile isolation and portability for AI files, but is newer than this issue and therefore cannot be its canonical duplicate under the re-review rule.
