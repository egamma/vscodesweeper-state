# Issue #176805 — Activation event for diagnostics

[https://github.com/microsoft/vscode/issues/176805](https://github.com/microsoft/vscode/issues/176805)

## Summary

A real extension-activation gap remains on main, and the abandoned implementation did not land. This team-authored request should remain open while the targeted diagnostic-source activation design is decided.

## Change summary

Allow extensions to defer activation until diagnostics from a relevant source need their code actions.

## Best solution

Define a targeted `onDiagnosticSource:<source>` activation event, including wildcard semantics, triggered independently of where diagnostics are displayed. This preserves lazy activation without coupling extensions to built-in view visibility.

## Vision fit

- **Fit:** aligned
- **Reason:** Targeted lazy activation supports extension capabilities while avoiding unnecessary startup work.
- **Evidence:** Public values emphasize that performance trumps functionality and that powerful capabilities should live in extensions.
