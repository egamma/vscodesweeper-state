# Issue #347902 — Agents window chat background renderer forces a layout on every streamed chunk even when no codicons background is set

The unnecessary layout reads remain in current source. Keep this open while the linked fixing PR is reviewed and merged.

## Change summary

Avoid measuring the Agents chat surface during background refreshes when no codicons background is active.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/347917, preserving codicons refresh behavior while eliminating size reads for absent and image backgrounds.

## Evidence

- **Current source confirms the defect:** In src/vs/workbench/contrib/sessions/browser/chatBackgroundRenderer.ts, the constructor's refreshScheduler callback evaluates element.clientWidth and element.clientHeight before calling renderCodicons. Its non-codicons guard therefore runs after the measurements. Interactive subtree mutations and scroll events schedule this callback regardless of background kind.
- **Intended behavior and boundary:** The same file's setBackground already measures only when switching to codicons. No background or an image background requires no codicon rendering; avoiding scheduled measurements does not require changing codicons behavior. Source inspection confirms unnecessary reads, but their measured layout cost is reporter-provided rather than independently executed.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/347917 is open and unmerged, explicitly states Fixes https://github.com/microsoft/vscode/issues/347902, and describes guarding the scheduled measurements. Its reported regression test counts size reads for absent, image, and codicons backgrounds; the PR reports failure against main and success with the fix.
