# Issue #340019 — Agents Window: Cmd+Escape does not stop the first request

[https://github.com/microsoft/vscode/issues/340019](https://github.com/microsoft/vscode/issues/340019)

## Summary

Thanks for the report. This is reopened and mid-verification (verification-found) with a 1.143.0 milestone, so it stays open. The reporter's focus-loss hypothesis is plausible, but two maintainers could not verify that Cmd+Escape cancels at all by hand. Playwright cancels correctly, while a physical macOS keyboard may not deliver Cmd+Esc to Chromium. This points to an environment or OS-level key-delivery limit rather than the focus bug described. I did not trace the code path in this review.

## Change summary

Cmd+Escape does not cancel the first in-progress request in the Agents Window until the chat input is focused.

## Best solution

Determine whether the physical-keyboard failure is an OS or Chromium limitation on Cmd+Esc. If so, consider changing the Stop keybinding or fixing the focus restoration after the new-session composer transitions to the created chat. Otherwise, make the Stop command eligible when focus is on the document body.
