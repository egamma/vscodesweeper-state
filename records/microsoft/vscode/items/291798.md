# Issue #291798 — Feature Request: Resize Prompt Input Box

[https://github.com/microsoft/vscode/issues/291798](https://github.com/microsoft/vscode/issues/291798)

## Summary

A real gap remains on current main: the panel chat composer grows with its content but has no user-controlled height. The request should remain open under discussion because no older canonical reports the same observable need and the interaction semantics still require a product decision.

## Change summary

Allow users to enlarge or shrink the Copilot Chat prompt editor for writing and reviewing long prompts.

## Best solution

Provide an accessible, user-controlled vertical size for the panel chat composer that coexists predictably with automatic content growth and available conversation space. Define whether the chosen height persists and provide keyboard operation and discoverability through Chat accessibility help.

- **Behavior:**

  > Users composing a long prompt in panel Chat can deliberately increase or decrease the prompt editor's vertical size without resizing the whole Chat view. Conversation content remains usable, and the composer never exceeds the host's available-height constraints. Automatic content growth and the reset behavior remain predictable. Resizing must be keyboard operable and documented in Chat accessibility help.
- **Trace:**

  > ChatInputPart._layout in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts currently chooses height exclusively from editor content and _effectiveInputEditorMaxHeight. ChatWidget.layout in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts supplies the available-height budget, while _layoutListForInputHeight reallocates the remaining space to the conversation. No Sash or equivalent user-height state exists on the panel input path; the Sash in src/vs/workbench/contrib/chat/browser/widgetHosts/chatQuick.ts controls the entire Quick Chat surface and is outside this request's boundary. Preserve compact and inline-chat behavior unless explicitly included, and do not replace content-driven growth for users who never resize. Any new interaction must have a keyboard equivalent and be reflected in src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts.
- **Open decisions:**
  - Should a manually selected prompt height persist across chat sessions or reset when the view or session closes?
  - After manual resizing, should new prompt content continue growing the editor automatically up to the available-space limit, or keep the selected height until the user resets it?
  - Should this capability apply only to panel Chat, or also to compact and inline Chat surfaces?

## Evidence

- **current source behavior:** In src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, ChatInputPart._layout derives the editor height from getContentHeight() and clamps it to _effectiveInputEditorMaxHeight; there is no independent user-selected height.
- **layout boundary:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts computes the input height budget and relayouts the conversation around the input's intrinsic height, so manual sizing would need an explicit contract with the existing automatic layout.
