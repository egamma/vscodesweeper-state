# Issue #326515 — Cursor doesn't follow page when scrolling with Ctrl+Arrow keys in VS Code

[https://github.com/microsoft/vscode/issues/326515](https://github.com/microsoft/vscode/issues/326515)

## Summary

Current behavior is intentional: VS Code binds Ctrl+Up/Ctrl+Down to viewport scrolling commands, while caret-moving line navigation is exposed through separate cursor commands and can be rebound by the user.

## Change summary

Change the default Ctrl+Up/Ctrl+Down behavior so the caret moves with the viewport, matching Visual Studio's behavior.

## Best solution

Keep the existing default keybindings for `editorScrollLineUp` and `editorScrollLineDown`; users who prefer Visual Studio-style caret movement can customize keybindings to the cursor movement commands instead of changing VS Code's default editor contract.

## Vision fit

- **Fit:** rejected
- **Reason:** Changing a long-standing default shortcut to a different editor's behavior would trade uniform VS Code interactions for one-off compatibility, while the product already supports customization through keybindings.
