# Issue #326515 — Cursor doesn't follow page when scrolling with Ctrl+Arrow keys in VS Code

[https://github.com/microsoft/vscode/issues/326515](https://github.com/microsoft/vscode/issues/326515)

## Summary

Traced in source: Ctrl+Up/Ctrl+Down are bound to the `scrollLineUp`/`scrollLineDown` core commands, which explicitly pass `revealCursor: false` — the cursor is deliberately left in place while the viewport scrolls, matching many other editors (not Visual Studio's convention). This is intentional design, not a defect.

## Change summary

Requests that Ctrl+Up/Ctrl+Down move the cursor along with the scrolled viewport, matching Visual Studio's behavior, instead of only scrolling the view.

## Best solution

Keep the current default (scroll without moving the cursor); users who want Visual Studio-style behavior can rebind Ctrl+Up/Down to `cursorUp`/`cursorDown` (or similar) in keybindings.json, or use an extension/profile that ships VS-style keybindings.
