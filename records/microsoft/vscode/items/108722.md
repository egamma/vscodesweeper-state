# Issue #108722 — API to trigger a refresh of the OUTLINE (DocumentSymbols)

[https://github.com/microsoft/vscode/issues/108722](https://github.com/microsoft/vscode/issues/108722)

## Summary

A real extension API gap remains on current main: document-symbol results can change independently of document text, but providers cannot invalidate the cached model or notify Outline. With 53 upvotes and several language-extension use cases, this accepted Backlog request should remain open.

## Change summary

Allow document-symbol providers to notify VS Code when symbols changed so Outline, breadcrumbs, and symbol commands refresh without editing the document.

## Best solution

Add an optional provider change event analogous to `CodeLensProvider.onDidChangeCodeLenses`, then propagate it through the extension-host protocol to invalidate the affected outline cache and refresh document-symbol consumers. Prefer this provider-owned event over a global refresh command.

## Evidence

- **API gap on main:** `DocumentSymbolProvider` in `src/vscode-dts/vscode.d.ts` exposes only `provideDocumentSymbols`, unlike CodeLens, folding-range, inlay-hint, and semantic-token providers, which expose change events.
- **cached results:** `src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts` reuses cached symbols until the text-model version or provider list changes; `src/vs/editor/contrib/documentSymbols/browser/documentSymbols.ts` routes `vscode.executeDocumentSymbolProvider` through that cache.
- **outline refresh path:** `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts` rebuilds for content, model, language, and provider-registry changes, but has no provider result-change signal.
- **maintainer direction:** In https://github.com/microsoft/vscode/pull/160027, the proposed command was declined in favor of a provider event analogous to `CodeLensProvider.onDidChangeCodeLenses`; the PR closed without implementing that event.
- **community demand:** The issue has 53 community upvotes and independent XML, Java, C/C++, ReScript, and background-analysis use cases; no separate open canonical issue was found.
