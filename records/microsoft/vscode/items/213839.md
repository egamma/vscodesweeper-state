# Issue #213839 — Window hang when rendering deeply nested trees

[https://github.com/microsoft/vscode/issues/213839](https://github.com/microsoft/vscode/issues/213839)

## Summary

This remains a confirmed core tree-widget performance defect: deeply nested trees can block the renderer, and the implicated recursive lookups and per-ancestor indent-guide rendering remain on current main. The team-authored issue should stay open; no older open canonical or fixing commit was found.

## Change summary

Rendering or scrolling a deeply nested Outline tree can make the VS Code window unresponsive, particularly with tree sticky scroll and indent guides enabled.

## Best solution

Make deeply nested trees remain responsive without disabling sticky scroll or indent guides, and establish a repeatable depth-stress check that catches renderer long tasks and stack-depth failures across tree consumers.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/tree/indexTreeModel.ts`, `src/vs/base/browser/ui/tree/abstractTree.ts`, `src/vs/base/test/browser/ui/tree/indexTreeModel.test.ts`
- **Validation:** Replay the issue's deeply nested Outline scenario in a development build with sticky scroll and indent guides enabled, scroll through the tree while recording a renderer profile, and verify that interaction remains responsive without multi-second long tasks; finish with targeted deep-location tree-model regression coverage.
- **Behavior:**

  > Opening and scrolling an Outline containing hundreds or thousands of nested symbols must not freeze the renderer or take minutes to complete. Sticky scroll and indent guides should remain functional rather than serving only as settings-based workarounds. Ordinary shallow trees must retain their current rendering, navigation, and visual behavior.
- **Trace:**

  > The issue's captured stack repeatedly enters getTreeNode in src/vs/base/browser/ui/tree/indexTreeModel.ts, and maintainers profiled sticky scrolling and indent guides as additional multipliers. Current main still recursively consumes location arrays in hasTreeNode, getTreeNode, and getParentNodeWithListIndex. TreeRenderer::_renderIndentGuides in src/vs/base/browser/ui/tree/abstractTree.ts walks every ancestor and creates one guide per level while repeatedly resolving node locations; StickyScrollController also repeatedly resolves locations, list indexes, and ancestors. A core JSON Outline reproducer is recorded in https://github.com/microsoft/vscode/issues/235890, confirming that the rendering defect is not owned solely by the Red Hat YAML extension. Keep YAML symbol production and language detection outside this fix, and do not solve the issue by globally disabling sticky scroll or indent guides.

## Evidence

- **confirmed reproduction:** Maintainer comments on https://github.com/microsoft/vscode/issues/213839 report successful reproduction and profiling on Stable; additional contributors confirmed the behavior, with 1,000 nested levels hanging VS Code for minutes.
- **current source:** src/vs/base/browser/ui/tree/indexTreeModel.ts still implements hasTreeNode, getTreeNode, and getParentNodeWithListIndex recursively while allocating a rest array at every depth; the same implementation was present at the issue's cited commit f10898df1d33b0cb8486e2cade6713f952ac6fe7.
- **render amplification:** src/vs/base/browser/ui/tree/abstractTree.ts::_renderIndentGuides walks every ancestor and repeatedly calls getNodeLocation/getParentNodeLocation/getNode, while StickyScrollController performs the same location/index traversals when computing ancestors and ranges.
- **related reports:** https://github.com/microsoft/vscode/issues/235890 confirms the same freeze in a core JSON Outline with extensions disabled, but it was opened after this issue and cannot be the canonical for this re-reviewed item. The older https://github.com/microsoft/vscode/issues/205840 described the same observable symptom but is closed, so it is not a valid duplicate target.
- **remaining work:** https://github.com/microsoft/vscode/issues/250787 remains open for reducing individual indent-guide elements; its discussion distinguishes that work from the code-execution bottleneck tracked here.
