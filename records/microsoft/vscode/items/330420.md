# Issue #330420 — Windows: Copilot CLI plugin operations fail with “Access is denied” while VS Code is running

[https://github.com/microsoft/vscode/issues/330420](https://github.com/microsoft/vscode/issues/330420)

## Summary

Real, independently-confirmed Windows bug: installing/uninstalling a Copilot CLI plugin fails with 'Access is denied' while VS Code is running, but succeeds once VS Code is closed — a maintainer (DonJayamanne) has already flagged it to an assignee, so this stays open for investigation.

## Change summary

On Windows, `/plugin install`/uninstall in a Copilot CLI session inside VS Code fails with an OS access-denied error that doesn't occur when the same command is run from a standalone terminal.

## Best solution

Investigate whether VS Code's agent-host file watchers on the Copilot customization/plugin directories (src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts uses IFileService.watch, including recursive watches) hold a Windows directory handle open that blocks the rename/move the @github/copilot-sdk plugin installer performs; the fix may need to land in vscode's watcher scoping or be reported upstream to the copilot-sdk/CLI installer if it's doing an in-place rename under a watched root.

- **plausible mechanism:** The agent host's customization discovery sets up recursive IFileService watchers on plugin/customization directories (src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts, e.g. `this._fileService.watch(rootUri, { recursive: next.recursive, excludes: [] })`); Windows directory watches are a known source of transient file locks that block rename/delete, which lines up with the 'Access is denied (os error 5)' symptom and the fact that closing VS Code (disposing the watcher) unblocks it.
- **external installer:** The actual plugin install/uninstall logic runs inside the `@github/copilot-sdk` package invoked from src/vs/platform/agentHost/node/copilot/copilotAgent.ts, not in vscode's own install code, so a full fix may require coordination with that package too.
