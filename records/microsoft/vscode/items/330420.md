# Issue #330420 — Windows: Copilot CLI plugin operations fail with “Access is denied” while VS Code is running

[https://github.com/microsoft/vscode/issues/330420](https://github.com/microsoft/vscode/issues/330420)

## Summary

Clear, deterministic repro (fails while VS Code is open, succeeds once it's closed) pointing at VS Code holding a lock/handle on the Copilot CLI plugin directory; a maintainer has already been tagged, so this just needs area routing and continued investigation, not a triage close.

## Change summary

On Windows, `/plugin install` and presumably uninstall in Copilot CLI fail with "Access is denied (os error 5)" while any VS Code window is open, but succeed once VS Code is fully closed.

## Best solution

Investigate whether VS Code's own file watchers on `~/.copilot/installed-plugins/<marketplace>/<plugin>` (set up in CopilotCliAgentPluginDiscovery.start in agentPluginServiceImpl.ts) hold a Windows directory/file handle that blocks the CLI's install/uninstall rename-move operations, and either exclude/relax that watch or make it resilient to concurrent writers.

- **Windows semantics:** Windows file watchers/handles are more restrictive than POSIX about concurrent rename/delete of watched directories, which is a plausible mechanism for the reported 'Access is denied (os error 5)' during install/uninstall while VS Code (and its watcher) is running.
