# Issue #283335 — Terminal Sticky Scroll causes incorrect screen size detection for scrolling

[https://github.com/microsoft/vscode/issues/283335](https://github.com/microsoft/vscode/issues/283335)

## Summary

Still present on main: terminal sticky scroll overlays content without adjusting the PTY's reported row count, causing pagers and scrollback to miscalculate visible area. A partial heuristic exists for `less`/`git log` pager detection (lines 300-312 of the overlay file) but it doesn't cover all scenarios and doesn't fix the page-up/page-down offset problem. Three independent reporters confirm the issue across different tools.

## Change summary

Terminal sticky scroll obscures top lines of output without adjusting the terminal's reported dimensions, causing programs with their own viewport management (pagers, entr, etc.) to show incorrect content and breaking page-up/page-down scrolling.

## Best solution

The sticky scroll overlay needs to either (a) reduce the terminal's effective row count reported to the PTY when visible, so programs correctly calculate visible area, or (b) more aggressively hide itself when a full-screen/pager program is detected. The existing pager heuristic in `terminalStickyScrollOverlay.ts` (lines 300-312) is too narrow. The fix belongs in `src/vs/workbench/contrib/terminalContrib/stickyScroll/browser/terminalStickyScrollOverlay.ts`.
