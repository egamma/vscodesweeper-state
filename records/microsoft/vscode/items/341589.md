# Issue #341589 — Harness Switching messes with Agent Selection

[https://github.com/microsoft/vscode/issues/341589](https://github.com/microsoft/vscode/issues/341589)

## Summary

Keep open as a harness-selection UX request: current source deliberately allows Copilot preference to override a remembered Local selection, matching the latest explanation in the discussion. The remaining question is how explicit harness choices and resulting agent availability should behave across chats, rather than whether the report lacks reproduction details.

## Change summary

Make harness selection predictable across chat transitions so workspace custom agents do not unexpectedly disappear.

## Best solution

Establish explicit harness-selection precedence for new chats and distinguish it from reopening an existing chat with its own harness. Preserve access to supported workspace agents and explain intentional capability differences without implying that their files have disappeared.
