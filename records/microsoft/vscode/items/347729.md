This directly explains why opening the reported mixed Markdown/code notebook leaves even code cells absent while warmup is pending.
- **Unbounded acknowledgement:** src/vs/workbench/contrib/notebook/browser/view/renderers/backLayerWebView.ts:1477-1498 creates a DeferredPromise in initializeMarkup and returns its promise; the initializedMarkup message handler at lines 623-627 completes it. The widget awaits this acknowledgement before attaching its list.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/347939 is open, has no merged_at timestamp, and explicitly states Fixes #347729. It proposes a bounded warmup wait and skipping unnecessary Markdown initialization; its reported test results are contributor evidence, not checks executed during this review.
- **Earlier decision has narrower scope:** https://github.com/microsoft/vscode/issues/342813#issuecomment-6295420004 describes idle-priority rendering of hidden notebooks as intentional. This report instead requests that the foreground cell list not depend indefinitely on that rendering; the earlier decision does not establish that this startup delay is intentional.
- **Related issue is distinct:** https://github.com/microsoft/vscode/issues/177409 is open but concerns thousands of Markdown cells flooding the renderer with dimension updates and list-height work. That differs from this report's two-cell notebook waiting on initialization while the window remains idle, so it is not a verified duplicate.
