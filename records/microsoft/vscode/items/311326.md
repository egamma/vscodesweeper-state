# Issue #311326 — codex not reflected in terminal title

[https://github.com/microsoft/vscode/issues/311326](https://github.com/microsoft/vscode/issues/311326)

## Summary

Keep open: current source still explains why a Node-launched Codex without an OSC title remains labeled node. The matching Fedora report is newer, so it cannot replace this previously reviewed issue as the canonical.

## Change summary

Launching Codex on macOS with agent CLI titles enabled shows node rather than the CLI identity.

## Best solution

Provide reliable Codex identity for the reported Node-launcher path without misidentifying ordinary Node programs, while preserving configured title overrides and restoring the shell title after exit.

## Plan brief

- **Likely files:** `src/vs/platform/terminal/node/terminalProcess.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/test/browser/terminalInstance.test.ts`
- **Validation:** On macOS, launch a Codex installation whose foreground process is reported as node in a fresh integrated terminal with terminal.integrated.tabs.allowAgentCliTitle=true. Verify a Codex-identifying title while active and restoration of the shell title after exit; repeat with an ordinary Node program, the setting disabled, and an explicit title template to check for regressions.
- **Behavior:**

  > A Node-launched Codex session on macOS should display a title identifying Codex when agent CLI titles are enabled, rather than the generic node process name. Exiting Codex should restore the normal shell title. Ordinary Node programs must not be identified as Codex, and disabled agent-title handling and explicit title templates must retain their existing behavior.
- **Trace:**

  > TerminalProcess._sendProcessTitle in src/vs/platform/terminal/node/terminalProcess.ts classifies the foreground executable name; node maps to GeneralShellType.Node even though a separate Codex mapping exists. TerminalInstance._onTitleChange in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts can recognize other Node-hosted agent CLIs through OSC titles, but agentCliTitlePatterns deliberately excludes Codex because it does not emit that signal. TerminalLabelComputer.refreshLabel consequently does not select the agent-title path for the reported launch. The remaining uncertainty is which reliable identity signal is available for this launcher and whether supporting it crosses the process or shell-integration boundary; adding a Codex OSC pattern alone would not address the reported case. Preserve other CLI detection, explicit title overrides, and shell restoration. The same symptom is reported on Fedora at https://github.com/microsoft/vscode/issues/311424, while https://github.com/microsoft/vscode/issues/311191 establishes the intended behavior.

## Evidence

- **Expected behavior:** https://github.com/microsoft/vscode/issues/311191 explicitly asks testers to verify that Codex displays its CLI identity or session title rather than node and that the shell title returns after exit. This report supplies the macOS trigger, enabled setting, and observed node title.
- **Process detection:** src/vs/platform/terminal/node/terminalProcess.ts:71–84 maps codex and node to different shell types. _sendProcessTitle at lines 437–458 derives identity from ptyProcess.process and its executable basename; the reported node value selects GeneralShellType.Node, not Codex.
- **Missing alternate identity signal:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:132–138 explicitly omits the Codex OSC detection pattern because Codex does not report an OSC title. _onTitleChange at lines 1951–1963 uses those patterns to identify Node-hosted agent CLIs. TerminalLabelComputer.refreshLabel at lines 2761–2765 enables the agent-title override only for recognized agent shell types.
- **Setting does not supply identity:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts registers terminal.integrated.tabs.allowAgentCliTitle as permission to use escape-sequence titles, not a mechanism for identifying a Node-hosted Codex process. Enabling it cannot supply the missing process identity.
