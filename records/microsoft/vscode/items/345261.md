# Issue #345261 — Prompts from custom mcp server not loading in chat after typing '/'

[https://github.com/microsoft/vscode/issues/345261](https://github.com/microsoft/vscode/issues/345261)

## Summary

Keep open: MCP prompt discovery and invocation remain missing from the Copilot harness, as the maintainer diagnosed and current source confirms. The reporter has already supplied the distinguishing evidence: identical prompts work with the Local harness.

## Change summary

Make MCP server prompts available through slash commands in Copilot harness chat sessions.

## Best solution

Provide host-owned MCP prompt discovery and invocation through the Copilot harness, preserving the Local harness experience and existing MCP connection ownership. Plan the SDK and client integration with the assigned owner before implementation.

- **Behavior:**

  > An MCP server's prompts are available from slash completion in Copilot harness chat, rather than only in Local harness chat. Selecting a prompt supports its declared arguments and makes its returned content usable in the conversation. Acceptance should cover prompt discovery, selection and invocation with a prompt-capable server, while preserving existing Local prompt behavior and ordinary slash commands.
- **Trace:**

  > The reporter confirmed server prompts through Inspector and curl and isolated the failure by switching harnesses. In chatInputCompletions.ts, mcpPromptSlashCommands reads workbench MCP server prompts but deliberately exits for agent-host-backed widgets. CopilotSlashCommandCompletionProvider instead reads SDK runtime commands and skills; CopilotAgentSession.handleMcpRequest does not support prompts/list or prompts/get, and mcpSideChannelSuite.ts expects the former to fail. The remaining uncertainty is the SDK prompt-access contract and how prompt arguments and returned content traverse host completions and client invocation. Preserve host ownership of MCP connections rather than relying on the Local workbench connection, and keep tool, resource and sampling behavior unchanged. The maintainer's direction is recorded at https://github.com/microsoft/vscode/issues/345261#issuecomment-7220547522; https://github.com/microsoft/vscode/issues/251746 and https://github.com/microsoft/vscode/issues/278164 are related UX work, not duplicate canonicals.
