# Issue #126960 — Revisit the use of `ITextEditorService` in preferences component

[https://github.com/microsoft/vscode/issues/126960](https://github.com/microsoft/vscode/issues/126960)

## Summary

The remaining preferences cleanup is still necessary: ordinary and split JSON settings opening paths construct typed editor inputs before calling openEditor. The final clarification explicitly permits createTextEditor inside resolver factories, so removing every ITextEditorService usage would miss the intended boundary.

## Change summary

Have preferences opening commands pass untyped inputs and leave typed editor construction to editor resolution.

## Best solution

Migrate the ordinary and split JSON settings opening paths to untyped inputs while preserving settings targets, text-editor selection, grouping, and reveal behavior. Keep typed construction inside the registered resolver factory where it is explicitly allowed.
