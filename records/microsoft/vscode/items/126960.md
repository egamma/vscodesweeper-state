# Issue #126960 — Revisit the use of `ITextEditorService` in preferences component

[https://github.com/microsoft/vscode/issues/126960](https://github.com/microsoft/vscode/issues/126960)

## Summary

The debt remains on current main: preferences service still uses ITextEditorService.createTextEditor to construct typed EditorInput instances (SideBySideEditorInput with two text editors) and passes them directly to openEditor, rather than adopting untyped editor descriptors through the resolver. Keeping open as valid debt.

## Change summary

Preferences component should stop creating typed EditorInput instances directly and instead use untyped editor descriptors resolved through the editor resolver API.

## Best solution

Refactor preferencesService.ts to pass untyped editor descriptors (with resource URIs and override options) to editorService.openEditor instead of manually constructing SideBySideEditorInput via createTextEditor. The split JSON settings editor path (createSplitJsonEditorInput) and getOrCreateEditableSettingsEditorInput are the remaining call sites.
