# Issue #126960 — Revisit the use of `ITextEditorService` in preferences component

[https://github.com/microsoft/vscode/issues/126960](https://github.com/microsoft/vscode/issues/126960)

## Summary

The debt is still present: `preferencesService.ts` on current main still calls `ITextEditorService.createTextEditor` directly in three places (lines 441, 442, 486) and creates `KeybindingsEditorInput` typed input directly (line 364). The custom-editor usages were cleaned up in 2021 but the preferences component was never migrated to the editor resolver API. Keeping open as valid unresolved debt.

## Change summary

Migrate the preferences component away from directly creating typed editor inputs via `ITextEditorService.createTextEditor`, using the editor resolver API instead.

## Best solution

Refactor `PreferencesService` in `src/vs/workbench/services/preferences/browser/preferencesService.ts` to stop calling `textEditorService.createTextEditor` directly and instead go through the editor resolver API for creating editor inputs, including the split-JSON and keybindings editor flows. This aligns with the broader goal of having all editor input creation go through the resolver.
