# Issue #126960 — Revisit the use of `ITextEditorService` in preferences component

[https://github.com/microsoft/vscode/issues/126960](https://github.com/microsoft/vscode/issues/126960)

## Summary

The architectural debt remains on current main: PreferencesService still creates typed text and side-by-side editor inputs before calling openEditor, even though the editor resolver now supports untyped side-by-side inputs. The accepted On Deck debt should remain open for the settings editor owner.

## Change summary

Move preferences opening paths away from constructing typed editor inputs upfront and let the editor resolver create them from untyped inputs.

## Best solution

Have preference-opening callers submit untyped resource or side-by-side descriptors, while keeping typed input creation inside the registered settings editor factory where ownership and caching require it.
