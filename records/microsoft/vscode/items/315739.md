# Issue #315739 — New session view should be in history

[https://github.com/microsoft/vscode/issues/315739](https://github.com/microsoft/vscode/issues/315739)

## Summary

The requested navigation remains missing on current main: Back returns from a new-session composer to the prior session, but Forward cannot restore that composer or its draft. This team-authored Backlog request should remain open for a persistence-semantics decision and implementation.

## Change summary

Include an in-progress new-session composer in Agents window navigation so Back followed by Forward restores the draft.

## Best solution

Treat the current new-session composer or untitled draft as a restorable navigation destination, preserving its prompt while the user temporarily visits another session. Decide whether that destination is window-local or participates in persisted recency before implementation.

## Plan brief

- **Likely files:** `src/vs/sessions/services/sessions/browser/sessionNavigation.ts`, `src/vs/sessions/services/sessions/browser/sessionsService.ts`, `src/vs/sessions/services/sessions/browser/sessionsRecencyHistory.ts`, `src/vs/sessions/services/sessions/test/browser/sessionNavigation.test.ts`, `src/vs/sessions/services/sessions/test/browser/sessionsManagementService.test.ts`
- **Validation:** Add focused SessionsNavigation coverage for existing session -> new-session draft -> Back -> Forward, asserting Forward is enabled after Back and restores the same draft; also verify through an Agents window fixture that typed prompt text remains present after the round trip.
- **Behavior:**

  > Starting a new Agents window session, typing a prompt, navigating Back to an earlier session, and then navigating Forward must return to the same in-progress composer with its prompt intact. Back and Forward enablement must reflect that destination. Existing navigation among submitted sessions and the behavior of a fresh composer with no prior history must remain unchanged.
- **Trace:**

  > SessionsNavigation in src/vs/sessions/services/sessions/browser/sessionNavigation.ts skips both an undefined composer and SessionStatus.Untitled sessions, using `_beyondHistory` only to make Back available; `_canGoForward` is therefore false after leaving that destination. Its ISessionOpener contract can reopen established sessions and chats but cannot reopen the new-session destination. SessionsService._openNewSession in src/vs/sessions/services/sessions/browser/sessionsService.ts retains `sessionsManagementService.newSession` and can reactivate that pending draft, while SessionsRecencyHistory is shared, persisted MRU state used beyond Back/Forward. Preserve established-session MRU ordering, chat navigation, deletion cleanup, and the single-composer invariant. The uncertainty starts at whether a draft navigation entry belongs only to the live navigation cursor or to persisted shared recency.
- **Open decisions:**
  - Should a new-session draft be a window-local Back/Forward destination only, or should it survive reload and participate in the shared recent-session history?

## Evidence

- **current source:** src/vs/sessions/services/sessions/browser/sessionNavigation.ts explicitly skips undefined new-session views and SessionStatus.Untitled sessions, records only `_beyondHistory`, and makes `_canGoForward` false while that state is active.
- **current tests:** src/vs/sessions/services/sessions/test/browser/sessionNavigation.test.ts asserts that entering the new-session view enables Back but leaves Forward disabled; no test restores that view after navigating back.
- **draft restoration path:** src/vs/sessions/services/sessions/browser/sessionsService.ts `_openNewSession` retains and restores `sessionsManagementService.newSession`, so the draft model can survive visiting another established session, but `ISessionOpener` in sessionNavigation.ts exposes only established-session and chat navigation.
- **maintainer intent:** The team-authored test plan https://github.com/microsoft/vscode/issues/315535 explicitly documented that the new-session view was not recorded in history; this issue requests changing that tested behavior and is assigned to the Backlog.
- **canonical search:** The older open issue https://github.com/microsoft/vscode/issues/298907 concerns established chats disappearing from the Chat history list, not inability to navigate Forward to an in-progress new-session composer, so it does not meet the re-review duplicate bar.
