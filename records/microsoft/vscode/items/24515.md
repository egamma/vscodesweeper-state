# Issue #24515 — [folding] Folding HTML tags should hide the closing tag. 

[https://github.com/microsoft/vscode/issues/24515](https://github.com/microsoft/vscode/issues/24515)

## Summary

This remains a valid, well-supported folding request: language-aware folding exists, but VS Code still cannot fold a multi-line HTML element into one displayed line because folding ranges are line-based. The linked inline-range request is newer than this re-reviewed issue and therefore cannot serve as its duplicate canonical.

## Change summary

When an HTML element is collapsed, hide its closing-tag line so the folded element appears on a single line.

## Best solution

Extend the editor folding model and rendering path to support ranges ending within a line, then have the HTML folding provider end element ranges after the closing tag; preserve current line-based behavior for providers that return ordinary folding ranges.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/browser/foldingRanges.ts`, `extensions/html-language-features/server/src/modes/htmlMode.ts`
- **Validation:** Add editor folding tests showing that an HTML range can collapse from its opening tag through an inline closing-tag boundary into one displayed line, while existing line-based folding tests remain unchanged.
- **Behavior:**

  > Collapsing a multi-line HTML element should display only its opening-tag line and hide the corresponding closing tag, producing a single-line folded representation. Expanding it must restore all content without changing selection or document text. Existing folding behavior for languages and providers that supply whole-line ranges must remain unchanged.
- **Trace:**

  > The report's central gap is not range discovery but range granularity: the editor folding model represents collapsed regions with line-based boundaries, so an HTML provider cannot include only the closing tag while preserving unrelated text on the same line. The likely shared path runs through folding range contracts in src/vs/editor/common/languages.ts and the folding range/model implementation under src/vs/editor/contrib/folding/browser/. HTML range production is owned by extensions/html-language-features/server/src/modes/htmlMode.ts. https://github.com/microsoft/vscode/issues/50840 tracks the broader inline-folding capability but is newer than this issue; treat it as architectural context, not a duplicate. The boundary is to retain existing whole-line folding semantics and avoid making HTML-specific rendering exceptions in the generic editor.
- **Open decisions:**
  - Should the folding provider contract gain character-level start/end positions for all languages, or should inline closing-tag concealment be an editor-owned presentation mode layered over existing line ranges?
  - When a closing tag shares its line with other visible content, should folding hide only the tag or leave the entire line visible to preserve current line-based semantics?

## Evidence

- **maintainer prerequisite:** A VS Code maintainer identified language-aware folding as the original prerequisite in the issue discussion; that prerequisite no longer resolves the central ask because current folding ranges still operate on whole lines.
