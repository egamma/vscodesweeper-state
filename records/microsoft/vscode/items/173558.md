## Evidence

- **Existing-capability check:** cli/src/tunnels/service.rs aliases ServiceManagerImpl to SystemdService on every Linux target, and create_service_manager unconditionally constructs that implementation. There is no OpenRC backend or Linux supervisor selection.
- **Requested command path:** cli/src/commands/tunnels.rs:298–320 routes tunnel service install through create_service_manager and manager.register. cli/src/commands/args.rs:1066–1090 exposes install, uninstall, log, and internal-run subcommands, but no OpenRC option.
- **Remaining implementation gap:** cli/src/tunnels/service_linux.rs connects to the session D-Bus and org.freedesktop.systemd1.Manager during registration, writes a systemd unit, and uses systemctl/journalctl for logs. These paths do not install or manage an OpenRC service.
- **Maintainer context and workaround:** In the supplied 2023-02-07 comment on https://github.com/microsoft/vscode/issues/173558, connor4312 confirms that service install supports only systemd Linux distributions and suggests a manually written OpenRC init script. That workaround supports running the tunnel externally, not the requested integrated installation.
