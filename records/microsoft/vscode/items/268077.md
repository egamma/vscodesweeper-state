# Issue #268077 — Update the extensionApi embeddings to use metis instead of textsmall

[https://github.com/microsoft/vscode/issues/268077](https://github.com/microsoft/vscode/issues/268077)

## Summary

The migration remains necessary: the extension API cache and query path still use text-embedding-3-small on current main. Keep it open because the accepted On Deck work must preserve the no-auth `@vscode` flow, which currently cannot return Metis embeddings.

## Change summary

Migrate extension API semantic-search cache and query embeddings from text-embedding-3-small to Metis without regressing authenticated or no-auth `@vscode` searches.

## Best solution

Move the extension API index and query onto matching Metis embeddings with query/document input types, while retaining functional no-auth `@vscode` search. Validate retrieval quality before retiring the text-embedding-3-small path.

- **Behavior:**

  > VS Code API semantic search should rank the published Metis API index using a Metis query embedding and return relevant API snippets. The query must be identified as a query rather than a document. Authenticated and supported no-auth `@vscode` users must continue receiving results, and retrieval evaluation scores must not regress.
- **Trace:**

  > ApiEmbeddingsIndex in extensions/copilot/src/extension/context/node/resolvers/extensionApi.tsx creates its API cache with `EmbeddingType.text3small_512`, and VSCodeAPIContextElement computes its query with the same type and empty options. RemoteEmbeddingsComputer supports the Metis type for authenticated Dotcom requests, but its no-auth branch delegates to computeCAPIEmbeddings, which is hard-coded to text-embedding-3-small and returns that type. The Metis API cache is already published according to https://github.com/microsoft/vscode/issues/268074#issuecomment-3544103869. Preserve the existing five-result API-context behavior and do not fold the separate command/settings migration from https://github.com/microsoft/vscode/issues/268074 into this issue.
- **Open decisions:**
  - Must Metis support land for the no-auth embeddings endpoint before switching all extension API searches, or should no-auth `@vscode` retain a text-embedding-3-small cache and query fallback while authenticated searches use Metis?
