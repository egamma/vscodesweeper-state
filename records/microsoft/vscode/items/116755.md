# Issue #116755 — SCM - improve focus movement

[https://github.com/microsoft/vscode/issues/116755](https://github.com/microsoft/vscode/issues/116755)

## Summary

Keep open: current source still implements the forward Tab jump into a change item's actions without the corresponding reverse navigation. The existing SCM navigation commands and related reports do not cover both reported focus transitions.

## Change summary

Make SCM keyboard focus reversible between a change item and its inline actions, and move backward from the changes list into the commit message input.

## Best solution

Provide predictable, reversible focus navigation in the SCM tree while preserving arrow-key navigation and toolbar interaction. Establish browser-level regression checks for both reported transitions before changing shared list behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/base/browser/ui/list/listWidget.ts`, `src/vs/base/browser/ui/actionbar/actionbar.ts`, `src/vs/base/test/browser/ui/list/listWidget.test.ts`
- **Validation:** In a Git workspace with several changed files and visible inline actions, keyboard-focus a change item, press Tab and then Shift+Tab, and verify focus returns to the same item. Separately keyboard-focus the first change item, press Shift+Tab, and verify the commit message input receives focus rather than title actions. Repeat with the SCM action button shown and hidden; establish an automated browser check that fails before the change and passes afterward.
- **Behavior:**

  > Keyboard focus in Source Control should follow the two transitions specified in the report. Tab from a focused change item enters its inline actions; Shift+Tab immediately afterward returns to that same item without changing its logical selection. Shift+Tab from the first change item reaches the commit message input rather than the view title actions. Existing arrow-key navigation, action invocation, and commit input editing remain unchanged.
- **Trace:**

  > DOMFocusController in src/vs/base/browser/ui/list/listWidget.ts intercepts forward Tab on the list root and jumps into a descendant of the focused row, but excludes Shift+Tab. SCMViewPane embeds both InputRenderer's commit editor and ResourceRenderer's toolbars inside this list; ListView makes its enclosing root tabbable before those descendants. ActionBar does not provide a reverse transition back to the originating list row, so native backward traversal cannot invert that jump. The source establishes the asymmetry, but the session still needs to observe actual browser focus targets and choose a regression harness before implementation. Shared list and action-bar behavior serves other views and must not acquire SCM-specific semantics indiscriminately. https://github.com/microsoft/vscode/issues/131006 and https://github.com/microsoft/vscode/issues/140513 concern related but different focus paths.

## Evidence

- **Forward-only list focus handling:** src/vs/base/browser/ui/list/listWidget.ts:609–658, DOMFocusController, handles only unmodified forward Tab. When the list root has focus, it prevents normal traversal and focuses the first tabbable descendant of the logically focused row. Shift+Tab has no corresponding handler.
- **SCM path and reverse-order mismatch:** src/vs/workbench/contrib/scm/browser/scmViewPane.ts:278–287 renders the commit input inside a tree row, and ResourceRenderer.renderTemplate at lines 514–523 embeds the inline toolbar inside each resource row. src/vs/base/browser/ui/list/listView.ts:406–410 makes the enclosing list root tabbable before those descendants. Consequently, native backward traversal does not invert the programmatic jump from that root into a later resource row; backward traversal from the root also bypasses the nested commit input.
- **Toolbar does not restore the originating row:** src/vs/base/browser/ui/actionbar/actionbar.ts:155–188 handles arrow navigation and selected forward-Tab cases, but not Shift+Tab restoration to the parent list. The SCM tree construction in scmViewPane.ts:1589–1663 supplies renderers and accessibility options without a compensating reverse-Tab handler.
- **Existing navigation is not coverage:** SCMViewPane.focusPreviousInput, focusNextInput, focusPreviousResourceGroup and focusNextResourceGroup provide explicit navigation commands. They do not make Tab followed by Shift+Tab return to the original change item or establish the requested backward traversal into the commit input.
