# Issue #329083 — Automations: Claude is being shown the Copilot permission picker

[https://github.com/microsoft/vscode/issues/329083](https://github.com/microsoft/vscode/issues/329083)

## Summary

The Automations dialog still uses the legacy chat input part instead of the new chat input widget, so it doesn't know a session is running the Claude harness and always renders the Copilot permission picker; this is explicitly tracked (and lists this issue as related) by the open canonical migration issue.

## Change summary

In the Automations dialog, the permission picker shown for a Claude-backed automation incorrectly displays Copilot's permission options instead of Claude's.

## Best solution

Consolidate onto https://github.com/microsoft/vscode/issues/330701 (assigned to benvillalobos) — migrating the Automations dialog to the new chat input widget (src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts / permissionPickerActionItem.ts's getExtensionPermissions delegate) will make all pickers, including permissions, harness-aware.
