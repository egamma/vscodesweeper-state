# Issue #196083 — Getting incorrect language features in diff editor, from GHPRI

[https://github.com/microsoft/vscode/issues/196083](https://github.com/microsoft/vscode/issues/196083)

## Summary

Still reproduces on main: the `pr` scheme was accidentally dropped from the TypeScript extension's `disabledSchemes` set during the March 2023 file-move refactor (commit 0acd2722684), so TS language features fire incorrectly for GHPRI diff editor files. No fix has been committed. The current `feature-request` label is arguably wrong — this is a regression.

## Change summary

TypeScript language features (diagnostics, completions, symbol highlights) show incorrect results in the diff editor when reviewing PRs via the GitHub Pull Requests extension, because the `pr` URI scheme is no longer excluded.

## Best solution

Re-add the `pr` scheme to `disabledSchemes` in `extensions/typescript-language-features/src/configuration/fileSchemes.ts`, restoring the behavior from commit 3dc43cb7b3b which originally fixed the same class of issue (#105842). A broader fix could add a denylist/allowlist mechanism so unknown schemes default to disabled, but the targeted fix is adding `pr` back.
