# Issue #339622 — Terminal: Run Recent Command… only remembers first Bash pipeline from list (before “;”) over SSH

[https://github.com/microsoft/vscode/issues/339622](https://github.com/microsoft/vscode/issues/339622)

## Summary

Thanks for the detailed report — the reporter themselves could not reliably reproduce this (observed twice, most retries with the same pipeline behaved correctly), so this needs a firmer repro before it can be investigated further.

## Change summary

Over SSH, 'Terminal: Run Recent Command…' sometimes only shows the portion of a Bash pipeline list before the first ';' instead of the full command line.

## Best solution

If reproducible, the likely area is shell integration's Bash command capture in src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh — __vsc_preexec captures the current command via `builtin history 1` (when HISTCONTROL enables verify mode) or raw `$BASH_COMMAND` otherwise; `$BASH_COMMAND` only ever holds the currently-executing simple command, not the whole ';'-joined line, so if history verification isn't active for some reason (e.g. HISTCONTROL settings, or a race where the history entry for the full line isn't yet committed when the first DEBUG trap fires), only the first sub-command would be captured. This matches the reported symptom and its flakiness, but needs a confirmed repro (exact HISTCONTROL/HISTSIZE/shopt settings, and whether it also happens locally vs. only over SSH) before concluding a code change is warranted.
