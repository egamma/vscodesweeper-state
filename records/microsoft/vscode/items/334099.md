# Issue #334099 — Agents window chat tab shortcuts override terminal tabs

[https://github.com/microsoft/vscode/issues/334099](https://github.com/microsoft/vscode/issues/334099)

## Summary

Confirmed in source: the Agents window's chat-tab navigation keybindings (Cmd+Shift+[ / ]) only exclude editor-area focus, not terminal focus, so they fire ahead of the terminal's own group-navigation shortcuts on the same keys — and there's already an open PR addressing exactly this.

## Change summary

In the Agents window, pressing Cmd+Shift+[ / ] while a terminal tab is focused switches the active chat tab instead of the terminal tab.

## Best solution

Land (or iterate on) the open fix at https://github.com/microsoft/vscode/pull/330095, which should scope the chat navigation keybindings in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts (NavigateNextChatAction/NavigatePreviousChatAction, lines ~696-731) to exclude terminal focus, mirroring how #332029 already excluded session navigation.

## Evidence

- **conflicting keybindings:** src/vs/sessions/contrib/sessions/browser/sessionsActions.ts:696-731 registers NavigateNextChatAction/NavigatePreviousChatAction on Cmd+Shift+] / [ with `when: IsSessionsWindowContext && !EditorAreaFocusContext && SessionHasMultipleOpenChatsContext` — this does not exclude terminal focus.
- **terminal's own shortcuts:** src/vs/workbench/contrib/terminal/browser/terminalActions.ts:527-556 binds TerminalCommandId.FocusNext/FocusPrevious to the same mac keys (Cmd+Shift+]/[) scoped to TerminalContextKeys.focus, at KeybindingWeight.WorkbenchContrib.
- **weight ordering:** CHAT_TAB_KEYBINDING_WEIGHT = KeybindingWeight.SessionsContrib + 10 (sessionsActions.ts:543), which appears to outrank the terminal action's WorkbenchContrib weight, explaining why the chat tab wins the conflict.
- **linked fix in progress:** Open PR https://github.com/microsoft/vscode/pull/330095 "Fix chat tab shortcuts in terminal" is already targeting this exact issue.
- **prior related fix:** Issue references #332029 as having previously removed these shortcuts from session navigation, implying the same fix pattern needs to be applied to chat navigation.
