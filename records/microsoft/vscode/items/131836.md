# Issue #131836 — Self-signed certificate error when installing Python support in WSL in spite of custom root certificate correctly installed in WSL

[https://github.com/microsoft/vscode/issues/131836](https://github.com/microsoft/vscode/issues/131836)

## Summary

The core certificate-loading infrastructure was significantly improved (1.85+ loads remote OS certs, and `http.systemCertificatesNode` was added), but 2024 comments confirm users behind corporate SSL inspection still need `NODE_EXTRA_CA_CERTS` workarounds in WSL. The gap between the stated fix (comment 18) and user reality (comments 19-21) suggests an incomplete fix. Keeping open as the issue remains relevant.

## Change summary

Installing extensions in WSL fails with 'self signed certificate in certificate chain' despite custom root CA being correctly installed in the WSL system certificate store.

## Best solution

Investigate why the `http.systemCertificates` loading path (via `@vscode/proxy-agent`'s `loadSystemCertificates`) does not cover the remote extension management agent process in WSL when custom CAs are added via `update-ca-certificates`. The gap is likely in the server-side agent process (extension gallery downloads) not going through the same proxy-agent patched paths. The `http.systemCertificatesNode` setting (currently defaulting to false) may need to be enabled or the existing v1 path needs to cover the agent's download requests.
