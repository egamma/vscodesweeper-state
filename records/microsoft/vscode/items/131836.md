# Issue #131836 — Self-signed certificate error when installing Python support in WSL in spite of custom root certificate correctly installed in WSL

[https://github.com/microsoft/vscode/issues/131836](https://github.com/microsoft/vscode/issues/131836)

## Summary

The core defect remains visible on current main: remote extension downloads use the Node request path without applying certificates loaded from the remote OS trust store. The issue already has the correct `proxy` routing label and should remain open.

## Change summary

Installing extensions in WSL fails TLS validation when the corporate root CA is trusted by the WSL system store but is not explicitly supplied through `NODE_EXTRA_CA_CERTS`.

## Best solution

Make the remote Node request path used by extension gallery downloads honor the configured OS certificate loading behavior for both direct HTTPS and proxied HTTPS connections, without disabling certificate verification.
