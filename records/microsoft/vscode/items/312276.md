# Issue #312276 — Chronicle: session_refs table is always empty — ref tracking only fires for MCP tools and Copilot terminal spans

[https://github.com/microsoft/vscode/issues/312276](https://github.com/microsoft/vscode/issues/312276)

## Summary

Current source still limits reference extraction to selected agent tool calls; ordinary Git activity and prompt references remain outside that coverage. Keep this accepted, team-authored request open: no verified older canonical or concrete fix covers its full scope.

## Change summary

Expand Chronicle reference tracking beyond GitHub MCP and Copilot terminal tool calls to include ordinary Git activity and references in user prompts.

## Best solution

Make Chronicle associate relevant commits and explicit GitHub references with sessions across ordinary workflows, consistently between live tracking and reindexing. First settle attribution when several sessions share a repository and distinguish issue references from PR references without guessing.

## Evidence

- **Existing capability and remaining gap:** extensions/copilot/src/extension/chronicle/vscode-node/sessionStoreTracker.ts subscribes to completed OTel spans and chat-session disposal. _handleToolSpan populates refs through GitHub MCP and terminal-tool extraction; _handleAgentSpan stores user messages without extracting references. No Git event subscription exists in this tracker.
- **Extraction remains narrow:** extensions/copilot/src/extension/chronicle/common/sessionStoreTracking.ts recognizes only runInTerminal and run_in_terminal as terminal tools. extractRefsFromTerminal handles gh pr create/checkout/view/merge, gh issue create, and git commit output. Thus gh pr merge already has partial coverage, contrary to the report's example, but ordinary terminal activity, prompt references, and the other requested commands remain uncovered.

Reindexing cannot recover signals those inputs never recorded.
