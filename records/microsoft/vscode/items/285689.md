# Issue #285689 — Break up large chat files

[https://github.com/microsoft/vscode/issues/285689](https://github.com/microsoft/vscode/issues/285689)

## Summary

The maintainability debt remains on current main: the four cited chat files now total roughly 20,000 lines despite several extractions and an initial widget-contribution mechanism. This team-authored architectural task should remain open and be approached as a sequence of bounded refactors.

## Change summary

Decompose the largest chat widget, input, renderer, and stylesheet files into smaller components with stable contribution boundaries.

## Best solution

Plan an incremental decomposition around cohesive widget, input, and renderer responsibilities, expanding the existing contribution pattern where appropriate while preserving chat behavior. Start with one independently testable slice rather than attempting all four files in one change.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`
- **Validation:** For each planned slice, extend the relevant ChatWidget, ChatListRenderer, or ChatInput browser tests and run `scripts/test.sh --grep 'ChatWidget|ChatListRenderer|ChatInput'`; finish with `npm run valid-layers-check` if module boundaries change.
- **Behavior:**

  > Chat input, transcript rendering, widget lifecycle, persistence, accessibility, and layout behavior remain unchanged. Cohesive chat features can be developed and tested without adding more unrelated state and lifecycle handling to the central widget, input, or renderer classes. Each extraction must retain its existing disposal, context-key, and state-restoration behavior, with targeted regression coverage for the selected slice.
- **Trace:**

  > Current main moved the targets under src/vs/workbench/contrib/chat/browser/widget but did not eliminate the core debt: the four files total approximately 20,000 lines. ChatWidget already has IChatWidgetContrib and ChatWidget.CONTRIBS, with concrete registrations in chat.shared.contribution.ts, promptTimeline.contribution.ts, and chatInputEditorContrib.ts. ChatInputPart similarly has extracted components and focused hosts, but still coordinates many unrelated widgets, models, events, and lifecycle stores. The uncertainty begins at selecting a cohesive first slice and tracing all of its consumers and tests; this should be resolved before defining a one-PR boundary. Do not change user-visible chat behavior or undertake a wholesale rewrite while extracting that slice.
