# Issue #285689 — Break up large chat files

[https://github.com/microsoft/vscode/issues/285689](https://github.com/microsoft/vscode/issues/285689)

## Summary

This team-authored Backlog debt remains necessary: the four named chat components have moved into a widget folder but remain exceptionally large, and no commit referencing this issue establishes completion. The broad contribution-oriented decomposition should be planned before implementation.

## Change summary

Decompose the large chat input, widget, renderer, and stylesheet files into smaller, independently maintained components.

## Best solution

Incrementally separate cohesive chat widget and input responsibilities, using the existing widget-contribution mechanism where appropriate, while preserving current chat behavior and keeping the stable widget core small.

- **Behavior:**

  > The chat widget, input, response list, and styling must retain their current user-visible behavior while becoming maintainable as smaller cohesive components. Input attachments, model and mode selection, notices, confirmations, response rendering, scrolling, focus, accessibility, and layout must remain unchanged. Acceptance requires the existing widget, renderer, and affected input suites to pass, with focused tests added where an extracted responsibility lacks coverage.
- **Trace:**

  > Current main places the four files under src/vs/workbench/contrib/chat/browser/widget, but they remain 4,230–6,017 lines each. ChatInputPart directly coordinates many independent feature widgets and their lifecycle, while ChatWidget owns the main list, input, welcome, transcript, editing, layout, and session state. The planning session should inventory cohesive responsibilities and their service, lifecycle, DOM, CSS, and test dependencies before choosing staged extraction boundaries. Preserve public chat contracts and all user-visible behavior; do not combine this debt work with feature changes.
