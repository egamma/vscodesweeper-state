# Issue #44941 — Proxy parameters are ignored and user-settings are missing a proxy-bypass option

[https://github.com/microsoft/vscode/issues/44941](https://github.com/microsoft/vscode/issues/44941)

## Summary

The original all-or-nothing report has narrowed but remains necessary: a maintainer confirmed that `--proxy-server` and `--proxy-bypass-list` work while `--ignore-certificate-errors` is still not honored outside Chromium's network stack, and later users report unresolved no-proxy/bypass behavior. The accepted `bug` label and Backlog milestone rule out a judgment close, and no verified older canonical with the same observable symptom is available.

## Change summary

Make command-line proxy, bypass, no-proxy, and certificate options apply consistently to JSON schema loading and other non-Chromium networking paths, with an equivalent proxy-bypass setting where needed.

## Best solution

Keep the issue as the compatibility gap between Chromium networking and Node/extension-host networking, then define and test which command-line proxy and TLS switches must be propagated to each request path. Reconcile the newer bypass-setting request at https://github.com/microsoft/vscode/issues/200464 without treating that younger issue as the canonical for this re-reviewed report.
