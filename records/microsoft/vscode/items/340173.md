# Issue #340173 — Automations: choosing a folder in the automation dialog's workspace picker doesn't add it to history

[https://github.com/microsoft/vscode/issues/340173](https://github.com/microsoft/vscode/issues/340173)

## Summary

Confirmed from source: AutomationsWorkspacePicker overrides `_shouldPersistSelection()` to return `false`, which also suppresses the `addRecentWorkspace` call in the shared `_selectFolder` path, so any folder browsed in the automation dialog never lands in recent-workspace history. Freshly filed by a team member, no fix exists yet — keeping open.

## Change summary

Choosing a folder via the automation dialog's workspace picker doesn't add it to the recent-workspace history for future pickers.

## Best solution

Split the single `_shouldPersistSelection()` flag in sessionWorkspacePicker.ts into two concerns — persisting the 'checked' workspace (should stay suppressed for automations) vs. adding a newly picked folder to the shared recents list (should still happen) — so AutomationsWorkspacePicker keeps its checked-state suppression but no longer blocks `addRecentWorkspace`.
