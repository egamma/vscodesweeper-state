# Issue #340552 — Data loss: Agent Host restores existing Copilot CLI sessions with 0 turns and permanently deletes them via empty-session GC

[https://github.com/microsoft/vscode/issues/340552](https://github.com/microsoft/vscode/issues/340552)

## Summary

Thanks for the detailed logs. Current main no longer lets GC delete a session that was restored from storage, so the destructive half of this report looks mitigated. The cause of the spurious 0-turn restore is still unknown, and there is no deterministic repro. I can't cite a specific fix commit, so this stays open and asks for confirmation on a current build.

## Change summary

An existing Copilot CLI session is sometimes restored with 0 turns. Empty-session GC then permanently deletes its persisted data.

## Best solution

Keep the draft-only GC guard in AgentService._maybeScheduleSessionGc and _runSessionGc. Find why a failed or interrupted history load, such as getMessages failing during a Copilot client restart, ends up as an empty restored state. A failed restore should surface a retryable error instead of an empty session.

## Evidence

- **current GC guard:** src/vs/platform/agentHost/node/agentService.ts, _maybeScheduleSessionGc (~L7249) only schedules GC when stateManager.isUnusedDraft(key) is true. Its doc comment says a session restored from durable storage, or one that ever had a turn, is never a candidate, because 'an empty state is also what a failed history load ... leave[s] behind'. _runSessionGc (~L7305) aborts when isUnusedDraft === false. This matches the deletion path in the report.
- **residual gap:** _runSessionGc still proceeds when the state entry is absent (evicted). The comment says absent means evicted and never came back. A restored session that was evicted could still reach disposeSession if isUnusedDraft only returns false for entries still in state. I did not trace this fully.
- **fix commit not identified:** The checkout history is shallow. The only commit that adds isUnusedDraft is 0cc5212573a6f95ad49962c7032cb769c85cfe85, an unrelated experiment-flag change that does not reference this issue. I can't cite it as the fix.
- **root cause of the 0-turn restore:** Unknown. The first incident involved a client restart during resume (code -32097). The second incident has no clear trigger, so it can't be reproduced from the report.
- **related:** https://github.com/microsoft/vscode/issues/340687 reports older chat sessions disappearing when opened on Insiders. It may share the restore-failure cause, but I haven't verified that.
