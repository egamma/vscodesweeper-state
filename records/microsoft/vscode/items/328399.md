# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Widely-confirmed macOS regression (15+ 👍, over a dozen independent reproductions with detailed OS-level diagnostics) where LAN traffic from VS Code's child processes is denied at the NECP/TCC layer starting in 1.131; a collaborator could not reproduce on his own machine and asked for a bisect, and no fix has landed on main yet, so this needs continued investigation rather than any close.

## Change summary

On macOS, VS Code 1.131+ silently blocks Local Network access (ping/ssh/docker/dotnet to LAN IPs) for the integrated terminal and Remote-SSH, while Terminal.app and VS Code 1.130 work fine on the same machine/network.

## Best solution

Needs an owning collaborator to correlate the Electron 42.6→42.7 bump (and later 42.8.x) with a change in how the app requests/retains the macOS Local Network (NECP/TCC) entitlement for spawned child processes — likely in build/darwin signing or Electron's own sandbox/network entitlement handling — confirmed via the requested vscode-bisect run and Console/NECP tracing before any fix is attempted; current main (electron 42.8.1 per package.json) has no evidence of a targeted fix landing.
