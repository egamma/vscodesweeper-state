# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Genuine, still-unresolved regression affecting many macOS users; the discussion shows highly inconsistent results across VS Code versions and macOS builds (some report 1.134/nightly fixes it, others still see it on 1.134, some only recover via a workaround), which points to an interaction between Electron's hardened-runtime/Local-Network entitlement and macOS Tahoe's per-user TCC state rather than a clean, verifiable core code fix — already correctly labeled `upstream`/`regression`, so it should stay open.

## Change summary

On macOS, VS Code 1.131+ intermittently loses OS-level Local Network access for the integrated terminal and Remote-SSH (ping/ssh to LAN IPs fail with 'No route to host'), while 1.130 and earlier work; downgrading or launching the app binary directly from a terminal are reported workarounds.

## Best solution

Keep tracking as an upstream/macOS TCC + Electron entitlement interaction; a maintainer should compare the darwin build's entitlements/signing (build/azure-pipelines/darwin/app-entitlements.plist, build/darwin/sign.ts) and Electron version across 1.130→1.131 and correlate with the per-user TCC duplicate-entry symptom (comment from izzomd citing Apple TN3179) rather than closing until a specific commit or Electron/macOS fix is confirmed by multiple reporters after the reopen.
