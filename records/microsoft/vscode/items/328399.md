# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Well-corroborated regression (multiple independent macOS reporters, workaround via downgrade) but a VS Code collaborator has been unable to reproduce it and no root cause has been isolated yet, so this must stay open pending the requested bisect results — it's already under active, ongoing investigation, not stale.

## Change summary

On macOS 1.131+, VS Code's spawned child processes (integrated terminal shell, Remote-SSH's ssh subprocess) lose Local Network TCC access that worked fine in 1.130, blocking LAN ping/ssh even though Terminal.app and other apps are unaffected.

## Best solution

Needs a maintainer-driven bisect/TCC investigation (deepak1556 is already engaged) to pin down what changed in the 1.131 packaging/entitlements or process-spawn path that causes macOS to silently revoke or fail to grant the Local Network TCC permission for VS Code's child processes; keep open until a bisect confirms a specific commit/PR.
