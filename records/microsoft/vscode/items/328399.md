# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Genuine, widely-confirmed macOS regression (15+ reactions, a dozen independent confirmations) where VS Code's child processes lose Local Network (LAN) access after the 1.130→1.131 Electron bump; a collaborator is already actively investigating via bisect but hasn't pinned the root cause or landed a fix, so this must stay open.

## Change summary

On macOS, VS Code 1.131+ (Electron 42.7+) silently loses Local Network TCC permission for its integrated terminal and Remote-SSH child processes, breaking ping/ssh/docker/db connections to LAN hosts that work fine in 1.130 and in Terminal.app.

## Best solution

Maintainers (deepak1556 is already engaged) need to finish the bisect/root-cause work on the Electron 42.6→42.8 upgrade path and the macOS Local Network (NECP/TCC) entitlement handling for spawned child processes; likely belongs in the Electron sandbox/entitlements plumbing (build/darwin packaging or Electron's own network-extension helper) rather than app TypeScript code.
