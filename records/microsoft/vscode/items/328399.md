# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Real, widely-confirmed regression (20+ upvotes, dozens of independent reproductions with detailed NECP/TCC diagnostics) affecting macOS Local Network access from VS Code's child processes since 1.131; a collaborator could not repro on their machine and later reports about 1.134 are contradictory, so there's no citable fix commit yet — this must stay open.

## Change summary

On macOS, VS Code 1.131+ silently blocks Local Network (LAN) traffic — ping/ssh/db connections — from the integrated terminal and Remote-SSH/extension child processes, even though 1.130 and Terminal.app work fine on the same machine/network.

## Best solution

A collaborator (deepak1556) needs to pin down the exact TCC/NECP entitlement or Electron-bump interaction (candidates raised in comments: Electron 42.6→42.7 bump, `build/darwin/sign.ts` entitlements, bundle executable/symlink changes in PR #326502) using the community's bisect data and the detailed traffic-fingerprint diagnosis in the thread (broadcast/mDNS/LAN-unicast blocked, gateway/internet allowed); until a specific commit is confirmed to fix it, keep this open rather than closing on the unconfirmed 1.134 reports.
