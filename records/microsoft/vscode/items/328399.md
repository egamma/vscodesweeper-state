# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Genuine, widely-reproduced macOS regression around Local Network TCC permission handling for VS Code's process tree (terminal, Remote-SSH, extension child processes) since 1.131; reports remain inconsistent across 1.131–1.135 and macOS 26.5/26.6, so this is not yet resolved reliably enough to close.

## Change summary

On macOS 1.131+, VS Code's spawned processes (integrated terminal, Remote-SSH ssh, extensions) lose Local Network access even with the permission granted, breaking LAN connectivity that worked on 1.130.

## Best solution

Needs an engineer with a real macOS 26.x machine to trace how the Local Network TCC entry (tied to NSLocalNetworkUsageDescription in build/darwin/sign.ts and the app's code signature/entitlements) is being requested/retained across the Electron bump between 1.130 and 1.131+, since some users see it resolved by 1.134/1.135 while others on the same OS build still fail — likely an interaction between the app's re-signed bundle identity and macOS's per-binary Local Network TCC cache, not a simple code regression fixable from source alone.
