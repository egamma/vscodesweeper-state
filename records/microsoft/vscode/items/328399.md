# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Real, reopened regression: macOS Local Network access breaks for VS Code's spawned processes (terminal, Remote-SSH, language runtimes) starting around 1.131, tied to Electron/macOS TCC entitlement handling — already labeled `upstream`, and the thread shows it is not reliably fixed even in 1.133/1.134, so this should stay open rather than close.

## Change summary

On macOS, VS Code 1.131+ silently loses previously-granted Local Network permission for child processes (integrated terminal, Remote-SSH, spawned tools), causing 'No route to host' errors that don't occur on 1.130 or in other terminal apps.

## Best solution

Keep tracking upstream — likely an Electron/Chromium macOS sandbox or code-signing/entitlement change interacting with Apple's Local Network TCC database; the fix belongs in how VS Code's Electron app requests/retains the `com.apple.security.network.client`/Local Network entitlement across app updates, not in this repo's TypeScript sources (no entitlement/plist files exist in this checkout). Needs a maintainer with macOS release-signing access to compare the 1.130 vs 1.131+ app bundle entitlements and codesign diffs.
