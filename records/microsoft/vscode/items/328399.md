# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Real, still-unresolved macOS Local Network/TCC regression already labeled `bug`/`upstream`/`macos`/`regression`; comment evidence is mixed and inconsistent (some report 1.134/1.135 fixed it, many others on the same builds still see it, and workarounds vary — launching from Terminal, deleting duplicate 'Local Network' TCC entries, reinstalling), so no clean fix can be cited and this stays open.

## Change summary

Starting with VS Code 1.131 on macOS, the app's spawned processes (integrated terminal shell, Remote-SSH's ssh subprocess) lose Local Network access even though the system permission toggle appears granted, breaking LAN ping/SSH that worked fine on 1.130.

## Best solution

Investigate whether VS Code's macOS signing/update pipeline is causing duplicate or stale 'Local Network' TCC entries for the app bundle (per multiple user reports of seeing two Code/Electron entries in System Settings after updating), which would explain why some users self-resolve by deleting the duplicate entries or launching the raw Electron binary from a terminal instead of the app bundle; this is an Apple TCC/Electron entitlement interaction issue, not something visible or verifiable in this source checkout (no entitlements/signing plist files are present here), so it needs an engineer with a real macOS+Electron TCC debugging setup rather than a source-only fix.
