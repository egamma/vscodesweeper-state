# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Active, reopened regression: many independent macOS users (21 upvotes, ~30 comments) confirm VS Code's spawned child processes (integrated terminal, Remote-SSH, extensions) lose Local Network access starting at 1.131, coinciding with an Electron 42.6→42.7 bump; a collaborator could not repro on their machine and the picture is still messy across 1.131–1.135, so this needs continued maintainer/Apple-side investigation, not a close.

## Change summary

On macOS, VS Code 1.131+ silently denies LAN traffic (ping/ssh/docker/db connections) from its child processes even though Local Network permission appears granted, while 1.130 and Terminal.app work fine.

## Best solution

Keep open and continue the regression bisect with @deepak1556 (comment from 2026-08-06) — likely tied to the Electron 42.6→42.7 update or a macOS/TCC entitlement-handling change; some users report partial improvement on 1.134/1.135 but others still fail, so this isn't resolved yet and needs a definitive root-cause fix (or Apple-side workaround) before closing.
