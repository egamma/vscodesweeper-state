# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Well-documented macOS Local Network / TCC regression between 1.130 and 1.131, independently confirmed by multiple reporters with a consistent workaround (downgrade), but a VS Code collaborator could not reproduce it on their own machine and has asked for a bisect run — this is a live, actively-investigated regression, not something to close or park at needs-info.

## Change summary

On macOS, VS Code 1.131+ silently loses Local Network access (integrated terminal ping/ssh, Remote-SSH, extension LAN connections all fail with 'No route to host'), while 1.130 and earlier work fine on the same machine/network.

## Best solution

Continue the collaborator-led investigation in-thread (deepak1556 is already engaged); the fix likely belongs in the macOS app bundling/entitlement or Electron-upgrade path (Electron 42.6.0 → 42.7.0 between 1.130 and 1.131 per a commenter) rather than in TypeScript source — no entitlement or Info.plist changes were found in this range in the checkout, so root cause is probably in Electron's TCC/bundle-signing behavior and needs the requested `@vscode/vscode-bisect` results plus a Console.app trace to pin down.
