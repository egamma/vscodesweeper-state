# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Legitimate regression under active maintainer investigation: multiple independent users on 1.131/1.132 report Local Network (macOS TCC) access breaking for the integrated terminal and Remote-SSH, with a consistent workaround of downgrading to 1.129/1.130; a VS Code collaborator has engaged and requested a bisect to pin the exact regressing commit.

## Change summary

On macOS, VS Code 1.131+ appears to break the app's Local Network (TCC) permission for child processes (terminal, ssh), causing LAN connections to fail with 'No route to host' even though they work in Terminal.app and on 1.130.

## Best solution

Let the collaborator (deepak1556) finish the bisect they requested to identify the exact commit/version that corrupted the Local Network TCC state, then trace the macOS bundling/entitlement or process-spawning change in that range (main/vscode.xcodeproj or the Electron bundling scripts) and fix or revert it; this needs a real macOS TCC investigation, not a source-only fix.
