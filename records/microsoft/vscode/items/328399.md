# Issue #328399 — macOS: VS Code 1.131 blocks Local Network access for integrated terminal/Remote-SSH (regression, works on 1.130)

[https://github.com/microsoft/vscode/issues/328399](https://github.com/microsoft/vscode/issues/328399)

## Summary

Widely confirmed macOS regression: VS Code's child processes (integrated terminal, Remote-SSH, extensions) lose Local Network access starting around 1.131, correlating with an Electron 42.6→42.7 bump; a VS Code collaborator could not reproduce it and reports for 1.133–1.135 are mixed (some fixed, many still broken), so this is not yet resolved and stays open.

## Change summary

On macOS, VS Code 1.131+ blocks Local Network (LAN) traffic from processes it spawns (terminal, ssh, extensions), even though the Local Network TCC permission appears granted; downgrading to 1.130 restores access.

## Best solution

Needs an engineer with access to the exact affected macOS/Electron combination to trace how the Local Network TCC entitlement is (re)requested for child processes across the 1.130→1.131 Electron bump (42.6.0→42.7.0) and confirm whether the fix already landed in Electron 42.8.1 (used in 1.134/1.135) or whether VS Code needs additional entitlement/bundle changes; the bisect tool run requested by @deepak1556 (npx @vscode/vscode-bisect -q insider -g 1.129 -b 1.131) should be re-attempted by an affected reporter to pin the exact regression range.
