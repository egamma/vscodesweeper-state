# Issue #321557 — [Copilot] Display info about tokens spent on the concrete tasks and on the whole session

[https://github.com/microsoft/vscode/issues/321557](https://github.com/microsoft/vscode/issues/321557)

## Summary

A real user-facing gap remains: VS Code displays per-turn and session credit totals, while detailed input, output, and cached-token accounting is confined to internal telemetry and Chat Debug surfaces. No verified canonical issue or open fixing PR owns this broader request, so it should remain open for product and presentation design.

## Change summary

Expose input, output, and cached-token usage for each Copilot task and aggregate those values for the whole session.

## Best solution

Design a normal user-facing usage view that presents provider-reported input, output, and cached-token counts per turn and across the session, clearly preserving partial or unavailable counters rather than presenting them as zero. Reuse the existing Agent Host token snapshots and session information surface rather than deriving totals from displayed credit values.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/agent.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageDetails.ts`
- **Validation:** Add targeted state-adapter and chat usage-view tests showing input, output, and cached-token counters for one turn and their session aggregate, including a partial provider report where unavailable counters are not rendered as zero.
- **Behavior:**

  > Users can inspect provider-reported input, output, and cached-token usage for each completed Copilot task and for the whole current session. The presentation must distinguish an actual zero from a counter the provider did not report, and session totals must not imply completeness when one or more turn records are partial. Existing model, credit, quota, and context-window displays remain available. Acceptance should cover a complete turn, a partial turn, and aggregation across multiple turns.
- **Trace:**

  > The normal turn footer is produced by formatTurnResponseDetails in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts and currently renders model plus credits. Session information in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageDetails.ts likewise exposes session credits and context-window usage, not cumulative billing-token categories. Provider-observed per-turn counters already exist as IAgentTurnTokenUsage summaries in src/vs/platform/agentHost/common/agent.ts and preserve known, partial, and notReported states; AgentHostTurnTracker currently reads them for telemetry. Chat Debug independently aggregates model-turn token categories in src/vs/workbench/contrib/chat/browser/chatDebug/chatDebugOverviewView.ts, demonstrating the requested values but not a suitable normal-user surface. Keep credit accounting, context-window occupancy, and billing-token accounting conceptually separate, and do not infer missing counters from credits or coerce them to zero.
- **Open decisions:**
  - Should detailed per-task token categories appear inline in each response footer or behind a task-level details affordance?
  - Should the session summary aggregate only root task turns, or also expose separate subagent and compaction usage so users can reconcile the full session cost?
  - When any provider record lacks a token category, should the session UI show a partial subtotal with an explicit incomplete indicator or withhold that category's total entirely?

## Evidence

- **existing user-facing capability:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts formats a turn footer as model plus Copilot credits, while src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageDetails.ts displays only the whole-session credit cost and current context-window token count.
- **token data exists internally:** src/vs/platform/agentHost/common/agent.ts defines per-turn provider-observed summaries with independent knownInputTokens, knownOutputTokens, and knownCacheReadTokens fields and explicit known/partial/notReported states; AgentHostTurnTracker currently consumes these snapshots for telemetry rather than the normal chat UI.
- **debug-only aggregation:** src/vs/workbench/contrib/chat/browser/chatDebug/chatDebugOverviewView.ts already aggregates total input, output, and cached-input tokens from model turns, but this is the Chat Debug overview rather than the ordinary session experience requested by users.
- **canonical search:** The closest open result, https://github.com/microsoft/vscode/issues/311705, concerns BYOK/Ollama dropping usage in the context widget; it does not request the same per-task and whole-session Copilot accounting UI and therefore does not satisfy the stronger duplicate bar for this re-reviewed item.
- **human interest:** The request has four issue-body upvotes, and a contributor independently asked why VS Code does not expose the session total already shown by Copilot App and Copilot CLI.
