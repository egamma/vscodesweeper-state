# Issue #91711 — Diagnostic link hovers should show target

[https://github.com/microsoft/vscode/issues/91711](https://github.com/microsoft/vscode/issues/91711)

## Summary

The Problems panel already supplies destination tooltips, but editor diagnostic hovers and the diagnostic navigation widget still render code links without a destination tooltip. Keep this team-authored request open to settle how the remaining surfaces should reveal their targets before activation.

## Change summary

Expose diagnostic code links' destination URLs before users click them.

## Best solution

Preserve the existing Problems panel tooltips and provide a consistent destination-preview affordance for diagnostic links in editor hovers and the diagnostic navigation widget. Resolve the thread's concern about nested tooltips before completing the remaining editor surfaces.

  > Users should be able to inspect a diagnostic code link's destination before opening it. The Problems panel already provides URL tooltips, while the editor hover and diagnostic navigation widget lack an explicit destination-preview affordance. Acceptance should cover all these surfaces, retain the displayed diagnostic code, and preserve existing link activation. The editor-hover presentation needs a maintainer decision because the discussion explicitly questions a tooltip inside an existing hover.
- **Trace:**
