# Issue #339752 — Manage settings not followed when enabling sandbox

[https://github.com/microsoft/vscode/issues/339752](https://github.com/microsoft/vscode/issues/339752)

## Summary

Security-sensitive: this describes a managed-policy (sandbox network lockdown) bypass via the user-editable allowed-domains list, so per policy this must stay open for a human to handle rather than be triaged to a close.

## Change summary

With a managed policy setting `userPolicy.network.allowOutbound: false`, outbound network requests to a domain listed in the user-editable `chat.agent.sandbox.network.allowedDomains` setting still succeed after `/sandbox enable`.

## Best solution

A maintainer on the agent-host/sandbox team should decide whether the managed `allowOutbound: false` policy is meant to override user-level domain allowlists entirely, and if so, make `SandboxSettingsResolutionHelper`/the domain-restriction resolution path in `sessionSandbox.ts` and `terminalChatAgentToolsConfiguration.ts` enforce that precedence.
