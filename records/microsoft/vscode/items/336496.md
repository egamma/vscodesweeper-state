# Issue #336496 — Perf: per-row getMenuActions is uncached; tree find widget turns every update into a full list rebuild (20s freeze)

[https://github.com/microsoft/vscode/issues/336496](https://github.com/microsoft/vscode/issues/336496)

## Summary

The menu-resolution portion was optimized by the merged PR, but the primary full-tree refilter remains directly visible on current main. The issue should stay open for the bounded tree-find performance fix.

## Change summary

Updating a populated tree while its find widget contains a pattern synchronously refilters and rebuilds the entire rendered list, causing a long UI freeze when row rendering is expensive.

## Best solution

Preserve correct find results after tree-model changes while coalescing redundant refilters so a burst of updates causes at most one full rendered-list splice. Retain the targeted model-update behavior and avoid changing normal find matching or tree rendering semantics.
