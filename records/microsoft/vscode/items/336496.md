# Issue #336496 — Perf: per-row getMenuActions is uncached; tree find widget turns every update into a full list rebuild (20s freeze)

[https://github.com/microsoft/vscode/issues/336496](https://github.com/microsoft/vscode/issues/336496)

## Summary

Both defects are confirmed present on current main by direct source inspection: MenuService.getMenuActions constructs an uncached MenuImpl per call, and FindController's onDidChangeModel handler calls tree.refilter() synchronously, bypassing IndexTreeModel's own refilterDelayer coalescing. This is a well-diagnosed, actionable perf report — routing to the relevant areas rather than closing.

## Change summary

Tree find widget triggers an uncached, uncoalesced menu-action rebuild across every visible row on each model update, causing multi-second UI freezes when many view/item/context menu items are registered.

## Best solution

Two independent fixes: (1) cache/memoize the grouped+sorted menu structure in MenuService.getMenuActions / MenuImpl keyed on MenuId (only the context-match pass is per-call-context-dependent), in src/vs/platform/actions/common/menuService.ts; (2) route FindController's tree.refilter() calls in src/vs/base/browser/ui/tree/abstractTree.ts through the existing refilterDelayer/microtask coalescing in indexTreeModel.ts instead of calling refilter() synchronously on every splice.
