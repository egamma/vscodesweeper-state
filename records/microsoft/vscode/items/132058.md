# Issue #132058 — `debug.startDebugging()` can't find configuration from `.code-workspace` file

[https://github.com/microsoft/vscode/issues/132058](https://github.com/microsoft/vscode/issues/132058)

## Summary

This remains a valid debug API feature request: named `debug.startDebugging` lookups are intentionally folder-scoped today, while multiple users need configurations declared in the active `.code-workspace`. No verified older issue with the same observable symptom or completed implementation is identified, so the Backlog item should remain open.

## Change summary

Allow named `debug.startDebugging` calls and related `serverReadyAction.startDebugging` flows to resolve launch configurations declared in a `.code-workspace` file.

## Best solution

Define and implement workspace-level named-configuration lookup for `debug.startDebugging`, including how the API selects between folder and `.code-workspace` configurations when names collide, and keep `serverReadyAction` behavior consistent with that resolution.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostDebugService.ts`, `src/vs/workbench/contrib/debug/browser/debugService.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`
- **Validation:** Add debug service/API tests with a multi-root `.code-workspace` launch configuration proving that a named `debug.startDebugging` request resolves it, that `serverReadyAction` follows the same lookup, and that folder-local launch configurations retain the agreed precedence.
- **Behavior:**

  > An extension can start a named debug configuration declared in the active `.code-workspace` without duplicating it into a folder's `.vscode/launch.json`. The same named lookup works when initiated by `serverReadyAction` with `action: "startDebugging"`. Existing folder-local named configuration behavior remains compatible, and name collisions resolve according to an explicitly documented rule.
- **Trace:**

  > The public API currently documents named lookup in the supplied folder's `.vscode/launch.json`, and maintainer comment https://github.com/microsoft/vscode/issues/132058 confirms workspace-file launch configurations are unsupported. The extension-host request enters through the debug API service and is resolved by the workbench debug service, while `serverReadyAction` provides a second caller of named start-debugging behavior. The implementation boundary is named configuration discovery and selection: do not alter inline `DebugConfiguration` launches or general debug-adapter behavior. Related extension report https://github.com/hbenl/vscode-mocha-test-adapter/issues/172 demonstrates downstream demand but does not own this core API change.
- **Open decisions:**
  - When a folder-local and `.code-workspace` launch configuration have the same name, which one should a named `debug.startDebugging` call select?
  - Should passing a specific `WorkspaceFolder` continue to restrict lookup to that folder, or may it fall back to the active `.code-workspace` launch section?
  - Should workspace-level named lookup require an omitted folder argument, or should existing calls that pass a folder gain the fallback automatically?
