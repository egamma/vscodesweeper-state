# Issue #315926 — apply_patch PostToolUse hook fires before file is actually edited

[https://github.com/microsoft/vscode/issues/315926](https://github.com/microsoft/vscode/issues/315926)

## Summary

Valid bug: PostToolUse hook fires before file edits are flushed to disk, so external hook commands see stale content. A team member confirmed this is the current behavior and pointed to extension-powered hooks (issues #295076, #306375) as the long-term fix. Worth keeping open as a tracked gap.

## Change summary

PostToolUse hooks for file-editing tools (apply_patch, create_file, etc.) fire before the edited content is flushed to disk, causing external hook commands to read stale pre-edit file content.

## Best solution

Ensure file edits are flushed to disk before firing PostToolUse hooks for write tools, or provide an extension-powered hook mechanism (tracked in https://github.com/microsoft/vscode/issues/295076 and https://github.com/microsoft/vscode/issues/306375) that can read the in-memory buffer state directly. The second commenter's data-loss scenario (hook writes to the same file, racing the async flush) strengthens the case for a flush-before-hook guarantee.
