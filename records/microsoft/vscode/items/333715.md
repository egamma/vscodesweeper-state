# Issue #333715 — Copilot context: fork skill receives stale initial chat task

[https://github.com/microsoft/vscode/issues/333715](https://github.com/microsoft/vscode/issues/333715)

## Summary

Confirmed in source: `invokeFork` in skillTool.ts builds the subagent's task from `conversation.turns[0]` (the chat's very first message) instead of the current triggering turn, exactly matching the report — a forked skill can act on a stale, unrelated request.

## Change summary

A `context: fork` skill's subagent receives the chat's original first message as its Task instead of the message that actually invoked the skill, causing it to act on stale/unrelated intent.

## Best solution

In `SkillTool.invokeFork` (extensions/copilot/src/extension/tools/node/skillTool.ts), use the latest/current turn's request message (e.g. `conversation.getLatestTurn().request.message`, the pattern already used in agentIntent.ts) instead of `turns[0]`, so the forked subagent's Task reflects the message that triggered the skill.
