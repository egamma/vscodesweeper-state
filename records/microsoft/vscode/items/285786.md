# Issue #285786 — WSL copilot

[https://github.com/microsoft/vscode/issues/285786](https://github.com/microsoft/vscode/issues/285786)

## Summary

Verified duplicate: the older open remote-agent issue tracks the same failure where Copilot file tools reject Linux workspace paths while terminal commands continue to work. Its discussion also identifies the Windows-style path conversion and remote extension placement that produce this symptom.

## Change summary

Copilot running in a WSL workspace converts Linux paths to Windows-style paths and consequently cannot read or edit workspace files.

## Best solution

Consolidate the WSL evidence on https://github.com/microsoft/vscode/issues/280816 and ensure Copilot Chat uses its default remote workspace extension placement so Linux paths are resolved by the remote extension host.
