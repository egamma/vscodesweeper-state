# Issue #350000 — Agents window: list and open the chats of Dev Containers opened in an editor window

[https://github.com/microsoft/vscode/issues/350000](https://github.com/microsoft/vscode/issues/350000)

## Summary

Keep open: current source explicitly excludes Dev Container session handoff and restores known container providers disconnected, leaving the requested discovery and opening capability missing. The assigned 1.149.0 milestone also requires preserving this scheduled, team-authored work.

## Change summary

List chats from containers already open in editor windows and let Open in Agents Window continue the selected container chat.

## Best solution

Allow the Agents window to discover and connect to editor-opened containers and reveal their existing conversations without creating a new chat first. Preserve container host identity and existing SSH, WSL, and tunnel handoff behavior.

- **Behavior:**

  > Chats started through the Copilot harness in a Dev Container editor window appear in the Agents window without first starting another container session there. Open in Agents Window opens the selected existing conversation, rather than a new source-folder draft. Previously known containers expose chats created since their last Agents-window connection when their editor window is open.
- **Trace:**

  > resolveAndOpenRemoteSession in src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts rejects Dev Container authorities before calling the remote workspace handoff service. The handoff test explicitly expects that rejection, and the remote provider specification documents it. DevContainerAgentHostService._restoreProviders reconstructs stored providers, while _ensureProvider marks them disconnected and supplies an on-demand connector; this does not provide editor-window container discovery. Existing host sharing therefore supplies conversations only after a connection exists. The unresolved architecture is how editor-opened container inventory and connection demand reach the Agents window. Preserve exact conversation identity, existing cancellation behavior, and SSH/WSL/tunnel semantics; latency and transient labeling work in https://github.com/microsoft/vscode/issues/349395 are separate acceptance concerns.
