# Issue #85930 — In some places, allow to use URL in addition to URI

[https://github.com/microsoft/vscode/issues/85930](https://github.com/microsoft/vscode/issues/85930)

## Summary

Keep open: the public openExternal and DocumentLink APIs still require Uri, so the requested supported URL-preserving API remains missing. The undocumented string workaround only partially covers the request, and remote-resource semantics still need an API-owner decision.

## Change summary

Allow URL values alongside Uri in openExternal and DocumentLinkProvider without losing externally meaningful URL encoding.

## Best solution

Provide a supported external-URL contract for both extension APIs that preserves URL semantics while retaining existing Uri behavior. Settle how URL targets interact with remote resource transformation and tunneling before implementation.

MainThreadWindow.$openUri preserves the string only when no URI transformation is detected, exposing why public typing alone does not settle remote semantics. - **Open decisions:**
