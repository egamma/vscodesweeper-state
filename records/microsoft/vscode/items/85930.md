# Issue #85930 — In some places, allow to use URL in addition to URI

[https://github.com/microsoft/vscode/issues/85930](https://github.com/microsoft/vscode/issues/85930)

## Summary

The requested API capability remains absent on main and has enough community support for the Backlog. Existing routing is correct, and no fixing PR or canonical replacement owns the full request.

## Change summary

Allow extension APIs such as `env.openExternal` and `DocumentLink` to accept standard `URL` values without lossy URI re-encoding.

## Best solution

Design a stable `URL` or string-compatible API path that preserves external URL text while retaining URI transformation for remote and file resources, then apply the same semantics to document links with extension-host serialization tests.

## Evidence

- **partial internal workaround:** src/vs/workbench/api/common/extHostWindow.ts accepts `string | URI`, and src/vs/workbench/api/browser/mainThreadWindow.ts preserves an unchanged string, but src/vs/workbench/api/common/extHost.api.impl.ts and the public declaration still expose only URI.
- **document-link path:** src/vs/workbench/api/common/extHostTypeConverters.ts serializes `DocumentLink.target` directly as the internal URI representation, so the second API surface identified by the issue remains unresolved.
- **remote design constraint:** The maintainer discussion explains that remote extension-host URIs require transformation, so accepting URL values needs explicit semantics rather than only a declaration-file overload.
