# Issue #207765 — Cannot use arrow keys to go to toggle icon in notebook find widget

[https://github.com/microsoft/vscode/issues/207765](https://github.com/microsoft/vscode/issues/207765)

## Summary

Still reproduces on main despite PR #306559: the merged fix pushes `_findFilter.container` (a non-focusable div) into the arrow-key navigation list, but focus actually lands on the actionbar's child element inside it, so `indexOf(activeElement)` never matches. PR #308429 is open with a proposed fix; the issue should stay open until that or another fix lands.

## Change summary

Arrow key navigation in the notebook find widget skips the filter (funnel) toggle button, cycling only through the first three toggles.

## Best solution

Land a corrected fix that pushes the actually-focusable element (the actionbar's anchor inside `_findFilter.container`) into `getToggleDomNodes()`, or makes the container itself focusable. PR https://github.com/microsoft/vscode/pull/308429 is actively working on this and should be reviewed/landed.

## Evidence

- **MEMBER confirmation:** justschen (MEMBER) confirmed on 2026-04-06 that the bug still reproduces: 'still seeing this looping on the first 3 in this list'.
- **open PR:** https://github.com/microsoft/vscode/pull/308429 is open with a revised fix attempt and includes automated tests; awaiting maintainer review.
- **root cause in source:** In src/vs/base/browser/ui/findinput/findInput.ts, the arrow-key handler checks `indexes.indexOf(<HTMLElement>this.domNode.ownerDocument.activeElement)` — the activeElement is the focusable <a> tag inside the actionbar, not the container div, so the filter button is effectively invisible to arrow navigation.
