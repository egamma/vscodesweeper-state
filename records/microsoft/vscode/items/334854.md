# Issue #334854 — Remote session artifact fails to open because its Windows path is resolved locally

[https://github.com/microsoft/vscode/issues/334854](https://github.com/microsoft/vscode/issues/334854)

## Summary

Team-authored bug report (keep-open regardless), and I traced a concrete, localized root cause on main: session-artifact `uri`/`link` fields are parsed as raw URIs and never passed through the provider's existing `_diffUriMapper()` remote-resource wrapper, so a remote Windows agent's file artifact is opened as a local `file:` path instead of a `vscode-agent-host://` one.

## Change summary

Opening a Markdown artifact chip produced by an agent session on a remote Windows host fails because its `c:/...` path is resolved as a local file instead of being routed through the remote agent host connection.

## Best solution

In `agentHostSessionArtifacts.ts:toSessionArtifact`, wrap `artifact.uri` (and `link` where it can be a filesystem path) through the same per-provider resource mapper used for diffs (`_diffUriMapper()` in `baseAgentHostSessionsProvider.ts`, overridden in `remoteAgentHostSessionsProvider.ts`/`localAgentHostSessionsProvider.ts` to call `toAgentHostUri`) before building the `ISessionArtifact`, and thread that mapper into `partitionSessionArtifacts`/`getPresentedArtifacts` call sites (lines ~398 and ~1049 of `baseAgentHostSessionsProvider.ts`).
