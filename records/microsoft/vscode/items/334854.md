# Issue #334854 — Remote session artifact fails to open because its Windows path is resolved locally

[https://github.com/microsoft/vscode/issues/334854](https://github.com/microsoft/vscode/issues/334854)

## Summary

Traced this to a real gap in the Sessions provider: artifact URIs from a remote agent host session's meta are never mapped through the same remote-authority translation the working directory and project URIs get, so a Windows-remote path opens as a local file and fails.

## Change summary

Clicking a Markdown artifact chip from a completed session on a remote Windows agent host tries to open the raw `c:/...` path locally instead of through the remote agent host filesystem provider.

## Best solution

In `BaseAgentHostSessionsProvider`, map each artifact's `uri` through the same `mapProjectUri`/`mapWorkingDirectoryUri`-style remote-authority translation (`toAgentHostUri`) before exposing it on `this.artifacts`, so remote file-scheme artifact URIs resolve through the agent host filesystem provider instead of the local one.
