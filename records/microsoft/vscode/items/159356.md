# Issue #159356 — Notebook API: Support Language Providers for Notebook Output Cells

[https://github.com/microsoft/vscode/issues/159356](https://github.com/microsoft/vscode/issues/159356)

## Summary

The capability remains missing on current main: inline notebook outputs use the webview renderer rather than the text-model language-feature pipeline. This accepted Backlog request has 43 upvotes and should remain open under its existing notebook-output classification.

## Change summary

Allow notebook-scoped semantic-token and document-link providers to operate on inline JSON output cells.

## Best solution

Define a supported bridge between inline notebook output rendering and notebook-scoped language providers, or introduce an equivalent output-specific API, while preserving the webview renderer boundary.

## Evidence

- **current inline architecture:** src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts:2632-2645 passes output items directly to `renderers.render` inside the notebook webview; this path does not create an editor text model for language providers.
- **limited existing capability:** src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts:606-632 creates an `ITextModel` only when an output URI is resolved for the separate output text/preview editor, so it does not satisfy the central request for providers in inline JSON output cells.
- **provider boundary:** src/vs/editor/common/languageFeatureRegistry.ts:92-181 evaluates semantic-token and link providers against `ITextModel` instances and their resolved notebook metadata, leaving inline webview-rendered output outside that pipeline.
- **community acceptance:** The issue has 43 upvotes, and https://github.com/microsoft/vscode/issues/159356#issuecomment-1235021750 records that it passed the community threshold and was moved to Backlog.
- **affected extension:** https://github.com/DeltaXML/vscode-xpath-notebook/issues/10 remains open and documents the missing highlighting and node navigation, with an HTML-renderer workaround rather than restoration of the requested provider support.
