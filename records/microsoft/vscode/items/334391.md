# Issue #334391 — Windows: CLI plugin discovery watchers block plugin install, update, and uninstall

[https://github.com/microsoft/vscode/issues/334391](https://github.com/microsoft/vscode/issues/334391)

## Summary

Thanks for the detailed diagnosis — traced in the current source and it checks out: AbstractAgentPluginDiscovery._toPlugin does create non-recursive watchers directly on the plugin root and its component directories, which matches the reported Windows access-denied failures. Already correctly labeled (windows, chat); the fix needs an architecture decision, so it stays open for area triage.

## Change summary

On Windows, VS Code's Copilot CLI plugin discovery holds persistent file-watcher handles inside CLI-owned plugin directories, causing 'Access is denied' failures when the CLI tries to install/update/uninstall plugins.

## Best solution

Restructure CopilotCliAgentPluginDiscovery/AbstractAgentPluginDiscovery to avoid holding persistent handles inside CLI-owned plugin directories — e.g. watch ancestor/marketplace directories recursively and rediscover components on change, rather than watching the plugin root and each component dir (commands/skills/agents/hooks) directly in agentPluginServiceImpl.ts; also exclude CLI staging directory names (`.<plugin>.tmp-<pid>-0`) from discovery.
