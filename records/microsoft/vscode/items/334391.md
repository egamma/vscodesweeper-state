# Issue #334391 — Windows: CLI plugin discovery watchers block plugin install, update, and uninstall

[https://github.com/microsoft/vscode/issues/334391](https://github.com/microsoft/vscode/issues/334391)

## Summary

Real, well-diagnosed bug: traced in current source that `AbstractAgentPluginDiscovery._toPlugin` (and `CopilotCliAgentPluginDiscovery`) creates persistent non-recursive watchers directly inside CLI-owned plugin root/component directories with no filtering of CLI staging names, matching the reported Windows handle-lock behavior exactly; already carries a real milestone (1.138.0), so it stays open regardless.

## Change summary

On Windows, VS Code's Copilot CLI plugin discovery holds persistent file-watcher handles inside CLI-installed plugin directories, causing `Access is denied` failures when the CLI tries to install/update/uninstall a plugin while VS Code is open.

## Best solution

Rework `AbstractAgentPluginDiscovery`/`CopilotCliAgentPluginDiscovery` (src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts) to watch from an ancestor (installed-plugins root or marketplace bucket) recursively instead of opening per-plugin-root and per-component (`commands`/`skills`/`agents`/`hooks`) watchers, and exclude CLI staging directory names (`.<plugin>.tmp-<pid>-0`) from discovery — this is the suggested direction in the report and matches the code paths at lines ~393, 459, 472, and 912/936.
