# Issue #225179 — Python: Improved Bracket Pair Detection for strings that contain `{{` 

[https://github.com/microsoft/vscode/issues/225179](https://github.com/microsoft/vscode/issues/225179)

## Summary

Keep this accepted Backlog request open: escaped Python f-string braces still lack the metadata that would distinguish them from structural brackets. Disabling bracket colorization is only a workaround, and the related reports do not provide a verified canonical duplicate or fixing commit.

## Change summary

Render escaped `{{` and `}}` in Python f-strings as escape sequences rather than independently colored bracket pairs, while preserving colorization inside interpolation expressions.

## Best solution

Make the built-in Python tokenization distinguish escaped literal braces from interpolation delimiters and dictionary braces. Preserve normal bracket matching and colorization for actual Python expressions without requiring users to disable the feature.

## Plan brief

- **Likely files:** `extensions/python/package.json`, `extensions/python/syntaxes/MagicPython.tmLanguage.json`
- **Validation:** In a development build with bracket pair colorization enabled, inspect tokens and rendering for `print(f'Explicit map {{1: 2}}.')` and `print(f'Explicit map keys { {1:2}.keys() }.')`. Escaped doubled braces must retain escape-sequence highlighting, while genuine interpolation and dictionary braces remain structural and colorized. Cover opening and closing escapes, single- and triple-quoted f-strings, and ordinary dictionary literals; establish an executable tokenization regression check during planning.
- **Behavior:**

  > Python f-string doubled braces represent literal escaped characters and should not receive separate bracket-pair colors. Real interpolation delimiters and dictionary braces inside expressions should continue to participate in bracket matching and colorization. Acceptance includes both opening and closing escapes and single- and triple-quoted f-strings with colorization enabled. The invalid unspaced second example in the report must not become valid Python or conceal its syntax error.
- **Trace:**

  > The built-in Python grammar is contributed by extensions/python/package.json and stored in extensions/python/syntaxes/MagicPython.tmLanguage.json. Its fstring-formatting-braces rule assigns doubled braces constant.character.escape.python, while the surrounding f-string container uses meta.fstring.python and the contribution supplies no token-type or bracket-scope overrides. The editor's TextBufferTokenizer in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/tokenizer.ts uses standard token type and balanced-bracket metadata, not escape scope names directly. This agrees with the diagnosis in https://github.com/microsoft/vscode/issues/225179, but current runtime metadata and rendering were not executed in this read-only review. Planning should establish that behavior and the regression-check mechanism before choosing an implementation. Keep genuine expression bracket behavior, Python syntax rules, and unrelated languages unchanged; https://github.com/microsoft/vscode/issues/238564 describes a separate intermittent string-coloring problem.
