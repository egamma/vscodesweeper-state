# Issue #207570 — Unable to update VS Code if authentication is previously canceled

[https://github.com/microsoft/vscode/issues/207570](https://github.com/microsoft/vscode/issues/207570)

## Summary

Keep open: multiple reporters confirmed that cancelling the macOS administrator prompt prevents subsequent updates, and the reporter reconfirmed after the information-request closure. Current source still delegates cancellation handling to Electron; no verified fix or same-symptom canonical was found.

## Change summary

Allow macOS updates to be retried successfully after cancelling the native administrator authentication prompt, without restarting VS Code.

## Best solution

Make administrator-prompt cancellation leave the macOS updater in a recoverable state with accurate feedback and a working retry. First capture Electron updater events during cancellation to establish whether recovery belongs in DarwinUpdateService or its native updater dependency.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`
- **Validation:** On a signed macOS build running under a non-admin account, allow an automatic update to request administrator credentials, cancel the prompt, then invoke Check for Updates and authenticate. Verify that the update reaches Restart to Update without quitting VS Code; repeat cancellation and retry, and confirm that uninterrupted authentication still works.
- **Behavior:**

  > Cancelling the native macOS administrator prompt during an automatic VS Code update must not permanently block updating within that application session. A subsequent Check for Updates must allow authentication and complete the update without requiring a full quit. The UI must not remain indefinitely at Downloading Update or repeatedly return to Check for Updates without progress or explanation. Acceptance includes repeated cancellation and retry, plus an uninterrupted successful update.
- **Trace:**

  > DarwinUpdateService in src/vs/platform/update/electron-main/updateService.darwin.ts forwards checks to electron.autoUpdater and derives its state from error, update-available, update-downloaded, and update-not-available events. onUpdateAvailable enters Downloading, while onError returns active states to Idle and suppresses the error text once downloading has begun. AbstractUpdateService.checkForUpdates in src/vs/platform/update/electron-main/abstractUpdateService.ts rejects checks outside Idle. The discussion at https://github.com/microsoft/vscode/issues/207570 confirms the native administrator-prompt trigger and successful updating after restarting, but does not supply the native event sequence needed to determine the root cause. Establish that sequence on a signed build before deciding whether the wrapper or Electron's updater owns recovery. Preserve normal successful updates and do not conflate this path with account authentication or download-progress feature requests.
