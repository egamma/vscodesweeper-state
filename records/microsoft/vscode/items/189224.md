# Issue #189224 — "Unicode Highlight" feature suggests incorrect locale for ignoring common characters

[https://github.com/microsoft/vscode/issues/189224](https://github.com/microsoft/vscode/issues/189224)

## Summary

Keep open: Ukrainian is still absent from the Unicode Highlight locale data, so explicitly allowing it cannot deliver the requested behavior. The older script-label request overlaps with the dialog wording but does not cover this additional locale-support gap.

## Change summary

Support Ukrainian common-character exclusions without requiring Russian locale exemptions, and offer appropriate choices in Adjust Settings.

## Best solution

Make Ukrainian common-character exclusions work independently of VS Code's display-language support. Coordinate the dialog terminology with https://github.com/microsoft/vscode/issues/160566, while retaining this issue's distinct requirement that an explicit Ukrainian allowed locale takes effect.

## Evidence

- **Current locale-support gap:** src/vs/base/common/strings.ts:1243–1254 embeds generated AmbiguousCharacters data containing ru but no uk entry. At lines 1297–1301, getInstance filters out locales absent from that data and falls back to _default when none remain. Explicitly configuring uk therefore contributes no Ukrainian exclusions; ua is not the Ukrainian language code.
- **Suggestion mechanism:** src/vs/editor/common/services/unicodeTextModelHighlighter.ts:102–123 builds notAmbiguousInLocales by enumerating AmbiguousCharacters.getLocales(), not by detecting the language of the text or selecting installed system languages. src/vs/editor/contrib/unicodeHighlighter/browser/unicodeHighlighter.ts:735–744 displays those candidates. Consequently, ru can be offered for shared Cyrillic characters while Ukrainian cannot appear.
- **Existing capabilities do not cover the ask:** editor.unicodeHighlight.allowedLocales is registered in src/vs/editor/common/config/editorOptions.ts:4432–4439, with _os and _vscode defaults. The editor resolves those defaults in unicodeHighlighter.ts:165–172, but they still depend on the finite locale table. allowedCharacters, includeStrings, and ambiguousCharacters offer broader or individual-character workarounds, not functioning Ukrainian locale support.
- **Older related issue is not a full canonical:** Verified https://github.com/microsoft/vscode/issues/160566 is open and was created on 2022-09-09. It reports the same ru suggestion for Cyrillic letters but specifically requests script-based wording. It does not request support for an explicitly configured uk locale, so it does not absorb this report's full scope, including under the stronger re-review duplicate bar.
- **Discussion and recent confirmation:** In https://github.com/microsoft/vscode/issues/189224, the reporter confirmed 1.80.2 and identified the generated locale-table limitation. Another participant reported persistence on 1.130.0 in July 2026. The reporter explicitly separated the unrelated Unicode-escape search discussion from this locale issue.
- **External cross-reference is a workaround, not a fix:** https://github.com/TypeFox/monaco-languageclient/issues/907 closed after its reporter disabled ambiguous-character highlighting through editor options. That resolution neither adds Ukrainian locale data nor resolves this issue's locale-specific exclusion requirement.
