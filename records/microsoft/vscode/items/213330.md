# Issue #213330 — VSCode does not honor LSP-advertised capabilities when displaying inlay hints menu

[https://github.com/microsoft/vscode/issues/213330](https://github.com/microsoft/vscode/issues/213330)

## Summary

Still reproduces on current main: the inlay hint label-part context menu shows all SymbolNavigationAction entries registered in EditorContext without evaluating their `when` clauses, so actions like 'Go to Declaration' and 'Go to Implementations' appear even when the LSP server doesn't advertise those capabilities.

## Change summary

The inlay hint label-part right-click menu shows navigation actions (Go to Declaration, Go to Implementations) that the language server does not support, unlike the regular editor context menu which correctly hides them.

## Best solution

In `showGoToContextMenu` (`src/vs/editor/contrib/inlayHints/browser/inlayHintsLocations.ts`), evaluate each menu item's `when` clause against the current context key service before including it, so that preconditions like `EditorContextKeys.hasDeclarationProvider` / `hasImplementationProvider` are honored — matching the regular editor context menu behavior.
