# Issue #318936 — Feature Request: Agent mode should support working across multiple workspace folders simultaneously

[https://github.com/microsoft/vscode/issues/318936](https://github.com/microsoft/vscode/issues/318936)

## Summary

Keep this accepted Backlog request open. Current main contains substantial experimental multi-root infrastructure, but the capability is hidden and disabled by default for every provider, so ordinary Agents Window sessions still do not satisfy the central request.

## Change summary

Allow one Agents Window session to understand, read, and edit across every folder in a multi-root workspace.

## Best solution

Graduate the existing multiple-working-directories capability into a supported Agents Window workflow: define whether sessions span all roots by default or require an explicit folder-scope choice, enable the resulting contract for supported providers, and complete the remaining multi-root presentation and changeset behavior.

## Vision fit

- **Fit:** aligned
- **Reason:** Cross-folder agent work advances VS Code's durable AI-assisted development and workbench UX themes for common multi-repository workflows.
- **Evidence:** Durable themes: “AI-assisted development” and “Workbench & core UX”; the request also preserves the existing multi-root workspace model rather than adding an unrelated specialized surface.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/agentService.ts`, `src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/claude/claudeAgent.ts`, `src/vs/platform/agentHost/node/codex/codexAgent.ts`, `src/vs/sessions/common/agentHostSessionWorkspace.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`
- **Validation:** Extend the existing Copilot, Claude, and Codex agent-host tests so a normally configured multi-root session receives every workspace root, can read and edit a file under a secondary root, and preserves those roots after resume; add an Agents Window provider test confirming the session workspace exposes all folders.
- **Behavior:**

  > A newly created Agents Window session in a multi-root workspace can reason about, read, and edit files under every included workspace folder. Its folder scope remains intact after reload or session resume, and customizations applicable to included folders are available according to the chosen scope contract. Single-folder sessions retain their current behavior. Acceptance should cover at least one edit in a secondary root, restoration of the full root set, and accurate multi-root session presentation.
- **Trace:**

  > The provider-neutral model already represents multiple folders through ISessionWorkspace.folders in src/vs/sessions/services/sessions/common/session.ts, and buildAgentHostSessionWorkspace in src/vs/sessions/common/agentHostSessionWorkspace.ts projects ordered workingDirectories into that model. Agent Host providers already have multiple-working-directory implementations and tests, but src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts keeps all three provider gates hidden and false by default. The current provider tests demonstrate additional-directory transport and secondary-root customization support, while https://github.com/microsoft/vscode/issues/321651 records remaining Agents Window presentation and harness gaps. Preserve single-folder behavior and avoid conflating this with per-repository worktree orchestration from https://github.com/microsoft/vscode/issues/311148.
- **Open decisions:**
  - Should a session created in a multi-root workspace span every workspace folder by default, or should users explicitly choose between all folders and a single-folder scope at session creation?
  - When one workspace contains multiple repositories, should isolation remain anchored to one primary repository while additional roots are shared, or must each root receive equivalent isolation semantics before the feature is enabled by default?
