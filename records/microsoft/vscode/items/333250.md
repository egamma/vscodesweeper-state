# Issue #333250 — Opening a completed session shows a new "Session finished" OS notification

[https://github.com/microsoft/vscode/issues/333250](https://github.com/microsoft/vscode/issues/333250)

## Summary

Confirmed regression traced in source: opening a completed session re-adds its chat model to ChatWindowNotifier's tracked set, and the transient requestInProgress flip during history replay is read as a real idle transition, firing a stray 'Session finished.' toast. An open PR already targets this exact fix, so this stays open pending that PR landing.

## Change summary

Opening an already-completed session now spuriously shows a 'Session finished.' OS notification, when it previously did not.

## Best solution

Land https://github.com/microsoft/vscode/pull/333582 ('chat: do not notify when a session replays its history'), which should suppress the idle-transition notification path in src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts (observeIsIdle/_trackModel) for models that are merely replaying persisted history rather than genuinely completing a live turn.

## Evidence

- **regression source:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts: `_trackModel` computes `isIdle` via `observeIsIdle(model)` and schedules a completion toast on the `false -> true` transition of `autorunDelta(isIdle, ...)`; opening a completed session adds the model to `_chatService.chatModels`, and if history replay transiently sets `model.requestInProgress` (derived from `lastRequestObs`, chatModel.ts:2833) before settling, the delta observer sees exactly that false->true edge and fires the idle notification body 'Session finished.' (localize('chat.idleNotificationDetail', ...)), matching the reported toast text exactly.
