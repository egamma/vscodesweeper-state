# Issue #106697 — editor.renderWhitespace should have option for selection+trailing

[https://github.com/microsoft/vscode/issues/106697](https://github.com/microsoft/vscode/issues/106697)

## Summary

The combined selection-plus-trailing behavior is still missing from current source and commands. This accepted Backlog request has 86 upvotes; retain it for a focused configuration-design decision rather than closing it for age.

## Change summary

Allow rendering all selected whitespace together with trailing whitespace outside the selection, without rendering other unselected whitespace.

## Best solution

Provide an opt-in way to combine selected and trailing whitespace rendering consistently across both editor rendering paths and the View menu, preserving existing settings and defaults. Decide whether this should be a combined enum value or an independent selection-rendering setting before implementation.

- **Behavior:**

  > Users can opt into showing every selected space and tab while also showing trailing whitespace on unselected text. Unselected leading and internal whitespace remains hidden. Removing the selection leaves trailing markers visible, and selecting trailing whitespace does not create duplicate markers. Existing whitespace modes and the default remain unchanged; wrapped visual-line boundaries must not be mistaken for actual trailing whitespace.

## Evidence

- **Existing capability check:** src/vs/editor/common/config/editorOptions.ts:749 and 6664–6677 restrict editor.renderWhitespace to none, boundary, selection, trailing, or all. No combined mode exists; all and boundary additionally render unselected non-trailing whitespace and therefore do not satisfy the request.
