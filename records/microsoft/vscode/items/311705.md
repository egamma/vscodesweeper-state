# Issue #311705 — Copilot Chat with Ollama/BYOK uses nominal context_length for prompt budgeting and drops token usage in the context widget

[https://github.com/microsoft/vscode/issues/311705](https://github.com/microsoft/vscode/issues/311705)

## Summary

Keep open: current source still budgets Ollama requests from nominal architecture metadata rather than the configured runtime context. Usage forwarding now exists in the provider and consumer paths, so that portion needs retesting with the supplied steps rather than assuming both defects remain.

## Change summary

Use Ollama's effective runtime context for prompt budgeting and display provider-reported token usage in the chat context widget.

## Best solution

Make Ollama's advertised context and prompt budget agree with the effective runtime limit, preserving the output reservation. Verify the existing usage forwarding end-to-end and address only any remaining gap.

## Evidence

- **Current-source budgeting defect:** extensions/copilot/src/extension/byok/vscode-node/ollamaProvider.ts, OllamaLMProvider._getOllamaModelInfo, reads model_info['<architecture>.context_length'] with a 32768 fallback and subtracts an output reservation. It does not inspect num_ctx or runtime context information. A model configured for 65536 tokens with larger architecture metadata therefore still advertises the larger budget.
- **Budget propagation:** extensions/copilot/src/extension/byok/common/byokProvider.ts, resolveModelInfo and resolveModelTokenLimits, propagate these capabilities into max_context_window_tokens and max_prompt_tokens. extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts:723-760 derives tokenLimit from modelMaxPromptTokens and checks the prompt against that limit; internal consistency does not correct an inflated Ollama input.
- **Independent confirmation and canonical ownership:** https://github.com/microsoft/vscode/issues/313715 reports a Modelfile with PARAMETER num_ctx 65536 appearing as approximately 246k. The maintainer explicitly acknowledges the metadata/runtime mismatch and closes that newer report as a duplicate of this issue at https://github.com/microsoft/vscode/issues/313715#issuecomment-5144915248.
