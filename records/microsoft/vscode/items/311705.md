# Issue #311705 — Copilot Chat with Ollama/BYOK uses nominal context_length for prompt budgeting and drops token usage in the context widget

[https://github.com/microsoft/vscode/issues/311705](https://github.com/microsoft/vscode/issues/311705)

## Summary

Both issues are confirmed in current main: the Ollama provider reads only the nominal `context_length` from `/api/show` metadata and never queries the runtime `num_ctx`, so the prompt budget can be inflated beyond the actual context window. Token usage is also not propagated to the context widget for BYOK/Ollama models.

## Change summary

Copilot Chat uses Ollama's nominal GGUF metadata context_length instead of the runtime num_ctx for prompt budgeting, and does not surface token usage from the Ollama backend in the context widget.

## Best solution

Update `OllamaLMProvider._getOllamaModelInfo` in `extensions/copilot/src/extension/byok/vscode-node/ollamaProvider.ts` to query the Ollama runtime for the effective `num_ctx` (e.g. via `/api/show` response's `parameters` field or a `/api/ps` call) and prefer it over the static `context_length` metadata. Separately, ensure the streaming response's `usage` object is propagated through the BYOK provider chain to the context widget.
