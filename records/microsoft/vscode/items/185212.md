# Issue #185212 — Allow safestorage api to detect presence of libsecret or kwallet if the desktop environment is unknown

[https://github.com/microsoft/vscode/issues/185212](https://github.com/microsoft/vscode/issues/185212)

## Summary

Keep open for the runtime-level keyring discovery work. Current VS Code offers explicit backend selection and warnings, but these do not establish automatic detection when the desktop environment is unknown.

## Change summary

Automatically discover an available Linux secret-storage backend despite an unknown desktop environment so authentication survives application restarts.

## Best solution

Electron's safeStorage backend selection should discover available libsecret or KWallet services without requiring a recognized desktop environment, and VS Code should consume that behavior while preserving explicit backend overrides and consent for weaker encryption.

- **Current source boundary:** src/vs/platform/encryption/electron-main/encryptionMainService.ts delegates encryption availability and selected-backend reporting to Electron safeStorage. src/vs/platform/secrets/common/secrets.ts, BaseSecretStorageService.initialize(), chooses InMemoryStorageService when encryption is unavailable. This traces the persistence consequence but does not establish current Linux runtime reproduction.
- **Existing mitigations are not automatic discovery:** src/vs/workbench/services/secrets/electron-browser/secretStorageService.ts provides troubleshooting and an explicit weaker-encryption choice. src/vs/platform/encryption/common/encryptionService.ts exposes the gnome-libsecret password-store option, and src/vs/workbench/contrib/encryption/electron-browser/encryption.contribution.ts migrates older explicit GNOME overrides. These require user configuration or weaken storage; they do not implement the central automatic-discovery request.
