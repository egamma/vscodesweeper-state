# Issue #185212 — Allow safestorage api to detect presence of libsecret or kwallet if the desktop environment is unknown

[https://github.com/microsoft/vscode/issues/185212](https://github.com/microsoft/vscode/issues/185212)

## Summary

This is a genuine upstream issue in Electron/Chromium's desktop-environment detection for safestorage on Linux. Electron PR #49054 (merged 2026-02-15, semver/major, no-backport) adds async safestorage with broader backend support via os_crypt_async, closing both electron/electron#39789 and electron/electron#47436. However, the fix is not in VS Code's current Electron 42.x — it targets a future Electron major version. Keep open until VS Code picks up the Electron version containing the fix and adopts the new async safeStorage APIs.

## Change summary

On Linux with an unknown or unsupported XDG_CURRENT_DESKTOP, Electron's safestorage falls back to BASIC_TEXT and reports encryption as unavailable, causing VS Code to use in-memory secret storage and lose sessions on restart.

## Best solution

When VS Code upgrades to the Electron version shipping os_crypt_async (PR electron/electron#49054, likely Electron 43+), adopt the new async safeStorage APIs (isAsyncEncryptionAvailable, encryptStringAsync, decryptStringAsync) so that libsecret/kwallet are auto-discovered via DBus Secret Service regardless of XDG_CURRENT_DESKTOP. The related open tracking issue https://github.com/microsoft/vscode/issues/187338 may serve as the canonical VS Code-side adoption tracker.

## Evidence

- **upstream root cause:** deepak1556 (MEMBER) traced the root cause to Chromium's key_storage_util_linux.cc: unknown desktop environments get BASIC_TEXT backend, and Electron's safeStorage.isEncryptionAvailable() returns false for BASIC_TEXT.
- **Electron fix PR:** https://github.com/electron/electron/pull/49054 (merged 2026-02-15) adds os_crypt_async support with new async safeStorage APIs, closing electron/electron#39789 and electron/electron#47436. Labeled semver/major and no-backport.
- **not in current Electron:** VS Code uses Electron 42.5.0; the fix merged to Electron main after v42.0.0 (compare status: 'behind'), so it ships in a future major version (likely 43+).
- **VS Code workarounds shipped:** VS Code added password-store configuration via argv.json (commit 8245737e938), user-facing notification when encryption is unavailable (PR #185390), and password-store migration (commit 29e000b1e5c).
- **related open issue:** https://github.com/microsoft/vscode/issues/187338 is still open and tracks the broader 'OS keyring couldn't be identified' problem on Linux.
