# Issue #273363 — Extension pack blocks target extension installation when remote.downloadExtensionsLocally is enabled

[https://github.com/microsoft/vscode/issues/273363](https://github.com/microsoft/vscode/issues/273363)

## Summary

The defect remains on current main: the local-download path treats extension-pack members like required dependencies, so one incompatible optional pack member aborts installation before the requested extension is installed.

## Change summary

Installing an extension remotely with `remote.downloadExtensionsLocally` enabled fails when an optional extension-pack member has no compatible version.

## Best solution

Make the native remote installation path preserve the distinction between required dependencies and optional extension-pack members, skipping incompatible pack members while continuing to install the requested extension and still failing for incompatible dependencies.

- **Trace:**

  > `NativeRemoteExtensionManagementService.downloadAndInstall` in `src/vs/workbench/services/extensionManagement/electron-browser/remoteExtensionManagementService.ts` installs everything returned by `getAllWorkspaceDependenciesAndPackedExtensions` before installing the requested extension. The recursive collector merges `extensionPack` and `extensionDependencies`, so `downloadCompatibleAndInstall` cannot distinguish an optional pack failure from a required dependency failure and propagates either compatibility error. ## Evidence

- **source-reproducible path:** In `src/vs/workbench/services/extensionManagement/electron-browser/remoteExtensionManagementService.ts`, `downloadAndInstall` calls `getAllWorkspaceDependenciesAndPackedExtensions`, installs every returned item sequentially, and only installs the requested extension afterward. `downloadCompatibleAndInstall` throws when `checkAndGetCompatible` cannot find a compatible version, so an incompatible pack member prevents the target installation.
- **root cause:** `getAllWorkspaceDependenciesAndPackedExtensions` and `getDependenciesAndPackedExtensionsRecursively` combine `manifest.extensionPack` and `manifest.extensionDependencies` into undifferentiated arrays, losing whether failure is optional or required.
- **intended behavior precedent:** `src/vs/platform/extensionManagement/common/abstractExtensionManagementService.ts` in `getAllDepsAndPackExtensions` retains an `isDependency` flag: compatibility errors for pack members are logged and skipped, while dependency errors are rethrown.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/245540 concerns repeated dependency reinstallation and a request to disable dependency installation; it does not own this report's incompatible optional pack-member failure.
