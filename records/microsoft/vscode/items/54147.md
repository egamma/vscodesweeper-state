# Issue #54147 — Provide an API to track a position in a document across edits

[https://github.com/microsoft/vscode/issues/54147](https://github.com/microsoft/vscode/issues/54147)

## Summary

The API gap remains on current main and still affects extension authors. Keep this Backlog request open for API design discussion rather than closing it for age.

## Change summary

Expose an extension API for maintaining live document positions or ranges as edits occur.

## Best solution

Design an editor API backed by the existing tracked-range machinery, with explicit stickiness, deletion behavior, and disposal semantics. The editor API and extension-host owners should decide whether this warrants a first-class primitive over edit-delta tracking.

## Evidence

- **current public API:** src/vscode-dts/vscode.d.ts exposes only `key` and `dispose()` on `TextEditorDecorationType`; it provides no way to retrieve the decoration's tracked range. `TextDocumentContentChangeEvent` exposes edit deltas but no tracked-position primitive.
- **internal capability:** src/vs/editor/common/model/textModel.ts implements private `_setTrackedRange` and `_getTrackedRange` methods using model decorations, confirming that equivalent tracking exists internally but is not extension API.
- **recent maintainer confirmation:** A maintainer confirmed in 2025 that no position-tracking API exists and that extensions must currently observe document edits themselves: https://github.com/microsoft/vscode/issues/264581#issuecomment-3246418602
- **canonical search:** The related open https://github.com/microsoft/vscode/issues/73780 concerns flexible decoration rendering and only references this API as supporting work; it does not own the general tracked-position requirement.
