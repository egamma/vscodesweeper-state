# Issue #264528 — Accepting an ML completion while in references view switches focus to main editor

[https://github.com/microsoft/vscode/issues/264528](https://github.com/microsoft/vscode/issues/264528)

## Summary

Still reproduces on main: `AcceptInlineCompletion.run()` calls `getInFocusedEditorOrParent()`, which resolves to the outer/parent editor when the focused editor is an `EmbeddedCodeEditorWidget` (as in the references peek view). The completion is then accepted and focus is set on the wrong editor.

## Change summary

Accepting an inline/ML completion (Tab) while editing in the references peek view incorrectly applies the completion to the parent editor and steals focus.

## Best solution

In `AcceptInlineCompletion.run()` (and the other accept variants), use the focused code editor directly instead of `getOuterEditor`/`getInFocusedEditorOrParent` — or check whether the inline completion controller exists on the focused embedded editor first and only fall back to the parent when the focused editor has no active inline completion. The fix likely touches `src/vs/editor/contrib/inlineCompletions/browser/controller/commands.ts` and possibly `inlineCompletionsController.ts`.
