# Issue #324685 — Git: Always shows the same tag when multiple tags point to the same commit

[https://github.com/microsoft/vscode/issues/324685](https://github.com/microsoft/vscode/issues/324685)

## Summary

The current Git integration selects a matching tag, not the tag used for checkout, so the requested distinction remains unsupported. Route to the Git owner for a decision about checkout-provenance display; no verified duplicate or fixing commit supports closing it.

## Change summary

Display the explicitly checked-out tag when several tags identify the same commit.

## Best solution

Define whether the Git status indicator represents the current commit's refs or the user's checkout target. Supporting the latter needs explicit semantics for terminal checkouts, window reloads, and unavailable checkout history, rather than changing tag ordering.

## Evidence

- **Current selection behavior:** extensions/git/src/git.ts:2893–2918, Repository.getHEADRef(), obtains detached HEAD's commit and selects tags.find(tag => tag.commit === HEAD!.commit). Both example tags therefore produce the same displayed name regardless of which was checked out.
- **Checkout target versus repository state:** extensions/git/src/git.ts:2927–2986 reads detached HEAD as a commit without a tag name. extensions/git/src/repository.ts:2301–2320 retains the requested treeish as an operation label during checkout, but the settled status indicator uses Repository.headLabel at lines 3385–3400; extensions/git/src/statusbar.ts, CheckoutStatusBar.command, renders that label after the operation.
- **Classification and remaining gap:** The selected tag still identifies the correct commit; the source deliberately derives a representative tag from refs rather than promising checkout provenance. Displaying the exact checkout target adds behavior beyond that existing contract. Detached HEAD's commit alone cannot distinguish two tags on the same commit.
- **Existing-capability check:** extensions/git/package.json registers git.checkout, git.checkoutDetached, and git.checkoutType. These control checkout operations or picker contents, not which matching tag the settled status indicator displays; the inspected display path has no checkout-target selection setting.
