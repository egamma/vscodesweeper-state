# Issue #280834 — Git Warning Message Incorrectly Styled as Error

[https://github.com/microsoft/vscode/issues/280834](https://github.com/microsoft/vscode/issues/280834)

## Summary

Keep open while the existing fix proposals are reviewed. Current source can select an informational SSH known_hosts line as the primary error message when a Git command fails; the linked PR has not merged.

## Change summary

Prevent informational SSH known_hosts messages from being presented as Git errors, without downgrading genuine command failures.

## Best solution

Review the existing implementation candidates, especially https://github.com/microsoft/vscode/pull/327894, and land an approach that distinguishes informational SSH output from actual failures. Mixed output must retain error severity and show the actionable failure rather than the known_hosts notice.

## Evidence

- **Current source: error propagation:** extensions/git/src/git.ts:666-677 rejects a nonzero Git exit code with a GitError containing the complete stderr. Successful commands return normally, so a successful first SSH connection emitting this line alone does not trigger this error path.
- **Current source: misleading message selection:** In extensions/git/src/commands.ts, Commands.createCommand initializes notification type to 'error'. Its default handler selects the first nonempty stderr line without filtering SSH known_hosts notices or preferring fatal lines, and showErrorNotification dispatches that message to window.showErrorMessage. A failing command whose stderr begins with 'Warning: Permanently added ...' therefore displays that informational line with error styling.
