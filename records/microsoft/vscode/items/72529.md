# Issue #72529 — Support restart of remote EH to avoid window reloads

[https://github.com/microsoft/vscode/issues/72529](https://github.com/microsoft/vscode/issues/72529)

## Summary

Still valid: the workaround code (`hostService.reload()` with `TODO@aeschli, workaround`) is present on current main in both relauncher.contribution.ts and workspaceEditingService.ts. Remote EH restart without a full window reload remains unimplemented.

## Change summary

When workspace folders change with a remote authority, VS Code does a full window reload instead of gracefully restarting the remote extension host.

## Best solution

Implement remote extension host restart support in the extension service so that workspace folder changes and entering workspaces with a remote authority can stop/start the remote EH without a disruptive full window reload. The fix would remove the `hostService.reload()` workaround paths in `src/vs/workbench/contrib/relauncher/browser/relauncher.contribution.ts` (line 306) and `src/vs/workbench/services/workspaces/electron-browser/workspaceEditingService.ts` (line 203), replacing them with the same `stopExtensionHosts`/`startExtensionHosts` flow used for the local case.
