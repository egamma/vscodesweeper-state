# Issue #336466 — Agent Host can send a queued steering message after removal or while it is being edited

[https://github.com/microsoft/vscode/issues/336466](https://github.com/microsoft/vscode/issues/336466)

## Summary

Team-authored bug report (author is a VS Code maintainer) describing a race between queue-state mutation (remove/edit) and delivery in the Agent Host steering-message queue; filed hours ago with no comments or linked fix yet, so it stays open regardless.

## Change summary

A queued Agent Host steering message can still be delivered after being removed from the queue, or while it is actively being edited, even though the visible queue no longer shows it (or shows it as being edited).

## Best solution

Likely belongs in src/vs/platform/agentHost/node/chatContributions/queueDrain/queueDrainContribution.ts, which owns queue draining/consumption (_tryConsumeNextQueuedMessage, ChatPendingMessageRemoved handling) — the fix needs the drain/consume path to atomically check current queue/edit state (not a stale snapshot) before sending, closing the window between removal-or-edit-start and delivery.
