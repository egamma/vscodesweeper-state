# Issue #157408 — Add `selectionGroup` to TreeItem to allow for multiselect restrictions

[https://github.com/microsoft/vscode/issues/157408](https://github.com/microsoft/vscode/issues/157408)

## Summary

Keep this accepted feature request open: the current extension API still cannot restrict tree multiselection to compatible item groups. It reached 20 community upvotes and was explicitly promoted to Backlog; no verified older canonical issue was found.

## Change summary

Allow extension authors to prevent incompatible tree item types from being selected together through an optional selection-group API.

## Best solution

Provide an opt-in extension API for compatible-item multiselection, preserving unrestricted selection for existing extensions. Settle the compatibility rules for ungrouped items, wildcard items, and range selection before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTreeViews.ts`, `src/vs/workbench/api/browser/mainThreadTreeViews.ts`, `src/vs/workbench/common/views.ts`, `src/vs/workbench/browser/parts/views/treeView.ts`
- **Validation:** Use a test extension with a canSelectMany tree containing interleaved file and stash items. Verify mouse modifier selection, Shift-range selection, and keyboard multiselection cannot produce incompatible groups; verify selection events and command arguments contain only permitted items. Repeat with an extension that supplies no grouping metadata and confirm existing selection behavior is unchanged.
- **Behavior:**

  > An extension can opt into selection compatibility groups so selecting a file does not allow stashes to join that selection, and selecting a stash does not allow files to join it. The restriction must hold for mouse and keyboard multiselection, with consistent selection events and command arguments. Extensions that do not opt in retain existing behavior. Acceptance must also cover the agreed behavior for ungrouped items, wildcard compatibility, and ranges spanning incompatible items.
- **Trace:**

  > The public API in src/vscode-dts/vscode.d.ts currently offers only the boolean TreeViewOptions.canSelectMany; TreeItem.contextValue affects menu contributions, not selection eligibility. ExtHostTreeView._createTreeNode in src/vs/workbench/api/common/extHostTreeViews.ts builds the transported ITreeItem, whose contract resides in src/vs/workbench/common/views.ts. The workbench tree in src/vs/workbench/browser/parts/views/treeView.ts enables multiple selection globally and forwards selection changes through src/vs/workbench/api/browser/mainThreadTreeViews.ts. This establishes the missing API-to-workbench capability without executing code. Preserve existing ungrouped-extension behavior and do not expand the work into unrelated built-in tree selection changes. The remaining uncertainty is the public compatibility contract, including the optional wildcard suggested in https://github.com/microsoft/vscode/issues/157408.
- **Open decisions:**
  - When an extension opts into grouping, how do items without a group interact with grouped items, and should an explicit wildcard group be supported?
  - When Shift-range selection spans incompatible groups, should it select only compatible items within the range or reject the range extension?
