# Issue #286260 — Worktrees state is only reflecting latest commit, not pending changes

[https://github.com/microsoft/vscode/issues/286260](https://github.com/microsoft/vscode/issues/286260)

## Summary

The misleading commit-age timestamp has been removed, but worktree entries still do not indicate pending changes. Keep this team-authored issue open for the maintainer-supported status-indicator improvement; the later timestamp change covers only part of the request.

## Change summary

Make worktree entries in the Source Control Repositories view visibly reflect pending changes, including changes made in another window.

## Best solution

Provide a recognizable pending-change indicator on worktree entries that updates when their working directories change, while preserving the distinction between branches and worktrees. Coordinate the visual treatment with the existing codicon discussion rather than treating removal of the timestamp as completion.

- **Behavior:**

  > A worktree entry should communicate whether that worktree has pending changes instead of appearing unchanged while work happens in another window. The status treatment must leave worktrees recognizable and must not weaken deletion warnings.
- **Trace:**

  > GitArtifactProvider in extensions/git/src/artifactProvider.ts obtains worktrees through Repository.getWorktreeDetails in extensions/git/src/repository.ts, which supplies commit metadata rather than dirty status.
