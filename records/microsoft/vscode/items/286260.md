# Issue #286260 — Worktrees state is only reflecting latest commit, not pending changes

[https://github.com/microsoft/vscode/issues/286260](https://github.com/microsoft/vscode/issues/286260)

## Summary

Keep open: worktree rows still lack a pending-changes indicator, and maintainers explicitly requested one. The original age display is absent from current worktree artifacts, but that does not satisfy the remaining request.

## Change summary

Show pending changes on SCM worktree entries, including changes made in another window, without obscuring their worktree identity.

## Best solution

Provide an understandable clean-versus-dirty indication in the SCM Repositories worktree list, while preserving the distinction between branches, worktrees, and agent sessions. Settle the user-visible indicator and cross-window freshness expectations before implementation.

- **Likely files:** `extensions/git/src/artifactProvider.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/icons.ts`, `src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts`
- **Validation:** In the SCM Repositories view, create a linked worktree and open it in another window. Make a tracked edit and create an untracked file there; verify that the originating window indicates pending changes according to the agreed refresh contract. Commit or discard all changes and verify that the indicator returns to clean. Check that worktree identity remains distinguishable from a branch in light, dark, and high-contrast themes.
- **Behavior:**

  > A worktree entry should communicate whether it contains pending changes instead of appearing unchanged while another window edits its files. Tracked edits and untracked files must be covered, and returning to a clean state must clear the indication. The indication must remain understandable without obscuring worktree identity. Acceptance includes the two-window editing scenario from the report; presentation and freshness expectations need maintainer agreement.
- **Trace:**

  > GitArtifactProvider.provideArtifacts in extensions/git/src/artifactProvider.ts constructs worktree rows from Repository.getWorktreeDetails, which currently returns worktree and commit metadata without pending-change state. The provider's worktree refresh notification is tied to local Worktree write operations; the trace does not establish a cross-window pending-edit observation mechanism. SCMArtifactRenderer.renderElement in src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts renders the supplied icon and description rather than deriving dirty state itself. Current worktree artifacts omit timestamps, so do not restore the old commit-age display as a proxy for activity. Preserve deletion safeguards and distinguish worktree identity from agent-session identity. The related icon discussion at https://github.com/microsoft/vscode-codicons/issues/374 contains a selected variation to try, but does not settle the pending-state presentation or freshness contract here.
- **Open decisions:**
  - Should pending changes be shown through a worktree icon modifier, a textual state, or both, while preserving the worktree's visual identity?
  - Should edits made in another window update the originating worktree list automatically, or is explicit refresh acceptable?
