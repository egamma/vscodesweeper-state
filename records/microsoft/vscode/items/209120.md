# Issue #209120 — Centered Layout: Maintain editor width until space doesn't allow it

[https://github.com/microsoft/vscode/issues/209120](https://github.com/microsoft/vscode/issues/209120)

## Summary

A real centered-layout gap remains on current main: side-by-side editor groups still disable centered layout by default, while fixed-width mode constrains the entire editor grid rather than maintaining a useful width per editor. This issue is already the canonical report for that behavior and should remain open in the Backlog.

## Change summary

Make centered layout preserve each editor's comfortable width as groups are added, expanding to the available width only when those widths no longer fit.

## Best solution

Centered layout should retain an effective target width for each side-by-side editor group while space permits, then degrade predictably when the available editor area becomes too narrow. The behavior should also remain coherent for stacked and nested group layouts.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/parts/editor/editorPart.ts`, `src/vs/base/browser/ui/centered/centeredViewLayout.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** Exercise centered layout with one, two, and three side-by-side groups plus stacked and nested layouts: group widths should remain stable while they fit, use the available width when they do not, and return to their centered width after groups are removed.
- **Behavior:**

  > With centered layout enabled, adding side-by-side editor groups should not immediately stretch the editor area across the full window. Each group should retain a comfortable centered width while the available space can accommodate the groups, and the layout should consume more width only after that constraint can no longer be met. Stacked groups should remain centered, and removing groups should restore the prior centered sizing without requiring the existing drag-order workaround.
- **Trace:**

  > Layout.centerMainEditorLayout in src/vs/workbench/browser/layout.ts computes `hasMoreThanOneColumn` and disables centered layout under the default auto-resize setting. EditorPart wraps the complete editor grid in a single CenteredViewLayout, and src/vs/base/browser/ui/centered/centeredViewLayout.ts persists only one total `targetWidth` or pair of margin ratios. Commit b274aac2ca213a2ca9b9626b7060328f31cfffaf, associated with https://github.com/microsoft/vscode/pull/236471, narrowed the disable condition so vertically stacked groups remain centered but left side-by-side groups unchanged. Preserve current handling for complex editors, maximized groups, and manual centered-layout resizing; the uncertainty begins at how a target width should be interpreted for unequal or nested group arrangements.
- **Open decisions:**
  - For unequal or nested editor groups, should the maintained width apply equally to every column, preserve the user's existing column ratios, or constrain only the active column?
  - When the requested widths no longer fit, should all columns shrink proportionally or should centered margins collapse fully before editor-group ratios change?

## Evidence

- **current source:** src/vs/workbench/browser/layout.ts still deactivates centered layout when `hasMoreThanOneColumn` is true and `workbench.editor.centeredLayoutAutoResize` is enabled.
- **existing settings do not cover the request:** src/vs/workbench/browser/workbench.contribution.ts defines `workbench.editor.centeredLayoutAutoResize` as resizing to maximum width for multiple groups, while `workbench.editor.centeredLayoutFixedWidth` only controls whether the centered layout maintains a constant total width.
- **sizing boundary:** src/vs/base/browser/ui/centered/centeredViewLayout.ts stores one `targetWidth` and applies it to the complete wrapped editor-grid view; it has no editor-group count or per-group sizing behavior.
- **partial related implementation:** Commit b274aac2ca213a2ca9b9626b7060328f31cfffaf from https://github.com/microsoft/vscode/pull/236471 only changed the auto-resize test so stacked groups can remain centered; it did not implement adaptive widths for side-by-side groups.
- **canonical status:** A maintainer closed https://github.com/microsoft/vscode/issues/242968 as a duplicate and explicitly stated that fixing this issue would cover multiple centered panes; https://github.com/microsoft/vscode/issues/278604 was later closed as another duplicate of this issue.
- **related but distinct older issue:** https://github.com/microsoft/vscode/issues/60900 is older but primarily tracks editor movement and resizing when side bars open or close, not the same editor-group split symptom required for a duplicate close on this re-review.
