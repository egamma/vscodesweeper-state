# Issue #201051 — Use inline diff view for added and removed files by default

[https://github.com/microsoft/vscode/issues/201051](https://github.com/microsoft/vscode/issues/201051)

## Summary

Keep open: existing layout settings do not automatically select inline view specifically for added and removed files. Related requests are newer and differ in scope or default behavior, so they are not canonical duplicates for this re-reviewed item.

## Change summary

Automatically display added and removed files inline while retaining side-by-side comparisons for modified files, preferably without whole-file background highlighting.

## Best solution

Provide file-aware diff presentation that avoids an empty comparison pane for whole-file additions and deletions while preserving the user's layout preference for modified files. Decide whether these cases should also use a compact status indicator instead of whole-file highlighting.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/diffEditorOptions.ts`, `src/vs/editor/common/config/diffEditor.ts`, `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/browser/widget/diffEditor/components/diffEditorDecorations.ts`, `src/vs/editor/test/browser/widget/diffEditorWidget.test.ts`
- **Validation:** Extend the diff editor widget tests to check wide-editor presentation for whole-file additions, whole-file deletions, and ordinary modifications under the chosen defaults and explicit layout preferences. Manually verify added/deleted file comparisons retain readable content and an accessible status indication under the chosen highlighting policy.
- **Behavior:**

  > The reporter wants added and removed files to use the full editor width without manually toggling between inline and side-by-side views. Ordinary modified-file comparisons should retain their preferred presentation. A secondary request is to replace whole-file background highlighting with a small added/deleted status indicator. Acceptance should cover both additions and deletions at widths where the existing responsive fallback does not activate, with explicit layout preferences and accessibility behavior preserved according to the agreed contract.
- **Trace:**

  > DiffEditorOptions in src/vs/editor/browser/widget/diffEditor/diffEditorOptions.ts derives layout from configured renderSideBySide, width, screen-reader state, and an internal compactMode. Its isSimpleDiff helper already recognizes insertion-only and deletion-only mappings, but compactMode defaults to false in src/vs/editor/common/config/diffEditor.ts and is not a registered user setting. The registered layout settings in src/vs/editor/common/config/editorConfigurationSchema.ts do not distinguish whole-file additions/deletions. DiffEditorDecorations in src/vs/editor/browser/widget/diffEditor/components/diffEditorDecorations.ts independently applies background decorations to added and removed ranges. Related requests https://github.com/microsoft/vscode/issues/325668 and https://github.com/microsoft/vscode/issues/334268 provide additional demand but differ in defaults and scope. Preserve ordinary modified-file presentation and existing accessibility behavior; uncertainty concerns the user-visible activation and highlighting policy, not helper selection.
- **Open decisions:**
  - Should whole-file additions and deletions automatically use inline presentation by default, or should this be opt-in and subordinate to an explicit side-by-side preference?
  - Should automatic inline presentation apply only when an entire file is added or removed, or also to addition-only and deletion-only changes within existing files?
  - Should whole-file additions and deletions retain existing background highlighting, or replace it with a compact status indicator while ordinary modified-file highlighting remains unchanged?

## Evidence

- **Existing settings do not cover the central ask:** src/vs/editor/common/config/editorConfigurationSchema.ts registers diffEditor.renderSideBySide, diffEditor.renderSideBySideInlineBreakpoint, and diffEditor.useInlineViewWhenSpaceIsLimited. These select layout globally or by editor width, not by whether an entire file was added or removed.
- **Partial internal capability:** src/vs/editor/browser/widget/diffEditor/diffEditorOptions.ts derives renderSideBySide using compactMode and shouldRenderInlineViewInSmartMode; isSimpleDiff accepts insertion-only or deletion-only mappings. However, src/vs/editor/common/config/diffEditor.ts defaults compactMode to false, and it is not registered as a user setting in editorConfigurationSchema.ts. This internal capability does not establish the requested default behavior.
- **Highlighting remains separate:** src/vs/editor/browser/widget/diffEditor/components/diffEditorDecorations.ts adds background decorations for nonempty original and modified mapping ranges, including pure additions and deletions. renderIndicators controls the accompanying indicators rather than suppressing those background decorations.
- **Verified related request, not a canonical:** https://github.com/microsoft/vscode/issues/325668 is open, created on 2026-07-13, and requests opt-in automatic inline rendering for any addition-only or deletion-only diff. It overlaps this request but is newer than this 2023 report and proposes different default semantics; it cannot serve as the canonical under the re-review rules.

It is newer and covers additions rather than this report's additions and deletions.
