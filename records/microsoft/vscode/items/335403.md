# Issue #335403 — Copilot Chat shows "Sign in to use GitHub Copilot" modal when chat activates before the token source is ready

[https://github.com/microsoft/vscode/issues/335403](https://github.com/microsoft/vscode/issues/335403)

## Summary

Well-documented race: the reporter's logs and the core `chatSetupRunner.ts` code both show that when `ChatEntitlement.Unknown` is the state at the moment the setup/sign-in flow runs, the UI renders the 'Sign in to use GitHub Copilot' dialog — exactly the dialog seen here, appearing in the ~1.4s window before the Copilot token resolves. No fix exists yet on main, so this stays open pending a maintainer look at where the flow is triggered before the token source is ready.

## Change summary

The 'Sign in to use GitHub Copilot' modal is spuriously triggered/left on screen when Copilot Chat activates before the token source resolves, even though the user is signed in and the token arrives ~1.4s later.

## Best solution

In src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupRunner.ts, avoid rendering (or auto-dismiss) the sign-in dialog when entitlement is `ChatEntitlement.Unknown` purely due to an in-flight token fetch — either delay showing it until the token source has had a chance to resolve, or wire it to dismiss automatically once the entitlement/token state resolves to signed-in.
