# Issue #294847 — Chat: steering/queueing is quite heavy visually

[https://github.com/microsoft/vscode/issues/294847](https://github.com/microsoft/vscode/issues/294847)

## Summary

The composer already groups queue/steer choices into a dropdown, but typing during an active response still exposes that control alongside Stop. Keep this open for a design decision: maintainers proposed simplification but disagreed about the default submission behavior.

## Change summary

Reduce competing Stop, Send, Queue, and Steer affordances in the chat composer.

## Best solution

Give the active-response composer one clear primary action appropriate to its input state, while retaining discoverable, keyboard-accessible stopping and alternate submission options. Settle whether simplification changes submission defaults or only the visible controls.
