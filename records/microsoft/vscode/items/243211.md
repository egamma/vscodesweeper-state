# Issue #243211 — [Enhancement] When `(Get-Command code).Path` is set as the value of `$Env:EDITOR`, it doesn't support `systemctl edit`.

[https://github.com/microsoft/vscode/issues/243211](https://github.com/microsoft/vscode/issues/243211)

## Summary

VS Code doesn't support the nano-style `+N` line-number argument that `systemctl edit` passes, nor does it implicitly wait for the editor to close — both are needed for proper `$EDITOR` integration with CLI tools like systemctl. This is a valid enhancement request with no existing fix on main.

## Change summary

Support the `+N` (goto-line) argument syntax used by systemctl and other CLI tools when VS Code is set as `$EDITOR`.

## Best solution

Two gaps: (1) parse `+N` as a goto-line argument in the CLI argv handler (src/vs/platform/environment/node/argvHelper.ts / extpath.ts), and (2) document or improve the `$EDITOR` story (users need `code --wait` but systemctl doesn't pass `--wait`). The `+N` parsing is a small CLI change; the wait semantics may need a wrapper script recommendation or an env-var trigger. This is a valid niche enhancement for Linux CLI/editor interop.
