# Issue #311917 — [Error] potential listener LEAK — textModel / codeBlockPart (chat code block rendering)

[https://github.com/microsoft/vscode/issues/311917](https://github.com/microsoft/vscode/issues/311917)

## Summary

The reported listener accumulation remains present on current main: every live chat CodeBlockPart owns a TextModel that subscribes to the shared language-configuration event, while the pool limits only idle instances. This needs a lifecycle or virtualization design rather than closure or consolidation with the related notebook and chat-editing reports.

## Change summary

Prevent long agent responses containing many rendered code blocks from triggering a potential-listener-leak error through their per-block TextModels.

## Best solution

Bound the number or lifetime of TextModels retained by rendered chat code blocks, or eliminate their redundant shared language-configuration subscriptions, while preserving syntax highlighting, streaming updates, accessibility, and keyed editor reuse. Raising the global warning threshold alone would hide the accumulation rather than address it.
