# Issue #125582 — Restored custom editors never load if the extension is uninstalled

[https://github.com/microsoft/vscode/issues/125582](https://github.com/microsoft/vscode/issues/125582)

## Summary

Still reproduces on main: when a custom editor's backing extension is uninstalled, the webview restore path enqueues the editor into a RevivalPool that waits indefinitely for a reviver that will never register, causing a permanent loading spinner. No fallback, timeout, or error UI exists.

## Change summary

Restored custom editors show an infinite loading spinner when the contributing extension has been uninstalled or disabled.

## Best solution

Add a fallback in `WebviewEditorService.resolveWebview` (or a timeout in `RevivalPool.enqueueForRestoration`) that detects when the required extension is not installed/enabled and renders an inline error message with a 'Reopen With...' action, similar to the existing unresolved editor pattern. The team consensus from the discussion favors an inline editor-area message over a notification.
