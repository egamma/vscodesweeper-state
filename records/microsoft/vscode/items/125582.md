# Issue #125582 — Restored custom editors never load if the extension is uninstalled

[https://github.com/microsoft/vscode/issues/125582](https://github.com/microsoft/vscode/issues/125582)

## Summary

The defect remains traceable on current main, but an open PR already directly fixes the restoration path and references this issue. Keep the issue open while that implementation is reviewed.

## Change summary

Restoring a custom editor whose provider extension was uninstalled or disabled leaves the editor indefinitely loading without an actionable recovery path.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/328185, which makes unavailable custom-editor restoration fail visibly with an option to reopen the resource in the default editor while preserving normal restoration when the provider activates.
