# Issue #227709 — Allow opening chat code block in full editor

[https://github.com/microsoft/vscode/issues/227709](https://github.com/microsoft/vscode/issues/227709)

## Summary

Keep open: copying a chat code block into a new untitled editor already exists, but opening the original code-block resource for deeper exploration remains distinct. The linked discussion explicitly identifies that goal, and current source still redirects code-block resource navigation into the chat widget.

## Change summary

Allow a response code block to open in a full editor for exploration outside the cramped chat panel.

## Best solution

Provide an explicit full-editor exploration action for the original response code block, distinct from inserting a copy into a new file. Establish its editing and lifetime semantics while preserving ordinary navigation back into chat.

- **Validation:** Add action-level coverage asserting that explicit exploration opens the intended code-block resource in a full editor rather than creating an untitled copy. Manually open a response code block from its menu, verify full-editor navigation and language features, verify the chosen editing/lifetime behavior during streaming and chat closure, and confirm ordinary code-block navigation and Insert into New File remain unchanged.
- **Behavior:**

  > A user can explicitly open a response code block in a full editor to explore it without first inserting a copy into a new file. The linked author clarification identifies deeper IntelliSense exploration as the purpose. Acceptance must distinguish this operation from Insert into New File and preserve ordinary navigation into chat. Editing permissions and behavior when the originating response changes or closes must be agreed before implementation.
- **Trace:**

  > InsertIntoNewFileAction in src/vs/workbench/contrib/chat/browser/actions/chatCodeblockActions.ts copies context.code into an untitled editor and records an acceptance action; it does not expose the original model. ChatWidget in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts intercepts vscodeChatCodeBlock editor navigation and returns the matching embedded editor after revealing its response. ChatCodeBlockContentProvider in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/codeBlockPart.ts can resolve an existing code-block model. The author's explanation at https://github.com/microsoft/vscode-copilot/issues/8003#issuecomment-2338585761 confirms that full-editor exploration is the intended distinction. Preserve normal chat navigation and the existing copy/insertion commands; this request does not require implementing backing-URI metadata from https://github.com/microsoft/vscode/issues/283247. The trace establishes the entry points but not a durable editor/model lifetime contract.
- **Open decisions:**
  - Should the full-editor view remain read-only like the response code block, or allow edits, and if editable should those edits change the displayed response?
  - Should the full-editor view track streaming updates and remain usable after the originating chat closes, and what should survive a window reload?
