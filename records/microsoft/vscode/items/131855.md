# Issue #131855 — ctrl+z undo both auto-indentation and default behavior

[https://github.com/microsoft/vscode/issues/131855](https://github.com/microsoft/vscode/issues/131855)

## Summary

The reported undo behavior remains on current main: Tab computes the complete smart indentation as one edit, so one undo necessarily returns the line to its original empty state. The related paste issue does not own this request and in fact discusses the opposite undo-grouping preference for a different action.

## Change summary

Undoing smart indentation inserted by Tab should retain the ordinary one-tab indentation instead of returning the cursor to the start of the line.

## Best solution

Decide whether smart indentation triggered by Tab should expose an intermediate ordinary-tab state in the undo history, then encode that contract in the editor cursor tests without changing paste undo semantics.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add a cursor controller test reproducing the issue's JavaScript example: after Tab the cursor reaches the computed smart indentation, the first Undo leaves one normal tab stop of indentation, and the second Undo restores the empty line; existing Tab and paste undo tests must remain unchanged.
- **Behavior:**

  > On a whitespace-only line where Tab jumps to a smart indentation target deeper than one normal tab stop, pressing Undo once should retain the indentation that an ordinary Tab would have inserted. A second Undo should restore the original line. Tab behavior on lines that do not use smart indentation and undo behavior after paste must remain unchanged.
- **Trace:**

  > CoreEditingCommands.Tab in src/vs/editor/browser/coreCommands.ts places undo stops around one call to TypeOperations.tab. TypeOperations.tab delegates to TabOperation.getCommands in src/vs/editor/common/cursor/cursorTypeEditOperations.ts; for a whitespace-only line, that method computes the complete smart target and emits one ReplaceCommand, so the model contains no intermediate ordinary-tab edit for Undo to restore. Existing tests in src/vs/editor/test/browser/controller/cursor.test.ts confirm the smart jump but do not assert its undo granularity. https://github.com/microsoft/vscode/issues/30406 is related but paste-specific and debates combining rather than splitting undo items, so its semantics must not be changed implicitly.
- **Open decisions:**
  - Should a single Tab invocation intentionally create two undoable states when smart indentation exceeds one ordinary tab stop?
  - Should the intermediate state always be exactly one configured tab stop from the original cursor, including tabs-versus-spaces and partially indented whitespace-only lines?
  - Is this undo behavior strictly limited to Tab, leaving the paste auto-indentation behavior discussed in https://github.com/microsoft/vscode/issues/30406 unchanged?

## Evidence

- **current source path:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts, TabOperation.getCommands, computes `_goodIndentForLine`, normalizes the entire result, and returns one ReplaceCommand for the whitespace-only line. There is no separate ordinary-tab edit that undo could preserve.
- **undo boundary:** src/vs/editor/browser/coreCommands.ts runs TypeOperations.tab between one undo stop before and one after the command, making the resulting smart indentation a single undo unit.
- **current test coverage:** src/vs/editor/test/browser/controller/cursor.test.ts contains Tab auto-indentation tests such as `bug #16543: Tab should indent to correct indentation spot immediately`, but does not test the requested intermediate state after Undo.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/30406 remains open and concerns an extra undo item created by auto-indentation after paste. Its discussion asks whether paste and indentation should be combined, whereas this report asks for Tab's ordinary and smart indentation to become separately undoable.
