# Issue #107123 — Option to combine tabs and title bar

[https://github.com/microsoft/vscode/issues/107123](https://github.com/microsoft/vscode/issues/107123)

## Summary

Keep this accepted, well-supported request open: current settings do not combine editor tabs and window controls into one row in windowed mode. The older related requests are platform-specific and do not fully absorb this Windows-inclusive request.

## Change summary

Offer a windowed layout that combines editor tabs and the title bar to reclaim vertical editing space.

## Best solution

Design an optional combined title/tab row that preserves window controls, window dragging, menu access, and editor navigation. Agree how split editor groups and overflowing tabs participate before implementing the workbench layout changes.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/browser/parts/editor/editorTitleControl.ts`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`, `src/vs/workbench/electron-browser/desktop.contribution.ts`
- **Validation:** The plan should end with an explicit desktop check: enable the proposed mode in a non-fullscreen window, open enough editors to overflow tabs, split an editor group, and verify the combined row saves vertical space while tab selection/reordering, window dragging, minimize/maximize/close, and keyboard menu access remain usable. Disabling the mode must restore the existing layout.
- **Behavior:**

  > Users can opt into a windowed layout where editor tabs share the title-bar row rather than consuming a second row. The mode must retain usable window controls, window dragging, editor navigation, and menu access. Acceptance includes overflowing tabs, split editor groups, and restoring the existing layout when the option is disabled; fullscreen alone does not satisfy the request.
- **Trace:**

  > The inspected checkout keeps the title bar and editor in separate grid leaves in src/vs/workbench/browser/layout.ts:createGridDescriptor. EditorTitleControl.createEditorTabsControl in src/vs/workbench/browser/parts/editor/editorTitleControl.ts creates tab controls per editor group, while window title-bar UI belongs to src/vs/workbench/browser/parts/titlebar/titlebarPart.ts. The existing window.customTitleBarVisibility and workbench.editor.editorActionsLocation settings hide chrome or relocate actions, not tabs into window chrome. The remaining uncertainty is the user-facing composition of a shared row across editor groups and the space reserved for window interactions. Preserve existing default, fullscreen, and editor-group behavior outside the opt-in mode. Related platform explorations are https://github.com/microsoft/vscode/issues/12377 and https://github.com/microsoft/vscode/issues/43154, not verified duplicate canonicals for this issue.
- **Open decisions:**
  - When editors are split into groups, does the combined title row show only the active group's tabs or tab regions for multiple groups?
  - When tabs fill the available row, what visible space remains reserved for window dragging, window controls, and menu access?
