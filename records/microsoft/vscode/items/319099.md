# Issue #319099 — [BYOM]: Models use Anthropic messages API  can not specify custom reasoning effort field path.

[https://github.com/microsoft/vscode/issues/319099](https://github.com/microsoft/vscode/issues/319099)

## Summary

The underlying capability may already exist — when `apiType: 'messages'` is configured, the Messages API code path automatically sends reasoning effort as `output_config.effort` (messagesApi.ts line 257) without needing `reasoningEffortFormat`. However, the user-facing documentation and configuration surface don't make this clear, and the interaction between `thinking`, `supportsReasoningEffort`, and `apiType` for BYOM Messages API endpoints may have gaps. Keeping open as a valid feature request / documentation gap.

## Change summary

Allow BYOM models using the Anthropic Messages API to specify a custom reasoning effort field path (e.g. `output_config.effort`), since `reasoningEffortFormat` only accepts `'chat-completions'` or `'responses'`.

## Best solution

Clarify in the BYOM documentation that Messages API endpoints (`apiType: 'messages'`) automatically place reasoning effort in `output_config.effort` — `reasoningEffortFormat` is only relevant for OpenAI-compatible endpoints. If the automatic handling doesn't cover the reporter's scenario (e.g. custom providers with non-standard field paths), consider adding a `'messages'` value to `reasoningEffortFormat` or a freeform field-path override. The code in `extensions/copilot/src/platform/endpoint/node/messagesApi.ts` and `extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts` would be the likely touch points.
