# Issue #334489 — Alt keyup is missed while a webview editor has focus, silently turning a tab's Close button into "Close Other Editors"

[https://github.com/microsoft/vscode/issues/334489](https://github.com/microsoft/vscode/issues/334489)

## Summary

Keep open: two independent reports reproduce a destructive stale-Alt state when returning to a webview-focused VS Code window, on both Windows and Linux. The older related reports were closed, and current 1.136.1 confirmations show that their fixes did not resolve this webview-specific symptom.

## Change summary

Releasing Alt after switching back to a webview-focused window can leave VS Code treating Alt as held, turning a tab's Close action into Close Other Editors.

## Best solution

Correct modifier-state synchronization across native-window and webview focus transitions, and ensure the tab close action cannot remain in Close Other Editors mode after Alt is physically released. Add regression coverage for returning to a window while a webview-backed editor owns focus.

## Plan brief

- **Behavior:**

  > When VS Code regains focus after Alt+Tab while a webview-backed editor had focus, releasing Alt must clear any Alt-modifier state even if the keyup was not delivered to the workbench document. Hovering and clicking a tab close button must then perform the ordinary Close action, not Close Other Editors. Deliberately holding Alt and clicking a close button while VS Code is focused must continue to invoke Close Other Editors. Acceptance should cover the built-in Markdown Preview path and a normal text editor control case.
- **Trace:**

  > The issue and an independent Linux confirmation isolate the trigger to webview-backed editor focus and report that keyboard input clears the stale state while blur/focus alone does not. The observable consumer is the editor tab close action, which switches to Close Other Editors based on global modifier state; the likely producer lies in browser modifier tracking and the webview focus boundary. Related reports https://github.com/microsoft/vscode/issues/331979, https://github.com/microsoft/vscode/issues/332070, and https://github.com/microsoft/vscode/issues/333480 are closed, while this exact symptom is confirmed on 1.136.1, so their prior handling must not be treated as proof of resolution. Preserve intentional Alt+Click behavior and avoid changing unrelated webview keyboard routing.
