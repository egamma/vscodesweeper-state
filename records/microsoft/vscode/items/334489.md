# Issue #334489 — Alt keyup is missed while a webview editor has focus, silently turning a tab's Close button into "Close Other Editors"

[https://github.com/microsoft/vscode/issues/334489](https://github.com/microsoft/vscode/issues/334489)

## Summary

This is a very well-diagnosed report of the same modifier-key latch that #331979 already tracks (an open issue with a matching title), just narrowed down to the webview-focus precondition — proposing a duplicate close so the investigation consolidates on one thread, carrying forward the extra diagnostic detail.

## Change summary

After Alt+Tab away and back while a webview-backed editor (e.g. Markdown preview) has focus, VS Code keeps believing Alt is held, silently turning a tab's Close button into destructive 'Close Other Editors'.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/331979 and fix the root cause in ModifierKeyEmitter (src/vs/base/browser/dom.ts) — modifier state is only reset on a top-level `window` 'blur' event and never re-synced on refocus; when the Alt keyup is delivered to a webview iframe (or to the OS switcher) rather than to the top document, the emitter's latched altKey never clears, and multiEditorTabsControl.ts's 'Close Others' affordance (added in #328975) then acts on the stale state.

## Evidence

- **canonical candidate:** https://github.com/microsoft/vscode/issues/331979 is open and titled 'Alt-Tab away and back leaves a tab's Close button stuck showing "Close Other Editors"' — same symptom, same trigger (Alt-Tab), listed as a related item in this issue's timeline.
- **mechanism traced:** src/vs/base/browser/dom.ts ModifierKeyEmitter.registerListeners only resets `_keyStatus` on the top-level window's 'blur' event (line ~1994); there is no 'focus' handler to re-sync state, and keydown/keyup listeners are attached per top window (lines 1911, 1948), so a keyup delivered inside a webview iframe's separate document (or swallowed by the OS switcher before VS Code regains focus) never reaches this listener, leaving altKey latched true.
- **affordance that exposed it:** src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts:1673 (`wantsCloseOthersAction`) reads `modifierKeyEmitter.keyStatus.altKey` to decide whether hovering the close button shows 'Close Others' — added in #328975 (shipped 1.134), turning the pre-existing latch into a destructive action.
- **closed related report:** https://github.com/microsoft/vscode/issues/333480 ('The tab button is changed to one that closes all tabs') is already closed, consistent with this being a recognized, recurring symptom of the same defect.
