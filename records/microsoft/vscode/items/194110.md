# Issue #194110 — Changing the setting from boolean to string should be shown as a deprecation and not as an error at least for some grace period

[https://github.com/microsoft/vscode/issues/194110](https://github.com/microsoft/vscode/issues/194110)

## Summary

Team-authored issue still valid on main — the settings editor still shows a hard error when a setting's type changes (e.g. boolean→string), with no grace-period or deprecation-style presentation. No fix has landed.

## Change summary

When a setting's type changes from boolean to string, the settings editor shows a validation error instead of a softer deprecation warning during a transition period.

## Best solution

Add a grace-period mechanism in the settings type validation path (around `getInvalidTypeError` in `src/vs/workbench/services/preferences/common/preferencesValidation.ts` and its consumers in `settingsTree.ts`) that renders a deprecation-style warning instead of an error when the stored value matches a previously-valid type. The `IConfigurationMigrationRegistry` could drive which settings are in a transition period.
