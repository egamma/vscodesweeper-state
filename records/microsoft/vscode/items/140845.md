# Issue #140845 — Proposal: pin specific thread(s) when debugging

[https://github.com/microsoft/vscode/issues/140845](https://github.com/microsoft/vscode/issues/140845)

## Summary

Keep open: focused-thread stepping already exists, but a stable, ordered set of pinned threads does not. The linked concurrency proposal is related design work, not a verified duplicate of this report's moving call-stack controls and pinned-thread stepping request.

## Change summary

Provide stable access to selected debugging threads, optionally pinned in selection order, with stepping commands that target those threads.

## Best solution

Define a persistent-within-session selection of interesting threads in the debug Call Stack experience, with stable ordering and explicit stepping targets. Coordinate with the concurrent-debugging discussion while preserving ordinary focused-thread stepping.

- **Behavior:**

  > The reporter repeatedly loses reliable access to a thread's stepping controls as the Call Stack changes during multithreaded debugging. Interesting threads should remain easy to locate and operate without accidentally targeting another thread. If pinning is adopted, multiple pinned threads should retain pin-time ordering and the stepping interaction should explicitly identify its target. Acceptance must cover repeated stops, stack refreshes and thread exit, while preserving ordinary focused-thread stepping.
- **Trace:**

  > CallStackDataSource.getChildren in src/vs/workbench/contrib/debug/browser/callStackView.ts exposes session.getAllThreads(), and its thread renderer supplies context-bound inline stepping actions. getThreadAndRun in src/vs/workbench/contrib/debug/browser/debugCommands.ts selects the supplied thread or falls back to the debug view model's focusedThread; the inspected command and configuration registrations do not establish a pinned-thread collection. The existing editor-opening pinned option is unrelated. https://github.com/microsoft/vscode/issues/116109 contains thread tracking and bookmark design discussion, but does not settle this request's multiple-target interaction. https://github.com/microsoft/vscode/issues/322448 separately discusses preserving focus during stepping and should inform, not replace, this design. Keep ordinary debugging and adapter execution semantics unchanged outside the approved pinned-target contract.
- **Open decisions:**
