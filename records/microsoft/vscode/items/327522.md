# Issue #327522 — Terminal always starts with a warning sign

[https://github.com/microsoft/vscode/issues/327522](https://github.com/microsoft/vscode/issues/327522)

## Summary

The warning is intentional VS Code behavior when an extension changes the environment of an already-running extension-owned terminal. The late contribution originates in the Microsoft Python Environments extension, so this should remain open until it is moved to that extension's tracker.

## Change summary

Avoid requiring a relaunch when Python environment variables are contributed after the PowerShell extension creates its background terminal.

## Best solution

Move the issue to https://github.com/microsoft/vscode-python-environments and investigate why its asynchronous environment initialization updates the collection after the PowerShell terminal starts. Preserve VS Code's safeguard against automatically restarting extension-owned terminals.

## Evidence

- **core behavior:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts deliberately excludes feature and extension-owned terminals from automatic environment-change relaunches, while environmentVariableInfo.ts presents the warning and manual relaunch action.
- **intentional safeguard:** https://github.com/microsoft/vscode/pull/117987 introduced commit cf3faa404605db2e613a99da38000e1c1b2bd2fe specifically to prevent automatic relaunch of extension-owned terminals.
- **extension ownership:** https://github.com/microsoft/vscode-python-environments/blob/c0f89be34b5074483235c93f08e799a1f397586d/src/features/terminal/terminalEnvVarInjector.ts updates the extension environment-variable collection asynchronously during initialization; that repository is active and has its own issue tracker.
