# Issue #332631 — Search: async exclude evaluation ignores a matching exclude when several exclude expressions are configured

[https://github.com/microsoft/vscode/issues/332631](https://github.com/microsoft/vscode/issues/332631)

## Summary

Confirmed real bug in QueryGlobTester.includedInQuery: when multiple exclude expressions are configured and at least one is evaluated asynchronously (sibling clause), Promise.all + .some() ORs per-expression results, so a non-matching exclude from one expression can override a matching exclude from another, and the sync branch never even checks its own `excluded` result. An open PR already fixes it, so no close is proposed.

## Change summary

Async exclude evaluation in includedInQuery can incorrectly report a path as included even though one of several configured exclude expressions matches it, diverging from the correct semantics implemented in includedInQuerySync.

## Best solution

Land and review PR https://github.com/microsoft/vscode/pull/332632 ("Search: make async includedInQuery respect any exclude expression"), which appears to directly fix this defect; once merged this issue can be closed as completed.
