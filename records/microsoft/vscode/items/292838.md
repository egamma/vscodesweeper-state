# Issue #292838 — "Open File" from diff editor should be in the context menu and command palette

[https://github.com/microsoft/vscode/issues/292838](https://github.com/microsoft/vscode/issues/292838)

## Summary

The discoverability gap remains: current main provides a related palette command, but not the requested diff-tab context-menu action or consistently available equivalent of the toolbar's Open File action. Keep this open as a feature request; the verified related issues do not cover its full scope.

## Change summary

Expose the diff editor's Open File action in the tab context menu and command palette.

## Best solution

Make opening the corresponding normal file editor discoverable from both requested surfaces, with behavior consistent with the existing toolbar action. Reuse the existing Git/editor command infrastructure while preserving the distinction between opening a historical diff side and opening the working file.

Its commandPalette entry at lines 1263–1265 instead requires resourceScheme == file && scmActiveResourceHasChanges; it does not mirror the toolbar's availability. The manifest has no editor/title/context contribution.
- **Existing capability is partial:** src/vs/workbench/browser/parts/editor/diffEditorCommands.ts:30–44 exposes workbench.action.compareEditor.openSide as Open Active Diff Side in the command palette. DiffEditorCommandsService.openActiveDiffSide in diffEditorCommandsService.ts:119–138 opens the original input when that side has text focus, otherwise the modified input. This helps open a diff side separately, but does not provide the requested tab context-menu entry or necessarily the working-file semantics of git.openFile.
- **Command behavior boundary:** extensions/git/src/commands.ts:1300–1375 implements git.openFile. An explicitly supplied Git URI is converted to a file URI, whereas invocation without an argument resolves an SCM resource or falls back to the active document URI. Exposing another invocation surface therefore needs attention to which resource it opens, not only command visibility.
