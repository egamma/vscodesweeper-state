# Issue #345628 — Consider removing the results section of worktree cleanup

[https://github.com/microsoft/vscode/issues/345628](https://github.com/microsoft/vscode/issues/345628)

## Summary

Keep open for a UX decision: successful cleanup rows are deliberately retained today, but removing that redundant detail is a reasonable refinement. The decision must preserve useful progress, failure recovery, and accessible completion feedback.

## Change summary

Remove successfully deleted worktrees from the cleanup list instead of retaining them in the results section.

## Best solution

Agree whether successful cleanup needs per-worktree history or only concise completion feedback, then apply that presentation consistently in the cleanup editor while retaining pending and failed worktrees.
