# Issue #240207 — WebView state unexpectedly persists across sessions without a WebviewPanelSerializer

[https://github.com/microsoft/vscode/issues/240207](https://github.com/microsoft/vscode/issues/240207)

## Summary

The behavior is reproducible on current main — WebviewViewPane stores state in a workspace-scoped Memento that persists across restarts (commit be6d3c4dda from 2020 intentionally added this). The documentation about WebviewPanelSerializer only describes WebviewPanel behavior; WebviewView state persistence is undocumented but appears intentional. Keeping open as the intended behavior vs. documentation mismatch needs a maintainer decision.

## Change summary

WebviewView state (via getState/setState) persists across VS Code restarts even without a WebviewPanelSerializer, contradicting the documented behavior for webview state persistence.

## Best solution

The maintainer should decide whether WebviewView state should reset on restart (requiring a code change in webviewViewPane.ts to not restore persisted state unless an opt-in mechanism exists) or whether the documentation should be updated to clarify that WebviewView persistence works differently from WebviewPanel persistence. If the current behavior is intentional, document it clearly and provide an API for extensions to opt out of cross-session state persistence.
