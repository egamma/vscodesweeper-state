# Issue #240207 — WebView state unexpectedly persists across sessions without a WebviewPanelSerializer

[https://github.com/microsoft/vscode/issues/240207](https://github.com/microsoft/vscode/issues/240207)

## Summary

The sample uses a WebviewView, whose state intentionally persists across editor restarts without a WebviewPanelSerializer. Keep this accepted Backlog item open for documentation clarification: the serializer documentation uses generic language that obscures the distinction between views and panels.

## Change summary

Clarify webview view versus panel persistence, including restart behavior, state scoping, and replacement semantics.

## Best solution

Clarify the API documentation in src/vscode-dts/vscode.d.ts so WebviewPanelSerializer's requirements explicitly apply to panels, and cross-reference WebviewViewResolveContext.state for automatically persisted views. Preserve existing view persistence and explain that state is scoped to the view within its workspace and setState replaces the whole value.
