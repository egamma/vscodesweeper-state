# Issue #198984 — Search view is default view when using remote

[https://github.com/microsoft/vscode/issues/198984](https://github.com/microsoft/vscode/issues/198984)

## Summary

The view-restoration race remains visible in current source: Explorer can be treated as empty during native remote startup, causing the activity bar to fall through to Search. The issue should remain open as the older, broader report while the overlapping draft fix is reviewed.

## Change summary

Reloading or opening remote and heavily concurrent windows can replace the previously active Explorer view with Search or another activity-bar view.

## Best solution

Preserve Explorer as the active default while its views are still initializing in native remote windows, without exposing genuinely empty extension containers. Review and extend https://github.com/microsoft/vscode/pull/288264 to cover this broader remote and multi-window report and add a startup-restoration regression test.

## Evidence

- **current source path:** src/vs/workbench/contrib/files/browser/explorerViewlet.ts registers Explorer as the default sidebar container with `hideIfEmpty: true`. In src/vs/workbench/browser/parts/paneCompositeBar.ts, `shouldBeHidden` can see that container before its active views load, skips cached visibility for a native remote sidebar, and returns true.
- **fallback behavior:** src/vs/workbench/browser/parts/compositeBar.ts hides the active default container and opens the first remaining visible composite, explaining why Search or another neighboring view becomes active.
- **confirmed reproduction:** A later commenter reproduced the lost primary-sidebar selection with extensions disabled by opening many windows concurrently and identified Explorer initialization timing as the trigger.
- **related report:** https://github.com/microsoft/vscode/issues/245936 described the same Explorer-to-next-view symptom in WSL but was closed only after its reporter stopped seeing it; no concrete fixing commit was identified.
- **overlapping implementation:** The newer, narrower https://github.com/microsoft/vscode/issues/286289 remains open for the top-activity-bar variant, with draft PR https://github.com/microsoft/vscode/pull/288264 modifying the same `shouldBeHidden` path. That PR does not reference this issue and its current change leaves the native-remote cache exclusion in place.
