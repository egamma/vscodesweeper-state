# Issue #166489 — Support alt+enter in terminal quick fixes to add a command but not execute it

[https://github.com/microsoft/vscode/issues/166489](https://github.com/microsoft/vscode/issues/166489)

## Summary

A real gap remains on current main: terminal quick fixes always execute selected command actions, while Run Recent Command already supports inserting with the Alt modifier. Maintainers explicitly accepted the consistency goal, so this On Deck request should remain open.

## Change summary

Allow an alternate terminal quick-fix acceptance gesture to insert the selected command without executing it.

## Best solution

Terminal command quick fixes should support both outcomes consistently with Run Recent Command: normal acceptance executes the command, while the alternate acceptance inserts it and returns focus to the terminal. Opener and VS Code command quick fixes should retain their existing behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts`, `src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFix.ts`, `src/vs/workbench/contrib/terminalContrib/quickFix/test/browser/quickFixAddon.test.ts`, `src/vs/platform/actionWidget/browser/actionWidget.ts`, `src/vs/workbench/contrib/terminalContrib/accessibility/browser/terminalAccessibilityHelp.ts`
- **Validation:** Add a terminal quick-fix test using a mocked IActionWidgetService that verifies normal acceptance requests runCommand(command, true), alternate acceptance requests runCommand(command, false), and non-terminal quick-fix actions remain unchanged; manually verify the documented shortcut from the focused quick-fix menu.
- **Behavior:**

  > Selecting a terminal-command quick fix normally executes the proposed command. Accepting the same item with the terminal alternate gesture inserts the command at the prompt without executing it and returns focus to the terminal, matching Run Recent Command. Opener, port, explain, and VS Code command actions retain their current behavior. The terminal accessibility help identifies the alternate gesture.
- **Trace:**

  > TerminalQuickFixAddon.showMenu in src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts passes supportsPreview=false and its delegate discards the optional alternate-selection argument, so every terminal-command item runs its preconfigured action. The generated action then fires onDidRequestRerunCommand with a fixed shouldExecute value, which TerminalQuickFixContribution forwards to ITerminalInstance.runCommand. Run Recent Command already establishes the requested terminal behavior in src/vs/workbench/contrib/terminalContrib/history/browser/terminalRunRecentQuickPick.ts by using the Alt modifier to pass false. The shared action widget currently reserves Ctrl/Cmd+Enter for preview, so the plan must preserve editor code-action behavior while providing the terminal-specific Alt+Enter contract. Do not alter execution semantics for non-terminal-command quick fixes.

## Evidence

- **current source gap:** src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts:143-151 ignores the action-widget selection modifier and calls IActionWidgetService.show with supportsPreview=false, so alternate acceptance cannot request insertion without execution.
- **execution path:** src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts:394-408 fires onDidRequestRerunCommand with the quick fix's fixed shouldExecute value, and src/vs/workbench/contrib/terminalContrib/quickFix/browser/terminal.quickFix.contribution.ts:56 forwards that value to ITerminalInstance.runCommand.
- **existing precedent:** src/vs/workbench/contrib/terminalContrib/history/browser/terminalRunRecentQuickPick.ts:352-366 passes !quickPick.keyMods.alt to runCommand, so accepting with Alt inserts the selected recent command without executing it and restores terminal focus.
