# Issue #335015 — Agents window needs CLI/native Chat feature parity for daily use

[https://github.com/microsoft/vscode/issues/335015](https://github.com/microsoft/vscode/issues/335015)

## Summary

A real cross-cutting parity gap remains, although current main already implements parts of the request. Older issues cover individual slices, but none is an older canonical with the same full observable scope required to close this re-reviewed item as a duplicate.

## Change summary

Make the Agents Window practical for daily use by matching CLI and native Chat capabilities for context, configuration, navigation, session management, and visible runtime state.

## Best solution

Keep this as the Agents Window parity umbrella and define a provider-neutral capability matrix covering folder context, session controls, model/agent configuration, shortcuts, and visible state. Focused implementation issues such as multi-root operation can remain independently tracked while this issue records whether the overall daily-use parity contract is met.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/slashCommands.ts`, `src/vs/sessions/contrib/chat/browser/modelPicker.ts`, `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/services/sessions/common/sessionsProvider.ts`
- **Validation:** End the plan with a provider-by-provider parity matrix and focused tests demonstrating the selected folder-context, model/agent/reasoning, slash-command, keyboard-navigation, and session-list behaviors in the Agents Window.
- **Behavior:**

  > The Agents Window should support daily agent work without forcing users to switch to the CLI or normal Chat for basic context, configuration, navigation, or session-management operations. Users can attach the supported folder contexts, understand and change the active model/agent/reasoning configuration, navigate sessions efficiently, and see the effective working directory and context. Each CLI capability selected for parity must have either compatible slash syntax or an obvious UI, command-palette, and keybinding path.
- **Trace:**

  > Current main already contains several independent pieces: ModelPicker in src/vs/sessions/contrib/chat/browser/modelPicker.ts, SlashCommandHandler in src/vs/sessions/contrib/chat/browser/slashCommands.ts, additional-folder handling through sessionWorkspacePicker.ts and newChatWidget.ts, and the persisted session surface in sessionsList.ts. The provider contract in src/vs/sessions/services/sessions/common/sessionsProvider.ts is the boundary through which provider-specific capabilities must remain exposed without coupling shared Sessions UI to a provider. Multi-root read/write behavior is already tracked by https://github.com/microsoft/vscode/issues/318936, and local-harness parity is tracked by https://github.com/microsoft/vscode/issues/325133; those are component work, not full canonical replacements for this umbrella. Preserve provider-neutral Sessions ownership and avoid requiring every backend to advertise capabilities it cannot support.
- **Open decisions:**
  - Which CLI operations must retain slash-command syntax in the Agents Window, and which may be satisfied solely by discoverable UI, command-palette, and keybinding equivalents?
  - Does cross-folder parity require one agent session to read and write every selected root, or may some attached directories be context-only?
  - Which active configuration fields must remain persistently visible versus being available on demand, especially in compact layouts?

## Evidence

- **partial existing capability:** Current main already has a provider-neutral model picker in src/vs/sessions/contrib/chat/browser/modelPicker.ts and built-in slash-command handling, including `/models`, in src/vs/sessions/contrib/chat/browser/slashCommands.ts.
- **folder context:** src/vs/sessions/contrib/chat/browser/newChatWidget.ts and sessionWorkspacePicker.ts use the additional-folder identifiers defined in src/vs/sessions/contrib/chat/common/newChatContextIds.ts, but the broader multi-root read/write behavior remains separately tracked by the open https://github.com/microsoft/vscode/issues/318936.
- **session history surface:** src/vs/sessions/SESSIONS_LIST.md and src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts confirm that the Agents Window has a grouped, filterable session list with archive, pin, grouping, sorting, and persisted presentation state; this only partially covers the requested parity and discoverability.
- **related but narrower:** The older open https://github.com/microsoft/vscode/issues/325133 concerns using the native local Copilot harness in the Agents Window, while https://github.com/microsoft/vscode/issues/318936 concerns multi-root operation. Neither owns this issue's complete CLI/UI parity scope or the same full reporter-observable symptom.
- **remaining gap:** The static Agents Window command set in src/vs/sessions/contrib/chat/browser/slashCommands.ts exposes customization commands and `/models`, but does not itself provide the requested session, directory, agent-switching, or reasoning-level command parity; Agent Host command completion is delegated to the host.
