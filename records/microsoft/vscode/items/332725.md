# Issue #332725 — Renderer and extension host OOM when running multiple concurrent Copilot chat/agent sessions (Windows)

[https://github.com/microsoft/vscode/issues/332725](https://github.com/microsoft/vscode/issues/332725)

## Summary

Keep open: a team-authored report provides repeated renderer OOM reproductions and concrete listener-retention stacks, while current source inspection does not establish that the renderer leak is fixed. Older OOM reports share the visible crash symptom but do not establish the same retention path strongly enough for the re-review duplicate bar.

## Change summary

Multiple concurrent, long-running Copilot agent sessions accumulate renderer listeners and memory until the renderer, extension host, or related utility processes terminate.

## Best solution

Bound renderer memory across concurrent chat sessions by identifying which rendered code-block references and chat-editing model references remain live after their content or session is released. Validate the renderer and extension-host paths separately, preserving long transcripts, code-block rendering, and editing-session restoration while preventing sustained listener and heap growth.
