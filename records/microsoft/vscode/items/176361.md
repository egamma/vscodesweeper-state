The unresolved git.path environment-variable behavior is already tracked by the older, open canonical issue. Consolidate there, preserving this report's evidence that a system Git installation masks the intended portable executable.

## Change summary

A git.path containing an environment-variable placeholder selects the system Git instead of the configured portable Git.

Resolve environment-variable handling for git.path under https://github.com/microsoft/vscode/issues/116495 so the configured executable takes precedence after resolution; retain this report's two-installation reproduction in that discussion.

- **Current source trace:** extensions/git/src/main.ts:42-53 reads git.path and passes its strings directly to findGit without variable expansion. In extensions/git/src/git.ts:86-97, findSpecificGit passes the unchanged path to cp.spawn; findGit at lines 165-184 tries those hints and then falls back to platform discovery. findGitWin32 at lines 157-163 searches standard Windows installations before PATH. This explains the reported selection without treating the final portable path as evidence of placeholder expansion.
