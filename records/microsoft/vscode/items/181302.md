# Issue #181302 — Custom task shell executable doesn't work

[https://github.com/microsoft/vscode/issues/181302](https://github.com/microsoft/vscode/issues/181302)

## Summary

Thanks for the report and for tracing the cause. A custom shell executable still skips the shell's command flag on current main. The task fails unless the user adds `-Command`, `-c` or `/d /c` to `args` by hand. The issue is labeled `bug` and parked in Backlog, so a decline close is off the table. The earlier fix citation was refuted and the cited commit is not in this checkout.

## Change summary

A task with a custom `options.shell.executable` fails because the shell's command flag (e.g. `-Command`) is not added automatically.

## Best solution

Either add the default command flag when the user gives an executable but no args, or document clearly that custom shell args must include the command flag. A maintainer should choose.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`
- **Validation:** A terminal task system test showing that a task with a custom shell executable and no args gets the shell's command flag, if auto-adding is chosen.
- **Behavior:**

  > A task that sets `options.shell.executable` without args should run its command in that shell, as it does with the default shell. Acceptance: pwsh, bash and cmd custom executables run the task command, and tasks that already set args are unchanged.
- **Trace:**

  > In terminalTaskSystem.ts, the shell argument setup (~1251-1305) uses `shellSpecified` to skip adding `-Command`, `-c` or `/d /c` once an executable is configured. This dates from an old commit referenced in the thread. The boundary is that tasks with explicit `args` must keep working. Uncertainty: changing the default could double the flag for users who already pass it.
- **Open decisions:**
  - Auto-add the command flag when an executable is set but no args are given, or keep the current behavior and document it?
  - If auto-adding, how should users who already pass the flag in `args` be handled?

## Evidence

The behavior from the report is therefore unchanged on main.
