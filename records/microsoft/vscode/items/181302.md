# Issue #181302 — Custom task shell executable doesn't work

[https://github.com/microsoft/vscode/issues/181302](https://github.com/microsoft/vscode/issues/181302)

## Summary

Thanks for the report. The behavior still exists on main: when `options.shell.executable` is set, `terminalTaskSystem.ts` skips adding the shell's command flag (`-Command`, `-c`, `/d /c`), so the task command is not executed. The workaround is to add `args` explicitly. The maintainers have not decided whether to change this or document it.

## Change summary

A custom task shell executable stops the command-flag (e.g. `-Command` for PowerShell, `-c` for bash) from being added, so the task fails to run its command.

## Best solution

Either always add the shell-appropriate command flag for known shells when only `executable` is given (and `args` is unset), or document that `shell.args` must include the command flag. The fix belongs in the shell-args block of `terminalTaskSystem.ts` (`shellSpecified` handling).

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`
- **Validation:** A task-system test (or manual check) where `shell.executable` is pwsh.exe/bash with no args runs the command, and an existing config with explicit `-Command` args does not get the flag twice.
- **Behavior:**

  > A task that sets only `options.shell.executable` to a known shell (pwsh, powershell, bash, zsh, cmd) runs its command, or the docs clearly state that `args` must carry the command flag. Existing configs that specify `shell.args` keep working unchanged.
- **Trace:**

  > In `terminalTaskSystem.ts`, `shellSpecified` is set when `shellOptions.executable` is given. The `toAdd` command flags are then only added when `!shellSpecified`. This was introduced in 8b5b1eb4 and the behavior is unchanged on main. Do not break configs that already supply `args` containing the flag. Related, still open: https://github.com/microsoft/vscode/issues/214931 (quoting) is a different symptom.
- **Open decisions:**
  - Should the command flag be auto-added when only `executable` is set (a behavior change), or should this be documentation-only?
  - If auto-added, how should it avoid duplicating a flag when users already pass `args: ["-Command"]`?

## Evidence

- **current code:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts (~lines 1251-1305): `shellSpecified = true` when `shellOptions.executable` is set, and every `toAdd.push('-Command' / '-c' / '/d','/c')` is guarded by `!shellSpecified`.
- **workaround:** In the thread, the reporter confirmed `"shell": {"executable": "...pwsh.exe", "args": ["-Command"]}` works.
- **prior review:** A previously cited fix commit was refuted, so there is no fix on main and the issue stays open.
