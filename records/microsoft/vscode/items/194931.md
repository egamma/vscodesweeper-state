# Issue #194931 — Find and Replace in closed notebook search

[https://github.com/microsoft/vscode/issues/194931](https://github.com/microsoft/vscode/issues/194931)

## Summary

Keep open: notebook-aware replacement across closed notebooks remains distinct from the existing experimental search capability. Maintainers have explicitly retained this issue as the destination for open/closed notebook search differences; no verified fix or older canonical covers the request.

## Change summary

Support notebook-aware workspace search and replacement in closed notebooks without editing serialized JSON as ordinary text.

## Best solution

Complete the closed-notebook search-to-edit lifecycle so replacements operate on notebook cell content and save through the notebook model and serializer. Preserve notebook structure and escaping, and retain read-only treatment of output matches.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/notebookSearch/notebookSearchService.ts`, `src/vs/workbench/contrib/search/browser/notebookSearch/notebookSearchModel.ts`, `src/vs/workbench/contrib/search/browser/replaceService.ts`, `src/vs/workbench/contrib/notebook/common/notebookEditorModelResolverService.ts`
- **Validation:** Use a workspace containing closed .ipynb files with quoted strings, backslashes, and multiline cell sources. Compare notebook-aware search results with the same files open; exercise individual replacement and Replace All, then reopen the notebooks and verify exact cell text, valid serialization, unchanged metadata and outputs, and no edits to output-only matches.
- **Behavior:**

  > Workspace search should support replacing matches in closed notebook cell content without requiring the user to open each notebook first. Searching and replacing quoted strings, escape sequences, and multiline content must use notebook text semantics rather than serialized JSON syntax. Individual replacement and Replace All must persist the expected cell content without corrupting notebook structure, metadata, or outputs. Output-only matches remain read-only.
- **Trace:**

  > search.experimental.closedNotebookRichContentResults is disabled by default in src/vs/workbench/contrib/search/browser/search.contribution.ts and gates closed-notebook rich search in notebookSearchService.ts. MatchInNotebook.isReadonly and CellMatch.hasCellViewModel in notebookSearchModel.ts distinguish editable live-cell matches from search-only cell models and output matches. ReplaceService.createEdits in replaceService.ts uses cell resource URIs for notebook edits, and replace subsequently resolves and saves their owning notebooks. The author's comment identifies full notebook content and NotebookTextModel resolution as the missing lifecycle; this review has not established how closed results retain sufficient identity and content across resolution, editing, and saving. https://github.com/microsoft/vscode/pull/194932 explicitly leaves the full implementation here, and https://github.com/microsoft/vscode/issues/250056 supplies a concrete quoted-string search case consolidated into this issue. Preserve existing open-notebook replacement and output read-only behavior; do not substitute raw JSON replacement for notebook-aware edits.

- **Current replacement boundary:** In src/vs/workbench/contrib/search/browser/notebookSearch/notebookSearchModel.ts, MatchInNotebook.isReadonly includes the absence of a cell view model and webview matches; CellMatch.hasCellViewModel distinguishes CellSearchModel from live cell models.
