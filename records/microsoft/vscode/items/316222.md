# Issue #316222 — Run in terminal sync mode returns stale `^C` in Remote-SSH Windows/PowerShell

[https://github.com/microsoft/vscode/issues/316222](https://github.com/microsoft/vscode/issues/316222)

## Summary

Still reproduces on main: the pre-command Ctrl+C generates a complete shell integration command lifecycle that wins the onCommandFinished race in RichExecuteStrategy before the real command is sent, returning stale output. No fix has landed.

## Change summary

run_in_terminal sync mode returns stale ^C output instead of actual command output on Remote-SSH Windows/PowerShell because the cleanup Ctrl+C triggers an onCommandFinished event before the real command runs.

## Best solution

Fix the race in the Ctrl+C cleanup path: either defer `setNextCommandId` until after the Ctrl+C + timeout (so the empty command doesn't consume the command ID), or add a filter in RichExecuteStrategy that ignores command-finished events that fire before `runCommand` actually sends the command line. The fix belongs in `terminalInstance.ts` (reorder setNextCommandId after the ETX block) and/or `commandDetectionCapability.ts` (_ensureCurrentCommandId should validate the command line before consuming _nextCommandId).
