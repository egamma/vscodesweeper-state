# Issue #331469 — Agents Window: Fully support grid and split interactions in the single-pane layout

[https://github.com/microsoft/vscode/issues/331469](https://github.com/microsoft/vscode/issues/331469)

## Summary

Keep open: this is a team-authored parent issue in the Backlog, and current main deliberately disables the requested editor-grid behavior rather than implementing it. The related landed work explicitly identifies this issue as the follow-up for full support.

## Change summary

Add complete, discoverable editor-grid and split behavior to the Agents Window single-pane layout, including details synchronization, file targeting, restoration, keyboard use, and accessibility.

## Best solution

Define the multi-group single-pane contract, then support splitting, joining, moving, resizing, focus-driven Files/Changes details, and session-aware restoration without changing the classic layout or the independent chat grid. Remove the current split guards only when command, drag-and-drop, programmatic, persistence, and accessibility paths are covered together.

## Plan brief

- **Likely files:** `src/vs/sessions/LAYOUT.md`, `src/vs/sessions/SINGLE_PANE_SCENARIOS.md`, `src/vs/sessions/browser/parts/singlePaneEditorPart.ts`, `src/vs/sessions/browser/parts/editorParts.ts`, `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneDockedTabsCoordinator.ts`, `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneDetailPanelCoordinator.ts`, `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneExistingSessionStrategy.ts`, `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneDraftSessionStrategy.ts`, `src/vs/sessions/test/browser/workbench.test.ts`, `src/vs/sessions/contrib/layout/test/browser/singlePaneStrategies.test.ts`
- **Validation:** Replace the current single-group rejection tests with focused coverage for group creation, movement, joining, active-group detail mapping, Files-originated opens, and session/reload restoration, then run `scripts/test.sh --grep 'Sessions - Workbench|SinglePane layout strategies'`; also validate keyboard-only split navigation and focus announcements in an Agents Window UI scenario.
- **Behavior:**

  > The single-pane Agents Window must support splitting, joining, moving, and resizing editor groups through clear pointer and keyboard affordances. Focusing a group must select the Files or Changes details associated with that group, and opening from Files must target the intended file editor group without replacing unrelated content. Group geometry, active selection, details state, and focus must remain synchronized through session switches and reloads. Unsupported drop targets must remain hidden, while supported interactions match normal editor-grid keyboard and accessibility behavior.
- **Trace:**

  > Current main intentionally enforces one group in SinglePaneMainEditorPart: addGroup returns the existing group, multi-group applyLayout is ignored, restored groups are merged, and split drop targets are disabled. EditorParts separately blocks moves and copies involving that part. The docked-tab and detail coordinators operate around mainPart.activeGroup and one global DetailPanelTarget, while the session strategies derive Files/Changes details from the globally active editor; that is where group-specific ownership becomes unresolved. Existing tests in src/vs/sessions/test/browser/workbench.test.ts enforce rejection and restored-group collapse, while src/vs/sessions/contrib/layout/test/browser/singlePaneStrategies.test.ts covers details selection and group switching. https://github.com/microsoft/vscode/pull/331939 introduced the temporary restriction and identifies this issue as the full-support follow-up. Preserve behavior outside the single-pane Agents Window, keep the independent chat grid unchanged, and continue opening editors through IEditorService.
- **Open decisions:**
  - Does each editor group retain its own Files/Changes details target, or does one shared details panel always follow the currently active group?
  - When a file is opened from Files with multiple groups present, what user-visible state designates the target Files editor group: current focus, the group associated with the Files detail, or a persistent preferred group?
  - Is editor-grid geometry and group-to-details association restored per session, or is one grid layout shared across session switches while only editor working sets change?
