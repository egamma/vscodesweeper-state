# Issue #167874 — Allow static contribution of status bar items

[https://github.com/microsoft/vscode/issues/167874](https://github.com/microsoft/vscode/issues/167874)

## Summary

Static status bar contributions are implemented behind the contribStatusBarItems proposed-API gate, not finalized for general extension use. Keep this api-proposal tracking issue open for the API owners; the merged implementation does not complete its lifecycle.

## Change summary

Let extensions declare status bar items before activation, with command-triggered activation and potentially context-dependent visibility.

## Best solution

Have the API owners evaluate and finalize contributes.statusBarItems, including whether declarative when clauses are supported and how they interact with runtime show()/hide(). Preserve the ability for an activated extension to take over its statically contributed item.

- **Fit:** aligned
- **Reason:** Declarative contributions let extensions expose useful commands without startup activation, supporting performance and the extension ecosystem.

Its handler explicitly rejects extensions without isProposedApiEnabled(entry.description, 'contribStatusBarItems'), so the capability remains proposed rather than generally available.
- **Proposal still references this issue:** src/vscode-dts/vscode.proposed.contribStatusBarItems.d.ts remains a proposed contribution placeholder and explicitly links https://github.com/microsoft/vscode/issues/167874.

Its body explicitly identifies this issue, but the current proposed-API gate demonstrates that implementation alone is not finalization.
- **Visibility contract remains unsettled:** The current statusBarItemSchema includes id, name, text, tooltip, command, alignment, priority, and accessibilityInformation, but no when property. The September 2023 discussion requests when support and explicitly raises its interaction with show()/hide().
