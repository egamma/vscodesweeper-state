# Issue #326572 — VS Code Speech cannot stop playback for long GitHub Copilot Chat responses

[https://github.com/microsoft/vscode/issues/326572](https://github.com/microsoft/vscode/issues/326572)

## Summary

Traced a real gap in the text-to-speech cancellation path: stopping read-aloud only cancels the internal token and resets state in core, but the `ITextToSpeechSession` contract has no method to tell the underlying speech provider to abort audio that's already been handed off for synthesis, so long in-flight utterances keep playing and a restart can overlap them.

## Change summary

Stopping VS Code Speech read-aloud (via the stop icon or Esc) doesn't actually halt playback of a long Copilot Chat response; restarting causes overlapping audio.

## Best solution

Extend `ITextToSpeechSession` (src/vs/workbench/contrib/speech/common/speechService.ts) with an explicit cancel/stop capability that `ChatSynthesizerSessions.stop()` in voiceChatActions.ts invokes, so providers (e.g. the VS Code Speech extension) get a clear signal to abort in-progress audio rather than just having the token race abandoned.

## Evidence

- **cancellation only cancels the token:** src/vs/workbench/contrib/chat/electron-browser/actions/voiceChatActions.ts ChatSynthesizerSessions.start()/stop(): `activeSession.dispose(true)` cancels a CancellationTokenSource and disposes local disposables (resetting the `ScopedChatSynthesisInProgress` context key), but never calls anything on the `ITextToSpeechSession` itself.
- **no session-level stop API:** src/vs/workbench/contrib/speech/common/speechService.ts: `ITextToSpeechSession` only exposes `onDidChange` and `synthesize(text): Promise<void>` — there is no `stop()`/`dispose()` the core can call to interrupt audio already queued or playing inside the provider.
- **raceCancellation doesn't cancel downstream work:** `await raceCancellation(session.synthesize(chunk), activeSession.token)` in voiceChatActions.ts just stops *awaiting* the promise on cancellation; it does not signal the provider (implemented by the separate VS Code Speech extension) to abort the audio it may already be playing, matching the reporter's symptom of playback continuing after Stop/Esc and overlapping on restart.
- **no prior fix:** `git log` on src/vs/workbench/contrib/speech/common/speechService.ts shows no recent change touching this cancellation path.
