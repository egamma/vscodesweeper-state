# Issue #375 — [html] intellisense should be more context aware

[https://github.com/microsoft/vscode/issues/375](https://github.com/microsoft/vscode/issues/375)

## Summary

A meaningful gap remains on current main: attribute suggestions are tag-aware, but child-tag suggestions ignore the parent and ARIA suggestions are not filtered by role. This issue is already the canonical report and remains correctly classified in the Backlog.

## Change summary

Make HTML IntelliSense filter elements and attributes according to the surrounding element, parent element, and relevant attribute values such as ARIA roles.

## Best solution

Extend the vscode-html-languageservice data model and completion pipeline to represent parent-child content constraints and conditional attributes, then consume the updated language-service package from VS Code's built-in HTML extension.

## Evidence

- **current integration:** extensions/html-language-features/server/src/modes/htmlMode.ts delegates completion to vscode-html-languageservice through `doComplete2`; extensions/html-language-features/server/package-lock.json currently resolves vscode-html-languageservice 6.0.0-next.2.
- **remaining parent-context gap:** Current vscode-html-languageservice `src/services/htmlCompletion.ts` implements `collectOpenTagSuggestions` by iterating every tag returned by each provider without consulting the current node's parent, so contexts such as children of `<ul>` remain unfiltered.
- **partial existing coverage:** The same completion source calls `provideAttributes(currentTag)`, and `src/languageFacts/dataProvider.ts` returns tag-specific plus global attributes. This covers basic tag-aware attributes, but `HTMLDataV1` and `IHTMLDataProvider` expose no parent constraint or role-dependent applicability contract.
- **ARIA behavior:** The upstream completion tests explicitly expect the full ARIA attribute set for both `<div>` and `<span>`, confirming that suggestions are not conditioned on an element's `role` value.
- **canonical history:** https://github.com/microsoft/vscode/issues/19114 reports the same parent-sensitive tag-completion request and was closed by a maintainer as a duplicate of https://github.com/microsoft/vscode/issues/375. It is younger and closed, so it cannot replace this re-reviewed issue as canonical.
