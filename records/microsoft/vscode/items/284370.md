# Issue #284370 — Mouse is registered somewhere else than where it is

[https://github.com/microsoft/vscode/issues/284370](https://github.com/microsoft/vscode/issues/284370)

## Summary

Keep open as a corroborated Linux display-scaling defect: pointer hit-testing diverges from the visible window, and commenters report persistence across multiple releases. Related scaling issues exist, but neither a fixing commit nor a canonical covering this regression is established.

## Change summary

Mouse clicks register at positions different from the visible pointer in Linux VS Code windows, making controls unreliable or inaccessible.

## Best solution

Restore agreement between rendered window geometry and pointer hit-testing at affected display scales, including external monitors. Diagnose the native-window/display-protocol boundary before deciding whether the correction belongs in VS Code or Electron/Chromium.
