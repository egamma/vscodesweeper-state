# Issue #135105 — Different breakpoint marker for unverified breakpoint before debug session start

[https://github.com/microsoft/vscode/issues/135105](https://github.com/microsoft/vscode/issues/135105)

## Summary

The requested pre-session breakpoint state is still absent on current main, and no canonical issue owns the same work. This remains a valid but low-demand UX decision already parked in the Backlog under discussion, so it should stay open.

## Change summary

Distinguish breakpoints that have not yet been validated by a debug session, potentially with a dedicated marker and explanatory hover.

## Best solution

The debug UX owners should decide whether a subtle unknown or verified-state affordance improves comprehension without implying an error, then apply that decision consistently to source, conditional, function, data, and log breakpoints. Dynamic validation after session start and existing disabled/unverified meanings should remain distinct.
