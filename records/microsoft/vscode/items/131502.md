# Issue #131502 — Source code downloaded via the debuggers sourceRequest creates lots of duplicate open files across debug sessions

[https://github.com/microsoft/vscode/issues/131502](https://github.com/microsoft/vscode/issues/131502)

## Summary

Downloaded debug sources still receive session-specific editor identities, so repeated sessions can accumulate identical tabs. The optional auto-close setting mitigates tab accumulation but does not deliver the cross-session reuse and history handling accepted in the discussion.

## Change summary

Prevent downloaded debug sources from accumulating duplicate editors across successive debug sessions while preserving correct source contents and breakpoint identity.

## Best solution

Define safe cross-session identity and lifecycle semantics for downloaded sources in the debug contribution, including history cleanup. Preserve session-local sourceReference resolution and avoid conflating generated or SDK-version-dependent sources merely because their displayed paths match.

- **Behavior:**

  > Repeatedly debugging into the same downloaded source should not leave a growing collection of indistinguishable stale editors. The finished behavior must specify whether stable sources reuse an editor or expired sources are retired, and how quick-open history is handled. Generated sources and sources from different SDK versions must not be incorrectly merged because they share a displayed name or path. Existing auto-close preferences, concurrent debug sessions, and breakpoint correctness must remain respected.
- **Trace:**

  > Source.getUriFromSource in src/vs/workbench/contrib/debug/common/debugSource.ts includes both session ID and sourceReference in debug URIs, and Source.openInEditor uses that URI as the editor resource. DebugSession.getSource caches only within the session; DebugContentProvider resolves the resource through its encoded session and session.loadSource. DebugService's adapter-end handler optionally closes session debug tabs under debug.closeReadonlyTabsOnEnd, but does not establish cross-session identity or clean history there. The Debug - Source suite currently asserts the session-bearing URI format. The discussion at https://github.com/microsoft/vscode/issues/131502 supports improvement but does not settle stable-source equivalence; preserve DAP session-local reference semantics and do not merge sources solely by display name. https://github.com/microsoft/vscode/issues/85290 is related disk-versus-downloaded-source work, not a duplicate of this lifecycle defect.
- **Open decisions:**
  - What adapter-provided identity or stability guarantee permits cross-session editor and breakpoint reuse when sourceReference values change or displayed paths identify different source versions?
  - For sources without a cross-session stability guarantee, should ended-session editors remain readable snapshots, be closed automatically, or be replaced on a later launch, and should their quick-open history entries be removed regardless of the auto-close preference?

## Evidence

- **Current source reproduces the identity mismatch:** src/vs/workbench/contrib/debug/common/debugSource.ts:getUriFromSource constructs positive-sourceReference resources with query `session=${sessionId}&ref=${raw.sourceReference}`. Source.openInEditor opens that resource with revealIfOpened, so different session IDs produce distinct editor resources even for identical paths, references, and contents.
- **Deduplication remains session-local:** src/vs/workbench/contrib/debug/browser/debugSession.ts:getSource constructs Source with this.getId() and caches it in the session's sources map; shutdown clears that map. src/vs/workbench/contrib/debug/common/debugContentProvider.ts resolves content through the encoded session and session.loadSource, so removing session identity without a replacement resolution contract would be unsafe.
- **Existing mitigation is partial:** src/vs/workbench/contrib/debug/browser/debug.contribution.ts:519-523 registers debug.closeReadonlyTabsOnEnd with default false. debugService.ts:775-780 closes matching session debug editors only when enabled; this block neither reuses editor identities nor removes history entries. https://github.com/microsoft/vscode/pull/199898 is merged, but the subsequent discussion explicitly identifies remaining work.
