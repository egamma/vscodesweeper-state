# Issue #324961 — BYOK PDF support requires a hardcoded model family

[https://github.com/microsoft/vscode/issues/324961](https://github.com/microsoft/vscode/issues/324961)

## Summary

Valid feature request: BYOK endpoints currently cannot advertise PDF support independently of the hardcoded model-family allowlist. The prior PR (#323836) that attempted this was closed without merging; the capability gap remains on current main.

## Change summary

Allow custom BYOK language model endpoints to explicitly advertise accepted file MIME types (e.g. `application/pdf`) instead of relying solely on a hardcoded model-family allowlist.

## Best solution

Add a `fileInputMimeTypes` capability to the language-model endpoint metadata (proposed API surface and Custom Endpoint configuration), with three-state semantics: `undefined` falls back to the existing family check, `[]` means explicitly unsupported, and `['application/pdf']` means supported. Update `modelSupportsPDFDocuments` in `extensions/copilot/src/platform/endpoint/common/chatModelCapabilities.ts` and the prompt-side gate in `fileVariable.tsx` to honor the explicit capability before falling through to the family heuristic. The reporter has outlined a concrete follow-up plan and is awaiting maintainer feedback on the shape.
