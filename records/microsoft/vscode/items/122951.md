## Summary

Keep open as an Electron/Chromium sandbox compatibility issue. Maintainers explicitly identify the upstream cause, and neither the sandbox-disabling workaround nor the new opt-in de-elevation API establishes that elevated operation under AppLocker is fixed.

## Change summary

Allow sandboxed webviews and child processes to start when VS Code runs elevated on Windows under AppLocker.

## Best solution

Resolve the elevated-process sandbox failure in Electron/Chromium and verify adoption on VS Code's affected startup and webview paths. Preserve sandbox protection by default; restarting without elevation does not satisfy workflows that explicitly require administrator privileges.
