# Issue #334077 — Claude now not loading models

[https://github.com/microsoft/vscode/issues/334077](https://github.com/microsoft/vscode/issues/334077)

## Summary

Same underlying defect as the open, maintainer-assigned https://github.com/microsoft/vscode/issues/334405: after a pinned Claude agent-sdk version bump, no code path ever downloads the new SDK, so the model picker stays permanently empty ('SDK not downloaded yet' looping forever) with no in-product recovery except manually extracting the tarball into the sdk-cache and creating a `.complete` sentinel — exactly what this issue's commenters worked out independently.

## Change summary

After updating VS Code, the Claude agent's model picker shows no models and imported sessions fail with 'Provider claude could not describe claude:/', with logs repeating 'SDK not downloaded yet'.

## Best solution

Consolidate onto https://github.com/microsoft/vscode/issues/334405, which traces the exact deadlock (the only two triggers for `loadSdkRoot` — a running session and the setup notification button — are both unreachable when the cached SDK doesn't match the newly pinned version) and is already assigned to a maintainer (TylerLeonhardt). Current `main`'s `getAgentSdkSetupState` (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSdkSetupNotification.ts) now offers the download banner unconditionally whenever `download === 'notDownloaded'`, ahead of the sign-in gate, which looks like exactly this fix landing — but this checkout is shallow (single commit) so no specific fix commit can be cited for a completed close; that verification belongs with the assignee on the canonical issue.
