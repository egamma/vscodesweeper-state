# Issue #334077 — Claude now not loading models

[https://github.com/microsoft/vscode/issues/334077](https://github.com/microsoft/vscode/issues/334077)

## Summary

Real, reproducible regression in the Claude agent SDK download/cache flow: after updating, models fail to load with 'Provider claude could not describe claude:/…' and the SDK stays undownloaded. Two independent commenters confirm the same symptom and the same workaround (manually placing the SDK tarball plus a `.complete` sentinel file), so this is not a one-off report — keeping it open for the agent-host/Claude owners to trace the actual download-trigger failure.

## Change summary

After a recent VS Code update, the Claude agent in the Agents window shows no models and fails to open imported sessions because its SDK is never auto-downloaded/cached.

## Best solution

Have the Agent Host/Claude owners trace why `AgentSdkDownloader`'s download-trigger path (src/vs/platform/agentHost/node/agentSdkDownloader.ts) isn't firing or completing for these users — comment 2 shows a download that extracted files but never wrote the `.complete` sentinel, which per the code's own comment (lines 384-394) means the cache-hit check will always miss and treat it as never downloaded. This needs a concrete repro/log trace from a maintainer, not a blind source read, before a fix lands.
