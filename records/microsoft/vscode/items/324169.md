# Issue #324169 — Support installing extensions from git URLs

[https://github.com/microsoft/vscode/issues/324169](https://github.com/microsoft/vscode/issues/324169)

## Summary

A real capability gap remains: current main installs extensions from gallery identifiers, VSIX resources, or local workspace-extension directories, but not directly from pinned Git repositories. The request needs product and security design before implementation and has no verified canonical issue or existing capability that fully covers it.

## Change summary

Allow the CLI and workspace extension configuration to install extensions from Git URLs, including branches, tags, commits, subdirectories, and private repositories.

## Best solution

Define a secure source-installation model before implementation, including whether repositories must contain a ready-to-run extension or may execute build steps, how commit pinning and updates work, and how authentication, trust, integrity, and signatures are handled. Preserve Marketplace/VSIX behavior and treat local workspace extensions as a partial workaround rather than equivalent coverage.

## Evidence

- **current CLI boundary:** On current main, src/vs/platform/extensionManagement/common/extensionManagementCLI.ts classifies URI inputs as VSIX installations and string inputs as Marketplace extension IDs; installExtensions has no Git clone, ref, subdirectory, or source-build path.
- **workspace configuration boundary:** src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts restricts .vscode/extensions.json recommendations to ${publisher}.${name} identifiers through EXTENSION_IDENTIFIER_PATTERN, so Git URLs are not accepted.
- **partial existing capability:** src/vs/workbench/contrib/extensions/browser/workspaceRecommendations.ts discovers unpacked local extensions under .vscode/extensions, but this requires committing or otherwise placing extension contents in the workspace and does not provide Git URL fetching, commit pinning, private-repository authentication, or source updates.
- **canonical search:** The older open https://github.com/microsoft/vscode/issues/347 concerns workspace-specific extension sets, while https://github.com/microsoft/vscode/issues/40239 concerns enabling and disabling extensions from configuration; neither owns the same observable request to install extension artifacts directly from Git URLs.
