# Issue #270731 — Editor can process e.g. `deleteLeft` out of order when command is sent from an extension keybinding function

[https://github.com/microsoft/vscode/issues/270731](https://github.com/microsoft/vscode/issues/270731)

## Summary

Keep open: current source still allows ordinary typing to overtake an extension-bound Backspace command during its extension-host round trip. The report supplies a minimal reproduction independent of Keyman, and no verified canonical or landed fix was found.

## Change summary

Preserve input ordering when an extension's Backspace handler delegates to deleteLeft and subsequent text input arrives before that command returns.

## Best solution

Preserve the reported Backspace-before-text ordering across extension command dispatch and editor input without blocking unrelated commands or freezing typing behind arbitrary extension work. This needs an editor/extension-host design pass and a deterministic ordering regression check.

- **Behavior:**

  > A Backspace keybinding whose extension handler returns commands.executeCommand('deleteLeft') can delete text from a later keystroke instead of the preceding character. For the report's ten a/Backspace/= sequences, the final text must consistently be ========== rather than a=a=a=a=a=. The same ordering should preserve Keyman's replacement-character sequence. Ordinary typing and direct built-in Backspace behavior must remain responsive and unchanged.
- **Trace:**

  > AbstractKeybindingService dispatches the contributed command without waiting for its promise. MainThreadCommands.$registerCommand sends execution to the extension host, and ExtHostCommands._doExecuteCommand sends deleteLeft back to the renderer. Meanwhile, CodeEditorWidget's normal input delegate independently executes Handler.Type, allowing later text to arrive before deletion. This path remains present in the inspected checkout; the Windows sample itself was not run. The boundary spans shared command dispatch and editor input, so a blanket queue for every command is not an established solution. The minimal sample and reproduction are linked from https://github.com/microsoft/vscode/issues/270731; the Markdown workaround is documented at https://github.com/yzhang-gh/vscode-markdown/issues/1539#issuecomment-3455838684.
- **Open decisions:**
  - What ordering guarantee should extension-bound editing keybindings provide relative to later native text input, and what should users observe if the extension handler is slow or never completes?
