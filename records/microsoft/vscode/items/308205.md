# Issue #308205 — [Mac] Unable to input a backslash in the terminal using the fish shell with a Japanese keyboard

Keep open: the supplied Japanese-keyboard and IME steps suffice to retest, but the fish-specific character substitution remains unverified. Current terminal code and its xterm dependency have evolved since 1.114.0; neither the inspected source nor related reports establish that this exact behavior is fixed.

## Change summary

On macOS with a Japanese keyboard configured to emit backslash, pressing the yen key in the integrated terminal running fish inserts U+00A5 instead of U+005C.

## Best solution

Preserve the configured backslash character when typing into fish, without changing legitimate yen input or other keyboard layouts. First isolate whether the substitution occurs in browser input, xterm keyboard-protocol encoding, or fish decoding; the kitty-protocol path is a concrete investigation lead, not a confirmed cause.
