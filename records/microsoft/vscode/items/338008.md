# Issue #338008 — Workbench.colorCustomizations setting not working

[https://github.com/microsoft/vscode/issues/338008](https://github.com/microsoft/vscode/issues/338008)

## Summary

Verified duplicate: the older, still-open https://github.com/microsoft/vscode/issues/326445 tracks the exact same root cause -- Modern UI's hardcoded `!important` CSS overrides discarding `workbench.colorCustomizations` (e.g. tab/activity-bar colors) -- and a maintainer is already engaged there.

## Change summary

After updating to 1.139, `workbench.colorCustomizations` entries for tab borders (and other UI parts) stop applying because the Modern UI tab/workbench styling overrides them.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/326445, which already has the maintainer-identified root cause (Modern UI CSS using `!important` to force transparent/overridden colors) and a proposed direction (let themes/customizations opt out of Modern UI's enforced colors).

  > Thanks for the detailed report (and the screenshots). This looks like the same underlying issue as https://github.com/microsoft/vscode/issues/326445: when Modern UI is active, its CSS hardcodes several colors (including tab borders) with `!important`, which silently overrides `workbench.colorCustomizations` for those properties. A maintainer is already discussing a fix there (letting customizations opt out of the Modern UI color enforcement). In the meantime, `"workbench.experimental.modernUI": false` should restore your custom tab colors without reverting VS Code. Consolidating the discussion on the older issue.
