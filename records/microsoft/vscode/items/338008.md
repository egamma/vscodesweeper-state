# Issue #338008 — Workbench.colorCustomizations setting not working

[https://github.com/microsoft/vscode/issues/338008](https://github.com/microsoft/vscode/issues/338008)

## Summary

Confirmed on main: Modern UI (now default in 1.139 via the `experiment: { mode: 'auto' }` setting) forcibly suppresses the legacy tab border colors the reporter customized, and a commenter shows modernEditorTab.* colors also only apply in pill style, not the default connected style — both contradict the feature's own documented override contract, but the fix requires a maintainer call on intended behavior, so this stays open per the prior review's stronger duplicate bar.

## Change summary

workbench.colorCustomizations entries for tab.activeBorder / tab.activeBorderTop (and reportedly modernEditorTab.* in connected mode) stopped rendering after upgrading to 1.139, where Modern UI's tab redesign became the default.

## Best solution

Have a maintainer decide whether tab.activeBorder/tab.activeBorderTop should still render an indicator in Modern UI's connected tab style when explicitly customized (currently force-overridden to transparent/hidden), and whether modernEditorTab.* should apply identically in connected and pill styles as the README promises; then adjust src/vs/workbench/contrib/modernUI/browser/media/tabs.css accordingly.

## Evidence

- **forced transparent top border:** src/vs/workbench/contrib/modernUI/browser/media/tabs.css:78 sets `--tab-border-top-color: transparent !important;` on every `.modern-ui-tabs .tab`; because it's a stylesheet !important rule, it wins over the inline `tabContainer.style.setProperty('--tab-border-top-color', ...)` written by multiEditorTabsControl.ts's doRedrawTabActive for TAB_ACTIVE_BORDER_TOP, nullifying `tab.activeBorderTop` for a plain single active tab (only narrower `.tab.selected:not(.active)`/`.tab.active.multi-selected` selectors at lines 343/347 re-enable it with their own !important).
- **bottom border container hidden:** src/vs/workbench/contrib/modernUI/browser/media/tabs.css:279 sets `.tab-border-bottom-container { display: none !important; }` unconditionally for non-HC themes, which is the element `TAB_ACTIVE_BORDER` (`tab.activeBorder`) paints into — so that customization has no visible effect in Modern UI's default connected style, only re-enabled for hc-black/hc-light at lines 852/856.
- **Modern UI now default:** src/vs/workbench/browser/workbench.contribution.ts:834 registers `workbench.experimental.modernUI` with `'default': true` and `experiment: { mode: 'auto' }`, consistent with the reporter seeing this only after updating from 1.138 to 1.139.
- **second reporter, different facet:** Comment from nannerpusser: modernEditorTab.* colors (documented in src/vs/workbench/contrib/modernUI/README.md as applying to 'connected and pill tabs alike') reportedly only take effect in pill style, not the default connected style — a second concrete instance of the same override-precedence problem.
