# Issue #312808 — hovering while selecting type in agents app doesn't show extra info

[https://github.com/microsoft/vscode/issues/312808](https://github.com/microsoft/vscode/issues/312808)

## Summary

Keep open: this team-authored Backlog request has explicit maintainer support, and current main still provides no explanatory information for available harnesses in the session-type picker. The related onboarding issue is newer and broader, so it does not meet the stronger duplicate bar for this re-reviewed item.

## Change summary

Show concise explanatory information when users hover or keyboard-focus Copilot and Claude choices in the Agents Window session-type picker.

## Best solution

Give each available harness a concise, localized explanation in the picker, available to pointer, keyboard, and screen-reader users, while preserving the existing selection and availability behavior. Reuse consistent wording from the equivalent VS Code tooltips where applicable.

- **Likely files:** `src/vs/sessions/services/sessions/common/session.ts`, `src/vs/sessions/contrib/chat/browser/sessionTypePicker.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`, `src/vs/sessions/contrib/chat/test/browser/sessionTypePicker.test.ts`

- **Behavior:**

  > When the Agents Window session-type picker is open, hovering or keyboard-focusing Copilot and Claude presents a concise explanation of what each harness is. Screen-reader users receive equivalent information, and unavailable-state explanations remain understandable. Session labels, ordering, selection, authentication, and creation behavior remain unchanged.
- **Trace:**

  > `ISessionType` in `src/vs/sessions/services/sessions/common/session.ts` has no description contract. `SessionTypePicker._showPicker` in `src/vs/sessions/contrib/chat/browser/sessionTypePicker.ts` supplies hover content only for unavailable rows, so available harnesses render as unexplained labels. Agent Host already receives `AgentInfo.description`, but `_syncSessionTypesFromRootState` in `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts` drops it while creating provider-neutral session types; static Copilot types are declared in the Agent Host and Copilot Chat provider files. Keep the behavior provider-neutral and do not change session selection, availability, authentication, or provider routing. The broader https://github.com/microsoft/vscode/issues/313101 may inform wording and onboarding consistency but does not replace this specific picker requirement.
- **Open decisions:**
  - What user-visible facts must every harness explanation cover—execution location, provider identity, credential/subscription behavior, or a consistent subset of these—and what approved wording should Copilot and Claude use?
