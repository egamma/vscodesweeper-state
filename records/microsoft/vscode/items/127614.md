# Issue #127614 — Trusted uris: added uri should be focused

[https://github.com/microsoft/vscode/issues/127614](https://github.com/microsoft/vscode/issues/127614)

## Summary

The focus gap remains on current main: adding a trusted folder refreshes the sorted table without focusing or selecting the newly added URI. The issue already has the correct workspace-trust routing and should remain open.

## Change summary

After adding a trusted folder, focus the corresponding row at its sorted position instead of another row.

## Best solution

Preserve the URI chosen by Add Folder through the trust-list refresh, then focus and select its row after sorting without changing edit or delete focus behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/workspace/browser/workspaceTrustEditor.ts`
- **Validation:** Launch the Workspace Trust editor with enough trusted folders to require sorting, add a folder whose sorted position is near the top or middle, and verify keyboard focus and selection land on that exact row; repeat deletion and editing checks to ensure their existing focus behavior is unchanged.
- **Behavior:**

  > When Add Folder succeeds, the trusted-folders table refreshes and keyboard focus and selection move to the row representing the URI just added, wherever sorting places it. The row must be revealed when outside the visible portion of a long list. Canceling the picker must not move focus, and existing edit and delete focus behavior must remain unchanged.
- **Trace:**

  > WorkspaceTrustedUrisTable in src/vs/workbench/contrib/workspace/browser/workspaceTrustEditor.ts receives the chosen URI in the Add Folder button handler, but only forwards it to IWorkspaceTrustManagementService.setUrisTrust. The void onDidChangeTrustedFolders event later invokes updateTable(), which reconstructs and sorts the entries and splices the whole table without identifying the newly added item. selectTrustedUriEntry already centralizes row focus and selection for editing, but the add-refresh path has no corresponding item context. Commit d95f2e01ab8dd30aabff8f291124bd2606b50c2e and https://github.com/microsoft/vscode/issues/127622 cover deletion focus only; preserve that behavior and avoid changing generic list focus semantics.

## Evidence

- **current source:** In src/vs/workbench/contrib/workspace/browser/workspaceTrustEditor.ts, the Add Folder handler passes the selected URI to setUrisTrust and discards it; onDidChangeTrustedFolders subsequently calls updateTable(), which replaces the sorted table contents but never calls selectTrustedUriEntry for the added URI.
- **related focus fix:** Commit d95f2e01ab8dd30aabff8f291124bd2606b50c2e fixed the distinct removal-focus report https://github.com/microsoft/vscode/issues/127622 by adding identity and delete-neighbor handling. Its diff does not focus a newly added row.
- **canonical search:** The older https://github.com/microsoft/vscode/issues/109277 concerns extension hooks for opening URLs, not trusted-folder table focus. No open older issue was found with the same reporter-observable symptom.
