# Issue #296656 — Export chat as HTML

[https://github.com/microsoft/vscode/issues/296656](https://github.com/microsoft/vscode/issues/296656)

## Summary

Current main supports JSON export and portable Markdown copying, but not HTML export. This distinct, team-authored feature request should stay open and route to the chat area for an output-scope decision.

## Change summary

Add a first-party way to export the focused chat session as readable HTML for sharing, editing, and demos.

## Best solution

Provide a safe, self-contained HTML transcript that opens outside VS Code, preserves the useful chat structure, and does not expose machine-local links or executable content. The chat owners should first choose how much metadata and assistant activity belongs in the exported artifact.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatClipboard.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatClipboard.test.ts`
- **Validation:** Add focused tests that export a representative multi-turn session and verify the resulting self-contained HTML preserves turn order and code blocks, opens without VS Code resources, and excludes machine-local/internal link targets; also verify save cancellation produces no file.
- **Behavior:**

  > Users can export the currently focused chat as a single HTML document suitable for sharing, light editing, and demos. The document remains readable when opened independently of VS Code and preserves the selected user-visible transcript content and code formatting. It must not expose machine-local paths through links or contain active VS Code command links. Existing JSON export/import and Copy All behavior remain unchanged.
- **Trace:**

  > The current file export is `workbench.action.chat.export` in src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts; it writes `model.toExport()` as JSON. The current human-readable transcript path is `CopyAllAction` in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts, which maps request/response view models through `stringifyItem` and then `toPortableMarkdown`. The latter lives in src/vs/workbench/contrib/chat/browser/widget/chatClipboard.ts and already defines the portability boundary by scrubbing local and internal targets. The reporter's prototype at https://github.com/benmartens/copilot-chat-export proves the workflow but exposes unresolved product choices around activity detail, metadata, summaries, and themes. Keep JSON round-trip export, chat rendering, and clipboard semantics out of scope; HTML must be a static sharing artifact rather than an import format.
- **Open decisions:**
  - Should the core HTML artifact contain only user prompts and final assistant responses, or also expose tool/thinking activity with hidden, collapsed, or expanded presentation?
  - Should the first-party command produce one fixed VS Code-styled transcript, or offer user-visible choices for theme, metadata, summaries, links, and code blocks?

## Evidence

- **current export surface:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts registers `workbench.action.chat.export`, but it serializes `model.toExport()` only as JSON with a `.json` filter.
