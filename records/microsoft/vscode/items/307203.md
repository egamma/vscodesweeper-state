  > Thanks for the detailed report.

  > **Hook auto-discovery from plugins** — this is already implemented. When a plugin is registered in `chat.pluginLocations`, its hooks are automatically discovered alongside skills, agents, and MCP servers. If you're seeing hooks ignored from a specific plugin, could you share the plugin directory structure and its `hooks.json` layout so we can investigate? (This is what connor4312 asked about above.)
  > 
  > **UNC/absolute path validation** — the path restriction on `chat.hookFilesLocations` is intentional: these settings are designed to be portable across machines via Settings Sync and remote sessions (WSL, SSH, Dev Containers). `chat.pluginLocations` is scoped to `machine` settings specifically because plugin paths are expected to be machine-specific, which is why it accepts absolute paths. Since hooks inside plugins are already auto-discovered, you shouldn't need to add UNC paths to `hookFilesLocations` separately.
  > 
  > As aeschli mentioned — for WSL workflows, using the [WSL extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-wsl) avoids UNC paths entirely. Could you clarify why that isn't an option for your setup?
