# Issue #307203 — chat.hookFilesLocations: rejects UNC/absolute paths inconsistently vs chat.pluginLocations + hooks inside agent plugins should be auto-discovered

[https://github.com/microsoft/vscode/issues/307203](https://github.com/microsoft/vscode/issues/307203)

## Summary

The hook-location restriction is intentional for portable settings, as explained by the maintainer. Plugin hook auto-discovery already exists; the thread supplies no example demonstrating a failure of that supported behavior.

## Change summary

Allow absolute and UNC paths in chat.hookFilesLocations and automatically discover hooks from registered plugins.

## Best solution

Keep the intentional portable-path contract for chat.hookFilesLocations and use existing plugin hook discovery through chat.pluginLocations. A concrete plugin that fails discovery should be investigated separately against its format-specific hook location and manifest.

- **Proposed comment:**

  > Thanks for clarifying. The restriction in `chat.hookFilesLocations` is intentional: it accepts workspace-relative or `~/` paths so the configuration remains portable across machines and remote environments. `chat.pluginLocations` has a different, machine-scoped path contract.
  > 
  > Hooks from plugins registered in `chat.pluginLocations` are already discovered without an additional `chat.hookFilesLocations` entry. The default location depends on the plugin format: `hooks.json` for Copilot format, `hooks/hooks.json` for Claude/OpenPlugin format, or `com.github.copilot/hooks/hooks.json` for AgentPlugin format; a manifest can also declare a custom hook path. If a plugin using its supported location is not discovered, please provide its manifest, hook JSON and directory layout so that specific failure can be investigated.
