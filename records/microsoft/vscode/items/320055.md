## Evidence

- **Current-source root cause:** extensions/typescript-language-features/src/tsServer/versionProvider.electron.ts, DiskTypeScriptVersionProvider.loadTypeScriptVersionsFromPath, constructs multi-root pathLabel values using path.join(root.name, relativePath). For a parent-relative SDK path, normalization cancels the workspace-name selector against the leading '..', losing information needed to resolve the original SDK.
- **Persistence and reload:** extensions/typescript-language-features/src/tsServer/versionManager.ts, getLocalPickItems, writes version.pathLabel to js/ts.tsdk.path. extensions/typescript-language-features/src/utils/relativePathResolver.ts recognizes workspace-name prefixes before resolving against the root filesystem path; the normalized label no longer retains that selector. This explains why the selected version works immediately but resolves incorrectly after reopening.
- **Prompt versus command:** In versionManager.ts, promptUseWorkspaceTsdk only updates the workspace-version preference and active version when accepted; unlike manual selection, it does not rewrite tsdk.path. This matches the reporter's distinction between accepting the startup prompt and manually choosing the workspace version.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/338270 is currently OPEN and explicitly states 'Fixes #320055'. Its diff preserves the workspace selector without normalizing parent traversal and adds configuration round-trip coverage for relative SDK paths. The PR reports baseline failures and passing fixed-source checks on macOS, but native Windows validation is not established.
