Keep open: the sample and steps are sufficient to retest the unwanted tree-focus transfer. Current source includes editable-focus restoration for clipboard commands, but that does not establish that opening the context menu preserves focus; no verified fixing commit or eligible duplicate was found.

## Change summary

Right-clicking inside a webview moves focus to the previously active tree item and disrupts input context-menu operations.

## Best solution

Preserve the originating webview's input and selection context through context-menu opening, dismissal, and clipboard actions without activating an unrelated tree item. First reproduce the supplied sequence on Windows and distinguish menu-opening focus transfer from clipboard-command restoration.
