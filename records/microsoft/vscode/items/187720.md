# Issue #187720 — Ability to overtype angle brackets (similar to normal parentheses)

[https://github.com/microsoft/vscode/issues/187720](https://github.com/microsoft/vscode/issues/187720)

## Summary

Keep open: current source still couples snippet bracket overtyping to the language's autoClosingPairs, so the requested completion-only behavior remains missing. The related issues inspected do not meet the duplicate bar for this re-reviewed report.

## Change summary

Allow typing over completion- or snippet-inserted closing angle brackets without enabling automatic angle-bracket insertion during ordinary typing.

## Best solution

Support provenance-aware overtyping of inserted generic delimiters in the editor while preserving comparison-operator typing and existing bracket behavior. Decide whether eligibility is inferred from snippets or explicitly declared through language configuration before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursor.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/common/languages/languageConfiguration.ts`, `src/vs/editor/contrib/snippet/browser/snippetSession.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Extend the cursor controller tests with a language that does not auto-close angle brackets: insert a generic-type snippet with the cursor before '>', type '>', and assert unchanged text with the cursor advanced past it. Also assert ordinary '<' does not insert '>', manually typed comparison operators remain unchanged, editor.autoClosingOvertype='never' disables skipping, and existing configured-pair tests pass.
- **Behavior:**

  > A generic-type completion or snippet inserts angle brackets with the cursor inside them. Typing the existing closing '>' should advance past it rather than create a duplicate, without enabling automatic '>' insertion when '<' is typed normally. Preserve comparison-operator input and the existing overtyping controls. Acceptance checks must distinguish snippet-inserted delimiters from manually entered text and retain existing parentheses and quote behavior.
- **Trace:**

  > Cursor._findAutoClosingPairs in src/vs/editor/common/cursor/cursor.ts already considers '>' but only tracks it when autoClosingPairsCloseSingleChar contains a unique matching pair. isAutoClosingOvertype in src/vs/editor/common/cursor/cursorTypeEditOperations.ts independently requires membership in that same map, so changing editor.autoClosingOvertype alone cannot cover the request. LanguageConfiguration currently has no separate overtyping eligibility contract, and Rust's bundled configuration places angle brackets only in surroundingPairs. SnippetSession in src/vs/editor/contrib/snippet/browser/snippetSession.ts supplies the insertion path; the cursor controller suite has an existing snippet-overtyping test to extend. Preserve normal autoclosing, comparison typing and existing configured-pair semantics. https://github.com/microsoft/vscode/issues/315131 tracks a separate, newer completion-source regression; https://github.com/microsoft/vscode/issues/38352 concerns user customization rather than this specific decoupling.
- **Open decisions:**
  - Should completion/snippet-inserted angle brackets become overtypable automatically, or should languages explicitly opt in through a separate overtyping-pair configuration contract?

## Evidence

- **clarified scope:** In the supplied discussion at https://github.com/microsoft/vscode/issues/187720, the reporter explicitly distinguishes overtyping completion/snippet-inserted angle brackets from auto-inserting angle brackets during ordinary editing. They acknowledge autoClosingPairs as an existing mechanism but explain its conflict with comparison operators.
- **current snippet eligibility:** src/vs/editor/common/cursor/cursor.ts:439–472, _findAutoClosingPairs, recognizes '>' in its closing-character pattern but requires exactly one matching entry in autoClosingPairsCloseSingleChar. executeEdits invokes this tracking path for source 'snippet'; an angle pair omitted from autoClosingPairs therefore cannot acquire the usual snippet auto-closed tracking.
- **existing setting does not cover the request:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts:1041–1084, isAutoClosingOvertype, rejects characters absent from autoClosingPairsCloseSingleChar before applying editor.autoClosingOvertype. - **language configuration boundary:** src/vs/editor/common/languages/languageConfiguration.ts exposes autoClosingPairs, surroundingPairs and colorizedBracketPairs, but no independent overtyping-pair declaration. extensions/rust/language-configuration.json includes '<'/'>' in surroundingPairs, not autoClosingPairs; surrounding support does not satisfy the overtyping checks.
