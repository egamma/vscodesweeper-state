# Issue #101172 — Add several basic predefined variables for use in launch.json - e.g.  ${uid}, ${gid}, ${user}, ${home}

[https://github.com/microsoft/vscode/issues/101172](https://github.com/microsoft/vscode/issues/101172)

## Summary

The requested values are intentionally supplied through existing environment, user-home, and command-variable mechanisms; a maintainer explicitly declined additional predefined variables.

## Change summary

Add predefined user, home, UID, GID, platform, architecture, and hostname variables for launch and settings configuration.

## Best solution

Keep the existing `${userHome}`, `${env:NAME}`, and `${command:id}` mechanisms rather than expanding the predefined-variable set; users can define portable normalized environment variables or extension commands.

## Vision fit

- **Fit:** rejected
- **Reason:** Adding redundant predefined variables creates configuration surface for values already available through extensible mechanisms.
- **Evidence:** Public values: “Out of the box, VS Code is a text editor: lightweight and fast” and “The power lives in extensions.”

- **Proposed comment:**

  > Thanks for the request and additional context. The supported approach is to use `${userHome}`, `${env:NAME}`, or an extension-provided `${command:id}` variable. Platform-specific values such as UID, GID, architecture, or hostname can be normalized into environment variables by the launching environment. Since additional predefined variables were explicitly declined in favor of these existing mechanisms, this is working as designed.

## Evidence

- **maintainer decision:** In https://github.com/microsoft/vscode/issues/101172, a contributor explains that `${env:HOME}` and `${env:USER}` already work, UID/GID can be supplied through environment or command variables, and arbitrary replacements are not planned.
- **current implementation:** Current main retains `UserHome`, `Env`, and `Command` variable kinds in src/vs/workbench/services/configurationResolver/common/configurationResolver.ts; src/vs/workbench/services/configurationResolver/common/variableResolver.ts resolves `${userHome}`, `${env:NAME}`, and command mappings.
- **broader settings request:** Variable substitution in settings remains separately tracked by the open https://github.com/microsoft/vscode/issues/2809 and does not require keeping this predefined-variable request open.
