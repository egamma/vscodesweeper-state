# Issue #234568 — Git - Git blame editor decoration color

[https://github.com/microsoft/vscode/issues/234568](https://github.com/microsoft/vscode/issues/234568)

## Summary

The core ask — a more subtle/comment-like default for the git blame editor decoration color — is still unaddressed on main; the prior implemented-on-main close citing commit 9fbff868f was already refuted, and I find no newer commit changing the default. The thread does show the real, useful partial answer (a documented theme color to customize it), which should go in a comment, but that doesn't close the default-color ask.

## Change summary

Git blame inline decorations use a default foreground color that's too prominent; the reporter wants it to default to something as subtle as the theme's comment color.

## Best solution

Users can already restyle this via the `git.blame.editorDecorationForeground` theme color (confirmed working by multiple commenters as recently as Aug 2026), but the shipped default itself (`editorInlayHint.foreground` in extensions/git/package.json) still doesn't resemble comment subtlety — a maintainer could decide whether to change the default token (e.g. toward a dimmer/disabled-style color) to better match the original ask.

  > Thanks for the report and for everyone's follow-ups. The default blame decoration color is still `editorInlayHint.foreground` on main — no change there yet — but in the meantime you can customize it directly via the `git.blame.editorDecorationForeground` theme color, e.g.
  > 
  > ```json
  > "workbench.colorCustomizations": {
  >   "git.blame.editorDecorationForeground": "#888"
  > }
  > ```
  > 
  > This also now works when set by a theme itself (just reload the window the first time). Leaving this open to track making the shipped default more comment-like/subtle rather than requiring customization.
