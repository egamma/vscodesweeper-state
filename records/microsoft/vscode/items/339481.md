# Issue #339481 — Add a dedicated link color token for hover/widget/tooltip content

[https://github.com/microsoft/vscode/issues/339481](https://github.com/microsoft/vscode/issues/339481)

## Summary

Legitimate gap confirmed on main: hover/widget content has no scoped link-color token, so links inside a custom-themed hover fall back to the global textLink.foreground and can lose contrast. Too new (0 days, no reactions, no maintainer input) to judge demand or settle the exact token design, so keeping open as a feature request.

## Change summary

Add a hover-widget-scoped link foreground color token (e.g. editorHoverWidget.linkForeground) that falls back to textLink.foreground, instead of hover links always using the global link color.

## Best solution

Register a new color token following the existing editorHoverWidget.* pattern (editorHoverBackground/editorHoverForeground in src/vs/platform/theme/common/colors/editorColors.ts) that defaults to textLinkForeground, and apply it via a CSS custom property scoped to the hover widget container in src/vs/editor/contrib/hover/browser/hover.css; the author has offered to send a PR.

## Plan brief

- **Validation:** A themed hover snapshot/manual check confirming hover links pick up the new token when set and fall back to textLink.foreground when unset.
- **Open decisions:**
  - Should the new token be hover-widget-only (editorHoverWidget.linkForeground) or cover other widgets/tooltips too, as the issue title suggests ('hover/widget/tooltip content')?
