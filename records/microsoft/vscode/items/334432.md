# Issue #334432 — Copilot Chat: switching a session to autopilot mid-conversation injects task_complete instructions into the middle of the system prompt, invalidating prefix cache for third-party (chatProvider) models

[https://github.com/microsoft/vscode/issues/334432](https://github.com/microsoft/vscode/issues/334432)

## Summary

Well-diagnosed, verifiable-on-main issue: the autopilot task_complete instruction is genuinely rendered mid-system-prompt via a conditional SystemMessage block, then collapsed with the rest of the system text — exactly as described. This is a real prefix-cache-cost concern specific to third-party chatProvider models that lack cache-control breakpoints, and belongs with the Copilot Chat/prompt team to weigh the fix against instruction-following implications.

## Change summary

Switching a chat session to autopilot mid-conversation inserts a conditional system-prompt block in the middle of the system message, breaking prefix-cache reuse for OpenAI-compatible third-party model providers.

## Best solution

Move the isAutopilot/isVoiceModeInput/templateVariablesContext conditional SystemMessage blocks in agentPrompt.tsx out of the leading system section and append them near the tail (e.g. alongside the existing `drift` mechanism in getOrFreezeCustomizationsIndex), so the system prefix stays byte-stable across turns; this is a maintainer call because it may also affect instruction-following behavior, not a purely mechanical fix.
