# Issue #335691 — Add a command to focus and expand the Chat “Files changed” list

[https://github.com/microsoft/vscode/issues/335691](https://github.com/microsoft/vscode/issues/335691)

## Summary

A real keyboard-accessibility gap remains on current main: Chat exposes navigation for response file trees, but the separate collapsible Files Changed lists cannot be expanded and focused through a targeted command. Route this to the Chat files-summary and accessibility owners for a command-design decision.

## Change summary

Expose a keyboard-assignable command that expands the relevant Chat Files Changed disclosure and focuses its first or previously focused file.

## Best solution

Provide a Chat command that targets the relevant changed-files summary from the input, opens its disclosure, and restores the last focused row or selects the first row. The owners should decide whether this extends the existing Next File Tree command or uses a dedicated public command, and how it behaves when several turns contain summaries.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatFileTreeActions.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatChangesSummaryPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatTurnPillsPart.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatChangesSummaryPart.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatTurnPillsPart.test.ts`
- **Validation:** Add browser unit coverage that invokes the selected command while focus is in Chat input, verifies the relevant closed details element opens and its first changed-file row receives focus, then verifies a later invocation restores the previously focused row; also cover the agreed behavior when multiple turn summaries exist.
- **Behavior:**

  > From the Chat input, users can invoke a public, keybinding-assignable command to reach Files Changed without using the mouse or first seeding generic list focus. The command expands the relevant collapsed summary and focuses its previously focused file, or the first file when no row was focused before. Existing file activation, keep/undo actions, and Focus Chat Input behavior remain unchanged. The agreed behavior for chats containing multiple changed-files summaries must be covered.
- **Trace:**

  > On current main, workbench.action.chat.nextFileTree in src/vs/workbench/contrib/chat/browser/actions/chatFileTreeActions.ts navigates only IChatFileTreeInfo objects returned by the widget. ChatListRenderer populates those objects only from renderTreeData(), whereas ChatCheckpointFileChangesSummaryContentPart and ChatTurnPillsContentPart render independent WorkbenchList instances through renderChangesSummaryFileList() inside HTML details disclosures. That helper returns only IDisposable, so neither ChatListRenderer nor the action layer can currently open or focus these lists directly. Existing summary rendering, row activation, diff opening, and generic response-tree navigation are the boundary and should retain their behavior. The accessibility help in chatAccessibilityHelp.ts must describe whichever public command semantics are selected.
- **Open decisions:**
  - Should the existing workbench.action.chat.nextFileTree command include Files Changed summaries, or should VS Code expose a dedicated changed-files focus command with a distinct public command ID?
  - When multiple responses or turns contain Files Changed summaries, should invocation from the Chat input always target the most recent summary or cycle among summaries on repeated invocation?
