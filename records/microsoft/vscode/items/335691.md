# Issue #335691 — Add a command to focus and expand the Chat “Files changed” list

[https://github.com/microsoft/vscode/issues/335691](https://github.com/microsoft/vscode/issues/335691)

## Summary

Genuine gap: no dedicated command exists to expand/focus the chat 'Changed N files' list (rendered per-response in ChatMultiDiffContentPart), only generic list commands that require the section to already be expanded and focused once — keeping this open as a real accessibility/keyboard-navigation feature request.

## Change summary

Add a command that expands the Chat 'Files changed' list if collapsed and moves keyboard focus into it (with a way to return to chat input).

## Best solution

Add a dedicated command (analogous to the existing workbench.action.chat.focusTodosView toggle-focus pattern) that targets the most relevant ChatMultiDiffContentPart list, expands it, and focuses it/restores prior focus — in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts and the chat actions/keybinding registration files.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts`
- **Validation:** A command that, given a chat session with a rendered file-changes list, expands it if collapsed and moves DOM/list focus into it; verified via an accessibility/action test analogous to existing focusTodosView tests.
- **Behavior:**

  > A user should be able to invoke a keybindable command that expands the Chat 'Changed N files' list (if collapsed) and moves keyboard focus to it (first item, or the previously focused item), without needing the mouse. Acceptance: after invoking the command, the list is visibly expanded and has DOM/list focus, and existing generic list navigation commands work on it immediately afterward.
- **Trace:**

  > The 'Files changed' UI lives in ChatMultiDiffContentPart (src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts), which owns a local `isCollapsed` boolean and a `WorkbenchList<IChatMultiDiffItem>` per content part instance — there is currently no registry or accessor letting an external command find 'the' current files-changed list for a chat session. A comparable existing pattern, workbench.action.chat.focusTodosView (src/vs/workbench/contrib/chat/browser/actions/chatActions.ts), toggles focus for a different chat-adjacent widget and is a reasonable template. The boundary: don't change chat response rendering or generic list command semantics — only add a new targeted focus/expand command.
- **Open decisions:**
  - Which files-changed list instance should the command target when multiple chat turns each have one (last turn's? the currently visible one)?
  - Should this be a single toggle command (mirroring focusTodosView) or a one-way focus command returning via the existing workbench.action.chat.focusInput?
  - Does expanding the list on focus persist collapse state, or reset each time?

## Evidence

- **no existing command:** grep across src/vs/workbench/contrib/chat/browser/actions for 'files changed'/'filesChanged'/'focusFilesChanged' found nothing; only generic list commands exist.
- **widget location:** The 'Changed N files' UI is ChatMultiDiffContentPart (src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMultiDiffContentPart.ts), rendered per chat-response content part with its own collapse state and WorkbenchList — there is no singleton service reference to target it externally today.
- **precedent pattern:** A similar toggle-focus command exists for a different chat widget: workbench.action.chat.focusTodosView in chatActions.ts, which could serve as an implementation template.
