# Issue #241968 — `i` should be marked as an alias of `install`

[https://github.com/microsoft/vscode/issues/241968](https://github.com/microsoft/vscode/issues/241968)

## Summary

Keep open: current terminal completions still present npm's `i` and `add` as ordinary subcommands rather than aliases of `install`. The thread supports this enhancement, and neither the related icon-classification issue nor the existing settings cover it.

## Change summary

Identify npm's `i` completion as an alias of `install` in terminal suggestions.

## Best solution

Make recognized npm subcommand aliases visibly identify their canonical command while preserving their insertion text and argument completions. Settle whether this treatment should apply generally to alternate Fig subcommand names or only to explicitly recognized aliases.

- **Behavior:**

  > When terminal suggestions offer npm's `i`, users should be able to recognize it as an alias of `install`. The canonical `install` entry remains a normal subcommand, and selecting `i` still inserts the shorthand. Package and option completions after either spelling must remain equivalent. The enhancement must not introduce npm's unwanted misspelling aliases.
- **Trace:**

  > The npm spec in extensions/terminal-suggest/src/completions/npm.ts groups install, i, and add in one name array. convertSubcommand and makeNamedMap in extensions/terminal-suggest/src/fig/fig-autocomplete-shared/convert.ts preserve that array and map each spelling to the same subcommand. collectCompletionItemResult in extensions/terminal-suggest/src/fig/figInterface.ts emits all subcommands as Method entries without distinguishing their canonical spelling. Existing shell alias handling does not address this path, and the terminal alias icon in src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalSymbolIcons.ts shares its base glyph with the method icon, so classification alone may not convey the relationship. Preserve parsing, insertion, options, generators, and shell-alias behavior. The discussion at https://github.com/microsoft/vscode/issues/241968 supports considering npm aliases but does not settle whether all alternate Fig subcommand names should receive this treatment; https://github.com/microsoft/vscode/issues/241825 addresses a different classification problem.
- **Open decisions:**
  - Should alternate names in every Fig subcommand name array be displayed as aliases of its first name, or should alias treatment be limited to explicitly recognized canonical/alias relationships such as npm's install/i/add?
