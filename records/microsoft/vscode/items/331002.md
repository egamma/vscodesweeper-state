# Issue #331002 — Custom agent `agents:` frontmatter allowlist is parsed but never enforced by RunSubagentTool — coordinator can invoke any enabled agent, not just the ones listed

[https://github.com/microsoft/vscode/issues/331002](https://github.com/microsoft/vscode/issues/331002)

## Summary

Confirmed on main: `RunSubagentTool.invoke()`/`prepareToolInvocation()` resolve a requested subagent purely by name+enabled status and never check `currentModeInstructions?.allowedSubagents`, so the `agents:` frontmatter allowlist is parsed but not enforced — a real gap that should be routed to the chat/agents area.

## Change summary

The `agents:` frontmatter allowlist on a custom coordinator agent is documented as restricting which subagents it can delegate to via `runSubagent`, but the dispatch code never enforces it, letting a coordinator invoke any enabled custom agent by name.

## Best solution

In src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts, gate `getSubAgentByName`'s result (or the call site in `invoke()`/`prepareToolInvocation()`) against `currentModeInstructions?.allowedSubagents` when that list is defined, rejecting/erroring on names outside it, matching the documented allowlist behavior.
