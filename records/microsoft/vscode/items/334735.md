# Issue #334735 — [Bug] CoPilot Chat is unable to invoke commands when `pwsh` is the default shell, because its mandatory wrapper prepends POSIX `$Env:PATH` assignments to every invoked command.

[https://github.com/microsoft/vscode/issues/334735](https://github.com/microsoft/vscode/issues/334735)

## Summary

Confirmed in the current source: `TerminalSandboxEngine.wrapCommand` (non-Windows path) always builds the sandbox runtime invocation with bare POSIX env-var-assignment syntax (`PATH="$PATH:..." TMPDIR="..." "exec" ... -c '...'`) and never checks whether the terminal's actual shell is PowerShell, so the wrapped line is invalid pwsh syntax whenever `pwsh` is the configured shell on Linux/macOS.

## Change summary

The mandatory agent-sandbox command wrapper on Linux/macOS always emits POSIX-shell env-var-prefix syntax, which pwsh cannot parse when it is the user's default/configured shell, breaking every sandboxed command invocation.

## Best solution

In src/vs/platform/sandbox/common/terminalSandboxEngine.ts, make the non-Windows branch of `wrapCommand` shell-aware: when the target shell is PowerShell, either force the sandbox invocation through an explicit POSIX interpreter (mirroring how `_wrapUnsandboxedCommand` already wraps with `env ... <shell> -c '<command>'` when a shell is supplied) or emit pwsh-native syntax (`$Env:PATH = ...; ...`) instead of the bare `VAR=val cmd` form. The shell-detection logic already exists as `isPowerShell()` in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/runInTerminalHelpers.ts and is already used by the sibling `commandLineSandboxRewriter.ts` for tree-sitter parsing — the fix likely needs a platform-layer-safe equivalent (or a boolean flag threaded through `ITerminalSandboxService.wrapCommand`) since the engine lives below the workbench layer.
