# Issue #334735 — [Bug] CoPilot Chat is unable to invoke commands when `pwsh` is the default shell, because its mandatory wrapper prepends POSIX `$Env:PATH` assignments to every invoked command.

[https://github.com/microsoft/vscode/issues/334735](https://github.com/microsoft/vscode/issues/334735)

## Summary

Confirmed in source: the non-Windows sandbox-runtime wrapper always emits POSIX `PATH="$PATH:..."` assignment syntax regardless of the user's actual shell, so it breaks when the integrated terminal's default shell is `pwsh` on Linux/macOS.

## Change summary

Copilot Chat's terminal-tool sandbox wrapper fails to run any command when the default shell is PowerShell (pwsh) on Linux, because the wrapped command prepends bash-style `PATH="$PATH:..."` env assignments that pwsh can't parse.

## Best solution

In terminalSandboxEngine.ts, build the sandboxed command's env-var prefix with the shell-agnostic `env VAR=val ...` form (as `_wrapUnsandboxedCommand` already does for its fallback path) instead of raw `VAR="..."` assignment syntax, so it works under bash, zsh, and pwsh alike.
