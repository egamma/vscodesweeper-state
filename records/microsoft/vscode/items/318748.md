# Issue #318748 — Custom endpoint language models display id instead of name in model picker

[https://github.com/microsoft/vscode/issues/318748](https://github.com/microsoft/vscode/issues/318748)

## Summary

Keep open: current source still conflates same-ID variants within a provider group, and the separate-group workaround still leaves utility-model overrides ambiguous. Display names are propagated today, but that does not resolve the identity problem acknowledged in the discussion.

## Change summary

Custom models sharing an upstream model ID need distinguishable display names, independent configurations, and unambiguous selection in model overrides.

## Best solution

Establish a stable identity for configured model variants without changing the upstream model ID sent to the endpoint, then use that identity consistently for registration, configuration lookup, and utility-model selection. A maintainer should settle the public configuration and override contract before implementation.
