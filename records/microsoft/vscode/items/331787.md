# Issue #331787 — [Webview] Service worker corrupts raw remoteAuthority containing - followed by four hex digits

[https://github.com/microsoft/vscode/issues/331787](https://github.com/microsoft/vscode/issues/331787)

## Summary

The reported authority corruption is still present in current main: the service worker forwards a raw remote hostname into a handler that always decodes it. Keep this open and route it to the webview area; the old reported version does not invalidate the current source diagnosis.

## Change summary

Preserve literal remote hostnames containing a hyphen followed by four hexadecimal digits when loading webview resources.

## Best solution

Make the webview resource-loading path preserve raw remote authorities while continuing to decode authorities produced by asWebviewUri. Cover both request origins with regression tests without changing resource authorization or authentication behavior.
