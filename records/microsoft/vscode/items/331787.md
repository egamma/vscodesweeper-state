# Issue #331787 — [Webview] Service worker corrupts raw remoteAuthority containing - followed by four hex digits

[https://github.com/microsoft/vscode/issues/331787](https://github.com/microsoft/vscode/issues/331787)

## Summary

Traced and confirmed on current main: the webview service worker's remote-authority fetch branch sends the raw hostname as `authority`, but `webviewElement.ts` unconditionally runs it through `decodeAuthority`, which is only valid for `encodeAuthority`-produced strings — a raw host containing `-[0-9a-f]{4}` gets corrupted into a different hostname, breaking the resource fetch.

## Change summary

Webview resource requests 404 when the VS Code remote authority (hostname) happens to contain a hyphen followed by four hex digits, because the raw authority gets run through the encoded-authority decoder.

## Best solution

In src/vs/workbench/contrib/webview/browser/pre/service-worker.js, mark authorities from the remote-authority branch (around line 382, `authority: requestUrl.host`) as raw/already-decoded (or encode them there), and change the `load-resource` handler in src/vs/workbench/contrib/webview/browser/webviewElement.ts (around line 288) to only call `decodeAuthority` for authorities explicitly flagged as encoded — this requires a protocol-shape change between the two files, so it needs a maintainer to work out versioning (the SW has a `VERSION` cache-buster) rather than a blind patch.

## Evidence

- **encode/decode asymmetry:** src/vs/workbench/contrib/webview/common/webview.ts:62-78 defines encodeAuthority (escapes non-alphanumerics as `-XXXX` hex) and decodeAuthority (undoes exactly that pattern) as a matched pair.
- **raw authority sent unencoded:** src/vs/workbench/contrib/webview/browser/pre/service-worker.js:375-384 — the remote-authority fetch branch sends `authority: requestUrl.host` verbatim (never passed through encodeAuthority), unlike the vscode-resource branch above it (line 357) which extracts an already-encoded authority.
- **unconditional decode:** src/vs/workbench/contrib/webview/browser/webviewElement.ts:288 calls `decodeAuthority(entry.authority)` for every `load-resource` message with no flag distinguishing raw vs. encoded authorities, so a raw host matching `-[0-9a-f]{4}` is silently mangled.
- **no existing fix:** git log on these three files shows no recent related change (last touch is an unrelated agents worktree commit, 6b335613); the asymmetry is present on current main.
