# Issue #332126 — MSAL: stale session records in SecretStorage cause Settings Sync sign-out every ~1h

[https://github.com/microsoft/vscode/issues/332126](https://github.com/microsoft/vscode/issues/332126)

## Summary

Detailed, plausible-sounding report but unconfirmed by anyone else and not fully verifiable from source: the leftover-legacy-key part checks out, but the core claim (a stale MSAL token cache entry silently surviving fresh interactive re-login and causing periodic Settings Sync sign-out) depends on @azure/msal-node internals this repo doesn't control, so I can't confirm it conclusively — asking the reporter to confirm on the latest build and share the requested diagnostics.

## Change summary

Settings Sync repeatedly signs out ~30-60 minutes after a fresh personal-MSA login because SecretStorage allegedly accumulates stale session/PCA cache records that a silent refresh later falls back to.

## Best solution

If confirmed, this belongs in extensions/microsoft-authentication: either prune stale per-realm account cache entries on successful interactive login, or make getAllSessionsForPca (src/node/authProvider.ts) fall back to another cached realm/token instead of returning 0 sessions when the preferred (home-tenant) account fails silent refresh; also delete the legacy `microsoft.login.keylist` entries once `_migrateSessions` has run instead of leaving them behind.
