# Issue #332126 — MSAL: stale session records in SecretStorage cause Settings Sync sign-out every ~1h

[https://github.com/microsoft/vscode/issues/332126](https://github.com/microsoft/vscode/issues/332126)

## Summary

Well-diagnosed, still-reproducing bug: personal Microsoft accounts get periodically signed out of Settings Sync because stale legacy session/PCA-cache records in SecretStorage are never cleaned up after migration, and three commenters confirm it persists through 1.135.0 and 1.136.1; routing to the microsoft-authentication area rather than closing.

## Change summary

Personal Microsoft accounts get signed out of Settings Sync roughly every hour because stale, never-cleaned-up session/PCA cache records in SecretStorage cause silent token refresh to pick an old, expired refresh token.

## Best solution

Have MsalAuthProvider._migrateSessions (extensions/microsoft-authentication/src/node/authProvider.ts) and the legacy-key migrations in publicClientCache.ts/accountAccess.ts delete the old keys once migrated instead of leaving them in SecretStorage forever, and review getAllSessionsForPca's per-homeAccountId account selection so a stale cached account entry can't shadow the freshly-authenticated one.

## Evidence

- **migration never cleans up:** extensions/microsoft-authentication/src/node/authProvider.ts _migrateSessions() reads old session records via BetterTokenStorage('microsoft.login.keylist', ...) but only sets a globalState flag afterward — it never calls delete on the old keys, matching the reporter's dump showing residual 'f8cdef31-.../1:live.com:<puid>/...' and 'microsoft.login.keylist' entries.
- **legacy account/PCA-list keys never deleted:** extensions/microsoft-authentication/src/common/accountAccess.ts AccountAccessSecretStorage.initialize() and src/node/publicClientCache.ts PublicClientApplicationsSecretStorage.getOldValue()/runMigration() read the old 'accounts-<cloud>-<clientId>-<authority>' / 'publicClientApplications-<cloud>' keys but never remove them, leaving permanent duplicates as the reporter observed.
- **account selection could pick a stale entry:** authProvider.ts getAllSessionsForPca() groups cachedPca.accounts by homeAccountId and picks one by tenant match/home-tenant heuristic — if a stale account entry from old migrated data shares a homeAccountId with a fresh one, this heuristic, not recency, decides which refresh token gets used.
- **corroboration:** 3 independent commenters confirm recurrence on v1.135.0 and v1.136.1, 5 issue-body upvotes.
- **related but not verified duplicate:** https://github.com/microsoft/vscode/issues/242814 is open, labeled upstream/authentication-microsoft, and tracks the same general personal-MSA auto-sign-out symptom family, but has no confirmed identical root-cause diagnosis to this issue's stale-SecretStorage-record mechanism.
