## Evidence

- **Confirmed reproductions:** The discussion at https://github.com/microsoft/vscode/issues/345090 contains independent macOS and Linux confirmations on Insiders 1.146.0. With tracked and untracked parent edits, confirming Merge Changes produces no visible error and leaves both repositories unchanged. The November 12 debugger investigation identifies the rejected merge action and an onDidRun emitter with no listeners.
- **Current host precondition:** src/vs/platform/agentHost/node/agentHostMergeOperationHandler.ts:98-100 rejects a dirty parent repository before reaching the worktree commitAll call. This matches the reported trigger and explains why the confirmation's promised commit does not occur.
- **Current error propagation:** ChangesWorkbenchButtonBarWidget in src/vs/workbench/contrib/sessionChanges/browser/changesView.ts:522-523 returns changeset.invokeOperation(op.id) without reporting its rejection. WorkbenchButtonBar constructs a plain ActionRunner in src/vs/platform/actions/browser/buttonbar.ts:82; src/vs/base/common/actions.ts:189-203 catches action errors and publishes them only through onDidRun. The changes widget has no onDidRun error listener.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/345058 is open. Its description explicitly addresses silent title-bar failures, conditional commit messaging, and a proposed Stash and Merge recovery. The issue author requests area-owner judgment rather than prescribing that recovery UX.
- **Related issue is not the same symptom:** https://github.com/microsoft/vscode/issues/316336 requests selective file/hunk application and safer merge-back around unrelated edits, describing a chat-mediated merge workflow. It does not establish the same silent title-bar rejection, so it does not meet the stronger duplicate bar for this re-reviewed issue.
