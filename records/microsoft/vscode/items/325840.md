## Summary

A vague, unbudged request to add automatic cleanup for several unrelated on-disk caches (Chromium's Cache/Code Cache/CachedData directories plus VS Code's local file history); part of the ask is already addressed by existing settings, and the rest (Chromium/Electron cache dirs) isn't something VS Code core directly manages, so this needs product discussion rather than a close.

## Change summary

Reporter wants VS Code to automatically clean up growing cache/history folders (Cache, CachedData, Code Cache, User\History) since nothing currently prunes them.

## Best solution

Point the reporter at the existing local-history retention settings (workbench.localHistory.maxFileEntries/maxFileSize/exclude/enabled) for the User\History part; the Cache/CachedData/Code Cache directories are Chromium/Electron's own disk and V8 code caches (self-managed, size-bounded by Chromium, not a VS Code core file), so that portion is better tracked as a narrower, Electron-specific report if the reporter can show unbounded (non-evicting) growth.
