## Summary

The report identifies several independent storage systems but does not quantify which one is growing, what content it holds, or what activity triggers the growth. Current source already applies different retention policies to code cache and local history, so a targeted reproduction is needed before determining which subsystem is defective.

## Change summary

Prevent VS Code cache and local-history directories from growing excessively, and provide a supported way to reclaim their disk space.

## Best solution

Identify the specific unbounded store and its trigger, then correct that subsystem's retention policy or expose an appropriate cleanup mechanism without indiscriminately deleting recoverable local-history data.
