# Issue #178505 — Allow extensions to specify the schema for arguments to contributed commands

[https://github.com/microsoft/vscode/issues/178505](https://github.com/microsoft/vscode/issues/178505)

## Summary

The extension command-schema gap remains in current source: built-in command metadata supplies argument completion, but contributed commands cannot expose equivalent metadata through a supported contract. Keep this accepted Backlog request open; no qualifying open canonical was found.

## Change summary

Let extensions declare command argument schemas for completion when configuring command invocations.

## Best solution

Provide a supported extension-facing command argument-schema contract that integrates with the existing schema-driven completion infrastructure. Settle whether schemas are declarative or registered at runtime, and whether the initial consumer scope includes command inputs in tasks.json and launch.json.

- **Behavior:**

  > Extension authors can supply a supported schema describing a contributed command's arguments without publishing a separate schema for user configuration files. When configuring that command in keybindings.json, users receive schema-based argument completion comparable to built-in commands. Commands without schemas and existing built-in completion retain their behavior. The issue additionally requests consideration of command-input consumers in tasks.json and launch.json; their inclusion needs an explicit scope decision.
- **Trace:**

  > KeybindingsJsonSchema.updateSchema in src/vs/workbench/services/keybinding/browser/keybindingService.ts consumes a single argument schema from CommandsRegistry metadata. The commands contribution schema and handler in src/vs/workbench/services/actions/common/menusExtensionPoint.ts expose no corresponding extension field. Public command registration in src/vscode-dts/vscode.d.ts has no metadata parameter, and ExtHostCommands forwards only command IDs to MainThreadCommands, despite accepting metadata internally. These paths establish the missing supported contract, not a runtime defect. Preserve command execution, activation, and existing built-in schema behavior; automatic inference from TypeScript handlers is an optional suggestion, not an established requirement. The separate inputs schema is in src/vs/workbench/services/configurationResolver/common/configurationResolverSchema.ts. Related demand appears in https://github.com/microsoft/vscode/issues/187039, but that newer closed issue cannot absorb this report.
- **Open decisions:**
  - Should the supported public contract declare argument schemas in contributes.commands, expose them through runtime command registration, or support both, including completion before extension activation?
  - Should initial support cover only keybindings.json, or also command inputs in tasks.json and launch.json?
