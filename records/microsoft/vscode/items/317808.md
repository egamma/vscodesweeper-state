# Issue #317808 — Profile to authentication path

[https://github.com/microsoft/vscode/issues/317808](https://github.com/microsoft/vscode/issues/317808)

## Summary

Keep open: choosing an external browser is supported, but choosing a matching browser profile for authentication remains a distinct gap. No verified older canonical owns this same behavior, and this team-authored request is protected from judgment closes.

## Change summary

Allow work and personal VS Code profiles to direct extension authentication into their corresponding external-browser profiles.

## Best solution

Define a supported way to associate a VS Code profile with an external-browser profile for authentication, building on the external-opening infrastructure. Preserve the distinction between browser-session selection and an extension's already-authenticated account preference.

## Evidence

- **Existing capability is partial:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.externalBrowser as a browser name or executable path. src/vs/workbench/electron-browser/window.ts, setupOpenHandlers, passes that setting to nativeHostService.openExternal. This supports browser selection, not a built-in mapping to a browser's work or personal profile.
- **Current launch boundary:** src/vs/platform/native/electron-main/nativeHostMainService.ts, openExternalBrowser, calls open(url, { app: { name: ... } }) without browser-profile arguments. workbench.externalUriOpeners in src/vs/workbench/contrib/externalUriOpener/common/configuration.ts maps URL patterns to opener IDs, not browser-profile identities. Neither examined configuration directly supplies the requested association.
- **Browser-profile selection was explicitly left separate:** https://github.com/microsoft/vscode/issues/96132 is closed after implementing workbench.externalBrowser. A commenter subsequently asked whether browser profiles could be specified at https://github.com/microsoft/vscode/issues/96132#issuecomment-2225035357; the maintainer requested a new feature request at https://github.com/microsoft/vscode/issues/96132#issuecomment-2252887540. The closed browser-selection issue is therefore neither an open duplicate target nor proof that this request is implemented.
