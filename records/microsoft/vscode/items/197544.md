# Issue #197544 — Merge Editor: Accept Combination When Edits replace same range with same new text

[https://github.com/microsoft/vscode/issues/197544](https://github.com/microsoft/vscode/issues/197544)

## Summary

Valid, unimplemented enhancement to the merge editor's smart-combine logic. The existing `smartCombineInputs` in `modifiedBaseRange.ts` bails out when two edits from different inputs overlap (line 221), even when they replace the same range with the same text. This could be improved by deduplicating identical overlapping edits instead of failing. Team-authored, milestone Backlog — keeping open.

## Change summary

When two merge inputs each replace the same base range with the same new text (but have additional non-overlapping changes), the merge editor should auto-combine them instead of treating them as an unresolvable conflict.

## Best solution

Extend `editsToLineRangeEdit` in `src/vs/workbench/contrib/mergeEditor/browser/model/modifiedBaseRange.ts` (around line 221) to detect when consecutive sorted edits from different inputs target the same range and produce the same replacement text, and deduplicate them instead of returning `undefined`. This would also allow `computeAutoMergedResult` to auto-resolve more conflicts on open.
