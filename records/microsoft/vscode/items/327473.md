# Issue #327473 — Why does the built-in AI agent tool, edit_notebook_file, often fail to edit, meaning it executes but doesn't make any changes? However, it never has any problems when editing a brand new notebook.

[https://github.com/microsoft/vscode/issues/327473](https://github.com/microsoft/vscode/issues/327473)

## Summary

Confirmed bug: the catch block in `_createModifiedFileEntry` incorrectly assumes any failure means the file doesn't exist, causing repeated 'file already exists' errors for existing notebooks (especially over SSH Remote). An open community PR (#327585) addresses this — it should be reviewed and landed.

## Change summary

The `edit_notebook_file` agent tool silently fails on existing notebooks because the error-handling path wrongly assumes a missing file and attempts to create it without an overwrite flag.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/327585 which adds a `fileService.exists()` guard before the create-file fallback in the catch block, and improves the stale-cell-ID error message in `editNotebookTool`. The fix is small and localized.
