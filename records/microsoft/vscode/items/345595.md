# Issue #345595 — MCP disabled transitively through plugin hard to re-enable

[https://github.com/microsoft/vscode/issues/345595](https://github.com/microsoft/vscode/issues/345595)

## Summary

Keep open: existing Enable Plugin and Show Plugin actions partially address recovery, but do not provide the requested discoverable flow with a preview and control of affected components. This team-authored request needs a UX decision, not a judgment close.

## Change summary

Make it easier to recover a plugin-disabled MCP server while understanding and controlling which sibling customizations become enabled.

## Best solution

Provide a clear recovery entry point from the disabled MCP control in the shared Customizations editor, with an explicit account of the parent-plugin effects. Settle whether that entry point navigates to plugin management or offers an inline confirmation with component-level choices.

- **Reason:** Making inherited disablement understandable and recoverable supports consistent customization management without introducing a separate enablement model.
