# Issue #255738 — Build: Universal build flakes at "Set hardened entitlements"

[https://github.com/microsoft/vscode/issues/255738](https://github.com/microsoft/vscode/issues/255738)

## Summary

Keep open in vscode-build: maintainers repeatedly confirmed signing failures after both the osx-sign upgrade and the retry mitigation. Current source retains those mitigations, but there is no evidence that the underlying intermittent failure is resolved.

## Change summary

macOS builds intermittently fail at Set Hardened Entitlements with a missing-keychain-item error despite an available signing identity.

## Best solution

Establish why codesign intermittently cannot access the configured identity and make the macOS signing pipeline reliable without weakening signing requirements. Investigate failed-agent state and the difference between an in-process retry and restarting the job before choosing a further mitigation.

## Plan brief

- **Likely files:** `build/darwin/sign.ts`, `build/azure-pipelines/darwin/product-build-darwin-universal.yml`, `build/azure-pipelines/darwin/steps/product-build-darwin-sign-local.yml`

Validate the eventual change with repeated affected signing jobs, including universal signing, and successful signature verification; a single green rerun is insufficient to establish that this flake is fixed.
- **Behavior:**

  > macOS builds intermittently fail during Set Hardened Entitlements with 'The specified item could not be found in the keychain.' Maintainers observed the certificate and matching valid identity in an unlocked keychain, and short retries did not reliably recover. The expected outcome is reliable signing of the intended build artifacts with the configured identity and required hardened entitlements. Acceptance must exercise the affected CI environment repeatedly and verify the resulting signatures rather than merely demonstrate that a job restart sometimes succeeds.
- **Trace:**

  > The universal pipeline in build/azure-pipelines/darwin/product-build-darwin-universal.yml prepares buildagent.keychain and calls main in build/darwin/sign.ts; the local signing template invokes the same entry point. main supplies explicit keychain and identity values to @electron/osx-sign, then calls sign through retrySignOnKeychainError, which retries the specific missing-item error three times with short delays. https://github.com/microsoft/vscode/pull/270324 introduced this mitigation, but https://github.com/microsoft/vscode/issues/255738 records failures afterward, including an in-job retry failure followed by a successful delayed job restart. The dependency upgrade in https://github.com/microsoft/vscode/pull/259758 also preceded confirmed recurrence. The trace stops at the external signing/keychain interaction: an agent-state race or stale codesign process is a maintainer hypothesis, not a confirmed diagnosis. Preserve identity selection, hardened-runtime requirements, entitlement mappings, and explicit propagation of unrecoverable signing failures; do not bypass signing or broaden this into unrelated security changes.
