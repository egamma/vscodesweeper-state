# Issue #348369 — Let a LanguageModelChatProvider declare that it defers tools, so they are left out of the prompt budget

[https://github.com/microsoft/vscode/issues/348369](https://github.com/microsoft/vscode/issues/348369)

## Summary

A real provider-API gap remains: extension providers cannot declare deferred tool definitions for prompt budgeting. The related issues address different contracts or failure modes and do not fully cover this request.

## Change summary

Allow language model providers to declare tool-definition deferral so prompt budgeting reflects the definitions actually loaded.

## Best solution

Define a provider-neutral accounting contract that accommodates partially deferred tool sets, preserves accurate context limits, and retains existing budgeting for providers that do not opt in.

- **Behavior:**

  > A provider that defers most tool definitions should not lose conversation capacity to definitions that its model has not received. Definitions that remain eager or become loaded must still count against the effective budget. The provider should report truthful input, output, and context-window limits rather than inflate maxInputTokens. Providers that do not declare deferral must retain current behavior.
- **Trace:**

  > AgentIntent in extensions/copilot/src/extension/intents/node/agentIntent.ts:704–736 subtracts countToolTokens(availableTools) before rendering the conversation. ExtensionContributedChatEndpoint in extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts supplies ExtensionContributedChatTokenizer, whose countToolTokens in extChatTokenizer.ts:91–110 estimates every definition without loading-state information. The stable and proposed provider declarations contain no corresponding accounting contract. Internal ChatEndpoint tool-search metadata is not exposed as a provider-neutral declaration. Source inspection establishes the missing contract, but the reporter's backend and numerical estimate were not executed. Keep backend deferral implementation, tool execution, and the separate Context Size display issue outside this request; the uncertainty begins at how partial and changing tool-loading state should be communicated.
- **Open decisions:**

## Evidence

- **Missing public capability:** src/vscode-dts/vscode.d.ts:20851–20991 defines LanguageModelChatInformation, capabilities, and provideTokenCount without a tool-deferral or tool-budget contract. capabilities.toolCalling already accepts a numeric tool-count limit, but that does not describe token accounting.
- **Proposed API check:** src/vscode-dts/vscode.proposed.chatProvider.d.ts exposes maxContextWindowTokens and configurationSchema, but neither declares deferred definitions or their effective token cost.
- **Current accounting path:** extensions/copilot/src/extension/intents/node/agentIntent.ts:704–736 counts availableTools through endpoint.acquireTokenizer().countToolTokens(tools), subtracts that cost from baseBudget, and applies a safety margin. toolSearchEnabled is read separately; this budget calculation does not exclude deferred definitions.
- **Extension-provider boundary:** ExtensionContributedChatEndpoint in extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts acquires ExtensionContributedChatTokenizer. Its countToolTokens implementation in extChatTokenizer.ts:91–110 estimates every supplied tool's name, description, and schema, adds per-tool overhead, and applies a 10% margin without deferral information.
- **Existing capability is not coverage:** ChatEndpoint reads internal capabilities.supports.tool_search in extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts:278. Model-family heuristics in extensions/copilot/src/platform/endpoint/common/chatModelCapabilities.ts:522 onward identify known tool-search families; neither provides the requested public contract for an arbitrary local-model provider. Inflating maxInputTokens changes the declared input limit rather than representing tool deferral.
- **Related requests have different scope:** Verified open https://github.com/microsoft/vscode/issues/334424 requests a Custom Endpoint Responses API configuration switch; https://github.com/microsoft/vscode/issues/347351 requests an Agent Host tool-count ceiling; https://github.com/microsoft/vscode/issues/347754 reports Agent Host tool-search activation regressions. Their discussions do not establish a canonical issue owning this provider-level budgeting contract.
- **Related budget failure:** Verified open https://github.com/microsoft/vscode/issues/329040 primarily reports silent failures when tool definitions exhaust the budget. Its secondary observation concerns deferred-tool accounting, but it does not establish ownership of the public provider capability requested here.
- **Separate display workaround consequence:** https://github.com/microsoft/vscode/issues/348370 concerns inconsistent Context Size displays after reporting inflated maxInputTokens. Correcting that display would not remove deferred definitions from the conversation budget.
