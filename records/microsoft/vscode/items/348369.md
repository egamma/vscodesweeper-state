# Issue #348369 — Let a LanguageModelChatProvider declare that it defers tools, so they are left out of the prompt budget

[https://github.com/microsoft/vscode/issues/348369](https://github.com/microsoft/vscode/issues/348369)

## Summary

Keep open in Backlog Candidates: current provider capabilities cannot declare deferred-tool budgeting, and the extension-provider tokenizer still counts every offered definition. The related requests address different capabilities, not this accounting gap.

## Change summary

Allow language model providers to declare tool deferral so deferred definitions do not unnecessarily consume the conversation budget.

## Best solution

Define a provider-facing accounting contract that distinguishes eagerly included definitions from deferred tools, and honor it during prompt budgeting without inflating maxInputTokens. Preserve existing accounting for providers that do not opt in.

- **Current accounting path:** extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts constructs ExtensionContributedChatTokenizer for extension-provided models. Its countToolTokens method in extChatTokenizer.ts:91 counts every tool's name, description, and schema, plus overhead, without checking whether the backend defers it.
- **Conversation budget impact:** extensions/copilot/src/extension/intents/node/agentIntent.ts:704–735 counts availableTools and subtracts toolTokens from baseBudget before rendering. Provider-side deferral therefore does not remove those definitions from the local budget.
