# Issue #336363 — Git multi-file diff refresh steals keyboard focus from the terminal

[https://github.com/microsoft/vscode/issues/336363](https://github.com/microsoft/vscode/issues/336363)

## Summary

Traced conclusively in source: the multi-diff editor's automatic first-change selection and active-item restoration both use a stale `_preserveFocusOnLoad` flag (set once at open time) rather than checking where focus currently is, so a later Git status refresh can steal keyboard focus from the terminal without the user having interacted with the diff.

## Change summary

When an open multi-file Git diff (Staged/Unstaged Changes) refreshes its file list, it can grab keyboard focus away from the integrated terminal, so subsequent typing lands in the diff instead.

## Best solution

In src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidgetImpl.ts, add a current-focus containment check to the automatic first-change selection (line ~329) and active-item restoration (line ~543) so they only move focus when the widget already contains focus, instead of trusting the open-time `_preserveFocusOnLoad` flag — the reporter's own diagnostic patch demonstrates this fixes the reported cases.
