# Issue #272887 — Parallel callstacks

[https://github.com/microsoft/vscode/issues/272887](https://github.com/microsoft/vscode/issues/272887)

## Summary

Keep this accepted backlog request open: the existing Call Stack view does not provide a merged parallel-stacks visualization, and the request has 22 community upvotes. The older concurrency discussion overlaps, but does not clearly own the same physical-thread visualization requested here.

## Change summary

Provide a Visual Studio-style parallel-stacks view that merges common frames across multiple threads.

## Best solution

Design a grouped-stack visualization in the debug workbench, first resolving whether existing DAP stack traces suffice for the initial physical-thread use case or whether adapter-provided relationships are required. Coordinate with the existing concurrency discussion without treating its broader protocol exploration as a proven duplicate.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/callStackView.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/test/browser/callStack.test.ts`
- **Validation:** Use a paused multithreaded debug session with two threads sharing part of a stack and one divergent thread. Verify that the visualization merges the common frames, preserves divergent branches and thread identity, and selecting a concrete frame updates the editor and Variables view for the correct thread. Retain existing Call Stack navigation behavior.
- **Behavior:**

  > Users debugging concurrent programs should be able to understand common and divergent call paths without inspecting each thread separately. The requested parallel-stacks visualization groups shared frames while retaining enough thread identity to inspect a particular execution context. Acceptance should cover shared and divergent stacks and correct frame selection, including the corresponding editor location and variables. The initial supported thread types and relationship semantics need agreement before implementation.
- **Trace:**

  > CallStackDataSource in src/vs/workbench/contrib/debug/browser/callStackView.ts currently exposes a session/thread/frame hierarchy, with frame retrieval through getThreadCallstack; its existing grouping concerns deemphasized frames within an individual thread, not shared stacks across threads. src/vs/workbench/contrib/debug/browser/debug.contribution.ts registers the existing Call Stack view and navigation commands, with no equivalent parallel-stack surface found. The maintainer and reporter disagree about whether DAP relationships are necessary or existing frame data can support the desired visualization. https://github.com/microsoft/vscode/issues/116109 contains related logical-thread and adapter-provided call-graph design proposals, whereas https://github.com/microsoft/vscode/issues/214824 requests a distinct single-thread view. https://github.com/microsoft/vscode/issues/319193 records an extension attempt and an active-frame selection limitation, not a completed solution. Preserve the current per-thread view and debugger frame-selection semantics while defining the new visualization.
- **Open decisions:**
  - Should the initial feature group physical-thread stacks using existing DAP frame data, or require adapter-provided relationships and include logical tasks or green threads?
  - What constitutes a shared frame for the user-visible grouping: matching display text alone, or matching source and execution-location identity as well?
