# Issue #341093 — Local harness - MCP elicitation isn't shown and requests times out

[https://github.com/microsoft/vscode/issues/341093](https://github.com/microsoft/vscode/issues/341093)

## Summary

Thanks for the detailed debugging. The report is complete and the diagnosis is plausible: the standalone GET SSE stream is opened after the server sends the elicitation, so the server has no stream to send it on. It could not be confirmed from source, so it stays open for a maintainer to look at the local harness MCP connection ordering.

## Change summary

With the Local harness, an MCP elicitation sent right after a tool call is lost because the standalone SSE GET stream arrives after the server's send, so the request times out on the first attempt.

## Best solution

Make the local-harness MCP client open the standalone GET SSE stream before it issues the first tool call. Alternatively, make it tolerate servers that cannot yet push server-to-client requests. Align the ordering with the Copilot harness path, which does not reproduce.
