# Issue #344076 — Support a connection token file when launching with --remote host:port

[https://github.com/microsoft/vscode/issues/344076](https://github.com/microsoft/vscode/issues/344076)

## Summary

The requested desktop CLI capability remains missing: direct host:port resolution still supplies no connection token, and the existing token-file option belongs to the server. Keep this security-sensitive request open for maintainer decisions about credential lifetime, restoration, and window isolation, coordinating with the reporter's prototype.

## Change summary

Allow desktop direct-remote launches to authenticate using a local token file without exposing credentials or weakening existing connection checks.

## Best solution

Establish an explicit credential-lifecycle contract for desktop direct-remote connections, then evaluate the existing prototype against it. The resulting capability should fail closed on credential-read errors, keep credentials separate from workspace identity, and preserve existing host confirmation behavior.

- **Existing-capability check:** The desktop argument registrations in src/vs/platform/environment/node/argv.ts include --remote but no connection-token or remote-connection-token-file option. The inspected direct-resolution path provides no CLI token-file input; resolver-supplied credentials do not satisfy the requested extension-free workflow.
- **Server-side capability is distinct:** src/vs/server/node/serverEnvironmentService.ts registers --connection-token-file for the server. parseServerConnectionToken in src/vs/server/node/serverConnectionToken.ts reads UTF-8 content, strips one trailing LF or CRLF, validates the token, and returns explicit errors for unreadable or invalid files; this does not supply credentials to the desktop client.
- **Existing credential plumbing:** src/vs/platform/remote/electron-browser/remoteAuthorityResolverService.ts maintains authority-keyed connection tokens through _setAuthorityConnectionToken and getConnectionData.
