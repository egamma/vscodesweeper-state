# Issue #235785 — Allow for subtraction in Settings editor search queries

[https://github.com/microsoft/vscode/issues/235785](https://github.com/microsoft/vscode/issues/235785)

## Summary

Settings search still lacks general query subtraction; existing filters do not cover the requested behavior. Keep this accepted, team-authored request open: the related negation request is newer and cannot serve as its duplicate canonical.

## Change summary

Allow negative terms such as `-query` to exclude matching settings from Settings editor search results.

## Best solution

Define consistent negative-term semantics for Settings editor search and apply them across its result providers. Coordinate with https://github.com/microsoft/vscode/issues/331042 on whether the same syntax should also negate structured filters.

Manually verify that excluded settings do not return through alternate search providers.
- **Behavior:**

  > Users should be able to subtract unwanted settings from Settings editor search results using negative query terms. Matching exclusions must remain excluded regardless of which search provider supplies a result. Existing searches without negative terms should retain their behavior. Acceptance should cover mixed positive and negative queries and the agreed behavior for exclusion-only queries.
- **Trace:**

  > parseQuery and IParsedQuery in src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts expose positive structured filters and remaining query text, but no general exclusion semantics. SettingsEditor2.triggerSearch in src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts transfers those filters into viewState and forwards remaining text to triggerFilterPreferences. LocalSearchProvider and SettingMatches in src/vs/workbench/contrib/preferences/browser/preferencesSearch.ts consume that text as a positive search string; cleanFilter preserves minus signs. The provider module also contains TF-IDF and AI search paths, whose results need to obey the same agreed exclusion contract. Existing @stable behavior is a specialized exclusion, not coverage of this request. Preserve ordinary search and existing positive filters; do not conflate this work with changing whether setting values are searchable. https://github.com/microsoft/vscode/issues/331042 adds a related request to negate structured feature filters; the product scope and literal-minus behavior remain unsettled.
- **Open decisions:**
  - Should negative syntax cover plain-text terms only, or also structured filters such as -@feature:terminal?
  - Should an exclusion-only query show all otherwise eligible settings except those excluded?
  - How should users search for a literal leading minus sign rather than invoking subtraction?
