# Issue #336150 — Custom editors cannot receive the selection passed to vscode.openWith

[https://github.com/microsoft/vscode/issues/336150](https://github.com/microsoft/vscode/issues/336150)

## Summary

Real, additive API gap: `resolveCustomTextEditor`/`resolveCustomEditor` (and the proposed `resolveCustomEditorDiff`) take no options argument, so `TextDocumentShowOptions.selection` passed to `vscode.openWith` is silently dropped for custom editors. Confirmed by reading `src/vscode-dts/vscode.d.ts` (lines ~10378, ~10556) — no such parameter exists on main. Two viable API shapes are proposed by the author; a maintainer needs to pick one before implementation.

## Change summary

Custom text/webview editors have no way to receive the `selection`/reveal options passed via `vscode.openWith`, unlike text editors opened with `showTextDocument`.

## Best solution

Design and land an additive API — most likely a `reveal`-style event on `WebviewPanel` (covers both initial-open and already-open-tab cases) or an extra options parameter on `resolveCustomTextEditor`/`resolveCustomEditor` — then update `vscode.d.ts` and `extHostCustomEditors.ts` accordingly.
