# Issue #336150 — Custom editors cannot receive the selection passed to vscode.openWith

[https://github.com/microsoft/vscode/issues/336150](https://github.com/microsoft/vscode/issues/336150)

## Summary

Confirmed real API gap: `resolveCustomTextEditor`/`resolveCustomEditor` (and the proposed diff variants) take no options argument, so a `selection` passed to `vscode.openWith` is silently dropped for custom editors — routing to the extension-API area for a design decision between the two additive approaches the reporter suggests.

## Change summary

Custom editor providers have no way to receive the `selection` (or other `TextDocumentShowOptions`) passed to `vscode.openWith`, unlike text editors.

## Best solution

API owners should decide between adding an optional `options` (with `selection`) parameter to `resolveCustomTextEditor`/`resolveCustomEditor` or introducing a `reveal`-style event on `WebviewPanel`; either is additive and should start as a proposed API in `vscode.proposed.*.d.ts`.
