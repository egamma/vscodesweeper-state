# Issue #340377 — Chat: stop binding bare Delete to Undo Requests / Restore Checkpoint, and keep removed turns recoverable

[https://github.com/microsoft/vscode/issues/340377](https://github.com/microsoft/vscode/issues/340377)

## Summary

Fresh, well-researched design proposal about a destructive keybinding in chat (Delete → Undo Requests / Restore Checkpoint). The specific `inputFocus` hole from #340134 has already landed on main, but the broader design ask (don't bind a bare key to a destructive command by default, make removal visible/reversible, keep removed turns recoverable) is a genuine open gap with no maintainer response yet.

## Change summary

Requests VS Code stop binding the bare Delete key to destructive chat-turn-removal commands by default, and make removed/discarded chat turns visible and recoverable instead of silently vanishing.

## Best solution

A maintainer decision is needed on design direction: require a modifier chord (or unbind by default) for Undo Requests/Restore Checkpoint, and decide between a transient notice with inline Redo, a collapsed-but-recoverable turn model, or a branch-based undo — this is a UX/data-model design call, not a small bounded fix.

- **Trace:**

  > Undo Requests and Restore Checkpoint are registered with Delete/Cmd+Backspace keybindings in chatEditingActions.ts (lines ~454-505 and ~507-560), gated by inChatSession/textInputFocus/InputFocusedContext/inChatQuestionCarousel/readOnly context keys; restoreSnapshotWithConfirmation only prompts when file edits exist and a setting is enabled. chatModel.ts's setCheckpoint() hides rather than deletes removed turns, recoverable via redoEdit/redoEdit2 only until the next message is sent. Do not touch the existing inputFocus guards (#340134, #298752) — those fixes should remain; the open area is whether/how the default binding and discard-without-warning behavior itself changes.
- **Open decisions:**
  - Should the destructive commands require a deliberate key chord, or be left unbound by default (reachable only via toolbar/menu)?
  - What form should the 'removal is reversible' notice take — a transient notice with inline Redo, or something else?
  - Should removed turns be kept as collapsed/read-only recoverable entries, or should undo become a branch point preserving the old branch, or should VS Code instead just warn before permanently discarding on next send?
