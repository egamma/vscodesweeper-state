# Issue #319672 — Configuration-Based AI Integration

[https://github.com/microsoft/vscode/issues/319672](https://github.com/microsoft/vscode/issues/319672)

## Summary

Current VS Code already provides the requested optional, configuration-based AI integration surface through configurable language-model providers and the extension API, so no additional generic `configuration/ai` area is needed.

## Change summary

Provide an optional user-configured foundation through which extensions can integrate external AI services without adding a default provider.

## Best solution

Keep the existing provider-based design: users configure external services through Manage Language Models and `chatLanguageModels.json`, while extensions contribute providers through `languageModelChatProviders` and register their implementations with `vscode.lm.registerLanguageModelChatProvider`.

## Vision fit

- **Fit:** aligned
- **Reason:** The existing provider-extension architecture enables external AI integrations without adding provider-specific functionality to the default editor.
- **Evidence:** Public values: “The power lives in extensions” and “Out of the box, VS Code is a text editor: lightweight and fast”; durable themes include AI-assisted development and extension ecosystem API hygiene.

## Evidence

- **extension API:** src/vscode-dts/vscode.d.ts exposes the stable `vscode.lm.registerLanguageModelChatProvider` API and explicitly pairs it with the `languageModelChatProviders` extension contribution point.
- **configuration surface:** src/vs/workbench/contrib/chat/common/languageModels.ts registers `languageModelChatProviders`, including provider-defined configuration schemas, and exposes operations for configuring provider groups and individual models.
- **user workflow:** src/vs/workbench/contrib/chat/browser/chatManagement/chatManagement.contribution.ts registers `workbench.action.chat.manage` as “Manage Language Models” and `workbench.action.openLanguageModelsJson` for opening the underlying configuration.
- **external endpoints:** extensions/copilot/package.json contributes an optional `customendpoint` provider whose user configuration supports custom URLs, API keys, models, and Chat Completions, Responses, or Messages protocols.
