# Issue #194060 — SCM - Visually distinguishing Staged Changes from Changes in Tree View

[https://github.com/microsoft/vscode/issues/194060](https://github.com/microsoft/vscode/issues/194060)

## Summary

Keep open for a focused SCM design decision: current resource-group styling does not clearly distinguish section headings from directory rows. The verified related reports are either closed, address different visual problems, or are newer than this re-reviewed issue.

## Change summary

Make Staged Changes and Changes headings easier to distinguish from folders and files in the Source Control tree.

## Best solution

Establish a restrained, consistent heading treatment for SCM resource groups that makes staging boundaries easy to scan while preserving extension-provided label casing. Agree on the visual treatment before implementing it in the SCM renderer and styles.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/contrib/scm/browser/media/scm.css`
- **Validation:** In a development build, modify files in nested directories and stage only a subset, then select Source Control tree view. Confirm the agreed heading treatment distinguishes both staging sections from directory rows in light, dark, and high-contrast themes, with one and multiple repositories; verify keyboard navigation, count badges, inline actions, and extension-provided label casing remain unchanged.
- **Behavior:**

  > The Source Control tree should make Staged Changes and Changes recognizable as section headings rather than ordinary directory rows. Users should be able to identify the boundary between staged and unstaged files while scanning nested changes. Acceptance should cover the agreed treatment in light, dark, and high-contrast themes, including multiple repositories. Preserve label casing, keyboard navigation, staging actions, and count information.
- **Trace:**

  > ResourceGroupRenderer in src/vs/workbench/contrib/scm/browser/scmViewPane.ts renders a plain name element alongside actions and a CountBadge. The corresponding resource-group rules in src/vs/workbench/contrib/scm/browser/media/scm.css establish layout and truncation without a dedicated heading treatment. Existing SCM settings change view mode, sorting, folder compression, or action and repository-badge visibility rather than heading hierarchy. The issue discussion establishes that resource-group label casing can be meaningful to other SCM providers, so generic uppercase conversion is not a safe assumed outcome. https://github.com/microsoft/vscode/issues/286487 independently reports the same visual concern; https://github.com/microsoft/vscode/issues/141078 concerns file-path presentation and is outside this narrow scope. The unresolved boundary is the user-visible distinction to apply, not which renderer or CSS helper implements it.
- **Open decisions:**
  - Should resource-group headings be distinguished through typography alone, or through a section separator/background treatment that also changes the visual boundary between groups?
