# Issue #40604 — [json] suggest used values when property name has already been used

[https://github.com/microsoft/vscode/issues/40604](https://github.com/microsoft/vscode/issues/40604)

## Summary

The requested completion remains absent on current main: schema-less JSON suggests keys from structurally similar objects, but not from arbitrary nested objects such as the reported `RateTrip.Rating` example. No older open canonical issue was found, so this should remain open for a product decision rather than be closed as stale.

## Change summary

Suggest JSON property names previously used elsewhere in the document, even when the objects are at different structural locations.

## Best solution

Decide whether schema-less JSON completion should search keys across the whole document or retain its narrower structurally-similar-object scope, accounting for suggestion noise. If broader completion is desired, implement and test it in `vscode-json-languageservice`, then consume the updated service in VS Code.

## Evidence

- **maintainer assessment:** A VS Code maintainer confirmed the concrete example and characterized it as an improvement before retitling the issue: https://github.com/microsoft/vscode/issues/40604#issuecomment-357196698.
- **current JSON behavior:** `getSchemaLessPropertyCompletions` in https://github.com/microsoft/vscode-json-languageservice/blob/main/src/services/jsonCompletion.ts collects property names only from other objects under the same property name or sibling objects in the same array; for a root object it contributes only `$schema`. It therefore does not source the root-level `Rating` completion from nested `RateTrip.Rating`.
- **bundled dependency:** `extensions/json-language-features/server/package-lock.json` pins `vscode-json-languageservice` 6.0.0-next.4, while `extensions/json-language-features/server/src/jsonServer.ts` delegates completion to that language service.
- **fallback suppression:** `src/vs/editor/contrib/suggest/browser/suggest.ts` queries completion providers in ranked groups and stops after the first group producing results. Because JSON completion can return `$schema` at the root, the global word-based provider is not guaranteed to supply the previously used nested key.
