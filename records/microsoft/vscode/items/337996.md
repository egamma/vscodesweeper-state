# Issue #337996 — "Sign in to use GitHub Copilot" shown on every restart with GHE.com; agent host gets 401 on Copilot user info

[https://github.com/microsoft/vscode/issues/337996](https://github.com/microsoft/vscode/issues/337996)

## Summary

Fresh, well-documented report (0 days old, no comments yet) of the Copilot sign-in dialog reappearing on every restart for a GHE.com EMU account with EU data residency. The reported symptom matches the agent host's known 401-triggers-reauth codepath, but the deeper root cause (why the CAPI token is rejected for this enterprise/residency configuration) needs investigation beyond what a source read can settle.

## Change summary

With github-enterprise.uri configured for a GHE.com EMU account (EU data residency), the agent host's Copilot client repeatedly gets a 401 'Bad credentials' fetching Copilot user info after every restart, forcing the user to re-sign-in each time even though the stored GitHub session itself verifies fine.

## Best solution

Diagnose why the Copilot CAPI/model-list token exchange rejects a verified GHE.com EMU session on restart (token host routing, residency-specific CAPI endpoint, or stale/short-lived enterprise token) in src/vs/platform/agentHost/node/copilot/copilotAgent.ts and extensions/github-authentication, then ensure a valid stored session is reused without re-prompting.
