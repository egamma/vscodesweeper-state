# Issue #248799 — mac / zsh: onDidEndTerminalShellExecution event never fires for second executeCommand

[https://github.com/microsoft/vscode/issues/248799](https://github.com/microsoft/vscode/issues/248799)

## Summary

The bug has a second independent confirmation (zsh, intermittent). No commit references this issue, and the relevant code paths in `extHostTerminalShellIntegration.ts` and `commandDetectionCapability.ts` have not received a targeted fix for this pattern. The issue is real and should remain open — but it already carries the right area labels (`terminal-shell-integration`, `terminal-shell-zsh`) and needs a maintainer to investigate the zsh-specific command detection sequencing.

## Change summary

When using `terminal.shellIntegration.executeCommand` twice in sequence on zsh, the `onDidEndTerminalShellExecution` event never fires for the second command execution.

## Best solution

Investigate why zsh's shell integration sequences (prompt start / command executed / command finished) are not reliably detected for the second `executeCommand` call. The issue likely lives in the interaction between `CommandDetectionCapability.handleCommandFinished` (which fires `onCommandFinished`) and the zsh shell integration script's sequence emission timing. The `endShellExecution` flow in `extHostTerminalShellIntegration.ts` (lines 321–346) depends on `$shellExecutionEnd` being called from the main thread, which in turn depends on `onCommandFinished` firing — if zsh doesn't emit the D (command finished) sequence for the second command, the entire chain stalls.
