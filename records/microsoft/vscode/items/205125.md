# Issue #205125 — Git - "Discard Changes" and "Stage Changes" don't work for submodules

[https://github.com/microsoft/vscode/issues/205125](https://github.com/microsoft/vscode/issues/205125)

## Summary

The closed-submodule repository lookup still drops individual resource actions on current main. Keep this open while the existing staging fix candidate is reviewed; the earlier merged change did not resolve this reproduction.

## Change summary

Individual Stage Changes and Discard Changes actions fail for a submodule when its repository is closed in Source Control.

## Best solution

Review https://github.com/microsoft/vscode/pull/296975 against the closed-submodule reproduction, ensuring that individual staging, unstaging, and discard actions operate on the parent repository's submodule entry without changing ownership of files inside the submodule.

## Evidence

- **current-source failure path:** extensions/git/src/commands.ts:5751-5765, CommandCenter.runByRepository, first calls model.getRepository(resource) and drops the resource when no repository is found, before reaching getRepositoryForSubmodule. Model.getOpenRepository in extensions/git/src/model.ts:956-1000 excludes the parent when the resource matches a submodule root. extensions/git/src/util.ts:325-327 confirms isDescendant returns true for equal paths. With the child repository closed, neither repository resolves and no Git operation is dispatched.
- **affected commands:** extensions/git/src/commands.ts:1570-1580 sends individual staging resource URIs through runByRepository before repository.add. Individual revert and clean paths also use runByRepository, so the lookup failure is shared rather than a Git execution error.
- **confirmed reproduction and workarounds:** The discussion at https://github.com/microsoft/vscode/issues/205125 includes independent confirmations on Windows and Linux. On 2025-01-24 the maintainer confirmed that a closed submodule's head cannot be staged individually in the parent repository. Opening the submodule repository or staging everything works; the reporter also confirmed that bulk discard works while the individual action produces no Git output.
- **open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/296975 is OPEN with mergedAt null and explicitly references this issue. Its diff changes Model.getOpenRepository to exclude submodule descendants only when the resource is not the submodule root, addressing the traced staging lookup failure. It remains a candidate, not a landed fix, and its stated scope is staging.
- **previous fix was insufficient:** The context links merged https://github.com/microsoft/vscode/pull/236098. The reporter retested its advertised Insiders build and found the closed-submodule buttons still broken; another contributor confirmed unchanged behavior on main, and the issue was reopened. That earlier change cannot justify a completed close.

Verified https://github.com/microsoft/vscode/issues/134921 is open but concerns slow Git state updates, not individual actions being dropped for closed submodules; it is not a duplicate target.
