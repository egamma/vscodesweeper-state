# Issue #321918 — Gemma models return reasoning in `<thought>` tags – UI does not format/hide them

[https://github.com/microsoft/vscode/issues/321918](https://github.com/microsoft/vscode/issues/321918)

## Summary

Current main still treats Gemma reasoning embedded in `<thought>` tags as ordinary answer text, so the internal reasoning is rendered verbatim. This remains a valid BYOK parsing bug and should be routed to the custom-model area.

## Change summary

Recognize Gemma `<thought>...</thought>` output from custom endpoints as reasoning instead of displaying it in the final answer.

## Best solution

Define how tagged reasoning from thinking-capable custom models maps to the existing reasoning UI, then handle complete, fragmented, and unterminated `<thought>` blocks without changing ordinary answer text or structured reasoning fields.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/networking/node/stream.ts`, `extensions/copilot/src/platform/thinking/common/thinkingUtils.ts`, `extensions/copilot/src/platform/endpoint/test/node/stream.sseProcessor.spec.ts`, `extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts`
- **Validation:** Add SSE processor tests where `<thought>` content arrives in one chunk and across tag/token boundaries; assert it does not enter visible solution text, the final answer remains unchanged, and existing `reasoning_content` and `reasoning` cases still pass.
- **Behavior:**

  > When a configured thinking-capable Gemma custom endpoint emits reasoning inside `<thought>...</thought>`, that reasoning must not appear as raw final-answer text. The final answer after the closing tag must remain visible and unchanged. Streaming boundaries may split either tag or its contents, and ordinary responses that are not reasoning must retain their text.
- **Trace:**

  > Custom endpoints are created in extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts and their Chat Completions streams run through SSEProcessor in extensions/copilot/src/platform/networking/node/stream.ts. SSEProcessor calls extractThinkingDeltaFromChoice, whose recognized fields are defined in extensions/copilot/src/platform/thinking/common/thinkingUtils.ts; embedded tags are not among them. The fallback path appends `choice.delta.content` directly to APIJsonDataStreaming, which conclusively explains the raw tags and reasoning in the visible response. Existing structured-reasoning regression tests are in extensions/copilot/src/platform/endpoint/test/node/stream.sseProcessor.spec.ts. Preserve structured `reasoning_content`, `reasoning`, and `thinking` handling and do not reinterpret tag-like text from models outside the selected compatibility boundary. The younger https://github.com/microsoft/vscode/issues/323172 concerns a different structured-delta path and is not a canonical duplicate.
- **Open decisions:**
  - Should `<thought>` interpretation apply only to custom models explicitly configured with thinking support, to known Gemma models, or to every Chat Completions response?
  - Should tagged reasoning be exposed through the existing collapsible reasoning UI or removed entirely from the displayed response?
