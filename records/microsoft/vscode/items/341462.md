# Issue #341462 — Copilot CLI (Copilot SDK) agent sessions can't use visible VS Code terminals, so the user can't complete interactive auth (SSH/sudo passwords)

[https://github.com/microsoft/vscode/issues/341462](https://github.com/microsoft/vscode/issues/341462)

## Summary

Thanks for the detailed report. Copilot SDK sessions run commands in a hidden shell, so the user can't type into them for SSH, sudo or 2FA prompts. The Agent Host custom terminal tool covers part of this, but it is disabled on Windows. This is a valid gap that needs a design decision, and I found no verified duplicate.

## Change summary

Copilot CLI/SDK agent sessions need visible, interactive terminals, or a way for the user to type into the agent's shells, so interactive authentication can work.

## Best solution

Let Copilot sessions use visible, interactive terminals. Either enable the Agent Host custom terminal tool on Windows, or let the Background Shells preview accept input and open in the Terminal view. The second option may need SDK support for writing to a shell's input.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionSandbox.ts`, `src/vs/platform/agentHost/common/copilotCliConfig.ts`
- **Validation:** On Windows, a Copilot SDK session starts `ssh` in a visible terminal. The user can type a password there, and later agent commands reuse that authenticated session.
- **Behavior:**

  > A Copilot CLI/SDK session can run a command in a terminal the user can see and type into. The agent can send more input to that terminal and read its output. Acceptance: on Windows, an SSH or sudo password prompt can be answered in VS Code and the agent continues in the same session.
- **Trace:**

  > The Agent Host custom terminal tool creates real, revealable terminals. It is disabled on win32 in copilotSessionLauncher.ts:1135 and copilotSessionSandbox.ts:161, so Windows sessions use the SDK's hidden shell. The uncertainty starts at why Windows is excluded (PTY or sandbox constraints, possibly related to https://github.com/microsoft/vscode/issues/341333) and whether the SDK can write input to running shells. Do not change non-Windows behavior or the sandbox semantics.
- **Open decisions:**
  - Enable the custom terminal tool on Windows, or make the Background Shells preview interactive (forward keyboard input to the shell)?
  - Should shells started by the agent be revealed in the Terminal view by default or only on request?

## Evidence

- **Corroboration:** Two other users reproduce this on Windows (a comment on the issue). One of them is closing the duplicate #341717.
