## Summary

Thanks for the detailed report. The error comes from automodeService.ts, which throws when a turn has no prompt or command and no compatible cached session exists. The report is complete, but I could not confirm which request shape reaches that branch without running the code.

## Change summary

Auto mode throws 'needs a prompt or a command to route a request' on the second vscode.lm sendRequest in a tool-call loop from a chat participant.

## Best solution

Make auto-mode routing for vscode.lm.sendRequest follow-up requests reuse the cached session or the originating request's prompt, so tool-result-only turns do not throw. Fix in extensions/copilot/src/platform/endpoint/node/automodeService.ts or in the caller that builds the routing request.
