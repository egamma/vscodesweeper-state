# Issue #47783 — Command - Undo Replace All

[https://github.com/microsoft/vscode/issues/47783](https://github.com/microsoft/vscode/issues/47783)

## Summary

Keep open: cross-file undo already exists, but the requested Search-panel action remains missing. The reporter explicitly distinguished that gap from ordinary editor Undo; 66 upvotes and an existing duplicate support retaining this Backlog request.

## Change summary

Provide an Undo Replace All action in Search that reverses the replacement across affected files without requiring an affected editor to be active.

## Best solution

Expose a discoverable Search action for undoing the last Replace All operation, including changes to unopened files, while preserving existing workspace undo safeguards. Define its behavior when intervening edits prevent undoing the replacement as one operation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/searchView.ts`, `src/vs/workbench/contrib/search/browser/searchWidget.ts`, `src/vs/workbench/contrib/search/browser/replaceService.ts`, `src/vs/workbench/contrib/bulkEdit/browser/bulkTextEdits.ts`
- **Validation:** Exercise Replace All across several files with all affected editors closed, then with an unrelated editor active; invoke the Search undo action and verify every affected file is restored while unrelated edits remain unchanged. Add targeted Search tests for those cases and for the agreed behavior after intervening edits.
- **Behavior:**

  > Users can undo a Search Replace All operation from Search without locating or activating a changed file. The operation includes files that were not open when replacement occurred and does not silently undo unrelated work. Acceptance covers no affected editor being open, an unrelated editor being active, and intervening edits under the agreed undo policy.
- **Trace:**

  > ReplaceService.replace in src/vs/workbench/contrib/search/browser/replaceService.ts already submits all resource edits through IBulkEditService. BulkTextEdits.apply in src/vs/workbench/contrib/bulkEdit/browser/bulkTextEdits.ts creates a MultiModelEditStackElement for multiple affected models, so grouped undo infrastructure exists. SearchView.replaceAll in src/vs/workbench/contrib/search/browser/searchView.ts displays a completion message, while searchWidget.ts exposes Replace All but no corresponding undo action. The thread confirms that ordinary editor Undo can reverse changes to unopened files; the missing capability is invoking the relevant operation from Search independently of the active editor. Preserve existing workspace undo safety and ordinary editor Undo semantics. https://github.com/microsoft/vscode/issues/157533 is already consolidated into this request; uncertainty remains around selecting and enabling the Search action after subsequent edits.
- **Open decisions:**
  - When intervening edits prevent the last Replace All from being undone together, should the Search action be disabled, explain the blocking edits, or offer the existing workspace undo choices?
