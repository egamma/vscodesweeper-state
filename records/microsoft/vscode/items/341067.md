## Summary

Thanks for the automated report. The failure is still visible on main: the onDidRoute listener in reportAutoModeRouting pushes to the chat response stream with no guard. If a turn is cancelled or finished before routing resolves, the push throws 'Response stream has been closed', and the event emitter reports it as an unhandled error. It is a new bucket in 0.69.0 with 108 affected users.

## Change summary

An unguarded stream.push inside the auto-mode routing event listener throws 'Response stream has been closed' when the response stream has already been closed.

## Best solution

In the reportAutoModeRouting listener (automodeService.ts), skip pushing parts, or swallow the closed-stream error, once the request is cancelled or its stream has been closed. Routing state such as `tier` should still be tracked.
