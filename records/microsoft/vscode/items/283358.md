# Issue #283358 — Running tests should incrementally increase coverage rather than clearing coverage from other tests

[https://github.com/microsoft/vscode/issues/283358](https://github.com/microsoft/vscode/issues/283358)

## Summary

The requested accumulation remains missing, but an older, verified open issue already tracks the same observable behavior: coverage from a subsequent partial run replaces earlier coverage. Consolidate this report into that issue.

## Change summary

Preserve and accumulate coverage across separately executed test classes instead of requiring a full-suite rerun.

## Best solution

Track cross-run coverage accumulation in https://github.com/microsoft/vscode/issues/210509, carrying over this report's single-class workflow and Dart evidence. Resolve stale-file and coverage-reset semantics there before implementing accumulation.

Coverage actions in src/vs/workbench/contrib/testing/browser/testExplorerActions.ts run tests or open/clear a report; these surfaces do not provide cross-run accumulation.
- **Maintainer direction and unresolved semantics:** https://github.com/microsoft/vscode/issues/283358#issuecomment-3656505225 explicitly keeps this work tracked while noting a suspected existing issue. The older canonical's maintainer discussion at https://github.com/microsoft/vscode/issues/210509#issuecomment-2061732353 identifies stale coverage after file moves, renames, or deletion as a design concern. These support continued tracking, not a decline close.
- **Unique supporting workflow:** This report describes running test classes one by one while adding coverage. https://github.com/Dart-Code/Dart-Code/issues/5634 independently describes one package's coverage disappearing when another package's tests run; https://github.com/Dart-Code/Dart-Code/issues/5634#issuecomment-3664940622 directs that discussion to this VS Code request. Both are supporting cases for the canonical accumulation work.
- **Earlier clearing request is distinct:** https://github.com/microsoft/vscode/issues/202712 requested clearing coverage when rerunning a test without coverage. It does not implement or replace the request to accumulate results from successive coverage-enabled runs.
