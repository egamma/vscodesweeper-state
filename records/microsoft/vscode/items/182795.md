# Issue #182795 — Simple browser will be opened multiple times with race

[https://github.com/microsoft/vscode/issues/182795](https://github.com/microsoft/vscode/issues/182795)

## Summary

Keep open: the Simple Browser fallback still permits a newly created panel and a restored panel to coexist, and several explicitly linked fix proposals remain open. Review those proposals against the reload scenario rather than starting another implementation.

## Change summary

Prevent duplicate Simple Browser panels when an activation-time open command runs before restoration of an existing background tab.

## Best solution

Review the existing PRs and land a fix that preserves a single Simple Browser panel while honoring the requested navigation during restoration. Evaluate the actual reload ordering, not only repeated synchronous calls to show(), and avoid identifying panels by their display title.

## Evidence

- **Current source retains the duplicate-panel path:** In extensions/simple-browser/src/simpleBrowserManager.ts, show() creates a panel whenever _activeView is undefined. If restore() follows, it wraps the existing restored panel and registers its listeners, but `_activeView ??= view` retains the newly created view without disposing either panel. SimpleBrowserView.restore() in extensions/simple-browser/src/simpleBrowserView.ts constructs a separate wrapper whose constructor calls show(), leaving both panels present.
- **Current command routing narrows but does not eliminate the defect:** extensions/simple-browser/src/extension.ts now forwards simpleBrowser.api.open to workbench.action.browser.open when that command is available. Otherwise it still calls manager.show(), while deserializeWebviewPanel independently calls manager.restore(). The retained fallback and serializer therefore still contain the reported ordering defect; this review did not execute the desktop reload scenario.
- **Discussion confirms the reported trigger:** The discussion at https://github.com/microsoft/vscode/issues/182795 includes an independent reproduction on June 19, 2024: reload with another tab focused, invoke the browser command before the old browser tab restores, and observe duplicate tabs. Later discussion also explains why matching a tab named 'Simple Browser' can mistake an ordinary file for a browser panel. The January 2026 non-reproduction comment supplies no evidence that this specific ordering was eliminated.
- **Open implementation candidates:** Verified OPEN: https://github.com/microsoft/vscode/pull/197188, https://github.com/microsoft/vscode/pull/285633, https://github.com/microsoft/vscode/pull/298545, and https://github.com/microsoft/vscode/pull/324379. Their bodies explicitly reference this issue. The proposals address different mechanisms, so an open PR is evidence of pending work, not proof of a completed fix.
