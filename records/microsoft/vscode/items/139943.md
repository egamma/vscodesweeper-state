# Issue #139943 — Filtering snippets in IntelliSense

[https://github.com/microsoft/vscode/issues/139943](https://github.com/microsoft/vscode/issues/139943)

## Summary

Dot-separated snippet navigation remains blocked by an intentional trigger-character restriction in current source. Keep this improvement open: the maintainer raised relaxing that restriction, and the matching open report is newer, so it cannot replace this re-reviewed issue.

## Change summary

Allow IntelliSense to continue filtering dot-separated snippet prefixes when typing a dot triggers language completions.

## Best solution

Support continued navigation of matching hierarchical snippet prefixes without reintroducing unrelated snippets after language trigger characters. Settle the matching semantics in the snippets completion area, informed by the reverted attempt documented in https://github.com/microsoft/vscode/issues/145960.

- **Behavior:**

  > The reporter organizes snippets using dot-separated prefixes such as px.fig.histogram and px.read.csv. Typing successive prefix segments should preserve useful IntelliSense navigation instead of removing matching snippets at each dot. The resulting behavior must avoid unrelated snippet suggestions when punctuation legitimately triggers language completions. Acceptance should cover both hierarchical filtering and suppression of unwanted snippets; Ctrl+Space and Insert Snippet must remain usable.
- **Trace:**

  > SnippetCompletionProvider.provideCompletionItems in src/vs/workbench/contrib/snippets/browser/snippetCompletionProvider.ts rejects TriggerCharacter requests whenever snippet.prefixLow does not start with context.triggerCharacter, before evaluating snippet anchors. SuggestModel._updateTriggerCharacters in src/vs/editor/contrib/suggest/browser/suggestModel.ts includes the snippet provider when a language provider registers a trigger and recomputes those items on typing. This directly explains why the supplied px.* snippets are excluded on a dot request; no runtime execution was performed. The restriction intentionally prevents unwanted snippets, with active quote-trigger tests in src/vs/workbench/contrib/snippets/test/browser/snippetsService.test.ts. The same file has a skipped dot-prefix regression test associated with https://github.com/microsoft/vscode/issues/145960, whose attempted relaxation was reopened for unwanted completions. Preserve normal language completion behavior and existing suppression guarantees; the uncertainty is the observable eligibility rule for prefixes containing, rather than beginning with, a trigger character.
- **Open decisions:**
  - Should embedded trigger characters keep snippets eligible only while continuing an already matching prefix, or also when opening a fresh completion session, and what matching condition excludes unrelated snippets?
