[https://github.com/microsoft/vscode/issues/339264](https://github.com/microsoft/vscode/issues/339264)

## Summary

Keep open: current remote main creates Windows junctions for this setting and delegates removal to Git without first unlinking them, but source inspection alone cannot confirm the reported target deletion. The checkout predates the setting's introduction; the supplied Windows steps suffice to retest the newer implementation.

## Change summary

Removing a worktree containing folders shared through git.worktreeSymlinkFolders reportedly deletes the original folders and their contents on Windows.

## Best solution

Ensure worktree removal preserves every shared target directory and its contents. First reproduce the Windows junction case and distinguish a VS Code cleanup gap from Git for Windows removal behavior before choosing the fix boundary.
