# Issue #249427 — Extension signature verification is failing with error code 137

[https://github.com/microsoft/vscode/issues/249427](https://github.com/microsoft/vscode/issues/249427)

## Summary

Keep this canonical issue open: current VS Code still delegates verification to the bundled .NET-based `vsce-sign`, while the CoreCLR virtual-address reservation defect remains open upstream. Later reports of the same error were explicitly consolidated here.

## Change summary

Extension installation fails with internal code 137 when CoreCLR cannot reserve the large virtual address range requested while starting `vsce-sign` on constrained Linux hosts.

## Best solution

Track https://github.com/dotnet/runtime/issues/85556 and adopt a `vsce-sign` build containing a complete upstream runtime fix once available; until then, retain the documented `DOTNET_GCHeapHardLimit` or virtual-memory-limit workarounds and consider verifier fallback behavior separately.
