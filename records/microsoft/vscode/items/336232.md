# Issue #336232 — ${env:VAR} is not substituted in mcp.json server headers

[https://github.com/microsoft/vscode/issues/336232](https://github.com/microsoft/vscode/issues/336232)

## Summary

Confirmed in source: the workspace-root `.mcp.json` (the newer "portable" format) is read by `WorkspaceDotMcpDiscovery` via `claudeConfigToServerDefinition`, which never sets `variableReplacement` on the resulting server definitions, so `McpRegistry._replaceVariablesInLaunch` short-circuits and nothing — not just headers, nothing at all — gets substituted for that file; `.vscode/mcp.json` and user `mcp.json` go through `InstalledMcpServersDiscovery`, which does wire up `variableReplacement` and works correctly.

## Change summary

`${env:VAR}` (and other `${...}` variables) inside `headers` of a root-level `.mcp.json` server entry are sent to the MCP server literally instead of being resolved.

## Best solution

Give workspace-root `.mcp.json` the same variable-resolution path as `.vscode/mcp.json`/user `mcp.json` (set `variableReplacement` for definitions produced by `claudeConfigToServerDefinition` in workspaceDotMcpDiscovery.ts, or implement the portable-format `${NAME}`/`${NAME:-default}` syntax), or clearly document that the root `.mcp.json` format doesn't resolve variables yet. This overlaps the broader design work already underway in microsoft/vscode#340161, which maps out exactly which variable kinds the portable format can and can't support (including header values, case C8).

## Evidence

- **no variableReplacement for root .mcp.json:** src/vs/workbench/contrib/mcp/common/discovery/workspaceDotMcpDiscovery.ts builds definitions via claudeConfigToServerDefinition(...) with no `variableReplacement` field set, unlike src/vs/workbench/contrib/mcp/common/discovery/installedMcpServersDiscovery.ts:103 which does set it for .vscode/mcp.json and user mcp.json.
- **resolver short-circuits:** src/vs/workbench/contrib/mcp/common/mcpRegistry.ts:462 `_replaceVariablesInLaunch` returns the launch unchanged `if (!definition.variableReplacement)`, so any `${...}` in headers (or anywhere else) from the root .mcp.json path is left literal.
