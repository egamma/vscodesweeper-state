# Issue #157343 — Add support for a border below section headers in Sidebar and Panel

[https://github.com/microsoft/vscode/issues/157343](https://github.com/microsoft/vscode/issues/157343)

## Summary

The optional section-header bottom border remains unsupported on current main, and the linked implementation PR closed without merging. Keep this under discussion: a maintainer conditionally accepted the capability, and no verified canonical issue absorbs it.

## Change summary

Allow themes to add a border below individual Sidebar and Panel section headers without changing default themes.

## Best solution

Provide an opt-in theme-color capability for section-header bottom borders while preserving existing separator colors, default appearance, and keyboard-focus visibility. Settle the public color contract and its relationship to topmost-view borders before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/common/theme.ts`, `src/vs/workbench/browser/parts/views/viewPaneContainer.ts`, `src/vs/base/browser/ui/splitview/paneview.ts`, `src/vs/workbench/browser/parts/views/media/paneviewlet.css`
- **Validation:** With a theme that opts into the agreed bottom-border colors, inspect multiple stacked Sidebar and Panel views, including the topmost view and expanded/collapsed states. Verify borders appear below the intended headers, keyboard-focus indicators remain distinct, and removing the opt-in colors restores the previous appearance in light, dark, and high-contrast themes.
- **Behavior:**

  > Theme authors cannot currently draw an optional border below individual Sidebar and Panel section headers using supported theme colors. The requested capability should distinguish each header from its content without changing default themes or existing separator-color behavior. Acceptance checks should cover stacked views, the topmost header, expanded and collapsed states, and visible keyboard focus. Borders below the overall Sidebar or Panel title are a related but separate capability.
- **Trace:**

  > ViewPaneContainer in src/vs/workbench/browser/parts/views/viewPaneContainer.ts maps the existing section-header colors from src/vs/workbench/common/theme.ts to headerBorder. Pane.updateHeader in src/vs/base/browser/ui/splitview/paneview.ts uses that value only for a vertical pane's borderTop, while src/vs/workbench/browser/parts/views/media/paneviewlet.css suppresses the first view's top border. The proposed bottom-border plumbing in https://github.com/microsoft/vscode/pull/157344 never merged and is absent from current source. The maintainer's conditional acceptance at https://github.com/microsoft/vscode/issues/157343#issuecomment-1212294482 establishes that default themes and existing theme compatibility must be preserved. Uncertainty remains around the supported public color names and whether topmost-header borders are independent of the separately requested title divider in https://github.com/microsoft/vscode/issues/157312; do not treat that closed request as a duplicate or silently expand this one's scope.
- **Open decisions:**
  - Should bottom borders have independently configurable public theme colors, such as sideBarSectionHeader.borderBottom and panelSectionHeader.borderBottom, while the existing .border colors retain their current separator behavior?
  - Should opting into bottom borders affect every section header, including the topmost view, independently of the separate capability to draw a divider below the overall Sidebar or Panel title?
