# Issue #335244 — GitHub Copilot: camelCase subagentStart hook is silently ignored

[https://github.com/microsoft/vscode/issues/335244](https://github.com/microsoft/vscode/issues/335244)

## Summary

Confirmed on main: the GitHub Copilot hook-name maps in hookTypes.ts and pluginParsers.ts omit the documented camelCase keys `subagentStart` and `preCompact`, so hooks configured with those exact GitHub Copilot doc names are silently dropped by parseHooksJson while the PascalCase spellings work.

## Change summary

A `.github/hooks` hook configured with the documented camelCase event name `subagentStart` (and likely `preCompact`) is silently ignored by VS Code's GitHub Copilot hook parser.

## Best solution

Add `'subagentStart': HookType.SubagentStart` and `'preCompact': HookType.PreCompact` to `HOOKS_BY_TARGET[Target.GitHubCopilot]` in hookTypes.ts and to `HOOK_TYPE_MAP` in pluginParsers.ts (mirroring the existing camelCase entries like `subagentStop`/`agentStop`), and add a unit test asserting every `HookType` enum member has a camelCase GitHub Copilot alias in both tables so this class of omission is caught going forward.
