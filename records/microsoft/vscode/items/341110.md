# Issue #341110 — Markdown editor: Undo reverts one character at a time

[https://github.com/microsoft/vscode/issues/341110](https://github.com/microsoft/vscode/issues/341110)

## Summary

Thanks for the report. This is consistent with the source: every webview edit is applied as its own WorkspaceEdit with default undo stops, so typing is never coalesced into word-level undo steps. The report is a new, team-adjacent test finding for the Markdown Editor, and it stays open.

## Change summary

Typing in the Markdown Editor creates one undo step per character instead of coalescing like the Text Editor.

## Best solution

Coalesce consecutive typing edits into word-level undo groups in the Markdown editor edit path. Alternatively, route the history chords through an undo model that groups edits.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/src/preview/markdownEditorProvider.ts`, `extensions/markdown-language-features/markdown-editor-src/editor.ts`
- **Validation:** Extension test in src/test/markdownEditorBridge.test.ts: type a multi-word phrase through the bridge, run one undo, and assert that only the last word is removed.
- **Behavior:**

  > Typing a phrase at normal speed in the Markdown Editor and pressing undo removes one word at a time, as in the Text Editor. Explicit pauses, newlines and non-typing edits still create separate undo steps. Redo mirrors undo.
- **Trace:**

  > Each webview edit in markdownEditorProvider.ts is applied through vscode.workspace.applyEdit, so the TextDocument records one undo element per keystroke. editor.ts routes the undo/redo chords to the TextDocument through `historyStrategy`. The boundary is that the TextDocument stays the single source of truth for history; do not add a second local undo stack. The uncertainty is that the extension API offers no undo-coalescing control for WorkspaceEdit, so the design may need batching in the webview or an API gap.
- **Open decisions:**
  - Coalesce by batching keystrokes into one WorkspaceEdit in the webview, or request an extension API for undo stops?
  - What grouping boundaries should apply (word, pause duration, paragraph)?

## Evidence

- **edit path:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts (~lines 591-625): each webview `edit` message becomes a `vscode.workspace.applyEdit(new WorkspaceEdit().replace(...))`, so each keystroke is a separate undo element on the TextDocument.
- **undo routing:** markdown-editor-src/editor.ts (~lines 445-455) delegates undo/redo to the TextDocument's own stack via `history`, so the per-edit granularity is not coalesced anywhere.
