# Issue #349353 — Sessions: per-session policy config reads deep-clone the full configuration; each agent-host notification blocks the renderer up to ~1.6 s

[https://github.com/microsoft/vscode/issues/349353](https://github.com/microsoft/vscode/issues/349353)

## Summary

The reported amplification remains in current source: session enumeration repeats policy inspections that clone the consolidated configuration, and recent-session lookups multiply those enumerations. Keep this open; the source confirms the mechanism, although the reported timings were not independently measured.

## Change summary

Eliminate repeated full-configuration cloning during policy-gated session enumeration and notification-driven lookups.

## Best solution

Make session enumeration and lookup costs independent of repeated policy evaluation for each cached session, while preserving readable policy-disabled history and current enforcement. Assess the shared configuration read cost separately so caller-side improvements do not leave the platform bottleneck unaddressed.
