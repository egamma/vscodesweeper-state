# Issue #335229 — MCP task with status "failed" never calls tasks/result, discarding the tool result payload (structuredContent)

[https://github.com/microsoft/vscode/issues/335229](https://github.com/microsoft/vscode/issues/335229)

## Summary

The reported payload loss remains directly reproducible from current source: a failed MCP task rejects before requesting its underlying result. Keep this open as a bounded protocol-handling bug; the related background-task UX issue does not own this symptom.

## Change summary

Preserve the underlying MCP tool result, including structured diagnostics, when a task reaches failed status.

## Best solution

Failed tasks should expose the underlying tasks/result response through the existing tool-result pipeline, preserving isError and structuredContent while retaining genuine JSON-RPC errors as errors. Keep task backgrounding and content-selection policy outside this correction.
