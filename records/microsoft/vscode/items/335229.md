# Issue #335229 — MCP task with status "failed" never calls tasks/result, discarding the tool result payload (structuredContent)

[https://github.com/microsoft/vscode/issues/335229](https://github.com/microsoft/vscode/issues/335229)

## Summary

Confirmed on current main: `McpTask`'s status-handling autorun rejects immediately on `failed` without calling `getTaskResult`, discarding any `structuredContent`/`content` payload the server attached — a real, well-diagnosed bug with a clear fix boundary.

## Change summary

When an MCP task reaches terminal status `failed`, VS Code rejects with only `statusMessage` and never calls `tasks/result`, so the underlying `CallToolResult` payload (e.g. `structuredContent` with build diagnostics) is lost.

## Best solution

In `McpTask`'s status autorun (src/vs/workbench/contrib/mcp/common/mcpServerRequestHandler.ts, ~line 708), mirror the `completed` branch: call `handler.getTaskResult({ taskId: _task.taskId }, _token)` on `failed` too, and settle/reject using the real `CallToolResult` (respecting `isError`) instead of a synthetic Error built only from `statusMessage`.
