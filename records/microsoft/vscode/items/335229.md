# Issue #335229 — MCP task with status "failed" never calls tasks/result, discarding the tool result payload (structuredContent)

[https://github.com/microsoft/vscode/issues/335229](https://github.com/microsoft/vscode/issues/335229)

## Summary

Confirmed in the current source: `McpTask`'s status autorun rejects immediately on `failed` using only `statusMessage`, never calling `getTaskResult`, so any structured payload (`structuredContent`, `content`) the server attached to a failed task is discarded — matching the reporter's spec citation exactly.

## Change summary

When an MCP task reaches terminal status "failed", VS Code never calls `tasks/result`, so the underlying `CallToolResult` payload (structuredContent, content, isError) is lost instead of surfaced to the model.

## Best solution

In `McpTask`'s status autorun in mcpServerRequestHandler.ts, treat `failed` like `completed`: call `handler.getTaskResult(...)` and settle the promise with (or attach) that result instead of synthesizing a bare Error from `statusMessage` alone, so `isError: true` results and their structured payload reach the caller.
