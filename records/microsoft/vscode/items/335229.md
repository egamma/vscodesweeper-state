# Issue #335229 — MCP task with status "failed" never calls tasks/result, discarding the tool result payload (structuredContent)

[https://github.com/microsoft/vscode/issues/335229](https://github.com/microsoft/vscode/issues/335229)

## Summary

The reported defect remains in current main: failed MCP tasks reject without retrieving their underlying result, preventing structured diagnostics from reaching the model. Keep this open as a bounded protocol-handling bug, distinct from the related background-task UX request.

## Change summary

Preserve the underlying tool result, including error content and structuredContent, when an MCP task reaches failed status.

## Best solution

Failed task-backed tool calls should expose the same CallToolResult that a non-task invocation would return, preserving isError, content, and structuredContent while still propagating genuine JSON-RPC errors. Existing completion, cancellation, and task-lifecycle behavior should remain unchanged.
