## Summary

Keep open while the Chromium keyboard-identity regression and the linked terminal workaround are evaluated. The fixing PR remains open, and the older editor numpad-Delete report does not cover this enhanced-keyboard TUI symptom.

## Change summary

Restore numpad input in integrated-terminal TUI applications that enable enhanced keyboard reporting.

## Best solution

Review https://github.com/microsoft/vscode/pull/299408 against the reported Windows TUI scenario and determine whether its compatibility workaround is appropriate while the upstream keyboard mapping is corrected. Resolution must preserve numpad digits, Enter, decimal and operators under enhanced keyboard reporting, not merely restore ordinary shell input.

- **Open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/299408 is OPEN, has no merge timestamp, and explicitly says Fixes #299374. Its proposed workaround normalizes Unidentified numpad events before xterm.js processes them; its author reports successful manual TUI checks. This is an existing human-owned implementation lane, not a completed fix.
- **Current terminal integration:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1157-1218 passes the original KeyboardEvent through attachCustomKeyEventHandler without the proposed Unidentified/Numpad normalization. src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:281 and :623 forwards enableKittyKeyboardProtocol to xterm.js. These observations establish the relevant integration boundary, not a conclusive reproduction of the browser-dependent failure.
- **Existing workaround is not full coverage:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:604-609 registers terminal.integrated.enableKittyKeyboardProtocol with default true. Disabling enhanced reporting changes the application's available keyboard semantics rather than satisfying the request to retain working numpad input with that protocol enabled.

A September comment on https://github.com/microsoft/vscode/issues/283460 claims a Chromium 152 fix, but that concerns the related Delete report and supplies neither a fixing commit nor proof that the Windows enhanced-keyboard TUI path is resolved in this checkout.
