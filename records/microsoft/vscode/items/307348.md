# Issue #307348 — Chat session permanently unloadable after VS Code killed mid-response (TypeError: Cannot read properties of undefined (reading 'response'))

[https://github.com/microsoft/vscode/issues/307348](https://github.com/microsoft/vscode/issues/307348)

## Summary

Still reproduces on main: when VS Code is killed mid-streaming-response, the session .jsonl contains an incomplete request entry (no response property). On next load, `ChatSessionOperationLog.read()` replays the Set entry through `objectMutationLog.ts` schema extraction, which accesses `.response` properties on an undefined value, throwing a TypeError caught by the outer catch block at chatSessionStore.ts:690–692, permanently discarding the session. No fix has merged.

## Change summary

Chat session becomes permanently unloadable after VS Code is killed during a streaming response, because the deserialization path does not guard against requests with missing response data.

## Best solution

Guard the deserialization path in `chatSessionStore.ts` (and/or `chatSessionOperationLog.ts` schema extraction) to handle requests where `response` is undefined — either skip incomplete requests or provide a default empty/cancelled response. The open PR https://github.com/microsoft/vscode/pull/309286 addresses a related write-side failure but does not fix this read-side crash; both should land.
