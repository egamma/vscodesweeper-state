# Issue #307348 — Chat session permanently unloadable after VS Code killed mid-response (TypeError: Cannot read properties of undefined (reading 'response'))

[https://github.com/microsoft/vscode/issues/307348](https://github.com/microsoft/vscode/issues/307348)

## Summary

The recovery gap remains on current main: any exception while replaying or reviving a session causes ChatSessionStore to return undefined, leaving the indexed history entry unloadable without salvaging completed turns. The related older issue reports a different corruption mechanism, and the broader recovery issue is younger, so neither clears the stronger duplicate bar for this re-reviewed item.

## Change summary

Recover completed chat turns when VS Code is terminated while the session log contains an incomplete in-flight request.

## Best solution

Make chat-session restoration tolerate or truncate an incomplete trailing request while preserving completed requests, with a regression fixture representing an interrupted JSONL stream. Recovery should avoid silently returning an unusable history entry.

## Evidence

- **confirmed failure:** The report includes repeatable termination steps and a renderer log showing ChatSessionStore rejecting the session as malformed with `Cannot read properties of undefined (reading 'response')`; another user reports losing a 172-message session after an interruption.
- **current source:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts:680-710 still wraps replay and revival in one try/catch and returns undefined for the entire session on any exception; it has no partial-tail recovery.
- **persistence schema:** src/vs/workbench/contrib/chat/common/model/chatSessionOperationLog.ts:137-178 permits request serialization while `m.response` is absent, and seals requests only after a terminal model state, so interruption can leave an unsealed request representation.
