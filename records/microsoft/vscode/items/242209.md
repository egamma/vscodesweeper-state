## Evidence

- **error source:** The error originates from src/vs/workbench/api/common/extHostCommands.ts:316 — `$executeContributedCommand` rejects because `editor.action.clipboardCopyAction` is registered as an editor action on the renderer side (src/vs/editor/contrib/clipboard/browser/clipboard.ts:79), not as a contributed command in the extension host.
- **related fix:** Commit 13450f968960f47cda472a5e76edbfc6d9724146 (June 2025, PR #251761) fixed notebook clipboard actions to properly check `editor.hasEditorFocus()` before running, which may have resolved a focus-routing path that could cause the command to go through the wrong dispatch channel.
- **unclear repro:** Original reporter uses Jupyter Extension 2024.11.0 on VS Code 1.96.4; commenter 1 says it happens with plain markdown files (no notebooks); commenter 2 confirms in Jupyter notebooks. The conflicting scenarios make root-cause identification difficult without more detail.
- **notebook clipboard architecture:** src/vs/workbench/contrib/notebook/browser/contrib/clipboard/notebookClipboard.ts adds implementations to CopyAction at priority 105. If the notebook implementation returns false (bypasses), the editor action chain should still handle it on the renderer side — the extension host path should never be involved for this command ID.
