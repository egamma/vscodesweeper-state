# Issue #185634 — Pass http.proxyAuthorization in extension requests

[https://github.com/microsoft/vscode/issues/185634](https://github.com/microsoft/vscode/issues/185634)

## Summary

The gap remains on current main: core requests consume `http.proxyAuthorization`, but extension-host requests do not pass that setting into `@vscode/proxy-agent`. The older extension-proxy issue is broader and does not report this same setting-specific symptom, so it is not a valid duplicate for this re-reviewed item.

## Change summary

Apply the configured `http.proxyAuthorization` value to HTTP requests made through the extension host's patched networking APIs.

## Best solution

Make the extension-host proxy authorization lookup honor `http.proxyAuthorization` consistently across the HTTP, HTTPS, fetch, and WebSocket paths patched by `@vscode/proxy-agent`, while preserving the existing Kerberos and interactive Basic-authentication fallbacks.

## Evidence

- **core request behavior:** src/vs/platform/request/node/requestService.ts reads `http.proxyAuthorization` during configuration and adds it as the `Proxy-Authorization` header for core Node requests.
