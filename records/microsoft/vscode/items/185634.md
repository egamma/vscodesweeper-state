# Issue #185634 — Pass http.proxyAuthorization in extension requests

[https://github.com/microsoft/vscode/issues/185634](https://github.com/microsoft/vscode/issues/185634)

## Summary

Still open on main: the `lookupProxyAuthorization` callback in `src/vs/workbench/api/node/proxyResolver.ts` handles Kerberos and Basic auth challenges but never falls back to the static `http.proxyAuthorization` setting value. Extensions making HTTP requests through the patched http/https modules don't get this header, while VS Code's own request service does.

## Change summary

Extension HTTP requests via @vscode/proxy-agent do not include the user-configured `http.proxyAuthorization` header value.

## Best solution

In `src/vs/workbench/api/node/proxyResolver.ts`, the `lookupProxyAuthorization` callback should fall back to reading `http.proxyAuthorization` from `configProvider` (similar to how the node request service does it in `src/vs/platform/request/node/requestService.ts:86`) when no Kerberos/Basic auth succeeds and the first call has no `proxyAuthenticate` challenge.
