# Issue #309828 — Option to disable auto “Jump to next edit” after approving a Copilot/AI edit (not file-based)

[https://github.com/microsoft/vscode/issues/309828](https://github.com/microsoft/vscode/issues/309828)

## Summary

Keep open: the existing setting suppresses automatic file transitions, but individual Keep actions still navigate within the file. This request has 11 upvotes and corroborating feedback; no verified older canonical covers the remaining behavior.

## Change summary

Allow approving an individual Copilot edit without automatically moving the cursor or viewport to another edit or file.

## Best solution

Provide an opt-out from automatic navigation after individual chat-edit approval while preserving explicit navigation commands and the current default. Decide whether the existing setting should cover both navigation scopes or whether users need independent controls.

- **Behavior:**

  > Users can approve an individual chat-generated change without losing their cursor or viewport context to automatic navigation. The opt-out must cover remaining changes in the same file and transitions after the final change in a file. Explicit Next and Previous commands remain usable, and the current automatic-navigation default remains unchanged. Acceptance checks should exercise mouse and keyboard approval with multiple hunks and multiple files.
- **Trace:**

  > ChatEditingEditorAction resolves the active entry and its editor integration; AcceptRejectHunkAction invokes acceptNearestChange before consulting chat.editing.revealNextChangeOnResolve for the final-hunk file transition. In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts, acceptNearestChange unconditionally calls next(true), whose _reveal path changes the editor position to another tracked change. The existing setting therefore cannot suppress same-file navigation. Notebook integrations have their own acceptNearestChange and navigation paths, so their coverage must be established rather than assumed. Preserve explicit navigation and existing defaults; do not conflate chat-edit review with inline completion or next-edit-suggestion acceptance. The predecessor discussion at https://github.com/microsoft/vscode/issues/298434 confirms that the file-only implementation left the central request unmet. The newer feedback umbrella https://github.com/microsoft/vscode/issues/339363 provides product context but is not a duplicate canonical.
- **Open decisions:**
  - Should chat.editing.revealNextChangeOnResolve control both same-file and cross-file navigation, or should users be able to configure those behaviors independently?
  - Should the opt-out apply to both Keep and Undo, as the existing setting does, or only to approval?
  - Should the initial contract cover chat-edit hunk review, including notebooks, or also distinct inline-completion and next-edit-suggestion acceptance flows?
