# Issue #309828 — Option to disable auto “Jump to next edit” after approving a Copilot/AI edit (not file-based)

[https://github.com/microsoft/vscode/issues/309828](https://github.com/microsoft/vscode/issues/309828)

## Summary

Valid feature request: the existing `chat.editing.revealNextChangeOnResolve` setting (PR #303473, from the predecessor issue #298434) only controls auto-jump after keep/undo in the chat editing review flow. It does not cover the inline edit / next edit suggestions (NES) accept flow, which still auto-jumps to the next edit within the same file after accept. This issue asks for that remaining gap to be addressed.

## Change summary

Add an option to disable automatic jump-to-next-edit within the same file after accepting an inline/NES suggestion.

## Best solution

Add a setting (e.g. under `editor.inlineSuggest.edits.*`) that suppresses the within-file auto-jump after accepting an inline edit suggestion. The accept flow in `src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts` sets `_inAcceptFlow` to `true` (line ~1012) which drives automatic re-trigger and Tab-jump behavior; a new setting would gate that so the cursor stays put. The chat editing setting (`chat.editing.revealNextChangeOnResolve`) already covers the between-file agent-edit review case, so only the NES/inline-edit path needs this addition.
