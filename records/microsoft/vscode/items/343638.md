# Issue #343638 — Preserve deterministic BYOK provider errors across the Agent Host bridge

[https://github.com/microsoft/vscode/issues/343638](https://github.com/microsoft/vscode/issues/343638)

## Summary

Keep open: current source confirms that the BYOK bridge discards provider error classification and unconditionally returns HTTP 502 for failed requests. This is a concrete VS Code bridge defect, distinct from the generic no-response meta issue.

## Change summary

Preserve deterministic BYOK provider error classifications across the Agent Host bridge so invalid requests do not become retryable HTTP 502 failures.

## Best solution

Known deterministic provider failures should reach the Responses client as non-retryable 4xx errors, while unknown errors, transport failures, and upstream 5xx failures retain the existing 502 recovery path. Cover both request-start and streaming failures without changing successful completions or continuation handling.
