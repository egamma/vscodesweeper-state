# Issue #194377 — Can not accept current file in Git view

[https://github.com/microsoft/vscode/issues/194377](https://github.com/microsoft/vscode/issues/194377)

## Summary

Keep open: the recording shows a deleted-file conflict, and the current SCM acceptance commands still silently skip files without textual conflict markers. Stage Changes provides a keep/delete workaround, but does not fix the advertised acceptance action.

## Change summary

Accept All Current in the Source Control view does nothing for a modify/delete conflict.

## Best solution

Make SCM acceptance actions handle modify/delete conflicts explicitly rather than silently applying an empty edit. Preserve ordinary text-conflict behavior and use the Git area's existing deletion-resolution semantics as the reference.

- **Trace:**

  > The recording on https://github.com/microsoft/vscode/issues/194377 identifies a struck-through CMake file under Merge Changes and selection of Accept All Current. extensions/merge-conflict/package.json offers the action for every Git merge resource. CommandHandler.registerTextEditorCommand in extensions/merge-conflict/src/commandHandler.ts routes resource arguments to acceptAllResources, which only edits parsed textual conflicts and silently skips documents with none. Modify/delete conflicts therefore produce no edits; MergeConflictParser in extensions/merge-conflict/src/mergeConflictParser.ts recognizes markers rather than Git conflict states. CommandCenter.stage and _stageDeletionConflict in extensions/git/src/commands.ts already resolve deletion conflicts through keep/delete choices and repository.add or repository.rm. The unresolved boundary is how SCM acceptance should interact with Git index resolution; do not expand this issue into binary-file support, submodule resolution, or changes to ordinary text-conflict acceptance.
- **Open decisions:**
  - For modify/delete conflicts, should Accept All Current/Incoming immediately resolve and stage the selected side, or lead into the existing explicit keep/delete staging flow?

- **Current command registration:** extensions/merge-conflict/package.json exposes merge-conflict.accept.all-current and merge-conflict.accept.all-incoming whenever scmProvider == git && scmResourceGroup == merge, without excluding deletion conflicts.
- **Source-confirmed no-op:** In extensions/merge-conflict/src/commandHandler.ts, registerTextEditorCommand routes SCM resources to acceptAllCurrentResources, then acceptAllResources. That method opens text documents, skips every document with no parsed conflicts, and applies the resulting empty WorkspaceEdit. extensions/merge-conflict/src/mergeConflictParser.ts recognizes textual conflict markers only; modify/delete conflicts have no such blocks. No Git keep/delete resolution occurs on this path.
- **Existing workaround is a separate action:** extensions/git/src/commands.ts routes git.stage deletion conflicts through CommandCenter._stageDeletionConflict. DELETED_BY_THEM offers Keep Our Version or Delete File; DELETED_BY_US offers Keep Their Version or Delete File, using repository.add or repository.rm. This resolves deletion conflicts through Stage Changes, not through the action reported here.
