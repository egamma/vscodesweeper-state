# Issue #267606 — Git - better support for bare repositories

[https://github.com/microsoft/vscode/issues/267606](https://github.com/microsoft/vscode/issues/267606)

## Summary

Keep open: current source still prevents sibling discovery from a linked worktree and lacks the correct bare-repository hierarchy. The related issues and open PRs cover portions of the discussion, not the full bare-repository problem.

## Change summary

Recognize linked worktrees belonging to a bare repository and present their repository relationship correctly in Source Control.

## Best solution

Support bare-repository identity and linked-worktree discovery without requiring a primary working tree, while honoring detection settings and explicit repository closure. Review the existing worktree PRs for their overlapping changes; retain this issue for the bare-specific gap and investigate the later Windows over-detection report separately.

## Evidence

- **Source-confirmed discovery gap:** For the reporter's trigger—opening agents.md.git/trees/test-branch—extensions/git/src/git.ts:1378 classifies the repository as a worktree because it has a commonPath. extensions/git/src/model.ts:806-815 returns from checkForWorktrees for that kind, even when git.detectWorktrees is enabled, so the sibling-discovery loop is never reached.
- **Bare hierarchy remains unsupported:** extensions/git/src/repository.ts:963-973 derives the parent SCM root as dirname(commonPath), rather than the bare common directory. Git.getRepositoryRoot in extensions/git/src/git.ts:510-511 uses rev-parse --show-toplevel, which requires a working tree; getWorktreesFS at lines 3087-3101 deliberately omits the main-worktree entry for bare repositories. These paths do not establish a bare parent repository for the reported hierarchy.
- **Existing support is partial:** extensions/git/src/git.ts:3104-3130 can enumerate linked worktrees from the common directory, and extensions/git/src/repository.ts:996-999 uses the bare commonPath for activeRepositoryName. Neither capability removes the Model discovery guard or supplies the missing SCM parent.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/267692 is open and addresses hierarchy discovery from non-primary worktrees. Its body explicitly states that it still does not support the bare-repository hierarchy reported in https://github.com/microsoft/vscode/issues/267606; it is not a completed fix, and overlapping implementation should not compete with that PR.
- **Canonical search:** https://github.com/microsoft/vscode/issues/259083 is older and open, but concerns creating a worktree from another worktree and does not own the full bare-parent hierarchy or settings/closure behavior. https://github.com/microsoft/vscode/issues/260948 contains a matching bare-layout example but is closed as a duplicate, so it cannot be a canonical target.
