# Issue #344216 — Model picker redesign in 1.142 is a usability regression — please revert or rework

[https://github.com/microsoft/vscode/issues/344216](https://github.com/microsoft/vscode/issues/344216)

## Summary

Keep open as actionable model-picker design feedback. Current source provides search, pinning, and remembered expansion, but these do not fully deliver the requested at-a-glance, low-interaction model switching; the related pinned-tab request covers only part of this report.

## Change summary

Rework the redesigned Copilot model picker to improve model visibility, selection clarity, and switching efficiency.

## Best solution

Have the model-picker owners evaluate a directly scannable selection experience against the current provider-tab and shortlist design, preserving clear selection state and keyboard access. Coordinate with the pinned-tab request without treating that narrower feature as a complete solution.

Record interaction counts and verify keyboard-only selection and search; acceptance should demonstrate reduced switching overhead without losing provider identity or selection clarity.
- **Behavior:**

  > Users who frequently switch models should be able to discover available choices and recognize the current selection without unnecessary navigation. The report asks for a simple, scannable experience rather than prescribing a particular replacement. Acceptance should compare common switching tasks with the current picker, including cross-provider switching and returning to recently used models, while preserving keyboard access.
- **Trace:**

  > ModelPickerWidget in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts opens TabbedModelPicker. In modelPickerTabbedWidget.ts, _buildItems renders routing models, pinned models, the shortlist, and a potentially collapsed Other Models section; expansion is remembered, and search flattens destinations into results. buildModelPickerSections in modelPickerTabs.ts retains selected models in the shortlist but does not promote recentModelIds into that section. These capabilities mitigate parts of the feedback without establishing that the broader interaction request is satisfied. https://github.com/microsoft/vscode/issues/342157 tracks the narrower cross-provider Pinned tab and contains relevant user feedback. The unresolved boundary is the desired default browsing experience, not model availability or entitlement enforcement; preserve those contracts.
- **Open decisions:**
  - Should opening the picker prioritize a consolidated model list or retain provider tabs with a curated shortlist?
  - Which models should be immediately visible by default: all available models, pinned and recently used models, or the existing suggested set?
