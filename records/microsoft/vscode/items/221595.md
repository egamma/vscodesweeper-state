# Issue #221595 — Support selecting debug configuration providers using ‘when’ clause

[https://github.com/microsoft/vscode/issues/221595](https://github.com/microsoft/vscode/issues/221595)

## Summary

The requested selection-specific when-clause remains absent on current main, and the existing debugger-level `when` clause is not equivalent because it controls whether the debugger is enabled globally. This team-authored Backlog request should remain open in the debug area.

## Change summary

Allow debugger contributions to use active-resource and extension-defined context keys when VS Code chooses a debug configuration provider without a launch configuration.

## Best solution

Add a selection-only context-key expression to debugger contributions and evaluate it in `AdapterManager.guessDebugger`, while preserving language-first selection for contributions that do not declare the expression. Define deterministic fallback behavior when a predicate is false or multiple debuggers match.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/debug/common/debugSchemas.ts`, `src/vs/workbench/contrib/debug/common/debugger.ts`, `src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts`, `src/vs/workbench/contrib/debug/test/browser/debugAdapterManager.test.ts`
- **Validation:** Add focused AdapterManager tests covering unchanged language-first selection without the new condition, true and false selection conditions, fallback after a false language match, and multiple matching providers; run `./scripts/test.sh --grep "AdapterManager guessDebugger"`.
- **Behavior:**

  > Debugger contributions can condition configuration-provider selection on standard or extension-defined context keys, including the active resource's extension and filename. Contributions without the new condition retain today's language-first guessing behavior. A matching condition can make an otherwise non-language-associated provider eligible, while a false condition does not select that provider. Selection remains deterministic when no provider or multiple providers satisfy the applicable rules.
- **Trace:**

  > `AdapterManager.guessDebugger` in src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts currently filters enabled debuggers by `Debugger.interestedInLanguage` and immediately returns a sole language match; its fallback considers all configuration-capable debuggers. `IDebuggerContribution` and the extension-point schema live in src/vs/workbench/contrib/debug/common/debug.ts and debugSchemas.ts. `Debugger` in src/vs/workbench/contrib/debug/common/debugger.ts already demonstrates parsing and evaluating context-key expressions, but its existing `when` property controls global debugger enablement and must retain that meaning. The boundary is provider guessing: debugger availability, explicit launch configurations, and existing contributions without the new property must not change.
- **Open decisions:**
  - When a language-matching debugger declares the selection condition and it evaluates false, should guessing consider other condition-matched providers before presenting the existing general picker?
  - If multiple debugger contributions satisfy their selection conditions, should all appear in the existing picker or should language matches retain priority over non-language matches?

## Evidence

- **current contribution schema:** src/vs/workbench/contrib/debug/common/debugSchemas.ts defines `languages`, `configurationAttributes`, `when`, and `hiddenWhen`, but no `providesConfigurationWhen` or equivalent selection-specific property.
- **current contribution type:** src/vs/workbench/contrib/debug/common/debug.ts defines `IDebuggerContribution`; it likewise has no context expression dedicated to configuration-provider selection.
- **current selection path:** src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts:344-374 implements `AdapterManager.guessDebugger`: it returns a sole enabled language-matching debugger immediately, otherwise falls back to all enabled debuggers that provide configurations, without evaluating a selection-specific condition.
- **existing capability is insufficient:** src/vs/workbench/contrib/debug/common/debugger.ts:52-53 and 156-169 parse the existing contribution-level `when` expression and expose it through `Debugger.enabled`; using it for this request would disable the debugger outside matching active-resource contexts rather than only influence guessing.
