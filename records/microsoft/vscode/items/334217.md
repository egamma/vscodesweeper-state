# Issue #334217 — VSCode 1.137.0-insider: Chats in Agents Window not working/not doing anything

[https://github.com/microsoft/vscode/issues/334217](https://github.com/microsoft/vscode/issues/334217)

## Summary

Keep open as the older report for a confirmed Agents Window first-turn dispatch failure. The newer https://github.com/microsoft/vscode/issues/336146 independently confirms the same user-visible symptom and missing `chat/turnStarted`, but cannot be the canonical for this re-reviewed item because it was filed later.

## Change summary

New and existing Agents Window chats remain indefinitely in Considering or Working because the submitted turn never reaches Agent Host, while regular editor chat continues working.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostChatContribution.test.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/sessions/contrib/providers/agentHost/test/browser/localAgentHostSessionsProvider.test.ts`
- **Validation:** On a current Insiders/main build, create a local Agents Window session and immediately submit its first prompt while capturing renderer and AHP logs; verify that `chat/turnStarted` is dispatched or that any failed prerequisite terminates with a visible error. Finish with a deterministic focused test that blocks the identified prerequisite and asserts the request cannot remain active indefinitely.
- **Behavior:**

  > Submitting a message in a new or existing local Agents Window chat must either dispatch the turn to Agent Host and complete normally or terminate with a visible actionable error. The chat must not remain indefinitely in Considering or Working without a corresponding `chat/turnStarted`. Regular editor-chat behavior must remain unchanged. Acceptance requires exercising the first-send path on a current build and a deterministic regression covering the identified stalled prerequisite.
- **Trace:**

  > The affected build logged entry into `AgentHostSessionHandler._invokeAgent` but no later AHP `dispatchAction` or `chat/turnStarted`; https://github.com/microsoft/vscode/issues/336146 independently establishes that boundary and proves the same host/provider could complete a direct AHP turn. Current `main` routes the request through `_invokeAgent` in `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, including trust resolution, provisional-session settlement, eager-session state, authentication, subscriptions, active-client publication, and `_handleTurn`. Eager backend creation is owned by `NewSession.eagerCreate` and `_startNewSessionBackend` in `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`. The earlier create-before-subscribe race in https://github.com/microsoft/vscode/issues/330531 was fixed before this report and should not be assumed to be the same cause. Keep the investigation bounded to first-turn dispatch and error settlement; historical-session hydration and provider/model execution after `chat/turnStarted` are outside this report.

## Evidence

The available reports do not identify which stage failed on the affected build.
- **related older defect differs:** https://github.com/microsoft/vscode/issues/330531 involved subscribing before backend `createSession` and was fixed by https://github.com/microsoft/vscode/pull/330761 on 2026-08-13, before this later regression; it is closed and cannot serve as a duplicate canonical.
