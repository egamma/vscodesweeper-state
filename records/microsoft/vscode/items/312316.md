# Issue #312316 — Add model name completion with @

[https://github.com/microsoft/vscode/issues/312316](https://github.com/microsoft/vscode/issues/312316)

## Summary

A real discoverability gap remains: current main can route subagents to named models, but chat input does not offer model-name completions or their request multipliers. Route this to the chat-subagents area for a product decision about syntax and selection scope.

## Change summary

Provide chat-input completion for available subagent models, including cost multipliers, and support using the selected model for delegation or staged model switching.

## Best solution

Define a discoverable chat-input syntax that lists eligible subagent models with multiplier metadata and carries the selection into delegation, while preserving the existing `@` participant interaction. Treat multi-phase model switching as a separate scope unless the chosen syntax can represent it unambiguously.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletionUtils.ts`, `src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/editor/chatInputCompletions.test.ts`, `src/vs/workbench/contrib/chat/test/common/tools/builtinTools/runSubagentTool.test.ts`
- **Validation:** After choosing the syntax and selection scope, add targeted chat-input completion tests that enumerate eligible models with multiplier metadata and an end-to-end tool test showing that accepting a model selection supplies the expected model to subagent resolution without changing existing `@participant` completion behavior.
- **Behavior:**

  > Users composing an agent request can discover eligible subagent models without memorizing exact names and can see each available request multiplier. Selecting a model produces an unambiguous instruction that is honored for the intended delegation scope. Existing `@participant`, attachment, and model-picker workflows remain available and keyboard accessible. Multi-phase switching is included only if its lifetime and transition semantics are explicitly selected.
- **Trace:**

  > Local chat `@` completion is implemented by `AgentCompletions` in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts and currently represents participants, with completion-range helpers in chatInputCompletionUtils.ts. Agent-host-backed sessions delegate completion lists through AgentHostInputCompletions, so parity across local and agent-host surfaces must be considered. Installed model names and metadata are available through ILanguageModelsService; prompt-header model completion already consumes that service in promptHeaderAutocompletion.ts. RunSubagentTool in src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts already accepts a model name and evaluates multiplier constraints. Preserve existing participant invocation and attachment semantics; the uncertainty begins at the user-visible syntax and how long a model selection remains in effect. The broader delegation request at https://github.com/microsoft/vscode/issues/296469 is related but does not settle those interaction choices.
- **Open decisions:**
  - Should model completion share `@` with chat participants, use a distinct qualifier or trigger, or remain in the existing model picker?
  - Does an inline model selection affect one subagent invocation, the current parent conversation, or subsequent delegations until changed?
  - Is staged model switching within one prompt part of this feature, and if so, what explicit user-visible boundary causes the model transition?

## Evidence

- **current input behavior:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts registers `@` completions for chat participants through `AgentCompletions`; it supplies no language-model entries and restricts participant selection to input with no preceding text.
- **partial existing capability:** src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptHeaderAutocompletion.ts already completes installed model names for the `model` attribute in `.agent.md` and prompt headers, but that does not provide model discovery in chat input.
- **delegation foundation:** src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts exposes an optional `model` parameter, resolves named models, and uses `multiplierNumeric` to enforce cost-tier constraints, so model and cost data exist below the requested input experience.
