# Issue #238363 — Git - Opening diff from blame should reveal previously focused line

[https://github.com/microsoft/vscode/issues/238363](https://github.com/microsoft/vscode/issues/238363)

## Summary

Still unfixed on main. The blame decoration click opens the multi-diff editor via `git.viewCommit` but passes no line/range in the `reveal` parameter, so the diff always scrolls to the top. The infrastructure to reveal a specific range already exists in the `_workbench.openMultiDiffEditor` command — it just isn't wired through from the blame flow.

## Change summary

Clicking a blame decoration opens the commit diff scrolled to the top instead of revealing the line the cursor was on.

## Best solution

Pass the cursor's line number from the blame decoration command through `git.viewCommit` into the `reveal.range` of `_workbench.openMultiDiffEditor`. The status bar item command at blame.ts:736 already passes the URI; add the active line as a fourth argument and thread it through `viewCommit` at commands.ts:5129.
