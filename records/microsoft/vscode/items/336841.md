# Issue #336841 — MCP: initialized notification is not ordered before the first request, breaking stateful Streamable HTTP servers intermittently

[https://github.com/microsoft/vscode/issues/336841](https://github.com/microsoft/vscode/issues/336841)

## Summary

Confirmed on current main: `McpHTTPHandle.send()` in extHostMcp.ts only serializes through `_requestSequencer` while `_mode.value === HttpMode.Unknown`, so `notifications/initialized` and the first real request race as unordered HTTP POSTs against stateful Streamable HTTP servers. A fixing PR is already open, so this stays open pending review/merge rather than being fixed on main yet.

## Change summary

The MCP client's `notifications/initialized` isn't ordered before the first subsequent request, causing intermittent 400 'Session not initialized' errors against stateful Streamable HTTP MCP servers.

## Best solution

Land https://github.com/microsoft/vscode/pull/336843 (or an equivalent fix keeping requests queued behind `_requestSequencer` until the initialized notification's POST resolves) in `McpHTTPHandle.send()`.
