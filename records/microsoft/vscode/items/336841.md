# Issue #336841 — MCP: initialized notification is not ordered before the first request, breaking stateful Streamable HTTP servers intermittently

[https://github.com/microsoft/vscode/issues/336841](https://github.com/microsoft/vscode/issues/336841)

## Summary

Well-diagnosed, source-confirmed race: McpHTTPHandle.send() only serializes through _requestSequencer while mode is Unknown, so the fire-and-forget notifications/initialized can race the first real request against stateful Streamable HTTP servers. An open PR (#336843) already targets exactly this fix, so keep this open for that PR to land rather than proposing any close.

## Change summary

The initialized notification isn't ordered before the first real MCP request over Streamable HTTP, so stateful servers intermittently reject the first request and VS Code retries forever.

## Best solution

Land https://github.com/microsoft/vscode/pull/336843 (or an equivalent fix) that keeps serializing sends through _requestSequencer until the initialized notification has actually been sent, then close this via that PR.
