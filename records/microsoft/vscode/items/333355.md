# Issue #333355 — Allow runSubagent model param to differentiate same-name models across BYOK groups (vendor/group/id)

[https://github.com/microsoft/vscode/issues/333355](https://github.com/microsoft/vscode/issues/333355)

## Summary

Legitimate feature request with a verified code-level gap: BYOK groups sharing the same vendor/name silently collide in model resolution. It's freshly filed and in the Backlog Candidates holding bin with 0 upvotes, so it stays open for the normal 60-day community upvote process rather than being closed for being quiet.

## Change summary

Let the runSubagent tool's model parameter (and prompt files) disambiguate BYOK models that share the same display name across different BYOK groups, e.g. via a `<vendor>/<group>/<id>` qualified name.

## Best solution

Extend the qualified-name format (and `ILanguageModelChatMetadata.matchesQualifiedName` / `lookupLanguageModelByQualifiedName` in src/vs/workbench/contrib/chat/common/languageModels.ts) to optionally include a group/id disambiguator, and thread that through runSubagentTool.ts's explicit model parameter instead of relying on first-match iteration order.

## Evidence

- **matchesQualifiedName only compares name+vendor:** src/vs/workbench/contrib/chat/common/languageModels.ts:360-364 — `matchesQualifiedName` compares only `name (vendor)`, with no group/id distinction.
- **first-match resolution:** src/vs/workbench/contrib/chat/common/languageModels.ts:1182-1188 — `lookupLanguageModelByQualifiedName` iterates `_modelCache.entries()` and returns the first metadata matching the qualified name, so duplicate names across BYOK groups silently resolve to whichever entry comes first.
- **runSubagentTool consumes qualified name directly:** src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts:505-513 — `resolveSubagentModel` calls `lookupLanguageModelByQualifiedName(explicitModelQualifiedName)` with no group/id parameter, confirming there is currently no way to disambiguate.
