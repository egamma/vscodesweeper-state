[https://github.com/microsoft/vscode/issues/119824](https://github.com/microsoft/vscode/issues/119824)

## Summary

Keep open: maintainers confirmed that competing diagnostic producers can overwrite each other's problems after a file closes, and the relevant marker-storage boundary remains unchanged. The linked workaround PR is still open, not a landed fix.

## Change summary

Preserve problems from both the core and extension build tasks when an editor closes, without duplicating live TypeScript diagnostics.

## Best solution

Retain independent build diagnostics while coordinating their visibility with live language-service diagnostics. Review the existing workaround PR separately; combining the repository's build tasks does not resolve the underlying shared-owner collision.
