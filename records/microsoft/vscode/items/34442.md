# Issue #34442 — Extract the integrated terminal

[https://github.com/microsoft/vscode/issues/34442](https://github.com/microsoft/vscode/issues/34442)

## Summary

Keep this accepted request open: terminal windows exist, but independently launching one from the CLI without an open editor window remains missing. The existing area labels are appropriate, and neither the closed prototype PR nor related panel-detachment requests completes this work.

## Change summary

Allow launching a lightweight VS Code terminal window independently of an editor workspace, sharing existing terminal configuration and functionality.

## Best solution

Provide an independently launchable terminal window that preserves VS Code terminal settings and avoids initializing an unnecessary full editor workbench. Plan its startup and service lifetime with the terminal and workbench owners rather than treating hidden editor UI as equivalent to a lightweight terminal.

Verify configured profiles, fonts, keybindings and shell interaction match existing terminal windows; confirm existing new-window and move-terminal commands still work. Measure startup time and memory against normal-workbench and existing terminal-window baselines, with acceptance thresholds agreed before implementation. No execution was performed during this read-only review.
- **Behavior:**

  > Users can launch a VS Code terminal window from the CLI without first opening an editor window or workspace. It provides the existing terminal configuration and shell experience without showing unrelated editor UI. Acceptance includes cold startup, normal terminal interaction, configuration fidelity, and unchanged existing terminal-window commands. Lightweight startup must be evaluated through startup and memory measurements, not inferred from hidden UI.
- **Trace:**

  > TerminalCommandId.NewInNewWindow in src/vs/workbench/contrib/terminal/browser/terminalActions.ts creates a compact auxiliary editor group through the current terminal service. TerminalEditorService.openEditor in src/vs/workbench/contrib/terminal/browser/terminalEditorService.ts uses the existing editor service, while AuxiliaryWindowService in src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts opens and styles windows from mainWindow. NativeParsedArgs and OPTIONS in src/vs/platform/environment/common/argv.ts and src/vs/platform/environment/node/argv.ts expose no standalone-terminal launcher. This establishes the missing entry point and current main-window coupling, but does not establish a complete independent service-bootstrap design. Preserve terminal behavior and shared configuration; panel detachment is separate work tracked at https://github.com/microsoft/vscode/issues/193267. The unmerged prototype https://github.com/microsoft/vscode/pull/294035 only hides normal-workbench UI, which does not meet the memory intent stated at https://github.com/microsoft/vscode/issues/34442#issuecomment-901959244.
- **Open decisions:**
  - What CLI syntax and path-argument semantics should independently launch a terminal window?
  - What measurable startup-time and memory criteria define an acceptable lightweight terminal window?
  - Is upgrading a terminal-only window into a workspace while preserving its running terminals part of the initial public contract or a follow-up?
