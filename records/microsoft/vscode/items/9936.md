# Issue #9936 — Allow to bring up a dialog with multiple inputs

[https://github.com/microsoft/vscode/issues/9936](https://github.com/microsoft/vscode/issues/9936)

## Summary

Keep open: extensions still lack a built-in API for presenting several editable fields together in one dialog. Multi-step quick input and webview panels offer alternatives, but neither satisfies the native, simultaneous-input request; 33 upvotes and an accepted Backlog milestone support retaining it.

## Change summary

Expose a cross-platform extension API for collecting multiple named inputs together in a single dialog.

## Best solution

Have the API and dialogs owners define a minimal, accessible multi-field input contract, starting with the text-only scope the reporter explicitly accepts. Preserve existing single-input and sequential quick-input APIs rather than treating those workarounds as completion.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/platform/dialogs/common/dialogs.ts`, `src/vs/workbench/api/common/extHost.api.impl.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHostQuickOpen.ts`, `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`
- **Validation:** Use an extension-host sample to request project directory and project name together: verify both fields remain simultaneously visible and editable, submission returns correctly associated values, and Escape cancels without submitting. Repeat on Windows, macOS, and Linux, including keyboard-only and screen-reader interaction; verify existing single-input and multi-step flows remain unchanged.
- **Behavior:**

  > An extension can collect multiple values in one built-in dialog rather than asking each question in a separate step. Users can see and revise all displayed values before submitting. The reporter accepts text-only fields as an initial scope; mixed text and choice fields are a broader suggestion, not a minimum requirement. Acceptance must cover field ordering, association of returned values with fields, cancellation, and accessible cross-platform interaction.
- **Trace:**

  > The public window.showInputBox and window.createInputBox APIs in src/vscode-dts/vscode.d.ts expose one value, while QuickInput.step and totalSteps describe sequential flows. ExtHostQuickOpen.showInput in src/vs/workbench/api/common/extHostQuickOpen.ts forwards a single input request through extHost.protocol.ts to MainThreadQuickOpen.$input in src/vs/workbench/api/browser/mainThreadQuickOpen.ts, which uses IQuickInputService.input. Separately, src/vs/platform/dialogs/common/dialogs.ts already defines internal multi-input dialog arguments and array-valued results, but this does not establish a suitable public extension contract. Preserve existing single-input behavior and do not expand the request into arbitrary custom windows or webview layout changes. Related modal-webview requests https://github.com/microsoft/vscode/issues/47899 and https://github.com/microsoft/vscode/issues/340002 are distinct design leads, not duplicate targets. The uncertainty starts at the supported field types and public validation, submission, and cancellation contract; no execution was performed in the read-only checkout.
- **Open decisions:**
  - Should the initial public API support only text inputs, as the reporter accepts, or also choice fields displayed alongside them?
  - What public contract should govern field identification and ordering, validation across fields, submitted results, and cancellation?
