## Summary

Thanks for the detailed report. Maintainers in the thread (a CONTRIBUTOR and a MEMBER) confirmed that the restrictive serverName charset lives in the bundled Copilot runtime validator, and that VS Code keeping the exact registry name is correct. This issue stays open as the tracker for integrating and verifying the runtime fix. Related issues #338879 and #341800 cover different symptoms (gallery command admission and matcher precedence), so it is not a duplicate of either.

## Change summary

Registry-style serverName values containing '/' or '.' cannot be allowlisted in managed settings because the runtime validator rejects them.

## Best solution

Consume the corrected Copilot runtime validator that accepts literal registry-style names. Keep exact-name matching in VS Code with no normalization. Verify file- and server-delivered managed settings, and align matchesMatcher() precedence with the runtime under the separate issue #341800.
