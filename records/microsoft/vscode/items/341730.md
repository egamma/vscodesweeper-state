# Issue #341730 — MCP allowlist: `serverName` can never match registry-installed servers (raw `owner/name` label vs `^[A-Za-z0-9_-]+$` validation, no normalization) when using **server-managed** settings

[https://github.com/microsoft/vscode/issues/341730](https://github.com/microsoft/vscode/issues/341730)

## Summary

Thanks for the detailed report. The VS Code side is confirmed in source: `matchesMatcher` in allowedMcpServers.ts compares `serverName` by strict equality with the raw registry name. The managed-settings validator is in the bundled Copilot runtime and was not checked here. Which matcher or normalization to add is a design decision, so this stays open.

## Change summary

Registry-installed MCP servers with names like `owner/name` cannot be allowlisted by `serverName`, because the managed-settings validator rejects `/` and `.` and VS Code does no normalization.

## Best solution

Add a registry-identity matcher (or a documented deterministic normalization applied on both the validator and VS Code sides). Align `matchesMatcher()` precedence between `serverName` and `serverCommand`/`serverUrl` with the Copilot runtime. Coordinate with https://github.com/microsoft/vscode/issues/338879.
