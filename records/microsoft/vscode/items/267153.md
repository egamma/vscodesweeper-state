Still reproduces on main: the 'Accept Inline Completion' action in the accessible view toolbar retrieves the editor and inline completion model, but when triggered from the toolbar the model state may be null or the accept fails silently. No fix commit found. The bug is properly labeled and milestoned on 'On Deck'; keeping open.

## Change summary

Pressing 'Accept Inline Suggestion' from the accessible view toolbar (Alt+F2 → Shift+Tab → Enter) does nothing — the inline completion is not accepted.

## Best solution

Debug why `AccessibleViewAcceptInlineCompletionAction.run()` in `src/vs/workbench/contrib/accessibility/browser/accessibleViewActions.ts` (line 326–341) fails to accept the completion. The controller at `src/vs/editor/contrib/inlineCompletions/browser/controller/inlineCompletionsController.ts` line 283 already preserves inline completions when the accessible view is shown, so the model should still have state. The likely issue is that `getActiveCodeEditor()` does not return the correct editor when focus is in the accessible view, or that `model.accept(editor)` needs the editor to be focused. The fix should ensure the accept path works when invoked from the accessible view toolbar.
