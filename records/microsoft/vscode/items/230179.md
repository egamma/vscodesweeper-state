# Issue #230179 — Contributing a text editor provider raises warning, even when user selects it as 'workbench.editor.defaultBinaryEditor'

[https://github.com/microsoft/vscode/issues/230179](https://github.com/microsoft/vscode/issues/230179)

## Summary

Still reproducible on main: when a CustomTextEditorProvider is set as `workbench.editor.defaultBinaryEditor`, opening a binary file still triggers the 'File seems to be binary' warning because the text file resolution path in textFileService.ts unconditionally throws FILE_IS_BINARY before the configured editor override takes effect. The issue is accepted and labeled `help wanted`.

## Change summary

Setting a CustomTextEditorProvider as the default binary editor still shows a 'File seems to be binary' warning because the text model resolution throws before the editor override is applied.

## Best solution

The fix should suppress the binary warning when the configured `defaultBinaryEditor` is set and differs from the default text editor. The `openAsBinary` path in `src/vs/workbench/contrib/files/browser/editors/textFileEditor.ts` already handles redirection to the configured editor, but the underlying issue is that `CustomTextEditorProvider` resolves a text document, so the binary detection in `textFileService.ts` fires again when the custom editor resolves its model. The fix likely needs to allow the custom text editor model to resolve with `forceOpenAsText` semantics when the editor was explicitly chosen for binary files.
