# Issue #230179 — Contributing a text editor provider raises warning, even when user selects it as 'workbench.editor.defaultBinaryEditor'

[https://github.com/microsoft/vscode/issues/230179](https://github.com/microsoft/vscode/issues/230179)

## Summary

The configured binary editor is selected, but a CustomTextEditorProvider still resolves its backing file through the text-only loader and encounters the reported binary-file error. Keep this open in custom-editors; the linked maintainer discussion supports addressing the warning rather than declining the workflow.

## Change summary

Honor an explicitly selected default binary editor without blocking its text-editor provider on the binary-file warning.

## Best solution

Make the explicitly selected binary-editor workflow usable while preserving binary-file protection for ordinary text opens. Clarify whether the supported contract is decoding the original file for a CustomTextEditorProvider or presenting extension-generated text, since suppressing the warning alone does not supply an objdump text document.

- **Behavior:**

  > Opening a binary with an explicitly configured default binary editor currently fails while resolving the custom text editor's backing document. The reporter also needs an objdump text representation with language features; acceptance must distinguish successful provider resolution from actually delivering that representation.
- **Trace:**

  > TextFileEditor.openAsBinary selects the configured override, and MainThreadCustomEditors.getOrCreateCustomEditorModel creates a CustomTextEditorModel for text providers. CustomTextEditorModel.create requests the original resource through ITextModelService.createModelReference; the file-backed resolver supplies no allowBinary option, so TextFileEditorModel.resolveFromFile performs a text-only read and the binary decoder throws. This path establishes the reported rejection without executing the extension. The public CustomTextEditorProvider contract still describes an original TextDocument synchronized with a webview, whereas the reporter describes generated objdump text in a native editor. The maintainer discussion at https://github.com/microsoft/vscode-discussions/discussions/1532#discussioncomment-10798417 supports addressing the configured-editor warning but does not settle that representation contract. Do not globally disable binary detection or treat raw binary decoding as equivalent to generating objdump output.
- **Open decisions:**
  - Should this issue cover only allowing the explicitly selected CustomTextEditorProvider to load the original binary as text, or also automatic presentation of a separate generated-text document with native editor language features?
