# Issue #258281 — *Destructive* shortcut keys override standard text file operations (Ctrl+N rejects changes)

[https://github.com/microsoft/vscode/issues/258281](https://github.com/microsoft/vscode/issues/258281)

## Summary

The initial mitigation landed, but current main still intentionally overrides standard New File/New Window shortcuts during chat-edit review, and multiple users confirmed the remaining destructive behavior after that change. Maintainers have accepted the problem and are discussing the appropriate keybinding and review-mode UX, so this issue remains the canonical open discussion.

## Change summary

Prevent chat-edit Keep/Undo commands from unexpectedly overriding standard file and window creation shortcuts and discarding pending edits.

## Best solution

Choose a review interaction that preserves efficient keyboard-based hunk review without silently overriding standard creation shortcuts—for example, non-conflicting defaults or an explicit, visibly indicated review mode—and ensure rejected edits have a clear recovery path.

- **current source:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts still binds `chatEditor.action.undoHunk` to Ctrl/Cmd+N when `ctxCursorInChangeRange` is true, while file-level Undo Chat Edits remains bound to Ctrl/Cmd+Shift+N with `WorkbenchContrib + 10` weight and an explicit `win over new-window-action` comment.
- **post-fix reproduction:** https://github.com/microsoft/vscode/issues/258281#issuecomment-3579005644 reports Ctrl+Shift+N discarding edits on Insiders 1.108 after the mitigation had merged; later comments through September 2026 independently report the same remaining behavior.
