# Issue #172882 — Replace in files doesn't work as expected with match containing newline

[https://github.com/microsoft/vscode/issues/172882](https://github.com/microsoft/vscode/issues/172882)

## Summary

Keep open: current source still computes capture substitutions from preview text that can omit the next-line lookahead context, causing a literal $1 replacement. Maintainers consolidated older reports into this issue, and no verified open canonical or fixing PR supersedes it.

## Change summary

Make workspace regex replacement expand capture groups correctly when a lookaround depends on text outside the matched lines.

## Best solution

Compute replacement captures with sufficient original-file context while preserving the exact selected match range and agreement between preview and applied edits. Establish an approach that covers open and closed files without stripping lookarounds or changing search-provider contracts unintentionally.

## Evidence

- **Exact failing source path:** In src/vs/workbench/services/search/common/searchHelpers.ts, editorMatchToTextSearchResult collects only lines spanned by the consumed match. For child: (\w+);(?=[\S\s\n]*?\}), the consumed match ends on the first line, so the next-line } is absent from the preview even though it is required by the lookahead.
- **Literal replacement fallback:** src/vs/workbench/contrib/search/browser/searchTreeModel/match.ts, MatchImpl.replaceString, retries against fullMatchText(true), but that method only returns _fullPreviewLines, not full document contents. Without the next-line }, every regex evaluation fails and the final fallback returns replacePattern.pattern, which is the literal $1. src/vs/workbench/services/search/common/replace.ts, ReplacePattern.getReplaceString, returns null when the regex cannot match the supplied text.
