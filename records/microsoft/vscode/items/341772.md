# Issue #341772 — MCP migration says an update is needed to keep working but drops registry auto-updates

[https://github.com/microsoft/vscode/issues/341772](https://github.com/microsoft/vscode/issues/341772)

## Summary

Keep open: current main explains the runtime-format change more clearly, but migration still explicitly drops registry updates without explaining their scope or the supported replacement workflow. The related marketplace-installation issue concerns a different observable behavior and does not absorb this request.

## Change summary

Preserve registry-managed MCP updates across migration, or explain the update limitation, post-migration maintenance procedure, and consequences of ignoring migration.

## Best solution

Define the registry-update contract for MCP servers migrated to Copilot configuration, then make the migration UI explain that contract before consent. Prefer preserving registry association; if unsupported, provide accurate maintenance guidance and distinguish registry configuration updates from updates to a remotely hosted service.

- **Behavior:**

  > A user reviewing migration of a registry-installed MCP server can understand what changes before consenting. - **Trace:**

Keep unrelated marketplace destination work in https://github.com/microsoft/vscode/issues/343548 separate, and do not infer a hosted-service update failure from removal of local registry metadata.
- **Open decisions:**
