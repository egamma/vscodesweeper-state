# Issue #321731 — vsce-sign crashes with SIGILL verifying Pylance on Ubuntu 26.04 aarch64 in Lima on Apple M4

[https://github.com/microsoft/vscode/issues/321731](https://github.com/microsoft/vscode/issues/321731)

## Summary

Keep open as an upstream-runtime adoption issue. The SIGILL is independently confirmed and matches a fixed .NET ARM64 defect, but current VS Code main still bundles a vsce-sign Linux ARM64 binary that predates adoption of that fix.

## Change summary

Extension signature verification crashes when its NativeAOT ARM64 runtime executes an SVE `rdvl` instruction on virtualized Apple CPUs exposing SME without standalone SVE.

## Best solution

Publish a Linux ARM64 vsce-sign binary built with a .NET runtime containing https://github.com/dotnet/runtime/commit/d99474c5ca575fee7d83073015beb6b89e7421a8, adopt that binary in VS Code, and validate signature verification on SME-without-SVE guests using both large and small extensions.

## Evidence

- **confirmed symptom:** The report reproduces exit code 132 with the bundled signer on Ubuntu 26.04 ARM64 under Lima, while the same assets succeed on a guest without the additional SME flags. A second reporter reproduced the crash under Parallels and disassembled the faulting instruction as `rdvl x0, #1`.
- **upstream root cause:** https://github.com/dotnet/runtime/issues/122608 documents the same SIGILL on Apple M4 virtualization where SME is exposed without standalone SVE.
- **upstream fix:** https://github.com/dotnet/runtime/commit/d99474c5ca575fee7d83073015beb6b89e7421a8 removes `CONTEXT_GetSveLengthFromOS`, whose ARM64 implementation executes `rdvl`, and instead reads `sve->vl` from the signal frame specifically to avoid SIGILL on SME-without-SVE platforms.
- **adoption still missing:** Current main's build/package-lock.json resolves @vscode/vsce-sign 2.1.0 but still bundles @vscode/vsce-sign-linux-arm64 2.0.6. The September confirmation identifies that shipped binary as .NET 9 NativeAOT and still reproduces the fault, while the upstream fix is assigned to the .NET 11.0.0 milestone.
- **current call path:** src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts imports @vscode/vsce-sign and invokes its `verify` function; there is no VS Code-side implementation of the faulting runtime instruction.
