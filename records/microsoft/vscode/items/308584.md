# Issue #308584 — Visual Studio Code Agents (Preview) should gracefully handle PowerShell shell fallback on Windows

[https://github.com/microsoft/vscode/issues/308584](https://github.com/microsoft/vscode/issues/308584)

## Summary

The agent host terminal manager already has shell fallback logic (configured shell → `getSystemShell` → PowerShell enumeration including Windows PowerShell), and a `defaultShell` setting was added in commit 8b28f914f2a. However, the related PR #312999 was closed without merging, a commenter still reports the issue as of May 2026, and the exact failure path is unclear — routing to the agent-host area for investigation.

## Change summary

Agent host terminal tasks fail on Windows when `pwsh` is not discoverable, instead of falling back to Windows PowerShell or another available shell.

## Best solution

The agent-host team should investigate why `getDefaultShell()` in `agentHostTerminalManager.ts` does not find a usable PowerShell on affected Windows machines despite the enumeration in `src/vs/base/node/powershell.ts` covering Windows PowerShell as a final fallback. The non-null assertion on line 67 of `src/vs/base/node/shell.ts` (`(await getFirstAvailablePowerShellInstallation())!.exePath`) may crash if no PowerShell is found at all. Getting a reproduction with logs from the affected reporter would clarify the gap.

## Evidence

- **fallback logic exists:** src/vs/platform/agentHost/node/agentHostTerminalManager.ts lines 789–799 implement getDefaultShell() with fallback from configured shell to getSystemShell(), which on Windows calls getFirstAvailablePowerShellInstallation() enumerating PSCore, MSIX, dotnet global tool, Scoop, and Windows PowerShell.
- **non-null assertion risk:** src/vs/base/node/shell.ts line 67 uses a non-null assertion: `(await getFirstAvailablePowerShellInstallation())!.exePath` — if no PowerShell installation is found, this crashes rather than falling back to COMSPEC or cmd.exe.
