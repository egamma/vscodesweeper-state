# Issue #325919 — Agents renderer OOM: unbounded workspaceFileCount telemetry search materializes every file

[https://github.com/microsoft/vscode/issues/325919](https://github.com/microsoft/vscode/issues/325919)

## Summary

Real, source-verified bug: the Agents/Sessions workspace-file-count telemetry helper runs an unbounded `rg --files` search with no `maxResults` and no telemetry-level gate, and the renderer materializes every match — a large workspace (e.g. $HOME) can OOM-crash the renderer. Routing to the sessions area rather than closing.

## Change summary

Sending a foreground agent-session message triggers an unbounded workspace file-count search for telemetry, which can materialize millions of file URIs in the renderer and OOM-crash it, even with telemetry disabled.

## Best solution

In sessionsTelemetry.contribution.ts, gate `_startWorkspaceFileCountFetch` on `telemetryLevel >= TelemetryLevel.USAGE` before starting the scan, and pass a bounded `maxResults` (or an extension-host-side count) to `fileSearch` in `_computeWorkspaceFileCount` so results are never fully materialized in the renderer just to get a length.
