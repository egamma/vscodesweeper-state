# Issue #119868 — Npm Scripts view not available if package.json located only in nested folder

[https://github.com/microsoft/vscode/issues/119868](https://github.com/microsoft/vscode/issues/119868)

## Summary

Keep this accepted feature request open: current source still lacks an opt-in to activate npm discovery for nested-only package.json files. The request has 33 upvotes, maintainer support, and duplicates consolidated here; neither the closed implementation attempt nor existing workarounds completes it.

## Change summary

Allow users to opt into discovering nested package.json files and showing NPM Scripts without first opening a JSON file or adding a root package.json.

## Best solution

Provide reliable, workspace-configurable startup discovery for nested npm projects while retaining the lightweight default activation behavior. Settle whether the opt-in searches the workspace recursively or targets configured package locations, including its search-timeout contract.

## Plan brief

- **Likely files:** `extensions/npm/package.json`, `extensions/npm/package.nls.json`, `extensions/npm/src/npmMain.ts`, `extensions/npm/src/tasks.ts`, `extensions/npm/README.md`
- **Validation:** Open a fresh workspace containing scripts only in ui/package.json and ui/tools/tool1/package.json, with no root manifest or restored JSON editor. With the agreed opt-in enabled, verify NPM Scripts becomes available without opening files or running terminal commands and includes every package covered by the chosen discovery contract. Reload and repeat; verify the default activation behavior remains unchanged. Include a delayed-search case to verify the agreed timeout semantics.
- **Behavior:**

  > A workspace containing only nested package.json files currently requires another activation trigger before NPM Scripts can appear. Users should be able to configure that workspace so the view and its scripts become available on startup without opening a JSON editor, executing a terminal script, or creating a root manifest. The opt-in must continue working after window reload. Default startup behavior should retain its existing performance characteristics; the packages covered and search-completion behavior must follow the agreed product contract.
- **Trace:**

  > extensions/npm/package.json declares root-manifest, JSON-language, and npm-task activation, but no configurable startup-discovery capability. In extensions/npm/src/npmMain.ts, activate sets npm:showScriptExplorer after hasPackageJson succeeds; extensions/npm/src/tasks.ts checks root manifests and otherwise performs a recursive search capped at one second. npm.autoDetect and npm.enableRunFromFolder do not provide the requested startup contract. https://github.com/microsoft/vscode/pull/124930 was closed without merging and addressed only the post-activation timeout, not startup activation. The setting-based activation prerequisite https://github.com/microsoft/vscode/issues/55299 was declined, so that historical design cannot be assumed available. Preserve normal task execution, existing exclusions, and the lightweight default; uncertainty remains around the opt-in's observable discovery scope and how it can be activated reliably.
- **Open decisions:**
  - Should the workspace opt-in discover all nested package.json files recursively, or activate discovery only for explicitly configured package locations?
  - Should opted-in discovery wait until its search completes, or retain a bounded timeout with a visible retry path when discovery is incomplete?

## Evidence

- **Existing-capability check:** extensions/npm/package.json activates through onTaskType:npm, onLanguage:json, and workspaceContains:package.json; it has no npm.alwaysPerformLookup or npm.packageJsonPath setting. npm.autoDetect controls task detection, not unconditional startup activation. npm.enableRunFromFolder offers a manual folder action, while npm.refresh is hidden from the Command Palette; these do not provide the requested persistent startup opt-in.
- **Current discovery boundary:** extensions/npm/src/npmMain.ts:activate sets npm:showScriptExplorer only after activation and a successful hasPackageJson() result. extensions/npm/src/tasks.ts:hasPackageJson first checks workspace-root manifests, then searches **/package.json with a one-second cancellation timeout. Nested discovery exists after activation, but that does not supply the requested configurable activation path.
