# Issue #200687 — trackFocus is a busy loop

[https://github.com/microsoft/vscode/issues/200687](https://github.com/microsoft/vscode/issues/200687)

## Summary

Still reproduces on main: the `trackFocus` function in webview's `index.html` still uses a 250ms `setInterval` polling loop. The open PR #201124 was never completed or merged. The issue remains valid and is labeled `help wanted`.

## Change summary

The webview `trackFocus` function uses a 250ms polling `setInterval` loop instead of event-driven focus/blur tracking, wasting CPU cycles.

## Best solution

Replace the `setInterval` polling in `trackFocus` (src/vs/workbench/contrib/webview/browser/pre/index.html, line 61–77) with `focus`/`blur` event listeners on the document and on the active iframe's `contentWindow`. The tricky part — as noted by @mjbvz on the open PR — is correctly tracking focus when the webview contains iframes, which is why `hasFocus()` polling was used originally. A correct event-driven approach needs to handle cross-origin iframe focus transitions.
