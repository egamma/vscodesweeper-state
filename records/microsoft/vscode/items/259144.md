# Issue #259144 — Adding context in Chat using vscode-copilot-chat repo adds a ton of unnecessary symbols

[https://github.com/microsoft/vscode/issues/259144](https://github.com/microsoft/vscode/issues/259144)

## Summary

Keep open: current main still adds every symbol from cached outline models to Chat's `#` suggestions, making JSON files such as package.json unusually noisy. This team-authored, under-discussion UX issue needs a product choice about filtering versus grouping rather than a judgment close.

## Change summary

Reduce the large number of low-value JSON symbols shown when invoking Chat context suggestions with `#`.

## Best solution

Avoid presenting raw JSON property symbols in the initial mixed context list while preserving deliberate symbol lookup, likely by grouping context types or requiring symbol-specific intent. Coordinate the behavior with https://github.com/microsoft/vscode/issues/273774, which tracks the broader context-bucket design.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/editor/chatInputCompletions.test.ts`
- **Validation:** Add targeted Chat input completion tests using cached JSON and source-code outline models, asserting the selected policy for bare `#` and explicit symbol-prefixed input while preserving intentional source-symbol completion.
- **Behavior:**

  > Opening Chat context suggestions with bare `#` should not flood the initial list with low-value property symbols from an active JSON file such as package.json, settings.json, or mcp.json. Users must still be able to attach useful document symbols through the chosen explicit symbol flow. File, tool, and other context suggestions must remain discoverable, and source-code symbol completion must not regress.
- **Trace:**

  > Symbol completions are registered in `BuiltinDynamicCompletions` in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts. Its `addSymbolEntries` method iterates all cached `OutlineModel` instances, flattens each through `asListOfDocumentSymbols()`, and appends the results without considering language or document type, which directly explains the package.json entries. The related design issue https://github.com/microsoft/vscode/issues/273774 proposes first-level context buckets and an explicit `sym:` flow, but it postdates this issue and does not settle whether JSON symbols should remain available there. Keep the boundary to Chat input suggestion composition; do not change JSON outline providers or remove JSON symbols from editor navigation.
- **Open decisions:**
  - Should bare `#` suppress JSON symbols specifically, or should all symbols move behind a Symbol bucket or explicit `sym:` prefix?
  - If users deliberately enter the symbol flow, should JSON property symbols remain available or be excluded there as well?
