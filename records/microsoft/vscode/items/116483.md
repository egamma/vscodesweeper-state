# Issue #116483 — Allow code folding in the diff editor

[https://github.com/microsoft/vscode/issues/116483](https://github.com/microsoft/vscode/issues/116483)

## Summary

Code-block folding remains explicitly disabled in the current diff editor; collapsing unchanged regions does not satisfy this request. Keep this accepted Backlog feature open for design work on folding and alignment, supported by 20 upvotes and maintainer investigation.

## Change summary

Allow users to fold code blocks while reviewing diffs, including changed code.

## Best solution

Support ordinary code-block folding in the diff editor while preserving corresponding-line alignment and existing unchanged-region collapsing. Establish how folding on one side affects the other before implementing and validating the interaction.

- **Behavior:**

  > Users reviewing a diff should be able to collapse and expand code blocks, including newly added or modified functions, to inspect their high-level structure. Folding must not leave corresponding visible lines misaligned or make subsequent changes inaccessible. Existing unchanged-region collapsing and normal-editor folding must continue to work. Acceptance checks should exercise changed and identical blocks, folding and unfolding from either side, and the interaction with unchanged-region collapsing.
- **Trace:**

  > DiffEditorEditors._adjustOptionsForSubEditor in src/vs/editor/browser/widget/diffEditor/components/diffEditorEditors.ts explicitly disables folding for both subeditors, so the request is not implemented by the ordinary editor.folding setting. FoldingController in src/vs/editor/contrib/folding/browser/folding.ts manages syntax/indentation folding and applies hidden ranges through setHiddenAreas. DiffEditorViewZones in src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/diffEditorViewZones.ts computes alignment and synchronizes scrolling, while HideUnchangedRegionsFeature independently manages corresponding hidden unchanged ranges. The maintainer investigation in https://github.com/microsoft/vscode/issues/116483 specifically identifies misalignment after folding identical regions; current disabled folding prevents confirming that hypothetical enabled path without a prototype. Preserve normal-editor folding, existing diff navigation, and unchanged-region behavior rather than treating this as removal of a single option override. The existing DiffEditorWidget2 browser suite provides a widget-level validation starting point. The remaining product uncertainty is whether matching code blocks fold together or each pane retains independent folding state.
- **Open decisions:**
