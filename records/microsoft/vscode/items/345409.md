# Issue #345409 — MCP: optional content pinning for package-based servers in `mcp.json`

[https://github.com/microsoft/vscode/issues/345409](https://github.com/microsoft/vscode/issues/345409)

## Summary

Keep open for human security and product review: current configuration hashing does not establish package-content identity. The discussion identifies unresolved trust-provenance and re-review semantics; this supply-chain-sensitive request is protected from closing.

## Change summary

Optionally record and check content identities for package-launched MCP servers, or provide an external pre-start verification hook.

## Best solution

Define an optional content-identity verification contract for MCP launchers that distinguishes repository-provided pins from local approval and first-use recording from explicit re-review. Specify whether verification covers registry metadata or the actual launched artifact before presenting any verified state.

## Evidence

- **Existing-capability check:** src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts defines launcher command, args, environment, sandbox and development properties but no package integrity pin or external verification-hook property. Arbitrary launcher arguments permit Docker digest references and verifier wrappers, but do not provide the requested client-managed recording and checking lifecycle.
- **Configuration identity is not content identity:** src/vs/workbench/contrib/mcp/common/mcpTypes.ts: McpServerLaunch.fromServerConfiguration copies launcher configuration; McpServerLaunch.hash hashes JSON.stringify(launch), not package bytes or registry artifact hashes. Unchanged launch configuration therefore does not identify changed package content.
- **Complete discussion:** https://github.com/microsoft/vscode/issues/345409#issuecomment-6559007968 identifies npm dist.integrity, PyPI per-file digests and OCI digests as existing sources, and raises repository-pin versus local-approval provenance, trust-on-first-use labeling and explicit re-review. This is community design input, not an accepted maintainer decision.
