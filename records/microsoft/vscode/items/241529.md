# Issue #241529 — Odd colorization of quotes PHP in JS in HTML

[https://github.com/microsoft/vscode/issues/241529](https://github.com/microsoft/vscode/issues/241529)

## Summary

Keep open: the current event-handler grammar splits embedded JavaScript at quotes inside PHP, providing a source-level explanation for the mismatched delimiters. Related reports are closed, but none establishes that this behavior was fixed.

## Change summary

PHP string quotes inside an HTML onclick attribute receive inconsistent highlighting and disrupt the surrounding JavaScript and HTML delimiters.

## Best solution

Make nested PHP tokenization respect PHP string boundaries inside JavaScript-valued HTML attributes, while preserving ordinary HTML attribute termination. Establish the responsible HTML/PHP grammar boundary and coordinate any upstream grammar change before adopting it here.

In https://github.com/microsoft/vscode/issues/241529#issuecomment-2683133517, the reporter clarifies that the PHP double quotes differ in color and highlighting spills into the closing HTML attribute delimiter; this directly addresses the maintainer's initial non-reproduction.
- **Current source boundary:** extensions/html/syntaxes/html.tmLanguage.json:155–223 recognizes onclick as an event handler, then retokenizes chunks using source.js. Its double-quoted attribute content match, ([^\n"/]|/(?![/*]))+, consumes myfunc(<?php echo but stops before the PHP opening double quote. Consequently the captured JavaScript/PHP tokenization cannot carry the PHP string across that boundary, and the outer HTML rule can interpret that quote as its attribute terminator.

PHP recognition therefore exists, but does not remove the HTML event-handler capture boundary.
