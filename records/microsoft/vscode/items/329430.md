# Issue #329430 — Agent Host: Peer-chat subagent replay corrupts backend session URI

[https://github.com/microsoft/vscode/issues/329430](https://github.com/microsoft/vscode/issues/329430)

## Summary

Well-diagnosed, currently-reproducible bug: peer-chat subagent history restore stamps a malformed backend session URI. Already correctly labeled (bug, agent-host) by the reporting team member — nothing to change, just needs the fix implemented.

## Change summary

After restarting a persisted peer-chat with completed subagents, history reconstruction builds a corrupted `ahp-chat`+base64 session URI for restored subagent tool calls, so backend lookup fails and subagent history/state isn't restored.

## Best solution

Implement the reporter's own suggested fix: keep the logical backend `sessionUri` distinct from the storage/routing URI (`_storageUri`) throughout the replay path in copilotAgentSession.ts / mapSessionEvents.ts, stamp restored subagent tool metadata with `buildSubagentChatUri(parentSessionUri, toolCallId)`, register discovered peer-chat subagent state, and harden `parseChatUri()` against unexpected extra path segments as defense in depth.

## Evidence

- **confirmed _storageUri source:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:836-838 — `_storageUri` returns the `ahp-chat` channel URI for any non-default chat (peer chats), not the backend `sessionUri`.
- **getSubagentSessions uses storage URI:** copilotAgentSession.ts:2353,2373 builds `parentSessionStr = this._storageUri.toString()` and passes it into `buildSubagentSessionUri(parentSessionStr, tc.toolCallId)` — for a peer chat this is the ahp-chat channel string, not a backend session URI.
- **_computeMappedEvents also uses storage URI:** copilotAgentSession.ts:2417 calls `mapSessionEvents(this._storageUri, db, events, …)`, and mapSessionEvents.ts:833 in turn calls `buildSubagentSessionUri(sessionUriStr, d.toolCallId)` with that same storage URI.
- **parseChatUri decodes the corrupted path:** src/vs/platform/agentHost/common/state/sessionState.ts:964-991 — for a subagent chat authority it splits `encoded` on `/` and base64-decodes only the first segment as the session, discarding/mangling any extra `/subagent/<id>` suffix appended by the mis-typed builder call, exactly matching the reported corruption.
- **second exposure point:** copilotAgentSession.ts:4065 also builds `buildSubagentSessionUri(this._storageUri.toString(), parentToolCallId)` for telemetry, sharing the same storage/session conflation.
