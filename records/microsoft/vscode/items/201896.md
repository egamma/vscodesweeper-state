# Issue #201896 — undo/redo "chunking" broken for find/replace input

[https://github.com/microsoft/vscode/issues/201896](https://github.com/microsoft/vscode/issues/201896)

## Summary

A real consistency gap remains: shared native input boxes still rely on Chromium's character-by-character undo grouping, unlike Monaco-backed inputs. The existing `under-discussion` and `editor-find` routing is appropriate while maintainers decide whether shared custom undo behavior is warranted.

## Change summary

Group rapid repeated deletions in find, replace, and quick-open inputs into a single undo operation.

## Best solution

Decide whether `InputBox` should provide a shared undo stack or whether Chromium's native behavior should remain; any change belongs in the base input-box implementation so find, search, and quick input stay consistent.
