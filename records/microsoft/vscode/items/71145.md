# Issue #71145 — Debug: Server ready action pattern should have validation

[https://github.com/microsoft/vscode/issues/71145](https://github.com/microsoft/vscode/issues/71145)

## Summary

The validation gap remains in current source: invalid server-ready patterns have neither schema validation nor a dedicated startup diagnostic. The linked implementation PR closed without merging, and the related JSON language-service enhancement remains open.

## Change summary

Validate invalid regular expressions in serverReadyAction.pattern and provide actionable feedback instead of silently losing server-ready detection.

## Best solution

Provide regex diagnostics for serverReadyAction.pattern in launch.json and an explicit diagnostic when an invalid pattern reaches debug startup. Coordinate editor validation with the JSON language-service enhancement while preserving valid-pattern behavior.

## Plan brief

- **Likely files:** `extensions/debug-server-ready/package.json`, `extensions/debug-server-ready/src/extension.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Using an existing runnable debug configuration, set serverReadyAction.pattern to '[unclosed': verify launch.json reports an invalid-regex diagnostic and debug startup provides actionable feedback if the invalid value reaches runtime. Repeat for all serverReadyAction alternatives, then verify a valid capturing pattern still triggers the configured action and an omitted pattern retains existing default behavior.
- **Behavior:**

  > An invalid regular expression in serverReadyAction.pattern currently receives no regex-specific editor validation and reaches an unguarded compilation during debug startup. Users should receive an actionable diagnostic identifying the invalid field. Acceptance covers each action variant, invalid patterns that reach startup, valid matching patterns, and the existing default when the pattern is omitted.
- **Trace:**

  > extensions/debug-server-ready/package.json contains four pattern schema declarations, each limited to string typing. ServerReadyDetector.start in extensions/debug-server-ready/src/extension.ts constructs a detector whose constructor directly compiles the configured expression; activate and startTrackerForType both reach this path. The JSON server in extensions/json-language-features/server/src/jsonServer.ts uses vscode-json-languageservice, whose regex-format enhancement remains tracked at https://github.com/microsoft/vscode-json-languageservice/issues/289. The earlier attempt at https://github.com/microsoft/vscode/pull/270244 closed without merging. Preserve valid-pattern matching, capture substitution, action selection, and omitted-pattern defaults; the uncertainty is the observable response to an invalid explicit pattern, not how to structure the implementation.
- **Open decisions:**
  - When an invalid explicit pattern reaches debug startup, should the debug launch be rejected, or should debugging continue with the server-ready action disabled after displaying a diagnostic?

## Evidence

- **Current schema:** extensions/debug-server-ready/package.json declares pattern as a string in all four serverReadyAction alternatives, without regex-format validation. The existing schema does not cover the requested invalid-regex diagnostic.
- **Current startup path:** In extensions/debug-server-ready/src/extension.ts, ServerReadyDetector.start constructs ServerReadyDetector, whose constructor directly calls new RegExp(session.configuration.serverReadyAction.pattern || PATTERN, 'i'). A nonempty invalid pattern such as '[unclosed' throws without a dedicated configuration diagnostic. Both the debug-start listener and debug-adapter tracker factory reach this constructor.
- **Unmerged implementation:** https://github.com/microsoft/vscode/pull/270244 explicitly references this issue and proposes schema and runtime validation, but GitHub reports CLOSED with mergedAt and mergeCommit both null. Its proposed changes are not evidence of a landed fix.
- **Related language-service work:** https://github.com/microsoft/vscode-json-languageservice/issues/289 remains open and explicitly identifies this issue as requiring regex-format support. The maintainer clarification at https://github.com/microsoft/vscode-json-languageservice/issues/289#issuecomment-3594498317 confirms the requested optional validation behavior. This dependency work does not independently cover the missing startup diagnostic.
