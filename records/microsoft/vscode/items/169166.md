## Summary

The confirmed compound-debugging race is addressed on current main: concurrent requests no longer return premature task success, and instead await the existing task's completion. The fixing change landed after this issue was reopened.

## Change summary

Ensure every debug configuration in a compound waits for its shared preLaunchTask before starting or attaching.

This changes the precise premature-success outcome identified by the maintainer. The change merged through https://github.com/microsoft/vscode/pull/180546.
- **Supporting startup synchronization:** https://github.com/microsoft/vscode/pull/180617 merged before the fixing change and makes TerminalTaskSystem._executeTask register the task and its completion promise synchronously, before terminal acquisition. Concurrent callers can therefore reuse the pending execution rather than miss a task that is still starting.

The premature-success guard is absent; TerminalTaskSystem.run returns terminalData.promise for an existing instance, AbstractTaskService returns that promise, and DebugTaskRunner awaits it for the foreground sleep task. The original bypass does not reproduce in this source trace; no runtime execution was performed.
