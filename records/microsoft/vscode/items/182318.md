- **Validation:** After agreeing on the awareness contract, open a merge fixture containing Git conflict markers whose changes the merge editor automatically handles. Verify that users can discover the automatic resolution and inspect the affected result using keyboard and screen-reader interaction; verify that an ordinary non-conflicting change and a manually handled conflict are not falsely attributed to editor-only resolution.
- **Behavior:**

  > When Git reports a conflict that the merge editor can resolve automatically, users should understand that the editor performed that resolution and be able to inspect its result. The awareness mechanism must be discoverable and accessible without requiring users to infer the event from a reduced remaining-conflict count. Acceptance should distinguish this case from ordinary non-conflicting changes and manual conflict handling. The issue does not specify whether awareness is automatic or explicitly requested.
- **Trace:**

  > WorkspaceMergeEditorModeFactory in src/vs/workbench/contrib/mergeEditor/browser/mergeEditorInputModel.ts detects the presence of conflict markers and supplies resetResult to MergeEditorModel. MergeEditorModel.reset and computeAutoMergedResult automatically handle one-sided and equal changes, while ResultCodeEditorView displays remaining conflicts and handled/conflicting decorations. The existing merge.showNonConflictingChanges command exposes otherwise hidden changes, but does not establish provenance identifying which original Git conflicts the editor resolved. The uncertainty starts at the user-visible awareness contract and how precisely the original Git conflict regions must be identified. Preserve existing automatic merge results, manual acceptance behavior and completion semantics. https://github.com/microsoft/vscode/issues/162039 is related navigation work, not a verified canonical for this awareness requirement.
- **Open decisions:**
  - Should users receive automatic awareness when the merge editor resolves a Git conflict, or discover this through an explicit inspection action?
  - Should awareness provide only a file-level summary, or identify each original Git conflict region that the editor resolved?
