# Issue #181369 — Expose ability to replace an existing Output along with the metadata

[https://github.com/microsoft/vscode/issues/181369](https://github.com/microsoft/vscode/issues/181369)

## Summary

The requested API capability is still missing: targeted output-item replacement preserves existing metadata, while whole-cell replacement requires supplying all outputs. Keep this team-authored, accepted backlog item open; no verified canonical or issue-referencing fix was found.

## Change summary

Allow notebook extensions to replace one existing output's items and metadata without replacing the cell's other outputs or waiting for pending additions to reach the notebook model.

## Best solution

Provide an execution API for targeted replacement of a complete notebook output, including metadata, while preserving neighboring outputs and ordered pending updates. Review the proposed overload's public contract before implementing it across the execution update pipeline.

- **Validation:** Add notebook execution API coverage that queues three output additions and immediately replaces the second output's items and metadata without awaiting model synchronization. Verify the final three-output order, unchanged neighboring items and metadata, updated target items and metadata, and continued documented behavior of existing replaceOutput and replaceOutputItems calls.
- **Behavior:**

  > An extension executing a notebook cell must be able to replace one previously submitted output's items and metadata without supplying the entire cell output list. With three outputs, replacing the second leaves the first and third unchanged and preserves their order. The operation must also work when the original output addition is still pending synchronization. Existing whole-cell replacement and item-only replacement remain compatible.
- **Trace:**

  > NotebookCellExecutionTask in src/vs/workbench/api/common/extHostNotebookKernels.ts batches output updates through TimeoutBasedCollector. updateOutputs carries complete outputs but targets the cell, while updateOutputItems targets output.id and carries no metadata. ICellExecuteOutputItemEdit in src/vs/workbench/contrib/notebook/common/notebookExecutionService.ts and updateToEdit in src/vs/workbench/contrib/notebook/browser/services/notebookExecutionStateServiceImpl.ts preserve that limitation. NotebookCellTextModel.changeOutputItems explicitly retains old metadata; its internal replaceOutput accepts complete data but is not a public execution API. https://github.com/microsoft/vscode/issues/178307 explicitly distinguishes the already-supported targeting mechanism from the remaining metadata problem. The unresolved public-contract boundary is output identity after complete replacement; do not broaden this work into whole-cell replacement regressions such as https://github.com/microsoft/vscode/issues/173577.
- **Open decisions:**
  - After targeted complete-output replacement, should subsequent updates continue to target the original output object, or must they target the replacement output object?
