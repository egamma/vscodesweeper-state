# Issue #225231 — Git - Source Control / File Watcher does not respect settings

[https://github.com/microsoft/vscode/issues/225231](https://github.com/microsoft/vscode/issues/225231)

## Summary

Keep open: current settings do not provide the requested strict repository allowlist within a larger shared workspace. The reported scanning follows the existing settings' semantics, but that does not resolve the accepted request to limit discovery.

## Change summary

Allow users to restrict Git repository discovery to explicitly selected directories without narrowing the shared workspace.

## Best solution

Define an explicit selective-discovery contract in the built-in Git extension that can retain selected repositories while preventing discovery elsewhere. Keep filesystem watching and Git discovery distinct, and document how selective discovery interacts with automatic scanning and opening files.

  > Thanks for the detailed examples. `git.scanRepositories` adds paths to automatic scanning; it does not restrict scanning to those paths, and it is currently skipped when `git.autoRepositoryDetection` is false. `git.ignoredRepositories` matches exact repository paths, not glob patterns, while `files.watcherInclude` adds watched paths and does not control Git discovery.

## Evidence

- **Discussion establishes the remaining requirement:** https://github.com/microsoft/vscode/issues/225231: the reporter tried the suggested relative git.scanRepositories paths and still saw unwanted repositories, then clarified that the shared /data/home workspace uses Remote SSH. A second user reported similar limitations with an AOSP tree on VS Code 1.118.1 over SSH.
- **Git scan paths are additive, not an allowlist:** extensions/git/src/model.ts:361–402, Model.scanWorkspaceFolders, first enumerates workspace subfolders and then adds git.scanRepositories entries to that set. It rejects absolute entries and returns before reading scanRepositories when git.autoRepositoryDetection is false. These branches directly explain the reported configurations; they do not establish a strict selected-directories mode.
- **Existing restrictions provide only partial coverage:** extensions/git/package.json registers git.repositoryScanMaxDepth and git.repositoryScanIgnoredFolders. Model.traverseWorkspaceFolder compares ignored folder names exactly, while Model.shouldRepositoryBeIgnored at extensions/git/src/model.ts:740–760 compares exact repository paths rather than glob patterns. Therefore alps/** and alps/* are not subtree exclusions. Limiting traversal depth can reduce discovery, but does not create a global allowlist across discovery paths.
- **Watcher includes do not restrict Git discovery:** src/vs/workbench/contrib/files/browser/files.contribution.ts describes files.watcherInclude as extra watched paths. WorkspaceWatcher.watchWorkspace at src/vs/workbench/contrib/files/browser/workspaceWatcher.ts:133–184 always includes the workspace root, adds include paths, and passes watcher exclusions to fileService.watch. Git's initial traversal separately uses fs.promises.readdir in extensions/git/src/model.ts, not these watcher settings.

It describes an explicitly ignored SSHFS repository being discovered when opening a file; it does not own the broader selected-directory scanning requirement, including git.scanRepositories with automatic detection disabled. https://github.com/microsoft/vscode/issues/41565 is also open and older, but requests discovery of additional ignored nested repositories rather than restricting discovery.
