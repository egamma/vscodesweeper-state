# Issue #246058 — Independent options to enable/disable preview for the editor and source control management

[https://github.com/microsoft/vscode/issues/246058](https://github.com/microsoft/vscode/issues/246058)

## Summary

Independent Explorer and Source Control preview behavior remains unsupported by the current settings. Keep this accepted Backlog request open: it has 35 upvotes, and neither the existing workarounds nor the two closed predecessor requests resolve it.

## Change summary

Allow ordinary files to open in persistent tabs while Source Control diffs open in reusable preview tabs.

## Best solution

Provide independent preview control for Source Control and ordinary file opening, preserving existing behavior when no override is configured. Settle the configuration contract and its interaction with the global preview setting before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/common/editor.ts`, `src/vs/workbench/browser/parts/editor/editorGroupView.ts`, `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/contrib/files/browser/views/explorerView.ts`, `src/vs/workbench/services/editor/test/browser/editorGroupsService.test.ts`
- **Validation:** Add editor-group tests covering the chosen preview-policy contract. Manually single-click two Explorer files and then two tracked-file changes in Source Control: ordinary files must remain in separate tabs while successive diffs reuse a preview tab. Verify explicit double-click keeps a diff open and unconfigured behavior remains unchanged.
- **Behavior:**

  > Users should be able to keep ordinary file tabs persistent while browsing Source Control changes in a reusable preview tab, without repeatedly double-clicking files or manually closing diffs. Acceptance requires opening two ordinary files and retaining both tabs, then opening two SCM diffs without retaining both as persistent tabs. Explicitly keeping a diff open must continue to work. Existing behavior must remain unchanged when the new control is not configured.
- **Trace:**

  > The relevant configuration is registered in src/vs/workbench/browser/workbench.contribution.ts; existing source-specific controls cover Quick Open and code navigation, not Explorer versus SCM. EditorGroupView.doOpenEditor in src/vs/workbench/browser/parts/editor/editorGroupView.ts globally pins non-transient editors when enablePreview is false, so a caller's pinned: false alone cannot provide the requested behavior. ExplorerView in src/vs/workbench/contrib/files/browser/views/explorerView.ts passes tree editor options to the editor service. SCMViewPane.open in src/vs/workbench/contrib/scm/browser/scmViewPane.ts dispatches provider resource commands; the built-in Git resolver in extensions/git/src/repository.ts uses vscode.open or vscode.diff. The uncertainty is the public setting scope and precedence, not whether the current registrations provide this capability. Preserve explicit keep-open gestures, dirty-editor protection, and existing defaults; automatic diff cleanup is not a substitute. The predecessor requests https://github.com/microsoft/vscode/issues/187186 and https://github.com/microsoft/vscode/issues/149891 were closed for insufficient votes and supply historical demand, not implementation decisions.
- **Open decisions:**
  - Should the new control apply to all editors opened from Source Control, only SCM diff editors, or all diff editors regardless of where they are opened?
  - Should independence be exposed through an SCM override that can enable previews while workbench.editor.enablePreview is false, or through an Explorer-specific opt-out while global preview remains enabled?

## Evidence

- **Existing settings do not cover the request:** src/vs/workbench/browser/workbench.contribution.ts:331-345 registers workbench.editor.enablePreview, workbench.editor.enablePreviewFromQuickOpen, and workbench.editor.enablePreviewFromCodeNavigation. The latter two address different entry points; there is no corresponding independent Explorer or SCM preview setting in the inspected registrations.
- **Global preview policy remains decisive:** src/vs/workbench/browser/parts/editor/editorGroupView.ts:1190-1217, EditorGroupView.doOpenEditor, pins non-transient editors whenever the global enablePreview option is false, even if the caller supplies pinned: false. Ordinary SCM diffs therefore cannot independently request reusable preview tabs through that option.
- **SCM opening path:** src/vs/workbench/contrib/scm/browser/scmViewPane.ts:1670-1735 dispatches vscode.open/vscode.diff resource commands with the tree open event. extensions/git/src/repository.ts:517-562, resolveDefaultCommand and resolveChangeCommand, selects file versus diff opening but supplies no independent SCM preview policy.
