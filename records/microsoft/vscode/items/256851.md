# Issue #256851 — Do not move my cursor while typing

[https://github.com/microsoft/vscode/issues/256851](https://github.com/microsoft/vscode/issues/256851)

## Summary

Keep open: current source still allows an automatically triggered next edit suggestion to capture Tab while the user is indenting a nonempty line, moving the cursor or accepting an unrelated edit. The discussion confirms this workflow; available workarounds do not resolve the keybinding conflict.

## Change summary

Prevent next edit suggestions from hijacking Tab-based indentation and unexpectedly relocating the cursor after pasting code.

## Best solution

Preserve ordinary indentation during manual code cleanup while retaining deliberate NES navigation and acceptance. Agree on the user-visible precedence rule for Tab, then cover it in the inline-completions model and keybinding behavior.

Cover repeated indentation, intentional NES acceptance outside the protected context, and Escape followed by Tab. Run the targeted Inline Edits suite with scripts/test.sh --run src/vs/editor/contrib/inlineCompletions/test/browser/inlineEdits.test.ts in an implementation workspace.
- **Behavior:**

  > After pasting code, users must be able to indent and review nonempty lines without Tab unexpectedly navigating to or applying an automatic next edit suggestion. Repeated indentation must keep the cursor on the line being edited and must not modify unrelated code. NES should remain available for deliberate navigation and acceptance. Acceptance checks must cover a multiline suggestion, repeated Tab presses, and dismissal before indentation; the maintainer must first settle which editing contexts give indentation precedence.
- **Trace:**

  > InlineCompletionsController triggers suggestions on onDidPaste, onDidType, and execution of the ordinary Tab command. InlineCompletionsModel._tabShouldIndent protects multiline/full-line selections and completely empty lines, but not an empty selection in leading whitespace on a nonempty line. Its tabShouldJumpToInlineEdit and tabShouldAcceptInlineEdit values feed the Tab bindings in controller/commands.ts; jump() sets the cursor to the NES target. The existing Inline Edits suite provides a mock suggestion provider and asynchronous editor/model harness. Preserve intentional NES acceptance and unrelated IntelliSense behavior; do not treat the unconfirmed Escape complaint as diagnosed. https://github.com/microsoft/vscode/issues/257073 records maintainer interest in de-conflicting Tab, while https://github.com/microsoft/vscode/issues/255143 documents the bracket-alignment case and https://github.com/microsoft/vscode/issues/283075 provides broader suggestion-timing context.
- **Open decisions:**
  - Should Tab always prioritize indentation for an empty selection in leading whitespace on a nonempty line, including when a NES targets that same line, or should this protection apply only during a post-paste/manual-indentation interaction?
