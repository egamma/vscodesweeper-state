# Issue #290905 — sessions buttons: preference on buttons

[https://github.com/microsoft/vscode/issues/290905](https://github.com/microsoft/vscode/issues/290905)

## Summary

The current default compact layout already puts the chat/dropdown section after the session indicators, while badge mode retains the original order. Keep this team-authored design discussion open: no verified issue-referencing fix establishes completion, and the remaining decision is whether badge mode should adopt that arrangement despite the entry-point movement concern.

## Change summary

Prefer arranging the session-status buttons so the chat dropdown chevron sits at the far right.

## Best solution

Have the UX owner compare the current compact and badge layouts against the proposed arrangement, including changes between idle, running, and unread states. Resolve whether badge mode should also place the chat/dropdown section last while keeping the chat entry point predictably positioned.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/experiments/agentTitleBarStatusWidget.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/experiments/media/agenttitlebarstatuswidget.css`
- **Validation:** In a running workbench, compare chat.agentsControl.enabled set to compact and badge with chat.viewSessions.enabled enabled. Exercise no sessions, running sessions, unread sessions, and combined states; verify the agreed button order and chat-entry-point positioning, then check chat toggle, dropdown actions, status filtering, and keyboard traversal.
- **Behavior:**

  > The proposal makes the chat dropdown chevron the trailing affordance of the session-status control. Current compact mode already follows that ordering, while badge mode does not. The design must decide whether both modes should follow it and address the reported concern that changing status indicators can move the chat target. Acceptance should cover idle, running, unread, and combined states without changing the controls' existing actions or keyboard usability.
- **Trace:**

  > The original test surface is documented at https://github.com/microsoft/vscode/issues/290650. AgentTitleBarStatusWidget._renderStatusBadge in src/vs/workbench/contrib/chat/browser/agentSessions/experiments/agentTitleBarStatusWidget.ts constructs the chat primary action and dropdown together, then selects ordering based on whether an inlineContainer was supplied. Compact rendering supplies the pill and appends the chat/dropdown section last; standalone badge rendering appends it first. Both visual ordering and roving keyboard navigation are assembled in this method. The current default is compact, as registered in chat.shared.contribution.ts. The uncertainty is the desired badge-mode behavior and positional stability, not the existing toggle, menu, or filtering semantics; preserve those semantics. The maintainer's unresolved tradeoff is recorded at https://github.com/microsoft/vscode/issues/290905#issuecomment-3807662892.
- **Open decisions:**
  - Should badge mode also place the chat/dropdown section after all session-status indicators, or should the two modes intentionally retain different ordering?
  - If badge mode adopts trailing chat controls, must the chat entry point remain positionally stable as status indicators appear and disappear, or is movement acceptable?
