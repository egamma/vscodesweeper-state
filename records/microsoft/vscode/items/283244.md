# Issue #283244 — Adopt per-TextChunk references in chat

[https://github.com/microsoft/vscode/issues/283244](https://github.com/microsoft/vscode/issues/283244)

## Summary

This migration remains partially incomplete on current main. Several prompt components still report references globally or omit them from their prunable text chunks, so references can outlive the content they describe.

## Change summary

Associate chat prompt references with individual TextChunk or CodeBlock content so pruning also removes references for omitted context.

## Best solution

Complete the migration across the remaining prompt components while preserving intentional aggregate outputs such as `referencesOut`; define and test the range deduplication semantics for workspace chunks before implementation.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/prompts/node/panel/workspace/workspaceContext.tsx`, `extensions/copilot/src/extension/prompt/node/testExample.tsx`, `extensions/copilot/src/extension/prompts/node/panel/symbolAtCursor.tsx`, `extensions/copilot/src/extension/prompts/node/panel/definitionAtPosition.tsx`, `extensions/copilot/src/extension/intents/node/testIntent/summarizedDocumentWithSelection.tsx`, `extensions/copilot/src/extension/prompt/node/intentDetector.tsx`
- **Validation:** Add focused prompt-rendering unit tests that force prioritization to remove individual workspace, definition, test-example, and summarized-document chunks, then assert that only references belonging to surviving chunks appear in the rendered prompt result.
- **Behavior:**

  > Chat should report a file or range reference only when the prompt content derived from that source survives token-budget prioritization and is sent to the language model. Pruning one source chunk must remove that chunk's reference without removing references for surviving chunks. Existing reference metadata and intentional aggregate outputs used outside prompt rendering must remain available. Acceptance requires prompt-rendering tests covering both retained and pruned chunks.
- **Trace:**

  > `CodeBlock` in `extensions/copilot/src/extension/prompts/node/panel/safeElements.tsx` already scopes its `references` prop inside the generated `TextChunk`, and several listed consumers have adopted it. `WorkspaceChunkList.render` in `workspaceContext.tsx` instead emits all references before rendering independently prioritized chunks, while `TestExample` and `SymbolAtCursor` have similar aggregate placement. `DefinitionAtPosition` and `SummarizedDocumentWithSelection` render source-bearing code blocks without references. The boundary is prompt reference attribution: prompt text, priority order, ignore-file handling, reply-interpreter metadata, and external `referencesOut` behavior must not change. The legacy discussion at https://github.com/microsoft/vscode-copilot/issues/5356 leaves uncertainty around adjacent and overlapping workspace ranges.
- **Open decisions:**
  - Should adjacent workspace ranges be merged, kept as distinct per-chunk references, or represented both per chunk and in a separately deduplicated aggregate?
  - Which existing aggregate reference outputs, especially `WorkspaceChunkList.referencesOut`, are compatibility contracts that must remain independent of rendered-chunk pruning?
  - Should empty-document messages retain file-level references even though they contain no code chunk?

## Evidence

- **incomplete workspace path:** `extensions/copilot/src/extension/prompts/node/panel/workspace/workspaceContext.tsx` still emits one global `<references value={references} />` before separately prioritized `TextChunk` elements; its TODO explicitly says the references should be tied to the rendered user message.
- **remaining global references:** `extensions/copilot/src/extension/prompt/node/testExample.tsx` and `extensions/copilot/src/extension/prompts/node/panel/symbolAtCursor.tsx` still emit aggregate `<references>` elements outside the corresponding prunable `CodeBlock` content.
- **missing scoped references:** `extensions/copilot/src/extension/prompts/node/panel/definitionAtPosition.tsx` and `extensions/copilot/src/extension/intents/node/testIntent/summarizedDocumentWithSelection.tsx` render source content through `CodeBlock` without supplying references.
- **migration mechanism exists:** `extensions/copilot/src/extension/prompts/node/panel/safeElements.tsx` already accepts `CodeBlockProps.references` and places the `<references>` element inside the generated `TextChunk`; `currentEditor.tsx`, `currentSelection.tsx`, and `symbolDefinitions.tsx` demonstrate partial adoption.
- **migrated tracker:** The closed legacy tracker https://github.com/microsoft/vscode-copilot/issues/5356 points to https://github.com/microsoft/vscode/issues/283244 as its public replacement; it was not closed because the work was completed.
- **open semantic question:** Discussion on https://github.com/microsoft/vscode-copilot/issues/5356 raised unresolved handling for neighboring and overlapping workspace ranges; current `WorkspaceChunkList.toReferences` deduplicates contained ranges but does not merge adjacent ranges.
