# Issue #182034 — Right Overflow

[https://github.com/microsoft/vscode/issues/182034](https://github.com/microsoft/vscode/issues/182034)

## Summary

Thanks for the original report and the detailed follow-ups. Current main contains a CSS/listView mechanism (`--list-scroll-right-offset` in src/vs/workbench/browser/parts/views/media/views.css and src/vs/base/browser/ui/list/listView.ts) that specifically repositions row actions back into view when horizontal scrolling pushes them off-screen — the exact failure mode described here (actions disappearing when `workbench.list.horizontalScrolling: true` and item names overflow the panel width, as alexr00 diagnosed in the thread). However, the prior review's citation of that fix commit was independently refuted, and that commit's own message targets a different issue number, so I can't confirm from source alone whether it fully covers this report's repro. Given that uncertainty, this needs a fresh confirmation from the reporter on a current build rather than a close.

## Change summary

Action buttons on the right side of a tree/list row (explorer, remote explorer, npm scripts) disappear or are pushed out of view when the row's content width exceeds the panel width and horizontal scrolling is enabled.

## Best solution

Have the reporter re-test on the latest build with `workbench.list.horizontalScrolling: true` and a long item name; if actions are still cut off, a maintainer should diagnose why the existing `--list-scroll-right-offset` repositioning (views.css / listView.ts) doesn't cover this exact case (e.g. scroll position timing, specific view types, or decorations) and extend it.
