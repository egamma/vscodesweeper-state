# Issue #79080 — Bring the "track changes" feature to VS Code

[https://github.com/microsoft/vscode/issues/79080](https://github.com/microsoft/vscode/issues/79080)

## Summary

Keep this accepted request open: current comparison tools do not provide saved-versus-unsaved line indicators for files outside version control. The closely related local-history gutter request is newer, so it cannot replace this re-reviewed issue as a duplicate canonical.

## Change summary

Provide editor gutter indicators for local files that distinguish unsaved edits from changes saved since the file was opened.

## Best solution

Provide repository-independent, session-based line-change indicators while preserving existing SCM decorations. Coordinate with the related local-history gutter request, but settle the baseline lifetime and interaction with SCM before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/common/quickDiffService.ts`, `src/vs/workbench/contrib/scm/browser/quickDiffModel.ts`, `src/vs/workbench/contrib/scm/browser/quickDiffDecorator.ts`, `src/vs/workbench/contrib/scm/browser/quickDiff.contribution.ts`, `src/vs/workbench/contrib/localHistory/browser/localHistoryTimeline.ts`
- **Validation:** In a folder without a Git repository, open an existing file, add and modify lines, save, then edit again. Verify unsaved changes have a distinct indicator, saving retains session-change indicators rather than clearing them, and subsequent unsaved edits remain distinguishable; repeat in a Git repository to verify the agreed SCM coexistence behavior.
- **Behavior:**

  > Local files outside version control should show line-change indicators during editing. Unsaved edits must be distinguishable from changes saved since the file was opened, and saving must not erase all evidence of session changes. Acceptance should exercise edit, save, and further edit sequences in a non-Git folder and verify that existing SCM indicators remain usable in Git-backed files.
- **Trace:**

  > QuickDiffService.getQuickDiffs in src/vs/workbench/contrib/scm/common/quickDiffService.ts resolves comparison resources supplied by registered providers, while quickDiffModel.ts computes changes and quickDiffDecorator.ts presents decorations. The configuration in quickDiff.contribution.ts controls decoration presentation rather than establishing session and save baselines. LocalHistoryTimeline in src/vs/workbench/contrib/localHistory/browser/localHistoryTimeline.ts exposes saved snapshots through Timeline; the Compare with Saved command in src/vs/workbench/contrib/files/browser/fileCommands.ts opens an explicit disk comparison. Neither inspected surface supplies the requested continuous two-state tracking. Coordinate product semantics with https://github.com/microsoft/vscode/issues/167306, which additionally requests reset and reopening controls; it is newer and is not a duplicate target for this re-reviewed report. Preserve existing SCM comparison meanings and local-history retention behavior; the unresolved boundary is the tracking lifetime and how its indicators share the editor gutter with SCM.
- **Open decisions:**
  - Should the opening baseline reset when an editor tab closes and reopens, or should session markers survive until an explicit reset or window reload?
  - For files covered by an SCM provider, should session-change indicators coexist with SCM indicators or be limited to files without an SCM baseline?
