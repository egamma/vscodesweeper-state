# Issue #145661 — `CallHierarchyProvider`'s provided name should be used in references window for previous searches when there is no result for call hierarchy search

[https://github.com/microsoft/vscode/issues/145661](https://github.com/microsoft/vscode/issues/145661)

## Summary

Still a real gap on current main: the References view labels history entries with the word at the cursor, never with the CallHierarchyItem's provided name, so keep this open as a Backlog feature request in the references-view extension (now in-repo at extensions/references-view).

## Change summary

Ask for the References view's previous-searches (history) entries to be labelled with the CallHierarchyItem's name/detail rather than the word under the cursor at search time.

## Best solution

Let a SymbolTreeInput optionally carry a display label (resolved from the prepared CallHierarchyItem's name/detail) and have TreeInputHistory.add use it instead of the word-at-position fallback in extensions/references-view/src/tree.ts; falling back to the current word when no label is supplied.

## Evidence

- **gap confirmed on main:** extensions/references-view/src/tree.ts `TreeInputHistory.add` derives the history label purely from the document: `doc.getWordRangeAtPosition(input.location.range.start) ?? ... /[^\s]+/`, falling back to '???'; `HistoryItem.word` is then used as the tree item label (getTreeItem) and as the quick-pick label in `references-view.pickFromHistory`.
- **no provider name available to the history:** The `SymbolTreeInput` contract in extensions/references-view/src/references-view.d.ts exposes only `title` ('Callers Of' / 'Calls From') and `location` — nothing carries the resolved `CallHierarchyItem.name`/`detail`, so `CallsTreeInput` (extensions/references-view/src/calls/model.ts) cannot surface the provided name even though it resolves items via `vscode.prepareCallHierarchy`.
