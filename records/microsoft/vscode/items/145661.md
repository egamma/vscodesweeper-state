# Issue #145661 — `CallHierarchyProvider`'s provided name should be used in references window for previous searches when there is no result for call hierarchy search

[https://github.com/microsoft/vscode/issues/145661](https://github.com/microsoft/vscode/issues/145661)

## Summary

A real gap remains on main: call-hierarchy history still derives its label from text at the cursor, while a generic position check prevents providers from handling empty lines. The issue is already correctly classified and routed in the Backlog.

## Change summary

Use the provider's CallHierarchyItem name and detail for history entries and invoke call-hierarchy providers on empty lines.

## Best solution

Update the built-in references-view extension so CallsTreeInput retains provider-supplied root metadata for history display, while allowing call-hierarchy inputs to bypass the generic word-position restriction.
