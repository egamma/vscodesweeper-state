# Issue #327194 — Settings.json incorrectly marks permitted extension versions as not accepted

[https://github.com/microsoft/vscode/issues/327194](https://github.com/microsoft/vscode/issues/327194)

## Summary

Real regression, root cause confirmed in source, and an open PR already fixes it — keep open until it merges rather than closing now. A real version milestone (1.135.0) is also assigned, which independently bars a close.

## Change summary

The `extensions.allowed` setting's JSON schema wrongly flags valid version-array values (e.g. `["1.31.4"]`) as invalid after a vscode-json-languageservice bump started enforcing validation against every matching `patternProperties` pattern.

## Best solution

Land https://github.com/microsoft/vscode/pull/329744, which anchors the extension-id and publisher-only patternProperties regexes with `^` so a compound key like `ms-vscode.cpptools` no longer matches both patterns; that removes the double-validation and the false warning.
