# Issue #327194 — Settings.json incorrectly marks permitted extension versions as not accepted

[https://github.com/microsoft/vscode/issues/327194](https://github.com/microsoft/vscode/issues/327194)

## Summary

Confirmed bug on main, with an open unmerged PR already fixing it — keep open until that PR lands; also carries a real (non-holding-bin) milestone, which independently bars closing.

## Change summary

The `extensions.allowed` setting schema falsely flags valid per-version arrays (e.g. `["1.31.4"]`) as invalid because two `patternProperties` regexes are anchored only at the end, so a compound key like `ms-vscode.cpptools` matches both the extension-id and publisher-only patterns and gets validated against the incompatible one.

## Best solution

Land and merge PR https://github.com/microsoft/vscode/pull/329744, which anchors both patterns with `^` in extensionManagement.ts so they become mutually exclusive; runtime enforcement is already correct, this is purely a schema/diagnostics fix.
