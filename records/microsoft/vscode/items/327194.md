# Issue #327194 — Settings.json incorrectly marks permitted extension versions as not accepted

[https://github.com/microsoft/vscode/issues/327194](https://github.com/microsoft/vscode/issues/327194)

## Summary

A member (sandy081) already root-caused this: the `extensions.allowed` JSON schema's `patternProperties` are unanchored, so an extension ID like `ms-vscode.cpptools` matches both the extension-ID pattern and the publisher pattern, and the publisher pattern rejects version arrays — surfaced by the upgrade to `vscode-json-languageservice@6.0.0-next.2`, which now validates against every matching pattern property instead of just the first.

## Change summary

Settings.json wrongly flags valid `extensions.allowed` version-array entries (e.g. `"ms-vscode.cpptools": ["1.31.4"]`) as invalid after 1.130.0, even though the setting still functions correctly at runtime.

## Best solution

Anchor the two relevant patternProperties regexes in the `extensions.allowed` schema (add `^` at the start of the extension-ID and publisher-ID patterns) in src/vs/platform/extensionManagement/common/extensionManagement.ts so they no longer both match the same key; this removes the spurious diagnostic while keeping runtime behavior (which already worked) unchanged.

Because the publisher pattern lacks a `^` anchor, it also matches the tail of a full extension ID like `ms-vscode.cpptools` (matching just `cpptools`), so a key like `ms-vscode.cpptools` satisfies BOTH pattern properties. Since vscode-json-languageservice was upgraded to 6.0.0-next.2 (see extensions/json-language-features/server/package.json), it now validates a property against every matching patternProperties schema rather than just one, so the publisher-only schema (which only allows boolean/string, not arrays) now flags legitimate version-array values such as `["1.31.4"]` as invalid, even though the extension host still honors them correctly at runtime. Fix by anchoring both regexes with a leading `^` so they are mutually exclusive (an extension-ID key like `pub.ext` should no longer also match the publisher-only pattern). Do not change the `\*` pattern or the runtime validation/parsing logic that reads `extensions.allowed` values — this is purely a JSON schema diagnostic fix. Add a unit test that validates a sample `extensions.allowed` object containing a publisher.extension key with an array value against the schema and asserts no diagnostics are produced, confirming both before (fails) and after (passes) the anchoring fix.
