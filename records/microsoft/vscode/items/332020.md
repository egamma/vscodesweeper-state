# Issue #332020 — Opening the Agents window briefly revokes shared Agent Host authentication

[https://github.com/microsoft/vscode/issues/332020](https://github.com/microsoft/vscode/issues/332020)

## Summary

Team-authored, freshly filed bug with precise code citations that check out on current main — the shared Agent Host auth path collapses 'not yet loaded' and 'explicit sign-out' into the same empty-token signal, causing a brief false global credential revocation whenever the Agents window opens alongside an authenticated editor window.

## Change summary

Opening the Agents window sends an empty auth token before its provider finishes loading, which Agent Host treats as an explicit sign-out and briefly revokes shared credentials (worst case: Claude tears down and recreates its local proxy, breaking resumed sessions pointed at the old port).

## Best solution

Distinguish 'no answer yet' from 'explicit revocation' in the shared auth path (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts, authenticateProtectedResourceWithServices's `token ?? ''` forwarding and AgentHostAuthenticationService's handling), and make Claude's proxy handle rebind live SDK processes rather than disposing the handle out from under them (claudeAgent.ts / claudeAgentSession.ts).
