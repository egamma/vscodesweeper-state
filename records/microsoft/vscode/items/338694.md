# Issue #338694 — Add an Agent Host URI layer to the layer checker

[https://github.com/microsoft/vscode/issues/338694](https://github.com/microsoft/vscode/issues/338694)

## Summary

Reasonable build-tooling hardening proposal (self-filed, 0 days old, no discussion yet) to add a layer-check rule stopping Agent Host URI code from depending on local-only URI construction; keeping it open for design input since the exact layer boundary and disallowed helpers aren't yet pinned down.

## Change summary

Add a dedicated layer-checker rule for src/vs/platform/agentHost URI handling so shared/opaque host-advertised URIs can't accidentally be rebuilt using local-only URI construction helpers.

## Best solution

Extend build/checker/layersChecker.ts (or a new tsconfig.<layer>.json) with a rule targeting src/vs/platform/agentHost/common URI files that disallows importing local-only default chat URI constructors, backed by a fixture test demonstrating a violation is caught; a maintainer should first confirm which specific helpers/files are in scope given the referenced regression.

## Plan brief

- **Likely files:** `build/checker/layersChecker.ts`, `src/vs/platform/agentHost/common/agentHostUri.ts`, `build/checker/test/`
- **Validation:** A layer-checker fixture/test asserting that a file in the new Agent Host layer importing a local-only default chat URI constructor is flagged as a violation, while opaque host-advertised URI handling is not.
- **Trace:**

  > The layer checker (build/checker/layersChecker.ts) currently only distinguishes common/browser/electron-main/electron-utility layers via glob-matched IRule entries with disallowedTypes; there is no rule isolating src/vs/platform/agentHost URI helpers from VS Code's local default chat URI construction (referenced regression: issue #337859). Do not change the existing native-type rules; scope is additive.
- **Open decisions:**
  - Which exact files/directories form the new Agent Host URI layer (all of src/vs/platform/agentHost/common, or just the URI helper modules)?
  - Which specific local-only/default chat URI construction helpers or types should be disallowed in that layer?
  - Should this be implemented as a new IRule in layersChecker.ts's disallowedTypes list, or as a separate tsconfig.<layer>.json layer like other layer boundaries?

## Evidence

- **layer checker exists:** build/checker/layersChecker.ts defines an IRule[] with glob targets and disallowedTypes, e.g. common/browser/electron-main rules; no Agent Host-specific rule exists there today.
- **referenced regression:** Issue references #337859 ("Agent Host: chat URIs encode the owning session, contrary to AHP"), an open, related issue in the candidate canonicals list, as the motivating regression — but that issue is a separate bug report, not a duplicate of this tooling request.
- **agentHostUri.ts scope:** src/vs/platform/agentHost/common/agentHostUri.ts documents the vscode-agent-host:// scheme and IAgentHostResourceUriMapper, which is the kind of shared URI-handling code the new rule would need to isolate.
