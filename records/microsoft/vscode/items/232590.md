# Issue #232590 — Panel: no drop zone for views after the last panel

[https://github.com/microsoft/vscode/issues/232590](https://github.com/microsoft/vscode/issues/232590)

## Summary

This remains a valid panel-layout polish issue: the discussion identifies why the panel's trailing empty area is not a drop target and clarifies that the desired change should preserve the panel action layout.

## Change summary

Allow a dragged view container to be dropped after the final panel item using the panel header's trailing empty space.

## Best solution

Extend the panel activity-bar drop targeting so the trailing actions/empty region exposes an insertion target after the last view container, without changing the panel's flex-growth behavior or interfering with actions such as the Debug Console filter.
