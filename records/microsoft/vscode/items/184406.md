# Issue #184406 — editor.renderFinalNewline is misleading

[https://github.com/microsoft/vscode/issues/184406](https://github.com/microsoft/vscode/issues/184406)

## Summary

Keep this open as editor-core polish. Current main intentionally applies `editor.renderFinalNewline` only to the final line number, and its description now says so, but the setting identifier remains misleading and the requested full-line hiding behavior is still absent.

## Change summary

Rename or replace `editor.renderFinalNewline` and make its disabled mode completely hide the final empty visual line rather than only its line number.

## Best solution

Editor-core should separate the two concepts: provide an accurately named line-number option with a compatibility path for existing configurations, then decide whether a distinct mode should hide the final visual row without changing the file's trailing-newline contents.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/config/migrateOptions.ts`, `src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts`
- **Validation:** Add focused editor tests for a model ending in a newline that cover the rendered gutter, visible final row, Ctrl+End cursor destination, and unchanged saved contents for both legacy and replacement settings; run the matching editor unit-test selector.
- **Behavior:**

  > For a file ending in a newline, the setting's name and description must match what users see. If a full-hide mode is adopted, selecting it must remove the final empty visual row and prevent navigation into that displayed row while preserving the file's trailing newline. Existing `editor.renderFinalNewline` configurations must retain defined compatibility behavior.
- **Trace:**

  > `EditorOptions.renderFinalNewline` is registered in src/vs/editor/common/config/editorOptions.ts and consumed by `LineNumbersOverlay` in src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts. The `off` branch only assigns an empty string to `renderLineNumber`; the view-model line remains present, so cursor movement and layout are unaffected. Boolean-to-enum compatibility already passes through src/vs/editor/browser/config/migrateOptions.ts. The setting originated in https://github.com/microsoft/vscode/pull/64667 as control over the numbered blank line, with the author explicitly noting naming uncertainty. The boundary is editor presentation and navigation: trailing-newline file contents and `files.insertFinalNewline`/`files.trimFinalNewlines` semantics must not change.
- **Open decisions:**
  - Should this remain naming-only polish, or should VS Code add the requested mode that hides the final visual row?
  - Should compatibility use a deprecated alias, a new setting, or revised enum values under the existing setting?
  - If the final row is hidden, where should Ctrl+End and cursor movement land while preserving the underlying trailing newline?

## Evidence

- **current implementation:** src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts handles `editor.renderFinalNewline` exclusively inside LineNumbersOverlay: `off` clears `renderLineNumber`, while `dimmed` adds a line-number CSS class. It does not remove the final view-model line.
- **current setting description:** src/vs/editor/common/config/editorOptions.ts registers the setting with the description “Render last line number when the file ends with a newline.” This accurately documents the current behavior but does not resolve the misleading `renderFinalNewline` identifier.
- **origin:** https://github.com/microsoft/vscode/pull/64667 introduced the setting specifically to control display of the numbered blank line and explicitly noted uncertainty about the naming. Its merge commit is 3d662dd0e1eb1e89e3dd10c3235a8f9a87f58e53.
