# Issue #184406 — editor.renderFinalNewline is misleading

[https://github.com/microsoft/vscode/issues/184406](https://github.com/microsoft/vscode/issues/184406)

## Summary

The final empty row is intentionally retained because it remains an editable model line, but the setting ID and enum values describe that behavior imprecisely. Keep this open as editor configuration polish while preserving the established model and extension behavior.

## Change summary

Make `editor.renderFinalNewline` and its values accurately communicate that they control the final empty line's gutter number, not whether the line itself is rendered.

## Best solution

Preserve the interactive final model line required by editor and extension APIs, while giving the setting a compatibility-safe, unambiguous public contract through clearer naming or deprecation and migration.

- **Trace:**

The compatibility migration for legacy boolean values is in `src/vs/editor/browser/config/migrateOptions.ts`, with migration coverage in `src/vs/editor/test/browser/config/editorConfiguration.test.ts`. https://github.com/microsoft/vscode/issues/1027 establishes that the final row must remain interactive for editor and extension APIs, so completely hiding that row is outside this polish's boundary.
- **Open decisions:**

## Evidence

- **current source:** `src/vs/editor/common/config/editorOptions.ts` registers `renderFinalNewline` with the explicit description "Render last line number when the file ends with a newline," confirming that the behavior is narrower than the setting ID suggests.
- **rendering path:** `src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts` handles `off` by assigning an empty string only to `renderLineNumber`; it does not suppress the final view line.
- **established behavior:** In https://github.com/microsoft/vscode/issues/1027, the editor maintainer explicitly confirmed that retaining the cursor-accessible final line is expected because editor and extension APIs can address and edit it; that completed issue introduced suppression of only its line number.
- **compatibility surface:** `src/vs/editor/browser/config/migrateOptions.ts` already migrates legacy boolean values for `renderFinalNewline`, and `src/vs/editor/test/browser/config/editorConfiguration.test.ts` contains the corresponding configuration-migration test suite.
