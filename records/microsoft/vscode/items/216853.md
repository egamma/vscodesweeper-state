# Issue #216853 — Copy a link from integrated terminal via context menu

[https://github.com/microsoft/vscode/issues/216853](https://github.com/microsoft/vscode/issues/216853)

## Summary

Keep this accepted terminal-links request open: current context-menu and link commands do not provide link-target copying without selection. Related maintainer comments explicitly support a link-specific context menu; neither related issue supersedes this request.

## Change summary

Allow users to copy a hyperlink target from the integrated terminal through its context menu without manually selecting the text.

## Best solution

Provide a link-aware Copy Link action in the integrated terminal context menu, covering detected URLs and explicit terminal hyperlinks. Settle its interaction with existing right-click settings before implementation, without expanding this work into browser-selection or incognito support.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkContribution.ts`, `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts`, `src/vs/workbench/contrib/terminal/browser/terminalContextMenu.ts`, `src/vs/workbench/contrib/terminal/browser/terminalMenus.ts`, `src/vs/workbench/contrib/terminalContrib/clipboard/browser/terminal.clipboard.contribution.ts`
- **Validation:** In panel and editor terminals, print an ordinary HTTPS URL, a URL wrapping across terminal rows, and an OSC 8 hyperlink whose displayed text differs from its target. Invoke Copy Link from the context menu and paste into an editor; verify the exact complete target is copied without selection or browser activation. Verify non-link context menus and the agreed behavior for default, selectWord, copyPaste, paste, nothing, and Shift-right-click remain correct. Add targeted coverage in the terminal-link contribution/manager tests for target resolution and clipboard action invocation.
- **Behavior:**

  > A user can invoke Copy Link from the context menu on an integrated-terminal hyperlink without precisely selecting its text or opening a browser. The clipboard receives the complete hyperlink target, including when the URL wraps across rows; an explicit hyperlink copies its destination rather than its display label. The action works in both panel and editor terminals, while ordinary selection copying and non-link context menus remain unchanged. Acceptance includes verifying the chosen interaction with existing right-click settings.
- **Trace:**

  > Terminal menus in src/vs/workbench/contrib/terminal/browser/terminalMenus.ts expose selection-based copying; the registered commands in src/vs/workbench/contrib/terminalContrib/links/browser/terminal.links.contribution.ts expose link opening, not copying. TerminalLinkContribution wires TerminalLinkManager but does not currently handle link-specific mouse events. TerminalLinkManager in src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts has separate detected-link adapters and an xterm linkHandler for explicit hyperlinks, so both paths matter when identifying a target. TerminalInstance.handleMouseEvent dispatches to contributions before its right-click handling, and terminal clipboard contributions separately handle copyPaste/paste behavior; menu context currently identifies terminal instances rather than links. https://github.com/microsoft/vscode/issues/231446#issuecomment-2535435016 supports this context-menu direction, while https://github.com/microsoft/vscode/issues/202717#issuecomment-2550995362 treats incognito support as separate dependent work. Preserve existing link activation, selection copying, and non-link mouse behavior; browser-opening options are outside this request. The remaining product uncertainty is right-click precedence and whether the initial action extends beyond web hyperlinks to local-file and extension-provided links.
- **Open decisions:**
  - Should right-clicking a hyperlink override copyPaste, paste, or nothing settings to show link actions, or should Copy Link be available only when the configured behavior or Shift-right-click opens a context menu?
  - Should the initial Copy Link action cover only detected URL and OSC 8 hyperlinks, or also local-file and extension-provided links?
