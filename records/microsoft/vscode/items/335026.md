# Issue #335026 — Multi-file diff editor: Open File opens with cursor at the start of the file instead of where it was in the diff

[https://github.com/microsoft/vscode/issues/335026](https://github.com/microsoft/vscode/issues/335026)

## Summary

Team-authored bug report (collaborator chrmarti) filed hours ago; source tracing shows the multi-diff editor's Open File action already tries to preserve the cursor selection, but the capture silently fails for diff rows that aren't currently mounted (virtualized/off-screen), which likely explains the reported regression to start-of-file. No commit exists in this checkout that fixes and references this issue, so a completed close isn't available — keeping this open for a maintainer/code owner to confirm and land the fix.

## Change summary

The multi-diff editor's 'Open File' action should preserve the cursor position from the diff view instead of opening the target file at line 1.

## Best solution

In src/vs/workbench/contrib/multiDiffEditor/browser/actions.ts (GoToFileAction) and src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidgetImpl.ts (tryGetCodeEditor), fall back to a persisted last-known selection per URI (tracked in the view model) when the row's template isn't currently mounted, instead of relying solely on a live editor instance.

## Evidence
