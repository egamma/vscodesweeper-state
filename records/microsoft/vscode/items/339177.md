## Change summary

In the MCP migration picker (Agent Customizations → Migrations → Migrate MCP Servers), clicking a server's row and/or checkbox does not reliably toggle its selection, leaving the checkbox, selected count, and Migrate button out of sync.

## Evidence

- **row click never toggles selection:** In src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMigrationDashboard.ts, the tree is configured with openOnSingleClick: true (line 481) and tree.onDidOpen (lines 597-603) calls only this.openMigrationItem(entry) -> this.callbacks.openCustomization(...) (lines 668-670); there is no code path where a row click calls setMigrationItemSelected. Only the checkbox's onChange handler (line 232) does that — contradicting the issue's stated Expected Behavior that row clicks should toggle selection too.
- **selection-reset side effect:** tree.onDidChangeSelection(() => tree.setSelection([])) (line 584) immediately clears the tree's internal highlight selection after every click, which plausibly produces the 'hover/focus feedback but nothing changes' visual the recording shows, independent of the checkbox's own toggle logic.
- **checkbox click isolation:** Checkbox clicks call event.stopPropagation() (line 233) and Toggle's own onclick handler (src/vs/base/browser/ui/toggle/toggle.ts ~line 170) toggles state and fires onChange on 'click' — this looks correctly isolated from the tree's open/select handling, so the reported intermittent checkbox failures are not yet explained by source alone.
