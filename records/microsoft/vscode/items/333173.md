# Issue #333173 — renderWhitespace: the dot of a space is painted at its pre-widget column when an inline 'after' decoration sits immediately before it

[https://github.com/microsoft/vscode/issues/333173](https://github.com/microsoft/vscode/issues/333173)

## Summary

The whitespace overlay still uses a caret-boundary position that falls before an immediately preceding after decoration, rather than the space's rendered position. Keep this open as an editor-rendering bug; the source confirms the reported asymmetry.

## Change summary

Render the whitespace marker over the actual space following an inline after decoration, accounting for the decoration's displayed width.

## Best solution

Correct whitespace-marker geometry in the editor's whitespace overlay and rendered-line measurement path while preserving existing caret placement around after decorations. Cover the reported after-then-space case and the already-correct before and space-then-after cases.
