# Issue #330087 — [Claude] Creating a Fork is blocked on session not running

[https://github.com/microsoft/vscode/issues/330087](https://github.com/microsoft/vscode/issues/330087)

## Summary

Traced the root cause in current main: forking a Claude-harness session and sending a message on that same session both serialize on the same `_sessionSequencer` key, so a fork queued behind an in-flight turn blocks until that turn completes — matching the reported spin. Real, source-confirmed bug worth routing to the agent-host owners; not something to close.

## Change summary

Forking a Claude conversation while a turn is still running doesn't happen immediately — it waits for the in-flight turn to finish, unlike the Copilot SDK harness.

## Best solution

In src/vs/platform/agentHost/node/claude/claudeAgent.ts, `_forkSession` (queues on `_sessionSequencer.queue(sourceSessionId, …)`, ~line 1070) shares its lock key with `_sendMessage`'s per-session queue (~line 2171), whose task doesn't resolve until the SDK turn completes (see the `_abortSession` comment on why abort deliberately bypasses this same queue). The fix likely needs a narrower lock — e.g. only guarding the transcript read + `forkSession` SDK call against concurrent transcript mutation, rather than the full in-flight turn — mirroring how `_abortSession` intentionally sidesteps the sequencer for latency-sensitive operations.
