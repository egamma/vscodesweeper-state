# Issue #338087 — Managed enabledPlugins refresh does not reconcile active Agent Host sessions

[https://github.com/microsoft/vscode/issues/338087](https://github.com/microsoft/vscode/issues/338087)

## Summary

Real, scheduled gap (milestone 1.142.0, so a close is barred regardless of other evidence): the agent-host managed-settings service (src/vs/platform/agentHost/node/agentHostManagedSettingsService.ts) only tracks permissions/sandbox state per client, with no mechanism that reconciles `enabledPlugins` changes into an already-running session's plugin/skill/agent/hook/MCP inventory — matching the reported gap.

## Change summary

When a managed `enabledPlugins` policy changes after an Agent Host session has started, the running session keeps its stale plugin inventory instead of converging (or explicitly signaling that a restart is required).

## Best solution

Design and land an explicit convergence path in the agent-host layer: either live-reconcile plugin enablement/contributions for running sessions, or have the host detect a new managed-settings generation and surface a clear 'restart required' affordance — coordinated with the external host-independent runtime contract (github/copilot-agent-runtime#22922) and Copilot App integration (github/github-app#16986).
