# Issue #338087 — Managed enabledPlugins refresh does not reconcile active Agent Host sessions

[https://github.com/microsoft/vscode/issues/338087](https://github.com/microsoft/vscode/issues/338087)

## Summary

Fresh, well-diagnosed report from a contributor with clear architecture knowledge of this subsystem; the codebase itself documents the exact gap being reported (managed `enabledPlugins` edits only take effect on the runtime's next settings read or restart), so this is a real, still-open design gap worth tracking, not something to close.

## Change summary

When a managed `enabledPlugins` policy changes, active Agent Host sessions keep their old plugin/skill/agent/hook/MCP inventory instead of converging (or explicitly signaling that a restart is required).

## Best solution

Design and implement an explicit host-side convergence path per agent provider (Claude/Codex/Copilot) for managed-settings generation changes: apply what's safe to reconcile live, and surface a clear 'restart required' state for what isn't, with tests covering add/withdraw of `enabledPlugins` on a live session.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/claude/customizations/claudeSessionCustomizationDiscovery.ts`, `src/vs/platform/agentHost/node/claude/customizations/scan/claudeNativePluginScan.ts`, `src/vs/platform/agentHost/common/agentHostManagedSettings.ts`, `src/vs/platform/policy/common/copilotManagedSettings.ts`, `src/vs/platform/agentHost/browser/agentHostEnablementService.ts`
- **Validation:** An integration test that applies a managed `enabledPlugins` policy change (add and withdraw) while an Agent Host session is already running, then asserts the session's plugin/skill/agent/hook/MCP inventory converges within the documented lifecycle, or that the product surfaces an explicit restart-required state instead of silently retaining the stale inventory.
- **Behavior:**

  > When a managed `enabledPlugins` policy update (grant or withdrawal) applies while an Agent Host session is already open, the session should converge its plugin-provided skills/agents/hooks/MCP servers/extensions where it is safe to do so live, or explicitly tell the user a new session/restart is needed rather than silently keeping stale behavior. Policy withdrawal must remove contributions on the same documented lifecycle as installation.
- **Trace:**

  > Today the Claude-side watcher (`claudeSessionCustomizationDiscovery.ts` / `claudeNativePluginScan.ts`) only refreshes the *displayed* customization list; per `roadmap.md` (~L1927-1950) a mid-session `enabledPlugins` edit takes effect only on the runtime's next `settingSources` read or full restart — there is no generation-based reconciliation service comparable to `agentHostCatalogReconciliationService.ts` (which reconciles session catalog data, not managed plugin policy) for this concern. The gap likely spans each provider's session/runtime bridge (Claude, Codex, Copilot) differently, since each auto-loads plugins through its own SDK mechanism. Do not conflate this with the narrower, already-fixed force-enablement case in microsoft/vscode#338071.
- **Open decisions:**
  - Which parts of the plugin/skill/agent/hook/MCP inventory can be safely reconciled into a live session versus which genuinely require a new session or process restart?
  - Should each agent provider (Claude, Codex, Copilot) implement a shared generation/version-based reconciliation contract, or provider-specific mechanisms given their differing SDK plugin-loading models?
  - What UI/notification surface tells the user a restart is needed to pick up a managed policy change?

## Evidence

- **no reconciliation service found:** Searched src/vs/platform/agentHost for a live managed-policy convergence path (generation-based reapply of enabledPlugins to a running session); found only the Claude native-plugin scanner/watcher (claudeNativePluginScan.ts, claudeSessionCustomizationDiscovery.ts) and the permissions bridge in agentHostManagedSettings.ts, neither of which reconciles plugin install/enable/disable for an already-materialized session.
- **related fix:** microsoft/vscode#338071 (cited by the reporter) fixed force-enablement for an already-installed plugin but explicitly not live refresh convergence, per the issue body.
