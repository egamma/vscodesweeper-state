# Issue #332514 — Starting a new Copilot thread with pasted text always leads to "#attachment:Pasted text #1" as the chat title

[https://github.com/microsoft/vscode/issues/332514](https://github.com/microsoft/vscode/issues/332514)

## Summary

The title regression remains source-reproducible on current main: title generation receives the pasted-text placeholder as the prompt, while the actual pasted content is available only through the request references and is ignored by the Copilot title provider.

## Change summary

Generate distinct Copilot chat titles from the contents of long pasted-text attachments instead of using the shared `#attachment:Pasted text #1` placeholder.

## Best solution

Include the matching pasted-text reference content when constructing the input for Copilot's chat-title prompt, while preserving current title behavior for ordinary prompts and unrelated attachments.

## Evidence

- **current source path:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts` replaces a sufficiently long paste with `#attachment:Pasted text #N` and stores the original text in an `IChatRequestPasteVariableEntry`.
- **API bridge:** `src/vs/workbench/api/common/extHostChatAgents2.ts` constructs `ChatRequestTurn` with `h.request.message` as `prompt` and separately converts the pasted entry into `references`, whose string value retains the original pasted content.
- **root cause:** `extensions/copilot/src/extension/prompt/node/title.ts` passes only `firstRequest.prompt` to `TitlePrompt` and never reads `firstRequest.references`; an attachment-only request therefore asks the title model to summarize the literal placeholder.
