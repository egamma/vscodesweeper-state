This is distinct from Copilot service authentication.
- **Current authentication boundary:** src/vs/platform/agentHost/node/agentHostGitHubService.ts constructs the shared GitHub credential provider with getToken and onDidChange but no invalidateToken callback. Its repository-client credential-invalidation listener handles only reason 'account', not authentication rejection. The shared implementation in src/vs/platform/github/common/githubService.ts delegates rejection through the optional provider invalidateToken hook, leaving the Agent Host token store disconnected from that recovery path.
- **Current lookup failure path:** src/vs/platform/agentHost/node/agentHostGitStateService.ts:212-250 obtains the repository token, resolves the checkout PR, and catches lookup failures by logging a warning. It does not retain the failed lookup for authentication recovery or request replacement credentials. _getGitHubAuthToken reads the same resource/scopes from AgentHostAuthenticationService, whose stored tokens are not invalidated by GitHub REST rejection.

Its proposed behavior includes rejected-token quarantine, expired-auth notification, replacement credentials and pending-lookup recovery; the issue must remain open while this candidate is reviewed.
