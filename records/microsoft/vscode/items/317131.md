# Issue #317131 — Agent app should expose the full Copilot CLI command surface and provide VS Code–level UI depth over it

[https://github.com/microsoft/vscode/issues/317131](https://github.com/microsoft/vscode/issues/317131)

## Summary

Keep this team-authored umbrella request open. Current main has added substantial command, configuration, tool-call, and sub-agent integration since the report, but the central full-parity goal remains incomplete because several Copilot CLI/TUI commands are not exposed through the headless SDK and the requested UI-depth contract is not yet defined.

## Change summary

Make the Agents Window expose the complete usable Copilot CLI command and configuration surface while providing inspectable tool, sub-agent, and effective-state UI.

## Best solution

Define a durable parity contract between the Copilot runtime and the Agents Window: runtime-advertised commands should be discoverable and invokable, unsupported TUI-only capabilities should either gain headless runtime support or an explicit VS Code equivalent, and tool, sub-agent, and effective configuration state should have first-class inspection surfaces.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/slashCommands.ts`, `src/vs/sessions/contrib/chat/browser/agentHostInputCompletions.ts`, `src/vs/platform/agentHost/node/copilot/copilotSlashCommandProvider.ts`, `src/vs/platform/agentHost/node/copilot/copilotSlashCommandCompletionProvider.ts`, `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSession.ts`, `src/vs/sessions/AI_CUSTOMIZATIONS.md`
- **Validation:** End the plan with contract tests proving every command advertised by the active runtime is completable and invokable from an Agents Window composer, plus focused component or provider tests for the agreed configuration controls and tool/sub-agent inspection details.
- **Behavior:**

  > The Agents Window must not direct users to Copilot CLI operations that are unavailable in the window without also providing an actionable equivalent. Commands and configuration capabilities included in the agreed parity boundary are discoverable and usable through command input or first-class controls. Tool calls, sub-agent activity, and effective configuration expose the level of detail selected by the maintainer. Existing commands, normal prompt submission, and provider-neutral Sessions behavior remain functional.
- **Trace:**

  > The Agents Window has two relevant command paths: src/vs/sessions/contrib/chat/browser/slashCommands.ts handles Sessions-owned commands and prompt customizations, while src/vs/sessions/contrib/chat/browser/agentHostInputCompletions.ts consumes commands and configuration actions published by an Agent Host. The Copilot host integration discovers and invokes runtime commands through src/vs/platform/agentHost/node/copilot/copilotSlashCommandProvider.ts and its completion provider. Commit 2c1cf66a8d87b22288269d123f5d28ffdb2eca35 removed several command collisions and exposed the supported customization commands, but https://github.com/microsoft/vscode/issues/337929 records that many interactive CLI commands are absent from the headless runtime contract. The extension-side session wrapper in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSession.ts already renders tool invocations and attaches sub-agent metadata, so the remaining uncertainty is the desired presentation depth rather than absence of an event path. Preserve provider-neutral Sessions ownership and do not duplicate TUI-only operations in shared UI without deciding whether they belong in the headless runtime contract.
- **Open decisions:**
  - Does “full parity” include commands currently available only in the interactive CLI/TUI, requiring corresponding headless runtime support, or is the contract limited to commands advertised by the SDK?
  - For each supported configuration capability, which operations require a visible GUI control and which may be satisfied by discoverable command input?
  - What tool-call and sub-agent information must be visible by default or on inspection for the Agents Window to meet the intended VS Code-level UI depth?
