# Issue #331086 — Commit messages garbled depending on Git settings

[https://github.com/microsoft/vscode/issues/331086](https://github.com/microsoft/vscode/issues/331086)

## Summary

Real bug: VS Code's git extension decodes git command output (including commit messages) as UTF-8 unconditionally, so repos configured with `i18n.commitEncoding`/`i18n.logOutputEncoding` other than UTF-8 (e.g. EUC-JP) show garbled commit messages in the Graph and blame views. There's already an open PR from the same reporter addressing it, so this stays open pending that PR.

## Change summary

Commit messages appear garbled in Source Control Graph / blame decorations when a repository sets `i18n.commitEncoding` or `i18n.logOutputEncoding` to a non-UTF-8 charset.

## Best solution

Land (after review) the linked PR https://github.com/microsoft/vscode/pull/331087, which forces commit message output to UTF-8 (or otherwise decodes according to the configured i18n encoding) in extensions/git/src/git.ts's spawn/exec handling.

## Evidence

- **no encoding handling:** `grep -rn "commitEncoding\|logOutputEncoding" extensions/git/src/*.ts` returns no matches — the git extension does not read or honor these git config settings.
- **hardcoded utf8 decoding:** extensions/git/src/git.ts decodes process stdout with `toString('utf8')` / `setEncoding('utf8')` in multiple places (e.g. lines 244, 657, 2798), so non-UTF-8 git output (as produced when i18n.commitEncoding is set to e.g. EUC-JP) is misdecoded.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/331087 ('Force commit messages output to UTF-8'), opened by the same reporter, is open and unmerged.
