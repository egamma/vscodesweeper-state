# Issue #206612 — Git - Support diff textconv on unstaged changes

[https://github.com/microsoft/vscode/issues/206612](https://github.com/microsoft/vscode/issues/206612)

## Summary

Keep this accepted feature request open: current source still compares a textconv-converted baseline with the raw working-tree file for unstaged changes. It has 31 upvotes, and the reviewed related issues do not provide an eligible canonical covering the same remaining work.

## Change summary

Apply the configured Git textconv conversion to both sides of unstaged SCM diffs, including Ansible Vault files and normalized JSON.

## Best solution

Provide a meaningful converted comparison for unstaged changes in the built-in Git extension without requiring staging first. Settle whether that comparison is read-only and how editing or partial-staging actions behave when converted lines do not correspond to the underlying file.

Repeat after staging and with a normal file without a driver; verify the chosen editing/partial-staging contract and that viewing leaves working-tree and index bytes unchanged.
- **Behavior:**

  > For a tracked file with a configured textconv driver, opening unstaged changes currently displays converted baseline content against raw working-tree content. The desired comparison applies the conversion consistently to both sides without first staging the file, making decrypted or normalized changes understandable. Viewing must not modify the file or index, and staged comparisons and ordinary files must retain their existing behavior. Acceptance includes agreement with command-line git diff for a deterministic conversion fixture and explicit verification of the selected editing and partial-staging semantics.
- **Trace:**

  > ResourceCommandResolver.getLeftResource/getRightResource in extensions/git/src/repository.ts supplies a Git URI for the unstaged baseline and a working-tree file URI for the modified side; staged changes use Git URIs on both sides. GitFileSystemProvider.readFile in extensions/git/src/fileSystemProvider.ts delegates to Repository.buffer, whose implementation in extensions/git/src/git.ts invokes git show --textconv, so the baseline is converted while the working-tree side bypasses that path. This was confirmed by source inspection, not runtime execution. Git URI parameters live in extensions/git/src/uri.ts; CommandCenter._stageChanges in extensions/git/src/commands.ts expects a file-scheme document and applies line changes to the baseline, identifying the interaction boundary that remains undecided. Preserve ordinary file editing, staged diffs, and on-disk/index content; do not fold clean/smudge-filter support into this request. https://github.com/microsoft/vscode/pull/327079 separately changes quick-diff gutter behavior and explicitly leaves this SCM comparison unchanged. https://github.com/microsoft/vscode/issues/302990 is related filter work, not a canonical duplicate of this request.
- **Open decisions:**
  - Should converted unstaged comparisons be read-only, or should editing remain available despite textconv potentially being irreversible?
  - Should partial-stage and revert controls be unavailable in converted comparisons, or must the feature provide a defined mapping back to underlying file changes?
