## Change summary

Opening a search result inside a notebook cell throws `TreeError [SearchView] Tree element not found` when `tree.setSelection`/`setFocus` is called on a match that hasn't been materialized in the compressed tree model yet.

## Best solution

Land the fix in the open PR https://github.com/microsoft/vscode/pull/328973 ("fix: guard notebook match selection against unmaterialized tree element (fixes #328427)"), which guards the `searchView.ts` selection call with a tree-node existence check before calling `setSelection`/`setFocus`.
