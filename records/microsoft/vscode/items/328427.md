## Summary

The defect remains on current main: opening a remapped notebook search match can select an element that the asynchronous Search tree has not materialized. The related fixing PR was closed without merging, so the issue is still necessary.

## Change summary

Opening notebook search results can throw a TreeError when Search attempts to select an unmaterialized remapped match.

## Best solution

Guard the notebook match selection in `SearchView.open()` with `tree.hasNode(match)` while preserving notebook highlighting, and add a regression test covering materialized and unmaterialized matches.
