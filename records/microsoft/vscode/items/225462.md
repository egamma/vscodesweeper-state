# Issue #225462 — Suggest: Test Explorer exists by default, but off

[https://github.com/microsoft/vscode/issues/225462](https://github.com/microsoft/vscode/issues/225462)

## Summary

The discovery gap remains: Test Explorer still requires a registered test provider, so its existing welcome content does not deliver the requested provider-free entry point. Keep this open for the visibility decision discussed in the thread; no qualifying canonical duplicate was established.

## Change summary

Make Testing available as an unchecked Activity Bar option before any test provider is installed, with introductory content and a Marketplace link when enabled.

## Best solution

Provide an intentional way to discover Testing before installing a provider without adding an always-visible Activity Bar icon. Settle whether the requested opt-in entry point should ship directly or first be evaluated through the experiment suggested in the discussion.

- **Behavior:**

  > Users without test-provider extensions cannot currently discover Testing through the proposed unchecked Activity Bar entry. The requested experience keeps the default Activity Bar uncluttered while allowing users to enable Testing and learn how to install a provider. Acceptance should cover the provider-free entry point, introductory content, a working Marketplace search, and unchanged testing behavior after a provider is installed. Whether this experience is generally available or initially experimental remains a maintainer decision.
- **Trace:**

  > In src/vs/workbench/contrib/testing/browser/testing.contribution.ts, the Testing container uses hideIfEmpty and Test Explorer has a providerCount > 0 activation condition. The same contribution already registers welcome text and an extension-search link, but those do not remove the provider gate. The inspection establishes the missing entry point, not the full Activity Bar persistence behavior; that interaction needs tracing during planning. The related https://github.com/microsoft/vscode/issues/206573 concerns discovery after tests exist and does not absorb this request.
