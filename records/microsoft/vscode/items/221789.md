# Issue #221789 — An extension quick pick can break quick open

Keep open: maintainers confirmed the timing-dependent selection failure, and the reporter says steps 1–5 returned in February 2026. The original fix predates that recurrence, and no verified canonical or subsequent fixing commit was identified.

## Change summary

Typing before asynchronously loaded branch items appear can prevent accepting a quick-pick selection and historically also broke subsequent Quick Open.

Reproduce the renewed failure through the extension quick-pick bridge and identify whether filtering, active-item updates, or acceptance loses the selected branch. Restore reliable acceptance without leaving shared Quick Input state impaired; independently check whether the historical Quick Open failure also recurs.

- **Behavior:**

  > A branch quick pick must accept a visible matching branch even when the user starts filtering before asynchronous items arrive. The reporter says this acceptance failure returned in February 2026. After dismissing that picker, Quick Open must remain able to open files; determine separately whether this historical secondary symptom still occurs. Acceptance should be demonstrated with a controlled asynchronous item-loading sequence and subsequent successful file selection.
- **Trace:**

  > The historical exception originated in setting focus to an item absent from the QuickInput tree. https://github.com/microsoft/vscode/pull/222248 guarded hidden focus targets, and that guard remains in QuickInputList.setFocusedElements in src/vs/platform/quickinput/browser/quickInputList.ts. MainThreadQuickOpen.$createOrUpdate in src/vs/workbench/api/browser/mainThreadQuickOpen.ts applies transferred item and active-item updates; QuickPick.update in src/vs/platform/quickinput/browser/quickInput.ts rebuilds, filters, and activates items, while QuickPick.show wires selection and acceptance. The February recurrence does not include a new stack, so neither the old exception nor the secondary Quick Open failure is established for the renewed case. Start by reproducing and capturing that update order rather than treating the retained guard as proof of resolution. Preserve existing single-select, multi-select, filtering, and extension API semantics; scope the investigation to reliable asynchronous selection and shared-picker recovery.
