## Evidence

- **Verified open canonical:** Read the body and full discussion of https://github.com/microsoft/vscode/issues/47770 through GitHub. It remains OPEN and requests editor text selection through touch gestures; its 2018 report predates this 2020 issue.
- **Remote Desktop explicitly covered:** https://github.com/microsoft/vscode/issues/47770#issuecomment-389894256 describes remoting into VS Code using Remote Desktop Connection in Touch mode and requests double-tap word selection and draggable selection handles. This directly covers the central Remote Desktop touch-selection request, rather than merely sharing title keywords.
- **Matching tablet scenario:** https://github.com/microsoft/vscode/issues/47770#issuecomment-1003657862 describes the same Notepad comparison on a Surface Pro tablet. The canonical discussion also includes Windows tablets and iPad Pro users unable to select text by touching and dragging.
- **Existing capability is partial:** In src/vs/editor/browser/controller/pointerHandler.ts, TouchHandler.onChange scrolls rather than selecting. PointerEventHandler distinguishes touch scrolling from pen selection, but PointerHandler selects that handler only for iOS or mobile Android with pointer-event support. These paths do not establish that Remote Desktop touch/stylus selection is already fully supported; no touch-selection option was found in src/vs/editor/common/config.
- **Report-specific evidence to retain:** https://github.com/microsoft/vscode/issues/104292 describes Surface Pro X access to desktop and Azure Windows environments using a pen/stylus. Its July 2021 comment adds iOS Remote Desktop, failed double-tap selection, and failed Shift-plus-arrow selection using both Magic Keyboard and the app keyboard; those observations should accompany consolidation without asserting a separately diagnosed keyboard defect.
