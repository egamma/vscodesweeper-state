# Issue #153982 — Events and registered commands on TreeView are unreliable when refreshing treeview

[https://github.com/microsoft/vscode/issues/153982](https://github.com/microsoft/vscode/issues/153982)

## Summary

Still reproduces on current main: when a tree view refreshes, the `_elements` map is cleared, so any expand/collapse notification arriving during or after the refresh silently drops the event because `getExtensionElement` returns `undefined`. The race also explains command arguments being lost. No fix has landed for this specific issue.

## Change summary

TreeView `onDidExpandElement`/`onDidCollapseElement` events and context-menu command arguments are silently dropped when a tree refresh clears the internal element map concurrently.

## Best solution

In `ExtHostTreeView.setExpanded` (src/vs/workbench/api/common/extHostTreeViews.ts), when `getExtensionElement` returns `undefined` during a pending refresh, defer the event until the refresh completes and re-resolve the element from the refreshed map. The same pattern should protect command-argument resolution. This is a localized fix in the ext-host tree view layer.
