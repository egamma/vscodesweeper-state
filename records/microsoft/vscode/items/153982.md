# Issue #153982 — Events and registered commands on TreeView are unreliable when refreshing treeview

[https://github.com/microsoft/vscode/issues/153982](https://github.com/microsoft/vscode/issues/153982)

## Summary

The refresh-time handle-resolution gap remains in current source: visible items can lose their extension-side mappings before replacement data arrives, causing missing expand/collapse events and undefined command arguments. Keep this older, broader report open; the newer matching command-argument report is related, not a valid canonical for closing it.

## Change summary

TreeView refreshes can drop expansion/collapse notifications and leave item-context commands without their target element.

## Best solution

Make interactions with still-displayed TreeView items resolve their corresponding provider elements throughout asynchronous refreshes, without reusing obsolete mappings after items are retired. Cover both event delivery and command argument conversion with deterministic refresh-in-flight regression tests in the extension-host TreeView suite.
