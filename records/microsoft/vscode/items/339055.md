# Issue #339055 — Custom models on Copilot Chat from Azure are not using Entra ID

[https://github.com/microsoft/vscode/issues/339055](https://github.com/microsoft/vscode/issues/339055)

## Summary

The Azure BYOK provider does have an Entra ID code path (azureProvider.ts falls back to vscode.authentication when no apiKey is configured, and AzureOpenAIEndpoint sends a Bearer token instead of an api-key header), so this isn't obviously broken from source alone — but the report is too thin to pin down why it's failing for this reporter, so asking for repro detail is the right next step rather than a close.

## Change summary

Azure BYOK custom models configured to use Entra ID (no API key) appear to still authenticate with a key instead of the Entra ID token.

## Best solution

Get the reporter's exact model/deployment type (Azure OpenAI `openai.azure.com` vs. Azure AI Foundry `models.ai.azure.com`/`inference.ml.azure.com`) and the actual error seen. If it's a Foundry serverless deployment, verify whether the fixed `https://cognitiveservices.azure.com/.default` scope used in `AzureAuthMode.COGNITIVE_SERVICES_SCOPE` (configurationService.ts) is the correct token audience for that endpoint type — that's the most likely gap if the hypothesis holds.

## Evidence

- **Entra path exists:** extensions/copilot/src/extension/byok/vscode-node/azureProvider.ts provideLanguageModelChatResponse: if model.configuration?.apiKey is falsy, it calls vscode.authentication.getSession('microsoft', [COGNITIVE_SERVICES_SCOPE]) and passes the Entra token through instead of an API key.
- **Entra header handling:** extensions/copilot/src/extension/byok/node/azureOpenAIEndpoint.ts AzureOpenAIEndpoint.getExtraHeaders() sets `Authorization: Bearer <entraToken>` and explicitly deletes any `api-key` header, so the code is defensively built not to send a key when using Entra.
- **possible scope mismatch:** The fixed scope `https://cognitiveservices.azure.com/.default` (configurationService.ts AzureAuthMode.COGNITIVE_SERVICES_SCOPE) is used for all Azure URL shapes; whether this audience is valid for Azure AI Foundry serverless `models.ai.azure.com` deployments (vs. classic `openai.azure.com`) is unverified without running the service — this is a hypothesis, not a confirmed defect.
