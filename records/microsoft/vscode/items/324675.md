[https://github.com/microsoft/vscode/issues/324675](https://github.com/microsoft/vscode/issues/324675)

## Summary

A second reporter reproduced and clarified this with a video: dragging to select text in the Find/Replace input stops updating once the mouse cursor exits the input's bounding box, instead of continuing like standard text-field selection. No fixing commit exists on main and I couldn't find code in findInput.ts/inputBox.ts that explicitly breaks native mouse-capture selection, so routing to the find/input area for investigation.

## Change summary

Dragging to select text in the Find/Replace search box stops extending the selection once the cursor leaves the input's boundary, instead of continuing to track the mouse like normal text-field selection; a related complaint is that re-dragging already-selected text in the box can drag it into the document.

## Best solution

Investigate mouse capture / pointer events for the Find widget's input elements (src/vs/base/browser/ui/findinput/findInput.ts, src/vs/base/browser/ui/inputbox/inputBox.ts) to restore native input drag-selection continuing outside the element bounds, and consider suppressing native HTML5 drag-out-of-input for already-selected text in the find/replace box.
