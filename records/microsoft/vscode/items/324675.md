# Issue #324675 — Select on Find is delayed

[https://github.com/microsoft/vscode/issues/324675](https://github.com/microsoft/vscode/issues/324675)

## Summary

Keep open: a commenter consistently reproduced selection stopping when the pointer leaves the search field, and the reporter confirmed that clarification. The same symptom has a newer independently confirmed report, but neither a qualifying older canonical nor a concrete fixing commit was established.

## Change summary

Mouse selection in Find and Replace stops updating outside the input boundary; the reporter also describes accidentally dragging already-selected input text into the document.

## Best solution

Restore continuous text selection across Find and Replace input boundaries without changing document focus or content during a selection gesture. Diagnose the shared input/browser interaction first, keeping the separate selected-text drag concern distinct from the boundary-selection defect.

- **Validation:** On Windows, enter a long term in editor Find and Replace and workspace Search and Replace. Start a fresh selection in each field, hold the left button, and drag beyond its left, right, top, and bottom boundaries at normal and fast speeds. Verify selection keeps updating until release, focus remains in the input, and typing replaces only the selected input text without modifying the document. Compare with a plain native textarea to establish ownership before selecting a regression harness.
- **Behavior:**

  > Selecting text in Find or Replace must continue while the mouse button is held, even when the pointer leaves the input boundary. Fast right-to-left selection must not leave an unintended partial selection. A fresh selection gesture must retain input focus and must not modify the document. Starting a drag on already-selected text is a separately reported interaction and must not be assumed to share the primary defect's cause.
- **Trace:**

  > The thread supplies a consistent Windows reproduction, confirmed by the reporter; it does not establish reproduction against this checkout. FindWidget and SearchWidget both use flexible-height FindInput and ReplaceInput controls, which delegate through HistoryInputBox to InputBox's native textarea and ScrollableElement wrapper. Preserve existing keyboard selection, multiline input, search toggles, and Linux middle-button behavior. https://github.com/microsoft/vscode/issues/328920 independently confirms the primary symptom but is younger than this issue; https://github.com/microsoft/vscode/issues/176523 concerns focus transfer and selected-text dragging rather than complete coverage of the primary symptom.
