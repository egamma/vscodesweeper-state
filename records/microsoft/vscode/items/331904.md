# Issue #331904 — `task` tool model override rejects BYOK models with "Model '...' is not available"

[https://github.com/microsoft/vscode/issues/331904](https://github.com/microsoft/vscode/issues/331904)

## Summary

Real, traceable fragility in how BYOK task-tool model overrides are keyed, but the specific failure shown is very likely a one-character typo the calling model itself made ('Kimi 2.7 Code' vs 'Kimi K2.7 Code'), not a confirmed VS Code defect — keeping open for further tracing rather than closing.

## Change summary

Overriding the `task` tool's model with a BYOK model id is rejected as 'not available' even though the id is listed as available.

## Best solution

Investigate agentHost's BYOK selection-id scheme (`src/vs/platform/agentHost/common/agentHostByokLm.ts:getByokLmSelectionModelId`/`getByokLmAgentModelId` and `copilotSessionLauncher.ts:resolveByokSessionConfig`), which builds model ids as `vendor/group/id` embedding the user's free-text provider-group display name; this is brittle when a model must reproduce that string verbatim (here it dropped one letter). Consider normalizing/case-insensitive matching or having the harness resolve model overrides by model id alone rather than requiring an exact group-name match.

## Evidence

- **id encoding scheme:** src/vs/platform/agentHost/common/agentHostByokLm.ts (getByokLmSelectionModelId/getByokLmAgentModelId) builds BYOK selection ids as `vendor/group/id`, where `group` is the free-text `name` field from chatLanguageModels.json (here 'Kimi K2.7 Code', which is also the main model's own display name).
- **wiring into CLI session:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:resolveByokSessionConfig wires these vendor/group/id ids into the launched Copilot CLI session's provider/model config; the doc comment at line 511 confirms the `vendor/[group/]id` format matches the renderer's AgentHostByokLmHandler.
- **typo in the reported override:** The user's requested override was 'customendpoint/Kimi 2.7 Code/Qwen3.8-27B' — missing the 'K' present in the actual group name 'Kimi K2.7 Code' shown in the 'Available models' list — a one-character mismatch consistent with the calling model mistyping the group segment rather than a confirmed code defect.
- **distinct code path:** src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts (the workbench's own 'task' subagent tool) uses a different qualified-name format ('Name (Vendor)') and a different error message ('Requested model ... not found'), so the exact code that throws the reported 'Model ... is not available. Available models: ...' message was not found verbatim in this checkout — it likely lives in the vendored Copilot CLI harness invoked as a subprocess, which is outside this source tree.
