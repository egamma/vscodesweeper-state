# Issue #329979 — Signed out agents window should have some indication of credentials?

[https://github.com/microsoft/vscode/issues/329979](https://github.com/microsoft/vscode/issues/329979)

## Summary

Keep open for a credential-discoverability design decision. Current source distinguishes native Claude availability from Copilot authentication, but the inspected UI does not explain the active credential source or its configuration location; this team-authored suggestion has no verified fix or qualifying duplicate.

## Change summary

Explain which credentials enable signed-out Agents window use, with an optional way to locate their configuration.

## Best solution

Make the selected provider's authentication source understandable through an existing account or model surface, without exposing secrets or changing authentication precedence. Decide whether source-category information is sufficient or whether supported configuration locations should also be discoverable.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/claude/claudeTransportMode.ts`, `src/vs/platform/agentHost/node/claude/claudeAgent.ts`, `src/vs/sessions/contrib/accountMenu/browser/account.contribution.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSdkSetupNotification.ts`
- **Validation:** On a build permitting signed-out Agents window use, independently configure Claude with an environment API key and a native login credential, then open the window without GitHub authentication and inspect the agreed credential-information surface. Verify its source description matches the active configuration, exposes no secret values, remains keyboard and screen-reader accessible, and does not change model routing or sign-in requirements; if location discovery is accepted, verify it identifies the actual supported configuration location rather than guessing.
- **Behavior:**

  > A user running an agent without GitHub sign-in can understand which external authentication configuration enables that agent. The description must distinguish known credential sources without displaying keys or tokens, and must not claim a source or storage location that cannot be established. Whether configuration-location discovery is included remains a product decision. Existing signed-in behavior and the ability to run native models without GitHub authentication remain unchanged.
- **Trace:**

  > ClaudeTransportMode.isClaudeAccountSetUp consumes SDK AccountInfo fields including tokenSource, apiKeySource, and apiProvider; ClaudeAgent retains a boolean availability result and publishes provider-qualified model availability. Native credential resolution remains SDK-owned through claudeSdkOptions.ts, and ClaudeAgent's setup channel supplies documentation rather than an in-app login control. The inspected Sessions account panel has Copilot and ChatGPT sections but no Claude provenance presentation, while agentHostSdkSetupNotification.ts handles unavailable-account setup guidance. The uncertainty starts at which SDK-reported source details can reliably reach the UI and whether they identify a configuration location. Preserve credential resolution, model-provider precedence, and provider-neutral Sessions boundaries; do not infer the selected source by independently scanning for secrets. Related design context is https://github.com/microsoft/vscode/issues/323049, and signed-out rollout is tracked separately at https://github.com/microsoft/vscode/issues/329671.
- **Open decisions:**
  - Should credential information be discoverable on demand in the account/model surface, or also appear when entering the Agents window signed out?
  - Is a credential-source category sufficient, or should this request also include navigation to known configuration locations, with explicit handling for environment and keychain sources?
