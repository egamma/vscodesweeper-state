# Issue #270778 — When automatic type capture is disabled, the web type file system loads the file automatically incrementing the vscode-node-modules schema

[https://github.com/microsoft/vscode/issues/270778](https://github.com/microsoft/vscode/issues/270778)

## Summary

Still reproduces on main: the `realpath` function in the web server host unconditionally remaps node_modules paths to the `vscode-node-modules` scheme without checking `enabledExperimentalTypeAcquisition`, unlike every other fs operation in the same file.

## Change summary

When `typescript.disableAutomaticTypeAcquisition` is true in a web IDE, reading node_modules files still has their URI scheme replaced with `vscode-node-modules` in `realpath`, causing file reads to fail.

## Best solution

Guard the `isNm` → `mapUri(uri, 'vscode-node-modules')` call in `realpath` (line 382 of `serverHost.ts`) with the same `enabledExperimentalTypeAcquisition` check used in `readFile`, `getFileSize`, `fileExists`, `getModifiedTime`, and `getAccessibleFileSystemEntries`.
