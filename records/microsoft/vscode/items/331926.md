# Issue #331926 — Integrated browser remote proxy should support remote AHP hosts in Agents window

[https://github.com/microsoft/vscode/issues/331926](https://github.com/microsoft/vscode/issues/331926)

## Summary

Freshly-filed, well-diagnosed feature request in its 60-day upvote window (Backlog Candidates milestone, 2 upvotes, 14 days old) — traced the gap in current source and it's real, but the community process for this milestone means keeping it open rather than closing for being quiet.

## Change summary

Let the integrated browser proxy traffic through a remote AHP (Agent Host Protocol) host selected in an Agents window session, not just a VS Code Remote workspace authority.

## Best solution

Extend `BrowserViewWorkbenchService.willUseRemoteProxy()` (src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts) to also recognize an active Agents-window AHP session's remote host as a proxy authority, likely coordinating with src/vs/platform/agentHost for the connection info; this is genuinely new capability requiring an implementation decision, not something a maintainer has ruled on yet.
