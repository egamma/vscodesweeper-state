# Issue #335316 — Agents window: Show confirmation after Commit and Sync actions complete

[https://github.com/microsoft/vscode/issues/335316](https://github.com/microsoft/vscode/issues/335316)

## Summary

Keep open: current operation controls provide progress and repository counts, but not explicit completion feedback describing the resulting state. The related Git/worktree umbrella explicitly preserves this narrower report rather than replacing it.

## Change summary

Provide non-modal confirmation and resulting repository state after Commit or Sync completes in the Agents window.

## Best solution

Provide quiet, session-scoped completion feedback that distinguishes a local commit from synchronization and remains understandable after the initiating control disappears. Agree on its presentation and lifetime within the broader Git/worktree UX, without changing Git operation semantics.

- **Behavior:**

  > After a successful Commit or Sync in the Agents window, users can tell what completed and whether their changes are committed locally or synchronized. Feedback must not require a modal interaction or dismissal, and must remain understandable when the initiating action disappears. Failed or cancelled operations must not appear successful. The acceptance check covers both actions, session switching during execution, and accessible presentation of the result.
- **Trace:**

  > Commit currently lives in the Changes editor header through ChangesHeaderChangesetOperationsActionContribution in src/vs/sessions/contrib/changes/browser/changesActions.ts; changesView.ts excludes Commit from the title-bar operations. SessionSyncChangesAction and SessionSyncChangesActionViewItem in sessionSyncChanges.ts expose progress and counts, while shouldShowSyncChanges removes Sync when incoming and outgoing counts reach zero. AbstractAgentHostChangeset.invokeOperation in src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionChangesets.ts awaits the backend operation without retaining its result for presentation, and cancellation can return without executing it. Existing tests explicitly cover completed Sync action removal, failure propagation, and focus restoration. Preserve those behaviors and existing Git execution semantics; the unresolved boundary is the user-visible completion presentation and its lifetime. Coordinate the design with https://github.com/microsoft/vscode/issues/336620, which explicitly retains this narrower request.
- **Open decisions:**
  - Should completion feedback be a transient inline acknowledgement, persistent repository status, or both, and how long should it remain visible after the initiating action disappears?
