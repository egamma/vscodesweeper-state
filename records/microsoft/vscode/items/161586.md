# Issue #161586 — Close, minimize and maximize buttons missing on macOS after using the restart to update option

[https://github.com/microsoft/vscode/issues/161586](https://github.com/microsoft/vscode/issues/161586)

## Summary

Keep open pending confirmation that the landed fullscreen-restoration mitigation resolves this report. Multiple users confirmed the missing controls, but the available evidence does not establish that every reported macOS window-restoration case is fixed.

## Change summary

Restoring windows after Restart Code to Update can leave a non-fullscreen macOS window without close, minimize, or maximize controls.

## Best solution

Ensure the restored window's workbench fullscreen state agrees with its actual native state and that window controls remain available when fullscreen restoration fails. First verify the existing timeout recovery against the reported multi-window update scenario before making further changes.

- **Trace:**

  > In src/vs/platform/windows/electron-main/windowImpl.ts, BaseWindow.applyState requests setFullScreen(true, true) for persisted fullscreen state. BaseWindow.doSetNativeFullScreen temporarily reports the requested state while awaiting native transition events, then clears that state; failed restoration additionally emits onDidLeaveFullScreen when Electron reports the window is not fullscreen. CodeWindow forwards that event to the renderer. The recovery was introduced by https://github.com/microsoft/vscode/commit/1a37acbdf9c83ad21f68a48562346980a31ffa1b and refined by https://github.com/microsoft/vscode/commit/44fd438df521b26bb360fca7d4fee512415a5ddb. Historical logs and confirmations support the suspected state mismatch, but no current native-transition reproduction was performed. Begin by determining whether controls still disappear despite recovery, and whether that failure is renderer state or native window state; preserve successful fullscreen transitions and do not assume external displays are required.

These directly address the suspected stale-fullscreen/titlebar path, but are not confirmation that the complete reported native-controls failure is resolved.
