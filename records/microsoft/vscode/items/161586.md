Repeat with multiple displays and a single display, recording native fullscreen state and the fullscreen-transition warning if the failure occurs.
- **Behavior:**

  > After Restart Code to Update restores mixed fullscreen and ordinary macOS windows, ordinary windows must display working close, minimize and maximize controls. Fullscreen windows must retain correct fullscreen behavior, and toggling fullscreen must remain functional. Historical reports confirm the failure, but whether current builds still exhibit it is unresolved; first repeat the supplied scenario and observe the existing recovery interval.
- **Trace:**

  > WindowsStateHandler.getNewWindowState in src/vs/platform/windows/electron-main/windowsStateHandler.ts allows persisted fullscreen restoration when lifecycleMainService.wasRestarted is true. BaseWindow.doSetNativeFullScreen in src/vs/platform/windows/electron-main/windowImpl.ts maintains transient fullscreen state and now recovers after ten seconds when restoration times out and BrowserWindow reports it is not fullscreen. That recovery was introduced by https://github.com/microsoft/vscode/commit/1a37acbdf9c83ad21f68a48562346980a31ffa1b and refined by https://github.com/microsoft/vscode/commit/44fd438df521b26bb360fca7d4fee512415a5ddb; CodeWindow forwards the resulting event to src/vs/workbench/electron-browser/window.ts. The uncertainty is whether the original mixed-window update failure reaches this timeout branch or follows another native-state path. Preserve successful fullscreen restoration and do not assume external displays are required: a reporter reproduced on a fresh single-display machine. Related reports were consolidated into https://github.com/microsoft/vscode/issues/161586, and no open competing implementation was found in its timeline.

## Evidence

- **Confirmed reports, not missing basic reproduction information:** https://github.com/microsoft/vscode/issues/161586 supplies a mixed fullscreen/windowed restart-to-update sequence. Commenters confirmed reproduction on 1.73.0 and 1.75.1, and later on a fresh 1.79.2 installation never connected to an external display. These are historical confirmations, not a current-main reproduction.
- **Maintainer diagnosis and correction:** In the supplied discussion, maintainers identified a possible mismatch between presumed fullscreen state and actual native state. They also clarified that fullscreen windows legitimately retain normal width/height values, so default dimensions alone do not establish corrupted state or a missing-display root cause.
- **Concrete mitigation, not proven complete coverage:** https://github.com/microsoft/vscode/commit/1a37acbdf9c83ad21f68a48562346980a31ffa1b added recovery in BaseWindow.doSetNativeFullScreen: after a restored fullscreen transition times out, it clears transient state and emits onDidLeaveFullScreen. https://github.com/microsoft/vscode/commit/44fd438df521b26bb360fca7d4fee512415a5ddb restricts recovery to a window that is not actually fullscreen. These changes address the hypothesized failed-transition mechanism, but neither establishes which path affected the reporter's previously windowed windows.
- **Current restoration and notification path:** src/vs/platform/windows/electron-main/windowsStateHandler.ts:275-290 permits persisted fullscreen restoration after an application restart. src/vs/platform/windows/electron-main/windowImpl.ts:592-643 retains the ten-second recovery; its leave-fullscreen event is forwarded at lines 928-929 and handled by src/vs/workbench/electron-browser/window.ts:289-291. Native transition behavior was not executed in this read-only review.
- **This issue already owns the duplicate cluster:** Open-issue searches for fullscreen buttons, traffic lights and restart-related window controls found no verified older canonical with the same symptom. https://github.com/microsoft/vscode/issues/160328 was explicitly merged into this issue, as were https://github.com/microsoft/vscode/issues/182258 and https://github.com/microsoft/vscode/issues/190468; their closed state does not provide a duplicate target.
- **Upstream reference does not prove a fix:** https://github.com/electron/electron/issues/35360 describes asynchronous fullscreen API reporting. Its maintainer discussion identifies a documentation issue requiring transition-event handling, not a verified upstream fix for these missing controls.

The July 2025 comment asks for status; it neither confirms nor disproves the 2024 mitigation.
