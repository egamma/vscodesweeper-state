# Issue #331666 — create_file tool reports success on /memories/ virtual paths but writes nothing (silent no-op)

[https://github.com/microsoft/vscode/issues/331666](https://github.com/microsoft/vscode/issues/331666)

## Summary

Confirmed in source: `create_file` has no special handling for `/memories/...` paths — unlike the `Memory`/`ResolveMemoryFileUri` tools, which validate and route them into the physical memory store — so it treats the string as a literal absolute filesystem path and unconditionally reports success regardless of whether the write actually lands.

## Change summary

The create_file tool silently no-ops on /memories/ virtual paths while still returning a success message, causing agents to believe memory notes were saved when nothing was written.

## Best solution

In CreateFileTool.invoke (extensions/copilot/src/extension/tools/node/createFileTool.tsx), detect filePath values starting with /memories/ and reject them with an error directing the agent to the Memory tool, the same way memoryTool.tsx already validates its own paths — the current code path skips straight to `promptPathRepresentationService.resolveFilePath`, which resolves any string starting with `/` as a literal POSIX path with no notion of the virtual memory namespace.
