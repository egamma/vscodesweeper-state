# Issue #326758 — Persistent HTTP 503 error from tool_search during Copilot deferred-tool discovery

[https://github.com/microsoft/vscode/issues/326758](https://github.com/microsoft/vscode/issues/326758)

## Summary

The embeddings endpoint persistently returns HTTP 503 for tool_search, and the client in remoteEmbeddingsComputer.ts has no retry/backoff logic for transient server errors — it throws immediately. The service-side 503 is the root cause, but the client's lack of resilience is a valid in-repo concern. Related open issues https://github.com/microsoft/vscode/issues/318009 and https://github.com/microsoft/vscode/issues/318012 track the same embeddings path with HTTP 422 errors.

## Change summary

Copilot's tool_search fails with persistent HTTP 503 from the embeddings endpoint during deferred-tool discovery, blocking agent-mode tool use.

## Best solution

Two-pronged fix: (1) the Copilot service team should investigate why the embeddings endpoint returns persistent 503s for this user/configuration, and (2) the client in `extensions/copilot/src/platform/embeddings/common/remoteEmbeddingsComputer.ts` should add retry logic with exponential backoff for transient HTTP status codes (502, 503, 429) instead of throwing immediately on the first failure. The related 422 issues should be investigated together since they share the same embeddings request path.
