# Issue #241855 — Bash env doesn't update on first `unset`

[https://github.com/microsoft/vscode/issues/241855](https://github.com/microsoft/vscode/issues/241855)

## Summary

Still reproduces on main: the bash shell integration script does not track env var deletions, so when a var is `unset`, no `EnvSingleDelete` sequence is sent, and the old value persists in the capability's env state.

## Change summary

Unsetting an environment variable in bash does not update the terminal shell integration env on the first occurrence.

## Best solution

The bash shell integration script (`shellIntegration-bash.sh`) needs to track previously-reported env vars and emit `EnvSingleDelete` sequences for vars that were in the cache but are no longer set. The comment at line 322/344 explicitly defers this: 'Track missing env vars not needed for now'. Implementing the deletion tracking in `__vsc_update_env()` and emitting the `EnvSingleDelete` OSC sequence for disappeared vars would fix this.
