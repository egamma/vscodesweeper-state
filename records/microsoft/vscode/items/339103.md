[https://github.com/microsoft/vscode/issues/339103](https://github.com/microsoft/vscode/issues/339103)

## Summary

Real new regression in 0.68.0, but the root cause traces to the OpenTelemetry JS SDK's OTLP exporter retry/promise-queue code (otlp-exporter-base), not to anything this repo's otelServiceImpl.ts controls — it should stay open as an upstream-rooted issue, and it already has an assignee and the *fix automation label working it.

## Change summary

An unhandled 'Export failed with retryable status' rejection is thrown from the OTLP span/log/metric exporter when the configured collector endpoint (default http://localhost:4318) is unreachable, surfacing as a VS Code error report instead of being swallowed.

## Best solution

Either upstream @opentelemetry/otlp-exporter-base needs to stop leaving an unawaited rejection in its retry promise chain, or extensions/copilot/src/platform/otel/node/otelServiceImpl.ts should add a scoped guard (e.g. around exporter creation/export) to catch and log this specific rejection instead of letting it become an unhandled error, since DiagnosticSpanExporter only observes the resultCallback path today and never sees the raw internal retry promise.
