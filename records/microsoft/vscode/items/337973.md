# Issue #337973 — Agent sessions: built-in GitHub MCP server is locked to a read-only 19-tool subset and its toolset cannot be configured

[https://github.com/microsoft/vscode/issues/337973](https://github.com/microsoft/vscode/issues/337973)

## Summary

Current main confirms a real capability gap: Agent Host exposes the built-in GitHub MCP server through a fixed `X-MCP-Tools` allowlist and provides only an enable/disable setting, while the normal Copilot MCP path supports configurable `X-MCP-Toolsets`. No older open issue reports this same observable limitation, so this should remain open as a feature request.

## Change summary

Allow Agent Host sessions to expose user-selected GitHub MCP toolsets, including write-capable project, issue, label, and pull-request tools when authorized.

## Best solution

Define an explicit Agent Host contract for GitHub MCP toolset selection that works consistently across supported providers, preserves a safe default, and specifies how a same-endpoint user definition interacts with the built-in server.

- **Validation:** Extend the Agent Host GitHub MCP unit tests and run `./scripts/test.sh --grep "githubMcpServer"`; verify configured toolsets produce the intended request headers, the default remains restricted, disabling still removes the built-in server, and same-URL user definitions retain the selected behavior across supported providers.
- **Behavior:**

  > Agent sessions should let users deliberately select additional GitHub MCP toolsets when their account is authorized, rather than always exposing only the fixed built-in subset. The default experience must remain safe and predictable, and disabling the built-in server must continue to work. A user-supplied definition for the official endpoint must not silently lose its requested toolsets through deduplication. The behavior should be consistent across Agent Host providers.
- **Trace:**

  > On current main, `createGitHubMcpServerConfiguration` in src/vs/platform/agentHost/node/shared/githubMcpServer.ts constructs the official endpoint with fixed `X-MCP-Tools` and no `X-MCP-Toolsets`. The only corresponding root setting is the boolean registered in src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts and represented in agentHostSchema.ts. Claude consumes the shared configuration in `ClaudeAgentSession._getGitHubMcpServerConfiguration` and considers any discovered server with the same URL to be the built-in server; Codex also consumes the shared resolver, while Copilot delegates its built-in server to the runtime through `COPILOT_ENABLE_BUILTIN_GITHUB_MCP`. The normal Copilot extension path already has a separate configurable toolset contract in extensions/copilot/src/extension/githubMcp/common/githubMcpDefinitionProvider.ts. Preserve the existing safe default and enterprise endpoint resolution; do not broaden tools implicitly for users who have not opted in.
- **Open decisions:**
  - Should Agent Host inherit `github.copilot.chat.githubMcpServer.toolsets`, or expose a separate Agent Host setting with independently defined scope and persistence?
  - Does selecting a write-capable toolset replace the curated `X-MCP-Tools` restriction, intersect with it, or require a separate explicit opt-in?
  - When a user supplies the official GitHub MCP endpoint with custom headers, should that definition override the built-in configuration or be merged under a documented precedence rule?

## Evidence

- **current source gap:** src/vs/platform/agentHost/node/shared/githubMcpServer.ts defines only `X-MCP-Features` and `X-MCP-Tools`; `createGitHubMcpServerConfiguration` always populates the latter from hardcoded arrays and has no `X-MCP-Toolsets` input.
- **configuration surface:** src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts registers `chat.agentHost.githubMcpServer.enabled` as a boolean only; no Agent Host toolset setting exists on current main.
- **workbench precedent:** extensions/copilot/src/extension/githubMcp/common/githubMcpDefinitionProvider.ts reads configured toolsets and emits `X-MCP-Toolsets`, while extensions/copilot/package.json contributes `github.copilot.chat.githubMcpServer.toolsets`; that configuration is not consumed by the Agent Host path.
- **deduplication behavior:** src/vs/platform/agentHost/node/claude/claudeAgentSession.ts identifies a discovered GitHub MCP definition solely by matching its normalized remote URL and suppresses addition of the built-in definition when such a match exists, making same-endpoint precedence part of the required design.
- **related issues checked:** https://github.com/microsoft/vscode/issues/328241 concerns enterprise allowlist enforcement, not user-selected GitHub toolsets. https://github.com/microsoft/vscode/issues/337978 is newer, broader, and reports general tool-management/authentication inconsistencies rather than this same symptom, so neither clears the re-review duplicate bar.
