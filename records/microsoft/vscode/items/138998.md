# Issue #138998 — column number bug with emojis

[https://github.com/microsoft/vscode/issues/138998](https://github.com/microsoft/vscode/issues/138998)

## Summary

The status-bar column is intentionally a UTF-16 model offset, not a grapheme/display-cell count, so multi-code-unit emoji produce a larger column number. This behavior is confirmed by the source and remains an open correctness/UX issue because the label does not explain those semantics.

## Change summary

Report a user-perceived character column in the status bar when the line contains emoji or other multi-code-unit grapheme clusters.

## Best solution

Keep Monaco's UTF-16 `Position.column` contract unchanged for extensions and editor internals, but decide whether the workbench status bar should present a separate grapheme-aware display column or clarify that the value is a model offset.

- **Trace:**

  > Current editor positions use 1-based UTF-16 offsets, and the workbench editor-status contribution displays the active position without converting it to an extended-grapheme-cluster index. The boundary is the user-facing status display: do not silently change Monaco's `Position.column`, model offsets, extension API coordinates, selection behavior, or protocol contracts.
