# Issue #295620 — Copilot with Claude models fails to handle backticks with gh

[https://github.com/microsoft/vscode/issues/295620](https://github.com/microsoft/vscode/issues/295620)

## Summary

Still a valid issue — the terminal tool does not sanitize or escape shell-special characters (backticks) in model-generated commands before sending them to the shell, and no fix has landed on main. Already triaged with correct labels and milestone; keeping open.

## Change summary

When Copilot agent mode generates terminal commands containing backticks in double-quoted arguments (e.g. `gh pr create --body "text with `code`"`), the shell interprets backticks as command substitution, producing garbled output or hanging the terminal.

## Best solution

The best fix is a combination: (1) prompt-level guidance instructing the model to use `--body-file` or single-quoted / escaped arguments when content contains backticks, and (2) optionally a defensive layer in the terminal tool (in the agent host terminal contribution) that detects unescaped backticks in double-quoted strings and either escapes them or rewrites to a file-based approach. The prompt-based approach is more robust since it covers all shell metacharacters, but a tool-level guard would catch model failures.
