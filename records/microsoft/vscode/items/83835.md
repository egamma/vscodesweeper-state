# Issue #83835 — [css] support css-variable completion in calc 

[https://github.com/microsoft/vscode/issues/83835](https://github.com/microsoft/vscode/issues/83835)

## Summary

A real completion gap remains on current main, but the behavior is owned by the bundled vscode-css-languageservice dependency. Keep the issue open and classify it as upstream so the language-service implementation can be corrected and then consumed by VS Code.

## Change summary

CSS custom-property completion inside `calc()` should insert `var(--property)` rather than a bare `--property` reference.

## Best solution

Teach vscode-css-languageservice to offer ordinary declaration-value completions inside `calc()` arguments, preserving its existing behavior of wrapping custom properties as `var(--property)`, then update VS Code to consume that language-service version.

## Evidence

- **current integration:** `extensions/css-language-features/server/src/cssServer.ts` delegates completion directly to `vscode-css-languageservice` through `doComplete2`; `extensions/css-language-features/server/package.json` declares that dependency.
- **remaining source gap:** Current https://github.com/microsoft/vscode-css-languageservice/blob/main/src/services/cssCompletion.ts routes expressions within function arguments to `getCompletionsForFunctionArgument`, but that method only supplies custom-property proposals when the function is `var`; a `calc()` argument receives none of the generic declaration-value variable proposals.
- **existing wrapping behavior:** The same upstream file's `getVariableProposals` already inserts CSS custom properties as `var(${symbol.name})`, and https://github.com/microsoft/vscode-css-languageservice/blob/main/src/test/css/completion.test.ts verifies that a `--myvar` proposal in an ordinary declaration value becomes `var(--myvar)`. No corresponding `calc()` test exists.
- **related shipped capability:** https://github.com/microsoft/vscode/issues/133330 and https://github.com/microsoft/vscode/issues/133996 added and verified `var()` and custom-property suggestions, but neither covers the reporter-observable `calc(--property)` completion path.
- **canonical search:** No open microsoft/vscode issue found in searches for CSS-variable/custom-property completion inside `calc()`, so there is no verified older canonical that meets the stronger duplicate bar for this re-reviewed item.
