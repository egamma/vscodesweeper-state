# Issue #327088 — Linux .deb installer creates duplicate desktop shortcuts leading to startup crash loops and orphaned crashpad handlers on Ubuntu MATE

[https://github.com/microsoft/vscode/issues/327088](https://github.com/microsoft/vscode/issues/327088)

## Summary

There's a real, narrower bug hiding under an exaggerated report: resources/linux/code.desktop sets StartupWMClass from @@NAME_SHORT@@ (mixed-case, e.g. "Code"), which mismatches the actual lowercase runtime WM_CLASS on Linux, causing icon/taskbar grouping and launcher-matching issues on strict window managers like MATE — but the described crashpad-handler crash-loop mechanism is unverified and not something a WM_CLASS mismatch would plausibly cause. An open PR (#327720) already fixes the casing, so this should stay open pending that review rather than being closed or auto-fixed.

## Change summary

On Ubuntu MATE (and possibly other WMs), the .deb-installed launcher's StartupWMClass casing doesn't match the running app's WM_CLASS, reportedly causing duplicate/orphaned processes and crash loops.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/327720, which lowercases the StartupWMClass template value in build/gulpfile.vscode.linux.ts / resources/linux/code.desktop so it matches the runtime WM_CLASS; the crash-loop/crashpad narrative in the report should be treated with skepticism until independently confirmed.
