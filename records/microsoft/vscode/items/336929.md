# Issue #336929 — titleBar.inactiveForeground is overridden by additional opacity when the window is unfocused

[https://github.com/microsoft/vscode/issues/336929](https://github.com/microsoft/vscode/issues/336929)

## Summary

Confirmed in source: the title bar applies a blanket `opacity: 0.6` to all its children when the window is inactive, on top of the `titleBar.inactiveForeground`/`menubar.inactive` color, so a customized inactive foreground color never renders as configured. Whether this dimming is intentional design or should be reconciled with explicit color customization is a call for a maintainer, so this stays open rather than being auto-closed as as-designed.

## Change summary

titleBar.inactiveForeground (and the menubar's inactive color) is visually washed out by an additional CSS opacity applied to the whole inactive title bar, so a custom inactive foreground color can't be rendered exactly as configured.

## Best solution

A maintainer should decide whether the intentional 'dim inactive window chrome' opacity in titlebarpart.css (`.part.titlebar.inactive > *`, opacity 0.6) should be skipped for elements that already have an explicit `titleBar.inactiveForeground`/`activityBar.inactiveForeground` color applied, or whether the dimming is deliberate OS-convention behavior that should stay and the report should be declined as as-designed.

- **Reason:** Dimming inactive window chrome is a common, long-standing UI convention balancing simple/uniform UI against user color customization; the vision doesn't clearly favor one resolution.
