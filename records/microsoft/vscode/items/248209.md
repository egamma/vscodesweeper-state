## Evidence

- **Current source confirms the defect:** src/vs/editor/contrib/find/browser/findModel.ts:481–503, FindModelBoundToEditorModel.replace(), applies the replacement and then sets the search start to new Position(selection.startLineNumber, selection.startColumn + replaceString.length). For the reported replacement '\ntext1', this leaves the search start on the original line rather than after the inserted text. research(true) subsequently searches from that position, allowing the newly inserted 'text' to be selected again.
