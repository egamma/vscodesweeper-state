# Issue #323174 — Agent auto-persists referenceable/feature-specific knowledge into always-loaded global memory, inflating per-turn context cost

[https://github.com/microsoft/vscode/issues/323174](https://github.com/microsoft/vscode/issues/323174)

## Summary

Valid feature request for smarter memory tiering — relevance-scoping by workspace, preventing auto-persist of referenceable/feature-specific content to always-loaded global memory, and aging out stale entries. No fix has landed on main; the existing MemoryCleanupService only handles 14-day time-based retention, not the semantic scoping requested here.

## Change summary

The memory tool auto-persists feature-specific knowledge into always-loaded global memory, inflating per-turn context with irrelevant cross-workspace content.

## Best solution

Implement relevance-scoping in the memory tool: (1) distinguish global always-loaded memory (small cross-cutting facts) from repo/workspace-scoped on-demand memory, (2) stop auto-writing referenceable content that already exists in docs/ to the global tier, (3) add workspace-awareness so notes from workspace A don't load in workspace B, and (4) surface memory size/token footprint in the UI. The memory tool logic lives in extensions/copilot/src/extension/tools/ and the prompt instructions in extensions/copilot/src/extension/prompts/node/agent/.
