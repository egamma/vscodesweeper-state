## Summary

Keep open: current source still loads global memory without workspace relevance filtering, and the maintainer acknowledged changes were needed. The supplied cross-workspace steps suffice to retest; source inspection confirms the loading mechanism but not Claude's automatic choice to persist feature-specific content.

## Change summary

Prevent workspace-specific or already-referenceable knowledge from accumulating in automatically loaded global memory, and make its scope and context footprint controllable.

## Best solution

Preserve genuinely cross-workspace preferences while keeping project knowledge scoped and retrieved on demand, with explicit user control over persistence and an observable context budget. The memory owners should settle retention and confirmation semantics without treating manual cleanup as enforcement.
