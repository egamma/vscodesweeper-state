# Issue #342483 — Agent Host: `create_session` can't set reasoning effort or context tier, and passing `model` drops the caller's reasoning effort

[https://github.com/microsoft/vscode/issues/342483](https://github.com/microsoft/vscode/issues/342483)

## Summary

The reported configuration loss is still present in current source: explicitly supplying the caller's model replaces its configured selection with an ID-only selection. Keep this open; neither the existing global overrides nor the current tool schema provides the requested per-created-chat control.

## Change summary

Preserve supported reasoning and context selections during tool-driven chat creation and allow those selections to be specified per invocation.

## Best solution

Tool-created chats should retain compatible caller selections when the same model is explicitly named, while allowing validated per-call reasoning and context choices. Cover current-session chats, independent sessions, and the retained legacy create_chat execution path without changing provider boundaries or runtime policy precedence.

- **Independent sessions have the same loss:** src/vs/platform/agentHost/node/shared/sessionServerTools.ts:1152-1157 constructs an independent session's model as `{ id: args.model.id }` for an explicit model, but forwards defaults.model intact otherwise.
