# Issue #342483 — Agent Host: `create_session` can't set reasoning effort or context tier, and passing `model` drops the caller's reasoning effort

[https://github.com/microsoft/vscode/issues/342483](https://github.com/microsoft/vscode/issues/342483)

## Summary

Keep open: current source still discards model configuration when an explicit model is supplied, including when it names the caller's existing model. The reporter confirmed the behavior on 1.142.0; per-created-chat effort and context controls also remain unavailable.

## Change summary

Preserve supported reasoning and context selections during delegated chat creation and provide a way to choose them per created chat.

## Best solution

Explicitly naming the same model should not silently discard the caller's supported configuration. Agree on the model-facing contract for per-chat overrides, then provide consistent, capability-validated behavior across current-session creation, independent creation, and the retained create_chat compatibility path without bypassing managed model constraints.
