# Issue #65876 — Overriding the default 'type' command and then calling the default 'type' command results in significantly slower execution time

[https://github.com/microsoft/vscode/issues/65876](https://github.com/microsoft/vscode/issues/65876)

## Summary

Keep this accepted performance request open: extension-host affinity mitigates contention but does not eliminate the typing interception round trip. No verified fix or older canonical with the same observable symptom was established.

## Change summary

Reduce typing latency when an extension overrides `type` and forwards input to `default:type`.

## Best solution

Establish a current end-to-end latency baseline with the minimal forwarding extension, then reduce avoidable interception overhead while preserving extension-controlled typing semantics. Distinguish command execution time, extension-host contention, and input-to-paint delay before choosing an optimization.

Compare repeated baseline and intercepted typing runs, measuring command completion separately from input-to-paint latency; repeat with affinity enabled and disabled. Any proposed optimization should demonstrate a repeatable latency reduction without dropped or reordered characters, and preserve interception, composition, undo, and selection behavior.
- **Behavior:**

  > An extension that forwards intercepted typing unchanged to `default:type` should not introduce disproportionate typing delay or accumulating input lag. The thread provides a minimal forwarding extension and historical measurements, but the reported tenfold execution penalty has not been verified on current main. Establish separate command-completion and input-to-paint baselines before agreeing on a measurable acceptance target. Preserve character ordering and existing extension interception semantics.
- **Trace:**

  > Normal editor typing dispatches Handler.Type through CodeEditorWidget's command delegate in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts. An extension override registered through MainThreadCommands.$registerCommand sends execution to the extension host; forwarding to `default:type` returns through ExtHostCommands._doExecuteCommand and MainThreadCommands.$executeCommand. In src/vs/editor/browser/coreCommands.ts, both command names target the same editor handler. ExtensionRunningLocationTracker._computeAffinity supports isolation from other extensions but retains this round trip. Historical maintainer measurements distinguish rendering-frame delay from transport latency, so the source confirms an architectural cost, not the size or cause of today's slowdown. Related https://github.com/microsoft/vscode/issues/75627 concerns contention, and https://github.com/microsoft/vscode/issues/13441 concerns command ownership; neither should broaden this work into unrelated extension conflicts. Investigation must first establish which portion of the current forwarding path dominates latency.
