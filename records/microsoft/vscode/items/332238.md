Repeat with VS Code running and fully quit; confirm ordinary folder opening and the existing New Terminal Window command remain unchanged.
- **Behavior:**

  > Finder offers New VS Code Window Here and New VS Code Terminal Here. Folder selections use the folder itself; file selections use their parent folder. Multiple selections produce one corresponding window per distinct directory, with terminal windows starting in that directory. Acceptance must cover both an already-running application and invocation while VS Code is quit.
- **Trace:**

  > build/lib/electron.ts already registers public.folder document support and application URL schemes, but the inspected configuration has no NSServices declaration. src/vs/code/electron-main/app.ts contains existing macOS open-file handling; a native Services callback and its path into terminal creation were not established. workbench.action.terminal.newInNewWindow in src/vs/workbench/contrib/terminal/browser/terminalActions.ts already creates a compact auxiliary terminal window, and terminalService.ts supports terminal creation with cwd options. Preserve ordinary file/folder association behavior, existing terminal profiles, and normal command behavior. https://github.com/microsoft/vscode/issues/1223 supplies historical Service discussion, while https://github.com/microsoft/vscode/issues/200479 concerns a separate unwanted Finder association. The uncertainty starts at native Services registration and delivery, especially how a cold-start request reaches a workbench capable of creating the dedicated terminal window.
