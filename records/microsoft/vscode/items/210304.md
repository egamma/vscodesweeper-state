# Issue #210304 — Add a preRestartCommand / command equivalents of debug lifecycle hooks

[https://github.com/microsoft/vscode/issues/210304](https://github.com/microsoft/vscode/issues/210304)

## Summary

Current main supports the issue's alternative of correlating debug sessions with test runs, but does not expose the requested general command lifecycle hooks. Keep this team-authored request open until the owner decides whether test-run correlation satisfies the intended scope; no issue-referencing fix commit was established.

## Change summary

Allow extensions to coordinate debug restarts with test-run cleanup through command lifecycle hooks or an explicit test-run association.

## Best solution

Use the existing DebugSessionOptions.testRun integration for test-debug restart coordination where it meets the extensions' needs. Decide whether independent command lifecycle hooks remain necessary before expanding the debug configuration contract.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostDebugService.ts`, `src/vs/workbench/contrib/debug/browser/debugSession.ts`, `src/vs/workbench/contrib/debug/browser/debugService.ts`, `src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`
- **Validation:** In a test extension, associate a debug session with a TestRun, pause at a breakpoint, and press Restart. Verify cancellation reaches the old run, the extension completes cleanup before ending that run, and a new debug test run starts afterward. Repeat without testRun association to verify ordinary debug restart behavior remains unchanged; validate any approved command-hook contract separately.
- **Behavior:**

  > Vitest and Playwright need the debug toolbar's Restart action to coordinate cleanup of the previous test run before starting its replacement. The issue permits either command lifecycle hooks or explicit correlation between debug sessions and test runs. Acceptance should demonstrate that restarting a paused debug test does not reattach before the extension finishes the preceding run's cleanup, while ordinary non-test debugging retains its existing behavior.
- **Trace:**

  > Current main already exposes DebugSessionOptions.testRun in src/vscode-dts/vscode.d.ts. ExtHostDebugService.startDebugging forwards its run/task identifiers, DebugSession resolves correlatedTestRun, and DebugService.restartSession cancels an active correlated run, awaits its completion, and invokes runResolvedTests with the original request. The generic restart path still uses task lifecycle hooks; no preRestartCommand implementation was found in the inspected debug sources. The original ordering requirement is documented at https://github.com/vitest-dev/vscode/issues/320#issuecomment-2051200414, and the maintainer confirms both integrations' interest at https://github.com/vitest-dev/vscode/issues/320#issuecomment-2053693355. The unresolved boundary is whether the existing test-specific contract fulfills this request or whether a general extension-command contract is independently desired. Preserve unrelated adapter restart behavior and do not treat the external extension issue's closure as completion of this core request.
- **Open decisions:**
  - Does the existing DebugSessionOptions.testRun lifecycle integration satisfy the intended scope, or should VS Code additionally expose general command-based debug lifecycle hooks?
  - If general command hooks remain required, which lifecycle phases should they cover, and should a command failure cancel the associated debug operation?
