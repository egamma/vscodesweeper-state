# Issue #39888 — Feature Request: Keybinding Overloading

[https://github.com/microsoft/vscode/issues/39888](https://github.com/microsoft/vscode/issues/39888)

## Summary

Keep this accepted Backlog request open: current keybinding resolution still selects one matching command rather than offering a choice. The request has 26 upvotes, and neither the existing conflict inspector nor sequential command execution supplies the requested behavior.

## Change summary

Offer an opt-in menu of applicable commands when multiple commands share the same keybinding, instead of silently choosing one.

## Best solution

Design an optional, keyboard-accessible command chooser for simultaneously applicable bindings while preserving existing resolution by default. Establish its interaction with incomplete chord sequences before changing the shared resolver and dispatch contracts.

## Plan brief

- **Likely files:** `src/vs/platform/keybinding/common/keybindingResolver.ts`, `src/vs/platform/keybinding/common/abstractKeybindingService.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/platform/keybinding/test/common/keybindingResolver.test.ts`, `src/vs/platform/keybinding/test/common/abstractKeybindingService.test.ts`
- **Validation:** Extend the resolver and abstract keybinding service suites to cover two simultaneously applicable commands, one applicable command, excluded when conditions, cancellation, and unchanged default precedence. Manually bind two commands to the same shortcut, enable the proposed mode, verify keyboard selection executes only the chosen command, and verify cancellation executes neither; include chord cases matching the agreed design.
- **Behavior:**

  > When overload selection is enabled, pressing a shortcut shared by multiple applicable commands presents an accessible choice instead of silently executing the winning binding. Selecting a command executes only that command; cancelling executes none. A single applicable command retains direct execution, and disabling the feature preserves existing precedence. This is not sequential macro execution or handler-controlled fallback.
- **Trace:**

  > KeybindingResolver.resolve and _findCommand in src/vs/platform/keybinding/common/keybindingResolver.ts reduce matching candidates to one result, which AbstractKeybindingService dispatches in src/vs/platform/keybinding/common/abstractKeybindingService.ts. This behavior was confirmed by read-only source inspection, not runtime execution. The existing keybindings.editor.showConflicts action only filters the shortcuts editor, while runCommands executes a sequence, so neither provides the requested chooser. Preserve existing when-condition filtering, command arguments, removal rules, and default dispatch behavior; do not introduce handler-controlled fallback chains. The shared resolver also returns MoreChordsNeeded, so the interaction between complete matches and longer chord prefixes needs a product decision. The decline in https://github.com/microsoft/vscode/issues/134544#issuecomment-937615186 concerns asynchronous fallback execution, not this chooser.
- **Open decisions:**
  - With overload selection enabled, when a pressed sequence matches complete commands and also prefixes a longer chord, should it offer the complete commands immediately or retain chord continuation precedence?
