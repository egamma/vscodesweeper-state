# Issue #325825 — Configure Tools selection still does not persist in VS Code 1.128.0

[https://github.com/microsoft/vscode/issues/325825](https://github.com/microsoft/vscode/issues/325825)

## Summary

The persistence bug remains actionable: a second reporter confirmed the same selection rollback on 1.130 and isolated it to the presence of a custom tool-set file. The issue should stay open for diagnosis of the interaction between custom tool sets and persisted Configure Tools state.

## Change summary

Tool selections made through Configure Tools revert when the dialog is reopened, particularly when a custom tool set exists.

## Best solution

Make tool enablement changes persist independently of custom tool-set definitions, while retaining custom tool sets and their intended membership. Add regression coverage for changing individual tool selections with a custom tool-set file present.

- **Validation:** Add an automated chat tools configuration test that creates a custom tool set, changes an individual tool selection through the same persistence service used by Configure Tools, reloads that state, and asserts the changed selection remains while the custom tool set is preserved.
- **Behavior:**

  > When a user selects or deselects an individual tool in Configure Tools and confirms the dialog, reopening Configure Tools must show that choice unchanged. The behavior must remain correct when one or more custom tool sets exist, without requiring users to delete their tool-set files. Custom tool-set definitions and membership must remain intact.
- **Trace:**

  > The original report reproduces the selection rollback on 1.128.0, and an independent report confirms the same symptom on 1.130. The strongest boundary clue is that removing a custom tool-set file from the user prompts directory restores individual tool-selection persistence, which points to state reconciliation between custom tool sets and configured tool enablement rather than the dialog alone. Trace the Configure Tools confirmation path and the custom tool-set discovery/reconciliation path under `src/vs/workbench/contrib/chat`; preserve behavior when no custom tool sets exist and do not remove or rewrite valid tool-set definitions. The supplied candidate issues do not report this same observable symptom.

## Evidence
