# Issue #339441 — Allow configuring which terminal profiles are elevated into the AI group

[https://github.com/microsoft/vscode/issues/339441](https://github.com/microsoft/vscode/issues/339441)

## Summary

Confirmed on main: the AI-group split in terminalMenus.ts is a hardcoded substring match on profile name/extension id with no configuration surface, exactly as described. Reasonable, well-diagnosed request; keeping open as a feature request pending a maintainer design decision on the mechanism.

## Change summary

Make which terminal profiles get elevated into the AI dropdown group configurable, instead of a hardcoded name-substring match for 'copilot'/'claude'.

## Best solution

Extend the terminal profile schema (or add a settings-level matcher list) so user-defined profiles can opt into the AI group the same way contributed profiles can via the existing terminalProfileGroup proposed API; needs a maintainer to pick the mechanism given the related #332673 (opt-out) discussion.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalMenus.ts`, `src/vs/platform/terminal/common/terminal.ts`
- **Validation:** A test verifying a user-defined terminal profile is routed into the AI group via the chosen configuration mechanism (setting or profile field), not by name substring.
- **Behavior:**

  > A user should be able to control which `terminal.integrated.profiles.*` entries are elevated into the AI dropdown group, without relying on the profile's display name containing 'copilot' or 'claude'. Existing contributed-profile behavior (via the `terminalProfileGroup` proposed API) should remain unaffected.
- **Trace:**

  > `isAiProfileName()` and `isAiContributedProfile()` in src/vs/workbench/contrib/terminal/browser/terminalMenus.ts (lines 877-915) are the sole gate for AI-group placement; `splitProfiles()`/`splitContributedProfiles()` call them and feed `getTerminalActionBarArgs()` (used at line 820). No configuration is consulted. Do not touch the contributed-profile path (`isAiContributedProfile`/extension id checks) which already has a working opt-in mechanism via #293569 — the gap is only for user-defined `terminal.integrated.profiles.*` entries. Related: https://github.com/microsoft/vscode/issues/332673, https://github.com/microsoft/vscode/issues/293569, https://github.com/microsoft/vscode/issues/293554.
- **Open decisions:**
  - Should the mechanism be a new settings-level matcher list (e.g. `terminal.integrated.profiles.aiGroupMatchers`) or a per-profile schema field (e.g. `group: "ai"`) mirroring the proposed `terminalProfileGroup` API?
  - Should this also subsume #332673's request to disable the AI grouping entirely, or stay scoped to selecting which profiles are included?
