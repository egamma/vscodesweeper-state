# Issue #196491 — [wrapped lines] inline chat zone shows on the wrong line

[https://github.com/microsoft/vscode/issues/196491](https://github.com/microsoft/vscode/issues/196491)

## Summary

Still present on main: ZoneWidget always sets afterColumn from the position, causing view-zone placement between wrapped segments of a model line instead of after the last wrapped segment. No fixing commit found.

## Change summary

Inline chat zone widget appears between wrapped line segments instead of after the full wrapped line when word wrap is enabled.

## Best solution

Fix the view-zone positioning for wrapped lines in `src/vs/editor/browser/viewParts/viewZones/viewZones.ts` or `src/vs/editor/contrib/zoneWidget/browser/zoneWidget.ts`. The `_computeWhitespaceProps` path that handles `afterColumn` should ensure the zone is placed after the last view line of the model line (e.g. by using `afterColumnAffinity: PositionAffinity.Right` or defaulting to max column). This is a broader editor API issue affecting any consumer of view zones with word wrap, not just inline chat.

  > The view zone appears between wrapped segments of a model line instead of after the last segment. Traced in src/vs/editor/browser/viewParts/viewZones/viewZones.ts `_computeWhitespaceProps` (lines 158-196): when `afterColumn` is set (lines 159-163), the model position (lineN, afterColumn) is converted to a view position via `convertModelPositionToViewPosition`, and if afterColumn is 1 (or any column before a wrap break), it maps to an early view line of the wrapped model line. The zone should appear after the LAST view line. The root cause is in src/vs/editor/contrib/zoneWidget/browser/zoneWidget.ts lines 330-331 where `updatePositionAndHeight` blindly sets `afterColumn` from the position's column without considering word wrap. Fix options: (1) In ZoneWidget, when setting afterColumn from a position, also set `afterColumnAffinity` to `PositionAffinity.Right` so the coordinate converter maps to the end of the wrapped segment, OR (2) in ZoneWidget, default afterColumn to the line's max column so the zone always appears after the full line. Option 1 is more surgical. Do NOT change how view zones work for consumers that intentionally position zones mid-wrap. Validate with a unit test: create a model with word wrap, a long line that wraps, add a zone widget after that line, and assert it renders after the last wrapped segment.
