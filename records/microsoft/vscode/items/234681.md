# Issue #234681 — weird behaviour in some cases when assigning multiple keybindings

[https://github.com/microsoft/vscode/issues/234681](https://github.com/microsoft/vscode/issues/234681)

## Summary

Still reproduces on main: `findUserKeybindingEntryIndex` in the keybinding editing service matches entries by command + when expression only, which can incorrectly identify the wrong entry when multiple user keybindings exist for the same command with different keys but overlapping when-expression states during editing.

## Change summary

Editing the when expression of a second keybinding for the same command incorrectly overwrites the first keybinding's key.

## Best solution

Fix `findUserKeybindingEntryIndex` in `src/vs/workbench/services/keybinding/common/keybindingEditing.ts` to also match on the keybinding key (not just command + when), so that editing one entry doesn't accidentally target a sibling entry for the same command.

Root cause is `findUserKeybindingEntryIndex` in `src/vs/workbench/services/keybinding/common/keybindingEditing.ts` (line 175) — it matches entries by command + when expression only, ignoring the `key` field. When two entries share the same command and neither has a when expression set yet (or both have the same when), the method returns the first match, causing the wrong entry to be updated. Fix: include the keybinding key in the match criteria so the correct entry is identified. The key from the `keybindingItem` should be compared against `keybinding.key` in the user entries. Do NOT change the add-new-entry path (index === -1).
