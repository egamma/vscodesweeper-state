# Issue #331746 — Markdown previews do not support path drag-and-drop

[https://github.com/microsoft/vscode/issues/331746](https://github.com/microsoft/vscode/issues/331746)

## Summary

Real gap: the markdown preview tab's editor input exposes a synthetic `webview-panel://` resource instead of the underlying markdown file's URI, so it's filtered out of drag-and-drop file data. Fixing this generically for WebviewInput needs a product/API decision rather than a narrow patch, so routing to the relevant area rather than closing.

## Change summary

Dragging an open markdown preview tab into the terminal (or elsewhere expecting a file path) does not insert the underlying markdown file's path, unlike dragging the real text editor tab.

## Best solution

Decide whether `WebviewInput` (src/vs/workbench/contrib/webviewPanel/browser/webviewEditorInput.ts) or the markdown preview provider specifically should expose an associated source-file resource for drag-and-drop purposes, then have `fillEditorsDragData` (src/vs/workbench/browser/dnd.ts) use it when populating file/text drag data.

## Evidence

- **synthetic resource:** src/vs/workbench/contrib/webviewPanel/browser/webviewEditorInput.ts:51-56 — WebviewInput.resource returns a URI with scheme Schemas.webviewPanel (`webview-panel/webview-...`), not the markdown source file's URI.
- **drag data filtering:** src/vs/workbench/browser/dnd.ts fillEditorsDragData() builds resources from `editor.editor.resource` and then filters via `fileService.hasProvider(resource)` before building the text/file transfer data used for e.g. terminal path insertion; the webviewPanel scheme has no file provider so preview tabs are excluded.
- **extension architecture:** Markdown preview is implemented purely via vscode.window.createWebviewPanel on the extension side (extensions/markdown-language-features/src/preview/preview.ts), which maps to the generic core WebviewInput — there's no existing hook for the extension to associate a backing file resource with the panel for DnD.
