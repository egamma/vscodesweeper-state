# Issue #74360 — [folding] Fold All in selection

[https://github.com/microsoft/vscode/issues/74360](https://github.com/microsoft/vscode/issues/74360)

## Summary

A real capability gap remains: Fold All is file-wide, while Fold Recursively only operates on the folding region containing each selection's start line and does not fold arbitrary ranges across a selected span. The Backlog request should remain open while maintainers decide the command and selection-boundary semantics.

## Change summary

Make it possible to fold all folding ranges within the editor's current selection instead of affecting the entire file.

## Best solution

Provide selection-scoped recursive folding while preserving the established file-wide Fold All behavior when there is no non-empty selection. A maintainer should decide whether this is an overload of Fold All or a separate command and how partially intersecting folding ranges are handled.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Extend the folding model tests with several sibling and nested ranges plus a multi-line selection; verify that the ranges selected under the chosen boundary rule collapse, ranges outside the selection remain unchanged, and the no-selection path still folds the whole model.
- **Behavior:**

  > Users need an action that recursively folds code only within a non-empty editor selection, leaving folding ranges outside that selection unchanged. With no non-empty selection, the established file-wide Fold All behavior must remain available. Acceptance must cover sibling and nested folding ranges, selection boundaries, and the unchanged no-selection behavior after maintainers choose the command and boundary semantics.
- **Trace:**

  > FoldAllAction in src/vs/editor/contrib/folding/browser/folding.ts calls setCollapseStateLevelsDown without locations, which deliberately selects every folding region. FoldRecursivelyAction passes FoldingAction.getSelectedLines(), but that helper retains only each selection's start line; setCollapseStateLevelsDown in src/vs/editor/contrib/folding/browser/foldingModel.ts then operates on the containing region and its descendants. The existing foldingModel tests cover line-scoped recursive folding and whole-model folding, but not a selected line span. https://github.com/microsoft/vscode/issues/32607 documents the established convention that an All command remains file-wide, while https://github.com/microsoft/vscode/issues/61463 confirms recursive folding as a workaround for one containing region. Keep the change within folding actions/model selection logic and do not alter folding providers, range computation, or the extension API.
- **Open decisions:**
  - Should a non-empty selection change the behavior of the existing Fold All command, or should selection-scoped folding be exposed as a separate command while Fold All remains unconditionally file-wide?
  - Should the operation include folding ranges whose start line is inside the selection, only ranges fully contained by it, or any range intersecting it?

## Evidence

- **current Fold All behavior:** src/vs/editor/contrib/folding/browser/folding.ts:994-1011 defines FoldAllAction and calls setCollapseStateLevelsDown(foldingModel, true) without any selection lines, so every folding region is considered.
- **partial existing capability:** src/vs/editor/contrib/folding/browser/folding.ts:571-574 and 811-829 show that Fold Recursively reduces each selection to its start line and folds the containing region and descendants; it does not use the selected range's end or cover arbitrary sibling regions across the span.
- **model behavior:** src/vs/editor/contrib/folding/browser/foldingModel.ts:349-369 scopes setCollapseStateLevelsDown either to regions found at supplied line numbers or, when no lines are supplied, to the entire model. There is no selected-range mode.
- **existing convention:** In https://github.com/microsoft/vscode/issues/32607#issuecomment-327435299, a maintainer stated that Unfold All intentionally affects the whole file regardless of selection and directed users to Unfold Recursively. This makes changing the established Fold All contract a product decision rather than an obvious implementation detail.
- **canonical search:** Older https://github.com/microsoft/vscode/issues/61463 was closed after its reporter accepted Unfold Recursively for a containing function, but it does not cover arbitrary selection spans. Searches found no older open issue with the same observable request, so there is no valid duplicate canonical.
