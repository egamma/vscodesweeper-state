# Issue #332505 — Create session from PR: wrong repo is used for PR list

[https://github.com/microsoft/vscode/issues/332505](https://github.com/microsoft/vscode/issues/332505)

## Summary

Real, plausible bug in the 'New Session from Pull Request' repo-resolution path, but I couldn't pin down the exact swap mechanism from source alone, and the issue already carries the real 1.136.0 milestone, which blocks any close regardless.

## Change summary

Creating a session from a pull request shows the PR list for the wrong repo when the user has two similarly-configured repos (e.g. vscode-docs and vscode-docs-pr).

## Best solution

In src/vs/sessions/contrib/github/browser/pullRequestPicker.ts, resolvePullRequestSessionRepository() picks folderUri from the first non-GitHub-remote folder across all of the section's sessions, while the separate getFirstGitHubRepository() helper independently scans all folders of all sessions for the first one with resolved gitHubInfo (no scheme filter, no requirement that it be the same folder/session as folderUri). A maintainer should verify whether these two independent 'first match' scans can diverge (e.g. a multi-root workspace, a not-yet-resolved gitHubInfo on the chosen folder, or a stale/instance-shared GitHubRepositoryModel) and make identity resolution derive owner/repo from the same folder that produced folderUri instead of scanning independently.
