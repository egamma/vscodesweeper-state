# Issue #337322 — Sending the first message to a remote session caused a different session to open

[https://github.com/microsoft/vscode/issues/337322](https://github.com/microsoft/vscode/issues/337322)

## Summary

A detailed, well-diagnosed race condition from a maintainer (occurred once, during tunnel reconnect for a remote Agent Host session) where a still-deferred new session gets replaced by a stale archived session in the UI during first-send materialization. Keep open — the reporter's own timeline and technical breakdown are strong, but I could not independently trace the exact reconciliation code path (catalogue refresh / active-session fallback) that causes the archived-session swap, so I can't confirm the fix location from source alone.

## Change summary

When the Agent Host tunnel drops/reconnects during the first send of a new deferred session, the client transiently swaps the active/visible session to an archived one before the real new session finishes materializing.

## Best solution

Trace the session catalogue reconciliation path (listSessions refresh vs. locally-tracked pending/new session) to implement one or more of the reporter's suggested safeguards — preserve locally known pending sessions across a catalogue refresh, and/or pin the active session while its first request is in flight — most likely in the session collection/active-session tracking code near sessionsManagementService.ts and the view service that listens to onWillSendRequest/onDidSendRequest.
