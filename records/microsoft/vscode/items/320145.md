# Issue #320145 — Tools without `inputSchema` send requests to OpenAI-compatible endpoints with `parameters` field omitted

[https://github.com/microsoft/vscode/issues/320145](https://github.com/microsoft/vscode/issues/320145)

## Summary

Keep open: another reporter confirmed the LM Studio failure and supplied a schema-repair proxy workaround. Current main normalizes missing parameters at the BYOK request boundary, but that Chat Completions behavior predates this report; the newer Responses fix does not establish that the reported omission is resolved.

## Change summary

Ensure parameterless tools sent through Copilot BYOK to OpenAI-compatible endpoints have an explicit object parameters schema.

## Best solution

Establish which request path bypassed the existing normalization, then ensure the serialized BYOK request includes an object schema for parameterless tools without requiring existing extension contributions to declare inputSchema.

Pin any identified bypass with a serialized-request regression test covering mixed parameterless and parameterized tools.
- **Behavior:**

  > Agent mode with an LM Studio OpenAI-compatible endpoint must not fail because a parameterless tool lacks its parameters schema. The reporter and another user observed this failure, with a schema-repair proxy providing a workaround. Acceptance requires inspecting the serialized outbound request, including mixed parameterless and parameterized tools, and confirming parameterless tools have an explicit object schema. Existing schemas and extension contribution compatibility must remain unchanged.
- **Trace:**

  > DefaultToolCallingLoop in extensions/copilot/src/extension/intents/node/toolCallingLoop.ts passes optional inputSchema directly, and CopilotLanguageModelWrapper in extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts can also produce undefined parameters. OpenAIEndpoint.interceptBody already repairs undefined function.parameters, and networkRequest invokes that hook before handing the JSON body to the fetcher. This normalization predates the report, so intermediate undefined values alone do not prove an outbound defect. Current openAIEndpoint.spec.ts contains parameterless-tool checks for Chat Completions and Responses, but these inspect body objects rather than captured serialized requests. The uncertainty is which actual provider/request path produced the reporter's omitted field; reproduce that path before deciding whether additional code is needed. The later Responses-only fix at https://github.com/microsoft/vscode/commit/2f7f56e135f4af871fb356e519e377ab908548e7 addresses an empty-schema rejection and must not be assumed to resolve this omission. Keep the investigation bounded to outbound BYOK schema handling; making IToolData.inputSchema globally required is not an acceptance requirement.
