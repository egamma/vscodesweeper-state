# Issue #320145 — Tools without `inputSchema` send requests to OpenAI-compatible endpoints with `parameters` field omitted

[https://github.com/microsoft/vscode/issues/320145](https://github.com/microsoft/vscode/issues/320145)

## Summary

Confirmed on current main: tools without `inputSchema` emit OpenAI tool definitions with `parameters` omitted, violating the OpenAI spec and breaking strict OpenAI-compatible endpoints (LM Studio, etc.). The bug is in the tool-conversion code in the Copilot extension, not fixed.

## Change summary

Agent mode sends tool definitions without the required `parameters` field to OpenAI-compatible BYOK endpoints when a tool has no `inputSchema`, causing 400 errors.

## Best solution

Add a normalizer at the tool-conversion boundary — when mapping `IToolData` to `OpenAiFunctionDef`, default `parameters` to `{ type: 'object', properties: {} }` when `inputSchema` is undefined. The primary site is `toolCallingLoop.ts` line 1569; the same pattern appears in the OTel logging paths of `anthropicProvider.ts` and `geminiNativeProvider.ts`. A single `toOpenAIParameters()` helper avoids scattering the fallback.
