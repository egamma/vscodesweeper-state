# Issue #337963 — Asking a question from agent, the agent answered and resolved the comment

[https://github.com/microsoft/vscode/issues/337963](https://github.com/microsoft/vscode/issues/337963)

## Summary

Traced this to the Agents Window feedback/comment system: when the agent replies to a question left as a feedback comment and then resolves it in the same turn, the comment (and the reply text inside it) is hidden by default, with no notification that a reply landed — matching the reporter's 'agent answered and resolved, so I never saw its response'.

## Change summary

In the Agents Window, asking a question via a feedback comment and having the agent both answer and resolve it in one step hides the answer from the user with no way to notice it happened.

## Best solution

Decide the intended UX for this case in agentFeedbackService.ts / agentEditorCommentsProvider.ts — e.g. don't auto-resolve a comment in the same turn a reply was added until the user has seen it, or surface an 'unread reply' indicator for resolved items — then implement it.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts`, `src/vs/sessions/contrib/agentFeedback/browser/agentEditorCommentsProvider.ts`, `src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts`
- **Validation:** A test asserting that after `replyToComment` followed by `resolveComments` on the same feedback item within one turn, the reply is still surfaced to the user (e.g. still visible, or an unread-reply signal is set) rather than silently hidden.
- **Behavior:**

  > When a user leaves a question as a feedback/editor comment and the agent both replies and resolves that comment in the same turn, the user must still be able to see the agent's answer — either the comment stays visible until acknowledged, or some clear signal (badge/notification) points the user at the newly-resolved thread with an unread reply. Acceptance: after an agent replies-then-resolves a comment, the reply is not silently lost from the default UI.
- **Trace:**

  > `markFeedbackSubmitted` in agentFeedbackService.ts sets agent-host feedback items to `AgentFeedbackState.Submitted`/`Resolved`; the agent later calls the `resolveComments` tool (agentFeedbackServerTools.ts) after `replyToComment`, and `listComments`/the editor comment provider (agentEditorCommentsProvider.ts) omit resolved items by default (`getVisibleResolvedFeedbackIds` is the only path back to visibility). `onDidAddReply` exists but is wired only to telemetry (sessionsTelemetry.contribution.ts), not to any UI affordance. Do not change the underlying resolve/reply tool contracts or the default 'hide resolved comments' behavior for comments the user never asked about — the fix should be scoped to surfacing unseen replies on comments the agent resolves in the same pass it replied.
- **Open decisions:**
  - Should the agent be blocked from resolving a comment in the same turn it replies to it, so the user has a chance to see the answer first?
  - Should there be a UI indicator (badge/notification) for a resolved comment that carries an unread agent reply?
  - Should question-type feedback comments behave differently from actionable feedback comments with respect to auto-resolve?

## Evidence

- **resolve hides replies:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts `markFeedbackSubmitted` documents that agent-host sessions 'hand the feedback to an agent that resolves each comment (via the resolveComments tool) once it has acted on it'; resolved items are then omitted by default per the `listComments` tool description in src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts ('Resolved comments are omitted by default').
- **no unread-reply signal:** `onDidAddReply` (agentFeedbackService.ts) is only consumed for telemetry logging in sessionsTelemetry.contribution.ts — there is no UI badge/notification when a reply is added to an item that becomes resolved.
- **resolved items hidden from editor:** src/vs/sessions/contrib/agentFeedback/browser/agentEditorCommentsProvider.ts only re-surfaces a resolved item via `hideFeedbackInEditor`/`getVisibleResolvedFeedbackIds`, i.e. resolved comments are hidden from the editor comment surface unless explicitly toggled visible.
- **no recent fix:** `git log` on agentFeedbackService.ts shows no commit addressing this reply-then-resolve visibility gap.
