# Issue #339938 — Sandboxed Copilot sessions hang during MCP startup when using a localhost proxy

[https://github.com/microsoft/vscode/issues/339938](https://github.com/microsoft/vscode/issues/339938)

## Summary

Thanks for the detailed report. This is a team-authored bug parked in On Deck. The reproduction steps are complete and the diagnosis points to a missing sandbox proxy route in the agent host. I did not inspect the code or history, so I could not confirm the defect or find a fix, and it stays open. The report also names a workaround: `chat.agent.sandbox.network.allowLocalNetwork`.

## Change summary

With a localhost HTTP(S) proxy configured, sandboxed Copilot sessions hang during local stdio MCP startup because the sandbox denies loopback access and no proxy route is supplied.

## Best solution

When VS Code forwards proxy settings or environment variables to the agent host runtime, populate the sandbox network proxy route (`userPolicy.network.proxy`) for loopback proxies. Also surface MCP startup progress or timeouts in the UI instead of an indefinite 'Reasoning…' state.
