# Issue #118905 — Some emojis not displaying correctly in VSCode macOS

[https://github.com/microsoft/vscode/issues/118905](https://github.com/microsoft/vscode/issues/118905)

## Summary

Keep this open as an upstream font-rendering issue: the editor behavior was reproduced in Chromium outside VS Code, while terminal spacing also depends on Unicode width handling and the application running in the terminal.

## Change summary

Emoji variation sequences render as monochrome or incorrectly sized glyphs in the macOS editor and can have inconsistent terminal spacing.

## Best solution

Track the editor rendering defect with Chromium and retain this issue as the VS Code-facing upstream tracker; keep terminal-specific width behavior aligned with xterm.js and Unicode-version handling rather than conflating it with the editor defect.

## Evidence

- **upstream reproduction:** A VS Code maintainer reproduced the editor behavior in a standalone Chromium test page and opened Chromium issue https://bugs.chromium.org/p/chromium/issues/detail?id=1190093; Safari rendered the same Menlo content differently.
- **maintainer diagnosis:** The maintainer explained that editor text rendering is delegated to Chromium, and the issue already carries `upstream` and `upstream-issue-linked`.
- **current confirmations:** Comments through 2024 report that affected variation-selector emoji such as ⚠️ still render incorrectly on modern macOS/VS Code, including VS Code 1.87 with Chromium 118; font-family workarounds are inconsistent.
- **terminal boundary:** The terminal maintainer identified a separate width problem governed by `terminal.integrated.unicodeVersion` and linked xterm.js issue https://github.com/xtermjs/xterm.js/issues/1709; the original reporter also observed spacing outside VS Code in the macOS terminal.
- **related report:** https://github.com/microsoft/vscode/issues/223483 remains open for a narrower pencil-emoji rendering case and does not absorb this issue's broader editor and terminal evidence.
