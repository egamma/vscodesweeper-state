# Issue #118905 — Some emojis not displaying correctly in VSCode macOS

[https://github.com/microsoft/vscode/issues/118905](https://github.com/microsoft/vscode/issues/118905)

## Summary

Still a valid upstream Chromium issue: the default macOS editor font Menlo does not fall back to Apple Color Emoji for certain Unicode codepoints (those using Variation Selector-16). The Chromium bug filed by alexdima remains the canonical upstream tracker. VS Code's default font stack in fontInfo.ts still starts with Menlo, so the issue persists out of the box on macOS.

## Change summary

Certain emojis (gear, zap, recycle, etc.) render as small monochrome glyphs instead of colorful emoji in the VS Code editor on macOS due to Chromium's font fallback behavior with the Menlo font.

## Best solution

The ideal fix is in Chromium's font fallback (bug 1190093). A VS Code workaround could add 'Apple Color Emoji' to the default macOS font stack in `src/vs/editor/common/config/fontInfo.ts` (`DEFAULT_MAC_FONT_FAMILY`), but that has been reported to cause side effects with non-emoji character rendering. Keep tracking the upstream Chromium fix; the existing workaround (users adding Apple Color Emoji to their font settings) is documented in the comments.
