# Issue #330984 — "View comments" tool doesn't reliably detect comments

[https://github.com/microsoft/vscode/issues/330984](https://github.com/microsoft/vscode/issues/330984)

## Summary

The stale-result path remains on current main: review threads refresh initially and poll every 60 seconds, but invoking `viewUnreviewedComments` reads the existing annotation snapshot without forcing a GitHub refresh. This team-authored bug should remain open until that tool-triggered path is fixed or explicitly verified otherwise.

## Change summary

Make the View Comments tool reliably discover newly added pull-request review comments instead of returning an empty result from cached state.

## Best solution

Before deciding that no pull-request review comments exist, the View Comments flow should force and await an authoritative refresh for every pull request associated with the session, then mirror and return the refreshed comments while retaining periodic polling as background synchronization.

- **Behavior:**

  > When a pull-request review comment is added after the Agents window's previous refresh, invoking View Comments must discover and return it immediately. The flow must not report that there are no comments merely because the periodic poll has not run yet. Existing selection, submission, multi-PR, and resolved-comment filtering behavior must remain unchanged. Acceptance requires a test where a newly available comment is returned by the tool before the next scheduled poll.
- **Trace:**

  > The GitHub-side source of truth is GitHubPullRequestReviewThreadsModel in src/vs/sessions/contrib/github/browser/models/githubPullRequestReviewThreadsModel.ts. CodeReviewService in src/vs/sessions/contrib/codeReview/browser/codeReviewService.ts refreshes when the active PR context is established and then polls every 60 seconds; AgentFeedbackPRReviewSeederContribution mirrors only the resulting observable comments into Agent Host annotations. The `viewUnreviewedComments` case in src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts reads that annotation state synchronously and cannot request or await a client-side refresh, so a tool call during the polling gap returns an empty list. Commit https://github.com/microsoft/vscode/commit/2ae61ac0521a646704be58617b3ea56a2ed9cd09 reduced but did not eliminate this gap. The uncertainty starts at the cross-process synchronization seam needed to refresh and mirror comments before tool evaluation; preserve the existing annotation state machine, explicit-selection behavior, multi-PR support, and background polling.

## Evidence

- **tool path:** src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts handles `viewUnreviewedComments` by synchronously reading `pendingRevealAnnotations(state)` or `createdReviewableAnnotations(state)`; it has no refresh step before returning an empty comments array.
- **cached synchronization:** src/vs/sessions/contrib/codeReview/browser/codeReviewService.ts starts an immediate refresh and periodic polling, while src/vs/sessions/contrib/github/browser/models/githubPullRequestReviewThreadsModel.ts defines a 60,000 ms polling interval. A comment added after the last refresh can therefore remain invisible to a tool invocation until the next poll.
