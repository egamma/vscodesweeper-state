# Issue #330984 — "View comments" tool doesn't reliably detect comments

[https://github.com/microsoft/vscode/issues/330984](https://github.com/microsoft/vscode/issues/330984)

## Summary

Team-authored bug report (roblourens) with no fix commit referencing this issue, so it stays open regardless; I traced the plausible root cause in current main and it matches the reporter's own hypothesis exactly.

## Change summary

The agent's PR-comments tool sometimes reports no comments even when unresolved review comments exist, because it reads stale state instead of forcing a fresh check.

## Best solution

Have the `listComments`/`viewUnreviewedComments` tool path trigger a forced refresh (`GitHubPullRequestReviewThreadsModel.refresh(true)`, surfaced through `CodeReviewService`) before reading PR review state, instead of relying on the 60s background poll.

## Evidence

- **60s poll, no on-demand refresh:** src/vs/sessions/contrib/github/browser/models/githubPullRequestReviewThreadsModel.ts sets DEFAULT_POLL_INTERVAL_MS = 60_000 and only refreshes via a RunOnceScheduler or after explicit actions like postReviewComment(); nothing in the tool-invocation path calls refresh(true).
- **seeder consumes cached observable:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackPRReviewSeeder.ts and src/vs/sessions/contrib/codeReview/browser/codeReviewService.ts mirror PR review comments into agent feedback purely from the reactive `reviewThreads` observable — populated only by the poll/initial refresh, with no forced re-fetch tied to a tool call.
- **no tool-triggered refresh found:** src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts (listComments/viewUnreviewedComments handlers) and src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackItemsBackend.ts contain no call to force a review-thread refresh before reporting comment state.
