# Issue #330984 — "View comments" tool doesn't reliably detect comments

[https://github.com/microsoft/vscode/issues/330984](https://github.com/microsoft/vscode/issues/330984)

## Summary

Real, source-confirmed staleness bug in the Agents window's PR review comment plumbing — reported by a team member, so it stays open for a fix regardless; author's own suspicion about caching matches what the code shows.

## Change summary

The agent-host `viewUnreviewedComments` tool (and the comments banner) sometimes reports no PR review comments even though the PR has them, only picking them up on a later check.

## Best solution

Give the PR review comment path (GitHubService.activeSessionPullRequestReviewThreadsObs -> CodeReviewService.getPRReviewState -> AgentFeedbackPRReviewSeederContribution -> the listComments/viewUnreviewedComments tools in agentFeedbackServerTools.ts) a way to force a fresh fetch of review threads when the tool is invoked, instead of relying purely on whatever background poll cadence backs the reactive model.

## Evidence

- **seeding relies on a reactive model:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackPRReviewSeeder.ts reads `ICodeReviewService.getPRReviewState`, which is only re-derived when `IGitHubService.activeSessionPullRequestReviewThreadsObs`'s underlying model changes — there is no explicit refresh triggered by the tool call itself.
- **review threads come from a polling model:** src/vs/sessions/contrib/github/browser/githubService.ts (around line 27, 205-226) documents 'the whole flow end-to-end (lookup -> fetch -> poll -> icon)' and derives `activeSessionPullRequestReviewThreadsObs` from `GitHubPullRequestReviewThreadsModelReferenceCollection`, i.e. background polling rather than an on-demand fetch.
- **tool consumes whatever state is currently cached:** src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts's `listCommentsToolName`/`viewUnreviewedCommentsToolName` handlers just read the agent-feedback annotations snapshot that the seeder produced; they never trigger a fetch themselves.
