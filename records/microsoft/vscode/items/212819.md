# Issue #212819 — Provide a command to reset the completed steps of a walkthrough

[https://github.com/microsoft/vscode/issues/212819](https://github.com/microsoft/vscode/issues/212819)

## Summary

Keep this accepted Backlog request open: existing commands support individual-step changes and a global reset, but not resetting a walkthrough by its ID. The request has 24 upvotes, and no verified canonical or completed implementation was found.

## Change summary

Expose an extension-callable command that resets the completed steps of one walkthrough without affecting other walkthroughs.

## Best solution

Provide a walkthrough-scoped reset contract in the getting-started contribution, preserving unrelated progress. Reuse the existing individual-step commands for the secondary task, and settle whether restarting a walkthrough also re-enables automatic completion events already consumed in the session.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStarted.contribution.ts`, `src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStartedService.ts`
- **Validation:** Exercise the command with two registered walkthroughs containing completed steps: resetting one must clear only its steps, update the visible walkthrough, and persist across reload without changing the other walkthrough's progress or metadata. Repeat a previously consumed onCommand completion event after reset and assert the agreed restart semantics, including when that event is shared with another walkthrough.
- **Behavior:**

  > An extension can reset the completed steps of a specific registered walkthrough using its fully qualified walkthrough ID. Other walkthroughs retain their progress and metadata, and the target's cleared completion state is reflected in the UI and persists across reload. Existing individual-step completion commands remain available. Acceptance must also establish whether previously consumed automatic completion events can complete reset steps again during the same session.
- **Trace:**

  > The global reset action in src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStartedService.ts accepts no target and also clears global metadata. WalkthroughsService.getWalkthrough resolves a category by ID, while deprogressStep removes a step's persisted completion and fires its progress event. src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStarted.contribution.ts already exposes welcome.markStepComplete and welcome.markStepIncomplete for individual fully qualified step IDs. Extension walkthrough IDs use publisher.extension#walkthroughId, without the extra dot shown in the issue's example. The unresolved contract is session restart behavior: progressByEvent deduplicates through sessionEvents, which deprogressStep leaves intact, and completion events may be shared across walkthroughs. Preserve the existing global reset and unrelated walkthrough state; the request is https://github.com/microsoft/vscode/issues/212819.
- **Open decisions:**
  - Should resetting a walkthrough only clear its completed-step state, or also allow automatic completion events already consumed in the current session to complete its steps again, while leaving other walkthroughs unaffected?
