# Issue #290918 — [GitHub Copilot Telemetry] Missing request events in Chat Panel with disabled models

[https://github.com/microsoft/vscode/issues/290918](https://github.com/microsoft/vscode/issues/290918)

## Summary

A real telemetry gap remains for panel-chat submissions that stop at model authorization: request/response events are emitted only after a model call starts, so declining enablement leaves experiments without an attempt outcome. The older umbrella issue explicitly spawned this focused report, so it should remain open rather than be folded back into that broader discussion.

## Change summary

Record telemetry when panel chat targets a disabled model and the user declines to enable it, including direct model selections and models resolved through Auto.

## Best solution

Define a pre-request attempt/outcome telemetry contract that records the selected and resolved model, whether Auto performed the routing, and authorization rejection without representing an unstarted network call as a successful request.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostLanguageModels.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTelemetry.ts`, `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts`, `extensions/copilot/src/extension/prompt/node/chatMLFetcherTelemetry.ts`
- **Validation:** Add a focused telemetry test that submits panel chat through a disabled directly selected model and an Auto-resolved disabled model, declines authorization, and asserts one attempt outcome with the expected model attribution while asserting that no network request/response success event is emitted.
- **Behavior:**

  > When a panel-chat submission targets a model requiring enablement and the user declines, telemetry records that the user attempted the submission and that authorization prevented the model call. The record distinguishes direct model selection from Auto routing and supplies enough model attribution to avoid experiment sample-ratio mismatches. No request or response success event should imply that a network call occurred.
- **Trace:**

  > The panel submission reaches `ChatWidget._acceptInput` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts and then the language-model API. In src/vs/workbench/api/common/extHostLanguageModels.ts, `_sendChatRequest` performs `_getAuthAccess` before `$tryStartChatRequest`; declining the dialog returns false and throws `NoPermissions`. Consequently, extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts never reaches its `request.sent` emission, and response telemetry in chatMLFetcherTelemetry.ts cannot run. The model picker now logs direct selections through `ModelPickerTelemetrySession.logModelChange`, but that does not describe submission, authorization outcome, or Auto's resolved model. Preserve the semantic distinction between an attempted submission and an actual provider request; do not emit successful request/response telemetry for work that never started. The broader context is https://github.com/microsoft/vscode/issues/287920, whose discussion deliberately split this panel-specific case into the present issue.
- **Open decisions:**
  - Should authorization rejection be represented by a dedicated pre-request attempt/outcome event, or by a terminal outcome in an expanded chat-submit telemetry contract?
  - For Auto routing, should model attribution record both the user-selected Auto model and the disabled resolved model, or only one of them?

## Evidence

- **authorization path:** src/vs/workbench/api/common/extHostLanguageModels.ts `_sendChatRequest` calls `_getAuthAccess` before `$tryStartChatRequest`; when the user declines, it throws `LanguageModelError.NoPermissions`, so no provider request starts.
- **request telemetry boundary:** extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts emits `request.sent` only after constructing the endpoint request and opening the transport path, which the authorization rejection never reaches.
- **partial existing telemetry:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts logs `chat.modelChange` when a model is selected, but this does not capture a later declined submission or an Auto-routed disabled model.
- **related issue:** https://github.com/microsoft/vscode/issues/287920 is an older umbrella for consistent Chat Submit telemetry, but its maintainer discussion requested separate focused reports; the author then created this panel-chat authorization case and linked it from https://github.com/microsoft/vscode/issues/287920#issuecomment-3806784924.
