# Issue #345918 — CLI argument to open the native Git diff view

[https://github.com/microsoft/vscode/issues/345918](https://github.com/microsoft/vscode/issues/345918)

## Summary

The native multi-file SCM diff exists, but the inspected CLI and Git URI entry points do not expose the requested automatic repository-review workflow. Keep this team-authored request open for a decision on the command-line contract; no verified canonical or fixing commit was found.

## Change summary

Allow an external command-line tool to open a repository's native multi-file Git diff for review and working-tree edits.

## Best solution

Provide a supported command-line entry point into the existing SCM multi-diff editor rather than introducing another review surface. Establish repository selection and change-group semantics before accepting an implementation.

- **Behavior:**

  > An external command-line tool should be able to open a repository directly in VS Code's native multi-file Git review experience without requiring manual Source Control navigation. Users must be able to review multiple changed files and edit their working-tree contents there. Acceptance should cover a fresh window and an already-open repository while preserving existing two-file --diff behavior.
- **Trace:**

  > OPTIONS in src/vs/platform/environment/node/argv.ts exposes only the two-file --diff contract for diff review. The desktop path passes args.diff through src/vs/code/electron-main/app.ts, and windowsMainService.ts converts two file inputs into filesToDiff before the renderer opens them in window.ts. OpenScmGroupAction in scmMultiDiffSourceResolver.ts already opens a native multi-diff using repositoryUri and resourceGroupId. git.openAllChanges opens individual files, and the Git URI handler supports cloning rather than review. The missing boundary is a supported external invocation contract and its handoff to an available SCM repository; preserve the existing review editor and ordinary file-opening semantics. The issue at https://github.com/microsoft/vscode/issues/345918 does not settle repository ambiguity or which change groups the invocation should display.
- **Open decisions:**
  - Should repository review use a dedicated CLI option or extend --diff, and how should the invocation select a repository in multi-root or multi-repository windows?
  - Should the initial review include unstaged changes only, or also staged and untracked changes, and how should those groups be presented?
