# Issue #175770 — Disassembly View: Add text field to go to specific instruction

[https://github.com/microsoft/vscode/issues/175770](https://github.com/microsoft/vscode/issues/175770)

## Summary

The navigation gap remains on current main, and a maintainer agreed that a Go to Line-style experience makes sense. This team-authored Backlog request should stay open for design and implementation.

## Change summary

Add a text-entry workflow for navigating directly to a specified instruction in the Disassembly view.

## Best solution

Provide a keyboard-accessible Go to Disassembly Address flow for the active Disassembly editor that loads, reveals, and focuses the requested instruction while reporting invalid or unavailable addresses clearly.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/disassemblyView.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorActions.ts`
- **Validation:** Run a debug session whose adapter supports the DAP `disassemble` request, open the Disassembly editor, enter valid loaded and unloaded addresses through the selected UI, and verify that each instruction is loaded, centered, and keyboard-focused; also verify that malformed and unavailable addresses produce accessible feedback without changing the current location.
- **Behavior:**

  > While a supported debug session is paused, users can enter an instruction address and navigate directly to it from the Disassembly editor. The target is loaded when outside the currently displayed range, then revealed and keyboard-focused. Invalid or unavailable input produces clear accessible feedback and leaves the current location unchanged. Existing scrolling, stack-frame navigation, and instruction-breakpoint behavior remain unchanged.
- **Trace:**

  > The current address path is concentrated in `DisassemblyView` at src/vs/workbench/contrib/debug/browser/disassemblyView.ts: disassembly responses are parsed into bigint addresses, `loadDisassembledInstructions` populates the table, `reloadDisassembly` loads around an instruction reference, and private `goToAddress` can reveal only an already-loaded address. No user-facing address command or input is registered in current main. The closed https://github.com/microsoft/vscode/pull/138125 explored a quick-access provider in debugEditorActions.ts, but it predates the current view implementation and was never merged. Keep the boundary within the core debug/disassembly surface; do not change DAP semantics, breakpoint behavior, or generic Go to Line behavior. The uncertainty starts at the entry UX and at whether the public input contract is limited to displayed numeric addresses or includes opaque DAP instruction references.
- **Open decisions:**
  - Should address entry be a persistent control in the Disassembly editor or an on-demand command/quick-access interaction?
  - Should the accepted input contract cover only numeric addresses displayed by the view, or also opaque DAP instruction references and symbols when an adapter supports them?

## Evidence

- **current source gap:** src/vs/workbench/contrib/debug/browser/disassemblyView.ts parses instruction addresses and has private reveal/loading primitives (`goToAddress`, `reloadDisassembly`, and `loadDisassembledInstructions`), but exposes no text input, command, or quick-access provider for an address supplied by the user.
- **abandoned implementation:** https://github.com/microsoft/vscode/pull/138125 proposed a Go to Disassembly Address quick-access command, but it was closed unmerged after its author confirmed that the branch was outdated and work would not continue.
- **maintainer intent:** The issue author is a repository member, and a maintainer explicitly agreed that an address-based experience similar to Go to Line probably makes sense.
- **related umbrella:** https://github.com/microsoft/vscode/issues/129762 is older and lists “GoTo Disassembly at a specific address,” but it is a broad milestone-tracking umbrella rather than a same-symptom canonical issue, so it does not satisfy the stronger duplicate bar for this re-review.
- **extension API boundary:** https://github.com/Open-CMSIS-Pack/vscode-cmsis-debugger/issues/317 independently requests “Show Disassembly at Address” and notes that extensions cannot currently extend the core Disassembly view to provide it.
