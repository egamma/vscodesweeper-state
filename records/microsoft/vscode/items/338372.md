# Issue #338372 — Agents window: allow a configurable or full-width conversation column

[https://github.com/microsoft/vscode/issues/338372](https://github.com/microsoft/vscode/issues/338372)

## Summary

Well-argued, detailed feature request for the dedicated Agents window's fixed-width conversation column; no existing setting or toggle covers a full-width mode for the primary (non-split) chat view, so this stays open as a genuine gap. Too fresh (0 days, 0 upvotes, no maintainer input) to weigh demand or commit to a specific design.

## Change summary

Allow the Agents window's centered conversation column to be widened or made full-width (globally or per content type) instead of the fixed ~950px max width.

## Best solution

Add a user-facing way (command/setting) to relax `AGENTS_CENTERED_CONTENT_MAX_WIDTH` for the primary chat view in src/vs/sessions/contrib/chat/browser/chatView.ts and src/vs/sessions/browser/parts/sessionView.ts, similar to how `setPrimary(primary, split)` already lifts the cap to `Number.POSITIVE_INFINITY` for split view — but as an explicit user choice for the non-split case, persisted per the maintainers' preference.

## Plan brief

- **Likely files:** `src/vs/sessions/common/layoutConstants.ts`, `src/vs/sessions/contrib/chat/browser/chatView.ts`, `src/vs/sessions/browser/parts/sessionView.ts`, `src/vs/sessions/browser/parts/customViewNode.ts`
- **Validation:** A sessions/chatView test asserting the conversation column's maximum width switches between the constrained default and full width when the new toggle/setting is applied, mirroring the existing split-mode width test in chatView.test.ts.
- **Behavior:**

  > In the dedicated Agents window, the primary (non-split) conversation column defaults to its current constrained centered width. A user can opt into a wider or full-width mode for the column (via a command, chat-layout control, and/or setting), and the choice is remembered across sessions. Prose is unaffected when the user has not opted in.
- **Trace:**

  > The centered-column cap is `AGENTS_CENTERED_CONTENT_MAX_WIDTH` (950px) in src/vs/sessions/common/layoutConstants.ts, applied via `ChatViewPane`/`chatView.ts`'s `setMaximumWidth` calls and `sessionView.ts`'s `CENTERED_CONTENT_MAX_WIDTH`. The only existing code path that lifts this cap is the split-view case in `setPrimary(primary, split)` (chatView.ts:859), which is orthogonal to this request (multi-pane layout, not a user preference for the single column). Do not change the split-view behavior; the new mechanism should apply only to the primary, non-split column.
- **Open decisions:**
  - Is the new mode a full-width toggle for the whole column, or does it only let wide block content (tables, code, diagrams) expand while prose stays constrained, as the reporter's alternative suggests?
  - Is the choice a command/toolbar toggle, a settings.json option (with a configurable max width), or both?
  - Is the preference persisted globally, per workspace, or per session/conversation?

## Evidence
