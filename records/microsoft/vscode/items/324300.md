# Issue #324300 — Bad UX when auto-save is on (all but "off")

[https://github.com/microsoft/vscode/issues/324300](https://github.com/microsoft/vscode/issues/324300)

## Summary

Legitimate UX issue: the auto-save timer in EditorAutoSave does not pause when a closeHandler confirmation dialog is active, and onFocusChange mode triggers a save before the dialog can appear. This affects editors with custom close handlers. Keeping open as a real, if niche, bug in the editor-input area.

## Change summary

Auto-save (afterDelay and onFocusChange modes) interferes with editor close confirmation dialogs — the timer doesn't pause during dialog display, and focus-change saves bypass confirmation entirely.

## Best solution

EditorAutoSave should be aware of pending close confirmations: pause scheduled saves when a closeHandler dialog is active (afterDelay case), and the close flow should save-then-confirm rather than letting onFocusChange silently save before the dialog appears. The fix likely touches `src/vs/workbench/browser/parts/editor/editorAutoSave.ts` and the close confirmation path in `src/vs/workbench/browser/parts/editor/editorGroupView.ts`.
