# Issue #324300 — Bad UX when auto-save is on (all but "off")

[https://github.com/microsoft/vscode/issues/324300](https://github.com/microsoft/vscode/issues/324300)

## Summary

Keep open: delayed auto-save remains active while the close confirmation awaits a choice, so saving can undermine the offered Don't Save action. The onFocusChange case is explicitly implemented behavior rather than merely an accidental blur; changing it needs an editor-owner decision.

## Change summary

Prevent auto-save from undermining close-confirmation choices and clarify whether closing an editor should offer a discard choice in focus-based auto-save modes.

## Best solution

Make close confirmation and delayed auto-save behave coherently in the editor-group and auto-save paths. Separately decide whether focus-based auto-save should retain its deliberate save-on-close behavior or provide a discard opportunity.
