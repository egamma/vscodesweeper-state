## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts`, `src/vs/editor/browser/controller/editContext/native/screenReaderSupport.ts`, `src/vs/editor/browser/controller/editContext/native/screenReaderContentSimple.ts`, `src/vs/editor/browser/controller/editContext/screenReaderUtils.ts`
- **Validation:** On macOS with VoiceOver and editor.editContext enabled, open a file of at least 100 distinguishable lines, press Cmd+Down, then navigate repeatedly with Up/Down and verify announcements match the caret's line. Repeat with an empty final line and Up Arrow from that line. Compare with editor.editContext disabled, and require the default path to work without focus resets; derive a targeted automated regression check once the failing synchronization is identified.
- **Behavior:**

  > VoiceOver must continue announcing the correct editor content after a jump to the end of a large file. Moving upward from an empty final line must announce the previous line reliably rather than an unrelated character. Both cases must work with the default input configuration, without opening another UI or disabling EditContext.
- **Trace:**

  > The issue thread confirms reproduction but does not establish a current-source root cause. In src/vs/editor/browser/view.ts, _instantiateEditContext chooses the native or textarea input path according to effectiveEditContext. NativeEditContext.onCursorStateChanged forwards selection changes to ScreenReaderSupport; its default SimpleScreenReaderContent uses SimplePagedScreenReaderStrategy, replaces DOM textContent, and updates the DOM selection. SimpleScreenReaderContent._getScreenReaderContentState contains special handling for an empty final line, but its relationship to the reported failure remains unproven. The newer matching report, https://github.com/microsoft/vscode/issues/294263, confirms that disabling editor.editContext helps and supplies a focus-reset workaround. Diagnose that boundary before assigning fault to Chromium or macOS; preserve ordinary editing, selection direction, and non-VoiceOver screen-reader behavior.
