# Issue #321274 — Staged Changes/Files don't allow "Go to Definition" [Working Tree Diff View]

[https://github.com/microsoft/vscode/issues/321274](https://github.com/microsoft/vscode/issues/321274)

## Summary

Staged-diff definition navigation remains unsupported in the current TypeScript implementation. Keep this open for language-service design: opening the working file is a workaround, not equivalent support within the staged snapshot.

## Change summary

Allow Ctrl+click and Go to Definition from staged-file diffs, as already available from working-tree diffs.

## Best solution

Support definition navigation from staged snapshots without changing their displayed content or interfering with working-tree language-service buffers. First settle whether navigation resolves against staged content or maps into the working-tree project when those versions differ.

- **Validation:** In a Git-initialized TypeScript workspace, stage a file importing a symbol from another file, open its staged diff, and invoke both Ctrl+click and Go to Definition. Repeat with additional unstaged edits shifting lines or changing the referenced symbol, and with both staged and working-file editors open. Verify the chosen navigation semantics, unchanged snapshot content, unaffected normal-editor navigation, and unchanged Git index; pin these cases in the TypeScript extension test harness.
- **Behavior:**

  > Users should be able to navigate to definitions while reviewing staged TypeScript changes, without unstaging or leaving the diff first. Ctrl+click and Go to Definition should agree. Acceptance must cover staged content that differs from the working tree, including shifted lines and changed symbols, while preserving normal-editor navigation and the Git index. C++ confirmation establishes a wider symptom, but does not establish that the same TypeScript-specific implementation can address other providers.
- **Trace:**

  > ResourceCommandResolver.getRightResource in extensions/git/src/repository.ts uses git-scheme index snapshots for staged files and working-file resources for unstaged modifications. TypeScript explicitly excludes git in configuration/fileSchemes.ts; TypeScriptServiceClient.toTsFilePath therefore returns undefined, BufferSyncSupport.openTextDocument refuses synchronization, and TypeScriptDefinitionProvider.provideDefinition exits without a result. Buffer maps and synchronization use toTsFilePath as their normalizer, so snapshot-to-working-file identity affects shared language-service state, not only the definition request. Preserve staged snapshot contents, ordinary working-file buffers, and existing handling of historical revisions; do not assume replacing the snapshot with the working file satisfies the request. https://github.com/microsoft/vscode/issues/324356 documents related reference-navigation behavior and a reporter's experimental path-unwrapping approach, but does not settle its correctness when versions differ. The uncertainty begins at which content and project context staged navigation should resolve against.
- **Open decisions:**
  - When staged and working-tree content differ, should definition navigation resolve the symbol from the staged snapshot, or navigate through a mapped position in the current working-tree project?

## Evidence

- **Reported scope and confirmation:** https://github.com/microsoft/vscode/issues/321274 reports definition navigation working in normal and unstaged TypeScript editors but failing after staging. The July 14 comment independently confirms the staged-versus-unstaged distinction for C++; that language's implementation was not inspected.
- **Staging changes the document scheme:** extensions/git/src/repository.ts: ResourceCommandResolver.getRightResource returns toGitUri(resource.resourceUri, '') for INDEX_MODIFIED and other staged states, but returns the working-file resource for MODIFIED. resolveChangeCommand opens those resources through vscode.diff. extensions/git/src/uri.ts: toGitUri constructs a git-scheme URI carrying path and ref.
- **Explicit TypeScript support boundary:** extensions/typescript-language-features/src/configuration/fileSchemes.ts explicitly includes git in disabledSchemes. TypeScriptServiceClient.toTsFilePath returns undefined for that scheme; BufferSyncSupport.openTextDocument consequently declines the buffer. TypeScriptDefinitionProvider.provideDefinition returns undefined when toOpenTsFilePath fails. This is an explicitly excluded resource type, so the requested expansion is classified as a feature request rather than an accidental failure of supported navigation.
- **Existing capability is only a workaround:** extensions/git/package.json registers git.openFile for staged SCM resources and git-scheme diff editors. extensions/git/src/commands.ts: Commands.openFile converts a git URI to Uri.file(fromGitUri(arg).path), allowing navigation in the working file without unstaging. It leaves the staged snapshot, however, and can expose different content; no configuration enabling staged TypeScript navigation was found.

Its requested behavior is references rather than definition navigation, and it does not own this report's broader language scope. Searches for staged definition navigation, diff definition navigation, and Git language-feature support found no verified canonical covering the full request.
