# Issue #208482 — Allow icons in menus

[https://github.com/microsoft/vscode/issues/208482](https://github.com/microsoft/vscode/issues/208482)

## Summary

This remains a well-supported feature request with 40 upvotes and a confirmed gap on current main. No older open issue owns the same request; the younger issue and its open implementation PR should be consolidated around this issue rather than making this re-reviewed item a duplicate.

## Change summary

Allow context-menu actions to display their existing command icons alongside the required text labels.

## Best solution

Keep this as the canonical design discussion, consolidate https://github.com/microsoft/vscode/issues/304904 into it, and evaluate https://github.com/microsoft/vscode/pull/304906 after deciding whether icons are opt-in or default and how partially populated menus avoid visual noise.

## Vision fit

- **Fit:** aligned
- **Reason:** Paired icons and labels can improve recognition in a heavily used workbench surface while preserving readable text and accessibility, although the design must remain calm and uniform.
- **Evidence:** Durable themes: “Workbench & core UX” and “Accessibility”; the simple, uniform UI guardrail supports resolving icon consistency and visual-noise concerns before landing.

## Evidence

- **current source gap:** On current main, src/vs/platform/actions/common/actions.ts derives MenuItemAction.class from an ICommandAction ThemeIcon, but src/vs/base/browser/ui/menu/menu.ts constructs IMenuItemOptions without forwarding that icon state and renders only the check indicator and text label. The existing command icon therefore is not displayed beside context-menu text.
- **active implementation:** https://github.com/microsoft/vscode/pull/304906 is open and changes src/vs/base/browser/ui/menu/menu.ts to forward action icon state and render a separate decorative menu-item icon. It fixes the younger https://github.com/microsoft/vscode/issues/304904 and is currently blocked rather than merged.
