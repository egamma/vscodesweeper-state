# Issue #264140 — The "save as" popup dialog's behavior does not align with the primary side bar's Folders

[https://github.com/microsoft/vscode/issues/264140](https://github.com/microsoft/vscode/issues/264140)

## Summary

Keep open: the simple Save As dialog still uses a different filename comparator from Explorer, so the requested ordering consistency remains missing. The additional case-sensitive overwrite report has concrete retest steps but is not conclusively explained by this source inspection.

## Change summary

Make the remote Save As dialog consistent with Explorer ordering and avoid misleading overwrite confirmation for distinct case-sensitive filenames.

## Best solution

Use consistent natural filename ordering across Explorer and the simple file dialog, with an explicit decision about whether Explorer's optional sorting preferences also apply. Separately verify that saving A.py beside a.py on a case-sensitive remote filesystem prompts only when the actual destination exists.
