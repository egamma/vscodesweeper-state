# Issue #262343 — Cleanup usage of createModel in chat

[https://github.com/microsoft/vscode/issues/262343](https://github.com/microsoft/vscode/issues/262343)

## Summary

The cleanup remains necessary on current main: chat code blocks still call `IModelService.createModel` directly and then acquire a resolver reference, while the registered content provider only returns an already-created model. This is distinct from the observable edited-command state loss still tracked by https://github.com/microsoft/vscode/issues/259088.

## Change summary

Move chat code-block and confirmation model creation under the text-model resolver lifecycle while retaining the correct simple-widget model option.

## Best solution

Have the chat code-block content provider create models requested through `createModelReference`, carrying enough URI metadata to preserve `isForSimpleWidget`, and let the resulting reference own the model lifetime. Preserve ordinary code-block, confirmation-editor, and pooled-render behavior.
