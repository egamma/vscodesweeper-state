# Issue #191453 — Unlucky Diff - Semantic Diffing?

[https://github.com/microsoft/vscode/issues/191453](https://github.com/microsoft/vscode/issues/191453)

## Summary

Keep open: the default diff algorithm still scores matching lines without parent-symbol context, so the requested semantic alignment remains missing. The related merge-editor issue concerns a different comparison strategy and does not establish a duplicate.

## Change summary

Improve ambiguous line alignment by preferring matches within corresponding parent symbols.

## Best solution

Evaluate symbol-aware alignment in the diff computation pipeline against the supplied Monaco example, preserving fast text-only behavior when symbol information is unavailable. Establish matching semantics and performance limits before implementation.

- **Behavior:**

  > Repeated text in different functions or classes can produce confusing line matches. The goal is to prefer matches within corresponding parent symbols where that makes the comparison reflect the actual edits. Acceptance should include the supplied Monaco example and repeated identical lines in separate symbols. Texts without symbol providers must retain useful comparisons, and obtaining symbol information must not make editing unresponsive.
- **Trace:**

  > DefaultLinesDiffComputer.computeDiff in src/vs/editor/common/diff/defaultLinesDiffComputer/defaultLinesDiffComputer.ts scores line matches using text equality and length below a combined 1700-line threshold, then switches to Myers for larger inputs. OutlineModel.create and OutlineModelService.getOrCreate in src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts asynchronously obtain provider-specific hierarchical symbols; WorkerBasedDocumentDiffProvider.computeDiff currently delegates directly to the editor worker. - **Open decisions:**
