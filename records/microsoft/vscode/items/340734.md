# Issue #340734 — macOS: non-recursive file watcher refuses every path under /Volumes/ by prefix, breaking extension watchers on local internal APFS volumes

[https://github.com/microsoft/vscode/issues/340734](https://github.com/microsoft/vscode/issues/340734)

## Summary

Keep open: current source still rejects non-recursive watches on local macOS volumes solely because their real paths start with /Volumes/. The network-share crash issue explains the safeguard but does not resolve this distinct local-volume failure.

## Change summary

Restore non-recursive file watching on local macOS volumes mounted under /Volumes/ without reintroducing unsafe network-share watching.

## Best solution

Local internal and external volumes should support non-recursive watch events while retaining protection against the documented network-filesystem crash. Establish a reliable locality check or safe watcher alternative in the platform file-watching layer before changing the guard.
