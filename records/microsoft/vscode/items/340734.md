# Issue #340734 — macOS: non-recursive file watcher refuses every path under /Volumes/ by prefix, breaking extension watchers on local internal APFS volumes

[https://github.com/microsoft/vscode/issues/340734](https://github.com/microsoft/vscode/issues/340734)

## Summary

Thanks for the detailed report. The /Volumes/ prefix check is still on main and refuses every non-recursive directory watch there, including on local internal APFS volumes. It is a deliberate mitigation for the network-share crash in #106879, so a maintainer needs to decide how to refine it. Not a close.

## Change summary

On macOS, the non-recursive file watcher refuses all paths under /Volumes/, so extension watchers on local internal volumes get no events.

## Best solution

Replace the path-prefix heuristic in nodejsWatcherLib.ts with a real locality check (for example statfs MNT_LOCAL or filesystem type), cached per mount point. Keep refusing network filesystems so the #106879 crash mitigation stays intact.

## Plan brief

- **Likely files:** `src/vs/platform/files/node/watcher/nodejs/nodejsWatcherLib.ts`
- **Validation:** A unit test, or a manual check on macOS: a non-recursive watch on a local APFS /Volumes path delivers events, while an SMB/NFS mount is still refused.
- **Behavior:**

  > A non-recursive directory watch on a local APFS or HFS volume mounted under /Volumes/ should work and deliver events. Network mounts (smbfs, nfs, afpfs, webdav) must still be refused to avoid the crash tracked in #106879.
- **Trace:**

  > The prefix check in NodeJSFileWatcherLibrary.doWatchWithNodeJS in nodejsWatcherLib.ts is the only gate. It runs on the realpath, and directory watches never reuse a recursive watcher (doWatchWithExistingWatcher returns false for directories). Boundary: do not weaken protection for network shares or touch the recursive (parcel) watcher. Related: https://github.com/microsoft/vscode/issues/106879 and https://github.com/microsoft/vscode/issues/231332. Uncertainty: Node has no built-in statfs flag for locality, so a native module or child-process probe may be needed.
- **Open decisions:**
  - How should locality be detected on macOS: native statfs, a child-process probe, or a user setting that allow-lists volumes?
  - Should a non-recursive directory watch inside an already-watched workspace folder be served by the existing recursive watcher instead?
