# Issue #253683 — Support agent mode in the terminal

[https://github.com/microsoft/vscode/issues/253683](https://github.com/microsoft/vscode/issues/253683)

## Summary

Keep this as the canonical request for a terminal-native agent experience. Current main has inline terminal chat and an experimental Agent Host backend, but neither establishes the requested unified shell/agent input behavior; a maintainer has already consolidated related demand here.

## Change summary

Integrate Copilot agent interaction with terminal input so users can move between shell commands and agent requests without leaving the terminal.

## Best solution

Define a terminal-native interaction contract that combines normal shell use and agent work while retaining access to editor changes. Evaluate the existing experimental terminal Agent Host path first, then decide how users select shell versus agent input and whether automatic switching is appropriate.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatWidget.ts`, `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatController.ts`, `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatActions.ts`, `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatSessionResolver.ts`
- **Validation:** After agreeing on the input contract, manually exercise alternating a normal shell command, an agent request requiring terminal work and an editor change, and another shell command without navigating to the chat view. Confirm each input reaches the intended recipient, terminal focus and interactive shell input remain usable, and ordinary Ctrl/Cmd+I command assistance still works.
- **Behavior:**

  > The reporter wants normal shell commands and Copilot agent requests available within one terminal-centered workflow, rather than moving to the chat view for agent work. Success means alternating shell use and agent interaction without leaving that surface, while code changes remain accessible in the editor. Acceptance must demonstrate that command text is never accidentally sent to the agent and agent-request text is never accidentally executed by the shell. The precise switching behavior needs a maintainer decision before implementation.
- **Trace:**

  > TerminalChatWidget currently embeds a separate InlineChatWidget with ChatMode.Ask; terminalChatActions.ts exposes explicit opening, command insertion, and command execution. TerminalChatSessionResolver.resolve can select an experimental Agent Host Copilot backend via chat.terminal.agentHost.enabled, and TerminalChatWidget._createSession locks requests to that session contribution. This establishes a backend starting point but does not establish a merged shell/agent input contract. The related request at https://github.com/microsoft/vscode/issues/260361 was consolidated into https://github.com/microsoft/vscode/issues/253683 by Tyriar. Preserve existing ordinary shell input and command-assistance behavior; do not interpret backend replacement alone as fulfillment of the requested UX. Planning should first evaluate the experimental path interactively, then settle the user-visible switching contract.
- **Open decisions:**
  - Should shell and agent input use a shared input surface or remain distinct inputs within the terminal?
  - Should switching be explicit, inferred automatically from input, or a combination with explicit override, and how must the active recipient be communicated before submission?
