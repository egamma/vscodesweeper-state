## Plan brief

- **Likely files:** `src/vs/workbench/api/browser/mainThreadEditor.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** Add an extension-host/profile lifecycle test that sets an editor cursor style through the extension API, stops or restarts that extension host, and asserts the cursor returns to the configured/default style while an explicit user cursor setting remains intact.
- **Behavior:**

  > An extension may temporarily change an editor's cursor style while its extension host is active. After switching to a profile where that extension is disabled and its host has stopped, the editor must return to the cursor style selected by the active profile or to the normal default. The behavior must also hold for already-open editors, and an explicit user cursor-style setting must not be overwritten.
- **Trace:**

  > The issue's confirmed path starts when Vim sets the editor cursor style to block through the extension API; profile switching then disables Vim and restarts the extension host, but the main-thread editor retains that override. The editor owner explicitly states at https://github.com/microsoft/vscode/issues/191855#issuecomment-1700467090 that no code restores the default when the extension host goes down. Investigation should trace the editor-option update path through src/vs/workbench/api/browser/mainThreadEditor.ts and the editor option definitions in src/vs/editor/common/config/editorOptions.ts, then identify the extension-host disconnect/profile-switch cleanup boundary. Do not globally reset cursor style or erase active-profile/user configuration; only stale extension-owned state should be removed.
- **Open decisions:**
  - Should editor-option overrides be associated with an extension host and rolled back generically on disconnect, or should cursor style receive targeted lifecycle cleanup?
  - What value should restoration use when the active profile has an explicit cursor-style setting versus no setting?
  - Should cleanup cover all editors affected by the stopped extension host, including editors that remain open across the profile switch?
