# Issue #191855 — Block cursor remains after switching to profile with enabled vim extension and back

[https://github.com/microsoft/vscode/issues/191855](https://github.com/microsoft/vscode/issues/191855)

## Summary

Still reproduces on main: when an extension sets cursorStyle via the API and the extension host restarts (profile switch), nothing resets it to the user's configured default. The dispose path in mainThreadEditors cleans up listeners and decorations but not extension-set editor options.

## Change summary

Block cursor set by the Vim extension persists after switching to a profile where Vim is disabled, because extension-set editor options are not reverted on extension host restart.

## Best solution

Track editor options that extensions override via the API (cursorStyle, lineNumbers, etc.) and restore the user-configured defaults when the extension host stops or restarts. The fix likely belongs in `src/vs/workbench/api/browser/mainThreadEditor.ts` (MainThreadTextEditor.setConfiguration) and `src/vs/workbench/api/browser/mainThreadEditors.ts` (dispose path).
