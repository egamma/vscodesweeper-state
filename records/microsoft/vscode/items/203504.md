# Issue #203504 — Refactor Indent Detection to set `indentSize` to `auto` rather than `tabSize`

[https://github.com/microsoft/vscode/issues/203504](https://github.com/microsoft/vscode/issues/203504)

## Summary

Keep open: indentation detection still couples indentation width to tab display width, with explicit TODOs acknowledging the unfinished separation. The older empty-file report covers only one consequence, not this request's full scope.

## Change summary

Finish separating detected indentation width from tab display width so space indentation can be detected without overriding independently configured tab stops.

## Best solution

Complete the separation across model creation, explicit detection, and configuration updates, preserving independently configured tab display width. Establish compatible configuration semantics before changing the existing detection behavior.

Assert the agreed independent-width behavior and retain coverage for indentSize: 'tabSize'; run the targeted TextModel and model-service suites through scripts/test.sh.
- **Behavior:**

  > Users who indent with spaces should be able to detect the file's indentation width without losing their independently configured tab display width. The behavior must be consistent when opening a file, invoking Detect Indentation from Content, and updating configuration. Acceptance checks should include a space-indented document containing literal tabs, an empty document, and existing configurations where indentation width follows tabSize. The compatibility behavior for existing detection settings must be agreed before implementation.
- **Trace:**

  > TextModel.resolveOptions in src/vs/editor/common/model/textModel.ts applies the guessed width to tabSize and sets indentSize to 'tabSize'; TextModel.detectIndentation instead writes the same guessed number to both fields. Both carry explicit TODOs about independent indent-size detection. guessIndentation in src/vs/editor/common/model/indentationGuesser.ts exposes only tabSize and insertSpaces, while ModelService._setModelOptionsForModel passes no independent indentation fallback to detection. The schema currently accepts a numeric indentSize or 'tabSize', with no 'auto' mode. Disabling detection supports independent configured widths but does not deliver automatic indentation detection. Preserve the existing distinction between indentation and literal-tab rendering, and do not broaden this work to unrelated comment or formatting behavior. https://github.com/microsoft/vscode/issues/187944 supplies the related empty-file case but is not a full-scope duplicate.
- **Open decisions:**
  - Should existing editor.detectIndentation configurations change to preserve configured tab display width, or should independent detection require a new opt-in mode such as editor.indentSize: 'auto' while retaining legacy behavior for existing configurations?
