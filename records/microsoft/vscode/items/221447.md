# Issue #221447 — Multi Diff Editor: Adopt Custom Hover

[https://github.com/microsoft/vscode/issues/221447](https://github.com/microsoft/vscode/issues/221447)

## Summary

Still open on main: the hidden-unchanged-regions widget used by the (multi) diff editor still sets native `title` attributes for all four labels called out in the report, so the custom-hover adoption is incomplete; team-authored and parked in Backlog, so it stays open.

## Change summary

Replace the remaining native `title` hovers in the diff editor's hidden-unchanged-regions controls with VS Code's custom hover service.

## Best solution

Adopt `IHoverService` (already injected in `CollapsedCodeOverlayWidget`) for the four remaining native `title` hovers in `src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts`, matching the `setupDelayedHover` pattern already used for the compact disclosure toggle.

## Plan brief

- **Likely files:** `src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts`
- **Validation:** Manual: open a diff with collapsed unchanged regions and confirm each of the four controls shows a themed VS Code hover (no native tooltip), plus `npm run eslint -- src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts`.
- **Behavior:**

  > Hovering the 'Click or drag to show more above'/'below' strips, the 'Show Unchanged Region' control, and the '{n} hidden lines' label in a diff editor's collapsed unchanged region shows VS Code's themed custom hover instead of the OS native tooltip. Labels, timing behavior, and all click/double-click/drag interactions stay exactly as today, and no hover appears while a strip is being dragged. Acceptance: no `title:` attributes remain in the widget's DOM construction, and the collapsed-region controls behave identically otherwise.
- **Trace:**

  > `CollapsedCodeOverlayWidget` in src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts builds its DOM via `h(...)`/`$(...)` with native `title` options at lines 314, 320, 325 and inside the label autorun at line 503. The widget already takes `@IHoverService` (line 339) and uses `setupDelayedHover` for the compact toggle, so the dependency and pattern exist. The span at line 503 is recreated on every autorun pass, so any hover registered for it belongs to `reader.store`, not the widget's store. Boundary: do not change label text, the drag/mousedown handlers on `top`/`bottom`, the compact-control code path, or the existing toggle hover.
- **Open decisions:**
  - Should the drag affordance strips ('Click or drag to show more above/below') show a hover at all, or only the actionable controls — a custom hover is more prominent than a native tooltip and may be distracting on a drag target?
  - Should the hovers use the delayed hover delegate (matching the existing toggle) or the standard element hover, i.e. is a visible delay the intended behavior for these controls?
