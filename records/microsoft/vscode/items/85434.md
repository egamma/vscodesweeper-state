# Issue #85434 — Git - Explorer .gitignore integration considers git repo outside of workspace folder

[https://github.com/microsoft/vscode/issues/85434](https://github.com/microsoft/vscode/issues/85434)

## Summary

Keep open pending a current-build retest of the supplied nested-repository scenario. Repository selection and parent-repository handling now appear to prevent the reported fading, but the original steps suffice to retest and no verified fix for that exact outcome was established.

## Change summary

Files in a repository opened from inside another repository's ignored node_modules directory appear faded by the outer repository's ignore rules.

## Best solution

Files in the opened inner repository should receive ignore decorations from that repository, not an ancestor outside the workspace. Retest the original xterm-under-node_modules layout before deciding whether the existing repository-selection behavior resolves this report or a decoration defect remains.

Maintainers discussed conflicting repository ignore results, but the reporter's final comment says a smaller nested-repository example did not reproduce. This does not invalidate the original layout or establish its root cause.
- **Current ignore-decoration path:** extensions/git/src/decorationProvider.ts: GitIgnoreDecorationProvider.provideFileDecoration selects one repository through Model.getRepository(uri), then batches checkIgnore calls for that repository. It does not independently combine ignore results from every ancestor repository.
- **Current repository selection:** extensions/git/src/model.ts:929-1000: getRepository delegates to getOpenRepository, which sorts open repositories by descending root-path length before selecting a containing repository. An opened inner repository therefore takes precedence over an opened outer repository.
- **Parent-repository handling changed:** https://github.com/microsoft/vscode/commit/78f9b0610109078cfa962d6c578fa0a1cbe5400d added an early return in Model.openRepository for repositories outside the workspace unless parent opening is enabled or previously approved. Current extensions/git/src/model.ts:631-649 retains that boundary, and extensions/git/package.json registers git.openRepositoryInParentFolders with default prompt. This addresses ancestor discovery, but does not conclusively establish the cause or fix of the original inner-repository decoration report.

It mixes discovery of ignored nested repositories with fading when opening a plain folder below an external repository; https://github.com/microsoft/vscode/issues/41565#issuecomment-1349947643 explicitly distinguishes these cases and says its fading does not occur when opening a repository root. That distinction prevents treating it as a verified canonical for this report, which explicitly opens an inner repository.
