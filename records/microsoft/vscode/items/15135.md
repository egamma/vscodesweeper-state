# Issue #15135 — Remember undo history on hot-exit

[https://github.com/microsoft/vscode/issues/15135](https://github.com/microsoft/vscode/issues/15135)

## Summary

Keep open: current hot-exit backups preserve editor contents, but not undo/redo history across restarts. This team-authored, accepted request has 41 upvotes; existing settings and related issues do not establish a fix or a qualifying canonical duplicate.

## Change summary

Preserve undo/redo history when editors are restored after hot exit or a crash.

## Best solution

Restore usable undo/redo history alongside hot-exit editor contents, coordinated with the editor serialization work tracked at https://github.com/microsoft/vscode/issues/7536. Design the persistence and recovery contract before implementation, preserving existing backup reliability and editor performance.

## Plan brief

- **Likely files:** `src/vs/editor/common/services/modelService.ts`, `src/vs/workbench/services/textfile/common/textFileEditorModel.ts`, `src/vs/workbench/services/untitled/common/untitledTextEditorModel.ts`
- **Validation:** Acceptance check: make several distinguishable edits in a saved file and an untitled editor, undo one edit to leave both undo and redo history, hot-exit, and relaunch into a fresh process. Verify restored contents and successive Undo/Redo results match the pre-exit history. Repeat crash recovery after a backup has completed, and verify existing content-only backups remain recoverable.
- **Behavior:**

  > Editors restored after hot exit should retain the editing history associated with their recovered contents, so Undo and Redo remain useful across the restart. Cover saved-file and untitled text editors, including a history with both undoable and redoable edits. Crash recovery should preserve history consistent with the recovered backup. Existing recovery of unsaved contents must remain reliable.
- **Trace:**

  > ModelService in src/vs/editor/common/services/modelService.ts retains disposed model information and undo-redo elements in memory, with content checks and memory limits; files.restoreUndoStack reconnects that state when files reopen in the same session. TextFileEditorModel.backup and doResolveFromBackup in src/vs/workbench/services/textfile/common/textFileEditorModel.ts persist and restore text plus file metadata, with no edit-stack payload. UntitledTextEditorModel.backup in src/vs/workbench/services/untitled/common/untitledTextEditorModel.ts similarly persists text only. https://github.com/microsoft/vscode/issues/7536 tracks the serialization prerequisite, not an implemented hot-exit integration. The trace establishes the missing integration but not a complete persistence contract for editor histories across a fresh process. Preserve current same-session restoration, content-only backup compatibility, and content recovery reliability; terminal lifecycle behavior and Local History snapshot commands are outside this request.
- **Open decisions:**
  - Should the initial persistence contract cover only text editors recovered from hot-exit backups, or all restored editor histories as suggested in the discussion?
  - What history retention limits are acceptable across sessions, and should they differ from current same-session memory limits?
