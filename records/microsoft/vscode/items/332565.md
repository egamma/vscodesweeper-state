# Issue #332565 — Worker bootstrap blob URLs are never revoked (13 GB of blob_storage on my machine)

[https://github.com/microsoft/vscode/issues/332565](https://github.com/microsoft/vscode/issues/332565)

## Summary

Confirmed on current main: `getWorkerBootstrapUrl` in webWorkerServiceImpl.ts creates a blob URL for every worker and it is never revoked anywhere in `_createWorker`, `whenESMWorkerReady`, or `WebWorker`'s dispose — a genuine, well-diagnosed memory leak affecting every web worker created through this shared service.

## Change summary

Blob URLs created for web worker bootstrap scripts are never revoked, permanently retaining ~1MB+ per worker (observed as 13GB of accumulated blob_storage).

## Best solution

In src/vs/platform/webWorker/browser/webWorkerServiceImpl.ts, capture the blob URL returned by getWorkerBootstrapUrl in `_createWorker` and revoke it once whenESMWorkerReady resolves (or the worker errors/is disposed before ready) — mirroring the existing revoke pattern in src/vs/workbench/services/timer/browser/timerService.ts (createBlobWorker + URL.revokeObjectURL in a .finally).
