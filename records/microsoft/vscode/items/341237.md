## Evidence

- **Current source confirms object-store leakage:** src/vs/platform/agentHost/node/agentHostGitService.ts:683-715 routes repositories containing untracked files through _runWithTempIndex. At lines 752-780, that method overrides GIT_INDEX_FILE but neither GIT_OBJECT_DIRECTORY nor GIT_ALTERNATE_OBJECT_DIRECTORIES; its finally block removes only agent-host-git-diff-<uuid>. Consequently, objects created by staging are not confined to the directory it cleans up.
- **Large-file interruption path remains:** src/vs/platform/agentHost/node/agentHostGitService.ts:822-837 stages changed paths with git add -A --pathspec-from-file and supplies no timeout override. _runGit defaults to 5000 ms at line 1371 and invokes killTree on timeout at lines 1416-1423. This matches the reporter's trigger: repeated staging of a large untracked file can interrupt object creation in the repository store. Exact compression time and disk-growth rate were not executed or measured during this read-only review.
- **Independent corroboration:** The supplied discussion on https://github.com/microsoft/vscode/issues/341237 includes jamesgyoung's 2026-10-19 report of approximately 80 GB across more than 900 .git/objects/pack/tmp_pack_* files with a greater-than-500 MB untracked Parquet file on macOS arm64. They observed the same agent-host-git-diff staging command and reported that suspending VS Code and its Git child stopped growth. The pack-file variant should remain part of the investigation rather than being assumed identical in every detail.
- **Existing implementation candidate:** The supplied timeline identifies https://github.com/microsoft/vscode/pull/341238 as open and directly referencing this issue, titled "agentHost: keep temp-index diff blobs out of the repository object store". The reporter describes object-directory isolation and an integration test there. Current checkout source still lacks that isolation; the PR is a candidate fix, not evidence of completion.
