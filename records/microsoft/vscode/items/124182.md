# Issue #124182 — Workspace Trust - Extension Development Host 

[https://github.com/microsoft/vscode/issues/124182](https://github.com/microsoft/vscode/issues/124182)

## Summary

Keep open for investigation of extension activation after switching to a trusted folder in the Extension Development Host. Current source intentionally exempts development extensions from enablement filtering, but that explains only the first symptom; this team-authored issue has no verified fixing commit or eligible canonical duplicate.

## Change summary

Extensions reportedly fail to activate after an Extension Development Host switches from an untrusted folder to a trusted folder, until debugging is restarted.

## Best solution

Establish whether the folder-switch activation failure still occurs, separating it from the intentional development-extension enablement exemption. Extensions should activate normally in the newly trusted workspace without requiring the developer to restart debugging.
