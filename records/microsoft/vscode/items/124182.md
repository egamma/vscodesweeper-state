# Issue #124182 — Workspace Trust - Extension Development Host 

[https://github.com/microsoft/vscode/issues/124182](https://github.com/microsoft/vscode/issues/124182)

## Summary

The first reported behavior (dev extension activating in untrusted workspace) is explicitly by design in current code — `filterEnabledExtensions` never disables extensions with `isUnderDevelopment: true`. The second behavior (extension not reactivating after trust change during a session) may be a real lifecycle bug but is hard to verify without running the scenario. Team-authored item, keeping open for the author's judgment.

## Change summary

Extension Development Host does not respect workspace trust for extensions under development, and trust state changes mid-session may not properly reactivate extensions.

## Best solution

Clarify whether bypassing trust for development extensions is the desired behavior and document it. If the intent is to allow testing trust behavior during development, `filterEnabledExtensions` in `src/vs/workbench/services/extensions/common/abstractExtensionService.ts` (line 1452) would need to conditionally respect trust for dev extensions. The trust-state-change reactivation issue may have been addressed by subsequent lifecycle improvements.
