# Issue #328295 — Detached Agents window does not expose MCP servers from Remote (WSL) extension host

[https://github.com/microsoft/vscode/issues/328295](https://github.com/microsoft/vscode/issues/328295)

## Summary

Real gap, not a duplicate of an existing report: opening the detached Agents window drops the current window's remote context, so MCP servers running in the Remote-WSL extension host aren't available there — this needs area-team attention rather than a close.

## Change summary

MCP servers running in a Remote-WSL extension host are visible to Copilot Chat in the WSL window but not in the detached Agents window opened via 'Open in Agents'.

## Best solution

Thread the originating window's remote authority (not just local `file://` folders) through `openAgentsWindow`/`ensureAgentsWindow` so the spawned Agents window's agent host attaches to the same remote extension host and its MCP servers, rather than only a local workspace folder.

## Evidence

- **remote context dropped on open:** src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts:51 — `openCurrentWorkspaceInAgentsWindow` only forwards `folderUri` when `folderUri?.scheme === Schemas.file`, discarding remote (e.g. `vscode-remote://wsl+...`) folder URIs before calling `nativeHostService.openAgentsWindow`.
- **agents window opens as new local browser window:** src/vs/platform/windows/electron-main/windowsMainService.ts:295-311 — `openAgentsWindow` opens a fresh window against `environmentMainService.agentSessionsWorkspace` (a local workspace file) and only sends the folder/session URIs over IPC after the window is created; there is no remote-authority/extension-host reattachment in this path, consistent with the reported loss of the WSL extension host's MCP servers.
- **related but distinct open reports:** Several other open issues cover different symptoms of incomplete remote support in the Agents window (model picker gaps: https://github.com/microsoft/vscode/issues/324396; black screen on WSL open: https://github.com/microsoft/vscode/issues/321561; duplicate remote agent host installs over SSH: https://github.com/microsoft/vscode/issues/328613; Dev Containers support request: https://github.com/microsoft/vscode/issues/317380) — none of these owns this specific MCP-tools-missing report, so this is not a clean duplicate of any of them.
