# Issue #332249 — Agents Window: Asked to trust internal folder

[https://github.com/microsoft/vscode/issues/332249](https://github.com/microsoft/vscode/issues/332249)

## Summary

Team-authored regression (author and multiple MEMBER commenters), already carries a real release milestone (1.135.0) — both are hard keep-open conditions. Verified in source that the trust-folder resolution regression from #331895 is unfixed on current main.

## Change summary

After a recent update, opening/restoring a workspace-less quick chat (or a worktree session in an already-trusted folder) triggers an unnecessary workspace-trust prompt for its private `~/.copilot/chats/<sessionId>` scratch directory.

## Best solution

In `AgentHostSessionHandler._resolveSessionTrustFolders`/`_existingSessionWorkingDirectories` (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts), consult `readSessionWorkspaceless(meta)` (src/vs/platform/agentHost/common/state/sessionState.ts) on the persisted session state before treating `workingDirectories` as trust-gated folders — a workspace-less session's scratch cwd should short-circuit to an empty trust-folder set regardless of what `workingDirectories` reports.
