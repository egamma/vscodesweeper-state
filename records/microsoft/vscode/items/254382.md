# Issue #254382 — The column number calculation in the status bar has issues when meeting the full-width characters and emoji characters

[https://github.com/microsoft/vscode/issues/254382](https://github.com/microsoft/vscode/issues/254382)

## Summary

The reported counting behavior remains present, but current tests explicitly require it: the status bar counts Unicode code points with tab expansion, not display-cell widths. Keep this open for an editor-core decision about changing that established contract; no verified canonical issue was found.

## Change summary

Make the status-bar column advance by two for full-width CJK characters and emoji rather than counting each code point as one.

## Best solution

Have the editor-core owner decide whether the status-bar column should represent code-point position or approximate display-cell position. Treat the requested width-aware counting as a behavior change, preserving the distinction from model offsets and accounting for existing CJK, emoji, and tab expectations.
