# Issue #254382 — The column number calculation in the status bar has issues when meeting the full-width characters and emoji characters

[https://github.com/microsoft/vscode/issues/254382](https://github.com/microsoft/vscode/issues/254382)

## Summary

The reported counting behavior remains on main, but explicit tests establish it as the current status-bar contract rather than an accidental failure of full-width detection. Keep this open as a request to change that contract; the verified related issues do not qualify as duplicate canonicals for this re-reviewed report.

## Change summary

Make the status-bar column advance by two for full-width CJK characters and emoji rather than counting each Unicode code point once.

## Best solution

Have the editor owner decide whether status-bar columns should represent approximate display width instead of the existing tab-expanded code-point count. Any approved change should define its relationship to Go to Line/Column and preserve model-position semantics rather than changing shared cursor calculations indiscriminately.

  > Thanks for the detailed investigation. The status bar currently uses `CursorColumns.toStatusbarColumn()`, which expands tabs but counts other Unicode code points once; the full-width-aware function you linked is used for a separate visible-column calculation. Existing tests explicitly cover this counting behavior for CJK characters and emoji, so displaying their approximate width would be a change to the current column semantics. Keeping this open for an editor-owner decision, with related discussion in https://github.com/microsoft/vscode/issues/259270.
