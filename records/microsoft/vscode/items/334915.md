## Summary

Well-diagnosed report, but the double-click word-selection boundary computation lives entirely in the bundled @xterm/xterm package, not in VS Code's own code — VS Code only forwards the `terminal.integrated.wordSeparators` setting straight into xterm's `wordSeparator` option, so any fix belongs upstream.

## Change summary

Double-click word selection in the integrated terminal overruns one cell into a following CJK fullwidth separator character when a custom wordSeparators list includes wide punctuation.

## Best solution
