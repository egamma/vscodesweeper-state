# Issue #79141 — [css] Add support for CSS @supports selector() function

[https://github.com/microsoft/vscode/issues/79141](https://github.com/microsoft/vscode/issues/79141)

## Summary

A real CSS language-feature gap remains: current parsing accepts `selector(...)` only as an opaque general-enclosed function, so selector-aware completion is unavailable. This belongs with the VS Code-team-owned CSS extension and should be transferred to its tracker rather than closed.

## Change summary

Add syntax highlighting and selector-aware completion inside the CSS `@supports selector(...)` function.

## Best solution

Move the issue to https://github.com/microsoft/vscode-css and add explicit `selector()` parsing plus selector completions in the CSS language service, with corresponding TextMate grammar coverage where generic highlighting is insufficient.

## Evidence

- **current parser:** The current vscode-css-languageservice `Parser._parseSupportsConditionInParens` consumes any identifier followed by parentheses as opaque `general_enclosed` content; it does not parse `selector(...)` using the selector grammar.
- **current completion path:** `CSSCompletion.getCompletionsForSupportsCondition` in vscode-css-languageservice offers declaration-property/value completions for parenthesized support conditions and has no selector-function branch, so selector-aware completion remains missing.
- **grammar:** extensions/css/syntaxes/css.tmLanguage.json routes `@supports` headers through `#feature-query` and generic `#rule-list-innards`; there is no explicit `selector()` support rule.
- **canonical search:** Searches of open microsoft/vscode issues and the vscode-css-languageservice issue tracker found no older open issue owning this specific `@supports selector()` request; https://github.com/microsoft/vscode/issues/79141 remains the only matching report.
