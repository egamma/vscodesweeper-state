# Issue #344699 — Agents window opened from WSL workspace restores an older Windows workspace instead of the active remote context

[https://github.com/microsoft/vscode/issues/344699](https://github.com/microsoft/vscode/issues/344699)

## Summary

Keep open: the current folder-only handoff discards WSL workspace URIs, leaving no workspace selection to supersede the restored Windows session. The source confirms this context-loss path; the connection and session-restoration behavior needs coordinated investigation before implementation.

## Change summary

Opening Agents from a WSL editor loses the source project's remote context and leaves an unrelated Windows session selected.

## Best solution

Explicit workspace handoff should preserve the WSL distribution and Linux project path, selecting the matching remote execution environment or offering a clear connection action. Preserve the separate focus-only command's existing session and draft behavior.

- **Behavior:**

  > An explicit Open in Agents action from a WSL editor must retain the source distribution and exact Linux workspace path. It must either select that WSL execution environment or clearly offer connection to it, rather than silently presenting an unrelated Windows project as the requested destination. Conversation migration is not required. Generic focus-only opening must continue preserving existing sessions and drafts.
