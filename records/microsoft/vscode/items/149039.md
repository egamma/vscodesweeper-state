# Issue #149039 — Bracket pair colorization: allow colorize parentheses, brackets and braces independently

[https://github.com/microsoft/vscode/issues/149039](https://github.com/microsoft/vscode/issues/149039)

## Summary

Keep this accepted feature request open: current colorization supports independent nesting counters, but not separately configurable palettes for parentheses, square brackets, and braces. The related report was closed as a duplicate of this issue, and the older open candidates concern different behavior.

## Change summary

Allow parentheses, square brackets, and braces to use separately configurable nesting-color palettes.

## Best solution

Extend the built-in bracket-color theming contract to support optional per-type palettes while preserving existing shared-palette defaults. Settle the public customization surface and bracket-guide behavior with the area maintainer before implementation.

- **Behavior:**

  > Users can configure distinct nesting-color palettes for parentheses, square brackets, and braces in built-in bracket pair colorization. With independent same-type nesting enabled, each type cycles through its own palette and matching opening and closing brackets agree. Existing configurations without per-type overrides retain their current appearance. Acceptance includes mixed nesting, palette cycling, fallback to existing colors, and the agreed bracket-guide behavior.
- **Trace:**

  > BracketPairColorization in src/vs/editor/common/config/editorOptions.ts exposes only enablement and independentColorPoolPerBracketType. ColorProvider in src/vs/editor/common/model/bracketPairsTextModelPart/colorizedBracketPairsDecorationProvider.ts translates the selected nesting depth into a depth-only CSS class, and its theming participant resolves all classes against one shared six-token palette registered in src/vs/editor/common/core/editorColorRegistry.ts. Thus independent counters do not provide independent palettes. BracketPairGuidesClassNames in src/vs/editor/common/model/guidesTextModelPart.ts likewise carries depth but not bracket type. Preserve current defaults, bracket matching, invalid-bracket styling, and language-defined bracket recognition; adjacent-pair color cycling is separate work tracked at https://github.com/microsoft/vscode/issues/131029. The exact matching report at https://github.com/microsoft/vscode/issues/165474 was already consolidated into this issue. The remaining uncertainty is the public palette customization contract and whether guides adopt it.
- **Open decisions:**
  - Should per-type palettes be exposed through theme color tokens, editor configuration, or both, and what fallback applies when a type has no override?
  - Should bracket-pair guides automatically follow the corresponding per-type palette, or retain the existing shared guide colors?
