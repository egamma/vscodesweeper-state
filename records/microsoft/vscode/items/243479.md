# Issue #243479 — Git - Add support for cloning a repository from Azure Repos

[https://github.com/microsoft/vscode/issues/243479](https://github.com/microsoft/vscode/issues/243479)

## Summary

Keep this accepted Git feature request open: cloning from a pasted URL exists, but built-in Azure Repos discovery in the clone picker remains missing. The older Azure DevOps cloning request focuses on authentication and does not clearly absorb repository enumeration.

## Change summary

Add a Clone from Azure Repos source that lists repositories accessible to the signed-in user.

## Best solution

Provide Azure Repos discovery through the existing remote-source provider surface, preserving the normal local Git clone workflow. Decide whether that provider ships by default or through an optional extension, and coordinate authentication requirements with https://github.com/microsoft/vscode/issues/228202.

## Plan brief

- **Likely files:** `extensions/git/src/cloneManager.ts`, `extensions/git-base/src/remoteSource.ts`, `extensions/git-base/src/api/git-base.d.ts`, `extensions/github/src/extension.ts`, `extensions/github/src/remoteSourceProvider.ts`
- **Validation:** With an Azure DevOps account that can access repositories in multiple projects, invoke Git: Clone, select Clone from Azure Repos, select a listed repository, and confirm it becomes a normal local Git checkout. Verify repository discovery covers the agreed organization scope, cancellation creates no checkout, and GitHub discovery and pasted-URL cloning remain unchanged.
- **Behavior:**

  > The Source Control Clone Repository flow should offer Azure Repos discovery and let the user choose an accessible repository without copying its URL from another application. Selecting a repository should use the ordinary Git clone destination and opening workflow, not a virtual read-only workspace. Acceptance should cover accessible repositories across the agreed account and organization scope, cancellation, and unchanged GitHub and URL-based cloning.
- **Trace:**

  > CloneManager.clone in extensions/git/src/cloneManager.ts delegates source selection to pickRemoteSource and then clones the returned URL. extensions/git-base/src/remoteSource.ts renders registered providers and their getRemoteSources results; its exported contract is in extensions/git-base/src/api/git-base.d.ts. The built-in GitHub extension registers GithubRemoteSourceProvider, whose implementation lists authenticated-user repositories through Octokit. No Azure Repos discovery registration was found in the checkout. The discovery gap is established, but Azure account, organization enumeration, and credential integration have not been traced to an implementation. Preserve generic cloning and existing provider behavior; https://github.com/microsoft/vscode/issues/228202 separately records Azure DevOps authentication needs and should inform planning without being assumed to cover this picker requirement.
- **Open decisions:**
  - Should Azure Repos discovery be available in the default installation or supplied by an optional extension?
  - Should discovery enumerate all accessible Azure DevOps organizations automatically, or require the user to select or configure an organization first?
