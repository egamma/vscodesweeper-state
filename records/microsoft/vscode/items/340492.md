# Issue #340492 — Pinned files

[https://github.com/microsoft/vscode/issues/340492](https://github.com/microsoft/vscode/issues/340492)

## Summary

This matches documented, intentional behavior of the default `window.restoreWindows: all` setting: opening a file externally (e.g. via File Explorer's "Open with") replaces previously restored editors, including pinned ones, unless the setting is changed to `preserve`.

## Change summary

Opening a file via Windows Explorer's "Open with VS Code" (while VS Code is closed) drops previously pinned tabs instead of reopening them alongside the new file.

## Best solution

Keep current behavior as the default; point the reporter at `window.restoreWindows: "preserve"`, which the setting's own description says reopens previously opened editors (including pinned ones) together with files opened from the command line/OS.

- **Proposed comment:**

  > Thanks for the report! This matches how `window.restoreWindows` works today (default is `all`): when a file is opened externally — including via "Open with VS Code" from File Explorer — and no window is already running, VS Code opens that file in place of the previously restored editors rather than alongside them. If you set `window.restoreWindows` to `preserve`, previously opened editors (including pinned ones) are kept and the new file opens alongside them. Closing this as working as designed, but let us know if `preserve` doesn't give the behavior you're after.
