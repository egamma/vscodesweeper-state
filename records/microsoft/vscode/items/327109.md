# Issue #327109 — Copilot Chat can invoke an MCP tool before its adapter is registered (undefined.invoke)

[https://github.com/microsoft/vscode/issues/327109](https://github.com/microsoft/vscode/issues/327109)

## Summary

The reported race remains possible on current main: tool registration can change during asynchronous invocation preparation, leaving the previously resolved entry without an implementation. Route this confirmed core defect to the MCP chat area.

## Change summary

Prevent Copilot Chat from dereferencing an MCP tool implementation that was replaced or disposed while its invocation was being prepared.

## Best solution

Make `LanguageModelToolsService.invokeTool` safely resolve the current implementation after asynchronous preparation, coordinating with MCP tool re-registration so an invocation either waits for the replacement adapter or fails with a controlled diagnostic.

## Evidence

- **registration lifecycle:** `registerToolImplementation` in the same file sets `entry.impl = undefined` when its registration is disposed, allowing the checked property to change while `invokeTool` is awaiting.
- **MCP update path:** `src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts` lines 162–168 clear and re-register an MCP tool when its metadata changes, providing a concrete path that invalidates an invocation's previously captured entry.
- **current main:** No post-report commit or test was found that closes this race; current main retains the unguarded final dereference.
