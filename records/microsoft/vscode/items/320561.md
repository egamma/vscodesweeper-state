# Issue #320561 — Extension view: right bar doesn't scroll all the way down

[https://github.com/microsoft/vscode/issues/320561](https://github.com/microsoft/vscode/issues/320561)

## Summary

The bug remains plausible and traceable on current main: the extension metadata pane computes its scroll range before asynchronous metadata can finish changing the content, leaving the bottom unreachable in a short window.

## Change summary

The extension details editor's right-hand metadata pane cannot scroll far enough to reveal all information when vertical space is limited.

## Best solution

Keep the metadata pane's scroll dimensions synchronized with all synchronous and asynchronous updates from AdditionalDetailsWidget, while preserving the independent README scroll position and the existing narrow-layout behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts`, `src/vs/workbench/contrib/extensions/browser/media/extensionEditor.css`
- **Validation:** Open the Python extension details page in a development workbench, reduce the editor height until the metadata pane overflows, wait for asynchronously computed metadata such as cache size to appear, and verify mouse-wheel, trackpad, keyboard, and scrollbar-thumb navigation can reveal the complete final metadata row.
- **Behavior:**

  > When an extension details editor has less vertical space than its right-hand metadata requires, every metadata row remains reachable. This must remain true after asynchronously computed entries appear and after resizing the window. The README/content pane must retain independent scrolling, and widths below the existing narrow-layout threshold must continue hiding the metadata pane.
- **Trace:**

  > ExtensionEditor.renderAdditionalDetails in src/vs/workbench/contrib/extensions/browser/extensionEditor.ts wraps `.additional-details-content` in DomScrollableElement and scans it during initial rendering and editor layout. AdditionalDetailsWidget subsequently appends category data and computed cache-size metadata asynchronously without causing another scroll-dimension scan, so the custom scrollbar can retain an obsolete scrollHeight. The relevant height and overflow constraints are in src/vs/workbench/contrib/extensions/browser/media/extensionEditor.css around `.additional-details-container` and `.additional-details-content`. The boundary is the extension metadata pane: do not alter README webview scrolling, extension-feature scrolling, or the existing narrow-mode threshold. No existing ExtensionEditor layout test was found, so the plan must establish a reliable regression check before implementation.
