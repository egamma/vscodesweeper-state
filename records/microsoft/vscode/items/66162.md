# Issue #66162 — Find usages (find all file references / find all folder references)

[https://github.com/microsoft/vscode/issues/66162](https://github.com/microsoft/vscode/issues/66162)

## Summary

Keep open for the remaining folder-reference and cross-language capability. Built-in file-reference commands partially satisfy the request, but neither covers folder-wide aggregation; the accepted Backlog request has 52 upvotes.

## Change summary

Expose file-reference searches directly and add a folder-reference search that finds references to files throughout the selected folder.

## Best solution

Provide a discoverable, provider-backed file and folder reference experience, retaining existing JS/TS and Markdown support. Coordinate the shared provider contract with https://github.com/microsoft/vscode/issues/134405 while keeping this issue's folder-wide user requirement explicit.

## Plan brief

- **Likely files:** `extensions/typescript-language-features/src/languageFeatures/fileReferences.ts`, `extensions/typescript-language-features/package.json`, `extensions/markdown-language-features/src/languageFeatures/fileReferences.ts`, `extensions/markdown-language-features/package.json`, `src/vscode-dts/vscode.d.ts`
- **Validation:** End the plan with a runnable acceptance scenario: create a configured JS/TS project with two files inside a folder, including a nested file, and imports of both from outside that folder. Invoke the folder-reference action and verify that both importing locations are returned and navigable; cancellation and existing single-file and symbol-reference commands must remain functional. Define provider-contract coverage for additional languages before claiming cross-language support.
- **Behavior:**

  > Users should be able to find references to a selected file without locating an existing import first, and find references to files throughout a selected folder, including nested files. Existing JS/TS and Markdown file-reference commands satisfy part of this goal but not folder-wide aggregation or a consistent extensible experience. Acceptance should demonstrate navigable references for multiple files in one selected folder and preserve existing single-file and symbol-reference behavior.
- **Trace:**

  > FileReferencesCommand.execute in extensions/typescript-language-features/src/languageFeatures/fileReferences.ts accepts one resource, opens it as a text document, requires a supported JS/TS language, and sends a single-file tsserver fileReferences request. FindFileReferencesCommand.execute in extensions/markdown-language-features/src/languageFeatures/fileReferences.ts similarly queries one resource through MdLanguageClient and uses editor.action.showReferences to present results. Both extensions register language-specific file actions in package.json; these paths do not implement folder enumeration. The public ReferenceProvider API in src/vscode-dts/vscode.d.ts is document-and-position-based, while https://github.com/microsoft/vscode/issues/134405 separately proposes a file-oriented provider contract. The trace establishes the missing surface but not a complete cross-layer implementation boundary: the session must determine provider participation, aggregation cost, and integration with that API work. Preserve semantic language-provider results and existing commands; do not treat plain filename text search or safe-delete behavior from https://github.com/microsoft/vscode/issues/52844 as equivalent coverage.
- **Open decisions:**
  - Should the folder action initially expose JS/TS-only support, or require a shared provider contract supporting multiple participating language extensions?
  - When files in a selected folder have no participating reference provider, should the result explicitly disclose incomplete coverage, or should the action be unavailable?

## Evidence

- **Existing capability:** extensions/typescript-language-features/package.json registers typescript.findAllFileReferences in the command palette, Explorer context menu, and editor-tab context menu for JS/TS. FileReferencesCommand.execute in extensions/typescript-language-features/src/languageFeatures/fileReferences.ts opens one text document, checks its supported language, requests tsserver fileReferences for that file, and displays locations through editor.action.showReferences. It does not enumerate a selected folder.
