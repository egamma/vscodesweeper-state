# Issue #60900 — Centered layout should be per workbench, not per editor area

[https://github.com/microsoft/vscode/issues/60900](https://github.com/microsoft/vscode/issues/60900)

## Summary

This accepted Backlog request remains necessary: current main still centers within the editor area, so toggling a sidebar moves the centered content. With 56 community upvotes and multiple duplicate reports, it should remain the canonical issue.

## Change summary

Keep centered-layout content centered relative to the whole workbench when side areas are shown or hidden.

## Best solution

Coordinate centered layout with the workbench's side-area dimensions so the editor remains at the workbench center whenever space permits, shifting only enough to avoid overlap. Preserve the existing editor-relative behavior unless this request is intentionally adopted as the default or a configurable mode.

## Evidence

- **current source:** src/vs/workbench/browser/parts/editor/editorPart.ts constructs CenteredViewLayout around the editor-part grid, while src/vs/base/browser/ui/centered/centeredViewLayout.ts centers solely within the width supplied to that editor part. - **existing setting:** workbench.editor.centeredLayoutFixedWidth, registered in src/vs/workbench/browser/workbench.contribution.ts, only maintains a constant editor width as its containing area resizes; it does not anchor that editor to the whole workbench.
