# Issue #297745 — Opening a mix of elevated and unelevated instances only kind of works

[https://github.com/microsoft/vscode/issues/297745](https://github.com/microsoft/vscode/issues/297745)

## Summary

Keep open: the linked fix attempt was closed without merging, and current main retains the administrator-instance warning. The report provides sufficient launch-order steps to retest on Windows, but source inspection cannot establish that the apparently elevated and unelevated windows actually run at different privilege levels.

## Change summary

Opening additional unelevated windows behaves differently depending on whether an unelevated instance existed before the elevated launch.

## Best solution

Establish the actual process elevation and IPC ownership for both launch orders, then make startup behavior consistent while preserving shared user-data protection. Do not adopt the rejected random-IPC fallback or assume that successful window creation proves independent mixed-elevation processes.
