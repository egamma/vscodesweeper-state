# Issue #255103 — Gemini thinking tokens ExP

[https://github.com/microsoft/vscode/issues/255103](https://github.com/microsoft/vscode/issues/255103)

## Summary

The requested experiment remains unimplemented on current main: Gemini model metadata exposes thinking-budget limits, but the CAPI request path neither reads an experiment-controlled budget nor sends one. The Backlog milestone and maintainer discussion establish an accepted direction, so this should remain open while the experiment design is resolved.

## Change summary

Make Gemini's thinking-token budget experiment-controlled and pass the assigned budget to CAPI so response quality and latency can be compared.

## Best solution

Define the Gemini budget cohorts and evaluation criteria, then carry the selected treatment through the Copilot CAPI request path while respecting each model's advertised minimum and maximum. Coordinate this experiment-specific work with the broader Gemini thinking-configuration request at https://github.com/microsoft/vscode/issues/303360 without treating that newer issue as the canonical owner.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/configuration/common/configurationService.ts`, `extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts`, `extensions/copilot/src/platform/endpoint/test/copilotChatEndpoint.spec.ts`, `extensions/copilot/src/platform/networking/common/networking.ts`
- **Validation:** Add endpoint tests that create Gemini CAPI request bodies under control and treatment assignments, asserting the selected in-range thinking budget is serialized only for the intended Gemini treatment and is absent for the control and unrelated models.
- **Behavior:**

  > Eligible Gemini requests should use the thinking-token budget assigned by the experiment so maintainers can compare response quality and latency across defined cohorts. Control requests must preserve existing behavior, and assigned values must remain within the model limits advertised by CAPI. Acceptance includes endpoint tests for treatment, control, limit handling, and non-Gemini requests, plus an agreed telemetry or evaluation method for comparing the cohorts.
- **Trace:**

  > The Copilot chat-completions path runs through ChatEndpoint.createRequestBody, createCapiRequestBody, and ChatEndpoint.customizeCapiBody in extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts and extensions/copilot/src/platform/networking/common/networking.ts. ChatEndpoint already receives IExperimentationService and customizeCapiBody demonstrates an experiment-backed Gemini request option through ConfigKey.TeamInternal.GeminiFunctionCallingMode. Model metadata is already projected into minThinkingBudget and maxThinkingBudget, but no Gemini CAPI path consumes those limits or assigns thinking_budget. The Messages API implementation is Anthropic-specific and must not be generalized accidentally. https://github.com/microsoft/vscode/issues/303360 is related general configuration work, but it is newer and does not replace this experiment-specific backlog item.
- **Open decisions:**
  - Is the original controlled budget experiment still required now that CAPI advertises Gemini reasoning-effort and thinking-budget capabilities, or should the accepted outcome be general user-facing thinking configuration instead?
  - Which thinking-budget cohorts and quality-versus-latency success criteria should the experiment use?
