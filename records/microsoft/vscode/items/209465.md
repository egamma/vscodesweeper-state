# Issue #209465 — Add option to create reference links when pasting links into markdown

[https://github.com/microsoft/vscode/issues/209465](https://github.com/microsoft/vscode/issues/209465)

## Summary

Keep open: Markdown URL paste still offers inline links, not reference links with definition reuse. The existing reference-link refactoring requires a separate action and does not fulfill this request; no qualifying canonical or open implementation PR was identified.

## Change summary

Offer reference-link creation when pasting URLs into Markdown, reusing matching definitions where possible, with file paste/drop suggested as an additional application.

## Best solution

Provide an optional reference-link paste choice in the built-in Markdown extension without changing existing inline-link behavior. Coordinate definition lookup and generation with the Markdown language service, following the direction already suggested in the discussion.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/src/languageFeatures/copyFiles/pasteUrlProvider.ts`, `extensions/markdown-language-features/src/languageFeatures/copyFiles/shared.ts`, `extensions/markdown-language-features/src/languageFeatures/copyFiles/dropOrPasteResource.ts`, `extensions/markdown-language-features/src/test/pasteUrl.test.ts`
- **Validation:** Extend the Markdown extension tests to verify reference-link paste creates a usable definition, reuses an existing matching definition, avoids conflicting labels, and preserves current inline-link output. Manually paste http://example.com into a Markdown document and select the reference-link alternative; verify the resulting link resolves through its definition.
- **Behavior:**

  > Pasting a URL into a Markdown editor offers a reference-link alternative alongside the existing inline-link choice. Selecting it produces a reference use and a corresponding definition, or reuses a suitable definition already present in the document. Existing inline-link paste remains available and unchanged. Acceptance checks cover a document without definitions, one with a matching definition, and one containing a conflicting reference label.
- **Trace:**

  > PasteUrlEditProvider.provideDocumentPasteEdits in extensions/markdown-language-features/src/languageFeatures/copyFiles/pasteUrlProvider.ts delegates to createInsertUriListEdit in shared.ts. That helper builds range edits using createUriListSnippet, whose normal-link branch emits inline Markdown and has no definition lookup or definition insertion path. ResourcePasteOrDropProvider in dropOrPasteResource.ts uses the same helper for URI lists. Existing inline-output assertions are in src/test/pasteUrl.test.ts. The discussion at https://github.com/microsoft/vscode/issues/209465#issuecomment-2035253940 identifies the Markdown language service's extractLinkDef.ts as relevant prior art, but its suitability as a paste-edit contract has not been established in this review. Preserve current defaults, selection handling, and media insertion; the separate refactoring tracked by https://github.com/microsoft/vscode/issues/162094 is not equivalent to a paste alternative.
- **Open decisions:**
  - Should the initial reference-link option apply only to pasted text URLs, or also to file links inserted by paste and drop?
  - When a new definition is needed, should the paste operation use the Extract Link Definition refactoring's naming, placement, and rename interaction, or a different paste-specific interaction?

## Evidence

- **Current URL paste path:** extensions/markdown-language-features/src/languageFeatures/copyFiles/pasteUrlProvider.ts: PasteUrlEditProvider.provideDocumentPasteEdits calls createInsertUriListEdit and returns one Markdown link edit. The markdown.editor.pasteUrlAsFormattedLink.enabled setting controls activation, not reference-link syntax.
- **Existing capability does not cover the request:** extensions/markdown-language-features/src/languageFeatures/copyFiles/shared.ts: createUriListSnippet constructs normal links as [text](destination); its link-kind options cover links, images, audio, and video, not reference links. createInsertUriListEdit does not look up or append reference definitions. extensions/markdown-language-features/src/test/pasteUrl.test.ts explicitly expects inline-link snippets.
- **File paste and drop share the same limitation:** extensions/markdown-language-features/src/languageFeatures/copyFiles/dropOrPasteResource.ts: ResourcePasteOrDropProvider routes URI-list insertion through createInsertUriListEdit, so the suggested file paste/drop application also lacks reference-link generation.
- **Discussion establishes implementation direction:** https://github.com/microsoft/vscode/issues/209465#issuecomment-2035253940 recommends using microsoft/vscode-markdown-languageservice for reference lookup and definition edits, pointing to src/languageFeatures/codeActions/extractLinkDef.ts. https://github.com/microsoft/vscode/issues/209465#issuecomment-2035424149 explicitly notes the complexity of implementing this correctly.
- **Related refactoring is not a duplicate:** https://github.com/microsoft/vscode/issues/162094 is closed and covers the separate Extract Link Definition code action. Its documented behavior converts existing inline links and appends a definition; it does not supply a reference-link choice during paste and is not an open duplicate target.
- **Canonical and implementation search:** Read-only GitHub searches for Markdown reference links, reference-style links, and paste-related work found no older open issue owning the same requested behavior and no matching open implementation PR. The supplied keyword candidates concern different product behaviors.
