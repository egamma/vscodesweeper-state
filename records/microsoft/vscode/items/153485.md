# Issue #153485 — Show both selection and semantic occurrences in the scrollbar

[https://github.com/microsoft/vscode/issues/153485](https://github.com/microsoft/vscode/issues/153485)

## Summary

Keep open: current source still suppresses selection markers whenever semantic highlighting is enabled and a provider exists, even when it returns no matches. A maintainer explicitly consolidated a later report here; separate color tokens already exist, but simultaneous scrollbar highlighting remains missing.

## Change summary

Allow selection-based and semantic occurrence markers to coexist in the scrollbar with independently configurable colors.

## Best solution

Support distinguishable selection and semantic markers in the editor overview ruler without disabling semantic highlighting. Decide whether coexistence should be the default or opt-in, and account for the minimap report already consolidated here.

- **Behavior:**

  > With selection highlighting and semantic occurrences enabled, selecting repeated text should permit both types of scrollbar markers to remain visible and distinguishable. Textual occurrences in comments, strings or unresolved symbols must not disappear merely because the language has a semantic provider. Existing independent overview-ruler color customizations must remain effective. Acceptance must cover providers returning semantic matches and providers returning none, while preserving ordinary in-editor highlights and selection behavior.
- **Trace:**

  > SelectionHighlighter._setState in src/vs/editor/contrib/multicursor/browser/multicursor.ts derives semantic precedence from provider registration and the occurrencesHighlight option, without consulting actual highlight results. getSelectionHighlightDecorationOptions in src/vs/editor/contrib/wordHighlighter/browser/highlightDecorations.ts maps that flag to selection decorations lacking both overview-ruler and minimap metadata. Separate overview-ruler color tokens already exist, so missing color registration is not the central gap. The existing highlight tests live in the 'Selected text occurrence matching highlights' suite in src/vs/editor/contrib/multicursor/test/browser/multicursor.test.ts. Preserve semantic provider contracts, selected-text matching rules and in-editor selection exclusion. https://github.com/microsoft/vscode/issues/216747#issuecomment-2186249337 consolidates minimap impact here, while https://github.com/microsoft/vscode/issues/100530 concerns a different in-editor overlap symptom. The unresolved boundary is whether the new coexistence behavior changes the default and whether it applies equally to the minimap.
- **Open decisions:**
  - Should simultaneous selection and semantic overview-ruler markers become the default, or require an explicit opt-in?
  - Should the coexistence behavior also apply to minimap markers, as requested by the later report consolidated here?
