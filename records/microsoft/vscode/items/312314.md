# Issue #312314 — Agent Hooks dont work when Windows Powershell is restricted on workstation

[https://github.com/microsoft/vscode/issues/312314](https://github.com/microsoft/vscode/issues/312314)

## Summary

The configured terminal profiles cannot affect hook execution on current main: Windows hooks use `ComSpec` and may launch Windows PowerShell through an absolute path. This remains a valid bug for environments where that executable is restricted.

## Change summary

Allow agent hooks on Windows to use an approved configured shell instead of unconditionally falling back from cmd.exe to Windows PowerShell.

## Best solution

Define and document which existing shell-profile setting governs hook commands, including precedence and fallback behavior, then resolve that profile in the hook executor while preserving the current behavior when no applicable profile is configured.

- **Behavior:**

  > On Windows, agent hooks can execute when legacy Windows PowerShell is blocked but an approved shell such as PowerShell 7 is configured. The selected configuration and its precedence are documented and applied consistently. Existing hook execution behavior remains unchanged when no applicable shell profile is configured, including stdin, cwd, environment, timeout, cancellation, and result handling.
- **Trace:**

  > `NodeHookExecutor._spawn` in extensions/copilot/src/platform/chat/node/hookExecutor.ts delegates to `getShellCommand`, which examines only `process.env.ComSpec`; cmd.exe leads directly to the legacy Windows PowerShell executable. The existing unit suite locks in that behavior. The two settings named in the report currently have narrower documented owners: run-in-terminal tools and task/debug automation, respectively, while `ChatHookCommand` carries no shell selection. The uncertainty starts at that public configuration boundary; preserve non-Windows behavior and the hook lifecycle/result semantics.
- **Open decisions:**
  - Should hooks use `chat.tools.terminal.terminalProfile.windows`, `terminal.integrated.automationProfile.windows`, or a hook-specific setting, and what precedence applies when multiple profiles are configured?
  - Should hook execution honor the selected profile's arguments and environment as well as its executable path, or intentionally consume only the path?
