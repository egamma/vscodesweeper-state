# Issue #197555 — Diff Editor, Unchanged Code Widget: Consider not setting background to grey

[https://github.com/microsoft/vscode/issues/197555](https://github.com/microsoft/vscode/issues/197555)

## Summary

Keep open for a focused design decision: unchanged code still receives a grey tint, although compact hidden-lines controls now have a transparent resting background. This team-authored Backlog item is not demonstrably completed or a verified duplicate.

## Change summary

Reconsider the unchanged-code widget's grey background so its splitter interaction is easier to understand.

## Best solution

Agree on the visual distinction between revealed unchanged code, the hidden-lines control, and its draggable edges, then apply that design consistently across diff-editor variants and themes. Preserve existing reveal and splitter behavior and theme customization.

- **Behavior:**

  > The unchanged-code widget should make the relationship between hidden code, revealed unchanged lines, and draggable splitter edges understandable without an unnecessarily prominent grey surface. The issue requests reconsideration rather than specifying a final visual treatment. Acceptance must cover collapsed, partially revealed, and fully revealed states across supported themes while preserving existing splitter and reveal interactions.
- **Trace:**

  > HideUnchangedRegionsFeature in src/vs/editor/browser/widget/diffEditor/features/hideUnchangedRegionsFeature.ts applies diff-unchanged-lines decorations to unchanged ranges on both editors, independently of the compact control variant. style.css maps these decorations to diffEditor.unchangedCodeBackground, whose editorColors.ts defaults remain translucent grey. The collapsed control separately uses diffEditor.unchangedRegionBackground, while the compact disclosure variant overrides its resting background to transparent. Existing workbench.colorCustomizations provides overrides but does not choose the product default. The uncertainty is which of these distinct surfaces the intended design should neutralize and how their hierarchy should remain apparent. Related discussion at https://github.com/microsoft/vscode/issues/185841#issuecomment-1602598958 raises contrast requirements, and https://github.com/microsoft/vscode/issues/186332 discusses splitter discoverability. Keep diff computation, hidden-range selection, scrolling, and reveal/drag semantics outside this visual-design scope.
- **Open decisions:**
  - Should the revised default remove the tint from revealed unchanged code, neutralize the collapsed hidden-lines control, or change both?
  - What visual distinction should remain between ordinary editor content, revealed unchanged code, and draggable control edges so the splitter stays discoverable across light, dark, and high-contrast themes?
