# Issue #169821 — VS Code is still adding `/d /c` to task commands

[https://github.com/microsoft/vscode/issues/169821](https://github.com/microsoft/vscode/issues/169821)

## Summary

The remaining defect is confirmed in current source: an automation profile using extensionless `pwsh` still receives `/d /c`, as do unrecognized shell wrappers. Nushell-specific support covers part of the original report, but the broader fix was reverted and the issue was subsequently reopened.

## Change summary

Windows tasks append cmd-specific execution arguments to non-cmd automation shells despite the user's configured executable and arguments.

## Best solution

Make task command construction honor the selected automation shell without injecting cmd-only switches into other shells. Preserve explicit task shell overrides, command quoting, and empty-command terminal startup behavior that previous attempts regressed.
