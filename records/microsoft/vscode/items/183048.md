# Issue #183048 — Git - implement shelve feature

[https://github.com/microsoft/vscode/issues/183048](https://github.com/microsoft/vscode/issues/183048)

## Summary

Keep open: native stash browsing now covers part of this accepted request, but comparing saved changes with an arbitrary branch remains missing from the stash workflow. Neither verified related issue owns the full remaining scope.

## Change summary

Provide a shelf-like explorer for saved changes that remains accessible across branches and supports comparison with any branch.

## Best solution

Extend the existing native Git stash experience to support the requested cross-branch inspection, rather than introduce a parallel shelf surface without a demonstrated need. A maintainer should settle comparison semantics and whether Git-backed storage satisfies the intended shelf behavior.

## Plan brief

- **Likely files:** `extensions/git/src/artifactProvider.ts`, `extensions/git/src/commands.ts`, `extensions/git/package.json`
- **Validation:** In a disposable Git repository with two branches containing different versions of a tracked file, save changes on one branch, switch branches, and inspect the saved entry from the native SCM explorer without applying it. Verify comparison against a selected branch follows the agreed semantics, includes added/deleted and untracked files where applicable, and leaves the working tree, index, stash contents, and existing View/Apply/Pop/Drop behavior unchanged.
- **Behavior:**

  > Saved changes should remain discoverable through an explorer-style native Git surface after switching branches. Users should be able to inspect those changes against a branch they select without applying them or modifying either branch. Native stash listing already supplies part of this behavior; the remaining work must establish the comparison meaning and whether individual saved files need to be browsable inline. Acceptance should cover branch switching, selected-branch comparison, and preservation of saved and working-tree changes.
- **Trace:**

  > GitArtifactProvider in extensions/git/src/artifactProvider.ts already lists repository-wide stashes and binds entries to git.repositories.stashView. Commands.artifactStashView resolves an entry and delegates to Commands._viewStash in extensions/git/src/commands.ts, which compares tracked files against the stash's first parent and handles untracked files through its third parent. The package.json comparison action is restricted to branch/tag artifacts; the generic Commands._openChangesBetweenRefs path exists, but the stash workflow does not expose branch selection. Existing stash lifecycle actions must remain intact, and no separate storage system should be assumed before the product decision. https://github.com/microsoft/vscode/issues/180720 covers native stash-list UX, while https://github.com/microsoft/vscode/issues/322218 covers expanding individual files; neither establishes the full comparison contract here. Investigation stopped at the distinction between comparing saved snapshots and comparing saved change hunks relative to another branch; these yield different user-visible results.
- **Open decisions:**
  - Should the shelf experience use existing Git stashes, or must saved changes have storage and lifecycle semantics independent of Git stash?
  - When comparing saved changes with a selected branch, should the result show snapshot differences or the saved change hunks interpreted against that branch?
  - Does the requested explorer experience require individual saved files as expandable children, or is selecting a saved entry to open the multi-file diff sufficient?
