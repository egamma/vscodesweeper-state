# Issue #333037 — Git: Clone destination folder dialog never appears for a repo with no prior clone history

[https://github.com/microsoft/vscode/issues/333037](https://github.com/microsoft/vscode/issues/333037)

## Summary

Traced the exact flow on current main (extensions/git/src/cloneManager.ts and commands.ts) and the destination dialog is always shown when there's no cached repo — the reporter explicitly hasn't tested with all extensions disabled, so this needs isolation before it can be treated as a core defect.

## Change summary

The native folder picker for `Git: Clone` destination is skipped for repos with no prior clone history, going straight to the post-clone prompt without ever running `git clone`.

## Best solution

Ask the reporter to retest with `code --disable-extensions` (especially with the GitHub Pull Requests extension off) since core's `git.clone` command only skips the dialog when a `parentPath` is already supplied by the caller — if the dialog reappears with extensions disabled, this is extension-caused; if it still reproduces, it points to something upstream of `CloneManager.clone` invoking the command with a preset `parentPath`.
