# Issue #180144 — Goto line picker should not announce the line content

[https://github.com/microsoft/vscode/issues/180144](https://github.com/microsoft/vscode/issues/180144)

## Summary

Keep open: quick access still separately announces destination-line content, so the architectural concern remains. The thread explicitly requires preserving working Windows announcements until an editor-level replacement is verified.

## Change summary

Make destination-line accessibility feedback an editor responsibility rather than a separate quick-access announcement.

## Best solution

Provide reliable destination-line feedback through the editor's accessibility machinery for both built-in and extension-driven navigation, then retire the redundant quick-access announcement. Establish current Windows and macOS behavior before changing the workaround.

## Evidence

- **Current quick-access responsibility:** src/vs/editor/contrib/quickAccess/browser/gotoLineQuickAccess.ts:66–78 calls gotoLocation on acceptance. In src/vs/editor/contrib/quickAccess/browser/editorNavigationQuickAccess.ts:145–156, gotoLocation sets the selection, reveals the range, optionally focuses the editor, then independently reads getLineContent and sends status("Line {0}, column {1}: {2}"). The central architectural concern is still present, although the current implementation uses status rather than alert.
- **Long-line concern partially mitigated:** src/vs/base/browser/ui/aria/aria.ts caps inserted announcements at MAX_MESSAGE_LENGTH = 20000. Thus a 10 MB line is not inserted in full into the live region, but quick access still obtains the entire line and constructs the message before that truncation. This mitigation does not move announcement ownership into the editor.
