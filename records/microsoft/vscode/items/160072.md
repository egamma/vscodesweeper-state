# Issue #160072 — Guarantee that TextDocument.version doesn't skip versions

[https://github.com/microsoft/vscode/issues/160072](https://github.com/microsoft/vscode/issues/160072)

## Summary

Keep open as the older canonical API-contract request. Current main increments versions consecutively while a model is open, but the public API deliberately guarantees only strict increase, and the separate close/reopen requirement remains under active design discussion.

## Change summary

Strengthen the TextDocument.version contract to guarantee consecutive increments and preserve monotonic versioning when documents are closed and reopened.

## Best solution

The editor API owners should decide the two guarantees separately: whether extensions may rely on exactly one increment per content-change event, and whether versions remain monotonic across model disposal and recreation. If accepted, the behavior and vscode.d.ts contract should be updated together; discussion from https://github.com/microsoft/vscode/issues/223077 should consolidate here because this older request includes both concerns.

## Evidence

- **current implementation:** src/vs/editor/common/model/textModel.ts initializes `_versionId` to 1 and `_increaseVersionId()` advances it with `this._versionId + 1`, so consecutive increments are current implementation behavior but not an API guarantee.
- **public contract:** src/vscode-dts/vscode.d.ts documents only that TextDocument.version "will strictly increase after each change, including undo/redo"; it does not promise consecutive values.
- **remaining lifecycle gap:** A new TextModel initializes its version to 1, while restoration can overwrite that value; therefore monotonicity across close/reopen depends on retained model history and is not guaranteed for the whole application lifecycle.
- **related discussion:** https://github.com/microsoft/vscode/issues/223077 is open and discusses the close/reopen portion in detail. Its implementation PR https://github.com/microsoft/vscode/pull/223079 was closed without merging, and a maintainer later reopened the issue for further discussion.
- **canonical scope:** This 2022 issue predates https://github.com/microsoft/vscode/issues/223077 and requests the stronger consecutive-increment guarantee in addition to raising close/reopen monotonicity; the newer issue does not fully absorb that broader contract.
