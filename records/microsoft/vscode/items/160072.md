# Issue #160072 — Guarantee that TextDocument.version doesn't skip versions

[https://github.com/microsoft/vscode/issues/160072](https://github.com/microsoft/vscode/issues/160072)

## Summary

A real API-contract gap remains: current main increments versions consecutively for content changes, but the public API still guarantees only strict increase. The broader reopen-lifecycle discussion does not cover the requested no-skips guarantee.

## Change summary

Guarantee that each observed TextDocument content change advances its version by exactly one, including a related request for continuity across close and reopen.

## Best solution

Have the editor API owners confirm and document the +1 invariant for each emitted content-change event if it is supportable long-term. Track cross-close/reopen monotonicity separately in https://github.com/microsoft/vscode/issues/223077.

## Evidence

- **current implementation:** On current main, src/vs/editor/common/model/textModel.ts:782-789 implements `_increaseVersionId` as exactly `this._versionId + 1`; the content mutation paths at lines 524, 562, and 1524 invoke it before emitting their change events.
- **public contract:** src/vscode-dts/vscode.d.ts:137-141 still says only that the version will "strictly increase" after each change, without promising consecutive values.
- **reopen behavior:** src/vs/editor/common/services/modelService.ts:315-346 restores a disposed model's saved version only under specific undo/redo and content conditions, so lifecycle-wide monotonicity is not guaranteed.
- **related issue:** https://github.com/microsoft/vscode/issues/223077 remains open and discusses lifecycle-wide monotonicity, but does not require every change to advance by exactly one; it therefore does not absorb this issue's central API-contract request.
