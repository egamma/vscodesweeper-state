# Issue #208865 — Support filtering in builtin notebook variable view

[https://github.com/microsoft/vscode/issues/208865](https://github.com/microsoft/vscode/issues/208865)

## Summary

Keep open: Jupyter implemented automatic exclusions for several variable types, but the built-in view still lacks the requested user-selectable filtering. The related notebook-papercuts issue explicitly tracks this remaining work rather than replacing it.

## Change summary

Support notebook-variable filtering by user ownership and type, including exclusion of kernel- and extension-provided helpers.

## Best solution

Provide a coherent filtering experience for Notebook Variables, coordinating with variable providers where identifying user-created variables requires language-specific knowledge. Decide whether provider-side filtering alone is sufficient or whether users should control which categories are visible.

- **Behavior:**

  > Notebook Variables should let users focus on relevant notebook state rather than kernel- or extension-generated clutter. The requested capabilities include a user-variable-only view and filtering by variable type. Automatic Jupyter exclusions already address part of the clutter, so acceptance must distinguish that existing behavior from the remaining filtering capability. Verify the agreed behavior with mixed variable categories and after notebook execution refreshes.
- **Trace:**

  > NotebookVariablesView.renderBody in src/vs/workbench/contrib/notebook/browser/contrib/notebookVariables/notebookVariablesView.ts creates the tree without category filtering controls. NotebookVariableDataSource.getRootVariables in notebookVariablesDataSource.ts forwards all selected-kernel results into tree elements. VariablesResult in src/vs/workbench/contrib/notebook/common/notebookKernelService.ts supplies optional type information but no ownership classification. https://github.com/microsoft/vscode-jupyter/pull/15551 implemented automatic exclusions for several Python types, while the issue discussion also allows provider-side filtering or grouping. - **Open decisions:**
  - Should filtering be user-selectable, with a way to reveal excluded categories, or should providers determine a fixed filtered or grouped presentation?
