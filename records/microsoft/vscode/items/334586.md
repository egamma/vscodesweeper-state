# Issue #334586 — Terminal and agent command output is inaccessible after output and scrollback limits are reached

[https://github.com/microsoft/vscode/issues/334586](https://github.com/microsoft/vscode/issues/334586)

## Summary

A real gap remains: existing output artifacts preserve retrieved text, but cannot recover command output already evicted from terminal scrollback. Route this request to the terminal agent-tools area to consider complete, user-accessible command records independently of display limits.

## Change summary

Retain complete agent command output and provide a user-visible way to inspect it after terminal scrollback and inline output limits are exceeded.

## Best solution

Provide a searchable or exportable command record independent of bounded terminal scrollback, while keeping terminal rendering and model previews bounded. Coordinate with the existing large-result storage work without treating artifact-read permissions as a solution to output lost before artifact creation.

## Evidence

- **Existing setting is only partial coverage:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts registers terminal.integrated.scrollback with a default of 1000 lines and explicitly documents increased memory consumption for larger values. Increasing this finite buffer does not provide the requested independent, complete command record.
- **Output is retrieved after buffer eviction:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/outputHelpers.ts:getRawOutput reads only xterm.raw.buffer.active and clamps a disposed start marker to line 0. executeStrategy/richExecuteStrategy.ts:207–231 retrieves finished-command or marker-based output and explicitly reports 'Output exceeded terminal scrollback; beginning of output was lost'. This is a documented limit rather than evidence of an existing complete-transcript contract being violated.
- **Existing artifact cannot restore missing text:** browser/largeOutputFileWriter.ts:processOutput saves supplied text exceeding MAX_OUTPUT_LENGTH, which is 20000 characters in outputHelpers.ts. browser/tools/runInTerminalTool.ts:2510–2524 passes terminalResult, optionally compacted, to that writer only after retrieval. The saved file therefore cannot recover earlier lines already absent from the terminal buffer.
- **Related completed work does not satisfy this request:** https://github.com/microsoft/vscode/issues/321667 addressed retrieval failure after scrollback overflow. Its verification comment, https://github.com/microsoft/vscode/issues/321667#issuecomment-4723812199, explicitly says the fix returns whatever remains and warns that the beginning was lost; it does not retain the complete output.
- **Older open reports are related, not canonical duplicates:** https://github.com/microsoft/vscode/issues/333709 concerns agent file-read approval for existing spill artifacts; https://github.com/microsoft/vscode/issues/314212 concerns agent access to truncated output; https://github.com/microsoft/vscode/issues/329179 concerns reasoning from previews despite an available full payload. None establishes the same user-visible symptom and full scope of this re-reviewed request: recovering command output after scrollback eviction.
- **Maintainer direction on adjacent storage work:** https://github.com/microsoft/vscode/issues/333709#issuecomment-5501363707 recommends consolidating terminal-specific spilling into generic Copilot session-resource handling. That is relevant coordination, but changing the downstream storage mechanism alone does not preserve text lost before retrieval.
