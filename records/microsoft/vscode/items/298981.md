# Issue #298981 — New Chat Shows Agent Prompts of Custom Agent

[https://github.com/microsoft/vscode/issues/298981](https://github.com/microsoft/vscode/issues/298981)

## Summary

A real gap remains: current main records agent targets on prompt files and handoffs, but the new-chat welcome surface does not expose agent-aware suggestions. No older issue found reports this same observable request, so the re-reviewed item should remain open for a product decision.

## Change summary

Show prompt files and handoffs targeting the selected custom agent as suggestions when starting a new chat.

## Best solution

Define an agent-aware new-chat recommendation experience that surfaces only prompt files and incoming handoffs applicable to the selected custom agent, with a clear ranking and activation behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`
- **Validation:** Add targeted chat widget/browser tests that select a custom agent and verify the new-chat recommendation surface includes prompt files and handoffs targeting that agent, excludes entries targeting other agents, and launches the selected entry with the expected agent.
- **Behavior:**

  > When a new chat has a custom agent selected, it should make workflows for that agent discoverable by showing applicable prompt files and handoffs as suggested actions. Suggestions targeting other agents must not appear. Activating a suggestion must preserve the intended target agent and prompt content. The experience must remain usable when no applicable suggestions exist and when enough matches exist to require ranking or truncation.
- **Trace:**

  > PromptFileParser in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts already exposes a prompt file's `agent` and parses handoff target metadata. Custom-agent handoffs are represented in src/vs/workbench/contrib/chat/common/chatModes.ts through ICustomAgentInfo and buildCustomAgentHandoffsInfo. The current new-chat welcome path ends in ChatWidget.getWelcomeViewContent in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts, while IChatViewWelcomeContent and ChatViewWelcomePart in src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts currently have no recommendation surface. The uncertainty starts at the product presentation: the previous general welcome suggestions are no longer part of this path, so the plan must choose where agent-aware suggestions live and how they are ranked. Do not change post-response handoff semantics or make unrelated prompt files visible to the selected agent.
- **Open decisions:**
  - Should agent-aware recommendations restore a suggestion section in the empty-chat welcome view, or appear in an existing prompt-selection surface such as the slash-command picker?
  - When many prompt files and incoming handoffs target the selected agent, which entries are shown first and what limit or overflow behavior should users see?

## Evidence

- **current source gap:** On current main, src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:getWelcomeViewContent returns title, message, icon, and additionalMessage but no suggested prompts; IChatViewWelcomeContent in src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts likewise has no suggestion model.
- **available metadata:** src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts exposes the prompt file's `agent` attribute and parses each custom-agent handoff's target `agent`, label, prompt, and send behavior, so the requested relationships exist in the current source.
- **existing configuration:** The `chat.promptFilesRecommendations` setting remains registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts, but current-source search finds its getter only in src/vs/workbench/contrib/chat/common/promptSyntax/config/config.ts and no welcome-view consumer.
- **related issues are not canonical:** https://github.com/microsoft/vscode/issues/287170 asks for clicking a handoff to start a fresh session, while https://github.com/microsoft/vscode/issues/301044 asks for programmatic fresh-session handoffs and was created after this issue. Neither reports the same symptom of a new chat listing prompts and handoffs associated with its selected custom agent, so the stronger re-review duplicate bar is not met.
