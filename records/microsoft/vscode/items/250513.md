# Issue #250513 — navigating through prompt history with a mcp image resource will cause a delay

[https://github.com/microsoft/vscode/issues/250513](https://github.com/microsoft/vscode/issues/250513)

## Summary

The delay remains source-reproducible on current main: prompt-history navigation waits for the remote image to be fetched and resized before restoring the prompt text. This team-authored bug should remain open.

## Change summary

Navigating back to a prompt containing an MCP image resource blocks prompt restoration while the image is retrieved and processed.

## Best solution

Make prompt text and history state appear immediately while image data is restored asynchronously, ensuring a slow or failed image fetch cannot block navigation or overwrite a newer history selection.

- **Trace:**

On navigation, `ChatInputPart.navigateHistory` awaits `restoreAttachments` before calling `setValue`; `restoreAttachments` performs the potentially remote image read and `resizeImage`, conclusively placing network and image-processing latency on the prompt-restoration path. Keep history persistence, image size/format handling, and non-image attachment restoration semantics unchanged, and account for navigation occurring while an earlier image restoration is still pending.

## Evidence

- **source reproduction:** In src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, `_getFilteredEntry` deliberately removes image `value` data from persisted history entries, so an image with references must be recovered when revisiting the prompt.
- **blocking path:** In `ChatInputPart.navigateHistory`, `await this.restoreAttachments(...)` runs before `setValue(inputText, true)`. `restoreAttachments` awaits `sharedWebExtracterService.readImage` or `fileService.readFile` and then `resizeImage`, directly causing the reported delay before the previous prompt is displayed.
- **confirmed scope:** The maintainer comment at https://github.com/microsoft/vscode/issues/250513#issuecomment-2936179703 indicates the same path likely affects image attachments generally, not only MCP-originated images.
