# Issue #255142 — Allow to disable project context in ask mode

[https://github.com/microsoft/vscode/issues/255142](https://github.com/microsoft/vscode/issues/255142)

## Summary

A real per-agent isolation gap remains: `tools: []` restricts tools but does not suppress all automatically injected workspace metadata and project instructions. This team-authored feature request has no qualifying referenced fix or older canonical, so it should remain open for a product-contract decision.

## Change summary

Allow a custom Ask agent or prompt to opt out of automatically supplied project context.

## Best solution

Define a per-agent or shared prompt-customization isolation contract that controls automatic workspace metadata and instruction injection while preserving existing behavior by default. The contract should clearly distinguish implicit project context from the customization's own instructions and explicitly attached context.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vscode-dts/vscode.proposed.chatPromptFiles.d.ts`, `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx`, `extensions/copilot/src/extension/prompts/node/panel/customInstructions.tsx`, `extensions/copilot/src/extension/prompts/node/agent/test/agentPrompt.spec.tsx`
- **Validation:** Extend `extensions/copilot/src/extension/prompts/node/agent/test/agentPrompt.spec.tsx` with isolated and non-isolated custom-agent cases: the isolated rendering must omit every context category selected by the contract, while the control case retains the existing prompt and both retain the custom agent's own instructions.
- **Behavior:**

  > A custom Ask agent configured to run without project context must not receive the categories of automatically injected workspace context covered by the isolation contract. The agent's own instructions must remain effective, and custom agents without the option must retain current behavior. Acceptance should separately exercise workspace metadata, project instruction files, and explicit user-supplied context so the boundary is observable and stable.
- **Trace:**

  > `AgentPrompt` in `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx` independently adds `CustomInstructions` and `GlobalAgentContext`. `GlobalAgentContext` always emits workspace-folder information, while `AgentMultirootWorkspaceStructure` only omits the file tree when `listDirectory` is unavailable; therefore `tools: []` does not mean context-free. `CustomInstructions` in `extensions/copilot/src/extension/prompts/node/panel/customInstructions.tsx` also loads agent instruction files independently of the selected tool set. The custom-agent API and prompt header schema currently carry no isolation bit, so the option must cross the parser/API boundary before prompt rendering can honor it. Keep default agents and tool-selection semantics unchanged. The related https://github.com/microsoft/vscode/issues/273815 broadens the design question to prompt files but is newer and not a duplicate canonical.
- **Open decisions:**
  - Does isolation suppress only automatically applied instruction files, or all implicit project context including workspace folder paths, file trees, repository metadata, tasks, preferences, and customization indexes?
  - Should the same isolation contract apply to both custom agents and reusable prompt files, as requested by https://github.com/microsoft/vscode/issues/273815, or only to custom agents?

## Evidence
