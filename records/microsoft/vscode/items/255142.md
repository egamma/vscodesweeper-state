# Issue #255142 — Allow to disable project context in ask mode

[https://github.com/microsoft/vscode/issues/255142](https://github.com/microsoft/vscode/issues/255142)

## Summary

A real gap remains: current custom-agent metadata cannot suppress the workspace context that the Copilot prompt injects at the start of a conversation. This member-authored request must stay open, with the exact isolation semantics settled before implementation.

## Change summary

Allow a custom Ask-mode agent to omit automatically supplied project context so general questions are not biased toward the open workspace.

## Best solution

Provide a documented per-custom-agent isolation option that omits the agreed automatic workspace context while preserving context the user explicitly attaches. Define its relationship to environment details and automatic instruction files before finalizing the contract.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/service/promptsService.test.ts`, `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx`, `extensions/copilot/src/extension/prompts/node/agent/test/agentPrompt.spec.tsx`
- **Validation:** Extend the custom-agent parsing tests to verify the selected isolation contract reaches mode metadata, and extend `agentPrompt.spec.tsx` to verify an isolated agent omits the agreed automatic context while a normal agent and explicitly attached context remain unchanged.
- **Behavior:**

  > A custom Ask-mode agent can declare that automatically supplied project context should not be included. When selected, a general question is sent without the agreed workspace-derived context, while user-authored mode instructions and explicitly attached context remain available. Agents without the option retain current behavior. Acceptance must separately cover an isolated agent, a default agent, and an isolated request with an explicit attachment.
- **Trace:**

  > Custom-agent frontmatter is described in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts and resolved by `CustomAgent.fromParsedPromptFile` in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts; scalar advanced options already flow through `ChatRequestModeInstructions.metadata`. In extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx, `AgentPrompt.render` always calls `getOrCreateGlobalAgentContext`, whose `GlobalAgentContext` emits OS details, task information, workspace folders, and the workspace tree. No metadata value currently gates that path. The boundary should preserve explicit attachments, mode instructions, and tool selection, and should not alter default agents. https://github.com/microsoft/vscode/issues/273815 separately raises automatic instruction-file suppression; the plan must decide whether that is part of this contract or remains separate.
- **Open decisions:**
  - Does disabling project context suppress only workspace folders and the workspace tree, or also environment and task information emitted by `GlobalAgentContext`?
  - Should the option also suppress automatically discovered instruction files and customizations, or should that remain the separate scope tracked by https://github.com/microsoft/vscode/issues/273815?
  - Should isolation be a top-level custom-agent attribute or a documented advanced option shared with other agent harnesses?
