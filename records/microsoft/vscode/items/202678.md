# Issue #202678 — resourceLabelFormatters include a leading backslash on Windows paths and stripPathStartingSeparator doesn't affect this

[https://github.com/microsoft/vscode/issues/202678](https://github.com/microsoft/vscode/issues/202678)

## Summary

The accepted label-provider bug remains source-reproducible on current main: separator stripping occurs before path-separator conversion and compares the URI's leading `/` with the requested Windows `\`, so the leading separator survives.

## Change summary

A custom resource label using `${path}`, Windows separators, and `stripPathStartingSeparator` displays an unwanted leading backslash.

## Best solution

Make `stripPathStartingSeparator` consistently remove the URI path's initial separator before display-separator conversion, while preserving leading separators when the option is disabled and leaving non-path template text unchanged.
