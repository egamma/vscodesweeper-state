# Issue #204193 — Editor.cursorSurroundingLines broken with update to 1.86

[https://github.com/microsoft/vscode/issues/204193](https://github.com/microsoft/vscode/issues/204193)

## Summary

Current source still lets the configured maximum Sticky Scroll height override cursorSurroundingLines, including at the bottom of the viewport. Keep this canonical report open: the linked bottom-padding PR remains unmerged, and the maintainer's explanation of cursor protection does not resolve the full reported behavior.

## Change summary

Prevent Sticky Scroll's maximum line count from imposing unnecessary cursor-surrounding margins when its widget does not occupy that space.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/292158 for the bottom-margin defect, while retaining this issue for the remaining top-margin behavior. Cursor revealing should preserve visibility beneath Sticky Scroll without reserving unused maximum widget space or imposing that reservation at the bottom.

## Evidence

- **Current source confirms the interaction:** In src/vs/editor/browser/viewParts/viewLines/viewLines.ts:720-740, ViewLines._computeScrollTopToRevealRange computes surroundingLines as Math.max(cursorSurroundingLines, stickyScrollEnabled ? maxNumberStickyLines : 0), then uses the resulting context for both paddingTop and paddingBottom. With keyboard navigation, cursorSurroundingLines=2, stickyScroll.maxLineCount=10, and a sufficiently tall viewport, both margins therefore derive from 10 rather than 2, independently of actual widget height.
- **Confirmed reproduction and workaround:** https://github.com/microsoft/vscode/issues/204193#issuecomment-2748743069 provides complete settings and arrow-key reproduction steps, confirming excess margins at both viewport boundaries. https://github.com/microsoft/vscode/issues/204193#issuecomment-2133980646 independently confirms that disabling Sticky Scroll restores the surrounding-lines behavior; this workaround sacrifices Sticky Scroll rather than solving the interaction.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/292158 is OPEN with mergedAt=null. Its description explicitly addresses part of this issue, and its diff separates top and bottom context so Sticky Scroll's maximum affects only the top. The inspected main source still contains the original shared-context calculation; the PR is neither a landed fix nor a complete solution for the top margin.
