# Issue #329516 — Agent plugins: auto-update permanently fails with "Cannot fast-forward to multiple branches" due to concurrent git fetch/pull in the same plugin clone

[https://github.com/microsoft/vscode/issues/329516](https://github.com/microsoft/vscode/issues/329516)

## Summary

Confirmed on current main: `AgentPluginRepositoryService.pullRepository`/`fetchRepository` are not serialized against `ensureRepository`'s `_cloneSequencer`, so concurrent `git fetch`/`pull` in the same clone can corrupt `FETCH_HEAD`; `LocalGitService._isFastForwardPullFailure` also doesn't recognize `Cannot fast-forward to multiple branches`, so the existing retry/hard-reset recovery never kicks in and the plugin is stuck failing forever.

## Change summary

Agent-plugin auto-update permanently fails with 'Cannot fast-forward to multiple branches' because concurrent git fetch/pull in the same plugin clone race on FETCH_HEAD, and the failure isn't recognized as recoverable.

## Best solution

Two independent, both worth landing: (1) broaden `LocalGitService._isFastForwardPullFailure` in src/vs/platform/git/node/localGitService.ts to also match `Cannot fast-forward to multiple branches`, so the existing fetch-retry/hard-reset recovery repairs the clone instead of failing forever; (2) serialize `pullRepository`/`fetchRepository` on the existing `_cloneSequencer` keyed by repoDir in agentPluginRepositoryService.ts (or add an on-disk lock for cross-window contention) to stop the races at the source.
