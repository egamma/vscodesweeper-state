- **Confirmed startup regression:** https://github.com/microsoft/vscode/issues/344044 includes concrete chat-startup steps, Darwin x64 runtime.node dlopen errors, and repeated failures through VS Code 1.146.0. Independent commenters report that downgrading to 1.141 restores functionality, while completions remain functional.
- **Upstream compatibility lead:** https://github.com/microsoft/copilot-sdk/issues/2919 tracks older-macOS runtime.node loading failures beginning with SDK >=1.0.18 / runtime >=1.0.94. Comment 13 in the reviewed issue attributes failures to unavailable system symbols, but the precise CryptoKit and _proc_signal_with_audittoken claims were not independently verified.
- **Workarounds do not establish resolution:** The reporter describes recovery after updating both macOS and Node.js, but other commenters still report failures, including on Ventura 13.7.8. Comment 12 supplies settings to bypass the Copilot harness; bypassing the failing runtime is not evidence that its compatibility defect was fixed.
- **Canonical comparison:** https://github.com/microsoft/vscode/issues/342470 reports an ARM64 failure on macOS 14.0 and diagnoses a missing libruntime.dylib referenced through a build-runner path. The shared dlopen message does not establish that its packaging defect owns this Intel Ventura compatibility report, particularly under the re-review duplicate bar.

It is closed according to the supplied context and therefore cannot serve as a duplicate canonical; its fetched content supplies no fixing commit.
