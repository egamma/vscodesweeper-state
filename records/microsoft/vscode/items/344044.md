# Issue #344044 — Copilot Chat CLI server fails to start on Intel Mac (macOS x64) after VS Code update

[https://github.com/microsoft/vscode/issues/344044](https://github.com/microsoft/vscode/issues/344044)

## Summary

Keep open as an upstream Copilot SDK runtime compatibility issue. Multiple reports confirm the startup failure on older macOS, and no concrete fixing commit establishes that the bundled runtime now resolves it.

## Change summary

Copilot Chat cannot start because the bundled macOS native runtime fails to load on Intel Macs running Ventura.

## Best solution

Resolve the native runtime compatibility problem through the SDK investigation, then verify the adopted runtime on affected macOS x64 systems. Preserve this VS Code report until its startup failure is demonstrably resolved.

## Evidence

- **Confirmed user impact:** https://github.com/microsoft/vscode/issues/344044 contains repeated failures through VS Code 1.146.0, including Intel macOS 13.4, with CLI exit code 1 and runtime.node dlopen failure. Several commenters report that downgrading to 1.141 restores chat; code completion continues working.
- **Verified upstream investigation:** https://github.com/microsoft/copilot-sdk/issues/2919 is open and explicitly references this issue. Its body describes the same runtime.node loading failure in darwin-x64 and darwin-arm64 packages beginning with SDK 1.0.18/runtime 1.0.94, with reports across VS Code, JetBrains, and Copilot Desktop.
- **Canonical comparison:** https://github.com/microsoft/vscode/issues/342470 is older and open, but its report concerns ARM64 on macOS 14.0 and a missing libruntime.dylib dependency at a build-machine path. That does not establish the same cause as this Intel Ventura compatibility report, so it does not justify a duplicate close under the re-review bar.
- **Closed satellite:** https://github.com/microsoft/vscode/issues/347718 reports the same x64 runtime loading error on macOS 12.7.6. It is closed and cannot serve as a duplicate canonical; its report supplies no fixing commit.
- **Current source boundary:** package.json now pins @microsoft/copilot-sdk 2.0.1. src/vs/platform/agentHost/node/copilot/copilotRuntimePaths.ts selects the platform/architecture package and checks that copilot-runtime, runtime.node, and SDK assets exist; copilotAgent.ts uses those resolved assets for SDK startup. These checks do not establish that the native binary loads on Ventura, and a changed dependency version is not proof of a fix.
- **Workaround and uncertainty:** The local-harness workaround in the discussion corresponds to registered settings chat.editor.localAgent.enabled, chat.defaultToCopilotHarness, and chat.editor.preferCopilotHarness in src/vs/platform/agentHost/common/agentHostEnablementService.ts, but bypassing the SDK is not a runtime fix. One reporter recovered after an OS upgrade, while another reports the error on Ventura 13.7.8; the claimed missing system symbols remain an investigation lead rather than conclusively proven here.
