# Issue #344044 — Copilot Chat CLI server fails to start on Intel Mac (macOS x64) after VS Code update

[https://github.com/microsoft/vscode/issues/344044](https://github.com/microsoft/vscode/issues/344044)

## Summary

Keep open to investigate the confirmed macOS runtime-loading regression. The reporter recovered after updating macOS, but other users still report failures; neither a fixing commit nor a canonical covering the Intel failure has been established.

## Change summary

Copilot Chat cannot start because its bundled native runtime fails to load on Intel macOS after updating VS Code.

## Best solution

Establish the native loader failure on the affected Intel/macOS combination and ensure the bundled runtime works on supported systems. Distinguish OS compatibility failures from the missing-library packaging problem reported on ARM64 before consolidating the reports.

## Evidence

- **Repeated reproduction:** https://github.com/microsoft/vscode/issues/344044 contains concrete startup steps and repeated reporter confirmations on versions 1.143.1, 1.144.0 and 1.144.1: the CLI exits with code 1 while loading runtime.node, although code completion works.
- **Workarounds are not a verified fix:** The November 12 discussion at https://github.com/microsoft/vscode/issues/344044 reports recovery after updating macOS from Ventura 13.3.1 to 13.7.8 alongside a Node.js change. Another user reports that downgrading to 1.141 restores operation; these observations do not isolate the cause or establish a landed fix.
- **Related Intel report:** https://github.com/microsoft/vscode/issues/347718 reports the same darwin-x64 runtime.node loading failure on VS Code 1.146.0 and macOS 12.7.6. It is a newer related report, not an established canonical for this re-reviewed issue.
- **ARM64 duplicate not established:** https://github.com/microsoft/vscode/issues/342470 describes the same startup symptom on ARM64, but specifically diagnoses a missing libruntime.dylib referenced through a build-machine path. This issue has no equivalent Intel loader diagnosis, and recovery after an OS update leaves a potentially distinct compatibility cause.
- **Current source boundary:** src/vs/platform/agentHost/node/copilot/copilotRuntimePaths.ts selects copilot-sdk-darwin-x64 using process.platform/process.arch and checks that copilot-runtime, runtime.node and the SDK entry point exist. Those checks do not establish that macOS can dynamically load the native binary. build/darwin/create-universal-app.ts preserves both architecture-specific SDK packages, but source inspection cannot verify their native dependency compatibility.
