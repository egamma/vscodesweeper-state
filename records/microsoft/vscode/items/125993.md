# Issue #125993 — Webview Service Worker Error in registration due to invalid document state

[https://github.com/microsoft/vscode/issues/125993](https://github.com/microsoft/vscode/issues/125993)

## Summary

This is a long-standing upstream Chromium bug where service worker registration intermittently fails with InvalidStateError. The issue remains unresolved on current main — no retry logic or mitigation has been added to the webview service worker registration path, and the root cause lives in Chromium's service worker lifecycle. With 134 upvotes and active cross-references from 2025–2026, it clearly still affects users.

## Change summary

Webview service worker registration intermittently fails with 'InvalidStateError: The document is in an invalid state', breaking all webview-based extensions until a restart or cache clear.

## Best solution

The best end state is either (1) Chromium fixes the underlying InvalidStateError race, or (2) VS Code adds resilience — a retry loop around `navigator.serviceWorker.register()` in `src/vs/workbench/contrib/webview/browser/pre/index.html` (line 256), or (3) the alternative webview-without-service-workers approach tracked in https://github.com/microsoft/vscode/issues/326331 lands. In the meantime, a retry with exponential backoff on registration failure would mitigate the impact for most users.
