# Issue #125993 — Webview Service Worker Error in registration due to invalid document state

[https://github.com/microsoft/vscode/issues/125993](https://github.com/microsoft/vscode/issues/125993)

## Summary

Long-standing upstream Chromium bug causing intermittent service worker registration failures in webviews. Still present on current main — no fix or retry logic has been added, and the error path in `index.html` remains unchanged. The issue is correctly labeled `upstream` and `chromium` and parked on `On Deck`; it should stay open as the canonical tracker for this class of failure.

## Change summary

Webview service worker registration intermittently fails with 'InvalidStateError: The document is in an invalid state', breaking all webview-based extensions until a restart or cache clear.

## Best solution

The root cause is in Chromium's service worker lifecycle (registration races when the document navigates or the sandbox attribute changes). The best end state is either an upstream Chromium fix, or a VS Code-side mitigation — retry logic around the `navigator.serviceWorker.register()` call in `src/vs/workbench/contrib/webview/browser/pre/index.html`, or the longer-term approach tracked in https://github.com/microsoft/vscode/issues/326331 (webviews without service workers). Keep this open as the canonical upstream tracker with 134 upvotes.
