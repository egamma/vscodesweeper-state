# Issue #186637 — Simple file dialog: support multi-select

[https://github.com/microsoft/vscode/issues/186637](https://github.com/microsoft/vscode/issues/186637)

## Summary

The simple picker still lacks multi-selection, including the reported Add Folder to Workspace scenario. The merged related PR preserves multiple results from Show Local, but does not implement selection of multiple remote files or folders within the simple dialog.

## Change summary

Support selecting multiple files or folders in one simple file dialog invocation.

## Best solution

Honor canSelectMany within SimpleFileDialog, including folder-only workspace selection, while preserving folder navigation and existing single-selection behavior. Agree on how folder selection and navigation coexist before implementing the interaction.

- **Fit:** aligned
- **Reason:** Providing equivalent selection capabilities across native and simple dialogs supports consistent workspace interactions and remote development.
- **Evidence:** Public values: “Simple, uniform UI and UI interactions.” Durable themes: Workbench & core UX and Remote development.

## Plan brief

- **Likely files:** `src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts`, `src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts`, `src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts`, `src/vs/workbench/browser/actions/workspaceCommands.ts`
- **Validation:** After agreeing on the interaction, add SimpleFileDialog tests asserting that canSelectMany returns both selected folder URIs and both selected file URIs, cancellation returns undefined, and single-selection and save behavior remain unchanged. Manually enable files.simpleDialog.enable, invoke Add Folder to Workspace, select two sibling folders in one invocation, and verify both are added; repeat for remote folders without Show Local.
- **Behavior:**

  > A simple open dialog whose caller enables canSelectMany should let the user select multiple eligible resources and return them together. In particular, Add Folder to Workspace must allow two folders to be added in one invocation without switching to a native dialog. Folder navigation must remain available, and single-selection, save, and cancellation behavior must remain unchanged. The interaction for selecting a folder separately from entering it needs agreement.
- **Trace:**

  > selectWorkspaceFolders() in src/vs/workbench/browser/actions/workspaceCommands.ts already requests multiple folders, and AbstractFileDialogService.showOpenDialogSimplified() forwards its options to SimpleFileDialog. In src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts, pickResource() does not enable QuickPick multi-selection, while onDidAccept() returns one URI and uses folder acceptance to navigate. This establishes the missing capability from source without executing the UI. https://github.com/microsoft/vscode/pull/300408 preserves native Show Local arrays only; https://github.com/microsoft/vscode/pull/300163 was closed unmerged and described file selection with navigation-only folders. Preserve those native-result semantics and all single-selection/save behavior. The remaining uncertainty is the user interaction that distinguishes choosing folders from navigating into them, not the array transport through the service.
- **Open decisions:**
  - In multi-folder mode, which mouse and keyboard interactions select a folder for the final result, and which navigate into it?
