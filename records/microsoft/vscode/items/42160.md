# Issue #42160 — Comment for erb files in rails 

[https://github.com/microsoft/vscode/issues/42160](https://github.com/microsoft/vscode/issues/42160)

## Summary

ERB-aware commenting requires template-specific semantics that belong in dedicated ERB language support rather than VS Code's generic Ruby configuration.

## Change summary

Make Toggle Line Comment produce valid ERB comments for Ruby expressions inside `<% %>` delimiters.

## Best solution

A dedicated ERB extension should register ERB language support and provide a template-aware commenting command that transforms `<% code %>` into `<%# code %>` without changing generic Ruby commenting.

## Vision fit

- **Fit:** rejected
- **Reason:** Rails-specific template behavior is well suited to an extension and would add niche language semantics to the lightweight core editor.
- **Evidence:** Public value: “The power lives in extensions.”

- **Proposed comment:**

  > Thanks for the request. VS Code currently associates `.erb` with generic Ruby, whose comment configuration only provides `#` and `=begin`/`=end`; the editor command does not understand ERB delimiters. Correctly turning `<% code %>` into `<%# code %>` therefore belongs in dedicated ERB language support, consistent with the maintainer guidance in https://github.com/microsoft/vscode/issues/53462#issuecomment-540046485.

## Auto-fix candidate

- **Auto-fixable:** no

## Evidence

- **current language contribution:** extensions/ruby/package.json associates `.erb` with the generic `ruby` language, while extensions/ruby/language-configuration.json defines only Ruby `#` and `=begin`/`=end` comments; there is no ERB-specific comment configuration.
- **editor behavior:** src/vs/editor/contrib/comment/browser/lineCommentCommand.ts resolves the language configuration at the beginning of the selected line and applies its generic comment token; it has no knowledge of ERB `<% %>` delimiters.
- **maintainer scope precedent:** In https://github.com/microsoft/vscode/issues/53462#issuecomment-540046485, a maintainer states that proper `.erb` support should come from dedicated language support rather than teaching generic HTML features about individual template languages.
- **related behavior:** The analogous Razor template-comment request remains classified as a feature request at https://github.com/microsoft/vscode/issues/44612, reflecting that template-aware commenting is additional language capability rather than broken generic commenting.
