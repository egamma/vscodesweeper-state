# Issue #47197 — [json] completion has bad replacement span, overwrites comment

[https://github.com/microsoft/vscode/issues/47197](https://github.com/microsoft/vscode/issues/47197)

## Summary

The default insertion mode now avoids the original destructive acceptance behavior, but the underlying JSON language-service replacement span still covers the entire parser-selected string literal. This remains a valid upstream heuristic improvement rather than a completed or duplicate issue.

## Change summary

Improve JSON value completion ranges so accepting a suggestion does not overwrite an adjacent commented-out value or produce invalid JSON.

## Best solution

Improve the overwrite-range heuristic in vscode-json-languageservice and add the reported malformed JSONC case as a completion regression test, while preserving VS Code's existing insertion-only range behavior.

- **VS Code mitigation:** extensions/json-language-features/client/src/jsonClient.ts converts that range into separate insertion and replacement ranges: insertion ends at the cursor, while replacement retains the full language-service range. `editor.suggest.insertMode` defaults to `insert` in src/vs/editor/common/config/editorOptions.ts.
- **shipped capability:** https://github.com/microsoft/vscode/commit/5f1b81b4976cc6a31d46befb828c0fe64ce47f49 added separate insert and replace proposals on 2019-12-02, mitigating the reported overwrite under the default mode without correcting the replacement heuristic itself.
