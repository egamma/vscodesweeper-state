# Issue #198903 — Changing actions.find's "when" to "editorFocus || !!editorIsOpen" creates a duplicate user shortcut that can't be removed

[https://github.com/microsoft/vscode/issues/198903](https://github.com/microsoft/vscode/issues/198903)

## Summary

This is the same invalid-When-expression defect already tracked by the older, open canonical issue: a shortcut displays a blank condition and cannot be edited, reset, or removed. Consolidate this report there, preserving its built-in-command reproduction with extensions disabled.

## Change summary

Entering `editorFocus || !!editorIsOpen` for `actions.find` creates a user shortcut that cannot be removed or reset through the Keyboard Shortcuts editor.

## Best solution

Track the remaining work in https://github.com/microsoft/vscode/issues/193521: shortcuts with invalid When expressions must remain recoverable through the editor rather than requiring manual JSON cleanup.

- **Current parser path:** In src/vs/platform/contextkey/common/contextkey.ts, Parser._term consumes one negation and rejects a second negation token; Parser.parse returns undefined on that parsing error. Consequently ContextKeyExpr.deserialize('editorFocus || !!editorIsOpen') returns undefined.
- **Current removal failure:** src/vs/workbench/services/keybinding/common/keybindingIO.ts deserializes the stored When expression, losing the invalid text in the resolved item. src/vs/workbench/services/preferences/browser/keybindingsEditorModel.ts then presents an empty When value. In src/vs/workbench/services/keybinding/common/keybindingEditing.ts, findUserKeybindingEntryIndex matches neither a truthy raw invalid `when` against an undefined resolved condition nor the both-defined branch, so removeUserKeybinding finds no entry; both remove and reset use this path.
