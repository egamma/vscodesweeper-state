# Issue #169800 — Outline View line wrap

[https://github.com/microsoft/vscode/issues/169800](https://github.com/microsoft/vscode/issues/169800)

## Summary

Keep this accepted feature request open: current Outline rendering still uses fixed-height, non-wrapping rows, and no existing wrapping setting covers the request. Its 27 upvotes and confirmed Backlog promotion support retaining it for design and implementation.

## Change summary

Provide an optional word-wrap mode so long Outline entries, including function signatures, remain readable within the view.

## Best solution

Support optional wrapping in the Outline view with row heights that accommodate the full label and signature details. Preserve the current compact default and breadcrumb behavior, and establish which Outline providers the option covers before implementation.

- **Behavior:**

  > Long Outline entries currently remain on one line, obscuring function signatures in narrow views. An optional wrapping mode should make the full supplied label and signature details readable within the available width, without overlapping adjacent entries. Resizing the view must preserve correct row layout and navigation. The current compact presentation should remain the default, and breadcrumbs should retain their existing behavior.
- **Trace:**

  > OutlinePane in src/vs/workbench/contrib/outline/browser/outlinePane.ts constructs a WorkbenchDataTree using each outline provider's delegate and renderers. For document symbols, DocumentSymbolVirtualDelegate.getHeight returns a constant 22, while DocumentSymbolRenderer.renderElement in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts applies nowrap and renders symbol.name plus symbol.detail through IconLabel. The configuration registrations in outline.contribution.ts expose no wrapping setting; horizontal scrolling and hover titles do not satisfy the request. DocumentSymbolOutline in documentSymbolsOutline.ts shares these rendering components between Outline and breadcrumbs, so preserve the latter's behavior. The trace establishes the document-symbol path, but does not establish variable-height support across every Outline provider. The accepted request is https://github.com/microsoft/vscode/issues/169800; no verified canonical or open implementation PR was found.
- **Open decisions:**
