# Issue #293233 — returning a `requestHandler` in `ChatSessionContentProvider#provideChatSessionContent` doesn't fire

[https://github.com/microsoft/vscode/issues/293233](https://github.com/microsoft/vscode/issues/293233)

## Summary

Confirmed from source: the `requestHandler` returned by `provideChatSessionContent` is wired into the session proxy in `mainThreadChatSessions.ts` but the chat service's `sendRequest` flow in `chatServiceImpl.ts` never consults it — it always dispatches to `chatAgentService.invokeAgent()`, which calls the participant's handler from `createChatParticipant`. The bug is still present on current `main`.

## Change summary

The `requestHandler` returned from `ChatSessionContentProvider#provideChatSessionContent` is never called; the participant handler from `createChatParticipant` is always invoked instead.

## Best solution

The chat service's request path (`chatServiceImpl.ts`, around the `invokeAgent` call at line ~1588) needs to check whether the resolved session carries a `requestHandler` and, if so, delegate to it instead of (or before falling through to) the agent service's `invokeAgent`. The session proxy in `mainThreadChatSessions.ts` already surfaces the handler; the gap is in the consumer.
