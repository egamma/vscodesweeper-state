# Issue #293233 — returning a `requestHandler` in `ChatSessionContentProvider#provideChatSessionContent` doesn't fire

[https://github.com/microsoft/vscode/issues/293233](https://github.com/microsoft/vscode/issues/293233)

## Summary

The reported dispatch gap remains visible in current source: session request handlers are constructed, but submitted messages follow the participant invocation path instead. Keep this team-authored bug open; the related API-consolidation request is newer and is not a qualifying duplicate.

## Change summary

Messages submitted inside a contributed chat session bypass the requestHandler returned by its content provider.

## Best solution

Make contributed-session request dispatch consistent with the supported API contract, so a supplied session handler is not silently ignored. Coordinate the callback contract with the related API-consolidation discussion while preserving ordinary participant behavior.
