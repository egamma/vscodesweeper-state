# Issue #205289 — `resolveCodeLens` invokes `validateRange` on disposed model

[https://github.com/microsoft/vscode/issues/205289](https://github.com/microsoft/vscode/issues/205289)

## Summary

The disposed-model failure remains reachable in current source: CodeLens resolution awaits an extension response, then validates its range without checking whether the model survived. Keep this team-authored issue open; no verified canonical duplicate or issue-referencing fix was found.

## Change summary

Prevent asynchronous CodeLens resolution from validating a range against a model disposed while resolution was pending.

## Best solution

Make the main-thread CodeLens bridge safely handle results arriving after model disposal while preserving range validation for live models and existing cancellation behavior. Pin the disposal race with a regression test in the existing language-feature bridge suite.
