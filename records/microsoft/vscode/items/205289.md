# Issue #205289 — `resolveCodeLens` invokes `validateRange` on disposed model

[https://github.com/microsoft/vscode/issues/205289](https://github.com/microsoft/vscode/issues/205289)

## Summary

Still reproduces on main: in `mainThreadLanguageFeatures.ts`, the `resolveCodeLens` callback calls `model.validateRange()` after the async proxy returns without checking if the model has been disposed, causing the logged error.

## Change summary

resolveCodeLens calls validateRange on a potentially disposed model after an async proxy call returns.

## Best solution

Add a `model.isDisposed()` guard before calling `model.validateRange(result.range)` at line 211 in `src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts`, returning `undefined` if the model is disposed.
