# Issue #122293 — Workspace Trust - Workspace file save location very slow to be added to workspace trust

[https://github.com/microsoft/vscode/issues/122293](https://github.com/microsoft/vscode/issues/122293)

## Summary

Keep open: multiple reporters confirmed a trust-dependent 60-second file-creation delay, but the current-main behavior has not been reverified and the extension-host stall remains undiagnosed. This is a team-authored, accepted Backlog bug, so the hard keep-open rule overrides the usual info-needed treatment for an unclear current reproduction.

## Change summary

Saving a workspace or creating a file after changing workspace trust can wait for the full file-participant timeout before completing.

## Best solution

Reproduce the trust transition on the current build, identify why the extension host does not complete the file-create participant request, and ensure workspace-file and ordinary file creation proceed without waiting for the 60-second timeout.

## Plan brief

- **Likely files:** `src/vs/workbench/services/workspaces/browser/abstractWorkspaceEditingService.ts`, `src/vs/workbench/api/browser/mainThreadFileSystemEventService.ts`, `src/vs/workbench/api/common/extHostFileSystemEventService.ts`, `src/vs/workbench/contrib/extensions/browser/extensionEnablementWorkspaceTrustTransitionParticipant.ts`
- **Validation:** On a current development build, follow the maintainer's folderA/folderB trust steps and then Save Workspace As; verify the workspace file is created promptly without showing `Running 'File Create' participants...` until the 60-second timeout, then repeat with File: New File.
- **Behavior:**

  > After a workspace trust transition, saving a workspace file and creating an ordinary file must complete promptly rather than waiting for the file-participant timeout. File-operation participants must still receive their normal events and edits. Acceptance requires running both the folderA/folderB Save Workspace As scenario and the grant-trust-then-File: New File scenario without a 60-second delay.
- **Trace:**

  > `AbstractWorkspaceEditingService.saveWorkspaceAs` creates the target `.code-workspace` file through `textFileService.create` before calling `trustWorkspaceConfiguration`. File creation invokes the main-thread participant in `mainThreadFileSystemEventService.ts`, which waits on `ExtHostFileSystemEventService.$onWillRunFileOperation` and cancels only at `files.participants.timeout`, currently 60000 ms. The issue discussion established that the renderer reached this wait while the extension host failed to respond after trust changes, but the extension-host cause was not diagnosed. Trust transitions can update extension enablement or restart extension hosts through `ExtensionEnablementWorkspaceTrustTransitionParticipant`; the uncertainty begins at the interaction between that lifecycle and delivery of the file-operation RPC. Preserve extension API participant semantics and keep non-trust file operations out of scope.
