## Summary

The reported nonce-free sequence still exposes a source-level defect: command execution replaces the explicitly supplied command with prompt-derived text while retaining high confidence. Keep this open; the related task issues do not own the multiline command-value problem.

## Change summary

Preserve the supplied multiline command text in terminal shell-execution events instead of including displayed continuation prompts.

## Best solution

Make shell-execution command values and confidence consistently reflect the explicit OSC 633 E payload, without changing nonce-based trust or prompt-display behavior. Cover both nonce-free and matching-nonce sequences, including the reporter's follow-up that adding nonce support did not resolve their case.
