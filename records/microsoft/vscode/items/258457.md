# Issue #258457 — Shell integration not working correctly for `Pseudoterminal`

[https://github.com/microsoft/vscode/issues/258457](https://github.com/microsoft/vscode/issues/258457)

## Summary

Confirmed bug on current main: the non-Windows pty heuristic's `handleCommandExecuted` unconditionally overwrites the command text from the promptInputModel buffer (which includes `... ` continuation prefixes), even when `setCommandLine()` already set a high-confidence, properly escaped command line via the `633;E` sequence. The confidence field is not overwritten, so it stays 'high' but the value is wrong.

## Change summary

When a Pseudoterminal sends a multi-line command via the 633;E escape sequence, the `execution.commandLine.value` in the `onDidStartTerminalShellExecution` event incorrectly includes visual continuation prompt prefixes (`... `) from the buffer instead of using the properly escaped command text.

## Best solution

Guard line 575 of `commandDetectionCapability.ts` (the non-Windows `handleCommandExecuted` in the pty heuristics class) so it only overwrites `currentCommand.command` from the `promptInputModel` when `commandLineConfidence` is not already `'high'`. This mirrors the existing guard in the constructor's `onCommandExecuted` handler (line 91).
