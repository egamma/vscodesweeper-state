The OSC 52 clipboard write still stops at in-memory storage on current main. Keep this open while the two existing fix proposals are reviewed; terminal-input already routes it correctly.

## Change summary

In src/vs/platform/clipboard/browser/clipboardService.ts:130-140, that truthy type stores the payload in mapTextToType and returns before navigator.clipboard.writeText or the fallback. This conclusively explains the unchanged system clipboard without executing the checkout.
- **Workbench delegation preserves the defect:** src/vs/workbench/services/clipboard/browser/clipboardService.ts:31-37 forwards the explicit 'clipboard' type unchanged to the base browser service. Typed reads also delegate to the in-memory path, explaining why an OSC 52 query can return the payload despite the failed system write.
