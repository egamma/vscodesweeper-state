# Issue #318254 — OSC52 unsupported in `code serve-web`

[https://github.com/microsoft/vscode/issues/318254](https://github.com/microsoft/vscode/issues/318254)

## Summary

Still reproduces on main: the BrowserClipboardService short-circuits writeText/readText to in-memory storage when a `type` parameter is provided, which prevents OSC52 clipboard sequences from reaching the system clipboard in `code serve-web`. An open PR (#318255) by the reporter addresses this.

## Change summary

OSC52 escape sequences in the integrated terminal fail to write to the system clipboard when running under `code serve-web`, because the browser clipboard service treats all typed clipboard operations as in-memory only.

## Best solution

Review and land (or close with feedback) the author's open PR at https://github.com/microsoft/vscode/pull/318255, which allows `type: 'clipboard'` to fall through to the system clipboard path in `src/vs/platform/clipboard/browser/clipboardService.ts`. The fix needs careful review since the in-memory-only guard was intentional — the reviewer should confirm that letting `type: 'clipboard'` through doesn't break other typed clipboard consumers.
