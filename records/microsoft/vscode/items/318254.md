# Issue #318254 — OSC52 unsupported in `code serve-web`

[https://github.com/microsoft/vscode/issues/318254](https://github.com/microsoft/vscode/issues/318254)

## Summary

The OSC 52 clipboard-write defect remains in current main: the web clipboard service stores the payload in memory instead of updating the system clipboard. Keep this open while the two linked implementation candidates are reviewed.

## Change summary

OSC 52 writes in the code serve-web terminal should update the system clipboard rather than an internal text map.

## Best solution

Review and land an appropriate fix from https://github.com/microsoft/vscode/pull/318255 or https://github.com/microsoft/vscode/pull/334287 so system-clipboard targets reach the browser clipboard API, while preserving primary-selection handling, desktop behavior, and browser permission requirements.

## Evidence

- **Exact failing path on current main:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:341-354 registers the clipboard addon and maps OSC 52 target c to writeText(text, 'clipboard'). src/vs/platform/clipboard/browser/clipboardService.ts:130-140 treats every nonempty type as an in-memory target and returns before navigator.clipboard.writeText or the execCommand fallback. The reporter's printf sequence therefore cannot update the system clipboard through this path.
- **Web service wiring and desktop distinction:** src/vs/workbench/services/clipboard/browser/clipboardService.ts registers the browser implementation for IClipboardService and forwards typed writes to the affected base implementation. src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts:34-37 instead forwards the clipboard target to the native host; this is a VS Code web implementation defect, not an extension-owned or upstream limitation.
- **Confirmed reproduction and workaround:** https://github.com/microsoft/vscode/issues/318254#issuecomment-5573909489 confirms reproduction on VS Code 1.135.0 web in Chrome on Linux, demonstrates that an OSC 52 query returns the internally stored payload, and reports that neither browser clipboard write mechanism is invoked. Shift-drag selection followed by Ctrl+Shift+C, or terminal.integrated.copyOnSelection, is a workaround rather than support for programmatic OSC 52 writes.
