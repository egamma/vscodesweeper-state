# Issue #334837 — Main process leaks every terminal's pty output: `ProxyChannel.fromService(PtyHostService)` buffers `onProcessData` via `Event.buffer` for a `localPty` listener that never attaches

[https://github.com/microsoft/vscode/issues/334837](https://github.com/microsoft/vscode/issues/334837)

## Summary

Confirmed via checkout: `ProxyChannel.fromService(ILocalPtyService, disposables)` at src/vs/code/electron-main/app.ts:1447 has no `unbufferedEvents` option, so `Event.buffer` (src/vs/base/parts/ipc/common/ipc.ts:1164) eagerly buffers `onProcessData` and friends forever since renderers get pty data over the direct MessagePort and never call `listen()` on `localPty` — matches the exact `unbufferedEvents` precedent already used for `onDidBlurMainWindow` at app.ts:1412. An open PR (#334913) already targets this exact issue with `Fixes #334837`, so per policy the issue stays open pending that PR's review/merge rather than being closed now.

## Change summary

The main process's `localPty` ProxyChannel buffers every terminal's pty output events forever because no renderer ever calls `listen()` on that channel (pty data flows over a direct MessagePort instead), causing unbounded heap growth and eventual OOM crash of the main process.

## Best solution

Land https://github.com/microsoft/vscode/pull/334913, which marks the seven per-process pty events (onProcessData, onProcessReady, onProcessExit, etc.) as `unbufferedEvents` on the `localPty` channel while preserving buffering for the `onPtyHost*` events — matching the existing `unbufferedEvents: ['onDidBlurMainWindow']` precedent in the same file.
