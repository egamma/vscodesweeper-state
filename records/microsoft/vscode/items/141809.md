# Issue #141809 — Closing dirty custom document calls revert after the view is disposed before onDidDispose is called

[https://github.com/microsoft/vscode/issues/141809](https://github.com/microsoft/vscode/issues/141809)

## Summary

Still reproduces on main: when a dirty custom editor is closed with 'Don't Save', the editorGroupView calls revert() on the editor input (line 1865 of editorGroupView.ts), but the webview view may already be destroyed before the extension receives onDidDispose — causing the extension's revertCustomDocument to attempt communication with a dead webview.

## Change summary

Closing a dirty custom editor calls revert on the document after the view is disposed but before onDidDispose fires, causing extensions to fail when they try to update the destroyed webview.

## Best solution

The close flow in editorGroupView.ts (DONT_SAVE case at line 1861) should either ensure onDidDispose fires before revert reaches the extension, or the custom editor model should guard revert calls when the view is already gone — likely in the customEditorInput.ts revert method or in the extHostCustomEditors $revert handler.
