# Issue #146815 — Can't type in Cmd+` in Keyboard Shortcut UI

[https://github.com/microsoft/vscode/issues/146815](https://github.com/microsoft/vscode/issues/146815)

## Summary

Keep open as an upstream macOS/Electron limitation: native menu accelerators consume Cmd+` before VS Code's shortcut-recording widget receives the keyboard event. Current main still installs resolved native keybindings as Electron menu accelerators.

## Change summary

The Keyboard Shortcuts editor cannot capture Cmd+` on macOS when that combination is handled as a native menu accelerator.

## Best solution

Determine with Electron whether native accelerator dispatch can be suppressed while VS Code's keybinding recorder has focus, without changing normal native-menu shortcut behavior. If the platform offers no safe interception mechanism, retain the JSON workaround and document the limitation.

## Evidence

- **confirmed root cause:** A VS Code maintainer traced the behavior in https://github.com/microsoft/vscode/issues/146815#issuecomment-1168770231: once Cmd+` is displayed on the native macOS menu, the OS invokes that menu action directly and VS Code does not receive the keyboard event for capture.
- **current source:** src/vs/workbench/electron-browser/parts/titlebar/menubarControl.ts resolves menu keybindings through getElectronAccelerator(), while src/vs/platform/menubar/electron-main/menubar.ts applies a native binding as MenuItemConstructorOptions.accelerator in withKeybinding().
- **reporter confirmation:** https://github.com/microsoft/vscode/issues/146815#issuecomment-1089558522 confirms that the JSON-defined shortcut executes successfully, but the graphical recorder either invokes Toggle Terminal or records only Cmd.
