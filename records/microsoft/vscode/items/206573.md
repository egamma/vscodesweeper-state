# Issue #206573 — Add "discover" action in the test tree

[https://github.com/microsoft/vscode/issues/206573](https://github.com/microsoft/vscode/issues/206573)

## Summary

The discoverability gap remains: discovering tests still hides the welcome actions, and the existing refresh and profile commands do not expose those setup contributions again. Keep this accepted, team-authored request open for a focused UX design.

## Change summary

Provide persistent access to extension-contributed test setup actions after the Test Explorer contains tests.

## Best solution

Give users a persistent Test Explorer entry point to the applicable extension-contributed setup actions without clearing or replacing discovered tests. Decide how those actions are presented while preserving their contribution conditions.

- **Behavior:**

  > Users must be able to find applicable extension-contributed test setup actions after one or more tests have been discovered. Access must not require deleting tests or resetting the workspace. - **Trace:**

  > TestingExplorerView.shouldShowWelcome() and its view model's reevaluateWelcomeState() in src/vs/workbench/contrib/testing/browser/testingExplorerView.ts restrict the welcome surface to an empty, idle collection. ViewWelcomeController in src/vs/workbench/browser/parts/views/viewPane.ts retrieves welcome descriptors from the views registry and removes the surface when the delegate disables it. Existing actions in src/vs/workbench/contrib/testing/browser/testExplorerActions.ts refresh tests, configure run profiles, or search for extensions; they do not recover the contributed setup actions. Core welcome registrations are in src/vs/workbench/contrib/testing/browser/testing.contribution.ts. The remaining uncertainty is the user-facing presentation and access to applicable contributions outside the empty state; preserve normal welcome behavior for other views and do not equate setup access with rerunning discovery. https://github.com/microsoft/vscode/issues/244814 concerns a separate hidden-test API request.
- **Open decisions:**
