# Issue #342001 — Claude agent harness ignores GitHub Copilot account preference when multiple GitHub accounts are signed in

[https://github.com/microsoft/vscode/issues/342001](https://github.com/microsoft/vscode/issues/342001)

## Summary

Thanks for the detailed report. The Agent Host auth path appears to pick a GitHub session without consulting the 'Manage Extension Account Preferences' choice for GitHub Copilot, which fits the reported symptom. Keeping this open for a maintainer to decide how the preference should apply.

## Change summary

With two GitHub accounts signed in, the Claude harness model picker shows no Copilot models because it does not use the account selected for GitHub Copilot.

## Best solution

Make the Agent Host's GitHub session resolution honor the Copilot extension account preference, so the Claude harness picks the same account as the Local harness.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts`
- **Validation:** A unit test for agentHostAuth session resolution with two GitHub sessions, where the preferred account is selected. It should fail before the change and pass after.
- **Behavior:**

  > With two GitHub accounts signed in and the Copilot account preference set to account B, the Claude harness resolves its GitHub session for account B and lists Copilot-routed Claude models. Single-account behavior is unchanged.
- **Trace:**

  > agentHostAuth.ts resolves sessions via authenticationService.getSessions and picks the first candidate, with no account option unless a preferredSessionId is supplied. The Local harness honors the extension account preference through a different path, so that path is the reference. Still unestablished: where the Claude harness's token request originates and how the extension account preference can be read from the Agent Host layer.
- **Open decisions:**
  - Should the Agent Host read the Copilot extension account preference directly, or should the Copilot extension's chosen session be passed to it?

## Evidence

- **session resolution:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts (~lines 410-440) calls authenticationService.getSessions(providerId, scopes, { authorizationServer }) and takes the first candidate session. It passes no account preference unless a preferredSessionId is supplied. I did not trace the full call chain, so this is not a confirmed root cause.
- **reporter workaround:** Signing out of the non-Copilot account makes the models appear, which is consistent with the wrong account being chosen.
