## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`
- **Validation:** On Windows with MSVC installed, run the published shell task from VS Code launched outside the Developer Command Prompt. Build a minimal C/C++ program with a space in the basename, then with a space in the parent directory, and verify exit code 0 and the expected executable. Also check a path without spaces, a Visual Studio installation path containing parentheses, and an existing custom cmd.exe task that already supplies outer quotes.
- **Behavior:**

  > The documented MSVC shell task must initialize the Visual Studio environment and compile the active source file even when its basename or parent directory contains spaces. The VsDevCmd.bat path and the compiler's source/output paths must retain their intended argument boundaries. Acceptance includes successful builds for spaced and unspaced paths without requiring users to rename files or switch shells. Existing custom cmd.exe tasks that already provide command wrapping must continue to work.
- **Trace:**

  > TerminalTaskSystem._buildShellCommandLine in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts quotes spaced task arguments but wraps the command for cmd.exe only when both commandQuoted and argQuoted are true. The reported 'cl.exe' command is unquoted, while the quoted VsDevCmd.bat prefix lives separately in shellOptions.args; the launch assembly subsequently joins that prefix and commandLine without complete-command wrapping. This matches the reported terminal command and cmd.exe's documented quote-stripping rules. The live tutorial still supplies the same configuration, and https://github.com/microsoft/vscode/issues/158615#issuecomment-3436251149 provides an outer-quote workaround. The uncertainty is whether the documented configuration should explicitly own this wrapping or the task runner should normalize custom cmd.exe prefixes. Preserve other shells, explicit quoting, and already-wrapped custom command lines; https://github.com/microsoft/vscode/issues/260534 demonstrates the compatibility risk of indiscriminate wrapping. A documentation change would belong in the separate microsoft/vscode-docs repository, not this checkout.
- **Open decisions:**
  - Should explicit custom cmd.exe shell arguments remain caller-owned raw command fragments, with the tutorial corrected accordingly, or should VS Code guarantee complete-command wrapping for this prefix-plus-task configuration?

## Evidence

- **Current source reproduces the command construction:** In src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1628-1723, _buildShellCommandLine quotes the spaced source/output arguments but adds cmd.exe outer quotes only when commandQuoted && argQuoted. For the supplied command 'cl.exe', commandQuoted is false. Lines 1269-1334 then prepend the custom shell arguments and join everything with spaces, producing /C "C:/Program Files/.../VsDevCmd.bat" && cl.exe ... "c:\Test\test file.c" without an enclosing quote pair around the complete command.
- **Shell parsing explains the observed failure:** https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/cmd documents that /C preserves quotation marks only under restrictive conditions, including exactly one quote pair; otherwise the opening and closing quotes are stripped. The additional compiler-path quote pairs trigger this behavior in the command generated above. This was traced from source and documented shell semantics; no Windows execution was performed.
- **Current documentation still contains the trigger:** https://code.visualstudio.com/docs/cpp/config-msvc#_run-vs-code-outside-the-developer-command-prompt still specifies custom shell args ['/C', quoted VsDevCmd.bat path, '&&'], command 'cl.exe', and separate source/output arguments, without the outer command quotes. Updating the Visual Studio version in the example has not removed the reported quoting gap.
- **Discussion and workarounds:** https://github.com/microsoft/vscode/issues/158615#issuecomment-1256264581 supplies full failing configurations and output after the maintainer's quoting suggestion. https://github.com/microsoft/vscode/issues/158615#issuecomment-1898599401 describes a PowerShell-based workaround. https://github.com/microsoft/vscode/issues/158615#issuecomment-3436251149 reports success after adding an outer quote pair across the shell prefix and task arguments.
