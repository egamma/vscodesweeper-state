# Issue #331546 — Remote tunnel service status client can take over tunnel ownership

[https://github.com/microsoft/vscode/issues/331546](https://github.com/microsoft/vscode/issues/331546)

## Summary

Keep open: current source still allows the desktop service-status client to become the tunnel host after a service disconnect, and reports the requested name rather than the service's actual name. The linked fixing PR was closed without merging.

## Change summary

Make the desktop service-status process attach-only across service restarts, report the running service's identity, and preserve in-session hosting when service installation fails.

## Best solution

Keep service-status attachment separate from acquire-or-host behavior so service restarts cannot transfer ownership to the desktop child. Preserve status/log streaming, report the singleton's emitted name, and retain the existing named hosting fallback after installation failure.
