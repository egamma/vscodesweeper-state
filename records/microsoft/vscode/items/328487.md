# Issue #328487 — Improve pre-tool agent hooks to provide more MCP-specific information

[https://github.com/microsoft/vscode/issues/328487](https://github.com/microsoft/vscode/issues/328487)

## Summary

The requested MCP identity is genuinely absent from the current hook contract, leaving policy hooks unable to reliably distinguish MCP servers. This should remain open as a focused agent-hook feature request.

## Change summary

Provide PreToolUse hooks with structured MCP server identity and transport information instead of only the encoded tool name.

## Best solution

Extend the existing tool-hook payload with optional structured MCP source metadata, passing it from the selected LanguageModelToolInformation into ChatHookService. Include stable server label/name and a sanitized transport descriptor while excluding sensitive headers and environment values.

- **transport definitions:** src/vscode-dts/vscode.d.ts defines MCP HTTP URI and stdio command details, but also sensitive headers and environment fields that require an explicit sanitization boundary.
- **consumer evidence:** https://github.com/obot-platform/obot/issues/7426 is open and states that enforcement cannot map the current hook payload back to the configured MCP URL or command.
