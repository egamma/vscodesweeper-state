- **Current recorder path:** src/vs/workbench/contrib/preferences/browser/keybindingWidgets.ts:73–137 routes keydown events through StandardKeyboardEvent and keybindingService.resolveKeyboardEvent, then prints getUserSettingsLabel(). An incomplete modifier chord is replaced by the next event; this does not establish why the reporter's keypad event was absent or misclassified.
- **Windows event mapping:** src/vs/base/browser/keyboardEvent.ts:11–48 derives the key from the browser keyCode. src/vs/workbench/services/keybinding/common/windowsKeyboardMapper.ts:413–417 constructs a chord from that normalized key and its modifiers. src/vs/base/common/keyCodes.ts:597 explicitly maps browser keyCode 102 to Numpad6. The reported physical-key event sequence cannot be inferred from these mappings alone.
- **Existing keypad support is not a fix:** src/vs/workbench/services/keybinding/test/node/windowsKeyboardMapper.test.ts contains a 'resolveKeybinding Ctrl+NUMPAD_0' test expecting 'ctrl+numpad0'. This demonstrates keypad binding support, but does not exercise recording Ctrl+Shift+Numpad6 on Windows.
- **Intervening change:** https://github.com/microsoft/vscode/commit/fa6217ecb59b750bf9fbf2644cc006b327f84e7b changes composing keystrokes to KEY_IN_COMPOSITION in StandardKeyboardEvent. Its scope is IME composition, not the reported keypad combination, so it is not evidence of completion.
- **Canonical search:** Searches for numpad, Ctrl/Shift combinations, and numeric-keypad terminology did not establish an open canonical for this recording failure. https://github.com/microsoft/vscode/issues/205934 is open but concerns ordinary Numpad2/Numpad3 text input doing nothing, not modifier-only shortcut recording; shared keypad terminology does not prove the same defect.
- **Secondary navigation request:** src/vs/editor/common/config/editorOptions.ts defines editor.gotoLocation.alternativeDefinitionCommand with default editor.action.goToReferences and editor.gotoLocation.multipleReferences with default 'peek'. These support related reference navigation, but the alternative command is conditional on Go to Definition resolving to the current location and does not satisfy unconditional Ctrl+click-to-references.
