## Summary

Keep this report open and move it to the Remote WSL tracker. The discussion documents a surviving Windows daemon returning an unusable endpoint after WSL shuts down, with Reload Window failing to restart the missing remote server.

## Change summary

Recover Remote WSL connections when the Windows daemon survives but its Linux-side VS Code Server session has disappeared.

## Best solution

Remote WSL should detect an unusable reused session and bootstrap a working server once the distribution becomes available, coordinating recovery across connected windows without treating every transient socket failure as a terminated session.

## Evidence

- **Original endpoint failure:** https://github.com/microsoft/vscode/issues/308839 includes repeated resolver responses for Windows endpoint 127.0.0.1:59279, ECONNREFUSED from the forwarded Linux port 43997, no listener on that Linux port, and an empty response from the Windows endpoint's /version route. These observations support an unusable reused session, not merely a generic WebSocket error.
- **Confirmed recovery failure:** https://github.com/microsoft/vscode/issues/308839#issuecomment-5647603530 documents a WSL update shutting down Ubuntu while the original Windows wslDaemon.js process and listener survived. Both windows continued resolving the original endpoint after Reload Window; no main remote server was running, and restarting VS Code completely restored connectivity. This is a captured incident, not a controlled reproduction or a confirmed code-level root cause.
