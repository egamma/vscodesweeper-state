# Issue #270437 — Bad terminal history navigation after terminal clear command

[https://github.com/microsoft/vscode/issues/270437](https://github.com/microsoft/vscode/issues/270437)

## Summary

Thanks for the detailed repro. This is a known conpty/PSReadLine history-redraw glitch after `Terminal: Clear`; a maintainer already pointed at `terminal.integrated.windowsUseConptyDll` as a workaround, with mixed reports (helps GitBash always, PowerShell only sometimes depending on build), and the default for that setting has since flipped to `true` on main. Nobody has confirmed whether the PowerShell case still reproduces on a current build, so this needs a fresh confirmation rather than a close.

## Change summary

After running `Terminal: Clear` and then navigating command history with the up arrow, previous commands (especially multi-line ones in PowerShell) render split across the wrong lines in the terminal view.

## Best solution

Get a fresh repro check from the reporters on a current build (where `windowsUseConptyDll` now defaults to `true`) to see whether the PowerShell case is still broken; if it is, the remaining work likely sits in node-pty/conpty's cursor-reflow handling (see `reflowCursorLine` wiring in terminalInstance.ts) rather than in VS Code's own terminal code.
