# Issue #205207 — Adding support for the uniqueKeys vocabulary in settings.json validation

[https://github.com/microsoft/vscode/issues/205207](https://github.com/microsoft/vscode/issues/205207)

## Summary

The requested property-based uniqueness constraint remains distinct from the existing uniqueItems validation. Keep this accepted Backlog request open; no verified older canonical or implementation was found.

## Change summary

Support uniqueKeys in extension-contributed configuration schemas so settings.json can flag repeated property values across otherwise different array objects.

## Best solution

Have the JSON language tooling owners decide whether to support this nonstandard vocabulary, with validation implemented in vscode-json-languageservice and exposed through configuration schemas. Preserve the existing whole-item semantics of uniqueItems.

## Evidence

- **Requested semantics:** https://github.com/microsoft/vscode/issues/205207 requests uniqueness of selected properties across array objects, not uniqueness of complete objects. It has six upvotes, no comments or linked implementation, and the Backlog milestone.
- **Vocabulary definition:** https://docs.json-everything.net/schema/vocabs/array-ext/ defines uniqueKeys as a non-empty array of JSON Pointers whose ordered value combinations must differ across items, distinguishing missing values from null. This is an extension vocabulary rather than the standard uniqueItems keyword.
- **Existing-capability check:** src/vs/base/common/jsonSchema.ts exposes uniqueItems but not uniqueKeys. extensions/json-language-features/server/src/jsonServer.ts:400-411 delegates diagnostics to languageService.doValidation; its server/package.json depends on vscode-json-languageservice ^6.0.0-next.4. No configuration or command delivering the requested constraint was identified.
- **Validator implementation:** Read-only inspection of https://github.com/microsoft/vscode-json-languageservice/blob/main/src/parser/jsonParser.ts found uniqueItems comparing complete item values with equals(value, values[j]), and no uniqueKeys handling. Objects sharing a selected property but differing elsewhere therefore are not covered by that existing check.
