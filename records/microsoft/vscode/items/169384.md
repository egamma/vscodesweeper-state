# Issue #169384 — Accessibility detection on Windows is off

[https://github.com/microsoft/vscode/issues/169384](https://github.com/microsoft/vscode/issues/169384)

## Summary

This is an upstream Chromium/Electron tracking issue about false-positive screen reader detection on Windows. The issue remains relevant as the accessibility detection path (`app.on('accessibility-support-changed')` in `src/vs/code/electron-main/app.ts:466`) still relies entirely on Chromium's signal, and no VS Code-side mitigation or telemetry for this specific problem has landed on main.

## Change summary

Chromium's accessibility detection on Windows falsely reports a screen reader is attached, causing VS Code to enable accessibility mode unnecessarily.

## Best solution

Verify whether Electron 42 (Chromium 134+) has improved Windows accessibility detection compared to Electron 19. If false positives persist, implement the proposed mitigations: add telemetry to measure the false-positive rate and consider a platform-specific fallback for Windows. The relevant code path is `src/vs/code/electron-main/app.ts` (main process listener) and `src/vs/workbench/electron-browser/window.ts` (renderer handler).
