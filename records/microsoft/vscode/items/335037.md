# Issue #335037 — Agent Host file tools do not support extension-registered filesystems

[https://github.com/microsoft/vscode/issues/335037](https://github.com/microsoft/vscode/issues/335037)

## Summary

Real architectural gap with maintainer engagement already underway; the reporter has now supplied the requested scenario detail (a FileSystemProvider-backed virtual notebook workspace), so this shouldn't be left to the info-needed auto-close — it should stay open as a feature request pending a design decision from the Agent Host team.

## Change summary

Agent Host file/notebook tools (e.g. getNotebookSummary) assume native OS paths and cannot read/edit resources served by an extension-registered FileSystemProvider, even though VS Code's own filesystem APIs can access them.

## Best solution

A maintainer decision is needed on whether Agent Host client-side tools should route non-native-scheme URIs through IFileService/notebook APIs instead of assuming a native path — src/vs/platform/agentHost/common/agentHostFileSystemService.ts and the shared tool host (src/vs/platform/agentHost/node/shared/agentServerToolHost.ts) look like the right area to start; roblourens flagged real complexity (no working shell tool for virtual workspaces), so this is a scoped design discussion, not a quick fix.
