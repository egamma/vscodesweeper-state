# Issue #335037 — Agent Host file tools do not support extension-registered filesystems

[https://github.com/microsoft/vscode/issues/335037](https://github.com/microsoft/vscode/issues/335037)

## Summary

Confirmed in the current source: Agent Host file tooling assumes native `file://` paths and doesn't fall back to VS Code's filesystem/editing abstractions for extension-registered filesystem providers — a real, well-diagnosed architectural gap worth routing to the agent-host area.

## Change summary

Agent Host (Codex and potentially other providers) file read/edit tools cannot operate on resources served by extension-registered filesystem providers, only on native OS paths.

## Best solution

Have Agent Host file tools use IFileService/ITextFileService-style abstractions (or a bridge to them) for non-`file://` workspace URIs, falling back to native fs only for local paths; likely touches src/vs/platform/agentHost/node/agentHostWorkspaceFiles.ts and the per-provider tool implementations (e.g. src/vs/platform/agentHost/node/codex/codexAgent.ts) which currently shell out to Node's `fs`/`child_process` directly.
