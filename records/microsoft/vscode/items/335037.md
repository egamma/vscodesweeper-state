# Issue #335037 — Agent Host file tools do not support extension-registered filesystems

[https://github.com/microsoft/vscode/issues/335037](https://github.com/microsoft/vscode/issues/335037)

## Summary

The reporter confirmed a concrete virtual-workspace failure, but the item is team-authored and the discussion still needs an explicit product decision about how Agent Host providers should handle resources without native filesystem paths. Keep it open while the Agent Host owner evaluates the clarified scenario.

## Change summary

Agent Host tools such as getNotebookSummary fail on notebooks exposed through an extension-registered FileSystemProvider, despite VS Code APIs being able to access them.

## Best solution

Preserve non-file resource URIs across the Agent Host boundary and execute VS Code-side file and notebook operations through VS Code resource abstractions, while retaining provider-native filesystem and shell tools for local resources. The owner should first define which standard tools must support virtual resources and what capability limitations are exposed to providers that fundamentally require native paths.
