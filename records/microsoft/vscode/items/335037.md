# Issue #335037 — Agent Host file tools do not support extension-registered filesystems

[https://github.com/microsoft/vscode/issues/335037](https://github.com/microsoft/vscode/issues/335037)

## Summary

Real architectural gap: Codex (and likely other) Agent Host providers run as separate native processes that operate on OS file paths directly, so they can't reach extension-registered virtual filesystems the way VS Code's own file service can. Worth routing to the agent host area, but too early and unconfirmed by other reports to close or classify definitively.

## Change summary

Agent Host file-editing tools (e.g. Codex) require native OS paths and can't read/edit resources served by extension-registered filesystem providers (non-`file:` URIs).

## Best solution

Extend Agent Host tool routing so non-native workspace URIs go through the existing AHP `resource*`/reverse-RPC surface (already used for `vscode-agent-client:` client-hosted files in src/vs/platform/agentHost/node/shared/agentServerToolHost.ts and covered by src/vs/platform/agentHost/test/node/e2e/suites/clientHostedFilesystemSuite.ts) instead of assuming every workspace resource has a native path — likely touching how Codex/Claude tool hosts resolve workspace roots before invoking their native file tools.
