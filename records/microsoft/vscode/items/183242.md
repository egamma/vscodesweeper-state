# Issue #183242 — Merge editor commands should use accessible descriptor 

[https://github.com/microsoft/vscode/issues/183242](https://github.com/microsoft/vscode/issues/183242)

## Summary

The requested command-label improvement remains missing: conflict-toggle commands still identify inputs as Left and Right. Keep this deliberately separated, team-authored request open; the related accessibility tracking issues do not establish a duplicate.

## Change summary

Give merge-editor commands non-positional, accessible input descriptors that remain accurate across merge, rebase, and stash workflows.

## Best solution

Use consistent, non-positional descriptors for merge-editor input commands and their accessibility help, preserving existing command IDs and actions. A maintainer should settle whether generic Input 1/Input 2 titles suffice or context-specific descriptive commands are needed.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/mergeEditor/browser/commands/commands.ts registers merge.toggleActiveConflictInput1 and merge.toggleActiveConflictInput2 with titles 'Toggle Current Conflict from Left' and 'Toggle Current Conflict from Right'. The comparison commands already use Input 1/Input 2, while merge.acceptAllInput1 and merge.acceptAllInput2 retain mixed Incoming/Current and Left/Right terminology. These actions are registered in browser/mergeEditor.contribution.ts.
- **Descriptors must accommodate actual input roles:** extensions/git/src/commands.ts labels a stash input 'Stashed Changes', reverses Current/Incoming input ordering during rebase, and supplies Workspace/Worktree titles for worktree merges. A universal Left=Incoming and Right=Current naming scheme would not accurately describe all callers.
