# Issue #259978 — start must be before end

[https://github.com/microsoft/vscode/issues/259978](https://github.com/microsoft/vscode/issues/259978)

## Summary

Still reproduces on main: GhostText.renderForScreenReader throws 'start must be before end' when the line text is shorter than the ghost text parts' column positions, causing TextEdit.apply to construct an invalid range.

## Change summary

Screen reader rendering of inline completions throws when the editor line is shorter than the ghost text parts' column offsets.

## Best solution

Guard `renderForScreenReader` in `src/vs/editor/contrib/inlineCompletions/browser/model/ghostText.ts` so that part columns exceeding the line text length are clamped or the edit is skipped, preventing `rangeFromPositions` from receiving start > end. A unit test should construct a `GhostText` with a part column beyond the line text length and call `renderForScreenReader`.
