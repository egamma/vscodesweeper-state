# Issue #326966 — [Markdown Editor (experimental)] AI plugins cannot recognize active file context

[https://github.com/microsoft/vscode/issues/326966](https://github.com/microsoft/vscode/issues/326966)

## Summary

The defect is present on main: the experimental editor is a custom text editor, while Copilot only derives active-file context from a `TextEditor` and ignores custom-editor tabs. Route this to the Markdown editor and Chat owners.

## Change summary

AI integrations fail to infer the active Markdown document when it is open in the experimental Markdown editor.

## Best solution

Teach Copilot's tabs/document-context abstraction to resolve the document URI from an active `TabInputCustom`, then construct document context without requiring a `TextEditor`; preserve normal selection-aware behavior for standard editors. The experimental Markdown editor should expose consistent active-resource context without changing the established meaning of `window.activeTextEditor`.

## Evidence

- **custom editor implementation:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts registers `MarkdownEditorProvider` as a `vscode.CustomTextEditorProvider`, retaining a real `TextDocument` but not creating a `TextEditor`.
- **missing custom-tab handling:** extensions/copilot/src/platform/tabs/vscode/tabsAndEditorsServiceImpl.ts:56-78 falls back only to visible text editors, while `_asTabInfo` at lines 97-107 handles `TabInputText`, notebook, and diff inputs but omits `TabInputCustom` even though it exposes a URI.
- **context loss:** extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts:121 passes only `tabsAndEditorsService.activeTextEditor`; extensions/copilot/src/extension/prompt/node/documentContext.ts:84-86 consequently creates no document context when the custom editor is active.
- **available API:** src/vscode-dts/vscode.d.ts defines `TabInputCustom.uri`, and src/vs/workbench/api/common/extHostVariableResolverService.ts already uses custom-editor tab URIs when resolving the active resource, demonstrating the supported lookup pattern.
