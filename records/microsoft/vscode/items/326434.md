# Issue #326434 — Add a supported non interactive CLI for provisioning BYOK model secrets into VS Code SecretStorage

[https://github.com/microsoft/vscode/issues/326434](https://github.com/microsoft/vscode/issues/326434)

## Summary

Keep open: current source supports BYOK secret references and programmatic model-group creation, but neither provides the requested supported administrative CLI with stable identifiers and secure input. The related requests do not own this specific provisioning contract; credential handling and storage fallbacks require human review.

## Change summary

Provide supported non-interactive creation, rotation, and removal of BYOK secrets through a secure input channel, with stable configuration references and documented storage guarantees.

## Best solution

Have the language-model and secret-storage owners decide a supported administrative provisioning contract covering the target user/store, stable identifiers, automation exit codes, and unavailable-encryption behavior. Any accepted interface should use the existing BYOK secret-resolution backend without routing credentials through ordinary CLI arguments or temporary editor-input files.
