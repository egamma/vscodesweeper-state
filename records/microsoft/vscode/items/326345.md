# Issue #326345 — SCM Changes view does not restore repository/group collapsed state after reload

[https://github.com/microsoft/vscode/issues/326345](https://github.com/microsoft/vscode/issues/326345)

## Summary

The main SCM Changes tree still loses saved collapse choices on current main. The source confirms both the expanded-default fallback and the loss of restoration context for repositories or groups discovered after initialization.

## Change summary

Restore mixed repository and resource-group expansion states in the main Source Control Changes view across window reloads and application restarts.

## Best solution

Make the SCM Changes view retain saved collapse choices through asynchronous repository and resource-group discovery, while keeping genuinely new nodes expanded by default. Preserve repository visibility selection and active-editor auto-reveal as separate behaviors.
