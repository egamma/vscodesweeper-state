# Issue #326345 — SCM Changes view does not restore repository/group collapsed state after reload

[https://github.com/microsoft/vscode/issues/326345](https://github.com/microsoft/vscode/issues/326345)

## Summary

Well-diagnosed, source-verified bug: the SCM Changes tree's saved view state (`scm.viewState2`) is only threaded through the initial `tree.setInput()` call, but Git repositories are typically discovered asynchronously after that call runs, so later `updateChildren()` refreshes (which never receive a `viewStateContext`) fall back to the default collapse state instead of the restored one.

## Change summary

After reload/restart, the main Source Control Changes tree loses the user's previous mixed expanded/collapsed state for repositories and resource groups discovered after the initial tree render.

## Best solution

In src/vs/base/browser/ui/tree/asyncDataTree.ts / scmViewPane.ts, thread the loaded view state (or the set of previously-expanded ids) through to later async `updateChildren()` calls that populate nodes discovered after `setInput()` — not just the very first render — so repositories/groups that appear once Git discovery settles are matched against the saved expanded-id list instead of falling through to `defaultCollapseState`.

## Evidence

- **public updateChildren never carries viewState:** src/vs/base/browser/ui/tree/asyncDataTree.ts:798-800 — `updateChildren()` always calls `_updateChildren(element, recursive, rerender, undefined, options)`, i.e. `viewStateContext` is always undefined outside of the initial `setInput()` call (line 786).
- **new nodes without viewStateContext default to expanded:** src/vs/base/browser/ui/tree/asyncDataTree.ts:1287-1290 and 1349-1355 — a child's collapsed state is only matched against `viewStateContext.viewState.expanded` when a context is passed; otherwise it uses `node.defaultCollapseState`, which for SCM repositories/resource groups is expanded per scmViewPane.ts's `collapseByDefault` callback (around line 1966: `return !(isSCMRepository(e) || isSCMResourceGroup(e) || isSCMResourceNode(e));`).
- **setInput happens before repos are discovered:** scmViewPane.ts ~line 1542 calls `this.tree.setInput(this.scmViewService, viewState)` on becoming visible, while repository discovery (`onDidChangeVisibleRepositories` → `this.updateChildren()`) is wired up and fired afterward and asynchronously, so repos/groups that materialize after that point are rendered via plain `updateChildren()` with no view state, permanently losing the saved collapse info for that session.
- **no existing fix:** `git log --grep=326345` and recent history on asyncDataTree.ts show no related change; this is unaddressed on current main.
