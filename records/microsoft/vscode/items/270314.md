# Issue #270314 — Remove usage of setupManagedHover

[https://github.com/microsoft/vscode/issues/270314](https://github.com/microsoft/vscode/issues/270314)

## Summary

The cleanup remains necessary: current main still exposes the deprecated API and contains extensive usage across the workbench. Related merged PRs migrated only selected consumers and explicitly described themselves as parts of this issue.

## Change summary

Remove remaining uses of the deprecated `setupManagedHover` API in favor of the delayed-hover APIs.

## Best solution

Complete the migration across base, editor, platform, workbench, and sessions while preserving each hover's placement, update, grouping, and keyboard behavior, then remove the obsolete managed-hover API once no consumers remain.

- **Reason:** Consolidating workbench hovers on one supported API improves interaction consistency and removes a deprecated path documented as scaling poorly.

## Plan brief

- **Behavior:**

  > All existing hovers continue to appear with their current content, delay, placement, pointer style, update behavior, and keyboard accessibility. Moving between related hover targets preserves immediate group transitions where configured. Acceptance requires no remaining `setupManagedHover` or `showManagedHover` references and no regression in representative shared-widget, SCM, debug, and chat hover behavior.
- **Trace:**

  > The deprecated contract remains in src/vs/base/browser/ui/hover/hover.ts and its implementation remains in src/vs/platform/hover/browser/hoverService.ts, while current main contains 224 references across 111 files. The supported paths are `setupDelayedHover` and `setupDelayedHoverAtMouse`, whose lifecycle options cover grouping and keyboard setup but whose return type and content model differ from `IManagedHover`. https://github.com/microsoft/vscode/pull/270313 demonstrates migration patterns for updateable titles and base widgets, while https://github.com/microsoft/vscode/pull/271527 covers chat attachment widgets. The boundary is behavior preservation: do not standardize placement, delay, persistence, focus, or content-refresh semantics merely as part of removing the deprecated API. The broader API design work remains tracked by https://github.com/microsoft/vscode/issues/243348.
