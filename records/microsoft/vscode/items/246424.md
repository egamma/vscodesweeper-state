# Issue #246424 — about running vscode in old linux

[https://github.com/microsoft/vscode/issues/246424](https://github.com/microsoft/vscode/issues/246424)

## Summary

The substantive comment asks how to use an updated VS Code Server without root access or Docker, rather than reporting a defect or requesting a defined product change. Answer the question with the existing custom-sysroot workaround and close as a question.

## Change summary

Find a way to run an updated VS Code Server on older Linux without root privileges or Docker.

## Best solution

Explain that a compatible sysroot and patchelf can be prepared on another machine and copied into user-writable directories on the remote host. Retain the documented unsupported-status warning and minimum kernel requirement; this is not a guarantee that every older distribution will work.

- **Proposed comment:**

  > Thanks for the question. For the VS Code Server scenario you linked, Docker and root access on the remote host are not required by the custom-sysroot approach: you can prepare a compatible sysroot and patchelf on another machine, copy them into directories you can write to on the remote host, and set `VSCODE_SERVER_CUSTOM_GLIBC_LINKER`, `VSCODE_SERVER_CUSTOM_GLIBC_PATH`, and `VSCODE_SERVER_PATCHELF_PATH` as described in https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions.
  > 
  > This remains an unsupported workaround, and the documented kernel requirement is still 4.18 or newer; supplying newer libraries does not upgrade the kernel. Closing as a usage question rather than a product defect.

- **Documented alternative:** https://code.visualstudio.com/docs/remote/faq#_can-i-run-vs-code-server-on-older-linux-distributions documents supplying a sysroot with glibc >= 2.28 and libstdc++ >= 3.4.25, installing patchelf >= 0.18, and setting VSCODE_SERVER_CUSTOM_GLIBC_LINKER, VSCODE_SERVER_CUSTOM_GLIBC_PATH, and VSCODE_SERVER_PATCHELF_PATH. Docker is presented as an example build environment, not a required runtime. The workaround is explicitly unsupported, and the listed kernel requirement is >= 4.18.
- **Current source capability:** resources/server/bin/code-server-linux.sh consumes the three custom-sysroot environment variables and invokes the supplied patchelf binary to set the server Node executable's rpath and interpreter. These paths are caller-provided, with no requirement to install the libraries in system directories. resources/server/bin/helpers/check-requirements-linux.sh recognizes VSCODE_SERVER_CUSTOM_GLIBC_LINKER and warns that server stability is not guaranteed. Source inspection only; no compatibility test was executed.
