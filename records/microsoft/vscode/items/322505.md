## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/322505 reports that Shift+Cmd+V in Safari/macOS and Shift+Ctrl+V in Edge/Windows fail to leave Markdown preview on vscode.dev 1.125.1, while markdown.togglePreview works from the Command Palette. This supplies a concrete trigger, affected surface, expected result, and cross-platform observations.
- **Open implementation candidates:** Verified that https://github.com/microsoft/vscode/pull/322680 and https://github.com/microsoft/vscode/pull/327301 are both OPEN and explicitly reference this issue with closing syntax. Both change src/vs/platform/actions/browser/menuEntryActionViewItem.ts to disable Shift-based alternative action selection on the web; neither is a landed fix.
- **Expected shortcut remains registered:** extensions/markdown-language-features/package.json:990-994 registers markdown.togglePreview as shift+ctrl+v, with shift+cmd+v on macOS, and explicitly permits activeCustomEditorId == 'vscode.markdown.preview.editor'. The requested preview-to-text shortcut is existing intended behavior, not a new capability.
- **Toolbar symptom versus shortcut cause:** src/vs/platform/actions/browser/menuEntryActionViewItem.ts:240-251 still selects an alternative command when Shift is held and the mouse is over the item, without a web-platform exclusion. That callback updates labels, tooltips, and classes; it does not itself preventDefault or stopPropagation on a keyboard event. The proposed PR condition therefore explains the icon change but does not establish why shortcut dispatch fails.
- **Current keyboard forwarding path:** src/vs/workbench/contrib/webview/browser/pre/index.html:635-649 forwards key events with shiftKey, altKey, ctrlKey, and metaKey preserved. src/vs/workbench/contrib/webview/browser/webviewElement.ts:753-768 gates forwarding through shouldForwardKeyEvent and isActiveElement, then redispatches a KeyboardEvent to the host window. Source inspection alone did not conclusively reproduce the browser-specific failure.
- **Canonical search:** Searches for webview Shift shortcuts and web markdown.togglePreview found no verified canonical for this symptom. https://github.com/microsoft/vscode/issues/241801 concerns double execution of editor-switching shortcuts, whereas https://github.com/microsoft/vscode/issues/109147 concerns synthetic keyboard events failing on Windows desktop. Neither establishes the same observable web preview-to-text failure required for a duplicate close of this re-reviewed item.
