# Issue #156886 — Improve workflow for applying/previewing fixes

[https://github.com/microsoft/vscode/issues/156886](https://github.com/microsoft/vscode/issues/156886)

## Summary

Keep this broader workflow proposal open: current Refactor Preview covers some details, but preview defaults, category controls, mutually exclusive alternatives, and extension feedback remain unresolved. Verified related issues cover individual requests, not the whole proposal.

## Change summary

Improve WorkspaceEdit review with automatic diff previews, configurable initial selection, category controls, alternative selection, keyboard-friendly navigation, and extension-defined feedback actions.

## Best solution

Retain this as the cross-cutting design discussion and coordinate its remaining requirements with the narrower preview issues. Settle preview-selection and alternative-edit semantics before expanding the public WorkspaceEdit contract, while preserving explicit confirmation and selective application.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditPane.ts`, `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditTree.ts`, `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditPreview.ts`, `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEdit.contribution.ts`, `src/vs/workbench/contrib/bulkEdit/test/browser/bulkEditPreview.test.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** The plan should conclude with an extension-host scenario invoking workspace.applyEdit on multiple files and labelled edit groups: verify the agreed initial diff and selection state, keyboard/category toggles, and that Apply changes only selected edits while Discard changes nothing. Extend bulkEditPreview.test.ts for any agreed selection or exclusivity semantics.
- **Behavior:**

  > Extensions proposing complex workspace edits need a review workflow that exposes the changes clearly and lets users accept a meaningful subset. The proposal includes automatic diff opening, preview with initially selected edits, category-level selection, mutually exclusive alternatives, keyboard navigation, and optional extension-defined feedback actions. Acceptance must cover both Code Actions and direct workspace.applyEdit callers, preserve selective application and discard behavior, and follow the agreed confirmation semantics.
- **Trace:**

  > BulkEditPreviewContribution._previewEdit in bulkEdit.contribution.ts opens the preview pane and awaits BulkEditPane.setInput. The pane focuses and expands its tree, while its onDidOpen handler opens the multi-diff editor; setInput does not automatically open it. BulkFileOperations initializes selection from needsConfirmation, coupling confirmation to unchecked edits, and CategoryElement supports toggling despite CategoryElementRenderer having no checkbox. WorkspaceEdit metadata in src/vscode-dts/vscode.d.ts has no exclusivity or feedback-action contract. Preserve existing confirmation behavior for existing callers unless an explicit compatible contract is approved; do not assume Code Action preview entry points cover direct applyEdit. Related work is tracked at https://github.com/microsoft/vscode/issues/159327, https://github.com/microsoft/vscode/issues/207578, https://github.com/microsoft/vscode/issues/207579, and https://github.com/microsoft/vscode/issues/162743. Source inspection establishes partial coverage, but the public behavior and scope of the remaining proposal are not settled.
- **Open decisions:**
  - Should extensions be able to request a preview with edits initially selected independently of needsConfirmation, and what compatibility guarantees should existing callers retain?
  - Should mutually exclusive alternatives be selectable inside one WorkspaceEdit preview, or remain separate Code Actions?
  - Should Refactor Preview expose extension-defined actions and outcome context, or should extension feedback remain outside the preview surface?
  - When a preview opens its diff automatically, which edit should it reveal when none are selected, and should keyboard focus remain in the preview tree?
