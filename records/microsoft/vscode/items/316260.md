# Issue #316260 — Feature request: multiple Copilot chat tabs inside the Chat pane (not Chat Editor)

[https://github.com/microsoft/vscode/issues/316260](https://github.com/microsoft/vscode/issues/316260)

## Summary

Keep open: current Chat pane navigation offers a session list and title picker, not persistent conversation tabs inside the pane. The closest open request is newer than this re-reviewed item, so it cannot be used as its duplicate canonical.

## Change summary

Provide multiple visible conversation tabs inside the Chat pane, with quick switching and optional pinning or renaming, without occupying file editor groups.

## Best solution

Design a compact, accessible conversation-switching surface within the existing Chat pane that keeps file editors separate and reuses existing session pinning and renaming. Coordinate with https://github.com/microsoft/vscode/issues/316615 rather than treating Agents Window tabs or the existing session list as complete coverage.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewTitleControl.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/viewPane/chatViewPane.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/viewPane/chatViewTitleControl.test.ts`
- **Validation:** In a sidebar and secondary-sidebar Chat pane, create three independent conversations and switch between their visible tabs using mouse and keyboard. Confirm each retains its conversation and draft, no Chat Editor is opened, file editor groups remain unchanged, and the chosen overflow, pinning, renaming, and reload semantics work at narrow widths. Add targeted coverage in the existing ChatViewPane and ChatViewTitleControl test suites for the agreed behavior.
- **Behavior:**

  > Users working with several conversations should be able to keep those conversations visibly available inside the Chat pane and switch between them without opening Chat Editors. Conversation contexts and drafts must remain independent, and file editor groups must not change during switching. The design must accommodate narrow sidebar widths and keyboard and screen-reader navigation. Acceptance includes switching among three conversations, with pinning, renaming, overflow, and reload behavior matching the maintainer-approved contract.
- **Trace:**

  > ChatViewPane in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts owns one ChatWidget, a current model reference, and a cache of widget view states. Its createSessionsControl path supplies the existing session list; createChatTitleControl supplies ChatViewTitleControl, whose current title action opens AgentSessionsPicker rather than a tab strip. The chat.viewSessions.enabled and chat.viewSessions.orientation settings configure list visibility and placement, not persistent tabs. PinAgentSessionAction and RenameAgentSessionAction already exist in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts. Keep existing session history, independent conversation state, and Chat Editor behavior intact; the requested surface belongs in the regular Chat pane, not solely in the separate Agents Window. https://github.com/microsoft/vscode/issues/316615 describes the same requested surface, and https://github.com/microsoft/vscode/issues/316615#issuecomment-4472488027 establishes the space constraint and openness to alternatives. The uncertainty is the user-visible tab presentation and lifetime contract, not whether the existing session list already fulfills the request.
- **Open decisions:**
  - Should pane tabs represent explicitly opened conversations, pinned sessions plus the current conversation, or another defined subset of session history?
  - At narrow sidebar widths, should the tab surface scroll, wrap, or use an overflow menu, and should it replace or coexist with the current title picker?
  - Should the pane's open-tab set survive reload, and should closing a tab only remove it from the pane while preserving the session in history?
