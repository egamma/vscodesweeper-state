# Issue #346899 — confusing, gap in training / onboarding

[https://github.com/microsoft/vscode/issues/346899](https://github.com/microsoft/vscode/issues/346899)

## Summary

Keep open as Agents Window onboarding and discoverability feedback. Commit functionality exists, but the walkthrough does not clearly distinguish committing changes from marking files viewed or marking a session done.

## Change summary

Make the Agents Window commit workflow understandable after onboarding, including the meaning of its checkmarks.

## Best solution

Make onboarding identify the available commit action and explain how file-review state and session completion differ from Git operations. Coordinate with the broader Git/worktree UX discussion without treating that umbrella as a replacement for this specific onboarding report.

## Evidence

- **Existing commit capability:** src/vs/sessions/contrib/changes/browser/changesActions.ts:getChangesetOperations exposes provider-supplied Commit operations in the Changes editor title; registerChangesetOperationAction invokes the selected changeset operation. The capability exists, but that does not establish that onboarding makes it understandable.
- **Existing onboarding is partial coverage:** src/vs/sessions/contrib/getStarted/browser/getStartedTours.ts:createKeepChangesSteps points to changes, the diff editor, and the changes-action target. Its final explanation says to 'merge, commit or create a pull request' but does not distinguish Viewed or Mark as Done from committing.
- **Viewed is review state:** src/vs/workbench/contrib/sessionChanges/browser/sessionChangesEditor.ts renders the per-file Viewed checkbox; changesViewService.ts:setChangesetFilesReviewState delegates to changeset.setReviewState. These controls represent review state rather than a Git commit.
- **Related work, not a verified duplicate:** The open https://github.com/microsoft/vscode/issues/336620 discusses Git-action discoverability and Mark as Done semantics, but explicitly says it is not intended to replace narrower reports. https://github.com/microsoft/vscode/issues/305870 concerns differing worktree/workspace integration actions and the agentic commit flow, not this walkthrough's failure to explain the controls.
