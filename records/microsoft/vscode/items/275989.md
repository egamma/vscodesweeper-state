# Issue #275989 — Cloning in VSCode sets absolute worktree path. It breaks git on WSL. How to prevent VSCode from doing this unnecessary behavior?

[https://github.com/microsoft/vscode/issues/275989](https://github.com/microsoft/vscode/issues/275989)

## Summary

Confirmed bug: the clone command passes an absolute folderPath to `git clone` (line 480 of git.ts), causing git to record an absolute `core.worktree` in `.git/config` that breaks WSL access. An open PR (#300038) proposes the fix — keeping open for that PR to land.

## Change summary

VS Code's git clone passes an absolute destination path, causing git to store an absolute worktree path in .git/config that is invalid when the repo is accessed from WSL.

## Best solution

Land the open PR https://github.com/microsoft/vscode/pull/300038 which changes `folderPath` to `folderName` in the clone args at `extensions/git/src/git.ts:480`. Since `exec` already runs with `cwd` set to `parentPath`, a relative name produces the same result without the absolute worktree entry.
