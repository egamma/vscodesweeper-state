# Issue #114514 — Suggest to include the event source metadata for FillWillRenameEvent

[https://github.com/microsoft/vscode/issues/114514](https://github.com/microsoft/vscode/issues/114514)

## Summary

The API gap remains on current main: rename events expose no source metadata, and only undo-triggered operations bypass participants. This team-authored Backlog request should remain open for API design.

## Change summary

Let extensions distinguish user file renames from renames caused by applying workspace edits.

## Best solution

Prevent file-operation participants from running recursively for edits returned by an onWill listener, as the maintainer suggested, or expose a carefully designed operation-source API if extensions need broader provenance.
