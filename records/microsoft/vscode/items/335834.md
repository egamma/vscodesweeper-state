# Issue #335834 — Inconsistent inheritance

[https://github.com/microsoft/vscode/issues/335834](https://github.com/microsoft/vscode/issues/335834)

## Summary

Team-authored self-investigation (opened by sbatten while verifying #335228) flagging a real inconsistency in the sessions word-wrap settings; source confirms the described behavior, so this stays open as active follow-up work, not a triage close.

## Change summary

`sessions.diffEditor.wordWrap`'s `inherit` option is documented/implemented to defer to `editor.wordWrap`, not to the parallel `diffEditor.wordWrap` setting one would expect it to mirror.

## Best solution

Decide the intended inheritance chain for `sessions.diffEditor.wordWrap: inherit` (likely inherit from `diffEditor.wordWrap` for consistency with the core diff editor's own setting) and align both the config description and the `diffWordWrap` value passed into the diff editor control in src/vs/sessions/contrib/editor/browser/diffEditor.sessions.contribution.ts / diffEditorOptionsService.ts.

## Evidence

- **config description:** src/vs/sessions/contrib/editor/browser/diffEditor.sessions.contribution.ts:186 documents `sessions.diffEditor.wordWrap`'s `inherit` as wrapping 'according to the #editor.wordWrap# setting' — the same wording used for the separate `sessions.editor.wordWrap` setting at line 200 — rather than referencing `#diffEditor.wordWrap#`.
- **runtime behavior:** The raw `sessions.diffEditor.wordWrap` value ('off'|'on'|'inherit') is passed straight through as `diffWordWrap` to the diff editor control (lines 141-153), and core diff editor semantics treat `diffWordWrap: 'inherit'` as inheriting from `editor.wordWrap` (src/vs/editor/common/config/editorConfigurationSchema.ts:252-260), so the sessions setting never actually chains through the core `diffEditor.wordWrap` setting as its name would suggest.
