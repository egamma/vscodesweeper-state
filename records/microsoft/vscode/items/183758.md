# Issue #183758 — Support a toolbar with labels on each side in diff editor

[https://github.com/microsoft/vscode/issues/183758](https://github.com/microsoft/vscode/issues/183758)

## Summary

The standard diff editor still lacks separate labeled action bars above its two panes, including in the save-conflict flow. Keep this accepted Backlog request open; the related file-identification report was explicitly consolidated into this issue.

## Change summary

Support a label and toolbar above each side of the diff editor to clarify the compared contents and their available actions.

## Best solution

Provide optional per-side headers for the standard diff editor, usable by save-conflict resolution to identify disk contents versus unsaved editor contents. Settle their availability in ordinary comparisons and their behavior in inline mode before implementation, without replacing save-conflict resolution with the merge editor.

Resize the split and switch to inline mode to verify the agreed header behavior; compare ordinary files to verify the agreed default visibility.
- **Behavior:**

  > The standard side-by-side diff editor should support a label and actions above each pane, allowing users to identify what each side represents without interpreting a combined tab title. In save-conflict resolution, the labels must distinguish disk contents from unsaved editor contents. Existing accept/revert outcomes must remain unchanged, and any header actions must be keyboard-accessible. Acceptance includes correct association during split resizing and the maintainer-approved behavior in inline mode and ordinary comparisons.
- **Trace:**

  > TextDiffEditor.createEditorControl in src/vs/workbench/browser/parts/editor/textDiffEditor.ts directly constructs DiffEditorWidget. That widget creates full-height original and modified editor containers without dedicated label/action rows. ResolveSaveConflictAction.run in src/vs/workbench/contrib/files/browser/editors/textFileSaveErrorHandler.ts supplies a combined editor label, while fileActions.contribution.ts registers conflict actions in the editor title menu. The merge editor's codeEditorView.ts provides a title/description/toolbar precedent, and the multi-diff template has a shared per-file header, but neither supplies this capability on the standard save-conflict path. Preserve comparison semantics and existing conflict actions; switching to the merge editor is separate work tracked by https://github.com/microsoft/vscode/issues/156546. The remaining uncertainty is the user-visible activation scope and presentation when the diff uses inline mode.
- **Open decisions:**
  - Should per-side headers appear only when a caller supplies labels/actions, or also by default in ordinary file comparisons?
  - When the diff switches to inline mode, should both side identities and their actions remain visible, or should the separate headers be hidden?
