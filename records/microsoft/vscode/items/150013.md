# Issue #150013 — VS Code blocks Windows from shutting down when there is an update or confirm dialog

[https://github.com/microsoft/vscode/issues/150013](https://github.com/microsoft/vscode/issues/150013)

## Summary

Still a valid, confirmed bug: VS Code's lifecycle veto mechanism and the Inno Setup updater spawned on quit block Windows shutdown. Multiple users confirm it persists through v1.103 (August 2025) and March 2026. No fix found on main.

## Change summary

VS Code blocks Windows shutdown when an update is pending or a confirm dialog is open, because the lifecycle service vetoes the quit and/or the Inno Setup installer process prevents the system from completing shutdown.

## Best solution

Two fixes are needed: (1) When the quit reason is a system shutdown (Electron's `before-quit` triggered by Windows session-end), the lifecycle service should not allow window vetoes (confirm dialogs) to block the quit. (2) The Inno Setup update spawned at quit (`doQuitAndInstall` in `updateService.win32.ts`) should be made shutdown-aware — either by deferring it to the next launch or by passing `/RESTARTAPPLICATIONS` so Inno cooperates with the Windows restart manager.

## Evidence

- **Inno updater spawned on quit:** src/vs/platform/update/electron-main/updateService.win32.ts line 617: `doQuitAndInstall` spawns Inno Setup with `/silent` — Inno Setup's process blocks the Windows shutdown because it registers with the restart manager as a running installer.
