# Issue #216815 — Git - Recommend running `git gc` when git operations take too long

[https://github.com/microsoft/vscode/issues/216815](https://github.com/microsoft/vscode/issues/216815)

## Summary

The built-in Git extension records slow operations but does not suggest repository maintenance. Keep this accepted Backlog request open; related reports support the usefulness of the advice, but do not own the requested detection feature.

## Change summary

Suggest running `git gc` when local repository operations are persistently slow.

## Best solution

Provide restrained, repository-specific maintenance guidance in the built-in Git extension, without automatically running cleanup or implying that garbage collection fixes every slowdown. Agree on the qualifying operations, trigger, and notification frequency before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/repository.ts`
- **Validation:** End the plan with executable tests using controlled command durations: qualifying slow local operations produce repository-specific maintenance advice under the agreed trigger; fast operations and ordinary slow network operations do not; repeated qualifying operations respect the agreed notification limit; no cleanup runs automatically.
- **Behavior:**

  > Users with persistently slow local Git operations should receive actionable guidance that repository maintenance with `git gc` may help. The guidance must not promise a speedup or automatically alter the repository. Acceptance should distinguish qualifying local delays from ordinary network delays, leave fast repositories unaffected, and prevent repeated notifications according to an agreed policy.
- **Trace:**

  > Git._exec and Git.stream in extensions/git/src/git.ts already measure command elapsed time for output logging. Repository.getStatus in extensions/git/src/repository.ts separately measures status duration and emits statusSlow telemetry above five seconds; its user-facing warning concerns excessive active changes, not elapsed time. No registered maintenance recommendation was found. https://github.com/microsoft/vscode/issues/183199 contains both successful and unsuccessful `git gc` workarounds, and https://github.com/microsoft/vscode/issues/240460 records another successful case, so elapsed time alone does not establish a maintenance-related root cause. Preserve existing command results, cancellation behavior, status-limit warnings, and normal network-operation behavior; automatic garbage collection is outside this request. The remaining uncertainty is the product contract for when advice is warranted and how often users see it.
- **Open decisions:**
  - Should advice require repeated slow local operations alone, or additional repository-maintenance evidence, and which operations and delay threshold qualify?
  - How often may a repository show the recommendation, and how should dismissal suppress future advice?

## Evidence

- **Reported benefit:** https://github.com/microsoft/vscode/issues/216815 reports that `git gc` reduced general `git log` latency from over five seconds to 1.5 seconds and the permalink-specific call to approximately 100 ms. The request is for automatic advice, not another fix to permalink generation.
- **Existing capability does not cover the request:** extensions/git/src/git.ts:601-680 routes commands through Git._exec and logs elapsed milliseconds; stream also logs elapsed time. extensions/git/src/repository.ts:3107-3152 measures status duration and emits statusSlow telemetry above 5000 ms, but provides no maintenance advice.
- **Different existing warning:** extensions/git/src/repository.ts:3157-3207 warns when the active-change limit is exceeded and may suggest adding a folder to .gitignore. The registered git.ignoreLimitWarning setting controls that warning, while git.showOutput exposes command logs; neither provides slow-repository detection with a `git gc` recommendation. Searches of the Git extension's command/configuration registrations and source found no such capability.
- **Older related issue is not a canonical:** https://github.com/microsoft/vscode/issues/183199 is open and older, but reports Git operations becoming slow rather than requesting maintenance recommendations. https://github.com/microsoft/vscode/issues/183199#issuecomment-2483369545 confirms that `git gc` restored performance, whereas https://github.com/microsoft/vscode/issues/183199#issuecomment-2322994105 reports that it did not help. This mixed performance thread does not establish the same requested work or satisfy the stronger duplicate bar for this re-reviewed item.
