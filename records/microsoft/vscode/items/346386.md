# Issue #346386 — Evals: Compare skills, plugins, and MCP configurations in the Agents window

[https://github.com/microsoft/vscode/issues/346386](https://github.com/microsoft/vscode/issues/346386)

## Summary

Keep open: Compare supports model and effort variants, but its attempt configuration does not support independently selected customization versions or enablement. The maintainer discussion explicitly keeps this request open and identifies customization ownership with Compare coordination.

## Change summary

Allow isolated Compare attempts to vary skills, plugins, and MCP configurations while holding the model, effort, prompt, and repository revision constant.

## Best solution

Extend Compare with reproducible, attempt-scoped customization variants and identifiable configuration evidence for review and optional judging. Customization and Compare owners should settle isolation and version-selection semantics before implementation.

Supplement with a provider-backed enabled-versus-disabled skill comparison.
- **Behavior:**

  > Users can compare skill enablement or content versions, plugin versions, and MCP server configurations or tool sets without changing the model, reasoning effort, prompt, or baseline repository revision. Each attempt uses its selected customization variant independently of concurrent attempts. Review and optional judging identify which variant produced each result. Existing model comparisons and unrelated user customization settings remain unchanged.
- **Trace:**

  > ISessionComparisonAttemptConfiguration and ISessionComparisonHarness in src/vs/workbench/contrib/sessions/common/sessionComparison.ts currently represent model, effort, mode, and permission choices, not customization variants. createSessionComparisonHarness in src/vs/workbench/contrib/sessions/browser/sessionComparisonConfiguration.ts validates model-schema configuration. SessionComparisonService._createOptions in src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts forwards those choices through normal provider session creation with worktree isolation. src/vs/sessions/AI_CUSTOMIZATIONS.md establishes runtime-owned plugin activation at global and repository scopes, so concurrent variant isolation cannot be assumed from existing management controls. Provider support and immutable version capture remain untraced; the listed files identify the comparison boundary, not the complete implementation scope. Preserve provider ownership, policy enforcement, ordinary customization settings, and existing comparison behavior. The ownership direction is recorded in https://github.com/microsoft/vscode/issues/346386.
- **Open decisions:**
  - What constitutes a selectable version for each customization type: installed versions, local content snapshots, or externally supplied candidates?
  - Which customization state is frozen for reproducibility, particularly user-scoped files and MCP services whose behavior can change independently of repository revision?
  - Which providers and customization types must support isolated variants initially, and how should unsupported combinations be presented?
