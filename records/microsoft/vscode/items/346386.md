# Issue #346386 — Evals: Compare skills, plugins, and MCP configurations in the Agents window

[https://github.com/microsoft/vscode/issues/346386](https://github.com/microsoft/vscode/issues/346386)

## Summary

Compare supports model and reasoning variants, but its attempt configuration does not capture independent skill, plugin, or MCP variants. Keep this team-authored request open for design; the related skill-comparison request overlaps but does not explicitly cover MCP configurations and versions.

## Change summary

Allow controlled comparisons of customization configurations while holding model, reasoning effort, prompt, and repository revision fixed.

## Best solution

Extend comparison attempts with independently scoped, identifiable customization variants that remain distinguishable in results and Judge evidence. Coordinate the shared skill/plugin requirements with https://github.com/microsoft/vscode/issues/344494 while retaining explicit coverage of MCP versions and tool sets.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/sessions/common/sessionComparison.ts`, `src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts`, `src/vs/sessions/contrib/sessionComparison/browser/modelEvaluationTools.ts`, `src/vs/sessions/contrib/sessionComparison/browser/sessionComparisonTool.ts`
- **Validation:** Extend src/vs/workbench/contrib/sessions/test/browser/sessionComparisonService.test.ts and src/vs/sessions/contrib/sessionComparison/test/browser/modelEvaluationTools.test.ts to verify distinct customization variants with identical model, effort, prompt, and starting revision. Provider-level validation must confirm that a disabled customization is actually unavailable and concurrent attempts do not change each other's configuration.
- **Behavior:**

  > Users can compare a skill enabled versus disabled or before versus after edits, plugin versions, and MCP server versions or tool sets. Attempts keep the same model, reasoning effort, prompt, and starting repository revision. Results and optional Judge evidence identify the customization variant actually used. Configuring one attempt must not alter another attempt or unrelated sessions.
- **Trace:**

  > ISessionComparisonHarness currently represents model and permission choices, and SessionComparisonService._createOptions launches independent worktree attempts without customization variants. ModelEvaluationTool's selectionSchema exposes the same model-focused boundary; ReadSessionComparisonTool.getManifest reports model, reasoning, and permissions rather than customization provenance. The customization architecture delegates runtime behavior to harness providers, so worktree isolation alone does not establish independent user-level plugin or MCP state. Preserve provider-neutral orchestration, existing comparison behavior, permission enforcement, and advisory Judge semantics. https://github.com/microsoft/vscode/issues/344494 supplies overlapping skill/plugin requirements; the unresolved boundary is how selected customization versions are retained and supported by each provider.
- **Open decisions:**
  - Must a comparison retain immutable customization contents and versions for later reruns, or record the launch-time configuration without guaranteeing replay?
  - Which customization sources and agent providers must the initial version support, and how should unsupported configuration or version selections be presented?

## Evidence

- **Existing capability and remaining gap:** src/vs/sessions/SESSION_COMPARISONS.md documents isolated attempts, optional Judge evaluation, and same-model reasoning variants behind sessions.chat.compareAgents.enabled. These capabilities do not provide per-attempt customization configuration or version selection.
- **Attempt contract and launch path:** ISessionComparisonHarness in src/vs/workbench/contrib/sessions/common/sessionComparison.ts records provider, model configuration, mode, and permissions, but no skill, plugin, or MCP variant. SessionComparisonService._createOptions in src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts forwards those choices with worktree isolation and a branch, without customization overrides.
- **Agent-driven surface:** The selectionSchema in src/vs/sessions/contrib/sessionComparison/browser/modelEvaluationTools.ts accepts sessionTypeId, modelId, and modelConfiguration, with additionalProperties disabled. It exposes no customization-comparison capability.
- **Related request is narrower:** https://github.com/microsoft/vscode/issues/344494 requests skill enabled/disabled and before/after comparisons, also mentioning plugins. Its text does not explicitly own MCP server-version and tool-set comparisons, so it is related rather than a verified full-scope duplicate.

The author's follow-up also raises customization-update visibility; that adjacent concern should not replace the issue's controlled-evaluation goal. src/vs/sessions/AI_CUSTOMIZATIONS.md assigns runtime customization behavior to harness providers.
