# Issue #346386 — Evals: Compare skills, plugins, and MCP configurations in the Agents window

[https://github.com/microsoft/vscode/issues/346386](https://github.com/microsoft/vscode/issues/346386)

## Summary

Keep open: Compare supports model and reasoning variants, but not controlled per-attempt skill, plugin, or MCP variants. The maintainer has accepted customization ownership; the related skill-comparison request does not cover the full MCP scope.

## Change summary

Compare customization configurations and versions while holding the model, reasoning effort, prompt, and repository revision constant.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionComparisonModelSelection.ts`, `src/vs/sessions/contrib/chat/browser/newChatWidget.ts`, `src/vs/sessions/services/sessions/common/sessionComparison.ts`, `src/vs/sessions/services/sessions/browser/sessionComparisonService.ts`
- **Validation:** Run two isolated attempts with identical model, effort, prompt, and starting commit but different customization variants. Verify the disabled skill is unavailable, each plugin/MCP variant exposes its intended version or tool set, unrelated customizations and global state remain unchanged, and comparison evidence identifies each effective variant. Repeat after editing the source customization to check the chosen reproducibility contract.
- **Behavior:**

  > Users can compare skill enablement or versions, plugin versions, and MCP versions or tool sets without also changing model, reasoning effort, prompt, or starting repository revision. Each attempt actually receives its selected customization configuration, rather than an instruction to ignore unwanted tools or skills. Attempts remain isolated and independently reviewable, and the optional Judge can distinguish their effective configurations. Acceptance includes proving that a disabled customization is unavailable and that launching one variant does not alter another attempt or global customization state.
- **Trace:**

  > SessionComparisonModelSelection currently queues model IDs and model-configuration variants. NewChatWidget constructs comparison harnesses from those selections, and SessionComparisonService._createOptions forwards model, permission, isolation, and branch choices through ISessionsManagementService; the comparison contracts contain no customization variant identity or snapshot. SESSION_COMPARISONS.md places orchestration in the comparison service and execution isolation in providers, while AI_CUSTOMIZATIONS.md places discovery and enablement in shared customization services and harness descriptors. The trace establishes the missing comparison contract but does not establish how each provider can freeze and apply customization versions independently. Preserve provider-neutral orchestration, enterprise restrictions, existing model comparisons, and global customization state. https://github.com/microsoft/vscode/issues/344494 provides overlapping skill/plugin requirements, while https://github.com/microsoft/vscode/issues/347619 requests adjacent custom-agent variants; neither replaces this issue's MCP scope.
- **Open decisions:**
  - Should a launched comparison preserve immutable customization contents and resolved versions for later replay, or record references and explicitly report when those references have changed?
  - Which customization configuration should the optional Judge use: the unchanged baseline or a separately selected evaluation configuration?
