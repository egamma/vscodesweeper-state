## Change summary

Integrated-browser agent tools never return on one Windows laptop even though the browser page loads and is shared successfully.

## Best solution

Diagnose where the affected laptop stops between Playwright page resolution, summary generation, and tool-result delivery, then ensure browser operations return a result or a bounded, actionable failure. Preserve this report separately unless evidence establishes that the older completion-routing report owns the same failure.

## Evidence

- **Complete reproduction and repeated retests:** https://github.com/microsoft/vscode/issues/341410 describes opening https://example.com with forceNew and invoking readPage, screenshotPage, or runPlaywrightCode with return 1 + 1;. Follow-ups confirm persistence on 1.141.2 and 1.142.0 and distinguish the affected Windows 11 Insider laptop from a working desktop.
- **Current timeout boundary:** src/vs/platform/browserView/node/playwrightService.ts:474-522, PlaywrightSession._runWithDeferral, races page execution against timeoutMs but subsequently awaits _getSummary(pageId) outside that race. This could explain why an execution deadline does not bound the whole response, but does not establish which operation hangs on the laptop.
- **Shared summary path:** src/vs/platform/browserView/node/playwrightService.ts:350-369 returns a summary after page discovery/navigation; _getSummary delegates to PlaywrightTab.getSummary. In src/vs/platform/browserView/node/playwrightTab.ts:205-224, getSummary awaits initialization, an accessibility snapshot, and the page title. The 'Resolved Playwright page to view' message records identity binding, not completion of these operations.
- **Older related report is not a verified duplicate:** https://github.com/microsoft/vscode/issues/335378 is open and predates this issue, but reports browser operations completing in milliseconds with their client-dispatch results subsequently lost. This report instead identifies page resolution as the last observed progress and a laptop-only failure; matching tool names and a hanging result do not establish the same defect.
