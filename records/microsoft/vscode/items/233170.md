# Issue #233170 — Support comment toggling for languages that do not support content on the first column

[https://github.com/microsoft/vscode/issues/233170](https://github.com/microsoft/vscode/issues/233170)

## Summary

A real gap remains for languages that reserve column one, and the request earned 23 upvotes and was promoted to the Backlog. Existing support can force comments into column one, but cannot reliably target column two.

## Change summary

Allow language configurations to place line-comment tokens in a fixed non-first column while preserving comment toggling.

## Best solution

Generalize the language comment configuration to support a fixed comment column beyond the existing first-column-only option, then use that offset consistently when adding and detecting comments in the editor comment contribution.

- **confirmed limitation:** https://github.com/microsoft/vscode-discussions/discussions/2363 confirms that configuring a leading-space token such as ` !` repeatedly adds comments instead of toggling them.
- **current source gap:** src/vs/editor/contrib/comment/browser/lineCommentCommand.ts computes commentStrOffset from firstNonWhitespaceIndex and checks the complete token at that offset, so a token containing its required leading column cannot be detected for removal.
- **partial existing capability:** src/vs/editor/common/languages/languageConfiguration.ts exposes only `LineCommentConfig.noIndent`; the schema in src/vs/workbench/contrib/codeEditor/common/languageConfigurationExtensionPoint.ts describes it as forcing the token into the first column.
- **related fix does not cover request:** https://github.com/microsoft/vscode/pull/243283 added `noIndent` for Makefiles in commit d9145a291dcef0bad3ace81a3d55727ca294c122, but that forces column one rather than supporting a language that reserves column one.
