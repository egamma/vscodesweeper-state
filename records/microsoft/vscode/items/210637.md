# Issue #210637 — Minimap section headers are not shown for regions in HTML and CSS

[https://github.com/microsoft/vscode/issues/210637](https://github.com/microsoft/vscode/issues/210637)

## Summary

The requested capability remains missing on current main, and this is the established canonical backlog item with 47 community upvotes. Keep it open under the existing editor-minimap routing.

## Change summary

Show minimap section-header labels for HTML and CSS `#region` block comments, including regions in embedded languages.

## Best solution

Teach region-header detection in `findSectionHeaders.ts` to extract labels captured inside folding-marker matches instead of only reading text after the match, with corresponding HTML/CSS folding configurations and tests. Embedded-language regions should ultimately resolve folding markers for the language at each position.

## Evidence

- **current source:** `src/vs/editor/common/services/findSectionHeaders.ts` lines 67–87 matches the complete folding start marker, then derives the label only from `lineContent.substring(match[0].length)`. This is empty when HTML/CSS marker regexes consume the full comment.
- **language configurations:** `extensions/html/language-configuration.json` uses a start regex ending in `.*-->`; `extensions/css/language-configuration.json` captures the label inside `(.*?)`, but the region collector does not consume that capture.
- **backlog signal:** The issue has 47 body upvotes and was explicitly promoted to Backlog in https://github.com/microsoft/vscode/issues/210637#issuecomment-2253716590.
- **related implementation:** Commit 7ad2ae78703de53653822865686970481f37b1a8 and https://github.com/microsoft/vscode/pull/283583 fixed embedded-language validation for `MARK:` headers only; region detection remains unchanged.
- **canonical status:** The newer https://github.com/microsoft/vscode/issues/318644 reports the embedded-language form of the same limitation; this older, promoted issue is the better canonical item.
