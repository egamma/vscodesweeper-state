# Issue #102650 — Allow tooltips/hovering on symbols in outline view and breadcrumbs

[https://github.com/microsoft/vscode/issues/102650](https://github.com/microsoft/vscode/issues/102650)

## Summary

The requested documentation hover remains missing: outline and breadcrumb symbols still use a name-and-kind tooltip rather than provider-supplied documentation. No older canonical issue covering the same observable request was found, so this accepted backlog item should remain open.

## Change summary

Allow outline and breadcrumb symbols to display additional documentation through custom tooltips or the document's HoverProvider.

## Best solution

Provide consistent, on-demand symbol documentation in both outline and breadcrumbs without requiring navigation into the editor. Decide whether this reuses existing HoverProviders or introduces a DocumentSymbol tooltip contract, while retaining a useful fallback for long symbol names.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts`, `src/vs/editor/common/languages.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** Using a document with a registered symbol provider and HoverProvider, verify that hovering the same symbol in outline and breadcrumbs displays the agreed documentation without navigating the editor. Verify that symbols without documentation retain a useful name tooltip, including truncated long names, and that existing selection and navigation behavior is unchanged.
- **Behavior:**

  > Users should be able to inspect additional symbol documentation directly from outline and breadcrumbs without first navigating to the symbol in the editor. Both surfaces should expose consistent information without adding always-visible clutter. Symbols without documentation must retain a useful fallback, particularly when their visible names are truncated. The acceptance check should exercise both surfaces with and without provider documentation.
- **Trace:**

  > DocumentSymbolRenderer.renderElement in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts constructs a name-and-kind tooltip and renders symbol.detail as secondary text. OutlineItem.render in src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts uses the outline's renderer, so the two surfaces share this limitation. Neither the public DocumentSymbol declaration in src/vscode-dts/vscode.d.ts nor its internal counterpart in src/vs/editor/common/languages.ts exposes tooltip metadata. The source establishes the capability gap, but not whether documentation should come from a new symbol API or existing HoverProviders. Preserve symbol navigation and the long-name fallback raised in https://github.com/microsoft/vscode/issues/102650; unrelated outline providers are outside the established trace.
- **Open decisions:**
  - Should documentation come from existing HoverProviders, an explicit DocumentSymbol tooltip property, or both with a defined precedence?
  - If HoverProviders are used, should documentation be available automatically for all symbols or require an explicit opt-in, and at what scope?

## Evidence

- **Current renderer:** src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts, DocumentSymbolRenderer.renderElement, explicitly sets the tooltip title to "{name} ({kind})" and passes symbol.detail as the secondary label. It does not obtain symbol documentation from a HoverProvider.
- **Breadcrumb rendering:** src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts, OutlineItem.render, delegates symbol rendering to outline.config.renderers. Breadcrumb symbols therefore share the document-symbol renderer rather than supplying an independent documentation hover.
- **API and existing-capability check:** DocumentSymbol in src/vscode-dts/vscode.d.ts and src/vs/editor/common/languages.ts has name, detail, kind, ranges, tags and children, but no tooltip or hover-provider opt-in property. Inspection of outline.contribution.ts and breadcrumbs.ts found no configuration enabling the requested documentation hover; displaying detail is not equivalent to it.
- **Canonical search:** Open-issue searches for outline hover, breadcrumbs tooltip, outline tooltip titles and DocumentSymbol hover found no verified older canonical for this request. https://github.com/microsoft/vscode/issues/238598 concerns Jupyter outline previews, is newer and narrower, and cannot absorb this re-reviewed 2020 report.
- **Discussion and accepted scope:** https://github.com/microsoft/vscode/issues/102650 has the Backlog milestone and five community upvotes. The supplied comment notes that repeating a long title in a tooltip remains useful; richer documentation should not eliminate that fallback.
