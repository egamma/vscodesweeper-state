# Issue #329146 — Go to Symbol in Editor: fuzzy-match the query against a symbol's full ancestor path (e.g. `prod port` → `production.server.port`)

[https://github.com/microsoft/vscode/issues/329146](https://github.com/microsoft/vscode/issues/329146)

## Summary

Fresh, well-researched feature request (1 day old, no maintainer engagement yet) with the described current-behavior limitations verified directly in source; routing to the relevant area for maintainer consideration rather than closing.

## Change summary

Make 'Go to Symbol in Editor' match the query against a symbol's full ancestor path (not just the immediate parent), and allow outside-in query order (e.g. `prod port` for `production.server.port`).

## Best solution

Worth a maintainer look: the current container matching in gotoSymbolQuickAccess.ts only stores/matches the immediate parent name (OutlineModel._flattenDocumentSymbols), so deep, repeated-name hierarchies (config files, nested JSON/YAML) are genuinely unresolvable in the picker today. A full ancestor-path match would require plumbing the whole parent chain through DocumentSymbol.containerName (or a new field) and reworking the query-splitting logic in doGetSymbolPicks — a real but non-trivial editor/quick-access feature, not obviously extension territory since it touches the built-in outline model.
