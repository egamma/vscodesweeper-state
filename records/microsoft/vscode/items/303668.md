# Issue #303668 — Terminal: Run Active File In Active Terminal fails when folder name contains a "~"

[https://github.com/microsoft/vscode/issues/303668](https://github.com/microsoft/vscode/issues/303668)

## Summary

The current source still removes literal tildes before executing the active file, matching the reported path corruption. Route this to terminal maintainers to consider improving deliberately aggressive path sanitization; the related maintainer decision concerns a different character and does not establish that this report should close.

## Change summary

Preserve literal tildes in directory names when running the active file in the terminal.

## Best solution

Allow safely quoted literal tildes to identify the actual file without weakening shell-injection protections. Terminal maintainers should settle that behavior against the existing intentional sanitization policy before implementation.

## Evidence

- **Exact command path:** src/vs/workbench/contrib/terminal/browser/terminalActions.ts:587–611 registers workbench.action.terminal.runActiveFile and passes the active editor URI to instance.sendPath(uri, true). src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1433–1440 delegates through preparePathForShell.
- **Current path corruption:** src/vs/workbench/contrib/terminal/common/terminalEnvironment.ts:320–382 takes resource.fsPath and delegates non-Windows paths to escapeNonWindowsPath. In src/vs/platform/terminal/common/terminalEnvironment.ts, escapeNonWindowsPath explicitly includes '~' in bannedChars and removes those characters before quoting. Thus '/Users/admin/Library/Mobile Documents/com~apple~CloudDocs/Scripts/test.sh' becomes the reporter's '/Users/admin/Library/Mobile Documents/comappleCloudDocs/Scripts/test.sh'; '/test~folder/script.sh' likewise becomes '/testfolder/script.sh'. This was established by source inspection, not execution.
- **Intentional sanitization and related precedent:** escapeNonWindowsPath documents intentionally inaccurate escaping to prevent script injection. In https://github.com/microsoft/vscode/issues/206205#issuecomment-1964637879, a maintainer described removal of '#' by this sanitizer as by design. That closed report concerns a hash-prefixed filename, not literal tildes in macOS directory names, so it is related policy evidence rather than a verified duplicate or a full-scope decline precedent.
