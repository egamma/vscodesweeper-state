# Issue #334660 — Consider more visual indicator(s) into existing session's harness choice

[https://github.com/microsoft/vscode/issues/334660](https://github.com/microsoft/vscode/issues/334660)

## Summary

Keep open: the disabled-picker implementation was subsequently hidden by default and excluded from the Agents window, then the team-authored issue was explicitly reopened. A clear harness indicator remains accepted but unresolved product-design work.

## Change summary

Make the selected harness more visually apparent in existing editor and Agents-window sessions without restoring the removed Continue In picker or participant heading.

## Best solution

Choose a durable, read-only harness identity treatment that works consistently and accessibly in both editor chat and the Agents window, while preserving the decision not to restore delegation controls or participant-name headings.

- **Behavior:**

  > An existing agent session clearly identifies its active harness in both editor chat and the Agents window. The identity remains understandable visually and to assistive technology, including compact layouts, but does not imply that the harness can be changed. The removed Continue In picker and participant-name heading must not return. New-session harness selection and Local-session delegation remain unchanged.
- **Trace:**

  > PR https://github.com/microsoft/vscode/pull/335195 introduced a disabled DelegationSessionPickerActionItem as the indicator, but follow-up https://github.com/microsoft/vscode/pull/335606 gated it behind a hidden false-by-default setting and excluded the Agents window; the issue was reopened after both changes. Current visibility is controlled by OpenDelegationPickerAction in src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts and `AGENT_HOST_EXISTING_SESSION_HARNESS_PICKER_ENABLED_CONTEXT_KEY` from src/vs/platform/agentHost/common/agentHostEnablementService.ts. DelegationSessionPickerActionItem already resolves provider labels and enforces the non-interactive state, but its presentation is not the settled product design. Preserve new-session selection, Local-session delegation, provider label refresh, and all AI-feature visibility gates; the uncertainty starts at which read-only visual treatment should represent harness identity across both surfaces.
- **Open decisions:**
  - Which read-only visual treatment should identify the harness without resembling the removed Continue In control or restoring participant-name headings?
  - Should the indicator occupy the same location and visual hierarchy in editor chat and the Agents window, or use surface-specific placements while retaining a consistent identity affordance?
