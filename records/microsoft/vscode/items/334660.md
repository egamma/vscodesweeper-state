# Issue #334660 — Consider more visual indicator(s) into existing session's harness choice

[https://github.com/microsoft/vscode/issues/334660](https://github.com/microsoft/vscode/issues/334660)

## Summary

Keep open: a disabled harness picker for existing Agent Host sessions did land (PRs 335195/335606), but on current main it is gated behind the experimental, hidden setting `chat.editor.agentHost.existingSessionHarnessPicker.enabled` (default `false`, `included: false`) and is scoped to the main window only, so the ask — a clearer harness indicator for existing sessions in both the editor and the Agents window — is not yet delivered by default. This is a team-authored, reopened item in the `On Deck` holding bin, so no close is proposed.

## Change summary

Make the harness selected for an existing chat session more visually obvious than the gray placeholder text in the chat input, in both the editor and Agents windows.

## Best solution

Decide the rollout of the already-implemented disabled harness picker: either flip `chat.editor.agentHost.existingSessionHarnessPicker.enabled` on by default after the experiment reads out, or pick an alternative indicator — and settle whether the Agents window (currently excluded via `IsSessionsWindowContext.negate()` in chatExecuteActions.ts) gets the same treatment.
