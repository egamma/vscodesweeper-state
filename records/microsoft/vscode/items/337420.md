# Issue #337420 — Agents window hangs with thousands of binary text models and a stale origin/HEAD base branch

[https://github.com/microsoft/vscode/issues/337420](https://github.com/microsoft/vscode/issues/337420)

## Summary

Fresh, detailed report from a collaborator describing the Agents window hanging (200%+ CPU, 8-9GB memory) when a session's base-branch comparison lands on a stale/huge diff (thousands of files, hundreds of binaries), causing sustained text-model creation for PNG/GIF/MP4 resources. The reporter explicitly notes the exact hot function and causal link are unconfirmed (no JS CPU profile), so this needs more diagnosis before a fix is scoped.

## Change summary

Agents window becomes unresponsive processing thousands of binary text models when a session's base branch resolves to a stale origin/HEAD pointing at a huge, wrong diff.

## Best solution

Two things likely need attention: (1) base-branch selection in the agent host/session-workspace layer should not blindly trust a stale local origin/HEAD when the hosted repo's actual default branch differs, and (2) the changes/diff view and text-file model creation path should avoid eagerly materializing text models for binary resources (PNG/GIF/MP4) in large diffs — likely bounded/lazy loading. A JS CPU profile from the reporter or a controlled reproduction would help pin the exact hot path before scoping a fix.

- **Behavior:**

  > When a session's base branch is stale or resolves to a huge diff containing many binary files, the Agents window should not hang or spike CPU/memory processing those binaries as text models.
