# Issue #211424 — Right click on a file on the file explorer shifts into an already opened image instead of the one that is being clicked

[https://github.com/microsoft/vscode/issues/211424](https://github.com/microsoft/vscode/issues/211424)

## Summary

The Explorer right-click switching focus to an adjacent image preview is covered by the verified open issue tracking context menus making adjacent webviews steal focus. Consolidate there while preserving this report's Windows 11 and built-in image-preview reproduction.

## Change summary

Right-clicking an Explorer file while the left text editor is active unexpectedly activates the image preview in the right editor group.

## Best solution

Resolve context-menu-induced webview focus stealing under https://github.com/microsoft/vscode/issues/212679, including this built-in image-preview case, so opening an Explorer context menu does not activate an unrelated editor group.

## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/212679 is OPEN. Its reproduction opens a text document beside a webview, invokes a context menu in the sidebar or editor, and observes the webview becoming focused. It explicitly confirms the regression in 1.88 and 1.89, but not 1.87, and reports it with extensions disabled. This encompasses the present report's Explorer context menu activating the adjacent image preview.
- **Built-in image preview uses a webview:** extensions/media-preview/src/imagePreview/index.ts:15-48 defines ImagePreviewManager as a CustomReadonlyEditorProvider and resolves image editors through a vscode.WebviewPanel. The reported image is therefore a concrete built-in instance of the canonical issue's adjacent-webview scenario, not evidence of a third-party extension defect.
- **Independent Windows confirmation:** https://github.com/microsoft/vscode/issues/215547 independently reports Windows 11 Explorer right-clicks transferring focus to a webview, beginning with 1.88.1. Its below-editor layout differs, but corroborates the same context-menu-induced focus transfer. No runtime reproduction was performed in this read-only review.
- **Related but distinct older issue:** https://github.com/microsoft/vscode/issues/203876 is open, but concerns restoring keyboard focus to a link inside a webview after dismissing that webview's context menu. It does not establish ownership of the adjacent-webview activation reported here; https://github.com/microsoft/vscode/issues/212679 directly does.
- **Recent Explorer change is not proof of this fix:** Commit 49247edb6ab458e52a9e787945f0aa4985f129d0 adds selection of the context-menu target in src/vs/workbench/contrib/files/browser/views/explorerView.ts:698-705. Its diff addresses Explorer selection targeting, not adjacent image/webview activation, so it does not substantiate an implemented-on-main close.
