# Issue #334058 — [Linux/Regression] Segfault with --ozone-platform=x11 when KDE Global Menu is active

[https://github.com/microsoft/vscode/issues/334058](https://github.com/microsoft/vscode/issues/334058)

## Summary

A newly reported regression (1.135→1.136) where VS Code's Electron/Chromium main process segfaults on X11 when a D-Bus AppMenu registrar (KDE's kappmenu/kded6 appmenu module) is active; the crash trace points at GObject/GLib signal handling inside Chromium's Linux menu integration, not VS Code's own TypeScript/Electron-main code, so this is best tracked as an upstream Electron/Chromium (or GTK/libdbusmenu) defect rather than something fixable directly in this repo.

## Change summary

VS Code 1.136+ segfaults on Linux X11 (--ozone-platform=x11) at startup when a KDE D-Bus AppMenu registrar is present, a regression from 1.135.

## Best solution

Bisect the Electron/Chromium version bump between 1.135 and 1.136 to confirm which upstream change altered GTK/D-Bus AppMenu (libdbusmenu-glib / GObject signal) handling on X11, and either file/track it against the relevant Electron or Chromium issue tracker, or pin/patch the affected native integration if VS Code controls that code path.
