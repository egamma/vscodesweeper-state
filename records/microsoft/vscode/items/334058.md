# Issue #334058 — [Linux/Regression] Segfault with --ozone-platform=x11 when KDE Global Menu is active

[https://github.com/microsoft/vscode/issues/334058](https://github.com/microsoft/vscode/issues/334058)

## Summary

Genuine regression report, but the crash trace (content/browser/browser_main_loop.cc, GLib-GObject signal handler mismatch) points squarely at Chromium's Ozone-X11 backend interacting with KDE's libdbusmenu-glib global-menu integration — VS Code only forwards --ozone-platform to Electron and does not implement AppMenu/DBusMenu handling itself, so this is upstream territory to keep open and route, not close.

## Change summary

VS Code 1.136 segfaults on launch with --ozone-platform=x11 when KDE's Global Menu widget is active, working fine in 1.135.

## Best solution

File/trace this against the bundled Electron/Chromium version bump between 1.135 and 1.136 — the fix belongs in Chromium's Ozone X11 GTK AppMenu/DBusMenu integration (or Electron's packaging of it), not in VS Code's own TypeScript sources; a maintainer should bisect the Electron version change and consider reporting upstream to Electron/Chromium if not already tracked there.
