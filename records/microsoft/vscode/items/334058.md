# Issue #334058 — [Linux/Regression] Segfault with --ozone-platform=x11 when KDE Global Menu is active

[https://github.com/microsoft/vscode/issues/334058](https://github.com/microsoft/vscode/issues/334058)

## Summary

Real regression (1.135 → 1.136 introduced the crash) with two independent, detailed confirmations including crashpad dumps showing SIGSEGV in the Electron main/browser process before any VS Code log directory is created — this points to Chromium/Electron's Linux global-menu (D-Bus AppMenu registrar) integration, not VS Code's own TypeScript code, so it should stay open as an upstream-owned issue rather than be closed.

## Change summary

VS Code 1.136+ segfaults on Linux when launched with --ozone-platform=x11 while a KDE AppMenu/Global Menu D-Bus registrar (kded6 appmenu module) is active, a regression from 1.135.

## Best solution

Track this as an Electron/Chromium regression tied to the bundled Electron version bump (target 43.6.0 per .npmrc); a VS Code maintainer should bisect the Electron/Chromium release notes around the 1.135→1.136 Electron bump for changes to Linux GlobalMenuBar/AppMenu D-Bus handling and, if confirmed upstream, file/link a Chromium or Electron issue rather than attempt a local patch.
