# Issue #149552 — Bracket colorization w/ semantic tokens

[https://github.com/microsoft/vscode/issues/149552](https://github.com/microsoft/vscode/issues/149552)

## Summary

Keep open: current source still lacks semantic-token-controlled suppression of bracket colors, and the maintainer explicitly proposed a highlighting-only mechanism. This issue already owns a related duplicate and carries the correct area label.

## Change summary

Allow semantic token providers to suppress bracket colorization within identified tokens without changing synchronous bracket matching or typing behavior.

## Best solution

Support selective, presentation-only suppression of bracket colors based on semantic token information while preserving syntax-driven matching and auto-closing. A maintainer should settle the provider-facing contract before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/model/bracketPairsTextModelPart/colorizedBracketPairsDecorationProvider.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/common/tokens/sparseTokensStore.ts`, `src/vs/editor/test/common/model/bracketPairColorizer/getBracketPairsInRange.test.ts`
- **Validation:** Add an editor-model regression test using a semantic provider or equivalent semantic-token fixture: after semantic tokens arrive, designated brackets have no colorization decorations, brackets outside the designated tokens remain colored, and bracket-matching results are identical before and after semantic updates. Cover token removal and edits, and manually verify auto-closing with delayed semantic responses.
- **Behavior:**

  > A language extension can identify semantic tokens whose brackets should not receive bracket-pair colors without supplying equivalent TextMate scopes. Once that semantic information arrives, designated brackets are not colorized and unrelated brackets retain normal colorization. Semantic updates must not change bracket matching, auto-closing, or typing behavior. Acceptance checks cover delayed token arrival, token removal, and edits so suppression does not remain on unrelated text.
- **Trace:**

  > TokenizationTextModelPart.getLineTokens merges semantic styling into syntax tokens through SparseTokensStore.addSparseTokens, whose override mask preserves syntax token type and balanced-bracket metadata. TextBufferTokenizer consequently still recognizes brackets in syntax-level Other tokens even when their semantic type is comment. ColorizedBracketPairsDecorationProvider.getDecorationsInRange emits decorations for the resulting brackets without semantic suppression. The maintainer explicitly limits the intended solution to highlighting at https://github.com/microsoft/vscode/issues/149552#issuecomment-1127509125; do not alter shared matching or auto-closing semantics. Existing global colorization settings and TextMate bracket-scope controls do not provide the requested provider capability. https://github.com/microsoft/vscode/issues/163954 is related but additionally concerns mismatched pairs in inactive code, which is not settled by this presentation-only goal. The unresolved boundary is how providers express suppression and whether existing semantic types gain automatic suppression behavior.
- **Open decisions:**
  - Should existing semantic comment and string token types automatically suppress bracket colors, or should suppression require an explicit opt-in semantic modifier or separate provider contract?
