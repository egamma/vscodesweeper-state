# Issue #65663 — Temporarily Set Configuration For Save Operation

[https://github.com/microsoft/vscode/issues/65663](https://github.com/microsoft/vscode/issues/65663)

## Summary

Keep open: current configuration and Save Without Formatting do not provide the requested per-file, operation-scoped overrides for normal saves. This accepted Backlog request has 40 upvotes, but the API owner's objections to unrestricted participant suppression require agreement on a configuration-oriented contract before implementation.

## Change summary

Allow per-file save policy from extensions such as EditorConfig to coexist with VS Code's built-in whitespace and final-newline settings without persistent configuration changes.

## Best solution

Agree on a user-controlled, configuration-oriented way to reconcile file-specific save policy with built-in cleanup, preserving unrelated formatting and extension actions. Use the API owner's configuration-first guidance as the boundary rather than reviving unrestricted save-participant suppression.

Add focused regression cases to src/vs/workbench/contrib/codeEditor/test/browser/saveParticipant.test.ts.
- **Behavior:**

  > An extension needs to apply file-specific whitespace and final-newline policy during normal saves without built-in cleanup subsequently contradicting it. Existing language-level configuration is only a workaround because files of the same language can require different policies. The agreed behavior must preserve unrelated save actions, isolate each file's policy, and avoid persistent configuration churn. Acceptance should cover explicit save and autosave with conflicting settings and two same-language files.
- **Trace:**

  > TrimWhitespaceParticipant, FinalNewLineParticipant, and TrimFinalNewLinesParticipant in src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts read resource/language configuration directly; SaveParticipantsContribution registers these alongside code-action and formatting participants. The settings in src/vs/workbench/contrib/files/browser/files.contribution.ts are language-overridable booleans, while TextEditorOptions and TextDocumentWillSaveEvent in src/vscode-dts/vscode.d.ts expose no temporary cleanup-policy contract. MainThreadSaveParticipant in src/vs/workbench/api/browser/mainThreadSaveParticipant.ts connects extension pre-save handling to the pipeline. The existing Save Without Formatting command bypasses participants wholesale and therefore does not establish selective override semantics. https://github.com/microsoft/vscode/pull/124945 was rejected and never merged; https://github.com/microsoft/vscode/issues/65663#issuecomment-852849446 establishes configuration-first guidance and a boundary against suppressing other extensions. The uncertainty is the supported per-file policy and precedence contract, not whether the rejected patch should be revived; unrelated participant behavior must remain intact.
- **Open decisions:**
  - Should configuration-first handling remain user-configured conflict avoidance, or should VS Code support an explicitly user-authorized, nonpersistent per-file cleanup policy supplied by extensions?
  - If per-file policy is supported, which user, workspace, and language settings retain precedence, and how are conflicting policies from multiple extensions resolved visibly and predictably?

## Evidence

- **Remaining capability gap:** src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts: TrimWhitespaceParticipant, FinalNewLineParticipant, and TrimFinalNewLinesParticipant obtain their switches from IConfigurationService using the document resource and language. They do not consume an extension-supplied, operation-local override.
- **Existing configuration is partial coverage:** src/vs/workbench/contrib/files/browser/files.contribution.ts:237–259 registers files.trimTrailingWhitespace, files.insertFinalNewline, and files.trimFinalNewlines as LANGUAGE_OVERRIDABLE booleans. Users can disable conflicting cleanup, including by language, but this does not express differing EditorConfig policy for individual files sharing a language.
- **Existing command is not equivalent:** src/vs/workbench/contrib/files/browser/fileCommands.ts:506–514 implements workbench.action.files.saveWithoutFormatting with skipSaveParticipants: true. This skips the participant pipeline for the selected-editor save; it does not selectively reconcile the three settings during ordinary saves while retaining other participants.
- **Public API check:** src/vscode-dts/vscode.d.ts:690–732 exposes indentation and display options through TextEditorOptions, not the requested cleanup overrides. TextDocumentWillSaveEvent at lines 13503–13545 exposes document, reason, and waitUntil, with no participant-policy override; TextDocument.save() takes no options.
