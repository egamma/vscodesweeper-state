# Issue #312120 — Can we make extensions.json as the only source of truth

[https://github.com/microsoft/vscode/issues/312120](https://github.com/microsoft/vscode/issues/312120)

## Summary

A real extension-management request remains: VS Code supports manually maintaining workspace recommendations, but does not synchronize them with extension installation or enablement changes. The older related issues cover declarative enablement or forced installation rather than this same observable behavior, so the re-reviewed duplicate bar is not met.

## Change summary

Automatically add installed or enabled extensions to the workspace extensions.json file and remove them when disabled.

## Best solution

The extensions area should decide whether workspace recommendations may opt into synchronization with extension installation and enablement state, while preserving a clear distinction between team recommendations and each developer's personal extension choices.

## Vision fit

- **Fit:** unclear
- **Reason:** Consistent team environments fit the extension ecosystem theme, but automatically writing personal extension choices into shared workspace configuration may conflict with keeping extension customization user-controlled.
- **Evidence:** Public values: "The power lives in extensions" and users may install extensions that change the nature of VS Code; the roadmap does not settle whether those personal choices should automatically become shared workspace recommendations.

## Evidence

- **current source:** src/vs/workbench/services/extensionRecommendations/common/workspaceExtensionsConfig.ts defines extensions.json as recommendations/unwantedRecommendations and only changes those arrays through explicit toggleRecommendation and toggleUnwantedRecommendation calls; it has no installation or enablement synchronization.
- **existing capability:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts registers workbench.extensions.action.addExtensionToWorkspaceRecommendations and removeExtensionFromWorkspaceRecommendations, providing manual add/remove actions but not the requested automatic capture.
- **configuration semantics:** src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts describes recommendations as extensions that should be recommended to workspace users, not as an authoritative installed/enabled extension manifest.
- **related issue:** https://github.com/microsoft/vscode/issues/299826 is open but concerns force-installing bundled workspace-resource extensions; it explicitly excludes marketplace extensions and does not synchronize installation or disablement actions into extensions.json.
- **distinct older request:** https://github.com/microsoft/vscode/issues/40239 is open and older, but requests declarative workspace enable/disable state in a configuration file. It does not request automatically recording extension actions into the recommendations file, so it lacks the same reporter-observable symptom required for a duplicate close on re-review.
- **demand:** The issue has no comments or community upvotes, and no maintainer decision establishes the requested synchronization semantics.
