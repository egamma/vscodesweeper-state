# Issue #91861 — Minify dependencies and remove junk files

[https://github.com/microsoft/vscode/issues/91861](https://github.com/microsoft/vscode/issues/91861)

## Summary

The junk-file portion was substantially addressed, but current main still packages production dependencies largely as individual, unminified files inside `node_modules.asar`. The remaining bundling/minification opportunity is real but needs measurement and compatibility decisions, so this should remain open as under discussion.

## Change summary

Reduce the desktop distribution's size and packaging overhead by removing unnecessary dependency files and bundling or minifying shipped dependency code.

## Best solution

Measure the remaining contents and cost of `node_modules.asar`, then bundle or minify only dependency groups that are safe around dynamic loading, native modules, source maps, and license obligations. The resulting build should demonstrate a meaningful package-size or startup/install improvement without changing module resolution.

## Plan brief

- **Likely files:** `build/gulpfile.vscode.ts`, `build/.moduleignore`, `build/lib/asar.ts`
- **Validation:** Produce the existing minified macOS package, inventory and compare `node_modules.asar` byte/file counts before and after the eventual change, then run the packaged desktop smoke tests and verify native modules, worker entrypoints, and bare dependency imports still load.
- **Behavior:**

  > The packaged desktop application should contain only runtime-required dependency artifacts, with eligible JavaScript bundled or minified. Required licenses, native binaries, worker or subprocess entrypoints, and dynamically resolved modules must remain available. Acceptance requires a measured reduction in archive or application size, unchanged packaged-app startup and smoke-test behavior, and successful loading of native and bare-module dependencies.
- **Trace:**

  > Desktop dependency packaging runs through `cleanedDeps` in `build/gulpfile.vscode.ts`, where production files are filtered by `build/.moduleignore` and platform rules before being passed to `build/lib/asar.ts#createAsar`. Commit afb0e96b666ce964b6daf6d6e7a475c696240753 already removed broad classes of documentation, examples, tests, and sources, so that part of the report is substantially covered. On current main, retained JavaScript is still archived file-by-file without dependency-wide minification or bundling. The uncertainty begins at the safe bundling boundary: runtime resolution includes native modules, workers, subprocesses, dynamic imports, and explicit unpack/duplicate rules that must not change. License removal also cannot be treated as generic junk cleanup without preserving the distribution's notice obligations.
- **Open decisions:**
  - Which production dependencies can be bundled safely, and which must retain their package/file layout for dynamic resolution, workers, subprocesses, or native modules?
  - What package-size, install-time, or startup-time improvement is large enough to justify the build complexity?
  - Which license artifacts must remain in the packaged dependency tree versus being represented by the consolidated notices?

## Evidence

- **partial implementation:** https://github.com/microsoft/vscode/commit/afb0e96b666ce964b6daf6d6e7a475c696240753 introduced `build/.moduleignore` rules excluding dependency documentation, examples, tests, TypeScript sources, changelogs, and readmes from packaged node modules.
- **remaining source path:** `build/gulpfile.vscode.ts` still streams production dependency files through cleanup filters and `createAsar`; JavaScript receives source-map URL rewriting but no dependency-wide bundling or minification before entering `node_modules.asar`.
- **archive implementation:** `build/lib/asar.ts#createAsar` stores each retained file's original contents in the archive, with separate handling for native and externally spawned resources; it does not transform or minify JavaScript.
- **canonical search:** https://github.com/microsoft/vscode/issues/112718 concerned consolidating development-time `node_modules` to improve install and build-cache performance; it is closed and does not own the remaining shipped-dependency bundling request.
