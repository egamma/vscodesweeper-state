# Issue #91861 — Minify dependencies and remove junk files

[https://github.com/microsoft/vscode/issues/91861](https://github.com/microsoft/vscode/issues/91861)

## Summary

Current packaging already removes many non-runtime files, but it still archives largely unminified production dependencies rather than bundling them. The remaining optimization is valid but needs measurement and a compatibility design, so this should stay open as under discussion.

## Change summary

Reduce the installed application size and packaging overhead by pruning unnecessary dependency files and bundling or minifying runtime dependencies where safe.

## Best solution

Measure the size, installation, startup, and source-map effects of the remaining dependency payload, then selectively bundle safe JavaScript dependencies while preserving required licenses, package metadata, dynamic module resolution, native modules, and spawned-process entry points.

- **Fit:** aligned
- **Reason:** Reducing shipped files and runtime packaging overhead directly supports VS Code's lightweight, fast default experience.
- **Evidence:** Public values and durable themes explicitly state that "Performance trumps functionality" and identify performance, startup time, and download size as continuing investments.

- **existing cleanup:** build/.moduleignore lines 176-194 already exclude dependency docs, examples, tests, histories, changelogs, READMEs, contribution files, and most TypeScript sources, so the junk-file portion is partially implemented but not the broader bundling request.
- **core bundle boundary:** build/gulpfile.vscode.ts registers esbuild-vscode-min for minified VS Code source bundles, while packaged production dependencies follow the separate cleanedDeps/createAsar path.
- **maintainer context:** https://github.com/microsoft/vscode/issues/91861#issuecomment-593320430 explains that ASAR already improved installation and startup performance while acknowledging that the dependency contents could still be webpacked.
