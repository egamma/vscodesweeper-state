## Evidence

- **Independent reproduction:** https://github.com/microsoft/vscode/issues/255637#issuecomment-3067262346 confirms selection deletion crashing with Gboard across Chrome 137, 139, and 140, and an Android emulator running Chrome 124. Other tested keyboards did not crash; the problem also occurred with the soft keyboard. The attached trace identifies Chromium EditContext::DeleteSurroundingText as the unfinished frame, but does not establish the root cause.
- **Partial workaround and remaining symptoms:** https://github.com/microsoft/vscode/issues/255637#issuecomment-3102951319 reports that disabling EditContext prevents the crash, but deletion still requires two presses and paste/undo remain unreliable. https://github.com/microsoft/vscode/issues/255637#issuecomment-3068058295 reports related non-crashing problems in Firefox. The earlier setting advice contains a contradictory true value; current source confirms that disabling requires editor.editContext=false.
- **Current input paths:** src/vs/editor/common/config/editorOptions.ts registers editor.editContext with default true. EffectiveEditContextEnabled combines that setting with API support, and src/vs/editor/browser/view.ts::_instantiateEditContext selects NativeEditContext or TextAreaEditContext. NativeEditContext::_emitTypeEvent translates browser textupdate events into editor edits; textAreaEditContextInput.ts separately handles Android composition events. Reading these paths does not conclusively reproduce the reported browser crash or demonstrate its resolution.
