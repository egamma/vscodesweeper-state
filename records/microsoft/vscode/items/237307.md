# Issue #237307 — When pasting multiline text into a comment, it should keep all lines commented out

[https://github.com/microsoft/vscode/issues/237307](https://github.com/microsoft/vscode/issues/237307)

## Summary

This accepted Backlog request remains necessary: current paste handling inserts multiline text verbatim and does not preserve an existing line-comment context. It should be routed to editor auto-indentation for a product decision on the exact cross-language semantics.

## Change summary

Continue the surrounding comment marker onto every line of multiline text pasted into an existing comment.

## Best solution

Provide language-aware comment continuation for multiline paste while preserving ordinary paste behavior outside comments. The design should explicitly define supported comment forms, blank-line behavior, multi-cursor behavior, and whether this is default or configurable.

- **Fit:** aligned
- **Reason:** Preventing pasted text from unexpectedly becoming active code is consistent editor behavior that improves the developer inner loop.

- **Likely files:** `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/contrib/indentation/browser/indentation.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`, `src/vs/editor/contrib/indentation/test/browser/indentation.test.ts`
- **Validation:** Add editor cursor or indentation tests showing that multiline text pasted after a configured line-comment token leaves every inserted line commented, while equivalent paste outside a comment, blank lines, trailing newlines, and multi-cursor paste retain their intended behavior.
- **Behavior:**

  > When multiline text is pasted at a position inside an existing line comment, every inserted line should remain part of that comment rather than becoming active source text. Pasting outside comments must remain unchanged. Acceptance should cover a language-configured line-comment token, blank and trailing lines, and cursor placement after paste.
- **Trace:**

  > PasteOperation._simplePaste in src/vs/editor/common/cursor/cursorTypeEditOperations.ts currently inserts clipboard text through a plain replacement command without consulting comment configuration. AutoIndentOnPaste in src/vs/editor/contrib/indentation/browser/indentation.ts runs separately and adjusts leading whitespace only, while editor.action.addCommentLine in src/vs/editor/contrib/comment/browser/comment.ts is an explicit post-paste command. Existing paste coverage is in src/vs/editor/test/browser/controller/cursor.test.ts, with language-aware indentation fixtures in src/vs/editor/contrib/indentation/test/browser/indentation.test.ts. Preserve raw paste behavior outside a recognized comment and avoid changing Paste As, formatting, undo grouping, or multi-cursor distribution semantics. The exact earlier request at https://github.com/microsoft/vscode/issues/87639 was closed by the old upvote process rather than resolved.
- **Open decisions:**
  - Should continuation apply only to line comments, or also to block and documentation-comment interiors?
  - Should this behavior be the default paste semantic, follow auto-indent settings, or require a separate setting or Paste As mode?
  - How should blank lines, trailing newlines, selections spanning comment and code, and multiple cursors be handled?
