# Issue #237307 — When pasting multiline text into a comment, it should keep all lines commented out

[https://github.com/microsoft/vscode/issues/237307](https://github.com/microsoft/vscode/issues/237307)

## Summary

Keep open in the Backlog: this request passed the community threshold with 23 upvotes, and current paste handling still inserts multiline text without preserving the surrounding line-comment context.

## Change summary

Keep every pasted line commented when multiline text is pasted into an existing line comment.

## Best solution

Provide language-aware multiline paste behavior for line comments while leaving ordinary paste, block comments, selections, and multi-cursor paste unchanged outside the defined comment context.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add focused cursor paste tests for a language with a configured line-comment token, asserting that multiline text pasted in the chosen comment context remains commented while ordinary multiline paste and existing multi-cursor behavior remain unchanged.
- **Behavior:**

  > Pasting multiline text at the content position of a line comment should keep each pasted line inside that line comment. Ordinary paste outside comments must remain unchanged, and the operation must preserve indentation, undo behavior, selections, and multi-cursor semantics. Acceptance requires focused tests for commented and non-commented paste contexts.
- **Trace:**

  > TypeOperations.paste delegates to PasteOperation.getEdits in src/vs/editor/common/cursor/cursorTypeOperations.ts. PasteOperation._simplePaste in src/vs/editor/common/cursor/cursorTypeEditOperations.ts currently creates a ReplaceCommand directly from the original clipboard text, although CursorConfiguration already provides access to language configuration and the model provides tokenization. Existing coverage for simple and multiline paste is in src/vs/editor/test/browser/controller/cursor.test.ts. Keep the scope to line-comment-aware paste behavior; do not change generic comment toggling, block-comment formatting, or unrelated clipboard transformations. The earlier matching request at https://github.com/microsoft/vscode/issues/87639 was closed by the old upvote process rather than resolved.
- **Open decisions:**
  - Should comment preservation trigger only when the insertion point follows the line's leading comment delimiter, or anywhere the insertion point is tokenized as part of a line comment?
