# Issue #54248 — [json] package.json: complete package versions from scopes or private registries

[https://github.com/microsoft/vscode/issues/54248](https://github.com/microsoft/vscode/issues/54248)

## Summary

This remains a valid core feature request: package-version completion still queries the public npm registry directly, so scoped packages mapped to private registries are not covered. The linked merged work changed package-information lookup but did not implement registry-aware version completion.

## Change summary

Complete dependency versions in package.json for scoped packages and packages hosted on registries configured through .npmrc.

## Best solution

Make package-version completion use the package manager's effective registry configuration, while preserving the existing public-registry path and avoiding credential exposure or disruptive package-manager subprocesses.

## Plan brief

- **Likely files:** `extensions/npm/src/features/packageJSONContribution.ts`
- **Validation:** Add package.json completion coverage using a temporary npm configuration and mock private registry, asserting that version suggestions for a scoped package come from its configured registry while ordinary packages continue to use the default registry.
- **Behavior:**

  > When editing a dependency version in package.json, VS Code should offer versions for scoped and unscoped packages using the registry selected by the user's package-manager configuration, including private registries. Existing completion against the public npm registry must continue to work. Authentication material must not appear in completion output or logs, and a missing or unavailable registry must fail without blocking editing.
- **Trace:**

  > The issue identifies the built-in npm package contribution in extensions/npm/src/features/packageJSONContribution.ts as the owner. The maintainer discussion establishes that its lookup was limited to the default npm registry and that delegating registry resolution to the configured npm command was the proposed direction. https://github.com/microsoft/vscode/pull/56040 changed package-information lookup but does not establish completion for package versions through scoped/private registry mappings. The extension mentioned in the thread is a workaround, not the owner of this core behavior. Keep the scope to package.json package metadata/version completion; package-name discovery across private registries is separate.
- **Open decisions:**
  - Should built-in completion support only npm and its .npmrc registry mappings, or define user-visible behavior for other package managers as well?
  - May completion invoke the configured package-manager executable, with its authentication and network behavior, or must registry access remain inside VS Code's existing request path?
  - What timeout and fallback behavior should users observe when a configured private registry is unavailable?
