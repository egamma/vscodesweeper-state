## Change summary

## Plan brief

- **Likely files:** `src/vs/platform/environment/common/environmentService.ts`, `src/vs/workbench/services/themes/common/iconExtensionPoint.ts`, `src/vs/platform/theme/browser/iconsStyleSheet.ts`, `src/vs/base/browser/cssValue.ts`, `src/vs/base/common/network.ts`, `src/vs/code/electron-browser/workbench/workbench.html`, `src/vs/platform/protocol/electron-main/protocolMainService.ts`
- **Validation:** On Windows with a readable UNC share, launch a current build with VSCODE_EXTENSIONS set to that share and install an extension contributing a bundled .woff2 icon font. Trigger its icons and capture the font URL, effective CSP, and request result in Developer Tools. Compare with the same extension installed locally; acceptance requires successful font loading and correctly rendered icons in both configurations without weakening unrelated resource restrictions.
- **Behavior:**

  > Setting VSCODE_EXTENSIONS to a readable Windows UNC share causes bundled extension fonts to be reported as blocked:csp and their icons to disappear; installing the same extension locally works. Confirm this comparison on a current Windows build before changing behavior. Legitimate extension fonts should render from either configured location, with existing resource-access protections retained.
- **Trace:**

  > EnvironmentService.extensionsPath accepts VSCODE_EXTENSIONS, and ProtocolMainService adds that directory to its valid resource roots. IconExtensionPoint resolves contributed font paths against the extension location; iconsStyleSheet emits @font-face rules through cssValue.asCSSUrl and FileAccess.uriToBrowserUri. The URI conversion preserves a UNC server authority, whereas workbench.html's font-src allows 'self' and specific remote/CDN sources rather than arbitrary vscode-file authorities. This is a plausible explanation established by source inspection, not a current Windows reproduction. The uncertainty begins with whether the reporter's failing font uses this workbench contribution path or an extension-authored webview with its own CSP. Preserve UNC filesystem round-tripping, local font loading, and resource isolation; the Remote-SSH reports at https://github.com/microsoft/vscode/issues/334144 describe a different resource path.
