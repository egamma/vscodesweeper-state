# Issue #157957 — Visual Studio Code launch can't find custom prelaunch task

[https://github.com/microsoft/vscode/issues/157957](https://github.com/microsoft/vscode/issues/157957)

## Summary

Keep open: current source still cannot match user-authored object identifiers to built-in shell tasks, while launch IntelliSense continues to suggest that form. The reporter's string-label workaround does not resolve the task-system defect maintainers explicitly accepted.

## Change summary

Make object-form task references resolve built-in tasks consistently instead of suggesting references that fail before debugging starts.

## Best solution

Honor the agreed task-system direction: built-in shell and process tasks should be referenceable through user-authored ITaskIdentifiers, with launch IntelliSense describing a working reference shape. Preserve string-label lookup and extension-contributed task-definition matching.

## Evidence

This narrows the issue from generic task discovery to object-reference resolution.
- **Confirmed current-source failure:** src/vs/workbench/contrib/debug/browser/debugTaskRunner.ts:194-207 passes the object unchanged to taskService.getTask and emits 'Could not find the specified task' when lookup returns undefined. In src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts:953-1007, both configured-task lookup and the provider fallback filter through task.matches using TaskDefinition.createTaskIdentifier.
- **Identifier mismatch:** src/vs/workbench/contrib/tasks/common/tasks.ts:690-698 compares object references exclusively by _key. CustomTask.getDefinition at lines 777-810 assigns _key from the internal task ID, whereas TaskDefinition.createTaskIdentifier and KeyedTaskIdentifier.create construct a serialized definition key from the user-authored object. src/vs/workbench/contrib/tasks/common/taskConfiguration.ts:1604-1605 creates configured custom tasks using uuidMap.getUUID(taskName). Consequently, neither {task:label,type:'shell'} nor the maintainer-tested {label:label,type:'shell'} matches that UUID-backed definition.
- **Misleading completion remains:** src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts:181-197 still includes defaultSnippets with {task:'',type:''} for both preLaunchTask and postDebugTask. The suggested shell-task object therefore still reaches the incompatible lookup path.
