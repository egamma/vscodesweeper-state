# Issue #286989 — Font sharpening for the remote terminal of vscode on the windows platform

[https://github.com/microsoft/vscode/issues/286989](https://github.com/microsoft/vscode/issues/286989)

## Summary

Keep open: the original VS Code 1.108 resizing defect was confirmed fixed, but a later commenter reproduced similar font distortion in 1.110 Insiders specifically with GPU acceleration and terminal images enabled. Current main still couples image support to xterm transparency, so the remaining configuration-specific regression needs diagnosis.

## Change summary

GPU-accelerated terminal text becomes sharpened, compressed, or otherwise distorted after output and resizing, with a later reproduction tied to terminal image support.

## Best solution

Preserve stable terminal glyph rendering while GPU acceleration and supported terminal images are enabled. Diagnose whether the remaining alpha-canvas behavior belongs in VS Code's xterm configuration or requires an upstream xterm.js/Chromium change, then consolidate the younger https://github.com/microsoft/vscode/issues/299442 report here if the root cause matches.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts`, `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`, `src/vs/workbench/contrib/terminal/test/browser/xterm/xtermTerminal.test.ts`
- **Validation:** On Windows at 125% display scaling, enable GPU acceleration, toggle `terminal.integrated.enableImages`, print enough multiline output to fill the terminal, and repeatedly resize its height; verify glyph shape and sharpness remain stable while supported terminal images still render. Add or extend xterm terminal tests to lock down the selected transparency behavior during construction and configuration updates.
- **Behavior:**

  > Terminal text must retain stable glyph dimensions and rasterization while output accumulates or the terminal is resized. Enabling supported terminal images together with GPU acceleration must not make ordinary text sharpen, compress, or alternate between rendering states. Disabling images or GPU acceleration must remain supported, and image protocols must continue working according to the documented platform requirements.
- **Trace:**

  > The original 1.108.0 resize-dependent WebGL defect was reproduced upstream in https://github.com/xtermjs/xterm.js/issues/5606 and reporters confirmed that 1.108.1 resolved it. A later comment on this issue establishes a distinct remaining trigger in 1.110 Insiders: GPU acceleration plus `terminal.integrated.enableImages`. Current src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts maps `enableImages` directly to xterm's `allowTransparency` option at creation and update time, then loads the image addon only when WebGL is active; src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts documents that coupling. The younger https://github.com/microsoft/vscode/issues/299442 reports the same configuration-sensitive symptom and should be treated as corroborating evidence, not as the canonical issue for this re-review. Keep the scope to terminal glyph rendering under WebGL/image transparency; do not alter terminal font-family, font-size, shell, or remote-session behavior unless reproduction proves those paths contribute.
- **Open decisions:**
  - When terminal images are enabled, must VS Code preserve the platform's normal text antialiasing even if that requires a different image-compositing path, or is grayscale rendering acceptable provided glyph dimensions remain stable?

## Evidence

- **confirmed original regression:** Multiple reporters reproduced distorted terminal glyphs on Windows with GPU acceleration in VS Code 1.108.0; https://github.com/microsoft/vscode/issues/286870 records a maintainer reproduction at 125% display scaling and traces that original defect to https://github.com/xtermjs/xterm.js/issues/5606.
- **later recurrence:** The 2026-03-03 comment on this issue provides an A/B comparison on VS Code 1.110 Insiders: distortion occurs with `terminal.integrated.gpuAcceleration: on` plus `terminal.integrated.enableImages: true`, but not when either GPU acceleration or images is disabled.
- **current source path:** Current main still assigns `allowTransparency: config.enableImages` during terminal construction and configuration updates in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts, while `_refreshImageAddon` loads the image addon only alongside WebGL. src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts documents that enabling images also enables terminal transparency.
- **related report:** https://github.com/microsoft/vscode/issues/299442 reports the same image-enabled font degradation and remains open, but it was created after this re-reviewed issue and therefore cannot serve as its duplicate canonical.
- **not a valid duplicate close:** https://github.com/microsoft/vscode/issues/286870 is older and covered the original resizing symptom, but it is closed after an upstream fix; https://github.com/microsoft/vscode/issues/320367 is newer and primarily reports different intermittent glyph substitution and black-square symptoms.
