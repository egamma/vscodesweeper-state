# Issue #257707 — Tab order not working as expected in Copilot Chat for chat responses

[https://github.com/microsoft/vscode/issues/257707](https://github.com/microsoft/vscode/issues/257707)

## Summary

Keep open: maintainers confirmed that Tab should enter the focused response and identified this as broken existing keyboard guidance. Current source still relies on generic list-to-row tab handling, and neither the closed scrolling issue nor the later last-focused-message command owns this exact behavior.

## Change summary

After Ctrl/Cmd+Up focuses the latest chat response, Tab leaves that response instead of moving through its references, code blocks, and other interactive content.

## Best solution

Restore a predictable transition from the focused chat list row into that same response's first meaningful interactive element, then preserve normal document-order Tab navigation through the response.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/base/browser/ui/list/listWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`
- **Validation:** In a chat response containing references and a code block, focus the latest response with Ctrl/Cmd+Up and press Tab: focus must remain in that response and advance through its meaningful interactive elements in document order; Shift+Tab and Up/Down list navigation must remain unchanged.
- **Behavior:**

  > When Ctrl/Cmd+Up focuses a chat response, pressing Tab must enter that same response rather than restarting navigation elsewhere in the transcript. References, code blocks, and other interactive response content must be reachable in logical document order. Up/Down must continue navigating request and response rows, and Shift+Tab must provide the corresponding reverse traversal.
- **Trace:**

  > The Focus Chat List action in src/vs/workbench/contrib/chat/browser/actions/chatActions.ts calls ChatWidget.focusResponseItem(), which reaches ChatListWidget.focusLastItem() and focuses the final WorkbenchObjectTree row. A plain Tab at the list root is handled by DOMFocusController.onTab() in src/vs/base/browser/ui/list/listWidget.ts, which selects the first `[tabIndex]` descendant of the focused row. ChatListItemRenderer.renderTemplate() in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts creates multiple tab stops before and within response content, so first reproduce which descendant or external element receives focus on current main. Keep arrow-key row navigation, the newer last-focused-message command from https://github.com/microsoft/vscode/issues/268238, and ordinary Tab order outside chat unchanged.

## Evidence

- **confirmed regression:** Maintainer confirmation at https://github.com/microsoft/vscode/issues/257707#issuecomment-3115078164 says the documented keyboard flow is Ctrl/Cmd+Up followed by Tab and that it previously worked.
- **expected behavior:** Maintainer analysis at https://github.com/microsoft/vscode/issues/257707#issuecomment-3115099096 states that Tab should flow to the next document element after the response is focused.
- **current focus path:** src/vs/workbench/contrib/chat/browser/actions/chatActions.ts runs focusResponseItem() for Ctrl/Cmd+Up; ChatListWidget.focusLastItem() in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts sets the final tree item as focused and calls domFocus().
- **current tab path:** DOMFocusController.onTab() in src/vs/base/browser/ui/list/listWidget.ts searches the focused row for its first `[tabIndex]` descendant. ChatListItemRenderer.renderTemplate() in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts creates several tab stops in DOM order, including the username before response content, so this generic path needs live verification against the reported response-content order.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/231438 concerned keyboard scrolling and was closed in favor of page-scrolling work; its discussion explicitly points back to this issue for the anomalous Tab behavior.
- **existing command is not coverage:** https://github.com/microsoft/vscode/issues/268238 added Ctrl/Cmd+Shift+Up to restore the last focused message, but it is newer than this re-reviewed issue and does not address Tab entering the currently focused response.
