[https://github.com/microsoft/vscode/issues/342038](https://github.com/microsoft/vscode/issues/342038)

## Summary

Keep open: a maintainer confirmed checkpoint creation despite disabling chat.checkpoints.enabled, and current source still writes Agent Host checkpoint refs without consulting that setting. The report contains sufficient reproduction detail; the remaining work is to establish the control's scope and address repository clutter without breaking change tracking.

## Change summary

Copilot creates persistent refs/agents checkpoint references in users' Git repositories despite checkpoints being disabled, cluttering external history viewers.

## Best solution

Make checkpoint controls accurately govern repository writes, including read-only Ask conversations, while preserving explicitly enabled recovery and change tracking. Define safe lifecycle cleanup for existing checkpoint references rather than relying on manual Git database edits or external-viewer filtering.
