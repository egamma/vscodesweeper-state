# Issue #328545 — Allow the integrated browser to be selected in workbench.editor.associations

[https://github.com/microsoft/vscode/issues/328545](https://github.com/microsoft/vscode/issues/328545)

## Summary

This is a valid, currently unsupported integrated-browser workflow. Route it to the browser integration area for product and implementation review.

## Change summary

Allow file patterns such as `*.html` to select the integrated browser through `workbench.editorAssociations`.

## Best solution

Extend the browser editor resolver to support eligible local HTML resources and translate them into browser-view inputs, while preserving workspace-trust and desktop-only constraints. This should expose `workbench.editor.browser` as a valid association without changing the existing explicit command.

- **Fit:** aligned
- **Reason:** Making local HTML previews directly selectable improves the integrated browser's role in the developer inner loop.
- **Evidence:** Integrated browser development is a current agent-experience priority, and the public durable themes include workbench UX and the developer inner loop.

## Evidence

- **resolver limitation:** `src/vs/workbench/contrib/browserView/electron-browser/browserView.contribution.ts` registers `workbench.editor.browser` with `RegisteredEditorPriority.exclusive` and only supports the `vscode-browser` scheme, so ordinary file resources cannot resolve to it through `workbench.editorAssociations`.
- **association schema:** `src/vs/workbench/browser/parts/editor/editorConfiguration.ts` excludes exclusive editors from the generated `workbench.editorAssociations` candidates.
- **partial existing capability:** `src/vs/workbench/contrib/browserView/electron-browser/features/browserTabManagementFeatures.ts` provides `Open in Integrated Browser` for local HTML files, but only as an explicit command that creates a separate browser-view resource; it does not satisfy automatic file association.
- **related implementation:** https://github.com/microsoft/vscode/issues/309057 delivered the explicit local-HTML command, confirming local HTML is supported while leaving this automatic association workflow distinct.
