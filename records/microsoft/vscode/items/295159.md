# Issue #295159 — Splitting a terminal window will open the terminal in the main workbench window, not the terminal window

[https://github.com/microsoft/vscode/issues/295159](https://github.com/microsoft/vscode/issues/295159)

## Summary

Still reproduces on current main: the `splitInstance` method in the terminal editor service opens the split with `SIDE_GROUP`, which resolves to the main window's editor groups rather than the auxiliary terminal window's groups.

## Change summary

Splitting a terminal editor in an auxiliary (terminal) window opens the new split terminal in the main workbench window instead of the same auxiliary window.

## Best solution

Fix `TerminalEditorService.splitInstance` to resolve the target editor group relative to the window containing the instance being split, rather than using the global `SIDE_GROUP` constant which defaults to the main window. The group of the instance being split is already retrieved — the fix should use that group's window context when opening the split editor.
