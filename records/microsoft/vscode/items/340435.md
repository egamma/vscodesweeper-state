## Summary

Well-diagnosed, source-confirmed bug with an open fixing PR already attached — keep open and let that PR land rather than closing or routing elsewhere.

## Change summary

After an MCP server reconnects mid-turn, subsequent tool-confirmation requests for that server's tools arrive with no `ToolCallContributor`, so clients can't attribute them to their MCP server.

## Best solution

Land https://github.com/microsoft/vscode/pull/340436, which appears to implement exactly the reporter's proposed fix (threading `request.serverName` into `_getToolCallContributor` for the `mcp` permission-request kind).
