# Issue #182098 — Support setting a badge-only color in file decorations

[https://github.com/microsoft/vscode/issues/182098](https://github.com/microsoft/vscode/issues/182098)

## Summary

Keep open: current main still lacks per-decoration control over whether a text badge's color also affects the resource label. The existing user setting is only a blanket override, and the discussion explicitly supports letting extensions choose per decoration.

## Change summary

Allow extension-provided file decorations to color a badge without recoloring the associated resource label.

## Best solution

Provide a backward-compatible FileDecoration API for choosing badge-only coloring per decoration, while retaining existing defaults and user overrides. Settle the public contract with the API owners rather than changing coloring defaults across all trees.

- **Fit:** aligned
- **Reason:** This is a concrete extension-API gap that lets extensions present meaningful status badges without unnecessarily emphasizing entire resource labels.

- **Behavior:**

  > An extension must be able to return a colored text badge without changing the associated resource label's foreground. Existing decorations must retain their current behavior, and user controls for decoration colors and badges must remain effective. Acceptance includes a colored M beside an otherwise normally colored label and unchanged rendering for existing full-color decorations.
- **Trace:**

  > FileDecoration currently exposes one color, and ExtHostDecorations.$provideDecorations transports it through MainThreadDecorations into IDecorationData. DecorationRule._appendForOne and _appendForMany in src/vs/workbench/services/decorations/browser/decorationsService.ts apply that color to both label and text-badge CSS. ResourceLabel in src/vs/workbench/browser/labels.ts can suppress label coloring independently, but the choice comes from surface-wide options; extension trees read those options from explorer.decorations in treeView.ts. The discussion at https://github.com/microsoft/vscode/issues/182098 supports extension-selected behavior rather than uniform tree defaults. Preserve existing SCM and Explorer defaults, user overrides, and behavior for providers that do not opt in. The remaining uncertainty is the public API contract, not whether the existing setting satisfies the request.
- **Open decisions:**
