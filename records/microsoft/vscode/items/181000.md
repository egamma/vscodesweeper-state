# Issue #181000 — Search & Replace is behaving strange for readonly files

[https://github.com/microsoft/vscode/issues/181000](https://github.com/microsoft/vscode/issues/181000)

## Summary

The defect remains traceable in current main: search replacement can mutate a configured-readonly buffer, while the text-file model deliberately neither marks it dirty nor saves it. Keep this open in search; the existing discussion and files.readonlyInclude reproduction provide enough information to proceed.

## Change summary

Search & Replace modifies readonly file buffers and presents changes that are silently discarded when the editor is reopened.

## Best solution

Search replacement should respect provider- and configuration-defined readonly state before modifying file contents, without implying that an unapplied replacement succeeded. Preserve ordinary writable-file replacement and the separate handling of overridable OS permissions.
