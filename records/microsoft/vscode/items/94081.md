# Issue #94081 — Confusion about how EnvironmentVariableCollection handles multiple extensions changing the same variable 

[https://github.com/microsoft/vscode/issues/94081](https://github.com/microsoft/vscode/issues/94081)

## Summary

Still reproduces on main: the MergedEnvironmentVariableCollection constructor silently drops a later extension's Append/Prepend when an earlier extension's Replace is already at position [0] in the mutator list. The acknowledged ordering issue from the 2020 API call has not been addressed.

## Change summary

When multiple extensions mutate the same environment variable, a Replace from one extension silently blocks Append/Prepend mutations from other extensions, regardless of activation order.

## Best solution

Revise the merge logic in `MergedEnvironmentVariableCollection` (src/vs/platform/terminal/common/environmentVariableCollection.ts, lines 45–64) so that a Replace sets the base value but still allows subsequent Append/Prepend mutations from other extensions to layer on top. The ordering semantics should be documented in the API so extension authors understand the composition model.
