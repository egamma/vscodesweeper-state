# Issue #94081 — Confusion about how EnvironmentVariableCollection handles multiple extensions changing the same variable 

[https://github.com/microsoft/vscode/issues/94081](https://github.com/microsoft/vscode/issues/94081)

## Summary

The reported result remains reproducible from current source: a restored Replace collection causes the later extension's Append contribution to be discarded. Keep this open; the maintainer acknowledged the ordering problem, but current tests encode the opposite precedence and warrant a compatibility decision before changing it.

## Change summary

A nonpersistent extension's later Append contribution is ignored when another extension has already restored a persistent Replace contribution for the same terminal environment variable.

## Best solution

Resolve the acknowledged ordering mismatch in the terminal environment collection API, with an explicit cross-extension precedence contract and regression coverage for persisted Replace followed by nonpersistent Append. Account for existing extensions that rely on the currently tested first-replacement precedence.
