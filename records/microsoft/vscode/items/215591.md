# Issue #215591 — Installation appears to be corrupt

[https://github.com/microsoft/vscode/issues/215591](https://github.com/microsoft/vscode/issues/215591)

## Summary

Still valid on main: the integrity service compares the running process's expected checksums against on-disk files that were updated externally, producing a misleading 'corrupt' warning. No fix has landed for this scenario.

## Change summary

VS Code shows a false 'Installation appears to be corrupt' warning when reloading a window after the installation was updated externally (e.g., via apt) while still running.

## Best solution

The integrity service (src/vs/workbench/services/integrity/electron-browser/integrityService.ts) should detect when the running build's commit differs from the on-disk build's commit (a version mismatch from an external update) and show a more appropriate 'restart required' message instead of a corruption warning, or suppress the check entirely in that case.
