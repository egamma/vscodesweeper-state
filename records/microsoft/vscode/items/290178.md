- **Validation:** Add prompt-validator coverage using real file-service resources for an existing relative Markdown target, an existing target with a `#fragment`, and a multi-root workspace; each valid target must produce no file-not-found diagnostic while a missing target still does.
- **Behavior:**

  > Prompt and instruction files must not report “File not found” when a relative Markdown link resolves to an existing file. URL query or fragment components must not be treated as part of the filesystem path. The behavior must hold for repository-root and multi-root workspaces, while genuinely missing targets continue to produce diagnostics.
- **Trace:**

  > The diagnostic originates in the Copilot prompt validator’s `validateBody` flow, where Markdown references are resolved through `body.resolveFilePath(ref.content)` and checked with `this.fileService.exists(resolved)`. Reports show two potentially related paths: fragment-bearing links visibly retain the fragment in the filesystem resource, while fragment-free links resolve to the displayed correct path but still fail existence checks. https://github.com/microsoft/vscode/issues/308367 is a newer multi-root variant and may provide additional reproduction evidence, but it cannot be the canonical duplicate for this re-reviewed older issue. Preserve missing-file diagnostics and avoid changing the built-in Markdown validator, which does not own these diagnostics.
