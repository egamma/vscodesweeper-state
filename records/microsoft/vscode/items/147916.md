# Issue #147916 — Warn when auth extension is disabled

[https://github.com/microsoft/vscode/issues/147916](https://github.com/microsoft/vscode/issues/147916)

## Summary

Keep open for actionable disabled-provider diagnostics. Re-enabling Microsoft Authentication resolved the reporter's sign-in failure, but the maintainer accepted improving the error, and the current shared authentication path still reports a generic registration timeout.

## Change summary

Explain when sign-in cannot proceed because the authentication provider's built-in extension is disabled, and make the recovery discoverable.

## Best solution

Improve the shared authentication failure experience so an explicitly requested sign-in identifies a disabled provider extension and explains how to enable it. Preserve intentional extension disablement and distinguish it from activation failures or account-service errors.
