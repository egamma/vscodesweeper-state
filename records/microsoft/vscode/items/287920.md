# Issue #287920 — [GitHub Copilot Telemetry] Add consistent telemetry for Chat Submit

[https://github.com/microsoft/vscode/issues/287920](https://github.com/microsoft/vscode/issues/287920)

## Summary

This remains the canonical design issue for consistent chat-submit telemetry. The inline-chat satellite was explicitly consolidated here, while the disabled-model panel gap remains open and the thread has not settled whether targeted request-event fixes or a dedicated submit event should provide the experiment contract.

## Change summary

Provide a reliable telemetry event for user-initiated chat submissions, including the chat surface and experiment-relevant mode properties.

## Best solution

Define one telemetry contract at the user-attempt boundary that consistently covers panel and inline chat, including attempts stopped before a model request, while leaving the generic workbench action event command-agnostic. Resolve how `isAuto`, command or mode, and surface are represented, then use the narrower panel issue to validate the disabled-model case.

- **current source:** src/vs/base/common/actions.ts defines `WorkbenchActionExecutedEvent` with only generic `id`, `from`, and optional `detail` fields. src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts routes `workbench.action.chat.submit` to `widget.acceptInput(...)` without emitting a dedicated submit event.
- **request boundary:** extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts emits `request.sent` only once an HTTP or WebSocket model request has reached the transport path (around lines 1235 and 1524), so it cannot represent every user submission attempt that stops before request creation.
