# Issue #282418 — Regression in vscode.workspaceConfiguration.Update: version 1.106.3 throws CodeExpectedError

[https://github.com/microsoft/vscode/issues/282418](https://github.com/microsoft/vscode/issues/282418)

## Summary

The regression remains source-reproducible on current main: replacing a standalone launch configuration produces an undefined operation key, and the policy validation mistakenly inspects that undefined key. The issue should remain open for a bounded configuration-service fix and regression test.

## Change summary

Updating the complete workspace-folder launch configuration through `WorkspaceConfiguration.update` fails when the environment contains a managed setting, preventing creation of `launch.json`.

## Best solution

Restore full `launch.json` updates while retaining policy enforcement for actual managed configuration keys, with coverage for a workspace-folder launch update when an unrelated policy is active.

## Evidence

- **current source defect:** In src/vs/workbench/services/configuration/common/configurationEditing.ts, getConfigurationEditOperation returns `key: jsonPath[jsonPath.length - 1]` for standalone configuration replacement; for a folder `launch` update, `jsonPath` is empty and the resulting operation key is undefined. validate then unconditionally calls `this.configurationService.inspect(operation.key).policyValue`, matching the reported `Unable to write undefined` failure.
- **current trigger:** The reporter's `config.update('launch', ..., vscode.ConfigurationTarget.WorkspaceFolder)` selects the full standalone launch-file path in WORKSPACE_STANDALONE_CONFIGURATIONS. When any policy-backed setting exists, inspection of the undefined key can expose a policy value and reject the unrelated launch write.
- **independent confirmation:** The newer open report https://github.com/microsoft/vscode/issues/327114 reproduces the same observable failure on VS Code 1.130.0 when configuring launch settings while any setting has `@hasPolicy`. Because it was created after this re-reviewed issue, it cannot be the canonical duplicate.
