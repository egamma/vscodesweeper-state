# Issue #143514 — Workspace root folder gets unnecessary nested in Explorer after VSC being restarted

[https://github.com/microsoft/vscode/issues/143514](https://github.com/microsoft/vscode/issues/143514)

## Summary

The inconsistent Explorer hierarchy remains source-reproducible on current main. The issue is already accepted as a bug in the Backlog, and neither the existing expansion setting nor the related historical fix addresses whether the single workspace root is displayed.

## Change summary

Keep a saved one-folder workspace from gaining an additional visible root-folder level in Explorer after VS Code restarts.

## Best solution

Make the Explorer hierarchy for a saved one-folder workspace consistent before and after restart, preserving the flat presentation rather than adding a visible root-folder level only after reopening.

## Evidence

- **current reload path:** In src/vs/workbench/contrib/files/browser/views/explorerView.ts, ExplorerView.setTreeInput uses the roots array whenever WorkbenchState is not FOLDER. A saved workspace therefore starts with the workspace root as a tree element after reload.
- **transition inconsistency:** ExplorerView reacts to onDidChangeWorkbenchState only by updating title casing, while ExplorerViewletViewsContribution keeps the existing Explorer view registered when transitioning between non-empty folder and workspace states. ExplorerService calls setTreeInput when model roots change, but saving the same root as a workspace does not change those roots, leaving the pre-save flat input until restart.
- **existing setting is partial:** The registered explorer.expandSingleFolderWorkspaces setting in src/vs/workbench/contrib/files/browser/files.contribution.ts controls whether the sole root is expanded during initialization; it does not hide that root or provide the flat presentation requested here.
- **related fix is not coverage:** Commit https://github.com/microsoft/vscode/commit/f781291461a7a172d914160b5b4d17d30118dd67 fixed https://github.com/microsoft/vscode/issues/134665 by preserving collapse state and adding explorer.expandSingleFolderWorkspaces. Its diff changes root expansion, not whether the root row is rendered, so it does not resolve this report.
- **accepted backlog bug:** The issue carries the maintainer-applied bug and file-explorer labels and is assigned to the Backlog milestone; no later maintainer comment reverses that accepted classification.
