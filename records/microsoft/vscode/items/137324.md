# Issue #137324 — Merge Conflict incorrectly removing conflict markers

[https://github.com/microsoft/vscode/issues/137324](https://github.com/microsoft/vscode/issues/137324)

## Summary

Verified duplicate: the older open canonical reports the same observable failure—using another conflict CodeLens before decorations refresh applies stale ranges and deletes unrelated lines. Consolidating this report preserves a single place to track the remaining defect.

## Change summary

Accepting another merge conflict while CodeLens decorations are stale can apply the resolution at obsolete line ranges and remove unrelated text.

## Best solution

Track and fix the stale-range handling in https://github.com/microsoft/vscode/issues/107821 so conflict actions cannot modify text using a conflict descriptor captured before the document changed.

- **same root cause:** extensions/merge-conflict/src/codelensProvider.ts passes a captured DocumentMergeConflict object to each CodeLens command, and extensions/merge-conflict/src/commandHandler.ts accepts that known conflict without revalidating its ranges against the current document.
