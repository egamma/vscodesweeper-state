# Issue #137324 — Merge Conflict incorrectly removing conflict markers

[https://github.com/microsoft/vscode/issues/137324](https://github.com/microsoft/vscode/issues/137324)

## Summary

Still reproduces on main: the merge-conflict codelens captures conflict range objects at render time, and a stale reference is used when a second Accept is clicked before the codelens refreshes — applying the edit at wrong line numbers. No fix has landed.

## Change summary

Clicking two merge-conflict Accept codelens actions in quick succession applies the second edit at wrong line numbers, corrupting the file.

## Best solution

Guard `commandHandler.ts#accept()` against stale conflict data by re-scanning the document (or checking `document.version`) before applying the edit when the conflict was passed as a `'known-conflict'` argument. Alternatively, invalidate/disable outstanding codelens immediately on the first edit so stale links cannot be clicked.
