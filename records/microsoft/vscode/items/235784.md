# Issue #235784 — "Clear All Output" is greyed out and doesn't clear execution count unless output is available

[https://github.com/microsoft/vscode/issues/235784](https://github.com/microsoft/vscode/issues/235784)

## Summary

Keep open: current source still disables Clear All Outputs when cells have execution counts but no outputs. The cell-level workaround and fixes for the separate execution-count persistence regression do not cover this toolbar-enablement request.

## Change summary

Allow Clear All Outputs to clear notebook execution counts even when no cell has produced output.

## Best solution

Make the notebook-wide clearing action available for completed cells with execution counts and no output, preserving its existing output-clearing behavior and protection of actively executing cells.

- **Behavior:**

  > A notebook containing completed cells with execution counts but no displayed outputs must allow the user to invoke Clear All Outputs from its toolbar. Invoking it clears those completed cells' execution counts both visually and in the saved notebook. Mixed notebooks continue to clear outputs and completed execution counts together. Actively executing cells retain the existing protection against clearing their execution metadata.
- **Trace:**

  > ClearAllCellOutputsAction in src/vs/workbench/contrib/notebook/browser/controller/editActions.ts registers notebook.clearAllCellsOutputs with NOTEBOOK_HAS_OUTPUTS as its precondition. NotebookEditorContextKeys._handleDidChangeModel in src/vs/workbench/contrib/notebook/browser/viewParts/notebookEditorWidgetContextKeys.ts derives that key only from output presence and listens to output changes, not execution metadata. ## Evidence

- **Current enablement gap:** src/vs/workbench/contrib/notebook/browser/controller/editActions.ts:316–342 registers notebook.clearAllCellsOutputs with precondition NOTEBOOK_HAS_OUTPUTS for both notebook-toolbar and editor-title placement. In src/vs/workbench/contrib/notebook/browser/viewParts/notebookEditorWidgetContextKeys.ts, NotebookEditorContextKeys._handleDidChangeModel computes that key exclusively from outputsViewModels.length > 0, ignoring executionOrder. Running only import statements therefore leaves the action disabled.
- **Existing capability is partial:** ClearAllCellOutputsAction.runWithContext in editActions.ts:347–377 already clears executionOrder and execution timing metadata for non-executing cells, including cells without outputs, when invoked. ClearCellOutputsAction, command notebook.cell.clearOutputs, also clears execution metadata without an output prerequisite on its command registration. These handlers do not remove the notebook-wide toolbar's output-only precondition; notebook.contribution.ts exposes no setting that changes it.
- **Maintainer-confirmed workaround:** https://github.com/microsoft/vscode/issues/235784#issuecomment-2533207066 recommends Notebook: Clear Cell Outputs and explicitly acknowledges that it does not fix the disabled icon.
