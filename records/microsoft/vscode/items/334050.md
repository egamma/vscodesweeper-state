# Issue #334050 — GitHub username in Accounts menu does not update after renaming the account on github.com

[https://github.com/microsoft/vscode/issues/334050](https://github.com/microsoft/vscode/issues/334050)

## Summary

Traced the defect in current main: GitHubAuthenticationProvider.readSessions() only calls getUserInfo() to refresh the account label/avatar when a stored session lacks an `account` object; once a session has one (which it does after any login), the cached label is reused verbatim forever, so a username change on github.com never gets picked up, matching the report exactly.

## Change summary

After renaming a GitHub account on github.com, VS Code's Accounts menu keeps showing the old username indefinitely, surviving reload, restart, and re-sign-in.

## Best solution

In extensions/github-authentication/src/github.ts (GitHubAuthenticationProvider.readSessions / tokenToSession), decide and implement a strategy to periodically or opportunistically re-verify the cached account label/avatar against getUserInfo() instead of trusting the stored `session.account` forever.
