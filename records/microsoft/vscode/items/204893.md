# Issue #204893 — Allow globally disabling extensions from withinn an untrusted workspace

[https://github.com/microsoft/vscode/issues/204893](https://github.com/microsoft/vscode/issues/204893)

## Summary

Valid feature request — the DisableGloballyAction only enables itself when an extension is in EnabledGlobally/EnabledWorkspace state, so extensions with DisabledByTrustRequirement cannot be globally disabled from that context. Still unaddressed on main.

## Change summary

Allow globally disabling extensions from an untrusted workspace where they are auto-disabled by trust requirements.

## Best solution

Extend `DisableGloballyAction.update()` in `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts` to also enable the action when the extension's enablement state is `DisabledByTrustRequirement` (and possibly other auto-disabled states), so users can globally disable extensions without needing to open a trusted workspace first.
