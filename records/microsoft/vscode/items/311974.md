# Issue #311974 — Support background / agent-owned browser pages

[https://github.com/microsoft/vscode/issues/311974](https://github.com/microsoft/vscode/issues/311974)

## Summary

Ownership infrastructure and some background-page behavior exist, but browser tools still request editor opening and ordinary tab disposal still destroys the page. Keep this team-authored request open: the linked merged PR explicitly implements only part of it.

## Change summary

Allow agents to operate browser pages without opening workbench tabs, with page lifetime controlled by the owning agent session.

## Best solution

Complete session-owned page lifecycle independently of editor presentation, retaining the ability to reveal a page when needed. Existing ownership and Sessions-window handling provide a foundation, but do not establish the full requested contract.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts`, `src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts`, `src/vs/workbench/contrib/browserView/common/browserEditorInput.ts`, `src/vs/sessions/contrib/browserView/browser/sessionBrowserView.ts`
- **Validation:** Exercise an agent-created page without any editor tab: read and interact with it, reveal and close its tab, and verify the page remains usable until the agreed owning-session lifecycle ends. Verify ordinary user-owned tabs retain their current close behavior and session cleanup leaves no orphan pages.
- **Behavior:**

  > Agents can create and operate browser pages without opening them in the workbench. Revealing or closing a page's editor tab must not determine the lifetime of an agent-owned page. Acceptance must cover automation while no tab exists, continued operation after closing a revealed tab, and cleanup at the agreed session-lifecycle boundary. User-owned browser tabs retain their existing behavior.
- **Trace:**

  > OpenBrowserTool._openNewPage in src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts stamps agent ownership but supplies editor-opening options. BrowserViewWorkbenchService.createBrowserView supports creation without those options, while _openEditorForCreatedView supports presentation vetoes. BrowserEditorInput.dispose still disposes its model unless vetoed. SessionBrowserViewController in src/vs/sessions/contrib/browserView/browser/sessionBrowserView.ts adds inactive-session presentation suppression and session-switch lifecycle protection, but attaches lifecycle tracking through editor events. The merged https://github.com/microsoft/vscode/pull/312166 explicitly describes itself as partial work for this issue. Preserve user-owned tab semantics, page-sharing restrictions, and storage isolation; https://github.com/microsoft/vscode/issues/297474 is related headless-browser work, and https://github.com/microsoft/vscode/issues/332409 identifies a separate hidden-page interaction risk.
- **Open decisions:**
  - Should agent-created pages remain hidden by default, or should background presentation be an explicit tool option or user preference?
  - Which owning-session transitions end a page's lifetime: disposal, archival, removal, or another explicit boundary, and should pages survive session restoration?

## Evidence

- **Partial implementation:** https://github.com/microsoft/vscode/pull/312166 is merged and its body says 'Part of https://github.com/microsoft/vscode/issues/311974'. It added browser ownership and creation infrastructure, not an explicit claim that the complete request was delivered.
- **Current tool presentation:** src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts, OpenBrowserTool._openNewPage, creates an agent-owned view but passes { preserveFocus: true } as editor-opening options. BrowserViewWorkbenchService.createBrowserView invokes _openEditorForCreatedView whenever those options are provided; preserving focus is not equivalent to avoiding a tab.
- **Current lifecycle boundary:** src/vs/workbench/contrib/browserView/common/browserEditorInput.ts, BrowserEditorInput.dispose, disposes the browser model unless an onBeforeDispose listener vetoes disposal. Agent ownership alone does not detach page lifetime from tab lifetime.
- **Existing background support is partial:** src/vs/sessions/contrib/browserView/browser/sessionBrowserView.ts, SessionBrowserViewController, suppresses editor opening for known inactive sessions and vetoes disposal during session switches. Its lifecycle tracking attaches through editor-opening/group events; this is narrower than general session-owned, tab-independent browser pages. BrowserViewWorkbenchService also permits creation without editor-opening options, but the standard open tool supplies them.
- **Related request is not a verified canonical:** https://github.com/microsoft/vscode/issues/297474 is open and older, requesting headless browser testing across subagents and worktrees. It does not explicitly establish agent-session ownership or tab-independent lifecycle, so it does not clearly absorb this request's full scope under the stronger re-review duplicate bar. https://github.com/microsoft/vscode/issues/332409 separately reports interaction failures on hidden pages and is newer.
