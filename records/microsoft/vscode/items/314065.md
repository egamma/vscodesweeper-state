# Issue #314065 — vscode remote-cli ssh executable does NOT accept --user-data-dir switch

[https://github.com/microsoft/vscode/issues/314065](https://github.com/microsoft/vscode/issues/314065)

## Summary

The remote CLI (`server.cli.ts`) intentionally excludes `--user-data-dir` because the remote server's data directory is set at server startup, not per CLI invocation — the CLI is a thin proxy that forwards commands to the already-running server or the desktop client, neither of which can change their user-data-dir mid-session.

## Change summary

The `code` remote CLI on a connected SSH host rejects `--user-data-dir` with "not supported for code."

## Best solution

This is as-designed. To use a custom data directory on the remote, the VS Code Server must be started with `--user-data-dir` at launch time (via the server startup arguments), not through the integrated terminal's `code` CLI proxy. The reporter should configure the server-side data directory through the Remote SSH extension's server startup settings instead.

- **server sets user-data-dir at startup:** src/vs/server/node/server.main.ts line 45: `args['user-data-dir'] = USER_DATA_PATH;` — the server sets its own user-data-dir at startup time, not from per-invocation CLI arguments.
- **CLI is a proxy:** The remote CLI (server.cli.ts) is documented as a 'standalone CLI app that opens VS Code from a remote terminal' — it forwards commands to either the desktop client (VSCODE_CLIENT_COMMAND) or the running server (VSCODE_IPC_HOOK_CLI), neither of which can change their data directory after startup.
