# Issue #314065 — vscode remote-cli ssh executable does NOT accept --user-data-dir switch

[https://github.com/microsoft/vscode/issues/314065](https://github.com/microsoft/vscode/issues/314065)

## Summary

The remote CLI intentionally excludes --user-data-dir: it sends requests to the connected desktop instance rather than starting a Linux desktop instance with separate user data. Host-specific Linux settings are supported through Remote Settings, so the reported warning is expected behavior.

## Change summary

The reporter wants the remote Linux settings used in a Windows-to-Linux SSH session and encounters an unsupported-option warning for --user-data-dir.

## Best solution

Keep the remote CLI's existing process boundary and configure the desired host-specific settings through Preferences: Open Remote Settings (JSON). Explain that this does not automatically load an existing Linux desktop profile or its entire user-data directory.

- **Proposed comment:**

  > Thanks for the report. The remote-terminal `code` command communicates with your connected Windows VS Code instance; it does not launch a Linux desktop instance, so `--user-data-dir` is intentionally unsupported.
  > 
  > For Linux-host-specific settings, run **Preferences: Open Remote Settings (JSON)** (`workbench.action.openRemoteSettingsFile`) while connected and copy the applicable settings there. This does not automatically load your existing Linux desktop profile or its entire user-data directory. The settings model is documented at https://code.visualstudio.com/docs/remote/ssh#_ssh-hostspecific-settings.

## Evidence

- **Intentional CLI restriction:** src/vs/server/node/server.cli.ts:40–84 explicitly rejects user-data-dir for the client-command path and omits it from the pipe-path allowlist. main removes unsupported options before parsing, and onUnknownOption emits exactly the warning reported in https://github.com/microsoft/vscode/issues/314065.
- **Remote CLI boundary:** src/vs/server/node/server.cli.ts documents that integrated remote terminals communicate with the existing remote server through VSCODE_IPC_HOOK_CLI. Its pipe path sends an open request containing file/folder URIs and window options, not a request to launch a Linux desktop using another user-data directory.
- **Existing settings capability:** src/vs/workbench/contrib/preferences/browser/preferences.contribution.ts:552–583 registers workbench.action.openRemoteSettings and workbench.action.openRemoteSettingsFile. src/vs/workbench/services/preferences/browser/preferencesService.ts:298 onward opens the remote environment's settings with ConfigurationTarget.USER_REMOTE.
- **Documented configuration model:** https://code.visualstudio.com/docs/remote/ssh#_ssh-hostspecific-settings documents reuse of local User settings and host-specific overrides through Preferences: Open Remote Settings. This supports configuring Linux-host settings, but does not claim automatic reuse of a Linux desktop profile.
