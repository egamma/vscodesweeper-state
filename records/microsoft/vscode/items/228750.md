# Issue #228750 — URI not properly serialized when sent to webworker

[https://github.com/microsoft/vscode/issues/228750](https://github.com/microsoft/vscode/issues/228750)

## Summary

The underlying issue — URIs losing their `$mid` field when sent to web workers via structured clone — remains unfixed on main. Two TODO comments from the workaround (lines 108 and 313) explicitly call out the unresolved root cause. Team-authored debt item; keep open.

## Change summary

URI objects lose their `$mid` marshalling marker when transferred to web workers via the structured clone algorithm, causing `revive()` to fail and requiring manual `URI.revive()` workarounds.

## Best solution

Investigate why the structured clone algorithm drops `$mid` from URI objects sent to web workers. The fix likely involves either ensuring `$mid` survives structured clone (e.g. by setting it as an enumerable own property before transfer) or introducing a custom serialization step for URIs crossing the worker boundary. The workarounds in `src/vs/workbench/services/search/worker/localFileSearch.ts` (line 312–319, `reviveFolderQuery`) and `src/vs/workbench/services/search/browser/searchService.ts` (line 108–112, `reviveMatch`) can then be simplified back to plain `revive()` calls.
