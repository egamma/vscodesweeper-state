# Issue #228750 — URI not properly serialized when sent to webworker

[https://github.com/microsoft/vscode/issues/228750](https://github.com/microsoft/vscode/issues/228750)

## Summary

Still unresolved on main. The workaround (explicit `URI.revive()` calls) is in place, but the underlying issue — `$mid` not surviving structured clone to web workers — remains, with TODO comments confirming the debt.

## Change summary

URIs sent to web workers via structured clone lose their `$mid` field, preventing the generic `revive()` from properly deserializing them.

## Best solution

Fix the URI marshalling layer so that `$mid` survives the structured clone algorithm used for web worker communication, then remove the workaround `URI.revive()` calls and TODO comments in `src/vs/workbench/services/search/worker/localFileSearch.ts` (line 313) and `src/vs/workbench/services/search/browser/searchService.ts` (line 108).
