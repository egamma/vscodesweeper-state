# Issue #338582 — Customization Marketplace: repair staging folder briefly appears as an installed skill

[https://github.com/microsoft/vscode/issues/338582](https://github.com/microsoft/vscode/issues/338582)

## Summary

Confirmed the root cause in source: readSkills in pluginParsers.ts scans every child directory of a skill root for a SKILL.md with no filter for dot-prefixed directories, so the repair staging folder (.customization-marketplace-<UUID>, created as a sibling of the target by customizationMarketplaceSkillInstaller.ts) can be discovered as a real skill during the race window before cleanup. Real, bounded bug worth fixing, but the reporter themselves notes it's intermittent (one repro, one non-repro).

## Change summary

During skill repair, the internal staging directory briefly appears in the Discover UI as an installed skill with its own Uninstall action before it is cleaned up.

## Best solution

Filter out dot-prefixed (hidden) child directories in readSkills' directory scan in src/vs/platform/agentPlugins/common/pluginParsers.ts, so staging directories like .customization-marketplace-<UUID> are never surfaced as discovered skills, matching the general convention of ignoring dotfiles/dirs during discovery scans.
