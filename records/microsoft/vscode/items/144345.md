[https://github.com/microsoft/vscode/issues/144345](https://github.com/microsoft/vscode/issues/144345)

## Summary

The reported ctrl+click double-encoding bug has a known root cause in the `encodeURI(externalUri.toString(true))` fallback in `openerService.ts`, but the most common code path (built-in link computer returning a string URL) is guarded against it since PR #141944. Need confirmation whether this still reproduces on current builds.

## Change summary

Ctrl+clicking a URL with percent-encoded characters in the editor opens the link with double-encoded percent signs (e.g. `%3F` becomes `%253F`).
