# Issue #181050 — editor.selectionClipboard option has no effect on vscode.dev

[https://github.com/microsoft/vscode/issues/181050](https://github.com/microsoft/vscode/issues/181050)

## Summary

Still reproduces on main: the selection clipboard paste preventer and the SelectionClipboard editor contribution are registered only in the electron-browser layer, so they never activate on vscode.dev. The bug is real and unresolved.

## Change summary

The `editor.selectionClipboard` setting has no effect on vscode.dev because the paste-prevention and selection-clipboard logic only runs in the desktop (Electron) build.

## Best solution

Move the `LinuxSelectionClipboardPastePreventer` logic (and the `SelectionClipboard` editor contribution registration) from `electron-browser/selectionClipboard.ts` into the `browser/` layer so it activates on vscode.dev as well. As alexdima noted, the contribution could be converted to an `IEditorFeature` (see `src/vs/editor/common/editorFeatures.ts`) to avoid the workbench-contribution instantiation gap in the standalone editor.
