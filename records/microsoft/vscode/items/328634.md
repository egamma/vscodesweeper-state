# Issue #328634 — Custom foreground colors for the editor affects the Debug Console

[https://github.com/microsoft/vscode/issues/328634](https://github.com/microsoft/vscode/issues/328634)

## Summary

Traced this to VS Code's standard color-registry pattern: colors can default to referencing another color rather than a literal hex, and `debugConsole.infoForeground`/`warningForeground` are registered with defaults of `editorInfoForeground`/`editorWarningForeground`. Overriding the editor color therefore intentionally cascades to the Debug Console default, and the reporter's own workaround (explicitly overriding `debugConsole.*Foreground`) is the documented way to opt out of that cascade.

## Change summary

Setting `editorInfo.foreground`/`editorWarning.foreground`/`editorError.foreground` via colorCustomizations also changes the Debug Console's info/warning/error text colors, since those keys aren't overridden separately.

## Best solution

Keep the current default-reference design; the fix for users is to override `debugConsole.infoForeground`/`warningForeground`/`errorForeground` alongside the editor keys, as the reporter already discovered. If there's appetite to decouple these defaults, that would be a deliberate, separate design change to debugColors.ts, not a bug fix.

This isn't a bug in the editor/debug boundary — it's how VS Code's color registry works generally: many theme colors are registered with a *default* that references another color instead of a literal value, and `debugConsole.infoForeground`/`warningForeground`/`errorForeground` default to `editorInfoForeground`/`editorWarningForeground`/`errorForeground` (see `src/vs/workbench/contrib/debug/browser/debugColors.ts`). I'll close this as as-designed, but if you'd like the Debug Console defaults decoupled from the editor squiggle colors, that'd be a good case to make as a separate feature request.
