# Issue #320271 — Middle click scroll and drag causes text to be deleted

[https://github.com/microsoft/vscode/issues/320271](https://github.com/microsoft/vscode/issues/320271)

## Summary

Keep open: another CachyOS user confirms the reported behavior, and current source leaves Linux middle-button selection and clipboard handling active during autoscroll. The unintended text modification needs investigation; the related mouse-configuration requests do not own this defect.

## Change summary

Middle-button hold-and-drag autoscrolling selects text and deletes it on release on Linux.

## Best solution

Make editor autoscroll gestures leave document contents and selections unchanged, while preserving ordinary Linux primary-selection paste outside autoscroll. First establish whether the reported deletion is a native paste replacing the drag selection or a separate edit.

## Evidence

- **Reported trigger and confirmation:** https://github.com/microsoft/vscode/issues/320271 reports middle-button hold-and-drag selecting text while scrolling, followed by deletion on release in VS Code 1.121.0 on CachyOS, with extensions disabled. The reporter reiterates the deletion in the June 7 discussion; znepb independently reports the same issue on CachyOS on October 4.
- **Selection conflict in current source:** src/vs/editor/browser/controller/mouseHandler.ts, MouseHandler._onMouseDown, starts MouseDownOperation for middle-button presses before emitting the editor mouse-down event. In src/vs/editor/browser/view/viewController.ts, ViewController.dispatchMouse suppresses middle-button selection for scrollOnMiddleClick only when Linux selectionClipboard is off; with the default selectionClipboard=true, the gesture can reach ordinary drag-selection handling.
- **Release and clipboard boundary:** src/vs/editor/contrib/middleScroll/browser/middleScrollController.ts prevents default on mouse-down and ends a scrolling session on mouse-up after movement, but does not prevent default on that release. LinuxSelectionClipboardPastePreventer in src/vs/workbench/contrib/codeEditor/electron-browser/selectionClipboard.ts prevents middle-button release paste only when editor.selectionClipboard is disabled, without considering autoscroll. This supports a clipboard-interaction hypothesis, but does not conclusively establish the native event sequence causing deletion.
- **Existing capability is partial:** src/vs/editor/common/config/editorOptions.ts registers editor.scrollOnMiddleClick and editor.selectionClipboard. MiddleScrollController already supports release-to-stop after scrolling and click-to-lock without movement. Disabling editor.selectionClipboard is a plausible workaround, not proof that the reported combination is safe or intentionally modifies text.

That closed issue concerns clicking empty tab-strip space, not this autoscroll gesture, so it is neither a duplicate target nor proof of a fix.
