# Issue #301679 — Copilot agent terminal commands in VS Code Insiders + WSL intermittently terminate with exit codes 130 / 1

[https://github.com/microsoft/vscode/issues/301679](https://github.com/microsoft/vscode/issues/301679)

## Summary

Multiple independent reports confirm that agent-driven terminal commands can be interrupted or misreported as exit 130 across WSL, Windows, and macOS. The issue remains useful as a cross-platform chat-terminal report because later fixes addressed known SIGINT races without conclusively covering every reported path.

## Change summary

Prevent Copilot agent terminal orchestration from injecting or attributing spurious interrupts that terminate commands or report successful commands as exit 130.

## Best solution

Route this to the chat-terminal owners to reproduce the remaining command-lifecycle race on current main, correlate completion events to the command that was actually launched, and preserve genuine command failures and user-initiated cancellation.

- **Behavior:**

  > Agent-driven terminal commands must not be interrupted by tool-generated Ctrl+C unless cancellation is explicitly required for a command that is still running. Completion output and exit status must belong to the command the current tool invocation launched, so a successful command is not reported as exit 130 or 1. Genuine failures and user-initiated cancellation must continue to surface normally, without suppressing general terminal exit alerts.
- **Trace:**

  > The run-in-terminal tool selects RichExecuteStrategy, BasicExecuteStrategy, or NoneExecuteStrategy under src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy. Commit 8eaab1c0893e29a5d7105a39b4e9deddb1f23655 addressed two known races by filtering stale onCommandFinished events and replacing idle-prompt SIGINT with Ctrl+U; 4d75b7af0178ab23ba7d33040284d914188acf76 corrected that filtering to compare command markers.
