# Issue #166106 — 3-way merge: Dropdown in the results view

[https://github.com/microsoft/vscode/issues/166106](https://github.com/microsoft/vscode/issues/166106)

## Summary

The result-view resolution label is still non-interactive; existing commands and input-pane menus do not provide the requested state dropdown. Keep this accepted, team-authored request open for a focused design decision about selectable resolution states.

## Change summary

Turn each conflict's result-view resolution summary into a dropdown for choosing its resolution without interacting with the input panes.

## Best solution

Provide a result-local resolution selector that reflects the current state and offers applicable alternatives while preserving existing merge semantics. Settle how manual resolutions and ordered combinations appear before implementation, coordinating with the related result-code-lens discussion.

- **Behavior:**

  > Each conflict's result summary should allow the user to inspect and choose applicable resolutions from the result pane. Choosing a supported state should update only that conflict and accurately reflect the resulting content. Existing input-pane acceptance, combination constraints, and undo/redo must remain consistent. Acceptance must cover base, each input, supported combinations, and the agreed treatment of manually edited content, including keyboard access.
- **Trace:**

  > ActionsSource.resultItems in src/vs/workbench/contrib/mergeEditor/browser/view/conflictActions.ts constructs a passive first item; ActionsContentWidget.setState renders it as a span. src/vs/workbench/contrib/mergeEditor/browser/view/viewZones.ts supplies these items to the result conflict zones. Input-gutter menu behavior exists in ModifiedBaseRangeGutterItemModel.getContextMenuActions in src/vs/workbench/contrib/mergeEditor/browser/view/editors/inputCodeEditorView.ts, while combination validity and ordering are defined in src/vs/workbench/contrib/mergeEditor/browser/model/modifiedBaseRange.ts. Preserve those semantics and unrelated editor commands. The uncertainty is the user-visible state menu, especially whether Manual Resolution is descriptive or selectable and which combination variants it exposes. Coordinate with https://github.com/microsoft/vscode/issues/161969, which proposes an alternative inline-action presentation rather than specifying this dropdown.
- **Open decisions:**
  - Should Manual Resolution appear only as the current descriptive state, or be selectable to restore previously edited content?
  - Should the selector expose automatic combinations, ordered concatenations, or both, and how should unavailable combinations be presented?
