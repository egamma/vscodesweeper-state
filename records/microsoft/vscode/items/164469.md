# Issue #164469 — Support breaking strings across lines (by extending onEnterRules to have more context?)

[https://github.com/microsoft/vscode/issues/164469](https://github.com/microsoft/vscode/issues/164469)

## Summary

Keep this accepted, community-supported request open: current Enter rules still cannot express token-conditioned string splitting. The related issues cover different observable behavior and do not satisfy the stronger duplicate bar for this re-reviewed item.

## Change summary

Allow language extensions to split a single-line string on Enter, inserting the necessary delimiters while preserving its value and restricting the action to string contexts.

## Best solution

Provide a language-configurable, context-aware Enter capability that lets Dart implement string splitting without imposing language-specific behavior on other languages. Settle the public matching and edit contract first, preserving responsive typing and compatibility with existing Enter rules.

Include negative cases outside strings and unchanged legacy rules; run the relevant suites with ./scripts/test.sh --run src/vs/editor/test/common/modes/supports/onEnter.test.ts --run src/vs/editor/test/browser/controller/cursor.test.ts. No tests were run during this read-only review.
- **Behavior:**

  > A language extension should be able to configure Enter inside a single-line string to produce two valid string segments without changing the string's value. The action must not activate on equivalent-looking text outside the intended string context. Existing comment continuation, indentation and unconfigured languages must retain their behavior. Acceptance should cover both delimiter insertion and cursor placement, not merely detecting a string token.
- **Trace:**

  > OnEnterRule and EnterAction in src/vs/editor/common/languages/languageConfiguration.ts currently expose regex text conditions and a limited static action. getEnterAction in src/vs/editor/common/languages/enterAction.ts tokenizes the model and obtains processed context, then discards token metadata when calling OnEnterSupport.onEnter in src/vs/editor/common/languages/supports/onEnter.ts. EnterOperation._enter in src/vs/editor/common/cursor/cursorTypeEditOperations.ts applies newline-prefixed edits, so token filtering alone would not establish the requested closing delimiter before the newline. Public declarations and the language-configuration extension-point parser/schema are additional contract surfaces. Preserve existing rules, embedded-language handling and the cheap-tokenization fallback; do not hard-code Dart semantics or introduce extension callbacks into synchronous Enter handling. https://github.com/microsoft/vscode/issues/66235 documents renderer serialization and latency constraints, while https://github.com/microsoft/vscode/issues/236296 is related context-processing work rather than a duplicate. The uncertainty starts at the public token-context and two-sided edit contract, not whether the current rule shape covers the request.
- **Open decisions:**
  - Should Enter-rule context conditions expose standard lexical token categories only, or also grammar scopes or semantic-token classifications, and what behavior is promised when that context is unavailable?
  - What language-configurable edit contract should support closing the original string before the newline and opening its continuation afterward, including the resulting cursor position?
