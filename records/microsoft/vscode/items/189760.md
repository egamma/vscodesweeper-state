# Issue #189760 — Git commit (amend) context menu

[https://github.com/microsoft/vscode/issues/189760](https://github.com/microsoft/vscode/issues/189760)

## Summary

Keep open for a Git action-menu design decision: current source still places Commit (Amend) before Commit & Push, and two later reports were consolidated here. The maintainer explicitly retained this feedback; the remembered-action setting helps frequent push users but does not resolve the requested menu ordering.

## Change summary

Move Commit (Amend) below common commit-and-push actions to reduce accidental selection.

## Best solution

Agree on a safer default ordering for the Git commit dropdown that makes common commit-and-push actions easy to find while retaining explicit access to amend and extension-contributed actions. Keep this issue as the canonical feedback thread for that decision.

## Plan brief

- **Likely files:** `extensions/git/src/postCommitCommands.ts`, `extensions/git/src/actionButton.ts`
- **Validation:** After agreeing on the ordering, add a command-group test that asserts the exact dropdown order with built-in and extension-contributed post-commit providers. Manually open the SCM commit dropdown in a repository with pending changes and verify that order, command dispatch, and remembered/default primary-button behavior.
- **Behavior:**

  > Users intending Commit & Push report accidentally choosing Commit (Amend), which occupies an earlier dropdown position. The desired outcome is a predictable ordering that prioritizes common commit-and-push actions and makes amend less easy to select accidentally, while keeping amend available. Acceptance should verify the agreed ordering and that each action still invokes its advertised operation. Remembered and configured primary-button actions must retain their existing behavior.
- **Trace:**

  > CommitCommandsCenter in extensions/git/src/postCommitCommands.ts constructs a Commit/Commit (Amend) group and prepends it to provider-supplied post-commit groups; the built-in provider supplies Commit & Push and Commit & Sync. ActionButton.getCommitActionButtonSecondaryCommands() in extensions/git/src/actionButton.ts forwards these groups without reordering. getPrimaryCommand() supports git.rememberPostCommitCommand and git.postCommitCommand, but neither changes the dropdown. The maintainer deliberately chose the current grouping and retained this issue for feedback; https://github.com/microsoft/vscode/issues/200920 and https://github.com/microsoft/vscode/issues/229074 were subsequently closed into it. The unresolved boundary is the visible ordering and grouping, not Git amend semantics: preserve commit execution, branch protection, merge/rebase handling, and extension-contributed command availability.
- **Open decisions:**
  - Should the dropdown prioritize Commit & Push and Commit & Sync ahead of Commit (Amend), departing from the current grouping of all plain Commit commands first; if so, where should amend appear relative to extension-contributed post-commit actions?

## Evidence

- **Current menu ordering:** extensions/git/src/postCommitCommands.ts: CommitCommandsCenter.getCommitCommands() returns git.commit followed by git.commitAmend; getSecondaryCommands() prepends that group before post-commit providers. GitPostCommitCommandsProvider.getCommands() supplies Commit & Push and Commit & Sync in a later group. extensions/git/src/actionButton.ts forwards these groups through getCommitActionButtonSecondaryCommands(), preserving the reported ordering.
- **Existing capability is a workaround:** extensions/git/package.json registers git.rememberPostCommitCommand with default false and git.postCommitCommand with push/sync options. CommitCommandsCenter.getPrimaryCommand() selects the remembered or configured post-commit action for the primary button, but getSecondaryCommands() retains the same dropdown ordering. These settings do not satisfy the central request.
