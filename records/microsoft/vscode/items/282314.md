# Issue #282314 — CustomEditor Dirty Flag may be not correct

[https://github.com/microsoft/vscode/issues/282314](https://github.com/microsoft/vscode/issues/282314)

## Summary

The reported save → undo → new edit sequence still produces a false-clean state in current source: replacing the saved edit reuses its array index without invalidating the save point. Keep this open; the custom-editor model needs to distinguish the saved history state from a replacement edit.

## Change summary

Custom editors incorrectly clear their dirty flag when a new edit replaces an undone saved edit, risking loss of unsaved changes on close.

## Best solution

Make custom-editor dirty tracking identify the actual saved history state rather than treating a reused edit index as saved. Preserve clean-state detection when undo or redo genuinely returns to the saved state.
