# Issue #282314 — CustomEditor Dirty Flag may be not correct

[https://github.com/microsoft/vscode/issues/282314](https://github.com/microsoft/vscode/issues/282314)

## Summary

Confirmed on current main: after save→undo→new edit, the dirty flag incorrectly returns false because `spliceEdits` never invalidates `_savePoint` when the saved edit is among the spliced-away edits, leading to potential data loss on close.

## Change summary

CustomEditor dirty flag returns false after save→undo→new edit because the save-point index is not invalidated when the edit it pointed to is spliced away.

## Best solution

In `MainThreadCustomEditorModel.spliceEdits()`, invalidate `_savePoint` (set to -2 or similar sentinel) when the splice removes the edit at the save-point index — i.e. when `_savePoint > _currentEditIndex`. This ensures `isDirty()` returns true after diverging from the saved state.
