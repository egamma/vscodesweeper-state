# Issue #114047 — Unexpected editor.selection in onDidChangeActiveTextEditor callback

[https://github.com/microsoft/vscode/issues/114047](https://github.com/microsoft/vscode/issues/114047)

## Summary

Still reproducible on main: when switching tabs within the same editor group, the code editor widget receives a new model before the selection is restored, so `onDidChangeActiveTextEditor` fires with a stale (0,0) selection. The `setModelAndSelection` approach suggested by a contributor in 2021 was never implemented. Maintainer-acknowledged, properly labeled, and in the Backlog — keeping open.

## Change summary

Extension API reports incorrect (0,0) selection in the `onDidChangeActiveTextEditor` callback when switching tabs within the same editor group, because selection restoration happens after the active-editor event fires.

## Best solution

Implement the `setModelAndSelection` pattern suggested by @jrieken: have the workbench atomically set both the model and the restored selection on the code editor before the ext-host delta is computed and the `onDidChangeActiveTextEditor` event fires. The fix would likely touch `src/vs/workbench/api/browser/mainThreadDocumentsAndEditors.ts` (delta computation) and the editor model-setting path.
