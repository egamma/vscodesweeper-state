# Issue #319726 — Failed to open chat session: Illegal argument: character must be non-negative

[https://github.com/microsoft/vscode/issues/319726](https://github.com/microsoft/vscode/issues/319726)

## Summary

Still reproduces on main — the 0-based vs 1-based off-by-one in copilotCLITools.ts is confirmed present in the current source with no fix committed. Root cause is well-identified by roblourens; this needs a code fix.

## Change summary

Opening a chat session from history crashes with 'Illegal argument: character must be non-negative' when a selection attachment starts at line 0, character 0.

## Best solution

Align all producer/consumer paths to the SDK's 0-based contract: remove the `- 1` adjustments in `copilotCLITools.ts` line 627 (`buildChatHistoryFromEvents`) and remove the `+ 1` adjustments in `copilotcliPromptResolver.ts` lines 228-233. Both changes cancel out for the resolver path but the editor-context producer path (`sendContext.ts` → `getSelection.ts`) correctly stores 0-based, so only the consumer subtraction causes underflow.

  > The bug is a 0-based vs 1-based convention mismatch for selection attachments in the Copilot CLI chat history path. The SDK contract (@github/copilot/sdk) documents selection start/end as 0-based. Two spots are wrong: (1) Consumer in extensions/copilot/src/extension/chatSessions/copilotcli/common/copilotCLITools.ts at line 627 — `buildChatHistoryFromEvents` subtracts 1 from already-0-based values (`new Range(attachment.selection.start.line - 1, attachment.selection.start.character - 1, ...)`), causing underflow to -1 for selections at file start. Remove the `- 1` from all four arguments so 0-based SDK values pass through directly. (2) Producer in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliPromptResolver.ts at lines 228-233 — adds `+ 1` to VS Code's 0-based Range values before storing as SDK attachments, violating the SDK's 0-based contract. Remove the `+ 1` from all four lines so VS Code Range values (already 0-based) are stored as-is. These two errors currently cancel out for the resolver path, but the editor-context path (sendContext/getSelection) correctly stores 0-based, so the consumer's `- 1` causes the crash. After the fix, both paths are consistently 0-based. Add a unit test in the existing copilotCLITools.spec.ts that exercises buildChatHistoryFromEvents with a selection attachment at (0, 0) and asserts it produces a valid Range(0, 0, ...) without throwing.
