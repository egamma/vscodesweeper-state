# Issue #329915 — First time prompt is chosen, it is streamed in, then it is replaced

[https://github.com/microsoft/vscode/issues/329915](https://github.com/microsoft/vscode/issues/329915)

## Summary

Traced the exact code path causing this: the prompt-option selection logic in the new session composer only animates the typing effect the very first time a suggested prompt is picked, then instantly replaces the input text on every later pick — this asymmetry is intentional-looking code, not a random glitch, but the reporter's expectation of consistent behavior (always animate, or never after the first) is reasonable.

## Change summary

In the new-session onboarding composer, choosing a suggested prompt streams the text in letter-by-letter the first time, but instantly replaces it on every subsequent choice.

## Best solution

Decide the intended UX for src/vs/sessions/contrib/chat/browser/newSessionPromptOptions.ts (`_select`, line ~165: `const animate = previousSelectedOptionId === undefined;`) — either always animate via `newChatInput.ts`'s `animatePrompt`, or always do the instant `_replacePrompt`, so the behavior is consistent across all prompt picks.
