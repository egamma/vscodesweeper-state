# Issue #309241 — bug: FileSystemWatcher emits incorrect events when renaming an external watched folder

[https://github.com/microsoft/vscode/issues/309241](https://github.com/microsoft/vscode/issues/309241)

## Summary

Keep open while the linked fix PR is reviewed: its author reports reproducing the missing root-deletion notification on current main. Review should also cover the reporter's stale child-deletion events and the public FileSystemWatcher API, not only backend failure recovery.

## Change summary

Renaming an externally watched folder fails to notify FileSystemWatcher clients that the base path disappeared and can leave subsequent deletion events pointing at stale paths.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/332170 if it restores the reported public API behavior: notify clients when the watched base disappears and stop reporting changes from the renamed folder under its old path. Confirm coverage for uncorrelated extension watchers as well as the correlated backend regression test.
