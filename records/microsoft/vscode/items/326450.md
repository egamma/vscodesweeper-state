# Issue #326450 — Restore Checkpoint not working with AH session

[https://github.com/microsoft/vscode/issues/326450](https://github.com/microsoft/vscode/issues/326450)

## Summary

Keep open: a maintainer confirmed that checkpoint restoration is not persisted until another message is sent, and current source still defers host-history truncation to that next message. The older matching report does not establish the same Agent Host runtime/protocol defect, so consolidation is not yet justified.

## Change summary

Preserve an Agent Host session's restored checkpoint when switching away and back without sending another message.

## Best solution

Make the selected checkpoint durable across session rehydration without prematurely deleting recoverable history, coordinating the Agent Host client and host history contract. Keep filesystem restoration and selected conversation history consistent.

## Evidence

- **Confirmed failure and diagnosis:** https://github.com/microsoft/vscode/issues/326450 describes Restore Checkpoint → switch sessions → switch back, after which later history reappears. In the supplied July 22 maintainer comment, connor4312 confirms that this state is not persisted until the next message and identifies missing non-destructive runtime/protocol support.
- **Current client behavior:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSnapshotController.ts stores the selected position in the in-memory _currentCheckpointIndex. restoreSnapshot calls _navigateToCheckpointIndex, which writes checkpoint file contents and updates that local cursor; this path does not publish a durable selected-history position to the host.
- **Deferred history mutation:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:3392-3416 compares the chat model with protocol turns and dispatches ChatTruncated while preparing a subsequent message. This supports the maintainer's diagnosis rather than proving that switching sessions alone preserves restoration.
- **Protocol dependency remains open:** https://github.com/microsoft/agent-host-protocol/issues/353 is OPEN. Its Chats as a DAG RFC proposes a durable headTurnId and host-brokered checkout that coordinates workspace restoration with selected history; this is a design dependency, not evidence of an adopted fix.
- **Older same-symptom candidate:** https://github.com/microsoft/vscode/issues/319225 is OPEN and predates this report. It describes the same checkpoint → session switch → history reappears symptom, but its body and comments do not establish Agent Host involvement or the same runtime/protocol cause. The stronger re-review duplicate bar is therefore not fully met.
