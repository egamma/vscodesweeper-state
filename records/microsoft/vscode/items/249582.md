# Issue #249582 — Sidebar icons look bold/with incorrect width and incorrectly rendered

[https://github.com/microsoft/vscode/issues/249582](https://github.com/microsoft/vscode/issues/249582)

## Summary

Verified duplicate of the older, still-open https://github.com/microsoft/vscode/issues/238151, which reports the exact same symptom from the same cause (codicon/product-icon fonts rendered bold or hairline on Linux when the distro sets FREETYPE_PROPERTIES stem darkening) and already has maintainer engagement; consolidating there also preserves the useful FontationsFontBackend workaround found in this thread.

## Change summary

On Fedora, VS Code's sidebar/product icons render bold and with wrong widths because the distro-set FREETYPE_PROPERTIES stem-darkening settings are applied to the icon font.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/238151 and decide there whether VS Code should insulate its icon fonts from FreeType text-rendering settings (e.g. by not relying on an icon font for codicons, or by opting those glyphs out) — the underlying rendering behavior comes from Chromium/FreeType, so any VS Code-side change is a mitigation, not a fix of the root cause.

- **root cause is outside VS Code's own code:** git grep across the checkout finds no reference to Fontations, FREETYPE_PROPERTIES, stem darkening or gtk-xft anywhere in the repo — VS Code neither sets nor compensates for these; the glyph rasterization is done by Chromium/FreeType in Electron (currently 43.7.7 per .npmrc `target`).
- **workaround and the 'make it permanent' question:** Both workarounds in this thread (`FREETYPE_PROPERTIES=autofitter:no-stem-darkening=1` and `--enable-features=FontationsFontBackend`) are environment/command-line level. src/mainImpl.ts's `SUPPORTED_ELECTRON_SWITCHES` allowlist (around lines 250-270) accepts only `disable-hardware-acceleration`, `force-color-profile`, `disable-lcd-text`, `proxy-bypass-list`, `remote-debugging-port` (plus `force-renderer-accessibility`/`password-store` on Linux), so `enable-features` cannot be persisted via argv.json today — this is worth carrying over to the canonical.
