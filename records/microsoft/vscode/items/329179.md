# Issue #329179 — Copilot Chat can act on truncated tool-result previews instead of the full payload

[https://github.com/microsoft/vscode/issues/329179](https://github.com/microsoft/vscode/issues/329179)

## Summary

Thanks for the detailed report — but VS Code already implements exactly the mitigation being requested: when a tool result (including MCP resources) is truncated, the prompt explicitly instructs the model to read the full content via the read_file tool rather than reason from the preview, so this is working as designed rather than a missing safeguard.

## Change summary

Copilot Chat sometimes appears to reason from a truncated inline tool-result preview instead of opening the full linked payload.

## Best solution

Keep the existing design: large tool results are either written to disk with an explicit 'read this file' instruction (chat.agent.largeToolResultsToDisk.enabled, default true, threshold chat.agent.largeToolResultsToDisk.thresholdBytes = 8KB) or, for MCP linked resources, the prompt appends an explicit hint to read the full content via the ReadFile tool when truncated. Whether the model always follows that instruction is inherent LLM behavior, not a code defect that can be deterministically fixed here.

## Evidence
