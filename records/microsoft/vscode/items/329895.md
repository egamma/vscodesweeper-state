# Issue #329895 — terminal.integrated.shellIntegration in runCommand alway timeout 5s

[https://github.com/microsoft/vscode/issues/329895](https://github.com/microsoft/vscode/issues/329895)

## Summary

Traced and confirmed on current main: `runCommand` in terminalInstance.ts only listens for a *future* `onDidAddCommandDetectionCapability` event, so when shell integration registers command detection before the listener is attached (fast shell startup), the listener never fires and the code falls through to the hardcoded timeout, delaying command execution by the full `timeoutMs` (default 5000ms).

## Change summary

runCommand() in terminalInstance.ts can deadlock for the full shell-integration timeout (default 5s) when CommandDetection capability registers before the listener attaches, due to a missed one-shot event.

## Best solution

Add a synchronous re-check of the already-current `commandDetection` capability inside the promise executor (as the reporter's suggested fix does) before relying solely on the future `onDidAddCommandDetectionCapability` event, so fast shell-integration startups don't fall through to the timeout.
