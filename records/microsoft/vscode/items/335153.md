# Issue #335153 — Copilot diff incorrect - shows old changes of mine as its own changes

[https://github.com/microsoft/vscode/issues/335153](https://github.com/microsoft/vscode/issues/335153)

## Summary

Multiple independent reporters (original author, msdcssd, sbozonnet) describe the same symptom — the Copilot edit review diff showing old, unrelated changes as if newly made by the agent — but nobody has pinned an exact reproduction recipe, and no fix exists on main; keeping this open rather than closing, though a bug this thin on repro steps would normally need info, the corroborating reports raise it above a simple ask-and-close.

## Change summary

Reopening an old chat/agent conversation and giving it a new task can cause the edit-review diff (Keep/Undo) to use a stale baseline, so long-past manual edits show up as if the agent just made them.

## Best solution

Trace how ChatEditingSession restores/refreshes its per-file baseline (chatEditingSession.ts `restoreSnapshot`/timeline, and `initialContent` in chatEditingModifiedDocumentEntry.ts) when a session that was created long ago is resumed, to confirm whether the timeline's checkpoint/snapshot state can drift from the file's actual current disk content across a multi-week gap; a maintainer or an agent session should reproduce it deliberately (create a session, edit the file outside the session over time, resume) before attempting a fix.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCheckpointTimeline.ts`
- **Validation:** A test that creates a chat editing session, disposes/persists it, mutates the tracked file outside the session (simulating time passing / an unrelated commit), reopens the session, and asserts the diff baseline matches the file's actual pre-session content rather than a stale snapshot.
- **Behavior:**

  > When a user resumes an old (weeks/months-old) chat/agent conversation and gives it a new task, the resulting edit-review diff (Keep/Undo UI) should show only the changes the agent just made in this turn. Instead it sometimes also shows the user's own older, already-applied edits as if the agent had just made them, and can mark an entire file as changed when only a few lines actually changed. Acceptance: reopening a stale session and running a new agent turn produces a diff baseline equal to the file's state immediately before that turn, regardless of how long ago the session was created or how much has changed on disk since.
- **Trace:**

  > The likely mechanism is that ChatEditingSession stores its per-file baseline/snapshot state via a checkpoint timeline (restoreSnapshot in chatEditingSession.ts:418, _timeline.navigateToCheckpoint) and per-entry `initialContent` (chatEditingModifiedDocumentEntry.ts:124), and that when a session persisted long ago is reloaded, one of these baselines may not be refreshed against the file's actual current on-disk content, effectively diffing against an out-of-date snapshot. This has not yet been confirmed by tracing an actual reload path in the debugger/tests — the trace only identifies the plausible components; the reproduction step (create session, let time pass with real edits, resume, inspect diff) still needs to be run to confirm which store is stale.
