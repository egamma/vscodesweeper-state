# Issue #335153 — Copilot diff incorrect - shows old changes of mine as its own changes

[https://github.com/microsoft/vscode/issues/335153](https://github.com/microsoft/vscode/issues/335153)

## Summary

Thanks for the report — three independent users describe the same symptom (resuming an old/long-dormant chat session shows a stale diff baseline, mixing in the user's own earlier commits as if Copilot made them), which is a real-sounding and concerning defect, but nobody — including the reporter — has pinned down concrete reproduction steps, so this needs more specifics before it's actionable.

## Change summary

When resuming an old Copilot chat/agent conversation, the file-change diff review (Keep/Undo) appears to use a stale snapshot of the file as its baseline instead of the file's current on-disk state, showing the user's own older edits as if they were Copilot's.

## Best solution

Once a reliable repro is in hand, investigate whether the chat editing session's per-file baseline/snapshot (chatEditingModifiedFileEntry.ts / chatEditingSession.ts under src/vs/workbench/contrib/chat/browser/chatEditing) is refreshed against the current document state when a dormant session's request is resumed, rather than reusing content captured at the session's original creation time.
