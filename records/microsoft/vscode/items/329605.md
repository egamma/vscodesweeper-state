# Issue #329605 — Modern UI: close button overlay causes accidental tab closure when clicking the filename

[https://github.com/microsoft/vscode/issues/329605](https://github.com/microsoft/vscode/issues/329605)

## Summary

Confirmed in current source: the Modern UI tab-actions overlay sits absolutely positioned on top of the tab label and switches to `pointer-events: auto` on hover, so a short filename's visible text falls under the clickable close-button hit area and gets clicked instead of activating the tab.

## Change summary

In the new Modern UI tab design, the floating close-button overlay can cover part of a short filename, making that covered text clickable as a tab-close action instead of a tab-activate click.

## Best solution

Reserve trailing space for the action overlay (or otherwise keep its hit target off the label) in src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css / multiEditorTabsControl.ts, likely coordinated with the ongoing Modern UI tabs redesign work (see the linked tracking issue) rather than as a one-off patch.

## Evidence

- **no reserved space for short names:** Lines 248-250: `.tab:is(.sizing-shrink, .sizing-fixed) > .tab-label { padding-right: 0; }` — the label is not given trailing padding to avoid the 24px action box, so short filenames get covered.
