# Issue #329605 — Modern UI: close button overlay causes accidental tab closure when clicking the filename

[https://github.com/microsoft/vscode/issues/329605](https://github.com/microsoft/vscode/issues/329605)

## Summary

Traced this in the current Modern UI tab CSS: the close button is deliberately overlaid on top of the label (not given its own column), and on hover the whole 24px action box gets `pointer-events: auto` while sitting at `z-index: 7` above the label — so clicks meant for the filename land on the close action instead. Confirmed by a second reporter with the same complaint, so this is a real hit-target regression in an actively evolving experimental feature, not a one-off report.

## Change summary

In the new experimental Modern UI tab style, the close-button overlay sits on top of the tab label and steals clicks meant for the filename, especially for short filenames.

## Best solution

Adjust the Modern UI tab hover/hit-target logic in src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css (and the label sizing in editorTabsControl.ts/multiEditorTabsControl.ts) so the close action's clickable area doesn't overlap visible label text — e.g. shrink the label's `max-width`/`text-overflow` boundary on hover to make room, or reduce the action hit target to the icon glyph rather than the full 24px box.

## Evidence

- **overlay design comment:** src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css lines 256-271: '/* Overlay tab actions on the label instead of reserving a trailing/leading column... */' followed by `.tab-actions { position: absolute; z-index: 7; top:0; right:0; bottom:0; width: 24px; pointer-events: none; }`.
- **hover hit target:** Lines 292-296: `.tab:not(.close-action-off):hover > .tab-actions { ...; pointer-events: auto; }` — the full 24px absolutely-positioned box (not just the visible icon) becomes clickable on hover, directly above the tab label.
- **origin PR:** The overlay design was introduced by the merged PR https://github.com/microsoft/vscode/pull/328111 ('Modern UI tabs redesign and bug bash'), which explicitly states it 'Moves editor tab actions to render above tab content rather than to the side of it' — this is intentional layout, but the resulting hit-target overlap with short filenames appears to be an unaddressed side effect.
- **second confirmation:** Comment from frankobjank (2026-08-09) on macOS reports the same overlap independently, also noting it obscures the git decorator/badge, corroborating this isn't isolated to one OS/config.
