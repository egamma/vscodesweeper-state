# Issue #184172 — API to access the product configuration

[https://github.com/microsoft/vscode/issues/184172](https://github.com/microsoft/vscode/issues/184172)

## Summary

The requested extension API remains incomplete: commit and quality are exposed through the proposed resolvers API, but the server names and update endpoint are not. Keep this team-authored request open for an API contract decision; no verified older canonical or issue-referencing fix was found.

## Change summary

Expose product configuration to extensions across desktop and web without depending on the installation's file layout.

## Best solution

Define a supported extension-facing contract for the product metadata remote resolvers need, usable in desktop and web hosts without reading product.json. API owners should settle whether to expose selected properties or an opaque configuration value, as raised in the existing discussion.

- **Behavior:**

  > Remote resolver extensions need product metadata without assuming where VS Code installs product.json. Existing proposed access covers commit and quality, but not the requested server application name, server data folder name or update endpoint. The agreed API must work in desktop and web hosts and specify how unavailable product values are represented. Acceptance includes reading the approved metadata in both host types without filesystem access.
- **Trace:**

  > src/vscode-dts/vscode.proposed.resolvers.d.ts declares env.appCommit and env.appQuality; their getters in src/vs/workbench/api/common/extHost.api.impl.ts read initialization data after checking the resolvers proposal. IExtensionHostInitData in src/vs/workbench/services/extensions/common/extensionHostProtocol.ts already carries commit and quality. The remaining values exist internally in src/vs/base/common/product.ts, but searches of the extension API implementation and declarations found no corresponding accessor. The stable env.appRoot contract permits an empty value and cannot replace metadata access in web hosts. The unresolved boundary is the public contract, not a confirmed runtime defect: https://github.com/microsoft/vscode/issues/184172#issuecomment-1573880326 suggests either additional properties or an opaque configuration value. Preserve existing environment getters and do not assume the full internal product configuration is intended to become public.
- **Open decisions:**
  - Should extensions receive selected typed product properties or an opaque product configuration value, and which requested values belong in that supported contract?
