# Issue #348053 — The Copilot harness cannot read, edit, or display Code Approvals / Diffs for files in the virtual file system.

[https://github.com/microsoft/vscode/issues/348053](https://github.com/microsoft/vscode/issues/348053)

## Summary

Keep open for virtual-workspace parity: current main supports Copilot file reads and writes, but explicitly publishes empty virtual-workspace changesets. The existing implementation does not satisfy the full approval and diff request.

## Change summary

Provide Copilot harness virtual-file reading, editing, approvals, and diff review equivalent to the Local harness.

## Best solution

Support reviewable virtual-file changes without requiring an on-disk Git repository, and diagnose why the reporter's file reads fail despite the existing filesystem bridge. A maintainer should settle the intended approval and review experience before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotVirtualSessionFs.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/node/agentHostChangesetService.ts`, `src/vs/platform/agentHost/test/node/copilotVirtualWorkspace.test.ts`
- **Validation:** In a writable virtual workspace, select Copilot, read a known file, request a controlled edit, and verify the selected approval behavior plus reviewable before/after content. Repeat with the reporter's provider once identified, and cover virtual changeset output with targeted agent-host tests.
- **Behavior:**

  > The Copilot harness should let users read and edit writable virtual-workspace files and inspect the resulting changes without switching to Local. Current filesystem support does not provide the requested full review experience. Acceptance must cover successful reads and edits, correct virtual-file links, and reviewable before/after content. Approval behavior must match the maintainer-approved product contract.
- **Trace:**

  > CopilotVirtualSessionFs routes workspace operations through the active client's filesystem bridge, and CopilotSessionLauncher passes it to the SDK. CopilotAgentSession._sdkFileServiceUri and _buildEditsForPermission preserve virtual resources for edit previews. AgentHostChangesetService instead detects virtual roots and publishes empty changesets, establishing a remaining review limitation. https://github.com/microsoft/vscode/pull/346117 introduced this partial support and documents its exclusions. The reporter's generic-file-tool failure cannot yet be attributed to this changeset limitation. Preserve local-filesystem behavior and do not assume virtual providers support shell commands, Git, or writes.
- **Open decisions:**
  - Should virtual-workspace edits retain current in-root auto-approval or provide the same approval checkpoints requested for the Local harness?
  - Which review scopes must virtual workspaces support: individual edits, per-turn changes, session-wide changes, or all applicable scopes?

## Evidence

- **Existing capability:** src/vs/platform/agentHost/node/copilot/copilotVirtualSessionFs.ts implements readFile, writeFile, and other filesystem operations through the owning window. copilotAgent.ts advertises supportsVirtualWorkspaces and configures sessionFs; copilotSessionLauncher.ts supplies createSessionFsProvider.
- **Partial implementation:** https://github.com/microsoft/vscode/commit/a059735a27001babc2ff0787d35093497d0f1417 added virtual-workspace support on 2026-11-04. https://github.com/microsoft/vscode/pull/346117 describes working reads and edits but explicitly excludes changes aggregation and auto-approves in-root reads and writes. This predates the report and does not establish that its full request is fixed.
- **Remaining review gap:** src/vs/platform/agentHost/node/agentHostChangesetService.ts checks _isVirtualWorkspace at multiple changeset entry points and uses _publishEmptyChangeset; virtual workspaces therefore lack the aggregated change-review output requested here. CopilotAgentSession._buildEditsForPermission already maps virtual edit-preview URIs, so not every diff-related path is absent.
