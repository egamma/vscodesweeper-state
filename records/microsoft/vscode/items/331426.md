# Issue #331426 — [BUG] Custom Endpoint context window size is bloated by +16K in UI & context manager, causing potential backend context overflow

[https://github.com/microsoft/vscode/issues/331426](https://github.com/microsoft/vscode/issues/331426)

## Summary

Traced the exact +16K delta in `resolveModelTokenLimits` (extensions/copilot/src/extension/byok/common/byokProvider.ts): when a Custom Endpoint config sets `maxInputTokens` (e.g. 212000) without `contextWindow`, the window is intentionally derived as `maxInputTokens + maxOutputTokens` (128000/212000 + a 16384 `maxOutputTokens` matches the report exactly) — this is documented, tested backward-compat behavior, not a defect.

## Change summary

Reporter sees the UI/context-manager context window for a Custom Endpoint model exceed their configured server limit by exactly their configured `maxOutputTokens` (16384), and worries the extra headroom could overflow the backend's real context limit.

## Best solution

No code change needed: the fix is configuration — set `contextWindow` (the field documented as "the source of truth for the full window") to the server's real total (e.g. `-c 212000`) instead of `maxInputTokens`, and the resolver will derive `maxInputTokens = contextWindow - maxOutputTokens` with `maxOutputTokens` clamped so the two never sum past the configured window. Could still consider clarifying the `maxInputTokens` setting description or the Session Info tooltip to reduce this specific confusion.
