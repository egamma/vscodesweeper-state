# Issue #309219 — Chat artifacts settings don't support workspace settings

[https://github.com/microsoft/vscode/issues/309219](https://github.com/microsoft/vscode/issues/309219)

## Summary

Keep open to resolve repository-specific artifact grouping for CLI sessions. Current settings already support window-workspace configuration, but that does not establish coverage for CLI sessions associated with different repositories; no verified fix or older same-symptom canonical was found.

## Change summary

Allow artifact grouping paths to be configured per workspace rather than shared across repositories.

## Best solution

Make repository-specific artifact grouping consistent across local and CLI chat, with explicit configuration ownership when a session's repository differs from the open workspace. Treat grouping separately from changing the CLI's managed plan-file location.

Include a CLI session whose working directory differs from the open workspace, configuration changes during a session, and unchanged CLI plan-mode behavior.
- **Behavior:**

  > Different repositories can define different artifact grouping paths without changing a shared user setting. Matching artifacts use the appropriate repository's groups in local and CLI chat, while unrelated files are not included by another repository's rules. Acceptance must distinguish display grouping from where the CLI stores its managed plan file. The configuration source for sessions outside the open workspace needs an explicit maintainer decision.
- **Trace:**

  > Artifact rule settings are registered in chat.shared.contribution.ts with default WINDOW scope, and UnifiedChatArtifacts in chatArtifactsService.ts reads them through IConfigurationService without resource overrides. The configuration model already merges window-workspace values, so adding workspace eligibility alone would not address the remaining uncertainty. AgentHostSessionInputPills reads recorded session artifacts separately and merges their sections with transcript artifacts; the trace has not established repository-specific configuration resolution across both sources. Preserve existing session overrides, artifact metadata, and CLI-managed plan storage rather than assuming that moving plan.md solves grouping. The author and maintainer discussion at https://github.com/microsoft/vscode/issues/309219 establishes CLI relevance but does not settle configuration ownership when the session repository differs from the window workspace.
- **Open decisions:**
  - When a CLI session's repository differs from the open window workspace, should artifact grouping use the session repository's configuration or the window workspace's configuration?
