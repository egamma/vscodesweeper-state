# Issue #245971 — Can't Use "Publish Branch" Feature When Using SOCKS5 Proxy

[https://github.com/microsoft/vscode/issues/245971](https://github.com/microsoft/vscode/issues/245971)

## Summary

Same root cause as #241201: the GitHub extension's `getAgent` in `auth.ts` uses the `tunnel` package (`httpsOverHttp`), which only supports HTTP/HTTPS proxies — a SOCKS5 URL hits `new URL()` and then fails because `tunnel` cannot handle the socks5 protocol. Proposing duplicate close against the open canonical issue.

## Change summary

Publishing a branch to GitHub fails when `http.proxy` is set to a SOCKS5 proxy URL because the GitHub extension's proxy agent only supports HTTP/HTTPS proxies.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/241201, which tracks the same `Invalid URL protocol` failure path in the GitHub extension when a SOCKS5 proxy is configured. The fix is to add SOCKS proxy support in `extensions/github/src/auth.ts` (replace or augment the `tunnel`-based agent with a SOCKS-capable agent), and that work belongs in the canonical issue.

## Evidence

- **root cause in source:** extensions/github/src/auth.ts:getAgent() parses the proxy URL with `new URL()` then passes it to `httpsOverHttp` from the `tunnel` package, which only supports HTTP/HTTPS proxies. A socks5:// URL causes 'Invalid URL protocol' or a silent failure.
- **canonical issue:** https://github.com/microsoft/vscode/issues/241201 is open, labeled bug+upstream+proxy, and describes the identical failure: GitHub authentication fails with SOCKS5 proxy due to 'Invalid URL protocol'. Multiple users confirmed.
- **http.proxy accepts SOCKS:** src/vs/platform/request/common/request.ts validates `http.proxy` with a pattern that explicitly allows socks/socks5 URLs, but the GitHub extension's agent code doesn't honor them.
- **dependency limitation:** The `tunnel` package (^0.0.6) in extensions/github/package.json only provides HTTP tunneling agents — it has no SOCKS support.
