# Issue #337492 — Prompt to SKILL migration fails in multiroot workspace

[https://github.com/microsoft/vscode/issues/337492](https://github.com/microsoft/vscode/issues/337492)

## Summary

Freshly filed, team-authored bug report with clear repro steps for the prompt-to-SKILL migration flow in multiroot workspaces; author association (MEMBER) bars any judgment close, and there's no fix commit yet, so this stays open regardless.

## Change summary

Migrating a prompt file to a SKILL in a multiroot workspace deletes the source prompt but writes the new SKILL into the first workspace folder instead of the folder the prompt came from.

## Best solution

Fix the customization-migration target-folder resolution so a prompt file's SKILL destination is scoped to its own workspace root rather than defaulting to the first root; likely in resolveCustomizationMigrationTargetFolders/getCustomizationMigrationFolders in aiCustomizationManagementEditor.ts, working with the multi-root folder list produced by promptFilesLocator.ts's getResolvedSourceFolders.

- **Validation:** A test that migrates a prompt file located in the second (non-first) folder of a multi-root workspace and asserts the resulting SKILL is written under that same folder's skills location, not the first workspace folder's.
- **Behavior:**

  > In a multiroot workspace, migrating a single prompt file to a SKILL should place the new SKILL under the workspace folder that owns the source prompt file, and delete only that source prompt. Acceptance: migrating a prompt from workspace root #2 (in a 2+ root workspace) results in the SKILL folder appearing under root #2, and root #1 is untouched.
- **Trace:**

  > migrateCustomizations() (customizationMigration.ts) picks one target folder per (targetType, storage) from a map built by resolveCustomizationMigrationTargetFolders() (aiCustomizationManagementEditor.ts), which in turn draws candidates from PromptsService.getSourceFolders()/getResolvedSourceFolders() (promptsServiceImpl.ts, promptFilesLocator.ts) — these enumerate all workspace roots via IWorkspaceContextService.getWorkspace().folders, so multiple valid skill destinations can exist. I could not confirm from source alone whether the auto-pick path (matchingFolders.length === 1 shortcut, or getCustomizationMigrationFolders filtering) fails to scope candidates to the specific prompt's own root, or whether some other step is at fault — reproducing interactively in a real multi-root workspace is the needed next step. Do not change the single-root migration behavior, which works correctly per existing tests in customizationMigration.test.ts.
- **Open decisions:**
  - Reproduce interactively: does the bug occur even with only one skills folder available per root (auto-pick path), or only when the quick-pick selection logic misattributes the chosen folder across customizations?
  - Should the destination be inferred automatically from the source file's workspace root, or should the user still be prompted when multiple roots are eligible?
