# Issue #339657 — worktree disk-usage traversal causes high CPU load

[https://github.com/microsoft/vscode/issues/339657](https://github.com/microsoft/vscode/issues/339657)

## Summary

Still present on main: the worktree disk-usage traversal runs in the renderer and issues one resourceResolve RPC per child entry. The recently reviewed state is unchanged, and no fix commit references this issue.

## Change summary

Worktree disk-usage measurement in the Agents renderer generates a large Agent Host IPC storm and high CPU, and the AHP JSONL logging setting is not applied dynamically.

## Best solution

Move the disk-usage traversal into the Agent Host, or use a single batched or recursive size RPC, so the renderer is not orchestrating one request per file. Also make the AHP JSONL logger observe its setting dynamically, or document that it needs a restart.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/providers/agentHost/browser/worktreeDiskUsage.ts`, `src/vs/platform/agentHost/common/agentService.ts`
- **Validation:** Extend src/vs/sessions/contrib/providers/agentHost/test/browser/worktreeDiskUsage.test.ts to assert the number of RPCs does not scale with the number of files in a directory.
- **Behavior:**

  > Measuring session worktree disk usage must not issue a per-file IPC request from the Agents renderer, and it must not saturate the renderer on large worktrees such as node_modules. The reported total size must stay the same. Disabling the AHP JSONL setting should stop logging on existing connections.
- **Trace:**

  > getWorktreeDiskUsage in worktreeDiskUsage.ts drives the recursion from the renderer: resourceList per directory, then Promise.all over resourceResolve per child. The caller chain is SessionStorageCleanupNotice -> SessionWorktreeCleanupService._measureWorktrees. The measurement should stay cancellable and must not change what is reported to the cleanup notice. The separate AHP logging-setting issue is in LocalAgentHostService, which stores a readonly logger from its constructor.
- **Open decisions:**
  - Should the host expose a new size or batch RPC (a protocol change), or should the traversal move wholesale into the Agent Host?
  - Should the AHP JSONL setting apply live to existing connections, or be documented as requiring a restart?
