# Issue #339657 — worktree disk-usage traversal causes high CPU load

[https://github.com/microsoft/vscode/issues/339657](https://github.com/microsoft/vscode/issues/339657)

## Summary

The renderer-side traversal still issues an RPC for every entry, with unbounded per-directory fan-out and timeouts that leave underlying scans running. Keep this older, team-authored report open; the related Windows report supplies additional evidence but is newer and cannot replace it under the re-review rules.

## Change summary

Prevent session worktree disk-usage measurement from saturating the Agents renderer with filesystem RPCs and associated logging overhead.

## Best solution

Make worktree-size measurement bounded and lifecycle-controlled without requiring the renderer to orchestrate every filesystem entry, while preserving accurate totals and compatibility with remote hosts. Address diagnostic logging amplification separately from the independently confirmed traversal bottleneck.

- **Trace:**

  > SessionWorktreeCleanupService._measureWorktrees invokes sessionsManagementService.getSessionWorktreeDiskUsage, which routes to BaseAgentHostSessionsProvider.getSessionWorktreeDiskUsage and then getWorktreeDiskUsage. The cleanup service's raceTimeout releases its limiter slot without stopping that work. Current tests explicitly preserve shared measurement continuation when a foreground waiter cancels.
