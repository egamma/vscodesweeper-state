# Issue #349214 — Automations: show interrupted run status and offer Keep going on the run entry

[https://github.com/microsoft/vscode/issues/349214](https://github.com/microsoft/vscode/issues/349214)

## Summary

Keep open: the conversation offers Keep Going, but automation history still lacks the requested summary-driven interruption status and continuation action. A maintainer confirmed the gap and proposed a shared solution; its protocol contract needs agreement before implementation.

## Change summary

Show resumable interruptions on automation run entries and allow continuing the affected chat directly from the entry.

## Best solution

Expose authoritative, restart-safe continuation eligibility through lightweight summaries and present Interrupted plus Keep Going in automation history and the shared session list. Revalidate eligibility when invoked and continue the exact chat without navigating away or changing existing resume semantics.

- **Behavior:**

  > A resumable interrupted automation run is visibly distinguishable from successful completion before its conversation is loaded. Its entry offers Keep Going with the same continuation behavior as the conversation. Invoking it resumes the affected chat without leaving Automations and rechecks current eligibility. Restart recovery preserves the affordance; successful continuation or lost eligibility removes it. Status and action remain accessible without relying on color alone.
- **Trace:**

  > The maintainer's restored-interruption reproduction is recorded at https://github.com/microsoft/vscode/issues/349214. AgentHostSessionHandler::_getTurnErrorDetails currently derives Keep Going from hydrated turn error details and resumability. AutomationHistorySection uses SessionsFlatList, but registerAutomationHistoryItemActions has no continuation action and the provider-neutral session model has no equivalent eligibility contract. The investigation establishes a lightweight-summary gap, not a missing conversation button. Preserve lazy listing, exact advertised chat identity, existing resume eligibility, and alternate-host compatibility. Uncertainty starts at the summary wire contract and its durable host publication; generated protocol files must not be edited directly.
- **Open decisions:**
  - Should continuation eligibility be a standardized chat/session-summary protocol contract or an optional VS Code-specific default-chat metadata extension, with corresponding interoperability and clearing semantics?
