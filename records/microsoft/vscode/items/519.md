# Issue #519 — Allow to change the font size and font of the workbench

[https://github.com/microsoft/vscode/issues/519](https://github.com/microsoft/vscode/issues/519)

## Summary

Keep open: current main still lacks independent workbench font-family and font-size preferences, and global zoom does not cover the request. Two verified open contributions address the work; review them before considering completion.

## Change summary

Allow users to configure workbench text size and font family independently of editor fonts and global window zoom.

## Best solution

Review https://github.com/microsoft/vscode/pull/319151 for the broader capability and https://github.com/microsoft/vscode/pull/340334 for its sidebar subset, ensuring larger fonts remain usable within virtualized lists and other workbench layouts. Keep this issue tracking the full request rather than treating sidebar-only customization as completion.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/electron-browser/desktop.contribution.ts registers window.zoomLevel as zoom for entire windows, including fractional increments. This scales the surrounding UI rather than independently configuring workbench text, and cannot select a font family.
- **Current source retains fixed typography:** src/vs/workbench/browser/media/style.css sets .monaco-workbench to font-size: 13px and defines platform- and language-specific font-family rules. Targeted inspection of workbench.contribution.ts and workbench.ts found workbench.fontAliasing but no workbench.fontFamily or workbench.fontSize configuration.
- **Layout constraint corroborated:** src/vs/workbench/contrib/files/browser/views/explorerViewer.ts defines ExplorerDelegate.ITEM_HEIGHT = 22 and returns it from getHeight. This corroborates the thread's quoted maintainer explanation and the latest workaround report: increasing CSS font size alone does not adjust virtualized Explorer row geometry.
- **Open broader implementation candidate:** https://github.com/microsoft/vscode/pull/319151 was verified OPEN with mergedAt null. Its body explicitly says Fixes #519 and proposes workbench.fontSize and workbench.fontFamily; an unmerged contribution is not evidence that the request is implemented.
- **Open partial implementation candidate:** https://github.com/microsoft/vscode/pull/340334 was verified OPEN with mergedAt null. It proposes workbench.sideBar.fontFamily and workbench.sideBar.fontSize for primary and secondary sidebar content, explicitly excludes broader workbench customization, and leaves embedded editors and extension webviews using their own font settings.
