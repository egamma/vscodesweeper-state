# Issue #282004 — Dangerous keyboard shortcut in Copilot Chat: Delete triggers multi file undo from chat input

[https://github.com/microsoft/vscode/issues/282004](https://github.com/microsoft/vscode/issues/282004)

## Summary

The destructive shortcut remains present on current main and the exact failure path is source-reproducible. This should stay open as the oldest active report for deciding and implementing a safer default interaction.

## Change summary

Ctrl/Cmd+Backspace in an empty Copilot Chat input invokes Undo All Edits, allowing the following Enter or Space keypress to confirm removal of changes across multiple files.

## Best solution

Do not bind Undo All Edits to a common text-editing chord inside the chat input. Preserve the explicit toolbar/command action and its confirmation while either removing the default shortcut or moving it to a chord that cannot be reached accidentally while deleting prompt text.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing`
- **Validation:** Add a keybinding-resolution test showing that Ctrl/Cmd+Backspace with an empty focused chat input and pending edits does not resolve to `chatEditing.discardAllFiles`; also verify that the chosen explicit Undo All Edits action still opens its confirmation and existing prompt word deletion remains unchanged.
- **Behavior:**

  > Using Ctrl/Cmd+Backspace to delete words in the Copilot Chat input must never unexpectedly invoke Undo All Edits when the prompt becomes empty. With pending multi-file chat edits, an extra Ctrl/Cmd+Backspace must leave those edits untouched and must not open the destructive confirmation dialog. The explicit Undo All Edits action must remain available and retain confirmation. Normal word deletion in non-empty prompt text must remain unchanged.
- **Trace:**

  > ChatEditingDiscardAllAction in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts registers Ctrl/Cmd+Backspace when `hasUndecidedChatEditingResource`, `inChatInput`, and `!chatInputHasText`; this exactly arms the command after prompt text has been erased. The command calls `discardAllEditsWithConfirmation`, whose primary confirmation is `Yes` and whose successful path calls `currentEditingSession.reject()` for the session. The binding originated in https://github.com/microsoft/vscode/pull/232162 and remains on current main. Preserve the explicit toolbar/command action and confirmation semantics; the scope is the unsafe default input keybinding, not chat edit rollback itself. Newer matching reports are https://github.com/microsoft/vscode/issues/306770 and https://github.com/microsoft/vscode/issues/317320.
- **Open decisions:**
  - Should Undo All Edits have no default keybinding while focus is in the chat input, or move to a distinct chord such as Ctrl/Cmd+Shift+Backspace?
