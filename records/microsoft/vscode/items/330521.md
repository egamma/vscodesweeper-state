# Issue #330521 — Feature Request: Queued / Pending Prompts during long-running background tasks in Copilot Chat

[https://github.com/microsoft/vscode/issues/330521](https://github.com/microsoft/vscode/issues/330521)

## Summary

This exact capability — staging follow-up prompts as 'Queued' while a request is in progress, then auto-dispatching them once it completes, with full edit/remove/send-immediately controls — is already shipped in Copilot Chat, so this can be closed as covered by existing behavior.

## Change summary

Request a queued/pending-prompt mechanism so users can type follow-up instructions during a long-running Copilot Chat request instead of waiting or interrupting the stream.

## Best solution

Point the reporter at the existing Queue/Steer feature (Add to Queue / Steer with Message actions, the pending-request UI, and the `chat.requestQueuing.defaultAction` setting) — no new capability is needed.

- **Proposed comment:**

  > Thanks for the request! This is already built into Copilot Chat — while a request is running you can queue a follow-up with "Add to Queue" (or steer the current run with "Steer with Message"), and queued messages show a pending state with options to edit, remove, or send immediately. They're automatically sent once the current request finishes. You can control the default behavior of the queue button via the `chat.requestQueuing.defaultAction` setting. Closing as already covered by existing behavior — please reopen if you're seeing something different from this.

## Evidence

- **queue/steer actions:** src/vs/workbench/contrib/chat/browser/actions/chatQueueActions.ts implements ChatQueueMessageAction ('Add to Queue'), ChatSteerWithMessageAction ('Steer with Message'), plus ChatRemovePendingRequestAction, ChatEditPendingRequestAction, ChatSendPendingImmediatelyAction, and ChatRemoveAllPendingRequestsAction — covering exactly the 'stash & submit', 'smart staging', and management of pending prompts requested.
- **auto-dispatch API:** src/vs/workbench/contrib/chat/common/chatService/chatService.ts declares removePendingRequest, sendPendingRequestImmediately, and pending-request state on the chat model, i.e. queued requests are held and auto-dispatched when the current request completes.
- **user setting:** chat.requestQueuing.defaultAction (src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:1699) with 'queue'/'steer' options controls default behavior when a request is in progress, and defaults to 'steer' but supports full queuing.
- **context keys / UI state:** ChatContextKeys.isPendingRequest, hasPendingRequests, and isRequestVM(context).pendingKind gate menu items (Edit, Remove, Send Immediately) shown only for pending/queued messages, confirming a full 'Pending / Queued' UI state exists.
