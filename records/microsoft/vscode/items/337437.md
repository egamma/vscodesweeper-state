# Issue #337437 — Agent Host: Claude sessions are never reaped — 91 orphaned `claude` processes after 8 days, plus O(n) state broadcasts to unknown sessions

[https://github.com/microsoft/vscode/issues/337437](https://github.com/microsoft/vscode/issues/337437)

## Summary

Keep open: the reporter confirmed substantial Claude process retention and customization log storms through direct lifecycle testing. Current main has resource-release and broadcast-deduplication mechanisms, but they do not establish that this reported failure is resolved.

## Change summary

Completed Claude conversations retain live subprocesses, while customization updates repeatedly target unknown sessions and amplify resource consumption.

## Best solution

Make completed, unobserved Claude conversations eligible for reliable non-destructive runtime release, preserving history and legitimate active work. Ensure customization publication cannot continue targeting removed session state; first identify which subscriptions, activity flags, or provider resources prevent the existing release path from completing.

End with a live process-count check across repeated conversation completion and reopening, distinguishing legitimately pinned sessions from leaked runtimes.
- **Behavior:**

  > The reporter observed Claude subprocesses accumulating across completed conversations until memory pressure made the machine unusable; marking a conversation Done did not release its process, and externally terminating it caused replacement. Completed conversations that no longer need a resident runtime should release their subprocesses without deleting history, and reopening should resume transparently. Active turns and legitimately observed conversations must remain usable. Customization updates must not repeatedly publish to removed session state or generate unbounded identical warnings. Acceptance should cover repeated completion/reopening, stable eligible-runtime counts, preserved history, and removal during an in-flight customization refresh.
- **Trace:**

  > Current AgentService delegates release eligibility to AgentSessionResidency, which applies a ten-session soft limit and archived-session priority but exempts subscriptions, active turns, restoration, and Agent Merge holds. AgentService also reconciles on SessionIsArchivedChanged; the unresolved boundary is whether the reporter's Done workflow removes all residency-pinning client subscriptions and whether provider activity accurately becomes idle. ClaudeAgent._releaseChat resolves one exact backing, skips active or unready pipelines, and disposes its live runtime while retaining cold-resume backing data. The release infrastructure predates the report, so its presence cannot be treated as a fix. AgentSideEffects enumerates current state-manager sessions and suppresses equal customization snapshots, but a pending fetch can still dispatch after state removal when both observed snapshots are undefined. Preserve durable session/catalog history, valid active work, and existing cold-resume behavior; do not equate every listed durable session with a leaked process or remove durable registrations merely because in-memory state is absent. The newer reports https://github.com/microsoft/vscode/issues/340489 and https://github.com/microsoft/vscode/issues/340942 are related performance investigations, not duplicate targets.

A retained subscription can prevent release even for an archived session; the reporter's Done action has not been traced through the client subscription lifetime.
- **Claude teardown boundary:** src/vs/platform/agentHost/node/claude/claudeAgent.ts:1648-1660 implements _releaseChat, skips unready or active pipelines, disposes the live session, and retains backing information for cold resume. _disposeLiveSession at :1344 aborts the runtime and deletes its live entry.
