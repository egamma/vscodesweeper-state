# Issue #350543 — Integrated browser: scoped lifecycle status for historical agent page handles

[https://github.com/microsoft/vscode/issues/350543](https://github.com/microsoft/vscode/issues/350543)

## Summary

A distinct capability gap remains: existing browser tools expose current pages and deferred executions, not authoritative lifecycle history for unavailable handles. Keep this request open for a product decision on scoped status and retention.

## Change summary

Provide permission-scoped historical page lifecycle and client-request status without exposing page content or unrelated tabs.

## Best solution

Define a documented, session-scoped status contract backed by authoritative browser lifecycle observations, returning unknown when evidence is unavailable. Preserve sharing revocation and distinguish page destruction, automation visibility loss, and client-request completion.

## Evidence

- **Existing capability check:** src/vs/workbench/contrib/browserView/electron-browser/tools/listBrowserPagesTool.ts describes list_browser_pages as listing currently shared pages. runPlaywrightCodeTool.ts requires a pageId and supports deferredResultId, but neither exposes historical page lifecycle status.
- **Unavailable-handle path:** src/vs/platform/browserView/node/playwrightService.ts:588-594 throws Page not found when _tryGetPage cannot resolve the handle. _onPageRemoved at lines 664-670 deletes identity mappings without retaining a lifecycle record.
- **Visibility is not destruction:** src/vs/platform/browserView/electron-main/browserViewGroup.ts removeView removes group membership and disposes CDP targets without destroying the underlying browser view. Automation target disappearance therefore cannot establish backend page destruction.
- **Request tracking boundary:** src/vs/platform/browserView/common/playwrightService.ts exposes waitForDeferredResult for a particular tool invocation, not associated network-request status. src/vs/platform/browserView/node/playwrightTab.ts records requestfailed messages for current-page summaries, not a retained pending/terminal/unknown request ledger.
- **Extension API is not equivalent:** src/vscode-dts/vscode.proposed.browser.d.ts exposes current browserTabs, open/close events, BrowserTab.close(), and CDP sessions. It does not expose a historical agent-handle lookup or the requested scoped lifecycle/request-status contract.
- **Close-tool precedent:** https://github.com/microsoft/vscode/issues/312609#issuecomment-4327676637 intentionally declines a dedicated close tool and offers page.close() through Playwright. That addresses closing resolvable pages, not historical status or unavailable handles.
- **Related issues do not own this request:** https://github.com/microsoft/vscode/issues/341248 and https://github.com/microsoft/vscode/issues/340718 are closed reports about sharing and reconnect failures. https://github.com/microsoft/vscode/issues/311974 remains open but requests background, agent-owned pages rather than lifecycle inspection of previously shared handles. None covers this request's full scope.
