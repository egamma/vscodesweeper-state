# Issue #314752 — Copilot CLI session cannot be opened in Chat when historical permission.requested events are validated against the current schema

[https://github.com/microsoft/vscode/issues/314752](https://github.com/microsoft/vscode/issues/314752)

## Summary

Valid backward-compatibility bug: the Copilot CLI SDK's strict Zod schema validation rejects older `permission.requested` events missing the `ephemeral` field (or having it in an unexpected shape), and VS Code's error-recovery path (`isUnknownEventTypeError`) only catches "Unknown event type" errors, not schema validation failures like this one. The session fails to open instead of falling back to partial history.

## Change summary

Opening a historical Copilot CLI session in Chat fails with a Zod schema validation error when older `permission.requested` events don't include the `ephemeral` field in the shape the current SDK expects.

## Best solution

Two fixes are needed: (1) broaden the `isUnknownEventTypeError` guard in `copilotCLIChatSessions.ts` and `copilotCLIChatSessionsContribution.ts` to also catch SDK Zod validation errors (e.g. match `Invalid event at line` or `Invalid literal value`), so the `tryGetPartialSessionHistory` fallback kicks in; (2) upstream to the `@github/copilot` SDK to make the `ephemeral` field optional/lenient in the `permission.requested` event schema for backward compatibility.
