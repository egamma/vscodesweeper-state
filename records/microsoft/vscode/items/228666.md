# Issue #228666 — Utility process: Simplify the command line and make it obvious which process is doing what

[https://github.com/microsoft/vscode/issues/228666](https://github.com/microsoft/vscode/issues/228666)

## Summary

Keep open: VS Code knows each utility process's role, but the inspected launch path does not explicitly expose that role in its command-line arguments. The built-in Process Explorer is only a partial workaround, and no verified canonical or referenced fix establishes completion of this team-authored request.

## Change summary

Make utility-process command lines readable and distinguishable in OS process viewers and debugger attach pickers.

## Best solution

Expose recognizable utility-process roles to external process inspection while preserving startup and debugging behavior. Establish what Electron permits for argument placement and shortening before deciding the cross-platform presentation contract.

- **Behavior:**

  > Utility processes should be recognizable by role when users inspect VS Code through native process tools or an Attach to Process picker. Acceptance should check externally visible command lines on supported desktop platforms and preserve normal process startup and debugger attachment. The record does not settle whether recognizable identities alone suffice or whether shortening and leading placement are also required.
- **Trace:**

  > UtilityProcess.doStart in src/vs/platform/utilityProcess/electron-main/utilityProcess.ts launches bootstrap-fork.js with caller-provided args and execArgv, plus a separate Electron serviceName option. - **Open decisions:**
