# Issue #207717 — Explorer: In folders with large numbers of files, group files by shared prefix

[https://github.com/microsoft/vscode/issues/207717](https://github.com/microsoft/vscode/issues/207717)

## Summary

A real Explorer capability gap remains: file nesting can group files only beneath an existing file, not create virtual groups from a shared prefix. The issue is already correctly classified as under discussion, and no verified older canonical owns the same observable request.

## Change summary

Allow the Explorer to create collapsible virtual groups for files sharing configurable filename prefixes, such as monthly migration buckets.

## Best solution

Decide whether Explorer file nesting should support synthetic parent nodes generated from captured filename prefixes, while preserving the existing behavior for real parent files. The product design should define naming, ordering, file operations, and interaction semantics for these virtual groups before implementation.

## Evidence

- **source gap:** src/vs/workbench/contrib/files/common/explorerFileNestingTrie.ts computes ancestors exclusively from filenames already present in the directory, while src/vs/workbench/contrib/files/common/explorerModel.ts attaches nested children to those existing ExplorerItem instances. Neither path creates a synthetic grouping node.
- **workaround is incomplete:** https://github.com/microsoft/vscode/issues/207717#issuecomment-2000281700 confirms that existing file nesting can pair each down migration with an up migration but cannot create the requested month-level groups.
