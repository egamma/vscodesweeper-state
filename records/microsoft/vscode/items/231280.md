- **Reporter clarification and maintainer confirmation:** The discussion at https://github.com/microsoft/vscode/issues/231280 distinguishes extending a selection with the mouse button held from dragging already-selected text. On 2026-02-10, the reporter confirmed the former gesture in Firefox 147.0.3, and aiday-mar subsequently reported seeing a related _doHitTest error; the earlier unsuccessful attempt does not establish non-reproduction.
- **Current source defect:** src/vs/editor/browser/controller/mouseTarget.ts:1043-1047 calls document.caretPositionFromPoint and immediately reads hitResult.offsetNode.nodeType without checking whether hitResult is null. MouseTargetFactory.doHitTest selects this path when caretRangeFromPoint is unavailable and caretPositionFromPoint exists (lines 1098-1102). A null caret position therefore throws in VS Code's own code.
- **Selection and fallback boundary:** src/vs/editor/browser/controller/dragScrolling.ts:126-158, TopBottomDragScrollingOperation._execute, invokes createMouseTarget during selection auto-scroll and already falls back to an outside-editor position when no usable target position exists. The neighboring caretRangeFromPoint implementation in mouseTarget.ts:1005-1006 also handles an unavailable DOM result with UnknownHitTestResult.

The author reports a before-and-after Firefox reproduction, but the guard is absent from the inspected main source; this is a candidate fix, not a completed fix.
