# Issue #349701 — Agents window: Move to Session takes 0.4–0.8 s before the sessions list updates

[https://github.com/microsoft/vscode/issues/349701](https://github.com/microsoft/vscode/issues/349701)

## Summary

The move still waits for host restoration and catalog updates before changing the list. Keep this open: the related archive fix does not address moving sessions, and the supplied measurements and steps establish a distinct responsiveness problem.

## Change summary

Update the sessions list immediately after choosing a Move to Session destination, restoring the original placement if the host refuses.

## Best solution

Make list placement responsive independently of expensive host restoration, while reconciling with authoritative catalogs and preserving refusal rollback. Retain the host's backing-recovery requirements so a moved legacy chat remains restorable and promotable.

- **Restoration correctness boundary:** AgentService._movedSessionChat documents that full restoration recovers and records a missing provider backing so the nested chat can later become a session again. Removing restoration indiscriminately would bypass an existing correctness requirement.

Optimistic placement must account for these ownership-following notifications rather than treating nesting as an archive-style boolean.
