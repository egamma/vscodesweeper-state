# Issue #52777 — [HTML] Auto tag-closing doesn't work with undo/redo and programmatic changes

[https://github.com/microsoft/vscode/issues/52777](https://github.com/microsoft/vscode/issues/52777)

## Summary

Keep open: the undo/redo portion was fixed, but the acknowledged programmatic-edit gap remains. This is a team-authored Backlog debt item, and no older canonical with the same observable symptom has been established.

## Change summary

Make HTML auto-tag closing distinguish direct typing from undo/redo and programmatic document changes so collaborative or automated edits do not generate duplicate closing tags.

## Best solution

Provide an editor or extension API that lets language features react specifically to local typing, then migrate HTML tag closing away from inferring user intent from generic document-change events. Preserve normal local HTML auto-closing while ignoring remote and programmatic edits.

- **Behavior:**

  > HTML auto-tag closing should run once for a participant's direct typing, but not for document changes produced by Live Share synchronization, workspace edits, or undo/redo. A direct typed trigger must continue to produce exactly one matching closing tag. Programmatic edits and synchronized remote edits must leave the document unchanged beyond the supplied edit.
- **Trace:**

  > The HTML feature historically reacts through extensions/html-language-features/client/src/tagClosing.ts to document changes, but the extension-facing change path does not retain enough origin information to separate keyboard input from programmatic edits. Maintainers confirmed in https://github.com/microsoft/vscode/issues/52777 that undo metadata became available and fixed the undo portion through https://github.com/microsoft/vscode/issues/34484, while the programmatic-change reason remains lost. The likely boundary crosses the HTML client and the main-thread/ext-host document event bridge; it may require a public typing-trigger provider rather than exposing every internal edit reason. Do not regress ordinary local HTML auto-closing or broaden this into changing general undo semantics.
