# Issue #325673 — Agent host: Delete... on a Claude session doesn't delete the SDK transcript — session resurrects on next list refresh

[https://github.com/microsoft/vscode/issues/325673](https://github.com/microsoft/vscode/issues/325673)

## Summary

Current main prevents the reported resurrection through durable registry tombstones, but Claude's destructive chat disposal still explicitly leaves the SDK transcript on disk. The issue remains valid for the incomplete deletion semantics and should be routed to the Agent Host/Claude owners.

## Change summary

Deleting an Agent Host Claude session should also remove its provider transcript instead of retaining the conversation on disk.

## Best solution

Define a provider lifecycle contract that distinguishes permanent session deletion from non-destructive release and ordinary peer-chat removal, then have Claude permanently delete the corresponding SDK transcript for the approved cases.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/agent.ts`, `src/vs/platform/agentHost/node/agentService.ts`, `src/vs/platform/agentHost/node/claude/claudeAgent.ts`, `src/vs/platform/agentHost/test/node/agentService.test.ts`, `src/vs/platform/agentHost/test/node/claudeAgent.test.ts`
- **Validation:** Extend the Agent Host and Claude unit suites to assert that permanent deletion removes the intended SDK transcript and that a subsequent provider discovery/list refresh cannot surface the deleted session, while non-destructive release preserves it.
- **Behavior:**

  > Deleting a top-level Claude session from the Agents window permanently removes its provider transcript and the session does not return after provider discovery, list refresh, or restart. Releasing an idle session remains non-destructive and resumable. The plan must explicitly settle deletion behavior for externally discovered sessions and peer chats before defining their acceptance checks.
- **Trace:**

  > `AgentService._doDisposeSession` in `src/vs/platform/agentHost/node/agentService.ts` destructively tears down each catalog chat and durably tombstones the top-level session, which fixes resurrection even when provider storage survives. Claude's `_disposeChat` in `src/vs/platform/agentHost/node/claude/claudeAgent.ts` shuts down the live query and removes `_chatBackings`, but lines 1621–1623 explicitly leave the SDK transcript on disk. The current `IAgentChats` seam in `src/vs/platform/agentHost/common/agent.ts` distinguishes `disposeChat` from `releaseChat` but does not tell the provider whether disposal is part of permanent top-level session deletion or removal of one peer chat. The earlier direct approach in https://github.com/microsoft/vscode/pull/325683 was closed unmerged before this lifecycle architecture landed, so it should be treated as historical context rather than a ready patch. Preserve durable tombstone behavior and non-destructive idle eviction.
- **Open decisions:**
  - When a user permanently deletes an externally discovered Claude session, should VS Code delete the external CLI transcript or only remove it from the Agent Host catalog?
  - Should removing an individual Claude peer chat also delete its backing SDK transcript, or should destructive transcript deletion be limited to deleting the top-level Agent Host session?
