# Issue #262726 — *First* integrated Git Bash terminal does not load Specified rcfile

[https://github.com/microsoft/vscode/issues/262726](https://github.com/microsoft/vscode/issues/262726)

## Summary

The bug concerns the first (restored/revived) Git Bash terminal not honoring user-configured `--rcfile` args; the discussion stalled with the reporter asking if the maintainer tested with a multi-root workspace. The `confirmation-pending` label is appropriate — more info is still needed to confirm the reproduction scenario.

## Change summary

The first integrated Git Bash terminal (restored on VS Code restart) ignores the user-configured `--rcfile` argument, while newly created terminals honor it correctly.

## Best solution

A maintainer should attempt reproduction using a multi-root workspace with a custom `--rcfile` arg on Git Bash, as the reporter requested. The likely culprit is how the terminal revive path (`_reviveTerminalProcess` in `src/vs/platform/terminal/node/ptyService.ts`) reconstructs the shell launch config — specifically whether user-configured profile args from `terminal.integrated.profiles.windows` are properly carried through the serialized `shellLaunchConfig` during session persistence and revival. If the source-based profile forces `--login -i` during revive and drops user overrides, that's the bug.
