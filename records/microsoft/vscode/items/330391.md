## Summary

Fresh, single-reporter bug (0 days old, no comments/upvotes) about project-level `chat.agentSkillsLocations` entries not showing up in the Agents window, while global-settings entries do. Plausible given the code, but not confirmed by anyone else and not conclusively traced, so this needs more detail before triage can be finished.

## Change summary

Skills configured via project `.vscode/settings.json` under `chat.agentSkillsLocations` are usable via explicit invocation but don't appear in the Agent chat window / 'Agent Customizations for Copilot' panel, unlike skills from user/global settings.

## Best solution

Confirm which harness/session type the reporter is using in the Agents window (Local harness vs. Copilot CLI/Claude/Codex), and whether `IWorkspaceService.getWorkspaceFolders()`/`resolveSkillConfigLocations` in extensions/copilot/src/extension/chatSessions/common/skillConfigLocations.ts correctly resolves relative project-settings paths for that session's working directory; the customization-discovery renderer (src/vs/workbench/contrib/chat/browser/chatDebug/chatCustomizationDiscoveryRenderer.ts) and CopilotCLISkills.getSkillsLocations both consume the same `chat.agentSkillsLocations` key, so the gap is likely in how workspace-scoped config is read for that harness/session rather than a fully separate code path.
