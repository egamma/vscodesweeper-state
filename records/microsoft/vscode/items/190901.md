# Issue #190901 — Notebook cut fails to paste

[https://github.com/microsoft/vscode/issues/190901](https://github.com/microsoft/vscode/issues/190901)

## Summary

Keep this accepted Backlog request open: cutting a notebook cell still overwrites the text clipboard, so the requested separation remains missing. The related clipboard request is closed, and the open undo-stack issue does not own the same observable behavior.

## Change summary

Preserve previously cut text when a subsequent notebook cell cut stores the cell for pasting.

## Best solution

Provide notebook cell clipboard behavior that preserves independently copied or cut text while retaining cell paste support. The notebook owner should settle whether this becomes the default or an optional mode, including the intended behavior when copying cell text into other applications.

- **Trace:**

  > runCutCells in src/vs/workbench/contrib/notebook/browser/contrib/clipboard/notebookClipboard.ts writes current cell text to IClipboardService in all three selection paths, then updates INotebookService.setToCopy. Cutting a cell whose text was already cut consequently overwrites the system clipboard with an empty string. runCopyCells also writes the system clipboard, while runPasteAction and notebook.cell.paste read the separately stored cell state; NotebookService.setToCopy/getToCopy are in browser/services/notebookServiceImpl.ts.
