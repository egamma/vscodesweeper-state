# Issue #239404 — disable terminal tab hover, unusable in portrait mode monitor

[https://github.com/microsoft/vscode/issues/239404](https://github.com/microsoft/vscode/issues/239404)

## Summary

Keep open: current source still overrides the hover's vertical fallback when neither side has room, matching the reported obstruction of terminal tabs. Two open PRs address this issue; review the existing fixes rather than start competing work.

## Change summary

Prevent terminal-tab hovers from covering the tabs and blocking clicks in narrow windows or portrait-monitor layouts.

## Best solution

Ensure a terminal-tab hover stays off its target when neither horizontal side has enough room. Review the fallback correction in https://github.com/microsoft/vscode/pull/338419 alongside the width-constraining approach in https://github.com/microsoft/vscode/pull/246659, and resolve the overlapping proposals before closing the issue.

- **Terminal hover entry point:** src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts:306-319 requests a pointer hover through showDelayedHover, using HoverPosition.LEFT for right-side terminal tabs and HoverPosition.RIGHT for left-side tabs; it does not force the position.
- **Current-source defect:** In src/vs/platform/hover/browser/hoverWidget.ts, adjustHorizontalHoverPosition sets a LEFT hover to BELOW when its width plus pointer offset exceeds the room on both sides. This conclusively traces the erroneous horizontal placement without executing the UI.
