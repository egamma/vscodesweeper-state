# Issue #276603 — Clicking Try Again on a failed request should clear the error and resend the last network request to the model

[https://github.com/microsoft/vscode/issues/276603](https://github.com/microsoft/vscode/issues/276603)

## Summary

A real gap remains in the Copilot extension path: its “Try Again” button submits a new confirmation turn containing that label instead of retrying the failed request. The newer Agent Host path already has the requested resend-and-clear behavior, but it does not cover this path.

## Change summary

Make the error-state “Try Again” action clear the failed response and resend the original model request instead of submitting “Try Again” as a new user turn.

## Best solution

Give Copilot error confirmations an explicit retry semantic that invokes the existing chat resend path, while leaving filtered errors, rate-limit choices, and Agent Host turn-resume behavior unchanged. Because exposing that semantic may extend the proposed chat-participant API contract, a maintainer should settle the API boundary before implementation.

- **Behavior:**

  > When a retryable Copilot model request fails, selecting “Try Again” clears the failed response state and retries the original user request. It must not add “Try Again” as a user-authored turn. If the retry fails, the latest error remains visible and can be retried again. Filtered errors and non-retry confirmation choices retain their current behavior.
- **Trace:**

  > AgentIntent.modifyErrorDetails in extensions/copilot/src/extension/intents/node/agentIntent.ts creates the current button with only `copilotContinueOnError` data. The existing `IChatService.resendRequest` path already reissues the original message and clears the old failed request, while AgentHostSessionHandler demonstrates a separate same-turn resume flow using internal `resend` and `preserveRequestId` fields. Those fields are absent from the proposed `ChatErrorDetailsConfirmationButton` API, which is where the contract uncertainty begins. Keep filtered-error handling, rate-limit choice buttons, and Agent Host resume semantics outside this change.
- **Open decisions:**
