# Issue #344924 — Copilot harness: retain local memories

[https://github.com/microsoft/vscode/issues/344924](https://github.com/microsoft/vscode/issues/344924)

## Summary

The existing local-memory setting only partially addresses this request: it uses a GitHub-repository JSONL store, not the Local harness's editable user, repository, and session files. Keep this open for memory-backend parity rather than treating the maintainer's setting suggestion as full coverage.

## Change summary

Allow Copilot harness sessions to optionally reuse the Local harness's local, inspectable memory files and scopes.

## Best solution

Provide an opt-in local-memory experience for the Copilot harness that preserves user, repository, and session scopes without requiring GitHub-hosted repositories or placing personal memory in the working tree. Establish the runtime integration and migration contract before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/common/copilotCliConfig.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCopilotCliSettingsContribution.ts`, `extensions/copilot/src/extension/tools/node/memoryTool.tsx`
- **Validation:** With local memory selected, create and inspect user, repository, and session memories in Copilot harness sessions on a non-GitHub workspace. Verify user memory follows the user across workspaces, repository memory remains workspace-scoped, session memory stays conversation-scoped, existing Local harness files can be reused, and no memory file is added to the working tree. Confirm existing cloud-memory behavior remains unchanged when the option is not selected.
- **Behavior:**

  > Copilot harness users should be able to opt into the Local harness's inspectable, editable local memory files rather than requiring cloud-backed or working-tree memory. The local experience must retain distinct user, repository, and session scopes and work without a GitHub-hosted repository. Existing memories should remain usable, and opting in should not create personal-memory files in the working tree.
- **Trace:**

  > chat.shared.contribution.ts registers the existing local-memory setting with explicit GitHub-hosting and scope limitations. AgentHostCopilotCliSettingsContribution forwards configuration, and copilotSessionLauncher.ts selects the runtime's in-repository store through copilot_swe_agent_memory_in_repo_store. The separate MemoryTool in extensions/copilot/src/extension/tools/node/memoryTool.tsx supplies the Local harness's file-based scopes. The trace establishes the mismatch but not a supported runtime integration for that store; planning must identify that boundary and its create/resume lifecycle. Preserve existing cloud behavior and authoritative runtime policy enforcement. Related user-memory and tool-provisioning reports are https://github.com/microsoft/vscode/issues/342279 and https://github.com/microsoft/vscode/issues/334251.
