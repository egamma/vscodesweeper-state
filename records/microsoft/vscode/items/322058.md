# Issue #322058 — Updating the remote tunnel service caused a failure

[https://github.com/microsoft/vscode/issues/322058](https://github.com/microsoft/vscode/issues/322058)

## Summary

Team-authored bug report: the remote tunnel service update flow left stale `new_`-prefixed files that prevented the tunnel from restarting, breaking the session despite the promise that it would not be interrupted. No fix commits reference this issue; keeping open and routing to the tunnel area.

## Change summary

Choosing 'Always update' for the remote tunnel service broke the connection and left stale staging files that prevented the tunnel from restarting.

## Best solution

The tunnel server update mechanism should atomically swap the updated binary and clean up staging artifacts (the `new_`-prefixed files) on failure, so a failed update doesn't leave the tunnel in an unrecoverable state. The fix likely lives in the CLI update/self-update paths under `cli/src/` (possibly `self_update.rs` or the tunnel code server update flow). The related issue https://github.com/microsoft/vscode/issues/322059 covers the server-side failure screenshot and should be consolidated with this one.
