# Issue #109151 — Text cursor indicator displays incorrect

[https://github.com/microsoft/vscode/issues/109151](https://github.com/microsoft/vscode/issues/109151)

## Summary

Keep open: this accepted Backlog bug has repeated Windows reproductions, including reports with extensions disabled, and current source still relies on synthetic editor input surfaces whose native caret geometry can diverge from the rendered cursor. No verified fix for this issue or broader open canonical was found.

## Change summary

Make the Windows accessibility text cursor indicator follow the visible VS Code editor caret instead of appearing at an incorrect location.

## Best solution

Reproduce the indicator behavior on current Windows with both the default native EditContext path and the textarea fallback, then make the active input surface expose caret geometry that stays synchronized with the rendered editor cursor without regressing screen-reader or IME behavior.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts`, `src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts`, `src/vs/editor/browser/controller/editContext/native/screenReaderSupport.ts`
- **Validation:** On current Windows, enable Settings > Accessibility > Text cursor > Text cursor indicator, then verify in a focused editor that typing, repeated Left/Right and Up/Down navigation, selection, horizontal and vertical scrolling, wrapped lines, and zoom keep the OS indicator aligned with the visible caret under both the default EditContext path and the textarea fallback; also run the existing editor input and IME tests.
- **Behavior:**

  > With the Windows Text Cursor Indicator enabled, its two colored markers must remain aligned with VS Code's visible editor caret while typing, navigating character-by-character or line-by-line, selecting text, scrolling, wrapping, and zooming. It must not remain on an earlier line, jump to the editor corner, or disappear while the caret is visible. Screen-reader input and IME composition behavior must remain unchanged.
- **Trace:**

  > The editor can use either TextAreaEditContext in src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts or NativeEditContext in src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts. The textarea path computes top/left from the primary cursor and scroll state, then adjusts its internal scroll offsets; the native path positions screen-reader content separately in ScreenReaderSupport. Commit 7cc154201cc32e26f469000bff1dcb801dc1b99f improved the related Windows Magnifier behavior by using the accessibility-sized textarea path on Windows, but later Text Cursor Indicator reports persisted. The investigation boundary is editor input/caret exposure: do not redesign the rendered cursor, accessibility mode, or general editor layout, and preserve IME and screen-reader semantics. Related reports are https://github.com/microsoft/vscode/issues/105558, https://github.com/microsoft/vscode/issues/164591, https://github.com/microsoft/vscode/issues/179545, and https://github.com/microsoft/vscode/issues/283921.
