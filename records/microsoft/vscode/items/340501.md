# Issue #340501 — Copilot harness in Dev Containers fails Git HTTPS authentication (missing REMOTE_CONTAINERS_IPC)

[https://github.com/microsoft/vscode/issues/340501](https://github.com/microsoft/vscode/issues/340501)

## Summary

Reproducible gap confirmed in source: the Dev Container Agent Host launch path (src/vs/platform/agentHost/node/devContainerAgentHostService.ts) execs the agent host and Git configuration commands via the devcontainer CLI without ever setting or forwarding REMOTE_CONTAINERS_IPC, so the Dev Containers Git credential helper inside the container has no socket to reach the host's stored HTTPS credentials — matching the reporter's own terminal test (env -u REMOTE_CONTAINERS_IPC reproduces the same failure). This is distinct from the already-fixed Git identity issue (#335761); closing here as mid-verification/duplicate would be wrong since that issue covered author identity, not credential-helper IPC.

## Change summary

Git HTTPS authentication (via the Dev Containers credential helper) fails for the Copilot/Agent Host harness inside a Dev Container because REMOTE_CONTAINERS_IPC is not defined in that process's environment, even though it works in the integrated terminal.

## Best solution

Investigate how VS Code's own Dev Containers integrated terminal obtains/forwards REMOTE_CONTAINERS_IPC (likely a socket set up by the Dev Containers extension/CLI) and apply the same forwarding when devContainerAgentHostService.ts execs the agent host and Git configuration commands — similar to how it already injects VSCODE_REMOTE_CONTAINERS_SESSION_ENV into the spawn command. This may need coordination with the devcontainers CLI / Dev Containers extension if the socket isn't otherwise discoverable from this process.

- **Behavior:**

  > Git HTTPS operations run by the Copilot/Agent Host harness inside a Dev Container should succeed using the same forwarded credentials the integrated terminal uses, without requiring the user to manually export REMOTE_CONTAINERS_IPC. Acceptance: `git ls-remote` (or any HTTPS git operation) against a private remote succeeds from an Agent Host session the same way it does from the integrated terminal in the same container.
- **Trace:**

  > devContainerAgentHostService.ts execs the agent host and Git setup commands (_createExec, _spawnDevContainer) via the devcontainer CLI's `exec` subcommand without ever setting or forwarding REMOTE_CONTAINERS_IPC, unlike whatever mechanism establishes it for the Dev Containers-managed integrated terminal (not visible in this repo — likely owned by the devcontainers CLI or the Dev Containers extension). The existing _configureGitIdentity()/_configureGitSafeDirectory() calls (lines 292, 301) are the closest analogous one-time container setup hooks and show the pattern already used for forwarding host Git state into the container; the fix for IPC forwarding should not disturb that existing identity/safe-directory configuration. Related: https://github.com/microsoft/vscode/issues/335761 (git identity, already fixed, different root cause) and https://github.com/microsoft/vscode-remote-release/issues/4202 (general discussion of Git credential helper for external shells in Dev Containers).
- **Open decisions:**

## Evidence
