# Issue #331993 — Chat paste attachment lifecycle diverges between the workbench and Agents window inputs

[https://github.com/microsoft/vscode/issues/331993](https://github.com/microsoft/vscode/issues/331993)

## Summary

Keep open: this team-authored cleanup identifies a concrete testing gap between two active chat-input implementations, and current main still has separate lifecycle reconciliation with coverage only for the Agents window path.

## Change summary

Add a shared conformance suite that verifies pasted-attachment lifecycle behavior in both the workbench chat input and the Agents window input.

## Best solution

Define one shared paste-attachment lifecycle scenario table and consume it from both input implementations' browser tests, covering paste, undo/redo, reference deletion, attachment deletion, and the attachment payload sent with the request without unifying the production implementations.

- **Behavior:**

  > Workbench chat and the Agents window must expose the same lifecycle for a pasted-text attachment even though their implementations remain separate. A qualifying paste creates both an attachment and inline reference; undo and redo keep them synchronized; deleting either representation removes the other; and after every transition the attachments included in the outgoing request exactly match what the input displays. Existing behavior for non-qualifying paste content must remain unchanged.
- **Trace:**

  > The shared paste decision boundary is IChatPasteTarget, implemented by ChatWidgetPasteTarget in src/vs/workbench/contrib/chat/browser/attachments/chatWidgetPasteTarget.ts and NewChatInputPasteTarget in src/vs/sessions/contrib/chat/browser/newChatInputPasteTarget.ts. Post-creation lifecycle remains separate: ChatDynamicVariableModel in src/vs/workbench/contrib/chat/browser/attachments/chatDynamicVariables.ts tracks editor decorations and refreshes parsed input, while AgentHostInputCompletionHandler::_updateDecorations in src/vs/sessions/contrib/chat/browser/agentHostInputCompletions.ts reconstructs references from raw text. The Agents window lifecycle harness already exists in src/vs/sessions/contrib/chat/test/browser/newChatInputPaste.test.ts; current workbench tests exercise lower-level dynamic-variable cases but not the same end-to-end scenario matrix. Follow the test-only scenario-sharing pattern established by modelSelectionConformance.ts and its two consumers. Keep production reconciliation implementations separate and do not redesign either chat input or alter paste thresholds as part of this debt item.
