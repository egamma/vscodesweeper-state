# Issue #122698 — Make a single Windows installer

[https://github.com/microsoft/vscode/issues/122698](https://github.com/microsoft/vscode/issues/122698)

## Summary

The requested installation-time choice is still missing: current source builds separate user and system installers. The linked implementation PR was closed without merging, and no verified open canonical owns the same request.

## Change summary

Provide one Windows installer that lets users choose installation for the current user or all users without downloading another installer.

## Best solution

Provide a single Windows installer with an explicit installation-scope choice while preserving existing installations and unattended updates. First settle migration behavior and the transition away from the two existing download artifacts.

## Plan brief

- **Likely files:** `build/gulpfile.vscode.win32.ts`, `build/win32/code.iss`, `src/vs/platform/update/electron-main/updateService.win32.ts`
- **Validation:** On Windows, exercise fresh current-user and all-users installations from the same executable, then upgrades of existing user-only, system-only, and coexisting installations. Verify interactive scope selection, unattended updates without prompts, preserved installation identity, and no unintended scope changes.
- **Behavior:**

  > A person downloading the Windows installer can choose current-user or all-users installation without returning to the website for a different executable. Existing installations must continue updating in their original scope without unexpected prompts or duplicate installations. Acceptance includes fresh installations in both scopes and interactive and unattended upgrades from the existing installers.
- **Trace:**

  > buildWin32Setup in build/gulpfile.vscode.win32.ts currently creates separate artifacts, selects scope-specific AppIds, and writes a fixed product target. build/win32/code.iss uses InstallTarget preprocessor branches for installation directory, privileges, and registry roots; scope is not a runtime choice. Win32UpdateService.buildUpdateFeedUrl in src/vs/platform/update/electron-main/updateService.win32.ts also distinguishes the user update feed. The closed, unmerged attempt at https://github.com/microsoft/vscode/pull/238042 documents unresolved compatibility and silent-update concerns, so it is prior research rather than a shipped fix or an active competing implementation. Preserve installation identity and unattended update behavior; the uncertainty begins with user-visible migration requirements and download-transition policy.
- **Open decisions:**
  - Must existing user and system installations upgrade in place without uninstalling, including machines where both scopes coexist?
  - Should the transition immediately replace both download artifacts, or retain legacy scope-specific installers temporarily while introducing the combined installer?

## Evidence

- **Current capability remains split:** build/gulpfile.vscode.win32.ts:61–109 accepts only separate 'system' and 'user' build targets, selects different AppIds, and embeds the selected target in product.json. build/win32/code.iss:49–55 chooses installation directory and privileges at compile time; it does not offer the requested runtime scope choice. Choosing the other existing download does not satisfy the central ask.
- **Update compatibility boundary:** src/vs/platform/update/electron-main/updateService.win32.ts:208–217 selects a different update-feed platform for user installations. Combining installer artifacts therefore involves existing installation identity and update delivery, not only adding an installer dialog.
- **Linked implementation did not land:** https://github.com/microsoft/vscode/pull/238042 is CLOSED with mergedAt null, closed on 2025-12-12. Its discussion identifies AppId compatibility, silent-update scope selection, and installations where both scopes exist as transition concerns: https://github.com/microsoft/vscode/pull/238042#issuecomment-2597510385 and https://github.com/microsoft/vscode/pull/238042#issuecomment-2606586648.

Documentation improvements did not deliver installation-time scope selection.
