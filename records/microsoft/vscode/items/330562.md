[https://github.com/microsoft/vscode/issues/330562](https://github.com/microsoft/vscode/issues/330562)

## Summary

The native swap action already exists for eligible file comparisons, but clipboard comparisons remain excluded and their ordering is not configurable. Keep the remaining clipboard request open for a product decision; folder comparison has separate extension-candidate precedent.

## Change summary

Reuse the existing swap surface if clipboard comparisons gain supported reversal, with an explicit decision about editability and default ordering that preserves selective-change workflows. Treat directory comparison separately, following the established extension-candidate precedent rather than expanding this clipboard request.

## Evidence

- **Existing native capability:** src/vs/workbench/browser/parts/editor/editor.contribution.ts registers a title-bar arrowSwap action; diffEditorCommands.ts exposes workbench.action.compareEditor.swapSides. DiffEditorCommandsService.swapDiffSides in diffEditorCommandsService.ts replaces the current diff with its original and modified inputs exchanged. The assertion that native swapping never exists is therefore too broad.
- **Remaining clipboard limitation:** src/vs/workbench/contrib/files/browser/fileActions.ts, CompareWithClipboardAction.run, unconditionally assigns the clipboardCompare virtual resource to original and the active file to modified, without reading an orientation setting. src/vs/workbench/browser/parts/editor/editorGroupView.ts gates swapping on a non-read-only original input and file-provider-backed or untitled resources on both sides; clipboardCompare does not meet that resource gate.
- **Maintainer explanation and related request:** https://github.com/microsoft/vscode/issues/259434#issuecomment-3156188594 explains that the editable file intentionally appears on the right to permit selectively applying clipboard changes, and that swapping is restricted to editable comparisons. That issue requested clipboard ordering and swapping, but was closed for insufficient community votes, not because the capability shipped; it is not an eligible duplicate canonical.
