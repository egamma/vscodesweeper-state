## Evidence

- **Current source confirms the failure:** extensions/copilot/src/extension/tools/node/editNotebookTool.tsx: EditNotebookTool.invoke reads this.promptContext?.stream and throws ErrorWithTelemetrySafeReason('Invalid input, no stream', 'invalid_input_no_stream') when absent, before opening the notebook. Insert, delete, and cell-text changes subsequently depend on stream.notebookEdit or stream.textEdit.
- **Confirmed reports and workaround:** The discussion at https://github.com/microsoft/vscode/issues/343214 confirms failures on Linux in 1.143.0 and 1.144.0 for both editing an existing cell and inserting a cell. Another reporter identifies the Copilot harness as affected and reports that switching a new session to Local permits notebook editing.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/345123 is currently open. Its description identifies tool invocation without resolveInput as the missing-stream trigger and proposes applying notebook and cell edits through WorkspaceEdit when no applicable stream exists; it also addresses stale prompt-context streams. This is pending work, not a landed fix.
- **Follow-up scope:** The November 15 comment at https://github.com/microsoft/vscode/issues/343214 distinguishes missing notebook Keep/Undo and checkpoint support, referencing https://github.com/microsoft/vscode/issues/343685, from an Assisted permissions false rejection when populating an empty cell. Neither establishes that the original missing-stream failure has been resolved.
