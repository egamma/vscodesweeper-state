# Issue #336394 — Hosted Agent: Codex Agent: agent unable to read it's own path, e.g. `~/.codex`, in `Auto-Review` mode

[https://github.com/microsoft/vscode/issues/336394](https://github.com/microsoft/vscode/issues/336394)

## Summary

Plausible sandbox-profile gap for Codex's Auto-Review mode (which uses the same sandboxed filesystem profile as Default, just with `approvalsReviewer: auto_review` instead of prompting the user) — the workspace permission profile in codexLaunchConfig.ts denies `:root` and only allowlists the workspace roots and tmp dirs, with no explicit allowance for CODEX_HOME (`~/.codex`). But I can't confirm from this checkout alone whether Codex's own built-in `:workspace` profile (defined in the external codex CLI/sandbox helper, not in this repo) already grants read access to CODEX_HOME by default, so the root cause is unverified.

## Change summary

In Hosted Agents' Codex Auto-Review mode, the sandboxed agent gets 'Operation not permitted' reading its own `~/.codex/plugins/cache` and `~/.codex/skills`, and files one folder above the workspace root; Full Access mode works fine.

## Best solution

An agentHost/Codex-sandbox maintainer should check whether `codexPermissionProfileOverrides`/`codexPermissionProfile` in src/vs/platform/agentHost/node/codex/codexLaunchConfig.ts needs to add explicit read access to CODEX_HOME for the vscode-workspace permission profiles; the workspace-parent-folder denial is likely intended sandbox behavior and probably not part of the bug.
