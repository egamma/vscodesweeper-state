# Issue #325830 — Subagents UX in editor window

[https://github.com/microsoft/vscode/issues/325830](https://github.com/microsoft/vscode/issues/325830)

## Summary

Keep open: current main implements the compact, open-in-editor UX, but the editor client still subscribes to unopened child chats to enrich and update the parent transcript. The remaining subscription-lifecycle requirement is real, and this team-authored issue has no explicitly linked fixing commit or canonical duplicate.

## Change summary

Align editor-window subagents with the Agents window by using non-expandable pills that open dedicated chat editors without subscribing to unopened child chats.

## Best solution

Retain the default compact pill and dedicated chat-editor behavior, while making unopened subagents rely only on lightweight session-catalog metadata; acquire the child ChatState subscription when its chat editor opens and release it when that chat closes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-chat/state.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostChatContribution.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatSubagentContentPart.test.ts`
- **Validation:** Extend the AgentHost chat contribution tests to assert that hydrating a parent containing subagent pills does not acquire a child StateComponents.Chat subscription, then assert that opening the child editor acquires it and disposing the editor releases it; retain the existing renderer tests for the non-expandable pill and editor-opening behavior.
- **Behavior:**

  > In an editor-window parent chat, a subagent is represented by a compact, keyboard-accessible pill rather than an expandable inline transcript. Activating the pill opens that subagent in its own pinned chat editor, both while it is running and after completion. Merely displaying or restoring the parent chat must not subscribe the client to the child's full ChatState; the subscription exists only while the child chat is fully open. The pill must still communicate the maintainer-selected minimum status and input-needed information without requiring that subscription.
- **Trace:**

  > The presentation half already exists: `ChatSubagentContentPart._updateOpenChatOnlyMode` suppresses the collapsible surface, and `chatSubagentOpenChat.ts` maps the child resource into a dedicated editor. The remaining conflict is in `AgentHostSessionHandler`: parent-history enrichment and live `_observeSubagentSession` processing call `_ensureChatSubscription` for each eligible child, with lifetime managed by `_additionalChatSubscriptions`, even if no child editor is open. `SessionState.chats` exposes lightweight `ChatSummary` metadata including status and activity, but active-tool, usage, and confirmation details currently come from child ChatState. Preserve the existing editor-opening, keyboard/ARIA behavior, Agents-window behavior, and explicit legacy inline-rendering setting; the uncertainty starts at which pill details must be projected into catalog metadata versus omitted until the child editor opens.
- **Open decisions:**
  - Which user-visible details must an unopened subagent pill retain without a child ChatState subscription—catalog status/activity only, or also active tool, credit usage, and input-required state via an expanded ChatSummary contract?
