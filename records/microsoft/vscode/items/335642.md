# Issue #335642 — beforeWhitespace setting doesn't seem to work as intended

[https://github.com/microsoft/vscode/issues/335642](https://github.com/microsoft/vscode/issues/335642)

## Summary

Confirmed real bug from source: the `autoClosingBrackets`/`autoClosingQuotes` 'beforeWhitespace' strategy is supposed to require the cursor be left of literal whitespace, but the end-of-line guard in the autoclose check bypasses that validation entirely when nothing follows on the line, so autoclose always fires at EOL even though the strategy's own predicate excludes newline. The reporter (a VS Code collaborator) gave a precise before/after repro and explicit expected behavior.

## Change summary

With `editor.autoClosingBrackets`/`autoClosingQuotes` set to 'beforeWhitespace', typing an opening bracket at the end of a line (cursor followed only by a newline, no trailing space) incorrectly auto-closes it, when the setting's semantics (cursor must be left of whitespace) should prevent that.

## Best solution

In the per-position loop of `_findAutoClosingPairOpen`/autoclose check in cursorTypeEditOperations.ts, stop skipping the whitespace check when `lineAfter.length === 0`; treat end-of-line as a virtual '\n' and run it through the same `shouldAutoCloseBefore` predicate instead of implicitly allowing autoclose.
