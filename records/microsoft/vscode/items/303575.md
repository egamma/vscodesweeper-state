# Issue #303575 — Add install URI / deep link support for agent plugin marketplaces

[https://github.com/microsoft/vscode/issues/303575](https://github.com/microsoft/vscode/issues/303575)

## Summary

The core deep-link flow already shipped in VS Code 1.113, but the confirmation currently shows only the parsed source reference, not the requested marketplace name, owner, description, and repository metadata. That remaining trust-preview enhancement is a real gap and should be routed to the agent-plugins area.

## Change summary

Show descriptive marketplace metadata in the confirmation presented by the agent-plugin marketplace installation deep link.

## Best solution

Keep the existing `vscode://chat-plugin/add-marketplace?ref=<source>` flow, but give users a trustworthy marketplace preview before modifying `chat.plugins.marketplaces`, with explicitly defined behavior when metadata is unavailable or the source is not GitHub.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/pluginUrlHandler.ts`, `src/vs/workbench/contrib/chat/test/browser/plugins/pluginUrlHandler.test.ts`, `src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts`, `src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts`
- **Validation:** Extend the PluginUrlHandler browser tests to verify the metadata shown in the add-marketplace confirmation, the decided unavailable-metadata behavior, and that configuration changes still occur only after explicit confirmation.
- **Behavior:**

  > Opening `vscode://chat-plugin/add-marketplace?ref=<source>` must focus VS Code and require explicit confirmation before changing user configuration. The confirmation should identify the marketplace with its name, owner, description, and repository URL when those values can be established, rather than showing only an opaque source reference. Declining must leave `chat.plugins.marketplaces` unchanged, and unavailable metadata must follow the maintainer-selected fallback behavior. Existing plain-text/base64 references and canonical deduplication must continue to work.
- **Trace:**

  > `PluginUrlHandler._handleAddMarketplace` in `src/vs/workbench/contrib/chat/browser/pluginUrlHandler.ts` parses the reference, displays `displayLabel` and `rawValue`, then appends the reference to `ChatConfiguration.PluginMarketplaces` after confirmation. The flow was introduced by https://github.com/microsoft/vscode/pull/302556 and is covered by `src/vs/workbench/contrib/chat/test/browser/plugins/pluginUrlHandler.test.ts`. `IMarketplaceReference` contains clone and GitHub identity information but no description, and the current marketplace manifest model contains plugin-level rather than marketplace-level descriptive metadata. The uncertainty starts at provenance: GitHub repository metadata, marketplace-provided metadata, and link-supplied metadata have different availability and trust properties. Preserve the existing URI formats, explicit confirmation requirement, deduplication, and configuration target; the plugin-install route is outside this issue's remaining scope.
- **Open decisions:**
  - Which source is authoritative for the displayed marketplace name, owner, description, and repository URL, particularly when repository and marketplace-provided metadata differ?
  - For arbitrary Git sources or network failures where descriptive metadata cannot be resolved, should the dialog permit a clearly labeled source-only confirmation or prevent the marketplace from being added?

## Evidence

- **existing capability:** VS Code 1.113 documents `vscode://chat-plugin/add-marketplace?ref=<source>` as the supported marketplace-install URL: https://code.visualstudio.com/updates/v1_113#_url-handlers-for-plugin-installation
- **implementation:** Merged pull request https://github.com/microsoft/vscode/pull/302556 and commit https://github.com/microsoft/vscode/commit/988ee7fee3f4d76f1fbc1206c1fd72bd47170246 added the handler, confirmation, deduplication, and user-setting update before this issue was filed.
- **remaining source gap:** On current main, `src/vs/workbench/contrib/chat/browser/pluginUrlHandler.ts` builds the add-marketplace dialog from `ref.displayLabel` and `ref.rawValue` only; it does not resolve or display marketplace name, owner, description, or repository metadata.
- **metadata boundary:** `IMarketplaceReference` in `src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts` carries source identity but no description, while `IMarketplaceJson` in `src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts` exposes plugin metadata rather than the requested marketplace-level metadata.
- **related tracking:** The broader URL-handler request https://github.com/microsoft/vscode/issues/302316 is closed as implemented, and targeted searches found no open canonical issue specifically owning the confirmation-metadata gap.
