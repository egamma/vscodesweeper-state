# Issue #332152 — OpenRouter provider hardcodes reasoning efforts in copilot extension

[https://github.com/microsoft/vscode/issues/332152](https://github.com/microsoft/vscode/issues/332152)

## Summary

Confirmed in source: OpenRouter's `resolveModelCapabilities` hardcodes `supportsReasoningEffort` to `['low','medium','high']` whenever a model supports any reasoning parameter, ignoring the actual per-model reasoning-effort levels (including `xhigh`) that OpenRouter's models API reports, so those higher tiers are unreachable in the UI.

## Change summary

The OpenRouter BYOK provider always offers only low/medium/high reasoning effort, never exposing model-specific tiers like xhigh that OpenRouter's API actually reports.

## Best solution

In extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts, derive `supportsReasoningEffort` from the model's actual reported reasoning data (per https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties#response-data-items-reasoning) instead of the static `['low','medium','high']` list; the reporter has offered to submit a PR for this.
