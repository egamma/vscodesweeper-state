# Issue #332152 — OpenRouter provider hardcodes reasoning efforts in copilot extension

[https://github.com/microsoft/vscode/issues/332152](https://github.com/microsoft/vscode/issues/332152)

## Summary

Traced and confirmed on main: OpenRouterLMProvider.resolveModelCapabilities hardcodes supportsReasoningEffort to ['low','medium','high'] instead of deriving it from the model's actual reasoning capability data, so levels like 'xhigh' that OpenRouter reports are silently dropped for BYOK users.

## Change summary

OpenRouter BYOK provider always offers only low/medium/high reasoning effort, never exposing higher tiers (e.g. xhigh) that OpenRouter's model list API actually reports for a given model.

## Best solution

Update resolveModelCapabilities in extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts to derive the effort-level array from OpenRouter's per-model `reasoning` data (per https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties) instead of the fixed ['low','medium','high'] literal; the downstream pipeline (byokKnownModelToAPIInfoWithEffort, openAIEndpoint) already handles arbitrary effort arrays, e.g. ['minimal','low','medium','high'] for other providers, so this is a localized, well-contained change.
