# Issue #1792 — Proposal: Add mnemonics to context menu items

[https://github.com/microsoft/vscode/issues/1792](https://github.com/microsoft/vscode/issues/1792)

## Summary

The requested capability remains absent on current main: the shared menu widget supports mnemonic rendering and keyboard activation, but the context-menu service does not enable it. This issue is the established canonical report and has maintainer acceptance plus an On Deck milestone, so it should remain open.

## Change summary

Display and activate Windows-style mnemonic access keys for context-menu items.

## Best solution

Context menus should expose localized mnemonic characters and activate matching items from the keyboard, with a defined policy for commands that do not provide an explicit mnemonic and predictable handling of collisions.

## Plan brief

- **Likely files:** `src/vs/platform/contextview/browser/contextMenuHandler.ts`, `src/vs/platform/actions/common/actions.ts`, `src/vs/base/browser/ui/menu/menu.ts`, `src/vs/base/test/browser/ui/menu/menu.test.ts`
- **Validation:** Add browser menu/context-menu tests that open a menu with explicit, missing, and colliding mnemonics, verify the displayed mnemonic markup, and dispatch mnemonic key events to confirm the intended item is focused or invoked without changing ordinary arrow-key and mouse behavior.
- **Behavior:**

  > On Windows, opening a VS Code context menu should display mnemonic characters and allow the corresponding character key to select or invoke an enabled item. The behavior must cover the agreed scope of core and extension-contributed menu items, handle collisions predictably, and preserve arrow-key, mouse, submenu, disabled-item, and keybinding-label behavior. Acceptance should include explicit, absent, and colliding mnemonic cases.
- **Trace:**

  > The shared `Menu` implementation in src/vs/base/browser/ui/menu/menu.ts already recognizes mnemonic markup, renders it, listens for matching key presses, and cycles duplicate matches when `enableMnemonics` is true. `ContextMenuHandler.showContextMenu` in src/vs/platform/contextview/browser/contextMenuHandler.ts creates this widget without that option, conclusively leaving context menus on the disabled path. `MenuItemAction.label` in src/vs/platform/actions/common/actions.ts uses the normal title value, whereas menubar code separately chooses `mnemonicTitle`, so the trace becomes uncertain at the policy for actions without mnemonic-bearing labels, especially extension-contributed commands. Preserve existing menu navigation and invocation semantics; collision cycling is existing widget behavior unless the maintainer chooses a different user-visible contract. Related reports are younger duplicates of https://github.com/microsoft/vscode/issues/1792, not alternate canonicals.
- **Open decisions:**
  - Should context-menu mnemonics be limited to commands with explicitly localized mnemonic titles, or should VS Code assign mnemonics automatically so ordinary and extension-contributed items receive them too?

## Evidence

- **current source gap:** src/vs/base/browser/ui/menu/menu.ts supports `enableMnemonics`, renders mnemonic markup, handles matching key presses, and cycles colliding actions; src/vs/platform/contextview/browser/contextMenuHandler.ts constructs `Menu` without setting that option, so context menus do not use the capability.
- **action-label boundary:** src/vs/platform/actions/common/actions.ts (`MenuItemAction.label`) selects the ordinary localized title value rather than `mnemonicTitle`, while menubar-specific code explicitly selects `mnemonicTitle`; enabling the widget alone may therefore not cover all command and extension-provided context-menu items.
- **maintainer direction:** A maintainer stated that custom menus made this possible but that the context-menu service had not enabled the mnemonic option: https://github.com/microsoft/vscode/issues/1792#issuecomment-421132926.
- **canonical status:** The younger reports https://github.com/microsoft/vscode/issues/97421, https://github.com/microsoft/vscode/issues/146665, and https://github.com/microsoft/vscode/issues/174038 were all closed by maintainers as duplicates of this issue. No older open issue with the same observable request was found.
- **accepted backlog:** The issue carries the `feature-request` and `menus` labels and is assigned to the On Deck holding milestone, so a judgment-based decline would contradict existing triage.
