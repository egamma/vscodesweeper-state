# Issue #266950 — Restore local model selection (ability to disable models) in VS Code Copilot Chat

[https://github.com/microsoft/vscode/issues/266950](https://github.com/microsoft/vscode/issues/266950)

## Summary

Keep open: persistent model-picker hiding is restored, but it does not constrain Auto routing. Maintainers have recently consolidated two requests for Auto model exclusions into this issue, confirming that it owns the remaining work.

## Change summary

Provide persistent local model exclusions that constrain automatic selection as well as the manual model picker.

## Best solution

Provide an explicit local model-availability preference honored by Auto routing and define its reach into subagent and fallback selection, while preserving organization restrictions. Keep this issue as the canonical tracker rather than treating restored picker visibility controls as full completion.

- **Likely files:** `src/vs/workbench/contrib/chat/common/languageModels.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts`, `extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts`, `extensions/copilot/src/platform/endpoint/node/automodeService.ts`, `extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts`, `extensions/copilot/src/platform/endpoint/node/test/automodeService.spec.ts`
- **Validation:** Extend the AutomodeService unit suite with a mocked router returning an excluded model and verify that no request is dispatched to it, including cached selection and routing-failure fallback. Verify preference persistence across reload and unchanged selection for permitted models; add acceptance checks for subagents once their exclusion contract is decided.
- **Behavior:**

  > Users can persistently exclude models they do not want used without organization-admin access. Restored picker hiding alone does not satisfy the request: Auto must respect explicit availability preferences across subsequent turns and reloads. Acceptance must cover an excluded model returned by the router, a previously cached model that becomes excluded, and fallback behavior when no permitted model is available. The product contract must also state whether exclusions cover subagents and utility requests.
- **Trace:**

  > LanguageModelsService in src/vs/workbench/contrib/chat/common/languageModels.ts persists picker-hidden identifiers under chatModelVisibility, and Manage Models is available to Business and Enterprise users in modelPickerItems.ts. EndpointProviderImpl in extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts sends the Copilot auto pseudo-model into AutomodeService, while explicitly selected non-Copilot models take a separate endpoint path. AutomodeService calls AutoV2Fetcher without a local eligibility list; the POST /auto body carries the prompt, image flag, multi-turn state and tier, and returned models can be instantiated from embedded metadata. This establishes the remaining Auto eligibility gap but not the server contract needed to honor exclusions or the complete subagent-selection path. Preserve organization restrictions and direct BYOK main-request behavior; do not treat picker hiding as an existing execution prohibition. Maintainer duplicate decisions at https://github.com/microsoft/vscode/issues/294791 and https://github.com/microsoft/vscode/issues/339680 identify this issue as the tracker for Auto exclusions.
- **Open decisions:**
  - Should hiding a model also prohibit its execution, or should availability exclusions be a separate user-facing preference?
  - Should local exclusions govern only Auto, or also subagents, utility requests and automatic fallbacks?
  - When exclusions leave no eligible model, should the request fail with an explanation or ask the user to choose an explicitly permitted model?
