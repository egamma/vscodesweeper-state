# Issue #252000 — Working progress in ask mode

[https://github.com/microsoft/vscode/issues/252000](https://github.com/microsoft/vscode/issues/252000)

## Summary

Current main still gives Ask mode a top-header progress treatment that disappears when streaming completes, while Agent mode uses bottom progress. This team-authored UX item remains necessary because the desired progress placement is unresolved and no issue-referencing fix has landed.

## Change summary

Prevent Ask-mode responses from jumping upward when the top “Working” indicator disappears after streaming.

## Best solution

Choose an Ask-mode progress treatment that remains discoverable without displacing the response when it completes, while preserving Ask mode's intentional no-auto-scroll reading behavior and leaving Agent-mode scrolling unchanged.

- **Behavior:**

  > While an Ask-mode response streams, progress remains visible without competing with the response being read. When streaming completes, removing or completing that progress must not make the response text jump upward. Ask mode must retain its intentional no-auto-scroll reading behavior, and Agent-mode progress and scrolling must remain unchanged.
- **Trace:**

  > The view-pane and editor hosts configure progressMessageAtBottomOfResponse as `mode => mode !== ChatModeKind.Ask` in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts and src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts. ChatListItemRenderer.renderDetail in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts consequently writes “Working” into the response header only while an Ask response is incomplete, then clears it on completion. Persistent bottom progress exists but is experimental and defaults off in Stable, so it is not a complete resolution. The boundary is Ask-mode progress layout and completion behavior; do not alter Agent-mode auto-scroll semantics or general response rendering. https://github.com/microsoft/vscode/issues/261766 confirms this is the canonical issue and records the preference to preserve Ask's reading behavior while eliminating the jump.
- **Open decisions:**
  - Should Ask mode retain a progress indicator at the top without participating in response layout, or adopt the bottom progress treatment used by Agent mode despite Ask's no-auto-scroll behavior?
