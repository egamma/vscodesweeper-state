# Issue #243940 — MCP: Customize descriptions for server/tools via mcp.json

[https://github.com/microsoft/vscode/issues/243940](https://github.com/microsoft/vscode/issues/243940)

## Summary

User-authored, server-scoped guidance remains missing: current MCP configuration does not expose instructions or tool-description overrides. Keep this team-authored request open for a product decision; support for server-provided instructions does not satisfy the customization request.

## Change summary

Allow users to customize MCP server or tool guidance without adding unrelated instructions to every chat request.

## Best solution

Agree on a scoped customization contract that distinguishes user guidance from server-provided instructions and applies only when the relevant tools are available. Resolve whether the initial capability is server-level guidance or individual tool-description customization before implementation.

- **Behavior:**

  > Users need to tailor MCP tool guidance to their workflows, including distinguishing two instances of the same server, without including that guidance in unrelated chat requests. Existing server-provided instructions and ordinary tool-selection frontmatter do not provide this customization. Acceptance should demonstrate distinct guidance for separate server instances, inclusion only with the relevant tools, and unchanged behavior when no customization is configured. The initial granularity and authoring surface remain to be agreed.
- **Trace:**

  > mcpStdioServerSchema and mcpRemoteServerSchema in src/vs/workbench/contrib/mcp/common/mcpConfiguration.ts reject additional properties and expose no instructions override; the corresponding configuration types are in src/vs/platform/mcp/common/mcpPlatformTypes.ts. The tools accessor in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts represents tool selection rather than a custom-description mapping. https://github.com/microsoft/vscode/issues/250017 covers server-authored initialization instructions, not this remaining user-authored capability. The uncertainty starts at the public customization contract, not at whether the current mcp.json schema supports the proposed field.
- **Open decisions:**
