## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/340148 specifies the font installation path, cache refresh, editor.fontFamily setting, full restart, Snap revision 267, and X11 environment. Computed CSS contains JetBrains Mono, while Rendered Fonts reports DejaVu Sans Mono; the reporter also checked host matching and the Snap font cache.
- **Current editor path:** src/vs/editor/browser/config/domFontInfo.ts::applyFontInfo assigns fontInfo.getMassagedFontFamily() to the DOM font-family property. This is consistent with the reporter’s correctly applied CSS setting, but does not prove that Chromium selects or opens the requested font.
- **Current Snap boundary:** resources/linux/snap/electron-launch exports FONTCONFIG_PATH=/etc/fonts and FONTCONFIG_FILE=/etc/fonts/fonts.conf. resources/linux/snap/snapcraft.yaml uses classic confinement and core20, stages graphics libraries, and excludes bundled usr/share/fonts. These identify the packaging boundary to investigate, not a conclusive defect; no Linux Snap execution was performed.

Its PR, https://github.com/microsoft/vscode/pull/292808, discusses earlier font configuration problems, but the diff does not establish coverage of this system-wide font failure reported against the September 30 release.
