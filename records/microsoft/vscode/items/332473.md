# Issue #332473 — execution_subagent detached terminal completion does not notify parent chat

[https://github.com/microsoft/vscode/issues/332473](https://github.com/microsoft/vscode/issues/332473)

## Summary

Plausible but unconfirmed report about a very new, narrow interaction between the Copilot `execution_subagent` tool and the core background-terminal completion notification path; I traced the relevant code but couldn't conclusively confirm a defect without running it, so this needs more detail from the reporter before a verdict can be made.

## Change summary

When a terminal command started via the `execution_subagent` tool times out and detaches into the background, its later completion doesn't resume/notify the parent chat, unlike terminals started directly by the main agent.

## Best solution

A maintainer familiar with `ExecutionSubagentToolCallingLoop` and `RunInTerminalTool#_registerCompletionNotification` should confirm whether the subagent's nested terminal invocation shares the same `chatSessionResource`/session as the parent turn at notification time; if it diverges, the fix likely belongs in extensions/copilot/src/extension/prompt/node/executionSubagentToolCallingLoop.ts or how the subagent's tool-invocation context is threaded through to src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts.

## Evidence

- **core notification mechanism exists:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts `_registerCompletionNotification` (line ~3002) registers a background-completion listener keyed by `chatSessionResource` that resumes the chat session via `this._chatService` when a background/async terminal finishes — this is the mechanism the reporter expects for directly-owned terminals.
- **subagent reuses parent request:** extensions/copilot/src/extension/tools/node/executionSubagentTool.ts passes `request: request` (the parent's original ChatRequest) into `ExecutionSubagentToolCallingLoop`, and extensions/copilot/src/extension/intents/node/toolCallingLoop.ts reuses `request.toolInvocationToken` for nested tool calls, so in principle the same chat session should be used for the subagent's own `run_in_terminal` calls.
- **subagent's own background handling:** extensions/copilot/src/extension/prompt/node/executionSubagentToolCallingLoop.ts and executionSubagentTool.ts's `appendBackgroundCommandNotesToFinalAnswer` only append a text note to the subagent's own final answer about commands left running in the background — this is a one-time textual note, not a hook into the core completion-notification listener, and it only fires if the subagent loop is still executing when the tool result is built.
- **no confirmation:** Issue is 0 days old, no comments, no reactions, single reporter; the flow (GitHub Copilot Agent mode + execution_subagent + timed-out terminal) is narrow enough that I cannot rule out session/config-specific factors without executing it.
