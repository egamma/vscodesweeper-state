# Issue #308704 — QuickPick does not support icon colors

[https://github.com/microsoft/vscode/issues/308704](https://github.com/microsoft/vscode/issues/308704)

## Summary

Keep this accepted QuickPick color-support request open: current source still drops explicit ThemeIcon colors, and the merged tree-view fix does not change QuickPick. Neither related issue qualifies as a canonical duplicate under the re-review rules.

## Change summary

Support consistent icon colors when extension-provided TreeView items are presented as QuickPick items.

## Best solution

Make QuickPick item icons honor explicit ThemeIcon colors and the applicable tree-view color conventions, while preserving file-icon-theme behavior. Settle whether URI-backed icons need a new color-override contract rather than treating inline codicons as complete coverage.

## Plan brief

- **Likely files:** `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** Use an extension sample showing the same items in a TreeView and both window.showQuickPick and window.createQuickPick. Compare explicitly colored ThemeIcons, default symbol codicons, URI-backed icons, and resourceUri file/folder icons across light and dark themes. Explicit ThemeIcon colors must survive transfer, and existing URI images and file-icon-theme behavior must remain intact; validate any additional URI-color behavior against the agreed contract.
- **Behavior:**

  > Copying a TreeItem's supported icon representation into a QuickPickItem should not silently discard its explicit ThemeIcon color. Default symbol-icon colors should follow the agreed cross-widget convention, without requiring an inline-label workaround. Existing URI-backed image rendering and resourceUri-derived file icons must remain functional. Acceptance should compare matching TreeView and QuickPick items, including explicit colors, default symbol colors, and file icons in light and dark themes.
- **Trace:**

  > IconPath.from in src/vs/workbench/api/common/extHostTypeConverters.ts preserves ThemeIcon data, but MainThreadQuickOpen.expandIconPath in src/vs/workbench/api/browser/mainThreadQuickOpen.ts reduces it to CSS classes and loses the color. The internal IQuickPickItem already has iconColor, consumed by the list renderer, so the explicit ThemeIcon case has an identified boundary. Resource-based file/folder icons take a separate path through expandItemProps and getIconClasses; preserve that behavior and do not assume arbitrary URI images can be recolored by setting foreground color. https://github.com/microsoft/vscode/issues/185356 concerns buttons and shares plumbing, while the newer https://github.com/microsoft/vscode/issues/321773 isolates default symbol-icon colors. https://github.com/microsoft/vscode/pull/320391 only changes custom TreeView rendering. The remaining design uncertainty is whether this request extends the public contract for URI-backed icon color overrides.
- **Open decisions:**
  - Should URI-backed QuickPick icons retain only their intrinsic or file-theme colors, or should this request introduce an explicit theme-color override for them?
