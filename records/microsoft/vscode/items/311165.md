# Issue #311165 — Subject: Codex session handling in VS Code is broken and unacceptable

[https://github.com/microsoft/vscode/issues/311165](https://github.com/microsoft/vscode/issues/311165)

## Summary

The reported sessions are contributed and persisted by the third-party OpenAI Codex extension, which owns their global scope and lifecycle. VS Code does not treat the legacy `openai-codex` provider as Copilot-owned storage, so per-session deletion and workspace separation need to be implemented by that extension.

## Change summary

Allow individual deletion, archiving, and workspace-separated management of sessions created by the OpenAI Codex extension.

## Best solution

The OpenAI Codex extension should expose per-session deletion and scope or filter its session catalogue by workspace while preserving unrelated sessions.

- **Reason:** Session persistence and lifecycle for an external agent provider belong with that extension rather than as Codex-specific behavior in VS Code core.
