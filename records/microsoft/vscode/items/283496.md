# Issue #283496 — Better granularity/configuration options for the "Terminal integrated Suggest" feature

[https://github.com/microsoft/vscode/issues/283496](https://github.com/microsoft/vscode/issues/283496)

## Summary

Keep open: current settings protect shell Tab completion and control automatic suggestions, but do not provide command-specific enablement or independent file/folder exclusions. The maintainer endorsed command-specific opt-in, and the merged defaults and relative-path changes do not fulfill that request.

## Change summary

Allow users to retain terminal suggestions selectively while using native shell completion for excluded commands or file/folder contexts.

## Best solution

Define selective terminal-suggest configuration with the terminal owner, preserving native shell completion in excluded contexts while retaining suggestions elsewhere. Resolve whether command-specific control alone meets the request or independent file/folder filtering is also needed.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/suggest/common/terminalSuggestConfiguration.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalSuggestAddon.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts`, `extensions/terminal-suggest/src/terminalSuggestMain.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/test/browser/terminalSuggestConfiguration.test.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/test/browser/terminalCompletionService.test.ts`
- **Validation:** After the configuration contract is agreed, verify in bash with shell integration and native completion enabled that an excluded cd/path context leaves Tab with the shell, while an included command such as git still offers terminal suggestions. Repeat with Ctrl+Space to verify the chosen explicit-invocation semantics, and add focused configuration/completion tests for included, excluded and unconfigured contexts.
- **Behavior:**

  > Users want terminal suggestions for useful commands without replacing native shell completion in contexts they exclude, such as cd or file/folder selection. Current global controls require either manual invocation everywhere or broad disabling, rather than selecting individual commands. Acceptance should demonstrate shell-owned Tab completion in an excluded context and retained terminal suggestions in an included context. Unconfigured users must retain the existing default behavior.
- **Trace:**

  > The current configuration exposes global enablement, automatic-trigger categories, provider toggles and selection mode, but no command-name policy or independent resource-kind exclusion. TerminalSuggestAddon._sync categorizes command versus argument input using whitespace; TerminalCompletionService._getEnabledProviders filters providers globally. The built-in provider in extensions/terminal-suggest/src/terminalSuggestMain.ts derives currentCommandString and returns spec-driven resource requests, so both automatic triggering and completion content are relevant surfaces. https://github.com/microsoft/vscode/pull/285060 changed defaults and https://github.com/microsoft/vscode/pull/282861 corrected paths, but neither supplies the requested granularity. Preserve existing defaults, unrelated completion ranking and native shell behavior; replacing or importing the shell completion engine is outside this request. The uncertainty is the observable configuration contract, not whether a selective-control gap remains.
- **Open decisions:**
  - Should selective configuration enable suggestions only for listed commands, exclude listed commands from otherwise enabled suggestions, or support both modes?
  - Should file/folder suggestions have an independent exclusion control, or should the initial feature be limited to command-specific enablement?
  - Should exclusions suppress only automatically triggered suggestions, or also suggestions explicitly requested with Ctrl+Space?
