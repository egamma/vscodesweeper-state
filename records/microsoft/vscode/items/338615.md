# Issue #338615 — Please provide supported Copilot Chat / VS Code commands or agent tools to initialize, refresh, inspect, and configure the semantic code index for an open workspace.

[https://github.com/microsoft/vscode/issues/338615](https://github.com/microsoft/vscode/issues/338615)

## Summary

Real request, but a meaningful part of the ask already exists in core: Copilot Chat already ships a build-index command, a debug diagnostics-dump command, and a Chat status item reporting index state/reasons — the gap is the finer-grained include/exclude scope control and structured status (indexed count, skipped files, confirmed roots) the reporter wants exposed as first-class commands/agent tools.

## Change summary

Expose commands/agent tools to build, configure scope for, and inspect the status of Copilot's workspace semantic code index.

## Best solution

Extend the existing workspaceChunkSearch surface (commands.ts / workspaceIndexingStatus.ts) with a status command that reports indexed file count, skipped/unreadable files, and confirmed roots, and a way to scope include/exclude beyond `.copilotignore` — but this needs a maintainer product decision on which of these become supported public commands/API vs. internal diagnostics.

## Evidence

- **existing build command:** extensions/copilot/src/extension/workspaceChunkSearch/vscode-node/commands.ts registers `github.copilot.buildRemoteWorkspaceIndex` (Chat: Build Codebase Semantic Index, package.json line ~2826), which triggers indexing and reports success/failure via a progress notification.
- **existing diagnostics command:** The same file registers `github.copilot.debug.collectWorkspaceIndexDiagnostics` (Developer category, package.json line ~2975), which opens a markdown doc streaming `workspaceChunkSearch.getDiagnosticsDump()` — partial coverage of the requested 'inspect index status' ask.
- **existing status surface:** extensions/copilot/src/extension/workspaceChunkSearch/vscode-node/workspaceIndexingStatus.ts implements `ChatStatusWorkspaceIndexingStatus`, a Chat status item showing indexing/ready/not-indexed/error states per repo, with a link to build/update the index — but it does not report indexed file counts, excluded/skipped file lists, or confirmed workspace roots as the issue requests.
- **existing scope control:** package.json includes a `.copilotignore` file-exclude mechanism and settings like `github.copilot.chat.localIndex.enabled` / `github.copilot.chat.workspace.maxLocalIndexSize`, but no per-extension include-pattern or configurable exclude-glob setting matching the reporter's request.
