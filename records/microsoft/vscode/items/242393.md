# Issue #242393 — Sidebar does not empty when no views are present

[https://github.com/microsoft/vscode/issues/242393](https://github.com/microsoft/vscode/issues/242393)

## Summary

The bug remains present on main and is already correctly routed to workbench views. An open draft PR explicitly references this issue and addresses the missing transition when the last visible view container disappears, so the issue must remain open while that human-owned fix is reviewed.

## Change summary

Hide or empty a sidebar when its last conditional extension view becomes unavailable instead of leaving a pseudo-empty active container.

## Best solution

Review and either land or supersede https://github.com/microsoft/vscode/pull/266219, ensuring that a `hideIfEmpty` container becoming empty also deactivates its active pane composite and that the container is restored when a view becomes available again.

## Evidence

- **current source:** `src/vs/workbench/browser/parts/paneCompositeBar.ts` removes a `hideIfEmpty` container from the composite bar when it has no active views, while `src/vs/workbench/browser/parts/compositeBar.ts` currently only resets the active model item in `hideComposite`; it does not call `AbstractPaneCompositePart.hideActivePaneComposite`, leaving the pane content in the reported pseudo-empty state.
- **maintainer confirmation:** A VS Code maintainer states that custom view containers have `hideIfEmpty = true` and should hide automatically when their view is removed: https://github.com/microsoft/vscode/issues/242393#issuecomment-2703306097.
- **open fix attempt:** The open draft https://github.com/microsoft/vscode/pull/266219 explicitly references this issue and adds notification from `CompositeBar.hideComposite` to `hideActivePaneComposite` when the final visible composite disappears; it has not merged into main.
- **related reports:** The same view-management gap is discussed in the newer reports https://github.com/microsoft/vscode/issues/265248 and https://github.com/microsoft/vscode/issues/261140. Neither can be the canonical duplicate for this re-reviewed item because both were created after it.
