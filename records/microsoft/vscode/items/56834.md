# Issue #56834 — Show file picker for 'path' string settings

[https://github.com/microsoft/vscode/issues/56834](https://github.com/microsoft/vscode/issues/56834)

## Summary

Keep this accepted settings-editor request open: current string-setting controls still lack a file picker, and maintainers explicitly directed later requests here. The remaining work needs a configuration-metadata contract and a decision on folder selection.

## Change summary

Allow users to browse for a path in the Settings editor while retaining manual text editing.

## Best solution

Provide an opt-in path-selection control for string settings, preserving ordinary string values and manual editing. Settle the extension-contributed metadata contract and file-versus-folder scope before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/configurationExtensionPoint.ts`, `src/vs/platform/configuration/common/configurationRegistry.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`
- **Validation:** The plan should establish a Settings editor check in which a designated path setting offers browsing, choosing a file updates the visible and persisted string, cancelling leaves the value unchanged, and manual editing still works. Ordinary string settings and policy-disabled settings must retain their existing behavior; include folder selection if approved.
- **Behavior:**

  > Users configuring a path-valued string setting should be able to select a file through a picker instead of typing or copying its path. The textbox must remain manually editable, and cancelling selection must not change the setting. Ordinary string settings must remain unchanged. Acceptance should verify that a selected path appears in the control and is persisted as the setting's string value; folder-selection acceptance depends on the scope decision.
- **Trace:**

  > The original interaction is described at https://github.com/microsoft/vscode/issues/50249#issuecomment-414362277. configurationExtensionPoint.ts currently accepts only singlelineText and multilineText presentation metadata, SettingsTreeSettingElement.initSettingValueType in settingsTreeModels.ts dispatches strings accordingly, and AbstractSettingTextRenderer in settingsTree.ts builds a text input without picker integration. This establishes a missing capability, not a broken existing picker. The maintainers' discussion at https://github.com/microsoft/vscode/issues/97796 favors additional metadata rather than a new JSON-schema primitive type, but does not settle the public contract. Preserve existing string serialization, manual editing, validation, and policy restrictions; planning must also establish local versus remote path interpretation before promising uniform picker behavior.
- **Open decisions:**
  - What public configuration metadata should identify a path-valued string and distinguish file selection from folder selection?
  - Should the initial capability support both files and folders, as requested in the discussion, or files only?
  - For remote settings, which filesystem should the picker browse, and what path representation should be persisted?
