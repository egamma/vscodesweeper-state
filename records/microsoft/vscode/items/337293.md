# Issue #337293 — GitHub Copilot in VS Code 1.138.0 does not respect "Preview" features disabled in the Enterprise policies for Autopilot

[https://github.com/microsoft/vscode/issues/337293](https://github.com/microsoft/vscode/issues/337293)

## Summary

Source-confirmed gap: the Autopilot permission level's enable/disable check in permissionPickerActionItem.ts only reads the `chat.tools.global.autoApprove` policy (backed by the `COPILOT_DISABLE_BYPASS_PERMISSIONS_MODE_KEY` managed setting) — it never consults `chat_preview_features_enabled` (the `editor_preview_features` entitlement the reporter's org disabled). Whether "Autopilot (Preview)" is meant to also respect the generic preview-features toggle is a policy-design call for a maintainer, so this stays open rather than being auto-fixed.

## Change summary

Enterprise policy disabling "Preview" features does not grey out or block enabling the "Autopilot (Preview)" chat permission level.

## Best solution

A maintainer should decide whether `getPermissionLevelMeta`/`isAutoApprovePolicyRestricted` in src/vs/workbench/contrib/chat/browser/widget/input/permissionPickerActionItem.ts (and the sibling checks in chatSuggestNextWidget.ts / chatSlashCommands.ts) should also disable Autopilot when `chat_preview_features_enabled === false`, following the same pattern already used for Chat Hooks (chat.shared.contribution.ts) and Agents Voice (agentsVoice.ts) — or explicitly document that Autopilot is governed only by the bypass-permissions-mode policy, independent of the general preview-features toggle.
