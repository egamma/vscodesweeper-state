# Issue #331842 — VS Code update unexpectedly executes code-tunnel.exe tunnel kill, triggering endpoint security detections

[https://github.com/microsoft/vscode/issues/331842](https://github.com/microsoft/vscode/issues/331842)

## Summary

Traced this in source: `RemoteTunnelWorkbenchContribution` runs on every window's `LifecyclePhase.Restored`, calls `initialize()`/`updateTunnelProcess()` unconditionally, and when Remote Tunnel Access and agent-host sharing are both inactive it calls `coordinator.restart()` which forces a reconcile (bypassing the 'already satisfied' check) and spawns `code-tunnel.exe tunnel kill` as a no-op safety cleanup — on every VS Code launch for every user, not just after updates. Working as designed, but the unconditional subprocess spawn is worth reviewing given the EDR false-positive impact this report describes.

## Change summary

code-tunnel.exe tunnel kill is invoked on VS Code startup/update even for users who have never used Remote Tunnels, tripping endpoint-security SSH/lateral-movement heuristics (MITRE T1021.004).

## Best solution

In src/vs/platform/remoteTunnel/node/tunnelProcessCoordinator.ts, `_reconcile`/`restart()` could skip the `tunnel kill` invocation when there is no evidence a tunnel/service was ever launched (e.g. no tunnel mutex/process and no prior active session), instead of unconditionally shelling out on every restart; alternatively, document this as expected safety-cleanup behavior for security teams tuning EDR rules.
