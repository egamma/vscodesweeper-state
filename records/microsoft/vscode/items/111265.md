# Issue #111265 — Typing } changes the indentation (autoIndent "none" doesn't work)

[https://github.com/microsoft/vscode/issues/111265](https://github.com/microsoft/vscode/issues/111265)

## Summary

Keep open: the current electric-character typing path still realigns closing braces without consulting editor.autoIndent. A maintainer explicitly designated this issue as the tracking report for that defect; the related closed report documents a workaround, not a fix.

## Change summary

Typing a closing brace changes existing indentation even when editor.autoIndent is set to "none".

## Best solution

Make closing-brace typing honor editor.autoIndent: "none" while retaining bracket matching and the established indentation behavior for other modes. Keep this issue as the existing canonical report.

## Evidence

- **Current source confirms the reported trigger:** In src/vs/editor/common/cursor/cursorTypeOperations.ts:166–195, typeWithInterceptors reaches InterceptorElectricCharOperation after the ordinary auto-indent path declines the edit. In src/vs/editor/common/cursor/cursorTypeEditOperations.ts:487–553, the electric-character path checks cursor count, tokenization, selection and matching brackets, but never config.autoIndent. For the report's whitespace-only line beneath int func() {, typing } finds the opening brace and replaces the line prefix with the opening line's indentation.
- **Built-in C++ configuration supplies the trigger:** extensions/cpp/language-configuration.json declares the { } bracket pair. src/vs/editor/common/cursor/cursorCommon.ts:170–180 constructs electricChars from language configuration without consulting autoIndent, and src/vs/editor/common/languages/supports/electricCharacter.ts returns a matching-bracket action when the closing brace is preceded only by whitespace. This does not require the external C/C++ extension.
- **Maintainer confirmation and workaround:** https://github.com/microsoft/vscode/issues/181386#issuecomment-2025561683 explicitly states that editor.autoIndent: 'none' should prevent this indentation, identifies nonempty bracket configuration as the remaining trigger, and closes that newer report in favor of https://github.com/microsoft/vscode/issues/111265. Setting editor.language.brackets to [] is a workaround that changes bracket configuration, not a correction to autoIndent.
- **Extension reference distinguishes ownership:** https://github.com/microsoft/vscode-cpptools/issues/6576#issuecomment-733424712 identifies the closing-brace behavior as coming from VS Code; https://github.com/microsoft/vscode-cpptools/issues/6576#issuecomment-733432235 records filing this core issue.
