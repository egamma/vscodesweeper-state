# Issue #164329 — Jump to first error when clicking on error number in tab

[https://github.com/microsoft/vscode/issues/164329](https://github.com/microsoft/vscode/issues/164329)

## Summary

Keep this accepted feature request open: editor-tab problem counts remain passive decorations, and existing navigation commands do not provide the requested click interaction. The request has 22 upvotes and already passed the community process into Backlog.

## Change summary

Make the problem-count badge on an editor tab clickable to navigate to the first error in that file.

## Best solution

Provide a discoverable, keyboard-accessible navigation action on editor-tab diagnostic badges while preserving normal tab selection. Settle how mixed error/warning counts map to the navigation target before implementation.

- **Behavior:**

  > The editor-tab problem count currently attracts attention but clicking it only performs normal tab activation. The requested interaction navigates directly to the first error in the represented file, without requiring knowledge of F8. Acceptance should cover active and inactive tabs, a caret positioned after the first error, and an accessible equivalent to mouse activation. Ordinary tab selection and existing problem-navigation shortcuts must retain their behavior.
- **Trace:**

  > MarkersDecorationsProvider.provideDecorations in src/vs/workbench/contrib/markers/browser/markersFileDecorations.ts produces a combined error/warning count, with severity reflected by color. DecorationsService renders the count using generated CSS ::after content, and the shared IDecorationData contract contains presentation metadata only. MultiEditorTabsControl.redrawTabLabel passes this decoration to its resource label; registerTabListeners opens or selects the editor without a diagnostic-specific branch. Existing MarkerController navigation in src/vs/editor/contrib/gotoError/browser/gotoError.ts serves next/previous problem commands, not an explicit first-error badge action. Preserve generic decorations from other providers, normal tab-selection semantics, and existing navigation commands. The remaining product uncertainty is how a combined problems badge should choose its target when errors and warnings coexist or only warnings remain. The accepted request is https://github.com/microsoft/vscode/issues/164329; no matching canonical or fixing commit was established.
- **Open decisions:**
  - Should the combined error/warning badge always navigate to the first error when one exists, falling back to the first warning, or navigate to the first problem in document order regardless of severity?
