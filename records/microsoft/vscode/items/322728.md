# Issue #322728 — Custom BYOK endpoint: "Sorry, no response was returned" when empty tool_calls: [] on content deltas

[https://github.com/microsoft/vscode/issues/322728](https://github.com/microsoft/vscode/issues/322728)

## Summary

Confirmed on current main: the stream parser at line 473 of stream.ts checks `if (choice.delta?.tool_calls)` which is truthy for an empty array `[]`, causing content deltas from vLLM-backed endpoints to be swallowed. The fix is small and localized. Not a duplicate of the broad meta issue #253126, and the narrower #255934 was closed as NOT_PLANNED without a code fix landing.

## Change summary

BYOK custom endpoints backed by vLLM return `"tool_calls": []` on content deltas, which VS Code treats as a tool invocation — discarding the actual content and showing 'Sorry, no response was returned.'

## Best solution

Guard the `tool_calls` branch in `extensions/copilot/src/platform/networking/node/stream.ts` (line 473) with a `.length > 0` check so empty arrays are treated the same as absent/null. The same guard should be applied to the `ToolCallsStreamCollector.update` method (line 112) for consistency.
