# Issue #260977 — Chat input isn't scrolled to the top when ctrl+home is used

[https://github.com/microsoft/vscode/issues/260977](https://github.com/microsoft/vscode/issues/260977)

## Summary

Still reproduces on main: the TopCommand in coreCommands.ts uses revealAllCursors which doesn't account for editor padding, leaving a shadow artifact when Ctrl+Home is pressed in padded editors like the chat input. An open PR exists but hasn't been merged.

## Change summary

Ctrl+Home in the chat input moves the cursor to the top but doesn't scroll to reveal the editor's top padding, leaving a visible shadow.

## Best solution

Review and land (or rework) the open PR https://github.com/microsoft/vscode/pull/264883, or implement hediet's suggestion that when the cursor lands on line 1, the editor's top padding should be revealed as well. The fix belongs in `src/vs/editor/browser/coreCommands.ts` in the `TopCommand` class.

- **open PR:** https://github.com/microsoft/vscode/pull/264883 is an open (unmerged) Copilot coding agent PR attempting to fix this by using VerticalRevealType.Top when the cursor reaches position (1,1).
