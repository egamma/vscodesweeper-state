# Issue #348553 — Always on Top is lost if the window is minimized when VS Code quits

[https://github.com/microsoft/vscode/issues/348553](https://github.com/microsoft/vscode/issues/348553)

## Summary

Keep open: current source persists Electron's transient always-on-top value directly, matching the reported macOS failure. The detached-window symptom also needs checking because its persistence path differs.

## Change summary

Preserve each window's Always on Top preference when quitting with that window minimized.

## Best solution

Persist the user's intended Always on Top state independently of temporary minimization effects, for both main and detached windows, while preserving explicit off states and independent per-window toggles.

Repeat with explicit off states and non-minimized controls. Add focused regression tests for persistence when the minimized native query returns false.
- **Behavior:**

  > An enabled Always on Top preference must survive quitting and reopening even when the window was minimized at shutdown. This applies independently to main and detached editor windows. Explicitly disabled states and restoration of non-minimized windows must remain unchanged.
- **Trace:**

  > CodeWindow.serializeWindowState() in src/vs/platform/windows/electron-main/windowImpl.ts reads isAlwaysOnTop() directly in both fullscreen and ordinary branches; WindowsStateHandler persists that result, and defaultBrowserWindowOptions consumes it on restoration. The report documents that macOS returns false while minimized, making the main-window failure traceable without execution. Detached windows instead cache the native query and onDidChangeWindowAlwaysOnTop events in NativeAuxiliaryWindow before createState() persists the cache; whether minimization changes that cache remains unconfirmed. NativeHostMainService exposes the raw native query and toggles. Preserve independent per-window behavior, explicit off states, and existing restoration semantics. https://github.com/microsoft/vscode/issues/348421 defines the persistence expectation; https://github.com/microsoft/vscode/issues/348554 concerns a separate indicator feature.

## Evidence

- **Source-confirmed persistence failure:** In src/vs/platform/windows/electron-main/windowImpl.ts:1587 and :1630, CodeWindow.serializeWindowState() directly saves this._win.isAlwaysOnTop(). With the reported macOS minimized-window return value of false, both serialization branches persist off rather than the user's enabled preference.
- **Shutdown and restoration:** src/vs/platform/windows/electron-main/windowsStateHandler.ts collects window state through toWindowState(), which invokes serializeWindowState({ exact }). src/vs/platform/windows/electron-main/windows.ts:288-289 enables the restored BrowserWindow option only when the saved or overriding alwaysOnTop value is true.
- **Detached-window boundary:** src/vs/workbench/services/auxiliaryWindow/electron-browser/auxiliaryWindowService.ts uses NativeAuxiliaryWindow.handleAlwaysOnTopState() to initialize from the native query and track native change events; createState() persists that cached value. This differs from CodeWindow serialization, so the detached-window report requires confirming event behavior during minimization.
- **Intended behavior:** https://github.com/microsoft/vscode/issues/348421 explicitly requires main and detached windows to preserve independent Always on Top states across quit and restoration, including explicit off states.
- **Related issue is distinct:** https://github.com/microsoft/vscode/issues/348554 is open but requests a visible main-window pin indicator, not preservation after quitting while minimized. It is not a canonical duplicate of this report.
- **Canonical and ownership checks:** Open-issue searches for Always on Top with minimized and restore returned only this issue. Its timeline contained no cross-references; no fixing commit was established from the available local history.
