# Issue #110010 — Add a hotkey to go back one level of breadcrumbs

[https://github.com/microsoft/vscode/issues/110010](https://github.com/microsoft/vscode/issues/110010)

## Summary

A real gap remains: current breadcrumb commands require first focusing the widget, while the closest editor command follows folding ranges rather than directly navigating to the parent breadcrumb symbol. The accepted Backlog request should remain open.

## Change summary

Add a bindable command that moves the editor directly to the parent symbol represented by the preceding breadcrumb.

## Best solution

Add a breadcrumb navigation command in `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts` that resolves and reveals the preceding symbol breadcrumb without transferring focus to the breadcrumbs widget.

## Evidence

- **current breadcrumb commands:** `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts` registers `breadcrumbs.focusPrevious`, but its context requires `breadcrumbsActive`; `breadcrumbs.focusAndSelect` first focuses/selects the last breadcrumb. Neither performs the requested direct editor navigation.
- **closest existing capability:** `editor.gotoParentFold` in `src/vs/editor/contrib/folding/browser/folding.ts` uses folding ranges through `getParentFoldLine` in `foldingModel.ts`. It can stop at the current fold's first line before moving to its parent, and folding hierarchy need not match document-symbol breadcrumbs.
- **discussion:** The reporter clarified at https://github.com/microsoft/vscode/issues/110010#issuecomment-722522644 that the requested behavior is one-step navigation without focusing the breadcrumb UI; the suggested breadcrumb commands did not provide that.
