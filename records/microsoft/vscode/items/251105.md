# Issue #251105 — Select Default Profile (terminal) doesn't work for projects with terminal specified

[https://github.com/microsoft/vscode/issues/251105](https://github.com/microsoft/vscode/issues/251105)

## Summary

The workspace-aware picker enhancement accepted by the maintainers remains missing: current source still writes the selected default exclusively to user settings. The linked implementation PR was closed without merging, and no verified canonical owns the same request.

## Change summary

Make Select Default Profile account for workspace overrides and clearly distinguish workspace-defined terminal profiles.

## Best solution

Deliver the maintainer-agreed scope chooser when workspace and user defaults differ, plus a workspace profiles section in the terminal picker. Preserve explicit user control over whether versioned workspace settings are changed.

- **Behavior:**

  > When a workspace terminal default differs from the user default, Select Default Profile must make the configuration scope explicit instead of silently changing an overridden user setting. The accepted interaction lets the user apply the selection to User, Workspace, both, or neither. Workspace-defined terminal profiles must be identifiable in a workspace section. Acceptance includes correct effective defaults after reload, no changes on cancellation, and no unsolicited edits to versioned workspace settings.
- **Trace:**

  > TerminalProfileQuickpick.showAndGetResult in src/vs/workbench/contrib/terminal/browser/terminalProfileQuickpick.ts writes defaultProfile settings only to ConfigurationTarget.USER, including its early-return path for extension-contributed profiles. _createAndShow uses merged availableProfiles and provides no workspace grouping; TerminalProfileService._detectProfiles reads effective merged configuration in src/vs/workbench/contrib/terminal/browser/terminalProfileService.ts. Preserve normal createInstance behavior, profile safety checks, and configuration precedence; do not automatically modify workspace files merely because a user selects a profile. The planning session should establish executable scope-selection and grouping coverage before reviving the implementation.
