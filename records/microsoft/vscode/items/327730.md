# Issue #327730 — Maximized window edge triggers resize cursor and fails scrollbar hit testing

[https://github.com/microsoft/vscode/issues/327730](https://github.com/microsoft/vscode/issues/327730)

## Summary

Two independent reporters confirm the same symptom on Linux/Wayland/GNOME with a frameless custom title bar: at the maximized window's right edge, the OS-level window resize hit-test region overlaps the vertical scrollbar, so the cursor sometimes shows the resize icon instead of engaging the scrollbar. This looks like a real conflict between Electron's non-client resize-edge hit testing and VS Code's custom-titlebar/frameless window, but I can't trace or confirm the exact ownership boundary from source alone (no GUI/build available in this environment).

## Change summary

On a maximized window with a vertical scrollbar visible, moving the mouse to the rightmost edge intermittently triggers the OS resize cursor instead of engaging the scrollbar, so dragging fails to scroll.

## Best solution

Needs a maintainer with a Linux/Wayland/GNOME setup to confirm whether VS Code's frameless-window configuration (src/vs/platform/windows/electron-main/windows.ts, options.frame = false path) is retaining a resizable edge region while maximized, or whether this is an Electron/Chromium non-client hit-testing bug on Wayland that should be filed upstream against Electron.
