# Issue #334456 — Agent session resume fails when an event is missing agentDisplayName

[https://github.com/microsoft/vscode/issues/334456](https://github.com/microsoft/vscode/issues/334456)

## Summary

Real, traceable bug: the Copilot agent resume path deliberately does not fall back to an empty session for arbitrary SDK errors (to avoid discarding live history), so a `session.resume` failure caused by an older event log missing the now-required `agentDisplayName` field on `subagent.started` events surfaces as a hard failure instead of a graceful recovery. Team-authored and freshly filed, so this simply stays open pending a fix.

## Change summary

Resuming an agent session whose event log has a `subagent.started` event without `agentDisplayName` fails outright instead of tolerating or migrating the missing field.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts, the resume-error recovery (`shouldCreateEmptySessionAfterResumeError` / `RESUMABLE_HISTORY_ABSENT_PATTERNS`, around lines 326-351) is intentionally narrow because falling back there discards history — so this needs a repair path instead of a broader allowlist: either detect this specific 'missing field agentDisplayName' schema error and patch/backfill the field in the on-disk event log before retrying resume, or (more durably) get the bundled `@github/copilot-sdk` to tolerate/default a missing `agentDisplayName` on read, since it currently enforces the field as required strictly on parse.
