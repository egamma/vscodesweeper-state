# Issue #167514 — Implicit activation events - call out implicit activation in the logs

[https://github.com/microsoft/vscode/issues/167514](https://github.com/microsoft/vscode/issues/167514)

## Summary

The diagnostic gap remains on current main: extension-host activation logs report the activation event but not whether it was generated implicitly. This team-authored Backlog request should remain open for the extension-activation area.

## Change summary

Distinguish implicitly generated activation events from explicitly declared events in the Extension Host activation log.

## Best solution

Make extension activation diagnostics identify an event's implicit origin without changing activation behavior, while defining how the log represents an event that is both declared explicitly and inferred from contributions.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/common/implicitActivationEvents.ts`, `src/vs/workbench/services/extensions/common/extensions.ts`, `src/vs/workbench/api/common/extHostExtensionActivator.ts`, `src/vs/workbench/api/common/extHostExtensionService.ts`, `src/vs/workbench/api/test/common/extHostExtensionActivator.test.ts`
- **Validation:** Launch an Extension Development Host with one extension whose language contribution omits `onLanguage` and another that declares the same event explicitly; activate both and verify the Extension Host output distinguishes their origins while preserving the existing event and root-cause details.
- **Behavior:**

  > When an extension is activated by an event inferred from its contributions, the Extension Host log identifies that event as implicit. Explicit activation events remain distinguishable, and the existing startup, event, and root-cause diagnostics remain available. Acceptance should cover an implicit-only event, an explicit event, and an event represented by both mechanisms.
- **Trace:**

  > ImplicitActivationEventsImpl in src/vs/platform/extensionManagement/common/implicitActivationEvents.ts starts with the manifest's explicit `activationEvents` and appends events generated from contributions, returning one flat string array. ExtensionDescriptionRegistry consumes that flattened list, and ExtensionsActivator in src/vs/workbench/api/common/extHostExtensionActivator.ts creates an ExtensionActivationReason containing only the event string. AbstractExtHostExtensionService._doActivateExtension in src/vs/workbench/api/common/extHostExtensionService.ts therefore logs no origin marker. Preserve activation ordering, dependency activation, telemetry payloads, and root-cause logging; the requested scope is diagnostic output only.
- **Open decisions:**
  - When the same activation event is both explicitly declared and generated from a contribution, should the log classify it as explicit, implicit, or both?

## Evidence
