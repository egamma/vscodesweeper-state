# Issue #327343 — Single Panel Detail Panel: File keeps closing

[https://github.com/microsoft/vscode/issues/327343](https://github.com/microsoft/vscode/issues/327343)

## Summary

Keep open: the Backlog request remains independently tracked, and current main still deliberately removes the Files placeholder when a real file opens without restoring it when that file closes. The Changes request is partly covered by an experimental setting, but not by the requested quick in-surface mode switch.

## Change summary

Keep the Files browsing workflow available after closing an opened file, and provide an easy way to switch Changes between multi-file and single-file presentation.

## Best solution

Define a consistent Files-tab fallback that restores the workspace tree after the relevant file editor closes, without unexpectedly reopening tabs the user explicitly dismissed. Make the existing single-file Changes behavior discoverable through an accessible per-surface mode control while preserving multi-file review as an available mode.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/layout/browser/singlePane/singlePaneDockedTabsCoordinator.ts`, `src/vs/sessions/contrib/layout/test/browser/singlePaneStrategies.test.ts`, `src/vs/sessions/contrib/layout/test/browser/desktopSessionLayoutController.test.ts`, `src/vs/sessions/contrib/changes/browser/changesView.ts`, `src/vs/sessions/contrib/changes/browser/changesViewActions.ts`, `src/vs/sessions/contrib/changes/browser/changes.contribution.ts`
- **Validation:** Add focused single-pane layout tests showing the chosen Files fallback after closing the last real file, plus Changes-view tests showing that each selected mode opens the intended single-file or multi-file diff and persists for the chosen scope.
- **Behavior:**

  > Opening a workspace file from Files and then closing it must leave the user with a useful Files browsing surface according to the selected fallback semantics, rather than unexpectedly losing the workflow. Changes must support both the existing all-files multi-diff and a single-file-at-a-time mode through a keyboard-accessible, clearly labeled control. Selecting a changed file must open or reveal content according to the active mode, and existing multi-diff, Alt-modifier, and explicit tab-close behavior must remain coherent.
- **Trace:**

  > SinglePaneDockedTabsCoordinator removes EmptyFileEditorInput when a newly opened workspace file enters the main editor group; its ambient close reconciliation intentionally does not restore defaults while the editor is visible. The current last-editor-close behavior is covered in src/vs/sessions/contrib/layout/test/browser/singlePaneStrategies.test.ts and closes the side pane. ChangesViewPane already branches on `sessions.changes.openSingleFileDiff` in src/vs/sessions/contrib/changes/browser/changesView.ts, while src/vs/sessions/contrib/changes/browser/changesViewActions.ts exposes Expand/Collapse All but no single/multi-file mode control. Keep the work scoped to the Agents Window single-pane presentation; do not change ordinary workbench editor-group semantics or the standard-layout Changes experience. Related direction is recorded in https://github.com/microsoft/vscode/issues/324836 and the narrower later follow-up https://github.com/microsoft/vscode/issues/332302.
- **Open decisions:**
  - After closing the last real file, should Files always return to its tree placeholder, only return when the Files tab was pinned or retained, or preserve an explicit user dismissal?
  - Should single-file versus all-files Changes presentation be a persistent setting, a per-window or per-session mode, or a temporary per-tab choice?
