# Issue #226817 — Avoid inlining large types

[https://github.com/microsoft/vscode/issues/226817](https://github.com/microsoft/vscode/issues/226817)

## Summary

Keep open: the proposed text-search API still exposes folderOptions as a large anonymous type, although the internal search types already have named folder-option interfaces. This is actionable API cleanup, not a runtime search defect.

## Change summary

Expose a named type for individual search-provider folder options so extension authors can reference it in helper signatures.

## Best solution

Provide a reusable named folder-options type in the proposed text-search declarations while preserving the existing structural contract and runtime behavior. Keep the parallel file-search declaration consistent without redesigning query or option semantics.
