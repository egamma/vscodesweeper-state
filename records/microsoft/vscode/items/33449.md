# Issue #33449 — [folding] Automatic function/method folding

[https://github.com/microsoft/vscode/issues/33449](https://github.com/microsoft/vscode/issues/33449)

## Summary

This remains a well-supported Backlog feature request with 58 community upvotes. Current main supports manual folding and automatic import folding, but not automatically folding function bodies, expanding the body containing the cursor, or pinning selected bodies open.

## Change summary

Add an opt-in editing mode that keeps function and method bodies folded except for the body containing the cursor and explicitly pinned bodies.

## Best solution

Design an opt-in editor folding mode backed by language-aware function/body folding ranges: expand the body containing the cursor, re-collapse it after focus moves elsewhere, and preserve explicit user pins without changing existing folding defaults.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** Add folding-controller coverage using function/body ranges to verify initial collapse, cursor-entry expansion, cursor-exit re-collapse, and pinned-range preservation; manually verify the same flow in a TypeScript file while confirming existing Fold All, manual folds, and editor.foldingImportsByDefault remain unchanged.
- **Behavior:**

  > When the opt-in mode is enabled and language-aware function/body ranges are available, function and method bodies start collapsed. Moving the cursor into a body expands that body; leaving it re-collapses it unless the user pinned it open. Explicitly pinned bodies remain expanded while navigating, and disabling the mode preserves today's folding behavior. Existing manual folding commands and automatic import folding continue to behave as before.
- **Trace:**

  > FoldingController in src/vs/editor/contrib/folding/browser/folding.ts computes and restores folding ranges and listens for cursor movement, but revealCursor only unfolds hidden ancestors needed to expose the cursor. Automatic kind-specific collapse is currently limited to FoldingRangeKind.Imports through editor.foldingImportsByDefault in src/vs/editor/common/config/editorOptions.ts. FoldingRangeKind in src/vs/editor/common/languages.ts and src/vscode-dts/vscode.d.ts standardizes only comment, imports, and region, so providers cannot identify method bodies consistently. The related https://github.com/microsoft/vscode/issues/128912 requests a manual body-folding action and may share the range-kind/API work, but it does not settle this issue's automatic lifecycle or pinning contract. Keep the feature opt-in and avoid changing existing Fold All, fold-level, import-folding, or view-state restoration semantics.
- **Open decisions:**
  - Should the public folding contract expose one generic body kind, or distinct function/method and type/class kinds for providers and commands?
  - Does pinning apply only for the current editor session, or persist with the editor's folding view state when the file is reopened?
  - When a user manually expands or collapses a body while automatic folding is enabled, should that action create or remove a pin, or remain separate from pin state?
  - Should opening a file with an existing restored folding state apply automatic body folding immediately, or preserve the restored state until cursor navigation begins?

## Evidence

- **current source gap:** src/vs/editor/contrib/folding/browser/folding.ts registers Fold All, fold-level, comment, region, and import actions; its cursor handler revealCursor only expands an already-hidden range so the cursor can be revealed. It does not re-collapse the previous function or track pinned functions.
- **existing setting:** src/vs/editor/common/config/editorOptions.ts defines editor.foldingImportsByDefault as the only kind-specific automatic-collapse setting; it applies only to import ranges and does not cover function or method bodies.
- **missing range classification:** src/vs/editor/common/languages.ts standardizes only comment, imports, and region FoldingRangeKind values. There is no function/body kind through which language providers can identify the ranges required by this proposal.
- **related request:** https://github.com/microsoft/vscode/issues/128912 is open but was created in 2021, after this re-reviewed 2017 issue, and primarily requests a manual “Fold all bodies” action. It is related infrastructure work, not an older canonical for this issue's cursor-driven automatic behavior and pinning.
- **maintainer and community signal:** A maintainer confirmed in 2022 that the request remains in Backlog, and the issue has 58 community upvotes. The Backlog feature-request rules therefore favor retaining it rather than closing it for age.
- **partial workaround:** The thread mentions the felicio.vscode-fold extension and users running Fold All manually, but neither is evidence that current VS Code provides the requested cursor-sensitive expansion, automatic re-folding, and pin behavior.
