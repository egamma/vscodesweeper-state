# Issue #312152 — The pined VS Code shortcut icon in the Windows 10 Start menu does not display.

[https://github.com/microsoft/vscode/issues/312152](https://github.com/microsoft/vscode/issues/312152)

## Summary

The bug remains actionable on current main: background updates replace the versioned icon resources but deliberately skip refreshing an existing Start Menu shortcut, matching the repeated Windows 10 reports. Route this to the Windows installer area rather than closing it against the older, closed reports.

## Change summary

After each VS Code update on Windows 10, a pinned Start Menu tile loses its icon until the shortcut is manually modified.

## Best solution

Keep the pinned Start Menu icon valid across background updates by ensuring Windows is notified when the versioned Visual Elements icon path changes, without recreating optional shortcuts the user removed.

## Plan brief

- **Likely files:** `build/win32/code.iss`
- **Validation:** On Windows 10, install the user setup, pin VS Code to Start, apply two consecutive background updates, and verify after each update and Explorer restart that the tile icon remains visible without editing or repinning the shortcut; also verify that optional desktop and Quick Launch shortcut choices remain unchanged.
- **Behavior:**

  > A VS Code tile pinned to the Windows 10 Start Menu must retain its icon across every background update. No shortcut-property edit, repinning, reinstall, or icon-cache cleanup should be required. Updating must not recreate optional desktop or Quick Launch shortcuts that the user removed. Acceptance requires the icon to survive two consecutive packaged background updates and an Explorer restart.
- **Trace:**

  > The packaged resources/win32/VisualElementsManifest.xml uses @@VERSIONFOLDER@@ for both tile images, and build/gulpfile.vscode.ts resolves that token to the current versioned resources directory. The Start Menu .lnk is declared in build/win32/code.iss, where ShouldUpdateShortcut skips every existing shortcut during a background update. Reporter evidence shows that changing any shortcut property immediately restores the tile, while the earlier manifest-path fix https://github.com/microsoft/vscode/commit/4c1cc1582a579003a19dce9eed0630626a463336 did not address this cache-refresh step. Keep the work bounded to update-time shortcut/cache behavior: do not remove versioned resources or change normal executable, desktop-shortcut, or Quick Launch semantics.

## Evidence

- **current source path:** resources/win32/VisualElementsManifest.xml points Square150x150Logo and Square70x70Logo into @@VERSIONFOLDER@@, so their resolved paths change with the versioned resources directory.
- **source-confirmed trigger:** build/win32/code.iss registers the Start Menu shortcut through [Icons], but ShouldUpdateShortcut returns false whenever a background update finds the existing .lnk. The update therefore changes the manifest/icon resource path without refreshing the shortcut that prompts Windows 10 to invalidate its cached tile icon.
- **confirmed symptom:** Three reporters confirmed the same update-triggered behavior through VS Code 1.124.2; modifying any shortcut property restores the icon, which is consistent with the unrefreshed-shortcut path.
- **related closed report:** https://github.com/microsoft/vscode/issues/293098 reports the same observable symptom and identifies the shortcut-cache refresh gap after the manifest-path fix. It is closed, so it cannot serve as a duplicate canonical for this re-reviewed issue.
- **incomplete earlier fix:** https://github.com/microsoft/vscode/commit/4c1cc1582a579003a19dce9eed0630626a463336 added the version folder to the manifest icon paths, but later confirmations at https://github.com/microsoft/vscode/issues/293098#issuecomment-4090084796 and https://github.com/microsoft/vscode/issues/293098#issuecomment-4130694239 show that updates still leave the cached tile blank until the shortcut is modified.
