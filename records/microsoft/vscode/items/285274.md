# Issue #285274 — VSCode API Range intersection does not differentiate between inclusive and exclusive

[https://github.com/microsoft/vscode/issues/285274](https://github.com/microsoft/vscode/issues/285274)

## Summary

Touching ranges intentionally produce an empty intersection, as explicitly asserted by existing API tests. Keep this open as a request for optional strict-overlap or selection-aware semantics, rather than a defect in the existing intersection behavior.

## Change summary

Provide a way for extension authors to distinguish strict selection overlap from endpoint contact without separately checking whether the intersection is empty.

## Best solution

Preserve the established Range.intersection contract and have API owners decide whether an additive overlap capability is warranted. Clarify endpoint-contact semantics in the API documentation regardless of whether a new capability is accepted.
