# Issue #307216 — Electron fetch in the utility process doesn't respect HTTP cache headers

[https://github.com/microsoft/vscode/issues/307216](https://github.com/microsoft/vscode/issues/307216)

## Summary

Keep open: Electron's merged session-support change enables caching only when explicitly adopted, and VS Code's current utility-process launcher supplies neither a session nor a partition. The upstream merge therefore does not resolve the reported disk-cache behavior on this code path.

## Change summary

Repeated Copilot model-list requests bypass the disk cache despite applicable HTTP cache headers.

## Best solution

Adopt Electron's session-backed utility-process networking for the extension-host request path, preserving authentication handling and appropriate session isolation. Confirm that the two model-list fetches in the reported 12-minute scenario use the HTTP disk cache before treating this issue as completed.

Its shell/browser/api/electron_api_utility_process.cc diff uses a session network context only when session_ is supplied; the else branch still uses the system network context. Its utility-process documentation explicitly states that the default has no HTTP cache support.
- **Missing adoption on current main:** src/vs/platform/utilityProcess/electron-main/utilityProcess.ts: UtilityProcess.doStart passes serviceName, env, execArgv, allowLoadingUnsignedLibraries, respondToAuthRequestsFromMainProcess, and stdio to utilityProcess.fork, but no session or partition. src/vs/platform/extensions/electron-main/extensionHostStarter.ts: ExtensionHostStarter.start launches the extension host through this wrapper. extensions/copilot/src/platform/networking/vscode-node/electronFetcher.ts: ElectronFetcher.create uses Electron net.fetch.
