# Issue #316966 — Ctrl + scroll to zoom out has a massive jump

[https://github.com/microsoft/vscode/issues/316966](https://github.com/microsoft/vscode/issues/316966)

## Summary

The older, open Mermaid zoom report describes the same Windows Ctrl+mousewheel symptom: zooming in works incrementally, but one downward notch zooms far out. Both surfaces share the implicated wheel handler, so consolidate this report with that issue.

## Change summary

Ctrl+scroll zooming out of a Mermaid diagram jumps disproportionately compared with zooming in.

## Best solution

Track the correction in https://github.com/microsoft/vscode/issues/293468, preserving this report's additional confirmation and the observation that Alt+scroll is more stable. Mermaid wheel zoom should remain gradual in both directions without breaking trackpad pinch zoom.

Its reproduction explicitly describes opening a Mermaid diagram from chat, zooming in with Ctrl+mousewheel, then seeing the diagram zoom far out with one wheel notch. This meets the re-review requirement of an older issue with the same observable symptom.
- **Matching Windows mouse configuration:** The canonical's reporter confirms Windows and a standard mouse wheel at https://github.com/microsoft/vscode/issues/293468#issuecomment-3863379738. This report carries the windows label and independently describes the same directional imbalance.
- **Current source explains the jump:** extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts, PanZoomHandler.handleWheel, treats every Ctrl+wheel event as pinch zoom, multiplies zoomFactor by five, and computes scale * (1 - deltaY * effectiveZoomFactor), clamped to minScale/maxScale. With zoomFactor 0.002, a positive deltaY of 100 produces a zero multiplier and immediately clamps to minimum scale; the opposite delta produces a finite increase.
- **Shared product path:** extensions/mermaid-markdown-features/preview-src/chat/index.ts and index-editor.ts both call initializeMermaidWebview from mermaidWebview.ts. The canonical's editor reproduction and this report's chat-diagram testing exercise the same wheel logic rather than unrelated editor scrolling.
- **Discussion and scope:** https://github.com/microsoft/vscode/issues/316966 records a maintainer observation that Alt+scroll is more stable and asks whether Ctrl+scroll should be disabled. That observation is consistent with the handler applying its extra multiplier only when ctrlKey is true; it should be retained in the consolidated discussion.
