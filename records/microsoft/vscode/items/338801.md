# Issue #338801 — Copilot Chat OTel: set service.instance.id on the resource

[https://github.com/microsoft/vscode/issues/338801](https://github.com/microsoft/vscode/issues/338801)

## Summary

Confirmed gap on main: the Copilot Chat OTel resource in otelServiceImpl.ts sets service.name, service.version and session.id but no service.instance.id, which breaks per-instance aggregation for Prometheus-style backends as described; a small, bounded fix with an obvious value (reuse the existing per-window session.id) and an existing test harness to validate it.

## Change summary

Add a service.instance.id resource attribute (e.g. the existing per-window session.id) to the Copilot Chat OTel resource so Prometheus-style backends can aggregate metrics per VS Code window instead of conflating all windows/users into one series.

## Best solution

Set 'service.instance.id': this.config.sessionId alongside the existing 'session.id' attribute in the resourceFromAttributes(...) call in extensions/copilot/src/platform/otel/node/otelServiceImpl.ts, matching the OTel semantic-conventions recommendation the reporter cites.
