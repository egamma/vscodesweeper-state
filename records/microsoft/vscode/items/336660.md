# Issue #336660 — Agents Window SSH fails with Kerberos/GSSAPI authentication while Remote-SSH works

[https://github.com/microsoft/vscode/issues/336660](https://github.com/microsoft/vscode/issues/336660)

## Summary

Real, source-confirmed gap: the Agents Window's own SSH client (built on the pure-JS `ssh2` npm library) only supports none/publickey/agent/password/keyboard-interactive authentication — GSSAPI/Kerberos is not implemented anywhere in that auth handler, unlike Remote-SSH which can shell out to the system OpenSSH client. This needs a maintainer decision on approach, so it stays open rather than being routed as a quick fix.

## Change summary

The Agents Window's SSH connection fails with GSSAPI/Kerberos-authenticated hosts that Remote-SSH (and the system OpenSSH client) connect to successfully.

## Best solution

A maintainer should pick a direction: extend/replace the ssh2-based auth handler to support GSSAPI, shell out to the system OpenSSH client the way Remote-SSH does (respecting `remote.SSH.path`), or have the Agents Window reuse an already-established Remote-SSH connection instead of opening a second independent one.
