# Issue #336660 — Agents Window SSH fails with Kerberos/GSSAPI authentication while Remote-SSH works

[https://github.com/microsoft/vscode/issues/336660](https://github.com/microsoft/vscode/issues/336660)

## Summary

Keep open: the Agents Window uses ssh2, whose supported authentication methods exclude Kerberos/GSSAPI. Current source still cannot authenticate to a GSSAPI-only host; the related key-authentication and host-certificate reports do not establish a canonical for this distinct limitation.

## Change summary

Allow Agents Window sessions to connect to Kerberos/GSSAPI-authenticated SSH hosts that already work through system OpenSSH and Remote-SSH.

## Best solution

Provide a supported Agents Window connection path for GSSAPI-only hosts, either through an adopted upstream authentication capability or an OpenSSH-backed transport. Preserve this issue as the focused compatibility requirement rather than treating missing SSH keys as its cause.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/336660 describes successful OpenSSH authentication using gssapi-with-mic on macOS arm64, followed by Agents Window New > Remote > SSH failing with 'All configured authentication methods failed'. The reporter explicitly distinguishes this from public-key or ssh-agent authentication.
- **Current authentication path:** src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts:176–181 defines SSHAuthAttempt without GSSAPI; _buildAuthAttempts at lines 1806–1873 constructs agent, publickey, password and keyboard-interactive attempts. _connectSSH installs makeAuthHandler, which filters attempts against server-advertised methods and calls callback(false) when exhausted. A server offering only gssapi-with-mic therefore has no compatible attempt.
- **Upstream capability boundary:** https://github.com/mscdex/ssh2/blob/master/README.md documents authHandler method names as none, password, publickey, agent, keyboard-interactive and hostbased, excluding GSSAPI. SSHRemoteAgentHostMainService._createSSHClient at src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts:1791–1794 constructs this library's Client.
- **Existing capability check:** SSHRemoteAgentHostMainService._doResolveSSHConfig at src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts:1423–1434 invokes system ssh only with -G to resolve configuration; authentication still uses ssh2. Searches of the Agent Host and remote Agents provider sources found no GSSAPI support or remote.SSH.path integration. Configuration resolution is not an OpenSSH authentication fallback.

Its logs show none attempted, then agent, publickey and keyboard-interactive skipped because the server allows only gssapi-with-mic.
