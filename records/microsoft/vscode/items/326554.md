# Issue #326554 — Auto Mode Router overrides an explicitly selected BYOK model with a Copilot model

[https://github.com/microsoft/vscode/issues/326554](https://github.com/microsoft/vscode/issues/326554)

## Summary

Real, still-reproducing bug: a second reporter confirmed on 2026-08-20 (VS Code 1.134.0 / Copilot Chat 0.62.0 / Codex For Copilot 1.6.0) that an explicitly selected BYOK model is still not used for the visible response, even though the misleading 'Routed to <model>' UI message is gone. Current main has a guard that should prevent this (`model.vendor !== 'copilot'` short-circuits straight to `ExtensionContributedChatEndpoint` before the auto-mode path can run), so the persisting reports point to the override happening somewhere else in the pipeline that I couldn't pin down from source alone.

## Change summary

Auto Mode Router silently substitutes a Copilot-hosted model for the main chat response even when the user explicitly picked a third-party/BYOK model.

## Best solution

Have someone with a BYOK provider trace a live repro on latest Insiders: confirm whether `ProductionEndpointProvider.getChatEndpoint` (extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts) is actually receiving the BYOK `model` object for the main request, or whether something upstream (request construction in the default agent / conversation feature, or a capability-based fallback such as vision/context-window checks) is substituting the `AutoChatEndpoint.pseudoModelId` before this guard ever sees it. The existing `model.vendor !== 'copilot'` check at line 135 looks correct in isolation but evidently isn't catching every call path.
