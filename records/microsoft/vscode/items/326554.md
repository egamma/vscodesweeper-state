# Issue #326554 — Auto Mode Router overrides an explicitly selected BYOK model with a Copilot model

[https://github.com/microsoft/vscode/issues/326554](https://github.com/microsoft/vscode/issues/326554)

## Summary

The report claims the Auto Mode Router overrides an explicitly selected BYOK model for the main chat response. However, current code in `endpointProviderImpl.ts` (line 135–136) short-circuits non-copilot vendors directly to `ExtensionContributedChatEndpoint`, bypassing auto-routing entirely. The auto router only activates when the selected model is `copilot/auto`. This suggests either the third-party extension ('Codex For Copilot') registers its models with vendor `copilot` (which would trigger auto-routing), or the model picker is not propagating the BYOK selection correctly. More information is needed to distinguish a VS Code core bug from a third-party extension registration issue.

## Change summary

User reports that selecting a third-party BYOK model in the chat picker still routes the primary chat response through the Copilot Auto Mode Router to a Copilot-hosted model instead.

## Best solution

Ask the reporter to confirm the vendor string their extension registers (via `vscode.lm.selectChatModels()` or the Debug View's model metadata). If the extension registers under vendor `copilot`, that's the root cause — it should use a distinct vendor ID. If it uses a non-copilot vendor, this is a genuine core bug in the model-selection propagation path and should be investigated in `src/vs/workbench/contrib/chat/browser/widget/input/chatModelPicker.ts` and the chat service's request pipeline.
