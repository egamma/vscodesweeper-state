# Issue #326554 — Auto Mode Router overrides an explicitly selected BYOK model with a Copilot model

[https://github.com/microsoft/vscode/issues/326554](https://github.com/microsoft/vscode/issues/326554)

## Summary

Current main still contains the cross-extension-host fallback that explains the report: when the selected provider model is unavailable in Copilot Chat's extension-host-local cache, VS Code silently substitutes the default Copilot model. Multiple remote-workspace confirmations and the successful same-host workaround support keeping this open as a core bug.

## Change summary

Preserve an explicitly selected third-party language model when its provider and Copilot Chat run in different extension hosts.

## Best solution

Make the selected language model usable across extension-host boundaries, or fail explicitly if it cannot be resolved; never silently replace an explicit selection with Auto or another Copilot model.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostLanguageModels.ts`, `src/vs/workbench/api/browser/mainThreadLanguageModels.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHostChatAgents2.ts`, `src/vs/workbench/api/test/common/extHostLanguageModels.test.ts`, `src/vs/workbench/api/test/common/extHostChatAgents2.test.ts`
- **Validation:** Add an extension-host API test where userSelectedModelId names a model registered through another extension host; assert that the participant receives that exact model and that the default Copilot model is never substituted.
- **Behavior:**

  > In a remote workspace, explicitly selecting a language model must send the visible primary chat request to that model even when its provider runs in the local UI extension host and Copilot Chat runs in the workspace extension host. Auto routing must run only when Auto was selected. If cross-host access cannot be established, the request must report an actionable model-unavailable error rather than silently using another model. Acceptance requires a cross-host test proving the participant receives the selected vendor and model identifier without invoking the default-model fallback.
- **Trace:**

  > The workbench carries the explicit identifier as userSelectedModelId into ExtHostChatAgents2.getModelForRequest() in src/vs/workbench/api/common/extHostChatAgents2.ts. That method calls ExtHostLanguageModels.getLanguageModelByIdentifier(); in src/vs/workbench/api/common/extHostLanguageModels.ts, the selected identifier is absent from _localModels when its provider belongs to another extension host, and the method returns undefined after attempting to resolve it. getModelForRequest() then calls getDefaultLanguageModel(), which explains why Copilot Auto receives the primary request. MainThreadLanguageModels already brokers providers through the shared ILanguageModelsService, but the requesting extension host receives identifiers without enough locally cached model data to construct the selected LanguageModelChat. Preserve authorization, cancellation, token counting, and provider ownership semantics, and do not change utility-model routing tracked separately by https://github.com/microsoft/vscode/issues/324890.

## Evidence

- **source trace:** In src/vs/workbench/api/common/extHostLanguageModels.ts, getLanguageModelByIdentifier() explicitly recognizes that a provider may live in another extension host, but returns undefined when the selected identifier remains absent from that host's _localModels cache.
- **silent fallback:** In src/vs/workbench/api/common/extHostChatAgents2.ts, getModelForRequest() receives userSelectedModelId, attempts the cross-host lookup, and then silently calls getDefaultLanguageModel() when it returns undefined. This changes the reporter's explicit BYOK selection into the default Copilot/Auto model before the participant handles the request.
- **confirmed remote trigger:** https://github.com/GaussianGuaicai/Codex-For-Copilot/issues/25 contains logs showing the visible panel/editAgent request used gpt-5.3-codex, plus independent Remote-SSH confirmation that forcing the provider into the workspace extension host restores the selected model.
- **workaround evidence:** https://github.com/GaussianGuaicai/Codex-For-Copilot/pull/102 changes the provider's extensionKind preference to the workspace host specifically to avoid this cross-host routing defect; its description states that the workaround should become unnecessary after microsoft/vscode#326554 is fixed.
- **related request:** https://github.com/microsoft/vscode/issues/324890 concerned configurable utility-model routing and is closed; it does not own this issue's observable symptom of replacing the visible primary-response model.
