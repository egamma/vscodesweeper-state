# Issue #333729 — Opening chat in a diferent own window fails

[https://github.com/microsoft/vscode/issues/333729](https://github.com/microsoft/vscode/issues/333729)

## Summary

Verified duplicate of the open, earlier-filed https://github.com/microsoft/vscode/issues/333721, which has an identical stack trace (createDormantHost -> activate -> register in chatPetWidgetService.ts) and is already assigned to a maintainer; a commenter on this issue independently flagged the same match.

## Change summary

Opening chat in a new/auxiliary editor window throws "Not allowed to create elements in child window JavaScript context" from ChatPetWidgetCoordinator.createDormantHost.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/333721 (filed ~76 minutes earlier, same exact minified stack trace, already assigned). The underlying fix belongs in src/vs/workbench/contrib/chat/browser/widget/chatPetWidgetService.ts:createDormantHost — it calls dom.$('div'), which resolves the ambient `document` to whichever window's JS realm the coordinator singleton executes in; when that's an auxiliary window, this hits the auxiliaryWindowService createElement guard despite the comment's claim that it always runs in the main window realm. Needs to explicitly target mainWindow.document (or an equivalent helper) rather than relying on module-scope `document`.
