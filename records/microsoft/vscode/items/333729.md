# Issue #333729 — Opening chat in a diferent own window fails

[https://github.com/microsoft/vscode/issues/333729](https://github.com/microsoft/vscode/issues/333729)

## Summary

Reproduces from source on main: the chat pet widget's dormant host is created via the ambient `document` (dom.$), which — when this code runs inside the auxiliary (popped-out chat) window's JS realm — is the aux window's own document, whose `createElement` is intentionally patched to throw. The in-code comment claims it uses the main-window realm, but it doesn't.

## Change summary

Opening/moving chat into its own (auxiliary) window throws 'Not allowed to create elements in child window JavaScript context' and chat fails to activate there.

## Best solution

In `ChatPetWidgetCoordinator.createDormantHost()` (src/vs/workbench/contrib/chat/browser/widget/chatPetWidgetService.ts), build the parked host element explicitly against `mainWindow.document` instead of the ambient `dom.$('div')`, matching the pattern used elsewhere (e.g. chatInputNoticeWidget) for auxiliary-window safety.
