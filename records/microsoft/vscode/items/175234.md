# Issue #175234 — Support hover popup webview

[https://github.com/microsoft/vscode/issues/175234](https://github.com/microsoft/vscode/issues/175234)

## Summary

Keep open: extensions still lack an API for interactive webviews in editor hover popups. The request has 95 upvotes and was accepted into Backlog; Markdown hovers and proposed editor insets do not cover its floating, transient interaction model.

## Change summary

Allow extensions to provide interactive HTML widgets in editor hover popups, such as scalar and vector pickers.

## Best solution

Design an extension-facing hover webview contract with explicit focus, dismissal, reuse, and resource-lifetime semantics. Keep specialized picker implementations in extensions while core supplies the missing hosting capability.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vscode-dts/vscode.proposed.editorInsets.d.ts`, `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadCodeInsets.ts`, `src/vs/editor/contrib/hover/browser/markdownHoverParticipant.ts`
- **Validation:** The plan should end with an extension-host integration scenario that opens an interactive scalar picker over a source token, changes the source through webview messaging, moves to another token, and dismisses the hover. Verify keyboard entry and exit, coexistence with ordinary hover content, and bounded live webview resources across repeated hover transitions.
- **Behavior:**

  > An extension can display an interactive HTML widget in a popup anchored to source text without opening a separate editor or inserting an inline view zone. The widget supports interactions such as changing scalar or vector values and communicating edits back to the extension. Acceptance should cover movement between source locations, dismissal, keyboard interaction, ordinary hover compatibility, and bounded resource use. The reporter proposes reusing at most one webview per extension, but that lifecycle contract has not been accepted by a maintainer.
- **Trace:**

  > The stable Hover API in src/vscode-dts/vscode.d.ts accepts MarkdownString and MarkedString content; HoverAdapter in src/vs/workbench/api/common/extHostLanguageFeatures.ts converts those provider results into editor hovers. Existing Markdown HTML support is restricted rendering, not a scriptable webview host. The proposed createWebviewTextEditorInset API in src/vscode-dts/vscode.proposed.editorInsets.d.ts reaches EditorWebviewZone in src/vs/workbench/api/browser/mainThreadCodeInsets.ts, which uses editor view zones rather than hover overlays. These declarations and implementations establish the missing hosting surface, but not its public contract or complete implementation boundary. Preserve existing Markdown hover, panel, and inline-inset behavior; do not treat changing those surfaces as satisfying the request. Related work is https://github.com/microsoft/vscode/issues/3220 and https://github.com/microsoft/vscode/issues/85682, neither of which establishes the transient hover contract requested here.
- **Open decisions:**
  - Does an interactive webview augment the existing merged hover content or occupy an exclusive popup at the hovered location?
  - What focus and dismissal behavior lets users enter and operate the widget by keyboard while preserving normal editor hover behavior?
  - Is webview state retained across hover locations and dismissal, and is the resource limit per extension or global to the editor hover?
