# Issue #290861 — The agent status bar is way too noisy

[https://github.com/microsoft/vscode/issues/290861](https://github.com/microsoft/vscode/issues/290861)

## Summary

Compact mode reduces the title-bar footprint, but current main still presents unread and in-progress sessions as separate icon/count controls. Keep this team-authored request open: the requested consolidation remains missing, and no verified older canonical owns the same feedback.

## Change summary

Consolidate unread and in-progress agent-session indicators to reduce title-bar noise.

## Best solution

Agree on a calmer consolidated session-status affordance in the title-bar widget, retaining access to unread and running sessions. Decide its count and activation semantics before implementation; hiding the entire indicator is not equivalent to simplifying it.

- **Behavior:**

  > The title-bar agent indicator feels crowded when unread and running sessions each add their own icon/count control. The desired outcome is a calmer consolidated presentation that still lets users discover both kinds of session. Acceptance should exercise simultaneous unread and running sessions, the agreed count and activation behavior, and keyboard access. Hiding the whole indicator does not satisfy the request.
- **Trace:**

  > AgentTitleBarStatusWidget._renderStatusBadge in src/vs/workbench/contrib/chat/browser/agentSessions/experiments/agentTitleBarStatusWidget.ts independently builds unreadSection and activeSection and appends both in compact and badge modes. Each section invokes _openSessionsWithFilter with a distinct category; this is observable behavior that consolidation must account for. The corresponding CSS lives in experiments/media/agenttitlebarstatuswidget.css. chat.agentsControl.enabled is registered in chat.shared.contribution.ts and already defaults to compact, but compact changes placement rather than combining these controls. https://github.com/microsoft/vscode/pull/300560 provides relevant design history, while https://github.com/microsoft/vscode/issues/304156 tracks different visual polish. The uncertainty is the consolidated affordance's public count and interaction contract, not whether the current controls are separate. Keep unrelated session-state computation, needs-input behavior, and chat toggling outside the consolidation scope.
- **Open decisions:**
  - Should the consolidated affordance display one deduplicated total, a prioritized status, or retain distinct counts inside a single control?
  - Should activating the consolidated control show the union of unread and running sessions, or offer a choice between the existing category filters?
