# Issue #329107 — Expose provider-owned draft session configuration for serialization

[https://github.com/microsoft/vscode/issues/329107](https://github.com/microsoft/vscode/issues/329107)

## Summary

Team-authored API design proposal for provider-owned session execution configuration, tied to migrating automations to provider-served sessions — this is a real, open architectural gap on main (no `ISessionExecutionConfiguration` type exists anywhere in the tree), so it should stay open and be routed to the right area owners.

## Change summary

Add a provider-neutral API (`ISessionExecutionConfiguration`, exposed via `ISessionsProvider`/`ISessionsManagementService`) so consumers like the automation dialog can read and reapply a draft session's mode/permission configuration without coupling to picker UI internals.

## Best solution

Design and land the proposed `ISessionExecutionConfiguration` capability on `ISessionsProvider`, with Agent Host and Copilot providers implementing it, as part of the discussed migration of automations to be provider-served rather than automation-service-managed; likely touches `src/vs/sessions/contrib/providers/*` and the automation dialog consumer.
