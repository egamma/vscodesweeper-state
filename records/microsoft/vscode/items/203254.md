# Issue #203254 — Provide API for skipped ranges in test coverage

[https://github.com/microsoft/vscode/issues/203254](https://github.com/microsoft/vscode/issues/203254)

## Summary

The coverage API still cannot explicitly represent skipped or excluded ranges; omitting them does not preserve their exclusion status. Keep this accepted, team-authored API request open for contract design.

## Change summary

Allow coverage providers to report intentionally skipped or excluded source ranges distinctly from covered, uncovered, and unreported code.

## Best solution

Define a coverage API contract for explicit exclusions, including their effect on coverage totals and presentation. Keep the initial scope focused on test coverage rather than implicitly turning the coverage API into a general static-analysis reporting API.

- **Behavior:**

  > Coverage providers such as gcovr integrations need to identify intentionally excluded source ranges rather than report them as uncovered or silently omit their status. The API should preserve that distinction through coverage reporting and expose the agreed presentation to users. Acceptance must cover excluded, covered, uncovered, and unreported ranges together, with backwards-compatible behavior for providers that do not report exclusions. The treatment of exclusions in totals and editor presentation needs an explicit product contract.
- **Trace:**

  > The current public contract in src/vscode-dts/vscode.d.ts exposes execution counts or booleans on StatementCoverage, BranchCoverage, and DeclarationCoverage, with no explicit exclusion state. TestCoverage.fromDetails in src/vs/workbench/api/common/extHostTypeConverters.ts maps those values into CoverageDetails in src/vs/workbench/contrib/testing/common/testTypes.ts and rejects negative execution counts. Omitting details cannot preserve the reason a range was not reported. The relevant downstream surfaces include the coverage model in common/testCoverage.ts and editor presentation in browser/codeCoverageDecorations.ts; the trace establishes the missing contract, not a complete implementation design. Preserve existing coverage-provider semantics and distinguish this request from skipped test-result states. The original context is https://github.com/microsoft/vscode/issues/123713#issuecomment-1902726181; its broader static-analysis examples do not settle the scope of the new coverage contract.
- **Open decisions:**
  - Should explicit exclusion apply to statement/line ranges only, or also to branches and declarations?
  - How should excluded ranges affect reported totals, and what visible distinction should users see between excluded and unreported code?
