# Issue #135591 — Support codicons in file decorations

[https://github.com/microsoft/vscode/issues/135591](https://github.com/microsoft/vscode/issues/135591)

## Summary

Codicon file decorations exist behind a proposed-API gate, but the stable API still accepts only string badges and the multi-provider composition limitation remains. This api-proposal tracking issue must stay open for the API owners to resolve and finalize.

## Change summary

Allow extensions to supply ThemeIcon badges through the stable file decoration API instead of relying on Unicode glyphs.

## Best solution

Resolve the user-visible composition and precedence rules for icon and text decorations, then let the API owners finalize ThemeIcon support in FileDecoration. Retain this issue as the proposal's tracking record until that decision is complete.

## Evidence

- **Protected API tracking issue:** https://github.com/microsoft/vscode/issues/135591 remains open with api-proposal. Proposed implementation does not complete this tracking issue; finalization belongs to the API owners.
- **Existing capability is proposed, not stable:** src/vscode-dts/vscode.proposed.codiconDecoration.d.ts explicitly references this issue and declares FileDecoration2.badge as string | ThemeIcon. In contrast, src/vscode-dts/vscode.d.ts:8251–8281 declares FileDecoration.badge and its constructor badge argument as string only. src/vs/workbench/api/common/extHostDecorations.ts:104–105 calls checkProposedApiEnabled(extensionId, 'codiconDecoration') for non-string badges.
- **Remaining composition limitation:** DecorationRule._appendForMany in src/vs/workbench/services/decorations/browser/decorationsService.ts stops at the first ThemeIcon and renders that icon instead of the collected string badges; multiple string badges are otherwise joined with commas. This matches the maintainer's October 2024 statement that a codicon still limits the result to one decoration.
- **Related implementations are not finalization:** https://github.com/microsoft/vscode/pull/166358 was merged on 2022-11-15 and describes itself as 'Part of' this issue. https://github.com/microsoft/vscode/pull/181292 references resolving this issue but is closed without merging. Neither establishes completion of the stable API.
- **Canonical search:** An open-issue search for codicon decorations found no verified canonical owning this proposal. https://github.com/microsoft/vscode/issues/182098 concerns independent badge/text colors and is newer; https://github.com/microsoft/vscode/issues/116136 concerns replacing internal hardcoded Unicode icons, not exposing ThemeIcon through the stable file decoration API. Neither meets the same-scope duplicate bar for this re-reviewed item.
