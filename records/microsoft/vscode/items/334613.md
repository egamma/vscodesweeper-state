# Issue #334613 — Forking Copilot (Agent Host) chat creates orphaned sessions, broken in VSCode

[https://github.com/microsoft/vscode/issues/334613](https://github.com/microsoft/vscode/issues/334613)

## Summary

Detailed, well-evidenced report (including a screenshot of `copilot --resume` proving the Agent Host CLI does create the forked session on disk) that forking a chat backed by the Agent Host / Copilot CLI provider loses the new session in the VS Code UI — title reverts, back-navigation and the session list only ever show the original chat. The forking machinery spans several async paths (`agentHostForkActions.ts`, `baseAgentHostSessionsProvider.ts`, `sessionsManagementService.ts`, `chatForkActions.ts`) and I could not conclusively trace the exact defect by reading source alone, so this needs an owner to actually run the repro.

## Change summary

Forking a Copilot Agent Host chat (via `/fork` or the Fork button) creates a real session on disk but the forked chat never becomes navigable in the VS Code UI — the title reverts and only the original session remains reachable.
