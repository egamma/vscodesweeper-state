# Issue #334613 — Forking Copilot (Agent Host) chat creates orphaned sessions, broken in VSCode

[https://github.com/microsoft/vscode/issues/334613](https://github.com/microsoft/vscode/issues/334613)

## Summary

Fresh, detailed, and well-evidenced report (exact steps, expected/actual, and screenshots proving the CLI sees a forked session that VS Code's UI never surfaces) of a real defect in the Copilot Agent Host chat-fork flow; no fix commit found on main and the issue is only hours old, so it needs maintainer/engineering triage rather than a close.

## Change summary

Forking a Copilot (Agent Host) chat via /fork or the Fork button creates a new session on disk, but VS Code's UI loses the forked title, shows only the original session on 'Back', and opens the original (not the fork) from the title/overview — effectively orphaning the forked session in the UI.

## Best solution

Trace how forked Copilot sessions are registered/resolved in the Agents Window session list and chat title flow (src/vs/platform/agentHost/node/agentService.ts forked-title refinement around agentService.ts:3171-3227, src/vs/platform/agentHost/node/copilot/copilotAgent.ts createChat/_forkSdkChat path, and the sessions list/back-navigation wiring in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts and src/vs/sessions/services/sessions/browser/sessionsManagementService.ts) to find why the new session/chat resource isn't kept distinct from the source after the SDK fork completes.
