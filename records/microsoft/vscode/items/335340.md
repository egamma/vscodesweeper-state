# Issue #335340 — disappearing chat selectors

[https://github.com/microsoft/vscode/issues/335340](https://github.com/microsoft/vscode/issues/335340)

## Summary

Keep open: the team-authored report includes a repeatable remote-workspace trigger and recording, while current source still has an asynchronous workspace-to-composer transition without an integrated selector-lifecycle regression test.

## Change summary

Starting a new chat from the plus button beside a remote workspace can make the chat selectors disappear.

## Best solution

Keep the workspace and chat configuration selectors visible and usable while the newly opened composer adopts the selected remote workspace, without changing the explicit Show/Hide Session Options behavior.

Acceptance requires a regression test covering the deferred remote-workspace transition and preserving the existing collapse semantics.
- **Trace:**

  > NewSessionForWorkspaceAction in src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts awaits ISessionsService.openNewSession and then calls SessionView.selectWorkspace with the source session's folder and provider. NewChatWidget in src/vs/sessions/contrib/chat/browser/newChatWidget.ts independently derives selector placement and visibility from quick-chat identity, active-session loading, provider configuration resolution, and the persisted session-options expansion state. Existing tests cover deferred workspace selection and selector rendering separately, not their combined remote-workspace transition. Diagnosis should identify which observable transition removes or strands the selector DOM; preserve intentional explicit collapse behavior and ordinary quick-chat presentation.
