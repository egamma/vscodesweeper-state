# Issue #339763 — Terminal: Run Recent Command…: Pin command fails quietly

[https://github.com/microsoft/vscode/issues/339763](https://github.com/microsoft/vscode/issues/339763)

## Summary

Traced in source: the picker's generic onDidTriggerItemButton handler in terminalRunRecentQuickPick.ts unconditionally re-invokes/recreates the whole quick pick for every item-button click, with no exemption for the pin/pinned buttons that showWithPinnedItems (quickPickPin.ts) adds later — these two mechanisms race, which is consistent with a pin toggle that silently has no visible effect.

## Change summary

Clicking the pin icon in Terminal: Run Recent Command… doesn't appear to pin the command — no visual change and no error.

## Best solution

Exempt the pin/pinned button clicks from the catch-all recursive refresh in terminalRunRecentQuickPick.ts's onDidTriggerItemButton handler (or otherwise let showWithPinnedItems's own in-place update own the pin flow exclusively) so the two update paths stop competing.

## Evidence

- **conflicting handler:** src/vs/workbench/contrib/terminalContrib/history/browser/terminalRunRecentQuickPick.ts registers quickPick.onDidTriggerItemButton (around the removeFromCommandHistoryButton/commandOutputButton branches) which unconditionally falls through to `await instantiationService.invokeFunction(showRunRecentQuickPick, ...)` for ANY item-button trigger, including the pin button, even though it only has explicit branches for remove/output.
- **pin ownership:** src/vs/platform/quickinput/browser/quickPickPin.ts's showWithPinnedItems registers its own onDidTriggerItemButton (added later, at the end of showRunRecentQuickPick) which actually performs the pin toggle: filters on pinButtonClass/pinnedButtonClass, writes to storage via updatePinnedItems, and updates quickPick.items in place. Since the generic handler (registered first) fires for the same event, it unconditionally rebuilds the whole picker right alongside the dedicated pin update, which is wasted and a likely source of the silent no-op the reporter sees.
- **wiring confirmed:** src/vs/workbench/contrib/terminalContrib/history/browser/terminal.history.contribution.ts wires 'Terminal: Run Recent Command…' (ctrl+alt+r) to showRunRecentQuickPick, matching the reporter's exact repro steps.
- **no test harness:** No existing unit tests cover terminalRunRecentQuickPick.ts or quickPickPin.ts pin behavior, so there's no runnable check to pin the fix against yet.
