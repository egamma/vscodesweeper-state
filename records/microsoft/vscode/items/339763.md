# Issue #339763 — Terminal: Run Recent Command…: Pin command fails quietly

[https://github.com/microsoft/vscode/issues/339763](https://github.com/microsoft/vscode/issues/339763)

## Summary

The pinning failure is confirmed in current source: recent commands are matched by timestamp ID, but saved pins discard that ID, so reopening the picker cannot recognize them. Keep this open for a bounded persistence fix.

## Change summary

Pinning a recently executed terminal command does not produce a recognizable pinned entry when the picker is reopened.

## Best solution

Make persisted pins retain a consistent identity across saving and reopening the recent-command picker, without serializing terminal runtime objects or changing command execution and output actions.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/vscode/issues/339763 describes running a command, clicking its Pin command button in Terminal: Run Recent Command…, and reopening the picker without any visible pinned state.
- **Current-source identity mismatch:** src/vs/workbench/contrib/terminalContrib/history/browser/terminalRunRecentQuickPick.ts assigns current-session command items id: entry.timestamp.toString(). In src/vs/platform/quickinput/browser/quickPickPin.ts, getItemIdentifier prefers item.id, but formatPinnedItemForStorage saves only label, description and detail. After reopening, itemsMatch compares the live timestamp ID with the stored label/description/detail fallback, so _formatPinnedItems cannot reconstruct the pinned command.
- **Pin button appearance:** quickPickPin.ts intentionally retains the original command row with its Pin command button and creates a separate pinned copy with a Pinned command button. The original button remaining unchanged alone is not a defect; the failure to reconstruct the pinned copy after reopening is.
- **Historical change is not a fix for this report:** https://github.com/microsoft/vscode/pull/250875 merged on 2025-06-06 and closed https://github.com/microsoft/vscode/issues/250874, which reported a console error when pinning. Its diff introduced formatPinnedItemForStorage to avoid serializing full items, but omitted id. Current source retains that omission; the closed earlier report is neither an open duplicate canonical nor proof this newer failure is resolved.
