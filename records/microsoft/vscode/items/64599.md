# Issue #64599 — Using OS user name / git user name inside code snippets

[https://github.com/microsoft/vscode/issues/64599](https://github.com/microsoft/vscode/issues/64599)

## Summary

Keep open: shared snippets still lack built-in user identity expansion, and two linked implementation proposals remain open. Maintainer feedback identifies a genuine distinction between process-environment values and workspace-aware Git identity that needs resolving before landing a solution.

## Change summary

Allow shared snippets to insert each user's OS or Git name and optionally their email without hardcoding personal values.

## Best solution

Review the existing implementation proposals against the requested author-name and email behavior, settling identity-source semantics and whether extension-contributed variables are needed for workspace-aware Git identity. Land the agreed solution through the existing PR lane rather than starting a competing implementation.

## Evidence

- **Existing-capability check:** src/vs/editor/contrib/snippet/browser/snippetVariables.ts defines KnownSnippetVariableNames without MY_NAME, USER_NAME, TM_FULLNAME, TM_EMAIL, or a Git identity variable. The resolver compositions in src/vs/editor/contrib/snippet/browser/snippetSession.ts provide selection, model, clipboard, comment, time, workspace, and random values, but no user identity resolver. The snippet command/schema registrations in src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts do not supply the missing identity capability.
- **Unknown variables are not identity lookup:** src/vs/workbench/contrib/snippets/browser/snippetsFile.ts converts unknown variables without defaults into editable placeholders. This does not automatically personalize the reporter's shared TODO snippet, and a hardcoded default does not satisfy the per-user requirement.
- **Open implementation candidates:** https://github.com/microsoft/vscode/pull/300898 was verified OPEN and explicitly says Fixes #64599; it proposes USER_NAME and USER_HOME from process environment variables. https://github.com/microsoft/vscode/pull/315156 was also verified OPEN and proposes TM_FULLNAME and TM_EMAIL using environment-variable fallbacks. Neither proposal is a landed fix.
- **Maintainer direction:** In the supplied discussion at https://github.com/microsoft/vscode/issues/64599, the MEMBER comment dated 2026-05-19 questions whether the VS Code process environment represents the loaded workspace and suggests Git/auth identity through an extension-contributed snippet-variable API. This is an unresolved product boundary, not an established rejection of the request.
- **Canonical ownership:** https://github.com/microsoft/vscode/issues/83688 was verified CLOSED as a duplicate of this issue, with the explicit consolidation comment at https://github.com/microsoft/vscode/issues/83688#issuecomment-548259856. The older open https://github.com/microsoft/vscode/issues/63534 requests externally defined global/project snippet variables for customization, not the same automatic author-identity behavior; it is related infrastructure rather than a verified canonical for this re-reviewed report. Searches for open snippet username/author issues found no verified older canonical owning this exact request.
