# Issue #227434 — VS Code should not recommend deprecated workspace recommendations

[https://github.com/microsoft/vscode/issues/227434](https://github.com/microsoft/vscode/issues/227434)

## Summary

A real gap remains on current main: recommendation views exclude deprecated gallery extensions, but workspace recommendation notifications use a separate installability path that does not. The request was accepted by a maintainer and placed in Backlog, so it should remain open.

## Change summary

Prevent deprecated extensions listed in a workspace's extensions.json from being presented as installable recommendations.

## Best solution

Make workspace recommendation notifications and installation actions apply the same deprecated-extension filtering as the Extensions view, without automatically rewriting the repository-owned extensions.json file.

## Evidence

- **current source gap:** src/vs/workbench/contrib/extensions/browser/extensionsViews.ts:getInstallableRecommendations excludes gallery entries with extension.deprecationInfo, while src/vs/workbench/contrib/extensions/browser/extensionRecommendationNotificationService.ts:getInstallableExtensions accepts any gallery extension for which canInstall returns true and does not check deprecationInfo.
- **notification path:** src/vs/workbench/contrib/extensions/browser/extensionRecommendationsService.ts:promptWorkspaceRecommendations passes workspace recommendation IDs to ExtensionRecommendationNotificationService, so a deprecated entry can still produce the install prompt even though the @recommended view filters it out.
- **maintainer direction:** The maintainer comment at https://github.com/microsoft/vscode/issues/227434 states that deprecated extensions should not be recommended even when present in an outdated recommendations file.
