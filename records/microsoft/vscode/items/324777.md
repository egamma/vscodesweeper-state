# Issue #324777 — Copilot chat feedback

[https://github.com/microsoft/vscode/issues/324777](https://github.com/microsoft/vscode/issues/324777)

## Summary

The defect remains on current main: Send to New Chat preserves only the prompt text, so explicitly attached file selections are absent when the request is submitted in the new session. This is a bounded core Chat bug that should be routed to the chat area.

## Change summary

Preserve explicitly attached file selections when sending the current prompt to a new chat.

## Best solution

Send the prompt and all explicit draft attachments to the new chat while leaving implicit session context and conversation history behind. Cover file selections alongside the existing image and special-variable attachment cases.

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts, SendToNewChatAction.run captures only `widget.getInput()`, clears the session, and calls `widget.acceptInput(inputBeforeClear, ...)`; it never captures or restores `widget.attachmentModel.attachments`.
- **submission path:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts builds `requestInputs.attachedContext` from the current input's attachment model after the new session has been created, so attachments owned by the old draft are not available to the request.
- **related reports:** https://github.com/microsoft/vscode/issues/281808 reports the same observable loss for pasted images, and https://github.com/microsoft/vscode/issues/292064 reports it for `#changes`. Both are older and open, but each is scoped to a different attachment subtype and therefore is too narrow to own this re-reviewed report about multiple file selections.
- **history:** Commit 93e385b750068cbc7772a1ab256e4f02c69a5ed7 previously fixed Send to New Chat by preserving the text value, but its diff did not preserve attached context and does not reference this issue.
