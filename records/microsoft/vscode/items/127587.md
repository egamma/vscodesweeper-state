# Issue #127587 — [remote] Prefer to open a file in an existing window even when that window is connected to a remote with that file opened

[https://github.com/microsoft/vscode/issues/127587](https://github.com/microsoft/vscode/issues/127587)

## Summary

This remains a valid, community-supported feature request: external local-file opens still need a reverse mapping to select an existing Dev Container or WSL window. The thread explicitly clarified that this is not the same-folder/two-window problem, and no verified older canonical owns the same observable behavior.

## Change summary

When an externally opened local file is mounted in an existing remote workspace, prefer opening its corresponding remote URI in that window instead of creating a local window.

## Best solution

Define a remote-resolver contract for mapping an incoming local URI to an equivalent remote URI and use it during window selection, with deterministic handling when zero, one, or multiple open remote windows claim the file.

## Plan brief

- **Likely files:** `src/vs/platform/remote/common/remoteAuthorityResolver.ts`, `src/vs/code/electron-main/app.ts`, `src/vs/code/electron-main/windows.ts`
- **Validation:** Add focused window-routing tests covering an externally supplied local file that maps to exactly one open remote workspace, no matching remote workspace, and multiple matching remote workspaces; verify only the unique match is reused.
- **Behavior:**

  > Opening a local file from Explorer, the OS file association, the CLI, or another application should reuse an existing remote VS Code window when that local file has a known equivalent URI inside the window's Dev Container or WSL workspace. If no equivalence is known, current local-window behavior remains unchanged. The chosen behavior must be deterministic when more than one remote window could map the same local path.
- **Trace:**

  > The issue thread establishes that incoming external opens carry a local URI, while the already-open remote window knows the file by a different remote URI. A maintainer notes at https://github.com/microsoft/vscode/issues/127587#issuecomment-895991053 that remote resolvers can provide a canonical URI in the opposite direction but cannot currently answer this local-to-remote lookup. The likely boundary spans the remote authority resolver contract in src/vs/platform/remote/common/remoteAuthorityResolver.ts and external-open/window selection in src/vs/code/electron-main/app.ts and src/vs/code/electron-main/windows.ts. Preserve the rule that arbitrary local files cannot be opened directly inside a remote-authority window; only resolver-confirmed equivalent remote resources should affect routing.
- **Open decisions:**
  - What public resolver contract should establish that a local URI and a remote URI identify the same file?
  - When multiple open remote windows claim the same local file, should VS Code choose one deterministically, prompt the user, or retain the current local-window behavior?
