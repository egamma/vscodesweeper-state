# Issue #332129 — New chats remain stuck in Agent Host after switching back to Local Chat due to persisted chat.userSelectedSessionType

[https://github.com/microsoft/vscode/issues/332129](https://github.com/microsoft/vscode/issues/332129)

## Summary

Traced in source: the remembered session type (`chat.userSelectedSessionType`, stored via `chatSessionTypePreference.ts`) is treated as usable by `getUsableRememberedSessionType`/`isNewChatSessionTypeUsable` in `constants.ts` as long as Agent Host is enabled at all — it does not check whether the user's harness-preference settings (`chat.editor.preferCopilotHarness`, `chat.defaultToCopilotHarness`) still favor Agent Host. So toggling those settings back to Local has no effect on new chats until the user explicitly picks Local in the session-target picker (which calls `recordUserSelectedSessionType`) or the internal storage entry is removed by hand.

## Change summary

Once Agent Host / Copilot CLI is selected, VS Code keeps routing new chats to it even after the user changes chat settings back to Local and restarts, because the persisted `chat.userSelectedSessionType` is not invalidated by the settings change.

## Best solution

Have a maintainer decide the intended semantics: either `getUsableRememberedSessionType` (src/vs/workbench/contrib/chat/common/constants.ts) should also require the remembered type to still match the currently preferred/default harness, or there should be a supported UI/setting affordance to reset the remembered session type — right now the only way out is editing `state.vscdb` by hand, which matches the reporter's workaround exactly.

## Evidence

- **remembered-type check:** src/vs/workbench/contrib/chat/common/constants.ts:435-445 `getUsableRememberedSessionType` calls `isNewChatSessionTypeUsable`, which for an Agent Host target only checks `agentHostEnabled` (line 356-357), ignoring `chat.editor.preferCopilotHarness`/`chat.defaultToCopilotHarness`.
- **resolution order:** src/vs/workbench/contrib/chat/common/constants.ts:389-392 and 421-424 return the remembered type before falling back to `getComputedDefaultSessionType`, so a stale remembered Agent Host value always wins while Agent Host remains enabled.
- **storage key:** src/vs/workbench/contrib/chat/common/chatSessionTypePreference.ts:8-20 confirms the value is a profile-scoped persisted storage key (`chat.userSelectedSessionType`), matching the reporter's `state.vscdb` finding.
- **no clearing path:** `recordUserSelectedSessionType` (constants.ts:460-473) only clears the stored value when the newly-selected type equals the freshly computed default — a settings-only change never triggers this, since it requires an explicit new-chat selection.
