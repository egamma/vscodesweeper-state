# Issue #332129 — New chats remain stuck in Agent Host after switching back to Local Chat due to persisted chat.userSelectedSessionType

[https://github.com/microsoft/vscode/issues/332129](https://github.com/microsoft/vscode/issues/332129)

## Summary

Real bug: the persisted `chat.userSelectedSessionType` storage value overrides the user's explicit Local/Extension Host configuration on restart, confirmed by tracing `chatSessionTypePreference.ts` where `getRememberedSessionType` unconditionally wins over the harness default. The reporter has already opened a fixing PR (#333155), so the right next step is reviewing/landing that PR rather than closing or auto-fixing.

## Change summary

Once `chat.userSelectedSessionType` is persisted to Agent Host, changing the chat harness settings back to Local and restarting VS Code has no effect — new chats keep routing to Agent Host because the stored preference is checked before the default harness selection.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/333155, which the reporter says fixes this and the related https://github.com/microsoft/vscode/issues/333154 by adjusting the session-type resolution in `src/vs/workbench/contrib/chat/common/chatSessionTypePreference.ts` so an explicit settings change can override the persisted storage value.
