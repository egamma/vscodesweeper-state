# Issue #332129 — New chats remain stuck in Agent Host after switching back to Local Chat due to persisted chat.userSelectedSessionType

[https://github.com/microsoft/vscode/issues/332129](https://github.com/microsoft/vscode/issues/332129)

## Summary

Traced the logic in constants.ts: once `chat.userSelectedSessionType` remembers an Agent Host target, `getDefaultNewChatSessionTypeAndReasonFromServices` keeps returning it as long as Agent Host itself stays enabled — it doesn't re-check whether the user's harness-preference settings (e.g. `chat.defaultToCopilotHarness`, `chat.editor.localAgent.enabled`) have since changed. That matches the report exactly, but this file is under very active, ongoing development (several commits this week reworking session-type selection reasons), so a maintainer should confirm the intended invalidation rule rather than treat it as settled.

## Change summary

The persisted `chat.userSelectedSessionType` (agent-host-copilotcli) keeps winning for new chats even after the user changes settings back to prefer Local/Extension Host chat and restarts, with no supported UI way to clear it short of editing the internal state DB.

## Best solution

In `getUsableRememberedSessionType`/`getDefaultNewChatSessionTypeAndReasonFromServices` (src/vs/workbench/contrib/chat/common/constants.ts, ~lines 423-470), decide whether a remembered session type should be invalidated when it no longer matches the user's current harness-preference configuration (not just when Agent Host is fully disabled), and/or surface a supported command/UI action to reset the remembered session-type preference instead of requiring manual state.vscdb edits.
