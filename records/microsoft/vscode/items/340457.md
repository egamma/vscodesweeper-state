# Issue #340457 — Onboarding overlay ignores `chat.disableAIFeatures` contributed by an extension

[https://github.com/microsoft/vscode/issues/340457](https://github.com/microsoft/vscode/issues/340457)

## Summary

Confirmed on main: `StartupPageRunnerContribution` calls `tryShowOnboarding()` synchronously from its constructor (startupPage.ts:103), before extensions are registered, so the `sentiment.hidden` check (line 249) can't yet see a `chat.disableAIFeatures` default contributed via an extension's `configurationDefaults`. An open PR (#340445) already fixes exactly this by moving the gate after extensions register, so this stays open pending that PR landing rather than any automated close.

## Change summary

The onboarding overlay (and its theme-picker step, which writes to USER settings) ignores `chat.disableAIFeatures` when that value is contributed via an extension's `configurationDefaults` rather than user settings, because the gate runs before extensions are registered.

## Best solution

Land PR #340445, which moves the `tryShowOnboarding()` gate to run after `whenInstalledExtensionsRegistered()` so extension-contributed `configurationDefaults` are visible when the sentiment check runs; the reporter separately notes this doesn't address the web-path early-return (#309741), which is a distinct issue.
