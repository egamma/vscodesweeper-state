# Issue #320051 — Support runtimeArgs for integrated browser

[https://github.com/microsoft/vscode/issues/320051](https://github.com/microsoft/vscode/issues/320051)

## Summary

Valid feature request — the integrated browser (used via the `editor-browser` debug type from js-debug) does not support `runtimeArgs` for passing Chromium flags like `--disable-web-security`. No existing setting or command covers this. The feature sits at the intersection of js-debug and VS Code's integrated browser; keeping open for community traction in the Backlog Candidates process.

## Change summary

Allow passing Chromium runtime arguments (e.g. `--disable-web-security`) to the integrated browser when launching via `"type": "editor-browser"` in launch.json.

## Best solution

Implement runtimeArgs support in the integrated browser launch path, likely requiring coordination between the js-debug extension (which owns the `editor-browser` debug type) and VS Code core's `src/vs/platform/browserView/` layer (which manages the embedded Chromium instance). The integrated browser would need to accept and apply BrowserWindow/BrowserView webPreferences or Chromium switches from the debug configuration.
