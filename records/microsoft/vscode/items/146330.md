# Issue #146330 — Allow WebviewViews to be explicitly created, so badges can be shown

[https://github.com/microsoft/vscode/issues/146330](https://github.com/microsoft/vscode/issues/146330)

## Summary

This is the canonical feature request for allowing extensions to show badges on WebviewViews before the user has opened them. The gap remains on current main — no eager-creation API exists. Two duplicate issues were closed pointing here, and it has 19 upvotes and an On Deck milestone.

## Change summary

Allow extensions to set a badge on a WebviewView before the user has opened it, analogous to how TreeView supports badges via `createTreeView`.

## Best solution

Add an API (analogous to `createTreeView`) that lets extensions eagerly obtain a WebviewView handle — or at minimum set a badge on a registered WebviewView before resolution. The implementation would likely live in `src/vs/workbench/api/common/extHostWebviewView.ts` and `src/vs/workbench/contrib/webviewView/browser/webviewViewPane.ts`, decoupling badge state from the lazy webview resolution lifecycle.
