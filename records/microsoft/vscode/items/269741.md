# Issue #269741 — Shell integration is lost when ps1 activate script are ran twice

[https://github.com/microsoft/vscode/issues/269741](https://github.com/microsoft/vscode/issues/269741)

## Summary

Still open on main: when a user manually runs a Python venv activate.ps1 script a second time, it overwrites the VS Code shell integration prompt function, breaking shell integration. The guard at line 7 of shellIntegration.ps1 prevents re-sourcing of the SI script itself, and the guard at line 77 prevents double auto-activation, but neither protects against a manual second invocation of the venv's Activate.ps1 overwriting the prompt.

## Change summary

Shell integration is lost when the Python venv activate.ps1 script is manually run a second time, because the activate script overwrites the VS Code-customized prompt function.

## Best solution

The shellIntegration.ps1 script (or the Python activate hook logic) needs to detect that the prompt has already been wrapped by VS Code and either re-wrap after activation or prevent the activate script from clobbering the SI prompt. The fix likely belongs in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1` — either by hooking post-activation prompt restoration or by making the prompt function resilient to being overwritten. Related issue https://github.com/microsoft/vscode/issues/287181 tracks a similar activate.ps1 interaction (exit code corruption) and may share root-cause work.
