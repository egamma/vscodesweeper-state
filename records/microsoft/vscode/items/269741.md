# Issue #269741 — Shell integration is lost when ps1 activate script are ran twice

[https://github.com/microsoft/vscode/issues/269741](https://github.com/microsoft/vscode/issues/269741)

## Summary

Keep open: startup activation followed by manual reactivation can replace the PowerShell prompt that emits shell-integration markers. The closed prompt-prefix issue addressed a different problem, and the related open reports do not establish a qualifying canonical for this re-reviewed item.

## Change summary

Preserve PowerShell shell integration when a Python virtual environment's Activate.ps1 script runs again after startup activation.

## Best solution

Make the PowerShell prompt lifecycle tolerate repeated virtual-environment activation while preserving command completion, decorations, and the environment prefix. Establish a live-shell regression scenario before changing the prompt integration.

- **Likely files:** `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1`, `src/vs/workbench/contrib/terminal/test/browser/xterm/shellIntegrationAddon.integrationTest.ts`
- **Validation:** On Windows with PowerShell and a Python venv activated through shellStartup, confirm command decorations initially work, manually invoke .venv\Scripts\Activate.ps1 again, and run Write-Output 'after activation'. Check that the command completes with its decoration and the venv prefix remains correct; repeat activation and then deactivate. Record the sequence with Developer: Record Terminal Session for command-detection assertions, and separately verify live-shell behavior because replay alone does not execute the activation script.
- **Behavior:**

  > A PowerShell terminal whose Python virtual environment was activated during shell startup must retain shell integration after the user manually activates that environment again. Subsequent commands must finish normally and retain command decorations, and the virtual-environment prefix must remain correct without accumulating duplicates. Repeated activation and subsequent deactivation must not strand command detection or remove the shell-integration prompt behavior.
- **Trace:**

  > In src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1, startup activation occurs before Global:Prompt is installed, and the activated prompt is captured in __VSCodeState.OriginalPrompt. CPython's Activate.ps1 saves the pre-activation prompt as _OLD_VIRTUAL_PROMPT and restores it during the next activation's deactivate -nondestructive call, so this sequence can replace the later VS Code wrapper. The original maintainer confirmation is https://github.com/microsoft/vscode/issues/269636#issuecomment-3363675924. Preserve normal activation environment changes, user prompt customization, and existing shell-integration protocol semantics; do not assume the exit-code-only defect in https://github.com/microsoft/vscode/issues/214909 has the same fix. The inspected recording suite validates received markers but does not execute this prompt lifecycle, so the planning session should first establish the live-shell regression and validation boundary.

After activation occurred before VS Code installed its wrapper, this saved prompt predates the wrapper; manual reactivation restores and wraps that earlier prompt, bypassing VS Code's marker-emitting Global:Prompt.
