# Issue #326087 — Copilot Chat: Add Prompt Markers to the Chat Scrollbar for Faster Navigation

[https://github.com/microsoft/vscode/issues/326087](https://github.com/microsoft/vscode/issues/326087)

## Summary

A real navigation gap remains: current VS Code supports sequential previous/next prompt commands but provides no visual landmarks in the chat scrollbar. The only implementation attempts were closed without merging, while the newer overview-ruler request is broader and cannot be the canonical duplicate for this re-reviewed issue.

## Change summary

Add configurable, downsampled user-prompt markers to chat scrollbars with previews and click-to-reveal behavior.

## Best solution

Decide whether prompt markers should remain a focused navigation feature or form the first accessible layer of a broader chat overview ruler, then implement the chosen design across the Chat View and Agents window without disrupting existing keyboard navigation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/common/constants.ts`
- **Validation:** Create component fixtures and focused browser tests covering prompt-only marker selection, hover previews, reveal versus reveal-and-focus behavior, density downsampling, keyboard/screen-reader equivalence, and availability in both the Chat View and Agents window.
- **Behavior:**

  > Long chat transcripts should expose user prompts as semantic navigation landmarks without adding markers for assistant or system turns. Users must be able to identify a marker, inspect its prompt and timestamp, and reveal the corresponding request while preserving the existing previous/next prompt commands. Marker density must remain useful in long sessions, and equivalent navigation must be available to keyboard and screen-reader users. The behavior must work consistently in both the Chat View and Agents window.
- **Trace:**

  > Current prompt navigation is implemented in src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts and filters request view models before focusing and revealing the previous or next prompt. The transcript itself is hosted by ChatListWidget in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts, which currently has no prompt-marker surface. Closed PR https://github.com/microsoft/vscode/pull/326137 explored a controller, three experimental settings, accessibility-help content, CSS, fixtures, and unit tests, but it was never merged. The newer https://github.com/microsoft/vscode/issues/327564 proposes a broader multi-layer overview ruler and explicitly treats prompt markers as a subset. Preserve existing sequential command behavior and avoid expanding this request into context heatmaps or error visualization unless the maintainer chooses consolidation.
- **Open decisions:**
  - Should prompt-only markers ship as a focused standalone rail, or should this work be consolidated into the first layer of the broader overview-ruler design in https://github.com/microsoft/vscode/issues/327564?
  - Should individual markers be keyboard-focusable controls with their own accessible names and previews, or should the visual rail remain non-focusable while the existing previous/next prompt commands provide the equivalent accessible interaction?
  - Should the feature remain opt-in through multiple experimental settings as proposed, or should the product expose a smaller configuration surface?

## Evidence

- **current capability:** src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts registers `workbench.action.chat.previousUserPrompt` and `workbench.action.chat.nextUserPrompt`, but these commands navigate sequentially and do not provide scrollbar landmarks, previews, or direct selection.
- **unmerged implementation:** https://github.com/microsoft/vscode/pull/326137 implemented the requested marker controller, settings, accessibility-help update, tests, and fixtures, but remained unmerged and was closed by its author for lack of community interest.
- **superseded first attempt:** https://github.com/microsoft/vscode/pull/326088 was closed and explicitly superseded by https://github.com/microsoft/vscode/pull/326137; neither PR merged.
- **related broader request:** https://github.com/microsoft/vscode/issues/327564 is open and describes this prompt-marker request as a subset of a broader overview ruler. It was created after this issue and requests additional viewport, response, context-heatmap, and error layers, so it does not satisfy the stronger duplicate bar for this re-reviewed item.
- **source gap:** Current src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts contains the chat transcript list and scrollbar integration but no prompt-marker controller, and the proposed `chat.scrollbarPromptMarkers.*` settings are absent from current main.
