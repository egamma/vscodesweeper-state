# Issue #193164 — Editor is broken when opening files with >120M lines

[https://github.com/microsoft/vscode/issues/193164](https://github.com/microsoft/vscode/issues/193164)

## Summary

Still present on main: the `| 0` bitwise truncation in scrollable.ts and editor code is unchanged, so files with >120M lines still overflow int32 and break scrolling. The issue is correctly in Backlog awaiting a decision on the tradeoff between int32 performance and large-file support.

## Change summary

Opening files with >120 million lines breaks editor scrolling because `| 0` bitwise operations overflow int32 when total pixel height exceeds 2,147,483,647.

## Best solution

Decide whether to replace `| 0` with `Math.floor` (or `Math.trunc`) in scroll-related code paths, accepting potential perf cost, or fail gracefully with telemetry as alexdima suggested. The fix touches `src/vs/base/common/scrollable.ts` and numerous editor layout files. The related exploration in https://github.com/microsoft/vscode/issues/167719 (ArrayBuffer backend) may also inform the approach.
