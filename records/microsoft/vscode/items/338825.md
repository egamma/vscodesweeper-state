# Issue #338825 — [Regression] Extension Development Host fails to start because js-debug connects to IPv6 localhost on VS Code 1.139.1

[https://github.com/microsoft/vscode/issues/338825](https://github.com/microsoft/vscode/issues/338825)

## Summary

Real regression, but the root cause and fix live in the bundled ms-vscode.js-debug extension's own repo, not in this repo's source — I found a near-exact upstream match already fixed there, but can't verify from this checkout that it's fully shipped/confirmed, so keeping open rather than closing.

## Change summary

Extension Development Host debug attach fails on VS Code 1.139.1 because js-debug's localhost endpoint discovery races between the IPv4 and IPv6 probes and never falls back successfully, unlike 1.138.0.

## Best solution

This looks already fixed upstream: microsoft/vscode-js-debug#2416 ('Node 24.20+ concurrent localhost endpoint probes cause attach failures') describes the identical failure in `getWSEndpoint`/`fetchJsonWithLocalhostFallback` (src/targets/browser/spawn/endpoints.ts) racing 127.0.0.1 vs [::1], caused by a Node 24.20 change to how aborted `got` requests report abort errors (see https://github.com/sindresorhus/got/issues/2469). It was fixed in https://github.com/microsoft/vscode-js-debug/pull/2417 and shipped in js-debug 1.140, which is already the version bundled in this repo's product.json on main. Best outcome is to confirm on an Insiders/next-stable build (js-debug >= 1.140) and close once confirmed.

- **upstream root-cause comment:** js-debug maintainer traced it to src/targets/browser/spawn/endpoints.ts (fetchJsonWithLocalhostFallback) and basicResourceProvider.ts's abort handling, triggered by a Node 24.20 change in how aborted `got` requests report errors (https://github.com/sindresorhus/got/issues/2469).
