# Issue #335657 — Copilot errors out when it is unable to access the web even with local model

[https://github.com/microsoft/vscode/issues/335657](https://github.com/microsoft/vscode/issues/335657)

## Summary

This matches the exact 'Failed to fetch models' symptom that the open meta-tracking issue #253137 exists to consolidate, caused by network/firewall blocking of the Copilot model-list endpoint — proposing a duplicate close there.

## Change summary

In a network where Copilot's endpoints are blocked, background calls to fetch the Copilot models list (used even for intent detection / utility model resolution) fail with an HTML block page instead of JSON, breaking chat even though a local/custom model is configured.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/253137, the maintainer-curated meta issue for 'Language Model Unavailable' / 'Failed to fetch models' network-blocking reports; this report's added detail (custom model provider still requires the internal `copilot-utility-small` model list, and IntentDetector's background telemetry call also silently fails for the same reason) is useful context to fold into that thread.

- **why it happens even with a custom model:** extensions/copilot/src/extension/prompt/node/intentDetector.tsx `collectIntentDetectionContextInternal()` still calls `endpointProvider.getChatEndpoint('copilot-utility-small')`, which resolves through `getCopilotUtilityModel()` in modelMetadataFetcher.ts — this always needs the CAPI models list regardless of the user's configured chat model, explaining why disabling telemetry settings doesn't stop it.
