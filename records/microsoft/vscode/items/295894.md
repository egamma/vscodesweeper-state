# Issue #295894 — per-model(s) instruction files

[https://github.com/microsoft/vscode/issues/295894](https://github.com/microsoft/vscode/issues/295894)

## Summary

Valid feature request for model-conditional instruction files. No existing attribute or mechanism filters instruction files by the active model — the current `model` header attribute selects which model runs a prompt/agent, which is a different concept. No duplicate found. Keeping open for community traction.

## Change summary

Allow instruction files to specify an `applyToModel` glob so they only activate when a matching model is in use.

## Best solution

Add an optional `applyToModel` (or similar) frontmatter attribute to instruction files that filters inclusion based on the active chat model, alongside the existing `applyTo` file-glob filter. Implementation would touch the prompt file attributes definition in `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, the header parser in `promptFileParser.ts`, and the automatic-instruction matching logic in `computeAutomaticInstructions.ts`. Needs a product decision on whether model-specific instructions are a valuable user-facing concept before implementation.

## Evidence

- **no existing support:** The `PromptHeaderAttributes` namespace in `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts` (lines 65–88) defines `model` (selects which model runs the prompt) and `applyTo` (file-glob filter), but has no `applyToModel` or model-conditional filtering attribute.
- **existing model attribute is different:** The `model` attribute in instruction/agent files (promptFileAttributes.ts line 60) specifies 'The model to use in this prompt', not a condition for when the instruction applies. The two concepts are orthogonal.
- **instruction matching is file-glob only:** `computeAutomaticInstructions.ts` (line 294) matches instructions via `_matches(files, applyToPattern)` using file-path globs; no model-based filtering branch exists.
