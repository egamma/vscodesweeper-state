# Issue #345745 — Agents: Add group configuration's

[https://github.com/microsoft/vscode/issues/345745](https://github.com/microsoft/vscode/issues/345745)

## Summary

Group-specific defaults remain a distinct feature gap: creating a session from a group currently carries group membership, not model or configuration defaults. Keep this request open for product consideration; the inspected related requests do not clearly own this behavior.

## Change summary

Allow custom session groups to supply model, settings, and scope defaults when creating a session through the group's plus button.

## Best solution

Define whether custom groups should also act as reusable session presets, including which options they support and how those defaults interact with explicit session choices and existing configuration.

## Evidence

- **Existing group capability:** src/vs/sessions/services/sessions/browser/sessionGroupsService.ts defines ISessionGroup with identity, name, creation time, parent, and appearance fields, but no model or session-configuration defaults. src/vs/sessions/SESSIONS_LIST.md explicitly describes group state as local presentation state rather than provider configuration.
- **Plus-button behavior:** src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts:1069–1103 registers sessionsView.newSessionInGroup. Its handler opens the new-session composer and calls setPendingNewSessionGroup(context.group.id); the pending-group implementation records membership intent, not session defaults.
- **Existing defaults are not group presets:** chat.defaultModel is registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts for new conversations. src/vs/sessions/contrib/chat/browser/sessionModelSelection.ts consumes that configuration through the shared model-selection controller, without a custom-group configuration input. This does not provide independently configurable defaults for each group.
- **Related requests are not verified duplicates:** https://github.com/microsoft/vscode/issues/342875 is open and concerns unified model configuration across roles and surfaces; https://github.com/microsoft/vscode/issues/340294 is open and concerns capability parity across Chat and the Agents window. Their inspected bodies do not establish ownership of custom session-group presets or inheritance through the group's plus button.
- **Demand and scope:** https://github.com/microsoft/vscode/issues/345745 has no comments, upvotes, or linked implementation in the supplied context. The central request is clear, but the supported settings and meaning of scope remain unspecified.
