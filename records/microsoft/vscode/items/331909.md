# Issue #331909 — Integrated Browser intermittently drops initial localhost navigation in Remote Tunnel after idle

[https://github.com/microsoft/vscode/issues/331909](https://github.com/microsoft/vscode/issues/331909)

## Summary

Confirmed on current main: `BrowserSessionRemote.whenReady` only awaits the Electron `setProxy()` call, not the actual upstream tunnel connection, and `TunnelProxy` resets the client connection on a transient upstream error without replaying the initial navigation — matching the reported blank-tab-after-idle symptom. An open PR (#331912) already targets this fix, so the issue should stay open pending review/merge rather than being closed.

## Change summary

After the Integrated Browser sits idle in a Remote Tunnel session, the first navigation to a fixed localhost URL can silently fail to reach the remote server and is never automatically replayed.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/331912, which proposes making remote browser proxy startup and first-connection resilient — the underlying fix should broaden `whenReady`/proxy state (off/pending/ready/failed) to include the upstream tunnel connection and replay the initial idempotent navigation once after a transient failure, per the reporter's diagnosis in browserSessionRemote.ts and tunnelProxy.ts.

## Evidence
