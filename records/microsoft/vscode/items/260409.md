# Issue #260409 — Text sometimes doesn't render correctly in Markdown preview since 1.103.0 update

[https://github.com/microsoft/vscode/issues/260409](https://github.com/microsoft/vscode/issues/260409)

## Summary

Keep open: multiple users confirmed a Windows Markdown-preview rendering regression, with useful display-scaling and version comparisons. No verified canonical or concrete fixing commit establishes that the reported behavior is resolved.

## Change summary

Scrolling the Markdown preview intermittently makes ordinary paragraphs appear heavier until another scroll or hover repaints them.

## Best solution

Restore consistent paragraph rendering in the desktop Markdown preview at 100% and 125% Windows display scaling. First reproduce on a current build and distinguish preview styling or webview integration from an Electron/Chromium paint defect before choosing the owning fix.

- **Validation:** On Windows 11 with a current desktop build, extensions disabled, Default Light+, and a 1080p display at 100% then 125% scaling, preview several ordinary paragraphs surrounding a fenced code block and repeatedly scroll up and down. Compare 150% scaling and vscode.dev as controls.
- **Behavior:**

  > Ordinary Markdown paragraphs should retain the same visual weight while scrolling the desktop preview. Reporters observe transient heavier text at 100% and 125% Windows display scaling, sometimes corrected by hovering or scrolling again. Diagnosis should first establish whether this persists on a current build using a light theme and a document containing a fenced code block. Acceptance requires stable rendering under those conditions without changing intentional bold text, code-block scrolling, or editor-preview synchronization.
- **Trace:**

  > The preview styles live in extensions/markdown-language-features/media/markdown.css, including positioned line-hover markers and overflow on fenced-code containers; the inspected rules do not change paragraph font weight on hover. The scroll listener in extensions/markdown-language-features/preview-src/index.ts:770-789 updates stored position and posts revealLine messages. https://github.com/microsoft/vscode/issues/260409 documents a regression from 1.102 to 1.103, multiple affected graphics configurations, normal browser rendering, and a display-scaling dependency. That evidence makes a desktop paint/compositing interaction plausible, but does not identify its root cause or prove current-main reproduction. The investigation must establish whether ownership lies in preview CSS, webview integration, or Electron/Chromium before defining a bounded change; do not substitute different typography or disable synchronization merely to conceal the symptom.

## Evidence

- **Independent reproduction:** https://github.com/microsoft/vscode/issues/260409#issuecomment-3431292152 independently confirms the symptom on VS Code 1.103.2, Windows 11 23H2, a 1080p external monitor, 100% scaling, and Default Light+. Downgrading to 1.102.3 avoids it.
- **Scaling and hardware isolation:** https://github.com/microsoft/vscode/issues/260409#issuecomment-3191899538 reports reproduction on both Intel and AMD graphics at 100% or 125% scaling, but normal rendering at 150%. The body reports reproduction with extensions disabled.
- **Desktop versus browser comparison:** After a maintainer requested a browser comparison, https://github.com/microsoft/vscode/issues/260409#issuecomment-3189134702 reports normal rendering in vscode.dev on Chrome 139.0.7258.128 and in desktop version 1.102, but easy reproduction in desktop 1.103.1. This suggests a desktop rendering boundary without proving an upstream root cause.
- **Persistence and specific trigger:** https://github.com/microsoft/vscode/issues/260409#issuecomment-3211836582 narrows the trigger to Windows 11, 100% scaling, a light theme, and a Markdown document containing a fenced code block; two coworkers also observed it. https://github.com/microsoft/vscode/issues/260409#issuecomment-3399202283 reports persistence through version 1.105.
- **Current source inspection:** extensions/markdown-language-features/media/markdown.css defines paragraph spacing, positioned preview-line hover markers, and scrollable fenced-code containers, but no paragraph hover rule that changes font weight. extensions/markdown-language-features/preview-src/index.ts:770-789 handles preview scrolling by recording position and revealing the corresponding editor line, not by changing paragraph weight. These reads do not establish the environment-dependent paint defect or its resolution.

The checkout is shallow with only one available history commit, so local history cannot substantiate a fixing commit. No runtime reproduction was attempted in this read-only macOS checkout.
