# Issue #287077 — Installing a language model provider extension should show it in the Manage Model list

[https://github.com/microsoft/vscode/issues/287077](https://github.com/microsoft/vscode/issues/287077)

## Summary

The discoverability gap remains on current main: installed but unconfigured model providers are available through Add Models but do not appear in the model list, and no post-install handoff exists. A maintainer accepted improving this flow, while the exact interaction still needs a product choice.

## Change summary

Make an installed language-model-provider extension's configuration entry discoverable without requiring the user to infer that they must select Add Models.

## Best solution

After installing an extension that contributes `languageModelChatProviders`, expose its configuration flow immediately and contextually. The plan should choose between representing the unconfigured provider in the model list or opening the models editor and configuration picker after installation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatManagement/chatManagement.contribution.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/chatManagement/chatModelsViewModel.test.ts`
- **Validation:** Add a focused chat-management test that simulates a newly installed extension contributing an unconfigured language-model provider and verifies the chosen discoverability/configuration flow, while updates and unrelated extension installs produce no handoff.
- **Behavior:**

  > After a user installs an extension that contributes a language model provider, the provider's configuration path is immediately discoverable without requiring the user to infer that Add Models is the next step. The experience must still require explicit credential or model configuration before models become usable. Extension updates, unrelated installs, and already configured providers must not trigger an unsolicited flow.
- **Trace:**

  > `ChatModelsViewModel.refreshAllVendors` enumerates provider descriptors, but `groupModels` only emits groups derived from configured models or statuses, so an unconfigured provider disappears from the table. `ChatModelsWidget.updateAddModelsButton` separately exposes every configurable vendor through Add Models. `ChatManagementActionsContribution` owns opening the management editor but does not observe extension installations; the only analogous listener found is `ChatGettingStartedContribution`, which is restricted to the default chat extension. The Install Model Providers work in https://github.com/microsoft/vscode/pull/318840 covers Marketplace discovery, not the post-install transition. Keep the scope to fresh installs that contribute `languageModelChatProviders`; do not change model activation, credential requirements, extension-update behavior, or unrelated installation UX.
- **Open decisions:**
  - Should a newly installed but unconfigured provider appear as a collapsed row with an inline configuration affordance, or should installation open the models editor and provider configuration picker?
  - If installation initiates configuration, should it happen automatically or through a non-modal prompt that preserves the user's current focus?

## Evidence

- **maintainer direction:** In https://github.com/microsoft/vscode/issues/287077, a maintainer agreed that users should be driven to add models after installing a contributing extension and proposed opening the models editor with its configuration picker; the reporter agreed that approach could work.
- **current list construction:** On current main, `ChatModelsViewModel.groupModels` in `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts` creates provider rows only while iterating configured models or provider status groups. An installed provider with neither has no row.
- **existing partial capability:** `ChatModelsWidget.updateAddModelsButton` in `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts` puts configurable provider descriptors behind Add Models, preserving the reported extra discovery step.
- **missing post-install flow:** `src/vs/workbench/contrib/chat/browser/chatManagement/chatManagement.contribution.ts` registers the management editor and commands but has no extension-install listener. The nearby listener in `src/vs/workbench/contrib/chat/browser/actions/chatGettingStarted.ts` handles only installation of the default chat extension.
- **later related work is insufficient:** https://github.com/microsoft/vscode/pull/318840 added an Install Model Providers button that opens a Marketplace search. It improves pre-install discovery but does not surface or configure a provider after its extension is installed.
