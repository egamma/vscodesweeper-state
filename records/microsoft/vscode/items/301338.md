# Issue #301338 — Integrate Session Window as a Built-in VS Code Feature with Quick Toggle

[https://github.com/microsoft/vscode/issues/301338](https://github.com/microsoft/vscode/issues/301338)

## Summary

This remains a distinct product request: current VS Code can open and switch to the separate Agents Window, but it cannot transform the existing editor window into the agent-optimized workbench in place. The issue is still within its Backlog Candidates voting period, so it should remain open under discussion.

## Change summary

Add a reversible command or control that switches the current VS Code window between the standard workbench and the agent-optimized Sessions experience without opening another window.

## Best solution

Decide whether VS Code should support an in-place Agents presentation mode that preserves the current window's editors, terminals, and layout, then define how that mode coexists with the deliberately separate Agents Window and integrated Sessions panel.

## Evidence

- **clarified gap:** The reporter clarified at https://github.com/microsoft/vscode/issues/301338#issuecomment-4086753696 that the request is specifically for an in-place, reversible workbench transition preserving editor, terminal, and layout continuity—not merely access to the integrated Sessions panel.
- **current architecture:** src/vs/sessions/LAYOUT.md defines the Agents Window as a Sessions-owned workbench topology with fixed part positions that omits the standard Activity Bar, Status Bar, and Banner; it does not define a mode that replaces and restores a standard editor window's workbench in place.
- **existing commands:** src/vs/sessions/contrib/openAgentsWindow/electron-browser/openAgentsWindowCommand.ts implements workbench.action.openAgentsWindow through INativeHostService.openAgentsWindow, while src/vs/sessions/electron-browser/actions/vscodeActions.ts switches focus to or opens another main window. These commands retain the separate-window model and do not satisfy the central request.
