# Issue #337284 — Staging a file with * adds unrelated files

[https://github.com/microsoft/vscode/issues/337284](https://github.com/microsoft/vscode/issues/337284)

## Summary

Real bug in the built-in Git extension: paths passed to `git add`/`rm`/etc. are not marked as literal pathspecs, so a file literally named with glob characters like `*.md` causes git itself to glob-match and stage unrelated files. Confirmed the root cause in git.ts and reproduced git's own pathspec globbing directly with the CLI.

## Change summary

Staging a file whose name contains a glob character (e.g. a file literally named `*.md`) via the Source Control view also stages other files that match the pattern.

## Best solution

In extensions/git/src/git.ts, mark user-selected file paths as literal git pathspecs (e.g. prefix with `:(literal)` magic) wherever `sanitizeRelativePath` results are passed to git commands (`add`, `rm`, `revert`, `clean`, `checkout`, `apply`, etc.), so a selected path is always treated as an exact path rather than a glob pattern.

## Evidence

- **code path:** extensions/git/src/git.ts add() (line ~1964) builds args as ['add', '-A', '--', ...paths.map(p => this.sanitizeRelativePath(p))] and sanitizeRelativePath() (line 372) only normalizes backslashes to slashes — it never escapes or marks the path as a literal pathspec.
- **confirmed git behavior:** Reproduced directly with git CLI: `touch '*.md' another.md; git add -A -- '*.md'` stages both files, because git's default pathspec matching treats `*` as a wildcard even when passed as a single argv token (no shell involved) unless `:(literal)` magic or `--literal-pathspecs` is used.
- **scope:** The same unguarded pattern (`paths.map(p => this.sanitizeRelativePath(p))`) recurs at git.ts lines 1974, 1989, 2053, 2299, 2339, 2368, 3380 — i.e. add, rm, revert/reset, clean, checkout, and stage-related commands all share the same exposure.
