# Issue #121440 — Notebook cell focus feedback should disappear when clicking the empty view content or somewhere else

[https://github.com/microsoft/vscode/issues/121440](https://github.com/microsoft/vscode/issues/121440)

## Summary

The focus-feedback improvement remains relevant: current source deliberately retains an active cell and draws an inactive indicator after focus leaves. Keep this open for a notebook UX decision about blank-space clicks and the distinction between active-cell state and keyboard focus.

## Change summary

Make notebook cell focus feedback disappear when clicking empty notebook space or another surface.

## Best solution

Make cell focus feedback accurately distinguish keyboard focus from retained active-cell context, without losing the target for notebook commands. Settle where keyboard focus goes after a blank-space click before changing notebook list behavior or indicator styling.

Verify the agreed indicator state and keyboard focus destination, return to the notebook and invoke Insert Code Cell Above to confirm retained command context, and check keyboard navigation and high-contrast focus visibility.
- **Behavior:**

  > The reporter wants cell focus feedback to disappear when clicking blank notebook content or another surface instead of requiring Escape. Current notebook feedback distinguishes active and inactive cell focus, so the desired treatment of the inactive indicator needs agreement. Acceptance must cover blank-space clicks and focus transfer outside the notebook in both border and gutter modes. Notebook command targeting and visible keyboard focus must remain reliable.
- **Trace:**

  > The base List mouse controller in src/vs/base/browser/ui/list/listWidget.ts focuses the list and attempts to clear row focus on a blank-space click. NotebookCellList.setFocus in src/vs/workbench/contrib/notebook/browser/view/notebookCellList.ts rejects clearing focus for a nonempty model, explicitly preserving the context discussed in https://github.com/microsoft/vscode/issues/121129. NotebookEditorWidget's blur handler updates editor-focus state but retains the focused row. notebookFocusIndicator.css and NotebookEditorWidget's generated gutter styles intentionally render inactive focus feedback; notebook.cellFocusIndicator only changes placement. The issue's comment supports the improvement but does not decide the blank-space keyboard focus destination. Preserve cell-command context, keyboard navigation, and accessible focus visibility; do not treat deleting the focus-retention guard as an established requirement.
- **Open decisions:**
  - After clicking blank notebook space, should keyboard focus remain on the notebook list with its active-cell context retained, or move to a notebook-level focus target?
  - When a cell remains the active command target but no longer has keyboard focus, should its inactive indicator disappear entirely or remain as a quieter active-cell cue?
