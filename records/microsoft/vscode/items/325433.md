# Issue #325433 — Main process crash closes all windows: access violation in unloaded explorerframe.dll (BEX64, 0xc0000005), recurring since June 2026

[https://github.com/microsoft/vscode/issues/325433](https://github.com/microsoft/vscode/issues/325433)

## Summary

Credible, well-diagnosed crash, but the fault is inside Windows' own explorerframe.dll (the shell's native file-dialog/COM machinery), reached only through Electron's `dialog.showOpenDialog`/`showSaveDialog` wrapper — VS Code doesn't own or load that DLL itself, so this is upstream (Electron/Windows shell), not a fixable VS Code source bug; routing to the Windows area rather than closing given the crash severity and multi-version recurrence.

## Change summary

Main process periodically access-violates in an already-unloaded explorerframe.dll (Windows shell/COM), killing all windows, apparently tied to earlier use of a native file dialog and a delayed COM unload.

## Best solution

Confirm VS Code's native dialog calls (src/vs/platform/dialogs/electron-main/dialogMainService.ts, using electron.dialog) are the only path that pulls in explorerframe.dll, then track/report this upstream to Electron (and ultimately Microsoft's Windows shell team, per the reporter's own linked Microsoft Q&A thread showing other apps hit by the same fault) rather than trying to patch it in VS Code's own code.
