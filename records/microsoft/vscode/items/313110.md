# Issue #313110 — Agents: Support drag-and-drop sub-session tabs

[https://github.com/microsoft/vscode/issues/313110](https://github.com/microsoft/vscode/issues/313110)

## Summary

The requested same-group tab reordering remains missing on current main. Existing drag-and-drop only moves chats between groups or splits them side by side, so this team-authored On Deck request should remain open.

## Change summary

Allow users to drag sub-session chat tabs into a different order.

## Best solution

Provide editor-style positional reordering within each chat tab strip while preserving the existing drag gestures for moving chats between groups and splitting them side by side. Decide whether the main chat can move and whether a custom order persists for single-group sessions.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/chatCompositeBar.ts`, `src/vs/sessions/browser/parts/chatGroupView.ts`, `src/vs/sessions/browser/parts/chatGroupsView.ts`, `src/vs/sessions/browser/parts/chatGroupDropTarget.ts`, `src/vs/sessions/test/browser/chatCompositeBar.test.ts`, `src/vs/sessions/test/browser/chatGroupsView.test.ts`
- **Validation:** Add targeted chat composite-bar and chat-groups tests that drag a tab before and after another tab, assert the resulting `resourceIds` order, verify activation remains correct, and confirm existing center/edge drops still move or split chats as before; include reload restoration if persistence is selected.
- **Behavior:**

  > Users can drag sub-session chat tabs to a specific position in the tab strip. The resulting visual and keyboard-navigation order must match the drop position, without breaking activation, close actions, or existing cross-group move and side-by-side split gestures. Acceptance should cover moving a tab in both directions and the chosen behavior for the main tab and reload persistence.
- **Trace:**

  > ChatCompositeBar in src/vs/sessions/browser/parts/chatCompositeBar.ts renders tabs in the order supplied by `IChatCompositeBarDelegate.chats` and currently publishes only drag start/end callbacks. ChatGroupView forwards that delegate from ChatGroupsView, whose per-group `resourceIds` array is explicitly the tab order. ChatGroupsView._onChatDrop currently treats a same-group center drop as a no-op, moves a chat to another group on a foreign center drop, and creates a split on edge drops. Multi-group `resourceIds` order is serialized by `_persistLayout`, but single-group layouts are removed from storage. Preserve cross-group and split behavior, chat activation, pin state, and drag-to-chat-reference payloads; the uncertainty begins at the intended main-tab and single-group persistence contracts.
- **Open decisions:**
  - May the session's main chat tab be reordered, or must it remain anchored as the first tab?
  - Should a custom tab order persist across reloads for single-group sessions, or remain window-lifetime presentation state?
  - When transferring a tab to another group's tab strip, should its precise drop position be honored or should cross-group drops continue appending it?

## Evidence

- **current drag behavior:** In src/vs/sessions/browser/parts/chatGroupsView.ts, `_onChatDrop` explicitly returns when a chat is dropped in the center of its own group; edge drops call `_splitChatIntoNewGroup`, while center drops on another group call `_moveChatToGroup`. No path changes a tab's index within its existing group.
- **tab surface:** src/vs/sessions/browser/parts/chatCompositeBar.ts marks each chat tab draggable and emits drag start/end callbacks, but `IChatCompositeBarDelegate` has no positional reorder operation or tab-drop callback.
- **persistence boundary:** ChatGroupsView stores `resourceIds` in tab order for multi-group layouts, but `_persistLayout` clears storage when only one group exists. A persisted custom order for the common single-group tab strip is therefore not currently represented.
- **related implementation:** https://github.com/microsoft/vscode/commit/dd7687527a42277a9625f06391880cb5aaa4fc83 introduced the current chat-tab and group drag implementation, but its diff only supports cross-group movement and side-by-side splitting, not same-group reordering.
