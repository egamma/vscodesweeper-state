# Issue #292992 — Add User Interaction Mechanism for Webview in GitHub Copilot Chat Output Renderer API

[https://github.com/microsoft/vscode/issues/292992](https://github.com/microsoft/vscode/issues/292992)

## Summary

A real gap remains: the ChatOutputRenderer API currently exposes a one-way webview (tool → render) with no mechanism for the webview to send interaction results back to the tool or model. The request is in the Backlog Candidates community process with 10 days remaining; keeping open per policy.

## Change summary

Allow webview elements rendered via ChatOutputRenderer to send user interaction results back to the language model tool for further processing.

## Best solution

Extend the `ChatOutputWebview` API surface (in `src/vs/workbench/api/common/extHostChatOutputRenderer.ts`) to support bidirectional messaging — the webview already has `postMessage`/`onDidReceiveMessage` on the underlying `ExtHostWebview`, but the `ChatOutputWebview` wrapper currently only exposes `webview` and `onDidDispose`. A design decision is needed on whether interactions should flow back through the tool invocation result, a new event channel, or the existing webview message API surfaced to the tool. This needs API design input from the chat/API area owners.
