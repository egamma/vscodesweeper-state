- **Exact current-source path:** extensions/git/src/commands.ts:2822-2845, CommandCenter.checkout2 (git.graph.checkout), resolves the selected remote reference through findTrackingBranches and passes branches[0].name to repository.checkout instead of the selected remote reference. extensions/git/src/git.ts:2989-2994 finds tracking branches solely by upstream name, without comparing commit IDs. With foo tracking origin/foo and git.pullBeforeCheckout disabled, this checks out the older foo tip exactly as reported.
- **Shared branch-picker behavior:** extensions/git/src/commands.ts:166-185, CheckoutRemoteHeadItem.run, also substitutes the first local tracking branch when a remote branch is selected. The canonical's branch-picker report and this graph report therefore expose the same behavior across two built-in Git entry points.
- **Existing capabilities are partial workarounds:** extensions/git/package.json:3826-3830 registers git.pullBeforeCheckout with default false. The graph honors it, and extensions/git/src/repository.ts:1730-1747 attempts a safe fast-forward fetch, but rejection leaves the local branch unchanged and checkout still proceeds. git.graph.checkoutDetached in commands.ts:2852-2857 checks out the selected history commit explicitly. Neither removes the misleading behavior of the ordinary remote-checkout action across behind and diverged branches.
- **Independent confirmation and unique evidence:** The discussion at https://github.com/microsoft/vscode/issues/286359 includes the reporter's confirmation after upgrading from 1.107.0 and protron's independent confirmation on Windows VS Code 1.115.0.
