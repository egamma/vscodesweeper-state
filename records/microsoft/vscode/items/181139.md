# Issue #181139 — Accessibility: Make Tab key focus restricted to the currently open view

[https://github.com/microsoft/vscode/issues/181139](https://github.com/microsoft/vscode/issues/181139)

## Summary

Keep open for an accessibility design decision: current find-widget navigation still permits focus to leave the overlay, and the existing Tab focus command does not provide scoped cycling. The discussion explicitly retained this as a feature request; no verified canonical or completed implementation supersedes it.

## Change summary

Allow Tab and Shift+Tab to cycle within the active overlay instead of moving into the underlying editor or surrounding workbench.

## Best solution

Agree on a consistent accessibility interaction for non-modal overlays that provides clear focus boundaries without inadvertently blocking workbench navigation. Resolve whether containment is optional or changes the default, and which surfaces participate, before implementation.

- **Behavior:**

  > The reporter wants Tab and Shift+Tab to stay within the active overlay, using Find as an example, until the user explicitly leaves or dismisses it. Current application-wide traversal makes the boundary confusing for blind users. Acceptance must cover forward and backward traversal, Find and Replace states, disabled controls, dismissal, and deliberate access to the surrounding workbench. Whether this behavior is optional or the default, and which non-modal surfaces it covers, requires a maintainer decision.
- **Trace:**

  > FindWidget in src/vs/editor/contrib/find/browser/findWidget.ts contains bespoke Tab navigation between inputs, toggles, and buttons rather than general overlay containment. Its Close-button handler explicitly calls _codeEditor.focus() when Replace is expanded but replacement is unavailable, confirming that editor escape remains possible. editor.action.toggleTabFocusMode changes tab insertion versus workbench navigation, not the requested scope boundary; editorOptions.ts documents the same distinction. https://github.com/microsoft/vscode/issues/181139#issuecomment-1536055983 establishes the existing application-wide navigation intent, and https://github.com/microsoft/vscode/issues/181139#issuecomment-1708933841 records concerns about scope-specific modes. - **Open decisions:**
  - Should scoped Tab cycling be opt-in, enabled automatically for screen reader users, or the default for all users?
  - Which non-modal surfaces should participate: editor overlays such as Find, or also panels and other views?
