# Issue #337279 — Agent Host regression: no per-hunk Accept/Undo or reviewed state for agent changes

[https://github.com/microsoft/vscode/issues/337279](https://github.com/microsoft/vscode/issues/337279)

## Summary

Confirmed from source: the sessions Changes editor only tracks review state per whole file (ISessionFileChange.reviewed, toggled via setChangesetFilesReviewState / 'Mark as Reviewed'), with no per-hunk accept/undo or reviewed marker like the old chat-editing workflow had. This is a real, well-diagnosed gap, but the right design (restore accept/undo semantics vs. a lighter per-hunk reviewed flag, and how it interacts with the existing file-level state) needs a maintainer decision before implementation.

## Change summary

Agent Host's Changes editor only supports marking an entire file as reviewed; there is no per-hunk Accept/Undo or per-hunk reviewed/unreviewed state like the previous Copilot Chat editing UI provided.

## Best solution

Extend the sessions changes review model (src/vs/sessions/contrib/changes) to track reviewed state at hunk granularity, exposed in the multi-diff editor per changed region, and clear that state when the agent re-touches the hunk — but the maintainers should first decide whether to reintroduce apply/undo-style per-hunk actions or a lighter 'mark hunk reviewed' toggle.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/changes/common/changesViewService.ts`, `src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts`, `src/vs/sessions/contrib/changes/browser/changesActions.ts`, `src/vs/sessions/services/sessions/common/session.ts`
- **Validation:** A test in the sessions changes suite asserting a hunk-level reviewed/accepted state can be set and cleared, and that it resets when the agent re-modifies that hunk.
- **Behavior:**

  > When reviewing Agent Host changes, the user should be able to mark (or accept/undo) an individual diff hunk, not just the whole file. The per-hunk state should persist while navigating between files and should reset automatically if the agent subsequently modifies that same hunk. File-level 'Mark as Reviewed' should keep working for users who don't need hunk granularity.
- **Trace:**

  > Review state currently lives only at the file level: `ISessionFileChange.reviewed` (src/vs/platform/services/sessions/common/session.ts, referenced via changesViewService.ts) is a boolean per file, surfaced through `setChangesetFilesReviewState(resources, reviewed)` and the `SessionChangesReviewedFilesContext`/`ChangesetReviewedFilesContext` context keys in changesActions.ts and changesetReviewActions.ts. The multi-diff source resolver (changesMultiDiffSourceResolver.ts) resolves one row per file with no hunk-level metadata. The legacy `chatEditor.action.acceptHunk` in chatEditingCodeEditorIntegration.ts is wired to the old chat-editing text model change service, a separate pipeline not used by Agent Host sessions. Do not touch that legacy chat-editing path; the new capability belongs in the sessions changes model and its multi-diff integration. Where uncertainty starts: whether hunk state should trigger an actual accept/undo of the edit (reintroducing apply/reject semantics) or remain a pure bookkeeping flag, and where that state should be persisted (session state vs. ephemeral UI state).
- **Open decisions:**
  - Should per-hunk controls perform an actual Accept/Undo of the edit (as in the old chat-editing UI), or only mark hunks as reviewed/unreviewed without altering the file content?
  - Should per-hunk reviewed state persist across window reloads/session restore, or only for the current UI session?
  - How should per-hunk reviewed state interact with the existing whole-file 'Mark as Reviewed' toggle (e.g., does marking all hunks reviewed auto-mark the file, and vice versa)?

## Evidence

- **file-level only:** src/vs/sessions/contrib/changes/common/changesViewService.ts defines `setChangesetFilesReviewState(resources, reviewed)` operating on whole-file URIs; src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts documents `SessionChangesReviewedFilesContext` as tracking 'the URIs ... of every file the user has marked as reviewed' — no hunk-level equivalent exists.
- **old per-hunk actions were chat-editing-specific:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts has `chatEditor.action.acceptHunk`, tied to the legacy chat-editing text model change service, not to the Agent Host session-changes pipeline the reporter is now using.
