# Issue #337279 — Agent Host regression: no per-hunk Accept/Undo or reviewed state for agent changes

[https://github.com/microsoft/vscode/issues/337279](https://github.com/microsoft/vscode/issues/337279)

## Summary

Confirmed real gap from source: the Agent Host / Agents Window changes view only exposes whole-file 'Mark as Reviewed' (SessionChangesReviewedFilesContext in changesMultiDiffSourceResolver.ts), unlike the older chatEditing flow which has per-hunk chatEditor.action.acceptHunk/undoHunk. Two related but non-duplicate issues exist (one older, different symptom; one newer, can't be canonical per the re-review rule), so this stays open on its own.

## Change summary

Agent Host sessions apply edits directly to the working tree and only offer file-level 'Mark as Reviewed', losing the per-hunk Accept/Undo/Reviewed granularity that the previous Copilot Chat editing UI provided.

## Best solution

Extend the Agents Window changes review model (src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts and its multi-diff editor integration) with a per-hunk reviewed/unreviewed state, analogous to the existing SessionChangesReviewedFilesContext but scoped to individual diff hunks; a maintainer should first decide whether Accept/Undo semantics (which imply reverting a hunk in the working tree) or a lighter-weight 'mark hunk reviewed' bookkeeping state is the intended design for direct-to-working-tree edits.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts`
- **Validation:** A test asserting a per-hunk reviewed/unreviewed (or accept/undo) state persists across navigation and clears when the agent re-modifies that hunk.
- **Behavior:**

  > In an Agent Host session's Changes view, a user can mark an individual diff hunk (not just the whole file) as reviewed/accepted, with that state visible while navigating between files/hunks and cleared automatically if the agent subsequently re-modifies that hunk.
- **Trace:**

  > SessionChangesReviewedFilesContext in src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts currently tracks review state per file only; the older chatEditing flow's per-hunk chatEditor.action.acceptHunk/undoHunk (chatEditingEditorActions.ts, chatEditingTextModelChangeService.ts) is the prior-generation analog but assumes a revertible pending-edit model that doesn't map directly onto Agent Host's direct-to-working-tree edits. Do not change file-level review semantics or the underlying working-tree apply model; scope is additive per-hunk state. See also https://github.com/microsoft/vscode/issues/338205 which may consolidate related Agents Window review-UX gaps.
- **Open decisions:**
  - Should per-hunk state be Accept/Undo (implying reverting the hunk in the working tree) or a non-destructive 'mark hunk reviewed/unreviewed' bookkeeping flag?
  - How should this new per-hunk state relate to the existing file-level 'Mark as Reviewed', and to the overlapping ask in https://github.com/microsoft/vscode/issues/338205?
  - Should the diff for an unreviewed hunk remain editable in place, addressing the related 'locked diff' comment, or is that a separate issue?
