# Issue #337279 — Agent Host regression: no per-hunk Accept/Undo or reviewed state for agent changes

[https://github.com/microsoft/vscode/issues/337279](https://github.com/microsoft/vscode/issues/337279)

## Summary

Confirmed on main: the Agent Host review service (src/vs/platform/agentHost/common/agentHostReviewService.ts) only exposes file-level `markFileReviewed`/`getReviewedPaths` — there is no per-hunk accept/undo or reviewed-state concept, unlike the older chat-editing flow (chatEditingCodeEditorIntegration.ts) which had hunk-level revert/accept. This is a real, still-open capability gap, not something fixed on main.

## Change summary

Agent Host sessions lost the per-hunk Accept/Undo and per-hunk reviewed-state controls that the previous Copilot Chat editing workflow had, leaving only whole-file 'Mark as Reviewed'.

## Best solution

Extend the Agent Host review/changeset model (agentHostReviewService.ts, the changeset protocol in src/vs/platform/agentHost/common/state/protocol/channels-changeset/) and the multi-diff editor UI (src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts) to support per-hunk reviewed/accepted state, likely reusing concepts from the retired chatEditingCodeEditorIntegration.ts hunk accept/undo UI — this needs a design decision on granularity and semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/common/agentHostReviewService.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-changeset/state.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-changeset/actions.ts`, `src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts`
- **Validation:** A test confirming an agent-session changeset can mark an individual hunk reviewed/accepted independently of other hunks in the same file, and that modifying the hunk again clears its reviewed state.
- **Trace:**

  > Established so far: agentHostReviewService.ts's review API is file-scoped (markFileReviewed/getReviewedPaths); the changeset protocol in channels-changeset/state.ts and actions.ts has no per-hunk state; chatEditingCodeEditorIntegration.ts shows the previous (non-Agent-Host) editing flow had hunk-level accept/revert. The uncertainty starts at design: whether review state should live per-hunk in the changeset protocol or be derived from diff hashes, and whether the UI should be Accept/Undo (destructive) or Reviewed/Unreviewed (non-destructive) semantics.
- **Open decisions:**
  - Should the control be destructive Accept/Undo (reverting the agent's edit) or non-destructive Mark Hunk Reviewed/Unreviewed (bookkeeping only)?
  - Is review state tracked per-hunk by diff position, or keyed to content hash so it survives unrelated edits elsewhere in the file?
  - Should reviewed state be scoped to the current Agent Host session only, or persist across sessions/reloads like file-level reviewed state does today?

## Evidence

- **file-level only API:** src/vs/platform/agentHost/common/agentHostReviewService.ts exposes only markFileReviewed(...)/getReviewedPaths(...) — no hunk-granular method exists.
- **no hunk concept in changeset state:** rg for 'hunk' in agentHostReviewService.ts and changesMultiDiffSourceResolver.ts returns no matches, confirming no per-hunk tracking today.
- **prior hunk UI existed elsewhere:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts and chatEditingEditorActions.ts implement acceptHunk/revertHunk for the older chat-editing flow, supporting the reporter's regression claim.
- **no recent fix:** git log on agentHostReviewService.ts shows only an unrelated perf commit (280a9749), no work toward per-hunk review.
