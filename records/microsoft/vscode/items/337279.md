# Issue #337279 — Agent Host regression: no per-hunk Accept/Undo or reviewed state for agent changes

[https://github.com/microsoft/vscode/issues/337279](https://github.com/microsoft/vscode/issues/337279)

## Summary

Confirmed from source: the sessions Changes editor only tracks a file-level 'reviewed' context key, with no per-hunk accept/undo or reviewed state. This is a real, well-corroborated gap (two commenters agree) in the new Agent Host editing workflow versus the old Copilot Chat editing UX, and it needs a maintainer design decision before implementation.

## Change summary

Agent Host sessions apply edits directly with only whole-file 'Mark as Reviewed'; there is no per-hunk Accept/Undo or reviewed/unreviewed tracking like the previous chat editing workflow had.

## Best solution

Design and add per-hunk review state (Accept/Undo or Mark Hunk Reviewed/Unreviewed) in the sessions Changes multi-diff flow, likely extending src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts and the multi-diff editor contribution, with persistence/clearing semantics settled by a maintainer first.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts`, `src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffSourceResolverService.ts`
- **Validation:** A test confirming a per-hunk reviewed/accepted state persists and is exposed via context keys analogous to SessionChangesReviewedFilesContext, scoped to individual diff hunks rather than whole files.
- **Trace:**

  > Root cause traced to src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts, which only exposes a per-file `SessionChangesReviewedFilesContext` for 'Mark as Reviewed' toolbar actions; no equivalent per-hunk state exists in the Agent Host Changes editor or multi-diff editor contribution. Where uncertainty starts: whether the UI should restore Accept/Undo per hunk (as in the legacy chat edit flow) or a simpler Mark Hunk Reviewed/Unreviewed toggle, and how that state persists/clears when the agent re-edits a hunk.
- **Open decisions:**
  - Should the restored control be Accept/Undo (applying/reverting the hunk) or a lighter Mark as Reviewed/Unreviewed toggle that doesn't change the already-applied edit?
  - Where and how is per-hunk reviewed state persisted/cleared — tied to content hash of the hunk, session state, or something else — when the agent subsequently re-edits that hunk?
  - Should the previous chat-editing workflow's in-place diff editability (raised in a comment) be restored for Agent Host sessions, or is that a separate concern?

## Evidence

- **no per-hunk search hits:** No 'markAsReviewed'/hunk-review constructs found elsewhere in multiDiffEditor or scm contributions that would provide hunk-level accept/undo for Agent Host sessions.
