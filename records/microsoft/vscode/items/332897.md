# Issue #332897 — PHP syntax highlighting breaks in embedded SQL strings with unmatched [ after escaped quote

[https://github.com/microsoft/vscode/issues/332897](https://github.com/microsoft/vscode/issues/332897)

## Summary

Verified duplicate root cause: the embedded SQL grammar's unmatched `[` bracket rule leaking past the PHP string boundary — the exact mechanism already tracked, with multiple corroborating reports, in the open canonical issue #221571 by the same author.

## Change summary

An unmatched `[` inside a PHP string that embeds SQL highlighting (e.g. starting with SELECT) leaves syntax highlighting corrupted for the rest of the file.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/221571 (open, labeled bug+grammar, same author, same underlying defect) — fixing the SQL-in-PHP embedding so an unclosed `[`...`]` bracketed-identifier scope from source.sql can't leak past the enclosing PHP string's end quote resolves both reports.

## Evidence

- **grammar trace:** extensions/php/syntaxes/php.tmLanguage.json 'sql-string-single-quoted' (begin ~line 3307) embeds source.sql inside PHP strings starting with SELECT/INSERT/UPDATE/DELETE/CREATE/REPLACE/ALTER/AND/WITH.
- **unmatched bracket rule:** extensions/sql/syntaxes/sql.tmLanguage.json lines 15-36 define a begin:'\[' / end:'\]' 'text.bracketed' rule for T-SQL bracketed identifiers; if no ']' appears before the PHP string's closing quote, this nested scope never closes and highlighting corruption bleeds into the rest of the file.
- **canonical issue:** https://github.com/microsoft/vscode/issues/221571 (open, labels bug+grammar, filed by the same reporter Daijobou) documents the identical mechanism via 'AND [' and other embedded-SQL triggers, with alexr00 identifying it as 'an issue with embedded SQL in php strings' and neerolyte confirming it 'breaks the syntax highlighting for the rest of the file'.
- **reporter's own working/non-working pairs:** The issue body's own examples (`'SELECT \'%[abcdef%]\''` works, `'SELECT \'%[abcdef\''` doesn't) confirm the trigger is specifically an unmatched `[` before string end, matching the bracketed-identifier rule exactly.
