# Issue #332897 — PHP syntax highlighting breaks in embedded SQL strings with unmatched [ after escaped quote

This is another reproduction of the embedded-SQL highlighting leak tracked by the verified open issue https://github.com/microsoft/vscode/issues/221571. Consolidate there while preserving this escaped-quote example.

## Change summary

An unmatched opening bracket inside a SQL-prefixed PHP string causes highlighting to continue past the PHP string's closing quote.

## Best solution

- **Maintainer diagnosis and independent confirmation:** https://github.com/microsoft/vscode/issues/221571#issuecomment-2244483670 identifies embedded SQL in PHP strings as the problem. https://github.com/microsoft/vscode/issues/221571#issuecomment-2357368626 independently reports highlighting leaking into subsequent PHP code and asks for a way to disable embedded SQL highlighting.
- **Shared trigger in current source:** extensions/php/syntaxes/php.tmLanguage.json:3307-3359 defines sql-string-single-quoted with the same keyword trigger for SELECT and AND, handles escaped quotes as escape tokens, and includes source.sql. Thus the reporter's escaped quote does not establish a nested SQL string; the following unmatched [ reaches the same SQL bracket rule as the canonical's AND examples.
- **Source-confirmed boundary leak:** extensions/sql/syntaxes/sql.tmLanguage.json:15-36 opens text.bracketed on [ and closes it only on ]. That nested state does not terminate on a PHP closing quote, preventing the enclosing PHP SQL-string end pattern from being considered until the bracket state ends. This explains both reports without executing code.
- **Distinct evidence retained:** https://github.com/microsoft/vscode/issues/332897 supplies a recent Windows Insiders reproduction with extensions disabled, an escaped single quote before the unmatched bracket, and controls showing that removing the SQL prefix or balancing the bracket avoids the leak. These strengthen the canonical report without establishing a separate defect.
