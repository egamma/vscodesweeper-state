# Issue #222062 — In code-server, disconnected processes eventually block forever on stdout/stderr PTY buffer

[https://github.com/microsoft/vscode/issues/222062](https://github.com/microsoft/vscode/issues/222062)

## Summary

Still reproduces on main: when a code-server client disconnects, the PTY flow control pauses the pty (unacknowledged chars exceed the high watermark) and never resumes it until a client reconnects and triggers replay. Child processes block on stdout/stderr during the disconnection window.

## Change summary

In code-server, disconnected terminal processes eventually block forever on stdout/stderr because the PTY flow control pauses the pty and no client is present to acknowledge data.

## Best solution

Call `clearUnacknowledgedChars()` (or equivalent resume) on the underlying `TerminalProcess` when `PersistentTerminalProcess.detach()` is called, so the PTY stays unpaused during the disconnection grace period. The scrollback serializer already captures data independently, so flow control is unnecessary when no renderer is connected. The fix is localized to `src/vs/platform/terminal/node/ptyService.ts` in the `detach()` method.
