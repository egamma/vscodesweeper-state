# Issue #222062 — In code-server, disconnected processes eventually block forever on stdout/stderr PTY buffer

[https://github.com/microsoft/vscode/issues/222062](https://github.com/microsoft/vscode/issues/222062)

## Summary

Keep open: a maintainer confirmed that disconnected terminal jobs stall, and current source still relies on browser acknowledgements despite recording output server-side. No verified fix or eligible older canonical was found.

## Change summary

Prevent retained terminal processes from blocking on stdout/stderr after the browser disconnects and output exceeds the flow-control window.

## Best solution

Retained server-side terminal sessions should continue consuming output into bounded scrollback while no browser is attached, without weakening connected-client backpressure or changing process-retention timeouts. Diagnose acknowledgement ownership across disconnect and reconnect before implementing the change.

## Evidence

- **Confirmed reproduction:** The reporter runs `while true; do date; done`, closes the browser, and observes a blocked PTY writer on Ubuntu 22.04 with VS Code 1.91.1 and extensions disabled. A maintainer independently reconfirmed on VS Code 1.96.0 and Ubuntu 24.04: https://github.com/microsoft/vscode/issues/222062#issuecomment-2549203752.
- **Current flow-control mechanism:** src/vs/platform/terminal/node/terminalProcess.ts:323-334 increments the unacknowledged character count and pauses node-pty above FlowControlConstants.HighWatermarkChars, currently 100000. Its acknowledgeDataEvent method resumes only after the count drops below the low watermark; server-side recording alone does not decrement that count.
- **Browser-dependent acknowledgements:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:_writeProcessData acknowledges output from the browser xterm write callback. RemotePty.acknowledgeDataEvent in src/vs/workbench/contrib/terminal/browser/remotePty.ts forwards those acknowledgements through the remote terminal channel. Closing the browser removes that consumer.
- **Recording does not drain flow control:** src/vs/platform/terminal/node/ptyService.ts:PersistentTerminalProcess records onProcessData through XtermSerializer.handleData, whose implementation calls headless xterm.write without acknowledging TerminalProcess. detach schedules process retention rather than transferring acknowledgement ownership; triggerReplay clears unacknowledged characters when replay occurs, not throughout the disconnected interval.

It concerns acknowledgements discarded during replay after reload, rather than output stalling while the browser remains disconnected.
