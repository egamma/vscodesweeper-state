# Issue #332008 — "Export Chat as Zip" doesn't work from remote session

[https://github.com/microsoft/vscode/issues/332008](https://github.com/microsoft/vscode/issues/332008)

## Summary

Team-authored bug report with a clear root cause traced in the checkout: the native Export Chat as Zip pipeline always treats the target save-dialog URI and file sources as local filesystem paths, so it breaks when the workspace is remote — this needs to be routed to the chat/native-host owners, not closed.

## Change summary

The 'Export Chat as Zip' command fails with ENOENT when run against a remote workspace, because the target path is written via the local Electron main process instead of the remote file system.

## Best solution

Fix src/vs/platform/native/electron-main/nativeHostMainService.ts#createZipFile (and its caller in src/vs/workbench/contrib/chat/electron-browser/actions/chatExportZip.ts) so the zip target/sources are validated or redirected through IFileService when the URI scheme isn't `file`, instead of unconditionally using `zipPath.fsPath` on the electron-main (local) process.

## Evidence

- **action calls native host directly:** src/vs/workbench/contrib/chat/electron-browser/actions/chatExportZip.ts:111 calls `nativeHostService.createZipFile(result, files)` where `result` is whatever URI `showSaveDialog` returns — which is a remote URI when the active workspace is remote.
- **main-process zip write assumes local fs:** src/vs/platform/native/electron-main/nativeHostMainService.ts:1494-1500 calls `zip(zipPath.fsPath, ...)` and `fs.promises.stat(zipPath.fsPath)` unconditionally — `.fsPath` on a `vscode-remote://` URI degenerates into a bogus local path (matching the reporter's `C:\workspaces\whatever-repo\chat.zip` ENOENT), because this code runs in the Electron main process which only has access to the local disk.
- **source files also assumed local:** same file, line 1456-1457: `if (source.scheme !== Schemas.file) { throw new Error('Cannot add non-local resource...') }` — so the implementation is fundamentally scoped to local-only sources/targets, with no remote-aware code path.
