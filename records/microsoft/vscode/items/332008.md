# Issue #332008 — "Export Chat as Zip" doesn't work from remote session

[https://github.com/microsoft/vscode/issues/332008](https://github.com/microsoft/vscode/issues/332008)

## Summary

Real bug, confirmed by tracing the source: 'Export Chat as Zip' lives in electron-browser and always writes through INativeHostService.createZipFile in the Electron main process, which operates on the local filesystem via zipPath.fsPath — it never routes through IFileService for remote targets, so a save-dialog path chosen in a remote/container window (e.g. `/workspaces/whatever-repo/chat.zip`) gets naively treated as a local path on the client machine, producing the mismatched `C:\workspaces\whatever-repo\chat.zip` error the reporter saw.

## Change summary

The 'Export Chat as Zip' command fails with an ENOENT error when run from a remote/container window because it writes the zip to the local client filesystem instead of the remote workspace.

## Best solution

In workbench.action.chat.exportAsZip (chatExportZip.ts), detect when the target save URI is non-local and either build the zip locally then copy the bytes to the remote target via IFileService, or otherwise bridge createZipFile's local-only assumption for remote windows.
