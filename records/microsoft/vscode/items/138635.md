# Issue #138635 — Codelens breaks bracket guides

[https://github.com/microsoft/vscode/issues/138635](https://github.com/microsoft/vscode/issues/138635)

## Summary

Bracket-pair guides still stop at CodeLens view zones in the current source. Keep this bracket-specific report open: the older indentation-guide issue shares the rendering limitation, but its verified scope does not establish coverage of this re-reviewed report.

## Change summary

CodeLens inserts gaps into otherwise continuous bracket-pair guides.

## Best solution

Render continuing bracket-pair guides through CodeLens spacing without extending them across unrelated embedded-editor or diff view zones. Coordinate with the existing indentation-guide work while preserving bracket-specific coverage.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/indentGuides/indentGuides.ts`, `src/vs/editor/browser/viewParts/indentGuides/indentGuides.css`, `src/vs/editor/browser/view/viewOverlays.ts`, `src/vs/editor/contrib/codelens/browser/codelensWidget.ts`, `src/vs/editor/browser/editorBrowser.ts`
- **Validation:** In an editor with nested bracket pairs and a CodeLens inside an enclosing pair, enable editor.guides.bracketPairs and editor.codeLens and verify that continuing guides remain connected across the lens spacing. Repeat after scrolling, folding/unfolding and toggling CodeLens; verify that Peek References and diff view zones do not acquire unwanted guide overlays. Establish a rendering regression check before implementation.
- **Behavior:**

  > With bracket-pair guides enabled, displaying a CodeLens inside a bracketed block must not interrupt a guide that continues above and below the lens. Guide positions and active/inactive colors must remain correct, and CodeLens text and commands must remain readable and interactive. Scrolling, folding and toggling CodeLens must not leave gaps or stale guide fragments. Unrelated embedded-editor and diff view zones must retain their existing presentation.
- **Trace:**

  > CodeLensWidget in src/vs/editor/contrib/codelens/browser/codelensWidget.ts registers a CodeLensViewZone with heightInPx before its source line. IndentGuidesOverlay.prepareRender in src/vs/editor/browser/viewParts/indentGuides/indentGuides.ts produces bracket guides as per-line overlay content; ViewOverlayLine in src/vs/editor/browser/view/viewOverlays.ts constrains each container to lineHeight, and indentGuides.css makes guide height relative to that container. This conclusively explains the unpainted CodeLens spacing in the current source. IViewZone in src/vs/editor/browser/editorBrowser.ts exposes geometry and DOM hooks but no explicit guide-rendering eligibility. The remaining investigation is how to associate continuing guides with eligible zone geometry without changing other shared view-zone consumers; that boundary has not been fully traced. Preserve CodeLens commands, bracket computation and unrelated zone presentation. The selective-zone distinction is supported by https://github.com/microsoft/vscode/issues/9604#issuecomment-240098460; that issue is related indentation work, not a verified bracket-specific duplicate target.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/138635 reports broken bracket guides with editor.guides.bracketPairs and editor.codeLens enabled on Windows 10 in VS Code 1.62.3; the screenshot supplies the observable rendering defect.
- **Current source path:** src/vs/editor/contrib/codelens/browser/codelensWidget.ts constructs CodeLensViewZone before the lens's source line and registers it with addZone. The zone reserves heightInPx and creates an empty DOM node, without rendering guides.
- **Guide height excludes CodeLens spacing:** IndentGuidesOverlay.prepareRender in src/vs/editor/browser/viewParts/indentGuides/indentGuides.ts emits bracket and indentation guides per text line. ViewOverlayLine.renderLine and layoutLine in src/vs/editor/browser/view/viewOverlays.ts size their containers to lineHeight; src/vs/editor/browser/viewParts/indentGuides/indentGuides.css sizes each guide to 100% of that container. Consequently the guides do not span the additional CodeLens view-zone height. This was traced without executing or modifying the checkout.
- **Older related issue is not a verified bracket canonical:** https://github.com/microsoft/vscode/issues/9604 is open and predates this report, but its body and discussion explicitly concern indentation guides. Its maintainer comment at https://github.com/microsoft/vscode/issues/9604#issuecomment-240098460 identifies CodeLens view zones as suitable for guide rendering while excluding embedded-editor and diff zones. Shared infrastructure alone does not establish full bracket-pair scope under the stronger re-review duplicate bar.
- **Canonical search:** Searches for bracket/CodeLens and guide/view-zone reports found no verified older open bracket-specific canonical. https://github.com/microsoft/vscode/issues/178487 describes the same bracket-guide interruption, but is newer and closed; its maintainer's /duplicate comment names no canonical target, so it cannot justify closing this report.
