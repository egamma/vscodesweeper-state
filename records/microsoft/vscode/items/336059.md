## Change summary

Markdown Preview does not scroll/reveal the clicked Search result's line when the preview is set as the default editor for .md files.

  > Thanks for the detailed report and repro steps. This is the same underlying platform gap tracked at https://github.com/microsoft/vscode/issues/289785 — the editor service doesn't pass a target selection/range through to webview-based custom editors (CustomTextEditorProvider/CustomEditorProvider) when navigation is triggered from Search, Go to Symbol, or a `#L` link fragment. The built-in Markdown Preview hits this because it's registered as `vscode.markdown.preview.editor`, a custom editor, so it only ever sees the document, not the click location. Consolidating there so the fix (passing selection into the resolve call) covers Markdown Preview too. I'll carry over that this specifically affects the built-in preview now that it can be the default `.md` editor, plus your note that Go to Symbol in Workspace and `#L` fragment links likely hit the same gap.

## Evidence

- **platform doesn't pass selection to webview editors:** src/vs/workbench/browser/parts/editor: applyTextEditorOptions (which applies IEditorOptions.selection) is only invoked from textCodeEditor.ts, textDiffEditor.ts, and textResourceEditor.ts — never from the webview/custom-editor pane path — confirming search's IEditorService.openEditor({options:{selection}}) (see searchView.ts:2253) has no route into a webview-based custom editor.
