## Summary

Keep open: manual archival still queues background commits that inherit Git signing configuration, explaining the delayed GPG prompts and repeated attempts. The source confirms the reported path; the intended noninteractive preservation behavior needs a maintainer decision.

## Change summary

## Best solution

  > Bulk marking sessions done currently causes delayed GPG prompts from background preservation commits, even though no active agent is committing. - **Trace:**

  > AgentSideEffects handles SessionIsArchivedChanged by queuing manual archives in 'commit' mode. AgentHostWorktreeCleanupService later invokes WorktreeIsolation.removeRecordedWorktree, which calls AgentHostGitService.commitAll for dirty worktrees with the exact message reported in https://github.com/microsoft/vscode/issues/349266. commitAll runs ordinary git commit --no-verify, so configured signing remains active; failed cleanup is retained and retried with backoff. Existing worktreeIsolation tests deliberately require preservation commits and retention when committing fails. The uncertainty is the desired preservation behavior when signing requires interaction, not the cause of the prompts. Keep automatic 'synced' cleanup safety, worktree recovery, and explicit commit signing outside any incidental behavior change.
- **Open decisions:**
  - When archival preservation would require signing interaction, should cleanup retain the dirty worktree without committing, or should archival offer an explicit user-authorized preservation action?
