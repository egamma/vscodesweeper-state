# Issue #329426 — Cannot Enable GitHub authentication Extention

[https://github.com/microsoft/vscode/issues/329426](https://github.com/microsoft/vscode/issues/329426)

## Summary

Traced a real logic bug on main: `throwErrorIfCannotChangeEnablement` in extensionEnablementService.ts blocks changing enablement of the GitHub Authentication extension unconditionally whenever it's the default-account or settings-sync auth provider — including re-enabling it once it ends up disabled (e.g. via an old synced state), which matches the reporter's exact symptom and workaround.

## Change summary

Once the GitHub Authentication extension gets disabled (e.g. via Settings Sync from an old profile), the Enable action is permanently greyed out and there is no way to turn it back on while sync is active.

## Best solution

In src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts, scope the `isDefaultOrSettingsSyncAuthProviderExtension` guard in `throwErrorIfCannotChangeEnablement` (and the workspace variant) to only block *disabling* an already-enabled provider, not re-enabling one that is currently disabled, so users aren't permanently stuck.
