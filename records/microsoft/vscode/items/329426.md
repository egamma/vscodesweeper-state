# Issue #329426 — Cannot Enable GitHub authentication Extention

[https://github.com/microsoft/vscode/issues/329426](https://github.com/microsoft/vscode/issues/329426)

## Summary

Traced to a real lockout in the enablement guard: `throwErrorIfCannotChangeEnablement` (and the `canChangeEnablement` check used by the UI) blocks changing enablement of an auth-provider extension whenever Settings Sync currently depends on it — but it applies this block symmetrically to both disabling AND enabling, so once the extension is (or arrives via synced state as) disabled, the user can never re-enable it through the UI while sync is on.

## Change summary

GitHub Authentication extension gets disabled via a synced extensions.json state, and the user cannot re-enable it afterward because Settings Sync depends on that provider.

## Best solution

In src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts, make the settings-sync-auth-provider guard direction-aware: it should only refuse a *disable* action, not an *enable* action, so a synced-disabled auth extension that sync currently depends on can be turned back on. `setEnablement`/`canChangeEnablement` currently call `throwErrorIfCannotChangeEnablement` without regard to `newState`.
