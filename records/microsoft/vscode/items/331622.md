# Issue #331622 — [2026 Dark Theme] Keyword color is too similar to function color

[https://github.com/microsoft/vscode/issues/331622](https://github.com/microsoft/vscode/issues/331622)

## Summary

Real, well-diagnosed bug: in the 2026 themes, TextMate scope specificity causes the inherited `keyword.control` rule from dark_plus.json/light_plus.json to override the theme's own generic `keyword` color, making keywords render close to the function color — and an open PR (#331643) already fixes it, so this should stay open pending review/merge, not be closed.

## Change summary

In the 2026 Dark (and Light) theme, keywords are visually too close in color to function names.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/331643, which adds `keyword.control` alongside `keyword` in 2026-dark.json/2026-light.json's own tokenColors so the theme's intended coral/red keyword color wins over the inherited magenta `keyword.control` rule.

## Evidence

- **theme file:** extensions/theme-defaults/themes/2026-dark.json defines `entity.name.function` as #d2a8ff and a generic `keyword` scope as #ff7b72 (line ~365-383).
- **root cause verified:** extensions/theme-defaults/themes/dark_plus.json (an ancestor in the 2026-dark → dark_modern → dark_plus include chain) defines its own `keyword.control` rule (line 77), which is more scope-specific than the 2026 theme's plain `keyword` rule and therefore wins for most real keyword scopes (e.g. `keyword.control.flow.python`).
- **open fixing PR:** https://github.com/microsoft/vscode/pull/331643 explicitly states 'Fixes #331622', diagnoses the same TextMate specificity collision, and proposes adding `keyword.control` to the theme's own tokenColors for both 2026-dark.json and 2026-light.json.
