# Issue #229152 — Enabling the `issueReporter.experimental.auxWindow` setting prevents Issue Reporter window from being focused

[https://github.com/microsoft/vscode/issues/229152](https://github.com/microsoft/vscode/issues/229152)

## Summary

The obsolete experimental setting was removed, but the underlying focus bug remains in the current classic Issue Reporter path: reopening it calls DOM `window.focus()`, which VS Code's own multi-window code documents as insufficient to raise Electron auxiliary windows.

## Change summary

Reinvoking Help: Report Issue while the auxiliary Issue Reporter is behind another window should bring that existing window to the foreground.

## Best solution

Keep the existing reporter state while bringing its auxiliary window to the foreground through the workbench host focus mechanism; the newer wizard editor path and reporter data should remain unchanged.
