# Issue #38834 — ANSI color support in edit buffer

[https://github.com/microsoft/vscode/issues/38834](https://github.com/microsoft/vscode/issues/38834)

## Summary

Keep open: current editor rendering does not interpret ANSI color sequences, and the extension previews discussed in the thread do not fully cover the requested edit-buffer experience. With 380 upvotes and an accepted Backlog placement, this warrants a product decision about editor integration rather than a cleanup close.

## Change summary

Render ANSI-colored files and piped output with their intended colors in the editor, without displaying escape sequences as ordinary text.

## Best solution

Define an opt-in ANSI-aware document experience that preserves the underlying file while providing readable colors and usable search and copy behavior. Decide whether that experience belongs in the text editor or a bundled preview; existing extension previews remain useful workarounds, not proof that the original request is satisfied.

## Plan brief

- **Likely files:** `src/vs/editor/common/viewLayout/viewLineRenderer.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/workbench/contrib/debug/browser/debugANSIHandling.ts`
- **Validation:** After choosing the product surface, open a file containing actual ESC-based foreground/background colors, reset sequences, and 24-bit colors. Verify readable rendered output, the agreed escape-sequence visibility, search across styled text, copy behavior, and byte-preserving save/reopen; confirm ordinary plain-text files are unchanged.
- **Behavior:**

  > Opening a file containing ANSI color escapes currently displays raw sequence text rather than the colored text requested in the issue. The desired experience makes ANSI-bearing logs readable without exposing escape sequences as visible clutter. Acceptance must cover search, selection and copying, and preservation of the underlying file on save/reopen. A separate preview satisfies some commenters, but the record does not establish that it replaces the original edit-buffer request.
- **Trace:**

  > In src/vs/editor/common/viewLayout/viewLineRenderer.ts, _renderLine renders characters and maps document columns; its control-character handling does not interpret ANSI sequences. editor.renderControlCharacters in src/vs/editor/common/config/editorOptions.ts is not an ANSI rendering mode. src/vs/workbench/contrib/debug/browser/debugANSIHandling.ts supplies handleANSIOutput for debug surfaces, including true-color parsing, but those callers do not provide an ANSI-aware document editor. The extension workarounds documented at https://github.com/microsoft/vscode/issues/38834 demonstrate preview feasibility while also documenting differences in copying, layout and search. The uncertainty starts at the product boundary: an interpreted edit buffer and a separate preview expose different editing and clipboard contracts. Preserve ordinary text editing and file contents; do not treat this as a request for full terminal emulation.
- **Open decisions:**
  - Should the supported experience interpret ANSI sequences inside the editable document, or provide a separate preview while retaining a raw-text editor?
  - How should ANSI interpretation be activated: an explicit command, a distinct language mode, or document detection?
  - What should copying interpreted text produce, and how should search treat hidden escape sequences?
  - Which styles are required initially: foreground/background colors including 24-bit RGB, or also bold, italic and other SGR formatting?
