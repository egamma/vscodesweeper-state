# Issue #115266 — Support minimap for native notebooks

[https://github.com/microsoft/vscode/issues/115266](https://github.com/microsoft/vscode/issues/115266)

## Summary

Notebook-wide minimap support remains missing, and this accepted Backlog request has substantial community demand. The related scroll-state API proposal enables possible extension implementations but does not deliver the requested feature or replace this issue.

## Change summary

Provide a minimap for navigating native notebook documents.

## Best solution

Design a notebook-wide minimap that supports meaningful navigation across cells while preserving notebook performance. Decide whether delivery belongs in the native editor or an extension enabled by the separately tracked scroll-state API.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`, `src/vs/workbench/contrib/notebook/browser/viewParts/notebookOverviewRuler.ts`, `src/vs/workbench/contrib/notebook/browser/viewModel/cellEditorOptions.ts`, `src/vs/workbench/contrib/codeEditor/browser/toggleMinimap.ts`, `src/vscode-dts/vscode.d.ts`
- **Validation:** After design approval, open a notebook containing multiple code and markdown cells plus tall outputs; verify that the chosen minimap can be enabled, reflects viewport changes during scrolling, and navigates to the represented location when clicked. Repeat after cell insertion, collapse, and output-height changes, and verify ordinary text-editor minimap behavior remains unchanged.
- **Behavior:**

  > Users want a minimap for the entire native notebook, rather than separate minimaps inside individual cell editors. The existing Toggle Minimap command does not currently deliver that capability. Acceptance should establish how users enable it and verify that viewport indication and navigation remain accurate across cells, tall outputs, and notebook layout changes. Which notebook content appears in the minimap requires an explicit product decision.
- **Trace:**

  > ToggleMinimapAction in src/vs/workbench/contrib/codeEditor/browser/toggleMinimap.ts changes editor.minimap.enabled, but BaseCellEditorOptions in src/vs/workbench/contrib/notebook/browser/viewModel/cellEditorOptions.ts disables minimaps in embedded cell editors. NotebookOverviewRuler in src/vs/workbench/contrib/notebook/browser/viewParts/notebookOverviewRuler.ts paints decoration markers, not notebook content. NotebookEditorWidget in src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts already exposes internal scroll position and navigation, whereas the public NotebookEditor interface in src/vscode-dts/vscode.d.ts exposes only cell-range navigation. https://github.com/microsoft/vscode/issues/311289 separately tracks a proposed pixel-level API and provides a reference extension lead; neither is a shipped minimap or a canonical duplicate. Preserve ordinary text-editor minimaps and notebook virtualization; do not treat enabling per-cell minimaps as satisfying the document-wide request. The uncertainty begins at the user-facing delivery surface and representation of markdown and outputs.
- **Open decisions:**
  - Should the notebook-wide minimap be native notebook UI or an extension-delivered feature supported by the separately tracked scroll-state API?
  - Should the minimap depict cell source only, or also rendered markdown and outputs, and how should tall outputs be represented?
  - Should the existing Toggle Minimap command and editor.minimap.enabled control notebook minimaps, or should notebooks have an independent enablement control?

## Evidence

- **Existing capability check:** src/vs/workbench/contrib/codeEditor/browser/toggleMinimap.ts registers editor.action.toggleMinimap, which only toggles editor.minimap.enabled. BaseCellEditorOptions in src/vs/workbench/contrib/notebook/browser/viewModel/cellEditorOptions.ts overrides that setting with minimap: { enabled: false }; its per-cell editor customizations do not provide a notebook-wide minimap.
- **Overview ruler is not a minimap:** src/vs/workbench/contrib/notebook/browser/viewParts/notebookOverviewRuler.ts renders proportional decoration markers using fillRect. It does not render a miniature view of notebook content, so the existing overview ruler does not satisfy the central request.
