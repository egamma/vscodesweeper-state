# Issue #336131 — Windows User Installer becomes corrupted after reboot with a pending background update

[https://github.com/microsoft/vscode/issues/336131](https://github.com/microsoft/vscode/issues/336131)

## Summary

Fresh, well-documented report of the Windows background updater leaving an installation unusable when Windows restarts mid-update; the reported setup-log behavior ("Skipping inno_updater.exe call because OS session is ending") matches the actual guardrail in build/win32/code.iss, so this is a real gap in the update/shutdown interaction, not a fluke.

## Change summary

When Windows restarts while a VS Code User Installer background update is staged but not yet applied, the setup process skips calling inno_updater.exe (to avoid running during shutdown) but this can leave the install with neither the old nor new application files intact, so VS Code can no longer launch.

## Best solution

Someone on the setup/build team needs to review the interaction between the session-end skip (SessionEndFileExists/`sessionend` flag) and the background-update file-swap step in build/win32/code.iss (and the inno_updater.exe binary, whose Rust source isn't in this checkout) so a skipped swap always leaves either the fully-old or fully-new installation intact, never a half-applied state; likely needs staging to a safe rollback point before any destructive step runs.
