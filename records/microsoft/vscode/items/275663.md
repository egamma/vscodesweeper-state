# Issue #275663 — Model picker needs to react to changes in model visibility in other windows

[https://github.com/microsoft/vscode/issues/275663](https://github.com/microsoft/vscode/issues/275663)

## Summary

The cross-window synchronization defect remains on current main: each language-model service reads profile visibility only during construction and updates its cache only for local writes. The issue is team-authored and the source conclusively confirms the reported behavior, so it should remain open for a bounded fix.

## Change summary

Model visibility changes made in one VS Code window should update model pickers and model consumers in other open windows without requiring a reload.

## Best solution

Keep the profile-scoped visibility state synchronized across windows and emit the existing model-visibility change event when another window changes that state, while preserving the current no-op behavior for unchanged values.
