# Issue #194759 — Fallback to default language if `files.associations` points to a invalid language

[https://github.com/microsoft/vscode/issues/194759](https://github.com/microsoft/vscode/issues/194759)

## Summary

The requested fallback is still missing: an association naming an unavailable language overrides the built-in YAML association and resolves to plain text. Keep this accepted Backlog request open; the remaining product question is how fallback should behave while extension languages are still registering.

## Change summary

Use the default file-language association when a matching files.associations entry names an unavailable language.

## Best solution

Allow files with unavailable configured languages to retain their normal built-in language support, while preserving valid explicit associations. Settle the extension-registration timing semantics before implementation.
