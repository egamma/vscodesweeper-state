# Issue #345833 — Copilot SDK agent sessions are lost after rebuilding a devcontainer

[https://github.com/microsoft/vscode/issues/345833](https://github.com/microsoft/vscode/issues/345833)

## Summary

Keep open: multiple users confirm session loss after container rebuilds, and a maintainer is actively considering durable storage. The discussion distinguishes actual transcript deletion from surviving transcripts becoming inaccessible when the session registry is recreated; neither is established as resolved.

## Change summary

Preserve Copilot SDK session history and discoverability across devcontainer rebuilds, matching Local sessions.

## Best solution

Give session registries, chat databases, and Copilot backing data a coordinated lifetime that survives container replacement. Follow the maintainer's persistence proposal while settling Docker-volume versus host-backed storage semantics; recovery of surviving orphaned data does not replace preventing deletion.

- **Likely files:** `src/vs/platform/agentHost/node/agentHostBootstrap.ts`, `src/vs/platform/agentHost/node/sessionDataService.ts`, `src/vs/platform/environment/common/copilotHome.ts`, `src/vs/platform/environment/node/copilotHomeService.ts`
- **Validation:** In a devcontainer whose home directory is replaced on rebuild, create SDK and Local sessions, exchange messages, rebuild and reopen, then verify both remain listed with intact history and that the SDK conversation can continue. Separately test preserved transcripts with a recreated registry, and verify isolation between two containers. Do not execute these checks in this read-only review.
- **Behavior:**

  > Rebuilding and reopening a devcontainer must preserve existing Copilot SDK sessions, their messages, and their ability to continue, as it does for Local sessions. The report includes both physical deletion of backing data and loss of discoverability when only some storage roots survive. Acceptance must cover the ordinary rebuild workflow without requiring users to hand-edit mounts, and must preserve separation between unrelated containers.
- **Trace:**

  > Agent Host bootstrap constructs the registry at appSettingsHome/globalStorage/agent-host.db and chat storage through SessionDataService under userDataPath/agentSessionData. CopilotHomeService independently resolves COPILOT_HOME or the executing user's .copilot directory. The thread at https://github.com/microsoft/vscode/issues/345833 confirms that these locations can have different rebuild lifetimes and records a maintainer proposal to persist them together. The trace establishes the storage consumers, not the Dev Containers extension's mount-provisioning implementation; that integration boundary still needs investigation. Preserve existing session identities and history formats, and do not equate repairing a surviving registry gap with recovering files that were deleted.
- **Open decisions:**
  - Should durable session storage default to a per-container Docker volume or host-backed storage, and should the alternative be user-selectable?
  - What retention and deletion guarantees should users expect for persisted sessions when containers or their associated volumes are explicitly removed?
