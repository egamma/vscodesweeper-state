# Issue #345833 — Copilot SDK agent sessions are lost after rebuilding a devcontainer

[https://github.com/microsoft/vscode/issues/345833](https://github.com/microsoft/vscode/issues/345833)

## Summary

Keep open: an independent commenter confirms disappearance even when conversation storage survives the rebuild. Current source supports the registry-recovery gap; the maintainer's explanation about container-local storage does not resolve that case.

## Change summary

Copilot SDK sessions disappear after rebuilding a devcontainer, including when transcripts survive but the session registry does not.

## Best solution

Establish a coherent persistence contract for container-hosted Agent Host sessions and recover retained conversations when their registry is recreated. Distinguish recoverable registry loss from deletion of the underlying SDK history.

- **Likely files:** `src/vs/platform/agentHost/node/agentHostBootstrap.ts`, `src/vs/platform/agentHost/node/sessionDataService.ts`, `src/vs/platform/agentHost/node/agentSessionRegistry.ts`, `src/vs/platform/agentHost/node/agentHostCatalogReconciliationService.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`
- **Validation:** Using disposable test storage, create a Copilot SDK conversation, retain its conversation databases and SDK state, recreate only the central registry, and restart with fresh host instances. Verify the agreed recovery behavior preserves history and identity without exposing internal chat backings. Separately repeat the issue's container rebuild comparison with Local sessions.
- **Behavior:**

  > After a devcontainer rebuild, Copilot SDK conversations can disappear while Local conversations remain available. An independent report demonstrates a recoverable variant where conversation files survive but the central registry is recreated. Retained conversations should have a supported path back to usable history without manual database editing. Acceptance must distinguish registry-only loss from a rebuild that deletes all underlying conversation data.
- **Trace:**

  > Agent Host bootstrap opens globalStorage/agent-host.db separately from SessionDataService's agentSessionData directory. AgentSessionRegistry.list enumerates central registrations, while CopilotAgent._discoverCopilotChats deliberately excludes SDK sessions identified as Agent Host-created. This supports the reported discovery gap but does not establish that blindly importing SDK entries would preserve original session identities or multi-chat membership. Existing reconciliation operates over registered sessions and central receipts. Preserve provider ownership, internal-backing suppression, and deletion exclusions. The confirmed retained-data case is documented at https://github.com/microsoft/vscode/issues/345833#issuecomment-6654708638; its manual reconstruction procedure was not executed or independently validated. Uncertainty remains at the intended persistence guarantee across container replacement and the user-visible recovery contract.
- **Open decisions:**
  - Should default container rebuilds preserve Copilot SDK conversations without user-configured storage mounts, matching Local sessions?
  - When conversation data survives but the central registry is missing, should recovery restore sessions automatically or require an explicit recovery action?
