# Issue #345833 — Copilot SDK agent sessions are lost after rebuilding a devcontainer

[https://github.com/microsoft/vscode/issues/345833](https://github.com/microsoft/vscode/issues/345833)

## Summary

Keep open: multiple users confirm session loss after container rebuilds, and a maintainer is considering persistent Docker-volume storage. The existing area labels are appropriate; preserving transcripts alone does not address the separately stored session registry.

## Change summary

Preserve Copilot SDK session history and discoverability across devcontainer rebuilds, matching Local sessions.

## Best solution

Provide coordinated persistence for the Agent Host registry, conversation databases, and Copilot-native state across container rebuilds. Follow the maintainer's proposed volume-based direction and distinguish prevention of deleted data from recovery of surviving but unregistered sessions.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentHostBootstrap.ts`, `src/vs/platform/agentHost/node/sessionDataService.ts`, `src/vs/platform/environment/node/copilotHomeService.ts`
- **Validation:** In a disposable devcontainer, create SDK and Local sessions with messages, rebuild and reopen, then verify both remain listed with readable history and can accept another turn. Repeat with Stable and Insiders storage paths; separately exercise preserved transcripts with a missing registry to establish the recovery contract.
- **Behavior:**

  > Rebuilding and reopening a devcontainer must preserve existing Copilot SDK sessions, including their history and their presence in the session list. Local sessions must retain their existing behavior. Acceptance requires reopening a pre-rebuild SDK conversation, reading its prior messages, and successfully continuing it. Distinguish preventing future deletion from recovering data that already survived without its registry.
- **Trace:**

  > Agent Host bootstrap constructs the registry at appSettingsHome/globalStorage/agent-host.db and conversation storage through SessionDataService under userDataPath/agentSessionData. CopilotHomeService resolves a separate Copilot-native storage root. The discussion at https://github.com/microsoft/vscode/issues/345833 confirms both complete container-local data deletion and partial persistence that leaves transcripts without their registry. The maintainer proposes coordinated per-container Docker-volume storage, but the container creation/mount integration and existing-container migration path were not traced in this checkout. Preserve provider identities, session relationships, and Local-session behavior; do not treat registry repair alone as a fix for deleted native data.
- **Open decisions:**
  - Should automatic persistence apply to existing devcontainers on their next rebuild as well as newly created containers, and what should users observe when explicit mounts already cover some storage paths?
  - Does the initial delivery include recovery of surviving session databases when the registry is missing, or only prevention of future loss?
