# Issue #340483 — Agent Host: MCP servers without protected-resource metadata can never authenticate (empty `authorization_servers` in fallback)

[https://github.com/microsoft/vscode/issues/340483](https://github.com/microsoft/vscode/issues/340483)

## Summary

Thanks for the detailed report. The defect is still present on main. When an MCP server publishes no protected-resource metadata, the Agent Host fallback omits `authorization_servers`, and the renderer loops over `authorization_servers ?? []`, so no provider is ever tried.

## Change summary

Agent Host MCP auth never resolves for OAuth servers without RFC 9728 protected-resource metadata, because the fallback resource has no authorization servers.

## Best solution

In `_protectedResourceFromMcpAuthRequest`, default `authorization_servers` to the server URL's origin when there is no valid metadata, matching the MCP spec and Local-harness behavior. The renderer should also log when no authorization server is available instead of silently doing nothing.
