# Issue #340483 — Agent Host: MCP servers without protected-resource metadata can never authenticate (empty `authorization_servers` in fallback)

[https://github.com/microsoft/vscode/issues/340483](https://github.com/microsoft/vscode/issues/340483)

## Summary

Confirmed from source: Agent Host's protected-resource fallback omits `authorization_servers`, so both the MCP OAuth resolver and the background credential resolver silently no-op for servers lacking RFC 9728 metadata — a real, bounded bug worth fixing.

## Change summary

MCP servers that don't publish protected-resource metadata can never authenticate through the Agent Host (Copilot harness), because the fallback resource object omits `authorization_servers`.

## Best solution

Have `_protectedResourceFromMcpAuthRequest` in copilotAgentSession.ts include `authorization_servers: [new URL(serverUrl).origin]` in its fallback (mirroring the Local/extension-host path in extHostMcp.ts), so the renderer's resolvers in agentHostAuth.ts have something to iterate.
