# Issue #154063 — Support Markdown hovers for CodeLens

[https://github.com/microsoft/vscode/issues/154063](https://github.com/microsoft/vscode/issues/154063)

## Summary

Keep open: current main still exposes only plain-text CodeLens tooltips, and the request has met the community threshold with 27 upvotes. No verified canonical or open implementation PR was found; the existing API and CodeLens labels already route it appropriately.

## Change summary

Allow extension-provided CodeLens hovers to display rich Markdown rather than plain text.

## Best solution

Provide an extension API for Markdown content on CodeLens hovers, rendered consistently with other editor hovers while preserving existing plain-text tooltips and command execution. Settle whether that capability belongs on CodeLens specifically or on the shared Command contract before implementation.

Add automated coverage for the chosen public contract, extension-host conversion, and hover rendering.
- **Behavior:**

  > Extensions should be able to display rich Markdown when users hover a CodeLens, without adding a separate text decoration. The capability should work for commands returned directly by provideCodeLenses and commands supplied by resolveCodeLens. Existing string tooltips and CodeLens command execution must remain compatible. Acceptance includes formatted content on the actual lens and unchanged behavior for existing providers.
- **Trace:**

  > The public CodeLens in src/vscode-dts/vscode.d.ts carries a Command whose tooltip is string-only; the internal Command in src/vs/editor/common/languages.ts has the same limitation. CodeLensAdapter in src/vs/workbench/api/common/extHostLanguageFeatures.ts passes both immediate and resolved commands through CommandsConverter.toInternal in src/vs/workbench/api/common/extHostCommands.ts. CodeLensContentWidget.withCommands in src/vs/editor/contrib/codelens/browser/codelensWidget.ts places that tooltip in a native title attribute for both links and spans. DecorationOptions.hoverMessage already supports Markdown, but that separate text-hover surface does not satisfy https://github.com/microsoft/vscode/issues/154063. Preserve CodeLens placement, provider resolution behavior, command semantics, and existing plain-text compatibility. The remaining product decision is the scope of the public Markdown contract; the current evidence does not settle whether other Command consumers should gain it.
- **Open decisions:**
  - Should Markdown hover content be a CodeLens-specific API capability, or should the shared Command.tooltip contract accept MarkdownString and establish expectations for its other UI consumers?
