# Issue #331477 — Agents window: disable-model-invocation: true prevents manual slash invocation of Agent Skills

[https://github.com/microsoft/vscode/issues/331477](https://github.com/microsoft/vscode/issues/331477)

## Summary

Well-diagnosed, independently reproduced bug: in the Agents window, a skill with `disable-model-invocation: true` shows up in the `/` menu but silently fails to load on explicit manual invocation, falling back to treating the slash text as a plain prompt — while the same skill works fine in regular Copilot Chat. Already labeled `agents-window`; keeping open for a maintainer/engineer to trace the Agent Host's skill dispatch path.

## Change summary

Agent Skills marked `disable-model-invocation: true` can't be manually invoked via `/skill-name` in the Agents window, even though they still appear in autocomplete and work fine in regular Copilot Chat.

## Best solution

Trace why the Agent Host's manual slash-command dispatch treats a `disable-model-invocation: true` skill as unavailable — VS Code only forwards `skillDirectories` to `@github/copilot-sdk` (src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts, toSdkSkillDirectories), so the enforcement of model-vs-user invocation happens inside the SDK's slash-command handling; the fix may need to land in @github/copilot-sdk itself, or in how the Agent Host forwards the explicit `/command` request. At minimum the silent fallback (treating the missed invocation as an ordinary prompt with no error) should be fixed regardless of where the root cause lives.
