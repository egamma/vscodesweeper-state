# Issue #331477 — Agents window: disable-model-invocation: true prevents manual slash invocation of Agent Skills

[https://github.com/microsoft/vscode/issues/331477](https://github.com/microsoft/vscode/issues/331477)

## Summary

Real, independently reproduced bug in the Agents window: a skill marked `disable-model-invocation: true` correctly still appears in the `/` menu, but explicit manual invocation silently fails to load it (falling back to treating the text as a plain prompt), unlike regular Copilot Chat where manual invocation still works. A VS Code contributor confirmed this on Insiders and merged a duplicate report into this thread, so this is the right consolidation point — keeping it open for the Agent Host / skill-invocation fix.

## Change summary

In the Agents window, explicitly invoking (`/skill-name`) an Agent Skill that has `disable-model-invocation: true` does not load/execute the skill, even though the same manual invocation works in regular Copilot Chat.

## Best solution

Fix the Agent Host / Copilot agent invocation path so `disableModelInvocation` only suppresses automatic model-initiated use and not explicit user slash invocation — likely in the skill materialization/dispatch logic used by src/vs/platform/agentHost/node/copilot/copilotAgent.ts (toSkillInvocationFlags/mapToParsedPlugin) or the underlying Copilot CLI/SDK it drives, which isn't visible in this checkout; also add explicit UI feedback when a slash invocation is skipped instead of silently falling back to a plain prompt (per digitarald's comment).
