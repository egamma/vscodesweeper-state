# Issue #331477 — Agents window: disable-model-invocation: true prevents manual slash invocation of Agent Skills

[https://github.com/microsoft/vscode/issues/331477](https://github.com/microsoft/vscode/issues/331477)

## Summary

Freshly filed, well-diagnosed report with a plausible, traceable code gap in the Agent Host skill-parsing pipeline, but I can't confirm from this checkout alone whether the actual manual-invocation gate lives here or in the external Copilot CLI/agent SDK — keeping open for a maintainer with SDK visibility.

## Change summary

In the Agents window, a skill with `disable-model-invocation: true` shows in the `/` menu but fails to load when manually invoked, even though the same skill invokes fine via slash command in regular Copilot Chat.

## Best solution

Wire `disable-model-invocation` (and `user-invocable`) through the skill-parsing pipeline the same way `parseAgentFile`/`resolveAgentDisableModelInvocation` already do for agents — src/vs/platform/agentPlugins/common/pluginParsers.ts's `parseSkillFile`/`readSkills`/`makeSkillCustomization` never read or propagate `disable-model-invocation` into `SkillCustomization`, even though the protocol type (channels-session/state.ts:953-971) already defines `disableModelInvocation`/`disableUserInvocation` for skills and nothing in src/vs/platform/agentHost consumes them. Also confirm whether the harness (Copilot CLI/agent SDK, reached via `toSdkSkillDirectories`, which hands over raw skill directories) is what actually gates manual invocation from the SKILL.md frontmatter directly — if so, the real fix belongs in that external SDK, not this repo.

## Evidence

- **unwired skill field:** src/vs/platform/agentHost/common/state/protocol/channels-session/state.ts:953-971 defines `SkillCustomization.disableModelInvocation`/`disableUserInvocation`, but `parseSkillFile` (pluginParsers.ts:1175-1186) only extracts `name`/`description`/`user-invocable` and never reads `disable-model-invocation`; `makeSkillCustomization` (pluginParsers.ts:326-335) never sets these fields.
- **agent parity gap:** The equivalent agent path (`parseAgentFile` + `resolveAgentDisableModelInvocation`, pluginParsers.ts:1151-1172, and `makeAgentCustomization`, pluginParsers.ts:311-324) correctly parses and forwards `disable-model-invocation`/`infer`, but no analogous wiring exists for skills.
- **no consumers found:** `grep -rn 'disableModelInvocation' src/vs/platform/agentHost` shows the field is only ever set/read for AgentCustomization, never for SkillCustomization — confirming the flag currently has zero effect on skill behavior anywhere in this repo's own code.
- **completion provider ignores gating:** src/vs/platform/agentHost/node/agentHostSkillCompletionProvider.ts lists every skill child customization for slash completions without consulting `disableUserInvocation`/`disableModelInvocation` at all, consistent with the reporter's observation that the skill still appears in the `/` menu.
