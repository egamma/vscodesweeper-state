# Issue #288873 — Line breaks incorrectly when variable font size

[https://github.com/microsoft/vscode/issues/288873](https://github.com/microsoft/vscode/issues/288873)

## Summary

Still reproduces on main: the monospace line breaks computer does not account for per-token font size multipliers from `editor.tokenColorCustomizations`, so lines with enlarged tokens overflow past the wrap column. The related PR #300915 was closed without merging, and no fix has landed. Team-authored issue — keeping open.

## Change summary

Word wrap does not account for variable font sizes set via `editor.tokenColorCustomizations`, causing lines with enlarged tokens to overflow the wrap column.

## Best solution

The monospace line breaks computer (`src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts`) needs to scale character widths by the font-size multiplier during the column-scanning loop. The closed PR #300915 sketched this approach (monospace computer only); the DOM-based advanced wrapping strategy would need a separate pass. The fix should also recompute line breaks when font decorations arrive asynchronously after tokenization.
