# Issue #317483 — vscode.FileDecorationProvider in git extension is too greedy in applying file decorations to URIs

[https://github.com/microsoft/vscode/issues/317483](https://github.com/microsoft/vscode/issues/317483)

## Summary

The built-in Git ignore decoration provider still matches unrelated URI schemes by filesystem path, allowing ignored-file coloring to leak into extension tree items. This remains actionable and should be routed to the Git area.

## Change summary

Prevent Git file decorations from applying to extension-defined resource URIs solely because they share a filesystem path.

## Best solution

Keep Git ignore decorations scoped to resources Git owns, without changing legitimate file or Git-resource decorations. Address the path-only matching in the built-in Git ignore provider rather than changing decoration precedence across extensions.

## Evidence

- **Current source confirms the leaking path:** In extensions/git/src/decorationProvider.ts, GitIgnoreDecorationProvider.provideFileDecoration() accepts any URI scheme, calls model.getRepository(uri), and queues uri.fsPath. checkIgnoreSoon() returns gitDecoration.ignoredResourceForeground whenever that path is ignored, including for an unrelated custom-scheme URI.
- **Repository lookup does not reject custom schemes:** extensions/git/src/model.ts:929–1000 shows getRepository() delegating to getOpenRepository(). The URI branch special-cases git URIs but otherwise uses hint.fsPath and repository-path containment, so a custom URI pointing into an open repository reaches the ignore provider.
- **Bounded provider distinction:** GitDecorationProvider and GitIncomingChangesFileDecorationProvider in extensions/git/src/decorationProvider.ts already key their decoration maps by full URI strings. The path-only behavior is specifically in GitIgnoreDecorationProvider; GitDecorations registers this provider independently of git.decorations.enabled.
- **Independent confirmation:** The reporter identifies the built-in Git extension and reports that disabling it removes the interference. A second extension developer confirms the same problem at https://github.com/microsoft/vscode/issues/317483#issuecomment-4599557698.
- **Decoration composition:** src/vs/workbench/api/common/extHostDecorations.ts forwards resource URIs to registered providers. src/vs/workbench/services/decorations/browser/decorationsService.ts combines returned decorations and chooses foreground colors from the resulting list, so an incorrectly returned Git ignore color can interfere with another provider's resource coloring.
