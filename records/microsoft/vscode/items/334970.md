# Issue #334970 — MCP client triggers confusing "does not support automatic client registration" OAuth dialog for servers using only static headers (non-OAuth), e.g. on an expired credential

[https://github.com/microsoft/vscode/issues/334970](https://github.com/microsoft/vscode/issues/334970)

## Summary

Confirmed in source: the MCP client's OAuth discovery/DCR fallback is triggered by status code alone, with no check for whether the server config already has static headers and no `oauth` block, so an expired static credential surfaces a confusing OAuth client-registration dialog instead of a plain auth failure.

## Change summary

MCP servers configured with only static headers (no OAuth) show the OAuth 'does not support automatic client registration' dialog on any 401/403, e.g. an expired header token.

## Best solution

In extHostMcp.ts's _fetchWithAuthRetry, skip OAuth discovery/DCR when the server launch config has no `oauth` block and already sends static Authorization/auth headers; surface a plain auth failure (and ideally re-prompt the relevant `${input:...}` value) instead.
