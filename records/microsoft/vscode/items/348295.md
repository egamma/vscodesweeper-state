# Issue #348295 — Tree view: reveal() while the tree is loading or refreshing can drop the UI's children fetch (node stays empty), reject with 'Data tree node not found', or silently do nothing

[https://github.com/microsoft/vscode/issues/348295](https://github.com/microsoft/vscode/issues/348295)

## Summary

Keep open: current source confirms that reveal can supersede an in-flight children request, leaving the renderer with a persistently empty node. The recent renderer batching changes do not eliminate this extension-host race.

## Change summary

Make TreeView.reveal coordinate with loading and refreshing so children remain visible and valid targets are reliably revealed.

## Best solution

Ensure overlapping reveal and children-loading operations preserve valid results through the extension-host and renderer caches. Address deferred-refresh ordering without changing unrelated tree consumers or silently treating an unsuccessful reveal as successful.
