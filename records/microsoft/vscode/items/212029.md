# Issue #212029 — Run command on save feature

[https://github.com/microsoft/vscode/issues/212029](https://github.com/microsoft/vscode/issues/212029)

## Summary

This is established extension territory: VS Code already exposes save events, and maintainers previously declined the same core capability in favor of watch tasks or extensions. The strong community support demonstrates demand but does not overcome the existing scope and performance guidance.

## Change summary

Run configurable shell commands for selected file types whenever matching files are saved.

## Best solution

Provide this through a run-on-save extension using `workspace.onDidSaveTextDocument`, or use a toolchain-native watch task for continuous builds. A standardized repository manifest should remain outside VS Code core unless independently designed and adopted with a robust trust model.

## Vision fit

- **Fit:** rejected
- **Reason:** The extension API already supports implementing this specialized automation, while executing processes on every save adds security, performance, and configuration costs to the default product.
- **Evidence:** Values and guardrails: “The power lives in extensions,” “Performance trumps functionality,” and capabilities implementable through existing extension APIs generally belong in extensions.

  > Thanks for the request and the thoughtful security discussion. VS Code already exposes `workspace.onDidSaveTextDocument`, so this workflow can be implemented by an extension, and run-on-save extensions are available today. The same core capability was previously evaluated in https://github.com/microsoft/vscode/issues/2159 and https://github.com/microsoft/vscode/issues/148617; maintainers favored toolchain-native watch tasks or extensions because repeatedly launching commands on save carries performance, battery, and trust costs. Given that precedent, this is best treated as an extension candidate.
