# Issue #144423 — suggest list hover view shouldn't appear border

[https://github.com/microsoft/vscode/issues/144423](https://github.com/microsoft/vscode/issues/144423)

## Summary

The discussion identifies a credible intermittent visual defect: when the suggest widget is created or repositioned beneath a stationary pointer, its resize sash can immediately render hover feedback even though the pointer never moved over it. No verified duplicate or evidence of a fix is present, so this should remain open in the suggest backlog.

## Change summary

Prevent the suggest widget's resize sash from showing hover-border feedback merely because the widget appeared beneath a stationary mouse pointer.

## Best solution

Adjust the shared sash hover activation or the suggest widget's sash lifecycle so hover feedback requires genuine pointer interaction after the widget appears, while preserving normal resize affordance when users intentionally move onto the sash.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/sash/sash.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidget.ts`
- **Validation:** Add or identify a browser UI test that places a stationary pointer at the future suggest-widget sash position, opens/repositions the widget, and verifies no hover styling appears until a pointer-move event; then verify normal sash hover and drag behavior still works.
- **Behavior:**

  > Opening or repositioning the suggest widget beneath a stationary mouse pointer must not immediately show the resize-sash hover border. Moving the pointer onto the sash afterward must still reveal the resize affordance, and dragging must continue to resize the widget normally. Acceptance should cover both the stationary-pointer case and ordinary hover/drag behavior.
- **Trace:**

  > The issue discussion identifies the border as shared resize-sash hover feedback, not a normal suggest-widget border: https://github.com/microsoft/vscode/issues/144423#issuecomment-1059721124. The failure occurs when widget geometry moves the sash beneath an already-stationary pointer, so investigation should trace hover activation in `src/vs/base/browser/ui/sash/sash.ts` and suggest-widget sash creation/layout in `src/vs/editor/contrib/suggest/browser/suggestWidget.ts`. A maintainer noted uncertainty about detecting this safely at https://github.com/microsoft/vscode/issues/144423#issuecomment-1060880885. Preserve hover feedback after actual pointer movement and all drag/resize behavior; do not broadly suppress sash hover across other widgets without checking shared consumers.
