## Change summary

Ctrl/Cmd-clicking a changed file in the Source Control view should open the full editable file instead of the diff.

## Best solution

Extend the tree's open handler in scmViewPane.ts to check for ctrlKey/metaKey (mirroring the existing middle-click check for opening the multi-diff editor) and route to the file-opening command instead of the diff command when the modifier is held.

- **Behavior:**

  > Ctrl+click (Windows/Linux) or Cmd+click (macOS) on a changed file row in the Source Control view should open the working-tree file in a normal editor, while a plain click continues to open the diff. Middle-click behavior (opening the multi-diff editor) is unaffected.
- **Trace:**

  > The tree's open() handler in src/vs/workbench/contrib/scm/browser/scmViewPane.ts (isSCMResource branch, ~line 1708) currently checks only `isPointerEvent(e.browserEvent) && e.browserEvent.button === 1` for an alternate open path; there is no check for ctrlKey/metaKey. The file-opening command (`git.openFile` in extensions/git/src/commands.ts) already exists and could be invoked from that branch. Boundary: don't touch the middle-click multi-diff path or the default diff-open behavior for a plain click.
- **Open decisions:**
  - Should this apply uniformly across all SCM providers (not just Git), and does it need SCM-API-level support, or is it fine to special-case within the core SCM view using the existing open/diff command distinction already present on ISCMResource?
