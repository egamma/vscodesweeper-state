# Issue #320110 — Copilot Chat fails to process images with third-party OpenAI-compatible models (DeepSeek V4): unknown variant image_url, expected text

[https://github.com/microsoft/vscode/issues/320110](https://github.com/microsoft/vscode/issues/320110)

## Summary

The failing wire-format conversion is owned by the installed third-party OAI Compatible Provider, not VS Code core. Core passes image bytes to language-model providers as `LanguageModelDataPart`; the provider constructs the reported `image_url` request.

## Change summary

Make images pasted into Copilot Chat work with DeepSeek V4 models supplied by an OpenAI-compatible provider.

## Best solution

Handle DeepSeek's multimodal request requirements in https://github.com/JohnnyZ93/oai-compatible-copilot, or use VS Code's built-in Custom OpenAI-compatible provider instead.

## Evidence

- **core provider boundary:** On current main, extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts:339-360 converts internal image content into `vscode.LanguageModelDataPart` before invoking an extension-contributed language-model provider.
- **extension-host conversion:** src/vs/workbench/api/common/extHostTypeConverters.ts:2466-2486 maps internal `image_url` content to `LanguageModelDataPart`, so the proprietary internal representation is not exposed as the provider's wire request.
- **third-party serializer:** The installed `johnny-zhao.oai-compatible-copilot` extension is sourced at https://github.com/JohnnyZ93/oai-compatible-copilot; its `src/openai/openaiApi.ts` consumes `LanguageModelDataPart` and constructs `{ type: "image_url", image_url: { url } }` itself.
- **provider tracker:** https://github.com/JohnnyZ93/oai-compatible-copilot/issues/235 documents that this extension owns image conversion and forwards its generated `image_url` objects to OpenAI-compatible endpoints.
