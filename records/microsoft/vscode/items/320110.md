## Summary

Decline close (out-of-scope) gated off: the issue carries `bug` and sits in Backlog — the owner already triaged it as accepted work. Original assessment: The failing request is produced by the third-party OAI Compatible Provider for Copilot extension, not by VS Code's image transport. Both current main and the provider's source at the report date show VS Code delivering a typed image data part and the provider converting it to the OpenAI `image_url` wire format, so endpoint/model compatibility belongs in that extension's tracker.

## Change summary

Make image attachments work with DeepSeek V4 models registered through a third-party OpenAI-compatible provider.

## Best solution

Handle DeepSeek's accepted multimodal request shape and model capability declaration in the OAI Compatible Provider for Copilot extension, while retaining VS Code's provider-neutral `LanguageModelDataPart` contract.
