## Summary

This failure is in the externally maintained OAI Compatible Provider for Copilot or its configured endpoint, not VS Code's image-handling path. The provider owns conversion from VS Code language-model data parts to the selected API protocol.

## Change summary

- **VS Code API boundary:** Current VS Code source exposes images to language-model providers as `LanguageModelDataPart` (`src/vscode-dts/vscode.d.ts`) and forwards these parts to the registered provider in `src/vs/workbench/api/common/extHostLanguageModels.ts`; core does not select that provider's wire protocol.
- **extension conversion:** The provider's `src/openai/openaiApi.ts` consumes `LanguageModelDataPart` image parts and constructs OpenAI-compatible `{ type: "image_url", image_url: { url } }` content, placing protocol conversion and endpoint compatibility in the external extension.
- **provider tracker precedent:** https://github.com/JohnnyZ93/oai-compatible-copilot/issues/235 tracks another image-request conversion problem in the same provider and identifies its OpenAI adapter files as the fix location.
- **independent confirmation:** https://github.com/microsoft/vscode/issues/320110#issuecomment-4634407389 confirms the symptom with DeepSeek V4 Pro, but does not establish a defect in VS Code's provider API boundary.
