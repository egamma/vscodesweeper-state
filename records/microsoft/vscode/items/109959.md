# Issue #109959 — Horizonal Scrolling through pointer on scroll bar

[https://github.com/microsoft/vscode/issues/109959](https://github.com/microsoft/vscode/issues/109959)

## Summary

The requested interaction remains absent on current main: a vertical wheel event over the horizontal scrollbar still scrolls vertically unless Shift is held. No open canonical issue was found, so this should remain open for an explicit interaction-design decision.

## Change summary

Make vertical mouse-wheel input scroll horizontally when the pointer is over the editor's horizontal scrollbar.

## Best solution

Define consistent wheel-over-scrollbar behavior in the shared scrollbar widget, preserving ordinary editor scrolling while allowing the scrollbar under the pointer to determine the intended axis.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts`, `src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts`
- **Validation:** Add a scrollable-element browser test showing that a vertical wheel event targeting the horizontal scrollbar changes scrollLeft but not scrollTop, while the same event over content retains existing vertical scrolling; run the targeted scrollableElement test suite.
- **Behavior:**

  > When the pointer is over a visible horizontal scrollbar, rotating a standard vertical mouse wheel should move the content horizontally without requiring Shift. The same wheel input over editor content must continue to scroll vertically, and native horizontal-wheel or trackpad input must remain unchanged. Acceptance should cover both target locations and verify that only the intended scroll axis changes.
- **Trace:**

  > The editor constructs a SmoothScrollableElement in src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts. Its shared `_onMouseWheel` path in src/vs/base/browser/ui/scrollbar/scrollableElement.ts maps vertical input to horizontal only for `scrollYToX` or non-macOS Shift-wheel; although the horizontal scrollbar is a child of the listening DOM node, event-target location is not considered. The existing `scrollYToX` option is enabled for breadcrumbs but not the editor and applies globally rather than only over a scrollbar. The boundary is shared scrollbar input semantics: ordinary editor wheel scrolling, Shift-wheel behavior, touchpad deltas, and consumers intentionally using `scrollYToX` must not regress. Related reports https://github.com/microsoft/vscode/issues/53492, https://github.com/microsoft/vscode/issues/96986, and https://github.com/microsoft/vscode/issues/124895 cover distinct interactions.
- **Open decisions:**
  - Should wheel-axis selection follow the hovered scrollbar for every shared ScrollableElement consumer, or be opt-in for the editor?
  - Should the behavior apply only to physical vertical mouse wheels, or also to predominantly vertical trackpad gestures over the horizontal scrollbar?
  - How should the interaction behave when the horizontal scrollbar is visible but cannot scroll farther in the requested direction?

## Evidence

- **current source:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts handles wheel events in `_onMouseWheel`; it converts vertical input to horizontal only when `scrollYToX` is enabled or Shift is held, and does not inspect whether the event target is the horizontal scrollbar.
- **editor configuration:** src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts creates the editor's SmoothScrollableElement without enabling `scrollYToX`, so the existing shared option does not satisfy this pointer-dependent request.
- **existing workaround:** Current source retains the reporter's Shift-wheel workaround through `shiftConvert` in `_onMouseWheel`; there is no setting or command that enables conversion only while hovering the horizontal scrollbar.
- **canonical search:** The suggested https://github.com/microsoft/vscode/issues/53492 concerns page-wise scrollbar-track clicks, https://github.com/microsoft/vscode/issues/96986 concerns a dedicated horizontal wheel, and open https://github.com/microsoft/vscode/issues/124895 concerns failed pointer dragging; none owns this wheel-over-scrollbar interaction.
