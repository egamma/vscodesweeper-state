# Issue #109959 — Horizonal Scrolling through pointer on scroll bar

[https://github.com/microsoft/vscode/issues/109959](https://github.com/microsoft/vscode/issues/109959)

## Summary

The requested pointer-sensitive wheel behavior remains absent on current main, and no open canonical issue was found that owns the same request. The accepted Backlog feature request should remain open under its existing editor-scrollbar classification.

## Change summary

When the pointer is over the editor's horizontal scrollbar, make a vertical mouse-wheel gesture scroll the editor horizontally without requiring Shift.

## Best solution

Treat wheel input over the horizontal scrollbar as horizontal movement while preserving ordinary vertical scrolling over editor content and existing Shift-plus-wheel and native horizontal-wheel behavior.

## Evidence

- **current source:** src/vs/base/browser/ui/scrollbar/scrollableElement.ts:460-503 processes wheel deltas globally and converts vertical input to horizontal only when `scrollYToX` is enabled or Shift is held; it does not inspect whether the event target is the horizontal scrollbar.
- **editor configuration:** src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts:38-66 constructs the editor scrollable element without enabling `scrollYToX`, so the requested pointer-over-scrollbar behavior is not provided by the editor configuration.
- **existing capability check:** The existing `editor.scrollbar.scrollByPage` setting documented in https://github.com/microsoft/vscode/issues/53492 changes track-click behavior, not mouse-wheel axis selection, so it does not satisfy this request.
- **canonical search:** https://github.com/microsoft/vscode/issues/96986 and https://github.com/microsoft/vscode/issues/107848 concern unreliable dedicated horizontal-wheel input, while https://github.com/microsoft/vscode/issues/124895 concerns dragging scrollbars; none owns this vertical-wheel-over-horizontal-scrollbar request.
