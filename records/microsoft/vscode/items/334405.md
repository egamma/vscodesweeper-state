# Issue #334405 — Claude BYOK broken in 1.136: SDK download deadlock for signed-in users

[https://github.com/microsoft/vscode/issues/334405](https://github.com/microsoft/vscode/issues/334405)

## Summary

Well-diagnosed, source-confirmed deadlock: a signed-in-but-no-subscription BYOK Claude user is permanently stuck after the pinned SDK version bumps, because the only download trigger is gated to signed-out users and the command isn't in the palette. This is a real regression, not a design choice, so it should be routed to the agent host/Claude area rather than closed.

## Change summary

Claude native/BYOK becomes permanently unusable after upgrading to 1.136 for signed-in GitHub users without a Copilot subscription, because the pinned SDK version changed and no download path is reachable.

## Best solution

In src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSdkSetupNotification.ts, getAgentSdkSetupState()'s guard `!inputs.allowSignedOutWhenUsable || !inputs.entitlementResolved || inputs.signedIn` unconditionally hides the download offer for signed-in users; maintainers need to decide whether to also surface a download affordance (banner and/or a Command Palette entry for workbench.action.chat.agentHost.downloadAgentSdk, currently registered without f1) for signed-in BYOK users whose SDK cache misses the newly pinned version in src/vs/platform/agentHost/node/agentSdkDownloader.ts's exact-match isSdkResolvableWithoutDownload.
