# Issue #329904 — Flaky Tests: imports a prepared model directory and creates scanner metadata

[https://github.com/microsoft/vscode/issues/329904](https://github.com/microsoft/vscode/issues/329904)

## Summary

Fresh flaky-test report (1/20 on Windows) for a brand-new feature (FoundryLocalModelImport); tracing the source shows a plausible, well-known root cause — the import code uses raw `fs.promises.rename` for directory swaps instead of the project's Windows-AV-lock-retry-aware `Promises.rename` helper — so this stays open for a fix rather than any close.

## Change summary

The 'imports a prepared model directory and creates scanner metadata' unit test intermittently fails on Windows CI (1 failure out of 20 runs).

## Best solution

Swap the raw `fs.rename` calls in src/vs/platform/localTranscription/node/foundryLocalModelImport.ts for `Promises.rename` from src/vs/base/node/pfs.ts, which already retries on EACCES/EPERM/EBUSY — the exact transient-lock class that causes Windows directory-rename flakiness right after writing files (e.g. AV scanning).
