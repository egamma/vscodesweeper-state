# Issue #211068 — Error rendering should be unified across notebooks and editor

[https://github.com/microsoft/vscode/issues/211068](https://github.com/microsoft/vscode/issues/211068)

## Summary

Keep open for a notebook/Problems design decision: current code provides conditional cell-failure diagnostics, but notebook errors still have a separate renderer. The discussion identifies a real distinction between language-specific kernel output and structured Problems markers, without settling how their presentation should converge.

## Change summary

Consider sharing error presentation between notebook execution outputs and the Problems view instead of maintaining separate experiences.

## Best solution

Have the notebook and Problems owners decide which presentation and navigation conventions should be shared, accounting for the existing cell-failure diagnostics bridge. Preserve access to kernel-specific traceback details rather than assuming every execution error can become a structured diagnostic.
