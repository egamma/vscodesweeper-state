# Issue #331677 — Add local timestamps to Agent Host network diagnostics files for traceability

[https://github.com/microsoft/vscode/issues/331677](https://github.com/microsoft/vscode/issues/331677)

## Summary

Current main still omits collection and probe timestamps from Agent Host network diagnostics, and exported debug-log names contain session/chat titles but no timestamp. This remains a valid Agent Host observability request and should be routed to that area.

## Change summary

Add chronological metadata to Agent Host network reports, connectivity probes, and debug-log archive names.

## Best solution

Define one consistent timestamp contract for Agent Host diagnostics, then expose collection start/completion metadata and enough per-probe timing information to correlate reports while giving user-facing exports chronologically distinguishable names.

- **Behavior:**

  > Separate Agent Host diagnostic collections must be chronologically distinguishable after files are moved or shared. A network report should identify when collection began and ended, and probe entries should provide the absolute timing metadata selected by the maintainer while retaining existing duration and connectivity details. User-facing debug-log archive names should include the selected filesystem-safe timestamp format without losing their session/chat namespace. Acceptance includes deterministic tests for formatting, timezone semantics, and filename safety.
- **Trace:**

  > The network report is assembled in collectNetworkDiagnostics and formatEndpointSection in src/vs/workbench/contrib/chat/electron-browser/actions/networkDiagnosticsAction.ts. NetworkDiagnosticsService.fetch and resolveDns in src/vs/platform/agentHost/node/networkDiagnosticsService.ts currently return elapsed durations through interfaces in src/vs/platform/agentHost/common/agentService.ts, with no absolute times. User-facing export names come from getAgentHostDebugLogsExportName in src/vs/workbench/contrib/chat/browser/actions/exportAgentHostDebugLogsAction.ts; UUID names in AgentHostDebugLogsCollector are temporary internal artifacts and should not be confused with the final selected destination. Preserve existing endpoint results, duration measurements, title-based archive names, protocol interoperability, and temporary-artifact uniqueness. The related https://github.com/microsoft/vscode/issues/331678 covers broader Copilot Chat diagnostics and is not a canonical duplicate for this re-reviewed issue.
- **Open decisions:**
  - Should the stable diagnostic representation use UTC ISO 8601 timestamps, local timestamps with an explicit numeric offset, or both? The requested wording says local time while its filename example uses the UTC “Z” suffix.
  - Should absolute start/end timestamps be added to every DNS and HTTP probe result across the Agent Host protocol, or should the report carry collection-level timestamps while retaining per-probe elapsed durations only?
  - Should timestamped naming apply only to the user-facing exported archive, or also to temporary Agent Host artifacts that are normally hidden from users?
