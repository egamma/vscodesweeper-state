# Issue #198883 — Apparent lifecycle discrepancy between `ManagementPersistentConnection` and  `ExtensionHostPersistentConnection`

[https://github.com/microsoft/vscode/issues/198883](https://github.com/microsoft/vscode/issues/198883)

## Summary

The original lifecycle-mismatch concern was partially addressed by the configurable `--reconnection-grace-time` (commit 6cc2564bf9d), which now applies to both management and extension host connections. However, a recent commenter (Feb 2026) reports the setting is not fully effective — the extension host still terminates prematurely even with a 24-hour grace time — indicating a remaining bug. Keeping open.

## Change summary

Extension host terminates after 3 hours of disconnection even when the management connection survives longer, creating a broken-feeling session on reconnect; a configurable grace time was added but may not be working reliably.

## Best solution

Investigate why `--reconnection-grace-time 86400` does not prevent premature extension host termination as reported in the latest comment. The grace time propagation path (CLI → `serverEnvironmentService.reconnectionGraceTime` → `VSCODE_RECONNECTION_GRACE_TIME` env var → `extensionHostProcess.ts` `readReconnectionValue`) should be traced end-to-end. The fix likely lives in `src/vs/workbench/api/node/extensionHostProcess.ts` or `src/vs/server/node/extensionHostConnection.ts`.
