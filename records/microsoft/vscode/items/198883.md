# Issue #198883 — Apparent lifecycle discrepancy between `ManagementPersistentConnection` and  `ExtensionHostPersistentConnection`

[https://github.com/microsoft/vscode/issues/198883](https://github.com/microsoft/vscode/issues/198883)

## Summary

Keep open: the configurable reconnection grace period addresses the original fixed three-hour limit, but a current-version report says the extension host can still terminate before the configured one-day grace period. That leaves a distinct timer/lifecycle correctness bug requiring diagnosis.

## Change summary

Keep the remote extension host lifecycle consistent with the surviving management session and honor the configured reconnection grace period before terminating a disconnected extension host.

## Best solution

Trace every extension-host shutdown path and timer reset against `reconnection-grace-time`, then ensure premature termination cannot occur while the management connection remains eligible for reconnection.

## Plan brief

- **Likely files:** `src/vs/workbench/api/node/extensionHostProcess.ts`, `src/vs/server/node/remoteExtensionHostAgentServer.ts`
- **Validation:** Add or extend remote reconnection lifecycle coverage to simulate repeated disconnect/reconnect periods with a configured grace time and assert that the extension host terminates only after one continuous disconnection exceeding that value.
- **Behavior:**

  > A remote extension host must remain alive for the full configured `reconnection-grace-time` while its renderer is disconnected. Reconnecting before the deadline must reset the effective disconnected interval, including across repeated disconnect/reconnect cycles. The extension host may terminate only after one continuous disconnection exceeds the configured grace period, while unchanged default behavior remains covered.
- **Trace:**

  > The original path reaches the disconnected-renderer shutdown logic in `src/vs/workbench/api/node/extensionHostProcess.ts`, while `src/vs/server/node/remoteExtensionHostAgentServer.ts` owns remote extension-host connection and reconnection handling. Commit https://github.com/microsoft/vscode/commit/6cc2564bf9dfdb55cf62eebf7746cad0279819bd introduced configurable grace time, but the latest report observes premature termination with a one-day value on 1.109.5. Diagnosis should establish which disconnect event starts the timer, whether reconnect reliably cancels or resets it, and whether another shutdown path still uses a default interval. Preserve intentional cleanup after a genuinely continuous expired grace period and do not broaden the work into management-session retention policy.
