A maintainer explicitly confirmed it as a duplicate of the canonical in https://github.com/microsoft/vscode/issues/48964#issuecomment-421368500. This is the same command-in-diff-editor failure described here, not merely related SCM work.
- **Discussion establishes core ownership:** https://github.com/microsoft/vscode/issues/116863#issuecomment-780790612 identifies the diff-editor context and distinguishes its action from the regular-editor action. https://github.com/microsoft/vscode/issues/116863#issuecomment-793100512 confirms that both command sets are core and describes their inconsistent Command Palette registration; the initial extension suspicion is therefore not a basis for closure.
- **Current source retains separate command identities:** src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts:875-913 registers GotoNextChangeAction as workbench.action.editor.nextChange with a precondition excluding active text diff editors. src/vs/workbench/browser/parts/editor/diffEditorCommands.ts:47-61 separately registers workbench.action.compareEditor.nextChange, its Option/Alt+F5 shortcut, and a Command Palette entry. DiffEditorCommandsService.navigateInDiffEditor delegates to goToDiff. Availability of this separate working command does not establish that the reported command-alignment problem was fixed.
