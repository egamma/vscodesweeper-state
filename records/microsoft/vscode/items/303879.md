# Issue #303879 — Sessions App: Need a way to snooze inline suggestions

[https://github.com/microsoft/vscode/issues/303879](https://github.com/microsoft/vscode/issues/303879)

## Summary

The status dashboard has since been added to the Agents Window, but current main explicitly removes its snooze control, so the requested discoverable UI remains missing. This team-authored, under-discussion request should stay open while maintainers decide which editor controls belong in the Sessions dashboard.

## Change summary

Provide a discoverable way in the Sessions app to temporarily snooze distracting inline suggestions and ghost text.

## Best solution

Expose the existing inline-suggestion snooze capability through the Agents Window account/status dashboard on desktop and mobile, while keeping unrelated editor settings hidden if they do not belong in the streamlined Sessions UI.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/accountMenu/browser/account.contribution.ts`, `src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts`, `src/vs/workbench/contrib/chat/test/browser/chatStatusDashboard.test.ts`
- **Validation:** Verify in desktop and mobile Agents Window layouts that the account/status dashboard offers Snooze Inline Suggestions, selecting a duration suppresses ghost text, and the existing non-Sessions dashboard tests remain passing.
- **Behavior:**

  > Users composing prompts in an Agents Window editor need a discoverable way to snooze inline suggestions for a chosen duration. Snoozing must suppress both ghost text and next-edit suggestions consistently with the main VS Code window, and cancellation or expiry must restore suggestions. The control should be available in the supported desktop and mobile Sessions account/status surfaces without requiring a conventional workbench status bar.
- **Trace:**

  > The Agents Window reuses ChatStatusDashboard from src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts through src/vs/sessions/contrib/accountMenu/browser/account.contribution.ts. The shared dashboard already supports snoozing and invokes the editor.action.inlineSuggest.snooze capability, but both Sessions construction paths explicitly set `disableCompletionsSnooze: true`; this conclusively explains the remaining UI gap on main. Commit https://github.com/microsoft/vscode/commit/de317652c4a0b5ba7ab14ec49336bce1152b4666 brought the dashboard into the Agents Window without enabling snooze. The boundary is the Sessions presentation policy: existing snooze behavior and ordinary workbench dashboard behavior must not change.
- **Open decisions:**
  - Should Sessions expose only the snooze action, or also any of the other editor-specific quick settings currently disabled in its dashboard?
  - Should the snooze control appear identically in both desktop hover and mobile account-sheet presentations?

## Evidence

- **current source:** src/vs/sessions/contrib/accountMenu/browser/account.contribution.ts passes `disableCompletionsSnooze: true` in both `createCopilotHoverContent` and `ChatDashboardServiceImpl.createDashboardElement`, removing snooze from the desktop and mobile Sessions dashboards.
- **shared capability:** src/vs/workbench/contrib/chat/browser/chatStatus/chatStatusDashboard.ts renders the snooze control when `disableCompletionsSnooze` is not set, while src/vs/editor/browser/services/inlineCompletionsService.ts registers the existing `editor.action.inlineSuggest.snooze` command.
- **implementation history:** https://github.com/microsoft/vscode/commit/de317652c4a0b5ba7ab14ec49336bce1152b4666 updated the chat status dashboard for the Agents Window after this issue was filed, but retained `disableCompletionsSnooze: true` and does not reference https://github.com/microsoft/vscode/issues/303879.
- **maintainer direction:** The discussion agreed that core capabilities should not depend on adding a conventional status bar and proposed reusing the Copilot status popover; no related open fixing pull request or canonical duplicate was found.
