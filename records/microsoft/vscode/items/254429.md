# Issue #254429 — Attach a terminal as context

[https://github.com/microsoft/vscode/issues/254429](https://github.com/microsoft/vscode/issues/254429)

## Summary

Keep open: current terminal metadata, selection attachments, and command-output attachments do not provide a persistent connection to a user-started watch terminal. The related open reports are newer and cannot absorb this re-reviewed, team-authored request under the duplicate rules.

## Change summary

Let users attach an existing terminal to agent chat so the agent can inspect its running process and changing output without starting a redundant process.

## Best solution

Provide an explicit, read-only attachment to a selected existing terminal, preserving access to its current output while the user's watch task continues running. Coordinate the attachment semantics with the agent-host context work without treating terminal observation as permission to execute or terminate commands.

Change a test so the same process emits new output, then verify the agent can access that output without restarting the watcher or launching another test process. Add attachment/context tests matching the agreed refresh semantics and retain existing selection and command-attachment behavior.
- **Behavior:**

  > A user can select an already-running terminal as context for agent chat, including a terminal started manually or by a task. The agent can identify the running command and inspect output produced after the terminal was attached, without requiring the process to be restarted by the agent. Acceptance includes a vitest watch session whose later test results remain accessible through the same selected terminal. Attaching read context does not grant authority to send input, stop the process, or start replacement processes.
- **Trace:**

  > TerminalStatePromptElement in extensions/copilot/src/extension/prompts/node/base/terminalState.tsx supplies terminal names and last-command metadata but no output. ChatAddTerminalSelection in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/terminal.chatAgentTools.contribution.ts creates a text snapshot, while TerminalContext.asAttachment in src/vs/workbench/contrib/chat/browser/actions/chatContext.ts captures one detected command. GetTerminalOutputTool resolves only RunInTerminalTool execution UUIDs, so it does not expose arbitrary user-started watch terminals through that path. TerminalServiceImpl in extensions/copilot/src/platform/terminal/vscode/terminalServiceImpl.ts already exposes terminal enumeration, per-terminal buffers, and terminal-data events; those primitives alone do not establish the requested attachment contract. Preserve existing selection, completed-command attachment, and command-execution semantics. Coordinate with https://github.com/microsoft/vscode/issues/329541 for agent-host coverage and https://github.com/microsoft/vscode/issues/264789 for watch-task discovery. The remaining design uncertainty is how changing output becomes available during and between agent turns.
- **Open decisions:**
  - Should an attached terminal deliver new output automatically during an active agent turn, or expose fresh output only when the agent reads it or the user submits another request?
