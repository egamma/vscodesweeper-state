# Issue #141253 — Emmet breaks with cryptic error message in files that cannot be parsed

[https://github.com/microsoft/vscode/issues/141253](https://github.com/microsoft/vscode/issues/141253)

## Summary

Real confirmed bug: Emmet silently stops working when the HTML file contains parse errors (e.g. missing `>`). The parser in parseDocument.ts has no error recovery or user-facing diagnostic, so Emmet just disappears. Still unfixed on main.

## Change summary

Emmet stops providing abbreviation expansions in files with HTML syntax errors, with no helpful error message to the user.

## Best solution

Add error recovery or partial parsing to the Emmet parse pipeline so that Emmet continues to work in the valid portions of a document, or at minimum surface a visible diagnostic explaining why Emmet is unavailable. The fix belongs in `extensions/emmet/src/parseDocument.ts` and the upstream `@emmetio/html-matcher` library.
