# Issue #274013 — Check edits setting in CommandLineFileWriteAnalyzer

[https://github.com/microsoft/vscode/issues/274013](https://github.com/microsoft/vscode/issues/274013)

## Summary

Keep open: CommandLineFileWriteAnalyzer still does not consult chat.tools.edits.autoApprove, so the requested integration remains missing. The related core-extraction issue is newer and does not qualify as a duplicate canonical under the re-review rules.

## Change summary

Honor file-edit auto-approval rules when evaluating detected file writes in terminal commands.

## Best solution

Make detected terminal writes respect the applicable file-edit confirmation rules, coordinated with the shared-core work in https://github.com/microsoft/vscode/issues/274770. Settle how those rules interact with the existing terminal-wide file-write setting before implementation.

- **Behavior:**

  > Detected file writes in terminal commands should consult the applicable chat.tools.edits.autoApprove rules rather than relying exclusively on terminal-wide workspace boundaries. Acceptance must cover a destination requiring confirmation, an explicitly approved destination, an unmatched destination, and commands writing multiple files. The maintainer must first establish how file-specific rules interact with the all, outsideWorkspace, and never terminal modes. Commands without detected writes should retain their current behavior.
- **Trace:**

  > CommandLineFileWriteAnalyzer._getFileWrites collects redirections and command-specific writes, resolves destinations against cwd, and passes them to _getResult in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/commandLineAnalyzer/commandLineFileWriteAnalyzer.ts. _getResult consults only TerminalChatAgentToolsSettingId.BlockDetectedFileWrites; it has no edit-pattern evaluation. makeUriConfirmationChecker in extensions/copilot/src/extension/tools/node/editFileToolUtils.tsx supplies the existing edit-rule semantics, including protected patterns and additional filesystem checks. https://github.com/microsoft/vscode/issues/274770 tracks making that logic available to core and explicitly names this issue as its terminal consumer. The current analyzer test suite supplies a bounded validation surface, but the record does not settle precedence between the two settings. Keep this work limited to detected-write approval; do not expand shell-write detection or treat it as complete filesystem sandbox enforcement.
- **Open decisions:**
  - How should file-specific true and false edit-approval rules interact with each terminal file-write mode: are they additional restrictions only, or may explicit approvals override outsideWorkspace or all?
