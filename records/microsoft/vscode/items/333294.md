# Issue #333294 — Navigating to Automations can recursively rerender a long chat and freeze the renderer

[https://github.com/microsoft/vscode/issues/333294](https://github.com/microsoft/vscode/issues/333294)

## Summary

Freshly filed, well-diagnosed renderer freeze with concrete telemetry (render counts, timestamps) and a plausible root cause I could confirm in the current source; no fix exists yet, so this stays open for engineering work.

## Change summary

Navigating from a long Agents chat to the Automations custom view can recursively re-enter ListView._rerender via a synchronous setScrollTop→onScroll loop, freezing the renderer for ~20-30 seconds.

## Best solution

Add a re-entrancy guard around ListView._rerender (src/vs/base/browser/ui/list/listView.ts) so a synchronous setScrollTop→onScroll during scroll-anchor correction cannot recursively re-enter rendering, and/or skip dynamic-height probing while the chat list viewport is hidden/collapsed during the Automations transition (src/vs/sessions/browser/workbench.ts, src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts).
