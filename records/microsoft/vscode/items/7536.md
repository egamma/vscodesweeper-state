# Issue #7536 — Implement editor undo stack serialization

[https://github.com/microsoft/vscode/issues/7536](https://github.com/microsoft/vscode/issues/7536)

## Summary

Keep open as the canonical infrastructure request for persistent undo serialization. Current main serializes edit elements only for in-memory retention and still does not preserve undo history across VS Code sessions.

## Change summary

Provide serialization and deserialization of editor undo stacks so they can be persisted and restored across sessions.

## Best solution

Extend the editor undo/redo infrastructure to persist complete resource stacks on disk and restore them after validating that the file contents still match. Clarify that `files.restoreUndoStack` currently covers reopening within the same process, not restarting VS Code.

## Evidence

- **current source:** `src/vs/editor/common/model/editStack.ts` serializes `SingleModelEditStackData` into an `ArrayBuffer`, but exposes no persistence format or complete stack restoration facility.
- **in-memory scope:** `src/vs/editor/common/services/modelService.ts` retains disposed models in the process-local `_disposedModels` map and reconnects their undo elements when the same resource is reopened; nothing writes this state to disk.
- **implementation history:** Commit a297639830452025d44eaebcd908e6210366a79e introduced the existing serialization specifically to reduce memory usage for closed edit-stack elements, not to persist them between sessions.
- **setting limitation:** `src/vs/workbench/contrib/files/browser/files.contribution.ts` registers `files.restoreUndoStack`, while the implementation remains process-local; this explains reports that enabling it does not survive a restart.
- **maintainer confirmation:** A maintainer confirmed that undo/redo was retained only in memory and not saved to disk: https://github.com/microsoft/vscode/issues/7536#issuecomment-623422668.
- **dependent request:** The open hot-exit request https://github.com/microsoft/vscode/issues/15135 explicitly identifies this serialization work as a prerequisite.
