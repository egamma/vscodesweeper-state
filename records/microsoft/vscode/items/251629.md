# Issue #251629 — reference large interactive cell outputs in chat

[https://github.com/microsoft/vscode/issues/251629](https://github.com/microsoft/vscode/issues/251629)

## Summary

A meaningful gap remains: notebook output attachments send HTML source rather than the current rendered state of interactive outputs. Keep this team-authored request open; existing image attachments and focused-window screenshots provide partial alternatives, not the requested output-specific capture.

## Change summary

Allow chat references to large interactive HTML cell outputs to use rendered screenshots instead of raw output content.

## Best solution

Support a bounded visual snapshot of an interactive cell output's current rendered state in chat context, while preserving existing text and image attachment behavior. Decide whether capture is explicitly requested or automatically selected before designing the notebook-to-chat capture contract.

- **Behavior:**

  > Chat should be able to receive a visual representation of a large interactive HTML cell output in its current rendered state rather than relying exclusively on raw HTML. Acceptance must include an output whose visible state changes after execution through JavaScript interaction. Establish the capture moment and image bounds, verify the resulting attachment matches them, and measure rather than assume a token reduction. Existing text and image output references must remain usable.
- **Trace:**

  > The notebook chat contribution uses createNotebookOutputVariableEntry in src/vs/workbench/contrib/notebook/browser/contrib/chat/notebookChatUtils.ts to identify an output by URI, index, and MIME type. In extensions/copilot/src/extension/prompts/node/panel/chatVariables.tsx, output references reach NotebookCellOutputVariable in notebookVariables.tsx, which sends text/html as truncated source and handles existing image/png data separately. That model-data path cannot represent JavaScript mutations confined to the rendered output. The focused-window screenshot path in src/vs/workbench/contrib/chat/browser/actions/chatActions.ts is available but does not establish output-scoped capture. The renderer capture mechanism and its cross-boundary contract remain untraced; preserve existing attachment behavior and do not assume desktop-only capture satisfies every notebook host. https://github.com/microsoft/vscode/issues/283206 concerns automatic context inclusion, not rendered-state capture.
- **Open decisions:**
  - Should rendered capture be an explicit attachment choice, or automatically replace raw HTML for qualifying large interactive outputs?
  - Should a snapshot represent the state when attached or when the chat request is submitted?
  - Should capture include only the visible output viewport or the complete rendered output subject to a size limit?
