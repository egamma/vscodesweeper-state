# Issue #325939 — winpty has been removed

[https://github.com/microsoft/vscode/issues/325939](https://github.com/microsoft/vscode/issues/325939)

## Summary

This is a support request about documented terminal compatibility after WinPTY removal. The reported Windows build predates the supported ConPTY baseline; upgrading Windows is the documented resolution.

## Change summary

The reporter needs help opening the integrated terminal on Windows 10 build 10240 after WinPTY removal.

## Best solution

Use a newer Windows version with ConPTY support rather than restore WinPTY. Explain the compatibility boundary and acknowledge that the suggested bundled-ConPTY setting is not a guaranteed workaround for this old build.

  > Thanks for the report. Your system is running Windows 10 build 10240, which predates the terminal compatibility baseline documented in the [WinPTY removal notes](https://code.visualstudio.com/updates/v1_109#_removal-of-winpty-support). Please upgrade to a newer Windows 10 version or Windows 11 to use the integrated terminal. The suggested `terminal.integrated.windowsUseConptyDll` setting is not a guaranteed workaround for this older build; if upgrading is not currently possible, use a separate Command Prompt or PowerShell window.

- **Documented compatibility boundary:** https://code.visualstudio.com/updates/v1_109#_removal-of-winpty-support explicitly states that WinPTY removal means terminals no longer work on Windows versions before Windows 10 version 1809. It recommends upgrading Windows and describes terminal.integrated.windowsUseConptyDll as a possible experimental workaround, not guaranteed compatibility.

On the reporter's build 10240, enabling the setting does not enable either option through this path. Lines 254-255 surface the WinPTY-removal explanation when ConPTY cannot launch.
- **Maintainer response:** The supplied discussion contains a July 15 maintainer suggestion to enable terminal.integrated.windowsUseConptyDll and restart. There is no reporter confirmation that this worked and no maintainer commitment to restore legacy Windows support.
