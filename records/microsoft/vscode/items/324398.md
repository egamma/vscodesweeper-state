# Issue #324398 — Mermaid Diagram Markdown Preview ignores theme-related config properties

[https://github.com/microsoft/vscode/issues/324398](https://github.com/microsoft/vscode/issues/324398)

## Summary

Current source explains the reported behavior: VS Code initializes Mermaid with a complete VS Code-derived theme-variable set, which Mermaid then carries into diagram-specific themes. This valid visual bug should remain open and route to the Markdown extension area.

## Change summary

Mermaid diagrams in Markdown preview ignore diagram-specific `theme` and partially override `themeVariables` from YAML frontmatter.

## Best solution

Preserve the VS Code-derived default theme while ensuring explicit per-diagram frontmatter themes start from their own variables and override the site configuration across Markdown, notebook, and chat renderers.

## Evidence

- **current source:** `extensions/mermaid-markdown-features/preview-src/markdown/index.ts` initializes Mermaid with `buildMermaidConfig`, while `preview-src/shared/vsCodeTheme.ts` maps the default `vscode` theme to Mermaid's `base` theme plus a complete VS Code-derived `themeVariables` object.
- **merge behavior:** Mermaid 11.15.0's `packages/mermaid/src/config.ts` seeds a diagram-selected theme with `configFromInitialize.themeVariables` before applying frontmatter variables. Consequently, VS Code's initialized palette carries into `forest` and other per-diagram themes.
- **documented expectation:** Mermaid's documentation explicitly supports diagram-specific themes and `themeVariables` through frontmatter: https://github.com/mermaid-js/mermaid/blob/mermaid%4011.15.0/packages/mermaid/src/docs/config/theming.md
- **regression origin:** Commit 80afb57617705c037c65ab9bd2d4c6cb3defa8e3 introduced the VS Code-derived Mermaid theme and its global theme-variable initialization; no subsequent commit in this area addresses frontmatter precedence.
