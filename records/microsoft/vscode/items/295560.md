# Issue #295560 — Approval UI needs to be friction-less to use

[https://github.com/microsoft/vscode/issues/295560](https://github.com/microsoft/vscode/issues/295560)

## Summary

Keep open: current approval controls still put alternative approval scopes behind a dropdown rather than offering directly discoverable shortcuts for each scope. Session approval can now be the primary action in some cases, but that only partially addresses the request.

## Change summary

Expose available approval scopes inline with easy, discoverable keyboard shortcuts instead of requiring dropdown navigation.

## Best solution

Make one-time, session, and workspace approval choices directly discoverable and keyboard-operable wherever those choices are available, without changing their permission semantics. Agree the shortcut and focus behavior before implementation, coordinating with the related confirmation-action redesign.

- **Behavior:**

  > Users should be able to discover and invoke each available approval scope without navigating a dropdown. Approval choices must clearly communicate whether consent applies once, to the session, or to the workspace. Keyboard activation must execute exactly the chosen scope and must not consume ordinary chat-input typing. Existing policy restrictions and unavailable-choice behavior remain unchanged.
- **Trace:**

  > ToolConfirmationAction in src/vs/workbench/contrib/chat/browser/actions/chatToolActions.ts dispatches Ctrl/Cmd+Enter to the active confirmation's primary action. AbstractToolConfirmationSubPart.render() selects a session action as primary in some cases and places alternatives in moreActions; buildCustomOptionButtons() similarly groups provider-supplied approval choices. BaseChatConfirmationWidget.updateButtons() renders those alternatives as ButtonWithDropdown. This establishes partial existing coverage, not the requested direct access to every approval scope. Preserve the existing approval callbacks, policy restrictions, and scope persistence rather than altering permission enforcement. Coordinate with https://github.com/microsoft/vscode/issues/262341, which discusses the surrounding confirmation-action design but does not settle the requested shortcut contract. The remaining uncertainty is how shortcuts activate safely across confirmation and chat-input focus.
- **Open decisions:**
