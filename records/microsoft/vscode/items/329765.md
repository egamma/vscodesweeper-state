# Issue #329765 — Ctrl+A + Esc scrolls to bottom of file

[https://github.com/microsoft/vscode/issues/329765](https://github.com/microsoft/vscode/issues/329765)

## Summary

Traced in source: Select All (Ctrl+A) deliberately sets the cursor's active/view position to the end of the buffer, and Escape's cancel-selection simply collapses to that current cursor position and reveals it — this is the standard collapse-to-active-end behavior most editors use, not a defect.

## Change summary

After Ctrl+A (select all) then Esc, the editor scrolls to the end of the file instead of restoring the pre-selection cursor position.

## Best solution

Keep current behavior — CursorMoveCommands.selectAll (src/vs/editor/common/cursor/cursorMoveCommands.ts:167) always places the active cursor at (lineCount, maxColumn), and CoreEditingCommands.CancelSelection (src/vs/editor/browser/coreCommands.ts:1775) collapses to and reveals that active cursor position. Restoring the pre-Ctrl+A cursor location on Escape would require tracking and special-casing prior state specifically for select-all, which is a design change, not a bug fix.

  > Thanks for the report. I traced this in the source: Ctrl+A (Select All) intentionally places the active cursor at the very end of the buffer (src/vs/editor/common/cursor/cursorMoveCommands.ts, `selectAll`), and Escape's cancel-selection simply collapses the selection to wherever the cursor currently is and reveals it (`cancelSelection` + `CoreEditingCommands.CancelSelection`). So after Select All, Escape naturally leaves (and scrolls to) the cursor at the end of the file — this matches how most editors handle select-all-then-collapse. Restoring your original pre-selection position would be a deliberate behavior change rather than a bug fix, so I'm closing this as by design. Feel free to open a feature request if you'd like Escape-after-select-all to restore the prior cursor position instead.
