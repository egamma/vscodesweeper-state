# Issue #329765 — Ctrl+A + Esc scrolls to bottom of file

[https://github.com/microsoft/vscode/issues/329765](https://github.com/microsoft/vscode/issues/329765)

## Summary

Traced in source: this is the standard 'Escape collapses selection to the caret' behavior, not a bug — Select All puts the caret at the end of the document, so collapsing there naturally scrolls to the bottom.

## Change summary

After Ctrl+A then Esc, the editor scrolls to the end of the file instead of staying at the original cursor position.

## Best solution

Keep current behavior — Escape/cancelSelection intentionally collapses to the selection's active end (viewState.position), matching standard editor conventions where Select All's caret sits at document end; no code change needed.

- **Proposed comment:**

  > Thanks for the report. I traced this in the source: pressing Esc runs the `cancelSelection` command (src/vs/editor/browser/coreCommands.ts), which collapses the cursor to the selection's active end (`cursor.viewState.position` in src/vs/editor/common/cursor/cursorMoveCommands.ts) — not the position you started from. For Ctrl+A, that active end is the end of the document, so the caret (and the viewport) end up there after Esc. This matches how Escape works after any selection, and isn't specific to Select All, so I don't think it's a bug — closing as as-designed. Feel free to open a feature request if you'd like Escape after Select All to specifically restore the pre-selection cursor position.

## Evidence

- **cancelSelection impl:** src/vs/editor/common/cursor/cursorMoveCommands.ts lines 241-253: `cancelSelection` collapses the cursor to `cursor.viewState.position` (the selection's active/head end), not the anchor or a saved pre-selection position.
- **coreCommands wiring:** src/vs/editor/browser/coreCommands.ts lines 1775-1799: the `cancelSelection` core command (bound to Escape) calls `CursorMoveCommands.cancelSelection` and then `viewModel.revealAllCursors`, which is what causes the scroll to the new (collapsed) position.
- **select-all caret position:** Ctrl+A (editor.action.selectAll, src/vs/editor/browser/editorExtensions.ts:703) creates a selection whose active end is at the end of the document, so collapsing on Escape naturally lands the caret — and the viewport — at the bottom.
- **longstanding code:** This logic is original/unchanged in cursorMoveCommands.ts history (git log -p shows no later modification of the cancelSelection logic since its introduction), indicating deliberate, stable design rather than a regression.
