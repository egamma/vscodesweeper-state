# Issue #68123 — Specify terminal group for integrated terminal in launch configuration

[https://github.com/microsoft/vscode/issues/68123](https://github.com/microsoft/vscode/issues/68123)

## Summary

This remains the canonical request for arranging integrated terminals created by compound debug sessions. Current DAP and VS Code sources still expose no terminal grouping or split-placement metadata, so the prerequisite protocol design remains unresolved.

## Change summary

Allow debug configurations or compounds to place their integrated terminals into specified groups or split layouts.

## Best solution

Define portable terminal-placement semantics in the Debug Adapter Protocol, or an explicitly sanctioned client-specific extension mechanism, and then have VS Code honor that metadata when creating integrated debug terminals. The existing launch-configuration `presentation.group` must remain distinct unless its current dropdown-grouping contract is deliberately expanded.

## Evidence

- **protocol gap:** Current `DebugProtocol.RunInTerminalRequestArguments` in src/vs/workbench/contrib/debug/common/debugProtocol.d.ts exposes only `kind`, `title`, `cwd`, `args`, `env`, and `argsCanBeInterpretedByShell`; it has no grouping, split, location, or client-options field. The current microsoft/debug-adapter-protocol schema has the same shape.
- **VS Code creation path:** src/vs/workbench/api/node/extHostDebugService.ts `$runInTerminal` creates an integrated terminal through `createTerminalFromOptions` with shell, cwd, name, and icon options, but receives and applies no group or split-placement information.
- **existing capability does not cover request:** The debug `presentation.group` currently feeds sorting and separators in src/vs/workbench/contrib/debug/browser/debugActionViewItems.ts and debugQuickAccess.ts; its schema describes grouping in the configuration dropdown and command palette, not terminal layout.
- **maintainer assessment:** A maintainer confirmed in the issue discussion that launch configuration terminal behavior belongs to debugger implementations and later stated that DAP support is still required.
- **canonical status:** Newer reports https://github.com/microsoft/vscode/issues/69619 and https://github.com/microsoft/vscode/issues/189596 were redirected to this issue. The broader 2026 request https://github.com/microsoft/vscode/issues/310020 explicitly references this issue and was closed by the feature-request lifecycle, not by an implementation.
