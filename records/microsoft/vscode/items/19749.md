# Issue #19749 — Add action to show inline all diagnostics in file.

[https://github.com/microsoft/vscode/issues/19749](https://github.com/microsoft/vscode/issues/19749)

## Summary

Keep this accepted request open: current diagnostic navigation still shows one problem at a time, not all diagnostic messages inline. The request has 61 upvotes, maintainer interest, and later reports explicitly consolidated here; ErrorLens is a useful workaround, not a shipped implementation of the requested command.

## Change summary

Add an opt-in editor action that displays all diagnostics in the current file simultaneously inline.

## Best solution

Provide an opt-in file-wide diagnostic view consistent with existing problem navigation, without moving the selection or scrolling to the last diagnostic. Preserve the existing F8 behavior and default editor experience, and establish rendering and lifecycle requirements before implementation.

Verify diagnostic updates, removal, dismissal, model switching, and editor disposal; existing F8/Shift+F8 navigation must remain unchanged. Include a large-file check for responsiveness and keyboard/screen-reader access.
- **Behavior:**

  > Users can invoke an opt-in action to see all diagnostic messages for the current file inline rather than navigating them individually. Showing the overview preserves the current selection and does not scroll to a distant diagnostic. Messages remain associated with their source locations as diagnostics update, and no stale messages remain after switching files or disposing the editor. Existing problem navigation and the default editor presentation remain unchanged.
- **Trace:**

  > MarkerController in src/vs/editor/contrib/gotoError/browser/gotoError.ts owns one MarkerNavigationWidget and displays the selected marker through showAtMarker() or navigate(); no registered action creates a file-wide overview. MarkerNavigationWidget.showAtMarker() in gotoErrorWidget.ts reveals and focuses its target, while ZoneWidget._showImpl() in src/vs/editor/contrib/zoneWidget/browser/zoneWidget.ts inserts a view zone and reveals its range. These source paths substantiate the historical concern that repeatedly displaying navigation widgets would move the viewport. The three implementation attempts at https://github.com/microsoft/vscode/pull/20042, https://github.com/microsoft/vscode/pull/27218, and https://github.com/microsoft/vscode/pull/29145 were closed without merging. The remaining planning boundary is how simultaneous diagnostic presentation behaves across virtualization and diagnostic updates without changing shared zone-widget consumers; that design and its regression harness were not fully traced. Preserve the requested opt-in command, existing F8 semantics, and default presentation; extension recommendations in the discussion do not settle the native implementation.

## Evidence

- **Current capability gap:** src/vs/editor/contrib/gotoError/browser/gotoError.ts stores a single MarkerNavigationWidget in MarkerController._widget. Its registered actions are editor.action.marker.next, editor.action.marker.prev, editor.action.marker.nextInFiles, and editor.action.marker.prevInFiles; navigate() displays only model.selected.marker. These present diagnostics in a panel or the status bar, not simultaneous inline messages. editor.renderValidationDecorations in src/vs/editor/common/config/editorOptions.ts controls validation decorations, not a file-wide expansion of diagnostic text.
