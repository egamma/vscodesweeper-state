# Issue #196969 — Activation `onCommand` sometimes never returns when there are multiple extension hosts

[https://github.com/microsoft/vscode/issues/196969](https://github.com/microsoft/vscode/issues/196969)

## Summary

Team-authored bug with `important` label — hard keep-open. The initial fix (PR #197440) landed in Nov 2023, but the author reopened in Apr 2024 after reproducing the issue again. No subsequent fix commit references this issue, and the underlying race (a terminated web worker extension host blocking `activateByEvent`) may still be latent on current main.

## Change summary

In multi-extension-host setups (Codespaces), a terminated web worker extension host can block all subsequent `activateByEvent` calls indefinitely, hanging commands like staging files or editing PR comments.

## Best solution

Investigate the race in `ExtensionHostManager._activateByEvent` (src/vs/workbench/services/extensions/common/extensionHostManager.ts) where `await this._proxy` may hang if the web worker extension host terminated without the proxy promise rejecting. The fix likely needs the proxy promise to reject or resolve to `null` when the extension host is terminated, so `_activateByEvent` can bail out. The `containsActivationEvent` guard from PR #197440 helped but didn't fully resolve the terminated-host scenario.
