# Issue #334092 — Diff editor ignores working-tree-encoding, showing entire file as modified

[https://github.com/microsoft/vscode/issues/334092](https://github.com/microsoft/vscode/issues/334092)

## Summary

Well-diagnosed bug: `Repository.buffer()` in the git extension fetches the index/HEAD side with `git show --textconv`, which doesn't apply the `working-tree-encoding` re-encoding that git applies on checkout — so files using that gitattribute show a garbled left side and spurious full-file diffs. A second reporter independently reproduced it with a different encoding (Shift_JIS) and confirmed that swapping in `git cat-file --filters` fixes it locally.

## Change summary

Diff editor decodes the git-stored (index/HEAD) side of a file as UTF-8 even when `.gitattributes` sets `working-tree-encoding`, producing mojibake and a false full-file diff.

## Best solution

In extensions/git/src/git.ts, change `Repository.buffer()` (and possibly `detectObjectType()`) to use `git cat-file --filters <rev>:<path>` instead of `git show --textconv`, so the working-tree-encoding conversion is applied the same way `git diff` applies it; needs care to confirm `--filters` doesn't regress existing textconv/binary-detection behavior for files without the attribute.
