# Issue #334092 — Diff editor ignores working-tree-encoding, showing entire file as modified

[https://github.com/microsoft/vscode/issues/334092](https://github.com/microsoft/vscode/issues/334092)

## Summary

Traced in source: the git extension's `buffer()` fetches the diff base via `git show --textconv ref:path` (extensions/git/src/git.ts), which applies diff textconv drivers but not the working-tree-encoding clean/smudge conversion, so an object stored UTF-8 in the index is handed to VS Code as raw UTF-8 bytes and then decoded with the working-tree encoding, producing mojibake and a spurious full-file diff — matches the reporter's diagnosis and git's own documented distinction between textconv and filtered content.

## Change summary

The diff editor's left-hand (index/HEAD) content ignores the `working-tree-encoding` gitattribute, so files whose working-tree encoding differs from the git-object encoding (UTF-8) render garbled and show as fully modified.

## Best solution

In the git extension's content-provider path (extensions/git/src/git.ts `buffer()`, used by extensions/git/src/fileSystemProvider.ts via repository.buffer), source the index/HEAD side using a primitive that applies working-tree-encoding conversion (e.g. `git cat-file --filters` or an equivalent) instead of relying solely on `--textconv`, while preserving textconv behavior for genuinely binary/textconv-configured files; this needs design work to reconcile textconv vs. filters, so it belongs with the git extension owners rather than an unreviewed auto-fix.
