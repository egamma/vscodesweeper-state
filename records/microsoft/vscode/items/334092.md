# Issue #334092 — Diff editor ignores working-tree-encoding, showing entire file as modified

[https://github.com/microsoft/vscode/issues/334092](https://github.com/microsoft/vscode/issues/334092)

## Summary

Verified duplicate: https://github.com/microsoft/vscode/issues/127441 (2021, open, `bug`-labeled, assigned) reports the exact same root cause — VS Code's diff/decoration machinery decodes the git-object side of a file using the working-tree encoding instead of accounting for `working-tree-encoding` gitattributes transforms, causing spurious full-file diffs. That issue is older and owns the same underlying problem, so this is a duplicate consolidation, not a competing report.

## Change summary

When `.gitattributes` sets `working-tree-encoding` to something other than UTF-8, the diff editor decodes the git HEAD/index side using the working-tree encoding instead of the object-database encoding, garbling that side and marking the whole file as changed.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/127441 and fix the git extension's buffer retrieval (currently `git show --textconv` in extensions/git/src/git.ts) to honor working-tree-encoding, e.g. via `git cat-file --filters` as confirmed working by a commenter on this thread.
