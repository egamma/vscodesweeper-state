# Issue #340279 — Workspace settings change is dropped when a `.code-workspace` file changes folders and settings at the same time

[https://github.com/microsoft/vscode/issues/340279](https://github.com/microsoft/vscode/issues/340279)

## Summary

Confirmed on current main: when a `.code-workspace` edit changes both folders and workspace settings in the same write, the workspace-settings configuration change event is dropped because a local `change` variable shadows the outer one before it's used.

## Change summary

External edits to a `.code-workspace` file that change folders and settings simultaneously silently drop the settings change (no `onDidChangeConfiguration`, stale `getConfiguration().get()`).

## Best solution

In `updateWorkspaceConfiguration` (configurationService.ts), merge the outer workspace-settings `change` with the folder change (e.g. `mergeChanges(change, folderChange)`, as already done in `onWorkspaceFolderConfigurationChanged` at line 939) before calling `triggerConfigurationChange`, instead of letting the inner `const change = await this.onFoldersChanged()` shadow it.
