# Issue #199939 — `createSession` passes in a set of scopes and the session returned shouldn't need to match those scopes

[https://github.com/microsoft/vscode/issues/199939](https://github.com/microsoft/vscode/issues/199939)

## Summary

Keep open: current source still leaves pending sign-in requests uncleared when a successful extension-initiated sign-in returns different scopes. The Accounts-menu command clears its own request directly, but that does not cover the broader reported behavior.

## Change summary

Clear a fulfilled authentication sign-in request without requiring the returned session scopes to equal the requested scopes.

## Best solution

Ensure successful authentication completes the originating pending request independently of returned scope equality, while preserving independent requests for other authentication contexts.
