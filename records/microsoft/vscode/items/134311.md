# Issue #134311 — Language detection server retains 5Mb if not cleaned up

[https://github.com/microsoft/vscode/issues/134311](https://github.com/microsoft/vscode/issues/134311)

## Summary

The language-detection worker still retains its loaded model after detection becomes idle; text-model cleanup does not release that worker or its model. Keep this accepted, team-authored performance issue open: no qualifying fix or canonical duplicate was established.

## Change summary

Release language-detection worker memory when detection is no longer needed, while allowing subsequent detection to resume.

## Best solution

Give the language-detection worker a bounded idle lifetime without interrupting active requests or changing detection results. Establish the idle policy and measure current browser memory savings versus worker/model reload latency before implementation.

## Evidence

- **Current worker lifetime:** In src/vs/workbench/services/languageDetection/browser/languageDetectionWorkerServiceImpl.ts, LanguageDetectionWorkerClient.detectLanguage creates the worker when URI-based guessing fails. _getOrCreateLanguageDetectionWorker caches the worker and synchronization client in this.worker and registers both for owner disposal; there is no idle termination or reset path.
- **Model retention:** In src/vs/workbench/services/languageDetection/browser/languageDetectionWebWorker.ts, getModelOperations caches ModelOperations in _modelOperations, with weights loaded using response.arrayBuffer().
