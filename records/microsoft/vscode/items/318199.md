# Issue #318199 — Wrong GIT_EDITOR configuration breaks all tools

[https://github.com/microsoft/vscode/issues/318199](https://github.com/microsoft/vscode/issues/318199)

## Summary

The quotes are intentional: GIT_EDITOR is a shell-interpreted command, not a raw filesystem path. Passing that command directly to cygpath or wslpath does not demonstrate an incorrect VS Code configuration.

## Change summary

Remove the quotes around the Git editor script in GIT_EDITOR so path-conversion tools accept its value directly.

## Best solution

Preserve command quoting so editor paths containing spaces work. Path-conversion integrations should distinguish an editor command from its executable path; users who manage their own editor command can disable git.terminalGitEditor.

- **Proposed comment:**

  > Thanks for the report. `GIT_EDITOR` is a shell command, not a raw path: Git explicitly supports quoted executable paths and additional arguments (https://git-scm.com/docs/git-var). VS Code quotes the script path so locations containing spaces work correctly.
  > 
  > Passing the entire command to `cygpath` or `wslpath` treats those quotes as filename characters; path conversion needs to operate on the executable path rather than the complete editor command. If you prefer to configure your own editor command, disable `git.terminalGitEditor` and restart the terminal. The quoting itself is working as designed.

## Evidence

- **Git's documented contract:** https://git-scm.com/docs/git-var explicitly states that GIT_EDITOR is interpreted by the shell and illustrates a quoted Windows executable path followed by arguments. Neither GIT_EDITOR nor core.editor is guaranteed to contain a bare path.
- **Current source:** extensions/git/src/gitEditor.ts:29–34 deliberately constructs GIT_EDITOR as a quoted script path. GitEditor.getTerminalEnv() at lines 61–64 exposes it only when git.useEditorAsCommitInput and git.terminalGitEditor are enabled; extensions/git/src/terminal.ts passes the value unchanged through environmentVariableCollection.replace(). This matches the reported quoted value.
- **Reported trigger:** https://github.com/microsoft/vscode/issues/318199 demonstrates cygpath and wslpath receiving the entire shell command as one filesystem-path argument. It does not show Git failing to invoke the configured editor. Removing quoting would instead break shell interpretation of paths containing spaces.
