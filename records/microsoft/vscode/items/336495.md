# Issue #336495 — Menus: MenuInfo runs the full collect+sort twice on every construction

[https://github.com/microsoft/vscode/issues/336495](https://github.com/microsoft/vscode/issues/336495)

## Summary

Traced this directly in src/vs/platform/actions/common/menuService.ts: MenuInfoSnapshot's constructor calls this.refresh(), which virtually dispatches to MenuInfo's overridden _sort (the real sort), and then MenuInfo's own constructor calls this.refresh() again — so every MenuInfo construction sorts and collects context keys twice, with the first pass's result thrown away. Real, still-present perf bug on main; good candidate for a quick fix.

## Change summary

MenuInfo construction runs the full menu collect+sort twice per instance because both MenuInfoSnapshot's base constructor and MenuInfo's derived constructor call refresh(), and virtual dispatch means the base call already does the expensive sort.

## Best solution

Remove the redundant this.refresh() call in MenuInfo's constructor (menuService.ts), or restructure MenuInfoSnapshot to not call refresh() from its own constructor and let each concrete subclass call it exactly once, keyed off a guard so the sort method is resolved before use.
