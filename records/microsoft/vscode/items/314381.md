# Issue #314381 — Integrated terminals can inherit env vars from a previously opened repository/session

[https://github.com/microsoft/vscode/issues/314381](https://github.com/microsoft/vscode/issues/314381)

## Summary

Valid bug: when VS Code is launched via `code .` from a terminal with direnv-set variables, the main process inherits those variables and propagates them to integrated terminals in subsequent windows. The `isLaunchedFromCli` path in shellEnv.ts skips environment resolution and preserves the launching shell's env, which then leaks to all windows in the session.

## Change summary

Integrated terminals in one VS Code window inherit project-specific environment variables (set by direnv) from a different repository's session, because the VS Code main process environment is shared across all windows.

## Best solution

The terminal process manager should consider per-window shell environment resolution rather than relying solely on the shared main-process environment. The `isLaunchedFromCli` shortcut in `src/vs/platform/shell/node/shellEnv.ts` preserves the launching terminal's full env for all windows — a per-window env-stripping or re-resolution mechanism (at least for non-VS Code env vars) would fix this. Related prior work: issues #15452 and #108804 addressed startup latency but not the cross-window contamination case.

## Evidence

- **code path:** src/vs/platform/shell/node/shellEnv.ts: when `isLaunchedFromCli(env)` is true (VSCODE_CLI set), `getResolvedShellEnv` returns `{}` — meaning the process keeps its inherited env as-is, including direnv variables from the launching shell.
- **architectural limitation:** VS Code runs as a single Electron main process; subsequent `code .` invocations send IPC to the existing process. The main process environment (set at first launch) persists for all windows.
- **prior work:** https://github.com/microsoft/vscode/issues/15452 (closed, moved to #108804) addressed per-window env inconsistencies but focused on startup latency, not cross-workspace env contamination from direnv/dotenv.
- **related issue:** https://github.com/microsoft/vscode/issues/319200 reports similar cross-workspace terminal state leakage (working directory from another workspace).
