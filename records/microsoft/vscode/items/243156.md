# Issue #243156 — SCM Graph - auto should include default branch when checked out detached

[https://github.com/microsoft/vscode/issues/243156](https://github.com/microsoft/vscode/issues/243156)

## Summary

The detached-checkout gap remains in current source: Auto drops the branch context and selects only the detached revision. Keep this already-routed Backlog request open; the verified related issues do not cover the same detached-checkout behavior.

## Change summary

Include the default branch and its upstream in SCM Graph Auto mode while HEAD is detached, preserving an easy route back to branch history.

## Best solution

Define detached Auto mode to retain useful default-branch context alongside the checked-out revision, without changing named-branch Auto selection. The likely implementation boundary is GitHistoryProvider’s current-reference calculation, which feeds the SCM graph filter.

## Evidence

- **Detached behavior remains:** extensions/git/src/historyProvider.ts:174-180 explicitly clears both _currentHistoryItemRemoteRef and _currentHistoryItemBaseRef for a detached commit. resolveHEADMergeBase at lines 542-549 also returns undefined when HEAD has no branch name.
- **Auto filter consumes the cleared references:** src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:1394-1408, _resolveHistoryItemFilter, builds Auto from historyItemRef, historyItemRemoteRef and historyItemBaseRef, filtering out undefined entries. After detached checkout, this leaves only the checked-out revision rather than independently including default-branch tips.
- **Existing capabilities are workarounds:** HistoryItemRefPicker in src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:1495-1590 supports All and explicit reference selection, but makes these mutually exclusive with Auto. The scm.graph settings in scm.contribution.ts do not provide detached default-branch inclusion; git.defaultBranchName is documented in extensions/git/package.nls.json as controlling new-repository initialization, not graph selection.
- **Older related issue is not the same symptom:** https://github.com/microsoft/vscode/issues/240489 is open and older, but concerns selecting or manually overriding a named branch’s merge base. Its discussion identifies branch creation on another machine as the source of missing default-branch context, not detached checkout: https://github.com/microsoft/vscode/issues/240489#issuecomment-2732894346. It does not meet the same-observable-symptom duplicate bar for this re-reviewed item.
