# Issue #185678 — Allow to recover directories from local history

[https://github.com/microsoft/vscode/issues/185678](https://github.com/microsoft/vscode/issues/185678)

## Summary

Directory-scoped recovery remains missing: current local history lets users find saved versions, including those of deleted files, but recovery still proceeds one file at a time. This accepted Backlog request has 37 upvotes; the related Git folder-timeline issue does not clearly own bulk recovery of uncommitted local history.

## Change summary

Allow users to browse and recover multiple files within a directory from local history after accidental deletion or a destructive Git reset.

## Best solution

Provide directory-scoped browsing of retained local-history entries, including missing files, with a deliberate multi-file recovery workflow. Agree on revision-selection and overwrite semantics before implementation, without implying that per-file history constitutes an atomic directory snapshot.

Existing single-file recovery must remain unchanged.
- **Behavior:**

  > Users recovering from accidental deletion or a destructive Git reset currently have to locate and restore retained versions one file at a time. The requested workflow should expose local history for files within a selected directory, including files no longer present on disk, and make recovery across multiple files practical. Acceptance must cover nested paths, deleted files, existing files with newer contents, and preservation of unselected files. Recovery must remain limited to versions actually retained by local history.
- **Trace:**

  > workbench.action.localHistory.restoreViaPicker in src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts already obtains all resources with retained entries, but its two pickers choose one resource and one entry. LocalHistoryTimeline.provideTimeline() in src/vs/workbench/contrib/localHistory/browser/localHistoryTimeline.ts retrieves entries for one URI rather than descendants. WorkingCopyHistoryService.getAll() and getEntries() in src/vs/workbench/services/workingCopy/common/workingCopyHistoryService.ts provide resource enumeration and per-file history; the contract in workingCopyHistory.ts contains no atomic directory snapshot. Preserve existing single-file commands, capture and retention settings, and Git-provider behavior. https://github.com/microsoft/vscode/issues/95332 is related folder-timeline work, but its Git-focused request does not settle local-history bulk-recovery semantics. The remaining uncertainty is the user-facing recovery contract, not whether a per-file enumeration mechanism exists.
- **Open decisions:**
  - Should recovery let users choose a version independently for each selected file, or restore each file's latest retained version at or before a shared time?
  - Should the initial feature provide directory-scoped browsing with explicit per-file restoration, or include a bulk restore action?
  - When restoring multiple files over existing or unsaved contents, should users receive one aggregate confirmation or a per-file review and conflict choice?
