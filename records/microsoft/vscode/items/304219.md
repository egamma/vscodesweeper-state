# Issue #304219 — Right arrow doesn't open thinking effort UI on first press

[https://github.com/microsoft/vscode/issues/304219](https://github.com/microsoft/vscode/issues/304219)

## Summary

Still reproduces on main: when the model picker opens with focusFilterOnOpen, DOM focus is on the filter input (which lives outside the list's domNode), so the ArrowRight keydown listener on the list's domNode never fires until the user presses Up/Down (which moves DOM focus to the list).

## Change summary

Pressing the right arrow key to open the thinking effort submenu in the model picker does not work on the first press when the picker is opened via mouse.

## Best solution

Move the ArrowRight keydown handler (or a duplicate) so it also covers events originating from the filter input. The simplest fix is to check for ArrowRight in the same way focusPrevious/focusNext handle filter-input focus: either attach the listener to a shared parent, or add a parallel ArrowRight handler on the filter input that delegates to the submenu-open logic. The fix is localized to `src/vs/platform/actionWidget/browser/actionList.ts`.

But the filter input is created in a separate `_filterContainer` (line ~808) that is positioned as a sibling of `this.domNode` (line ~1340), not inside it. When `focusFilterOnOpen: true` (used by the model picker at src/vs/workbench/contrib/chat/browser/widget/input/chatModelPicker.ts line 1424), DOM focus goes to the filter input on open, so the ArrowRight keydown event never reaches `this.domNode`.
- **why Up/Down fixes it:** The `focusPrevious()`/`focusNext()` methods (lines ~1405, ~1442) are invoked via ActionWidgetService keybinding commands and explicitly call `this._list.domFocus()` when the filter has focus, moving DOM focus to the list. After that, ArrowRight works because the keydown fires on `this.domNode`.
