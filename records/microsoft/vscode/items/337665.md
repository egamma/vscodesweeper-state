# Issue #337665 — VSCode 1.139 forces rounded corners of Window Frame on Linux

[https://github.com/microsoft/vscode/issues/337665](https://github.com/microsoft/vscode/issues/337665)

## Summary

Real, unaddressed regression: a recent Electron bump now forces rounded window corners on Linux and VS Code exposes no `roundedCorners: false` override anywhere in its BrowserWindow construction, matching the report exactly. It's already assigned to the Electron/window maintainer (deepak1556) but carries no labels or PR yet, so routing it is the useful action.

## Change summary

On Linux, VS Code's window frame now has forced rounded corners (an Electron/Chromium default change) with no setting to disable them; `window.titleBarStyle: native` avoids it but loses the custom title bar controls.

## Best solution

Expose a Linux-only window setting (mirroring the existing Windows-only `window.border`) that maps to Electron's `BrowserWindowConstructorOptions.roundedCorners`, defaulting to current behavior but letting users opt out.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/workbench/electron-browser/desktop.contribution.ts`, `src/vs/workbench/electron-browser/window.ts`
- **Validation:** Manual check: with the new setting off/disabled, launch VS Code on a Linux desktop without compositor-level rounding and confirm the window frame renders square corners; with it on (or absent), current rounded-corner behavior is unchanged.
- **Behavior:**

  > On Linux, users should be able to opt out of the rounded corners that current Electron versions apply to the custom (non-native) title bar window frame, similar to how `window.border` lets Windows users control border rendering. With the new setting disabled, the window frame renders with square corners; leaving it at its default preserves today's (rounded) behavior so nothing breaks for users who like it or who use `window.titleBarStyle: native`.
- **Trace:**

  > `defaultBrowserWindowOptions` in src/vs/platform/windows/electron-main/windows.ts builds the `BrowserWindowConstructorOptions` consumed by `new electron.BrowserWindow(options)` in src/vs/platform/windows/electron-main/windowImpl.ts:796; it never sets `roundedCorners`, so Electron's Linux default (rounded corners, per the reporter and Electron's own `roundedCorners` option docs) applies unconditionally whenever the custom title bar is used (`hideNativeTitleBar` branch at windows.ts:209-235, which sets `frame: false` on non-macOS). The precedent is `window.border` (desktop.contribution.ts:320, `included: isWindows`) — a similarly platform-scoped setting read via `IConfigurationService` and applied in `defaultBrowserWindowOptions`. Boundary: do not touch macOS/Windows frame handling or the native-titlebar path; scope any new setting to `isLinux` and the custom-title-bar branch only. Refs: https://github.com/microsoft/vscode/issues/153233 (unrelated, opposite ask), https://github.com/microsoft/vscode/issues/326146 (unrelated, Modern UI toggle).
- **Open decisions:**
  - Should this be a new dedicated setting (e.g. a Linux-only `window.cornerStyle`/`roundedCorners` toggle) or folded into an existing window-chrome setting?
  - Should the new option default to disabled (square corners, matching most Linux desktop themes) or keep rounded as default and let users opt out?
