# Issue #206914 — Add option to increase the clickable space between the gutter and the first character of the line

[https://github.com/microsoft/vscode/issues/206914](https://github.com/microsoft/vscode/issues/206914)

## Summary

The older, open issue https://github.com/microsoft/vscode/issues/135114 already covers clickable padding before the first character, not merely visual spacing. Consolidate this clearer restatement there, preserving its explicit click-and-drag requirement and workaround limitations.

## Change summary

Provide additional space between the gutter and line text where clicking places the cursor at column one and dragging starts a normal text selection.

## Best solution

Track the missing clickable editor padding in https://github.com/microsoft/vscode/issues/135114, retaining this report's acceptance criteria: column-one cursor placement and partial-line drag selection without disabling folding or changing line-number behavior.

## Evidence

- **Verified canonical:** Read the body and discussion of https://github.com/microsoft/vscode/issues/135114 and verified its current OPEN state. Created on 2021-10-14, it predates this report and requests both gutter-to-text padding and the ability to click that padding to place the cursor at the start of the nearest line.
- **Exact interaction already documented:** The same reporter explicitly requested clickable space for selecting text to or from the beginning of a line in https://github.com/microsoft/vscode/issues/135114#issuecomment-1745885374. Their later comment https://github.com/microsoft/vscode/issues/135114#issuecomment-1800827121 reiterates that cursor placement in the added space is crucial. This establishes the same observable requirement, rather than merely a related aesthetic request.
- **Existing capability does not cover the request:** src/vs/editor/common/config/editorOptions.ts registers only editor.padding.top and editor.padding.bottom in EditorPadding. Its layout calculation places contentLeft directly after lineDecorationsWidth. In src/vs/editor/browser/controller/mouseTarget.ts, HitTestRequest classifies coordinates before contentLeft as margin, and _hitTestMargin returns GUTTER_LINE_DECORATIONS for the remaining gutter region. Increasing lineDecorationsWidth therefore enlarges gutter space rather than adding the requested text-selection padding.
- **Workarounds and demand:** This report has 42 upvotes and is accepted into Backlog; inactivity is not grounds for declining it. The discussion offers hiding folding controls, keyboard navigation, and https://github.com/cooltools2077/line-number-cursor-plugin-for-vscode, but the reporter explicitly notes that line-number selection does not support selecting only the first part of a line and asks whether the plugin permits rightward dragging. These limitations belong with the canonical request.
