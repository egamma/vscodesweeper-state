# Issue #89826 — Tab does not work as a trigger character for 

[https://github.com/microsoft/vscode/issues/89826](https://github.com/microsoft/vscode/issues/89826)

## Summary

Keep open for a decision on Tab-triggered completions: current source still separates indentation commands from typed-character triggers, matching the maintainer's explanation. Existing completion settings do not cover the requested provider-specific invocation after indentation.

## Change summary

Allow completion providers to request automatic invocation when Tab indents the document, including when indentation inserts spaces.

## Best solution

Define whether registering '\t' should opt a provider into completions after Tab indentation, and what trigger context it receives when spaces are inserted. Preserve normal indentation, snippet navigation, and completion acceptance behavior.

- **Behavior:**

  > An extension author wants suggestions to appear after pressing Tab to indent a blank YAML line beneath a mapping key. Registering '\t' currently does not deliver that behavior, whether indentation inserts tabs or spaces. Planning must settle the provider opt-in and trigger context, then validate both indentation modes without changing unrelated Tab interactions.
- **Trace:**

  > SuggestModel._updateTriggerCharacters in src/vs/editor/contrib/suggest/browser/suggestModel.ts observes onDidType and composition completion; the Tab command in src/vs/editor/browser/coreCommands.ts instead executes TypeOperations.tab. CodeEditorWidget._type in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts emits the typing event for keyboard-originated typing, explaining the distinction described in the issue. editor.tabCompletion accepts completions and editor.action.triggerSuggest explicitly requests them; neither supplies automatic provider-specific invocation after indentation. The related Flow report at https://github.com/flow/flow-for-vscode/issues/385 confirms demand outside YAML. Preserve indentation, snippet navigation, focus movement, and suggestion acceptance; uncertainty begins at the observable meaning of a '\t' registration when the resulting document edit contains spaces.
- **Open decisions:**
  - Should registering '\t' opt a completion provider into invocation after the Tab indentation command even when that command inserts spaces, and, if so, should CompletionContext.triggerCharacter report '\t'?
