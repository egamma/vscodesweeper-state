# Issue #327454 — Environment variables from the first VS Code launch carry over to later windows

[https://github.com/microsoft/vscode/issues/327454](https://github.com/microsoft/vscode/issues/327454)

## Summary

This is as-designed behavior of VS Code's shared main process architecture. On Windows, the main process inherits the environment of the first launcher and reuses it for subsequent windows — documented at the link a contributor already provided. The `--user-data-dir` flag or pre-launching an empty window are the intended workarounds.

## Change summary

Environment variables from the shell that first launched VS Code carry over into later windows opened from different shells.

## Best solution

Close as as-designed. The shared main process architecture intentionally works this way on Windows (shell env resolution is explicitly skipped on Windows in `src/vs/platform/shell/node/shellEnv.ts`). The isolation documentation covers the workaround. Feature work to refresh environment per-window would be tracked under https://github.com/microsoft/vscode/issues/47816.
