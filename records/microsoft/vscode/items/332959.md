# Issue #332959 — Add Auto Tier recommendation to usage notifications

[https://github.com/microsoft/vscode/issues/332959](https://github.com/microsoft/vscode/issues/332959)

## Summary

A real gap remains on current main: quota notifications can only recommend generic Auto, while the Auto response and routing layers do not yet carry the server's recommended next-cheaper tier. This team-authored, On Deck request should remain open for the Auto model area.

## Change summary

Use CAPI's advisory `recommended_auto_tier` value to recommend and select the next-cheaper Auto tier in usage notifications.

## Best solution

Carry the validated server recommendation from Auto routing into the quota-notification context, then present an action that starts a new Auto session configured for that tier without changing the current session.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts`, `extensions/copilot/src/platform/endpoint/node/automodeService.ts`, `extensions/copilot/src/platform/endpoint/node/test/automodeService.spec.ts`, `src/vs/workbench/contrib/chat/browser/chatQuotaNotification.ts`, `src/vs/workbench/contrib/chat/test/browser/chatQuotaNotification.test.ts`
- **Validation:** Extend the Auto routing tests to verify valid `recommended_auto_tier` values are surfaced and invalid values are ignored, then extend chatQuotaNotification.test.ts to verify the usage warning names and configures the recommended tier while retaining the generic fallback when no recommendation is available.
- **Behavior:**

  > At an eligible usage checkpoint, a server-provided next-cheaper Auto tier should replace the generic Auto recommendation with a recommendation for that specific tier. Accepting it starts a new Auto session configured for the recommended tier; it must not alter the current Auto session. Missing, invalid, or inapplicable recommendations retain the existing generic or budget-management behavior.
- **Trace:**

  > POST /auto is parsed as AutoV2Response in extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts and consumed by AutomodeService in automodeService.ts, but the response type and routing state contain no recommendation today. The notification is independently built by ChatQuotaNotificationContribution in src/vs/workbench/contrib/chat/browser/chatQuotaNotification.ts and currently emits a generic SwitchToModel action. That action infrastructure already supports schema-filtered configuration through `IChatInputNotificationSwitchToModelAction.config`, so the unresolved boundary is transporting and retaining the advisory value between the extension-owned Auto response and workbench-owned quota UI. Preserve current-session tier immutability, existing treatment eligibility, managed-plan handling, and fallback notification behavior.
- **Open decisions:**
  - How long and at what scope should a recommendation from an Auto response remain applicable: only to its originating conversation, to the active chat input, or across later sessions until usage state changes?
  - When the recommendation is available while the user is already in an Auto session, should the usage notification offer starting a new session at that tier or continue showing the existing budget-management action?

## Evidence

- **server contract:** The maintainer clarified that CAPI returns advisory `recommended_auto_tier` values `intelligence`, `balance`, or `efficiency` after at least 75% usage, and that applying one must start a new Auto session rather than mutate the current session.
- **response gap:** extensions/copilot/src/platform/endpoint/node/autoV2Fetcher.ts defines `AutoV2Response` without `recommended_auto_tier`; extensions/copilot/src/platform/endpoint/node/automodeService.ts consumes the response for model, token, discount, and cache state but does not surface a tier recommendation.
- **current notification:** src/vs/workbench/contrib/chat/browser/chatQuotaNotification.ts currently renders the generic text `Switch to Auto to reduce credit usage.` and targets Auto without tier configuration.
- **existing action capability:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputNotificationService.ts already permits a SwitchToModel action to include schema-filtered model configuration, and chatInputNotificationWidget.ts applies that configuration after selecting the model.
- **current test coverage:** src/vs/workbench/contrib/chat/test/browser/chatQuotaNotification.test.ts asserts the generic Auto recommendation, while extensions/copilot/src/platform/endpoint/node/test/automodeService.spec.ts is the existing Auto routing test surface.
