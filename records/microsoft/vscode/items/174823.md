# Issue #174823 — Workspace Trust - should be made accessible more easily.

[https://github.com/microsoft/vscode/issues/174823](https://github.com/microsoft/vscode/issues/174823)

## Summary

A real discoverability gap remains: trusted workspaces expose the management editor primarily through the Command Palette, while the status-bar affordance intentionally exists only for Restricted Mode. The Backlog and under-discussion classification protects this accepted request from a decline close.

## Change summary

Make the Workspace Trust management editor easier to find after a workspace has been trusted, such as through an existing settings or management menu.

## Best solution

Keep the status bar focused on Restricted Mode warnings, but expose the existing “Manage Workspace Trust” command through an appropriate existing settings or management menu so users can review and remove trusted folders without knowing the command name.

- **Fit:** aligned
- **Reason:** Improving discoverability for a security control through an existing menu supports both workspace security and consistent core UX without adding persistent chrome.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts`
- **Validation:** In a trusted workspace, verify that the chosen existing menu exposes “Manage Workspace Trust,” opens the Workspace Trust editor, and leaves the status-bar warning hidden; repeat in an untrusted workspace and verify the existing Restricted Mode entry still works.
- **Behavior:**

  > Users must be able to discover and open the Workspace Trust management editor after the current workspace has been trusted, without remembering or searching for its Command Palette name. The affordance should use an existing management surface rather than adding an always-visible trusted-state warning. Opening it must show the existing trusted-folders management UI, while Restricted Mode behavior remains unchanged.
- **Trace:**

  > `workbench.trust.manage` is registered in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts as an F1 command that opens WorkspaceTrustEditorInput. The same file's WorkspaceTrustUXHandler deliberately removes `status.workspaceTrust` when trust is granted. A contextual link also exists in src/vs/workbench/contrib/preferences/browser/settingsEditorSettingIndicators.ts, but only for settings affected by trust. The persistent-status-icon option conflicts with the later maintainer explanation at https://github.com/microsoft/vscode/issues/170664#issuecomment-5107669675; preserve that warning-only lifecycle. The uncertainty begins at selecting the existing global menu where the command should appear.
- **Open decisions:**
  - Which existing settings or management menu should permanently expose “Manage Workspace Trust” in trusted workspaces?

## Evidence

- **current command surface:** src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts registers `workbench.trust.manage` with `f1: true`, making it available through the Command Palette, but does not contribute it to a settings or management menu.
- **status-bar lifecycle:** WorkspaceTrustUXHandler.updateStatusbarEntry in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts clears `status.workspaceTrust` when the workspace becomes trusted and creates it only while untrusted.
- **partial existing access:** src/vs/workbench/contrib/preferences/browser/settingsEditorSettingIndicators.ts links to `workbench.trust.manage` only from the contextual “Requires workspace trust” indicator; this does not provide general access for reviewing trusted folders.
- **related design decision:** A maintainer explained at https://github.com/microsoft/vscode/issues/170664#issuecomment-5107669675 that the status-bar icon is intentionally a Restricted Mode warning and that a persistent trusted-state indicator would be a separate feature request. That precedent covers the proposed persistent icon, but not this issue's broader request for a discoverable menu entry.
- **canonical search:** Searches for Workspace Trust management and status-bar issues found no open, older issue with the same observable request. https://github.com/microsoft/vscode/issues/170664 is closed and only concerns persistence of the status-bar icon, so it cannot serve as a duplicate canonical.
