# Issue #176277 — tasks.json npm script does not work with arguments on Mac

[https://github.com/microsoft/vscode/issues/176277](https://github.com/microsoft/vscode/issues/176277)

## Summary

The macOS failure is the same observable npm-task argument-quoting defect documented in the older, still-open canonical issue. Consolidate there, preserving the macOS reproduction and workaround; the reported Windows recovery does not establish a macOS fix.

## Change summary

Npm tasks on macOS quote the script name and appended arguments together, preventing npm from running the intended script.

## Best solution

Resolve script-name versus argument handling under https://github.com/microsoft/vscode/issues/139937, preserving script names containing spaces while supporting separately passed arguments across shells.

The maintainer confirmed reproduction with Git Bash and identified separate npm-task arguments as the needed capability: https://github.com/microsoft/vscode/issues/139937#issuecomment-1007533126. This is the same reporter-observable failure, not merely a related feature.
- **Canonical includes macOS:** https://github.com/microsoft/vscode/issues/139937#issuecomment-1508358301 explicitly reports the same inability to pass --debug to an npm task on Mac. The canonical therefore encompasses this platform-specific report rather than covering only a narrower Windows case.
- **Current source confirms the quoted-script path:** In extensions/npm/src/tasks.ts, NpmTaskProvider.resolveTask passes kind.script unchanged to createScriptRunnerTask. getRunScriptCommand appends that entire string as one argument; escapeCommandLine at lines 308–316 marks whitespace-containing arguments with -- as ShellQuoting.Weak. In src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts, quote at lines 1660–1664 wraps weak-quoted values and quoteIfNecessary at lines 1681–1689 honors the explicit quoting. Thus script: "build -- --sourcemap" remains one quoted script argument on macOS, matching the Sonoma/zsh report.
- **Linked merged PR is a downstream workaround:** https://github.com/microsoft/vscode-edu-extension/pull/2096 changed that repository's .vscode/tasks.json from npm tasks to shell tasks with command: "npm" and separate args arrays. Its diff does not fix VS Code's npm task provider.
- **Discussion distinguishes Windows recovery from macOS defect:** The supplied discussion confirms the macOS failure on Ventura and Sonoma, including VS Code 1.87.0 with zsh and the generated command npm run "build -- --sourcemap". The later v1.104 recovery concerns a Windows PowerShell regression and does not confirm resolution of the macOS report.
