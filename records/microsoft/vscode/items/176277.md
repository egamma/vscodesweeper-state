# Issue #176277 — tasks.json npm script does not work with arguments on Mac

[https://github.com/microsoft/vscode/issues/176277](https://github.com/microsoft/vscode/issues/176277)

## Summary

Thanks for the report. Two other users confirmed it on macOS (Ventura and Sonoma). The current npm task code still passes the whole script string, arguments included, as one quoted argument to `npm run`. A fix would need a decision on how npm task arguments should be expressed.

## Change summary

An npm task whose `script` includes arguments (e.g. `build -- --flag`) is run as a single quoted argument to `npm run` and fails on macOS.

## Best solution

Give npm tasks a robust way to pass arguments, as requested in https://github.com/microsoft/vscode/issues/139937. Until then, the `shell` task type with `command` and `args` is the workaround. Fixing this properly should also resolve the Windows variant.

## Plan brief

- **Likely files:** `extensions/npm/src/tasks.ts`, `extensions/npm/package.json`
- **Validation:** Create an npm task whose script is 'build -- --flag' and check on macOS that it runs `npm run build -- --flag` rather than a single quoted argument.
- **Behavior:**

  > An npm task with a script containing arguments (e.g. `build -- --sourcemap`) runs the script with those arguments on macOS, Linux and Windows in each supported shell. Existing script names that contain spaces must keep working.
- **Trace:**

  > `getRunScriptCommand` and `escapeCommandLine` in extensions/npm/src/tasks.ts build `ShellExecution(scriptRunner, ['run', script])`. The script is passed whole, either quoted as a single argument or, since `escapeCommandLine` uses Weak quoting when it contains '--', quoted with expansion allowed, so npm receives one argument. The boundary is the other consumers of `getRunScriptCommand` (the npm explorer and the hover or run actions). Related: https://github.com/microsoft/vscode/issues/139937 and https://github.com/microsoft/vscode/issues/115876.
- **Open decisions:**
  - Add an explicit `args` property to the npm task definition, split the `script` string into arguments, or both?
  - Should a script string that includes arguments remain supported for backward compatibility?

## Evidence

- **code path:** extensions/npm/src/tasks.ts: `getRunScriptCommand` pushes the raw `script` as one argument. `escapeCommandLine` wraps it in a quoting object, using Weak quoting when it contains '--' and Strong otherwise. The result is `npm run "build -- --sourcemap"`, which matches the output reported in comment 3.
- **confirmations:** Comments 2 and 3 independently confirm the failure on macOS (Ventura, Sonoma/zsh 1.87.0). Comment 4 reports a related Windows PowerShell quoting failure that was later fixed in 1.104 per that commenter.

- **no fix found:** git log on extensions/npm/src/tasks.ts shows no change that splits the arguments out of the script string. I did not run it on macOS.
