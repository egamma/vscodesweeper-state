# Issue #45368 — Emmet completions disappear when using bem in the presence of other snippets

[https://github.com/microsoft/vscode/issues/45368](https://github.com/microsoft/vscode/issues/45368)

## Summary

Keep open: the discussion confirms a completion-provider retriggering defect, not merely an ordering preference, and current source retains the empty-result limitation. The linked older issue is closed; the newer related request cannot serve as a duplicate target under the re-review rules.

## Change summary

Keep Emmet completions available when typing a BEM filter through an intermediate empty result while other snippets remain visible.

## Best solution

Allow the completed BEM abbreviation to appear without requiring Escape followed by Ctrl+Space. Coordinate the Emmet behavior with the empty-incomplete-list contract discussed in https://github.com/microsoft/vscode/issues/155738, preserving ordinary snippet matching and ranking.

## Evidence

- **Confirmed diagnosis and workaround:** In the supplied discussion of https://github.com/microsoft/vscode/issues/45368, ramya-rao-a confirms that Emmet returns no completions at the intermediate '|be' prefix and is not consulted when the final 'm' is typed. Escape followed by Ctrl+Space restores completion; the comment proposes addressing retriggering or returning a provisional Emmet completion.
- **Current completion-model limitation:** src/vs/editor/contrib/suggest/browser/completionModel.ts, getIncompleteProvider(), only recognizes providers with a nonempty item array whose first item's container is incomplete. src/vs/editor/contrib/suggest/browser/suggest.ts, provideSuggestionItems(), stores completion items but no independently retriggerable empty list; suggestModel.ts:771–789 builds its incomplete-provider retrigger set from those retained items.
- **Current Emmet boundary:** extensions/emmet/src/defaultCompletionProvider.ts delegates abbreviation validation and completion generation to the Emmet helper and returns new vscode.CompletionList(newItems, true). That incomplete flag alone cannot preserve retriggering when newItems is empty. The current helper's exact '|b' → '|be' → '|bem' output was not executed, so current end-to-end reproduction remains unverified despite the historical confirmation.
- **Ordering is not the missing capability:** extensions/emmet/package.json registers emmet.showSuggestionsAsSnippets, and extensions/emmet/package.nls.json documents combining it with editor.snippetSuggestions for ordering. This can prioritize an existing Emmet result but cannot recover one omitted because its provider was not retriggered.

Its maintainer discussion describes empty completion results being intentionally discarded, and its closing comment cites backlog grooming rather than a fix. It is neither an open duplicate canonical nor evidence that this Emmet defect was implemented.
