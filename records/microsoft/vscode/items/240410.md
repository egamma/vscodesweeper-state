# Issue #240410 — `IConfigurationChangeEvent.affectsConfiguration` does not support `overrides` properly for default changes

[https://github.com/microsoft/vscode/issues/240410](https://github.com/microsoft/vscode/issues/240410)

## Summary

The defect remains source-reproducible on current main: default configuration updates mutate the model retained as the previous configuration, so changed keys inside a language override can disappear from the event. The open related PR explicitly does not address this override gap.

## Change summary

Language-specific default configuration changes can fail to make `affectsConfiguration` report the affected nested setting.

## Best solution

Make default-override change events retain enough pre-change state to report every changed nested key for the affected override identifier, then cover the in-place default-model update path with a regression test.

## Evidence

- **shared mutable model:** src/vs/workbench/services/configuration/browser/configurationService.ts constructs Configuration with `this.defaultConfiguration.configurationModel`; src/vs/platform/configuration/common/configurations.ts later mutates that same ConfigurationModel in `updateConfigurationModel` before firing the change event.
- **lost override keys:** src/vs/platform/configuration/common/configurationModels.ts:909-928 derives nested override keys by comparing `_defaultConfiguration` with `defaults`. Because both can reference the already-mutated model, the comparison at lines 917-923 yields no nested changes.
- **observable failure path:** ConfigurationChangeEvent only adds nested keys supplied in `change.overrides` to `affectedKeys` at src/vs/platform/configuration/common/configurationModels.ts:1235-1243. Without those keys, `affectsConfiguration('editor', { overrideIdentifier: 'markdown' })` returns before its value comparison, leaving consumers such as src/vs/workbench/browser/parts/editor/textEditor.ts unaware of the default change.
- **test gap:** The existing `Test compare and update default configuration` case in src/vs/platform/configuration/test/common/configurationModels.test.ts:1124-1138 compares two distinct ConfigurationModel instances, so it does not exercise the shared in-place model used by WorkspaceService.
- **related PR:** https://github.com/microsoft/vscode/pull/332624 is open but explicitly states that https://github.com/microsoft/vscode/issues/240410 is a different override-identifier gap not addressed by that PR.
- **canonical search:** The later https://github.com/microsoft/vscode/issues/290703 only cited this issue among several possible causes and was closed for missing information; it does not own this specific defect, and no older canonical report was found.
