# Issue #325473 — Terminal file links should resolve relative paths using the terminal's current working directory

[https://github.com/microsoft/vscode/issues/325473](https://github.com/microsoft/vscode/issues/325473)

## Summary

The requested behavior — resolving relative terminal links against the terminal's current working directory — is already implemented via shell integration's CWD tracking (`getCwdForLine` in `updateLinkWithRelativeCwd`). The fallback to `initialCwd` occurs only when shell integration is unavailable or doesn't report CWD correctly, which is likely the case in MINGW64/Git Bash.

## Change summary

Relative file paths in terminal output should resolve against the terminal's current working directory rather than the workspace root or initial CWD.

## Best solution

The feature already exists: `TerminalLocalLinkDetector.detect()` resolves relative paths against the per-line CWD reported by shell integration (`CommandDetection.getCwdForLine`). If the reporter's terminal (MINGW64/Git Bash) doesn't support shell integration CWD reporting, the fallback to `initialCwd` is by design. The reporter should verify shell integration is active (`terminal.integrated.shellIntegration.enabled`) and working in their shell.
