# Issue #330927 — Banner for pending Copilot comments in agent review sessions

[https://github.com/microsoft/vscode/issues/330927](https://github.com/microsoft/vscode/issues/330927)

## Summary

Current main already displays counted agent-review and PR-comment banners with Address Comments and Reveal actions, but it does not fully match the requested resolution and persistence semantics. Keep this team-authored request open for the owner to reconcile those remaining requirements with the existing experience.

## Change summary

Surface pending Copilot review comments in an accessible session banner with a count, viewing and resolution actions, and persistence until resolution or dismissal.

## Best solution

Build on the existing SessionInputBanners experience rather than adding another banner. Agree whether Address Comments satisfies the requested Resolve action and whether accepted-but-unresolved comments should remain visible, then address only the confirmed gaps.

- **Behavior:**

  > The active review session should expose pending Copilot comments through a non-blocking banner with an accurate count and accessible actions to inspect and handle them. Main already provides counted banners, Reveal, Address Comments, and session-scoped dismissal. The remaining acceptance contract must distinguish sending comments to an agent from marking them resolved and specify whether the banner stays visible while accepted comments are still unresolved. Verify the agreed behavior in both in-product agent reviews and pull-request reviews, including zero comments and explicit dismissal.
- **Trace:**

  > SessionInputBanners in src/vs/sessions/contrib/sessionInputBanners/browser/sessionInputBanners.ts filters feedback to AgentFeedbackState.Created and separates AgentReview items from PRReview items associated with each pull request. _agentCommentActions and _pullRequestActions expose Address Comments and Reveal; _addressComments calls acceptFeedback before submitFeedback, so acceptance removes items from the counted state without requiring resolution. AgentFeedbackService in src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts maintains separate acceptance and resolution transitions. SessionInputBannerWidget already provides status semantics, labeled buttons, dismissal, and focus restoration; preserve that infrastructure and existing CI and multi-PR behavior. The uncertainty is the product contract, not where to place a guard: whether the current agent-submission action is sufficient and how unresolved accepted feedback should remain represented. https://github.com/microsoft/vscode/issues/332973 concerns outside-session notifications and is not a duplicate or part of this narrow banner scope.
- **Open decisions:**
  - Does Address Comments, which submits the suggestions to an agent, satisfy Resolve, or should the banner also offer explicit resolution with or without confirmation?
  - Should the banner count and remain visible for accepted or submitted comments until they are resolved, or should it intentionally represent only comments awaiting user triage?
