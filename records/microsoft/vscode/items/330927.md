# Issue #330927 — Banner for pending Copilot comments in agent review sessions

[https://github.com/microsoft/vscode/issues/330927](https://github.com/microsoft/vscode/issues/330927)

## Summary

Current main already provides counted, dismissible review-comment banners with Reveal and Address Comments actions, but addressing comments is not the requested resolve operation. Keep this team-authored request open to settle that remaining behavior; no qualifying issue-referencing implementation or canonical duplicate was established.

## Change summary

Surface pending Copilot review comments in an accessible session banner with a count, navigation, and a resolve action.

## Best solution

Reuse the existing Sessions input banner rather than introduce another notification surface. Decide whether its action should resolve review comments directly, confirm bulk resolution, or retain the current agent-addressing workflow, then reconcile the acceptance criteria and implementation.

The request additionally calls for resolving pending comments, directly or through confirmation, while the existing banner instead asks the agent to address them. Acceptance must distinguish accepting feedback for agent processing from resolving a review thread, and define when the banner disappears. Keyboard and screen-reader users must be able to discover and invoke the actions.
- **Trace:**

  > SessionInputBanners in src/vs/sessions/contrib/sessionInputBanners/browser/sessionInputBanners.ts already renders Created PRReview and AgentReview feedback for completed sessions, with per-session dismissal and reactive count updates. Its Reveal action calls revealFeedback; Address Comments accepts feedback and submits /act-on-feedback, which is not a direct thread-resolution operation. AgentFeedbackPRReviewSeederContribution mirrors unresolved GitHub review threads into session feedback, while CodeReviewService exposes resolvePRReviewThread as a separate operation. Existing SessionInputBanners tests cover PR counts, action scoping, and dismissal. Preserve session/PR targeting, CI-banner behavior, and provider-neutral Sessions boundaries; do not add a second competing banner. https://github.com/microsoft/vscode/issues/332973 concerns visibility outside the active session and remains separate. The uncertainty is the intended user-facing resolution contract, not where to place a helper.
