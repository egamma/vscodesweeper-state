# Issue #163939 — Support validating all markdown files in a workspace

[https://github.com/microsoft/vscode/issues/163939](https://github.com/microsoft/vscode/issues/163939)

## Summary

Keep this accepted Markdown feature request open: the existing validation settings and tab-based diagnostic configuration do not expose validation of every Markdown file under a chosen folder. The linked iteration plans show maintainer interest, but do not establish completion.

## Change summary

Support validating all Markdown files in a configurable workspace or parent-folder scope, including files that are not open.

## Best solution

Extend the built-in Markdown validation experience to report diagnostics for unopened files within a selected folder scope, with explicit performance and exclusion semantics. Establish those observable behaviors before implementing workspace-wide diagnostic collection.

- **Reason:** Extending existing Markdown diagnostics to a project scope supports first-class language tooling and the developer inner loop, provided large-workspace performance is preserved.

- **Behavior:**

  > Users should be able to validate all Markdown files in a chosen workspace or parent-folder scope without opening every document. Diagnostics should identify invalid links in unopened files and cease reporting them when the underlying problems are resolved. Acceptance must cover nested folders, scope exclusions, and preservation of existing document-level validation when the broader behavior is disabled.
- **Trace:**

  > startClient in extensions/markdown-language-features/src/client/client.ts configures diagnostic pulls on changes and tabs and exposes findMarkdownFilesInWorkspace, which enumerates Markdown files while excluding node_modules. The existing settings in package.json select validation categories, and _markdown.toggleValidation in src/languageFeatures/diagnostics.ts only changes markdown.validate.enabled; neither exposes the requested scan scope. The extension consumes vscode-markdown-languageserver and vscode-markdown-languageservice 0.5.0, so planning must establish which workspace-diagnostic capabilities that server actually supports before defining the implementation boundary. The project-wide linting entries in https://github.com/microsoft/vscode/issues/187398 and https://github.com/microsoft/vscode/issues/189778 show interest, not a landed implementation. Preserve existing validation categories and ordinary document/tab behavior; avoid assuming that workspace file enumeration already produces diagnostics.
- **Open decisions:**
  - Should folder-wide validation run continuously when enabled, run only on an explicit command, or support both modes?
  - What folder-selection contract should support the requested parent-directory scope, including directories outside the opened workspace?
  - Which exclusions should govern the scan, and should diagnostics be removed immediately when a file leaves the configured scope?
