# Issue #266331 — `gitDecoration.ignoredResourceForeground` does not respect `git.decorations.enabled`

[https://github.com/microsoft/vscode/issues/266331](https://github.com/microsoft/vscode/issues/266331)

## Summary

The bug remains on current main: ignored-file decorations are registered unconditionally, while `git.decorations.enabled` controls only the other Git decoration providers. This is a bounded lifecycle defect in the built-in Git extension.

## Change summary

Disabling `git.decorations.enabled` should also remove the Explorer foreground color applied to ignored files.

## Best solution

Make the ignored-resource decoration provider follow the same enablement lifecycle as the other Git decoration providers, including reacting immediately when `git.decorations.enabled` changes.

## Evidence

- **source reproduction:** `extensions/git/src/decorationProvider.ts` constructs `GitIgnoreDecorationProvider` unconditionally in the `GitDecorations` constructor. Its decoration always uses `gitDecoration.ignoredResourceForeground`.
- **setting bypass:** In the same file, `GitDecorations.update()` applies `git.decorations.enabled` only through `enable()` and `disable()`, which manage `GitDecorationProvider` and `GitIncomingChangesFileDecorationProvider`; the ignored-file provider remains registered in `this.disposables` when the setting is false.
- **documented expectation:** `extensions/git/package.nls.json` describes `git.decorations.enabled` as controlling whether Git contributes colors and badges to the Explorer and Open Editors view, which includes the ignored-resource foreground color.
