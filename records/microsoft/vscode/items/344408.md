## Evidence

- **Confirmed schema workaround:** The reporter confirmed that correcting the configuration to use mcpServers restored chat: https://github.com/microsoft/vscode/issues/344408#issuecomment-6472918245. Another user independently reported migration breaking MCP and session history, resolved by the same correction: https://github.com/microsoft/vscode/issues/344408#issuecomment-6602876382. This supports a configuration/schema failure, not proof of a missing Windows path separator.
- **Later persistence reports:** Deleting mcp-writer.binding and mcp-writer.lock restored Copilot for additional users, including https://github.com/microsoft/vscode/issues/344408#issuecomment-6897626403 and https://github.com/microsoft/vscode/issues/344408#issuecomment-7005929599. These are workarounds, not evidence that the underlying defect was fixed.
- **Current configuration boundary:** src/vs/platform/mcp/common/mcpCopilotGlobalConfiguration.ts:53–71 accepts an object without mcpServers and treats it as an empty server list. In contrast, the reported runtime error requires mcpServers. src/vs/workbench/contrib/chat/browser/aiCustomization/mcpServerCustomizationMigration.ts:607–639 initializes missing target files with mcpServers but does not establish recovery for every existing malformed configuration.
- **Session startup dependency:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:9434–9438 awaits client.rpc.mcp.config.list() in _disabledRootMcpServers. The configuration read is therefore part of the launch enablement path; the inspected method does not handle a rejected configuration read locally. Runtime propagation and writer-state ownership remain unconfirmed.
- **Path construction:** src/vs/platform/environment/common/copilotHome.ts constructs the default directory with join(userHomePath, '.copilot') and then joins mcp-config.json, while honoring COPILOT_HOME. The inspected helper does not concatenate username and .copilot without a separator.
- **No verified canonical or fix:** Exact-error and writer-state searches found no open canonical reporting the same symptom. https://github.com/microsoft/vscode/issues/332782 describes migration support broadly, while https://github.com/microsoft/vscode/issues/343548 concerns marketplace installation destinations rather than chat-blocking validation. No open PR mentioning this issue was found. Commit 8b86ea560f440dda8b24fc7e685e48ac4c6e08ec only adds editor schema associations for a different issue; it does not repair this failure.
