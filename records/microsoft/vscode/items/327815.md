# Issue #327815 — Error when launching the VSCode via Code.exe

[https://github.com/microsoft/vscode/issues/327815](https://github.com/microsoft/vscode/issues/327815)

## Summary

Real, well-diagnosed bug: `createEnv()` in the utility-process fork path clones `process.env` and forwards it to Electron's `utilityProcess.fork` without stripping keys that aren't valid JS identifiers (e.g. digit-leading names like `16`), which Electron's ForkUtilityProcess rejects with `TypeError: Invalid value for env`, killing the extension host before any extension can load.

## Change summary

Launching Code.exe (not the code.cmd/CLI path) throws 'Invalid value for env' from ForkUtilityProcess and no extensions load, when an invalid-named environment variable (e.g. a digit-leading name like SharePoint's `16`) is present in the process environment.

## Best solution

In `createEnv()` (src/vs/platform/utilityProcess/electron-main/utilityProcess.ts), filter out env entries whose keys are not valid environment-variable identifiers (letters/digits/underscore, not starting with a digit) before calling `utilityProcess.fork`, alongside the existing `removeDangerousEnvVariables` call — this keeps the forwarded env electron-safe regardless of what odd variables the OS/other installers injected.
