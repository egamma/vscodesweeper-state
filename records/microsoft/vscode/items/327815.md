# Issue #327815 — Error when launching the VSCode via Code.exe

[https://github.com/microsoft/vscode/issues/327815](https://github.com/microsoft/vscode/issues/327815)

## Summary

Confirmed on main: `UtilityProcess.createEnv` in electron-main forks the extension host with a raw copy of `process.env`/host env and only strips a hardcoded 'dangerous' variable set, without validating variable names — so an environment variable whose name starts with a digit (a real-world case here: SharePoint's `16` var) passes straight to Electron's `utilityProcess.fork`, which throws `TypeError: Invalid value for env` and aborts the extension host, breaking all extensions when VS Code is launched via Code.exe.

## Change summary

Launching VS Code via Code.exe (not via bin/code.cmd) fails to start the extension host and no built-in extensions load, when an inherited environment variable has a name starting with a digit.

## Best solution

In `src/vs/platform/utilityProcess/electron-main/utilityProcess.ts`'s `createEnv`, filter out (or otherwise sanitize) environment variable keys that aren't valid identifiers (e.g. don't match `/^[A-Za-z_][A-Za-z0-9_]*$/`) before passing `env` to `utilityProcess.fork`, mirroring the existing `removeDangerousEnvVariables`/`sanitizeProcessEnvironment` pattern in `src/vs/base/common/processes.ts` so it's unit-testable the same way.

- **root cause identified by commenter:** https://github.com/microsoft/vscode/issues/327815#issuecomment (jeremia, 2026-08-14): traced the failure to an environment variable name starting with a digit (Node/Electron require env var names to start with a letter or underscore); removing such a variable (e.g. the SharePoint-created `16` var) resolves the crash. - **why code.cmd works but Code.exe doesn't:** bin/code.cmd forks the extension host through the regular node.js child_process path (e.g. src/vs/base/parts/ipc/node/ipc.cp.ts, which has no name-format validation but also isn't going through Electron's stricter utilityProcess.fork), whereas the desktop shortcut launches the main Electron process which uses UtilityProcess.fork for the extension host — explaining why only the .exe launch path is affected.
