# Issue #334496 — Fills with first prompt not changed prompt

[https://github.com/microsoft/vscode/issues/334496](https://github.com/microsoft/vscode/issues/334496)

## Summary

The defect is present on current main: resubmitting an inline-edited request sends the changed prompt but records history through the main input after the inline input has been disposed. This team-authored bug should remain open for a bounded chat-widget fix.

## Change summary

After changing and resending a failed prompt, Arrow Up restores the original prompt instead of the changed prompt.

## Best solution

Ensure request resubmission records the submitted inline input state in chat history before that input is torn down, while preserving the existing main-input draft and normal history behavior.
