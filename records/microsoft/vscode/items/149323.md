# Issue #149323 — Support for updatable/async menus and submenus

[https://github.com/microsoft/vscode/issues/149323](https://github.com/microsoft/vscode/issues/149323)

## Summary

The async-menu capability remains absent on current main, and Electron declined the required native-menu support. This team-authored, accepted Backlog item should remain open while the menus area decides between a VS Code-owned custom-menu solution and renewed upstream work.

## Change summary

Allow menus and submenus to populate or replace their entries asynchronously while displayed, so context-sensitive refactorings and source actions are discoverable in place.

## Best solution

Provide an updatable menu abstraction that can initially show a loading entry and replace it with asynchronously resolved code actions without dismissing the menu. Given Electron's decision, the practical path is likely the custom HTML menu infrastructure while preserving existing native-menu behavior unless Electron gains equivalent support.

## Evidence

- **current native path:** src/vs/workbench/services/contextmenu/electron-browser/contextmenuService.ts synchronously calls delegate.getActions() and serializes the complete menu before popup; src/vs/base/parts/contextmenu/common/contextmenu.ts models submenu contents only as arrays.
- **Electron implementation:** src/vs/base/parts/contextmenu/electron-main/contextmenu.ts recursively constructs every Electron MenuItem before menu.popup(), with no channel or callback for replacing visible submenu contents.
- **custom menu limitation:** src/vs/platform/contextview/browser/contextMenuHandler.ts likewise snapshots delegate.getActions() and constructs one Menu when the context view renders; no asynchronous update contract is present.
- **upstream decision:** Electron closed https://github.com/electron/electron/issues/528 as not planned in https://github.com/electron/electron/issues/528#issuecomment-2597433985, leaving the native-menu dependency unresolved.
- **related older request:** https://github.com/microsoft/vscode/issues/110218 remains open and concerns an extension API for runtime-contributed submenu definitions.
