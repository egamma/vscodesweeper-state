# Issue #194313 — Command center - make it leaner?

[https://github.com/microsoft/vscode/issues/194313](https://github.com/microsoft/vscode/issues/194313)

## Summary

The request remains unsatisfied: the editor window still reserves a 35px title bar with Command Center enabled. Keep it open for a design decision on a leaner default versus an optional compact mode, preserving usable controls and window dragging across platforms.

## Change summary

Reduce the title bar's vertical footprint while retaining Command Center.

## Best solution

Provide a more space-efficient Command Center title bar consistent with workbench density conventions, without compromising window controls or dragging. Decide whether this becomes the default or an opt-in density mode before implementation.

- **Validation:** After agreeing the behavior, compare the editor-window title bar with Command Center enabled before and after at zoom levels 0 and -0.5 on macOS, Windows, and Linux. Verify the selected compact behavior reduces vertical space while preserving unclipped menus, keyboard focus, window controls, and usable drag regions in both narrow and wide windows; verify unchanged behavior outside the selected scope.
- **Behavior:**

  > Users want to keep Command Center while spending less vertical space on the editor-window title bar. The current 35px title bar feels disproportionately large, and the thread suggests evaluating a 28px alternative rather than aggressively shrinking all controls. Acceptance should demonstrate a smaller vertical footprint under the agreed default or compact mode, with usable buttons, keyboard navigation, and window dragging across supported platforms. Disabling Command Center is not fulfillment of this request.
- **Trace:**

  > DEFAULT_CUSTOM_TITLEBAR_HEIGHT in src/vs/platform/window/common/window.ts is 35. BrowserTitlebarPart.minimumHeight in src/vs/workbench/browser/parts/titlebar/titlebarPart.ts uses it when Command Center is visible; NativeTitlebarPart.minimumHeight in src/vs/workbench/electron-browser/parts/titlebar/titlebarPart.ts does the same on macOS. The registered window.density.editorTabHeight setting affects editor title controls, while window.density.layout does not enter these Command Center height calculations. BrowserTitlebarPart.preventZoom intentionally preserves window-control sizing at negative zoom, so the later zoom observation must not be treated as permission to remove that safeguard. Preserve platform window controls, draggable regions, and unrelated title bars. https://github.com/microsoft/vscode/issues/152578 was consolidated into this issue; https://github.com/microsoft/vscode/issues/168671 supplies broader density-design context. The uncertainty is the user-facing density policy and supported compact height, not whether the inspected height remains 35px.
- **Open decisions:**
  - Should the leaner Command Center title bar become the editor-window default or be enabled through an opt-in compact density mode?
  - What compact height should be supported across platforms while preserving usable controls and drag regions, given the proposed 28px alternative and concerns about 22px?
