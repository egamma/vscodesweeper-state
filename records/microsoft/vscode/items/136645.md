# Issue #136645 — [json] Explorer Outline view shows wrong int values when viewing JSON document

[https://github.com/microsoft/vscode/issues/136645](https://github.com/microsoft/vscode/issues/136645)

## Summary

The defect remains in the current JSON language service: numeric tokens are parsed as JavaScript numbers and then converted back to strings for outline details, losing precision for integers beyond the safe range. Keep this open and track the correction through the upstream language-service dependency.

## Change summary

Preserve the exact textual representation of large JSON integers when displaying values in the Explorer Outline.

## Best solution

Update `vscode-json-languageservice` so document-symbol details preserve the original numeric token text rather than round-tripping through a JavaScript number, add a large-integer regression test there, and then consume the corrected dependency in VS Code.

## Evidence

- **current VS Code path:** `extensions/json-language-features/server/src/jsonServer.ts` still delegates hierarchical outline generation to `vscode-json-languageservice.findDocumentSymbols2`; `extensions/json-language-features/server/package.json` currently depends on `vscode-json-languageservice` 6.0.0-next.4.
- **source-confirmed root cause:** Current upstream `src/services/jsonDocumentSymbols.ts` sets each symbol's detail through `getDetail(valueNode)`, which returns `String(node.value)` for numbers, while `src/parser/jsonParser.ts` creates numeric AST values with `JSON.parse(tokenValue)`. Thus `1457573422205218818` is rounded before the outline converts it back to text: https://github.com/microsoft/vscode-json-languageservice/blob/main/src/services/jsonDocumentSymbols.ts
- **maintainer confirmation:** The maintainer comment identifies the unsafe JavaScript-number conversion and explicitly states that the outline can preserve the value without converting it to a number and back.
- **canonical search:** No older open issue with the same reporter-observable JSON Outline precision symptom was found. https://github.com/microsoft/vscode/issues/111203 concerns launch.json numeric handling, while the younger https://github.com/microsoft/vscode/issues/147621 concerned Sort JSON and is closed; neither qualifies as a canonical duplicate for this re-reviewed issue.
