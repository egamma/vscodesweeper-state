# Issue #350262 — automations should report their run summary

[https://github.com/microsoft/vscode/issues/350262](https://github.com/microsoft/vscode/issues/350262)

## Summary

Keep open: current run history exposes execution lifecycle, not an automation-reported task result. This team-authored request covers broader work than the linked notification and warning requests; the related protocol proposal still has unresolved outcome semantics.

## Change summary

Let automations report task success or a need for human attention independently of session lifecycle, potentially including generated artifacts.

## Best solution

Agree on task-result semantics with microsoft/agent-host-protocol#575, then carry run-owned results through host persistence, provider projection, and automation history. Preserve the distinction between execution completion and achieving the automation's intended task; decide artifact reporting scope before implementation.

Verify history distinguishes their task outcomes without changing lifecycle status, retains results after host restart and client reconnect, and remains usable with hosts that omit the optional fields.
- **Behavior:**

  > An automation can report what its run accomplished and whether a person needs to act, independently of whether execution completed normally. Users can inspect that result from automation history without opening the transcript. Runs without reported results retain their existing behavior. Whether generated artifacts are part of the initial result surface remains a scope decision.
- **Trace:**

  > The current AHP run lifecycle in src/vs/platform/agentHost/common/state/protocol/channels-automation-run/state.ts carries timestamps, usage, or execution errors but no typed task result. IAutomationRun in src/vs/workbench/contrib/chat/common/automations/automation.ts and AgentHostAutomationStore._projectRun in src/vs/workbench/contrib/sessions/providers/agentHost/browser/agentHostAutomationStore.ts likewise expose lifecycle rather than task achievement. AutomationRunSession in src/vs/sessions/contrib/automations/browser/automationRunHistory.ts derives execution status and forwards session artifacts, which is not run-owned result reporting. Host execution and persistence belong to AgentHostAutomationService according to src/vs/sessions/AUTOMATIONS.md; that implementation path still needs diagnosis during planning. Coordinate semantics with https://github.com/microsoft/agent-host-protocol/issues/575; generated protocol files are synchronized from that repository, not edited locally. Preserve existing session lifecycle, provider neutrality, and compatibility with hosts that do not publish results.
- **Open decisions:**
  - Which task outcomes should users see: success and needs-attention only, or a distinct nothing-to-do outcome as well?
  - Should the initial feature include run-scoped artifact references, or only summary and task outcome?
  - How should an automation-reported attention result affect notification and warning indicators independently of execution failure?
