# Issue #331750 — VS Code Snap leaves processes running after exit and blocks updates

[https://github.com/microsoft/vscode/issues/331750](https://github.com/microsoft/vscode/issues/331750)

## Summary

Real, well-documented Snap-packaging issue: crashpad_handler and a dconf watcher process survive VS Code's exit and keep the systemd user scope alive, which can block snapd refreshes. It's unlabeled despite already having a maintainer (deepak1556) assigned, so this needs routing rather than closing.

## Change summary

On the classic-confinement Snap build, chrome_crashpad_handler and a `dconf watch` helper process outlive VS Code after normal exit, keeping the `snap.code.code-*.scope` active and sometimes blocking pending snap refreshes.

## Best solution

Investigate whether the Snap launcher (resources/linux/snap/electron-launch) or the crashpad/dconf spawn path can be made to terminate its children when the main Electron process exits (e.g. process-group/scope cleanup), since this is Snap classic-confinement-specific process lifecycle behavior rather than a general Electron bug; label it `snap` so the assigned owner can track it.
