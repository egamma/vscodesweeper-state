# Issue #331750 — VS Code Snap leaves processes running after exit and blocks updates

[https://github.com/microsoft/vscode/issues/331750](https://github.com/microsoft/vscode/issues/331750)

## Summary

Well-documented, reproducible-sounding report specific to the classic-confinement Snap build: crashpad_handler and a dconf watch process survive after VS Code exits, keeping the systemd scope alive and blocking snap refresh. This is a real packaging/lifecycle issue but is environment-dependent (systemd/snapd process tracking) and can't be verified purely from source, so routing to the Snap/Linux owners rather than closing.

## Change summary

On the official Snap build, helper processes (chrome_crashpad_handler, a dconf watch) don't terminate when VS Code closes, so the snap.code.code-*.scope stays active and snapd refuses to refresh the Snap.

## Best solution

Snap/Linux packaging maintainers should investigate whether the electron-launch wrapper or app exit path needs to ensure child helper processes are reaped so the systemd scope for the classic-confinement snap terminates cleanly; likely involves resources/linux/snap/snapcraft.yaml and how crashpad_handler/dconf watch processes are spawned/tracked.
