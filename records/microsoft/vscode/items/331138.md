# Issue #331138 — Slash commands never submit when the resolved command has no readable content

[https://github.com/microsoft/vscode/issues/331138](https://github.com/microsoft/vscode/issues/331138)

## Summary

Well-diagnosed bug, still present on main, with an open fixing PR (#331145) already in flight — keeping open so a human lands that PR rather than treating this as fixed or auto-fixable.

## Change summary

Accepting a slash-command completion whose backing resource has no readable content (e.g. discovery-only built-in skills) throws inside resolvePromptSlashCommand, silently blocking message submission — most severe for remote/dev-container sessions where nearly all offered completions are affected.

## Best solution

Land #331145 (or an equivalent fix) making the prompt-file parse in `resolvePromptSlashCommand` best-effort, matching the tolerant pattern already used by `promptFilePickers`; verify it also covers the case where completions include ~49/50 agent-builtin skill entries as described in the reporter's later comment.
