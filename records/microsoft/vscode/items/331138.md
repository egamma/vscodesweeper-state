# Issue #331138 — Slash commands never submit when the resolved command has no readable content

[https://github.com/microsoft/vscode/issues/331138](https://github.com/microsoft/vscode/issues/331138)

## Summary

Confirmed defect on main: `resolvePromptSlashCommand` (chatInputEditorContrib.ts:341, via customizationHarnessService.ts:634) parses a command's URI unconditionally even though built-in skill commands are discovery-only with no readable content, so accepting such a completion silently blocks message submission. The reporter already opened a fixing PR, so this should stay open pending review/merge rather than being closed now.

## Change summary

Accepting a slash-command completion whose backing resource has no readable content (e.g. a built-in skill in a remote/dev-container window) makes the chat input never submit, with no error surfaced to the user.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/331145, which makes `parsedPromptFile` optional in `resolvePromptSlashCommand` so an unreadable command URI resolves best-effort instead of throwing; the PR includes a new regression test and updates the two consumers (`chatWidget.ts`, `chatSessions.contribution.ts`) that dereferenced the field.
