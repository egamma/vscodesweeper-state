# Issue #144893 — Toggle all files in "refactor previews"

[https://github.com/microsoft/vscode/issues/144893](https://github.com/microsoft/vscode/issues/144893)

## Summary

Keep open: current Refactor Preview supports toggling individual files and categories, but has no preview-wide check/uncheck action. The related requests do not provide an older canonical covering this capability, and the Backlog milestone records accepted, unscheduled work.

## Change summary

Provide a preview-wide check/uncheck control so users can deselect generated checkpoints before selecting the files they actually want to refactor.

## Best solution

Provide an explicit, keyboard-accessible way to clear all checked changes across the entire Refactor Preview, then select individual files without discarding the preview. Settle the complementary check-all or toggle semantics without changing initial confirmation defaults or language-provider rename scope.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEdit.contribution.ts`, `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditPane.ts`, `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditTree.ts`, `src/vs/workbench/contrib/bulkEdit/test/browser/bulkEditPreview.test.ts`
- **Validation:** Manually preview a rename spanning ordinary files and generated checkpoint files, including collapsed rows. Clear all checks, select only ordinary files, and apply; only the selected files should change. Repeat with category grouping and mixed checked states, exercise the control by keyboard, and retain the BulkEditPreview suite's confirmation-default and category-selection checks.
- **Behavior:**

  > A rename preview containing many checkpoint files currently requires users to uncheck files individually before selecting a small desired subset. Users should be able to clear all checked changes across the preview without discarding it, including changes beneath collapsed rows, and then select individual files to apply. Applying must affect only the chosen changes. Existing initial checkbox defaults and per-file selection behavior must remain unchanged.
- **Trace:**

  > refactorPreview.toggleCheckedState in bulkEdit.contribution.ts delegates to BulkEditPane.toggleChecked() in bulkEditPane.ts, which toggles only the first focused element. The tree disables multiple selection, while FileElement.setChecked() and CategoryElement.setChecked() in bulkEditTree.ts operate at file and category scope. CheckedStates and BulkFileOperations in bulkEditPreview.ts maintain checked edits and produce the accepted workspace edit. Source inspection found no registered preview-wide selection control. Keep language-provider search scope, initial needsConfirmation behavior, and Apply/Discard semantics outside this request. https://github.com/microsoft/vscode/issues/207579 provides related demand but concerns category-checkbox visibility, not an older canonical for this issue.
- **Open decisions:**
  - Should the preview expose separate Check All and Uncheck All actions, or a single state-dependent toggle; if a single toggle is chosen, what should it do when only some changes are checked?
