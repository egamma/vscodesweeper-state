# Issue #334900 — VS Code integrated browser cannot complete Microsoft certificate authentication

[https://github.com/microsoft/vscode/issues/334900](https://github.com/microsoft/vscode/issues/334900)

## Summary

Traced a real gap on main: the integrated browser's Electron session never registers a `select-client-certificate` handler, so a corporate mTLS/Windows Hello certificate challenge is left unanswered and the request times out — matching the reported `ERR_TIMED_OUT`. Routing to the browser-view owners rather than closing.

## Change summary

The VS Code integrated browser (used by Copilot Chat) hangs and times out on a Microsoft certificate-authentication step that native Edge completes via Windows Hello.

## Best solution

Add an `app.on('select-client-certificate', …)` handler for the integrated browser's session (src/vs/platform/browserView/electron-main/browserView.ts / browserSession.ts), similar in spirit to the existing `login` (HTTP basic auth) handler at browserView.ts:407, so the OS can present a certificate/Windows Hello prompt instead of letting the request hang; the existing webPageLoader.ts handler (line 97) only calls `event.preventDefault()` with no certificate and is for a different, headless feature so it's not a template to copy as-is.

- **browserView event handlers:** src/vs/platform/browserView/electron-main/browserView.ts registers `login` (HTTP basic auth, line 407), `certificate-error` (via BrowserSessionTrust, for *server* cert trust decisions), `select-bluetooth-device`, etc., but no `select-client-certificate` handler anywhere in src/vs/platform/browserView.
- **cert trust code is server-cert only:** src/vs/platform/browserView/electron-main/browserSessionTrust.ts handles `setCertificateVerifyProc` and `certificate-error` for TLS server certificates (self-signed proxy cert, user-trusted exceptions) — a separate concern from client certificate (mTLS) selection.
