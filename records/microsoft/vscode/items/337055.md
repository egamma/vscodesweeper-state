# Issue #337055 — Modern UI ignores sideBarSectionHeader.background

[https://github.com/microsoft/vscode/issues/337055](https://github.com/microsoft/vscode/issues/337055)

## Summary

The reported behavior is intentional in Modern UI: section headers explicitly use their containing side bar's background, overriding the legacy section-header background. Source comments, explicit test expectations, and a maintainer-approved merged styling PR establish this as a design choice rather than an accidental theming regression.

## Change summary

Allow side bar section headers to retain a separately customized background when Modern UI is enabled.

## Best solution

Keep Modern UI's deliberate surface-matching section headers and explain which color tokens remain effective. Supporting an independently colored header in this mode would require a separate customization decision, not a correction to the existing implementation.

- **Fit:** aligned
- **Reason:** Preserving theme customization fits the project's settings-fidelity theme, although that does not establish that this particular legacy color must override the modern header design.
- **Evidence:** Durable theme: Workbench & core UX — layout flexibility, profiles, settings fidelity.

- **Proposed comment:**

  > Thanks for the report. Modern UI deliberately makes section headers match the surrounding side bar at rest, so `sideBar.background` controls their background and `sideBarSectionHeader.background` is overridden. This treatment was introduced in https://github.com/microsoft/vscode/pull/331485; `sideBarSectionHeader.border` still controls section dividers, and `list.hoverBackground` controls the header hover tint.
  > 
  > Closing as designed: restoring a separate section-header background in Modern UI would be a change to that customization behavior rather than a fix to its current implementation.
