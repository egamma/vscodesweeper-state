# Issue #337055 — Modern UI ignores sideBarSectionHeader.background

[https://github.com/microsoft/vscode/issues/337055](https://github.com/microsoft/vscode/issues/337055)

## Summary

Traced in source: Modern UI deliberately overrides the pane-header background to match `sideBar.background` (and `panel.background`) so headers read as part of the body rather than a tinted strip, so `sideBarSectionHeader.background` never applies there — this is documented, intentional behavior, not an oversight.

## Change summary

With `workbench.experimental.modernUI` enabled, `sideBarSectionHeader.background` no longer colors side bar section headers.

## Best solution

Keep the current Modern UI behavior — it's intentional per the code comment and README; if desired, the request would be a new Modern UI-specific color override rather than reusing `sideBarSectionHeader.background`, but that's a design choice for the Modern UI owners, not a bug fix.

## Evidence

- **override rule:** src/vs/workbench/contrib/modernUI/browser/media/paneHeaders.css:82-84 sets `.modern-ui :is(.part.sidebar, .part.auxiliarybar) .monaco-pane-view .pane > .pane-header { background-color: var(--vscode-sideBar-background) !important; }`, overriding any `sideBarSectionHeader.background` value.
- **documented intent:** Comment at paneHeaders.css:74-77: 'let the header match its surface at rest so it reads as part of the panel / side bar body rather than a tinted strip. The inline header background from the PaneView is overridden here.'
- **README confirms only border customization remains:** src/vs/workbench/contrib/modernUI/README.md:76 states 'Side bar section dividers use `sideBarSectionHeader.border`' — only the border color is called out as applicable in Modern UI, not the background.
- **not a regression:** git log on paneHeaders.css shows no recent change; the override has been the design since the file's introduction.
