# Issue #343570 — Copilot remote codebase index fails for Azure DevOps orgs in a non-home tenant (ADO token requested without tenant)

[https://github.com/microsoft/vscode/issues/343570](https://github.com/microsoft/vscode/issues/343570)

## Summary

Keep open: current source confirms that ADO index requests acquire credentials without organization or tenant context, matching the reported cross-tenant failure. The report provides sufficient reproduction details; tenant-aware authentication needs investigation across credential acquisition and repository authorization state.

## Change summary

Copilot remote indexing fails for Azure DevOps repositories in a tenant different from the signed-in account's home tenant, sometimes exposing an HTML-response JSON parsing error.

## Best solution

Make ADO remote indexing and search authenticate against the organization's tenant while preserving existing home-tenant behavior and repository authorization invalidation. Authentication failures should produce actionable diagnostics rather than an unexplained JSON SyntaxError.

## Evidence

- **Tenant context is absent in current source:** extensions/copilot/src/platform/authentication/vscode-node/authenticationService.ts: AuthenticationService.getAnyAdoSession requests only the ADO resource scope and offline_access, uses a single 'ado' TaskSingler key, and stores one _anyAdoSession. Neither it nor getAdoAccessTokenBase64 accepts organization context.
- **Reported trigger follows the affected path:** The reporter signs in with a Tenant A account, opens a repository belonging to Tenant B, and collects workspace index diagnostics. In extensions/copilot/src/platform/remoteCodeSearch/common/adoCodeSearchService.ts:158-165, getRemoteIndexStateImpl obtains credentials through getAdoAuthToken(auth.silent) before constructing the organization-specific endpoint; lines 393-394 forward only the silent option to authentication.
- **Tenant-scoped provider capability already exists:** extensions/microsoft-authentication/src/common/scopeData.ts: ScopeData.getTenant recognizes VSCODE_TENANT:<tenantId>, otherwise defaults to organizations. Copilot's ADO session request does not supply that scope; this is a missing integration, not evidence that Microsoft Authentication lacks tenant support.
- **HTML response explains the secondary symptom:** extensions/copilot/src/platform/remoteCodeSearch/common/adoCodeSearchService.ts checks unsuccessful HTTP responses, mapping 401/403 to not-authorized, but subsequently calls result.json() without checking for an HTML response. A successful-status HTML response can therefore surface the reported SyntaxError; the actual remote response was not independently exercised.
