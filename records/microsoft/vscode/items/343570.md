# Issue #343570 — Copilot remote codebase index fails for Azure DevOps orgs in a non-home tenant (ADO token requested without tenant)

[https://github.com/microsoft/vscode/issues/343570](https://github.com/microsoft/vscode/issues/343570)

## Summary

Keep open: current source still requests ADO authentication without organization or tenant context. The supplied cross-tenant steps suffice to retest; the reported server response remains unverified, and the older authorization report does not establish the same tenant-specific defect.

## Change summary

Copilot remote indexing fails for Azure DevOps repositories outside the signed-in account's home tenant and surfaces an HTML response as a JSON parsing error.

## Best solution

Make remote-index authentication honor the Azure DevOps organization's tenant while preserving account selection and same-tenant behavior. Authentication failures should produce actionable diagnostics rather than a JSON SyntaxError.

- **Behavior:**

  > An account with access to an Azure DevOps repository in a non-home tenant should be able to retrieve its Copilot remote-index status. Authentication for one organization must not prevent access to another organization in a different tenant. Same-tenant authentication and account selection must remain unchanged. An HTML authentication response should yield an actionable authentication diagnostic rather than a JSON parsing exception.
- **Trace:**

  > AdoCodeSearchService.getRemoteIndexStateImpl has the repository organization but obtains its token through getAdoAuthToken(silent), which forwards only authentication options. AuthenticationService.getAnyAdoSession uses fixed resource scopes, one shared 'ado' task key, and a single cached session; neither it nor the indexing sign-in helpers accepts tenant context. The Microsoft provider's ScopeData already recognizes VSCODE_TENANT scopes. Successful HTTP responses are parsed directly as JSON, consistent with the reported HTML parsing error, but actual cross-tenant session selection and server responses have not been reproduced. Establish those behaviors first; preserve GitHub authentication, local-search fallback, and existing same-tenant flows. https://github.com/microsoft/vscode/issues/325107 is related authorization evidence, not a confirmed canonical for this tenant-specific path.
