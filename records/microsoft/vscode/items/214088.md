# Issue #214088 — `explorer.excludeGitIgnore` should also exclude files listed in `.git/info/exclude`

[https://github.com/microsoft/vscode/issues/214088](https://github.com/microsoft/vscode/issues/214088)

## Summary

A real Explorer capability gap remains on current main: `explorer.excludeGitIgnore` discovers and parses `.gitignore` files only. The request is accepted in the Backlog but needs scope decisions around additional Git exclude sources, so it should remain open under discussion.

## Change summary

Make `explorer.excludeGitIgnore` hide files matched by repository-local `.git/info/exclude`, with a commenter also requesting support for `core.excludesFile`.

## Best solution

Make Explorer exclusion semantics account for repository-local Git excludes alongside `.gitignore`, including a defined policy for linked worktrees and optionally configured `core.excludesFile` paths, while preserving web and no-Git-install operation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `src/vs/workbench/contrib/files/browser/files.contribution.ts`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`, `src/vs/workbench/services/search/common/ignoreFile.ts`
- **Validation:** Add a targeted FilesFilter test that enables `explorer.excludeGitIgnore`, supplies `.git/info/exclude` with positive and negated patterns, and verifies matching Explorer items are hidden while the setting-off case remains visible; run it with `scripts/test.sh --grep "FilesFilter"`.
- **Behavior:**

  > With `explorer.excludeGitIgnore` enabled, files ignored through the supported repository-local Git exclude source should be hidden from Explorer just like files ignored by `.gitignore`. Negated patterns should retain the same precedence semantics as Git, and disabling the setting should show those files again. Existing nested `.gitignore` behavior and the rule that visible editors remain visible must not regress.
- **Trace:**

  > FilesFilter in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts maintains IgnoreFile trees per workspace root. Its filter method discovers an ignore source only when an Explorer item is named `.gitignore`, then processIgnoreFile reads it and attaches the parsed IgnoreFile at that file's containing directory; `.git/info/exclude` is never discovered through this path, and `.git` is normally hidden by `files.exclude`. IgnoreFile in src/vs/workbench/services/search/common/ignoreFile.ts already parses patterns and supports parent chaining, but the review did not establish the desired precedence and repository-root semantics for combining additional sources. Keep search behavior, visible-editor exceptions, and operation without a Git executable unchanged. https://github.com/microsoft/vscode/issues/186640 is related only to writing entries through a Git context-menu command, not this filtering path.
- **Open decisions:**
  - Should the setting cover only the standard repository-local `.git/info/exclude`, or also the path configured by Git's `core.excludesFile`?
  - Should support resolve linked-worktree and submodule `.git` pointer files to exclude files outside the workspace, or be limited to literal `.git/info/exclude` files under workspace roots?
