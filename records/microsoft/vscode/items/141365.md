# Issue #141365 — Wrong keybind is used with colemak & russian layout

[https://github.com/microsoft/vscode/issues/141365](https://github.com/microsoft/vscode/issues/141365)

## Summary

Still present on main: the non-Latin fallback in macLinuxKeyboardMapper.ts hardcodes QWERTY scan-code-to-character mappings, so switching from Colemak to Russian resolves keybindings as if the Latin layout were QWERTY.

## Change summary

When a non-QWERTY Latin layout (e.g. Colemak) is paired with a non-Latin layout (e.g. Russian), switching to the non-Latin layout causes keybindings to resolve against QWERTY instead of the user's actual Latin layout.

## Best solution

The `_registerLetterIfMissing` fallback in `macLinuxKeyboardMapper.ts` should use the user's actual Latin layout mapping (from the last-known Latin keyboard layout) instead of the hardcoded QWERTY scan-code-to-character table. This likely requires caching the scan-code-to-keyCode mapping from the previously-active Latin layout and using that as the fallback source.
