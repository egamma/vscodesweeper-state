# Issue #330032 — Having managed-settings makes "read file outside of workspace" confirmations show up often

[https://github.com/microsoft/vscode/issues/330032](https://github.com/microsoft/vscode/issues/330032)

## Summary

Fresh, team-authored bug report (author already self-confirmed in a follow-up comment) about a misleading confirmation reason; source inspection confirms the read-confirmation title is hardcoded regardless of the actual trigger cause, so this stays open for a fix.

## Change summary

Presence of a managed-settings file (even with an empty deny list) triggers a 'read file outside of workspace' confirmation for in-workspace files, and the shown reason is wrong.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotToolDisplay.ts, the `read` case of the tool-display switch always renders the localized title `copilot.permission.read.title` ('Allow reading file outside of workspace?') for any read-permission confirmation; the real trigger (managed-settings presence) needs to be threaded through so the title/message reflects the actual reason, which likely requires additional context from the Copilot CLI/SDK request payload rather than a pure string fix.
