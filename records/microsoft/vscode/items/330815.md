# Issue #330815 — runSubagent still allows empty agentName and bypasses custom agent allow-list (related to #306266)

[https://github.com/microsoft/vscode/issues/330815](https://github.com/microsoft/vscode/issues/330815)

## Summary

Traced this in the current source: the `agents:`/`allowedSubagents` allow-list is only used to filter which agent names get advertised to the model in the prompt (extensions/copilot's automaticInstructionsCollector.ts); `runSubagentTool.invoke()` never checks the resolved agent name against `currentModeInstructions.allowedSubagents` before invoking, whether `agentName` is empty or explicitly given. That confirms the reporter's observation, though the intended semantics for the empty-`agentName` self-continuation path (documented in the tool schema itself as 'if not provided, uses the current agent') are a product call, not a clear-cut fix, so this needs an area-owner decision rather than an automatic patch.

## Change summary

runSubagentTool allows the current agent to spawn itself as a subagent (and possibly any agent) without enforcing the `agents:` allow-list configured in its own agent definition.

## Best solution

In src/vs/workbench/contrib/chat/common/tools/builtinTools/runSubagentTool.ts, decide and enforce a validation step (both in the empty-agentName self-continuation branch around lines 216-230 and the explicit-name branch around lines 173-215) that checks the resolved agent name against `currentModeInstructions?.allowedSubagents` (respecting the `'*'` wildcard convention used elsewhere) before invoking, and reject with a clear error otherwise; this likely belongs with the customizations/agent-host owners given the related closed issues (microsoft/vscode#306266, microsoft/vscode#306568, microsoft/vscode#306871).
