# Issue #330815 — runSubagent still allows empty agentName and bypasses custom agent allow-list (related to #306266)

[https://github.com/microsoft/vscode/issues/330815](https://github.com/microsoft/vscode/issues/330815)

## Summary

Confirmed on current main: an omitted, empty, or whitespace-only `agentName` resolves to the current agent, but that resolved name is never checked against the current agent's `allowedSubagents`. The issue should remain open as a bounded correctness bug.

## Change summary

Enforce a custom agent's `agents` allow-list when `runSubagent` defaults an omitted or empty `agentName` to the current agent.

## Best solution

Validate the final effective agent name against `allowedSubagents` in both preparation and invocation. Preserve current-agent inheritance when that agent is explicitly allowed or the allow-list contains `*`, and cover omitted and empty names with regression tests.
