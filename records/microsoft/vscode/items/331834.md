# Issue #331834 — Code actions with `arguments` fail with "Actual command not found" when the Quick Fix menu is open for ~2s (regression in 1.134.0)

[https://github.com/microsoft/vscode/issues/331834](https://github.com/microsoft/vscode/issues/331834)

## Summary

Traced and confirmed in current main: CodeActionModel#trigger() (src/vs/editor/contrib/codeAction/browser/codeActionModel.ts) synchronously calls `this.codeActionsDisposable.clear()` on every re-trigger (auto-trigger on cursor move or marker change), which disposes the currently displayed CodeActionSet — and with it the extension-host command cache entries created by CommandsConverter#toInternal for any command with `arguments` (src/vs/workbench/api/common/extHostCommands.ts). Since codeActionsDisposable is a MutableDisposable, assigning a new value already disposes the old one automatically, so the extra explicit clear() is both redundant and the actual regression.

## Change summary

Activating a Quick Fix whose command has non-empty `arguments` fails with "Actual command not found" if the menu has been open long enough for a re-trigger (cursor/marker change) to fire in the background.

## Best solution

Stop eagerly clearing `codeActionsDisposable` in CodeActionModel#trigger() (and in _update()) — let the MutableDisposable's normal value-replacement semantics dispose the previous CodeActionSet only once a new one is actually assigned, restoring the lifetime long enough for an open menu's cached command payload to remain resolvable until superseded or dismissed. This is a follow-up correction to the memory-leak fix that shipped in 1.134.0.
