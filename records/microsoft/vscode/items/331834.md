# Issue #331834 — Code actions with `arguments` fail with "Actual command not found" when the Quick Fix menu is open for ~2s (regression in 1.134.0)

[https://github.com/microsoft/vscode/issues/331834](https://github.com/microsoft/vscode/issues/331834)

## Summary

Freshly filed, well-diagnosed regression: current main's `CodeActionModel` disposes its `codeActionsDisposable` (a `MutableDisposable`) whenever the model re-triggers (auto-trigger via marker/cursor changes, or a manual re-trigger), which tears down the extension-host command cache for a code action set that a still-open Quick Fix menu is referencing — matching the reporter's own trace of PR #330142's leak fix.

## Change summary

Activating a code action whose command has non-empty `arguments` fails with "Actual command not found" if the Quick Fix menu was open for ~2s before selection, a regression since 1.134.0.

## Best solution

In src/vs/editor/contrib/codeAction/browser/codeActionModel.ts, the CodeActionSet cache backing an open menu needs to live until the menu is dismissed or the action is actually applied, not be torn down the instant a new trigger (auto or manual) reassigns `codeActionsDisposable.value`; likely needs to track the 'currently displayed' set separately from in-flight recomputation, or defer disposal until the action widget signals it's closed.
