# Issue #331834 — Code actions with `arguments` fail with "Actual command not found" when the Quick Fix menu is open for ~2s (regression in 1.134.0)

[https://github.com/microsoft/vscode/issues/331834](https://github.com/microsoft/vscode/issues/331834)

## Summary

Traced this in the current source and it holds up: CodeActionModel.codeActionsDisposable is a MutableDisposable that gets reassigned (and thus disposes the previous CodeActionSet) on every auto-retrigger, even when that same CodeActionSet is still referenced live by CodeActionController._activeCodeActions and shown in an open Quick Fix menu — this is the reusable-MutableDisposable ownership tightened by #330142, applied too eagerly.

## Change summary

Activating a code action with non-empty `command.arguments` after the Quick Fix menu has been open ~2s fails with "Actual command not found", a regression since 1.134.0.

## Best solution

In src/vs/editor/contrib/codeAction/browser/codeActionModel.ts, don't let an auto-retrigger's reassignment of `codeActionsDisposable` dispose a CodeActionSet that's still the one displayed/held by CodeActionController's `_activeCodeActions` — extend its lifetime until the menu is dismissed or the action resolves, without reintroducing the leak #330142 fixed.

## Evidence

- **disposal trigger:** src/vs/editor/contrib/codeAction/browser/codeActionModel.ts:48-49,64-67 wires cursor-position and onMarkerChanged events to `_tryAutoTrigger`, which after a 250ms delay calls `trigger()` and recomputes a new CodeActionSet, assigning it to `this.codeActionsDisposable.value` (line 254/358) — MutableDisposable.set disposes the previous value whenever it differs by reference (src/vs/base/common/lifecycle.ts:592-595).
- **shared reference, no ownership check:** src/vs/editor/contrib/codeAction/browser/codeActionController.ts:270-271 stores the very same CodeActionSet in `_activeCodeActions.value` and renders it via `showCodeActionList`, but nothing prevents the model's independent `codeActionsDisposable` from disposing that same object out from under the open menu.
- **dispose -> extension host cache release:** CodeActionSet.dispose() propagates to the code-action provider's `dispose` callback registered in src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts:398-402, which calls `$releaseCodeActions`, deleting the ext-host command+arguments cache entry in extHostLanguageFeatures.ts:580-583 — exactly the delegating-command payload the reporter shows going missing.
- **reporter's own diagnosis:** The issue independently names the same file and the same causal PR (#330142, 'fix: memory leak in code actions'), and confirms via diff that the extension-host side is unchanged between 1.133.0 and 1.134.0, isolating the regression to codeActionModel.ts's lifecycle change.
