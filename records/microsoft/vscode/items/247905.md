# Issue #247905 — Improve UX for cell output -> chat dnd

[https://github.com/microsoft/vscode/issues/247905](https://github.com/microsoft/vscode/issues/247905)

## Summary

Keep open: output dragging exists, but the discoverability gap remains in the inspected implementation. This team-authored UX follow-up is already correctly routed, and no qualifying fix or open canonical was found.

## Change summary

Make dragging individual notebook outputs into chat discoverable without interfering with text selection or cell reordering.

## Best solution

Provide a discoverable per-output drag affordance in the notebook output UI while preserving text selection and existing cell-reordering handles. Confirm the proposed dedicated handle UX before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts`, `src/vs/workbench/contrib/notebook/browser/view/renderers/cellRenderer.ts`
- **Validation:** In a notebook with image and text outputs and chat beside it, verify the agreed affordance identifies how to attach each individual output. Drag each supported output into chat and confirm the intended attachment; select text normally, reorder cells with existing margin handles, and verify other outputs are not attached accidentally.
- **Behavior:**

  > Users should be able to discover how to drag an individual supported notebook output into chat without prior knowledge of Alt-drag. The interaction must distinguish an output attachment from moving the containing cell. Acceptance includes attaching image and text outputs individually while normal text selection and cell reordering continue to work.
- **Trace:**

  > OutputElement in src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts emits a notebook-cell-output payload containing outputId. The current GitHub source enables image dragging directly and other output dragging through Alt key handlers, with no dedicated handle in the inspected constructor. The local src/vs/workbench/contrib/notebook/browser/view/renderers/cellRenderer.ts registers the output focus indicator and margin as cell-reordering handles. The maintainer explanation at https://github.com/microsoft/vscode/issues/247460#issuecomment-2835930523 confirms these are intentionally distinct interactions. Preserve text selection, individual-output attachment scope, and existing cell reordering; whole-cell or all-output attachment is outside this request. The remaining uncertainty is the user-facing affordance: the issue proposes a per-output upper-right drag icon but does not record final UX approval.
- **Open decisions:**
  - Should discoverability use the proposed dedicated per-output drag handle, or guidance for the existing output-body and Alt-drag interaction?
