# Issue #339750 — Copilot SDK harness receives abap: documents as read-only snapshots while Local can edit them

[https://github.com/microsoft/vscode/issues/339750](https://github.com/microsoft/vscode/issues/339750)

## Summary

Real architectural gap, not a bug in existing code: the agent host's snapshot mechanism intentionally treats content it cannot address as a real workspace file as read-only context, and a custom non-`file:` scheme (here `abap:`, from the SAP ADT extension's filesystem provider) falls into that bucket for the out-of-process Copilot SDK/Codex/Claude harnesses, while the in-process Local harness can use VS Code's full provider registry directly. Whether (and how) SDK harnesses should gain read/write access to arbitrary registered filesystem providers is a product/design question, not something to triage as a defect yet.

## Change summary

Attaching a document with a non-file URI scheme (abap:, provided by a third-party filesystem provider extension) to a Copilot SDK harness chat yields a read-only snapshot, whereas the Local harness can read/edit the live document through the registered provider.

## Best solution

A maintainer should decide whether out-of-process harnesses (Copilot SDK/Codex/Claude) should proxy reads/writes for non-file URI schemes through the existing vscode-agent-client filesystem bridge (see _readClientResource/toAgentClientUri in src/vs/platform/agentHost/node/agentService.ts) instead of only snapshotting them read-only, or whether this remains an intentional limitation that should be documented.

## Evidence

- **intentional snapshot design:** src/vs/platform/agentHost/common/meta/vscode/agentSnapshotAttachmentMeta.ts documents that the host snapshots 'client-resident or derived content ... that cannot be referenced as a real workspace file' and marks it read-only context by design.
- **rewrite logic:** src/vs/platform/agentHost/node/agentService.ts `_rewriteSingleAttachment` only skips snapshotting when `originalUri.scheme === Schemas.file` and the file exists on the agent host side (#319314); any other scheme, including a registered non-file provider like `abap:`, falls through to the snapshot/read-only path via `_readClientResource`.
- **existing proxy for reads:** `_readClientResource` already proxies reads through the `vscode-agent-client` filesystem provider via `toAgentClientUri`, but there is no corresponding write-back path for non-file schemes, which is what the reporter is missing for edit+activate workflows.
