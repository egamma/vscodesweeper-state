## Evidence

- **Defect traced in source:** src/vs/base/common/strings.ts still uses /\b/g in both lcut() and rcut(). For 'héllo wörld ünï' with n=7, rcut() accepts the false boundary immediately after 'w', producing 'héllo w…'; lcut() accepts the boundary before 'r', producing '…rld ünï'. This follows directly from the inspected loops without executing code.
- **Affected consumers:** src/vs/workbench/contrib/search/browser/searchTreeModel/match.ts:66 calls lcut(fullBefore, 26, '…') for preview context. src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts:421,599,1228 calls rcut() for descriptions and first-line titles.
- **Open implementation candidate:** GitHub confirms https://github.com/microsoft/vscode/pull/349203 is OPEN with no merge commit and a body containing 'Fixes #349121'. It proposes Unicode-property word boundaries rather than Intl.Segmenter and reports added non-ASCII tests; those claims were not executed or independently validated in this read-only review.
- **Existing compatibility contract:** src/vs/base/test/common/strings.test.ts contains lcut/rcut cases covering ASCII words, punctuation/version strings, trimming, and prefix/suffix behavior. The inspected implementation retains ASCII-only boundaries, so the reported Unicode gap remains.
