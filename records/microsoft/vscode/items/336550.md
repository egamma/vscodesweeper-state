# Issue #336550 — Agent Merge: Monitoring is unable to continuously see/act on existing reviews/comments and CI issue

[https://github.com/microsoft/vscode/issues/336550](https://github.com/microsoft/vscode/issues/336550)

## Summary

Real, actively-investigated bug: Agent Merge's persistent monitoring stops acting on new reviews/CI failures after the first repair turn, and a follow-up /fix-ci command doesn't carry the runtime authorization block the tool requires — both confirmed by the reporter's log excerpts showing 'Agent Merge action ... is not authorized for the active turn.' A contributor (benibenj) is already engaged and has asked for a full debug-log export to pin down the exact skip point, so this should stay open pending that diagnosis.

## Change summary

After Agent Merge's first repair turn, continued monitoring for new reviews/comments/CI failures silently stops working, and manually invoking /fix-ci later fails with an 'action is not authorized for the active turn' error.

## Best solution

A maintainer (benibenj or another agentHost owner) should use the requested Agent Host debug log export to determine whether (a) the backstop/fingerprint scheduler in agentMergeController.ts stops re-evaluating after the first repair turn ends, and (b) why a /fix-ci-triggered turn is built without the '<agent_merge_state>' authorization block that IAgentMergeTurnContext.actions requires in agentMergeTools.ts's _requireTurnAction — then fix whichever gap is confirmed.
