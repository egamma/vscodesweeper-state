# Issue #336550 — Agent Merge: Monitoring is unable to continuously see/act on existing reviews/comments and CI issue

[https://github.com/microsoft/vscode/issues/336550](https://github.com/microsoft/vscode/issues/336550)

## Summary

Traced a concrete cause on main: Agent Merge caps repair turns at `maximumTotalPromptCount` (6) regardless of whether each turn addressed a different cause, then silently disables itself — which matches the reporter's "only resolved once, then nothing" experience despite the "will remain active" message.

## Change summary

Agent Merge claims persistent monitoring for reviews/comments/CI but stops acting on new ones after an initial pass, requiring the user to manually re-prompt.

## Best solution

In src/vs/platform/agentHost/node/agentMergeController.ts, decide whether `totalPromptCount` should keep counting across genuinely different gate fingerprints (new reviews/CI failures), or only cap repeated identical blockers as `repeatedPromptCount` already does; also fix the disable notice text (`agentMergeDisableReasons.repairBudgetExhausted()` in agentMerge.ts) which claims "the same pull request blockers remained" even when the cap was hit by distinct causes.
