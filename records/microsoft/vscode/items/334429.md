# Issue #334429 — Markdown Editor is entirely unavailable

[https://github.com/microsoft/vscode/issues/334429](https://github.com/microsoft/vscode/issues/334429)

## Summary

Traced conclusively in source: the built-in Markdown Editor and Markdown Preview custom editors are only registered with `filenamePattern: "*.md"`, while VS Code's own markdown language contribution recognizes many more extensions (`.markdown`, `.mkd`, `.mkdn`, `.mdwn`, `.mdown`, etc.). The editor-type resolver matches purely by filename glob, so files with those other extensions never get a second matching editor and "Reopen Editor With" never shows.

## Change summary

Opening a `.markdown` (non-`.md`) file never shows the "Reopen Editor With" menu entry needed to switch to the new WYSIWYG Markdown Editor.

## Best solution

Widen the `selector.filenamePattern` for both `vscode.markdown.preview.editor` and `vscode.markdown.editor` in extensions/markdown-language-features/package.json to cover the same extension set the markdown language contribution declares (extensions/markdown-basics/package.json), so `getAvailableEditorTypes` in src/vs/workbench/browser/parts/editor/editorTypePicker.ts finds more than one match for those files too.

## Evidence

- **narrow selector:** extensions/markdown-language-features/package.json:1742-1767 registers both `vscode.markdown.preview.editor` and `vscode.markdown.editor` with selector `{"filenamePattern": "*.md"}` only.
- **language recognizes more extensions:** extensions/markdown-basics/package.json declares the `markdown` language for `.md, .mkd, .mkdn, .mdwn, .mdown, .markdown, .markdn, .mdtxt, .mdtext, ...` — so a `.markdown` file has `editorLangId == markdown` (menu commands gated on langId still show) but is not covered by the custom editor's glob selector.
- **resolver logic:** src/vs/workbench/services/editor/browser/editorResolverService.ts:451 matches associations via `globMatchesResource(association.filenamePattern, resource)` — pure filename glob, independent of language ID.
- **menu gating:** src/vs/workbench/browser/parts/editor/editorGroupView.ts:2157-2166 only adds the "Reopen Editor With" submenu when src/vs/workbench/browser/parts/editor/editorTypePicker.ts's `getAvailableEditorTypes()` finds more than one matching editor for the resource — which requires the glob match above to succeed.
