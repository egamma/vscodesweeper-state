# Issue #347 — Support workspace extensions

[https://github.com/microsoft/vscode/issues/347](https://github.com/microsoft/vscode/issues/347)

## Summary

Keep open: this protected plan item still tracks a meaningful gap—repository-defined extension enablement that follows a workspace and can be shared with a team. Recommendations, profiles, and local workspace extensions each cover part of the request but not its central declarative allowlist behavior.

## Change summary

Allow a workspace to define and share which extensions should be installed or enabled, while keeping unrelated extensions inactive for that workspace.

## Best solution

Settle a trust-aware, repository-shareable workspace extension policy that can recommend missing Marketplace extensions and activate an explicit installed-extension allowlist without silently installing untrusted code. The design should build on `extensions.json`, workspace trust, and existing workspace enablement rather than requiring teams to vendor extension packages.
