## Summary

Verified duplicate: the multi-minute extension-host freeze in large workspaces has the same root cause already diagnosed in the open, broader issue #335194 — I traced the exact code path on current main (filterIngoredResources's unbounded Limiter over the whole result array, with Limiter.consume's O(n) Array.shift dequeue) and it matches the reporter's own extension-host profile blaming github.copilot-chat.

## Change summary

In workspaces with hundreds of thousands of files, the Copilot Chat extension host pegs CPU and becomes unresponsive for minutes at a time shortly after activation, scaling with workspace file count.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/335194 — fixing filterIngoredResources in extensions/copilot/src/platform/ignore/common/ignoreService.ts (avoid enqueueing the entire result array through a single Limiter, whose outstandingPromises.shift() dequeue is O(n) per pop, causing O(n²) blocking for very large batches) resolves this report too.
