# Issue #334582 — Agent shell init script is not applied when sandboxing is enabled

[https://github.com/microsoft/vscode/issues/334582](https://github.com/microsoft/vscode/issues/334582)

## Summary

Freshly filed, team-authored bug report; traced conclusively in source — the fix is a small, well-localized sandbox policy gap, so this stays open for a code fix.

## Change summary

When shell tool sandboxing is enabled, the configured shell init script (e.g. sourcing ~/.bashrc) silently fails to apply because the sandbox denies read access to the profile file it sources.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, extend _sandboxExtraReadonlyPaths() (used by _computeSdkSandboxConfig and _applyEffectiveSandboxConfig) to also grant read access to the actual shell profile paths the generated init script sources ($HOME/.bashrc on Linux/macOS, $PROFILE.CurrentUserAllHosts / $PROFILE.CurrentUserCurrentHost on Windows/PowerShell) whenever the init script is materialized — not just the generated script's own directory.
