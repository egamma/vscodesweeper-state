# Issue #267005 — Turn off local indexing of files in the workspace (for working with large size repo under GVFS)

[https://github.com/microsoft/vscode/issues/267005](https://github.com/microsoft/vscode/issues/267005)

## Summary

Team-authored bug about VS Code unexpectedly hydrating GVFS-virtualized files at rest. No fix commit references this issue, assignees are active, and the core problem (file reads beyond stat during workspace enumeration) remains unresolved on main.

## Change summary

VS Code causes GVFS-mounted files to be fully hydrated (downloaded) when a large repo is opened, even when the user performs no actions, degrading git performance.

## Best solution

Investigate what in VS Code's workspace initialization reads file content (not just metadata) on GVFS mounts — likely in file watchers, search indexing, or language server file enumeration under `src/vs/platform/files/` and the chat codebase indexing paths. Ideally provide a setting or detect GVFS/ProjFS and avoid content reads for files that haven't been explicitly opened. The related issue https://github.com/microsoft/vscode/issues/307688 (closed) addressed a similar symptom for `git add` in Copilot sessions but the broader hydration-at-rest problem here remains.
