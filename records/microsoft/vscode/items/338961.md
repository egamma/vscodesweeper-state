# Issue #338961 — Unicode highlight boxes outlive their highlighter when the worker result arrives after dispose

[https://github.com/microsoft/vscode/issues/338961](https://github.com/microsoft/vscode/issues/338961)

## Summary

Confirmed on current main by tracing the source: DocumentUnicodeHighlighter's worker-result callback only checks model disposal/version, not whether the highlighter itself (`this`) was disposed, so a late result can re-populate a decorations collection that `dispose()` already cleared, leaving stray Unicode highlight boxes until the tab is reopened.

## Change summary

Unicode highlight decoration boxes can persist after the highlighter is disposed, when a worker request for the old options resolves after a language/option change disposed the highlighter.

## Best solution

Guard the `.then()` callback in `DocumentUnicodeHighlighter._update()` (src/vs/editor/contrib/unicodeHighlighter/browser/unicodeHighlighter.ts) with a disposed check on the highlighter itself (e.g. `this._store.isDisposed`) before calling `this._decorations.set(...)`, as the reporter suggests.
