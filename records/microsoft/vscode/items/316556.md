# Issue #316556 — shellIntegration.executeCommand() read() stream never ends for multi-line commands on Linux/bash

[https://github.com/microsoft/vscode/issues/316556](https://github.com/microsoft/vscode/issues/316556)

## Summary

Consolidate with the older, verified open issue https://github.com/microsoft/vscode/issues/250764. The reporter's correction establishes the same observable failure—missing execution completion for newline-containing commands on Linux/bash—with an additional consequence for read() consumers.

## Change summary

Ensure newline-containing commands executed through bash shell integration terminate their output streams and deliver execution-end events after completion.

## Best solution

Resolve multiline execution completion under https://github.com/microsoft/vscode/issues/250764, retaining this report's read() hang and Manjaro/bash 5.2 details as acceptance cases. Both the returned stream and the execution-end event must complete for the original execution object.

- **Shared completion lifecycle in current source:** In src/vs/workbench/api/common/extHostTerminalShellIntegration.ts, endShellExecution calls InternalTerminalShellExecution.endExecution to open the read() stream barrier, then flushes the stream before emitting the execution-end event. Its multiline handling can defer completion while unresolvedCommandLines remain. src/vs/workbench/api/browser/mainThreadTerminalShellIntegration.ts forwards command-detection completion through $shellExecutionEnd. These paths connect the stream hang to the completion lifecycle already covered by the canonical report; they do not prove the reporter's hypothesis that bash loses an OSC marker.
