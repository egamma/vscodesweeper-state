# Issue #319382 — Plugins disabled by enterprise policy should indicate reason

[https://github.com/microsoft/vscode/issues/319382](https://github.com/microsoft/vscode/issues/319382)

## Summary

Valid UX gap filed by a team member: plugins disabled by enterprise policy (via ChatEnabledPlugins or strict marketplace rules) appear in the 'Disabled Locally' group without any indication of *why* they are disabled. Keeping open for the area owner.

## Change summary

When enterprise policy disables a plugin, the plugin list should indicate the policy-based reason rather than showing it as a generic disabled item.

## Best solution

In the plugin list widget renderer (pluginListWidget.ts), detect when a plugin's `policyBlocked` observable is true and render a visual indicator (e.g. shield icon + tooltip or inline text) explaining that the plugin is disabled by organization policy, similar to how the global plugins-disabled banner already distinguishes policy vs. user-disabled states (lines 709–720).
