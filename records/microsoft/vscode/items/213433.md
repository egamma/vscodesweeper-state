# Issue #213433 — Add enum to let users tune find in cell selection behavior

[https://github.com/microsoft/vscode/issues/213433](https://github.com/microsoft/vscode/issues/213433)

## Summary

Keep open: notebook Find supports manually selected scopes, but current main does not expose the requested automatic-selection policy. This team-authored follow-up has neither a verified fixing commit nor an open canonical that would justify closing it.

## Change summary

Provide a three-value policy for automatically enabling Find in Selection in notebooks, analogous to editor.find.autoFindInSelection.

## Best solution

Define notebook automatic-selection semantics consistent with the editor's never/always/multiline policy, then expose and honor that policy when opening notebook Find. Settle how those modes map to selected cells versus text selections before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFind.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindReplaceWidget.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts`, `src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts`, `src/vs/workbench/contrib/notebook/common/notebookCommon.ts`
- **Validation:** After deciding semantics, check each policy by opening Find in a notebook containing the same term inside and outside selected cells or selected text. Cover one selected cell, multiple selected cells, single-line text, multiline text, and reopening Find; verify search scope and toggle state match the chosen policy and that manual scope toggling still works.
- **Behavior:**

  > Users should be able to control when notebook Find automatically restricts searches to their selection through a three-value policy analogous to the text editor's never/always/multiline setting. Manual Find in Selection already exists and must remain usable. Acceptance should exercise each mode with cell selections and text selections, checking both included matches and excluded matches. The mapping of modes and the default remain product decisions.
- **Trace:**

  > The notebook.find action and openFindWidget in src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFind.ts open the notebook-specific widget; the latter reads several EditorOption.find fields but not autoFindInSelection. SimpleFindReplaceWidget in notebookFindReplaceWidget.ts owns the manual selection toggle and maps multiple selected cells to cell scope, otherwise multiline text to text scope, otherwise the selected cell to cell scope. Neither its show method nor NotebookFindWidget.show applies an automatic-selection policy, and notebook.find.filters only controls content categories. The original setting discussion is https://github.com/microsoft/vscode/pull/213409#discussion_r1614018756; the broader manual-scope feature in https://github.com/microsoft/vscode/issues/209839 is closed. Preserve existing search-string seeding, manual scope selection, and content filters; the uncertainty is the user-facing policy contract, not whether scope-search machinery exists.
- **Open decisions:**
  - Should notebook Find honor editor.find.autoFindInSelection or expose a separate notebook-specific setting?
  - How should always and multiline map to a single selected cell, multiple selected cells, and single-line versus multiline text selections?
  - What should the default automatic-selection behavior be when opening notebook Find?
