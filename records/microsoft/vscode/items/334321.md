# Issue #334321 — Support Gemini 3.8 and future unlisted models via fallback capabilities and custom model settings

[https://github.com/microsoft/vscode/issues/334321](https://github.com/microsoft/vscode/issues/334321)

## Summary

Traced on main: GeminiNativeBYOKLMProvider.getAllModels() in geminiNativeProvider.ts still drops any model not present in _knownModels, unlike anthropicProvider.ts which falls back to generic capabilities for unlisted models — the inconsistency the reporter describes is real and unaddressed.

## Change summary

Add a capability fallback for unlisted Gemini models (matching Anthropic's BYOK provider) plus a user-settable custom-model list, so newly released Gemini models work without waiting for a CDN manifest update.

## Best solution

In extensions/copilot/src/extension/byok/vscode-node/geminiNativeProvider.ts, mirror anthropicProvider.ts's else-branch fallback (generic capabilities for unknown model IDs) inside getAllModels(); the custom-model settings.json addition is a separate, larger design decision a BYOK maintainer should weigh in on.
