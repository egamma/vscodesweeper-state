# Issue #334321 — Support Gemini 3.8 and future unlisted models via fallback capabilities and custom model settings

[https://github.com/microsoft/vscode/issues/334321](https://github.com/microsoft/vscode/issues/334321)

## Summary

Well-researched request: verified on main that GeminiNativeBYOKLMProvider.getAllModels() strictly drops any model not present in _knownModels, unlike AnthropicLMProvider which falls back to generic capabilities for unknown models — a real inconsistency worth routing to the BYOK/chat area.

## Change summary

Add a default-capabilities fallback for unlisted Gemini models (matching Anthropic's pattern) and a settings.json option for user-defined Gemini model IDs/capabilities.

## Best solution

Bring extensions/copilot/src/extension/byok/vscode-node/geminiNativeProvider.ts's getAllModels() in line with anthropicProvider.ts's fallback-capabilities pattern for unknown models; the custom-model settings addition is a separate, larger design decision that a BYOK-area maintainer should weigh in on.
