# Issue #334321 — Support Gemini 3.8 and future unlisted models via fallback capabilities and custom model settings

[https://github.com/microsoft/vscode/issues/334321](https://github.com/microsoft/vscode/issues/334321)

## Summary

Confirmed on current main: `geminiNativeProvider.ts` still hard-filters to `_knownModels` while `anthropicProvider.ts` already falls back to generic capabilities for unlisted models — a real, well-evidenced gap and inconsistency, with community traction (5 upvotes, multiple comments, a user-authored manual patch). Worth a maintainer decision on the fallback defaults and settings shape before implementation.

## Change summary

Gemini BYOK provider silently drops any model not in the hardcoded `_knownModels` map, so new/preview Gemini releases (e.g. Gemini 3.8 Flash) can't be used until the CDN manifest or extension ships an update; requester wants a capability-fallback plus a user-defined custom-model setting, matching the Anthropic provider's existing pattern.

## Best solution

Add a generic-capabilities fallback to `GeminiNativeBYOKLMProvider.getAllModels()` for models absent from `_knownModels` (mirroring `anthropicProvider.ts`), and consider a `github.copilot.chat.byok.gemini.customModels`-style setting for user-declared model overrides — but a maintainer should settle the concrete default capability values and whether the custom-model setting is per-provider or generalized across BYOK providers before coding.
