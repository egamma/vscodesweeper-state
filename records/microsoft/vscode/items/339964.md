# Issue #339964 — VS Code 1.101+ cannot find its own files on Omnissa App Volumes writable volumes (libuv `GetFileInformationByName` fast path, same cause as #251448 / libuv#4844)

[https://github.com/microsoft/vscode/issues/339964](https://github.com/microsoft/vscode/issues/339964)

## Summary

Well-diagnosed upstream libuv issue (same root cause as the FSLogix case in #251448, filed as libuv/libuv#4844): libuv's GetFileInformationByName fast path misreports files as missing on Omnissa App Volumes writable volumes, and the narrow FSLogix-registry workaround added for #251448 doesn't cover this driver. No fix lives in this repo's code, so this stays open pending an upstream libuv/Node fix (or a broadened workaround) that gets pulled into Electron's Node build.

## Change summary

VS Code 1.101+ fails to launch on Omnissa App Volumes writable-volume profiles because libuv's by-name stat fast path reports existing files as not found; request a general fallback to handle-based stat instead of the FSLogix-only registry check.

## Best solution

Track this as an upstream libuv defect (libuv/libuv#4844); the long-term fix is a generic fallback to the handle-based stat path (not a vendor-specific registry check) landing in libuv and flowing into the Node.js version Electron bundles. No fix is possible by editing this repository's own TypeScript/JS sources.
