# Issue #293025 — Inconsistent keyboard shortcut for inserting new line between Source Control input and Find widget

[https://github.com/microsoft/vscode/issues/293025](https://github.com/microsoft/vscode/issues/293025)

## Summary

The difference is intentional: in the Find widget, Shift+Enter is bound to 'Find Previous' (a standard convention shared with browsers and other editors), so Ctrl+Enter is used for newline insertion instead. The SCM input has no match-navigation concept, so Shift+Enter is free for newlines.

## Change summary

Request to unify keyboard shortcuts for newline insertion across the Find widget and Source Control input.

## Best solution

Keep the current behavior — the Find widget's Enter/Shift+Enter for Next/Previous match is a deeply established UX convention that cannot be reassigned without breaking navigation expectations. The SCM input has different functional needs.

  > Thanks for the detailed report. The difference here is intentional rather than an oversight:
  > 
  > - In the **Find widget**, `Shift+Enter` is bound to **Find Previous** (mirroring the standard Enter = Next Match, Shift+Enter = Previous Match convention used across browsers and editors). Since that shortcut is taken, `Ctrl+Enter` is used for newline insertion.
  > - In the **SCM input**, there's no match-navigation concept, so `Shift+Enter` is free to insert a newline.
  > 
  > These two inputs serve fundamentally different purposes, so their shortcut allocations reflect their respective primary functions. Unifying them would mean either losing Find Previous navigation or breaking a widely-expected convention.
  > 
  > Closing as by-design, but the discoverability concern is fair — the `Ctrl+Enter` hint does appear in the Find widget's toggle button tooltip.
