# Issue #334178 — Agent terminal file-write detection misses cmd.exe root deletion caused by PowerShell quoting

[https://github.com/microsoft/vscode/issues/334178](https://github.com/microsoft/vscode/issues/334178)

## Summary

Well-documented, reproducible safety gap: PowerShell's C-style `\"` quoting inside a nested `cmd.exe /c "rd /s /q ..."` payload is not recognized as an escape by PowerShell, so the path argument is split off and `rd /s /q` receives a bare `\`, i.e. the current drive root — and CommandLineFileWriteAnalyzer reported `File writes detected [[]]` for it. This is a real, high-severity gap in the terminal tool's safety net, not a request to second-guess Bypass Approvals.

## Change summary

The agent terminal's file-write/destructive-command analyzer fails to detect a drive-root `rd /s /q` deletion when it's wrapped in a `cmd.exe /c "..."` string with C-style quote-escaping run from PowerShell, because the effective argv split by PowerShell differs from what the analyzer assumes.

## Best solution

In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/commandLineAnalyzer/commandLineFileWriteAnalyzer.ts, extend detection to parse the effective argv of common shell-wrapper invocations (cmd.exe /c, powershell -Command, pwsh -Command, sh -c) per the *outer* shell's quoting rules rather than assuming the inner command's literal string is intact, and add a non-bypassable hard guard (even under autoApprove) for recursive deletion targeting a filesystem/drive root or user-profile root. This is exactly the kind of gap #261794/#271351 aimed to close, so it likely belongs alongside that tree-sitter-based analyzer work.
