# Issue #208255 — Auto-load workspace file if it is the only workspace file in the folder root

[https://github.com/microsoft/vscode/issues/208255](https://github.com/microsoft/vscode/issues/208255)

## Summary

Keep this accepted, 45-upvote request open: current workspace discovery still requires an explicit action and does not provide repository-configured automatic opening. The earlier requests are closed, and no verified older open canonical was found.

## Change summary

Allow a repository setting to automatically open the sole root-level .code-workspace file when its folder is opened, including through code .

## Best solution

Provide opt-in automatic workspace selection for a folder containing exactly one root-level workspace file, without requiring each contributor to configure their editor. Settle how repository opt-in interacts with an explicit user preference to remain in folder mode before implementing it in the workspace-opening flow.

- **Behavior:**

  > Opening a repository folder containing exactly one root-level .code-workspace file should use that workspace automatically when the repository opts in, without a notification click or per-contributor setup. The behavior must cover both UI folder opening and code . and must not arbitrarily select a workspace when multiple files exist. With automatic opening disabled, existing explicit workspace-opening behavior remains unchanged. Acceptance must include a fresh user configuration and a repeat opening of the same repository.
- **Trace:**

  > WorkspacesFinderContribution in src/vs/workbench/contrib/workspaces/browser/workspaces.contribution.ts discovers root-level workspace files after LifecyclePhase.Eventually, restricted to single-folder, nonvirtual workspaces. Its single-file branch currently offers a notification action that invokes IHostService.openWindow with the discovered workspace URI; discovery alone never opens it. Existing tests in src/vs/workbench/contrib/workspaces/test/browser/workspaces.contribution.test.ts mock file resolution and host opening. Configuration searches found no automatic-opening setting, while explicit workspace-opening commands remain available. The reporter's central requirement is repository-controlled onboarding, not a replacement project picker or recursive workspace search. Planning must establish the repository/user precedence contract and whether late discovery can preserve the expected folder-opening behavior; do not broaden this into automatic selection among multiple workspaces. Earlier discussion at https://github.com/microsoft/vscode/issues/153452 describes a similar root-only opt-in, but does not settle user override semantics.
- **Open decisions:**
  - Should a repository-local opt-in take effect without user configuration while still allowing an explicit user preference to open that repository in folder mode, and which preference wins when both are present?
