# Issue #153522 — Replacing with capture groups writes the first match's values to all matches in that line

[https://github.com/microsoft/vscode/issues/153522](https://github.com/microsoft/vscode/issues/153522)

## Summary

The reported lookahead replacement defect remains traceable in current main. An open PR explicitly targets this issue, so keep it open while that implementation is reviewed.

## Change summary

Workspace regex replacement incorrectly reuses the first occurrence's capture groups for later matches sharing the same preview.

## Evidence

- **Current-source defect:** In src/vs/workbench/contrib/search/browser/searchTreeModel/match.ts, MatchImpl.replaceString first evaluates fullMatchText(), which isolates '=' or '%3D' and therefore cannot satisfy the reporter's following-digit lookahead. Its fallback evaluates fullMatchText(true), which returns the shared preview without selecting the current occurrence.
- **First-occurrence capture reuse:** In src/vs/workbench/services/search/common/replace.ts, ReplacePattern.getReplaceString resets lastIndex to zero and calls exec(text), explicitly returning the replacement for the first match. Both occurrences consequently use '=' on the reporter's first line and '%3D' on the second line, explaining the exact reported output without executing code.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/340333 is verified OPEN and includes 'Fixes #153522'. It targets MatchImpl.replaceString and adds a searchModel regression test for the reported lookahead case; its description explicitly leaves lookbehind behavior outside its scope. It is not a landed fix.
