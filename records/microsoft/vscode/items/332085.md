# Issue #332085 — Agents window: BYOK custom-endpoint model not selectable for WSL workspaces

[https://github.com/microsoft/vscode/issues/332085](https://github.com/microsoft/vscode/issues/332085)

## Summary

A VS Code team member (vritant24) confirmed the root cause directly in the issue thread: BYOK models aren't wired up for the Agent Host when it runs over the WSL remote path, and support has been added to the backlog — this is a genuine, maintainer-acknowledged gap, not something to close.

## Change summary

BYOK custom-endpoint models configured in the Agents window are not selectable when the workspace is a WSL (Remote-WSL) folder, though they work for local Windows workspaces and the regular Chat view.

## Best solution

Extend Agent Host BYOK wiring to the remote/WSL topology so `IByokLmBridgeRegistry` is populated when the Agent Host runs remotely, not just the local 'renderer' case — src/vs/platform/agentHost/node/agentHostBootstrap.ts and agentHostServices.ts currently model only `{ kind: 'renderer' } | { kind: 'unavailable' }`, confirming the remote path is unimplemented. Maintainer already owns this on the Backlog milestone.
