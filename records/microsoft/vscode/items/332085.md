# Issue #332085 — Agents window: BYOK custom-endpoint model not selectable for WSL workspaces

[https://github.com/microsoft/vscode/issues/332085](https://github.com/microsoft/vscode/issues/332085)

## Summary

Fresh, well-diagnosed report (0 days old, no comments yet) of BYOK Custom Endpoint models being unavailable in the Agents window specifically for WSL workspaces, while working in the regular Chat view (WSL) and in the Agents window for a local Windows folder. Source review turned up a real architectural seam in the BYOK bridge that plausibly explains exactly this gap, so this stays open for the agent-host/BYOK owners to confirm which code path a plain Remote-WSL workspace takes.

## Change summary

A BYOK Custom Endpoint model (configured in `chatLanguageModels.json`) is registered and selectable everywhere except in the Agents window model picker when the session's workspace is opened via Remote-WSL.

## Best solution

Have the agent-host/BYOK owners trace which agent-host launch path services a plain Remote-WSL workspace's Agents-window session and confirm whether it wires a real `ByokLmBridgeRegistry` (renderer kind) or falls back to `NullByokLmBridgeRegistry` (src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts) the way the standalone/dedicated remote agent host does; if the latter, either connect the bridge to the remote extension host's LM API or document the limitation.

## Evidence

- **BYOK bridge requires a co-located extension host:** src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts:180-204 defines `NullByokLmBridgeRegistry`, documented as used for 'agent host entrypoints that do not support BYOK — e.g. the remote agent host, where no extension host runs alongside the agent host to serve the renderer LM API.'
- **byok kind selection:** src/vs/platform/agentHost/node/agentHostBootstrap.ts:145 only builds a real bridge registry when `options.byok.kind === 'renderer'`; src/vs/platform/agentHost/node/agentHostServerMain.ts:202 hardcodes `byok: { kind: 'unavailable' }` for its (remote/standalone) launch path, while the local utility-process entry (src/vs/platform/agentHost/node/agentHostMain.ts:129) uses `{ kind: 'renderer', bridgeRegistry }`.
- **listModels gate:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts:160-191 enumerates only models the renderer's own `ILanguageModelsService` can see and reach via the bridge; if the serving connection differs for a WSL session, its BYOK models would not surface.
- **not yet independently confirmed:** Could not pin down with certainty (without executing code) which concrete agent-host launch path a plain Remote-WSL folder open takes for the in-workbench Agents window, versus the opt-in 'Remote Agent Host' (dedicated/editor) feature under src/vs/sessions/contrib/providers/remoteAgentHost/.
