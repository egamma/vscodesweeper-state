# Issue #303886 — Sessions App: Elapsed time

[https://github.com/microsoft/vscode/issues/303886](https://github.com/microsoft/vscode/issues/303886)

## Summary

Keep open: the current sessions list still suppresses its timestamp while the main chat is running, and its existing relative timestamps do not measure running duration. This team-authored request has a concrete navigation use case, but the thread leaves the readability tradeoff unresolved.

## Change summary

Show elapsed running time in the sessions list so users can distinguish long-running sessions without opening each one.

## Best solution

Provide a glanceable running-duration indication in the Agents Window sessions list, with agreed timing semantics and presentation that preserves row readability. Completion recency should remain distinguishable from elapsed execution time.

- **Behavior:**

  > Users need to distinguish short-running and long-running sessions from the sessions list without opening each session. The requested indication represents elapsed running time, not time since the last update or completion. Timing boundaries and presentation must first be agreed with the maintainer.
- **Trace:**

  > SessionItemRenderer in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts derives timeDate from mainChat.updatedAt but suppresses it for InProgress; formatSessionListTime formats recency rather than runtime. The internal showMetadataWhileActive override is used by externally linked automation runs and does not provide a running-duration capability for the primary list. The list specification requires provider-neutral observable state and safe virtualized-row reuse; existing minute timers are disposed with row state. Investigate the timing information available through session.ts before deciding whether the requested duration can be derived reliably. Preserve existing completion-recency semantics and automation behavior. The unresolved product discussion is recorded at https://github.com/microsoft/vscode/issues/303886.
- **Open decisions:**
  - Should elapsed time measure the current turn or the session's cumulative execution, and should time waiting for user input count?
  - Should running duration be shown directly in the normal session row despite the readability concern raised in the thread, or through another list-level presentation that still avoids opening individual sessions?
