# Issue #167788 — Weird overcaching of code for extension host

[https://github.com/microsoft/vscode/issues/167788](https://github.com/microsoft/vscode/issues/167788)

## Summary

Still valid on main: the extension host inherits `VSCODE_CODE_CACHE_PATH` for non-dev-mode, so V8 bytecode cached under `CachedData/<commit>/` can become stale when workspace `node_modules` files change within the same VS Code version. The fix from #105512 only covers `_isExtensionDevHost`; normal extension host processes are still affected.

## Change summary

V8 code cache for extension-host-loaded workspace modules becomes stale when `node_modules` are upgraded, causing 'Cannot find module' errors until `--no-cached-data` is used.

## Best solution

Either disable V8 code caching for workspace-originated modules loaded by the extension host (extending the #105512 approach beyond dev mode), or implement content-hash-aware cache invalidation for the extension host's cached data. The fix area is `src/vs/workbench/services/extensions/electron-browser/localProcessExtensionHost.ts` around the `VSCODE_CODE_CACHE_PATH` handling.
