# Issue #337351 — Make agent bake-offs available as an agent-invokable tool

[https://github.com/microsoft/vscode/issues/337351](https://github.com/microsoft/vscode/issues/337351)

## Summary

Brand-new, team-authored (COLLABORATOR) design proposal for an Agent Host tool with no implementation yet on main; it explicitly lists open design questions, so it stays open for planning rather than any close.

## Change summary

Expose an Agent Host tool an agent can invoke to run a bounded, isolated bake-off comparing multiple models/providers/agents/configs on the same task and return structured comparable results.

## Best solution

Work through the listed open design questions (schema/result format, candidate dimensions, success-criteria evaluation, telemetry, confirmation/policy gates) with the agent-host team, then implement as a new server tool alongside existing ones in src/vs/platform/agentHost/node/shared (e.g. near sessionServerTools.ts / agentServerToolHost.ts), reusing the existing child-session/subagent infrastructure (agentService.ts, claudeSubagentSignals.ts) for isolation and cleanup.

## Plan brief

- **Behavior:**

  > An agent can invoke a new tool with a bounded set of candidates (models/providers/agents/configs) and a task/eval prompt; each candidate runs in an isolated, cancellable child session with configurable concurrency/timeout/resource limits; the tool returns a structured, comparable result set (outcome, summary, diff, validation results, duration, usage/cost) and can identify a selected/recommended result; child sessions and worktrees are reliably cleaned up including on cancellation or partial failure.
- **Trace:**

  > No existing code implements this: a repo-wide search for 'bakeoff'/'bake-off' in src/ is empty. The nearest existing infrastructure is the agent-host server tool contribution pattern (src/vs/platform/agentHost/node/shared/agentServerToolHost.ts, sessionServerTools.ts) and child/subagent session handling (src/vs/platform/agentHost/node/agentService.ts, node/claude/claudeSubagentSignals.ts), which would need to be extended to orchestrate multiple concurrent isolated sessions rather than a single subagent. The issue itself lists unresolved product questions that must be settled before coding starts.
- **Open decisions:**
  - What is the stable tool schema and structured result format for the comparison?
  - Which candidate dimensions are supported initially (model, provider, custom agent, permission profile, prompt variation)?
  - How are success criteria supplied and evaluated without letting the judge silently redefine the task?
  - What telemetry and user-visible progress must be surfaced during a bake-off run?
  - What confirmation or policy gates are required before spawning multiple sessions or consuming significant resources?
