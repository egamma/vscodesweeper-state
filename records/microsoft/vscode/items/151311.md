# Issue #151311 — editor.actions.findWithArgs behaves inconsistently when searchString is empty

[https://github.com/microsoft/vscode/issues/151311](https://github.com/microsoft/vscode/issues/151311)

## Summary

The empty-search inconsistency remains traceable in current main. Keep this issue open while the explicitly linked fix candidate is reviewed; its PR is still open and unmerged.

## Change summary

Repeatedly invoking editor.actions.findWithArgs with an explicit empty searchString alternates between an empty query and selected editor text.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/334803 if it correctly preserves explicit search strings, including empty strings, while retaining automatic seeding when searchString is omitted. Variable substitution is separate work and should not expand this fix's scope.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/vscode/issues/151311 supplies a cmd+f binding invoking editor.actions.findWithArgs with {"isRegex":true,"searchString":""}; repeated invocation alternates between an empty query and the selected text.
- **Current source confirms the defect:** src/vs/editor/contrib/find/browser/findController.ts, StartFindWithArgsAction.run, constructs newState from args but chooses selection seeding using the previous controller searchString.length rather than whether args.searchString was supplied. CommonFindController._start spreads newState and then overwrites its searchString with selected text when seeding is enabled. With globalFindClipboard disabled, an initially empty query becomes the selection, the next invocation applies the explicit empty string, and the cycle repeats. Its clipboard fallback also treats an explicit empty string as absent.
- **Human-owned open fix candidate:** https://github.com/microsoft/vscode/pull/334803 was verified OPEN with mergedAt null and explicitly says Fixes #151311. Its diff gates selection and clipboard seeding on args.searchString being undefined and adds repeated-invocation tests for omitted, empty, and non-empty search strings. This is a candidate fix, not a completed implementation.
