# Issue #167969 — Tasks use Windows instead of WSL env on WSL

[https://github.com/microsoft/vscode/issues/167969](https://github.com/microsoft/vscode/issues/167969)

## Summary

Still reproduces on main: `${env:FOO}` in tasks resolves against the Windows renderer process environment rather than the WSL remote environment. The browser ConfigurationResolverService passes an empty env object, and no fix has been committed. Team-authored with `help wanted` — keeping open for a contributor.

## Change summary

Task variable `${env:...}` substitutes Windows host environment variables instead of WSL remote environment variables when running tasks in a WSL remote session.

## Best solution

The browser `ConfigurationResolverService` (src/vs/workbench/services/configurationResolver/browser/configurationResolverService.ts) passes `Promise.resolve(Object.create(null))` as `envVariablesPromise`, so `${env:FOO}` falls through to the renderer's `process.env`. It should instead obtain the remote environment (e.g. via the remote agent service) so that env-variable resolution in tasks reflects the WSL-side environment. The fix is localized to how the browser config resolver sources its environment promise, and possibly how `taskSystemInfo.resolveVariables` propagates the remote env for `CustomExecution`-based tasks.
