# Issue #239851 — Force Update Git internals when Refreshing Explorer

[https://github.com/microsoft/vscode/issues/239851](https://github.com/microsoft/vscode/issues/239851)

## Summary

Keep open: current source confirms that manual refresh does not invalidate cached Git-ignore decorations. The maintainer accepted investigating Explorer refresh, and the related older issue does not own the full requested recovery behavior across Explorer and open editors.

## Change summary

Make manual refresh recover stale Git-ignore and modification indicators without closing and reopening the project.

## Best solution

Provide reliable manual recovery of Git-derived decorations, including ignore-state changes after files leave the index. Establish the Explorer-to-Git refresh boundary and diagnose the open-editor indicators before treating the entire report as resolved.

## Evidence

- **Reporter-confirmed recovery failure:** https://github.com/microsoft/vscode/issues/239851#issuecomment-2787665081 describes adding .vscode to .gitignore, removing files from the index, committing, and running Git: Refresh without updating Explorer colors; reopening the project restores the correct ignored appearance.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/239851#issuecomment-2788712706 distinguishes Source Control refresh from Explorer refresh and accepts investigating Explorer recovery. This is accepted work, not grounds for an as-designed decline.
- **Current ignore invalidation gap:** extensions/git/src/decorationProvider.ts, GitIgnoreDecorationProvider, invalidates decorations only on saves of .gitignore or .git/info/exclude and repository open/close. It does not subscribe to repository status refresh. Consequently, an ignore result cached while a file is tracked can survive subsequent index removal and manual Git refresh.
- **Cache preserves the stale result:** src/vs/workbench/services/decorations/browser/decorationsService.ts:279-355 caches decoration results per provider, including null results. getDecoration fetches again only when the provider entry is absent; provider change events invalidate those entries. A tree refresh alone does not clear this cache.
- **Existing refresh commands are partial coverage:** extensions/git/src/commands.ts:808-810 routes git.refresh to Repository.refresh in extensions/git/src/repository.ts:1180-1183. GitDecorationProvider listens to onDidRunGitStatus, but GitIgnoreDecorationProvider does not. workbench.files.action.refreshFilesExplorer in src/vs/workbench/contrib/files/browser/views/explorerView.ts:1152-1176 calls ExplorerService.refresh; src/vs/workbench/contrib/files/browser/explorerService.ts:356-373 refreshes the filesystem tree without requesting Git refresh or decoration-cache invalidation.
- **Older related issue is not full-scope coverage:** https://github.com/microsoft/vscode/issues/70963 is open and older, and its discussion confirms intermittent missing ignore colors, including the reporter's earlier refresh proposal at https://github.com/microsoft/vscode/issues/70963#issuecomment-1055891541. It primarily tracks ignore coloring across several causes, whereas this item additionally requests explicit recovery of modification decorations and open-editor indicators. It is related, not a verified full-scope duplicate.
