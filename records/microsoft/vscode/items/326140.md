# Issue #326140 — Package.json dependency metadata lookup; slow with PNPM

[https://github.com/microsoft/vscode/issues/326140](https://github.com/microsoft/vscode/issues/326140)

## Summary

The PNPM hover slowdown remains present on current main: every dependency metadata request waits for a project-local `npm ls --depth=0`, whose traversal cost can dominate in a large non-hoisted PNPM installation. No older open issue reports this same observable symptom, so this should remain open in the npm area.

## Change summary

Dependency hovers in package.json take up to eight seconds in large PNPM projects using the default non-hoisted node_modules layout.

## Best solution

Make package metadata hovers resolve promptly in non-hoisted PNPM projects without unnecessarily traversing the complete dependency layout, while preserving installed-version information when it can be obtained efficiently.

## Plan brief

- **Likely files:** `extensions/npm/src/features/packageJSONContribution.ts`, `extensions/npm/src/test`
- **Validation:** Add an npm extension test that models a fast registry metadata result and a slow project-local installed-version lookup, then assert that the dependency hover meets the selected responsiveness contract; run the npm extension integration-test configuration labeled `npm`.
- **Behavior:**

  > In a package.json from a large PNPM project using the default non-hoisted node_modules layout, hovering a dependency name or version must show package metadata promptly rather than remaining on “Loading...” for several seconds. Hover behavior in npm and hoisted projects must remain responsive. The treatment of the installed-version line must follow the maintainer's decision below and be covered explicitly by the test.
- **Trace:**

  > PackageJSONContribution.fetchPackageInfo in extensions/npm/src/features/packageJSONContribution.ts starts npmView and npmListInstalledVersion together and awaits both through Promise.all. npmListInstalledVersion executes `npm ls --json --depth=0 -- <package>` with the package.json directory as cwd, making every hover wait for traversal of the project's dependency layout; the reporter's `node-linker=hoisted` result is consistent with this path. Commit e42ae9ae255821a0a9ade39f65298aacc159d177 introduced that lookup, while 4c482dcb913d7a27a18dfa3fc36b37ea76d3fbe7 only parallelized it. The `npm.packageManager` setting currently belongs to task execution in extensions/npm/src/tasks.ts and does not select the hover command. Keep registry lookup semantics, package validation, completion behavior, and non-dependency package.json hovers unchanged.
- **Open decisions:**
  - When installed-version discovery is slow in a PNPM project, must the initial hover continue waiting to include that line, should it omit the line to preserve responsiveness, or should VS Code use the project's selected package manager to obtain it efficiently?
