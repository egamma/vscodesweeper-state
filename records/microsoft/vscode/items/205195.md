# Issue #205195 — Provide Notebook Cell Progress Bar Control in Extension API

[https://github.com/microsoft/vscode/issues/205195](https://github.com/microsoft/vscode/issues/205195)

## Summary

Keep open: the extension API still does not expose determinate notebook-cell execution progress, and an open PR already proposes this capability. Review the existing contribution rather than starting a competing implementation.

## Change summary

Expose an extension API for reporting determinate execution progress through the built-in notebook-cell progress bar.

## Best solution

Resolve the public API contract through review of https://github.com/microsoft/vscode/pull/205204, allowing notebook controllers to report determinate cell progress while preserving indeterminate progress when no measurements are supplied.

- **Current cell rendering:** src/vs/workbench/contrib/notebook/browser/view/cellParts/cellProgressBar.ts routes executing cells through showProgressBar(), which unconditionally calls progressBar.infinite().show(500). The current cell surface therefore does not expose the requested determinate behavior.
- **Partial alternative is not coverage:** src/vscode-dts/vscode.d.ts:13014-13065 exposes ProgressLocation.Notification for discrete progress and other window/view progress locations, but no notebook-cell location. Notification progress or cell status-bar text does not provide the requested native cell progress bar.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/205204 is OPEN. Its body explicitly says it resolves this issue and proposes NotebookCellExecution.setTotalProgress(), setProgress(), and setIncrementProgress(), retaining infinite progress when these methods are unused. This is an existing human-owned implementation candidate, not a landed fix.
