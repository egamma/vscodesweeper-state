# Issue #131370 — The kernel selection UI should not appear if only one notebook controller is marked as preferred

[https://github.com/microsoft/vscode/issues/131370](https://github.com/microsoft/vscode/issues/131370)

## Summary

Keep open: current notebook execution still prompts when multiple controllers are available even if exactly one is preferred. The existing history-service test explicitly preserves this behavior, so changing it needs a product decision rather than a completed-fix close.

## Change summary

Automatically use the sole preferred notebook controller without prompting, while retaining kernel selection when preference is ambiguous.

## Best solution

Honor a unique extension-declared preferred controller for a previously unbound notebook, preserving explicit selections and prompting when multiple controllers are preferred. Confirm that policy for the current MRU picker before changing its selection behavior.

- **Behavior:**

  > A notebook opened without a previous VS Code kernel binding should use its uniquely preferred controller without requiring a kernel-picker interaction, even when another compatible controller is installed. An existing explicit selection remains authoritative. If multiple controllers are preferred, the user must still choose. Acceptance includes first execution without a picker for the unique-preference case and unchanged selection behavior for ambiguous preferences.
- **Trace:**

  > NotebookKernelService.getSelectedOrSuggestedKernel() already recognizes a sole affinity-2 controller, but NotebookExecutionService.executeNotebookCells() resolves through KernelPickerMRUStrategy.resolveKernel() instead. That resolver uses NotebookKernelHistoryService.getKernels(), which only supplies an existing binding or the sole available controller and otherwise invokes SELECT_KERNEL_ID. The history test 'notebook kernel empty history' explicitly expects no automatic selection after one of two controllers becomes preferred, establishing that this is a requested policy change rather than an accidental deviation from current tests. - **Open decisions:**
