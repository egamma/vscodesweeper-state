# Issue #332557 — The "filename | path" rendering broke my expectation

[https://github.com/microsoft/vscode/issues/332557](https://github.com/microsoft/vscode/issues/332557)

## Summary

Keep open for a multi-file diff header design decision: current source still separates the filename from its trailing directory description, which explains the reported scanning confusion. This is team-authored UX feedback, not grounds for an as-designed close.

## Change summary

Make multi-file diff headers easier to recognize when users expect the filename to be the final path segment.

## Best solution

Agree on a header presentation that makes the filename unmistakable while retaining directory context for similarly named files. Evaluate path-first presentation against the existing workbench filename-first convention before changing shared resource labels.
