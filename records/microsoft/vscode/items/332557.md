# Issue #332557 — The "filename | path" rendering broke my expectation

[https://github.com/microsoft/vscode/issues/332557](https://github.com/microsoft/vscode/issues/332557)

## Summary

A team-authored UX observation about the multi-file diff editor's file header ordering (filename shown before path, unlike GitHub's PR review UI); this is a fresh, unactioned suggestion with no fix yet, so it should be routed to the diff-editor area for a maintainer decision rather than closed.

## Change summary

In the multi-file diff editor, file headers render as `<filename> <path>`, which can read confusingly when the last path segment looks like a folder name that resembles a filename (e.g. `viewModel`).

## Best solution

A maintainer familiar with `src/vs/editor/browser/widget/multiDiffEditor/diffEditorItemTemplate.ts` (which drives the header via `IResourceLabel.setUri`) should decide whether to reorder the label so the path/breadcrumb is visually distinguished from the filename, similar to GitHub's PR file header layout; this is a design/consistency call, not a mechanical fix.
