## Evidence

- **Current source confirms the reported trigger:** In src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkParsing.ts, detectLinks calls detectPathsNoSuffix for './src/(hello)/[world]/file.tsx'. RegexPathConstants.ExcludedPathCharactersClause and WinExcludedPathCharactersClause explicitly exclude '(' and ')', and unixLocalLinkClause/winLocalLinkClause use those clauses throughout path segments. Consequently, the complete reported path cannot be returned as one no-suffix path. This was established by source inspection without executing code.
- **Confirmed discussion and narrower bracket support:** https://github.com/microsoft/vscode/issues/212109#issuecomment-2558270966 confirms that individual bracket or parentheses segments behave differently from combined '[test]/(test)/file.txt'; the subsequent maintainer comment reports '[test]/[test]/file.txt' working. The current source permits square brackets inside paths but still excludes parentheses, supporting the diagnosis rather than treating every bracket-containing path as broken.
- **Open implementation candidates:** GitHub read-only inspection verified that https://github.com/microsoft/vscode/pull/304992 and https://github.com/microsoft/vscode/pull/340113 are both OPEN with mergedAt null, and both explicitly reference this issue with closing syntax. The former removes parentheses exclusions; the latter proposes balanced segments and reports that removing exclusions alone incorrectly includes trailing punctuation in '(./foo/bar)'. These are pending proposals, not landed fixes.
- **Workaround is partial coverage:** The reporter's linked workaround at https://github.com/microsoft/vscode/issues/236436#issuecomment-2556493155 removes square brackets from terminal.integrated.wordSeparators. Current terminalWordLinkDetector.ts reads that setting, whereas terminalLinkParsing.ts uses independent path regexes. Changing word separators can help word-link detection but does not correct the confirmed local-path parser defect.
- **Existing consolidation and canonical search:** https://github.com/microsoft/vscode/issues/236436 is closed, with https://github.com/microsoft/vscode/issues/236436#issuecomment-2557070593 explicitly marking it as a duplicate of this issue. Searches for open terminal-link reports involving parentheses and brackets found no verified older issue owning the same symptom; this report remains the established tracking location.
- **Earlier bracket fix does not complete this report:** https://github.com/microsoft/vscode/pull/169774 is merged and titled 'Full support for local files and folders containing [ and ] chars'. It addresses square-bracket support, while the current source still excludes parentheses on the reporter's no-suffix path. It is not evidence that this combined-segment report is resolved.
