# Issue #212109 — Parentheses `()` and square brackets `[]` in file names can break terminal links (eg. next.js dynamic file paths)

[https://github.com/microsoft/vscode/issues/212109](https://github.com/microsoft/vscode/issues/212109)

## Summary

Still reproduces on main: parentheses and brackets are explicitly excluded from terminal link path characters, breaking links for Next.js dynamic routes and similar patterns. An open PR (#304992) is attempting a fix.

## Change summary

Terminal links break when file paths contain parentheses `()` or mixed brackets/parens (e.g. Next.js dynamic route segments like `[slug]/(group)/page.tsx`).

## Best solution

Land PR https://github.com/microsoft/vscode/pull/304992 (or an equivalent fix) that extends the path character regexes in `terminalLinkParsing.ts` to allow balanced parentheses and brackets within paths, while preserving the existing line:col suffix parsing that uses `()` and `[]` as delimiters.

## Evidence

- **source trace:** In src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkParsing.ts, `ExcludedPathCharactersClause` (line 345) excludes `()` and `ExcludedStartPathCharactersClause` (line 346) excludes `()[]` from valid path characters, causing paths like `./src/(hello)/[world]/file.tsx` to be split at those characters.
- **suffix path regex:** Line 212: `linkWithSuffixPathCharacters` regex also excludes `[({` from the start of paths, compounding the issue when brackets appear after a suffix match.
