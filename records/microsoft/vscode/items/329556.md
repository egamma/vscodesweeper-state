# Issue #329556 — Level 4 Markdown heading gets duplicated in rendered preview

[https://github.com/microsoft/vscode/issues/329556](https://github.com/microsoft/vscode/issues/329556)

## Summary

Detailed, cross-platform (Windows, Linux, vscode.dev), extensions-disabled report with exact repro steps and a public sample repo; the author independently re-confirmed it in a second comment. This looks like a real defect in the markdown preview's incremental DOM update path, so it should be routed to the markdown preview area rather than closed.

## Change summary

Editing/appending unrelated content in a Markdown file while Preview is open to the side causes an existing heading elsewhere in the document to be duplicated and moved to a second location in the rendered preview.

## Best solution

Investigate the incremental preview-update path in extensions/markdown-language-features/preview-src/index.ts (the morphdom-based patch in the 'updateContent' message handler, especially the onBeforeElUpdated data-line reconciliation added for the recent diff/change-indicator feature) for a node-matching bug that duplicates/misplaces subtrees when content is appended; the recent diff-highlighting commits (e.g. 'Various improvements and fixes for markdown diff rendering', 'Fix some bugs and clean up how markdown change indicators are rendered') are a good place to start bisecting since this is a fairly newly-touched code path.

## Evidence

- **cross-env confirmation:** Author reproduced with all extensions disabled on Windows and separately confirmed reproduction on github.dev/vscode.dev and Linux (comment at 2026-08-07T09:16:34Z).
- **incremental update path:** extensions/markdown-language-features/preview-src/index.ts lines ~339-409: the 'updateContent' handler re-parses the full new HTML and uses morphdom({childrenOnly:true, onBeforeElUpdated...}) to patch the existing '.markdown-body' DOM in place; onBeforeElUpdated has custom logic (lines 374-392) that manually copies 'data-line' attributes across matched nodes and logs 'unexpected line number change' when element counts differ, suggesting known fragility in node matching for this diff.
- **engine renders full doc, not incremental:** extensions/markdown-language-features/src/markdownEngine.ts render() re-renders the whole document's tokens each time (no partial re-render), so the duplication must originate in the client-side morphdom patch step rather than the server-side markdown-it rendering.
- **recent churn in this area:** git log on preview-src/index.ts shows very recent commits ('Fix some bugs and clean up how markdown change indicators are rendered', 'Various improvements and fixes for markdown diff rendering', 'Add inner highlighting support in md diff preview') touching exactly this update/diff-highlight pipeline, making it a plausible regression source.
