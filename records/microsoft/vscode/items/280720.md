# Issue #280720 — `chat.tools.eligibleForAutoApproval` setting doesn't work with tools from extensions

[https://github.com/microsoft/vscode/issues/280720](https://github.com/microsoft/vscode/issues/280720)

## Summary

Still reproduces on main: the `isToolEligibleForAutoApproval` method in `languageModelToolsService.ts` looks up tools by their full reference name (which for extension tools is `extensionId/toolName`), but when users configure the setting with a bare tool name like `issue_fetch`, no fallback match to the bare name is attempted — the setting is silently ignored.

## Change summary

The `chat.tools.eligibleForAutoApproval` setting does not match extension-provided tools when configured with the bare tool name (e.g. `issue_fetch`) rather than the full namespaced name (e.g. `github.vscode-pull-request-github/issue_fetch`).

## Best solution

Add a fallback in `isToolEligibleForAutoApproval` (in `src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts`) to also check the bare `toolReferenceName` when the full namespaced name doesn't match the config. Alternatively, ensure IntelliSense for the setting always suggests the correct full reference name and the documentation makes the required format clear. The existing tests only cover `ToolDataSource.Internal` tools — extension-sourced tools need test coverage here.
