# Issue #302656 — Copilot CLI: Simpler way to open terminal associated with Session

[https://github.com/microsoft/vscode/issues/302656](https://github.com/microsoft/vscode/issues/302656)

## Summary

Keep open: the existing terminal command still requires a session-item argument, so assigning it a keyboard shortcut alone does not remove the Sessions-list detour. The newer Agents Window manages session terminals automatically, but that does not establish completion of this team-authored request for the regular workbench.

## Change summary

Provide a direct way to open a terminal in the current Copilot CLI session's worktree without navigating to the Sessions list.

## Best solution

Provide a discoverable, keyboard-accessible action from the current CLI session that opens a shell in its working directory while preserving the existing list-context action. Decide whether this warrants a default shortcut or only a bindable command.

Verify the existing context-menu action still targets the clicked session rather than the active one, and that opening a shell does not resume the CLI agent.
- **Behavior:**

  > A user viewing a Copilot CLI session can open a terminal in that session's worktree without returning to the Sessions list. The terminal must target the invoked session, not an unrelated active terminal or another session's directory. Existing list-context terminal actions must retain their targeting behavior. Opening a working-directory shell remains distinct from resuming the CLI session in a terminal.
- **Trace:**

  > github.copilot.cli.sessions.openWorktreeInTerminal is registered in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts and copilotCLIChatSessions.ts; both handlers require a ChatSessionItem resource and otherwise return. They already resolve the session directory and create a visible terminal, while package.json exposes the command through the session context menu and hides it from the Command Palette. The remaining uncertainty is the intended direct invocation surface and its session-targeting contract, not directory-resolution mechanics. src/vs/sessions/contrib/terminal/browser/sessionsTerminalContribution.ts already supplies automatic terminal association in the separate Agents Window; do not treat that as coverage of the regular workbench or alter its lifecycle for this request. https://github.com/microsoft/vscode/issues/297829 concerns failing actions, and https://github.com/microsoft/vscode/issues/298170 concerns naming; neither is a verified duplicate.
- **Open decisions:**
  - Should direct invocation target the currently viewed CLI chat session, or offer a session picker when no CLI chat has focus?
  - Should this ship with a default keyboard shortcut, or as a discoverable command users can bind themselves?
