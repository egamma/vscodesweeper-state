[https://github.com/microsoft/vscode/issues/272827](https://github.com/microsoft/vscode/issues/272827)

## Summary

The request to fold multiple pills for the same file into one consolidated UI element remains a valid UX improvement. Related work (ChatCheckpointFileChangesSummaryContentPart, simpler changed file pill) has landed but no commit explicitly references this issue or addresses the exact inline-pill deduplication described.

## Change summary

When chat applies multiple edits to the same file, each edit renders as a separate pill — the same filename appears multiple times instead of being consolidated into one entry.

## Best solution

Consolidate per-file edit pills so that when a response contains multiple edits to the same file, only one pill is shown (possibly with aggregated +/- stats or a collapsible view). The change would likely live in the chat content-part rendering pipeline that produces inline edit pills (chatTextEditContentPart.ts or the code-block rendering path).
