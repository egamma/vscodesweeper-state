# Issue #339869 — Steering message is stuck on the idle chat

[https://github.com/microsoft/vscode/issues/339869](https://github.com/microsoft/vscode/issues/339869)

## Summary

Fresh, team-authored bug report on the in-progress cross-session steering feature. Traced the likely race in source: a steering message set on a chat's activeTurn is only cleared by an explicit provider 'steering_consumed' signal or by being admitted as a new turn's queuedMessageId — nothing clears it when the targeted turn finishes before the provider acts on it, so it can be left stuck forever (and also blocks future steer attempts via the `cannotSteer` check).

## Change summary

Sending a 'steer' message to another (side) chat can leave a stale steering message displayed even after both chats have finished their turns.

## Best solution

In the turn-completion path (e.g. QueueDrainContribution.onTurnEnd in src/vs/platform/agentHost/node/chatContributions/queueDrain/queueDrainContribution.ts, or AgentSideEffects' turn-end handling), detect an un-consumed steeringMessage when its owning turn ends and resolve it explicitly — clear it, re-queue it, or surface a failure to the sender — rather than leaving it stuck; a maintainer should decide the exact fallback behavior for the orphaned message's content and sender-visible status.
