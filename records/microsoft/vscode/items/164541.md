# Issue #164541 — Expand state is kept even after switching setting

[https://github.com/microsoft/vscode/issues/164541](https://github.com/microsoft/vscode/issues/164541)

## Summary

Still present on current main: the Outline pane caches per-file tree view state in an in-memory LRU and never invalidates it when `outline.collapseItems` changes, so already-visited files keep their old expansion state until a reload. Team-authored and still carrying `under-discussion`, so it stays open — the remaining question is how far the reset should go.

## Change summary

Changing `outline.collapseItems` does not reset the remembered per-file outline expansion state for files already visited in the session.

## Best solution

Invalidate (or re-seed) the Outline pane's `_treeStates` cache in src/vs/workbench/contrib/outline/browser/outlinePane.ts when `outline.collapseItems` changes, so the new default applies to previously visited files without a window reload; keep the per-file memory itself, which jrieken and dbaeumer both consider the right design.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/outline/browser/outlinePane.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts`, `src/vs/workbench/contrib/outline/browser/outline.contribution.ts`
- **Validation:** After changing `outline.collapseItems` to `alwaysCollapse`, reopening a previously visited file shows a collapsed outline without a window reload, while the per-file expansion memory still works within a single setting value.
- **Behavior:**

  > With the Outline pane open, expand a file's outline, then change `outline.collapseItems` to `alwaysCollapse`. Switching back to that file (or closing and reopening it) should honor the new setting rather than the state remembered under the old one; today only a window reload does that. Per-file expansion memory must keep working as before while the setting is unchanged — jrieken confirmed that part is by design. Acceptance: the setting change takes effect for already-visited files in the same session, for both the active editor and files revisited later.
- **Trace:**

  > The Outline pane keeps an in-memory `LRUCache<string, IAbstractTreeViewState> _treeStates` (src/vs/workbench/contrib/outline/browser/outlinePane.ts:76), written in `_captureViewState` (line 193) and read in `updateTree` at line 287 when the tree input is first set. There is no configuration listener in that file, so a change to `outline.collapseItems` never invalidates the cache; the setting itself is only read once per outline instance into `collapseByDefault` in DocumentSymbolsOutline's constructor (src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts:164), and it is ignored whenever a stored view state is applied. A reload works only because the LRU is session-scoped. Boundary: do not remove or persist per-file state memory, and leave the breadcrumbs/notebook outline paths (notebookOutline.ts reads the same key separately) untouched unless the maintainer asks for them. Discussion: https://github.com/microsoft/vscode/issues/164541#issuecomment-1290031459.
- **Open decisions:**
  - On a `outline.collapseItems` change, should all remembered per-file states be discarded, or only the collapse/expand defaults re-applied while preserving other view state (scroll, focus)?
  - Should the reset also apply to the notebook outline and breadcrumbs, which read the same setting, or only to the Outline pane's document-symbol trees?
  - Should the currently active file's outline update immediately on the setting change, or only the next time it is revisited?

## Evidence

- **cause on main:** src/vs/workbench/contrib/outline/browser/outlinePane.ts:76 holds `private _treeStates = new LRUCache<string, IAbstractTreeViewState>(10);`, written at line 193 (`_captureViewState`) and read at line 287 when a tree input is set. A grep of that file shows no `onDidChangeConfiguration` listener at all, so nothing clears the cache when the setting changes — matching the report that only a reload (which drops the in-memory LRU) restores the collapsed default.
- **setting read once per outline:** src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts:164 reads `OutlineConfigKeys.collapseItems` once in the constructor into `collapseByDefault`; that default is only consulted when no stored view state is applied, so a cached state wins over the new setting.
- **maintainer discussion:** jrieken confirmed the per-file persistence is by design (https://github.com/microsoft/vscode/issues/164541#issuecomment-1290031459); dbaeumer agreed with the design but expects the state to be reset when the setting changes. The issue still carries `under-discussion`.
