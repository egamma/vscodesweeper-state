# Issue #164541 — Expand state is kept even after switching setting

[https://github.com/microsoft/vscode/issues/164541](https://github.com/microsoft/vscode/issues/164541)

## Summary

Keep open: this team-authored design discussion identifies a real gap on current main, where changing `outline.collapseItems` does not invalidate cached per-file expansion state.

## Change summary

Reset remembered Outline expansion states when the collapse-items setting changes.

## Best solution

Decide whether a setting change should clear all cached Outline tree states, then implement that behavior in `OutlinePane` while preserving per-file state during ordinary editor switching.

## Evidence

- **current source:** `src/vs/workbench/contrib/outline/browser/outlinePane.ts` stores per-resource states in `_treeStates` and restores them in `updateTree`; it has no configuration-change listener that clears those states.
- **setting application:** `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts` reads `outline.collapseItems` only while constructing the outline's initial tree options, after which a cached view state can override that default.
- **existing capability:** `outline.collapseItems` exists on main, but it does not cover the central request because changing it does not reset remembered state until the in-memory `OutlinePane` cache is discarded.
- **maintainer discussion:** The discussion at https://github.com/microsoft/vscode/issues/164541 agrees that per-file expansion memory is intentional while leaving open whether changing the setting should reset it.
