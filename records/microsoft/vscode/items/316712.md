# Issue #316712 — Agent SSH connection fails on Windows target due to Unix-only probe (uname -s)

[https://github.com/microsoft/vscode/issues/316712](https://github.com/microsoft/vscode/issues/316712)

## Summary

Confirmed in source: the SSH agent host connection unconditionally runs `uname -s` / `uname -m` and `resolveRemotePlatform()` only handles Linux and Darwin — Windows SSH targets are unsupported. The bug is still present on current main, and a newer duplicate (#327469) has been assigned to a team member, indicating active awareness.

## Change summary

Agent SSH connection to Windows hosts fails because the platform detection probe uses Unix-only `uname` commands that don't exist in PowerShell.

## Best solution

Add Windows support to the SSH platform detection in `sshRemoteAgentHostService.ts` and `sshRemoteAgentHostHelpers.ts`: detect when `uname` fails and fall back to a PowerShell-compatible probe (e.g. `[System.Environment]::OSVersion`), then extend `resolveRemotePlatform()` to handle Windows identifiers. The newer issue https://github.com/microsoft/vscode/issues/327469 is assigned to joshspicer — this issue is the original report and should be kept as the canonical tracker or consolidated with that one.
