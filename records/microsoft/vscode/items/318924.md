# Issue #318924 — Copilot resumes chat when it should not

[https://github.com/microsoft/vscode/issues/318924](https://github.com/microsoft/vscode/issues/318924)

## Summary

Keep open: current source suppresses notifications when the user closes a terminal, but stopping its background application can still start another agent turn after the previous answer finished. Automatic background completion turns are intentional today, so the remaining request needs a product decision about when a completed task should stop accepting them.

## Change summary

Prevent stopping a leftover background application from restarting an agent conversation that has already completed its task.

## Best solution

Distinguish an agent waiting for background results from an agent that has declared its task finished, preserving useful asynchronous continuation without restarting finished work when the user stops a leftover application.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/test/electron-browser/runInTerminalTool.test.ts`
- **Validation:** Extend the run-in-terminal notification tests to distinguish a finished task from intentional waiting for background results. Manually verify an agent-started long-running application: let the agent declare the task finished, then separately close its terminal and interrupt the application; verify the approved continuation policy and preserve notifications for genuinely pending asynchronous work.
- **Behavior:**

  > An agent finishes a testing task but leaves its supporting application running. Stopping that application can produce another agent turn without a new user message. The desired outcome is that finished work does not restart unexpectedly, while work deliberately waiting for background results can still continue. Acceptance must cover manual terminal closure, interruption inside a surviving terminal, normal background completion, and agent cancellation.
- **Trace:**

  > RunInTerminalTool._registerCompletionNotification in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts retains completion listeners after a successful answer and sends system-initiated Steering requests on command completion. Its cancellation guard checks isCanceled, whereas terminal disposal separately suppresses TerminalExitReason.User. ChatServiceImpl.sendRequestInternal queues and processes these requests even when no foreground request is active. The existing runInTerminalTool.test.ts helper sendBackgroundCompletionNotification exercises this event-to-request path. https://github.com/microsoft/vscode/issues/317059 records that automatic continuation is intentional; commit 101c2055872ae901c79abba9e76bcf0a1fa93b76 addressed manual terminal closure only. The unresolved boundary is how to distinguish waiting for asynchronous results from genuinely finished work; do not indiscriminately disable background notifications or kill deliberately persistent servers.
- **Open decisions:**
  - What observable state should distinguish a finished task from an agent intentionally ending its turn while waiting for background results, and should later completion events start another turn in each state?
  - When the user interrupts a leftover application without closing its terminal, should that event suppress automatic continuation even though shell integration reports it as command completion?
