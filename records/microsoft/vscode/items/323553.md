# Issue #323553 — drop indicator for moving one group into another

[https://github.com/microsoft/vscode/issues/323553](https://github.com/microsoft/vscode/issues/323553)

## Summary

The misleading drop target remains traceable on main: dropping the lower adjacent group after the upper group advertises an accepted position but produces no order change, while the line immediately below an expanded header visually suggests nesting. This team-authored issue should remain open for a focused Sessions-list fix.

## Change summary

Make the drop indicator accurately represent the top-level destination when reordering session-group headers.

## Best solution

Keep custom groups as top-level siblings and ensure drag feedback corresponds to the resulting top-level order, without advertising an adjacent no-op slot or visually implying that one group can be nested inside another.

## Evidence

- **source trace:** In src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, SessionsListDragAndDrop.onHeaderDragOver accepts every different top-level header and maps the lower target sector to ListDragOverEffectPosition.After; drop then calls reorderSection with the same target and position.
- **direction-dependent no-op:** For adjacent groups A then B, dragging B onto the lower half of A requests “B after A”, which is already the current order, while the accepted After indicator is rendered directly below A's header and above its children.
