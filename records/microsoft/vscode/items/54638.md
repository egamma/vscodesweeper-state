# Issue #54638 — [scss] Add "Go to or peek defintion" for imported mixins and variables for SCSS files

[https://github.com/microsoft/vscode/issues/54638](https://github.com/microsoft/vscode/issues/54638)

## Summary

Imported SCSS mixin and variable definitions remain outside the built-in navigation support. Keep this accepted Backlog request open: the older related issues do not establish a canonical covering the same navigation symptom under the re-review rules.

## Change summary

Support Go to Definition and Peek Definition for SCSS mixins and variables declared in imported files.

## Best solution

Extend the built-in SCSS language support to resolve imported symbols to their declaration locations, preserving existing same-file navigation. Coordinate the language-service and server work with the broader multi-file investigation without treating import-path links or variable completion as equivalent coverage.

## Plan brief

- **Likely files:** `extensions/css-language-features/server/src/cssServer.ts`, `extensions/css-language-features/server/src/languageModelCache.ts`, `extensions/css-language-features/server/src/test/links.test.ts`, `extensions/css-language-features/server/package.json`
- **Validation:** Add executable two-file SCSS navigation checks with a partial declaring a variable and mixin and a consumer importing and referencing both. Definition requests at the consumer references must return the provider URI and declaration ranges; same-file definitions and existing import-link tests must continue to pass. Manually verify both Go to Definition and Peek Definition on the same fixture.
- **Behavior:**

  > SCSS users should be able to invoke Go to Definition or Peek Definition on a variable reference or mixin invocation whose declaration is in an imported SCSS file. Both actions should identify the declaration in the provider file, not merely open the import target. Acceptance checks cover a variable and mixin imported from a partial, alongside unchanged same-file navigation and import-path links.
- **Trace:**

  > The built-in definition handler in extensions/css-language-features/server/src/cssServer.ts calls findDefinition with the current document and its cached stylesheet. Import-path navigation follows a separate findDocumentLinks2 path with document context. The dependency's current upstream CSSNavigation.findDefinition constructs a symbol scope from one stylesheet and returns only the current document URI; SCSSNavigation extends link resolution but does not override symbol definitions. The investigation therefore reaches a shared language-service boundary, not a bounded server-only omission; the exact bundled implementation and a suitable cross-file resolution contract remain to be established. Preserve same-file definitions, existing import resolution, and unrelated CSS/HTML completion behavior. Related design context is https://github.com/microsoft/vscode/issues/47331, while https://github.com/microsoft/vscode/issues/86085 documents a distinct modern @use example; neither is an eligible canonical for closing this re-reviewed request.
- **Open decisions:**
  - Should the initial supported contract cover legacy @import navigation only, or also namespaced @use and re-exported @forward symbols?
