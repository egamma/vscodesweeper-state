# Issue #160518 — Command palette and customize layout hide behind the WCO

[https://github.com/microsoft/vscode/issues/160518](https://github.com/microsoft/vscode/issues/160518)

## Summary

Keep open as the established report for floating UI obscured by native window controls. The discussion confirms additional affected menus, and current positioning code still permits title-bar overlap; no concrete fixing commit was established.

## Change summary

Prevent the command palette, Customize Layout picker, and title-bar menus from being obscured by window controls in narrow Windows windows.

## Best solution

Make floating UI placement account for the native window-controls region while preserving normal title-bar integration. Retain this older report as the consolidation point for its existing duplicates and coordinate the related context-widget work.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/platform/contextview/browser/contextView.ts`
- **Validation:** On Windows with custom title-bar window controls enabled, narrow the window and open the command palette, Customize Layout, and a title-bar context menu near the controls. Verify that popup text and actions remain visible and clickable, including after resizing while open; compare with a wide window and native title-bar mode.
- **Behavior:**

  > In a narrow Windows window, floating command and layout UI can overlap the native minimize, maximize, and close controls, obscuring content. The finished behavior must keep popup content and actions visible and usable without breaking the window controls. Acceptance includes the command palette, Customize Layout, and title-bar context menus at narrow widths and during resizing. Normal wide-window placement and native title-bar behavior must remain intact.
- **Trace:**

  > Layout.computeContainerOffset in src/vs/workbench/browser/layout.ts places quick input within the title-bar band when the command center is visible. QuickInputController.updateLayout in src/vs/platform/quickinput/browser/quickInputController.ts centers and sizes the unanchored picker against the container without excluding native controls. Electron titleBarOverlay is configured in src/vs/platform/windows/electron-main/windows.ts; context-view positioning has a separate contract in src/vs/platform/contextview/browser/contextView.ts. The historical defect is confirmed by the thread and duplicate reports, but current native rendering was not executed. Diagnose the Windows overlap and enumerate the shared placement consumers before determining the implementation boundary; do not assume a DOM z-index change can place content above native controls. Coordinate with https://github.com/microsoft/vscode/issues/165454 without replacing this older report with that newer issue.
