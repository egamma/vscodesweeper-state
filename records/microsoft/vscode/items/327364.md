# Issue #327364 — [Bug] `chat.sessionSync.enabled` cannot be enabled in `1.131.0-insider`, due to purported organisation-instituted restrictions, despite no organisational accounts added.

[https://github.com/microsoft/vscode/issues/327364](https://github.com/microsoft/vscode/issues/327364)

## Summary

Traced in source: `chat.sessionSync.enabled` is gated by the `CopilotSessionSync` policy, whose value comes solely from the account-level entitlement flag `cloud_session_storage_enabled` (src/vs/workbench/services/accounts/browser/defaultAccount.ts:643) — not from any org membership or the `ChatApprovedAccountOrganizations` gate. The settings editor's generic policy indicator (settingsEditorSettingIndicators.ts:360) always renders 'Managed by organization' for any resolved policy value regardless of source, which is misleading here since the reporter belongs to no organization. Whether the underlying gate itself (an experimental feature rollout flag) is intentional can't be confirmed without server-side data, so this stays open for area-owner triage rather than a close.

## Change summary

Enabling `chat.sessionSync.enabled` is blocked with a message implying an organization policy, even though the user has no organizational GitHub accounts.

## Best solution

Either (a) confirm with the Copilot/session-sync team whether `cloud_session_storage_enabled: false` is an intentional gradual rollout gate for this account and, if so, adjust the generic 'Managed by organization' wording in settingsEditorSettingIndicators.ts to distinguish account/entitlement-driven policy sources from true admin org policies, or (b) if this is unintended, ensure the entitlement flag isn't defaulting to false for ungated accounts.
