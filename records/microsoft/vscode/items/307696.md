# Issue #307696 — User confirmation feedback audio is sometimes not heard in terminal

[https://github.com/microsoft/vscode/issues/307696](https://github.com/microsoft/vscode/issues/307696)

## Summary

Real accessibility bug — the Chromium autoplay policy silently suppresses audio signals when there hasn't been recent user interaction (e.g. during long-running terminal tasks). The code already catches and swallows this error (line 211 of accessibilitySignalService.ts). The issue is valid and remains unresolved on main; keeping open for the accessibility team to explore workarounds.

## Change summary

Terminal confirmation prompts sometimes fail to play audio feedback due to Chromium's autoplay restriction, making them invisible to screen reader users.

## Best solution

Explore workarounds for the Chromium autoplay restriction in `src/vs/platform/accessibilitySignal/browser/accessibilitySignalService.ts` — potential approaches include resuming the AudioContext on any user gesture, using Web Audio API with a persistent AudioContext, or ensuring the ARIA alert (which already fires) is sufficient as a fallback when audio is blocked. Related: https://github.com/microsoft/vscode/issues/178642.
