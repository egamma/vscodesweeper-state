# Issue #299619 — No Workspace/Worktree selector shows up when in an existing  localchat session

[https://github.com/microsoft/vscode/issues/299619](https://github.com/microsoft/vscode/issues/299619)

## Summary

Keep open for a session-context UX decision: current source explicitly restricts the local workspace picker to the welcome flow, but that does not resolve the reported confusion when continuing an existing local session. This team-authored report has neither an explicitly linked fixing commit nor a verified older duplicate.

## Change summary

Make the differing availability of workspace/worktree controls understandable when moving between new-session creation and an existing local chat.

## Best solution

Make the existing local session's workspace context and isolation limitations understandable without implying that its execution location can be changed mid-session. The chat owner should decide whether this needs a persistent context indicator or an explanation associated with session creation.
