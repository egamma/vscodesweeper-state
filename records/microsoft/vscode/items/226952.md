# Issue #226952 — notebookDocument/didChange event's `notebook.version` contains previous notebook version (which means 0 is sent on the first edit)

[https://github.com/microsoft/vscode/issues/226952](https://github.com/microsoft/vscode/issues/226952)

## Summary

The stale notebook version remains possible on current main because the cell
text-document change reaches the extension host before the separate notebook-version update. Keep
this open for the notebook API event-ordering fix.

## Change summary

Ensure LSP notebook didChange notifications carry the incremented notebook
version for cell edits.

## Best solution

Synchronize the parent notebook version before extensions observe the cell's
text-document change, likely across the main-thread/ext-host notebook synchronization path, and add
an API integration test asserting the first edit reports version 1 rather than 0.

the cell-model events that advance the parent notebook.
- **separate notebook update:** src/vs/workbench/contrib/notebook/common/model/notebookTextModel.ts:365-400
increments and emits the notebook version;

extension-host message, and src/vs/workbench/api/common/extHostNotebookDocument.ts:236-242 updates
NotebookDocument.version only when that message arrives.

not make the notebook-version update precede the independently forwarded text-document event
described here.
