# Issue #338398 — Error message could be more helpful

[https://github.com/microsoft/vscode/issues/338398](https://github.com/microsoft/vscode/issues/338398)

## Summary

Traced the exact code path: installing a plugin from a private GitHub repo surfaces the raw `git clone` stderr ("fatal: could not read Username ... terminal prompts disabled") verbatim in a notification. That's real, actionable UX debt, but adding a working 'Sign In' action needs a design decision on how credentials get into the clone, so this is plan-tier rather than a bounded one-file fix.

## Change summary

When cloning a private GitHub plugin repo fails because no git credentials are available, the notification shows the raw low-level git error instead of a clear 'sign in required' message with a Sign In action.

## Best solution

Detect this specific git-auth-failure case in the plugin clone error handler and show a friendly, localized message plus a real Sign In action that supplies GitHub credentials (e.g. via the existing GitHub authentication session) and retries the clone, instead of surfacing raw git stderr.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentPluginRepositoryService.ts`, `src/vs/workbench/contrib/chat/browser/pluginSources.ts`, `src/vs/workbench/contrib/chat/common/plugins/pluginGitService.ts`
- **Validation:** Manually attempt to install a plugin from a private GitHub repo while signed out of GitHub auth; confirm a clear, translated 'sign-in required' message appears with a working Sign In action, and that completing sign-in and retrying successfully installs the plugin.
- **Trace:**

  > The catch block in `_cloneRepository` (agentPluginRepositoryService.ts:355-384) and the equivalent path in pluginSources.ts:192 forward `err?.message` from a failed `this._pluginGit.cloneRepository(...)` call directly into a user-facing notification. When git has no credential helper / no cached auth for a private repo over HTTPS, git fails with 'fatal: could not read Username ... terminal prompts disabled', and that raw string is what the user sees. No code path today inspects the error to detect this specific auth failure, and no code path supplies GitHub-auth-backed credentials to the clone. Boundary: do not change clone behavior for public/already-authorized repos, and do not remove the 'Show Git Output' fallback for other clone failures.
- **Open decisions:**
  - Should the handler special-case this auth-failure pattern with a friendlier localized message, while keeping the raw output only in 'Show Git Output' for diagnostics?
  - Should 'Sign In' actually inject credentials from VS Code's existing GitHub authentication session (e.g. via a credential helper or rewritten clone URL) and automatically retry the clone, or just prompt the user to sign in and re-run install manually?
  - Should this fix apply to all git-clone plugin source paths (marketplace index refresh, direct git-url install, pluginSources.ts) or only the marketplace-listed-plugin install flow this report exercises?
