# Issue #280190 — Regression: The toggle/disable completions commands are no longer functional in WSL workspaces

[https://github.com/microsoft/vscode/issues/280190](https://github.com/microsoft/vscode/issues/280190)

## Summary

The WSL-specific regression remains actionable: the reporter supplied a detailed comparison with local workspaces, another report independently observed disablement failure on the same VS Code release and WSL, and no fixing commit or valid canonical issue was found.

## Change summary

Copilot's enable, disable, and toggle completion commands do not update the effective completion setting or status in a Windows-hosted WSL workspace.

## Best solution

Make the command-palette completion controls resolve and update `github.copilot.enable` for the active remote document just as reliably as the status-bar control, with coverage for a WSL multi-root workspace and its configuration scopes.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/completions-core/vscode-node/completionsServiceBridges.ts`, `extensions/copilot/src/extension/completions-core/vscode-node/extension/src/config.ts`, `extensions/copilot/src/extension/completions-core/vscode-node/extension/src/statusBarPicker.ts`
- **Validation:** In a Windows-hosted WSL multi-root workspace, invoke each enable, disable, and toggle command with an active remote editor and verify that the effective `github.copilot.enable` value, status-bar state, and completion behavior all change immediately; repeat in a local workspace to confirm existing behavior is preserved.
- **Behavior:**

  > In a WSL workspace, GitHub Copilot's Enable Inline Suggestions, Disable Inline Suggestions, and Toggle Inline Suggestions commands must change the effective completion state immediately. The status bar must reflect the new state, and automatic completions must start or stop accordingly. The same checks must continue to pass in local and multi-root workspaces, including when the setting is defined at user, workspace, or workspace-folder scope.
- **Trace:**

  > Command-palette handlers are registered in extensions/copilot/src/extension/completions-core/vscode-node/completionsServiceBridges.ts and dispatch to the functions in extension/src/config.ts. The latter scopes `editor.inlineSuggest.enabled` to the active document but obtains and updates `github.copilot.enable` without that document scope; determine whether this selects the wrong effective value or configuration target in WSL/multi-root workspaces. Also verify which extension host owns each Chat/client command ID, because the status-bar path was reported to work while command-palette paths did not. Preserve snooze behavior and ordinary local-workspace completion semantics. https://github.com/microsoft/vscode/issues/281914 corroborates WSL disablement failure on the same release but is a younger, closed report rather than a canonical issue.

## Evidence

- **detailed reproduction:** https://github.com/microsoft/vscode/issues/280190 documents that all three completion commands fail in VS Code 1.106.3 in a WSL workspace while the same commands work in a local workspace; the reporter also checked settings, logs, restarts, and WSL restarts.
- **independent corroboration:** https://github.com/microsoft/vscode/issues/281914 independently reports that completion disablement did not take effect in VS Code 1.106.3 with WSL. It is younger than this re-reviewed issue and closed, so it cannot serve as the canonical duplicate.
- **maintainer response:** https://github.com/microsoft/vscode/issues/280190#issuecomment-3633206387 says the maintainer would investigate and identifies the status-bar item as a working interim path, supporting a distinction between that path and the failing commands.
- **current command path:** extensions/copilot/src/extension/completions-core/vscode-node/completionsServiceBridges.ts registers both Chat and client enable/disable/toggle command IDs and dispatches them to enableCompletions, disableCompletions, and toggleCompletions.
- **configuration-scope lead:** extensions/copilot/src/extension/completions-core/vscode-node/extension/src/config.ts scopes `editor.inlineSuggest.enabled` lookups to the active document, but reads and updates `github.copilot.enable` through an unscoped WorkspaceConfiguration and target-selection helper. Remote and multi-root scope resolution therefore remains a concrete diagnostic lead, although the checkout was not executed under WSL.
