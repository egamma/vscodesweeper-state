# Issue #322646 — Could we add collapsable sections to Chat prompts and a search option

[https://github.com/microsoft/vscode/issues/322646](https://github.com/microsoft/vscode/issues/322646)

## Summary

Search within the current transcript has since shipped, but collapsing complete prompt/response turns remains a real chat-navigation gap. Route this to the chat area for a product decision rather than closing the broader request as completed.

## Change summary

Let users search a long chat and collapse individual or all prompt-and-response turns for easier navigation.

## Best solution

Retain the shipped Find in Chat command and design a turn-level disclosure that can collapse a user request together with its response, including an efficient collapse-all/expand-all affordance. The design should preserve transcript search and reveal a collapsed turn when navigating to a match.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatFind/chatFindWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatFindWidget.test.ts`
- **Validation:** Add chat widget tests covering collapse and expansion of a complete turn, collapse-all/expand-all behavior across multiple turns, and Find in Chat revealing a match inside a collapsed turn.
- **Behavior:**

  > Users can collapse a long conversation into compact, identifiable turns and expand any turn to inspect its complete response. A global affordance can collapse or expand all eligible turns. Find in Chat continues to search collapsed content and reveals the matched turn when navigating to it. Active or streaming turns must remain readable and existing intermediate-work disclosures must continue to behave consistently.
- **Trace:**

  > Current transcript search is implemented by ChatFindWidget in src/vs/workbench/contrib/chat/browser/widget/chatFind/chatFindWidget.ts and registered as `workbench.action.chat.find`; it searches logical chat items and opens closed disclosure ancestors for matches. ChatListRenderer in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts currently creates `<details>` only around intermediate work in a completed response, leaving the final response and user request visible as separate list items. ChatListWidget owns the virtualized transcript rows, so grouping or collapsing complete turns must preserve row measurement, focus, reveal, and search behavior. The boundary is transcript presentation: do not change stored conversation data, response generation, or the existing semantics of intermediate tool/thinking disclosures. Related navigation work is described in https://github.com/microsoft/vscode/issues/324984, but that newer issue is not a valid duplicate canonical for this re-reviewed item.
- **Open decisions:**
  - Should the collapsible unit always be the complete user-request/response turn, or should users be able to collapse the request and response independently?
  - Should collapsed state persist when a saved chat is reopened, or remain transient presentation state?
  - Should collapse-all include the current or streaming turn, or only completed turns?

## Evidence

- **search implemented:** Find within the current chat transcript shipped in VS Code 1.134.0 through https://github.com/microsoft/vscode/commit/f5929d2a1e34b2dc062e80f9b14958d915928a44; `workbench.action.chat.find` is registered in src/vs/workbench/contrib/chat/browser/actions/chatFindActions.ts and uses Ctrl/Cmd+F.
- **remaining gap:** src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts only creates a completed-response disclosure for intermediate response work before the final answer. It does not collapse the complete user-request/response turn requested here.
- **related demand:** https://github.com/microsoft/vscode/issues/324984 independently requests collapsible conversation turns and turn navigation, but it was created after this re-reviewed issue and therefore cannot serve as its duplicate canonical.
- **search compatibility:** src/vs/workbench/contrib/chat/browser/widget/chatFind/chatFindWidget.ts already searches the logical transcript and opens closed `<details>` ancestors when revealing a match, establishing the expected integration point for future turn disclosures.
