## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts`, `src/vs/platform/agentHost/electron-browser/sshRemoteAgentHostServiceImpl.ts`, `src/vs/platform/agentHost/test/node/sshHostKeyVerification.test.ts`
- **Validation:** With an ssh-agent-authenticated configured host and matching known_hosts entry, fully quit and relaunch VS Code with startup auto-reconnect enabled. Confirm verification completes; separately close the server connection while verification is pending, confirm no uncaught exception, and reconnect successfully without restarting VS Code.
- **Behavior:**

  > A configured SSH remote agent host should reconnect after application startup under the same trust policy that permits a later connection. If the server closes while verification is pending, the attempt must terminate cleanly and subsequent reconnects must remain usable without restarting the application. Acceptance includes startup success, clean failure settlement, and successful retry. Unknown or mismatched host keys must retain their existing policy behavior.
- **Trace:**

  > SSHRemoteAgentHostMainService._verifyHostKey gathers known_hosts evidence but always delegates the decision through a pending renderer request. SSHRemoteAgentHostService registers its connection factory before its verification-event subscription; whether the initial connection can outrun IPC subscription readiness is unresolved. cancelLiveHostKeyRequests invokes the saved ssh2 verifier during rejectConnect, including the close-event path, matching the vicinity of the reported exception. Existing host-key tests cover cancellation but do not confirm the actual ssh2 protocol teardown behavior. Diagnose both event delivery and promise settlement before treating either as the root cause; preserve trust decisions, credential-verification ordering, and unrelated authentication behavior.
