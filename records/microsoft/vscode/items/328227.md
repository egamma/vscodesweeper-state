# Issue #328227 — [Error] [GitHub.copilot-chat] unhandlederror-database is locked

[https://github.com/microsoft/vscode/issues/328227](https://github.com/microsoft/vscode/issues/328227)

## Summary

Confirmed on current main: ExternalIngestIndex opens SQLite connections without any busy_timeout PRAGMA, so any transient cross-window/cross-connection lock on the shared per-workspace codebase-external.sqlite immediately throws 'database is locked' instead of waiting — matching the 14x regression spike and the analysis already written up in the linked issue.

## Change summary

The Copilot chat extension's workspace external ingest index throws an unhandled SQLITE_BUSY 'database is locked' error from file-watcher handlers when another window/connection briefly holds a write lock on the shared per-workspace SQLite file.

## Best solution

Add a `PRAGMA busy_timeout` (e.g. 5000ms) to every connection ExternalIngestIndex opens — both the existing-database branch of `openOrCreateDatabase` (which currently applies no PRAGMAs at all) and `createFreshDatabase` — so SQLite blocks briefly and retries instead of failing fast on transient cross-window contention.
