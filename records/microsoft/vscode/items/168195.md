# Issue #168195 — Remote SSH incorrectly strips empty but defined environment variables from shell environment

[https://github.com/microsoft/vscode/issues/168195](https://github.com/microsoft/vscode/issues/168195)

## Summary

Confirmed open bug — empty-but-defined environment variables are stripped when spawning integrated terminal processes. Team members (roblourens, Tyriar) acknowledged the issue in comments 9–10 and added the `help wanted` label, but no fix has been committed. The code paths on current main (`mergeNonNullKeys`, `deepClone`, `_parseEnv`) appear to handle empty strings correctly at each individual step, so the root cause may be in how the remote resolver environment or pty host process inheritance interacts with `null` vs `""` semantics — further debugging with a live SSH setup is needed.

## Change summary

Environment variables defined with empty values (e.g. `export TESTVAR3` or `export TESTVAR3=""`) are silently dropped from the integrated terminal's environment when connecting via Remote SSH.

## Best solution

Identify the exact point where empty-string env vars are lost — likely candidates are (1) the `resolverEnv` passed from the SSH extension containing `null` for empty vars, which then overwrites the real value via `...startParamsEnv` in `buildUserEnvironment` (`src/vs/server/node/extensionHostConnection.ts`), or (2) the pty host fork chain (`src/vs/base/parts/ipc/node/ipc.cp.ts` line 180). A targeted fix with a test asserting that `TESTVAR=""` survives the full `createTerminalEnvironment` pipeline would resolve this. The `help wanted` label is appropriate — this is a good community contribution candidate.
