# Issue #333607 — Agent Window: Add 'attach to chat' on session context menu

[https://github.com/microsoft/vscode/issues/333607](https://github.com/microsoft/vscode/issues/333607)

## Summary

A real gap remains: current main supports specialized `#session` references for `/troubleshoot`, but the session context menu cannot attach a previous session to the active chat for general use. The Backlog milestone reflects accepted work, and no older issue with the same observable request was found.

## Change summary

Add an Attach to Chat action to session-row context menus so a previous session can be referenced from the current conversation.

## Best solution

Provide a session-row action that adds the selected session as a visible, removable context attachment in the active chat composer without opening or sending it. Define a provider-neutral contract for what session content reaches the model rather than limiting the feature to Copilot CLI troubleshooting logs.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts`, `src/vs/sessions/services/sessions/browser/sessionReference.ts`, `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts`, `src/vs/sessions/browser/parts/sessionView.ts`, `src/vs/sessions/contrib/chat/browser/sessionReferenceCompletions.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsActions.test.ts`, `src/vs/sessions/services/sessions/test/browser/sessionsManagementService.test.ts`
- **Validation:** Add focused tests asserting that the session context menu contributes Attach to Chat, invokes the active composer's attachment path without sending, and that the selected session reference reaches an ordinary request according to the chosen content contract; run the affected Sessions unit tests with `scripts/test.sh --grep "session reference|Attach to Chat"`.
- **Behavior:**

  > A user can open a previous session's context menu and attach that session to the currently active chat. The active composer shows a visible, removable attachment, keeps existing input intact, and does not send a request or navigate away. On the next send, the agent receives the prior-session context defined by the chosen contract. The action must remain keyboard-accessible through the existing context menu.
- **Trace:**

  > Session-row actions are registered in `src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts`. A session-reference attachment format already exists in `src/vs/sessions/services/sessions/browser/sessionReference.ts` and is produced by `SessionReferenceCompletionHandler`, but that completion only lists Copilot CLI sessions and `SessionsManagementService._augmentOptionsForTroubleshoot` removes references from ordinary requests. The Sessions view attachment bridge currently accepts only resource URIs, so the trace reaches an unresolved cross-component contract for adding generic context entries to the active composer. Preserve current file-attachment behavior and do not automatically open the selected session, switch focus, or submit the chat. https://github.com/microsoft/vscode/issues/335015 is related parity discussion but is newer and broader, not a duplicate canonical.
- **Open decisions:**
  - What model-visible representation should a generally attached session provide: full transcript, bounded summary, selected chats or turns, or another redacted and size-limited form?
  - Should Attach to Chat support every provider-neutral `ISession`, or initially appear only for providers that can supply a defined session-context representation?

## Evidence

- **current source gap:** src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts registers the session-row context-menu actions, including Pin, Rename, Archive, New Chat, and Open to the Side, but has no action that attaches the selected session to another chat.
- **partial existing capability:** src/vs/sessions/contrib/chat/browser/sessionReferenceCompletions.ts already creates visible `#session` attachment entries, but only for Copilot CLI sessions. src/vs/sessions/services/sessions/browser/sessionsManagementService.ts `_augmentOptionsForTroubleshoot` consumes those references for `/troubleshoot` and strips them from ordinary requests, so this does not satisfy general cross-session context.
- **missing attachment bridge:** src/vs/sessions/browser/parts/sessionView.ts exposes `attach(uris: URI[])`, and the concrete chat views use it for file resources; there is no provider-neutral Sessions-list API for inserting a generic session-reference entry into the active composer.
- **canonical search:** https://github.com/microsoft/vscode/issues/335015 is a newer, broad Agents Window parity request and does not report this same context-menu workflow. Under the stronger re-review duplicate bar it cannot serve as the canonical for this older, specific request.
