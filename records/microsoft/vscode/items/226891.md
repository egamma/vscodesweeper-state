# Issue #226891 — `onDidChangeTerminalShellIntegration` fired twice on terminal creation without `reason` property

[https://github.com/microsoft/vscode/issues/226891](https://github.com/microsoft/vscode/issues/226891)

## Summary

Still reproduces on main: `$shellIntegrationChange` fires `_onDidChangeTerminalShellIntegration` unconditionally on line 101 of `extHostTerminalShellIntegration.ts` every time it's called, and the `TerminalShellIntegrationChangeEvent` interface has no `reason` property. The double-fire and the missing discriminator are both unaddressed.

## Change summary

`onDidChangeTerminalShellIntegration` fires twice on terminal creation with no way to distinguish why each fire occurred.

## Best solution

Either deduplicate the fire (skip if no property actually changed) or add a `reason` property to `TerminalShellIntegrationChangeEvent` so consumers can distinguish initial activation from property updates. The fix touches `src/vs/workbench/api/common/extHostTerminalShellIntegration.ts` and the API surface in `src/vscode-dts/vscode.d.ts`.
