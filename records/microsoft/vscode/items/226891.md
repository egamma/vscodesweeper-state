# Issue #226891 — `onDidChangeTerminalShellIntegration` fired twice on terminal creation without `reason` property

[https://github.com/microsoft/vscode/issues/226891](https://github.com/microsoft/vscode/issues/226891)

## Summary

Keep open for an API-owner decision on distinguishing shell-integration activation from property updates. Current source still permits successive startup notifications without a reason field; these notifications follow the documented contract, so the remaining work is an API improvement rather than a proven duplicate-event defect.

## Change summary

Make successive terminal shell-integration notifications understandable to extensions, potentially by exposing which change triggered each event.

## Best solution

Establish an explicit activation-versus-property-change contract for TerminalShellIntegrationChangeEvent, preserving notifications for genuine cwd and environment changes. API owners should decide whether to expose change metadata or alter initial notification semantics before implementation.
