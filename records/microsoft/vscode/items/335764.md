# Issue #335764 — Agents window `Create PR` button has to be tied to specific session

[https://github.com/microsoft/vscode/issues/335764](https://github.com/microsoft/vscode/issues/335764)

## Summary

Keep open for product design: current main intentionally derives changes and Create PR operations from the active session, leaving no project-level action when no session is selected. The related umbrella is newer and explicitly preserves this narrower report, so it is not a valid duplicate canonical under the re-review rules.

## Change summary

Allow users to create a pull request from existing project changes in the Agents window without first starting or selecting a session.

## Best solution

Provide a project-scoped Create PR entry point when the mounted repository has eligible changes, while making its repository and session-association semantics explicit and preserving the existing session-scoped flow.

  > When the Agents window is showing a project with eligible Git changes but no specific session is active, users can start Create PR without first creating a session. Existing session-scoped Create PR behavior, including its originating-chat flow, remains unchanged.
- **Trace:**

  > ChangesViewService in src/vs/sessions/contrib/changes/browser/changesViewService.ts obtains changesets, repository state, and operations solely from ISessionsService.activeSession; with no active session, activeSessionChangesetsObs and activeSessionChangesetObs have no project-level source. ChangesWorkbenchButtonBarWidget in src/vs/sessions/contrib/changes/browser/changesView.ts consequently has no changeset operation to render, and its Create PR invocation captures the active session and chat. Preserve session-specific PR attribution and chat behavior; the uncertainty begins at defining ownership for a PR initiated outside any session.
- **Open decisions:**
