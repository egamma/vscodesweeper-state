# Issue #168476 — Add please colors to the outline panel.

[https://github.com/microsoft/vscode/issues/168476](https://github.com/microsoft/vscode/issues/168476)

## Summary

Keep this accepted, community-supported request open: Outline supports colored symbol icons and diagnostic labels, but neither provides the requested coloring of symbol names, arguments, and return types. No verified older canonical or linked implementation was found.

## Change summary

Support colorized symbol names and differentiated argument and return-type text in the Outline view.

## Best solution

Design theme-consistent Outline text coloring, with an explicit decision on whether it distinguishes symbol kinds or reflects language syntax. Preserve diagnostic and selection contrast, and establish how argument and return-type segments can be identified without assuming a language-specific signature format.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.css`, `src/vs/workbench/contrib/outline/browser/outline.contribution.ts`, `src/vs/editor/common/languages.ts`
- **Validation:** After agreeing on the coloring contract, verify Outline entries containing a function name, parameters, and a return type in light, dark, and high-contrast themes. Check the agreed text distinctions, selected-row contrast, diagnostic-color precedence, fuzzy-search highlighting, and unchanged navigation; include renderer-level coverage for the chosen behavior.
- **Behavior:**

  > The request is to distinguish Outline symbol names by color and optionally distinguish arguments and return types within displayed signatures. Existing colored icons and error/warning coloring do not satisfy that goal. Acceptance should demonstrate the agreed distinctions on representative function signatures while preserving selection readability, diagnostic visibility, filtering, and navigation.
- **Trace:**

  > DocumentSymbolRenderer.renderElement in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts renders symbol.name and symbol.detail as IconLabel text; its current highlights represent fuzzy matches rather than syntax tokens. _renderMarkerInfo and documentSymbolsTree.css provide diagnostic label coloring and focused-selection overrides, which must remain effective. outline.contribution.ts exposes icon and diagnostic-color settings but no equivalent text-coloring capability. DocumentSymbol in src/vs/editor/common/languages.ts supplies unstructured name/detail strings rather than parameter and return-type segments, so the trace establishes the missing surface but not a language-independent tokenization contract. https://github.com/microsoft/vscode/issues/168476 has established community demand; the uncertainty is the intended coloring semantics and signature coverage, not whether colored icons already satisfy it.
- **Open decisions:**
  - Should symbol-name colors follow symbol kinds, the editor's syntax or semantic colors, or another shared theme contract?
  - Should the initial capability include independently colored arguments and return types, and what should users see when a provider supplies only an unstructured detail string?
  - Should text coloring be the default Outline presentation or an opt-in mode?
