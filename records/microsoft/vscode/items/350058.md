# Issue #350058 — Copilot SDK sessions: read existing integrated-terminal output without Computer Use

[https://github.com/microsoft/vscode/issues/350058](https://github.com/microsoft/vscode/issues/350058)

## Summary

Keep this request open and route it to the terminal area. Existing selection sharing provides a partial workaround, but does not establish equivalent SDK access to user-selected terminals, last-command output, and retained scrollback independently of command execution.

## Change summary

Provide user-controlled, read-only access to manually opened integrated-terminal output in Copilot SDK sessions without requiring Computer Use or execution permissions.

## Best solution

Provide narrowly scoped terminal-context sharing for SDK sessions, reusing existing terminal selection and command-output capabilities where appropriate. Keep permission to read the selected output independent of permission to execute commands or send terminal input.

## Evidence

- **Existing capabilities and remaining scope:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/getTerminalSelectionTool.ts and getTerminalLastCommandTool.ts implement terminalSelection and terminalLastCommand against the active integrated terminal. Their existence establishes reusable Local capabilities, not equivalent availability in the reported SDK session.
- **Partial user-controlled workaround:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/terminal.chatAgentTools.contribution.ts registers Add Terminal Selection to Chat, which attaches selected text as generic chat context without executing a command. This does not provide terminal discovery, last-command retrieval, or retained-scrollback access.
- **Related closed issue:** https://github.com/microsoft/vscode/issues/341462 is closed and concerns visible agent terminals and interactive SSH/sudo authentication. The reporter explicitly distinguishes this request for read-only access to existing user terminals; that closure is not evidence that this capability shipped.
- **Canonical search:** Read the open https://github.com/microsoft/vscode/issues/346123 and https://github.com/microsoft/vscode/issues/349269. The former requests developer-controlled execution and execution records; the latter exposes agent-created background shells to users. Neither clearly owns independent read-only access by SDK agents to manually opened terminals.
- **Separate output-artifact request:** https://github.com/microsoft/vscode/issues/333709 is open but concerns automatic read_file authorization for output artifacts produced by agent commands, not reading existing user-terminal buffers.
