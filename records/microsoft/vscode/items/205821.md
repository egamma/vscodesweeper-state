# Issue #205821 — Option to auto-expand groups in variables panel while debugging

[https://github.com/microsoft/vscode/issues/205821](https://github.com/microsoft/vscode/issues/205821)

## Summary

Keep open: current source still automatically expands only the first non-expensive scope, leaving the requested multi-scope expansion capability missing. Maintainers acknowledged the problem, and neither related issue provides an applicable open duplicate target.

## Change summary

Provide a way to expand relevant debugging scope groups without opening each Block group individually.

## Best solution

Provide predictable scope-level expansion in the Variables view while preserving explicit user expansion choices and avoiding automatic retrieval of expensive scopes. Settle whether this is an opt-in automatic policy or an explicit expand-scopes action before implementation.

- **Behavior:**

  > When debugging code with several nearby Block scopes, users should be able to expose their variables without individually guessing and opening each group. The finished behavior should make the relevant scope contents readily accessible while keeping expensive scopes protected from unintended retrieval. Acceptance should cover multiple Block scopes, explicit user collapse choices, stepping, and switching away from and back to a stack frame. Resolving lazy variable values is a separate capability.
- **Trace:**

  > VariablesView in src/vs/workbench/contrib/debug/browser/variablesView.ts saves tree view state by stackFrame.getId(), restores it through tree.setInput(), then expands only scopes.find(s => !s.expensive). Preserve explicit user expansion choices and avoid broad changes to debug-adapter scope identity or variable evaluation; uncertainty starts at the user-visible expansion policy.
