# Issue #329245 — Make /vscode-pet a Tamagotchi for AI agents 🐣

[https://github.com/microsoft/vscode/issues/329245](https://github.com/microsoft/vscode/issues/329245)

## Summary

A real feature gap remains: the pet already reacts to chat activity and supports persistent achievements, but it has no needs, progression, token-linked state, or feed/play/status interactions. No older issue with the same request was found, so this should remain open for product design rather than be closed as a duplicate.

## Change summary

Turn the optional VS Code chat pet into a persistent Tamagotchi-like companion whose needs, activity, experience, and evolution reflect AI-agent usage.

## Best solution

Extend the existing optional pet with a lightweight progression model driven by meaningful agent activity, without consuming extra tokens or incentivizing waste. Maintainers should first decide whether metered token counts are an appropriate input and define persistence, reset, and interaction semantics.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatPetService.ts`, `src/vs/workbench/contrib/chat/browser/chatSlashCommands.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts`, `src/vs/workbench/contrib/chat/browser/chatPetAchievements.ts`, `src/vs/sessions/contrib/chat/browser/chatPetAchievements.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatPetWidget.test.ts`, `src/vs/sessions/contrib/chat/test/browser/chatPetAchievements.test.ts`
- **Validation:** Extend the ChatPetWidget and sessions achievement unit suites with deterministic tests covering activity-to-state transitions, persisted progression across service recreation, explicit interactions, and confirmation that idle activity does not advance progression; run the targeted ChatPetWidget and SessionsChatPetAchievementContribution tests.
- **Behavior:**

  > When the optional VS Code pet is enabled, meaningful AI-agent activity can affect a clearly visible, persistent progression state without initiating requests or consuming additional tokens. Active agents should wake or energize the pet, sustained inactivity should let it sleep, and explicit interactions should report or affect its state according to documented rules. Progress must survive reloads when intended, be resettable, and remain inert while the pet is disabled. Acceptance should cover deterministic state transitions, persistence, reset behavior, and the absence of progression from idle time alone.
- **Trace:**

  > The current animation path is in src/vs/workbench/contrib/chat/browser/widget/chatPetWidget.ts: ChatPetWidget observes IChatModel.hasActiveRequest and getChatPetBaseState maps active, input, and idle conditions to rendering, typing, and sleep. Persistent pet data and cross-window synchronization live in ChatPetService in src/vs/workbench/contrib/chat/browser/chatPetService.ts. Agent-related rewards already enter through ChatPetAchievementIds and SessionsChatPetAchievementContribution, but they are one-time achievements rather than a continuous needs or experience model. `/vscode-pet` is registered in src/vs/workbench/contrib/chat/browser/chatSlashCommands.ts as a toggle only. Preserve the existing opt-in behavior, reduced-motion handling, accessibility announcements, achievement compatibility, and the requirement that pet mechanics never generate AI requests merely to alter state.
- **Open decisions:**
  - Should progression use actual metered token consumption, bounded qualitative agent events, or both, given the different privacy, availability, and engagement implications?
  - Which needs and progression state persist across reloads or devices, and what user-visible reset behavior is required?
  - Should feed/play/status be explicit slash-command interactions, passive pet behavior, or both, and may any interaction affect progression without corresponding agent activity?
  - What guardrail ensures the experience reflects existing usage without rewarding unnecessary token consumption?

## Evidence
