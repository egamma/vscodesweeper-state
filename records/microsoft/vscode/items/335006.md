# Issue #335006 — `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` never expanded for Agent Plugins 1.0 (canonical schema) plugins — pluginRootTokens empty for format 3

[https://github.com/microsoft/vscode/issues/335006](https://github.com/microsoft/vscode/issues/335006)

## Summary

Confirmed on main: the Agent Plugins v1 (canonical schema) format entry in pluginParsers.ts has empty `pluginRootTokens`/`pluginRootEnvVars`, so the shared `interpolateMcpPluginRoot` expansion never substitutes `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` or injects them into the subprocess env for this format, while the legacy Copilot/Claude/OpenPlugin formats do get expansion.

## Change summary

For plugins using the canonical Agent Plugins 1.0 `$schema`, `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` placeholders in mcp.json are left unexpanded and never injected into the MCP server's environment.

## Best solution

Give the `AGENT_PLUGIN_FORMAT` config in src/vs/platform/agentPlugins/common/pluginParsers.ts its own field-scoped expansion (args/env/cwd only, never `command`/HTTP `url`/`headers`) and define how `PLUGIN_DATA` resolves to a persistent per-plugin directory — this needs a product/design decision (where that directory lives, lifecycle) before it's a safe change, so it belongs with the chat/agent-plugins owners rather than an automatic fix.
