# Issue #335006 — `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` never expanded for Agent Plugins 1.0 (canonical schema) plugins — pluginRootTokens empty for format 3

[https://github.com/microsoft/vscode/issues/335006](https://github.com/microsoft/vscode/issues/335006)

## Summary

Traced and confirmed on current main: `AGENT_PLUGIN_FORMAT` in pluginParsers.ts sets `pluginRootTokens`/`pluginRootEnvVars` to empty arrays, so `interpolateMcpPluginRoot` is a no-op for canonical Agent Plugins 1.0 plugins and `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` are never substituted or injected into the subprocess environment — matching the reporter's own root-cause analysis exactly.

## Change summary

For plugins using the canonical Agent Plugins 1.0 schema, `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` placeholders in mcp.json args/env/cwd are never expanded and the corresponding env vars are never injected into the MCP server subprocess.

## Best solution

Give `AGENT_PLUGIN_FORMAT` its own format-aware expansion path in pluginParsers.ts that substitutes `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` only in stdio `args`, `env` values, and `cwd` (never `command`, remote `url`, or `headers`), and injects `PLUGIN_ROOT`/`PLUGIN_DATA` into the subprocess env — while also deciding how a real per-plugin `PLUGIN_DATA` directory is allocated, since no such persistent-data-directory concept exists in the codebase yet.

## Evidence

- **empty token table:** src/vs/platform/agentPlugins/common/pluginParsers.ts:216-217 — `AGENT_PLUGIN_FORMAT.pluginRootTokens`/`pluginRootEnvVars` are `[]`, unlike COPILOT_FORMAT/CLAUDE_FORMAT/OPEN_PLUGIN_FORMAT which populate `${PLUGIN_ROOT}`/`${CLAUDE_PLUGIN_ROOT}`.
- **no-op expansion:** interpolateMcpPluginRoot (pluginParsers.ts:568-600) reduces over `tokens`/`envVars`; with both empty for AgentPlugin format, `replace()` and the env-injection loop never run, so `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` pass through literally and are never injected as env vars.
- **existing test documents current (buggy) behavior:** src/vs/platform/agentPlugins/test/common/pluginParsers.test.ts:728 'reads known MCP fields and leaves harness placeholders unresolved' asserts args/env containing `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` come back unexpanded for the Agent Plugin format — this would need updating alongside a fix.
- **internal architecture doc corroborates the gap:** src/vs/workbench/contrib/chat/common/plugins/AGENTS_PLUGINS.md:99 lists '${CLAUDE_PLUGIN_ROOT} token replacement' and '${PLUGIN_ROOT} token replacement' as special handling for Claude/Open Plugin formats but nothing equivalent for Agent Plugins v1.
- **export path expects these tokens to be meaningful:** src/vs/workbench/contrib/chat/browser/actions/createPluginAction.ts:570 and :624 treat `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` as valid, portable cwd/env tokens when exporting a plugin to the Agent Plugins format, which is inconsistent with the read path never expanding or injecting them.
