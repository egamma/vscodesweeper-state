# Issue #335006 — `${PLUGIN_ROOT}` / `${PLUGIN_DATA}` never expanded for Agent Plugins 1.0 (canonical schema) plugins — pluginRootTokens empty for format 3

[https://github.com/microsoft/vscode/issues/335006](https://github.com/microsoft/vscode/issues/335006)

## Summary

Confirmed on current main: the canonical Agent Plugins 1.0 format config (`AGENT_PLUGIN_FORMAT`) ships with empty `pluginRootTokens`/`pluginRootEnvVars`, so `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` are never substituted in that format's `mcp.json`, contradicting the shipped VS Code docs the reporter cites; `PLUGIN_DATA` also has no real implementation anywhere (it's conflated with the plugin root path, not a distinct persistent directory).

## Change summary

For plugins using the canonical Agent Plugins 1.0 `$schema`, `${PLUGIN_ROOT}`/`${PLUGIN_DATA}` placeholders in `mcp.json` are left literal instead of being expanded/injected as the spec and VS Code docs describe.

## Best solution

Give `AGENT_PLUGIN_FORMAT` its own format-aware MCP interpolation path (restricted to stdio `args`, `env` values, and `cwd`, never `command`/`url`/`headers`), and introduce an actual `PLUGIN_DATA` concept (a distinct, client-managed persistent directory per plugin) rather than reusing the plugin-root path — today `interpolateMcpPluginRoot` in src/vs/platform/agentPlugins/common/pluginParsers.ts only knows a single substitution value for every token/env var.
