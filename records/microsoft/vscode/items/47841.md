# Issue #47841 — Windows update failed: Access is denied

[https://github.com/microsoft/vscode/issues/47841](https://github.com/microsoft/vscode/issues/47841)

## Summary

Keep open: multiple users confirmed Windows update failures involving locked files, and the maintainer explicitly retained this issue after a mitigation that did not eliminate the failure. Current source still uses the background updater; neither a complete fix nor an eligible older duplicate was established.

## Change summary

Windows updates fail with access-denied errors when the updater cannot replace locked installation files after Code exits.

## Best solution

Identify which process or permission condition prevents replacement on an affected Windows machine, then make the update complete reliably without leaving an unusable installation. Distinguish the original Code.exe locking failure from newer installer-extraction and terminal-cleanup failures before consolidating reports.

- **Behavior:**

  > Users report Windows updates failing with access denied after the updater determines Code.exe is no longer running. Expected behavior is that an update completes and VS Code relaunches; a blocked replacement must not leave the installation unusable. Re-establish the failure on current Windows builds and verify the identified scenario with both background and foreground update paths.
- **Trace:**

  > Win32UpdateService in src/vs/platform/update/electron-main/updateService.win32.ts selects background application for user installations when update.enableWindowsBackgroundUpdates is enabled; doApplyUpdate launches Inno Setup, while doQuitAndInstall releases the pending update or launches the foreground installer. build/win32/code.iss invokes inno_updater.exe for background application and old-version cleanup. The maintainer's mitigation in https://github.com/microsoft/vscode/issues/47841#issuecomment-417442074 intentionally preserved this issue because avoiding broken installations did not resolve every update failure.
