# Issue #47841 — Windows update failed: Access is denied

[https://github.com/microsoft/vscode/issues/47841](https://github.com/microsoft/vscode/issues/47841)

## Summary

Long-standing issue where corporate security software (ESET, CrowdStrike, McAfee) blocks file deletion during Windows background updates. The inno_updater has been improved many times since 2018, but the environmental root cause (security suites holding file handles) may still affect managed machines. Keeping open as the issue remains valid for enterprise environments.

## Change summary

VS Code's Windows background updater fails with 'Access is denied' (os error 5) when trying to delete Code.exe during update, typically on enterprise-managed machines with security software.

## Best solution

The updater could detect the access-denied condition more gracefully and fall back to prompting the user to run the update manually (or offer the traditional update flow). The workaround `update.enableWindowsBackgroundUpdates: false` exists but isn't discoverable. A better UX when the background update fails on managed machines would close this gap — likely in the inno_updater retry/fallback logic and in the notification shown to users.
