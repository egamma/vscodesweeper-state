## Summary

Traced the MCP OAuth resource-metadata discovery path in the checkout: `fetchResourceMetadata` in src/vs/base/common/oauth.ts already tries the full-path well-known URL (`origin + /.well-known/oauth-protected-resource + pathname`) before falling back to the bare root, exactly what the report asks for. ## Change summary

MCP OAuth protected-resource metadata discovery should use the full server URL (including subpath), not just scheme+host, when deriving the well-known discovery URL.

## Best solution

Keep the current implementation in src/vs/base/common/oauth.ts (`fetchResourceMetadata`, lines ~1250-1280): it already tries an explicit challenge URL, then a path-appended well-known URL, then falls back to root discovery only as a last resort, matching the expected RFC 9728-style behavior. No further change needed; ask the reporter to confirm on a current build (1.132.0+) since they tested on 1.106.0.
