# Issue #192943 — Terminal profile settings not reflected in terminals created using VSCode API

[https://github.com/microsoft/vscode/issues/192943](https://github.com/microsoft/vscode/issues/192943)

## Summary

Valid feature request, still unimplemented on main. When extensions call `createTerminal()` without specifying `shellPath`/`shellArgs`, the default terminal profile's properties (env vars, args, etc.) should be merged in. The `$createTerminal` path in `mainThreadTerminalService.ts` still builds the shell launch config directly from extension-provided values without consulting `ITerminalProfileResolverService`.

## Change summary

Terminals created via `vscode.window.createTerminal()` without explicit `shellPath`/`shellArgs` should inherit the default terminal profile's settings (env, args, etc.).

## Best solution

In `mainThreadTerminalService.ts#$createTerminal`, when `shellPath` and `shellArgs` are both undefined, call into `ITerminalProfileResolverService` to resolve the default profile and merge its properties (env, args, path) into the `shellLaunchConfig` before creating the terminal instance. Care is needed to avoid breaking extensions that rely on the current behavior when they do set `shellPath`.
