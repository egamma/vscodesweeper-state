# Issue #156281 — Throwing exceptions across extension host RPC boundaries doesn't preserve Error.name

[https://github.com/microsoft/vscode/issues/156281](https://github.com/microsoft/vscode/issues/156281)

## Summary

The RPC code correctly serializes and deserializes Error.name (line 431 of rpcProtocol.ts). The reported problem was that the reporter's custom Error subclass never set .name — a JavaScript behavior, not a VS Code bug. alexdima confirmed this is working as intended.

## Change summary

Custom Error subclass name not preserved across extension host RPC, but the root cause is the subclass not setting .name (a JS behavior, not a VS Code defect).

## Best solution

Close as designed — the RPC layer faithfully serializes whatever .name is set on the Error. The remaining suggestion (documentation about how errors are transported) is a nice-to-have but has had no traction in 4 years; a docs PR from the community would still be welcome.

  > Thanks for the report. As alexdima explained in the thread, the RPC layer correctly serializes and deserializes whatever `.name` is set on the Error object (see `rpcProtocol.ts` line 431). The issue is that subclassing `Error` in JavaScript does not automatically set `.name` to the subclass name — you need to do that manually in the constructor:
  > 
  > ```ts
  > export class LoginTimeOutError extends Error {
  >     constructor(message?: string) {
  >         super(message);
  >         this.name = 'LoginTimeOutError';
  >     }
  > }
  > ```
  > 
  > Since this is working as designed and the discussion concluded 4 years ago, I'm closing this. PRs to improve documentation around error transport across processes are always welcome.
