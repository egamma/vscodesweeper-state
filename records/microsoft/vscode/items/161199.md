# Issue #161199 — HTML intellisense not filtering on partial text but CSS is

[https://github.com/microsoft/vscode/issues/161199](https://github.com/microsoft/vscode/issues/161199)

## Summary

Still reproduces on main: the @vscode/emmet-helper library uses strict prefix matching (`startsWith`) for HTML snippet suggestions, so typing `inpb` never matches `input:b` or `input:btn`. CSS works differently because it has built-in fuzzy property name matching. The bug lives in the emmet-helper dependency.

## Change summary

Typing a partial abbreviation like `inpb` in an HTML file should offer Emmet completions like `input:b`, `input:btn`, `input:button` but instead shows nothing.

## Best solution

Fix `makeSnippetSuggestion` in `@vscode/emmet-helper` to support fuzzy/substring matching for markup snippet keys (e.g. matching `inpb` against `input:b`), or adopt a colon-aware prefix strategy that treats the part before `:` as the tag prefix. The fix belongs in the `@vscode/emmet-helper` npm package (`microsoft/vscode-emmet-helper` repo), then bump the dependency in `extensions/emmet/package.json`.

## Evidence

- **source trace:** In `extensions/emmet/node_modules/@vscode/emmet-helper/lib/esm/emmetHelper.js`, `makeSnippetSuggestion()` filters snippet keys with `snippetKey.startsWith(prefix.toLowerCase())`. When the user types `inpb`, `prefix` is `inpb` and no snippet key starts with that string — `input:b`, `input:btn`, `input:button` all start with `input`, not `inpb`.
- **CSS difference:** CSS completions use a different code path with built-in property name fuzzy matching in the emmet expand engine, which is why `fsiz` matches `font-size`.
- **current version:** @vscode/emmet-helper v2.11.0 on current main still has the same `startsWith` logic in `makeSnippetSuggestion`.
