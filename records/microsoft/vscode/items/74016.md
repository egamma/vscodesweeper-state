# Issue #74016 — Expose vscode remote reconnecting UI.

[https://github.com/microsoft/vscode/issues/74016](https://github.com/microsoft/vscode/issues/74016)

## Summary

The requested API would let extensions block the entire workbench during reconnection, which received an explicit maintainer objection. Current VS Code instead presents remote reconnection as non-blocking status feedback, so the request can be closed as designed.

## Change summary

Expose the Remote reconnection UI to extensions so networked extensions such as Live Share can block editor interaction while reconnecting.

## Best solution

Extensions should preserve their own synchronization invariants while presenting non-blocking connection feedback through `window.withProgress` or a status bar item; the workbench-wide blocking mechanism should remain unavailable to extensions.

## Vision fit

- **Fit:** rejected
- **Reason:** Allowing an extension to block the whole workbench conflicts with VS Code's preference for simple, uniform UI interactions and a responsive editor.
- **Evidence:** Public values and guardrails: “Simple, uniform UI and UI interactions” and “Performance trumps functionality.”
