# Issue #333409 — Persist Copilot chat history per workspace with protection against accidential deletion

[https://github.com/microsoft/vscode/issues/333409](https://github.com/microsoft/vscode/issues/333409)

## Summary

Current main already provides workspace-scoped persistence, confirmation before permanent deletion, and JSON import/export, but deletion remains irreversible and cross-session full-text search is still missing. No single older issue owns this entire re-reviewed request, so it should remain open but be narrowed to recoverable deletion rather than closed as a duplicate.

## Change summary

Make workspace chat history durable and recoverable, with deletion confirmation, a retained trash or undo path, backup import/export, and optional full-text search.

## Best solution

Keep the existing workspace persistence, confirmation, and JSON import/export behavior, and narrow this issue to a provider-aware recoverable deletion design with a defined retention period and restore UI. Track full-text search in https://github.com/microsoft/vscode/issues/254027 and workspace move/relink behavior in https://github.com/microsoft/vscode/issues/305818 or https://github.com/microsoft/vscode/issues/332166 rather than duplicating those efforts here.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/sessions/services/sessions/common/sessionsProvider.ts`, `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts`, `src/vs/sessions/contrib/sessions/browser/sessionsActions.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts`
- **Validation:** Add focused storage and Sessions action tests proving that confirmed deletion enters a recoverable state, restoration returns the chat or session to its original workspace, expiry permanently removes it, and cancelling the existing confirmation leaves storage unchanged.
- **Behavior:**

  > Deleting a committed chat or session continues to require explicit confirmation. After confirmation, supported sessions remain recoverable for the chosen retention period and can be restored to their original workspace with their content and metadata intact; expiry permanently removes them. Closing and reopening chat tabs remains a separate, non-destructive operation. Existing JSON import/export behavior and deletion of transient untitled drafts remain unchanged.
- **Trace:**

  > Local chat persistence is owned by ChatSessionStore in src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts; internalDeleteSession currently removes the session files immediately and deletes the index entry. Session and individual-chat deletion flow through ISessionsProvider in src/vs/sessions/services/sessions/common/sessionsProvider.ts and ISessionsManagementService, with confirmation in Sessions actions and provider-specific chat deletion. Closed chats already have a separate in-memory/view-state reopen path in src/vs/sessions/services/sessions/common/sessionsManagement.ts, explicitly excluding deleted chats, so it must not be conflated with durable recovery. Provider-backed Agent Host sessions may own data outside ChatSessionStore, which is where the cross-provider scope uncertainty begins. Full-text search and workspace relinking are already represented by https://github.com/microsoft/vscode/issues/254027, https://github.com/microsoft/vscode/issues/305818, and https://github.com/microsoft/vscode/issues/332166 and should remain outside this change.
- **Open decisions:**
  - Should recoverable deletion apply only to locally stored Copilot chats, or must every Sessions provider expose a trash-and-restore contract before the UI is offered?
  - Should deleted items be retained for a fixed period such as 30 days or use a user-configurable retention policy?
  - Should recovery be presented only within the original workspace or through a cross-workspace deleted-sessions view?

## Evidence

- **deletion confirmation:** src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts and src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts already display confirmation dialogs stating that deletion cannot be undone.
