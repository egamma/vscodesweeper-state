# Issue #236313 — In Terminal view, the 'Next/Previous Match' search function conflicts with the redirection triggered by Ctrl+Left Click.

[https://github.com/microsoft/vscode/issues/236313](https://github.com/microsoft/vscode/issues/236313)

## Summary

Still open on main — no fix has been applied. The terminal find widget delegates find-next/previous to xterm.js's search addon, which uses cursor position; Ctrl+Click (link open) repositions the cursor, resetting the search to the beginning. Valid but niche interaction bug.

## Change summary

Terminal find next/previous match resets to the first match after Ctrl+Click opens a link, because the link activation moves the terminal cursor position that the search addon relies on.

## Best solution

The terminal find widget (or the xterm integration layer) should preserve and restore the search position across Ctrl+Click link activations, likely by saving the search state before the link open and restoring it afterward. The fix would touch `src/vs/workbench/contrib/terminalContrib/find/browser/terminalFindWidget.ts` and possibly `src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts`. Alternatively, this may need an upstream xterm.js search-addon change to decouple search position from cursor position.
