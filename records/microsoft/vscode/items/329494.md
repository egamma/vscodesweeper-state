# Issue #329494 — Hybrid Markdown editor: "Add comment for agent" does not work (Windows, VS Code 1.132.0)

[https://github.com/microsoft/vscode/issues/329494](https://github.com/microsoft/vscode/issues/329494)

## Summary

The 'Add Comment' affordance in the Hybrid Markdown editor is intentionally scoped to files that are part of an active agent feedback/plan-review session — a plain .md file opened without such a session correctly shows no comment UI, which matches what the reporter saw; this is as-designed, not a defect.

## Change summary

Selecting text in the Hybrid Markdown editor and choosing 'Add Comment' does nothing when the file has no active agent session.

## Best solution

Keep the current scoping (comment mode only mounts when `acceptsComments` is true, i.e. the resource is in scope for an agent feedback/plan-review session); if the maintainers want the comment affordance to work for arbitrary Markdown files outside a session, that would be a new feature request, not this bug.

  > Thanks for the report. This is expected: the 'Add Comment' affordance in the Hybrid Markdown editor is only active while the file is part of an active agent feedback/plan-review session (the same gating the code editor's inline feedback widget uses — see `acceptsComments` in `agentEditorCommentsProvider.ts` and the comment-controller mount logic in `markdown-editor-src/editor.ts`). Opening a standalone `.md` file with no active agent session correctly shows no comment UI. If you'd like comments to work outside a session context, that would be a separate feature request. Closing as as-designed for now — please reopen if you were actually inside an active agent session when this happened.

## Evidence

- **webview gating:** extensions/markdown-language-features/markdown-editor-src/editor.ts:255-269 mounts `CommentModeController` (the 'Add Comment' UI) only while `#acceptsComments` observable is true, and tears it down otherwise, with a comment explicitly noting 'only useful when the workbench feedback store will actually accept the comment'.
- **acceptsComments source:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts:578 posts `acceptsComments: commentsProvider.acceptsComments` to the webview, backed by src/vs/sessions/contrib/agentFeedback/browser/agentEditorCommentsProvider.ts:50-52 `acceptsComments(resource) { return !!this._agentFeedbackService.getFeedbackSessionResource(resource); }`.
- **session requirement:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackEditorInputContribution.ts:479-488 shows the same gating for the regular code editor's feedback widget: it requires `ChatContextKeys.enabled` and a resolvable feedback session resource for the file, i.e. the file must be part of an active Agents window / plan-review feedback scope.
