# Issue #329494 — Hybrid Markdown editor: "Add comment for agent" does not work (Windows, VS Code 1.132.0)

[https://github.com/microsoft/vscode/issues/329494](https://github.com/microsoft/vscode/issues/329494)

## Summary

The hybrid Markdown editor's comment affordance is deliberately gated to resources that are in scope for an active agent feedback/plan-review session; a plain .md file opened directly (no active session) correctly shows no Add Comment UI, matching the intentional design in a recent commit that added this exact guard.

## Change summary

Selecting text in the experimental Hybrid Markdown editor and trying to add a comment does nothing — no comment UI appears at all, even via right click.

## Best solution

Keep the current gating: `AgentEditorCommentsBridge.acceptsComments`/`AgentEditorCommentsProviderContribution.acceptsComments` only returns true when `IAgentFeedbackService.getFeedbackSessionResource` resolves a session for the resource (i.e. it's part of an active agent review), so no provider is registered for a manually opened .md file and the widget is intentionally hidden per commit aaea53646d3ab78ffc16a6f39fce1f0160736bc.

## Vision fit

- **Fit:** aligned
- **Reason:** The feature is part of the Agents window / agent feedback and review flow, which the current-priorities layer names as a focus area, and gating comments to actual review sessions keeps the default editor experience lean rather than showing an always-on affordance.
- **Evidence:** Durable theme: Workbench & core UX and AI-assisted development; current priorities: Agents window multi-session review flows (PR/changes review) are an active workstream.

  > Thanks for the report! The "Add comment" affordance in the Markdown editor is intentionally scoped to files that are part of an active agent feedback/plan-review session — it's meant for commenting on changes an agent is actively working on or that are under review, not for arbitrary Markdown files opened on their own. That's implemented in `AgentEditorCommentsProviderContribution.acceptsComments` (src/vs/sessions/contrib/agentFeedback/browser/agentEditorCommentsProvider.ts), and commit aaea53646d3 explicitly hides the widget when commenting isn't possible for the resource. If you hit this while genuinely inside an active agent session/plan review (not just opening a plain .md file), please reopen with those repro details — that would point to a real gap rather than the by-design gating.

## Evidence

- **session-scoped provider:** src/vs/sessions/contrib/agentFeedback/browser/agentEditorCommentsProvider.ts:52 — acceptsComments(resource) returns `!!this._agentFeedbackService.getFeedbackSessionResource(resource)`, i.e. only resources tied to an active agent feedback session accept comments.
- **webview honors the flag:** extensions/markdown-language-features/markdown-editor-src/editor.ts:296-314 — the CommentModeController (the 'Add a comment' affordance) is only constructed when the `#acceptsComments` observable, driven by the extension host's `acceptsComments` message, is true.
