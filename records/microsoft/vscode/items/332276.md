# Issue #332276 — External agent host sessions: user messages sent from VS Code show added metadata

[https://github.com/microsoft/vscode/issues/332276](https://github.com/microsoft/vscode/issues/332276)

## Summary

Fresh, already correctly labeled and routed (polish, agent-host) report from the linked test plan item; the checkout confirms VS Code's agent host really does inject context like `<environment_context>`, `<current_datetime>`, and `<system_reminder>` directly into the user message text, which is exactly what would leak into an external client's raw transcript view — a real design gap, not something to close.

## Change summary

When an agent host session is driven from an external app (Copilot/ChatGPT/Claude apps) instead of VS Code, the extra context VS Code injects into the user turn (environment context, datetime, system reminders) shows up as visible junk in that external app's conversation view.

## Best solution

Decide, in the agent-host side-effects/context-injection layer (src/vs/platform/agentHost/node/agentSideEffects.ts and the turn lifecycle contributions under chatContributions/), whether VS Code-authored context should be sent as a separate system-level content block/hidden metadata instead of being concatenated into the visible user message text, so external clients rendering the raw transcript don't show it to the user.
