# Issue #122265 — link parsing should favor on screen urls over offscreen content for huge files

[https://github.com/microsoft/vscode/issues/122265](https://github.com/microsoft/vscode/issues/122265)

## Summary

Still a valid feature request: link detection in large (but sub-50 MB) files parses the entire document before any links become clickable. No viewport-prioritized approach has been implemented — current main either parses all links or disables them entirely for very large files.

## Change summary

Request to prioritize visible-viewport link parsing over offscreen content in large files so links become clickable faster.

## Best solution

Implement viewport-aware link detection in `src/vs/editor/contrib/links/browser/links.ts`: parse visible lines first, render their decorations, then parse the remainder in the background. This would close the gap between 'parse everything' (slow for 100K+ line files) and 'disable entirely' (the current `isTooLargeForSyncing` guard added in commit 17f32eac9de). The area owner (`editor-contrib`) should evaluate whether the complexity is justified given the niche audience.
