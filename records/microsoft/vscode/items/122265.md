# Issue #122265 — link parsing should favor on screen urls over offscreen content for huge files

[https://github.com/microsoft/vscode/issues/122265](https://github.com/microsoft/vscode/issues/122265)

## Summary

A real large-file responsiveness gap remains on current main: link detection scans the complete model and the editor waits for every provider before adding link decorations. The Backlog request should remain open but move to under-discussion because visible-range prioritization requires a product and provider-contract design, and it has no recorded community demand beyond the reporter.

## Change summary

Prioritize link detection around the visible editor range in huge files so nearby URLs become clickable before offscreen content is scanned.

## Best solution

Design progressive link detection that makes links in or near the viewport available first while preserving complete-document results for extensions and eventual background processing. The editor and language-feature owners should decide whether this is a core-only optimization or requires a range-aware/progressive LinkProvider contract.
