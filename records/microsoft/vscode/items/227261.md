# Issue #227261 — Support mouse wheelScrollSensitivity in notebooks

[https://github.com/microsoft/vscode/issues/227261](https://github.com/microsoft/vscode/issues/227261)

## Summary

Keep open: notebooks still share the workbench-list sensitivity, so the existing setting cannot adjust notebook scrolling without also changing Explorer scrolling. This issue already owns a consolidated report; the remaining decision is how notebooks should expose independent sensitivity while preserving existing configurations.

## Change summary

Allow notebook mouse-wheel scrolling sensitivity to be adjusted independently of Explorer and other workbench lists.

## Best solution

Provide a notebook scrolling configuration contract that permits independent tuning without changing other lists. Decide whether notebooks should inherit editor sensitivity or expose a notebook-specific override, including the compatibility behavior for existing workbench-list settings.

- **Behavior:**

  > Users must be able to tune outer notebook mouse-wheel scrolling without changing Explorer or other workbench-list scrolling. The reporter needs notebook sensitivity around 2 while other lists remain around 0.3-0.5; the current shared setting cannot express that configuration. Acceptance must cover initial configuration, live configuration changes, and the agreed behavior when no notebook override is configured. Existing unrelated list scrolling and keyboard navigation must remain unchanged.
- **Trace:**

  > NotebookCellList in src/vs/workbench/contrib/notebook/browser/view/notebookCellList.ts extends WorkbenchList and delegates construction to it. toWorkbenchListOptions in src/vs/platform/list/browser/listService.ts supplies workbench.list.mouseWheelScrollSensitivity after spreading caller options, and WorkbenchList's configuration listener reapplies the same shared value. NotebookEditorWidget creates this list without independent sensitivity configuration; notebook editor customizations apply to embedded cell editors rather than the outer list. This establishes the configuration gap, not the cause of the reporter's platform-specific perceived speed difference. Preserve unrelated workbench-list behavior and avoid treating the separate webview-normalization report at https://github.com/microsoft/vscode/issues/331600 as a substitute for independent tuning. The maintainer consolidated https://github.com/microsoft/vscode/issues/229580 into this issue; the uncertainty is the user-facing inheritance and compatibility contract.
- **Open decisions:**
  - Should outer notebook scrolling follow editor.mouseWheelScrollSensitivity, or offer a notebook-specific sensitivity override?
  - When no notebook-specific value is configured, should existing workbench.list.mouseWheelScrollSensitivity behavior remain the default, or should notebooks switch to editor sensitivity?
