# Issue #192462 — New terminal not opening in default project path in remote connection

[https://github.com/microsoft/vscode/issues/192462](https://github.com/microsoft/vscode/issues/192462)

## Summary

Confirmed and still open: the remote terminal backend's `createProcess` ignores the `cwd` parameter (marked with a TODO since 2021), causing new terminals in WSL remote connections to open at `/` instead of the workspace folder. Tyriar confirmed the reproduction and the root cause in the pty host. No fix commit references this issue.

## Change summary

New terminal opens at `/` instead of the project directory when using a WSL remote connection via `code .`.

## Best solution

Fix the cwd resolution path in `src/vs/workbench/contrib/terminal/browser/remoteTerminalBackend.ts` so that the `cwd` parameter passed to `createProcess` is properly forwarded to the remote pty host instead of being ignored, ensuring `shellLaunchConfig.cwd` is populated with the workspace folder URI before reaching the remote channel.
