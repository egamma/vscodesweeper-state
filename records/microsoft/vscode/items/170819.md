# Issue #170819 — SCM - Reveal Active File in Git View

[https://github.com/microsoft/vscode/issues/170819](https://github.com/microsoft/vscode/issues/170819)

## Summary

Keep open: automatic reveal does not cover the requested explicit command, especially when the active file belongs to a hidden repository. The request has sufficient community support and a maintainer-approved direction that preserves existing repository selections.

## Change summary

Add an explicit command to open Source Control and reveal/select the active file, making its repository visible when necessary.

## Best solution

Provide an on-demand SCM reveal command that works independently of scm.autoReveal and preserves other visible repositories in multiple-selection mode. Follow the maintainer's additive repository-selection direction rather than the reporter's original request to deselect everything else.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/contrib/scm/browser/scmViewService.ts`, `src/vs/workbench/contrib/scm/browser/scm.contribution.ts`
- **Validation:** In a workspace with two Git repositories containing changed files, hide repository B, activate its changed file, disable scm.autoReveal, and invoke the new command with Source Control initially hidden. Verify Source Control opens and the file is revealed/selected in both list and tree modes; in multiple-selection mode repository A must remain visible. Repeat with single-selection mode against the agreed contract and verify ordinary automatic reveal remains unchanged.
- **Behavior:**

  > Users can explicitly reveal the active changed file in Source Control without enabling automatic reveal or manually locating its repository. Invoking the command opens the Source Control view, makes the owning repository visible, and reveals/selects the file even under collapsed tree ancestors. In multiple-selection mode, previously visible repositories remain visible, as the maintainer requested. Acceptance must cover a previously hidden repository, disabled scm.autoReveal, and both list and tree modes; single-selection behavior needs an explicit contract.
- **Trace:**

  > SCMViewPane.onDidActiveEditorChange in src/vs/workbench/contrib/scm/browser/scmViewPane.ts is the existing reveal path: it is gated by scm.autoReveal and searches only visible repositories before expanding and selecting a matching SCM resource. SCMViewService.toggleVisibility in src/vs/workbench/contrib/scm/browser/scmViewService.ts already distinguishes additive multiple selection from exclusive single selection. The maintainer approved pursuing a command and rejected deselecting other repositories at https://github.com/microsoft/vscode/issues/170819#issuecomment-2154628381. Preserve existing automatic-reveal semantics and repository-selection settings; do not turn this into a redesign of SCM navigation. The staged-diff URI mismatch tracked by https://github.com/microsoft/vscode/issues/320087 is related but distinct and should not be silently absorbed into this feature. The trace establishes the missing manual entry point and hidden-repository boundary, but not a tested implementation or complete input contract.
- **Open decisions:**
  - When repository selection mode is Single and the active file belongs to a hidden repository, should the command switch the sole visible repository or preserve the current selection and decline to reveal the file?
