# Issue #332033 — Copilot Chat renders large blank regions after a long multi-turn Agent session

[https://github.com/microsoft/vscode/issues/332033](https://github.com/microsoft/vscode/issues/332033)

## Summary

Two users report the same blank-region failure, and the detailed transcript diagnostics point to the chat list's dynamic-height or content-part rendering rather than whitespace returned by the model. No open canonical or landed fix was found, so this should remain open and be routed to the chat response owners.

## Change summary

Long or tool-heavy Agent conversations accumulate large blank regions between or inside rendered responses while requests continue normally.

## Best solution

Diagnose the mismatch between rendered response bounds and the virtualized chat tree's cached row heights, including short or empty tool-bearing assistant records, then add a long-transcript regression test that exercises row recycling.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`
- **Validation:** Add a chat list widget regression test with a long transcript containing short or empty tool-bearing responses, scroll far enough to recycle rows, and assert that rendered row bounds and the tree's content height contain no unexplained vertical gaps before and after recycling.
- **Behavior:**

  > A long or tool-heavy Agent conversation must render each request, response, tool result, and progress item using only the space required by visible content. Empty assistant text associated with tool calls must not accumulate large vertical gaps. Scrolling away and back, row virtualization, request completion, and session restoration must preserve the same compact layout. Existing non-empty responses and intentional spacing must remain unchanged.
- **Trace:**

  > The transcript is rendered by the dynamically sized WorkbenchObjectTree created in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts. ChatListDelegate starts unknown rows at 200 pixels, and ChatListItemRenderer in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts measures mounted rows through ResizeObserver, records `currentRenderedHeight`, and emits updates that reach `tree.updateElementHeight`. `renderChatResponseBasic` also builds response rows from references, annotated response content, tool invocations, summaries, and progress even when markdown text is empty. The report's many zero-content, tool-bearing assistant records make short-row estimates and recycling important, but the evidence does not yet distinguish stale tree height from a content part that remains structurally tall. The prior swallowed-growth defect at https://github.com/microsoft/vscode/issues/326952 was fixed by https://github.com/microsoft/vscode/pull/326961 and must not be treated as the same root cause without a matching trace. Keep transport retry behavior and intentional response spacing out of scope unless instrumentation shows they create the layout mismatch.

## Evidence

- **confirmed symptom:** The report includes a screenshot, precise environment data, and persisted-session diagnostics; https://github.com/microsoft/vscode/issues/332033#issuecomment- reports an independent occurrence, including in shorter BMAD sessions.
- **rendering path:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts creates a WorkbenchObjectTree with dynamic heights and a 200-pixel default estimate, while src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts measures each row through ResizeObserver and reconciles that measurement with `currentRenderedHeight` before calling `tree.updateElementHeight`.
- **short-row lead:** In `reconcileChatItemHeight` at src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts, an initial measurement smaller than its allocated estimate is stored without notifying the tree. The report's roughly 30 zero-content assistant records make stale overestimates a concrete investigation lead, although the full trigger is not yet proven.
- **distinct prior fix:** https://github.com/microsoft/vscode/issues/326952 and merged https://github.com/microsoft/vscode/pull/326961 fixed swallowed growth notifications that clipped response tails. The current report was filed against a later build and describes excess blank space rather than clipped content, so that closed issue is neither an open canonical nor proof of resolution.
- **canonical search:** Searches for open VS Code issues describing Copilot Chat blank space or blank regions found no issue that owns this same rendering failure.
