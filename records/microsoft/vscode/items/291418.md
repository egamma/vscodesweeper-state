# Issue #291418 — Mermaid file URIs are not unique on reload

[https://github.com/microsoft/vscode/issues/291418](https://github.com/microsoft/vscode/issues/291418)

## Summary

Still reproduces on main: after reload, the deserialized mermaid preview registers under a different content hash than a fresh open, so the duplicate-detection in `openPreview` misses it and creates a second tab.

## Change summary

After reloading VS Code, opening the same mermaid diagram from chat creates a duplicate editor tab instead of revealing the already-restored one.

## Best solution

Fix the webview-id mismatch by either (a) trimming the source before hashing in `getWebviewId`, (b) embedding the source without HTML-template whitespace in the `<pre>` tag, or (c) saving the original clean source in the webview state instead of extracting it from `textContent`. The fix lives in `extensions/mermaid-markdown-features/src/editorManager.ts` and possibly `preview-src/chat/mermaidWebview.ts`.
