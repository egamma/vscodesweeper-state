# Issue #292689 — Setting output channel default verbosity has issues with extension channels

[https://github.com/microsoft/vscode/issues/292689](https://github.com/microsoft/vscode/issues/292689)

## Summary

The reload-specific persistence bug remains source-reproducible on current main: extension defaults are initially taken from stale process environment data and `argv.json` is only reparsed after a subsequent file-change event.

## Change summary

Extension output channels fail to consistently adopt a newly persisted default log level after reloading the window.

## Best solution

Ensure persisted extension log-level defaults are loaded before extension-host initialization after a window reload, while preserving explicit per-logger overrides and immediate updates to active channels.

## Evidence

- **source trace:** src/vs/workbench/services/log/common/defaultLogLevels.ts initializes `_defaultLogLevels.extensions` through `_getExtensionsDefaultLogLevelsFromEnv()` in the constructor; `_parseLogLevelsFromArgv()` is only called by `onDidChangeArgv()` after a file-change event or by `setDefaultLogLevel()`.
- **reload trigger:** After `setDefaultLogLevel()` writes the new extension level to `argv.json`, reloading the renderer constructs a new service from the still-running process environment. Because the write happened before the new file watcher was registered, no event reparses the persisted value, matching the reporter's stale level and disabled Set As Default action.
