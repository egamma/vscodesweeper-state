# Issue #58038 — Settings editor not showing inherited values in workspace scope

[https://github.com/microsoft/vscode/issues/58038](https://github.com/microsoft/vscode/issues/58038)

## Summary

This long-standing feature request (96 upvotes, On Deck milestone) to show inherited user-setting values in the workspace scope of the settings editor remains unimplemented on main. The settings editor still shows defaults rather than inherited values, with only a 'Modified in' indicator. A team member acknowledged the request and discussed solutions but no implementation landed.

## Change summary

When viewing workspace settings in the settings editor, settings modified in user scope should show their effective (inherited) value rather than the schema default, making it possible to override a user setting back to the default via the UI.

## Best solution

Implement the approach discussed by roblourens in comment 11: workspace settings should use the user-configured value as the 'default' display value (not the schema default), so toggling a checkbox or editing a field in workspace scope writes the value to workspace settings.json even when it matches the schema default. This enables overriding user settings from the workspace UI without resorting to JSON editing.
