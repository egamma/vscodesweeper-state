# Issue #58038 — Settings editor not showing inherited values in workspace scope

[https://github.com/microsoft/vscode/issues/58038](https://github.com/microsoft/vscode/issues/58038)

## Summary

Keep open: ordinary Workspace Settings still display schema defaults instead of inherited User values. The persistence problem was addressed separately, but the maintainer explicitly retained this issue for inherited-value presentation, and current source confirms that gap remains.

## Change summary

Show inherited configuration values in scoped Settings controls when no explicit value exists at the selected scope.

## Best solution

Make scoped Settings presentation communicate inherited values and distinguish them from explicit overrides, while preserving configuration precedence and manual-reset behavior. Extend the existing Agents-window approach only after establishing consistent semantics for workspace, folder, remote, and language-filtered views.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`, `src/vs/workbench/contrib/preferences/test/browser/settingsTreeModels.test.ts`, `src/vs/workbench/contrib/preferences/test/browser/settingsTree.test.ts`
- **Validation:** Extend settingsTreeModels.test.ts to cover User formatOnSave=true with no Workspace override, an explicit Workspace false, and reset restoring inheritance; include remote, folder, and language-filtered cases matching the agreed semantics. Run the focused preferences model and renderer suites, and manually verify that inherited presentation does not write configuration until the user edits a control.
- **Behavior:**

  > When a setting has no explicit Workspace value, its control should communicate the inherited value rather than presenting a conflicting schema default. An explicit Workspace override must remain distinguishable from inheritance, including when it equals the schema default. Resetting an override should restore inherited presentation without changing User settings. Acceptance should cover boolean and numeric controls, configuration changes while the editor is open, and the agreed remote, folder, and language-filtered behavior.
- **Trace:**

  > SettingsTreeSettingElement.update in src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts chooses inspected.defaultValue for unconfigured scopes, except for a narrowly gated Agents-window path that uses inspected.value. Language-filtered presentation subsequently has a separate override/default branch. The manual-reset work in https://github.com/microsoft/vscode/pull/144429 solved persistence, not this display choice; preserve that behavior and the actual configuration precedence. https://github.com/microsoft/vscode/issues/341044 provides a recent comparison of the two window types. The remaining design boundary is how inherited presentation should interact with language overrides and scopes beyond ordinary Workspace Settings; do not assume the fully effective inspected.value is the correct inherited value for every tab.
- **Open decisions:**
  - In an unfiltered scope tab, should inherited presentation include language-specific values from the active editor, or should those appear only when the corresponding language filter is selected?

## Evidence

- **Remaining capability gap:** src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts:310–321, SettingsTreeSettingElement.update: an unset scoped value uses inspected.defaultValue unless isSessionsWindow is true, targetSelector is workspaceValue, and no language filter is active. Consequently, ordinary Workspace Settings still show the schema default rather than the inherited User value.
- **Partial fix is not completion:** https://github.com/microsoft/vscode/pull/144429 merged the manual-reset/persistence change. The maintainer explicitly stated that inherited-value presentation remained unchanged at https://github.com/microsoft/vscode/issues/58038#issuecomment-1067354287 and retained this issue for that remaining request at https://github.com/microsoft/vscode/issues/58038#issuecomment-1074184622.
- **Existing capability and workarounds:** The registered command workbench.action.openWorkspaceSettingsFile opens workspace JSON; it does not make Settings controls display inherited values. The maintainer also documented changing a control away and back to persist an explicit default at https://github.com/microsoft/vscode/issues/58038#issuecomment-1810678997. Neither workaround covers the remaining presentation request.
- **Recent related report:** https://github.com/microsoft/vscode/issues/341044 is open and explicitly reproduces the difference between inherited values in Agents Window Settings and schema defaults in ordinary Workspace Settings. It was created in 2026, so it cannot serve as an older canonical for this re-reviewed 2018 issue.
- **Older canonical checked:** https://github.com/microsoft/vscode/issues/57330 is open and older, but concerns settings whose sentinel defaults refer to other settings, such as suggest font size 0 meaning editor font size. That is not the same observable symptom as inheritance of one setting across User and Workspace scopes.
- **Demand and accepted direction:** The issue has 96 community upvotes and an On Deck holding milestone. The maintainer acknowledged demand for inherited values rather than declining the request; neither age nor the completed persistence subproblem justifies closing the remaining work.
