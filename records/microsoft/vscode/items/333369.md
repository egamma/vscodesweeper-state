# Issue #333369 — `runSubagent` bypasses `disable-model-invocation` when `agentName` is omitted

[https://github.com/microsoft/vscode/issues/333369](https://github.com/microsoft/vscode/issues/333369)

## Summary

Confirmed on current main: `runSubagent` does not enforce an agent's `agentInvocable` visibility for either explicit selection or inherited current-agent invocation. The issue should remain open for a bounded runtime-enforcement fix.

## Change summary

Prevent `runSubagent` from invoking custom agents marked `disable-model-invocation: true`, including when `agentName` is omitted.

## Best solution

Enforce model-invocation eligibility before dispatch for both named agents and inherited current agents, while preserving existing instruction inheritance and allowlist behavior for invocable agents.
