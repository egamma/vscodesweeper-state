# Issue #333369 — `runSubagent` bypasses `disable-model-invocation` when `agentName` is omitted

[https://github.com/microsoft/vscode/issues/333369](https://github.com/microsoft/vscode/issues/333369)

## Summary

Well-diagnosed, code-confirmed gap: `runSubagent` never checks `disable-model-invocation`/`agentInvocable` when cloning the current mode into a subagent, so an agent authored to be manual-only can still be auto-invoked as a subagent (both implicitly via the omitted-`agentName` path and, per the report, even when named explicitly).

## Change summary

`runSubagentTool.ts` clones the current mode's instructions into a subagent without ever checking that mode's `disable-model-invocation` flag, so the flag has no runtime enforcement.

## Best solution

Thread agent invocability into the subagent dispatch path in runSubagentTool.ts: for the implicit (`agentName` omitted) branch, resolve the current mode's custom-agent record (e.g. via `getSubAgentByName(currentModeInstructions.name)`) and reject when `visibility.agentInvocable` is false, mirroring the existing `validateSubagentAllowed` allowlist check; extend the same check to the explicit-name branch so an explicit `agentName` can't bypass it either.
