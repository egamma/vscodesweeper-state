[https://github.com/microsoft/vscode/issues/323357](https://github.com/microsoft/vscode/issues/323357)

## Summary

The reported coupling remains in current source: native chat requests start MCP discovery before dispatching the participant's /compact handler. Keep this open for a bounded fix that leaves ordinary chat-message autostart behavior unchanged.

## Change summary

Prevent explicit conversation compaction from triggering unrelated MCP server discovery and startup.

## Best solution

Make /compact complete without initiating MCP discovery or starting idle servers, while preserving configured MCP autostart for ordinary chat requests. Address the request-dispatch boundary rather than changing MCP startup policy globally.
