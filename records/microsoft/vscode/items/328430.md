# Issue #328430 — Github Copilot change from Agent to Plan Mode triggers "Start Implementation" 

[https://github.com/microsoft/vscode/issues/328430](https://github.com/microsoft/vscode/issues/328430)

## Summary

Confirmed on current main: when a completed response was produced by a built-in mode (e.g. Agent) whose request metadata lacks `modeInstructions`, switching to Plan mid-conversation with Autopilot on incorrectly resolves the 'response mode' to the newly selected Plan mode instead of the mode that actually produced the response, auto-firing Plan's send-handoff ("Start implementation") and discarding the user's draft.

## Change summary

Switching from Agent to Plan mode in an existing Copilot Chat session (with Autopilot) auto-submits "Start implementation" and wipes the user's freshly typed prompt.

## Best solution

In chatWidget.ts's renderChatSuggestNextWidget, resolve the response mode via modes.findModeById(modeInfo.kind) as a fallback before falling back to the current input mode, restoring the built-in-mode lookup that was dropped in the modeId->telemetryModeId refactor; add a regression test covering completed Agent response + Autopilot + non-empty draft when switching to Plan.

  > In src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts, method renderChatSuggestNextWidget (around lines 1632-1642), the code tries to recover the chat mode that produced the last response so handoffs reflect that mode rather than whatever is currently selected in the mode picker. Fix by adding a fallback that resolves the built-in response mode via `modes.findModeById(modeInfo.kind)` when `modeInfo?.kind` is defined, before falling back to `currentModeObs.get()` for legacy sessions with no modeInfo at all.
