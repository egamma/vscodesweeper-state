# Issue #295917 — chat references never lead to exact code locations that chat intended to reference, but lead to definitions instead

[https://github.com/microsoft/vscode/issues/295917](https://github.com/microsoft/vscode/issues/295917)

## Summary

The reporter wants chat inline reference links (clickable pills) to navigate to the specific usage/call site the chat was discussing, rather than the symbol definition. Current behavior is by design — inline references resolve to symbol definitions because the model emits symbol names, not usage-site locations. This is a feature request to improve location targeting of chat references.

## Change summary

Clicking a chat reference link for a method call (e.g. `async.queue`) always navigates to the symbol's definition instead of the specific usage location in the user's code that the chat response was referring to.

## Best solution

This requires the chat model to emit more precise location data (file + range of the call site) rather than just symbol names that resolve to definitions. The `IChatContentInlineReference` already supports `Location` (URI + range), so the model/agent pipeline would need to provide the exact call-site location when referencing a specific usage. This is an enhancement to the chat response pipeline, likely spanning `src/vs/workbench/contrib/chat/common/widget/annotations.ts` and the upstream model/agent response handling. Labeling as `feature-request` with `copilot` area would route it to the right team.
