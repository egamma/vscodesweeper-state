# Issue #176890 — Make the Command Palette show the keybindings corresponding to the command being displayed

[https://github.com/microsoft/vscode/issues/176890](https://github.com/microsoft/vscode/issues/176890)

## Summary

Keep this accepted Backlog request open: current source still selects the displayed shortcut by command ID without matching arguments, so the reported mismatch remains possible. The request has 22 upvotes, and no verified canonical absorbs its central requirement.

## Change summary

Make Command Palette shortcut hints match the arguments used by the displayed command, with an optional ability to expose named argument-specific variants.

## Best solution

Make shortcut hints describe the invocation that selecting the palette entry actually performs, preserving normal keybinding precedence among matching invocations. Decide separately whether user-defined argument variants should become named palette entries; extension-contributed argument variants are related work, not a substitute for accurate hints.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/commandsQuickAccess.ts`, `src/vs/platform/keybinding/common/keybinding.ts`, `src/vs/platform/keybinding/common/abstractKeybindingService.ts`, `src/vs/platform/keybinding/common/keybindingResolver.ts`, `src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts`
- **Validation:** With Calva installed, retain its default no-argument calva.connect shortcut and add the report's ctrl+alt+c shift+c binding with {"disableAutoSelect":true}. Open the Command Palette and verify that the no-argument entry advertises the matching default shortcut, not the argument-bearing shortcut; verify selecting the entry still invokes the no-argument command. Repeat with no matching no-argument shortcut and with multiple context-dependent bindings, checking the agreed hint behavior and unchanged keyboard execution.
- **Behavior:**

  > A Command Palette entry must not advertise a shortcut that invokes the same command ID with different arguments. In the reported Calva example, the no-argument entry should continue showing its eligible no-argument shortcut after an argument-bearing custom binding is added. Acceptance must also cover no matching shortcut and multiple context-dependent bindings without changing what either the palette entry or a keyboard shortcut executes. Separately titled argument variants are an optional extension of the request whose scope remains to be decided.
- **Trace:**

  > AbstractCommandsQuickAccessProvider.toCommandPick in src/vs/platform/quickinput/browser/commandsQuickAccess.ts looks up a shortcut solely by commandId, while its accept handler executes the pick's own arguments. AbstractKeybindingService.lookupKeybinding delegates to KeybindingResolver.lookupPrimaryKeybinding, which considers command ID, precedence and when-context but not commandArgs. CommandsQuickAccessProvider.getGlobalCommandPicks in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts creates ordinary contributed entries without arguments from custom bindings. This source trace establishes the missing distinction without running the application. Preserve keyboard dispatch semantics, command execution arguments and unrelated consumers of keybinding lookup. https://github.com/microsoft/vscode/issues/41692 concerns extension-contributed argument variants, not the inaccurate-hint symptom. Planning should settle argument matching semantics and whether separately named variants belong in this change.
- **Open decisions:**
  - Should hint matching require structurally equal explicit arguments, treating omitted arguments as a distinct invocation, or support any command-declared equivalence between argument forms?
  - Should this request cover only accurate shortcut hints, or also introduce user-defined titles and palette entries for argument-bearing keybindings?

## Evidence

- **Current palette behavior:** src/vs/platform/quickinput/browser/commandsQuickAccess.ts:280 calls lookupKeybinding(commandPick.commandId) without arguments. Its accept handler at lines 316–320 independently executes commandPick.args when present, otherwise executes the command without arguments.
- **Argument-insensitive lookup:** src/vs/platform/keybinding/common/abstractKeybindingService.ts:135–140 delegates to lookupPrimaryKeybinding and returns only the resolved shortcut. src/vs/platform/keybinding/common/keybindingResolver.ts:291–313 selects by command ID, reverse precedence and when-context; it does not compare commandArgs. Thus an eligible custom calva.connect binding with disableAutoSelect can supply the hint for a no-argument palette invocation.
- **Existing capability does not cover the request:** src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts:getGlobalCommandPicks constructs contributed palette entries from MenuId.CommandPalette with command ID and title metadata, without copying custom keybinding arguments into those entries. Existing argument-bearing keybindings therefore neither provide argument-matched hints nor automatically create separately titled palette entries.

It does not report the same observable symptom of a palette entry displaying a shortcut for a different invocation, so it does not meet the re-review duplicate bar.
