# Issue #307478 — Plugin hooks can't invoke relative bundled scripts

[https://github.com/microsoft/vscode/issues/307478](https://github.com/microsoft/vscode/issues/307478)

## Summary

The original relative-path failure remains visible in current source: plugin hooks with cwd set to '.' still resolve against the workspace, not the plugin installation. Plugin-root token interpolation now provides a workaround, but neither that mitigation nor the cited MCP change establishes a complete fix.

## Change summary

Allow installed plugin hooks to invoke bundled scripts reliably without hardcoding their installation path.

## Best solution

Establish and consistently implement plugin-hook working-directory semantics across supported plugin formats while preserving workspace-hook behavior. Retain plugin-root token support, but explicitly decide whether plugin-relative execution should be automatic or require an explicit plugin-root cwd.

- **Behavior:**

  > Installed plugin hooks must have a reliable way to execute scripts bundled in the plugin without knowing its installation directory. The original reproduction uses a relative script command and cwd '.', which currently targets the workspace instead. Acceptance must establish the intended meaning of omitted and relative cwd for plugin hooks, verify standalone and embedded definitions consistently, and preserve ordinary workspace hooks. Existing plugin-root token commands must continue to work.
- **Trace:**

  > In src/vs/platform/agentPlugins/common/pluginParsers.ts, readHooks and embedded manifest parsing dispatch through formatConfig.parseHooks. All four adapters now use interpolateHookPluginRoot, which expands the format-specific root token and sets its environment variable before passing the original workspaceRoot to parseHooksJson. resolveHookCommand resolves relative cwd against that workspaceRoot and uses it when cwd is omitted; it never receives pluginUri as a separate resolution base. This conclusively retains the original relative-path mismatch, although the explicit root-token workaround is now supported. The maintainer reproduction is https://github.com/tspascoal-samples/hook-plugin, described at https://github.com/microsoft/vscode/issues/307478#issuecomment-4450492285. Preserve workspace-hook resolution and existing token interpolation; Windows shell selection and quoting in https://github.com/microsoft/vscode/issues/337374 are separate concerns. The uncertainty is the public execution-directory contract, not where to place a guard or helper.
- **Open decisions:**
  - For installed plugin hooks, should omitted cwd and relative cwd values such as '.' resolve against the plugin directory, or remain workspace-relative with plugin authors required to specify the plugin-root token explicitly?

## Evidence

- **Confirmed reproduction:** A maintainer supplied https://github.com/tspascoal-samples/hook-plugin and confirmed that discovered plugin hooks execute from the workspace and fail to find scripts/on-user-prompt.sh: https://github.com/microsoft/vscode/issues/307478#issuecomment-4450492285.
- **Current source path:** In src/vs/platform/agentPlugins/common/pluginParsers.ts, readHooks passes pluginUri and workspaceRoot to formatConfig.parseHooks. All four format adapters now call interpolateHookPluginRoot, but that helper ultimately calls parseHooksJson with workspaceRoot. resolveHookCommand at lines 798–818 resolves relative cwd against workspaceRoot and defaults omitted cwd to workspaceRoot; commands without root tokens retain their relative script paths.
