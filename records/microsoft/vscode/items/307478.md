# Issue #307478 — Plugin hooks can't invoke relative bundled scripts

[https://github.com/microsoft/vscode/issues/307478](https://github.com/microsoft/vscode/issues/307478)

## Summary

Confirmed bug: Copilot-format plugin hooks resolve relative script paths and cwd against the workspace root instead of the plugin installation directory, making bundled hook scripts unreachable when the plugin is installed from the marketplace.

## Change summary

Hooks bundled in a Copilot plugin fail to execute because relative paths in hook commands resolve against the workspace directory rather than the plugin's installation directory.

## Best solution

In `src/vs/platform/agentPlugins/common/pluginParsers.ts`, update `COPILOT_FORMAT.parseHooks` (and/or `resolveHookCommand`) so that when hooks come from a plugin (not a workspace), the default `cwd` falls back to the plugin directory rather than `workspaceRoot`. The Claude and OpenPlugin formats already handle this via `${PLUGIN_ROOT}` interpolation — the Copilot format should either adopt the same token interpolation or set the cwd to `pluginUri` when `workspaceRoot` would otherwise be used for a plugin-sourced hook. The existing `sourceUri` field on `IParsedHookCommand` may help downstream consumers distinguish plugin hooks from workspace hooks.
