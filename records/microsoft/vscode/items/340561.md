# Issue #340561 — Agent edits to AGENTS.md / copilot-instructions.md rewrite the system prompt mid-conversation and invalidate the prompt cache

[https://github.com/microsoft/vscode/issues/340561](https://github.com/microsoft/vscode/issues/340561)

## Summary

Thanks for the detailed report. The source confirms that instruction-file contents are re-read on every prompt render and inlined into the system message. Only the customizations index is frozen, so editing AGENTS.md mid-conversation changes the system prompt prefix and breaks the prompt cache.

## Change summary

Instruction-file contents in the system message are not frozen mid-conversation, so editing them invalidates the prompt cache.

## Best solution

Extend the existing first-turn freeze in agentPrompt.tsx so the rendered instruction-file contents are snapshotted. Report later changes via the existing customizationsUpdate path in the latest user message, or at minimum keep the system message stable.

- **Trace:**

  > CustomInstructions in panel/customInstructions.tsx re-reads each instruction file through createElementFromURI on every render. The result goes into the SystemMessage via getAgentCustomInstructions in agentPrompt.tsx. getOrFreezeCustomizationsIndex stores only the index and tool references in CustomizationsIndexMetadata on the first turn. The freeze lives in the same metadata and cache-key mechanism. Do not change the index freeze or the customizationsUpdate semantics for the listing. - **Open decisions:**
