# Issue #336183 — Copilot agent host injects incomplete GIT_CONFIG_* environment tuple on Windows linked worktrees

[https://github.com/microsoft/vscode/issues/336183](https://github.com/microsoft/vscode/issues/336183)

## Summary

Well-diagnosed, concrete report: the reporter captured the actual defective GIT_CONFIG_COUNT/KEY/VALUE environment tuple the agent host injects (duplicate entries, two `core.fsmonitor` keys with no matching values), which would make Git calls unreliable inside a linked worktree on Windows. I could not locate the code that builds this env tuple in the OSS checkout (no `GIT_CONFIG_COUNT`/`safe.bareRepository`/`credential.interactive` hits under `src/` or `extensions/copilot`), so this needs to be routed to whoever owns that part of the agent host/Copilot git integration rather than closed from here.

## Change summary

On Windows with a linked Git worktree, the Copilot agent host sets GIT_CONFIG_COUNT=6 but only supplies values for 4 of the 6 indexed GIT_CONFIG_KEY_n entries (the two core.fsmonitor entries have no corresponding GIT_CONFIG_VALUE_n), leaving Git commands in the spawned agent process unreliable until the user manually sets the missing values.

## Best solution

Whoever owns the agent host's git-environment construction (likely inside the private chat-lib/agent runtime, not the visible OSS source) should either drop the duplicate/incomplete `core.fsmonitor` entries or emit a matching non-empty value for every `GIT_CONFIG_KEY_n`, and validate the indexed tuple is complete before spawning the agent process.
