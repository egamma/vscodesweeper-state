# Issue #346824 — Markdown preview editor and rendered Markdown diff never re-read a file whose change on disk was missed

[https://github.com/microsoft/vscode/issues/346824](https://github.com/microsoft/vscode/issues/346824)

## Summary

The stale-model recovery gap remains in current source: custom text editors reuse loaded contents without requesting a disk reload, and Markdown refresh renders that same cached document. Keep this report open because the related preview and diff reports do not establish a canonical covering its full scope.

## Change summary

Make Markdown preview editors and rendered diffs recover current disk contents after a missed file-watcher event, including on explicit refresh.

## Best solution

Restore clean-document disk reconciliation when custom text editors and rendered diffs are opened or revealed, and make explicit Markdown refresh recover missed changes without discarding unsaved edits. Preserve existing watcher coverage rather than requiring continuous watching of otherwise excluded files.

- **Validation:** Run both CLI-based scenarios from the issue in an isolated profile: after missed disk changes, reopening or revealing the preview and rendered diff, and invoking Markdown: Refresh Preview, must show current contents without a source-editor round trip. Add regression coverage with a retained clean model and a disk write that emits no watcher event; separately verify dirty buffers remain unchanged.
- **Behavior:**

  > A missed file-watcher event must not leave a clean Markdown preview or rendered diff permanently stale. Opening or revealing the editor again, or explicitly refreshing its preview, must recover the current disk contents without switching to source. Both original and modified diff resources are covered. Unsaved edits must remain intact; continuous live updates for unwatched files are outside this request.
- **Trace:**

  > CustomTextEditorModel.create uses ITextModelService.createModelReference, whose file-model resolution does not request reload; TextFileEditorModelManager therefore reuses an existing model without reading disk. MainThreadCustomEditors obtains both rendered-diff resources through this model path, and CustomEditorInput.resolve retains the existing custom model. MarkdownPreview.refresh ultimately calls workspace.openTextDocument, while ExtHostDocuments.ensureDocumentData returns an already-loaded document immediately. FileEditorInput.resolve differs by explicitly requesting an asynchronous reload. The missing recovery is confirmed from source, but the complete reveal lifecycle and a safe extension-to-core explicit-refresh path have not been traced sufficiently to bound an implementation. Preserve dirty-buffer semantics, virtual resources, and watcher policy; related https://github.com/microsoft/vscode/issues/344736 and https://github.com/microsoft/vscode/issues/343080 cover narrower symptoms.
