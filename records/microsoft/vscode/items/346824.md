# Issue #346824 — Markdown preview editor and rendered Markdown diff never re-read a file whose change on disk was missed

[https://github.com/microsoft/vscode/issues/346824](https://github.com/microsoft/vscode/issues/346824)

## Summary

Keep open: current source reuses loaded text models without checking disk when custom Markdown editors resolve, and Refresh Preview renders that same cached document. The report provides concrete reproductions for both preview and rendered diff; related stale-preview issues do not establish a canonical covering this recovery defect.

## Change summary

Recover current Markdown contents when opening, revealing, or explicitly refreshing previews and rendered diffs after a missed file-change event.

## Best solution

Bring custom text editor recovery into parity with text editors, including both rendered-diff inputs, and make explicit Markdown refresh recover clean documents from disk. Preserve unsaved edits and existing virtual-document behavior; continuous updates without watcher coverage are outside this recovery fix.

- **Behavior:**

Unsaved edits must remain intact, and continuous live updates where no watcher covers the file are not required by this change.
- **Trace:**

  > CustomTextEditorModel.create obtains an ITextModelService reference without reload; MainThreadCustomEditors.getOrCreateCustomEditorModel and CustomEditorInput.resolve also retain existing models directly.
