# Issue #172387 — Terminal ... menu doesn't promote action when there's only one action 

[https://github.com/microsoft/vscode/issues/172387](https://github.com/microsoft/vscode/issues/172387)

## Summary

This remains an accepted workbench action-bar improvement: current main still keeps a lone non-primary action in the overflow menu. The member-authored issue is parked in On Deck, and there is no factual fix or verified duplicate supporting closure.

## Change summary

Automatically show the sole overflow-menu action in a view's action bar and remove the redundant ellipsis menu.

## Best solution

Define consistent view-header behavior that promotes a lone secondary action without changing how menus containing multiple secondary actions are grouped, then cover the shared workbench action path with focused tests.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/views/viewMenuActions.ts`, `src/vs/workbench/browser/parts/views/viewPane.ts`, `src/vs/platform/actions/browser/menuEntryActionViewItem.ts`
- **Validation:** Add and run browser unit coverage for action grouping: one secondary action appears directly in the toolbar with no overflow entry, while zero or multiple secondary actions and existing primary-group classification retain their intended behavior.
- **Behavior:**

  > When a view title has exactly one action that would otherwise be placed in the ellipsis menu, that action is displayed directly in the action bar and the empty ellipsis affordance is absent. Views with multiple overflow actions continue to expose those actions through the menu, and explicitly primary actions retain their current ordering and visibility. Acceptance should cover action-set updates as context keys add or remove the sole secondary action.
- **Trace:**

  > ViewPane constructs ViewMenuActions in src/vs/workbench/browser/parts/views/viewPane.ts and forwards its primary and secondary arrays directly to WorkbenchToolBar in `setActions()`. ViewMenuActions in src/vs/workbench/browser/parts/views/viewMenuActions.ts delegates grouping to `getActionBarActions`, considering only `navigation` and configured `primaryActionGroups` primary. The shared classifier in src/vs/platform/actions/browser/menuEntryActionViewItem.ts preserves every other group in the secondary bucket regardless of its final size. No current branch promotes a sole secondary action. Preserve multiple-action overflow behavior, configured primary groups, separators, and submenu handling; the unresolved scope is whether this should become a contract for all view headers or only the terminal view.
- **Open decisions:**
