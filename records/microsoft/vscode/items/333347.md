# Issue #333347 — Highlighting text appears to unhighlighted when tooltip/pop up appear

[https://github.com/microsoft/vscode/issues/333347](https://github.com/microsoft/vscode/issues/333347)

## Summary

This looks like a real rendering-order defect, not a feature request: the hover-highlight decoration overlay paints on top of the selection overlay, so a semi-transparent 'must not be opaque' background (editor.hoverHighlightBackground) visually overrides the selection instead of blending under it as its own doc comment intends. Worth a maintainer/rendering-owner look rather than the community backlog-vote track it's currently on.

## Change summary

When a hover tooltip appears while dragging a text selection, the selected text's highlight visually disappears, fading to near the editor background color.

## Best solution

Have the editor rendering owner review the view-part paint order in src/vs/editor/browser/view.ts: `SelectionsOverlay` is added (and thus painted) before `DecorationsOverlay`, so the hoverHighlight decoration (editor.hoverHighlightBackground, a low-alpha color explicitly documented as 'must not hide underlying decorations') paints over the selection instead of under it. Either reorder/exempt the hover-highlight decoration from painting over active selection ranges, or confirm the composited color is intentional and close as as-designed with a rationale.
