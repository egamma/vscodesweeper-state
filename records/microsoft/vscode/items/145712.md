# Issue #145712 — For language-specific settings, modified settings should be shown first

[https://github.com/microsoft/vscode/issues/145712](https://github.com/microsoft/vscode/issues/145712)

## Summary

The requested modified-first ordering remains absent from the current settings search path. Keep this accepted request open, respecting the maintainer's distinction between category ordering with the Table of Contents visible and prioritization when it is hidden.

## Change summary

Prioritize settings explicitly modified for the selected language in language-filtered Settings UI results.

## Best solution

Provide modified-first ordering for language-filtered results when the Table of Contents is hidden, retaining unmodified settings below them and preserving category order when it is visible. Settle how that prioritization interacts with additional search text before implementation.

- **Behavior:**

  > Searching @lang:markdown should make settings explicitly modified for Markdown easy to find without hiding other applicable settings. In the maintainer-confirmed scope where the Table of Contents is hidden, those modifications should appear first. Global-only changes must not count as Markdown-specific changes, and visible-Table-of-Contents category ordering must remain unchanged. Acceptance should cover multiple settings targets and the agreed interaction with additional search text.
- **Trace:**

  > SettingsEditor2.triggerSearch parses the language filter and uses createFilterModel for filter-only searches; both filter-only and textual searches feed SearchResultModel in src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts. SearchResultModel.sortResults currently considers category order and relevance but not configured language overrides. inspectSetting already determines whether the selected language has an explicit override at the selected target, and SettingsTreeSettingElement uses that result for the modified tag. The @modified filter removes other settings rather than delivering the requested ordering. The maintainer limits the remaining request to the hidden-Table-of-Contents scenario at https://github.com/microsoft/vscode/issues/145712#issuecomment-1745613580. Preserve existing configuration-scope semantics, category navigation, and searches without a language filter; uncertainty starts at whether modified priority should override relevance when free text accompanies @lang.
- **Open decisions:**
  - When free text accompanies @lang with the Table of Contents hidden, should language-specific modifications rank ahead of more relevant unmodified matches, or should modified-first ordering apply only to filter-only searches?
