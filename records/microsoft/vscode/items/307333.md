# Issue #307333 — runCommands defined in keybindings.json stopped working in version 1.114.0

[https://github.com/microsoft/vscode/issues/307333](https://github.com/microsoft/vscode/issues/307333)

## Summary

Plausible regression: the quick pick accept/attach refactoring in 1.114 (commits 81a1a5ff617 and f42f9b10eaf) changed how acceptance works in the picker, which may have broken the fragile runCommands pattern of chaining gotoSymbol + acceptSelectedQuickOpenItem. Routing to the keybindings/quickinput area for investigation.

## Change summary

Using runCommands to chain workbench.action.gotoSymbol followed by workbench.action.acceptSelectedQuickOpenItem no longer executes the second command in 1.114.0.

## Best solution

Investigate whether the accept/attach refactoring in https://github.com/microsoft/vscode/commit/f42f9b10eaf or https://github.com/microsoft/vscode/commit/81a1a5ff617 changed timing or behavior of programmatic accept() calls when items haven't loaded yet. The root issue may be that gotoSymbol returns void synchronously, so runCommands can't await picker readiness — if that's the design, consider documenting it; if the accept used to fire late enough to catch items, restore that behavior.
