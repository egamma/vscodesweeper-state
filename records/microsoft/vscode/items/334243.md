# Issue #334243 — Support symlinks to be shown in multi-diff editor

[https://github.com/microsoft/vscode/issues/334243](https://github.com/microsoft/vscode/issues/334243)

## Summary

Freshly filed (same-day), no comments yet, but the underlying gap is verifiable in source: the git extension's quick-diff providers intentionally skip symbolic links, so a symlink can appear as a dirty/changed resource in the Agent Sessions changes view (SCM) while the multi-diff editor renders nothing for it.

## Change summary

Symlinked files that show as modified in the SCM/Agent Sessions changes list are silently skipped by the multi-diff editor, leaving an invisible dirty entry with no reviewable diff.

## Best solution

Decide, in the git extension's quickDiffProvider (extensions/git/src/quickDiffProvider.ts, lines ~35-40 and ~103-108) and the sessions changes multi-diff resolver, whether to render a symlink's target-path diff (even minimally, e.g. showing the link target changed) or to filter such resources out of the Agent Sessions dirty/changed count so the two views stay consistent — either resolves the 'invisible dirty file' confusion.
