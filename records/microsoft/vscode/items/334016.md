# Issue #334016 — Late aborted Copilot turn can wedge subsequent messages

[https://github.com/microsoft/vscode/issues/334016](https://github.com/microsoft/vscode/issues/334016)

## Summary

Team-authored, freshly filed regression with a detailed, reproduced root-cause analysis from a second maintainer (connor4312) pinpointing a race between abort cancellation and a replacement turn's idle handling in the Copilot runtime bridge (regressed between runtime 1.0.80 and 1.0.82-0); no fix has landed yet, so this stays open.

## Change summary

When a foreground turn is aborted while a background subagent is also in flight, a late `session.idle` (tagged `aborted: null` instead of `true` due to internal state reset) incorrectly clears the just-started replacement turn, wedging the chat session until the window is reloaded.

## Best solution

Fix the idle-tagging race in the Copilot agent-host bridge (likely around the deferred idle/abort-state handling in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts and copilotSessionWrapper.ts) so a deferred idle evaluated after a new turn starts is still correctly tagged as an aborted completion of the prior turn rather than clearing the new one.
