# Issue #334016 — Late aborted Copilot turn can wedge subsequent messages

[https://github.com/microsoft/vscode/issues/334016](https://github.com/microsoft/vscode/issues/334016)

## Summary

Team-authored, actively-diagnosed regression with a confirmed, consistent 3-run reproduction (connor4312) pinning the race to a specific abort/idle reset-ordering change between runtime 1.0.80 and 1.0.82-0; no fix has landed (the linked cross-provider PR #335981 is closed and unmerged), so this stays open per the team-authored hard keep-open rule.

## Change summary

When a foreground turn's abort races a concurrently-dispatched subagent cancellation and a replacement message is sent immediately, the deferred `session.idle` can land tagged `aborted: null` instead of `true` after the abort state resets, causing `onIdle` to wrongly treat it as authoritative completion and silently wedge the replacement turn (dropped deltas, no idle) until the window is reloaded.

## Best solution

Either make the vscode-side `onIdle` handler in copilotAgentSession.ts resilient to a stale/mistagged deferred idle (e.g. by tracking a turn/abort generation token instead of trusting the SDK's `aborted` flag alone), or fix the runtime's idle-tagging/reset ordering in @github/copilot-sdk so the deferred idle is evaluated before the abort state resets — a maintainer should decide which side owns the fix before implementation starts.

## Evidence

- **handler code:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:5685-5751 (`wrapper.onIdle`) only special-cases `e.data.aborted === true`; a falsy/null `aborted` on a stale deferred idle falls through to the generic 'complete the current turn' path at line 5750, matching the reported symptom exactly.
- **confirmed repro:** connor4312's comment (2026-09-02) gives a 5-step causal chain and a 3-run, fully consistent POC table: regression reproduces on runtime 1.0.82-0, does not on 1.0.80.
- **no fix landed:** The only related PR, https://github.com/microsoft/vscode/pull/335981, is closed and unmerged; jruales' 2026-09-22 comment explicitly says the Codex-side lead in https://github.com/microsoft/vscode/issues/334431 is a sibling issue, not proof of a shared cause or an additional repro.
- **dependency pin:** package.json:324 pins `copilotRuntimeVersion` (currently 1.0.87-unstable); the described regression window (1.0.80 vs 1.0.82-0) is inside this external runtime, so part of the fix may need to land upstream in @github/copilot-sdk rather than in this repo.
