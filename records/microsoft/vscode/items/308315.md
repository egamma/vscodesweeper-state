## Summary

Keep open: the reporter and another user confirm excessive startup CPU usage that stops when symlink following is disabled. That workaround does not establish a fix, and the related reports do not yet establish a shared root cause suitable for consolidation.

## Change summary

Prevent startup file discovery from sustaining excessive ripgrep CPU usage in workspaces containing multiple projects and symlinks.

## Best solution

Diagnose the startup file-search caller and traversed symlink targets, then address the runaway work while preserving legitimate symlink searches. Compare the reproduction with the ancestor-symlink traversal issue before deciding whether the fix belongs in VS Code's search orchestration or upstream ripgrep.

## Evidence

- **Observed resource usage:** https://github.com/microsoft/vscode/issues/308315 reports startup CPU saturation on Ubuntu 24.04.4 with Flatpak VS Code 1.113.0. Its process listing shows two bundled rg --files processes consuming 674% and 837% CPU, with accumulated CPU times of 43:18 and 53:01.
- **Confirmed workaround:** In the April 10–12 discussion at https://github.com/microsoft/vscode/issues/308315, DarionSCS recommends search.followSymlinks=false, the reporter confirms that it stops the malfunction, and DarionSCS confirms Copilot can remain enabled with that setting. The reporter describes opening the parent directory of multiple projects.
- **Current source boundary:** src/vs/workbench/contrib/search/browser/search.common.contribution.ts registers search.followSymlinks with default true and search.ripgrep.maxThreads with default 0. src/vs/workbench/services/search/common/queryBuilder.ts maps the symlink setting to ignoreSymlinks; src/vs/workbench/services/search/node/ripgrepFileSearch.ts:getRgArgs adds --follow unless ignoreSymlinks is set. This explains the workaround but does not prove which startup caller or symlink topology causes the excessive work.
- **Related ancestor-symlink defect:** https://github.com/microsoft/vscode/issues/336327 is open and reproduces startup CPU saturation by placing a symlink to / inside a workspace, triggering built-in task and activation scans.
