## Evidence

- **Remaining launcher defect:** src/vs/code/node/cli.ts:69-85 launches native CLI subcommands with ['ignore', 'pipe', 'pipe'] on Windows and forwards their output through Node. In cli/src/commands/output.rs:377-399, stdout_supports_utf8() deliberately treats pipes as UTF-8-capable, so the native process cannot detect the legacy console code page at the final destination.
- **Detached supervisor propagation:** cli/src/commands/agent_host.rs:669-685 forwards stdout_supports_utf8() through VSCODE_CLI_PARENT_STDOUT_SUPPORTS_UTF8 when daemonizing. Because the foreground native CLI itself receives a pipe from Node, this propagates the wrong terminal capability for the reported invocation.
- **Partially implemented behavior:** cli/src/commands/agent_host.rs:573-579 constructs the Manage hint from constants::APPLICATION_NAME. cli/src/commands/output.rs centralizes Unicode/ASCII selection, also used by agent_ps.rs, agent_logs.rs, and pager status output; the remaining gap is the launcher boundary, not absence of these helpers.
- **Reopened after initial fix:** https://github.com/microsoft/vscode/pull/333376 merged on 2026-08-31 and explicitly referenced this issue. The supplied discussion records a maintainer confirming continued reproduction on 2026-09-04 in 1.137.0-insider, so that initial fix does not justify closing this reopened report.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/335349 is OPEN with no merge commit. Its patch changes the Windows Node launcher to inherit standard I/O and guards forwarding when piped streams are absent; the issue author linked this PR in the supplied 2026-09-23 comment.
