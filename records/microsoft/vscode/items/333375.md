# Issue #333375 — Agent Host CLI output is garbled and shows the wrong management command on Windows

[https://github.com/microsoft/vscode/issues/333375](https://github.com/microsoft/vscode/issues/333375)

## Summary

There's already substantial UTF-8/ASCII detection machinery on main (utf8_or_ascii, GetConsoleOutputCP checks, an env var forwarding the foreground console's capability into the detached supervisor, and constants::APPLICATION_NAME used for the manage-command hint), but a contributor explicitly reconfirmed the mojibake on 1.137.0-insider after this issue was reopened — so whatever gap remains is unresolved on the exact build in scope, and a real version milestone (1.137.0) independently bars a close anyway.

## Change summary

On Windows consoles using a non-UTF-8 code page, Agent Host CLI banners/agent ps/agent logs emit raw UTF-8 decoration bytes that get mis-decoded, and the banner hardcodes the stable `code` command name instead of the running product's application name.

## Best solution

Needs a real Windows repro with a legacy console code page to find why `output::stdout_supports_utf8()` (cli/src/commands/output.rs) and its call sites in cli/src/commands/agent_ps.rs / agent_logs.rs still produce mojibake despite the existing utf8_or_ascii detection and the VSCODE_CLI_PARENT_STDOUT_SUPPORTS_UTF8 env-var handoff for the detached supervisor in cli/src/commands/agent_host.rs — likely a timing/handle issue (e.g. code page read before ANSI mode setup, or a path that bypasses the env-var handoff) rather than a missing implementation.
