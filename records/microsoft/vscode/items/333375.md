# Issue #333375 — Agent Host CLI output is garbled and shows the wrong management command on Windows

[https://github.com/microsoft/vscode/issues/333375](https://github.com/microsoft/vscode/issues/333375)

## Summary

Team-authored, reopened bug — a maintainer already tried to fix it once and it came back, so this needs an after-reopen fix before it can close. Tracing the code shows the UTF-8/ASCII detection and application-name fixes are partially in place, but I found a genuine remaining gap: one of the two supervisor-spawn paths doesn't forward the parent's console-capability env var, so encoding can still depend on which code path spawned the supervisor.

## Change summary

On Windows, Agent Host CLI banners and `agent ps`/`logs` output emit UTF-8 decorative characters that get mis-decoded by non-UTF-8 console code pages, and the banner hardcodes `code` instead of the actual product's `applicationName`.

## Best solution

Finish threading `output::PARENT_STDOUT_SUPPORTS_UTF8_ENV` through every supervisor-spawn call site — `spawn_supervisor_and_wait_ready` (used by `ensure_supervisor_running`/`spawn_dedicated_supervisor`) currently omits the `#[cfg(windows)]` env block that `daemonize_supervisor` already has — then re-verify the exact `agent host --tunnel` repro on a real Windows console with a non-UTF-8 code page before closing.
