# Issue #309661 — YAML support for VSCode tasks

[https://github.com/microsoft/vscode/issues/309661](https://github.com/microsoft/vscode/issues/309661)

## Summary

Feature request to allow YAML as an alternative format for tasks configuration files. A predecessor issue (#4851) was closed in 2016 with a clear product decision to stay with JSON, but the requester asks for that decision to be revisited. With 10 upvotes, this hasn't yet hit the 20-upvote backlog threshold, so it should stay open for the community process.

## Change summary

Allow VS Code task definitions to be written in YAML (tasks.yml) as a fallback when tasks.json is not found, enabling YAML anchors to reduce repetition.

## Best solution

This is a product-direction decision that a maintainer should weigh in on. The 2016 rationale (native JSON parser speed, TypeScript alignment, avoiding dual code paths/docs) still largely holds. If the team's position hasn't changed, this could be closed as *out-of-scope or *as-designed consistent with #4851. If the landscape has changed enough to revisit, it would need a design proposal covering schema validation, IntelliSense, and the fallback semantics.

## Vision fit

- **Fit:** rejected
- **Reason:** Adding a second configuration file format cuts against the 'lightweight and fast' value (dual parsing paths, dual docs) and the guardrail against configuration sprawl. The capability could live in an extension that pre-processes YAML into tasks.json.
- **Evidence:** Value: 'Out of the box, VS Code is a text editor: lightweight and fast.' Guardrail: requests that add configuration sprawl in the default product cut against the lean default experience.
