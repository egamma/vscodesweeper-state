# Issue #114319 — Add config option for image root in markdown preview

[https://github.com/microsoft/vscode/issues/114319](https://github.com/microsoft/vscode/issues/114319)

## Summary

Keep open: current Markdown preview still resolves root-relative images against the workspace root, not a configurable static-assets directory. This accepted Backlog request has 56 upvotes, and the maintainer explicitly requested a solution covering completions and link validation as well as preview rendering.

## Change summary

Allow Markdown image paths such as /image.png to resolve against a configured static-assets root without changing the source Markdown.

## Best solution

Provide consistent configurable asset-root resolution across Markdown preview, path completions, and link validation. Develop the shared resolution contract before revisiting the preview-only approach rejected in https://github.com/microsoft/vscode/pull/300913.

- **Behavior:**

  > A static-site project can retain its published root-relative Markdown image URLs while resolving them against a configured local assets directory. In the reported Hugo layout, /image.png must locate static/image.png when the configured root is static. Preview, image-path completions, and link validation must agree. Leaving the setting unset must preserve existing resolution, and ordinary relative paths and external URLs must remain unchanged.
- **Trace:**

  > MarkdownItEngine.#addImageRenderer in extensions/markdown-language-features/src/markdownEngine.ts delegates image rewriting to #toResourceUri, whose slash-prefixed branch joins the image path directly to the containing workspace folder. Configuration registrations in extensions/markdown-language-features/package.json expose no alternative image root; markdown.copyFiles.destination addresses file placement rather than this resolution path. MdLanguageClient.resolveLinkTarget in extensions/markdown-language-features/src/client/client.ts sends resolution requests to the Markdown language server, so the relevant behavior extends beyond the preview renderer. The closed, unmerged https://github.com/microsoft/vscode/pull/300913 attempted only preview rewriting; the maintainer required completions and validation support in https://github.com/microsoft/vscode/pull/300913#issuecomment-4042161615. The server-side resolution and configuration contract remain untraced, so planning must establish those consumers and their shared semantics before implementation. Preserve existing defaults and unrelated path handling; remote HTTP asset-root support mentioned later in the thread is not required to demonstrate the original local Hugo case.
- **Open decisions:**
  - Should the configured root apply only to image destinations, or to all root-relative Markdown links and media destinations? The original request concerns images, while the related baseUrl request includes broader resource handling.
