## Summary

Same underlying defect as the older, still-open https://github.com/microsoft/vscode/issues/324541: the NES doc-state cache lookup throws BugIndicatingError() when a streamed edit targets a document not found in either `projectedDocuments` or `xtabEditHistory`. Line numbers and surrounding function names differ only because the extension was refactored between 0.54.0 and 0.57.0+ (the lookup was extracted into `_rebaseAndCacheStreamedEdit`), but the throw site is identical.

## Change summary

Automated error-telemetry report: NES ("An unexpected bug occurred.") crash/error in the next-edit-suggestion streamed-edit rebase path, continuing across copilot-chat 0.57.0–0.60.0.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/324541 (open since 2026-07-06, same signature since extension 0.54.0). The real fix belongs in `createDocStateLookupMap`'s callback in extensions/copilot/src/extension/inlineEdits/node/nextEditProvider.ts (currently lines 131-163): when a streamed edit's target document isn't found in `projectedDocuments` or `xtabEditHistory`, it throws `BugIndicatingError()` (line 149) instead of returning a `NoNextEditReason`/undefined so the caller (`_rebaseAndCacheStreamedEdit`, lines 785-796, via `statePerDoc.get(streamedEdit.targetDocument)`) can bail out gracefully.
