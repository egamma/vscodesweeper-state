# Issue #36700 — Allow to open two distinct editors side by side in one group

[https://github.com/microsoft/vscode/issues/36700](https://github.com/microsoft/vscode/issues/36700)

## Summary

Keep open: current Split Editor in Group still duplicates the same editor, rather than letting users pair two distinct editors under one tab. The maintainer explicitly retained that broader request here; neither the preview-specific issue nor the newer Vim-style layout request replaces it.

## Change summary

Allow two distinct editors to share one tab, with horizontal or vertical layout and keyboard navigation between their panes.

## Best solution

Provide a supported, keyboard-accessible way to pair two distinct editors in one tab using the existing side-by-side editor infrastructure. Settle pairing and unpairing behavior without expanding this request into arbitrary nested editor grids.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorCommands.ts`, `src/vs/workbench/browser/parts/editor/editor.contribution.ts`, `src/vs/workbench/browser/parts/editor/sideBySideEditor.ts`, `src/vs/workbench/common/editor/sideBySideEditorInput.ts`, `src/vs/workbench/services/editor/browser/editorResolverService.ts`
- **Validation:** After the maintainer settles the interaction contract, manually pair foo.h and foo.cpp into one tab, switch to another tab and back, verify both files return together, edit and focus both sides, toggle horizontal/vertical layout, and unpair with dirty edits on either side without losing either file's changes. Preserve existing same-file split/join behavior; add targeted editor command/group tests for distinct-input pairing and the chosen unpairing contract.
- **Behavior:**

  > Users can view and edit two distinct files together under one tab without creating another editor group or entering a diff view. Switching away and back restores the pair, and keyboard navigation reaches both sides. Both existing split orientations remain available. Acceptance must cover independent editing, tab switching, and safe handling of dirty files when the pair is dissolved; arbitrary grids within a tab are outside this request.
- **Trace:**

  > registerSplitEditorInGroupCommands in src/vs/workbench/browser/parts/editor/editorCommands.ts currently constructs SideBySideEditorInput with the same editor twice, while joinEditorInGroup replaces the composite with its primary input. SideBySideEditorInput already accepts distinct inputs, EditorResolverService.doResolveSideBySideEditor resolves them independently, and SideBySideEditor.createEditors hosts two independent EditorPane instances. The missing supported workflow is selecting and combining distinct editors; current same-file joining does not establish what should happen to a distinct secondary editor. Preserve existing same-file split behavior and ordinary editor-group splitting. The maintainer retained two-editor pairing here in https://github.com/microsoft/vscode/issues/36700#issuecomment-915246880; preview-specific integration remains related work at https://github.com/microsoft/vscode/issues/22068, and full layout tabs are separate at https://github.com/microsoft/vscode/issues/143024.
- **Open decisions:**
  - What user-facing pairing workflow should be supported initially: choosing a second editor from Quick Open, combining two selected tabs, or both?
  - When a distinct-editor pair is joined or dissolved, should both files become separate tabs, or should one remain visible while the other is safely retained elsewhere?
  - Does the initial supported contract cover distinct text editors only, or also mixed editor types such as a text editor and a preview?
