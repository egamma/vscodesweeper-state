# Issue #336105 — Smart window reuse: seamlessly accept files/folders in multi-root workspace windows from external tools

[https://github.com/microsoft/vscode/issues/336105](https://github.com/microsoft/vscode/issues/336105)

## Summary

Real gap, but the report overstates it: findWindowOnFile in src/vs/platform/windows/electron-main/windowsFinder.ts already resolves multi-root workspace folders and reuses the window when a *file* under any workspace root is opened via CLI/desktop/link context (windowsMainService.ts line ~594) — so the `code file.ts:42:10` and `vscode://file/...` scenarios described should already work on current main. The remaining gap is narrower: opening a bare *folder* that is already a root of an open multi-root workspace still goes through `findWindowOnWorkspaceOrFolder`, which only matches exact configPath/folder-URI equality, not membership inside an existing workspace's roots (windowsMainService.ts lines 642, 674, 1464-1482).

## Change summary

Requests that external tools (CLI, error links, deeplinks) opening a file or folder belonging to an already-open multi-root workspace reuse that window instead of spawning a new one.

## Best solution

Extend `findWindowOnWorkspaceOrFolder` (or add a variant) in src/vs/platform/windows/electron-main/windowsFinder.ts to also match when the requested folder URI is one of the roots of an already-open multi-root workspace window, mirroring what `findWindowOnFile` already does for files; the file-open path already appears covered on main.

## Evidence

- **file-open already reuses multi-root windows:** src/vs/platform/windows/electron-main/windowsFinder.ts findWindowOnFile (lines 11-42) resolves the workspace and checks `resolvedWorkspace.folders.some(folder => isEqualOrParent(fileUri, folder.uri))`, and windowsMainService.ts line 594 calls it for OpenContext.DESKTOP/CLI/DOCK/LINK — so `code file.ts` and `vscode://file/...` for a file inside any workspace root should already reuse the window.
- **folder-open gap remains:** findWindowOnWorkspaceOrFolder (windowsFinder.ts lines 44-60) only compares exact configPath/folder-URI equality, with no check against a multi-root workspace's constituent folders; used at windowsMainService.ts lines 642, 674, 1464, 1473, 1482.
