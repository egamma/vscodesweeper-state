# Issue #336105 — Smart window reuse: seamlessly accept files/folders in multi-root workspace windows from external tools

[https://github.com/microsoft/vscode/issues/336105](https://github.com/microsoft/vscode/issues/336105)

## Summary

The exact capability requested — reusing an open multi-root workspace window when a CLI/`vscode://file` request targets a file inside one of that workspace's roots — is already implemented and covered by an existing unit test on current main; the issue's premise that this 'breaks' today doesn't match the source.

## Change summary

Requests that opening a file/folder from an external tool (CLI, error link, deeplink) reuse an already-open multi-root workspace window when the path is inside one of its roots, instead of spawning a new window.

## Best solution

No core change needed: `findWindowOnFile` in src/vs/platform/windows/electron-main/windowsFinder.ts already resolves the workspace's folders and matches the target file against them for the CLI/DESKTOP/DOCK/LINK contexts, and this exact scenario is asserted by the 'Workspace folder wins' test. If the reporter has a concrete case where reuse still fails (e.g. remote authority mismatch, untrusted workspace, `openFilesInNewWindow` setting), that would need a fresh, reproducible report.

## Evidence

- **multi-root match in findWindowOnFile:** src/vs/platform/windows/electron-main/windowsFinder.ts lines 14-32: for windows with an opened workspace, it resolves the workspace and checks `resolvedWorkspace.folders.some(folder => extUriBiasedIgnorePathCase.isEqualOrParent(fileUri, folder.uri))`, returning that window if the target file is inside any workspace root.
- **wired up for CLI/desktop/dock/link:** src/vs/platform/windows/electron-main/windowsMainService.ts lines 592-595: `findWindowOnFile` is invoked when `openConfig.context` is DESKTOP, CLI, DOCK, or LINK (i.e. `code <file>`, dock/file-manager opens, and `vscode://file/...` deeplinks) and `openFilesInNewWindow` is not forced.
- **default setting reuses windows:** src/vs/platform/windows/electron-main/windowsMainService.ts lines 1361-1400: `window.openFilesInNewWindow` defaults to 'off', so by default files open in an existing suitable window rather than a new one.
- **existing regression test for this exact case:** src/vs/platform/windows/test/electron-main/windowsFinder.test.ts, test 'Workspace folder wins': asserts that a file inside a multi-root workspace folder resolves to the window that has that workspace open.
