# Issue #344566 — Working progress is recomputed over the whole response for every tool part while rendering

[https://github.com/microsoft/vscode/issues/344566](https://github.com/microsoft/vscode/issues/344566)

## Summary

Keep open: the reported trace identifies repeated whole-response progress computation, and current source still queues an independent update for each notification. The completed-response guard exists, but why it did not prevent the measured work remains unresolved.

## Change summary

Avoid repeatedly recomputing working progress across an entire large response while its tool parts render.

## Best solution

Make progress recomputation bounded per response update burst while preserving live confirmation and activity changes. Establish why the restored response reaches this computation despite the completion guard, and ensure completed responses incur no unnecessary progress scans.
