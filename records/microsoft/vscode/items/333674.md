# Issue #333674 — Clicking away during in-place rename of chat tab will loose the changes

[https://github.com/microsoft/vscode/issues/333674](https://github.com/microsoft/vscode/issues/333674)

## Summary

The requested behavior remains missing on current main: leaving an in-place chat-tab rename explicitly cancels the edit, while Enter commits it and Escape already cancels it. This team-authored, Backlog-accepted feature request must remain open.

## Change summary

Commit an edited nested chat-tab title when focus leaves the rename input, while retaining Escape as an explicit cancellation path.

## Best solution

Make focus loss preserve a valid changed chat-tab title while Escape remains the explicit way to cancel. Before implementation, decide whether the same behavior should apply to the matching session-header rename interaction for consistency.

- **Trace:**

Existing tests in src/vs/sessions/test/browser/chatCompositeBar.test.ts exercise rename entry and input event isolation but not completion behavior. Keep chat switching, tab closing, drag behavior, empty-title handling, and provider rename semantics outside the scope.
