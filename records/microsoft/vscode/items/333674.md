# Issue #333674 — Clicking away during in-place rename of chat tab will loose the changes

[https://github.com/microsoft/vscode/issues/333674](https://github.com/microsoft/vscode/issues/333674)

## Summary

Confirmed in the current source: the inline chat-tab rename input explicitly cancels on blur by design (`finish(false)` on the BLUR listener), discarding the typed title exactly as described. This is a real, narrow UX defect worth fixing, not a close candidate — the item is also team-authored, which bars any judgment close anyway.

## Change summary

Clicking away from an in-progress chat-tab rename discards the typed title instead of committing it, unlike pressing Enter.

## Best solution

In `_startTabEditing` (chatCompositeBar.ts) and the equivalent session-title rename in sessionHeader.ts, change the BLUR handler to call `finish(true)` (commit) instead of `finish(false)` (cancel), keeping Escape as the only explicit-cancel path — mirroring how VS Code's other inline rename widgets (e.g. the Explorer) behave.
