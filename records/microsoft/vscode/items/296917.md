# Issue #296917 — GitHub Enterprise Subscription Not Recognized in VSCode Private Marketplace Login

[https://github.com/microsoft/vscode/issues/296917](https://github.com/microsoft/vscode/issues/296917)

## Summary

Keep open and classify as a bug. Maintainers confirmed that a GitHub Enterprise subscription should be sufficient, while current main still denies personal GitHub accounts whose eligibility comes from enterprise membership rather than a Copilot SKU.

## Change summary

Allow personal GitHub accounts belonging to an active GitHub Enterprise organization to access a configured Private Marketplace without a Copilot license.

## Best solution

Private Marketplace eligibility should recognize an authoritative GitHub Enterprise membership or subscription entitlement independently of Copilot licensing, while preserving the existing Copilot SKU and GitHub Enterprise Server paths.

## Plan brief

- **Likely files:** `src/vs/workbench/services/accounts/browser/defaultAccount.ts`, `src/vs/base/common/defaultAccount.ts`, `src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts`, `src/vs/workbench/services/extensionManagement/test/electron-browser/extensionGalleryManifestService.test.ts`
- **Validation:** Add a targeted marketplace account test covering a personal github.com account with an active GitHub Enterprise entitlement and no Copilot SKU; it must become eligible, while an account with neither entitlement remains denied and the existing Copilot Business eligibility test continues to pass.
- **Behavior:**

  > A personal github.com account belonging to an active GitHub Enterprise organization can connect to a configured VS Code Private Marketplace without a Copilot license. An account with neither an eligible Copilot SKU nor GitHub Enterprise entitlement remains denied. Existing Copilot Business/Enterprise and GitHub Enterprise Server access behavior must remain unchanged.
- **Trace:**

  > On current main, GitHubGalleryAccountProvider.checkAccess in src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts accepts only an access SKU or IDefaultAccount.enterprise. DefaultAccountProvider constructs that flag in src/vs/workbench/services/accounts/browser/defaultAccount.ts from the authentication-provider kind or an underscore in the account label, neither of which represents ordinary personal-account membership in a GitHub Enterprise organization. The issue supplies multiple matching accounts and a maintainer explicitly confirms that GitHub Enterprise-only access is intended. Investigation must establish where an authoritative enterprise-subscription signal is available before bounding the implementation. Preserve Copilot SKU eligibility, GitHub Enterprise Server authentication, Microsoft-provider handling, and denial for genuinely ineligible accounts. Related issue https://github.com/microsoft/vscode/issues/281250 concerns on-premises GitHub Enterprise and is not the same observable case.

## Evidence

- **maintainer expectation:** Maintainers state in https://github.com/microsoft/vscode/issues/296917 that Private Marketplace access should work with an active GitHub Enterprise subscription and subsequently assigned the issue for investigation.
- **current source:** At current main commit dd7687527a42277a9625f06391880cb5aaa4fc83, src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts:142-150 grants GitHub access only for a configured Copilot SKU or when IDefaultAccount.enterprise is true.
- **root cause:** src/vs/workbench/services/accounts/browser/defaultAccount.ts:900-908 sets IDefaultAccount.enterprise from the authentication provider or an underscore in the account label; it does not derive the flag from membership of a GitHub Enterprise organization. A personal github.com account with no Copilot SKU therefore reaches AccessDenied.
- **independent confirmations:** The report at https://github.com/microsoft/vscode/issues/296917 contains logs from multiple clean personal accounts and later independent confirmations showing that GitHub Enterprise-only users are denied while Copilot Enterprise users can browse the same marketplace.
- **canonical search:** https://github.com/microsoft/vscode/issues/281250 is older but concerns GitHub Enterprise Server/on-premises authentication and does not report the same personal-account GitHub Enterprise subscription symptom, so it does not meet the stronger duplicate bar for this re-reviewed issue.
