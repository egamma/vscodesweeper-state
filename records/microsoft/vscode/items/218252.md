# Issue #218252 — Missing theme variables for test coverage highlight background

[https://github.com/microsoft/vscode/issues/218252](https://github.com/microsoft/vscode/issues/218252)

## Summary

Decline close (out-of-scope) gated off: the issue sits in the Backlog milestone — the owner already triaged it as accepted work. Original assessment: The reported highlights belong to the third-party Jest extension, not VS Code's built-in coverage renderer. Its formatter supplies literal background colors, so adding core testing theme variables would not make these highlights themeable.

## Change summary

Allow theme authors to customize the uncovered and partially covered line backgrounds displayed by Jest: Toggle Coverage.

## Best solution

The Jest extension should expose theme color contributions or consume suitable existing testing colors for its coverage decorations. Its existing jest.coverageColors setting provides a user-level color override, but theme-level integration belongs in jest-community/vscode-jest.

AbstractFormatter.ts in the same directory returns configured overrides or literal red/yellow RGBA values rather than VS Code theme colors.
- **Existing extension capability and remaining gap:** https://github.com/jest-community/vscode-jest/blob/master/README.md#coveragecolors documents jest.coverageColors with uncovered, covered, and partially-covered overrides. This allows settings-level customization, but does not itself provide theme-contributed color identifiers, so it is a workaround rather than full coverage of the theme author's request.
- **Core capability check:** Current src/vs/workbench/contrib/testing/browser/theme.ts registers testing.coveredBackground, testing.uncoveredBackground, and testing.uncoveredBranchBackground; browser/media/testing.css consumes the coverage background variables. These control core coverage rendering, not the Jest extension's independently constructed decorations.
