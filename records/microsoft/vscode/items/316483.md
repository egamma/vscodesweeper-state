# Issue #316483 — Agent terminal history does not respect checkpoints

[https://github.com/microsoft/vscode/issues/316483](https://github.com/microsoft/vscode/issues/316483)

## Summary

Keep this accepted checkpoint bug open. The reporter confirmed it on the then-latest release, and although current main truncates provider history during checkpoint restoration, no fixing commit or test establishes that regenerated terminal context excludes commands from discarded turns.

## Change summary

Restoring an agent checkpoint leaves later terminal commands in the terminal-history context supplied to subsequent requests.

## Best solution

Reproduce this against the current Copilot Agent Host path, then ensure checkpoint restoration truncates both the provider transcript and any terminal context reconstructed for the next request. Add coverage proving a command executed after the checkpoint cannot appear in the next request after restoration.

- **Likely files:** `src/vs/platform/agentHost/node/agentSideEffects.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/test/node/copilotAgent.test.ts`
- **Validation:** Run an Agent Host Copilot scenario that executes a uniquely identifiable terminal command after checkpoint A, restores checkpoint A, sends another prompt, and asserts that the serialized provider request contains neither that command nor its output while retaining terminal context from turns before A.
- **Behavior:**

  > Restoring a checkpoint must make the next agent request reflect the conversation and terminal state at that checkpoint. Terminal commands and output produced only in discarded turns must not appear in the request's context, while terminal context from retained turns remains available. Acceptance requires a uniquely identifiable post-checkpoint command to be absent after restore and an earlier command to remain present.
- **Trace:**

  > Checkpoint restoration currently reaches AgentSideEffects in src/vs/platform/agentHost/node/agentSideEffects.ts, which dispatches truncateChat to the addressed provider. CopilotAgent.truncateChat in src/vs/platform/agentHost/node/copilot/copilotAgent.ts resolves the SDK event boundary, and CopilotAgentSession.truncateAtEventId in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts invokes rpc.history.truncate and removes later database turns. The unresolved boundary is where terminal history is assembled or regenerated for the next provider request: the source reviewed here proves transcript truncation, but not that this derived context observes the same boundary. Preserve normal terminal history outside restored branches and do not alter filesystem checkpoint semantics tracked separately by https://github.com/microsoft/vscode/issues/282069.
