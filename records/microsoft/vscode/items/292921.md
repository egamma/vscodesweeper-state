## Change summary

Allow users to sort the Manage Language Models table by displayed properties such as name, context size, and cost or request multiplier.

## Best solution

Provide accessible ascending and descending sorting from the model table's sortable columns while preserving understandable provider grouping. Coordinate the detailed interaction and persistence semantics with the broader model-management UX exploration at https://github.com/microsoft/vscode/issues/317128.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts`, `src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts`, `src/vs/workbench/contrib/chat/test/browser/chatManagement/chatModelsViewModel.test.ts`, `src/vs/base/browser/ui/table/table.ts`, `src/vs/base/browser/ui/table/tableWidget.ts`
- **Validation:** Add focused ChatModelsViewModel tests covering ascending and descending name, context-size, and cost ordering within provider groups, plus an interaction/accessibility test confirming mouse and keyboard header activation updates the order and announced sort direction; run `./scripts/test.sh --grep "ChatModelsViewModel|ChatModelsWidget"`.
- **Behavior:**

  > The Manage Language Models view should let users order models by meaningful displayed columns, including name, context size, and the applicable pricing or request-cost value. Both ascending and descending order must be discoverable and keyboard accessible, with the active column and direction announced to assistive technology. Sorting must remain predictable when models are grouped by provider and when a model lacks the selected metadata. Filtering, hiding, and model actions must continue to operate on the same model set.
- **Trace:**

  > ChatModelsWidget in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsWidget.ts declares the visible WorkbenchTable columns but provides no header interactions. ChatModelsViewModel.groupModels in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts currently performs fixed alphabetical sorting within each provider group. The generic ITableColumn and ColumnHeader contracts in src/vs/base/browser/ui/table/table.ts and tableWidget.ts have no sorting event or state, so the uncertainty starts at whether sorting belongs in shared table infrastructure or in this management surface. Keep the boundary to management-view ordering: do not alter model-picker ranking, provider membership, filtering, visibility, or configuration semantics. The broader UX discussion is https://github.com/microsoft/vscode/issues/317128, but it does not settle this request's interaction details.
- **Open decisions:**
  - Should selecting a sort column reorder models only within each provider group, or flatten and sort the complete model catalog across providers?
  - Which displayed columns are sortable, and where should models with missing values appear in ascending and descending order?
  - Should the selected sort column and direction persist when the management editor is reopened, or reset to name ordering each time?

## Evidence
