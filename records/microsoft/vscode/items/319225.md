# Issue #319225 — GitHub Copilot "Restore Checkpoint" isn't persisted after switching sessions

[https://github.com/microsoft/vscode/issues/319225](https://github.com/microsoft/vscode/issues/319225)

## Summary

Keep this open as the older canonical report for an unresolved Agent Host protocol limitation: restoring a checkpoint changes only local in-memory state until another message is submitted, so switching sessions can rehydrate the discarded tail.

## Change summary

Persist the selected Restore Checkpoint history boundary when switching away from and back to a chat session.

## Best solution

Complete the durable chat-history head and atomic workspace checkout contract tracked by https://github.com/microsoft/agent-host-protocol/issues/353, then adopt it in the Agent Host checkpoint path so restoration is persisted immediately rather than deferred until the next submitted turn.

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSnapshotController.ts keeps the restored boundary only in `_currentCheckpointIndex`; `restoreSnapshot` moves this in-memory cursor and restores files but does not persist or dispatch a protocol history boundary.
- **deferred truncation:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts dispatches `ChatTruncated` only while preparing the next submitted turn, when it detects that the chat model has fewer requests than protocol state. Switching sessions before another submission therefore leaves the protocol tail intact.
- **confirmed symptom:** The newer https://github.com/microsoft/vscode/issues/326450 reports the same observable sequence—restore a checkpoint, switch sessions, switch back, and see the removed history return. A maintainer identifies the missing durable turn pointer and links the protocol work.
- **upstream dependency:** https://github.com/microsoft/agent-host-protocol/issues/353 is open and proposes a durable `headTurnId` plus an atomic history/workspace checkout operation, which is the protocol capability needed to persist this state without waiting for another turn.
