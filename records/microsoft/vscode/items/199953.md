# Issue #199953 — Aux window: should change the cursor style within the dropping area

[https://github.com/microsoft/vscode/issues/199953](https://github.com/microsoft/vscode/issues/199953)

## Summary

Keep open: native drag feedback still has no identified solution that preserves cross-window editor dragging without affecting other applications. This issue is the established tracking point for the desktop symptom and related tab-reordering reports; existing settings do not deliver the requested feedback.

## Change summary

Show appropriate drag cursor feedback when an editor can be dropped to create a floating window, including the related forbidden-cursor feedback reported during tab reordering.

## Best solution

Provide accurate feedback for supported editor drops while preserving native cross-process dragging and avoiding unintended text or file transfers to other applications. First establish a feasible approach across the affected platforms and distinguish the internal tab-reordering symptom from desktop drop feedback.

- **Behavior:**

  > Dragging an editor to a location that creates a floating window should provide feedback consistent with that supported action rather than implying that releasing it has no effect. Related reports describe forbidden feedback while reordering tabs at valid positions; establish whether that symptom shares the desktop mechanism. Cross-window placement and normal tab reordering must continue to work, and floating-window dragging must not inject text or files into other applications. Acceptance includes desktop drops, internal reordering, cross-window placement, background-terminal drops, and the documented Alt toggle on affected platforms.
- **Trace:**

  > MultiEditorTabsControl's drag-start observer in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts sets native effectAllowed to copyMove, records local editor transfers, and calls doFillResourceDataTransfers with isNewWindowOperation. EditorTabsControl in src/vs/workbench/browser/parts/editor/editorTabsControl.ts derives that mode from workbench.editor.dragToOpenWindow and Alt; its drag-end flow creates an auxiliary editor part after checking the release location. fillEditorsDragData in src/vs/workbench/browser/dnd.ts suppresses standard text, download, and URI-list transfers for this mode while retaining Code-specific editor data. The maintainer's constraint at https://github.com/microsoft/vscode/issues/199953#issuecomment-1838694912 is to preserve native dragging without making background applications consume dummy content; cross-process placement must also remain intact. Source inspection establishes the transfer boundary, not the actual native cursor result or a safe way to change it. Planning should begin with platform reproduction and feasibility investigation; the Linux internal-tab report at https://github.com/microsoft/vscode/issues/250637 must not be assumed to have the same cause without tracing it.
