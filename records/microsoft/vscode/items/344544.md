The Markdown editor's Mermaid guest still lacks pan/zoom integration and host-toolbar actions. Keep this maintainer-authored request open; existing preview controls and related issues do not cover the requested surface.

- **Behavior:**

  > Mermaid blocks in the experimental Markdown editor support zoom in, zoom out, reset, and toggled drag-to-pan through the host toolbar beside existing block actions. Navigation works inline and in full view, and toolbar actions are keyboard accessible with exposed toggle state. Existing mouse-navigation and controls-visibility settings apply consistently with the preview, or any intentional difference is documented. Rendering, editing, theme updates, and sizing remain intact.
- **Trace:**

  > The guest in extensions/mermaid-markdown-features/preview-src/markdownEditor/index.ts connects through WebEditorClient, renders into a detached staging element, swaps the diagram into main, and reports natural height; it never installs DiagramManager. The preview entry point uses DiagramManager.setup, whose shared implementation owns transforms, interaction state, internal controls, and resizing. Its existing internal toolbar and resize handle cannot be assumed to match the editor's host-owned chrome. The provider supplies presentation preferences, and the Markdown editor entry point constructs the embedded editor factory. https://github.com/microsoft/vscode/pull/344399 explicitly leaves toolbar pan/zoom for later; https://github.com/microsoft/vscode-packages/pull/396 supplies presentation negotiation but not this action contract. The remaining design boundary is the web-editors/markdown-editor package integration outside this checkout. Preserve preview/notebook behavior, current natural sizing, and error recovery; do not add a second toolbar inside the guest.
- **Open decisions:**
  - What public, capability-negotiated contract should guests use to expose host-toolbar actions, including invocation and toggle state, while remaining compatible with older hosts?
  - Should mouse-navigation and controls-visibility settings retain exactly their preview semantics in the host toolbar, or should the editor document a deliberate difference?
