# Issue #162639 — Wrong AppData folder

[https://github.com/microsoft/vscode/issues/162639](https://github.com/microsoft/vscode/issues/162639)

## Summary

Keep open: current source still drops the UNC server when converting an extension's global storage URI into a filesystem path. The discussion contains independent confirmations, and the Electron/sandbox hypothesis does not explain away this identifiable core path-conversion defect.

## Change summary

Preserve redirected Windows AppData UNC paths when exposing extension global storage locations, rather than resolving them onto the local drive.

## Best solution

Ensure local extensions receive usable global storage locations that retain the UNC server and share, while preserving local-drive, remote, and web storage behavior. Treat this as a VS Code extension-host storage defect rather than assuming an upstream sandbox restriction.
