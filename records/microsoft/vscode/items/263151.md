# Issue #263151 — Improvements to Copilot Chat Usability (History Navigation & Mentions)

[https://github.com/microsoft/vscode/issues/263151](https://github.com/microsoft/vscode/issues/263151)

## Summary

Current main addresses the history-navigation and dual-prefix portions, but copying a sent prompt still uses plain text and drops the structured file-reference metadata. This issue remains the canonical open report for that meaningful usability gap.

## Change summary

Improve chat prompt editing and reuse by preserving drafts during history navigation, retaining file references when copying prompts, and accepting both `#` and `@` reference prefixes.

## Best solution

Preserve the existing safe history navigation and dual-prefix completions, and make copying a previously sent request retain enough structured attachment data to recreate its file references when pasted into another chat input without degrading portable plain-text copying.

- **Behavior:**

  > Copying a previously sent prompt containing file references and pasting it into another chat input should recreate those references with their original workspace-relative identities, including when files share a basename. The clipboard must still provide useful portable plain text outside VS Code, and Paste as Text must not create attachments. Existing draft-preserving history navigation and both `#` and `@` completion prefixes must remain unchanged.
- **Trace:**

  > History navigation is already guarded at the exact first/last editor positions in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, and current drafts are overlaid before navigation. Dual-prefix file/reference completion is already implemented and tested in chatInputCompletions.ts and chatInputCompletions.test.ts. The remaining path starts in CopyItemAction in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts: sent requests expose structured variables through IChatRequestViewModel.variables, but the action writes only stringifyItem output as plain text. CopyAttachmentsProvider in chatPasteProviders.ts already defines the receiving structured attachment format, but its copy preparation reads only from a live IChatPasteTarget. Preserve ordinary response copying, external plain-text portability, Paste as Text behavior, and attachment identity; do not reopen the resolved history-key or mention-prefix behavior. Related reports: https://github.com/microsoft/vscode/issues/249523 and https://github.com/microsoft/vscode/issues/286266.
- **Open decisions:**
  - Should Copy on a sent request always include private structured attachment data alongside portable plain text, or should retaining references be exposed as a distinct copy action so ordinary Copy remains text-only?
