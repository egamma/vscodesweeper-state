# Issue #331919 — Primary action on automations is to delete while it is archive on regular sessions

[https://github.com/microsoft/vscode/issues/331919](https://github.com/microsoft/vscode/issues/331919)

## Summary

Team-authored report (author alexdima is a VS Code core member) flagging an inline toolbar-action inconsistency in the Agents/Sessions window: automation items surface Delete as the primary inline action while regular sessions surface Archive. This is fresh (1 day old), has no fix yet, and team-authored issues can only be closed with a citable fix commit referencing this issue — none exists, so it stays open.

## Change summary

The primary (inline) toolbar action shown on automation session items is Delete, whereas regular session items show Archive as the primary action, an inconsistent UX across the two item types.

## Best solution

In src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts, decide whether automations should gain an Archive-equivalent action or whether Delete-as-primary is intentional for automations (which only declare `supportsDelete`, not archive, per src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts and the automationsView test fixtures), then align the `SessionItemToolbarMenuId` 'navigation' group registrations for BaseArchiveSessionAction/DeleteSessionAction so the same semantic slot is used consistently between sessions and automations.

## Evidence

- **archive action registration:** BaseArchiveSessionAction registers its icon in the SessionItemToolbarMenuId 'navigation' group (order 1) only when SessionIsArchivedContext is false (src/vs/sessions/contrib/sessions/browser/views/sessionsViewActions.ts lines ~868-887).
- **delete action registration:** DeleteSessionAction only registers in SessionItemContextMenuId ('1_edit', order 4), gated on SessionSupportsDeleteContext, not in the toolbar navigation group directly (same file, lines ~1012-1023) — so the discrepancy likely stems from automation capabilities lacking an archive-equivalent, causing a different action to end up in the visible slot.
- **automation capabilities:** Automation/agent-host sessions are created with capabilities such as `{ supportsMultipleChats: false, supportsDelete: true }` with no archive capability (src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:1068, and automationsView.fixture.ts:123), consistent with Delete surfacing instead of Archive for automations.
