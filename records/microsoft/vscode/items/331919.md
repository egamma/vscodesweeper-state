# Issue #331919 — Primary action on automations is to delete while it is archive on regular sessions

[https://github.com/microsoft/vscode/issues/331919](https://github.com/microsoft/vscode/issues/331919)

## Summary

Team-authored (alexdima), filed hours ago and tagging @benibenj for input — a real UX inconsistency between automation cards and the sessions list, but too fresh for any fix to have landed and a team-authored item can't be closed on judgment alone.

## Change summary

Automation cards in the Sessions window only offer Run/Delete buttons, so delete is the primary destructive action, while regular sessions default to archive as the primary (less destructive) action, creating an inconsistent UX between the two surfaces.

## Best solution

Decide (with @benibenj) whether automations should gain an archive-style primary action to match sessions' convention, or whether delete-as-primary is intentional for automations since they don't currently model an archived state — then align src/vs/sessions/contrib/sessions/browser/views/automationsView.ts with the sessions list's action ordering in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts.
