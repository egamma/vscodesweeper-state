# Issue #152042 — Should diff editor revert icon change?

[https://github.com/microsoft/vscode/issues/152042](https://github.com/microsoft/vscode/issues/152042)

## Summary

Keep open for a diff-editor design decision: current source still uses different revert icons in split and inline views. Staging and tooltips now address secondary requests, but the central icon question remains; the verified matching reports are newer and cannot replace this re-reviewed item.

## Change summary

Make the diff editor's partial-revert affordance clearer, potentially by reusing the inline diff's discard icon.

## Best solution

Agree on icon semantics that distinguish reverting Git changes from copying between arbitrary files, then apply that decision consistently across diff-editor revert surfaces. Preserve the existing staging actions and use the newer reports as supporting UX evidence.

- **Trace:**

- **Open decisions:**
  - Should all partial-revert controls use the discard/undo glyph, or should Git diffs and generic file comparisons use different glyphs to distinguish reverting changes from copying original content into modified content?
