# Issue #331853 — Unbounded concurrent reads in prompt discovery exhaust file handles (EMFILE) and hang the window

[https://github.com/microsoft/vscode/issues/331853](https://github.com/microsoft/vscode/issues/331853)

## Summary

Well-diagnosed bug, confirmed in the current source: three discovery paths in promptsServiceImpl.ts still use unbounded `Promise.all` over every discovered prompt/agent/hook file, which can exhaust file handles (EMFILE) on profiles with many customization files, cascading into terminal/extension-host unresponsiveness. The author says a fix PR bounding these with `Limiter` is already open, so this should route to review of that PR rather than an automatic fix.

## Change summary

computeSlashCommandDiscoveryInfo, computeAgentDiscoveryInfo, and computeHooks fan out unboundedly over all discovered files via Promise.all, exhausting OS file handles (EMFILE) on large profiles and hanging the window.

## Best solution

Bound the three call sites (computeSlashCommandDiscoveryInfo, computeAgentDiscoveryInfo, computeHooks in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts) with a `Limiter`, matching the existing pattern in src/vs/platform/agentHost/node/agentService.ts (`new Limiter<boolean>(4)`); review and land the author's linked PR. The separate CachedPromise non-cancelling-invalidation issue is correctly deferred as a follow-up.
