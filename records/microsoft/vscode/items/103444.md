# Issue #103444 — Git - gutters don't show on filenames that have changed case

[https://github.com/microsoft/vscode/issues/103444](https://github.com/microsoft/vscode/issues/103444)

## Summary

Still reproduces on main: the URI identity cache (`IUriIdentityService.asCanonicalUri`) retains the old casing after a case-only file rename, so the quick-diff system feeds git a path whose case doesn't match git's tracked name, suppressing gutter decorations. No fix has landed.

## Change summary

Git gutter decorations do not appear for files whose name casing has been changed (e.g. `counter.jsx` → `Counter.jsx`), because the cached canonical URI keeps the old casing.

## Best solution

The URI identity cache in `IUriIdentityService` needs to invalidate or update its canonical URI when it observes a case-only rename via file events. The fix likely spans `src/vs/platform/uriIdentity/common/uriIdentityService.ts` (cache invalidation on rename events) and possibly the text-model layer that first resolved the URI. The quickDiff model at `src/vs/workbench/contrib/scm/browser/quickDiffModel.ts` line 91 consumes the stale canonical URI; fixing the source (the identity service) is preferable to working around it downstream. This is a cross-cutting concern — the same stale-casing bug likely affects any feature that compares a cached URI against a case-sensitive external tool.
