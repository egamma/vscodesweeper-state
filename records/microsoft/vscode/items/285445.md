# Issue #285445 — Chat input field strips backslash before dot in Windows paths (e.g., 

[https://github.com/microsoft/vscode/issues/285445](https://github.com/microsoft/vscode/issues/285445)

## Summary

The submitted prompt remains intact, but current main still renders request bubbles as Markdown, so Markdown escape processing visually removes the backslash before a dot. This accepted UX polish should remain open while maintainers decide whether request bubbles should become plain text or retain selected Markdown behavior.

## Change summary

Make submitted chat requests display Windows paths verbatim instead of visually consuming backslashes used as Markdown escapes.

## Best solution

Ensure the rendered request bubble faithfully represents the text sent to the model, while preserving required chat decorations and attachment UI. A maintainer should first decide whether that means plain-text request bodies or narrower escaping that retains intentional Markdown formatting.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownDecorationsRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentMarkdownRenderer.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`
- **Validation:** Add a ChatListRenderer browser test that renders a request containing `$env:USERPROFILE\.ssh\` and `C:\Users\allan\.ssh\id_ed25519`, then asserts the request bubble's textContent preserves every backslash; also assert the chosen formatting behavior for intentional Markdown and existing chat decorations.
- **Behavior:**

  > A submitted chat request must display Windows and PowerShell paths with exactly the same visible path characters the user entered, including a backslash immediately before a dot. The request sent to the model must remain unchanged. Agent, slash-command, variable, and attachment decorations must continue to render, and intentional Markdown behavior must follow the maintainer's chosen request-formatting policy.
- **Trace:**

  > On current main, ChatListItemRenderer.renderChatRequest in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts obtains a string from getRequestMarkdown, wraps it in MarkdownString, and renders it through ChatMarkdownContentPart. ChatMarkdownDecorationsRenderer.convertParsedRequestToMarkdown in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownDecorationsRenderer.ts copies ChatRequestTextPart text directly into that Markdown source. ChatContentMarkdownRenderer in src/vs/workbench/contrib/chat/browser/widget/chatContentMarkdownRenderer.ts excludes strings containing backslashes from its plain-text fast path, so marked interprets `\.` as an escaped dot and omits the backslash visually. The maintainer confirms at https://github.com/microsoft/vscode/issues/285445#issuecomment-3700213501 that the underlying model request is already verbatim; do not change prompt serialization, parsing, or delivery. Keep attachment and request-decoration rendering in scope, but do not alter response Markdown rendering.
- **Open decisions:**
  - Should user-authored request bodies render entirely as plain text, or should request bubbles retain intentional Markdown while escaping literal path characters such as backslashes?

## Evidence

- **current source path:** On current main, src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts renderChatRequest/getRequestMarkdown passes request text through new MarkdownString and ChatMarkdownContentPart rather than rendering it as literal text.
