- **Behavior:**

Explicit exit, existing shell history configuration, and terminal persistence behavior must continue working.
- **Trace:**

TerminalProcess.shutdown in src/vs/platform/terminal/node/terminalProcess.ts:462-484 ultimately calls _kill, which invokes node-pty.IPty.kill() at line 403. This establishes the relevant boundary but does not prove whether each shell currently flushes history.
- **Windows behavior has changed:** package.json declares node-pty ^1.2.0-beta.15. Its https://github.com/microsoft/node-pty/blob/v1.2.0-beta.15/src/windowsPtyAgent.ts kill method treats bundled ConPTY differently: it destroys the input socket and closes the PTY, whereas the non-DLL branch also kills enumerated processes. VS Code defaults terminal.integrated.windowsUseConptyDll to true in src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:495-499. The original 2022 process-kill hypothesis therefore cannot be assumed to describe the current default path.
- **Partial improvements are not a complete fix:** The thread points to https://github.com/microsoft/vscode/issues/181508 as a recent improvement, but that report concerns a later Bash shutdown regression and contains no confirmation resolving this entire issue. Current Git Bash profiles already include --login and -i in src/vs/platform/terminal/node/terminalProfiles.ts:290, addressing the older interactive-shell concern without establishing history persistence on shutdown.
- **History surfaces differ:** https://github.com/microsoft/vscode/issues/250564#issuecomment-2940222312 explains that Terminal: Run Recent Command stores previous-session commands independently in VS Code storage. That capability and terminal buffer revival do not establish that Bash or Zsh writes its own history file when VS Code exits.
