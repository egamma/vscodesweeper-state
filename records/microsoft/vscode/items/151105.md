# Issue #151105 — Some shells don't remember history

[https://github.com/microsoft/vscode/issues/151105](https://github.com/microsoft/vscode/issues/151105)

## Summary

Still reproduces on main: the terminal shutdown path in `terminalProcess.ts` force-kills shell processes (after a 5s timeout on Windows, immediately on other platforms) without sending a graceful SIGHUP/exit that would let bash/zsh flush history to disk. The `-i` flag fix from commit 245c0c781c9 was a partial improvement but explicitly noted it does not fix the issue. The underlying problem remains.

## Change summary

Shells like Git Bash and zsh lose command history when VS Code closes because the terminal process is killed before the shell can write its history file.

## Best solution

The terminal shutdown path (`src/vs/platform/terminal/node/terminalProcess.ts`) needs to send a graceful shutdown signal (e.g. SIGHUP on Unix, or close the conpty cleanly on Windows) and allow shells time to run their exit hooks before force-killing. This likely also requires node-pty changes to avoid killing all console process list entries before the shell can flush. The workaround (`PROMPT_COMMAND='history -a'` for bash, `SHARE_HISTORY` for zsh) is documented but doesn't address the root cause.
