# Issue #286478 — Copilot sending backtick followed by a number is always seen as vscodecontentref

[https://github.com/microsoft/vscode/issues/286478](https://github.com/microsoft/vscode/issues/286478)

## Summary

Valid bug report from a team member about .NET generic type notation (e.g. List`1) being rendered as a vscodecontentref link. Part of a cluster of contentref rendering issues; needs investigation to determine whether the fix in f340d3616a8 (PR #296201, which added `isInsideCodeContext` guarding) covers this specific case, or whether a separate fix is needed.

## Change summary

When Copilot outputs .NET generic type notation containing a backtick followed by a number (e.g. List`1), it renders as a clickable `http://_vscodecontentref_/1` link instead of plain text.

## Best solution

Investigate whether the backtick-number pattern is mishandled by the linkifier (extensions/copilot/src/extension/linkify/common/) or the chat markdown rendering pipeline (src/vs/workbench/contrib/chat/common/widget/annotations.ts). The fix in f340d3616a8 (Feb 2026) added `isInsideCodeContext` to suppress contentref links inside code spans — verify whether that covers this case. If not, the linkifier's inline-code accumulation logic or the file-path linkifier's regex may need hardening to avoid false-positive matches on backtick-number sequences.
