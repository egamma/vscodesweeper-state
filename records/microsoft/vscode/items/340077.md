# Issue #340077 — "This extension is disabled for this workspace by the user." - No way to re-enable?

[https://github.com/microsoft/vscode/issues/340077](https://github.com/microsoft/vscode/issues/340077)

## Summary

A dedicated re-enable path exists for exactly this case — the Copilot Chat extension intentionally hides the generic Enable/Disable (Workspace) actions and shows AI-specific ones instead, and the 'Enable AI Features (Workspace)' action is designed to be enabled precisely when the extension is EnablementState.DisabledWorkspace with the workspace AI setting set to true, which is the state this report describes.

## Change summary

After disabling GitHub Copilot Chat for the workspace via the Extensions view Cog menu, the user could not find a way to re-enable it; the Chat UI disappeared and the normal Enable/Disable buttons seemed unavailable.

## Best solution

Keep the existing mechanism (the Cog menu's 'Enable AI Features (Workspace)' action, gated in EnableAIFeaturesInWorkspaceAction.update() in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts) as the supported re-enable path; the real gap is discoverability, which is already the subject of the open UX-improvement issue https://github.com/microsoft/vscode/issues/337891.

  > Thanks for the report — sorry for the confusing experience. For the built-in Copilot Chat extension, disabling/enabling for the workspace goes through a dedicated action rather than the generic one: open the Extensions view (Ctrl+Shift+X), find 'GitHub Copilot Chat', click the gear/cog icon on that row, and choose **Enable AI Features (Workspace)**. That's the counterpart to 'Disable AI Features (Workspace)', which is what 'Disable Extension for Workspace' maps to for this extension — the generic Enable/Disable (Workspace) buttons are intentionally hidden for Copilot Chat. We agree the discoverability here could be better; that's being tracked more broadly in https://github.com/microsoft/vscode/issues/337891. Closing as working as designed, but please reopen if the 'Enable AI Features (Workspace)' option isn't appearing for you.

## Evidence

- **special-cased chat extension:** ManageExtensionAction.getActionGroups() in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts (around line 1379) checks `isChatExtension` and, when true, shows EnableAIFeaturesGloballyAction/EnableAIFeaturesInWorkspaceAction and DisableAIFeaturesGloballyAction/DisableAIFeaturesInWorkspaceAction instead of the generic Enable/DisableForWorkspaceAction — so the Cog menu for Copilot Chat never offers the plain 'Enable (Workspace)' button, by design.
- **generic actions explicitly disabled for chat ext:** EnableForWorkspaceAction.update() and EnableGloballyAction.update() (lines ~1672, ~1707) both return early with `this.enabled = false` when `ExtensionIdentifier.equals(this.extension.identifier.id, this.productService.defaultChatAgent?.chatExtensionId)` — confirming the plain re-enable buttons are intentionally unavailable for this extension.
- **working re-enable path traced:** EnableAIFeaturesInWorkspaceAction.update() (line ~1865) sets `this.enabled = true` when `inspect.workspaceValue === true` (the workspace AI-disabled setting, which DisableAIFeaturesInWorkspaceAction sets when the user disables it for the workspace) — this is exactly the state described in the report, so the action should be present and clickable in the same Cog menu.
- **related UX work:** https://github.com/microsoft/vscode/issues/337891 (team-authored, assigned) tracks improving the UX for configuring plugin/extension enabled-disabled state across global and workspace scope — the kind of discoverability gap this report surfaces, but it targets the Agents Customization window rather than this classic Extensions view flow, so it isn't a direct duplicate.
