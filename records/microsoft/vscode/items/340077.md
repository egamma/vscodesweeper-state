# Issue #340077 — "This extension is disabled for this workspace by the user." - No way to re-enable?

[https://github.com/microsoft/vscode/issues/340077](https://github.com/microsoft/vscode/issues/340077)

## Summary

The reporter's immediate problem is resolved (the 'Extensions: Enable All Extensions for this Workspace' command and the per-extension Enable dropdown in the Extensions view both already restore a workspace-disabled extension), but the underlying discoverability gap they raise is real and unaddressed on main: the 'disabled for this workspace by the user' status message has no inline way to re-enable, unlike the sibling 'disabled by dependency' status which does show a link.

## Change summary

After disabling Copilot Chat for the workspace via the chat/extension menu, there is no obvious UI to re-enable it — the contributed Chat menu disappears along with the extension, and the Extensions-view status text for 'disabled for this workspace' offers no link back.

## Best solution

Add an inline enable affordance to the 'This extension is disabled for this workspace by the user' status message (src/vs/workbench/contrib/extensions/browser/extensionsActions.ts around line 3078), mirroring the existing 'Show Dependencies' link pattern for DisabledByExtensionDependency (line 3042) — but a maintainer should decide whether this generalizes to all workspace-disabled extensions or is special-cased for the chat extension (which already has separate EnableAIFeaturesInWorkspaceAction logic), and what command the link should invoke since no command is currently registered for that action.
