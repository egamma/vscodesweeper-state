# Issue #330402 — [Source Control] Feature Request: Identify commit hashes in commit descriptions in commit hover tips and make them link to the referenced commit

[https://github.com/microsoft/vscode/issues/330402](https://github.com/microsoft/vscode/issues/330402)

## Summary

The requested navigation remains missing: commit-message hovers link GitHub issue references, but do not automatically link referenced commit hashes. Keep this open as a feature request; no older canonical covering the same observable behavior was found.

## Change summary

Recognize short and full commit hashes in commit-message hovers and make them open the referenced commit's changes inside VS Code.

## Best solution

Support repository-aware commit-reference navigation in the built-in Git hover experience, preserving existing issue links and message formatting. Product review should establish how ambiguous or unavailable commit references behave before implementation.

## Evidence

- **current message-link behavior:** extensions/git/src/historyProvider.ts passes commit messages through provideSourceControlHistoryItemMessageLinks before constructing history-item hovers. In extensions/github/src/historyItemDetailsProvider.ts, GitHubSourceControlHistoryItemDetailsProvider.provideMessageLinks replaces only ISSUE_EXPRESSION matches for #N and GH-N issue references; it does not recognize short or full commit hashes.
- **existing capability does not cover the request:** extensions/git/src/hover.ts:getHoverCommitHashCommands creates an Open Commit link using git.viewCommit for the hovered commit itself. appendContent renders the message without detecting embedded hashes. extensions/git/src/commands.ts:viewCommit can retrieve a specified commit, but the inspected Git/GitHub command and configuration registrations expose no automatic commit-message hash-linking capability; git.commitShortHashLength controls hash display rather than reference detection.
- **hover integration boundary:** extensions/git/src/hover.ts:getHistoryItemHover places message content and command actions in separate MarkdownString objects, with enabledCommands assigned only to the actions object. Local command links embedded in message content therefore require deliberate integration, not merely substituting hash text with markdown.
