# Issue #258605 — Confirmation experience is heavy when rerunning multiple cells

[https://github.com/microsoft/vscode/issues/258605](https://github.com/microsoft/vscode/issues/258605)

## Summary

Keep open: the notebook execution tool still accepts and confirms one cell per invocation, so the requested one-confirmation rerun remains missing. This team-authored improvement has neither a verified fixing commit nor an older canonical issue covering the same symptom.

## Change summary

Allow an agent-requested sequence of notebook cells to be confirmed together instead of requiring a separate confirmation for every cell.

## Best solution

Provide a clearly scoped approval for a multi-cell notebook execution sequence while preserving execution order and existing error and cancellation expectations. Decide the user-visible batch approval contract before extending the notebook tool.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`, `extensions/copilot/src/extension/tools/node/runNotebookCellTool.tsx`, `extensions/copilot/src/platform/notebook/vscode/notebookServiceImpl.ts`, `extensions/copilot/test/e2e/notebookTools.stest.ts`
- **Validation:** With default manual approvals, use a fresh Python kernel and three dependent code cells; ask the agent to rerun the prerequisite sequence after the later cell fails. Verify one approval covers exactly the displayed sequence, execution follows notebook order, rejection runs none of that sequence, and unrelated later execution still requires approval. Include failure and cancellation cases and preserve the existing single-cell and markdown-cell selection checks.
- **Behavior:**

  > When a later notebook cell fails because prerequisite cells have not run, asking the agent to rerun those prerequisites currently produces a separate confirmation for each cell. The desired experience allows the user to approve the intended sequence together without enabling blanket auto-approval. Acceptance should demonstrate one clearly scoped confirmation, ordered execution, no execution after rejection, and unchanged approval behavior outside the approved sequence. Existing single-cell execution must continue to work.
- **Trace:**

  > RunNotebookCellTool in extensions/copilot/src/extension/tools/node/runNotebookCellTool.tsx resolves a scalar cellId, prepares a confirmation for that cell, and invokes NotebookService.runCells with a one-cell range. The manifest in extensions/copilot/package.json exposes the same scalar contract. The underlying runCells implementation in extensions/copilot/src/platform/notebook/vscode/notebookServiceImpl.ts already forwards a range to notebook.cell.execute, so range execution exists below the tool boundary. The existing output collection and execution-summary wait are also single-cell-specific. extensions/copilot/test/e2e/notebookTools.stest.ts covers individual cell selection, including a three-cell request, but does not establish grouped approval semantics. Preserve default manual approval outside the explicitly authorized sequence and existing single-cell behavior; automatic inference or execution of prerequisites is not required by the central request. The unresolved boundary is what user-visible sequence a single approval authorizes, not whether notebook commands can execute ranges.
- **Open decisions:**
  - Should one approval authorize a single explicitly displayed contiguous cell range, or also a displayed list of individually selected cells that may be noncontiguous?
