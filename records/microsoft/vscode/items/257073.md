# Issue #257073 — Bug: tab to fix indentation not working because intellisense

[https://github.com/microsoft/vscode/issues/257073](https://github.com/microsoft/vscode/issues/257073)

## Summary

Valid, acknowledged NES/Tab-vs-indent polish issue. A team member confirmed it's in the backlog, it already carries the right labels (polish, NES, NES-ux), and the On Deck milestone is appropriate. The existing `_tabShouldIndent` heuristic in `inlineCompletionsModel.ts` doesn't cover the paste-then-indent workflow well enough. Keep open for the team to address.

## Change summary

Tab key is hijacked by inline/NES suggestions when the user is trying to indent pasted code, forcing a double-tab workflow.

## Best solution

Improve the `_tabShouldIndent` heuristic in `src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts` to better detect paste-then-indent and multi-line selection indentation scenarios, so Tab inserts indentation instead of accepting/jumping to an NES suggestion. Issue #275108 (NES unusable without mouse) is related but distinct — that one covers keyboard-only NES navigation more broadly. Both should be considered together in the Tab-key de-confliction work.
