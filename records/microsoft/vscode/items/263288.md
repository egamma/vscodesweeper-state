End with a focused widget/list test covering disposal of an offscreen edited row followed by cancellation.
- **Behavior:**

  > Cancelling request editing must leave the original sent request in the chat transcript, even when keyboard navigation has scrolled that request outside the virtualized viewport. Its text, position, and subsequent edit affordance must remain intact. Validate with the reported reduced-height, repeated-Tab, and click-to-cancel sequence.
- **Trace:**

  > The report and maintainer confirmation establish the original failure, but it has not been reconfirmed against current main. ChatWidget.startEditing attaches the inline input to the request row and tracks editing state; ChatListItemRenderer.disposeElement emits onDidDispose when that edited row leaves the viewport; ChatWidget's onDidDispose listener re-homes the input before cancelEditing eventually calls finishedEditing. Current code additionally holds auto-scroll and preserves template mappings while editing, so the plan must first determine whether the failure remains and which lifecycle transition loses the request. Keep the scope to sent-request editing and transcript virtualization; queued Agent Host delivery races in https://github.com/microsoft/vscode/issues/336466 are distinct.
