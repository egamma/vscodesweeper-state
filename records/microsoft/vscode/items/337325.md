# Issue #337325 — Agents Window: deleted worktree remains selectable and creates a failed session

[https://github.com/microsoft/vscode/issues/337325](https://github.com/microsoft/vscode/issues/337325)

## Summary

Team-authored, freshly filed bug with clear repro steps and a video; the code confirms the underlying gap (no existence check filters stale worktree entries out of the workspace picker), so this stays open regardless of the team-authored protection rule — there's no fix commit to cite.

## Change summary

A deleted worktree remains selectable in the Agents Window workspace picker; submitting a prompt against it creates a session that immediately fails with SessionWorkingDirectoryMissingError instead of being filtered out beforehand.

## Best solution

Filter stale/missing worktree entries out of the recent-workspace list in the sessions workspace picker (or validate existence before session creation), so users can't select a path that no longer exists; likely lives in src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts alongside the existing folder-exists check.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/localAgentHostSessionsProvider.ts`, `src/vs/platform/agentHost/node/shared/worktreeIsolation.ts`
- **Validation:** A test asserting a recent-workspace/worktree entry whose folder no longer exists on disk is excluded (or visibly disabled) in the workspace picker's item list, and that submitting a session against it does not leave a persistent failed session entry.
- **Behavior:**

  > Worktree entries that no longer exist on disk should not remain selectable in the Agents Window repository/workspace picker — they should be filtered out or clearly disabled. Submitting a prompt against a missing working directory should not create a persisted, failed session that has to be manually marked done; the user should get an immediate, actionable error instead.
- **Trace:**

  > The picker already validates existence for manually browsed paths (sessionWorkspacePicker.ts:1387-1395, `fileService.exists` + 'Path does not exist' dialog) but the recent-workspace/worktree items assembled from `recentWorkspaceEntries` (around lines 1564-1586) skip that check. Separately, session creation goes through to WorktreeIsolation (src/vs/platform/agentHost/node/shared/worktreeIsolation.ts ~1011/1026) which throws SessionWorkingDirectoryMissingError only after the session object already exists, so the failure surfaces as a persisted failed session rather than being caught earlier. Do not touch the existing manual-path exists-check or the error class itself — this is about closing the earlier gap for the recent-entries path and reconsidering whether the failure should be surfaced before persisting a session record. Related: https://github.com/microsoft/vscode/issues/336620 (broader worktree UX, does not cover this case).
- **Open decisions:**
  - Should stale worktree entries be silently removed from the picker's recent list, or shown but disabled with an explanatory tooltip?
  - Should existence be checked synchronously as the picker renders (may need to stat many recent entries) or lazily on selection/submit?
  - When a session does fail with a missing working directory, should it still be auto-marked done/cleaned up instead of requiring the user to dismiss it manually?
