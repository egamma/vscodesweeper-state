# Issue #257335 — The `"smart"` value for `editor.AcceptSuggestionOnEnter` should invoke auto-import actions always

[https://github.com/microsoft/vscode/issues/257335](https://github.com/microsoft/vscode/issues/257335)

## Summary

Keep open: current source exposes a plausible smart-Enter eligibility gap for lazily resolved import edits, but the Python provider's exact path remains unconfirmed. The supplied steps suffice to retest; inspection of current main does not establish that the behavior reported in 1.102.1 has been fixed.

## Change summary

Accept an auto-import completion with smart Enter when it adds an import, even if its insertion text matches the typed identifier.

## Best solution

Make smart-Enter eligibility reflect a completion's import text edits while preserving newline insertion for genuinely unchanged suggestions. First establish whether the reported Python completion supplies those edits eagerly, during resolution, or through a command.

- **Behavior:**

  > With smart Enter enabled, accepting an auto-import suggestion should add its import even when the identifier already matches the suggestion's insertion text. An ordinary completion that makes no textual change should continue to allow Enter to insert a newline. Reproduce the Python os example first, then verify the confirmed provider behavior and existing snippet and Tab acceptance.
- **Trace:**

  > SuggestController computes MakesTextEdit in the widget.onDidFocus listener and the Enter keybinding requires that context key. Eager additionalTextEdits and snippet insertion rules already count as changes, but commands do not. SuggestWidget starts asynchronous resolution before emitting focus; its resolution callback rerenders with focus events suppressed, while CompletionItem.resolve merges potentially new edits into the existing item. This makes delayed edits a concrete candidate, but the Python completion payload has not been inspected, matching the unresolved question at https://github.com/microsoft/vscode/issues/257335#issuecomment-3377131781. Preserve immediate completion acceptance, ordinary smart-mode newline behavior, and existing additional-edit application; do not assume every arbitrary completion command represents an import.
