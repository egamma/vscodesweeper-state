# Issue #258587 — Terminal Chat Participant should know about shell version

[https://github.com/microsoft/vscode/issues/258587](https://github.com/microsoft/vscode/issues/258587)

## Summary

Terminal chat receives the active shell type, but the inspected prompt path does not provide explicit shell or REPL version metadata. Keep this accepted, team-authored request open; the existing subshell support only partially covers the ask, and no qualifying canonical or referenced fix was established.

## Change summary

Give terminal chat reliable context about the active shell or REPL, including its version.

## Best solution

Provide terminal chat with trustworthy active-runtime identity and version context, distinguishing the current REPL from its parent shell. First settle whether this should use only observable session information or also discover versions when that information is absent.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/terminalIntent.ts`, `extensions/copilot/src/extension/prompts/node/panel/terminal.tsx`, `extensions/copilot/src/platform/terminal/common/terminalService.ts`, `extensions/copilot/src/platform/terminal/vscode/terminalServiceImpl.ts`, `extensions/copilot/src/platform/terminal/vscode/terminalBufferListener.ts`
- **Validation:** Add prompt-construction checks for supplied runtime identity/version and unavailable-version cases. Manually enter a Python REPL with a known version, invoke terminal inline chat, and ask which runtime and version are active; confirm it distinguishes the REPL from its parent shell, does not invent unavailable versions, and continues to generate REPL-appropriate commands.
- **Behavior:**

  > Terminal chat should identify the active shell or REPL and accurately use its version when that information is available. Entering a Python REPL must not leave the answer describing only the parent shell. Acceptance should cover known-version and unavailable-version sessions, with no fabricated version and no regression to parent-shell command suggestions.
- **Trace:**

  > TerminalIntentInvocation.buildPrompt in extensions/copilot/src/extension/intents/node/terminalIntent.ts obtains terminalShellType from ITerminalService and passes it with the OS into TerminalPrompt. TerminalServiceImpl delegates shell detection to getActiveTerminalShellType in extensions/copilot/src/platform/terminal/vscode/terminalBufferListener.ts, which reads state.shell or infers an executable name, without version metadata. TerminalPrompt includes shell identity and TerminalLastCommand; the latter can expose command output, but a version banner is only incidental context. The original work documented by https://github.com/microsoft/vscode/issues/258274 and https://github.com/microsoft/vscode/issues/254462 establishes REPL-appropriate suggestions, not version awareness. Preserve that existing behavior and keep richer command-success/failure history outside the initial scope unless the maintainer explicitly includes it. The uncertainty begins at how trustworthy version information is obtained and what the product does when it is unavailable; no runtime behavior was executed during this read-only review.
- **Open decisions:**
  - Should terminal chat use only version information already observable in the active session, or may it initiate runtime-version discovery when that information is absent?
  - When the active runtime is known but its version is unavailable, should chat report that limitation or guide the user through obtaining the version?
