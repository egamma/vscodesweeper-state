# Issue #269518 — Hitting undo after code completion should signal that completion was not wanted

[https://github.com/microsoft/vscode/issues/269518](https://github.com/microsoft/vscode/issues/269518)

## Summary

A real completion UX gap remains on main: immediate undo does not influence repeated commit-character acceptance. Keep this Backlog request open under discussion because a maintainer identified a plausible adaptive-setting design.

## Change summary

Treat an immediate undo of a commit-character completion as negative feedback so the same unwanted behavior is not repeatedly imposed.

## Best solution

Use the existing suggestion edit-source metadata to recognize repeated immediate undos, then offer a lightweight prompt to disable `editor.acceptSuggestionOnCommitCharacter` or another deliberately designed mitigation. The behavior belongs around the suggest controller and undo handling, with care not to suppress valid completion items silently.

## Evidence

- **current source:** On current main, src/vs/editor/contrib/suggest/browser/suggestCommitCharacters.ts accepts the active item whenever its commit character is typed and `editor.acceptSuggestionOnCommitCharacter` is enabled; it retains no immediate-undo or rejected-item state.

- **partial workaround:** src/vs/editor/common/config/editorOptions.ts exposes `editor.acceptSuggestionOnCommitCharacter`, but this global switch disables the behavior rather than learning from an immediately undone completion.
- **maintainer direction:** The discussion at https://github.com/microsoft/vscode/issues/269518 includes a maintainer-supported design direction: annotate smart edits and suggest changing the corresponding setting after repeated undos.
