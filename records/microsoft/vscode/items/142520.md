# Issue #142520 — Opening a terminal in Multi-root workspace appends cwd option for new terminal. 

[https://github.com/microsoft/vscode/issues/142520](https://github.com/microsoft/vscode/issues/142520)

## Summary

Still reproduces on main: `resolveWorkspaceFolderCwd` applies the workspace-level `terminal.integrated.cwd` setting to every folder in the multi-root picker, so when that setting resolves to an absolute path (e.g. `${workspaceFolder:Build}`), all picker entries collapse to the same CWD regardless of which folder the user selects. The bug is real, localized, and unfixed.

## Change summary

In a multi-root workspace with `terminal.integrated.cwd` set to a workspace-folder variable, the "New Terminal" folder picker ignores the user's folder selection and always opens in the configured CWD.

## Best solution

Fix `resolveWorkspaceFolderCwd` (or the call site in the `TerminalCommandId.New` action) so that when the user explicitly picks a workspace folder, the `terminal.integrated.cwd` override is either scoped correctly per-folder or bypassed for the picker — matching the behavior of the `NewWithProfile` action which already works. Related issue https://github.com/microsoft/vscode/issues/189166 covers a remote-specific variant of the same root cause and should be considered together.
