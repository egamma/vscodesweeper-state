# Issue #336557 — Touch long-press context menus flash-close on Android Chromium: four interacting hide paths with no Android exemption (iOS only)

[https://github.com/microsoft/vscode/issues/336557](https://github.com/microsoft/vscode/issues/336557)

## Summary

Well-researched report with precise line citations that all check out on current main — the iOS-only exemption in contextview.ts and the unconditional blur-hide in contextMenuHandler.ts are exactly as described. This is a real, actionable Android-touch bug that should be routed to the workbench/context-menu owners rather than closed.

## Change summary

On Android Chromium (touch, coarse pointer), long-press context menus flash-close within ~10-50ms due to four cascading hide paths (viewport-resize relayout hide, window-blur hide from the native selection toolbar, duplicate showContextView calls, and post-open focus-steal blur) that only have an iOS exemption today.

## Best solution

Extend the existing `platform.isIOS` touch exemption in `ContextViewHandler.layout()` (contextview.ts L329) to Android with a coarse-pointer check, and make the window BLUR handler in contextMenuHandler.ts (L100) tolerant of transient blur from the Android system selection toolbar; also look at deduping the dual context-menu synthesis in `List.onContextMenu` (listWidget.ts ~L1476), which is already tracked partly by #332619/#331838.
