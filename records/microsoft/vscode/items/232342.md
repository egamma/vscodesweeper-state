# Issue #232342 — Insiders API Change: no NotebookData class in NotebookSerializer.serializeNotebook handed over (only same Interface)

[https://github.com/microsoft/vscode/issues/232342](https://github.com/microsoft/vscode/issues/232342)

## Summary

The confirmed regression remains on current main: the remote-save path passes a structural object rather than a NotebookData instance. Keep this open under notebook API discussion despite the reporter's extension-side workaround.

## Change summary

NotebookSerializer.serializeNotebook no longer consistently receives an object satisfying `data instanceof vscode.NotebookData`.

## Best solution

Decide whether NotebookData runtime identity is an API guarantee; if so, construct an extHostTypes.NotebookData in ExtHostNotebookController's save path, otherwise explicitly document that serializers receive structural data and must not use instanceof.
