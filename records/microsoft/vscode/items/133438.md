# Issue #133438 — Enable picking relative files from quick open

[https://github.com/microsoft/vscode/issues/133438](https://github.com/microsoft/vscode/issues/133438)

## Summary

Keep this accepted request open: Quick Open still resolves relative paths against workspace roots, not the active file's directory, and does not provide the requested directory-only browsing. The verified related issues do not establish an older canonical covering the same observable behavior.

## Change summary

Allow Quick Open to resolve ./ and ../ relative to the active file and restrict suggestions to the corresponding directory.

## Best solution

Provide explicit active-file-relative navigation in Quick Open while preserving ordinary workspace-wide search. Plan the directory-browsing behavior and its interaction with history and symbol results before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/searchQuickAccess.contribution.ts`
- **Validation:** In a workspace containing src/file1.ts, src/file2.ts and a root-level file2.ts, activate src/file1.ts and verify that Quick Open ./file2.ts selects src/file2.ts. Verify that . and .. list only files in the selected current or parent directory, including when unrelated history entries exist. Confirm that unprefixed workspace search, absolute paths and line/symbol navigation retain their existing behavior; repeat the relative-path checks in a multi-root workspace.
- **Behavior:**

  > Quick Open should support paths relative to the file active when navigation starts. With src/file1.ts active, ./file2.ts should identify src/file2.ts rather than a same-named file at the workspace root. Entering . or .. should restrict file suggestions to the current or parent directory respectively, without unrelated history results leaking into that scope. Ordinary unprefixed file search should remain workspace-wide.
- **Trace:**

  > AnythingQuickAccessProvider in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts currently routes file queries through doFileSearch, which merges workspace-wide search with getRelativePathFileResults. The latter resolves against every workspace folder and accepts exact files only; it neither uses the active editor as its base nor enumerates directories. doGetPicks separately assembles history and optional symbol results, so the requested restriction must be considered across the displayed picker, not only exact-file lookup. workbench.action.quickOpen is registered in searchQuickAccess.contribution.ts. Preserve ordinary search, absolute-path handling and existing line/symbol navigation; changing global fuzzy-query normalization is not established as necessary. The related normalization issue https://github.com/microsoft/vscode/issues/139845 is distinct. The trace establishes the gap, but not the intended navigation contract for directories containing subdirectories or subsequent directory traversal.
- **Open decisions:**
  - Should directory-scoped results show only immediate files, or also selectable subdirectories that allow continued navigation within Quick Open?

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts:771–806, getRelativePathFileResults, resolves query.original through folder.toResource for each workspace folder and accepts only stat.isFile results. With src/file1.ts active, ./file2.ts is therefore checked against workspace roots rather than src; a directory query does not enumerate its children.
- **Workspace search and history remain unscoped:** In anythingQuickAccess.ts, doFileSearch combines workspace-wide getFileSearchResults with workspace-relative exact-file results; doGetPicks independently includes editor history and optional symbol results. There is no ./ or ../ branch limiting these result sources to the active file's directory.
