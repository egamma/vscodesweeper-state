# Issue #77861 — [folding] Preserve folded ranges on revert

[https://github.com/microsoft/vscode/issues/77861](https://github.com/microsoft/vscode/issues/77861)

## Summary

Keep open for design discussion: current main preserves folds through ordinary edits and folding-provider changes, but it has no explicit mechanism for matching collapsed regions across a file replacement or reload from disk. No older issue with the same observable revert symptom was found.

## Change summary

Preserve applicable collapsed folding ranges when Git revert replaces the contents of an open file.

## Best solution

Preserve collapsed state for fold regions that can be safely matched after a reload from disk, while discarding folds whose corresponding content or structure no longer exists.

- **Reason:** Reliable folding state improves navigation and focus in the core editor without adding permanent UI or specialized bundled functionality.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`, `src/vs/editor/common/services/modelService.ts`, `src/vs/workbench/services/textfile/common/textFileEditorModel.ts`
- **Validation:** Extend the Folding Model browser tests and the relevant text-file reload test to simulate a reloadFromDisk replacement, asserting that corresponding collapsed ranges remain folded and incompatible ranges are removed; run the targeted suites with scripts/test.sh --grep "Folding Model|TextFileEditorModel".
- **Behavior:**

  > When an open file is replaced by a Git revert or equivalent reload from disk, collapsed regions that still correspond to valid folding regions remain collapsed. Regions that no longer have a safe correspondence are not applied to unrelated text. Ordinary edits, provider recomputation, cursor reveal behavior, and reopening a genuinely changed file retain their existing semantics.
- **Trace:**

  > Disk reloads enter through TextFileEditorModel.resolveFromContent in src/vs/workbench/services/textfile/common/textFileEditorModel.ts and reach ModelService.updateModel in src/vs/editor/common/services/modelService.ts with EditSources.reloadFromDisk(). ModelService computes one replaceMove edit around the common prefix and suffix. FoldingController.onDidChangeModelContent in src/vs/editor/contrib/folding/browser/folding.ts then recomputes ranges, while FoldingModel.update in src/vs/editor/contrib/folding/browser/foldingModel.ts preserves collapsed ranges only through their transformed decorations. Existing work in https://github.com/microsoft/vscode/pull/139779 and https://github.com/microsoft/vscode/pull/155302 protects folds when providers lose ranges, but does not define matching across a file replacement. Preserve the checksum safety that prevents stale view-state folds from being restored onto unrelated externally changed content.
- **Open decisions:**
  - Should a fold survive only when its content or structural boundaries still match after revert, or may line-position matching preserve it when the reverted content differs?
  - Should preservation apply to every reloadFromDisk event, or only to explicit revert/discard operations where the previous file version is known?

## Evidence

- **maintainer assessment:** The maintainer comment at https://github.com/microsoft/vscode/issues/77861#issuecomment-515058222 identifies the missing capability directly: revert is treated as a file replacement, with no matching logic to preserve folds.
- **reload path:** src/vs/workbench/services/textfile/common/textFileEditorModel.ts reloads disk contents through EditSources.reloadFromDisk(), while src/vs/editor/common/services/modelService.ts applies the replacement as a computed replaceMove edit based only on common prefix and suffix.
- **folding path:** src/vs/editor/contrib/folding/browser/folding.ts responds to model-content changes by recomputing ranges, and src/vs/editor/contrib/folding/browser/foldingModel.ts carries collapsed state through tracked decoration positions; neither path contains reload-specific or content-based matching for a replaced file.
- **partial existing capability:** https://github.com/microsoft/vscode/pull/139779 and https://github.com/microsoft/vscode/pull/155302 added preservation when folding providers temporarily lose ranges, but neither references this issue or establishes preservation across Git/file reload replacement.
- **canonical search:** https://github.com/microsoft/vscode/issues/16082 is older and open but concerns retaining folded state when copying and pasting code, not folds disappearing when the current file is reverted; it does not meet the re-review requirement of the same reporter-observable symptom.
