# Issue #332109 — Suggestion dropdown shows hover effect before mouse movement

[https://github.com/microsoft/vscode/issues/332109](https://github.com/microsoft/vscode/issues/332109)

## Summary

Real, reproducible UX rough edge rather than a code defect: the suggest widget's row highlight is driven by plain CSS `:hover`, so if the dropdown happens to open under the cursor, the browser applies `:hover` immediately with no mouse movement required. Worth routing to the editor/suggest area as a polish item rather than closing.

## Change summary

The suggestion (IntelliSense) dropdown can appear with an item already showing the hover highlight before the user moves the mouse, because the highlight comes from native CSS `:hover` rather than a tracked 'has the user moved the mouse since open' state.

## Best solution

If addressed, it would need to be a deliberate UX change in the shared list widget (src/vs/base/browser/ui/list/listWidget.ts, which emits the `:hover` background/outline rules) or specifically in the suggest widget's row renderer/CSS (src/vs/editor/contrib/suggest/browser/media/suggest.css) to suppress the `:hover` style until a real mousemove is observed after the widget opens — a design call about whether it should apply to all monaco lists or just suggest, so best left to an editor/suggest area owner.
