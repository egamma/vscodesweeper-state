# Issue #332109 — Suggestion dropdown shows hover effect before mouse movement

[https://github.com/microsoft/vscode/issues/332109](https://github.com/microsoft/vscode/issues/332109)

## Summary

Plausible but unconfirmed report filed hours ago with no reproduction steps beyond a video; the underlying cause is likely the browser's native `:hover` CSS pseudo-class applying to whatever list row happens to sit under the cursor as soon as the suggest widget renders, which is a general list-widget behavior rather than a suggest-specific defect — needs a reporter-confirmed repro before any action.

## Change summary

The suggestion (IntelliSense) dropdown sometimes shows an item already in hover state the instant it opens, before the user moves the mouse.

## Best solution

If confirmed, this belongs in the shared list widget's mouse/hover handling (src/vs/base/browser/ui/list/listWidget.ts, which applies `.monaco-list-row:hover` via plain CSS) rather than the suggest widget itself — e.g. suppressing the CSS hover state until a real mousemove is observed after render. Needs a maintainer decision on whether that broad, cross-list change is worth the complexity, or whether this is accepted native browser behavior.
