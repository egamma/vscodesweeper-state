# Issue #202880 — SCM Input - Allow contributing editor context menus

[https://github.com/microsoft/vscode/issues/202880](https://github.com/microsoft/vscode/issues/202880)

## Summary

The SCM input still lacks an extension-contributable editor context menu. The existing scm/inputBox proposal covers toolbar actions, not this request, so the issue should remain open for a contribution-contract decision.

## Change summary

Allow extensions to contribute context-menu commands to the editor embedded in the SCM input.

## Best solution

Provide an explicitly scoped contribution surface for the SCM input context menu while preserving the minimal menus of other embedded inputs. Decide whether this is SCM-specific or a shared embedded-editor contract before implementing it.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmInput.ts`, `src/vs/platform/actions/common/actions.ts`, `src/vs/workbench/services/actions/common/menusExtensionPoint.ts`, `src/vs/editor/contrib/contextmenu/browser/contextmenu.ts`
- **Validation:** Use a development extension contributing a uniquely named command through the chosen menu contract. Confirm it appears and executes from both right-click and Shift+F10 in the SCM input, respects its when clause, preserves standard editing actions, and does not appear in unrelated embedded inputs unless the approved contract explicitly includes them.
- **Behavior:**

  > Extensions can intentionally contribute commands to the SCM input editor's context menu. Contributions respect their visibility conditions and execute when selected using either mouse or keyboard. Standard editing actions remain available, and ordinary editor contributions must not automatically clutter unrelated embedded inputs. The contribution surface is distinct from the SCM input toolbar.
- **Trace:**

  > SCMInputWidget in src/vs/workbench/contrib/scm/browser/scmInput.ts constructs a simple CodeEditorWidget with ContextMenuController but no contextMenuId override. CodeEditorWidget defaults simple widgets to MenuId.SimpleEditorContext, and ContextMenuController reads that menu; the extension registry exposes editor/context for MenuId.EditorContext, not the simple-widget menu. SCMInputWidgetToolbar separately consumes MenuId.SCMInputBox, so https://github.com/microsoft/vscode/issues/195474 does not cover this context-menu request. https://github.com/microsoft/vscode/issues/89459 records why unrestricted editor contributions were undesirable in embedded inputs and discusses a separate embedded-editor or SCM-specific menu. Preserve that isolation and existing toolbar behavior. The unresolved boundary is the public contribution scope, not whether the current source exposes the requested capability.
- **Open decisions:**
  - Should the public contribution point target only SCM input editors, or support explicitly targeted contributions across a defined set of embedded editors?
