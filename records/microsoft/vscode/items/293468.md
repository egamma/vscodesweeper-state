# Issue #293468 — weird zooming behavior in mermaid editor

[https://github.com/microsoft/vscode/issues/293468](https://github.com/microsoft/vscode/issues/293468)

## Summary

Team-authored bug still present on main — the ctrl+wheel zoom-out path applies a large multiplier (×5 or ×10) that makes `scale * (1 + delta)` shrink disproportionately compared to zoom-in, causing the 'really far out with one bump' effect. No fix commit references this issue.

## Change summary

Ctrl+mousewheel zoom out in the mermaid editor overshoots dramatically compared to zoom in.

## Best solution

Clamp or linearize the zoom delta so zoom-out cannot exceed a proportional per-step ratio (e.g. mirror the zoom-in factor as `1/factor` for out). The fix lives in the `handleWheel` methods in `extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts` and `extensions/mermaid-markdown-features/preview-src/shared/diagramManager.ts`.

- **Fix prompt:**

  > The mermaid editor's ctrl+mousewheel zoom-out overshoots because the formula `scale * (1 + delta)` is asymmetric: zoom-in adds a small positive to 1 (e.g. 1.24 → ×1.24), but zoom-out subtracts the same magnitude (e.g. 1 + (-0.24) = 0.76 → ×0.76 — or worse with large deltaY values on Windows standard mice where deltaY=±120, producing delta values near ±0.24 with the ×5 multiplier, or ±0.48 with the ×10 in diagramManager.ts). Fix both `handleWheel` methods: in `extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts` (line ~160) and `extensions/mermaid-markdown-features/preview-src/shared/diagramManager.ts` (line ~427). Replace `scale * (1 + delta)` with an exponential formula like `scale * Math.exp(delta)` or `scale * Math.pow(zoomBase, -deltaY * factor)` so that equal wheel ticks produce symmetric zoom-in/out ratios. Keep minScale/maxScale clamping. Do NOT change the Alt+click zoom, button zoom, or pan behavior.
