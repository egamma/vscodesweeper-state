# Issue #336263 — Allow viewing changes by commit in agents window

[https://github.com/microsoft/vscode/issues/336263](https://github.com/microsoft/vscode/issues/336263)

## Summary

Keep open: the Agents Window provides branch, session, and turn changes, but not a selectable per-commit review mode. This team-authored request remains a distinct capability gap; no verified older canonical or completed fix was found.

## Change summary

Allow users to select a Git commit and view its file changes within the Agents Window.

## Best solution

Provide session-repository-aware commit selection and read-only commit diffs in the Agents Window, preserving existing aggregate and turn-based views. Settle the history scope and supported-provider behavior before implementation.

- **Validation:** In an Agents session with two commits changing different files and an additional uncommitted edit, select each commit and verify that its displayed files and contents reflect only that commit, excluding the other commit and working-tree edit. Confirm existing branch/session/turn views remain unchanged and switching sessions does not retain the previous repository's commit selection.
- **Behavior:**

  > Users should be able to select an individual Git commit and inspect the changes introduced by that commit inside the Agents Window. The displayed comparison must represent the selected commit rather than cumulative branch changes, a chat turn, or current working-tree contents. Acceptance should use a session with two distinguishable commits and an uncommitted edit, then verify each selection independently and verify isolation when switching sessions. The available history range and behavior for providers without commit-history access require a maintainer decision.
- **Trace:**

  > ChangesPickerActionItem in src/vs/sessions/contrib/changes/browser/changesView.ts renders the provider-neutral catalogue exposed by IChangesViewService.activeSessionChangesetsObs. Agent Host createChangesets in src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionChangesets.ts currently adapts branch, uncommitted, session, turn, and Agent Merge entries; the Copilot Chat createChangesets implementation exposes branch/all/last-turn comparisons backed partly by checkpoint refs. These comparisons do not establish arbitrary per-commit selection, although the built-in Git extension separately registers git.viewCommit. The trace identifies the display and provider boundaries but does not establish a shared history-enumeration contract across providers. Preserve existing changeset semantics and keep shared Sessions code provider-neutral; inspection must not commit, reset, or modify working-tree files. https://github.com/microsoft/vscode/issues/336620 is related design context, not a duplicate canonical.
- **Open decisions:**
  - Should selectable history include only commits on the session branch since its base, or the repository's broader reachable history?
  - Should the initial capability cover both local/remote Agent Host sessions and GitHub-backed Copilot Chat sessions, and what should users see when their provider cannot supply commit history?
