# Issue #329947 — Integrated terminal makes characters after the line wrap invisible (when uzing `fzf`)

[https://github.com/microsoft/vscode/issues/329947](https://github.com/microsoft/vscode/issues/329947)

## Summary

Fresh, well-documented report: PSFzf's Ctrl+R history search appears to corrupt the terminal's line-wrap/rendering state so that subsequent wrapped text becomes invisible on Windows PowerShell with ConPTY; the reporter confirmed it reproduces with fzf/PSFzf specifically (not with the default terminal Ctrl+R, and not over WSL/remote), across two environments including a clean sandbox install.

## Change summary

After using fzf's Ctrl+R history search in the Windows PowerShell integrated terminal, characters typed on a subsequently wrapped line render invisible (likely a stuck SGR/color or wrap-flag state).

## Best solution

Route to the terminal team to trace the interaction between PSFzf's escape sequences (alternate-buffer/cursor save-restore or SGR toggling) and xterm.js/ConPTY's line-wrap and attribute state; a targeted repro capturing the raw byte stream from fzf would help isolate whether the defect is in xterm.js's buffer handling or in how VS Code synchronizes ConPTY screen state after such switches.
