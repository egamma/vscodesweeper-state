# Issue #328400 — Subsessions should have the same permission level as parent session

[https://github.com/microsoft/vscode/issues/328400](https://github.com/microsoft/vscode/issues/328400)

## Summary

Reasonable, well-specified feature request: subagent/subsession threads currently get their own approval state rather than inheriting the parent session's approval level, forcing redundant confirmations even when the parent runs in "allow all" mode. Already correctly labeled feature-request/agents-window; no evidence this has landed or is covered elsewhere.

## Change summary

When an agent spawns a subsession/subagent, the child session starts with default (not-yet-approved) tool permissions instead of inheriting the parent session's approval level (e.g. "allow all").

## Best solution

Extend the existing per-provider subagent session creation (e.g. `_createSubagentSession` in src/vs/platform/agentHost/node/codex/codexAgent.ts, which already shares the parent's `acceptedForSession` memo) to also propagate the parent's broader approval/trust mode, likely via the shared session-permissions layer in src/vs/platform/agentHost/node/sessionPermissions.ts, with the opt-in setting the reporter suggests if maintainers want it gated.
