# Issue #314775 — VS Code leaks TCP connections to Ollama endpoint via SSH tunnel, causing silent task failures

[https://github.com/microsoft/vscode/issues/314775](https://github.com/microsoft/vscode/issues/314775)

## Summary

The report claims a TCP connection leak in VS Code's core HTTP client, but the evidence doesn't isolate a VS Code-specific defect. The same behavior across three independent extensions (one built-in, two third-party) is consistent with Node.js 22's default keep-alive agent behavior over SSH tunnels, not a shared VS Code code path. More information is needed to determine whether this is a VS Code core issue, a Node.js runtime behavior, or an SSH tunnel interaction.

## Change summary

TCP connections to an Ollama endpoint via SSH tunnel accumulate unboundedly when using Ollama integrations through Remote-SSH, eventually causing silent task failures.

## Best solution

Clarify whether the leak reproduces without the SSH tunnel (direct localhost Ollama), and whether it reproduces with a simple Node.js script using the same `http.request` pattern. If the root cause is Node.js 22's default `keepAlive: true` global agent over SSH tunnels, the fix would be configuring a custom HTTP agent with `maxSockets`/`maxFreeSockets`/`keepAliveTimeout` in the Copilot BYOK networking layer (`extensions/copilot/src/platform/networking/node/nodeFetcher.ts`). The third-party extensions (Opilot, Continue) would need their own fixes.

## Evidence

- **NodeFetcher implementation:** extensions/copilot/src/platform/networking/node/nodeFetcher.ts line 99 uses `module.request(url, { method, headers })` without specifying a custom HTTP agent — it relies on Node.js's default global agent, which in Node 22 has `keepAlive: true` by default.
- **No shared HTTP client:** The three extensions named (Copilot BYOK Ollama, Opilot, Continue) do not share a common HTTP client code path in VS Code core. Copilot uses its own NodeFetcher; the third-party extensions use their own fetch implementations. The common factor is the Node.js runtime, not VS Code.
- **SSH tunnel topology:** The leak involves an SSH tunnel (`ssh -fNL`) between the remote dev server and the Ollama host. SSH tunnels can interact poorly with HTTP keep-alive connections because the tunnel process holds sockets open even after the HTTP-level connection is idle.
- **Node.js 22 default behavior:** Node.js 19+ changed `http.Agent` to default `keepAlive: true`. Combined with `maxSockets: Infinity` (the default), connections are kept alive indefinitely with no cap, which explains the unbounded growth pattern.
