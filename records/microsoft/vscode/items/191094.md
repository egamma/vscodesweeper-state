# Issue #191094 — International settings in VS Code

[https://github.com/microsoft/vscode/issues/191094](https://github.com/microsoft/vscode/issues/191094)

## Summary

Independent date/time formatting remains missing: local-history timestamps still follow the display language. Keep this accepted Backlog request open for a localization design decision; related reports do not provide an older canonical.

## Change summary

Allow users to choose regional date/time formatting without changing VS Code's display language.

## Best solution

Provide a consistent regional-format preference independent of display language, covering local-history timestamps and other core date/time surfaces. A maintainer should settle whether the preference selects a formatting locale or exposes individual date/time options, and define the default behavior.

- **Behavior:**

  > Users currently need to change the display language to obtain their preferred regional date/time presentation in local history. They should be able to retain English UI text while selecting Polish-style dates and 24-hour time. Acceptance should verify independent formatting in the local-history tooltip and consistency across the core surfaces included in the agreed scope. The behavior when no override is configured must be explicitly defined.
- **Trace:**

  > getLocalHistoryDateFormatter in src/vs/workbench/contrib/localHistory/browser/localHistory.ts caches an Intl formatter constructed with platform.language; localHistoryTimeline.ts uses it in the reported tooltip, and localHistoryCommands.ts also consumes it for history labels. src/vs/base/common/platform.ts already distinguishes UI language, configured locale, and OS/browser locale, but this formatter does not expose an independent preference. Test-run names in src/vs/workbench/contrib/testing/common/testResult.ts likewise use the UI language. workbench.action.configureLocale changes display language rather than providing the requested independent control. The related testing report https://github.com/microsoft/vscode/issues/204738 was consolidated into this issue; newer reports https://github.com/microsoft/vscode/issues/241245 and https://github.com/microsoft/vscode/issues/235944 add demand but are not duplicate targets. - **Open decisions:**
