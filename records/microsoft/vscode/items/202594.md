# Issue #202594 — Middle click on Linux can only paste from copied text, not from the Primary buffer

[https://github.com/microsoft/vscode/issues/202594](https://github.com/microsoft/vscode/issues/202594)

## Summary

The report describes middle-click pasting from the system clipboard instead of the X11 primary selection buffer on Linux, but the reporter noted inconsistency in comment 1. The code architecture (SelectionClipboard contribution + NativeClipboardService passing 'selection' type to Electron) is designed to support primary selection, but there may be edge cases or timing issues. A second reporter confirms an issue on Wayland. Related open issues exist (#130208, #261170) about primary selection interactions, but none are exact duplicates of this middle-click paste behavior. Keeping open — insufficient reproduction detail to close or to confirm a distinct root cause from the related issues.

## Change summary

Middle-click on Linux sometimes pastes from the system clipboard (Ctrl+C) instead of the X11 primary selection buffer (last selected text).

## Best solution

Investigate whether this is a timing/race condition in the SelectionClipboard contribution's debounced write (100ms RunOnceScheduler in `src/vs/workbench/contrib/codeEditor/electron-browser/selectionClipboard.ts`) or an Electron/Chromium limitation with X11 primary selection handling, particularly on Wayland. If this is a symptom of the same root cause as https://github.com/microsoft/vscode/issues/130208, consolidate there.
