# Issue #344474 — run_in_terminal: clearing pending PowerShell input depends on the PSReadLine edit mode, not the OS

[https://github.com/microsoft/vscode/issues/344474](https://github.com/microsoft/vscode/issues/344474)

## Summary

Keep open: current source still chooses PowerShell prompt clearing from the OS rather than PSReadLine behavior. The merged predecessor fixes default Windows configurations, not the two non-default edit-mode cases reported here.

## Change summary

Clear pending PowerShell input before agent commands without assuming that PSReadLine's edit mode matches the operating system.

## Best solution

Make fallback terminal execution respect the shell's actual input-clearing behavior while preserving running-command interruption. The terminal owner should establish how this works when shell integration is disabled and edit-mode information is unavailable.

## Evidence

- **Current source:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy/strategyHelpers.ts, canClearPromptInputWithCtrlU, returns true immediately for non-Windows terminals and false for Windows PowerShell. It neither receives nor checks PSReadLine edit mode.
- **Reported trigger traced:** runInTerminalTool.ts:2770-2774 records typed pending input through onDidInputData. NoneExecuteStrategy.execute and BasicExecuteStrategy.execute then consult canClearPromptInputWithCtrlU before sending '\x15', followed by the command. Thus macOS PowerShell in Windows edit mode receives the unbound control character; Windows PowerShell in Emacs mode receives no clearing sequence before the new command.
- **Predecessor is not this fix:** https://github.com/microsoft/vscode/pull/343074 merged as 90842528a71d2ec0df87b63e5f1997ecc60d5656. Its strategyHelpers.ts diff introduces the OS-based decision still present today, rather than mode-aware clearing. Path history shows no subsequent change to that helper.
