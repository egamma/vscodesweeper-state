# Issue #344474 — run_in_terminal: clearing pending PowerShell input depends on the PSReadLine edit mode, not the OS

[https://github.com/microsoft/vscode/issues/344474](https://github.com/microsoft/vscode/issues/344474)

## Summary

Keep open: both fallback execution strategies still decide whether to clear PowerShell input using the OS rather than PSReadLine's actual bindings. The source confirms the mismatch; reporting edit mode through shell integration alone would not resolve the explicitly reported integration-disabled case.

## Change summary

Prevent run_in_terminal from appending commands to pending PowerShell input or inserting an unbound Ctrl+U when PSReadLine uses a nondefault edit mode.

## Best solution

Make pending-input handling respect PowerShell's actual clearing capabilities while preserving the existing protections against unintended Ctrl+C cancellation. Establish safe behavior when shell integration cannot provide those capabilities, rather than treating OS defaults as authoritative.

## Evidence

- **OS-only decision confirmed:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/executeStrategy/strategyHelpers.ts:14–31 documents the PSReadLine edit-mode distinction, but canClearPromptInputWithCtrlU returns true for every non-Windows OS and false for identified PowerShell on Windows. Its inputs contain no edit-mode or key-binding information.
