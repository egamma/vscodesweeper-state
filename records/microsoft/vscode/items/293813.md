# Issue #293813 — `SCMRepository` lifecycle is weird

[https://github.com/microsoft/vscode/issues/293813](https://github.com/microsoft/vscode/issues/293813)

## Summary

The lifecycle ownership concern remains on current main: SCMRepository still disposes a store created and populated by SCMService. Keep this bounded cleanup open; the interface already extends IDisposable, but the implementation does not own and track its resources conventionally.

## Change summary

Make SCMRepository responsible for its own disposable lifetime instead of consuming a caller-created DisposableStore.

## Best solution

Give SCMRepository conventional, tracked ownership of its lifetime resources while preserving SCMService registration/removal bookkeeping and existing provider teardown behavior. This is lifecycle debt, not evidence of a confirmed user-facing memory leak.
