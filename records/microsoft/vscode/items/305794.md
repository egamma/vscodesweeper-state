# Issue #305794 — agentPlugins with devcontainer story

[https://github.com/microsoft/vscode/issues/305794](https://github.com/microsoft/vscode/issues/305794)

## Summary

This remains a real cross-component gap: VS Code can discover configured plugin directories, but Dev Containers cannot declaratively provision and enable agent plugins inside the container. The Dev Containers extension owns the environment-provisioning side, so the issue should be moved to its tracker while retaining the agent-plugin context.

## Change summary

Allow a devcontainer configuration to install and enable agent plugins and marketplaces inside the container, with optional additional plugins layered over the container definition.

## Best solution

Define a Dev Containers integration that declaratively provisions plugin sources and required dependencies inside the container, then exposes those installations to VS Code's agent-plugin discovery and enablement system. The design should also settle whether host-configured additional plugins are inherited or explicitly opted into for each container.

## Evidence

- **current configuration boundary:** On current main, src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.pluginLocations` with `ConfigurationScope.MACHINE`, so a devcontainer workspace cannot declare these plugin paths in workspace settings.
- **discovery without provisioning:** ConfiguredAgentPluginDiscovery in src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts reads filesystem paths from `chat.pluginLocations`; it discovers directories that already exist but does not provide a devcontainer declaration or container provisioning lifecycle.
- **global installation state:** src/vs/workbench/contrib/chat/common/plugins/AGENTS_PLUGINS.md documents installed marketplace plugins in application-scoped, machine-targeted storage, rather than as workspace or devcontainer configuration.
- **partial implementation attempt:** https://github.com/microsoft/vscode/pull/315123 is still open and proposes only changing `chat.pluginLocations` to workspace scope. That addresses local path declaration but not automatic marketplace installation, dependency provisioning inside the container, or host-versus-container layering.
