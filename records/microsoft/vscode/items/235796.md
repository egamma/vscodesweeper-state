# Issue #235796 — Re-opening a notebook results in failure to render output with the right renderer

[https://github.com/microsoft/vscode/issues/235796](https://github.com/microsoft/vscode/issues/235796)

## Summary

Still a valid open bug with community confirmations as recently as October 2025. The widget renderer fails to fall back to text/plain when reopening notebooks with widget outputs (tqdm, matplotlib). The upstream Jupyter issue was closed as not-reproducible but this continues to be reported.

## Change summary

Reopening a notebook with widget outputs (tqdm, matplotlib) fails to render them and does not properly fall back to the text/plain alternative output.

## Best solution

The notebook output rendering path in cellOutput.ts needs to handle the case where `application/vnd.jupyter.widget-view+json` cannot be rendered (widget JS state lost on reopen) and reliably fall back to the next available mime type (e.g. text/plain). The Jupyter extension's widget renderer should signal failure so the fallback triggers. Needs investigation between notebook core and the Jupyter extension's renderer messaging.
