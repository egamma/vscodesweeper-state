# Issue #167783 — Enable peek definition in signature help and IntelliSense UIs

[https://github.com/microsoft/vscode/issues/167783](https://github.com/microsoft/vscode/issues/167783)

## Summary

Definition previews from suggestion details and signature help remain a real gap in the current source. Existing commands do not provide navigation for the displayed completion or signature, and the linked Interactive Diagnostics proposal does not clearly own this work.

## Change summary

Allow users to preview or navigate to symbol definitions directly from suggestion details and signature help.

## Best solution

Define a provider-backed definition-navigation contract for these two editor widgets, then expose a consistent, keyboard-accessible preview interaction without requiring users to accept a completion first. Coordinate with the related interactive-types discussion without treating diagnostic navigation as coverage of this request.

- **Behavior:**

  > Users should be able to inspect a symbol's definition while viewing its completion details or signature help, rather than first inserting the completion or leaving the widget. The interaction should be consistent with existing definition previews and available by keyboard. Acceptance must cover both widgets, entries without definition targets and preservation of existing completion and signature-selection behavior.
- **Trace:**

  > SuggestDetailsWidget.renderItem in src/vs/editor/contrib/suggest/browser/suggestWidgetDetails.ts renders detail as plain text and documentation through the Markdown renderer. ParameterHintsWidget.render in src/vs/editor/contrib/parameterHints/browser/parameterHintsWidget.ts renders the signature and parameter documentation without definition-target metadata. The corresponding CompletionItem and SignatureInformation interfaces in src/vs/editor/common/languages.ts have no definition location, and the command registrations inspected do not navigate from these displayed items. The author suggests either symbol locations with optional jump actions or clickable displayed types; the record does not settle the public contract or exact interaction. https://github.com/microsoft/vscode/issues/64566 is related diagnostic-interaction work, not a verified duplicate. Preserve ordinary editor navigation, completion acceptance and overload cycling; the extension API bridge and language-provider adoption still need to be traced during planning.
- **Open decisions:**
  - Should providers expose a definition target for the whole completion or signature, navigable targets for individual displayed types, or both?
  - Should the initial user-facing interaction provide modifier-hover previews only, or also explicit jump-to-definition actions, and what keyboard interaction should accompany it?
