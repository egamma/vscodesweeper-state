## Change summary

Provide a live hierarchical view of subagents with status, activity, metadata, transcript access, and attention indicators.

## Best solution

Build an accessible recursive subagent overview on the existing Sessions chat model, reusing the current status and transcript-opening capabilities while preserving the quieter inline cards. Decide whether the overview is a persistent panel or an expanded existing Subagents surface, and whether child conversations remain read-only or support user interaction.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionBackgroundActivitiesControl.ts`, `src/vs/sessions/services/sessions/common/session.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/openSubagentChat.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentOpenChat.ts`
- **Validation:** Add focused Sessions tests that project parent, child, and grandchild chats into the chosen hierarchy with running, waiting, completed, failed, and rejected states; add UI fixture or integration coverage for keyboard tree navigation, transcript opening, focus restoration, and screen-reader labels.
- **Behavior:**

  > Users can inspect the complete live parent-to-child subagent hierarchy without asking the busy parent agent for an update. Each node identifies the agent and exposes its current state, elapsed activity, and available metadata, with attention-required and rejected attempts distinguishable from ordinary running work. Activating an available node opens its transcript, while unavailable or rejected nodes explain their state. The surface is fully keyboard operable and presents equivalent hierarchy and status information to screen-reader users.
- **Trace:**

  > The provider-neutral IChat model in src/vs/sessions/services/sessions/common/session.ts already carries observable chat status and IChatOrigin.parentChat relationships for tool-created chats. SessionBackgroundActivitiesControl in src/vs/sessions/contrib/chat/browser/sessionBackgroundActivitiesControl.ts intentionally collects only direct children and reduces them to label/icon/open picker entries, so nested structure and detailed status are lost at the aggregate surface. ChatSubagentContentPart and OpenSubagentChatActionViewItem in src/vs/workbench/contrib/chat/browser/widget/chatContentParts already render rich per-invocation activity, model, duration, credits, and confirmation state, while src/vs/sessions/contrib/providers/agentHost/browser/openSubagentChat.ts resolves and opens child transcripts. Failed spawn attempts may not create an IChat, so the plan must trace whether Agent Host protocol state retains enough information to represent them. Preserve existing inline subagent cards, transcript behavior, and concurrency semantics; this work should add observability rather than duplicate or alter execution.
- **Open decisions:**
  - Should the hierarchy be a persistent dedicated view, or an expanded form of the existing Subagents pill/picker?
  - Should opening a child remain read-only, or should the overview permit sending input or steering a child when the provider supports it?
  - Are rejected spawn attempts first-class temporary tree nodes, and how long should they remain visible after rejection?
