# Issue #275353 — Follow instructions file link tooltip shows full file path

[https://github.com/microsoft/vscode/issues/275353](https://github.com/microsoft/vscode/issues/275353)

## Summary

The raw `file://` presentation has improved on current main, but the tooltip still exposes the full filesystem path instead of identifying the extension that supplied the prompt. Keep this open while maintainers decide how to preserve the security-relevant source location without presenting an opaque path.

## Change summary

Show a useful source-oriented tooltip for an extension-contributed instructions-file link instead of its full filesystem path.

## Best solution

Present the contributing extension's display name alongside enough human-readable location information to preserve source transparency, with a safe path-based fallback when extension provenance is unavailable.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatMarkdownRenderer.test.ts`, `src/vs/base/browser/markdownRenderer.ts`
- **Validation:** Add a focused chat test that renders the generated follow-instructions link and asserts the chosen managed-hover text for an extension-contributed prompt, plus a fallback case that still reveals a human-readable filesystem location when provenance is unavailable.
- **Behavior:**

  > A follow-instructions link for an extension-contributed prompt identifies its source in a concise, understandable tooltip rather than showing an opaque full file URI. The tooltip retains whatever location or provenance information maintainers decide is necessary for users to assess the instruction source. Ordinary file links and prompt files without known extension provenance continue to expose a human-readable location.
- **Trace:**

  > CreateRemoteAgentJobFromEditorAction in src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts currently emits a markdown link containing the prompt basename and URI but no title or source metadata. The generic link renderer in src/vs/base/browser/markdownRenderer.ts therefore derives the tooltip from the full decoded filesystem path, and ChatContentMarkdownRenderer installs that value as a managed hover. Explicit markdown titles are already supported and covered in src/vs/base/test/browser/markdownRenderer.test.ts. The uncertainty begins at provenance: the current action has the active model URI and destination session contribution, but it does not directly carry the extension that contributed the prompt. Preserve ordinary file-link behavior and the security property that users can understand where instructions originate.
- **Open decisions:**
  - For an extension-contributed prompt, should the tooltip show the extension display name alone, the extension name plus a readable location, or retain the full path alongside the extension identity?
  - When extension provenance cannot be resolved, should the fallback show the complete decoded filesystem path or a shorter label-service representation?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts constructs `Follow instructions in [<basename>](<uri>)` without an explicit markdown title, so extension identity is not represented.
- **current rendering:** src/vs/base/browser/markdownRenderer.ts derives a file link's tooltip from its decoded filesystem path when no explicit title is supplied; src/vs/workbench/contrib/chat/browser/widget/chatContentMarkdownRenderer.ts then uses that title for the managed hover. This removes raw `file://` formatting but still exposes the full path.
- **existing capability:** src/vs/base/test/browser/markdownRenderer.test.ts confirms that explicit markdown titles override the generated file-path title, so the rendering layer can already display a source-oriented tooltip.
- **design constraint:** The maintainer comment at https://github.com/microsoft/vscode/issues/275353#issuecomment-3490279342 says the location is intentionally revealed for security reasons; the follow-up at https://github.com/microsoft/vscode/issues/275353#issuecomment-3493736883 proposes extension identity or a better-formatted path.
