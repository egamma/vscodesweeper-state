# Issue #165454 — Context widgets are not aware of Window Controls Overlay (WCO)

[https://github.com/microsoft/vscode/issues/165454](https://github.com/microsoft/vscode/issues/165454)

## Summary

Still reproduces on main: the context view layout in contextview.ts uses the full viewport (window.innerWidth/innerHeight) without subtracting the Window Controls Overlay area, so menus and context widgets can render underneath native window controls. This is the canonical issue — #235498 and #210710 were both closed as duplicates of it.

## Change summary

Context menus and dropdown widgets overlap with native window control buttons (minimize/maximize/close) when Window Controls Overlay (WCO) is enabled.

## Best solution

Modify the viewport calculation in `src/vs/base/browser/ui/contextview/contextview.ts` `doLayout()` to reduce the available viewport width by the WCO area (via `getWCOTitlebarAreaRect`) so that context views are clamped away from the window control buttons. The titlebar part already uses `getWCOTitlebarAreaRect` for its own layout — the same approach should feed into `layout2d`'s viewport parameter.
