Team-authored performance bug about notebook resize causing UI thread lockup. No fix commit references this issue, and the core resize layout path still lacks visible throttling. Keeping open.

## Change summary

Resizing notebooks causes UI thread lockup with 15-50ms+ frames, especially on average hardware.

## Best solution

Investigate and optimize the notebook layout path during resize — likely needs throttling or batching of layout recalculations in the notebook editor widget's resize handling. The cell list relayout and webview resize coordination are the probable hot paths.
