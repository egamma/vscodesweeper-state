# Issue #335627 — Emmet suggestions should only appear in JSX/TSX markup contexts

[https://github.com/microsoft/vscode/issues/335627](https://github.com/microsoft/vscode/issues/335627)

## Summary

Traced this in the current Emmet completion provider: for jsx/tsx syntax, the AST-aware location check is never populated (rootNode/currentNode are only computed for stylesheet syntaxes and HTML script/style blocks), so `isValidLocationForEmmetAbbreviation` falls back to a naive backtrack for an unescaped `<`/`>` — if none appears within the last 500 characters before the cursor, it defaults to valid even when the cursor is in plain JS/TS code far from any markup. This is a real, traceable gap, not a documented design choice, so it stays open for the Emmet area to consider a proper JSX-context fix.

## Change summary

In .jsx/.tsx files, Emmet abbreviation suggestions can appear for plain JavaScript/TypeScript identifiers outside any JSX markup, not just inside JSX.

## Best solution

Give jsx/tsx a real AST-based location check (similar to the HTML/CSS paths) — e.g. populate currentNode from a JSX-aware parse or use the TS/JS language service's syntax-kind-at-position — instead of relying on the heuristic backtrack-for-angle-bracket fallback in extensions/emmet/src/abbreviationActions.ts and extensions/emmet/src/defaultCompletionProvider.ts.

## Evidence

- **no AST for jsx:** extensions/emmet/src/defaultCompletionProvider.ts only computes rootNode/currentNode when isStyleSheet(document.languageId) (line 136) or isStyleSheet(syntax) (line 149) — jsx satisfies neither, so currentNode stays undefined when isValidLocationForEmmetAbbreviation is called (line 160).
- **naive fallback:** extensions/emmet/src/abbreviationActions.ts lines 522-618: with currentHtmlNode undefined, `start` stays 0 and the function just backtracks through up to 500 preceding characters looking for an unescaped `<`/`>`; if none is found, `valid` stays true by default — exactly the false-positive the reporter describes for plain JS/TS code above any JSX.
- **no existing setting covers this:** emmet.excludeLanguages / emmet.showExpandedAbbreviation only disable Emmet for the whole language (defaultCompletionProvider.ts lines 44-58), not scoped to markup-vs-code context.
- **not a known duplicate:** Candidate canonicals (e.g. https://github.com/microsoft/vscode/issues/61474) address the opposite problem (Emmet not expanding inside JSX where it should); none of the listed open issues own this specific over-triggering-outside-markup report.
