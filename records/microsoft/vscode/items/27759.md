# Issue #27759 — Align explorer sorting with platform sorting

[https://github.com/microsoft/vscode/issues/27759](https://github.com/microsoft/vscode/issues/27759)

## Summary

Keep open: merged work added several sorting modes and fixed edge cases, but current main still uses locale-aware numeric sorting by default rather than matching each platform's file-manager ordering. This accepted Backlog request has 39 upvotes and recent concrete examples, so the remaining default-ordering decision is still relevant.

## Change summary

Make Explorer filename ordering match platform conventions, including punctuation, case, prefixes, and names beginning with numeric-looking segments.

## Best solution

Define the intended Explorer ordering contract for each platform, then make the default comparator follow it while preserving explicit cross-platform ordering options for users who need deterministic Unicode or locale behavior.

- **Validation:** Add deterministic comparator and Explorer sorter tests covering foo.ts versus foo_test.ts, upper/lower-case ordering, punctuation, locale-sensitive names, and GUID/hash prefixes for every selected platform or configured ordering contract.
- **Behavior:**

  > Explorer entries should follow a documented ordering contract that addresses the platform mismatches in this issue. The acceptance matrix must cover prefix-versus-punctuation ordering, case behavior, locale-sensitive names, and numeric-looking GUID/hash prefixes. Existing explicit upper, lower, and Unicode modes must retain their documented behavior. Sorting by type, modified time, folder grouping, file nesting, and reverse order must remain unchanged.
- **Trace:**

  > The Explorer's FileSorter in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts selects one of the filename comparators from src/vs/base/common/comparers.ts. The default comparator is an Intl.Collator using the process locale with numeric sorting enabled; compareFileNamesUnicode is the only current non-locale, non-numeric alternative. Configuration is registered as explorer.sortOrderLexicographicOptions in src/vs/workbench/contrib/files/browser/files.contribution.ts. https://github.com/microsoft/vscode/pull/97200 fixed several neighboring filename-order cases, and https://github.com/microsoft/vscode/pull/97272 added case-grouping and Unicode options, but neither established platform-native default ordering. Keep the work bounded to filename comparison and Explorer configuration; do not alter unrelated grouping, file nesting, or modified-time sorting. The uncertainty starts at the public behavior contract: whether VS Code should vary with each platform's file manager or expose a stable additional mode.
- **Open decisions:**
  - Should the default Explorer order mirror each host platform's file manager, even when that makes the same workspace sort differently across operating systems, or remain cross-platform consistent with platform matching as an explicit mode?
  - For the intended default or new mode, should locale collation, case grouping, and numeric comparison follow the platform file manager exactly, or should VS Code define a narrower stable contract for those dimensions?

## Evidence

- **current source:** src/vs/base/common/comparers.ts constructs the default filename comparator with Intl.Collator(undefined, { numeric: true }); src/vs/workbench/contrib/files/browser/views/explorerViewer.ts applies that comparator without selecting platform-native ordering.
- **existing capability:** src/vs/workbench/contrib/files/browser/files.contribution.ts exposes explorer.sortOrderLexicographicOptions values default, upper, lower, and unicode. Unicode provides strict code-point ordering, but none is documented or implemented as matching the host platform's file manager.
- **partial implementation:** https://github.com/microsoft/vscode/pull/97200 explicitly described itself as partially addressing this issue and merged edge-case fixes in commit 4d44f6a861bb3cbbde4e20f52dccb45979848d78; https://github.com/microsoft/vscode/pull/97272 added the current lexicographic options in commit f280f4c63ef258953c7a33abf094ac3e7fc2c700.
