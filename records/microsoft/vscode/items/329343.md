# Issue #329343 — Switching between chats doesn't persist the scroll location for the chat

[https://github.com/microsoft/vscode/issues/329343](https://github.com/microsoft/vscode/issues/329343)

## Summary

Freshly-filed, team-authored bug with a clear repro video; tracing the code confirms the chat view's session-switch path has no scroll-position save/restore, unlike the chat-editor host which already does this — routing to the chat area rather than closing.

## Change summary

When switching away from and back to a chat session in the chat sidebar, the previously scrolled-up chat resets to the bottom instead of restoring its prior scroll position.

## Best solution

Extend the per-session scroll persistence that already exists for the editor-hosted chat (ChatEditor.loadEditorViewState/scrollTop, src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts:284-314) to the sidebar ChatViewPane's loadSession/clear/showModel flow (src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts:1399-1486), capturing scrollTop keyed by session resource before switching and restoring it after showModel completes.

## Evidence

- **view pane host lacks it:** src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts:1399-1486 — `clear()` and `loadSession()` call `updateViewState()`/`showModel()` but never read or write `_widget.scrollTop` per session, so switching sessions in the sidebar loses scroll position, matching the reported repro.
