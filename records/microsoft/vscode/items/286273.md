# Issue #286273 — Offer to open worktree

[https://github.com/microsoft/vscode/issues/286273](https://github.com/microsoft/vscode/issues/286273)

## Summary

Team-authored issue; the worktree creation happy path in _createWorktree (extensions/git/src/commands.ts) completes without offering to open the new worktree, confirmed by source inspection. Keeping open per team-member rule.

## Change summary

After creating a git worktree, VS Code does not offer to open or check out the new worktree — the user must manually find and right-click it.

## Best solution

After a successful `repository.createWorktree()` call in `_createWorktree` (extensions/git/src/commands.ts ~line 3548), prompt the user to open the worktree in the current window or a new window — reusing the pattern already in `handleWorktreeConflict` (lines 3740-3748) which shows 'Open Worktree in Current Window' / 'Open Worktree in New Window'. Also consider auto-expanding the Worktrees section in the SCM view.
