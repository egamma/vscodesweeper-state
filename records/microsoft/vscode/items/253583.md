# Issue #253583 — Deeplinking from Coding Agent back into VS Code

The basic cloud-session and PR checkout deep links now exist, but the discussion explicitly leaves entry-point coverage to revisit. Keep this accepted Backlog request open to settle that remaining scope; neither a qualifying fix commit nor an older open canonical was established.

## Change summary

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/chatSessions/vscode/chatSessionsUriHandler.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts`, `extensions/copilot/src/extension/chatSessions/vscode/test/chatSessionsUriHandler.spec.ts`
- **Validation:** After agreeing the entry points and handoff contract, exercise each browser link with the repository already open, with a known local clone but another workspace open, and with no local clone. Verify the selected task opens, the agreed branch/review behavior occurs, and conversation continuity matches the agreed contract; include a repository with uncommitted changes to ensure the handoff does not discard edits.
- **Behavior:**

  > A user reviewing a cloud coding-agent task can follow an agreed browser entry point into VS Code and reach the corresponding task and changes. Existing Mission Control session links and GHPR checkout links already provide parts of this experience. Acceptance must specify which entry points expose the action and whether arrival opens the conversation, checks out the task branch, or attaches to the original environment. Existing local edits must remain safe during the handoff.
- **Trace:**

  > ChatSessionsUriHandler in extensions/copilot/src/extension/chatSessions/vscode/chatSessionsUriHandler.ts accepts /openAgentSession and resolves a repository before opening a copilot-cloud-agent task resource. New clones use the supplied branch, whereas an already-open matching repository proceeds directly to openPendingSession without branch checkout. CopilotCloudSessionsProvider in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts separately exposes github.copilot.chat.checkoutPullRequestReroute through pr.checkoutFromDescription. Existing tests in extensions/copilot/src/extension/chatSessions/vscode/test/chatSessionsUriHandler.spec.ts cover direct and pending task-resource opening. https://github.com/microsoft/vscode/issues/274934 documents the Mission Control handoff, while https://github.com/microsoft/vscode/issues/253583#issuecomment-3629957085 leaves entry-point coverage open. The uncertainty is the remaining user-facing contract, not whether a deep-link handler exists; browser link placement may lie outside these client files. Preserve the existing session and checkout capabilities rather than introducing a parallel protocol.
- **Open decisions:**
  - Which additional browser entry points are required beyond Mission Control: PR descriptions, task/session pages, or both?
  - Should the review handoff automatically check out the task branch, open the cloud conversation with an explicit checkout action, or attach to the original cloud container?
