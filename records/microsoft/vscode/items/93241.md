# Issue #93241 — Should we use namespacing in the CLI

[https://github.com/microsoft/vscode/issues/93241](https://github.com/microsoft/vscode/issues/93241)

## Summary

Namespaced commands already exist in the Rust CLI, but the desktop CLI still exposes extension management through top-level flags rather than the requested extension subcommands. Keep this open for CLI-owner agreement on that remaining public-interface gap; the later discussion supersedes the earlier out-of-scope suggestion.

## Change summary

Organize non-editor CLI capabilities into discoverable subcommands while preserving existing flags for backward compatibility.

## Best solution

Agree on a consistent subcommand contract across the desktop and Rust CLIs, particularly extension management and command-specific help, while preserving existing extension flags and file-opening behavior. Reuse the existing Rust interface rather than designing a competing namespace.

- **Behavior:**

  > Users should discover non-editor CLI functionality through coherent subcommands and focused help instead of an increasingly long list of unrelated flags. The Rust CLI already offers extension subcommands, but the desktop CLI retains flat extension-management flags. Existing scripts using those flags and normal file-opening commands must continue to work. Acceptance requires agreement on which desktop commands and help sections adopt the namespaced interface.
- **Trace:**

  > cli/src/commands/args.rs defines the ext namespace and extension operations; cli/src/bin/code/main.rs dispatches them by translating to existing desktop flags, and cli/src/bin/code/legacy_args.rs preserves older argument forms. The desktop path remains src/vs/platform/environment/node/argv.ts plus src/vs/code/node/cli.ts: NATIVE_CLI_COMMANDS delegates tunnel, serve-web, and agent, but not ext, while extension operations remain top-level OPTIONS entries. https://github.com/microsoft/vscode-cli/pull/432 implemented the Rust subcommand interface, so the remaining question is adoption and presentation in the desktop entry point, not whether subcommands exist. https://github.com/microsoft/vscode/issues/93241#issuecomment-1188985081 explicitly requires owner agreement. Preserve legacy flags and file-opening semantics; adding terminal-control functionality is not required to resolve the namespacing decision. https://github.com/microsoft/vscode/issues/328446 identifies a related path-name collision concern to consider without treating it as a duplicate.
- **Open decisions:**
  - Should the desktop code CLI expose the Rust CLI's ext subcommands, and should extension-management help move under that namespace while legacy flags remain accepted?
