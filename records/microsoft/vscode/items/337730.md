# Issue #337730 — Automations and Customizations sidebar entries look like tree group headers but behave inconsistently

[https://github.com/microsoft/vscode/issues/337730](https://github.com/microsoft/vscode/issues/337730)

## Summary

Team-authored UX critique of the chat sidebar's Automations/Customizations rows visually matching tree group headers while behaving as three different interaction models (expand, navigate-to-editor, open-modal). This is a real, unresolved design inconsistency with no fix on main; team-authored items are also protected from judgment closes regardless.

## Change summary

Automations and Customizations sidebar entries render identically to the group headers below them (Pinned, Chats, ...) but have three different behaviors (navigate, open modal, expand/collapse), with no visual affordance distinguishing them, and only Automations can show a badge.

## Best solution

A maintainer/design pass on the chat sidebar's top-level row treatment (likely in aiCustomizationManagement.ts / automation-related sidebar rendering plus chatViewPane.ts) to give command-like rows (Automations, Customizations) a distinct visual affordance from expandable tree group headers, and decide whether Customizations should also support a badge.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagement.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/common/automations/automation.ts`
- **Validation:** Manual visual check: after the change, Automations/Customizations rows are visually distinguishable from expandable group headers (Pinned, Chats, ...), and the badge treatment is consistent between the two command rows.
- **Behavior:**

  > The chat sidebar's Automations and Customizations rows should be visually distinguishable from the expand/collapse tree group headers (Pinned, Chats, ...) they currently look identical to, since they trigger different interactions (navigate to editor, open modal) rather than expanding in place. Acceptance: a user can tell at a glance which rows expand vs. which trigger a command, and badge support is applied consistently across command-style rows.
- **Trace:**

  > The sidebar renders Automations/Customizations rows with the same indentation, icon+label treatment, and weight as the real group headers below them; Automations navigates to an editor (see chat/common/automations/automation.ts and its consumers), Customizations opens a modal (aiCustomizationManagement.ts), while Pinned/Chats headers just expand/collapse. No differentiating affordance (icon, chevron, styling) currently exists between these row kinds, and badge rendering is only wired for Automations. Boundary: this is a visual/interaction-affordance change to the sidebar row template, not a change to navigation or modal behavior itself.
- **Open decisions:**
  - What visual affordance (icon, chevron, styling) should distinguish expand-in-place headers from command rows that navigate or open a modal?
  - Should Customizations also support the badge treatment currently exclusive to Automations, and if so, what does it represent?
