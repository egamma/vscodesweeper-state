# Issue #320989 — [Feature]Stable installation path required: commit ID breaks third-party integrations

[https://github.com/microsoft/vscode/issues/320989](https://github.com/microsoft/vscode/issues/320989)

## Summary

Valid feature request — the Windows versioned-update mechanism intentionally uses a commit-hash subfolder (`build/lib/util.ts: getVersionedResourcesFolder`) for background update support. This breaks third-party tools that hardcode paths to VS Code internals. Already correctly labeled `under-discussion`.

## Change summary

Request a stable installation path on Windows that doesn't change with each update, so third-party integrations (e.g. SumatraPDF inverse search) don't break.

## Best solution

Consider providing a stable symlink, junction, or a well-known registry key/env var pointing to the current versioned folder, so third-party tools can resolve the active installation without embedding the commit hash. The fix would likely live in `build/win32/code.iss` (Inno Setup script) or the `inno_updater` logic. Alternatively, document a stable path (like the `bin` folder's `code.cmd`) that tools should reference instead.
