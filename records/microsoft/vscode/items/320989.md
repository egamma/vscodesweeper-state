# Issue #320989 — [Feature]Stable installation path required: commit ID breaks third-party integrations

[https://github.com/microsoft/vscode/issues/320989](https://github.com/microsoft/vscode/issues/320989)

## Summary

The central requirement already has a stable entry point: bin\code.cmd resolves the versioned cli.js internally and forwards file-and-line arguments. Integrations can use that launcher without knowing the commit ID; the versioned resource layout itself is intentional.

## Change summary

Provide an update-stable invocation path for third-party integrations such as SumatraPDF inverse search.

## Best solution

Use the installed bin\code.cmd launcher with --reuse-window --goto "file:line" rather than referencing cli.js directly. Preserve the versioned installation layout while keeping its internal paths out of integration configuration.

  > Thanks for the report. There is already a stable entry point for this: use `bin\code.cmd` inside your VS Code installation directory with `--reuse-window --goto "C:\path\document.tex:42"`. ## Evidence

- **Existing stable launcher:** resources/win32/versioned/bin/code.cmd invokes the executable and @@VERSIONFOLDER@@\resources\app\out\cli.js internally, forwarding all caller arguments with %*. The integration does not need to supply the versioned resource path.
- **Stable installation destination:** build/win32/code.iss installs bin\{#ApplicationName}.cmd into {code:GetDestDir}\bin. GetDestDir resolves to {app} for the versioned installation layout; GetBinDirApplicationCmdFilename uses the normal application command name outside update staging.
- **File-and-line invocation:** src/vs/platform/environment/node/argv.ts registers --goto/-g with file:line[:character]. src/vs/platform/environment/node/argvHelper.ts parses and validates those arguments, and src/vs/platform/windows/electron-main/windowsMainService.ts converts goto-mode line and column values into editor selections.
- **Intentional versioned layout:** In https://github.com/microsoft/vscode/issues/298286#issuecomment-4355271633, a maintainer confirms that the commit-hash folder is part of the updated client structure. https://github.com/microsoft/vscode/pull/263998 is the merged implementation of versioned Windows resources.
- **Prior inverse-search evidence:** https://github.com/microsoft/vscode/issues/139087 reports the same SumatraPDF inverse-search context and explicitly confirms that using code.cmd works, while separately noting its transient console window. This issue requests path stability, not suppression of that window; the closed report is supporting evidence, not a duplicate target.
