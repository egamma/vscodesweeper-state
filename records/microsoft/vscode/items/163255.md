# Issue #163255 — WORKSPACE_CONTAINS_TIMEOUT should be configurable

[https://github.com/microsoft/vscode/issues/163255](https://github.com/microsoft/vscode/issues/163255)

## Summary

Valid feature request with 31 upvotes (promoted to Backlog). The WORKSPACE_CONTAINS_TIMEOUT is still hardcoded at 7000ms on current main with no configuration option — the gap remains.

## Change summary

Allow users to configure the workspaceContains activation event timeout (currently hardcoded at 7 seconds), so extensions relying on glob-pattern workspace scanning are not silently skipped on large workspaces.

## Best solution

Add a setting (e.g. `extensions.workspaceContainsTimeout`) that overrides the hardcoded 7000ms constant in `src/vs/workbench/services/extensions/common/workspaceContains.ts`. This is a small, localized change — read the setting via a configuration service and pass it through `IExtensionActivationHost` or directly in `_activateIfGlobPatterns`.
