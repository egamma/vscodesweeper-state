# Issue #338336 — MCP Apps: App-provided tools registered via App.registerTool() are not exposed to Copilot agent

[https://github.com/microsoft/vscode/issues/338336](https://github.com/microsoft/vscode/issues/338336)

## Summary

Keep open: current source supports App-to-server tool calls but does not discover or expose tools provided by an App. The issue is already correctly classified and routed; its On Deck milestone records accepted, unscheduled work.

## Change summary

Expose tools registered by a live MCP App to the active agent and dispatch invocations to that App instance.

## Best solution

Extend the MCP Apps host and chat tool integration to support App-provided tools with explicit session and instance lifetimes, invocation routing, and cleanup. Preserve the existing App-to-server tool path and prevent tools from remaining callable after their owning App is disposed.

- **Protocol declaration is not implementation:** src/vs/platform/mcp/common/modelContextProtocolApps.ts:570-597 defines McpUiAppCapabilities.tools and includes appCapabilities in initialization. However, its AppMessage and HostMessage unions contain no Host-to-App tool request/App response exchange for discovering and invoking these tools.
- **Existing tool calls target the server:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatMcpAppModel.ts:859-864 handles incoming tools/call by forwarding to McpToolCallUI.callTool. This accounts for the reporter's working app.callServerTool() path, not invocation of tools registered inside the App.

That registration path does not discover tools from live App instances; ui/update-model-context provides context attachments, not callable App tools.
