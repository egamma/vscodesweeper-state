# Issue #303895 — `auxiliaryBarFocus` is always `false`

[https://github.com/microsoft/vscode/issues/303895](https://github.com/microsoft/vscode/issues/303895)

## Summary

The context key can remain false because auxiliary-bar focus tracking is wired to the part's root container even though focus may stay inside the active view pane's scoped context-key service. The report remains actionable on current main and should be routed to the existing layout area.

## Change summary

Make `auxiliaryBarFocus` become true while keyboard focus is anywhere within the auxiliary bar so keybindings scoped to that context work.

## Best solution

Align auxiliary-bar focus tracking with the focused view pane's context-key scope, while preserving the existing sidebar and panel focus semantics.
