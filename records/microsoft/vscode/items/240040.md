# Issue #240040 — Git - Blame not working on remote repositories

[https://github.com/microsoft/vscode/issues/240040](https://github.com/microsoft/vscode/issues/240040)

## Summary

Blame support for virtual repositories remains a distinct capability gap, rather than a failure of local Git blame. Route this request to the VS Code-owned Remote Repositories tracker by transferring the existing issue, not closing it.

## Change summary

Display inline and status-bar blame when browsing a virtual repository through Remote Repositories.

## Best solution

Provide provider-backed blame for virtual repository files, with editor and status-bar presentation consistent with local repositories. The Remote Repositories owners should assess that capability in microsoft/vscode-remote-release without assuming a local Git executable or filesystem checkout.

## Evidence

- **Reported scope and confirmation:** https://github.com/microsoft/vscode/issues/240040 describes missing inline and status-bar blame specifically through Remote Repositories, while local repositories and Codespaces work. The September 9, 2025 comment independently confirms missing blame when browsing a remote repository.
- **Existing capability boundary:** extensions/git/src/blame.ts:67-68 limits supported resources to file and git schemes. GitBlameController._updateTextEditorBlameInformation requires a repository with HEAD.commit and rejects unsupported schemes; _getBlameInformation obtains blame through repository.blame2(resource.fsPath, commit). This is a filesystem-backed Git path, not a virtual-repository blame provider.
- **Settings do not bridge the gap:** extensions/git/package.json:4086-4109 registers git.blame.editorDecoration.enabled and git.blame.statusBarItem.enabled, but these control presentation rather than adding virtual repository support. extensions/git/src/model.ts:1125-1129 filters workspace folders to the file scheme when checking repository workspace membership. Enabling the reported settings therefore does not supply the missing provider-backed capability.
- **Canonical search:** Read-only searches in microsoft/vscode for blame with remote titles, remote repositories, virtual, RemoteHub, and vscode.dev did not establish an older open issue owning the same observable symptom. A blame-title search in microsoft/vscode-remote-release returned no matching issue. No verified duplicate or concrete fixing commit was identified.
- **Ownership and preservation:** The reported entry point is Remote Repositories, a VS Code-team-owned extension whose designated tracker is https://github.com/microsoft/vscode-remote-release.
