Local copying must preserve image content, and a failed cross-origin copy must not silently masquerade as success with alt text.
- **Behavior:**

  > The Markdown preview's Copy Image command has been confirmed to paste only alt text after an attempted fix. Successful copying should yield usable image content in an image-capable destination. When browser restrictions prevent copying, the failure should be clear rather than hidden behind text-only clipboard content, consistent with the maintainer's comment. Acceptance checks should distinguish local images, cross-origin images and preview focus transitions.
- **Trace:**

  > CopyImageCommand.execute in extensions/markdown-language-features/src/commands/copyImage.ts forwards the request to a preview, whose copyImage method in src/preview/preview.ts reveals the webview and posts a message. The handler in preview-src/index.ts calls copyImage, which briefly retries focus acquisition, draws the image to a canvas and writes a PNG ClipboardItem. Its catch path logs the error and falls back to selecting the image for document.execCommand('copy'), or copying the source URL when no selection exists. https://github.com/microsoft/vscode/pull/240508 introduced this fallback, but the maintainer confirmed alt-text-only pasting and reopened https://github.com/microsoft/vscode/issues/205624 afterward. Runtime investigation must establish the current clipboard formats and whether CORS failure, focus timing or both explain the remaining symptom; the source alone does not establish a complete fix boundary.
