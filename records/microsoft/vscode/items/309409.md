# Issue #309409 — Add "Don't Save All" button

[https://github.com/microsoft/vscode/issues/309409](https://github.com/microsoft/vscode/issues/309409)

## Summary

Bulk discard already exists when quitting or invoking Close All Editors, but its button is labeled "Don't Save", and some multi-editor closing paths still confirm each editor separately. Keep this open to distinguish the requested labeling improvement from an apply-to-all option for those remaining paths.

## Change summary

Provide an explicit "Don't Save All" choice when closing multiple modified files or quitting VS Code.

## Best solution

Make the scope of discard confirmation clear: preserve existing bulk-discard behavior and determine whether this request calls for clearer plural wording, an apply-to-all choice during sequential confirmations, or both.

## Evidence

- **Existing bulk-confirmation capability:** src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts:186–219 accepts multiple filenames and changes "Save" to "Save All", but keeps "Don't Save" unchanged. Both buttons return a decision for the entire supplied list.
- **Closing all editors:** src/vs/workbench/browser/parts/editor/editorActions.ts:678–700 collects ordinary dirty editors into one confirmation and reverts that collection on DONT_SAVE. CloseAllEditorsAction registers workbench.action.closeAllEditors at lines 798–819; it excludes sticky editors. This already supplies bulk discard for that command, without the requested explicit button wording.
- **Quitting:** src/vs/workbench/services/workingCopy/electron-browser/workingCopyBackupTracker.ts:294–323 passes all modified working copies to showSaveConfirm and invokes doRevertAllBeforeShutdown on DONT_SAVE. A separate bulk-discard operation is therefore not missing from this shutdown confirmation.
- **Remaining distinction between closing paths:** src/vs/workbench/browser/parts/editor/editorGroupView.ts:handleCloseConfirmation processes editors recursively, while doHandleCloseConfirmation calls showSaveConfirm([name]) for each ordinary editor. closeEditors and closeAllEditors use this path, so the global Close All Editors command does not establish equivalent batch confirmation for every multi-file closing operation.
