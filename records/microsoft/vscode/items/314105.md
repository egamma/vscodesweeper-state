# Issue #314105 — Update button shows up a second too late on new windows

[https://github.com/microsoft/vscode/issues/314105](https://github.com/microsoft/vscode/issues/314105)

## Summary

The accidental activation remains possible on current main: a new renderer initially has no update button, then asynchronously inserts an actionable Restart to Update control into the title bar. The issue should stay open while maintainers choose how to keep that hit target stable or protect the restart action.

## Change summary

Prevent the update control from appearing beneath an in-progress title-bar double-click and accidentally restarting all VS Code windows.

## Best solution

Make the title-bar geometry and action safety stable while the initial update state is loading, so a gesture begun on draggable title-bar space cannot become a restart action. Preserve update discoverability and keyboard accessibility without requiring users to disable the indicator.

## Plan brief

- **Likely files:** `src/vs/platform/update/common/updateIpc.ts`, `src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts`, `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/contrib/update/test/browser/updateTitleBarEntry.test.ts`
- **Validation:** With an update already in Ready state, open a new Windows window and immediately double-click the title-bar location where the update control will render; the window must maximize without invoking `update.restart`. Add coverage for the Uninitialized-to-Ready transition and verify the update action remains keyboard accessible once intentionally activated.
- **Behavior:**

  > Opening a new window while an update is ready must not allow an in-progress title-bar double-click to turn into a Restart to Update activation. The same gesture should maximize the window, while an intentional pointer or keyboard activation of the update control should remain available. Normal update-state transitions and update discoverability must remain intact.
- **Trace:**

  > UpdateChannelClient in src/vs/platform/update/common/updateIpc.ts starts at State.Uninitialized and asynchronously retrieves the main-process state. UpdateTitleBarContribution in src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts initially leaves UpdateTitleBarContext false, then enables it when the retrieved state is actionable, causing MenuId.TitleBarUpdate to insert a control into existing title-bar space. UpdateTitleBarEntry.runAction maps Ready directly to `update.restart`, so a pointer event landing on the newly inserted control can restart VS Code. The `update.titleBar` setting is only a workaround because it removes the indicator entirely. Preserve the update state machine, non-title-bar update commands, and accessible keyboard operation; the uncertainty begins at the desired visible safety behavior during initialization.
- **Open decisions:**
  - Should the default UI reserve a stable non-actionable update position while the initial state loads, prevent activation during the opening gesture, or confirm a title-bar Restart to Update action?

## Evidence

- **asynchronous initial state:** On current main, src/vs/platform/update/common/updateIpc.ts initializes UpdateChannelClient to State.Uninitialized and only later applies `_getInitialState` through a promise, creating the reported startup interval.
- **dynamic title-bar insertion:** src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts keeps UpdateTitleBarContext false for non-actionable states and sets it true for AvailableForDownload, Downloaded, or Ready; the MenuId.TitleBarUpdate item is therefore inserted after the asynchronous state arrives.
- **immediate restart action:** UpdateTitleBarEntry.runAction in src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts maps StateType.Ready directly to `update.restart`; src/vs/workbench/contrib/update/browser/update.ts registers that title-bar action without a confirmation step.
- **existing workaround is incomplete:** The `update.titleBar` setting in src/vs/platform/update/common/update.config.contribution.ts can hide the indicator, but that removes the title-bar update surface rather than making its default interaction safe.
- **still present on main:** Post-report commits 5bd47d12fb6eadbe3f90ad046bcd9bda41b9f5f2 and 84ed7dda5079317e1b886613892607ebf23ca3ae repositioned the update toolbar, but the current implementation still conditionally inserts it after update-state initialization and neither commit references https://github.com/microsoft/vscode/issues/314105.
