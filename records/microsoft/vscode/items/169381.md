## Summary

Keep open: current task command construction still mishandles the supplied Bash input under both strong and escape quoting. The issue is already correctly routed to tasks, and no verified older canonical owns this symptom.

## Change summary

Preserve literal input-variable values containing apostrophes and shell metacharacters when passing them as explicitly quoted task arguments.

## Best solution

Make explicitly quoted Bash task arguments reach the invoked program as one unchanged argument, including the literal input `';'`. Cover the command-construction path with regression checks while preserving process-task behavior and intentional shell-command syntax.
