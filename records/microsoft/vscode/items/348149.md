# Issue #348149 — Remote DevContainer: chat.pluginLocations makes sessions fail

[https://github.com/microsoft/vscode/issues/348149](https://github.com/microsoft/vscode/issues/348149)

## Summary

Keep open to investigate why resuming a Dev Container session substitutes an installed-plugin path for a working project-local plugin. Current source resolves workspace-relative plugin locations, but the reported resume failure remains unconfirmed; the reported workflow and error suffice for a targeted retest.

## Change summary

Sessions using project-local plugins through chat.pluginLocations fail to resume because initialization looks for the plugin under the container user's installed-plugins directory.

## Best solution

Preserve the configured plugin's effective location across session restoration so project-local plugins remain usable without copying them into the container home. Establish whether the incorrect path originates in VS Code's customization handoff or the Copilot runtime before choosing the fix boundary.
