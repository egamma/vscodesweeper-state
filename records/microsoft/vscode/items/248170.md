# Issue #248170 — Cannot connect to MCP server via SSE using trusted developer certificate

[https://github.com/microsoft/vscode/issues/248170](https://github.com/microsoft/vscode/issues/248170)

## Summary

Keep open as a confirmed Electron/BoringSSL upstream defect. The latest investigation isolates certificate-validation behavior that differs from standalone Node.js/OpenSSL, and no merged upstream fix or VS Code workaround is identified.

## Change summary

Allow VS Code's MCP HTTP transports to connect securely to trusted self-signed certificates, including ASP.NET Core development certificates.

## Best solution

Bring Electron's Node/BoringSSL self-signed-certificate validation in line with standalone Node.js/OpenSSL, then consume that fix in VS Code. If an upstream fix is not viable, evaluate a narrowly scoped proxy-agent transport workaround without disabling TLS verification globally.

- **upstream root cause:** The latest investigation at https://github.com/microsoft/vscode/issues/248170#issuecomment-3379193314 reports that Electron 43.6.0 with BoringSSL rejects a trusted self-signed certificate lacking `keyCertSign`, while standalone Node.js with OpenSSL accepts the otherwise identical certificate.

- **related certificate fix is insufficient:** dotnet/aspnetcore#64261 fixed missing SKI/AKI generation, but the later controlled comparison identifies a distinct BoringSSL trust rule involving `keyCertSign`; there is no evidence that the ASP.NET Core change resolves this canonical report.
