# Issue #295948 — macOS: Overwriting updates sometimes returns no update after attempting to download the second one

[https://github.com/microsoft/vscode/issues/295948](https://github.com/microsoft/vscode/issues/295948)

## Summary

Keep open: the logs identify a concrete overwrite attempt that abandons a ready update and returns to idle. Update-feed handling has changed since the report, but the recorded sequence suffices to retest and no verified fix or older canonical establishes that this is resolved.

## Change summary

On macOS, attempting to replace an already-downloaded update with a newer one can return no update and leave the application idle instead of ready to restart.

## Best solution

Ensure the macOS overwrite flow retains a usable update when the second check reports no update, and distinguish feed-response inconsistencies from Electron updater behavior before choosing the correction.

- **Behavior:**

  > A macOS user has an update downloaded and ready, then requests restart after a newer update becomes available. The reported failure postpones restart to fetch the newer update but returns to idle without completing the replacement. Acceptance should establish that successful replacement reaches Ready for the newer update and that a no-update response does not discard access to a usable pending update. Ordinary checks with no pending update must retain their existing behavior.
- **Trace:**

  > AbstractUpdateService.quitAndInstall calls checkForOverwriteUpdates, which probes the pending commit and starts a replacement when it is no longer latest. DarwinUpdateService.doCheckForUpdates transitions to CheckingForUpdates and delegates to electron.autoUpdater; onUpdateNotAvailable then transitions to Idle without retaining the prior Ready state. This matches the reported state progression conditionally, but the reason Electron reports no update after the preceding positive probe is unresolved. The latest-version probe now passes internalOrg following https://github.com/microsoft/vscode/commit/9fc3d42d22bce4b6d57feb442e417c74aaa856d0, so reproduce with current feed parameters before attributing the failure to the state machine or its dependency. Keep ordinary no-update checks, update-mode handling, metered-connection behavior, and non-macOS installation semantics unchanged.
