# Issue #299190 — Weird ask questions UI

[https://github.com/microsoft/vscode/issues/299190](https://github.com/microsoft/vscode/issues/299190)

## Summary

Keep open: current main still renders a numeric shortcut beside every multi-select checkbox, reproducing the visually competing affordances. This is also a team-authored, accepted bug with a maintainer-directed polish effort, so a judgment close is barred.

## Change summary

Simplify multi-select Ask Questions options so numeric shortcut cues do not compete visually with their checkboxes.

## Best solution

Give each multi-select option one clear visual selection affordance—the checkbox—while preserving accessible arrow/space navigation and deciding whether number-key shortcuts should remain undisclosed or receive a quieter, non-competing cue.

- **Behavior:**

  > A multi-select Ask Questions card should feel calm and focused: each option has an unmistakable checkbox, without a second keybinding-like badge competing for attention. Pointer and keyboard users must still be able to toggle options, navigate the list, enter a custom answer, and submit. Acceptance should cover the approved shortcut presentation and preserve accessible labels and selection state.
- **Trace:**

  > On current main, `ChatQuestionCarouselPart.renderMultiSelect` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts appends a visible `.chat-question-list-number` and a `Checkbox` to every option row. The same method handles arrow navigation, Space toggling, and Digit1-Digit9 shortcuts, while chatQuestionCarousel.css lays the number and checkbox out as separate visible controls. The maintainer comment at https://github.com/microsoft/vscode/issues/299190#issuecomment-3998937966 establishes that keybinding-like badges should no longer lead the UI. Keep the change within questionnaire option presentation and interaction; do not alter answer serialization, single-select semantics, freeform answers, or carousel submission.
- **Open decisions:**
  - Should multi-select rows hide number-key shortcuts completely and rely on arrow/space navigation, or retain Digit1-Digit9 behavior with a quieter visual cue that does not compete with the checkbox?
