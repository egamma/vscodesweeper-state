# Issue #336033 — Can't use BYOK when github copilot is down.

[https://github.com/microsoft/vscode/issues/336033](https://github.com/microsoft/vscode/issues/336033)

## Summary

Keep open as a request for BYOK availability during GitHub authentication outages. Current source supports some token-independent operation, but does not establish that the reported outage and forced-sign-out scenario is resolved.

## Change summary

Allow configured BYOK models to remain usable when GitHub authentication or Copilot services are unavailable.

## Best solution

Make independent BYOK chat resilient to transient GitHub authentication failures while preserving enterprise BYOK restrictions and authentication requirements for GitHub-backed operations. Coordinate with the related authentication work, but retain this outage-specific requirement until its behavior is explicitly covered.

- **Validation:** With a working configured BYOK endpoint, simulate HTTP 503 from GitHub authentication during an existing session and after reload; verify model availability and successful BYOK turns. Exercise token-only loss separately from identity changes, restore GitHub availability, and verify explicitly denied enterprise BYOK remains denied. Extend the existing BYOK contribution and authentication tests to cover the agreed outage semantics.
- **Behavior:**

  > A user with a working BYOK configuration should not lose independent chat solely because GitHub authentication returns a transient HTTP 503. Acceptance should cover an ongoing conversation and a window reload during the outage, followed by recovery without losing the configured model. GitHub-backed models and operations must retain their normal authentication requirements, and explicit enterprise BYOK restrictions must remain effective.
- **Trace:**

  > BYOKContrib._applyPolicy uses isClientBYOKAllowed, which permits a missing GitHub session but rejects an existing session without a Copilot token. Token-loss-only events preserve registrations, whereas authentication-change events reevaluate policy; the current contribution test explicitly records this distinction. ConversationFeature already supports activation from available BYOK models, so complete authentication independence is partially implemented rather than wholly absent. The reporter's HTTP 503-to-sign-out transition remains untraced, and the affected provider and harness are unspecified. Related work is https://github.com/microsoft/vscode/issues/324310 and https://github.com/microsoft/vscode/issues/329667; outage acknowledgment appears at https://github.com/microsoft/vscode/issues/330408#issuecomment-5318403631. Diagnose the outage lifecycle before defining coverage, and do not turn transient availability handling into a bypass of explicit organizational policy.
- **Open decisions:**
  - During a GitHub outage, should BYOK remain available only when permission was previously established, or also on a signed-in cold start where no Copilot token or prior policy decision is available?
