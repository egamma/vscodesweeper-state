# Issue #200531 — Click scroll bar by page not smooth(Editor,Workbench list )

[https://github.com/microsoft/vscode/issues/200531](https://github.com/microsoft/vscode/issues/200531)

## Summary

The bug remains on current main: editor and workbench lists configure smooth scrolling, but scrollbar-track page clicks explicitly use the immediate-scroll path. No open canonical issue found owns this mismatch.

## Change summary

Scrollbar-track clicks should animate when page scrolling and smooth scrolling are both enabled in the editor or a workbench list.

## Best solution

Honor the configured smooth-scroll duration for page-based scrollbar-track clicks while preserving immediate thumb dragging and existing behavior when smooth scrolling is disabled.

- **Behavior:**

  > With `scrollByPage` and smooth scrolling enabled, clicking the scrollbar track in an editor or workbench list should animate by one page. Disabling smooth scrolling should retain an immediate page movement. Dragging the scrollbar thumb must remain immediate and responsive, and ordinary wheel and keyboard scrolling must remain unchanged.
- **Trace:**

  > The editor sets its animation duration in `ViewLayout._configureSmoothScrollDuration` in src/vs/editor/common/viewLayout/viewLayout.ts, while lists set it when constructing `Scrollable` in src/vs/base/browser/ui/list/listView.ts. Both use `AbstractScrollbar._onPointerDown` in src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts, where the paged target is calculated correctly but passed to `_setDesiredScrollPositionNow`. That helper calls `Scrollable.setScrollPositionNow`, whose implementation in src/vs/base/common/scrollable.ts explicitly bypasses and cancels smooth animation. The boundary is scrollbar-track page clicks: do not alter thumb-dragging immediacy or unrelated click-to-position, wheel, keyboard, and terminal behavior.

## Evidence

- **current source:** src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts `_onPointerDown` computes the paged destination with `getDesiredScrollPositionFromOffsetPaged`, then calls `_setDesiredScrollPositionNow`; that helper unconditionally invokes `Scrollable.setScrollPositionNow`.
- **animation bypass:** src/vs/base/common/scrollable.ts documents `setScrollPositionNow` as the non-smooth path and shows that it terminates any outstanding animation, while `setScrollPositionSmooth` honors the configured duration.
- **affected consumers:** src/vs/editor/common/viewLayout/viewLayout.ts configures the editor Scrollable from `editor.smoothScrolling`, and src/vs/base/browser/ui/list/listView.ts configures a 125 ms duration from `workbench.list.smoothScrolling`; both ultimately share the immediate scrollbar-track handler.
