# Issue #273757 — Git - Use `git mv` when moving and renaming files

[https://github.com/microsoft/vscode/issues/273757](https://github.com/microsoft/vscode/issues/273757)

## Summary

Keep open: Explorer-integrated Git moves remain unimplemented, and the linked implementation PR is still open in microsoft/vscode. The merge mentioned in the discussion was into the contributor's fork, not this repository.

## Change summary

Use git mv for Explorer file renames and moves inside Git repositories.

## Best solution

Review the existing PR's Explorer integration and staging semantics, then land or resolve that implementation candidate. Distinguish automatic staging from history preservation: Git detects renames from content rather than storing a special history-preserving move operation.

It proposes an opt-in git.autoStageOnMove setting and Explorer rename/move integration; its implementation and validation claims have not been independently verified here.
- **Discussion resolves merge confusion:** The supplied AugustDeer comment dated 2026-08-25 explains that https://github.com/reena96/vscode/pull/1 merged into the contributor's fork. The live state of https://github.com/microsoft/vscode/pull/279722 confirms that the upstream PR remains unmerged.
- **Existing capability is only partial coverage:** extensions/git/package.json registers git.rename; CommandCenter.rename in extensions/git/src/commands.ts invokes repository.move, which reaches the ['mv', from, to] command in extensions/git/src/git.ts. This explicit Git command already offers a workaround, but does not replace normal Explorer rename and move operations.
- **Explorer integration remains absent:** src/vs/workbench/contrib/files/browser/fileActions.ts performs Explorer renames and cut/paste moves through explorerService.applyBulkEdit with ResourceFileEdit. Searches of extensions/git found no onWillRenameFiles, onDidRenameFiles, or autoStageOnMove integration.
- **Related reports are not open canonicals for this request:** https://github.com/microsoft/vscode/issues/236857 concerns empty historical file contents after a committed git mv, and https://github.com/microsoft/vscode/issues/210332 concerns missing File History after git mv. Both are open, but neither owns automatic Explorer integration. The directly matching older https://github.com/microsoft/vscode/issues/142821 is closed and cannot serve as a duplicate target.
- **Rename detection does not require git mv:** https://github.com/microsoft/vscode/issues/142821#issuecomment-1652464151 explains content-based rename detection; the maintainer comment at https://github.com/microsoft/vscode/issues/142821#issuecomment-2604895670 identifies git.similarityThreshold as controlling detection in status and commit views. Those capabilities address detection, not the requested automatic staging through Explorer.
