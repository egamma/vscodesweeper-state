# Issue #332721 — TernarySearchTree.has reports true for strict prefixes of stored keys

[https://github.com/microsoft/vscode/issues/332721](https://github.com/microsoft/vscode/issues/332721)

## Summary

The strict-prefix membership defect remains in current source. Keep this open while the explicitly linked fixing PR is reviewed; it has not merged.

## Change summary

Make TernarySearchTree.has reject unstored strict prefixes while preserving membership for explicitly stored keys.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/332722, preserving the existing distinction between exact membership and subtree existence. Explicitly stored undefined values must still count as present, so agreement with get(key) !== undefined is not a universal contract.

## Evidence

- **Current-source reproduction:** src/vs/base/common/ternarySearchTree.ts:479–508: _getNode stops when the query iterator ends, including at an intermediate node. After set('foobar', 1), the nodes for 'foo' and 'f' have no value but have a mid child; has therefore returns true while get returns undefined.
- **Reachable configuration impact:** src/vs/platform/contextkey/browser/contextKeyService.ts:151–163: ConfigAwareContextValuesContainer.getValue returns the cached trie value whenever has(key) succeeds. Caching config.editor.fontSize first consequently makes a later config.editor lookup return undefined without consulting the configuration service.
- **Existing membership contract:** src/vs/base/common/ternarySearchTree.ts:252–263 stores explicit undefined through Undef.Val. src/vs/base/test/common/ternarySearchtree.test.ts:244–262 explicitly requires has('foobar') to remain true after set('foobar', undefined), although get('foobar') returns undefined. The issue's general get-based equivalence needs this qualification.
- **Open fixing PR:** https://github.com/microsoft/vscode/pull/332722 is OPEN, has no mergedAt timestamp, and explicitly says Fixes #332721. Its diff checks node.value rather than node.mid, preserving the undefined sentinel, and adds strict-prefix and falsy-value assertions. This is an existing implementation candidate, not a completed fix; no tests were executed during this read-only review.
