# Issue #309620 — Agents: initial session list focus shows no indication

[https://github.com/microsoft/vscode/issues/309620](https://github.com/microsoft/vscode/issues/309620)

## Summary

Still reproduces on current main: the earlier cited fix commit (already refuted) only made the *explicit* `SessionsList.focus()` method fall back to `tree.focusFirst()` when nothing is focused — but that method is only invoked by a few programmatic callers (the 'New' button handler, storage-cleanup notice, archive notification). When a user Tabs into the tree natively, the browser just moves DOM focus onto the tree's container; the tree's own `onDidFocus` handler (sessionsList.ts:4069) only updates `focusedGuideSessionIds`/context, it never calls `focusFirst()`. So native keyboard Tab-navigation — exactly the reported repro — still leaves no row focused until an arrow key is pressed.

## Change summary

After reloading the window and Tab-navigating to the Agents sessions list, no row shows a focus indicator until an arrow key is pressed.

## Best solution

In SessionsList's tree setup (src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts), call `this.tree.focusFirst()` from the tree's `onDidFocus` handler whenever `this.tree.getFocus().length === 0`, mirroring the guard already present in the explicit `focus()` method, so native Tab focus (not just programmatic calls) seeds an initial row focus.
