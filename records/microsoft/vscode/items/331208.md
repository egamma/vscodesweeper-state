# Issue #331208 — Duplicate vscode pets if you have both a new and existing chat

[https://github.com/microsoft/vscode/issues/331208](https://github.com/microsoft/vscode/issues/331208)

## Summary

Freshly filed, team-authored bug with a clear repro screenshot; the pet-visibility logic in chatWidget.ts looks like a plausible source of the duplicate-pet defect, but I found no fix commit or linked PR, so this must stay open per the team-authored keep-open rule.

## Change summary

When two chat widgets (a new and an existing chat) are shown side by side, both display an active vscode pet instead of only the focused one.

## Best solution

Investigate the per-widget `isLatestFocusedWidgetInWindow` observable in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts (around line 1023) — it's seeded from `chatWidgetService.lastFocusedWidget === this` at widget-creation time and only updated via `onDidChangeFocusedWidget`, which can leave a second widget created after the last focus-change event believing it is also the focused one, so both instantiate an active `ChatPetWidget`.
