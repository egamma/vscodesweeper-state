# Issue #335090 — Change flow when viewing .code-workspace file contents

[https://github.com/microsoft/vscode/issues/335090](https://github.com/microsoft/vscode/issues/335090)

## Summary

Reasonable UX improvement request for a real, source-confirmed gap: the 'Open Workspace' button rendered in .code-workspace text files calls hostService.openWindow(...) without forceNewWindow, so it reuses the current window and can trigger a data-loss-risk save prompt for unrelated unsaved editors. New issue with no traction yet, but the underlying behavior is real and worth a maintainer product call.

## Change summary

Clicking the 'Open Workspace' button shown when viewing a .code-workspace file as text reuses the current window (prompting to save unrelated unsaved editors) instead of opening a new window, risking accidental data loss.

## Best solution

In the 'workbench.action.openWorkspaceFromEditor' action (src/vs/workbench/contrib/workspaces/browser/workspaces.contribution.ts), consider opening in a new window (forceNewWindow: true) when other editors besides the workspace file are open in the current window, similar to how 'Duplicate as Workspace in New Window' always forces a new window — this needs a maintainer UX decision rather than an automatic fix.

## Evidence
