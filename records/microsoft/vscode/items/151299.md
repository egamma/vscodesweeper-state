# Issue #151299 — Change the "Run and Debug" View's "Play" icon to a "Connect" icon when an Attach Mode Configuration is Selected

[https://github.com/microsoft/vscode/issues/151299](https://github.com/microsoft/vscode/issues/151299)

## Summary

The requested distinction remains absent on current main, and the backlog request has 35 community upvotes. Keep it open for a debug UX decision covering attach, launch, and compound configurations.

## Change summary

Show a connect-oriented start icon when the selected debug configuration attaches to an existing target instead of launching one.

## Best solution

Give attach configurations an action icon that communicates connection without changing launch behavior, while defining a stable fallback for compound and dynamically resolved configurations. The debug UX owner should first decide whether this is automatic from `request`, explicitly configurable, or a uniform icon for all session types.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugActionViewItems.ts`, `src/vs/workbench/contrib/debug/browser/debugIcons.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/contrib/debug/test/browser/debugConfigurationManager.test.ts`
- **Validation:** Add a browser unit test for the Run and Debug start action that selects launch, attach, and compound configurations and verifies the agreed icon behavior after each selection change; run the targeted debug browser test suite.
- **Behavior:**

  > The Run and Debug start action clearly communicates whether activating the selected configuration launches code or attaches to an existing target. Launch configurations retain the familiar start/play affordance. Attach configurations use the maintainer-approved connect affordance, and compound or dynamically resolved configurations follow an explicitly defined stable fallback. Changing the selected configuration updates the action consistently without changing how starting, keyboard activation, or configuration selection works.
- **Trace:**

  > The start control is `StartDebugActionViewItem` in src/vs/workbench/contrib/debug/browser/debugActionViewItems.ts. Its `render()` method creates the action with the fixed `debugStart` icon, while `updateOptions()` reacts to selection changes but stores only labels and handlers. `IConfig.request` in src/vs/workbench/contrib/debug/common/debug.ts distinguishes `launch` and `attach`; `ICompound` has no single request value, which is where the source trace stops and the product decision begins. Connect-oriented codicons now exist in src/vs/base/common/codiconsLibrary.ts. Preserve command execution, keyboard behavior, dropdown contents, debug adapter semantics, and running-session stop/disconnect controls; this request concerns only the pre-session Run and Debug start affordance.
- **Open decisions:**
  - Should the icon change automatically from the selected configuration's `request` value, be explicitly configurable by the configuration or extension, or remain uniform across all debug session types?
  - What icon should the start action show for compound configurations containing both launch and attach entries?
  - What fallback should appear when a dynamic configuration's request type is unavailable until after provider resolution?
