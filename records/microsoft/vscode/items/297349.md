# Issue #297349 — Chat panel should virtualize DOM for long conversations (performance degrades over time)

[https://github.com/microsoft/vscode/issues/297349](https://github.com/microsoft/vscode/issues/297349)

## Summary

The long-session slowdown has multiple independent confirmations and remains worth investigating, but the proposed root cause is outdated: current chat rows are already viewport-virtualized. The remaining problem likely involves retained tool/edit resources or expensive rendering work associated with long agent transcripts.

## Change summary

Long Copilot agent conversations progressively increase renderer memory and make typing, scrolling, clicking, and resizing sluggish, especially after file-edit tool calls.

## Best solution

Profile a 100+ turn conversation containing repeated file-edit tools, identify resources or layout work that continue growing despite row virtualization, and make heap usage, DOM complexity, and interaction latency plateau as older turns leave the viewport.

## Evidence

- **current virtualization:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts constructs the transcript as a WorkbenchObjectTree with dynamic heights, while ChatListDelegate in chatListRenderer.ts extends CachedListVirtualDelegate. src/vs/base/browser/ui/list/listView.ts computes a viewport render range and removes rows outside it.
- **offscreen cleanup:** ChatListItemRenderer.disposeElement in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts clears element disposables, code-block and file-tree registrations, toolbar contexts, and token-stat hovers when a virtualized row leaves the viewport. This contradicts the report's claim that every message necessarily remains mounted in the DOM.
- **confirmed symptom:** Several commenters on https://github.com/microsoft/vscode/issues/297349 independently report progressively worsening interaction latency and relief after reloading the window; later comments specifically associate the increase with apply_patch/file-edit output and diff visualization.
- **related profiling:** The related investigation at https://github.com/microsoft/vscode/issues/294576#issuecomment-4202663343 confirmed multi-second major-GC pauses during the same class of UI jank, although it did not establish transcript DOM retention as the cause.
- **validation gap:** scripts/chat-simulation/common/perf-scenarios.js defines the long-conversation scenario with only 10 user turns, and scripts/chat-simulation/test-chat-mem-leaks.js measures cleanup after opening a fresh chat. Neither currently exercises the reported 100+ turn same-session growth with repeated edit tools.
