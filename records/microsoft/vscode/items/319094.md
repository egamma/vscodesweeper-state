# Issue #319094 — chat.tools.autoApprove: true does not suppress approval prompts for built-in agent tools

[https://github.com/microsoft/vscode/issues/319094](https://github.com/microsoft/vscode/issues/319094)

## Summary

The setting `chat.tools.autoApprove` referenced in the report does not exist — the correct setting is `chat.tools.global.autoApprove`, which deliberately requires a one-time opt-in confirmation dialog before activating due to its extreme security implications. This is by design.

## Change summary

Built-in agent tools still prompt for approval despite setting `chat.tools.autoApprove` and `chat.tools.global.autoApprove` to `true`.

## Best solution

Close as designed. The setting `chat.tools.autoApprove` does not exist — the reporter likely confused it with `chat.tools.edits.autoApprove` (file-edit auto-approval only). The real global auto-approve setting (`chat.tools.global.autoApprove`) intentionally requires a one-time security confirmation dialog before it takes effect. Alternatively, the session-level permission picker in the chat input bar can be set to "Auto-Approve" or "Autopilot" mode to bypass tool approval for a given session.

- **Proposed comment:**

  > Thanks for the report. A couple of things are at play here:
  > 
  > 1. **`chat.tools.autoApprove` is not a valid setting.** The correct settings are:
  >    - `chat.tools.global.autoApprove` — the global "YOLO mode" that disables all tool approval
  >    - `chat.tools.edits.autoApprove` — controls auto-approval of file edits only (glob patterns)
  > 
  > 2. **`chat.tools.global.autoApprove: true` deliberately requires a one-time opt-in confirmation dialog** before it takes effect, due to its extreme security implications. When you first trigger a tool call with this setting enabled, you should see an "Enable global auto approve?" warning dialog — clicking "Enable" there will activate it for all subsequent tool calls.
  > 
  > 3. **An alternative approach:** You can use the permission-level picker in the chat input bar (the dropdown next to the mode selector) and set it to "Auto-Approve" to bypass tool approval for the current session without the global setting.
  > 
  > Since the behavior is intentional, I'm closing this as by-design. If you've already confirmed the opt-in dialog and tools still prompt, please open a new issue with those specific details.

## Evidence

- **non-existent setting:** `chat.tools.autoApprove` is not registered as a configuration key anywhere in the codebase. The actual settings are `chat.tools.global.autoApprove` (YOLO mode), `chat.tools.edits.autoApprove` (file edits), and per-tool eligibility via `chat.tools.eligibleForAutoApproval`.
- **opt-in dialog by design:** In `src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts` (line 1427–1499), `_checkGlobalAutoApprove()` checks for a `GlobalAutoApproveOptIn` storage flag. If not set, it shows a warning dialog ('Enable global auto approve?') requiring the user to confirm. This is deliberately gated as a security measure — the setting alone is not sufficient.
- **setting description confirms danger:** The `chat.tools.global.autoApprove` setting description (line 579 of chat.shared.contribution.ts) explicitly warns: 'This is extremely dangerous and is *never* recommended... This feature disables critical security protections.'
