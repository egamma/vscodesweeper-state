# Issue #321548 — Extension host OOM crash: glob.ts compiles an arbitrarily long watcher pattern into a pathological regex (regExp.test blows the V8 heap)

[https://github.com/microsoft/vscode/issues/321548](https://github.com/microsoft/vscode/issues/321548)

## Summary

Confirmed on main: glob.ts compiles arbitrary-length pattern strings into regexes with no length/complexity guard, and a pathological pattern causes catastrophic backtracking that OOM-kills the extension host. The defect is in core, not in the triggering extension.

## Change summary

An arbitrarily long, non-glob string passed as a watcher pattern causes glob.ts to compile a pathological regex that OOM-crashes the extension host on the first match attempt.

## Best solution

Add a defense-in-depth guard in glob.ts: reject (return NULL matcher for) patterns exceeding a reasonable length threshold (e.g. 1–2 KB) before they reach parseRegExp/toRegExp. Additionally or alternatively, add a regex complexity check (e.g. cap the number of path-separator character classes or total regex length). The fix belongs in src/vs/base/common/glob.ts, likely in parsePattern or toRegExp.
