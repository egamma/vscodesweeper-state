## Evidence

- **Reporter narrowed the trigger:** In https://github.com/microsoft/vscode/issues/314564, the reporter clarified on 2026-05-08 that command editing becomes unavailable only when sandboxing is enabled through chat.agent.sandbox.enabled. The reported environment is Windows with WSL Ubuntu.
- **Current source explains the disabled editor:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/commandLinePresenter/sandboxedCommandLinePresenter.ts returns a presentation result whenever the sandbox service is enabled. RunInTerminalTool installs that presenter and assigns its result to toolSpecificData.presentationOverrides in runInTerminalTool.ts:1236-1268.
- **Intentional read-only boundary:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolConfirmationSubPart.ts computes isReadOnly from presentationOverrides or editable === false and registers command-edit tracking only when the editor is writable. Its comment explicitly explains that presentation overrides can differ from the executable command. This is an intentional implementation restriction, rather than an unexplained editor malfunction.
- **Existing capability does not cover the request:** The same confirmation component supports editable commands without presentation overrides, and RunInTerminalTool selects commandLine.userEdited for execution. SandboxedCommandLinePresenter creates an override even for ordinary shell commands; its existing tests explicitly cover enabled sandboxing and non-sandboxed commands while enabled. Ordinary command editing therefore does not satisfy editing with sandboxing retained.
- **Related issue has a different failure:** https://github.com/microsoft/vscode/issues/293310 is open but concerns Claude Agent SDK confirmations accepting edits and then silently executing the original command. The closed https://github.com/microsoft/vscode/issues/307956 was redirected there and describes that same ignored-edit symptom. Neither establishes a canonical for this report's sandbox-specific, read-only editor.
- **Review limits:** Read-only source inspection confirms the restriction remains in the checkout. No runtime reproduction, build, or tests were performed, and the checkout remained unchanged. Searches for sandbox command-editing reports did not establish a matching canonical or a landed fix.
