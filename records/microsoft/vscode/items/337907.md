# Issue #337907 — Reporting an issue for an extension fails silently if that extension does not have an issue reporting URL

[https://github.com/microsoft/vscode/issues/337907](https://github.com/microsoft/vscode/issues/337907)

## Summary

Traced this to a real gap in baseIssueReporterService.ts: when a selected extension has neither a GitHub-matching bugsUrl/repositoryUrl nor any bugsUrl at all, createIssue() falls through to `getIssueUrl()` returning an empty string, and the only feedback is `console.error('No issue url found')` — no dialog, toast, or visible message, exactly matching 'nothing happens' on submit.

## Change summary

Clicking submit in the issue reporter for an extension with no configured bug-report URL fails without any user-visible feedback.

## Best solution

Surface a user-visible error (reuse the existing `extension-selection-validation-error-no-url` message / issueFormService dialog pattern used for the clipboard-too-large case) instead of only logging to console when `getIssueUrl()`/`createIssue()` can't resolve a target URL; also reconcile this with the unconditional 'This extension handles issues outside of VS Code' messaging in `renderBlocks()` (line ~1167), which fires even when there is no actual bugsUrl/extensionUrl to send the user to.

- **Validation:** A test that selects/report-issues an extension with `bugsUrl: undefined, repositoryUrl: undefined` and asserts the user sees an explicit error message/dialog (not just a console.error) and/or that the submit button is disabled with the no-url validation message visible.
- **Behavior:**

  > When a user tries to report an issue for an extension that provides no bug-report URL (no `bugsUrl`, no matching `repositoryUrl`), clicking the submit/create button must show a clear, visible message explaining that this extension doesn't support issue reporting through this dialog — never a silent no-op. Behavior for extensions that DO have a valid GitHub or non-GitHub URL must be unchanged.
- **Trace:**

  > `createIssue()` in src/vs/workbench/contrib/issue/browser/baseIssueReporterService.ts calls `getIssueUrl()` → `getExtensionGitHubUrl()`, which returns `''` when both `bugsUrl` and `repositoryUrl` are absent (confirmed by reading the function at ~line 1438-1455); `createIssue()` then only does `console.error(...); return false;` (~line 1345-1349), and the calling click handlers (createAction/previewAction, ~line 134-153) swallow the `false` return with no user feedback. Separately, `renderBlocks()` (~line 1167) unconditionally relabels the button to 'Open External Issue Reporter' whenever `nonGitHubIssueUrl` is true, even with no URL, and `updateButtonStates()`/`setExtensionValidationMessage()` (~line 1518-1613) define a dedicated `extension-selection-validation-error-no-url` message that may or may not be reached depending on which flow (dropdown selection vs. direct per-extension 'Report Issue' command) triggers the render. The boundary: do not change the GitHub-submission path for extensions that DO have a resolvable URL; only add/surface feedback for the empty-URL case.
- **Open decisions:**
  - Should the no-URL case disable the submit button (relying on the existing `extension-selection-validation-error-no-url` message) or should `createIssue()` itself raise a dialog/notification when it hits the empty-URL branch?
  - Does the direct per-extension 'Report Issue' command path (openReporter/fileOnExtension pre-selected) currently invoke the same validation logic as the dropdown-selection path, or does it need its own wiring?

## Evidence

- **silent failure path:** src/vs/workbench/contrib/issue/browser/baseIssueReporterService.ts createIssue() (~line 1345-1349): `issueUrl = this.getIssueUrl()`; `if (!issueUrl) { console.error(...); return false; }` — only a console message, no UI feedback, and the caller (createAction/previewAction handlers, ~line 134-153) just resets the submitting state on false.
- **root cause:** getExtensionGitHubUrl() (~line 1438) sets `nonGitHubIssueUrl = true` and returns `bugsUrl || extensionUrl || ''` — when an extension has neither field set, this is `''`, so getIssueUrl() returns empty and createIssue() bails silently.
- **inconsistent UI path:** renderBlocks() (~line 1167) shows 'This extension handles issues outside of VS Code' / relabels the button to 'Open External Issue Reporter' whenever `nonGitHubIssueUrl` is true, with no check that an actual URL exists — while a separate validation path (updateButtonStates → setExtensionValidationMessage, ~line 1518-1613) already defines an `extension-selection-validation-error-no-url` message for exactly this no-URL case, but it's unclear these two paths are reconciled for the direct per-extension 'Report Issue' command flow described in the repro steps.
- **no existing test coverage:** src/vs/workbench/contrib/issue/test/browser/baseIssueReporterService.test.ts has no test exercising an extension with both bugsUrl and repositoryUrl undefined through createIssue().
