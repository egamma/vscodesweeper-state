# Issue #29669 — auto indenting issues with C# files

[https://github.com/microsoft/vscode/issues/29669](https://github.com/microsoft/vscode/issues/29669)

## Summary

Keep open: current core still lacks C# indentation rules, so moving lines preserves indentation rather than providing the requested context-sensitive correction. The related issue was closed after disabling unsupported smart movement, not after delivering C# indentation support.

## Change summary

Provide correct C# indentation when moving closing braces and adjacent lines up or down.

## Best solution

Provide C#-aware line-move indentation that handles the supplied brace-and-comment examples without disturbing unrelated code. Evaluate this against the broader tree-sitter indentation work, while retaining this older report's concrete acceptance cases.

- **Behavior:**

  > Moving a C# closing brace above the supplied comment lines and back should leave it correctly aligned for its resulting syntactic context. The adjacent-brace example should also leave both affected lines correctly indented. Comments and non-whitespace content must remain unchanged. Acceptance must cover movement in both directions rather than only Enter-key indentation.
- **Trace:**

  > The built-in C# contribution registers extensions/csharp/language-configuration.json, which currently has brackets and comment-continuation onEnterRules but no indentationRules. MoveLinesCommand.shouldAutoIndent requires indentation-rule support, so the built-in configuration cannot enter its contextual reindentation path even with editor.autoIndent set to full. The existing no-rules test deliberately preserves indentation. https://github.com/microsoft/vscode/issues/29722 closed the earlier partial-smart-movement behavior without supplying the capability requested here. https://github.com/microsoft/vscode/issues/208985 describes a possible broader indentation foundation, but does not supersede this older report. The unresolved technical scope is reliable C# indentation across syntax and comments, including interaction with configurations contributed by the installed C# extension; preserve no-rules fallback behavior for other languages.
