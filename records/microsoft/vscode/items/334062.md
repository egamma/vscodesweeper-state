# Issue #334062 — 1.136.0: no window on Linux when appmenu-gtk-module is loaded via gtk-modules (works in 1.134.0)

[https://github.com/microsoft/vscode/issues/334062](https://github.com/microsoft/vscode/issues/334062)

## Summary

Extremely well-documented regression: with the appmenu-gtk-module GTK module loaded (default on KDE Plasma desktops), the 1.136.0 browser process SIGSEGVs inside libgio/libglib during startup and the window never appears, while 1.134.0 works fine with the identical module loaded. This needs a native/Electron-side maintainer to look at what changed in the GTK/GLib integration between those releases; I can't verify the exact commit from the TypeScript source, so I'm not proposing a close.

## Change summary

Starting in 1.136.0, VS Code never opens a window on Linux/X11 when the appmenu-gtk-module GTK module is loaded (the default on KDE Plasma with appmenu-gtk3-module installed), whereas 1.134.0 works fine with the same module loaded.

## Best solution

A VS Code/Electron maintainer with native debugging tooling should compare what changed in GTK/GLib main-loop integration (or the Electron/Chromium version) between 1.134.0 and 1.136.0 that makes this third-party module's callback crash; likely candidates are src/vs/platform/*/electron-main startup flag changes or an Electron version bump, but this needs to be confirmed with the actual bisect artifacts (e.g. a bisected commit range or an Electron version diff) rather than source reading alone.
