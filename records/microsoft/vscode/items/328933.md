# Issue #328933 — Markdown editor: Undo groups typing one character at a time

[https://github.com/microsoft/vscode/issues/328933](https://github.com/microsoft/vscode/issues/328933)

## Summary

Keep open: a recent independent report confirms character-by-character undo in the integrated Markdown Editor, and a maintainer explicitly consolidated that report into this issue. Current source still forwards each text change as a separate workspace edit without typing-group metadata.

## Change summary

Group contiguous Markdown Editor typing into meaningful undo steps instead of requiring one undo per character.

## Best solution

Preserve the backing TextDocument as the authoritative undo history while making natural typing form meaningful groups across the renderer-to-host bridge. Establish the intended word-versus-phrase granularity before implementing grouping and its semantic boundaries.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/markdown-editor-src/editor.ts`, `extensions/markdown-language-features/src/preview/markdownEditorProtocol.ts`, `extensions/markdown-language-features/src/preview/markdownEditorProvider.ts`, `extensions/markdown-language-features/src/test/markdownEditorBridge.test.ts`, `src/vs/workbench/api/common/extHostBulkEdits.ts`, `src/vs/workbench/contrib/bulkEdit/browser/bulkEditService.ts`
- **Validation:** In an editable saved Markdown document, type ' typed words here' using real keyboard events at approximately 120 ms per key, then invoke undo and redo through both the keyboard and native commands. Assert the agreed word-or-phrase grouping, identical document and rendered content, and separate groups after navigation, Enter, paste, pointer interaction, blur, composition boundaries, external edits, and undo/redo. Add host-history regression coverage alongside the existing Markdown editor bridge tests; insertText or paste alone does not validate natural typing.
- **Behavior:**

  > Natural keyboard typing in the experimental Markdown Editor currently creates one native undo step per character. Contiguous typing should instead produce meaningful groups, with undo and redo behaving consistently through keyboard shortcuts and native commands. The maintainer must settle whether a multi-word typing run groups by word, as in the Text Editor comparison, or as an entire phrase, as requested in the original report. Acceptance must exercise actual keyboard typing and verify that navigation, Enter, paste, pointer interaction, blur, composition boundaries, external edits, and undo/redo prevent inappropriate merging.
- **Trace:**

  > The sourceText autorun in extensions/markdown-language-features/markdown-editor-src/editor.ts forwards each observed delta to markdownEditorHost.edit; markdownEditorProtocol.ts carries ranges, text, and editEpoch but no grouping intent. MarkdownEditorProvider's edit handler queues each request and calls workspace.applyEdit separately, while its history handler drains that queue before executing native undo/redo. ExtHostBulkEdits.applyWorkspaceEdit supplies no undoRedoGroupId, and BulkEditService creates a fresh group without a matching active group, so host grouping requires investigation beyond merely attaching metadata to the RPC. The renderer deliberately omits local history recording: preserve the authoritative TextDocument history, edit ordering, stale-epoch rejection, CRLF handling, dirty state, and external-update synchronization. Existing bridge coverage is in extensions/markdown-language-features/src/test/markdownEditorBridge.test.ts, but it does not exercise natural typing or undo grouping. The recent reproduction at https://github.com/microsoft/vscode/issues/341110 was consolidated here; https://github.com/microsoft/vscode/issues/327535 concerns undo commands not applying edits and remains a distinct problem.
- **Open decisions:**
  - Should contiguous multi-word typing undo by word to match the Text Editor, or should one undo remove the entire uninterrupted phrase as the original report requests?
