# Issue #238241 — Test Run completion takes very long on many tests (after `RunHandler` is completed)

[https://github.com/microsoft/vscode/issues/238241](https://github.com/microsoft/vscode/issues/238241)

## Summary

Keep open: an independent adapter author confirmed substantial UI processing delays after test execution completes, with specific state-update triggers and workarounds. Current source still processes individual test-state updates synchronously; profiling is needed to establish the dominant cost before selecting a bounded fix.

## Change summary

Large test runs leave VS Code processing test statuses and output long after the extension's run handler finishes.

## Best solution

Make the testing result and explorer update pipeline handle thousands of rapid state transitions without a prolonged UI backlog, while preserving final results, durations, output, and cancellation semantics. Reproduce with the supplied project and distinguish result aggregation costs from tree rendering and automatic reveal before choosing an optimization.
