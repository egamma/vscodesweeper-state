[https://github.com/microsoft/vscode/issues/322571](https://github.com/microsoft/vscode/issues/322571)

## Summary

Confirmed on main: `_setDocumentSemanticTokens` does not validate `edit.deleteCount` before computing `deltaLength`, allowing a negative typed-array length. An open PR (#322575) addresses this — keeping open pending merge.

## Change summary

A semantic token edit with an oversized `deleteCount` causes a `RangeError: Invalid typed array length` crash when allocating the destination `Uint32Array`.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/322575 which validates the delete count before the allocation. The guard should clamp or reject invalid `deleteCount` values (similar to the existing `edit.start` validation at line 351) and bail out gracefully.
