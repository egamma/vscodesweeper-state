# Issue #267915 — Enable `window.autoDetectColorScheme` by default

[https://github.com/microsoft/vscode/issues/267915](https://github.com/microsoft/vscode/issues/267915)

## Summary

The requested default and migration remain missing: ordinary VS Code windows still default window.autoDetectColorScheme to false. Keep this accepted Backlog request open for a decision on enrollment, particularly whether automatic switching should require the OS itself to be configured for automatic appearance changes.

## Change summary

Enable automatic system-theme matching by default, migrating eligible built-in-theme users while preserving custom-theme preferences.

## Best solution

Agree on the default and migration eligibility before changing theme configuration and startup behavior together. Preserve explicit preferences and custom themes, and settle the thread's unconditional-versus-OS-Auto enrollment choice.

## Evidence

- **Existing capability does not cover the default:** src/vs/workbench/services/themes/common/themeConfiguration.ts registers window.autoDetectColorScheme with default: false. Enabling it explicitly selects workbench.preferredDarkColorTheme or workbench.preferredLightColorTheme; that opt-in capability does not satisfy automatic enrollment. The conditional agentsWindow default: true applies only on web and does not cover ordinary VS Code windows.
- **Desktop startup default:** src/vs/platform/theme/electron-main/themeMainServiceImpl.ts independently defines Setting.DETECT_COLOR_SCHEME with fallback false because main-process configuration does not know registered defaults. ThemeMainService uses this setting to choose system appearance behavior.
