# Issue #309877 — Git File History Doesn't Work if File Renamed

[https://github.com/microsoft/vscode/issues/309877](https://github.com/microsoft/vscode/issues/309877)

## Summary

The rename-history defect remains in current source, but the same Timeline comparison failure is already tracked by an older, verified open issue. Consolidate this report into that issue.

## Change summary

Timeline lists Git history across a file rename but cannot open comparisons for commits using the file's former path.

## Best solution

Track the fix in https://github.com/microsoft/vscode/issues/205244 so Timeline comparisons resolve each revision using its historical file path rather than the current path.

This satisfies the re-review requirement of an older canonical with the same observable symptom.
- **Current source confirms the shared defect:** extensions/git/src/timelineProvider.ts:140-149 requests file history with follow: true, then passes the current file URI to resolveTimelineOpenDiffCommand at line 207. extensions/git/src/commands.ts:4804-4825 constructs both historical diff URIs from that same current URI. For a commit before the isolated rename, the requested path does not exist at that revision.
- **Canonical diagnosis and workaround:** https://github.com/microsoft/vscode/issues/205244#issuecomment-3033080268 identifies the same shared-path assumption in Timeline diff construction. https://github.com/microsoft/vscode/issues/205244#issuecomment-3259656490 confirms that Open Commit works while clicking the Timeline entry does not; this alternative does not repair direct Timeline comparisons.
- **Additional matching confirmation:** https://github.com/microsoft/vscode/issues/275318 is also OPEN. https://github.com/microsoft/vscode/issues/275318#issuecomment-4994064078 confirms the same historical-path failure on VS Code 1.129.0 on macOS, and https://github.com/microsoft/vscode/issues/275318#issuecomment-5384066844 links the older canonical.
