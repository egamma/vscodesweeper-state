# Issue #301253 — replace_string_in_file / create_file tools fail with "File does not exist" on Remote SSH (NFS UNC paths)

[https://github.com/microsoft/vscode/issues/301253](https://github.com/microsoft/vscode/issues/301253)

## Summary

Still reproduces on main: when Windows connects via Remote SSH to a Linux host with NFS paths like `/nfs/mount/...`, `getFilePath` returns `\\nfs\mount\...` (UNC form via `uri.fsPath`), but `resolveFilePath` maps that UNC path back to a `file:///` URI instead of `vscode-remote://`, so `canExistingFileBeEdited` stats a nonexistent local file and returns false.

## Change summary

Copilot's `replace_string_in_file` and `create_file` tools fail with "File does not exist" on Windows→Remote SSH when the workspace is on an NFS mount whose path starts with `/nfs/...` (rendered as a UNC path `\\nfs\...`).

## Best solution

In `resolveToolInputPath` (or `resolveFilePath`), detect when the client is Windows but the workspace is remote and pass the correct `predominantScheme` (`vscode-remote`) so UNC-looking paths from the model resolve back to the remote scheme instead of `file:///`. The `read_file` tool likely sidesteps this because it takes a different path-resolution route; making the edit tools consistent with it is the fix.
