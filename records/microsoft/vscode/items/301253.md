## Summary

The reported read-versus-write path mismatch is plausible but not confirmed on current main. Source inspection shows these tools now share path-resolution code, while similar Remote SSH failures were caused by forcing Copilot to run on the Windows UI side, so the extension placement and current tool logs are needed before diagnosing a core defect.

## Change summary

Make read, replace, and create tools resolve NFS-backed Remote SSH workspace paths consistently instead of treating edit targets as nonexistent Windows UNC paths.

## Best solution

First distinguish a `remote.extensionKind` placement override from a genuine tool mismatch. If the failure persists with Copilot running on the remote extension host, preserve the remote URI scheme and authority consistently across read, replace, and create operations in the prompt path/tool resolution layer.
