# Issue #284515 — `reportFeedback` is now false by default

[https://github.com/microsoft/vscode/issues/284515](https://github.com/microsoft/vscode/issues/284515)

## Summary

The cleanup remains necessary: current main still defines the setting with a false default and uses it to hide chat issue reporting. This team-authored, under-discussion item should remain open while maintainers settle how potentially sensitive diagnostic data is disclosed or stored.

## Change summary

Remove the team-only feedback-reporting gate and decide how to make Copilot issue reporting safely available to all users.

## Best solution

Make chat issue reporting available without the team-internal setting while requiring a deliberate privacy-safe review or private-upload flow for prompt, workspace, tool, and edit diagnostics. Separately decide whether the developer STest command and semantic-search feedback command should remain internal or receive independent gates.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/configuration/common/configurationService.ts`, `extensions/copilot/src/extension/conversation/vscode-node/feedbackReporter.ts`, `extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts`, `extensions/copilot/src/extension/contextKeys/vscode-node/contextKeys.contribution.ts`, `extensions/copilot/package.json`, `src/vs/workbench/contrib/issue/browser/issueReporterOverlay.ts`, `src/vs/workbench/contrib/issue/test/browser/issueReporterOverlay.test.ts`
- **Validation:** Add targeted coverage proving that ordinary users receive the intended Report Issue affordance without the team setting and that generated diagnostic data is visibly reviewable and removable before submission; separately assert the chosen availability of Generate STest and semantic-search feedback.
- **Behavior:**

  > Copilot issue reporting is available to the intended non-team audience without requiring `chat.advanced.debug.reportFeedback`. Before diagnostic content can be submitted, users can understand that it may contain personal information, inspect it, and exclude it or use the approved private path. The Generate STest and semantic-search feedback commands retain exactly the availability selected by maintainers.
- **Trace:**

  > The setting is defined as false in extensions/copilot/src/platform/configuration/common/configurationService.ts. FeedbackReporter exposes it through `canReport`, and ChatAgentService copies that value to `ChatParticipant.supportIssueReporting`; core then gates `workbench.action.chat.reportIssueForBug` through `ChatContextKeys.responseSupportsIssueReporting`. The same setting also drives `github.copilot.debugReportFeedback`, which gates unrelated developer and search-feedback commands in extensions/copilot/package.json. FeedbackReporter sends prompt, workspace, tool, and edit data to `workbench.action.openIssueReporter`. The current IssueReporterOverlay review step displays this extension data and lets the user deselect it, but the thread has not settled whether that review is sufficient, needs an explicit warning, or should be replaced by private storage. Keep unrelated feedback telemetry and ordinary issue-reporter diagnostics outside this cleanup.
- **Open decisions:**
  - Should public chat issue reporting submit diagnostics through the existing inspect-and-exclude review step with an explicit personal-information warning, or upload them through a private storage path?
  - Does removing `chat.advanced.debug.reportFeedback` make only the chat Report Issue affordance public, or should Generate STest and semantic-search feedback also become available to non-team users?
