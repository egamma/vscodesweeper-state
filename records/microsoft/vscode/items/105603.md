# Issue #105603 — Copy/paste from custom titlebar doesn't work in markdown previews

[https://github.com/microsoft/vscode/issues/105603](https://github.com/microsoft/vscode/issues/105603)

## Summary

Keep open: the discussion confirms the custom-menu copy failure, separately from double-click navigation. Current source contains a potentially covering menu-focus fallback, but the later confirmations prevent treating that change alone as proof of resolution.

## Change summary

Copying selected Markdown preview text through a custom menu copies a blank line instead of the selected text.

## Best solution

Verify the supplied selection → Edit → Copy → external paste sequence on current Windows builds with the custom title bar. If it persists, make menu-triggered copying preserve the preview selection and target the preview rather than the source editor.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/webview/browser/webview.contribution.ts`, `src/vs/workbench/contrib/webview/browser/webviewService.ts`, `src/vs/workbench/contrib/webview/browser/webviewElement.ts`, `src/vs/workbench/contrib/webview/browser/pre/index.html`
- **Validation:** On Windows with window.titleBarStyle set to custom, open a Markdown preview, drag-select a distinctive phrase, choose Edit → Copy, and paste into an external text editor; require exactly the selected phrase. Repeat using the preview context-menu Copy and Ctrl+C, with another value initially on the clipboard to detect no-op copying. Check that copying from the source editor and unrelated text inputs remains unchanged.
- **Behavior:**

  > Selecting text in a Markdown preview and invoking Copy through the custom title-bar Edit menu should place exactly that selection on the clipboard. The report instead observes a blank line, while drag-selection followed by Ctrl+C works. Acceptance covers external paste after Edit-menu Copy, preview context-menu Copy, and Ctrl+C. Double-click navigation to the source editor is a separate behavior and is outside this issue.
- **Trace:**

  > In src/vs/workbench/contrib/webview/browser/webview.contribution.ts, overrideCommandForWebview dispatches CopyAction to the focused webview or falls back to the active WebviewInput when an action-menu-item has focus. WebviewService clears activeWebview on blur; WebviewElement.copy() sends an execCommand message that browser/pre/index.html executes in the content document. The fallback originated in https://github.com/microsoft/vscode/commit/d215fc72380047d9e9034e74ebb3e29953bdb85c and was narrowed in https://github.com/microsoft/vscode/commit/066f28822afc34968f87f7163b22ac28aa0f667e, but later discussion still reports failure. The unresolved boundary is whether current menu invocation reaches that fallback and whether the preview selection remains usable when the content document executes Copy. First establish current reproduction; preserve source-editor copying, unrelated input focus, and Markdown double-click navigation.
