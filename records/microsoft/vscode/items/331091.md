# Issue #331091 — Support keyboard Layout on Linux

[https://github.com/microsoft/vscode/issues/331091](https://github.com/microsoft/vscode/issues/331091)

## Summary

Linux desktop still lacks the web version's manual keyboard-layout selection and keyboardLayout.json workflow. Keep this request open: the existing dispatch setting does not supply that capability, and no verified canonical owns the same request.

## Change summary

Allow Linux desktop users to override keyboard-layout detection using keyboard.layout and the web version's Configure Keyboard Layout workflow.

## Best solution

Provide an opt-in Linux desktop layout override consistent with the existing web workflow, while preserving native automatic detection by default. This needs a product decision before implementation rather than treating keyboard.dispatch as equivalent functionality.

## Evidence

- **Desktop implementation gap:** src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts delegates getCurrentKeyboardLayout() and getRawKeyboardMapping() to the native service, returns an empty array from getAllKeyboardLayouts(), and does not consume keyboard.layout or keyboardLayout.json.
- **Web-only capability:** src/vs/workbench/workbench.web.main.ts imports both services/keybinding/browser/keyboardLayoutService.ts and contrib/preferences/browser/keyboardLayoutPicker.ts; workbench.desktop.main.ts instead imports electron-browser/nativeKeyboardLayout.ts. BrowserKeyboardLayoutService reads keyboard.layout and loads UserKeyboardLayout from keyboardLayoutResource; the picker implements Configure Keyboard Layout.
- **Existing setting is not coverage:** src/vs/platform/keyboardLayout/common/keyboardConfig.ts exposes keyboard.dispatch on Linux with code and keyCode options. The desktop getKeyboardMapper() uses this to select dispatch behavior, not to choose a named layout or load a user-provided mapping.
- **Older candidate has different scope:** https://github.com/microsoft/vscode/issues/1240 was verified open and its body and discussion concern contributing layout-specific default keybindings. It does not report the missing Linux desktop manual-layout configuration workflow, so it does not meet the same-symptom duplicate bar for this re-reviewed item.
- **Canonical search:** Repository issue searches for keyboard-layout overrides, manual selection, keyboardLayout.json, Change Keyboard Layout, and Configure Keyboard Layout did not establish an older open canonical covering this request. Related shortcut failures and web detection reports do not establish ownership of the requested desktop capability.
