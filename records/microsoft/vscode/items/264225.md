# Issue #264225 — Inconsistent nested markdown formatting in editor preview: strikethrough and bold render differently based on nesting order

[https://github.com/microsoft/vscode/issues/264225](https://github.com/microsoft/vscode/issues/264225)

## Summary

This reports the same underlying TextMate fontStyle behavior as #306368, which was closed as *as-designed — VS Code's TextMate implementation replaces (rather than combines) fontStyle when multiple scopes match, so nested bold-inside-strikethrough or vice versa only renders the innermost style. Proposing duplicate close against that issue.

## Change summary

Nested bold and strikethrough markdown formatting in the editor only renders the innermost font style instead of combining both.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/306368, which established that this fontStyle-replacement behavior is by design in VS Code's TextMate implementation. If the team ever decides to adopt TextMate 2.0's additive fontStyle semantics, that would be the issue to reopen.
