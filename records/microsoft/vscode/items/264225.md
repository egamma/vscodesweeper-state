# Issue #264225 — Inconsistent nested markdown formatting in editor preview: strikethrough and bold render differently based on nesting order

[https://github.com/microsoft/vscode/issues/264225](https://github.com/microsoft/vscode/issues/264225)

## Summary

Confirmed grammar bug: the strikethrough rule uses a `match` pattern (not `begin`/`end`), which limits how nested bold renders inside it. The fix belongs in the upstream grammar repo (microsoft/vscode-markdown-tm-grammar). Issue is properly labeled and should stay open.

## Change summary

When nesting bold inside strikethrough (`~~text **bold**~~`), the bold text does not render as bold in the editor, while the reverse nesting (`**text ~~strike~~**`) works correctly.

## Best solution

Fix the strikethrough rule in the upstream grammar (https://github.com/microsoft/vscode-markdown-tm-grammar) by converting it from a `match` pattern to a `begin`/`end` pattern, consistent with how bold and italic are defined. This would allow proper nested tokenization. Then update the grammar in VS Code via the usual grammar sync process. Related issue https://github.com/microsoft/vscode/issues/242167 covers a similar grammar edge case with strikethrough and underscores.

- **markdown-it renders correctly:** Testing with the bundled markdown-it (14.2.0) confirms both `~~strikethrough **bold**~~` and `**bold ~~strikethrough~~**` produce correct HTML with proper nesting. The issue is editor tokenization only.
