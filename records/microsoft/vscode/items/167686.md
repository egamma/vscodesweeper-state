# Issue #167686 — Allow jump to bracket and select to bracket to stay within brackets

[https://github.com/microsoft/vscode/issues/167686](https://github.com/microsoft/vscode/issues/167686)

## Summary

Keep this accepted Backlog request open: excluding brackets from selection is already supported, but jumping repeatedly between the interior bracket boundaries remains unsupported. The request has 23 upvotes and already carries the appropriate area label.

## Change summary

Provide discoverable bracket-navigation and selection options that keep the cursor or selection inside the bracket pair.

## Best solution

Offer opt-in navigation between the opening bracket's end and the closing bracket's start, preserving existing Go to Bracket behavior. Reuse the existing bracket-excluding selection capability and decide how both behaviors should be exposed discoverably.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/contrib/bracketMatching/test/browser/bracketMatching.test.ts`
- **Validation:** Extend the existing bracket matching suite to verify repeated opt-in jumps alternate between interior boundaries for ordinary, nested, empty, and multicursor bracket pairs, while existing default navigation and selectToBracket(false) expectations remain unchanged. Manually verify that the chosen command or configuration surface is discoverable through the intended UI.
- **Behavior:**

  > Users should be able to opt into bracket navigation that alternates between the position immediately after the opening bracket and immediately before its matching closing bracket without leaving that pair. Existing default Go to Bracket behavior must remain unchanged. Bracket-excluding selection already works through selectBrackets:false and must continue to work. Acceptance covers repeated navigation, nested and empty pairs, multiple cursors, and discoverability of the selected public surface.
- **Trace:**

  > JumpToBracketAction and SelectToBracketAction are registered in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts. BracketMatchingController.jumpToBracket resolves matching, enclosing, or next brackets and places the cursor at bracket start positions; its return to the opening bracket is outside the requested interior boundary. SelectToBracketAction already accepts selectBrackets:false, and selectToBracket uses opening-end/closing-start positions, with coverage in src/vs/editor/contrib/bracketMatching/test/browser/bracketMatching.test.ts. This establishes a missing navigation mode rather than a regression in existing behavior. Preserve default navigation, selection direction, multicursor behavior, and bracket matching semantics; do not broaden this into the previous/next navigation request at https://github.com/microsoft/vscode/issues/183994. The uncertainty is how to expose the opt-in behavior and make the existing selection option discoverable.
- **Open decisions:**
  - Should interior bracket navigation be exposed as an argument to Go to Bracket, a separately searchable command, or a configuration option?
  - What discoverable UI or command surface should expose bracket-excluding selection alongside the existing selectBrackets:false keybinding argument?
