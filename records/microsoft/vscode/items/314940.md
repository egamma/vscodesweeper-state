The plan must establish expected outcomes before these checks become executable acceptance tests; no tests were run during this read-only review.
- **Behavior:**

  > Installing a plugin should make its declared compatible plugin dependencies available without requiring users to discover and install each dependency manually. Shared dependencies need predictable version selection and actionable conflict reporting. Dependency lifecycle tracking must distinguish explicitly installed plugins from automatically installed dependencies so pruning preserves user-selected installations. Acceptance should cover transitive chains, cross-marketplace resolution, conflicts, and pruning while retaining existing trust and enterprise restrictions.
- **Trace:**

  > PluginInstallService.installPlugin in src/vs/workbench/contrib/chat/browser/pluginInstallService.ts handles trust and dispatch for one selected plugin; uninstallPlugin removes one installed entry and performs source cleanup. In src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts, IMarketplacePlugin has no dependency metadata, and readSinglePluginManifest extracts descriptive metadata rather than dependency declarations. chat.plugins.marketplaces in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts supplies marketplace discovery, not version reconciliation. These paths establish the local gap but do not establish the dependency behavior of every Agent Host provider. https://github.com/microsoft/vscode/issues/332083 documents broader migration and cross-client compatibility questions and is related, not a duplicate. Planning should verify the external manifest contract and runtime ownership; preserve marketplace trust, policy enforcement, and explicit-install intent.
- **Open decisions:**
  - Which dependency manifest contract and version-resolution semantics should VS Code guarantee across local and Agent Host runtimes?
  - When top-level plugins require incompatible versions of a shared dependency, should installation fail or support isolated versions?
  - When a dependency belongs to a previously untrusted marketplace, what approval must installation obtain before continuing?
  - Should unused automatically installed dependencies remain until an explicit prune command, or be removed automatically when their last dependent is uninstalled?
