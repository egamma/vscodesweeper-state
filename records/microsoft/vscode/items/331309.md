## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug`, `src/vs/workbench/contrib/chat`
- **Validation:** Add an agent-tool integration test that starts a debug session, emits known Debug Console lines, and verifies the tool can retrieve and search those lines without returning unrelated output.
- **Behavior:**

  > An AI agent can inspect output from the relevant active Debug Console and search it using a text or grep-style query. Results identify the associated debug session and preserve output ordering. Starting, stopping, or switching debug sessions must not expose unrelated stale console content, and normal human Debug Console behavior must remain unchanged.
- **Trace:**

  > The request spans the debug console's output/session model and the built-in agent tool surface. The review establishes the product gap and intended user outcome, but not a settled public contract for selecting among concurrent debug sessions, exposing historical output, or bounding result volume. Keep the work within first-party VS Code debug and agent tooling; do not depend on the installed third-party DebugMCP extension or alter debug adapter protocols.
- **Open decisions:**
  - Should agents read only the currently focused debug session, or select explicitly among concurrent and recently ended sessions?
  - Should search cover only retained in-memory Debug Console output, or expose a defined history beyond the console's current lifecycle?
  - What result-size and truncation contract should the tool expose for large or continuously streaming output?
