# Issue #235988 — Terminal ligatures have limited length even when the font supports longer ligatures

[https://github.com/microsoft/vscode/issues/235988](https://github.com/microsoft/vscode/issues/235988)

## Summary

Keep open as upstream tracking: the earlier change increased the supported ligature width but did not remove the texture-size limit. The subsequent confirmed failure and explicit maintainer decision to retain this issue rule out treating the merged stabilization PR as completion.

## Change summary

Long Fira Code ligatures should remain visible in the terminal instead of disappearing when their rendered width exceeds the texture limit.

## Best solution

Resolve oversized ligature rendering in xterm.js so long runs remain complete without requiring one texture wide enough for the entire run, then adopt that behavior in VS Code. Retain this issue as the downstream tracker for the remaining limitation.

## Evidence

- **Confirmed remaining failure:** https://github.com/microsoft/vscode/issues/235988#issuecomment-2623224352 confirms that long Fira Code '#' runs still stop rendering on a 16-inch MacBook Pro after the earlier change; it also records malformed '#' and '=' rendering.
- **Maintainer intent:** https://github.com/microsoft/vscode/issues/235988#issuecomment-2624861516 attributes the remaining length limitation to the device maximum texture size, identifies cell-sized ligature rendering as a more substantial solution, and explicitly says this issue will remain open to track that work. The malformed equals-sign symptom is not diagnosed there.
- **Verified upstream tracker:** https://github.com/xtermjs/xterm.js/issues/5246 is currently open and tracks the same maximum-width failure. https://github.com/xtermjs/xterm.js/issues/5246#issuecomment-2624860794 confirms that the limit remains problematic on common MacBooks.
- **Partial fix is not completion:** https://github.com/xtermjs/xterm.js/pull/5278 increased support to the device maximum texture size but explicitly left overflow beyond that size unhandled. https://github.com/microsoft/vscode/pull/237503 merged on 2025-01-08 and referenced this issue, but the January 30 confirmation and reopened state establish that its changes were insufficient.
- **Current rendering boundary:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:980-1002 loads @xterm/addon-ligatures with font-feature and fallback-sequence options; it does not implement oversized glyph splitting. Current upstream https://github.com/xtermjs/xterm.js/blob/master/addons/addon-webgl/src/TextureAtlas.ts:835-850 still places oversized glyphs on an overflow page sized to deviceMaxTextureSize.
