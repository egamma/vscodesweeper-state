# Issue #152672 — Don't select inlay hint UI when it's next to a selected variable or have a parameter to enable that

[https://github.com/microsoft/vscode/issues/152672](https://github.com/microsoft/vscode/issues/152672)

## Summary

Keep open: current source still maps double-click word selection to a visual range that includes an inlay hint immediately before the identifier. The related selection reports are newer or describe different symptoms, so none qualifies as a canonical duplicate for this re-reviewed, team-authored issue.

## Change summary

Selecting an identifier should not make an adjacent leading inlay hint appear selected.

## Best solution

Make the visual boundaries of word selection exclude adjacent inlay hints while preserving the selected document text, provider-supplied hint positions, and existing cursor navigation behavior. The relevant boundary is model-to-view cursor selection conversion, not C/C++ hint placement.

## Evidence

- **Current-source reproduction:** In src/vs/editor/browser/coreCommands.ts, WordCommand.runCoreEditorCommand invokes CursorMoveCommands.word. That method in src/vs/editor/common/cursor/cursorMoveCommands.ts:236-238 returns a model-only word selection. Cursor._setState in src/vs/editor/common/cursor/oneCursor.ts:146-153 converts its boundaries to view positions without specifying affinity. ModelLineProjectionData.translateToOutputPosition in src/vs/editor/common/modelLineProjectionData.ts:111-125 maps the word-start position before injected text at that offset unless affinity is Right. Consequently, a leading hint lies inside the resulting visual word-selection range.
- **Hint rendering and selection overlay:** InlayHintsFragments in src/vs/editor/contrib/inlayHints/browser/inlayHints.ts attaches a hint at a word's start using direction 'before'. SelectionsOverlay in src/vs/editor/browser/viewParts/selections/selections.ts renders the view-selection ranges, explaining the reporter's visual symptom without implying that hint text becomes document content.
- **Existing capability does not cover word selection:** src/vs/editor/common/viewModel/viewModelLines.ts:903-912 already excludes boundary injections when converting a nonempty model range, using Right affinity at its start and Left at its end; the model-only cursor-state path above does not use that range conversion.
