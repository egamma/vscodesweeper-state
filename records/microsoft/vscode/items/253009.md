# Issue #253009 — Caption button show 2 tooltips on Windows

[https://github.com/microsoft/vscode/issues/253009](https://github.com/microsoft/vscode/issues/253009)

## Summary

Keep open as an Electron/Windows caption-control issue. A later independent report describes the same duplicate Close tooltip on VS Code 1.109.5, and no verified fix or older canonical was found.

## Change summary

Hovering Windows caption buttons displays both an application-styled tooltip and an OS tooltip.

## Best solution

Ensure Electron's Windows title-bar overlay presents only one tooltip per caption button while preserving native window controls. Retain this older report as the tracking issue and associate the later report's precise pointer-movement reproduction with it.

- **Later independent reproduction:** https://github.com/microsoft/vscode/issues/296880 is open, was created on 2026-02-23, and reports the same Close-button symptom on VS Code 1.109.5 with extensions disabled: hover the button's bottom edge, move to its top edge, then wait approximately two seconds for a second, OS-localized tooltip. It is newer than this re-reviewed issue, so it cannot serve as its duplicate canonical.
- **Native control ownership:** src/vs/platform/window/common/window.ts defaults window controls to native and enables useWindowControlsOverlay for custom desktop title bars. src/vs/platform/windows/electron-main/windows.ts passes titleBarOverlay to Electron. NativeTitlebarPart.createContentArea in src/vs/workbench/electron-browser/parts/titlebar/titlebarPart.ts creates DOM caption buttons only when that overlay is disabled; its fallback buttons do not install tooltip handlers. This supports the existing upstream/electron classification rather than attributing the overlay tooltips to workbench hover rendering.
- **Canonical search:** Read-only searches for caption tooltips and duplicate Windows Close tooltips found the later matching report but no verified older canonical. https://github.com/microsoft/vscode/issues/185249 concerns the top-right resize hit area, not duplicate tooltips, and does not own this behavior.
