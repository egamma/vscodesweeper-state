# Issue #253728 — addfindmatchtoselection in notebooks has different behavior for single characters

[https://github.com/microsoft/vscode/issues/253728](https://github.com/microsoft/vscode/issues/253728)

## Summary

Still reproduces on main — the notebook multicursor `getWord` method always expands the selection to the full word boundary via `getWordAtPosition`, ignoring partial-word or multi-token selections like single `f` or `f.`. No fix commit references this issue.

## Change summary

Notebook Ctrl+D (addFindMatchToSelection) misbehaves for single-character and multi-token selections: it loops within the cell for single chars and drops punctuation from selections like `f.`.

## Best solution

The `getWord` method in `notebookMulticursor.ts` should respect the user's actual selection text when a range is selected, rather than always expanding to `getWordAtPosition`. For a ranged selection, use the selected text as the search string and disable the `wordSeparators` constraint in `findNextMatch`. This mirrors how the regular editor's `AddSelectionToNextFindMatchAction` handles partial-word selections.
