# Issue #331823 — Copilot `fetch failed` to send `google` apikey and to download `claud SDK`

[https://github.com/microsoft/vscode/issues/331823](https://github.com/microsoft/vscode/issues/331823)

## Summary

Traced to a real gap on current main: `getProxyAgent` in `src/vs/platform/request/node/proxy.ts` only builds an agent for `http:`/`https:` proxy URLs and silently returns `null` for `socks5://`, so the agent-host's SDK downloader (which routes through `IRequestService`) makes a direct, unproxied connection and fails. The BYOK Gemini/Anthropic providers separately construct `GoogleGenAI`/`Anthropic` SDK clients with no custom fetch/proxy wiring at all, unlike the OpenAI-compatible path which goes through the Electron-backed `_fetcherService` (Chromium's `net` module natively understands SOCKS) — matching the reporter's own diagnosis that these two code paths diverge.

## Change summary

With `http.proxy` set to a `socks5://` URL, adding a Google Gemini API key and downloading the Claude agent SDK both fail with `fetch failed`, while OpenRouter (OpenAI-compatible) and `http://` proxies work.

## Best solution

Two related gaps: (1) `getProxyAgent` (src/vs/platform/request/node/proxy.ts) needs SOCKS support (e.g. via a `socks-proxy-agent` dependency) so the Node-side `IRequestService`/agent-host SDK downloader honors `socks*://` proxies; (2) the BYOK Gemini/Anthropic providers (extensions/copilot/src/extension/byok/vscode-node/{geminiNativeProvider,anthropicProvider}.ts) construct their SDK clients with only `{ apiKey }`, bypassing the proxy-aware fetcher entirely and need a custom fetch/dispatcher wired through.

## Evidence

- **no SOCKS support in core proxy helper:** src/vs/platform/request/node/proxy.ts:34-36 checks `!/^https?:$/.test(proxyEndpoint.protocol)` and returns `null` before building any agent, so a `socks5://` `http.proxy` value is silently ignored for Node-side requests.
- **agent-host download path uses this helper:** src/vs/platform/agentHost/node/agentSdkDownloader.ts:555-583 delegates its `_fetch` to `IRequestService` ('Delegate to IRequestService (corporate proxy, strictSSL, kerberos, ...)'), which is `RequestService` in src/vs/platform/request/node/requestService.ts, using `getProxyAgent` from proxy.ts — explaining the 'Failed to download claude SDK ... Cause: fetch failed' log with a socks5 proxy.
- **Gemini/Anthropic SDKs bypass the proxy-aware fetcher:** extensions/copilot/src/extension/byok/vscode-node/geminiNativeProvider.ts:49 (`new GoogleGenAI({ apiKey })`) and anthropicProvider.ts:70 (`new Anthropic({ apiKey })`) use the third-party SDK's own HTTP client, unlike extensions/copilot/src/extension/byok/vscode-node/abstractLanguageModelChatProvider.ts:137 which calls `this._fetcherService.fetch(...)`.
- **OpenAI-compatible path uses Electron's net (SOCKS-capable):** extensions/copilot/src/platform/networking/vscode-node/electronFetcher.ts:53 (`require('electron').net`) is preferred by fetcherServiceImpl.ts, and Chromium's net stack supports SOCKS natively — matching the reporter's observation that OpenRouter has no issue.
