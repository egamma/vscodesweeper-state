# Issue #331823 — Copilot `fetch failed` to send `google` apikey and to download `claud SDK`

[https://github.com/microsoft/vscode/issues/331823](https://github.com/microsoft/vscode/issues/331823)

## Summary

Two distinct proxy gaps were reported together. The Claude SDK download failure is likely already fixed by PR #331488 (shipped 1.135.0), but the Gemini BYOK 'fetch failed' issue is confirmed still open in source: GeminiNativeBYOKLMProvider constructs `@google/genai`'s `GoogleGenAI` client directly with only `{ apiKey }`, unlike sibling providers (e.g. openRouterProvider.ts) which inject `IFetcherService` so requests go through VS Code's proxy-aware fetcher.

## Change summary

Copilot BYOK Gemini model listing fails with 'fetch failed' when using a socks5 http.proxy, and Claude agent-host SDK download similarly fails behind that proxy.

## Best solution

Wire GeminiNativeBYOKLMProvider (extensions/copilot/src/extension/byok/vscode-node/geminiNativeProvider.ts) through the same `IFetcherService`/proxy-aware fetch mechanism already used by openRouterProvider.ts and other BYOK providers, so `GoogleGenAI` requests respect `http.proxy` (including socks5). Re-verify the Claude SDK download side against a build past PR #331488 (1.135.0) before considering that half resolved.
