# Issue #348864 — Integrated browser can't open Copilot-created HTML files in remote windows

[https://github.com/microsoft/vscode/issues/348864](https://github.com/microsoft/vscode/issues/348864)

## Summary

Keep open: current source adds only local Copilot roots, leaving remote session HTML outside the browser's authorized folders. This team-authored follow-up remains necessary and already has the correct area label.

## Change summary

Allow Copilot-created HTML in remote Copilot session folders to open in the integrated browser without starting a server.

## Best solution

Resolve Copilot roots on the owning remote and incorporate them into that authority's browser file-access roots, preserving local/remote isolation and compatibility with hosts that omit optional metadata.

## Evidence

- **Local-only Copilot roots:** src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts:1024-1037 constructs Copilot roots from the local environment and wraps them with URI.file. Its _getRemoteNetworks method at lines 961-977 selects remote roots by scheme and authority, so those local roots cannot authorize the reported remote session file.
- **Remote agent-host gap:** src/vs/sessions/contrib/browserView/browser/sessionBrowserNetwork.ts:213-224 computes remote trusted roots exclusively from session workspace working directories. It does not include remote Copilot session-state folders outside those workspaces.
- **Exact failure path:** For the reported trigger—opening HTML under the remote ~/.copilot/session-state/<id>/files directory outside trusted workspace roots—src/vs/platform/browserView/electron-main/browserSession.ts:449-453 calls authorizeRemoteFilePath and returns HTTP 403 with the exact reported 'Forbidden. File does not reside within a trusted folder.' message when authorization fails. This was traced from source; no runtime execution was performed.
- **Existing discovery surface:** src/vs/platform/environment/common/copilotHome.ts defines getCopilotRootPaths as the configured Copilot home plus ~/.copilot. src/vs/platform/mcp/common/nativeMcpDiscoveryHelper.ts already exposes homedir and optional copilotHome, but browser root construction does not consume remote discovery data.
- **Related work does not complete this issue:** https://github.com/microsoft/vscode/issues/327028 is closed and covers the local case. https://github.com/microsoft/vscode/pull/347936 merged remote file loading, but current source still omits remote Copilot roots; neither is an open duplicate canonical.
- **Protection and ownership:** The author is a COLLABORATOR, the issue is accepted as bug/browser-integration, and no issue-referencing fix was established. The proposed change also affects the browser's filesystem authorization boundary and warrants human review.
