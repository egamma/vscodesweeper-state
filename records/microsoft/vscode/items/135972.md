# Issue #135972 — The call hierarchy UI should have the ability to filter calls, or apply name filter patterns

[https://github.com/microsoft/vscode/issues/135972](https://github.com/microsoft/vscode/issues/135972)

## Summary

Still a real gap on current main: the call hierarchy peek tree has no filtering of any kind (no find widget, no name/path exclusion), and with 61 upvotes plus a maintainer saying name/pattern filtering should be possible, this should stay open as the canonical request for call-hierarchy filtering.

## Change summary

Let users filter call hierarchy results — by name/pattern and by file or folder path (e.g. exclude tests) — similar to Eclipse's 'Filter Calls' dialog.

## Best solution

Add filtering to the call hierarchy peek tree in src/vs/workbench/contrib/callHierarchy/browser/callHierarchyPeek.ts — at minimum enable the standard tree find widget in Filter mode (needs a keyboardNavigationLabelProvider in callHierarchyTree.ts), and ideally a path/glob exclude so test folders can be filtered out; the same treatment would apply to the type hierarchy peek.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/callHierarchy/browser/callHierarchyPeek.ts`, `src/vs/workbench/contrib/callHierarchy/browser/callHierarchyTree.ts`, `src/vs/workbench/contrib/callHierarchy/browser/callHierarchy.contribution.ts`
- **Validation:** A call hierarchy peek test (or a manual check with explicit steps) asserting that with a filter active, non-matching callers are hidden from the tree while matching ones and their ancestors remain visible, and that clearing the filter restores the full list.
- **Behavior:**

  > In the call hierarchy peek, the user can narrow the displayed callers/callees: typing in a filter hides non-matching entries (keeping ancestors of matches visible), and clearing it restores the full tree. The frequently requested case is excluding results from a path such as src/test or node_modules. Expanding, navigating, direction switching (callers/callees) and the preview editor must behave exactly as today when no filter is active. Acceptance: filtering hides non-matching entries and is reversible; existing call hierarchy behavior is unchanged with an empty filter.
- **Trace:**

  > CallHierarchyTreePeekWidget._fillBody in src/vs/workbench/contrib/callHierarchy/browser/callHierarchyPeek.ts constructs a WorkbenchAsyncDataTree with options limited to sorter, accessibilityProvider, identityProvider, expandOnlyOnTwistieClick and overrideStyles — no filter and no defaultFindMode — and src/vs/workbench/contrib/callHierarchy/browser/callHierarchyTree.ts provides no keyboardNavigationLabelProvider, so the generic tree find widget (TreeFindMode.Filter / TreeFindMatchType in src/vs/base/browser/ui/tree/abstractTree.ts) is not wired up here; confirmed by rg plus git log over the contrib directory. A key constraint the plan must face: the tree is async and lazily resolved per expansion (callHierarchyTree.ts DataSource), so a tree-level filter only sees already-resolved children — path/folder exclusion may instead need to drop items as the data source resolves them. Boundaries: do not change the CallHierarchyProvider extension API or the provider results themselves, and leave the type hierarchy peek alone unless the maintainer wants it in scope. Related: https://github.com/microsoft/vscode/issues/162474 (copy call hierarchy) and the closed restatement https://github.com/microsoft/vscode/issues/205411.
- **Open decisions:**
  - Should filtering reuse the standard tree find widget in Filter mode (type-to-filter over resolved nodes), or a dedicated filter control with include/exclude fields like the Search view?
  - Is path/folder exclusion (e.g. hiding src/test or node_modules) in scope, or only name/pattern matching on the displayed labels?
  - Does a filter apply only to already-resolved items, or should it also suppress items as deeper levels are resolved (and should filtered-out branches still be expandable)?
  - Should the filter be session-only, or persisted/configurable through a setting (e.g. default exclude globs for call hierarchy)?
