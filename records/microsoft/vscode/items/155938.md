# Issue #155938 — Align with another line to bring the diff back in sync

[https://github.com/microsoft/vscode/issues/155938](https://github.com/microsoft/vscode/issues/155938)

## Summary

Keep this accepted diff-editor request open: current controls do not provide user-selected alignment anchors. It has 24 upvotes, and neither the closed predecessor nor the newer merge-editor request is a valid duplicate target.

## Change summary

Allow users to pair a line in each diff pane and recompute the comparison using that alignment.

## Best solution

Provide manual alignment in the two-way diff editor, usable in embedded Monaco scenarios, while preserving automatic comparison when no anchors are supplied. Agree on anchor lifetime and editing behavior before implementing the interaction and computation contract.

Select a corresponding line on each side and verify that comparison honors that pair without changing either file; remove the alignment and verify ordinary automatic comparison resumes. Cover the chosen anchor contract in focused diff-model or widget tests, including unchanged behavior with no anchors and the agreed behavior after document edits.
- **Behavior:**

  > Users comparing files with repeated or reordered code need to override an unwanted automatic match by selecting corresponding lines in the two panes. The resulting comparison should honor that correspondence without modifying file contents. Automatic comparison must remain unchanged when no manual alignment is active, and the interaction must be usable through keyboard navigation. Acceptance should cover ambiguous repeated blocks, reordered sections, removing an alignment, and the agreed behavior when either document changes.
- **Trace:**

  > The current DiffEditorViewModel computation passes the two complete text models and automatic diff options to WorkerBasedDocumentDiffProvider; ILinesDiffComputerOptions contains no user-supplied alignment constraints. The existing moved-code Compare action in movedBlocksLinesFeature.ts operates only on a MovedText already detected by the algorithm, so it does not satisfy arbitrary line pairing. The relevant boundaries are diff-editor commands, view-model state, provider computation, and embedded Monaco usability; the trace has not established the final public contract or behavior across edits. Preserve ordinary no-anchor diffing and file contents, and do not expand this request into merge-conflict acceptance behavior. https://github.com/microsoft/vscode/issues/165684 offers related design discussion, but its maintainer explicitly separates two-way diff requests from merge-editor work.
- **Open decisions:**
  - Should manual alignment points track their selected lines across document edits, or be cleared when either document changes?
  - Should manual alignment be temporary for the current comparison, or survive closing and reopening that comparison?
