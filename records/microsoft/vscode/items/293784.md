# Issue #293784 — auto try again

[https://github.com/microsoft/vscode/issues/293784](https://github.com/microsoft/vscode/issues/293784)

## Summary

This remains a valid Copilot agent resilience request: transient provider failures can leave an unattended run blocked behind a manual Try Again action. The report has independent confirmation, and there is not enough verified evidence for a close or for folding this re-reviewed item into another issue.

## Change summary

Automatically retry transient Copilot agent request failures with backoff instead of always pausing for the user to click Try Again.

## Best solution

Define a bounded retry policy in the core chat request pipeline for errors known to be transient, using capped exponential backoff and preserving an explicit manual retry when the retry budget is exhausted. Permanent, authentication, quota, billing, permission, and user-action errors must remain visible without automatic retry.

- **Behavior:**

  > When a Copilot agent request fails for a recognized transient reason, VS Code retries it automatically with bounded backoff so an unattended run can continue. Automatic retries stop after a finite budget, after which the existing failure and manual Try Again affordance remain available. Authentication, quota, permission, billing, cancellation, and other permanent or user-action failures are not retried automatically. Acceptance should cover transient failure followed by success, retry exhaustion, cancellation during backoff, and a permanent failure.
