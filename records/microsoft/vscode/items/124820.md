# Issue #124820 — Proposed API checks fail due to nullExtensionDescription when symlinks (`npm link`) is used (doc needed?)

[https://github.com/microsoft/vscode/issues/124820](https://github.com/microsoft/vscode/issues/124820)

## Summary

Still reproduces on current main: when `npm link` creates symlinks to dependencies outside the extension folder, `require('vscode')` from those modules resolves to `nullExtensionDescription` because `findSubstr` only checks whether the calling file is under the extension root — it doesn't account for symlinked dependencies whose real paths are elsewhere. No fix has been committed.

## Change summary

Proposed API checks fail when extension dependencies are symlinked via `npm link` because the extension host cannot identify the extension from a require call originating outside the extension directory tree.

## Best solution

In `VSCodeNodeModuleFactory.load()` (and the equivalent in `OpenNodeModuleFactory`), when the initial `findSubstr` against the resolved parent URI fails, try resolving the parent URI back through the symlink (i.e. check the original symlinked path under `node_modules/` in the extension root, not just the realpath target). Alternatively, the extension path index could register both the extension's real path and the symlink source paths of its `node_modules` entries. The fix is localized to `src/vs/workbench/api/common/extHostRequireInterceptor.ts` and `src/vs/workbench/api/common/extHostExtensionService.ts`. Given 0 upvotes and niche use case (extension dev with `npm link`), this is low priority but a real developer-experience gap worth documenting or fixing.

## Evidence
