# Issue #340313 — Copilot Chat: Delete archives first filtered session instead of editing the session filter

[https://github.com/microsoft/vscode/issues/340313](https://github.com/microsoft/vscode/issues/340313)

## Summary

Thanks for the report. Source confirms it: the Delete-to-archive keybinding is active whenever the sessions list has focus, which includes the tree's built-in find input, and nothing excludes text-input focus.

## Change summary

Pressing Delete in the agent sessions filter (find) input archives the first filtered session instead of deleting a character.

## Best solution

Add `EditorContextKeys.inputFocus`-style negation (`InputFocusedContext.negate()`) to the `when` of the Delete-based session keybindings so typing in the find input is untouched.

Also check the Shift+Delete unarchive binding (~L573) and the other agentSessionsViewerFocused bindings (~L732).
- **Behavior:**

  > While the sessions find/filter input has focus, Delete (and Shift+Delete on the unarchive action) only edits the text and never archives or unarchives a session. When the list itself has focus, Delete still archives the focused session. On macOS, Cmd+Backspace should likewise not archive while typing in the input.
- **Trace:**

  > agentSession.archive in agentSessionsActions.ts registers KeyCode.Delete (mac: CtrlCmd+Backspace) gated on ChatContextKeys.agentSessionsViewerFocused. That key is bound to the tree's contextKeyService in agentSessionsControl.ts (~L372), and the tree's find widget (findWidgetEnabled: true, ~L360) lives inside it, so the binding fires from the input. The fix is to add InputFocusedContext.negate() (from vs/platform/contextkey/common/contextkeys) to the affected `when` clauses. Do not change the list's keyboard behavior otherwise. Related: https://github.com/microsoft/vscode/issues/281760
