# Issue #96875 — Add support for `.XCompose`

[https://github.com/microsoft/vscode/issues/96875](https://github.com/microsoft/vscode/issues/96875)

## Summary

Keep open: custom compose sequences on native Wayland remain a supported, repeatedly reported gap, with no verified fix or eligible open canonical issue found. The existing reproduction is concrete; investigation should distinguish VS Code's input integration from Electron/Chromium limitations before choosing an implementation.

## Change summary

Honor custom ~/.XCompose sequences in the editor and integrated terminal on Linux, including sequences that extend built-in compose mappings.

## Best solution

Deliver native-Wayland input parity with X11 for custom compose sequences through the platform input-method integration, without requiring users to switch display backends. Establish whether the remaining work belongs in VS Code initialization or upstream before changing editor-specific input handling.
