# Issue #332615 — CLI: known subcommand name passed as option value is treated as subcommand

[https://github.com/microsoft/vscode/issues/332615](https://github.com/microsoft/vscode/issues/332615)

## Summary

Confirmed on main: `parseArgs`'s subcommand-detection predicate only checks token shape, not whether the token is the value of a preceding string option, so `code --profile agent` is mis-parsed as the `agent` subcommand. An open PR already targets this fix, so it should be reviewed/landed rather than auto-fixed here.

## Change summary

`code --profile <subcommand-name>` silently drops `--profile` and launches the named subcommand instead of using it as the option's value.

## Best solution

Land https://github.com/microsoft/vscode/pull/332625, which tracks pending option values (including aliases/deprecated ids) while scanning for the subcommand token, then close this issue once merged.
