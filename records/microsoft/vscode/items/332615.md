## Evidence

- **Defect traced in current source:** In src/vs/platform/environment/node/argv.ts, OPTIONS registers profile as a string option and agent as a subcommand. parseArgs selects firstPossibleCommand using args.find with only token-shape and subcommand-membership checks; it never checks whether the preceding option consumes that token. Consequently, ['--profile', 'agent'] elects agent before minimist can consume it as the profile value.
- **Observable consequence:** The command branch in parseArgs replaces the top-level option descriptions with globalOptions plus command.options, removes the elected command token, recursively parses the remainder, and returns the subcommand-shaped result. profile is neither global nor an agent option, so the requested profile is lost. This is a source trace, not an executed reproduction.
- **Existing open implementation candidate:** https://github.com/microsoft/vscode/pull/332625 was verified OPEN with mergedAt null. Its body explicitly states Fixes #332615 and describes tracking pending string option values, including aliases and deprecated IDs. It reports argv regression tests and remains draft pending triage; those validation claims were not independently executed in this read-only review.
