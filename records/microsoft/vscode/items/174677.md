# Issue #174677 — Zen Mode

[https://github.com/microsoft/vscode/issues/174677](https://github.com/microsoft/vscode/issues/174677)

## Summary

Keep open: existing settings can suppress individual distractions, but Toggle Zen Mode still does not provide the requested reversible switch between automatic assistance and quiet editing. The older Zen Mode Settings request is related, but does not establish the same popup-and-live-diagnostics symptom required for a duplicate close on this re-reviewed item.

## Change summary

Provide a quick, reversible quiet-editing mode that suppresses automatic suggestions, hovers, and intrusive diagnostics while retaining assistance on demand.

## Best solution

Define an opt-in quiet-editing experience that restores the user's normal assistance settings when disabled and preserves explicitly requested suggestions. Coordinate with the configuration-scoping discussion at https://github.com/microsoft/vscode/issues/45617 without treating configurable layout alone as satisfying this request.

- **Behavior:**

  > The reporter wants to switch quickly between normal assistance and quiet editing without permanently giving up helpful features. Current Zen Mode changes surrounding layout but leaves automatic suggestions, hover popups, and live diagnostic distractions. The finished experience should preserve explicit access to assistance and restore the user's previous behavior when quiet editing ends. Acceptance must distinguish hiding diagnostic presentation from actually delaying validation until save.
- **Trace:**

  > workbench.action.toggleZenMode is registered in src/vs/workbench/browser/workbench.zenMode.contribution.ts and invokes toggleZenMode in src/vs/workbench/browser/layout.ts. That path handles layout, editor tabs, line numbers, and notification filtering, but does not override suggestion, hover, or diagnostic settings. src/vs/editor/common/config/editorOptions.ts exposes independent quick-suggestion, trigger-character, and hover controls; these cover individual distractions rather than a coordinated temporary state. The reporter explicitly rejected ordinary layout-only Zen Mode as sufficient. https://github.com/microsoft/vscode/issues/45617 discusses broader Zen-specific overrides and configuration precedence, but does not settle the quiet-assistance contract here. Preserve existing normal-mode preferences and explicit assistance commands; broader completion-ranking changes and relocating all assistance into a pane are separate suggestions, not established acceptance requirements.
- **Open decisions:**
