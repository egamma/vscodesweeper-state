# Issue #288803 — Background agent worktrees: hard to apply/push/PR when local workspace is dirty

[https://github.com/microsoft/vscode/issues/288803](https://github.com/microsoft/vscode/issues/288803)

## Summary

Keep open for the remaining background-session workflow polish. Worktree terminals and session-scoped publishing actions now cover substantial parts of the request, but the classic background-session surface still differs from the Agents window, and the Apply failure path still reports every error as a dirty-workspace problem.

## Change summary

Make background-session results easy to validate and publish independently without disturbing an intentionally dirty foreground workspace.

## Best solution

Reuse the existing worktree-scoped terminal and publishing capabilities in a discoverable background-session workflow, preserving foreground changes. Treat accurate Apply feedback and conflict handling as distinct remaining work rather than requiring users to clean their foreground workspace to publish an isolated experiment.

Session actions identify the correct worktree and branch without manual branch hunting. Existing terminal access and Agents-window publishing must remain available. Acceptance includes preserving foreground contents and staged state through PR creation and subsequent pushes, and accurately distinguishing Apply failures from a dirty workspace.
- **Trace:**
