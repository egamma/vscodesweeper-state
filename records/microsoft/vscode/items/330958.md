# Issue #330958 — Promo banners shouldnt show in inline chat

[https://github.com/microsoft/vscode/issues/330958](https://github.com/microsoft/vscode/issues/330958)

## Summary

Team-authored report of a real gap: the promo-notification widget is instantiated unconditionally in `ChatInputPart.ensureNotificationWidget()` with no gating on `ChatAgentLocation.EditorInline`, so promos surfaced by `ChatPromoNotificationContribution` render in inline-chat sessions too, not just the chat panel.

## Change summary

Promo banners (surfaced via ChatPromoNotificationContribution / ChatInputNotificationWidget) currently render in inline chat as well as the chat panel; the request is to restrict them to the panel/new sessions only.

## Best solution

Gate the notification widget (or the promo-specific `sessionTypes` filtering) on `this.location !== ChatAgentLocation.EditorInline` in `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, so inline chat (which renders with `renderStyle: 'minimal'`, falling into the same DOM branch as the panel) never mounts or shows chat-input notifications tied to the promo.

## Evidence

- **no location filter:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputNotificationService.ts only filters notifications by sessionTypes/sessionResources (isChatInputNotificationApplicableToSessionType/Session) — there is no ChatAgentLocation check anywhere in the notification pipeline.
- **widget instantiation unconditional:** ensureNotificationWidget() in chatInputPart.ts (called from refreshViewModelScopedState and elsewhere) always creates/attaches ChatInputNotificationWidget with no location guard, and the constructor call passes no location parameter at all.
- **inline chat shares the container:** EditorBasedInlineChatWidget (src/vs/workbench/contrib/inlineChat/browser/inlineChatWidget.ts:156) renders its ChatWidget with `renderStyle: 'minimal'`, which falls into chatInputPart.render()'s non-'compact' branch — the same branch that includes `.chat-input-notification-container` — so the promo notification container is present in inline chat too.
- **promo harness targeting:** chatPromoNotification.ts buckets one promo per harness via `meta.targetChatSessionType ?? localChatSessionType`, which matches inline chat's local session type the same as the panel, so a promo for the local pool would surface in both surfaces.
