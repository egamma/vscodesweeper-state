# Issue #222244 — Search in markdown preview panel not working in current main branch local build

[https://github.com/microsoft/vscode/issues/222244](https://github.com/microsoft/vscode/issues/222244)

## Summary

Keep open: local OSS builds still depend on a frame-search API absent from stock Electron. The maintainer-confirmed upstream gap remains distinct from the related crash and IME fixes, and the existing area labels are appropriate.

## Change summary

Make searching rendered Markdown and other find-enabled webviews work in local OSS desktop builds.

## Best solution

Upstream Electron's frame-targeted search capability and adopt it on the existing desktop webview search path, bringing OSS builds to parity with official builds without searching unrelated frames.

## Evidence

- **Reported trigger and confirmed diagnosis:** https://github.com/microsoft/vscode/issues/222244 reports opening a Markdown preview in a local desktop build and searching for present text without results. The discussion traces this to undefined frame.findInFrame; the December 16, 2024 maintainer reply explicitly confirms that the API is unavailable in OSS builds and needs upstreaming.
- **Current source path:** src/vs/workbench/contrib/webview/electron-browser/webviewElement.ts routes ElectronWebviewElement.updateFind and find through IWebviewManagerService.findInFrame. In src/vs/platform/webview/electron-main/webviewMainService.ts, WebviewMainService.findInFrame invokes search and registers the result listener only when typeof frame.findInFrame === 'function'; there is no fallback when the API is missing.
- **Upstream implementation status:** https://github.com/electron/electron/pull/28274 proposes webFrameMain.findInFrame/stopFindInFrame for frame-targeted search, but is closed with no merge timestamp. An upstream PR search found no replacement implementation proposal; the other result, https://github.com/electron/electron/pull/28330, concerns tests rather than supplying the missing API.
- **Recent related fix explicitly preserves this gap:** The merged https://github.com/microsoft/vscode/pull/320898 fixes IME composition focus churn, not search availability. Its description explicitly states that desktop webview find is not functional in local builds because stock Electron lacks the findInFrame patch, and cites this issue as the reason validation used the web build.
- **Canonical search and scope distinction:** Repository searches for findInFrame, OSS webview search, and Markdown preview search found no verified open older canonical owning this missing-search behavior. https://github.com/microsoft/vscode/issues/213147 is closed and concerns a crash after a successful search; its discussion explicitly separated the local-build search failure into this issue. https://github.com/microsoft/vscode/issues/201176 is also closed and primarily requests access to Microsoft's Electron binaries; its maintainer response instead identifies upstream feature parity as the intended direction.
