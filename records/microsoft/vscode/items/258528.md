Current source still permits the reported second-open behavior: the chat file-change row reopens the same diff without requesting that its changes be revealed, so the diff editor preserves the previous view state. ## Change summary

Clicking a chat checkpoint's changed-file row a second time can reopen its diff with the original side positioned at the top of the file instead of at the changed lines.

## Best solution

Ensure activation of a file-change row consistently reveals the relevant diff hunk, including when the same diff input is already open, while preserving the existing snapshot resources and focus behavior.
