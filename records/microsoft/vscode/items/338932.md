# Issue #338932 — Existing Local chat session remains usable after managed Agent Host sandbox policy applies

[https://github.com/microsoft/vscode/issues/338932](https://github.com/microsoft/vscode/issues/338932)

## Summary

Security-sensitive sandbox-enforcement gap (an existing Local chat session keeps running unsandboxed after a managed Agent Host policy takes effect) that was closed as by-design and then reopened by a contributor insisting it must be fixed — several hard keep-open rules apply (security-sensitive, team-authored with a real milestone, reopened), so this stays open regardless of other evidence.

## Change summary

An existing Local chat session is not migrated or blocked when an enterprise-managed Agent Host sandbox policy is applied mid-session, letting it keep running outside the mandated sandbox.

## Best solution

Decide and implement the product behavior for existing sessions when a managed sandbox policy newly applies: either force-migrate the session to Agent Host or block further messages until the user switches, in the chat/agentSessions harness-selection code (e.g. src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts and the session-target picker) referenced from the linked PRs #331298 and #339144.
