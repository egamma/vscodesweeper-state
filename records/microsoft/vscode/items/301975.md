# Issue #301975 — You will be asked to trust your folder, but you will also be asked to trust to repo root. Trust both.

[https://github.com/microsoft/vscode/issues/301975](https://github.com/microsoft/vscode/issues/301975)

## Summary

Keep open: the initial trust dialog still lacks repository-root awareness, and a maintainer explicitly supported improving it. Existing parent-folder trust is only partial coverage, and the older trust-dialog reports inspected concern different scenarios.

## Change summary

Let the initial workspace trust dialog explicitly offer to trust the enclosing Git repository, avoiding a later repository trust decision.

## Best solution

Offer informed, opt-in trust of the enclosing repository root during initial workspace trust, including when the workspace is nested several levels below it. Preserve restricted mode and separate repository-opening preferences; trusting the workspace alone must not implicitly trust its ancestors.

- **Validation:** With Workspace Trust enabled and clean trust state, open both a direct repository child and a several-level nested folder. Verify the first dialog can explicitly trust the enclosing repository root; accepting that scope avoids a subsequent resource-trust prompt when opening the parent repository. Choosing workspace-only trust or restricted mode must leave ancestors untrusted. Exercise the selected scope and trust inheritance in the workspaceTrust unit suite.
- **Behavior:**

  > Opening a folder nested inside a Git repository currently presents workspace trust first, then a parent-repository opening notification and potentially another trust dialog. The first trust dialog should explain and offer explicit trust of the enclosing repository root, including for deeply nested folders. Accepting that scope should eliminate the later repository trust decision without implicitly choosing to open the repository. Workspace-only trust and restricted mode must remain available without trusting ancestors.
- **Trace:**

  > The startup trust handler in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts labels an optional immediate-parent checkbox, and WorkspaceTrustManagementService.canSetParentFolderTrust/setParentFolderTrust in src/vs/workbench/services/workspaces/common/workspaceTrust.ts operate on dirname(workspaceUri), not a detected repository root. In extensions/git/src/model.ts, showParentRepositoryNotification asks to open the parent repository, while openRepository separately calls workspace.requestResourceTrust for the Git metadata location. extensions/git/package.json disables the Git extension in untrusted workspaces, leaving unresolved how repository information becomes available before the initial trust choice. Preserve explicit consent, existing repository-opening preferences, and restricted-mode behavior; do not automatically expand trust. The maintainer-supported direction is recorded at https://github.com/microsoft/vscode/issues/301975#issuecomment-4069077272, and the original scenario is documented in https://github.com/microsoft/vscode/issues/301544.
