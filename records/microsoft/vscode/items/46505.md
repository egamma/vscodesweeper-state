# Issue #46505 — Feature Request : SHOW / HIDE comments in editor

[https://github.com/microsoft/vscode/issues/46505](https://github.com/microsoft/vscode/issues/46505)

## Summary

Keep this accepted, well-supported request open: current comment folding does not provide the space-removing, reversible comment-hiding experience described in the discussion. This issue already owns consolidated reports, and no verified open canonical supersedes it.

## Change summary

Provide reversible visual hiding of source comments without changing the document or leaving their occupied space behind.

## Best solution

Design an opt-in, language-aware comment-hiding experience that preserves source text and documentation tooling while removing comment-only lines and inline comment text from the visual presentation. Settle how hidden comments are revealed for editing before implementation; ordinary block folding and transparent text do not satisfy the request.

Add targeted editor projection and interaction tests for the agreed behavior.
- **Behavior:**

  > Users want to read documented source as though comments were absent, then reveal those comments for editing without modifying the underlying file. Ordinary folding and transparent comment text are insufficient because they retain distracting content or occupied space and do not cover inline comments. Acceptance must cover comment-only lines and comments sharing a line with executable code, preserve documentation hovers, and ensure visibility changes do not alter saved text or dirty state. The thread disagrees on visible indicators and automatic reveal, so those interactions require a product decision.
- **Trace:**

  > FoldAllBlockCommentsAction in src/vs/editor/contrib/folding/browser/folding.ts implements the existing editor.foldAllBlockComments command using folding-region types or block-comment opening tokens. HiddenRangeModel in src/vs/editor/contrib/folding/browser/hiddenRangeModel.ts manages folded hidden ranges and selection adjustment; src/vs/editor/common/viewModel/viewModelLines.ts normalizes hidden areas to complete lines. The folding appearance settings in src/vs/editor/common/config/editorOptions.ts do not supply comment elision. The trace establishes the gap but not a complete inline projection or language-aware comment-identification design. Preserve source text, existing folding behavior, executable code, and documentation tooling; do not remove comments from the text model. https://github.com/microsoft/vscode/issues/85783 is a separate narrower unfolding request, while https://github.com/microsoft/vscode/issues/45020 and https://github.com/microsoft/vscode/issues/142159 already consolidate into this issue.
- **Open decisions:**
  - Should hidden comments have a discoverable visual marker and reveal automatically during caret navigation, or remain completely unmarked until an explicit show command?
  - Should the initial experience hide all source comments, including inline spans, or offer independently selectable documentation, comment-only-line, and inline-comment categories?
