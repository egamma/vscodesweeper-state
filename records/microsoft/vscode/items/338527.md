# Issue #338527 — Notebook editor bottom corners are not rounded with modern UI

[https://github.com/microsoft/vscode/issues/338527](https://github.com/microsoft/vscode/issues/338527)

## Summary

Traced a real gap on main: the notebook editor's DOM is rendered as a `position: fixed` overlay anchored via CSS anchor positioning (src/vs/base/browser/overlayLayoutElement.ts), which bypasses the `.part.editor` border-radius/overflow:hidden clipping that `editorBorder.css` uses to round the editor frame — so the notebook's own content squarely overlaps the intended rounded bottom corners.

## Change summary

With Modern UI enabled, the notebook editor's bottom corners stay square instead of matching the rounded editor-part frame used by other editors.

## Best solution

Give the notebook editor's overlay content (OverlayLayoutElement.content, used via `this._overlayLayout.content` / `.notebookOverlay` in notebookEditorWidget.ts) a matching `--vscode-cornerRadius-large` + clip under `.modern-ui`, either generically in overlayLayoutElement.ts for all anchor-positioned overlay content or scoped to the notebook's own container — a maintainer should pick the scope before implementing.

## Plan brief

- **Likely files:** `src/vs/base/browser/overlayLayoutElement.ts`, `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`, `src/vs/workbench/contrib/modernUI/browser/media/editorBorder.css`
- **Validation:** Visual check: with `workbench.experimental.modernUI` enabled, open a notebook and confirm the bottom corners of the notebook editor area are rounded to match the editor part's frame, with no regression to other overlay-anchored widgets (e.g. webview-based editors).
- **Trace:**

  > The notebook editor's actual rendered content lives in `OverlayLayoutElement.content` (src/vs/base/browser/overlayLayoutElement.ts), a `position: fixed` element anchored via CSS anchor positioning over the notebook editor pane so it can be re-parented without losing iframe/webview state. `NotebookEditorWidget` appends `this._overlayLayout.root` into its container and treats `this._overlayLayout.content` as `_overlayContainer` (notebookEditorWidget.ts ~L333-429). Because this content element is a separate DOM subtree from `.part.editor`, the rounded-corner border-radius + overflow:hidden that `editorBorder.css` applies to `.part.editor` under `.modern-ui` never clips it, so its square background shows through at the bottom. Do not touch the general editor-part rounding rule itself or other editor types that render directly inside `.part.editor` — those already work. Where the uncertainty starts: whether the radius should be added generically to `OverlayLayoutElement.content` (affecting every overlay-anchored consumer) or scoped to the notebook's own overlay container, and whether all four corners or only the bottom need it given the toolbar already sits inside the properly clipped `.part.editor`.
- **Open decisions:**
  - Should the corner-radius fix live generically in OverlayLayoutElement (affecting all anchor-positioned overlay content, e.g. other iframe/webview-backed widgets) or be scoped specifically to the notebook editor's overlay container?
  - Should all four corners of the notebook overlay be rounded, or only the bottom corners, given the top is typically covered by the notebook toolbar which already renders inside the correctly-clipped `.part.editor`?

## Evidence

- **editor rounding source:** src/vs/workbench/contrib/modernUI/browser/media/editorBorder.css lines 26-32 apply `border-radius: var(--vscode-cornerRadius-large)` and `overflow: hidden` to `.modern-ui .monaco-grid-view .part.editor:not(.modal-editor-part)`.
- **notebook overlay escapes that clip:** src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts lines 333-429: `this._overlayLayout = new OverlayLayoutElement()`, `this._overlayContainer = this._overlayLayout.content`, and `container.appendChild(this._overlayLayout.root)` — the notebook's real content lives in `content`, which is a separate DOM subtree.
- **fixed-position anchor mechanism:** src/vs/base/browser/overlayLayoutElement.ts: `content.style.position = 'fixed'` with `top/left: anchor(...)`, explicitly designed so a DOM node 'cannot be re-parented without losing its state' — this deliberately sits outside the normal editor-part DOM tree that carries the rounded-corner styling, so no border-radius from editorBorder.css reaches it.
