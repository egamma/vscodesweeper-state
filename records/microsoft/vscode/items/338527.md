# Issue #338527 — Notebook editor bottom corners are not rounded with modern UI

[https://github.com/microsoft/vscode/issues/338527](https://github.com/microsoft/vscode/issues/338527)

## Summary

Keep open: current source rounds the modern editor card but leaves the separately mounted notebook overlay square, so the reported inconsistency remains. The existing steps are sufficient; no verified canonical or linked open fix PR was found.

## Change summary

Notebook editors should display rounded bottom corners consistent with other editor cards in the non-compact modern UI.

## Best solution

Make the visible notebook surface respect the modern editor card’s corner treatment without changing classic or compact layouts, notebook scrolling, or floating editor widgets.

## Evidence

- **Intended editor treatment:** src/vs/workbench/browser/media/floatingPanels.css:104–127 rounds `.part.editor > .content` with `--vscode-cornerRadius-large`, separately rounds `.webview-overlay-content`, and explicitly removes rounding in compact mode. This establishes the expected non-compact modern editor treatment.
- **Notebook bypasses the rounded ancestor:** src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts:333–334 constructs an OverlayLayoutElement and uses its content as the notebook container; lines 418–429 append its root to the workbench container, not inside the rounded editor content. layoutContainerOverShadowElement at lines 1932–1943 anchors this separate overlay over the notebook editor.
- **Square notebook surface:** src/vs/base/browser/overlayLayoutElement.ts creates content with overflow hidden and positions it using fixed CSS anchors; its clipping is rectangular `content-box` clipping, with no corner radius. src/vs/workbench/contrib/notebook/browser/media/notebook.css:11–17 and 409–411 style the notebook overlay and its background without rounding its outer surface. Consequently, enabling modern UI and opening a notebook leaves its painted bottom corners square despite the rounded card behind it.
- **Existing analogous boundary:** src/vs/workbench/browser/media/floatingPanels.css:109–120 explicitly explains that separately mounted webview overlays need their own corner treatment because rounding the underlying card or overlay root does not clip the fixed content.
