## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/quickInputBox.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/base/browser/ui/list/listWidget.ts`
- **Validation:** In a current web build on macOS with Safari and VoiceOver, open Quick Open with Cmd+P and navigate populated results with Up/Down; each newly focused item should be announced. Repeat in a non-file QuickPick and after Tab/Shift+Tab between the input and list. Check Chrome with VoiceOver and Windows/Linux screen-reader navigation for regressions.
- **Behavior:**

  > In VS Code web, VoiceOver should announce the focused result as the user navigates QuickPick items with the keyboard. The report covers both file Quick Open and other QuickPick widgets; the latest confirmation limits the remaining failure to Safari. Acceptance includes correct announcements after moving between the input and list with Tab/Shift+Tab, without stale-item speech. Normal text editing and working announcements in other browsers and screen readers must remain unchanged.
- **Trace:**

  > QuickInputController in src/vs/platform/quickinput/browser/quickInputController.ts copies QuickInputList.getActiveDescendant() to the focused input and updates QuickInputBox.setListFocusMode(). The underlying list independently maintains aria-activedescendant in src/vs/base/browser/ui/list/listWidget.ts, so both elements can reference a result simultaneously. https://github.com/microsoft/vscode/issues/96578#issuecomment-627364021 connects that overlap to VoiceOver failure, but its partial workaround regressed Shift+Tab and the subsequent minimal Chrome example did not reproduce. Current QuickInputBox ARIA attributes differ from the historical example, and current Safari speech was not tested during this read-only review. Diagnose the exact runtime interaction before selecting a fix; do not change shared list behavior or input-only QuickInput semantics without evidence. https://github.com/microsoft/vscode/issues/267445 concerns role semantics, while https://github.com/microsoft/vscode/issues/280911 concerns focus loss, so neither is a demonstrated duplicate.
