# Issue #277454 — Wait for shell integration to be ready when opening new terminal via API

[https://github.com/microsoft/vscode/issues/277454](https://github.com/microsoft/vscode/issues/277454)

## Summary

The requested API already exists: `window.onDidChangeTerminalShellIntegration` fires when shell integration activates for a terminal, and `terminal.shellIntegration` exposes readiness. Extensions should listen to this event before executing commands, as documented in the stable API.

## Change summary

Request for an event/API to detect when shell integration is ready after creating a terminal via the extension API.

## Best solution

Close as already available — extensions should check `terminal.shellIntegration` and listen to `window.onDidChangeTerminalShellIntegration` before running commands that depend on shell integration. The pattern is documented inline in `vscode.d.ts`.

- **Proposed comment:**

  > Thanks for the report. The API you're describing already exists in the stable extension API:
  > 
  > - `terminal.shellIntegration` — `undefined` until shell integration activates
  > - `window.onDidChangeTerminalShellIntegration` — fires when shell integration becomes ready for a terminal
  > 
  > The recommended pattern (from the API docs) is:
  > 
  > ```ts
  > if (terminal.shellIntegration) {
  >   // ready now
  > } else {
  >   const disposable = window.onDidChangeTerminalShellIntegration(({ terminal: t, shellIntegration }) => {
  >     if (t === terminal) {
  >       // now ready — execute your command
  >       disposable.dispose();
  >     }
  >   });
  > }
  > ```
  > 
  > Extensions that create a terminal and immediately run a command should wait for this event before using shell-integration-dependent features. Since this capability is already shipping, closing as already covered by design.
