# Issue #335652 — Choose Folder: Make parent folder of current folder the starting point

[https://github.com/microsoft/vscode/issues/335652](https://github.com/microsoft/vscode/issues/335652)

## Summary

Still an open gap on main: team-authored request from a collaborator, parked in the On Deck holding bin, asking the Agents Window Choose Folder dialog to start near the user's workspaces instead of the home folder. Not fixable with a trivial one-line change because which 'current folder' to anchor on (active session vs. most recent workspace) is an open product decision.

## Change summary

When browsing for a folder to start a new Agents Window session, default the file-picker's starting location to the parent of the user's current/most-recent folder instead of the home directory.

## Best solution

Pass a computed `defaultUri` (parent of the active session's or most-recent workspace folder) into the `showOpenDialog` calls in `sessionWorkspacePicker.ts`'s `_browseForLocalFolder` (and the analogous one in `newSessionFolderQuickPickAction.ts`), after a maintainer decides which folder counts as 'current'.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts`, `src/vs/sessions/contrib/chat/browser/newSessionFolderQuickPickAction.ts`
- **Validation:** A unit test asserting `showOpenDialog` (or the equivalent fileDialogService mock) is invoked with a `defaultUri` equal to the parent of the chosen 'current folder', in the existing `sessionWorkspacePicker.test.ts` / `newSessionFolderQuickPickAction.test.ts` suites.
- **Behavior:**

  > Opening the folder-browse dialog from the Agents Window ('Choose Folder' flow, or the 'New Session in Folder...' quick pick's 'Browse...' item) should start the native/file picker at the parent folder of the user's current reference folder, rather than the home directory. Existing behavior when there is no current/recent folder (e.g. brand-new install) is unchanged. Acceptance: a test confirms `defaultUri` passed to `showOpenDialog` equals the parent of the chosen reference folder.
- **Trace:**

  > `_browseForLocalFolder` in sessionWorkspacePicker.ts and the 'Browse...' handler in newSessionFolderQuickPickAction.ts both call `fileDialogService.showOpenDialog(...)` without a `defaultUri`, so the platform file-dialog service's own default-path logic (last active workspace root, or home as a final fallback) decides the starting folder — confirmed by reading `abstractFileDialogService.ts`'s `defaultFolderPath`/`defaultFilePath`. `ISessionsRecentWorkspacesService.getRecentWorkspaces()` (used elsewhere in both files) and `ISessionsService.activeSession` both expose a workspace folder URI that could supply the 'current folder' to take `dirname()` of. The boundary: don't touch the platform-level `fileDialogService` default-path logic itself — only supply an explicit `defaultUri` from the Agents Window's own folder context at these two call sites.
- **Open decisions:**
  - Should 'current folder' mean the active session's open workspace folder, or the most recently used entry in the recents list, when they differ?
  - Should the new default apply to both the main Choose Folder dialog and the alternate 'New Session in Folder...' quick pick, or only one?

## Evidence

- **no defaultUri on main:** src/vs/sessions/contrib/chat/browser/sessionWorkspacePicker.ts `_browseForLocalFolder` (around line 1557) calls `fileDialogService.showOpenDialog({ canSelectFolders: true, canSelectFiles: false, canSelectMany: false })` with no `defaultUri`, so it falls through to the generic file-dialog default (last active root or home) rather than anything derived from the current Agents Window folder.
- **same gap in alternate entry point:** src/vs/sessions/contrib/chat/browser/newSessionFolderQuickPickAction.ts (line ~101) has an identical unqualified `showOpenDialog` call for the 'Browse...' quick-pick item.
- **available data to anchor on:** ISessionsRecentWorkspacesService.getRecentWorkspaces() and ISessionsService.activeSession both expose a current workspace folder URI that a 'parent of current folder' default could be derived from — but no code currently computes or passes it.
