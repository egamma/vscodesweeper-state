[https://github.com/microsoft/vscode/issues/185775](https://github.com/microsoft/vscode/issues/185775)

## Summary

This request belongs to the VS Code team's Remote - WSL extension and should be moved to microsoft/vscode-remote-release rather than closed. An older open issue there tracks the same failure with `fmask=111`, including the need to restore script execution after every extension update.

## Change summary

Support WSL mount configurations that remove executable bits by ensuring Remote - WSL shell scripts remain runnable after extension updates.

## Best solution

Consolidate this report into https://github.com/microsoft/vscode-remote-release/issues/2126 and update Remote - WSL's script-launch path so installations on mounts using `metadata` and `fmask=111` do not require a manual `chmod` after each update.
