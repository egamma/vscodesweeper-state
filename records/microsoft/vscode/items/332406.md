# Issue #332406 — Sticky scroll can partially overlap with next "Restore Checkpoint" bar

[https://github.com/microsoft/vscode/issues/332406](https://github.com/microsoft/vscode/issues/332406)

## Summary

Fresh test-plan finding (filed while verifying the tree-based chat sticky scroll test item #332197) reporting that the sticky-scroll header can visually collide with the checkpoint/"Restore Checkpoint" bar of the request below it. The two elements are rendered by separate, uncoordinated CSS rules with no evident stacking/overlap handling, so this is a real, still-open visual gap.

## Change summary

When chat's experimental tree sticky scroll is enabled, the sticky-scroll row can partially overlap the checkpoint/"Restore Checkpoint" bar of the next request.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts / chatListRenderer.ts and the sticky-scroll/checkpoint-container rules in media/chat.css, account for the checkpoint bar's height when computing sticky-scroll node height/offset (stickyScrollMaxNodeHeight, stickyScrollNodeSourceRangeProvider) or add a stacking rule so the checkpoint bar isn't obscured; needs an area-owner triage since it's under an experimental setting (chat.experimental.stickyScroll).
