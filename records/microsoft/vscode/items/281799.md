The original failure is confirmed, and later changes appear to address both the stripped URI prefix and the unnecessary external-file confirmation. ## Change summary

Loading an on-demand user-level instruction could strip its `vscode-userdata:` scheme, trigger an Allow dialog, and then fail because the resulting filesystem path was outside the workspace.

## Best solution

Verify that an on-demand instruction under `vscode-userdata:` is passed unchanged to `read_file`, loads without an external-path confirmation, and applies without requiring `applyTo: **`. If that succeeds, the issue owner can close this as covered by the existing prompt and authorization fixes; otherwise add a regression test spanning the customization index and read-file authorization path.
