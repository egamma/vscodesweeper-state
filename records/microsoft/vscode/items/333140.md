# Issue #333140 — VS Code Agents Window mcp server integration is a blocker to use

[https://github.com/microsoft/vscode/issues/333140](https://github.com/microsoft/vscode/issues/333140)

## Summary

The Agents Window has a working per-tool-call MCP OAuth flow (ToolCallStatus.AuthRequired surfaces a 'sign in' card in chat), but there is no manual re-auth affordance at the MCP-server/customization level — so a server that fails to even list tools without OAuth (blocking at startup, before any tool call happens) has no way for the user to trigger the browser auth flow, matching the report.

## Change summary

When an MCP server needs an OAuth re-auth before it can start, the Agents Window session gets stuck with no way to trigger the browser sign-in flow.

## Best solution

Add a manual 'Authenticate' action for MCP server customizations in `McpServerStatus.AuthRequired` state (e.g. in the customizations tree view / MCP servers list), reusing the same OAuth resource/oauthClient plumbing already built for tool-call-time auth in `stateToProgressAdapter.ts` / `mcpCustomizationController.ts`, so re-auth isn't gated on a tool call ever being reached.
