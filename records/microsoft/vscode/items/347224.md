## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/265401 is open and predates this report. It describes thousands of failing git rev-parse --show-toplevel calls with Copilot enabled in large workspaces; comments explicitly confirm the non-Git-folder trigger and resulting system slowdown.
- **Same diagnosed root cause:** https://github.com/microsoft/vscode/issues/265401#issuecomment-6625899114 identifies ExternalIngestIndex content-exclusion checks, copilotignore_enabled, and uncached per-file repository lookups as the cause. This matches the trigger and diagnosis in https://github.com/microsoft/vscode/issues/347224.
- **Current source confirmation:** extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts:188-198 calls getRepositoryFetchUrls for each uncached file and caches only resolved repositories. extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts:250-258 resolves each file's directory and calls getRepositoryRoot without folder-level coalescing; extensions/git/src/git.ts:512-513 executes git rev-parse --show-toplevel.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/345758 is open and explicitly references the canonical issue. Its description addresses the same per-file process storm through bounded repository lookups and avoiding Git where no repository markers exist; it intentionally avoids persistent negative answers because repositories can appear without an open event. It is not a landed fix.
- **Distinct evidence to preserve:** https://github.com/microsoft/vscode/issues/347224 adds Windows 11 ARM64 reproduction, organization content exclusion enabled, approximately 1,600 Git invocations in 16 seconds, repeated calls from the same directory, and Defender overhead. These refine the existing defect rather than establish a separate root cause.
