- **Behavior:**

  > Users should be able to supply context from a workbench terminal to Agent Host chat even when the SDK executes commands in a separate shell. Explicitly attached selections and completed commands should arrive as model-readable context rather than being omitted. Sharing context must not imply executing commands in, or taking ownership of, the user's existing terminal. Acceptance should verify selection text and command output reach the outgoing request; automatic context collection requires a separate scope decision.
- **Trace:**

  > The workbench selection action creates a generic text entry in terminal.chatAgentTools.contribution.ts, while TerminalContext.asAttachment in chatContext.ts creates a terminalCommand entry with command, output, and exit code. AgentHostSessionHandler._variableEntriesToAttachments delegates to _convertVariableToAttachment, which lacks a terminalCommand branch and only accepts generic entries carrying attachment-detail metadata. TerminalChatSessionResolver already supplies shell type and OS metadata for Agent Host-backed terminal chat, but that does not carry workbench output. These source observations identify attachment gaps without establishing the intended automatic-context policy. Preserve SDK shell execution, terminal ownership, and existing nonterminal attachments; terminal reuse requested in https://github.com/microsoft/vscode/issues/338999 is distinct work.
- **Open decisions:**
  - Should this request cover only user-selected terminal attachments, or also automatically include context from workbench terminals? If automatic inclusion is intended, which terminals and how much command/output history should be included?
