# Issue #344491 — Remove Dynamic Authentication Providers picker can't distinguish entries that share an authorization server

[https://github.com/microsoft/vscode/issues/344491](https://github.com/microsoft/vscode/issues/344491)

## Summary

Current source confirms that distinct resource-specific providers can appear identical in both the removal picker and confirmation dialog. Keep this open while the linked implementation candidate is reviewed; it has not merged.

## Change summary

Make dynamic authentication providers distinguishable by resource when their authorization server, label, and client ID are shared.

## Best solution

Review https://github.com/microsoft/vscode/pull/344502 for resource-specific identification in both the picker and removal confirmation, while preserving provider-specific deletion and existing authentication identities.

## Evidence

- **Picker and confirmation defect:** src/vs/workbench/contrib/authentication/browser/actions/manageDynamicAuthenticationProvidersAction.ts constructs picker entries using only provider.label and 'Client ID: {0}', without displaying providerId or resource information. The confirmation derives providerNames solely from item.provider.label. Providers sharing the reported label and CIMD client ID therefore produce identical visible entries and confirmation names.
- **Distinct identities with identical labels:** src/vs/workbench/api/common/extHostAuthentication.ts:519-525 constructs the default provider ID from the authorization server plus resource, but sets the label to resource_name or the authorization server authority. Distinct resources without resource_name behind the same authorization server consequently have distinct IDs but identical labels, matching the reported trigger.
- **Information available at the affected surface:** DynamicAuthenticationProviderInfo in src/vs/workbench/services/authentication/common/dynamicAuthenticationProviderStorage.ts includes providerId, authorizationServer, label, and clientId. The removal action already retains each provider object and deletes by providerId; the demonstrated defect is missing identification in the UI, not an inability to target separate providers internally.
- **Open implementation candidate:** The public GitHub API confirms https://github.com/microsoft/vscode/pull/344502 is open with merged_at null and explicitly says 'Fixes #344491'. Its description addresses resource identification in both picker entries and confirmation names. This is pending work, not evidence of a landed fix, and precludes a competing agent implementation.
