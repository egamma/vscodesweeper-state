# Issue #193558 — Only on macOS , some drag-and-drop interactions fail within iframe in extension's webview

[https://github.com/microsoft/vscode/issues/193558](https://github.com/microsoft/vscode/issues/193558)

## Summary

Still reproduces on current main. The webview's pre/index.html attaches drag event handlers (lines 913–916, 1219–1222) that call `e.preventDefault()` unconditionally on dragover in the content window — this may interfere with extension-authored drag-and-drop inside nested cross-origin iframes, and the macOS-only manifestation suggests Chromium/Electron platform behavior differences. The `help wanted` label from prior triage indicates the team would accept a community contribution.

## Change summary

Drag-and-drop interactions within cross-origin iframes embedded inside extension webviews fail on macOS, while working on Windows.

## Best solution

Investigate whether the unconditional `e.preventDefault()` in `handleInnerDragEvent` (src/vs/workbench/contrib/webview/browser/pre/index.html, line 804) should be conditioned on file drags only (matching the message-posting guard), or whether the macOS failure is an upstream Chromium/Electron issue with cross-origin iframe drag events under the webview's sandbox rules. If upstream, document the limitation and consider whether adding the Chromium bug reference as an `upstream` label is appropriate. A contributor could narrow the fix by testing whether guarding the `preventDefault()` call behind the file-drag check resolves the macOS behavior.

## Evidence

- **drag handler intercepts all dragover:** src/vs/workbench/contrib/webview/browser/pre/index.html line 804: `handleInnerDragEvent` calls `e.preventDefault()` unconditionally on all dragover/drag events, but only posts a host message for file-type drags (line 811–816). This blanket preventDefault may suppress extension drag-and-drop in nested iframes on macOS.
- **handlers attached to sub-iframe contentWindow:** Lines 1219–1222 attach dragenter/dragover/drag/drop handlers to every sub-iframe's contentWindow, meaning extension content that nests its own iframe will have these handlers intercept drag events in the nested frame as well.
