# Issue #343117 — Codex agent host: model selection during thread startup can route the first turn through the wrong provider

[https://github.com/microsoft/vscode/issues/343117](https://github.com/microsoft/vscode/issues/343117)

## Summary

Keep open: current main still permits a provider change during asynchronous thread creation to leave the first turn using the previous provider. This is a VS Code startup-reconciliation defect, distinct from Codex's handling of encrypted history after a provider switch.

## Change summary

Ensure a fresh Codex thread uses the selected model provider before its first turn, including selections changed while startup is pending.

## Best solution

Make the Codex harness honor the latest provider selection before committing the first turn, with deterministic coverage of changes during pending startup. Preserve intentional provider switching on existing conversations; recovery of incompatible historical ciphertext remains separate upstream work.
