# Issue #293702 — Screen reader does not read BYOC model selection

[https://github.com/microsoft/vscode/issues/293702](https://github.com/microsoft/vscode/issues/293702)

## Summary

Keep open: the model picker has been redesigned since this report, and current source supplies model names and selection semantics, but that does not establish that Windows screen readers announce custom models correctly. The supplied steps suffice to retest; no verified duplicate or specific fixing commit was established.

## Change summary

Custom models in the chat model picker are announced as "Action" or remain silent during arrow-key navigation instead of exposing their names and selection state.

## Best solution

Verify custom-model announcements in the current chat picker on Windows, then address any remaining accessible-name, selection-state, or focus-announcement defect. Preserve meaningful selection announcements in both searchable and menu presentations rather than requiring the literal words "Checked" and "Unchecked" everywhere.

- **Current accessible-name and selection path:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemPrimitives.ts: createModelAction assigns metadata.name to the action label and compares model.identifier with selectedModelId for checked state; createModelItem copies the label into the list item. modelPickerItems.ts: getModelPickerAccessibilityProvider exposes that label, uses menuitemradio with checked state for menu presentation, and uses option semantics with a "Current model" announcement for search presentation.

ModelPickerWidget and TabbedModelPicker now pass getModelPickerAccessibilityProvider to their lists; ActionListWidget updates the search input's aria-activedescendant as list focus changes.
