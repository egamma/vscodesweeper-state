## Evidence

- **Intentional watcher configuration:** src/vs/workbench/api/common/extHostFileSystemEventService.ts:175-231, FileSystemWatcher.ensureWatching, applies files.watcherExclude as exclusions for recursive requests. For non-recursive requests inside a workspace, it deliberately converts those patterns into includes so the additional watcher supplies events omitted by the standard workspace watcher without duplicating its events.
- **Exact Git call paths:** extensions/git/src/repository.ts:930 creates the recursive repository watcher with RelativePattern(repository.root, '**'). DotGitWatcher at lines 462-510 watches the .git directory and upstream ref through extensions/git/src/watch.ts, whose RelativePattern(location, '*') creates non-recursive requests. These paths explain both log examples without an exclusion-mapping defect.
- **Includes are event filters:** src/vs/platform/files/node/watcher/nodejs/nodejsWatcherLib.ts:486-508 checks includes against individual event paths before aggregation. The patterns listed under includes do not themselves create recursive watches of those folders. src/vscode-dts/vscode.d.ts:14002-14006 also documents that non-recursive extension watchers bypass recursive watcher exclusions.
