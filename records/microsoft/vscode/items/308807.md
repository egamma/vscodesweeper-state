## Evidence

- **Intentional exclusion-to-inclusion mapping:** src/vs/workbench/api/common/extHostFileSystemEventService.ts, FileSystemWatcher.ensureWatching, applies files.watcherExclude as exclusions for recursive requests. For non-recursive requests inside a workspace, it deliberately converts those patterns into includes, appending /**, to supply events excluded from the ordinary workspace watcher without duplicating its events.
- **Exact Git registration path:** extensions/git/src/repository.ts, DotGitWatcher.updateTransientWatchers, watches the current upstream ref under .git/refs/remotes/<remote>/<branch>. extensions/git/src/watch.ts constructs a RelativePattern(location, '*'), producing the non-recursive request shown in the report. The includes do not turn that request into recursive watches of all listed directories.
- **Historical rationale:** The current exclusion-to-inclusion code explicitly references https://github.com/microsoft/vscode/issues/148245, a closed report about missing extension file events when watcher exclusions were configured. That issue explains the complementary watcher behavior; it is not a canonical duplicate for the remote crash.
- **Crash evidence is incomplete:** https://github.com/microsoft/vscode/issues/308807 identifies intermittent core files associated with the remote fileWatcher process, but supplies no termination signal, backtrace, or action that reliably triggers termination. Its reproduction steps demonstrate trace logging, not the crash. Inspection of the attached log at https://github.com/user-attachments/files/26607931/vscode-app-1775729310203.copy.log found no matching crash, signal, ENOSPC, ENOMEM, or watcher failure diagnostic.
- **Canonical search:** GitHub searches for watcherExclude/includes, fileWatcher core dumps, and open Linux watcher crashes did not establish an open canonical owning this report. The open Windows-specific report https://github.com/microsoft/vscode/issues/317176 concerns a regex backreference failure in Windows paths and does not establish the same cause on Red Hat.
