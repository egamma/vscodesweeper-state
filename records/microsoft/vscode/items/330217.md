# Issue #330217 — F*** this GitHub Authentication built-in module, please?

[https://github.com/microsoft/vscode/issues/330217](https://github.com/microsoft/vscode/issues/330217)

## Summary

The fix for the linked issue (auto re-enabling the GitHub Authentication extension) only covers the Copilot Chat setup/sign-in flow, not other consumers of the extension like Git source control — so users whose GitHub Authentication extension ends up disabled outside that flow still hit a dead end, matching this report and the independent corroboration in the comments.

## Change summary

GitHub Authentication built-in extension gets disabled and can't be re-enabled through the UI, breaking Copilot sign-in and Git source control auth.

## Best solution

Extend or generalize the auto re-enable check beyond `maybeEnableAuthExtension` in src/vs/workbench/contrib/chat/browser/chatSetup/chatSetup.ts (currently only invoked from chatSetupProviders.ts and chatSetupController.ts) so Git/source-control authentication flows also recover a disabled GitHub Authentication extension, and/or surface an enable action in the Extensions view for the enablement states this check doesn't handle.
