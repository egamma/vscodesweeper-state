# Issue #335822 — Manual automations can be disabled even though they remain runnable

[https://github.com/microsoft/vscode/issues/335822](https://github.com/microsoft/vscode/issues/335822)

## Summary

Confirmed on main: the Disable/Enable context-menu actions for automation cards are gated only on `AutomationCardEnabledContext`, not on whether the automation has a schedule, and the run button's enabled state (`card.runButton.enabled`) is driven only by `canRunAutomation`, never by `automation.enabled` — so a manual automation can be marked Disabled while remaining fully runnable, exactly as reported.

## Change summary

Manual (schedule-less) automations can be toggled to a 'Disabled' state via the card's overflow menu, but the disabled state has no effect: the run button stays active and the automation can still be started manually.

## Best solution

In src/vs/sessions/contrib/sessions/browser/views/automationsView.ts, hide the Disable/Enable menu entries (and the disabled badge) for automations whose `schedule.interval === 'manual'`, since suspending a schedule is the only meaningful semantics of 'disabled' today; alternatively, make the run button honor `automation.enabled` for all automations if disabling is meant to fully pause them.
