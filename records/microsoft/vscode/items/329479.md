# Issue #329479 — AllowedExtensions - Problems with Permitting Extensions from Trusted Publishers

[https://github.com/microsoft/vscode/issues/329479](https://github.com/microsoft/vscode/issues/329479)

## Summary

Traced this in the source: when an extension's publisherDisplayName matches a configured trusted `extensionPublisherOrgs` entry (e.g. "Microsoft"), `AllowedExtensionsService.isAllowed` swaps the lookup key from the raw publisher id (`ms-azuretools`) to the org name (`microsoft`) — so an `AllowedExtensions` entry keyed by the specific publisher id is silently never checked. This looks like a real precedence gap in the allow-list logic, not a documented design choice, so it needs a maintainer call on intended precedence rather than a close.

## Change summary

AllowedExtensions policy entries for a specific publisher id (e.g. `ms-azuretools`) are ignored for extensions whose publisherDisplayName maps to a trusted org (e.g. `microsoft`), forcing admins to allow the entire org instead of one publisher.

## Best solution

In src/vs/platform/extensionManagement/common/allowedExtensionsService.ts, decide (and implement) whether the publisher-id key should still be checked as a fallback/override even when the org-mapped key exists, so admins can allow a specific publisher without allow-listing the whole trusted org; route to the extension-management area owners for a design decision, then add a regression test alongside the existing allowedExtensionsService.test.ts suite.
