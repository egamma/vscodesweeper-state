# Issue #175164 — vscode web incorrectly opens uri resolved from IExternalUriResolver

[https://github.com/microsoft/vscode/issues/175164](https://github.com/microsoft/vscode/issues/175164)

## Summary

The TODO at openerService.ts:221 confirms this is a known gap — IExternalUriResolver only accepts/returns URI, losing URL-string fidelity. The linked PR #175166 is still open and unmerged. Keeping open as a valid backlog item with an existing implementation candidate.

## Change summary

IExternalUriResolver should support returning a URL string (not just URI) so resolved external URIs don't lose encoding fidelity when opened in VS Code web.

## Best solution

Review and land (or close) the open PR https://github.com/microsoft/vscode/pull/175166 which extends IExternalUriResolver to return URI or URL string, addressing the TODO at src/vs/editor/browser/services/openerService.ts:221.
