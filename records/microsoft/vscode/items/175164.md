# Issue #175164 — vscode web incorrectly opens uri resolved from IExternalUriResolver

[https://github.com/microsoft/vscode/issues/175164](https://github.com/microsoft/vscode/issues/175164)

## Summary

Keep open: the web embedder resolver still only accepts and returns URI objects, and current opener code retains the encoding limitation identified in the report. The linked implementation PR remains open, so the next step is to review that candidate rather than close the issue or start competing work.

## Change summary

Allow web embedders to resolve external URLs without losing their intended percent-encoding through URI conversion.

## Best solution

Provide an encoding-preserving web embedder resolver contract while retaining compatibility with existing URI-based embedders. Review https://github.com/microsoft/vscode/pull/175166 against that requirement and the earlier encoding regressions before landing a change.

- **Current opening path:** src/vs/platform/opener/common/opener.ts likewise restricts resolver results to resolved: URI. In src/vs/editor/browser/services/openerService.ts, _resolveExternalUriOpenTarget retains the TODO to support URI | string; it preserves the original input string only when the resolved URI matches the input URI, otherwise constructing href with encodeURI(externalUri.toString(true)). The raw-string escape hatch therefore does not cover a resolver that changes the target.
