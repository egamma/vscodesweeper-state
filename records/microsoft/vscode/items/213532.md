# Issue #213532 — Git - Git fails to switch to remote branch when same name local branch exists

[https://github.com/microsoft/vscode/issues/213532](https://github.com/microsoft/vscode/issues/213532)

## Summary

The collision-handling gap remains in current source: selecting upstream/master attempts to create master when no local branch tracks that remote, even if master already exists. Keep this report open; the related naming request is newer, and the earlier closed report addressed a different tracking case.

## Change summary

When checking out a remote branch whose default local name already exists, offer a different local name and establish tracking automatically.

## Best solution

Provide collision recovery in the built-in Git checkout flow that creates a user-named branch tracking the selected remote without changing the existing branch or its upstream. Preserve the existing behavior of switching to a local branch that already tracks the selected remote.

## Evidence

- **Current collision path:** extensions/git/src/commands.ts:166–185, CheckoutRemoteHeadItem.run, searches for branches tracking the exact selected remote. With master tracking origin/master and no branch tracking upstream/master, it calls repository.checkoutTracking('upstream/master'). extensions/git/src/repository.ts:2322–2329 forwards track: true, and extensions/git/src/git.ts:2047–2079 constructs git checkout -q --track upstream/master with no alternate local name or collision recovery.
- **Exact upstream matching:** extensions/git/src/git.ts:2989–2994, findTrackingBranches, filters local branches by exact upstream equality. A same-named branch tracking origin/master does not satisfy a checkout of upstream/master.
- **Existing capability is partial:** The registered git.branchFrom command in extensions/git/package.json and Commands._branch in extensions/git/src/commands.ts let users select a remote starting point and supply a local name. However, extensions/git/src/git.ts:2189–2196 explicitly creates that branch with --no-track, so this alternative does not deliver the requested automatic tracking. Checkout detached also does not create the requested persistent tracking branch.
- **Earlier report has different coverage:** https://github.com/microsoft/vscode/issues/60904 is closed. Its maintainer explanation at https://github.com/microsoft/vscode/issues/60904#issuecomment-430485479 calls for switching to an existing local branch already tracking the selected remote. Current CheckoutRemoteHeadItem implements that behavior, but it does not cover this report's different-remotes name collision.
