# Issue #329280 — ExtensionDependencies cascade error fires despite capabilities.untrustedWorkspaces.supported: false being explicitly declared

[https://github.com/microsoft/vscode/issues/329280](https://github.com/microsoft/vscode/issues/329280)

## Summary

This matches VS Code's intended dependency-cascade handling, not a violation of the untrustedWorkspaces contract: the ModusToolbox extension itself correctly stays disabled in Restricted Mode, and the notification is shown for a *different*, dependent extension (e.g. the ModusToolbox AI Assistant) that cannot activate because its declared dependency is trust-disabled.

## Change summary

An extension that declares `capabilities.untrustedWorkspaces.supported: false` still appears associated with an activation-error toast when an untrusted workspace is opened.

## Best solution

Close as as-designed: this is the intended `DisabledByTrustRequirement` notification path for a dependent extension whose dependency is disabled by trust, not a bug in core's untrusted-workspace enforcement. If the reporter believes ModusToolbox for VS Code itself is executing code in Restricted Mode (not just being named in another extension's error), that would need to be filed against InfineonAG's extension repo instead.
