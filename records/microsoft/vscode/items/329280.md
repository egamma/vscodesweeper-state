# Issue #329280 — ExtensionDependencies cascade error fires despite capabilities.untrustedWorkspaces.supported: false being explicitly declared

[https://github.com/microsoft/vscode/issues/329280](https://github.com/microsoft/vscode/issues/329280)

## Summary

Traced the exact code path on main: when a dependency extension is disabled specifically due to workspace trust (`EnablementState.DisabledByTrustRequirement`), VS Code deliberately shows a 'Cannot activate ... not supported in Restricted Mode' toast (with a 'Manage Workspace Trust' action) to explain why the *dependent* extension failed to activate — this is purpose-built notification code, not the untrusted extension itself being activated.

## Change summary

Reporter says an extension declaring `untrustedWorkspaces.supported: false` still triggers an activation-error toast in an untrusted workspace instead of staying silently disabled.

## Best solution

Keep the existing behavior: `src/vs/workbench/api/browser/mainThreadExtensionService.ts` (lines ~122-135) intentionally surfaces this specific toast so users understand why a dependent extension can't load, while the untrusted extension itself remains disabled as documented — no code change needed unless the reporter can show the untrusted extension's own code actually executes.

## Evidence
