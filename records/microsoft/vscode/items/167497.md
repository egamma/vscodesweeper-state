# Issue #167497 — Custom Emmet snippets wrap selected text incorrectly

[https://github.com/microsoft/vscode/issues/167497](https://github.com/microsoft/vscode/issues/167497)

## Summary

Confirmed bug still present on main: custom Emmet snippets from snippets.json place wrapped text at the wrong position (in the outermost element instead of the deepest). No fix commit references this issue, and the wrap+custom-snippet code path in the emmet library has not changed.

## Change summary

Custom Emmet snippets using `$#` for output position place wrapped text in the wrong (outermost) element when used with Wrap with Abbreviation.

## Best solution

The fix likely needs to happen in the `emmet` npm package (v2.4.11) or `@vscode/emmet-helper` (v2.11.0) where custom snippet abbreviations are resolved with the `text` wrap option — the text placement logic doesn't honor the `$#` marker from user-defined snippets. Updating the emmet dependency or patching the expand logic in `extensions/emmet/node_modules/@vscode/emmet-helper/lib/esm/emmetHelper.js` around the `getExpandOptions` / `expand` call would be needed.
