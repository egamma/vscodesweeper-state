# Issue #334248 — Agent Host file monitor watches session roots recursively, ignoring files.watcherExclude

[https://github.com/microsoft/vscode/issues/334248](https://github.com/microsoft/vscode/issues/334248)

## Summary

Still present on current main: the agent host's changeset coordinator acquires a recursive watcher with a hardcoded git-only exclude list and never merges the user's `files.watcherExclude`, so large workspaces (node_modules etc.) get fully watched by the agent host's watcher process; keep open and route to the file-watcher/agent-host owners.

## Change summary

The Agent Host file monitor watches session roots recursively using only its built-in git excludes, ignoring the user's `files.watcherExclude`, which can exhaust inotify watch limits.

## Best solution

Plumb the workspace folder's `files.watcherExclude` patterns into the agent host's watcher acquisition and merge them with DEFAULT_AGENT_HOST_WATCH_EXCLUDES — mirroring how the extension host already auto-adds `files.watcherExclude` to extension-created watchers in src/vs/workbench/api/common/extHostFileSystemEventService.ts.

Acceptance: on a workspace with `**/node_modules/**` excluded, the agent host's file watcher process no longer holds watches under node_modules, and change notifications the agent host relies on for non-excluded paths still fire.
- **Trace:**

  > `AgentHostChangesetFileMonitorCoordinator._ensureRootWatcher` (src/vs/platform/agentHost/node/agentHostChangesetFileMonitorCoordinator.ts:382-395) calls `IAgentHostFileMonitorService.acquire` with `excludes: DEFAULT_AGENT_HOST_WATCH_EXCLUDES`; `AgentHostFileMonitorService._createEntry` (src/vs/platform/agentHost/node/agentHostFileMonitorService.ts:107-113) uses exactly those patterns for both `IFileService.watch({ recursive: true, excludes })` and the in-process match filter. `rg watcherExclude` shows no configuration read anywhere in src/vs/platform/agentHost, confirming the report. The boundary: keep the default git patterns, keep the refcounted entry keying (the key already includes the exclude list, agentHostFileMonitorService.ts:182-184) so differing exclude sets do not silently share an entry, and do not change the debounce or callback semantics. - **Open decisions:**
