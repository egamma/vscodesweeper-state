# Issue #334248 — Agent Host file monitor watches session roots recursively, ignoring files.watcherExclude

[https://github.com/microsoft/vscode/issues/334248](https://github.com/microsoft/vscode/issues/334248)

## Summary

Verified against current main: the Agent Host changeset file monitor really does hardcode its own git-only exclude list and never consults `files.watcherExclude`, so root watches can balloon into hundreds of thousands of inotify handles and, at common ulimits, break file watching for the whole window.

## Change summary

Agent Host's recursive session-root file watcher ignores the user's `files.watcherExclude` configuration, watching far more of the tree (e.g. `node_modules`) than the workbench watcher does.

## Best solution

Merge the resource-scoped `files.watcherExclude` patterns into the excludes passed to `IAgentHostFileMonitorService.acquire` in `ChangesetFileMonitorCoordinator._ensureRootWatcher` (currently hardcoded to `DEFAULT_AGENT_HOST_WATCH_EXCLUDES`), presumably by resolving them through the existing agent host configuration plumbing (`agentConfigurationService.ts`) rather than assuming the two exclude sets are unrelated.
