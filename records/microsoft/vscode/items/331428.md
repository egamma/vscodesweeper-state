# Issue #331428 — Copilot retries deterministic inaccessible-image HTTP 400 four times

[https://github.com/microsoft/vscode/issues/331428](https://github.com/microsoft/vscode/issues/331428)

## Summary

Confirmed on current main: `shouldAutoRetry()` in toolCallingLoop.ts retries any non-success response in auto-approve/autopilot except a short deny-list (rate-limit, quota, cancel, off-topic, refusal) — `vision_attachment_not_accessible` isn't special-cased anywhere in the extension, so a deterministic bad-request gets resent unchanged three times. An open PR already fixes this, so it should stay open for that PR to land rather than being closed or auto-fixed here.

## Change summary

Restored chats with an inaccessible historical image cause Copilot agent mode to auto-retry a deterministic `vision_attachment_not_accessible` HTTP 400 three extra times instead of failing fast and offering recovery.

## Best solution

Land https://github.com/microsoft/vscode/pull/331430, which classifies `vision_attachment_not_accessible` distinctly, skips generic auto-retry for it, and does a single clean retry with the stale image set omitted (persisting a SHA-256 hash marker in turn metadata) — matching exactly what this issue asks for.
