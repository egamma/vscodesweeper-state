# Issue #198096 — Support fontFamily per token type

[https://github.com/microsoft/vscode/issues/198096](https://github.com/microsoft/vscode/issues/198096)

## Summary

The underlying infrastructure for per-token fontFamily now exists on main (via tokenColorCustomizations and the theme token settings schema), but the specific UX proposed — an object-form `editor.fontFamily` setting with named token-type keys — has not been implemented. Team-authored feature request in Backlog; keeping open.

## Change summary

Allow setting different font families per token type (comment, string, etc.) via a structured `editor.fontFamily` setting.

## Best solution

Evaluate whether the existing `editor.tokenColorCustomizations` textMateRules + token group settings (which already support `fontFamily`, `fontSize`, `lineHeight`) satisfy this request, or whether a first-class `editor.fontFamily` object-form setting is still desired for discoverability. If the existing mechanism suffices, close as covered; if a friendlier setting surface is wanted, implement it in the editor configuration schema.

## Evidence

- **fontFamily in token schema:** src/vs/workbench/services/themes/common/colorThemeSchema.ts defines `fontFamily` as a property in the token settings schema, allowing themes and tokenColorCustomizations to specify font family per token scope.
- **fontFamily in IFontTokenOption:** src/vs/editor/common/textModelEvents.ts defines `IFontTokenOption.fontFamily?: string`, and the decoration provider in src/vs/editor/common/model/tokens/tokenizationFontDecorationsProvider.ts applies it via CSS class decorations.
- **colorThemeData processing:** src/vs/workbench/services/themes/common/colorThemeData.ts reads `ruleSettings.fontFamily` from token color rules and feeds it into the font token index.
- **no object-form setting:** The `editor.fontFamily` setting remains a simple string in src/vs/editor/common/config/editorOptions.ts — the object-form with per-token-type keys proposed in this issue has not been implemented.
