# Issue #198096 — Support fontFamily per token type

[https://github.com/microsoft/vscode/issues/198096](https://github.com/microsoft/vscode/issues/198096)

## Summary

TextMate font-family customization now covers part of this request, but semantic-token font families and per-token variation/ligature settings remain unsupported. Keep this team-authored backlog item open to settle the remaining configuration contract.

## Change summary

Allow font families to vary by token type, with discussion requesting semantic-selector support and comparable control over font variations and ligatures.

## Best solution

Build on the existing TextMate font customization rather than introduce a competing mechanism without a product decision. Define the remaining semantic-token and per-token typography contract, coordinating with the related semantic font-metadata work.

  > Users want distinct fonts for token categories while retaining a default editor font. - **Trace:**

  > TextMate settings enter through colorThemeSchema.ts and ColorThemeData.getTokenFontIndex in src/vs/workbench/services/themes/common/colorThemeData.ts; TokenizationFontDecorationProvider and generateFontTokensCSS in the editor convert token-font metadata into decorations and CSS. Semantic TokenStyle in src/vs/platform/theme/common/tokenClassificationRegistry.ts carries no font-family or variation/ligature fields. Editor options provide scalar editor.fontFamily and separate editor.inlineSuggest.fontFamily settings. Preserve existing TextMate behavior and editor.allowVariableFonts/editor.allowVariableFontsInAccessibilityMode restrictions. Related semantic metadata work is tracked at https://github.com/microsoft/vscode/issues/287118, with an inheritance example at https://github.com/microsoft/vscode/issues/286157; these younger, narrower issues do not supersede this report.
