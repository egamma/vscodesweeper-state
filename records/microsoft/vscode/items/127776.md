# Issue #127776 — Call stack decoration: consider using background color and not a decoration

[https://github.com/microsoft/vscode/issues/127776](https://github.com/microsoft/vscode/issues/127776)

## Summary

A real gap remains: current main highlights the active stack-frame line with a background but still inserts an inline arrow for mid-line statement positions, which shifts the source text. The request has maintainer support but needs a small product decision about the intended highlight range before implementation.

## Change summary

Indicate the active debugging statement with background highlighting rather than an inline arrow that shifts source text.

## Best solution

Use a non-layout-shifting highlight for the active statement while preserving useful gutter and breakpoint indicators. The debug area should first settle whether that highlight covers the statement range or the whole line and whether end-of-function pauses receive a highlight.

- **Behavior:**

  > Pausing or stepping on a statement must not change the horizontal position of source text, including when the statement begins in the middle of a line. The active and focused stack frames must remain distinguishable, and breakpoint indicators must retain their existing meaning. The selected highlight range and behavior at locations without an executable expression must follow the maintainer decisions below. Acceptance requires unit coverage for generated decorations and a manual stepping check confirming that text remains stationary.
- **Trace:**

  > The remaining layout shift originates in `createDecorationsForStackFrame` in src/vs/workbench/contrib/debug/browser/callStackEditorContribution.ts: it always emits the background class and additionally emits `makeStackFrameColumnDecoration` for top frames whose `startColumn` is greater than 1. The inline class is styled with width and margins in src/vs/workbench/contrib/debug/browser/media/debug.contribution.css; only its `start-of-line` variant is absolutely positioned. Background colors are already registered and rendered through src/vs/workbench/contrib/debug/browser/media/callStackEditorContribution.css. The `decorations` test in src/vs/workbench/contrib/debug/test/browser/callStack.test.ts captures the current start-column behavior. Preserve breakpoint-candidate rendering and unrelated inline breakpoint controls; this request concerns the current-stack-frame indicator described in https://github.com/microsoft/vscode/issues/127776 and the originating discussion at https://github.com/microsoft/vscode/issues/124169#issuecomment-872219638.
- **Open decisions:**
  - Should the active-statement background cover the debugger-reported expression range or the entire source line?
  - After removing the text-shifting inline arrow, should the existing gutter stack-frame arrow remain for every active frame?
  - When the debugger reports a position at the end of a function without an executable expression, should VS Code highlight the line or show no editor highlight?
