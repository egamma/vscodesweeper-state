# Issue #240719 — Git - stage selected ranges in an untracked file

[https://github.com/microsoft/vscode/issues/240719](https://github.com/microsoft/vscode/issues/240719)

## Summary

Keep open: staging only selected lines of an untracked file remains unsupported, and a maintainer explicitly recognized the scenario's merit. The intentional switch to a normal editor does not satisfy this request, and the verified related issues concern different behaviors.

## Change summary

Allow staging selected ranges of a new, untracked file without staging its entire contents first.

## Best solution

Provide a supported partial-staging workflow in the built-in Git extension that leaves unselected content in the working file. Decide how users discover and invoke it while preserving the intentional normal-editor default for untracked files.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/quickDiffProvider.ts`, `extensions/git/src/staging.ts`
- **Validation:** In a disposable Git repository, create an untracked text file containing several distinct lines, select only a subset in the agreed VS Code surface, and invoke partial staging. Inspect git show :<path> to verify that only selected lines entered the index, verify the working file is unchanged, and verify remaining content is still unstaged. Repeat with a tracked modified file to confirm existing selected-range staging behavior is preserved.
- **Behavior:**

  > Users can stage selected lines from a genuinely untracked text file without first staging or committing the whole file. The index contains only the selected content, while the working file retains all content and the remainder stays unstaged. The workflow must be discoverable in the agreed editor surface and must preserve existing full-file staging and tracked-file partial staging. Acceptance includes inspecting the Git index and working file after selecting only part of a new file.
- **Trace:**

  > ResourceCommandResolver in extensions/git/src/repository.ts opens untracked resources in a normal editor because getLeftResource supplies no baseline for Status.UNTRACKED. CommandCenter.stageSelectedChanges in extensions/git/src/commands.ts requires getWorkingTreeDiffInformation, whose helpers in extensions/git/src/staging.ts require an original Git URI; Git quick-diff provision in extensions/git/src/quickDiffProvider.ts explicitly excludes untracked files. The command is registered for ordinary file editors, but its context-menu entry requires a diff editor, and _stageChanges also opens a Git baseline before constructing staged contents. Repository.stage already accepts explicit contents for the index. Preserve the intentional distinction between nonexistent and empty Git resources described at https://github.com/microsoft/vscode/issues/239914#issuecomment-2642654634; do not restore a blanket empty-content fallback or include the separate rename and diff-refresh issues. The remaining uncertainty is the user-visible entry point: normal-editor selective staging versus an explicit untracked-file diff surface.
- **Open decisions:**
  - Should partial staging of untracked files be exposed directly in the normal editor, through an explicit opt-in diff view, or through both, while retaining the current normal-editor default?

## Evidence

The On Deck milestone represents accepted, unscheduled work; an as-designed decline would contradict this direction.
- **Existing capability does not cover untracked files:** extensions/git/package.json registers git.stageSelectedRanges in the command palette and as a keybinding for file editors, but its editor context-menu entry requires a diff editor. In extensions/git/src/commands.ts:1778-1811, stageSelectedChanges returns when getWorkingTreeDiffInformation is absent. extensions/git/src/quickDiffProvider.ts:60-64 explicitly excludes untracked files from original-resource provision, and extensions/git/src/staging.ts:217-227 requires an original Git resource for working-tree diff information.
- **Current opening behavior and setting:** In extensions/git/src/repository.ts:532-561 and 603-620, an untracked resource has no left resource and resolveChangeCommand opens a normal editor through vscode.open. git.openDiffOnClick is a boolean setting in extensions/git/package.json:3892-3896; enabling it still follows that resolver and does not create an untracked-file diff or enable partial staging.
- **Staging boundary:** extensions/git/src/commands.ts:1940-1953 builds selected content against a Git original document at ref '~', then calls Repository.stage. extensions/git/src/repository.ts:1323-1330 already accepts explicit staged contents. Supporting a genuinely untracked file therefore requires addressing the absent baseline as well as command discoverability, not merely changing the context-menu condition.
