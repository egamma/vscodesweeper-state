# Issue #327597 — kimi-k2.7-code generates tool_use IDs that block subsequent requests to Anthropic with HTTP 400

[https://github.com/microsoft/vscode/issues/327597](https://github.com/microsoft/vscode/issues/327597)

## Summary

Confirmed in source: the Copilot extension's messagesApi.ts passes tool call IDs through to Anthropic without sanitization (line 295, line 341), so IDs from models like kimi that use dots/colons break Anthropic's `^[a-zA-Z0-9_-]+$` validation on model switch. This is a real cross-model interop bug.

## Change summary

Switching models mid-session after using kimi-k2.7-code permanently breaks the session because kimi's tool_use IDs (containing dots and colons) violate Anthropic's ID format constraint.

## Best solution

Sanitize tool call IDs in `extensions/copilot/src/platform/endpoint/node/messagesApi.ts` when building Anthropic message payloads — replace characters outside `[a-zA-Z0-9_-]` with `_` in the `id` field at line 295 and the `tool_use_id` field at line 341. Alternatively, the sanitization could live in the conversation history builder (`chatHistoryBuilder.ts`) so all downstream endpoints benefit. The server-side GitHub Copilot API proxy could also enforce this, but a client-side guard is the most robust defense.
