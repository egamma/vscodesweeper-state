# Issue #327597 — kimi-k2.7-code generates tool_use IDs that block subsequent requests to Anthropic with HTTP 400

[https://github.com/microsoft/vscode/issues/327597](https://github.com/microsoft/vscode/issues/327597)

## Summary

Already fixed on main: the Anthropic Messages API path sanitizes tool call IDs before replaying history, exactly addressing the `functions.list_dir:0` style IDs described here.

## Change summary

kimi-k2.7-code produces tool_use IDs with dots/colons that Anthropic rejects (HTTP 400) when the conversation history is later replayed to an Anthropic model, permanently breaking the session.

## Best solution

Keep the existing fix in `extensions/copilot/src/platform/endpoint/node/messagesApi.ts` (sanitizeToolCallId / createAnthropicToolCallIdMapper), which replaces any character outside `[a-zA-Z0-9_-]` with `_` and de-duplicates collisions when remapping IDs for Anthropic requests — no further change needed beyond the reporter confirming on a build that includes it.
