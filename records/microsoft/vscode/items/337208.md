## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser`, `src/vs/platform/terminal`
- **Validation:** Manual verification that terminal glyph rendering is visibly crisper on HiDPI macOS with the new setting enabled, while default (`inherit`) behavior and terminal image transparency remain unchanged.
- **Behavior:**

  > A new opt-in terminal setting controls font antialiasing/rendering sharpness for terminal text only (not editor/workbench text), defaulting to today's unchanged behavior (`inherit`) with an opt-in `crisp` mode. It must work across normal, detached, and sticky-scroll terminals and preserve terminal image transparency.
- **Trace:**

  > The author identifies the difference as an antialiasing policy difference between editor/workbench text and terminal GPU-canvas text rendering on macOS, exercised through xterm's `allowTransparency` canvas path since xterm.js does not yet expose a dedicated antialiasing option. The open question (per dalisoft's comment) is how this setting should behave under light themes, and how Windows/Linux grayscale antialiasing requests should be scoped relative to the existing GPU renderer alpha-capable canvas path.
- **Open decisions:**
  - Should the setting default/behavior differ for light vs. dark themes (per dalisoft's follow-up)?
  - Should this be pursued now via the allowTransparency canvas-path workaround, or deferred until xterm.js ships a first-class antialiasing option upstream?
