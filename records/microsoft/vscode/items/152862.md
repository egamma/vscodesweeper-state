# Issue #152862 — A change in VScode makes it confusing for a user to switch the to a different PowerShell environment in the Integrated Terminal.

[https://github.com/microsoft/vscode/issues/152862](https://github.com/microsoft/vscode/issues/152862)

## Summary

Valid UX concern about language status discoverability — the request for extensions to programmatically pin status items remains unimplemented. The LanguageStatusItem API still has no pin/pinByDefault property on current main, and both the PowerShell team (MEMBER) and community are asking for it.

## Change summary

Extensions cannot programmatically pin language status items to the status bar, making important session-switching UX less discoverable.

## Best solution

Add a `pinned` or `pinByDefault` property to the `LanguageStatusItem` API so extensions like PowerShell can opt into permanent status bar visibility without user intervention. The implementation would touch `src/vs/workbench/contrib/languageStatus/browser/languageStatus.ts` (pin logic) and `src/vscode-dts/vscode.d.ts` (API surface). Related issue https://github.com/microsoft/vscode/issues/165940 tracks broader control of language status text but not specifically default pinning.
