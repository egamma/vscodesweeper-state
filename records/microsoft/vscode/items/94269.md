# Issue #94269 — [semantic tokens] provide code assist for tokenModifiers

[https://github.com/microsoft/vscode/issues/94269](https://github.com/microsoft/vscode/issues/94269)

## Summary

The requested modifier-aware completion remains missing on current main. The existing schema suggests bare token types and wildcard modifier selectors, but cannot provide contextual combinations such as `variable.readonly`; the maintainer explicitly identified a completion provider as the intended direction.

## Change summary

Provide code completion for semantic-token modifiers while authoring semantic-token theme selectors.

## Best solution

Add contextual semantic-token selector completion for color-theme files, using registered token types and modifiers without materializing every permutation. A maintainer should first settle whether the same provider covers `editor.semanticTokenColorCustomizations.rules` and whether suggestions are limited to statically contributed classifications.

## Plan brief

- **Likely files:** `extensions/configuration-editing/src/configurationEditingMain.ts`, `extensions/configuration-editing/src/test/completion.test.ts`, `src/vs/platform/theme/common/tokenClassificationRegistry.ts`
- **Validation:** Extend the configuration-editing completion tests to open a color-theme JSON document and assert that completion after a selector such as `variable.` includes registered modifiers without proposing an already-used modifier; add the equivalent settings test if that surface is included.
- **Behavior:**

  > When authoring a semantic-token style selector, completion should offer valid token modifiers after a token type or existing modifier, producing selectors such as `variable.readonly`. Suggestions should avoid duplicating modifiers already present in the selector and preserve existing completion for bare token types and wildcard modifier selectors. The plan must decide whether this applies only to color-theme files or also to `editor.semanticTokenColorCustomizations.rules`, and which registered classifications are discoverable.
- **Trace:**

  > `src/vs/platform/theme/common/tokenClassificationRegistry.ts` maintains the authoritative registered token types and modifiers and builds `tokenStylingSchema`; its schema properties contain bare token types and `*.modifier` entries, while `patternProperties` merely validates arbitrary selector combinations. `src/vs/workbench/services/themes/common/colorThemeSchema.ts` references that schema for `semanticTokenColors`. `extensions/configuration-editing/src/configurationEditingMain.ts` has no color-theme or semantic-selector completion provider, matching the maintainer diagnosis in the issue. The boundary is selector authoring assistance: semantic-token parsing, styling precedence, and runtime token-provider behavior must remain unchanged. The uncertainty starts at how the built-in extension obtains the live classification set and which JSON surfaces should receive the provider.
- **Open decisions:**
  - Should modifier-aware selector completion apply only to `semanticTokenColors` in color-theme files, or also to `editor.semanticTokenColorCustomizations.rules` in settings?
  - Should suggestions include only standard and package-contributed semantic classifications, or also classifications observed dynamically from document-provider legends?

## Evidence

- **maintainer direction:** The maintainer comment states that schema-based completion cannot represent the many type/modifier permutations and that this needs a completion provider in `configuration-editing`.
- **current schema limitation:** `src/vs/platform/theme/common/tokenClassificationRegistry.ts` registers completion properties for each bare token type and each wildcard modifier selector (`*.modifier`), while arbitrary combined selectors are accepted only through `patternProperties`; therefore selectors such as `variable.readonly` are not enumerated for completion.
- **provider remains absent:** `extensions/configuration-editing/src/configurationEditingMain.ts` registers providers for settings, variables, extensions, and context keys, but no provider targets `color-theme.json` or semantic-token selectors.
- **distinct candidate:** https://github.com/microsoft/vscode/issues/284658 concerns language-client registration of runtime semantic-token providers, not theme-selector authoring completion, so it does not own this request.
- **canonical search:** Searches for open semantic-token theme completion, selector suggestion, and token-modifier completion issues found no older open canonical with the same reporter-observable request.
