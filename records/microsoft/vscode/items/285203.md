# Issue #285203 — Quick Pick cannot be dismissed with mouse only (accessibility issue)

[https://github.com/microsoft/vscode/issues/285203](https://github.com/microsoft/vscode/issues/285203)

## Summary

The older, open issue already tracks the same mouse-only dismissal problem and the generic close-button solution, including quick picks without title bars. Consolidate this report there while retaining its assistive-input example and Python interpreter context.

## Change summary

Provide a visible cancellation control for quick picks that deliberately remain open when focus is lost.

## Best solution

Resolve the generic dismissal capability in https://github.com/microsoft/vscode/issues/99081, preserving ignoreFocusOut semantics while allowing cancellation without a keyboard or accepting a selection.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/99081 was created on 2020-06-02 and was verified OPEN through GitHub. Its original report describes clicking outside a persistent quick pick failing to dismiss it, with only an accepting button available to mouse users—the same observable cancellation problem reported here.
- **Canonical owns the full generic solution:** https://github.com/microsoft/vscode/issues/99081#issuecomment-637696722 expands the issue to a dismiss button for non-dismissible quick picks across multiple features. https://github.com/microsoft/vscode/issues/99081#issuecomment-1024683051 explicitly requests a close button whenever ignoreFocusOut is true, regardless of title-bar presence; https://github.com/microsoft/vscode/issues/99081#issuecomment-1027565662 discusses both a forced title bar and an input-inline close button. This is not merely a related Settings Sync problem.
- **Maintainer-approved scope:** In the supplied discussion for https://github.com/microsoft/vscode/issues/285203, the maintainer explicitly accepts a generic close control for all quick picks using ignoreFocusOut. Changing the Python interpreter picker's focus-loss behavior or toggling its status-bar entry is separate extension-owned work, not the remaining core request.
- **Current capability check:** src/vs/platform/quickinput/browser/quickInputController.ts:350-357 suppresses blur dismissal when either the input or service ignores focus loss. src/vs/platform/quickinput/browser/quickInput.ts:418-448 renders supplied title, inline, and input buttons without automatically supplying cancellation; its QuickPick.update visibility construction at lines 1036-1050 likewise has no generic close control. The requested generic capability remains missing.
- **Existing setting does not cover the request:** workbench.quickOpen.closeOnFocusLost is registered in src/vs/workbench/browser/workbench.contribution.ts and consumed in src/vs/workbench/services/quickinput/browser/quickInputService.ts:42. Enabling it does not override a picker's own ignoreFocusOut=true because the controller requires both ignore-focus conditions to be false before hiding.
- **Additional evidence to preserve:** The supplied report describes Windows 10, VS Code 1.107.1, and an accidentally opened Python interpreter picker used with a one-handed button-panel/stick-cursor device. https://github.com/microsoft/vscode/issues/285478#issuecomment-3711638174 also consolidates a remote-folder picker report into this issue. These are additional instances of the same generic cancellation gap, not distinct remaining capabilities.
