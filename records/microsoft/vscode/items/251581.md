# Issue #251581 — Disable Autosave for Merge Editor Result File

[https://github.com/microsoft/vscode/issues/251581](https://github.com/microsoft/vscode/issues/251581)

## Summary

Keep open: the default merge editor still shares the result file's ordinary autosave behavior, with no merge-specific exemption. This team-authored request remains distinct from the older restore-on-abort issues, and recent comments confirm continuing demand.

## Change summary

Prevent automatic saving of the merge editor's result file while retaining autosave for other files.

## Best solution

Make merge-result autosave suppression part of the merge editor lifecycle, preserving explicit Save and Accept Merge and ordinary autosave elsewhere. Settle how suppression ends when an unresolved merge is closed so pending autosave cannot undermine the chosen close action.

- **Behavior:**

  > With autosave enabled globally, reviewing or editing a merge result must not automatically persist that result while the merge editor is open. Switching between conflicted files or losing window focus must not implicitly save the active merge result. Other files continue to autosave, and explicit Save and Accept Merge retain their existing behavior. Acceptance must also cover the agreed treatment of a dirty unresolved result when its merge editor closes.
- **Trace:**

  > MergeEditorInput defaults to WorkspaceMergeEditorModeFactory in src/vs/workbench/contrib/mergeEditor/browser/mergeEditorInput.ts. The factory in mergeEditorInputModel.ts saves the original result before initialization and passes the real file text model to MergeEditorModel; there is no autosave suppression in this contribution. FilesConfigurationService.disableAutoSave already supports resource-scoped suppression, and EditorAutoSave checks it for both editors and working copies. Releasing suppression can immediately save a waiting dirty resource, so the uncertainty begins at unresolved-close behavior and shared-resource lifetime. Preserve explicit save/accept, the initial pre-merge snapshot save, unrelated files' autosave and the separate temporary-result mode. https://github.com/microsoft/vscode/issues/161560 and https://github.com/microsoft/vscode/issues/238347 concern adjacent abort/restoration semantics, not verified duplicates of this request.
- **Open decisions:**
  - When the merge editor closes with an unresolved dirty result, should ordinary autosave resume immediately and persist that result, or should saving remain explicit until the unresolved merge is deliberately saved or discarded?
