# Issue #299550 — Hooks not visible in chat

[https://github.com/microsoft/vscode/issues/299550](https://github.com/microsoft/vscode/issues/299550)

## Summary

The visibility gap remains on current main: successful hooks generally emit no chat progress, and empty hook progress is explicitly suppressed by the renderer. This team-authored UX follow-up should stay open while maintainers decide which successful hook executions warrant a persistent status.

## Change summary

Show a subtle chat status when an agent-scoped hook such as Stop or UserPromptSubmit executes successfully.

## Best solution

Provide a low-noise success indication for the agreed user-relevant hook types while preserving the existing blocked and warning presentations and avoiding repetitive PreToolUse/PostToolUse noise.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/hookResultProcessor.ts`, `extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts`, `extensions/copilot/src/extension/intents/test/node/hookResultProcessor.spec.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatService.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatHookContentPart.ts`
- **Validation:** Add targeted producer and chat-renderer tests showing that successful hooks in the chosen scope produce one muted status row, while existing blocked and warning hook tests retain their current presentation.
- **Behavior:**

  > Users should receive a subtle visible indication when a successful hook in the maintainer-approved scope runs, including the hook type. Blocking and warning outcomes must retain their stronger existing presentation, and a single execution must not create duplicate rows. High-frequency hooks must not make ordinary chat turns noisy.
- **Trace:**

  > Successful results pass through processHookResults in extensions/copilot/src/extension/intents/node/hookResultProcessor.ts without calling hookProgress; UserPromptSubmit follows this path from extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts. IChatHookPart in src/vs/workbench/contrib/chat/common/chatService/chatService.ts represents only result messages, and ChatListRenderer.renderHookPart suppresses parts without stopReason or systemMessage. ChatHookContentPart already has a check icon but labels non-blocked rows as warnings. Preserve blocked/error behavior and subagent/tool grouping; the uncertainty begins at which successful hook types should generate durable chat UI.
- **Open decisions:**
  - Should successful execution feedback appear for every hook source, or only hooks scoped to the selected custom agent?
  - Which hook types should receive a persistent success row, particularly whether frequent PreToolUse and PostToolUse executions should remain hidden?
  - Should multiple successful hooks of the same type in one turn appear individually or be summarized into one status?

## Evidence

- **successful execution path:** extensions/copilot/src/extension/intents/node/hookResultProcessor.ts calls hookProgress only for stops, errors, and warnings; successful results invoke onSuccess without emitting visible progress.
- **UserPromptSubmit path:** extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts executes UserPromptSubmit hooks but emits hookProgress only when a result blocks the request.
- **renderer behavior:** src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:4962-4965 explicitly renders no content when an IChatHookPart has neither stopReason nor systemMessage.
- **display contract:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatHookContentPart.ts currently titles hook rows as blocked or warning outcomes; it has no successful-execution title despite supporting a check icon.
- **linked implementation:** https://github.com/microsoft/vscode/pull/299029 added agent-scoped hook support for https://github.com/microsoft/vscode/issues/299337, but it did not reference or complete this separate visibility request.
