# Issue #342761 — `vscode.executeDocumentRenameProvider` command fails with "Unexpected type" error

[https://github.com/microsoft/vscode/issues/342761](https://github.com/microsoft/vscode/issues/342761)

## Summary

Confirmed in current source: resolving an unloaded document passes the rename argument as an array, causing the string assertion to fail. Keep this open while the existing fixing PR is reviewed and merged.

## Change summary

Make vscode.executeDocumentRenameProvider accept a valid newName when the target document requires model resolution.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/342762 so rename arguments reach the provider consistently for both loaded and newly resolved models, preserving model-reference disposal.
