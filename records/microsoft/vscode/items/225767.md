# Issue #225767 — Persistent `rg.exe` blocking Visual Studio Code Updates

[https://github.com/microsoft/vscode/issues/225767](https://github.com/microsoft/vscode/issues/225767)

## Summary

The issue describes rg.exe becoming unkillable on Windows, blocking VS Code updates. The code does call kill() on cancellation, but this appears to be a Windows-specific scenario where the ripgrep process enters an unkillable state. Multiple users confirm the problem persists across years and versions, but root cause and reproduction steps remain unclear.

## Change summary

On Windows, rg.exe spawned by VS Code search becomes permanently unkillable, blocking self-updates that need to replace the binary.

## Best solution

Investigate why rg.exe enters an unkillable state on Windows — likely a kernel-mode I/O wait or file lock. Consider using Windows Job Objects to ensure child processes are terminated when VS Code exits, or have the updater handle locked files more gracefully (e.g. retry after marking for deletion on reboot). The search service's process lifecycle in `src/vs/workbench/services/search/node/ripgrepTextSearchEngine.ts` already calls kill(), so the issue is likely that the process ignores SIGTERM on Windows when stuck in I/O.
