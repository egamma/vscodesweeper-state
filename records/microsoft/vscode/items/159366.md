# Issue #159366 — Cursor no longer selects entire tab (accessibility issue)

[https://github.com/microsoft/vscode/issues/159366](https://github.com/microsoft/vscode/issues/159366)

## Summary

The block cursor rendering on tabs was intentionally changed in commit a449148a14d to fix https://github.com/microsoft/vscode/issues/151959 — block cursor now uses a single-character width on tabs, matching SublimeText's behavior. A VS Code team member (alexdima) confirmed the intentional change, and isidorn suggested keeping the new behavior and collecting feedback. The suggested path for the old behavior is an extension using editor decorations.

## Change summary

Block cursor no longer spans the full tab width (e.g. 4 columns) and instead renders as a single-character-width block when positioned on a tab character.

## Best solution

Close as designed — the current 1ch-wide block cursor on tabs is intentional (commit a449148a14d, matching SublimeText). If a user wants the old wide-tab-cursor behavior, an extension with editor decorations is the recommended path, as isidorn suggested in the discussion.
