# Issue #331914 — tabGroups: background tab reported as activeTab after iconPath/title change — stale isActive in cached tab DTO

[https://github.com/microsoft/vscode/issues/331914](https://github.com/microsoft/vscode/issues/331914)

## Summary

Traced and confirmed on current main: the tab-patching handlers in mainThreadEditorTabs.ts mutate the cached DTO in place without recomputing `isActive`, so a previously-active tab keeps `isActive: true` forever once any later patch event (label, dirty, pin, preview) touches it — exactly as the report describes.

## Change summary

vscode.window.tabGroups.activeTabGroup.activeTab can report a stale, non-active background tab after that tab's label/icon/dirty/pin/preview state changes, because the cached tab DTO's `isActive` flag is never cleared.

## Best solution

In src/vs/workbench/api/browser/mainThreadEditorTabs.ts, have the patch handlers (_onDidTabLabelChange, _onDidTabDirty, _onDidTabPinChange, _onDidTabPreviewChange) recompute isActive from group.isActive(editor) (or have _onDidTabActiveChange clear isActive on the previously active tab) before sending the DTO update, so the cached isActive stays consistent with workbench truth.
