# Issue #334424 — BYOK Custom Endpoint: allow explicit Responses API tool search capability in chatLanguageModels.json

[https://github.com/microsoft/vscode/issues/334424](https://github.com/microsoft/vscode/issues/334424)

## Summary

Freshly-filed, well-diagnosed feature request: current main confirms the described gap — BYOK custom-endpoint config has no way to set `tool_search` capability, so `ChatEndpoint` always falls back to the model-ID heuristic for custom endpoints. This is a reasonable, small, localized capability-plumbing addition; needs a maintainer/product decision before landing, so it stays open for triage rather than an automatic close.

## Change summary

Add an optional `toolSearch` boolean to BYOK custom-endpoint model config (`chatLanguageModels.json`) so users can explicitly opt a custom Responses-API endpoint into VS Code's client-executed tool-search protocol, instead of relying solely on the built-in model-ID/family heuristic.

## Best solution

Plumb an optional `toolSearch?: boolean` through `_CustomEndpointModelConfig` (extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts) and `BYOKModelCapabilities` (extensions/copilot/src/extension/byok/common/byokProvider.ts), preserve it (not coerce to boolean) as `capabilities.supports.tool_search` in `resolveModelInfo()`, and add the property to the `chatLanguageModels.json` JSON schema in extensions/copilot/package.json — exactly as the issue's proposed implementation lays out. A maintainer should confirm the three-state (true/false/undefined) semantics fit before merging.
