# Issue #334424 — BYOK Custom Endpoint: allow explicit Responses API tool search capability in chatLanguageModels.json

[https://github.com/microsoft/vscode/issues/334424](https://github.com/microsoft/vscode/issues/334424)

## Summary

Well-researched, concrete feature request; verified against current main that no toolSearch/tool_search capability plumbing exists yet for BYOK custom endpoints, so the gap the author describes is real and the proposed fix is small and localized.

## Change summary

Add an explicit per-model `toolSearch` boolean to `chatLanguageModels.json` custom-endpoint config so users can opt Responses API models into VS Code's existing client-executed tool-search path, rather than relying only on the built-in model-ID heuristic.

## Best solution

Add `toolSearch?: boolean` to `_CustomEndpointModelConfig` and `BYOKModelCapabilities`, thread it through `resolveModelInfo()` as `capabilities.supports.tool_search` (preserving `undefined` vs `false`), pass it through `CustomEndpointBYOKModelProvider.createOpenAIEndPoint()`, and add the schema property in `extensions/copilot/package.json` — this is straightforward plumbing consistent with how `toolCalling`/`thinking`/etc. are already handled.
