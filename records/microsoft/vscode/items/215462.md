# Issue #215462 — Tree Sticky Scroll does not support Touch

[https://github.com/microsoft/vscode/issues/215462](https://github.com/microsoft/vscode/issues/215462)

## Summary

The touch-support gap remains on current main: ordinary tree rows receive gesture taps, but the separately rendered sticky rows do not. The request is already accepted into the Backlog and no older issue owns the same observable behavior, so it should remain open.

## Change summary

Support touchscreen interaction with sticky Explorer tree rows, including expanding and collapsing folders.

## Best solution

Give sticky tree rows parity with ordinary rows for tap handling: tapping the twistie should expand or collapse the folder, while other sticky-row taps should retain the established focus and selection behavior. Preserve existing mouse, keyboard, context-menu, and scrolling semantics.

## Evidence

- **confirmed product gap:** A VS Code maintainer confirmed that tree sticky scroll does not support touch in https://github.com/microsoft/vscode/issues/215462#issuecomment-2174336087.
- **current source:** In src/vs/base/browser/ui/list/listWidget.ts, MouseController registers Gesture on List.getHTMLElement(), which is the list root, while src/vs/base/browser/ui/list/listView.ts exposes onTap from the separate rowsContainer. StickyScrollWidget in src/vs/base/browser/ui/tree/abstractTree.ts appends sticky rows outside that rows container.
- **non-bubbling gesture:** src/vs/base/browser/touch.ts creates gesture events with bubbling disabled and dispatches them directly to registered Gesture targets. Consequently, a tap originating in a sticky row is dispatched to the list root and cannot reach the rowsContainer tap listener used by TreeNodeListMouseController.
- **remaining gap:** TreeNodeListMouseController in src/vs/base/browser/ui/tree/abstractTree.ts already implements sticky-row mouse behavior, including twistie collapse/expand, but current main has no corresponding sticky touch path or sticky-touch test.
- **canonical search:** Repository issue searches for tree sticky-scroll touchscreen and Explorer folder touch behavior found no older open issue reporting the same sticky-row interaction failure.
