# Issue #186337 — Diff Editor - code move is not shown

[https://github.com/microsoft/vscode/issues/186337](https://github.com/microsoft/vscode/issues/186337)

## Summary

Keep open: current move detection still excludes isolated one- and two-line changes, matching the limitation identified by the maintainer. This team-authored request needs a decision on short-move detection; no verified older canonical owns that same work.

## Change summary

Recognize meaningful short code relocations as moves instead of displaying only deletions and insertions.

## Best solution

Define which short relocations merit move highlighting, then extend the diff algorithm to recognize those cases without introducing noisy matches for trivial lines. Keep the separately tracked intermittent alignment problem outside this work.

- **Behavior:**

  > With moved-code highlighting enabled in a side-by-side diff, meaningful short relocations should be distinguishable from unrelated deletions and insertions under a maintainer-approved eligibility policy. The current limitation affects isolated changes shorter than three lines, even when their text is substantial. Acceptance should cover eligible short relocations and intentionally rejected trivial or ambiguous matches. Existing longer-move highlighting and ordinary diff correctness must remain intact.
- **Trace:**

  > DefaultLinesDiffComputer.computeDiff calls computeMoves when computeMoves is enabled, then delegates candidate discovery to computeMovedLines in src/vs/editor/common/diff/defaultLinesDiffComputer/computeMovedLines.ts. Both discovery paths enforce three-line seeds: simple deletion/insertion matching checks range lengths, and unchanged matching uses three-line hashes. The later character-content filter cannot admit candidates those paths never produced. The maintainer identified this boundary and suggested character-based eligibility at https://github.com/microsoft/vscode/issues/186337#issuecomment-1611405491; https://github.com/microsoft/vscode/issues/188785 provides a concrete short-relocation example. The existing fixture harness invokes DefaultLinesDiffComputer with computeMoves enabled and records move ranges. Preserve normal diff mappings, timeout handling, longer-move behavior, and false-positive suppression; intermittent editor alignment belongs to https://github.com/microsoft/vscode/issues/190737. The unresolved point is which short relocations the product should highlight, not where to place the implementation.
- **Open decisions:**
  - Should substantial single-line moves be eligible, or should move highlighting retain a minimum of two substantive lines?
  - What content threshold should distinguish meaningful short moves from trivial matches, and should it replace or supplement the existing line-count policy?
