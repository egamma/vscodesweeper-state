# Issue #244087 — Browser Cursor and VSCode Cursor Overlapping Issue

[https://github.com/microsoft/vscode/issues/244087](https://github.com/microsoft/vscode/issues/244087)

## Summary

Still reproduces on main: the `.inputarea` textarea lacks `caret-color: transparent`, so Safari on iPad renders its native text caret on top of VS Code's custom cursor. An open community PR (#244091) addresses this.

## Change summary

On iPad Safari, the browser's native text caret overlaps with VS Code's rendered cursor in the editor.

## Best solution

Review and land the open PR https://github.com/microsoft/vscode/pull/244091 (or a maintainer-authored equivalent) that adds `caret-color: transparent` to `.monaco-editor .inputarea` in `textAreaEditContext.css`. Care is needed to preserve the existing `caret-color` override for the `.ime-input` state.

## Evidence

- **missing caret-color:** In `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.css`, the `.monaco-editor .inputarea` rule sets `color: transparent` and `background-color: transparent` but does NOT set `caret-color: transparent`. Safari on iPad renders its native caret in the textarea, overlapping VS Code's custom cursor.
- **ime-input has caret-color:** The `.inputarea.ime-input` class at line 36 explicitly sets `caret-color: var(--vscode-editorCursor-foreground)`, confirming the codebase is aware of `caret-color` but doesn't suppress it in the base state.
- **open PR:** https://github.com/microsoft/vscode/pull/244091 is open and proposes fixing this by making the browser caret transparent. PR https://github.com/microsoft/vscode/pull/244089 was closed without merging.
- **no fix on main:** git log shows no changes to textAreaEditContext.css since the issue was filed; the defect path is unguarded on current main.
