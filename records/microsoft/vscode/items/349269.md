# Issue #349269 — Show Copilot harness background shells as read-only terminals in the Terminal view

[https://github.com/microsoft/vscode/issues/349269](https://github.com/microsoft/vscode/issues/349269)

## Summary

Keep open: current source provides read-only background-shell previews inside chat, not discoverable terminals in the Terminal view. The earlier closed authentication issue does not establish that this visibility request was completed.

## Change summary

Expose running Copilot SDK background shells as bounded, read-only Terminal view entries with chat attribution, reveal actions, and automatic cleanup.

## Best solution

Design an opt-in Terminal view presentation for existing background-shell output, preserving its noninteractive nature and chat ownership. Coordinate with the client output-bounding work before keeping these subscriptions alive for long-running processes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostBackgroundShells.ts`, `src/vs/workbench/contrib/chat/browser/sessionBackgroundShellsControl.ts`, `src/vs/workbench/contrib/chat/browser/sessionBackgroundShellOutputView.ts`, `src/vs/workbench/contrib/terminal/browser/agentHostTerminalService.ts`
- **Validation:** Extend the agentHostTerminalService and sessionBackgroundShellsControl browser suites to cover visibility, reveal actions, ignored input, attribution, and cleanup. The plan should also define a sustained-output check proving bounded retained state and scrollback after the output-bounding dependency is addressed.
- **Behavior:**

  > With the experiment enabled, a running Copilot SDK background shell is discoverable in the Terminal view and streams output without accepting process input. Its command, agent origin, background or detached status, and owning chat are identifiable. Reveal actions from chat reach the matching entry without creating duplicates. Output remains bounded during a long-running stream, and entries show completion status before being removed on exit or chat closure. Foreground commands and interactive shell control remain outside scope.
- **Trace:**

  > CopilotNonPtyShellTerminals creates and retains output-only protocol terminal channels for background commands. AgentHostBackgroundShellOutputs observes those channels and projects their contents into chat background-shell models; BackgroundShellOutputView renders a readonly detached terminal only inside chat details. AgentHostTerminalService.attachOutputTerminal registers an output source, whereas its separate PTY revival path creates hidden feature terminals. The trace establishes reusable output plumbing, but not a complete Terminal view instance and lifecycle contract for output-only channels. Preserve advertised chat and terminal identities and do not turn an output mirror into a PTY or input bridge. https://github.com/microsoft/vscode/issues/343079 tracks the client-state bounding dependency; chat-local bounded display alone does not establish bounded subscription memory.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/chat/browser/sessionBackgroundShellOutputView.ts constructs a readonly detached terminal and attaches it to the chat details container. src/vs/workbench/contrib/chat/browser/sessionBackgroundShellsControl.ts supplies Stop Shell actions, but no Open in Terminal action.
- **SDK output is already represented:** src/vs/platform/agentHost/node/copilot/copilotNonPtyShellTerminals.ts:623-649 creates output-only terminal channels through createOutputTerminal and retains them when commands continue in the background. These protocol channels are not themselves visible integrated terminal instances.
- **Terminal bridge distinguishes output from PTYs:** src/vs/workbench/contrib/terminal/browser/agentHostTerminalService.ts:407-412 attaches output through AgentHostOutputChannel and registerOutputSource. Its separate _doReviveTerminal path creates a PTY-backed feature terminal with hideFromUser: true at lines 414-446; enabling chat.agentHost.customTerminalTool.enabled therefore does not deliver the proposed read-only SDK presentation.
- **Output-bounding dependency:** https://github.com/microsoft/vscode/issues/343079 is open and specifically tracks unbounded client terminal state and incremental rendering after front trimming. That work is a dependency, not a duplicate of Terminal view visibility.
- **Closed related requests are not canonical targets:** https://github.com/microsoft/vscode/issues/341717 and https://github.com/microsoft/vscode/issues/341462 are both closed. The former explicitly requested Terminal view access, including read-only output; closing it into the authentication discussion does not prove the visibility capability shipped.
- **Related demand and scope:** https://github.com/microsoft/vscode/issues/348170 describes missing terminal visibility alongside interactive control, while https://github.com/microsoft/vscode/issues/348186 combines terminal access with several unrelated harness-parity requests. Neither establishes a dedicated canonical implementation of this narrower read-only background-shell proposal.
