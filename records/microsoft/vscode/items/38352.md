# Issue #38352 — Autoclosing pairs should be configurable

[https://github.com/microsoft/vscode/issues/38352](https://github.com/microsoft/vscode/issues/38352)

## Summary

Keep open: current settings control autoclosing strategies but still do not let users choose arbitrary autoclosing and surrounding pairs per language. The request has explicit maintainer support and 148 upvotes; the related broader settings request is newer and cannot replace this re-reviewed item.

## Change summary

Allow users to customize autoclosing and selection-surrounding pairs per language without editing installed language configuration files.

## Best solution

Provide supported user configuration for the effective autoclosing and surrounding pair sets through the editor's language-configuration system, preserving language defaults when unconfigured. Settle replacement versus selective customization semantics, including the long-pair use case raised in the discussion, before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/common/languages/languageConfigurationRegistry.ts`, `src/vs/editor/common/languages/supports/characterPair.ts`, `src/vs/editor/common/cursorCommon.ts`
- **Validation:** The plan should define language-configuration and cursor tests for the chosen override semantics: add a pair absent from a language's defaults, disable a selected default pair, customize surrounding independently, and preserve defaults when unconfigured. Manually verify typing and wrapping selections in Markdown and Plain Text, language-scoped isolation, and configuration updates without restarting the editor.
- **Behavior:**

  > Users should be able to choose autoclosing and selection-surrounding pairs for a language through supported settings rather than modifying installed extension files. This must cover pairs missing from language defaults and unwanted default pairs, while preserving existing behavior for users who configure nothing. Acceptance should exercise Markdown and Plain Text, independent surrounding behavior, language-specific isolation, and live configuration changes. The request to jump outside a pair and insert a space is outside this feature's scope.
- **Trace:**

  > LanguageConfigurationService in src/vs/editor/common/languages/languageConfigurationRegistry.ts combines contributed language data with user customization, but getCustomizedLanguageConfig currently reads only bracket and colorization overrides. CharacterPairSupport in src/vs/editor/common/languages/supports/characterPair.ts chooses explicit autoClosingPairs before its brackets fallback and obtains surroundingPairs separately. CursorConfiguration in src/vs/editor/common/cursorCommon.ts consumes those resolved sets; the existing editor.autoClosingQuotes, editor.autoClosingBrackets and editor.autoSurround settings choose strategies rather than pair definitions. This establishes the missing capability without executing or modifying the checkout. The related https://github.com/microsoft/vscode/issues/102574 concerns broader configuration overrides and is not a valid duplicate target for this older re-reviewed issue. Preserve unrelated indentation, bracket colorization, and cursor-exit behavior; uncertainty begins at the public override model, especially selective changes to large language-defined lists and conditional multi-character pairs.
- **Open decisions:**
  - Should user customization replace the entire language-defined pair list, selectively add and remove pairs, or support both? This determines whether users must repeat dozens of unchanged language defaults.
  - Should the user-facing configuration expose the full conditional pair contract, including multi-character opening and closing sequences and notIn restrictions, or a deliberately narrower contract?
  - Should autoclosing and surrounding have independent overrides, and what should surrounding do when only an autoclosing override is supplied?
