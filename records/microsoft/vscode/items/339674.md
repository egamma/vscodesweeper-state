# Issue #339674 — create-canvas skill refers to VS Code-specific env variable

[https://github.com/microsoft/vscode/issues/339674](https://github.com/microsoft/vscode/issues/339674)

## Summary

Team-authored, freshly-filed bug (collaborator chrmarti, same-day) and confirmed from source: the create-canvas skill prompt and the Agent Host's launch env both use the VS Code-branded `VSCODE_CANVAS_DATA_DIR` variable, even though this skill is contributed to all `copilotcli` session types — including non-VS Code Agent Hosts like the standalone GitHub Copilot app — which don't set it, so canvas extensions can't resolve their data directory there.

## Change summary

The create-canvas skill tells agents to read `process.env.VSCODE_CANVAS_DATA_DIR`, a name/contract that only the VS Code Agent Host actually populates.

## Best solution

Rename the contract to a host-neutral env var (e.g. drop the `VSCODE_` prefix) in the SKILL.md instructions and in `copilotAgent.ts`'s extension launch env, then coordinate with the GitHub Copilot app's own host implementation so it sets the same variable — this is an AHP interoperability fix per `.github/instructions/agent-host-interoperability.instructions.md`.
