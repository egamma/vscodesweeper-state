- **Current detection path:** extensions/merge-conflict/src/mergeConflictParser.ts: containsConflict checks only for opening and closing marker substrings; scanDocument accepts headers beginning with <<<<<<< and footers beginning with >>>>>>>, including SEARCH and REPLACE. With a separator exactly equal to =======, it creates a conflict descriptor regardless of Git state. extensions/merge-conflict/src/documentTracker.ts passes these descriptors to consumers, and src/codelensProvider.ts creates the Accept Current Change and Accept Incoming Change actions.
- **Reproduction qualification:** The literal issue-body sample contains six equals signs, whereas current scanDocument requires seven; that exact pasted sample would not yield a complete descriptor. The linked PR reports the false positive and includes before/after screenshots, supporting reproduction of the intended SEARCH/REPLACE scenario. No code was executed during this read-only review.
- **Scope of proposed correction:** The linked PR adds MergeConflictParser.isInActiveMerge and gates documentTracker scanning on repository.state.mergeChanges, returning false when no repository is found. Current extensions/merge-conflict/src/codelensProvider.ts explicitly registers file, vscode-vfs, untitled, and vscode-userdata documents, so requiring active Git state potentially removes existing assistance on other supported paths.
- **Existing controls:** extensions/merge-conflict/package.json exposes merge-conflict.codeLens.enabled and merge-conflict.decorators.enabled. These disable their respective UI globally rather than distinguish SEARCH/REPLACE text from actual conflict markers.
