## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/commands.ts`
- **Validation:** In disposable repositories outside the shared checkout, configure origin and a separate fork, set branch.<name>.remote to the fork URL and branch.<name>.merge to its branch ref, commit a change, and invoke Source Control Sync. Compare destination refs with argumentless git push; repeat with branch.<name>.pushRemote present and absent. The fork must receive the commit and origin must remain unchanged.
- **Behavior:**

  > A branch checked out from a fork can use the fork URL as its branch-level remote without adding a named repository remote. After committing, implicit Source Control synchronization must not send that commit to origin when argumentless git push would send it to the fork. Verify both the GitHub CLI configuration containing pushRemote and the reported hub-style configuration without it. Preserve explicitly selected Push To destinations.
- **Trace:**

  > The report is https://github.com/microsoft/vscode/issues/189239; its linked CLI discussion confirms that a URL-valued branch remote is a supported workflow. In extensions/git/src/git.ts, getBranch() derives upstream from for-each-ref atoms, and getHEADRef() resolves any resulting upstream through a remote-tracking ref. Commands._sync() in extensions/git/src/commands.ts takes the ordinary Push path when upstream is absent; Repository.push() in extensions/git/src/repository.ts then omits remote/refspec unless upstream exists. Conversely, Repository._sync() explicitly reuses an available upstream destination for both pull and push. Establish the actual HEAD metadata and emitted command for the supplied URL configuration before diagnosing the failure; the source does not conclusively show an origin fallback. Related reports https://github.com/microsoft/vscode/issues/158644 and https://github.com/microsoft/vscode/issues/137686 concern named-remote triangular workflows and are not yet verified duplicates of the URL-only case. Keep explicit destination commands and unrelated synchronization behavior out of scope.
