# Issue #329185 — `cmd+w` sometimes closes chats and sometimes files

[https://github.com/microsoft/vscode/issues/329185](https://github.com/microsoft/vscode/issues/329185)

## Summary

Real, traceable focus-scoping bug in the Agents window's Cmd+W handling, but it already carries the 1.135.0 milestone, so per policy it stays open for the assigned release rather than being proposed for closing here.

## Change summary

Cmd/Ctrl+W intermittently closes the active chat instead of acting on the focused Files pane entry.

## Best solution

Tighten CloseChatAction's keybinding `when` clause in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts (line ~660) so it only intercepts Cmd/Ctrl+W when a chat tab (not the Files sidebar view) actually has focus — EditorAreaFocusContext.toNegated() is too broad since the Files pane is a sidebar view, not the editor area, so it also falls into the 'not editor area' bucket and gets its Cmd+W hijacked by CloseChatAction.

## Evidence

- **keybinding when-clause:** src/vs/sessions/contrib/sessions/browser/sessionsActions.ts:655-663 — CloseChatAction binds Cmd/Ctrl+W with `when: ContextKeyExpr.and(IsSessionsWindowContext, EditorAreaFocusContext.toNegated(), SessionActiveChatIsClosableContext)`, i.e. it fires whenever focus is anywhere outside the editor area (not specifically the chat tab).
- **Files pane is a sidebar view:** src/vs/sessions/contrib/files/browser/filesView.ts implements the Files pane as a view/pane, not part of the editor area, so focusing it also satisfies `EditorAreaFocusContext.toNegated()` and lets CloseChatAction hijack the shortcut.
