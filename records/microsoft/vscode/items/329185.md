# Issue #329185 — `cmd+w` sometimes closes chats and sometimes files

[https://github.com/microsoft/vscode/issues/329185](https://github.com/microsoft/vscode/issues/329185)

## Summary

Team-authored bug, confirmed in current source: the CloseChatAction keybinding in sessionsActions.ts still gates on `!editorAreaFocus` instead of positive Sessions focus, so clicking the blank Files placeholder (which takes neither editor-area nor Sessions focus) leaves Cmd+W hitting the high-priority close-chat binding instead of the intended editor/pane close. A linked fix PR (#329372) traced this exact root cause and proposed the SessionsFocusContext-based fix, but it was closed without merging, so the defect remains live on main.

## Change summary

Cmd+W sometimes closes an active chat instead of the focused Files pane/editor in the Agents window, because the close-chat keybinding's `when` clause only checks the negation of editor-area focus rather than requiring actual chat focus.

## Best solution

Land the fix already prototyped in the closed PR #329372: change the `CloseChatAction` keybinding's `when` clause in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts to require `SessionsFocusContext` (positive chat/session-content focus) instead of `EditorAreaFocusContext.toNegated()`, so the blank Files placeholder and other non-chat, non-editor surfaces fall through to the normal close-editor/close-pane behavior.
