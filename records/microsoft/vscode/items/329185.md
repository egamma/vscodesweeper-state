# Issue #329185 — `cmd+w` sometimes closes chats and sometimes files

[https://github.com/microsoft/vscode/issues/329185](https://github.com/microsoft/vscode/issues/329185)

## Summary

Real, traceable bug already scheduled for milestone 1.137.0 — that assigned milestone is a scheduling decision, so per policy this stays open regardless of any other evidence.

## Change summary

In the Agents Window, Cmd+W sometimes closes the focused Files-panel file and sometimes closes a chat tab instead, depending on which pane has focus.

## Best solution

Narrow the `CloseChatAction` keybinding's `when` clause in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts (around line 761) so it only fires while focus is actually within the chat/session area, not merely 'anywhere outside the editor area' (which also covers the Files pane in the sidebar).

## Evidence

- **conflicting keybinding:** src/vs/sessions/contrib/sessions/browser/sessionsActions.ts:756-763 registers CLOSE_CHAT_COMMAND_ID on Cmd+W with `when: ContextKeyExpr.and(IsSessionsWindowContext, EditorAreaFocusContext.toNegated(), SessionActiveChatIsClosableContext)` — this fires whenever focus is anywhere outside the editor area (including the Files pane), not just when the chat tab strip/area itself has focus.
- **broad pattern reused elsewhere:** The same `EditorAreaFocusContext.toNegated()` guard (without a more specific 'chat area focused' context) is reused for many other Cmd+W-bound actions in sessionsActions.ts and sessionsViewActions.ts (e.g. lines 267, 309, 382, 402, 641, 706, 726, 814, 861), so a fix needs care to avoid regressing those.
