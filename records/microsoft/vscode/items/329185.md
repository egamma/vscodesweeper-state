# Issue #329185 — `cmd+w` sometimes closes chats and sometimes files

[https://github.com/microsoft/vscode/issues/329185](https://github.com/microsoft/vscode/issues/329185)

## Summary

Milestone 1.134.0 is already assigned, so this is a scheduling decision and stays open regardless; but the root cause is also clearly traceable on main: two competing Ctrl/Cmd+W keybindings in the Agents window disagree on scope.

## Change summary

In the Agents window, pressing Cmd+W while the Files pane (sidebar) has focus closes the active chat instead of acting on the Files pane, because the chat-close keybinding fires unexpectedly.

## Best solution

In src/vs/sessions/contrib/sessions/browser/sessionsActions.ts, narrow the `CloseChatAction` keybinding's `when` clause (currently `IsSessionsWindowContext && EditorAreaFocusContext.toNegated() && SessionActiveChatIsClosableContext`) so it only fires when focus is actually within the chat/tab area, not merely 'not the editor area' — e.g. by also checking `FocusedViewContext` isn't the Files/Changes sidebar view, or by requiring a chat-specific focus context.

## Evidence

- **competing keybindings:** sessionsViewActions.ts:65 registers CLOSE_SESSION_COMMAND_ID for Ctrl/Cmd+W when `EditorsVisibleContext.negate()` at weight `KeybindingWeight.SessionsContrib` (250), while sessionsActions.ts:528-546 registers CloseChatAction for the same key when `IsSessionsWindowContext && EditorAreaFocusContext.toNegated() && SessionActiveChatIsClosableContext` at `CHAT_TAB_KEYBINDING_WEIGHT = SessionsContrib + 10` (260).
- **root cause:** `EditorAreaFocusContext.toNegated()` is true whenever focus is anywhere outside the editor area — including the Files pane in the sidebar — so the higher-weight CloseChatAction wins and closes the chat instead of respecting the Files pane's own close semantics.
- **no fix on main:** git log on sessionsActions.ts shows the most recent commits (9eb249a, e9d3ba1, 264a406) are unrelated feature work (Chats picker grouping, reopen-last-closed, middle-click tab close); none touch this when-clause scoping.
