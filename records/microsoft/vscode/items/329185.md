# Issue #329185 — `cmd+w` sometimes closes chats and sometimes files

[https://github.com/microsoft/vscode/issues/329185](https://github.com/microsoft/vscode/issues/329185)

## Summary

The defect remains source-reproducible on current main: the high-priority close-chat binding matches whenever editor focus is absent, including when the blank Files surface has focus. The prior fixing PR was closed unmerged, so this accepted team-authored bug should remain open.

## Change summary

In the Agents window, Cmd+W can close the active peer chat instead of the focused Files surface because shortcut ownership does not positively require chat focus.

## Best solution

Make Cmd+W ownership follow actual keyboard focus: close a peer chat only while the Sessions content has focus, while allowing normal editor or surface behavior when Files or another workbench part is focused.

## Evidence

- **current source:** In src/vs/sessions/contrib/sessions/browser/sessionsActions.ts, CloseChatAction registers its high-weight Cmd+W binding with `isSessionsWindow && !editorAreaFocus && sessionActiveChatIsClosable`; it does not require `sessionsFocus`, so the reported blank-Files focus state still satisfies the predicate.
- **available focus signal:** src/vs/sessions/browser/parts/sessionsPart.ts binds `SessionsFocusContext` and updates it from the Sessions content focus tracker; this distinguishes chat/Sessions focus from the Files placeholder described by the reporter.
