# Issue #291688 — Feature Request: Public API to access Local History entries

[https://github.com/microsoft/vscode/issues/291688](https://github.com/microsoft/vscode/issues/291688)

## Summary

This accepted Backlog request remains necessary: current main has an internal Local History query service but no corresponding Extension API. It has 25 community upvotes and is already correctly routed.

## Change summary

Expose a supported read-only Extension API for querying a resource's Local History entries.

## Best solution

Design a read-only proposed API backed by `IWorkingCopyHistoryService`, including stable entry metadata and access to snapshot contents without exposing internal storage paths. The API should also define how extensions observe entry changes and whether unsaved buffer states are in scope.

- **Fit:** aligned
- **Reason:** A supported API enables specialized history and recovery workflows to remain in extensions while eliminating dependence on private storage internals.
- **Evidence:** Values and guardrails: “The power lives in extensions”; a missing extension-API capability is valid core work.
