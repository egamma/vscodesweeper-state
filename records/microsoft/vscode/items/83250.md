# Issue #83250 — [folding] Auto re-fold a region after the cursor leaves it.

[https://github.com/microsoft/vscode/issues/83250](https://github.com/microsoft/vscode/issues/83250)

## Summary

A real capability gap remains: VS Code automatically unfolds hidden ranges when navigation moves the cursor into them, but has no option to restore those folds after the cursor leaves. The closest older requests concern initial or function-specific folding and do not fully own this behavior, so this should remain open under discussion.

## Change summary

Add an option to automatically restore a folded region after cursor navigation temporarily expands it and then leaves it.

## Best solution

Define the lifecycle for navigation-expanded folds, then add an opt-in editor behavior that restores eligible folds without changing manually expanded ranges or the default folding experience.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/folding/test/browser/folding.test.ts`
- **Validation:** Add a FoldingController browser test that starts with a collapsed range, navigates a selection into it and then outside it, and asserts the approved opt-in restoration semantics while the default behavior remains unchanged; run scripts/test.sh --grep "auto re-fold".
- **Behavior:**

  > With the proposed option disabled, cursor navigation and folding continue to behave exactly as they do today. With it enabled, a folded range that navigation expands so the cursor can be revealed can become folded again after the relevant cursor or cursors leave it. Manually chosen expansion state must not be unexpectedly discarded. Acceptance must cover Find-style navigation, nested folding ranges, and multiple selections according to the maintainer-approved semantics.
- **Trace:**

  > FoldingController in src/vs/editor/contrib/folding/browser/folding.ts listens for cursor movement and schedules revealCursor. That method finds collapsed regions containing a cursor in a hidden line and expands them with FoldingModel.toggleCollapseState, but it does not distinguish navigation-driven expansion from user-driven expansion or retain candidates for later restoration. Folding options are declared and registered in src/vs/editor/common/config/editorOptions.ts, where no equivalent setting exists. The closest open reports are https://github.com/microsoft/vscode/issues/33449 and https://github.com/microsoft/vscode/issues/40338, but neither fully covers arbitrary ranges temporarily opened by Find. Preserve default behavior and explicit manual folding actions; uncertainty begins at which expanded ranges should be remembered and when multiple selections make restoration safe.
- **Open decisions:**
  - Should automatic restoration apply only to ranges that FoldingController itself expanded to reveal a cursor, or to any range that was collapsed before the cursor entered it?
  - Should the option cover every folding range, only marker regions, or selected folding-range kinds such as functions and imports?
  - For nested ranges and multiple selections, should a range remain expanded until every selection has left it, and should its previously collapsed ancestors be restored independently?

## Evidence

- **current source:** In src/vs/editor/contrib/folding/browser/folding.ts, FoldingController.onCursorPositionChanged schedules revealCursor; revealCursor detects a cursor in a hidden line and expands every enclosing collapsed region through toggleCollapseState, but records no navigation-expanded state and has no corresponding re-collapse path.
- **existing configuration:** src/vs/editor/common/config/editorOptions.ts registers folding, foldingStrategy, foldingHighlight, foldingImportsByDefault, foldingMaximumRegions, and unfoldOnClickAfterEndOfLine; none restores folds after cursor navigation.
- **related initial-state request:** https://github.com/microsoft/vscode/issues/40338 is open and older, but concerns which ranges start collapsed when a file opens rather than restoring a range temporarily expanded by Find/navigation.
- **closest related behavior:** https://github.com/microsoft/vscode/issues/33449 is open and older and proposes expanding the current function then folding it when the cursor leaves, but its function-only, folded-by-default and pinning model does not own this report's general restoration of arbitrary folded ranges opened by Find.
