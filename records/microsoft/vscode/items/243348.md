# Issue #243348 — Hover API improvements

[https://github.com/microsoft/vscode/issues/243348](https://github.com/microsoft/vscode/issues/243348)

## Summary

This remains active hover API debt: several referenced changes landed, but current main still exposes the delayed-hover names and optional behavior called out by the unchecked tasks. The issue is already correctly classified and routed, and no open PR currently owns the remaining work.

## Change summary

Simplify and clarify the internal workbench hover APIs, defaults, positioning styles, and usage guidance.

## Best solution

Settle one coherent hover contract for keyboard dismissal, positioning, pointer behavior, and compact presentation, then complete the API migration and document when each style should be used.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/hover/hover.ts`, `src/vs/platform/hover/browser/hoverService.ts`, `src/vs/platform/hover/browser/hoverWidget.ts`, `src/vs/platform/hover/test/browser/hoverService.test.ts`
- **Validation:** Extend the HoverService unit suite to cover the chosen keyboard-dismissal, positioning, pointer, and compact defaults, then run `scripts/test.sh --grep "HoverService"`; verify migrated consumers no longer use the superseded API names or redundant option combinations.
- **Behavior:**

  > Workbench hovers should use a small, clearly documented set of styles with consistent defaults across consumers. Keyboard dismissal, pointer presentation, compact presentation, and target-relative versus mouse-relative positioning must behave predictably without every caller rebuilding the same option bundle. Existing specialized hovers must retain their intentional interaction and accessibility behavior after migration.
- **Trace:**

  > The central contract is IHoverDelegate2 and its option types in src/vs/base/browser/ui/hover/hover.ts, implemented by HoverService in src/vs/platform/hover/browser/hoverService.ts and rendered by HoverWidget in src/vs/platform/hover/browser/hoverWidget.ts. Current main retains the delayed API names and all three questioned options; `hideOnKeyDown` is coerced to false when omitted, while HoverStyle supplies only partial appearance defaults. Usage is broad across workbench consumers, and the focused coverage lives in src/vs/platform/hover/test/browser/hoverService.test.ts. Commit 42a55e8a9989e153ddf1636e245477453b2023c0 and the later linked PRs establish that this is staged cleanup rather than completed work. Keep removal of deprecated managed hovers coordinated with https://github.com/microsoft/vscode/issues/270314, and do not regress hover locking, keyboard accessibility, nesting, or delayed-hover grouping.
- **Open decisions:**
  - Should ordinary keyboard input dismiss workbench hovers by default, and which interactive or focus-trapped hovers must be exempt?
  - Which delayed-hover presentation should be the default: target/text aligned, mouse aligned, or centered with a pointer?
  - What user-visible distinction warrants compact hover presentation, and should it remain caller-selectable or follow the selected hover style?

## Evidence

- **remaining API surface:** Current main still declares `showDelayedHover`, `setupDelayedHover`, and `setupDelayedHoverAtMouse`, plus optional `hideOnKeyDown`, `compact`, and `forcePosition`, in src/vs/base/browser/ui/hover/hover.ts.
- **current behavior:** src/vs/platform/hover/browser/hoverService.ts passes `!!options.persistence?.hideOnKeyDown`, so keyboard dismissal is still disabled by default; src/vs/platform/hover/browser/hoverWidget.ts still implements compact styling and forced positioning.
- **partial implementation:** https://github.com/microsoft/vscode/pull/243349 merged as commit 42a55e8a9989e153ddf1636e245477453b2023c0 and completed only the `showHover` to `showInstantHover` rename. Later partial work landed through https://github.com/microsoft/vscode/pull/270313, https://github.com/microsoft/vscode/pull/272244, and https://github.com/microsoft/vscode/pull/272245.
- **canonical status:** The older https://github.com/microsoft/vscode/issues/204965 was closed as a duplicate pointing to this issue and the narrower https://github.com/microsoft/vscode/issues/270314; the latter remains open and covers removal of `setupManagedHover`, so it does not absorb this issue's broader checklist.
- **guidance work:** https://github.com/microsoft/vscode-docs/issues/8135 remains open and records the unresolved UX questions about hover styles, keyboard dismissal, compact presentation, and positioning.
