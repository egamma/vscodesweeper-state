# Issue #280486 — chat will always error after attaching an image that exceeds the limit

[https://github.com/microsoft/vscode/issues/280486](https://github.com/microsoft/vscode/issues/280486)

## Summary

The defect remains source-reproducible on current main: an extreme-aspect image can bypass resizing despite one dimension exceeding 8000 pixels, after which the invalid attachment remains in request history and is restored into later attempts.

## Change summary

An oversized image rejected by the chat provider remains attached through history and checkpoint restoration, causing subsequent requests in the session to fail.

## Best solution

Ensure every image sent to chat satisfies the provider's dimensional limits before it enters request history, while preserving ordinary images and allowing users to recover an existing failed request by removing or replacing its invalid attachment.

## Evidence

- **current source trigger:** src/vs/workbench/contrib/chat/browser/chatImageUtils.ts returns the original bytes when `(width <= 768 || height <= 768) && !isGif`; therefore an image such as 9000x500 bypasses resizing even though it exceeds the reported provider limit of 8000 pixels.
- **attachment path:** src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentResolveService.ts stores the result of `resizeImage` directly as the image attachment value, so bytes admitted by that early-return path reach the request model unchanged.
- **restoration path:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts restores both `request.attachedContext` and `currentElement.variables` into the edited request without filtering an image that previously caused a provider validation failure.
- **maintainer confirmation:** The maintainer response on https://github.com/microsoft/vscode/issues/280486 confirms that the failed image remains in chat history and that VS Code does not specially revert previously attached items after the error.
