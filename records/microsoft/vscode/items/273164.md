# Issue #273164 — include extra info in `aria-description` instead of `aria-label`

[https://github.com/microsoft/vscode/issues/273164](https://github.com/microsoft/vscode/issues/273164)

## Summary

Keep open: current source supports separate accessible descriptions in some controls, but still folds supplemental information into accessible names elsewhere. This team-authored, accepted accessibility request remains relevant; no verified canonical or issue-referencing fix establishes completion.

## Change summary

Separate supplemental accessibility information from an element's accessible name so screen readers can announce its primary content before the description.

## Best solution

Establish a consistent name-versus-description contract for the affected controls, retaining concise identifying names while exposing supplemental guidance separately. Start with a maintainer-agreed set of surfaces and verify the resulting announcement order with supported screen readers.

## Plan brief

- **Likely files:** `src/vs/platform/actionWidget/browser/actionList.ts`, `src/vs/base/browser/ui/list/listWidget.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`
- **Validation:** For the agreed controls, verify with supported screen readers that focusing each control announces its identifying content before supplemental guidance. Add DOM-level assertions that names and descriptions remain separate through updates and list-row recycling, and confirm verbosity settings still suppress the corresponding hints.
- **Behavior:**

  > Supplemental guidance should not replace or inflate the primary accessible name of an affected control. Screen-reader users should encounter the control's identifying content before its supplementary description. Acceptance must cover announcement order, preservation of essential identity and state, and existing verbosity settings. The issue does not identify the initial set of controls to migrate.
- **Trace:**

  > Current source has mixed patterns: SelectBoxNative independently sets aria-label and aria-description, while ActionList.getAriaLabel concatenates supplemental fields into the name that the list accessibility renderer writes to aria-label. TerminalInstance._setAriaLabel likewise appends mode and help guidance to terminal identity. These paths establish remaining opportunities, but do not prove announcement order across screen readers. Preserve meaningful accessible names, control roles and states, keyboard behavior, and existing verbosity semantics; do not indiscriminately move every label field into a description. https://github.com/microsoft/vscode/issues/321958 addresses a different role/name problem and is not a duplicate canonical.
- **Open decisions:**
