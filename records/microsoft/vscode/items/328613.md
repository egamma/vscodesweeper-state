# Issue #328613 — Agents Window SSH creates separate remote agent host under default home instead of existing Remote-SSH home, causing duplicate installs/processes

[https://github.com/microsoft/vscode/issues/328613](https://github.com/microsoft/vscode/issues/328613)

## Summary

Well-diagnosed architectural gap, confirmed in current source: Agents Window SSH uses the ssh2 library and a hardcoded `bash -l -c` invocation, while classic Remote-SSH shells out to the real OpenSSH binary honoring `RemoteCommand`, so a user with a custom `HOME` via SSH config gets two separate server roots and duplicate agent host processes on the same box.

## Change summary

Agents Window SSH resolves a different effective remote HOME/server root than Remote-SSH for the same host (when SSH config uses RemoteCommand to alter shell startup HOME), causing duplicate agent host installs/processes.

## Best solution

In src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts, either invoke the user's actual configured remote shell/RemoteCommand chain (as Remote-SSH does) before resolving the server root, or add explicit reuse-detection that queries the effective remote HOME the same way Remote-SSH does, so both entry points converge on one install/process per host; this is agent-host/SSH-transport work, not a UI concern.
