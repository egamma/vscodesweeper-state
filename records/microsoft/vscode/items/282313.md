# Issue #282313 — Custom Text Editor dirty flag inconsistencies

[https://github.com/microsoft/vscode/issues/282313](https://github.com/microsoft/vscode/issues/282313)

## Summary

Keep open: the sample and restart steps suffice to retest the dirty-indicator mismatch, and current source still contains a plausible restoration-notification gap. The implementation has evolved since 1.87.2, but neither recovery of the missing edits nor the complete reported failure has been verified on current main.

## Change summary

Restoring a custom text editor after an unsaved development-window shutdown leaves a dirty indicator that saving cannot clear, while the underlying document reports clean and edits appear missing.

## Best solution

Make restored custom text editor indicators agree with the resolved text document and preserve recoverable unsaved edits through the normal text-file backup lifecycle. First reproduce the supplied cat-scratch scenario and distinguish stale UI state from an actual backup-restoration failure.
