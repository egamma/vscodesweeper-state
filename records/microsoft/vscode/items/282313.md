# Issue #282313 — Custom Text Editor dirty flag inconsistencies

[https://github.com/microsoft/vscode/issues/282313](https://github.com/microsoft/vscode/issues/282313)

## Summary

Still reproduces on main: the custom text editor hot-exit restore flow has a disconnect between the serialized `startsDirty` flag in `CustomEditorInput` and the underlying `textFileService` dirty state, causing the dirty dot to persist after save.

## Change summary

After crash recovery of a Custom Text Editor, the dirty flag cannot be cleared by saving because the UI dirty state and the underlying text model dirty state are out of sync.

## Best solution

The `CustomTextEditorModel` or the `CustomEditorInput.resolve()` path needs to reconcile the `_defaultDirtyState` flag with the actual text file model's backup state after restore — similar to how `MainThreadCustomEditorModel._fromBackup` is handled for binary custom editors.

## Evidence
