# Issue #236814 — [json] Automatically Escape Pasted Text in JSON string

[https://github.com/microsoft/vscode/issues/236814](https://github.com/microsoft/vscode/issues/236814)

## Summary

Keep open in the JSON backlog: the request has 58 community upvotes, current main has no JSON paste-escaping capability, and the only implementation PR was closed without merging because its approach was too complex. The maintainer explicitly left room for a simpler implementation or an extension-based solution.

## Change summary

Automatically escape quotes, backslashes, newlines, tabs, and other required characters when text is pasted inside a JSON string.

## Best solution

Design a substantially simpler JSON/JSONC paste edit that preserves ordinary paste behavior outside string literals and avoids introducing a parallel cached parser. A maintainer should first decide whether this transforms normal paste by default or is exposed through an opt-in setting or Paste As action.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/package.json`, `extensions/json-language-features/client/src/test`
- **Validation:** Add targeted JSON language-feature tests asserting that quotes, backslashes, newlines, and tabs are escaped when pasted inside JSON and JSONC string literals; paste outside strings remains unchanged; and the maintainer-selected enablement mode is honored.
- **Behavior:**

  > Pasting arbitrary plain text inside a JSON or JSONC string can produce valid JSON by escaping quotes, backslashes, newlines, tabs, and other required characters. Pasting outside a string remains unchanged. The behavior must follow the maintainer-selected activation model and must cover settings.json as JSONC. Acceptance includes targeted cases for escaped characters, multiline text, inside-versus-outside-string placement, and disabled or unselected behavior if the feature is opt-in.
- **Trace:**

  > Current main has no DocumentPasteEditProvider in extensions/json-language-features/client/src/jsonClient.ts and no related contribution in extensions/json-language-features/package.json. The closed, unmerged attempt at https://github.com/microsoft/vscode/pull/319460 proved the paste-edit API can express the behavior, but introduced a separate 399-line parser/cache and unrelated changes; the maintainer rejected that complexity at https://github.com/microsoft/vscode/pull/319460#issuecomment-4600099404. Planning should begin at the boundary between the JSON extension client and its existing server-side parsing infrastructure and determine whether a sufficiently simple context check is available. Keep the scope to JSON/JSONC paste handling and targeted tests; do not revive the parser cache or alter generic editor paste behavior.
- **Open decisions:**
  - Should ordinary paste inside a JSON string escape text automatically by default, or should users invoke an explicit Paste As action or enable a setting?
  - Is a simple implementation in the built-in JSON extension acceptable, or should this remain an external extension capability if it cannot reuse existing JSON parsing without substantial new infrastructure?
