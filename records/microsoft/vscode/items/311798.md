# Issue #311798 — [Bug] Minimax 2.7 thinking tokens not correctly parsed in agent/chat

[https://github.com/microsoft/vscode/issues/311798](https://github.com/microsoft/vscode/issues/311798)

## Summary

The defect remains present on current main: OpenAI-compatible streams recognize structured reasoning fields, but `<think>` content is appended to the visible response unchanged. Multiple commenters confirmed the same symptom with MiniMax M2.7 and M3, and no older issue owns this exact observable behavior.

## Change summary

MiniMax reasoning returned inside `<think>` tags is displayed as ordinary chat text instead of thinking content.

## Best solution

Define an explicit compatibility policy for tagged reasoning from OpenAI-compatible BYOK models, then separate recognized MiniMax thinking from the visible answer while preserving ordinary or malformed literal `<think>` content according to that policy.

- **Validation:** Add an SSEProcessor test with `<think>` delimiters split across stream chunks and a following normal answer; verify the reasoning is emitted through `IResponseDelta.thinking`, the answer remains ordinary text, and no tag text leaks into the visible response.
- **Behavior:**

  > When a supported MiniMax BYOK response contains reasoning inside `<think>...</think>`, the reasoning should appear through the chat thinking presentation and neither delimiter should appear in the ordinary answer. Content after the closing delimiter must remain normal response text, including when delimiters and reasoning span multiple streaming chunks. Ordinary responses and structured `reasoning_content` streams must remain unchanged. The plan must also specify deterministic handling for literal, malformed, or unclosed tags.
- **Trace:**

  > The reported Custom OpenAI model resolves through extensions/copilot/src/extension/byok/vscode-node/customOAIProvider.ts to OpenAIEndpoint. SSEProcessor in extensions/copilot/src/platform/networking/node/stream.ts calls `extractThinkingDeltaFromChoice`, which only inspects structured properties defined in extensions/copilot/src/platform/thinking/common/thinkingUtils.ts; otherwise `APIJsonDataStreaming.append` places `delta.content` directly into visible output. Existing tests in extensions/copilot/src/platform/endpoint/test/node/stream.sseProcessor.spec.ts verify `reasoning_content` and `reasoning`, not streamed `<think>` delimiters. Keep structured reasoning behavior and non-thinking OpenAI-compatible content unchanged; the uncertainty starts at whether tagged reasoning should be interpreted globally or only when the configured model/provider opts into that convention. https://github.com/microsoft/vscode/issues/312746 is related structured-reasoning work but does not cover this tagged-content symptom.
- **Open decisions:**
  - Should `<think>` delimiters be interpreted for every OpenAI-compatible response, only for models configured with `thinking: true`, or only for a known provider/model family?
  - For malformed, unclosed, or intentionally literal `<think>` content, should VS Code preserve it visibly or classify everything after the opening delimiter as thinking?
