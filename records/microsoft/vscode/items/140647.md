# Issue #140647 — Activity bar activity indicator is `1px` but configured as `2px`

[https://github.com/microsoft/vscode/issues/140647](https://github.com/microsoft/vscode/issues/140647)

## Summary

The confirmed visual defect remains relevant on current main: the activity marker is configured as 2px, but contributors observed it rendering as 1px across Windows and web. An earlier platform-specific correction was reverted because it regressed Linux with a native title bar, so this needs a cross-platform diagnosis rather than closure.

## Change summary

Make the activity bar's selected-item indicator render at its intended 2px visual thickness and remain flush with the window edge across supported layouts.

## Best solution

Preserve a consistent, clearly visible selected-item marker across web and desktop, with the activity bar on either side and with native or custom title bars, without introducing platform-specific alignment regressions.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/activitybar/media/activityaction.css`, `src/vs/workbench/browser/layout.ts`
- **Validation:** Run the workbench on Windows with native and custom title bars in maximized and restored windows, on web, and on Linux with a native title bar; for each, place the activity bar on both the left and right and verify that the selected-item marker is visibly 2 CSS pixels wide, flush with the intended edge, and neither clipped nor separated by a gap.
- **Behavior:**

  > The selected activity-bar item must have a consistently visible marker with the intended 2px visual weight. It must remain aligned with the activity-bar edge when the bar is on either side, across web and desktop window modes. Acceptance requires confirming the marker is neither clipped to 1px nor shifted into a gap, while preserving high-contrast focus behavior.
- **Trace:**

  > The marker is produced by `.active-item-indicator:before` in src/vs/workbench/browser/parts/activitybar/media/activityaction.css as a zero-width pseudo-element with a 2px left border, positioned at the left or right edge inside an overflow-hidden container. A Windows offset in commit https://github.com/microsoft/vscode/commit/b7f4e903c2e8606dce6f9a1ee2d87e26a1f5a350 addressed the original symptom, but commit https://github.com/microsoft/vscode/commit/8fa7a735d84cc811bfd1c59e7195ee8d67d1f7e8 removed it after exposing a Linux/native-title-bar regression. The workbench still exposes window-state classes through src/vs/workbench/browser/layout.ts, but the 2024 confirmation that web also reproduces means this cannot be assumed to be solely a Windows frame offset. Keep high-contrast focus styling and unrelated activity-bar dimensions out of scope.

## Evidence

- **current source:** src/vs/workbench/browser/parts/activitybar/media/activityaction.css still defines the marker as a zero-width pseudo-element with `border-left: 2px solid`, anchors it at the outer edge, and clips its containing `.active-item-indicator` with `overflow: hidden`; no current-main change establishes that the reported visual result was corrected.
- **confirmed reproduction:** The 2024-12-15 comments on https://github.com/microsoft/vscode/issues/140647 confirm that the 2px CSS border appears visually as 1px on web as well as desktop, while macOS fullscreen renders differently.
- **reverted fix:** https://github.com/microsoft/vscode/commit/b7f4e903c2e8606dce6f9a1ee2d87e26a1f5a350 attempted to fix this issue with Windows-specific offsets, but https://github.com/microsoft/vscode/commit/8fa7a735d84cc811bfd1c59e7195ee8d67d1f7e8 deliberately removed them because they affected Linux users with a native title bar.
- **related issue:** https://github.com/microsoft/vscode/issues/140723 is a younger, closed report limited to maximized-window alignment on Windows, not an older open canonical for the cross-platform thickness problem.
- **canonical search:** Repository issue searches found no older open report with the same observable symptom; the other referenced issue, https://github.com/microsoft/vscode/issues/145925, concerns configuring an application window border rather than activity-indicator thickness.
