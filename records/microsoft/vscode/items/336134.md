# Issue #336134 — Copilot Chat: customizationsUpdate block re-injected identically on every turn, count grows unbounded across a long conversation

[https://github.com/microsoft/vscode/issues/336134](https://github.com/microsoft/vscode/issues/336134)

## Summary

Traced this in the current-main copilot extension source: the anti-churn freeze/drift mechanism in getOrFreezeCustomizationsIndex (agentPrompt.tsx) has a real design gap that reproduces the reported growth pattern, so this stays open as a bug rather than closed.

## Change summary

The `<customizationsUpdate>` block gets re-injected as a new, identical block on every subsequent turn once the customizations-index value drifts once from its first-turn snapshot, growing without bound across a long conversation.

## Best solution

In extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx (`getOrFreezeCustomizationsIndex`) and extensions/copilot/src/extension/prompt/common/conversation.ts (`CustomizationsIndexMetadata`), track the last-surfaced drift value separately from the frozen system-prompt baseline, and only emit a new `<customizationsUpdate>` block when the current value differs from the last *surfaced* value — not from the original turn-1 snapshot — while still keeping the system-prompt-embedded value frozen for cache stability.
