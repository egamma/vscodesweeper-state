# Issue #154913 — find and replace works poorly in notebooks

[https://github.com/microsoft/vscode/issues/154913](https://github.com/microsoft/vscode/issues/154913)

## Summary

Keep open: current notebook search code still wraps the active occurrence index by the number of matching cells rather than total occurrences, which can reset search position after replacement. The maintainer's automatic-search improvement does not establish that both reported problems were resolved.

## Change summary

Notebook find and replace should start near the active cell and preserve progress through successive replacements.

## Best solution

Make notebook find-position restoration retain the correct occurrence across cells and after individual replacements, with regression coverage for multiple matches per cell. Preserve the existing policy against unsolicited scrolling during automatic searches.

## Evidence

- **Current-source defect:** src/vs/workbench/contrib/notebook/browser/contrib/find/findModel.ts: FindModel._updateCurrentMatch assigns currentMatchesPosition % findMatches.length. Each findMatches entry represents a cell, potentially containing multiple occurrences; _matchesCountBeforeIndex and the within-cell offset instead produce an occurrence index. For one cell with multiple remaining matches, every restored position becomes zero.
- **Reporter trigger and replacement path:** The reporter describes losing position after replacing one occurrence. NotebookFindWidget.replaceOne in src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts edits the current match; FindModel._registerModelListener schedules research after cell-content changes, and _research restores the position through _updateCurrentMatch. Replacing a middle occurrence in a single matching cell therefore returns the active index to its first remaining occurrence.
- **Initial-search path:** FindModel._research initially locates the first matching cell at or after notebook focus, converts preceding matches into an occurrence count, and passes that count through the same incorrect modulo. Thus the current focus-aware search logic does not guarantee the correct starting occurrence when cells contain multiple matches.
