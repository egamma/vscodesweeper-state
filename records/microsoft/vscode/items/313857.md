# Issue #313857 — copilot tools are mismatched, selective filtering is partially broken with custom toolsets and tool names do not match

[https://github.com/microsoft/vscode/issues/313857](https://github.com/microsoft/vscode/issues/313857)

## Summary

The original custom-toolset filtering failure was credible, but current main contains substantially revised enablement logic intended to preserve directly enabled tools when another containing toolset is disabled. The remaining behavior cannot be confirmed from source alone, so a current-build reproduction and request log are needed.

## Change summary

Overlapping built-in and custom toolsets can display inconsistent checkbox state and omit an enabled editing tool, while prompt references expose internal tool names that differ from their UI names.

## Best solution

Confirm the overlapping-toolset scenario on the latest Insiders build and compare `chat/selectedTools`, the request's selected tool IDs, and the final model tool catalog. If the tool is still dropped, fix the ID/reference-name translation between `ChatSelectedTools` and the Copilot extension tool filter without changing the intentional distinction between user-facing references and model-facing tool names.

## Evidence

- **current selection logic:** On current main, src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts resolves a member tool as enabled when its containing visible toolset is enabled or the tool itself is explicitly enabled (`toolSetEnabled || currentMap.tools.get(tool.id) === true`). The adjacent `Can still enable/disable user toolsets #251640` test covers overlapping user-toolset enablement.
- **tool serialization:** Commit https://github.com/microsoft/vscode/commit/12717879c47434790e4e956f8e211dc6b1948efa, merged after this report through https://github.com/microsoft/vscode/pull/322548, introduced `ToolAndToolSetEnablementMap` and explicitly separated toolset UI state from the actual tools sent in requests, but it does not reference this issue or conclusively prove this exact report fixed.
- **name mapping:** extensions/copilot/package.json intentionally contributes `copilot_editFiles` as a placeholder with reference name `editFiles`; extensions/copilot/src/extension/tools/common/toolNames.ts maps it to model-facing `edit_files`, while extensions/copilot/src/extension/intents/node/agentIntent.ts disables that placeholder and uses its selection to gate the real edit tools. A maintainer previously explained this UI-name/model-name distinction at https://github.com/microsoft/vscode/issues/296021#issuecomment-3922168263.
- **related items:** https://github.com/microsoft/vscode/issues/323088 is younger, closed, and concerns disabling tools to reduce context rather than this report's mismatched overlapping-toolset state, so it is not a valid duplicate canonical. The later https://github.com/microsoft/vscode/issues/326517 reports a related custom-agent edit checkbox symptom but is also younger than this re-reviewed issue.
