Keep open: current source still constructs full diff editors for newly acquired collapsed rows, matching the reported scrolling cost. The explicitly linked fixing PR remains open and should be reviewed before considering completion.

## Change summary

Scrolling fully collapsed Git commit multi-diffs repeatedly performs unnecessary editor construction and header-template allocation, causing renderer stalls.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/337615 so collapsed-header scrolling avoids unnecessary diff-editor work and uses bounded template reuse, while preserving expanded-editor behavior.

## Evidence

- **Reported trigger and measurements:** https://github.com/microsoft/vscode/issues/337614 describes opening a 58-file Git commit, collapsing every section, and scrolling rapidly with a trackpad. The reporter reproduced this in stable and development builds and recorded 13 renderer long tasks, including one around 642 ms; disabling list smooth scrolling did not resolve it.
- **Current-source allocation path:** In src/vs/editor/browser/widget/multiDiffEditor/virtualizedItemManager.ts, ManagedVirtualizedItem._render acquires a template when a visible item has no binding. MultiDiffEditorWidgetImpl creates DiffEditorItemTemplate for that acquisition, and its constructor in diffEditorItemTemplate.ts unconditionally constructs DiffEditorWidget before binding the item. The collapsed state hides the editor DOM but does not prevent construction.
- **Current-source template churn:** CompressedVirtualizedScrollView._render in src/vs/editor/browser/widget/multiDiffEditor/compressedVirtualizedScrollView.ts interleaves hiding and rendering in item order, allowing newly visible earlier rows to acquire templates before later off-screen rows release theirs during upward scrolling. VirtualizedTemplatePool in virtualizedItemManager.ts retains only five unused templates.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/337615 was verified OPEN with mergedAt null and explicitly says 'Fixes #337614'. It proposes lazy editor construction, release-before-acquire rendering, bounded lightweight-header reuse, and related lifecycle safeguards. Its local after-capture is evidence for the proposed change, not proof that current main is fixed.
- **Related reports do not own this symptom:** https://github.com/microsoft/vscode/issues/240181 is open and concerns lazy text-model loading when opening very large commits; https://github.com/microsoft/vscode/issues/335966 is open and concerns renderer replenishment during pool disposal. Neither establishes ownership of the same collapsed-header scrolling symptom required for a duplicate close on this re-reviewed issue.
- **Inspection limits:** Source inspection confirms unnecessary editor allocation on the reported path; platform-specific frame timings were not independently measured. No code was executed or modified, and the checkout remained clean.
