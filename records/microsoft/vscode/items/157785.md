# Issue #157785 — There is no color customization option for layout controls in the hover state

[https://github.com/microsoft/vscode/issues/157785](https://github.com/microsoft/vscode/issues/157785)

## Summary

Hover backgrounds are already customizable, but the discussion narrowed the request to foreground customization, including hover-state control that current theme tokens do not provide. Keep this older report open for the unresolved title-bar theming decision; the closest related request is newer and cannot be its duplicate canonical.

## Change summary

Allow theme authors to customize layout-control hover foregrounds independently of the title bar's resting foreground.

## Best solution

Agree on a consistent theme-token contract for title-bar toolbar hover foregrounds, preserving window-focus distinctions and existing theme defaults. Resolve the overlapping navigation-button request alongside this work rather than adding isolated layout-icon styling.

## Plan brief

- **Likely files:** `src/vs/platform/theme/common/colors/editorColors.ts`, `src/vs/workbench/common/theme.ts`, `src/vs/workbench/browser/media/style.css`, `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css`
- **Validation:** After agreeing on the token contract, use workbench.colorCustomizations with contrasting resting and hover foregrounds; hover enabled layout controls in focused and unfocused windows. Confirm the configured foreground affects only the agreed surfaces and states, existing toolbar.hoverBackground still works, and unset customization preserves existing behavior across light, dark and high-contrast themes.
- **Behavior:**

  > Theme authors can customize layout-control hover foregrounds independently of their resting foregrounds. The existing toolbar.hoverBackground setting already covers hover backgrounds, while titleBar.activeForeground and titleBar.inactiveForeground affect resting and hovered title-bar content together. Acceptance must cover the chosen foreground customization in focused and unfocused windows, with unchanged defaults when it is unset. Disabled controls and unrelated surfaces must retain their existing behavior unless explicitly included in the agreed contract.
- **Trace:**

  > In src/vs/workbench/browser/parts/titlebar/titlebarPart.ts, updateToolBar obtains layout actions from MenuId.LayoutControlMenu, and updateStyles sets the title-bar element's foreground according to window focus. src/vs/workbench/common/theme.ts registers the active and inactive title-bar foregrounds. Shared toolbar hover rules in src/vs/workbench/browser/media/style.css use toolbar.hoverBackground and toolbar.hoverOutline, whose registrations are in src/vs/platform/theme/common/colors/editorColors.ts; there is no corresponding hover-foreground token in these paths. The discussion leaves title-bar inheritance versus shared icon/toolbar theming unsettled, and titlebarpart.css also contains command-center foreground rules that must be considered when defining scope. https://github.com/microsoft/vscode/issues/272840 requests overlapping hover customization for navigation buttons but is newer and is not a duplicate target for this report. Preserve existing background customization and default window-focus behavior; the uncertainty is the public theming contract, not whether a hover foreground token exists.
- **Open decisions:**
  - Should hover-foreground customization apply to toolbars throughout the workbench or only to title-bar toolbar actions, and should command-center navigation actions share that contract?
  - Should the chosen hover foreground apply equally in focused and unfocused windows, or should theme authors be able to distinguish those states?
