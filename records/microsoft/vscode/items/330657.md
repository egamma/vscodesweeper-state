# Issue #330657 — CopilotCLIModels queries github.com instead of configured GitHub Enterprise host, causing repeated 401 Bad credentials

[https://github.com/microsoft/vscode/issues/330657](https://github.com/microsoft/vscode/issues/330657)

## Summary

Traced this in the source: `CopilotCLISDK.getAuthInfo()` in copilotCli.ts hardcodes `host: 'https://github.com'` in its fallback branch whenever the SDK's `resolveAuthInfoFromToken` doesn't resolve `userInfo` for the token — for a GitHub Enterprise session this sends an enterprise-issued token against github.com, producing exactly the reported 401 loop. The mechanics inside `resolveAuthInfoFromToken` itself live in the private `@github/copilot/sdk` package, which isn't in this checkout, so I can't fully confirm why it fails to resolve for GHE tokens, but the call-site fallback is a clear, verifiable defect regardless.

## Change summary

CopilotCLIModels repeatedly logs 401 Bad credentials because it queries github.com for Copilot user info instead of the configured GitHub Enterprise host, even though the enterprise Copilot token itself is valid.

## Best solution

In `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts` (`getAuthInfo`), stop hardcoding `host: 'https://github.com'` in the fallback path — resolve the actual configured host (via `authProviderId`/the enterprise URI, mirroring how `src/vs/platform/agentHost/common/agentHostCustomizationConfig.ts` pushes `github-enterprise.uri` into the agent host) so the CLI model lookup targets the same host the user actually authenticated against, or silently skip the CLI model fetch when the SDK can't resolve a host for that provider.
