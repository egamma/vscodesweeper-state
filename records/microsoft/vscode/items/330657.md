# Issue #330657 — CopilotCLIModels queries github.com instead of configured GitHub Enterprise host, causing repeated 401 Bad credentials

[https://github.com/microsoft/vscode/issues/330657](https://github.com/microsoft/vscode/issues/330657)

## Summary

Traced a concrete bug in this repo's own code: CopilotCLIModels.getAuthInfo() falls back to a hardcoded 'https://github.com' host whenever the SDK's resolveAuthInfoFromToken() can't resolve the token, ignoring the configured GitHub Enterprise host — exactly matching the reported symptom of an enterprise-authenticated user getting repeated 401 'Bad credentials' from the CLI model list while normal Copilot auth succeeds.

## Change summary

CopilotCLIModels repeatedly logs 401 'Bad credentials' fetching the CLI model list when authenticated via GitHub Enterprise, because it queries github.com instead of the configured enterprise host.

## Best solution

In extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts, CopilotCLISDK.getAuthInfo()'s fallback (around lines 677-683) should resolve host from the actual configured auth provider (authProviderId(configurationService) + configurationService.getNonExtensionConfig<string>('github-enterprise.uri')) instead of hardcoding 'https://github.com', mirroring how DomainService (extensions/copilot/src/platform/endpoint/node/domainServiceImpl.ts) already derives the enterprise URL.
