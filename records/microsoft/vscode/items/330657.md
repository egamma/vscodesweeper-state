# Issue #330657 — CopilotCLIModels queries github.com instead of configured GitHub Enterprise host, causing repeated 401 Bad credentials

[https://github.com/microsoft/vscode/issues/330657](https://github.com/microsoft/vscode/issues/330657)

## Summary

Traced this on current main: `CopilotCLISDK.getAuthInfo()` in `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts` falls back to a hardcoded `host: 'https://github.com'` whenever the SDK's `resolveAuthInfoFromToken(token)` call doesn't resolve user info from the token — which is exactly what happens for an enterprise-only account, since that call isn't given the configured GHE host. That produces the reported repeating 401 loop even while the real Copilot token (fetched via the correctly enterprise-aware `AuthenticationService`) keeps refreshing fine.

## Change summary

CopilotCLIModels/CopilotCLISDK queries github.com for Copilot user info instead of the configured GitHub Enterprise host, causing repeated 401 'Bad credentials' errors for GHE users (and possibly the same-session image upload 401).

## Best solution

In `CopilotCLISDK.getAuthInfo()` (copilotCli.ts), resolve the host the same way `DomainService`/`CAPIClientService` do — check `ConfigKey.Shared.AuthProvider`/`github-enterprise.uri` (already injected `configurationService` is available in this class) — and pass/use that host both when calling `resolveAuthInfoFromToken` (if the SDK API supports it) and in the fallback `{ type: 'token', ... host }` object, instead of the literal `'https://github.com'`.
