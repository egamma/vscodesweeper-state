# Issue #235344 — `Add line comment` should await the tokenization to get the correct language at the position

[https://github.com/microsoft/vscode/issues/235344](https://github.com/microsoft/vscode/issues/235344)

## Summary

The regression remains present on current main, and a team member plus a contributor confirmed the startup-sensitive embedded-language failure. Keep the issue open while the existing human-authored fix PR is reviewed.

## Change summary

Toggle Line Comment can use the HTML language configuration instead of JavaScript immediately after restoring an HTML editor with the cursor inside a script block.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/244217 together with the broader async-tokenization investigation at https://github.com/microsoft/vscode/issues/244225, ensuring comment commands receive accurate embedded-language tokens before selecting a comment configuration.

## Evidence

- **confirmed reproduction:** A VS Code team member reproduced the behavior after window reload and identified that the TextMate or embedded grammar was not yet loaded; another contributor supplied recordings and narrowed it to the async-tokenization regression.
- **regression commit:** Commit https://github.com/microsoft/vscode/commit/29be8e8665989b2b5c217ea7f7ce5df3d90c9d33 changed `editor.experimental.asyncTokenization` from false to true by default, matching the reported regression window from 1.92.2 to 1.93.0.
- **current source:** On current main, src/vs/editor/common/config/editorConfigurationSchema.ts still defaults `editor.experimental.asyncTokenization` to true, while LineCommentCommand in src/vs/editor/contrib/comment/browser/lineCommentCommand.ts calls `tokenizeIfCheap` and immediately reads `getLanguageIdAtPosition`; this can consume incomplete embedded-language tokens.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/244217 remains open, explicitly uses `Fixes #235344`, and proposes disabling async tokenization by default because of embedded-language failures.
- **broader investigation:** https://github.com/microsoft/vscode/issues/244225 is open and tracks the async-tokenization failures, explicitly linking this report and the pending fix PR.
