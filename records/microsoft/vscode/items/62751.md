# Issue #62751 — Git - Provide task progress

[https://github.com/microsoft/vscode/issues/62751](https://github.com/microsoft/vscode/issues/62751)

## Summary

Keep open: Git operations have an indeterminate activity indicator, but push output is still buffered until completion rather than providing live progress details. This team-authored Backlog request has 23 upvotes, and no verified older canonical or issue-referencing fix establishes completion.

## Change summary

Expose live Git operation output or phase details so long-running pushes and hooks do not appear stalled.

## Best solution

Provide readable, operation-attributed live feedback in the built-in Git extension, including hook and remote messages when available. Keep unknown phases indeterminate rather than presenting Git's phase percentages as reliable end-to-end completion.

## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/repository.ts`, `extensions/git/package.json`
- **Validation:** Exercise a controlled slow push with a hook emitting distinguishable messages before a delayed exit: feedback must appear before completion. Repeat with concurrent operations to verify attribution and readability, and confirm success, failure, and existing clone progress remain correct.
- **Behavior:**

  > Long-running Git pushes should provide meaningful feedback before the operation finishes, rather than exposing remote and hook messages only afterward. The author explicitly accepts live Git output as the minimum useful outcome; phase labels or percentages are additional possibilities. Acceptance must demonstrate early feedback during a delayed push and hook, readable concurrent-operation output, and an accurate final result without implying that a phase percentage measures the entire operation.
- **Trace:**

  > Repository.push in extensions/git/src/git.ts delegates to the buffered execution path without requesting progress output or installing a progress observer. The exec helper collects stdout and stderr, and Git._exec logs them only after completion. ProgressManager in extensions/git/src/repository.ts supplies indeterminate SCM activity, while clone has a separate stderr parser and --progress invocation. The maintainer explanation at https://github.com/microsoft/vscode/issues/85732#issuecomment-561078441 identifies parallel-output intermixing as a deliberate constraint. Preserve command-result parsing, error handling, and existing clone behavior; do not treat arbitrary hook execution as measurable end-to-end progress. The remaining design boundary is how concurrent operations expose live feedback without losing attribution or readability.
- **Open decisions:**
  - Is live, operation-attributed Git output sufficient for the first delivery, or should push also expose phase details in a user-facing progress surface?
