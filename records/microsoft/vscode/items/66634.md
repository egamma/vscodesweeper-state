# Issue #66634 — Disable Multiple Cursors

[https://github.com/microsoft/vscode/issues/66634](https://github.com/microsoft/vscode/issues/66634)

## Summary

Keep open: current main still offers only Alt or Ctrl/Cmd for mouse multicursor creation, with no explicit off option. The cursor-limit workaround prevents additional cursors but produces limit warnings and interferes with column selection; the request has 30 upvotes and remains accepted Backlog work.

## Change summary

Provide an explicit way to disable accidental multicursor creation rather than requiring a choice between two mouse modifiers.

## Best solution

Provide a discoverable opt-out in the editor configuration and Selection menu while retaining today's defaults. Decide whether it disables only modifier-click cursor creation or all multiple-selection mechanisms, including deliberate column selection and keyboard commands.

- **Reason:** An explicit opt-out addresses accidental editing and makes an existing editor interaction more predictable without adding a new editing subsystem.

- **Behavior:**

  > Users need an explicit, discoverable way to prevent accidental extra cursors caused by modifier-clicks. The opt-out should not emit cursor-limit warnings, and existing Alt and Ctrl/Cmd modes should retain their current behavior. Acceptance must cover clicks followed by typing, configuration persistence, and Selection-menu state. Whether intentional column selection, keyboard Add Cursor commands, and programmatic multiple selections remain available requires a scope decision.
- **Trace:**

  > editor.multiCursorModifier in src/vs/editor/common/config/editorOptions.ts accepts only alt and ctrlCmd, and ToggleMultiCursorModifierAction in src/vs/workbench/contrib/codeEditor/browser/toggleMultiCursorModifier.ts toggles between those values. ViewController.dispatchMouse in src/vs/editor/browser/view/viewController.ts routes modifier clicks to cursor creation and separately handles column selection. The existing multiCursorLimit: 1 workaround truncates selections in CursorsController.setStates and triggers a warning in CodeEditorWidget, so it is not an interaction-level opt-out. ClickLinkGesture.createOptions couples navigation modifiers to the multicursor setting; the uncertainty starts at what navigation and deliberate selection gestures should mean when multicursor creation is disabled. Preserve current defaults and existing enabled-mode behavior, and do not broaden this into general mouse-shortcut customization. https://github.com/microsoft/vscode/issues/3130 is related customization work; https://github.com/microsoft/vscode/issues/87737 concerns only HTML tag mirroring.
- **Open decisions:**
  - Should the opt-out disable only modifier-click cursor creation, preserving deliberate column selection and keyboard commands, or prohibit multiple selections through every editor entry point?
  - When modifier-click multicursor creation is off, which modifiers should Go to Definition and Open Link use, and should Alt-drag column selection remain available?
