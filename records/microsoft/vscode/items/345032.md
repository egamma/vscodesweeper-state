# Issue #345032 — Agent Host: steering a running session ends its turn, so clients see the agent as finished

[https://github.com/microsoft/vscode/issues/345032](https://github.com/microsoft/vscode/issues/345032)

## Summary

The reported false completion remains visible in current source: Copilot and Codex emit an unqualified turn completion while steering continues the underlying run. Keep this open pending agreement on the protocol-visible distinction between steering hand-over and actual completion.

## Change summary

Make steering hand-overs distinguishable from the agent finishing for clients observing Agent Host actions.

## Best solution

Establish interoperable steering-continuation semantics with https://github.com/microsoft/agent-host-protocol/issues/550, then apply them consistently in the Copilot and Codex providers without timing-based client heuristics.

Repeat the issue's second-client scenario with both providers: steer during the second long-running command and verify that no timing-based debounce is needed to distinguish the hand-over from the final DONE response.
- **Behavior:**

  > An AHP client observing a running Copilot or Codex chat must not mistake consumption of a steering message for the underlying agent finishing. Continuation must be distinguishable from genuine completion without waiting an arbitrary interval for another action. Final completion must remain observable when the task actually finishes, and ordinary queued follow-up messages must retain their distinct meaning.
- **Trace:**

  > CopilotAgentSession._beginSteeringTurn calls _completeActiveTurn and then starts a new presentation turn, retaining the underlying SDK turn association. CodexAgent._beginSteeringTurn similarly completes the old host turn and remaps the same app-server turn before starting the steering turn. Both completion payloads lack continuation metadata, despite ChatTurnCompleteAction documenting assistant idleness. The existing Copilot promotion test explicitly pins the presentation split, so removing that split would change established behavior rather than merely repairing a guard. Coordinate the public contract with https://github.com/microsoft/agent-host-protocol/issues/550; generated protocol files must be changed in their source repository and synchronized, not edited directly. Preserve steering delivery, queued-message semantics, active tool routing, and compatibility with conforming hosts and older clients.
- **Open decisions:**
  - Should consumed steering remain within the active protocol turn, or should separate presentation turns remain with an explicit interoperable continuation signal?
