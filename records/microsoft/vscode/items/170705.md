# Issue #170705 — PHP formatting on typing

[https://github.com/microsoft/vscode/issues/170705](https://github.com/microsoft/vscode/issues/170705)

## Summary

The maintainer-confirmed embedded-language mismatch remains visible on current main: typing an HTML closing tag uses HTML rules initially, but inherited indentation is calculated with the PHP model's rules. This should remain open for an editor auto-indent fix.

## Change summary

HTML closing tags typed inside PHP files can be deindented past their containing HTML element.

## Best solution

Make inherited indentation consistently follow the active embedded HTML language across the current and preceding lines, while preserving PHP indentation inside PHP scopes, and add a mixed-language regression test.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/editor/common/languages/supports/indentationLineProcessor.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add a cursor auto-indent regression test with PHP as the model language and HTML-tokenized lines, asserting that typing `>` to complete an indented `</ul>` preserves the containing HTML indentation while existing PHP and single-language indentation tests remain unchanged.
- **Behavior:**

  > In a PHP document containing an HTML region, typing an HTML closing tag must align it with its matching opening tag rather than moving it to column one. HTML indentation inside PHP should behave like the equivalent HTML document, while indentation within PHP code remains governed by PHP rules. Acceptance should cover the nested `<div><ul></ul></div>` scenario from https://github.com/microsoft/vscode/issues/170705 and ensure ordinary single-language auto-indent behavior is unchanged.
- **Trace:**

  > In src/vs/editor/common/languages/autoIndent.ts, `getIndentActionForType` resolves the active language at the cursor and therefore recognizes the HTML `decreaseIndentPattern`. It then calls `getInheritIndentForLine`, which constructs its `indentRulesSupport` from `model.tokenization.getLanguageId()` instead of the embedded language, reproducing the mismatch diagnosed in https://github.com/microsoft/vscode/issues/170705. The PHP grammar's embedded-language mapping is declared in extensions/php/package.json. The uncertainty starts at how inherited indentation should carry a language identity while walking prior blank or mixed-language lines; the boundary is the generic auto-indent machinery, and PHP-only or HTML-only behavior must not regress.
- **Open decisions:**
  - Should inherited indentation use one language configuration selected from the target token scope, or resolve the relevant embedded language separately for each preceding line?
  - What behavior should apply when blank lines or token boundaries separate the current embedded scope from the preceding non-empty line?

## Evidence

- **maintainer diagnosis:** The discussion at https://github.com/microsoft/vscode/issues/170705 confirms the reproduction and identifies the mismatch: the typed closing tag is evaluated with HTML rules while inherited indentation is looked up using the PHP model language.
- **current source:** src/vs/editor/common/languages/autoIndent.ts:375-396 obtains `indentRulesSupport` from `getLanguageIdAtPosition`, then calls `getInheritIndentForLine`; that function at lines 75-90 still obtains its rules from `model.tokenization.getLanguageId()`, the top-level PHP language.
- **embedded grammar:** extensions/php/package.json:39-49 maps `text.html` scopes within the PHP grammar to the `html` language, confirming that the active token language can legitimately differ from the model language on this path.
- **no canonical replacement:** The related PHP auto-indent reports found are either older resolved behavior or distinct problems such as PHP block indentation; no open canonical issue was found that owns this embedded HTML closing-tag defect.
