# Issue #56326 — Support auto update for Windows and Linux ZIP

[https://github.com/microsoft/vscode/issues/56326](https://github.com/microsoft/vscode/issues/56326)

## Summary

Keep open: Windows and Linux archive builds still direct users to external downloads rather than applying updates in place. This accepted Backlog request has 31 upvotes, and neither installer-based updates nor the discussion's scripts satisfy the portable workflow.

## Change summary

Support integrated, restart-to-apply updates for Windows and Linux archive distributions while preserving portable user data.

## Best solution

Design an archive-update lifecycle in the platform update services that preserves portable data and replaces application files without requiring manual extraction. Keep installer and package-manager update behavior unchanged, and establish failure-recovery expectations before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.win32.ts`, `src/vs/platform/update/electron-main/updateService.linux.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`, `src/vs/platform/update/common/update.ts`
- **Validation:** On Windows ZIP and Linux TAR.GZ portable builds, start an older version with distinctive settings, an extension, and an unsaved editor; accept an available update and restart. Verify the new version runs without manual extraction, settings/extensions/unsaved content survive, and obsolete application files are removed. Exercise interrupted application and an unwritable installation directory to verify recoverability and explicit failure reporting; confirm Setup and package-manager installations retain their existing behavior.
- **Behavior:**

  > Windows and Linux archive users currently leave VS Code to download and manually replace application files when an update is available. The requested outcome is an integrated update-and-restart experience that retains portable settings, extensions, and unsaved work without requiring an installer or a user-maintained script. Acceptance should cover successful updates, obsolete-file removal, interrupted updates, and unwritable locations. Existing installer and package-manager workflows must remain unchanged.
- **Trace:**

  > Win32UpdateService.doCheckForUpdates in src/vs/platform/update/electron-main/updateService.win32.ts branches on UpdateType.Archive and stops at AvailableForDownload; its doDownloadUpdate opens an external URL. LinuxUpdateService in src/vs/platform/update/electron-main/updateService.linux.ts likewise exposes downloads without an application-replacement lifecycle. src/vs/platform/update/electron-main/win32UpdateType.ts distinguishes Setup from archive by product target, and update.config.contribution.ts contains no setting that enables archive application. This confirms a missing feature, not a malfunction of the existing updater. https://github.com/microsoft/vscode/issues/63307 already consolidates into this issue, while https://github.com/microsoft/vscode/issues/43671 concerns a separate Linux download-guidance problem. The trace establishes the entry points but not a complete cross-platform replacement, restart, and recovery design; preserve portable data and keep Setup/package-manager paths outside the change boundary.
- **Open decisions:**
  - If archive-update application is interrupted or fails, should the supported recovery contract automatically restore the previous version, or retain a recoverable installation and require explicit user action?

## Evidence

- **Windows capability remains missing:** src/vs/platform/update/electron-main/win32UpdateType.ts classifies non-Setup targets as UpdateType.Archive. In updateService.win32.ts:261–264, archive updates enter AvailableForDownload and bypass automatic downloading; doDownloadUpdate at lines 370–374 opens the download URL externally and returns to Idle.
- **Linux capability remains missing:** src/vs/platform/update/electron-main/updateService.linux.ts sets AvailableForDownload when an update exists. LinuxUpdateService.doDownloadUpdate opens the product download page or archive URL externally; it does not replace application files or arrange restart-to-apply.
- **Existing settings do not cover the request:** src/vs/platform/update/common/update.config.contribution.ts registers update.mode for automatic update checks and update.enableWindowsBackgroundUpdates for background installation. Neither overrides the archive-specific external-download paths. https://code.visualstudio.com/docs/setup/portable explicitly says Windows ZIP archives do not support auto update and documents copying the data folder to a newer extracted version on Windows and Linux.
- **Discussion establishes the portable requirement:** https://github.com/microsoft/vscode/issues/56326#issuecomment-412826592 rejects the user installer as a substitute for portable use. https://github.com/microsoft/vscode/issues/56326#issuecomment-413557230 describes external scripts as a workaround, and https://github.com/microsoft/vscode/issues/56326#issuecomment-419589057 independently describes the same manual-update burden.
- **Workarounds have preservation limitations:** https://github.com/microsoft/vscode/issues/56326#issuecomment-419863423 notes that extracting over an existing installation does not remove obsolete files. https://github.com/microsoft/vscode/issues/56326#issuecomment-989492142 warns that the posted script's deletion of user-data backups can lose unsaved work; these scripts are not equivalent to a supported updater.
