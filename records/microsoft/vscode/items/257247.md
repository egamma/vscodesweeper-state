# Issue #257247 — Extended git conflict markers are not handled correctly

[https://github.com/microsoft/vscode/issues/257247](https://github.com/microsoft/vscode/issues/257247)

## Summary

Confirmed bug: VS Code's merge conflict parser uses an exact match for the splitter marker (`=======`, 7 chars), so git's extended conflict markers (8+ chars) are not recognized. The merge editor's markers controller is similarly hardcoded. No fix has landed on main.

## Change summary

Git's extended conflict markers (8+ characters, produced in certain merge topologies with the ORT engine) are not recognized by VS Code's merge conflict parser, leaving conflict markers in resolved files.

## Best solution

Update `extensions/merge-conflict/src/mergeConflictParser.ts` to accept variable-length conflict markers: the splitter check (`line.text === splitterMarker`) should allow longer `=` sequences (while still avoiding false positives with short `===` in code). The merge editor's `mergeMarkersController.ts` should similarly handle extended markers. The fix needs care to avoid regressing #95040 (JavaScript `===` false positives) — a regex like `/^={7,}$/` for the splitter would cover extended markers without matching code lines.
