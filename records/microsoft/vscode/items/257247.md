# Issue #257247 — Extended git conflict markers are not handled correctly

[https://github.com/microsoft/vscode/issues/257247](https://github.com/microsoft/vscode/issues/257247)

## Summary

The defect remains directly visible on current main: the merge-conflict parser recognizes extended start and end markers but rejects an extended separator, so it cannot construct the conflict descriptor. The older related issue does not report the same observable failure and does not meet the stronger duplicate bar for this re-reviewed item.

## Change summary

Recognize valid Git conflict blocks whose marker width is greater than the default seven characters, without mistaking ordinary runs of equals signs for separators.

## Best solution

Make conflict parsing validate a consistent Git marker width across the opening, separator, optional ancestor, and closing lines. Preserve the protection against treating Markdown headings or unrelated equals-sign runs inside conflict content as separators.
