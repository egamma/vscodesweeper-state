# Issue #143774 — Allow to use codicons for the gutter decorations

[https://github.com/microsoft/vscode/issues/143774](https://github.com/microsoft/vscode/issues/143774)

## Summary

The extension-facing gutter decoration API still accepts image paths, not built-in icons or spinner modifiers, so the requested capability remains missing. Keep this accepted Backlog request open: it has 46 upvotes, and the related file-decoration and commenting issues do not own the same API work.

## Change summary

Allow extension authors to use built-in icons, including an animated pending indicator, in editor gutter decorations without supplying image assets.

## Best solution

Provide a supported, theme-aware gutter icon capability through the text editor decoration API while preserving existing image decorations. An API-owner planning session should establish the public icon contract and animation/color semantics before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/test/browser/services/decorationRenderOptions.test.ts`
- **Validation:** After agreeing on the API, exercise an extension that decorates a line with a pending spinner, then success and error icons; verify theme changes and unchanged image-based gutter decorations. Add conversion and rendering assertions, including theme overrides, to the relevant API tests and src/vs/editor/test/browser/services/decorationRenderOptions.test.ts.
- **Behavior:**

  > An extension author should be able to select built-in icons for editor gutter decorations without packaging image assets or copying font glyphs. The motivating workflow distinguishes pending evaluation with an animated indicator, success with a checkmark, and failure with a cross, with theme-aware colors where supported. Existing image-based decorations must retain their behavior. Acceptance should cover state transitions, theme changes, and the agreed animation behavior.
- **Trace:**

  > The public gutter contract is ThemableDecorationRenderOptions.gutterIconPath: string | Uri in src/vscode-dts/vscode.d.ts. Both decoration conversion paths in src/vs/workbench/api/common/extHostTypeConverters.ts serialize it as a URI; src/vs/editor/common/editorCommon.ts carries only a URI and size for the gutter. DecorationCSSRules.getCSSTextForModelDecorationGlyphMarginClassName in src/vs/editor/browser/services/abstractCodeEditorService.ts produces background-image CSS, confirming that the extension-facing path lacks built-in icon support. Existing CSS-generation and theme-override tests live in src/vs/editor/test/browser/services/decorationRenderOptions.test.ts. Preserve image rendering, decoration ranges, and non-gutter attachments. Built-in commenting changes discussed in https://github.com/microsoft/vscode/issues/115808 do not establish a public extension contract, and https://github.com/microsoft/vscode/issues/135591 concerns a separate file-decoration surface. The unresolved boundary is the public icon representation and its animation/color semantics, not whether gutter indicators are technically renderable.
- **Open decisions:**
  - What public contract should identify gutter icons: ThemeIcon values, status-bar-style icon strings, or a separate decoration option?
  - Should the initial contract include animated icon modifiers and independently themeable gutter icon colors, as needed by the pending/success/error workflow?
