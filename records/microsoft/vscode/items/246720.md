# Issue #246720 — Difference in UI between `vscode.workspace.applyEdit(isRefactoring: true)` with 1 edit vs >1 edit

[https://github.com/microsoft/vscode/issues/246720](https://github.com/microsoft/vscode/issues/246720)

## Summary

The single-file versus multi-file saving difference remains in current source, and the existing workspace-edit label is appropriate. Keep this open: correcting the closed-file case needs to preserve the deliberately unsaved active-editor behavior described by a maintainer.

## Change summary

Refactoring workspace edits affecting one previously closed file leave it dirty and open it, whereas edits affecting multiple files trigger automatic saving.

## Best solution

Make refactoring-save behavior handle previously closed files consistently regardless of file count, while preserving the intended treatment of active-editor edits. Settle that saving boundary before changing the shared bulk-edit service; workspace-wide formatting and suppressing format-on-save are separate concerns.
