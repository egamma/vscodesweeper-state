# Issue #246720 — Difference in UI between `vscode.workspace.applyEdit(isRefactoring: true)` with 1 edit vs >1 edit

[https://github.com/microsoft/vscode/issues/246720](https://github.com/microsoft/vscode/issues/246720)

## Summary

The `resources.length > 1` guard in bulkEditService.ts is intentional — it was re-added in commit b65a4918b85 to fix a regression where single-file auto-save caused Organize Imports to hang (issue #165326). The inconsistency the reporter describes is real and traceable in the source, but removing the guard requires solving the re-entrant save-participant problem first. Keeping open as a real but known limitation.

## Change summary

When `vscode.workspace.applyEdit({ isRefactoring: true })` touches exactly one file, the file is opened but not auto-saved, whereas multi-file edits auto-save and stay closed — an inconsistent UX caused by a deliberate guard.

## Best solution

Fix the underlying re-entrancy problem with save participants (issue #166352 touched on this) so the `resources.length > 1` guard can be safely removed. The fix lives in `src/vs/workbench/contrib/bulkEdit/browser/bulkEditService.ts` at the `_saveAll` gate, but the real blocker is that single-file auto-save triggers format-on-save / code-actions-on-save re-entrantly. A proper solution likely involves skipping save participants for saves triggered by bulk edits, or marking those saves as programmatic.
