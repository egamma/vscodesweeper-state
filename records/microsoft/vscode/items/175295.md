# Issue #175295 — A "tight layout" mode that reduces vertical spacing

[https://github.com/microsoft/vscode/issues/175295](https://github.com/microsoft/vscode/issues/175295)

## Summary

Keep open: existing notebook settings reduce toolbar overhead but still do not expose the internal cell padding and spacing controls requested here. The maintainer-supported request remains valid, and the earlier vertically compact notebook issue was explicitly consolidated into this one.

## Change summary

Provide an opt-in notebook layout that reduces internal cell padding and vertical gaps while retaining useful execution feedback.

## Best solution

Provide a coherent opt-in vertical-density configuration in the notebook layout system, preserving current defaults and usable execution indicators. Settle whether this is a single tight-layout preset or individual spacing controls before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/notebookOptions.ts`, `src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts`, `src/vs/workbench/contrib/notebook/browser/viewModel/cellEditorOptions.ts`, `src/vs/workbench/contrib/notebook/browser/view/cellParts/cellEditorOptions.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/profile/notebookProfile.ts`
- **Validation:** Compare the supplied sample notebook with the opt-in layout disabled and enabled at a fixed viewport and editor line height. Verify reduced single-line code-cell height and inter-cell/output gaps, visible execution feedback, no clipping or toolbar overlap during editing and execution, and unchanged default layout; add notebook option and cell-layout tests for the agreed configuration contract.
- **Behavior:**

  > Users working on small displays need a notebook layout with less empty space inside code cells and between cells and outputs. Existing toolbar-hiding settings improve density but leave internal padding that users cannot configure. An opt-in compact layout should reduce that remaining overhead without changing the default experience or losing usable execution feedback. Acceptance should compare the same notebook at a fixed viewport and line height, including single-line cells, multiple outputs, and running cells.
- **Trace:**

  > NotebookOptions in src/vs/workbench/contrib/notebook/browser/notebookOptions.ts owns cell margins, output padding, and status-dependent editor padding; its top padding starts at 12 and may increase for editor decorations. BaseCellEditorOptions._computeEditorOptions in browser/viewModel/cellEditorOptions.ts overwrites user padding, and CellEditorOptions.getValue in browser/view/cellParts/cellEditorOptions.ts applies NotebookOptions.computeEditorPadding. The existing notebook.compactView setting changes some margins and toolbar gaps but does not expose the remaining code-cell padding; notebook.setProfile in browser/contrib/profile/notebookProfile.ts only combines existing presentation settings. The maintainer acknowledged notebook padding controls at https://github.com/microsoft/vscode/issues/175295#issuecomment-1449096674, and https://github.com/microsoft/vscode/issues/147244 was consolidated here. Preserve default geometry, decoration accommodation, and existing toolbar and execution functionality. The unresolved boundary is the user-facing density contract and how execution feedback remains available in the tight layout.
- **Open decisions:**
  - Should users get a single tight-layout preset, independently configurable cell/editor/output spacing, or both?
  - Should the tight layout retain the existing execution status bar or provide execution feedback without reserving that separate row?
