# Issue #166804 — allow filename#L<line_number> syntax to open file at specific line

[https://github.com/microsoft/vscode/issues/166804](https://github.com/microsoft/vscode/issues/166804)

## Summary

Keep open: current CLI parsing does not support filename#L<number>, and the request earned its Backlog placement with 20 community upvotes. No verified canonical duplicate or completed implementation was found.

## Change summary

Allow code --goto to accept GitHub-style filename#L<number> references alongside the existing colon-delimited syntax.

## Best solution

Support the requested line-anchor syntax in the CLI goto flow while preserving existing file:line[:column] behavior. Settle how goto mode distinguishes an anchor from a literal filename ending in #L<number> before implementation.

- **Behavior:**

  > The request is to open a local file at a specified line using code -g 'filename#L<number>', without rewriting the copied line anchor into colon syntax. Existing file:line[:column] inputs must retain their behavior. Acceptance includes POSIX and Windows paths and opening the underlying existing file at the requested line. The behavior for actual filenames ending in #L<number> must be agreed before implementation; full GitHub URLs, commit resolution, and line ranges are outside the stated request.
- **Trace:**

  > parseLineAndColumnAware in src/vs/base/common/extpath.ts recognizes colon-separated positions only and currently preserves #L64 as part of the filename. - **Open decisions:**
