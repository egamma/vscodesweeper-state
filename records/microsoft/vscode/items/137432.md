# Issue #137432 — Git - git.autoRepositoryDetection does not honour git.ignoredRepositories nor files.exclude

[https://github.com/microsoft/vscode/issues/137432](https://github.com/microsoft/vscode/issues/137432)

## Summary

Still a real gap on current main: `git.ignoredRepositories` is only consulted after the repository root has already been resolved by invoking git on the path, so an ignored (here, sshfs-mounted) location is still scanned; `files.exclude` is not consulted by the git extension at all.

## Change summary

Automatic repository detection runs git against paths the user listed in `git.ignoredRepositories` (and excluded via `files.exclude`), causing very slow scans/hangs on an sshfs mount.

## Best solution

Move/duplicate the ignore check in `Model.openRepository` (extensions/git/src/model.ts) so a path matching `git.ignoredRepositories` short-circuits before `getRepositoryRoot` spawns git, after a maintainer decides the matching semantics (exact root equality today vs. path containment); `files.exclude` is an explorer-visibility setting and should stay out of git detection, which deserves an explicit note on the issue.

## Plan brief

- **Likely files:** `extensions/git/src/model.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`
- **Validation:** A git extension test asserting that `openRepository()` for a path covered by `git.ignoredRepositories` does not invoke `git rev-parse --show-toplevel` (no git child process) and does not open a repository.
- **Behavior:**

  > With `git.autoRepositoryDetection` enabled and a path listed in `git.ignoredRepositories`, VS Code must not run git against that location at all — opening a file inside it should produce no repository-root resolution, no repository in Source Control, and no git output for that path. Repositories not on the ignore list keep their current detection behavior, including parent-folder prompting, unsafe-repository handling, and closed-repository handling. Acceptance: with an ignored path configured, the git log shows the path skipped before any git invocation; existing git extension tests still pass. `files.exclude` is explicitly out of scope — it governs explorer visibility, not git detection.
- **Trace:**

  > In extensions/git/src/model.ts, `Model.openRepository(repoPath)` resolves the repository root via `this.getRepositoryRoot(repoPath)` — which spawns git (`rev-parse --show-toplevel`) against the supplied path — and only afterwards calls `this.shouldRepositoryBeIgnored(repositoryRoot)`. On a slow or stalled filesystem (the reporter's sshfs mount) that git invocation plus the follow-on `repository.status()` is exactly the multi-hour scan they describe, so the ignore list cannot protect them. `shouldRepositoryBeIgnored` compares with `pathEquals` against resolved roots only (absolute entries, or entries joined to each workspace folder), so an entry that is not byte-equal to the resolved root never matches. Entry points that reach this path are `onDidChangeVisibleTextEditors` (visible editors) and `scanWorkspaceFolders`/`traverseWorkspaceFolder` (which already honors `git.repositoryScanIgnoredFolders`). The boundary: do not change parent-repository, unsafe-repository, resource-trust, or closed-repository handling, and do not introduce any `files.exclude` dependency in the git extension. Related: https://github.com/microsoft/vscode/issues/145066 (closed, addressed by `git.openRepositoryInParentFolders`).
- **Open decisions:**
  - Should `git.ignoredRepositories` match only an exact repository root (today's contract) or also suppress detection for any path *under* a listed directory, which is what the reporter needs before the root is known?
  - Should the pre-resolution ignore check also accept glob patterns, consistent with `git.repositoryScanIgnoredFolders`, or stay with plain path entries?
  - Should `files.exclude` be documented as explicitly not affecting git repository detection (settings description update), or is honoring it considered desirable?

## Evidence

- **ordering confirmed in source:** extensions/git/src/model.ts `openRepository()` calls `this.getRepositoryRoot(repoPath)` (which runs git against the path) at ~line 617 and only then calls `this.shouldRepositoryBeIgnored(repositoryRoot)` at ~line 626 — so git is invoked on an ignored location before the ignore list is ever consulted.
- **matching semantics:** `shouldRepositoryBeIgnored` (model.ts ~line 740) uses `pathEquals` against the resolved repository *root* only (absolute entries, or workspace-folder-relative entries); it never matches a parent or child path, which explains reports where a listed path appears not to take effect.
- **detection entry point:** `onDidChangeVisibleTextEditors` (model.ts ~line 531) calls `openRepository(path.dirname(uri.fsPath))` for each visible editor when `git.autoRepositoryDetection` is `true`/`openEditors`, matching the reporter's step 5.
- **files.exclude:** `rg` over extensions/git/src finds no reference to `files.exclude` anywhere — the git extension has never consulted it, and the equivalent knobs are `git.ignoredRepositories`, `git.repositoryScanIgnoredFolders`, and `git.repositoryScanMaxDepth` (extensions/git/package.json).
- **related issue:** https://github.com/microsoft/vscode/issues/145066 is closed and was addressed by the `git.openRepositoryInParentFolders` setting; it covers parent-folder repositories, not ignore-list ordering, so it is not a canonical for this report.
