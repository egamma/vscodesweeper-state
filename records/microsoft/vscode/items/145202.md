# Issue #145202 — Timeline: support multi select commands

[https://github.com/microsoft/vscode/issues/145202](https://github.com/microsoft/vscode/issues/145202)

## Summary

The capability remains absent on current main: Timeline explicitly disables multiple selection and command invocation marshals only the focused item. The Backlog request should stay open for a decision about command compatibility and mixed-provider selection semantics.

## Change summary

Allow Timeline context-menu commands to operate on multiple selected entries, enabling bulk local-history deletion and comparison of two chosen versions.

## Best solution

Give the Timeline tree standard multi-selection behavior and expose the complete selection to contributed and built-in commands without breaking existing single-item handlers; then make Local History's Delete command perform one coherent bulk operation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/timeline/browser/timelinePane.ts`, `src/vs/workbench/api/common/extHostTimeline.ts`, `src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts`
- **Validation:** Create at least three local-history entries, select two with the platform multi-select modifier, invoke Delete from the selection's context menu, and verify both selected entries—and no unselected entry—are removed after a single coherent confirmation; also verify existing single-item Timeline commands still receive their expected argument.
- **Behavior:**

  > Timeline entries support standard keyboard and pointer multi-selection. Invoking a context-menu command on a selected entry makes the complete selection available, while single-item commands continue to work compatibly. Local History Delete can remove exactly the selected entries as one bulk operation, and selecting two versions can support an exact-pair comparison. Load-more rows and unselected entries must not enter the command selection.
- **Trace:**

  > TimelinePane in src/vs/workbench/contrib/timeline/browser/timelinePane.ts creates a WorkbenchObjectTree with `multipleSelectionSupport: false`. Its `onContextMenu` path resets focus to the clicked item and supplies one `{ uri, item }` context; TimelineActionRunner then marshals one handle/source tuple. src/vs/workbench/api/common/extHostTimeline.ts resolves that tuple into one extension TimelineItem, while Local History Delete in src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts accepts and removes one entry. Existing single-item command behavior is the compatibility boundary; the uncertainty begins at the selection's command-argument contract and whether selections may span Timeline providers. The narrower comparison request at https://github.com/microsoft/vscode/issues/117261 is closed and does not own this broader work.
- **Open decisions:**
  - Should contributed Timeline commands keep the focused item as their first argument and receive the full selection separately, or should the primary argument become a collection?
  - May one Timeline selection contain entries from different providers, and if so, how are context-menu applicability and provider-specific commands determined?
  - For destructive bulk commands such as Local History Delete, should the user receive one consolidated confirmation or confirmation per selected entry?
