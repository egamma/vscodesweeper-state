# Issue #159327 — Auto open Diff Editor when Refactor Preview is opened

[https://github.com/microsoft/vscode/issues/159327](https://github.com/microsoft/vscode/issues/159327)

## Summary

Keep open: current Refactor Preview still requires opening a tree entry to display the diff, and the request has met the community threshold for Backlog. The old implementation PR was closed without merging; the remaining work needs a UX decision about automatic editor opening in the current multi-diff experience.

## Change summary

Automatically display the first applicable diff when Refactor Preview opens, provide a file fallback when nothing is checked, and restore the preview editor when returning to the panel.

## Best solution

Resolve the discoverability-versus-distraction tradeoff with the workspace-edit and design owners, then establish consistent initial-opening and return-to-preview behavior for the current multi-diff editor. Preserve explicit confirmation and keep Apply/Discard discoverable.

- **Behavior:**

  > Users currently see the Refactor Preview panel without a diff until they open an entry. The requested experience automatically shows the first checked edit, falls back to the first file when nothing is checked, and restores the preview editor when returning to the panel after switching tabs. The plan must settle whether automatic presentation is appropriate and where keyboard focus remains. Acceptance must cover mixed and entirely unchecked edits without implicitly accepting confirmation-required changes, plus navigation back to the preview and unchanged Apply/Discard behavior.
- **Trace:**

  > BulkEditPreviewContribution._previewEdit in src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEdit.contribution.ts opens the view and delegates to BulkEditPane.setInput. In bulkEditPane.ts, _setTreeInput sets, focuses and expands the tree; editor opening occurs through the tree onDidOpen event and _openElementInMultiDiffEditor, which now constructs a multi-diff editor. BulkFileOperations in bulkEditPreview.ts initializes checked state from needsConfirmation metadata, and bulkEditPreview.test.ts covers selection behavior. Preserve confirmation state and the contribution's UXState restoration and preview-editor cleanup. https://github.com/microsoft/vscode/pull/159283 was closed unmerged because its per-file approach is obsolete. https://github.com/microsoft/vscode/issues/156886 supplies broader design context; uncertainty is the user-visible automatic-opening and focus contract raised in this issue's discussion, not implementation placement.
- **Open decisions:**
  - Should opening Refactor Preview automatically display the multi-diff editor, or retain explicit entry opening to keep attention on the full edit list and Apply/Discard controls?
