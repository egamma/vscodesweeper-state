# Issue #347566 — MCP App fails to load in Codespaces: "The Agent Host connection is no longer available" (GitHub MCP issue_write)

[https://github.com/microsoft/vscode/issues/347566](https://github.com/microsoft/vscode/issues/347566)

## Summary

Keep open: current source exposes an authority-resolution mismatch for editor-remote Agent Hosts, consistent with the Codespaces report and independent WSL confirmation. Main now waits for a connection during initial app loading, but waiting does not repair an authority that the connection service cannot resolve.

## Change summary

MCP App forms fail to load in remote Copilot agent-host sessions even though ordinary MCP operations continue working.

## Best solution

Ensure MCP App render data resolves to its owning editor-remote Agent Host in Codespaces and WSL, including after reconnects. Preserve local and separately registered remote-host routing, and verify resource loading and subsequent form submissions through the same owning connection.
