# Issue #107842 — onDidDispose is fired when view is moved

[https://github.com/microsoft/vscode/issues/107842](https://github.com/microsoft/vscode/issues/107842)

## Summary

Still reproducible on main: WebviewViewPane.dispose() fires _onDispose which cascades through mainThreadWebviewViews to fire the extension-facing onDidDispose when a view is merely moved between containers. No fix commit found.

## Change summary

WebviewView.onDidDispose incorrectly fires when a webview view is moved between containers, not only when the view is actually destroyed.

## Best solution

Guard the dispose-to-extension path so that a view move (pane teardown + recreation) does not fire $disposeWebviewView on the extension host. The fix likely involves distinguishing a move-triggered dispose from a real dispose in WebviewViewPane or in mainThreadWebviewViews.ts, similar to how the webviewView object's own `dispose` callback (line 221) already only clears the webview without disposing the container.
