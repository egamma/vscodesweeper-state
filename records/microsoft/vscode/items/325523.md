# Issue #325523 — Copilot chat shows ignored-files troubleshooting text in grep search tool completion UI

[https://github.com/microsoft/vscode/issues/325523](https://github.com/microsoft/vscode/issues/325523)

## Summary

Traced and confirmed in source: the grep-style no-matches path embeds internal LLM troubleshooting text directly into the user-facing `toolResultMessage`, unlike the tag-style path. A workaround exists (revert to `tag` output format) but the underlying code path is a real defect worth fixing since `grep` is now the default.

## Change summary

When a grep search returns no results, the chat completion UI shows internal agent-guidance text (about search.exclude/ignore files) instead of a brief user-facing 'no results' message.

## Best solution

In `renderGrepStyle`'s no-matches branch (extensions/copilot/src/extension/tools/node/findTextInFilesTool.tsx, around line 187), stop passing the full `noMatchInstructions` string into `errorResult`'s `toolResultMessage`; instead keep a short user-facing message there (mirroring `getResultMessage`'s 0-results case) and surface the troubleshooting guidance only to the model (e.g. via the tool result content/parts), matching how `renderTagStyle` already separates the LLM-facing prompt from the user-facing `toolResultMessage`.
