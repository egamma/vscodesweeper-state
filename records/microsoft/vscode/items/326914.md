# Issue #326914 — Agent Host BYOK doubles customendpoint URL path → 404

[https://github.com/microsoft/vscode/issues/326914](https://github.com/microsoft/vscode/issues/326914)

## Summary

The reporter experiences a real error when using a customendpoint BYOK model in Agent Host, but the described root cause (URL path doubling) does not match the actual code flow on current main — the Copilot SDK never receives the customendpoint URL directly; it talks to a local BYOK proxy at `http://127.0.0.1:<port>/v/<vendor>/chat/completions`, which forwards requests to the renderer's LM API via IPC. More information is needed to identify the actual failure point.

## Change summary

Using a customendpoint BYOK model (e.g. DeepSeek) in Agent Host sessions fails with a JSON parse error, while the same model works in Chat view.

## Best solution

The reporter's root cause analysis appears incorrect: tracing the code on `main`, `resolveByokSessionConfig` in `copilotSessionLauncher.ts` sets each BYOK provider's `baseUrl` to the local proxy URL (`handle.providerBaseUrl(vendor)` → `http://127.0.0.1:<port>/v/customendpoint`), not the customendpoint URL from `chatLanguageModels.json`. The SDK appends `/chat/completions` to the proxy URL, not to `api.deepseek.com`. The actual failure likely lies elsewhere — possibly a model resolution error in the renderer bridge, a streaming/non-streaming mismatch, or a version-specific issue. Trace-level logs from both the agent host process and the renderer's `AgentHostByokLmHandler` would pinpoint the real cause.
