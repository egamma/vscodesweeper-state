# Issue #172460 — Setting trim_trailing_whitespace = true breaks undo history

[https://github.com/microsoft/vscode/issues/172460](https://github.com/microsoft/vscode/issues/172460)

## Summary

Still present on main: the trim-trailing-whitespace save participant uses `model.pushEditOperations()`, which pushes onto the undo stack and clears the redo stack, so any pending redo operations are lost after save.

## Change summary

Saving a file with `files.trimTrailingWhitespace` enabled destroys the redo history because the trim edit is pushed onto the undo stack.

## Best solution

The save participant's trim operation should not interfere with the user's redo stack. This likely requires either applying the trim edits outside the undo stack (e.g. a silent/background edit mechanism) or grouping the trim with the preceding user edit so redo can restore both. The fix is in `src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts`, method `doTrimTrailingWhitespace`.
