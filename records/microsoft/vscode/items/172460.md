# Issue #172460 — Setting trim_trailing_whitespace = true breaks undo history

[https://github.com/microsoft/vscode/issues/172460](https://github.com/microsoft/vscode/issues/172460)

## Summary

This remains a credible undo/redo correctness bug: save-time trailing-whitespace edits invalidate redo history, and a 2025 report confirms a related document-synchronization symptom on VS Code 1.99. The existing `bug` classification also bars a judgment close, and there is no verified fix or canonical duplicate.

## Change summary

Saving with trailing-whitespace trimming enabled clears redoable edits and can leave custom editor content out of sync with the underlying text document.

## Best solution

Preserve coherent undo/redo and text-document change semantics when save participants trim trailing whitespace, likely in the save-participant/editor-model path; first determine whether the custom-editor missing-event symptom is the same core transaction defect or a separate API contract issue.

Investigation should trace trailing-whitespace edits from src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts through text-model undo grouping and src/vs/platform/undoRedo/common/undoRedoService.ts, then check document-change propagation to custom editors.
