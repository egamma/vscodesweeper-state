# Issue #172460 — Setting trim_trailing_whitespace = true breaks undo history

[https://github.com/microsoft/vscode/issues/172460](https://github.com/microsoft/vscode/issues/172460)

## Summary

This is the intended consequence of VS Code's linear undo/redo model: trimming on save creates a new document edit, which invalidates the existing redo branch. Maintainers previously evaluated the same behavior and closed it as designed.

## Change summary

Preserve pending redo operations when saving trims trailing whitespace from the document.

## Best solution

Retain the current linear undo/redo semantics for save-participant edits. Supporting this request would require a broader product and architecture decision around parallel redo histories or non-document save transformations, rather than a narrow trim-whitespace fix.
