# Issue #348353 — Markdown preview highlights hyphenated path as PowerShell parameter

[https://github.com/microsoft/vscode/issues/348353](https://github.com/microsoft/vscode/issues/348353)

## Summary

Keep open: the built-in Markdown preview delegates highlighting to highlight.js, whose PowerShell grammar matches embedded hyphens as parameter-like tokens. The supplied example is sufficient to investigate; this is an upstream grammar issue, not evidence of an installed extension causing the problem.

## Change summary

Prevent the PowerShell Markdown highlighter from coloring the embedded -copy in an unquoted path like a parameter.

## Best solution

Correct highlight.js's PowerShell argument recognition so embedded path hyphens remain unclassified while actual parameters retain their highlighting, then consume the upstream fix in VS Code's Markdown preview.

## Evidence

- **Built-in rendering path:** extensions/markdown-language-features/src/markdownEngine.ts: getMarkdownOptions imports highlight.js and passes the fenced source directly to hljs.highlight with language: lang and ignoreIllegals: true. Preview highlighting therefore uses highlight.js rather than extensions/powershell/syntaxes/powershell.tmLanguage.json.
- **Bundled dependency:** extensions/markdown-language-features/package.json declares highlight.js ^11.8.0; the corresponding pnpm-lock.yaml importer resolves it to 11.8.0.
- **Upstream cause:** https://github.com/highlightjs/highlight.js/blob/11.8.0/src/languages/powershell.js defines PS_ARGUMENTS with className: 'literal' and begin: /(-){1,2}[\w\d-]+/, without a preceding token boundary. This matches -copy inside working-copy and assigns the same class used for genuine parameters.
