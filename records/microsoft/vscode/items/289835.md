## Evidence

- **Controlled reproduction:** https://github.com/microsoft/vscode/issues/289835#issuecomment-5180005550 reports repeated bidirectional experiments on 1.131.0: changing only the stored drive letter from uppercase to lowercase eliminates the trust prompt and SSH timeout, with fsPath and _sep absent in both cases. This explicitly retracts the earlier missing-fsPath diagnosis.
- **Independent confirmation:** https://github.com/microsoft/vscode/issues/289835#issuecomment-5276251865 confirms the same symptom on 1.133.0 with a Linux client and Windows SSH host. It also reports silently reverting Manage Workspace Trust edits and clarifies that the timeout notification can be queued behind the modal; the modal causing the timeout is not established.
- **Current matching behavior:** src/vs/workbench/services/workspaces/common/workspaceTrust.ts:369-407 matches grants through extUri.isEqualOrParent before reading fsPath for longest-match selection. src/vs/base/common/resources.ts:171-180 compares non-file URI paths using the provider-derived casing rule. src/vs/platform/uriIdentity/common/uriIdentityService.ts initially treats paths as case-sensitive when no provider exists.
- **Current persistence and recovery paths:** workspaceTrust.ts:636-638 awaits every getCanonicalUri before saving a grant; setTrustedUris clears the in-memory list before awaiting canonicalization. src/vs/platform/remote/electron-browser/remoteAuthorityResolverService.ts caches canonical-URI DeferredPromises, including failed requests, while _clearResolvedAuthority clears only authority-resolution requests. These paths support the reported inability to repair trust after remote resolution fails.
- **Diagnosis boundary:** UriIdentityService still contains the always-true comparison newIgnorePathCasingValue === newIgnorePathCasingValue, preventing canonical-map invalidation. However, it refreshes the casing-policy cache before that comparison, so this typo alone does not prove the entire trust failure. WorkspaceTrustUXHandler in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts waits for workspaceTrustInitialized before showing the startup modal; the proposed early-modal causal chain requires further investigation.
