# Issue #332666 — `read_file` does not report whether a line-range read reached EOF

[https://github.com/microsoft/vscode/issues/332666](https://github.com/microsoft/vscode/issues/332666)

## Summary

Traced in the current source: the `read_file` tool's response only ever includes an explicit "Lines X to Y (Z lines total)" header when the requested range does NOT reach the end of the file (or is truncated by a default page limit) — precisely the opposite of what's needed to signal EOF. When a range does reach or exceed the file's actual end, no header and no total-line-count metadata is emitted at all, so the model genuinely cannot distinguish "this is the whole file" from "this stopped at an arbitrary token budget cutoff." This matches the reporter's transcript exactly.

## Change summary

The Copilot `read_file` tool gives no explicit signal in its response for whether a requested line range reached or exceeded end-of-file, forcing agents to probe repeatedly to locate the end of a file (e.g. for append workflows).

## Best solution

In extensions/copilot/src/extension/tools/node/readFileTool.tsx, make `ReadFileResult.render()` always surface the total line count and an explicit end-of-file signal (not gated on the `useCodeFences` experiment flag or on `truncated`), and consider adding a small structured marker like `reachedEndOfFile`/`totalLines` to the returned content so append-at-EOF workflows become deterministic instead of inferential.
