# Issue #332666 — `read_file` does not report whether a line-range read reached EOF

[https://github.com/microsoft/vscode/issues/332666](https://github.com/microsoft/vscode/issues/332666)

## Summary

Confirmed real gap in current main: the read_file tool's response only ever surfaces total-line/EOF information via an internal, off-by-default experiment flag, and even then only when the read did NOT reach EOF — so the common case (reading to end of file) returns no structured signal distinguishing 'reached EOF' from 'more content exists'. Routing to the Copilot tools area as a legitimate contract enhancement.

## Change summary

Requests that the built-in read_file tool return structured metadata (e.g. reachedEndOfFile, totalLines) so callers can deterministically detect end-of-file instead of inferring it from line counts.

## Best solution

In extensions/copilot/src/extension/tools/node/readFileTool.tsx, ReadFileResult.render() (around line 462) should unconditionally include end-of-file/total-line information rather than gating it behind the ConfigKey.TeamInternal.ReadFileCodeFences experiment flag (default false) and the inverted condition that currently hides it precisely when the read reaches EOF; ideally surface it as structured tool-result metadata rather than only prose text so agents can rely on it programmatically.
