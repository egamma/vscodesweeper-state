# Issue #332666 — `read_file` does not report whether a line-range read reached EOF

[https://github.com/microsoft/vscode/issues/332666](https://github.com/microsoft/vscode/issues/332666)

## Summary

Confirmed in source: the built-in read_file tool's default response carries no structured EOF/total-line signal, only an experimental, disabled-by-default header — so this is a real, unaddressed gap worth routing to the chat/tools area rather than closing.

## Change summary

Requests that the `read_file` tool return structured metadata (e.g. `reachedEndOfFile`, `totalLines`) so agents can reliably detect end-of-file instead of guessing from returned content.

## Best solution

In extensions/copilot/src/extension/tools/node/readFileTool.tsx, promote the existing 'Lines X to Y (Z lines total)' header logic (currently gated behind the disabled-by-default `chat.advanced.readFileCodeFences` experiment, ReadFileResult.render around line 557-562) into an always-present, structured signal — e.g. an explicit reached-EOF/total-line indicator returned on every V1 and V2 read_file call, not just when useCodeFences is on.
