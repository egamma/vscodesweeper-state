# Issue #250506 — Incomplete highlighting after switching themes

[https://github.com/microsoft/vscode/issues/250506](https://github.com/microsoft/vscode/issues/250506)

## Summary

Still open on main — the tree-sitter theme-change code path in TreeSitterTokenizationImpl._updateTheme() marks the full range for refresh and re-tokenizes the viewport, but incomplete highlighting after rapid theme switching suggests a race or stale-quality-check issue in the viewport tokenization loop. No fix commit found.

## Change summary

Tree-sitter-based syntax highlighting shows incomplete coloring after switching between built-in themes.

## Best solution

Investigate whether _parseAndTokenizeViewPort's early-exit at `_rangeHasTokens(range, TokenQuality.ViewportGuess)` (line 236 of treeSitterTokenizationImpl.ts) fires before `_markForRefresh` fully invalidates the store, causing the viewport to skip re-tokenization after a theme change. The fix likely lives in the interaction between `_updateTheme()`, `_markForRefresh()`, and the viewport tokenization loop in `src/vs/editor/common/model/tokens/treeSitter/treeSitterTokenizationImpl.ts`.
