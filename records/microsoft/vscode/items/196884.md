# Issue #196884 — Cannot replace with positive lookbehind including `\n`

[https://github.com/microsoft/vscode/issues/196884](https://github.com/microsoft/vscode/issues/196884)

## Summary

The bug remains on main: single replace skips a selected multiline-regex match when its lookbehind needs text from the preceding line. The existing editor-find routing is correct.

## Change summary

Single replace fails for matches using a positive lookbehind containing `\n`, while replace-all succeeds.

## Best solution

Make multiline `findNextMatch` preserve sufficient preceding context for lookbehind while still returning only matches at or after the requested position, then cover single-replace behavior with regression tests.

## Evidence

- **source reproduction:** `src/vs/editor/common/model/textModelSearch.ts` classifies `(?<=\n)b` as multiline, but `_doFindNextMatchMultiline` constructs its search text beginning at column 1 of the current line. At line 2 this removes the preceding newline required by the lookbehind, so the search advances to a later match.
- **single-replace path:** `src/vs/editor/contrib/find/browser/findModel.ts` uses `_getNextMatch(selection.getStartPosition(), true, false)` and replaces only when that result equals the selection. Because `findNextMatch` returns the following line's match, single replace selects the next occurrence instead.
- **replace-all contrast:** `FindModelBoundToEditorModel._regularReplaceAll` calls `findMatches` over the full search range, which retains preceding-line context and therefore explains why replace-all works.
