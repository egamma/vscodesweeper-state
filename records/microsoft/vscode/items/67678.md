# Issue #67678 — Auto-indent on closing brace

[https://github.com/microsoft/vscode/issues/67678](https://github.com/microsoft/vscode/issues/67678)

## Summary

Keep this accepted, well-supported request open: current automatic indentation adjusts the typed line, not the existing contents of a newly enclosed block. Manual reindent commands and provider-dependent formatting are partial workarounds, and the checked related issues do not own this same request.

## Change summary

Automatically reindent existing code when typing the closing brace of a block added around it.

## Best solution

Support indentation-only adjustment of newly enclosed block contents, honoring the document's indentation settings without requiring unrelated formatting changes. Plan the editor autoindent behavior with the maintainer, including its activation and language scope.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/indentation/test/browser/indentation.test.ts`
- **Validation:** Add an editor typing regression case that starts with existing TypeScript statements, adds enclosing braces, and types the final closing brace; assert that the enclosed statements gain the appropriate indentation while the closing brace aligns with its opener. Cover tabs and spaces, nested relative indentation, unchanged non-whitespace content, and the agreed disabled-setting behavior. Supplement with an explicit manual JavaScript/TypeScript check with format-on-type disabled.
- **Behavior:**

  > When a user adds a brace-delimited block around existing code and types its closing brace, the enclosed statements should acquire the indentation appropriate to that block. Respect the document's indentation settings and preserve nested relative indentation and non-whitespace content. Acceptance must distinguish block-content indentation from merely aligning the closing brace, without depending on format-on-save or unrelated formatter edits. Activation and supported-language scope need agreement before implementation.
- **Trace:**

  > getIndentActionForType in src/vs/editor/common/languages/autoIndent.ts computes a single indentation string, and AutoIndentOperation in src/vs/editor/common/cursor/cursorTypeEditOperations.ts turns it into an edit on the typed line for an ordinary empty selection. That establishes the missing editor-autoindent capability, but does not establish the safest implementation boundary for reindenting an enclosing range. Explicit reindent commands exist in src/vs/editor/contrib/indentation/browser/indentation.ts; format-on-type instead delegates to a language provider, with JavaScript/TypeScript forwarding to TypeScript's formatonkey request. Preserve intentional indentation outside the affected block and do not broaden this into whole-document formatting. The related https://github.com/microsoft/vscode/issues/66235 concerns Enter alignment, not this trigger. No runtime verification was performed in the read-only checkout.
- **Open decisions:**
  - Should closing-brace block reindentation be part of editor.autoIndent=full, or require a separate opt-in?
  - Should the initial behavior apply to JavaScript/TypeScript brace blocks only, or to brace-delimited blocks across configured languages?
