# Issue #344616 — Add opt-in setting to keep Primary Side Bar visible when maximizing Secondary Side Bar

[https://github.com/microsoft/vscode/issues/344616](https://github.com/microsoft/vscode/issues/344616)

## Summary

Keep open for community review: current maximization still hides Explorer, and no existing setting covers the requested opt-in behavior. The related open request covers reopening the Primary Side Bar, not preserving an already-visible one during maximization.

## Change summary

Allow Secondary Side Bar maximization to optionally preserve the Primary Side Bar and its width while hiding the editor and retaining layout restoration.

## Best solution

Evaluate an opt-in layout mode that preserves project navigation during Secondary Side Bar maximization without changing the default behavior. Coordinate its toggle semantics with https://github.com/microsoft/vscode/issues/300729 while retaining this request's additional maximize-time requirements.

## Evidence

- **Current maximize behavior:** src/vs/workbench/browser/layout.ts:2179–2243, setAuxiliaryBarMaximized(), records the previous layout and unconditionally calls setSideBarHidden(true) when the Primary Side Bar was visible. The requested initial two-sidebar layout is therefore not supported by this path.
- **Existing capabilities checked:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.secondarySideBar.defaultVisibility and workbench.secondarySideBar.forceMaximized; neither preserves the Primary Side Bar. src/vs/workbench/browser/parts/auxiliarybar/auxiliaryBarActions.ts routes workbench.action.maximizeAuxiliaryBar and workbench.action.toggleMaximizedAuxiliaryBar through the same layout implementation. workbench.action.toggleEditorVisibility instead toggles panel maximization and does not provide the requested behavior.
- **Related open issue is narrower:** https://github.com/microsoft/vscode/issues/300729 is open and requests keeping the editor hidden when opening the Primary Side Bar after Secondary Side Bar maximization. Its April 6 clarification confirms that scope. It does not cover preserving an already-visible Primary Side Bar during the initial maximize operation or the requested opt-in configuration, so it does not absorb this re-reviewed item's full scope.
