# Issue #336241 — Copilot hangs on screenshot / image viewing

[https://github.com/microsoft/vscode/issues/336241](https://github.com/microsoft/vscode/issues/336241)

## Summary

Thanks for the very detailed report and logs. I traced a plausible concrete cause in the current source: `CopilotAgent.onClientToolCallComplete` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts) silently drops the completion via `target?.handleClientToolCallComplete(...)` with no logging or fallback when `_findChatByUri`/`_findSessionChat` fail to resolve a live SDK session entry for the chat — this matches the observed symptom of a successfully-forwarded completion that the session never acts on, with no error surfaced. This is a real, reproducible-in-source defect but the exact trigger (e.g. idle chat eviction racing a long-running client tool like screenshotPage) isn't fully confirmed, so it should stay open and be routed to the agent host owners rather than closed.

## Change summary

Copilot Chat agent/CLI turns sometimes hang indefinitely after a client tool call completes because the session never processes the completion acknowledgment, with no timeout or error surfaced.

## Best solution

In `CopilotAgent.onClientToolCallComplete` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts, around line 4142), add logging and a safe fallback when `target` is undefined — e.g. warn loudly and/or attempt to re-materialize the cold chat before dropping the completion — instead of silently swallowing it via `target?.`; a maintainer with full context on the multi-chat/eviction lifecycle should confirm the actual trigger (likely a chat evicted/cold between tool dispatch and completion) before landing a fix.

## Evidence

- **silent-drop code path:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:4142-4148 — `onClientToolCallComplete` resolves `target` via `_findChatByUri`/`_findSessionChat` and calls `target?.handleClientToolCallComplete(toolCallId, result)`; if no live chat entry is found, the completion is dropped with zero logging, zero retry, and zero surfaced error.
- **lookup miss mechanism:** `_findChatByUri` (copilotAgent.ts:3115-3119) requires a live `_chatEntriesBySdkId` entry keyed by SDK session id; a chat backing can exist while its live entry is absent (e.g. cold/evicted chat), which is exactly a scenario that would produce the reported symptom of a logged 'Forwarding client tool completion ... success=true' with no paired 'Tool completed' log ever following.
- **buffering only helps live entries:** `handleClientToolCallComplete` (copilotAgentSession.ts:2359) uses `_pendingClientToolCalls.respondOrBuffer`, which is well-designed for races on a *live* session, but it is never reached at all if `onClientToolCallComplete` can't resolve `target` in the first place.
- **related but distinct reports:** https://github.com/microsoft/vscode/issues/321432 covers a different mechanism (no idle timeout on the SSE read loop for a stalled streaming response), not the client-tool-completion routing gap traced here — related area but not verified as the same root cause, so not proposed as a duplicate.
