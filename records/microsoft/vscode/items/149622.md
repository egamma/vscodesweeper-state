# Issue #149622 — Git - After VSCode is updated, git@github.com: Permission denied (publickey).

[https://github.com/microsoft/vscode/issues/149622](https://github.com/microsoft/vscode/issues/149622)

## Summary

Keep open: reporters confirmed SSH authentication failures after updates, including cases where an external terminal works but VS Code does not. The workaround was already found insufficient and the issue reopened; neither a verified fix nor a canonical covering the update-triggered failure was established.

## Change summary

Git operations lose access to working SSH authentication after VS Code updates or restarts.

## Best solution

Identify why the update/relaunch environment differs from the working external shell, then preserve access to the existing SSH agent for both integrated-terminal and Source Control operations. Separate the Windows HOME and remote-environment reports if diagnosis establishes distinct causes.

- **Trace:**

  > Git.spawn in extensions/git/src/git.ts inherits the extension host process environment and merges overrides; main.ts obtains GUI authentication overrides from Askpass.getEnv in askpass.ts. getResolvedShellEnv in src/vs/platform/shell/node/shellEnv.ts resolves and caches an interactive login-shell environment on macOS/Linux, but skips ordinary CLI launches; src/vs/code/electron-main/app.ts invokes that resolution. ## Evidence

- **Original reproduction and insufficient workaround:** https://github.com/microsoft/vscode/issues/149622#issuecomment-1127398776 shows ssh-add restoring git pull with an id_ed25519 key. The reporter subsequently confirmed that the workaround must be repeated after every update at https://github.com/microsoft/vscode/issues/149622#issuecomment-1127843808. This does not establish a permanent fix, and the issue is reopened.
- **Independent confirmation:** https://github.com/microsoft/vscode/issues/149622#issuecomment-1835558573 reports failure in both Source Control and the integrated terminal on macOS with VS Code 1.84.2, while a separate terminal succeeds. Other supplied comments confirm GUI-only failures and recurrence across releases. These are credible historical reproductions, not a current-main runtime verification.
- **Maintainer diagnostic distinction:** https://github.com/microsoft/vscode/issues/149622#issuecomment-1254803936 asks about Stable versus Insiders and Git: Pull. https://github.com/microsoft/vscode/issues/149622#issuecomment-1833422806 distinguishes general Git configuration failures from VS Code-specific failures; the external-terminal success reports prevent treating the entire issue as a configuration question.
- **Current source boundary:** extensions/git/src/git.ts, Git.spawn, inherits process.env and merges extension and invocation overrides before spawning Git; it does not independently select SSH key filenames. extensions/git/src/main.ts supplies Askpass.getEnv(), and extensions/git/src/askpass.ts sets SSH_ASKPASS and SSH_ASKPASS_REQUIRE for GUI operations. src/vs/platform/shell/node/shellEnv.ts, getResolvedShellEnv, caches shell environment resolution, skips it for ordinary CLI launches and Windows, and otherwise invokes an interactive login shell. These identify relevant environment boundaries but do not conclusively reproduce an update-specific defect.
- **Canonical checked, different established trigger:** https://github.com/microsoft/vscode/issues/57488 was verified open. Its maintainer diagnosis at https://github.com/microsoft/vscode/issues/57488#issuecomment-417259290 identifies a Linux desktop launcher invoking the CLI entry point and bypassing shell-environment resolution. That is a useful related diagnosis, but this report has not been tied to that cause, and its macOS update-triggered integrated-terminal failure is not established as covered.
- **Additional reports are not one proven root cause:** https://github.com/microsoft/vscode/issues/149622#issuecomment-1926794210 describes a Windows custom-HOME configuration and links several related reports. The supplied discussion also includes network-drive, WSL and Dev Container workarounds. These leads should not be treated as proof that one configuration change fixes the original macOS update regression.
