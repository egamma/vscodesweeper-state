# Issue #266341 — Accepting NES moves text a bit

[https://github.com/microsoft/vscode/issues/266341](https://github.com/microsoft/vscode/issues/266341)

## Summary

The movement remains explainable on current main: NES renders the proposed insertion as injected text with inline left/right borders, then acceptance replaces it with ordinary text without those metric-affecting borders. Although the rendering compromise is intentional, the source explicitly marks the inline border as something to replace with an overlay, so this remains a valid bounded polish item.

## Change summary

Accepting a single-line next edit suggestion causes surrounding text to shift slightly as the decorated preview becomes ordinary editor text.

## Best solution

Render the insertion outline without changing the injected text's horizontal metrics, while retaining the border separation from neighboring characters; the existing source TODO points to an overlay-widget treatment like the deletion view.
