# Issue #147905 — View badge can get stale

[https://github.com/microsoft/vscode/issues/147905](https://github.com/microsoft/vscode/issues/147905)

## Summary

Team-authored bug (bpasero, CONTRIBUTOR) on the On Deck milestone — keeping open per policy. The described badge staleness when moving views between sidebars involves the interplay between ViewContainerActivityByView, composite bar badge rendering, and container-change events. While the activity service has onDidChangeContainer/onDidChangeLocation listeners, there may be a remaining timing or rendering issue in how the composite bar refreshes badges after a view container move.

## Change summary

View badge (e.g. SCM pending changes count) can become stale when a view is moved between the primary sidebar and secondary sidebar, or when changes are discarded after such a move.

## Best solution

Investigate the badge refresh path in the composite bar when a view container is moved — likely in how the activity bar's composite bar action items listen to onDidChangeActivity for containers that gain or lose views. The fix likely lives in the pane composite part or composite bar actions where badge rendering reacts to container changes. Files: src/vs/workbench/browser/parts/compositeBarActions.ts, src/vs/workbench/services/activity/browser/activityService.ts.
