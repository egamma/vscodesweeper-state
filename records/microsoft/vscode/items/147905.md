# Issue #147905 — View badge can get stale

[https://github.com/microsoft/vscode/issues/147905](https://github.com/microsoft/vscode/issues/147905)

## Summary

The recorded reproduction shows a real stale-badge defect after moving the SCM view, and no canonical issue or concrete fixing commit was found. Current source intends to relocate and dispose view activity, but there is no regression test proving this move-and-clear sequence works, so the issue should remain open pending current-build reproduction and diagnosis.

## Change summary

Moving the SCM Changes view between side bars can leave its activity badge showing a stale change count after the changes are discarded.

## Best solution

Ensure view-scoped activity follows its view across generated containers and is removed from every former and current container when the SCM count reaches zero, covered by a regression test exercising move, update, and disposal.

- **Behavior:**

  > An SCM change-count badge must follow the SCM Changes view when that view moves between the primary and secondary side bars. After the final change is discarded, no badge may remain on either the old or current activity icon. Repeated moves must not duplicate the activity, and ordinary SCM badge updates without view movement must remain unchanged.
- **Trace:**

  > SCMActiveRepositoryController in src/vs/workbench/contrib/scm/browser/activity.ts owns the count activity and clears it through the disposable returned by IActivityService.showViewActivity.
