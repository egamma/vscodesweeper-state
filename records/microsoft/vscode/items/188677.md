# Issue #188677 — Inconsistent column number due to unicode symbols between command palette and status bar (+ inconsistent with Chrome and Firefox Devtools)

[https://github.com/microsoft/vscode/issues/188677](https://github.com/microsoft/vscode/issues/188677)

## Summary

Still reproduces on main: `toStatusbarColumn` in `cursorColumns.ts` counts Unicode code points uniformly (+1 each), while `visibleColumnFromColumn` uses grapheme iteration with full-width/emoji awareness (+2), and the editor's internal column is UTF-16 offset-based — three different counting systems yield different numbers for the same cursor position when Unicode emoji or flag sequences are present. The internal inconsistency the reporter describes is real and unfixed.

## Change summary

Unicode emoji and flag sequences cause inconsistent column numbers between the status bar, Go to Line command palette, and the editor's internal position, and none match JavaScript engine column numbers.

## Best solution

Unify the column-counting semantics across status bar display (`toStatusbarColumn`), the Go to Line quick access provider, and the editor's internal column, ideally aligning with JavaScript engine (V8/SpiderMonkey) column numbering for JS/TS files. The root is in `src/vs/editor/common/core/cursorColumns.ts` — `toStatusbarColumn` uses `CodePointIterator` while `visibleColumnFromColumn` uses `GraphemeIterator` with full-width awareness. Issue https://github.com/microsoft/vscode/issues/254382 is a recent duplicate that should be consolidated here.

## Evidence

- **source trace:** `toStatusbarColumn` at `src/vs/editor/common/core/cursorColumns.ts:61-77` uses `CodePointIterator` and counts every non-tab code point as +1. `visibleColumnFromColumn` at the same file line 41-55 uses `GraphemeIterator` and counts full-width/emoji as +2. The editor's internal column is 1-based UTF-16 offset. These three systems diverge for multi-code-point emoji like flag sequences (🇩🇪 = 2 code points = 4 UTF-16 code units = 1 grapheme cluster).
- **no fix on main:** git log on `src/vs/editor/common/core/cursorColumns.ts` shows no changes addressing this inconsistency since the issue was filed.
- **related open issue:** https://github.com/microsoft/vscode/issues/254382 (July 2025) reports the same class of bug with full-width and emoji characters in the status bar column count, labeled `bug` + `editor-core`.
- **prior fix was partial:** https://github.com/microsoft/vscode/issues/34497 (2017, closed October 2019) fixed the emoji column count by switching from UTF-16 to code-point counting in the status bar, but did not address the inconsistency between status bar, Go to Line, and JS engine columns that this issue reports.
