# Issue #334196 — Agent Host logs superseded turn-changeset subscriptions as Resource not found

[https://github.com/microsoft/vscode/issues/334196](https://github.com/microsoft/vscode/issues/334196)

## Summary

The misleading error is directly reproducible from current source: an expected pending-subscription cancellation is converted to AHP_SESSION_NOT_FOUND and logged as an error. The issue remains necessary and is bounded enough for implementation.

## Change summary

Superseding a pending per-turn changeset subscription can produce repeated misleading “Resource not found” errors during Agent Host session hydration.

## Best solution

Represent superseded subscription work as an expected cancellation, preserve real missing-resource failures, and prevent the request dispatcher from logging the cancellation as an error.

- **Behavior:**

  > When a pending Agent Host subscription is superseded or explicitly unsubscribed, it must be treated as expected cancellation rather than a missing resource. The server must not emit a misleading “Resource not found” error log for that cancellation. Genuine missing resources must retain their current not-found response and logging behavior, and the replacement subscription must still succeed.
- **Trace:**

  > AgentHostLastTurnChangeset in src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionChangesets.ts derives its changeset URI from the latest hydrated chat turn; changing that URI disposes the prior subscription. ProtocolServerHandler._removeSubscription deletes the pending identity, AgentService.subscribe or ProtocolServerHandler's post-await guard then throws `Subscription cancelled`, and the subscribe catch in src/vs/platform/agentHost/node/protocolServerHandler.ts converts that non-ProtocolError into AHP_SESSION_NOT_FOUND. `_handleRequest` consequently logs it at error level. The existing `cancelled subscribe does not clean up a newer subscribe from the same client` test establishes the exact race boundary. Keep actual absent-resource behavior and replacement-subscription ownership unchanged; this issue is only about expected cancellation classification and logging.

## Evidence

- **confirmed source path:** src/vs/platform/agentHost/node/protocolServerHandler.ts installs a pending subscription identity; unsubscribe removes it, after which the subscribe path throws `Subscription cancelled`. Its catch block preserves only ProtocolError and converts every other failure to AHP_SESSION_NOT_FOUND with `Resource not found`, while `_handleRequest` logs that failure at error level.
- **triggering UI lifecycle:** src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionChangesets.ts derives the Last Turn Changes URI from the latest chat and turn, registers the corresponding subscription with `reader.store`, and therefore disposes the old subscription whenever hydration changes the selected turn.
