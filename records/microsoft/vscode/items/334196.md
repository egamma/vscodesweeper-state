# Issue #334196 — Agent Host logs superseded turn-changeset subscriptions as Resource not found

[https://github.com/microsoft/vscode/issues/334196](https://github.com/microsoft/vscode/issues/334196)

## Summary

Team-authored diagnosis holds up against the code: the `subscribe` request handler's catch block in protocolServerHandler.ts converts any non-ProtocolError — including the internal `Subscription cancelled` error thrown when a pending subscription is superseded — into `AHP_SESSION_NOT_FOUND`/`Resource not found`, and that error is then logged at `error` level. This keeps the issue open pending a fix; author being a collaborator doesn't change the outcome since no fix commit exists yet.

## Change summary

During session hydration, superseded per-turn changeset subscriptions are logged as 'Resource not found' errors instead of being recognized as benign cancellations.

## Best solution

In protocolServerHandler.ts's `subscribe` handler (around lines 1492-1516), distinguish a genuine 'Subscription cancelled' failure (thrown when `client.subscriptions.get(classified.uri) !== pendingSubscription`) from an actual missing-resource failure before converting to `ProtocolError(AHP_SESSION_NOT_FOUND, ...)`, and skip/soften the error-level log for the cancellation case — mirroring how the reconnect path (`_reconnect`, ~line 976) already logs a superseded subscription at `info` level instead of `error`.
