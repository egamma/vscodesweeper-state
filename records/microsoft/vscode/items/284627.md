# Issue #284627 — Allow agent skill scripts to retrieve the workspace root/workspace file

[https://github.com/microsoft/vscode/issues/284627](https://github.com/microsoft/vscode/issues/284627)

## Summary

A real gap remains: workspace folders are described to the model and new agent shells start in the primary working directory, but scripts receive no stable workspace-context contract after the model changes directories. The issue is already correctly routed and should remain open for a small public-contract design.

## Change summary

Provide agent skill scripts with deterministic access to the originating workspace root or workspace file, independent of the shell's current directory.

## Best solution

Define a session-scoped workspace-context contract available to skill-launched processes, with explicit single-folder and multi-root semantics, and keep the workspace prompt concise enough that agents do not need custom skill instructions to forward paths.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotShellTools.ts`, `src/vs/platform/agentHost/node/agentHostTerminalManager.ts`, `src/vs/platform/agentHost/test/node/copilotShellTools.test.ts`, `src/vs/platform/agentHost/test/node/agentHostTerminalManager.test.ts`, `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx`
- **Validation:** Extend the agent-host shell/terminal tests to launch a session-scoped shell, change its cwd, and assert that the agreed workspace-context contract still identifies the original workspace; add the agreed multi-root case and verify unrelated client terminals do not inherit session-specific values.
- **Behavior:**

  > A script invoked by an agent skill can deterministically discover the workspace context selected for that agent session without relying on the process cwd or on the model supplying an argument. The value remains stable after the model changes directories. Single-folder and multi-root workspaces expose the semantics selected by the maintainer, while workspaceless sessions do not claim a workspace. Existing ordinary terminal environments remain unchanged.
- **Trace:**

  > The extension prompt currently renders workspace folders through WorkspaceFoldersHint in extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx, while AgentTasksInstructions separately emits detailed task definitions. For Agent Host Copilot sessions, createShellTools in src/vs/platform/agentHost/node/copilot/copilotShellTools.ts acquires a persistent shell whose initial cwd comes from ShellManager. AgentHostTerminalManager.createTerminal in src/vs/platform/agentHost/node/agentHostTerminalManager.ts builds that shell's environment from process.env and fixed agent-terminal variables, with no workspace-context value; therefore changing cwd loses the only process-readable indication of the original root. Keep the scope to agent-owned process execution and its prompt contract: do not alter ordinary integrated terminals or infer workspace ownership from a skill's installation directory. The maintainer discussion at https://github.com/microsoft/vscode/issues/284627#issuecomment-3713834534 also identifies the verbose task payload as adjacent prompt work, but whether that changes in this slice depends on the chosen contract.
- **Open decisions:**
  - What stable public contract should scripts consume: one or more environment variables, a required invocation argument, or another session-provided mechanism?
  - For a multi-root workspace, should the contract expose the primary folder, the .code-workspace file, the complete ordered folder list, or a combination of these?
  - Must the contract behave identically across every agent harness and shell execution path, or is the first supported scope limited to VS Code's Copilot Agent Host terminals?
  - Should this change also replace the detailed task definitions in workspace_info with a concise tasks.json reference, or should that prompt cleanup remain separate?

## Evidence

- **current prompt:** extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx renders WorkspaceFoldersHint inside workspace_info, so paths are model context rather than a process-level contract; AgentTasksInstructions still embeds task definitions under workspaceFolder elements.
- **shell behavior:** src/vs/platform/agentHost/node/copilot/copilotShellTools.ts creates a shell with the session working directory as its initial cwd, but persistent shell state allows later commands and skill scripts to run after the model has changed directories.
