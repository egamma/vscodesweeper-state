# Issue #180869 — [Bug] cursorHome and cursorEnd keybind for filter in problem view does not work if view is in bottom panel 

[https://github.com/microsoft/vscode/issues/180869](https://github.com/microsoft/vscode/issues/180869)

## Summary

Still reproduces on current main: the ActionBar keydown handler unconditionally captures Home/End keys before they reach the filter input, preventing standard cursor navigation. No fix has landed.

## Change summary

Home and End keys in the Problems filter input (when in the bottom panel) are swallowed by the ActionBar, preventing cursor navigation.

## Best solution

Register Home/End as proper keybinding commands with appropriate `when` clauses (similar to how lists handle them), so they don't fire when an input element has focus. The fix belongs in `src/vs/base/browser/ui/actionbar/actionbar.ts` — the keydown handler should check whether the event target is an input/textarea before consuming Home/End.
