# Issue #253517 — More options when opening vscode:chat-prompt links in VS Code

[https://github.com/microsoft/vscode/issues/253517](https://github.com/microsoft/vscode/issues/253517)

## Summary

A real capability gap remains on current main: external prompt links still require creating a persistent file before opening it. This team-authored Backlog request should remain open under discussion because the user-visible meaning and scope of “Add to Chat” have not been settled.

## Change summary

Offer non-persistent ways to open externally linked prompt content in an editor or place it into the chat composer without running it.

## Best solution

Extend the prompt-link confirmation flow with safe, explicit choices to install the prompt, open its content in an unsaved editor, or place it in the chat composer without submitting it. Preserve the existing warning and require a separate user action before any prompt executes.

## Vision fit

- **Fit:** aligned
- **Reason:** Reducing friction for safely adopting shared prompts advances VS Code's AI-assisted development and core UX themes without requiring automatic execution.
- **Evidence:** Durable themes: “AI-assisted development” and “Workbench & core UX”; guardrail: maintain a simple, uniform interaction and avoid executing unreviewed content.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/promptSyntax/promptUrlHandler.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts`, `src/vs/workbench/contrib/chat/test/browser/promptUrlHandler.test.ts`
- **Validation:** Add PromptUrlHandler unit tests covering install, open-without-persisting, and populate-chat-without-submitting choices, then run `./scripts/test.sh --grep "PromptUrlHandler"`.
- **Behavior:**

  > Opening an external `vscode:chat-prompt` link presents explicit safe outcomes rather than requiring immediate installation. The user can retain the existing install flow, inspect and edit the fetched prompt without first storing it in a customization folder, or place it into chat without sending it. Canceling creates no file and changes no chat input. No option executes unreviewed prompt content automatically.
- **Trace:**

  > PromptUrlHandler.handleURL in src/vs/workbench/contrib/chat/browser/promptSyntax/promptUrlHandler.ts currently maps install routes to PromptsType, confirms access to the remote URL, downloads the content, invokes the destination and filename pickers, persists the file, and opens it. An unsaved editor can be represented through IEditorService inputs with `resource: undefined` and initial `contents`; the chat surface exposes IChatWidgetService.revealWidget() and IChatWidget.setInput() separately from acceptInput(). RunPromptBaseAction in src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts demonstrates the existing slash-command execution path, but this request explicitly must not call acceptInput(). Preserve URL validation, the security warning, cancellation behavior, and the existing install outcome; do not broaden generic URL-opener behavior tracked by https://github.com/microsoft/vscode/issues/109277.
- **Open decisions:**
  - Should “Add to Chat” insert the downloaded prompt text directly, or create/reference a prompt slash command while leaving it unsubmitted?
  - Should “Open” use an editable dirty untitled editor, or a read-only transient preview with an explicit save action?
  - Should the additional outcomes apply only to `chat-prompt` links, or also to the instruction and agent install routes handled by the same contribution?
