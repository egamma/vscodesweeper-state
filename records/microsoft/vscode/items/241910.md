# Issue #241910 — Copy paste of image from safari inserts attachment and url text

[https://github.com/microsoft/vscode/issues/241910](https://github.com/microsoft/vscode/issues/241910)

## Summary

The shared image-paste defect was fixed on main: image attachment creation is now performed only by the selected paste edit, preventing Safari's accompanying URL text from also being inserted.

## Change summary

Pasting a copied Safari image into Chat attached the image but also inserted its URL into the prompt.

## Best solution

Keep the side-effect-free image paste flow introduced by commit 08192b4c30682bd894ad408d3248641efbb91973; it returns an attachment edit with empty inserted text instead of independently attaching the image while another provider inserts the URL.

## Evidence

- **confirmed trigger:** The report at https://github.com/microsoft/vscode/issues/241910 includes a screenshot and exact Safari steps showing one paste producing both an image attachment and URL text.
- **root cause and fix:** Commit https://github.com/microsoft/vscode/commit/08192b4c30682bd894ad408d3248641efbb91973 removes the eager `widget.attachmentModel.addContext(scaledImageContext)` call from `PasteImageProvider`. Before that removal, the immediately following duplicate check found the just-added image and returned no image paste edit, leaving the clipboard text provider to insert Safari's URL while the eager side effect retained the attachment.
- **same defect verified:** The commit fixed https://github.com/microsoft/vscode/issues/267850, a later confirmed instance of the same attachment-plus-clipboard-text behavior when pasting an image file.
- **current main:** In `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts`, `PasteImageProvider` now returns `createCustomPasteEdit(...)` without eagerly adding the attachment; `createCustomPasteEdit` uses an empty `insertText` by default and adds the attachment only through the selected custom edit.
