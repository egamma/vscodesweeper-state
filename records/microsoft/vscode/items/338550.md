# Issue #338550 — Creating workspace-less sessions renders as "Chats"

[https://github.com/microsoft/vscode/issues/338550](https://github.com/microsoft/vscode/issues/338550)

## Summary

Team-authored (MEMBER) bug report from active testing of a related feature; the sessions-list row rendering confirms quick-chat sessions only ever show a generic 'No workspace' badge with no branch for a remote agent-host backing, so there's a real, currently-unfixed gap. No fix commit exists yet (issue is one day old), so it stays open.

## Change summary

A workspace-less chat session created on a remote agent host machine shows no visual indication (beyond a placeholder/hover) that it is running remotely rather than locally.

## Best solution

Extend the quick-chat row rendering in sessionsList.ts to surface the remote host/machine when the session's providerId indicates a remote agent host (via isAgentHostProviderId/REMOTE_AGENT_HOST_PROVIDER_PREFIX), similar to how workspaceBadgeLabel is shown for workspace-backed sessions.

- **Trace:**

  > In src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, the row-rendering autorun branches on `isQuickChat` to pick an icon (always Codicon.commentDiscussion) and badge label (always the localized 'No workspace' string), with no check against the session's providerId or remoteConnectionStatus. ISession.providerId (session.ts) encodes local vs. remote-agent-host provider identity, and isAgentHostProviderId/REMOTE_AGENT_HOST_PROVIDER_PREFIX (agentHostSessionsProvider.ts) already exist to classify it, but nothing in the badge path consumes them for quick chats. - **Open decisions:**
