# Issue #192309 — Support a special view in the quick pick optimized for displaying icons

[https://github.com/microsoft/vscode/issues/192309](https://github.com/microsoft/vscode/issues/192309)

## Summary

Keep open: terminal and profile icon grids now provide part of the experience, but QuickPick still lacks the requested reusable icon-focused mode and filtered list transition. The maintainer accepted that interaction after UX discussion; no verified canonical owns the remaining work.

## Change summary

Support an opt-in QuickPick presentation that initially displays an icon grid and switches to labeled list results when filtering.

## Best solution

Provide the agreed grid-to-list experience through shared quick-input infrastructure while preserving ordinary QuickPick behavior and accessible keyboard interaction. Reuse the existing icon-selection capabilities where appropriate rather than treating the standalone grid as completion of this request.

- **Behavior:**

  > An opted-in icon picker allows visual browsing in a grid when its search input is empty. Typing a query presents matching entries in the ordinary labeled QuickPick list, as agreed after the UX discussion; clearing the query restores visual browsing. Selection and dismissal remain usable without a mouse, and icon choices have accessible names. Ordinary QuickPick consumers retain their existing presentation and interactions.
- **Trace:**

  > IQuickPick in src/vs/platform/quickinput/common/quickInput.ts has no icon-grid presentation contract, and QuickPick filtering in src/vs/platform/quickinput/browser/quickInput.ts delegates to QuickInputList, whose WorkbenchObjectTree renders list entries. TerminalIconPicker already offers a standalone WorkbenchIconSelectBox through a hover; the base IconSelectBox filters icon IDs but retains tiles, so it does not implement the agreed transition. WorkbenchIconSelectBox supplies separate grid-navigation keybindings, including left/right navigation conditional on input focus and emptiness. The post-UX-sync interaction is settled at https://github.com/microsoft/vscode/issues/192309#issuecomment-1734085320; it should not be reopened as a grid-versus-list design question. Preserve existing ordinary picker contracts and do not conflate icon naming and curation with presentation work, which is separately discussed at https://github.com/microsoft/vscode/issues/171076. Planning must establish how the shared presentation fits picker navigation and accessibility, and whether the first delivery includes a public extension contract.
- **Open decisions:**
