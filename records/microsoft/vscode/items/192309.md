# Issue #192309 — Support a special view in the quick pick optimized for displaying icons

[https://github.com/microsoft/vscode/issues/192309](https://github.com/microsoft/vscode/issues/192309)

## Summary

The terminal now has a reusable icon grid, but QuickPick still lacks the requested icon-focused mode and grid-to-list transition when filtering. Keep this accepted backlog request open; the existing picker solves part of the original usability problem, not the agreed QuickPick enhancement.

## Change summary

Add an opt-in QuickPick mode that displays an icon grid initially and switches to labeled list results when the user types.

## Best solution

Provide the shared QuickPick experience agreed after the UX discussion: visual browsing with empty input and ordinary labeled results during filtering. Reuse relevant existing icon-picker behavior while preserving normal QuickPick behavior; public extension API exposure remains a separate scope decision.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/base/browser/ui/icons/iconSelectBox.ts`, `src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Extend the QuickInput browser suite to cover an opted-in picker showing a grid with empty input, labeled filtered rows after typing, and a grid again after clearing input, with selection preserved across transitions. Manually verify terminal icon selection using only the keyboard, including arrow navigation, Enter, Escape, and accessible item labels; ordinary QuickPick behavior must remain unchanged.
- **Behavior:**

  > An opted-in QuickPick lets users browse icons visually without first guessing an icon name. Empty input shows an icon-focused grid; typing switches to ordinary filtered list results with visible labels, as agreed after the UX sync. Clearing the input restores visual browsing without losing the selected icon unnecessarily. Keyboard selection, dismissal, accessible names, and standard non-opted-in QuickPicks remain usable and consistent.
- **Trace:**

  > IQuickPick in src/vs/platform/quickinput/common/quickInput.ts has no grid presentation option; QuickInputController creates QuickInputList, and QuickPick filters that list on input changes. The terminal already uses WorkbenchIconSelectBox through the hover service in src/vs/workbench/contrib/terminal/browser/terminalIconPicker.ts, while profiles use the same widget separately. IconSelectBox in src/vs/base/browser/ui/icons/iconSelectBox.ts filters icon IDs and keeps rendering a grid, so existing visual browsing does not establish the requested QuickPick behavior. The interaction decision is settled by https://github.com/microsoft/vscode/issues/192309#issuecomment-1734085320; grid-versus-list filtering is not an open design question. The unresolved technical boundary is integration with shared QuickPick rendering, focus, filtering, and selection rather than merely replacing the terminal widget. Preserve ordinary QuickPicks and the terminal's existing icon availability; curated naming work in https://github.com/microsoft/vscode/issues/171076 is related but distinct.
- **Open decisions:**
  - Should the first version remain an internal QuickPick capability, or also expose a public extension API? The issue describes public exposure as a possibility rather than an agreed requirement.
