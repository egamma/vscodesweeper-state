# Issue #338412 — Exclamation mark command runs under wrong working directory

[https://github.com/microsoft/vscode/issues/338412](https://github.com/microsoft/vscode/issues/338412)

## Summary

Traced to source: the `!command` handler resolves the working directory from the session's default chat instead of the addressed sub-chat, so `!` always runs in the main chat's folder even when invoked from a peer/sub-chat with its own working directory. Milestone is Backlog (a holding bin, judged on merits) and the bug label reflects the owner's own judgment, so a factual keep-open with a concrete fix path is appropriate.

## Change summary

Running a `!shell command` from a sub-chat (a peer chat with its own working directory, different from the session's default chat) executes in the default chat's working directory instead of the sub-chat's own.

## Best solution

In `BangLocalCommand._run` (src/vs/platform/agentHost/node/localCommands/bangLocalCommand.ts), pass the original `turnChannel` (the addressed chat) to `ctx.getState(...)` instead of the derived `sessionChannel`, so the per-chat `workingDirectories` override is honored for peer/sub-chats.

- **Trace:**

  > `BangLocalCommand._run` in src/vs/platform/agentHost/node/localCommands/bangLocalCommand.ts derives `sessionChannel` from the turn's chat channel (stripping the chat identity) and then calls `ctx.getState(sessionChannel)?.workingDirectories?.[0]` to get the cwd for the new terminal. `AgentHostStateManager.getSessionState` (src/vs/platform/agentHost/node/agentHostStateManager.ts:414-429) only returns a chat's own `workingDirectories` when given that chat's URI directly; given a bare session URI it substitutes the default chat's state via `buildDefaultChatUri`. `mergeSessionWithDefaultChat` (src/vs/platform/agentHost/common/state/sessionState.ts:1023) confirms a chat-level `workingDirectories` override exists and should win.
