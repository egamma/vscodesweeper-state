# Issue #331140 — MCP App webview blank in auxiliary chat window until scroll forces reinitializeAfterDismount; mountTo registers MessagePort handler on main window before DOM node is attached to aux window

[https://github.com/microsoft/vscode/issues/331140](https://github.com/microsoft/vscode/issues/331140)

## Summary

Traced and confirmed on main: the MCP App webview constructor captures the target window via `dom.getWindow(container)` and calls `mountTo` before the container is actually attached under the auxiliary window's DOM, so the MessagePort handshake binds to the wrong window and the app never loads until a scroll-triggered dismount/remount fixes the window reference.

## Change summary

MCP App webviews render blank in an auxiliary chat window (via "New Chat Window") until the user scrolls the item off-screen and back, which forces a remount.

## Best solution

In chatToolInvocationPart.ts, fire the existing `_onDidRemount` event (already wired to `ChatMcpAppModel.remount()` via `ChatMcpAppSubPart`) immediately after `appDomNode.replaceWith(this.mcpAppPart.value.domNode)`, so the webview re-derives the correct target window right after the DOM node is actually attached — this reuses the exact code path that already fixes the bug on scroll.
