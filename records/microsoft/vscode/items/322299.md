# Issue #322299 — Bug: Custom endpoint crashes with "No lowest priority node found" under context limits and silently ignores plain-text apiKey

[https://github.com/microsoft/vscode/issues/322299](https://github.com/microsoft/vscode/issues/322299)

## Summary

Two confirmed bugs in BYOK custom endpoint handling: (1) `decodeSecretKey` silently corrupts plain-text API keys instead of validating or rejecting them, and (2) the prompt-tsx pruning algorithm crashes when maxInputTokens is too low for the injected tool schemas. Both are real defects, though affecting the niche BYOK custom-endpoint audience.

## Change summary

Custom BYOK endpoints crash with 'No lowest priority node found' when token limits are tight and many tools are injected, and plain-text apiKey values are silently dropped instead of being used or rejected with a warning.

## Best solution

Fix `decodeSecretKey` in `src/vs/workbench/contrib/chat/common/languageModels.ts` to validate the secret-input format and either accept plain-text keys as a fallback or surface a clear configuration error. The pruning crash lives in `@vscode/prompt-tsx` and needs a graceful-degradation fix there (or a guard in the copilot extension before calling the renderer with an impossibly tight budget). The `toolCalling: false` model-hiding behavior may warrant a separate UX discussion.
