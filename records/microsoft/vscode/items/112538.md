# Issue #112538 — Support AppLocker

[https://github.com/microsoft/vscode/issues/112538](https://github.com/microsoft/vscode/issues/112538)

## Summary

This is an upstream Chromium/Electron sandbox issue that manifests when running VS Code as admin with AppLocker. A team member confirmed the root cause is in Chromium's process creation for sandboxing and suggested documentation as the only VS Code-side action. No code fix has landed or is feasible in this repo.

## Change summary

AppLocker blocks some VS Code child processes when running elevated, due to Chromium sandbox's use of CreateProcessAsUserW.

## Best solution

Document the incompatibility between AppLocker default rules and Chromium's sandbox when running elevated, and the `--no-sandbox` workaround with its security implications. The underlying fix belongs in Chromium (https://bugs.chromium.org/p/chromium/issues/detail?id=740132).
