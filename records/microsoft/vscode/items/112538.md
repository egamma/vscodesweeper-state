# Issue #112538 — Support AppLocker

[https://github.com/microsoft/vscode/issues/112538](https://github.com/microsoft/vscode/issues/112538)

## Summary

Keep open for human review of the Chromium sandbox/AppLocker compatibility boundary. Maintainers confirmed the upstream limitation and the security implications of disabling sandboxing; neither a verified fix nor an eligible older canonical issue was established.

## Change summary

Allow elevated VS Code processes to start under Windows AppLocker default rules without blocked child processes or a blank window.

## Best solution

Establish whether current Electron/Chromium supports this elevated AppLocker scenario without weakening sandbox protections, and document the supported boundary. Any runtime compatibility fix should preserve sandboxing rather than make the reported no-sandbox workaround the default.
