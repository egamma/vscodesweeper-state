# Issue #139968 — When characters are typed at a rapid rate, textDocument/onTypeFormatting fails to fire

[https://github.com/microsoft/vscode/issues/139968](https://github.com/microsoft/vscode/issues/139968)

## Summary

Still reproduces on main: the onDidType handler only checks the last character of the batched text string, so trigger characters embedded earlier in a rapid typing burst are missed. The cancellation logic also discards formatting when follow-on edits land before the async response returns.

## Change summary

When characters are typed rapidly, onTypeFormatting trigger characters batched with subsequent keystrokes are never detected, so the formatting request is never sent.

## Best solution

The `onDidType` handler in `FormatOnType._update` (formatActions.ts:89-94) should scan the entire batched text for any trigger character, not just the last character. Additionally, the cancellation guard in `_trigger` (line 124) is aggressive — it cancels for any edit on or before the trigger line, which also discards formatting when rapid follow-on keystrokes land. Both would need adjustment for a proper fix, but the interaction with OT/edit conflict detection makes this non-trivial.
