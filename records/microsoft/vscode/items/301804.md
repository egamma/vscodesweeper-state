# Issue #301804 — Copilot Agent run_in_terminal fails with ENOPRO: No file system provider found in GitHub Codespaces

[https://github.com/microsoft/vscode/issues/301804](https://github.com/microsoft/vscode/issues/301804)

## Summary

Fixed on main and shipped in 1.124.0. Commit 0712539c435 adds a `canHandleResource()` guard in `getCwdResource()` so the missing `file://` provider in VS Code web no longer throws ENOPRO — it returns `undefined` and the tool falls back to the workspace folder URI.

## Change summary

Copilot Agent's `run_in_terminal` tool throws ENOPRO in VS Code web (Safari, Firefox, Brave) because `getCwdResource()` calls `fileService.exists()` on a `file://` URI that has no registered provider in the browser.

## Best solution

Keep the shipped fix in commit 0712539c435 (1.124.0). No further change needed — the `canHandleResource()` guard prevents the ENOPRO from propagating to callers. Reporters should verify on VS Code 1.124.0+.
