# Issue #225977 — All content read as expanded in walkthrough for SR users

[https://github.com/microsoft/vscode/issues/225977](https://github.com/microsoft/vscode/issues/225977)

## Summary

Still reproduces on main: walkthrough steps are rendered as `button` elements with `role='button'` containing all description content as children, so screen readers announce every piece of inner text as part of the button. PR #228904 only added an accessible-view hint; the structural nesting issue remains unfixed.

## Change summary

Screen reader users hear all expanded walkthrough step content announced as 'expanded button' due to improper HTML nesting — inner content is a child of the button element rather than a sibling.

## Best solution

Refactor the walkthrough step markup to use a proper accordion pattern (WAI-ARIA APG): the button should control expand/collapse but the expanded description content should be a sibling element referenced via `aria-controls`, not nested inside the button. This fixes the 'everything reads as button' problem and enables keyboard collapse. Work belongs in `src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStarted.ts` around line 1600.
