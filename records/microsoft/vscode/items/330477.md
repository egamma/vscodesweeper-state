## Summary

This is the same underlying problem already tracked by the open, broader issue https://github.com/microsoft/vscode/issues/322015 ("Agent host does not seem to pick up account changes without process restart") — the reporter here even originally commented on #322015 before this was split out. No fix has landed on main for the stale-token path, so consolidating avoids splitting the same defect across two threads.

## Change summary

After exhausting quota and switching GitHub accounts, Copilot Agent Host sessions keep using the previous account's token/credit limit, even across a VS Code restart and in new sessions.

## Best solution

Keep tracking this in https://github.com/microsoft/vscode/issues/322015, which already carries `bug`/`authentication`/`agent-host` labels — the fix belongs in the agent-host session launch/account-binding path (see `isLaunchTokenCurrent`/`_isLaunchTokenCurrent` in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts) so a session re-checks or rebinds to the currently active account rather than the one active at launch.
