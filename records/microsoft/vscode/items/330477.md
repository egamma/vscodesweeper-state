# Issue #330477 — Copilot Agent Host not able to switch account

[https://github.com/microsoft/vscode/issues/330477](https://github.com/microsoft/vscode/issues/330477)

## Summary

This is a direct spin-off of the open canonical issue https://github.com/microsoft/vscode/issues/322015 ('Agent host does not seem to pick up account changes without process restart'), reporting the same stale-credentials defect with extra detail (staleness persists across a full VS Code restart, not just a window reload) — proposing a duplicate close so the evidence consolidates on the canonical thread.

## Change summary

After switching GitHub accounts (to escape an exhausted-credits error), the Copilot agent host keeps using the previous account's credentials, even in a new session and after restarting VS Code.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/322015, which already tracks the agent host not picking up account/token changes without a process restart; the fix belongs in the agent host's token/session caching (src/vs/platform/agentHost/node/shared/copilotApiService.ts's per-GitHub-token client cache and src/vs/platform/agentHost/node/agentHostAuthenticationService.ts's token store) so a new sign-in reliably invalidates the stale entry, including surviving a VS Code window restart if the agent host process itself is not restarted.
