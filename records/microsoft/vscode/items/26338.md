Keep open: external-script IntelliSense remains unsupported by the current built-in HTML JavaScript service. The implementation cited in the latest comment is in an open, unmerged PR, not a shipped fix.

## Evidence

- **Current source still isolates embedded JavaScript:** In extensions/html-language-features/server/src/modes/javascriptMode.ts, getLanguageServiceHost supplies only the embedded document URI and 'jquery' through getScriptFileNames. Its readFile, fileExists, and getScriptSnapshot callbacks consult the embedded document or loadLibrary, not workspace JavaScript files or project declarations.
- **Existing capability does not cover the request:** extensions/html-language-features/server/src/modes/javascriptLibs.ts loads bundled jquery.d.ts and TypeScript libraries, explaining the thread's jQuery exception. The HTML extension's package.json contributes no setting that enables workspace-script or declaration-file resolution. Embedded IntelliSense and bundled jQuery types do not satisfy arbitrary external references.
- **Referenced scripts are recognized but not loaded into the JavaScript project:** extensions/html-language-features/server/src/modes/embeddedSupport.ts collects script src values in importedScripts and exposes getImportedScripts, but the JavaScript language-service host does not include those references in its script list.
- **Latest implementation claim refers to an unmerged PR:** The final supplied comment says this was implemented in https://github.com/microsoft/vscode/pull/171547. GitHub inspection confirms that PR is OPEN with mergedAt null; its body explicitly lists this issue among its fixes. This establishes an existing implementation candidate, not completion on main.
