# Issue #123030 — Fails To Copy Large Text

[https://github.com/microsoft/vscode/issues/123030](https://github.com/microsoft/vscode/issues/123030)

## Summary

Keep open: the size-dependent Linux clipboard failure has an independent historical confirmation, but neither a concrete fix nor an eligible canonical duplicate was established. The next useful step is a current Linux reproduction that distinguishes editor payload generation from native clipboard transfer.

## Change summary

Copying approximately 2.15 million characters from a CSS file on Linux silently fails to make the selected text available to another editor.

## Best solution

Ensure large editor selections reach the Linux system clipboard intact, with an explicit failure indication if transfer cannot complete. First establish whether the failure remains on current builds and whether it originates in VS Code's copy handling or the native clipboard backend.

- **Behavior:**

  > The historical report describes a size-dependent Linux failure: copying an entire large CSS file produces no usable clipboard text, while copying smaller selections succeeds. The expected outcome is that the complete selected plaintext can be pasted into another editor without truncation or silent failure. Establish this behavior on current Linux before choosing a fix, and validate both keyboard and context-menu copying against large and small selections.
