## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/347985 supplies a Rust sample, Windows 11 and VS Code version, and affected bundled themes. The standard-library r.contains call highlights differently from default-library function calls despite correctly supplied semantic tokens.
- **Current source defect:** src/vs/platform/theme/common/tokenClassificationRegistry.ts:561-563 registers ordinary methods with entity.name.function.member before support.function. Lines 596-597 give function.defaultLibrary and deprecated member.defaultLibrary a support.function fallback, but omit method.defaultLibrary. The deprecated member inherits from method, not vice versa, so its special rule does not cover method tokens.
- **Observable color difference:** src/vs/workbench/services/themes/common/colorThemeData.ts:230-237 resolves matching default selectors through TextMate scopes. extensions/theme-defaults/themes/2026-dark.json:365-367 assigns entity.name.function purple, while inherited extensions/theme-defaults/themes/dark_plus.json:7-16 assigns support.function yellow. The missing method.defaultLibrary selector therefore explains the reported inconsistency.
- **Open implementation candidate:** The supplied timeline identifies https://github.com/microsoft/vscode/pull/348011 as open. Its fetched review describes adding method.defaultLibrary with support.function, explicitly references this issue, and requests regression coverage preserving ordinary method styling. That selector is still absent from the checkout; an open fix proposal is not a completed fix.
