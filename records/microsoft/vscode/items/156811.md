# Issue #156811 — Activation event for a particular folder opened

[https://github.com/microsoft/vscode/issues/156811](https://github.com/microsoft/vscode/issues/156811)

## Summary

The older, open directory-activation request explicitly includes activating when an opened folder's path matches a pattern, covering this folder-name case. Consolidate there while preserving the GistPad example and the motivation to avoid unconditional startup activation.

## Change summary

Allow extensions to activate selectively when an opened workspace folder's name matches a pattern such as *-wiki.

## Best solution

Resolve folder-name and folder-path activation together in https://github.com/microsoft/vscode/issues/2739, including the *-wiki use case without requiring a marker file or unconditional startup activation.

Its directory-activation scope was explicitly extended in https://github.com/microsoft/vscode/issues/2739#issuecomment-386590202 to matching folder paths and activating when a matching folder is opened, rather than only finding files inside it.
- **Re-review duplicate bar:** The canonical predates https://github.com/microsoft/vscode/issues/156811. The cited 2018 comment describes the same observable missing capability: selectively activating an extension when opening a folder identified by a path pattern. Matching the opened folder's *-wiki basename is a specific case of that requested folder-path matching, not merely another symptom of file-search limitations.
- **Existing capability does not cover the request:** src/vs/workbench/services/extensions/common/workspaceContains.ts sends wildcard patterns to checkGlobFileExists, which constructs a QueryBuilder.file query and calls searchService.fileSearch. Literal patterns are checked with resources.joinPath(folderUri, fileName). Neither path matches the opened folder's own basename against *-wiki. src/vs/workbench/services/extensions/common/extensionsRegistry.ts documents workspaceContains as matching contained files and has no workspaceName activation event.
- **Related extension discussion:** https://github.com/lostintangent/gistpad/issues/307#issuecomment-1201441951 distinguishes marker-file activation through workspaceContains from the missing foo-wiki folder-name trigger and links this issue. The follow-up at https://github.com/lostintangent/gistpad/issues/307#issuecomment-1201442987 only suggests trying workspaceContains:*-wiki; it does not confirm that it works. Closing that extension issue therefore does not establish a VS Code fix.
