# Issue #336376 — Copilot subagents receive mandatory tool_search instructions although Responses API disables tool search for subagents

[https://github.com/microsoft/vscode/issues/336376](https://github.com/microsoft/vscode/issues/336376)

## Summary

Confirmed on current main: the Responses API request builder (responsesApi.ts) deliberately disables tool_search/deferral for subagents, but the shared tool-search prompt guidance and the GPT-5.5-specific reminder only check `endpoint.supportsToolSearch`, not the effective per-request policy — so subagents get eagerly-loaded ordinary tools plus a false 'you must search before calling' instruction, which can cause them to stall.

## Change summary

Subagent requests disable tool_search and supply ordinary tool schemas directly, but the prompt text still instructs the subagent that it must call tool_search before using those (already-available) tools.

## Best solution

Make the prompt-generation components (toolSearchInstructions.tsx, gpt55Prompt.tsx, and any other model-specific reminders) gate on the same effective policy responsesApi.ts computes (`toolSearchEnabled && isAllowedConversationAgent && !isSubagent`) instead of raw `endpoint.supportsToolSearch`, so prompt text and the serialized request always agree.

- **Trace:**

  > responsesApi.ts computes `shouldDeferTools` from `toolSearchEnabled && isAllowedConversationAgent && !isSubagent` (subagent detected via `options.telemetryProperties?.subType?.startsWith('subagent')`) to decide whether to include the protocol `tool_search` tool and whether to withhold ordinary tool schemas for discovery. Where uncertainty starts: whether the fix should add a prop threaded down from the conversation/agent layer (carrying the same effective `shouldDeferTools` boolean) into these PromptElements, or compute an equivalent check locally in each prompt component from data already available at render time (e.g., via `PromptSizing`/metadata) — and whether gpt54Prompt.tsx, gpt56Prompt.tsx, gpt6Prompt.tsx, gpt55BasePrompt.tsx, and anthropicPrompts.tsx (all of which reference these shared components) need the same propagation.
- **Open decisions:**
  - Should the effective 'tool search enabled for this request' signal be threaded into prompt-tsx components as an explicit prop (e.g., `isSubagent`/`shouldDeferTools`) from the conversation/agent orchestration layer, or recomputed locally from information already available at prompt-render time?
  - Do the other model-specific prompt files that reuse ToolSearchToolPromptOptimized/DeferredToolListReminder (gpt54Prompt.tsx, gpt56Prompt.tsx, gpt6Prompt.tsx, gpt55BasePrompt.tsx, anthropicPrompts.tsx) need their own explicit fix, or do they inherit it automatically once the shared components are corrected?
