## Evidence

- **Clarified request:** In https://github.com/microsoft/vscode/issues/30320, the reporter's August 11, 2017 reply explicitly asks for a keyboard equivalent of moving the newest cursor with modifier-click and drag. The maintainer's existing find-match shortcut does not satisfy arbitrary positioning.
- **Verified older open canonical:** https://github.com/microsoft/vscode/issues/20742 is currently OPEN and was created on February 16, 2017, before this report. Its body requests arrow-key navigation while retaining marked cursors; https://github.com/microsoft/vscode/issues/20742#issuecomment-305195655 explicitly requests freely moving the active cursor while other cursor positions remain marked.
- **Same observable gap, not merely related work:** https://github.com/microsoft/vscode/issues/20742#issuecomment-399093659 explicitly asks for arrow-key navigation after activating multiple cursors without affecting the positions of the others. This encompasses the newest-cursor movement requested here and satisfies the stronger duplicate bar for a re-reviewed item.
- **Existing capabilities are partial:** In src/vs/editor/browser/coreCommands.ts:589-691, cursorMove and directional movement commands operate on viewModel.getCursorStates(), moving all cursors. In src/vs/editor/contrib/multicursor/browser/multicursor.ts, editor.action.moveSelectionToNextFindMatch and editor.action.moveSelectionToPreviousFindMatch move only between matches; editor.action.focusNextCursor and editor.action.focusPreviousCursor reorder cursor states and reveal the primary cursor without independently repositioning it.
- **Workaround discussion retained by canonical:** The canonical already discusses extension-based alternatives and their limitations. https://github.com/microsoft/vscode/issues/20742#issuecomment-2016810421 describes Keyboard Cursors and Selections as supporting keyboard navigation with retained inactive cursors; this is workaround evidence, not proof that core implemented the request.
