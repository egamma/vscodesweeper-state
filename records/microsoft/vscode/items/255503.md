# Issue #255503 — Unable to abandon task with ${input} variable type command

[https://github.com/microsoft/vscode/issues/255503](https://github.com/microsoft/vscode/issues/255503)

## Summary

Command-type input cancellation still fails in current source: an undefined command result is wrapped as a successful resolution instead of abandoning the task. Two verified open fix PRs already address this issue, so keep it open pending review and landing.

## Change summary

Restore task cancellation when a command-type ${input} returns undefined or null.

## Best solution

Review and consolidate the overlapping fixes in https://github.com/microsoft/vscode/pull/301995 and https://github.com/microsoft/vscode/pull/307980, then land one that restores cancellation while preserving valid string results and existing input behavior.

## Evidence

- **Current-source defect:** In src/vs/workbench/services/configurationResolver/browser/baseConfigurationResolverService.ts, showUserInput's command branch returns { value: result, input: info } for strings and undefined/null alike. resolveWithInteraction cancels only when the entire result is undefined, so a cancelled command input bypasses that check; promptString and pickString correctly return undefined on cancellation.
- **Observable consequence:** ConfigurationResolverExpression.resolve in src/vs/workbench/services/configurationResolver/common/configurationResolverExpression.ts marks the wrapped result resolved but preserves the original variable text when data.value is undefined. TerminalTaskSystem._acquireInput and _executeCommand in src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts accept the resulting map and continue execution rather than following their undefined cancellation path.
- **Confirmed reproduction in discussion:** https://github.com/microsoft/vscode/issues/255503#issuecomment-5208240243 supplies a complete tasks.json and confirms the problem on VS Code 1.130.0, including a command-type input invoking workbench.action.selectTheme without a third-party extension. The update explicitly retracts the initial suggestion that built-in commands no longer reproduce.
- **Open implementation candidates:** GitHub reads verified that https://github.com/microsoft/vscode/pull/301995 and https://github.com/microsoft/vscode/pull/307980 are both OPEN and explicitly reference this issue. Both address command-result cancellation; the latter describes a resolver regression test. These are pending fixes, not evidence of completion.
- **Closed attempt did not fix this behavior:** https://github.com/microsoft/vscode/pull/260354 is CLOSED with mergedAt null. Its diff changes cancellation of the problem-matcher picker in abstractTaskService.ts, not command-input resolution, agreeing with the reporter's explanation at https://github.com/microsoft/vscode/issues/255503#issuecomment-3234272730.
