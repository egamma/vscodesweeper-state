# Issue #255503 — Unable to abandon task with ${input} variable type command

[https://github.com/microsoft/vscode/issues/255503](https://github.com/microsoft/vscode/issues/255503)

## Summary

The cancellation defect remains in current main: command inputs wrap undefined/null results in an object, bypassing the resolver's cancellation check. Keep this issue open while the two existing fix proposals are reviewed.

## Change summary

Restore task cancellation when a command-type input returns undefined or null, consistently with cancelled built-in prompt and pick inputs.

## Best solution

Review and land one of the existing proposals at https://github.com/microsoft/vscode/pull/301995 or https://github.com/microsoft/vscode/pull/307980, preserving string-result handling while restoring cancellation propagation.

## Evidence

- **Current source confirms the defect:** src/vs/workbench/services/configurationResolver/browser/baseConfigurationResolverService.ts:338–345 accepts string, undefined, and null command results and returns { value: result, input: info }. resolveWithInteraction at lines 194–200 cancels only when the result object itself is undefined, so command-input cancellation bypasses that check.
- **Expected cancellation behavior:** In the same file, promptString and pickString return undefined when cancelled. resolveWithInteractionReplace at lines 146–155 propagates an undefined resolution rather than producing a task configuration; command inputs currently fail to reach that cancellation path.
- **Confirmed reproduction without third-party extensions:** https://github.com/microsoft/vscode/issues/255503#issuecomment-5208240243 provides a complete tasks.json using the built-in workbench.action.selectTheme command and reports that ${input:commandInput} is passed literally instead of abandoning the task. The edited comment explicitly retracts the suggestion that this is extension-owned.
