# Issue #111354 — Code Lens Should Respect Command's Enablement

[https://github.com/microsoft/vscode/issues/111354](https://github.com/microsoft/vscode/issues/111354)

## Summary

Keep open: current CodeLens rendering and invocation still do not consult a command's enablement. The maintainer already established the intended direction—disable commands without hiding lenses—and no verified canonical or fixing commit was found.

## Change summary

Make CodeLens commands respect contributed command enablement while preserving their layout.

## Best solution

CodeLens should reflect changes in command enablement and prevent disabled commands from being invoked through either mouse interaction or the current-line command picker. Preserve lens visibility and vertical space, and resolve enablement against the original contributed command even when extension-host conversion delegates its execution.

- **Behavior:**

  > A CodeLens associated with a contributed command must respect that command's enablement condition and update when the relevant context changes. Disabled lenses remain visible and retain their vertical space, as the maintainer explicitly rejected hiding them. Neither clicking a disabled lens nor choosing it through the current-line CodeLens command UI should invoke its handler. Acceptance includes commands with arguments, commands without arguments, and unchanged behavior for commands without an enablement clause.
- **Trace:**

  > CodeLensContentWidget.withCommands in src/vs/editor/contrib/codelens/browser/codelensWidget.ts renders every command with a nonempty ID as an actionable anchor, without consulting enablement. CodeLensContribution's mouse handler and ShowLensesInCurrentLine in src/vs/editor/contrib/codelens/browser/codelensController.ts both execute commands directly. The existing menu behavior evaluates ICommandAction.precondition in MenuItemAction, while menusExtensionPoint.ts registers contributed enablement as that precondition. CodeLensAdapter uses CommandsConverter.toInternal; extHostCommands.ts replaces contributed command IDs with a delegating ID when arguments are present, making original command identity a relevant cross-layer boundary. The trace establishes the missing behavior but does not finish how enablement metadata and context changes should reach both CodeLens surfaces. Preserve programmatic executeCommand semantics and commands without enablement; do not hide lenses or change layout. The accepted direction is recorded at https://github.com/microsoft/vscode/issues/111354.
