# Issue #100147 — Support reparenting views during drag and drop without destroying and recreating them

[https://github.com/microsoft/vscode/issues/100147](https://github.com/microsoft/vscode/issues/100147)

## Summary

The requested lifecycle capability is still missing: moving a view between containers disposes its pane and constructs another, and Refactor Preview remains excluded from individual view moves. Keep this accepted Backlog request open; the discussion explicitly calls for framework support rather than requiring passive views to reconstruct transient input.

## Change summary

Allow stateful views such as Refactor Preview to move between containers without destroying their live UI and operation state.

## Best solution

Provide a supported view-framework lifecycle that preserves participating views' live state across container moves, then allow Refactor Preview to use it. Establish the compatibility contract for existing views before changing shared lifecycle behavior.

For Refactor Preview, moving preserves the proposed edits and selection choices, and Apply or Discard continues to resolve the original preview operation. Acceptance must cover moves in both directions between panel and sidebar, continued usability at the destination, and normal cleanup when the operation actually ends.
