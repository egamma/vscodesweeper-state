# Issue #332601 — Copilot Not Respecting Disablement on Agent Host

[https://github.com/microsoft/vscode/issues/332601](https://github.com/microsoft/vscode/issues/332601)

## Summary

Traced on main: `shouldSurfaceLocalAgentHostProvider` (src/vs/platform/agentHost/common/agentService.ts) has explicit enablement checks for Claude (`chat.agentHost.claudeAgent.enabled`) and Codex (`chat.agentHost.codexAgent.enabled`/`chat.editor.codex.preferAgentHost`), but its `default` branch — which covers the Copilot provider — unconditionally returns `true`. There is no `chat.agentHost.copilotAgent.enabled`-style setting, so none of the settings the reporter tried can hide the Copilot harness option.

## Change summary

Disabling all the documented Copilot-related settings does not remove Copilot from the agent-host harness/session-type picker.

## Best solution

Give the Copilot agent-host provider the same per-provider enablement gate Claude and Codex already have (a `chat.agentHost.copilotAgent.enabled`-style setting consumed in `shouldSurfaceLocalAgentHostProvider`'s default case), or, if Copilot is intentionally always-on as the primary/fallback harness, document that and close as as-designed — that call needs a maintainer since it changes what 'agent host' guarantees.
