# Issue #332601 — Copilot Not Respecting Disablement on Agent Host

[https://github.com/microsoft/vscode/issues/332601](https://github.com/microsoft/vscode/issues/332601)

## Summary

Traced the picker gating logic on main: `shouldSurfaceLocalAgentHostProvider` in src/vs/platform/agentHost/common/agentService.ts explicitly checks the Claude and Codex enablement settings but falls through to `default: return true` for every other provider, including the built-in Copilot SDK harness (`copilotcli`) — so there is genuinely no setting today that hides it from the agent-host picker, confirming the reporter's diagnosis. A maintainer (roblourens) has already engaged and is questioning whether a disable setting is warranted, so this is an open design question rather than a settled bug or a ready close.

## Change summary

No configuration exists to hide the built-in Copilot SDK harness from the agent-host session picker, unlike Claude/Codex which already have enable/disable settings, blocking enterprise policy control after re-enabling native chat.

## Best solution

Extend `shouldSurfaceLocalAgentHostProvider` (src/vs/platform/agentHost/common/agentService.ts, currently `default: return true`) with an explicit case for the Copilot SDK provider gated by an enablement setting, mirroring the existing Claude/Codex cases — but this needs a maintainer/product decision on the right setting name and enterprise-policy semantics, which is already underway in the thread.
