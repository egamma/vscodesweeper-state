# Issue #298997 — Add UI for right time right place tips

[https://github.com/microsoft/vscode/issues/298997](https://github.com/microsoft/vscode/issues/298997)

## Summary

Keep open for a focused design session: current main has anchored onboarding callouts, but that does not establish completion of contextual tips outside the chat input. The older feedback issue provides design context rather than a verified duplicate, and this team-authored request has no verified issue-referencing fix.

## Change summary

Provide UI and backend support for tips shown beside the relevant action at a useful moment, rather than only above the chat input.

## Best solution

Define a restrained, accessible contextual-tip experience that builds on existing tip eligibility and onboarding target infrastructure. Settle placement, trigger, and dismissal semantics before extending tips to action-adjacent surfaces.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatTipService.ts`, `src/vs/workbench/contrib/chat/browser/chatTipCatalog.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputTipPresenter.ts`, `src/vs/workbench/contrib/onboarding/browser/spotlight/spotlightTypes.ts`, `src/vs/workbench/contrib/onboarding/browser/spotlight/spotlightPresentation.ts`
- **Validation:** For an agreed initial tip and target, exercise its eligibility trigger with the target visible and absent; verify placement beside the intended action, keyboard access, dismissal, suppression after the relevant action, and chat.tips.enabled=false. Add focused coverage alongside chatTipService.test.ts and the onboarding presentation tests for the chosen contract.
- **Behavior:**

  > Tips should appear where the user can invoke the relevant action and when that guidance is actionable, rather than relying exclusively on the chat-input banner. The experience should remain restrained and accessible, with predictable dismissal and suppression after the user has learned or used the feature. Acceptance should cover an agreed initial action, its eligibility trigger, target availability, keyboard interaction, and disabled tips. Presentation and persistence semantics require maintainer agreement first.
- **Trace:**

  > ChatInputTipPresenter currently obtains getWelcomeTip() from IChatTipService and renders it in a chat-input notice lane. The onboarding spotlight infrastructure already resolves named targets and supports anchored placement, context conditions, and target interaction, but SpotlightPresentation dims the window and runs guided steps. The remaining uncertainty is whether that guided presentation matches contextual tips and how tip eligibility and dismissal should apply outside the input. Preserve existing chat-tip controls and do not expand this into the notification-control work tracked at https://github.com/microsoft/vscode/issues/332650. https://github.com/microsoft/vscode/issues/296652 supplies relevant feedback on hierarchy and interruption, not a verified duplicate.
- **Open decisions:**
  - Should contextual tips be non-modal callouts that leave the workbench uninterrupted, or spotlight-style guidance that dims the surrounding UI?
  - Which initial actions and user-state transitions should trigger action-adjacent tips, and when should the existing chat-input presentation remain the fallback?
  - Should dismissing an action-adjacent tip hide it for the session or permanently, and should that dismissal also suppress the same tip in the chat-input surface?
