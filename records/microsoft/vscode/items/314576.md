# Issue #314576 — copilot_getNotebookSummary needs a freaking timeout and clear error

[https://github.com/microsoft/vscode/issues/314576](https://github.com/microsoft/vscode/issues/314576)

## Summary

Real bug, confirmed from source: the notebook summary tool's variable-fetching path (`NotebookService.getVariables`) awaits a kernel command (`jupyter.listVariables` or `vscode.executeNotebookVariableProvider`) with no timeout and no cancellation token, causing an indefinite hang when the kernel is unresponsive. Issues https://github.com/microsoft/vscode/issues/289225 and https://github.com/microsoft/vscode/issues/295047 are duplicates of this issue, which is the best-diagnosed report and should serve as the canonical tracker.

## Change summary

The `copilot_getNotebookSummary` tool hangs indefinitely when the notebook kernel is slow, remote, or busy because the variable-fetching call has no timeout or cancellation.

## Best solution

Add a timeout (and cancellation token propagation) to `NotebookService.getVariables()` in `extensions/copilot/src/platform/notebook/vscode/notebookServiceImpl.ts`, and plumb the cancellation token from `NotebookSummaryTool.invoke()` through `renderPromptElementJSON` into `NotebookVariables.prepare()`. On timeout, return an empty variable list (or a structured error) so the summary still returns cell structure from the local document. The `NotebookVariables.prepare()` already has a try/catch that returns `{ variables: [] }` on error, so a timeout rejection would degrade gracefully.
