# Issue #118833 — Notebook output must support more ANSI sequences

[https://github.com/microsoft/vscode/issues/118833](https://github.com/microsoft/vscode/issues/118833)

## Summary

Keep open: current notebook stream processing still lacks the requested general cursor-movement and erase behavior. Existing backspace, carriage-return, and limited cursor-up handling only partially cover the request; maintainers have explicitly welcomed further support.

## Change summary

Support additional ANSI cursor-movement and erase sequences in notebook stdout/stderr so terminal-oriented progress output updates correctly.

## Best solution

Extend notebook stream handling to cover the documented progress-bar sequences and establish the intended clear-screen behavior without discarding unrelated preceding output. Coordinate model normalization and built-in rendering so streamed updates and saved notebook output remain consistent.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/common/notebookCommon.ts`, `src/vs/workbench/contrib/notebook/common/model/notebookCellOutputTextModel.ts`, `src/vs/workbench/contrib/notebook/test/browser/notebookCommon.test.ts`, `extensions/notebook-renderers/src/ansi.ts`, `extensions/notebook-renderers/src/textHelper.ts`
- **Validation:** Add notebook stream tests covering ESC[K, parameterized/default cursor-up, cursor-down, and agreed clear-screen semantics with sequences split across output chunks. Verify a multiline progress update preserves preceding unrelated output, then manually compare streamed and saved/reopened notebook rendering; retain existing backspace, carriage-return, color, and Unicode behavior.
- **Behavior:**

  > Notebook stdout/stderr should interpret the agreed ANSI cursor and erase sequences rather than merely hide them or append repeated progress lines. The discussion identifies erase-to-end-of-line, cursor-up, cursor-down, and carriage return as important for Julia progress libraries, while the original request also includes clear-screen behavior. Acceptance should cover multiline progress updates without removing unrelated preceding output, chunk-boundary independence, and consistent rendering after reopening a notebook. Existing color and basic text-control behavior must remain intact.
- **Trace:**

  > compressOutputItemStreams in src/vs/workbench/contrib/notebook/common/notebookCommon.ts combines stream buffers and applies limited normalization; compressStreamBuffer recognizes only an exact ESC[A prefix on subsequent buffers. NotebookCellOutputTextModel.optimizeOutputItems in src/vs/workbench/contrib/notebook/common/model/notebookCellOutputTextModel.ts invokes that normalization when merging stream items and invalidates tracked buffer lengths after compression. The built-in renderer's handleANSIOutput in extensions/notebook-renderers/src/ansi.ts consumes cursor/erase sequences without applying their effects, and textHelper.ts uses it for text rendering. Existing normalization tests are in src/vs/workbench/contrib/notebook/test/browser/notebookCommon.test.ts. The record establishes the missing capability, but does not settle a complete terminal-control contract or clear-screen scope; preserve existing stream MIME handling, styling, and text normalization. The maintainer invitation is https://github.com/microsoft/vscode/issues/118833#issuecomment-1981801334; https://github.com/timholy/ProgressMeter.jl/issues/271 provides related library requirements.
- **Open decisions:**
  - Should the initial supported contract cover only the documented progress-bar cursor/erase sequences, or broader terminal control behavior?
  - For clear-screen sequences, should erasure affect only the current stdout/stderr stream output or all outputs in the cell, including earlier rich outputs?
