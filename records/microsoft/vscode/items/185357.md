# Issue #185357 — Merge Editor: Don't compute diff of result when result has been reset

[https://github.com/microsoft/vscode/issues/185357](https://github.com/microsoft/vscode/issues/185357)

## Summary

The redundant result-diff computations remain in current main: initialization computes a diff for the result that reset replaces, and resetting triggers another computation. Keep this issue as the existing canonical report for that bounded performance defect.

## Change summary

Avoid redundant base-to-result diff computations when the merge editor resets the result to its computed auto-merge.

## Best solution

Reset should produce an up-to-date result and its mappings without redundant result diff work, while preserving conflict state, normal editing, and undo/redo behavior. The relevant boundary is MergeEditorModel and TextModelDiffs.
