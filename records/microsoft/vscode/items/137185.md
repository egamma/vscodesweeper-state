# Issue #137185 — Notebook should have toggle commands for all layout command

[https://github.com/microsoft/vscode/issues/137185](https://github.com/microsoft/vscode/issues/137185)

## Summary

Keep open: existing view commands do not consistently reverse the layout changes described here. The related alignment issue explicitly consolidated its work into this issue, and no verified older canonical or concrete fixing commit was found.

## Change summary

Provide reversible notebook layout commands for Outline and Variables, accounting for views being moved, hidden, or collapsed.

## Best solution

Define consistent show/hide semantics for notebook-associated views across sidebar and panel placements, then expose commands that extensions can reuse. Preserve unrelated views when reversing a layout change.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/controller/layoutActions.ts`, `src/vs/workbench/contrib/notebook/browser/controller/variablesActions.ts`, `src/vs/workbench/services/views/browser/viewsService.ts`, `src/vs/workbench/browser/parts/views/viewPaneContainer.ts`
- **Validation:** Exercise Outline and Variables in their default and moved containers, with the container hidden, the pane hidden, and the pane collapsed. Invoke each agreed toggle twice and verify the specified visible-state transition, preservation of unrelated views, and identical behavior when invoked through the command service.
- **Behavior:**

  > Notebook layout commands should offer a straightforward way back from revealing Outline or Variables. Their behavior should remain understandable when a view is moved between sidebar and panel containers or starts hidden or collapsed. Acceptance requires an agreed state-transition matrix and checks that reversing the target view does not unexpectedly hide unrelated views.
- **Trace:**

  > The local shard exposes IViewPaneContainer.toggleViewVisibility in src/vs/workbench/common/views.ts; the missing implementations were read from GitHub main. OpenVariablesViewAction in src/vs/workbench/contrib/notebook/browser/controller/variablesActions.ts always opens and focuses the variables view. ViewsService.registerFocusViewAction also always opens its target, while registerOpenViewAction changes behavior by location and focus: sidebar repetition returns editor focus, whereas panel repetition hides the containing part. ViewPaneContainer distinguishes pane visibility from expansion. The uncertainty is the intended user-visible inverse across those independent states, explicitly raised in the issue discussion. Preserve existing generic focus commands and unrelated view layouts unless the maintainer expressly chooses a broader contract change. https://github.com/microsoft/vscode/issues/135014 consolidated related notebook alignment work here.
- **Open decisions:**
  - When a target view is already visible and expanded, should its notebook toggle collapse the pane, hide the pane, or hide its container, particularly when that container contains other views?
  - Should the second invocation restore the prior container and pane state, or apply a fixed hide operation regardless of the initial state?
  - Should the reversible behavior be exposed through separate reusable toggle commands, or change the observable contract of existing view-opening commands?

## Evidence

- **Requested semantics:** The body of https://github.com/microsoft/vscode/issues/137185 contrasts Toggle Breadcrumbs with one-way Show Outline and Show Variables. The final author comment identifies container visibility, pane membership, and collapsed state as distinct cases, and requests commands extensions can use.
- **Existing capability check:** Current GitHub main source in src/vs/workbench/contrib/notebook/browser/controller/variablesActions.ts registers notebook.openVariablesView; OpenVariablesViewAction.runWithContext always calls IViewsService.openView('workbench.notebook.variables', true), with no inverse branch. src/vs/workbench/contrib/outline/browser/outline.contribution.ts declares outline.focus; registerFocusViewAction in src/vs/workbench/services/views/browser/viewsService.ts likewise calls openView rather than hiding the view.
- **Partial generic support:** In current GitHub main, ViewsService.registerOpenViewAction generates a Show title for sidebar views and a Toggle title elsewhere. Repeating the command on a focused sidebar view returns focus to the editor without hiding the view; elsewhere it hides the containing workbench part. ViewPaneContainer.toggleViewVisibility in src/vs/workbench/browser/parts/views/viewPaneContainer.ts separately changes pane visibility. These capabilities do not establish uniform reversal across the states identified in the discussion.
- **Related issue consolidates here:** https://github.com/microsoft/vscode/issues/135014 is closed. Its maintainer comment explicitly says to track the work in this issue: https://github.com/microsoft/vscode/issues/135014#issuecomment-1343085535. It is not an open duplicate target or proof of implementation.
