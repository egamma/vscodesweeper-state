# Issue #277875 — Disable all extensions on remote

[https://github.com/microsoft/vscode/issues/277875](https://github.com/microsoft/vscode/issues/277875)

## Summary

A real gap remains: current VS Code can suppress selected automatic remote installations or disable extensions broadly, but it has no persistent control that disables all user extensions only on remote hosts while preserving local extensions.

## Change summary

Add a persistent configuration that prevents extensions from running or being installed on remote machines without disabling their local copies.

## Best solution

Provide an explicit remote-scoped extension policy that can prevent user extensions from being installed or activated on remote authorities while leaving local UI extensions unaffected.

## Vision fit

- **Fit:** aligned
- **Reason:** Giving users control over extension resource consumption on constrained remote hosts supports VS Code's remote-development and performance commitments.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/remote/common/remote.contribution.ts`, `src/vs/workbench/contrib/extensions/electron-browser/remoteExtensionsInit.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/services/extensionManagement/test/browser/extensionEnablementService.test.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsActions.test.ts`
- **Validation:** Add extension-management tests with separate local and remote servers asserting that the chosen remote-disable policy prevents remote user-extension installation and activation while equivalent local extensions remain enabled.
- **Behavior:**

  > Users can persistently disable user extensions on remote machines without disabling their local copies. Reconnecting or opening another workspace must not silently reactivate or reinstall extensions covered by that policy. Local UI extensions remain usable. Acceptance must cover an initial connection, reconnection, and an extension installed in both local and remote locations.
- **Trace:**

  > The existing `remote.defaultExtensionsIfInstalledLocally` setting is registered in src/vs/workbench/contrib/remote/common/remote.contribution.ts and consumed by `InstallRemoteExtensionsContribution.installExtensionsIfInstalledLocallyInRemote` in src/vs/workbench/contrib/extensions/electron-browser/remoteExtensionsInit.ts; it only controls a configured auto-install list. The bulk command in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts uses `ExtensionsWorkbenchService.local` and `DisabledGlobally`, while `ExtensionsWorkbenchService.local` in src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts merges extension servers and selects one primary copy per identifier. This leaves no explicit persistent remote-only all-extension control. The boundary is extension installation and enablement on remote authorities: local enablement behavior and unrelated Remote-SSH connection behavior must not change. Related reports are https://github.com/microsoft/vscode/issues/248248 and https://github.com/microsoft/vscode/issues/292476.
- **Open decisions:**
  - Should the control apply to every remote authority associated with the profile, or be configurable per remote authority?
  - Should disabling remote extensions prevent installation and reinstallation, prevent activation, or guarantee both?
  - Should the control cover only user-installed extensions, matching the existing bulk-disable behavior, or also disable remotely running built-in extensions?

## Evidence

- **partial existing setting:** src/vs/workbench/contrib/remote/common/remote.contribution.ts registers `remote.defaultExtensionsIfInstalledLocally`, but src/vs/workbench/contrib/extensions/electron-browser/remoteExtensionsInit.ts only uses it to suppress automatic installation of the listed product-default extensions; it is not a general remote-extension disable policy.
- **existing command is not remote-scoped:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts registers `workbench.extensions.action.disableAll`, which applies `DisabledGlobally` to the workbench service's selected installed extensions rather than expressing a persistent remote-only policy.
- **multi-server behavior:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts aggregates all extension-management servers and reduces duplicate identifiers to a primary extension in `local`, so the existing bulk command does not provide a clear independent switch for every remote installation.
- **confirmed limitation:** The discussion on https://github.com/microsoft/vscode/issues/248248 reports that clearing `remote.defaultExtensionsIfInstalledLocally` did not reliably prevent the unwanted remote installation; the issue is closed and therefore cannot be a duplicate canonical.
- **canonical search:** https://github.com/microsoft/vscode/issues/40239 is older and open but requests configuration-file enablement for individual workspace extensions, not the same remote-wide observable behavior required for a re-reviewed duplicate close. https://github.com/microsoft/vscode/issues/292476 is related but younger and Copilot-specific.
