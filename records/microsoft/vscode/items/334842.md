# Issue #334842 — SCM view keeps only one repository visible after a new repository is discovered before a previously-visible one

[https://github.com/microsoft/vscode/issues/334842](https://github.com/microsoft/vscode/issues/334842)

## Summary

Confirmed in source: onDidAddRepository's branch (A) resets didSelectRepository to false without clearing previousState, so a subsequently-discovered previously-visible repository takes branch (C) and wipes selection on everything added so far. An open PR (#334845) already fixes this — keep open pending review/merge.

## Change summary

In multi-root workspaces, discovering a new repository before a previously-visible one causes the SCM view to collapse to showing only that one previously-visible repository, and the bad state persists across restarts.

## Best solution

Land https://github.com/microsoft/vscode/pull/334845 (or an equivalent fix that stops consulting `previousState` once branch (A) has decided to select everything, e.g. clearing `previousState` before returning) in scmViewService.ts.
