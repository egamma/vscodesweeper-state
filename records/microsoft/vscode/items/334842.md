# Issue #334842 — SCM view keeps only one repository visible after a new repository is discovered before a previously-visible one

[https://github.com/microsoft/vscode/issues/334842](https://github.com/microsoft/vscode/issues/334842)

## Summary

The discovery-order visibility defect remains in current source. Keep this open while the linked implementation candidate is reviewed; it has not merged.

## Change summary

Discovering a new repository between previously visible repositories hides earlier repositories and persists the reduced selection across restarts.

## Best solution

Review https://github.com/microsoft/vscode/pull/334845 and resolve its interaction with intentionally hidden repositories before landing a fix. Repository visibility should not depend on discovery order, and restoration should preserve intentional selections when no new repository appears.

## Evidence

- **Current-source defect:** In src/vs/workbench/contrib/scm/browser/scmViewService.ts:350–425, SCMViewService.onDidAddRepository retains previousState and resets didSelectRepository to false after selecting all repositories for index === -1. With saved all=[A,B], visible=[0,1] and discovery A→C→B, A starts the restored selection, C selects A and C and resets the flag, then B's first-visible branch clears both earlier selections. Only B remains visible. This was traced without executing or modifying the checkout.
- **Persistent consequence:** SCMViewService.onWillSaveState in src/vs/workbench/contrib/scm/browser/scmViewService.ts:568–578 serializes the resulting visibleRepositories into scm:view:visibleRepositories after loading completes. The reduced selection therefore becomes the next session's restoration state.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/334845 is verified OPEN with no merge commit and explicitly states Fixes #334842. Its author reports paired reproduction runs against the original and patched binaries, and identifies the observable tradeoff that newly discovered repositories would also reveal intentionally hidden repositories. An open fixing PR is not a completed fix.
- **Related but not a duplicate:** https://github.com/microsoft/vscode/issues/301028 is verified OPEN and older, but reports intentionally hidden repositories becoming visible after restart—the opposite observable symptom. It shares restoration logic but does not satisfy the same-symptom duplicate requirement for this re-reviewed issue.
