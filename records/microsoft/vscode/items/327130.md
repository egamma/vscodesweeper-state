# Issue #327130 — gen_ai.agent.name never reflects the active custom agent for top-level (non-subagent) sessions

[https://github.com/microsoft/vscode/issues/327130](https://github.com/microsoft/vscode/issues/327130)

## Summary

Traced this on current main: the report is accurate — for top-level (non-subagent) sessions, `gen_ai.agent.name` is always the generic participant/agent-type string, never the active custom `.agent.md` persona's real name, even though that name is already resolved and available (as `modeInstructions2.name` / `customModeName`) at the exact point the session-start event and metrics are emitted.

## Change summary

Thread the active custom agent's real display name into `gen_ai.agent.name` (session.start event and agent metrics) for top-level/foreground sessions, not just runSubagent-dispatched ones.

## Best solution

This needs a maintainer product call, not a mechanical patch: `extensions/copilot/src/extension/intents/node/toolCallingLoop.ts` (around line 1237-1241) deliberately keeps `customModeName` out of `agentName` to avoid metric cardinality blowup, since `agentName` also feeds `GenAiMetrics.recordAgentDuration`/`recordAgentTurnCount` (extensions/copilot/src/platform/otel/common/genAiMetrics.ts:78-88) as a metric dimension. A safe path forward is likely to surface the custom persona name as a *separate* low-cardinality-safe attribute on `copilot_chat.session.start` (extensions/copilot/src/platform/otel/common/genAiEvents.ts:87-99) — mirroring the existing `CopilotChatAttr.MODE_NAME` already set on the `invoke_agent` span — without changing what feeds the per-agent metrics.
