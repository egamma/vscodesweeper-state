# Issue #58980 — Relative problem paths don't take `cwd` into account

[https://github.com/microsoft/vscode/issues/58980](https://github.com/microsoft/vscode/issues/58980)

## Summary

Still valid on current main: the problem matcher's relative file resolution defaults to `${workspaceFolder}` and never considers the task's `options.cwd`. The request for automatic alignment between the two is a reasonable enhancement with 12 upvotes, worth keeping open.

## Change summary

When a task sets `options.cwd`, the problem matcher should use that cwd (not the workspace folder) as the base for resolving relative file paths.

## Best solution

In `src/vs/workbench/contrib/tasks/common/problemMatcher.ts`, when `fileLocation` is unspecified or `relative` without an explicit prefix, default to the task's `options.cwd` instead of `${workspaceFolder}`. The change also needs plumbing in `terminalTaskSystem.ts` where matchers are resolved, to pass the task's resolved cwd. A compat flag or opt-in may be warranted given the breaking-change concern raised by the maintainer in the original comment.
