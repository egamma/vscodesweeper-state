# Issue #203983 — SCM Input - steals focus

[https://github.com/microsoft/vscode/issues/203983](https://github.com/microsoft/vscode/issues/203983)

## Summary

Team-authored bug, still present on main. The SCM input widget has several paths that unconditionally steal focus (e.g. `onDidChangeFocus` handler, `onDidChangeValidationMessage` with `focus: true`, and `shouldFocusAfterLayout`). After a commit with hooks, the input value change or re-validation can pull focus away from whatever the user is doing (like the command palette). Keeping open per team-authored policy.

## Change summary

After a commit with slow hooks, the SCM input editor steals focus from other UI elements like the command palette.

## Best solution

Guard the focus-stealing paths in `src/vs/workbench/contrib/scm/browser/scmInput.ts` (line 453: `input.onDidChangeFocus(() => this.focus())` and the validation-message handler on line 454) to only call `this.focus()` when the SCM view already has DOM focus or the user explicitly requested it. The `onDidChangeFocus` listener should check `this.hasFocus()` or whether the SCM pane is active before stealing focus.
