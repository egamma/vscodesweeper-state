# Issue #315925 — Custom editor diffs error after reloading

[https://github.com/microsoft/vscode/issues/315925](https://github.com/microsoft/vscode/issues/315925)

## Summary

The clipboard-comparison reload failure remains explainable in current source: custom diff serializers restore a temporary clipboard URI whose content provider no longer exists, so document resolution fails before the extension's diff callback. Keep this team-authored bug open; no verified canonical or issue-referencing fix was found.

## Change summary

Reloading a custom text editor clipboard comparison restores an unresolvable diff and never calls resolveCustomTextEditorSideBySideDiff.

## Best solution

Make custom clipboard comparisons follow a deliberate reload lifecycle without restoring broken editors, while preserving restoration of ordinary custom diffs. Normal text comparisons provide a transient-editor precedent; establish whether custom comparisons should follow it or retain their original clipboard snapshot.

Also verify ordinary file-backed custom diffs still restore and resolve both sides. Add automated persistence/resolution regression coverage for the selected contract.
- **Behavior:**

  > A custom text editor clipboard comparison currently becomes an error editor after window reload, and resolveCustomTextEditorSideBySideDiff is never invoked. Reload must not leave an editor pointing at an unavailable clipboard resource. Decide whether this temporary comparison should disappear on reload, as normal transient text comparisons do, or restore the original comparison snapshot. Ordinary file-backed custom diffs must continue restoring normally, and changing the clipboard must not silently substitute different comparison contents.
- **Trace:**

  > CompareWithClipboardAction.run in src/vs/workbench/contrib/files/browser/fileActions.ts creates a clipboardCompareN resource using a temporary text content provider. CustomEditorDiffInputSerializer and CustomEditorSideBySideDiffInputSerializer in src/vs/workbench/contrib/customEditor/browser/customEditorInputFactory.ts persist only resource identities and metadata, then reconstruct those inputs after reload. MainThreadCustomEditors.registerEditorProvider resolves both text models before dispatching the side-by-side callback; CustomTextEditorModel.create reaches ResourceModelCollection.doCreateReferencedObject, which cannot resolve the restored clipboard URI. The defect is confirmed from source, not a runtime attempt. Normal TextResourceEditorInput persistence offers a transient-editor precedent, but the issue does not explicitly choose between discarding the comparison and retaining a snapshot. Preserve regular custom diff restoration and avoid changing unrelated virtual-resource providers or the proposed extension API.
- **Open decisions:**
  - Should custom clipboard comparisons be transient across window reload, following normal text comparisons, or should they restore the original clipboard snapshot?
