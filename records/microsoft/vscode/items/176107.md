# Issue #176107 — Same file nested under two different files cannot be renamed

[https://github.com/microsoft/vscode/issues/176107](https://github.com/microsoft/vscode/issues/176107)

## Summary

The bug remains source-reproducible on current main: file nesting can place the same ExplorerItem beneath multiple parents, but the explorer model and tree identity represent only one occurrence reliably. The existing bug and file-explorer routing remain appropriate.

## Change summary

Renaming a file fails when file-nesting patterns display that file beneath two different parent files.

## Best solution

Define how multiple matching nesting parents should be represented, then ensure the resulting displayed occurrence or occurrences support rename and other file actions without ambiguous tree identity or parent state.

## Evidence

- **multiple nesting parents:** src/vs/workbench/contrib/files/common/explorerFileNestingTrie.ts:64-103 finds every root ancestor and adds a matching file to each ancestor's child set, so the reported configuration can intentionally return the same file beneath both matching `.prettierignore*` parents.
- **single-parent model:** src/vs/workbench/contrib/files/common/explorerModel.ts:338-362 reuses the same ExplorerItem in every matching parent's `nestedChildren` array while repeatedly overwriting its singular `nestedParent`, leaving only the last parent represented on the item.
- **ambiguous tree identity:** ExplorerItem.getId() in src/vs/workbench/contrib/files/common/explorerModel.ts:192-199 identifies an item only by root and resource, and src/vs/workbench/contrib/files/browser/views/explorerView.ts:85-92 passes that ID to the tree. Two rendered occurrences of the same resource therefore have the same object and identity.
- **rename path:** src/vs/workbench/contrib/files/browser/fileActions.ts:995-1033 starts inline editing on the selected ExplorerItem, while ExplorerView.setEditable in src/vs/workbench/contrib/files/browser/views/explorerView.ts:457-481 expands, refreshes, and reveals that shared item. The duplicate occurrence cannot be addressed independently through this path.
