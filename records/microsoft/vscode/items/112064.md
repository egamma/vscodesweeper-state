# Issue #112064 — Pressing `shift-left/right` will exit multi-caret mode

[https://github.com/microsoft/vscode/issues/112064](https://github.com/microsoft/vscode/issues/112064)

## Summary

This remains a source-reproducible editor bug: in column-selection mode, Shift+Left/Right reconstructs a box selection from only the primary cursor after ordinary movement clears the stored column-selection state, dropping the other aligned cursors.

## Change summary

Preserve aligned multiple cursors when Shift+Left/Right starts or adjusts a selection in column-selection mode.

## Best solution

Make horizontal column-selection commands preserve an existing aligned multi-cursor range when reconstructing column-selection state, while retaining current rectangular-selection behavior and the established handling of unaligned cursors.

- **Behavior:**

  > With column-selection mode enabled, aligned cursors on multiple lines must remain multiple cursors when Shift+Left or Shift+Right initiates or adjusts their selections. Each cursor should select the corresponding character without collapsing the set to the primary cursor. Existing rectangular selection behavior, including its handling of uneven line lengths, must remain unchanged.
- **Trace:**

  > In src/vs/editor/browser/coreCommands.ts, column-selection mode overrides Shift+Left/Right with CursorColumnSelectLeft/CursorColumnSelectRight, whose ColumnSelectCommand reads viewModel.getCursorColumnSelectData(). Ordinary cursor movement goes through CursorMoveBasedCommand and Cursor.setStates in src/vs/editor/common/cursor/cursor.ts, which clears _columnSelectData while preserving all cursor states. The fallback in Cursor.getCursorColumnSelectData() then derives the next column-selection range from only getPrimaryCursor(), and ColumnSelection.columnSelect in src/vs/editor/common/cursor/cursorColumnSelection.ts generates cursors only across that single derived line range. Existing tests in src/vs/editor/test/browser/controller/cursor.test.ts exercise the same commands but omit the aligned multi-cursor transition. Keep the boundary to column-selection state reconstruction; regular multi-cursor Shift+Left/Right behavior and unaligned box-selection semantics must not change.

## Evidence

- **confirmed reproduction:** A VS Code team member confirmed the behavior with a recording in 2021, and a separate user reproduced it with default keybindings on Ubuntu 22.04 in 2025.
- **keybinding path:** src/vs/editor/browser/coreCommands.ts registers Shift+Left/Right at higher priority as CursorColumnSelectLeft/CursorColumnSelectRight whenever EditorContextKeys.columnSelection is active.
- **source root cause:** Cursor.setStates in src/vs/editor/common/cursor/cursor.ts clears _columnSelectData after ordinary cursor movement; getCursorColumnSelectData then reconstructs fallback state exclusively from getPrimaryCursor(), so the next ColumnSelectCommand produces selections from one cursor's line range and discards the other aligned cursors.
- **missing regression coverage:** src/vs/editor/test/browser/controller/cursor.test.ts extensively covers keyboard column selection but has no case that starts with multiple aligned cursors, performs ordinary movement, and then invokes a horizontal column-selection command.
