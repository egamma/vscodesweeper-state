# Issue #176075 — different behavior of commands in right click menu of explorer

[https://github.com/microsoft/vscode/issues/176075](https://github.com/microsoft/vscode/issues/176075)

## Summary

A real consistency gap remains on current main: opening the Explorer background context menu preserves the selection, but New File and New Folder ignore it and fall back to the first workspace root. The existing `polish`, `help wanted`, and `file-explorer` labels appropriately keep this accepted, bounded work open.

## Change summary

Make Explorer background-context-menu commands consistently target the selected or most recently interacted folder, with labels that accurately describe workspace-wide actions.

## Best solution

Use one predictable target for Explorer background context-menu actions: the selected folder when available, otherwise the most recently interacted workspace folder, while preserving existing item-context and multi-selection behavior. Cover the background-menu creation path with a focused Explorer view test.
