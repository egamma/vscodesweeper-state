# Issue #270513 — Support launching Code for updating purposes only

[https://github.com/microsoft/vscode/issues/270513](https://github.com/microsoft/vscode/issues/270513)

## Summary

Keep open: the desktop CLI still lacks an update-only launch mode, and a maintainer explicitly broadened this accepted Backlog request to cover all operating systems. The similar newer request was closed as a duplicate, not implemented.

## Change summary

Provide a CLI invocation that updates the VS Code application without opening an interactive workspace and exits when finished.

## Best solution

Define an update-only desktop launch contract in the CLI and application lifecycle, reusing the platform update services. Settle supported installation types and behavior when another Code instance is running before implementation.

- **Reason:** A noninteractive application-update command supports CLI/UI interplay and managed installation workflows without adding default UI.

## Plan brief

- **Likely files:** `src/vs/platform/environment/common/argv.ts`, `src/vs/platform/environment/node/argv.ts`, `src/vs/code/node/cli.ts`, `src/vs/platform/update/common/update.ts`, `src/vs/platform/update/electron-main/abstractUpdateService.ts`, `src/vs/platform/update/electron-main/updateService.linux.ts`, `src/vs/platform/update/electron-main/updateService.darwin.ts`, `src/vs/platform/update/electron-main/updateService.win32.ts`
- **Validation:** For each supported installation type, invoke the update-only command with Code stopped and an older installed version; verify that the application version advances, no interactive workspace opens, and the command terminates. Also check already-current, update-error, and already-running-instance outcomes against the agreed exit-code and lifecycle contract.
- **Behavior:**

  > IT administrators need to launch the installed VS Code application solely to perform an update and then exit, without opening an interactive workspace. This request concerns the desktop application, not extensions or the standalone CLI binary. Acceptance should cover successful updating and termination, an already-current installation, and explicit failure reporting. Supported installation types and behavior with an existing Code process need agreement.
- **Trace:**

  > The desktop flag registry in src/vs/platform/environment/node/argv.ts and CLI-only dispatch in src/vs/code/node/cli.ts::shouldSpawnCliProcess have no application-update-only route. Workbench update commands invoke IUpdateService, whose platform implementations expose different completion behavior; LinuxUpdateService::doDownloadUpdate currently opens a download URL rather than installing unattended. The Rust standalone CLI updater targets TargetKind::Cli and is not coverage for this desktop request. Preserve normal desktop startup, extension-maintenance commands, and existing update controls. https://github.com/microsoft/vscode/issues/289805 supplies corroborating managed-installation demand but is newer and closed as duplicate; the present issue remains the accepted cross-platform request. The trace establishes the missing capability, but not a complete headless application-lifecycle design.
- **Open decisions:**
  - Which operating-system and installation-type combinations must support unattended installation, and what observable outcome should unsupported combinations return?
  - When VS Code is already running, should the command defer the update, fail without disturbing the session, or coordinate with the running instance?
  - What exit-status contract should distinguish a completed update, an already-current installation, a deferred update, and failure?

## Evidence

- **Accepted cross-platform scope:** https://github.com/microsoft/vscode/issues/270513 requests background application updating followed by exit. The issue is in Backlog, and the supplied February 21, 2026 maintainer comment explicitly broadens it to be non-OS-specific.
- **Existing desktop CLI does not cover the request:** src/vs/platform/environment/node/argv.ts registers --update-extensions and --disable-updates, but no application-update-only flag. src/vs/code/node/cli.ts::shouldSpawnCliProcess recognizes extension maintenance and other CLI-only tasks, not desktop application updating.
- **Standalone CLI updating is a different capability:** cli/src/commands/args.rs describes its Update subcommand as updating the CLI. cli/src/self_update.rs::get_current_release explicitly requests TargetKind::Cli, and do_update replaces the running CLI executable; it does not update the installed desktop application.
