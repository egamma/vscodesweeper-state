## Evidence

- **Current cancellation routing:** src/vs/workbench/contrib/mcp/common/mcpServerRequestHandler.ts:394-398 checks request.params.requestId for truthiness and calls this._rpc.cancelPendingRequest. Consequently ID 0 is ignored, while a nonzero colliding ID targets an outgoing editor request.
- **Source-confirmed direction mismatch:** In src/vs/base/common/jsonRpcProtocol.ts, sendRequest populates _pendingRequests and cancelPendingRequest cancels the promise in that map. _handleRequest instead creates a separate local CancellationTokenSource without indexing it by incoming request ID. The notification therefore cannot reach that incoming handler's token. mcpServerRequestHandler.ts forwards this token to ordinary sampling/createMessage and elicitation/create handlers.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/344912 is verified open with merged_at null and explicitly says Fixes #344911. Its body reports incoming-request tracking, cancellation-token tests, and an MCP regression test that fails on main; these are author-reported results, not tests executed during this review.

The linked PR explicitly leaves response emission after cancellation unchanged, so that concern should be resolved during review rather than assumed covered.
