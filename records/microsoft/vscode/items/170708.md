# Issue #170708 — Cannot paste full file paths after copying file from file explorer on Linux

[https://github.com/microsoft/vscode/issues/170708](https://github.com/microsoft/vscode/issues/170708)

## Summary

This is a duplicate of the more recent and better-diagnosed https://github.com/microsoft/vscode/issues/320375, which describes the same root cause (Electron/Chromium clipboard on Linux exposes `text/plain` with filename only, ignoring `text/uri-list` with full path) and has a detailed analysis. Proposing duplicate close in favor of #320375 which has the stronger write-up.

## Change summary

Pasting a file copied from a Linux file manager (Nautilus, Dolphin) into VS Code pastes only the filename or a relative path instead of the full absolute file path.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/320375 which has a thorough root-cause analysis. The fix likely involves reading `text/uri-list` from the system clipboard via Electron's native clipboard API when handling paste on Linux, rather than relying solely on `text/plain`. This may require changes in `src/vs/editor/browser/dataTransfer.ts` or the Electron-side clipboard service to surface the `text/uri-list` MIME type from external clipboard sources.

## Evidence

- **same root cause:** Both this issue (#170708) and https://github.com/microsoft/vscode/issues/320375 report that copying a file in a Linux file manager and pasting into VS Code yields only the filename instead of the full path. The clipboard contains `text/uri-list` with the full `file://` URI but VS Code reads `text/plain` which has only the filename.
- **code trace:** In `src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts`, the `PathProvider` (line 101–145) correctly handles `text/uri-list` by extracting `file://` URIs and converting to `fsPath`. However, the `text/uri-list` MIME type is never populated from external clipboard sources on Linux — `toExternalVSDataTransfer` in `src/vs/editor/browser/dataTransfer.ts` only maps the internal URI list type, and Electron/Chromium does not expose `text/uri-list` from the system clipboard on Linux.
- **native clipboard limitation:** In `src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts`, `readResources()` uses a custom internal buffer format (`NativeClipboardService.FILE_FORMAT`), not the system's `text/uri-list`. External file manager copies are invisible to this pathway.
- **better canonical:** https://github.com/microsoft/vscode/issues/320375 (opened 2026-06-08) has a detailed root-cause analysis with clipboard MIME type dumps, attempted fixes, and a concrete suggested fix approach — making it the better canonical issue for tracking.
- **multiple confirmations:** Multiple commenters on this issue confirmed the bug across Ubuntu, KDE/Dolphin, and various VS Code versions from 1.74 through 1.87.
