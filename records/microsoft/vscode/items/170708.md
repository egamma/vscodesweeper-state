# Issue #170708 — Cannot paste full file paths after copying file from file explorer on Linux

[https://github.com/microsoft/vscode/issues/170708](https://github.com/microsoft/vscode/issues/170708)

## Summary

This remains a confirmed Linux clipboard bug and should be routed to the editor clipboard area. Recent reports reproduce it with Nautilus and Nemo, while current source still lacks a path from the native Linux `text/uri-list` format into the editor's otherwise-correct URI paste providers.

## Change summary

Pasting a file copied from a Linux file manager into an editor or integrated terminal inserts only the filename, a relative representation, or `/` instead of the absolute path.

## Best solution

Keep this older report as the canonical issue, consolidate https://github.com/microsoft/vscode/issues/320375 into it, and make the desktop clipboard path expose Linux file-manager `text/uri-list` data to the existing absolute-path paste provider without changing ordinary text or Markdown paste behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts`
- **Validation:** On Linux under the supported display backends, copy one and multiple files from Nautilus, Nemo, and Dolphin and paste into a plain-text editor: absolute paths must be inserted; then verify normal text paste and Markdown paste-as-link behavior remain unchanged.
- **Behavior:**

  > Copying files or folders from a Linux file manager and pasting into a plain-text VS Code editor must insert their full absolute paths. Multiple copied resources must remain distinguishable, ordinary text clipboard contents must paste unchanged, and language-specific rich paste such as Markdown links must retain its existing selection behavior. Acceptance includes Nautilus, Nemo, and Dolphin coverage where available.
- **Trace:**

  > The browser paste event is converted into a VS data transfer in `CopyPasteController` at src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts. If it lacks `text/uri-list`, `mergeInDataFromCopy` asks `IClipboardService.readResources()`, but the desktop implementation in src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts reads only VS Code's private `code/file-list` format. When URI data is present, `PathProvider` in src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts already produces the expected absolute file paths, so the uncertainty begins at acquisition of external Linux clipboard formats. Preserve internal Explorer clipboard transfers, plain-text fallback, and Markdown's paste providers. The detailed current reproduction is https://github.com/microsoft/vscode/issues/320375.
- **Open decisions:**
  - Should the native clipboard service read Linux `text/uri-list` directly, or should external resource extraction be introduced through a separate platform-specific API?
  - Which clipboard encodings and format aliases must be supported across X11 and Wayland file managers?
  - When both `text/plain` and file URIs are present, should absolute paths be the automatic default in all plain-text editors or only an available Paste As choice?

## Evidence

- **current reproduction:** The September 2026 comment on https://github.com/microsoft/vscode/issues/170708 reports that Nemo pastes `/` in VS Code 1.126.0 while other text editors receive the full path.
- **independent confirmations:** The issue contains independent Nautilus and Dolphin confirmations, and https://github.com/microsoft/vscode/issues/320375 reports the same behavior through VS Code 1.135.0 with clipboard inspection showing a correct `text/uri-list` alongside an insufficient `text/plain` value.
- **source trace:** src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts merges URI data from `IClipboardService.readResources`, and src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts already converts file URIs to absolute paths through `PathProvider`.
- **native clipboard gap:** src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts implements `readResources()` by reading only VS Code's private `code/file-list` format, so externally copied Linux `text/uri-list` data is not recovered through this fallback.
- **partial implementation:** Commit 9ab88c7abc4d90e67c94ac341bc0fee7679c5556 added default URI-list paste providers, but later reproductions show that Linux file-manager clipboard data still does not consistently reach those providers.
- **canonical assessment:** https://github.com/microsoft/vscode/issues/164 concerns transferring actual files between VS Code and native applications, not inserting copied file paths as editor text; the newer https://github.com/microsoft/vscode/issues/320375 is a better-diagnosed instance of this older report rather than a broader canonical.
