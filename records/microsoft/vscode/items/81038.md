# Issue #81038 — [SCSS] Consider using new SCSS grammar (nested properties with shorthand values break syntax highlighting) 

[https://github.com/microsoft/vscode/issues/81038](https://github.com/microsoft/vscode/issues/81038)

## Summary

Still valid: VS Code's SCSS grammar is sourced from the archived atom/language-sass repo, which has no maintainer to fix nested-property highlighting. The title's ask — adopting a new SCSS grammar — remains the right direction and is unresolved on current main.

## Change summary

SCSS nested properties with shorthand values (e.g. `border: 0 { radius: 30px; }`) break syntax highlighting because the upstream TextMate grammar from atom/language-sass doesn't support them.

## Best solution

Replace the archived atom/language-sass grammar with a maintained alternative (a community TextMate grammar, or tree-sitter-scss once tree-sitter tokenization ships). The grammar source is `extensions/scss/syntaxes/scss.tmLanguage.json`; the header still points at atom/language-sass. Related open issue https://github.com/microsoft/vscode/issues/266686 suffers from the same root cause and would be fixed by a grammar replacement.
