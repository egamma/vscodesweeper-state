# Issue #325377 — Support cross-agent sessions and harness parameter for createSession/createChat

[https://github.com/microsoft/vscode/issues/325377](https://github.com/microsoft/vscode/issues/325377)

## Summary

Keep open for design: current main now resolves model names and providers for cross-agent session creation, but it does not expose the requested complete harness contract, custom-agent/runtime selection, or harness discovery. This is also a team-authored feature request parked in On Deck, so judgment-based closure is barred.

## Change summary

Expose deterministic harness selection and discovery for create_session/create_chat so callers can target a provider, model, custom agent, and supported runtime configuration without silent fallback.

## Best solution

Define a stable machine-readable harness descriptor and discovery contract, then use it to validate and route independent session creation through the selected provider, model, custom agent, and supported configuration. The design should explicitly define whether create_chat may select only options within its owning session's provider or can create work under a different harness.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/shared/sessionServerTools.ts`, `src/vs/platform/agentHost/node/agentService.ts`, `src/vs/platform/agentHost/common/agent.ts`, `src/vs/platform/agentHost/test/node/sessionServerTools.test.ts`
- **Validation:** Extend the session server-tool unit suite to verify harness enumeration/resolution, exact provider/model/custom-agent forwarding, rejection of unknown or ambiguous harnesses without fallback, and the chosen create_chat cross-harness boundary.
- **Behavior:**

  > Agent-facing session-management tools can discover valid harness choices and deterministically select the intended provider, model, custom agent, and supported runtime configuration when creating work. Unknown, ambiguous, or unsupported selections return a clear error and never silently discard model or harness information. create_chat follows an explicitly documented provider/harness boundary. Acceptance includes machine-readable discovery results and unit coverage for successful routing and rejected selections.
- **Trace:**

  > The tool schemas and argument resolution live in src/vs/platform/agentHost/node/shared/sessionServerTools.ts. Current main already accepts model IDs/display names, resolves them against the model catalogs supplied by AgentService._createSessionServerToolAccessor, derives the provider for independent sessions, and rejects ambiguous names. AgentService forwards provider/model/config through IAgentCreateSessionConfig, whose definition in src/vs/platform/agentHost/common/agent.ts also supports an initial AgentSelection, but the server tools do not expose that agent field or a harness discovery contract. create_chat is intentionally bound to an existing session and scopes model lookup to AgentSession.provider(session), so cross-harness chat semantics begin at a public behavior decision rather than a missing local guard. Preserve current-session lifecycle, workspace/worktree behavior, recursion limits, confirmation requirements, and provider capability checks.
- **Open decisions:**
  - Is the public selection contract a canonical opaque harness ID, a structured provider/model/agent/config object, or both with one canonical resolution result?
  - Which runtime choices belong in the harness contract, and which remain separate session configuration such as workspace isolation and sandbox policy?
  - Should create_chat permit only models and custom agents supported by its owning session's provider, or should selecting another harness create an independent session instead?
  - Should discovery be exposed as dedicated list/resolve tools or as one catalog operation, and which stability and capability metadata is part of that public machine-readable contract?

## Evidence

- **partial capability on main:** src/vs/platform/agentHost/node/shared/sessionServerTools.ts exposes `model` on both create_session schemas; `resolveModel` accepts an exact ID or unique display name, rejects unknown or ambiguous selections, and independent-session creation derives `IAgentCreateSessionConfig.provider` from the resolved model.
- **create_chat boundary:** getCreateChatArgs in src/vs/platform/agentHost/node/shared/sessionServerTools.ts resolves models only within `AgentSession.provider(session)`, and createChat forwards only title, model, and working directories. There is no harness or custom-agent argument.
- **missing discovery contract:** AgentService._createSessionServerToolAccessor in src/vs/platform/agentHost/node/agentService.ts internally aggregates provider model catalogs through `getModels`, but the server-tool group exposes no listHarnesses/resolveHarness-style tool or equivalent machine-readable provider, custom-agent, and configuration catalog.
