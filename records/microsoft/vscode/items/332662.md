# Issue #332662 — Diff Editor: Show semantic blocks of code, instead of N lines before/after

[https://github.com/microsoft/vscode/issues/332662](https://github.com/microsoft/vscode/issues/332662)

## Summary

Keep open: the diff editor still chooses unchanged context by line count, not semantic block boundaries. This team-authored, accepted request needs a design decision; no verified duplicate or concrete implementation was found.

## Change summary

Show semantic code blocks around changes instead of a fixed number of context lines.

## Best solution

Provide structurally meaningful context around diff changes without changing which text is considered changed. First settle the block-selection contract, activation behavior, and fallback for languages without structural information.

- **Behavior:**

  > The goal is to display meaningful semantic code blocks around diff changes rather than cutting context at an arbitrary line count. Acceptance should demonstrate that a change inside a larger code block retains the agreed structural context and that unrelated unchanged code can still be hidden. Both inline and side-by-side views must retain the same actual changes. The precise block granularity, activation behavior, and fallback remain to be agreed with the maintainer.
- **Trace:**

  > DiffEditorViewModel.updateUnchangedRegions in src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts calls UnchangedRegion.fromDiffs using numeric context options and document line counts. UnchangedRegion.fromDiffs computes the inverse of the changed line mappings and trims those unchanged ranges by minContext; this conclusively establishes the current line-based behavior, not a bug. DiffEditorOptions and editorConfigurationSchema expose the existing numeric controls, and diffEditorWidget.test.ts contains direct UnchangedRegion tests. The trace does not establish a structural-information provider for this path; selecting and supporting one belongs to the planning investigation. Preserve diff computation, change navigation, and existing manual reveal behavior rather than treating this as a semantic diff-alignment request. https://github.com/microsoft/vscode/issues/191453 concerns alignment and is related but does not own this context-display request.
- **Open decisions:**
  - What defines the displayed semantic block: the smallest enclosing syntax block, a whole function or symbol, or another structural unit, particularly for nested and adjacent changes?
  - Should semantic context replace the current numeric context behavior by default or be an opt-in mode?
  - When structural information is unavailable or delayed, should the editor retain numeric context, use indentation-based blocks, or show all surrounding code?
