# Issue #24916 — SCM - Support keyboard shortcuts

[https://github.com/microsoft/vscode/issues/24916](https://github.com/microsoft/vscode/issues/24916)

## Summary

Keep open: current source still does not provide selection-aware staging and unstaging through direct SCM keyboard shortcuts. This accepted Backlog request has 74 upvotes and maintainer support; existing keyboard workarounds cover only part of the requested workflow.

## Change summary

Support efficient keyboard-driven SCM actions on focused or selected changes, including staging, unstaging, and continued review without losing list focus.

## Best solution

Provide discoverable, bindable SCM actions that target the list's focused or selected resources rather than the unrelated active editor, with predictable focus after staging. Agree on default shortcuts and selection semantics before implementing, coordinating with the narrower SCM selection and navigation requests.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/contrib/scm/browser/scm.contribution.ts`, `extensions/git/src/commands.ts`, `extensions/git/package.json`
- **Validation:** In a Git workspace with several changed files, keep file A open while focusing file B in SCM and invoke the agreed staging shortcut: only B should stage. Repeat with multiple selected files, staged files for unstaging, no active editor, and multiple repositories; verify the agreed post-action focus behavior and unchanged editor-context commands.
- **Behavior:**

  > Users should be able to stage and unstage changes directly from the focused SCM list without first opening a diff or traversing inline toolbar buttons. Actions should target the intended focused or selected SCM resources, not an unrelated active editor. The finished workflow should support repeated review and staging with predictable keyboard focus. Acceptance includes single-file and multi-selection operations, no active editor, multiple repositories, and unchanged behavior outside SCM list focus.
- **Trace:**

  > CommandCenter.stage and CommandCenter.unstage in extensions/git/src/commands.ts use getSCMResource() when invoked without resource arguments; its fallback reads the active editor rather than SCM selection. RepositoryPaneActionRunner.runAction in src/vs/workbench/contrib/scm/browser/scmViewPane.ts already supplies selected resource arguments for menu actions, while getSelectedResources reads the tree selection. Existing editor-range shortcuts and SCM input/resource-group focus commands provide partial support, not the central requested workflow. Preserve editor-context commands, commit-message input, and provider-specific action semantics. Coordinate with https://github.com/microsoft/vscode/issues/211519 and https://github.com/microsoft/vscode/issues/339786 without treating their narrower scopes as duplicate canonicals. The unresolved product boundary is shortcut defaults, focused-row versus multi-selection precedence, and post-action focus; runtime behavior was not exercised.
- **Open decisions:**
  - Should selection-aware SCM actions ship with default shortcuts, or initially be commands users bind themselves?
  - When the focused row is outside an existing multi-selection, should a keyboard action target that row or the selected resources?
  - After staging removes a row from Changes, which remaining row should receive focus so repeated keyboard staging is predictable?
