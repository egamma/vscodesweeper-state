# Issue #68184 — Support comments in UI editors (settings and keyboard shortcuts)

[https://github.com/microsoft/vscode/issues/68184](https://github.com/microsoft/vscode/issues/68184)

## Summary

The requested UI support for personal comments and comment-based filtering remains missing. Keep this accepted Backlog request open: JSON editing is only a workaround, and the related comment-deletion reports do not own its full scope.

## Change summary

Allow users to add and view personal comments in the Settings and Keyboard Shortcuts UI editors, including filtering for commented entries.

## Best solution

Define a consistent comment-association model for both preferences editors, including comments attached to inactive settings or keyboard rules, before exposing comment editing, viewing, and filtering. Coordinate reset-preservation behavior with https://github.com/microsoft/vscode/issues/275792 without replacing this broader request.

## Evidence

- **Existing capability check:** src/vs/workbench/contrib/preferences/browser/preferences.contribution.ts registers workbench.action.openSettingsJson and workbench.action.openGlobalKeybindingsFile. These provide access to JSON comments but do not expose them inside either UI editor, which is the central request.
- **Settings model and filtering:** In src/vs/workbench/services/preferences/common/preferencesModels.ts, parse() initializes setting descriptions and description ranges as empty rather than associating personal JSON comments with settings. In src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts, parseQuery() supports modified, policy, tag, extension, feature, ID, and language filtering, but has no @commented handling.
- **Keyboard shortcuts filtering:** src/vs/workbench/services/preferences/browser/keybindingsEditorModel.ts implements command, when, source, extension, keybinding, and text searches in KeybindingsEditorModel.fetch(); it does not provide personal-comment filtering.
- **Related closed reports:** https://github.com/microsoft/vscode/issues/75599 concerns comments removed when resetting settings; its maintainer response at https://github.com/microsoft/vscode/issues/75599#issuecomment-502720282 explains that deletion behavior and recommends JSON editing. https://github.com/microsoft/vscode/issues/75603 concerns richer built-in setting documentation. Neither decision settles whether users should be able to manage their own comments in both UI editors.
