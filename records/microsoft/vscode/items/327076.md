# Issue #327076 — Opening a non-existent file should not trigger "save dirty file"  (Vim/Emacs-style "nothing changed, nothing to save")

[https://github.com/microsoft/vscode/issues/327076](https://github.com/microsoft/vscode/issues/327076)

## Summary

This accepted Backlog request remains necessary: current main still marks an untouched untitled editor with an associated path dirty, and no equivalent setting exists. A linked implementation remains open in a fork, so the issue should stay open while that approach is reviewed or superseded.

## Change summary

Add an opt-in mode where opening a nonexistent path and leaving it empty does not create a dirty editor or prompt to save.

## Best solution

Add an opt-in untitled-editor setting that leaves a newly opened, empty associated path clean until its content changes, while preserving dirty state for initial content and restored backups. Review the implementation in https://github.com/tlimoncelli26/vscode/pull/1 or replace it with a repository PR covering the same behavior and tests.
