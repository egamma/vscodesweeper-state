# Issue #336121 — Copilot chat with llama.cpp fails on every second request

[https://github.com/microsoft/vscode/issues/336121](https://github.com/microsoft/vscode/issues/336121)

## Summary

Real, environment-dependent bug: the reporter narrowed it to a system http_proxy on the remote SSH host causing the second chat request (tool-response follow-up) to a self-hosted llama.cpp custom model to hang and time out on headers, while the first request always succeeds and disabling the proxy fixes it. This is plausible but not source-confirmed against a specific fetch/proxy code path, so keeping it open for further diagnosis rather than closing.

## Change summary

Copilot chat's second request (after a tool call) to a custom llama.cpp OpenAI-compatible endpoint fails with a Headers Timeout Error when a system http_proxy is set, even though the target is a local/LAN server.

## Best solution

Diagnose whether the shared keep-alive undici.Agent in extensions/copilot/src/platform/networking/node/nodeFetchFetcher.ts (or the proxy-aware `__vscodePatchedFetch` it wraps) is bypassing/mishandling proxy routing or NO_PROXY semantics for local BYOK endpoints, and fix the connection reuse/proxy interaction for custom OAI-compatible providers.
