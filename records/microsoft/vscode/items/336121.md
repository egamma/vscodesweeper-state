# Issue #336121 — Copilot chat with llama.cpp fails on every second request

[https://github.com/microsoft/vscode/issues/336121](https://github.com/microsoft/vscode/issues/336121)

## Summary

This is a real, reproducible bug in Copilot Chat's built-in BYOK/custom-model support (chatLanguageModels.json → OpenAI-compatible endpoint, e.g. llama.cpp) rather than a third-party extension issue — the reporter has narrowed it to an http_proxy interaction on remote SSH workspaces where the second agent-loop request (with tool results appended) fails with a Headers Timeout Error while the first succeeds.

## Change summary

The second chat request in an agent-mode tool-calling turn against a custom OpenAI-compatible (llama.cpp) BYOK endpoint fails with a fetch 'Headers Timeout Error' when an http_proxy is configured in the remote environment; disabling http_proxy works around it.

## Best solution

Needs deeper investigation in the BYOK/networking layer (extensions/copilot/src/extension/byok/node/openAIEndpoint.ts and the proxy-aware fetch patch used by src/platform/networking/node/nodeFetchFetcher.ts, which relies on a host-provided `__vscodeCreateFetchPatch`) to understand why only the second request in a tool-calling turn is affected when a proxy is set — likely a connection-reuse/keep-alive or proxy-tunnel issue specific to sequential requests on the same endpoint.
