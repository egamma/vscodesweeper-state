# Issue #341252 — BYOK: `oneOf` is stripped from tool `inputSchema` and sub-constraints are downgraded into description text, so the model fills mutually exclusive fields

[https://github.com/microsoft/vscode/issues/341252](https://github.com/microsoft/vscode/issues/341252)

## Summary

Thanks for the detailed report. The top-level combinator stripping is confirmed in current source: toolSchemaNormalizer.ts deletes oneOf/anyOf/allOf/not/if/then/else from every tool schema for every model family. That strips the mutual-exclusion constraint on write_agent. Keeping this open.

## Change summary

Top-level oneOf and related combinators are removed from tool schemas before BYOK providers receive them, so the model fills mutually exclusive fields together.

## Best solution

Stop deleting the top-level combinators unconditionally in toolSchemaNormalizer.ts. Either limit the removal to families known to reject them, or fold the exclusivity into the tool description, and check what the BYOK path actually delivers.
