# Issue #341252 — BYOK: `oneOf` is stripped from tool `inputSchema` and sub-constraints are downgraded into description text, so the model fills mutually exclusive fields

[https://github.com/microsoft/vscode/issues/341252](https://github.com/microsoft/vscode/issues/341252)

## Summary

Thanks for the detailed report. The normalizer in extensions/copilot still deletes top-level oneOf/anyOf/allOf/not/if/then/else for every model family, so mutually exclusive tool fields reach providers with no constraint. The code comment says this was validated against claude and gpt-4o, so how to keep the constraint without breaking those families is a maintainer decision.

## Change summary

Top-level combinators such as oneOf are stripped from tool input schemas before reaching BYOK providers, so models fill mutually exclusive fields on write_agent and every call fails validation.

## Best solution

Preserve top-level combinators for families and providers that support them, for example BYOK openai-responses. Where they must be dropped, fold the exclusivity into the tool or parameter description. Also check where minItems/maxItems/uniqueItems are moved into the description text.
