# Issue #234358 — Task API for `ShellExecutionOptions.env` type does not support `undefined` values

[https://github.com/microsoft/vscode/issues/234358](https://github.com/microsoft/vscode/issues/234358)

## Summary

Confirmed on current main: `ShellExecutionOptions.env` and `ProcessExecutionOptions.env` still only accept `string` values, while `TerminalOptions.env` accepts `string | null | undefined`. The type mismatch remains unfixed. Team-authored issue, keeping open.

## Change summary

Task API's `ShellExecutionOptions.env` and `ProcessExecutionOptions.env` should allow `undefined` (and `null`) values like `TerminalOptions.env` does, so extensions can delete environment variables via tasks.

## Best solution

Widen the `env` type in `ProcessExecutionOptions` (line ~8879) and `ShellExecutionOptions` (line ~8987) in `src/vscode-dts/vscode.d.ts` from `{ [key: string]: string }` to `{ [key: string]: string | null | undefined }` to match `TerminalOptions.env`, and propagate the change through the task execution pipeline so `undefined`/`null` values are handled the same way (variable removal) as they are for terminal creation.
