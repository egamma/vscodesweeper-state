# Issue #250473 — Retry experience not good

[https://github.com/microsoft/vscode/issues/250473](https://github.com/microsoft/vscode/issues/250473)

## Summary

The retry UX remains unresolved on current main: it still uses a refresh icon, immediately replaces the request and response in ordinary chat, and only asks for confirmation when Agent/Edit mode would undo file edits. A maintainer has explicitly requested usage evidence before choosing among editing, moving, relabeling, or otherwise safeguarding the action.

## Change summary

Make retrying a chat response clearer and safer, particularly when an accidental click would discard a useful generated response.

## Best solution

Keep transient-error recovery available while making intentional regeneration distinct from editing and resubmitting a prompt. The chosen UX should prevent accidental loss—by preserving prior attempts, requiring an appropriate confirmation, or otherwise making the destructive consequence clear—and remain fully keyboard and screen-reader operable.

## Evidence

- **current retry surface:** src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts registers `workbench.action.chat.retry` with `Codicon.refresh` in the chat message footer, so the original icon concern remains present on current main.
- **destructive behavior:** RetryChatAction calls `chatService.resendRequest` without preserving the request ID; src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts:1205-1240 removes the existing request with `ChatRequestRemovalReason.Resend` before sending the replacement, which also removes the displayed prior response.
- **limited confirmation:** src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts only opens the retry confirmation when Agent/Edit mode has working-set entries modified by the request. Ordinary chat retries, including the accidental-click scenario described at https://github.com/microsoft/vscode/issues/250473#issuecomment-4350566638, proceed without confirmation.
- **existing edit path:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts registers the separate `workbench.action.chat.editRequests` action, while `chat.editRequests` in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts enables editing and resubmitting requests; the product decision is how this path should relate to unchanged retries.
- **maintainer direction:** A maintainer asked for evidence about why users retry before deciding whether to move the action or change its icon/label: https://github.com/microsoft/vscode/issues/250473#issuecomment-2946611743.
