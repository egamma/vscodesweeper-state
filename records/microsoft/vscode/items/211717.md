# Issue #211717 — Use a non-webview component for text outputs and errors in notebooks

[https://github.com/microsoft/vscode/issues/211717](https://github.com/microsoft/vscode/issues/211717)

## Summary

The requested architectural cleanup remains relevant: current notebook text and error outputs still use the webview rendering pipeline. Keep this team-authored debt issue open; no issue-linked fix or qualifying older duplicate was found.

## Change summary

Render notebook text outputs and errors outside the webview to reduce messaging overhead and enable reuse of core components and linking.

## Best solution

Establish a workbench-native rendering path for notebook text and error outputs while preserving rich-output renderer support and existing output interactions. Evaluate the suggested xterm approach against notebook selection, accessibility, streaming, and layout requirements before choosing the component.

- **Trace:**

  > CellOutputElement in src/vs/workbench/contrib/notebook/browser/view/cellParts/cellOutput.ts resolves MIME renderers and sends the selected output to NotebookEditorWidget.createOutput. In src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts, that method resolves and delegates to BackLayerWebView, including creation, updates, and positioning. extensions/notebook-renderers/package.json and src/index.ts confirm that plain text, streams, and errors are still handled by the built-in webview renderer. This establishes the remaining architectural work, not a runtime correctness defect or a measured performance regression. Preserve rich HTML/image and third-party renderer behavior; do not turn this into a wholesale removal of notebook webviews. - **Open decisions:**
  - Should the native surface retain document-style text selection and wrapping, or expose terminal-style behavior where xterm differs?
