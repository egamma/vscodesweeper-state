# Issue #339997 — Remote agent host: large chat history exceeds tunnel gateway frame limit and causes terminal timeout

[https://github.com/microsoft/vscode/issues/339997](https://github.com/microsoft/vscode/issues/339997)

## Summary

Keep open: current main still applies the gateway's default 16 MiB frame limit while the tunnel client accepts 100 MiB. The thread independently confirms that large chat snapshots break tunnel connections on Stable, and the gateway configuration mismatch remains directly visible in source.

## Change summary

Opening a large remote agent chat exceeds the tunnel gateway's WebSocket frame limit, disconnecting the shared connection and surfacing a misleading terminal timeout.

## Best solution

Make the gateway consistently support the existing bounded 100 MiB client transport contract across TCP targets, socket targets, and its client-facing connection. Preserve explicit limits and handle capacity failures promptly; history pagination is a separate longer-term improvement, not a prerequisite for fixing the demonstrated transport mismatch.
