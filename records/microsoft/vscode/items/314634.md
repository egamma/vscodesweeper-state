# Issue #314634 — Can't search for files in explorer view

[https://github.com/microsoft/vscode/issues/314634](https://github.com/microsoft/vscode/issues/314634)

## Summary

The current source explains the reported failure: reopening Explorer find preserves the query, but pressing Enter only returns focus to the tree and does not reapply the query or restore focus to a match after another file was selected. This is a bounded Explorer/tree-find bug that should remain open.

## Change summary

Repeating an existing Explorer filename search with Enter does not return focus to the matching file after another file has been selected.

## Best solution

Make repeating a populated tree search restore focus to an eligible match while preserving the existing query, history, filter/highlight modes, and normal behavior for newly typed queries.

## Evidence

- **source trace:** In src/vs/base/browser/ui/tree/abstractTree.ts, FindWidget's Enter handler only adds the value to history and calls `this.tree.domFocus()`; it does not invoke `onDidChangeValue`, `applyPattern`, or match navigation. AbstractFindController.open() also only focuses and selects the existing widget when it is already open.
- **matching path:** FindController.applyPattern() in src/vs/base/browser/ui/tree/abstractTree.ts is the path that refilters and calls `tree.focusNext(...)` to focus a match. Because the preserved query does not change when Enter is pressed, this path is not run again after the reporter selects a nonmatching file.
- **Explorer integration:** src/vs/workbench/contrib/files/browser/views/explorerView.ts constructs the Explorer tree with ExplorerFindProvider, while AsyncFindController in src/vs/base/browser/ui/tree/asyncDataTree.ts inherits the same FindController behavior and restricts navigation to provider matches.
