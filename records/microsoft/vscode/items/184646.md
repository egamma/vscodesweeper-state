# Issue #184646 — .vscode\cli\ ignores portable mode

[https://github.com/microsoft/vscode/issues/184646](https://github.com/microsoft/vscode/issues/184646)

## Summary

The CLI (Rust codebase) has no awareness of VSCODE_PORTABLE or portable mode — it always writes to ~/.vscode/cli unless --cli-data-dir or VSCODE_CLI_DATA_DIR is explicitly set. This is a legitimate gap in portable-mode support, already on the On Deck milestone, with #278854 closed as a duplicate of this issue. Keeping open.

## Change summary

The VS Code CLI creates ~/.vscode/cli/ even in portable mode, breaking the portable-mode contract that all data stays within the portable data/ folder.

## Best solution

Teach the CLI's LauncherPaths (cli/src/state.rs) to check for the VSCODE_PORTABLE environment variable and, when set, resolve the CLI data directory under the portable data path (e.g. data/cli/) instead of defaulting to ~/DEFAULT_DATA_PARENT_DIR/cli. The Electron side already sets VSCODE_PORTABLE and uses it pervasively in src/vs/platform/environment/ — the CLI just needs to mirror that logic.

## Evidence

- **CLI has no portable awareness:** grep -rn 'portable|VSCODE_PORTABLE' cli/src/ returns zero matches — the Rust CLI codebase is entirely unaware of portable mode.
- **hardcoded default path:** cli/src/state.rs LauncherPaths::migrate() defaults to home_dir/.vscode/cli when no --cli-data-dir is passed (lines 136-162); LauncherPaths::new() defaults to ~/{DEFAULT_DATA_PARENT_DIR}/cli (line 165).
- **Electron side handles it:** src/vs/platform/environment/common/environmentService.ts and node/userDataPath.ts check VSCODE_PORTABLE extensively and redirect data paths into the portable folder.
- **duplicate closed to this:** https://github.com/microsoft/vscode/issues/278854 was closed as a duplicate of this issue, confirming this is the canonical tracker.
- **workaround exists:** Comment 4 and 5 confirm that VSCODE_CLI_DATA_DIR env var or --cli-data-dir flag can work around the issue, but portable mode should handle this automatically.
