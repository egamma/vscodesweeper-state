# Issue #275046 — Agent file editor - migration quick fix removes editor focus

[https://github.com/microsoft/vscode/issues/275046](https://github.com/microsoft/vscode/issues/275046)

## Summary

The focus loss remains source-reproducible on current main: the code-action widget focuses the old editor before the asynchronous file rename replaces it, while the replacement preserves the resulting non-editor focus. This member-authored, accepted bug should remain open for a bounded code-action focus fix.

## Change summary

Keep keyboard focus in the editor after the quick fix migrates an open `.chatmode.md` file to `.agent.md`.

## Best solution

Ensure completion of an asynchronously applied code action restores text focus to the resulting active editor after a workspace file rename, without changing focus for unrelated views or inactive editors.

- **Behavior:**

  > Selecting a quick fix that renames the currently open file leaves keyboard focus in the editor showing the renamed resource once the action completes. Typing immediately after migration must edit the renamed file without requiring a click. Existing code actions that do not replace the editor retain their current focus behavior, and inactive editors or unrelated workbench parts must not be focused.
- **Trace:**

  > The migration provider in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptCodeActions.ts creates an IWorkspaceFileEdit that renames the active `.chatmode.md` file. In src/vs/editor/contrib/codeAction/browser/codeActionController.ts, the action-list `onSelect` starts `applyCodeAction` without awaiting it, hides the widget, and `onHide` focuses the old editor immediately. The rename subsequently reaches src/vs/workbench/services/editor/browser/editorService.ts, where `handleMovedFile` replaces the affected editor with `preserveFocus: true`, leaving the replacement without text focus. The maintainer diagnosis at https://github.com/microsoft/vscode/issues/275046#issuecomment-3641605205 establishes that focus preservation belongs to the code-action execution path. Keep the boundary to code actions initiated from an editor: do not make generic file moves steal focus from another workbench part or activate an inactive editor.
