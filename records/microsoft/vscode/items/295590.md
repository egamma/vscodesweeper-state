# Issue #295590 — VS Code opens non-existent file (.scss.scss) with incorrect content when Command-Clicking an import path inside a "Staged Changes" diff view.

[https://github.com/microsoft/vscode/issues/295590](https://github.com/microsoft/vscode/issues/295590)

## Summary

The current source explains both reported symptoms: SCSS link resolution can append a second extension to a Git URI, while its unchanged query makes Git load the importing file's content. Keep this open for a focused CSS/Git navigation fix.

## Change summary

Command-clicking an SCSS import in a staged diff should open the referenced file with the correct filename and content.

## Best solution

Make built-in SCSS import navigation resolve the referenced resource consistently from Git-backed diff documents. Settle whether navigation should open the corresponding Git revision or the working-tree file, then cover the target URI and loaded content together.

Resolve @import "./tailwindImports.scss" from a wrapper.scss Git URI; assert that the target has exactly one .scss extension, identifies tailwindImports.scss, and reads that file's distinct content. Include differing snapshot/working-tree content to enforce the chosen navigation contract, and retain existing file-URI and SCSS partial-resolution behavior.
- **Behavior:**

  > Command-clicking an explicit relative SCSS import from a staged diff must open the referenced file, not a fabricated doubled-extension path displaying the importing file's content. Verify this with two files whose contents are distinguishable. The target filename must contain exactly one .scss extension, and the opened content must belong to that target. Decide whether the content comes from the corresponding Git revision or the working tree; ordinary file-editor navigation must remain unchanged.
- **Trace:**

  > The CSS client accepts Git-backed SCSS documents, and cssServer.ts calls findDocumentLinks2 with getDocumentContext(document.uri, workspaceFolders). documentContext.ts resolves relative paths using vscode-uri utilities that preserve the original query, whereas Git resource identity is decoded from query.path and query.ref by extensions/git/src/uri.ts and consumed by GitFileSystemProvider.stat/readFile. This conclusively explains why a differently named target can load wrapper.scss. The exact bundled vscode-css-languageservice 7.0.0-next.2 additionally strips the .scss suffix from the complete URI string rather than its path, so a trailing Git query prevents stripping and produces a doubled-extension candidate. The existing Links suite exercises file and untitled CSS targets, not this Git-backed SCSS interaction. Preserve ordinary imports, Sass partial lookup, and Git snapshot identity outside this navigation boundary. https://github.com/microsoft/vscode/issues/295589 is the same closed report, not a usable canonical; https://github.com/microsoft/vscode/issues/324356 addresses a distinct TypeScript references limitation.
- **Open decisions:**
  - Should an SCSS import followed from a Git-backed diff open the referenced file at that document's Git revision, or open its current working-tree version?

The only supplied comment requests upgrading from 1.101.2; it does not confirm resolution or identify an extension cause.
- **Built-in link-resolution path:** extensions/css-language-features/client/src/cssClient.ts registers CSS/SCSS/LESS without a scheme restriction. extensions/css-language-features/server/src/cssServer.ts:260–267 passes the Git document URI through getDocumentContext to findDocumentLinks2. In server/src/utils/documentContext.ts, relative resolution changes the URI path through Utils.dirname/resolvePath but leaves the Git query unchanged.
- **Wrong-content mechanism:** extensions/git/src/uri.ts:20–21 decodes resource identity from uri.query; toGitUri stores the original file path and ref there. extensions/git/src/fileSystemProvider.ts:159–176 and 197–231 use that decoded path for stat and readFile. Consequently, an import target whose visible URI path changes but whose query still names wrapper.scss is checked and read as wrapper.scss.
- **Doubled-extension mechanism:** The checkout locks vscode-css-languageservice to 7.0.0-next.2 in extensions/css-language-features/server/package-lock.json. Read-only inspection of that exact package's lib/esm/services/scssNavigation.js shows toPathVariations applies target.replace(/\.scss$/, '') to the complete URI string before appending '.scss' to its basename. A Git URI has a trailing query, so the existing path extension is not stripped; the first candidate becomes tailwindImports.scss.scss. Its inherited query lets the Git provider report the importing file as existing.
