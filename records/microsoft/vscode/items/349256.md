[https://github.com/microsoft/vscode/issues/349256](https://github.com/microsoft/vscode/issues/349256)

## Summary

Keep open for the built-in Git extension: current source contains refresh-suppression paths consistent with the stale deleted-file count. The supplied steps suffice to retest; the exact two-worktree deletion race remains unverified without running VS Code.

## Change summary

Automatically retire stale Source Control state when an externally removed worktree disappears, without requiring the Source Control view to be opened.

## Best solution

The built-in Git extension should eventually remove a disappeared worktree repository and its badge contribution without user interaction. Diagnose the deletion-event and refresh lifecycle, including status-limit suppression, while preserving refresh throttling for existing large repositories.

## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/model.ts`, `extensions/git/src/watch.ts`, `extensions/git/src/test/smoke.test.ts`
- **Validation:** In an isolated extension-host workspace, auto-detect two large worktrees and remove them sequentially outside VS Code while Source Control remains hidden. Verify both repositories disappear from the Git API and their badge contributions clear without opening Source Control or manually refreshing. Exercise a mid-deletion status exceeding git.statusLimit and confirm surviving repositories retain their legitimate changes.
- **Behavior:**

  > Removing two auto-detected worktrees sequentially can leave thousands of deleted-file changes attributed to a worktree whose directory no longer exists. After removal finishes, its repository and badge contribution should disappear automatically, without opening Source Control. Existing repositories and their actual changes must remain unaffected. Acceptance includes the large-status case and the ordinary single-removal case.
- **Trace:**

  > Repository's constructor in extensions/git/src/repository.ts combines working-tree and Git-directory events into onFileChange. That handler skips refreshes for isRepositoryHuge and during active operations; getStatus sets isRepositoryHuge when the configured status limit is reached. Repository.run recognizes NotAGitRepository and changes repository state, which Model.open in extensions/git/src/model.ts observes for removal. Worktree discovery opens newly listed worktrees but does not itself reconcile removed ones. These paths make the report plausible, but the exact event ordering and whether status-limit suppression participates require reproduction first. Preserve existing large-repository performance safeguards and avoid conflating this with the explicit-disposal picker defect in https://github.com/microsoft/vscode/issues/346203.
