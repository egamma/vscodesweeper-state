# Issue #309990 — NES NextEditProvider: Cancel speculative/pending requests on disposal

[https://github.com/microsoft/vscode/issues/309990](https://github.com/microsoft/vscode/issues/309990)

## Summary

Keep open: speculative-request disposal and scheduled-state cleanup are now covered, but an ordinary pending stateless request still has no provider-lifetime cancellation. The report remains necessary for that residual shutdown defect.

## Change summary

Cancel provider-owned pending requests and discard deferred speculative work when NextEditProvider is disposed.

## Best solution

Ensure disposal cancels an ordinary in-flight stateless request, including its remaining background stream, while preserving SpeculativeRequestManager's existing disposal behavior and normal request-reuse semantics.
