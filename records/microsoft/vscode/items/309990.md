# Issue #309990 — NES NextEditProvider: Cancel speculative/pending requests on disposal

[https://github.com/microsoft/vscode/issues/309990](https://github.com/microsoft/vscode/issues/309990)

## Summary

Partially addressed by commit 197f33eb366 (SpeculativeRequestManager with proper dispose), but `_pendingStatelessNextEditRequest` still lacks cancellation on `NextEditProvider` disposal. Team-authored issue remains valid.

## Change summary

Cancel speculative and pending stateless NES requests when NextEditProvider is disposed to prevent leaked async work.

## Best solution

Add disposal logic to `NextEditProvider` that cancels `_pendingStatelessNextEditRequest.cancellationTokenSource` when the provider is disposed — the speculative side is now handled by the registered `SpeculativeRequestManager`, but the stateless pending request path remains unguarded.
