# Issue #199185 — Merge Editor: Current is not always HEAD for every merge conflict

[https://github.com/microsoft/vscode/issues/199185](https://github.com/microsoft/vscode/issues/199185)

## Summary

Keep open for diagnosis: current code still replaces conflict-stage inputs with commit snapshots without checking their equivalence. The exact multi-commit rebase failure remains unconfirmed, but this team-authored issue is protected from an insufficient-information close.

## Change summary

Ensure the merge editor compares the actual conflict-stage contents rather than assuming Current always matches HEAD.

## Best solution

The built-in Git extension should open merge inputs that faithfully represent the conflicted file's index stages, while retaining useful commit metadata and rename handling. First establish a multi-commit rebase fixture that demonstrates where the existing commit-based inputs diverge.
