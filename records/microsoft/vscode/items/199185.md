# Issue #199185 — Merge Editor: Current is not always HEAD for every merge conflict

[https://github.com/microsoft/vscode/issues/199185](https://github.com/microsoft/vscode/issues/199185)

## Summary

Still reproduces on main: during a multi-commit rebase with conflicts, the merge editor's 'Current' and 'Incoming' file contents are sourced from HEAD/REBASE_HEAD commit hashes rather than the git index stages `:2:`/`:3:`, which can show incorrect content because HEAD shifts per rebased commit.

## Change summary

Merge editor shows wrong file content for 'Current' side when rebasing multiple conflicting commits, because it uses HEAD's commit hash instead of git index stage `:2:`.

## Best solution

In `extensions/git/src/commands.ts` around line 879–908, stop overwriting `current.uri` and `incoming.uri` with commit-hash-based URIs. The metadata (detail, description) should still come from HEAD/REBASE_HEAD for display, but the actual file content URIs should remain as `mergeUris.ours` (`:2:`) and `mergeUris.theirs` (`:3:`) — or at minimum, the rename-detection logic should use stage refs instead of commit hashes. The rename-handling paths (lines 893–907) would need to be adapted accordingly.
