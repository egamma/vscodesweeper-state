# Issue #221583 — [File Watcher (node.js)] Error: ENAMETOOLONG: name too long

[https://github.com/microsoft/vscode/issues/221583](https://github.com/microsoft/vscode/issues/221583)

## Summary

Partially fixed by PR #224535 (guards paths starting with `^`), but bpasero's comment 6 reports paths ending with `^` (e.g. `/path/to/vscode/^`) still reach the file watcher — that case remains unguarded on current main. The issue should stay open for the remaining variant.

## Change summary

The TypeScript language service requests file watchers for in-memory resource paths (containing `^`), causing ENAMETOOLONG errors in the Node.js file watcher.

## Best solution

Extend the guard in `typescriptServiceClient.ts` (lines ~1042 and ~1058) to also reject paths that end with or contain `^` as a path segment, not just paths that start with it. The `inMemoryResourcePrefix` check needs to cover the trailing-`^` pattern reported by bpasero. This may also warrant an upstream TypeScript fix to stop emitting watch requests for these virtual paths.
