[https://github.com/microsoft/vscode/issues/340294](https://github.com/microsoft/vscode/issues/340294)

## Summary

Keep this higher-level parity request open: current source provides substantial tool and MCP management, but does not establish the requested consistent experience across compatible harnesses and windows. Preserve it as an umbrella for product decisions rather than treating a narrower implementation or related issue as completion.

## Change summary

Unify supported model, tool, MCP, configuration, and session capabilities across Chat, the Agents window, and compatible harnesses.

## Best solution

Define a capability-parity matrix and consistent presentation of supported versus unsupported functionality across harnesses, then coordinate bounded work through the existing focused issues. Retain working tool selection and MCP management while resolving configuration ownership, portability, and session-continuation contracts.

- **Full request and umbrella scope:** Read the complete body of https://github.com/microsoft/vscode/issues/340294 through the public API, including the portion truncated in the supplied context. It explicitly describes a higher-level product/UX request building on focused issues, with ten acceptance criteria spanning tool selection, models, MCP management, portability, identity, and session continuity. This is an umbrella and should remain open under the hard keep-open rule.
- **Existing tool capabilities are partial coverage:** src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts already defines individual-tool and tool-set checkbox items, origin buckets for user/built-in/MCP/extension tools, and user tool-set editing. These cover important individual capabilities, not their availability and consistent semantics across every requested harness.
- **Harness-scoped enablement:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostToolSetEnablementService.ts persists tool and tool-set overrides profile-wide, keyed by session type. Its documented target is the Copilot CLI session type, with isCopilotCliSessionType recognizing local and remote Copilot CLI sessions; this is not evidence of universal cross-harness parity.
- **Existing MCP commands:** src/vs/workbench/contrib/mcp/browser/mcpCommands.ts and src/vs/workbench/contrib/mcp/common/mcpCommandIds.ts already provide workbench.mcp.listServer, workbench.mcp.addConfiguration, workbench.mcp.browseServers, workbench.mcp.startServer, workbench.mcp.stopServer, workbench.mcp.restartServer, and separate user/workspace configuration commands. Their existence does not settle the requested shared configuration ownership and cross-surface behavior.
- **Compatibility distinctions remain explicit:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostMcpServerSupport.ts models server provenance, scope applicability, enablement, delivery, and supported/partially-supported/unsupported compatibility separately. It includes reasons such as unsupported source locations, unresolved configuration, and nonportable launch details, supporting capability-aware presentation rather than assuming all harnesses are interchangeable.
