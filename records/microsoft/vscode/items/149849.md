# Issue #149849 — Scrollbar Minimap and visible code are out of sync when CodeLens is used

[https://github.com/microsoft/vscode/issues/149849](https://github.com/microsoft/vscode/issues/149849)

## Summary

The report contains a concrete CodeLens/minimap reproduction, and a second user confirmed broader minimap desynchronization with videos and an organize-imports trigger. The existing `editor-minimap` routing is correct, and there is no verified fix or canonical issue in the supplied history.

## Change summary

Keep the minimap viewport highlight and rendered content synchronized with the editor when CodeLens height and document edits affect vertical layout.

## Best solution

Correct minimap vertical-coordinate and invalidation handling so `fit`, `fill`, and `proportional` modes remain aligned after CodeLens layout changes and organize-import edits, without reintroducing scrolling jitter.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/minimap/minimap.ts`, `src/vs/editor/browser/viewParts/minimap/minimapCharRenderer.ts`, `src/vs/editor/browser/viewParts/scrollbar/scrollbar.ts`

- **Behavior:**

  > The minimap content and viewport highlight must correspond to the code currently visible in the editor when CodeLens contributes extra vertical height. Alignment must remain correct for `fit`, `fill`, and `proportional` sizing, including after scrolling and document edits such as Organize Imports. Existing minimap rendering modes must not develop stale or duplicated sections, and proportional mode must not gain additional scroll jitter.
- **Trace:**

  > The primary report isolates a vertical-layout mismatch when CodeLens lines are omitted from minimap rendering, especially in `fit` and `fill`; it cites https://github.com/microsoft/vscode/issues/111499 and commit 53eac52308c4611000a171cc7bf1214293473c78 as incomplete prior handling. The later videos add a likely invalidation defect: after Organize Imports, proportional and Render Characters minimaps can retain content inconsistent with the editor depending on scroll position. Investigation should trace minimap layout scaling and viewport placement in `src/vs/editor/browser/viewParts/minimap/minimap.ts`, then distinguish that from stale rendered-minimap invalidation after model edits. Preserve normal proportional sizing behavior and editor scrolling; do not broaden the work to CodeLens presentation beyond what synchronization requires.
- **Open decisions:**
  - Should CodeLens occupy explicit blank vertical space in fit/fill minimap content, or should the viewport mapping intentionally normalize CodeLens height while still matching the visible editor range?
  - Are the CodeLens fit/fill offset and the organize-imports stale or duplicated minimap rendering one supported fix scope, or should the latter remain a separate defect if current-main tracing shows a distinct invalidation root cause?

## Evidence

- **original reproduction:** The reporter reproduced on VS Code 1.67.2 with extensions disabled: `editor.minimap.size` set to `fit` or `fill`, unevenly distributed CodeLens lines, and an exaggerated `editor.codeLensFontSize` make the minimap viewport diverge from visible editor code.
- **independent confirmation:** A second user supplied three videos from VS Code 1.74.2 on macOS showing stale or duplicated minimap sections in proportional and Render Characters modes, and narrowed one trigger to repeatedly running Organize Imports after scrolling.
- **prior related behavior:** The issue body identifies https://github.com/microsoft/vscode/issues/111499 and commit 53eac52308c4611000a171cc7bf1214293473c78 as prior work that addressed proportional scrollbar behavior but did not cover the reported `fit`/`fill` CodeLens discrepancy.
