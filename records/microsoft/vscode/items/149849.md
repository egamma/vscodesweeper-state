# Issue #149849 — Scrollbar Minimap and visible code are out of sync when CodeLens is used

[https://github.com/microsoft/vscode/issues/149849](https://github.com/microsoft/vscode/issues/149849)

## Summary

The CodeLens/minimap mismatch remains visible in current source: fit/fill layout computes the minimap slider from logical text lines while CodeLens contributes variable-height view zones to the editor's actual scroll geometry. The issue should remain open in editor-minimap while maintainers choose whether fit/fill should represent view-zone space or compensate only in slider geometry.

## Change summary

Keep the minimap viewport indicator aligned with visible editor content when CodeLens view zones are present in fit or fill mode.

## Best solution

Define consistent fit/fill semantics for editor view zones, then make the minimap's rendered content and viewport indicator use the same vertical model for CodeLens and other whitespace zones without regressing proportional mode.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/minimap/minimap.ts`, `src/vs/editor/contrib/codelens/browser/codelensWidget.ts`
- **Validation:** Create an editor with fit and fill minimap modes plus uneven, large view zones equivalent to CodeLens; scroll above, through, and below them and assert that the minimap slider bounds correspond to the editor viewport. Repeat in proportional mode to guard its existing behavior.
- **Behavior:**

  > With editor.minimap.size set to fit or fill, the minimap's highlighted viewport must correspond to the code actually visible in the editor even when large or uneven CodeLens rows occur between text lines. Scrolling across the CodeLens-heavy region must not accumulate an offset, and changing document content must not leave stale minimap rendering. Proportional mode and files without view zones must retain their current behavior.
- **Trace:**

  > CodeLensViewZone in src/vs/editor/contrib/codelens/browser/codelensWidget.ts reserves heightInPx in the editor layout. MinimapLayout.create in src/vs/editor/browser/viewParts/minimap/minimap.ts receives both realLineCount and actual scrollHeight; its minimapHeightIsEditorHeight branch derives slider height from text-line height but slider position from actual scroll height, while the non-fit/fill branch explicitly accounts for viewportContainsWhitespaceGaps. This confirms the mismatched coordinate models on current main. Commit 53eac52308c4611000a171cc7bf1214293473c78 addressed https://github.com/microsoft/vscode/issues/111499 through viewport-offset alignment but did not reconcile the fit/fill branch. The boundary should cover generic editor view zones, not special-case TypeScript CodeLens providers, and must not alter ordinary minimap rendering or proportional-mode behavior.
- **Open decisions:**
  - Should fit/fill minimaps visibly reserve scaled blank space for all editor view zones, or should only the viewport indicator compensate for their height?
  - Should the behavior cover every view zone uniformly, or only zones whose layout semantics match CodeLens?
  - When view-zone heights change dynamically, should fit/fill preserve a stable slider size or prioritize an exact representation of the currently visible line range?
