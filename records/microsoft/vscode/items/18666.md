# Issue #18666 — Multiple decorations on end of line

[https://github.com/microsoft/vscode/issues/18666](https://github.com/microsoft/vscode/issues/18666)

## Summary

A real gap remains for multiple end-of-line attachment decorations on non-empty lines. Keep this Backlog request open under discussion; current injected-text and inlay-hint support does not fully replace the generic decoration capability.

## Change summary

Allow multiple independently styled editor decorations to render at the same end-of-line position.

## Best solution

Preserve separate pseudo-element attachments when normalizing coincident end-of-line decorations in the editor renderer, with regression coverage for a non-empty line and the folded-region ellipsis case.

## Evidence

- **current source gap:** src/vs/editor/common/viewLayout/lineDecorations.ts:156-179 combines overlapping decoration class names into one DecorationSegment, while src/vs/editor/common/viewLayout/viewLineRenderer.ts:920-922 applies that normalization on non-empty lines; coincident `After` decorations therefore still share one CSS pseudo-element.
- **partial existing support:** src/vs/editor/common/viewLayout/viewLineRenderer.ts:374-409 emits separate attachment spans only for empty lines, covered by the `issue-118759` test at src/vs/editor/test/common/viewLayout/viewLineRenderer.test.ts:1230-1250.
- **related extension impact:** https://github.com/Dart-Code/Dart-Code/issues/2980 documents the same limitation hiding folded-region ellipses when an extension decoration occupies the coincident position.
- **existing alternative:** The InlayHintsProvider API in src/vscode-dts/vscode.d.ts can cover some inline-value scenarios, but it does not provide the requested general composition of TextEditorDecorationType attachments.
