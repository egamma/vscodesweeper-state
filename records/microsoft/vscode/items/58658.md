# Issue #58658 — [folding] go to region command

[https://github.com/microsoft/vscode/issues/58658](https://github.com/microsoft/vscode/issues/58658)

## Summary

A real navigation gap remains: VS Code can fold marker regions but still has no built-in command or standard outline entry for navigating to a named region. The related issues are closed and none qualifies as the older, same-symptom canonical required to close this re-reviewed item as a duplicate.

## Change summary

Add built-in navigation to named folding regions, such as a Go to Region command or region entries in the outline/quick outline.

## Best solution

Expose marker regions through a built-in navigation surface, preferably Outline or Go to Symbol, while preserving language-provided symbols and supporting nested regions consistently.

- **Behavior:**

  > Users can invoke a built-in navigation surface and select a named folding region to move the editor cursor to that region. Nested regions remain distinguishable, and ordinary language symbols continue to appear and navigate as before. Existing region folding commands and marker syntax are unchanged.
- **Trace:**

  > The issue asks to navigate the marker regions already consumed by the editor folding contribution, not to add new marker syntax. The likely path begins in src/vs/editor/contrib/folding/browser/foldingModel.ts and folding.ts, while existing Outline and Go to Symbol behavior is built around document symbols in src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts and src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts. Maintainer discussion favors Outline, while commenters also request a dedicated Go to Region command or an @-style quick picker; these differ in user-visible behavior and are not settled. Preserve language-provider symbols, existing symbol sort/filter semantics, and all current fold/unfold commands. Closed related items https://github.com/microsoft/vscode/issues/51738, https://github.com/microsoft/vscode/issues/55068, https://github.com/microsoft/vscode/issues/118983, and https://github.com/microsoft/vscode/issues/203703 do not provide an open canonical for this re-reviewed issue.
- **Open decisions:**
