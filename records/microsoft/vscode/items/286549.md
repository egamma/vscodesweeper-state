# Issue #286549 — workbench.action.files.setActiveEditorWriteableInSession makes TextDocumentContentProvider writable

[https://github.com/microsoft/vscode/issues/286549](https://github.com/microsoft/vscode/issues/286549)

## Summary

The readonly guarantee is still broken in current source: changing session readonly state can overwrite a content-provider editor's initial readonly configuration, including when another editor is active. Keep this open; the related older reports concern different observable failures.

## Change summary

Session writeability commands allow editing readonly TextDocumentContentProvider documents, including providers visible beside the active editor.

## Best solution

Keep content-provider documents readonly throughout editor configuration and capability updates, while preserving session writeability overrides for ordinary file editors. Cover both direct invocation and invocation with a different editor active.
