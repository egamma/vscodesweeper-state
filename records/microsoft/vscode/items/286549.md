# Issue #286549 — workbench.action.files.setActiveEditorWriteableInSession makes TextDocumentContentProvider writable

[https://github.com/microsoft/vscode/issues/286549](https://github.com/microsoft/vscode/issues/286549)

## Summary

Fixed on main: commit 65610918ba4 guards `updateReadonly` in the service layer so that session overrides are blocked for resources without a writable file system provider, which covers TextDocumentContentProvider-backed documents.

## Change summary

The `setActiveEditorWriteableInSession` command could override the readonly state of TextDocumentContentProvider-backed documents, making them editable when they should always be read-only.

## Best solution

Keep the shipped fix in commit 65610918ba4 (main-only so far). The new `canSetReadonlyStateInSession` guard in `FilesConfigurationService.updateReadonly` rejects session overrides for resources that lack a writable file system provider, which inherently covers TextDocumentContentProvider custom schemes. No further change needed.
