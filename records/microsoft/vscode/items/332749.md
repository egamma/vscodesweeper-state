# Issue #332749 — Source Control: "Reveal in File Explorer" is shown for deleted files but silently does nothing

[https://github.com/microsoft/vscode/issues/332749](https://github.com/microsoft/vscode/issues/332749)

## Summary

Confirmed on main: `git.revealInExplorer` and `git.revealFileInOS` in extensions/git/src/commands.ts never check whether the resource still exists (unlike `git.openFile`, which filters out DELETED/INDEX_DELETED resources), so revealing a deleted tracked file silently no-ops. The reporter already opened a fixing PR, so this should stay open pending review/merge rather than be auto-closed.

## Change summary

"Reveal in File Explorer/Finder" and "Open Containing Folder" are shown and clickable for deleted SCM resources but silently do nothing because the underlying OS reveal command has no target to reveal.

## Best solution

Land the reporter's own fix in https://github.com/microsoft/vscode/pull/332750, which guards `git.revealInExplorer`/`git.revealFileInOS` the same way `git.openFile` already guards against `Status.DELETED`/`Status.INDEX_DELETED`, and shows a warning instead of silently no-oping.
