# Issue #333278 — Duplicate model entries in Language Models management view ("Sprachmodelle") – second group uses versioned model ID (@1.0)

[https://github.com/microsoft/vscode/issues/333278](https://github.com/microsoft/vscode/issues/333278)

## Summary

Traced this in the source: the Manage Language Models view groups models by vendor id + display name (ChatModelsViewModel.groupModels/getProviderGroupId), and a second, distinct vendor is registered per agent-host session type (AgentHostChatContribution, vendor = sessionType, displayName = agent.displayName) that also renders as "Copilot". That second vendor's models come from AgentHostLanguageModelProvider, which hardcodes `version: '1.0'` on every model (explaining the observed `@1.0` tooltip suffix) and can inject the synthetic "Auto" entry. Two same-named, same-model groups are the expected (if confusing) result of this architecture, not random duplication.

## Change summary

The Manage Language Models view shows two separate "Copilot" provider groups with overlapping/duplicate model entries, one of them prefixed by a synthetic "Auto" model and versioned model IDs (name-version@1.0).

## Best solution

This needs a product/UX decision in src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts and agentHostChatContribution.ts: either give the agent-host vendor group a distinguishing label/subtitle (e.g. "Copilot (Agent)") instead of reusing the bare display name, or filter it out of the general Manage Models view entirely if it's only meant to be consumed by agent sessions. A quiet identical-label collision is not the intended experience either way.

## Evidence

- **grouping logic:** src/vs/workbench/contrib/chat/browser/chatManagement/chatModelsViewModel.ts groupModels()/createLanguageModelProviderEntry() groups by getProviderGroupId(provider) but labels the group with the raw `provider.group.name` (display name), so two different vendors sharing display name "Copilot" render as two separate group headers with identical text.
- **second vendor registration:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts:353-363 registers a distinct vendor per agent-host session type (`vendor = sessionType`) with `displayName: agent.displayName` and no `when` filter, so it always appears in getVendors()/the manage view alongside the primary Copilot chat vendor.
- **@1.0 suffix source:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLanguageModelProvider.ts:90 hardcodes `version: '1.0'` on every model metadata it returns, matching the reporter's observed 'name-version@1.0' tooltip on the second group.
- **Auto entry source:** Same file, lines 33-35 and 63-80: `agentHostProviderSupportsAutoModel` and the `isAuto` handling inject a synthetic 'Auto' model for harnesses like Copilot CLI, matching the reporter's Group 2 'Auto' entry.
