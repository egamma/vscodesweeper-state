# Issue #333278 — Duplicate model entries in Language Models management view ("Sprachmodelle") – second group uses versioned model ID (@1.0)

[https://github.com/microsoft/vscode/issues/333278](https://github.com/microsoft/vscode/issues/333278)

## Summary

Traced in source: the Manage Language Models view groups models by `vendor.group.vendor-group.name-sourceId` (chatModelsViewModel.ts `getProviderGroupId`), and the Agent Host language model provider (agentHostLanguageModelProvider.ts, used for the Copilot CLI agent-host harness) registers the same models under the same vendor display name ("Copilot") but with a distinct `sourceId`/versioned raw id (`...@1.0`) and a synthetic "Auto" entry — producing two visually-identical "Copilot" groups with no differentiating tooltip on the header. This is a real, traceable gap, not a config issue on the reporter's machine.

## Change summary

The Manage Language Models view shows two separate "Copilot" provider groups with overlapping model lists — one with plain model IDs, one with an `@1.0`-suffixed id and an extra "Auto" entry.

## Best solution

In `chatModelsViewModel.ts`, either give the Agent Host-sourced group header a distinguishing label/tooltip (e.g. "Copilot (Agent Sessions)") so the two groups are clearly different, or fold Agent Host models into the same group as the standard Copilot vendor entries when they represent the same underlying models. Needs a product decision on how Agent Sessions models should be surfaced in this view, so this belongs with the chat/agent-host area owners rather than an automatic fix.
