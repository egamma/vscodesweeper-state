# Issue #340242 — Markdown syntax highlighter: mismatched brackets in code blocks in hyperlinks

[https://github.com/microsoft/vscode/issues/340242](https://github.com/microsoft/vscode/issues/340242)

## Summary

Confirmed in source: the markdown grammar's bracket-matching relies on tokenTypes classification that markdown-basics never declares for inline code spans, so brackets inside backtick-quoted text aren't excluded from bracket matching the way they are in css/html/js/typescript grammars.

## Change summary

In a markdown link whose text contains an inline code span with brackets (e.g. `[test \`[test]\` test](test)`), the opening `[` of the link gets matched against the `]` inside the backtick span instead of the link's real closing `]`.

## Best solution

Add a `tokenTypes` entry to the markdown grammar contribution in extensions/markdown-basics/package.json mapping the inline raw/code-span scope (`markup.inline.raw.string.markdown`) to `"string"`, mirroring the existing precedent in extensions/css, extensions/html, extensions/javascript, extensions/typescript-basics, extensions/lua, extensions/make, and extensions/csharp, so bracket matching skips brackets inside backtick spans.

  > extensions/markdown-basics/package.json's grammar contribution for scope `text.html.markdown` has no `tokenTypes` entry, unlike extensions/css/package.json (`"tokenTypes": {"meta.function.url string.quoted": "other"}`), extensions/html, extensions/javascript, extensions/typescript-basics, extensions/lua, extensions/make, and extensions/csharp. The `link-inline` grammar rule's recursive `square` bracket-nesting regex itself is not the defect — it already nests `[test]` correctly at the tokenization level; do not touch that regex. The boundary is strictly the tokenTypes declaration in package.json; do not alter the grammar's matching logic or other scopes' classification.

## Evidence

- **grammar rule:** extensions/markdown-basics/syntaxes/markdown.tmLanguage.json's `link-inline` rule (~line 3110) recursively matches nested `[...]` for link text via a named `square` group, and correctly nests `[test]` inside the backticks as its own bracket pair at the grammar/tokenization level.
- **raw scope:** The `raw` rule (~line 3190) scopes backtick-quoted text as `markup.inline.raw.string.markdown`, but extensions/markdown-basics/package.json declares no `tokenTypes` map for this scope (confirmed via grep across the package.json).
- **bracket matcher:** src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsImpl.ts calls `ignoreBracketsInToken(lineTokens.getStandardTokenType(...))` to exclude String/Comment-typed tokens from bracket search; without a tokenTypes mapping, textMateTokenizationFeatureImpl.ts never assigns StandardTokenType.String to the raw scope, so the `[`/`]` characters inside the code span are treated as ordinary brackets and get matched.
