# Issue #328568 — Semantic indexing fails with HTTP 401 in WSL Remote and Remote SSH but succeeds locally

[https://github.com/microsoft/vscode/issues/328568](https://github.com/microsoft/vscode/issues/328568)

## Summary

Well-documented, cross-environment repro (multiple repos, machines, architectures) of remote codebase-indexing 401s that succeed locally; the code confirms a plausible architectural cause (GitHub Authentication runs on the local extension host while Copilot Chat and its indexing request run remote), but I can't confirm the exact defective line without deeper tracing of remote session propagation, so this should be routed to the chat-codebase/authentication owners rather than closed.

## Change summary

GithubCodeSearchService.triggerIndexing() gets a 401 'Requires authentication' when invoked from a remote extension host (WSL/Remote SSH), even though the same repo indexes fine locally with the same account.

## Best solution

Have the chat-codebase/authentication owners trace how `IAuthenticationService.getGitHubSession` resolves on the remote extension host vs. local (extensions/copilot/src/platform/authentication/common/*, and the token consumed in extensions/copilot/src/platform/remoteCodeSearch/common/githubCodeSearchService.ts around getGithubAccessToken/triggerIndexing) to see whether the remote host is getting a stale, minimal-scope, or unproxied session compared to the local host.
