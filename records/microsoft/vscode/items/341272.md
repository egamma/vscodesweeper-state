# Issue #341272 — Automation runs should not block each other or time out while the Mac sleeps

[https://github.com/microsoft/vscode/issues/341272](https://github.com/microsoft/vscode/issues/341272)

## Summary

Thanks for the detailed report. The source matches the description: an unfinished run blocks later occurrences, and a wall-clock 30-minute timer that keeps running while the Mac sleeps cancels the run and records it as `cancelled`. The report also bundles a design change (overlap policy, removing the timeout), so a maintainer should decide the direction.

## Change summary

A sleeping Mac makes the whole-run timeout fire and cancel an automation, and one unfinished run blocks later scheduled runs.

## Best solution

Record timeout and cancellation as distinct end reasons in run history, and don't let sleep time count toward the timeout. Decide whether to drop or relax the whole-run timeout and whether to add an overlap policy such as allow, skip, queue or replace. The work is in agentHostAutomationService.ts.
