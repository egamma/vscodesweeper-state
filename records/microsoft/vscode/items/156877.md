# Issue #156877 — Quick pick: allow to handle middle mouse button specifically

[https://github.com/microsoft/vscode/issues/156877](https://github.com/microsoft/vscode/issues/156877)

## Summary

The quick pick API still has no way to surface which mouse button triggered an accept. The `IQuickPickDidAcceptEvent` only carries `inBackground`; no `mouseButton` or equivalent has been added. The existing `AUXCLICK` handler in `quickInputList.ts` just fires `_onLeave` (dismisses the picker). This is a valid, unimplemented internal API enhancement request from a team contributor.

## Change summary

Expose which mouse button was used when accepting a quick pick item, similar to how `onKeyMods` exposes modifier keys, so callers can implement middle-click-specific behavior (e.g. open in new window).

## Best solution

Extend `IQuickPickDidAcceptEvent` (or add a parallel `onMouseButton`-style callback like `onKeyMods`) so quick pick callers can distinguish middle-click from left-click accepts. The changes would touch `src/vs/platform/quickinput/common/quickInput.ts` (interface), `src/vs/platform/quickinput/browser/quickInputList.ts` (the AUXCLICK handler), and `src/vs/platform/quickinput/browser/quickInput.ts` (the accept flow). The recently-opened picker in `windowActions.ts` would be the first adopter.
