# Issue #251570 — Save profile/extension preferences and timeline tempfiles for workspace in workspace folder (in .vscode subdirectory?)

[https://github.com/microsoft/vscode/issues/251570](https://github.com/microsoft/vscode/issues/251570)

## Summary

Keep open in the Backlog: the request passed the community threshold with 24 upvotes, and current main still ties these preferences and histories to path-dependent user storage.

## Change summary

Preserve workspace profile selection, extension enablement preferences, and local file history when a workspace folder is moved or renamed.

## Best solution

Design an opt-in portable workspace-state mechanism, or make workspace identity resilient to path changes, across profile associations, extension enablement storage, and local history. The design should avoid unintentionally committing private or voluminous history data under `.vscode`.

## Evidence

- **backlog decision:** The issue received 24 community upvotes, and https://github.com/microsoft/vscode/issues/251570#issuecomment-3065007387 confirms that it was promoted to the Backlog.
- **profile storage:** src/vs/platform/userDataProfile/common/userDataProfile.ts stores workspace/profile associations under `profileAssociations` and associates folder workspaces by URI, so moving the folder changes the association key.
- **extension storage:** src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts persists workspace-enabled and workspace-disabled extension identifiers through `StorageScope.WORKSPACE`, rather than a portable workspace file.
- **history storage:** src/vs/platform/environment/common/environmentService.ts defines local history under the user `History` directory, while src/vs/workbench/services/workingCopy/common/workingCopyHistoryService.ts hashes the full resource URI for each history folder.
- **related requests:** https://github.com/microsoft/vscode/issues/193970 covers configurable local-history storage, and https://github.com/microsoft/vscode/issues/40239 covers file-based extension enablement, but neither absorbs this broader request including profile association and move/rename resilience.
