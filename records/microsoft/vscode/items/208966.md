# Issue #208966 — macOS: state of native window tabs is not restored after restart

[https://github.com/microsoft/vscode/issues/208966](https://github.com/microsoft/vscode/issues/208966)

## Summary

Keep open: native macOS tab-group restoration remains missing, and an open implementation PR explicitly targets this issue. That PR depends on additional Electron APIs; neither proposal is a completed fix.

## Change summary

Preserve merged macOS window groups, tab order, and selected tabs across VS Code restarts.

## Best solution

Review the Electron tab-group APIs and the existing VS Code restoration PR together, then verify restoration after VS Code adopts a supporting Electron runtime. Preserve independent project windows and group boundaries rather than treating a multi-root workspace or merging every restored window into one group as equivalent.

## Evidence

- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/340605 is OPEN and explicitly says Fixes #208966. It proposes persisting independent native tab groups, ordering, and selection, but requires supporting Electron APIs and a subsequent runtime update. Its description states that end-to-end VS Code GUI restoration has not been verified.
- **Upstream dependency remains active:** https://github.com/electron/electron/pull/54783 is OPEN and proposes getTabbedWindows(), getSelectedTab(), selectTab(), and tabbingMode. The original blockers https://github.com/electron/electron/issues/18138 and https://github.com/electron/electron/issues/40529 are closed, but those closures alone do not establish that VS Code can persist and reconstruct native tab groups.
- **Existing capability does not cover restoration:** src/vs/platform/windows/electron-main/windows.ts:204-206 enables native tabs using a shared tabbingIdentifier. In windowsStateHandler.ts:20-50, persisted window state includes workspace/folder, backup, remote authority, and UI state, but no tab-group membership, tab order, or selected-tab metadata. windowsMainService.ts:1008-1061 restores project paths, while explicit addTabbedWindow invocation at lines 1616-1619 is conditional on forceNewTabbedWindow; these surfaces do not reconstruct saved native groups.
- **Confirmed symptom and canonical ownership:** https://github.com/microsoft/vscode/issues/283098 reports native tabs reopening as separate windows. A commenter confirmed Cmd+Q/relaunch reproduction on VS Code 1.107.0 at https://github.com/microsoft/vscode/issues/283098#issuecomment-3674282385, and a maintainer consolidated that report into this issue at https://github.com/microsoft/vscode/issues/283098#issuecomment-3769503091. The younger, closed report is not a duplicate target for this older canonical.
