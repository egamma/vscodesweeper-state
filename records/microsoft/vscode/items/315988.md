# Issue #315988 — Be able to paste text + image content into copilot chat at once

[https://github.com/microsoft/vscode/issues/315988](https://github.com/microsoft/vscode/issues/315988)

## Summary

Current main still treats text and image clipboard payloads as competing paste actions rather than one combined operation. This is a valid chat-input feature request with no verified canonical issue, so it should remain open and be routed to the chat input/vision owners.

## Change summary

Allow one clipboard paste into Copilot Chat to preserve both its text and image content.

## Best solution

Provide a chat-specific mixed-content paste operation that inserts the clipboard text and attaches the image atomically, while preserving the established text-first behavior for applications that expose an image merely as an alternate clipboard representation.

## Plan brief

- **Behavior:**

  > Chat must offer a single paste operation for intentionally mixed clipboard content that places the text in the prompt and attaches the image. Text-only and image-only clipboard pastes must retain their current behavior. Clipboard formats that include an image only as an alternate representation must follow the activation policy selected by the maintainer rather than unexpectedly adding context.
- **Trace:**

  > PasteImageProvider in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts returns an image-only custom edit whose insertText is empty. PasteTextProvider explicitly treats image/* as a richer flavor and therefore does not create its text attachment path, while the generic CopyPasteController applies only one selected DocumentPasteEdit. The likely boundary is the chat-specific provider and its tests; generic editor paste composition should not change. https://github.com/microsoft/vscode/issues/244271 records the competing requirement that OneNote clipboard data containing both representations should default to text, so the uncertainty begins at how the mixed operation is exposed or selected.
- **Open decisions:**
  - Should ordinary paste combine text and image whenever both MIME payloads are present, or should mixed-content paste be an explicit Paste As action so applications such as OneNote and Safari do not create unintended image attachments?

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts registers separate PasteImageProvider and PasteTextProvider implementations. PasteImageProvider creates an image attachment with an empty inserted string, while PasteTextProvider treats dataTransfer.matches('image/*') as a richer paste and declines its text-artifact path.
- **paste selection model:** src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts gathers the available paste edits but applies one active edit through PostPasteWidgetManager; the independently returned image and text edits are alternatives rather than composable results.
- **related behavior:** https://github.com/microsoft/vscode/issues/244271 is an older but distinct report where OneNote exposes both text and image clipboard representations. A maintainer favored plain text by default there, showing that blindly combining every mixed-MIME clipboard requires a product decision.
- **canonical search:** The older https://github.com/microsoft/vscode/issues/241910 tracks Safari adding unwanted URL text when an image is pasted, which is the opposite observable symptom and does not own this request. No older issue with the same mixed-content request was found.
