# Issue #247999 — `"editor.fontLigatures"` should not apply to code lens (esp. when using a different font)

[https://github.com/microsoft/vscode/issues/247999](https://github.com/microsoft/vscode/issues/247999)

## Summary

Keep this accepted feature request open: current source still applies editor font-feature settings to CodeLens independently of its font family. The request has 29 upvotes, and no verified canonical owns the same CodeLens-specific behavior.

## Change summary

Prevent editor-specific ligatures and stylistic sets from unintentionally changing CodeLens text rendered in a different font.

## Best solution

Make CodeLens font-feature behavior independent of editor-specific stylistic sets while preserving the editor's typography. Settle whether CodeLens should use its font's defaults or expose independent font-feature configuration before implementation.

Verify CodeLens reference counts use the agreed independent feature behavior while editor ss06 remains enabled; repeat with ss05 and verify live font-setting changes. Add an automated editor test asserting the agreed CodeLens feature settings when editor and CodeLens fonts differ.
- **Behavior:**

  > Editor stylistic sets selected for Fira Code must not unintentionally box or circle reference-count numerals in CodeLens rendered with a different font. Users must be able to retain their editor font features and their distinct CodeLens font. Acceptance should cover the reported ss06 case, the independently reported ss05 case, and live configuration changes without altering editor typography.
- **Trace:**

  > CodeLensContribution._updateLensStyle in src/vs/editor/contrib/codelens/browser/codelensController.ts unconditionally transfers editorFontInfo.fontFeatureSettings to the CodeLens CSS variable. src/vs/editor/contrib/codelens/browser/codelensWidget.css consumes that variable independently of the CodeLens font-family variables. src/vs/editor/common/config/editorOptions.ts exposes CodeLens font family and size but no separate feature configuration. The thread in https://github.com/microsoft/vscode/issues/247999 isolates the unwanted glyph substitutions to font-specific ss06 and ss05 settings, and current source retains that coupling. Keep editor ligature behavior, CodeLens commands, provider output, and layout semantics unchanged. The unresolved product boundary is whether CodeLens uses font-default features or allows independent user configuration, including its behavior when the fonts match.
- **Open decisions:**
  - Should CodeLens always use its font's default features, or should users have independent CodeLens font-feature configuration?
  - When CodeLens uses the same font as the editor, should it retain editor feature inheritance or follow the same independent behavior as a different-font CodeLens?
