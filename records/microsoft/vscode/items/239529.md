# Issue #239529 — When using "Open File on Remote From" the code lines selected are not preserved

[https://github.com/microsoft/vscode/issues/239529](https://github.com/microsoft/vscode/issues/239529)

## Summary

Decline close (out-of-scope) gated off: the issue carries the `bug` label — the owner already triaged it as accepted work. Original assessment: The reported menu and both commands belong to GitLens, not VS Code core. GitLens explicitly suppresses selected-line ranges when choosing another branch or tag, so changing this behavior belongs in its tracker.

## Change summary

Preserve selected-line anchors when opening a file remotely through the branch/tag picker.

## Best solution

Leave VS Code core unchanged and have the GitLens project consider preserving or mapping selections across revisions; its current implementation deliberately omits ranges because line numbers can differ.

## Evidence

- **Reported behavior explained:** In https://github.com/gitkraken/vscode-gitlens/blob/v16.2.1/src/commands/openFileOnRemote.ts, OpenFileOnRemoteCommand.preExecute sets pickBranchOrTag: true and range: false for OpenFileOnRemoteFrom, with the explanation "Override range since it can be wrong at a different commit". execute reads editor.selection only when args.range is true, explaining why the ordinary command preserves lines while the From variant does not.
- **Current extension behavior:** https://github.com/gitkraken/vscode-gitlens/blob/main/src/commands/openFileOnRemote.ts retains the same explicit range: false override for gitlens.openFileOnRemoteFrom. This is extension-owned intentional behavior, not evidence of a VS Code selection defect.
