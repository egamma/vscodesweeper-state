# Issue #299016 — Provide optional notification when Git auto-fetch detects remote changes

[https://github.com/microsoft/vscode/issues/299016](https://github.com/microsoft/vscode/issues/299016)

## Summary

Propose closing as an extension candidate: a maintainer previously directed the same incoming-commit notification capability to extensions. Current VS Code provides a passive status-bar indicator, while the requested proactive notification remains an extension-level enhancement under that precedent.

## Change summary

Provide an optional, default-disabled notification when automatic fetching discovers new commits on the current branch's upstream.

## Best solution

Keep the existing built-in sync indicator and provide proactive incoming-commit notifications through an extension using the Git repository-state API, consistent with the maintainer decision on https://github.com/microsoft/vscode/issues/100372.

## Evidence

- **Same-scope maintainer precedent:** https://github.com/microsoft/vscode/issues/100372 requested an outstanding notification for incoming Git commits despite the existing passive indicator. In https://github.com/microsoft/vscode/issues/100372#issuecomment-647141145, the Git maintainer explicitly recommended implementing this through the Git extension API. That issue is closed with *extension-candidate; it is precedent, not an open duplicate target.
- **Existing capability and remaining gap:** extensions/git/src/statusbar.ts: SyncStatusBar subscribes to repository.onDidRunGitStatus and includes repository.syncLabel when HEAD.ahead or HEAD.behind is nonzero. extensions/git/package.json registers git.enableStatusBarSync with default true. This already supplies passive incoming-commit visibility, but does not fully satisfy the request for proactive notification.
- **Current automatic-fetch behavior:** extensions/git/src/autofetch.ts: AutoFetcher.run calls repository.fetchDefault({ silent: true }) or repository.fetchAll({ silent: true }); it contains no notification for newly discovered upstream commits. The git.autofetch and git.autofetchPeriod registrations in extensions/git/package.json configure background fetching, not incoming-change alerts.
- **Extension API boundary:** extensions/git/src/api/git.d.ts exposes RepositoryState.HEAD and RepositoryState.onDidChange, together with Branch.upstream, Branch.ahead, and Branch.behind. An extension can observe increases in incoming commits on the tracked branch without requiring a new core notification setting.
- **Canonical search and re-review:** Repository issue searches for incoming-commit and fetch notifications found the older same-symptom request https://github.com/microsoft/vscode/issues/100372, but it is closed and therefore cannot be a duplicate canonical. This proposal rests on its explicit extension-candidate decision, not on age, lack of upvotes, or the prior review.
