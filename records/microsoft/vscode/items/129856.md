# Issue #129856 — Simple split editor should show the full file path in an editor tab tooltip

[https://github.com/microsoft/vscode/issues/129856](https://github.com/microsoft/vscode/issues/129856)

## Summary

The split JSON settings editor still loses the editable file's path when constructing its tab tooltip. Keep this accepted, team-authored bug open; the current source confirms the reported behavior.

## Change summary

Show the editable settings.json file's full path in the split settings editor's tab tooltip.

## Best solution

Make the split settings input expose the editable settings file's full path through its long title, while preserving concise tab names and existing behavior for unrelated side-by-side editors.

## Evidence

- **Original observable symptom:** https://github.com/microsoft/vscode/issues/125952#issuecomment-881169386 reports multiple settings.json tabs with no path in their titles or tooltips; copying the path through Open Editors is the documented workaround. The issue author explicitly accepted the need to customize the editor input.
- **Current settings input construction:** src/vs/workbench/services/preferences/browser/preferencesService.ts:431-442 opens the split settings editor using createSplitJsonEditorInput(), which constructs a generic SideBySideEditorInput with only editableSettingsEditorInput.getName() as its preferred name, no preferred description, and distinct default-settings and editable-settings inputs.
- **Source-confirmed path loss:** In src/vs/workbench/common/editor/sideBySideEditorInput.ts, getTitle() delegates to the primary input only when both sides match. The split settings inputs do not match, so it calls EditorInput.getTitle(), which returns getName() at src/vs/workbench/common/editor/editorInput.ts:164-165. The preferred name then supplies settings.json rather than its path; getPreferredTitle() adds only the same name, not the editable resource's long title.
- **Tooltip consumes the deficient title:** src/vs/workbench/browser/parts/editor/editorTabsControl.ts:621-632 constructs the tab hover from editor.getTitle(Verbosity.LONG). Thus requesting long verbosity does not recover the path omitted by the split input. This conclusion comes from source inspection, not an executed UI reproduction.
