# Issue #233942 — Semantic tokens are causing a large changed range onTokensChanged event to fire

[https://github.com/microsoft/vscode/issues/233942](https://github.com/microsoft/vscode/issues/233942)

## Summary

The requested optimization remains necessary on current main: viewport semantic-token updates still emit and invalidate the full requested range even when most token data is unchanged. The issue is assigned, explicitly referenced by a source TODO, and parked in the Backlog, so it should remain open.

## Change summary

Report only lines whose semantic tokens actually changed instead of firing a viewport-sized token-change range after scrolling.

## Best solution

Have semantic-token updates identify the minimal changed line ranges before notifying model and view consumers, avoiding redundant GPU cache invalidation while preserving conservative invalidation when tokens are removed or replaced wholesale.

## Plan brief

- **Likely files:** `src/vs/editor/common/tokens/sparseTokensStore.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/common/viewModel/viewModelImpl.ts`, `src/vs/editor/browser/gpu/renderStrategy/fullFileRenderStrategy.ts`, `src/vs/editor/test/common/model/tokensStore.test.ts`
- **Validation:** Add a semantic-token model/store test that applies an overlapping viewport-sized partial update with only one changed line and asserts that the emitted model token-change ranges contain only that line; also cover unchanged, removed-token, and full-replacement updates.
- **Behavior:**

  > When a viewport semantic-token request repeats token data already stored for most lines, token-change notifications should cover only lines whose effective tokens changed. An identical update should not cause viewport-wide GPU cache invalidation, while added, modified, and removed tokens must still invalidate every affected line. Full-document replacement or clearing must continue to notify all genuinely affected content.
- **Trace:**

  > ViewportSemanticTokensContribution in src/vs/editor/contrib/semanticTokens/browser/viewportSemanticTokens.ts requests visible ranges after scrolling and passes each result to TokenizationTextModelPart.setPartialSemanticTokens. SparseTokensStore.setPartial in src/vs/editor/common/tokens/sparseTokensStore.ts removes and reinserts intersecting pieces, then returns the entire union range without comparing old and new token data. TokenizationTextModelPart emits that range, ViewModel converts it to a ViewTokensChangedEvent, and FullFileRenderStrategy invalidates every line in it; its onTokensChanged TODO explicitly cites https://github.com/microsoft/vscode/issues/233942. The boundary includes all consumers of IModelTokensChangedEvent: exactness must not suppress notifications for removed tokens, full semantic-token replacement, syntactic-token changes, or model-to-view line conversion.

## Evidence

- **current source:** src/vs/editor/browser/gpu/renderStrategy/fullFileRenderStrategy.ts explicitly references https://github.com/microsoft/vscode/issues/233942 in onTokensChanged and states that the event still fires for the entire viewport whenever scrolling stops.
- **event producer:** src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts calls SparseTokensStore.setPartial and emits the returned range without checking which stored tokens actually changed.
- **root cause:** src/vs/editor/common/tokens/sparseTokensStore.ts setPartial returns the union of the requested range and incoming token-piece ranges; it replaces intersecting pieces but performs no equality comparison to derive minimal changed lines.
