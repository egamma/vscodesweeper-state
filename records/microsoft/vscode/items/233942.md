# Issue #233942 — Semantic tokens are causing a large changed range onTokensChanged event to fire

[https://github.com/microsoft/vscode/issues/233942](https://github.com/microsoft/vscode/issues/233942)

## Summary

A real optimization gap remains on current main: viewport semantic-token refreshes still report the entire requested range even when most or all stored tokens are unchanged. The issue is already correctly classified and routed to the Backlog.

## Change summary

Make semantic-token change events report only lines whose effective tokens changed instead of invalidating the full viewport request range.

## Best solution

Define precise change-event semantics for partial semantic-token replacement, then have the token store expose the smallest changed line ranges so renderers can retain unaffected cached lines without adding more work than the avoided invalidation.

## Plan brief

- **Likely files:** `src/vs/editor/common/tokens/sparseTokensStore.ts`, `src/vs/editor/common/model/tokens/tokenizationTextModelPart.ts`, `src/vs/editor/test/common/model/tokensStore.test.ts`
- **Validation:** Add targeted semantic-token model/store tests showing that replacing a viewport range with identical tokens causes no changed-line invalidation, while changing or removing tokens on one line reports only that line; existing partial-token replacement tests must continue to pass.
- **Behavior:**

  > Refreshing semantic tokens for a viewport must invalidate only lines whose effective semantic tokens changed. Repeating an identical result must not force viewport-wide cache rewrites, while added, removed, and modified tokens must still invalidate every affected line. Acceptance covers identical replacement, a single changed line, token removal, and overlapping partial ranges.
- **Trace:**

  > ViewportSemanticTokensContribution._requestRange in src/vs/editor/contrib/semanticTokens/browser/viewportSemanticTokens.ts forwards the full requested viewport range to TokenizationTextModelPart.setPartialSemanticTokens. SparseTokensStore.setPartial in src/vs/editor/common/tokens/sparseTokensStore.ts replaces pieces and returns that full range without comparing old and new effective tokens; TokenizationTextModelPart then emits it through onDidChangeTokens. This is the same path described by https://github.com/microsoft/vscode/issues/233942 and remains present on current main. The boundary is semantic-token change-range accuracy: partial replacement behavior, stale-token removal, syntactic tokenization events, and provider request scheduling must remain unchanged. The uncertainty starts at whether detecting unchanged lines belongs in SparseTokensStore and whether the event contract should permit no event or multiple disjoint ranges.
- **Open decisions:**
  - Should an identical partial semantic-token result suppress onDidChangeTokens entirely, or emit an event with no ranges?
  - Should one refresh report multiple disjoint changed ranges, or one minimal enclosing line range?
  - What comparison strategy provides accurate ranges without making token refresh more expensive than the cache work it avoids?
