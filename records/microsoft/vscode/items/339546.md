# Issue #339546 — Task problem monitor drops distinct errors on the same file

[https://github.com/microsoft/vscode/issues/339546](https://github.com/microsoft/vscode/issues/339546)

## Summary

Confirmed defect in current source: TaskProblemMonitor keys each owner's marker map only by resource URI, so a second error on the same file overwrites the first. An open PR already targets this fix, so the issue should stay open pending review/merge rather than being closed now.

## Change summary

TaskProblemMonitor.getTaskProblems() drops earlier errors when two distinct errors are reported for the same resource, keeping only the last.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339550 ("Preserve distinct task errors from the same resource"), which appears to key markers by a combination of resource URI and the project's existing marker identity rather than resource alone.

## Evidence

- **source bug:** src/vs/workbench/contrib/tasks/browser/taskProblemMonitor.ts line 57: `markerMap.set(marker.resource.toString(), marker);` uses only the resource string as the map key inside each owner's marker map, so a later marker for the same resource overwrites an earlier one regardless of line/column.
- **getTaskProblems impact:** getTaskProblems() (lines 79-98) iterates markerData.markers, which can only hold one entry per resource per owner given the keying above, so only the last error per file is returned.
