# Issue #336293 — MCP HTTP client: cross-origin redirect handling strips credentials from the caller's headers, so a retry to the original server goes out without Mcp-Session-Id and Cookie

[https://github.com/microsoft/vscode/issues/336293](https://github.com/microsoft/vscode/issues/336293)

## Summary

Confirmed on main: McpHTTPHandle._fetch mutates the caller's shared init.headers object when stripping credentials on a cross-origin redirect, so a subsequent retry to the original origin (e.g. after a 401) goes out without Mcp-Session-Id/Cookie. An open PR already fixes this with a regression test, so it should be reviewed and landed rather than closed now.

## Change summary

Cross-origin redirect handling in the MCP HTTP client strips Mcp-Session-Id and Cookie from the caller's shared headers object, so a later retry against the original server is missing them.

## Best solution

Land https://github.com/microsoft/vscode/pull/336295, which reworks `_fetch` in src/vs/workbench/api/common/extHostMcp.ts to operate on a per-hop local `headers` copy instead of mutating `init.headers`, and adds a regression test in src/vs/workbench/api/test/common/extHostMcp.test.ts.
