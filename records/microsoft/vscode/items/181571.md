# Issue #181571 — Improved visual image diffing in source control

[https://github.com/microsoft/vscode/issues/181571](https://github.com/microsoft/vscode/issues/181571)

## Summary

Keep open: the built-in image preview still lacks overlap or difference highlighting. Custom diff APIs now provide a possible foundation, but they do not deliver the requested image-comparison experience; a maintainer should settle whether that experience belongs in the bundled preview or an external custom editor.

## Change summary

Provide image-comparison views that reveal subtle pixel changes instead of relying only on side-by-side previews.

## Best solution

Deliver an image-aware custom diff view that makes subtle changes visible while preserving ordinary image preview and side-by-side comparison. Follow the maintainer's custom-editor direction, first deciding whether the renderer should be bundled or extension-provided.

## Plan brief

- **Likely files:** `extensions/media-preview/package.json`, `extensions/media-preview/src/imagePreview/index.ts`, `extensions/media-preview/media/imagePreview.js`, `src/vscode-dts/vscode.proposed.customEditorDiffs.d.ts`, `src/vs/workbench/contrib/customEditor/browser/customEditors.ts`
- **Validation:** After the product decision, compare two tracked PNG revisions differing in a small, known pixel region through Source Control. The chosen comparison view must expose that region clearly, show no differences for identical pixels, and preserve normal image preview and existing side-by-side comparison.
- **Behavior:**

  > Users comparing image revisions in Source Control need to identify subtle visual changes that are difficult to find in separate previews. The chosen comparison experience should visibly reveal a small known changed region and distinguish it from an identical image pair. Ordinary image preview and existing side-by-side comparison should remain available. The maintainer must first decide whether this experience is bundled or supplied by an external custom editor.
- **Trace:**

  > The bundled image provider is ImagePreviewManager in extensions/media-preview/src/imagePreview/index.ts; it resolves one document per preview and passes a single src to extensions/media-preview/media/imagePreview.js. Its package.json contributes preview, zoom, copy, and reopen capabilities, not image-diff modes. CustomEditorService.createDiffEditorInput and getDiffEditorLayout in src/vs/workbench/contrib/customEditor/browser/customEditors.ts choose provider-specific diff layouts when supported and otherwise retain two independent previews. The proposed customEditorDiffs API supplies both documents to a single webview, but the bundled image provider does not implement it. The maintainer's direction is recorded at https://github.com/microsoft/vscode/issues/181571#issuecomment-3485469345; the older extension-fit precedent is https://github.com/microsoft/vscode/issues/165003#issuecomment-1297951297. The remaining uncertainty is product ownership and the minimum comparison interaction, not whether generic custom diff infrastructure exists. Keep unrelated PNG-loading failures and general custom-editor API finalization outside this feature's acceptance boundary.
- **Open decisions:**
  - Should subtle image comparison be available in the bundled Media Preview extension, or should VS Code provide the custom-editor foundation and leave the renderer to an external extension?
  - Which minimum user-facing comparison experience should satisfy this request: an adjustable overlap view, explicit changed-pixel highlighting, or both?

## Evidence

- **Existing capability does not cover the request:** extensions/media-preview/package.json registers imagePreview.previewEditor and commands for zooming, copying, and reopening images, but no image-comparison mode. In extensions/media-preview/src/imagePreview/index.ts, ImagePreviewManager resolves individual documents and ImagePreview.getWebviewContents supplies one src; media/imagePreview.js renders one image. Neither implements overlap or pixel-difference highlighting.
- **Current diff fallback:** src/vs/workbench/contrib/customEditor/browser/customEditors.ts:204–263 selects custom diff layouts only when providers advertise the corresponding capabilities; otherwise it wraps two individual CustomEditorInput instances in DiffEditorInput. The bundled image provider does not implement the custom diff methods, so diffEditor.renderSideBySide is not an image-overlay setting.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/181571#issuecomment-3485469345 says custom editors should be able to handle diff views. This identifies a plausible implementation surface, not evidence that image highlighting has shipped.
- **API foundation is not product completion:** src/vscode-dts/vscode.proposed.customEditorDiffs.d.ts exposes resolveCustomEditorInlineDiff with both documents and one webview, plus a side-by-side counterpart. https://github.com/microsoft/vscode/issues/298924 is closed and describes custom diff infrastructure, but the bundled image preview does not adopt it to implement this request. https://github.com/microsoft/vscode/issues/138525 is also closed and concerns the general API rather than the remaining image-rendering capability.
- **Canonical search and precedent:** Repository issue searches for image diff, image diffing, image comparison, and image overlay found no verified open canonical owning this request. The older same-scope https://github.com/microsoft/vscode/issues/165003 is closed; its maintainer comment at https://github.com/microsoft/vscode/issues/165003#issuecomment-1297951297 recommends an extension. It is useful scope precedent, but not a duplicate target, and this item's Backlog acceptance bars a decline close.
- **Discussion and demand:** The issue has 15 body upvotes, a Backlog milestone, and maintainer interest. https://github.com/microsoft/vscode/issues/181571#issuecomment-3465975816 reports a missing PNG preview, which is a separate loading symptom rather than evidence that the requested comparison mode exists. The later comment at https://github.com/microsoft/vscode/issues/181571#issuecomment-4661032757 reiterates demand but does not establish implementation scope or effort.
