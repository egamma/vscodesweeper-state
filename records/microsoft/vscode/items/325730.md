# Issue #325730 — workbench.action.chat.nextUserPrompt/previousUserPrompt reveal the target prompt at inconsistent viewport positions

[https://github.com/microsoft/vscode/issues/325730](https://github.com/microsoft/vscode/issues/325730)

## Summary

The directional viewport inconsistency remains on current main and is directly traceable in the reveal path. This team-authored, bounded chat-navigation bug should remain open for a focused fix.

## Change summary

Make Next User Prompt and Previous User Prompt reveal their target prompt at the same fixed viewport position.

## Best solution

Use the established top-aligned prompt reveal behavior for both navigation commands while preserving their existing focus, clamping, and no-wrap semantics.

## Evidence

- **source reproduction:** src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts calls `widget.reveal(targetPrompt)` without a relative position for both commands.
- **directional behavior:** src/vs/base/browser/ui/list/listWidget.ts implements an omitted `relativeTop` as minimal scrolling: an item above the viewport is aligned to the top, while an item below it is aligned to the bottom.
- **existing convention:** src/vs/workbench/contrib/chat/browser/promptTimeline/promptTimelineModel.ts explicitly reveals prompts with relative position `0`, establishing top alignment for prompt navigation elsewhere in the chat UI.
- **API boundary:** ChatWidget and ChatListWidget already forward an optional `relativeTop`, but the IChatWidget declaration in src/vs/workbench/contrib/chat/browser/chat.ts currently exposes only `reveal(item)`, so the public widget contract must be kept consistent.
