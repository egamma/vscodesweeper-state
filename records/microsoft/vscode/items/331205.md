# Issue #331205 — Chat layout storage race

[https://github.com/microsoft/vscode/issues/331205](https://github.com/microsoft/vscode/issues/331205)

## Summary

Team-authored, still-open race in the agents-window grid persistence: no fix commit references this issue and the underlying storage design in sessionsService.ts plausibly explains the loss, so this stays open (Backlog milestone doesn't block keeping it, and there's no implemented-on-main or duplicate evidence to justify a close).

## Change summary

Reloading shortly after laying out a multi-chat grid and switching to a different session can lose the grid layout when switching back.

## Best solution

In src/vs/sessions/services/sessions/browser/sessionsService.ts, grid placement (visibleOrder/isActive/isSticky) is only snapshotted in `_snapshotVisibleSessionStates`, invoked from `_saveSessionStates` on `storageService.onWillSaveState` — i.e. whatever is visible *at save time* wins, and a save that lands after the switch-away (but before/without another save capturing the prior grid) can leave the old grid's sessions without a `visibleOrder`, so `_getVisibleSessionStates`/`_restoreVisibleSessions` never rebuilds them. Consider capturing/retaining the previous grid layout eagerly on switch-away rather than lazily at `onWillSaveState`, similar to the eager-capture fix already applied to editor-part-hidden state (see the comment at line ~769 in baseSessionLayoutController.ts referencing the same class of restore race).

## Evidence

- **snapshot-at-save-time design:** src/vs/sessions/services/sessions/browser/sessionsService.ts:1144-1201 — `_saveSessionStates`/`_snapshotVisibleSessionStates` only assign `visibleOrder`/`isActive`/`isSticky` to sessions that are visible in the grid at the moment `storageService.onWillSaveState` fires (line 396); sessions switched out of the grid just before that save are persisted with grid fields stripped (comment at line 1149: "Grid-placement fields are stripped so they are not restored into the grid").
- **restore reads only persisted visibleOrder:** `_getVisibleSessionStates()` (line 1207) and `_restoreVisibleSessions()` (line 1273) rebuild the grid solely from entries that still carry a `visibleOrder`, so a grid snapshotted-away by a same-tick switch is unrecoverable on reload.
- **known related race class:** baseSessionLayoutController.ts:769-772 documents an analogous "races with the incoming session's async layout restore" issue for editor-part-hidden state, suggesting the same lazy-capture-at-switch pattern is the likely root cause here too.
- **no fix found:** `git log` on sessionsService.ts and repo-wide search for '331205' turn up no commit or PR referencing this issue.
