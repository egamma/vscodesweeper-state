# Issue #331205 — Chat layout storage race

[https://github.com/microsoft/vscode/issues/331205](https://github.com/microsoft/vscode/issues/331205)

Team-authored bug report with an assigned real milestone (1.135.0), which bars any close under the hard keep-open rules regardless of other evidence; the reporter also flags it as a timing-dependent repro they haven't nailed down precisely.

## Change summary

Grid chat layout is lost after switching sessions and reloading the window in a fast sequence, apparently due to a race in when the layout is persisted/restored.

## Best solution

Needs investigation in src/vs/sessions/contrib/layout/browser/desktopSessionLayoutController.ts (and the singlePane layout strategies) to find where session switch + window reload can race the save of the grid layout state before storage; the reporter's own note about timing sensitivity suggests an async save that isn't awaited/ordered before reload captures state.
