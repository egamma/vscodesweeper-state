# Issue #326800 — When using dev containers, copilot uses `~/.copilot` within the container

[https://github.com/microsoft/vscode/issues/326800](https://github.com/microsoft/vscode/issues/326800)

## Summary

Real request, but it stems from how VS Code's remote extension-host model works, not a core bug — the fix, if any, likely belongs in the Dev Containers tooling (mounts) or in the Copilot extension's remote-awareness, so routing to the relevant area rather than proposing a close.

## Change summary

Custom agents created via `~/.copilot` inside a dev container land in the container's home directory instead of being shared with the host.

## Best solution

No core VS Code change is clearly indicated: `envService.userHome` (src/vs/platform/environment or extensions/copilot/src/platform/env/vscode-node/nativeEnvServiceImpl.ts) correctly resolves to the extension host's own home directory, which is the container's home when running remote — the same as `.gitconfig`/`.ssh` not auto-syncing today. Sharing `~/.copilot` across host and container is something users can already do via a `mounts` entry in `devcontainer.json` (e.g. bind-mounting `${localEnv:HOME}/.copilot`); a maintainer should decide whether this warrants a default mount recommendation (Dev Containers docs/tooling) or a Copilot-side remote-agent-sync feature before committing to either.
