# Issue #326800 — When using dev containers, copilot uses `~/.copilot` within the container

[https://github.com/microsoft/vscode/issues/326800](https://github.com/microsoft/vscode/issues/326800)

## Summary

A real customization/remote integration gap remains: personal `~/.copilot/agents` paths resolve against the Dev Container home on current main, so they are not shared with the host. Route this to the chat customization and container owners for a decision on host-versus-remote personalization semantics.

## Change summary

Make personal Copilot agents available from the host home when working inside a Dev Container instead of isolating them in the container home.

## Best solution

Define consistent remote-workspace semantics for personal Copilot customizations so host-level agents can be shared across local and Dev Container windows, while preserving an explicit way to use container-specific customizations if that remains supported.
