# Issue #326800 — When using dev containers, copilot uses `~/.copilot` within the container

[https://github.com/microsoft/vscode/issues/326800](https://github.com/microsoft/vscode/issues/326800)

## Summary

Legitimate bug: the prompts/customization discovery code uses `pathService.userHome()` without `preferLocal: true`, so in a dev container `~/.copilot` resolves to the container's home directory instead of the host's. The issue is traceable in source but the fix is cross-cutting across multiple call sites.

## Change summary

When using dev containers, Copilot custom agents and instructions placed in `~/.copilot` on the host are not found because the path resolves to the container's `~` instead.

## Best solution

Audit all `pathService.userHome()` calls in the prompts/customization discovery code (promptsServiceImpl.ts, promptFilesLocator.ts, aiCustomizationItemSource.ts, agentPluginServiceImpl.ts) and use `preferLocal: true` where the intent is to read user-level customization from the host. Some call sites (agentHostSessionHandler, chatContext, exportAgentHostDebugLogsAction) already do this correctly — the pattern exists, it just needs to be applied consistently for `~/.copilot` discovery.
