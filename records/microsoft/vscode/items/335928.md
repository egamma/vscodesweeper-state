# Issue #335928 — permissions.disableBypassPermissionsMode "allow-auto-only" incorrectly enables "Allow all" in Local and Copilot harnesses in VSCode

[https://github.com/microsoft/vscode/issues/335928](https://github.com/microsoft/vscode/issues/335928)

## Summary

Traced this in the current source: the client-side policy gate for the bypass/"Allow All" permission level only special-cases the managed-settings value `'disable'`, never the documented `'allow-auto-only'` enum value, so an admin's `allow-auto-only` restriction silently fails to lock "Allow All" in VS Code's UI even though the same key correctly restricts other clients.

## Change summary

Setting `permissions.disableBypassPermissionsMode: "allow-auto-only"` via managed-settings.json should permit assisted/auto-approve-per-tool permissions but keep full "Allow All" bypass locked; instead VS Code still lets users select "Allow All" in both the local and Copilot harnesses.

## Best solution

Extend `autoApprovePolicyValue` in src/vs/workbench/contrib/chat/common/agentHostConfigPolicy.ts (and the restriction helpers it feeds, `isAutoApprovePolicyRestricted`/`isAutoApproveValuePolicyRestricted`) to recognize `'allow-auto-only'` as a distinct, less-total lock than `'disable'` — one that blocks `ChatPermissionLevel.AutoApprove`/`Autopilot` but still permits `Assisted` — then thread that tri-state through the ~15 call sites that currently treat policy restriction as a boolean (chatInputPart.ts, permissionPickerActionItem.ts, languageModelToolsConfirmationService.ts, the agentHost session providers, etc.).

## Evidence

- **policy value callback:** src/vs/workbench/contrib/chat/common/agentHostConfigPolicy.ts:12-14 `autoApprovePolicyValue` returns `false` (restricted) only when `managedSettings[COPILOT_DISABLE_BYPASS_PERMISSIONS_MODE_KEY] === 'disable'`; any other value, including `'allow-auto-only'`, returns `undefined` and the restriction never applies.
- **documented enum ignored:** .github/skills/policy-and-managed-settings/github-managed-settings.md:53 documents `permissions.disableBypassPermissionsMode` as a string enum `'disable' | 'allow-auto-only'` with most-restrictive-wins composition, but no VS Code code path (grep across src/vs) ever compares against `'allow-auto-only'` — the agent-host bridge type itself is typed as `disableBypassPermissionsMode?: 'disable'` (src/vs/platform/agentHost/common/agentHostManagedSettings.ts:63).
- **single gate reused everywhere:** `isAutoApprovePolicyRestricted`/`isAutoApproveValuePolicyRestricted` (same file) are the sole restriction gate consumed by chatInputPart.ts, permissionPickerActionItem.ts, languageModelToolsConfirmationService.ts, languageModelToolsService.ts, and the agentHost session providers — explaining why the gap affects both the local and Copilot harnesses identically.
