# Issue #335928 — Align approval modes with resolved managed permission policy

[https://github.com/microsoft/vscode/issues/335928](https://github.com/microsoft/vscode/issues/335928)

## Summary

The gap is real and confirmed in source: the Agent Host derives `_getSdkPermissionMode()`/`_isBypassApprovals()` from a single boolean root-config flag (`AgentHostAutoApprovePolicyRestrictedConfigKey`, set synchronously in `_updateAutoApprovePolicyRestriction()`), while the Copilot SDK's own managed-settings restriction (`disableBypassPermissionsMode` in `agentHostManagedSettingsService.ts`) is a separate, asynchronously-populated permission set with no shared 'resolved/pending/fail-closed' state — exactly the architectural gap the issue describes. This stays open; it's too broad and design-dependent for a single bounded patch.

## Change summary

Align the picker/session permission-mode selection and the SDK's actual enforced mode with the resolved managed-permission policy, including handling of unresolved/pending policy state, across both the Agent Host (Copilot) and the Local harness.

## Best solution

Introduce a shared, explicitly-resolved effective session permission state (readiness + restriction) that both the picker/session config and `_getSdkPermissionMode()`/`syncPermissionMode()` in copilotAgentSession.ts consult before calling `permissions.setMode`, reconciling it on create/resume/turn-start/config-change without silently escalating or clobbering stored user preferences; verify the Local harness's separate policy consumer independently rather than assuming an Agent Host fix covers it.
