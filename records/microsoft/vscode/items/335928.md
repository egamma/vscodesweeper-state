# Issue #335928 — permissions.disableBypassPermissionsMode "allow-auto-only" incorrectly enables "Allow all" in Local and Copilot harnesses in VSCode

[https://github.com/microsoft/vscode/issues/335928](https://github.com/microsoft/vscode/issues/335928)

## Summary

Confirmed on source: VS Code's managed-settings schema for `permissions.disableBypassPermissionsMode` only recognizes the literal `'disable'` (src/vs/platform/agentHost/common/agentHostManagedSettings.ts:63,291,317-332); there is no `allow-auto-only`/granular-tier value at all, so the original 'incorrectly enables Allow All' report reflects a genuine capability gap rather than a simple mis-mapping bug. A MEMBER (rwoll) has already engaged and committed to look deeper with the team on the requested granularity, so this stays open pending that design work.

## Change summary

Admins want to disable bypass/yolo-mode across all GHC clients while still allowing (optionally team-scoped) Assisted Permissions mode, using a documented `allow-auto-only` policy value that VS Code doesn't currently support.

## Best solution

A maintainer needs to decide the shape of a more granular admin permissions policy (disable bypass entirely vs. enable Assisted Permissions vs. team-scoped access) and extend agentHostManagedSettings.ts's schema/contribution logic accordingly; the separate first-request permission-sync race reported by brunogsystem (copilotAgentSession.ts's syncPermissionMode/`_syncPermissionModeAfterConfigChange`) is a distinct, more mechanical defect that may be worth splitting into its own issue.
