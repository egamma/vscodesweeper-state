# Issue #335928 — Align approval modes with resolved managed permission policy

[https://github.com/microsoft/vscode/issues/335928](https://github.com/microsoft/vscode/issues/335928)

## Summary

Security-sensitive permission-bypass enforcement report — never propose closing per the hard keep-open rule for sandbox/permission-escape concerns. The underlying gap (permission mode not reflecting resolved managed policy before the SDK call) is source-traceable in copilotAgentSession.ts, but the full scope (Local harness, race/readiness handling, restored sessions) is not yet fully verified.

## Change summary

Agent Host's displayed/effective approval mode (picker + SDK permissions.setMode call) can diverge from the resolved managed-settings bypass-permission policy, especially under unresolved/fail-closed policy or in the Local harness, risking either a rejected 'allow-all' call or an incorrectly offered Allow All.

## Best solution

Introduce a shared effective session permission-mode state that Agent Host's picker, SDK mode selection (_getSdkPermissionMode/syncPermissionMode in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts), and the Local harness's editor-policy consumer all read from, gated on policy-resolution readiness rather than best-effort config reads — this needs design input given the several interacting timing scenarios described.
