## Plan brief

- **Likely files:** `src/vs/sessions/contrib/providers/remoteAgentHost/browser/manageRemoteAgentHosts.ts`, `src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteHostOptions.ts`, `src/vs/sessions/contrib/providers/remoteAgentHost/browser/tunnelAgentHost.contribution.ts`
- **Validation:** A UI/action test confirming the tunnels action opens the enhanced management surface and that host rename/reconnect actions remain reachable.
- **Behavior:**

  > Clicking the tunnels/remote-connections action should surface an entry point to full remote agent host management (enable/disable toggle, host list with state, rename/reconnect), instead of requiring users to separately discover the 'Manage Remote Agent Hosts...' command.
- **Trace:**

  > Today, host listing/rename/reconnect logic already lives in manageRemoteAgentHosts.ts (quick pick UI) and remoteHostOptions.ts (per-host actions), gated by the RemoteAgentHostsEnabledSettingId setting; the tunnels action itself (in tunnelAgentHost.contribution.ts) does not currently link to this flow. The boundary: reuse/extend this existing quick pick and its action set rather than building a parallel UI; do not change the underlying tunnel/host services.
- **Open decisions:**
  - Should the tunnels action open the existing 'Manage Remote Agent Hosts...' quick pick directly, or a new richer view/panel?
  - Where does the enable/disable checkbox live — inline in the list, or as a separate toggle above it?
  - Should this change the tunnels action's default click behavior for all users, or add a secondary discoverable affordance?
