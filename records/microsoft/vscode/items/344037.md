# Issue #344037 — Chat: let tools hint how string parameters should be rendered (syntax highlighting for code, SQL, shell, etc.)

[https://github.com/microsoft/vscode/issues/344037](https://github.com/microsoft/vscode/issues/344037)

## Summary

Keep open as a feature request: current Chat supports highlighting an entire tool input, but not schema-directed rendering of individual string parameters. The supplied searches did not establish an existing canonical issue covering this capability.

## Change summary

Allow tool schemas to supply optional per-parameter language hints so Chat displays code-like strings with decoded newlines and syntax highlighting.

## Best solution

Provide a consistent, optional presentation contract for MCP and extension tools that preserves readable parameter names, remaining JSON, and unchanged invocation values. Settle the annotation vocabulary and its interaction with editable approval inputs before implementation.

## Evidence

- **Existing capability is only whole-input highlighting:** src/vs/workbench/contrib/chat/common/tools/languageModelToolsService.ts:286-294 defines IToolResultInputOutputDetails.inputLanguage for the entire input string. ChatInputOutputMarkdownProgressPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatInputOutputMarkdownProgressPart.ts passes that string to one createCodePart(input, inputLanguage); its MIME-to-language handling applies to output parts, not individual input parameters.
- **MCP inputs retain JSON escaping:** src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts:252-260 supplies rawInput without parameter presentation metadata, and lines 277-281 construct completed input using JSON.stringify(invocation.parameters, undefined, 2). Multiline string properties therefore remain escaped within JSON; the proposed schema hints are not consumed on this path.
- **Approval rendering is a separate editable surface:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatToolConfirmationSubPart.ts:184-222 renders rawInput through JSON.stringify with a JSON language identifier and enables editing unless inputData.editable is false. Separate per-parameter presentation must account for this existing editing behavior, not only completed tool output.
- **Schema annotation is not presentation support:** src/vs/workbench/contrib/chat/common/tools/languageModelToolsParametersSchema.ts already declares contentMediaType in its schema vocabulary, but the source search found no tool-rendering consumer of that keyword. Accepting an annotation does not deliver the requested decoded, per-parameter code blocks.
