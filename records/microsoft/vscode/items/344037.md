# Issue #344037 — Chat: let tools hint how string parameters should be rendered (syntax highlighting for code, SQL, shell, etc.)

[https://github.com/microsoft/vscode/issues/344037](https://github.com/microsoft/vscode/issues/344037)

## Summary

A real presentation gap remains: current Chat supports a language for the entire input block, but not schema-directed rendering of individual string parameters. Keep this request open for design; the discussion supplies another concrete SQL/shell use case.

## Change summary

Allow tools to annotate string arguments so Chat displays decoded, syntax-highlighted content alongside the remaining JSON parameters.

## Best solution

Provide optional, display-only parameter hints shared by MCP and extension tools, with readable expanded inputs and approval prompts. Preserve exact invocation values, understandable parameter attribution, historical rendering, and compatibility with unannotated tools.

- **Behavior:**

  > Annotated code-like string arguments should be readable with their actual newlines and appropriate syntax highlighting, while remaining arguments retain an understandable JSON representation. Missing or unsupported hints must retain compatible behavior. Display metadata must not change validation, model-visible arguments, or executed values. Acceptance includes expanded input, approval prompts, editable-input consistency, and restored conversations.
- **Trace:**

  > MCP tool registration and invocation preparation live in src/vs/workbench/contrib/mcp/common/mcpLanguageModelToolContribution.ts; the completed result currently stringifies the full parameter object. IChatToolInputInvocationData stores rawInput, while IToolResultInputOutputDetails exposes only a whole-input inputLanguage. ChatInputOutputMarkdownProgressPart renders one input code part, and ChatToolConfirmationSubPart independently serializes input into an editable JSON editor. The schema definition already recognizes contentMediaType, but no parameter-presentation consumer was found. The discussion at https://github.com/microsoft/vscode/issues/344037 adds historical-rendering, provider-compatibility, parameter-attribution, and approval-surface concerns. Preserve existing approval decisions and exact argument semantics; uncertainty remains in the annotation contract and how the richer presentation coexists with confirmation editing.
- **Open decisions:**
  - Should the supported annotation contract be contentMediaType alone, or also include an explicit language-ID fallback for formats without registered MIME mappings?
  - In editable approval prompts, should separated highlighted parameters themselves be editable, or remain a preview alongside the existing authoritative JSON editor?
