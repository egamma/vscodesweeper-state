# Issue #269158 — Cloud Agent stop button (cancel button) and cancellation is not handled properly

[https://github.com/microsoft/vscode/issues/269158](https://github.com/microsoft/vscode/issues/269158)

## Summary

Keep open: current source cancels local cloud-response streaming without stopping the remote task. Later reports confirm the cancellation and chat-state problems; this reopened, team-authored issue remains the established place to track them.

## Change summary

Make the cloud agent Stop button actually stop the delegated run and reconcile the chat input and session state.

## Best solution

Explicit Stop should cancel the remote cloud task and leave the chat input, session list, and restored session consistent with the resulting state. Distinguish that operation from local streaming disposal and steering so switching sessions or yielding a response does not accidentally stop remote work.

- **Behavior:**

  > After delegating a task to the cloud agent, pressing Stop must stop the remote run rather than merely stop displaying its output. The chat input and session list must reflect the resulting state, and reloading must not resurrect the stopped run as active. Loading a session and then switching away must not let the obsolete load steal focus. Steering and ordinary local view disposal must retain their existing non-terminating behavior.

  > ExtHostChatSessions.$interruptChatSessionActiveResponse and $disposeChatSessionContent both cancel the same disposeCts token in src/vs/workbench/api/common/extHostChatSessions.ts.
