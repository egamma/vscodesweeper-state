# Issue #249604 — NES/Inline Completion - Get more information on show

[https://github.com/microsoft/vscode/issues/249604](https://github.com/microsoft/vscode/issues/249604)

## Summary

Keep open: current code records some NES presentation details internally, but providers still receive a one-time shown callback without the requested visibility information. Neither verified related issue owns this API extension.

## Change summary

Expose NES presentation kind, visible ranges, rendered edits, and cursor position to inline completion providers, including subsequent visibility changes.

## Best solution

Define a provider-facing presentation notification contract in the inline-completions proposed API that distinguishes initial display from later preview and visibility changes. Reuse existing internal presentation information where appropriate, while preserving compatibility with the existing shown callback.

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.proposed.inlineCompletionsAdditions.d.ts declares handleDidShowCompletionItem(completionItem, updatedInsertText) with no presentation kind, visible ranges, rendered edits, or cursor snapshot. Settings or display commands cannot supply this missing provider callback payload.
- **Current callback remains one-shot:** src/vs/editor/contrib/inlineCompletions/browser/model/provideInlineCompletions.ts:434–449, reportInlineEditShown, updates shown duration but returns when _didShow is already true. It stores the initial viewKind and renderData internally and passes only updatedInsertText and aggregate EditDeltaInfo to the internal provider callback, so subsequent presentation changes do not produce the requested provider events.
- **Internal presentation information exists:** src/vs/editor/contrib/inlineCompletions/browser/view/inlineEdits/inlineEditsView.ts:385–389 reports the selected presentation, including Collapsed, through InlineEditsModel.handleInlineEditShownNextFrame. inlineEditsViewInterface.ts defines SideBySide, LineReplacement, Collapsed, and other view kinds, plus render counts and cursor distances. This is partial internal coverage, not the requested extension-facing visibility contract.
- **Extension-host boundary confirms the gap:** src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts:1387–1404 forwards only the completion identifiers and updatedInsertText through $handleInlineCompletionDidShow. src/vs/workbench/api/common/extHostLanguageFeatures.ts:1542–1546 invokes the provider with only the completion item and updatedInsertText.
