# Issue #146569 — Perf: optimizing notebook cell status bar items creation

[https://github.com/microsoft/vscode/issues/146569](https://github.com/microsoft/vscode/issues/146569)

## Summary

The allocation work remains on current main: visibility changes synchronously construct per-cell helpers, separate controllers maintain separate observers, and execution timers allocate schedulers even for idle cells. Keep this accepted notebook performance cleanup open; the related delay-creation issue was explicitly consolidated into this one.

## Change summary

Reduce notebook scrolling overhead from repeated cell status bar helper, listener, observer, and scheduler creation.

## Best solution

Reduce transient allocations in the notebook cell status bar controllers while preserving execution indicators, elapsed-time updates, extension-provided items, and disposal behavior. The maintainer-endorsed next-tick creation delay provides a concrete acceptance target without requiring a broader notebook scrolling redesign.
