# Issue #146569 — Perf: optimizing notebook cell status bar items creation

[https://github.com/microsoft/vscode/issues/146569](https://github.com/microsoft/vscode/issues/146569)

## Summary

The two concrete optimizations proposed (sharing the NotebookVisibleCellObserver across controllers, and deferring item creation until execution state warrants it) remain unimplemented on current main — both controllers still instantiate their own observer and eagerly create status bar items for every visible cell on scroll.

## Change summary

Optimize notebook scrolling perf by sharing the visible-cell observer and deferring status bar item creation until cells are actually executing.

## Best solution

Deduplicate the two NotebookVisibleCellObserver instances into one shared observer (or a shared event), and gate ExecutionStateCellStatusBarItem creation on the cell being in an executing/pending state rather than creating items for every visible cell unconditionally. Work lives in src/vs/workbench/contrib/notebook/browser/contrib/cellStatusBar/.
