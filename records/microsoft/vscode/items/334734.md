# Issue #334734 — Trying to switch to a remote workspace does not work

[https://github.com/microsoft/vscode/issues/334734](https://github.com/microsoft/vscode/issues/334734)

## Summary

Real, already-well-labeled feature gap: the `set_workspace` server tool intentionally rejects any non-local-file workspace URI, so agents cannot switch a session to a remote/tunnel workspace as this report demonstrates — needs a product decision on remote-workspace support, not a close.

## Change summary

Asking a chat agent to switch the session workspace to a remote (tunnel) folder fails because `set_workspace` only accepts absolute local paths or `file://` URIs.

## Best solution

Extend `getSetWorkspaceArgs` (src/vs/platform/agentHost/node/shared/sessionServerTools.ts) and `_validateConversion` (src/vs/platform/agentHost/node/chatContributions/sessionWorkspaceConversion/sessionWorkspaceConversionService.ts) to accept remote workspace URIs (e.g. `vscode-remote://`) where the underlying session-conversion/isolation logic can actually support them, rather than hard-gating on `Schemas.file`.
