# Issue #334734 — Trying to switch to a remote workspace does not work

[https://github.com/microsoft/vscode/issues/334734](https://github.com/microsoft/vscode/issues/334734)

## Summary

Team-authored report (protected from judgment closes) tracing a real gap: `getSetWorkspaceArgs` in sessionServerTools.ts hard-rejects any `workspaceFolder` whose scheme isn't `file`, so the `set_workspace` tool cannot point at a remote/tunnel workspace even though the chat asked for exactly that — keeping open pending a decision on whether remote workspace targets should be supported.

## Change summary

Asking chat to switch the agent's workspace to a remote (tunnel) folder fails with 'workspaceFolder must be an absolute local path or file URI'.

## Best solution

Either extend `parseWorkspaceUri`/`getSetWorkspaceArgs` (src/vs/platform/agentHost/node/shared/sessionServerTools.ts) to accept `vscode-remote://` workspace URIs when the agent host supports operating against a remote target, or, if remote targets are intentionally out of scope for `set_workspace` right now, document that limitation — a maintainer call, not a mechanical fix.
