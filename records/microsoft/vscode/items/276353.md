# Issue #276353 — Checkpoint restoration only reverts first file when multiple files modified across separate requests

[https://github.com/microsoft/vscode/issues/276353](https://github.com/microsoft/vscode/issues/276353)

## Summary

Keep open: current source can skip restoring an existing file first edited in a later request because its baseline cannot be found at the earlier checkpoint. The reporter supplied the requested recording, and the two-file steps are sufficient for a focused regression test.

## Change summary

Restoring the first checkpoint should undo edits to both files across successive requests, including changes already kept.

## Best solution

Make checkpoint restoration recover the pre-edit contents of existing files first touched in later requests, while preserving the distinct restoration semantics for files created, deleted, or renamed by the agent. Cover the two-request, two-file case in the checkpoint timeline tests.
