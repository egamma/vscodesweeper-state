# Issue #337673 — Copilot Chat fails when an HTTP proxy rejects CONNECT for a custom HTTP endpoint

[https://github.com/microsoft/vscode/issues/337673](https://github.com/microsoft/vscode/issues/337673)

## Summary

Well-diagnosed report whose root cause lives outside this repo: the `@vscode/proxy-agent` package's fetch-proxy path always CONNECT-tunnels through the configured proxy regardless of destination protocol, which a strict proxy rejects for plain-HTTP targets. Keeping open as upstream; the fix belongs in the `@vscode/proxy-agent` repo (and possibly undici itself), not in microsoft/vscode.

## Change summary

Copilot Chat requests to a custom HTTP (not HTTPS) chat endpoint fail through an HTTP proxy that rejects CONNECT tunneling for plain-HTTP destinations.

## Best solution

Fix `createProxyAgent()` in microsoft/vscode-proxy-agent's src/index.ts to pass a protocol-aware `proxyTunnel` option to `undici.ProxyAgent` (tunnel only for https: destinations, mirroring nodejs/undici#5116's automatic tunnel selection), then bump the `@vscode/proxy-agent` dependency version in this repo's package.json.

## Evidence

- **proxy-agent source:** package.json pins "@vscode/proxy-agent": "^0.45.0" (external repo microsoft/vscode-proxy-agent, not vendored in this checkout). Its src/index.ts createProxyAgent() builds `new undici.ProxyAgent({ uri: proxyURL, allowH2, requestTls, proxyTls, clientFactory })` with no destination-protocol-aware `proxyTunnel` setting, so undici's default always-tunnel-via-CONNECT behavior applies even for plain-http targets.
- **reporter's own repro:** Standalone test against undici 7.29.0's bundled ProxyAgent reproduces the same 403 CONNECT rejection for an http: target and confirms `proxyTunnel: false` fixes it; reporter cites nodejs/undici#5116 as the upstream commit adding automatic tunnel selection by protocol.
