# Issue #337673 — Copilot Chat fails when an HTTP proxy rejects CONNECT for a custom HTTP endpoint

[https://github.com/microsoft/vscode/issues/337673](https://github.com/microsoft/vscode/issues/337673)

## Summary

Well-diagnosed, real defect: the copilot chat fetch path goes through @vscode/proxy-agent's `createProxyAgent`, which builds a plain `undici.ProxyAgent` with no protocol-aware tunnel selection, so it always issues CONNECT even for plain-HTTP destinations. Undici only fixed this (protocol-based tunnel/forward selection) in its v8 line — VS Code is pinned to undici v7.x, which doesn't have the fix — so this is genuinely an upstream/dependency gap rather than something fixable purely in this repo today.

## Change summary

A custom chat-completions endpoint over plain HTTP fails when the configured HTTP proxy rejects CONNECT tunneling, because VS Code's proxy-aware fetch always tunnels regardless of the target's protocol.

## Best solution

Either bump the `undici` dependency to the v8 line (which added `shouldProxyTunnel` protocol-based tunnel/forward selection in nodejs/undici PR #5116) or have `@vscode/proxy-agent`'s `createProxyAgent` implement equivalent protocol-based tunnel detection itself so plain-HTTP targets are forwarded rather than CONNECT-tunneled through the proxy.

## Evidence

- **vscode pins undici v7:** package.json/package-lock.json resolve `undici` to 7.29.0 (`^7.28.0`); @vscode/proxy-agent (locked to 0.45.0 in package-lock.json) imports `undici` directly and its `createProxyAgent()` (src/index.ts) constructs `new undici.ProxyAgent({ uri: proxyURL, ... })` with no `proxyTunnel`/protocol-aware option.
- **fix only in undici v8:** nodejs/undici PR https://github.com/nodejs/undici/pull/5116 ('fix: auto-detect HTTP proxy tunneling', merged as a8d1a95b) adds `shouldProxyTunnel(requestProtocol, proxyTunnel)` to `ProxyAgent`'s `factory()` so plain-HTTP targets are forwarded instead of CONNECT-tunneled. Verified via `git merge-base --is-ancestor` against the undici repo: this commit is NOT an ancestor of v7.29.0, v7.29.1, or v7.30.0 (the current v7.x releases), but is reachable from v8.7.0+; it has not been backported to the `backport-safe-main-fixes-to-v7.x` branch either.
- **reporter's own repro:** Reporter reproduced the exact `Proxy response (403) !== 200 when HTTP Tunneling` failure with a standalone request through the bundled undici's `ProxyAgent`, and confirmed `proxyTunnel: false` makes the plain-HTTP request succeed — consistent with v7's tunnel-always behavior for `ProxyAgent`.
