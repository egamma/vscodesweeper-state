# Issue #346731 — Automations: an org-required plugin can be unchecked in an automation, but runs still load it

[https://github.com/microsoft/vscode/issues/346731](https://github.com/microsoft/vscode/issues/346731)

## Summary

Keep open: current source confirms that automation customization choices cannot represent organization-required status, and every checkbox remains editable. The defect is misleading configuration UI, not evidence that runtime policy should stop loading required plugins.

## Change summary

Organization-required plugins can be unchecked and saved in an automation even though its runs still load them.

## Best solution

Make the automation dialog reflect authoritative required-plugin policy: required entries stay checked and disabled with an accessible organization-management explanation, including when reopening previously saved definitions. Preserve runtime enforcement and normal selection behavior for optional plugins.
