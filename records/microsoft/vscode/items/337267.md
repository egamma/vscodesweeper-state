# Issue #337267 — Codex Agent Host shows "No models available" while Copilot models load normally

[https://github.com/microsoft/vscode/issues/337267](https://github.com/microsoft/vscode/issues/337267)

## Summary

Current main still exposes a demand-driven initialization gap: the Agents Window can select Codex and target its model picker before the Codex host crosses the activation boundary that populates native models. The report should remain open in the Agents Window area.

## Change summary

Selecting Codex in the Agents Window can leave its model picker empty even though Codex models work in editor chat.

## Best solution

Selecting the Codex harness should count as explicit Codex use, initiate its demand-driven model discovery, and keep the picker in a loading state until the refreshed AgentInfo model catalog is published, without requiring a first send.

- **Behavior:**

  > Selecting Codex in the Agents Window must initialize the models available to that harness before the user sends the first prompt. The model picker may show a transient loading state, but it must not settle on "No models available" when the same Codex account can enumerate models. Copilot and Claude model pickers and passive Agent Host startup behavior must remain unchanged.
- **Trace:**

  > The Codex provider in src/vs/platform/agentHost/node/codex/codexAgent.ts intentionally leaves native models empty before `_activate()` and queues discovery after activation. The Agents Window selection path in src/vs/sessions/contrib/chat/browser/sessionTypePicker.ts changes only the selected type and model target; NewChatWidget's preparation path is workspace-oriented, and no inspected call crosses the Codex activation boundary. BaseAgentHostSessionsProvider subsequently filters the registered language-model catalog to `agent-host-codex`, producing the observed empty picker. The existing demand-driven contract in sessionTypeAvailability.ts says harness selection may initialize models, so the uncertainty is the cross-process lifecycle seam and its regression-test boundary, not the expected product behavior. Do not make passive startup, authentication replay, or background catalog refresh start a persistent Codex process.
