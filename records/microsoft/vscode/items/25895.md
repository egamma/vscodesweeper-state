# Issue #25895 — Stop rendering pseudo-italic fonts when italic is not available

[https://github.com/microsoft/vscode/issues/25895](https://github.com/microsoft/vscode/issues/25895)

## Summary

Keep open: current source does not expose a font-synthesis control, and disabling token italics does not satisfy the request to preserve real italic faces while suppressing synthetic ones. The related disable-italics request is newer and covers different behavior, so it is not a valid duplicate target.

## Change summary

Suppress artificial italic and bold rendering when the selected font or fallback glyph lacks the requested face, while retaining genuine styled faces.

## Best solution

Establish an editor font-synthesis policy that preserves genuine italic and bold faces without synthesizing missing variants. Verify Chromium's treatment of fallback emoji separately rather than assuming the CSS policy resolves that upstream limitation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/config/domFontInfo.ts`, `src/vs/editor/common/languages/supports/tokenization.ts`
- **Validation:** In a maintainer-run rendering check, compare an italic-themed comment containing text and emoji using a font installed without italic or bold faces against a font with genuine styled faces. Missing faces should remain unsynthesized under the chosen policy, genuine faces should retain styling, and fallback emoji should be checked independently on desktop and Chromium-based web.
- **Behavior:**

  > The requested outcome is to avoid artificially slanted or emboldened glyphs when the selected font or fallback font lacks the requested face. Genuine italic and bold faces should remain available, unlike a blanket removal of theme font styles. Acceptance should compare fonts with and without genuine faces and include emoji in italic comments. Whether suppression becomes the default or an opt-in policy remains a maintainer decision.
- **Trace:**

  > generateTokensCSSForColorMap() in src/vs/editor/common/languages/supports/tokenization.ts requests italic and bold through token CSS. applyFontInfo() in src/vs/editor/browser/config/domFontInfo.ts supplies editor font properties, and src/vs/editor/common/config/editorOptions.ts registers font options; no font-synthesis policy was found in src/vs. Token customization can remove styling, but cannot preserve genuine faces while selectively rejecting synthesized ones. The discussion on https://github.com/microsoft/vscode/issues/25895 separates ordinary missing-face synthesis from Chromium's emoji behavior, with an upstream report at https://bugs.chromium.org/p/chromium/issues/detail?id=1416834. Preserve theme styling intent and genuine faces; do not broaden this into disabling all italics as requested by the distinct, newer https://github.com/microsoft/vscode/issues/32579. Source inspection establishes the missing policy, not the current OS/browser rendering outcome.
- **Open decisions:**
  - Should suppression of missing-face italic and bold synthesis become the editor default, or remain an opt-in font-rendering policy?
