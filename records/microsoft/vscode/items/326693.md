# Issue #326693 — Assisted approvals changing repo visibility

[https://github.com/microsoft/vscode/issues/326693](https://github.com/microsoft/vscode/issues/326693)

## Summary

Keep open: the Copilot SDK's assisted-permission classifier approved an API operation that could expose repository data, and current Agent Host code still executes an SDK recommendation of `approve`. This is also a team-authored, security-sensitive report, so it requires human ownership rather than an automated close.

## Change summary

Assisted permissions allowed an attempted repository-visibility change without confirmation and retried after the user skipped a later confirmation.

## Best solution

The upstream assisted-permission classifier should classify repository visibility and comparable irreversible remote mutations as requiring confirmation, with Agent Host retaining defense-in-depth for privilege-sensitive operations. A user denial or skip must be propagated so an equivalent operation is not silently retried through another API.

## Evidence

- **confirmed feature contract:** The referenced team test item https://github.com/microsoft/vscode/issues/326555 says Assisted permissions uses an LLM classifier to run calls judged safe and otherwise request user permission; changing repository visibility without confirmation violates that contract.
- **current source path:** On current main, src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts maps the session setting to the Copilot SDK's `assisted` permission mode in `_getSdkPermissionMode`, records `promptRequest.assistedApproval` from the SDK, and `_handlePermissionRequest` returns `approve-once` when that recommendation is `approve` and no sandbox bypass was requested.
- **remaining gap:** The same handler explicitly blocks an assisted recommendation from bypassing the sandbox, but no equivalent guard identifies irreversible GitHub repository-setting mutations; an SDK-approved network/API call can therefore follow the auto-approval path.
- **denial behavior:** Current `respondToPermissionRequest` returns `{ kind: 'reject', feedback: 'The user denied permission.' }` for a declined request, but this only rejects that request and does not establish that an equivalent operation retried through a different API must be blocked.
- **canonical search:** No older open issue with the same reporter-observable symptom was found. https://github.com/microsoft/vscode/issues/337540 is newer and concerns administrator-marked tool eligibility, not an assisted classifier approving a repository-visibility change or retrying after skip.
