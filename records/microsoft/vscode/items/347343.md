# Issue #347343 — ResourceMap copy constructor drops custom toKey comparator causing data inaccessibility and duplicate keys

[https://github.com/microsoft/vscode/issues/347343](https://github.com/microsoft/vscode/issues/347343)

## Summary

The constructor defect remains directly traceable on current main, although no affected user workflow has been established. Keep this open while the maintainer evaluates the impact clarification and the existing fix PR.

## Change summary

ResourceMap copies retain existing internal keys but discard the original key function, breaking custom-key lookups and replacement semantics.

## Best solution

Review the impact clarification and https://github.com/microsoft/vscode/pull/347344 together. ResourceMap copies should preserve the source identity semantics unless explicitly overridden, with existing entries accessible under the selected key function.
