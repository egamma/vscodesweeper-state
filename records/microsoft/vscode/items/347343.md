# Issue #347343 — ResourceMap copy constructor drops custom toKey comparator causing data inaccessibility and duplicate keys

[https://github.com/microsoft/vscode/issues/347343](https://github.com/microsoft/vscode/issues/347343)

## Summary

The comparator mismatch remains in current main and is directly traceable in source. Keep this open while the existing fixing PR is reviewed.

## Change summary

ResourceMap copies lose custom URI identity semantics and fail to re-key entries when an explicit replacement comparator is supplied.

## Evidence

- **Current source confirms the defect:** src/vs/base/common/map.ts:78-80 copies arg.map unchanged but assigns toKey ?? ResourceMap.defaultToKey. ResourceMap.set(), get(), has(), and delete() subsequently compute keys using this.toKey, so copied storage and lookup semantics can disagree. An explicitly different comparator also leaves the stored keys unchanged.
- **Reported trigger traced:** src/vs/base/common/resources.ts:162-166 lowercases paths for extUriIgnorePathCase, declared at line 372. Copying that ResourceMap switches lookups to URI.toString(); an uppercase-path lookup misses the copied lowercase key, and setting that variant inserts a second entry. This was confirmed by source inspection without executing code.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/347344 is open; its body explicitly references this issue with closing syntax and describes preserving custom toKey and re-keying copied entries. An open fixing PR is not evidence that the fix has landed.
