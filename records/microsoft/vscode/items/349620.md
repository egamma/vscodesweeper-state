# Issue #349620 — Ctrl+N IS THE SHORTCUT TO UNDO AGENT EDITS IN LOCAL HARNESS

[https://github.com/microsoft/vscode/issues/349620](https://github.com/microsoft/vscode/issues/349620)

## Summary

The reported shortcut collision remains in current source: Ctrl+N intentionally invokes Undo this Change inside an agent-edited hunk, overriding New File. Keep this open for a keyboard-interaction decision rather than dismissing the unexpected edit rejection as designed.

## Change summary

Preserve the normal new-file shortcut while reviewing agent edits instead of using it to reject changes.

## Best solution

Choose a non-conflicting default shortcut for rejecting agent changes while preserving ordinary new-file and new-window commands. Keep explicit hunk rejection and configured next-change navigation available.

## Evidence

- **Direct shortcut collision:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts registers chatEditor.action.undoHunk in AcceptRejectHunkAction with CtrlCmd+N, weight WorkbenchContrib+1, and a cursor-in-change-range focus condition. Its handler calls rejectNearestChange.
- **Ordinary command:** src/vs/workbench/contrib/files/browser/fileCommands.ts registers New Untitled Text File with CtrlCmd+N at WorkbenchContrib weight. The chat hunk action therefore takes precedence in its matching context. New Window normally uses Ctrl+Shift+N, which the file-wide chat rejection action also overrides.
- **Cross-file behavior:** AcceptRejectHunkAction.runChatEditingCommand calls openNextOrPreviousChange after the file has no remaining changes. That helper opens another modified entry and reveals its change. chat.editing.revealNextChangeOnResolve defaults to true in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts, explaining why repeated rejection can continue into other files.
- **Existing capability boundary:** Removing the chatEditor.action.undoHunk keyboard binding is a workaround. Setting chat.editing.revealNextChangeOnResolve to false stops automatic cross-file navigation but does not resolve the Ctrl+N collision; neither provides a safer default.
- **Report and ownership:** https://github.com/microsoft/vscode/issues/349620 describes pressing Ctrl+N during local agent edit review on Windows in Code 1.146.0. The supplied attachment lists external agents, but the built-in action itself explains the symptom; extension ownership is not grounds for closing.
