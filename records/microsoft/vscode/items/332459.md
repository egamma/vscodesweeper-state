# Issue #332459 — File tree shifts to the right after invoking rename

[https://github.com/microsoft/vscode/issues/332459](https://github.com/microsoft/vscode/issues/332459)

## Summary

Current source confirms the Explorer deliberately disables horizontal scrolling when inline editing begins, changing the tree's scroll dimensions and causing the reported layout shift. This remains an open, bounded file-explorer/tree-widget bug.

## Change summary

Invoking inline rename in a horizontally scrollable Explorer changes the tree's horizontal layout instead of preserving its visual position.

## Best solution

Keep the Explorer tree at the same horizontal viewport position while entering and leaving inline rename, without regressing long-name editing or ordinary horizontal scrolling.
