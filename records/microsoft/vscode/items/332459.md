# Issue #332459 — File tree shifts to the right after invoking rename

[https://github.com/microsoft/vscode/issues/332459](https://github.com/microsoft/vscode/issues/332459)

## Summary

Traced a plausible root cause in the explorer's rename flow: `ExplorerView.setEditable` temporarily disables `horizontalScrolling` on the tree before calling `reveal(stat)`, which drops the tree's horizontal scroll offset back toward the start whenever a scrollbar is present — matching the reported rightward jump. Routing to the files/explorer area for a fix; no maintainer or fix commit exists yet.

## Change summary

Invoking rename in the file explorer while horizontally scrolled resets/shifts the tree's horizontal scroll position.

## Best solution

In `ExplorerView.setEditable` (src/vs/workbench/contrib/files/browser/views/explorerView.ts), capture `this.tree.scrollLeft` before toggling `horizontalScrolling` off and restore it after `reveal()`/on exit from editing, so entering/leaving rename mode doesn't perturb the user's horizontal scroll position.
