# Issue #291796 — Changing Close File Behaviour - UX Issue

[https://github.com/microsoft/vscode/issues/291796](https://github.com/microsoft/vscode/issues/291796)

## Summary

This is a valid, currently unsupported Explorer UX request: closing the active editor activates another editor and the Explorer auto-reveals it, potentially moving far from the user's working location. It should be routed to the file Explorer area for a product decision rather than closed.

## Change summary

Keep the Explorer's current position when closing a file while retaining automatic reveal when the user explicitly opens or selects another editor.

## Best solution

Distinguish an editor activated as the fallback after a close from one explicitly selected or opened, preserving Explorer position for the former while retaining normal auto-reveal for the latter. The area owner should decide whether this becomes the default behavior or an additional `explorer.autoReveal` mode.
