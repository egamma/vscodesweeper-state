# Issue #2739 — activationEvents.workspaceContains doesn't fire for directory

[https://github.com/microsoft/vscode/issues/2739](https://github.com/microsoft/vscode/issues/2739)

## Summary

Exact directory paths now activate extensions on the native existence-check path, but directory glob matching remains unsupported by the file-search path. Keep this accepted Backlog request open: existing startup activation is a workaround, and no verified open canonical covers the full remaining scope.

## Change summary

Allow extensions to activate selectively when a workspace contains a matching directory, with an additional request for matching the opened workspace's full path.

## Best solution

Define directory-aware workspace activation consistently across native, remote, and web extension hosts without sacrificing bounded startup searches. Decide separately whether matching the workspace's own name or ancestor path belongs in workspaceContains or a distinct activation event.

- **Existing exact-directory capability:** src/vs/workbench/services/extensions/common/workspaceContains.ts routes patterns without '*' or '?' to _activateIfFileName, which joins the pattern to each workspace folder and calls host.exists without checking file type. src/vs/workbench/api/node/extensionHostProcess.ts supplies Promises.exists; src/vs/base/node/pfs.ts implements that using fs.promises.access.
