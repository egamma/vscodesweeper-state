# Issue #318126 — Copilot CLI session errors out when opened via the Copilot Chat extension

[https://github.com/microsoft/vscode/issues/318126](https://github.com/microsoft/vscode/issues/318126)

## Summary

Team-authored bug report about a session schema validation failure when opening Copilot CLI sessions in the Chat extension; the root cause (null reasoningEffort in session JSON) appears to live in the Copilot CLI SDK's session writer. No fix referencing this issue found on main.

## Change summary

Opening a Copilot CLI session in the VS Code Chat extension errors with 'Session file is corrupted' because the session file contains null for `data.reasoningEffort` where the schema expects a string.

## Best solution

Fix the session schema or session writer to make `reasoningEffort` nullable/optional. The validation likely lives in the Copilot CLI SDK session file format — either the schema in the SDK should accept `null` (since sessions may not have a reasoning effort set), or the CLI should write an empty string or omit the field when no reasoning effort is specified. The graceful-corruption handler from commit 382e40aeea8 mitigates the crash but doesn't fix the underlying parsing failure.
