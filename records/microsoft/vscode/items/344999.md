# Issue #344999 — Agents window: canvases don't come back after the agent host process restarts

[https://github.com/microsoft/vscode/issues/344999](https://github.com/microsoft/vscode/issues/344999)

## Summary

Keep open as a recovery feature request: cold-resume suppression is intentional, but the existing UI does not recover arbitrary agent-created canvas instances. The sidebar-pinning PR explicitly leaves process-restart recovery as follow-up work.

## Change summary

Let users explicitly recover previously retained canvases after an agent-host process restart without asking the agent to reopen them.

## Best solution

Provide explicit recovery using the retained canvas identity while preserving the rule that resuming a chat does not automatically display old canvases. Settle recovery scope and missing-instance behavior before implementation, coordinating with the sidebar-pinning work.

- **Validation:** After the recovery surface is agreed, open an agent-created canvas with a non-default instance ID, retain it, quit and relaunch VS Code, and invoke recovery without sending a message. Verify the intended instance becomes available, ordinary chat resume does not display unrequested canvases, and unavailable instances follow the agreed behavior. Add focused automated coverage for identity routing and cold-start event ordering.
- **Behavior:**

  > Users should be able to explicitly recover a deliberately retained canvas after an agent-host process restart without asking the agent to reopen it. Recovery must preserve the owning chat and instance identity. Ordinary chat resume must continue to avoid automatically displaying historical canvases. Acceptance must cover agent-selected instance IDs, cold-start timing, and the agreed outcome when the runtime no longer has the instance.
- **Trace:**

  > Current CopilotAgentSession resume records unprojected runtime instances in _ignoredRestoredCanvasInstanceIds; openCanvas can explicitly recover a matching ID once projection is live. SessionCanvasRegistryService.openCanvas currently opens definitions under a generated extension/type instance ID, which does not recover arbitrary agent-created instances. The provider specification deliberately makes subscriptions passive, so retaining a subscription alone cannot recover a cold canvas. https://github.com/microsoft/vscode/issues/343711 fixed explicit-open suppression, not recovery discovery. Sidebar pins are being introduced in https://github.com/microsoft/vscode/pull/345150, whose description explicitly excludes process-restart recovery; coordinate with that work rather than duplicating it. Preserve passive subscriptions and the no-automatic-display contract; whether selection should recover only retained pins or expose other historical instances remains a product choice.
- **Open decisions:**
  - Should recovery initially cover only explicitly retained sidebar canvases, or also expose historical instances in the chat canvas menu?
  - When the runtime no longer has a retained instance, should recovery create a fresh instance under the same ID or leave it unavailable?
