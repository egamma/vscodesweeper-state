# Issue #335986 — VS Code's terminal audio/accessibility signals are intrusive, confusing, and absurdly difficult to disable

[https://github.com/microsoft/vscode/issues/335986](https://github.com/microsoft/vscode/issues/335986)

## Summary

Plausible but unconfirmed: `accessibility.signals.terminalCommandSucceeded`/`terminalCommandFailed` default to `auto`, which should only play sound when a screen reader is detected (`AccessibilitySignal.checkEnabledState` in accessibilitySignalService.ts, and `AccessibilityService.isScreenReaderOptimized()` in accessibilityService.ts) — for these to fire unprompted, either the user's `editor.accessibilitySupport` is set to `on`/`auto`-and-detected, or there's a real detection bug; we need the reporter's setting values to tell which.

## Change summary

Terminal command success/failure audio signals play by default with no screen reader active, and the controls to disable terminal sounds are scattered and hard to discover.

## Best solution

Ask the reporter to share the output of `editor.accessibilitySupport` and whether any OS-level accessibility feature (VoiceOver, Reduce Motion, Increase Contrast) is enabled — if `accessibilitySupport` is `on`/detected-as-enabled, this is as-designed `auto` behavior and the fix is discoverability (a consolidated 'terminal sounds' settings section or a single command), which belongs in src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts and the terminal accessibility contribution; if the reporter confirms no accessibility mode is active, this is a real detection bug worth reopening as such.
