# Issue #335986 — VS Code's terminal audio/accessibility signals are intrusive, confusing, and absurdly difficult to disable

[https://github.com/microsoft/vscode/issues/335986](https://github.com/microsoft/vscode/issues/335986)

## Summary

Legitimate discoverability/UX complaint about scattered terminal audio-signal settings; current default for `accessibility.signals.terminalCommandSucceeded`/`terminalCommandFailed` is `auto` (sound.enabled.auto in accessibilityConfiguration.ts, line 94-104), meaning it should only fire when a screen reader is detected as active — the reporter likely hit a screen-reader-detection edge case rather than an intentionally-always-on default, but neither can be confirmed without running the app, so this stays open rather than closing as as-designed or not-reproducible.

## Change summary

Terminal command success/failure accessibility sounds are hard to discover and disable, scattered across multiple unrelated settings (terminal bell, shell integration, accessibility signals, global signal volume).

## Best solution

Consolidate terminal audio-feedback settings under a single discoverable surface (e.g. a `terminal.integrated` grouping or improved settings search tags) and confirm whether `accessibility.signals.terminalCommandSucceeded`/`Failed` with value `auto` is unexpectedly firing without an active screen reader (a detection bug in `isScreenReaderOptimized()` in src/vs/platform/accessibility/browser/accessibilityService.ts) versus working as designed.
