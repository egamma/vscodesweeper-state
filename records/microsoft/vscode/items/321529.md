## Summary

The bug should remain open: multiple users confirmed blank Mermaid output, including a confirmation after the linked resize fix merged. Current main still renders contributed Mermaid code blocks while responses stream, so the remaining lifecycle race needs diagnosis rather than another completed-fix close.

## Change summary

Mermaid diagrams in Copilot Chat can remain blank during or after response streaming, and opening the blank diagram in an editor may not work.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatMarkdownContentPart.test.ts`, `extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts`

- **Behavior:**

  > A valid Mermaid block returned in Copilot Chat must render visibly when the response completes in both the Chat panel and an editor-tab chat. Streaming may show a pending state, but completion must not leave a blank diagram or require focus changes, reloads, or restarts. Opening the completed diagram in an editor must display the same source successfully, and ordinary code blocks and Markdown preview rendering must remain unchanged.
- **Trace:**

  > Mermaid chat output is created by MermaidChatOutputRenderer in extensions/mermaid-markdown-features/src/chatOutputRenderer.ts and laid out by PanZoomHandler in extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts. Commit 11bffd4d900d73ae7dcc1daf100f2527c66b2716 added container ResizeObserver handling, but a user reported the same symptom after that merge. ChatMarkdownContentPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts currently creates contributed output blocks during incomplete responses and rerenders them as Markdown grows. The closed https://github.com/microsoft/vscode/pull/330970 shows that response-completion lifecycle handling is a concrete lead, but it did not land and the review record does not establish whether webview recreation or fit-state calculation is the remaining cause. Keep normal code-block streaming, completed/restored response rendering, Markdown preview behavior, and explicit single-diagram editor opening outside the regression boundary.

## Evidence

- **confirmed reports:** The original reporter and another user reproduced the blank chat diagram on Windows; the reporter later described repeated redraws followed by a blank completed diagram in 1.133.0, and another user reported the same symptom on 2026-09-03.
- **partial merged fix:** https://github.com/microsoft/vscode/pull/330930 merged commit 11bffd4d900d73ae7dcc1daf100f2527c66b2716 and replaced window-resize handling with a container ResizeObserver in extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts. A later confirmation means that concrete positioning fix is insufficient evidence to close this issue.

- **unmerged lifecycle lead:** https://github.com/microsoft/vscode/pull/330970 proposed deferring contributed chat output webviews until response completion and added focused tests, but it was closed without merging. This identifies a plausible separate lifecycle cause without proving the correct fix.
