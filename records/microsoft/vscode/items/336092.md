# Issue #336092 — Agent Debug Logs Cache Explorer gets confused between multiple concurrent AI conversations/requests

[https://github.com/microsoft/vscode/issues/336092](https://github.com/microsoft/vscode/issues/336092)

## Summary

Traced the root cause on main: the Cache Explorer groups/filters turns by `requestName` (`agentKey()` in chatDebugCacheExplorerView.ts), but `extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts:829` sends a hardcoded `debugName: 'copilotLanguageModelWrapper'` for every request made through the `vscode.lm` wrapper API — which is exactly the path used by subagents and tool-summarization calls. All of those distinct concurrent conversations collapse into one indistinguishable bucket, so the explorer's sequential A→B diff compares turns from unrelated conversations and reports spurious cache-miss/history-rewritten noise, matching the report.

## Change summary

The Agent Debug Logs Cache Explorer conflates separate concurrent conversations (main agent, subagents, tool-summarization) because they all surface under the same generic label, producing false cache-break diagnoses.

## Best solution

Give LM-API-routed requests (in languageModelAccess.ts's CopilotLanguageModelWrapper) a debugName/requestName that reflects the actual calling context (e.g. subagent name, or a summarization/tool-call purpose tag, or the passed conversationId) instead of the fixed literal 'copilotLanguageModelWrapper', so chatDebugCacheExplorerView's agent grouping and sequential diffing can separate these conversations correctly.
