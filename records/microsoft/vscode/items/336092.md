# Issue #336092 — Agent Debug Logs Cache Explorer gets confused between multiple concurrent AI conversations/requests

[https://github.com/microsoft/vscode/issues/336092](https://github.com/microsoft/vscode/issues/336092)

## Summary

Traced this to a real defect: `CopilotLanguageModelWrapper._provideLanguageModelResponse` hardcodes `debugName: 'copilotLanguageModelWrapper'` for every request that flows through the public Language Model API wrapper, so the Cache Explorer's per-agent grouping (which keys off this exact field) can't tell the main conversation, subagents, and utility calls like tool summarization apart — exactly the symptom reported. This is a diagnostic-tooling bug, niche in audience (only affects users with Agent Debug Logs enabled), so it's routed to the chat area rather than closed.

## Change summary

Cache Explorer's per-conversation grouping conflates the main agent conversation, subagent invocations, and utility requests (e.g. tool summarization) because they all share the debug label "copilotLanguageModelWrapper", producing false cache-miss/history-rewrite findings.

## Best solution

In extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts (around the `makeChatRequest2` call at line 828-836), stop hardcoding `debugName: 'copilotLanguageModelWrapper'` and instead derive/thread a distinguishing label (e.g. from the restored OTel trace context tied to the originating invoke_agent span, or a new purpose field passed alongside `_conversationId`/`_otelTraceContext` in `ExtensionLanguageModelRequestOptions`) so the Cache Explorer's `agentKey`/rail grouping in chatDebugCacheExplorerView.ts can separate main/subagent/utility requests instead of lumping them under one label.
