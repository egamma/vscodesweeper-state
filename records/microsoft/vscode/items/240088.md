# Issue #240088 — Terminal suggest: Properly support paths with spaces in them

[https://github.com/microsoft/vscode/issues/240088](https://github.com/microsoft/vscode/issues/240088)

## Summary

Keep open: current source still provides only partial support for paths containing spaces, and this issue already owns two confirmed duplicate reports. The remaining work includes recognizing unescaped spaces and producing shell-appropriate insertion text.

## Change summary

Support terminal path suggestions containing spaces across tilde, relative, and absolute paths, including escaped and unescaped input.

## Best solution

Make resource lookup, suggestion filtering, replacement ranges, and accepted text consistently handle space-containing paths across supported shells. Settle how unescaped spaces are distinguished from argument separators before implementing the broader behavior.

## Evidence

- **Remaining source gap:** In src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalCompletionService.ts, resolveResources splits cursorPrefix on spaces not immediately preceded by a backslash. For `cd ~/3D Objects`, lastWord therefore becomes `Objects`, losing the tilde path and yielding a replacement range for only that final fragment. The Windows path branch explicitly notes that escaped-path handling only partially works.
- **Partial existing capability:** resolveResources already expands tilde paths and removes backslash-space escapes during resource lookup, covering some escaped forms. However, src/vs/workbench/contrib/terminalContrib/suggest/browser/terminalSuggestAddon.ts hides suggestions after a typed space and its acceptance path replaces spaces with backslash-space for folder/file-override labels without checking shell type.
