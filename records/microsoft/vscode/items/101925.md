# Issue #101925 — Zooming with Ctrl+MouseWheel doesn't update configuration

[https://github.com/microsoft/vscode/issues/101925](https://github.com/microsoft/vscode/issues/101925)

## Summary

Valid feature request: the editor font zoom level (set via Ctrl+MouseWheel) is internal-only (`EditorZoom` in `editorZoom.ts`) and not exposed to extensions via configuration or API. The gap still exists on current main — no extension API surfaces `onDidChangeZoomLevel` or the zoom level value. Keeping open as a niche but real extension-API gap.

## Change summary

Extensions cannot observe or read the editor font zoom level changed by Ctrl+MouseWheel because it is not exposed as a configuration setting or extension API.

## Best solution

Expose the editor font zoom level to extensions — either as a read-only configuration value (e.g. `editor.fontZoomLevel`) that stays in sync with `EditorZoom`, or as a proposed extension API event. The internal infrastructure (`EditorZoom.onDidChangeZoomLevel` in `src/vs/editor/common/config/editorZoom.ts`) already exists; the gap is purely at the API boundary. This is a legitimate extension-API hole, not an extension-candidate — the missing piece is core plumbing.

## Evidence

- **internal zoom infrastructure:** EditorZoom in src/vs/editor/common/config/editorZoom.ts provides getZoomLevel(), setZoomLevel(), and onDidChangeZoomLevel — all internal, not exposed to extensions.
- **mouse wheel zoom handler:** src/vs/editor/browser/controller/mouseHandler.ts lines 140-166 call EditorZoom.setZoomLevel() on Ctrl+MouseWheel, updating the in-memory zoom level without writing to configuration.
- **no extension API surface:** Searched src/vscode-dts/ for fontZoom, editorZoom, ZoomLevel — no matches. The zoom level is not accessible to extensions.
- **font zoom commands exist:** src/vs/editor/contrib/fontZoom/browser/fontZoom.ts registers editor.action.fontZoomIn/Out/Reset, which also use the same internal EditorZoom — but these likewise don't update configuration.
