# Issue #332507 — Quick pick filter freezes on queries with runs of * wildcards

[https://github.com/microsoft/vscode/issues/332507](https://github.com/microsoft/vscode/issues/332507)

## Summary

Confirmed real freeze bug: I reproduced the reported hang independently by running the exact `convertSimple2RegExpPattern`/`matchesFuzzy` logic from current main (8 stars against a 28-char non-matching string took ~730ms, matching the reporter's measurements) — but an open PR already proposes the exact fix, so this should stay open until that PR lands rather than being auto-fixed here.

## Change summary

Quick pick fuzzy filtering (`matchesFuzzy` in src/vs/base/common/filters.ts) builds a regex via `convertSimple2RegExpPattern`, which turns each `*` into an unbounded `.*`; a run of adjacent `*` characters in the query produces catastrophic backtracking and freezes the renderer while typing.

## Best solution

Land https://github.com/microsoft/vscode/pull/332510, which collapses runs of `*` to a single `*` in `convertSimple2RegExpPattern` (semantically identical, since `.*.*` accepts exactly what `.*` does) — this removes the adjacent-wildcard hang. The reporter's secondary note (separated wildcards like `a*b*c*d*e*f*g*h` can still backtrack, and there's no length cap unlike `fuzzyScore`'s `_maxLen = 128`) is a distinct follow-up worth tracking separately once this lands.
