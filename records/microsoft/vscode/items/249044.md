The authority is https://login.microsoftonline.com/organizations.
- **Account and maintainer investigation:** The reporter identifies an organizational account at https://github.com/microsoft/vscode/issues/249044#issuecomment-2920185992. At https://github.com/microsoft/vscode/issues/249044#issuecomment-2920196595, the maintainer says they contacted internal colleagues and recommends the reporter's Microsoft support contact; there is no subsequent resolution.
- **Current source boundary:** extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts:getNativeBrokerOptions constructs NativeBrokerPlugin from @azure/msal-node-extensions, and acquireTokenInteractive delegates to MSAL's PublicClientApplication. extensions/microsoft-authentication/src/node/flows.ts:DefaultLoopbackFlow supplies the interactive request. This supports the existing upstream classification, not attribution to the installed Azure App Service extension.
- **Existing workaround is not a native-broker fix:** extensions/microsoft-authentication/package.json registers microsoft-authentication.implementation with values msal and msal-no-broker. getNativeBrokerOptions returns undefined for msal-no-broker, allowing the browser flow rather than native brokering. No account-specific execution or concrete fixing commit establishes that the reported native HTTP 404 is resolved.
- **Older related report, not a verified canonical:** https://github.com/microsoft/vscode/issues/240304 is open and predates this report. Its comment https://github.com/microsoft/vscode/issues/240304#issuecomment-2740748287 describes the same HTTP 404 symptom during Microsoft sign-in, but specifically links it to an active proxy and confirms a loopback-exemption workaround. This reporter has not established that network condition or confirmed that workaround, so the same underlying defect is not verified for a duplicate close on this re-reviewed item.
- **Other canonical lead ruled out:** https://github.com/microsoft/vscode/issues/224574 is open and older, but concerns a browser that never opens on NixOS Plasma Wayland. That differs from this Windows organizational-account failure inside an already-open native authentication window.
