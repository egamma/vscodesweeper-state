## Change summary

Running xdg-open on a directory from VS Code's integrated terminal should open the system file manager rather than another VS Code window.

- **Validation:** On Ubuntu 24 with a current snap installation, run xdg-open /path/to/an/existing/folder from both the system terminal and VS Code's integrated terminal and verify both open the configured file manager. Any eventual fix must preserve explicit user MIME defaults and terminal environment overrides.
- **Behavior:**

  > After upgrading to Ubuntu 24, the reporter's integrated terminal opens a directory in another VS Code window when running xdg-open /path/to/folder, while the same command in the system terminal opens the file manager. A second snap user confirmed the symptom; the Debian comparison instead selected VLC. The expected result is consistent use of the configured directory handler from both terminals. Acceptance requires a current Ubuntu comparison covering snap and Debian without rewriting the user's application associations.
- **Trace:**

  > resources/linux/snap/electron-launch saves original XDG directory variables and prepends snap-specific data/configuration paths. createTerminalEnvironment in src/vs/workbench/contrib/terminal/common/terminalEnvironment.ts copies the supplied base environment and invokes sanitizeProcessEnvironment in src/vs/base/common/processes.ts, whose filters remove SNAP-prefixed variables but do not generally remove XDG directory variables. This establishes an environment-resolution lead, not a conclusive failing path; the next diagnostic boundary is the actual xdg-open executable and MIME-resolution output in each terminal. resources/linux/code.desktop no longer advertises inode/directory following https://github.com/microsoft/vscode/commit/f1c007109d0a1f51516f2c054dd7a09d9aad8815, which predates this report and must not be treated as its fix. Preserve user-selected handlers, explicit terminal environment overrides, and unrelated snap runtime requirements. https://github.com/microsoft/vscode/issues/233399 is related browser-handler evidence, not a verified duplicate.
