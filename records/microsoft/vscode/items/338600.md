# Issue #338600 — Session stuck in progress after background subagents fail with "GitHub token provider registration … is unavailable"

[https://github.com/microsoft/vscode/issues/338600](https://github.com/microsoft/vscode/issues/338600)

## Summary

Team-authored bug report describing a real race in the Copilot agent-host provider between GitHub token refresh and running background subagents; source strongly suggests the CopilotClient restart's busy check doesn't account for background subagent activity, but the exact fix needs design input, so this stays open rather than closed.

## Change summary

A background Copilot CLI subagent that is still running when the GitHub token is refreshed gets torn down mid-flight ('token provider registration ... is unavailable'), and its failure is never surfaced to the parent, leaving the session stuck 'in progress' forever.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotAgent.ts, make CopilotClient restart-deferral (_requestClientRestart/_applyPendingClientRestart, gated by _chatsWithActiveTurn) also account for in-flight background-subagent activity on a chat, and ensure a subagent failure caused by a restart is reported to the parent chat/turn so the session can leave the in-progress state instead of hanging silently.

## Evidence

- **restart deferral only checks foreground turns:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:1287-1294 and :1428-1429 defer a CopilotClient restart only while `_chatsWithActiveTurn()` (session.hasActiveTurn) is > 0; if a background subagent keeps running on the SDK session after the parent's visible turn is reported ended, the restart proceeds and `_applyPendingClientRestart` (line 1301-1318) calls `_chatEntriesBySdkId.clearAndDisposeAll()` and `_stopClient()`, tearing down the live session/token-provider registration the subagent is still using.
- **token update triggers the restart:** `_applyGitHubToken` (copilotAgent.ts:1986-2057) calls `_requestClientRestart('GitHub credential mode changed'/'GitHub credential update failed')` whenever the token provider mode changes or a per-session credential update fails/is rejected — matching the reporter's trigger of another window signing in and refreshing the shared token.
- **no parent notification path found:** AGENTS.md (agent host architecture doc) documents subagent spawn/end wiring (onDidSpawnChat/_onChatEnded) but no mechanism was found in copilotAgent.ts that reports a torn-down/failed subagent chat back to the parent turn or forces the session out of the in-progress state; this matches the reporter's observation that 'the parent agent was never told and the session never went idle'.
