# Issue #86761 — Allow to configure symbol visibility in pickers that may show symbols

[https://github.com/microsoft/vscode/issues/86761](https://github.com/microsoft/vscode/issues/86761)

## Summary

Keep this accepted feature request open: current symbol pickers still lack configurable per-kind visibility, and @: groups symbols without hiding unwanted kinds. The request has 54 upvotes; a maintainer should settle the configuration contract across the three picker surfaces.

## Change summary

Allow users to hide selected symbol kinds, such as variables, in editor-symbol, workspace-symbol, and combined file-and-symbol pickers.

## Best solution

Provide consistent per-kind visibility controls for symbol pickers while allowing editor and workspace navigation to have different preferences. Preserve existing defaults and keep Outline visibility independent unless a maintainer explicitly chooses otherwise.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts`, `src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoSymbolQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/symbolsQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts`, `src/vs/workbench/contrib/search/browser/search.contribution.ts`
- **Validation:** After choosing the contract, use a document-symbol provider and workspace-symbol provider that return a class, method, function, and variable. Verify that disabling variables removes only variables from each configured picker, including @ and @:, #, and combined Quick Open with search.quickOpen.includeSymbols enabled. Verify scope independence, unchanged defaults, unchanged Outline behavior, and successful navigation to retained symbols.
- **Behavior:**

  > Users cannot currently hide unwanted symbol kinds from Go to Symbol in Editor, despite having analogous Outline controls. The finished feature should let users exclude variables while retaining methods and other chosen kinds in the agreed picker scopes. Grouping with @: must not be mistaken for exclusion. Acceptance should cover editor, workspace, and combined results, unchanged defaults, and navigation to retained entries.
- **Trace:**

  > AbstractGotoSymbolQuickAccessProvider.doGetSymbolPicks in src/vs/editor/contrib/quickAccess/browser/gotoSymbolQuickAccess.ts builds document-symbol entries, applies text matching, and optionally groups them by kind; no visibility configuration enters that path. The workbench GotoSymbolQuickAccessProvider delegates text-editor picks to it. SymbolsQuickAccessProvider.getSymbolPicks in src/vs/workbench/contrib/search/browser/symbolsQuickAccess.ts supports only a coarse internal skipLocal option, which AnythingQuickAccessProvider hard-codes for combined workspace results. Outline's DocumentSymbolFilter supplies related prior art but belongs to separate outline/breadcrumbs settings. The historical workspaceSymbolsFilter proposal was withdrawn after the discussion broadened to editor-scoped and per-kind controls. Keep language-provider output, symbol resolution, and non-text-editor/chat navigation outside the initial boundary. https://github.com/microsoft/vscode/issues/52773 was consolidated into this issue; the uncertainty is the public configuration and interaction contract, not whether the gap remains.
- **Open decisions:**
  - Should per-kind visibility be shared across all three picker surfaces, or support independent editor, workspace, and combined-picker preferences?
  - Should the initial feature provide persistent visibility settings only, or also per-search kind filtering; if both are supported, can a per-search filter reveal a persistently hidden kind?
