# Issue #338731 — Show file paths in customization page list items

[https://github.com/microsoft/vscode/issues/338731](https://github.com/microsoft/vscode/issues/338731)

## Summary

Fresh, reasonable UX request with a real gap confirmed in source: list items only surface the full path via hover when no description is set, and the MCP/detail views show only a bare filename with no hover at all. No maintainer input yet on exact placement, so this stays open for design input rather than being implemented blind.

## Change summary

Show (sanitized) source file paths on customization list items, keep the full path in item hovers, and surface it in the details view too.

## Best solution

Design the path display consistently across aiCustomizationListWidget.ts (list secondary text/hover) and the detail views (embeddedMcpServerDetail.ts, embeddedAgentPluginDetail.ts), reusing labelService.getUriLabel's existing tildify/relative-path behavior rather than inventing new sanitization.

## Vision fit

- **Fit:** unclear
- **Reason:** Path visibility aids diagnosing multi-source customization setups (Workbench & core UX theme), but always-on path text in list rows is in tension with the 'simple, uniform UI' and 'lean default experience' guardrails, so the right balance needs a maintainer's call.
- **Evidence:** Durable theme: Workbench & core UX — 'settings fidelity'; Guardrail: 'Simple, uniform UI and UI interactions' and 'Lean default experience'.
