# Issue #312980 — Support marketplace specification in extensions.json

[https://github.com/microsoft/vscode/issues/312980](https://github.com/microsoft/vscode/issues/312980)

## Summary

A real security-sensitive gap remains: workspace recommendations identify extensions only by `publisher.name`, while installation resolves that identifier through the product's configured gallery. The issue must remain open for human security and format design review.

## Change summary

Allow an `extensions.json` recommendation to bind an extension identity to its intended marketplace or publisher key.

## Best solution

Define a backward-compatible source-bound extension recommendation format and ensure installation warns, rejects, or requires explicit confirmation when the active gallery cannot prove the requested identity. The design should cover VS Code-compatible products using different galleries without weakening existing recommendation workflows.

## Evidence

- **current schema:** src/vs/workbench/contrib/extensions/common/extensionsFileTemplate.ts defines `recommendations` as strings matching only `${publisher}.${name}` and provides no marketplace, UUID, or public-key field.
- **configuration model:** src/vs/workbench/services/extensionRecommendations/common/workspaceExtensionsConfig.ts models recommendations as `string[]` and normalizes them solely by lowercasing the extension ID.
- **installation path:** InstallRecommendedExtensionAction in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts resolves a recommendation with `getExtensions([{ id: this.extensionId }], ...)`; ExtensionGalleryManifestService in src/vs/platform/extensionManagement/common/extensionGalleryManifestService.ts obtains the gallery from the product-wide `extensionsGallery.serviceUrl`, so the recommendation itself does not identify its intended source.
- **partial ecosystem mitigation:** https://github.com/EclipseFdn/open-vsx.org/issues/9961 documents that Open VSX checks VS Code Marketplace publisher ownership when granting a namespace. That reduces namespace-claiming risk but does not cryptographically or structurally bind an `extensions.json` recommendation to a particular gallery.
- **canonical search:** https://github.com/microsoft/vscode/issues/40239 concerns enabling or disabling extensions from workspace configuration, not cross-marketplace identity binding, and therefore does not own this request.
