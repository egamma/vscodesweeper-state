# Issue #283206 — Auto-include Interactive Window cell output in context

[https://github.com/microsoft/vscode/issues/283206](https://github.com/microsoft/vscode/issues/283206)

## Summary

Keep open: current implicit-context handling explicitly excludes Interactive Window history, and the existing output attachment action does not provide automatic inclusion when an output is clicked. The related issues inspected cover different behaviors, not a verified duplicate of this request.

## Change summary

Automatically include the selected Interactive Window cell output in Copilot Chat context when the user clicks that output.

## Best solution

Evaluate output-selection context in the core chat/notebook integration, accounting for Interactive Window API limitations and preserving ordinary output interaction. Existing explicit attachment support is a useful foundation, but does not satisfy the requested automatic workflow.

## Evidence

- **Current capability gap:** In src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts, ChatImplicitContextContribution.updateImplicitContext explicitly sets newValue to undefined when notebookEditor.isReplHistory is true, with the explanation that chat APIs do not work well with Interactive Windows. Ordinary notebook handling selects a cell URI or source range, not the clicked output.
- **Existing settings do not cover the request:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.implicitContext.enabled, chat.implicitContext.suggestedContext, and chat.implicitContext.includeActiveEditor. These control active-editor context inclusion or suggestion; they do not establish clicked-output inclusion or bypass the Interactive Window exclusion.
- **Explicit attachment remains manual:** src/vs/workbench/contrib/notebook/browser/controller/chat/notebook.chat.contribution.ts registers notebook.cellOutput.addToChat, which resolves an output and explicitly calls widget.attachmentModel.addContext. src/vs/workbench/contrib/notebook/browser/contrib/chat/notebookChatUtils.ts constructs notebookOutput entries for supported text and image MIME types. This is an explicit command, not automatic attachment on output selection.
- **Related limitation, not a canonical:** https://github.com/microsoft/vscode/issues/282937 is closed and concerns chat failing after an attached Interactive Window is closed, rather than automatic inclusion of selected output. A maintainer explains the Interactive Window extension-API limitation at https://github.com/microsoft/vscode/issues/282937#issuecomment-3644915116; that does not establish a decision against this distinct output-context request.
