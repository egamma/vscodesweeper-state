# Issue #110663 — Missing language IDs for Emmet supported languages

[https://github.com/microsoft/vscode/issues/110663](https://github.com/microsoft/vscode/issues/110663)

## Summary

Emmet still supports Haml, Slim, and Stylus without VS Code bundling their language registrations, so the reported distinction remains. Keep this accepted Backlog item open: extension-provided IDs address configuration, but neither settle the request for built-in registrations nor resolve the documentation ambiguity.

## Change summary

Make the language IDs for Emmet-supported Haml, Slim, and Stylus available or clearly explain their dependency on language extensions.

## Best solution

Clarify the Emmet documentation to distinguish supported expansion syntaxes from bundled language modes, including how to exclude extension-provided IDs. Have the Emmet owner explicitly decide whether built-in registrations are also warranted rather than treating working extension support as resolving that request.

## Evidence

- **Current source boundary:** extensions/emmet/src/util.ts defines LANGUAGE_MODES entries for haml, slim, and stylus. extensions/emmet/src/emmetCommon.ts:213–223 registers completion providers for those language IDs; provider registration does not itself contribute language modes.
- **Missing built-in registrations:** Searching extensions/**/package.json for language contributions with IDs haml, slim, or stylus found none. Current source therefore still distinguishes Emmet syntax support from out-of-the-box language registration.
- **Existing configuration capability:** extensions/emmet/package.json:79–86 declares emmet.excludeLanguages as an array of strings, and extensions/emmet/src/defaultCompletionProvider.ts:43–47 checks it against document.languageId. Once a language extension supplies the matching ID, exclusion does not require inventing a new ID; this does not provide built-in file recognition.
- **Discussion evidence:** The 2021-02-12 comment on https://github.com/microsoft/vscode/issues/110663 reports successful Emmet expansion after installing vayan.haml, sysoev.language-stylus, and sianglim.slim. The commenter explicitly leaves the out-of-box support decision to the maintainer; this is not a maintainer rejection or a fixing reference.
- **Documentation remains ambiguous:** https://code.visualstudio.com/docs/languages/emmet still lists haml, slim, and stylus as enabled by default without explaining the language-extension prerequisite in that section. https://code.visualstudio.com/docs/languages/identifiers explains that extensions contribute language IDs, but its known-identifiers table omits all three.
- **Canonical search:** Read-only GitHub searches for Emmet language IDs, language support, and Haml/Slim/Stylus found no verified canonical covering these missing registrations. https://github.com/microsoft/vscode/issues/49588 is open but requests filename-pattern/DocumentSelector mappings, a different capability that would not supply these language modes.
