# Issue #110663 — Missing language IDs for Emmet supported languages

[https://github.com/microsoft/vscode/issues/110663](https://github.com/microsoft/vscode/issues/110663)

## Summary

Stylus, slim, and haml are niche template/style languages whose language IDs are intentionally provided by extensions rather than bundled in VS Code core. The Emmet extension supports these syntaxes when the corresponding language extension is installed — this is by design per the extension-driven model.

## Change summary

Stylus, slim, and haml lack built-in language IDs despite being listed in Emmet's supported languages documentation.

## Best solution

Keep the current design where third-party extensions provide the language IDs for niche languages. The Emmet extension correctly activates for these syntaxes once an extension declares the language. At most, the Emmet documentation could clarify that some listed languages require a language extension to be installed.

## Vision fit

- **Fit:** rejected
- **Reason:** Bundling niche language support in core contradicts the 'lightweight text editor out of the box' value — the power belongs in extensions.
- **Evidence:** Value: 'Out of the box, VS Code is a text editor: lightweight and fast. Users may install extensions that impact the appearance and nature of VS Code.' and 'The power lives in extensions.'
