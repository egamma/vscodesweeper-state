# Issue #156178 — Git - Enable AI extensions to suggest a branch name (given the commit message)

[https://github.com/microsoft/vscode/issues/156178](https://github.com/microsoft/vscode/issues/156178)

## Summary

The standard Git branch-name input still has no integration for AI extensions to suggest a name from the last commit message. Existing Copilot session naming and older branch-naming requests do not fully cover this team-authored backlog item.

## Change summary

Allow AI extensions to provide an editable suggested branch name, derived from the last commit message, in the Git branch-name input.

## Best solution

Support extension-provided suggestions in the built-in Git branch-creation flow while preserving manual naming and existing validation. Coordinate the design with the older commit-message-seeding request, without treating its narrower issue-reference example as covering the extension integration.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/api/git.d.ts`, `extensions/git/src/repository.ts`, `extensions/copilot/src/extension/prompt/node/gitBranch.ts`
- **Validation:** After agreeing on the contract, run an extension-host scenario with a deterministic suggestion provider and a repository whose last commit has a known message: open Git: Create Branch, obtain the expected suggestion, edit and accept it, and verify the created branch. Also check cancellation, unavailable providers, invalid or conflicting suggestions, and unchanged manual/random naming without a provider.
- **Behavior:**

  > The standard Git branch-name input should allow an AI extension to suggest a meaningful name based on the repository's last commit message. The suggestion remains editable, and accepting it follows the existing branch-name validation and creation behavior. Manual naming must remain available when AI is disabled or no provider supplies a suggestion. Acceptance should verify the correct commit context, editable suggestions, cancellation, and preservation of existing prefix and random-name behavior.
- **Trace:**

  > Commands.promptForBranchName in extensions/git/src/commands.ts currently uses an explicit initial value or Repository.generateRandomBranchName with a static prefix fallback. Repository.generateRandomBranchName in extensions/git/src/repository.ts uses configured dictionaries, not commit context, and the API in extensions/git/src/api/git.d.ts has no branch-name suggestion registration. Copilot's GitBranchNameGenerator in extensions/copilot/src/extension/prompt/node/gitBranch.ts demonstrates semantic naming, but its inspected chat-session caller supplies the first chat prompt rather than the last commit message. The missing boundary is integration between the standard Git input and an extension-provided suggestion. Preserve existing manual creation, cancellation, sanitization, and duplicate-name checks; agent-session naming is not the reported surface. Coordinate with https://github.com/microsoft/vscode/issues/152852, which addresses commit-message seeding but does not settle the AI-provider contract.
- **Open decisions:**
  - Should an enabled provider populate the branch input automatically, or should generation require an explicit user action?
  - If multiple extensions provide suggestions, should the user select a provider or choose among their suggested names?

## Evidence
