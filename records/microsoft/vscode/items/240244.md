# Issue #240244 — Setting `editor.suggest.localityBonus` is not used

[https://github.com/microsoft/vscode/issues/240244](https://github.com/microsoft/vscode/issues/240244)

## Summary

Still reproduces on main: the `editor.suggest.localityBonus` setting is wired through `WordDistance.create` and the `CompletionModel` comparator, but the locality distance is a secondary tiebreaker after `score[0]` (fuzzy match score) — when two completions receive different fuzzy scores (even slightly), the distance bonus is never consulted. No fix has landed since the report.

## Change summary

The `editor.suggest.localityBonus` setting does not effectively prioritize completions closer to the cursor, because the locality distance is only used as a tiebreaker after fuzzy scores, which often differ.

## Best solution

The comparator in `CompletionModel._compareCompletionItems` (src/vs/editor/contrib/suggest/browser/completionModel.ts, line 244) should give more weight to the locality distance when `localityBonus` is enabled — either by incorporating it into the score or by applying it before the strict score comparison when scores are close. The `WordDistance` computation itself (src/vs/editor/contrib/suggest/browser/wordDistance.ts) appears correct; the issue is in how its output is ranked.
