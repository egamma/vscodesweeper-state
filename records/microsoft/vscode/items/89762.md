# Issue #89762 — Proposal: expose manual installation of vscode-remote

[https://github.com/microsoft/vscode/issues/89762](https://github.com/microsoft/vscode/issues/89762)

## Summary

Current CLI support covers much of scripted remote setup, but does not establish full coverage of preparing arbitrary containers or remote directories with predefined configuration before developers connect. Keep this accepted Backlog request open while clarifying the remaining provisioning contract.

## Change summary

Expose a supported, scriptable way to preinstall and configure VS Code's remote server across multiple workspaces without first connecting through the IDE.

## Best solution

Establish a documented provisioning workflow using existing server and CLI capabilities wherever possible, with explicit completion and compatibility guarantees for subsequently connecting clients. Determine whether install-only provisioning needs additional functionality rather than treating tunnel startup as equivalent.

## Plan brief

- **Likely files:** `cli/src/commands/args.rs`, `cli/src/tunnels/control_server.rs`, `cli/src/tunnels/code_server.rs`, `src/vs/server/node/serverEnvironmentService.ts`
- **Validation:** In a clean container or remote directory, run the agreed provisioning workflow without an IDE connection, wait for its explicit completion, then connect using the supported client path and verify that the intended server, extensions and configuration are ready. Repeat provisioning to check idempotence and simulate a failed download to verify that completion reports failure.
- **Behavior:**

  > An administrator can script preparation of multiple remote workspaces without first connecting through the VS Code IDE. The supported workflow should make the agreed server components and predefined configuration available when a developer connects. Acceptance should distinguish completed preparation from a background operation that might still fail. Existing interactive remote setup must remain available.
- **Trace:**

  > BaseServerArgs in cli/src/commands/args.rs provides extension preloading and configurable server-data and extension directories. preload_extensions in cli/src/tunnels/control_server.rs installs a Stable server and extensions before a client connects, but runs asynchronously alongside tunnel setup. ServerBuilder::setup in cli/src/tunnels/code_server.rs downloads and extracts the server into the CLI-managed cache. serverOptions in src/vs/server/node/serverEnvironmentService.ts exposes server configuration and extension-management arguments. The unresolved boundary is whether these existing facilities satisfy the intended connection workflow and directory/configuration contract; do not assume tunnel-based preparation is interchangeable with Remote-SSH or Dev Containers installation. Preserve existing connection, version-selection and interactive installation behavior.
- **Open decisions:**
  - Must provisioning terminate after preparing the workspace, or is a continuously running tunnel or web server an acceptable supported workflow?
  - Which subsequent connection paths must consume the prepared installation: Remote Tunnels, Remote-SSH, Dev Containers, or a defined subset?
  - What predefined configuration must provisioning guarantee beyond extensions and directory selection, and how must it behave when the connecting client's server version differs?

## Evidence

- **Accepted community demand:** https://github.com/microsoft/vscode/issues/89762 has 21 community upvotes and is in Backlog. The March 28, 2020 bot comment explicitly records promotion after meeting the community threshold.
- **Existing public capability:** https://code.visualstudio.com/docs/remote/vscode-server documents a standalone server accessed through the code CLI and code tunnel. cli/src/commands/args.rs::BaseServerArgs exposes --install-extension, --server-data-dir and --extensions-dir; ServeWebArgs also exposes --default-folder and --default-workspace.
- **Preconnection installation exists:** cli/src/tunnels/control_server.rs::preload_extensions sets start_server=false, resolves a Stable server, calls ServerBuilder::setup and installs extensions without a remote connection. Its caller launches this work asynchronously during tunnel setup, logging installation failure as a warning. This is meaningful partial coverage, but not proof of a standalone provisioning operation with a completion result.
- **Remaining scope:** cli/src/commands/args.rs registers tunnel startup, tunnel service installation and serve-web, but no dedicated server install-only subcommand. cli/src/tunnels/code_server.rs::ServerBuilder::setup downloads into the CLI-managed server cache. These paths do not by themselves establish the requested contract for preconfigured target directories or container images consumed by existing remote connection workflows.

The supplied candidate https://github.com/microsoft/vscode/issues/52116 concerns extension permissions, sandboxing and update management rather than scripted remote-server provisioning.
