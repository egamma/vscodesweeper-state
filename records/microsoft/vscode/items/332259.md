# Issue #332259 — Disabling for a specific workspace should make it clear for which workspace it is disabled

[https://github.com/microsoft/vscode/issues/332259](https://github.com/microsoft/vscode/issues/332259)

## Summary

Fresh, reasonable UX polish suggestion from internal testing: when an MCP server is disabled per-workspace, the greyed-out entry doesn't indicate which workspace it's disabled for. No existing hover/tooltip surfaces that info today, so this is a real small gap worth routing to the area owner.

## Change summary

When an MCP server/plugin entry shows 'Disable (Workspace)' as greyed out, it's unclear which workspace the disablement applies to; requester suggests surfacing this on hover.

## Best solution

Add a hover tooltip (via IHoverService, similar to the existing setupManagedHover/setupDelayedHover usages) on the disabled MCP server list item in src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts that names the workspace it's disabled for.
