# Issue #146547 — Add an `onExtensionActivated` activation event

[https://github.com/microsoft/vscode/issues/146547](https://github.com/microsoft/vscode/issues/146547)

## Summary

Valid, unimplemented feature request. No `onExtensionActivated` activation event exists on current main, and `extensionDependencies` does not solve the co-activation use case described. Stays open in Backlog for the community process.

## Change summary

Allow an extension to declare an activation event that fires when a specific other extension activates, so dependent extensions co-activate without duplicating activation events.

## Best solution

Implement an `onExtensionActivated:<extensionId>` activation event in the extension activation machinery (around `src/vs/workbench/services/extensions/common/extensions.ts` and the activation-event handling in `extHostExtensionActivator.ts`). This would let extensions declare co-activation dependencies cleanly. The existing `extensionDependencies` ensures ordering but not co-activation — both mechanisms would coexist.
