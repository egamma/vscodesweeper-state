# Issue #334441 — Agents Window logs noisy customization errors during disposal

[https://github.com/microsoft/vscode/issues/334441](https://github.com/microsoft/vscode/issues/334441)

## Summary

Traced and confirmed in source: SyncedCustomizationBundler's Limiter is disposed via `_register` while an in-flight `bundle()`/`collectDirectoryFiles` traversal is still queuing file operations, so every pending stat throws 'Object has been disposed' and gets trace-logged per file, flooding the Window log during normal Agents Window disposal.

## Change summary

Disposing an Agents Window customization scope mid-bundle causes a storm of 'Object has been disposed' trace logs (plus a benign canceled-network-request error log) instead of a clean, quiet shutdown.

## Best solution

In src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/syncedCustomizationBundler.ts, stop accepting new bundle() calls after dispose, let the file-operation limiter drain in-flight work (or have queued operations resolve as a benign cancellation) instead of throwing 'disposed', and only trace-log genuine stat failures — not disposal races. A commenter (benibenj) already sketched this exact fix shape.
