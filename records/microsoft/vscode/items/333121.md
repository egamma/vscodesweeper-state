# Issue #333121 — Copilot Chat is rendering identifiers like `__init__` as bold because the response is being interpreted as markdown.

[https://github.com/microsoft/vscode/issues/333121](https://github.com/microsoft/vscode/issues/333121)

## Summary

Confirmed by running VS Code's own vendored marked.js parser: `__init__` legitimately satisfies CommonMark's emphasis-flanking rules (no alphanumeric immediately outside either `__` run), so it renders as `<strong>init</strong>` — this is spec-compliant Markdown rendering, not a renderer defect, and the reporter's own tests show the correct workaround (backticks/code fences) already works.

## Change summary

Copilot Chat renders double-underscore Python identifiers like `__init__` as bold text instead of literal characters when the model emits them outside of code formatting.

## Best solution

Keep the current CommonMark-compliant rendering in src/vs/base/common/marked/marked.js / chatContentMarkdownRenderer.ts; the durable fix is for chat responses to wrap code identifiers in backticks (which the reporter confirms already renders correctly) rather than adding a special-cased underscore exception to the shared Markdown renderer.
