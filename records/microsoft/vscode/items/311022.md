# Issue #311022 — [Error] unhandlederror-potential listener LEAK detected, popular

[https://github.com/microsoft/vscode/issues/311022](https://github.com/microsoft/vscode/issues/311022)

## Summary

Still reproduces on main: the PersistedMenuHideState._onDidChange singleton emitter accumulates one listener per active MenuImpl (each notebook cell output toolbar creates one), crossing the global leak threshold of 175. No fix has landed that addresses this threshold-crossing pattern.

## Change summary

Notebook cell output toolbars subscribing to the shared PersistedMenuHideState._onDidChange emitter cause a listener-leak warning when many cells are visible.

## Best solution

Either raise the leak threshold on the PersistedMenuHideState._onDidChange emitter (since the many-subscribers pattern is legitimate), or restructure so MenuImpl instances don't each independently subscribe to it — e.g. use a reference-counted shared subscription or an observableSignal. This is the same root cause as https://github.com/microsoft/vscode/issues/308255 and could be fixed together.
