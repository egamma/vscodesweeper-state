# Issue #244972 — workspace/symbol only sends the part of the query before the first space the the provider

[https://github.com/microsoft/vscode/issues/244972](https://github.com/microsoft/vscode/issues/244972)

## Summary

The provider still receives only the first space-separated segment on current main; local full-query matching does not restore the information lost before provider invocation. Keep this accepted, team-authored request open: it has 39 upvotes, and the older related request concerns a different observable filtering problem.

## Change summary

Allow workspace symbol providers to receive complete multiword queries entered through Ctrl+T rather than only the first word.

## Best solution

Define how workspace symbol search can deliver complete queries to providers while retaining intentional symbol/container narrowing. Resolve that compatibility contract in the workspace-symbol quick-access area before implementing the accepted request.

- **Behavior:**

  > Ctrl+T currently sends only 'my' to a workspace symbol provider when the user enters '#my query string', preventing provider-side interpretation of the complete input. The requested outcome is that providers can receive the complete multiword query. Acceptance must cover recorded provider arguments and visible results for symbols containing spaces, with single-word navigation unchanged. The compatibility behavior for intentional symbol/container searches must be settled before implementation.
- **Trace:**

  > SymbolsQuickAccessProvider.getSymbolPicks in src/vs/workbench/contrib/search/browser/symbolsQuickAccess.ts prepares the filter through prepareQuery. In src/vs/base/common/fuzzyScorer.ts, prepareQuery splits on spaces; doGetSymbolPicks then selects the first piece as symbolQuery and the remaining pieces as containerQuery. getWorkspaceSymbols in src/vs/workbench/contrib/search/common/search.ts forwards symbolQuery.original unchanged to each provider. Full-query scoring in doGetSymbolPicks occurs only after providers return results, so it cannot repair missing provider input. The programmatic '_executeWorkspaceSymbolProvider' command already forwards its supplied query without this split; preserve that behavior and avoid changing shared fuzzy scoring for unrelated pickers. https://github.com/microsoft/vscode/issues/98125 provides related provider-controlled filtering design context, but describes a different symptom. No implementation or runtime reproduction was performed in this read-only review.
- **Open decisions:**
  - Should Ctrl+T always send the complete input to workspace symbol providers, or expose an explicit full-query mode while retaining first-segment provider queries for existing symbol/container searches?
