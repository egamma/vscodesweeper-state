# Issue #586 — Link to a file position in Output Channel

[https://github.com/microsoft/vscode/issues/586](https://github.com/microsoft/vscode/issues/586)

## Summary

Keep open: absolute file-position links and channel-specific custom link providers are supported, but default detection still requires a workspace-root prefix and does not cover the requested relative-path behavior. This accepted Backlog request has 39 upvotes; the verified related issues are newer and do not absorb its full scope.

## Change summary

Support clickable workspace-relative file-position links in Output channels, including paths with spaces and custom display text.

## Best solution

Extend the Output linking experience to resolve workspace-relative file positions reliably, with explicit multi-root semantics and supported space-containing paths. Use the existing channel-specific DocumentLinkProvider API for custom display text where sufficient, distinguishing clickable text ranges from replacing displayed URLs with aliases.

- **Behavior:**

  > Output should support navigation from workspace-relative diagnostic paths to the intended file position without requiring extensions to emit absolute paths. Supported paths containing spaces should retain their full target. Existing absolute links and line/column navigation must remain unchanged. Acceptance must establish relative-path resolution in single-root and multi-root workspaces, and distinguish custom clickable text already achievable through providers from any requested display-alias capability.
- **Trace:**

  > OutputLinkProvider registers OutputLinkComputer for the standard Output and Log languages and supplies workspace folder URIs. OutputLinkComputer.createPatterns requires the full workspace-root path in each match, so the reported './server_test.go:45' form is outside its current default detection. Its diagnostic patterns permit some spaces, but its colon-form strictPathPattern does not. The stable createOutputChannel languageId overload and registerDocumentLinkProvider API already support channel-specific custom link ranges; do not assume a new API is required for that part. Preserve existing absolute-path, remote-resource, and line/column handling. The uncertainty starts at how an Output channel's relative paths select a root when multiple workspace folders are open; https://github.com/microsoft/vscode/issues/149153 and https://github.com/microsoft/vscode/issues/191132 track related but distinct behaviors.
- **Open decisions:**
  - When the same relative path exists in multiple workspace folders, should clicking select among matching files, require explicit workspace qualification, or use a defined channel-associated root?
