# Issue #248533 — Accept all incoming or current changes for merge conflicts requires manual file saving and staging and does not work on .bin files

[https://github.com/microsoft/vscode/issues/248533](https://github.com/microsoft/vscode/issues/248533)

## Summary

The reported behavior remains in current source: the SCM actions only apply text edits and neither save nor stage them, while binary conflicts cannot be resolved through the text-conflict parser. Two older open issues cover the individual symptoms, but neither owns this compound report's full scope, so the stronger re-review duplicate bar is not met.

## Change summary

Make the SCM Accept All Current/Incoming actions complete conflict resolution without manual saving and staging, including for binary files.

## Best solution

Define consistent SCM-level semantics for accepting a side, then support both text and binary conflicts with clear failure feedback. Consolidate implementation and validation with the older text-save and binary-conflict reports while preserving their distinct requirements.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/commandHandler.ts`, `extensions/merge-conflict/src/mergeConflictParser.ts`, `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`
- **Validation:** In a temporary Git repository, create one text conflict and one binary conflict; invoke Accept All Current and Accept All Incoming from the SCM resource context menu and assert the selected content is on disk, the Git index has the intended side, and neither resource remains in the merge group.
- **Behavior:**

  > Accept All Current and Accept All Incoming from the Source Control merge group must visibly resolve the selected resource rather than silently doing nothing. Text conflicts must follow an explicitly chosen save/stage contract without leaving an unexpectedly dirty editor, and binary conflicts must select the requested Git side. Acceptance should cover both directions for text and binary files, multiple selected resources, resulting disk content, index state, and removal from the Merge Changes group.
- **Trace:**

  > The SCM menu registrations in extensions/merge-conflict/package.json invoke the resource callbacks in CommandHandler. `CommandHandler.acceptAllResources` in extensions/merge-conflict/src/commandHandler.ts opens resources as text documents, asks the marker-based tracker for conflicts, and applies a WorkspaceEdit without saving or staging. Binary conflicts contain no parsable conflict markers, so that path skips them; selecting a binary side likely requires coordination with the Git implementation in extensions/git/src/commands.ts and extensions/git/src/repository.ts. The unsaved-text subset is tracked by https://github.com/microsoft/vscode/issues/169923 and the binary subset by https://github.com/microsoft/vscode/issues/134785. Preserve editor-based conflict actions and unrelated staging commands; the plan should settle only the SCM resource action's persistence, staging, and binary semantics.
- **Open decisions:**
  - After accepting a side for a text conflict from the SCM resource menu, should VS Code save and stage automatically, or save while leaving staging as an explicit Git action?
  - For a binary conflict, should accepting Current or Incoming immediately stage the chosen blob, or update the working tree while leaving the resource unstaged?

## Evidence

- **current source:** extensions/merge-conflict/src/commandHandler.ts:277-294 implements `acceptAllResources` by opening each resource as a text document, parsing marker conflicts, constructing a `WorkspaceEdit`, and calling `vscode.workspace.applyEdit(edit)`; it does not save the documents or invoke Git staging.
- **binary path:** The same implementation depends on `openTextDocument` and marker-based `tracker.getConflicts(document)`, so it has no path for selecting an index side of a binary Git conflict.
- **related text issue:** https://github.com/microsoft/vscode/issues/169923 is older and open, and reports the same unsaved-text symptom, but it does not cover binary conflict resolution or the complete staging requirement.
- **related binary issue:** https://github.com/microsoft/vscode/issues/134785 is older and open, and reports the same no-op behavior for binary conflicts, but it does not own the text save-and-stage behavior.
- **history:** The relevant handler behavior remains on current main; post-report history for extensions/merge-conflict contains no change implementing save, staging, or binary-side selection.
