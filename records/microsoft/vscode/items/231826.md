## Change summary

VS Code's Windows system installer update corrupts the installation when a WSL session is actively connected, due to file locking conflicts.

## Best solution

The update service on Windows (src/vs/platform/update/electron-main/updateService.win32.ts) should detect active WSL/remote connections and either defer the update or warn the user before proceeding. Recent work on coordinating Inno spawns (#318486) and COM surrogate termination may provide patterns, but WSL-specific handling is still missing.
