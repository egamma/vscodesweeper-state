# Issue #341540 — Argument hint not always displayed in chat window for custom agent

[https://github.com/microsoft/vscode/issues/341540](https://github.com/microsoft/vscode/issues/341540)

## Summary

Thanks for the report. The report is complete (custom agent in .github/agents, restart, pick the agent) and a second comment confirms it persists in 1.142.0. I could not confirm the cause from source. The placeholder logic does not watch the agent's argument hint, which may explain the machine-dependent result.

## Change summary

The chat input placeholder sometimes shows the generic 'Chat with Copilot' text instead of a custom agent's argument-hint.

## Best solution

Make the chat input placeholder update whenever the current mode's argumentHint changes, and check the load-ordering of custom agents (WSL remote, restart) so the hint is not left stale.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputEditorContrib.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`
- **Validation:** Reproduce with a custom agent that has `argument-hint`, in a WSL remote window after a restart. Then add a test that changes a mode's argumentHint observable and asserts the placeholder decoration updates.
- **Behavior:**

  > When a custom agent with an `argument-hint` is selected, the empty chat input always shows that hint, including after a restart and in remote windows. Agents without a hint keep showing their description or the default placeholder. Acceptance: the placeholder reflects argumentHint changes without requiring a description change.
- **Trace:**

  > updateInputPlaceholderDecoration in chatInputEditorContrib.ts reads `mode.argumentHint?.get()` untracked, and the autorun that triggers refreshes subscribes only to `currentMode.description`. ChatMode in chatModes.ts updates argumentHint through its own observable (~line 585). Unconfirmed: whether the 'Chat with Copilot' text comes from viewModel.inputPlaceholder or from the mode being resolved late. Do not change the viewModel placeholder precedence.

## Evidence

- **placeholder source:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputEditorContrib.ts (~line 233) computes `mode.argumentHint?.get() ?? mode.description.get()`, but the autorun at ~line 146 only reads `currentMode.description`, not `argumentHint`. A late argumentHint update would not refresh the placeholder.
- **mode update path:** src/vs/workbench/contrib/chat/common/chatModes.ts line ~585 updates `_argumentHintObservable` separately from other fields. If the description is unchanged, nothing triggers a decoration refresh.
- **environment:** Reported with a WSL remote, where custom agents may load asynchronously after the chat widget renders; this fits the 'some computers only' pattern. I could not verify it without running the code.
