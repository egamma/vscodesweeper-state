# Issue #332379 — Copilot Chat reports an invalid GitHub token while VS Code still shows the account as signed in

[https://github.com/microsoft/vscode/issues/332379](https://github.com/microsoft/vscode/issues/332379)

## Summary

Traced a real, current gap in source: the HTTP401 'invalid token' warning is a plain `window.showWarningMessage` string with no action button, while the parallel Copilot welcome-view message for the same condition already ships a working 'Sign In' action wired to `workbench.action.chat.triggerSetupForceSignIn` — so the recovery path the reporter is asking for exists elsewhere in the product but isn't surfaced in the notification that actually fires.

## Change summary

When Copilot's GitHub token becomes invalid (HTTP 401), the notification shown to the user has no actionable recovery step and the Accounts UI doesn't clearly reflect the broken auth state, leaving the user to guess at sign-out/sign-in/reload cycles.

## Best solution

In extensions/copilot/src/platform/authentication/vscode-node/copilotTokenManager.ts (`_authShowWarnings`, HTTP401 branch), add a 'Sign In' action item to the `window.showWarningMessage` call that invokes the same `workbench.action.chat.triggerSetupForceSignIn` command already used by the `github.copilot.viewsWelcome.invalidToken` welcome content (package.nls.json), and ensure the `InvalidToken` context key path (contextKeys.contribution.ts) is also refreshed when a 401 occurs during a background token refresh, not just at initial activation, so the Accounts/welcome UI stays in sync with the live notification.
