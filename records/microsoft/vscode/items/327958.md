# Issue #327958 — Terminal in an auxiliary window stops rendering on U+2591: custom glyph rasterizer calls createElement in a child window

[https://github.com/microsoft/vscode/issues/327958](https://github.com/microsoft/vscode/issues/327958)

## Summary

Well-diagnosed, reproducible bug with a stack trace pinpointing the exact failure; an open PR (#330777) already targets this exact issue with "Fixes #327958", so per policy this stays open pending merge rather than closing.

## Change summary

In a terminal moved to an auxiliary window, rendering a shade block character (U+2591/2592/2593) throws inside CustomGlyphRasterizer's createElement call (blocked in child-window documents), permanently breaking further rendering of that terminal.

## Best solution

Land and verify https://github.com/microsoft/vscode/pull/330777, which disables xterm custom glyph rasterization while a terminal is hosted in an auxiliary window (and recreates the addon on window moves) to avoid the poisoned child-document createElement call; a collaborator has already posted verification steps for Insiders.
