# Issue #323622 — Increase Settings Sync limit for `keybindings.json` to 200kb

[https://github.com/microsoft/vscode/issues/323622](https://github.com/microsoft/vscode/issues/323622)

## Summary

This remains a valid, accepted backlog request with 55 community upvotes. Current main still handles a server-side 413 by disabling keybindings sync and presenting a hardcoded 100kb limit, with no existing setting or command covering larger keybinding files.

## Change summary

Allow Settings Sync to synchronize keybindings files between 100kb and at least 200kb.

## Best solution

Raise the sync service's supported payload allowance for keybindings while retaining a bounded safeguard, and ensure VS Code reports the effective service limit accurately rather than relying on a stale hardcoded value.

- **Reason:** Supporting complete synchronization of a user's keyboard workflow advances settings fidelity without adding default UI or always-on functionality.

## Plan brief

- **Likely files:** `src/vs/platform/userDataSync/common/userDataSyncStoreService.ts`, `src/vs/platform/userDataSync/common/abstractSynchronizer.ts`, `src/vs/workbench/contrib/userDataSync/browser/userDataSync.ts`
- **Validation:** Against a sync test service configured with the chosen cap, synchronize a generated keybindings payload between 100kb and 200kb across two clients, then verify that a payload above the cap is rejected with an error displaying the service's actual limit.
- **Behavior:**

  > Settings Sync accepts a keybindings file above 100kb up to the newly supported limit and restores it unchanged on another client. Files above the effective limit remain bounded and produce an accurate, actionable error rather than silently retrying. Settings and tasks retain whichever limits the selected resource policy defines.
- **Trace:**

  > The keybindings synchronizer ultimately writes through the shared sync store; src/vs/platform/userDataSync/common/userDataSyncStoreService.ts converts the service's HTTP 413 into TooLarge, and src/vs/platform/userDataSync/common/abstractSynchronizer.ts attaches the affected resource. src/vs/workbench/contrib/userDataSync/browser/userDataSync.ts then disables that resource and renders a hardcoded 100kb message. No client-side configuration currently controls the payload limit, so the authoritative acceptance policy appears to live in the sync service outside this checkout. The earlier discussion at https://github.com/microsoft/vscode/issues/86178 establishes that the limit should not be independently hardcoded by the client. Preserve rejection and sync-disable behavior for genuinely oversized payloads; do not turn this into an unlimited or user-configurable upload path without an explicit product decision.
- **Open decisions:**
  - Should the larger allowance apply only to keybindings, or uniformly to settings, keybindings, and tasks that currently share the same TooLarge handling?
  - Should clients discover and display a server-advertised maximum, or is a versioned fixed limit an intentional part of the Settings Sync contract?
  - What maximum payload provides the intended keybinding coverage while preserving the sync service's storage and request safeguards?

## Evidence

- **current user behavior:** src/vs/workbench/contrib/userDataSync/browser/userDataSync.ts disables keybindings sync after TooLarge and displays a hardcoded '100kb' limit in both automatic-sync and turn-on flows.
