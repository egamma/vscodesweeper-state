# Issue #211980 — Offering When Clause context for snippet activation

[https://github.com/microsoft/vscode/issues/211980](https://github.com/microsoft/vscode/issues/211980)

## Summary

Keep this accepted Backlog request open: current snippet contributions still cannot evaluate when-clause contexts. Existing language/file filters and manual enablement do not cover dynamic framework-version conditions; no verified open canonical owns the full request.

## Change summary

Allow extension-contributed snippet sets to be conditionally available through a when clause.

## Best solution

Support declarative context-dependent availability for contributed snippet sets in the snippets service, preserving existing language and file filtering. Settle which editor context is evaluated and whether conditions govern discovery only or explicit insertion as well.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/snippets/browser/snippetsService.ts`, `src/vs/workbench/contrib/snippets/browser/snippetsFile.ts`, `src/vs/workbench/contrib/snippets/browser/snippets.ts`, `src/vs/workbench/contrib/snippets/browser/snippetCompletionProvider.ts`, `src/vs/workbench/contrib/snippets/browser/tabCompletion.ts`, `src/vs/workbench/contrib/snippets/browser/commands/insertSnippet.ts`, `src/vs/workbench/contrib/snippets/test/browser/snippetsService.test.ts`
- **Validation:** Create an extension fixture contributing two HTML snippet sets under mutually exclusive context keys. Toggle those keys with setContext without reloading and verify completion, Tab completion and Insert Snippet follow the agreed condition semantics, including an embedded HTML region. Add targeted snippets-service tests for true, false, absent and changing conditions; run ./scripts/test.sh --run src/vs/workbench/contrib/snippets/test/browser/snippetsService.test.ts in the implementation workspace.
- **Behavior:**

  > An extension can conditionally expose a contributed snippet set using a when expression, such as language.versionFour. Changing the relevant context makes the matching set available without moving files or reloading the window. Contributions without a condition retain their existing behavior, and language/file restrictions continue to apply. Acceptance must cover normal and embedded-language completion, Tab completion and the agreed behavior of Insert Snippet.
- **Trace:**

  > snippetExt.ISnippetsExtensionPoint, snippetsContribution and toValidSnippet in src/vs/workbench/contrib/snippets/browser/snippetsService.ts carry only language/path metadata; _initExtensionSnippets stores snippet files without context conditions. Both getSnippets and getSnippetsSync feed _filterAndSortSnippets, which handles manual enablement and resource filtering but has no context-expression evaluation. Completion and Tab completion consume these service methods; InsertSnippetAction additionally supports explicit named insertion and raw snippet bodies. Preserve unconditional contributions, existing language selection, filename filters and direct raw-body insertion. The trace establishes the missing capability, but not which editor-scoped context should be used or whether named insertion may bypass a false condition. The merged external workaround at https://github.com/eclipse-che4z/che-che4z-lsp-for-cobol/pull/2917 demonstrates the dialect-selection gap rather than resolving it.
- **Open decisions:**
  - Should conditions evaluate against the editor requesting snippets, including editor-scoped keys, or only against window/workbench context?
  - Should a false condition hide snippets from discovery surfaces only, or also prevent explicit insertion by snippet name?

## Evidence

- **Current contribution contract:** src/vs/workbench/contrib/snippets/browser/snippetsService.ts defines snippetExt.ISnippetsExtensionPoint and snippetsContribution with language and path only. toValidSnippet returns language/location, and _initExtensionSnippets constructs SnippetFile without any condition metadata.
- **Existing capabilities do not cover the ask:** SnippetsService.isEnabled uses persisted manual enablement; _filterAndSortSnippets checks prefix, enablement, file-template status and resource inclusion, not context expressions. src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts offers scope and include/exclude filename globs, which cannot evaluate an extension-defined context such as language.versionFour.
- **Affected discovery paths:** src/vs/workbench/contrib/snippets/browser/snippetCompletionProvider.ts requests snippets for the language at the cursor and model URI. tabCompletion.ts uses getSnippetsSync, while commands/insertSnippet.ts supports both a picker and explicit named insertion; its named path requests snippets with includeNoPrefixSnippets and no resource URI. Context semantics must be defined across these entry points.
