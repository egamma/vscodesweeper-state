# Issue #340063 — fix: treat unresolved default chat backend URI as startup no-op (fixes #340059)

[https://github.com/microsoft/vscode/issues/340063](https://github.com/microsoft/vscode/issues/340063)

## Summary

Confirmed on main: `setChatReadState` throws 'The chat could not be found.' when the default chat's backend URI hasn't hydrated yet, because `getBackendChatResource` returns `undefined` for the default chat before the host catalog delivers it — exactly as this bot-authored report traces. The PR for this never actually landed (creation failed), so the fix is still needed.

## Change summary

Opening a session before the Agent Host chat catalog hydrates the default chat's backend URI causes an unhandled 'chat not found' error during the auto mark-as-read transition.

## Best solution

Apply the proposed fix in `setChatReadState` (src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts): treat an unresolved backend URI for the default chat (no fragment) as a not-ready no-op (return false) rather than throwing, mirroring the sibling guard three lines above; keep the throw for peer chats, which carry a fragment and represent genuine not-found cases.
