# Issue #335720 — Multi-diff model teardown re-enters binding disposal and throws

[https://github.com/microsoft/vscode/issues/335720](https://github.com/microsoft/vscode/issues/335720)

## Summary

Confirmed in current source: DiffEditorItemBinding.dispose() guards re-entrancy only via `this._store.isDisposed`, which stays false until super.dispose() runs, so a synchronous re-entrant call from the observable reaction chain during template.unbind() sees a partially-torn-down binding and throws. The listener-count issue in #206959 is unrelated.

## Change summary

Tearing down a multi-diff editor's virtualized bindings can re-enter binding disposal mid-teardown and throw a BugIndicatingError.

## Best solution

Make ManagedVirtualizedItem._clearBinding and DiffEditorItemBinding.dispose re-entrancy-safe (e.g. an explicit 'releasing' flag set before calling template.unbind/binding.dispose) so a nested call triggered by the observable reaction chain becomes a no-op instead of hitting a template whose view model was already cleared.
