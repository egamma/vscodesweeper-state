# Issue #34093 — Feature request - undo after moving cursor should optionally just put the cursor back, without undoing

[https://github.com/microsoft/vscode/issues/34093](https://github.com/microsoft/vscode/issues/34093)

## Summary

Keep this accepted Backlog request open: ordinary Undo still immediately undoes text, while Cursor Undo and Go to Last Edit Location remain separate commands. Neither delivers the requested optional two-stage Undo behavior, and no verified open canonical was found.

## Change summary

Optionally make the first Undo after cursor navigation return to the last edit location without changing text, with a subsequent Undo reverting the edit.

## Best solution

Design an opt-in editor Undo behavior that returns to the pending edit location before reverting text, while preserving the existing default behavior. Settle its interaction with Redo and viewport-only navigation before implementation.

Verify unchanged default behavior and the agreed Redo semantics. Manually check the reporter's type/select/copy/Undo/paste sequence and the agreed off-screen-edit behavior.
- **Behavior:**

  > Provide optional two-stage Undo behavior after navigating away from an edit. In the reporter's type/select/copy workflow, the first Undo returns to the last edit location without modifying text, regardless of intervening cursor moves, and the next Undo reverts the pending edit. Existing Undo behavior remains the default. Acceptance must also cover the agreed behavior for Redo and edits outside the current viewport.
- **Trace:**

  > CoreEditorCommands.Undo in src/vs/editor/browser/coreCommands.ts immediately invokes TextModel.undo(), which delegates to the undo/redo service; there is no preliminary navigation stage in this path. CursorUndoRedoController in src/vs/editor/contrib/cursorUndo/browser/cursorUndo.ts independently records selection changes and clears its stacks on content changes, so it does not implement the requested last-edit boundary. NavigateToLastEditLocationAction in src/vs/workbench/browser/parts/editor/editorActions.ts provides a separate workbench navigation command through IHistoryService.goLast(GoFilter.EDITS), not integrated Undo behavior. The reporter explicitly distinguished this request from Cmd+U in https://github.com/microsoft/vscode/issues/34093; cursor-history preservation in https://github.com/microsoft/vscode/issues/82011 is adjacent but separate. Preserve ordinary default Undo, standalone cursor navigation, and model-level text undo semantics. The remaining uncertainty is the user-visible contract for the optional navigation stage, rather than whether that stage already exists.
- **Open decisions:**
  - Should the cursor-only first Undo participate in Redo history, or act as navigation that leaves text Redo history unchanged?
  - Should scrolling the last edit out of view without moving the cursor also trigger the preliminary reveal-only Undo?
