- **Behavior:**

  > Enabling GitHub Environments for a local project must not fail because unrelated mapped network drives exist. Available local drives should retain their existing behavior, and network-backed roots must not bypass the existing local-directory restriction. Acceptance requires successful registration with and without an unrelated mapped drive.
- **Trace:**

  > MissionControlSharingService._getFileSystemRoots enumerates all Windows drive letters and filters UNC-shaped IFileService.realpath results before passing roots to configureMissionControl. The disk provider uses the callback-based pfs realpath helper, whereas MissionControlEnvironment._configure canonicalizes those roots with fs/promises.realpath and rejects UNC-shaped results. This is a plausible explanation for https://github.com/microsoft/vscode/issues/346245, not a confirmed current-main reproduction. The existing Windows-drive test supplies a mocked UNC result and therefore does not establish actual mapped-drive behavior. First establish both canonicalization results on Windows; preserve shared filesystem-service semantics, local-directory restrictions, and ordinary local-drive sharing.
