# Issue #84763 — Make "move line" command to work contextually

[https://github.com/microsoft/vscode/issues/84763](https://github.com/microsoft/vscode/issues/84763)

## Summary

Keep this accepted feature request open: Move Line still operates on selected lines rather than automatically including a multiline object property's value. The request has 21 upvotes, and neither existing selection commands nor the inspected related issues cover its one-command structural movement goal.

## Change summary

Allow moving a multiline object property and its nested value together from a cursor on the property's opening line.

## Best solution

Design syntax-aware property movement in the editor's line-operation area, preserving complete property values and valid sibling ordering. Decide whether this should augment the existing commands through an opt-in behavior or be exposed separately, without removing predictable literal line movement.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/linesOperations/browser/linesOperations.ts`, `src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts`, `src/vs/editor/contrib/linesOperations/test/browser/moveLinesCommand.test.ts`, `src/vs/editor/contrib/smartSelect/browser/smartSelect.ts`
- **Validation:** The plan should end with an executable editor test using the issue's JavaScript object: place an empty selection on position: {, invoke the chosen contextual move-up action once, and assert that the entire property precedes isValid with its nested value intact. Cover the reverse movement and preservation of ordinary literal line movement; no tests were executed in this read-only review.
- **Behavior:**

  > A user can move a multiline object property together with its nested value without first selecting all of its lines. For the issue's example, one contextual upward movement from position: { places the whole position property above isValid while preserving the object's contents and syntax. Acceptance should cover movement in both directions and leave a predictable way to move individual literal lines.
- **Trace:**

  > AbstractMoveLinesAction.run in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts forwards the current selections directly to MoveLinesCommand. MoveLinesCommand.getEditOperations in the adjacent moveLinesCommand.ts determines the moved block from those selection line boundaries and applies indentation adjustments, but does not discover an enclosing object property. SmartSelectController in src/vs/editor/contrib/smartSelect/browser/smartSelect.ts separately obtains selection ranges; it is not called by the move actions. This source trace establishes the missing automatic range discovery, not a chosen syntax-provider design. Preserve existing multiline-selection and literal-line movement semantics while the maintainer chooses the contextual command contract. The existing moveLinesCommand.test.ts suite is a relevant validation starting point; syntax-range integration remains to be designed. The indentation reports at https://github.com/microsoft/vscode/issues/213598 and https://github.com/microsoft/vscode/issues/221362 describe separate behavior and should not be folded into this scope.
- **Open decisions:**
  - Should contextual property movement be a separate command, an opt-in mode of Move Line Up/Down, or a change to their default behavior?
  - Should the initial public behavior apply only to JavaScript/TypeScript object properties, or to structural units in other supported languages as well?
