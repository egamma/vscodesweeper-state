# Issue #338119 — Ctrl+Shift+A no longer selects all

[https://github.com/microsoft/vscode/issues/338119](https://github.com/microsoft/vscode/issues/338119)

## Summary

Reporter gives a clear, simple, deterministic firsthand repro (extensions disabled, current build) and the source shows a plausible cause: the new 'Open Agents Window' keybinding's Linux-only carve-out only defers to a focused writable editor, not to the terminal, so Ctrl+Shift+A can claim the shortcut while a terminal has focus on Linux.

## Change summary

On Linux, Ctrl+Shift+A now opens the Agents Window instead of behaving as expected in the integrated terminal.

## Best solution

Extend the exclusion in OpenAgentsWindowAction's keybinding `when` clause (currently only defers to a focused, writable, non-readonly editor on Linux) to also defer when a terminal has focus, so the new global shortcut doesn't steal Ctrl+Shift+A away from terminal usage.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`
- **Validation:** Manually verify on Linux: focus the integrated terminal, press Ctrl+Shift+A, confirm it no longer opens the Agents Window (and behaves as before the Agents Window keybinding was added); confirm the shortcut still opens the Agents Window from a normal, non-editor, non-terminal focus context.
- **Behavior:**

  > On Linux, pressing Ctrl+Shift+A while the integrated terminal has focus should not open the Agents Window; the keystroke should reach the terminal exactly as it did before this shortcut was added. Ctrl+Shift+A should continue to open the Agents Window from other focus contexts (e.g. sidebar, panel, no editor focus) as intended, and should still defer to Toggle Block Comment in a focused writable editor as it already does.
- **Trace:**

  > The keybinding is defined in src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts, class OpenAgentsWindowAction. Its `when` clause only defers to Ctrl+Shift+A on Linux when focus is in the editor area (EditorAreaFocusContext) and the editor is writable — it never checks terminal focus, so the shortcut also fires while a terminal is focused. Do not touch the mac/accessibility-mode keybinding variant (the second entry with Alt) or change behavior outside Linux without confirming it's wanted; the editor-focused carve-out and its Toggle Block Comment rationale must remain intact. Related: terminal key routing goes through TerminalInstance.attachCustomKeyEventHandler (src/vs/workbench/contrib/terminal/browser/terminalInstance.ts) and commandsToSkipShell (src/vs/workbench/contrib/terminal/common/terminal.ts) — worth checking whether any negation should instead live there.
- **Open decisions:**
  - Should the terminal-focus exclusion be Linux-only (matching the existing editor carve-out's rationale) or apply to the Agents Window shortcut on all platforms?
  - Should the fix defer whenever any terminal instance has focus, or only in specific terminal states (e.g., not in the terminal's find widget)?

## Evidence

- **keybinding when-clause:** src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts (OpenAgentsWindowAction, ~line 293-306): `when: ContextKeyExpr.and(IsSessionsWindowContext.toNegated(), CONTEXT_ACCESSIBILITY_MODE_ENABLED.toNegated(), ContextKeyExpr.or(IsLinuxContext.toNegated(), EditorAreaFocusContext.toNegated(), EditorContextKeys.readOnly))`. The inline comment says the Linux carve-out exists only to defer to editor.action.blockComment (which is bound to ctrl+shift+a only on Linux, per src/vs/editor/contrib/comment/browser/comment.ts:145). Terminal focus is never checked, so on Linux the OR clause is satisfied whenever focus isn't in the editor area (including terminal), letting the global shortcut fire.
- **terminal key routing (partial trace):** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts ~1147-1207: attachCustomKeyEventHandler calls keybindingService.softDispatch and only defers the keystroke to VS Code's command dispatch (returns false) when the resolved commandId is in commandsToSkipShell or a Meta-key chord; the Agents Window command isn't in DEFAULT_COMMANDS_TO_SKIP_SHELL (terminal.ts ~502-555). I could not fully confirm at runtime (no build/run) exactly how xterm.js's own default handling of an unmapped Ctrl+Shift+A falls through in this specific case, so I'm relying on the reporter's direct account for the observed symptom rather than a full execution trace.
- **no default terminal select-all binding found:** TerminalCommandId.SelectAll's registered keybinding (terminalActions.ts ~1196-1209) has `primary: 0` (no default) except `mac: Cmd+A`; there's no VS Code-shipped Ctrl+Shift+A→select-all binding for terminal on Linux, so the reporter's prior experience may have relied on the key simply reaching the shell/xterm rather than an explicit VS Code command.
