# Issue #312174 — Launch configuration with non-trivial env file hangs

[https://github.com/microsoft/vscode/issues/312174](https://github.com/microsoft/vscode/issues/312174)

## Summary

The current integrated-debug-terminal path still expands every requested environment variable into one shell command, reproducing the reported large-command failure mechanism. This remains an actionable core debug bug and should be routed to the debug area.

## Change summary

Launching an integrated-terminal debug configuration hangs when its env file expands into a sufficiently large environment.

## Best solution

Make integrated-terminal debug launches carry large environments without placing the complete environment in terminal input, while preserving environment changes made by shell startup scripts and terminal reuse behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/api/node/extHostDebugService.ts`, `src/vs/workbench/contrib/debug/node/terminals.ts`, `src/vs/workbench/contrib/debug/test/node/terminals.test.ts`
- **Validation:** Launch a macOS integrated-terminal debug configuration whose env file produces a command longer than 1024 characters in both a fresh and reused debug terminal; both launches must start and receive all variables. Also verify an nvm-managed runtime still resolves and attaches correctly after shell initialization.
- **Behavior:**

  > An integrated-terminal debug launch must start successfully regardless of how many entries its env file contributes. Every requested variable must reach the debuggee in both a newly created terminal and a reused terminal. Shell-startup environment changes, including nvm-selected runtimes and PATH updates, must continue to apply, and small-environment launches must remain unchanged.
- **Trace:**

  > The DAP adapter supplies the resolved environment through `RunInTerminalRequestArguments.env`. In src/vs/workbench/api/node/extHostDebugService.ts, `$runInTerminal` passes that map to `prepareCommand` and sends the complete generated string to the terminal; src/vs/workbench/contrib/debug/node/terminals.ts serializes the map into `/usr/bin/env KEY=value ...` on macOS. https://github.com/microsoft/vscode/issues/198550 contains the same observable first-terminal truncation and warm-terminal success. Commit 6b6da7928db8f9b00ba8c1551e955c068ebaef76 avoided the large command by using terminal creation options, but d748e6abca77fce40746cd10eba7ca09f4d57f81 reverted it because that path regressed shell-managed environments as tracked by https://github.com/microsoft/vscode/issues/209693. Preserve terminal reuse, shell integration, startup-script PATH changes, and non-integrated terminal behavior; the uncertainty begins at the environment precedence contract for a fresh shell.
- **Open decisions:**
  - For a fresh integrated debug terminal, should adapter-provided variables override the environment after shell startup scripts run, while retaining all shell-added variables, or should they define the terminal's initial environment before those scripts run?
