# Issue #245385 — C# language server doesn't start on MacOS 11

[https://github.com/microsoft/vscode/issues/245385](https://github.com/microsoft/vscode/issues/245385)

## Summary

The failure comes from a macOS 12-targeted .NET host binary installed and launched by the external .NET Runtime/C# extension, not from VS Code core. This should be closed here as caused by an extension and reported to the extension owner.

## Change summary

Restore C# language-server startup on macOS 11 by providing a compatible .NET host runtime.

## Best solution

The .NET Runtime extension should either distribute a hostfxr build compatible with its supported macOS versions or clearly enforce and communicate a newer minimum version in https://github.com/dotnet/vscode-dotnet-runtime.

## Evidence

- **extension-owned binary:** The diagnostic identifies `globalStorage/ms-dotnettools.vscode-dotnet-runtime/.dotnet/9.0.3~arm64/host/fxr/9.0.3/libhostfxr.dylib`, which is installed by the external `ms-dotnettools.vscode-dotnet-runtime` extension rather than shipped by VS Code core.
- **platform incompatibility:** The dynamic loader reports that `libhostfxr.dylib` was built for macOS 12.0 and cannot resolve the required libc++ symbol on macOS 11.7.10.
- **confirmed persistence:** The reporter confirmed the same extension-runtime failure after updating from VS Code 1.98.2 to 1.99, which indicates that changing the VS Code version did not address the incompatible extension binary.
- **owning tracker:** The runtime extension is maintained at https://github.com/dotnet/vscode-dotnet-runtime.
