# Issue #259983 — Maximum call stack size exceeded

[https://github.com/microsoft/vscode/issues/259983](https://github.com/microsoft/vscode/issues/259983)

## Summary

Still present on main: the notebook cell list view can enter infinite recursion when `updateElementHeight` triggers `_rerender` which calls `setScrollTop`, re-entering the scroll/layout cycle without a recursion guard. No fix commit references this issue.

## Change summary

Notebook cell list view hits maximum call stack size due to unbounded recursion between updateElementHeight, _rerender, and setScrollTop.

## Best solution

Add a re-entrancy guard in `notebookCellListView.ts` (or in the base `listView.ts` `_rerender` path) to break the cycle when `updateElementHeight` triggers a scroll dimension change that re-enters the render pipeline. The `_renderingStack` counter is already tracked but not used as a guard against this specific recursion path.
