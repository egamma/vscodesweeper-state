# Issue #204173 — VSCode .js Debugger Does Not Respect Glob Negations

[https://github.com/microsoft/vscode/issues/204173](https://github.com/microsoft/vscode/issues/204173)

## Summary

Keep open: a merged JavaScript debugger fix directly addresses the zero-directory glob case behind this report, but the debugger version bundled by current main does not contain it. The supplied configuration is sufficient to retest after adoption; the complete Next.js stepping behavior has not been verified.

## Change summary

Honor skipFiles negations for webpack-internal URLs when a middle ** matches zero directories.

Adopt a JavaScript debugger version containing the fix from https://github.com/microsoft/vscode-js-debug/pull/2424, then verify that the reported app/packages exceptions permit normal stepping, including in event handlers, while other webpack internals remain skipped.

## Evidence

- **Reporter trigger and follow-up:** https://github.com/microsoft/vscode/issues/204173 supplies an Edge attach configuration where **/webpack-internal:///** skips scripts but !**/webpack-internal:///**/packages/** fails to exempt webpack-internal:///packages/... . The reporter confirmed persistence on 1.86.0 and the February 2024 nightly, particularly inside event handlers, and supplied requested logs privately.
- **Concrete upstream behavior change:** https://github.com/microsoft/vscode-js-debug/commit/dc7f1b280f77746dec8d72d133374ad744a45134 changes src/adapter/scriptSkipper/simpleGlobToRe.ts at the middle-** branch from regexParts.push('.*/') to regexParts.push('(.*/)?'). This lets the negated pattern match packages directly after webpack-internal:/// rather than requiring another slash. Its tests cover the equivalent positive-plus-negation case where foo/bar/baz must be exempted by !**/foo/**/bar/**.
- **Fix merged but not adopted:** https://github.com/microsoft/vscode-js-debug/pull/2424 merged on 2026-10-05. Current checkout product.json pins ms-vscode.js-debug to 1.140.0; https://github.com/microsoft/vscode-js-debug/blob/v1.140.0/src/adapter/scriptSkipper/simpleGlobToRe.ts still emits '.*/'. GitHub's comparison reports v1.140.0 one commit behind dc7f1b280f77746dec8d72d133374ad744a45134, so the merged fix does not establish resolution in this checkout.
- **Affected bundled call path:** https://github.com/microsoft/vscode-js-debug/blob/v1.140.0/src/adapter/scriptSkipper/implementation.ts uses simpleGlobsToRe in ScriptSkipper._regexForAuthored, tests those expressions in _testSkipAuthored, and passes them to Debugger.setBlackboxPatterns. The old compiler therefore remains active on the reported browser-debugging path.
- **Suggested duplicate ruled out:** The maintainer suggested https://github.com/microsoft/vscode/issues/203408, but that issue concerns at-signs in scoped-package paths and is closed; the reporter also explicitly reported that the suggested nightly did not resolve this case. It is not a valid open canonical.
- **Canonical search and verification limits:** Open-issue searches for skipFiles negation, skipFiles webpack, and skipFiles glob found no other verified canonical owning this defect. Inspection was read-only; no debugger session or tests were executed, so event-handler and source-map behavior remains unverified.
