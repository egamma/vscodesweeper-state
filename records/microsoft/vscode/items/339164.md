# Issue #339164 — Support expiring GitHub tokens with the offline_access scope

[https://github.com/microsoft/vscode/issues/339164](https://github.com/microsoft/vscode/issues/339164)

## Summary

Brand-new, team-authored feature request (author TylerLeonhardt, MEMBER) describing real missing functionality: persisted GitHub OAuth sessions never expire or renew today, unlike Entra-brokered ones. Clearly keep-open — team-authored and parked in the Backlog holding bin, with no basis for any close.

## Change summary

Extend GitHub Authentication's token renewal (currently only for Microsoft Entra-brokered sessions) to also cover ordinary GitHub OAuth sessions, by requesting the `offline_access` scope to get an expiring access token plus a refresh token.

## Best solution

Design and implement refresh-token support for persisted GitHub sessions: request `offline_access` during the OAuth flow, store the refresh token alongside the session, give persisted sessions their own expiry, and extend `stillGood`/the renewal path in github.ts to branch between Entra-renewal and refresh-token-renewal.

## Plan brief

- **Likely files:** `extensions/github-authentication/src/github.ts`, `extensions/github-authentication/src/githubServer.ts`
- **Validation:** A test exercising `stillGood`/`renew` for a persisted (non-Entra) session confirming it renews via a stored refresh token before expiry and is evicted only when the refresh token itself is invalid.
- **Behavior:**

  > A GitHub session signed in with the `offline_access` scope should expose a finite `expiresAfter`, be automatically renewed via its refresh token before expiry (mirroring how Entra-brokered sessions renew today), and only be dropped/reported as removed when the refresh token itself fails. Sessions without `offline_access` keep today's non-expiring behavior unchanged.
- **Trace:**

  > `stillGood()` in extensions/github-authentication/src/github.ts (~line 485) currently treats any session absent from `this._transientSessions` as non-expiring, because only Entra-brokered logins populate that map via `storeTransientSession` (lines 468, 619, 888). Persisted OAuth sessions have no expiry or refresh-token storage at all; `githubServer.ts`'s `login()` has no scope/refresh-token exchange logic. The boundary: do not change Entra-session renewal semantics or `renewNow`'s existing branch for those sessions — add a parallel renewal path for refresh-token-based sessions. See https://github.com/microsoft/vscode/issues/335183 and https://github.com/microsoft/vscode/issues/335184 for the Entra-side precedent this mirrors.
- **Open decisions:**
  - Is GitHub's OAuth app (client ID used by this extension) already configured to issue refresh tokens for `offline_access`, or does that require a separate GitHub-side app change first?
  - Where and in what format should the refresh token be persisted (same secret-storage entry as the session, or a separate keychain record), given it is a new category of secret for this extension?
  - Should `offline_access` be requested for all new sign-ins by default, or only opt-in/behind a setting, given it changes the scope set requested from GitHub?

## Evidence

- **current renewal code:** extensions/github-authentication/src/github.ts `stillGood()` (~line 485) only renews entries found in `this._transientSessions`, which are populated solely by Entra-brokered flows (`storeTransientSession` calls at lines 468, 619, 888); the function's own doc comment states 'Only transient sessions can go stale, and every one of those was brokered through Microsoft... When persisted tokens start expiring too, they will need an expiry of their own here and renewNow will need to branch on how a given session renews' — matching the issue's description exactly.
- **no offline_access handling:** `rg offline_access extensions/github-authentication/src` finds no implementation; githubServer.ts's `login()`/`loginWithMicrosoft()` scope handling has no refresh-token exchange path for ordinary GitHub OAuth logins.
- **related issues:** Issue references https://github.com/microsoft/vscode/issues/335183 and https://github.com/microsoft/vscode/issues/335184 (the prior Entra-expiry work) as the pattern to extend.
