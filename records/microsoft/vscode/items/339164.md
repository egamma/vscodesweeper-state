# Issue #339164 — Support expiring GitHub tokens with the offline_access scope

[https://github.com/microsoft/vscode/issues/339164](https://github.com/microsoft/vscode/issues/339164)

## Summary

Ordinary GitHub OAuth sessions still lack refresh-token persistence and expiry-aware renewal on current main. Keep this maintainer-authored Backlog request open; the existing Entra renewal implementation does not cover it.

## Change summary

Support expiring ordinary GitHub OAuth sessions by requesting offline_access, persisting refresh credentials, reporting remaining lifetime, and silently renewing access tokens.

## Best solution

Extend the built-in GitHub Authentication provider's OAuth session lifecycle to retain refresh credentials privately and return renewable, expiry-aware sessions. Preserve existing Entra renewal and compatibility with sessions whose expiry is unknown.

Retain the existing Entra and unknown-expiry session checks; none were executed in this read-only review.
- **Behavior:**

  > Ordinary GitHub OAuth sign-in requesting offline_access should produce a session with a usable access token and its positive remaining lifetime in milliseconds. Refresh credentials must survive reload without being exposed through AuthenticationSession. Reads near expiry should silently obtain a replacement access token while retaining session identity, and transient renewal failures should not discard a still-valid token. Existing Entra-brokered sessions and legacy sessions with unknown expiry must retain their current behavior.
- **Trace:**

  > GitHubServer.login in extensions/github-authentication/src/githubServer.ts obtains a string from IFlow.trigger in flows.ts and returns only token plus authorizationServer; the device-code path drops all response fields except access_token. GitHubSessionEngine.createSession persists the resulting AuthenticationSession, while SessionData and readSessions in github.ts carry neither refresh credentials nor expiry. stillGood selects only transient sessions for renewal, and renewNow exclusively renews through Microsoft. The persisted sessions are shared between windows through Keychain, whereas the renewal-coalescing map is process-local, so refresh-token rotation and concurrent persistence need investigation. Preserve Entra account binding, authorization-server provenance, legacy sessions, and sign-out semantics. The related lifetime contract is tracked separately at https://github.com/microsoft/vscode/issues/335184; the completed Entra-only work at https://github.com/microsoft/vscode/issues/335183 does not implement this request.
