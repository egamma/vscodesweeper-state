## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/276691 reports Source Control push/pull against a YubiKey-authenticated SSH remote failing with HTTP 500 and 'Permission denied (keyboard-interactive)', while the integrated terminal prompts successfully. The reporter's January 2 follow-up describes a terminal task running 'git fetch --dry-run' as a workaround, explicitly not a solution to GUI authentication.
- **Current source defect:** extensions/git/src/askpass.ts:118-159, Askpass.handleSSHAskpass, handles passphrase requests but treats every other request as a host-authenticity confirmation. A short keyboard-interactive prompt such as 'OTP:' leaves argv[6] undefined, so argv[6].replace throws; longer challenges still enter the wrong yes/no UI instead of an authentication-input path.
- **Failure propagation and terminal distinction:** extensions/git/src/ssh-askpass.sh forwards SSH prompt arguments to askpass-main.ts. extensions/git/src/ipc/ipcServer.ts:99-105 converts rejected handlers into HTTP 500, and extensions/git/src/askpass-main.ts prints 'Missing or invalid credentials.' on IPC failure. Askpass configures SSH_ASKPASS_REQUIRE=force for Git operations, whereas getTerminalEnv supplies only the HTTPS askpass environment, explaining why terminal SSH authentication can behave differently. This is a source trace, not an executed hardware reproduction.
- **Open linked implementation:** https://github.com/microsoft/vscode/pull/299382 is verified OPEN with mergedAt=null and a closing reference to this issue. Its diff separates host-authenticity handling from other SSH challenges and introduces keyboard-interactive input and security-key presence handling. It is an implementation candidate, not a landed fix.
