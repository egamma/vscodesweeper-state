# Issue #309209 — Add Collapsible Copilot Chat Input (Thin Status Bar Mode)

[https://github.com/microsoft/vscode/issues/309209](https://github.com/microsoft/vscode/issues/309209)

## Summary

A real chat-layout gap remains: current main can hide the composer for read-only sessions, but offers no user-controlled compact mode for active chats. Route this to the chat-input area and keep it under discussion because the collapsed row's content, persistence, and focus behavior need product decisions.

## Change summary

Allow the Copilot Chat composer to collapse into a thin, non-focus-stealing status row that preserves transcript space and essential actions.

## Best solution

Design a keyboard-accessible compact state for the active chat composer that preserves drafts, exposes an unambiguous expand action, and does not interfere with read-only-session behavior. The chat team should first settle what the compact row communicates and when it expands automatically.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/browser/actions/chatActions.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`
- **Validation:** Add ChatWidget tests covering collapse/expand layout, draft preservation, and focus behavior, then run the targeted ChatWidget unit-test suite; also verify the toggle and its expanded state are keyboard- and screen-reader-accessible.
- **Behavior:**

  > An active chat's input area can be collapsed to reclaim vertical transcript space and expanded again through both keyboard and visible controls. Collapsing preserves the current draft and attachments, does not capture focus unexpectedly, and leaves a clearly labeled compact row with the agreed status information and essential actions. Existing expanded-composer and read-only-session behavior remains unchanged.
- **Trace:**

  > ChatWidget.setReadOnly() in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts is currently the sole caller of setInputVisible(), so composer visibility is tied to read-only state rather than user preference. ChatInputPart.render() in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts owns the editor, toolbar, status, attachment, and notification surfaces that would participate in a compact presentation. The existing chat-input-hidden CSS removes most children and may retain persistent status controls, but it does not provide an interactive compact state. Chat actions and accessibility help currently expose input focus but no collapse operation. Preserve read-only hiding, drafts, attachments, pending confirmations, response collapsing, and non-chat input layouts; https://github.com/microsoft/vscode/issues/309514 is supporting demand, not a canonical replacement.
- **Open decisions:**
  - Should the compact row show the latest user message, the latest system status, or only a neutral Chat Input label and activity state?
  - Is the collapsed state remembered per chat, per workspace, or reset when the chat or window is reopened?
  - Which actions should automatically expand the composer, particularly Focus Chat Input, attaching context, and a session requesting user input?
