# Issue #284891 — VS Code PowerShell extension fails to detect corrupted UTF‑8 Chinese strings, causing silent syntax corruption

[https://github.com/microsoft/vscode/issues/284891](https://github.com/microsoft/vscode/issues/284891)

## Summary

The diagnostics the reporter expects (syntax error detection for unterminated strings, invalid try/catch, encoding mismatch warnings) come from the external PowerShell extension (ms-vscode.powershell, maintained at PowerShell/vscode-powershell), not VS Code core. The built-in `extensions/powershell` only provides TextMate grammars. VS Code core uses the standard TextDecoder API which handles invalid UTF-8 per spec (replacing bad sequences with U+FFFD). The report lacks version info, a concrete reproduction file, and conflates OneDrive sync corruption with editor behavior.

## Change summary

Request for VS Code to detect corrupted UTF-8 byte sequences in PowerShell files and surface syntax errors caused by encoding issues.

## Best solution

The syntax diagnostics (unterminated strings, invalid try/catch) belong to the PowerShell language server extension (ms-vscode.powershell). UTF-8 validation requests for that extension should be filed at https://github.com/PowerShell/vscode-powershell. The underlying file corruption appears to be caused by OneDrive sync or an encoding mismatch when saving without BOM and reading with system codepage — not a VS Code core defect.
