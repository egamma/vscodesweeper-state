# Issue #240489 — SCM Graph - add an action to manually set the merge base

[https://github.com/microsoft/vscode/issues/240489](https://github.com/microsoft/vscode/issues/240489)

## Summary

Keep open: the area maintainer identified a missing SCM Graph gesture for correcting the inferred base branch. Current source still offers manual graph filtering rather than a base-setting action, and the verified related issues do not own this same request.

## Change summary

Provide an SCM Graph action to choose the base branch when automatic inference selects a topic branch's own remote instead of its intended integration branch.

## Best solution

Provide a discoverable base-selection gesture in the built-in Git SCM Graph that makes Auto display the intended comparison branch without terminal configuration or switching branches. Preserve existing inference and manual filtering, and settle whether the selection changes shared Git base metadata or only the graph.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/commands.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/historyProvider.ts`, `src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts`
- **Validation:** In a repository with origin/master and a colleague's origin/demo, check out demo with its inferred base set to origin/demo. Use the planned gesture to select origin/master and verify that Auto immediately shows demo, origin/demo and origin/master without switching branches. Verify cancellation leaves the selection unchanged, switching branches preserves each branch's intended behavior, and reload honors the agreed persistence contract.
- **Behavior:**

  > When a user checks out a colleague's topic branch, Auto can omit the integration branch because the inferred base equals the topic branch's own remote. The user should be able to choose the intended base through the SCM Graph UI without running git config or replacing Auto with a fixed reference filter. The graph should update immediately after the choice, while cancellation should change nothing. Verify branch switching and reload against the persistence contract chosen during planning.
- **Trace:**

  > Repository.getBranchBase in extensions/git/src/repository.ts resolves a saved remote base, a reflog-derived remote source, or the default remote branch, and persists inferred choices in branch.<name>.vscode-merge-base. GitHistoryProvider.resolveHEADMergeBase consumes this result; onDidRunWriteOperation currently recomputes the base only when the branch name changes. SCMHistoryViewModel._resolveHistoryItemFilter in src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts consumes current, remote and base references for Auto, while HistoryItemRefPicker controls a separate repository-level display filter. The proposed history-provider contract exposes currentHistoryItemBaseRef as readonly in src/vscode-dts/vscode.proposed.scmHistoryProvider.d.ts. Preserve automatic inference, upstream configuration and existing explicit filtering; the planning boundary is whether this gesture changes the shared per-branch base or introduces graph-only behavior. The maintainer's direction is recorded at https://github.com/microsoft/vscode/issues/240489#issuecomment-2732894346; the related inference request at https://github.com/microsoft/vscode/issues/235391 is distinct.
- **Open decisions:**
  - Should the graph's base selection persist by changing branch.<name>.vscode-merge-base, thereby affecting other consumers of that base metadata, or should it be a graph-only override that leaves shared Git metadata unchanged?
