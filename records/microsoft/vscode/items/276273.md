# Issue #276273 — Publish Branch dialog closes immediately when connected to WSL and Windows proxy is set

[https://github.com/microsoft/vscode/issues/276273](https://github.com/microsoft/vscode/issues/276273)

## Summary

The publish flow still silently disposes its dialog when the initial GitHub request fails, matching the reported missing-error behavior. Keep this with the Git owner for error handling; the Windows-to-WSL proxy inheritance mechanism remains unverified.

## Change summary

Publish Branch should report connection failures instead of immediately dismissing its dialog without explanation.

## Best solution

Make genuine authentication and initial GitHub request failures visible in the built-in GitHub publishing flow while preserving quiet handling of deliberate sign-in cancellation. Address the missing error independently of whether the Windows proxy is reachable from WSL.

## Plan brief

- **Likely files:** `extensions/github/src/publish.ts`, `extensions/github/src/auth.ts`, `extensions/github/src/test/github.test.ts`
- **Validation:** Establish a regression check that rejects the initial GitHub user lookup with ECONNREFUSED and verifies a visible error rather than silent dismissal. Also check deliberate sign-in cancellation and successful publishing remain unchanged. Manual acceptance: connect to WSL with autoProxy=false and an unreachable Windows proxy, invoke Publish Branch on a repository without remotes, and verify the failure is explained; do not treat source inspection as validation of proxy inheritance.
- **Behavior:**

  > Publishing a repository without remotes currently opens a dialog that disappears without explanation when the initial GitHub request fails. A genuine connection or authentication failure must produce a clear, user-visible explanation rather than appearing to be cancellation. Deliberately cancelling sign-in should remain quiet, and successful private/public publishing should retain its existing behavior. Acceptance must distinguish a rejected initial user lookup, deliberate cancellation, and successful publishing.
- **Trace:**

  > CommandCenter.publish in extensions/git/src/commands.ts delegates repositories without remotes to GithubRemoteSourcePublisher in extensions/github/src/remoteSourcePublisher.ts, which calls publishRepository in extensions/github/src/publish.ts. publishRepository shows the quick pick before awaiting getOctokit and users.getAuthenticated, then treats every exception from both operations as sign-in cancellation and disposes the picker. This conclusively explains silent dismissal for a rejected request, but does not establish why Windows proxy settings reach the WSL request. getOctokit and getSession live in extensions/github/src/auth.ts; the current tests in extensions/github/src/test/github.test.ts do not exercise this publishing path. Keep the scope on publishing error visibility and cancellation semantics, not proxy forwarding, Git push behavior, or empty-repository handling. The older related discussion at https://github.com/microsoft/vscode/issues/245971#issuecomment-2791874110 identifies the same catch; the session should first establish a runnable failure/cancellation regression check.
