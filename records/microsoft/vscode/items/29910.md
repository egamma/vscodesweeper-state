# Issue #29910 — CLI proxy support

[https://github.com/microsoft/vscode/issues/29910](https://github.com/microsoft/vscode/issues/29910)

## Summary

Keep open: the CLI supports explicitly configured proxies, but still lacks the desktop application's full proxy integration. Current documentation explicitly identifies this issue as tracking that remaining gap; the reporter's TEMP correction resolved their installation problem, not the broader request.

## Change summary

Support CLI extension installation behind corporate proxies without requiring separate legacy proxy configuration.

## Best solution

Bring CLI Marketplace requests and extension downloads into supported parity with desktop proxy behavior, including system proxy discovery and an appropriate unattended authentication contract. Preserve this issue as the CLI-specific tracking item rather than folding it into extension-host networking.

- **Likely files:** `src/vs/code/node/cliProcessMain.ts`, `src/vs/platform/request/node/requestService.ts`, `src/vs/platform/request/node/proxy.ts`, `src/vs/platform/extensionManagement/common/extensionGalleryService.ts`

Cover explicit http.proxy and HTTP_PROXY/HTTPS_PROXY configurations as regressions, and verify authenticated-proxy behavior follows the agreed unattended contract without hanging.
- **Behavior:**

  > CLI extension installation should work in supported corporate-proxy environments without requiring users to maintain a separate proxy configuration solely for the CLI. Successful Marketplace discovery must be followed by successful extension download and installation. Existing explicit proxy settings and environment-variable support must remain usable. Authentication requirements must have a defined unattended outcome rather than leaving automation stuck.
- **Trace:**

  > CLIProcessMain in src/vs/code/node/cliProcessMain.ts initializes user configuration and supplies the Node RequestService to extension-management services. ExtensionGalleryService.queryRawGalleryExtensions() in src/vs/platform/extensionManagement/common/extensionGalleryService.ts uses that service for Marketplace requests. RequestService in src/vs/platform/request/node/requestService.ts reads legacy proxy settings and calls getProxyAgent() in src/vs/platform/request/node/proxy.ts, which chooses an explicit proxy or proxy environment variables rather than resolving OS/PAC configuration. Node resolveProxy() and lookupAuthorization() are unimplemented, although a Kerberos helper exists; the required authentication integration remains to be designed. The official network documentation names https://github.com/microsoft/vscode/issues/29910 as the outstanding CLI limitation. Preserve existing explicit configuration behavior and keep extension-host networking tracked separately in https://github.com/microsoft/vscode/issues/12588; the Electron credential-dialog implementation in https://github.com/microsoft/vscode/pull/22369 does not settle headless CLI behavior.
- **Open decisions:**
  - Which desktop proxy capabilities must be supported by the standalone CLI: OS proxy discovery, PAC resolution, and which authentication methods?
  - When an authenticated proxy requires credentials unavailable to an unattended CLI invocation, what supported credential mechanism and user-visible failure behavior should the CLI provide?
