# Issue #325635 — `chat.tools.terminal.autoApprove` does not work for `npm exec -- ...` commands

[https://github.com/microsoft/vscode/issues/325635](https://github.com/microsoft/vscode/issues/325635)

## Summary

Confirmed bug: the tree-sitter PowerShell grammar fails to parse `npm exec -- tsc ...` into any `(command)` node, so `extractSubCommands` returns an empty array and auto-approval is unconditionally blocked. The `--` argument separator is the likely grammar-level trigger. No fix on current main.

## Change summary

Terminal auto-approve rules are never evaluated for `npm exec -- ...` commands in PowerShell because the tree-sitter parser returns no sub-commands for that syntax.

## Best solution

Add a workaround in `TreeSitterCommandParser.extractSubCommands` (similar to the existing `maskPwshFlagEquals` workaround for `--flag=value`) that handles the `--` argument separator pattern in PowerShell so that `npm exec -- tsc --noEmit` is recognized as a command. Alternatively, fall back to treating the full trimmed command line as a single sub-command when the grammar returns nothing for a non-empty input — but that changes the security posture and needs careful consideration. The existing test suite in `treeSitterCommandParser.test.ts` should gain a PowerShell test case for `npm exec -- tsc --noEmit --pretty false`.
