# Issue #336425 — Observe VS Code trusted folders in Copilot

[https://github.com/microsoft/vscode/issues/336425](https://github.com/microsoft/vscode/issues/336425)

## Summary

Fresh, well-researched feature request (same day, contributor-authored) proposing that Copilot's agent runtime observe VS Code's workspace trust state (multi-root trusted folders) instead of only supporting a single session-scoped trust attestation; needs design/contract work across both repos, so it should stay open for engineering discussion.

## Change summary

Extend the Copilot SDK session-create/event contract so VS Code can pass its full set of trusted workspace folders and so the runtime can request trust escalation, rather than only supporting a single 'session' trust attestation for one working directory.

## Best solution

Track as a cross-repo design item: needs a session-scoped host trust snapshot/set and a typed 'trust required' event in the Copilot agent runtime contract (see linked github/copilot-agent-runtime issues), plus corresponding VS Code-side wiring once that contract exists — not something to auto-fix or close today.
