# Issue #336425 — Observe VS Code trusted folders in Copilot

[https://github.com/microsoft/vscode/issues/336425](https://github.com/microsoft/vscode/issues/336425)

## Summary

Keep open: current main does not propagate VS Code folder trust into Copilot SDK sessions, and the missing multi-root trust snapshot and runtime trust-request event require upstream contract work. This also concerns a security boundary and is team-authored, so it must remain open for human ownership.

## Change summary

Integrate VS Code Workspace Trust with Copilot sessions for multi-root trust decisions and runtime-initiated trust requests.

## Best solution

Extend the Copilot agent runtime contract with session-scoped trusted-folder attestations and a typed trust-required request, then have VS Code answer from its existing resource-trust APIs without persisting duplicate trust state in Copilot configuration.
