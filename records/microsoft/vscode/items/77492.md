# Issue #77492 — If pasting over text containing TextEditorDecorations, they are retained

[https://github.com/microsoft/vscode/issues/77492](https://github.com/microsoft/vscode/issues/77492)

## Summary

A real extension API gap remains: the editor model can collapse decorations fully covered by replacement edits, but `TextEditorDecorationType` cannot request that behavior. This team-authored feature request has no referenced implementing commit or verified duplicate, so it should remain open.

## Change summary

Allow text editor decorations to be cleared or truncated instead of being inherited by replacement text.

## Best solution

Define the public replacement semantics for extension-owned decorations, preferably exposing the editor model's existing opt-in collapse behavior while preserving the current default for extensions that rely on tracked ranges.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/test/browser/services/decorationRenderOptions.test.ts`, `src/vs/editor/test/common/model/modelDecorations.test.ts`
- **Validation:** Add a targeted decoration API test that registers the chosen replacement behavior, replaces a range encompassing the decoration, and asserts the resulting range collapses rather than covering inserted text; run the Decoration Render Options and model decorations unit suites.
- **Behavior:**

  > Replacing all text covered by a text editor decoration must not apply that decoration to the newly inserted text when the selected replacement behavior requests collapse. Partial replacements should retain only the portion justified by the remaining tracked text. Existing extensions that do not select the new behavior must retain their current range-tracking semantics.
- **Trace:**

  > The public `DecorationRenderOptions` contract in src/vscode-dts/vscode.d.ts exposes edge stickiness through `rangeBehavior` but no full-replacement behavior. `DecorationRenderOptions.from` in src/vs/workbench/api/common/extHostTypeConverters.ts and `DecorationTypeOptionsProvider` in src/vs/editor/browser/services/abstractCodeEditorService.ts therefore cannot propagate such a choice. The underlying model already supports it: `nodeAcceptEdit` in src/vs/editor/common/model/intervalTree.ts checks internal `collapseOnReplaceEdit`, with coverage in src/vs/editor/test/common/model/modelDecorations.test.ts and precedent in https://github.com/microsoft/vscode/commit/eadda7cd27a41d7c57fef3d3ce3605cef517e6a4. Preserve existing decoration defaults and unrelated semantic-token refresh behavior; the uncertainty begins at the public contract's default semantics.
- **Open decisions:**
  - Should decorations collapse on encompassing replacement edits by default, changing existing extension behavior, or only when an extension explicitly opts into the behavior?

## Evidence

- **public API gap:** src/vscode-dts/vscode.d.ts exposes only `DecorationRenderOptions.rangeBehavior`, which controls edits at range edges; it has no option for a replacement that encompasses the entire decoration.
- **existing internal capability:** src/vs/editor/common/model.ts defines internal `collapseOnReplaceEdit`; src/vs/editor/common/model/intervalTree.ts applies it in `nodeAcceptEdit` when an edit encompasses the complete decoration range.
- **internal precedent:** https://github.com/microsoft/vscode/commit/eadda7cd27a41d7c57fef3d3ce3605cef517e6a4 introduced `collapseOnReplaceEdit` for https://github.com/microsoft/vscode/issues/41492. The current regression test is in src/vs/editor/test/common/model/modelDecorations.test.ts, but the commit predates and does not reference this issue.
- **missing API plumbing:** src/vs/workbench/api/common/extHostTypeConverters.ts converts `rangeBehavior`, while src/vs/editor/common/editorCommon.ts and `DecorationTypeOptionsProvider` in src/vs/editor/browser/services/abstractCodeEditorService.ts do not carry replacement-collapse behavior into extension decoration options.
