# Issue #331572 — chat sessions are gone

[https://github.com/microsoft/vscode/issues/331572](https://github.com/microsoft/vscode/issues/331572)

## Summary

Traced a real, currently-unfixed defect: when a window transitions between single-folder and multi-root workspace storage, ChatSessionStore copies the chat session .jsonl transcripts to the new storage root but never migrates or rebuilds the chat.ChatSessionStore.index entries for the new workspace scope, so the session list silently freezes at the transition point even though the files are intact on disk.

## Change summary

Two days (and, per a follow-up comment, several more days) of chat sessions disappear from the Chat Sessions list after a workspace/folder change or restart, even though the underlying transcript files still exist.

## Best solution

In `migrateSessionsToNewWorkspace` (src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts), populate index entries for the migrated session files (or reconcile the index against the `chatSessions/` directory on startup) instead of just clearing `indexCache` and flushing an effectively empty index for the new workspace storage scope.

## Evidence

- **index scoped per-workspace:** `getIndexStorageScope()` (line 432) keys the `chat.ChatSessionStore.index` storage entry by `StorageScope.WORKSPACE` (or `APPLICATION` for empty windows tied to a fixed 'no-workspace' key), so after a transition the freshly-cleared, re-read index for the *new* workspace id has no entries pointing at the just-copied files.
- **no startup reconciliation:** `migrateDataIfNeeded`/`migrate` (lines 610-630) only migrate from the old storage-service format when no index exists at all; nothing reconciles an existing (but incomplete) index against orphaned files in `chatSessions/` on load.
