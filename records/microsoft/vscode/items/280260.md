# Issue #280260 — Copilot Agents Don't Install Dependencies via Proper Commands

[https://github.com/microsoft/vscode/issues/280260](https://github.com/microsoft/vscode/issues/280260)

## Summary

A real gap remains on current main: dependency-management guidance is inconsistent across agent prompts, and the agent's workspace context can omit the lockfiles needed to identify the active package manager. The older Copilot report was explicitly closed in favor of this issue, making #280260 the canonical thread.

## Change summary

Prefer project-appropriate dependency-management commands over direct manifest edits, using the existing terminal approval flow.

## Best solution

Give every agent model shared guidance to detect the project's package manager and run its add/install command through the existing terminal permission flow, updating manifests directly only when explicitly requested or when no supported command workflow exists.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/prompts/node/agent/defaultAgentInstructions.tsx`, `extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx`, `extensions/copilot/src/extension/context/node/resolvers/promptWorkspaceLabels.ts`, `extensions/copilot/src/extension/prompts/node/agent/test/agentPrompt.spec.tsx`
- **Validation:** Add prompt-rendering tests covering all registered agent model families and representative npm, yarn, Cargo, and Python workspaces, then add a simulation asserting that an add-dependency request invokes the detected package manager through the terminal rather than editing its manifest directly.
- **Behavior:**

  > When asked to add or install a dependency, the agent identifies the package manager already used by the project and invokes that manager's add/install command. The command uses the existing terminal permission flow so the user's configured approval policy remains authoritative. The agent does not directly edit the dependency manifest unless the user explicitly asks for that or no command-based workflow is available. Existing non-dependency file edits and explicit manifest-edit requests remain unchanged.
- **Trace:**

  > The shared DefaultAgentPrompt in extensions/copilot/src/extension/prompts/node/agent/defaultAgentInstructions.tsx lacks dependency-management guidance, while only some model-specific prompts mention package managers or generated package.json files. GlobalAgentContext in extensions/copilot/src/extension/prompts/node/agent/agentPrompt.tsx supplies a workspace tree, but shouldAlwaysIgnoreFile in extensions/copilot/src/platform/workspaceChunkSearch/node/workspaceFileIndex.ts removes yarn.lock and package-lock.json from that view. BasicPromptWorkspaceLabels in extensions/copilot/src/extension/context/node/resolvers/promptWorkspaceLabels.ts detects yarn.lock, but its ProjectLabels consumer is used by panel and inline prompts rather than the agent prompt. The older https://github.com/microsoft/vscode-copilot/issues/13553 diagnosed missing lockfile context and was closed in favor of this issue. Keep the existing terminal approval system and explicit-manifest editing behavior unchanged; the plan should unify package-manager context and guidance without introducing a separate installer UI.
