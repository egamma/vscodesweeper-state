# Issue #335866 — [typescript] Coloring is broken for type assertion functions with multi-line generic return types

[https://github.com/microsoft/vscode/issues/335866](https://github.com/microsoft/vscode/issues/335866)

## Summary

Well-documented TextMate grammar bug: multi-line generic type-predicate return types (e.g. `r is\n  Required<A>`) break TypeScript syntax highlighting for the rest of the file. Reporter confirmed it across three independent environments (local VS Code, vscode.dev, StackBlitz) with screenshots, so this is a credible, real defect, not a thin report — but it only carries `triage-needed`/`stale` and no area label, so routing it is the right move.

## Change summary

TypeScript syntax coloring breaks for the remainder of a file when a method's type-predicate return type (`r is X`) is generic and wraps onto a second line.

## Best solution

Fix the return-type / type-predicate-operator TextMate rules in TypeScript.tmLanguage.json (ideally upstream in microsoft/TypeScript-TmLanguage, then re-synced via `update-grammars`) so a multi-line generic type predicate doesn't leave the return-type scope unterminated; add a colorize-test fixture (extensions/vscode-colorize-tests/test/colorize-fixtures) covering this exact case to lock in the fix.

## Evidence

- **reporter repro:** Reporter reproduced the broken coloring on VS Code 1.137.0 local, vscode.dev, and StackBlitz with matching screenshots, and isolated it to: multi-line + generic + type-predicate return type together (single-line or non-generic works fine).
- **grammar source:** extensions/typescript-basics/syntaxes/TypeScript.tmLanguage.json is vendored from https://github.com/microsoft/TypeScript-TmLanguage (see cgmanifest.json), regenerated via `node ./build/update-grammars.mjs`; the relevant rules are `return-type` (line ~3972), `return-type-core`, and `type-predicate-operator` (line ~4586) in that file.
- **plausible mechanism:** The `return-type` begin/end rule's end pattern (`(?<![:|&])(?=$|^|[{};,]|//)`) is evaluated per-line against the tokenizer's line-by-line state machine; when the predicate's generic argument (`Required<A>`) spans onto the next line, the scope likely fails to close on the expected line and 'leaks' into subsequent lines — consistent with the reporter's observation that coloring stays broken until end of file.
- **validation infra exists:** extensions/vscode-colorize-tests/test/colorize-fixtures/ already has per-issue fixtures (e.g. test-issue5431.ts) with matching expected token dumps in colorize-results/ and colorize-tree-sitter-results/, giving a concrete way to pin down and verify a fix.
