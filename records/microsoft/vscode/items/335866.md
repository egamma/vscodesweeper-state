# Issue #335866 — [typescript] Coloring is broken for type assertion functions with multi-line generic return types

[https://github.com/microsoft/vscode/issues/335866](https://github.com/microsoft/vscode/issues/335866)

## Summary

Reproducible TextMate-grammar defect: the `return-type` rule's end pattern in the vendored TypeScript grammar terminates at end-of-line unless preceded by `:`, `|`, or `&`, so a type-predicate return type that wraps after the `is` keyword (e.g. `r is\n  Required<A>`) falls out of `meta.return.type.ts` scope and subsequent tokens (strings, braces) get misclassified.

## Change summary

Syntax highlighting breaks for the rest of a TypeScript file when a type-predicate return type (`x is T`) wraps onto a new line before a generic type.

## Best solution

Fix belongs in the upstream microsoft/TypeScript-TmLanguage grammar (this repo's copy is vendored, per the file's own contributor note) — extend the `return-type` end-pattern's negative lookbehind to also exclude a preceding `is`/`asserts` keyword boundary so the region continues onto the next line, then re-import the updated grammar here.

  > Thanks for the detailed repro. I traced this to the TypeScript grammar's `return-type` rule (extensions/typescript-basics/syntaxes/TypeScript.tmLanguage.json): its end pattern closes the return-type region at end-of-line unless the previous character is `:`, `|`, or `&`. When a type-predicate return type (`x is T`) wraps right after `is`, that exclusion doesn't apply, so the region ends early and the wrapped generic type (and everything after it) falls outside `meta.return.type.ts`, throwing off subsequent coloring. Since this grammar is vendored from https://github.com/microsoft/TypeScript-TmLanguage (see the file's own header), the fix needs to land there first before it can be pulled into VS Code.
