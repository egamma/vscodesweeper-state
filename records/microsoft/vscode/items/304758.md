# Issue #304758 — Feature request: icon field in agent plugin plugin.json

[https://github.com/microsoft/vscode/issues/304758](https://github.com/microsoft/vscode/issues/304758)

## Summary

Plugin-authored branding remains unsupported in the current metadata and list-rendering paths. Keep this accepted On Deck request open, preserving the maintainer's direction to use `logo`; the referenced specification has since changed, so the manifest contract needs clarification before implementation.

## Change summary

Allow agent plugins and marketplace entries to supply custom branding images for plugin discovery and management.

## Best solution

Support optional plugin branding throughout installed-plugin and marketplace presentation, following the maintainer's `logo` direction and preserving existing behavior when branding is absent. Resolve compatibility with the current manifest specification before defining the public field contract.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/plugins/agentPluginService.ts`, `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/pluginListWidget.ts`
- **Validation:** After settling the contract, add focused metadata-resolution and plugin-list tests covering a plugin-relative branding image, marketplace discovery before installation, and absent or unreadable branding. Manually verify that two differently branded plugins remain distinguishable in installed and marketplace lists without changing their accessible names or actions.
- **Behavior:**

  > Plugin authors can supply an optional branding image that distinguishes their plugin in customization management and marketplace discovery. The maintainer has selected `logo` terminology rather than the proposed `icon`. Plugins without usable branding retain a consistent fallback and remain discoverable and operable. Acceptance covers installed plugins and marketplace entries before installation, without requiring branding metadata for existing plugins.
- **Trace:**

  > IAgentPlugin in src/vs/workbench/contrib/chat/common/plugins/agentPluginService.ts and IMarketplacePlugin plus IMarketplaceJson in src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts currently carry no image metadata. IPluginManifest in agentPluginServiceImpl.ts accepts unknown keys, but that alone does not expose branding to consumers. Installed and marketplace renderers in browser/aiCustomization/pluginListWidget.ts construct text-and-action rows without plugin-authored images. The maintainer chose `logo` at https://github.com/microsoft/vscode/issues/304758#issuecomment-4128551965, but the linked specification now redirects to a published schema that excludes top-level branding fields. Clarify the supported manifest contract first; preserve plugin enablement, installation behavior, accessible names, and unbranded presentation. Individual agent-picker codicons in https://github.com/microsoft/vscode/issues/329308 are separate work.
- **Open decisions:**
  - How should `logo` be represented across the existing plugin manifest formats and the current closed root plugin.json specification: which formats accept a top-level field, and does the root format require namespaced metadata?
