# Issue #337041 — Chat tab - flicker on reload

[https://github.com/microsoft/vscode/issues/337041](https://github.com/microsoft/vscode/issues/337041)

## Summary

Team-authored (MEMBER) bug with a video-documented reproduction; it stays open per policy for team-authored items, and I found no fix commit on main, so keep-open is correct regardless.

## Change summary

On reload, an Agents Window chat tab briefly shows the underlying session's name before the label flips to the chat's actual (custom) title.

## Best solution

Trace and fix the async two-phase title resolution in ChatEditorInput.getName() (src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts) so the tab shows the final title immediately on reload instead of an intermediate session-derived name.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts`
- **Validation:** A test asserting that on session restore, the editor's onDidChangeLabel does not fire an intermediate title different from the final model title (or that getName() returns the eventual chat title from the first render when the persisted title is available).
- **Trace:**

  > getName() in ChatEditorInput falls back to chatService.getSession(...)/getSessionTitle(...) (persisted/session-registry title) before a resolved model is available, then switches to model.title once resolve() completes and fires _onDidChangeLabel (chatEditorInput.ts lines 176-205, 359, 381). The observable defect is that these two sources can disagree during reload, producing a visible tab-title flicker. Do not change the general title-resolution priority order for non-reload cases (custom titles, truncation) — only the transient reload window is in question. As far as established: the mechanism that could cause it is identified, but I did not confirm from source whether the persisted/session-registry title actually differs from the eventual model title in the reported scenario, or whether the fix should suppress the early render, pre-warm the persisted title to match, or debounce the label-change event.
- **Open decisions:**
  - Should the tab avoid rendering any title until the chat model resolves, or should the initially-shown persisted/session title be kept in sync with the eventual chat title so no visible change occurs?
  - Is the 'session name' shown initially actually the same underlying value as the persisted chat title (a staleness bug) or a genuinely different concept (e.g., workspace/session metadata) that shouldn't be shown as a chat tab title at all?

## Evidence

On reload the model resolves asynchronously and fires _onDidChangeLabel once resolve() completes (line 359/381), which matches a title that changes shortly after the tab first renders.
