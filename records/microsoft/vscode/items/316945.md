# Issue #316945 — powershell tool assumes PowerShell 6+ (pwsh.exe) — fails silently on machines with only Windows PowerShell 5.1

[https://github.com/microsoft/vscode/issues/316945](https://github.com/microsoft/vscode/issues/316945)

## Summary

The report describes a real usability gap: Copilot agent mode's `powershell` tool fails with a cryptic error on Windows machines that have only Windows PowerShell 5.1 (no PowerShell 7 / pwsh.exe). The runInTerminalTool already has a fallback to `powershell.exe` for the classic terminal tool path, but the agent host shell resolution path may not handle this equivalently. The exact failing code path is hard to pin down without execution — it may involve the SDK layer or the agent host terminal manager — so routing to the agent-host area for investigation.

## Change summary

The Copilot agent mode `powershell` tool assumes `pwsh.exe` (PowerShell 7+) is available, failing with a cryptic error on Windows machines that only have Windows PowerShell 5.1.

## Best solution

Ensure the agent host's shell resolution for the `powershell` tool falls back to `powershell.exe` (Windows PowerShell 5.1) when `pwsh.exe` is not found, mirroring the existing fallback in `runInTerminalTool.ts` (line 3448). If `pwsh.exe` is truly required, surface a clear actionable error pointing the user to install PowerShell 7. The existing `src/vs/base/node/powershell.ts` already enumerates PowerShell installations with proper fallback logic — the agent host should use it.

## Evidence

- **existing fallback in runInTerminalTool:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts line 3444-3451 already falls back to `C:\WINDOWS\System32\WindowsPowerShell\v1.0\powershell.exe` when the default shell is cmd.exe — the agent host path lacks an equivalent.
- **agent host shell resolution:** src/vs/platform/agentHost/node/copilot/copilotShellTools.ts line 107-111: `getResolvedExecutable()` delegates to `IAgentHostTerminalManager.getDefaultShell()` which calls `getSystemShell()` — on Windows this returns `cmd.exe` (COMSPEC), not a PowerShell executable.
- **shellType mapping:** src/vs/platform/agentHost/node/shared/shellCommandExecution.ts line 73: unknown shells (like cmd.exe) default to `'powershell'` type on Windows, so the tool is named `powershell` but the underlying terminal runs cmd.exe.
- **PowerShell enumeration utility exists:** src/vs/base/node/powershell.ts provides `getFirstAvailablePowerShellInstallation()` which enumerates pwsh.exe installations and falls back to Windows PowerShell 5.1 — this could be leveraged by the agent host.
- **Windows PowerShell prevalence:** The reporter correctly notes that PowerShell 7 does not auto-install with Windows; Windows PowerShell 5.1 is the default on most Windows 10/11 machines, making this a common-breadth issue.
