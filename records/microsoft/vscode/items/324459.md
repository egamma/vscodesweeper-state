## Summary

Team-authored bug found during TPI #324418 verification — chat asks file-read permission for an explicitly attached session, and uses an opaque internal file path instead of a user-friendly description. No fix found on main. Keeping open for the area owner.

## Change summary

When a user explicitly attaches a prior chat session as context, the agent still prompts for file-read permission using an internal file path the user has never seen.

## Best solution

The session-attachment flow in the agent host should either auto-grant read access for user-attached sessions (so no permission prompt appears) or, if a prompt is required, describe the resource as the attached session rather than an opaque file path. Likely touches code in `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionReferenceAttachment.ts` and related tool-confirmation logic.
