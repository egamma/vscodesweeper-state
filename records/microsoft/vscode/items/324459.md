# Issue #324459 — Chat asks to read a file after I've explicitly attached a chat session

[https://github.com/microsoft/vscode/issues/324459](https://github.com/microsoft/vscode/issues/324459)

## Summary

Keep open: current source still loses the attached session's identity when presenting a read-permission request. This team-authored report has neither a verified fixing commit nor an older canonical covering the same symptom.

## Change summary

Explicitly attaching a chat session can lead to a permission prompt naming its unfamiliar backing file rather than the attached session.

## Best solution

Preserve the connection between the selected session and its backing resource through permission presentation, so any required confirmation identifies the session the user attached. Determine whether explicit attachment already authorizes that read without overriding managed approval requirements or other runtime restrictions.
