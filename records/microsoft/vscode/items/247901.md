# Issue #247901 — Add a "disable" option on tool confirmations

[https://github.com/microsoft/vscode/issues/247901](https://github.com/microsoft/vscode/issues/247901)

## Summary

Keep open: current tool confirmations offer approval and one-call skipping, but no standard action that disables the tool in the picker. The thread explicitly requests this second entry point into the existing enablement model, so the separate Configure Tools interface does not complete the request.

## Change summary

Allow users to disable a tool directly from its confirmation, with the change reflected in tool selection.

## Best solution

Expose tool disablement at the confirmation using the same enablement state as the tool picker, rather than introducing a separate denial list. Agree on the action's persistence and workspace scope before implementation, since today's selection model supports session, custom-agent, and profile scopes.

- **Behavior:**

  > Users should be able to disable an unwanted tool directly from its pending confirmation instead of opening the tool picker separately. Disablement must be reflected in the same selection state the picker displays, and the pending invocation must not execute. Subsequent requests must respect the disabled state, and re-enabling the tool through the picker must restore availability. The scope and persistence of this action must be explicit, while ordinary Skip retains its existing one-call behavior.
- **Trace:**

  > The thread at https://github.com/microsoft/vscode/issues/247901 explicitly settles that this is a second UI for the existing tool enablement model, not a separate deny policy. AbstractToolConfirmationSubPart.render in browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts supplies standard approval and Skip buttons; ToolConfirmationSubPart.additionalPrimaryActions in the neighboring chatToolConfirmationSubPart.ts obtains additional approvals from the confirmation service. - **Open decisions:**
