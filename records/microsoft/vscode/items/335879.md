[https://github.com/microsoft/vscode/issues/335879](https://github.com/microsoft/vscode/issues/335879)

## Summary

Team-authored (MEMBER) design/performance issue scoping out optimizations for automatic session cleanup in the Agents Window; there's no bug to reproduce or duplicate to verify — this is a legitimate scoping item that should stay open for implementation.

## Change summary

Automatic session cleanup repeatedly re-evaluates unchanged/non-actionable sessions and calls the expensive restoreSession path unnecessarily; request is to make eligibility checks cheaper and avoid duplicated GitHub/provider work.

## Best solution

Implement caching/backoff or event-driven reevaluation in the sessions lifecycle code (src/vs/sessions, likely near restoreSession usage in sessionsPart.ts/workbench.ts) so cheap authoritative data is used for eligibility checks, reserving restoreSession/full validation for the actual archive/delete action.
