# Issue #325859 — editor.inertialScroll misclassifies high-resolution mouse wheels as touchpads

[https://github.com/microsoft/vscode/issues/325859](https://github.com/microsoft/vscode/issues/325859)

## Summary

The misclassification is directly reproducible in current source and remains unresolved after the earlier inertial-scroll mouse fix. Route this Linux input-device regression to the editor scrolling owners.

## Change summary

High-resolution mouse-wheel deltas are classified as touchpad input, causing editor.inertialScroll to add unwanted synthetic momentum.

## Best solution

Define how inertial scrolling should distinguish high-resolution wheels from touch input, then update MouseWheelClassifier while preserving its existing Magic Mouse and touchpad classifications. A recorded-event regression test should cover the reported Logitech sequence.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** Add a MouseWheelClassifier test using the reported high-resolution Logitech deltas and run scripts/test.sh --grep "MouseWheelClassifier"; the new sequence must classify as physical-wheel input while the existing Magic Mouse and touchpad recordings remain nonphysical.
- **Behavior:**

  > With editor.inertialScroll enabled, scrolling with a high-resolution physical mouse wheel must stop when physical wheel input stops; VS Code must not append synthetic inertia. Touchpad and Magic Mouse gestures must continue receiving inertial behavior. Acceptance requires the reported fractional wheel sequence to classify as physical without changing the expected classifications of the existing recorded-device tests.
- **Trace:**

  > MouseWheelClassifier._computeScore in src/vs/base/browser/ui/scrollbar/scrollableElement.ts treats non-integral deltas as touchpad evidence and clamps the modulo divisor to at least 1. For repeated 0.2 events, the modulo check therefore cannot contribute physical-wheel evidence, leaving the rolling score above the physical-wheel threshold; AbstractScrollableElement._onMouseWheel then starts synthetic inertia. The current tests in src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts also show that real touch devices can emit repeated fractional sub-unit deltas, so a value-only adjustment must not reclassify those recordings. https://github.com/microsoft/vscode/pull/268284 added the classifier gate after https://github.com/microsoft/vscode/issues/256269, but did not cover this high-resolution-wheel case. Keep the scope to input classification and editor inertial behavior; the broader native-scroll-area, refresh-rate, Explorer, and Wayland hold-gesture concerns are separate work.
- **Open decisions:**
  - Should editor.inertialScroll continue automatically inferring wheel versus touch input, or expose an explicit input-device mode for hardware whose event streams are indistinguishable to the classifier?

## Evidence

- **source reproduction:** In src/vs/base/browser/ui/scrollbar/scrollableElement.ts, MouseWheelClassifier._computeScore adds 0.25 for every non-integral delta. Its modulo comparison clamps the smaller magnitude to at least 1, so consecutive 0.2 deltas produce 0.2 % 1 rather than matching and remain classified as touchpad-like.
- **behavioral consequence:** AbstractScrollableElement._onMouseWheel in src/vs/base/browser/ui/scrollbar/scrollableElement.ts starts synthetic inertia whenever editor.inertialScroll is enabled and MouseWheelClassifier.isPhysicalMouseWheel() is false.
- **regression constraint:** src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts contains Magic Mouse and touchpad recordings with repeated fractional sub-unit deltas that must remain nonphysical, so treating repeated fractional values as wheel input without another signal would regress existing classifications.
- **prior fix:** https://github.com/microsoft/vscode/pull/268284 introduced the current classifier gate for https://github.com/microsoft/vscode/issues/256269, but the reported high-resolution-wheel sequence still follows the touchpad branch on current main.
- **canonical search:** No open issue or PR was found that owns this specific high-resolution-wheel misclassification; the related inertial-scrolling issue https://github.com/microsoft/vscode/issues/201937 and prior mouse regression https://github.com/microsoft/vscode/issues/256269 are closed.
