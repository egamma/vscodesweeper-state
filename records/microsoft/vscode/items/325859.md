# Issue #325859 — editor.inertialScroll misclassifies high-resolution mouse wheels as touchpads

[https://github.com/microsoft/vscode/issues/325859](https://github.com/microsoft/vscode/issues/325859)

## Summary

Current source confirms that fractional sub-unit wheel deltas are classified as touchpad input and therefore receive synthetic inertia. This is a valid editor-scrollbar bug, but the existing touchpad fixtures show that a narrow arithmetic adjustment could regress real touchpads, so the input distinction needs design before implementation.

## Change summary

High-resolution physical mouse wheels on Linux Wayland receive synthetic scrolling after the wheel stops when `editor.inertialScroll` is enabled.

## Best solution

Define a reliable way for `ScrollableElement` to distinguish high-resolution wheels from touchpads, or a safe fallback for ambiguous input, while preserving touchpad inertia and the classifier behavior used by smooth scrolling and terminal consumers.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts`
- **Validation:** Run `./scripts/test.sh --grep "MouseWheelClassifier"` with a fixture for the reported MX Master sequence; it must classify as a physical wheel after sufficient events while all existing physical-wheel, touchpad, and Magic Mouse fixtures retain their expected classifications.
- **Behavior:**

  > With `editor.inertialScroll` enabled, a high-resolution physical mouse wheel must stop scrolling when physical wheel input stops. Touchpads and other gesture devices must retain synthetic inertia where needed, and ordinary wheel smooth-scrolling behavior must not regress. Acceptance requires the reported fractional MX Master sequence to classify as physical while every existing classifier fixture keeps its expected result.
- **Trace:**

  > `MouseWheelClassifier._computeScore` in `src/vs/base/browser/ui/scrollbar/scrollableElement.ts` starts at 0.5, adds 0.25 for non-integral deltas, and can subtract physical-wheel evidence only through a modulo comparison whose minimum divisor is clamped to 1. Consequently, repeated sub-unit values such as 0.2 score as touchpad input; `_onMouseWheel` then starts `_periodicSync()` because `isPhysicalMouseWheel()` is false. The uncertainty begins at device discrimination: existing fixtures in `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts` demonstrate touchpads and Magic Mouse input with overlapping fractional values. The classifier is shared with editor mouse handling and terminal scrolling, so those consumers and existing touchpad classifications are outside the acceptable regression boundary. Relevant history is https://github.com/microsoft/vscode/pull/205122 and https://github.com/microsoft/vscode/pull/244034.
- **Open decisions:**
  - Which additional signal or event pattern should distinguish high-resolution physical wheels from touchpads when their fractional deltas overlap?
  - What fallback behavior should apply when the classifier cannot identify the device confidently?
  - Should any solution remain in the shared `MouseWheelClassifier`, or should inertial scrolling use a separate classification path to avoid changing smooth-scrolling and terminal behavior?

## Evidence

- **source reproduction:** In `src/vs/base/browser/ui/scrollbar/scrollableElement.ts`, `MouseWheelClassifier._computeScore` adds touchpad evidence for every non-integral delta. Its modulo comparison clamps the smaller magnitude to at least 1, so repeated values such as 0.2 never contribute physical-wheel evidence; the reported sequence therefore remains classified as non-physical.
- **observable effect:** `AbstractScrollableElement._onMouseWheel` in `src/vs/base/browser/ui/scrollbar/scrollableElement.ts` starts `_periodicSync()` whenever inertial scrolling is enabled and `isPhysicalMouseWheel()` is false, directly producing the reported post-wheel motion.
- **regression risk:** `src/vs/base/test/browser/ui/scrollbar/scrollableElement.test.ts` contains touchpad and Magic Mouse fixtures with repeated fractional sub-unit deltas, including 0.2, which must remain classified as non-physical; delta integrality or repetition alone cannot safely resolve the report.
- **implementation history:** https://github.com/microsoft/vscode/pull/205122 introduced the modulo heuristic for fractional Linux Wayland wheel events, and https://github.com/microsoft/vscode/pull/244034 later used the classifier to gate the optional synthetic inertial scrolling implementation.
