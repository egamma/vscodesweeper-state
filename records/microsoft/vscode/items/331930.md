# Issue #331930 — Skip tool button in agent mode should have option to give alternative instruction

[https://github.com/microsoft/vscode/issues/331930](https://github.com/microsoft/vscode/issues/331930)

## Summary

A real gap remains on current main: Skip carries no optional instruction and local tool handling sends the model a fixed skip result. The general steering-message feature stops the current response and starts another message, so it does not provide the requested same-turn correction.

## Change summary

Allow users to include alternative guidance when skipping a pending agent tool call so the agent can change course within the current turn.

## Best solution

Extend the existing tool-confirmation experience so optional user guidance accompanies the skipped-tool outcome across local tools and Agent Host sessions, while preserving one-click Skip without guidance. The interaction should remain keyboard-operable, screen-reader discoverable, and consistent with the existing confirmation card.

## Plan brief

- **Validation:** Add targeted chat tests proving that keyboard-entered guidance is included in the skipped local tool result and in the Agent Host `ChatToolCallConfirmed.userSuggestion`, while an ordinary Skip retains its current behavior; run those tests with `scripts/test.sh --grep "skip tool"`.
- **Behavior:**

  > A user facing a pending tool confirmation can skip the tool and optionally provide alternative instructions. The agent receives that instruction as part of the skipped-tool outcome and continues the current turn using the new direction; skipping without text remains unchanged. The interaction must work entirely by keyboard, restore focus predictably, and expose an appropriate accessible name and help text.
- **Trace:**

  > `ConfirmedReason` in src/vs/workbench/contrib/chat/common/chatService/chatService.ts currently represents Skip without a payload. `AbstractToolConfirmationSubPart` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts renders a fixed Skip action, and `LanguageModelToolsService.invokeTool` converts it to a fixed model-facing sentence. The Agent Host protocol already has `ChatToolCallDeniedAction.userSuggestion`, but `_awaitToolConfirmation` in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts does not receive or forward suggestion text. The existing `Steer with Message` flow from https://github.com/microsoft/vscode/issues/260330 is a separate request that stops the current response, so it must not be treated as equivalent or silently substituted. Preserve ordinary approval, custom confirmation options, one-click Skip, and existing steering semantics; update the existing chat accessibility help if a new confirmation interaction is introduced.
- **Open decisions:**
  - Should the existing Skip action expand an inline instruction field, or should the confirmation expose a separate “Skip with Instruction” action while retaining one-click Skip?

## Evidence

- **current skip contract:** src/vs/workbench/contrib/chat/common/chatService/chatService.ts defines `ConfirmedReason` for `ToolConfirmKind.Skipped` without an instruction payload.
- **current UI path:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/abstractToolConfirmationSubPart.ts renders Skip as a fixed secondary button and confirms only `{ type: ToolConfirmKind.Skipped }`.
- **current model outcome:** src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts handles a skipped confirmation by returning the fixed text `The user chose to skip the tool call, they want to proceed without running it`; no user guidance can reach the model.
- **Agent Host capability gap:** src/vs/platform/agentHost/common/state/protocol/channels-chat/actions.ts already permits `userSuggestion?: Message` on a denied tool-call action, but `_awaitToolConfirmation` in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts does not populate it from the confirmation UI.
- **existing capability is not equivalent:** The completed https://github.com/microsoft/vscode/issues/260330 introduced `Steer with Message`; current source describes it as stopping the current response and sending a new message, rather than attaching guidance to the skipped tool result.
- **canonical search:** No older open issue was found that reports the same observable need to skip a pending tool call while supplying replacement instructions; the supplied candidate canonicals concern unrelated settings and chat failures.
