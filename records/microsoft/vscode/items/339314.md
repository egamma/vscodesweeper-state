# Issue #339314 — [Error] unhandlederror-Cannot read properties of undefined (reading 'find')

[https://github.com/microsoft/vscode/issues/339314](https://github.com/microsoft/vscode/issues/339314)

## Summary

Confirmed defect on main (unguarded `.find` on possibly-undefined `framesInSubtree`), with a maintainer-diagnosed Electron root cause and an open PR already proposing a workaround fix — keeping open pending that PR, not proposing a close.

## Change summary

Main-process TypeError in WebviewMainService.getFrameByName/stopFindInFrame: `mainFrame.framesInSubtree` can be undefined due to an Electron/Chromium frame-conversion edge case, causing an unhandled crash in the errors dashboard telemetry.

## Best solution

Review and land the open PR https://github.com/microsoft/vscode/pull/339331, which guards webview find against the disposed/partial frame subtree in src/vs/platform/webview/electron-main/webviewMainService.ts; also consider reporting/tracking the underlying issue upstream in Electron per the maintainer's comment.

## Evidence

- **source confirmation:** src/vs/platform/webview/electron-main/webviewMainService.ts getFrameByName() calls `this.getWebContents(id).mainFrame.framesInSubtree.find(...)` with no guard; if framesInSubtree is undefined this throws exactly the reported 'Cannot read properties of undefined (reading find)'. No fix has landed on main (git log on the file shows only an unrelated recent commit, 3d5764c1).
- **maintainer root-cause analysis:** Comment by dmitrivMS traces the undefined value to Electron 43.7.5/Chromium 150's WebFrameMain::FramesInSubtree()/gin converter dropping the whole array when one frame is pending deletion, even while the webview is alive; confirms this is an Electron-side issue, with the VS Code PR being a workaround.
