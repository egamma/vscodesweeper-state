# Issue #200229 — The "View Problem" positioning error in the code diagnosis pop-up window #926

[https://github.com/microsoft/vscode/issues/200229](https://github.com/microsoft/vscode/issues/200229)

## Summary

The default severity-sorted path still selects a different diagnostic when clicking “View Problem” on a lower-severity diagnostic. Keep this open and classify it as a bug: position sorting is a confirmed workaround, not a fix for explicitly opening the clicked problem.

## Change summary

Make “View Problem” open the diagnostic whose hover action was clicked, even when another diagnostic has higher severity.

## Best solution

Explicitly opening a hovered diagnostic should display that diagnostic while preserving the configured order for subsequent next/previous navigation. The remaining defect is in VS Code’s editor marker-navigation implementation, not in the extensions supplying diagnostics.

- **Root cause:** src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts sorts markers by severity before position unless problems.sortOrder is position. MarkerList._initIdx selects the first sorted marker whose range contains the requested position or starts after it. With an information or warning diagnostic on line 1 and an error on line 2, the error is first in severity order and satisfies the starts-after condition, so the clicked diagnostic is bypassed.
- **Existing-capability check:** src/vs/workbench/contrib/markers/browser/markers.contribution.ts registers problems.sortOrder with default severity and alternatives severity/position.
