# Issue #200229 — The "View Problem" positioning error in the code diagnosis pop-up window #926

[https://github.com/microsoft/vscode/issues/200229](https://github.com/microsoft/vscode/issues/200229)

## Summary

The positional sort setting is a confirmed workaround, but it globally changes problem navigation and does not make “View Problem” reliably select the clicked diagnostic under the default severity ordering. The correctly routed request remains valid and under discussion.

## Change summary

Make “View Problem” open the diagnostic selected in the hover instead of another, higher-severity diagnostic.

## Best solution

Decouple the hover action from next-problem navigation ordering: select the supplied marker directly while preserving `problems.sortOrder` for F8 navigation. Coordinate the shared behavior with https://github.com/microsoft/monaco-editor/issues/2603.

## Evidence

- **confirmed behavior:** https://github.com/microsoft/vscode/issues/200229#issuecomment-1845111019 records a maintainer reproduction: selecting a warning opens an error when the error has higher severity.
- **source path:** On current main, src/vs/editor/contrib/hover/browser/markerHoverParticipant.ts passes the clicked marker to MarkerController.showAtMarker, but src/vs/editor/contrib/gotoError/browser/gotoError.ts resets navigation and resolves it again by position.
- **root cause:** src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts sorts markers by `problems.sortOrder` and `_initIdx` scans that sorted array by position; with the default severity ordering, this can select a different marker.
- **workaround limitation:** The reporter confirmed that `"problems.sortOrder": "position"` avoids the symptom, but the setting also changes normal next/previous problem navigation globally.
- **related tracker:** https://github.com/microsoft/monaco-editor/issues/2603 is an older open report of the same shared editor behavior.
