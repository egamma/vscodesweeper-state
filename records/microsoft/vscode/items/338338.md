# Issue #338338 — If not signed in to dev tunnels already the "connect" command doesn't properly sign in

[https://github.com/microsoft/vscode/issues/338338](https://github.com/microsoft/vscode/issues/338338)

## Summary

Keep open and route to remote authentication: a second maintainer confirms that selecting a known host fails until Dev Tunnels authentication is completed separately. Current source has differing authentication paths, but no verified fix covers both host-list connections and the first command invocation.

## Change summary

Connecting to a remote agent host should complete any required Dev Tunnels sign-in without hanging or requiring another Command Palette invocation.

## Best solution

Make explicit user-initiated connections complete the required authentication and continue to the selected host on desktop and mobile web. Preserve silent background discovery and reconnection, and investigate the first-invocation progress hang alongside the host-list authentication failure.

A single command invocation should reach the host picker, and selecting a known host should not require running a separate command first. This must work on desktop and touch-only mobile web. Cancellation or failure must terminate progress; background discovery and automatic reconnection must retain their noninteractive authentication behavior.
- **Trace:**

  > The report and a second maintainer's confirmation at https://github.com/microsoft/vscode/issues/338338 establish two affected entry points: the connect command and selecting an already listed host. promptToConnectViaTunnel in remoteAgentHostActions.ts explicitly awaits GitHub session creation before enumeration. BrowserTunnelAgentHostService._getToken and the Electron TunnelAgentHostService._getToken only allow interactive acquisition through a remembered provider, while their fallback provider searches remain silent. That is a plausible host-list failure boundary, not a conclusive explanation for the command's spinning notification. WebTunnelAgentHostService._createConnection delegates to discoveryProvider.connect, so the iOS embedder path must also be traced. Existing browser and Electron tests cover silent cached connections and explicit-provider behavior; preserve those contracts. Investigation must first distinguish an unresolved authentication promise from missing interactive acquisition and determine whether both reported entry points share a cause.
