# Issue #334860 — Markdown Preview search does not work when preview is moved to a separate window

[https://github.com/microsoft/vscode/issues/334860](https://github.com/microsoft/vscode/issues/334860)

## Summary

Credible, detailed repro (extensions confirmed disabled) pointing to a real gap in webview find-widget support when a webview editor (Markdown Preview) is detached into an auxiliary window; I couldn't trace the exact break in the multi-window plumbing from the checkout alone, so I'm not calling this confirmed-reproduced, but it lines up with a related open report of cross-window focus stealing for the same widget.

## Change summary

Ctrl/Cmd+F search in the Markdown Preview webview fails to find/highlight matches once the preview is moved to a separate (auxiliary) VS Code window.

## Best solution

Investigate webview find-widget routing for auxiliary windows in src/vs/workbench/contrib/webview/browser/webviewFindWidget.ts and src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts (getActiveWebviewEditor relies on IEditorService.activeEditor, which must resolve correctly against the aux window's own editor group); likely the same root cause as the focus-stealing report at https://github.com/microsoft/vscode/issues/336063, so the two should probably be triaged together by the webview/markdown owners.
