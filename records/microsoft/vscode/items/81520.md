# Issue #81520 — ctrl + click "go to definition" clashes with ctrl + click "follow link"

[https://github.com/microsoft/vscode/issues/81520](https://github.com/microsoft/vscode/issues/81520)

## Summary

The conflict remains in current source: separate mouse-gesture handlers independently open a document link and navigate to a definition at the same position. Keep this older report open; resolving which action wins needs a maintainer decision, and a previous attempted fix in a related report was reverted after breaking Markdown links.

## Change summary

Prevent one Ctrl/Cmd-click from both opening a link and navigating to a definition when their source ranges overlap.

## Best solution

Make overlapping link and definition targets resolve to one intentional navigation outcome while preserving access to both operations through explicit commands. Agree on precedence or a target chooser, and preserve link opening when a registered definition provider returns no result.

- **Behavior:**

  > A Ctrl/Cmd-click on a range that has both a document link and a definition must not launch both navigations. Both targets must remain accessible through deliberate actions. The maintainer must decide whether the shared gesture prioritizes one target or offers a choice. Acceptance includes unchanged link-only and definition-only navigation, successful link opening when a definition provider returns no result, and behavior independent of asynchronous provider completion order.
- **Trace:**

  > GotoDefinitionAtPositionEditorContribution in src/vs/editor/contrib/gotoSymbol/browser/link/goToDefinitionAtPosition.ts and LinkDetector in src/vs/editor/contrib/links/browser/links.ts each construct a ClickLinkGesture and independently consume onExecute. ClickLinkGesture in src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts subscribes to the editor's mouse events separately for each instance, with no shared consumption or arbitration. The definition consumer checks provider availability, while the link consumer checks a link occurrence; both can succeed at the same position. This conclusively preserves the reported double-dispatch path in current source, without runtime execution. Keep language servers free to expose both capabilities and preserve explicit keyboard/context-menu operations, modifier mappings and side-by-side navigation. https://github.com/microsoft/vscode/issues/147447 is a newer related report whose attempted fix was reverted after the empty-definition-result regression documented in https://github.com/microsoft/vscode/issues/169593. The unresolved boundary is the observable choice when both valid targets exist, not whether provider registration alone should suppress links.
- **Open decisions:**
