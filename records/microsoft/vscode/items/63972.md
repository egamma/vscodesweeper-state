# Issue #63972 — [folding] Move line up/down should skip over folded regions or folded sections

[https://github.com/microsoft/vscode/issues/63972](https://github.com/microsoft/vscode/issues/63972)

## Summary

This remains a valid, well-supported Backlog feature request: 71 community upvotes and two older reports consolidated into it establish clear demand, while current main still moves selections across one adjacent model line without consulting folded ranges.

## Change summary

Make Move Line Up/Down treat a collapsed region as one visible unit, skipping over it without expanding it.

## Best solution

Define fold-aware semantics for both sides of the operation, then integrate the editor's collapsed-range state into the move-lines action while preserving existing indentation, multi-selection, undo, and ordinary line-moving behavior.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/linesOperations/browser/linesOperations.ts`, `src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts`, `src/vs/editor/contrib/linesOperations/test/browser/moveLinesCommand.test.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`
- **Validation:** Add an editor integration test that creates and collapses a folding range, invokes editor.action.moveLinesUpAction and editor.action.moveLinesDownAction across it, and asserts the moved text lands beyond the complete range while the range remains collapsed; retain the existing move-lines command suite for non-folded and indentation behavior.
- **Behavior:**

  > When Move Line Up or Move Line Down encounters a collapsed region adjacent to the moved selection, one invocation moves the selection across the complete collapsed region rather than into its hidden lines. The collapsed region remains collapsed. Moving lines where no collapsed region is crossed behaves exactly as today, including indentation, multi-selection, undo, and document-boundary behavior. Acceptance covers both directions and both provider-based and marker-based folds where the folding test harness supports them.
- **Trace:**

  > AbstractMoveLinesAction in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts currently creates synchronous MoveLinesCommand instances without fold information. MoveLinesCommand in src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts swaps the selection with exactly one adjacent model line and performs indentation calculations around that assumption. FoldingController.getFoldingModel() in src/vs/editor/contrib/folding/browser/folding.ts is asynchronous and exposes the FoldingModel whose collapsed regions can identify the visible unit being crossed. Existing unit coverage is in src/vs/editor/contrib/linesOperations/test/browser/moveLinesCommand.test.ts, but the collapsed-state behavior likely needs an editor-level integration test because folding is editor view state rather than text-model state. Keep https://github.com/microsoft/vscode/issues/72422 out of scope: selecting or moving a folded region itself is related but distinct from moving an external selection across one.
- **Open decisions:**
  - Should this issue cover only moving an external selection across an adjacent collapsed range, or also make a selection on a fold's header move the entire folded range as requested separately in https://github.com/microsoft/vscode/issues/72422?
  - When multiple selections encounter collapsed and ordinary adjacent lines at different distances, should each selection cross its own next visible unit in one invocation, or should the command preserve a uniform one-model-line displacement?

## Evidence

- **current source gap:** On current main, AbstractMoveLinesAction in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts constructs MoveLinesCommand using only the selection, direction, auto-indent mode, and language configuration; it does not obtain FoldingController or collapsed ranges.
- **line-based implementation:** src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts computes the adjacent content as selection.endLineNumber + 1 or selection.startLineNumber - 1 and moves exactly that model line, so hidden lines inside a collapsed region are not treated as one visible unit.
- **folding access:** src/vs/editor/contrib/folding/browser/folding.ts exposes FoldingController.getFoldingModel() asynchronously, confirming that fold state exists at the editor-contribution layer but is not currently part of MoveLinesCommand.

- **canonical status:** The older https://github.com/microsoft/vscode/issues/55667 and the navigation-related https://github.com/microsoft/vscode/issues/64468 were both closed as duplicates of this issue, making https://github.com/microsoft/vscode/issues/63972 the established canonical rather than a duplicate candidate.
- **distinct related request:** The open https://github.com/microsoft/vscode/issues/72422 concerns selecting or operating on the first line of a folded range as the whole range; it does not own this issue's distinct request to move an external line across a collapsed range.
