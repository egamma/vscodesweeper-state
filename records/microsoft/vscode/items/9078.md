# Issue #9078 — support font-size in DecorationRenderOptions

[https://github.com/microsoft/vscode/issues/9078](https://github.com/microsoft/vscode/issues/9078)

## Summary

The public decoration API still lacks font-size support, although the internal renderer supports it. Keep this accepted Backlog request open: 30 upvotes demonstrate demand, and neither the CSS workaround nor the related variable-font work completes the requested API.

## Change summary

Allow extensions to specify font size for decorated document text and before/after decoration attachments.

## Best solution

Provide supported font-size options in the public decoration API, including theme overrides and attachments, with defined sizing limits and reliable cursor, selection, and layout behavior. Decide whether zero or near-zero sizes are supported before exposing the contract.

- **Behavior:**

  > Extensions should be able to request font sizes through supported decoration options for document text and before/after attachments, including theme-specific overrides. Existing decorations without a size must retain their behavior. Acceptance must cover smaller and larger text without cursor disappearance, focus loss, or incorrect selection geometry. Whether zero and near-zero sizes are supported remains a public-contract decision.
- **Trace:**

  > The public interfaces in src/vscode-dts/vscode.d.ts omit fontSize, and the three decoration converters in src/vs/workbench/api/common/extHostTypeConverters.ts do not forward it. Internal interfaces in src/vs/editor/common/editorCommon.ts and CSS generation in src/vs/editor/browser/services/abstractCodeEditorService.ts already support fontSize for text and attachments; this establishes partial infrastructure, not completion of the extension API. editor.allowVariableFonts is a rendering permission, not a substitute for the requested property. The discussion at https://github.com/microsoft/vscode/issues/9078 supplies historical cursor, focus, and selection problems at tiny sizes that require current runtime investigation. Keep existing decoration defaults, global font settings, and unrelated Monaco API adoption unchanged. https://github.com/microsoft/vscode/issues/256046 concerns a different API surface and is not a duplicate canonical.
- **Open decisions:**
  - Should the public font-size contract permit zero and near-zero sizes that effectively hide document text, or restrict sizes to a supported positive range?
