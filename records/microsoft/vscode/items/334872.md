# Issue #334872 — Wrong Content-Security-Policy header for serve-web

[https://github.com/microsoft/vscode/issues/334872](https://github.com/microsoft/vscode/issues/334872)

## Summary

Confirmed on main: `createWorkbenchContentSecurityPolicy` in webClientServer.ts hardcodes `http://${remoteAuthority}` in the script-src directive regardless of the scheme the browser actually used, breaking pages served behind an HTTPS-terminating reverse proxy. This is a real, still-open gap; how to safely detect the external scheme (e.g. trusting `X-Forwarded-Proto`) is a security-relevant design choice, not something to auto-fix blind.

## Change summary

The serve-web CSP `script-src` directive always uses `http://` for the remote-authority origin, so HTTPS reverse-proxy deployments get CSP violations and a blank page.

## Best solution

Detect the externally-observed scheme (via a configurable trusted-proxy header check, e.g. `X-Forwarded-Proto`, not blind trust) and use it when building the `script-src` origin in `createWorkbenchContentSecurityPolicy`/`webClientServer.ts`.
