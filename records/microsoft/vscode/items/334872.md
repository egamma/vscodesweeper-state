# Issue #334872 — Wrong Content-Security-Policy header for serve-web

[https://github.com/microsoft/vscode/issues/334872](https://github.com/microsoft/vscode/issues/334872)

## Summary

Confirmed on current main: createWorkbenchContentSecurityPolicy hard-codes `http://${remoteAuthority}` in the script-src directive regardless of the actual client-facing scheme, so serving behind an HTTPS-terminating reverse proxy produces a CSP that blocks the workbench scripts. Real, localized bug worth fixing.

## Change summary

The `code serve-web` Content-Security-Policy always uses `http://` for the remote authority in script-src, breaking pages served over HTTPS via a reverse proxy.

## Best solution

In src/vs/server/node/webClientServer.ts, detect the client-facing scheme (e.g. via the `X-Forwarded-Proto` request header, falling back to the connection's own protocol) and pass it into createWorkbenchContentSecurityPolicy instead of hard-coding `http://` in the script-src directive around line 149.
