# Issue #334872 — Wrong Content-Security-Policy header for serve-web

[https://github.com/microsoft/vscode/issues/334872](https://github.com/microsoft/vscode/issues/334872)

## Summary

Current main still constructs the serve-web CSP with an unconditional `http://` source even when forwarded host and port headers describe an HTTPS reverse-proxy deployment. The issue carries the `security` label, so it must remain open for human handling.

## Change summary

Make the serve-web Content-Security-Policy compatible with HTTPS termination at a reverse proxy instead of emitting a hard-coded HTTP origin.

## Best solution

Ensure the externally visible, security-validated origin used by serve-web is consistent across its CSP and generated web configuration when HTTPS is terminated by a trusted reverse proxy, with tests covering both direct HTTP and forwarded HTTPS requests.
