# Issue #303877 — Sessions App: Deleting a Fork conversation deletes work tree of original conversation

[https://github.com/microsoft/vscode/issues/303877](https://github.com/microsoft/vscode/issues/303877)

## Summary

Valid bug filed by a team member: forking a conversation shares the worktree, and deleting the fork's worktree breaks the original. No fix commit references this issue; a related fix (a654c5067a0, #313205) addressed wrong confirmation dialogs but not the shared-worktree protection itself. Keeping open.

## Change summary

Deleting a forked conversation in the Sessions App deletes the work tree shared with the original conversation, breaking the original session.

## Best solution

Implement option C from the discussion: when a worktree is shared between a forked and original session, suppress the 'delete worktree' prompt on the fork (or prevent worktree deletion entirely when other sessions reference it). The delete flow in the agent host and Copilot CLI sessions providers needs to check for shared worktree references before offering the cleanup option.
