## Evidence

- **verified canonical:** https://github.com/microsoft/vscode/issues/24389 is OPEN, was created on 2017-04-10, and explicitly requests keyboard shortcuts to navigate changed files. Its scope includes this report's central request.
- **same observable workflow:** https://github.com/microsoft/vscode/issues/24389#issuecomment-396818213 explicitly requests a dedicated command to open the next changed file from the currently open diff view. https://github.com/microsoft/vscode/issues/24389#issuecomment-1523843152 requests both next and previous diff-file navigation.
- **existing-capability boundary:** src/vs/workbench/browser/parts/editor/diffEditorCommandsService.ts, navigateInDiffEditor, delegates to the active single-file editor's goToDiff. In src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts:729-747, goToDiff cycles through mappings within that editor's model; it does not open an adjacent SCM file.
- **partial built-in coverage:** src/vs/workbench/contrib/multiDiffEditor/browser/actions.ts registers multiDiffEditor.goToNextChange and multiDiffEditor.goToPreviousChange. src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidgetImpl.ts:617-657 advances between files at change boundaries, but only inside the multi-file diff editor; this does not supply dedicated adjacent-file navigation in an ordinary SCM diff.
- **workarounds already discussed:** The canonical thread documents SCM-list command macros at https://github.com/microsoft/vscode/issues/24389#issuecomment-1671151829, their selection/tree-mode limitations at https://github.com/microsoft/vscode/issues/24389#issuecomment-1672634802, and an extension workaround at https://github.com/microsoft/vscode/issues/24389#issuecomment-1786015407. These are alternatives, not proof that the requested native capability is complete.
- **other leads:** https://github.com/microsoft/vscode/issues/145009 is also open and requests next-file keyboard navigation, but the older canonical explicitly covers both directions. https://github.com/microsoft/vscode/issues/296607 is newer and proposes a narrower boundary-triggered interaction, so it is not the preferred canonical.
