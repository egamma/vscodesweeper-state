[https://github.com/microsoft/vscode/issues/344974](https://github.com/microsoft/vscode/issues/344974)

## Summary

Keep open to investigate the Auto service/client fallback contract. Current main retains the rejection and cloud-only retry path shown in the logs; the supplied steps suffice to retest, but the actual fallback metadata is needed to distinguish a service response problem from a client compatibility defect.

## Change summary

Auto discards an eligible local MAI selection when cloud fallback metadata fails validation, returning a cloud response without explaining the intermediate rejection in the normal response UI.

## Best solution

Ensure Auto's local selections have a cloud fallback compatible with the Agent Host routing contract, and make incompatible fallback outcomes actionable. Establish the returned metadata before changing endpoint validation; accepting a responses-only fallback without corresponding transport support would not resolve the integration.
