# Issue #329163 — Plugin skills silently drop `user-invocable` / `disable-model-invocation` frontmatter

[https://github.com/microsoft/vscode/issues/329163](https://github.com/microsoft/vscode/issues/329163)

## Summary

Confirmed in current main: plugin-sourced skills (and agents) lose the `user-invocable`/`disable-model-invocation` frontmatter flags because the intermediate `INamedPluginResource` type never carries them, unlike the local-skills path. A team member independently reproduced and narrowed the repro conditions in the comments.

## Change summary

Skills/agents distributed via an agent plugin ignore `user-invocable: false` and `disable-model-invocation: true`, so they wrongly appear in the `/` slash menu and stay model-invocable.

## Best solution

In src/vs/platform/agentPlugins/common/pluginParsers.ts, extend `INamedPluginResource` with optional `userInvocable`/`disableModelInvocation` fields, propagate them from `parseSkillFile()`/`parseAgentFile()` through `readSkills()`/`readAgentComponents()`, and read them in `makeSkillCustomization()`/`makeAgentCustomization()` — mirroring the local-skills handling in promptsServiceImpl.ts (`disableModelInvocation: file.disableModelInvocation ?? false`, `userInvocable: file.userInvocable ?? true`). Also add the missing `disable-model-invocation` read to `parseSkillFile()`, which currently never reads it at all.
