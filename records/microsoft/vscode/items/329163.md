# Issue #329163 — Plugin skills silently drop `user-invocable` / `disable-model-invocation` frontmatter

[https://github.com/microsoft/vscode/issues/329163](https://github.com/microsoft/vscode/issues/329163)

## Summary

Confirmed on current main: plugin-sourced skills silently drop `user-invocable`/`disable-model-invocation`, so they wrongly appear in the `/` menu and remain model-invocable; a second reporter independently reproduced it with a plain local plugin folder (no marketplace/remote source needed), narrowing the root cause to the shared skill-parsing path rather than plugin-root resolution.

## Change summary

Skills distributed via an agent plugin ignore `user-invocable: false` / `disable-model-invocation: true` frontmatter and still show up in the `/` menu / remain model-invocable.

## Best solution

Fix `src/vs/platform/agentPlugins/common/pluginParsers.ts` so the skill path mirrors the already-correct agent path: extend `INamedPluginResource` with `disableModelInvocation`/`disableUserInvocation`, have `parseSkillFile()` also read `disable-model-invocation` (currently only reads `user-invocable`), propagate both through `readSkills()`/`addSkill()`, and populate them in `makeSkillCustomization()` — the target `SkillCustomization` protocol type (channels-session/state.ts) already declares both fields, so this is purely a plumbing gap.
