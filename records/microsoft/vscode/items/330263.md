# Issue #330263 — [Error] unhandlederror-Unexpected end of JSON input

[https://github.com/microsoft/vscode/issues/330263](https://github.com/microsoft/vscode/issues/330263)

## Summary

Real, evidence-backed regression in the new Agent Host IPC path (44 users, absent from 1.132 stable) — traced the exact throw site in `deserialize()`, but the actual sender-side bug that produces a truncated payload isn't yet identified, so this needs an agent-host-area engineer rather than a close or a blind auto-fix.

## Change summary

`JSON.parse` throws `Unexpected end of JSON input` inside `deserialize()` (vs/base/parts/ipc/common/ipc.ts) while the Agent Host processes a raw MessagePort IPC message, indicating a truncated/incomplete payload reaches the reader.

## Best solution

Trace why a MessagePortMain 'message' event ever delivers a partial `DataType.Object` payload to `ChannelServer.onRawMessage`/`deserialize` in src/vs/base/parts/ipc/common/ipc.ts and src/vs/base/parts/ipc/node/ipc.mp.ts — likely a large message being split across multiple postMessage/message events without reassembly on the agent host's utility-process channel — and either buffer/reassemble on the receiving `Protocol`, or fix whatever on the sending side (agentHostMain / plugin-cache init in commit d306b4b1) posts an incomplete frame.
