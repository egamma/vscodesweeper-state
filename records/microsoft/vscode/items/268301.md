# Issue #268301 — Custom editor retains previous error on reopen even when it no longer applies

[https://github.com/microsoft/vscode/issues/268301](https://github.com/microsoft/vscode/issues/268301)

## Summary

Still reproduces on main: `tryRetain` in `customEditorModelManager.ts` returns a cached rejected promise indefinitely without evicting the entry, so a custom editor that once failed to open can never recover. Four community PRs are open but none merged — the issue should stay open for one of them to land.

## Change summary

Custom editors cache a rejected model promise and re-throw the stale error on every reopen, even after the underlying file is created.

## Best solution

Land one of the open fix PRs (preferably https://github.com/microsoft/vscode/pull/312583, the most recent) that evicts the cache entry from `_references` when the model promise rejects, so a subsequent `tryRetain` returns `undefined` and the editor goes through a fresh `add` path. Review the four candidates and pick the cleanest approach.
