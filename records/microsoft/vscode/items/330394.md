# Issue #330394 — YAML indentation rules do not work

[https://github.com/microsoft/vscode/issues/330394](https://github.com/microsoft/vscode/issues/330394)

## Summary

Confirmed in source: this is a real, still-open bug with three concrete causes in the built-in YAML extension — not fixed on main. Already correctly labeled (`bug`, `editor-autoindent`); no close is warranted.

## Change summary

YAML auto-indentation doesn't increase indent after a property (`foo:`), an anchor (`foo: &anchor`), or a block scalar (`foo: |`) when pressing Enter.

## Best solution

Fix extensions/yaml/language-configuration.json (change the stray `&amp;` to `&` in increaseIndentPattern, and extend the pattern to cover block scalar indicators `|`/`>`), and reconsider extensions/yaml/package.json's `configurationDefaults` for `[yaml]`, which sets `editor.autoIndent` to `"advanced"` — one level below `"full"`, which is required for `indentationRules` (increase/decreaseIndentPattern) to ever be consulted at all (see src/vs/editor/common/languages/autoIndent.ts, `getInheritIndentForLine`/`getIndentForEnter`, both early-return `null` when `autoIndent < EditorAutoIndentStrategy.Full`).

## Evidence

- **root cause #1 (autoIndent capped):** extensions/yaml/package.json sets `"[yaml]": { "editor.autoIndent": "advanced" }`. In src/vs/editor/common/languages/autoIndent.ts, both `getInheritIndentForLine` (line ~81) and `getIndentForEnter` (line ~303) start with `if (autoIndent < EditorAutoIndentStrategy.Full) return null;`. Since YAML has no onEnterRules and 'foo:' matches no bracket regex in src/vs/editor/common/languages/supports/onEnter.ts, `getEnterAction` also returns null — so indentationRules (increaseIndentPattern) are never consulted for YAML files under the shipped default.
- **root cause #2 (anchor regex typo):** extensions/yaml/language-configuration.json line 32: `increaseIndentPattern` uses `(&amp;\w+)?` (HTML-entity-escaped, likely copy-pasted from an XML config) instead of `(&\w+)?`. Verified with node: `/(&amp;\w+)?/`-style pattern fails to match `"foo: &anchor"` (tested locally: regex returns false for the anchor case, true only for plain `"foo:"`).
- **root cause #3 (no block scalar handling):** The same increaseIndentPattern has no branch for block scalar indicators (`|`, `>`), confirmed by inspecting extensions/yaml/language-configuration.json lines 31-34; `"foo: |"` does not match the pattern.
