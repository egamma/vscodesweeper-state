# Issue #311723 — Copilot extension crashes for a folder with large number of files

[https://github.com/microsoft/vscode/issues/311723](https://github.com/microsoft/vscode/issues/311723)

## Summary

The crash report is ambiguous: the stack traces point to `ms-python.vscode-python-envs` during extension host shutdown ("Channel has been closed"), not to Copilot itself. The "Cannot read properties of undefined (reading 'subscriptions')" error lacks a stack trace tying it to Copilot code. Opening a folder with millions of files is an extreme scenario that likely causes OOM or resource exhaustion in the renderer, and disabling Copilot may simply reduce memory pressure rather than remove the root cause. Needs clearer isolation.

## Change summary

Extension host crashes (and VS Code becomes unusable) when opening a folder containing millions of files with the Copilot extension enabled.

## Best solution

Request a process monitor log (memory/CPU at crash time) and a targeted test: disable only the Python extensions while keeping Copilot enabled to isolate whether Copilot or the Python extension is the trigger. If it's resource exhaustion from file enumeration, the fix may belong in the file watcher/explorer layer rather than Copilot. The open PR #311739 adds speculative null guards but does not address the underlying resource issue.
