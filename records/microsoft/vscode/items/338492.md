# Issue #338492 — Peer sessions list is inconsistent when marking peer sessions as done

[https://github.com/microsoft/vscode/issues/338492](https://github.com/microsoft/vscode/issues/338492)

## Summary

Real, freshly filed bug in the newly testable peer-sessions 'mark as done' flow (milestone 1.141.0 assigned, so this stays open regardless); the reporter gives clear repro steps and a video, but I couldn't pin the exact defect in the observable pipeline from the checkout alone.

## Change summary

Marking a peer session as done removes it from the sessions list, but adding a new chat briefly brings it back — the archived/done state appears inconsistently reapplied.

## Best solution

Trace how per-chat archived state (e.g. the per-chat `_isArchived` observable around baseAgentHostSessionsProvider.ts:1006-1101) interacts with the session-level `isArchived` observable (baseAgentHostSessionsProvider.ts:1183/1454, ~2769/2814) and the sessionsList.ts filter (~4099-4106) — the reappearance on 'add new chat' suggests a stale/incorrectly-recomputed aggregate archived flag when the chat list changes.
