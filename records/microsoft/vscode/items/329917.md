# Issue #329917 — Selecting prompt and changing it makes the other onboarding prompts unselectable

[https://github.com/microsoft/vscode/issues/329917](https://github.com/microsoft/vscode/issues/329917)

## Summary

Traced this on main: NewSessionPromptOptionsWidget._updateButtons() disables ALL prompt-option buttons (including the already-selected one) whenever the composer's text no longer matches the generated prompt exactly, which is exactly what happens after any manual edit like deleting a character. The greyed-out, unselectable state has no explanatory tooltip, so it reads as broken even if the underlying intent (don't silently discard a user's edit) is reasonable.

## Change summary

In the experimental V3 new-session onboarding prompt-options flow, editing a selected onboarding prompt (e.g. deleting the last character) greys out and disables all prompt option buttons with no explanation.

## Best solution

The onboarding/agents-window feature owners (this was filed against the active test-plan item https://github.com/microsoft/vscode/issues/329851, milestone 1.133.0) should decide the intended UX: likely the selected option's button should stay enabled/clickable after a manual edit (to allow reselecting or undoing), and/or a hover/tooltip should explain why the other options are disabled. Fix lives in src/vs/sessions/contrib/chat/browser/newSessionPromptOptions.ts (_updateButtons/_select).
