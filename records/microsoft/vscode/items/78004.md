# Issue #78004 — [folding] When you cut a collapsed code block it should stays collapsed when you paste/drop it.

[https://github.com/microsoft/vscode/issues/78004](https://github.com/microsoft/vscode/issues/78004)

## Summary

This remains a valid editor-folding feature request: moving or pasting folded text does not preserve its collapsed state, and no older canonical with the same observable symptom is identified. The Backlog milestone and seven upvotes support leaving it open for an editor-area product decision.

## Change summary

Preserve a collapsed code block's folding state when it is cut and pasted or moved by drag and drop.

## Best solution

Define editor semantics for carrying folding state through text moves, then preserve the corresponding collapsed ranges when the destination can be mapped safely; ordinary copy/paste and edits that cannot retain a reliable range mapping should keep current behavior.

- **Behavior:**

  > When a user moves a collapsed code block by cutting and pasting it, or by editor drag and drop, the corresponding block at the destination remains collapsed. The source range is removed normally, unrelated folding regions keep their state, and operations without a safe one-to-one range mapping retain existing behavior. Acceptance should cover both move mechanisms and confirm that ordinary copy/paste does not unexpectedly transfer transient fold state.
- **Trace:**

  > The issue concerns transient folding state owned by the editor-folding contribution and text movement initiated by editor paste or drag-and-drop paths. https://github.com/microsoft/vscode/issues/201031 is a newer closed report of the drag-and-drop symptom, so it is supporting evidence rather than a valid canonical for this re-reviewed issue. The likely boundary is coordination between the folding model in src/vs/editor/contrib/folding/browser/foldingModel.ts and move operations such as src/vs/editor/contrib/dnd/browser/dnd.ts; do not alter language folding-range computation or persist folds across unrelated edits. The uncertainty begins at the public behavior boundary: whether fold transfer applies only to true moves or also to copied text, and how long the transfer context remains valid between cut and paste.
- **Open decisions:**

  - For cut and paste, should fold state survive only the immediate matching paste, or remain transferable across intervening edits and clipboard operations?
