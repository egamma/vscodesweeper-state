# Issue #115022 — View actions disappear when clicking "..."

[https://github.com/microsoft/vscode/issues/115022](https://github.com/microsoft/vscode/issues/115022)

## Summary

Keep open: the reported native-menu focus path remains plausible in current source, and the only likely covering commit does not reference this team-authored issue, so it cannot support a factual implemented-on-main close.

## Change summary

Opening the overflow menu on a nested view header causes that header's ellipsis action to disappear while the native menu is open.

## Best solution

Ensure a nested view header keeps its actions visible for the complete lifetime of its native overflow menu, then verify the behavior with native custom menus disabled on the affected desktop platforms.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/views/viewPane.ts`, `src/vs/base/browser/ui/splitview/paneview.css`
- **Validation:** With native title-bar/custom menus disabled as appropriate on Windows or Linux, open a viewlet containing multiple nested views, hover a nested view header, and click its ellipsis; the action must remain visible while the native menu is open and return to normal hover visibility after dismissal.
- **Behavior:**

  > When a user opens the overflow menu from a nested view header, the ellipsis and other header actions remain visible for the entire time that the native menu is open. Dismissing the menu restores the normal hover/focus visibility behavior. The top-level view-container toolbar and custom-menu behavior must remain unchanged.
- **Trace:**

  > The confirmed report is https://github.com/microsoft/vscode/issues/115022, with the focus diagnosis recorded at https://github.com/microsoft/vscode/issues/115022#issuecomment-767762121. src/vs/base/browser/ui/splitview/paneview.css hides pane-header actions unless the pane is hovered, contains focus, or has an explicit visibility state. src/vs/workbench/browser/parts/views/viewPane.ts creates the WorkbenchToolBar and prevents the default click behavior on its actions container, while native menus leave the DOM and may remove hover without preserving button focus. Commit https://github.com/microsoft/vscode/commit/6ee4ef1c2dbbe5a8763ccdce796a40be84c7ee8a later added :focus-within visibility but did not reference this issue. First confirm whether current native-menu interaction still lacks focus; keep changes bounded to view-header action visibility and do not make all header actions permanently visible.

## Evidence

- **confirmed symptom:** The reporter supplied two recordings, and the maintainer diagnosis at https://github.com/microsoft/vscode/issues/115022#issuecomment-767762121 identifies the observable path: native menus do not leave focus on the clicked button, while the header actions require hover or focus to remain visible.
- **current source:** src/vs/base/browser/ui/splitview/paneview.css still hides pane-header actions by default and reveals them through pane hover, :focus-within, or explicit focused/always-visible state; src/vs/workbench/browser/parts/views/viewPane.ts still calls preventDefault() on clicks in the actions container.
- **likely covering change:** https://github.com/microsoft/vscode/commit/6ee4ef1c2dbbe5a8763ccdce796a40be84c7ee8a added the pane :focus-within visibility rule shortly after the report, but its commit message does not reference https://github.com/microsoft/vscode/issues/115022 and therefore does not meet the factual-close bar for this team-authored issue.
