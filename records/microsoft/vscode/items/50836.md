# Issue #50836 — Support customisable alias for commands in command palette

[https://github.com/microsoft/vscode/issues/50836](https://github.com/microsoft/vscode/issues/50836)

## Summary

Keep this accepted backlog request open: current command aliases are developer-defined, not user-customizable. The previous implementation proposal was closed over its UI design, not because the requested capability shipped or was rejected outright.

## Change summary

Allow users to find and invoke existing commands through custom aliases while retaining their original names.

## Best solution

Provide user-defined command search aliases without cluttering the command palette or changing command identity and availability. Resolve the configuration and editing experience with the area maintainer, taking the previous preference for the existing gear affordance into account.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts`, `src/vs/platform/quickinput/browser/commandsQuickAccess.ts`, `src/vs/workbench/browser/quickaccess.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** After agreeing on the configuration contract, configure diff-buffer-with-file for the existing compare-with-saved command and touch for explorer.newFile. Verify that each alias finds and invokes its intended command, original names remain searchable, multiple aliases work, and removing an alias removes its search match. Check editor and global commands, localized labels, and unchanged command availability.
- **Behavior:**

  > Users want personal names and abbreviations for existing command-palette commands, without losing access through the original names. The requested examples include diff-buffer-with-file for compare-with-saved and touch for New File, with multiple aliases for a single command. Acceptance should demonstrate that configured aliases resolve to the original command and preserve its existing availability and execution behavior. The configuration and editing experience must be agreed before implementation.
- **Trace:**

  > CommandsQuickAccessProvider.getCommandPicks in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts combines editor and global picks, then attaches a gear that currently opens keyboard-shortcut settings. Global aliases come from original-language command metadata; AbstractEditorCommandsQuickAccessProvider.getCodeEditorCommandPicks in src/vs/editor/contrib/quickAccess/browser/commandsQuickAccess.ts obtains editor aliases from action metadata. AbstractCommandsQuickAccessProvider in src/vs/platform/quickinput/browser/commandsQuickAccess.ts already searches labels and aliases, but neither producer accepts a user mapping. The command-palette settings are registered in src/vs/workbench/browser/workbench.contribution.ts and represented in src/vs/workbench/browser/quickaccess.ts. Preserve command IDs, preconditions, localized-name matching, keybinding behavior, and existing ranking unless the agreed product contract explicitly requires otherwise. https://github.com/microsoft/vscode/pull/139670 was closed unmerged; its maintainer feedback favors avoiding another palette button and leaves the configuration/editing contract unresolved.
- **Open decisions:**
  - Should aliases be stored in a dedicated settings mapping or alongside keyboard-shortcut customization in keybindings.json?
  - Should users edit aliases only through JSON configuration, or should the existing command-palette gear expose an alias-editing interaction?

## Evidence

- **Existing capability does not cover the request:** In src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts, CommandsQuickAccessProvider.getGlobalCommandPicks derives commandAlias from the command title's original-language text. In src/vs/editor/contrib/quickAccess/browser/commandsQuickAccess.ts, getCodeEditorCommandPicks uses editorAction.alias. Neither path reads user-defined aliases.

The command-palette registrations in src/vs/workbench/browser/workbench.contribution.ts cover history, preserved input, suggestions, and chat-related discovery, but not a user alias mapping; these existing search features do not provide arbitrary names such as diff-buffer-with-file or tt.
