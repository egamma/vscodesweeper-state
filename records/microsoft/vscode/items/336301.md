# Issue #336301 — Agent executes thousands of tool calls from one model response without a per-response limit

[https://github.com/microsoft/vscode/issues/336301](https://github.com/microsoft/vscode/issues/336301)

## Summary

Confirmed in source: the Copilot Chat tool-calling loop has no cap on tool calls extracted from a single model response, only a round/iteration limit — a genuinely missing safeguard, not a design choice, so this stays open for a fix.

## Change summary

A single assistant response can contain thousands of tool calls (here, 3,871 memory-tool reads), and VS Code dispatches nearly all of them with no per-response cap, dedup, or early-abort, causing a ~14-minute stall and a token-usage spike.

## Best solution

Add a hard cap (and duplicate-request suppression) on the toolCalls array assembled per model response in extensions/copilot/src/extension/intents/node/toolCallingLoop.ts (the `finishedCb` that pushes `delta.copilotToolCalls` into `toolCalls` around line 1908, and the `toolCallLimit`/`onHitToolCallLimit` machinery around lines 62-75 and 1431-1452, which only bounds fetch iterations, not calls within one iteration); reject/truncate an oversized single-response batch with a recoverable error rather than rendering thousands of progress rows.

## Evidence

- **toolCallLimit is a round limit, not a per-response cap:** extensions/copilot/src/extension/intents/node/toolCallingLoop.ts lines 62-75 define `toolCallLimit`/`onHitToolCallLimit`, and lines 1444-1452 check `i++ >= this.options.toolCallLimit` per outer-loop iteration (i.e. per model round-trip), not per number of tool calls inside one response.
- **no cap when assembling tool calls from one response:** In the same file, lines 1893-1928, the `finishedCb` unconditionally does `toolCalls.push(...delta.copilotToolCalls.map(...))` for every delta chunk of a single fetch response, with no length check, dedup, or truncation before the batch is later executed and rendered.
- **reporter diagnostics:** Issue body: one `assistant.message` contained 3,871 toolRequests (3,781 distinct paths, 90 duplicates); VS Code executed/rendered ~3,870 of them over ~14 minutes before interruption.
- **possible regression:** Author's 2026-09-16 comment reports a 3rd reproduction and suspects this may be a new Insiders regression causing a token-usage spike, but has not yet confirmed a specific commit.
