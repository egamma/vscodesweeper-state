# Issue #336301 — Agent executes thousands of tool calls from one model response without a per-response limit

[https://github.com/microsoft/vscode/issues/336301](https://github.com/microsoft/vscode/issues/336301)

## Summary

Credible, well-diagnosed report from a contributor with persisted-transcript evidence of a single assistant response containing 3,871 tool calls that VS Code dispatched almost entirely without a per-response cap; I couldn't reproduce it myself (intermittent, needs a specific long-running agent/memory-tool scenario) but confirmed via the checkout that no such per-response tool-call limit exists in the agent/tool dispatch code I could find, so this stays open for the chat/agent-sessions area to investigate.

## Change summary

A single model response with thousands of tool calls (here, memory-tool reads) is fully dispatched and rendered with no per-response circuit breaker, flooding chat and burning ~14 minutes on a runaway read batch.

## Best solution

The chat/agent-host tool-dispatch path (e.g. src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts and src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts) should get a sane per-response tool-call cap and/or de-duplication before dispatch, independent of the existing multi-turn continuation limit; needs a design decision from the chat/agent team on the right threshold and UX for a rejected/truncated batch.
