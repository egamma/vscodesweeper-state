# Issue #347802 — Rendering the chat ring eats up 20-30% of the iGPU

[https://github.com/microsoft/vscode/issues/347802](https://github.com/microsoft/vscode/issues/347802)

## Summary

Keep open: the report identifies the animation, affected hardware, and GPU cost sufficiently to retest. Current main disables this border by default but retains its animated rendering path; that does not establish that the reported performance problem is fixed.

## Change summary

The animated chat input border reportedly consumes 20–30% GPU utilization on Intel UHD 770 graphics.

## Best solution

Measure the border's incremental GPU cost on the reported configuration and evaluate the existing static-border proposal at https://github.com/microsoft/vscode/pull/327051 before starting another implementation. Preserve a clear working indicator without sustained excessive rendering work.

Source inspection establishes the rendering mechanism, not its GPU cost.
- **Available mitigation:** src/vs/workbench/contrib/chat/browser/chatProgressConfiguration.ts:16–20 registers chat.progressBorder.enabled with default false. src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts:1056–1071 activates the ring only when that setting is true, motion is not reduced, and a request is running. Disabling the setting avoids the ring but does not demonstrate an efficiency fix when enabled.
