# Issue #325720 — Copilot Chat OTel exports tool call arguments/results (terminal output, file contents) to OTLP regardless of captureContent

[https://github.com/microsoft/vscode/issues/325720](https://github.com/microsoft/vscode/issues/325720)

## Summary

Security-sensitive data-exposure bug, confirmed on current main: tool call arguments/results are attached to the real OTLP-exported span unconditionally, bypassing captureContent. Keeping this open per the hard security-sensitive rule regardless of how clear-cut the fix looks.

## Change summary

gen_ai.tool.call.arguments / gen_ai.tool.call.result (terminal output, file contents, MCP I/O) are exported to OTLP unconditionally, ignoring captureContent=false.

## Best solution

Gate span.setAttribute(GenAiAttr.TOOL_CALL_ARGUMENTS/RESULT) in toolsService.ts on this._otelService.config.captureContent (matching the existing gatedParamAttrs pattern just below), or apply a content-stripping SpanExporter wrapper ahead of the OTLP BatchSpanProcessor so captureContent=false is enforced at export time regardless of what call sites set on the span.
