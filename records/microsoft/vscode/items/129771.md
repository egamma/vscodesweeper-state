# Issue #129771 — Allow to control the sidebar icon size

[https://github.com/microsoft/vscode/issues/129771](https://github.com/microsoft/vscode/issues/129771)

## Summary

Keep this accepted, well-supported request open: current controls do not provide independently adjustable sidebar icon sizes. Activity Bar compact mode offers only a smaller preset, while window zoom changes the rest of the UI.

## Change summary

Allow users to increase or decrease sidebar icon sizes without scaling unrelated UI.

## Best solution

Provide a supported icon-sizing experience that preserves surrounding text and editor scale, with consistent treatment of image and font icons. A maintainer should settle which sidebar surfaces it covers and how it relates to existing Activity Bar presets and broader density work.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/parts/activitybar/activitybarPart.ts`, `src/vs/base/browser/ui/iconLabel/iconlabel.css`, `src/vs/workbench/services/themes/browser/fileIconThemeData.ts`
- **Validation:** After agreeing the supported surfaces, manually exercise smaller, default, and larger icon sizes with image-based and font-based themes. Confirm targeted icons resize without changing editor or unrelated workbench text scale, remain unclipped and clickable, and return to the existing appearance when reset. Check applicable Activity Bar locations and existing compact mode.
- **Behavior:**

  > Users want sidebar icons to be more readable or more compact without zooming the rest of VS Code. The supported control should allow both increasing and decreasing the targeted icons while preserving unrelated text and editor scale. Acceptance should cover image and font icons, unclipped rendering, usable interaction targets, and restoration of the existing default appearance. The exact sidebar surfaces and supported sizing choices remain product decisions.
- **Trace:**

  > The current Activity Bar path uses workbench.activityBar.compact in workbench.contribution.ts and fixed default/compact icon constants in ActivitybarPart; its sizing changes also affect surrounding layout. Sidebar file icons use the shared IconLabel CSS, while fileIconThemeData.ts emits distinct image, mask, and font rules with theme-authored font sizing. These are separate rendering paths, so Activity Bar sizing alone would not establish coverage for semantic file-icon themes mentioned in the report. Preserve existing defaults, theme semantics, unrelated text sizing, and window zoom behavior. Broader density exploration at https://github.com/microsoft/vscode/issues/168671 is relevant design context, not a verified duplicate. The newer numeric Activity Bar request at https://github.com/microsoft/vscode/issues/335202 overlaps only that surface; https://github.com/microsoft/vscode/issues/247466 already consolidates smaller Activity Bar feedback into this report.
- **Open decisions:**
  - Should independent sizing cover sidebar file/folder icons, Activity Bar navigation icons, or both?
  - Should the supported control expose numeric sizes or a bounded set of smaller/default/larger presets, and how should it coexist with workbench.activityBar.compact?
