# Issue #336545 — Allow extension keybindings to inherit from another command

[https://github.com/microsoft/vscode/issues/336545](https://github.com/microsoft/vscode/issues/336545)

## Summary

Keep open: current keybinding contributions do not support inheriting another command's effective bindings. This is an API-proposal tracking issue, so its disposition belongs to the API owners.

## Change summary

Allow extension commands to inherit another command's effective shortcuts and arguments while retaining their own execution context and user overrides.

## Best solution

Define and review a keybinding contribution contract that projects effective source bindings into a target context, honoring source removals, target overrides, arguments, and shortcut-editor provenance. Keep this proposal open through the API owners' finalization or abandonment decision.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/services/keybinding/browser/keybindingService.ts defines keybindingType with command, args, key, platform variants, and when, but no inheritFrom. WorkbenchKeybindingService._asCommandRule consumes a physical platform-specific key and returns undefined when none is supplied; it does not derive shortcuts from another command.
- **Effective binding resolution:** WorkbenchKeybindingService._getResolver constructs defaults and user overrides separately. src/vs/platform/keybinding/common/keybindingResolver.ts combines them and applies handleRemovals, but contains no source-command-to-target-command projection. Existing customizations therefore do not provide the requested automatic inheritance.
- **Related work is not completion:** https://github.com/microsoft/vscode/pull/329414 is merged and registers Markdown editor commands for customization. https://github.com/microsoft/vscode-packages/issues/292 is closed and requests Markdown line-operation parity. Neither establishes the general inheritance contract or propagation of source-command customizations requested here.
