# Issue #336545 — Allow extension keybindings to inherit from another command

[https://github.com/microsoft/vscode/issues/336545](https://github.com/microsoft/vscode/issues/336545)

## Summary

Keep open: current extension keybinding contributions cannot inherit another command's effective bindings, so the requested capability remains missing. This is also an api-proposal tracking issue, whose completion belongs to the API owners.

## Change summary

Allow extension commands to inherit another command's effective shortcuts and arguments while using their own execution context and implementation.

## Best solution

Have the keybindings and API owners settle the contribution contract for source-context matching, projection precedence, and inherited-binding visibility. The resulting capability should propagate source customizations and removals without conflating source and target command execution.

- **Existing contribution surface does not cover inheritance:** src/vs/workbench/services/keybinding/browser/keybindingService.ts defines keybindingType with required command and key fields, plus args, when, and platform-specific key strings; it has no inheritFrom property. WorkbenchKeybindingService._asCommandRule consumes those explicit fields and returns undefined when no physical platform binding is supplied. The proposed inheritance-only example therefore does not create a binding through this path.
- **Effective-binding projection is absent:** WorkbenchKeybindingService._getResolver in src/vs/workbench/services/keybinding/browser/keybindingService.ts resolves defaults and user overrides independently and passes them to KeybindingResolver. In src/vs/platform/keybinding/common/keybindingResolver.ts, the constructor concatenates defaults and overrides, applies handleRemovals, and indexes the resulting rules; this path does not project one command's effective bindings onto another command.
- **Related work is not the requested inheritance mechanism:** https://github.com/microsoft/vscode/pull/329414 is merged and registers Markdown editor commands for shortcut customization. https://github.com/microsoft/vscode-packages/issues/292 is closed and requests Markdown move/copy-line command parity. Neither related item's stated scope establishes propagation of source-command user bindings and removals to distinct target commands.
