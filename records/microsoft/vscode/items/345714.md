## Evidence

- **Current source defect:** At checkout HEAD 53d2211d37ea4112096159c6efb75d513c8d975e, src/vs/editor/common/core/text/textLength.ts, TextLength.ofText, iterates strings with for...of and increments column once per yielded code point. A supplementary character therefore contributes one column rather than two UTF-16 code units.
- **Inverse corruption traced:** src/vs/editor/common/core/edits/textEdit.ts:157–176 constructs inverse replacements from getNewRanges(), which uses TextLength.ofText(replacement.text). Inserting the reported emoji at column 2 consequently produces an inverse range ending at column 3 rather than 4, deleting only its high surrogate.
- **Existing-text loss traced:** src/vs/editor/common/core/edits/textEdit.ts:725–754 converts common-prefix and suffix string offsets through TextLength.ofText. For the reported replacement of '😀a' with '😀ab', the common prefix has three UTF-16 units but is counted as two columns, reducing the replacement to overwriting the existing 'a' with 'b'.
- **Multicursor adoption:** src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts:1232–1260, getSecondaryEdits, reduces the primary replacement with removeCommonPrefixAndSuffix before translating its offsets to secondary cursors. This propagates the destructive reduced replacement to the secondary line; the normal inline-completion path calls this function at lines 675 and 691.
