# Issue #262237 — Reference Highlight stop works (get immediately unreferenced) after clicking in any Output pane that updates

[https://github.com/microsoft/vscode/issues/262237](https://github.com/microsoft/vscode/issues/262237)

## Summary

Still reproduces on current main. The wordHighlighter has a guard against output-scheme content changes (line 288), but the blur handler (lines 329–341) and/or focus-change interactions when the Output pane scrolls still clear highlights in the original editor. No fix has landed since the report; Yoyokrazy confirmed repro but hasn't submitted a fix yet.

## Change summary

Reference highlights in a code editor immediately disappear when a streaming Output pane updates or scrolls, because the wordHighlighter's blur/focus handling clears decorations.

## Best solution

Fix the blur/focus interaction in `src/vs/editor/contrib/wordHighlighter/browser/wordHighlighter.ts` so that Output pane updates (auto-scroll, content streaming) do not trigger `_stopAll()` on unrelated editors. The `onDidBlurEditorWidget` handler (line 329) and possibly the content-change handler need additional guards for the output scheme case — likely checking whether the newly-focused editor is an output channel editor before clearing highlights on the original editor.
