# Issue #338700 — Add way to add text on next line with onEnter rules

[https://github.com/microsoft/vscode/issues/338700](https://github.com/microsoft/vscode/issues/338700)

## Summary

Real, currently-unsupported capability: with `indentOutdent` + `appendText`, the appended text is merged into the *increased-indent* line's indentation (by design — this is exactly how the bundled `/** | */` JSDoc rule works), not placed on a new line below with the cursor left on a blank middle line as requested. Supporting the requested shape needs a new field or syntax so it doesn't break the existing JSDoc-style usage, which is a design decision for a maintainer.

## Change summary

Allow an onEnterRule using `indentOutdent` + `appendText` to insert the appended text on a new line below the cursor (not already present via `afterText`), leaving the cursor on an indented blank line in between, instead of merging it into the same line as the cursor.

## Best solution

Design a new onEnterRule mechanism (e.g. a distinct field, or a variant of `indentOutdent` that treats `appendText` as content for a line below rather than as indentation) and implement it in EnterOperation._enter's `IndentOutdent` branch in src/vs/editor/common/cursor/cursorTypeEditOperations.ts, taking care not to change behavior for existing consumers like extensions/php/language-configuration.json's `/** | */` rule.

- **Trace:**

  > EnterOperation._enter's IndentOutdent branch (src/vs/editor/common/cursor/cursorTypeEditOperations.ts:565-574) builds `increasedIndent = indentation + appendText` as the new middle line and positions the cursor at its end — this is intentional, since the bundled PHP JSDoc rule (extensions/php/language-configuration.json) relies on appendText becoming the new line's indentation/content while the existing `afterText`-matched line supplies the closer below. The open question is what new field/behavior lets an author request appendText be emitted as literal content on a fresh line below an empty, cursor-occupied middle line, without altering this existing combo's behavior.
- **Open decisions:**
  - Should this be a new onEnterRule action field (e.g. separate from appendText) or a variant of indentAction, and what is its name/schema?
  - Should the existing indentOutdent + appendText combo (used for JSDoc `/** | */`) remain unchanged, with the new behavior only triggered by a different config shape?

## Evidence

- **current semantics:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts lines 565-574: for IndentAction.IndentOutdent, `increasedIndent = indentation + appendText` becomes the content of the newly inserted middle line, and the cursor is placed at the end of that line via ReplaceCommandWithOffsetCursorState — exactly matching the reporter's described (undesired) `begin\nend|` outcome.
- **existing design intent:** extensions/php/language-configuration.json lines ~109-116 use the identical `indentOutdent` + `appendText: " * "` combo for the `/** | */` JSDoc rule, where appendText is deliberately meant to become the new line's content/indentation while an existing `afterText` match (` */`) supplies the closing text below — so appendText already serves a different, load-bearing purpose that a behavior change must not break.
- **related issue:** https://github.com/microsoft/vscode/issues/583 (open) requests a related but distinct capability (autoClosingPairs-like begin/end support) and does not own this specific onEnterRules request.
