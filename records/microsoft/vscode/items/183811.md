# Issue #183811 — 'Share...' shouldn't overwrite clipboard automatically

[https://github.com/microsoft/vscode/issues/183811](https://github.com/microsoft/vscode/issues/183811)

## Summary

Keep open: the Share command still overwrites the clipboard before presenting its dialog, so the requested explicit-copy interaction remains missing. This is accepted, team-authored backlog work, and no qualifying fix or canonical duplicate was found.

## Change summary

Show the generated sharing link with explicit Copy to Clipboard, Open Link, and Close actions instead of copying automatically.

## Best solution

Make the workbench Share dialog preserve the existing clipboard until the user explicitly chooses to copy, while retaining link-opening and dismissal actions. Keep provider selection and link generation unchanged.

- **Behavior:**

  > Invoking Share from the command or command-center button must not replace clipboard contents merely because a sharing result was generated. For a link result, the dialog displays the link and offers explicit Copy to Clipboard, Open Link, and Close actions. Only explicit copying changes the clipboard; opening or dismissing preserves its prior contents. Text-valued sharing results must likewise require explicit copying without gaining a link-opening action.
