# Issue #285872 — Custom Agent references multiple tools using 'search'

[https://github.com/microsoft/vscode/issues/285872](https://github.com/microsoft/vscode/issues/285872)

## Summary

Team-authored bug (MEMBER). When multiple tools share the same short reference name (e.g., 'search' from both a built-in tool and an MCP server extension), the custom agent `tools:` header matches ambiguously. The tool resolution pipeline (`getToolByName`, `getFullReferenceNames`) does not surface disambiguation for short names that collide across providers. Keeping open per hard keep-open rule for team-authored issues.

## Change summary

Configuring `tools: [search]` in a custom agent references multiple tools with the same short name from different providers, causing ambiguous tool resolution.

## Best solution

The tool reference resolution in prompt files should either require fully qualified tool names (e.g., `azure-mcp/search`) when a short name is ambiguous, or surface a clear diagnostic/warning in the prompt validator (`promptValidator.ts`) when a short tool name matches multiple registered tools. The `getToolByName` method in `languageModelToolsService.ts` returns only the first match — this needs to account for collisions, and the prompt validator's `validateVSCodeTools` should warn about ambiguous references.
