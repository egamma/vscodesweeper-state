# Issue #213669 — Markdown preview stops updating with unsaved content if dragged out to a new Window (and back again)

[https://github.com/microsoft/vscode/issues/213669](https://github.com/microsoft/vscode/issues/213669)

## Summary

Still reproduces on main: when a webview panel is moved to a new window, the overlay webview disposes and recreates the underlying webview element (overlayWebview.ts:137), but the markdown preview extension's content synchronization with unsaved document changes may not survive this recreation. No fix commit references this issue.

## Change summary

Markdown preview stops reflecting unsaved document changes after being dragged to an auxiliary window and back.

## Best solution

The webview recreation path in OverlayWebview.claim() (src/vs/workbench/contrib/webview/browser/overlayWebview.ts) clears and recreates the webview when moving windows, but the markdown preview extension's live-update pipeline doesn't fully re-establish after the new webview is created. The fix likely needs to ensure that extensions' webview panels fire appropriate lifecycle events (or re-post content) when the underlying webview element is recreated during a window transfer, or the markdown preview needs to detect and refresh when its webview is reclaimed.
