# Issue #340055 — Readonly untitled custom editors remain dirty and cannot close after discard

[https://github.com/microsoft/vscode/issues/340055](https://github.com/microsoft/vscode/issues/340055)

## Summary

Team-authored, freshly filed (same day) bug with a thorough root-cause trace confirmed directly against current main source; no fix has landed, so this stays open regardless of the detailed diagnosis.

## Change summary

A readonly untitled custom editor (e.g. image preview) can be marked dirty from initial bytes, but revert()/saveCustomEditor() both no-op when `_editable` is false, so Don't Save never clears the dirty flag and the tab refuses to close.

## Best solution

Fix MainThreadCustomEditorModel's lifecycle so a non-editable model doesn't acquire unclearable dirty ownership: either avoid setting `_isDirtyFromContentChange` for non-editable models at construction, or let an explicit discard clear it without routing through the editable-only revert/save RPC guards, per the reporter's own 'Implementation direction' section.

- **Trace:**

  > Root cause is confirmed in mainThreadCustomEditorModel: `create()` sets startDirty from `!!untitledDocumentData` regardless of the extension-reported `editable` flag; the constructor stores that into `_isDirtyFromContentChange` without gating on `_editable`; `isDirty()` returns true for that flag unconditionally; and both `revert()` and `saveCustomEditor()` short-circuit with `if (!this._editable) return;` before clearing it, so Don't Save's `editor.revert()` + `isDirty()` veto in editorGroupView.ts never resolves. - **Open decisions:**
