# Issue #340055 — Readonly untitled custom editors remain dirty and cannot close after discard

[https://github.com/microsoft/vscode/issues/340055](https://github.com/microsoft/vscode/issues/340055)

## Summary

Keep open: current source still allows readonly untitled custom models to become dirty while making revert a no-op, so Don't Save vetoes closing. Explicit discard must work without suppressing dirty warnings or concealing the companion text-preservation defect.

## Change summary

Allow explicit discard to close stranded dirty readonly custom editors while preserving retained content on Cancel.

## Best solution

Establish safe content ownership during custom-model creation and a supported explicit-discard lifecycle for already-stranded readonly models. Preserve the editor group's dirty-state veto and editable-provider behavior, coordinating creation-time ownership with https://github.com/microsoft/vscode/issues/340054.
