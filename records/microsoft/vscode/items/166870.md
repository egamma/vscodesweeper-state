# Issue #166870 — "Find All References" open in a tab editor as with "Search"

[https://github.com/microsoft/vscode/issues/166870](https://github.com/microsoft/vscode/issues/166870)

## Summary

Keep this accepted feature request open: current built-in reference results support peek and sidebar presentation, but not the requested editor tab. The extension workaround and the older multiple-results request do not establish that this specific capability has shipped or is already tracked by an equivalent canonical.

## Change summary

Allow Find All References results to open in an editor tab, analogous to Search's Open Results in Editor.

## Best solution

Provide an optional editor-tab presentation of semantic reference results with navigation to the exact source locations, while preserving existing peek and sidebar behavior. Establish the results tab's refresh and persistence contract before implementing the integration.

- **Behavior:**

  > Users can open Find All References results in an editor tab analogous to Search's Open Results in Editor. The tab displays semantic reference results and supports navigation to the corresponding source locations. Existing peek and sidebar presentations remain available and unchanged. Acceptance must cover cross-file results, exact-range navigation, and the agreed behavior when another reference search runs, source files change, or the window reloads.
- **Trace:**

  > extensions/references-view/package.json exposes references.preferredLocation only as peek or view. In extensions/references-view/src/references/index.ts, the find command invokes vscode.executeReferenceProvider through ReferencesTreeInput, while the view override accepts supplied locations; both pass their input to SymbolsTree.setInput. extensions/references-view/src/tree.ts maintains one active sidebar tree input, and extensions/references-view/src/references/model.ts groups semantic Location/LocationLink results by file. Search's existing editor export lives in src/vs/workbench/contrib/searchEditor/browser/searchEditorActions.ts:createEditorFromSearchResult and requires a query-backed ISearchResult, so it is not an existing reference-results export. Preserve semantic provider results rather than substituting textual searches, and do not change existing peek/sidebar defaults. https://github.com/microsoft/vscode/issues/148558 concerns retaining multiple results and is relevant design context, not a verified duplicate. The trace establishes the presentation gap but does not settle the editor result lifecycle or the integration boundary.
- **Open decisions:**
  - Should a reference-results tab be a retained snapshot, or support rerunning the original semantic reference query after source edits?
  - Should reference-results tabs survive window reload and support saving, like Search Editors, or remain session-only?
