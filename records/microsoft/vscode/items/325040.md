# Issue #325040 — Rendering Fail After Zoom+Scroll

[https://github.com/microsoft/vscode/issues/325040](https://github.com/microsoft/vscode/issues/325040)

## Summary

Verified duplicate: the open canonical issue reports the same editor-GPU rendering corruption after font-size changes and the identical texture-atlas limit error. This report adds useful zoom, scrolling, inline-suggestion, and GPU details that should be carried into the canonical discussion.

## Change summary

Repeatedly zooming and scrolling with experimental editor GPU acceleration eventually exhausts the glyph texture atlas and renders black rectangles over editor content.

## Best solution

Consolidate diagnosis and remediation in https://github.com/microsoft/vscode/issues/301420, ensuring that font-size changes do not retain obsolete glyph sets until the shared atlas reaches its 16-page limit.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/301420 is open and reports corrupted editor text after changing font sizes; its attached log contains the identical `Attempt to create a texture atlas page past the limit 16` failure.
- **same root cause:** Current source recreates the GlyphRasterizer when editor font size changes in src/vs/editor/browser/viewParts/viewLinesGpu/viewLinesGpu.ts, while the shared atlas is cleared for device-pixel-ratio and theme changes in src/vs/editor/browser/gpu/viewGpuContext.ts but not for font-size changes.
- **failure path:** src/vs/editor/browser/gpu/atlas/textureAtlas.ts retains glyphs keyed by rasterizer cache key and throws the reported error when its shared atlas reaches TextureAtlas.maximumPageCount, currently 16.
- **unique evidence:** This report demonstrates that repeated Ctrl+mouse-wheel zoom plus scrolling can trigger the exhaustion on Windows with Intel and NVIDIA GPUs, and that multi-line inline suggestions are corrupted along with normal editor text.
