# Issue #325040 — Rendering Fail After Zoom+Scroll

[https://github.com/microsoft/vscode/issues/325040](https://github.com/microsoft/vscode/issues/325040)

## Summary

Source-reproducible bug: the GPU texture atlas is never cleared when the editor font size changes (via Ctrl+Mouse Wheel zoom or settings), so each distinct font size accumulates a full set of warmed-up glyphs until the 16-page atlas limit is exceeded, producing black rectangles and the logged error.

## Change summary

Repeated editor-level zoom changes with GPU acceleration enabled exhaust the texture atlas page limit (16 pages), causing black rectangles in the editor.

## Best solution

Clear the texture atlas when the glyph rasterizer is recreated due to a font-size or font-family change. The atlas is already cleared on DPR change and theme change (in `viewGpuContext.ts` lines 127 and 130–133), but no equivalent clear exists in `viewLinesGpu.ts:_refreshGlyphRasterizer()` when the rasterizer changes. Adding `ViewGpuContext.atlas?.clear()` there would prevent stale glyphs from accumulating across zoom levels.

## Evidence

- **atlas warm-up accumulates across rasterizers:** In `src/vs/editor/browser/gpu/atlas/textureAtlas.ts` lines 126–129, `_warmedUpRasterizers` tracks rasterizer IDs; a new rasterizer ID triggers `_warmUpAtlas`, which enqueues all printable ASCII × all token colors × 10 sub-pixel offsets (lines 167–204). Without an atlas clear, each zoom level's warm-up adds to the existing pages.
- **hard limit throws:** `src/vs/editor/browser/gpu/atlas/textureAtlas.ts` line 147–148: `if (this._pages.length >= TextureAtlas.maximumPageCount) throw new Error(...)` — this is the exact error the reporter sees ('Attempt to create a texture atlas page past the limit 16').

Ctrl+Mouse Wheel editor zoom changes the editor font size but does NOT change `window.devicePixelRatio`, so neither clear triggers.
