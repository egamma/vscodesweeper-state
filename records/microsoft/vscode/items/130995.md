# Issue #130995 — Blank space above integrated terminal when using decimal value for window.zoomLevel

[https://github.com/microsoft/vscode/issues/130995](https://github.com/microsoft/vscode/issues/130995)

## Summary

Still reproduces on main: the terminal row-count calculation in `computeTerminalDimensions` uses `Math.floor` on scaled dimensions that can diverge from xterm.js's internal layout when `window.devicePixelRatio` is fractional (caused by decimal `window.zoomLevel`), producing blank space above the terminal content. No fix has been committed.

## Change summary

Blank space appears above the integrated terminal content when `window.zoomLevel` is set to certain decimal values, because VS Code's row calculation and xterm.js's internal rendering disagree on how many rows fit.

## Best solution

Align the row-height rounding in `computeTerminalDimensions` (src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts, around line 1112–1115) with xterm.js's internal cell-size computation so that fractional `devicePixelRatio` values don't produce a rows×lineHeight total that is shorter than the available container height. The fix should ensure the `xterm-screen` element fills the container without a gap.
