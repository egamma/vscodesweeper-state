# Issue #324356 — Using find references in the scm diff view doesn't currently work (possibly by design or bug)

[https://github.com/microsoft/vscode/issues/324356](https://github.com/microsoft/vscode/issues/324356)

## Summary

Keep open as a request to support TypeScript reference navigation from staged diffs: current source explicitly excludes git resources. Opening the working-tree file avoids unstaging, but does not deliver navigation within the staged snapshot.

## Change summary

Support Find All References for TypeScript symbols in read-only staged SCM diffs.

Define and support reference navigation from staged TypeScript snapshots without conflating their contents or positions with the working-tree document. The TypeScript language-feature owner should settle snapshot semantics before enabling git resources broadly.

- **Proposed comment:**

  > Thanks for the detailed report and investigation. The TypeScript extension currently excludes `git` resources, which explains the empty reference results in staged diffs. Supporting these snapshots needs care when staged content differs from the working tree; mapping both to the same TypeScript file path does not preserve that distinction.

  > You can use `git.openFile` to open the working-tree file and find references without unstaging anything. That is a workaround rather than support for references within the staged snapshot, so this request should remain open.

- **Why Find All References returns no results:** extensions/typescript-language-features/src/languageFeatures/references.ts registers TypeScriptReferenceSupport against selector.syntax, which languageProvider.ts constructs without scheme restrictions. provideReferences returns [] when toOpenTsFilePath fails; bufferSyncSupport.ts, openTextDocument, rejects git documents because toTsFilePath returns undefined. This explains the available command producing no results without establishing that snapshot semantics are already supported.
- **Reporter patch needs snapshot safeguards:** extensions/git/src/uri.ts represents both path and ref in GitUriParams. The proposed patch discards ref and maps every Git snapshot to the working-tree path. bufferSyncSupport.ts keys synced buffers through toTsFilePath, and SyncedBuffer.open sends document.getText() as fileContent; aliasing these documents can conflate staged, historical, and working-tree content. The newline-only example does not establish correctness when those versions differ.

This permits reference navigation in the working-tree file while preserving staged changes, but does not provide references from the staged snapshot itself.
