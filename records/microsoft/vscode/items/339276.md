# Issue #339276 — A single MCP tool with an incomplete (but JSON-Schema-legal) array parameter blocks registration of every tool from that server

[https://github.com/microsoft/vscode/issues/339276](https://github.com/microsoft/vscode/issues/339276)

## Summary

Confirmed on main: normalizeToolSchema in the bundled Copilot Chat extension throws for any array-typed parameter missing `items`, and that throw propagates out of the whole tool-list normalization call used to build each chat request's `tools` array — so one malformed tool from one MCP server aborts the entire request, not just that tool.

## Change summary

An MCP tool whose input schema has a JSON-Schema-legal array parameter with no `items` causes Copilot's tool-schema validator to throw, which blocks registration/use of every tool (from every server) for the whole chat turn.

## Best solution

In extensions/copilot/src/extension/tools/common/toolSchemaNormalizer.ts, make the array/`items` rule consistent with every other rule in jsonSchemaRules (which normalize via `onFix` rather than throw): default a missing `items` to `{}` (an empty/unconstrained schema, which is JSON-Schema-equivalent to omitting items and still satisfies strict-model array requirements) instead of throwing. This also fixes the actual blast-radius bug, since the per-tool try/catch in normalizeToolSchema (lines 29-49) currently just rewraps and rethrows rather than skipping the offending tool, so today nothing is actually isolated per-tool.
