# Issue #339276 — A single MCP tool with an incomplete (but JSON-Schema-legal) array parameter blocks registration of every tool from that server

[https://github.com/microsoft/vscode/issues/339276](https://github.com/microsoft/vscode/issues/339276)

## Summary

Verified duplicate of the older, open, already-assigned issue #325618, which reports the identical root cause (a single array-type tool parameter missing `items` throws and blocks registration of every tool from that MCP server) and proposes the same two fixes; consolidating avoids splitting the same fix across two threads.

## Change summary

An MCP tool with a valid-but-unconstrained array parameter (no `items`) throws in schema normalization and blocks every tool from that server, not just the offending one.

## Best solution

Fix `normalizeToolSchema` in extensions/copilot/src/extension/tools/common/toolSchemaNormalizer.ts (jsonSchemaRules, line ~101-106) to either treat a missing `items` as an unconstrained array per JSON Schema, or catch the per-tool error inside the for-loop in `normalizeToolSchema` (lines 29-50) and drop only the offending tool instead of rethrowing out of the whole batch; track and land this under the canonical issue https://github.com/microsoft/vscode/issues/325618, which is already assigned.
