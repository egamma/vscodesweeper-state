# Issue #342823 — Disconnecting / Detaching with multiple debug sessions

[https://github.com/microsoft/vscode/issues/342823](https://github.com/microsoft/vscode/issues/342823)

## Summary

The Call Stack row's Disconnect dropdown loses the command argument position that identifies its session, so the handler falls back to the focused session instead. This defect remains in current main and should go to the debug area.

## Change summary

Disconnecting from a Call Stack session row should detach that session, not another debug session.

## Best solution

Make the Call Stack row's secondary debug actions honor the originating session consistently with its primary action, while preserving focused-session targeting for the global debug toolbar.
