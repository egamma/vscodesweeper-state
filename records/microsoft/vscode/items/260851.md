# Issue #260851 — Support for MSYS2 Git breaks in version 1.103 (The folder currently open doesn't have a git repository)

## Summary

Keep open: the reporter's logs and an independent confirmation establish the MSYS2 Git repository-discovery regression, and current source retains the failing invocation. An open PR explicitly targets this issue, so it should remain open while that fix is reviewed and validated.

## Change summary

Restore discovery of valid repositories when VS Code invokes MSYS2 Git on Windows and superproject detection fails.

## Best solution

Review https://github.com/microsoft/vscode/pull/317226 and validate it against the reporter's Windows/MSYS2 configuration before landing. Repository discovery should tolerate failure of optional superproject detection without masking genuine repository-discovery errors or changing successful submodule and worktree classification.

## Evidence

- **Confirmed regression:** https://github.com/microsoft/vscode/issues/260851#issuecomment-3214407536 shows the same MSYS2 Git 2.50.0 opening a repository in VS Code 1.102.3, but failing in 1.103.2 with 'fatal: ls-tree returned unexpected return code 127'. Another user confirms the same output at https://github.com/microsoft/vscode/issues/260851#issuecomment-3253223601.
- **Detailed failing flow:** https://github.com/microsoft/vscode/issues/260851#issuecomment-3628183194 confirms git.path selects C:\msys64\usr\bin\git.exe. In 1.106.3, repository-root detection succeeds, but 'rev-parse --git-dir --git-common-dir --show-superproject-working-tree' exits 128 despite stdout containing '.git\n.git\n'; repository discovery consequently reports zero repositories.
- **Current source:** extensions/git/src/git.ts:566-575 still appends --show-superproject-working-tree for Git >=2.13.0 and awaits the combined command without fallback. Its execution path rejects nonzero exit codes at lines 667-674. extensions/git/src/model.ts:672 awaits getRepositoryDotGit before opening the repository, and the enclosing catch logs the failure rather than opening it.
- **Regression introduction:** The diff of https://github.com/microsoft/vscode/commit/6c8a25ae47508ad3152de7e6269b64f993e53859 replaces the original two-flag metadata query with the combined superproject query. The maintainer identifies this as the suspected regression at https://github.com/microsoft/vscode/issues/260851#issuecomment-3642155272. This is an introducing commit, not a fix.
- **Environment distinction and withdrawn workaround:** Both commands succeed when run manually in the reporter's terminal, as recorded at https://github.com/microsoft/vscode/issues/260851#issuecomment-3642164578 and acknowledged by the maintainer at https://github.com/microsoft/vscode/issues/260851#issuecomment-3642230737. The PATH suggestion at https://github.com/microsoft/vscode/issues/260851#issuecomment-3642083777 was explicitly withdrawn as a general solution; it does not establish resolution.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/317226 was verified OPEN with no merge commit and explicitly says 'Fixes #260851'. It proposes retrying the metadata query without superproject detection; its test plan still awaits confirmation on Windows with MSYS2 Git. An unmerged fix is not grounds for closing the issue or launching a competing agent implementation.
- **Canonical search:** A repository-scoped search for 'MSYS2 git' returned this issue and older closed reports, but no verified older open canonical for this regression. The keyword candidate https://github.com/microsoft/vscode/issues/70963 concerns ignored-file decoration rather than repository discovery and does not establish a duplicate.
