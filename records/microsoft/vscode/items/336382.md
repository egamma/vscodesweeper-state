## Summary

Fresh, plausible-sounding technical gap in the BYOK/Language Model API around preserving full reasoning/thinking history across a session for third-party models — no maintainer signal yet and no duplicate found, so this should stay open for area triage.

## Change summary

Requests that VS Code's chat completion BYOK and Language Model extension API let providers persist and resend the full `reasoning_content` history (not just within the current tool-call loop) for models like Kimi K3 that need it for optimal performance.

## Best solution

Have the model-byok/chat area owners assess whether the OpenAI-compatible BYOK endpoint (extensions/copilot/src/extension/byok/node/openAIEndpoint.ts) and the public Language Model API's thinking-part plumbing (src/vs/workbench/contrib/chat/common/languageModels.ts, extensions/copilot/src/platform/thinking/common/thinking.ts) should retain reasoning content for the full session rather than only the active tool-calling turn; a concrete design/decision from that team is needed before any change.
