[https://github.com/microsoft/vscode/issues/344862](https://github.com/microsoft/vscode/issues/344862)

## Summary

Current source still awaits a full remote inventory read for every local extension in an uninstall batch. Keep this open while the linked implementation candidate is reviewed; it has not merged.

## Change summary

## Evidence

- **Current source confirms repeated serial reads:** In src/vs/workbench/services/extensionManagement/common/extensionManagementService.ts, uninstallExtensions groups local items and passes them to uninstallInServer. Its local-with-remote branch awaits remote extensionManagementService.getInstalled(ExtensionType.User) inside the per-extension loop, before invoking the local server's uninstallExtensions. A dependency-free batch of N local items therefore incurs N sequential remote inventory reads.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/344866 is verified OPEN with mergedAt null and explicitly says Fixes #344862. Its description proposes one reserved inventory per local batch and coordination through physical deletion, but an open PR is not a landed fix.
- **Acceptance boundary:** https://github.com/microsoft/vscode/issues/344862 explicitly requires dependency consistency through local deletion, not merely a reused snapshot or final recheck. It distinguishes this work from mixed local/remote removal ordering in https://github.com/microsoft/vscode/issues/343168 and excludes eliminating all single-item coordination overhead.
