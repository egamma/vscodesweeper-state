# Issue #329618 — fix: use fresh service accessor when lazily initializing chat attachment context (fixes #329610)

[https://github.com/microsoft/vscode/issues/329618](https://github.com/microsoft/vscode/issues/329618)

## Summary

Verified on current main: `hookUpSymbolAttachmentDragAndContextMenu`'s lazy `ensureContextKeyService` closure (chatAttachmentWidgets.ts:1947-1951) reuses the `ServicesAccessor` captured from the original `invokeFunction` call to invoke `setResourceContext(accessor, ...)` after that invocation has returned, which throws the illegal-state error described in the linked telemetry issue microsoft/vscode#329610. The proposed fix (wrap the call in a fresh `instantiationService.invokeFunction(...)`, matching the existing pattern at line 1931) is correct and minimal.

## Change summary

Right-clicking a chat symbol attachment/inline anchor throws 'Illegal state: service accessor is only valid during the invocation of its target method' because the lazy context-menu closure reuses an expired ServicesAccessor.

## Best solution

Land the fix in `setResourceContext`'s caller: change `ensureContextKeyService` in chatAttachmentWidgets.ts to obtain a fresh accessor via `instantiationService.invokeFunction(accessor => setResourceContext(accessor, scopedContextKeyService!, attachment.value.uri))`, consistent with the dragstart handler a few lines above; a maintainer should open a PR from the already-pushed branch `fix/chat-attachment-stale-accessor-329610-13e64cb6c8a0f6d8` since automated PR creation failed here.
