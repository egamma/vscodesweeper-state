# Issue #209500 — Image attachments in markdown are not uniquely named

[https://github.com/microsoft/vscode/issues/209500](https://github.com/microsoft/vscode/issues/209500)

## Summary

Keep open: notebook attachment names are still disambiguated only within each cell, not uniquely across the notebook, and pasted images still receive filename-derived alt text. Existing Markdown file-naming customization and the related cell-copy issue do not cover this notebook-specific request.

## Change summary

Generate unique names for pasted notebook image attachments and avoid inserting meaningless filename captions as alt text.

## Best solution

Provide notebook-wide unique identifiers for newly pasted image attachments in the built-in ipynb paste provider, while preserving existing attachment references. Decide the default alt-text behavior with accessibility and downstream caption rendering in mind.

## Evidence

- **Current naming behavior:** https://github.com/microsoft/vscode/blob/main/extensions/ipynb/src/notebookImagePaste.ts: buildAttachment uses the supplied filename and checks collisions only against cell.metadata.attachments, adding numeric suffixes or reusing identical image data. Separate cells can therefore retain the same image.png name; this does not satisfy notebook-wide unique naming.
- **Alt-text behavior:** In the same file, DropOrPasteEditProvider.createInsertImageAttachmentEdit calls insertText.appendPlaceholder(`${filename}`) between the image's square brackets. The default alt text remains the attachment filename, although the inserted placeholder can be edited manually.
- **Existing-capability check:** https://github.com/microsoft/vscode/blob/main/extensions/ipynb/package.json exposes ipynb.pasteImagesAsAttachments.enabled, but no attachment-naming or default-alt-text setting. The paste provider does not consult markdown.copyFiles.destination.
- **Related naming request is not a canonical:** https://github.com/microsoft/vscode/issues/183560 is older and open, but requests naming templates for external image files pasted into ordinary Markdown. Its markdown.copyFiles.destination discussion does not cover cell-metadata attachment keys or the notebook alt-text request, so it does not establish a duplicate under the re-review bar.
- **Linked report concerns different behavior:** https://github.com/microsoft/vscode/issues/209455 was closed as a duplicate of the open https://github.com/microsoft/vscode/issues/200898. Those reports concern losing attachment metadata when copying or splitting cells, not generating unique names; changing names alone would not preserve missing metadata.
