# Issue #341533 — Agent session stays locked after a long-running turn completes

[https://github.com/microsoft/vscode/issues/341533](https://github.com/microsoft/vscode/issues/341533)

## Summary

Thanks for the detailed report. The lock is held inside the native copilot-runtime, not in VS Code's JavaScript Agent Host, so the owner of the root cause is likely the Copilot SDK/runtime. The lock-holder diagnostics rotated out, so the cause is still unconfirmed. The maintainer is already following up and the report is recent, so it stays open.

## Change summary

After a long turn, the native Copilot runtime session lock times out publishing the final event, and all later turns in that session fail with modelSelectionFailed until the Agent Host is restarted.

## Best solution

Capture the native process log with held_by on the next occurrence (Export Agent Host Debug Logs) and fix the lock leak in the Copilot runtime. In the Agent Host, recover or recreate the provider session after a session-lock timeout and surface the underlying error rather than modelSelectionFailed.
