# Issue #247137 — UX: Custom model picker doesn't behave like native

[https://github.com/microsoft/vscode/issues/247137](https://github.com/microsoft/vscode/issues/247137)

## Summary

The picker has gained mouse-down opening, active styling, and action-based model management, but current source still cannot complete selection with a native press-drag-release gesture and does not clear the highlighted row when the pointer leaves. The older related issue is broader and does not meet the stronger same-symptom duplicate bar for this re-review.

## Change summary

Make the custom chat model picker match native menu pointer, highlighting, action-item, and keyboard-focus behavior.

## Best solution

Preserve the current searchable model picker while completing its native-like interaction contract: accept a press-drag-release selection, clear pointer highlighting outside the menu, retain the open-state styling, and keep management actions in the menu's normal keyboard flow.

## Evidence

- **remaining hover defect:** The ActionList popup handles `MOUSE_LEAVE` only by cancelling submenu state in src/vs/platform/actionWidget/browser/actionList.ts; it does not clear list focus/highlighting, matching the report that a row remains selected after the pointer leaves.
- **management action:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItems.ts now represents `Manage Models...` as an `IActionWidgetDropdownAction`; modelPickerItemSections.ts renders it as a list item when there is no Other Models section, but otherwise places it in that section's toolbar rather than consistently in the normal menu-item flow.
