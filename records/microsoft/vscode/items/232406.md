# Issue #232406 — Option to enable `tsconfig.json` relative loading of TypeScript language service plugins

[https://github.com/microsoft/vscode/issues/232406](https://github.com/microsoft/vscode/issues/232406)

## Summary

Valid feature request with 54 upvotes, promoted to Backlog. The `allowLocalPluginLoads` flag is only wired in the web tsserver path, not in the desktop spawner — the requested capability (resolving TS plugins relative to tsconfig.json) is not implemented on current main.

## Change summary

Allow TypeScript language service plugins to be resolved relative to the `tsconfig.json` that lists them, instead of only relative to the TypeScript installation path.

## Best solution

Wire up an `--allowLocalPluginLoads` flag (or a new VS Code setting) in the desktop tsserver spawner (`extensions/typescript-language-features/src/tsServer/spawner.ts`) so that TS plugins listed in `tsconfig.json` are resolved relative to that config file's location. This would fix the pnpm/strict-package-manager scenario where the resolved TypeScript path diverges from the workspace root. The web server already partially supports this via `webServer.ts`.
