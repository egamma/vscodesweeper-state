# Issue #284339 — Allow .json files to support comments when a specific comment line is at the top of the file.

[https://github.com/microsoft/vscode/issues/284339](https://github.com/microsoft/vscode/issues/284339)

## Summary

A real gap remains: VS Code supports JSONC through an explicit language mode or file association, but it does not recognize a file-contained directive that opts an individual .json file into JSONC behavior. The Backlog request should remain open as under discussion because the directive contract and warning behavior need product agreement.

## Change summary

Recognize a designated leading comment in a .json file as an opt-in to JSON-with-comments behavior and warn that the convention is nonstandard.

## Best solution

If adopted, define one stable opt-in directive that switches only the containing document to JSONC language behavior while preserving strict JSON for ordinary .json files, and clearly communicate the interoperability risk.

## Evidence

- **validation behavior:** extensions/json-language-features/server/src/jsonServer.ts parses with `allowComments: true` but reports comments as errors unless the document language ID is `jsonc` (or validation severity is configured), so a leading marker currently cannot opt a .json document into JSONC semantics.
- **existing workaround:** https://github.com/microsoft/vscode/issues/243428 documents selecting the existing “JSON with Comments” language mode, while https://github.com/microsoft/vscode/issues/40538 also documents `files.associations`; neither satisfies this issue's central requirement that the file carry its own opt-in.
