# Issue #332616 — DOM: shared mutation observer is never disconnected once two consumers share it

[https://github.com/microsoft/vscode/issues/332616](https://github.com/microsoft/vscode/issues/332616)

## Summary

Confirmed real bug in sharedMutationObserver.observe: joining consumers only increment the users counter without registering their own decrementing disposable, so the count can never reach zero once shared, leaking the MutationObserver, its emitter, and the target node/map entries. An open PR already fixes this, so it stays open pending merge.

## Change summary

Shared MutationObserver in dom.ts is never disconnected once a second consumer joins, because only the creating consumer's disposable decrements the shared user count.

## Best solution

Land the linked fix (https://github.com/microsoft/vscode/pull/332626), which gives every joining consumer its own cleanup disposable so the observer disconnects exactly once regardless of dispose order.
