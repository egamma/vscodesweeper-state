# Issue #250490 — UX bug: unexpected hover behaviour - attached file

[https://github.com/microsoft/vscode/issues/250490](https://github.com/microsoft/vscode/issues/250490)

## Summary

The accepted UX bug remains visible in current source: file attachments are clickable and use a pointer cursor, but only the separate remove button receives hover treatment. This team-authored Backlog issue must remain open because no referenced fix or same-symptom canonical exists, and a maintainer explicitly accepted adding the missing treatment.

## Change summary

Give the clickable body of an attached file a hover affordance that distinguishes opening the file from removing it with the separate close button.

## Best solution

Make the attachment body reveal its clickable state on hover while preserving the close button as a visually distinct removal action. The result should follow the existing interaction model: clicking the body opens the file, while clicking the close button removes it.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts`
- **Validation:** In a development window, attach a file in Chat and verify in dark, light, and high-contrast themes that hovering the attachment body visibly indicates the open action, hovering the close button remains distinct, body click opens the file, and close-button click removes it.
- **Behavior:**

  > An attached file's clickable body must provide visible hover feedback so the pointer cursor and open action are understandable. The close button must retain a distinct hover state and remain the removal action. Acceptance requires the body to open the file, the close button to remove it, and both hover states to remain legible in dark, light, and high-contrast themes.
- **Trace:**

  > AbstractChatAttachmentWidget in src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentWidgets.ts creates one focusable attachment element with role button; addResourceOpenHandlers gives that element a pointer cursor and opens the resource. In src/vs/workbench/contrib/chat/browser/widget/media/chat.css, the attachment container has no clickable-body hover treatment, while the nested .monaco-button:hover receives toolbarHoverBackground. This conclusively preserves the reported mismatch on current main. Keep the existing interaction boundary: attachment-body activation opens the resource, while the nested close button and Delete/Backspace behavior remove it; do not turn the whole attachment into a removal target. The accepted direction is recorded at https://github.com/microsoft/vscode/issues/250490#issuecomment-2948397679.
