# Issue #167863 — Column number is incorrect when using tabs.

[https://github.com/microsoft/vscode/issues/167863](https://github.com/microsoft/vscode/issues/167863)

## Summary

This accepted Backlog feature request remains necessary: current main deliberately displays visual columns, and no setting or command exposes the requested character-based position in the status bar. The desired presentation needs a maintainer decision because replacing visual columns would conflict with established behavior.

## Change summary

Allow the editor status bar to show a character-based cursor position that counts each tab once instead of expanding tabs to their configured display width.

## Best solution

Preserve the established visual-column behavior while providing an intentional way to display character-based positions, likely through a configurable status-bar presentation or an additional value. Define how that position handles Unicode before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorStatus.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/editor/common/core/cursorColumns.ts`
- **Validation:** Add and run a targeted EditorStatus test covering `\t\tHello`: the selected presentation must report H as character position 3 when requested, preserve visual column 9 where visual-column behavior remains selected, and leave Go To Line behavior unchanged.
- **Behavior:**

  > Users working with source coordinates can obtain a cursor position that counts each tab as one character, so H in `\t\tHello` is position 3. Existing users who depend on visual columns must not silently lose the current tab-expanded value. The chosen behavior must be clearly identified and remain correct when tab size changes.
- **Trace:**

  > EditorStatus.onSelectionChange in src/vs/workbench/browser/parts/editor/editorStatus.ts replaces the model selection column with `editorWidget.getStatusbarColumn`. CodeEditorWidget.getStatusbarColumn in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts calls `CursorColumns.toStatusbarColumn`, whose implementation in src/vs/editor/common/core/cursorColumns.ts expands tabs to render stops. The related https://github.com/microsoft/vscode/issues/280540 and https://github.com/microsoft/vscode/pull/284668 intentionally aligned Go To Line with visual-column semantics, so that navigation behavior must not be accidentally reverted. The uncertainty begins at the status-bar contract: whether to expose both coordinate systems or make the display configurable, and what unit character position uses beyond ASCII.
- **Open decisions:**
  - Should the status bar show both visual and character-based positions, or offer a setting that selects one while preserving visual columns as the default?
  - Should character position follow the editor model's UTF-16 column convention or count Unicode code points/grapheme clusters?

## Evidence

- **current source:** src/vs/workbench/browser/parts/editor/editorStatus.ts:834-871 obtains the displayed position through `editorWidget.getStatusbarColumn`, explicitly documenting that it computes a visible column accounting for configured tab widths.
- **column semantics:** src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts:652-660 delegates the status-bar value to `CursorColumns.toStatusbarColumn`; src/vs/editor/common/core/cursorColumns.ts:57-78 expands tabs to render tab stops, so `\t\tHello` still reports H at visual column 9 rather than character position 3.
