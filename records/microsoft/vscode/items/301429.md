# Issue #301429 — Keyboard shortcuts for Open Chat keep overwriting the Toggle Autosuggest (previous default) on every update despite Open Chat being moved to another (custom) binding

## Summary

The update-reset symptom has an independent confirmation and remains distinct from the narrower keybinding-removal case already fixed under https://github.com/microsoft/vscode/issues/293802. Current source does not prove this report resolved, so it should remain open while the exact persisted-keybinding transition is diagnosed.

## Change summary

Updating VS Code repeatedly restores a chat binding on Ctrl/Cmd+I despite the user moving chat commands elsewhere and assigning that chord to Trigger Suggest.

## Best solution

Ensure a user-assigned Ctrl/Cmd+I binding remains authoritative across upgrades even when chat command registrations, IDs, or context conditions change, with a regression test covering the persisted pre-upgrade keybindings and upgraded defaults.

- **Behavior:**

  > A user who assigns Ctrl/Cmd+I to Trigger Suggest and moves every chat command to other chords keeps that assignment after upgrading VS Code. Newly added or changed chat defaults must not become effective on Ctrl/Cmd+I over the user's binding. Existing default shortcuts remain unchanged for users who have not customized them. Acceptance requires a regression test representing the persisted pre-upgrade entries and post-upgrade defaults.
- **Trace:**

  > Current registrations place Ctrl/Cmd+I on TriggerSuggestAction in src/vs/editor/contrib/suggest/browser/suggestController.ts and StartSessionAction in src/vs/workbench/contrib/inlineChat/browser/inlineChatActions.ts; PrimaryOpenChatGlobalAction in src/vs/workbench/contrib/chat/browser/actions/chatActions.ts uses a different chord. WorkbenchKeybindingService in src/vs/workbench/services/keybinding/browser/keybindingService.ts feeds defaults followed by user overrides into KeybindingResolver, whose reverse lookup should prefer the user rule. KeybindingEditingService records command-specific negative entries when moving defaults, while KeybindingResolver.handleRemovals handles those persisted removals. The unresolved boundary is the exact saved keybindings before the upgrade and which changed or newly registered chat command survives them afterward. Preserve default chat behavior for uncustomized users and do not resolve the report by removing Ctrl/Cmd+I defaults globally. The older related report https://github.com/microsoft/vscode/issues/293802 covers changed `when` clauses, while https://github.com/microsoft/vscode/issues/315085 covers a distinct focus/routing symptom.
