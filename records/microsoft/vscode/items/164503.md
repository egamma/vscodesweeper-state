# Issue #164503 — Unnecessary large screen update under Remote Desktop

[https://github.com/microsoft/vscode/issues/164503](https://github.com/microsoft/vscode/issues/164503)

## Summary

Keep open as an upstream Chromium performance investigation. VS Code limits its DOM updates to the necessary elements, but Chromium appears to combine the resulting regions into an editor-sized repaint under Remote Desktop; narrower VS Code-side repaint work does not resolve the overarching behavior.

## Change summary

Reduce editor repaint regions during simple text edits so Remote Desktop does not encode most of the editor after pressing Enter.

## Best solution

Compare the same vscode.dev scenario in Chromium-based Edge and Firefox, then provide the paint evidence and suitable tooling to Chromium maintainers if the behavior is Chromium-specific. Continue independently reducing avoidable VS Code repaint inputs through focused issues such as the open minimap work.
