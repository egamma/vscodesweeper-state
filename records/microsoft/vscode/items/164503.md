# Issue #164503 — Unnecessary large screen update under Remote Desktop

[https://github.com/microsoft/vscode/issues/164503](https://github.com/microsoft/vscode/issues/164503)

## Summary

Team-authored upstream Chromium issue about paint-region coalescing under Remote Desktop. VS Code touches only necessary DOM elements; the root cause is Chromium combining disjoint paint rects into one large bounding rectangle. Partial VS Code-side mitigations have been shipped (scrollbar, #191423) and are in progress (minimap, #193422), but the core Chromium behavior remains unresolved upstream. Keeping open.

## Change summary

Under Remote Desktop, pressing Enter in the editor causes Chromium to repaint the entire editor area instead of only the changed regions, increasing encoding/decoding latency.

## Best solution

The core fix belongs in Chromium's paint-region logic. VS Code-side mitigations (reducing unnecessary DOM touches that widen the bounding rect) are tracked by https://github.com/microsoft/vscode/issues/191423 (scrollbar — fixed) and https://github.com/microsoft/vscode/issues/193422 (minimap — still open). This umbrella issue should stay open until either Chromium fixes the coalescing behavior or all VS Code-side mitigation satellites are resolved. The outstanding action from the last comment is confirming whether the same behavior occurs in Firefox/Edge via vscode.dev, which could support filing a Chromium upstream bug.
