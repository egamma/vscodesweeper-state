# Issue #314132 — Panel closes immediately

[https://github.com/microsoft/vscode/issues/314132](https://github.com/microsoft/vscode/issues/314132)

## Summary

Still an open, credible crash path on current main: XtermTerminal.dispose() calls _disposeOfWebglRenderer() while the terminal core is mid-teardown, and the resulting async canvas-dimension refresh (via requestAnimationFrame) throws inside xterm.js when the render service is already gone — matching the reporter's exact stack trace. The previous review's cited fix commit was refuted, and no replacement fix is visible in this (shallow, single-commit) checkout, so this stays open rather than closing as implemented.

## Change summary

Toggling the terminal panel open closes it again immediately, with an uncaught xterm.js TypeError reading 'dimensions' on an undefined render service.

## Best solution

Diagnose why disposing the webgl renderer during terminal process-exit teardown (xtermTerminal.ts dispose() -> _disposeOfWebglRenderer()) triggers an async resize/refresh that outlives the render service, and guard or sequence that teardown so it doesn't throw; confirm whether the underlying defect is an xterm.js/webgl-addon ordering issue that needs an upstream fix or can be worked around in xtermTerminal.ts.
