# Issue #167840 — Expand all locations when using "go to locations"

[https://github.com/microsoft/vscode/issues/167840](https://github.com/microsoft/vscode/issues/167840)

## Summary

Keep this accepted, 22-upvote request open: reference peek still expands only the selected file, and no existing setting provides automatic expansion of every file. The related References sidebar request and its open PR do not implement the peek surface.

## Change summary

Provide an option to expand all file groups automatically when displaying reference locations in the editor's peek widget.

## Best solution

Offer opt-in automatic expansion in reference peek while preserving the current default and responsiveness. Settle the file-loading and expansion-limit behavior before implementation, coordinating with the related sidebar work without duplicating its open PR.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/gotoSymbol/browser/peek/referencesWidget.ts`, `src/vs/editor/contrib/gotoSymbol/browser/peek/referencesTree.ts`
- **Validation:** Use a references provider returning locations in at least three files. With the proposed option enabled, open reference peek and verify the agreed automatic-expansion behavior without manually opening each group; with the option disabled, verify today's selected-file-only expansion. Repeat with many files and a slow resolver to verify the agreed loading policy and responsiveness.
- **Behavior:**

  > Reference peek currently leaves other files collapsed, requiring repeated manual expansion to inspect locations across files. Users should be able to opt into automatic expansion when the results first appear. Preserve the current default and normal reference selection and navigation. Acceptance should cover multiple files, disabled-option compatibility, and the agreed behavior for large or slow-to-resolve result sets.
- **Trace:**

  > ReferenceWidget._onNewModel in src/vs/editor/contrib/gotoSymbol/browser/peek/referencesWidget.ts sets the ReferencesModel as the tree input for multi-file results; _revealReference expands only the selected reference's parent. The tree uses the underlying collapsed default and exposes no expansion preference through editor.gotoLocation options in src/vs/editor/common/config/editorOptions.ts. DataSource.getChildren in src/vs/editor/contrib/gotoSymbol/browser/peek/referencesTree.ts resolves each expanded file for textual previews, which makes eager expansion a potentially observable loading cost. Existing navigation settings choose peek versus direct navigation, not expansion. https://github.com/microsoft/vscode/issues/197592 and https://github.com/microsoft/vscode/pull/197594 concern the separate References sidebar; do not compete with or assume that PR covers peek. The uncertainty is the product policy for loading and expanding large result sets, not whether the requested option already exists.
- **Open decisions:**
  - Should the opt-in always expand every file group regardless of result size, or impose a documented automatic-expansion limit?
  - When resolving many files is slow, should peek show results immediately and expand progressively, or wait until automatic expansion is complete?
