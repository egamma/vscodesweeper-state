## Plan brief

- **Likely files:** `src/vs/sessions`, `src/vs/platform/agentHost`, `extensions/copilot`
- **Validation:** Exercise an end-to-end scenario in which one creator launches two independently scoped sessions in different workspaces, continues working, receives completion/input-needed/error signals, inspects both results without copy/paste, and can identify where each child's changes live.
- **Behavior:**

  > A creator session can launch and coordinate at least two independently scoped child sessions across separate workspaces, repositories, worktrees, providers, or lifecycles while remaining the primary user-visible result. Each child exposes its task, workspace, status, creator relationship, and useful integration metadata; the creator receives completion, input-needed, and failure signals and can inspect bounded results without manual context transfer. Same-session chat delegation remains the preferred path for parallel work sharing one workspace and aggregate diff, and existing confirmation, trust, permission, and concurrency controls remain effective.
- **Trace:**

  > The issue is the product-level umbrella for cross-session delegation rather than one bounded defect. https://github.com/microsoft/vscode/pull/331518 and https://github.com/microsoft/vscode/pull/331544 delivered delegation relationships and notification pieces, while https://github.com/microsoft/vscode/issues/331541 and https://github.com/microsoft/vscode/issues/336056 identify remaining input/wake coordination work. Relevant implementation spans the Agents Window/session model under src/vs/sessions, Agent Host protocol and lifecycle under src/vs/platform/agentHost, and Copilot-facing tool guidance under extensions/copilot. Preserve the boundary between same-session chats and independently scoped sessions, and do not weaken confirmation, trust, permission, or concurrency controls. The uncertainty starts at which remaining acceptance criteria belong in this umbrella versus independent follow-up issues and how aggregate-result primacy should appear across the Agents Window and creator chat.
- **Open decisions:**
  - Which child-session states and controls must appear inline in the creator session versus only in the Agents Window or child session?
  - What creator-visible contract should govern input-needed handling when a child is blocked while the creator is actively running?
  - Which child artifacts must be included in the creator's aggregate result, and which should remain linked but independently scoped?
