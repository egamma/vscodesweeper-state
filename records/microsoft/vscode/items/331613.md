## Evidence

- **Report and missing diagnosis:** https://github.com/microsoft/vscode/issues/331613 reports code 134 after connecting from Windows to Linux, despite server cleanup and disabling extensions including Copilot. It supplies no crash-time log sequence, dump or stack identifying the aborting process, and no repeatable workload beyond connecting and waiting.
- **Cross-transport scope:** The author's August 25 comment on https://github.com/microsoft/vscode/issues/331613 says WSL, tunnels and Dev Containers are affected too. The report therefore cannot safely be attributed to the Remote-SSH extension alone.
- **Socket error is not a crash diagnosis:** src/vs/platform/remote/common/remoteSocketFactoryService.ts, RemoteSocketFactoryService.connect, throws the reported error when no registered factory supports the connection. src/vs/workbench/api/browser/mainThreadManagedSockets.ts registers managed factories through $registerSocketFactory and owns their registrations in a disposable map. This explains how an unavailable factory can block reconnection, but does not establish what caused exit code 134.
- **Related remote crash, not verified duplicate:** https://github.com/microsoft/vscode/issues/340843 is open and reports the same downstream Managed(1) error, but its initiating failure is a macOS ARM64 SIGSEGV under heavy remote-terminal scrolling. No shared crash signature or root cause links that failure to this Windows code-134 report.
- **Same exit code does not establish ownership:** Open reports https://github.com/microsoft/vscode/issues/337630, https://github.com/microsoft/vscode/issues/333717 and https://github.com/microsoft/vscode/issues/331190 also mention code 134, but describe different workloads or extension correlations. The September 27 follow-up on the last report attributes its current failures to C# Dev Kit; this issue contains no corresponding evidence.
- **Other candidate crash signatures:** https://github.com/microsoft/vscode/issues/330153 contains Windows access-violation investigations, including a maintainer-identified MSAL shutdown stack; https://github.com/microsoft/vscode/issues/295023 concerns large remote Linux core dumps. Neither establishes the cause or complete scope of this report, so neither is a verified canonical.
