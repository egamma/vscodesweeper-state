# Issue #336305 — Agent Host steering starts a new turn instead of steering the active turn

[https://github.com/microsoft/vscode/issues/336305](https://github.com/microsoft/vscode/issues/336305)

## Summary

Well-diagnosed, still-open bug: steering is meant to inject into the active turn, but for the Copilot provider it is sent via `session.send({ mode: 'immediate' })` and the SDK records `delivery: idle` and starts a new turn instead; a comment independently confirms the same user-visible symptom for the Claude harness with a detailed transcript trace. No fix has landed on main and no maintainer has weighed in — this stays open.

## Change summary

When a user sends a steering instruction while an agent turn is still in progress, it is treated as a new follow-up turn instead of steering the active one.

## Best solution

Investigate per-provider: for Copilot, determine why `@github/copilot-sdk`'s `session.send({ mode: 'immediate' })` records `delivery: idle` instead of injecting into the active turn (may require an upstream SDK fix or a different AH-side call); for Claude, the commenter's proposal to deliver steering as a `queued_command`-style attachment (matching the Claude Code CLI) rather than a plain user message is a concrete lead in `copilotAgentSession.ts`/the Claude harness equivalent. Coordinate with the related visibility bug (https://github.com/microsoft/vscode/issues/337904).
