# Issue #330869 — Using `screenshot_page` tool without GitHub authentication provider stops chat

[https://github.com/microsoft/vscode/issues/330869](https://github.com/microsoft/vscode/issues/330869)

## Summary

Confirmed in source: when the built-in `github-authentication` extension is disabled, `AuthenticationService.tryActivateProvider` has no way to know the provider will never register, so it always waits the hardcoded 5s and then throws (`src/vs/workbench/services/authentication/browser/authenticationService.ts:479-489`). Something in the Copilot extension calls `vscode.authentication.getAccounts('github')` (per the `$getAccounts` frame in the reporter's stack) after a successful `screenshot_page` invocation, and that unhandled rejection surfaces as a chat-stopping error even though the tool itself already completed.

## Change summary

With `--disable-extension vscode.github-authentication` and a BYOK model, using the `screenshot_page` tool succeeds but is immediately followed by a `Timed out waiting for authentication provider 'github' to register.` error that halts the chat turn.

## Best solution

Two independent but related fixes: (1) in core, `AuthenticationService.tryActivateProvider`/`authenticationService.ts` should detect a permanently-disabled declared provider (extension not enabled) and fail fast with a clear, swallow-able condition instead of a 5s timeout + hard throw; (2) whatever Copilot-extension code queries `authentication.getAccounts('github')` on this path (likely BYOK/account-status checking triggered per turn) should not let that rejection propagate as a chat-blocking error when no GitHub auth provider is available.
