# Issue #131319 — Automatically hide panel when a file in the explorer is clicked

[https://github.com/microsoft/vscode/issues/131319](https://github.com/microsoft/vscode/issues/131319)

## Summary

Keep this accepted, well-supported request open: current layout handling still unmaximizes the panel when revealing an editor instead of hiding it. Existing commands and extension workarounds do not provide the requested built-in automatic behavior.

## Change summary

Allow opening a file to hide a maximized panel, preserving an all-or-nothing terminal workflow.

## Best solution

Provide an opt-in layout behavior that reveals the opened editor while hiding, not terminating, the maximized terminal panel. Decide its applicability to other panel views and file-opening routes before implementation, preserving existing behavior for users who do not opt in.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** With workbench.panel.opensMaximized set to always and the proposed behavior enabled, maximize a running terminal and open a file from Explorer: the editor must occupy the available central area and the panel must be hidden. Toggle the terminal back and verify the same session returns maximized. Repeat with terminal links and search results if included in the agreed scope, and verify disabling the behavior preserves today's unmaximize transition.
- **Behavior:**

  > Users who choose an all-or-nothing terminal workflow should be able to open a file from Explorer and see the editor without a partially visible terminal panel. Hiding must preserve the terminal session, and toggling it back must respect workbench.panel.opensMaximized. Existing layout behavior must remain available. Acceptance should cover Explorer navigation and whichever additional opening routes the maintainer includes.
- **Trace:**

  > registerLayoutListeners in src/vs/workbench/browser/layout.ts routes visible-editor changes and editor-group activation through showEditorIfHidden. That helper currently calls toggleMaximizedPanel, whose restore branch reveals the editor and resizes the panel to its stored non-maximized dimensions. workbench.panel.opensMaximized in src/vs/workbench/browser/workbench.contribution.ts controls opening the panel, not this transition. Manual hiding already exists as workbench.action.closePanel, but does not automate file navigation. Preserve terminal processes, default layout semantics, and the separate maximized auxiliary-bar behavior. https://github.com/microsoft/vscode/issues/133362 was consolidated into this issue; https://github.com/microsoft/vscode/issues/10952 concerns broader auto-hide interactions. The remaining uncertainty is the public scope of the opt-in behavior, not whether the current setting already provides it.
- **Open decisions:**
  - Should automatic hiding apply only to a maximized panel, or also to a non-maximized panel when a file opens?
  - Should the behavior apply to every panel view or only when the terminal is active?
  - Should the option cover all explicit file-opening routes, including terminal links, Quick Open, and search results, and leave automatic/background editor opens unchanged?
