- **Behavior:**

  > The report observes repeated missing-filesystem-provider errors for chat editing virtual documents after an agent finishes editing multiple files. Completion must not leave background consumers repeatedly making unsupported filesystem requests for those documents. Valid editing history, diff review, and undo behavior must remain available. Acceptance requires reproducing the reported workflow on a current build and observing no recurring errors during the subsequent usage period; renderer-freeze causality is a separate investigation.
- **Trace:**

  > ChatEditingService registers both text content providers at service scope, so session completion does not itself unregister their schemes. ChatEditingTextModelContentProvider and ChatEditingSnapshotTextModelContentProvider resolve through session state, whereas ExtHostConsumerFileSystem.readFile uses filesystem providers and converts ENOPRO into the reported Unavailable error. Commit https://github.com/microsoft/vscode/commit/f107b9824437a5e3c200099e3ed58d3752f3ca4b already prevents a Git repository lookup fallback from reading non-file resources. The uncertainty starts at the caller producing the repeated requests: the report contains no stack establishing whether that guarded Git path or another consumer is responsible. Preserve service-scoped provider registrations and legitimate snapshot access; do not introduce session-end cleanup based solely on the proposed root cause. https://github.com/microsoft/vscode/issues/337576 is related snapshot work but not a verified duplicate, and https://github.com/microsoft/vscode/issues/309527 tracks the separate terminal-monitoring freeze.

- **Provider lifetime differs from suspected cause:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingServiceImpl.ts registers both schemes with registerTextModelContentProvider in the ChatEditingService constructor and owns their registrations at service scope. The session-disposal handler stops the editing session; it does not unregister these providers.
- **Text content and filesystem providers are distinct:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingTextModelContentProviders.ts resolves content through editing sessions and returns null when required session data is unavailable. src/vs/workbench/services/textmodelResolver/common/textModelResolverService.ts treats content providers separately from filesystem providers. ExtHostConsumerFileSystem.readFile in src/vs/workbench/api/common/extHostFileSystemConsumer.ts uses filesystem APIs, and _handleError translates ENOPRO into FileSystemError.Unavailable; the reported error therefore does not establish that a text content provider was unregistered.
