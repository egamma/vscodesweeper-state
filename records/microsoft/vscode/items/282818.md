# Issue #282818 — Agent sessions: Allow Continue in/Delegate to create multiple agents

[https://github.com/microsoft/vscode/issues/282818](https://github.com/microsoft/vscode/issues/282818)

## Summary

Keep open: the inspected Continue In/Delegate flow still submits one prompt to one target, rather than creating multiple scoped agents from a plan in one action. Related orchestration work supplies useful infrastructure but does not establish completion of this team-authored request.

## Change summary

Allow one Continue In/Delegate action to launch multiple agents for a plan's variations or tasks.

## Best solution

Provide a plan-aware batch delegation experience that creates clearly scoped agents while preserving the originating plan and context. Coordinate its design with the existing child-session work, distinguishing shared-workspace subtasks from independently scoped sessions.

- **Behavior:**

  > A plan can describe multiple variations or tasks that the user wants handled by separate agents. Existing single-agent continuation must remain available.
- **Trace:**

  > ContinueChatInSessionAction and ChatContinueInSessionActionItem in src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts expose per-provider actions, each invoking CreateRemoteAgentJobAction.run with one contribution and one prompt. DelegationSessionPickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/delegationSessionPickerActionItem.ts stores one pending target; SubmitAction.handleDelegation in chatExecuteActions.ts resolves that target and invokes the same action once. This establishes the single-handoff boundary, not a batch plan contract. https://github.com/microsoft/vscode/issues/262767 discusses per-TODO delegation, while https://github.com/microsoft/vscode/issues/284124 was explicitly consolidated into this issue. https://github.com/microsoft/vscode/issues/331521 and merged https://github.com/microsoft/vscode/pull/331518 supply related cross-session coordination and distinguish same-session chats from independently scoped sessions, but do not settle this request's user interaction. Preserve existing provider eligibility, repository requirements, context transfer, and single-target behavior. Uncertainty begins at how users identify the work to fan out and whether that work creates chats within a session or independent sessions.
- **Open decisions:**
  - Does the batch action delegate all plan work automatically, or require the user to select or approve the individual tasks or variations first?
  - For same-workspace plan tasks, should separate agents run as chats within the originating session, while independently scoped work creates separate sessions?
  - Should batch delegation cover only independent tasks and alternatives, or also arrange execution of dependent plan phases?
