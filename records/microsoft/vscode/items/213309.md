# Issue #213309 — Very thin hollow/transparent gap/background between mini-map and scrollbar (on split editor)

[https://github.com/microsoft/vscode/issues/213309](https://github.com/microsoft/vscode/issues/213309)

## Summary

This is a Chromium scaling artifact rather than a gap in VS Code's logical editor layout. Keep it open as upstream; the existing `upstream` and `zoom` labels accurately classify the remaining issue.

## Change summary

Prevent a thin line of editor content from appearing between the minimap and scrollbar at non-default window zoom levels.

## Best solution

Chromium's scaled rectangle rasterization must avoid introducing seams between adjacent CSS-pixel regions. Until that changes upstream, using zoom level 0 and adjusting editor font size, or disabling the minimap, are the available workarounds.

## Evidence

- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/213309#issuecomment-2144615877 identifies Chromium's zoom-stage rounding as the cause and states that VS Code positions the rectangles at adjoining CSS coordinates.
- **current source:** src/vs/editor/common/config/editorOptions.ts computes `minimapLeft` as `outerWidth - minimapWidth - verticalScrollbarWidth`; Minimap._applyLayout in src/vs/editor/browser/viewParts/minimap/minimap.ts applies that left coordinate and width directly, while EditorScrollbar._setLayout in src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts spans the content and minimap widths. The logical CSS layout therefore contains no intended gap.
- **matching Chromium behavior:** https://github.com/microsoft/vscode/issues/82232#issuecomment-541055688 documents the same artifact: Chromium scales adjacent integer CSS rectangles using floating-point values and independently rounds their resulting coordinates, which can expose a one-device-pixel seam.
- **canonical search:** The exact earlier report https://github.com/microsoft/vscode/issues/69419 is closed, so it cannot serve as a duplicate canonical; no open canonical owning this Chromium rounding problem was found.
