# Issue #213309 — Very thin hollow/transparent gap/background between mini-map and scrollbar (on split editor)

[https://github.com/microsoft/vscode/issues/213309](https://github.com/microsoft/vscode/issues/213309)

## Summary

Already triaged as upstream by alexdima — the gap is caused by Chromium's sub-pixel rounding at non-zero zoom levels. No fix has landed on main; the issue correctly carries the `upstream` and `zoom` labels and should remain open as a known upstream limitation.

## Change summary

A thin transparent gap appears between the minimap and scrollbar at zoom level -1 in split editor, exposing underlying text.

## Best solution

This is a Chromium rendering limitation with sub-pixel rounding at fractional zoom. VS Code positions elements at pixel-perfect CSS coordinates, but Chromium introduces rounding gaps. The issue is correctly tagged `upstream`; it would need a Chromium-side fix or a VS Code workaround (e.g. overlap/bleed on minimap edges), though any such workaround risks introducing other visual artifacts at different zoom levels.
