# Issue #170645 — Remote IPC layer improvements

[https://github.com/microsoft/vscode/issues/170645](https://github.com/microsoft/vscode/issues/170645)

## Summary

Keep open: socket draining and WebSocket chunking exist, but the remote file-stream path still pushes data through IPC events without receiver-driven backpressure. This team-authored item deliberately tracks the remaining transport-design work; neither the closed parent nor the newer renderer-chunking request supersedes it.

## Change summary

Improve remote IPC flow control so large file transfers use available bandwidth without overwhelming clients or delaying unrelated messages.

## Best solution

Establish a remote IPC flow-control contract that bounds queued transfer data and preserves responsiveness for unrelated messages without introducing a round trip per chunk. Evaluate it on a plain VS Code server connection before attributing Codespaces upload/download performance to this transport.
