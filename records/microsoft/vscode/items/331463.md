# Issue #331463 — Command+A is not working on debug console

[https://github.com/microsoft/vscode/issues/331463](https://github.com/microsoft/vscode/issues/331463)

## Summary

The report is now actionable and remains a real gap on current main: the Debug Console's transcript is rendered as a virtualized tree, while Cmd+A is scoped to its input editor and cannot select the output. Keep it open and remove the stale info-needed classification.

## Change summary

Make Cmd+A select the Debug Console transcript so it can be copied with standard keyboard muscle memory.

## Best solution

Define explicit Debug Console select-all semantics in the debug REPL contribution, preserving normal editor selection while the prompt is focused and selecting the transcript when focus is on output; cover both focus states with targeted tests.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/browser/replViewer.ts`, `src/vs/workbench/contrib/debug/test/browser/repl.test.ts`
- **Validation:** Add targeted Debug Console tests for Cmd+A with focus in the prompt and with focus on transcript output, then verify copying produces the expected text in each state.
- **Behavior:**

  > Cmd+A in the Debug Console should provide standard select-all behavior for the region the user is interacting with. When focus is in the prompt, it must retain normal editor selection semantics; when focus is on transcript output, it should select the transcript so Cmd+C copies it. Existing Copy All behavior and keyboard navigation must remain available.
- **Trace:**

  > The Debug Console is implemented by Repl in src/vs/workbench/contrib/debug/browser/repl.ts. Output is a WorkbenchAsyncDataTree rendered through src/vs/workbench/contrib/debug/browser/replViewer.ts, while the input prompt is a separate CodeEditorWidget; editor.action.selectAll in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts is gated by textInputFocus. Repl.copyAll() already serializes transcript elements directly to the clipboard, but there is no selectable transcript model or Debug Console-specific Cmd+A command. The uncertainty begins at the observable selection model for a virtualized tree: visual selection, copy semantics, and focus interaction need an explicit decision. Do not change global editor Cmd+A behavior or terminal selection semantics.
- **Open decisions:**
  - When the transcript has focus, should Cmd+A visibly select all rendered transcript text, or may it establish an internal all-output selection whose primary observable effect is that Cmd+C copies the transcript?
  - When the prompt has focus, should the first Cmd+A select only prompt text, or should an empty prompt cause Cmd+A to target the transcript?
