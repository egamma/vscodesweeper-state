# Issue #336483 — [Accessibility] Reliably expose scrollable regions in Sidebar via UIAutomation

[https://github.com/microsoft/vscode/issues/336483](https://github.com/microsoft/vscode/issues/336483)

## Summary

Legitimate, source-confirmed gap: sidebar scroll containers deliberately hide their scrollbars from the accessibility tree (role="presentation", aria-hidden="true"), so no ScrollPattern/ScrollBar object reaches UIAutomation for voice-control tools like Talon. This is a real product decision to weigh, not a bug or something already covered — routing to the accessibility area.

## Change summary

Expose scrollable sidebar regions (explorer, search, extensions, etc.) via UIAutomation ScrollPattern or ScrollBar objects so voice-control/dictation tools can target scrolling.

## Best solution

An accessibility maintainer should decide whether to selectively surface ScrollPattern/native scrollbar semantics for sidebar scroll containers (src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts, scrollableElement.ts) without regressing screen-reader UX, since those nodes are currently marked role="presentation"/aria-hidden="true" on purpose.
