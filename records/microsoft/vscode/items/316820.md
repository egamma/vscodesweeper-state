# Issue #316820 — API: expose Explorer view selection to extensions (read + change event)

[https://github.com/microsoft/vscode/issues/316820](https://github.com/microsoft/vscode/issues/316820)

## Summary

Legitimate API gap: the built-in Explorer selection is only available to internal commands via IExplorerService, not to extensions. No proposed API or tracking issue exists on main. Keeping open for team evaluation of the API shape.

## Change summary

Expose the built-in file Explorer's current selection (and a change event) to the extension API so commands invoked from the palette/keybindings can act on what's selected.

## Best solution

Introduce a proposed API (likely under `window.fileExplorer` following the tabGroups pattern) that wraps the existing `IExplorerService.getContext(true)` and the tree's `onDidChangeSelection` event through the extHost/mainThread bridge. The team should decide the shape (Option A is most extensible) and whether to include the focused item.
