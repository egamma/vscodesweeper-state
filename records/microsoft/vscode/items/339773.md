# Issue #339773 — `workbench.editor.highlightModifiedTabs` enabled gumps when active vs not active

[https://github.com/microsoft/vscode/issues/339773](https://github.com/microsoft/vscode/issues/339773)

## Summary

Fresh bug report (filed same day, with an attached video) found while testing the connected test-plan item for editor tab geometry/customizations (#339385); the reporter shows tab geometry visibly shifting when `workbench.editor.highlightModifiedTabs` is on and a dirty tab toggles between active/inactive. No fix exists on main yet, so this should stay open for a maintainer to diagnose.

## Change summary

With `workbench.editor.highlightModifiedTabs` enabled, a dirty tab's geometry (width/padding) visibly jumps when it switches between the active and inactive tab state.

## Best solution

A maintainer should watch the attached repro video and trace the dirty/active CSS class interaction in multiEditorTabsControl.ts and multieditortabscontrol.css (e.g. the close-action-off + dirty-border-top padding toggle, or a border-height mismatch) to find exactly which rule causes the layout shift, then adjust the affected CSS so toggling active/dirty state doesn't change tab width.
