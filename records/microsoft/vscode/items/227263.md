# Issue #227263 — [Accessibility] Tooltips under user settings for extensions missing aria attributes.

[https://github.com/microsoft/vscode/issues/227263](https://github.com/microsoft/vscode/issues/227263)

## Summary

Still reproduces on main: the hover infrastructure sets role="tooltip" on the hover widget but never links the trigger element via aria-describedby, so screen readers cannot associate the tooltip with the control that opens it. The settings-indicator elements use this pattern for 'Applies to all profiles' and similar tooltips.

## Change summary

Screen readers cannot announce that a tooltip is available on settings-editor indicator elements because the trigger lacks aria-describedby pointing to the tooltip.

## Best solution

The fix belongs in the hover service infrastructure (src/vs/platform/hover/browser/hoverService.ts) — when a hover is shown, set aria-describedby on the target element referencing the tooltip's DOM id, and remove it when the hover hides. This would fix all hover-based tooltips across VS Code, not just the settings indicators.
