# Issue #170629 — The find widget in the output panel is too small to use with the output panel in the side bar

[https://github.com/microsoft/vscode/issues/170629](https://github.com/microsoft/vscode/issues/170629)

## Summary

Keep open: current source still imposes fixed compact widths and prevents resizing within those widths, supporting the reported sidebar limitation. Output now also has filtering controls, but those do not replace Find; the supplied steps suffice to retest the rendered behavior.

## Change summary

The Output view's Find widget becomes impractically small and cannot be enlarged when Output is moved into the sidebar.

## Best solution

Make the shared editor Find widget use the available space effectively in narrow Output views, with a readable search input and usable navigation. Validate the sidebar case without regressing compact layouts or Find/Replace in ordinary editors.

- **Behavior:**

  > Moving Output into the sidebar must leave Find usable within the available view width. The search input should not be unnecessarily compressed while substantial horizontal space remains, and any displayed resize affordance should work within the available space. Acceptance covers narrow sidebar widths, entering a longer query, navigating matches, and changing the sidebar width. Ordinary editor Find/Replace and keyboard access must remain unchanged.
- **Trace:**

  > OutputViewPane.layoutBodyContent in src/vs/workbench/contrib/output/browser/outputView.ts forwards the view dimensions to the embedded OutputEditor, whose minimap is disabled by default. The shared FindWidget in src/vs/editor/contrib/find/browser/findWidget.ts selects compact modes using editor-width thresholds; findWidget.css imposes fixed 257px and 170px maximum widths. The resize handler rejects every width below 419px as well as widths above the compact CSS maximum, and double-click reset returns for compact widgets. These restrictions match the reported inability to enlarge Find, but the exact current visual impact has not been observed in a running window. Keep the scope on shared Find sizing and its Output consumer; Output filtering is not a substitute, and Sticky Scroll overlap in https://github.com/microsoft/vscode/issues/316851 is separate work. Start by reproducing https://github.com/microsoft/vscode/issues/170629 and establishing a browser layout validation.

## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/170629 reports Windows 11, VS Code 1.74.2, extensions disabled, and concrete steps: move Output into the sidebar and open Find. The reporter's October 2023 follow-up says the size problem persisted after the rounded-corner change.
- **Output uses the shared editor layout:** src/vs/workbench/contrib/output/browser/outputView.ts: OutputViewPane.layoutBodyContent passes the view dimensions to OutputEditor. OutputEditor.getConfigurationOverrides disables the minimap by default and does not provide a separate sidebar Find layout.
- **Compact width restrictions remain:** src/vs/editor/contrib/find/browser/findWidget.ts:740-805 selects reduced, narrow, and collapsed modes from editor width. With the initial matches-count width of 69 and no minimap, a 300px editor selects collapsed mode. src/vs/editor/contrib/find/browser/findWidget.css caps narrow mode at 257px and collapsed mode at 170px with !important, leaving available sidebar space unused.
- **Resizing cannot overcome compact mode:** src/vs/editor/contrib/find/browser/findWidget.ts:1271-1334 creates a resize sash, but its change handler rejects requested widths below FIND_WIDGET_INITIAL_WIDTH (419px) and above the computed CSS maximum. A 170px or 257px compact maximum therefore admits no valid drag width; double-click reset also returns when the current width is below 419px.
- **Canonical search:** Open-issue searches for Find widget with sidebar, side bar, small, narrow, width, and Output resizing did not identify a canonical owning this behavior. https://github.com/microsoft/vscode/issues/316851 is open but concerns Find overlapping Sticky Scroll, not an undersized, non-resizable Output search input.
