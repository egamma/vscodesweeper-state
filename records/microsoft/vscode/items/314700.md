# Issue #314700 — Recent quick pick (Ctrl+R) should support Agents window

[https://github.com/microsoft/vscode/issues/314700](https://github.com/microsoft/vscode/issues/314700)

## Summary

A real gap remains on current main: later work partially connected Open Recent and the Agents Window, but opening Agents still does not reliably add it to history, and the meaning of Ctrl+R inside Agents remains platform-dependent. This accepted Backlog request should stay open while the intended cross-platform window-switching contract is settled.

## Change summary

Make Ctrl+R support switching between normal VS Code workspaces and the Agents Window, opening a selected workspace in a separate VS Code window when invoked from Agents.

## Best solution

Make Open Recent a reliable bidirectional window switcher: expose one canonical Agents Window entry, expose ordinary recent workspaces from Agents, and define consistent new-window and shortcut semantics across platforms without losing the existing recent-sessions picker.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowsMainService.ts`, `src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts`, `src/vs/workbench/browser/actions/windowActions.ts`, `src/vs/sessions/contrib/sessions/browser/sessionsActions.ts`, `src/vs/platform/workspaces/test/node/workspacesHistoryStorage.test.ts`
- **Validation:** Add focused history/keybinding coverage, then manually verify on macOS, Windows, and Linux that Open Recent exposes exactly one Agents Window entry and that invoking the chosen recent-workspace shortcut from Agents opens the selected workspace in a separate window without breaking the Sessions Picker shortcut.
- **Behavior:**

  > Users can switch from a normal VS Code window to the Agents Window through Open Recent, where exactly one stable Agents Window entry is shown. From the Agents Window, users can invoke the documented recent-workspace shortcut and choose a workspace that opens in a separate normal VS Code window. The behavior and discoverable shortcuts must be coherent across macOS, Windows, and Linux, while the recent-sessions picker remains available.
- **Trace:**

  > Agents launches pass through `WindowsMainService.ensureAgentsWindow` in src/vs/platform/windows/electron-main/windowsMainService.ts, which currently sets `noRecentEntry: true`. `WorkspacesHistoryMainService.canonicalizeAgentSessionsWorkspaces` in src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts only transforms internal Agents entries that already exist. `OpenRecentAction` in src/vs/workbench/browser/actions/windowActions.ts binds Ctrl+R and delegates selection to `hostService.openWindow`, with a new window forced only from picker modifiers. `ShowSessionsPickerAction` in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts also binds Ctrl+R on Windows/Linux but uses Ctrl+Alt+R on macOS after https://github.com/microsoft/vscode/commit/a1e92ea5ae5063f4fd0e20432fae5e1614463bf7. The boundary is the recent-window and Sessions-picker interaction; session recency ordering and session navigation from https://github.com/microsoft/vscode/pull/319991 should remain unchanged.
- **Open decisions:**
  - Should the Agents Window always be synthesized in Open Recent, or should opening it create a normal persisted recent-history entry?
  - Should Ctrl+R inside the Agents Window consistently mean recent workspaces on every platform, with the Sessions Picker moved to another shortcut, or should the current platform-specific behavior remain?
  - When a workspace is selected from Open Recent inside the Agents Window, must it always open in a separate window, or should the normal window-opening preference and modifier behavior apply?

## Evidence

- **remaining history gap:** Current src/vs/platform/windows/electron-main/windowsMainService.ts still sets `noRecentEntry: true` in `ensureAgentsWindow`, so opening the Agents Window does not reliably seed Open Recent with an Agents entry.
- **partial Agents entry implementation:** Commit https://github.com/microsoft/vscode/commit/21606a202455695ffcfdb0c99d4ff930b31d0a65 canonicalizes an already-present internal Agents workspace entry as “Agents Window” in src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts; it does not add an entry when history contains none. The narrower cleanup was verified through https://github.com/microsoft/vscode/issues/326566.
- **platform-dependent shortcut:** Commit https://github.com/microsoft/vscode/commit/a1e92ea5ae5063f4fd0e20432fae5e1614463bf7 moved the Sessions Picker to Ctrl+Alt+R only on macOS, leaving Ctrl+R for Open Recent there. Current src/vs/sessions/contrib/sessions/browser/sessionsActions.ts still binds Ctrl+R to the Sessions Picker on Windows/Linux, where it has higher Sessions contribution weight than workbench.action.openRecent.
- **new-window behavior:** src/vs/workbench/browser/actions/windowActions.ts opens an Open Recent selection through `hostService.openWindow`; `forceNewWindow` is set only when the picker records the Ctrl/Cmd modifier, rather than because the command was invoked from the Agents Window.
- **canonical search:** The older open candidate https://github.com/microsoft/vscode/issues/247164 concerns unstable sorting while filtering recent workspaces, not the same observable Agents-window switching behavior. The directly related later issues are closed, narrower implementation records rather than open canonicals.
