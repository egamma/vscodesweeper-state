# Issue #323132 — New Sessions / Agents handoff model picker does not show registered external language models

[https://github.com/microsoft/vscode/issues/323132](https://github.com/microsoft/vscode/issues/323132)

## Summary

The Agents window model picker correctly scopes models per session type — agent-host sessions (Copilot CLI, Claude, cloud agent) only show models registered with a matching `targetChatSessionType`, while external language models (like DeepSeek) register without one. This is architecturally intentional but represents a real gap: external models that work in regular Copilot Chat don't surface in agent-host session types. The assertion error is a separate issue. Keeping open as a valid feature request to surface general-purpose external models in agent-host sessions.

## Change summary

External language models registered by extensions (e.g. DeepSeek) do not appear in the Agents window's agent-host session model picker, though they work in regular Copilot Chat.

## Best solution

Extend `CopilotChatSessionsProvider.getModels()` (in `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`) for agent-host session types to also include general-purpose external models (those without a `targetChatSessionType`) alongside session-targeted models, similar to how `localChatSessionsProvider` already does. This requires product decision on whether external models should be usable with agent-host harnesses, since those harnesses may have specific model requirements.
