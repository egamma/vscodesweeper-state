# Issue #105935 — Interactive playground eats arrow keys

[https://github.com/microsoft/vscode/issues/105935](https://github.com/microsoft/vscode/issues/105935)

## Summary

The bug is still present on main: the `interactivePlaygroundFocus` context key in walkThroughPart.ts relies solely on DOM focus/blur events on the content div, which can stick as `true` when focus moves to widgets like peek references that don't trigger a blur on the walkthrough content. No fix has landed.

## Change summary

Arrow keys are eaten by the interactive playground's scroll commands even after navigating away, because the `interactivePlaygroundFocus` context key doesn't properly reset.

## Best solution

The `interactivePlaygroundFocus` context key should additionally be reset when the editor pane loses visibility or when the active editor changes — not solely relying on DOM blur events. A guard in the `when` clause (e.g., checking that the active editor pane IS the WalkThroughPart) would also prevent the arrow keys from firing in unrelated contexts.
