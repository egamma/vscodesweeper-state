# Issue #275103 — VSCode not recognising ']' in combination with cmd + shift

[https://github.com/microsoft/vscode/issues/275103](https://github.com/microsoft/vscode/issues/275103)

## Summary

Legitimate keyboard layout bug on macOS with EurKEY: when `]` is produced by Shift+9, adding Cmd causes VS Code to resolve the combo as `shift+9` instead of `shift+meta+]`. The keyboard layout mapper doesn't correctly reverse the shift-consumed character. No fix found on main.

## Change summary

On macOS with EurKEY layout, Cmd+Shift+] is misrecognized as shift+9 because the layout maps ] to Shift+9 and VS Code fails to resolve the logical key when Shift is already consumed by the character production.

## Best solution

The keyboard layout mapper (likely in `src/vs/platform/keyboardLayout/`) needs to handle the case where a modifier (Shift) is 'consumed' to produce a character (] = Shift+9 on EurKEY) — when Cmd is added, it should still resolve the intended logical key `]` rather than the physical key `9` with explicit Shift. This is the same class of problem as other non-US layout issues but specific to macOS EurKEY.
