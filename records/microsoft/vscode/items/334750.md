# Issue #334750 — Agent host Claude harness: toSdkModelId turns claude-fable-5-1[1m] into claude-fable-5 (native "Fable" row runs Fable 5 instead of 5.1)

[https://github.com/microsoft/vscode/issues/334750](https://github.com/microsoft/vscode/issues/334750)

## Summary

Traced and confirmed in source: `tryParseClaudeModelId` in `claudeModelId.ts` has no pattern for the `[1m]` bracket suffix Claude Code CLI actually emits, so a minor-versioned model id like `claude-fable-5-1[1m]` falls through to Pattern 4, which swallows the minor version into the modifier and silently drops it. This is a real, unfixed defect worth keeping open for a small, well-scoped patch.

## Change summary

The native Claude harness silently downgrades a configured `claude-{name}-{major}-{minor}[1m]` model to `claude-{name}-{major}` because the SDK model-id parser doesn't recognize the `[1m]` context-window suffix form.

## Best solution

Add `[1m]`/`[Nm]` bracket-suffix handling to the parser in src/vs/platform/agentHost/node/claude/claudeModelId.ts (e.g. strip a trailing `[...]` before the dash-based patterns run, or fold it into `joinModifiers`), and add a `claude-fable-5-1[1m]` / `claude-opus-4-8[1m]` case to claudeModelId.test.ts alongside the existing `-1m` dash-form tests.
