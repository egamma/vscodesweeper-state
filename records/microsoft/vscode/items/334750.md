# Issue #334750 — Agent host Claude harness: toSdkModelId turns claude-fable-5-1[1m] into claude-fable-5 (native "Fable" row runs Fable 5 instead of 5.1)

[https://github.com/microsoft/vscode/issues/334750](https://github.com/microsoft/vscode/issues/334750)

## Summary

Confirmed on current main by tracing the regex: `claude-fable-5-1[1m]` fails pattern 1 (the `[1m]` suffix isn't preceded by a dash), falls through to pattern 4, which swallows the minor version `1[1m]` into `mod`, and since `fable` isn't in `VALID_SUFFIXES`, `extractValidSuffix` drops it entirely — producing `claude-fable-5` instead of `claude-fable-5-1`. Confirmed with a second reporter on stable. Keeping open; the fix approach (parser-level bracket handling vs. skipping normalization for already-canonical native-transport ids) is a real design choice.

## Change summary

`toSdkModelId`/`tryParseClaudeModelId` mis-parse Claude model IDs with a trailing `[1m]` context suffix and a minor version (e.g. `claude-fable-5-1[1m]`), silently dropping the minor version and routing the session to the wrong model.

## Best solution

Fix the bracket-suffix handling in src/vs/platform/agentHost/node/claude/claudeModelId.ts (strip/reattach `[1m]`/`[2m]` before pattern matching, independent of the per-family VALID_SUFFIXES allowlist used for the dash form), or decide to bypass toSdkModelId entirely for ids sourced from supportedModels() on the native transport since those are already SDK-canonical; add claudeModelId.test.ts coverage for `claude-fable-5-1[1m]` and `claude-opus-4-8[1m]`.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/claude/claudeModelId.ts`, `src/vs/platform/agentHost/test/node/claudeModelId.test.ts`
- **Validation:** Add/extend claudeModelId.test.ts to assert toSdkModelId('claude-fable-5-1[1m]') and toSdkModelId('claude-opus-4-8[1m]') preserve the minor version correctly (and don't regress the existing dash-form 1m tests).
- **Behavior:**

  > A Claude model id with a trailing bracketed context suffix (`claude-fable-5-1[1m]`, `claude-opus-4-8[1m]`) must retain its major/minor version when normalized via toSdkModelId/tryParseClaudeModelId — the session must run on the exact configured model (e.g. Fable 5.1), not silently downgrade to the major-only id (Fable 5). Existing dash-form `-1m` behavior (only preserved for the opus family) must be unchanged. Acceptance: new test cases for the bracket form pass alongside all existing claudeModelId.test.ts cases.
- **Trace:**

  > doParse() in claudeModelId.ts tries patterns in order; the `[1m]` suffix has no leading dash so pattern 1 (`^claude-(name)-(major)-(minor)(?:-(mod))?$`) never matches the full string, and pattern 4 (`^claude-(name)-(major)(?:-(mod))?$`) matches instead, capturing the minor version as part of `mod` ('1[1m]'). extractValidSuffix() then looks up `name` in the family-scoped VALID_SUFFIXES map (only 'opus' lists '1m') and returns '' for any other family, so the minor version is lost. Ids without a minor version happen to fall through all patterns (brackets aren't \w chars) and pass through unchanged, which is why only the minor-version case is broken. The boundary: do not change the dash-form handling (VALID_SUFFIXES family gating) that existing tests cover; open question is whether the fix belongs in this general parser (affecting every toSdkModelId/CAPI translation caller) or only at the specific call site that feeds supportedModels() ids from the native transport into toSdkModelId, per the issue body's own 'possibly related' framing of the two suggested fixes. Related: https://github.com/microsoft/vscode/issues/335687, https://github.com/microsoft/vscode/issues/334017.
- **Open decisions:**
  - Should the bracket suffix (`[1m]`/`[2m]`) be handled generally inside tryParseClaudeModelId/toSdkModelId (affecting all callers, including CAPI dotted-id translation), or only at the specific call site that normalizes ids already sourced from the native transport's supportedModels(), which the code comment says should be identity-only?
  - Should the normalized bracket-form output re-attach the bracket literally (e.g. `claude-fable-5-1[1m]`) or convert it to the existing dash-form `-1m` modifier, and should that follow the same per-family VALID_SUFFIXES allowlist used today for the dash form?
