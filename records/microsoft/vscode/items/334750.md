# Issue #334750 — Agent host Claude harness: toSdkModelId turns claude-fable-5-1[1m] into claude-fable-5 (native "Fable" row runs Fable 5 instead of 5.1)

[https://github.com/microsoft/vscode/issues/334750](https://github.com/microsoft/vscode/issues/334750)

## Summary

Traced and confirmed against current main: toSdkModelId/tryParseClaudeModelId in claudeModelId.ts does not handle the trailing bracket `[1m]` suffix Claude Code actually writes to settings.json, so the minor version gets swallowed into an unrecognized modifier and silently dropped for the native (BYO-Anthropic) picker row.

## Change summary

The Claude harness model-ID normalizer mis-parses `claude-fable-5-1[1m]` (and `claude-opus-4-8[1m]`) as the major-only id, silently dropping the minor version and running the wrong model.

## Best solution

Add bracket-suffix handling to claudeModelId.ts (e.g. strip/parse a trailing `[1m]`/`[..]` modifier before the existing dash patterns, mirroring Claude Code's own `(?:\[[12]m\])?$` regex), and add `claude-fable-5-1[1m]` / `claude-opus-4-8[1m]` cases to src/vs/platform/agentHost/test/node/claudeModelId.test.ts.
