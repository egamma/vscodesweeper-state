# Issue #334750 — Agent host Claude harness: toSdkModelId turns claude-fable-5-1[1m] into claude-fable-5 (native "Fable" row runs Fable 5 instead of 5.1)

[https://github.com/microsoft/vscode/issues/334750](https://github.com/microsoft/vscode/issues/334750)

## Summary

Confirmed by tracing the parser on main: the bracketed `[1m]` context suffix (used natively by the Claude CLI) isn't preceded by a dash, so Pattern 1 in `tryParseClaudeModelId` fails to match and Pattern 4 swallows the minor version into the modifier, silently downgrading `claude-fable-5-1[1m]` to `claude-fable-5`. No fix exists on main yet.

## Change summary

toSdkModelId()/tryParseClaudeModelId() mis-parses model IDs with a minor version plus the native `[1m]` context suffix, dropping the minor version and running the wrong model.

## Best solution

Strip/recognize a trailing `[1m]`/`[2m]` suffix as a modifier before running the hyphen/dot patterns in claudeModelId.ts, so `claude-fable-5-1[1m]` parses as name=fable, major=5, minor=1, mod=1m (matching Claude Code's own `(?:\[[12]m\])?$` handling), and add a regression test alongside the existing 1m test cases in claudeModelId.test.ts.
