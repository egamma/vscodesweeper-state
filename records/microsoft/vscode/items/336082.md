# Issue #336082 — Disable sessions when isolated worktree creation fails

[https://github.com/microsoft/vscode/issues/336082](https://github.com/microsoft/vscode/issues/336082)

## Summary

The fallback-to-folder-isolation behavior described here is intentional and documented in code (WorktreeIsolation.resolveOnFirstSend explicitly falls back to folder isolation on any creation failure so the session isn't left permanently pending), but the report raises a real security/isolation-guarantee concern about that trade-off that only a maintainer can weigh — keeping open rather than closing given the security angle.

## Change summary

When isolated worktree creation fails, the session silently continues using the original repository folder instead of entering a failed/blocked state.

## Best solution

A maintainer needs to decide whether the deliberate 'never leave a session stuck pending' trade-off in src/vs/platform/agentHost/node/shared/worktreeIsolation.ts (resolveOnFirstSend / buildWorktreeFailureNotification) should instead fail the session outright when isolation was explicitly requested, since the current warning-only notice can be missed and lets the session modify the live checkout.
