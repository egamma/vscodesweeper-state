# Issue #332257 — Disable standalone MCP server should change the color of the entry

[https://github.com/microsoft/vscode/issues/332257](https://github.com/microsoft/vscode/issues/332257)

## Summary

Fresh, clearly-documented visual bug in the new MCP server list UI: disabling a standalone MCP server entry doesn't grey it out the way disabling a plugin-installed one does. The reporter gives precise repro steps plus a video, and this is very recent test feedback on an in-flight feature (issue #332023), so it should be routed to the MCP/chat customizations area for a fix.

## Change summary

In the MCP servers list, disabling a standalone (non-plugin) MCP server does not change the entry's color to grey, unlike disabling a plugin-provided server.

## Best solution

Fix the disabled-state rendering in src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts so standalone (workspace/user-configured) server entries reliably toggle the 'disabled' class the same way plugin-provided entries do — likely a gap in how `element.localServer` is resolved/matched (via `LocalMcpServerMatcher`) or in one of the several separate render branches (`updateKnownServerStatus` vs the plain autorun branch) that compute `disabled` differently per entry kind.
