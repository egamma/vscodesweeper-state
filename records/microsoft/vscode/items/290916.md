# Issue #290916 — Folders are not hidden when explorer.excludeGitIgnore is true

[https://github.com/microsoft/vscode/issues/290916](https://github.com/microsoft/vscode/issues/290916)

## Summary

Still reproduces on main: the case-insensitive fix in 10771d939c5 passes `ignoreCase` to `IgnoreFile` on creation, but `processIgnoreFile` is async and called without await in the synchronous `filter()` method — the ignore tree may not be populated when sibling folders are first filtered, causing them to be grayed (via git decorations) but not hidden by the explorer filter. The bug remains valid.

## Change summary

Folders matched case-insensitively by .gitignore on macOS are grayed out but not hidden when `explorer.excludeGitIgnore` is enabled.

## Best solution

Investigate why the async `processIgnoreFile` race in `FilesFilter.filter()` causes the initial tree render to miss the gitignore rules on macOS. The case-insensitive glob matching itself looks correct after 10771d939c5, so the likely remaining issue is timing: the filter runs synchronously but the ignore file content hasn't resolved yet. A re-filter after the ignore file is processed (the `_onDidChange.fire()` in line 1383) should re-hide items, so the bug may be more specific (e.g., only on first open, or related to the tree not re-evaluating directory visibility after the async update).
