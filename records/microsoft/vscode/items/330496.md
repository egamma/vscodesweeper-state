# Issue #330496 — ChatApprovedAccountOrganizations causes toolset bootstrap deadlock

[https://github.com/microsoft/vscode/issues/330496](https://github.com/microsoft/vscode/issues/330496)

## Summary

Well-diagnosed bug confirmed by tracing the source: `getToolByName` filters through `isPermitted` (agent-mode gating), which is circular for toolset registration during the transient window where account-policy verification disables agent mode, causing extension-contributed tools to be permanently dropped from built-in toolsets on that window.

## Change summary

During transient agent-mode-disabled windows (e.g. while `ChatApprovedAccountOrganizations` policy verification is pending), toolsets computed via `getToolByName` permanently miss extension-contributed tools even after the policy resolves and agent mode re-enables.

## Best solution

Apply the reporter's proposed fix in src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts: change `getToolByName()` to iterate `_tools` directly instead of `getAllToolsIncludingDisabled()`, so toolset-registration lookups aren't gated by the transient `isPermitted`/agent-mode check — consistent with the existing documented contract that `getToolByName` returns tools 'regardless of when clause'.

Add a new unit test verifying that when `ChatConfiguration.AgentEnabled` is set false and an extension-source `IToolData` is registered but not yet added to any toolset, `getToolByName` still resolves it by reference name — the test should fail before the fix (due to the `isPermitted` gate) and pass after.
