# Issue #116495 — Git - git.path not resolving path with environment variable

[https://github.com/microsoft/vscode/issues/116495](https://github.com/microsoft/vscode/issues/116495)

## Summary

Keep this accepted feature request open: current Git discovery still passes environment-variable placeholders literally to executable lookup. It has 27 upvotes, and the related general settings request does not establish the same Git-specific symptom required for a duplicate close on re-review.

## Change summary

Support ${env:NAME} substitution in git.path so Git executables can be located through environment-dependent paths.

## Best solution

Support environment-variable-based executable paths in the built-in Git extension while preserving literal paths, ordered candidate lookup, and existing trust restrictions. Coordinate the substitution contract with the broader settings-variable work without requiring that entire capability to land first.

- **Behavior:**

  > A git.path containing ${env:GDIR} should locate the same executable as the equivalent literal path when GDIR is defined in the relevant extension-host environment. Successful discovery must also support subsequent Git operations. Literal paths, candidate ordering, automatic fallback, and existing trust restrictions remain unchanged. Acceptance includes the reported Windows scenario and an explicitly agreed outcome for undefined environment variables.
- **Trace:**

  > createModel in extensions/git/src/main.ts reads git.path and builds pathHints without substitution. findGit in extensions/git/src/git.ts passes each hint to findSpecificGit, which spawns it literally; configuration retrieval in src/vs/workbench/api/common/extHostConfiguration.ts does not supply substitution either. The source therefore confirms a missing capability, not a regression in a documented Git substitution contract. The boundary is executable-path resolution in the built-in Git extension; do not introduce arbitrary command execution or global settings interpolation. Existing Restricted Mode absolute-path and workspace-exclusion checks must retain their protection. Coordinate terminology and expectations with https://github.com/microsoft/vscode/issues/2809; uncertainty remains over the user-visible handling of undefined variables.
- **Open decisions:**
