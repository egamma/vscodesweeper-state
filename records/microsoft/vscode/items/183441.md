# Issue #183441 — Focus on already opened editor instead of default editor provided by extension

[https://github.com/microsoft/vscode/issues/183441](https://github.com/microsoft/vscode/issues/183441)

## Summary

The reported gap remains in the current source: Explorer resolves the default custom editor without preferring an already-open text editor for the same resource. The linked implementation PR was closed without merging, and no verified older canonical owns this symptom.

## Change summary

Clicking a file in Explorer should reveal its already-open text editor rather than open a second tab using the default custom editor.

## Best solution

Preserve the user's existing editor choice when reopening the same file through Explorer, while retaining explicit Open With choices and existing editor-group semantics. Remembering editor types after all tabs close is a separate persistence feature, not necessary to resolve the reported bug.
