# Issue #183441 — Focus on already opened editor instead of default editor provided by extension

[https://github.com/microsoft/vscode/issues/183441](https://github.com/microsoft/vscode/issues/183441)

## Summary

Still present on main: the editor resolver only checks for existing editors with the same editorId, so clicking a file in the Explorer opens a second editor tab instead of revealing the one already open with a different editor type. The `help wanted` label is appropriate — the issue is acknowledged and awaiting a contribution.

## Change summary

When a file is already open in one editor type (e.g. text editor), clicking the file in the Explorer opens a second tab with the default custom editor instead of focusing the already-open editor.

## Best solution

Modify the editor resolution logic in `editorResolverService.ts` so that when resolving an editor for a resource, it checks whether *any* editor (regardless of `editorId`) is already open for that resource and prefers revealing the existing one. The previous attempt in PR https://github.com/microsoft/vscode/pull/189733 was closed without merge — a fresh contribution following the same general approach (preferring already-open editors during resolution) would address this.
