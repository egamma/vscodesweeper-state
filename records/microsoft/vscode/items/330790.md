# Issue #330790 — Terminal OutputMonitor may report "needs input" for long-running commands that continuously produce output

[https://github.com/microsoft/vscode/issues/330790](https://github.com/microsoft/vscode/issues/330790)

## Summary

The described defect is real and traceable in current code — `_handleTimeoutState` in outputMonitor.ts fires `onDidDetectInputNeeded` purely on extended-polling timeout, with no positive prompt evidence — but a VS Code collaborator has stated the team is moving away from this local-harness terminal monitor toward the new Copilot-based agent host and will likely not invest further fixes here.

## Change summary

OutputMonitor's extended-polling timeout signals 'input may be needed' for long-running commands that continuously stream new output (e.g. tqdm progress bars), even though continuous output is evidence the process is still working, not blocked on stdin.

## Best solution

Given the maintainer's stated direction away from this local harness monitor, the best end state is to decline further investment here and point users to the newer Copilot agent host/harness that is replacing this code path; if the team keeps investing in the legacy monitor, the fix would be in `_handleTimeoutState`/`_handleIdleState` in outputMonitor.ts to require positive prompt evidence (or track 'no new output' rather than 'not idle') before firing `onDidDetectInputNeeded`.
