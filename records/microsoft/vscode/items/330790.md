# Issue #330790 — Terminal OutputMonitor may report "needs input" for long-running commands that continuously produce output

[https://github.com/microsoft/vscode/issues/330790](https://github.com/microsoft/vscode/issues/330790)

## Summary

Traced in the current source: `_handleTimeoutState` in outputMonitor.ts fires `onDidDetectInputNeeded` purely because the extended-polling timeout elapsed, with no check for continuing output activity — matching the report exactly. A collaborator has flagged that the team is moving away from this local harness toward Copilot and may not prioritize a fix, so this stays open rather than being closed outright.

## Change summary

OutputMonitor's extended-polling timeout signals "input needed" for long-running commands that keep producing new output (e.g. a tqdm progress bar), even though continuous output is evidence the process is still working, not blocked on stdin.

## Best solution

In `_handleTimeoutState` (src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/monitoring/outputMonitor.ts), track whether new terminal data arrived during the extended polling window (similar to the existing `hasReceivedData` tracked in `_waitForIdle`) and suppress `onDidDetectInputNeeded` when output is still actively changing, only firing when the extended timeout elapses AND output has gone stale.
