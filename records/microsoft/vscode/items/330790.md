# Issue #330790 — Terminal OutputMonitor may report "needs input" for long-running commands that continuously produce output

[https://github.com/microsoft/vscode/issues/330790](https://github.com/microsoft/vscode/issues/330790)

## Summary

Traced conclusively in current main: `_waitForIdle`'s extended-polling loop can exit via timeout (2 minutes) purely because idle was never reached, and `_handleTimeoutState` then unconditionally fires `onDidDetectInputNeeded` for `extended=true` without checking whether the terminal was actively producing new output the whole time — exactly the false positive described.

## Change summary

Long-running commands with continuously changing output (e.g. tqdm progress bars) can be reported as 'may need input' purely because the extended 2-minute polling window elapsed, even with no idle period and no prompt pattern match.

## Best solution

In outputMonitor.ts, have `_waitForIdle` surface whether recent activity (`hasReceivedData`) was observed near the end of the extended window, and have `_handleTimeoutState` only fire `onDidDetectInputNeeded` when there's no such recent-activity evidence (or a high-confidence prompt pattern) — otherwise keep polling or report still-running.
