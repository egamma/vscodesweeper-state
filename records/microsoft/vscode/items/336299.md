# Issue #336299 — agentFilesLocations, skillFilesLocations disappears

[https://github.com/microsoft/vscode/issues/336299](https://github.com/microsoft/vscode/issues/336299)

## Summary

This is the intended, deliberately-built product direction, not a bug or accidental regression: the settings still work today but carry an explicit, coordinated deprecation notice pointing at a purpose-built migration flow, so I'd close as *as-designed rather than treat it as an open ask to reverse the plan.

## Change summary

Reporter wants `chat.agentFilesLocations` and `chat.agentSkillsLocations` (and the 'Local agent harness' they configure) kept configurable instead of being deprecated in favor of fixed `.github/agents` / `.github/skills` locations.

## Best solution

Keep the shipped direction: these settings (`chat.agentFilesLocations`, `chat.agentSkillsLocations`, `chat.promptFilesLocations`, `chat.modeFilesLocations`) are intentionally being sunset alongside the Local agent harness, with a dedicated 'Agent Customizations editor' migration flow (`AICustomizationManagementCommands.OpenEditor` / `CustomizationMigrationCategoryId.ConfiguredLocations`) already built to move custom locations into supported ones — the reporter's per-location and enable/disable use cases should be raised as follow-up asks against that new editor rather than by keeping the old settings alive.

## Vision fit

- **Fit:** aligned
- **Reason:** Consolidating ad-hoc, per-user configuration into a small set of supported, uniform locations backed by an in-product migration UI fits the 'simple, uniform UI and UI interactions' value and the extension-ecosystem/AI-assisted-development durable themes better than open-ended custom paths.
- **Evidence:** Values: "Simple, uniform UI and UI interactions." Durable theme: "Extension ecosystem — API hygiene ... authoring tooling."
