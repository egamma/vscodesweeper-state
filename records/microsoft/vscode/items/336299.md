[https://github.com/microsoft/vscode/issues/336299](https://github.com/microsoft/vscode/issues/336299)

## Summary

Keep open to resolve the remaining location-control requirement. The maintainer reports that custom-location support has been restored, but explicitly says built-in locations cannot be excluded, leaving the reporter's request to hide ~/.copilot skills unanswered.

## Change summary

Preserve configurable agent and skill directories, including the ability to exclude default user-skill locations during development.

## Best solution

Retain the restored custom-location support and establish a supported way to exclude unwanted default skill directories without copying or deleting their contents. Define how that exclusion applies to harness-owned discovery before treating the whole report as completed.

- **Behavior:**

  > Users need to reuse skills and custom agents from configured directories without copying them into vendor-specific folders. Restored additive location support addresses that portion, but users also want to exclude default user-skill directories during development without changing their files. Acceptance must demonstrate that an excluded directory contributes no skills to a new affected session while enabled custom directories continue working. Existing default discovery must remain unchanged when no exclusion is requested.
- **Trace:**

  > The local discovery path already interprets false location entries as exclusions: PromptsConfig.promptSourceFolders in src/vs/workbench/contrib/chat/common/promptSyntax/config/config.ts removes explicitly disabled defaults, and PromptFilesLocator.getLocalStorageFolders preserves that result. Copilot Agent Host discovery instead uses SDK discovery RPCs in src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts. The maintainer's update at https://github.com/microsoft/vscode/issues/336299#issuecomment-5948483087 reports that https://github.com/microsoft/vscode/pull/338985 restored additive client customizations but explicitly excludes removal of built-in locations. The supplied checkout predates that restoration, so first establish the post-restoration discovery and enablement paths before diagnosing the remaining exclusion behavior. Preserve additive custom-location support, normal defaults, and unrelated remote path-resolution behavior. Individual-skill toggles tracked by https://github.com/microsoft/vscode/issues/290290 are related but do not by themselves establish directory-level exclusion.
- **Open decisions:**
  - Should false entries in the existing location settings exclude matching harness-discovered default directories, or should directory exclusion use a separate supported control?
  - Should a workspace's exclusion of user-skill directories apply uniformly to all Agent Host harnesses, or only to explicitly selected harnesses?
