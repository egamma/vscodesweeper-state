# Issue #336299 — agentFilesLocations, skillFilesLocations disappears

[https://github.com/microsoft/vscode/issues/336299](https://github.com/microsoft/vscode/issues/336299)

## Summary

A maintainer (aeschli) explained this is a deliberate design direction — migrating away from a VS Code-specific configuration layer in favor of letting each harness (Copilot CLI, Claude, Codex) control its own customization locations — but the reporter and other commenters are actively pushing back and the thread is still live, so this isn't settled enough for a design-intent close.

## Change summary

Restore the removed `chat.agentFilesLocations` / `chat.skillFilesLocations` settings so users can configure custom, harness-neutral folders (e.g. `.agents/`) for agents and skills instead of being forced into harness-specific folders like `.github/`, `.claude/`.

## Best solution

This is a product-direction call for the chat/agent-customization owners: either confirm the harness-controlled approach as final (and close as-designed with a clear explanation of the Copilot CLI `skillDirectories` / `--plugin-dir` alternatives), or reconsider exposing a VS-Code-level override for workspace skill/agent folder discovery. Best tracked alongside the customization-discovery code in src/vs/workbench/contrib/chat/browser/aiCustomization.
