# Issue #141256 — The shortcut of `Replace with Next Value` conflicts with `Focus Breadcrumbs`

[https://github.com/microsoft/vscode/issues/141256](https://github.com/microsoft/vscode/issues/141256)

## Summary

The default shortcut conflict remains in current main, and the maintainer explicitly welcomed a replacement shortcut. Keep this accepted Backlog request open until a non-conflicting default is chosen; custom keybindings provide a workaround, not the requested default behavior.

## Change summary

## Plan brief

- **Likely files:** `src/vs/editor/contrib/inPlaceReplace/browser/inPlaceReplace.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts`
- **Validation:** On macOS, open a writable file with a value supported by Replace with Next Value and breadcrumbs available. Verify the agreed replacement shortcut changes the value rather than focusing breadcrumbs, while the existing breadcrumb shortcut still navigates breadcrumbs. Repeat with breadcrumbs disabled, and check the chosen binding for overlapping defaults on each platform where it will apply.
- **Behavior:**

  > Replace with Next Value should have a usable default shortcut that is not intercepted by breadcrumb commands. The reported macOS shortcut currently opens breadcrumb navigation instead of replacing the value. Acceptance requires the agreed shortcut to invoke value replacement with breadcrumbs both enabled and disabled, while preserving breadcrumb navigation and previous-value replacement.
- **Trace:**

  > InPlaceReplaceDown in src/vs/editor/contrib/inPlaceReplace/browser/inPlaceReplace.ts registers editor.action.inPlaceReplace.down as CtrlCmd+Shift+Period under editorTextFocus and writable-editor conditions. FocusAndSelectBreadcrumbs in src/vs/workbench/browser/parts/editor/breadcrumbsControl.ts registers that same shortcut at a higher workbench weight with conditions that overlap editor focus; breadcrumbs.toggleToOn also claims it when breadcrumbs are disabled. These current registrations establish that the default conflict remains without executing the checkout. The discussion at https://github.com/microsoft/vscode/issues/141256 settles the goal of finding another default, but not the replacement: Ctrl+Alt+Period is only a commenter suggestion. Preserve command identities, value-replacement semantics, and user-defined overrides; the scope is default keyboard access, not a redesign of breadcrumb navigation.
- **Open decisions:**
  - Which replacement shortcut and platform coverage should become the default for Replace with Next Value, and should Replace with Previous Value receive a matching shortcut for consistency?
