# Issue #200734 — Diff Editor: Swapping Left & Right side is slow due to diff computation

[https://github.com/microsoft/vscode/issues/200734](https://github.com/microsoft/vscode/issues/200734)

## Summary

Keep open: swapping an unchanged model pair still misses the direction-specific diff cache and requests another worker computation. The recomputation is confirmed from current source, but its present-day latency and a correctness-preserving optimization need investigation.

## Change summary

Swapping the original and modified sides of an existing comparison incurs another expensive diff computation.

## Best solution

Make swapping unchanged comparison models responsive without sacrificing correct line, character, and moved-text mappings. Establish the current performance cost and safe reuse boundary in the diff editor's view-model and provider path before implementing an optimization.

- **Direction-specific cache:** WorkerBasedDocumentDiffProvider.computeDiff in src/vs/editor/browser/widget/diffEditor/diffProviderFactoryService.ts keys its static cache by the ordered original and modified URIs and validates ordered model IDs and alternative version IDs. After computing A→B, a first swap to B→A therefore misses that entry and calls editorWorkerService.computeDiff again. Subsequent swaps can hit separately populated directional entries; this is not evidence that every swap always recomputes.
- **Worker and correctness boundary:** src/vs/editor/browser/services/editorWorkerService.ts:110–125 forwards each cache miss to worker.$computeDiff and reconstructs line and moved-text mappings.
