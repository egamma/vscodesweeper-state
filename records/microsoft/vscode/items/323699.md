# Issue #323699 — GitHub-managed custom model with Vision enabled is exposed as Tools-only and rejects image attachments

[https://github.com/microsoft/vscode/issues/323699](https://github.com/microsoft/vscode/issues/323699)

## Summary

The reported behavior — GitHub-managed custom models losing their Vision capability while the same model works via a direct custom endpoint — points to the GitHub API not propagating the vision flag for custom models. VS Code's client code faithfully reads `capabilities.supports.vision` from the API response (chatEndpoint.ts:183) and surfaces it correctly; the gap is upstream in the GitHub custom-models API or its capability metadata pipeline. Keeping open for triage and potential upstream escalation.

## Change summary

GitHub-managed custom models configured with Vision enabled are exposed as Tools-only in VS Code, rejecting image attachments, while the same model added as a direct custom endpoint correctly shows Tools + Vision.

## Best solution

Investigate whether the GitHub Models API (`/models` endpoint) returns `capabilities.supports.vision: true` for custom models that have Vision enabled in the GitHub UI. If the API omits the flag, the fix belongs in the GitHub custom-models platform (server-side capability propagation). If the API does return the flag, then there may be a client-side filtering issue in the Copilot extension's model metadata pipeline — the relevant code path is `extensions/copilot/src/platform/endpoint/node/chatEndpoint.ts` (constructor, line 183). The reporter's comparison with direct custom endpoints (BYOK) is strong evidence that the client path works when the metadata is correct.
