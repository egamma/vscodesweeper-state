# Issue #275808 — keybound merge-conflict.accept.both complains cursor not within a merge

[https://github.com/microsoft/vscode/issues/275808](https://github.com/microsoft/vscode/issues/275808)

## Summary

The shortcut invokes the conflict-marker editor's command, not the three-way merge editor's Accept Combination action. Keep this open for the remaining capability gap: a bindable command that smart-combines only the focused conflict.

## Change summary

Provide a keyboard-bindable equivalent of Accept Combination for the focused three-way merge conflict.

## Best solution

Expose the merge editor's per-conflict smart-combination action as a discoverable, bindable command, preserving the separate conflict-marker commands and leaving unrelated conflicts unchanged.

  > Thanks for the report. `merge-conflict.accept.both` operates on textual conflict markers, whereas the three-way merge editor uses separate commands. Its `mergeEditor.acceptAllCombination` command affects eligible conflicts throughout the file, and the individual input-toggle commands are not equivalent to Accept Combination. The remaining request is a bindable Accept Combination action for only the focused conflict.
