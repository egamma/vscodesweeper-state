# Issue #157461 — Support displaying inherited members in outline view

[https://github.com/microsoft/vscode/issues/157461](https://github.com/microsoft/vscode/issues/157461)

## Summary

Keep open: this team-authored Backlog request has 81 community upvotes, and current main still cannot represent hierarchical outline symbols located in another document. The Java extension's QuickPick command is a workaround, not implementation of the requested Outline behavior.

## Change summary

Allow Outline providers to include inherited members from other files and navigate to their definitions.

## Best solution

Extend the document-symbol/Outline contract with cross-document locations while preserving symbol hierarchy, then make Outline reveal open the target resource. The API design must remain compatible with language providers that only return symbols from the active document.

## Evidence

- **URI discarded:** src/vs/workbench/api/common/extHostLanguageFeatures.ts converts legacy SymbolInformation entries into DocumentSymbol objects using only location.range, dropping location.uri.
- **outline navigation:** src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts builds the model for one textModel.uri, and src/vs/workbench/contrib/outline/browser/outlinePane.ts delegates item activation to that document outline's reveal operation.
