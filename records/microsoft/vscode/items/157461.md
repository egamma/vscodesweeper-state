# Issue #157461 — Support displaying inherited members in outline view

[https://github.com/microsoft/vscode/issues/157461](https://github.com/microsoft/vscode/issues/157461)

## Summary

Inherited-member navigation remains unsupported by the built-in Outline's document-local symbol contract. Keep this accepted, team-authored request open: it has 80 upvotes, and the merged Java QuickPick implementation does not provide the requested Outline capability.

## Change summary

Allow the Outline to display inherited class members, optionally hide them, and navigate to their definitions in other documents.

## Best solution

Design a core Outline and extension-provider contract that supports inherited members with cross-document navigation while preserving existing document-local behavior. Language extensions should supply inheritance information rather than core inferring language semantics.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts`, `src/vs/workbench/contrib/outline/browser/outline.contribution.ts`
- **Validation:** With a test provider supplying a derived class and an inherited member defined in a second document, verify that Outline can show and hide inherited entries and opens the correct external definition when selected. Verify that existing document-local providers retain their hierarchy, navigation and filtering behavior; add provider-conversion and Outline-navigation tests for the agreed contract.
- **Behavior:**

  > A class outline should optionally include inherited members, including members defined outside the active document. Selecting an inherited member should navigate to its actual definition rather than reuse its range in the active document. Existing providers that supply only local symbols must continue to work unchanged. Acceptance should cover inherited-member visibility, external-definition navigation and preservation of local-symbol behavior.
- **Trace:**

  > DocumentSymbol in src/vscode-dts/vscode.d.ts has no URI, and DocumentSymbolAdapter._asDocumentSymbolTree in src/vs/workbench/api/common/extHostLanguageFeatures.ts discards SymbolInformation.location.uri. DocumentSymbolsOutline.reveal in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts always navigates using the outline model's URI. Existing outline.showMethods/showProperties/showFields settings are kind filters, not inheritance support. The merged Java implementation at https://github.com/redhat-developer/vscode-java/pull/2590 supplies a separate QuickPick workaround. The remaining uncertainty is the public contract and presentation, not whether the current document-local path can represent the request; preserve existing provider compatibility and leave language-specific inheritance discovery to extensions.
- **Open decisions:**
  - Should inherited members be exposed through an extension of DocumentSymbolProvider or through a separate provider contract?
  - Should inherited entries be grouped by declaring type or mixed with local members, and should their visibility be controlled globally or per Outline?

## Evidence

- **Current public API limitation:** src/vscode-dts/vscode.d.ts:3584-3633 defines DocumentSymbol with range, selectionRange and children, but no URI or inherited-member metadata. The requesting document remains the only document represented by this contract.
- **Reported fallback still loses location:** src/vs/workbench/api/common/extHostLanguageFeatures.ts:44-107, DocumentSymbolAdapter._asDocumentSymbolTree, converts SymbolInformation into document symbols using location.range without retaining location.uri. This confirms the limitation identified in comments 7 and 9 of https://github.com/microsoft/vscode/issues/157461.
- **Outline navigation remains document-local:** src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts:227-232, DocumentSymbolsOutline.reveal, opens model.uri with the selected symbol's range; it cannot select an individual symbol's external document.
- **Existing-capability check:** src/vs/workbench/contrib/outline/browser/outline.contribution.ts registers outline.showMethods, outline.showProperties and outline.showFields as symbol-kind filters. These settings filter supplied symbols; they do not request inherited members or enable cross-document locations.
- **Java workaround is not Outline support:** https://github.com/redhat-developer/vscode-java/pull/2590 merged on 2025-02-12 and provides inherited-symbol viewing through QuickPick using a Java language-server extension method. That separate UI does not resolve the built-in Outline/API request.

Earlier reports https://github.com/microsoft/vscode/issues/84060 and https://github.com/microsoft/vscode/issues/54850 are closed; https://github.com/microsoft/vscode/issues/167558 was explicitly closed as a duplicate of this issue.
