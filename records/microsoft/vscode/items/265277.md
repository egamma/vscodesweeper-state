# Issue #265277 — Markdown preview doesn't refresh/reload when the file is overwritten

[https://github.com/microsoft/vscode/issues/265277](https://github.com/microsoft/vscode/issues/265277)

## Summary

Still reproduces on main: the file-system watcher guard at line 167 of preview.ts drops change events when the document is already open, leaving the preview stale after external overwrites. An open PR (#316756) has the fix pending review.

## Change summary

Markdown preview does not refresh when the underlying file is overwritten externally (by an agent, script, file copy, etc.) while the document is open in VS Code.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/316756, which removes the open-document guard from the file-system watcher so `refresh()` fires unconditionally — downstream debouncing and version checks already prevent duplicate renders.

## Evidence

- **buggy code on main:** extensions/markdown-language-features/src/preview/preview.ts line 167: `if (!vscode.workspace.textDocuments.some(doc => areUrisEqual(doc.uri, uri)))` silently drops the file-system event when the document is open, but `onDidChangeTextDocument` may never fire for external overwrites.
- **open fix PR:** https://github.com/microsoft/vscode/pull/316756 removes the guard; the existing 300ms debounce timer and PreviewDocumentVersion check prevent duplicate refreshes.
- **partial prior fix:** https://github.com/microsoft/vscode/pull/300629 (merged) fixed the Windows drive-letter casing variant but did not address the open-document guard, which is the root cause on all platforms.
- **multiple confirmations:** Reports from Windows, Ubuntu, macOS/remote-SSH, and codespaces across versions 1.102–1.129, with 16 upvotes. Comment #17 by wh0 also identifies a secondary stale-HTML issue on tab switch.
