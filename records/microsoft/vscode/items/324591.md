# Issue #324591 — Agents - chat progress animation is choppy

[https://github.com/microsoft/vscode/issues/324591](https://github.com/microsoft/vscode/issues/324591)

## Summary

The choppy animation remains explainable on current main: chat-input layout changes deliberately restart the active progress-border animation, which can visibly jump multiple times during one turn. This team-authored report has no issue-linked fix and should remain open.

## Change summary

Keep the Agents chat progress-border animation moving smoothly instead of restarting and jumping during an active turn.

## Best solution

Preserve the progress border's visual phase when chat-input layout changes alter its duration, while retaining width-adjusted timing, reduced-motion behavior, and the existing `chat.progressBorder.enabled` setting.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`
- **Validation:** In the Agents window, start a turn with the progress border enabled, trigger repeated chat-input width/layout changes while the turn remains active, and verify with a screen recording or browser animation inspection that the border advances continuously without returning to its starting angle; also confirm reduced motion and `chat.progressBorder.enabled: false` still suppress it.
- **Behavior:**

  > While an Agents chat turn is active, the animated border around the chat input should travel continuously without visibly jumping back to its starting position when the input is laid out again. Width changes may adjust its speed, but must not reset its visual phase. Reduced-motion mode and disabling `chat.progressBorder.enabled` must continue to suppress the animation.
- **Trace:**

  > The active state is applied by `ChatWidget.updateInputBorderProgress` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts. During layout, `ChatInputPart._updateWorkingProgressAnimationDuration` in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts recalculates `--chat-input-anim-duration`; when `.working` is present, it briefly applies `chat-input-anim-restart`, explicitly restarting the CSS animation. The animation and custom angle are defined in src/vs/workbench/contrib/chat/browser/widget/media/chat.css. Keep the boundary to animation continuity during layout: do not remove width-based timing, alter request-in-progress semantics, or weaken reduced-motion behavior.

## Evidence

- **reported reproduction:** The maintainer reported the animation jumping multiple times during a turn while testing the multi-chat scenario from https://github.com/microsoft/vscode/issues/324361 and attached visual evidence.
- **current source path:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts:5190-5228 recalculates `--chat-input-anim-duration` during layout and, whenever the input is `.working`, deliberately adds and removes `chat-input-anim-restart` to restart the animation. Repeated meaningful width changes during a turn therefore reset its phase.
