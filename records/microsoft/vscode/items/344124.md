# Issue #344124 — Agents window: Akusto #kusto tool in a background session opens Kusto Explorer in the focused session

[https://github.com/microsoft/vscode/issues/344124](https://github.com/microsoft/vscode/issues/344124)

## Summary

Keep open: the current webview-opening path has no originating-session identity, so a background tool's ViewColumn.Active request targets the focused session's editor area. The platform gap remains; choosing session-targeted opens versus extension-visible focus information needs a maintainer decision.

## Change summary

Prevent a background session's extension tool from opening its results editor in the focused session's tabs.

## Best solution

Establish a supported platform contract that lets extension tools avoid placing background-session UI in another session's editor working set, without switching the focused session. Suppressing Akusto's automatic editor fallback is a useful mitigation, but does not address the general extension API gap.
