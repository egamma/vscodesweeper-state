- **Current source and remaining failure:** src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-rc.zsh sources the user's .zshrc at line 31, then directly expands "$VSCODE_SHELL_INTEGRATION" at line 99, exactly matching this report's error location. That read is unsafe under nounset if the variable has been unset; the preceding comment explicitly supports shells disabling integration by unsetting it. The Python activation guard now uses a default expansion, but this later read does not. Source was inspected without executing a reproduction.
- **Evidence to retain:** https://github.com/microsoft/vscode/issues/340269 reports the failure with extensions disabled on VS Code 1.139.1, Linux x64 6.18.55-1-cachyos-lts, specifically '/tmp/user-code-zsh/.zshrc:99: VSCODE_SHELL_INTEGRATION: parameter not set'. This adds a newer affected build and another unsafe expansion to the canonical's existing nounset-compatibility work.
