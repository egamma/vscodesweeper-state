# Issue #345985 — remote.defaultExtensionsIfInstalledLocally zips and uploads local extensions instead of installing from the Marketplace (gallery manifest not yet available at window restore)

[https://github.com/microsoft/vscode/issues/345985](https://github.com/microsoft/vscode/issues/345985)

## Summary

The startup race remains in current source: pending gallery initialization can send automatic remote installs through local ZIP uploads. Keep this open while the linked fixing PR is reviewed and landed.

## Change summary

Automatic remote extension installation uploads local packages when the Marketplace manifest is still initializing, unnecessarily slowing remote setup.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/346030 after resolving its review findings, ensuring pending manifest initialization does not trigger local-package fallback while preserving legitimate fallback behavior.

## Evidence

- **Startup trigger:** src/vs/workbench/contrib/extensions/electron-browser/extensions.contribution.ts:75 registers InstallRemoteExtensionsContribution at LifecyclePhase.Restored. remoteExtensionsInit.ts immediately starts installExtensionsIfInstalledLocallyInRemote, queries installed extensions, and calls installInServer without awaiting gallery manifest readiness.
- **Confirmed fallback path:** src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts:1481-1484 returns an empty result when galleryService.isEnabled() is false. installInServer at lines 2770-2800 treats that result as absence of gallery metadata and proceeds to zip(local) and server.extensionManagementService.install(vsix).
- **Manifest initialization race:** src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryManifestService.ts initializes currentStatus to Unavailable and starts asynchronous manifest initialization in its constructor. src/vs/platform/extensionManagement/common/extensionGalleryService.ts:696-697 reports enabled only for Available. Thus installation reaching the workbench lookup before initialization completes takes the upload path even for Marketplace extensions.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/346030 is an open fix linked in the supplied timeline. Its public review describes manifest-readiness changes and pending-manifest/fallback tests, with outstanding findings concerning gallery association and update notifications. An open implementation candidate is not a completed fix.
- **Scope and verification:** The implicated behavior belongs to core workbench extension management, not a third-party extension or the Remote Development extension tracker.
