# Issue #329464 — Hybrid Markdown editor: newlines that exit a list are not rendered — drawn as inline ↵ markers until the next keystroke

[https://github.com/microsoft/vscode/issues/329464](https://github.com/microsoft/vscode/issues/329464)

## Summary

Real rendering-staleness bug in the experimental Hybrid Markdown editor: the block view doesn't reflow after a newline exits a list, showing stray inline ↵ markers until the next keystroke. The reporter confirmed it reproduces on the latest stable (1.132.0), but the actual editor/reflow logic lives in the closed-source `@vscode/markdown-editor` npm package, not vendored in this checkout, so I can't trace or fix the exact code path here.

## Change summary

In the Hybrid Markdown editor's Editing mode, pressing Enter to exit a list at end-of-document inserts correct newlines into the model but the rendered view fails to reflow, drawing them as inline ↵ glyphs on the last list item until further typing forces a re-render.

## Best solution

Route to the markdown-editor area owners: the fix likely belongs in the `@vscode/markdown-editor` package's block/paragraph rendering logic consumed by extensions/markdown-language-features/markdown-editor-src/editor.ts — the view needs to force a reflow/re-render immediately after a newline-only edit produces a new empty block, not wait for the next keystroke.
