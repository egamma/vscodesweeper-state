# Issue #218530 — Change Explorer Default sort to `unicode`

[https://github.com/microsoft/vscode/issues/218530](https://github.com/microsoft/vscode/issues/218530)

## Summary

The requested default has not changed on current main, and this team-authored, under-discussion issue records an unresolved product decision about Explorer sorting. Related older issues discuss platform alignment, hashes, or extensible sorting rather than the same default-change request, so none clears the stronger re-review duplicate bar.

## Change summary

Make Unicode lexicographic ordering the default for file and folder names in the Explorer.

## Best solution

Choose an explicit Explorer default after evaluating the user-visible tradeoff between locale-aware natural sorting and raw Unicode ordering, including whether the change applies to all users without an explicit setting or only new profiles. If Unicode becomes the default, retain the existing locale-aware option and cover the default behavior with an Explorer sorting test.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/files.contribution.ts`, `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts`, `src/vs/base/common/comparers.ts`, `src/vs/base/test/browser/comparers.test.ts`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`
- **Validation:** Add an Explorer sorting test that loads the registered default configuration without a user override and asserts the agreed ordering for numeric names, mixed case, and the `bmp3xx.py`/`bmp280.py` example; run the targeted files contribution and comparer unit tests.
- **Behavior:**

  > Explorer entries without an explicit `explorer.sortOrderLexicographicOptions` override must use the sorting contract selected by the maintainer. The contract must define numeric-name and mixed-case behavior, including the reported `bmp280.py` versus `bmp3xx.py` case. Explicit `default`, `upper`, `lower`, and `unicode` selections must remain deterministic and preserve their documented behavior. Acceptance requires targeted tests for both the chosen default and explicit overrides.
- **Trace:**

  > The configuration default is registered in src/vs/workbench/contrib/files/browser/files.contribution.ts as `LexicographicOptions.Default`. ExplorerService carries that value into `FileSorter`, whose comparison switch in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts selects `compareFileNamesDefault` or `compareFileNamesUnicode` from src/vs/base/common/comparers.ts. The former uses locale-aware numeric collation; the latter uses raw Unicode string comparison, with their differing outcomes documented in src/vs/base/test/browser/comparers.test.ts. The referenced report is https://github.com/microsoft/vscode/issues/218423. Keep the scope to Explorer sorting defaults and compatibility; do not change unrelated consumers of the shared comparer functions.
- **Open decisions:**
  - Should raw Unicode ordering replace locale-aware numeric ordering as the Explorer default despite changing numeric and mixed-case ordering for all users without an explicit override?
  - If the default changes, should existing profiles without an explicit setting adopt it immediately, or should the new default apply only to new profiles while existing users retain the previous behavior?

## Evidence
