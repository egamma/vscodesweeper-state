# Issue #339662 — Flaky Test: snapshot persists across a database restart

[https://github.com/microsoft/vscode/issues/339662](https://github.com/microsoft/vscode/issues/339662)

## Summary

A genuine, team-filed flaky unit test (two independent CI failures cited) in the new SessionDatabase catalog-sync-snapshot test suite; team-authored and carrying `important`, so this stays open regardless — no fix is cited yet and the exact race hasn't been pinned down from source alone.

## Change summary

`SessionDatabase > catalog sync snapshot > snapshot persists across a database restart` intermittently fails in CI (1/20 in one run, and again in a second build), suggesting a race around closing and reopening the on-disk SQLite file.

## Best solution

Diagnose the close()/reopen race in src/vs/platform/agentHost/node/sessionDatabase.ts — close() awaits only `_dbPromise?.then(db => dbClose(db))` and does not wait on `_pendingWrites`/the write sequencers before closing, which is suspicious even though in this specific test the write is already awaited before close() is called; also worth checking whether the second `SessionDatabase.open()` can race the first connection's file handle release on CI disks.
