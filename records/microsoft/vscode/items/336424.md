# Issue #336424 — Codex Agent Host Auto-Review approves sandbox escalation but still runs the command inside the sandbox on macOS

[https://github.com/microsoft/vscode/issues/336424](https://github.com/microsoft/vscode/issues/336424)

## Summary

Traced the VS Code side of this: CodexAgent's guardian-approval handler (`_handleGuardianReviewCompleted` in src/vs/platform/agentHost/node/codex/codexAgent.ts) does nothing but forward the user's approval to the bundled Codex app-server via `thread/approveGuardianDeniedAction` — whether the retried command actually runs outside the sandbox is entirely up to that app-server/SDK (bundled 0.153.0). If the sandbox override is dropped, the defect most likely lives in the Codex CLI/app-server itself, not in this repo's TypeScript, so I'm keeping this open as upstream rather than closing it.

## Change summary

On macOS, approving a Codex 'require_escalated' sandbox retry under the Auto-Review preset still runs the command inside the managed sandbox instead of unsandboxed.

## Best solution

Confirm with a repro against the exact bundled app-server version whether `thread/approveGuardianDeniedAction` is actually re-issuing the command with the escalated sandbox profile; if the app-server itself ignores the override, this needs a fix/report upstream in the Codex CLI (the reporter already opened https://github.com/openai/codex/issues/36391), and VS Code would only need an SDK bump once that lands. If instead VS Code's own guardian-approval plumbing is dropping the escalation, the fix belongs in `_handleGuardianReviewCompleted` / `codexGuardianReview.ts`.
