# Issue #325938 — Linux: Window WM_CLASS is "code" while code.desktop StartupWMClass is "Code", causing taskbar icon mismatch on Cinnamon

[https://github.com/microsoft/vscode/issues/325938](https://github.com/microsoft/vscode/issues/325938)

## Summary

Real, source-traceable Linux packaging defect: the shipped .desktop template sets StartupWMClass to the mixed-case product name while Electron/Chromium derives the actual runtime WM_CLASS from the lowercase binary name, so strict window managers like Cinnamon/Muffin fail to match the launcher to the running window.

## Change summary

On Linux, the running VS Code window's WM_CLASS ("code") doesn't match the .desktop file's StartupWMClass ("Code"), so Cinnamon shows a duplicate/generic taskbar entry instead of grouping under the pinned launcher.

## Best solution

Fix resources/linux/code.desktop (and the corresponding replace() call in build/gulpfile.vscode.linux.ts) so StartupWMClass matches the actual case Chromium assigns to WM_CLASS (generally the lowercase applicationName), or explicitly force the window's WM_CLASS via an Electron API/--class flag to match the desktop entry; this needs cross-DE testing (GNOME, KDE, Cinnamon, Sway) before merging since other WMs may already tolerate the mismatch.
