## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/325938 reports that launching the official APT installation on Linux Mint Cinnamon X11 produces WM_CLASS="code", "code" while the launcher specifies StartupWMClass=Code, yielding a separate generic-icon taskbar entry.
- **Concrete behavioral fix:** https://github.com/microsoft/vscode/commit/4ae4d96052c5a986fe84974ed9d7b220234670b4 contains implementation changes, not merely an Electron bump: resources/linux/code.desktop line 9 replaces StartupWMClass=@@NAME_SHORT@@ with StartupWMClass=@@DESKTOP_NAME@@; prepareDebPackage in build/gulpfile.vscode.linux.ts installs the desktop file under product.linuxDesktopName and substitutes that same value into StartupWMClass.
- **Runtime adoption:** The same commit adds the Linux startup block in src/main.ts, currently lines 70–77. For an installed DEB desktop file, it calls app.setDesktopName(`${product.linuxDesktopName}.desktop`) before window creation. Thus the new identity is actively adopted on the reporter's installation path rather than merely available through a dependency update.
- **Electron identity propagation:** In the adopted Electron 43.6.0 runtime, https://github.com/electron/electron/blob/v43.6.0/shell/browser/api/electron_api_app.cc#L974-L978 sets CHROME_DESKTOP through App::SetDesktopName; https://github.com/electron/electron/blob/v43.6.0/shell/common/platform_util_linux.cc#L467-L480 removes the .desktop suffix for GetXdgAppId; https://github.com/electron/electron/blob/v43.6.0/shell/browser/native_window_views.cc#L318-L330 assigns that identity to wm_class_class. This matches the packaged StartupWMClass exactly.
