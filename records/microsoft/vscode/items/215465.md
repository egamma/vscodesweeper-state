# Issue #215465 — Give an option to not autoclose after word character other than "|' characters

[https://github.com/microsoft/vscode/issues/215465](https://github.com/microsoft/vscode/issues/215465)

## Summary

The requested control is still missing: current source restricts preceding-word suppression to single and double quotes, excluding backticks. This accepted, 20-upvote request should remain open; the older pair-customization issue does not describe the same observable behavior required for a re-reviewed duplicate close.

## Change summary

Allow configuring which opening characters suppress automatic closing when typed immediately after a word character.

## Best solution

Provide an opt-in way to extend preceding-word suppression to characters such as Scala backticks, preserving existing defaults and intentional JavaScript tagged-template behavior. Decide whether the control belongs in user settings, language configuration, or both before implementation.

Run the targeted cursor suite through scripts/test.sh --run src/vs/editor/test/browser/controller/cursor.test.ts, retaining the existing tagged-template and single/double-quote tests.
- **Behavior:**

  > Users should be able to select additional opening characters whose closing partner is not automatically inserted immediately after a word character. Scala backticks are the concrete example; suppression should not disable eligible autoclosing in other contexts. Without opting in, current single/double-quote behavior and backtick autoclosing must remain unchanged. Acceptance checks should distinguish preceding-word suppression from globally disabling a pair.
- **Trace:**

  > AutoClosingOpenCharTypeOperation in src/vs/editor/common/cursor/cursorTypeEditOperations.ts implements the preceding-word check with a literal single/double-quote condition and the configured word-separator map. isQuote in src/vs/editor/common/cursorCommon.ts includes backticks, but that broader classification does not govern this restriction. Existing editor auto-closing strategies in editorOptions.ts cannot select characters for the restriction, and languageConfiguration.ts's autoCloseBefore concerns following characters. The cursor test for issue 61070 deliberately requires backtick autoclosing after a word, so changing the default globally is outside the requested boundary. https://github.com/microsoft/vscode/issues/38352 is related pair-configuration work, not a verified duplicate. The unresolved boundary is the public control's ownership and its interaction with the existing 'always' strategy; no code was executed.
- **Open decisions:**
  - Should additional preceding-word suppression characters be configurable by users, contributed by language configurations, or supported through both contracts?
  - Should explicitly configured preceding-word suppression remain bypassed by the existing 'always' autoclosing strategy, as the current single/double-quote restriction is?

## Evidence

- **Current hardcoded restriction:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts:293–303 applies preceding-word suppression only when pair.open.length === 1, the typed character is a single or double quote, and autoCloseConfig is not 'always'. Backticks are excluded even though isQuote in src/vs/editor/common/cursorCommon.ts:433–435 includes them.
- **Existing settings do not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.autoClosingQuotes and editor.autoClosingBrackets with always, languageDefined, beforeWhitespace, and never strategies. None selects characters for preceding-word suppression; disabling quote autoclosing altogether also removes desired autoclosing elsewhere. LanguageConfiguration.autoCloseBefore in src/vs/editor/common/languages/languageConfiguration.ts:85–91 controls characters after the cursor, not the preceding-word condition.
