# Issue #232113 — Allow relative paths in `typescript.tsserver.nodePath`

[https://github.com/microsoft/vscode/issues/232113](https://github.com/microsoft/vscode/issues/232113)

## Summary

Valid feature request with 28 upvotes, promoted to Backlog. The inconsistency between `typescript.tsserver.nodePath` and `typescript.tsdk` in handling simple relative paths (without workspace-folder-name prefix) remains unfixed on current main.

## Change summary

Allow `typescript.tsserver.nodePath` to accept simple relative paths (e.g. `./my-node-script.sh`) resolved against the workspace root, matching the behavior of `typescript.tsdk`.

## Best solution

Update `RelativeWorkspacePathResolver.asAbsoluteWorkspacePath` (or the `readLocalNodePathWorker` call site in `configuration.electron.ts`) to fall back to resolving the path against each workspace folder root when the workspace-name prefix is absent — mirroring how `loadVersionsFromSetting` in `versionProvider.electron.ts` handles tsdk paths. The closed PR https://github.com/microsoft/vscode/pull/232115 attempted this but was not merged; a fresh implementation is needed.

## Evidence

- **code trace:** In `extensions/typescript-language-features/src/configuration/configuration.electron.ts` lines 63–66, `readLocalNodePathWorker` calls `RelativeWorkspacePathResolver.asAbsoluteWorkspacePath(fixedPath)` for non-absolute paths and returns null when it fails — no fallback to workspace-root resolution.
- **root cause:** `RelativeWorkspacePathResolver.asAbsoluteWorkspacePath` in `extensions/typescript-language-features/src/utils/relativePathResolver.ts` only matches paths prefixed with the workspace folder name (e.g. `./myFolder/script.sh`), rejecting simple relative paths like `./script.sh`.
- **inconsistency with tsdk:** The tsdk setting in `versionProvider.electron.ts` line 122 falls back to `loadTypeScriptVersionsFromPath` when `asAbsoluteWorkspacePath` returns undefined, giving it broader relative-path support that `nodePath` lacks.
