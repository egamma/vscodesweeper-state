# Issue #324402 — Copilot Chat loses custom agents and MCP servers after first prompt (workspace becomes `unknown:/`)

[https://github.com/microsoft/vscode/issues/324402](https://github.com/microsoft/vscode/issues/324402)

## Summary

Thanks for the detailed logs — this looks like a real bug in the agent-host/agents-window session workspace resolution, where the session's workspace URI falls back to an `unknown:` scheme after the first prompt, breaking custom-agent and MCP-server file resolution; already correctly labeled `agents-window`, so keeping open for the owning team to trace the exact trigger rather than closing.

## Change summary

After sending the first prompt in a chat with a custom agent selected, the session's workspace resolves to an unsupported `unknown:/` scheme, causing custom agents and MCP servers to disappear from the session.

## Best solution

Route to the agent-host/sessions team to trace why the session workspace URI degrades to the `unknown:` scheme placeholder after the first turn (see the fallback pattern in `copilotChatSessionsProvider.ts` and the acknowledged-limitation comment in `sessionsService.ts`) and ensure workspace-derived MCP/agent resolution keeps the real folder URI once a session is active.
