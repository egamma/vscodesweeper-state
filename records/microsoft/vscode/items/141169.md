# Issue #141169 — Trimming final newline is not POSIX standards compliant

[https://github.com/microsoft/vscode/issues/141169](https://github.com/microsoft/vscode/issues/141169)

## Summary

Valid, well-discussed request to change the default of `files.insertFinalNewline` for POSIX compliance. An open PR (https://github.com/microsoft/vscode/pull/175597) exists to address at least the Linux case, and the issue has 37 upvotes with substantive team engagement — keeping open as it awaits a decision on the open PR.

## Change summary

Change the default of `files.insertFinalNewline` to `true` on Linux (and possibly macOS) so files are saved with a final newline per POSIX standards.

## Best solution

Land or close PR https://github.com/microsoft/vscode/pull/175597 to decide the Linux default, and consider whether macOS should follow. The `editor.renderFinalNewline` was already changed to `dimmed` on Linux; the remaining decision is whether `files.insertFinalNewline` should default to `true` on POSIX platforms. Comment 14 raises a nuanced point about LF-as-terminator vs CRLF-as-separator that may inform a platform-conditional default.
