# Issue #297895 — Show progress indication for downloading update if it's taking a long time?

[https://github.com/microsoft/vscode/issues/297895](https://github.com/microsoft/vscode/issues/297895)

## Summary

Keep open: current macOS updates still provide no measurable download progress or remaining-time estimate. The newer update UI offers an indefinite indicator, but does not resolve the reporter's uncertainty during slow downloads; this team-authored request remains valid.

## Change summary

Provide meaningful progress feedback during long macOS update downloads, optionally including an approximate remaining time.

## Best solution

Expose measurable macOS update-download progress through the updater and reuse the existing update indicator and tooltip for percentage and, when reliable, remaining-time feedback. Establish the Electron-side capability first rather than treating an indefinite animation or hiding the indicator as completion.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `src/vs/platform/update/common/update.ts`, `src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts`, `src/vs/workbench/contrib/update/browser/updateTooltip.ts`, `src/vs/workbench/contrib/update/common/updateUtils.ts`
- **Validation:** Plan acceptance should include a throttled macOS update download lasting more than one minute: feedback should convey measurable advancement rather than only an indefinite wait message. Verify percentage and remaining-time presentation with known measurements, graceful fallback when measurements are unavailable, and unchanged completion/restart behavior; existing updateUtils and updateTitleBarEntry tests provide partial validation surfaces.
- **Behavior:**

  > A slow macOS update download currently looks indefinitely busy, leaving the user unable to distinguish advancement from a stalled operation. The desired outcome is useful progress feedback during long downloads without adding an intrusive always-on surface. An approximate remaining time is desirable when the available measurements support it, but must not imply certainty when they do not. Acceptance should exercise a download lasting more than one minute and preserve existing update completion and restart behavior.
- **Trace:**

  > DarwinUpdateService in src/vs/platform/update/electron-main/updateService.darwin.ts delegates downloads to electron.autoUpdater and publishes Downloading without byte counts or start time. The shared Downloading contract already accepts those fields, and UpdateTitleBarEntry and UpdateTooltip already consume them for percentage, speed and remaining-time presentation. Windows obtains measurements from its own download stream; that is not the macOS download path. Source inspection establishes the missing measurements, but does not establish whether the bundled Electron macOS updater can expose them or what upstream work is required. Preserve the existing updater's installation and restart semantics, and avoid fabricating measurable progress from elapsed time alone. The maintainer's Electron-work assessment is recorded at https://github.com/microsoft/vscode/issues/297895; https://github.com/microsoft/vscode/issues/279144 concerns a distinct Windows installation-launch scenario.
