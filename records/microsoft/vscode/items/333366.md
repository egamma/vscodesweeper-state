# Issue #333366 — macOS system Pinyin English candidate moves the caret and corrupts adjacent text

[https://github.com/microsoft/vscode/issues/333366](https://github.com/microsoft/vscode/issues/333366)

## Summary

Real, well-diagnosed bug with a candidate fix already in flight: the reporter opened PR #333365 ("Fixes #333366") the same day, with a root-cause writeup involving native EditContext/Chromium composition state and stale cached text. Keep open pending review/merge of that PR rather than closing.

## Change summary

With macOS system Pinyin input, the temporary caret move shown while an English candidate is pending gets committed to the editor model, corrupting adjacent text on candidate selection (e.g. `1234` + typing `review` produces `revieww234` instead of `review1234`).

## Best solution

Land (after review) the fix in open PR https://github.com/microsoft/vscode/pull/333365, which reportedly keeps the native EditContext in sync before model content listeners run and ignores composition-only selection updates beyond the unchanged replacement text; includes new tests in src/vs/editor/test/browser/controller/nativeEditContextUtils.test.ts.
