# Issue #334165 — Markdown Editor: Ability to copy comments in Agent window

[https://github.com/microsoft/vscode/issues/334165](https://github.com/microsoft/vscode/issues/334165)

## Summary

A real gap remains: current main lets users inspect or reveal submitted feedback comments, but provides no way to copy the comment bundle for recovery or reuse in another session. The issue already has the correct Agents Window routing and should remain open for a focused UX decision.

## Change summary

Allow users to copy comments attached to a submitted Agents Window request so they can reuse the feedback in another session or model.

## Best solution

Expose an accessible copy action from the feedback attachment context view that preserves the complete comment text and useful file/range context, ideally supporting the whole submitted bundle for transfer to a new session.

- **Evidence:** Durable themes: AI-assisted development and Workbench & core UX; the accessibility theme also supports a keyboard-operable alternative to the current hover-oriented presentation.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackContextView.ts`, `src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackAttachmentEntry.ts`, `src/vs/sessions/contrib/agentFeedback/test/browser/agentFeedbackAttachment.test.ts`, `src/vs/sessions/contrib/chat/browser/sessionsChatAccessibilityHelp.ts`
- **Validation:** Add a focused attachment/context-view test that activates the chosen copy action and asserts the clipboard text contains every expected comment with its file/range context and replies; also verify the action is keyboard reachable.
- **Behavior:**

  > Users can recover and reuse feedback comments after submitting them to an agent. From the submitted feedback attachment, a keyboard-accessible action copies the agreed comment scope with enough file/range context to remain meaningful when pasted into a new session. Copying must not remove comments, navigate away from the session, or alter existing attachment activation behavior.
- **Trace:**

  > AgentFeedbackAttachmentWidget in src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackAttachmentWidget.ts opens AgentFeedbackContextView for bundles containing multiple comments. AgentFeedbackContextView renders file and comment rows, but read-only comment rows have only a hover and navigation behavior; there is no clipboard path. The attachment already carries text, resource/range, selection, diff hunks, and replies, while src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackAttachmentEntry.ts contains textual formatting helpers. Preserve existing reveal, removal, Escape/focus restoration, and attachment submission behavior; the uncertainty starts at the user-visible copy scope and format.
- **Open decisions:**
  - Should the primary action copy the entire submitted comment bundle, only the focused comment, or expose both choices?
  - Should copied text use the concise new-session prompt format or the richer agent-facing format that includes selections and diff hunks?

## Evidence

- **current source:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackContextView.ts renders submitted comments as WorkbenchObjectTree rows. Read-only rows expose a rich hover and open the original feedback when activated, but neither the row nor its action bar provides a copy action.
- **stored representation:** src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackAttachmentEntry.ts already retains each comment's text, resource, range, selection, diff hunks, and replies, and provides buildAgentFeedbackValue/buildNewSessionPrompt formatting helpers; the data needed for a recoverable clipboard representation exists on current main.
