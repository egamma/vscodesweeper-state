# Issue #275985 — File > Open Folder > "Hide dot files" doesn't hide hidden folders in Windows

[https://github.com/microsoft/vscode/issues/275985](https://github.com/microsoft/vscode/issues/275985)

## Summary

Keep open as an accepted Backlog feature request. Current main still filters only dot-prefixed names, while Windows hidden and protected-system entries require filesystem metadata that the current file-stat contract does not expose.

## Change summary

Make the simple file dialog's hidden-files toggle hide Windows entries marked with the Hidden or protected-system attributes, not only dot-prefixed names.

## Best solution

Give the simple file dialog a platform-aware hidden-entry signal so its eye toggle hides dotfiles on Unix-like filesystems and Windows Hidden/protected-system entries on Windows, including remote Windows providers, while preserving the ability to reveal them.

## Plan brief

- **Likely files:** `src/vs/platform/files/common/files.ts`, `src/vs/platform/files/common/fileService.ts`, `src/vs/platform/files/node/diskFileSystemProvider.ts`, `src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts`, `src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts`
- **Validation:** Add a Windows-capable filesystem-provider test using entries with Hidden and protected-system attributes, plus a SimpleFileDialog test verifying the toggle excludes those entries and dotfiles when hidden while revealing all of them when enabled; run the targeted files and simple-dialog unit suites.
- **Behavior:**

  > In the simple Open File, Open Folder, and Save As dialogs, turning off hidden-file visibility must hide entries considered hidden by the target operating system. On Windows this includes files and directories carrying Hidden or protected-system attributes, even when their names do not start with a dot; turning visibility back on reveals them. Existing dotfile behavior and per-workspace toggle persistence must remain intact, including when the target filesystem belongs to a remote Windows environment.
- **Trace:**

  > SimpleFileDialog.createItems in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts currently filters only `child.name.startsWith('.')`. The children come from IFileService.resolve, whose IFileStat contract in src/vs/platform/files/common/files.ts has no hidden/system field; FileService.toFileStat in src/vs/platform/files/common/fileService.ts therefore cannot propagate such metadata. DiskFileSystemProvider.stat/readdir in src/vs/platform/files/node/diskFileSystemProvider.ts exposes type and POSIX-style permissions but not Windows attributes. The feature originated in https://github.com/microsoft/vscode/issues/136307, while the maintainer accepted OS-hidden-file support specifically at https://github.com/microsoft/vscode/issues/275985#issuecomment-3502882404. Preserve provider interoperability and do not change Explorer `files.exclude` behavior or the established per-workspace persistence semantics.

## Evidence

- **maintainer direction:** A maintainer explicitly classified this as a feature request to support OS-hidden files: https://github.com/microsoft/vscode/issues/275985#issuecomment-3502882404. The issue is assigned to the Backlog milestone, so a decline close would contradict accepted triage.
- **current filtering:** src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts:createItems filters children solely with `!child.name.startsWith('.')`; Windows Hidden or System attributes are not considered.
- **metadata gap:** src/vs/platform/files/common/files.ts exposes FileType and FilePermission values for readonly, locked, and executable state, but no hidden/system metadata. src/vs/platform/files/node/diskFileSystemProvider.ts:stat and readdir likewise return type and POSIX-style permissions without Windows hidden attributes.
- **existing capability is partial:** https://github.com/microsoft/vscode/issues/136307 introduced the simple-picker toggle, but current main implements the resulting capability as dot-name filtering only; it does not cover the Windows behavior requested here.
- **canonical search:** The related-item and repository searches found no older open issue reporting the same observable Windows simple-picker symptom. The original toggle request at https://github.com/microsoft/vscode/issues/136307 is closed and does not own this remaining platform-specific work.
