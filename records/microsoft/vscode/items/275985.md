# Issue #275985 — File > Open Folder > "Hide dot files" doesn't hide hidden folders in Windows

[https://github.com/microsoft/vscode/issues/275985](https://github.com/microsoft/vscode/issues/275985)

## Summary

Keep open: the simple file picker still filters dot-prefixed names only, and a maintainer explicitly accepted Windows hidden-attribute support as a feature request. The existing controls do not cover that request, and no verified canonical was found.

## Change summary

Allow the simple file picker to hide Windows hidden files and folders, including the protected entries identified in the report.

## Best solution

Extend the simple file picker's visibility behavior to account for Windows filesystem attributes while preserving access to hidden entries. Establish the treatment of protected system entries and the relationship to dotfile filtering before implementation; global toggle persistence is separate and was already clarified as per-workspace behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts`, `src/vs/platform/files/common/files.ts`, `src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts`
- **Validation:** On Windows, enable files.simpleDialog.enable and open a directory containing an ordinary folder, a dot-prefixed folder, a non-dot folder marked Hidden, and an entry marked Hidden+System. Verify the agreed filtering policy in File: Open Folder, verify that showing hidden entries restores access, and confirm existing dotfile filtering and per-workspace persistence remain unchanged.
- **Behavior:**

  > The simple file picker currently hides dot-prefixed names but leaves Windows-hidden folders visible. The requested outcome is a visibility control that also accounts for Windows-hidden entries, including the protected entries described in the report, while retaining a way to reveal and select them. Acceptance should cover ordinary, dot-prefixed, Hidden, and Hidden+System entries on Windows. The separate request for global persistence is outside this change: the maintainer confirmed that persistence is per workspace.
- **Trace:**

  > SimpleFileDialog.createItems in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts resolves directory children through IFileService and filters only child.name.startsWith('.'); setButtons explicitly describes dotfile visibility. The IStat and IFileStat contracts in src/vs/platform/files/common/files.ts contain no Hidden or System metadata, so the trace establishes the missing capability but not an end-to-end attribute acquisition path. FileDialogService.shouldUseSimplified in src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts distinguishes native and simple pickers; switching to native does not address remote or other simple-picker uses. Preserve existing non-Windows behavior, file selection, and per-workspace persistence. The maintainer accepted OS-hidden support at https://github.com/microsoft/vscode/issues/275985#issuecomment-3502882404; https://github.com/microsoft/vscode/issues/241705 covers the existing dotfile toggle rather than Windows attributes.
- **Open decisions:**
  - Should the existing toggle hide both dot-prefixed names and Windows Hidden entries, or should Windows attribute visibility be independently controllable?
  - Should Hidden+System entries follow the ordinary hidden-entry toggle, or remain hidden under a separate protected-system-entry policy?

## Evidence

- **maintainer direction:** https://github.com/microsoft/vscode/issues/275985#issuecomment-3502882404 explicitly classifies OS-hidden-file support as a feature request and explains that toggle persistence is per workspace, not global. This accepted direction and the Backlog milestone rule out a decline close.
- **current implementation:** src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts: SimpleFileDialog.setButtons labels the control "Hide dot files"; createItems filters children solely with !child.name.startsWith('.'). Windows Hidden or System attributes do not participate in that filtering.
- **existing-capability check:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers files.simpleDialog.enable, default false, to choose the simple picker. src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts: shouldUseSimplified selects between native and simple dialogs; using the native picker for local files is an alternative, not OS-hidden filtering within the simple picker.
- **metadata boundary:** src/vs/platform/files/common/files.ts: IStat, IBaseFileStat, and IFileStat expose file type, timestamps, permissions, and symbolic-link information, but no Windows Hidden or System attributes. The picker currently receives no such metadata through its IFileStat children, so this requires investigation beyond a name-filter adjustment.
- **earlier dotfile work:** https://github.com/microsoft/vscode/issues/136307 is closed and concerns the implemented dotfile toggle. https://github.com/microsoft/vscode/issues/241705 tests that toggle and its remembered state; neither establishes implementation of Windows attribute filtering.
- **canonical search:** Read-only searches for hidden files in dialogs and Windows hidden attributes found no verified older canonical for this symptom. https://github.com/microsoft/vscode/issues/306900 is open but newer and requests marking .vscode/.copilot directories hidden or relocating them, not filtering OS-hidden entries in the simple picker; it is not a duplicate target.
