# Issue #330395 — Keyword `$this` not correctly highlighted in interpolated php strings

[https://github.com/microsoft/vscode/issues/330395](https://github.com/microsoft/vscode/issues/330395)

## Summary

Confirmed real inconsistency in the PHP TextMate grammar: bare `$this->name` interpolation is scoped through `#variable-name`, which never applies `variable.language.this.php`, while braced `{$this->name}` re-enters the full grammar via `$self` and does hit `#var_language`. Routing to the PHP area; the grammar file itself notes fixes should go through the upstream source first.

## Change summary

`$this` is highlighted with the special "this" keyword color inside `{$this->name}` interpolation but not inside bare `$this->name` interpolation, in double-quoted/heredoc PHP strings.

## Best solution

The `variable-name` repository rule in extensions/php/syntaxes/php.tmLanguage.json (used by `#interpolation` for bare `$var` interpolation) needs a `this`-specific case so it emits `variable.language.this.php` for `$this`, matching what `#var_language` produces when interpolation re-enters `$self` via `{...}`. Per the file's own header, this should first be proposed against the upstream grammar source (https://github.com/KapitanOczywisty/language-php) and then pulled in via extensions/php/build/update-grammar.mjs, rather than patched directly in this generated file.

- **interpolation dispatch:** `#interpolation` (line ~2573) includes `#variable-name` for bare `$var...` interpolation (line ~2621), but for `{$...}` it begins a `{`/`}` block whose patterns include `$self` (lines 2591-2607), which re-enters the top-level grammar and can hit `#var_language` via `#variables`.
- **variable-name rule:** extensions/php/syntaxes/php.tmLanguage.json:4058-4102 `variable-name`'s main match always scopes capture group 1 as `variable.other.php`, with no special-case for the literal name `this`, so bare-interpolated `$this->name` never gets `variable.language.this.php`.
