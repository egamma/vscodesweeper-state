# Issue #135114 — Add `editor.contentLeftPadding` to add padding between the `editorGutter` and `editor`.

[https://github.com/microsoft/vscode/issues/135114](https://github.com/microsoft/vscode/issues/135114)

## Summary

Keep this accepted, well-supported request open: current editor options do not provide content-side left padding that separates text and guides from the gutter and supports cursor placement. Related issues cover parts of the request, but no verified older canonical owns its full scope.

## Change summary

Provide left padding between the editor gutter and rendered content, with aligned rulers and guides and a clickable area for placing the cursor at line start.

## Best solution

Provide supported content-side spacing through the editor's layout and mouse-targeting model rather than CSS injection or a minimap workaround. A maintainer should first settle whether this is opt-in configuration or a default spacing change.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/controller/mouseTarget.ts`, `src/vs/editor/browser/viewParts/margin/margin.ts`, `src/vs/editor/browser/viewParts/rulers/rulers.ts`, `src/vs/editor/test/browser/config/editorLayoutProvider.test.ts`
- **Validation:** Extend editor layout tests to check the agreed spacing and usable content width. In a running editor, use a contrasting editorGutter.background with folding, rulers, and bracket guides enabled: verify visual separation, ruler/guide alignment, and that clicking or beginning a selection within the added space targets the corresponding line start without folding it. Repeat with horizontal scrolling, wrapped lines, and zero spacing.
- **Behavior:**

  > Users should be able to separate unindented text and guides from the gutter without inserting document whitespace or repurposing the minimap. Clicking the added content-side space should place the cursor at the start of the corresponding line and allow selection without activating folding controls. Rulers and guides must remain aligned with text. Acceptance should cover contrasting gutter colors, folding enabled, wrapped lines, horizontal scrolling, and preservation of existing behavior when spacing is disabled.
- **Trace:**

  > EditorPadding in src/vs/editor/common/config/editorOptions.ts currently supports only top and bottom spacing. EditorLayoutInfoComputer places contentLeft immediately after lineDecorationsWidth; Margin in src/vs/editor/browser/viewParts/margin/margin.ts paints the gutter through that boundary. ResolvedHitTestRequest and MouseTargetFactory._hitTestMargin in src/vs/editor/browser/controller/mouseTarget.ts classify the area before contentLeft as gutter, explaining why decoration width is not equivalent to editable padding. The issue's CSS experiments demonstrate that visual displacement alone does not satisfy hit testing or ruler alignment. Preserve intentional gutter interactions, document contents, minimap functionality, and text/guide coordinate consistency. Related https://github.com/microsoft/vscode/issues/41574 owns line-start targeting, while https://github.com/microsoft/vscode/issues/206914 restates the clickable portion; neither establishes completion of this broader request. The remaining product uncertainty is whether spacing changes defaults and how it behaves during horizontal scrolling.
- **Open decisions:**
  - Should content-side spacing be opt-in with the existing default preserved, or should VS Code add default spacing with an option to disable it?
  - Should the spacing scroll away with the beginning of the rendered line, or remain a fixed blank strip beside the gutter during horizontal scrolling?
