# Issue #293101 — Consider `Shift Tab` to toggle between Plan/Agent modes in chat input

[https://github.com/microsoft/vscode/issues/293101](https://github.com/microsoft/vscode/issues/293101)

## Summary

The current behavior is intentional: Shift+Tab remains available for backward focus navigation, while agent switching is exposed through the Cmd/Ctrl+. picker and a separately bindable command. Maintainers explicitly rejected making Shift+Tab the default because it would impair screen-reader and keyboard-only navigation.

## Change summary

Make Shift+Tab cycle between Plan, Agent, and other chat modes from the chat input.

## Best solution

Preserve Shift+Tab for navigating chat input controls and retain Cmd/Ctrl+. as the default agent picker shortcut. Users who prefer direct cycling can bind Shift+Tab to `workbench.action.chat.toggleAgentMode` themselves.

## Vision fit

- **Fit:** rejected
- **Reason:** Stealing a standard backward-focus key for mode switching conflicts with VS Code's accessibility commitment and preference for uniform keyboard interactions.
- **Evidence:** Durable themes and values: Accessibility, and “Simple, uniform UI and UI interactions.”

## Evidence

- **existing command:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts registers `workbench.action.chat.toggleAgentMode` as “Switch to Next Agent”; it cycles built-in and custom modes and intentionally has no default keybinding.
- **existing default interaction:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts registers Cmd/Ctrl+. for `workbench.action.chat.openModePicker`, matching the maintainer-described picker workflow.
- **keyboard navigation contract:** src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts documents Shift+Tab as navigation between the chat input and file working set, confirming that the chord already serves focus movement.
