# Issue #293101 — Consider `Shift Tab` to toggle between Plan/Agent modes in chat input

[https://github.com/microsoft/vscode/issues/293101](https://github.com/microsoft/vscode/issues/293101)

## Summary

Keep open for an accessibility-aware interaction decision. Current `main` offers the Agent Picker on Ctrl/Cmd+Period and an unbound “Switch to Next Agent” command, but no default direct-cycling shortcut; the thread leaves both the shortcut and cycling behavior unsettled.

## Change summary

Provide a quick keyboard interaction for cycling between Plan, Agent, and other chat agents without first opening the picker.

## Best solution

Choose a discoverable shortcut and cycling model that preserves normal Tab/Shift+Tab navigation through chat controls, then expose it consistently in the chat accessibility help. The existing picker and user-assignable `workbench.action.chat.toggleAgentMode` command should remain available.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/accessibility/chatAccessibilityHelp.test.ts`
- **Validation:** Add targeted action/keybinding coverage for the chosen cycling behavior and accessibility-help coverage for its resolved keybinding; manually verify that Tab and Shift+Tab still traverse every chat-input control with keyboard-only navigation and a screen reader.
- **Behavior:**

  > Chat users should have a fast, discoverable keyboard interaction for changing the active agent without an unnecessary picker step. The interaction must behave predictably when built-in and custom agents coexist and must not make any chat control unreachable through normal keyboard navigation. The Agent Picker and custom keybinding support remain available. Acceptance includes verifying the selected cycling behavior and complete forward and reverse focus traversal around the chat input.
- **Trace:**

  > `ToggleChatModeAction` in `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts` already computes the next built-in or custom agent and is exposed as `workbench.action.chat.toggleAgentMode`, but has no default keybinding. `OpenModePickerAction` in the same file owns Ctrl/Cmd+Period and opens the picker. `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts` documents Tab/Shift+Tab navigation, and several chat-input widgets rely on reverse traversal to reach controls above the input. The implementation boundary is chat mode selection and its accessibility documentation; do not remove picker access, user keybinding customization, or reverse focus traversal. The prior attempt at https://github.com/microsoft/vscode/pull/293121 did not reach `main`.
- **Open decisions:**
  - Should the default interaction directly cycle every available built-in and custom agent, toggle only between Plan and Agent, or continue opening the Agent Picker?
  - Which default keybinding provides the quick interaction without taking Shift+Tab away from reverse focus navigation for keyboard and screen-reader users?
  - When many custom agents are installed, should direct cycling include all of them or only a defined subset of primary agents?

## Evidence

- **current capability:** On current `main`, `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts` registers `workbench.action.chat.toggleAgentMode` as “Switch to Next Agent” and cycles built-in and custom agents, but assigns it no default keybinding.
- **existing picker:** `OpenModePickerAction` in `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts` binds Ctrl/Cmd+Period while the chat input is focused, confirming that current built-in behavior opens the Agent Picker rather than directly cycling.
- **accessibility constraint:** Maintainers explain in https://github.com/microsoft/vscode/issues/293101 that Shift+Tab is required for screen-reader and keyboard-only navigation; current chat accessibility help and widgets also explicitly use Shift+Tab to reach controls above and around the input.
- **unresolved product behavior:** The discussion at https://github.com/microsoft/vscode/issues/293101 does not settle whether a shortcut should toggle Plan/Agent, cycle every available agent, or retain picker-first behavior. A maintainer notes that direct cycling previously changed to the picker after user feedback.
- **closed implementation attempt:** https://github.com/microsoft/vscode/pull/293121 proposed the keybinding but was closed without merging to `main`. Its follow-up https://github.com/microsoft/vscode/pull/293156 merged only into that PR branch, and the proposed Plan action/keybinding is absent from current `main`.
