# Issue #286157 — Default semantic token styles do not honour custom line heights or font sizes from TextMate themes

[https://github.com/microsoft/vscode/issues/286157](https://github.com/microsoft/vscode/issues/286157)

## Summary

Keep open: current source still inherits TextMate colors and font styles for semantic tokens without inheriting font size or line height. The closely matching semantic-font request is newer, and a maintainer explicitly consolidated another report here, so this remains a necessary tracking issue.

## Change summary

Make default semantic-token styling inherit custom TextMate font sizes and line heights consistently with italic and strikethrough styling.

## Best solution

Support font-size and line-height inheritance through the existing semantic-token fallback path while preserving semantic selector precedence and TextMate scope matching. Coordinate that work with https://github.com/microsoft/vscode/issues/287118, retaining this older report's concrete inconsistency as an acceptance case.

- **Validation:** Add focused tests in colorThemeData.test.ts and semanticTokensProviderStyling.test.ts covering mapped class tokens inheriting TextMate font size and line height alongside italic and strikethrough. Manually compare a TypeScript class declaration and references with semantic highlighting enabled: matching semantic fallback tokens should receive consistent metrics, and removing customizations should restore default layout.
- **Behavior:**

  > TextMate customizations for entity.name.type.class currently propagate italic and strikethrough to class occurrences through semantic fallback, but not custom font size or line height. The requested outcome is consistent metric inheritance for occurrences using that fallback. Acceptance should cover class declarations and references, changes and removal of customizations, and preservation of existing color and font-style behavior.
- **Trace:**

  > ColorThemeData.getTokenStyle probes mapped TextMate scopes through resolveScopes, which extracts only foreground and fontStyle. TokenStyleData, ITokenStyle, getTokenStyleMetadata and SemanticTokensProviderStyling.getMetadata also lack font-metric transport, although the TextMate schema and tokenFontMap already support syntactic-token metrics. This establishes the missing capability but not the complete representation and rendering design across the theme/editor boundary. Preserve intentional semantic-to-TextMate scope mapping rather than restricting styling to literal syntactic scopes. https://github.com/microsoft/vscode/issues/287118 requests broader semantic font support; https://github.com/microsoft/vscode/issues/263545 tracks this report as unfinished, and https://github.com/microsoft/vscode/issues/286196 was consolidated here. Planning should establish metric transport and precedence before implementation; direct semantic font customization is adjacent scope, not necessary to establish this report's fallback acceptance case.
