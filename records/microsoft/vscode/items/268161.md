# Issue #268161 — Option to align files with folders and control indentation width in Explorer

[https://github.com/microsoft/vscode/issues/268161](https://github.com/microsoft/vscode/issues/268161)

## Summary

Current VS Code already exposes tree indentation from 4–40 pixels, while file/folder alignment intentionally follows the selected file icon theme. Maintainer decisions covering both parts support closing this as designed rather than adding another Explorer-specific setting.

## Change summary

Add Explorer settings to align same-depth file and folder labels and customize the horizontal indentation between tree levels.

## Best solution

Keep `workbench.tree.indent` as the uniform tree-spacing control and use file icon themes to control the combination of file icons, folder icons, and Explorer arrows; themes can preserve rich file icons while supplying folder icons for aligned labels.

## Vision fit

- **Fit:** rejected
- **Reason:** A separate Explorer-only alignment toggle would add configuration for behavior already covered by the uniform tree setting and extensible icon-theme mechanism.
- **Evidence:** Values and guardrails: “Simple, uniform UI and UI interactions” and “The power lives in extensions.”

## Evidence

- **indentation setting:** Current main registers `workbench.tree.indent` with a 4–40 pixel range in `src/vs/platform/list/browser/listService.ts`; the configured value is passed to tree options and reapplied dynamically when the setting changes.
- **Explorer integration:** `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` observes `workbench.tree.indent` and recalculates the Explorer icon-alignment offset, while `src/vs/workbench/contrib/files/browser/views/explorerView.ts` deliberately varies alignment according to whether the active icon theme supplies file and folder icons.
- **alignment precedent:** In https://github.com/microsoft/vscode/issues/141406#issuecomment-1078514550, a maintainer concluded that file icon themes already have full control over file icons, folder icons, and Explorer arrows, and the request was closed as an extension candidate.
- **indentation precedent:** In https://github.com/microsoft/vscode/issues/305170#issuecomment-4370297890, a maintainer declined changing the indentation default because users can already customize it.
- **related open issue:** https://github.com/microsoft/vscode/issues/148974 remains open for the narrower file-nesting alignment symptom, but it does not own this broader request and therefore is not a valid duplicate canonical under the re-review rules.
