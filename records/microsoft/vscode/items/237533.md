# Issue #237533 — Keybindings different behavior in Windows and macOS with Czech localized keyboard layout

[https://github.com/microsoft/vscode/issues/237533](https://github.com/microsoft/vscode/issues/237533)

## Summary

Valid bug: on macOS with Czech keyboard layout, scan-code-based dispatch cannot resolve `ctrl+[` from extensions because `[` is not directly producible on that layout — the `keyCodeChordToScanCodeChord` lookup returns empty. Windows uses keyCode dispatch and succeeds. No fix on main; the workaround is `keyboard.dispatch: "keyCode"`.

## Change summary

Extension-contributed keybinding `ctrl+[` disappears on macOS with Czech keyboard layout because scan-code dispatch cannot map the keyCode chord back to a scan code when the character isn't directly producible.

## Best solution

The MacLinuxKeyboardMapper's `keyCodeChordToScanCodeChord` should fall back to the physical key position (BracketLeft) when the character `[` has no direct producer on the active layout, similar to how Windows resolves it via the scan code. This likely needs work in `src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts` around the `lookupKeyCodeCombo` path. Issue https://github.com/microsoft/vscode/issues/1240 (supporting layout-aware extension keybindings) is related but broader — this is a narrower bug where a single well-defined keybinding silently disappears.

## Evidence

- **source trace:** In src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts, `resolveKeybinding` calls `keyCodeChordToScanCodeChord` which calls `_scanCodeKeyCodeMapper.lookupKeyCodeCombo`. On Czech macOS layout, KeyCode.BracketLeft (the internal code for `[`) has no scan-code producer because the BracketLeft physical key produces `ú`, not `[`. The lookup returns an empty array, so the keybinding is silently dropped.
- **logs from reporter:** macOS log shows 'Resolving ctrl+[BracketLeft]' → 'No keybinding entries', while Windows log shows 'Resolving ctrl+[' → matched. The difference is dispatch strategy: macOS dispatches by scan code, Windows by keyCode.
- **workaround:** Setting `keyboard.dispatch: "keyCode"` (available only on macOS/Linux per keyboardConfig.ts line 42) forces keyCode-based dispatch and resolves the issue, as the reporter confirmed.
- **related issue:** https://github.com/microsoft/vscode/issues/1240 tracks the broader feature of layout-aware keybinding contributions, but this is a narrower correctness bug where a standard keybinding silently fails.
