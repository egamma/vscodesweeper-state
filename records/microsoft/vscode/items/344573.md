# Issue #344573 — Task terminal disappears from the Agents window after switching sessions; processes keep running

[https://github.com/microsoft/vscode/issues/344573](https://github.com/microsoft/vscode/issues/344573)

## Summary

Keep open: a maintainer reproduced task-terminal migration between same-folder sessions on recent Insiders, independently of WSL or Claude. Current source exposes an ownership gap; running-task visibility still needs diagnosis.

## Change summary

Preserve a running task's terminal, output, and stop controls in its originating Agents session across session switches.

## Best solution

Keep task execution and terminal ownership tied to the originating session rather than its shared working directory. Restore discoverable running-task status and termination without disrupting the process during session switches.

## Evidence

- **Independent reproduction:** At https://github.com/microsoft/vscode/issues/344573, alexdima confirmed on 2026-11-20 using macOS, Copilot CLI, and Insiders 1.147.0 (944d79c5b9): switching A to B moves the ticking task terminal into B; returning to A loses it, and Show Running Tasks reports no task.
- **Session ownership gap:** src/vs/sessions/contrib/terminal/browser/sessionsTerminalContribution.ts: _ensureTerminal falls back to untracked terminals matching cwd/backend when a session has no tracked terminals, then tracks those instances for that session. _terminalMatchesScope explicitly matches externally created task terminals by backend and cwd. Consequently, a newly visited same-folder session can claim an untracked task terminal from another session.
- **Task dispatch boundary:** src/vs/sessions/contrib/terminal/browser/agentHostSessionTaskRunner.ts: runTask creates an Agent Host terminal and sends the resolved command; its reuse key contains host, cwd, and task label, not session identity. Main-panel fallback activates the terminal without explicitly associating it with its originating session, and this runner does not register execution with ITaskService. This supports the ownership diagnosis but does not fully establish the reported task-command path.
