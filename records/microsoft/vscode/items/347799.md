# Issue #347799 — Chat UI: Display model generation speed (tok/s) and response duration per turn

[https://github.com/microsoft/vscode/issues/347799](https://github.com/microsoft/vscode/issues/347799)

## Summary

Existing Chat footers already expose model details, elapsed time, and some token counts, but not generation speed. Keep this request open: the related metrics issue does not establish ownership of the specific inline, configurable presentation requested here.

## Change summary

Show compact per-turn model, duration, and generation-speed metadata in the Chat response footer, with optional diagnostic details.

## Best solution

Extend the existing response-details surface with understandable, optional performance information rather than a separate competing footer. Define generation-speed semantics for multi-call agent turns and handle unavailable provider measurements without displaying misleading values.

- **Behavior:**

  > Users should be able to inspect the model, elapsed duration, and meaningful generation speed for a completed Chat turn without opening developer diagnostics. The information should remain compact and optional, with longer model names and diagnostic details accessible on intent. Missing measurements must not appear as zero or fabricated throughput. Acceptance covers a single model call, a multi-call agent turn, unavailable provider metrics, and keyboard/screen-reader access.
- **Trace:**

  > renderChatResponseDetails and formatResponseTokenStats in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts already own footer timing, model details, and token-count hovers; chat.verbose is registered in browser/chat.shared.contribution.ts. IChatUsage in common/chatService/chatService.ts carries optional latest-call duration and TTFT separately from whole-turn modelTotals, which may include parallel subagent work and are currently agent-host-only. The existing surface does not format generation speed. The uncertainty is the user-facing definition of speed across multiple calls and providers, not the location of a new formatter. Preserve existing credit accounting, accessible hover behavior, and missing-data handling. https://github.com/microsoft/vscode/issues/331953 is related measurement work, not a verified duplicate of this presentation request.
- **Open decisions:**
  - Should displayed tok/s describe the final model call, per-model generation throughput, or whole-turn throughput, and how should parallel subagent work be represented?
  - Should performance statistics be controlled by chat.verbose or a separate user-facing setting, and what should the default visibility be?
