# Issue #133198 — [Test UI] [Feature Request] Allow message for skipped() test function

[https://github.com/microsoft/vscode/issues/133198](https://github.com/microsoft/vscode/issues/133198)

## Summary

Keep open: the testing API still cannot attach an explanatory message to a skipped test. This older report should remain the consolidation point; the matching request filed in 2026 is not an eligible duplicate target for this re-reviewed item.

## Change summary

Allow test providers to attach skip or inconclusive reasons and display them without failure-style highlighting.

## Best solution

Provide an optional skip-reason contract in the testing API and surface those reasons with non-error presentation while preserving skipped status. Consolidate the newer matching request into this older issue; treat skipped-only filtering as a separate enhancement rather than a substitute.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTesting.ts`, `src/vs/workbench/contrib/testing/common/testTypes.ts`, `src/vs/workbench/contrib/testing/browser/testingDecorations.ts`, `src/vs/workbench/api/test/browser/extHostTesting.test.ts`
- **Validation:** Extend the extHostTesting unit suite to verify a skipped test retains its skipped state and optional reason, including calls without a reason. Manually run a test provider that reports a located skip reason and verify it is discoverable in testing UI without failure-style highlighting; existing failed and errored messages must remain unchanged.
- **Behavior:**

  > Test providers can explain why a test was skipped or inconclusive without reporting it as a failure. Users can discover the explanation in testing UI, and any editor highlight uses non-error presentation. Calls that omit a reason preserve existing skipped behavior. A skipped-only filter does not fulfill this request.
- **Trace:**

  > The public TestRun.skipped signature in src/vscode-dts/vscode.d.ts accepts only a TestItem. Its implementation in src/vs/workbench/api/common/extHostTesting.ts sends a skipped-state update without appending messages, unlike failed and errored. Internal messages in src/vs/workbench/contrib/testing/common/testTypes.ts distinguish only Error and Output, and testingDecorations.ts consumes that distinction. The remaining uncertainty is the public reason payload and its user-visible presentation, not whether a gap exists. Preserve existing failure reporting and no-reason skip behavior. https://github.com/microsoft/vscode/issues/300416 independently requests the same capability but is newer; https://github.com/microsoft/vscode-java-test/issues/1320 illustrates related provider demand.
- **Open decisions:**
  - Should the optional skip reason expose the full TestMessage contract, including multiple messages and locations, or a narrower reason payload?
  - Should located skip reasons use neutral or warning presentation, and should the skipped editor gutter affordance change as part of this feature?

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.d.ts:18680-18725 declares skipped(test: TestItem) without a message parameter, whereas failed() and errored() accept TestMessage values. appendOutput(output, location?, test?) supports test-associated terminal output, not a skip-reason message with the requested presentation.
- **Current implementation confirms the gap:** src/vs/workbench/api/common/extHostTesting.ts:776-789 implements skipped by updating TestResultState.Skipped only. The adjacent errored and failed implementations also call appendMessages; skipped does not.
