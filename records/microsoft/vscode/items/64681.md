# Issue #64681 — Slow syntax highlighting

[https://github.com/microsoft/vscode/issues/64681](https://github.com/microsoft/vscode/issues/64681)

## Summary

Keep this accepted performance request open: background tokenization now runs in a worker, but that does not establish that large C/C++ files highlight promptly. No verified older, open issue owns the same observable problem.

## Change summary

Reduce the delay before syntax highlighting appears in large C/C++ files, including amalgamated sources such as sqlite.c.

## Best solution

Measure current large-file highlighting latency, separate grammar execution from scheduling and token delivery, and address the dominant cost without compromising token correctness or editor responsiveness. Treat worker tokenization as an existing improvement, not proof that the reported delay is resolved.

Measure visible-range and whole-file highlighting completion on initial open and after an external edit; compare repeated baseline and candidate runs, verify identical token output, and check that typing and scrolling remain responsive.
- **Behavior:**

  > Large C/C++ sources should acquire syntax highlighting promptly without blocking editing or scrolling. The report describes approximately 10 seconds of delay for a 60k-line C++ file and identifies sqlite.c as a public workload. Acceptance should demonstrate a repeatable latency improvement on those workloads while preserving highlighting correctness. C/C++ extension enhanced colorization is a separate scenario and must not substitute for validating built-in syntax tokenization.
- **Trace:**

  > editor.experimental.asyncTokenization already defaults to true, and TextMateTokenizationFeatureImpl supplies ThreadedBackgroundTokenizerFactory.createBackgroundTokenizer to the TextMate support. The factory creates a worker for eligible models; TextMateWorkerTokenizer._tokenize processes invalid lines with carried grammar state and delivers batches through the controller. The source confirms that the suggested worker architecture exists, but does not establish current timing or identify whether grammar execution, scheduling, or delivery dominates the remaining delay. Start with the concrete workloads and distinguish C from C++ language mode. Preserve existing token semantics, large-file safeguards, and synchronous editing behavior; do not expand this into a tree-sitter migration or semantic-coloring redesign. Related architectural work is https://github.com/microsoft/vscode/issues/77140, and grammar optimization is discussed at https://github.com/microsoft/vscode/issues/243405.
