# Issue #331592 — Agent Host chat input reverts while typing after draft sync rejection

[https://github.com/microsoft/vscode/issues/331592](https://github.com/microsoft/vscode/issues/331592)

## Summary

Team-authored, freshly filed bug with a detailed protocol-log trace of the root cause (eager draft session ownership not transferring when opened in a second window). No fix commit exists yet, so this stays open regardless — team-authored items are only closed with a mechanical, issue-referencing fix commit.

## Change summary

When an eager/unpublished Agent Host draft session is opened in a second window, the original owning window can dispose the backend session while the second window keeps editing, causing every draft sync to be rejected and the chat input to keep reverting to the last confirmed prefix while typing.

## Best solution

Fix session ownership/lifecycle for eager draft sessions in src/vs/platform/agentHost so opening a draft URI in a second client either transfers or shares ownership (or is disallowed) instead of leaving the original NewSession free to dispose() the backend while another client is actively subscribed; separately, harden the chat input against clobbering in-progress local edits with rejected/rolled-back draft state.
