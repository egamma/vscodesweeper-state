# Issue #185200 — Allow EnvironmentVariableCollection to unset variables

[https://github.com/microsoft/vscode/issues/185200](https://github.com/microsoft/vscode/issues/185200)

## Summary

Keep open: the current environment collection API still cannot unset a variable, and existing terminal settings do not cover extension-controlled environment transitions. This accepted Backlog request needs an API compatibility decision before implementation.

## Change summary

Allow extensions to remove environment variables through EnvironmentVariableCollection rather than replacing their values with empty strings.

## Best solution

Provide a backward-compatible collection API that distinguishes an unset variable from an explicitly empty value, while preserving existing mutation and collection-deletion semantics. Settle the public API contract before extending terminal environment application and persistence.

Verify collection serialization round-trips and use a test extension to confirm the variable is absent in a newly created terminal; cover shell-integration application if included in the approved API scope.
- **Behavior:**

  > An extension must be able to request that a terminal environment variable be absent, rather than present with an empty string. This should support leaving a direnv/Nix environment without retaining empty MACOSX_DEPLOYMENT_TARGET or Git author variables. Existing callers that explicitly replace a value with an empty string must retain their current behavior unless they opt into the new contract. Deleting a collection mutation must continue to remove only that extension's contribution. Acceptance must distinguish absent keys from empty values and cover the approved scope and application modes.
- **Trace:**

  > The stable declarations in src/vscode-dts/vscode.d.ts expose string-valued Replace, Append and Prepend mutations and define delete as removal of a collection mutator. ExtHostEnvironmentVariableCollection.replace in src/vs/workbench/api/common/extHostTerminalService.ts records the mutation; MergedEnvironmentVariableCollection.applyToProcessEnvironment in src/vs/platform/terminal/common/environmentVariableCollection.ts assigns replacement values without a deletion operation. Internal mutation types and serialization are in src/vs/platform/terminal/common/environmentVariable.ts and environmentVariableShared.ts. Application also supports a separate shell-integration mode, encoding mutations as VSCODE_ENV_REPLACE/APPEND/PREPEND, so process-creation behavior alone would not settle that mode. Existing terminal.integrated.env settings can delete keys with null, but are not collection mutations. The compatibility discussion at https://github.com/microsoft/vscode/issues/185200#issuecomment-1602603173 leaves the public representation unresolved; preserve existing empty-string replacement and collection-delete semantics. The related https://github.com/microsoft/vscode/issues/182560 concerns extension-host launch behavior and is outside this request's boundary.
- **Open decisions:**
  - What backward-compatible public contract should express unsetting: an explicit per-mutation operation or option, a collection-wide opt-in such as unsetEmpty, or another API shape?
  - Must the new unset capability support both process-creation and shell-integration application from its introduction, or is its initial public contract limited to process creation?

No unsetEmpty or additional collection API was found in src/vscode-dts.
