# Issue #336904 — Agents Web: Expose ChatGPT/Codex providers from remote Agent Host

[https://github.com/microsoft/vscode/issues/336904](https://github.com/microsoft/vscode/issues/336904)

## Summary

Fresh, credible request (two independent reporters within hours, one over SSH, one over web tunnel) about a real architectural gap: remote Agent Host connections only surface Copilot/GitHub providers in the model picker, not ChatGPT/Codex or Claude that are configured on the host side. Too new and cross-cutting for a close; needs area routing.

## Change summary

When connecting to a remote/tunneled Agent Host from the Agents web client, the model/provider picker only shows Copilot options, not ChatGPT-Codex or Claude providers configured and authenticated on the actual host.

## Best solution

Route to the sessions/remote-agent-host owners to design how non-Copilot provider availability (Codex/ChatGPT, Claude) is negotiated and surfaced through the remote Agent Host protocol to the web/SSH client, likely touching src/vs/sessions/services/agentHostFilter and the remoteAgentHost provider/session contribution layer.

- **Behavior:**

  > When a user connects to a remote Agent Host (via SSH or a web/dev tunnel) from the Agents window, the model/provider picker should list the same providers available on the host (e.g. ChatGPT-authenticated Codex, Claude) that a local connection to that same host would show, not just Copilot options.
- **Trace:**

  > The client-side filter/grouping in agentHostFilterService.ts only rolls up connection status for remote providers; where the actual set of exposed providers/models is negotiated between the remote Agent Host and the connecting client was not conclusively traced in this pass — candidates are the remote provider/session contribution code under src/vs/sessions/contrib/providers/remoteAgentHost/ and src/vs/platform/agentHost/node/agentHostProviderService.ts. Where the uncertainty starts: whether the gap is a protocol limitation (provider list never sent), a client-side filter (list sent but dropped), or an intentional security boundary around forwarding ChatGPT/Claude credentials over a remote connection.
- **Open decisions:**

  - Does the fix belong in the Agent Host protocol (advertise provider list) or purely in how the web/SSH client renders the picker?
