# Issue #336904 — Agents Web: Expose ChatGPT/Codex providers from remote Agent Host

[https://github.com/microsoft/vscode/issues/336904](https://github.com/microsoft/vscode/issues/336904)

## Summary

Multiple independent reporters (SSH, Dev Tunnel, vscode.dev/agents) confirm the remote Agent Host model picker doesn't expose ChatGPT/Codex (and Claude) models that are available and authenticated on the host — this is a real, still-open gap in cross-host model/provider forwarding, not a duplicate of the sessions-window issue linked in the timeline.

## Change summary

When connecting to a remote Agent Host (via vscode.dev/agents, Dev Tunnel, or SSH), the model/provider picker only shows GitHub/Copilot options even though the remote host has ChatGPT-authenticated Codex (or Claude) configured and working locally.

## Best solution

The remote Agent Host connection path needs to forward/expose the full IAgentModelInfo catalog (including chatgptSubscription-sourced models per src/vs/platform/agentHost/common/agentModelSource.ts) from the remote host to the client picker, not just Copilot/GitHub-backed models — likely touching the remote connection customization and model source plumbing in src/vs/workbench/contrib/chat/browser/remoteAgentHost/ and src/vs/platform/agentHost/node/agentService.ts.
