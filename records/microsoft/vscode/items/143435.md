# Issue #143435 — Line numbers in the Problems windows not easy to read when it comes to cells

[https://github.com/microsoft/vscode/issues/143435](https://github.com/microsoft/vscode/issues/143435)

## Summary

Keep open: Problems still displays cell-local line and column numbers without identifying the notebook cell. The discussion establishes a useful improvement, but leaves the cell-label presentation undecided; no qualifying canonical or fixing commit was identified.

## Change summary

Identify the notebook cell associated with each diagnostic in the Problems view without requiring users to open the problem.

## Best solution

Provide concise, recognizable cell context alongside notebook diagnostics in the Problems view while preserving correct navigation and cell-local coordinates. Settle whether that context should be an ordinal, a source preview, or both before implementation.

- **Behavior:**

  > Notebook diagnostics currently expose cell-local coordinates that do not tell users which cell contains the problem. Users should be able to distinguish diagnostics in different cells by reading the Problems view without opening each entry. Preserve correct navigation and existing line/column meaning. Acceptance should cover identical coordinates across cells, tree and table views, and cell insertion or reordering.
- **Trace:**

  > MarkerWidget.renderDetails in src/vs/workbench/contrib/markers/browser/markersTreeViewer.ts passes only line and column to Messages.MARKERS_PANEL_AT_LINE_COL_NUMBER in messages.ts. ResourceMarkers.markers in markersModel.ts flattens grouped markers without a cell-heading element, and MarkerFileColumnRenderer in markersTable.ts uses the same coordinate formatter. Existing Problems settings do not add cell context. The discussion at https://github.com/microsoft/vscode/issues/143435 proposes source previews and cell ordinals without selecting a design. The uncertainty starts at that user-visible representation and how it stays meaningful as notebook cells move; preserve ordinary file diagnostics, diagnostic coordinates, and working navigation.
- **Open decisions:**
  - Should notebook diagnostics identify their cell by its current ordinal, a source preview, or both?
  - Should cell context appear as an intermediate grouping in the Problems tree or inline with each diagnostic, and how should the equivalent context appear in table mode?
