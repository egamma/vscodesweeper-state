# Issue #287059 — Workspace folder name integrated terminal title not preserved on window reload

[https://github.com/microsoft/vscode/issues/287059](https://github.com/microsoft/vscode/issues/287059)

## Summary

Keep open: current source reconstructs restored terminals' workspace-folder identity from the last active workspace root rather than their own persisted context, so ${workspaceFolderName} can change after reload. The report supplies sufficient reproduction steps, and no verified fix or canonical duplicate was found.

## Change summary

Preserve each terminal's workspace-folder-derived title across window reloads in multi-root workspaces.

## Best solution

Restore each terminal's original workspace-folder association so configured titles remain stable across reloads, without changing the separate current-directory description or overriding explicit terminal renames.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/platform/terminal/common/terminal.ts`, `src/vs/workbench/contrib/terminal/test/browser/terminalInstance.test.ts`
- **Validation:** In a two-root workspace with distinct folder names, apply the reported title and description settings, create a terminal in each root, and reload with one root last active. Both titles must retain their original folder names. Repeat after changing one shell's cwd into the other root: its launch-folder title must remain unchanged while its cwd description updates. Add regression coverage in terminalInstance.test.ts that exercises restored instance construction and label computation, not only a label computer supplied with an already-correct workspaceFolder.
- **Behavior:**

  > A terminal using ${workspaceFolderName} retains the name of the workspace folder in which it was launched when the window reloads. Terminals launched in different roots must not all inherit the last active root's name. Changing a shell's current directory affects cwd-derived descriptions, not its launch-folder title. Explicit terminal renames and ordinary new-terminal folder selection remain unchanged.
- **Trace:**

  > TerminalService._recreateTerminalGroup in src/vs/workbench/contrib/terminal/browser/terminalService.ts recreates terminals from attachPersistentProcess without supplying launch-folder context for independent groups. TerminalInstance's constructor in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts resolves _workspaceFolder from shellLaunchConfig.cwd or the last active workspace root; subsequent reconnection restores _cwd but leaves _workspaceFolder unchanged. TerminalLabelComputer.computeLabel then reads that incorrect folder for ${workspaceFolderName}, conclusively exposing the reported failure in current source. IPtyHostAttachTarget in src/vs/platform/terminal/common/terminal.ts has workspace-level metadata and cwd but no explicit original folder association. The remaining investigation is whether backend persistence retains recoverable launch-folder context, or whether preserving it requires changes across the persistence contract and its producers; those consumers have not yet been traced. Preserve the existing distinction between launch-folder identity and live cwd rather than solving only the case where both happen to match. https://github.com/microsoft/vscode/issues/306723 and https://github.com/microsoft/vscode/issues/327326 describe separate requirements, not canonical ownership of this defect.
