## Evidence

- **Specific reproduction:** https://github.com/microsoft/vscode/issues/263282 supplies both an echo shell task and a python -V process task, launched through Tasks: Run Task on Windows 11 with VS Code 1.103.2; the reporter states that extensions are disabled and standalone execution does not leak.
- **Independent confirmation:** https://github.com/github0null/eide/issues/502#issuecomment-3973491435 reports reproducing accumulating conhost processes with handwritten VS Code tasks, including after closing the task. That report lists VS Code 1.109.3, and https://github.com/github0null/eide/issues/502#issuecomment-3973519707 explicitly points back to this issue; its closure is not evidence of a fix.
- **Upstream precedent:** https://github.com/microsoft/vscode/issues/281187 describes the same Run Task symptom: the command exits while conhost remains, with another conhost added per execution. The reporter says disabling windowsEnableConpty avoids it. At https://github.com/microsoft/vscode/issues/281187#issuecomment-3615011813, a VS Code maintainer identifies an upstream component as responsible. This younger, closed issue is precedent, not an eligible duplicate canonical or proof of resolution.
- **Current source boundary:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts creates shell/process launch configurations and calls reuseTerminal for reusable task terminals. In src/vs/platform/terminal/node/terminalProcess.ts, setupPtyProcess delegates spawning to node-pty, its onExit handler queues cleanup, and _kill calls the PTY's kill method before disposal. The source contains an explicit cleanup attempt; reading it does not establish why native conhost processes survive or prove that the reported leak is fixed.
- **Older related report:** https://github.com/microsoft/vscode/issues/245187 was verified open and predates this issue. It reports conhost zombies during development, and https://github.com/microsoft/vscode/issues/245187#issuecomment-2836724788 reports accumulation when opening/closing terminals or running Rust tests. It does not establish the same minimal shell/process-task failure mechanism, so it remains related evidence rather than a verified canonical under the stronger re-review bar.

They identify node-pty and ConPTY as upstream dependencies; the review instructions require upstream issues to remain open.
