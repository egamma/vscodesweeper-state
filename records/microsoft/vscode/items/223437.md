# Issue #223437 — VS Code Speech - Adjust reading rate / speed

[https://github.com/microsoft/vscode/issues/223437](https://github.com/microsoft/vscode/issues/223437)

## Summary

Keep this accepted Backlog request open: the inspected speech settings and synthesis path still provide no reading-rate control. The related requests are newer and closed, so neither supplies a valid duplicate target or evidence of completion.

## Change summary

Allow users to adjust VS Code Speech read-aloud speed, ideally between 100 and 500 words per minute.

## Best solution

Provide an accessible, persistent reading-rate setting for VS Code Speech while preserving the current default. Establish what rate units and range the synthesis engine can reliably support before committing to a words-per-minute contract.

- **Behavior:**

  > Users relying on VS Code Speech should be able to select a slower or faster narration rate for Copilot responses. The reporter prefers a 100–500 words-per-minute setting, but the supported units and range require a product decision informed by engine capabilities. Acceptance should cover audibly different playback rates, persistence of the preference and unchanged behavior at the default rate.
- **Trace:**

  > The current voice configuration in src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts has language, automatic synthesis, code-block filtering and recognition timeout controls, but no rate setting. ITextToSpeechSessionOptions in src/vs/workbench/contrib/speech/common/speechService.ts and the SpeechService/ExtHostSpeech provider path carry only language. The inspected provider at https://github.com/microsoft/vscode-speech/blob/main/src/extension.ts constructs an @vscode/node-speech synthesizer and forwards plain text without rate configuration; native engine rate support was not established. Keep recognition timeout, language selection, spoken-content filtering and cancellation semantics outside this request. The newer closed request https://github.com/microsoft/vscode/issues/303296 corroborates demand but does not demonstrate a shipped capability.
- **Open decisions:**
  - Should the setting promise an absolute 100–500 words-per-minute rate, or expose a relative rate with engine-supported limits if absolute timing cannot be guaranteed across voices and languages?
