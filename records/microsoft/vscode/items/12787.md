# Issue #12787 — [html] closing </script> tag is not proposed

[https://github.com/microsoft/vscode/issues/12787](https://github.com/microsoft/vscode/issues/12787)

## Summary

A real gap remains on current main: completion after a partial closing tag inside `<script>` is routed to JavaScript rather than HTML. This team-authored Backlog request is protected from a staleness close, and no explicitly referencing implementation commit or older canonical issue was found.

## Change summary

Offer `</script>` as a completion when the user types `</` inside an unclosed HTML script element.

## Best solution

Recognize an incomplete closing-tag opener inside embedded script content as an HTML completion context and offer the containing `/script` end tag, while preserving JavaScript completions elsewhere in the script body.

## Evidence

- **current routing:** extensions/html-language-features/server/src/modes/languageModes.ts selects exactly one completion mode using HTMLDocumentRegions.getLanguageAtPosition; extensions/html-language-features/server/src/htmlServer.ts then invokes that mode's doComplete implementation.
- **remaining source gap:** extensions/html-language-features/server/src/modes/embeddedSupport.ts marks the scanner's entire Script token as JavaScript. The bundled vscode-html-languageservice scanner only leaves WithinScriptContent after matching a closing tag beginning with `</script`, so the shorter `</` remains JavaScript content and does not reach getHTMLMode.doComplete.
- **existing completion capability:** extensions/html-language-features/server/src/modes/htmlMode.ts delegates HTML proposals to vscode-html-languageservice.doComplete2, whose current htmlCompletion.ts can collect the nearest open end tag after EndTagOpen; the missing piece is reaching that HTML path from incomplete script content.
