# Issue #335219 — Custom chat-completions model fails intermittently with HTTP/2 GOAWAY (Undici) and truncated request body (Node https fetcher)

[https://github.com/microsoft/vscode/issues/335219](https://github.com/microsoft/vscode/issues/335219)

## Summary

Traced in source: chat completion requests through `FetcherService`/`fetchWithFallbacks` are never issued with `retryFallbacks: true` (only the token-manager and quota-service calls in `copilotTokenManager.ts` and `chatQuotaServiceImpl.ts` use that flag), so a transient HTTP/2 GOAWAY mid-stream on a custom endpoint genuinely surfaces as a user-visible error with no automatic retry, matching the report. The alleged Node `https` fetcher body-truncation defect isn't independently confirmed from source alone (the request path in `nodeFetcher.ts` does a straightforward `write`+`end`), so that half needs live investigation.

## Change summary

Custom chat-completions endpoints behind an HTTP/2-terminating proxy intermittently fail with an unretried Undici GOAWAY error, and switching to the Node https fetcher instead deterministically truncates large request bodies.

## Best solution

Route to the Copilot Chat networking owners to decide whether chat completion streaming calls should gain GOAWAY-aware retry/reconnect handling (extensions/copilot/src/platform/networking/node/fetcherFallback.ts, fetcherServiceImpl.ts), and to separately investigate the Node https fetcher body write path in nodeFetcher.ts for large payloads.
