# Issue #335219 — Custom chat-completions model fails intermittently with HTTP/2 GOAWAY (Undici) and truncated request body (Node https fetcher)

[https://github.com/microsoft/vscode/issues/335219](https://github.com/microsoft/vscode/issues/335219)

## Summary

Traced the root cause on main: the one-time-retry allowlist for GOAWAY-style network errors checks native Node HTTP2 error codes, but undici's fetch (used by the default node-fetch fetcher) throws a `SocketError` with `code: 'UND_ERR_SOCKET'` wrapped in a `TypeError: fetch failed` — a code namespace the allowlist never matches — so the retry never fires for exactly the scenario reported.

## Change summary

Custom chat-completions endpoints behind an HTTP/2-terminating proxy hit unretried GOAWAY socket errors with the default fetcher, and a truncated request body with the Node https fetcher fallback.

## Best solution

Fix `canRetryOnceNetworkError` in src/platform/networking/common/networking.ts to unwrap `reason?.cause?.code` (as `isFetcherError` in nodeFetchFetcher.ts already does) and include undici's own error codes (e.g. `UND_ERR_SOCKET`) or match on the GOAWAY error message/name, so the existing one-shot retry-and-reconnect path actually engages for undici-sourced HTTP/2 GOAWAY failures.
