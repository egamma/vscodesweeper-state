# Issue #199009 — Using vscode.dev viatunnel, markdown internal link can not be opened

[https://github.com/microsoft/vscode/issues/199009](https://github.com/microsoft/vscode/issues/199009)

## Summary

Still appears to be a live bug on main — the markdown preview click handler should intercept relative links via `data-href` and delegate to the extension host, but in the tunnel/vscode.dev context the browser follows the rendered `href` (which points to `vscode-resource.vscode-cdn.net`) instead, opening a broken new tab. No fixing commit found.

## Change summary

Clicking internal markdown links in the preview when using vscode.dev via tunnel opens a broken browser tab instead of navigating within the editor.

## Best solution

Investigate why the webview click handler in `extensions/markdown-language-features/preview-src/index.ts` (line ~657–690) fails to intercept link clicks in the tunnel/vscode.dev webview context. The `data-href` attribute is set correctly by `markdownEngine.ts` (line 343), and the click handler should pick it up and post `openLink` — the issue likely lies in how webview events propagate in the browser-based webview host used by tunnels. The fix would be in the webview infrastructure or the markdown preview click handling.

## Evidence

- **click handler:** extensions/markdown-language-features/preview-src/index.ts lines 657–690 — the click handler checks `data-href` first, then falls through to `href`. For relative links like `test.md`, `data-href` is set (markdownEngine.ts:343) and should be intercepted, but the reporter's symptom indicates the browser is following the rendered `href` directly.
- **href rendering:** extensions/markdown-language-features/src/markdownEngine.ts `#toResourceUri` (lines 353–395) transforms relative links into webview resource URIs for the `href` attribute, which in tunnel context becomes the `vscode-resource.vscode-cdn.net` URL that fails.
