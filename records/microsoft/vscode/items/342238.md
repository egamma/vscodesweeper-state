# Issue #342238 — chat.exploreAgent.defaultModel not applied in Copilot CLI (agent host) sessions; no way to set subagent models from VS Code

[https://github.com/microsoft/vscode/issues/342238](https://github.com/microsoft/vscode/issues/342238)

## Summary

The setting-to-harness mismatch remains in current source: the configured Explore model reaches only local sessions, while agent-host sessions hide the runtime's subagent preferences command. Keep this report open; the newer model-configuration proposal discusses the gap but cannot replace this older, re-reviewed report.

## Change summary

Make Explore model preferences effective and configurable within VS Code's Copilot CLI agent-host sessions.

## Best solution

Provide a supported VS Code configuration path to the runtime's Explore model preferences, with explicit precedence relative to existing CLI preferences and unchanged local-harness behavior. Coordinate that contract with the broader model-configuration proposal without requiring its entire redesign to resolve this report.

- **Behavior:**

  > Configuring chat.exploreAgent.defaultModel currently affects the local Explore agent but not the runtime-owned Explore agent in Copilot CLI agent-host sessions. Users need an effective, discoverable way to select the latter's model from VS Code without launching a separate terminal CLI. Acceptance must verify the actual resolved subagent model, not merely the displayed setting or outgoing configuration. Existing local-session model selection must remain unchanged.
- **Trace:**

  > ExploreAgentProvider in extensions/copilot/src/extension/agents/vscode-node/exploreAgentProvider.ts reads the setting and generates a model-bearing definition restricted to sessionTypes: ['local']. The agent-host settings contribution forwards search and execution subagent models, while copilotCliConfig.ts exposes only Explore enablement; CopilotSessionLauncher therefore supplies no corresponding Explore model preference. CopilotSlashCommandCompletionProvider also filters subagents from runtime command completions. The missing setting path is confirmed, but the supported SDK mechanism for applying runtime preferences and its interaction with existing CLI preferences have not been established. https://github.com/microsoft/vscode/issues/342875 discusses that broader contract but is newer than this report. Preserve runtime-owned model resolution, existing CLI preferences, and local-harness behavior; do not expand this fix into the full model-registry redesign.
- **Open decisions:**
  - When chat.exploreAgent.defaultModel and an existing CLI Explore preference disagree, should the VS Code setting override the CLI preference for VS Code sessions, or should VS Code expose the runtime preference separately with an explicit scope distinction?
