# Issue #332954 — kernel issue

[https://github.com/microsoft/vscode/issues/332954](https://github.com/microsoft/vscode/issues/332954)

## Summary

The reported Windows build predates the documented minimum for integrated-terminal support following winpty removal. Propose closing as designed, with an explanation of the OS compatibility boundary rather than treating this as a Jupyter kernel defect.

## Change summary

The integrated terminal fails to launch with Cannot launch conpty on Windows build 14393.

## Best solution

Keep the documented ConPTY-only terminal support boundary and explain that restoring terminal operation requires a newer Windows version; do not promise that upgrading VS Code alone or enabling the bundled ConPTY DLL will support build 14393.

- **Proposed comment:**

  > Thanks for the report. Your Windows build, 14393, is Windows 10 version 1607. Integrated terminals no longer support Windows versions before 1809 following the removal of winpty in VS Code 1.109: https://code.visualstudio.com/updates/v1_109#_removal-of-winpty-support.
  > 
  > Please upgrade to a newer Windows version to use the integrated terminal. The `terminal.integrated.windowsUseConptyDll` setting is not a guaranteed workaround for this older OS, and upgrading VS Code alone does not restore that support. Closing as designed because this matches the documented compatibility boundary.

## Evidence

- **Reported environment:** https://github.com/microsoft/vscode/issues/332954 reports VS Code 1.121.0 on Windows_NT 10.0.14393, with the exact terminal-launch message explaining that winpty was removed. The body contains no separate kernel reproduction.
- **Documented compatibility boundary:** https://code.visualstudio.com/updates/v1_109#_removal-of-winpty-support explicitly states that removing winpty means terminals no longer work on Windows versions before Windows 10 version 1809. Build 14393 is Windows 10 version 1607. The notes recommend upgrading Windows and describe terminal.integrated.windowsUseConptyDll only as an experimental possibility, not guaranteed compatibility.
- **Current source:** src/vs/platform/terminal/node/terminalProcess.ts constructs useConpty only for Windows builds >= 18309 and gates useConptyDll on that condition. TerminalProcess.start catches Cannot launch conpty and emits the reporter's winpty-removal explanation. On build 14393, enabling terminal.integrated.windowsUseConptyDll does not enable that bundled-DLL path in current source.
- **Maintainer guidance on the same OS:** https://github.com/microsoft/vscode/issues/293305#issuecomment-3861895576 advises updating Windows or trying terminal.integrated.windowsUseConptyDll for the same launch error on build 14393, linking the documented winpty removal. Subsequent comments confirm that the DLL setting did not restore terminals on Windows Server 2016.
- **Related-report checks:** https://github.com/microsoft/vscode/issues/298293 describes the same failure on build 14393 but is closed; its cited target https://github.com/microsoft/vscode/issues/288707 is also closed and concerns terminal input under an older reported OS. Neither is a valid duplicate canonical. The open https://github.com/microsoft/vscode/issues/316884 additionally reports missing pcwutl.dll without identifying its Windows build, so the same root cause is not established.
- **Existing discussion:** The only comment on https://github.com/microsoft/vscode/issues/332954 asks the reporter to upgrade VS Code from 1.121.0 to 1.135.0. It supplies no reproduction or fix evidence, and upgrading VS Code alone does not change the documented Windows compatibility boundary.
