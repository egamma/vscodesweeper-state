# Issue #332194 — Auto-delete closing tag when opening tag becomes self-closed

[https://github.com/microsoft/vscode/issues/332194](https://github.com/microsoft/vscode/issues/332194)

## Summary

Legitimate, unimplemented request: VS Code's auto-closing-tag support (jsxClosingTag) only inserts a matching closing tag as you type an opening tag — it has no logic to remove a stale closing tag when the opening tag is edited into a self-closing form. This is a new capability, not a bug, and worth routing to the TypeScript/JS language features area.

## Change summary

When a paired tag's opening side is edited to become self-closing (e.g. `<Skeleton></Skeleton>` → `<Skeleton/></Skeleton>`), the editor should auto-remove the now-redundant closing tag.

## Best solution

Extend the `TagClosing` feature in extensions/typescript-language-features/src/languageFeatures/tagClosing.ts (and the corresponding `jsxClosingTag`-style TS server request) to detect a `/` inserted before the closing `>` of an opening tag that already has a matching closing tag, and remove that closing tag via a workspace edit — gated behind the same `autoClosingTags.enabled` setting.
