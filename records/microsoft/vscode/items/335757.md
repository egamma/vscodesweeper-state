# Issue #335757 — Testing: Agent input request is not surface while session remains "Working"

[https://github.com/microsoft/vscode/issues/335757](https://github.com/microsoft/vscode/issues/335757)

## Summary

Team-authored bug report (hard keep-open rule) describing a UI/state-sync defect: the Agents Window doesn't surface an `ask_user` question emitted by a remote Agent Host running in a Dev Container, leaving the session stuck showing 'Working' until a window reload. No fix commit found on main referencing this issue, so it stays open.

## Change summary

When a remote Agent Host (Dev Container) emits `chat/inputRequested` / `session/inputNeededSet`, the Agents Window fails to surface the question and keeps showing the turn as actively working until the window is reloaded.

## Best solution

Diagnose why the Agents Window's session-state consumer doesn't react to `session/inputNeededSet` for remote/Dev Container Agent Host connections specifically — likely a race or missed state transition in the session state sync path (src/vs/platform/agentHost/common/state/protocol/channels-session/state.ts and the sessions window UI that renders working/input-needed state) — and reconcile the UI on receipt of that action instead of relying on a reload to pick it up.
