# Issue #333017 — Context-size configuration is lost for extension-provided models in Agent Host

[https://github.com/microsoft/vscode/issues/333017](https://github.com/microsoft/vscode/issues/333017)

## Summary

Well-diagnosed, source-confirmed gap: the Agent Host BYOK bridge only forwards an extension model's `reasoningEffort` configuration and silently drops the rest of its `configurationSchema` (including `contextSize`), so a control that works in normal Chat disappears in Agent Host sessions for the same model.

## Change summary

An extension-provided `LanguageModelChatProvider`'s `configurationSchema.properties.contextSize` (and any non-reasoningEffort config) is not surfaced when the same model is used from an Agent Host (Local) session.

## Best solution

Extend the BYOK bridge DTO (`IByokLmModelInfo` in src/vs/platform/agentHost/common/agentHostByokLm.ts) and `AgentHostByokLmHandler.listModels()` to carry the provider's full `configurationSchema` (or at least `contextSize`) across the bridge, and update the node-side synthesis in `copilotAgent.ts` (`_createThinkingLevelConfigSchemaProperty`, called at lines ~1840/2235) to build a corresponding config property the same way it does for reasoningEffort today; a maintainer should first decide whether the boundary is a generic schema passthrough or an explicit new bridge capability (as the reporter asks).

## Evidence

- **handler drops other schema properties:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostByokLmHandler.ts:listModels() (~lines 166-190) reads only `metadata.configurationSchema?.properties?.reasoningEffort` off the renderer LM metadata and discards every other declared property, including `contextSize`.
- **node-side synthesis is reasoningEffort-only:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:1840 and :2150 (`_createThinkingLevelConfigSchemaProperty`) construct only a `thinkingLevel`/reasoningEffort config property from `m.supportedReasoningEfforts`; there is no equivalent path for `contextSize`.
- **contrast with native-model path:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLanguageModelProvider.ts:_toLanguageModelConfigurationSchema does pass through a full config schema (with a 'tokens' group for `contextSize`) — but that is for Agent Host's own native models surfaced to normal Chat, not for extension BYOK models entering Agent Host, confirming the asymmetry the reporter describes.
