# Issue #143997 — Cannot read property 'scheme' of null

[https://github.com/microsoft/vscode/issues/143997](https://github.com/microsoft/vscode/issues/143997)

## Summary

Keep open: current source still allows a null SCM command resource to reach URI.from() and throw while opening an editor. A newer report corroborates the same SCM failure, but cannot replace this older, previously reviewed issue under the duplicate rules.

## Change summary

Opening an SCM resource can fail with a null-resource TypeError instead of opening the requested editor or reporting a meaningful argument error.

## Best solution

Diagnose where the SCM command acquires its null resource, then ensure editor-opening commands preserve valid URI arguments and reject invalid ones explicitly without guessing a file scheme. Coordinate with the newer telemetry report while retaining this older issue.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmViewPane.ts`, `src/vs/workbench/browser/parts/editor/editorCommands.ts`, `src/vs/workbench/api/common/extHostSCM.ts`, `src/vs/workbench/api/common/extHostCommands.ts`, `src/vs/workbench/api/common/extHostApiCommands.ts`
- **Validation:** Establish a regression check that publishes an SCM resource with a vscode.open command containing a null URI, converts it through the SCM bridge, and invokes its open action. Verify explicit invalid-argument handling instead of the scheme TypeError, and verify valid open/diff commands retain their editor options and side-by-side behavior.
- **Behavior:**

  > Opening an SCM item must not fail with an incidental null.scheme TypeError. Valid resource commands must continue opening the intended editor or diff with their existing options. Invalid resource arguments must be reported explicitly rather than silently ignored or interpreted as file URIs. Acceptance should cover the SCM command-conversion path as well as valid-resource behavior.
- **Trace:**

  > SCM resource commands pass through ExtHostSourceControlResourceGroup conversion in src/vs/workbench/api/common/extHostSCM.ts and CommandsConverter.toInternal in src/vs/workbench/api/common/extHostCommands.ts. The converter applies API argument conversion without the validation used during normal API command execution. SCMViewPane.open forwards the converted arguments to editorCommands.ts, where URI.from dereferences null. This confirms the failure given a null command argument, but does not identify which provider or lifecycle supplies it. Preserve valid URI semantics, editor context, and unrelated commands; do not infer a file scheme. https://github.com/microsoft/vscode/issues/315292 supplies corroborating telemetry and a separate command-link entry point that may inform the impact boundary.
