# Issue #289679 — Partial Completion doesnt work with cmd+right

[https://github.com/microsoft/vscode/issues/289679](https://github.com/microsoft/vscode/issues/289679)

## Summary

Keep open: current source supports accepting words from ghost-text completions, but not from next-edit previews. The reported no-op is consistent with that distinction; an area owner should establish whether this is missing NES functionality or a failure of ordinary completion acceptance before choosing a fix.

## Change summary

Allow Cmd+Right to accept the next word from the multiline prediction described by the reporter.

## Best solution

Retest the reported flow while distinguishing ghost-text completions from next-edit previews. Restore existing word acceptance if ghost text is affected; if the preview is NES, decide which insertion or replacement edits should support partial acceptance without changing ordinary cursor navigation.

- **existing command and scope:** src/vs/editor/contrib/inlineCompletions/browser/controller/commands.ts:138-159 registers editor.action.inlineSuggest.acceptNextWord with Cmd+Right on macOS. Its precondition requires inlineSuggestionVisible; its keybinding additionally requires cursorBeforeGhostText and disables this binding in accessibility mode. Unlike full acceptance, it does not include inlineEditVisible.
- **current source boundary:** src/vs/editor/contrib/inlineCompletions/browser/controller/inlineCompletionsController.ts:399-429 derives inlineSuggestionVisible and cursorBeforeGhostText from inlineCompletionState. Consequently, the existing partial-accept command cannot accept words from an inline-edit preview, even when invoked directly.
