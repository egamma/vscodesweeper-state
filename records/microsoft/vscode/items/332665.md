## Evidence

- **path resolver already prunes missing paths:** src/vs/platform/windows/electron-main/windowsMainService.ts, doResolveFilePath (~L1238-1258): on fs.stat ENOENT it explicitly calls `this.workspacesHistoryMainService.removeRecentlyOpened([fileUri])` with the comment 'since file does not seem to exist anymore, remove from recent'.
- **flow confirmed to hit the failure path:** getPathsToOpen -> doExtractPathsFromAPI (L901-933) resolves the openable via resolveOpenable -> doResolveFilePath; a deleted folder yields ENOENT there, so both removal calls above are on the exact path a macOS Open Recent click takes, and doOpen (L542+) leaves usedWindows empty in this scenario, matching success === false in the menu handler.
- **menu is rebuilt after removal:** removeRecentlyOpened fires onDidChangeRecentlyOpened (workspacesHistoryMainService.ts L159); NativeMenubarControl (src/vs/workbench/electron-browser/parts/titlebar/menubarControl.ts) and the shared base class react to this event and re-send the menu template via IMenubarService.updateMenubar, so the native macOS menu should reflect the pruned list.
