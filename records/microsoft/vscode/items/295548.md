## Summary

Keep this open as the individual host-architecture update item requested by the maintainer. Current source still selects universal updates for universal installations; the newer macOS update umbrella explicitly tracks this issue rather than replacing it.

## Change summary

Reduce macOS download and update sizes by moving universal installations to packages matching the host architecture.

## Best solution

Have universal macOS installations update automatically to the appropriate architecture-specific package, following the maintainer's agreed direction instead of requiring a website nudge. Verify that the package transition installs and relaunches successfully on supported Mac architectures.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `build/darwin/create-universal-app.ts`
- **Validation:** Add Darwin update-feed selection checks covering universal installations on ARM64 and Intel hosts and unchanged architecture-specific installations. On signed macOS builds, perform an update from a universal installation and verify the downloaded package matches the host architecture, installs successfully, and relaunches with existing user data and settings preserved; include an Apple Silicon Rosetta scenario.
- **Behavior:**

  > Universal macOS installations currently continue downloading universal update packages even when only one architecture is needed. The agreed goal is automatic updates to packages matching the host architecture, without an explicit migration nudge. Acceptance includes architecture-appropriate downloads and successful installation and relaunch on supported Mac architectures. Existing architecture-specific installations must retain their working update behavior.
- **Trace:**

  > DarwinUpdateService.buildUpdateFeedUrl in src/vs/platform/update/electron-main/updateService.darwin.ts gives productService.darwinUniversalAssetId precedence over process.arch; doCheckForUpdates and doDownloadUpdate both use that method. build/darwin/create-universal-app.ts writes the universal identifier into the merged application's product metadata. This establishes the selection gap without executing code, but does not establish whether Electron's autoUpdater safely replaces a universal bundle with a single-architecture bundle or how host detection behaves under Rosetta. The discussion settles the product direction in favor of automatic architecture-specific updates, not an additional prompt. Preserve existing explicit, background, and metered update behavior and avoid expanding this item into differential updates or other work tracked by https://github.com/microsoft/vscode/issues/295579.
