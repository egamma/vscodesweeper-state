# Issue #295548 — Nudge users towards ARM macOS download

[https://github.com/microsoft/vscode/issues/295548](https://github.com/microsoft/vscode/issues/295548)

## Summary

Keep open as the individual macOS architecture-specific update item, as explicitly requested by the maintainer. Current source still selects the universal update feed for universal installations rather than the smaller host-specific package.

## Change summary

Reduce macOS download and update sizes by moving universal installations toward packages matching the host architecture.

## Best solution

Have universal macOS installations receive host-architecture updates without requiring a download-page nudge, following the direction agreed in the discussion. Preserve this issue as the individual deliverable under https://github.com/microsoft/vscode/issues/295579.

## Plan brief

- **Likely files:** `src/vs/platform/update/electron-main/updateService.darwin.ts`, `build/darwin/create-universal-app.ts`
- **Validation:** Add focused update-feed selection tests covering universal installations on ARM64 and Intel hosts while preserving existing architecture-specific feeds. Validate a signed universal-to-native update on each supported host architecture, including successful restart and a subsequent update check; do not execute these checks during this read-only review.
- **Behavior:**

  > Users running a universal macOS installation should receive updates matching the host architecture instead of repeatedly downloading a universal package. The transition should not require a download-page nudge or manual reinstall. Acceptance includes selecting the appropriate package on Apple Silicon and Intel, successfully applying and restarting into that package, and retaining normal subsequent updates. Existing architecture-specific installations should retain their update behavior.
- **Trace:**

  > DarwinUpdateService.buildUpdateFeedUrl in src/vs/platform/update/electron-main/updateService.darwin.ts prioritizes productService.darwinUniversalAssetId over process.arch; build/darwin/create-universal-app.ts sets that metadata to 'darwin-universal'. Both doCheckForUpdates and doDownloadUpdate use this feed-selection path before calling Electron autoUpdater. This establishes the client-side gap, but signed cross-package replacement and update-service responses were not exercised. The maintainer explicitly chose automatic architecture-specific updates rather than a nudge and retained this issue as the child deliverable of https://github.com/microsoft/vscode/issues/295579. Preserve architecture-specific installations and ordinary update-state behavior; broader differential-update work and website redesign are outside this item. https://github.com/microsoft/vscode/issues/259112 separately concerns Intel installations running under translation.
