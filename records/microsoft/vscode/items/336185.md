# Issue #336185 — Copilot Chat: external-agent (Claude) delegated sessions missing from Copilot Chat's own history

[https://github.com/microsoft/vscode/issues/336185](https://github.com/microsoft/vscode/issues/336185)

## Summary

Well-documented, plausible bug: the reporter traced it via actual session transcript metadata (entrypoint sdk-ts, cwd under ~/.copilot/chats/<uuid>) showing Copilot's own history is keyed off a scratch cwd that doesn't survive the run, while Claude's own store keeps the transcript under ~/.claude/projects. Current main confirms the mechanism (ensureWorkspacelessScratchDir / per-chat cwd in claudeAgent.ts) but reconciling the two persistence stores is a design question, not a one-line fix.

## Change summary

Claude-delegated (external-agent) chat sessions don't show up in Copilot Chat's own sidebar history, even though the run completed and Claude Code's own session list has it.

## Best solution

Decide how Copilot Chat's own history should be sourced for external-agent sessions — either keep the per-chat scratch cwd alive/durable so the existing history lookup works, or have Copilot's history read/attribute the Claude SDK's own transcript store directly. This is an agentHost/Claude integration design call, likely touching src/vs/platform/agentHost/node/claude/claudeAgent.ts and whatever indexes Copilot Chat's sidebar history.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/claude/claudeAgent.ts`, `src/vs/platform/agentHost/common/state/sessionState.ts`
- **Validation:** A regression test (or manual check) confirming a completed Claude-delegated session appears in Copilot Chat's sidebar history after the run, using the chosen persistence design.
- **Behavior:**

  > After a Claude-targeted external-agent chat session completes, it should appear in Copilot Chat's own sidebar chat history list, the same way native Copilot sessions do — not only in Claude Code's separate session list. Acceptance: starting and finishing a Claude-delegated session, then reopening the Copilot Chat sidebar, shows the session in history.
- **Trace:**

  > For workspace-less chats, `_bindFreshConversation` in src/vs/platform/agentHost/node/claude/claudeAgent.ts (~line 1543) assigns a per-chat scratch cwd via `ensureWorkspacelessScratchDir(this._environmentService.userHome, AgentSession.id(...))` under `~/.copilot/chats/<uuid>/`; the reporter's transcript excerpt shows this same cwd. The Claude SDK/CLI persists its own transcript under `~/.claude/projects/<sanitized-cwd>/*.jsonl` independent of that scratch dir, while Copilot Chat's own history appears to depend on the scratch dir (or a DB record pointing at it) still existing on disk, which it reportedly does not after the run. The boundary: don't change Claude's own transcript format or the SDK invocation; the fix is in how Copilot Chat's own history store is populated/read for external-agent sessions. Related: https://github.com/microsoft/vscode/issues/334170, https://github.com/microsoft/vscode/issues/335215 (Agents window discovery, not this sidebar-history claim).
- **Open decisions:**
  - Should Copilot's own history be repopulated from the Claude SDK's own transcript store, or should the per-chat scratch cwd be made durable so the existing history mechanism just works?
  - Is the missing scratch dir an intentional cleanup step elsewhere in the agent host, and if so, can Copilot's history record be written before that cleanup runs?
