Keep open: current main still excludes Windows ARM64 from native MSAL runtime packaging. An open implementation candidate already addresses this gap, so it should be reviewed rather than treating the issue as fixed or starting competing work.

Enable native Microsoft authentication broker support on Windows ARM64 so sign-in does not fall back to a browser flow that fails device-compliance requirements.

Review and land the Windows ARM64 support in https://github.com/microsoft/vscode/pull/324803 after validating native broker sign-in on an ARM64 device and preserving existing platform packaging. Updating the dependency alone is insufficient while the extension build excludes Windows ARM64 binaries.
