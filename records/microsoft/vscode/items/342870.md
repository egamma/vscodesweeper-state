# Issue #342870 — VS Code destroys state.vscdb.backup — the file it keeps for exactly this scenario — after a single torn page in state.vscdb

[https://github.com/microsoft/vscode/issues/342870](https://github.com/microsoft/vscode/issues/342870)

## Summary

Keep open: current source confirms that corruption first detected while loading items bypasses backup restoration, then shutdown rebuilds from an incomplete cache and overwrites the backup. This is a core storage data-loss defect, not an extension failure.

## Change summary

Restore a readable state.vscdb.backup when the primary database opens successfully but its initial item read fails, rather than replacing saved state with session defaults.

## Best solution

Recover the original stored values from a valid backup before exposing initialized storage, and prevent failed initial loading from authorizing destructive recovery from an incomplete cache. Preserve existing cache-based recovery for databases that become corrupt after their contents were successfully loaded.
