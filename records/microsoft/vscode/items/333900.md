# Issue #333900 — Sandbox bypass confirmation should offer disabling sandbox for the session

[https://github.com/microsoft/vscode/issues/333900](https://github.com/microsoft/vscode/issues/333900)

## Summary

This has a real version milestone (1.138.0), which is a scheduling decision per the hard keep-open rules — no close is available regardless of merits. On the merits: the underlying capability (disabling sandbox for the session) already exists but is overloaded onto the generic 'Allow in this Session' option for sandbox-bypass tool calls; the ask is to split it into an explicit, clearly-worded third choice.

## Change summary

Add a distinct 'Disable sandbox for this session and run' confirmation choice for sandbox-bypass requests, instead of reusing the generic 'Allow in this Session' option.

## Best solution

Add the explicit sandbox-bypass confirmation option gated on the `sandbox.allowBypass` policy as specified, and decide whether the existing overloaded behavior on 'Allow in this Session' (which currently also disables session sandboxing for bypass-flagged calls per `handleToolCallConfirmed` in sessionPermissions.ts) should be retired once the new option ships.
