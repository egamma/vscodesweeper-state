# Issue #333900 — Sandbox bypass confirmation should offer disabling sandbox for the session

[https://github.com/microsoft/vscode/issues/333900](https://github.com/microsoft/vscode/issues/333900)

## Summary

Fresh, well-specified feature request (0 days old) proposing a new session-scoped sandbox-disable confirmation choice; current code confirms this gap is real and unimplemented, so this should stay open for product/design review.

## Change summary

Add a distinct 'Disable sandbox for this session and run' confirmation option (separate from 'Allow in this Session') when a Copilot Runtime request is flagged as a sandbox bypass, so the user isn't asked repeatedly for commands that legitimately need to escape the sandbox.

## Best solution

Design a sandbox-specific confirmation choice in languageModelToolsConfirmationService.ts, gated on session policy (`sandbox.allowBypass`), that disables sandboxing for the session (distinct from the existing per-tool 'Allow in this Session' approval) and surfaces the changed posture in the permissions UI; belongs to the agent-sandbox area under src/vs/platform/agentHost and src/vs/workbench/contrib/chat/browser/tools.
