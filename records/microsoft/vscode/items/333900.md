# Issue #333900 — Sandbox bypass confirmation should offer disabling sandbox for the session

[https://github.com/microsoft/vscode/issues/333900](https://github.com/microsoft/vscode/issues/333900)

## Summary

Thanks for the detailed spec. Current main already implements the underlying capability — selecting 'Allow in this Session' on a sandbox-bypass confirmation disables sandboxing for that session only, scoped via session config (not the workspace setting) — but it reuses the existing button/label rather than the distinct 'Disable sandbox for this session and run' option the author explicitly asked for, so the UX-level ask isn't fully met and this should stay open for a maintainer design call.

## Change summary

Add a distinct, clearly-worded confirmation choice that disables sandboxing for the current session (not just tool auto-approval) when a Copilot sandbox-bypass request comes in.

## Best solution

A maintainer should decide whether the current 'Allow in this Session' reuse (src/vs/platform/agentHost/node/sessionPermissions.ts, ALLOW_SESSION_OPTION_ID + SANDBOX_BYPASS_META_KEY handling in handleToolCallConfirmed) is sufficient, or whether a dedicated option/label is still wanted as originally requested; if sufficient, this closes *as-designed with a comment pointing to that code path.
