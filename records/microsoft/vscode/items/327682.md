# Issue #327682 — Cancelled ripgrep text searches can remain pending indefinitely waiting for child process close

[https://github.com/microsoft/vscode/issues/327682](https://github.com/microsoft/vscode/issues/327682)

## Summary

The cancellation gap remains in current main: absent a child-process close or error event, cancellation does not settle the provider promise. Keep this open while the explicitly linked fix PR is reviewed.

## Change summary

Cancelled ripgrep text-search provider operations should settle deterministically even when the child process does not emit close promptly.

## Best solution

Review and land an appropriate fix through https://github.com/microsoft/vscode/pull/327686, preserving normal completion, result-limit handling, and symlink-loop retries while making cancellation settle and clean up deterministically.

## Evidence

- **Current source confirms the pending-promise path:** In src/vs/workbench/services/search/node/ripgrepTextSearchEngine.ts, provideTextSearchResultsWithRgOptions registers cancellation to call cancel(), which only sets isDone, calls rgProc.kill(), and cancels the parser. It neither resolves nor rejects the provider promise. The cancelled-success branch resolves only inside rgProc.on('close'); without close or error, the promise remains pending. The cancellation subscription is also not retained for disposal.
- **Outer cancellation does not settle the provider:** src/vs/workbench/services/search/common/searchService.ts:221 wraps providerPromise with raceCancellationError. In src/vs/base/common/async.ts:109-116, that helper rejects its own promise on cancellation without settling the supplied promise. RipgrepTextSearchEngine.provideTextSearchResults aggregates folder operations with Promise.all, so one pending folder operation keeps the aggregate pending.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/327686 is currently OPEN and unmerged, contains Fixes #327682, and lists this issue in closingIssuesReferences. Its changed files are the ripgrep engine and src/vs/workbench/services/search/test/node/ripgrepTextSearchEngineUtils.test.ts; its description reports a regression test for a child process that never emits close. This is an existing human-owned fix lane, not a completed fix.
