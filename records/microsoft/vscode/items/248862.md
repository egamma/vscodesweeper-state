# Issue #248862 — chat.implicitContext.enabled setting needs more documentation

[https://github.com/microsoft/vscode/issues/248862](https://github.com/microsoft/vscode/issues/248862)

## Summary

The documentation gap remains on current main: the schema enumerates the values but not the valid location keys. Route this accepted debt to the chat area so maintainers can decide whether the experimental setting should be documented or removed.

## Change summary

Make the valid keys and values of `chat.implicitContext.enabled` discoverable in Settings, or remove the obsolete experimental setting.

## Best solution

First settle whether this experimental setting remains supported. If retained, its configuration schema should expose only the effective chat-location keys with descriptions and completion support; if obsolete, remove the setting and its runtime reads together.

## Evidence

- **current schema:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.implicitContext.enabled` with unrestricted `additionalProperties`; it enumerates `never`, `first`, and `always` as values but provides no properties or descriptions for valid location keys.
- **current runtime:** src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts reads the object by `widget.location` and currently updates widgets at `ChatAgentLocation.Chat` (`panel`) and `ChatAgentLocation.EditorInline` (`editor`), confirming that undocumented location identifiers remain part of the behavior.
- **location definitions:** src/vs/workbench/contrib/chat/common/constants.ts defines the location strings `panel`, `terminal`, `notebook`, and `editor`, while the implicit-context update path currently targets only `panel` and `editor`; documenting every enum member without resolving that distinction could be misleading.
- **maintainer direction unresolved:** The discussion at https://github.com/microsoft/vscode/issues/248862 includes a maintainer questioning whether the setting remains relevant and another proposal to remove it, but no final decision; a January 2026 comment confirms that the setting was still exposed.
