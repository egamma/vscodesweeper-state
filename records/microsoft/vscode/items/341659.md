# Issue #341659 — Stop "Agent host session" spam in git log --all

[https://github.com/microsoft/vscode/issues/341659](https://github.com/microsoft/vscode/issues/341659)

## Summary

Keep open: current Agent Host checkpointing deliberately creates repository-local commits that appear in git log --all, and the existing checkpoint setting does not disable that capture path. The thread confirms the impact and identifies switching to the local harness as a workaround, not a solution within the Copilot harness.

## Change summary

Allow Copilot Agent Host conversations without accumulating checkpoint commits in the user's all-ref Git history.

## Best solution

Provide a supported way to avoid Agent Host checkpoint clutter while preserving ordinary repository history. Decide whether this should retain checkpoint functionality through isolated storage or offer an explicit opt-out with clearly defined restoration consequences.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentHostCheckpointService.ts`, `src/vs/platform/agentHost/node/agentHostGitService.ts`, `src/vs/platform/agentHost/common/agentHostCheckpointService.ts`, `src/vs/platform/agentHost/test/node/agentHostCheckpointService.test.ts`
- **Validation:** The plan should end with a temporary-repository integration check: record user refs, exercise a baseline and multiple conversation turns under the chosen behavior, and verify that git log --all gains no unwanted Agent Host history while user refs, HEAD, index, and working files remain unchanged by checkpoint bookkeeping. Verify restoration behavior according to the selected contract and compatibility with existing stored checkpoints.
- **Behavior:**

  > Copilot Agent Host conversations currently add baseline and per-turn checkpoint histories visible in git log --all. Users need a supported way to avoid that clutter without switching harnesses or deleting their conversation data. Acceptance must cover repeated turns, ordinary Git history remaining untouched, and an explicit contract for whether checkpoint restoration remains available.
- **Trace:**

  > AgentHostCheckpointService._captureBaseline creates a commit and refs/agents checkpoint reference; _captureTurnCheckpoint creates a start/end commit pair and updates the turn reference. AgentHostGitService.commitTree and updateRef execute directly in the user's repository, explaining all-ref visibility without changing the current branch. CopilotAgent invokes baseline capture, AgentSideEffects invokes turn-start capture, and CheckpointAndChangesetContribution invokes turn-end capture. The existing chat.checkpoints.enabled setting has presentation consumers but does not gate these host capture paths. Session-data deletion removes recorded refs, which is cleanup rather than prevention. Preserve user-authored refs and files, and account for existing checkpoint consumers and stored sessions before changing the storage or availability contract. The report and harness workaround are documented at https://github.com/microsoft/vscode/issues/341659.
- **Open decisions:**
  - Should avoiding repository-local checkpoint history preserve checkpoint restoration through isolated storage, or be an explicit opt-out that disables restoration for affected turns?
