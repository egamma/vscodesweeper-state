# Issue #341659 — Stop "Agent host session" spam in git log --all

[https://github.com/microsoft/vscode/issues/341659](https://github.com/microsoft/vscode/issues/341659)

## Summary

Keep open: current Agent Host still creates repository-local checkpoint commits reachable through git log --all, and the existing checkpoint setting does not control this capture path. Multiple commenters confirm the disruption; the matching newer report cannot replace this older, re-reviewed issue.

## Change summary

Provide a supported way to prevent Agent Host checkpoint commits from cluttering all-ref Git history and manage existing checkpoint refs.

## Best solution

Make checkpoint storage coexist cleanly with ordinary Git history tools, with explicit semantics for disabling capture and handling existing checkpoints. Preserve turn comparisons and restoration where supported, and explain any functionality lost when capture is disabled.

Cover baseline and turn capture, restart, existing checkpoints, and session deletion in the checkpoint-service suite; verify comparison/restoration remains functional wherever the chosen contract promises it.
- **Behavior:**

  > Using the Copilot Agent Host harness creates baseline and per-turn checkpoint commits that appear in git log --all and external Git history tools. Users need a supported way to avoid this clutter without switching harnesses or manually deleting internal refs. Acceptance must cover both new capture and the documented treatment of existing checkpoints, and clearly state whether disabling capture removes comparison or restoration capabilities.
- **Trace:**

  > AgentHostCheckpointService._captureBaseline and _captureTurnCheckpoint create synthetic commits through AgentHostGitService.commitTree and anchor them through updateRef in refs/agents. CheckpointAndChangesetContribution.onTurnEnd requests capture for completed turns, while the registered chat.checkpoints.enabled setting is consumed by checkpoint UI rather than this capture path. The checkpoint service documents durable refs as inputs to turn diffs and removes recorded refs when session/chat data is deleted, so deleting refs alone is not a complete or functionality-neutral solution. Preserve user branches, index contents, and supported comparison/restoration contracts; storage and opt-out semantics remain undecided. https://github.com/microsoft/vscode/issues/342038 reports the same disruption but is newer than this issue.
- **Open decisions:**
  - Should users avoid Git-history clutter by disabling Git checkpoint capture, with explicit feature limitations, or should checkpoint functionality remain available through storage that does not introduce refs into the user's repository?
  - If capture can be disabled, should chat.checkpoints.enabled govern Agent Host persistence as well as presentation, and should disabling it retain existing checkpoints or offer explicit removal?
