# Issue #227697 — LSP DocumentColor Refresh Request

[https://github.com/microsoft/vscode/issues/227697](https://github.com/microsoft/vscode/issues/227697)

## Summary

The refresh capability is still missing on current main, and the issue remains the core API prerequisite for language clients to support `workspace/documentColor/refresh`. As a team-authored Backlog request with a confirmed downstream dependency, it should remain open for API design and implementation.

## Change summary

Allow document color providers to signal that previously computed color information has changed without requiring a text edit.

## Best solution

Add a document-color provider refresh signal through the editor language-feature and extension-host API layers, then have the color detector recompute affected decorations. The API contract should align with the LSP refresh semantics so language clients can forward `workspace/documentColor/refresh` without synthetic document edits.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/languages.ts`, `src/vs/editor/contrib/colorPicker/browser/colorDetector.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts`, `src/vs/workbench/api/test/browser/extHostLanguageFeatures.test.ts`
- **Validation:** Add an extension-host language-features test proving a document-color provider refresh crosses the RPC bridge, plus an editor color-detector test proving that firing the refresh without editing the model invokes the provider again and updates the decorations; run the targeted unit tests with `scripts/test.sh --grep "Document colors|ColorDetector"`.
- **Behavior:**

  > A document color provider can notify VS Code when its color information has changed even though the document text has not. Open editors using that provider recompute their color information and update their swatches, including after semantic project information becomes available or a referenced resource changes. Existing text-change refresh behavior and providers without a refresh signal remain unchanged.
- **Trace:**

  > `DocumentColorProvider` has no refresh event in either `src/vscode-dts/vscode.d.ts` or `src/vs/editor/common/languages.ts`. Its registration path crosses `ExtHostLanguageFeatures.registerColorProvider`, `MainThreadLanguageFeatures.$registerDocumentColorProvider`, and `MainThreadLanguageFeaturesShape` without the event handle used by comparable features such as folding ranges and inlay hints. `ColorDetector.updateColors` currently installs a model-content listener and recomputes on registry changes, but it has no provider-data invalidation source. The related language-client scenario is tracked at https://github.com/dotnet/vscode-csharp/issues/7515; keep protocol-client wiring outside this core change unless the API contract requires coordination.
- **Open decisions:**
  - Should the public provider event invalidate document colors globally, matching the parameterless LSP workspace refresh request and existing folding-range precedent, or identify specific document URIs so providers can avoid recomputing unaffected open editors?

## Evidence

- **public API gap:** On current main, `DocumentColorProvider` in `src/vscode-dts/vscode.d.ts` exposes only `provideDocumentColors` and `provideColorPresentations`; unlike `FoldingRangeProvider`, it has no change event.
- **extension-host gap:** `registerColorProvider` in `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `$registerDocumentColorProvider` in `src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts`, and the corresponding declaration in `src/vs/workbench/api/common/extHost.protocol.ts` carry no event handle or refresh signal.
- **consumer behavior:** `ColorDetector` in `src/vs/editor/contrib/colorPicker/browser/colorDetector.ts` recomputes for model content, model language, configuration, and provider-registry changes, but cannot observe a registered provider's underlying semantic data changing.
- **downstream dependency:** https://github.com/dotnet/vscode-csharp/issues/7515 remains open and explicitly blocked on https://github.com/microsoft/vscode/issues/227697 for XAML color swatches whose values become available or change outside the current document.
- **maintainer intent:** The maintainer comment at https://github.com/microsoft/vscode/issues/227697#issuecomment-2333329651 confirms that the VS Code API must be added before the corresponding LSP work.
- **canonical search:** Repository searches found no other open microsoft/vscode issue owning this request and no open or merged microsoft/vscode pull request implementing document-color refresh.
