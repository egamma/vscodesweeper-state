# Issue #308256 — Agents App: When I mark a session as done, I can't find it anymore

[https://github.com/microsoft/vscode/issues/308256](https://github.com/microsoft/vscode/issues/308256)

## Summary

Keep open for session-list discoverability improvements: the reporter found the Done section, but current source still places completed sessions after all workspace sections. This team-authored feedback remains actionable, and the related reports are newer rather than eligible duplicate canonicals.

## Change summary

Make completed sessions easy to rediscover after enabling Show Done, without unexpectedly losing their workspace context.

## Best solution

Improve completed-session navigation in the Agents Window so enabling Show Done makes those sessions readily discoverable. Decide whether they should remain within workspace sections or have a clearly discoverable separate destination, coordinating with https://github.com/microsoft/vscode/issues/313108.

- **Behavior:**

  > Marking a session done currently removes it from its workspace section, and enabling Show Done exposes a separate section that can be far below the viewport. Users should be able to locate that completed session without mistaking the filter for a broken control. Acceptance should cover a long workspace list, toggling completed-session visibility, and reopening or restoring the completed session. The exact destination and whether workspace context is preserved require a product decision.
- **Trace:**

  > groupSessionsForList in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts partitions archived sessions before workspace/date grouping and appends them as one final section; the tree composition also explicitly renders archived last. SessionsView.registerArchivedFilter in sessionsView.ts changes exclusion state without changing this placement. The existing sessionsList.test.ts section-order assertion and SESSIONS_LIST.md establish this as the current contract, not an accidental filtering failure. Keep provider archive persistence and session lifecycle semantics outside this usability change. Coordinate the observable grouping choice with https://github.com/microsoft/vscode/issues/313108; https://github.com/microsoft/vscode/issues/323450 provides corroborating discoverability feedback. Source was inspected without executing the UI.
- **Open decisions:**
  - When Show Done is enabled in workspace grouping, should completed sessions appear within their workspace sections or remain in a separate completed-session destination?
  - If the separate destination remains, should enabling Show Done navigate to that section or preserve the current scroll position while explicitly exposing where completed sessions can be found?
