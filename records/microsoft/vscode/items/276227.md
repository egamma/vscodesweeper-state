# Issue #276227 — Weird Prompt file linting error: No link definition found

[https://github.com/microsoft/vscode/issues/276227](https://github.com/microsoft/vscode/issues/276227)

## Summary

The false diagnostic remains explainable on current main: prompt files are sent through Markdown validation, but the bundled Markdown language service does not exclude the parser's `front_matter` token when scanning raw text for reference links. This should remain open and be addressed in the Markdown language service.

## Change summary

Markdown link validation interprets bracketed YAML values in prompt-file frontmatter as reference links and reports `link.no-such-reference` warnings.

## Best solution

Teach `vscode-markdown-languageservice` to exclude recognized frontmatter token ranges from link extraction, then update VS Code to the fixed service version. Preserve normal link validation in the Markdown body and for bracket syntax outside recognized frontmatter.

## Evidence

- **confirmed reproduction:** A maintainer confirmed that setting `markdown.validate.enabled` to true reproduces the report: https://github.com/microsoft/vscode/issues/276227#issuecomment-3517047068.
- **VS Code integration:** `extensions/markdown-language-features/src/util/file.ts` includes `prompt` in `markdownLanguageIds`, and `src/client/client.ts` passes all of those language IDs to the Markdown language server.
- **current parser:** `extensions/markdown-language-features/src/markdownEngine.ts` registers the frontmatter parser from `src/extensions/yamlPreamble/yamlPreamble.ts`, which emits a mapped `front_matter` token covering the YAML header.
- **upstream root cause:** In bundled `vscode-markdown-languageservice` 0.5.0, `src/util/noLinkRanges.ts` excludes only `code_block`, `fence`, and `html_block` tokens. `src/languageFeatures/documentLinks.ts` then applies its reference-link regex to the raw document, leaving bracketed values inside `front_matter` eligible for `link.no-such-reference`.
- **related change does not resolve diagnostics:** Commit 06115d9e8fbc5bfae917509a73cf7d394ae1f2d9 (https://github.com/microsoft/vscode/commit/06115d9e8fbc5bfae917509a73cf7d394ae1f2d9) and https://github.com/microsoft/vscode/pull/316147 added improved frontmatter parsing/rendering, but did not update the language service's no-link ranges.
- **canonical search:** No older open issue with the same prompt-frontmatter diagnostic was found. https://github.com/microsoft/vscode/issues/323229 is newer and concerns math blocks, so it cannot be the canonical issue for this re-reviewed report.
