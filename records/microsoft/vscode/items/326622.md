## Change summary

MCP servers configured via an installed agent plugin fail to spawn with 'spawn uvx ENOENT' when VS Code's GUI connects to a WSL (or SSH) remote, even though uvx works fine in the integrated terminal and via the Copilot CLI.

## Best solution

## Evidence

- **spawn code path:** src/vs/workbench/api/node/extHostMcpNode.ts startNodeMpc() spawns launch.command with env = {...process.env, ...launch.env}; PATH from launch.env is appended, not replacing process.env's PATH.
- **remote ext host env resolution:** src/vs/server/node/extensionHostConnection.ts buildUserEnvironment() normally merges getResolvedShellEnv(...) into the remote extension host's env before extensions (and thus extHostMcpNode) run, so PATH gaps for ~/.local/bin would be unusual unless that resolution is disabled or the server was started before it completed.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/320167 and its linked PR https://github.com/microsoft/vscode/pull/322874 fix a different ENOENT cause (bad cwd from Windows client fsPath on Windows→Linux Remote-SSH for absolute-path commands), not a PATH-resolution problem for a bare command like uvx.
