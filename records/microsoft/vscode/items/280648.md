# Issue #280648 — Allow dragging chat editors to the chat panel

[https://github.com/microsoft/vscode/issues/280648](https://github.com/microsoft/vscode/issues/280648)

## Summary

The capability remains missing on current main, and three team members agreed that dragging a chat editor back into the chat panel should work. This team-authored, On Deck request has a concrete implementation direction and should remain open.

## Change summary

Allow a chat editor tab to be dragged onto the chat panel, moving its existing session back into that view.

## Best solution

Represent a resolved chat editor's session in editor drag data, recognize that payload in the chat drop target, and move the session into the existing chat view through `IChatWidgetService.openSession` with `ChatViewPaneTarget`, preserving the current attachment behavior for other editor drops.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/editor/chatEditorInput.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatDragAndDrop.test.ts`
- **Validation:** Add targeted tests proving that a resolved `ChatEditorInput` produces drag data for its current session and that dropping this payload invokes `openSession(sessionResource, ChatViewPaneTarget)` without adding an attachment; run `./scripts/test.sh --grep "ChatEditorInput|ChatDragAndDrop"`, then manually drag a chat editor tab onto the chat panel and confirm the editor closes while the same session opens in the panel.
- **Behavior:**

  > Dragging a resolved chat editor tab onto the chat panel moves that existing session into the panel. The drop overlay identifies the action as opening the session rather than attaching a file, and the editor copy is removed through the existing move behavior. Ordinary file, folder, image, symbol, and chat-reference drops continue to create attachments exactly as before. An editor that does not yet identify a real session must not produce a misleading supported drop.
- **Trace:**

  > `fillEditorsDragData` in src/vs/workbench/browser/dnd.ts obtains transferable editor data exclusively through `EditorInput.toUntyped`; `ChatEditorInput` currently inherits the undefined implementation. The chat input drop target in src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts treats every `CodeDataTransfers.EDITORS` payload as file context and routes it through `resolveAttachmentsFromDragEvent`. The existing destination path is `IChatWidgetService.openSession(sessionResource, ChatViewPaneTarget)` in src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts, whose `prepareSessionForMove` already closes the source editor before loading the session in the view. The trace must resolve how `ChatEditorInput.resource` versus `sessionResource` is represented without reviving the mutable-resource problem tracked by https://github.com/microsoft/vscode/issues/281476. Keep generic editor DnD and all non-session attachment semantics unchanged.

## Evidence

- **missing drag identity:** `ChatEditorInput` in src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts does not override `toUntyped`, while `fillEditorsDragData` in src/vs/workbench/browser/dnd.ts skips editor inputs whose `toUntyped` returns undefined.
- **missing drop behavior:** `ChatDragAndDrop` in src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts classifies `CodeDataTransfers.EDITORS` only as an internal file and resolves it as attachment context; it has no chat-session drop type or path that opens the session in the panel.
- **existing move service:** `IChatWidgetService.openSession` in src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts already accepts `ChatViewPaneTarget`; its `prepareSessionForMove` path closes an existing chat editor before loading the same session in the chat view.
- **maintainer consensus:** Three VS Code team members endorsed the behavior, and the latest design comment outlines the `ChatEditorInput` and `ChatDragAndDrop` work: https://github.com/microsoft/vscode/issues/280648#issuecomment-3709791165.
- **related dependency:** The discussion identifies the still-open https://github.com/microsoft/vscode/issues/281476 as a possible prerequisite because editor drag data must distinguish the immutable editor resource from the resolved session resource.
- **canonical search:** Searches for open issues about dragging or moving chat editors into the panel found no older issue with the same reporter-observable behavior; the supplied candidates concern chat scrolling and do not own this work.
