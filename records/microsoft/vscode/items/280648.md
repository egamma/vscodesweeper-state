# Issue #280648 — Allow dragging chat editors to the chat panel

[https://github.com/microsoft/vscode/issues/280648](https://github.com/microsoft/vscode/issues/280648)

## Summary

Keep open: the existing move command returns a chat to the Chat view, but current drag-and-drop handling only attaches context and does not perform that move. Maintainers explicitly endorsed the requested gesture; no verified older canonical or issue-referencing fix was found.

## Change summary

Allow dragging a chat editor tab into the Chat view to move its existing session back out of the editor area.

## Best solution

Make dragging a chat editor into the Chat view perform the same session-preserving relocation as the existing move command, with feedback that distinguishes opening a session from attaching context.

Repeat with a non-active source tab; verify ordinary file/image context drops and chat-reference attachments remain unchanged.
- **Behavior:**

  > Dragging a recovered chat editor into the Chat view should move that existing session out of the editor area rather than attach it as context or do nothing. The destination should retain the conversation and unsent input, matching the existing move command, with feedback that communicates opening a session. Acceptance includes dragging a non-active source tab without accidentally moving the active chat. Existing attachment and chat-reference gestures must retain their current behavior.
- **Trace:**

  > ChatDragAndDrop in src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts currently routes drops only through attachment resolution; editor payloads are treated as internal files and overlays describe attaching context. ChatEditorInput in src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts does not override the base toUntyped method, which returns undefined, and its editor resource is distinct from its resolved sessionResource. The established command path is moveToSidebar in src/vs/workbench/contrib/chat/browser/actions/chatMoveActions.ts, which invokes ChatWidgetService.openSession with ChatViewPaneTarget and preserves input state; that service already manages model retention and source-editor closure during moves. The remaining investigation is how editor drag data identifies the actual source session across these identities without disturbing normal attachments or chat-reference drops. https://github.com/microsoft/vscode/issues/281476 documents the related identity concern but is not proof that this gesture must wait for that entire issue. The intended relocation behavior is already settled by the maintainer discussion at https://github.com/microsoft/vscode/issues/280648; payload transport and helper selection are implementation choices.

## Evidence

The December 23 and January 5 comments identify editor drag serialization and session-specific drop handling as missing pieces. - **Existing capability is only a workaround:** src/vs/workbench/contrib/chat/browser/actions/chatMoveActions.ts registers workbench.action.chat.openInSidebar and an editor-title 'Move Chat into Panel' variant when the Chat view is in the panel. moveToSidebar opens the editor's sessionResource through IChatWidgetService.openSession(..., ChatViewPaneTarget); this supports relocation by command, not by the requested drag gesture.
- **Current drop behavior:** In src/vs/workbench/contrib/chat/browser/widget/chatDragAndDrop.ts, ChatDragAndDrop.drop exclusively resolves and adds attachments. guessDropType classifies CodeDataTransfers.EDITORS as FILE_INTERNAL, and getOverlayText always describes attaching context. CHAT_REFERENCE likewise attaches a reference rather than relocating the dragged session; there is no session-opening drop branch.
- **Editor identity boundary:** src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts has separate readonly resource and sessionResource properties but no toUntyped override; the inherited implementation in src/vs/workbench/common/editor/editorInput.ts returns undefined. https://github.com/microsoft/vscode/issues/281476 remains open and documents the related editor-resource identity concern; it does not own the same observable drag-to-panel request.
- **Existing relocation lifecycle:** src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts implements openSession and prepareSessionForMove: it retains a model reference during relocation, closes the source editor through closeForMove, and loads the session into ChatViewPane. This establishes existing move semantics that the requested gesture should preserve.
