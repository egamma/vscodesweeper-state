# Issue #337653 — Claude agent host: model picker shows the first native model (Fable) after restart, while turns still run on the saved model

[https://github.com/microsoft/vscode/issues/337653](https://github.com/microsoft/vscode/issues/337653)

## Summary

Well-diagnosed, independently corroborated bug: the model picker (and in one reporter's logs, occasionally the actual routed model) reverts to the first native Claude model after a restart while the saved selection is Opus — a startup race between the async native `supportedModels()` fetch and remembered-model restoration. The workbench already has substantial machinery for exactly this class of race (`ChatInputModelSelectionController`/`SessionModelSelection` 'awaiting remembered model' handling), so this is a real gap in that mechanism for the agent-host Claude native-model path rather than an unhandled scenario, but I could not pin the precise faulty line without executing the flow.

## Change summary

After restarting VS Code and reopening a Claude agent-host session, the model picker shows Fable (the first native model) instead of the previously selected Opus, even though (usually) turns still route correctly to the saved model.

## Best solution

Trace the restore path in src/vs/sessions/contrib/chat/browser/sessionModelSelection.ts and src/vs/workbench/contrib/chat/browser/widget/input/chatInputModelSelectionController.ts against the Claude agent host's async native model list arrival (claudeAgent.ts / claudeModelSelection.ts mergeClaudeModelCatalogs) to find why the remembered-model reconciliation doesn't win the race for this provider, and ensure the picker label (and, per one reporter, actual routing) is not shown/committed until the true saved model is confirmed present or absent in the merged catalog.
