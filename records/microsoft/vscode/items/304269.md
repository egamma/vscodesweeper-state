# Issue #304269 — Support discovering and installing agent skills from `.well-known` skill indices

[https://github.com/microsoft/vscode/issues/304269](https://github.com/microsoft/vscode/issues/304269)

## Summary

Keep open: repository-backed plugin installation and marketplace skill discovery do not establish support for arbitrary publishers' .well-known skill indices. This team-authored request remains distinct from the related, closed URL-handler request, and no qualifying fix or open canonical duplicate was found.

## Change summary

Discover skills from a publisher's .well-known index and selectively install standalone or archived skills with integrity verification.

## Best solution

Integrate publisher-hosted skill discovery with the existing customization marketplace and installation experience, rather than adding a separate management surface. First settle the supported discovery-spec version and installation lifecycle, including trust, destination, updates, and removal.

- **Likely files:** `src/vs/platform/customizationMarketplace/common/customizationMarketplaceService.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/customizationMarketplaceInstallService.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/skillActions.ts`, `src/vs/workbench/contrib/chat/browser/pluginUrlHandler.ts`
- **Validation:** Use a controlled HTTP publisher fixture exposing /.well-known/agent-skills/index.json with a standalone SKILL.md and a tar.gz skill. Verify selective installation from two publishers, usable installed skills, digest-mismatch rejection, and rejection of traversal entries and oversized decompressed archives; verify the agreed destination, update, and removal behavior.
- **Behavior:**

  > A user supplies a publisher URL, sees the skills advertised by its standardized discovery index, and chooses which to install. Both standalone SKILL.md files and archived skills are supported, with integrity checks before installation and safe rejection of invalid archives. Multiple publishers can coexist without silently replacing unrelated skills. Acceptance should cover successful discovery and installation, failed integrity checks, unsafe archives, and the installation lifecycle agreed with the maintainer.
- **Trace:**

  > PluginUrlHandler in src/vs/workbench/contrib/chat/browser/pluginUrlHandler.ts handles repository-oriented plugin installation and marketplace URLs, not this discovery protocol.
