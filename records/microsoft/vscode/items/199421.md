# Issue #199421 — Can't paste external files or folders via explorer paste context menu

[https://github.com/microsoft/vscode/issues/199421](https://github.com/microsoft/vscode/issues/199421)

## Summary

The bug remains on current main: keyboard paste handles external files through the DOM paste event, while the Explorer context-menu command is disabled unless VS Code's internal file-copy context key is set. This team-authored, accepted bug must remain open.

## Change summary

Enable the Explorer context-menu Paste action after files or folders are copied from an external system file explorer.

## Best solution

Make the Explorer context-menu Paste action recognize and consume external native clipboard files through the same file-paste pipeline used by Ctrl/Cmd+V, while preserving internal copy/cut behavior and writable-resource guards.

## Evidence

- **current source:** src/vs/workbench/contrib/files/browser/fileActions.contribution.ts registers the Explorer context-menu Paste action with `FileCopiedContext` in its precondition, so it remains disabled when the clipboard was populated outside VS Code.
- **working keyboard path:** src/vs/workbench/contrib/files/browser/views/explorerView.ts handles the DOM `paste` event and passes `event.clipboardData.files` to `filesExplorer.paste`, explaining why Ctrl/Cmd+V works for the same external files.
- **clipboard boundary:** src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts reads resources only from VS Code's custom native clipboard format; an external system file copy does not set the `FileCopiedContext` used by the menu precondition.
- **current confirmation:** https://github.com/microsoft/vscode/issues/316001 reports the same disabled context-menu Paste action in VS Code 1.119 while Ctrl+V succeeds. It is newer than this re-reviewed issue, so it cannot serve as the canonical duplicate.
- **accepted bug:** The issue was authored by a repository member and carries the `bug` and `file-explorer` labels; the thread confirms the behavior applies to files and folders generally, with keyboard paste and drag-and-drop as workarounds.
