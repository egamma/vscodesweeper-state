# Issue #330388 — Semantic tokens not applied to deleted (original) lines in the inline/unified diff editor

[https://github.com/microsoft/vscode/issues/330388](https://github.com/microsoft/vscode/issues/330388)

## Summary

Traced and confirmed root cause on main: the inline diff editor never attaches the original model to a live editor, so the semantic-tokens fetch bails out early via `isAttachedToEditor()`, leaving deleted lines with TextMate-only coloring while side-by-side mode (which does attach a real editor to the original model) works correctly.

## Change summary

In the inline/unified diff view, deleted (original) lines only get TextMate tokenization, never semantic-token coloring, unlike side-by-side mode.

## Best solution

Either explicitly fetch/apply semantic tokens for the visible deleted-line ranges of the original model in diffEditorViewZones.ts (similar to how viewportSemanticTokens.ts handles large-file ranges), or relax the `isAttachedToEditor()` gate in ModelSemanticColoring for diff-original models so `_fetchDocumentSemanticTokensNow` still runs when the model backs an inline diff deletion view zone.

## Evidence

- **root cause:** src/vs/editor/contrib/semanticTokens/browser/documentSemanticTokens.ts `_fetchDocumentSemanticTokensNow()` returns early with `if (!this._model.isAttachedToEditor()) { ... return; }`, so semantic tokens are never fetched for a model unless a real editor has attached it.
- **attach mechanism:** src/vs/editor/common/model/textModel.ts tracks `_attachedEditorCount`; `isAttachedToEditor()` returns `_attachedEditorCount > 0`, incremented only when a CodeEditorWidget calls setModel.
- **inline diff rendering path:** src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/diffEditorViewZones.ts (around line 218-232) reads `originalModel.tokenization.getLineTokens(l)` directly to render deleted-line HTML via renderLines.ts, without ever attaching the original model to a live editor — so it never triggers a semantic-tokens request for that model.
- **side-by-side contrast:** In side-by-side mode both original and modified models are set on real ICodeEditor instances, incrementing `_attachedEditorCount` and enabling the semantic-tokens fetch, matching the reporter's observation that side-by-side is correctly colored.
