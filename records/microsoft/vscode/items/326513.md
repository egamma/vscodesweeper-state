# Issue #326513 — Extension API to restart all language servers

[https://github.com/microsoft/vscode/issues/326513](https://github.com/microsoft/vscode/issues/326513)

## Summary

A real API gap remains: VS Code exposes language-feature providers but no generic language-server lifecycle API. Route this feature request to the API area for reconsideration in the context of worktree-based agent workflows.

## Change summary

Allow extensions to restart all active language servers without reloading the window and interrupting agent sessions.

## Best solution

API owners should evaluate a scoped lifecycle protocol through which language extensions can participate in restart or workspace-repoint operations, rather than letting one extension terminate opaque servers directly. The design should preserve active agent sessions and define behavior for extensions that do not support restarting.

## Evidence

- **current API gap:** The public `languages` namespace in `src/vscode-dts/vscode.d.ts` exposes language enumeration, diagnostics, status items, and provider registration, but no language-server restart or lifecycle API.
- **server-specific precedent:** `extensions/typescript-language-features/src/commands/restartTsServer.ts` implements `typescript.restartTsServer` by directly restarting its own service client, confirming that restart ownership currently remains with each language extension.
- **earlier decision:** https://github.com/microsoft/vscode/issues/76405 requested the same generic capability and was closed after the LSP client library gained `client.restart()` for each extension to expose its own command; that does not let a separate worktree extension restart all clients.
- **canonical search:** Repository issue searches found no open canonical request covering a generic restart-all-language-servers API; https://github.com/microsoft/vscode/issues/315803 is a narrower C++ language-feature failure in an Agents window worktree.
