## Summary

The DocumentMissingInHistoryContext error persists on current main (line 631 of nextEditProvider.ts) and has been hitting ~69K+ users across multiple stable releases since v0.45.1. Root cause identified but no fix has landed.

## Change summary

The NES inline-completion provider throws an unhandled error when a document referenced in the edit history context is not found in the internal FifoSet cache.

## Best solution

Guard the fetchNextEdit path in nextEditProvider.ts to handle the missing-document case gracefully (e.g. return a non-throwing NoNextEditReason instead of Unexpected) so that documents evicted from the 50-entry FifoSet don't surface as unhandled errors. The culprit commit b05f3679 (PR #310969) changed speculative request lifecycle timing; the fix should ensure history context is refreshed or the missing-doc case is treated as a recoverable skip rather than an unexpected error.
