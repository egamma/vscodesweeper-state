# Issue #325069 — Custom chat model settings collide when multiple providers expose the same model id

[https://github.com/microsoft/vscode/issues/325069](https://github.com/microsoft/vscode/issues/325069)

## Summary

The bug report is plausible — model settings are keyed by `model.metadata.id` within provider groups, and when multiple providers define models with the same id, collisions can occur depending on how settings are persisted and looked up. Two open PRs already address this; the issue should stay open until one lands.

## Change summary

Custom chat model per-model settings (e.g. reasoningEffort) collide when multiple BYOK providers define models with the same id string.

## Best solution

Land one of the two open fix PRs (https://github.com/microsoft/vscode/pull/325153 or https://github.com/microsoft/vscode/pull/325154) that scope model settings by a provider-qualified key rather than bare model id. Review both and pick the approach that best fits the data model.
