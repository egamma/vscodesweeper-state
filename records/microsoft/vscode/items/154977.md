# Issue #154977 — onDidChangeTextEditorVisibleRanges shows strange behaviour!

[https://github.com/microsoft/vscode/issues/154977](https://github.com/microsoft/vscode/issues/154977)

## Summary

Verified duplicate: the open canonical issue tracks the same editor-model restoration timing and explicitly records the identical missing visible-range event when switching to a tab positioned at the top of a file.

## Change summary

Make visible-range notifications report only the restored viewport when opening or switching editors, without omitting the event at the top of a file or emitting a preliminary incorrect range.

## Best solution

Consolidate the editor-model restoration work in https://github.com/microsoft/vscode/issues/114047 so selections and visible ranges are synchronized only after the restored editor state is available.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/114047 is open and tracks extension-host editor state being synchronized before the workbench restores the selection and viewport. Its discussion explicitly reports that onDidChangeTextEditorVisibleRanges is absent when switching to a tab at the top of a file but fires when the restored viewport is elsewhere.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/114047#issuecomment-757695664 identifies the shared cause: one editor instance receives different models, and the API is synchronized before the saved editor state is restored.
- **current source:** src/vs/workbench/api/browser/mainThreadEditor.ts still calls MainThreadTextEditor._updatePropertiesNow immediately from setCodeEditor, then updates visible ranges again from onDidLayoutChange and onDidScrollChange. MainThreadTextEditorProperties.generateDelta emits only when ranges differ, explaining both the omitted top-of-file event and the preliminary-plus-restored pair.
- **extension-host delivery:** src/vs/workbench/api/browser/mainThreadDocumentsAndEditors.ts sends initial visibleRanges as editor-add state, while src/vs/workbench/api/common/extHostTextEditors.ts fires onDidChangeTextEditorVisibleRanges only for later property deltas. This matches the report's newly-opened-editor and tab-switch cases.
- **unique report evidence:** This report adds concrete viewport examples showing one event for a shallow restored offset, no event when the restored range equals the initial top range, and two events when restoring a deeper position; that evidence should be retained in the canonical discussion.
