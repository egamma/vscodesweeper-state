# Issue #154977 — onDidChangeTextEditorVisibleRanges shows strange behaviour!

[https://github.com/microsoft/vscode/issues/154977](https://github.com/microsoft/vscode/issues/154977)

## Summary

Still present on main: the visible-ranges change event fires inconsistently (0, 1, or 2 times) when an editor is opened or restored, depending on the memorized cursor/scroll position. No fix has been applied.

## Change summary

onDidChangeTextEditorVisibleRanges fires zero, one, or two times inconsistently when opening or switching to an editor tab, depending on cursor position and scroll restoration.

## Best solution

Normalize the visible-ranges event delivery during editor open/restore in `MainThreadTextEditor.setCodeEditor()` so extensions receive exactly one event with the final settled visible ranges, not intermediate states from cursor-reveal scrolling. The fix would likely touch `src/vs/workbench/api/browser/mainThreadEditor.ts` around the `_updatePropertiesNow` call at the end of `setCodeEditor`.
