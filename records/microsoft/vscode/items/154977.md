# Issue #154977 — onDidChangeTextEditorVisibleRanges shows strange behaviour!

[https://github.com/microsoft/vscode/issues/154977](https://github.com/microsoft/vscode/issues/154977)

## Summary

The report includes detailed scenarios, a minimal reproduction repository, confirmation across VS Code 1.68–1.69.1, and evidence of impact on multiple extensions. It should remain open because no fixing commit, merged PR, or verified canonical issue is identified.

## Change summary

The `onDidChangeTextEditorVisibleRanges` API omits or emits transient/duplicate range-change events when opening editors or switching tabs with restored cursor and scroll state.

## Best solution

Define and enforce stable event semantics during editor opening and view-state restoration: extensions should receive the final visible ranges without needing to debounce transient ranges, with regression coverage in the editor API integration tests.

The event must not be omitted merely because the final range begins near the top of the document, and extensions should not need timing-based debouncing to discard an incorrect transient range. Existing notifications for ordinary mouse and keyboard scrolling must remain unchanged.
