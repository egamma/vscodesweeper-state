# Issue #186067 — Terminal revive is storing sessions where nothing occurs

[https://github.com/microsoft/vscode/issues/186067](https://github.com/microsoft/vscode/issues/186067)

## Summary

Still reproduces on main: `serializeTerminalState` stores terminals whose only interaction was a replay (no user input), because `hasWrittenData` returns true for `InteractionState.ReplayOnly`. The fix is localized to the serialization check in ptyService.ts.

## Change summary

Terminal revive stores sessions that have only been replayed but never received actual user input, wasting storage and cluttering revive.

## Best solution

Change the `serializeTerminalState` gate at line 234 of `src/vs/platform/terminal/node/ptyService.ts` to only serialize terminals with `InteractionState.Session` (actual user input), not `ReplayOnly`. The existing `InteractionState` enum already distinguishes these cases; the serialization path just doesn't use the distinction.
