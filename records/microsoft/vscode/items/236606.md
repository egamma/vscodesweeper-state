# Issue #236606 — Automatically adjust minimap scale according to display scale

[https://github.com/microsoft/vscode/issues/236606](https://github.com/microsoft/vscode/issues/236606)

## Summary

The minimap scale computation in editorOptions.ts already accounts for pixelRatio (doubling scale when >= 2), but it does not produce a visually consistent minimap size across displays with different DPI — the user-configured scale is a single static integer. This is a real gap for multi-monitor setups with mixed scaling.

## Change summary

The minimap does not automatically adjust its visual size to match the display scale, causing it to appear too small on high-DPI displays or too large on standard displays when moving windows.

## Best solution

Adjust the minimap scale computation in `src/vs/editor/common/config/editorOptions.ts` (around line 2749) so the rendered minimap has a consistent physical size regardless of display DPI. This likely means computing a continuous scale factor from pixelRatio rather than applying a coarse integer doubling. The existing `editor.minimap.scale` setting should remain as a user override on top of the auto-adjusted base. Reference issue https://github.com/microsoft/vscode/issues/84168 for non-integer scale support.

## Evidence

- **scale computation:** src/vs/editor/common/config/editorOptions.ts line 2749: `let minimapScale = (pixelRatio >= 2 ? Math.round(input.minimap.scale * 2) : input.minimap.scale);` — this doubles the scale for HiDPI but doesn't produce consistent physical size across different DPI values (e.g. 175% vs 100%).
- **pixelRatio is dynamic:** The minimap does receive `pixelRatio` from `EditorOption.pixelRatio` which updates when a window moves between displays, but the scale adjustment is a coarse integer operation that doesn't normalize for consistent physical size.
- **related issue:** https://github.com/microsoft/vscode/issues/84168 tracks non-integer minimap scale support, which is related but distinct (that issue is about the setting itself, this is about automatic per-display adjustment).
