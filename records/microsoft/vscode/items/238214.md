# Issue #238214 — Jupyter Notebook: Affordance to display cell output of long cells

[https://github.com/microsoft/vscode/issues/238214](https://github.com/microsoft/vscode/issues/238214)

## Summary

Keep open: current main has a privately gated output-preview editor, but not a generally exposed affordance for monitoring output while editing a cell taller than the viewport. The discussion confirms demand, and the related output-pane proposals do not establish a qualifying duplicate under the re-review rules.

## Change summary

Make a long notebook cell's output visible while editing its code without scrolling to the cell's bottom.

## Best solution

Provide a discoverable way to monitor the active cell's output while its code remains visible, building on the existing notebook output-preview work where appropriate. Coordinate with the separate-output-view work without treating its private preview action as completion of this usability request.

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/controller/cellOutputActions.ts`, `src/vs/workbench/contrib/notebook/browser/outputEditor/notebookOutputEditor.ts`, `src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts`
- **Validation:** In a notebook, create a code cell taller than the viewport with visible text or plot output. While editing near its top and middle, invoke the agreed affordance without scrolling to the bottom; verify that code and output can be viewed together, then rerun the cell and check the agreed output-update behavior. Confirm ordinary inline output remains unchanged.
- **Behavior:**

  > Users editing a notebook cell taller than the viewport should be able to view its output without scrolling away from the code they are editing. The affordance must be discoverable from that editing context. Acceptance should cover text and rich output, continued code editing, and the agreed behavior when the cell is rerun. Existing inline notebook output should remain available.
- **Trace:**

  > src/vs/workbench/contrib/notebook/browser/controller/cellOutputActions.ts already registers notebook.cellOutput.openInOutputPreview and opens an output URI with openToSide: true. Its menu contribution is restricted to the output toolbar behind config.notebook.output.openInPreviewEditor.enabled, and it is not exposed through F1. NotebookOutputEditor.setInput in src/vs/workbench/contrib/notebook/browser/outputEditor/notebookOutputEditor.ts resolves and renders a selected cell output in a separate editor. The remaining uncertainty concerns the intended editing-context affordance and whether the displayed output stays pinned or follows the active cell; source inspection alone does not settle those product choices. Coordinate with https://github.com/microsoft/vscode/issues/247965 and https://github.com/microsoft/vscode/issues/143244, preserving normal inline output and avoiding unrelated supplementary-pane features.
- **Open decisions:**
  - Should the supported affordance expose the existing side-by-side output editor from the code-editing context, or keep output visible within the notebook viewport?
  - Should the output display stay pinned to the selected cell or follow the active cell, and should rerunning that cell automatically replace the displayed result?
