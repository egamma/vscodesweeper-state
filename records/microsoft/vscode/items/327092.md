## Evidence

- **Current source confirms the silent path:** In extensions/git/src/cloneManager.ts, CloneManager.clone routes cache hits to tryOpenExistingRepository. For the ordinary command, that method checks folder.workspacePath rather than folder.repositoryPath. If the parent workspace folder survives deletion of the clone, the entry passes validation; matchingInCurrentWorkspace then returns immediately without a destination picker, git clone, or notification.
- **Persistent workspace association:** extensions/git/src/repositoryCache.ts stores repositoryPath separately from workspacePath. RepositoryCache._findWorkspaceForRepo can associate a clone with its containing folder or a .code-workspace file, and save/load persist that association under git.repositoryCache. This explains why deleting the clone and reloading or restarting need not remove the cache hit.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/327198 was verified OPEN with mergedAt null and explicitly states Fixes #327092. Its proposed changes validate repositoryPath, prune stale entries, and fall through to cloning; the PR also lists manual verification as outstanding. It is not a landed fix and precludes a competing agent implementation.
- **Independent confirmations:** The supplied discussion on https://github.com/microsoft/vscode/issues/327092 includes phoehnel confirming the failure on 1.129.1 and contributory reporting recurrence. The reporter supplies deletion-and-reclone steps and reports the same behavior in Stable and Insiders.
- **Older related report, not a verified duplicate:** Canonical search found https://github.com/microsoft/vscode/issues/319084, verified open and created 2026-05-30. It describes Git: Clone reopening the deleted clone's parent folder, with a later Windows confirmation. This is consistent with the same cache-validation defect but differs from this item's silent no-op in the current workspace, so it does not meet the stricter same-observable-symptom bar for a re-reviewed duplicate close.
