## Summary

The localization-sensitive cache collision has been fixed on current main by giving each extension scan language a separate manifest cache file. This prevents differently localized scans from overwriting one another and triggering the false “modified on disk” notification.

## Change summary

Prevent localized built-in extension manifests from falsely triggering the extension-modified-on-disk reload notification.

- **confirmed trigger:** Three reporters observed the problem with German, Japanese, and zh-CN localization. The detailed log analysis at https://github.com/microsoft/vscode/issues/316256#issuecomment-5086650661 found that the cached English github.copilot-chat manifest differed only in localized strings from the fresh zh-CN scan; the maintainer accepted this diagnosis at https://github.com/microsoft/vscode/issues/316256#issuecomment-5177976338.
- **fix commit:** https://github.com/microsoft/vscode/commit/47aa3e984d2936482e055341852b70b95de94b89 fixes the collision: `getManifestCacheFileName` in `src/vs/platform/extensions/common/extensions.ts` now derives distinct cache filenames from the scan language, and `CachedExtensionsScanner.getCacheFile` in `src/vs/platform/extensionManagement/common/extensionsScannerService.ts` passes `input.language`.
- **trigger and changed outcome:** Previously, the window's localized scan and the shared process's unlocalized scan wrote the same cache file, so validation could compare manifests with different localized strings and fire `onDidChangeCache`, which `src/vs/workbench/services/extensions/electron-browser/cachedExtensionScanner.ts` turns into the reported notification. The cited diff separates those cache files and validates each language-specific entry independently.
- **regression coverage:** The fixing commit adds tests in `src/vs/platform/extensionManagement/test/node/extensionsScannerService.test.ts` asserting that system-extension scans create separate cache files per language and that a scan is served only from the cache for the same language.
- **related issue is distinct:** https://github.com/microsoft/vscode/issues/245986 concerns extension payloads being deleted while still referenced by custom profiles and `.obsolete`; it does not own this localization-driven manifest-cache notification.
