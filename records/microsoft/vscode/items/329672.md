# Issue #329672 — VS Code restores invalid window/maximize state on GNOME Wayland; XWayland works correctly

[https://github.com/microsoft/vscode/issues/329672](https://github.com/microsoft/vscode/issues/329672)

## Summary

Fresh, well-documented report with a clear, isolated repro (Wayland vs XWayland comparison, dock toggle side-effect) and no duplicate found; VS Code's window-restore logic depends on absolute cross-monitor x/y coordinates, which core Wayland does not expose to clients — this looks like an Electron/Ozone-Wayland platform limitation rather than a VS Code logic bug, so it stays open pending upstream/maintainer investigation.

## Change summary

On GNOME Wayland (multi-monitor), VS Code restores the wrong display, wrong size/position, and an initially non-functional maximize button; forcing `--ozone-platform=x11` fully fixes it.

## Best solution

Investigate whether Electron's Ozone/Wayland backend can be made to report/restore absolute window bounds and maximize state correctly on multi-monitor GNOME sessions (likely tracked against Electron upstream or requiring Wayland-specific handling in src/vs/platform/windows/electron-main/windowsStateHandler.ts and windowImpl.ts); if it's a hard Wayland protocol limitation, document the `--ozone-platform=x11` workaround for affected users.
