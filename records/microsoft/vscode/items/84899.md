# Issue #84899 — SCM - Make registerDiffInformationCommand public

[https://github.com/microsoft/vscode/issues/84899](https://github.com/microsoft/vscode/issues/84899)

## Summary

The stable extension-API gap remains: both the original command and its editor-attached successor are still proposed APIs. Keep this accepted Backlog request open for API-owner design and finalization, rather than publishing the original form against the maintainer's stated direction.

## Change summary

Expose stable diff information so SCM extensions can implement selected-range actions such as reverting individual changes.

## Best solution

Finalize an editor-attached diff-information API that supports third-party SCM selected-range workflows. Preserve the maintainer's direction away from making registerDiffInformationCommand public in its existing form.

- **Behavior:**

  > SCM extensions need stable access to diff ranges to provide actions such as reverting an individual change, without relying on proposed API permissions. The requested capability is not limited to Git and should support the ordinary-editor quick-diff workflow described in the discussion. Acceptance should demonstrate a non-proposed test extension receiving accurate, updated ranges and reverting a selected change without altering unrelated changes.
- **Trace:**

  > The original registerDiffInformationCommand remains declared in src/vscode-dts/vscode.proposed.diffCommand.d.ts and proposal-gated in src/vs/workbench/api/common/extHost.api.impl.ts. The maintainer direction at https://github.com/microsoft/vscode/issues/84899#issuecomment-554901223 is editor-attached diff information instead of stabilizing that original command. The successor declarations in src/vscode-dts/vscode.proposed.textEditorDiffInformation.d.ts already reference this issue, while MainThreadTextEditors._getTextEditorDiffInformation in src/vs/workbench/api/browser/mainThreadEditors.ts supplies ordinary-editor quick-diff results and diff-editor information. ExtHostTextEditor exposes those results through diffInformation. The remaining uncertainty is the stable public contract, not whether an internal diff pipeline exists. Preserve provider-independent SCM behavior and existing built-in selected-range actions; do not turn this into a provider-specific revert implementation. https://github.com/microsoft/vscode/pull/182039 was closed unmerged and does not resolve finalization.
- **Open decisions:**
  - Which editor-attached diff-information surface should become stable, and should the resource-based createSourceControlDiffInformation API be included in that finalization?
  - What guarantees should the stable API make about multiple SCM baselines, range coordinates, and unavailable or stale results so extensions can safely act on selected changes?
