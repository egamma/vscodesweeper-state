# Issue #234941 — Git - Built-in Git extension does not respect `includeIf` in a symbolic link directory

[https://github.com/microsoft/vscode/issues/234941](https://github.com/microsoft/vscode/issues/234941)

## Summary

The current Git subprocess path preserves the symlink as cwd but does not synchronize the logical PWD environment variable, leaving a source-reproducible failure when conditional configuration matches only the symlink. Keep this accepted Git bug open; no verified fix or canonical duplicate was found.

## Change summary

Make built-in Git operations honor gitdir-based conditional configuration when a repository is opened through a directory symlink.

## Best solution

Git operations launched from the symlinked repository should resolve the same conditional identity configuration as a shell operating in that logical directory, while preserving Git's identity checks and existing behavior for ordinary repositories.

- **Conditional-include mechanism:** https://github.com/git/git/blob/v2.47.1/config.c#L244-L300 shows include_by_gitdir first matching the physical path and then retrying strbuf_add_absolute_path. https://github.com/git/git/blob/v2.47.1/abspath.c#L293-L316 shows that the retry preserves a symlink spelling only when PWD identifies the current directory; otherwise it uses physical getcwd. This explains why merely passing the alias as Node's subprocess cwd does not preserve the reporter's includeIf match.
- **Identity safety is not the defect:** extensions/git/src/git.ts:2136-2142 deliberately adds user.useConfigOnly=true before committing.
