# Issue #339623 — Agent host: SessionCustomizationDiscovery retries agents/skills discovery endlessly for sessions whose worktree was deleted

[https://github.com/microsoft/vscode/issues/339623](https://github.com/microsoft/vscode/issues/339623)

## Summary

Fresh, well-diagnosed, team-authored (MEMBER) bug report with no fix on main yet — the hard keep-open rule for team-authored issues applies, and there is no citable fix commit or canonical duplicate to justify any close.

## Change summary

SessionCustomizationDiscovery re-runs agents/skills discovery on every file-change event for a session whose git worktree has been deleted, failing every time with 'Invalid working directory' and never stopping, flooding agenthost.log and sending repeated RPCs to copilot-runtime.

## Best solution

In src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts, debounce/coalesce _scheduleRefresh (currently fires _onDidChange synchronously per matching file event with no coalescing) and short-circuit discover() when a working directory no longer exists on disk, caching that state so repeated file-change bursts don't re-trigger the RPC, with failures logged once instead of per attempt.

## Plan brief

- **Validation:** A test that simulates a deleted working directory (IFileService stat/exists reporting absence) and asserts discover()/the agents/skills RPC is not re-issued on repeated onDidFilesChange events, plus a debounce test asserting a burst of file-change events within a short window produces only one discovery pass.
- **Behavior:**

  > For a session whose primary working directory (a git worktree) has been deleted, discovery must stop issuing repeated agents.discover/skills.discover RPCs and stop logging an error on every retry; a single failure (or a single existence check) should be enough, with at most one log entry per session rather than one per attempt. A burst of file-change events from an active agent should also not produce a burst of discovery passes for sessions whose working directory is still valid. Acceptance: the two validations above pass, and existing discovery behavior for valid working directories is unchanged.
- **Trace:**

  > Traced in src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts: the constructor's onDidFilesChange listener calls _scheduleRefresh() synchronously for any matching file event, and _scheduleRefresh() just fires _onDidChange with no debounce; discover() and the private discovery path build projectPaths directly from _workingDirectories without checking the paths still exist, so every subsequent RPC fails with 'Invalid working directory' and is logged and swallowed, re-arming on the next file event. The boundary: do not change discovery behavior for sessions with valid working directories, and do not alter the existing per-root project-path mapping (_rootForProjectPath, _containingWorkspaceRoot) used elsewhere in the file. Where the uncertainty starts: whether a missing working directory should permanently disable discovery for the life of the session object, or be re-armed if the directory reappears (e.g. via a parent-folder watcher, as the reporter suggests as one option) — and what debounce/coalescing window is appropriate for _scheduleRefresh.
- **Open decisions:**
  - Should discovery permanently stop for a session once its working directory is found missing, or should it watch for the directory reappearing (e.g. via a parent-folder watcher) and resume?
  - What debounce/coalescing interval (or strategy) should _scheduleRefresh use to avoid a burst of file-change events producing a burst of discovery passes?
