# Issue #318347 — chat.tools.terminal.autoApprove (and related terminal tool auto-approval) does not match inner commands when the command line uses common wrappers (timeout, bash -c, env, sudo time, etc.)

[https://github.com/microsoft/vscode/issues/318347](https://github.com/microsoft/vscode/issues/318347)

## Summary

Confirmed on current main: the auto-approve path uses `TreeSitterCommandParser.extractSubCommands` which returns outermost tree-sitter `(command)` nodes, never unwrapping common wrapper programs. The existing wrapper-stripping logic in `terminalCommandParser.ts` (`stripPrefixesAndWrappers`) is not used by the auto-approve analyzer, so inner commands like `git` inside `timeout 30 bash -c '… git …'` are invisible to deny/allow rules. Additionally, as the commenter notes, this means wrapping a denied command bypasses the deny list — a security-relevant gap.

## Change summary

Terminal auto-approve rules only match the outermost command, not the effective inner command behind common wrappers like `timeout`, `bash -c`, `env`, or `sudo`.

## Best solution

Integrate the existing `stripPrefixesAndWrappers` / `parseCommand` logic from `terminalCommandParser.ts` into `CommandLineAutoApproveAnalyzer.analyze()` so that each sub-command returned by tree-sitter is also unwrapped to its effective inner command before rule matching. Deny rules must be checked against both the outer and inner commands (fail closed). The `neverAutoApproveCommands` guard and `transientEnvVarRegex` checks must remain.
