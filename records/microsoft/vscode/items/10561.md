# Issue #10561 — Execute functions during snippet expansion

[https://github.com/microsoft/vscode/issues/10561](https://github.com/microsoft/vscode/issues/10561)

## Summary

A real API gap remains: extensions can generate snippet completions, but those snippets do not participate consistently in Insert Snippet and snippet-only tab completion. This team-authored Backlog request also has 70 community upvotes, so it should remain open.

## Change summary

Allow snippets to generate context-dependent text or execute extension logic during expansion while retaining the standard snippet invocation experience.

## Best solution

Design an extension-facing dynamic snippet mechanism that works consistently across suggestions, Insert Snippet, selections, and snippet-only tab completion, while accounting for the extension host's asynchronous process boundary. Keep this issue as the canonical design request rather than treating completion items as complete coverage.

## Evidence

- **partial existing capability:** src/vscode-dts/vscode.d.ts exposes CompletionItem.insertText as a SnippetString and CompletionItem.command for post-insertion work, so extensions can dynamically generate snippet completions.
- **remaining surface gap:** src/vs/workbench/contrib/snippets/browser/commands/insertSnippet.ts obtains entries exclusively from ISnippetsService, while src/vs/workbench/contrib/snippets/browser/tabCompletion.ts uses ISnippetsService.getSnippetsSync; extension-provided completion items are not integrated into those snippet surfaces.
- **resolver limitation:** src/vs/editor/contrib/snippet/browser/snippetSession.ts constructs CompositeSnippetVariableResolver from fixed core resolvers only; current main exposes no extension-contributed resolver in this expansion path.
- **architecture constraint:** In https://github.com/microsoft/vscode/issues/130325, a maintainer explained that extension resolvers are asynchronous because extensions run in another process, while snippet-only tab completion currently requires synchronous resolution.
- **related request distinction:** https://github.com/microsoft/vscode/issues/63534 remains open but only tracks global or project-level static variables; it does not absorb executing extension logic or preserving a consistent dynamic-snippet experience.
