# Issue #134322 — Git - git setting `core.excludesFile` is ignored if placed inside an include.path of ~/.gitconfig

[https://github.com/microsoft/vscode/issues/134322](https://github.com/microsoft/vscode/issues/134322)

## Summary

Keep open and classify as upstream: VS Code delegates global-ignore discovery to ripgrep, whose Git configuration parser still does not follow includes. The linked upstream report was closed as a duplicate, not fixed.

## Change summary

Search should honor core.excludesFile defined in a file included by ~/.gitconfig when search.useGlobalIgnoreFiles is enabled.

## Best solution

Resolve included Git configuration in ripgrep's global-ignore discovery and adopt that behavior in VS Code's bundled search engine, preserving ignore precedence. Until then, retain this report as the VS Code-facing record of the limitation.

The reporter's follow-up identifies ripgrep, and https://github.com/BurntSushi/ripgrep/issues/2062 records reproduction with standalone ripgrep.
- **Current VS Code search path:** src/vs/workbench/services/search/node/ripgrepTextSearchEngine.ts invokes the bundled ripgrep through cp.spawn; lines 503–505 only disable global ignores when useIgnoreFiles.global is false. src/vs/workbench/services/search/node/ripgrepFileSearch.ts likewise delegates discovery to ripgrep and conditionally adds --no-ignore-global. Neither path resolves included Git configuration itself.

- **Related issue and canonical search:** https://github.com/microsoft/vscode/issues/59364 concerns enabling global ignore support generally, not resolving included configuration, and is closed.
