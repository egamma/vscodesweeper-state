# Issue #246652 — AbstractContextKeyService has been disposed

[https://github.com/microsoft/vscode/issues/246652](https://github.com/microsoft/vscode/issues/246652)

## Summary

Still an active, high-impact bug on current main. The fix in 16f1ebc90d2 (clearing parent change listener before disposal) addressed one race, but the error continues to hit ~49,800 stable users and was reported again in 1.116.0 via #310777. The diff-editor gutter path in gutterFeature.ts line 60 — an `observableFromEvent` on `_menu.onDidChange` calling `getActions()` — can still fire after the scoped context key service is disposed during teardown.

## Change summary

DiffEditorGutter's menu observable fires after its scoped ContextKeyService is disposed, causing an unhandled error for tens of thousands of users.

## Best solution

The root cause is that `observableFromEvent(this, this._menu.onDidChange, () => this._menu.getActions())` in `gutterFeature.ts:60` evaluates menu actions (which calls `contextMatchesRules`) after the scoped context key service has been disposed. The fix should ensure the observable subscription is torn down before the context key service disposes, or the menu service should guard against disposed context key services without throwing. This likely needs a coordinated fix across gutterFeature.ts and possibly menuService.ts or contextKeyService.ts to handle the disposal ordering.
