# Issue #349952 — Sign in blocks the whole window

[https://github.com/microsoft/vscode/issues/349952](https://github.com/microsoft/vscode/issues/349952)

## Summary

Keep open: integrated-browser sign-in currently uses a window-modal dialog. Restricting it to the browser surface remains a distinct UX improvement, not something the existing visibility handling delivers.

## Change summary

Scope HTTP sign-in prompts to the integrated browser so users can navigate away or interact with agents without answering first.

## Best solution

Allow pending browser sign-in to coexist with interaction elsewhere in the window, while preserving credential submission, cancellation, and browser-host lifecycle behavior. The browser area owner should decide the presentation and navigation semantics before implementation.

## Evidence

- **Current presentation:** src/vs/workbench/contrib/browserView/electron-browser/browserDialogs.ts: BrowserDialogs.show() presents login requests through IDialogService.input({ custom: true, ... }), with username and password inputs. There is no browser-local presentation option on this path.
- **Existing capability boundary:** BrowserDialogs.setVisible() and setModel() control whether a pending dialog is presented and cancel its presentation when the host changes. This does not let users interact outside an already-open window-modal prompt; the inspected browser configuration and command registrations expose no setting that provides the requested scope.
- **Referenced test context:** https://github.com/microsoft/vscode/issues/349584 explicitly exercises HTTP Basic sign-in using https://httpbin.org/basic-auth/user/passwd. Its implementation, https://github.com/microsoft/vscode/pull/349555, is merged and adds sign-in and hidden-page dialog handling, but does not establish browser-local modality.
- **Related but distinct report:** https://github.com/microsoft/vscode/issues/349848 is open and concerns delayed dialogs appearing while the browser editor group is hidden. That visibility defect does not own this request to keep unrelated window interactions available while a visible browser requests sign-in.
