# Issue #345470 — URI with `windowId=1` is routed to window 10: the URL handler router matches the window id as a prefix

[https://github.com/microsoft/vscode/issues/345470](https://github.com/microsoft/vscode/issues/345470)

## Summary

The reported window-ID prefix collision remains in current main and can deliver callbacks to the wrong window. Keep this open for human review, including the security implications of misrouting OAuth callbacks.

## Change summary

Route app-scheme callbacks to the exact window identified by windowId rather than another window whose ID shares that prefix.

## Best solution

Ensure URLHandlerRouter selects only the intended window connection while preserving existing fallback behavior when no matching connection exists. Have a maintainer assess the authentication-callback implications alongside the routing correction.
