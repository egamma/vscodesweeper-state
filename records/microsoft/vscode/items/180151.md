# Issue #180151 — Git - Git smart commit commits also sub-repositories, which are normally ignored

[https://github.com/microsoft/vscode/issues/180151](https://github.com/microsoft/vscode/issues/180151)

## Summary

The reported mismatch remains in current source: smart commit stages the entire repository, including nested repositories deliberately omitted from the SCM changes list. Keep this accepted Backlog bug open; its cause and validation boundary are sufficiently concrete for an implementation session.

## Change summary

Smart commit unexpectedly records an untracked nested repository in the parent commit even though Stage All excludes it.

## Best solution

Make smart commit include the same eligible changes as Stage All, leaving undisplayed untracked nested repositories outside the parent commit. Preserve ordinary untracked-file inclusion in all mode, tracked-only behavior, and existing staged-submodule behavior.

- **Intentional SCM exclusion:** extensions/git/src/git.ts:884-887 explicitly excludes status entries whose paths end with '/', with the comment that these represent nested Git repositories. Consequently the nested repository is absent from the parent's resource groups.
- **Exact failing source path:** extensions/git/src/commands.ts:2456-2458 sets opts.all when smart commit is enabled and the index is empty; line 2573 passes those options to Repository.commit. extensions/git/src/repository.ts:1463-1466 calls this.repository.add([], addOpts) for all-mode commits. extensions/git/src/git.ts:1975-1990 translates that empty path list into git add -A -- ., which stages the untracked embedded repository as a gitlink before committing.
- **Stage All behaves differently:** extensions/git/src/commands.ts:1584-1592 builds explicit paths from workingTreeGroup and untrackedGroup and adds only those paths. The nested repository filtered by GitStatusParser never enters this list, explaining the reporter's observable difference.

These avoid adding the nested repository but also exclude ordinary untracked files, so they do not satisfy the requested all-mode behavior.
