# Issue #336883 — Incremental rendering re-animates the full response when main content contains a file reference

[https://github.com/microsoft/vscode/issues/336883](https://github.com/microsoft/vscode/issues/336883)

## Summary

The defect is confirmed in the current source, and an open PR directly references this issue with a targeted fix and regression test. Keep the issue open while that human-owned fix is reviewed.

## Change summary

Streaming an inline file reference in the main chat response recreates the markdown part and replays the incremental-rendering animation over previously rendered content.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/337916, preserving the markdown part when inline-reference metadata is only extended while still forcing a full render when an existing reference changes or disappears.

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts, ChatMarkdownContentPart.tryIncrementalUpdate currently calls equalsInlineReferences and returns false when a streamed update adds an inline-reference entry, causing the existing content part to be replaced.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/337916 is open, uses `Fixes #336883`, and changes the comparison to accept additive inline-reference metadata while retaining rejection of modified or removed references.
- **confirmed reproduction:** The PR author reports reproducing the issue with the chat simulation mock server: responses containing references created three markdown parts and replayed earlier animation, while the control created one; the proposed change kept the reference case at one part.
- **regression coverage:** The open PR adds a test in src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatMarkdownContentPart.test.ts asserting that successive inline references appended during incremental updates are accepted.
