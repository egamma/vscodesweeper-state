# Issue #320237 — Dropping views into a single-view merged-header custom view container is hard to hit

[https://github.com/microsoft/vscode/issues/320237](https://github.com/microsoft/vscode/issues/320237)

## Summary

This is the same observable bug tracked by the older open issue https://github.com/microsoft/vscode/issues/144122: another view cannot be reliably dropped into a sidebar or panel containing only one webview view. The newer report contributes a precise Linux merged-header reproduction, which should be carried into the canonical issue.

## Change summary

Make a single-view merged-header custom webview container expose a reliable drop target when another view is dragged into it.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/144122 and fix the shared webview-view drop path so the entire single-view target, including its merged container header and body, reliably produces feedback and accepts the drop.
