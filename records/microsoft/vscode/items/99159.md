# Issue #99159 — Partial cross-file undo if a file is changed in the meantime

[https://github.com/microsoft/vscode/issues/99159](https://github.com/microsoft/vscode/issues/99159)

## Summary

A real gap remains on current main: when one resource blocks a workspace undo, VS Code immediately falls back to undoing only the focused file instead of offering the requested local, partial, or cancel choices. The team-authored Backlog request should remain open for undo/redo design work.

## Change summary

Offer a partial cross-file undo when some files changed after a multi-file operation, while leaving unsafe files untouched.

## Best solution

When an atomic workspace undo is no longer safe, present an explicit choice between undoing the focused file, undoing every still-safe participating file, or cancelling; preserve the existing atomic behavior when all files remain eligible.

Files whose undo position is no longer safe remain untouched, and VS Code must not perform an unannounced partial operation. When every participating file remains safe, existing all-files undo behavior is unchanged.

The existing prompt handles all-files, this-file, and cancel only for an otherwise valid workspace element.
