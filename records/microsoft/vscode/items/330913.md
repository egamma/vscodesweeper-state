# Issue #330913 — agent host: make customization resolution unskippable at publication

[https://github.com/microsoft/vscode/issues/330913](https://github.com/microsoft/vscode/issues/330913)

## Summary

Keep open: current publication helpers still rely on callers to supply resolved customizations, so the structural cleanup remains necessary. Existing call-site guards do not establish the requested unskippable invariant.

## Change summary

Make customization publication resolve scoped enablement internally rather than relying on each caller to remember resolution.

## Best solution

Publication boundaries should own enablement resolution for both whole-list and individual customization updates, preserving durable MCP identity and existing runtime metadata. Pending decisions must remain transient and fail closed at SDK handoff.
