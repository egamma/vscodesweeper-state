# Issue #121313 — Allow execution of markdown cells

[https://github.com/microsoft/vscode/issues/121313](https://github.com/microsoft/vscode/issues/121313)

## Summary

A real API gap remains on current main: notebook execution explicitly excludes markup cells, so kernels cannot opt into executing rendered Markdown cells. This team-authored design request should remain open under discussion.

## Change summary

Allow notebook controllers such as SoS kernels to declare and execute Markdown cells while retaining Markdown rendering.

## Best solution

Extend the notebook controller and execution UI so a kernel can explicitly opt into particular markup-cell languages or kinds, while preserving non-executable markup as the default. The likely design spans controller capability declaration, execution filtering, and conditional run actions.

## Evidence

- **current source:** src/vs/workbench/contrib/notebook/browser/services/notebookExecutionServiceImpl.ts filters execution candidates with `c.cellKind === CellKind.Code`, conclusively excluding markup cells on current main.
- **current UI:** src/vs/workbench/contrib/notebook/browser/controller/executeActions.ts defines `executeCondition` with `NOTEBOOK_CELL_TYPE.isEqualTo('code')`, so markup cells cannot expose the normal execution action.
- **related issue:** https://github.com/microsoft/vscode/issues/120587 remains open but requests improved treatment of non-executable annotation/code cells, which is related rather than the same executable-markup requirement.
- **closed design discussion:** https://github.com/microsoft/vscode/issues/105933 established the generalized `NotebookCellKind.Markup` model but did not add kernel execution support for markup cells.
- **discussion:** https://github.com/microsoft/vscode/issues/121313#issuecomment-820148250 confirms that changing a code cell's language to Markdown converts it into a Markdown cell, so the suggested code-cell workaround does not preserve the required rendering behavior.
