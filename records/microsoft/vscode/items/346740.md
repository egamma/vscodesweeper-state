# Issue #346740 — Agents window ignores dev.containers.dockerPath when creating Dev Container sessions with WSL Containers

[https://github.com/microsoft/vscode/issues/346740](https://github.com/microsoft/vscode/issues/346740)

## Summary

Keep open: current source confirms that Agents-window container startup ignores the configured executable and invokes Docker instead. This path belongs to VS Code core, not the Dev Containers extension; executable configuration and WSL compatibility need a maintainer decision before implementation.

## Change summary

Make Agents-window Dev Container sessions honor a configured container CLI instead of unconditionally invoking Docker.

## Best solution

Provide consistent container-executable selection across the bundled Dev Container CLI and direct container operations, preserving default Docker behavior. Settle whether the Agents window consumes dev.containers.dockerPath or exposes an equivalent core setting, then validate the reported Windows/wslc workflow without weakening sandbox checks.
