# Issue #346740 — Agents window ignores dev.containers.dockerPath when creating Dev Container sessions with WSL Containers

[https://github.com/microsoft/vscode/issues/346740](https://github.com/microsoft/vscode/issues/346740)

## Summary

The Agents window's core container launcher has no configurable Docker executable, so the requested parity remains missing. Keep this open to establish support for custom container CLIs; the Dev Containers extension being installed does not make this an extension-owned failure.

## Change summary

Allow Agents-window Dev Container sessions to use the configured container CLI instead of requiring the default docker executable.

## Best solution

Provide a supported container-CLI selection contract for the Agents-window launcher, preferably compatible with existing Dev Containers configuration. Apply that selection consistently to availability checks, configuration reads, startup, execution, and container lifecycle operations.

## Evidence

- **Reporter evidence:** https://github.com/microsoft/vscode/issues/346740 provides concrete Windows steps, a successful Editor comparison with dev.containers.dockerPath set to wslc, and Agents-window logs showing default docker invocations during read-configuration and up.
- **Core ownership and missing configuration:** src/vs/platform/agentHost/node/devContainerAgentHostService.ts:1041-1064 resolves findExecutable('docker', ...) for direct Docker operations and spawns the bundled Dev Container CLI with the supplied arguments unchanged. Searches across src and extensions found no dockerPath or --docker-path handling.
- **Startup path:** DevContainerAgentHostService._connect in src/vs/platform/agentHost/node/devContainerAgentHostService.ts:298-316 reads the configuration and invokes up without a custom Docker executable. _runDevContainer at lines 819-827 forwards those arguments to _spawnDevContainer, matching the reported log commands.
- **Existing-capability check:** src/vs/platform/agentHost/common/devContainerAgentHost.ts defines connection inputs without a container-CLI selection. src/vs/sessions/contrib/providers/remoteAgentHost/electron-browser/devContainerAgentHostConnector.contribution.ts registers enablement, worktree, samples, and idle-timeout settings, but no equivalent executable setting; initial connection and reconnection likewise forward no executable selection.
- **Classification boundary:** The current core service explicitly documents availability as resolving Docker from the shell environment. No thread comment or core configuration contract establishes support for dev.containers.dockerPath, so this is conservatively classified as a missing compatibility capability rather than a proven violation of an existing core contract.
- **Candidate is not a duplicate:** https://github.com/microsoft/vscode/issues/285463 was verified open and read in full. It requests automatic Linuxbrew Docker-path discovery and lists dev.containers.dockerPath as a working workaround; it does not own the Agents-window failure to honor an explicitly selected alternative CLI.
