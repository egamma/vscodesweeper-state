# Issue #332808 — Unwanted `.claude` folder and `.claude.json` file

[https://github.com/microsoft/vscode/issues/332808](https://github.com/microsoft/vscode/issues/332808)

## Summary

Multiple independent reporters (Linux and Windows) confirm 1.135 creates `.claude`/`.claude.json` under `$HOME` and, on Windows, launches `claude.exe` (triggering firewall prompts) without the reporters ever touching a Claude-related feature; a maintainer explained the mechanism but the 'why does this fire for users who never invoked it' question is still unresolved, so this needs area-owner follow-up rather than a close.

## Change summary

VS Code 1.135 silently creates Claude-agent-harness files/folders and, on Windows, spawns `claude.exe` (contacting Anthropic) for users who report never using any Claude/agent feature.

## Best solution

The agent-host team should confirm whether `chat.agentHost.claudeAgent.enabled` (default `true` per src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts:250) is causing eager SDK download/process spawn during startup/session discovery rather than only on explicit user action, and either gate the SDK download/exe spawn behind explicit opt-in or flip the default while the feature is experimental; the maintainer's own reply also has a likely typo (`chat.agentHost.claudeAgent.enabled: true` to *disable* it, when `false` is what actually turns it off) that should be corrected in a follow-up comment.

## Vision fit

- **Fit:** rejected
- **Reason:** An always-on external process spawn and unsolicited network contact for users who never touched the feature cuts against the value that VS Code is lightweight/fast out of the box and that the power (and its side effects) should live in opt-in extensions.
- **Evidence:** Values: "Out of the box, VS Code is a text editor: lightweight and fast" and "Performance trumps functionality" — an experimental agent harness with default-on process execution and network calls runs counter to that baseline expectation.
