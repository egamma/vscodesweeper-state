# Issue #322785 — Show total session token usage

[https://github.com/microsoft/vscode/issues/322785](https://github.com/microsoft/vscode/issues/322785)

## Summary

A real gap remains: the context-usage popover shows session cost and the latest response's context-window consumption, but not cumulative session token usage. This team-authored feature request should remain open for a small product decision about incomplete provider data before implementation.

## Change summary

Show cumulative token usage for the current chat session alongside session cost in the context-usage details.

## Best solution

Add a distinct Session Info token total derived from the existing session usage aggregation, while preserving the Context Window section as the latest request's current-context measurement. Decide whether providers lacking complete whole-turn totals should show a clearly marked partial estimate or omit the session total.

- **Behavior:**

  > The Session Info area should show total token usage accumulated across completed responses in the current chat session, alongside Session Cost. It must update as additional responses complete and when restored usage becomes available. The existing Context Window count, percentage, reserve, and warning must remain scoped to the latest response rather than becoming cumulative. Acceptance tests must cover multiple responses and the selected presentation for sessions whose providers report only partial token data.
- **Trace:**

  > ChatInputPart.updateContextUsageWidget in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts currently gives ChatContextUsageWidget only model.lastRequest and separately refreshes model.sessionCost. ChatContextUsageWidget.updateFromResponse in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts derives usedTokens from that response, and ChatContextUsageDetails renders those values under Context Window. aggregateChatUsage in src/vs/workbench/contrib/chat/common/chatUsage.ts already aggregates all response usages, preserves per-model totals, and exposes isComplete when fallback prompt/completion counts are only partial. The implementation boundary is the session summary and context-usage presentation; do not change context-window occupancy semantics, request accounting, or billing calculations. The related billing meta at https://github.com/microsoft/vscode/issues/319403 supplies context but does not own this exact UI request.
- **Open decisions:**
  - When one or more responses lack authoritative whole-turn model totals, should Session Info show the available aggregate explicitly labeled as partial, or hide total token usage until a complete value is available?
