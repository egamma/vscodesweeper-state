# Issue #333337 — [WSL] VS Code 1.135.0 causes wsl.exe to consume one full CPU core after connecting to WSL

[https://github.com/microsoft/vscode/issues/333337](https://github.com/microsoft/vscode/issues/333337)

## Summary

Credible regression report affecting the Remote-WSL extension (wsl.exe pegs a CPU core after connecting in 1.135.0), corroborated by two other users; since Remote-WSL is a VS Code-team-owned extension, this belongs in its own tracker rather than microsoft/vscode, so I'm proposing a route (move), not a close.

## Change summary

After upgrading to VS Code 1.135.0, connecting to a WSL distro leaves a wsl.exe process pinned at ~100% CPU until the Remote-WSL session is disconnected; 1.134.0 does not reproduce it.

## Best solution

Move this to microsoft/vscode-remote-release, where Remote-WSL issues are tracked; a maintainer there can bisect the 1.134.0→1.135.0 regression in the WSL connection/server-startup path (wslServer.sh invocation) — one commenter's workaround (deleting .vscode-server to force a clean re-provision) is a useful lead for the investigation.
