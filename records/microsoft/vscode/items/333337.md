# Issue #333337 — [WSL] VS Code 1.135.0 causes wsl.exe to consume one full CPU core after connecting to WSL

[https://github.com/microsoft/vscode/issues/333337](https://github.com/microsoft/vscode/issues/333337)

## Summary

Well-documented regression, but the offending process (`wsl.exe ... scripts/wslServer.sh`) is spawned and driven entirely by the Remote-WSL extension (ms-vscode-remote.remote-wsl), whose code and issue tracking live outside this repo at microsoft/vscode-remote-release — this belongs there rather than being closed-and-refiled by the reporter.

## Change summary

After upgrading to VS Code 1.135.0, connecting Remote-WSL leaves one `wsl.exe` process pegging a full CPU core until the session is disconnected; 1.134.0 does not reproduce it.

## Best solution

Move this issue to microsoft/vscode-remote-release, where the Remote-WSL extension's connection/startup script (wslServer.sh) is maintained, so the extension team can bisect the 1.134.0→1.135.0 regression (the reporter kept the extension version constant across both, so the core-vs-extension interaction should be investigated there).
