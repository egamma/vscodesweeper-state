# Issue #307985 — Plugin agent discovery: support filesystem-based auto-discovery of .agent.md files

[https://github.com/microsoft/vscode/issues/307985](https://github.com/microsoft/vscode/issues/307985)

## Summary

The requested filesystem-based auto-discovery is already implemented: when the `agents` field is absent from `plugin.json`, the system automatically scans the default `agents/` directory for `.md` files. The reporter's reproduction steps (omit `agents` from manifest, place an agent file under `agents/`) should work on current main.

## Change summary

Request to auto-discover `.agent.md` files under the `agents/` directory when the `agents` field is omitted from `plugin.json`.

## Best solution

Close as already implemented. The `observeComponent('agents', ...)` path in `agentPluginServiceImpl.ts` uses `parseComponentPathConfig` which, for a missing manifest field, returns `{ paths: [], exclusive: false }`, and `resolveComponentDirs` always includes the default `agents/` subdirectory when `exclusive` is false. `readMarkdownComponents` then scans that directory for `.md` files. One nuance: the scan is non-recursive (only direct children of `agents/`), so `agents/my-agent/my-agent.agent.md` in a nested subdirectory would not be found — but direct `.md` files in `agents/` are discovered without any manifest entry. If the reporter specifically needs recursive or nested-directory scanning, that would be a separate, narrower feature request.
