# Issue #348293 — Git: Warn before amending a commit that has already been pushed

[https://github.com/microsoft/vscode/issues/348293](https://github.com/microsoft/vscode/issues/348293)

## Summary

Keep open: the Git maintainer confirmed the missing pushed-commit warning on current Insiders and explicitly retained this feature request. Existing confirmations do not cover it, and the related issues address different user-visible behavior.

## Change summary

Offer an opt-out confirmation before amending a commit already present on its upstream, without interrupting local-only amends.

## Best solution

Provide the targeted confirmation in the built-in Git extension's shared amend flow, explaining history rewriting and force-push requirements while preserving ordinary local amends and existing force-push safeguards.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`
- **Validation:** In a repository with a bare upstream, push HEAD, stage a change and invoke an amend command: confirmation must precede rewriting, and cancellation must preserve HEAD and staged changes. Accepting must amend; opting out must suppress subsequent warnings. Local-only amends and ordinary commits must remain unprompted by this safeguard; cover staged, all and no-verify amend variants.
- **Behavior:**

  > Amending a commit already present on the configured upstream should offer an opt-out confirmation explaining that the operation rewrites history and requires a force push to publish. Cancelling must leave the commit and staged changes intact. Local-only amends should remain uninterrupted. This feature must not automatically force-push or change Sync behavior.
- **Trace:**

  > In extensions/git/src/commands.ts, amend commands pass amend: true through commitWithAnyInput into smartCommit. The inspected smartCommit path reaches repository.commit without checking whether the amended HEAD is already on its upstream; existing no-verify and branch-protection prompts serve different conditions. The Git maintainer confirmed the behavior and supported the narrower warning in https://github.com/microsoft/vscode/issues/348293#issuecomment-7130478434. Configuration registrations live in extensions/git/package.json with descriptions in extensions/git/package.nls.json. Preserve existing commit checks, local-only amend behavior and force-push safeguards; post-amend Sync progress is separately tracked in https://github.com/microsoft/vscode/issues/338203.
