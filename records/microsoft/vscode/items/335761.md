# Issue #335761 — Testing: Dev container agent host does not inherit git identity for checkpoints and commits

[https://github.com/microsoft/vscode/issues/335761](https://github.com/microsoft/vscode/issues/335761)

## Summary

Team-authored (MEMBER) report from internal testing of a real gap: Agent Host's git service/checkpoint code never sets GIT_AUTHOR_* env vars or otherwise forwards a git identity into the Dev Container, so the baseline checkpoint commit fails when the container has no repo-local git config — confirmed by reading the code, and no fix is on main yet, so this stays open.

## Change summary

Agent Host running in a Dev Container fails to create its baseline checkpoint commit because it has no Git author identity, even though the host has one configured.

## Best solution

In src/vs/platform/agentHost/node/agentHostGitService.ts (commitTree/_runGit call sites) and agentHostCheckpointService.ts, either forward the host's git user.name/user.email into the container session (or set a synthetic default identity) before the baseline checkpoint commit, and surface a clear error/notification instead of a silent log warning when identity is unavailable — the exact approach needs a maintainer product decision among the options the reporter lists.
