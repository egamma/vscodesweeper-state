# Issue #300045 — VS Code crash on startup when installed on external drive on Mac

[https://github.com/microsoft/vscode/issues/300045](https://github.com/microsoft/vscode/issues/300045)

## Summary

The startup failure is caused by the portable user-data filesystem rejecting a Unix socket, not by the file-watcher warning. A maintainer explicitly established that user data on a filesystem without Unix socket support is unsupported, so an as-designed close is appropriate.

## Change summary

VS Code exits during startup when its portable user-data directory on an external Mac drive rejects creation of the main IPC socket.

## Best solution

Keep the established Unix-socket requirement for desktop user data. Run portable mode with its data on a socket-capable filesystem, or disable portable mode and retain local user data while keeping the application on the external drive.

- **Proposed comment:**

  > Thanks for the report. The startup error is `listen ENOTSUP` when creating the main IPC socket in `code-portable-data/user-data`; the file-watcher warning is separate and does not cause this exit.
  > 
  > VS Code's desktop user-data directory needs a filesystem that supports Unix sockets, as explained in https://github.com/microsoft/vscode/issues/137602#issuecomment-975501718. Use a socket-capable filesystem for the portable data, or disable portable mode so user data stays locally while the application remains on the external drive. In portable mode, `--user-data-dir` does not override the portable data location.
