# Issue #301167 — chat.pluginLocations: absolute paths and tilde (~/) paths not resolved in Remote WSL

[https://github.com/microsoft/vscode/issues/301167](https://github.com/microsoft/vscode/issues/301167)

## Summary

Confirmed on current main: `_resolvePluginPath` uses `URI.file()` for absolute and tilde paths, producing `file:` scheme URIs that the remote file service cannot resolve. An open PR (#326916) targets the fix but has not merged yet — keeping open.

## Change summary

`chat.pluginLocations` silently fails to discover plugins at absolute or tilde paths in Remote WSL/SSH/Dev Container because `URI.file()` produces the wrong URI scheme for the remote file service.

## Best solution

Land the open PR https://github.com/microsoft/vscode/pull/326916 which replaces `URI.file()` with a remote-aware URI construction in `_resolvePluginPath` and `_resolveEnterprisePluginId`. The same pattern should mirror what the prompt/agent/skill locations already do correctly (as confirmed by a team member in the latest comment).
