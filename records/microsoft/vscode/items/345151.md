# Issue #345151 — Add "AI features" filter to builtin changelog viewer

[https://github.com/microsoft/vscode/issues/345151](https://github.com/microsoft/vscode/issues/345151)

## Summary

Keep open for community review: the built-in release notes viewer does not currently provide the requested AI-content filter. The request has nine upvotes one day into its Backlog Candidates window, and no verified duplicate or completed implementation was found.

## Change summary

Allow readers to hide AI-related release-note content, optionally using chat.disableAIFeatures to determine the initial presentation.

## Best solution

Provide an optional, accessible way to focus the built-in release notes on non-AI changes while retaining access to the full document. First settle content classification and whether disabling AI should automatically affect release-note presentation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/update/browser/releaseNotesEditor.ts`, `src/vs/workbench/contrib/update/test/browser/releaseNotesEditor.test.ts`, `src/vs/workbench/contrib/update/test/browser/releaseNotesRenderer.test.ts`

Verify the agreed filtered presentation, restoration of the complete document, matching table-of-contents navigation, keyboard operation, and the chosen chat.disableAIFeatures default behavior.
- **Behavior:**

  > Readers should be able to focus the built-in release notes on changes unrelated to AI without disabling the release-note viewer itself. Non-AI content must remain readable and navigable, and the complete document must remain available. Acceptance checks should cover mixed-content notes, table-of-contents consistency, keyboard access and the agreed relationship to chat.disableAIFeatures.
- **Trace:**

  > ReleaseNotesManager.renderBody in src/vs/workbench/contrib/update/browser/releaseNotesEditor.ts renders fetched Markdown and adds only the update.showReleaseNotes preference checkbox. renderReleaseNotesMarkdown supports product-channel conditional blocks and highlights but has no AI-content classification input. ReleaseNotesTryouts.getState can hide individual example affordances; that is distinct from filtering their surrounding documentation. Preserve existing release-note display preferences, non-AI examples and AI-feature authorization behavior. The unresolved boundary is how authored sections, highlights and mixed paragraphs are categorized, and whether the existing AI-disable preference changes documentation presentation. The request and community-review context are at https://github.com/microsoft/vscode/issues/345151; release-note content is fetched externally, so any required authoring metadata must be considered separately from this viewer checkout.
- **Open decisions:**
  - Should chat.disableAIFeatures automatically initialize a filtered view, or should release-note filtering remain an independent reader preference?
  - Should excluded AI content be hidden entirely or remain visible in a de-emphasized presentation?
  - What counts as AI content, especially for mixed sections, highlights and changes that benefit both AI and non-AI workflows?
