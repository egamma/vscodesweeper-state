# Issue #228522 — vscode.dev blocks simple browser

[https://github.com/microsoft/vscode/issues/228522](https://github.com/microsoft/vscode/issues/228522)

## Summary

Still reproduces on main: Simple Browser on vscode.dev uses an iframe which most external pages cannot load due to missing CORS headers (`Cross-Origin-Resource-Policy`, `Cross-Origin-Embedder-Policy`). The contributor acknowledged this limitation and a team member suggested disabling Simple Browser in unsupported web scenarios, but no fix has landed yet.

## Change summary

Simple Browser on vscode.dev blocks loading external URLs because most pages lack the required cross-origin headers for iframe embedding.

## Best solution

Either disable/hide Simple Browser in serverless web contexts (as joaomoreno suggested in the related issue), or investigate the `credentialless` iframe attribute as mjbvz mentioned. On desktop this is already moot since commit b4018e320b8 hides Simple Browser in favor of the integrated browser, but the web path in `extensions/simple-browser/src/simpleBrowserView.ts` (line 169, the iframe with sandbox attributes) still has no cross-origin mitigation.

## Evidence

- **contributor acknowledgment:** mjbvz confirmed at https://github.com/microsoft/vscode-remote-release/issues/10023#issuecomment-2539728194 that pages need to set those headers, and that the `credentialless` iframe attribute might help but wasn't working at the time.

- **desktop mitigated:** Commit b4018e320b8 ('Never use simple browser on desktop') hides the Simple Browser command on desktop and routes to the integrated browser instead, but the web path remains unaddressed.
