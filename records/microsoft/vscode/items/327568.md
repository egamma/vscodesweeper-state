# Issue #327568 — Can only search for the content of the opened file.

[https://github.com/microsoft/vscode/issues/327568](https://github.com/microsoft/vscode/issues/327568)

## Summary

Real bug, but an open PR (#330902) already targets the exact root cause with `Fixes #327568`, so this should stay open pending review/merge of that fix rather than being closed now.

## Change summary

Workspace text search only matches GB2312/GBK-encoded files on disk when a UTF-8 (or already-open) equivalent exists; ripgrep/disk search doesn't decode GB2312 files correctly unless the file is already open in an editor buffer.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/330902, which maps 'gb2312' to the canonical 'gbk' encoding label in `toCanonicalName` (src/vs/workbench/services/textfile/common/encoding.ts) so ripgrep/disk search decodes GB2312 files the same way the in-memory text buffer already does.
