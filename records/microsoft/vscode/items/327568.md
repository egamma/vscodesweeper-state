# Issue #327568 — Can only search for the content of the opened file.

[https://github.com/microsoft/vscode/issues/327568](https://github.com/microsoft/vscode/issues/327568)

## Summary

This is a mixed-encoding search feature request rather than a regression. The search backend accepts one configured encoding per workspace folder, and maintainers previously declined the same capability as unsupported and out of scope.

## Change summary

Allow one workspace search to find text across both GB2312 and UTF-8 files regardless of the configured default encoding.

## Best solution

Keep workspace search limited to one configured encoding per folder; mixed-encoding projects should normalize files to UTF-8 or search separately after changing `files.encoding`.

## Vision fit

- **Fit:** rejected
- **Reason:** Per-file encoding detection during workspace search would add complexity and processing cost to a performance-sensitive core operation.
- **Evidence:** Public value: “Performance trumps functionality.”

- **Proposed comment:**

  > Thanks for the detailed report. Workspace search currently sends one `files.encoding` value per folder to the search backend, so it cannot decode GB2312 and UTF-8 files simultaneously. This mixed-encoding limitation was previously reviewed in https://github.com/microsoft/vscode/issues/155374 and determined to be unsupported by the search architecture and out of scope. The practical options are to normalize the files to UTF-8 or run separate searches after changing `files.encoding`.
