# Issue #334236 — Persist hidden chat state when reopening a session in an editor window

[https://github.com/microsoft/vscode/issues/334236](https://github.com/microsoft/vscode/issues/334236)

## Summary

Fresh, well-specified report with clear repro steps; traced the mechanism on main — reopening a session in a regular editor window unconditionally re-reveals the chat view with no check for a prior user hide, so this is a real gap that needs a design decision on where to persist the per-session/window hidden state, not a full trace of the exact eventual fix.

## Change summary

Hiding the session chat pane in a regular editor window (opened from the Agents window) doesn't stick — reopening the same or another session re-shows the chat automatically instead of respecting the user's hide.

## Best solution

Persist a hidden/visibility flag when the user explicitly hides the chat view in an editor window, and have the session-open path check it before force-revealing: `ChatCommandLineHandler.handleOpenChatSession` (src/vs/workbench/contrib/chat/electron-browser/chat.contribution.ts, ~line 89) calls `chatWidgetService.openSession(sessionResource, ChatViewPaneTarget)` unconditionally, which in `ChatWidgetService.openSession` (src/vs/workbench/contrib/chat/browser/widget/chatWidgetService.ts, ~lines 131-138) always calls `viewsService.openView(ChatViewId, ...)`; `IViewsService.openView` (src/vs/workbench/services/views/browser/viewsService.ts, ~line 302) has no concept of 'user closed this view for this session' and simply reveals the composite. A maintainer needs to decide the right place to key that state (per session resource vs. per window).
