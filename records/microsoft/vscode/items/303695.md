# Issue #303695 — MCP: "Failed to parse message: ''" warning from empty SSE priming frames

[https://github.com/microsoft/vscode/issues/303695](https://github.com/microsoft/vscode/issues/303695)

## Summary

The empty-frame warning remains source-reproducible in the POST response and legacy SSE handlers. The GET backchannel already filters empty messages, so the original GET-only diagnosis is incomplete; retain this issue for the remaining transport paths.

## Change summary

Prevent empty MCP SSE priming frames from producing JSON parse warnings while preserving normal message handling.

## Best solution

Make MCP HTTP transport handling consistently accept empty priming events without forwarding them as JSON-RPC messages, while preserving valid messages, reconnection metadata, endpoint negotiation, and warnings for genuinely malformed payloads.
