Keep open: the existing CodeLens quick picker provides command execution but does not cover the remaining nonvisual discovery and navigation requests. An open draft implementation already references this issue and should be reviewed before starting competing work.

## Evidence

- **Existing capability and its limit:** src/vs/editor/contrib/codelens/browser/codelensController.ts registers codelens.showLensesInCurrentLine. Its run method selects commands only when lens.symbol.range.startLineNumber equals the cursor line, then presents an accessible quick picker. This supports execution on a known line, not discovery of lens-bearing lines.
- **Current widget behavior:** src/vs/editor/contrib/codelens/browser/codelensWidget.ts, CodeLensContentWidget.withCommands, renders command anchors with role='button' but without href or tabindex. The inline widgets therefore do not provide ordinary keyboard focus stops; the quick-picker command is a separate access path.
- **Discussion narrows the remaining request:** In the supplied discussion on https://github.com/microsoft/vscode/issues/171755, maintainers explain the existing quick picker and discuss an audio cue and next/previous lens navigation. The April 28, 2023 comments confirm that Copilot suggestion acceptance was addressed separately and identify nonvisual CodeLens presence indication as remaining work. The remaining request adds discovery/navigation capabilities rather than repairing the existing picker's specified exact-line behavior.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/317265 is OPEN, draft, and unmerged, and GitHub lists it among this issue's closing PR references. It proposes nearest-preceding-lens selection and an editor accessibility-help entry, but explicitly introduces no accessibility signal. It is a candidate implementation, not evidence of a landed fix.
