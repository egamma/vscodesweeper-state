# Issue #323929 — Custom agents disappear and reappear in v1.126

[https://github.com/microsoft/vscode/issues/323929](https://github.com/microsoft/vscode/issues/323929)

## Summary

This remains a credible intermittent bug: the reporter observed it repeatedly across five releases, another user confirmed the disappearing agent and model inventories, and a newer report corroborates the editor-window symptom. Current source contains refresh paths that can replace a valid custom-agent inventory with an empty one, but the shared trigger behind agent loss, model loss, and disabled submission still needs diagnosis.

## Change summary

Custom agents intermittently disappear from the Local chat picker, sometimes alongside the model inventory and the ability to submit prompts, until VS Code is restarted.

## Best solution

Diagnose the transient inventory invalidation across custom-agent discovery and language-model registration, then preserve the last known valid state during recoverable refresh/provider interruptions and refresh automatically when the underlying service recovers.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/chatModes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/common/chatModeService.test.ts`
- **Validation:** First capture which custom-agent discovery or model-provider transition produces the fallback-only state; then add targeted tests covering that transition in chatModeService.test.ts and the relevant chat-input model-selection suite, asserting that valid agents remain available and submission recovers without recreating the window.
- **Behavior:**

  > In an editor-window Local chat session, valid custom agents remain available while their source files and enablement are unchanged. A transient discovery or provider interruption must not permanently replace the picker with only the default Agent entry, and recovery must not require restarting VS Code. If usable models remain available, prompt submission must remain enabled; if model availability is genuinely lost, it must recover when the provider returns.
- **Trace:**

  > The mode picker reads delegate.currentChatModes, backed by ChatModes in src/vs/workbench/contrib/chat/common/chatModes.ts. ChatModes refreshes on ICustomizationHarnessService.onDidChangeCustomAgents; refreshCustomPromptModes removes modes absent from a returned snapshot and clears the entire inventory after a non-cancellation error. Local custom agents originate through IPromptsService.getCustomAgents in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts. Separately, ChatInputPart disables sendable content when hasNoAvailableModel() is true, so the reported Auto-only selector and disabled Enter indicate that the investigation must correlate model-provider transitions with custom-agent refreshes rather than patching picker rendering alone. The uncertainty starts at which event produces the transient empty/error state; preserve intentional agent deletion and genuine no-model behavior. Do not conflate this editor-window path with the Agents Window reports in https://github.com/microsoft/vscode/issues/320993 or https://github.com/microsoft/vscode/issues/324402.

## Evidence

- **repeated confirmations:** The reporter reproduced the failure on VS Code 1.127 through 1.131, including agents disappearing shortly after initially appearing; another user independently reported that the model selector simultaneously falls back to Auto.
- **current source path:** src/vs/workbench/contrib/chat/common/chatModes.ts listens to ICustomizationHarnessService.onDidChangeCustomAgents and rebuilds the picker inventory in ChatModes.refreshCustomPromptModes; an empty result removes every unseen mode, while any non-cancellation error clears _customModeInstances entirely.
- **submission correlation:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts disables sendable input when hasNoAvailableModel() is true. The reported combination of missing custom agents, an Auto-only model selector, and Enter doing nothing therefore points upstream of the picker UI to transient customization/model inventory state.

It is newer and narrower than this report, so it should inform the diagnosis rather than replace this issue as a duplicate canonical.
