# Issue #299417 — Identifiable branch and worktree names for background agent sessions

[https://github.com/microsoft/vscode/issues/299417](https://github.com/microsoft/vscode/issues/299417)

## Summary

Keep open for the remaining naming-customization request. Current main already generates task-based branch names, but does not provide the requested natural-language naming rules or composition with random names.

## Change summary

Allow background agent branch and worktree names to follow user-defined naming instructions and optionally combine task identifiers with random names.

## Best solution

Retain the existing task-based naming capability and decide the supported customization contract for naming instructions and random-name composition. Extend the session naming paths consistently without changing existing branches or worktree identities.

- **Validation:** After settling the naming contract, validate new worktree sessions with descriptive naming enabled and disabled, random naming enabled and disabled, and configured naming instructions. Verify recognizable task identifiers, compliance with the chosen composition rules, valid unique Git branch names, unchanged existing worktrees, and preserved fallback behavior when name generation is unavailable.
- **Behavior:**

  > Background sessions already support branch names derived from their initial task. The remaining goal is to let users control naming conventions through natural-language rules and optionally retain random-name identifiers alongside the task description. Acceptance must cover the agreed instruction source and precedence, combinations of descriptive and random naming, collisions, and generation failure. Existing sessions and worktrees must retain their identities.
- **Trace:**

  > Copilot CLI session creation calls generateNewBranchName in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessions.ts, using GitBranchNameGenerator when github.copilot.chat.cli.aiGenerateBranchNames.enabled is enabled. The generator renders GitBranchPrompt with the first user request; the prompt has fixed naming guidance and no separate repository-instruction input. ChatSessionWorktreeService.generateBranchName accepts a preferred topic name, prepends git.branchPrefix and the built-in session prefix, and falls back to random or timestamp naming rather than composing random and descriptive names. The agent-host path separately implements topic generation in src/vs/platform/agentHost/node/shared/agentBranchNameGenerator.ts. These paths establish partial coverage, not a defect in existing behavior; uncertainty begins at the instruction-source and composition contracts. Preserve existing collision handling, fallback behavior, and already-created branch identities. The related prefix request at https://github.com/microsoft/vscode/issues/321685 is newer and narrower, not a duplicate canonical.
- **Open decisions:**
  - Should naming rules come from a dedicated setting, repository instruction files, or both, and which takes precedence?
  - When descriptive and random naming are both enabled, should task names replace random names or combine with them, and what user-visible ordering should apply?
  - Should the naming-customization contract apply equally to background Copilot CLI sessions and agent-host sessions across providers?
