# Issue #33974 — Smart Tabs - Feature Request

[https://github.com/microsoft/vscode/issues/33974](https://github.com/microsoft/vscode/issues/33974)

## Summary

Keep this accepted Backlog request open: current indentation settings do not distinguish structural indentation from alignment, and the request has 46 community upvotes. The related open issues do not provide an older canonical covering the same behavior; a maintainer-led design session should establish the language-awareness and fallback contract.

## Change summary

Support smart tabs that use tabs for code-block indentation and spaces for subsequent alignment.

## Best solution

Provide an opt-in editor behavior that distinguishes indentation from alignment across typing, automatic indentation, and indentation adjustments, while preserving existing behavior outside that mode. Establish how the editor obtains that distinction and behaves when language information is insufficient before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/common/core/misc/indentation.ts`, `src/vs/editor/common/cursorCommon.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/editor/common/commands/shiftCommand.ts`, `src/vs/editor/contrib/indentation/browser/indentation.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`, `src/vs/editor/test/browser/commands/shiftCommand.test.ts`, `src/vs/editor/contrib/indentation/test/browser/indentation.test.ts`
- **Validation:** The plan should define representative nested code and continuation-alignment examples, then add cursor and indentation tests covering Tab, Enter, indent/outdent, and paste adjustment. Assert exact whitespace: structural indentation uses tabs, alignment uses spaces, and changing displayed tab width preserves alignment within the same nesting level. Run the affected editor unit suites and verify unchanged behavior with the mode disabled.
- **Behavior:**

  > Users want code-block nesting represented by tabs and subsequent alignment represented by spaces, rather than treating all leading whitespace as interchangeable width. Editing should preserve that distinction instead of replacing alignment spaces with tabs. Acceptance examples should exercise nested blocks and aligned continuation lines through Tab, Enter, indentation adjustments, and paste, checking exact stored whitespace and alignment at multiple tab widths. Existing indentation behavior must remain unchanged when the new behavior is not enabled.
- **Trace:**

  > Current settings expose tabSize, indentSize, insertSpaces, and detectIndentation but no structural/alignment distinction. CursorConfiguration.normalizeIndentation delegates to the width-based helper in src/vs/editor/common/core/misc/indentation.ts; EnterOperation consumes that helper, while TabOperation can insert a literal tab regardless of alignment context. ShiftCommand also reconstructs prefixes from visible columns rather than nesting depth. Language-aware indentation passes through src/vs/editor/common/languages/autoIndent.ts, making it a relevant contract boundary, but the inspection did not establish a general source of separate structural and alignment information. The uncertainty is language coverage and fallback behavior, not whether the existing boolean setting already satisfies the request. Keep rendering, file encoding, and formatter-owned output outside the initial scope unless analysis demonstrates a necessary dependency. Related https://github.com/microsoft/vscode/issues/184700 describes the narrower Return-normalization symptom; https://github.com/microsoft/vscode/issues/5394 concerns a different mixed-indentation convention.
- **Open decisions:**
  - When language information cannot distinguish code-block indentation from alignment, should smart-tabs mode preserve existing whitespace without synthesizing a boundary, or infer one heuristically?
  - Should the initial supported behavior preserve user-established alignment only, or also generate language-aware continuation alignment automatically?

- **Existing-capability check:** src/vs/editor/common/config/editorConfigurationSchema.ts registers editor.tabSize, editor.indentSize, editor.insertSpaces, and editor.detectIndentation. Separating indentSize from tabSize does not deliver the requested smart-tabs behavior.
- **Current normalization behavior:** src/vs/editor/common/core/misc/indentation.ts::_normalizeIndentationFromWhitespace converts the entire leading whitespace prefix to a width, then emits as many tabs as possible when insertSpaces is false, retaining only remainder spaces. It receives no code-block depth or alignment boundary. CursorConfiguration.normalizeIndentation in src/vs/editor/common/cursorCommon.ts delegates to this helper, and EnterOperation in src/vs/editor/common/cursor/cursorTypeEditOperations.ts uses it when constructing newline indentation.
- **Current Tab behavior:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts::TabOperation._replaceJumpToNextIndent inserts a literal tab whenever insertSpaces is false, without distinguishing alignment positions. src/vs/editor/common/commands/shiftCommand.ts::ShiftCommand.shiftIndent and unshiftIndent likewise calculate replacement prefixes from visible columns and tab stops, not structural nesting.
