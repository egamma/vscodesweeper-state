# Issue #35785 — Input box completion support

[https://github.com/microsoft/vscode/issues/35785](https://github.com/microsoft/vscode/issues/35785)

## Summary

Dynamic quick-pick entries are supported today, but the discussion also requests word-level completion inside editable input, which the public InputBox API does not provide. Keep this accepted Backlog request open for a focused API decision; the related tab-completion issue is newer and does not cover the full request.

## Change summary

Expose extension-controlled input completions, including suggestions that complete individual words or command arguments.

## Best solution

Use the existing createQuickPick API for dynamically populated choices, and define the remaining contract for completing part of an editable input without submitting it. Coordinate keyboard behavior with the related tab-completion request while preserving accessible focus navigation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputBox.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`
- **Validation:** The plan should end with an extension-host acceptance scenario that offers multiple command-flag completions, inserts a selected completion without submitting the input, preserves surrounding text, and permits continued typing. Verify keyboard-only and screen-reader navigation, plus unchanged existing QuickPick selection and InputBox submission behavior.
- **Behavior:**

  > Extensions can already recompute QuickPick choices as the user types; that capability must remain unchanged. The remaining goal is completion within editable input, such as suggesting and inserting a command flag while retaining the surrounding command text. A completed design must distinguish accepting a suggestion from submitting the final input and preserve accessible keyboard navigation. Acceptance should demonstrate multiple suggestions, insertion into the intended text range, continued editing, and final submission.
- **Trace:**

  > The public QuickPick contract in src/vscode-dts/vscode.d.ts exposes onDidChangeValue and writable items; QuickPick.doSetValue and the items setter in src/vs/platform/quickinput/browser/quickInput.ts implement live updates. InputBox exposes valueSelection and validation but no suggestion-provider contract, and src/vs/platform/quickinput/browser/quickInputBox.ts wraps FindInput. Proposed QuickPick.valueSelection adds programmatic selection control, not a full completion contract. The uncertainty starts at the public interaction model for inserting a suggestion while continuing to edit. https://github.com/microsoft/vscode/issues/107265 documents the related Tab-completion request and the accessibility requirement for focus navigation; it is newer and not a duplicate target for this re-reviewed issue. Preserve existing QuickPick filtering, item acceptance, ordinary InputBox submission, and focus traversal.
- **Open decisions:**
  - Should the remaining capability be exposed as suggestions on InputBox, or as an explicit editable-completion mode on QuickPick?
  - Which gesture accepts a completion without submitting the input, and how should that coexist with Enter submission and Tab focus navigation?
