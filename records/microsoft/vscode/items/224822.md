# Issue #224822 — Keep Cursor Line Stable when Code Lenses are inserted

[https://github.com/microsoft/vscode/issues/224822](https://github.com/microsoft/vscode/issues/224822)

## Summary

Keep open: current CodeLens insertion preserves the first visible line, not the cursor line. The earlier cursor-anchoring change was reverted for regressions outside CodeLens, and this team-authored Backlog request explicitly tracks the narrower improvement.

## Change summary

Preserve the visible cursor line's vertical position when CodeLens entries are inserted, without changing other editor elements' scrolling behavior.

## Best solution

Provide CodeLens-specific cursor anchoring while retaining existing scroll behavior for diff-editor changes, review comments, and other view zones. Establish the behavior at the top of the document before implementing the scoped improvement.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/codelens/browser/codelensController.ts`, `src/vs/editor/browser/stableEditorScroll.ts`
- **Validation:** With TypeScript CodeLens enabled, navigate to a symbol in a previously unopened, uncached file and let lenses arrive asynchronously; compare the cursor line's viewport Y position before and after insertion. Repeat with scrollTop equal to zero and with the cursor outside the viewport according to the agreed behavior. Verify that deleting lines in a diff editor and expanding review comments retain their existing scrolling behavior.
- **Behavior:**

  > When code lenses arrive after navigation to a symbol, a visible cursor line should remain at the same vertical viewport position instead of moving down with newly inserted lens space. This behavior is specific to CodeLens insertion, not a global change to editor view-zone anchoring. Acceptance checks should cover asynchronous insertion into an uncached file, a cursor outside the viewport, and the agreed top-of-document behavior. Diff-editor line deletion and review-comment expansion must not acquire cursor-anchoring regressions.
- **Trace:**

  > CodeLensContribution._renderCodeLensSymbols in src/vs/editor/contrib/codelens/browser/codelensController.ts wraps CodeLensWidget view-zone insertion with StableEditorScrollState.capture and restore. In src/vs/editor/browser/stableEditorScroll.ts, capture records the first visible position and its scroll delta, while an early guard skips anchoring at scrollTop zero or during a pending scroll animation. Inserting lenses below that first visible position but above the cursor changes the cursor's viewport position without changing the recorded anchor. The shared helper also serves other editor contributions, so their behavior is outside this request's scope. https://github.com/microsoft/vscode/pull/221031 changed that shared anchor globally and was reverted by https://github.com/microsoft/vscode/pull/224289 after the regressions documented in https://github.com/microsoft/vscode/issues/224263 and https://github.com/microsoft/vscode/issues/224275. The remaining product uncertainty is whether CodeLens cursor stability should override the existing top-of-document no-scroll behavior.
- **Open decisions:**
  - When scrollTop is zero and lenses appear above a visible cursor, should the editor scroll to keep the cursor line stationary, or remain pinned to the document top even though the cursor moves?

## Evidence

- **Current insertion path:** In src/vs/editor/contrib/codelens/browser/codelensController.ts, CodeLensContribution._renderCodeLensSymbols captures StableEditorScrollState, inserts CodeLensWidget view zones, and calls scrollState.restore. In src/vs/editor/browser/stableEditorScroll.ts, capture anchors visibleRanges[0].getStartPosition(), and restore preserves that position rather than the cursor's position. Lenses inserted between the viewport anchor and the cursor therefore still move the cursor line.
- **Existing capabilities do not cover the request:** src/vs/editor/common/config/editorOptions.ts exposes editor.codeLens, editor.codeLensFontFamily, and editor.codeLensFontSize, but no CodeLens cursor-anchoring option. Disabling lenses avoids their layout changes but removes the requested feature. StableEditorScrollState.restoreRelativeVerticalPositionOfCursor compares cursor line positions using the post-change layout; it does not preserve a captured pre-insertion cursor viewport offset.
- **Earlier implementation was reverted:** https://github.com/microsoft/vscode/pull/221031 introduced visible-cursor anchoring globally in StableEditorScrollState.capture. https://github.com/microsoft/vscode/pull/224289 reverted it in commit d90ab31527203cdb15056df0dc84ab9ddcbbde40 because of diff-editor and review-comment regressions, addressing https://github.com/microsoft/vscode/issues/224263 and https://github.com/microsoft/vscode/issues/224275. The reverted change is not a completed fix for this request.
- **Maintainer intent and consolidation:** https://github.com/microsoft/vscode/issues/216824#issuecomment-2186112024 explains that preserving the cursor line would be an improvement over the implemented first-visible-line anchoring. The author subsequently closed that older report in favor of this issue: https://github.com/microsoft/vscode/issues/216824#issuecomment-2270690744.
