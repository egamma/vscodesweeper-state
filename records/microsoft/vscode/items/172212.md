# Issue #172212 — Clicking anywhere hides modal dialog about untrusted link 

[https://github.com/microsoft/vscode/issues/172212](https://github.com/microsoft/vscode/issues/172212)

## Summary

The defect remains visible in current main: protocol-link confirmation is still created without an owning window, allowing the native dialog to fall behind VS Code while continuing to block normal window actions.

## Change summary

Keep the native confirmation for an untrusted VS Code protocol link visibly modal instead of letting clicks move it behind the workbench.

## Best solution

Associate protocol-link confirmation with the appropriate VS Code window when one exists, so the dialog remains foreground-modal until the user accepts or rejects it while preserving headless and initial-startup protocol handling.
