# Issue #319557 — Prevent Escape key from accidentally closing the askQuestions dialog

[https://github.com/microsoft/vscode/issues/319557](https://github.com/microsoft/vscode/issues/319557)

## Summary

The accepted backlog bug remains present on current main: one Escape keypress anywhere inside a skippable question carousel immediately resolves it with no answers and discards its interactive state. The implementation is bounded, but a maintainer should first choose the intended Escape behavior.

## Change summary

Prevent an accidental single Escape keypress from dismissing the active askQuestions carousel and losing in-progress answers.

## Best solution

Retain an explicit, keyboard-accessible way to skip all questions while ensuring one accidental Escape does not immediately resolve the carousel with undefined answers. The UX owner should choose whether Escape moves focus, enters a confirmation state, or requires a second press.

- **Behavior:**

  > A single accidental Escape while answering an askQuestions carousel must not immediately skip all questions or lose the in-progress answer. The chosen Escape behavior must be keyboard-accessible, preserve a deliberate way to skip all questions, and work consistently for single- and multi-question carousels. Acceptance checks should cover Escape from text input, freeform textarea, and option controls, plus explicit Skip All behavior.
- **Trace:**

  > ChatQuestionCarouselPart registers a bubbling keydown listener on its root in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts; for Escape with allowSkip it unconditionally invokes ignore(). ignore() sends undefined through ChatListRenderer.handleSubmit, which marks the carousel used and completes ChatQuestionCarouselData, allowing AskQuestionsTool.invoke to resume with skipped answers. Preserve explicit Skip All, allowSkip=false semantics, answer submission, multi-question navigation, and draft restoration. Because this changes a keyboard interaction, the chat accessibility help should be checked and updated if it documents the affected action.
- **Open decisions:**
