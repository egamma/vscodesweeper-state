# Issue #284959 — Copilot silently corrupts long attached files

[https://github.com/microsoft/vscode/issues/284959](https://github.com/microsoft/vscode/issues/284959)

## Summary

Still valid and actively under discussion. The core summarization behavior remains on main — `CodeSummary`/`DocumentSummarizer` in `fileVariable.tsx` still silently truncates large attached files. The team member's partial mitigation (removing the 'you don't have to read' prompt, and the experimental `omitFileAttachmentContents` setting) shipped, but the fundamental design question — how to handle large attachments without silent corruption — remains open. The team member explicitly committed to further work.

## Change summary

Copilot silently summarizes/truncates long user-attached files (replacing content with 'Lines N-M omitted'), leading to degraded model responses because the LLM receives incomplete context without the user's knowledge.

## Best solution

Resolve the design question roblourens outlined: either (1) finish and ship the `omitFileAttachmentContents` approach (send only file paths, let the agent read as needed), or (2) make summarization visible to the user with a clear indicator and opt-out, or (3) increase the attachment budget / make it configurable. The partial fixes (prompt removal in commit f0c0f74cd85, the experimental setting in `chatVariables.tsx` line 76) are landed but the default experience still silently summarizes. The `CodeSummary` path in `extensions/copilot/src/extension/prompts/node/panel/fileVariable.tsx` (lines 308–328) is where the truncation occurs.
