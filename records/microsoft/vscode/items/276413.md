# Issue #276413 — Git - changes tool should avoid context blowout

[https://github.com/microsoft/vscode/issues/276413](https://github.com/microsoft/vscode/issues/276413)

## Summary

Keep open: the changes tool still lacks progressive disclosure for large diffs, and its structured output bypasses the existing text-result disk offload. The author reopened this after testing the earlier fix; no verified subsequent fix or eligible canonical was found.

## Change summary

Make large #changes responses compact while preserving access to detailed diffs on demand.

## Best solution

Provide a bounded initial changes response with discoverable access to complete diffs, retaining the useful inline experience for small changesets. Establish the model-facing size contract before implementing and validating the large-response behavior.

Disabling changes instead allowed terminal output to be inspected incrementally from content.txt.
- **Current changes-tool boundary:** extensions/copilot/src/extension/tools/node/scmChangesTool.ts limits diff retrieval to 200 files and 30 seconds, but returns successful diffs as LanguageModelPromptTsxPart through GitChanges. These limits do not establish a compact response-size contract, and remaining filenames are listed without a size bound.
- **Existing disk offload does not cover structured diffs:** In extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx, text parts use onText, which can write large results to disk; prompt-TSX parts use onTSX, which returns elementJSON, optionally wrapped in TokenLimit, without disk offload. GitChanges in extensions/copilot/src/extension/prompts/node/git/gitChanges.tsx renders each supplied diff inline. Token pruning does not provide access to omitted details.
