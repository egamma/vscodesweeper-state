# Issue #339580 — High CPU feedback loop between prompt discovery and Open Editors view when Copilot is enabled

[https://github.com/microsoft/vscode/issues/339580](https://github.com/microsoft/vscode/issues/339580)

## Summary

Well-diagnosed CPU feedback loop between FilesConfigurationService.updateReadonly, the Open Editors view's resourceExtname context key churn, and prompt-provider re-discovery; an open PR (#339987) already targets the fix, so this stays open pending that PR landing.

## Change summary

In remote WSL workspaces with Copilot enabled, switching to the Explorer view with an editor open causes a sustained high-CPU loop between readonly-state updates and prompt/custom-agent discovery.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/339987, which suppresses unchanged readonly notifications to break the resourceExtname set/reset churn that re-triggers ExtensionPromptFileService._listFromProviders.
