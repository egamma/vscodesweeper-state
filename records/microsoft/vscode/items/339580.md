# Issue #339580 — High CPU feedback loop between prompt discovery and Open Editors view when Copilot is enabled

[https://github.com/microsoft/vscode/issues/339580](https://github.com/microsoft/vscode/issues/339580)

## Summary

Confirmed on current main by tracing the exact code path the reporter captured: `FilesConfigurationService.updateReadonly`/`applyReadonly` fires `onDidChangeReadonly` unconditionally even when the readonly state didn't actually change, and `OpenEditorsView`'s `EDITOR_CAPABILITIES` handler reacts by re-focusing the list, which resets/sets `ResourceContextKey` and re-triggers prompt-provider discovery — closing the loop.

## Change summary

With the bundled Copilot extension enabled and the Open Editors/Explorer view visible, re-marking already-readonly prompt-provider URIs keeps firing a readonly-changed event that re-triggers list refocus, context-key churn, and prompt discovery in an unbounded loop, pinning the extension host at ~45-55% CPU.

## Best solution

Make `FilesConfigurationService.applyReadonly`/`updateReadonly` idempotent: track whether any resource's readonly state actually changed and only fire `onDidChangeReadonly` when it did, in src/vs/workbench/services/filesConfiguration/common/filesConfigurationService.ts. That breaks the loop at its source without touching the Open Editors focus-tracking or context-key behavior, which may be intentional elsewhere.
