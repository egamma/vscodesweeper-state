## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/test/browser/chatWidgetInputPreservation.test.ts`
- **Validation:** Add a targeted Chat browser test that types text and attaches context in a fresh sidebar conversation, switches to an existing conversation, returns to the fresh conversation, and asserts that the text and attachments are unchanged; also cover switching within the 150 ms input-state debounce interval.
- **Behavior:**

  > An unsent draft in a fresh sidebar Chat conversation must survive opening an existing conversation and returning. The preserved draft includes prompt text, screenshots, and other explicit attachments. Existing conversations retain their own drafts independently, and sending or explicitly clearing a draft still removes it. Acceptance requires coverage both after normal input synchronization and when navigation occurs during the debounce interval.
- **Trace:**

  > The sidebar host binds conversations through `ChatWidget.setModel` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts and `ChatInputPart.setInputModel` in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts. The input part debounces editor-to-model synchronization, flushes the outgoing state during model switches, stores empty-conversation state in `chat.untitledInputState`, and restores `state.inputText` in `_syncFromModel`; the remaining uncertainty is which `ChatViewPane` navigation/recreation path replaces or clears that state. The same symptom was independently confirmed in VS Code 1.135.0. https://github.com/microsoft/vscode/issues/324149 is a younger matching report and should be consolidated into this issue, not used as its canonical. Do not reuse the Agents Window fix from https://github.com/microsoft/vscode/pull/323213 because that changes src/vs/sessions rather than the sidebar Chat lifecycle.

- **younger matching report:** https://github.com/microsoft/vscode/issues/324149 is open and describes the same observable symptom, but it was created on 2026-07-03, after this issue's 2026-06-25 creation date; under the re-review rule it cannot be the canonical duplicate target.
- **current source path:** On current main, `ChatInputPart.setInputModel` in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts flushes the outgoing input state and `_syncFromModel` restores `inputText`; `ChatWidget.setModel` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts also flushes before dropping a model. The confirmed loss despite this intended lifecycle indicates a remaining host/session-rebinding path that lacks regression coverage.
