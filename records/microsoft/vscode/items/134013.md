# Issue #134013 — Code completion unexpectedly consumes closing paren (from auto-closing-brackets) that was inserted automatically when `(` triggered code completion

Keep open: the discussion contains a confirmed reproduction and maintainer diagnosis, and current source still compensates for newly inserted trailing text without distinguishing manually typed parentheses. The remaining work needs a behavior decision that preserves intentional completion overtyping and cursor navigation.

## Change summary

- **Trace:**

  > SuggestController creates a LineSuffix when SuggestModel emits onDidTrigger. In src/vs/editor/contrib/suggest/browser/suggestController.ts, an end-of-line trigger makes LineSuffix.delta measure all text between the current cursor and the line end; getOverwriteInfo adds this distance to overwriteAfter. In src/vs/editor/contrib/suggest/browser/suggestModel.ts, explicit keyboard movement refilters the session, and returning to the original trigger column does not meet the cancellation check for movement before that column. The issue's confirmed reproduction and maintainer diagnosis match this path, but it was not executed in this read-only review. The uncertainty is the intended distinction between manually typed trailing punctuation, auto-inserted brackets, and deliberately overtyped text. Preserve the behaviors described in https://github.com/microsoft/vscode/issues/26012 and https://github.com/microsoft/vscode/issues/3295; broad cancellation on every cursor movement is not an established solution.
