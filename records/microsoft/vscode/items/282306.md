# Issue #282306 — [FR] Scoped Context for Copilot Chat in Monorepos and Large Codebases (@package, package index, and Per-Package copilot-instructions.md)

[https://github.com/microsoft/vscode/issues/282306](https://github.com/microsoft/vscode/issues/282306)

## Summary

Existing directory-filtered semantic retrieval and path-scoped instructions address parts of this request, but do not establish the requested package-aware context and indexing workflow. Keep this accepted Backlog request open for a design decision on the remaining scope; no verified older canonical was found.

## Change summary

Provide package-scoped, relevance-ranked Copilot context in monorepos, with package-local instructions and optional dependency-aware indexing.

## Best solution

Define a supported package-scoping workflow that builds on existing semantic-search filters and scoped instructions while preserving the full monorepo workspace. Decide whether package discovery and dependency expansion require new product behavior, and justify independent package indexes against the existing filtered-search architecture before committing to them.

- **Behavior:**

  > Users working in a full monorepo workspace need a supported way to focus Copilot's relevance-ranked context on a selected package or small package set. Package-local conventions should be available for the selected work without applying unrelated package rules. Acceptance should use two packages with conflicting symbols and conventions to demonstrate the selected scope and the agreed treatment of dependencies. Keeping the full repository open must preserve navigation and tooling.
- **Trace:**

  > CodebaseTool.invoke in extensions/copilot/src/extension/tools/node/codebaseTool.tsx already accepts internal scopedDirectories and forwards them to WorkspaceContext. WorkspaceContext.render builds include globs, and WorkspaceChunks.prepare forwards them into searchFileChunks; this establishes filtered retrieval infrastructure, not independent package indexing or package discovery. InstructionsContextComputer in src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts already handles applyTo matching and optional nested AGENTS.md discovery, so scoped instructions are not wholly missing. The remaining uncertainty is the supported package-selection contract, dependency expansion, and whether independent indexes offer a required observable guarantee beyond filtered retrieval. Preserve existing unscoped retrieval and instruction behavior, and do not assume the requested @package spelling or copilot-package.json format has been approved. The related closed discussions at https://github.com/microsoft/vscode-copilot-release/issues/4936 and https://github.com/microsoft/vscode-copilot-release/issues/10075 provide context, not completion evidence or duplicate targets.
- **Open decisions:**
  - Should package selection be an explicit per-request scope, a persistent chat-session scope, or both?
  - Should retrieval stay strictly inside selected packages by default, or automatically include declared dependencies?
  - Should package boundaries come from existing workspace manifests and directory selection, or should VS Code introduce a new package metadata contract?
  - Does the supported workflow require independently maintained package indexes, or is relevance-ranked filtering over a shared index sufficient?
