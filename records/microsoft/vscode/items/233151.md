# Issue #233151 — [WSL2] Use relative paths when linking to files

[https://github.com/microsoft/vscode/issues/233151](https://github.com/microsoft/vscode/issues/233151)

## Summary

Keep open: current source restricts relative file-link resolution to local file models, excluding WSL's vscode-remote models. The report provides sufficient steps, and the remaining defect belongs to the core editor link contribution.

## Change summary

Ctrl-clicking file://./bar.ts in a WSL editor should open bar.ts beside the current file, as it does locally.

## Best solution

Relative file links in remote editors should resolve against the current document while preserving its remote scheme and authority. Keep existing local relative-link behavior and absolute-link semantics unchanged.
