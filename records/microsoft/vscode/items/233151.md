# Issue #233151 — [WSL2] Use relative paths when linking to files

[https://github.com/microsoft/vscode/issues/233151](https://github.com/microsoft/vscode/issues/233151)

## Summary

The WSL-specific relative file-link resolution bug remains valid and reproducible. The editor link detector resolves `file://./bar.ts` through URI parsing before applying workspace-relative semantics, causing the remote authority/path to be interpreted incorrectly under WSL.

## Change summary

Relative `file://./bar.ts` links in editor comments should open the sibling file when VS Code is connected to WSL, matching local Windows behavior.

## Best solution

Normalize relative file-link targets against the active document URI before opening them, preserving the document's remote scheme and authority while leaving absolute file URIs and ordinary web links unchanged.
