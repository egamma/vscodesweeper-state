# Issue #150360 — [CustomTextEditor Web extensions] "Unable to resolve filesystem provider with relative file path" after reloading vscode.dev and reopening named untitled document in custom text editor

[https://github.com/microsoft/vscode/issues/150360](https://github.com/microsoft/vscode/issues/150360)

## Summary

The error occurs because the extension's `tmp:` scheme uses a relative path (`tmp:pipeline.component.yaml` without a leading `/`), which fails the absolute-path validation in `fileService.ts`. It's unclear whether this is a VS Code restore-logic issue or an extension bug. The report is 3+ years old with no confirmation or further context.

## Change summary

Reopening a named untitled document in a custom text editor on vscode.dev after reload fails with 'Unable to resolve filesystem provider with relative file path'.

## Best solution

Clarify whether the `tmp:` scheme URI is generated by the extension or by VS Code's restore logic. If the extension creates URIs without absolute paths, this is `*caused-by-extension`. If VS Code's custom editor restore serializes/deserializes URIs incorrectly (dropping the leading `/`), the fix would be in the custom editor input restoration in `src/vs/workbench/contrib/customEditor/`.
