# Issue #150360 — [CustomTextEditor Web extensions] "Unable to resolve filesystem provider with relative file path" after reloading vscode.dev and reopening named untitled document in custom text editor

[https://github.com/microsoft/vscode/issues/150360](https://github.com/microsoft/vscode/issues/150360)

## Summary

The named-untitled reopening path still passes a file-scheme resource to the custom editor instead of retaining the untitled document identity. Keep this open: the current source confirms the resolution defect, although the subsequent reload-related data loss was not independently verified.

## Change summary

Reopening a restored named untitled document in a custom text editor fails filesystem resolution and reportedly loses the document after another reload.

## Best solution

Named untitled documents should reopen in custom text editors against their existing untitled text model, preserving contents and dirty state without attempting to read the suggested filename from a filesystem. Keep this distinct from unnamed-document and custom-document ownership reports unless a shared cause is demonstrated.
