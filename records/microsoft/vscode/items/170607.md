# Issue #170607 — set decoration's opacity is not working

[https://github.com/microsoft/vscode/issues/170607](https://github.com/microsoft/vscode/issues/170607)

## Summary

Still reproduces on main: the unnecessary-code dimming applies CSS `opacity` on the parent span (`.squiggly-inline-unnecessary`), which cascades multiplicatively to child decoration elements — a decoration's `opacity: "1"` cannot override a parent's lower opacity in CSS. No fix has been committed.

## Change summary

Decorations inside unused/unnecessary code regions are dimmed by the editor's `editorUnnecessaryCode.opacity` CSS rule, and the decoration's own `opacity` property cannot override this because CSS opacity is multiplicative on parent elements.

## Best solution

The unnecessary-code dimming in `codeEditorWidget.ts` (line ~2556) uses CSS `opacity` on the parent span, which unavoidably dims all child content. A fix would need to change the dimming approach — for example, applying the fade via a color transformation (adjusting the foreground/background alpha) rather than CSS `opacity`, or isolating the decoration content so it isn't a child of the unnecessary-code span. This is a non-trivial change in the editor decoration rendering pipeline.
