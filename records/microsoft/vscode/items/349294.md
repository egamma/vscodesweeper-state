# Issue #349294 — @vscode/vsce-sign drops stderr and misreports signal-terminated processes as UnknownError with Executed: false

[https://github.com/microsoft/vscode/issues/349294](https://github.com/microsoft/vscode/issues/349294)

## Summary

Keep open: the published @vscode/vsce-sign wrapper still discards stderr and misclassifies signal termination. This diagnostic defect is distinct from the underlying OpenSSL compatibility failure.

## Change summary

Preserve stderr and termination signals when extension signature verification crashes, and accurately report that the verifier executed.

## Best solution

Correct the process-result handling in @vscode/vsce-sign and ensure VS Code exposes those diagnostics through ExtensionSignatureVerificationService, without changing signature enforcement or treating termination as successful verification.

## Evidence

- **Published dependency source:** https://unpkg.com/@vscode/vsce-sign@2.1.1/src/main.js confirms that execCommand accepts only (error, stdout), sets output from stdout alone, and sets didExecute=true only for numeric error codes. A null code with SIGABRT therefore produces UnknownError and didExecute=false without stderr or signal diagnostics.
- **Current VS Code consumer:** src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts dynamically imports @vscode/vsce-sign, passes verbose=true at Trace level, and logs the returned code, didExecute, internalCode and output. Its result interface contains no termination-signal field, so the consumer cannot recover diagnostics discarded by the wrapper.
- **Concrete reported trigger:** https://github.com/microsoft/vscode/issues/349294 provides matching manual-verifier output and server Trace logs: stdout contains processed package/signature sizes, while the manually invoked verifier reports 'No usable version of libssl was found' and aborts. The server instead logs UnknownError and Executed: false.
- **Related reports are not established duplicates:** https://github.com/microsoft/vscode/issues/338194 concerns the runtime compatibility failure, whereas this report explicitly isolates diagnostic loss. https://github.com/microsoft/vscode/issues/254016 contains remote-install UnknownError logs, but those alone do not establish the same signal-termination cause or full diagnostic scope.
- **Installation-path qualification:** The reporter's 2026-11-20 comment on https://github.com/microsoft/vscode/issues/349294 says the observed failure requires the extension to be installed locally before installing it on the server. src/vs/platform/extensionManagement/node/extensionDownloader.ts also has explicit verification skips when verification is disabled or the gallery extension is unsigned; this inspection does not establish which difference explains the reporter's successful fresh-install path.
- **Verification boundary:** Read-only inspection confirmed the consumer and published wrapper behavior; no verifier was executed, no deployed dependency version was established from the checkout, and no concrete fixing commit was identified. The checkout remained unchanged.
