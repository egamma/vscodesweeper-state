# Issue #282301 — Todo list appears to be cleared when resuming after stopping agent

[https://github.com/microsoft/vscode/issues/282301](https://github.com/microsoft/vscode/issues/282301)

## Summary

Keep open for a cancellation UX decision: current source still clears the session's todo list when Stop is pressed. This implements an earlier maintainer decision, but the maintainer has proposed revisiting it with a paused indication; preserving resumable progress remains an unmet request.

## Change summary

Preserve unfinished agent todos across stopping and resuming a request, without suggesting that work is still running.

## Best solution

Retain the unfinished checklist when a user interrupts an agent to provide steering, while clearly indicating that execution has stopped. Agree on the pause/resume presentation and its relationship to explicit clearing before changing the chat widget lifecycle.

- **Behavior:**

  > Stopping a multi-step agent request to provide steering currently removes the checklist, including its completed progress. The requested outcome is to retain that progress for continuation in the same session while making clear that the agent is no longer executing. Acceptance should cover stopping midway, sending steering, resuming, and updating the retained checklist, without implying that completed items need to be repeated. Explicit clearing must remain available, and a different session must not inherit the checklist.
- **Trace:**

  > ChatWidget's completedRequest handler in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts force-clears todos when the last response is canceled. ChatInputPart delegates to ChatTodoListWidget.clear(); its clearAllTodos() writes an empty array through IChatTodoListService, whose implementation persists it in workspace storage. The path is intentional, as documented at https://github.com/microsoft/vscode/issues/274729#issuecomment-3483061338; the maintainer proposes a paused compromise at https://github.com/microsoft/vscode/issues/282301#issuecomment-3820778811. IChatTodo and the tool schema currently have three statuses, and the widget renders no paused presentation. The uncertainty starts at the desired user-visible interruption state and whether it changes the model-facing status contract. Preserve explicit clearing and session isolation; undo/checkpoint restoration tracked at https://github.com/microsoft/vscode/issues/276587 is distinct work.
- **Open decisions:**
  - Should stopping an unfinished request retain the checklist visibly with a paused indication, or hide it temporarily and restore it when the session continues?
  - Should interruption be a presentation-only state while tool-facing todos retain their existing statuses, or should the public tool/status contract gain a paused state?
