# Issue #274099 — Chat scrolling behavior should be improved

[https://github.com/microsoft/vscode/issues/274099](https://github.com/microsoft/vscode/issues/274099)

## Summary

Keep open for the remaining chat scrolling work. The initial-message positioning was fixed, and the reporter withdrew the request to disable auto-scroll, but smooth scrolling remains unresolved and the separate code-block layout bug is still open.

## Change summary

Make chat scrolling stable and readable when starting messages and rendering dynamically sized responses.

## Best solution

Complete the chat scrolling design so new-message navigation is smooth, respects reduced-motion preferences, and preserves progress and confirmation visibility without repeated scroll operations fighting dynamic row layout. Coordinate the code-block-specific failure with https://github.com/microsoft/vscode/issues/274428 rather than duplicating that narrower issue.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`, `src/vs/base/browser/ui/list/listView.ts`
- **Validation:** Run the targeted ChatListWidget browser tests and manually start a new agent-mode message after a long response with `workbench.list.smoothScrolling` both enabled and disabled; verify one stable transition, continued streaming progress visibility, a working Scroll to Bottom control after manual scrolling, and no animation when reduced motion is enabled.
- **Behavior:**

  > Starting a new chat message after a long conversation should move to the new request without exposing unrelated portions of the previous response or visibly jumping through intermediate positions. Agent-mode progress and confirmation widgets must remain discoverable, while manually scrolling away from the latest output must expose a reliable Scroll to Bottom control. The transition must respect reduced-motion preferences, and dynamically growing code blocks must not leave the final response content unrevealed.
- **Trace:**

  > The first reported positioning defect was addressed by https://github.com/microsoft/vscode/pull/288674, while the code-block-specific failure remains tracked by https://github.com/microsoft/vscode/issues/274428. ChatListWidget.scrollToEnd in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts currently clears its height reservation and immediately reveals the last tree item; ChatWidget has multiple callers that can initiate this path during model and item updates. The maintainer's trace at https://github.com/microsoft/vscode/issues/274099#issuecomment-3764890853 established that dynamic-height ListView updates cancel smooth operations and competing scroll calls cause the visible jank. The boundary is chat scrolling orchestration and its interaction with list layout: preserve agent-mode progress following, confirmation visibility, manual scroll lock, reduced-motion behavior, and the existing separate ownership of the code-block layout defect.
