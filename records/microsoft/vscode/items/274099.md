# Issue #274099 — Chat scrolling behavior should be improved

[https://github.com/microsoft/vscode/issues/274099](https://github.com/microsoft/vscode/issues/274099)

## Summary

Keep this open as the canonical chat smooth-scrolling and auto-scroll polish issue. One reported problem was fixed and another is tracked separately, but current main still performs immediate reveals from several paths and the maintainer's smooth-scroll experiment remains unresolved.

## Change summary

Make chat transitions and automatic scrolling less abrupt and more reliable while preserving access to newly generated content.

## Best solution

Provide a stable smooth transition when a new chat request starts, independent of the global list smooth-scrolling preference but respecting reduced-motion settings. Preserve the existing streaming auto-scroll and Scroll to Bottom affordance, while leaving the code-block layout defect to its dedicated issue.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`, `src/vs/base/browser/ui/list/listView.ts`
- **Validation:** Run the targeted ChatListWidget browser tests, then manually submit consecutive requests in a constrained-height chat view containing dynamically resizing code blocks: the new request transition should animate without jumping or stopping short, the existing streaming behavior and Scroll to Bottom button should remain functional, and reduced-motion mode should avoid animation.
- **Behavior:**

  > Starting a new chat request should move the transcript to the current request and response with a stable, non-abrupt transition. Dynamic-height rows must not cancel the transition or leave the final content partly hidden. Existing streaming auto-scroll and the Scroll to Bottom affordance must continue to expose confirmations and new output. Reduced-motion preferences must suppress the animation.
- **Trace:**

  > ChatListWidget.scrollToEnd in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts currently performs an immediate `_tree.reveal`. ChatWidget in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts invokes that operation from several request, restoration, and layout paths, matching the maintainer's observation that competing calls disrupt an animation. The prior ListView-level experiment in https://github.com/microsoft/vscode/pull/284652 was closed, and the maintainer recorded that dynamic-height row updates cancel ongoing smooth scrolling. Commit 7710bbee04c89f2db8afaceba9fa3d6144d07ee3 already resolved the preceding-response visibility problem, so that sizing behavior must remain unchanged. The code-block layout defect belongs to https://github.com/microsoft/vscode/issues/274428 and is outside this slice.

## Evidence

- **partial fix:** Commit 7710bbee04c89f2db8afaceba9fa3d6144d07ee3 from https://github.com/microsoft/vscode/pull/288674 explicitly references this issue and fixes point 1 by sizing the current response so the preceding response is hidden.
- **separate defect:** The failure to reveal the end of a response is independently tracked by the open https://github.com/microsoft/vscode/issues/274428. It is newer than this re-reviewed issue and therefore cannot serve as its duplicate canonical.
- **remaining source path:** On current main, ChatListWidget.scrollToEnd in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts performs an immediate `_tree.reveal`, while src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts calls scrollToEnd from request addition, layout, model restoration, and other paths. The chat tree construction does not opt into smooth scrolling.
- **existing affordance:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts already provides an accessible Scroll to Bottom button, so that portion of the requested end state exists even though the transition behavior remains abrupt.
