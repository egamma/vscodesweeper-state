Keep open: another user confirms the authentication failure on a newer build and provides an explicit Authorization-header workaround. The source intends to support the original configuration, but neither a fixing commit nor an older canonical reporting this same symptom was established.

## Change summary

Custom-endpoint Chat Completions requests reject a verified group-level API key while an explicit per-model Authorization header works.

## Best solution

Make group-level apiKey authentication behave consistently with the equivalent explicit Authorization header for local OpenAI-compatible endpoints. First isolate where the configured credential or outgoing request differs; preserve custom-header overrides and existing provider-specific authentication.
