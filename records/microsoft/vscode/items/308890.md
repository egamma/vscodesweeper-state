## Evidence

- **Current terminal serialization:** src/vs/workbench/api/common/extHostTerminalShellIntegration.ts:209-225 still copies the executable verbatim and quotes an argument only when it contains whitespace and no single quote, double quote, or backtick. An executable such as /tmp/My Tool and an argument such as a"b are therefore emitted without preserving literal token boundaries.
- **Existing public contract:** src/vscode-dts/vscode.d.ts:7887-7941 explicitly documents the whitespace-only quoting condition and warns that escaping is not a security measure. This already covers the report's documentation alternative; stronger literal-token preservation remains a capability improvement rather than a demonstrated deviation from that documented contract.
- **Shell execution path:** src/vs/workbench/api/browser/mainThreadTerminalShellIntegration.ts:112-113 forwards the serialized string to TerminalInstance.runCommand. src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1065 sends that command line through sendText; preparePathForShell at lines 1433-1440 is a separate path and does not protect this overload.
- **Open linked implementation:** https://github.com/microsoft/vscode/pull/314642 was verified OPEN and contains Fixes #308890. Its changed files cover subprocess escaping in extHostMcpNode.ts and debugAdapter.ts, plus a shared helper and tests; it does not change extHostTerminalShellIntegration.ts. It is not a landed fix or complete coverage of this report.
