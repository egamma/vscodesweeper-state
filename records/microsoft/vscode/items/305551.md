# Issue #305551 — rerun action icon disappear after use it once time

[https://github.com/microsoft/vscode/issues/305551](https://github.com/microsoft/vscode/issues/305551)

## Summary

Keep open: current core code drops the Rerun Task action when reusing a CustomExecution task terminal, matching the Gradle report. The defect is bounded, but validation needs to cover terminal action visibility rather than only successful task execution.

## Change summary

Keep the terminal's Rerun Task action available after rerunning a Gradle task.

## Best solution

CustomExecution task terminals should retain their task actions across dedicated/shared terminal reuse, consistent with shell tasks. Verify repeated reruns without changing ordinary terminal actions or task restart semantics.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`, `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`, `extensions/vscode-api-tests/src/singlefolder-tests/workspace.tasks.test.ts`
- **Validation:** Establish an executable regression check that runs a completed CustomExecution task in a dedicated terminal, invokes Rerun Task, and verifies that the reused terminal still exposes workbench.action.tasks.rerunForActiveTerminal after two successive reruns. Cover shared-terminal reuse and preserve shell-task behavior. Manual acceptance: run a short Gradle task from Gradle Projects, wait for completion, click the circular-arrow action twice across successive completions, and confirm it remains visible and usable.
- **Behavior:**

  > A completed Gradle task initially displays a Rerun Task action, but rerunning it in a reused terminal removes that action. The action must remain available and usable across repeated reruns of reusable CustomExecution tasks. Acceptance covers dedicated and shared terminal reuse, with ordinary shell-task actions and non-task terminal behavior unchanged.
- **Trace:**

  > Gradle 3.17.2 uses CustomExecution with dedicated/shared terminal reuse, as shown in https://github.com/microsoft/vscode-gradle/blob/3.17.2/extension/src/tasks/taskUtil.ts. In TerminalTaskSystem._createTerminal, the custom launch configuration omits tabActions; only the new-terminal branch assigns _terminalTabActions afterward. The reuse branch passes the incomplete configuration to TerminalInstance.reuseTerminal, which replaces _shellLaunchConfig, and TerminalTabsRenderer.fillActionBar then finds no additional action to render. Shell execution already supplies tabActions through _createShellLaunchConfig. The source establishes the defect without execution; uncertainty is how to pin action visibility in an executable regression test, since the existing CustomExecution API tests do not expose that UI state. Keep the scope to task-owned action continuity during reuse, not generic action inheritance, Gradle execution changes, or the separate restart regression discussed in https://github.com/microsoft/vscode/issues/319536.
