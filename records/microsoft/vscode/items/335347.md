# Issue #335347 — Generate Commit Message shows "Sign in to use GitHub Copilot" dialog with BYOK models and utility models configured

[https://github.com/microsoft/vscode/issues/335347](https://github.com/microsoft/vscode/issues/335347)

## Summary

Real, traceable bug on current main: the SCM 'Generate Commit Message' sparkle action gates on chat setup being 'completed' but doesn't account for BYOK-configured users, so it wrongly triggers the sign-in flow even though the utility model is fully configured and would otherwise work.

## Change summary

Clicking the Source Control 'Generate Commit Message' sparkle with a BYOK main-agent model and BYOK utility models configured (no GitHub sign-in) shows a 'Sign in to use GitHub Copilot' modal instead of generating the commit message.

## Best solution

In src/vs/workbench/contrib/scm/browser/scmInput.ts, the registerAction2 for SCMInputWidgetCommandId.SetupAction has a menu `when` of `ChatContextKeys.Setup.hidden.negate()`, `ChatContextKeys.Setup.disabledInWorkspace.negate()`, `ChatContextKeys.Setup.completed.negate()` — this needs an added `ChatEntitlementContextKeys.hasByokModels.negate()` clause (the same escape hatch already used elsewhere, e.g. the titlebar sign-in action and the `chatRequiresSetup` helper in chatEntitlementService.ts) so BYOK-only users skip the setup/sign-in prompt and go straight to `product.defaultChatAgent.generateCommitMessageCommand`.
