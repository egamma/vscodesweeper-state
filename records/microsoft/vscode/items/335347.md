# Issue #335347 — Generate Commit Message shows "Sign in to use GitHub Copilot" dialog with BYOK models and utility models configured

[https://github.com/microsoft/vscode/issues/335347](https://github.com/microsoft/vscode/issues/335347)

## Summary

Traced on current main: the SCM sparkle's `when` clause gates on `ChatContextKeys.Setup.completed`, which stays false for a user who never ran the GitHub Copilot sign-in/entitlement flow — even when they've fully configured a working BYOK main agent + utility models. That routes the click through the anonymous/sign-in setup command instead of straight to `generateCommitMessageCommand`, producing the sign-in modal the reporters see.

## Change summary

Clicking the SCM 'Generate Commit Message' sparkle shows a 'Sign in to use GitHub Copilot' modal for a signed-out user who has configured BYOK main-agent and utility models, instead of generating the commit message.

## Best solution

Have the SCM generate-commit-message action (and its menu `when` clause in scmInput.ts) recognize a working BYOK configuration — e.g. treat the utility model as resolvable, or expose a broader signal than `ChatContextKeys.Setup.completed` — so it invokes `product.defaultChatAgent.generateCommitMessageCommand` directly instead of routing through `CHAT_SETUP_SUPPORT_ANONYMOUS_ACTION_ID`, which forces the sign-in dialog for never-signed-in BYOK users.

## Evidence

- **gating when-clause:** src/vs/workbench/contrib/scm/browser/scmInput.ts:843-855 binds the sparkle to `SCMInputWidgetCommandId.SetupAction` whenever `ChatContextKeys.Setup.completed.negate()` is true, and that action (lines 875-889) calls `CHAT_SETUP_SUPPORT_ANONYMOUS_ACTION_ID` before the real generate command.
- **anonymous setup path:** src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts:305-325 shows `ChatSetupTriggerSupportAnonymousAction` just forwards into `CHAT_SETUP_ACTION_ID`, the same flow that can present the 'Sign in to use GitHub Copilot' dialog (id `workbench.action.chat.triggerSetupForceSignIn`, line ~330-346) — it does not check for an already-working BYOK configuration.
- **utility model resolution works independently:** extensions/copilot/src/extension/prompt/vscode-node/endpointProviderImpl.ts `_resolveUtilityOverride` (lines ~255-300) resolves `chat.utilityModel`/`chat.utilitySmallModel` overrides via `lm.selectChatModels` without requiring a Copilot token, so once past the sign-in gate the actual commit-message generation should work — the modal is a UI routing issue, not a missing-model error.
- **related but distinct:** https://github.com/microsoft/vscode/issues/335403 reports a similar dialog from a timing race during chat activation; this report is about the SCM sparkle's own routing logic never considering BYOK completeness, so it isn't a confirmed duplicate of that thread.
