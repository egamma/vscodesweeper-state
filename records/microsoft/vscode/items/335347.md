# Issue #335347 — Generate Commit Message shows "Sign in to use GitHub Copilot" dialog with BYOK models and utility models configured

[https://github.com/microsoft/vscode/issues/335347](https://github.com/microsoft/vscode/issues/335347)

## Summary

Confirmed by two independent commenters and traced in source: the SCM 'Generate Commit Message' sparkle action gates purely on `ChatContextKeys.Setup.completed`, which stays false for users who never sign into GitHub, even when they have valid BYOK utility models configured — so it wrongly forces the sign-in dialog instead of honoring the BYOK configuration the way `chatRequiresSetup()` already does elsewhere.

## Change summary

Clicking the sparkle 'Generate Commit Message' button in the SCM input shows a 'Sign in to use GitHub Copilot' modal even though the user has never signed in and instead configured BYOK utility/utility-small models with `chat.byokUtilityModelDefault` set.

## Best solution

Have the SCM sparkle action's menu `when` clause and its `run()` in src/vs/workbench/contrib/scm/browser/scmInput.ts (and the analogous merge-conflict action in scm.contribution.ts) consult `ChatEntitlementContextKeys.hasByokModels` / the `chatRequiresSetup()` logic before invoking `CHAT_SETUP_SUPPORT_ANONYMOUS_ACTION_ID`, so BYOK-only users aren't routed through the GitHub sign-in flow for a feature they've already configured.

- **existing BYOK-aware helper:** src/vs/workbench/services/chat/common/chatEntitlementService.ts lines 177-197 define `chatRequiresSetup()` which explicitly treats `hasByokModels` as sufficient to skip setup (`(!context.completed && !context.hasByokModels) || ...`), and a bound context key `ChatEntitlementContextKeys.hasByokModels` (`github.copilot.hasByokModels`) already exists at line 75 — but neither is consulted by the SCM action.
