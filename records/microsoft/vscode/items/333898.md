# Issue #333898 — SDK shell misses local sandbox retry when a pipeline masks the denied command's exit code

[https://github.com/microsoft/vscode/issues/333898](https://github.com/microsoft/vscode/issues/333898)

## Summary

The reporter's own diagnosis and the codebase agree: the denial-vs-exit-code correlation and local outside-sandbox retry for the SDK's built-in shell tool live inside the vendored `@github/copilot` SDK/runtime, not in VS Code's own Agent Host custom terminal tool — this is an upstream dependency gap, and a VS Code team member already confirmed the repro.

## Change summary

A sandboxed SDK shell command that is denied but ends in a zero exit code (because a later pipeline stage succeeds) is returned to the model as a successful result instead of triggering the local outside-sandbox retry prompt that the standalone CLI already shows for the same command.

## Best solution

Track this as upstream work against the bundled Copilot Agent SDK (`@github/copilot`, currently pinned at 1.0.83-2 in package.json) to bring the VS Code session's denial-detection/retry path in line with the standalone CLI's behavior; nothing in this repo's own `copilotShellTools.ts` (the Agent Host custom tool) needs to change, since the reporter explicitly excludes it and the repo's own script-safety/possiblePaths wiring in `copilotSessionLauncher.ts` shows the runtime, not the host, owns this classification.
