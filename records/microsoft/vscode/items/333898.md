# Issue #333898 — SDK shell misses local sandbox retry when a pipeline masks the denied command's exit code

[https://github.com/microsoft/vscode/issues/333898](https://github.com/microsoft/vscode/issues/333898)

## Summary

Real, well-diagnosed gap confirmed by a maintainer's repro: VS Code's SDK shell integration has no host-side sandbox-denial detection for pipelines whose final stage masks an earlier denial with exit code 0, so it silently returns a false success instead of offering the local outside-sandbox retry.

## Change summary

A sandboxed pipeline command that is denied mid-pipeline but ends in exit code 0 is returned to the model as a success instead of triggering VS Code's local outside-sandbox retry approval.

## Best solution

Add host-side sandbox-denial correlation (using shellToolInfo.possiblePaths and the active sandbox policy, not just exit code/text matching) in the agent host's SDK shell integration, likely in src/vs/platform/agentHost/node/copilot/copilotShellTools.ts and its sandbox-engine/permission-request plumbing, so a masked denial triggers a single local outside-sandbox approval before the tool result reaches the model — mirroring the standalone CLI's behavior described in the issue.
