# Issue #164744 — [scss] Sass modules intellisense when using @use at-rules.

[https://github.com/microsoft/vscode/issues/164744](https://github.com/microsoft/vscode/issues/164744)

## Summary

The Sass module support documented for VS Code 1.41 covers syntax recognition, but current main still does not provide completion for `sass:` built-in modules or members such as `math.`. This remains a valid, well-defined language-feature gap in the Backlog.

## Change summary

Provide SCSS IntelliSense for Sass built-in module names in `@use` rules and for namespaced members such as `math.`.

## Best solution

Extend the CSS language service's SCSS completion support to understand Sass built-in module namespaces and their exported functions, mixins, and variables, then consume that support through VS Code's built-in CSS language features extension.

## Plan brief

- **Likely files:** `extensions/css-language-features/server/src/cssServer.ts`, `extensions/css-language-features/client/src/cssClient.ts`
- **Validation:** Add CSS language service completion tests for `@use 'sass:math'` module-name completion and `math.` member completion, then run the CSS language-features completion test suite against the updated service.
- **Behavior:**

  > In an SCSS document, completion after `@use 'sass:` should offer Sass built-in modules such as `sass:math`. After importing a built-in module, completion on its namespace, such as `math.`, should offer that module's public functions and other members. Existing CSS/SCSS completion behavior and valid Sass module syntax must remain unchanged.
- **Trace:**

  > VS Code supplies SCSS IntelliSense through the built-in CSS language-features extension and the vscode-css-languageservice dependency. The earlier language-service work at https://github.com/microsoft/vscode-css-languageservice/pull/183 recognizes Sass module syntax, while this report and its confirmations show that semantic completion for built-in module identifiers and namespace members remains separate work. The extension cited at https://github.com/wkillerud/vscode-scss demonstrates the desired behavior but is not VS Code's built-in provider. The plan should establish whether the language service will own a maintained Sass built-in symbol catalog and how imported namespace resolution behaves; do not broaden the work to general Sass package resolution unless explicitly chosen.
- **Open decisions:**
  - Should built-in IntelliSense cover only Sass's standard `sass:` modules, or also resolve symbols from user and package `@use` targets?
  - Should the built-in module symbol catalog be maintained statically with the language service or derived from the installed Sass implementation and version?
