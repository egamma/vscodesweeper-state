# Issue #134561 — Add stronger checks to make sure an extension doesn't activate both locally and remotely

[https://github.com/microsoft/vscode/issues/134561](https://github.com/microsoft/vscode/issues/134561)

## Summary

Team-authored debt item requesting stronger enforcement that an extension activates on only one extension host (local or remote, not both). Related work exists (e.g. commit c1b8d66 for #184180 considers already-activated extensions), but no commit references this issue and the broader enforcement described in the linked comment hasn't been fully realized. Keeping open.

## Change summary

Add stronger checks in the extension host activation path to prevent an extension from activating on both local and remote extension hosts simultaneously.

## Best solution

Implement validation in `extensionRunningLocationTracker.ts` and/or `abstractExtensionService.ts` that asserts an extension gets exactly one running location, logging or erroring when a dual-activation scenario is detected. The existing `pickExtensionHostKind` already picks one location, but the ask is for runtime enforcement and diagnostics.
