# Issue #134561 — Add stronger checks to make sure an extension doesn't activate both locally and remotely

[https://github.com/microsoft/vscode/issues/134561](https://github.com/microsoft/vscode/issues/134561)

## Summary

Keep open: current code chooses one running location during allocation but still does not check when activation from an extension host overwrites an extension's recorded location. This team-authored debt item therefore remains relevant.

## Change summary

Detect and prevent an extension from activating concurrently in both a local and remote extension host.

## Best solution

Enforce the single-running-location invariant at the activation boundary, preserving the original location and producing a useful diagnostic when another extension host reports activation for the same extension.

- **Behavior:**

  > An extension may activate repeatedly only from its selected extension-host location. If another local or remote host attempts to activate the same extension concurrently, VS Code must detect the invariant violation, retain the original location, and provide an actionable diagnostic. Normal activation and repeated notifications from the same host must remain unchanged.
- **Trace:**

  > Initial allocation in AbstractExtensionService._resolveAndProcessExtensions calls ExtensionRunningLocationTracker.initializeRunningLocation, which consolidates local and remote copies into one location. Activation notifications flow through AbstractExtensionService._onWillActivateExtension to ExtensionRunningLocationTracker.set; set currently overwrites the map entry without comparing the prior and reporting locations. Commit https://github.com/microsoft/vscode/commit/c1b8d66d4bd95e4a9020433f7ca69aa6e56e6530 preserves already activated locations during later allocation calculations, but it does not guard this activation-time overwrite. Keep the scope to enforcing and diagnosing this invariant; do not alter extension-kind selection, affinity assignment, or legitimate reactivation in the same host.
