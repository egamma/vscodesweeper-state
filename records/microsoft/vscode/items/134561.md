# Issue #134561 — Add stronger checks to make sure an extension doesn't activate both locally and remotely

[https://github.com/microsoft/vscode/issues/134561](https://github.com/microsoft/vscode/issues/134561)

## Summary

Team-authored debt item requesting stronger runtime guards to prevent an extension from activating on both local and remote extension hosts simultaneously. The current `determineExtensionHostKinds` picks one host kind per extension, but alexdima wants additional runtime assertions/checks to catch violations. Still valid — no evidence of a dedicated fix beyond the existing single-pick logic.

## Change summary

Add stronger runtime checks to ensure an extension never activates on both the local and remote extension hosts at the same time.

## Best solution

Add runtime assertions in the extension activation path (likely in `ExtensionRunningLocationTracker` and the extension host managers) that verify no extension is already running on another host kind before activation proceeds, logging or throwing if a duplicate activation is detected.
