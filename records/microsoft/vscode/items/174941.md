# Issue #174941 — Git - extension API gives repository remotes with aliases

[https://github.com/microsoft/vscode/issues/174941](https://github.com/microsoft/vscode/issues/174941)

## Summary

Still valid on main: the git extension API returns raw `insteadOf` aliases instead of resolved URLs. The primary remote-reading path (`getRemotesFS`) parses the config file directly and never resolves aliases; the fallback (`getRemotesGit` via `git remote --verbose`) also returns unresolved URLs. PR #238675 attempted a fix but was closed without merging.

## Change summary

The git extension API's `Remote.fetchUrl`/`pushUrl` fields return raw URL aliases (e.g. `gh:user/private`) instead of resolved URLs when `url.<base>.insteadOf` is configured in `.gitconfig`.

## Best solution

Use `git remote get-url <name>` (which resolves `insteadOf` aliases) to populate `fetchUrl`/`pushUrl` in the Remote objects exposed by the git extension API. The fix belongs in `extensions/git/src/git.ts` around the `getRemotesFS`/`getRemotesGit` methods. The vscode-pull-request-github extension has worked around this on their side (PRs #8245 and #8754), but fixing it in the core git extension API would benefit all consumers.
