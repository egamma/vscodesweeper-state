# Issue #330783 — LanguageModelChatProvider lacks a usage-reporting channel and cannot participate in auto-compact

[https://github.com/microsoft/vscode/issues/330783](https://github.com/microsoft/vscode/issues/330783)

## Summary

Well-researched, still-valid gap: third-party LanguageModelChatProvider implementations have no way to report token usage or context-length-exceeded errors, unlike BYOK providers baked into the Copilot Chat extension. Routing to the chat/API area for a maintainer proposal decision.

## Change summary

Extend the LanguageModelChatProvider API (stable or proposed) with a usage-reporting channel and a context-length-exceeded signal so third-party providers can report token usage and participate in auto-compaction.

## Best solution

A chat/API owner should design a provider-side usage part (or `usage?: ChatResultUsage` on the response/progress payload) and a dedicated LanguageModelError code for context-length-exceeded in src/vscode-dts/vscode.proposed.chatProvider.d.ts, mirroring how ChatResponseStream.usage() already works for chat participants.
