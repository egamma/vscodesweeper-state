# Issue #330783 — LanguageModelChatProvider lacks a usage-reporting channel and cannot participate in auto-compact

[https://github.com/microsoft/vscode/issues/330783](https://github.com/microsoft/vscode/issues/330783)

## Summary

Well-diagnosed gap confirmed against current main: third-party LanguageModelChatProvider implementations have no way to report token usage or a context-length-exceeded error, unlike BYOK providers embedded in Copilot Chat. It's a fresh Backlog Candidates item (2 days old, 0 upvotes) — should stay open for the normal 60-day community upvote process, not be closed for being quiet.

## Change summary

Add a usage-reporting channel and a context-length-exceeded error to the LanguageModelChatProvider API so third-party model providers can surface token usage and participate in auto-compaction, matching what built-in BYOK providers already get.

## Best solution

This belongs with the `chatProvider`/`chatParticipantAdditions` proposed-API owners: extend `ProvideLanguageModelChatResponseOptions`/`LanguageModelResponsePart2` (src/vs/vscode-dts/vscode.proposed.chatProvider.d.ts) with a usage part or callback, and add a dedicated `LanguageModelError` code (or an `onDidChangeContextUsage`-style event) so third-party providers can report usage and trigger compaction the way embedded BYOK providers do today.
