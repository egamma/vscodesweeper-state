[https://github.com/microsoft/vscode/issues/341745](https://github.com/microsoft/vscode/issues/341745)

## Summary

Thanks for the request. The Application scope is intentional in current code, so this is a feature request rather than a bug. Workspace-defined plugin enablement needs a security and workspace-trust decision, and there is no maintainer signal or demand beyond the reporter yet.

## Change summary

Allow chat.plugins.enabledPlugins to be set in workspace settings so repositories can version-control which agent plugins are enabled.

## Best solution

Maintainers should decide whether repo-defined plugin enablement is acceptable. If it is, it would likely be a restricted setting gated by workspace trust (see the restricted PluginLocations setting) rather than a plain scope change. The setting also carries an enterprise policy, so the interplay with workspace values needs defining.
