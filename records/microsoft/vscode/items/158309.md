# Issue #158309 — Git - Git error (Cannot fast-forward to multiple branches.) when syncing during autofetch

[https://github.com/microsoft/vscode/issues/158309](https://github.com/microsoft/vscode/issues/158309)

## Summary

Keep open while the explicitly linked fixing PR is reviewed: current source still allows automatic fetches to overwrite FETCH_HEAD during a pull. The original failure has multiple independent confirmations, and the proposed fix has not merged.

## Change summary

Prevent background Git fetches from disrupting concurrent sync or terminal pull operations with spurious multiple-branch fast-forward failures.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338109 to preserve FETCH_HEAD during automatic fetches while retaining manual-fetch behavior and older-Git compatibility. Assess the later remote-tracking-ref collision separately, since preserving FETCH_HEAD does not serialize concurrent ref updates.

- **Current background-fetch path:** extensions/git/src/autofetch.ts: AutoFetcher.run waits for whenIdleAndFocused(), then invokes fetchDefault({ silent: true }) or fetchAll({ silent: true }). extensions/git/src/git.ts: Repository.fetch, lines 2422–2453, only sets VSCODE_GIT_FETCH_SILENT for silent fetches; it does not pass --no-write-fetch-head.
- **Concurrent pull remains possible:** extensions/git/src/repository.ts: Repository._sync, lines 2549–2605, invokes _pullAndHandleTagConflict. Repository.run, lines 2859–2897, tracks operations but starts their callbacks without a shared fetch/pull queue. whenIdleAndFocused prevents autofetch from starting while already busy, but does not prevent a user pull from starting after autofetch begins. Terminal Git processes also bypass extension operation tracking.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/338109 is OPEN with mergedAt=null and explicitly declares 'Fixes #158309.'
