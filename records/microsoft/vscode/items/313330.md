# Issue #313330 — Race between replace_string_in_file and terminal commands in chat

[https://github.com/microsoft/vscode/issues/313330](https://github.com/microsoft/vscode/issues/313330)

## Summary

The stale terminal read follows the intentional chat-editing model: edit tools update VS Code's in-memory model and return without guaranteeing that the edit has reached disk. A maintainer has confirmed this ordering as expected behavior, so adding a timing delay to terminal commands is not an appropriate synchronization guarantee.

## Change summary

Ensure terminal commands issued after replace_string_in_file observe the newly edited file instead of stale disk content.

## Best solution

Keep the current model-backed edit and autosave behavior rather than adding a timing-dependent delay. Workflows requiring guaranteed consistency with external processes would need an explicit synchronized-save contract or access to the in-memory document state, which should be designed separately.
