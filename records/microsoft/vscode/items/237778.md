## Evidence

- **Complete reproduction:** https://github.com/microsoft/vscode/issues/237778 specifies VS Code 1.96.2, Ubuntu 24.04.1, VirtualBox 7.0.22 on Windows 11, Wayland, enabled 3D acceleration, and File > Open File as the trigger. Extensions are disabled and --disable-gpu did not help. No VM reproduction was executed.
- **Reporter-linked predecessor:** https://github.com/microsoft/vscode/issues/173727 is closed, so it cannot be a duplicate canonical. Its reporter confirmed that --ozone-platform=wayland --disable-gpu solved the older Ubuntu 22.04 case at https://github.com/microsoft/vscode/issues/173727#issuecomment-1422084881; this is workaround evidence, not a fixing commit for the present report. The present report spells the attempted option --ozone-playtform=wayland, so it does not establish the result of using the correctly spelled option.
- **Current native-dialog boundary:** src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts routes ordinary local-file opening through nativeHostService unless the simplified picker is enabled. DialogMainService.showOpenDialog in src/vs/platform/dialogs/electron-main/dialogMainService.ts delegates rendering to electron.dialog.showOpenDialog. This identifies the boundary but does not conclusively assign the rendering defect to Electron, GTK, Wayland, or VirtualBox.
- **Existing workaround:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers files.simpleDialog.enable, default false, to replace system file dialogs. FileDialogService.shouldUseSimplified honors it. It bypasses the affected native surface rather than correcting it.
- **History does not prove resolution:** FileDialogService history includes 4ae4d96052c5, 'chore: update to Electron 43', but a dependency update is not proof of a rendering fix. Commit 351f5ff43e086547bda8a0a19dcb4ac19b735ee2 changes disposal of drained dialog queues, not native-dialog painting.
- **Canonical search:** Repository issue searches for VirtualBox dialogs, dialog flickering, and native dialogs on Wayland did not establish an open canonical owning this exact failure. https://github.com/microsoft/vscode/issues/219703 describes related VirtualBox modal corruption but is closed and has no confirmed fix; neither closed report supports a duplicate close.
