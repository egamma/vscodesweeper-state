# Issue #349300 — Markdown preview editor opens at top instead of specified line

[https://github.com/microsoft/vscode/issues/349300](https://github.com/microsoft/vscode/issues/349300)

## Summary

Keep open: the associated Markdown preview still lacks explicit source-position navigation. Existing scroll synchronization does not deliver the requested CLI and editor-opening behavior.

## Change summary

Honor requested source lines when opening Markdown files in the associated preview editor.

## Best solution

Extend the built-in Markdown preview's navigation support so explicit opening positions reveal the corresponding rendered content, including when reusing an existing preview, while preserving scroll restoration for opens without a position.

- **Current preview initialization:** In extensions/markdown-language-features/src/preview/previewManager.ts, MarkdownPreviewManager.#resolveCustomTextEditor initializes StaticMarkdownPreview using only TopmostLineMonitor.getPreviousTextEditorLineByUri(document.uri). It does not consume an explicit opening selection, and the provider implements no resolveCustomTextEditorNavigation method.
- **Existing capability does not cover the ask:** extensions/markdown-language-features/package.json registers `markdown.preview.scrollPreviewWithEditor`, defaulting to true. TopmostLineMonitor in src/preview/topmostLineMonitor.ts observes visible text-editor ranges, and StaticMarkdownPreview in src/preview/preview.ts follows those updates. This synchronizes an actual text editor; it does not deliver a requested position when opening directly into the associated preview.
- **Navigation infrastructure exists but is not adopted by this preview:** src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts:74-79 forwards opening selections only when the input has a navigation controller. extensions/markdown-language-features/src/preview/markdownEditorProvider.ts:333 implements resolveCustomTextEditorNavigation for the separate Markdown editor provider, whereas MarkdownPreviewManager does not. The proposal being enabled in the extension manifest therefore does not establish coverage for `vscode.markdown.preview.editor`.
