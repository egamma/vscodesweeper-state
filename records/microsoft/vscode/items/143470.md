# Issue #143470 — Accessibility: allow advanced styling of explorer decorations

[https://github.com/microsoft/vscode/issues/143470](https://github.com/microsoft/vscode/issues/143470)

## Summary

A real accessibility-oriented styling gap remains on main: file decorations support foreground color, badges, and strikethrough, but not configurable backgrounds or underlines. The Backlog milestone and existing area labels already route this accepted, unscheduled request appropriately.

## Change summary

Allow themes to distinguish Explorer file states using accessible non-text styling such as badge backgrounds or underlines instead of recoloring filenames.

## Best solution

Extend the shared file-decoration model and renderer in `src/vs/workbench/services/decorations/` with a restrained non-text visual treatment that themes can configure, while preserving existing defaults and consistent rendering across Explorer, tabs, and other decoration consumers.

## Evidence

- **current source gap:** `src/vs/workbench/services/decorations/common/decorations.ts` exposes decoration color, letter/icon, and strikethrough, but no background or underline style.
- **renderer behavior:** `src/vs/workbench/services/decorations/browser/decorationsService.ts` generates CSS only for label foreground color and badge/icon foreground color; it emits no configurable background or underline rule.
- **existing Git colors:** `extensions/git/package.json` contributes only `gitDecoration.*ResourceForeground` colors, so current themes cannot implement the requested non-text Git-state treatment.
- **partial controls:** `src/vs/workbench/contrib/files/browser/files.contribution.ts` provides `explorer.decorations.colors` and `explorer.decorations.badges` boolean controls, but neither allows styling badge backgrounds or underlines.
