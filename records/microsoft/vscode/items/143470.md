# Issue #143470 — Accessibility: allow advanced styling of explorer decorations

[https://github.com/microsoft/vscode/issues/143470](https://github.com/microsoft/vscode/issues/143470)

## Summary

The requested theme-controlled backgrounds or underlines remain unavailable in the current file-decoration pipeline. Keep this accepted Backlog request open: existing color and badge switches provide a partial workaround, and the linked squiggle request does not cover its full scope.

## Change summary

Allow themes to distinguish file status using backgrounds, badge backgrounds, or underlines while preserving readable filename foreground colors.

## Best solution

Define a consistent, theme-controlled decoration treatment that preserves filename contrast and distinguishes status without relying on filename color. Settle the supported visual treatment and whether it applies only to built-in Git decorations or to all file-decoration providers before implementation.

- **Behavior:**

  > Theme authors currently cannot give Explorer file statuses backgrounds or underlines independently of filename foreground colors. The intended outcome is distinguishable status information while filenames retain readable contrast. Acceptance must cover the selected visual treatment in light, dark and high-contrast themes, including selected and focused rows. Existing decoration visibility controls and status tooltips must retain their behavior.
- **Trace:**

  > DecorationRule in src/vs/workbench/services/decorations/browser/decorationsService.ts constructs filename and badge foreground rules from IDecorationData in src/vs/workbench/services/decorations/common/decorations.ts. ResourceLabelWidget in src/vs/workbench/browser/labels.ts applies filename coloring and badges independently; explorer.decorations.colors=false is therefore a partial workaround, not advanced styling support. Git theme contributions in extensions/git/package.json expose status foregrounds, and the public FileDecoration contract in src/vscode-dts/vscode.d.ts has no background or underline channel. The source establishes the missing capability, but not which visual treatment or public contract should be adopted. Preserve theme-level consistency and existing selection/focus readability rather than introducing arbitrary CSS customization. https://github.com/microsoft/vscode/issues/119023 is a closed, narrower diagnostic-squiggle request, not a canonical for this work; the later comment about SCM group backgrounds is additional scope, not existing coverage.
- **Open decisions:**
  - Which theme-controlled treatments should be supported: filename backgrounds, badge backgrounds, underlines, or a defined subset?
  - Should alternate styling apply only to built-in Git statuses, or become available to all file-decoration providers through a public contract?
  - Should this request cover Explorer file decorations only, or also shared label surfaces and the separately requested SCM group backgrounds?
