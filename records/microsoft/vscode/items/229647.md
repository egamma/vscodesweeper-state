# Issue #229647 — Undo stacks are not granular enough for Korean

[https://github.com/microsoft/vscode/issues/229647](https://github.com/microsoft/vscode/issues/229647)

## Summary

Keep open: current composition handling still lacks explicit Korean character-level undo boundaries, and maintainers have supported improving this behavior. The related Chinese IME issue concerns a different observable outcome and does not absorb this request.

## Change summary

Make undo for Korean input remove the last consonant/vowel, or at least the last completed syllable, rather than an entire line or word.

## Best solution

Define Korean-aware undo granularity in the editor input and cursor pipeline, then validate it across macOS and Windows with both textarea and native EditContext input. Preserve ordinary typing and other IMEs' composition semantics.

- **Behavior:**

  > Korean sentence entry currently has overly coarse undo: the report identifies whole-line removal on macOS and whole-word removal on Windows. The goal is to undo the most recent consonant/vowel contribution, with removal of only the last completed syllable identified as an acceptable lesser improvement. Acceptance must define successive undo and redo states for multi-syllable text on both platforms and both editor input implementations. Ordinary non-Korean typing and unrelated IME conversion behavior must remain unchanged.
- **Trace:**

  > CompositionOperation.getEdits in src/vs/editor/common/cursor/cursorTypeEditOperations.ts emits TypingOther operations with no trailing undo stop, and shouldPushStackElementBetween groups consecutive operations of the same normalized type. Cursor.startComposition/endComposition in src/vs/editor/common/cursor/cursor.ts tracks the composition outcome but does not establish a general Korean undo boundary. NativeEditContext._onType routes replacement updates through compositionType and insertion-only updates through type; TextAreaEditContext likewise forwards composition lifecycle and replacement events into the cursor pipeline. These paths explain why composition edits can accumulate, but the actual Korean event sequences and macOS/Windows differences were not captured. Existing composition simulations in src/vs/editor/test/browser/controller/cursor.test.ts provide a validation starting point. https://github.com/microsoft/vscode/issues/229606 is related Chinese conversion work, not a duplicate; avoid changing its intermediate-input semantics accidentally.
- **Open decisions:**
  - Should the first supported behavior undo individual consonant/vowel contributions within a Korean syllable, or undo one completed syllable at a time?
