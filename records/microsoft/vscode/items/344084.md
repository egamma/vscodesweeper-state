# Issue #344084 — New remote (Codespace) installs synced extensions even when Extensions is unchecked in Settings Sync

[https://github.com/microsoft/vscode/issues/344084](https://github.com/microsoft/vscode/issues/344084)

## Summary

The current source confirms that first-connection remote initialization reads and installs synced extensions without checking whether Extensions sync is enabled. Keep this open for human review; the reported publisher-trust and environment-isolation concern also triggers the security-sensitive keep-open rule.

## Change summary

Prevent new remote environments from installing extensions from stale Settings Sync data when the user has unchecked Extensions.

## Best solution

Remote extension initialization should respect the Extensions resource's sync enablement while preserving explicitly configured remote installs. A maintainer should also assess the reported trust implications without treating a devcontainer extension list as an established security allowlist.

## Evidence

- **Exact trigger remains reachable:** In src/vs/workbench/contrib/extensions/electron-browser/remoteExtensionsInit.ts, RemoteExtensionsInitializerContribution.initializeRemoteExtensions checks for a native remote window, a new remote authority/workspace, global Settings Sync enablement, and an authentication session. It then calls readResource(SyncResource.Extensions, null) without checking isResourceEnabled(SyncResource.Extensions), matching the reporter's new-Codespace scenario with stale cloud extension data.
- **Independent resource enablement:** src/vs/platform/userDataSync/common/userDataSyncEnablementService.ts:55-70 stores and reads resource-specific enablement separately from global enablement. Disabling the Extensions resource therefore does not satisfy the initializer's existing global-disable guard.
- **Installation path:** RemoteExtensionsInitializer.doInitialize in src/vs/workbench/contrib/extensions/electron-browser/remoteExtensionsInit.ts passes the cloud list through generatePreview, selects compatible workspace-executable extensions, and installs them through the remote extension-management service with EXTENSION_INSTALL_SKIP_PUBLISHER_TRUST_CONTEXT set to true. AbstractExtensionsInitializer.generatePreview in src/vs/platform/userDataSync/common/extensionsSync.ts filters ignored extensions and existing installations, but does not check resource enablement.
- **Desktop versus web:** src/vs/workbench/contrib/extensions/electron-browser/extensions.contribution.ts:74 registers the initializer at LifecyclePhase.Restored, and the initializer explicitly skips windows without a local extension-management server. This supports the report's desktop-versus-web distinction.
- **Discussion and protection:** The reporter's comments on https://github.com/microsoft/vscode/issues/344084 confirm a personally observed installation burst and provide the prior synced extensions.json attachment. The body explicitly raises publisher-trust and isolation concerns; this warrants human assessment and bars a close or agent-ready recommendation, without establishing an exploitable vulnerability.
