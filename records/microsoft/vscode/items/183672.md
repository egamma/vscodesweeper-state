# Issue #183672 — Partial Accept Should Autoclose Brackets/String Quotes

[https://github.com/microsoft/vscode/issues/183672](https://github.com/microsoft/vscode/issues/183672)

## Summary

Keep this accepted feature request open: partial acceptance still inserts literal text without autoclosing brackets or quotes. The existing bracket-completion capability does not cover accepted prefixes, and no verified canonical or fixing commit was found.

## Change summary

Automatically close brackets and string quotes introduced by partially accepting an inline completion.

## Best solution

Extend inline-completion partial acceptance to produce appropriately paired delimiters while preserving continued acceptance, cursor placement, undo behavior, and language-specific autoclosing rules. Establish the behavior for multiple unmatched opening delimiters before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts`, `src/vs/editor/contrib/inlineCompletions/browser/model/provideInlineCompletions.ts`, `src/vs/editor/common/cursor/cursorTypeOperations.ts`, `src/vs/editor/contrib/inlineCompletions/test/browser/inlineCompletions.test.ts`
- **Validation:** Add cases to the Inline Completions suite for word and line acceptance ending at opening brackets or quotes, nested openers, an existing closing delimiter, continued acceptance, and undo. Run ./scripts/test.sh --run src/vs/editor/contrib/inlineCompletions/test/browser/inlineCompletions.test.ts; assert document text, cursor positions, and remaining ghost text after each acceptance.
- **Behavior:**

  > Partially accepting an inline suggestion should close brackets and string quotes introduced by the accepted text, rather than leave the document unexpectedly unpaired. Closing must account for language rules and existing document delimiters without introducing duplicates. Subsequent acceptance must preserve the intended final suggestion, and undo and multicursor behavior must remain coherent. Acceptance checks should cover both word and line commands, quotes, nested brackets, nearby closers, and continued acceptance.
- **Trace:**

  > InlineCompletionsModel.acceptNextWord and acceptNextLine both reach _acceptNext in src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts, which applies the accepted ghost-text prefix as literal edits and reports its accepted length. CodeEditorWidget.edit forwards those edits to executeEdits, bypassing the keyboard typing interceptors in cursor.ts. The completeBracketPairs provider option in provideInlineCompletions.ts repairs the full suggestion, not the accepted prefix. The existing inlineCompletions.test.ts contains partial-acceptance, forward-stability, and multicursor coverage that can exercise the resulting document and ghost text. Preserve full-accept and snippet semantics and do not broadly change normal typing interception. The remaining design uncertainty is the extent of autoclosure when one accepted chunk introduces several unmatched openers; https://github.com/microsoft/vscode/issues/183672#issuecomment-1980405456 confirms an earlier prototype encountered issues.
- **Open decisions:**
  - When a partially accepted chunk introduces several unmatched opening delimiters, should acceptance close every newly opened pair or only the pair at the acceptance boundary?
