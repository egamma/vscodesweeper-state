# Issue #296393 — Add setting to auto-expand tool calls and edits in chat view

[https://github.com/microsoft/vscode/issues/296393](https://github.com/microsoft/vscode/issues/296393)

## Summary

A real gap remains: current settings alter tool grouping or expand specific failure/progress cases, but none makes all tool calls, edits, and progress disclosures start expanded. This team-authored feature request should remain open for a scope decision and implementation plan.

## Change summary

Add a user setting that makes collapsible tool calls, edits, and progress items in chat responses expanded by default.

## Best solution

Provide one coherent chat preference for the initial disclosure state of relevant agent activity while preserving manual per-item toggles. The chat area should first define whether this covers only tool/edit/progress activity or every collapsible response part.

## Vision fit

- **Fit:** aligned
- **Reason:** Making agent activity inspectable supports VS Code's durable investment in AI-assisted development without adding default UI for users who leave the setting disabled.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/constants.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatCollapsibleContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatSimpleToolProgressPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatInputOutputMarkdownProgressPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatToolInputOutputContentPart.test.ts`
- **Validation:** Extend the chat content-part browser tests to verify that representative tool, edit, and progress disclosures start expanded when the new setting is enabled, remain collapsed under the default setting, and continue honoring a user's manual toggle across re-rendering.
- **Behavior:**

  > Chat should offer an opt-in preference that makes the selected classes of agent activity start expanded, exposing their details without repeated clicks. The default experience must remain unchanged when the preference is disabled. Manual expansion or collapse must continue to take precedence for an already-rendered item and survive its normal re-render lifecycle. Acceptance should cover representative tool calls, edit summaries, and progress items rather than only one renderer.
- **Trace:**

  > Configuration is registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts, with identifiers in src/vs/workbench/contrib/chat/common/constants.ts. Tool disclosure defaults currently enter through ChatSimpleToolProgressPart and ChatInputOutputMarkdownProgressPart, which fall back to collapsed and remember per-invocation user state in WeakMaps. Other requested surfaces use separate implementations beneath src/vs/workbench/contrib/chat/browser/widget/chatContentParts/, so this is not confined to one constructor. Existing `chat.agent.thinking.collapsedTools`, `chat.tools.autoExpandFailures`, and `chat.experimental.persistentProgressVerbosity` are partial controls and must retain their established meanings. The related https://github.com/microsoft/vscode/issues/312289 concerns an extension-controlled subagent default and should not replace this user preference.
- **Open decisions:**
  - Should the setting govern only agent activity disclosures such as tool calls, edits, and progress, or every collapsible response part including references, questions, notifications, and review controls?
  - When another specialized setting requests a different initial state, which user-observable preference takes precedence?

## Evidence

- **remaining gap:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatSimpleToolProgressPart.ts and chatInputOutputMarkdownProgressPart.ts pass `false` as the fallback expanded state, retaining only a user's prior state for the same invocation.
- **partial existing settings:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.agent.thinking.collapsedTools` and `chat.tools.autoExpandFailures`; src/vs/workbench/contrib/chat/browser/chatProgressConfiguration.ts registers `chat.experimental.persistentProgressVerbosity`. These cover grouping, terminal failures, or persistent-progress tool chains, not the requested default for all tool, edit, and progress disclosures.
- **cross-cutting disclosure state:** Collapsible state is owned by several distinct content parts under src/vs/workbench/contrib/chat/browser/widget/chatContentParts/, including generic ChatCollapsibleContentPart-based rows and specialized tool, change-summary, and confirmation implementations.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/312289 is open but was filed later and narrowly requests an extension API for subagent sections; under the re-review duplicate rule it cannot be the canonical for this older, broader user-setting request.
