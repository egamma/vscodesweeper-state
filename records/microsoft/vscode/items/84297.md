# Issue #84297 — API support for Timeline view

[https://github.com/microsoft/vscode/issues/84297](https://github.com/microsoft/vscode/issues/84297)

## Summary

Keep open: the Timeline provider API is implemented but remains proposed, and the `api-proposal` label makes this a protected API-finalization tracker. Strong extension-author demand remains, while workspace-scoped timelines and cache/update semantics still need public-contract decisions.

## Change summary

Finalize a public Extension API for contributing extension-provided entries to the unified file Timeline view.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.proposed.timeline.d.ts`, `src/vs/platform/extensions/common/extensionsApiProposals.ts`, `src/vs/workbench/api/common/extHostTimeline.ts`, `src/vs/workbench/api/common/extHost.api.impl.ts`, `src/vs/workbench/contrib/timeline/common/timeline.ts`, `src/vs/workbench/contrib/timeline/browser/timelinePane.ts`
- **Validation:** The plan should end with an Extension API test exercising provider registration, paging, refresh/reset behavior, and the chosen resource/workspace scope through the extension-host bridge, plus API declaration generation checks for the finalized surface.
- **Behavior:**

  > Published Marketplace extensions can register Timeline providers through stable VS Code API and contribute chronologically ordered entries to the Timeline view. Paging, refresh, removal, and cache behavior have documented, deterministic semantics. The finalized contract explicitly defines whether providers are file-scoped only or can contribute workspace-scoped entries, and existing built-in Git and Local History timeline behavior remains unchanged.
- **Trace:**

  > The proposed contract is in src/vscode-dts/vscode.proposed.timeline.d.ts and is registered under `timeline` in src/vs/platform/extensions/common/extensionsApiProposals.ts. Extension registration enters through src/vs/workbench/api/common/extHost.api.impl.ts and ExtHostTimeline in src/vs/workbench/api/common/extHostTimeline.ts, then bridges to the timeline service and TimelinePane. TimelinePane currently requires a URI before loading, matching the unresolved workspace-scope discussion in https://github.com/microsoft/vscode/issues/94303. Internal TimelineOptions also carries resetCache/cacheResults fields absent from the proposed declaration, while https://github.com/microsoft/vscode/issues/145984 records the missing targeted-removal behavior. Keep the boundary to API finalization and compatibility; do not redesign unrelated Timeline presentation or replace the separate SCM history proposal at https://github.com/microsoft/vscode/issues/185269.
- **Open decisions:**
  - Should the stable provider contract remain resource-scoped, or support workspace-scoped timelines when no active resource URI exists?
  - What stable change semantics should providers expose for additions, targeted removals, refreshes, and full resets?
  - Should cache control remain entirely internal, or does the stable API need an explicit provider-visible cache or forced-refresh contract?

## Evidence

- **protected proposal tracker:** The issue carries `api-proposal`; policy requires proposal-tracking issues to remain open until the API is finalized or explicitly abandoned by its owners.
- **current proposed surface:** src/vscode-dts/vscode.proposed.timeline.d.ts still declares TimelineItem, TimelineProvider, TimelineOptions, and workspace.registerTimelineProvider, and src/vs/platform/extensions/common/extensionsApiProposals.ts still registers `timeline` as a proposed API.
- **implemented but not finalized:** src/vs/workbench/api/common/extHostTimeline.ts implements provider registration, item conversion, change events, paging, and extension-host/main-thread bridging; this proves proposed implementation, not stable API completion.
- **unsettled workspace scope:** https://github.com/microsoft/vscode/issues/94303 remains open for timeline providers without a resource URI, and src/vs/workbench/contrib/timeline/browser/timelinePane.ts currently stops loading when `this.uri` is undefined.
- **unsettled update contract:** https://github.com/microsoft/vscode/issues/145984 remains open because providers can only signal removal through a full reset; the issue discussion also identifies workspace-scoped timelines as a finalization blocker.
- **demand:** The issue has 66 body upvotes and repeated extension-author requests through September 2026; https://github.com/microsoft/vscode/issues/154362 was explicitly closed as a duplicate of this canonical tracker.
- **related but distinct API:** https://github.com/microsoft/vscode/issues/185269 is an open SCM history-provider proposal and does not absorb the broader multi-source Timeline contribution API tracked here.
