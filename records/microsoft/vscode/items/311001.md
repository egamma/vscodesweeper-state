# Issue #311001 — Agent Plugins: Add support for "userConfig" to inject inputs into MCP configs.

[https://github.com/microsoft/vscode/issues/311001](https://github.com/microsoft/vscode/issues/311001)

## Summary

Plugin-provided input declarations still have no supported path into MCP prompting in the inspected source. Keep this accepted Backlog request open; existing manual MCP inputs and newer migration work do not deliver the requested plugin configuration experience.

## Change summary

Allow agent plugins to declare user-supplied MCP configuration values and prompt for them, including sensitive inputs.

## Best solution

Provide a supported plugin input contract that supplies values to plugin-contributed MCP servers without requiring users to recreate their configurations manually. Settle whether that contract supports Claude-style userConfig, VS Code inputs, or both, including consistent sensitive-value handling across supported runtimes.

## Plan brief

- **Likely files:** `src/vs/platform/agentPlugins/common/pluginParsers.ts`, `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts`, `src/vs/workbench/contrib/mcp/common/discovery/pluginMcpDiscovery.ts`, `src/vs/workbench/contrib/mcp/common/mcpRegistry.ts`, `src/vs/workbench/contrib/mcp/test/common/pluginMcpDiscovery.test.ts`
- **Validation:** Extend plugin parsing and pluginMcpDiscovery tests with declarations under the agreed input contract. Validate interactively that starting a plugin-contributed MCP server prompts for its declared endpoint and sensitive token, substitutes the supplied values, masks sensitive entry, and handles cancellation without launching with unresolved placeholders; existing manually configured MCP inputs must remain unchanged.
- **Behavior:**

  > An installed agent plugin can declare configuration values required by its MCP servers, and users can supply them through an integrated prompt rather than recreating the server manually. Sensitive declarations must receive password-style input handling. Acceptance should cover non-sensitive and sensitive substitution, cancellation, and unchanged behavior for plugins without inputs and manually configured MCP servers.
- **Trace:**

  > AbstractAgentPluginDiscovery in src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts observes mcpServers and passes embedded definitions to parseMcpServerDefinitionMap without sibling input metadata. The shared parser in src/vs/platform/agentPlugins/common/pluginParsers.ts constructs server definitions and handles plugin-root/environment interpolation, but does not carry userConfig declarations. PluginMcpDiscovery._toServerDefinition in src/vs/workbench/contrib/mcp/common/discovery/pluginMcpDiscovery.ts enables generic variable replacement without supplying a plugin input contract; McpRegistry in src/vs/workbench/contrib/mcp/common/mcpRegistry.ts owns interactive resolution. This establishes the missing metadata path, not the appropriate public schema or cross-runtime behavior. Preserve existing plugin discovery, enablement and manually configured MCP input semantics. https://github.com/microsoft/vscode/issues/340161 provides related portable-configuration context but does not own this request.
- **Open decisions:**
  - Should the public plugin input contract accept Claude-style userConfig, VS Code inputs, or both?
  - Must plugin input prompting work across agent-host providers as well as VS Code's local MCP runtime, and what behavior should users see in runtimes that cannot prompt?
