[https://github.com/microsoft/vscode/issues/277958](https://github.com/microsoft/vscode/issues/277958)

## Summary

Keep open: current source still allows Windows-host Copilot PATH contributions to corrupt Linux remote terminals, and the discussion contains independent confirmation. An open draft PR addresses the same defect through a newer report; review that candidate rather than starting another implementation.

## Change summary

Prevent locally hosted Copilot Chat from injecting Windows paths and semicolon separators into Linux remote terminal PATH, breaking the code command.

## Best solution

Preserve the remote terminal's valid PATH entries without injecting unusable host-local command directories. Review https://github.com/microsoft/vscode/pull/296268 against this report's Windows-to-Linux reproduction, including persisted contributions and shell-integration application, before considering the issue resolved.

## Evidence

- **Independent reproduction:** https://github.com/microsoft/vscode/issues/277958#issuecomment-5265282656 confirms Windows-to-Ubuntu reproduction independently of the original RHEL report. The ptyHost PATH is clean, but its child shell receives a Windows copilotCli path ending in a semicolon, fusing it with the remote-cli directory and preventing code command resolution.
- **Current contribution source:** extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLITerminalIntegration.ts:92-100 derives copilotCli from the extension host's globalStorageUri.fsPath and contributes it unconditionally. extensions/copilot/src/platform/terminal/vscode/terminalServiceImpl.ts:165-172 joins contributions using path.delimiter and prepends or appends them without a terminal-target check. extensions/copilot/src/util/vs/base/common/path.ts:1591 selects the delimiter using the host platform.
- **Current application source:** src/vs/platform/terminal/common/environmentVariableCollection.ts:71-105 applies resolved mutator strings directly: Prepend concatenates value with the existing environment variable, and shell-integration application serializes the same value. No Windows-path rejection or target-platform translation exists on this path. Thus a Windows copilotCli directory followed by ';' does not delimit the following Linux remote-cli directory.
- **Related report is younger:** https://github.com/microsoft/vscode/issues/286553 is open, was created on 2026-01-08, and reports the same Windows-path injection and broken remote code command. It addresses the same defect but has not merged, so it is neither a completed fix nor grounds for another agent implementation.
