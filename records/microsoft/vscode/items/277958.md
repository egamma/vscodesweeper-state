# Issue #277958 — GitHub.copilot-chat incorrectly contributing Windows PATH components to Linux terminal (via Remote-SSH)

[https://github.com/microsoft/vscode/issues/277958](https://github.com/microsoft/vscode/issues/277958)

## Summary

Still reproduces on main: when the Copilot extension runs as a UI extension on Windows with a Linux remote via Remote-SSH, the PATH contribution in terminalServiceImpl.ts uses the local `path.delimiter` (`;`) and local `path.join` (backslashes), injecting Windows-style paths into the Linux terminal's PATH. No fix has landed.

## Change summary

Copilot Chat contributes Windows-style PATH components (backslash paths, semicolon delimiters) to Linux terminals when connected via Remote-SSH and the extension runs as a UI extension.

## Best solution

The `updateEnvironmentPath()` method in `extensions/copilot/src/platform/terminal/vscode/terminalServiceImpl.ts` needs to use the remote platform's path delimiter (`:`) and path format instead of the local `path.delimiter`. The `contributePath` callers also need to provide paths appropriate for the remote OS. Alternatively, the extension's `extensionKind` should ensure it always runs on the remote side when a remote is active, so `path` APIs match the terminal's platform.
