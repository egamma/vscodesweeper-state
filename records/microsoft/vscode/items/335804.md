# Issue #335804 — I get the auto-closing bracket even when one is present

[https://github.com/microsoft/vscode/issues/335804](https://github.com/microsoft/vscode/issues/335804)

## Summary

Team-authored bug report from verification testing of the recently-closed #335556 fix; the source shows a real gap — `hasUnmatchedClosingBracketAfter` intentionally returns `false` while background tokenization for the whole file is still catching up, so on large files the auto-close bracket balance check is skipped and a closing bracket gets inserted even though one already exists later in the file.

## Change summary

Typing an opening bracket in a large file still triggers auto-closing insertion even when a matching closing bracket is already present further down, apparently because the bracket-balance check is deferred until whole-file tokenization completes.

## Best solution

Investigate `hasUnmatchedClosingBracketAfter` in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/bracketPairsTree.ts (the `hasAccurateTokensForLine` early-return) and decide the right perf/correctness trade-off for large files where background tokenization for the whole document hasn't finished yet — this is a design call for the editor/bracket-pair-colorization owners, not a trivial guard.
