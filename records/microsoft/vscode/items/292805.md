# Issue #292805 — Visually indicate the currently active Copilot account in the VS Code Chat Side Bar

[https://github.com/microsoft/vscode/issues/292805](https://github.com/microsoft/vscode/issues/292805)

## Summary

Keep open under discussion: maintainers agreed that the active Copilot account should become visible through a dedicated Copilot entry in the Accounts menu, but current main still lacks that entry and an account-switching interaction.

## Change summary

Make the GitHub account currently used by Copilot visible in normal VS Code UI and provide a discoverable way to switch it.

## Best solution

Follow the maintainer-supported consolidated design: expose the active Copilot account through a dedicated entry in the Accounts menu, update it when the default account changes, and decide whether that entry also performs account switching. Avoid duplicating identity information across the Chat sidebar, status dashboard, and Accounts menu unless contextual visibility is still considered necessary.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/globalCompositeBar.ts`, `src/vs/workbench/services/accounts/browser/defaultAccount.ts`, `src/vs/workbench/test/browser/parts/globalCompositeBar.test.ts`
- **Validation:** Extend the GlobalCompositeBar account-menu tests to cover two GitHub accounts: the menu must identify the current default Copilot account, react to `onDidChangeDefaultAccount`, and, if switching is approved, invoke the selected account-preference action.
- **Behavior:**

  > When multiple GitHub accounts are signed in, users can identify which account Copilot currently uses from a normal, discoverable VS Code surface without opening the Extensions view. The indicator updates when the default Copilot account changes and distinguishes the selected account unambiguously by account name, not only by avatar. The planning session should settle whether this surface also switches accounts and whether the consolidated Accounts-menu entry fully replaces the requested Chat-sidebar and usage-popover indicators.
- **Trace:**

  > The selected Copilot identity is represented by `IDefaultAccountService.currentDefaultAccount` in src/vs/workbench/services/accounts/browser/defaultAccount.ts, with changes broadcast through `onDidChangeDefaultAccount`. `AccountsActivityActionViewItem` in src/vs/workbench/browser/parts/globalCompositeBar.ts already listens to that event and uses the selected account to choose the Accounts activity avatar, but `resolveMainMenuActions` only builds generic provider account submenus and does not identify a Copilot-selected account. The existing tests in src/vs/workbench/test/browser/parts/globalCompositeBar.test.ts cover default-account avatar selection but not menu identity or switching. The related token-selection defect remains separately tracked at https://github.com/microsoft/vscode/issues/291504 and must not be treated as solved by this UI work.
- **Open decisions:**
  - Should the dedicated Copilot entry in the Accounts menu be an indicator only, or should selecting it directly allow choosing the Copilot account?
  - Does the consolidated Accounts-menu entry satisfy the visibility requirement, or should the active account also appear contextually in the Chat status or usage surface?

## Evidence

- **maintainer direction:** Maintainer comments on https://github.com/microsoft/vscode/issues/292805 converge on a dedicated Copilot entry in the Accounts menu: sandy081 proposed consolidating account information there, and TylerLeonhardt agreed that it follows existing Settings Sync, Cloud Changes, and Tunnels patterns.
- **current source gap:** On current main, src/vs/workbench/browser/parts/globalCompositeBar.ts resolves generic authentication-provider account submenus and Codex actions, but does not create a dedicated Copilot account entry or display `IDefaultAccountService.currentDefaultAccount.accountName` in the menu.
- **available account state:** src/vs/workbench/services/accounts/browser/defaultAccount.ts exposes `currentDefaultAccount` and `onDidChangeDefaultAccount`; src/vs/workbench/browser/parts/globalCompositeBar.ts already consumes them to prefer the default account avatar, so the selected Copilot identity is available to the workbench UI.
- **related but distinct bug:** https://github.com/microsoft/vscode/issues/291504 is older and tracks Copilot using the wrong token after an account-preference change. It is not a duplicate canonical for this re-reviewed feature request because its observable symptom is incorrect account selection, whereas this issue asks for persistent identity visibility and switching UI.
- **remaining gap:** The current avatar preference is only a visual avatar on the general Accounts activity item; it neither names the active Copilot account nor provides the dedicated Copilot menu entry and switching flow discussed by maintainers.
