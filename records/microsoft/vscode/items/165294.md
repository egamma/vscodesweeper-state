# Issue #165294 — Enable opting out of particular actions in the ActionWidget

[https://github.com/microsoft/vscode/issues/165294](https://github.com/microsoft/vscode/issues/165294)

## Summary

A real gap remains: terminal quick fixes retain action and source identifiers, but the ActionWidget rows do not expose or persist per-action opt-outs. This team-authored request is accepted in the On Deck milestone, so it should remain open for design and implementation.

## Change summary

Allow users to disable a particular ActionWidget action, such as the terminal's Create PR quick fix from the built-in Git source.

## Best solution

Provide a consistent per-action opt-out backed by a stable source-and-action identity, with persistent state and a discoverable way to restore disabled actions. Terminal quick fixes should adopt the generic ActionWidget removal affordance without requiring users to disable all terminal quick fixes.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts`, `src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFix.ts`, `src/vs/workbench/contrib/terminalContrib/quickFix/test/browser/quickFixAddon.test.ts`, `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`
- **Validation:** Add a QuickFixAddon test that opts out of the built-in Git Create PR action, recreates or refreshes the quick-fix path, and verifies that Create PR stays absent while another eligible quick fix remains available; also verify that restoring the action makes it appear again.
- **Behavior:**

  > A user can opt out of one ActionWidget action without disabling unrelated actions or the entire terminal quick-fix feature. The disabled action remains hidden for the chosen persistence scope, and users have a discoverable way to restore it. Disabling the built-in Git Create PR action must leave other eligible terminal quick fixes available.
- **Trace:**

  > TerminalQuickFixAddon.showMenu in src/vs/workbench/contrib/terminalContrib/quickFix/browser/quickFixAddon.ts converts ITerminalAction values into TerminalQuickFixItem objects carrying action id and source, then toActionWidgetItems creates rows without removal behavior or exclusion filtering. IActionListItem in src/vs/platform/actionWidget/browser/actionList.ts already supports onRemove and renders the shared close-button affordance. The only existing terminal control is the global terminal.integrated.shellIntegration.quickFixEnabled boolean in src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts. The boundary is granular ActionWidget action preference handling: do not change matching, execution, or the semantics of unrelated quick fixes. The uncertainty starts at the persistence and restoration contract, not at the identified rendering path.
- **Open decisions:**
  - Should an action opt-out persist globally with the user/profile, per workspace, or only for the current window/session?
  - Where should users inspect and restore disabled actions so an accidental opt-out is reversible and discoverable?
  - Should the stable public identity be the source-and-action-id pair for all ActionWidget consumers, or should persistence initially be limited to terminal quick fixes?
