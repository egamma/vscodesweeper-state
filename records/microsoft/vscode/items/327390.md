# Issue #327390 — Eagerly re-check for PRs when a PR link is emitted in chat turn

[https://github.com/microsoft/vscode/issues/327390](https://github.com/microsoft/vscode/issues/327390)

## Summary

Keep open for a timing decision: current main already discovers branch PRs at turn end, but the inspected contribution does not refresh when a PR link arrives during the turn. This team-authored request has neither an explicitly referencing fix nor a verified older duplicate.

## Change summary

Use a PR link emitted by the agent as an early signal to refresh the current branch/session's PR association and icon.

## Best solution

Build on the existing folder-scoped PR discovery pipeline rather than introducing separate icon state. Establish whether turn-end discovery already addresses the reported delay; if an earlier update remains necessary, define when an emitted link should trigger a coalesced, branch-validated lookup.
