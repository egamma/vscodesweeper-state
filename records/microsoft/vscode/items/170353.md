# Issue #170353 — Incorrect prioritization of filename suggestions in quick open dialog (Ctrl+P)

[https://github.com/microsoft/vscode/issues/170353](https://github.com/microsoft/vscode/issues/170353)

## Summary

Keep open: the current scorer still discards the later contiguous match in the reported path, allowing scattered matches to rank higher. The older related reports are closed, cover a different ranking mechanism, or collect multiple independent improvements rather than owning this specific defect.

## Change summary

Quick Open ranks scattered matches above the contiguous directory name when searching for "ftu index" or "glossary ftu index".

## Best solution

Make the scorer retain the better consecutive alignment for the reported paths without sacrificing existing filename, boundary, and abbreviation ranking. Establish the regression case and assess the shared algorithm's ranking and performance constraints before changing it.

## Evidence

- **Current source diagnosis:** In src/vs/base/common/fuzzyScorer.ts, doScoreFuzzy retains only the winning prefix score and its consecutive-match state. For query "ftu" against files/en-us/glossary/ftu/index.md, the initial f receives the start-of-string bonus; the later f after / loses that comparison, so its potentially better contiguous continuation is discarded. computeCharScore and scoreSeparatorAtPos still implement the competing bonuses described in the discussion.
- **Quick Open adoption:** src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts:getAdditionalPicks sorts file results through compareItemsByFuzzyScore and obtains highlights through scoreItemFuzzy. In src/vs/base/common/fuzzyScorer.ts, doScoreItemFuzzyMultiple scores query pieces independently, and doScoreItemFuzzySingle sends directory matches through scoreFuzzy on description plus filename. The reported multiword queries therefore reach the implicated algorithm.
- **Discussion and diagnostic PR:** The discussion at https://github.com/microsoft/vscode/issues/170353 supplies a concrete mdn/content reproduction and a scorer matrix identifying the lost contiguous alignment. https://github.com/microsoft/vscode/pull/171308 was merged to improve diagnostic output, not to fix ranking.
