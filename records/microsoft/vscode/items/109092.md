# Issue #109092 — [html] Unecessary warning when script contains quotes on the same line as an onFoo attribute using the same quotes

[https://github.com/microsoft/vscode/issues/109092](https://github.com/microsoft/vscode/issues/109092)

The false JavaScript diagnostic remains traceable on current main, and the open Volar integration PR explicitly lists this issue among its fixes. Keep the issue open while that human-owned implementation is reviewed.

## Change summary

HTML JavaScript validation produces an unnecessary warning when an inline script and a same-quoted event-handler attribute occur on one line.

## Best solution

Review and either land or close https://github.com/microsoft/vscode/pull/171547; the resulting HTML embedded-language implementation should keep script bodies and event-handler attributes syntactically isolated during JavaScript validation.

## Evidence

- **current source path:** On current main, extensions/html-language-features/server/src/modes/embeddedSupport.ts collects both `<script>` contents and `on*` attribute values as JavaScript regions, then `getEmbeddedDocument` concatenates them into one whitespace-preserving virtual document. For the reported single-line input this places `"L"` and `show();` on the same generated JavaScript line, while inserting a newline in the HTML also inserts one in the virtual document.
- **validation path:** extensions/html-language-features/server/src/modes/javascriptMode.ts passes each generated embedded document to TypeScript's `getSyntacticDiagnostics`, explaining why the malformed combined virtual source produces a warning even though the original HTML is valid.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/171547 remains open and explicitly includes `Fixes #109092`; it replaces the built-in HTML embedded-language implementation with the Volar-based path.
- **reported workaround:** https://github.com/microsoft/vscode/issues/109092 includes an exact input and screenshot, and shows that splitting the script and anchor across lines suppresses the diagnostic, matching the current whitespace-preserving virtual-document behavior.
