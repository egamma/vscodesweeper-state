# Issue #31829 — macOS: Copying text to clipboard does not preserve tabs

[https://github.com/microsoft/vscode/issues/31829](https://github.com/microsoft/vscode/issues/31829)

## Summary

The original non-breaking-space behavior was partly fixed on macOS, but current main still converts tabs to ordinary spaces in the HTML clipboard representation. Rich-text macOS applications can therefore still lose the source tabs.

## Change summary

Preserve tab characters when copying syntax-highlighted editor text into macOS rich-text applications.

## Best solution

Make the HTML clipboard representation preserve source whitespace semantics while retaining visual indentation, likely by emitting literal tabs with appropriate `white-space` and `tab-size` styling in the editor clipboard path. Coordinate the cross-platform behavior with https://github.com/microsoft/vscode/issues/88178.

## Evidence

- **current source:** src/vs/editor/browser/controller/editContext/clipboardUtils.ts writes both the model-derived plain text and syntax-highlighted HTML to the clipboard; rich consumers may select the HTML representation.
- **tab conversion:** src/vs/editor/common/languages/textToHtmlTokenizer.ts converts every tab into enough space characters to reach the next tab stop instead of retaining a tab character.
- **partial fix:** Commit b6138b95268aea0768f77ae8e4eacbcc0621bf07, shipped in 1.40.0, stopped using non-breaking spaces on macOS but still converted tabs to regular spaces; it fixed https://github.com/microsoft/vscode/issues/80825 rather than fully implementing this issue's request.
- **related open issue:** https://github.com/microsoft/vscode/issues/88178 remains open for the corresponding Windows HTML-whitespace behavior; it is related but does not supersede this older macOS tab-preservation report.
