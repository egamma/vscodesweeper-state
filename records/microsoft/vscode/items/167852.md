# Issue #167852 — Hard coding of Username and password in VS code passthrough Proxy.

[https://github.com/microsoft/vscode/issues/167852](https://github.com/microsoft/vscode/issues/167852)

## Summary

Team-authored feature request for proxy authentication without hardcoded credentials. VS Code already supports Kerberos/Negotiate auth and the `http.proxyAuthorization` header, but the ask for seamless passthrough auth (NTLM/Windows credentials) without embedding them in the proxy URL remains a gap for corporate environments.

## Change summary

Allow proxy authentication in VS Code without requiring users to hardcode username and password in the proxy URL string.

## Best solution

The existing Kerberos support (`http.proxyKerberosServicePrincipal`) partially addresses this for Kerberos environments. For NTLM/Windows-credential passthrough scenarios, the platform request layer would need to integrate with OS credential stores or support negotiate-style auth flows automatically. This remains a valid gap for enterprise users behind authenticating proxies.
