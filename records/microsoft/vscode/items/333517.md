# Issue #333517 — `ctrl + enter` doesn't "create" in the New automation modal

[https://github.com/microsoft/vscode/issues/333517](https://github.com/microsoft/vscode/issues/333517)

## Summary

Team-authored (alexr00, MEMBER) so protected from a judgment close anyway, but this also traces to a real, bounded defect: Ctrl+Enter in the New Automation dialog's prompt field doesn't trigger the dialog's Create/Save button.

## Change summary

Pressing Ctrl+Enter with focus in the Prompt field of the New Automation dialog does not create/save the automation.

## Best solution

Add a scoped Ctrl+Enter keybinding rule for the automations dialog (mirroring the existing plain-Enter → insertNewline override) that invokes the dialog's save()/Create action instead of letting `workbench.action.chat.submitWithCodebase` (also bound to CtrlCmd+Enter, without excluding the dialog) fire on the reused chat input.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/automations/browser/automationDialog.ts`, `src/vs/sessions/contrib/automations/browser/automationDialogService.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts`
- **Validation:** A test in automationDialog.test.ts (alongside the existing 'reserves Enter for suggestions...' and Escape-modifier tests) asserting a Ctrl+Enter keydown on the prompt field invokes save()/clicks the Create button when the form is valid, and does not trigger the chat widget's acceptInput/submitWithCodebase path.
- **Behavior:**

  > With focus in the automations dialog's Prompt field, pressing Ctrl+Enter should trigger the same action as clicking the dialog's Create (or Save, when editing) button — subject to the same validation/enabled-state the button already respects. It must not fall through to the chat widget's 'Send with codebase' behavior. Acceptance: a new automationDialog.test.ts case confirms Ctrl+Enter dispatches the dialog's save flow and is prevented from reaching ChatSubmitWithCodebaseAction.
- **Trace:**

  > The dialog already overrides plain Enter (workbench.action.chat.automationsDialog.insertNewline, automationDialog.ts:1717-1731, scoped to ChatContextKeys.inAutomationsDialog) to stop ChatSubmitAction's Enter-to-send from firing inside the reused chat input, but has no matching override for Ctrl+Enter. ChatSubmitWithCodebaseAction (chatExecuteActions.ts:819-838) is bound to CtrlCmd+Enter under the broader `ChatContextKeys.inChatInput` when-clause (no automations-dialog exclusion) and calls widget.acceptInput(), not the dialog's local save() (automationDialogService.ts:143-189, wired to the Create/Save button at automationDialogService.ts:288-290). Boundary: do not touch the normal chat panel's Ctrl+Enter/codebase behavior — only add/adjust dialog-scoped handling, analogous to the existing insertNewline registration.
- **Open decisions:**
  - Should Ctrl+Enter in the dialog simply exclude/suppress ChatSubmitWithCodebaseAction (leaving Ctrl+Enter otherwise inert), or should it actively invoke Create/Save?
  - If it invokes Create/Save, should it be a no-op when the form is currently invalid/save button disabled, or should it also surface the existing validation errors?

## Evidence

- **enter override exists:** src/vs/sessions/contrib/automations/browser/automationDialog.ts:1717-1731 registers `workbench.action.chat.automationsDialog.insertNewline` bound to plain KeyCode.Enter, scoped to ChatContextKeys.inAutomationsDialog, to override ChatSubmitAction's Enter-to-send inside the dialog — but no equivalent override exists for Ctrl+Enter.
- **conflicting Ctrl+Enter binding:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts:819-838 (ChatSubmitWithCodebaseAction) binds KeyMod.CtrlCmd | KeyCode.Enter with `when: ChatContextKeys.inChatInput` (no `inAutomationsDialog.negate()`), and calls `widget.acceptInput()` on the chat widget the dialog reuses (per chatInputPart.ts:322 comment) rather than the dialog's local `save()` closure that drives the Create button (automationDialogService.ts:155-289).
- **no other Ctrl+Enter handling:** No keydown handler for ctrlKey/metaKey+Enter exists in automationDialog.ts's `registerAutomationDialogKeyboardNavigation` (only Escape/Tab and prompt-suggestion handling are intercepted there).
