# Issue #336918 — Chat: bare URLs are linkified together with the text that directly follows them

[https://github.com/microsoft/vscode/issues/336918](https://github.com/microsoft/vscode/issues/336918)

## Summary

The defect remains on current main and originates in the vendored `marked` GFM autolink tokenizer, which consumes CJK text and full-width punctuation following a bare URL. No older issue with the same observable symptom was found, so this should remain open while the dependency fix is tracked.

## Change summary

Bare URLs in rendered chat markdown incorrectly absorb directly adjacent localized text into the link and its target.

## Best solution

Correct the GFM bare-URL boundary handling in `marked`, then update VS Code's vendored parser and add a renderer regression test covering URLs followed by full-width punctuation and CJK text.

## Evidence

- **current source reproduction:** On current main, lexing `https://example.com。代理将能够读取其内容并进行交互。` with the same `{ gfm: true, breaks: true }` options produces one link token whose `href`, text, and raw value include the entire Chinese suffix; the full-width-comma case behaves identically.
- **chat trigger:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts enables GFM and line breaks for rendered chat markdown and passes those options to the shared renderer, directly exercising the defective URL tokenizer.
- **root cause:** src/vs/base/common/marked/marked.js lines 1215-1218 define the vendored GFM URL expression as consuming every non-whitespace/non-`<` character and backpedaling only a limited ASCII punctuation set; full-width `。` and `，` therefore remain inside the URL token.
- **canonical search:** Repository searches for bare-URL, Chinese-punctuation, full-width-punctuation, and adjacent-text linkification reports found no older open issue with the same reporter-observable symptom; https://github.com/microsoft/vscode/issues/337932 concerns untappable mobile links and is not canonical.
