# Issue #328839 — Determine base SHA fails at depth > 50

[https://github.com/microsoft/vscode/issues/328839](https://github.com/microsoft/vscode/issues/328839)

## Summary

Confirmed on current main: the component-fixtures workflow still does a shallow `--depth=50` fetch and a bare `git merge-base` with no fallback, so any PR whose branch sits more than ~50 commits behind main will deterministically fail the 'Determine base SHA' step, not because of the PR's own change.

## Change summary

The `Determine base SHA` step in the component-fixtures workflow fails whenever a PR branch is more than ~50 commits behind main, because the shallow fetch depth is too small for `git merge-base` to find a common ancestor.

## Best solution

Make the base-SHA lookup resilient to stale branches — e.g. retry with `git fetch --deepen=<N>` (or fall back to `--unshallow`) when `git merge-base` fails, or just increase/parametrize the depth — in `.github/workflows/component-fixtures.yml` around the 'Determine base SHA' step.
