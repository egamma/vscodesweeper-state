# Issue #134651 — Add "new folder" option -- to make starting a new project easier.

[https://github.com/microsoft/vscode/issues/134651](https://github.com/microsoft/vscode/issues/134651)

## Summary

Keep open: current Welcome and File-menu entries still do not clearly advertise creating and opening a new project folder. Creating a folder through Open Folder is an existing workaround, but it does not resolve the discoverability concern that the reporter clarified and a maintainer acknowledged.

## Change summary

Make creating and opening a new project folder discoverable from the Welcome page and File menu.

## Best solution

Provide a clear, language-neutral entry point for creating a folder and opening it as the workspace, with straightforward access to creating the first file. Decide whether clearer wording around the existing folder picker suffices or a dedicated creation action is warranted; language-specific scaffolding should remain extension-provided.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/welcomeGettingStarted/common/gettingStartedContent.ts`, `src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts`, `src/vs/workbench/browser/actions/workspaceActions.ts`, `src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts`
- **Validation:** After the entry-point decision, manually check an empty desktop window on macOS and Windows/Linux: both Welcome and File menu visibly communicate the new-folder workflow; completing it creates and opens the chosen folder as the workspace; the user can create the first file there. Canceling must leave the workspace and filesystem unchanged, and opening existing folders must retain its existing behavior.
- **Behavior:**

  > A user starting a project in an empty VS Code window can discover how to create a new root folder from the Welcome page and File menu without knowing that Open also permits creation. Completing the workflow opens the new folder as the workspace and makes creating the first file straightforward. Existing-folder opening and cancellation remain unchanged. The report permits either an explicit creation entry or clearer wording that makes the existing picker workflow discoverable.
- **Trace:**

  > The ordinary Welcome start entries are declared in src/vs/workbench/contrib/welcomeGettingStarted/common/gettingStartedContent.ts and still advertise New File..., Open..., and Open Folder..., not root-folder creation. OpenFolderAction in src/vs/workbench/browser/actions/workspaceActions.ts dispatches through IFileDialogService.pickFolderAndOpen; the desktop implementation selects the simplified or native picker. explorer.newFolder in src/vs/workbench/contrib/files/browser/fileActions.ts creates children under an existing Explorer root and does not cover an empty-window project-root flow. NewFileTemplatesManager in src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts supports contributed creation commands but supplies only a Text File entry itself. The maintainer discussion at https://github.com/microsoft/vscode/issues/134651#issuecomment-946842022 leaves the entry-point design unsettled. Preserve existing file creation, folder opening, workspace/window policy, and extension-provided scaffolding; automatically opening a saved file's parent is a separate suggested improvement, not required coverage of this request.
- **Open decisions:**
  - Should Welcome and File menu offer a dedicated Create Folder action, or should their existing Open entry explicitly advertise creating a new folder through the picker?
  - If a dedicated creation action is chosen, should its initial contract stop at creating and opening an empty folder, or also offer extension-contributed project scaffolding?
