# Issue #65369 — Prevent Find/Replace bar from returning after Next Match (F3)

[https://github.com/microsoft/vscode/issues/65369](https://github.com/microsoft/vscode/issues/65369)

## Summary

A real gap remains on current main: after Escape disposes the find model, F3 recreates it and reveals the widget. The newer `editor.find.closeOnResult` setting does not cover this hidden-widget path, so this upvoted Backlog request should remain open.

## Change summary

Allow F3 and Shift+F3 to navigate using the previous query without reopening the Find/Replace widget after it was dismissed.

## Best solution

Extend `editor.find.closeOnResult` or the explicit match-navigation flow so F3/Shift+F3 leave a previously dismissed widget hidden. Add coverage for Ctrl+F, query, Escape, then F3 and Shift+F3.

## Evidence

- **source trace:** In src/vs/editor/contrib/find/browser/findController.ts, `closeFindWidget()` sets `isRevealed` false, `_onStateChanged()` then disposes the find model, and `matchFindAction()` subsequently calls `start()` on F3, which reveals the widget.
- **existing setting gap:** Commit 22933cea7b65c18ba29aa7f52937f13b22bd2eb5 added `editor.find.closeOnResult`, but `matchFindAction()` only closes when `wasFindWidgetVisible` and `isFindInputFocused()` are both true. After Escape, both conditions exclude the requested F3 path.
- **adjacent completed request:** https://github.com/microsoft/vscode/issues/264818 requested automatic closing while searching and was completed by https://github.com/microsoft/vscode/pull/299865; it does not cover keeping an already-dismissed widget hidden during later F3 navigation.
