# Issue #324588 — Setting `update.mode: none` does not cancel the update's download

[https://github.com/microsoft/vscode/issues/324588](https://github.com/microsoft/vscode/issues/324588)

## Summary

Still reproduces on main: cancelling the download token after the HTTP response headers arrive has no effect because the node request service disposes its cancellation listener on the `response` event, allowing the stream to run to completion.

## Change summary

Setting `update.mode: none` while an update is downloading does not abort the in-flight download — the installer finishes downloading despite the mode change.

## Best solution

The cancellation listener in `src/vs/platform/request/node/requestService.ts` (line 293) should not be disposed on `response` — it should remain active so that cancelling the token destroys the socket/stream mid-download. The win32 update service correctly passes the token through to the download request, but the request layer stops honoring it once streaming begins. Alternatively, the update service's download path could wire a stream-destruction callback on token cancellation independently of the request layer.
