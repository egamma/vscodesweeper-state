# Issue #296414 — Sync ~/.copilot/skills via Settings Sync

[https://github.com/microsoft/vscode/issues/296414](https://github.com/microsoft/vscode/issues/296414)

## Summary

Keep open as a supported feature request: current Settings Sync does not synchronize ~/.copilot/skills, despite recognizing that directory as a personal skill source. The team-authored report has 30 upvotes, and the older organization-sharing request does not describe the same cross-device Settings Sync gap.

## Change summary

Synchronize personal skill folders under ~/.copilot/skills between machines through Settings Sync.

## Best solution

Extend Settings Sync to preserve personal skill content across machines, including the supporting files needed to use each skill. Settle the sync category, consent, and home-directory versus profile semantics before implementing the synchronization contract.

Confirm existing profile prompt synchronization remains unchanged.
- **Behavior:**

  > A personal skill created under ~/.copilot/skills on Machine A should become available on Machine B after the user enables the applicable Settings Sync category and signs in. Synchronization must preserve the supporting files necessary for the skill to function, rather than transferring only its SKILL.md description. Acceptance should cover initial transfer, subsequent changes, deletions, conflicts, and opting out, while preserving existing prompt-file synchronization.
- **Trace:**

  > PromptsSynchronizer in src/vs/platform/userDataSync/common/promptsSync/promptsSync.ts initializes its root from profile.promptsHome and collects only immediate files with four prompt-related suffixes; it neither visits ~/.copilot/skills nor traverses skill directories. DEFAULT_SKILL_SOURCE_FOLDERS in src/vs/workbench/contrib/chat/common/promptSyntax/config/promptFileLocations.ts separately recognizes ~/.copilot/skills as a personal source, so discovery support does not establish synchronization support. SyncResource in src/vs/platform/userDataSync/common/userDataSync.ts and the configuration picker in src/vs/workbench/contrib/userDataSync/browser/userDataSync.ts expose no skills category. Preserve existing prompt synchronization and do not conflate Settings Sync with forwarding customizations to an agent host or distributing organization libraries. https://github.com/microsoft/vscode/issues/291685 concerns the latter and is related, not a verified duplicate. The remaining uncertainty is the user-visible sync contract for machine-global skill files alongside profile-scoped user data.
- **Open decisions:**
  - Should personal skills use the existing Prompts sync category or a separately selectable Skills category, and what opt-in behavior should existing sync users see?
  - How should machine-global ~/.copilot/skills content interact with separate VS Code profiles, including conflicts when multiple profiles synchronize the same directory?
  - Which supporting files and file attributes must the skill synchronization contract preserve, and what exclusions or limits should be visible to users?
