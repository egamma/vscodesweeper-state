# Issue #332444 — SCM: "Open Changes" hangs while a commit message is being generated with Copilot

[https://github.com/microsoft/vscode/issues/332444](https://github.com/microsoft/vscode/issues/332444)

## Summary

Confirmed on current main: ScmMultiDiffSourceResolver.resolveDiffSource waits for absence of any progress badge on the SCM view container before resolving the diff editor, which conflates the initial-scan signal (issue #216788, the original reason for the wait) with any other progress shown in that same view container, including Copilot commit-message generation.

## Change summary

"Open Changes" in Source Control is blocked from opening until Copilot commit-message generation (or any other SCM-view progress) finishes, because it waits on a generic progress badge instead of a specific readiness signal.

## Best solution

Replace the generic 'no progress badge' wait in src/vs/workbench/contrib/multiDiffEditor/browser/scmMultiDiffSourceResolver.ts with an explicit readiness signal (e.g. an observable tracking whether the initial repository scan has completed) so unrelated long-running progress (like AI commit message generation) no longer blocks Open Changes.
