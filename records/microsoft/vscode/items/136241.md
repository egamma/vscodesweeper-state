# Issue #136241 — Decorations flickering on editor change

[https://github.com/microsoft/vscode/issues/136241](https://github.com/microsoft/vscode/issues/136241)

## Summary

A real extension API gap remains on current main: editor-owned decorations are removed when switching models, and extensions have no persistence option. This Backlog request has 41 community upvotes and should remain open.

## Change summary

Allow extension-provided editor decorations to persist across model detach and reattach so switching tabs does not visibly clear and repaint them.

## Best solution

Design an opt-in persistent or model-scoped decoration API with explicit disposal and leak safeguards, preserving the existing editor-specific behavior by default.

## Vision fit

- **Fit:** aligned
- **Reason:** Improving decoration lifecycle control strengthens the extension API and lets extensions deliver polished editor experiences without moving specialized functionality into core.
- **Evidence:** Durable themes: extension ecosystem API hygiene and the developer inner loop.

## Evidence

- **current source:** On current main, src/vs/workbench/api/browser/mainThreadEditor.ts routes extension decorations through `setDecorationsByType`, while src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts assigns them the editor owner ID and `_postDetachModelCleanup` removes every decoration for that owner when the model detaches.
- **API gap:** src/vscode-dts/vscode.d.ts exposes no persistent or model-scoped option on `DecorationRenderOptions` or `TextEditorDecorationType`.
- **maintainer confirmation:** https://github.com/microsoft/vscode/issues/136241#issuecomment-959874331 confirms that clearing editor-owned decorations on model detach is intentional leak prevention and identifies a persistent property as a possible improvement.
- **partial mitigation:** https://github.com/microsoft/vscode-extension-samples/pull/535 removed the sample's artificial activation delay, but it did not address the underlying detach cleanup; later reports in the issue still observe flicker.
- **community support:** The request received 41 issue-body upvotes and was promoted to the Backlog after crossing the 20-upvote threshold.
- **related issue:** https://github.com/microsoft/vscode/issues/235912 concerns decoration flicker during document deletion rather than persistence across editor switches, so it does not absorb this API request.
