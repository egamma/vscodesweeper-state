# Issue #286896 — Support win32-input-mode in terminal

[https://github.com/microsoft/vscode/issues/286896](https://github.com/microsoft/vscode/issues/286896)

## Summary

Keep open: win32 input mode is integrated, but current main still marks it experimental and disables it by default. That does not satisfy the author's explicit reason for reopening: keeping this issue open until the capability is stable.

## Change summary

Provide stable win32-input-mode support for enhanced Windows terminal keyboard input.

Complete stabilization of the existing win32 input integration and let the terminal owner determine when its experimental status can be removed. Resolve or explicitly account for the reported modifier-key scrolling regression before treating this request as complete.

## Evidence

- **Explicit remaining scope:** The author reopened the issue on January 26, 2026, stating: "This is just experimental for this release, reopening until stable" — https://github.com/microsoft/vscode/issues/286896#issuecomment-3801817988.
- **Existing capability remains experimental:** Current main's src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts registers terminal.integrated.enableWin32InputMode with default: false, tags: ['experimental', 'advanced'], and experiment.mode: 'auto'. The opt-in capability exists, but stable support—the reopening criterion—is not established.
- **Actual integration:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts passes config.enableWin32InputMode into vtExtensions.win32InputMode both when constructing xterm and when updating configuration. package.json currently includes @xterm/xterm ^6.1.0-beta.304; dependency availability alone does not establish stabilization.
- **Earlier implementation does not resolve reopening:** https://github.com/microsoft/vscode/pull/287015 merged on January 11, 2026, and explicitly disabled win32 input mode by default while adding experimental/advanced classification. https://github.com/microsoft/vscode/pull/287113 merged on January 12 as part of this issue. Both precede the January 26 reopening and cannot establish completion of the remaining stable-support scope.
- **Upstream progress:** https://github.com/xtermjs/xterm.js/pull/5604 merged on January 11, 2026, fixing capital letters and Ctrl+letter handling. The upstream capability issue https://github.com/xtermjs/xterm.js/issues/2357 is closed, but that does not override the subsequent VS Code reopening or current experimental configuration.
- **Related regression is not a canonical:** https://github.com/microsoft/vscode/issues/288356 is open and reports that enabling terminal.integrated.enableWin32InputMode, scrolling up, and pressing Ctrl scrolls the terminal to the bottom; another commenter confirms interference with terminal link clicks. It was created January 16, 2026, later than this issue, and covers a narrower regression rather than the stable-support request.
