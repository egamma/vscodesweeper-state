[https://github.com/microsoft/vscode/issues/340307](https://github.com/microsoft/vscode/issues/340307)

## Summary

Confirmed regression traced in loopbackServer.ts's stop() method, and a fix is already proposed in an open, unmerged PR that references this issue — keeping this open until that PR lands rather than closing or marking it agent-ready.

## Change summary

The GitHub auth loopback server's stop() times out waiting for the HTTP server to close, because open keep-alive connections from the browser prevent Node's server.close() callback from firing within the 5s window.

## Best solution

Land https://github.com/microsoft/vscode/pull/340316, which calls `server.closeAllConnections()` before the close timeout in src/vs/workbench/api/node/loopbackServer.ts to force-close lingering keep-alive sockets.
