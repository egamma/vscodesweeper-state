- **Current VS Code lifecycle:** In src/vs/platform/terminal/node/terminalProcess.ts, setupPtyProcess records onExit and schedules _queueProcessExit; that timeout calls _kill, which invokes node-pty's IPty.kill even after natural shell exit. In src/vs/platform/terminal/node/ptyService.ts, createProcess removes the PTY from _ptys on process exit, and later lookups can throw the missing-PTY error. These paths establish the integration boundary, but do not conclusively prove that AttachConsole failure causes every subsequent missing-PTY RPC.
- **Upstream mitigation, not complete fix proof:** https://github.com/microsoft/node-pty/commit/2b25c76157fdfe02be4387e892e850ae26b33c2f catches getConsoleProcessList failures in src/conpty_console_list_agent.ts and guards nonpositive _innerPid values in src/windowsPtyAgent.ts. The checkout declares node-pty ^1.2.0-beta.15 and locks beta.15. Upstream main still enumerates console processes in the non-DLL kill path without an _exitCode guard, while the helper catches AttachConsole failures. This supports likely mitigation of the original stack-trace spew, not a verified fix of the entire issue.
