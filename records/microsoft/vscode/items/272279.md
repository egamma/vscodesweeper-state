# Issue #272279 — NES proposal on backspacing

[https://github.com/microsoft/vscode/issues/272279](https://github.com/microsoft/vscode/issues/272279)

## Summary

Keep open: the detailed reproduction and maintainer diagnosis establish that NES can re-offer deleted text from its local cache, but the desired invalidation boundary remains an unresolved UX decision. This is also a team-authored issue, so the discussion that the behavior resembles normal completions is not grounds for an as-designed close.

## Change summary

Backspacing within a word can cause a cached next-edit suggestion to immediately restore the deleted characters as ghost text, making the visible string appear not to shrink.

## Best solution

Define when a destructive edit should invalidate an otherwise compatible cached NES result, then add a regression test for backspacing against the suggestion while preserving ordinary type-through and completion agreement behavior.
