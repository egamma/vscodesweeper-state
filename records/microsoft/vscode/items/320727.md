# Issue #320727 — Incorrect Authorization header for apiKey in Custom Endpoint (BYOK) scenarios

[https://github.com/microsoft/vscode/issues/320727](https://github.com/microsoft/vscode/issues/320727)

## Summary

The original complaint (Bearer vs api-key) is addressed by the existing `requestHeaders` override plus `${apiKey}` interpolation. However, the remaining bug — `${input:chat.lm.secret}` not being resolved inside `requestHeaders` values — is still present on main. The secret-storage variable substitution only applies to the top-level `apiKey` field, not to arbitrary header values.

## Change summary

When using `${input:chat.lm.secret}` in a custom endpoint's `requestHeaders`, the token is sent as the literal string instead of being resolved to the stored secret value.

## Best solution

Extend the secret-resolution logic (currently scoped to the `apiKey` field in `src/vs/workbench/contrib/chat/common/languageModels.ts`) to also resolve `${input:chat.lm.secret.*}` tokens appearing in `requestHeaders` values before they reach `OpenAIEndpoint._customHeaders`. The `_interpolateApiKey` method in `customEndpointProvider.ts` already handles the simpler `${apiKey}` placeholder, so the fix likely belongs upstream where the model configuration is materialized, or as a second interpolation pass in that method.
