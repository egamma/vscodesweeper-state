# Issue #125290 — Hex editor does not show fully after reload with untitled

[https://github.com/microsoft/vscode/issues/125290](https://github.com/microsoft/vscode/issues/125290)

## Summary

The restore gap remains source-reproducible, but it is owned by the VS Code-team-maintained Hex Editor extension rather than the core custom-editor restore path. This should be moved to microsoft/vscode-hexeditor instead of closed.

## Change summary

Reloading a window with an untitled document reopened in Hex Editor restores an empty or incomplete editor until another editor is opened.

## Best solution

Have Hex Editor preserve the untitled document's base bytes in its custom-document backup and reconstruct the base data together with unsaved hex edits when `backupId` is supplied.

## Evidence

- **confirmed reproduction:** Maintainers confirmed the reproduction in https://github.com/microsoft/vscode/issues/125290#issuecomment-853937218 and identified that `untitledDocumentData` was empty while restoring from backup in https://github.com/microsoft/vscode/issues/125290#issuecomment-858897551.
- **core restore contract:** Current `src/vscode-dts/vscode.d.ts` documents that an extension must restore from `backupId` when one is supplied. `src/vs/workbench/contrib/customEditor/browser/customEditorInputFactory.ts` restores a dirty custom editor with that backup ID, and `src/vs/workbench/api/browser/mainThreadCustomEditors.ts` forwards it to `openCustomDocument`.
- **extension root cause:** Current Hex Editor source still constructs an untitled accessor from `untitledDocumentData ?? new Uint8Array()` in https://github.com/microsoft/vscode-hexeditor/blob/main/src/fileSystemAdaptor.ts, while https://github.com/microsoft/vscode-hexeditor/blob/main/src/backup.ts stores only edit operations. On backup restore, https://github.com/microsoft/vscode-hexeditor/blob/main/src/hexDocument.ts therefore combines an empty base buffer with the saved edits instead of restoring the original untitled bytes.
- **related issue differs:** https://github.com/microsoft/vscode/issues/125202 was a side-by-side editor layout defect fixed by https://github.com/microsoft/vscode/pull/125445; maintainers explicitly distinguished this issue because resizing did not restore it and another editor had to be opened.
