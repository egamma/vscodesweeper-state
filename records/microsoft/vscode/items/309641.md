# Issue #309641 — Feature Request: Lazy inject MCP into agent only when the extension skill is invoked

[https://github.com/microsoft/vscode/issues/309641](https://github.com/microsoft/vscode/issues/309641)

## Summary

Keep open: existing tool search and virtualization reduce MCP context overhead, but do not provide the requested skill-triggered activation contract. No verified older canonical or concrete fixing commit establishes that this request is already covered.

## Change summary

Defer an extension's associated MCP tools until the agent invokes that extension's skill.

## Best solution

Evaluate an explicit skill-to-MCP association and activation contract in the agent runtime, reusing existing deferred-tool discovery rather than adding a parallel mechanism. Preserve ordinary MCP use without skills; sharing an extension provider alone should not silently make every MCP tool skill-dependent.
