# Issue #309641 — Feature Request: Lazy inject MCP into agent only when the extension skill is invoked

[https://github.com/microsoft/vscode/issues/309641](https://github.com/microsoft/vscode/issues/309641)

## Summary

A real optimization gap remains: current plugin discovery supplies MCP servers and skills together at session launch, without an association that could activate an MCP server when a particular skill is invoked. Route this to the MCP and agent-tool owners for design.

## Change summary

Defer MCP servers contributed alongside extension skills until the corresponding skill is invoked.

## Best solution

Define an explicit skill-to-MCP dependency in plugin contributions and let the agent runtime activate that server on skill invocation, while preserving current tool virtualization as the fallback for independently configured MCP servers.

## Vision fit

- **Fit:** aligned
- **Reason:** Reducing unused tool context and inference overhead directly supports efficient agent sessions without removing capability.
- **Evidence:** This aligns with current agent-experience priorities around inference cost and context efficiency, as well as the public value that performance trumps functionality.
