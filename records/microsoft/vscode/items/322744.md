# Issue #322744 — Agent Host file linkifier seems broken

[https://github.com/microsoft/vscode/issues/322744](https://github.com/microsoft/vscode/issues/322744)

## Summary

The malformed file link remains source-reproducible on current main. Agent Host intentionally emits empty-label file links for conversion into rich file widgets, but thinking-body rendering omits that conversion path.

## Change summary

File references in agent thinking text render as malformed `Editing [](file URI)` content instead of clickable file pills.

## Best solution

Thinking and reasoning content should render file URI links through the same inline-anchor decoration path used by ordinary chat markdown, while preserving existing web-link and streaming behavior.

- **Behavior:**

- **Trace:**

  > Agent Host markdown conversion in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts deliberately changes internal file links to empty-label `vscode-agent-host` links so the client can supply the visible filename. Ordinary response markdown completes that contract through ChatMarkdownContentPart and ChatMarkdownDecorationsRenderer, which ultimately call renderFileAnchor. ChatThinkingContentPart.renderThinkingMarkdown and renderSummaryRow render the Markdown but skip this decoration step; only title rendering near setTitleDetail currently calls renderFileWidgets. This directly leaves the issue's empty anchor in thinking-body content. Keep web links, heading promotion, streamed target reuse, and ordinary response rendering unchanged; the relevant regression coverage belongs in the existing ChatThinkingContentPart browser tests.
