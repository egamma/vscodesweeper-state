# Issue #312890 — API request: Allow extensions to mark files as read-only for OTHER extensions (not the user)

[https://github.com/microsoft/vscode/issues/312890](https://github.com/microsoft/vscode/issues/312890)

## Summary

Valid feature request for extension-scoped file write protection — no such API exists on current main. A related but distinct issue (https://github.com/microsoft/vscode/issues/289416, on the On Deck milestone) requests agent-level file permission controls. This issue's framing (extension-to-extension isolation, DLP use case) is narrower and more API-specific; the two share the same gap but propose different solutions. Keeping open as under-discussion — the community process is still running (10 days left) and the request is well-articulated, though it has not reached the 20-upvote threshold.

## Change summary

Request a VS Code extension API that lets one extension mark files as read-only for other extensions while leaving them user-editable.

## Best solution

The central ask — a deterministic, extension-API-level mechanism to block other extensions from writing to specified files — is not covered by any existing API (`FilePermission.Readonly` blocks all writers including the user, `files.readonlyInclude` does the same, and `.copilotignore` only restricts reads). The related https://github.com/microsoft/vscode/issues/289416 (On Deck) approaches the same gap from the agent-permissions angle and may absorb parts of this request if it lands. A maintainer should evaluate whether #289416's scope covers this issue's extension-to-extension isolation use case or whether a distinct API track is needed. If #289416 is broadened to cover extension-scoped write protection, this could be consolidated as a duplicate; otherwise it should stay open as a separate API proposal.
