# Issue #192719 — MacOS scrolling inertia is not cancelled when stopped

[https://github.com/microsoft/vscode/issues/192719](https://github.com/microsoft/vscode/issues/192719)

## Summary

Still reproduces on main: macOS native trackpad momentum scrolling is not cancelled when the viewport programmatically snaps to a new position (e.g., when the user types and the cursor is revealed). The scrollable element has no mechanism to suppress OS-delivered inertial wheel events after a programmatic scroll position change.

## Change summary

On macOS, trackpad inertial (momentum) scrolling continues to move the viewport even after a programmatic jump to the cursor position, causing a jarring scroll-away effect.

## Best solution

Add logic to the scrollable element's wheel event handler to detect and suppress OS-delivered momentum wheel events when the scroll position has been programmatically changed since the gesture began. This likely involves tracking the last programmatic scroll timestamp in the scrollable element and ignoring wheel events that arrive during the momentum phase shortly after a programmatic jump. The fix belongs in `src/vs/base/browser/ui/scrollbar/scrollableElement.ts` and possibly `src/vs/base/common/scrollable.ts`.
