# Issue #334144 — Icons render as missing glyphs in Remote-SSH since 1.136.0 — glicons.woff2 fails to load

[https://github.com/microsoft/vscode/issues/334144](https://github.com/microsoft/vscode/issues/334144)

## Summary

Confirmed live regression on current main: the managed-remote-resource protocol handler in src/vs/code/electron-main/app.ts still rejects requests with an empty (not undefined) referrer, and its notFound() fallback returns a string body incompatible with registerBufferProtocol — exactly the double defect diagnosed in the comments. An open PR (#335241) already targets this fix, so the issue should stay open pending that PR landing rather than being closed now.

## Change summary

Since 1.136.0, all icons/fonts (glicons.woff2, extension SVG icons, contributed icon fonts) served over vscode-managed-remote-resource:// fail to load in Remote-SSH sessions, rendering as tofu/missing glyphs.

## Best solution

Land the open PR https://github.com/microsoft/vscode/pull/335241 ("remote: fix managed resource loading from workbench"), which should correct the referrer check and buffer-protocol response in setupManagedRemoteResourceUrlHandler/onBeforeRequest in src/vs/code/electron-main/app.ts; this issue and its many duplicates can close once that merges and ships.
