# Issue #334144 — Icons render as missing glyphs in Remote-SSH since 1.136.0 — glicons.woff2 fails to load

[https://github.com/microsoft/vscode/issues/334144](https://github.com/microsoft/vscode/issues/334144)

## Summary

Confirmed live regression with a well-traced root cause: current main still contains the referrer check that rejects the empty-referrer requests workbench icon/font loads legitimately send over vscode-managed-remote-resource, so this stays open pending a maintainer fix rather than closing.

## Change summary

Since 1.136.0, extension and remote-provided icons (and glicons.woff2) fail to load in Remote-SSH sessions, rendering as tofu/missing glyphs, because vscode-managed-remote-resource requests are being rejected.

## Best solution

Fix the overly strict referrer/notFound handling in setupManagedRemoteResourceUrlHandler (src/vs/code/electron-main/app.ts) so legitimate empty-referrer workbench requests aren't rejected, and make notFound() return a real ArrayBufferView body compatible with registerBufferProtocol's buffer callback — this is a security-relevant access-control path so a maintainer (cc'd in the thread: connor4312, deepak1556) should confirm the correct narrowing rather than an automated change.
