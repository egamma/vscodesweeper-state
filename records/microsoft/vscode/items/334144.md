# Issue #334144 — Icons render as missing glyphs in Remote-SSH since 1.136.0 — glicons.woff2 fails to load

[https://github.com/microsoft/vscode/issues/334144](https://github.com/microsoft/vscode/issues/334144)

## Summary

Fresh, well-diagnosed regression: since 1.136.0, extension icons served through vscode-managed-remote-resource:// (SVGs) and glicons.woff2 (the remote product-icon font) fail to load in Remote-SSH sessions, confirmed independently by multiple reporters with console errors, screenshots, and a clean-profile isolation test; already tagged recent-regression but has no area routing yet.

## Change summary

Since 1.136.0, extension and product icons render as missing glyphs (tofu/empty boxes) in Remote-SSH windows because resource requests over vscode-managed-remote-resource:// and the remote-themed glicons.woff2 font fail with net::ERR_FAILED.

## Best solution

Trace the regression in the Electron-main resource protocol handling (src/vs/code/electron-main/app.ts, setupManagedRemoteResourceUrlHandler and the vscode-managed-remote-resource onBeforeRequest guard added there) and the remote product-icon font loading path, since this checkout's single-commit history can't be bisected here — a maintainer with full git history should identify the exact commit between 1.135.0 and 1.136.0 that changed request/referrer handling for this scheme.
