# Issue #334144 — Icons render as missing glyphs in Remote-SSH since 1.136.0 — glicons.woff2 fails to load

[https://github.com/microsoft/vscode/issues/334144](https://github.com/microsoft/vscode/issues/334144)

## Summary

Confirmed on current main: the referrer guard added for `vscode-managed-remote-resource` (PR #332793) still rejects requests with an empty-string `Referer`, which is exactly what ordinary workbench (non-webview) icon/font requests send — so every remote-contributed icon/font continues to fail with `net::ERR_FAILED`, matching the community's own traced diagnosis.

## Change summary

Since 1.136.0, extension- and language-server-contributed icons (and the remote product-icon font `glicons.woff2`) fail to load over Remote-SSH, rendering as tofu/missing glyphs, while local windows and built-in codicon-based icons are unaffected.

## Best solution

Fix the referrer check in `src/vs/code/electron-main/app.ts` (`setupManagedRemoteResourceUrlHandler`, ~line 849) so it doesn't reject a legitimately empty `Referer` from workbench (non-webview) requests, and separately fix `notFound()` (line 837) to return an `ArrayBufferView` body instead of a string, since Electron's buffer-protocol `kBuffer` path turns a string body into `net::ERR_FAILED` regardless of statusCode — this masks the real cause and should be routed to the Remote/Electron area owners as a broad, well-diagnosed regression.
