# Issue #334144 — Icons render as missing glyphs in Remote-SSH since 1.136.0 — glicons.woff2 fails to load

[https://github.com/microsoft/vscode/issues/334144](https://github.com/microsoft/vscode/issues/334144)

## Summary

Well-documented, widely-confirmed regression: extension-contributed icons/fonts fail to load over Remote-SSH via the vscode-managed-remote-resource:// protocol (net::ERR_FAILED). Many commenters trace it to the request-blocking check in the electron-main webRequest handler added in #332793, but I can't confirm a fixing commit on this checkout (only 1 commit of history is available), so this stays open pending a verifiable fix.

## Change summary

Since 1.136.0, extension icons and fonts (including glicons.woff2 and SVG icons) fail to load in Remote-SSH sessions, rendering as missing/empty glyphs, due to net::ERR_FAILED on vscode-managed-remote-resource:// requests.

## Best solution

Fix belongs in src/vs/code/electron-main/app.ts's onBeforeRequest handler for the vscode-managed-remote-resource scheme — ensure legitimate workbench-originated requests (empty/absent Referer, non-webview frames) are allowed, and fix the notFound()/500 responses to return a valid ArrayBufferView body for the buffer protocol as flagged in comment https://github.com/microsoft/vscode/issues/334144#issuecomment (apimentasoto). This should be treated as the canonical tracking issue given the many closed duplicates pointing here.
