# Issue #334692 — Reveal for comments just opens the line/file, does not reveal the comments

[https://github.com/microsoft/vscode/issues/334692](https://github.com/microsoft/vscode/issues/334692)

## Summary

Real bug in the Agents Window review-comments feature: the code path for 'Reveal' (open the editor, then anchor navigation to expand the comment widget) is wired through several indirections that plausibly race or mismatch, so the file/line opens but the comment widget never expands.

## Change summary

Clicking 'Reveal' on the PR/agent comments banner opens the file at the right line but never expands/shows the actual comment widget(s).

## Best solution

In src/vs/sessions/contrib/agentFeedback/browser, verify the ordering between AgentFeedbackService.revealSessionComment's editorService.openEditor(...) and its subsequent setNavigationAnchor()/onDidChangeNavigation fire versus AgentFeedbackEditorWidgetContribution's autorun (which only calls _handleNavigation() once _resolveSession() has picked up the new editor model) — a race there would exactly produce 'file opens, comments don't expand'; add a test that reveals a comment in a not-yet-open editor and asserts the widget ends up expanded.

## Evidence

- **reveal flow:** AgentFeedbackService.revealSessionComment (src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts:820-860) opens the editor via this._editorService.openEditor(...), then calls setNavigationAnchor(...) which fires onDidChangeNavigation.
- **expand logic:** AgentFeedbackEditorWidgetContribution._handleNavigation (agentFeedbackEditorWidgetContribution.ts:221-270) is what actually expands the correct widget and calls widget.expand()/focusFeedback, but it only runs against this._sessionResource, which is set in _resolveSession() from the *current* editor model — a separate autorun keyed off this._editor.onDidChangeModel (constructor, lines 57-88).
- **possible race:** If the onDidChangeNavigation handler (constructor lines 57-61) fires before the editor's onDidChangeModel-driven autorun has updated _sessionResource/rebuilt widgets for the freshly opened editor, _handleNavigation() is a no-op and the reveal silently only leaves the cursor/selection from openEditor's `selection` option, matching the reported symptom exactly.
- **docs intent:** The contribution's own doc comment states 'Widgets start collapsed and expand when navigated to' (agentFeedbackEditorWidgetContribution.ts:28), confirming expand-on-reveal is the intended behavior that isn't happening.
