# Issue #339508 — Uncontrollably Animated and/or PR/ad Material in Release Notes

[https://github.com/microsoft/vscode/issues/339508](https://github.com/microsoft/vscode/issues/339508)

## Summary

Two distinct asks here: the promotional/animated content itself is release-notes *document content* (authored outside this repo), but the accessibility gap is real and confirmed in source — VS Code's shared markdown sanitizer unconditionally allows `autoplay`/`loop` on video elements with no check against reduced-motion settings anywhere in the release notes rendering path.

## Change summary

Release notes can embed autoplaying/looping video/GIF content that ignores the OS/VS Code reduced-motion accessibility setting and offers no user control over autoplay.

## Best solution

Have the markdown sanitizer / release notes renderer suppress `autoplay`/`loop` (or pause media) for rendered HTML content when `prefers-reduced-motion`/`workbench.reduceMotion` is active; the promotional-content complaint itself is an editorial matter for the vscode-docs content, not a code fix here.

## Plan brief

- **Likely files:** `src/vs/base/browser/markdownRenderer.ts`, `src/vs/base/browser/domSanitize.ts`, `src/vs/workbench/contrib/update/browser/releaseNotesEditor.ts`, `src/vs/workbench/contrib/markdown/browser/markdownDocumentRenderer.ts`
- **Validation:** A test asserting that rendered markdown HTML with `<video autoplay loop>` does not retain autoplay/loop (or is paused) when reduced motion is simulated as enabled.
- **Behavior:**

  > When reduced motion is enabled (OS setting or VS Code's workbench.reduceMotion), video/GIF content embedded in rendered markdown documents (release notes and any other surface using the same sanitizer) must not autoplay or loop without explicit user interaction. Acceptance: opening release notes containing an autoplay/loop video with reduced motion enabled results in the video not auto-looping, with the user still able to play it manually.
- **Trace:**

  > allowedMarkdownHtmlAttributes in src/vs/base/browser/markdownRenderer.ts unconditionally allows 'autoplay' and 'loop' for sanitized HTML fed into domSanitize.sanitizeHtml (src/vs/base/browser/domSanitize.ts), which releaseNotesEditor.ts relies on to render release notes in a webview. No CSS/JS in that path (or in markdownDocumentRenderer.ts) checks `prefers-reduced-motion`, unlike many other UI surfaces in the repo. Do not change the broader allowed-tag/attribute surface beyond autoplay/loop/motion handling, and do not touch unrelated sanitizer behavior.
- **Open decisions:**
  - Should autoplay/loop simply be stripped when reduced motion is active, or should the player still be present but paused with a visible play control?
  - Should the fix live narrowly in the release notes webview, or in the shared markdown sanitizer/renderer used by other features (notebooks, hovers, chat)?
  - Is the presence of promotional/'Social media' content in the release notes document itself in scope for this repo, or purely an editorial decision in the vscode-docs content repo?
