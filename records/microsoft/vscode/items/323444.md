# Issue #323444 — 'Branch Changes' still offers to commit changes when there are no uncommitted changes

[https://github.com/microsoft/vscode/issues/323444](https://github.com/microsoft/vscode/issues/323444)

## Summary

The bug remains source-reproducible on current main: an existing session's Commit action is contributed for the selected Branch Changes changeset without checking whether the workspace has uncommitted changes. The related issue concerns aggregation across chats and does not own this observable symptom.

## Change summary

Prevent Branch Changes from offering an actionable Commit command when the session workspace has no uncommitted changes.

## Best solution

Make the existing-session Commit action reflect the repository's uncommitted-change count, with regression coverage for zero and nonzero counts while Branch Changes is selected.
