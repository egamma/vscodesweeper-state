## Change summary

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/chatContributions/queueDrain/queueDrainContribution.ts`, `src/vs/platform/agentHost/browser/agentHostProtocolClient.ts`, `src/vs/platform/agentHost/test/node/chatContributions.test.ts`, `src/vs/platform/agentHost/test/electron-browser/agentHostProtocolClient.test.ts`
- **Validation:** Add a deterministic Agent Host test that queues one message, exercises the suspected completion/reconnect ordering, and asserts exactly one ChatTurnStarted action and one provider send for that queued message ID.
- **Behavior:**

  > A prompt submitted once must create exactly one user turn and exactly one provider delivery, including when it is queued behind an active turn. Completing the active turn or reconnecting a client must not replay the queued prompt after its first admission. Multiple distinct queued prompts must still execute once each and in order.
- **Trace:**

  > Queued messages are admitted by QueueDrainContribution in src/vs/platform/agentHost/node/chatContributions/queueDrain/queueDrainContribution.ts, which can attempt draining after both pending-message actions and successful turn completion. ChatTurnStarted carries queuedMessageId, and the reducer in src/vs/platform/agentHost/common/state/protocol/channels-chat/reducer.ts synchronously removes that queue entry. Separately, AgentHostProtocolClient._drainAfterReconnect in src/vs/platform/agentHost/browser/agentHostProtocolClient.ts replays pending optimistic actions and deduplicates them against its outbox by clientSeq. The current source therefore contains intended exactly-once safeguards, but the issue evidence and maintainer confirmation show that a delivery path escaped them; establish whether duplicate queue entries are created client-side or one entry is admitted twice before selecting the fix boundary. Preserve steering behavior, ordering of distinct queued messages, and reconnect recovery. The newer same-symptom report is https://github.com/microsoft/vscode/issues/330713; the temporary UI-only symptom in https://github.com/microsoft/vscode/issues/331789 is out of scope.
