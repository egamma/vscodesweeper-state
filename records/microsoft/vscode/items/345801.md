# Issue #345801 — Markdown-based Copilot language modes prevent use of the configured Markdown formatter

[https://github.com/microsoft/vscode/issues/345801](https://github.com/microsoft/vscode/issues/345801)

## Summary

Keep open as a request for Markdown formatter interoperability across built-in language modes. Current provider matching explains the reported behavior, but automatic fallback would extend the existing integration contract rather than repair a demonstrated violation of it.

## Change summary

Preserve Markdown formatting for Skill and Agent documents without losing their specialized editing features.

## Best solution

Establish a supported formatter integration contract for Markdown-derived customization modes. Evaluate whether explicit formatter registration is sufficient or whether VS Code should provide narrowly scoped delegation; Biome's pending alias support addresses its integration but does not settle the broader core request.

## Evidence

- **Built-in ownership:** extensions/prompt-basics/package.json assigns SKILL.md to skill and *.agent.md to chatagent. Both use a Markdown-derived grammar, but the language contributions declare separate language IDs, not provider inheritance.
- **Current matching contract:** src/vs/editor/common/languageSelector.ts: score returns zero for a markdown language selector against skill or chatagent. src/vs/editor/common/languageFeatureRegistry.ts: _updateScores uses model.getLanguageId(), and _orderedForEach excludes zero-score providers.
- **Reported dialog path:** src/vs/editor/contrib/format/browser/format.ts: getRealAndSyntheticDocumentFormattersOrdered collects matching document and range providers. src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts: DefaultFormatter._analyzeFormatter emits the reported error when the configured extension has no matching provider; editor.defaultFormatter does not override provider eligibility.
- **Existing capabilities do not cover the request:** files.associations in src/vs/workbench/contrib/files/browser/files.contribution.ts can override the specialized language assignment, but that sacrifices the language mode the reporter explicitly wants to preserve. The inspected formatter selection path contains no Markdown-derived fallback.
- **Extension-side evidence:** https://github.com/biomejs/biome-vscode/issues/1204 reports the same Skill/Agent symptoms. Biome's current src/constants.ts includes markdown but not skill or chatagent, consistent with the selector mismatch.
- **Pending integration work:** https://github.com/biomejs/biome-vscode/issues/1204#issuecomment-6602692918 points to https://github.com/biomejs/biome-vscode/pull/1199. That PR is open and unmerged; it proposes configurable language aliases and server-facing language-ID translation, so provider selection alone may not complete formatter compatibility.
- **Canonical search:** Open-issue searches for Markdown formatters, prompt formatting, instructions formatters, and language inheritance did not identify a verified canonical owning this specific interoperability request. No fixing commit or completed implementation was established.
