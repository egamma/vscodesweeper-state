# Issue #194842 — Unhide Execute Cell button during notebook load

[https://github.com/microsoft/vscode/issues/194842](https://github.com/microsoft/vscode/issues/194842)

## Summary

Keep open: current source still allows Execute Cell to disappear before kernels or kernel sources become available. This team-authored request remains a product decision between showing a disabled button and allowing it to open kernel selection; no qualifying fix or canonical duplicate was established.

## Change summary

Keep the notebook Execute Cell button visible during kernel discovery instead of making it appear late during startup or reload.

## Best solution

Keep the existing cell execution affordance stable during notebook loading, with an agreed unavailable-state behavior: disabled during discovery or enabled to enter kernel selection. Resolve that interaction in the core notebook execution toolbar without changing normal execution and cancellation behavior.

## Evidence

- **Current visibility condition:** src/vs/workbench/contrib/notebook/browser/controller/executeActions.ts defines executeCondition as a code cell plus at least one matching kernel, at least one kernel source, or a missing kernel extension. ExecuteCell uses executeThisCellCondition for both its precondition and the NotebookCellExecutePrimary menu visibility. With the extension installed and both counts zero, the action remains hidden.
- **Discovery-dependent context:** NotebookEditorContextKeys._updateKernelContext in src/vs/workbench/contrib/notebook/browser/viewParts/notebookEditorWidgetContextKeys.ts sets notebookKernelCount from matching kernels and notebookKernelSourceCount from source actions. RunToolbar in src/vs/workbench/contrib/notebook/browser/view/cellParts/codeCellRunToolbar.ts reads the menu and supplies an empty primary-action list when no action qualifies.
- **Existing-capability check:** The notebook.cellToolbarLocation, notebook.cellToolbarVisibility, and notebook.consolidatedRunButton registrations in src/vs/workbench/contrib/notebook/browser/notebook.contribution.ts control placement, hover/click presentation, and dropdown actions, not visibility during discovery. NotebookExecutionService.executeNotebookCells already calls KernelPickerMRUStrategy.resolveKernel, whose implementation in browser/viewParts/notebookKernelQuickPickStrategy.ts invokes SELECT_KERNEL_ID when no kernel is selected; this existing downstream behavior does not make the hidden cell button accessible.
