# Issue #327396 — Cloud Session Sync

[https://github.com/microsoft/vscode/issues/327396](https://github.com/microsoft/vscode/issues/327396)

## Summary

The reporter describes a real architectural weakness in the cloud session sync: the in-memory event buffer is lost when the extension host restarts before the safety-timer flush fires, leaving cloud sessions with stubs but no content. The dispose() path does attempt a best-effort flush but it's fire-and-forget and cannot block, so fast shutdowns lose data. This is a valid bug in the Copilot Chat cloud sync mechanism (which lives in-repo under extensions/copilot/) and should be routed to the chronicle/session-sync area owner.

## Change summary

Cloud session sync loses buffered events when the extension host restarts before the safety-timer flush completes, leaving cloud sessions as empty stubs.

## Best solution

Harden the flush lifecycle in RemoteSessionExporter so that buffered events survive extension host restarts — either by persisting the event buffer to disk before dispose, or by implementing a re-upload mechanism that replays local session-store data for already-registered cloud sessions whose content never arrived. The reindex command already re-registers unregistered sessions but does not re-push content for registered-but-empty ones — closing that gap would fix the reported scenario.

## Evidence

- **dispose flush is fire-and-forget:** extensions/copilot/src/extension/chronicle/vscode-node/remoteSessionExporter.ts lines 369-386: dispose() calls _flushBatch() as fire-and-forget — if the extension host shuts down before the async flush completes, buffered events are lost.
- **safety timer default 60s:** SAFETY_INTERVAL_MS is 60_000ms (line 58); events without a terminal flush event may sit in the in-memory buffer for up to a minute before being uploaded, creating a wide window for data loss on restart.
- **reindex does not re-push content:** The reporter notes (and the code confirms via reindexSessions/reindexCloudSessions imports at line 40) that reindex re-registers unregistered sessions but does not replay content for already-registered sessions whose cloud content is missing.
- **no errors in logs:** The reporter scanned extension host logs and found zero sync-related errors — the data loss is silent, which is consistent with the fire-and-forget design.
