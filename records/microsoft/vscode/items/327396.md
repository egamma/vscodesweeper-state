# Issue #327396 — Cloud Session Sync

[https://github.com/microsoft/vscode/issues/327396](https://github.com/microsoft/vscode/issues/327396)

## Summary

The reporter's two-phase-sync hypothesis checks out against current main: the in-memory event buffer in RemoteSessionExporter has no disk persistence, and reindexCloudSessions skips any session already present in cloudSessionIds purely by cloud-ID existence, with no way to detect or resume a partially-flushed session. A second, independent reporter (different OS, Bitbucket-hosted repo) confirms the same symptom.

## Change summary

Cloud session sync silently leaves session content un-uploaded when the extension host restarts before the safety-flush timer fires, and reindex does not recover it because it only checks whether a cloud session ID exists, not whether content upload completed.

## Best solution

In extensions/copilot/src/extension/chronicle/node/sessionReindexer.ts, reindexCloudSessions (around the `if (cloudSessionIds.has(sessionId))` skip at line ~389) should distinguish 'registered' from 'fully uploaded' — e.g. by tracking a per-session upload-completeness marker (last flushed event index or a completion flag) so reindex can resume content upload for stub-only cloud sessions, and/or persist the in-memory _eventBuffer in RemoteSessionExporter (remoteSessionExporter.ts) so a clean-crash/reload doesn't drop unflushed events silently.
