# Issue #166118 — Setting to focus editor on mouse click

[https://github.com/microsoft/vscode/issues/166118](https://github.com/microsoft/vscode/issues/166118)

## Summary

This accepted Backlog request remains necessary: current main still hard-codes single-click file opening to preserve Explorer focus, and no setting changes that behavior. With 135 upvotes and multiple matching reports, it should remain open for design and implementation.

## Change summary

Add an option for a single click on an Explorer file to open it in preview while moving keyboard focus into the editor.

## Best solution

Provide an opt-in focus-transfer behavior that preserves single-click preview semantics and leaves the current behavior as the compatibility default. The design should explicitly decide whether the option applies only to the File Explorer or also to related file-opening lists such as Open Editors.

## Plan brief

- **Likely files:** `src/vs/platform/list/browser/listService.ts`, `src/vs/workbench/contrib/files/browser/views/explorerView.ts`, `src/vs/workbench/contrib/files/browser/files.contribution.ts`, `src/vs/workbench/contrib/files/test/browser/explorerView.test.ts`
- **Validation:** Add or extend an Explorer view test that dispatches a single-click open and asserts the editor open options preserve focus under the existing/default behavior but transfer focus when the new option is enabled; also verify preview pinning and double-click behavior remain unchanged.
- **Behavior:**

  > Users can opt into having a single mouse click on a file open its preview and transfer keyboard focus to the editor. Without the option, single-click opening continues to leave focus in the originating list. Double-click pinning, side-by-side opening, and keyboard navigation retain their existing behavior. Acceptance includes exercising both setting values and confirming that preview reuse still works when focus transfers.
- **Trace:**

  > ResourceNavigator.onPointer in src/vs/platform/list/browser/listService.ts currently fixes `preserveFocus` to true for every single-click open, while onMouseDblClick sets it to false. ExplorerView in src/vs/workbench/contrib/files/browser/views/explorerView.ts forwards that flag directly to IEditorService.openEditor. `workbench.list.openMode` only selects the click count, and `explorer.openAndPassFocus` in src/vs/workbench/contrib/files/browser/fileCommands.ts proves the editor-opening path already supports transferring focus. https://github.com/microsoft/vscode/issues/201667 was folded into this issue despite also naming Open Editors, so the unresolved boundary is whether the public option is Explorer-specific or shared across file-opening lists. Do not alter preview pinning, modifier-based side-by-side opening, double-click behavior, or keyboard-selection semantics.
- **Open decisions:**
  - Should the focus-transfer option apply only to files clicked in the File Explorer, or also to related file-opening lists such as Open Editors?

## Evidence

- **current source:** In src/vs/platform/list/browser/listService.ts, ResourceNavigator.onPointer hard-codes `preserveFocus = true` for a single click, while onMouseDblClick uses `preserveFocus = false`; this directly produces the reported distinction on current main.
- **Explorer path:** src/vs/workbench/contrib/files/browser/views/explorerView.ts passes `e.editorOptions.preserveFocus` unchanged to IEditorService.openEditor, so a single-click event cannot currently transfer focus to the opened editor.
- **existing setting gap:** `workbench.list.openMode` in src/vs/platform/list/browser/listService.ts controls only whether items open on single or double click; it does not configure focus transfer. The `explorer.openAndPassFocus` command in src/vs/workbench/contrib/files/browser/fileCommands.ts supplies the desired focus behavior only for command/keybinding invocation.
- **accepted demand:** The issue was promoted to the Backlog after passing the community threshold and now has 135 upvotes; recent comments still request the option.
- **canonical status:** https://github.com/microsoft/vscode/issues/201667 was closed as a duplicate of this issue, confirming this item owns the single-click focus request, including a related Open Editors case. The older open https://github.com/microsoft/vscode/issues/93772 instead requests hover-based focus-follow-mouse across all panes and does not report the same observable interaction.
