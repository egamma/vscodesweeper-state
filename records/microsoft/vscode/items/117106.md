# Issue #117106 — Advanced wrapping strategy causes hangs for larger files

[https://github.com/microsoft/vscode/issues/117106](https://github.com/microsoft/vscode/issues/117106)

## Summary

The performance defect remains present on current main: a 10 MB/80,000-line model is below the existing large-file thresholds, so advanced wrapping synchronously constructs and measures DOM for every line on open and again when wrapping dimensions change.

## Change summary

Prevent advanced word wrapping from freezing the editor when opening or resizing moderately large text files.

## Best solution

Bound the cost of advanced wrapping for large models, falling back or degrading gracefully before browser measurement can block the window while preserving accurate wrapping where it is required, particularly for accessibility.

## Plan brief

- **Likely files:** `src/vs/editor/common/viewModel/viewModelImpl.ts`, `src/vs/editor/common/viewModel/viewModelLines.ts`, `src/vs/editor/browser/view/domLineBreaksComputer.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** Run a browser performance regression scenario using the reported generated 80,000-line file with word wrap and advanced wrapping enabled; opening and resizing must remain responsive without regressing existing DOMLineBreaksComputer correctness tests.
- **Behavior:**

  > Opening an approximately 10 MB, 80,000-line text file with word wrap and advanced wrapping enabled must not block the VS Code window long enough to trigger an unresponsive-window prompt. Resizing the editor must remain responsive as wrapping dimensions change. Accurate wrapping for ordinary files, proportional fonts, complex scripts, and accessibility mode must remain correct.
- **Trace:**

  > On current main, ViewModelLinesFromProjectedModel._constructLines in src/vs/editor/common/viewModel/viewModelLines.ts adds every model line to one line-break computation. With the advanced strategy, that selects DOMLineBreaksComputer in src/vs/editor/browser/view/domLineBreaksComputer.ts, which renders and measures the full request synchronously. ViewModel in src/vs/editor/common/viewModel/viewModelImpl.ts avoids this projected path only when TextModel.isTooLargeForTokenization() is true; src/vs/editor/common/model/textModel.ts sets that at more than 20 MB or 300,000 lines, so the reported fixture is not protected. The boundary is advanced wrapping accuracy for smaller files and screen-reader users, because WrappingStrategy.compute in src/vs/editor/common/config/editorOptions.ts forces advanced wrapping when accessibility support is enabled.
- **Open decisions:**
  - Should the safeguard be based on model size and line count, an estimated DOM-measurement workload, or an elapsed-time budget?
  - When the safeguard activates, should VS Code use simple wrapping, disable wrapping, or compute advanced wrapping incrementally?
  - How should the safeguard behave when accessibility support forces advanced wrapping for textarea parity?

## Evidence

- **current source path:** src/vs/editor/common/viewModel/viewModelLines.ts `_constructLines` queues every model line and finalizes them synchronously; `createLineBreaksComputer` selects the DOM implementation whenever `wrappingStrategy === 'advanced'`.
- **browser workload:** src/vs/editor/browser/view/domLineBreaksComputer.ts builds one DOM entry for every requested line, appends the complete container to the document, and reads browser-computed break positions before returning.
- **threshold gap:** src/vs/editor/common/model/textModel.ts considers a model too large for tokenization only above 20 MB or 300,000 lines, while src/vs/editor/common/viewModel/viewModelImpl.ts bypasses projected wrapping only for models crossing that test. The reported 10 MB/80,000-line file crosses neither threshold.
- **known freeze behavior:** src/vs/editor/common/config/editorOptions.ts still describes `editor.wrappingStrategy: advanced` as a slow browser-based algorithm that may freeze on large files; it is also forced when accessibility support is enabled.
- **canonical search:** https://github.com/microsoft/vscode/issues/141618 was closed for missing information rather than owning or resolving the work, while https://github.com/microsoft/vscode/issues/249967 concerns decoration line heights and is not a canonical duplicate.
