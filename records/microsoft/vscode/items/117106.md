# Issue #117106 — Advanced wrapping strategy causes hangs for larger files

[https://github.com/microsoft/vscode/issues/117106](https://github.com/microsoft/vscode/issues/117106)

## Summary

The issue is still open and documents a confirmed severe performance problem: advanced wrapping can freeze the editor on large files, and the setting itself warns that this algorithm may cause such freezes. The requested large-file fallback remains useful and should stay tracked.

## Change summary

Automatically avoid or stop advanced browser-based word wrapping for large files so opening and resizing them does not hang VS Code.

## Best solution

Add an automatic large-file safeguard for advanced wrapping in the editor: fall back to the simple strategy when the document exceeds a measured threshold or wrapping exceeds a time budget, while clearly indicating the fallback and preserving an explicit override.

- **Behavior:**

  > Opening or resizing a large text file with word wrap enabled must not leave the editor unresponsive for tens of seconds or trigger repeated keep-waiting prompts. When advanced wrapping would exceed the supported performance envelope, VS Code should use a predictable fallback and make that degradation understandable to the user. Small and ordinary documents must retain the accurate advanced wrapping behavior. An explicit user override, if provided, must have clear precedence.
- **Trace:**

  > The issue's reproduction isolates `editor.wrappingStrategy: "advanced"`: an approximately 10 MB, 80,000-line file opens immediately without wrapping and remains fast with the simple strategy, while advanced wrapping blocks opening and window resize. The advanced path delegates wrap-point computation to browser layout and its registered option explicitly warns that it can freeze on large files. The likely boundary spans the wrapping strategy option in `src/vs/editor/common/config/editorOptions.ts` and browser line layout in `src/vs/editor/browser/viewParts/lines/viewLine.ts` and `viewLines.ts`; preserve advanced wrapping for normal documents and do not alter unrelated large-file optimizations such as tokenization limits. No open canonical issue or concrete fixing commit was established from the supplied related-item record.
- **Open decisions:**
  - Should the fallback be selected from document size or line characteristics before layout, or from a wrapping time budget after layout begins?
  - Should users be notified when VS Code falls back from advanced to simple wrapping, and if so through which existing editor notification surface?
  - Should an explicit setting allow advanced wrapping to remain forced for large files despite the freeze risk?
