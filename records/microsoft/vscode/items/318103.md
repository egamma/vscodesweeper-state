# Issue #318103 — Agents Window: support extension development workflow (extensionDevelopmentPath + debugger)

[https://github.com/microsoft/vscode/issues/318103](https://github.com/microsoft/vscode/issues/318103)

## Summary

The extension-development workflow remains unsupported on current main: debug launches prioritize the ordinary Extension Development Host, and opening an Agents Window from that host does not propagate its development configuration. This accepted Backlog request should stay open for a cross-process design and implementation.

## Change summary

Allow extension developers to launch or open an Agents Window with their development extension loaded and the extension-host debugger attached.

## Best solution

Provide one supported extension-debug launch path that creates the Agents Window workspace while preserving `extensionDevelopmentPath`, debug identifiers, inspect options, and the Agents Window profile. Opening Agents Window from an existing Extension Development Host should follow the same explicit propagation contract rather than reverting to process-startup arguments.

## Plan brief

- **Likely files:** `src/vs/platform/debug/electron-main/extensionHostDebugIpc.ts`, `src/vs/platform/launch/electron-main/launchMainService.ts`, `src/vs/platform/native/electron-main/nativeHostMainService.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`, `src/vs/workbench/contrib/debug/browser/extensionHostDebugService.ts`
- **Validation:** Launch a sample extension through an `extensionHost` debug configuration with `--agents`; verify the resulting window has Agents Window UI, runs the extension from `--extensionDevelopmentPath` rather than its installed copy, stops at a breakpoint in `activate`, and retains normal Agents Window extensions and profile behavior.
- **Behavior:**

  > An `extensionHost` debug configuration that explicitly requests `--agents` opens an Agents Window, loads the extension from `--extensionDevelopmentPath`, and attaches the debugger so activation breakpoints and variable inspection work. Opening Agents Window from an Extension Development Host follows the chosen propagation policy without silently substituting the installed extension. Ordinary Extension Development Host launches and ordinary Agents Window launches remain unchanged.
- **Trace:**

  > The debug IPC path in src/vs/platform/debug/electron-main/extensionHostDebugIpc.ts parses the launch arguments but always dispatches development paths to `IWindowsMainService.openExtensionDevelopmentHostWindow`. The second-instance path in src/vs/platform/launch/electron-main/launchMainService.ts likewise gives `extensionDevelopmentPath` precedence over `agents`. Separately, src/vs/platform/native/electron-main/nativeHostMainService.ts opens Agents Window using process-startup arguments, so a source Extension Development Host's window-specific debug configuration is absent. src/vs/platform/windows/electron-main/windowsMainService.ts can carry CLI configuration into the sessions workspace, but its dedicated Agents Window profile and debugger lifecycle must be reconciled deliberately. Keep ordinary editor-window extension debugging, non-development Agents Window startup, and installed-extension profile behavior outside this explicit workflow unchanged.
- **Open decisions:**
  - Should development configuration propagate only when `--agents` is explicitly present in the debug launch, or whenever an Extension Development Host opens an Agents Window?
  - In development mode, should the Agents Window load the development extension in addition to its normal Agents Window profile extensions, or replace an installed copy while otherwise preserving that profile?

## Evidence

- **debug launch path:** src/vs/platform/debug/electron-main/extensionHostDebugIpc.ts parses `--agents` but unconditionally calls `openExtensionDevelopmentHostWindow` whenever `extensionDevelopmentPath` is present; it never selects `openAgentsWindow`.
- **CLI precedence:** src/vs/platform/launch/electron-main/launchMainService.ts checks `extensionDevelopmentPath` before `args['agents']` in mutually exclusive branches, so supplying both selects the regular Extension Development Host.
- **handoff loses development state:** src/vs/platform/native/electron-main/nativeHostMainService.ts constructs the Agents Window request with `this.environmentMainService.args`, not the source window's `extensionDevelopmentPath`, debug ID, or inspect options.
- **profile behavior:** src/vs/platform/windows/electron-main/windowsMainService.ts preserves the request CLI in `ensureAgentsWindow`, but selects the dedicated Agents Window profile in `doOpenInBrowserWindow`; no current caller combines that window with the source development-host configuration.
- **canonical search:** No older open issue matching this extension-development/debugging symptom was found. https://github.com/microsoft/vscode/issues/325827 is younger and requests registration of external agent runtimes, not development-extension loading or debugger attachment.
- **maintainer triage:** The issue is classified `feature-request`, routed to `extension-host` and `agents-window`, and accepted into the Backlog milestone.
