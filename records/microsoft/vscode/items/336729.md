# Issue #336729 — Codex Agent Host on Linux: workspace sandbox hides the bundled Codex executable

[https://github.com/microsoft/vscode/issues/336729](https://github.com/microsoft/vscode/issues/336729)

## Summary

Keep open and route to the Codex Agent Host sandbox owners. The exact failure remains present in Codex's direct app-server command execution path, while current VS Code still supplies the restricted profile that exposes it.

## Change summary

Codex Agent Host commands on Linux fail before starting because bubblewrap cannot see the bundled Codex executable under the Agent Host SDK cache.

## Best solution

Fix Codex upstream so direct app-server `command/exec` adds its live runtime executables as exact read-only sandbox roots, then update VS Code's bundled Codex version containing that correction. Runtime-owned sandbox augmentation avoids duplicating path and security decisions in the host.

- **runtime path:** src/vs/platform/agentHost/node/agentSdkDownloader.ts places downloaded SDKs under `<userDataPath>/agent-host/sdk-cache/<package>/<version>/<target>`, and src/vs/platform/agentHost/node/codex/codexAgent.ts resolves and spawns the native Codex executable from that SDK root.
- **upstream root cause:** https://github.com/openai/codex/issues/29049 is open and documents the same `bwrap: execvp .../codex: No such file or directory` symptom. - **confirmed workaround:** The issue comment reports that granting read access to the Agent Host Codex SDK-cache directory makes commands work, confirming that runtime visibility—not a missing executable—is the failing boundary.
