# Issue #278353 — Word Wrap turns off when switching files in Explorer panel

[https://github.com/microsoft/vscode/issues/278353](https://github.com/microsoft/vscode/issues/278353)

## Summary

Keep open: the report provides sufficient steps to retest the Explorer-versus-tab difference, but the exact failure is not confirmed on current main. Wrapping synchronization has changed since the report, without a demonstrated fix for losing the original file's toggle state.

## Change summary

Returning to a file through Explorer loses its enabled word-wrap toggle, while switching through editor tabs reportedly preserves it.

## Best solution

Establish whether Explorer navigation replaces a preview editor and disposes its model, or incorrectly resets wrapping for a model that remains open. Preserve toggled wrapping for retained models; distinguish that defect from the existing intentional lifetime of in-memory toggles.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/workbench/contrib/files/browser/views/explorerView.ts`
- **Validation:** On current VS Code with extensions disabled and editor.wordWrap set to off, open two long-line files in pinned tabs. Enable View > Word Wrap in the first, navigate to the second and back using Explorer, and verify the first retains wrapping; compare with tab-bar navigation. Repeat with preview editors and record whether the first model is disposed, distinguishing closing/reopening from switching between retained models.
- **Behavior:**

  > The report says enabling word wrap in a file is undone when navigating away and back through Explorer, but not through editor tabs. A retained file model should keep its per-file toggle regardless of which navigation surface selects it. Acceptance should compare Explorer and tab navigation with both pinned and preview editors, separately identifying cases that close and recreate the original model. The toggle need not become a global setting or acquire restart persistence.
- **Trace:**

  > ToggleWordWrapAction and ToggleWordWrapController in src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts write and reapply wrapping through transient model properties. ModelTransientSettingWatcher in src/vs/editor/browser/services/abstractCodeEditorService.ts removes those properties when the model is disposed. ExplorerView in src/vs/workbench/contrib/files/browser/views/explorerView.ts passes the tree event's pinned option to IEditorService.openEditor, making preview replacement a relevant diagnostic boundary. Source inspection establishes these mechanisms, not whether the reported navigation disposes the original model or resets a still-live model. https://github.com/microsoft/vscode/issues/103199 concerns restart persistence and is not a verified duplicate. Keep global wordWrap configuration, cross-editor sharing of a model's toggle, and restart persistence outside this issue's initial scope.

No commenter independently confirms the reproduction.
- **Toggle lifetime in current source:** src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts stores editor.action.toggleWordWrap state through writeTransientState for a particular text model. ToggleWordWrapController reapplies that model's state on model changes; it does not configure wrapping globally.
- **Potential Explorer lifecycle boundary:** src/vs/workbench/contrib/files/browser/views/explorerView.ts:616 opens files with the tree event's pinned option. In src/vs/editor/browser/services/abstractCodeEditorService.ts:238-250 and 298-307, transient properties belong to a model watcher removed when the model is disposed. This explains a possible preview-replacement mechanism but does not establish that the reporter's original model was disposed.

Its maintainer comment at https://github.com/microsoft/vscode/issues/103199#issuecomment-686763015 explicitly describes Alt+Z as an in-memory, per-file toggle; this does not establish that resetting a retained model is intentional.
