# Issue #226754 — SCM Graph - On refresh, do not lose the current selection

[https://github.com/microsoft/vscode/issues/226754](https://github.com/microsoft/vscode/issues/226754)

## Summary

Keep open: refreshing the Source Control Graph still resets its scroll position and discards loaded history without explicitly restoring and revealing the selected commit. This team-authored, accepted request remains distinct from the related graph issues inspected.

## Change summary

Preserve and reveal the selected commit when refreshing the Source Control Graph.

## Best solution

Within the same repository and filter, refresh should retain the selected commit and reveal it again, including when it was reached through pagination. Preserve existing repository-switching and filtering semantics; broader changes to background-refresh behavior should be considered separately.

## Evidence

- **Current refresh behavior:** In src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts:1898–1916, the graph refresh action reaches SCMHistoryViewPane._refresh(), which clears repository state, updates children, and unconditionally sets this._tree.scrollTop = 0. It does not capture and reveal the previously selected commit.
- **Pagination boundary:** SCMHistoryViewModel.clearRepositoryState() deletes the active repository's cached state at scmHistoryViewPane.ts:1188–1195. getHistoryItems() at lines 1244–1280 subsequently starts with an empty history list and requests one page unless an existing load-more cursor is present. Refresh therefore does not retain the loaded range containing a selection beyond the first page.
- **Existing capability does not cover the ask:** workbench.scm.action.graph.revealCurrentHistoryItem invokes revealCurrentHistoryItem(), which finds the current branch revision through getCurrentHistoryItemTreeElement(), not the user's arbitrary selected commit. The scm.graph settings in src/vs/workbench/contrib/scm/browser/scm.contribution.ts:385–416 control pagination, badges, and incoming/outgoing changes; none provides selection restoration on refresh.
- **Background refresh remains conditional:** scmHistoryViewPane.ts:1787–1803 refreshes silently changed history references only when scrollTop is zero; otherwise it marks the graph outdated. This partially addresses fetch-driven updates but does not deliver the requested preservation of browsing context.
