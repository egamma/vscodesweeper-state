# Issue #336143 — Agents window Markdown preview renders link reference definitions instead of hiding them

[https://github.com/microsoft/vscode/issues/336143](https://github.com/microsoft/vscode/issues/336143)

## Summary

Plausible, well-documented report of a Markdown rendering defect specific to the Agents window's file preview, but I could not pin down which renderer the Agents window actually uses for full-file preview to confirm the defect in source, and no one else has confirmed it — asking the reporter for a bit more detail (which preview surface, a screenshot) before further triage.

## Change summary

Link reference definitions (e.g. `[1]: docker-login.md`) are rendered as visible code-style blocks in the Agents window's Markdown preview instead of being silently consumed, unlike the main window's Markdown preview.

## Best solution

If the Agents window uses a custom/simplified Markdown renderer for file previews (rather than the markdown-language-features extension's markdown-it engine), that renderer needs to consume link reference definitions the way CommonMark requires; if it turns out to reuse the shared `renderMarkdownDocument` helper in src/vs/workbench/contrib/markdown/browser/markdownDocumentRenderer.ts, the vendored marked.js there already appears to handle this case correctly (see evidence), so the actual renderer used for Agents-window file previews needs to be identified first.
