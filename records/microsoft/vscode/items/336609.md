# Issue #336609 — SVG viewer can't zoom

[https://github.com/microsoft/vscode/issues/336609](https://github.com/microsoft/vscode/issues/336609)

## Summary

Current main still contains the SVG dimension fallback that can produce this repeated-zoom failure. This is a source-reproducible regression in the built-in image preview and should be routed there rather than closed.

## Change summary

Repeated Ctrl+wheel zoom changes an SVG's checkerboard background but stops resizing the SVG content after the first tick.

## Best solution

Make SVGs without intrinsic dimensions retain one stable, unscaled base size across successive zoom operations, while preserving existing raster-image zoom and scale-to-fit behavior.

## Plan brief

- **Likely files:** `extensions/media-preview/media/imagePreview.js`
- **Validation:** Launch the media-preview extension in an Extension Development Host, open a viewBox-only SVG with no intrinsic width or height, and verify that at least five consecutive Ctrl+wheel ticks resize both the SVG content and checkerboard consistently in both directions; repeat with a raster image and after returning to scale-to-fit.
- **Behavior:**

  > An SVG without intrinsic width or height must zoom continuously on every Ctrl+wheel tick. Its rendered content and checkerboard-backed image box must scale together rather than making one large initial jump and then changing only the background. Zooming out and returning to scale-to-fit must remain correct, and raster-image behavior must not change.
- **Trace:**

  > The behavior is in extensions/media-preview/media/imagePreview.js. updateScale() detects missing natural dimensions and assigns minWidth/minHeight from the image's current client dimensions on every call; the wheel listener then repeatedly invokes updateScale() from the prior scale. This fallback originated in https://github.com/microsoft/vscode/pull/304973 for https://github.com/microsoft/vscode/issues/240638, but its repeated reassignment conflicts with the original requirement to establish a stable size before CSS zoom. Keep the scope within image-preview scaling: do not change general webview zoom, raster-image sizing, or unrelated custom editors. No existing media-preview test files were found, so validation coverage is the remaining planning concern.

## Evidence

- **current source:** In extensions/media-preview/media/imagePreview.js, updateScale() lines 109-116 recomputes and overwrites minWidth/minHeight from image.clientWidth/clientHeight every time an SVG lacks natural dimensions; the wheel handler at lines 265-286 calls that path repeatedly using the prior scale.
- **regression origin:** https://github.com/microsoft/vscode/pull/304973 introduced this fallback to fix https://github.com/microsoft/vscode/issues/240638. Its stated intent was to lock concrete dimensions before applying CSS zoom, but the dimensions are currently recalculated on every zoom update rather than captured once.
- **canonical search:** The only closely matching report, https://github.com/microsoft/vscode/issues/240638, is closed by the earlier fix and therefore cannot serve as an open duplicate canonical; no other matching open SVG zoom report was found.
