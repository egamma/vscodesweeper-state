# Issue #255286 — Language Model API doesn't allow system prompt

[https://github.com/microsoft/vscode/issues/255286](https://github.com/microsoft/vscode/issues/255286)

## Summary

Keep open for API finalization: system messages exist behind the `languageModelSystem` proposal, but the stable Language Model API still exposes only User and Assistant roles. A maintainer explicitly accepted finalizing this capability, and the remaining public-contract decision is documented in the proposal.

## Change summary

Allow extensions using the stable Language Model API to provide system instructions separately from user messages.

## Best solution

Finalize a stable system-instruction API that preserves system content as a distinct provider input, after choosing whether the public contract is a message role or a request-level property. Keep existing User and Assistant message behavior compatible.

- **Behavior:**

A language-model provider receives those instructions distinctly, including providers whose native protocol uses a top-level system field. Existing User and Assistant message behavior remains compatible. Acceptance requires an integration test using no proposed-API opt-in and confirming that system content is not delivered as a user message.
- **Trace:**

The scope is the public Language Model extension contract and its extension-host conversion path; do not change Copilot Agent's internal prompt construction or existing User/Assistant semantics.
