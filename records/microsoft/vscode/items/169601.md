# Issue #169601 — merge-conflict extension cannot handler '<<<<<<<<' conflict tag

[https://github.com/microsoft/vscode/issues/169601](https://github.com/microsoft/vscode/issues/169601)

## Summary

The bug remains in current main: Git permits non-default conflict-marker widths, but the built-in merge-conflict parser requires the separator to be exactly seven equals signs. Eight-character conflicts therefore pass the initial marker check but are never parsed into a conflict.

## Change summary

Recognize valid Git conflict blocks whose marker width is greater than the default seven characters.

## Best solution

Teach the merge-conflict parser to recognize a consistent Git conflict-marker width across the opening, ancestor, separator, and closing lines while retaining protection against ordinary source lines containing repeated equals signs.
