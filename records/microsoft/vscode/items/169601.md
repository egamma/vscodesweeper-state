# Issue #169601 — merge-conflict extension cannot handler '<<<<<<<<' conflict tag

[https://github.com/microsoft/vscode/issues/169601](https://github.com/microsoft/vscode/issues/169601)

## Summary

Still reproduces on main: the merge-conflict parser uses exact equality for the splitter marker (`=======`) while using `startsWith` for start/end markers, so conflicts with non-standard marker lengths (e.g., 8 characters from git's `conflict-marker-size` attribute or rename/delete scenarios) detect the start but fail to find the splitter.

## Change summary

The merge-conflict extension fails to parse conflicts when git produces markers longer than the standard 7 characters.

## Best solution

Make the splitter detection consistent with start/end: use `startsWith` (or a length-aware match anchored to the detected start-marker length) instead of exact equality in `mergeConflictParser.ts`. This aligns with how git itself scales all markers together when `conflict-marker-size` changes.
