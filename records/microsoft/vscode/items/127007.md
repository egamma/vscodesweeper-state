# Issue #127007 — Only sends a `textDocument/documentHighlight` request when on an identifier

[https://github.com/microsoft/vscode/issues/127007](https://github.com/microsoft/vscode/issues/127007)

## Summary

Keep open: current source still deliberately gates automatic document-highlight requests on a word range, preventing providers from handling standalone punctuation such as Rust exit-point tokens. Existing settings and the programmatic highlight command do not cover automatic cursor-triggered highlighting.

## Change summary

Allow automatic document-highlight requests at non-word positions so language providers can highlight operators and exit points.

## Best solution

Let semantic highlight providers determine whether a cursor position warrants highlights, while preserving word-based textual fallback and existing highlighting controls. The remaining work belongs in the editor occurrence-highlighting contribution, not rust-analyzer's exit-point implementation.
