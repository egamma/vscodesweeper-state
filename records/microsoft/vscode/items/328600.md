# Issue #328600 — 1.131.0 / 0.59.0: devcontainer chat agent type picker fails to list "Copilot CLI"

[https://github.com/microsoft/vscode/issues/328600](https://github.com/microsoft/vscode/issues/328600)

## Summary

Two independent reporters, on 1.131.0 and still on 1.132.0, consistently see the 'Copilot CLI' chat agent type missing from the picker inside a Dev Container, with the log 'Cannot notify option change for sessionType copilotcli: no provider registered. Registered types: []' — a real registration/activation defect, not yet routed to an owning area.

## Change summary

The Copilot CLI chat session provider (contributed by the built-in Copilot extension via the `chatSessions` extension point) fails to register when VS Code is connected to a Dev Container, so users can't select 'Copilot CLI' as an agent type even though `workbench.action.chat.openNewSessionEditor.copilotcli` can still start one.

## Best solution

Investigate why the Copilot extension's 'copilotcli' ChatSessionItemProvider (registered from extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts, bridged via src/vs/workbench/api/browser/mainThreadChatSessions.ts) isn't activating/registering in the remote extension host when the workspace is a Dev Container — likely an activation-event or remote-detection gap distinct from the newer unified AgentHost provider work tracked in the related Dev Containers issue.
