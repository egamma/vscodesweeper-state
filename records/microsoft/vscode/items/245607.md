# Issue #245607 — In fish, can't make shell integration and starship both work at the same time

[https://github.com/microsoft/vscode/issues/245607](https://github.com/microsoft/vscode/issues/245607)

## Summary

Still reproduces on current main. The fish shell integration script's prompt-wrapping mechanism mutually clobbers starship's `fish_prompt` replacement — whichever initializes second overwrites the other. The bash/zsh scripts detect starship via `STARSHIP_SESSION_KEY` and accommodate it, but the fish script lacks starship detection and has no compatible wrapping strategy.

## Change summary

In fish shell, VS Code shell integration and starship cannot both work simultaneously because each replaces `fish_prompt`, and whichever initializes second clobbers the other.

## Best solution

Add starship detection to the fish shell integration script (check `STARSHIP_SESSION_KEY` as bash/zsh already do) and implement a compatible prompt-wrapping strategy — likely by having VS Code SI hook into `fish_prompt` using fish event handlers or by preserving starship's internal call chain when wrapping. The fix belongs in `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.fish`.
