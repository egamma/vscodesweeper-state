# Issue #64721 — [folding] Preview folded content on hover

[https://github.com/microsoft/vscode/issues/64721](https://github.com/microsoft/vscode/issues/64721)

## Summary

A real gap remains: current main can expand a collapsed range from its gutter marker or inline ellipsis, but cannot preview its hidden content. This older issue is the canonical hover-preview request and should remain open under discussion.

## Change summary

Let users preview the contents of a collapsed folding range without expanding it.

## Best solution

Design a core editor preview for collapsed ranges using the established hover or peek infrastructure, with equivalent keyboard and screen-reader access. The design should preserve folding state and avoid changing folding-range computation or the separate custom folded-label API request.

## Vision fit

- **Fit:** aligned
- **Reason:** Previewing folded code improves navigation in a mainstream editor workflow without adding an unrelated bundled capability.
- **Evidence:** Durable themes: Developer inner loop and Workbench & core UX; the public values also favor simple, uniform UI interactions.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingDecorations.ts`, `src/vs/editor/contrib/folding/browser/folding.css`, `src/vs/editor/contrib/hover/browser/contentHoverController.ts`
- **Validation:** Add an editor browser test covering the chosen activation path and asserting that a collapsed range exposes its hidden text without changing collapse state; run the targeted editor folding/hover test with scripts/test.sh --grep "Folding" and complete a keyboard and screen-reader manual check.
- **Behavior:**

  > Users can inspect the text hidden by a collapsed folding range without expanding that range. Opening and dismissing the preview must preserve folding state, cursor position, and editor focus unless the chosen interaction explicitly transfers focus. Existing language hovers and folding toggle behavior must remain unchanged. The preview must be reachable without a mouse and expose meaningful content to screen readers.
- **Trace:**

  > FoldingController in src/vs/editor/contrib/folding/browser/folding.ts owns collapsed-range state and currently listens only for mouse-down and mouse-up events that toggle the range. FoldingDecorationProvider in src/vs/editor/contrib/folding/browser/foldingDecorations.ts supplies a static gutter tooltip, while folding.css renders the clickable inline ellipsis; neither path supplies hidden model text to a hover. ContentHoverController in src/vs/editor/contrib/hover/browser/contentHoverController.ts owns the existing editor content-hover surface and must be evaluated against a dedicated folding preview or peek widget. Keep folding-range computation, FoldingRangeProvider contracts, and provider-defined folded labels out of scope; the latter remains tracked separately by https://github.com/microsoft/vscode/issues/70794. The newer https://github.com/microsoft/vscode/issues/119884 points back to this issue as the canonical request.
- **Open decisions:**
  - Should the preview activate from the inline folded ellipsis, the gutter folding control, the entire folded line, or an explicit command/keybinding?
  - Should the preview be a passive read-only hover or a focusable peek-style editor that supports navigation and selection?
  - Should folded-content preview be enabled by default as part of normal hover behavior, or controlled by an editor setting?
