# Issue #45395 — Double-click selection matches some escaped characters

[https://github.com/microsoft/vscode/issues/45395](https://github.com/microsoft/vscode/issues/45395)

## Summary

Keep open: current word selection still lacks escape-sequence-aware boundaries, and existing settings do not cover the request. The related separator proposals address different behavior, so none verified here qualifies as a canonical duplicate.

## Change summary

Exclude an adjacent escape sequence from double-click word selection and word deletion.

## Best solution

Define escape-aware boundaries for editor word operations, including double-click selection and Ctrl+Backspace, without treating ordinary occurrences of escape letters as separators. Decide whether those boundaries should follow language tokenization or explicit configurable sequence rules.

- **Behavior:**

  > A word immediately following an escape sequence should be selectable without including the escape's letter. Deleting that word with Ctrl+Backspace should preserve the preceding escape sequence. The discussion also requests this for backtick-n escapes. Acceptance should cover the chosen language or configuration scope while leaving ordinary words containing n or t intact.
- **Trace:**

  > The normal double-click path in src/vs/editor/browser/view/viewController.ts invokes word selection, which reaches WordOperations.word in src/vs/editor/common/cursor/cursorWordOperations.ts. Its previous/next-word scans consume character classes from WordCharacterClassifier in src/vs/editor/common/core/wordCharacterClassifier.ts; default backslash and backtick separators leave the following escape letter joined to the next word. editor.wordSeparators cannot express multi-character boundaries, while editor.wordSegmenterLocales and editor.doubleClickSelectsBlock serve different purposes. Preserve ordinary text boundaries, existing separator customization, and unrelated bracket/string block-selection behavior. The unresolved boundary is how the editor identifies actual escape sequences rather than similar literal text. Related design discussions are https://github.com/microsoft/vscode/issues/54571 and https://github.com/microsoft/vscode/issues/40983, neither a verified duplicate of this report.
- **Open decisions:**
  - Should escape-aware boundaries follow language-recognized escapes by default, or require explicit configurable sequence rules, and therefore also apply in plain text?
