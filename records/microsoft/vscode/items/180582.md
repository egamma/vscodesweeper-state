# Issue #180582 — Proposal: Canonical URI identity provider

[https://github.com/microsoft/vscode/issues/180582](https://github.com/microsoft/vscode/issues/180582)

## Summary

Keep open: this is an `api-proposal` tracking issue, so implementing the API as proposed does not complete it; it remains open until the API owners finalize or explicitly abandon the contract. Current main still carries the proposed API, and workspace trust retains the URI-specific behavior the proposal was intended to replace.

## Change summary

Provide a common API for resolving equivalent resource URIs across filesystems, remote environments, and source-control URL forms.

## Best solution

The API owners should settle the canonical-URI contract, adopt it on the workspace-trust path where appropriate, and either finalize it into the stable extension API or explicitly abandon the proposal. Finalization must preserve the existing edit-session normalization behavior while replacing workspace trust's scheme-specific aliases with provider-based identities.
