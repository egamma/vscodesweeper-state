# Issue #332072 — Same-name user/workspace MCP collision leaves stopped server inoperable until server ID is renamed

[https://github.com/microsoft/vscode/issues/332072](https://github.com/microsoft/vscode/issues/332072)

## Summary

Fresh (same-day), well-documented bug report with a confirmed, repeatable reproduction sequence (comment 3) showing stale collision state between the workbench MCP registry and Agent Host session customization mapping; needs area-owner investigation rather than a mechanical close.

## Change summary

When user-scoped and workspace-scoped mcp.json define the same server ID, the collision 'losing' registration can leave a stale/unstartable server entry (stuck spinner, CodeLens missing, Agent Host logging 'Cannot start/stop unknown MCP server customization') even after the same-name sorting fix in #327979/#329010, and renaming only fixes it via a subsequent window reload.

## Best solution

MCP/Agent Host owners should trace how mcpWorkbenchService's per-resource 'Overwriting mcp server' collision resolution (src/vs/workbench/contrib/mcp/browser/mcpWorkbenchService.ts) is kept in sync with the Agent Host's customizationId-to-server mapping (e.g. src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts's 'Cannot start/stop unknown MCP server customization' path) so a collision winner change invalidates stale bindings without requiring a manual rename + window reload.
