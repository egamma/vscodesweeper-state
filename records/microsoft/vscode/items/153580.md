# Issue #153580 — Delay when switching between settings sections

[https://github.com/microsoft/vscode/issues/153580](https://github.com/microsoft/vscode/issues/153580)

## Summary

Still reproduces on main: switching settings scopes calls onConfigUpdate(undefined, true) which rebuilds the entire model — the TODO acknowledging this is still present in onDidSettingsTargetChange. PR #170911 only addressed one contributor (aria label computation), not the core rebuild.

## Change summary

Switching between User/Workspace/Folder settings sections causes a noticeable delay because the entire settings model is rebuilt instead of refreshing only the changed values.

## Best solution

Implement the TODO in onDidSettingsTargetChange (line ~921 of settingsEditor2.ts): instead of rebuilding the whole model via onConfigUpdate(undefined, true), refresh and uncache only the inspected setting values for the new target scope, avoiding the full tree reconstruction and extension toggle resolution.
