## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/90611 is currently open and was created on 2020-02-13, before this report. Its discussion explicitly reports missing editor gutters when a repository's parent directory is symlinked and editor paths differ from repository paths. https://github.com/microsoft/vscode/issues/90611#issuecomment-615939683 describes the path mismatch; https://github.com/microsoft/vscode/issues/90611#issuecomment-1099551954 explains that mismatch from the maintainer's perspective. This meets the re-review requirement of an older canonical with the same reporter-observable symptom.
- **Reporter supplied diagnostic evidence:** The complete final trace at https://github.com/microsoft/vscode/issues/267247#issuecomment-3642792891 switches to Trace before opening the affected file. The editor resource is /media/struct1/code/slide/src/songs.js, while repository discovery returns the existing /home/yo/code/slide repository and file-change events use that alias. No provideOriginalResource entries appear in that trace, consistent with filtering before the Git provider is called.
- **Current source confirms failing flow:** extensions/git/src/repository.ts creates source control with Uri.file(repository.root). src/vs/workbench/api/browser/mainThreadSCM.ts passes that rootUri into the quick-diff provider. src/vs/workbench/contrib/scm/common/quickDiffService.ts:87-94 filters providers by URI ancestry before invoking them. The real-path editor resource in this report is not beneath its symlink-path repository root, so the Git provider is excluded. UriIdentityService uses casing-aware lexical URI comparisons, not filesystem symlink resolution.
- **Repository deduplication does not fix gutter lookup:** extensions/git/src/model.ts:getRepositoryExact resolves real paths to deduplicate repositories, matching the reporter's 'already exists' trace. However, getOpenRepository checks ancestry against repository.root only, and extensions/git/src/quickDiffProvider.ts also depends on that lookup. These remaining alias-sensitive paths explain why successful repository discovery does not establish working gutters.
- **Other search lead is distinct:** https://github.com/microsoft/vscode/issues/184638 is also open, but its detailed symlink discussion concerns links inside a normal repository to another repository subdirectory. The parent-directory alias mismatch explicitly documented in https://github.com/microsoft/vscode/issues/90611 is the stronger canonical for this report.
