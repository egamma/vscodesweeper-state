# Issue #318863 — getCwd() on macOS invokes lsof on every terminal command, generating many syscalls per invocation

[https://github.com/microsoft/vscode/issues/318863](https://github.com/microsoft/vscode/issues/318863)

## Summary

Valid performance bug: `getCwd()` in `terminalProcess.ts` unconditionally spawns `lsof` on every call on macOS, even when shell integration has already reported the CWD via `_properties.cwd`. The workaround was for a Big Sur Electron bug (#105446) that the code's own comment acknowledges is fixed. Still present on current `main`.

## Change summary

On macOS, every terminal command triggers an expensive `lsof` invocation (~245k syscalls) to detect CWD, even when shell integration already reported it.

## Best solution

In `src/vs/platform/terminal/node/terminalProcess.ts` `getCwd()`, check `this._properties.cwd` first and return it when available (shell integration provides it via OSC 633). Fall back to `lsof` only when shell integration hasn't reported a CWD. Long-term, consider replacing `lsof` entirely with `proc_pidinfo` or removing it now that the Electron bug is fixed. This also relates to https://github.com/microsoft/vscode/issues/327349 which reports a parsing bug in the same lsof path.
