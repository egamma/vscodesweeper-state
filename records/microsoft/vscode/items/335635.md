# Issue #335635 — Copilot chat terminal command completed notification disrupts chat flow/context with "What would you like me to work on"

[https://github.com/microsoft/vscode/issues/335635](https://github.com/microsoft/vscode/issues/335635)

## Summary

Real, plausible defect in the agent-host/Copilot turn-state machine: a `shell_completed`/`shell_detached_completed` system notification is configured to `startsTurn: true` and, when it arrives while the parent turn has no active `_turnId`, forcibly resets turn state and opens a brand-new root turn instead of continuing the existing conversation — matching the reporter's symptom of a sudden context-free 'what would you like me to work on' reply. I traced the mechanism in source but could not execute the exact async-terminal + Ctrl-C race to confirm it end-to-end.

## Change summary

An async terminal 'command completed' system notification interrupts an in-progress agent turn and starts a fresh turn devoid of prior conversation context, derailing the chat.

## Best solution

In `copilotAgentSession.ts`'s `onSystemNotification` handler and the matching branch in `mapSessionEvents.ts`, ensure a turn-starting notification that arrives shortly after an in-flight turn (e.g. still mid tool-cycle, or immediately following a cancel signal that explicitly asked the model to keep going) is appended to/resumes the existing turn rather than unconditionally calling `resetTurnState`/emitting `ChatTurnStarted`.

- **Behavior:**

  > When an agent sends a cancel/interrupt to an async terminal and is explicitly told to continue the same turn, a subsequent 'command completed' system notification for that terminal must not truncate or restart the conversation. The agent's next model turn should retain full prior context (no sudden drop in input token count) and must not respond with a generic 'What would you like me to work on' message that ignores everything discussed so far. Acceptance: the added/extended turn-state test in copilotAgentSession.test.ts passes, confirming the notification is folded into the active turn instead of opening a new root turn.
- **Trace:**

  > `buildCopilotSystemNotification` (src/vs/platform/agentHost/node/copilot/copilotSystemNotification.ts) tags shell completion notifications `startsTurn: true`. In `copilotAgentSession.ts`'s `_subscribeToEvents`/`onSystemNotification` handler (~lines 5063-5103), when `this._turnId` is falsy at the moment the notification arrives, the code unconditionally calls `resetTurnState(turnId)` and emits a fresh `ActionType.ChatTurnStarted` using the notification text as the turn's origin message — this is the mechanism that produces the reported context-free 'what would you like me to work on' reply. `mapSessionEvents.ts` (lines 673-693) has an analogous branch keyed off `parentBuilder`/`rootAssistantTurnActive`. The open question is exactly when `_turnId` becomes unset relative to a Ctrl-C cancel that explicitly instructs the agent to keep going — i.e. whether the SDK/host is prematurely marking the parent turn as no-longer-active before the shell notification lands. Do not change the `startsTurn` semantics for genuinely idle/background completions (e.g. a detached shell finishing minutes after the user walked away) — those legitimately should surface as a new turn-starting notification; the fix must be scoped to the case where a turn is still logically in-flight. Related but distinct: https://github.com/microsoft/vscode/issues/332473 and https://github.com/microsoft/vscode/issues/336348.
- **Open decisions:**
  - What is the precise state transition that clears `_turnId` (or `parentTurnTerminated`/`rootAssistantTurnActive`) between the cancel signal and the shell-completed notification — is the turn marked complete too early, or is this genuinely a race between the SDK's async event stream and the turn lifecycle?
  - Should the fix live in the host's turn-state tracking (treat 'told not to end the turn' as keeping the turn open) or in the SDK/session layer that decides when to emit `shell_completed` events relative to turn boundaries?
  - Is there a general distinction the host should track between 'idle completion, safe to start a new turn' and 'completion during an active but currently-non-committed turn' that would also help https://github.com/microsoft/vscode/issues/336348?
