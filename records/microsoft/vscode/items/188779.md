# Issue #188779 — No progress if Notebook output coming in slow

[https://github.com/microsoft/vscode/issues/188779](https://github.com/microsoft/vscode/issues/188779)

## Summary

Keep open: current cell progress follows execution state, not pending output rendering, so the reported feedback gap is not covered by the existing indicator. The supplied notebook sample is sufficient to retest, but the current duration of the gap has not been verified.

## Change summary

Provide meaningful progress feedback when notebook execution finishes before its streamed output becomes visible.

## Best solution

Make the transition from execution to delayed output presentation understandable without misrepresenting kernel execution status. First retest the supplied sample and decide whether pending rendering should extend the existing progress presentation or have a distinct indication.

Acceptance should cover the supplied streaming sample and a small, immediately rendered output, with no artificial delay added to execution completion.

Preserve execution success semantics, streaming output content, and rendering responsiveness; the unresolved product boundary is how pending presentation should be represented after execution ends.
