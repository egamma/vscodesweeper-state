# Issue #341467 — Quick Search: Escape after previewing a match in another file does not reopen the original preview editor

[https://github.com/microsoft/vscode/issues/341467](https://github.com/microsoft/vscode/issues/341467)

## Summary

Thanks for the very detailed report. The source supports it: Quick Search restores the original editor via the shared PickerEditorState, which only reopens the saved input and never checks whether that preview input was replaced and disposed. I could not run it, but the report is complete (14/14 attempts, exact steps) and is enough to retest.

## Change summary

After previewing a match in another file from Quick Search, pressing Escape does not reopen the original preview editor.

## Best solution

Make PickerEditorState.restore() reliably bring back a preview editor that was replaced by the transient preview, for example by saving a resource-based editor reference or keeping the input alive. Quick Search and Quick Open should then share the fix.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/quickaccess.ts`, `src/vs/workbench/contrib/search/browser/quickTextSearch/textSearchQuickAccess.ts`
- **Validation:** Manually follow the report's steps: preview a.txt, then Quick Search for 'bravo', then Escape. a.txt should be open again at Ln 3, Col 2 and the b.txt preview closed. Add a PickerEditorState test with a preview editor replaced by a transient one.
- **Behavior:**

  > After Escape from Quick Search, the editor that was active when it opened must be restored, including when it was a preview editor replaced by a transient preview of another file. The transient preview is closed, the view state is restored, and keyboard focus does not move to the editor. Pinned and same-file behavior must not change.
- **Trace:**

  > PickerEditorState in src/vs/workbench/browser/quickaccess.ts stores the EditorInput and group in set(). openTransientEditor() opens the match transiently, which replaces a preview a.txt, and restore() reopens the stored input. The likely cause is that the stored input is disposed once the preview is replaced, so the reopen fails. This is unconfirmed and should be checked first. Related: https://github.com/microsoft/vscode/issues/341449. Do not change picker focus semantics.

## Evidence

- **code path:** src/vs/workbench/browser/quickaccess.ts, PickerEditorState.set() saves activeEditorPane.input. openTransientEditor() then opens the match, which replaces a preview a.txt. restore() calls group.openEditor(savedInput) without checking whether that input is still usable.
- **consumer:** src/vs/workbench/contrib/search/browser/quickTextSearch/ calls editorViewState.set(), openTransientEditor() and restore(). This matches the report, where a pinned a.txt restores and a preview a.txt does not.
- **not executed:** I could not run the repro, so the disposed-input explanation is a reading of the source, not an observed result. The report's own 14/14 repro and the code agree.
- **related:** https://github.com/microsoft/vscode/issues/341449 is a related but different symptom: the pinned case loses keyboard focus after Escape.
