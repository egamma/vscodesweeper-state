# Issue #305969 — Go to Repeating Prompt with Each Character Typed When Using a Screen Reader

[https://github.com/microsoft/vscode/issues/305969](https://github.com/microsoft/vscode/issues/305969)

## Summary

Keep open: another user confirms the repeated announcements, and no verified fix or canonical duplicate was found. The Linux comment distinguishes a related Quick Open symptom from Go to Line; current screen-reader behavior needs checking before choosing a fix.

## Change summary

Prevent Go to Line from repeating its navigation announcement twice for each digit typed with a screen reader.

## Best solution

Make Go to Line announce the updated destination once without repeatedly announcing the input prompt, while preserving text editing and result navigation. Investigate the shared quick-input accessibility lifecycle and verify the Windows report separately from the Linux Quick Open observation.

- **Current Go to Line path:** src/vs/editor/contrib/quickAccess/browser/gotoLineQuickAccess.ts: AbstractGotoLineQuickAccessProvider.provideWithTextEditor assigns a stable picker ariaLabel, then replaces picker.items on each value change with an item whose ariaLabel contains the destination and Enter instruction. The source identifies the announcement content but does not conclusively establish why a screen reader speaks it twice.
- **Shared accessibility lifecycle:** src/vs/platform/quickinput/browser/quickInputController.ts removes aria-activedescendant and disables list focus mode on non-modifier keydown, then restores them on list focus changes. QuickInputBox.setListFocusMode changes aria-haspopup and aria-autocomplete; QuickInputList.setElements also removes and reinserts the focused row on a timeout in screen-reader mode. These are investigation leads, not proof of the speech duplication's cause.
