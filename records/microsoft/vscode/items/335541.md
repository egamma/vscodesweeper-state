# Issue #335541 — Bundled GitHub.copilot-chat throws "CANNOT use API proposal: envIsConnectionMetered" on every inline completion request

[https://github.com/microsoft/vscode/issues/335541](https://github.com/microsoft/vscode/issues/335541)

## Summary

Well-diagnosed real bug: the official product.json's extensionEnabledApiProposals grant list for GitHub.copilot-chat is stale relative to the bundled extension's own manifest, and per src/vs/workbench/services/extensions/common/extensionsProposedApi.ts the product.json list fully overrides the extension's declared proposals — so a missing entry breaks every automatic inline completion. The public checkout doesn't contain the internal product.json used for official/Insiders builds, so I can't fix or confirm regeneration timing here, but the mechanism is confirmed in source.

## Change summary

Bundled Copilot Chat throws 'CANNOT use API proposal: envIsConnectionMetered' on every automatic inline completion because product.json's grant list is out of sync with the extension's package.json.

## Best solution

Ensure the internal build step that generates official product.json's extensionEnabledApiProposals for GitHub.copilot-chat is regenerated in lockstep with the bundled extension's package.json#enabledApiProposals for each Insiders build (ideally with a build-time check comparing the two lists); this is outside the public repo checkout, which only ships the stripped-down OSS product.json.
