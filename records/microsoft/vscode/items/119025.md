# Issue #119025 — Display mixed line endings explicitly in status bar as "LF (mixed)" or "CRLF (mixed)"

[https://github.com/microsoft/vscode/issues/119025](https://github.com/microsoft/vscode/issues/119025)

## Summary

Keep this accepted, community-supported request open: current source still normalizes mixed endings without exposing their original presence in the status bar. The older related issues cover preservation and per-line rendering, not the same requested status-bar indication.

## Change summary

Indicate that an opened file contains mixed line endings using an explicit status-bar label such as LF (mixed) or CRLF (mixed).

## Best solution

Expose the original file's mixed-EOL condition through the existing editor status entry, with a clearly defined lifetime across edits, saves, and reloads. Treat optional save confirmation and mixed-ending preservation as separate scope decisions, coordinated with https://github.com/microsoft/vscode/issues/127.

Add automated coverage for original mixed-EOL detection, including a CRLF sequence split between input chunks, and the agreed status-entry lifecycle.
- **Behavior:**

  > Opening a file with mixed LF, CRLF, or standalone CR endings should visibly distinguish it from a file with uniform endings in the existing EOL status entry. Uniform LF and CRLF files should retain their current labels and change-EOL interaction. Acceptance must define when the mixed indicator clears after edits, saving, or reloading. The reporter additionally requests optional save confirmation and preservation; those are not prerequisites for an informational indicator unless the maintainer explicitly includes them.
- **Trace:**

  > PieceTreeTextBufferBuilder in src/vs/editor/common/model/pieceTreeTextBuffer/pieceTreeTextBufferBuilder.ts already counts CR, LF, and CRLF before PieceTreeTextBufferFactory.create normalizes the chunks. createTextBufferFactory and createTextBufferFactoryFromStream in src/vs/editor/common/model/textModel.ts use finish() with normalization enabled. EditorStatus.onEOLChange in src/vs/workbench/browser/parts/editor/editorStatus.ts reads only the normalized model's getEOL(), so scanning that model cannot recover the original mixture. The distinction between original file bytes and normalized editor content is therefore central to the design. Preserve existing normalization and save behavior for an indicator-only scope; mixed-ending preservation is separately tracked at https://github.com/microsoft/vscode/issues/127, and inline rendering at https://github.com/microsoft/vscode/issues/12223. Source inspection establishes the missing capability, but no UI execution was performed in this read-only review.
- **Open decisions:**
  - Should the mixed indicator describe the original on-disk file until a successful save or reload, or clear upon the first edit as suggested in the issue body?
  - Is this request limited to an informational status indicator, or should it also include save confirmation and a Leave Mixed option that preserves individual endings?
