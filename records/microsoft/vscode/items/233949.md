# Issue #233949 — Editor GPU: Lines invalided by onLinesInserted and onLinesDeleted events should shift and retain valid line data

[https://github.com/microsoft/vscode/issues/233949](https://github.com/microsoft/vscode/issues/233949)

## Summary

Keep this protected plan-item open: current source still discards valid cached-line status after insertions and deletions, so the requested optimization remains outstanding.

## Change summary

Retain and shift valid GPU-rendered line data when lines are inserted or deleted instead of invalidating all subsequent lines.

## Best solution

Preserve reusable line data and corresponding cache validity across structural edits in FullFileRenderStrategy, while maintaining correct positioning and clearing obsolete rows in both buffers. Keep this specific optimization tracked separately from the broader GPU-renderer roadmap.

## Evidence

- **Protected planning item:** https://github.com/microsoft/vscode/issues/233949 carries plan-item, which requires keeping it open regardless of apparent completion or duplicate overlap. Backlog is a holding milestone, not a scheduled release.
- **Optimization remains absent:** In src/vs/editor/browser/gpu/renderStrategy/fullFileRenderStrategy.ts, onLinesInserted and onLinesDeleted both call _invalidateLinesFrom(e.fromLineNumber). That helper deletes every subsequent cached line number from both _upToDateLines sets; both handlers retain TODOs explicitly requesting shifting line data to preserve valid lines.
- **Partial shifting is not cache retention:** FullFileRenderStrategy.update handles queued ViewLinesDeleted events by shifting cell-buffer content and clearing obsolete rows, but the handler has already invalidated subsequent cache entries. Insertions do not queue an equivalent shift. Existing deletion-buffer movement therefore does not complete the central request.
- **Merged prerequisite, not completion:** https://github.com/microsoft/vscode/pull/233947 is merged and explicitly lists this issue as a follow-up. Its body closes https://github.com/microsoft/vscode/issues/227107, the initial dirty-line caching work, rather than this cache-retention optimization.
