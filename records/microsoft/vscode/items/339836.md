# Issue #339836 — Session-level "Mark as Done" only marked the main chat as done

[https://github.com/microsoft/vscode/issues/339836](https://github.com/microsoft/vscode/issues/339836)

## Summary

Confirmed in source: the explicit 'Mark as Read' command only marks the main chat, not peer chats, contrary to the TPI's intent of marking the whole session read. Routing with a bug label so the sessions area owner can pick it up.

## Change summary

Using the session-level 'Mark as Read' action only marks the main chat as read, leaving peer chats in the session unread.

## Best solution

Have the MarkSessionReadAction command (MARK_SESSION_READ_COMMAND_ID) call ISessionsManagementService.setSessionReadState (which already marks all unread aggregate chats, including peers, via the provider) instead of markRead (which is scoped to the main chat only and is also used by other flows like open-session auto-read that should keep their current main-chat-only behavior).

  > Thanks for the detailed repro. This traces to the 'Mark as Read' session command (MARK_SESSION_READ_COMMAND_ID) going through `ISessionsManagementService.markRead()`, which is scoped to the main chat only (sessionsManagementService.ts, `_setMainChatReadState`). The provider already has logic to mark a whole session's unread chats — including peers — read (`setSessionReadState`, used by bulk 'mark all read'); the explicit per-session command should use that instead so it matches the TPI's described behavior.
