# Issue #257285 — Users need to be guided to make a proper instruction file

[https://github.com/microsoft/vscode/issues/257285](https://github.com/microsoft/vscode/issues/257285)

## Summary

Keep open: current main guides users who create instruction files through the built-in command, but manually authored nonempty `.instructions.md` files without frontmatter receive no indication that they will not be attached automatically. This is also a team-authored feature request, and no explicit fixing commit or canonical duplicate was found.

## Change summary

Guide users to add an `applyTo` header when an instruction file is intended to be attached automatically.

## Best solution

Expose non-error guidance for instruction files without `applyTo`, explaining that they are currently manual-only and offering an easy way to add an automatic-attachment scope, while preserving intentional manually attached files as valid.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptHeaderAutocompletion.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptCodeActions.ts`, `src/vs/workbench/contrib/chat/test/browser/promptSyntax/languageProviders/promptValidator.test.ts`, `src/vs/workbench/contrib/chat/test/browser/promptSyntax/languageProviders/promptCodeActions.test.ts`
- **Validation:** Add focused language-provider tests showing the chosen guidance for a nonempty `.instructions.md` file without `applyTo`, no such guidance when a valid `applyTo` exists, and no error that would invalidate intentional manual-only instruction files; run `./scripts/test.sh --grep "PromptValidator|PromptCodeActionProvider|PromptHeaderAutocompletion"`.
- **Behavior:**

  > A user editing a workspace `.instructions.md` file without `applyTo` can discover that the file will not be attached automatically and how to configure automatic attachment. Files with a valid `applyTo` remain free of this guidance. Omitting `applyTo` remains supported for files that users intend to attach manually, so the guidance must not present the file as invalid.
- **Trace:**

  > The built-in creation flow in `src/vs/workbench/contrib/chat/browser/promptSyntax/newPromptFileActions.ts` already includes a commented `applyTo` example, but manually created nonempty files bypass that help. `PromptHeaderAutocompletion.provideCompletionItems` returns when no header can be parsed, `PromptValidator.validateApplyTo` silently accepts a missing attribute, and `PromptCodeActionProvider` excludes instruction files entirely. The existing tests confirm validation only for malformed present values and explicitly confirm the absence of instruction-file code actions. Keep manual attachment semantics unchanged, as documented by the maintainer discussion in https://github.com/microsoft/vscode/issues/249531; the uncertainty is only which user-visible guidance surface should explain automatic attachment.
- **Open decisions:**
  - Should a missing `applyTo` produce an informational editor diagnostic with a quick fix, a completion/header suggestion, status in the instruction-management UI, or more than one of these surfaces?
  - Should guidance appear for every workspace instruction file without `applyTo`, or only when VS Code can infer that the user expects automatic attachment?

## Evidence

- **originating verification:** The report arose from verification of https://github.com/microsoft/vscode/issues/255742; its final comment confirms that `.github/instructions/codestyle.instructions.md` was only attached after adding `applyTo: '**'`.
- **partial current guidance:** `getDefaultContentSnippet` in `src/vs/workbench/contrib/chat/browser/promptSyntax/newPromptFileActions.ts` now scaffolds new instruction files with a commented `applyTo` example and explains that it controls automatic attachment.
- **remaining source gap:** `PromptHeaderAutocompletion.provideCompletionItems` in `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptHeaderAutocompletion.ts` offers a header only for an entirely empty file and returns no suggestions for a nonempty file without a parsed header. Its generated empty-file header contains `description` but not `applyTo`.
- **no missing-scope diagnostic:** `PromptValidator.validateHeader` and `validateApplyTo` in `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts` return without reporting when the header or `applyTo` attribute is absent.
- **no instruction quick fix:** `PromptCodeActionProvider.provideCodeActions` in `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptCodeActions.ts` explicitly excludes `PromptsType.instructions`; `promptCodeActions.test.ts` asserts that instruction files receive no code actions.
- **optional semantics:** Maintainer discussion in https://github.com/microsoft/vscode/issues/249531 establishes that `applyTo` controls automatic attachment while files without it remain usable through manual attachment, so missing `applyTo` should not be treated as an invalid file.
