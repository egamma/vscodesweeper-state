# Issue #337392 — Zsh terminal revive reuses VS Code temporary ZDOTDIR as USER_ZDOTDIR

[https://github.com/microsoft/vscode/issues/337392](https://github.com/microsoft/vscode/issues/337392)

## Summary

Confirmed on main: the zsh shell-integration injection derives USER_ZDOTDIR from the raw ZDOTDIR env var, but on revive that env already carries VS Code's own temp ZDOTDIR from the first launch, so the revived shell inherits VS Code's temp dir as its "user" ZDOTDIR instead of the real one.

## Change summary

Reviving a persisted zsh terminal after a VS Code restart sets USER_ZDOTDIR to VS Code's internal shell-integration temp dir instead of the user's real ZDOTDIR/home, so the user's .zshrc isn't loaded.

## Best solution

In getShellIntegrationInjection's zsh branch (src/vs/platform/terminal/node/terminalEnvironment.ts), prefer an already-set env.USER_ZDOTDIR over env.ZDOTDIR when computing userZdotdir, since USER_ZDOTDIR (once set by a prior injection) is the authoritative real value, whereas ZDOTDIR may already be VS Code's own temp dir on revive.

## Evidence

- **root cause:** src/vs/platform/terminal/node/terminalEnvironment.ts:256 computes `const userZdotdir = env?.ZDOTDIR ?? os.homedir() ?? '~';` using whatever ZDOTDIR is already in the passed-in env, with no check for whether it's already VS Code's own temp dir.
- **why env already has the temp ZDOTDIR:** src/vs/platform/terminal/node/terminalProcess.ts:211-217 mutates `this._ptyOptions.env` in place with the injection envMixin (including ZDOTDIR=temp dir) during start(). ptyService.ts:337-343 stores that same env object (by reference) as `processLaunchOptions.env`, which is exactly what's serialized (ptyService.ts:239-240) and replayed on revive (ptyService.ts:297, 318-337) as the base `env` for the new TerminalProcess — so the second `getShellIntegrationInjection` call on revive sees env.ZDOTDIR already set to VS Code's temp dir.
- **existing test coverage gap:** src/vs/platform/terminal/test/node/terminalEnvironment.test.ts:190-200 only tests a genuinely custom ZDOTDIR being honored as USER_ZDOTDIR; there's no test for the revive case where ZDOTDIR is already VS Code's own temp value.
