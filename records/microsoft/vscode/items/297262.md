# Issue #297262 — Chat customisations search should be able to search across all customistations

[https://github.com/microsoft/vscode/issues/297262](https://github.com/microsoft/vscode/issues/297262)

## Summary

Keep open: category search still filters only the selected section. The experimental Discover surface now provides cross-category installed-item search, but it does not deliver the requested behavior from the existing category search boxes.

## Change summary

Search across customization categories, identify each result's category, and switch to that category when a result is selected.

## Best solution

Provide a consistent cross-category search experience in the shared customizations editor, reusing Discover's installed-item aggregation where appropriate. Retain clear category identification and navigation without requiring marketplace discovery to be enabled.

- **Reason:** Finding customizations without manually searching each category advances consistent workbench interactions and the AI-assisted development experience.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationListWidget.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationDiscoveryPage.ts`
- **Validation:** With differently named installed items in Agents, Skills, and Instructions, start a search from one category and verify matches in the other categories are discoverable, their categories are identifiable, and selecting a match activates its owning category. Repeat with chat.customizations.marketplace.enabled disabled and enabled; hidden harness sections must remain excluded.
- **Behavior:**

  > Searching from a customization category currently searches only that category. The requested experience finds matching customizations across categories, identifies each result's category, and activates the owning category when selected. Acceptance should include cross-category matches with marketplace discovery disabled, correct result navigation, and preservation of harness visibility restrictions.
- **Trace:**

  > AICustomizationListWidget.setSection() subscribes to one items-model section, and applyItemsFromModel() reloads only currentSection before applying the search filter. AICustomizationManagementEditor.setSearchQuery() separately dispatches to the active prompt, MCP, plugin, model, tools, or contributed-section widget. AICustomizationDiscoveryPage already aggregates installed items across prompt-based sections, plugins, and MCP servers, but its Discover surface is gated by experimental marketplace availability. The remaining uncertainty is the user-visible relationship between category search and this newer unified surface, not whether cross-category matches are desired. Preserve harness filtering and existing customization actions; marketplace catalog results are distinct from installed customizations. https://github.com/microsoft/vscode/issues/297572 is related result-labeling feedback, not a duplicate target.
- **Open decisions:**
  - Should entering a query in a category retain that category's view and display cross-category results there, or transition to a shared installed-customization search view that is available independently of marketplace discovery?
