## Summary

The requested multicursor line movement remains incomplete, but the older, open canonical issue already owns exactly this behavior. Consolidate this report there rather than close it as fixed.

## Change summary

- **Matching maintainer diagnosis and confirmation:** https://github.com/microsoft/vscode/issues/11809#issuecomment-246322673 identifies overlapping edits from one MoveLinesCommand per cursor, matching the maintainer's diagnosis in this report. https://github.com/microsoft/vscode/issues/11809#issuecomment-2979767058 confirms that consecutive lines still lose all but the primary cursor, while sufficiently separated selections move successfully.
- **Current built-in capability remains partial:** src/vs/editor/contrib/linesOperations/browser/linesOperations.ts:167-190 still creates a separate MoveLinesCommand for every selection in AbstractMoveLinesAction.run. The Alt+Up and Alt+Down registrations invoke this action; src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts operates on an individual selection, without coordinating adjacent selected lines.
