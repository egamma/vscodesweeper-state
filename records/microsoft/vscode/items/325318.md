# Issue #325318 — Profiles: Specify default profile per-machine

[https://github.com/microsoft/vscode/issues/325318](https://github.com/microsoft/vscode/issues/325318)

## Summary

A real configuration gap remains: the profile for new windows is currently synchronized across machines, with no machine-local override. Route this to the user profiles area.

## Change summary

Allow each machine to override the synchronized default profile used for unassociated folders and new windows.

## Best solution

Support a machine-local override for `window.newWindowProfile` while retaining the synchronized application-level value as its fallback. The user profiles configuration and management services already centralize selection of this profile.

## Vision fit

- **Fit:** aligned
- **Reason:** Per-machine profile selection improves settings fidelity and keeps work and personal environments appropriately separated.
- **Evidence:** Durable theme: Workbench and core UX includes profiles and settings fidelity.

## Evidence

- **current configuration:** `src/vs/workbench/common/configuration.ts` registers `window.newWindowProfile` with `ConfigurationScope.APPLICATION`, so Settings Sync carries one selection across machines.
- **selection path:** `src/vs/workbench/services/userDataProfile/browser/userDataProfileManagement.ts` reads `window.newWindowProfile` in `getDefaultProfileToUse()` for unassociated workspaces.
- **existing capability:** https://github.com/microsoft/vscode/pull/213403 introduced the selectable new-window profile, but did not provide a machine-local override.
- **prior use case:** The discussion in https://github.com/microsoft/vscode/issues/181677 explicitly raised different default profiles for work and home machines; that issue was closed after the synchronized setting was introduced.
