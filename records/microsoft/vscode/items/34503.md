# Issue #34503 — Implement privacy mode

[https://github.com/microsoft/vscode/issues/34503](https://github.com/microsoft/vscode/issues/34503)

## Summary

VS Code already provides per-service settings to disable all core outbound connections (telemetry, updates, extension auto-check, git fetch), documented in the FAQ. A single unified 'privacy mode' toggle that also blocks extension network access is out of scope — true network isolation is an OS-level concern (firewall, containers), and extensions intentionally have full node API access by design.

## Change summary

Request a single configurable privacy flag to block all outbound network connections from VS Code.

## Best solution

Close as out-of-scope. VS Code core's individual network-touching features are already configurable (update.mode, telemetry.telemetryLevel, extensions.autoCheckUpdates, git.autofetch). Blocking extension network access is architecturally outside VS Code's domain — extensions intentionally run with full node access. Users needing full network isolation should use OS-level tools (firewall rules, containers, flatpak sandboxing) as the commenters already noted.

## Vision fit

- **Fit:** rejected
- **Reason:** A blanket network kill-switch conflicts with the value that 'the power lives in extensions' (which have full node API access by design) and the lightweight-editor guardrail; OS-level containment is the correct layer for this.
- **Evidence:** Value: 'The power lives in extensions' — extensions have access to the full node API intentionally; constraining that from within VS Code conflicts with the extension model.
