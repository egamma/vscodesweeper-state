# Issue #34503 — Implement privacy mode

[https://github.com/microsoft/vscode/issues/34503](https://github.com/microsoft/vscode/issues/34503)

## Summary

Existing settings can disable individual online services, but they do not provide the requested single, default-deny control over all outbound connections, including extensions. Keep this privacy-boundary request open for a maintainer scope decision; neither a covering implementation nor an open canonical was established.

## Change summary

Provide a configurable privacy mode that blocks outbound network connections from VS Code and its extensions.

## Best solution

Define whether VS Code should offer an enforceable application-wide network-denial mode, explicitly distinguishing it from disabling individual online features. Any supported guarantee must account for extension and child-process networking rather than implying that service settings constitute a firewall.

- **Requested guarantee and workaround:** https://github.com/microsoft/vscode/issues/34503 requests prevention of all outbound connections. The reporter's follow-up explicitly rejects controls that do not block by default and describes Linux group-based iptables filtering; this is stronger than disabling telemetry or automatic updates.
- **Maintainer discussion:** The supplied 2017-10-18 maintainer comment acknowledges that the listed settings only get partway there and that extensions can make independent Node API requests. The 2018-09-18 follow-up says core online functions became individually configurable, while explicitly retaining the extension-networking limitation; it does not establish that the requested global mode shipped.
- **Existing-capability check:** src/vs/platform/update/common/update.config.contribution.ts registers update.mode='none'. src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts registers extensions.autoUpdate='off' and extensions.autoCheckUpdates=false, addressing the historical extension-update-check gap. These are separate feature controls, not a universal network-denial flag.
- **Current documentation:** https://code.visualstudio.com/docs/supporting/faq documents @tag:usesOnlineServices as a way to find and individually disable online features. It also warns that extensions may collect their own data outside telemetry.telemetryLevel; the documented controls do not promise process-wide outbound blocking.
