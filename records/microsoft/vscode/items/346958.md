# Issue #346958 — Agent host: MCP Authenticate fails with "Authentication failed for resource" after a failed tool call, in sessions created by another AHP client

[https://github.com/microsoft/vscode/issues/346958](https://github.com/microsoft/vscode/issues/346958)

## Summary

Keep open: current source still accepts Copilot MCP tokens through pending callbacks only, but the precise callback-ending trigger remains unconfirmed. Authentication lifecycle handling has evolved since the report; the supplied steps and logs suffice to retest without requesting more information.

## Change summary

Allow MCP authentication to recover after an unanswered sign-in request ends in a session created by another AHP client.

## Best solution

Make Authenticate recover the targeted server without requiring another chat turn, while preserving session/server targeting and existing authorization checks. Separately decide whether unattended sessions should request existing grants from connected windows.
