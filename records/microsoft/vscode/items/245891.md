# Issue #245891 — Feature Request: Allow extensions to control Activity Bar title casing (prevent automatic uppercase)

[https://github.com/microsoft/vscode/issues/245891](https://github.com/microsoft/vscode/issues/245891)

## Summary

Keep this accepted Backlog feature request open: it received 27 upvotes, and current main still provides no extension-level control over view-title casing. The emerging Modern UI styling changes casing globally, but does not fulfill the requested API.

## Change summary

Allow an extension-contributed Activity Bar view container title to retain the casing declared in its package manifest.

## Best solution

Resolve casing consistently at the workbench level rather than allowing each extension to impose separate branding. The workbench-views maintainers should decide whether the Modern UI casing should become standard or whether a global accessibility/appearance setting is appropriate.

## Vision fit

- **Fit:** rejected
- **Reason:** Per-extension visual casing controls conflict with the preference for uniform UI and add configuration surface for a narrow branding concern.
- **Evidence:** Value and guardrail: “Simple, uniform UI and UI interactions”; UI consistency is preferred over per-feature customization.

## Evidence

- **current behavior:** src/vs/workbench/browser/parts/sidebar/media/sidebarpart.css still applies `text-transform: uppercase` to sidebar title labels on the default UI.
- **partial existing capability:** Commit https://github.com/microsoft/vscode/commit/d814614992d0504c70a4bc19fa72d626e9204498 changes workbench title surfaces to `text-transform: capitalize`, but only under the experimental `workbench.experimental.modernUI` setting, which defaults to false in src/vs/workbench/browser/workbench.contribution.ts.
- **remaining gap:** src/vs/workbench/contrib/styleOverrides/browser/styleOverrides.contribution.ts applies casing as one global Modern UI style group; it exposes no per-extension or per-view-container casing control.
- **design precedent:** https://github.com/microsoft/vscode/issues/191160 and https://github.com/microsoft/vscode/issues/47213 document the historical decision to uppercase view titles for UI consistency, but both concern the global convention rather than this newer extension API request.
