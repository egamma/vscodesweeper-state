## Summary

Verified duplicate: the root cause — restoring a checkpoint while a response streams does not cancel the running request, leaving the input box inert — is the same defect fixed in the canonical issue. Proposing a duplicate close.

## Change summary

Restoring a checkpoint while a chat response is being streamed leaves the send button non-functional until the stream is manually cancelled.

## Best solution
