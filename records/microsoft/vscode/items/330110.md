# Issue #330110 — No indication in Customizations window that `strictPluginOnlyCustomization` is preventing workspace plugins from being usable.

[https://github.com/microsoft/vscode/issues/330110](https://github.com/microsoft/vscode/issues/330110)

## Summary

Team-authored UX follow-up (self-filed while testing a related PR): the MCP Servers page in Agent Customizations greys out enable/disable options when `strictPluginOnlyCustomization` blocks workspace-defined servers, but gives no explanation, so this needs routing to the owning area rather than closing.

## Change summary

Add an explanatory note/tooltip in the Agent Customizations MCP Servers view when `strictPluginOnlyCustomization` disables right-click enable/disable options for workspace MCP servers.

## Best solution

In src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts (and the enablement-action helpers like getLocalMcpServerEnablementActions/getAgentHostMcpServerEnablementActions), surface a hint (tooltip or inline note) explaining that policy is restricting workspace-only customization when the collection is filtered by isCollectionAllowed/strictPluginOnly in mcpRegistry.ts.
