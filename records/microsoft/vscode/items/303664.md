# Issue #303664 — Can't commit when git config is `~/.config/git/config`

[https://github.com/microsoft/vscode/issues/303664](https://github.com/microsoft/vscode/issues/303664)

Keep open: the report provides a concrete configuration, failing Source Control action, and working comparison sufficient to retest. Current source delegates configuration discovery to Git, but inspection did not establish whether the reported environment-dependent failure persists or identify a fixing commit.

## Change summary

Source Control fails to read Git identity and ignore configuration from ~/.config/git even though command-line Git reads it successfully.

## Best solution

Establish why the built-in Git extension and shell Git discover different configuration on the reported Linux setup, then restore consistent identity and ignore handling without requiring a proxy ~/.gitconfig or enabling identity auto-detection.

## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/repository.ts`, `src/vs/platform/shell/node/shellEnv.ts`
- **Validation:** In an isolated Linux profile, configure user.name/user.email only in ~/.config/git/config with no ~/.gitconfig or local identity. Compare command-line and Source Control commits using the same Git executable and repository; both must succeed with the configured identity. Separately verify an untracked file matching ~/.config/git/ignore stays excluded without core.excludesFile, and repeat with an explicit core.excludesFile.
- **Behavior:**

  > Explicit Git identity in ~/.config/git/config should work for Source Control commits whenever the same repository and Git executable can commit from the shell. Users should not need a proxy ~/.gitconfig or local identity overrides. Git's configured global excludes and default XDG ignore file should also be honored. Validate these cases independently so an identity fix does not conceal a remaining ignore-discovery problem.
- **Trace:**

  > Git.spawn in extensions/git/src/git.ts merges process.env with extension and operation-specific variables and delegates configuration discovery to the selected Git executable. The commit path adds user.useConfigOnly=true, while handleCommitError queries user.name and user.email through that same subprocess path; commands.ts turns failed queries into the reported message. This confirms the relevant path but not the defect: the reporter's actual subprocess environment and Git executable have not been compared with the working shell. src/vs/platform/shell/node/shellEnv.ts is a relevant environment-resolution lead, not an established cause. Preserve the existing identity auto-detection policy and Git configuration precedence; do not treat git.requireGitUserConfig=false as resolution. https://github.com/microsoft/vscode/issues/142333 involved symlinks, while https://github.com/microsoft/vscode/issues/206824 involves Windows network homes; neither is a verified canonical for this Linux report.

The follow-up also reports failure to honor the default ~/.config/git/ignore.
