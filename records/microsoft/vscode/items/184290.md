# Issue #184290 — Inconsistency in "Replace" between text files and notebooks

[https://github.com/microsoft/vscode/issues/184290](https://github.com/microsoft/vscode/issues/184290)

## Summary

Keep open: current notebook Replace still explicitly focuses the replacement input, and the inspected keyboard handling does not provide text-editor parity. The maintainer endorsed alignment, and no verified canonical covers the full request.

## Change summary

Align notebook Find/Replace focus, keyboard navigation, dismissal, and replacement shortcuts with the text editor.

## Best solution

Bring the notebook Find/Replace widget into line with the text editor’s keyboard interaction conventions while preserving notebook-specific search scopes and output restrictions. Establish interactive reproduction and widget-level regression coverage for the remaining differences before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFind.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts`, `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindReplaceWidget.ts`, `src/vs/editor/contrib/find/browser/findWidget.ts`
- **Validation:** Compare a text editor and a notebook containing two editable cells with repeated text: invoke Replace with and without a selection, check initial focus, Tab and Shift+Tab navigation, Escape from both inputs, and keyboard invocation of Replace One and Replace All. Verify replacements across cells and preservation of notebook search restrictions. The planning session should identify executable widget/keybinding regression coverage; none was established during this review.
- **Behavior:**

  > Notebook Find/Replace should follow the text editor's established keyboard interaction conventions. Opening Replace should select the corresponding input under equivalent selection conditions, Tab navigation should move consistently between inputs, and Escape should dismiss the widget from either input. Users should be able to invoke single and bulk replacement through configurable keyboard commands. Notebook-specific search scopes and restrictions on replacing rendered output must remain intact.
- **Trace:**

  > StartFindReplaceAction's notebook implementation in src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFind.ts calls controller.replace(); NotebookFindWidget.replace() in notebookFindWidget.ts explicitly selects _replaceInput regardless of whether search text was seeded. notebookFindReplaceWidget.ts builds separate find and replace rows, attaches an Escape keyup handler to the find row, and invokes protected replacement methods through buttons; notebookFind.ts additionally registers notebook.hideFind. The text editor's findWidget.ts has explicit Tab-to-replacement-input behavior absent from the inspected notebook sources. The source establishes the focus discrepancy, but effective Escape dispatch, shortcut routing, and a suitable executable widget test harness still need investigation. Preserve notebook scope, rendered-output restrictions, and replacement semantics; unrelated match-position problems in https://github.com/microsoft/vscode/issues/154913 are not this work. The scrolling-command suggestion in the thread is an additional request, not evidence that Find/Replace parity is already covered.
