# Issue #246888 — "Disable All Installed Extensions" not working because of language file

[https://github.com/microsoft/vscode/issues/246888](https://github.com/microsoft/vscode/issues/246888)

## Summary

Keep open: the reporter confirmed the exact language-pack enablement error, and current main still has a downstream path that can add extension-pack members without rechecking whether their enablement can change. No older issue with the same observable symptom or attributable fix commit was found.

## Change summary

Disable All Installed Extensions aborts when an installed language pack is included in the bulk enablement operation.

## Best solution

The bulk-disable flow should exclude non-changeable extensions, including language packs, at every aggregation stage and continue disabling the remaining installed extensions rather than aborting the entire operation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsWorkbenchService.test.ts`
- **Validation:** Add an extensions workbench service regression test that bulk-disables changeable extensions when an extension-pack relationship reaches a language-pack extension, asserting that the language pack remains enabled, eligible extensions are disabled, and no error aborts the operation.
- **Behavior:**

  > With a language pack installed, running Disable All Installed Extensions must disable every installed extension whose enablement can be changed. Language packs and other protected extensions must remain enabled without causing an error or preventing eligible extensions from being disabled. The equivalent workspace-scoped command should follow the same rule.
- **Trace:**

  > The command registration in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts filters its initial list through `IWorkbenchExtensionEnablementService.canChangeEnablement`. ExtensionsWorkbenchService.promptAndSetEnablement in src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts then expands extension-pack relationships through getExtensionsRecursively, whose added members are not checked with that predicate before checkAndSetEnablement forwards the combined list. ExtensionEnablementService.setEnablement in src/vs/workbench/services/extensionManagement/browser/extensionEnablementService.ts validates the whole list first and throws for language packs, matching the reported message. Reproduce the exact French Language Pack relationship before changing behavior; preserve individual enablement restrictions and dependency prompts, and limit the scope to making bulk operations skip protected entries rather than weakening those restrictions.
