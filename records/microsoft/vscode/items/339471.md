# Issue #339471 — Allow configuring the default search mode of the Command Center

[https://github.com/microsoft/vscode/issues/339471](https://github.com/microsoft/vscode/issues/339471)

## Summary

Fresh, reasonable request with no existing setting covering it — traced the Command Center's quick-open action (`workbench.action.quickOpenWithModes` in src/vs/workbench/browser/actions/quickAccessActions.ts) and confirmed it always opens the classic 'Files' Anything-provider mode with no default-prefix setting; keeping open for triage as a feature request since there's no upvotes or maintainer signal yet.

## Change summary

Add a setting to choose which quick-open mode (Files / Workspace Symbols `#` / File Symbols `@`) the Command Center opens by default.

## Best solution

Add a configuration (e.g. a `workbench.commandCenter.defaultQuickOpenMode` or similar) consumed by the QuickAccessAction handler in quickAccessActions.ts to pass the user's preferred prefix into `quickInputService.quickAccess.show(...)` instead of always opening with no prefix.

Acceptance: a new setting exists, is read by the quick-open action, and changes the opened mode accordingly, with Files remaining the default for existing users.
- **Trace:**

  > `QuickAccessAction.run` (src/vs/workbench/browser/actions/quickAccessActions.ts, around line 168) calls `openClassicQuickAccess`, which always calls `quickInputService.quickAccess.show(undefined, { preserveValue: true, providerOptions })` — the first argument is the prefix, hardcoded to `undefined` (Files mode). There's a separate unified-quick-access path gated by `UNIFIED_AGENTS_BAR_SETTING` that should probably be left alone. The open question is the exact setting shape/ID and whether it should also affect the unified quick access flow — that's a product decision for a maintainer, not an implementation detail.
