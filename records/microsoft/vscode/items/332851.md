# Issue #332851 — Sticky scroll: clicking on sticky scroll element should scroll to it, not edit it

[https://github.com/microsoft/vscode/issues/332851](https://github.com/microsoft/vscode/issues/332851)

## Summary

The defect remains on current main: clicking a sticky chat request first invokes the tree's reveal behavior, but the request renderer then handles the same click as “Click to Edit.” The referenced test plan explicitly requires sticky-request clicks to navigate, so this should remain open for a bounded fix.

## Change summary

Clicking a sticky chat request should reveal its original transcript section without entering request-editing mode.

## Best solution

Keep ordinary chat requests editable while making sticky-row request content navigation-only, preserving the tree sticky-scroll reveal behavior and removing any misleading edit affordance from the sticky copy.
