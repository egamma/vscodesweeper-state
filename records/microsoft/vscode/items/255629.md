## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/63813 is OPEN, was created on 2018-11-26, and reports external debug terminals remaining open at the same 'Press any key to continue...' prompt. Its scope covers this newer C#/Konsole case.
- **Exact option request already discussed:** https://github.com/microsoft/vscode/issues/63813#issuecomment-442254769 explicitly requests disabling the pause on Linux. https://github.com/microsoft/vscode/issues/63813#issuecomment-752927136 proposes the same waitAfterExternExit option named in this report.
- **Current source still adds the pause:** src/vs/platform/externalTerminal/node/externalTerminalService.ts, LinuxExternalTerminalService.runInTerminal, constructs the non-Ghostty command as `${quote(args)}; echo; read -p "${LinuxExternalTerminalService.WAIT_MESSAGE}" -n1;`. Konsole follows this path; the wait is imposed by VS Code's shared launcher, not necessarily by application code or the C# extension.
- **Existing capability check:** src/vs/platform/externalTerminal/common/externalTerminal.ts exposes only linuxExec, osxExec, and windowsExec in IExternalTerminalSettings. src/vs/workbench/api/node/extHostDebugService.ts forwards external runInTerminal requests into this service. Selecting a different executable through terminal.external.linuxExec does not itself provide a supported pause opt-out; the canonical thread's wrapper workaround removes the injected read command.
- **Product and layering discussion preserved:** https://github.com/microsoft/vscode/issues/63813#issuecomment-726696727 explains why the pause was introduced to preserve program output. https://github.com/microsoft/vscode/issues/63813#issuecomment-750843776 discusses ownership of debugger-specific launch.json properties, and https://github.com/microsoft/vscode/issues/63813#issuecomment-754481485 proposes an opt-in runInTerminal hint. These are the same lifetime/configuration decisions this request requires.
