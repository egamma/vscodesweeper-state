# Issue #206056 — CSS for debug icons applies to TreeItem inline commands

[https://github.com/microsoft/vscode/issues/206056](https://github.com/microsoft/vscode/issues/206056)

## Summary

The visual defect remains in current main: debug action color rules use workbench-wide codicon selectors, so extension-contributed TreeItem commands inherit colors intended for debug controls.

## Change summary

Debug-specific codicons used by extension TreeItem inline commands incorrectly receive debug toolbar foreground colors.

## Best solution

Limit debug action color rules to VS Code-owned debug surfaces while preserving the configured colors for the debug toolbar, debug title actions, and other intentional debug controls.

- **Trace:**

  > In src/vs/workbench/contrib/debug/browser/debugColors.ts, the theming participant emits workbench-wide selectors for several debug action codicons; for example, the step-back rule includes `.monaco-workbench .codicon.codicon-debug-step-back`. Because extension TreeItem inline actions render inside `.monaco-workbench`, they match these rules despite being outside the debug UI. The color registrations themselves describe debug toolbar icons, and the same file already demonstrates narrower surface selectors for disconnect. Keep debug toolbar, debug title-action, command-center, and other intentional debug-control coloring intact; do not change codicon registration or generic TreeItem rendering. https://github.com/microsoft/vscode/issues/321773 is related color behavior but is newer and reports a different QuickPick `iconPath` symptom.
