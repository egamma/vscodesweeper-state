# Issue #328165 — Bug in Settings / workbench.colorCustomizations

[https://github.com/microsoft/vscode/issues/328165](https://github.com/microsoft/vscode/issues/328165)

## Summary

Traced to a real schema-construction bug in VS Code's own theme configuration code, not an extension or upstream issue: theme-scoped `workbench.colorCustomizations` entries use a JSON Schema pattern (`$ref` combined with a sibling `additionalProperties: false`) that `vscode-json-languageservice` does not merge, so the referenced color properties are dropped and every property is reported as disallowed while autocomplete finds nothing — matching every symptom in the report and comments.

## Change summary

Theme-scoped color customizations (e.g. `"workbench.colorCustomizations": { "[Theme Name]": { ... } }`) show 'Property X is not allowed' for every valid color key and get no IntelliSense, even though the colors are still applied correctly.

## Best solution

In src/vs/workbench/services/themes/common/themeConfiguration.ts, change the per-theme `workbenchColors` schema object (line 243) from `{ $ref: workbenchColorsSchemaId, additionalProperties: false }` to `{ allOf: [{ $ref: workbenchColorsSchemaId }], additionalProperties: false }`, mirroring the already-working top-level `colorCustomizationsSchema` (`allOf: [{ $ref: workbenchColorsSchemaId }]`, no sibling keywords) — this restores validation/completion for theme-scoped keys without changing the working non-scoped case.
