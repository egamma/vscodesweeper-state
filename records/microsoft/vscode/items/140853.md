# Issue #140853 — File nesting: collapsing with nested file selected selects parent file's next sibling

[https://github.com/microsoft/vscode/issues/140853](https://github.com/microsoft/vscode/issues/140853)

## Summary

The general tree-selection defect remains actionable on current main: collapsing a node can desynchronize the visible list selection from the tree's element-based selection state. The closed, unmerged fix attempt confirms the diagnosis but does not resolve the issue.

## Change summary

Collapsing a tree node while one of its children is selected incorrectly highlights the following sibling and can show two highlighted rows after re-expansion.

## Best solution

Make collapse handling preserve selection by element rather than allowing removed child-row indexes to become associated with adjacent visible rows, consistently across Explorer, SCM, and other consumers of the base tree widget.
