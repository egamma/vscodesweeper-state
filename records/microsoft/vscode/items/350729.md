# Issue #350729 — P2 copilot-runtime is started twice at every window startup because the copilotConnectors root config arrives after CopilotClient started

[https://github.com/microsoft/vscode/issues/350729](https://github.com/microsoft/vscode/issues/350729)

## Summary

Keep open: current source still permits migration to start CopilotClient before initial configuration arrives, causing a discarded startup or restart. The related open PR explicitly leaves this double-start issue unchanged.

## Change summary

Avoid starting copilot-runtime twice when the initial Copilot Connectors configuration arrives after runtime startup begins.

## Best solution

Ensure initial startup-effective configuration is available before migration starts the runtime, while preserving legitimate later configuration restarts and compatibility with other AHP clients. Review the related prewarming PR independently; it does not resolve this startup-ordering defect.
