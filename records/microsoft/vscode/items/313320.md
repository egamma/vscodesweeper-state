# Issue #313320 — Show customization token usage in context window widget

[https://github.com/microsoft/vscode/issues/313320](https://github.com/microsoft/vscode/issues/313320)

## Summary

Keep open: current source provides partial customization attribution for Agent Host sessions, but the local Copilot breakdown does not identify customization usage separately. This team-authored Backlog request has no verified, issue-referencing fix, and the related broader tracking issue is newer rather than an eligible duplicate canonical.

## Change summary

Show the percentage of the context window consumed by customizations in the context-usage widget.

## Best solution

Provide an understandable customization-cost breakdown in the existing context-usage popover, using available attribution without double-counting or presenting unknown costs as zero. Agree on which customization types the percentage covers and ensure the intended chat surfaces supply that attribution.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageDetails.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts`, `extensions/copilot/src/platform/tokenizer/node/promptTokenDetails.ts`
- **Validation:** After agreeing on scope, exercise local Copilot and Agent Host sessions with known customization attribution and open the context-usage popover. Verify that displayed customization percentages use the context-window denominator, do not double-count parent and child attribution, update with usage, and distinguish unavailable attribution from zero cost.
- **Behavior:**

  > Users can see how much of their context window is consumed by customizations in the existing usage popover. Percentages have a clear denominator and explain which customization types are included. Existing total usage and non-customization breakdowns remain available. Missing attribution must not appear as a measured zero.
- **Trace:**

  > ChatContextUsageWidget forwards promptTokenDetails into ChatContextUsageDetails.renderTokenDetails, which converts prompt-relative percentages into context-window percentages. The Agent Host adapter already consumes contextAttribution and emits aggregate rows for skills, subagents, MCP servers, and plugins, while grouping them under User Context. The local Copilot tokenizer exposes only generic categories and maps the instruction tag to Messages. The remaining uncertainty is the intended customization accounting scope and whether coverage must span both paths; it is not whether the renderer can display percentages. Preserve total usage, response-reserve behavior, and existing attribution accounting. Related planning is at https://github.com/microsoft/vscode-internalbacklog/issues/9986; file-level estimates are separately requested at https://github.com/microsoft/vscode/issues/313321.
- **Open decisions:**
  - Which costs belong in the customization percentage: custom instructions and agent prompts only, or also skills, plugins, and MCP tool schemas?
  - Should the widget show one combined customization percentage, separate customization-type percentages, or both?
  - Must the first delivery cover both local Copilot and Agent Host sessions, or may coverage initially be limited to sessions with structured attribution?
