# Issue #336767 — Copilot Chat agent mode: no identical-tool-call repetition detection; "Continue to iterate?" auto-extends budget so loops run 12-18+ rounds unattended

[https://github.com/microsoft/vscode/issues/336767](https://github.com/microsoft/vscode/issues/336767)

## Summary

Current main has only an aggregate tool-call limit and no consecutive identical-call guard, so the reported safety gap remains. The request should stay open and route to the chat agent/tool owners for a product decision on repetition semantics.

## Change summary

Add a harness-level circuit breaker that detects repeated identical tool calls, prevents unbounded re-execution, and warns the model and user.

## Best solution

Define a model-independent repetition policy in the Copilot tool-calling loop that stops repeated calls before further execution, returns an actionable result to the model, and visibly tells the user why execution stopped. The normal request-budget continuation path should not bypass that stop condition.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/toolCallingLoop.ts`, `extensions/copilot/src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts`
- **Validation:** Add a focused Vitest case that emits the same tool name and arguments across consecutive rounds, proves execution stops at the selected threshold with a visible/model-facing explanation, and verifies that different arguments and ordinary repeated reads below the threshold continue; run it with `cd extensions/copilot && npm run test:unit -- src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts`.
- **Behavior:**

  > When an agent emits the same tool call with equivalent arguments repeatedly without meaningful progress, VS Code stops executing further copies at a defined threshold. The model receives an actionable result explaining that repetition was blocked, and the user sees a clear warning. Continuing the general request budget must not silently clear this repetition stop. Legitimate repeated calls with changed arguments, and calls below the threshold, continue normally.
- **Trace:**

  > The central loop is ToolCallingLoop._runLoop in extensions/copilot/src/extension/intents/node/toolCallingLoop.ts. Each `runOne` result is appended to `toolCallRounds`, and each IToolCall already contains `name` and serialized `arguments`, but `_runLoop` only checks the aggregate `toolCallLimit`. Autopilot can increase that limit to 200, and hitToolCallLimit exposes a further continuation request; neither path inspects repetition. Existing tests in extensions/copilot/src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts exercise loop-limit behavior and provide the nearest harness. Keep endpoint-specific behavior, normal tool-result handling, non-identical retries, and the general request-budget mechanism outside the change except where the repetition stop must remain authoritative. https://github.com/microsoft/vscode/issues/335214 and https://github.com/microsoft/vscode/issues/334421 are related examples but do not fully own this broader behavior.
- **Open decisions:**
  - After how many consecutive equivalent calls should execution stop, and should the threshold differ for potentially mutating tools versus read-only tools?
  - What constitutes equivalent arguments for the public behavior: byte-identical serialized arguments or structurally equivalent JSON with insignificant ordering and formatting differences ignored?
  - After the circuit breaker fires, may an explicit user action resume the same call sequence, or must progress require a changed tool call or a new user message?
