# Issue #250806 — Icons misalignment

[https://github.com/microsoft/vscode/issues/250806](https://github.com/microsoft/vscode/issues/250806)

## Summary

Keep open for the remaining cross-surface decoration alignment work. Current source reserves a consistent width for text badges in SCM resource rows, but not in Explorer, and the discussion leaves the effect on editor-tab widths unresolved.

## Change summary

Align letter-based file decorations such as M and U with lock decorations in SCM and Explorer without unnecessarily widening other resource labels.

## Best solution

Make equivalent file-decoration badges align consistently in SCM and Explorer through a coherent resource-label layout contract. Settle whether that contract also reserves space in editor tabs, preserving compact tab sizing unless an intentional change is agreed.

- **Trace:**

  > DecorationRule in src/vs/workbench/services/decorations/browser/decorationsService.ts generates text and icon pseudo-element rules, and DecorationsService.asDecoration identifies text badges through isTextBadge. ResourceLabelWidget in src/vs/workbench/browser/labels.ts passes that classification to the shared icon label. The generic ::after rule in src/vs/base/browser/ui/iconLabel/iconlabel.css has no reserved width, while scm.css supplies a centered minimum-width rule scoped to SCM resource rows; Explorer has no equivalent rule. Editor tabs reuse this label machinery and override badge margins in editortabscontrol.css. The uncertainty is the user-visible scope of width reservation, explicitly raised in https://github.com/microsoft/vscode/issues/250806#issuecomment-2948895704. Preserve badge content, tooltips, colors, icon selection, and bubbling semantics; this is alignment work, not a redesign of decoration providers.
- **Open decisions:**
  - Should consistent badge-width reservation apply only to list/tree resource rows, preserving compact editor tabs and breadcrumbs, or should tabs and breadcrumbs adopt the same reserved width?
