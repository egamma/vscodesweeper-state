# Issue #331062 — Custom Endpoint: switching an existing Chat Completions conversation to Responses API produces invalid input payload

[https://github.com/microsoft/vscode/issues/331062](https://github.com/microsoft/vscode/issues/331062)

## Summary

Real, source-confirmed bug: when replaying prior Chat Completions assistant turns into a Responses API `input`, VS Code omits the required `annotations` field on `output_text` content parts — exactly matching the reporter's `input[N].content[0].annotations` error from Azure. Scoped to Custom Endpoint/BYOK Responses conversion, so keeping open and routing to the area rather than closing.

## Change summary

Switching an in-progress Custom Endpoint conversation from a Chat Completions model to a Responses API model fails because the historical assistant turns are converted into an invalid Responses `input` payload (missing `annotations`).

## Best solution

Fix `rawContentToResponsesAssistantContent` and the local `ResponseInputAssistantTextContentPart` interface in extensions/copilot/src/platform/endpoint/node/responsesApi.ts to include `annotations: []` on constructed `output_text` parts, matching what the Responses API (and the file's own SSE-parsed objects) expect.
