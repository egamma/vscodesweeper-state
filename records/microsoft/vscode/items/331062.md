# Issue #331062 — Custom Endpoint: switching an existing Chat Completions conversation to Responses API produces invalid input payload

[https://github.com/microsoft/vscode/issues/331062](https://github.com/microsoft/vscode/issues/331062)

## Summary

Traced conclusively in source: when converting prior Chat Completions history into Responses API `input` for a BYOK custom endpoint, VS Code builds assistant output_text parts without the `annotations` field that the Responses API schema requires, exactly matching the reporter's `input[3].content[0].annotations` error.

## Change summary

Switching a Custom Endpoint conversation from a Chat Completions model to a Responses API model mid-conversation sends a malformed `input` payload missing required `annotations`, causing Azure to reject the request.

## Best solution

In extensions/copilot/src/platform/endpoint/node/responsesApi.ts, extend `ResponseInputAssistantTextContentPart` / `rawContentToResponsesAssistantContent` to include an `annotations: []` field (matching what the Responses API expects for output_text items) when synthesizing historical assistant messages into Responses API input.
