# Issue #288177 — Failed to copy 1 file to worktree

[https://github.com/microsoft/vscode/issues/288177](https://github.com/microsoft/vscode/issues/288177)

## Summary

Keep open: the worktree-copy warning still reports only a failure count, leaving the user to hunt through Git output for the affected file. The matching newer report cannot replace this older, team-authored item under the re-review duplicate rules.

## Change summary

Make worktree-copy failure notifications identify the affected files and provide useful diagnostic context.

## Best solution

Make the built-in Git extension's worktree-copy warning expose the affected paths or directly accessible failure details, while retaining best-effort copying. Treat the ASAR copy error as context rather than assuming that fixing that particular copy failure resolves the notification problem.

## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/commands.ts`, `extensions/git/src/test/worktreeInclude.test.ts`
- **Validation:** The plan should establish a notification-level regression check that forces one and multiple included-path copy failures and verifies that users can identify the affected paths from the warning or its directly accessible details. Also verify that successful copies continue and that a fully successful operation produces no failure warning.
- **Behavior:**

  > When copying included files or folders into a new worktree partially fails, the user should be able to identify the affected paths without searching an unrelated stream of Git output. The diagnostic should remain useful for both one failure and multiple failures. Successful copies should continue, and a fully successful copy should not produce a failure warning. The particular ASAR copy failure is not itself the scope of this improvement.
- **Trace:**

  > Repository._copyWorktreeIncludeFiles in extensions/git/src/repository.ts constructs source and target paths for each included entry and performs concurrent copies through a Limiter. It then filters Promise.allSettled results to count rejected operations, displays a count-only warning, and logs rejection reasons separately. Commands.showOutput in extensions/git/src/commands.ts already exposes the Git output channel, but the warning has no action connecting to it. The inspected extensions/git/src/test/worktreeInclude.test.ts covers path selection rather than notification behavior, so the plan must establish how the user-facing diagnostic will be exercised. Preserve include-pattern semantics, existing-target handling, copy concurrency, and best-effort completion; do not broaden this into fixing every filesystem copy error. https://github.com/microsoft/vscode/issues/314981 independently requests the same diagnostic improvement but is newer than this report.
