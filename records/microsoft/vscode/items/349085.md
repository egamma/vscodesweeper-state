# Issue #349085 — Sessions: GitHub PR models poll in lockstep and overflow the request queue ("Request capacity exceeded")

[https://github.com/microsoft/vscode/issues/349085](https://github.com/microsoft/vscode/issues/349085)

## Summary

Recurring PR polling still uses synchronized intervals that can overflow background request capacity and leave state stale. Keep this team-authored issue open while its linked implementation PR is reviewed.

## Change summary

Spread recurring GitHub PR metadata, review-thread, and CI polling across sessions to prevent synchronized request-queue overflow.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/349086 to stagger initial and recurring polls while preserving interactive request capacity. Keep startup and account-change refresh bursts outside this fix, as the report explicitly specifies.
