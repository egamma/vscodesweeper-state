# Issue #290438 — Advanced setting for auth provider does not show in Settings UI after extension unification

[https://github.com/microsoft/vscode/issues/290438](https://github.com/microsoft/vscode/issues/290438)

## Summary

Keep open: current main still consumes the GitHub Enterprise auth-provider configuration but does not contribute it to the Settings UI. The discussion has not settled whether unified authentication should expose this setting or replace it with another discoverable provider-selection flow.

## Change summary

Extension unification removed the discoverable Settings UI entry for selecting GitHub Enterprise as Copilot's authentication provider, while the hidden configuration remains functional.

## Best solution

Provide a supported, discoverable way to select GitHub Enterprise authentication under extension unification, and align the public authentication documentation with that experience. A maintainer should first decide whether that remains an advanced setting or belongs in the unified account-selection UI.

Acceptance should cover both GitHub.com and GitHub Enterprise selection under the unified extension.
- **Trace:**

  > Current main defines `ConfigKey.Shared.AuthProvider` in `extensions/copilot/src/platform/configuration/common/configurationService.ts`, and `configurationServiceImpl.ts` reads it as a hidden advanced value. The uncertainty begins at the public UX boundary: the thread does not establish whether the advanced setting should return or whether unified account selection should supersede it. Preserve existing configured-value compatibility and do not broaden the work into unrelated GHE service failures.
- **Open decisions:**
