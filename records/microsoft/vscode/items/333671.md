# Issue #333671 — Rename command behavior for nested chats

[https://github.com/microsoft/vscode/issues/333671](https://github.com/microsoft/vscode/issues/333671)

## Summary

Team-authored (COLLABORATOR) issue carrying a real release milestone (1.138.0), so per policy it stays open regardless of other evidence — but the underlying report also checks out in source: nested-chat rename actions in the Agents Window inconsistently expose/label the F2 keybinding.

## Change summary

In the Agents Window, the nested-chat tab menu's Rename command lacks an ellipsis and no F2 accelerator label, while the '...' menu's Rename... command also lacks a shown F2 binding, and F2 currently renames the primary session instead of the focused nested chat.

## Best solution

In src/vs/sessions/contrib/sessions/browser/sessionsActions.ts, reconcile the RenameChatAction (RENAME_CHAT_COMMAND_ID, F2-bound) with the tab-menu and list-item Rename... commands (RenameSessionListChatAction) so the same F2 keybinding is shown/scoped consistently across all three rename entry points for a focused nested chat, and title casing/ellipsis matches across menus.
