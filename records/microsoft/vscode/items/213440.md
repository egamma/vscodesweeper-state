# Issue #213440 — [Bug] Emoji/Full-width chars are not measured against font

[https://github.com/microsoft/vscode/issues/213440](https://github.com/microsoft/vscode/issues/213440)

## Summary

Still present on main: cursor up/down movement uses hardcoded Unicode width properties (isFullWidthCharacter/isEmojiImprecise → 2 columns) rather than actual font-measured widths, causing column jumps when the font renders these characters at a different width than assumed.

## Change summary

Cursor jumps columns when moving up/down between lines containing emoji or full-width characters whose actual rendered width differs from the hardcoded Unicode width assumption.

## Best solution

The vertical cursor movement path in `cursorMoveOperations.ts` delegates to `CursorColumns.visibleColumnFromColumn` which uses `isFullWidthCharacter`/`isEmojiImprecise` heuristics (hardcoded to 2). To fix, the visual column calculation during vertical movement should consult the actual measured character widths from `FontInfo`/`charWidthReader` rather than relying solely on Unicode category. This is a non-trivial change since the model-level cursor logic currently has no access to font metrics.
