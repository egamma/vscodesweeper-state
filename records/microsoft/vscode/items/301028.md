# Issue #301028 — SCM repository visibility is not persisted across restarts

[https://github.com/microsoft/vscode/issues/301028](https://github.com/microsoft/vscode/issues/301028)

## Summary

The visibility-restoration defect remains in current main. Keep this open while the existing fixing PR is reviewed, preserving the requirement that newly discovered repositories must not reveal previously deselected ones.

## Change summary

Preserve SCM repository visibility across restarts when hidden providers or genuinely new repositories register.

## Best solution

Review https://github.com/microsoft/vscode/pull/301029 against both reported triggers: hidden providers must not disturb restoration, and new repositories should become visible without changing existing selections. Coordinate with https://github.com/microsoft/vscode/pull/334845, whose select-all approach explicitly does not preserve the latter requirement.

## Evidence

- **Current-source defect:** In src/vs/workbench/contrib/scm/browser/scmViewService.ts, repositories excludes providers with isHidden === true, and onWillSaveState builds the persisted all array from that filtered getter. onDidAddRepository nevertheless consults previousState for hidden providers without excluding them, so their absent storage keys enter the index === -1 branch.
- **Exact failing flow:** SCMViewService.onDidAddRepository selects every internal repository and resets didSelectRepository when index === -1. With previousState all=[A,B], visible=[0], registering A, then deselected B, then a new repository or isHidden provider during loading makes B selected again. The branch retains previousState, allowing subsequent registrations to clear selections again. This was traced from current source without executing code.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/301029 is verified OPEN with mergedAt=null and explicitly states Fixes #301028. Its body addresses both hidden providers and new repositories while preserving existing visibility. It is an unmerged implementation candidate, not evidence of a completed fix.
- **Related discovery-order report:** https://github.com/microsoft/vscode/issues/334842 is verified OPEN and was created on 2026-09-07, after this issue. It reports repositories becoming invisible after a new repository registers, rather than deselected repositories becoming visible. Its open PR https://github.com/microsoft/vscode/pull/334845 explicitly acknowledges that its proposed select-all behavior reveals intentionally hidden repositories when a new repository appears, so it does not resolve this issue's full requirement.
- **Canonical search:** Searches for SCM repository visibility across restarts and worktree visibility identified https://github.com/microsoft/vscode/issues/271554 and https://github.com/microsoft/vscode/issues/326345. The former is older and open, but its linked open fixes https://github.com/microsoft/vscode/pull/307887 and https://github.com/microsoft/vscode/pull/320526 address restoration bypassed after the five-second loading debounce, not hidden-provider/new-repository corruption during loading. The latter is newer and concerns expanded/collapsed tree state in scm.viewState2, not visibility selection. Neither was established as a canonical owning this report's full work.
