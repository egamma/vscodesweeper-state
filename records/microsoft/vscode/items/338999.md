# Issue #338999 — Copilot coding agent cannot run commands in an already open terminal session and always creates a new terminal context

[https://github.com/microsoft/vscode/issues/338999](https://github.com/microsoft/vscode/issues/338999)

## Summary

Confirmed in source: the run_in_terminal tool always creates and reuses its own dedicated terminal per chat session, never attaching to a terminal the user already has open — this is intentional design, but no existing setting lets a user opt into reusing a specific pre-existing terminal, so the request is real and unmet.

## Change summary

Allow the Copilot agent's run_in_terminal tool to run commands in an already-open user terminal instead of always creating its own dedicated terminal.

## Best solution

Keep this open as a feature request for the terminal chat-agent-tools area; the design tradeoff (reliability of shell-integration/output tracking vs. racing with a user actively typing in the same terminal) needs a maintainer decision before any implementation — e.g. a 'reuse-only' opt-in mode with a confirmation/warning as the reporter suggests.

## Evidence

- **send_to_terminal scope:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/sendToTerminalTool.ts only accepts an `id` 'returned by run_in_terminal', i.e. an agent-created terminal, not any user terminal.
