# Issue #338999 — Copilot coding agent cannot run commands in an already open terminal session and always creates a new terminal context

[https://github.com/microsoft/vscode/issues/338999](https://github.com/microsoft/vscode/issues/338999)

## Summary

The requested capability remains missing: Copilot reuses its own session-associated terminals but cannot select an arbitrary user-opened terminal or enforce reuse-only execution. Route this to the terminal agent tools area as a feature request; the verified related reports do not cover the same full requirement.

## Change summary

Allow Copilot to target a selected existing terminal and enforce continuity without silently creating another execution context.

## Best solution

Have the terminal agent tools owner evaluate explicit attachment to a user-selected terminal and a strict reuse-only execution contract, including what happens when that terminal is busy or unavailable. Preserve existing agent-owned terminal reuse and background execution defaults outside that opt-in workflow.

- **Existing capability does not cover the request:** The runInTerminal tool input schema in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts exposes command, execution mode, timeout, and related execution metadata, but no existing-terminal selector.
