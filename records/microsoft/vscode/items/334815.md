# Issue #334815 — Claude harness: files edited externally during a session are attributed to the session's edited-files list

[https://github.com/microsoft/vscode/issues/334815](https://github.com/microsoft/vscode/issues/334815)

## Summary

Traced on main: the per-turn 'edited files' diff prefers a git-tree checkpoint diff over the tool-attributed tracker, and checkpoints are whole-working-directory git snapshots taken at turn start/end — so any file changed in that window by any actor (manual edit, another session, external process) is included, exactly as reported.

## Change summary

During a running Claude harness turn, files edited externally (by the user or another session) get listed as edited by that session, with diff/undo affordances applied to changes the session never made.

## Best solution

Reconcile the checkpoint-based turn diff (agentHostChangesetService.ts:_computeSingleFolderTurnDiffs, preferred for its terminal-tool visibility) with the tool-attributed FileEditTracker/aggregator (fileEditTracker.ts, sessionDiffAggregator.ts) so only paths the session's own tools (or terminal commands it ran) touched are reported — e.g. intersect the checkpoint diff's file set against tracked tool activity, or otherwise exclude paths with no corresponding tracked edit — since today's fallback-only relationship lets any concurrent external write ride along.

## Evidence

- **checkpoint diff preferred:** src/vs/platform/agentHost/node/agentHostChangesetService.ts:673-700 (_computeSingleFolderTurnDiffs) diffs the turn-start/turn-end checkpoint git refs first and only falls back to 'tracked file edits' when no checkpoint pair exists, explicitly noting the tracked aggregator 'cannot see terminal-tool edits'.
- **checkpoints are whole-tree, time-window snapshots:** src/vs/platform/agentHost/node/agentHostCheckpointService.ts captures a git tree of the working directory at turn boundaries (ITurnStartCheckpoint.trees), not a per-tool before/after snapshot, so anything else that changes the tree in that interval is included in the diff.
- **contrast: tool-attributed path is scoped correctly:** src/vs/platform/agentHost/node/shared/fileEditTracker.ts and src/vs/platform/agentHost/node/sessionDiffAggregator.ts only record/aggregate edits keyed to specific tool_use invocations (see node/claude/claudeFileEditObserver.ts observeAssistant/observeUser), so this narrower mechanism would not exhibit the reported bug — the checkpoint path is the one that does.
