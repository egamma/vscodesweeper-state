# Issue #334815 — Claude harness: files edited externally during a session are attributed to the session's edited-files list

[https://github.com/microsoft/vscode/issues/334815](https://github.com/microsoft/vscode/issues/334815)

## Summary

Traced the reported mechanism in source: for Claude harness sessions, the 'session'/'uncommitted' changeset (which drives the session's changed/edited-files summary and the revert affordance) is computed via `git status --porcelain` over the whole working directory in `agentHostChangesetService.ts`/`agentHostGitService.ts`, not from the agent's own tool-call edits — so any concurrent manual or external edit in a non-isolated (shared-workspace) session is indistinguishable from the agent's own changes. This matches the reporter's own theory exactly and is a real, if narrow, attribution gap; routing to the chat/agent-host area for a maintainer decision on whether to filter the git-diff view against known tool-attributed edits (there's a separate, correctly-scoped mechanism for that in `AgentHostSnapshotController`/`ClaudeFileEditObserver`) or accept it as an inherent trade-off of unisolated sessions.

## Change summary

During a Claude harness session, files edited manually or by other concurrent processes while the session is running get folded into that session's changed/edited-files list and revert/undo affordances, as if the agent itself had made those changes.

## Best solution

Either scope the session/uncommitted changeset display to paths the agent's own tool calls actually touched (cross-referencing the tool-call-attributed edit tracking already present in `AgentHostSnapshotController`/`ClaudeFileEditObserver`), or, if that's judged infeasible for the git-diff-based changeset model, document/as-designed this as a known limitation of unisolated (shared-workspace) sessions and steer users toward worktree isolation where the working tree is exclusive to the session.

## Evidence

- **changeset catalogue intent:** src/vs/platform/agentHost/common/changesetUri.ts documents 'session' changeset as 'Show all changes made in this session' and 'uncommitted' as 'Show uncommitted changes in this session' — both git-diff-based summaries feeding the Sessions UI (agentSessionsModel.ts, sessionSummaryHover.ts, agentHostSessionInputPills.ts).
- **contrast with correct per-tool-call tracking:** src/vs/platform/agentHost/node/claude/claudeFileEditObserver.ts and src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSnapshotController.ts already attribute edits strictly per tool_use_id/tool call, showing the codebase has a correctly-scoped mechanism that the git-diff-based changeset view does not use.
