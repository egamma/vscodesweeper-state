# Issue #334815 — Claude harness: files edited externally during a session are attributed to the session's edited-files list

[https://github.com/microsoft/vscode/issues/334815](https://github.com/microsoft/vscode/issues/334815)

## Summary

Traced in source: the Claude harness's file-edit tracker snapshots whole-file content at tool-call start/end and diffs those two snapshots, with no check that the change actually came from the tool's own write — so any external edit landing in that window is folded into the agent's reported diff, matching the report exactly.

## Change summary

Files edited by someone/something other than the agent's own tool calls during a Claude harness session get attributed to that session's edited-files list.

## Best solution

In FileEditTracker (src/vs/platform/agentHost/node/shared/fileEditTracker.ts), the before/after snapshot pair taken in trackEditStart/completeEdit has no defense against a write from outside the tool call landing in the same window; a maintainer needs to decide the detection strategy (e.g. verifying the diff against the tool's own edit instructions, or invalidating attribution when the file changes unexpectedly) before this can be fixed safely.

## Evidence

- **after-snapshot / race:** src/vs/platform/agentHost/node/shared/fileEditTracker.ts:84-100 completeEdit() re-reads the file after the tool call and diffs unconditionally in takeCompletedEdit(); claudeFileEditObserver.ts's own doc comment (lines 34-40) explicitly acknowledges this is a best-effort race ('the SDK proceeds to run the tool concurrently... gives enough microtask headroom in practice') with no fallback if that race is lost.
- **no external-edit guard:** No mtime check, file lock, or content-verification-against-tool-input exists anywhere in fileEditTracker.ts or claudeFileEditObserver.ts to reject a snapshot pair that includes a non-agent write.
