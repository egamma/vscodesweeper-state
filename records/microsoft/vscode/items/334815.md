# Issue #334815 — Claude harness: files edited externally during a session are attributed to the session's edited-files list

[https://github.com/microsoft/vscode/issues/334815](https://github.com/microsoft/vscode/issues/334815)

## Summary

Traced the Claude harness's edit-tracking path on main and it doesn't match the reported mechanism, so it's unclear which surface the reporter is actually seeing — asking for the session's isolation mode (worktree vs. workspace) and a fresh repro before this can be judged.

## Change summary

During a running Claude harness session, files edited by other processes/agents in parallel are shown in the session's own edited-files list, with diff/undo affordances as if the agent had changed them.

## Best solution

Confirm with the reporter whether the session used worktree or workspace isolation: for workspace isolation the session changeset is built from `file_edits` rows scoped to the agent's own tool calls (looks correctly attributed on main); for worktree isolation the 'branch changeset' intentionally diffs the whole branch/worktree, so any file edited inside that worktree directory legitimately shows up (as-designed, not a defect). If reproducible under workspace isolation specifically, that's a real attribution bug worth a closer trace.

## Evidence

- **fileEditTracker.ts:** src/vs/platform/agentHost/node/shared/fileEditTracker.ts's trackEditStart/completeEdit/takeCompletedEdit are all keyed by explicit filePath handed in by the observer per tool call, and only those paths are persisted via db.storeFileEdit into the file_edits table that feeds the session changeset (sessionDiffAggregator.ts).
- **agentHostChangesetSummary.ts:** getSummaryChangesetKind() picks StaticChangesetKind.Branch (a git diff of the whole worktree/branch) when session isolation is 'worktree', vs. Session (tool-tracked file_edits) otherwise — a worktree session's 'changes' view is, by design, everything changed on that branch, not just the agent's own tool edits.
