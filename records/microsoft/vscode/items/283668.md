# Issue #283668 — Issue reporter loses context of internal user

[https://github.com/microsoft/vscode/issues/283668](https://github.com/microsoft/vscode/issues/283668)

## Summary

Still reproducible on main: the issue reporter's extension-switching flow calls `clearExtensionData()` which zeroes out `privateUri`, and when switching back to Copilot Chat the `sendReporterMenu` response may not restore it, causing internal users to lose their internal filing context and file issues to the public repo instead.

## Change summary

When an internal user switches extensions in the issue reporter dropdown and switches back, the internal filing context (privateUri) is lost, causing issues to be filed publicly instead of internally.

## Best solution

Preserve the original `privateUri` and `githubAccessToken` across extension switches in the issue reporter. The `clearExtensionData()` method in `baseIssueReporterService.ts` should either not clear `privateUri`/`githubAccessToken` (since they are user-level, not extension-level properties), or the original values should be stashed and restored when switching back. The fix is small and localized to `baseIssueReporterService.ts`.
