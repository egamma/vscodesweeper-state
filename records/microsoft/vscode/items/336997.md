# Issue #336997 — Show session location in the Agents sidebar

[https://github.com/microsoft/vscode/issues/336997](https://github.com/microsoft/vscode/issues/336997)

## Summary

The location ambiguity remains on current main: active session rows intentionally replace workspace details with status text. This team-authored Backlog polish item should stay open while the indicator’s user-facing semantics are designed.

## Change summary

Keep each Agents sidebar session's workspace visible and add an at-a-glance indication of whether it runs locally, remotely, or in the cloud.

## Best solution

Give every non-quick-chat session row persistent workspace and execution-location context across completed, working, and input-needed states, with equivalent accessible labeling. The design should distinguish separate remote hosts when a coarse local/remote/cloud category would still leave rows ambiguous.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/browser/media/sessionsList.css`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts`
- **Validation:** Add focused SessionsList browser tests covering completed, InProgress, and NeedsInput local/remote/cloud rows, asserting persistent workspace and location presentation plus equivalent accessible names.
- **Behavior:**

  > Each non-quick-chat row in the Agents sidebar identifies both its workspace and execution location at a glance. Workspace and location remain available while the session is working or waiting for input rather than being replaced by status text. Local, remote, and cloud sessions are distinguishable, and separate remote hosts remain distinguishable when necessary. Accessible names communicate the same workspace, location, and status information.
- **Trace:**

  > SessionItemRenderer in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts rebuilds `.session-details-row` reactively. It sets `hideDetails` for InProgress and NeedsInput, suppresses the workspace badge in that state, and omits the type icon specifically for InProgress; SessionsAccessibilityProvider applies the same status-based workspace omission. Existing tests in src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts encode that suppression. Provider-neutral inputs already include ISessionWorkspace.group/typeIcon and ISessionsProvider.label/icon, but the record does not settle which should define the visible location identity. Preserve quick-chat behavior, status messaging, grouping semantics, and existing diff/timestamp behavior outside the requested location presentation.
- **Open decisions:**
  - Should the persistent location indicator show only the category (Local, Remote, or Cloud), or identify the provider or machine so sessions on different remote hosts can be distinguished?
  - In compact mode, must location remain continuously visible, or may it appear only on hover and keyboard focus as workspace context does today?
