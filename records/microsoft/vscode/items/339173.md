# Issue #339173 — Terminal shortcuts should take priority over VS Code commands when alternate buffer is active

[https://github.com/microsoft/vscode/issues/339173](https://github.com/microsoft/vscode/issues/339173)

## Summary

Re-reviewed and stays open: traced the code and confirmed a real gap — the keybinding skip-shell logic in terminalInstance.ts never consults the existing terminalAltBufferActive context key, so TUI shortcuts aren't automatically passed through on the alt buffer — but whether this should be automatic-by-default or an opt-in setting is an open design call, so this is plan-tier, not implement.

## Change summary

Automatically pass terminal shortcuts (e.g. Ctrl+P) through to the running program instead of VS Code when the terminal's alternate screen buffer is active, without the global side effects of terminal.integrated.commandsToSkipShell.

## Best solution

Have TerminalInstance.attachCustomKeyEventHandler consult TerminalContextKeys.altBufferActive when deciding whether to skip a keybinding to the shell, so alt-buffer TUI apps get shortcuts passed through automatically — scope and default-on/off behavior need a maintainer decision first.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts`, `src/vs/workbench/contrib/terminal/browser/terminalConfigurationService.ts`, `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`
- **Validation:** A terminal instance test asserting that, with TerminalContextKeys.altBufferActive true, a keybinding-resolved key event in attachCustomKeyEventHandler is NOT swallowed (falls through to xterm.js) even though it would normally be skipped by commandsToSkipShell logic; the same key in the normal buffer still resolves to the VS Code command.
- **Behavior:**

  > When a program running in the integrated terminal has switched to the alternate screen buffer (full-screen TUI apps, interactive CLI agents), keyboard shortcuts that VS Code would otherwise intercept as commands (e.g. Ctrl+P, Ctrl+Shift+P) should instead reach the terminal process, while the same shortcuts keep behaving as normal VS Code commands outside the terminal or when the terminal is on its normal buffer. Acceptance: toggling the alt-buffer context key in a test flips whether a bound keybinding is forwarded to xterm.js vs. intercepted as a command, without any change to terminal.integrated.commandsToSkipShell's existing global behavior.
- **Trace:**

  > terminalInstance.ts's attachCustomKeyEventHandler (around lines 1157-1184) decides whether to swallow a keybinding-resolved key event purely from `terminalConfigurationService.config.sendKeybindingsToShell` and `shouldCommandSkipShell(resolveResult.commandId)` (terminal.integrated.commandsToSkipShell) — it never reads `this._terminalAltBufferActiveContextKey` (bound at line 479 to TerminalContextKeys.altBufferActive), so alt-buffer state has no effect on this decision today. The context key itself is real and already consumed elsewhere (terminalActions.ts's `focusInAny_and_normalBuffer`), so a user can already hand-craft a per-shortcut keybinding with `when: terminalFocus && terminalAltBufferActive` as a workaround, but that's manual and per-key, not the automatic behavior requested. Boundary: do not touch the softDispatch/keybinding-resolution path itself or normal-buffer behavior — only the skip-vs-forward decision for the alt-buffer case.
- **Open decisions:**
  - Should alt-buffer passthrough be automatic by default for all terminals, or gated behind a new opt-in setting?
  - Which commands/shortcuts are in scope — all VS Code keybindings, only those listed in commandsToSkipShell, or a new dedicated list?
  - Should the existing terminalAltBufferActive context key simply be documented/supported as the sanctioned per-keybinding override mechanism instead of adding new core logic?

## Evidence

- **no alt-buffer awareness in skip logic:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1181 — the skip-to-command decision in attachCustomKeyEventHandler only checks `config.sendKeybindingsToShell` and `shouldCommandSkipShell(commandId)`; it never reads `this._terminalAltBufferActiveContextKey` (bound at line 479 from `TerminalContextKeys.altBufferActive`), so the alt-buffer state currently has zero effect on which shortcuts reach the terminal.
- **context key exists but underused:** src/vs/workbench/contrib/terminal/common/terminalContextKey.ts defines `TerminalContextKeys.altBufferActive` ('terminalAltBufferActive'); it is only consumed today in terminalActions.ts's `focusInAny_and_normalBuffer` expression, not in the keybinding-skip path.
- **existing workaround is global, as the reporter notes:** terminal.integrated.commandsToSkipShell / terminal.integrated.sendKeybindingsToShell (terminalConfiguration.ts:46-50) change behavior for all buffer states, matching the reporter's complaint that enabling it disables the VS Code shortcut everywhere, not just in the terminal's alt buffer.
