# Issue #336452 — Diff Editor hides semantically significant YAML indentation changes

[https://github.com/microsoft/vscode/issues/336452](https://github.com/microsoft/vscode/issues/336452)

## Summary

Thanks for the detailed report — VS Code already ships a mitigation for exactly this case: the built-in YAML extension sets a language-specific `diffEditor.ignoreTrimWhitespace: false` default, which overrides the editor-wide `true` default whenever a file is recognized as YAML (including `.yml`/`.yaml` workflow files).

## Change summary

Diff Editor's default `diffEditor.ignoreTrimWhitespace: true` can hide semantically meaningful indentation-only changes in YAML files (e.g. GitHub Actions workflows).

## Best solution

Keep the shipped mechanism: `extensions/yaml/package.json` already declares `"configurationDefaults": { "[yaml]": { "diffEditor.ignoreTrimWhitespace": false, ... } }`, so a `.yml`/`.yaml` file opened with the built-in YAML language mode already shows whitespace-only/indentation diffs by default — the global `true` default is intentional for languages where leading whitespace isn't semantically significant, and is deliberately overridden for YAML. If the reporter is still seeing the behavior, the likely cause is the file not being recognized as the `yaml` language (e.g. a `[yaml]` language override in user/workspace settings reverting the value to `true`, or a language-detection mismatch) rather than a core defect.
