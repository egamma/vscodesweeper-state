# Issue #344559 — Agent host: viewing a non-resident Copilot CLI session resumes the SDK session and replays its whole event journal

[https://github.com/microsoft/vscode/issues/344559](https://github.com/microsoft/vscode/issues/344559)

## Summary

Keep open: current source still resumes a cold Copilot SDK session for ordinary history reads and reconstructs the journal before completing restoration. The related remote-navigation report explicitly separates this host-side defect from its renderer and connection costs.

## Change summary

Opening a non-resident Copilot CLI conversation incurs SDK activation and full journal reconstruction, delaying subscription snapshots and other host work.

## Best solution

Make passive Copilot history restoration independent of execution-session activation, and avoid repeated full-journal reconstruction while preserving transcript fidelity. Address history materialization and subscription dependencies together, with measured host responsiveness for large single-turn conversations.

Add subscription-order coverage and a repeatable large-journal measurement across fresh host instances, recording snapshot latency and progress in another session.
- **Behavior:**

  > Viewing an existing, non-resident Copilot conversation must not activate its execution session solely to obtain history. The complete transcript, tool outputs, and on-demand child transcripts remain available, and sending the next message continues the same SDK conversation. Large completed histories should not repeatedly impose full replay costs after host restarts or prevent unrelated sessions from making progress. Acceptance should cover cold reads without explicit credentials, restart behavior, concurrent subscriptions, and first-send continuation.
- **Trace:**

  > CopilotAgent._getChatMessages in src/vs/platform/agentHost/node/copilot/copilotAgent.ts limits passive persisted reads to contexts with explicit credentials; ordinary cold reads reach _ensureResolvedChatSession and SDK resume. Both _doReadPersistedChatHistory and CopilotAgentSession._computeMappedEvents collect journal pages through readCopilotSessionEvents before mapping, and their caches are process-local. AgentService's full restore awaits provider turns before installing session state, so removing SDK activation alone does not establish independent summary delivery. The existing isolated-history test in copilotAgent.test.ts supplies a useful fidelity and no-activation baseline. Preserve exact advertised chat identities, recorded storage, credential boundaries, local-turn hydration, and live-send semantics; do not broaden this into renderer optimization or transport-limit work. https://github.com/microsoft/vscode/issues/344521 explicitly tracks this as separate host work, while https://github.com/microsoft/vscode/issues/339997 owns the distinct oversized-frame failure. The unresolved design scope is durable history freshness and what clients may observe before history hydration finishes.
- **Open decisions:**
  - When the native CLI changes a journal outside VS Code, what freshness guarantee must a durable materialized history provide on subscription?
  - Should session subscriptions return summaries before the default chat's history is hydrated, and what observable readiness state should clients receive during that interval?

## Evidence

- **Reported trigger and measurements:** https://github.com/microsoft/vscode/issues/344559 documents opening a completed, non-resident Copilot CLI session over SSH: a 7.3 MB snapshot with 3,891 response parts took 13.4 seconds, including 4.3 seconds of SDK resume and several seconds of journal reconstruction.
- **Cold history still activates execution:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:7476-7512 routes directly to persisted history only when !context.target && context.credentials && context.sdkSessionId. Without explicit credentials, it calls _ensureResolvedChatSession; at lines 7870-7904 that method resumes an absent SDK backing through _resumeSession or _resolveOrResumeChatSession.
- **Full reconstruction and process-local memoization:** copilotAgent.ts:7515-7570 stores persisted-history results in an in-memory Map and reads journal pages of up to 1,000 events before invoking mapSessionEvents. copilotAgentSession.ts:6529-6590 likewise memoizes mapped history only in memory and reconstructs events on the live-session path. copilotSessionHistory.ts:18-54 collects every backward page before returning the combined event array.
- **Subscription dependency:** src/vs/platform/agentHost/node/agentService.ts:10752-10764 restores non-resident sessions during subscription. Its full restore awaits _getChatMessages at line 13914 before publishing restored state at lines 14001-14010; _getChatMessages at lines 9730-9740 awaits provider history.

In https://github.com/microsoft/vscode/issues/344521#issuecomment-6443597318, this issue's author supplies the same large-chat measurements and explicitly lists https://github.com/microsoft/vscode/issues/344559 as the separately filed host-restore work.
