# Issue #326793 — Cannot see chart text in Windows' high contrast modes

[https://github.com/microsoft/vscode/issues/326793](https://github.com/microsoft/vscode/issues/326793)

## Summary

The screenshots demonstrate a current accessibility defect in the core chat Mermaid renderer, and current source has no Windows forced-colors handling for generated diagrams. Keep it open and route it to the Mermaid and accessibility owners.

## Change summary

Mermaid chart text in Copilot Chat becomes invisible when a Windows high-contrast mode is enabled.

## Best solution

Make Mermaid diagrams preserve readable text, node, and line contrast under Windows forced-colors modes across chat, Markdown preview, and notebook rendering, with explicit high-contrast validation.

- **Behavior:**

  > Mermaid diagrams must retain readable text, node boundaries, and connector lines whenever any Windows high-contrast mode is active. Text must be visible without selecting it in the Aquatic, Desert, Dusk, and Night themes. Normal VS Code light, dark, and high-contrast theme rendering must remain readable, and chat, Markdown preview, and notebook Mermaid output should behave consistently.
- **Trace:**

  > The chat path initializes and renders Mermaid in extensions/mermaid-markdown-features/preview-src/chat/mermaidWebview.ts through the shared `buildMermaidConfig`. `VsCodeMermaidThemeTracker` in extensions/mermaid-markdown-features/preview-src/shared/vsCodeTheme.ts resolves VS Code CSS variables into static Mermaid SVG theme colors, while extensions/mermaid-markdown-features/preview-src/shared/diagramStyles.css has no forced-colors-specific treatment. The reporter's Windows screenshots confirm the observable failure, but source inspection alone does not establish which generated SVG properties Windows overrides. The shared renderer is also consumed by Markdown preview and notebooks, so validation must cover those surfaces without changing ordinary-theme behavior. https://github.com/microsoft/vscode/issues/328924 is a newer related contrast report, not a valid canonical for this re-reviewed issue.
