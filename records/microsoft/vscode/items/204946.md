# Issue #204946 — Do not show complete content after reload if output is cleared 

[https://github.com/microsoft/vscode/issues/204946](https://github.com/microsoft/vscode/issues/204946)

## Summary

The defect remains on current main: clearing a LogOutputChannel only advances the current output model's read offset, while the underlying log file remains intact and is read again after the extension host reloads. The maintainer's latest comment explicitly accepts the overlooked clear behavior as a bug, and the current bug label and Backlog milestone should stand.

## Change summary

Explicitly clearing a LogOutputChannel should prevent its cleared content from reappearing after a window reload.

## Best solution

Make an explicit LogOutputChannel clear durable across extension-host and window reloads, with consistent behavior on macOS, Linux, Windows, and remote extension hosts. The design should settle whether clearing truncates the physical log or preserves it while persisting a display boundary, because that choice affects Developer: Open Log File.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostOutput.ts`, `src/vs/workbench/contrib/output/common/outputChannelModel.ts`, `src/vs/platform/log/common/log.ts`, `src/vs/platform/log/node/spdlogLog.ts`, `src/vs/workbench/api/test/node/extHostOutput.test.ts`
- **Validation:** Add an extension-host regression test that logs old content, clears the LogOutputChannel, recreates the output service against the same log location to simulate reload, appends new content, and asserts that only the new content is exposed; run it with scripts/test.sh --grep "LogOutputChannel clear survives reload".
- **Behavior:**

  > After an extension explicitly clears a LogOutputChannel, content written before that clear must not reappear in the Output view after Developer: Reload Window or extension-host restart. New entries written after the clear must remain visible and continue to use normal log formatting and rotation. The behavior must be consistent for local and remote extension hosts on supported operating systems. Acceptance includes a reload simulation proving that only post-clear content is exposed.
- **Trace:**

  > ExtHostOutputChannel.clear() in src/vs/workbench/api/common/extHostOutput.ts flushes the logger and sends a UI clear up to its current in-memory byte offset. FileOutputChannelModel in src/vs/workbench/contrib/output/common/outputChannelModel.ts uses that offset only in the current FileContentProvider; loadModel() in a subsequent extension host reads the unchanged backing file from the beginning. SpdLogLogger in src/vs/platform/log/node/spdlogLog.ts has no clear or truncate operation, so the persistence boundary currently stops at the output model. The API contract in src/vscode-dts/vscode.d.ts says clear removes all channel output, and the maintainer accepted this explicit-clear case as a bug. Preserve intentional retention across reload when no clear was requested, and do not change ordinary OutputChannel append/replace behavior. https://github.com/microsoft/vscode/issues/232500 establishes that physical-log behavior is part of this canonical issue; https://github.com/microsoft/vscode/issues/224516 is related but also includes an immediate partial-content symptom.
- **Open decisions:**
  - Should LogOutputChannel.clear() truncate or rotate the physical file exposed by Developer: Open Log File, or retain those bytes for diagnostics while persisting a display boundary that survives reload?
  - If the physical file is retained, what public behavior should Developer: Open Log File show after a clear: the full retained history or only post-clear entries?

## Evidence

- **source-reproducible path:** In src/vs/workbench/api/common/extHostOutput.ts, ExtHostOutputChannel.clear() flushes the logger and sends OutputChannelUpdateMode.Clear with the in-memory byte offset; it does not clear or truncate the logger's file. A newly constructed channel after reload starts with offset 0.
- **reload behavior:** In src/vs/workbench/contrib/output/common/outputChannelModel.ts, FileOutputChannelModel.update() handles Clear by resetting FileContentProvider's read position and clearing the text model. AbstractFileOutputChannelModel.loadModel() later reads the backing file's existing contents, so a new model after reload can expose the previously cleared bytes again.
- **logger limitation:** src/vs/platform/log/node/spdlogLog.ts exposes logging, flush, and disposal through SpdLogLogger but no clear or truncate operation; flush therefore cannot make the clear durable.
- **API contract:** src/vscode-dts/vscode.d.ts documents OutputChannel.clear() as removing all output from the channel, which the reload behavior violates.
- **maintainer confirmation:** The final maintainer comment at https://github.com/microsoft/vscode/issues/204946#issuecomment-2705919792 agrees after accounting for the explicit clear action; the issue was then labeled bug and moved to Backlog.
- **canonical status:** https://github.com/microsoft/vscode/issues/232500 was closed by a maintainer as a duplicate of this issue, confirming that this issue owns the persistent-log variant. The open https://github.com/microsoft/vscode/issues/224516 is younger and reports partial characters reappearing immediately after clear, so it cannot replace this re-reviewed issue as canonical.
