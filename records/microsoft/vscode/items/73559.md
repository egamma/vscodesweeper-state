# Issue #73559 — Cannot set embedded language indentation rules

[https://github.com/microsoft/vscode/issues/73559](https://github.com/microsoft/vscode/issues/73559)

## Summary

Keep open: current source still requires outer-language indentation rules on the reported move-lines path. Maintainers explicitly designated this issue as the tracking location for embedded-language indentation support.

## Change summary

Honor an embedded language's indentation rules when moving lines without requiring those rules on the enclosing language.

## Best solution

Make embedded-language indentation configuration sufficient for move-line indentation within that language, while preserving neighboring languages' behavior. Start with the shared indentation-inheritance path and verify its typing and Enter consumers before extending the behavior.

## Plan brief

- **Likely files:** `src/vs/editor/common/languages/autoIndent.ts`, `src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts`, `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/contrib/linesOperations/test/browser/moveLinesCommand.test.ts`
- **Validation:** Add embedded-language cases to the 'Editor contrib - Move Lines Command honors Indentation Rules' suite and run scripts/test.sh --grep 'Editor contrib - Move Lines Command honors Indentation Rules'. Cover moving up and down with rules registered only for the embedded language, conflicting enclosing-language rules, and unchanged adjacent-language behavior; also cover shared typing and Enter consumers if their behavior changes.
- **Behavior:**

  > Moving lines within an embedded language should honor that language's registered indentationRules without requiring equivalent rules on the enclosing language. The reported example is vue-html inside vue, where configuring vue-html alone should suffice. Acceptance checks cover moving both up and down and demonstrate that HTML rules do not alter neighboring JavaScript or CSS regions. Existing single-language indentation and editor.autoIndent modes must retain their behavior.
- **Trace:**

  > MoveLinesCommand in src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts already checks position-specific language configuration, but its virtual model reports the enclosing language from tokenization.getLanguageId(). getGoodIndentForLine in src/vs/editor/common/languages/autoIndent.ts selects embedded rules and then delegates to getInheritIndentForLine, which independently selects the enclosing language's rules and returns null when they are absent. This establishes the remaining prerequisite without executing the historical Vetur branch. getInheritIndentForLine also serves Enter and on-type indentation in autoIndent.ts and a caller in src/vs/editor/common/cursor/cursorTypeEditOperations.ts; the effects on those consumers need assessment before implementation. Preserve existing mixed-language selection safeguards and avoid broadening this into per-language indent-size or folding support. Maintainers consolidated the indentationRules work here in https://github.com/microsoft/vscode/issues/176034#issuecomment-1506725614.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/73559 describes moving lines within vue-html embedded in vue: registering only vue-html indentationRules is insufficient, while registering the rules on vue too works but risks affecting CSS and JavaScript regions.
- **Remaining source-level dependency:** In src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts, shouldAutoIndent checks the embedded language's rules and getEditOperations calls getGoodIndentForLine with a position-specific language ID. However, createVirtualModel exposes the enclosing model language through tokenization.getLanguageId(). In src/vs/editor/common/languages/autoIndent.ts:86-88, getInheritIndentForLine selects indentationRules using that enclosing language and returns null if none exist; getGoodIndentForLine calls it at line 242 and returns null when inheritance fails. Thus the reported outer-language prerequisite remains.
- **Existing capability check:** src/vs/editor/common/config/editorOptions.ts registers editor.autoIndent, whose full mode honors language indentationRules for moving lines. That setting enables rule processing but does not remove the enclosing-language lookup in getInheritIndentForLine; it is not a solution to the central request.
