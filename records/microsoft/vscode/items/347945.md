# Issue #347945 — Sessions view: group and filter agent sessions by tag

[https://github.com/microsoft/vscode/issues/347945](https://github.com/microsoft/vscode/issues/347945)

## Summary

Keep open as a feature request: existing custom groups and metadata search partially help, but neither provides tag-prefix grouping or explicit tag filtering. The requested protocol contract remains a proposal, and the linked grouping reports do not own this capability.

## Change summary

Support tag-prefix grouping, tag filtering, and visible session tags without changing default folder grouping or user-chosen titles.

## Best solution

Evaluate provider-neutral session tags alongside the protocol proposal, then integrate supported tags into native Sessions grouping, search, and row presentation. Preserve existing organization and treat extension-provided tag links as a separate optional scope decision.

## Evidence

- **Existing grouping capability:** src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts:239–245 defines Workspace, Repository, Environment, Date, and Inbox grouping, but no tag grouping. Its createGroupFromSessions and custom-group membership paths provide manual organization, not automatic grouping from shared tag metadata.
- **Existing search capability:** src/vs/workbench/contrib/sessions/browser/views/sessionsListSearch.ts defines searchable folder, repository, group, branch, pullRequest, and host fields. SessionsListSearchQuery splits the query into ordinary search words; it has no tag qualifier interpretation. Existing PR metadata search partly addresses PR discovery but does not cover arbitrary issue/task tags.
- **Protocol dependency:** https://github.com/microsoft/agent-host-protocol/issues/594 proposes SessionSummary.tags, session/tagsChanged, and capability limits. Its unresolved questions include session-versus-chat scope and tag inheritance on fork or handoff; this is a prerequisite contract proposal, not proof that the requested client behavior has shipped.
- **Related reports have different scope:** https://github.com/microsoft/vscode/issues/334397 concerns distinct workspace URIs collapsing under identical display labels. https://github.com/microsoft/vscode/issues/306592 concerns clustering worktrees by repository identity. Neither owns grouping unrelated repositories by client-editable task, issue, or PR tags.
