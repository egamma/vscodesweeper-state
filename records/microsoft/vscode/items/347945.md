# Issue #347945 — Sessions view: group and filter agent sessions by tag

[https://github.com/microsoft/vscode/issues/347945](https://github.com/microsoft/vscode/issues/347945)

## Summary

Tag-based organization remains a distinct capability gap. Keep this request open for product consideration alongside the protocol proposal; existing custom groups and metadata search only partially cover it.

## Change summary

Support grouping, filtering, and displaying agent-session tags across workspace boundaries, optionally with prefix-based links.

## Best solution

Evaluate provider-neutral session tags together with the protocol contract, then decide how tag grouping and exact-tag search should coexist with custom groups and existing placement rules. Preserve ordinary grouping for users who do not use tags.

## Evidence

- **existing grouping capability:** src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts:241–249 defines Workspace, Repository, Environment, Date, Inbox, and Worktree grouping, but no tag grouping. sessionsListActions.ts registers corresponding grouping commands.
- **existing search capability:** src/vs/workbench/contrib/sessions/browser/views/sessionsListSearch.ts defines searchable folder, repository, group, branch, pullRequest, and host fields. SessionsListSearchQuery splits input into ordinary search words; it does not interpret tag:pr:4521 as an exact tag filter.
- **partial workaround, not coverage:** src/vs/sessions/SESSIONS_LIST.md documents custom groups that can collect sessions across workspaces, but membership is local presentation state, each session belongs to at most one group, and this state is not synchronized to provider metadata. That does not deliver shared, multi-tag organization supplied by extensions or agents.
- **protocol prerequisite:** https://github.com/microsoft/agent-host-protocol/issues/594 proposes client-editable session tags, capability advertisement, summary propagation, and optional listing filters. It is the protocol-side counterpart, not a duplicate of the requested VS Code UI.
- **related reports have different scope:** https://github.com/microsoft/vscode/issues/334397 concerns unrelated folders collapsing under identical workspace labels; https://github.com/microsoft/vscode/issues/306592 concerns grouping worktrees by repository. Neither owns arbitrary cross-repository task or issue tags.
