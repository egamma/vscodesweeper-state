# Issue #336727 — Feature Request: expose an `explorerResourceIsSymbolicLink` context key for when clauses

[https://github.com/microsoft/vscode/issues/336727](https://github.com/microsoft/vscode/issues/336727)

## Summary

Verified on main: no `explorerResourceIsSymbolicLink` (or equivalent) context key exists — `ExplorerView.setContextKeys()` binds folder/readonly/root/parent-readonly but never symlink status, even though `ExplorerItem.isSymbolicLink` is already tracked and consumed elsewhere (fileActions.ts). This is a small, well-scoped, currently-unimplemented gap; it just entered the standard 60-day backlog-candidate upvote window, which does not block keeping it open.

## Change summary

Expose the focused Explorer item's symlink status as a when-clause context key (`explorerResourceIsSymbolicLink`) so extension-contributed `explorer/context` menu items can be scoped to symlinks.

## Best solution

Add a `ExplorerSymbolicLinkContext` RawContextKey next to `ExplorerFolderContext`/`ExplorerResourceReadonlyContext` in src/vs/workbench/contrib/files/common/files.ts, bind it in ExplorerView's constructor alongside the other context keys, and set it in `setContextKeys()` from `stat.isSymbolicLink`.
