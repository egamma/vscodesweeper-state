## Change summary

- **Current source confirms the missing icon class:** src/vs/workbench/contrib/notebook/browser/controller/editActions.ts:501-505 builds picker items using getIconClasses(..., this.getFakeResource(...)). At lines 549-565, getFakeResource returns undefined for a registered language with neither extensions nor filenames. src/vs/editor/common/services/getIconClasses.ts then returns only the base file-icon class because language-specific class generation is inside the resource guard.
- **Existing rendering contract:** src/vs/workbench/services/themes/browser/fileIconThemeData.ts:453-460 generates contributed-icon CSS targeting the language-specific <languageId>-lang-file-icon class. getIconClassesForLanguageId in src/vs/editor/common/services/getIconClasses.ts generates that class directly; the normal editor language picker uses it in src/vs/workbench/browser/parts/editor/editorStatus.ts:1186. The notebook's undefined-resource path omits the class required to select the contributed icon.
- **Open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/282367 is OPEN with mergedAt null and explicitly says Fixes microsoft/vscode#180080. It proposes using getIconClassesForLanguageId in ChangeCellLanguageAction. This is pending implementation work, not a landed fix, and precludes a competing agent implementation.

The supplied older candidate https://github.com/microsoft/vscode/issues/142133 was verified open, but requests dynamically adding arbitrary language-selector values rather than displaying contributed icons; it is not a duplicate canonical.
