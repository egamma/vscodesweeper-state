# Issue #209139 — Add a new event on a QuickPick after filtering is applied with the set of items filtered

[https://github.com/microsoft/vscode/issues/209139](https://github.com/microsoft/vscode/issues/209139)

## Summary

Keep open: extensions still cannot observe the complete post-filter QuickPick item set. The older custom-filter request overlaps with one use case but does not cover the distinct need to detect built-in filtering results.

## Change summary

Expose a QuickPick event pairing the filter value with its resulting visible items so extensions can detect empty results and provide supplemental choices.

## Best solution

Provide an extension-facing post-filter observation contract that preserves built-in matching and highlighting while exposing the resulting items and associated value. API owners should settle notification timing and behavior when listeners update items, coordinating with the related custom-filter proposal.

- **Current filtering and extension bridge:** src/vs/platform/quickinput/browser/quickInput.ts:594–606 applies QuickInputList.filter before firing onDidChangeValue, but the event carries only the value. src/vs/platform/quickinput/browser/quickInputList.ts:1423–1499 computes each item's hidden state; its onChangedVisibleCount at lines 723–724 exposes only an internal count. src/vs/workbench/api/browser/mainThreadQuickOpen.ts:145–170 forwards value, active-item, and selected-item events, not the complete filtered set.
- **Partial workaround:** QuickInputList.filter honors QuickPickItem.alwaysShow for unmatched items, allowing extensions to supply supplemental choices.
