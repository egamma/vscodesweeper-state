# Issue #325177 — Agent Mode md file is not visible similar to Ask and Plan modes

[https://github.com/microsoft/vscode/issues/325177](https://github.com/microsoft/vscode/issues/325177)

## Summary

Current behavior follows the implementation rather than a broken link: Ask and Plan are URI-backed generated custom agents, while the default Agent mode has no Agent.agent.md resource to open. Keep this as an under-discussion feature request for a consistent way to inspect the dynamically composed Agent configuration.

## Change summary

Expose the default Agent mode's instructions through a file action comparable to the Ask and Plan mode actions.

## Best solution

If maintainers want inspection parity, provide a read-only generated representation of the effective Agent configuration and expose it from the mode picker, while making clear that the prompt is dynamically composed rather than an editable Agent.agent.md source file.

## Evidence

- **mode picker behavior:** src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts creates a file/edit toolbar action only when an Agent-kind mode supplies `mode.uri`; the built-in Agent mode does not.
- **built-in mode model:** src/vs/workbench/contrib/chat/common/chatModes.ts defines Agent as `BuiltinChatMode`; that class serializes its identity, description, and kind but has no URI or agent-file content.
- **Ask and Plan distinction:** extensions/copilot/src/extension/agents/vscode-node/askAgentProvider.ts and planAgentProvider.ts generate cached Ask.agent.md and Plan.agent.md resources through `CachedAgentFileWriter`, which is why those entries have files to open.
- **Agent implementation:** The default coding agent is registered through extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts and its prompt is assembled by AgentIntent/AgentPrompt under extensions/copilot/src/extension/intents/node/agentIntent.ts and extensions/copilot/src/extension/prompts/node/agent/, rather than sourced from a single Agent.agent.md file.
- **canonical search:** Searches for an older open issue covering the same observable absence of the Agent-mode file action found no verified canonical; the mechanically suggested related items concern different agent behaviors.
