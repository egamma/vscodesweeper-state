# Issue #308964 — Copilot Chat should support cross-device cloud conversation memory for repository workflows

[https://github.com/microsoft/vscode/issues/308964](https://github.com/microsoft/vscode/issues/308964)

## Summary

Opt-in cloud session storage and cross-device history queries now cover part of this request, but they do not establish seamless continuation in Chat History. Keep this open to define repository-scoped resumption and its retention controls; the related reports do not meet the stronger duplicate bar for this re-reviewed item.

## Change summary

Provide opt-in, account-backed conversation continuity across devices, with repository scope and explicit retention and reset controls.

## Best solution

Build on the existing session-sync infrastructure rather than adding another memory store, and define how cloud conversations become resumable repository sessions. Distinguish restoring a conversation from retrieving historical context, with clear user and organization controls.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `extensions/copilot/src/extension/chronicle/vscode-node/remoteSessionExporter.ts`, `extensions/copilot/src/extension/tools/node/sessionStoreSqlTool.ts`
- **Validation:** The plan should define a two-device acceptance scenario: create a repository conversation on device A, open the same repository under the same account on device B, discover and continue the agreed context without manually copying a summary, then verify that opt-out, repository exclusions, organization policy, and forget/reset controls are honored.
- **Behavior:**

  > A user working on the same repository across machines should be able to continue prior coding context without manually reconstructing decisions or copying summaries. Cloud participation must remain opt-in and respect organization controls. Acceptance should distinguish historical-context retrieval from restoring a resumable conversation, and explicitly define repository matching, retention, and forget/reset behavior.
- **Trace:**

  > chat.shared.contribution.ts already registers experimental cloud session sync, repository exclusions, and an organization policy. RemoteSessionExporter uploads chat events and exposes cloud deletion commands, while sessionStoreSqlTool.ts can query cloud history across devices. ChatSessionStore remains the workbench persistence boundary to investigate for restored conversations; the trace has not established a cloud-to-local resumable-session path. A maintainer explicitly describes one-way synchronization in https://github.com/microsoft/vscode/issues/330608#issuecomment-5301225931. That younger report is related, not an eligible duplicate canonical; the older https://github.com/microsoft/vscode/issues/273751 concerns synchronized memory rather than clearly owning full conversation resumption. Preserve existing opt-in and enterprise restrictions, and avoid introducing a parallel storage system. The uncertainty starts at the intended restoration contract and lifecycle controls, not at whether cloud storage already exists.
- **Open decisions:**
  - Should cross-device continuation restore the original conversation as a resumable session, or start a new session populated with retrieved repository context?
  - How should repository identity and access determine which cloud conversations are offered when the same repository is opened on another device?
  - What retention policy should apply, and should forgetting a conversation remove only cloud history or also derived memory and local copies?

## Evidence

- **Existing capability:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:820–847 registers chat.sessionSync.enabled, defaulting to false and requiring github.copilot.chat.localIndex.enabled, plus chat.sessionSync.excludeRepositories and an organization policy that can prohibit cloud storage.
- **Cloud storage and reset:** extensions/copilot/src/extension/chronicle/vscode-node/sessionSync.contribution.ts constructs RemoteSessionExporter. extensions/copilot/src/extension/chronicle/vscode-node/remoteSessionExporter.ts exports chat events and registers github.copilot.sessionSync.deleteSessions and github.copilot.sessionSync.deleteSessionFromCloud. These cover cloud persistence and deletion, not proof of seamless conversation restoration.
- **Cross-device context retrieval:** extensions/copilot/src/extension/tools/node/sessionStoreSqlTool.ts:65–70 describes querying past coding sessions across devices and agents; its query path calls CloudSessionStoreClient.executeQuery. Historical context retrieval partially addresses repeated explanations but is distinct from reopening and continuing the original conversation.
- **Maintainer-confirmed product boundary:** https://github.com/microsoft/vscode/issues/330608 reports cloud transcripts not appearing in Chat History or the Agents window. A maintainer states that sync is one-way and cloud sessions are accessed through Chronicle commands: https://github.com/microsoft/vscode/issues/330608#issuecomment-5301225931. This issue was created after the reviewed item and cannot be its duplicate canonical under the prior-review rule.
- **Older related request:** https://github.com/microsoft/vscode/issues/273751 is open and predates this report, but requests synchronization of remembered preferences or patterns through VS Code's sync directory. It does not clearly own this report's full conversation-history restoration and repository-resumption scope.
- **Demand and remaining decisions:** https://github.com/microsoft/vscode/issues/308964 has one body upvote and an independent commenter requesting the same cross-machine continuity, repository scope, retention, and reset behavior. The request is actionable for design, but the existing cloud-query capability should be accounted for before selecting the remaining scope.
