# Issue #346273 — file paths bugging out

[https://github.com/microsoft/vscode/issues/346273](https://github.com/microsoft/vscode/issues/346273)

## Summary

Keep open: the current changed-files conversion bypasses the owning connection's URI mapper, matching the reported WSL file-opening failure. This belongs to VS Code's agent-host client, not an external extension.

## Change summary

Agent-host changed files in a WSL window should retain remote resource identities so their paths display correctly and clicking them opens the remote files.

## Best solution

Ensure changed-file identities consistently use the owning connection's client-space mapping across response summaries and changeset consumers, while preserving snapshot-content addressing and local-session behavior.
