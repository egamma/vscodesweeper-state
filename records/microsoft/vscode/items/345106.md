- **Current source confirms distinction:** src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts: RestartExtensionHostAction calls startExtensionHosts() without replacements. src/vs/workbench/contrib/extensions/browser/extensionsActions.ts: ExtensionRuntimeStateAction calls updateRunningExtensions(), which collects pending changes and supplies { toAdd, toRemove } in extensionsWorkbenchService.ts.
- **Existing capabilities do not cover the ask:** Current updateRunningExtensions() call sites provide internal UI callbacks rather than an exposed equivalent command. extensions.autoRestart is an opt-in, non-stable configuration tied to window focus, not an on-demand programmatic replacement.
- **Report-specific evidence to preserve:** https://github.com/microsoft/vscode/issues/345106 supplies a Windows 1.144.0 reproduction using workbench.extensions.installExtension with a local VSIX URI, plus a request to document the developer restart command’s different semantics.
