# Issue #345106 — Expose an update-aware “Restart Extensions” command for programmatic VSIX updates

[https://github.com/microsoft/vscode/issues/345106](https://github.com/microsoft/vscode/issues/345106)

## Summary

The requested programmatic capability remains missing: current source distinguishes restarting extension hosts from applying pending extension changes. Keep this open for an extension-management command-contract decision.

## Change summary

Expose a supported command that applies pending extension updates through the existing Restart Extensions operation without reloading the window.

## Best solution

Provide a documented programmatic equivalent of the Extensions editor’s update-aware restart, preserving the existing developer restart command’s semantics and lifecycle safeguards.

- **Update-aware operation:** src/vs/workbench/contrib/extensions/browser/extensionsActions.ts:2077–2082 routes the editor’s Restart Extensions action to updateRunningExtensions(). In extensionsWorkbenchService.ts:1727–1769, that operation collects pending additions/removals and passes { toAdd, toRemove } to startExtensionHosts().
- **Existing-capability check:** The workbench.extensions.installExtension handler in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts installs a supplied VSIX but exposes no update-aware restart option. Searches across src and extensions found updateRunningExtensions() used by internal services and UI callbacks, not an equivalent standalone registered command.
- **Partial alternative:** extensions.autoRestart is registered in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts with default false, excluded from stable settings, and described as restarting after updates when the window is unfocused. It does not provide the requested explicit notification-triggered command.
