# Issue #342034 — WSL MCP migration leaves migrated servers disabled while same-named Windows servers remain enabled

[https://github.com/microsoft/vscode/issues/342034](https://github.com/microsoft/vscode/issues/342034)

## Summary

Thanks for the detailed report. The steps and observed result are concrete, but this needs a WSL remote and an MCP migration to confirm. I did not trace the full path from migration to the 'Disabled (Globally)' label, so it stays open for the owning team to retest and decide how same-name conflicts should be surfaced.

## Change summary

After migrating WSL MCP servers to ~/.copilot/mcp-config.json, they show as Disabled (Globally) while same-named Windows servers stay enabled, with no explanation of a conflict.

## Best solution

Make migration detect same-name collisions with servers from other scopes (including the local Windows config). It should then either preserve the enabled state or explain the conflict and let the user resolve it. Disabled-state labels should say why a server is disabled.
