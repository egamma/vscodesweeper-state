# Issue #342034 — WSL MCP migration leaves migrated servers disabled while same-named Windows servers remain enabled

[https://github.com/microsoft/vscode/issues/342034](https://github.com/microsoft/vscode/issues/342034)

## Summary

Keep open: current source explains how migration reverses local/remote precedence and presents collision suppression as “Disabled (Globally)”. This confirms the reported list-state problem, not which server an active Copilot session actually executes.

## Change summary

Migrating WSL user MCP definitions changes their precedence against same-named Windows definitions without explaining the resulting disabled state.

## Best solution

Make MCP migration preserve the effective remote selection or explicitly identify the competing definition and let the user resolve the conflict. Collision-derived suppression should be distinguishable from an explicit global disablement.
