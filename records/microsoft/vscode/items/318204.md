# Issue #318204 — Memory Leak in Screenshot Annotation Tool

[https://github.com/microsoft/vscode/issues/318204](https://github.com/microsoft/vscode/issues/318204)

## Summary

The report claims unmanaged event listeners cause memory leaks in the screenshot annotation text editor, but the code uses DOM removal as cleanup (`cleanupTextEditor` removes the textarea), which releases listeners for GC. No concrete profiler evidence or reproduction steps were provided, and the reporter has not returned with the requested information in 62 days.

## Change summary

Event listeners on the text annotation textarea allegedly accumulate without removal, causing memory growth during repeated text edits.

## Best solution

The existing code in `screenshotAnnotation.ts` lines 1559-1577 uses raw `addEventListener` instead of `addDisposableListener`, which is a code-hygiene issue worth cleaning up. However, `cleanupTextEditor()` removes the textarea from the DOM (line 1666), and `startTextEdit` calls `commitTextEdit` first (line 1515) — so listeners are released with the element on each cycle. The reporter should provide heap snapshot evidence of actual accumulation before treating this as a real leak. If confirmed, converting to `addDisposableListener` in a `DisposableStore` cleared by `cleanupTextEditor` would be the correct fix.
