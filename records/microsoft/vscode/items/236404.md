# Issue #236404 — Devcontainers ignores terminal profile settings from settings.json when opening local integrated terminal

[https://github.com/microsoft/vscode/issues/236404](https://github.com/microsoft/vscode/issues/236404)

## Summary

Still reproduces on main: when creating a local terminal in a remote/container window, user-configured terminal profiles from settings.json are bypassed — the code falls back to the system default shell rather than resolving configured profiles against the local backend.

## Change summary

Local terminal in a devcontainer ignores custom terminal profile settings (e.g. `terminal.integrated.profiles.linux` and `terminal.integrated.defaultProfile.linux`) and falls back to the system default shell.

## Best solution

Extend the local-in-remote terminal creation path in `terminalService.ts` (lines 993–1000) to resolve the user's configured default profile against the local backend, rather than only fetching the system default shell. The November 2025 work (commits `3c31f617991`, `9fb14cce8aa`) added per-authority profile tracking but the final code only uses `backend.getDefaultSystemShell()`, discarding profile args, icon, overrideName, etc.
