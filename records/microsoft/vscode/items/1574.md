# Issue #1574 — Task and/or Extension Command User Arguments On Entry

[https://github.com/microsoft/vscode/issues/1574](https://github.com/microsoft/vscode/issues/1574)

## Summary

The task portion is implemented, while the remaining request for inline Command Palette arguments exactly matches a later request that maintainers closed as out of scope.

## Change summary

Allow users to supply one-time arguments when invoking tasks or extension commands from the Command Palette.

## Best solution

Use task input variables for task parameters and have extension commands collect runtime input through `window.showInputBox` or Quick Pick. Keep the shared Command Palette focused on selecting commands rather than providing command-specific argument grammars.

## Vision fit

- **Fit:** rejected
- **Reason:** Adding command-specific argument parsing to the shared palette conflicts with the preference for uniform UI when extensions can provide their own input flow.
- **Evidence:** Values and guardrails: “Simple, uniform UI and UI interactions” and “The power lives in extensions.”

  > Thanks for the request and discussion. The task use case was implemented by https://github.com/microsoft/vscode/pull/63910: task `inputs` can prompt for strings, choices, or command-provided values. Keybindings can also supply configured command `args`.

## Evidence

- **task support:** https://github.com/microsoft/vscode/pull/63910 implemented task input variables in commit f9703e9ad6681815a116ca3c9c29a9bd26ae0276; current `src/vs/workbench/services/configurationResolver/browser/baseConfigurationResolverService.ts` supports `promptString`, `pickString`, and command inputs.
- **maintainer precedent:** https://github.com/microsoft/vscode/issues/70889 requests the same inline Command Palette parameter flow and was closed with `*out-of-scope`; the maintainer discussion recommends an extension-managed Quick Pick and input box instead.
- **current behavior:** `src/vs/platform/quickinput/browser/commandsQuickAccess.ts` treats entered text as a command filter and executes selected commands without user-entered arguments; only arguments supplied internally with the command pick are forwarded.
- **keybinding support:** `src/vs/workbench/services/keybinding/browser/keybindingService.ts` already defines `args` as arguments passed to a command, covering the keybinding use case raised in the discussion.
