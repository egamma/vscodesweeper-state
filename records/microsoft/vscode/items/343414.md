# Issue #343414 — Canvases: built-in Terminal canvas isn't available

[https://github.com/microsoft/vscode/issues/343414](https://github.com/microsoft/vscode/issues/343414)

## Summary

Keep open as a Canvas interoperability feature request: VS Code supports extension canvases but does not provide the Terminal canvas contract used by Foundry. The linked discussion confirms this missing capability and documents workarounds, not a resolution.

## Change summary

Allow custom canvases to open an interactive terminal and send commands through a supported VS Code host contract.

## Best solution

Define a supported terminal integration contract for custom canvases, deciding whether compatibility with Copilot App's terminal canvas is appropriate or a host-specific capability is preferable. Preserve interactive output for long-running local agents; shell execution and copyable commands cover only part of the request.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/workbench/contrib/canvases/common/canvas.ts`, `src/vs/workbench/contrib/canvases/electron-browser/canvasService.ts`, `src/vs/platform/agentHost/test/node/copilotSdkCanvas.integrationTest.ts`
- **Validation:** After choosing the contract, exercise Foundry's terminal-opening flow in a Canvas-enabled local Copilot Agent Host session: open the terminal, send a benign command, observe interactive output, and verify that output remains available while a local agent runs. Cover the selected RPC contract in the existing Agent Host Canvas integration tests and verify ordinary extension canvases still open normally.
- **Behavior:**

  > Foundry custom canvases currently cannot open the terminal integration they use in Copilot App: requesting canvasId "terminal" fails because that canvas is not registered. Authentication can fall back to shell execution, but local agent startup still requires a manual copy-and-run step and visible terminal output. The desired outcome is a supported way for a custom canvas to launch an interactive terminal, send commands, and retain troubleshooting output. Acceptance must follow an explicitly chosen host contract rather than assume all Copilot App built-in canvases are available.
- **Trace:**

  > CopilotAgentSession.listCanvases and openCanvas in src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts delegate to the SDK runtime's canvas RPCs; the inspected source contains no terminal canvas registration or send_terminal_input implementation. Workbench Canvas definitions live in src/vs/workbench/contrib/canvases/common/canvas.ts, while CanvasService presents canvases through browser-view models, so generic canvas presentation is not itself an integrated-terminal adapter. The exact external calls are recorded at https://github.com/microsoft/foundry-dev-tools/issues/861#issuecomment-6332085738. The reporter explicitly confirms the missing built-ins and questions full App parity at https://github.com/microsoft/foundry-dev-tools/issues/861#issuecomment-6332180266. Existing terminal commands and the Canvas enablement setting do not establish that RPC contract. Preserve ordinary terminal behavior and existing extension-canvas support; other App built-in canvases are outside a terminal-focused first decision.
- **Open decisions:**
  - Should VS Code support Copilot App's canvasId "terminal" and send_terminal_input contract, or expose a distinct host capability that custom canvases must detect and use?

## Evidence

- **Concrete integration contract:** https://github.com/microsoft/foundry-dev-tools/issues/861#issuecomment-6332085738 supplies the actual calls: session.rpc.canvas.open({ canvasId: "terminal", ... }) followed by canvas.action.invoke with actionName "send_terminal_input". The observed failure is 'No canvas "terminal" is registered.'
- **Explicit capability gap:** https://github.com/microsoft/foundry-dev-tools/issues/861#issuecomment-6332180266 explicitly states that VS Code currently defines no built-in canvases such as Terminal, links this issue as the tracking location, and leaves Copilot App compatibility undecided. This supports a missing-capability classification rather than a regression in an existing VS Code terminal canvas.
- **Current source:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts implements listCanvases through the runtime's rpc.canvas.list and openCanvas through rpc.canvas.open(request). src/vs/workbench/contrib/canvases/common/canvas.ts describes extension-contributed canvas definitions, and canvasDefinitionStore.ts lists openable extension definitions. Searches across src and extensions found no send_terminal_input implementation or terminal canvasId registration.
- **Existing capability does not satisfy the contract:** The Canvas enablement setting is registered in src/vs/platform/agentHost/common/agentHostStarter.config.contribution.ts, and ordinary terminal creation commands are registered in src/vs/workbench/contrib/terminal/browser/terminalActions.ts. Neither supplies the missing canvasId "terminal" and provider action contract used by the reported calls.
- **Workarounds and remaining need:** https://github.com/microsoft/foundry-dev-tools/issues/861#issuecomment-6337576007 identifies two consumers: azd authentication and local agent startup. Foundry can use session.rpc.shell.exec for authentication and a copyable command for local startup, but the latter introduces a manual step and does not provide the requested interactive terminal integration.
- **Related item is not a duplicate target:** https://github.com/microsoft/foundry-dev-tools/issues/861 tracks Foundry's VS Code support and its plugin-side adaptations; its discussion explicitly delegates the absent host Terminal canvas capability to https://github.com/microsoft/vscode/issues/343414. Closing this issue against that external item would lose the VS Code-owned capability decision.
