# Issue #242494 — VSCode does not retrieve SSH passphrase from kwallet/ksshaskpass

[https://github.com/microsoft/vscode/issues/242494](https://github.com/microsoft/vscode/issues/242494)

## Summary

The built-in Git authentication path still replaces the configured KDE askpass helper and prompts without consulting KWallet. Keep this accepted bug open: the confirmed workaround bypasses that path, and the related older issue's diagnosed shell-environment problem does not establish a duplicate.

## Change summary

Git operations from the VS Code GUI repeatedly request an SSH key passphrase instead of using the configured ksshaskpass/KWallet integration.

## Best solution

Make GUI Git authentication cooperate with the user's configured SSH passphrase provider while preserving integrated authentication for users without one. The Git owner should settle whether an explicit external helper takes precedence or the integrated flow interoperates with it.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `extensions/git/src/main.ts`, `extensions/git/src/git.ts`, `extensions/git/package.json`, `extensions/git/package.nls.json`
- **Validation:** On KDE with an encrypted SSH key, an available agent that has not loaded the key, SSH_ASKPASS=ksshaskpass, SSH_ASKPASS_REQUIRE=prefer, and both reported Git settings enabled, compare terminal and GUI pulls. Verify that GUI pulls use the saved wallet passphrase without repeated prompts, including after restarting the desktop session; also check an initially empty wallet and the existing integrated prompt when no external helper is configured.
- **Behavior:**

  > A KDE user has configured ksshaskpass to retrieve an encrypted SSH key's passphrase from KWallet. Terminal Git uses that configuration, but GUI Git repeatedly asks for the passphrase despite the wallet already holding it. The finished behavior should let GUI Git benefit from the configured provider without requiring ssh-add on every boot or disabling integrated authentication entirely. Acceptance must cover saved and initially absent wallet entries, repeated GUI operations, session restart, and users without an external helper.
- **Trace:**

  > Askpass in extensions/git/src/askpass.ts constructs SSH_ASKPASS and SSH_ASKPASS_REQUIRE overrides; getEnv() exports them whenever git.useIntegratedAskPass is enabled. Activation in extensions/git/src/main.ts passes that environment into Git, whose spawn() in extensions/git/src/git.ts overlays it on process.env. handleSSHAskpass() returns an input-box result without consulting ksshaskpass or using the HTTPS credential cache, while getTerminalEnv() does not export the SSH overrides. This conclusively explains the reported GUI-versus-terminal distinction without executing KDE. Preserve existing HTTPS credentials-provider behavior and SSH host-authenticity confirmation; do not turn this into an SSH-agent startup change or unspecified passphrase persistence. The related https://github.com/microsoft/vscode/issues/57488 contains matching workaround reports but a different maintainer-diagnosed environment-loading failure. Uncertainty begins at the product contract for an explicitly configured external SSH helper when integrated authentication remains enabled.
- **Open decisions:**
  - With git.useIntegratedAskPass enabled and an explicit external SSH_ASKPASS configured, should GUI Git use that external provider directly, including its native prompt, or retain VS Code's prompt while interoperating with the external provider?

## Evidence

- **Confirmed report and workaround:** In https://github.com/microsoft/vscode/issues/242494, the reporter confirms both authentication settings are enabled, terminal Git retrieves the passphrase through ksshaskpass, and GUI Git prompts on every operation. Their July 9 reply confirms that disabling git.useIntegratedAskPass and configuring the external helper resolves the symptom, while explicitly requesting a fix to the built-in flow.
- **Current source explains helper replacement:** extensions/git/src/askpass.ts:46–48 sets SSH_ASKPASS to VS Code's script and SSH_ASKPASS_REQUIRE to force. Askpass.getEnv() at lines 161–163 supplies those overrides when git.useIntegratedAskPass is enabled. extensions/git/src/main.ts:82–93 passes them into Git, and Git.spawn() in extensions/git/src/git.ts:695 merges this.env after process.env, replacing the reporter's ksshaskpass/prefer values.
- **Repeated prompt path:** Askpass.handleSSHAskpass() in extensions/git/src/askpass.ts directly returns window.showInputBox() for a passphrase request, without invoking the inherited external helper or retaining the passphrase. The credential cache in the same file belongs to handleAskpass(), the HTTPS path. getTerminalEnv() exports the HTTPS environment but not sshEnv, explaining why terminal Git can retain the external SSH helper while GUI Git does not.
- **Existing setting is a bypass, not integrated coverage:** extensions/git/package.json:3957–3960 registers git.useIntegratedAskPass with default true. Setting it false makes Askpass.getEnv() return an empty object, preserving inherited authentication variables; it does not make integrated askpass retrieve a passphrase from KWallet.
- **Older related issue checked:** https://github.com/microsoft/vscode/issues/57488 is open and was created in 2018. Its discussion includes the same KDE workaround at https://github.com/microsoft/vscode/issues/57488#issuecomment-1413903793 and repeated-prompt confirmation at https://github.com/microsoft/vscode/issues/57488#issuecomment-2072932511. However, the maintainer diagnosis at https://github.com/microsoft/vscode/issues/57488#issuecomment-417259290 concerns launching Code without loading shell environment variables and consequently missing SSH-agent configuration. Here ssh-add already makes GUI Git work, and the source identifies explicit helper replacement. The shared workaround alone does not prove that the older issue owns this distinct remaining behavior.
- **Disposition and inspection limits:** The issue is already labeled bug and git and accepted into Backlog; neither the configuration suggestion nor the workaround establishes a maintainer decision to decline it. Inspection was read-only, with no KDE execution. The checkout is shallow and exposes only its boundary commit for askpass history, so no fixing commit was established.
