# Issue #324416 — UX defect - too easy to close terminal window when maximizing

[https://github.com/microsoft/vscode/issues/324416](https://github.com/microsoft/vscode/issues/324416)

## Summary

Keep open as terminal-toolbar polish: accidental activation of a neighboring destructive action is a legitimate interaction-design concern, not evidence that the maximize command malfunctions. Existing confirmation options only partially mitigate the risk, and no verified canonical or fixing commit was identified.

## Change summary

Make maximizing the terminal panel less prone to accidental terminal termination.

## Best solution

Evaluate the separation and presentation of terminal termination versus panel layout controls while retaining consistent workbench interactions. Distinguish the destructive trash action from Hide Panel, which preserves the terminal, before settling the design.

## Evidence

- **Reported interaction:** https://github.com/microsoft/vscode/issues/324416 describes accidentally closing a terminal while aiming for maximize on macOS with VS Code 1.127.0. There are no comments confirming a command-dispatch defect or specifying a preferred redesign.
- **Separate destructive and layout actions:** src/vs/workbench/contrib/terminal/browser/terminalMenus.ts:475-498 registers Split and Kill as neighboring terminal title actions, with Kill using the trash icon. src/vs/workbench/contrib/terminal/browser/terminalActions.ts:1266-1282 routes Kill through TerminalService.safeDisposeTerminal. This is explicit termination behavior, not maximize invoking the wrong command.
- **Hide is not termination:** src/vs/workbench/browser/parts/panel/panelActions.ts:74-81 registers Hide Panel at navigation order 2; the maximize action at lines 277-317 uses order 1. TogglePanelAction.run only changes panel visibility via setPartHidden, so the adjacent X control does not itself dispose terminal sessions.
- **Existing capability is partial:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:412-422 exposes terminal.integrated.confirmOnKill with panel and always options, defaulting to editor. src/vs/workbench/contrib/terminal/browser/terminalService.ts:430-443 confirms panel termination only when hasChildProcesses is true. This can protect running child processes but neither separates the controls nor protects every terminal session. workbench.action.toggleMaximizedPanel also provides a command-based alternative, not a correction to pointer targeting.
- **Related precedent does not cover the full request:** https://github.com/microsoft/vscode/issues/210216 is closed and concerned minimum target dimensions for maximize, split, and kill. Its maintainer response at https://github.com/microsoft/vscode/issues/210216#issuecomment-2052258719 recommends zooming and refers to https://github.com/microsoft/vscode/issues/209934. Neither is an open duplicate target, and the target-size decision does not establish that accidental destructive-action adjacency should be declined.
