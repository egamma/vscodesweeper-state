# Issue #275036 — Applying inline chat V2 styles to terminal

[https://github.com/microsoft/vscode/issues/275036](https://github.com/microsoft/vscode/issues/275036)

## Summary

Keep open: terminal inline chat still has a distinct presentation and does not receive the editor's V2-specific styles. The existing area label is appropriate; related layout reports and the declined lightweight-terminal exploration do not cover this consistency request.

## Change summary

Align terminal inline chat's visual presentation with the newer editor and notebook inline chat experiences.

## Best solution

Give equivalent inline-chat controls a consistent visual hierarchy, input treatment, and progress presentation while retaining terminal-specific command responses and actions. Agree which terminal-specific differences are intentional before implementing the visual alignment.

Confirm the agreed visual treatments match, then verify terminal Run Command, Insert Command, cancellation, keyboard focus, and resizing still work.
- **Behavior:**

  > Equivalent inline-chat controls should present a consistent hierarchy, input treatment, and progress feedback across editor, notebook, and terminal experiences. Terminal-specific differences should be intentional rather than inherited styling drift. Preserve terminal response text, command execution and insertion, cancellation, and keyboard accessibility. Acceptance requires comparing the agreed states across themes and confirming terminal actions and viewport layout remain usable.
- **Trace:**

  > TerminalChatWidget in src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatWidget.ts creates a terminal-inline-chat container and a TerminalInlineChatWidget derived from the shared InlineChatWidget. Its terminalChatWidget.css supplies separate borders, input spacing, background overrides, and busy-frame animation. Editor InlineChatController adds inline-chat-2, whose newer presentation rules in inlineChat.css are restricted to an editor zone-widget selector. Shared widget reuse therefore does not apply those V2-specific rules to terminal chat. The originating test plan at https://github.com/microsoft/vscode/issues/274768 also changes editor interaction semantics, which are outside this visual-alignment request. The later exploration at https://github.com/microsoft/vscode/issues/282481 was declined for now and should not be treated as approval to replace the terminal experience. The remaining uncertainty is the desired terminal visual treatment, not whether terminal chat should lose its responses or command actions.
- **Open decisions:**
  - Should terminal inline chat adopt the editor V2 input and progress presentation wholesale, or retain a terminal-specific frame and progress treatment as an intentional exception?
