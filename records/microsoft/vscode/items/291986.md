# Issue #291986 — GitHub Copilot imported chat is not kept

[https://github.com/microsoft/vscode/issues/291986](https://github.com/microsoft/vscode/issues/291986)

## Summary

The defect remains source-reproducible on current main: imported data is marked transient and explicitly excluded from persistence and session history. Keep the issue open while the directly linked fixing PR is reviewed and landed.

## Change summary

Importing a chat opens it temporarily but does not persist it or add it to Sessions, so closing the editor makes the imported conversation inaccessible.

## Best solution

Review, update, and land https://github.com/microsoft/vscode/pull/331738 so sanitized imported data receives a fresh local session identity and is persisted like a normal chat. The rebased implementation should preserve the current import trust-stripping and URI-validation behavior in `parseChatImport`.

## Evidence

- **current import path:** `src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts` passes the export-only result of `parseChatImport` directly to `loadSessionFromData` or `ChatEditorInput`, without assigning a persistent session ID or creation date.
- **source-confirmed root cause:** `src/vs/workbench/contrib/chat/common/model/chatModel.ts` sets `isImported` when initial data is exportable but not full serializable session data. `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` then excludes `isImported` sessions in both `shouldStoreSession` and `shouldBeInHistory`, matching the reported disappearance from Sessions and loss after closing the editor.
- **independent confirmations:** Two commenters confirmed the same observable behavior, including imports into the same folder and continued conversations still failing to enter the session list; `/fork` was identified only as an indirect workaround.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/331738 is open, uses `Fixes #291986`, and changes imported export data into full serializable chat data with a fresh session identity. It is currently unmerged and requires review/rebase, so the issue must remain open.
- **related satellite:** https://github.com/microsoft/vscode/issues/330491 reproduced the same imported-chat lifetime defect when moving the editor into the sidebar and was closed as a duplicate of this issue, supporting this issue as the canonical report.
