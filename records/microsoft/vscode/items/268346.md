# Issue #268346 — Kernel disposed because Notebook was closed or Cell was Deleted, when in fact notebook wasn't closed and cell wasn't deleted

[https://github.com/microsoft/vscode/issues/268346](https://github.com/microsoft/vscode/issues/268346)

## Summary

Confirmed by multiple users (Azure ML remote compute, WSL) that notebook kernels are disposed erroneously when the .ipynb file is externally modified or autosaved. Initially blamed on the Continue extension but later confirmed without it. Investigation stalled in July 2024 with no fix found in VS Code core or the Jupyter extension.

## Change summary

Notebook kernels are disposed unexpectedly (cells flagged as deleted, kernel shut down) when the .ipynb file is modified externally or by autosave on remote compute instances.

## Best solution

The root cause likely spans VS Code's notebook document reload-on-file-change logic (the model interprets an unchanged save as a document change, causing cells to appear deleted to the Jupyter extension). The fix in https://github.com/microsoft/vscode/issues/230017 ('Don't reload notebook model if data didn't change') may have addressed part of this. A maintainer should verify whether the Azure ML / WSL reproduction path still triggers on current builds and coordinate with the Jupyter extension team on the kernel disposal logic.
