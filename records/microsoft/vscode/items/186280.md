# Issue #186280 — Sharing links - improve discovery

[https://github.com/microsoft/vscode/issues/186280](https://github.com/microsoft/vscode/issues/186280)

## Summary

Keep open: line-sharing commands exist, but the inspected source does not provide the contextual discovery affordance requested here. This team-authored Backlog item has an acknowledged exploration direction, with no verified fix or canonical duplicate.

## Change summary

Make creating a shareable link to an editor line or selection discoverable without knowing to right-click the gutter.

## Best solution

Choose a lightweight, accessible contextual affordance for line sharing, then connect it to the existing sharing behavior. Preserve link generation and repository eligibility rather than redesigning those flows.

- **Behavior:**

  > Users can discover how to share an editor line or selection without prior knowledge of the gutter context menu. Existing line-link creation already works; the goal is a contextual entry point, not new URL semantics. Acceptance should cover discovery, keyboard and screen-reader access, correct line or range targeting, and eligibility for GitHub and Azure Repos. The exact affordance and when it appears require a maintainer decision.
- **Trace:**

  > extensions/github/package.json contributes github.copyVscodeDevLink to editor/lineNumber/context and editor/context/share, but excludes it from the command palette. registerCommands in extensions/github/src/commands.ts delegates to copyVscodeDevLink; extensions/github/src/links.ts resolves gutter line context or the active selection through getFileAndPosition and getRangeOrSelection. ShareWorkbenchContribution in src/vs/workbench/contrib/share/browser/share.contribution.ts offers a separate command-center action behind a default-off experimental setting and passes selection to ShareService. The inspected paths establish existing functionality but no contextual selection widget for discovering it. Azure Repos provider implementation was not traced in this checkout, so cross-provider availability must be established during planning. Preserve existing URL generation, publication prompts, eligibility, and context-menu behavior; post-copy dialog consistency is separate work in https://github.com/microsoft/vscode/issues/186312. The original cross-provider scenarios are documented in https://github.com/microsoft/vscode/issues/186199.
- **Open decisions:**
  - Should line-sharing discovery use a gutter affordance, a selection-adjacent action widget, or another existing editor surface?
  - Should the affordance appear only for whole-line selections, for any nonempty selection, or when interacting with an eligible line?
