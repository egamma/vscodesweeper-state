# Issue #335330 — Agent cannot access files within folder when using remote ssh

[https://github.com/microsoft/vscode/issues/335330](https://github.com/microsoft/vscode/issues/335330)

## Summary

Same root cause as the open, maintainer-assigned issue #334409: the agent's external-file check compares the workspace-opened path against the realpath()-resolved path, and a symlinked/bind-mounted/NFS-mounted workspace root produces a mismatch that wrongly flags in-workspace files as external.

## Change summary

Over Remote-SSH with an NFS-mounted workspace, the Copilot agent asks for external-file permission on files that are actually inside the opened folder, because the resolved (real) path differs from the folder path used to open the workspace.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/334409, which already tracks the same symlink/bind-mount/NFS path-containment mismatch in isFileExternalAndNeedsConfirmation / resolveRealPathForNonexistent (extensions/copilot/src/extension/tools/node/toolUtils.ts) and is assigned to a maintainer; this NFS report adds a concrete second environment confirming the same defect.
