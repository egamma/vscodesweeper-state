# Issue #335330 — Agent cannot access files within folder when using remote ssh

[https://github.com/microsoft/vscode/issues/335330](https://github.com/microsoft/vscode/issues/335330)

## Summary

Real, unrouted bug: on Remote-SSH against an NFS-mounted workspace, the agent's permission check resolves a file's symlink real path and finds it doesn't match the workspace root's representation, so ordinary in-workspace files are treated as external and repeatedly re-prompt for confirmation. Traced the exact mechanism in sessionPermissions.ts; keeping open and routing to the right area rather than closing given only a `triage-needed` label so far.

## Change summary

Opening a folder over Remote-SSH on an NFS mount causes the coding agent to ask for external-file permission on files that are actually inside the opened workspace, because the symlink-resolved real path diverges from the workspace root path.

## Best solution

Have the Remote-SSH/agentHost owners review `SessionPermissionManager._resolveResourcesForApproval` / `_isReadContainedByRoot` in src/vs/platform/agentHost/node/sessionPermissions.ts for the NFS/automounter case where a file's `fs.realpath` and the working directory's `fs.realpath` disagree even though both live under the same opened folder; this looks like the same underlying symlink-resolution defect as https://github.com/microsoft/vscode/issues/334409, which a maintainer should confirm and consolidate if so.

## Evidence

- **permission check code:** src/vs/platform/agentHost/node/sessionPermissions.ts: `_isReadContainedByRoot`/`_isEditAutoApproved` resolve both the target and the working directory through `_resolveResourcesForApproval` (which calls `fs.realpath` via `resolveRealPathForNonexistent`), then require every resolved candidate to be contained by some resolved working directory (lines ~527-676). This 'fail-closed on symlink escape' design is exactly what would misfire when NFS/automounter realpath resolution of the workspace root and of a file within it diverge, even though both are under the same opened folder.
