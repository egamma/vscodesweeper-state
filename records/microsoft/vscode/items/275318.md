# Issue #275318 — Timeline does not track renames

[https://github.com/microsoft/vscode/issues/275318](https://github.com/microsoft/vscode/issues/275318)

## Summary

The failure to open pre-rename Git Timeline entries is already tracked by the verified, older open issue https://github.com/microsoft/vscode/issues/205244. Consolidate there, preserving this report's confirmed macOS reproduction and historical-path diagnostic.

## Change summary

Opening a Git Timeline entry from before a file rename or move uses the current path instead of the historical path and fails to retrieve the file.

## Best solution

Resolve historical file paths for Git Timeline comparisons under https://github.com/microsoft/vscode/issues/205244 so entries before renames and moves open correctly. Carry this report's reproduction details into that canonical discussion.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/205244 was verified OPEN through GitHub and was created on 2024-02-14, before this issue's 2025-11-04 creation. Its reproduction commits a file, renames it, and clicks a pre-rename Timeline entry; the body explicitly identifies git show using the new filename instead of the historical filename.
- **Same observable failure, not merely the same area:** https://github.com/microsoft/vscode/issues/205244#issuecomment-3033080268 diagnoses Timeline comparisons constructing both revision URIs with one current file path and explicitly describes VS Code being unable to open the file at that wrong path. This matches the historical-entry opening failure reported here, satisfying the stronger duplicate bar for a re-reviewed item.
- **Current source confirms the remaining defect:** extensions/git/src/timelineProvider.ts, GitTimelineProvider.provideTimeline, requests logFile with follow: true but passes the unchanged current uri to resolveTimelineOpenDiffCommand for each historical commit. extensions/git/src/commands.ts:4804-4825 constructs vscode.diff arguments with toGitUri(uri, item.previousRef) and toGitUri(uri, item.ref), retaining the same path for both revisions. A pre-move commit lacking that current path therefore cannot provide the historical file. Source inspection only; no code was executed.
- **Confirmed reproduction to preserve:** The 2026-07-16 comment on https://github.com/microsoft/vscode/issues/275318 confirms the failure on VS Code 1.129.0, macOS Apple Silicon, and Git 2.53.0: commit a file, move or rename it and commit, then click an earlier Timeline entry. Logs show a nonexistent git URI using the current path, while git show with the historical path succeeds.
- **Discussion and scope:** The 2026-08-23 comment on https://github.com/microsoft/vscode/issues/275318 explicitly links the canonical. The separately mentioned https://github.com/microsoft/vscode/issues/236857 was also read and describes the same pre-rename Timeline retrieval problem, but the older verified canonical is https://github.com/microsoft/vscode/issues/205244. Suggestions about preserving local history through external or cross-workspace moves are additional discussion, not evidence of a distinct cause for the reported Git historical-path failure.
