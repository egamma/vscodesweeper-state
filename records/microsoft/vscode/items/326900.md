# Issue #326900 — Frequently claims it's in Plan mode when it's actually in Agents mode

[https://github.com/microsoft/vscode/issues/326900](https://github.com/microsoft/vscode/issues/326900)

## Summary

Corroborated by a second reporter (different GPT versions), so this isn't a one-off — but it's a stateful mode-switch/session-desync issue that can't be conclusively traced from source alone; routing to the chat-plan-agent area rather than closing.

## Change summary

The model's internal sense of its role gets stuck referring to the Plan sub-agent after a mode switch, even though the VS Code UI shows Agent mode, and toggling modes doesn't clear it (requires a new session).

## Best solution

Owned by the Plan/Agent handoff path in extensions/copilot/src/extension/tools/vscode-node/switchAgentTool.ts and extensions/copilot/src/extension/agents/vscode-node/planAgentProvider.ts — investigate whether the session/context passed to the model after workbench.action.chat.toggleAgentMode still carries stale Plan-agent framing, causing the model to believe it's still in Plan even though the UI mode changed.
