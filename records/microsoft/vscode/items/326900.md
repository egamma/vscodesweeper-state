# Issue #326900 — Frequently claims it's in Plan mode when it's actually in Agents mode

[https://github.com/microsoft/vscode/issues/326900](https://github.com/microsoft/vscode/issues/326900)

## Summary

Multiple independent reporters (3 users, including with different GPT models) describe the agent backend getting stuck reporting it's in the 'Plan' sub-agent state while the UI mode selector still shows Agent mode, requiring a brand-new session to recover — this looks like a real state-desync bug in the agent orchestration/mode-tracking layer, but I can't pin it to a specific line in this static-source-only checkout since it's driven by internal conversation/session state, not a simple rendering bug.

## Change summary

When Plan mode is invoked as a sub-agent internally, the backend's notion of the active mode gets stuck reporting 'Plan' even though the UI's mode selector still shows Agent mode, and switching modes in the UI doesn't clear the stuck state — only starting a brand-new session does.

## Best solution

Needs an owner on the chat/agents-window or chat-plan-agent side to trace how the internal mode/role state is set when Plan is invoked as a sub-agent, and ensure it's reset/synced when the UI mode selector changes or after Plan sub-agent completion, so a session doesn't get permanently stuck misreporting its own mode.
