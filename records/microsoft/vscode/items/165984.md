# Issue #165984 — vscode.dev: webviews key shortcuts doesn't work as expected

[https://github.com/microsoft/vscode/issues/165984](https://github.com/microsoft/vscode/issues/165984)

## Summary

Keep open: current webview keyboard forwarding includes browser-default suppression, but its close-tab check still excludes Ctrl+F4. The supplied Release Notes steps suffice to retest; source inspection cannot establish whether the browser permits intercepting this shortcut.

## Change summary

Pressing Ctrl+F4 while a vscode.dev webview is focused closes the browser tab instead of the active editor.

## Best solution

Establish whether Ctrl+F4 can be intercepted in supported browser and installed-app contexts, comparing a focused Release Notes webview with a normal editor. Where interception is supported, webview focus should preserve the normal close-editor behavior; browser-reserved combinations should be distinguished from a VS Code forwarding defect.

- **Behavior:**

  > The reporter opens Release Notes on vscode.dev and presses Ctrl+F4, expecting the editor to close but observing the entire browser tab close instead. Compare this with the same shortcut in a normal text editor on the same browser and OS. Where the browser supports interception, focusing webview content must not change close-editor behavior into closing the IDE page. Browser-reserved shortcuts must be identified separately rather than treated as confirmed forwarding defects.
- **Trace:**

  > editorCommands.ts registers Ctrl+F4 for workbench.action.closeActiveEditor on Windows. In webview/browser/pre/index.html, handleInnerKeydown cancels selected browser actions and then asynchronously forwards the event; isCloseTab recognizes Ctrl/Meta+W but excludes Ctrl+F4. WebviewElement.handleKeyEvent redispatches a synthetic event in the host window after trust and focus checks, which does not cancel the original iframe event. This identifies a potential cancellation gap, but browser-specific delivery and cancelability remain unverified. Preserve trust checks, normal text input, unrelated shortcuts, and desktop behavior. https://github.com/microsoft/vscode/issues/139163 documents the browser API limitation, while https://github.com/microsoft/vscode/issues/148545 addresses a different save-shortcut case.
