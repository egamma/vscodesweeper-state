# Issue #278312 — file order in explore in very strange orders

[https://github.com/microsoft/vscode/issues/278312](https://github.com/microsoft/vscode/issues/278312)

## Summary

Verified duplicate: the screenshot shows VS Code's numeric filename collation rather than an unsorted list, and the request for lexicographic/platform-style Explorer ordering is already tracked by the older open canonical issue.

## Change summary

Make hash-like filenames in the Explorer appear in strict lexicographic order instead of the default natural numeric order.

## Best solution

Consolidate the sorting semantics discussion in https://github.com/microsoft/vscode/issues/27759. Users needing strict Unicode ordering today can set `explorer.sortOrderLexicographicOptions` to `unicode`.

## Evidence

- **observed ordering:** The issue screenshot places names such as `0a5...` before `0a176...` and `0e8...` before `0e766...`, which is consistent with natural numeric comparison of digit runs rather than random or partially unsorted output.
- **current code:** `FileSorter.compare` in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` selects `compareFileNamesDefault` for the default mode; `src/vs/base/common/comparers.ts` implements that comparator with a numeric `Intl.Collator`.
- **existing alternative:** `src/vs/workbench/contrib/files/browser/files.contribution.ts` registers `explorer.sortOrderLexicographicOptions`, including `unicode`; `compareFileNamesUnicode` performs direct string ordering and therefore covers strict lexicographic ordering.
- **canonical issue:** https://github.com/microsoft/vscode/issues/27759 is open, predates this report, and broadly tracks Explorer sorting semantics. Its discussion explicitly includes the same numeric-versus-lexicographic symptom (`log-2`, `log-10`) and the Unicode-order option.
