# Issue #336698 — Copilot agent chat should not show feedback (chat transcript upload) buttons when telemetry off or using BYOK

[https://github.com/microsoft/vscode/issues/336698](https://github.com/microsoft/vscode/issues/336698)

## Summary

This describes a possible data-exposure concern, so it stays open per the hard security-sensitive keep-open rule regardless of my own findings. Source tracing shows the vote telemetry event itself never carries transcript content and is gated by `telemetryService.publicLog2`, which already no-ops when `telemetry.telemetryLevel` is off — so no chat data is actually uploaded in that state. The real, narrower bug is that the Helpful/Unhelpful buttons' visibility is gated only by the independent `telemetry.feedback.enabled` setting (default true), not by `telemetry.telemetryLevel` or by whether the active model is BYOK, so the controls stay visible (though functionally inert re: telemetry) in configurations where a user would expect them hidden.

## Change summary

Hide the chat 'Helpful'/'Unhelpful' feedback buttons when telemetry is off or the active model is a non-Microsoft BYOK provider.

## Best solution

Tighten the `when` clauses in src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts (MarkHelpfulAction/MarkUnhelpfulAction, and the issue-reporting action) so they also require `telemetry.telemetryLevel` to be at least USAGE, and add a context key reflecting whether the current chat model is a non-Copilot/BYOK vendor to also hide the buttons there; a maintainer should also confirm in the comment that no transcript data is sent today because publicLog2 already checks telemetry level.

- **Behavior:**

  > When `telemetry.telemetryLevel` is 'off', and/or when the active chat model is a non-Microsoft BYOK provider, the Helpful/Unhelpful (and issue-reporting) buttons on chat responses should not be shown, so the UI doesn't offer a feedback affordance the user has opted out of. Existing behavior when `telemetry.feedback.enabled` is true and telemetry is on should be unchanged. Acceptance: a test confirms the actions are hidden in the off/BYOK cases and still shown otherwise.
- **Trace:**

  > The buttons are registered in src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts and gated only by `ContextKeyExpr.has('config.telemetry.feedback.enabled')` (lines 48/53/93/98/138/143) — a setting fully independent from `telemetry.telemetryLevel` (src/vs/platform/telemetry/common/telemetryService.ts:330-375). Note for the maintainer/agent: no transcript is currently sent by these actions regardless of visibility — the vote event (chatServiceTelemetry.ts:237-243) carries no chat content, and TelemetryService already suppresses all publicLog2 sends when telemetryLevel is off (telemetryService.ts:213-217, telemetryUtils.ts:138-157) — so the fix is a UI-affordance correctness fix, not a data-leak fix; don't change the telemetry pipeline itself. The boundary: don't touch the vote event payload or the telemetry gating logic, only the `when` conditions controlling button visibility (and, for BYOK, add a narrowly-scoped context key reflecting the active model's vendor).
- **Open decisions:**
  - Should visibility require telemetryLevel >= USAGE outright, or only suppress when it's explicitly 'off'?
  - How should 'active model is BYOK' be exposed as a context key — per active chat widget/session or globally — and does it also need to affect other feedback-adjacent actions (issue reporting, survey prompts)?
  - Should this apply uniformly across all ChatMessageFooter/MENU_INLINE_CHAT_WIDGET_SECONDARY contributions or just the vote buttons named in the report?

## Evidence

- **vote gating today:** src/vs/workbench/contrib/chat/browser/actions/chatTitleActions.ts:32 defines `enableFeedbackConfig = 'config.telemetry.feedback.enabled'`, used in the button `when` clauses (lines 48, 53, 93, 98, 138, 143) — there is no reference to `telemetry.telemetryLevel` or any BYOK/model-vendor context key.
- **independent settings:** `telemetry.feedback.enabled` is a separate config (src/vs/platform/telemetry/common/telemetryService.ts:365-375, default true) from `telemetry.telemetryLevel` (line 330); setting telemetryLevel to off does not flip feedback.enabled, and relauncher.contribution.ts:70 lists them as unrelated watched settings.
- **no transcript in the event / telemetry level enforced server-side:** The vote handler (chatServiceTelemetry.ts:237-243) sends only `direction`, `agentId`, `command` via `publicLog2` — no transcript/code content — and TelemetryService._log (telemetryService.ts:213-217) drops any event when `this._telemetryLevel < eventLevel`, which is TelemetryLevel.NONE when telemetryLevel is 'off' (telemetryUtils.ts:138-157). So with telemetry off, clicking these buttons today sends nothing.
- **no BYOK context key:** src/vs/workbench/contrib/chat/common/actions/chatContextKeys.ts only has `chatNonCopilotModelsAreUserSelectable` (availability of BYOK models), not an 'active model is BYOK' key needed to gate visibility per active session.
