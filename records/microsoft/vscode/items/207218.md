# Issue #207218 — Release notes - clicking on a setting link open setting as a new tab in current editor group

[https://github.com/microsoft/vscode/issues/207218](https://github.com/microsoft/vscode/issues/207218)

## Summary

Still reproduces on main: the `openSettings2` method in `preferencesService.ts` opens the settings editor into `ACTIVE_GROUP` without `revealIfOpened`, so clicking a setting link from release notes in a different editor group opens a duplicate settings tab instead of revealing the existing one.

## Change summary

Clicking a settings link in release notes opens a new settings tab in the release notes' editor group instead of revealing an already-open settings editor in another group.

## Best solution

Add `revealIfOpened: true` to the editor options in `openSettings2` (or pass it through `validateSettingsEditorOptions`) so that the editor service reveals an existing settings editor across all groups rather than opening a duplicate. The keybindings editor already uses this pattern at line 343 of the same file.
