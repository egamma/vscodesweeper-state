# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are compared without unwrapping their agent-host URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Keep open: the original list-payload namespace mismatch has been addressed, but the discussion identifies a remaining session-creation path that still drops remote workspace folders on current main. That leaves sessions without roots for the workspace filter to match.

## Change summary

Ensure agent sessions belonging to a remote workspace appear in that window's sessions list.

## Best solution

Preserve the connected remote workspace's working directories through handler-driven session creation so those sessions remain discoverable by workspace containment. Retain authority-aware matching and the existing exclusion of unsupported or unrelated locations.
