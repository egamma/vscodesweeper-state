# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are reported as the remote local file: URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Well-diagnosed correctness bug in remote-window session-list filtering, with an open fix PR already in review — keep open and let that PR land rather than proposing a close or auto-fix.

## Change summary

In a remote/dev-container window, agent sessions whose working directory is reported as a `file:` URI are silently filtered out of the sessions list because `_matchesAnyFolder`/`isEqualOrParent` gate on scheme before comparing paths, so they never match the window's `vscode-remote:` folder URI.

## Best solution

Review and land PR https://github.com/microsoft/vscode/pull/331349, which reinterprets a `file:` working directory in the folder's namespace before the containment check in `_matchesAnyFolder` (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionListStore.ts) — narrowly scoped to file→remote rewriting with an authority present, leaving local windows and cross-authority remotes untouched.
