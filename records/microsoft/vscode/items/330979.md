# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are compared without unwrapping their agent-host URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Real, well-diagnosed bug: agent-host session working directories arrive wrapped in `vscode-agent-host:` URIs that are never unwrapped before the scheme-gated containment check, so remote-window sessions are silently filtered out of the list. An open PR already targets this exact defect, so the right move is to land or review that PR rather than close the issue.

## Change summary

In a remote window, agent sessions vanish from the sessions list because their working directories are wrapped `vscode-agent-host:` URIs compared scheme-first against the window's `vscode-remote:` folder URI, so containment can never match.

## Best solution

Land https://github.com/microsoft/vscode/pull/331349, which unwraps the `vscode-agent-host:` URI (via `fromAgentHostUri`) before containment comparison in `_containmentCandidates`/`_matchesAnyFolder` in agentHostSessionListStore.ts; the reporter confirms this restores the missing sessions in a live dev-container window.
