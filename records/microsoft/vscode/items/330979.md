# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are compared without unwrapping their agent-host URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Well-diagnosed, reproducible bug in remote-window session listing; there is already an open fixing PR that references this issue, so per policy this stays open pending review/merge rather than being closed now.

## Change summary

In a remote/dev-container window, agent sessions are filtered out of the sessions list because working directories reported as `vscode-agent-host://` (or `file:`) URIs are never recognized as contained in the window's `vscode-remote:` workspace folder.

## Best solution

Land the fix in https://github.com/microsoft/vscode/pull/331349, which unwraps the agent-host-wrapped URI (`vscode-agent-host://...?_ah=...`) before the containment check in `_matchesAnyFolder`/`isEqualOrParent`, with a narrowed `file:` scheme-rewrite fallback retained only for hosts with no wrapper; close this issue once that PR merges.
