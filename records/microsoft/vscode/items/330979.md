# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are reported as the remote local file: URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Traced in current source: `_matchesAnyFolder` in agentHostSessionListStore.ts relies on `extUriBiasedIgnorePathCase.isEqualOrParent`, which short-circuits to false whenever schemes differ (resources.ts:171-176), so `file:` working directories never match a `vscode-remote:` workspace folder — exactly as reported.

## Change summary

In a remote/dev-container window, agent sessions whose working directory is reported as a `file:` URI are filtered out of the sessions list because the containment check requires matching URI schemes against the window's `vscode-remote:` folder.

## Best solution

Needs a maintainer design decision (as the author's own follow-up notes): either normalize working-directory URIs into the client's namespace before they reach the list store, or make the containment check remote/namespace-aware using real host identity — a naive 'lift into the window's remoteAuthority' shortcut would introduce false positives for a local window connected to a remote agent host. Belongs in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionListStore.ts and possibly the IAgentHostSessionListConnection surface.
