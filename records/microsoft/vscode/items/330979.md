# Issue #330979 — Sessions are filtered out of the list in a remote window: working directories are reported as the remote local file: URIs

[https://github.com/microsoft/vscode/issues/330979](https://github.com/microsoft/vscode/issues/330979)

## Summary

Traced conclusively in source: `_matchesAnyFolder` in agentHostSessionListStore.ts delegates to `extUriBiasedIgnorePathCase.isEqualOrParent`, which gates on URI scheme before comparing paths, so a `file:` working directory can never match a `vscode-remote:` workspace folder — exactly the reported false-negative filtering in dev container windows.

## Change summary

In a remote (dev container) window, agent sessions whose working directory is reported as a `file:` URI are filtered out of the sessions list because the containment check compares scheme before path, and the workspace folder is a `vscode-remote:` URI.

## Best solution

This needs a design decision by the agent-sessions/agent-host owners rather than a client-side patch: either normalize/tag working directories with host identity before they reach the list store (requires widening `IAgentHostSessionListConnection`, per the reporter's comment-1 analysis), or make `_isSessionInWorkspace`/`_matchesAnyFolder` namespace-aware. The reporter's own local patch attempt (comment 2) reportedly failed in a live remote window for reasons neither of us can explain from source alone, so this is not a safe candidate for an automatic fix — route to the agent-sessions area owners to reproduce in a real dev container and decide the right layer for the fix.
