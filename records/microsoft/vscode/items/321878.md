# Issue #321878 — Agents: Need a way to heal broken worktree paths

[https://github.com/microsoft/vscode/issues/321878](https://github.com/microsoft/vscode/issues/321878)

## Summary

Keep open: this team-authored feature request identifies a real recovery gap for sessions whose worktree moved, and neither an explicitly referencing fix nor a canonical duplicate was found. Current Agent Host code can change working directories, but its existing conversion flow deliberately accepts only workspace-less sessions.

## Change summary

Allow an active Agents Window session to reconnect to its worktree after the worktree's parent path has moved or been renamed.

## Best solution

Provide a recovery flow that lets the user select the relocated worktree, validates that it corresponds to the session's repository, and consistently updates the agent runtime and durable session metadata without losing chat history or changes.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/chatContributions/sessionWorkspaceConversion/sessionWorkspaceConversionService.ts`, `src/vs/platform/agentHost/common/agent.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/sessions/services/sessions/common/sessionsProvider.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/platform/agentHost/test/node/sessionWorkspaceConversion.test.ts`
- **Validation:** Add a focused Agent Host test that starts with a workspace-backed session whose persisted worktree path is missing, relocates it to a matching worktree path, and verifies that the runtime and restored session metadata use the new path while preserving session and chat identity.
- **Behavior:**

  > When an active session's recorded worktree path no longer exists, the Agents Window should offer a recovery path instead of leaving the session unusable. The user can identify the worktree's new location, and successful recovery preserves the existing session, conversation, and changes while subsequent turns run in the relocated worktree. Invalid or unrelated folders must be rejected without partially changing the session. The recovered location must survive an Agent Host and window restart.
- **Trace:**

  > The session workspace is provider-owned state projected through ISession. Agent Host providers already expose working-directory mutation through IAgent.setWorkingDirectory, with CopilotAgentSession.setWorkingDirectory coordinating SDK, runtime, and shell alignment. SessionWorkspaceConversionService provides trust checks and atomic metadata handling for workspace-less-to-workspace conversion, but _validateConversion explicitly excludes existing workspace-backed sessions, which is where this issue's scenario begins. The boundary is broader than changing an in-memory URI: repository/worktree identity, workspace trust, provider state, persisted session metadata, and restart restoration must remain consistent. The broader worktree UX umbrella at https://github.com/microsoft/vscode/issues/336620 does not replace this narrower recovery requirement.
- **Open decisions:**
  - Should recovery be offered only after a missing-path failure, or also as an explicit session action while the old path still exists?
  - What Git identity evidence must prove that the selected directory is the relocated worktree rather than an unrelated checkout?
  - Should the first implementation support only local Agent Host sessions, or define a provider-neutral relocation capability for every provider that can mutate its working directory?
  - Which persisted repository and worktree fields must change when the parent repository and its sibling worktree directory move together?
