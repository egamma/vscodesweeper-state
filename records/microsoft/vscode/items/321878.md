# Issue #321878 — Agents: Need a way to heal broken worktree paths

[https://github.com/microsoft/vscode/issues/321878](https://github.com/microsoft/vscode/issues/321878)

## Summary

Valid feature request from a team member for a way to heal broken worktree paths when a parent folder is renamed. Existing relocation logic in `baseAgentHostSessionsProvider.ts` handles agent-selection rebasing during worktree creation, but does not cover the scenario of an external rename breaking the worktree path after session creation. No fix references this issue.

## Change summary

Provide a mechanism to update a session's worktree path when the original path becomes invalid due to an external rename of a parent folder.

## Best solution

Add a user-facing action in the Agents window (e.g. a 'Relocate worktree' command or an error-state prompt) that lets the user point a session at its moved worktree directory. The implementation likely lives in `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts` and the sessions management layer. Commit `fd5d846c3fe` (agent relocation on worktree creation) and `55a44c4b4c3` (restore missing Copilot worktrees) are related prior art but don't cover the external-rename case.
