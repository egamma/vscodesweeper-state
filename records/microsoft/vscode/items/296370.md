# Issue #296370 — Session memory should persist when forking or sending to new chat

[https://github.com/microsoft/vscode/issues/296370](https://github.com/microsoft/vscode/issues/296370)

## Summary

Keep open: local conversation forks copy the transcript into a new session ID, but session-memory files remain scoped to the original ID; Send to New Chat likewise starts a new session without transferring those files. This team-authored, accepted request still has a concrete gap, and no qualifying fix or older canonical was established.

## Change summary

Preserve session-scoped memory when forking a conversation or using Send to New Chat.

## Best solution

Make the source session's memory available in the destination for both explicit continuation workflows, through a supported boundary between workbench session creation and Copilot memory storage. Preserve ordinary new-chat isolation and existing user/repository memory behavior.
