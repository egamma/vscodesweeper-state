# Issue #194020 — Better synonym support in TF-IDF similar commands

[https://github.com/microsoft/vscode/issues/194020](https://github.com/microsoft/vscode/issues/194020)

## Summary

Keep open: the TF-IDF command-search path still scores literal query terms without synonym expansion. Command descriptions improve vocabulary coverage, but do not fully deliver this team-authored Backlog request.

## Change summary

Improve Command Palette similar-command results by recognizing known synonyms in the user's query.

## Best solution

Provide predictable, local synonym recognition for TF-IDF command search without requiring an AI provider. Agree on the initial supported vocabulary and language scope, while preserving direct-match precedence and keeping unrelated commands out of the results.

Run the targeted tests and manually repeat the agreed queries in the Command Palette with provider-backed natural-language search disabled.
- **Behavior:**

  > Users should find relevant commands in the local similar-commands results when they search using supported synonyms absent from the command's indexed text. This must work without an AI provider. Acceptance should cover agreed synonym examples, unchanged direct-match precedence, and negative examples that prevent overly broad suggestions. The initial supported vocabulary and language coverage remain to be decided.
- **Trace:**

  > AbstractCommandsQuickAccessProvider._getPicks in src/vs/platform/quickinput/browser/commandsQuickAccess.ts indexes labels, aliases, and descriptions through getTfIdfChunk, then passes the original query to TfIdfCalculator.calculateScores. In src/vs/base/common/tfIdf.ts, splitTerms performs lexical normalization and computeSimilarityScore requires identical terms; the source contains no synonym expansion on this path. Provider-backed semantic suggestions are separate in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts and must not become a prerequisite for the local behavior. Preserve existing direct matches, command-ID matching, cancellation, and result ordering outside the intended similarity improvement; do not assume other consumers of the shared calculator should gain synonym semantics. src/vs/base/test/common/tfIdf.test.ts establishes existing literal-scoring behavior. https://github.com/microsoft/vscode/issues/194021 supplies the original synonym example, while https://github.com/microsoft/vscode/issues/209511 tracks complementary description enrichment rather than this capability.
- **Open decisions:**
  - Which synonym pairs and disambiguation examples define the initial supported command-search vocabulary?
  - Should initial synonym recognition support English terminology only, or also queries and command labels in localized UI languages?
