# Issue #214340 — `launch` setting UI is bugged for the workspace tab

[https://github.com/microsoft/vscode/issues/214340](https://github.com/microsoft/vscode/issues/214340)

## Summary

Still reproduces on main: the `launch` setting reads its workspace value from `.vscode/launch.json` via the configuration service, causing the settings UI to report it as 'modified' even when the user never set it in `settings.json`. The 'Reset Setting' action then creates spurious files. No fix has landed.

## Change summary

The settings editor incorrectly shows the `launch` setting as modified in the workspace tab when a `launch.json` exists, and resetting it creates a blank settings.json and boilerplate launch.json.

## Best solution

The settings tree model (`settingsTreeModels.ts`) needs special handling for the `launch` setting (and potentially `tasks`) in the workspace scope — either suppress the modified indicator when the value comes solely from `launch.json` (not `settings.json`), or disable the 'Reset' action for these implicit-file-backed settings. The `disallowConfigurationDefault` flag on the registration in `debug.contribution.ts` may provide the hook.
