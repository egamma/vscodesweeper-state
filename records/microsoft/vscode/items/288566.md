# Issue #288566 — Allow agent to push a terminal into the background

[https://github.com/microsoft/vscode/issues/288566](https://github.com/microsoft/vscode/issues/288566)

## Summary

Keep open: current terminal tools support automatic background promotion and a manual Continue in Background action, but do not expose the requested agent-controlled transition for an existing foreground execution. The issue already has the correct area label; the remaining work needs a decision about when control returns to the agent.

## Change summary

Let the agent move an already-started foreground terminal execution into the background without interrupting its process, then continue other work and retrieve its result later.

## Best solution

Provide an agent-accessible background transition that preserves the running process, output tracking, and completion notifications while preventing subsequent foreground commands from reusing that terminal. Resolve how the agent regains control from a blocking invocation before choosing the tool contract.

Verify the original process is not interrupted, the second command uses a separate execution, and the original output and completion remain available. Add targeted runInTerminalTool tests for those lifecycle invariants.
- **Behavior:**

  > An agent that started a command in foreground mode can subsequently choose to continue it in the background without killing or restarting it. The agent can perform other work while that execution continues and later obtain its output and completion result. A subsequent foreground command must not interrupt or reuse the backgrounded execution. Acceptance includes the reported Windows compile scenario and preservation of ordinary synchronous completion and manual backgrounding.
- **Trace:**

  > RunInTerminalTool in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts races synchronous execution against manual continuation, timeout, input-needed detection, and idle silence. Timeout and idle-silence promotion already preserve the process and remove its foreground association; input-needed returns leave the execution foreground. ActiveTerminalExecution has an internal setBackground method, but terminalToolIds.ts and terminal.chatAgentTools.contribution.ts expose no model-facing transition. The uncertainty is how the model obtains a decision opportunity while the original tool call is blocking, rather than the mechanics of setting background state. Preserve manual continuation, normal synchronous results, and existing background output/completion tracking. Related design context is https://github.com/microsoft/vscode/issues/274550; the merged final diff of https://github.com/microsoft/vscode/pull/305804 does not implement the requested transition.
- **Open decisions:**
  - Should agent-controlled backgrounding apply only after a foreground invocation has returned control, or should foreground calls yield after an initial wait so the agent can choose whether to keep waiting or background them?
