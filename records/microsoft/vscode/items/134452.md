# Issue #134452 — Support global evaluation that requires a file for context

[https://github.com/microsoft/vscode/issues/134452](https://github.com/microsoft/vscode/issues/134452)

## Summary

The standardized global-evaluation context remains missing from the Debug Console path. Maintainers supported passing the active source, and the existing extension workaround does not fulfill that agreement; retain this already-correctly-routed Backlog request.

## Change summary

Provide source-file context for Debug Console evaluation without a stopped stack frame, with possible future support for selecting an evaluation context.

## Best solution

Complete the agreed initial active-file context behavior using a DAP-compatible contract, while preserving adapter-selected thread inference. Treat arbitrary context or isolate selection as a separate design step rather than a prerequisite for the initial capability.

- **Validation:** Add a debug evaluation test capturing the outgoing evaluate request while a session is running without a stack frame and a source editor is active. Assert that the agreed source context reaches the adapter, frameId remains absent, context remains 'repl', and existing stopped-frame evaluation remains unchanged.
- **Behavior:**

  > A user evaluating an expression in the Debug Console while execution is running can supply the active file's context through a standardized request contract, without first stopping at a breakpoint. The adapter continues to determine the thread for the initial implementation. Acceptance checks should inspect the outgoing request for active-source context and verify that existing stopped-frame evaluation still behaves as before.
- **Trace:**

  > ReplModel.addReplExpression in src/vs/workbench/contrib/debug/common/replModel.ts calls evaluateExpression without a location. ExpressionContainer.evaluateExpression in debugModel.ts forwards that absence to DebugSession.evaluate, whose source field comes only from location?.source. EvaluateArguments already has a source field associated with contextual line/column, but the REPL does not populate it; determine its suitability for the agreed global-evaluation contract rather than assuming its existence solved the request. DebugAdapterTracker remains a working extension-specific escape hatch, not the requested interoperable behavior. The initial active-file scope and adapter-side thread inference were accepted at https://github.com/microsoft/vscode/issues/134452#issuecomment-1020422369; do not require a new context-picker UI to deliver that scope.
- **Open decisions:**
  - Should global evaluation use the existing DAP source field as the active-file context contract, or does that field's contextual-location meaning require a distinct standardized attribute?
