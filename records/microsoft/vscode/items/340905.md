# Issue #340905 — Git: Continue during rebase does nothing when the index matches HEAD and the worktree has other changes

[https://github.com/microsoft/vscode/issues/340905](https://github.com/microsoft/vscode/issues/340905)

## Summary

Thanks for the detailed report. The early silent return in smartCommit is still present on main and doesn't check for an in-progress rebase or merge, so Continue does nothing when the index is empty and the worktree is dirty.

## Change summary

Continue during a rebase silently does nothing when the index group is empty, the working tree has changes, and smart commit is off.

## Best solution

In smartCommit, skip the 'no staged changes' early return (and the smart-commit prompt) when repository.rebaseCommit or repository.mergeInProgress is set, so the flow reaches rebaseContinue() and shows git's result. Separately, make Accept All Incoming/Current warn on binary files; that part is tracked in https://github.com/microsoft/vscode/issues/248533.
