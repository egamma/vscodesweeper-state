# Issue #344328 — Agents window: dev container agent host doesn't receive the GitHub Enterprise endpoint (asks for api.github.com, 'Authentication is required to start a session')

[https://github.com/microsoft/vscode/issues/344328](https://github.com/microsoft/vscode/issues/344328)

## Summary

The missing enterprise-endpoint propagation remains visible in current source: the client forwards it through the local agent-host service, but not to separately connected container hosts. Keep this core Agent Host issue open; the report already supplies sufficient steps and comparative logs.

## Change summary

A freshly rebuilt dev-container agent host requests github.com authentication instead of using the client's selected GitHub Enterprise endpoint.

## Best solution

Ensure fresh VS Code-managed container hosts receive the selected enterprise endpoint early enough for their initial authentication to target GHE. Coordinate endpoint initialization with remote connection authentication without forwarding machine-specific local settings or weakening resource-to-credential matching.

- **Behavior:**

  > A fresh VS Code-managed dev-container agent host should use the selected GitHub Enterprise account's endpoint without requiring a previous container configuration. Starting chat must resolve the enterprise credential rather than ask for github.com authentication. Rebuilding the container must not reintroduce the failure. Ordinary github.com authentication must remain unchanged.
- **Trace:**

  > AgentHostTerminalContribution computes the enterprise URI from IDefaultAccountService, but AgentHostRootConfigForwarder sends it only through IAgentHostService and explicitly excludes separate remote connections. AgentHostGitHubEndpointService derives protected resources from the executing host's root configuration, defaulting to github.com when the enterprise value is absent. RemoteAgentHostAuthenticationResolver resolves the remote host's advertised resources rather than initializing its endpoint. This confirms the missing propagation path, but the trace has not established where a fresh container connection can receive configuration before initial required-resource authentication and schema hydration complete. Preserve host-advertised resource identity, older or third-party host compatibility, credential matching, and existing explicit remote configuration; do not broaden forwarding to local shell paths. The intermittent WSL delay and the settings-editor failure tracked at https://github.com/microsoft/vscode/issues/344331 are separate investigations.
