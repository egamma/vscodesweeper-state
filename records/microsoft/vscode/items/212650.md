# Issue #212650 — Support multiple `SemanticTokensProvider` per document selector

[https://github.com/microsoft/vscode/issues/212650](https://github.com/microsoft/vscode/issues/212650)

## Summary

Keep this accepted backlog request open: current source still selects one provider's semantic tokens rather than combining complementary results. The request has 27 upvotes, and the canonical search found no verified open issue owning the same work.

## Change summary

Allow complementary semantic tokens from multiple providers to appear together in one document, including embedded languages inside Java annotations.

## Best solution

Define supported composition semantics for document semantic-token providers, preserving each provider's legend and incremental-result lifecycle. Settle overlap precedence and provider eligibility before implementing, so embedded-language highlighting can coexist with the host language's highlighting.

- **Behavior:**

- **Trace:**

  > getDocumentSemanticTokensProviders and getDocumentSemanticTokens in src/vs/editor/contrib/semanticTokens/common/getSemanticTokens.ts select the highest-scoring registry group and return one non-null result. ModelSemanticColoring in src/vs/editor/contrib/semanticTokens/browser/documentSemanticTokens.ts then styles that result using one provider and maintains one provider/resultId/data response for incremental edits and release. The public contract in src/vscode-dts/vscode.d.ts also describes single-provider selection. https://github.com/microsoft/vscode/pull/135602 implemented fallback, not composition; https://github.com/microsoft/vscode/issues/135599 is the closed earlier composition request. - **Open decisions:**

## Evidence

- **Current selection behavior:** src/vs/editor/contrib/semanticTokens/common/getSemanticTokens.ts:getDocumentSemanticTokensProviders selects only registry.orderedGroups(model)[0]. getDocumentSemanticTokens requests those providers concurrently but returns the first result containing tokens; it does not combine their results.
- **Single-provider rendering state:** src/vs/editor/contrib/semanticTokens/browser/documentSemanticTokens.ts:ModelSemanticColoring stores one _currentDocumentResponse. Its request handler obtains styling for the selected provider, and _setDocumentSemanticTokens applies that provider's data and incremental edits before replacing the model's semantic tokens.
- **Existing-capability check:** src/vscode-dts/vscode.d.ts:15053-15064 documents registerDocumentSemanticTokensProvider as selecting the best-matching provider, not composing providers. editor.semanticHighlighting.enabled in src/vs/editor/common/config/editorConfigurationSchema.ts controls whether highlighting is shown; editor.semanticTokenColorCustomizations controls styling, not provider composition.
- **Earlier implementation covers fallback only:** https://github.com/microsoft/vscode/pull/135602 is merged, but explicitly implements choosing the provider that returns results, not merging multiple non-null results. In https://github.com/microsoft/vscode/issues/135580#issuecomment-953990123, a maintainer distinguishes combining providers from the original fallback use case and supports the broader idea.
