# Issue #334856 — AI: Group custom agents by discovery source in the Agent picker

[https://github.com/microsoft/vscode/issues/334856](https://github.com/microsoft/vscode/issues/334856)

## Summary

The source-grouping gap remains on current main: the Agent picker places every non-built-in custom agent in one flat Custom category. This should stay open and route to the AI customizations area for interaction and provenance design.

## Change summary

Group custom agents in the Agent picker by discovery source, including organization-specific subgroups and accessible collapsible sections.

## Best solution

Give the Agent picker stable, accessible source groups while preserving its search, ordering, selection, and execution behavior. The design should use authoritative provenance from customization discovery rather than infer ownership solely from file paths.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts`, `src/vs/platform/actionWidget/browser/actionWidgetDropdown.ts`, `src/vs/platform/actionWidget/browser/actionList.ts`
- **Validation:** Add focused tests for source-to-group classification and an Agent picker component/UI check covering filtering, keyboard navigation, accessible expand/collapse state, duplicate-name disambiguation, and unchanged selection behavior.
- **Behavior:**

  > The Agent picker presents custom agents in labeled groups for organization, plugin, extension, repository, user, and otherwise-unclassified sources, omitting empty groups. Organization agents are distinguishable by organization, and agents with the same name remain distinguishable by provenance. Users can expand and collapse groups while search continues to find agents across every group; keyboard navigation, screen-reader semantics, selection, editing, ordering within groups, and agent execution remain functional.
- **Trace:**

  > ModePickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts currently partitions modes only into built-in and custom categories, so all non-built-in agents remain flat. IChatMode already carries IAgentSource from src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts, including storage kind and limited extension/plugin identity, but no explicit organization display identity. The generic ActionList supports collapsible sections and keyboard expansion, while ActionWidgetDropdown currently maps categories to static headers without section metadata. Keep discovery, de-duplication, precedence, mode IDs, ordering within each source group, and command execution unchanged. The scope is the runtime Agent picker; broader customization-management consistency remains tracked by https://github.com/microsoft/vscode/issues/332543.
- **Open decisions:**
  - What authoritative organization identity and display label should the picker receive when an organization-provided agent is discovered, rather than deriving ownership from a URI?
  - Should source groups start expanded or collapsed, and should each group's collapsed state persist across picker openings?

## Evidence

- **current picker implementation:** src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts defines only Built-In, Custom, and policy-disabled categories; makeActionFromCustomMode assigns all ordinary custom modes to the same Custom category.
- **available provenance:** src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts defines IAgentSource with local, user, built-in, extension, and plugin storage plus extensionId or pluginUri where applicable. It does not expose an organization display name, so the requested organization hierarchy needs a provenance-contract decision.
- **collapsible-list boundary:** src/vs/platform/actionWidget/browser/actionList.ts supports accessible collapsible sections, but src/vs/platform/actionWidget/browser/actionWidgetDropdown.ts currently converts action categories into static headers and IActionWidgetDropdownAction does not expose section-toggle metadata.
