# Issue #252077 — navigator is now a global in nodejs

[https://github.com/microsoft/vscode/issues/252077](https://github.com/microsoft/vscode/issues/252077)

## Summary

The `PendingMigrationError` is still thrown on current main when `extensions.supportNodeGlobalNavigator` is false (the default). The error is by design — a migration warning for extensions accessing `navigator` in Node.js — but the discussion shows real user impact: extensions like Remote SSH, WSL, and Copilot Chat crash or malfunction because their dependencies access `navigator` without null-checks. The debt is that the migration period has lasted over a year with no path toward resolution (flipping the default or removing the shim). Keeping open as a valid tracking issue.

## Change summary

Extensions crash or malfunction in remote scenarios because VS Code's `navigator` shim in the Node.js extension host throws `PendingMigrationError` when extensions access `navigator`, and key extensions haven't migrated.

## Best solution

The migration shim has been active for over a year; the team should decide on a timeline to flip `extensions.supportNodeGlobalNavigator` to `true` by default (exposing Node's real `navigator`) or remove the shim entirely. In the meantime, the first-party extensions causing crashes (Copilot Chat in `extensions/copilot/`, and the Remote extensions) should be patched to stop accessing `navigator` unsafely. The shim logic lives in `src/vs/workbench/api/node/extensionHostProcess.ts` lines 140–149.
