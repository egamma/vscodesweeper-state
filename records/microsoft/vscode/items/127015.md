# Issue #127015 — Create command to resolve one CompletionItem

[https://github.com/microsoft/vscode/issues/127015](https://github.com/microsoft/vscode/issues/127015)

## Summary

A real extension-API gap remains on current main: extensions can resolve the first N provider-order completions, but cannot selectively resolve one returned item. The API design needs discussion, so this Backlog request should remain open.

## Change summary

Add an API command that selectively resolves one CompletionItem returned by the completion provider command.

## Best solution

Design an API that returns stable opaque completion identities and permits resolving a selected item while its provider cache is valid. It should avoid eagerly resolving unrelated items and define whether displayed ranking is part of the API contract.

## Vision fit

- **Fit:** aligned
- **Reason:** A selective completion-resolution API enables extensions to implement efficient language-service forwarding without moving specialized functionality into core.
- **Evidence:** The public roadmap emphasizes that “The power lives in extensions” and treats extension API hygiene as a durable theme.

## Evidence

- **current implementation:** src/vs/editor/contrib/suggest/browser/suggest.ts:390-428 resolves the first N entries from `provideSuggestionItems`, converts them into a public CompletionList, and disposes the underlying completion collection shortly afterward; no single-item resolve command exists.
- **provider identity:** src/vs/workbench/api/common/extHostLanguageFeatures.ts:1193-1230 caches provider items under internal IDs and requires that ID to invoke `resolveCompletionItem`; the public command result does not expose this resolution handle.
