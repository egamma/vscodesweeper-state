# Issue #319370 — Workspace resets when switching to Agent View

[https://github.com/microsoft/vscode/issues/319370](https://github.com/microsoft/vscode/issues/319370)

## Summary

Real bug: the Agents window "Open in Editor" action only takes `folders[0]` from the session workspace, so returning to the normal view from a multi-root workspace drops all but the first folder. The defect is confirmed in the source on current main.

## Change summary

Switching from the Agents window back to the normal VS Code editor view loses all workspace folders except the first one in a multi-root workspace.

## Best solution

Fix `OpenSessionInVSCodeAction.getFolderUriToOpen` (desktop: `src/vs/sessions/electron-browser/actions/vscodeActions.ts`, browser: `src/vs/sessions/browser/actions/vscodeActions.ts`) to detect the original multi-root workspace and pass a `workspaceUri` (via `IWorkspaceToOpen`) to `openWindow` instead of a single `folderUri`. The session should ideally remember whether it was opened from a multi-root workspace and restore that `.code-workspace` file when switching back.

## Evidence

- **desktop action source:** In `src/vs/sessions/electron-browser/actions/vscodeActions.ts` line 78, `getFolderUriToOpen` reads only `workspace?.folders[0]?.workingDirectory` and passes it as `{ folderUri }` to `nativeHostService.openWindow`, discarding all other workspace folders.
- **browser action source:** In `src/vs/sessions/browser/actions/vscodeActions.ts` (lines ~80–90), the browser `OpenInVSCodeAction` similarly reads only `workspace?.folders[0]` and constructs a single-folder URI.
- **openWindow API supports workspaces:** `IWindowOpenable` in `src/vs/platform/window/common/window.ts` supports `IWorkspaceToOpen` with a `workspaceUri`, so the API already allows opening a full `.code-workspace` — the action just doesn't use it.
- **no fix on main:** git log shows no related change to the vscodeActions files addressing multi-root workspace handling; the `folders[0]` pattern remains on current main.
