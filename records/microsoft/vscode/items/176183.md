# Issue #176183 — Add option to persist search UI settings 

[https://github.com/microsoft/vscode/issues/176183](https://github.com/microsoft/vscode/issues/176183)

## Summary

Keep this accepted feature request open: Search view preferences still persist per workspace rather than providing configurable cross-workspace defaults. The request has 26 upvotes and maintainer support; existing settings do not cover the central ask.

## Change summary

Allow configurable Search view defaults for replace visibility and include/exclude expansion across workspaces, with related interest in default search toggles.

## Best solution

Provide explicit cross-workspace Search view defaults while retaining workspace-specific interaction state and keeping transient changes out of settings.json. Settle whether these defaults initialize new workspaces or override remembered state before implementing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/search/browser/searchView.ts`, `src/vs/workbench/contrib/search/browser/search.contribution.ts`
- **Validation:** In two fresh workspaces, verify that the chosen shared defaults produce the configured replace visibility and include/exclude expansion. Change the controls in one workspace, reload it, and switch to the other; verify the agreed precedence and that transient interactions do not rewrite settings.json. Without the new option, existing workspace-local restoration must remain unchanged.
- **Behavior:**

  > Users repeatedly reopening Search in different workspaces want their preferred replace and include/exclude controls available without repeating the same expansion clicks. Provide an explicit way to establish those preferences across workspaces. Acceptance must cover fresh workspaces, reloads, existing remembered states and temporary local changes, with no automatic settings.json churn from ordinary interaction. The discussion also requests default search toggles and distinguishes in-file Find from workspace Search; their inclusion needs an explicit scope decision.
- **Trace:**

  > SearchView in src/vs/workbench/contrib/search/browser/searchView.ts obtains its viewletState from a WORKSPACE-scoped memento in the constructor. renderBody restores query.queryDetailsExpanded, createSearchWidget restores view.showReplace and search toggles, toggleQueryDetails updates the expansion state, and saveState persists values into that same memento. This establishes why workspace-local restoration does not supply cross-workspace defaults. Existing search configuration registrations in search.contribution.ts and search.common.contribution.ts do not expose the requested defaults. Preserve existing restoration when the feature is unused, and do not share query text, replacement text or include/exclude patterns merely to share UI preferences. https://github.com/microsoft/vscode/issues/156160 addresses surrounding view layout rather than this internal Search state; it is related context, not a verified duplicate. The remaining uncertainty is the user-visible precedence and scope of the new preferences.
- **Open decisions:**
  - Should configured defaults initialize only workspaces without remembered Search state, or override remembered state whenever the Search view is restored?
  - Should the initial feature cover only replace visibility and search-details expansion, or also search toggles and the separately requested in-file Find defaults?
