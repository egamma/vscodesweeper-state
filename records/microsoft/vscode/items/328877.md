# Issue #328877 — .copilot.md should auto-load from nested workspace directories or allow custom paths

[https://github.com/microsoft/vscode/issues/328877](https://github.com/microsoft/vscode/issues/328877)

## Summary

The underlying ask — auto-loading a git-tracked, non-root context file, with a custom configurable location — is already covered by shipped settings: `chat.useNestedAgentsMdFiles` auto-discovers `AGENTS.md` anywhere in the workspace (including `dev-envs/AGENTS.md`), and `chat.instructionsFilesLocations` lets you point at arbitrary custom folders for `.instructions.md` files. Proposing *as-designed rather than a new custom-path setting for a `.copilot.md` filename that isn't actually part of the product.

## Change summary

Add a workspace setting to point Copilot's auto-loaded context file at a custom, non-root path (e.g. a git-tracked subdirectory) instead of only the workspace root.

## Best solution

Point the reporter at `chat.useNestedAgentsMdFiles` (nested `AGENTS.md` anywhere in the workspace) and `chat.instructionsFilesLocations` (arbitrary custom folders for `.instructions.md` files with front-matter `applyTo` globs) — both already deliver git-tracked, non-root, path-configurable shared context, which is the actual capability being requested.

  > Thanks for the report! The scenario you describe — a shared, git-tracked context file that lives outside the workspace root — is already supported by two shipped settings:
  > 
  > - `chat.useNestedAgentsMdFiles` (plus `chat.useAgentsMdFile`) makes VS Code auto-discover `AGENTS.md` anywhere in the workspace, e.g. `dev-envs/AGENTS.md`, so it doesn't need to sit at the root.
