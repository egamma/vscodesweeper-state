# Issue #338084 — Webview can stay on its old content when its HTML is replaced while that content is still loading

[https://github.com/microsoft/vscode/issues/338084](https://github.com/microsoft/vscode/issues/338084)

## Summary

Confirmed on current main: the single shared `loadTimeout` variable in the webview host page can be cleared by an older frame's late `load` event, leaving a newly-set frame stuck pending forever. A fixing PR is already open, so this stays open pending review/merge rather than any triage close.

## Change summary

When a webview's HTML is replaced while the previous content is still loading, the new content can get stuck pending forever and never receive messages.

## Best solution

Land the fix in the open PR (per-frame timer instead of one shared `loadTimeout`) rather than closing this issue now.
