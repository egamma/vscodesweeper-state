# Issue #338084 — Webview can stay on its old content when its HTML is replaced while that content is still loading

[https://github.com/microsoft/vscode/issues/338084](https://github.com/microsoft/vscode/issues/338084)

## Summary

Confirmed on current main: a webview's fallback-load timer is a single shared `loadTimeout` variable, so a stale frame's `load` event can consume a newer frame's timer and leave the new content stuck pending forever. A PR (#338085) is already open to fix this by giving each frame its own timer, so the right move is to review/land that PR rather than treat the issue as unowned.

## Change summary

Replacing a webview's HTML while the previous content is still mid-load can leave the new frame stuck in pending-frame state forever, with the old content shown and messages undelivered.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338085, which gives each frame its own fallback timer instead of sharing the module-level `loadTimeout` variable in src/vs/workbench/contrib/webview/browser/pre/index.html.
