# Issue #330397 — Add a diarized meeting mode for continuous agent orchestration

[https://github.com/microsoft/vscode/issues/330397](https://github.com/microsoft/vscode/issues/330397)

## Summary

Keep open: current dictation supports streaming text into an input, but does not cover speaker-attributed meeting transcripts and continuous orchestration. This team-authored request warrants a design session; no qualifying canonical duplicate or completed implementation was found.

## Change summary

Add a meeting dictation mode that preserves speaker-attributed, timestamped transcripts and periodically feeds a responsive agent that delegates work to other sessions.

## Best solution

Define an opt-in meeting workflow spanning transcription and agent sessions, with explicit transcript retention and delegated-action semantics. Establish diarization backend feasibility before committing to an implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/browser/speechToText/chatSpeechToTextService.ts`, `src/vs/workbench/contrib/chat/browser/speechToText/voiceCodeTranscriptionClient.ts`, `src/vs/workbench/contrib/chat/browser/speechToText/dictationSession.ts`
- **Validation:** The plan should define an executable scenario using simulated timestamped utterances from two speakers: preserve an append-only transcript, deliver new chunks without omissions or duplicate delivery, and demonstrate that incoming context remains accepted while delegated work runs. Verify explicit stop ends capture and future delivery, and ordinary input dictation remains unchanged.
- **Behavior:**

  > A user explicitly starts a meeting mode and supplies instructions describing what an agent should monitor or accomplish. The mode preserves raw transcript entries with speaker attribution and timestamps, and automatically provides new transcript chunks to a dedicated session at regular intervals. That session remains responsive to incoming conversation while delegating work to other sessions. Acceptance includes a two-speaker conversation, continued context delivery during delegated work, and stopping capture and delivery when the user ends the meeting.
- **Trace:**

  > Current dictation is input-oriented: ChatSpeechToTextService exposes cumulative text through IChatDictationTranscript, and startDictation in dictationSession.ts connects it to LiveTranscriptInserter in a code editor. The transcription client contract has revisions and turn identifiers but no speaker or utterance-time fields, and the existing editor dictation lifecycle has a 20-minute limit. Configuration registrations cover ordinary dictation and optional final-text cleanup, not the requested meeting workflow. The trace establishes a capability gap, not a confirmed defect; backend diarization support and the session-orchestration integration remain unverified. Preserve existing input dictation semantics and its local/cloud policy behavior. The product request is https://github.com/microsoft/vscode/issues/330397; its Azure AI Speech suggestion is a feasibility lead, not proof that the current backend supports the required contract.
- **Open decisions:**
  - Should meeting transcripts persist across reloads, and what user-visible retention and deletion controls should apply?
  - Should delegated actions begin automatically under existing session permissions, or require a meeting-specific approval step?
  - Which platforms and transcription backends should meeting mode support initially, and should it be unavailable when speaker diarization cannot be provided?
