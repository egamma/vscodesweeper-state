# Issue #335776 — Agent continues incorrectly on worktree creation failure

[https://github.com/microsoft/vscode/issues/335776](https://github.com/microsoft/vscode/issues/335776)

## Summary

Fresh (same-day), team-authored bug report with detailed logs from two distinct worktree-creation failures (Windows filename-length limit hitting Git exit code 128, and a Git LFS hook failure) where the agent silently falls back to the original folder instead of surfacing the failure correctly. No fix is present on main yet, so this stays open.

## Change summary

When isolated-worktree creation fails (e.g., Windows path-length limit, missing git-lfs), the agent session incorrectly continues in the original (non-isolated) folder rather than handling the failure correctly.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts (_resolveWorktreeBeforeSend) and src/vs/platform/agentHost/node/shared/worktreeIsolation.ts, decide the correct behavior on worktree-creation failure (block/notify clearly vs. silent fallback) and, separately, harden worktree path generation against Windows MAX_PATH limits; the linked issue #335779 (claims a worktree was created when it wasn't) suggests the failure/announcement path itself has a bug worth fixing alongside this.
