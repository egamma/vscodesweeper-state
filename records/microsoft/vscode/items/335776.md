# Issue #335776 — Agent continues incorrectly on worktree creation failure

[https://github.com/microsoft/vscode/issues/335776](https://github.com/microsoft/vscode/issues/335776)

## Summary

Confirmed on main: when isolated worktree creation fails, `_resolveWorkingDirectoryBeforeSend` in agentService.ts still falls back to the picked folder instead of surfacing the failure, matching the reported bug. An open (unmerged) PR fixes exactly this, so the issue stays open pending merge rather than being closed as implemented.

## Change summary

On Windows, worktree creation can fail (e.g. filename-length limit, Git LFS hook missing) and the agent session silently continues in the original folder instead of surfacing the failure.

## Best solution

Land PR https://github.com/microsoft/vscode/pull/336696 (agentHost: Stop sessions when worktree creation fails), which removes the silent fallback in `_resolveWorkingDirectoryBeforeSend`/`_resolveWorktreeBeforeSend` and instead throws/stops the session via `getCreationError`, then close this issue once merged.
