# Issue #165339 — Blocked popups are not handled in Chrome on Github Codespace

[https://github.com/microsoft/vscode/issues/165339](https://github.com/microsoft/vscode/issues/165339)

## Summary

Still reproduces on main: the popup-block detection and retry dialog in `setupOpenHandlers` is guarded by `if (isSafari)` — non-Safari browsers (Chrome, Edge, Firefox) silently fail when the popup is blocked, with no notification or retry offered to the user.

## Change summary

When an extension calls `vscode.env.openExternal` in a web context (Codespaces, Code Server), Chrome and other non-Safari browsers silently block the popup with no user-facing notification or retry mechanism.

## Best solution

Extend the popup-block detection in `src/vs/workbench/browser/window.ts` (`setupOpenHandlers`) to non-Safari browsers. The `windowOpenWithSuccess` helper in `src/vs/base/browser/dom.ts` already exists and returns a boolean — use it for Chrome/Edge/Firefox the same way it's used for Safari, then show the same retry dialog when the open fails. The `windowOpenNoOpener` path (which uses `_blank` + `noopener`) cannot detect blocking, so non-Safari may need to use `windowOpenWithSuccess` instead.
