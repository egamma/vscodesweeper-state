# Issue #309987 — NES NextEditProvider: Track fire-and-forget async loops for proper disposal

[https://github.com/microsoft/vscode/issues/309987](https://github.com/microsoft/vscode/issues/309987)

## Summary

The regular background stream still has no provider-lifetime cancellation, so disposal can leave it processing edits and updating the cache. Speculative-request disposal now has partial coverage, but it does not establish that all detached streaming work is lifetime-bound.

## Change summary

Ensure disposing NextEditProvider cancels its in-flight background edit streams and prevents subsequent stale cache writes.

## Best solution

Make background stream processing respect the provider's lifetime while preserving first-edit responsiveness and existing request-sharing semantics. Retain the speculative manager's existing cancellation behavior and cover regular streaming disposal with deterministic regression tests.
