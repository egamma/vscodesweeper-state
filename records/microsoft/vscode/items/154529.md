# Issue #154529 — Add option to display Selection Highlights across Split Editor panes

[https://github.com/microsoft/vscode/issues/154529](https://github.com/microsoft/vscode/issues/154529)

## Summary

Keep open: arbitrary-text selection highlights remain editor-local, and the suggested semantic-highlighting setting does not cover the request. With 59 upvotes, a Backlog milestone, and maintainer interest, this remains accepted work.

## Change summary

Add an opt-in way to display selection matches and their overview-ruler markers across split editors showing the same document.

## Best solution

Provide optional same-document cross-pane selection highlighting in the editor's selection-highlighter contribution, preserving the existing default and matching rules. Settle which pane's selection governs shared highlights when focus changes before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/multicursor/browser/multicursor.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/multicursor/test/browser/multicursor.test.ts`
- **Validation:** Extend the multicursor browser tests with two editors sharing one model: enabling the option makes arbitrary selected-text matches visible in both editors, including overview-ruler decorations for a plaintext model; disabling it preserves editor-local behavior. Cover the agreed focus-switch semantics and cleanup on selection clearing, model changes, and disposal. Run the targeted multicursor suite using scripts/test.sh --run src/vs/editor/contrib/multicursor/test/browser/multicursor.test.ts, then manually verify split-pane text highlights and scrollbar markers.
- **Behavior:**

  > When enabled, selecting arbitrary text in one pane should display matching occurrences in other split panes showing the same document, including their scrollbar markers in the reporter's plaintext scenario. The feature must be toggleable, and the existing editor-local default must remain available. Acceptance includes correct updates when the selection changes and cleanup when the selection or originating editor goes away. Existing case, multiline, length-limit, Find, and semantic-highlighting behavior remains unchanged except for the explicitly agreed cross-pane scope.
- **Trace:**

  > SelectionHighlighter in src/vs/editor/contrib/multicursor/browser/multicursor.ts computes textual matches from one editor's selections and stores them in an editor-owned decoration collection. EditorDecorationsCollection.set() in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts ultimately passes that editor's ID to model.changeDecorations(), establishing the current pane-local boundary. editor.selectionHighlight in src/vs/editor/common/config/editorOptions.ts has no scope option. The separate WordHighlighter multiFile path does not satisfy arbitrary text selection, as confirmed at https://github.com/microsoft/vscode/issues/154529#issuecomment-2619662948. The existing multicursor matching-highlight tests provide a starting validation surface; overview-ruler options come from highlightDecorations.ts and retain the existing semantic-suppression distinction tracked separately at https://github.com/microsoft/vscode/issues/153485. Keep the initial behavior boundary to split panes sharing one document, not cross-document text search or changes to semantic highlighting. The unresolved product behavior is which selection remains authoritative when focus moves between panes that retain different selections.
- **Open decisions:**
  - When focus moves to another pane of the same document, should shared highlights follow that pane's current selection immediately, or retain the last explicitly selected text until a new selection is made?
