# Issue #283525 — No validation or logs on adding a private MCP registry (that fails)

[https://github.com/microsoft/vscode/issues/283525](https://github.com/microsoft/vscode/issues/283525)

## Summary

Still valid on main: a team member (sandy081) acknowledged the trailing-slash bug and it remains unfixed. The URL normalization at `mcpGalleryManifestService.ts:47` strips trailing slashes before building the manifest, but the comparison at line 57 (`isProductGalleryUrl = this.productService.mcpGallery?.serviceUrl === url`) compares the *unnormalized* product URL against the *normalized* one, which can silently bypass the 'registry only' policy — a security-relevant behavior.

## Change summary

A trailing slash in a policy-configured private MCP registry URL causes VS Code to silently fall back to the default public registry, bypassing the enterprise 'registry only' policy.

## Best solution

Normalize the registry URL consistently before all comparisons (the `isProductGalleryUrl` check at `mcpGalleryManifestService.ts:57` and the `update()` equality check at line 75 both need to compare against the normalized URL). Additionally, surface errors from private registry fetch failures to the user rather than silently falling back to the public registry.
