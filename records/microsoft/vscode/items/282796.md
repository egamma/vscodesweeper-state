[https://github.com/microsoft/vscode/issues/282796](https://github.com/microsoft/vscode/issues/282796)

## Summary

Consolidate the remaining imported-chat persistence and session-list problem into the verified open canonical issue. Current main retains the model during sidebar moves, but imported chats still do not become persistent sessions.

## Change summary

Moving an imported chat into the secondary sidebar should preserve the conversation and make it available in the workspace's session list.

## Best solution

Track the remaining work in https://github.com/microsoft/vscode/issues/291986: imported conversations should become durable workspace sessions rather than requiring a separate /fork workaround. Preserve this report's Windows reproduction and missing-session-file error as supporting evidence.

- **Maintainer consolidation precedent:** https://github.com/microsoft/vscode/issues/330491 describes the same imported-chat sidebar move failure and diagnoses release of the last model reference before destination loading. A maintainer identified https://github.com/microsoft/vscode/issues/291986 as a duplicate candidate at https://github.com/microsoft/vscode/issues/330491#issuecomment-5309960055; the matching report was subsequently closed.
- **Move handoff addressed, not the entire report:** Commit https://github.com/microsoft/vscode/commit/14200868c7fb67eb932fbdf69abbe0f87b5da837 adds an acquireExistingSession reference around ChatWidgetService.openSession, retaining the model while prepareSessionForMove closes the source and the destination loads it. Current chatMoveActions.ts uses this path for sidebar moves. This addresses the reported missing-file handoff mechanism, but does not make imported chats persistent or discoverable in history.
- **Remaining gap on current main:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts passes imported data to ChatEditorInput.resolve, which calls loadSessionFromData. ChatModel marks export-only data as isImported; src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts:394 excludes such models from persistence, and :551 excludes them from live history. This conclusively preserves the session-list gap covered by the canonical issue; no runtime execution was performed.
- **Workaround and accepted direction:** https://github.com/microsoft/vscode/issues/282796#issuecomment-4080839885 suggests /fork as an indirect workaround, not a fix to import or move behavior. At https://github.com/microsoft/vscode/issues/291986#issuecomment-5309983032, a maintainer asks why imports do not automatically produce the expected fork-like durable session.
