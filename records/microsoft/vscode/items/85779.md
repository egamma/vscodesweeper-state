# Issue #85779 — Extension tests improperly activate instance from dist folder

[https://github.com/microsoft/vscode/issues/85779](https://github.com/microsoft/vscode/issues/85779)

## Summary

Still a valid pain point for webpack-based extension authors running tests — no mechanism to override the `main` field during test execution has been added. A team member (alexdima) acknowledged the issue and asked for design input; it remains under discussion.

## Change summary

Extension tests activate the bundled dist entry point (from package.json `main`) alongside unbundled test code from `out/`, causing duplicate registrations and test failures.

## Best solution

Provide a way to override the extension's `main` entry point during test runs — either a CLI flag (e.g. `--extensionMainOverride`), a test-specific `package.json` field, or documentation of the recommended workaround (mutating `package.json` before test execution). The fix belongs in the extension host activation path under `src/vs/workbench/services/extensions/`.
