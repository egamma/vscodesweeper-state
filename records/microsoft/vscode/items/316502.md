# Issue #316502 — Reintroduce find/grep/tree compression with smart summarization

[https://github.com/microsoft/vscode/issues/316502](https://github.com/microsoft/vscode/issues/316502)

## Summary

Keep open: current main still uses 200-line caps rather than the requested directory/file summaries and noise-aware tree filtering. The referenced removal PR was closed without merging, so its description does not establish that the filters were removed.

## Change summary

Replace line-capped find, grep, and tree tool output with deterministic summaries that account for omitted information.

## Best solution

Provide command-aware summaries in the terminal output compressor while preserving small outputs and existing protection rules. Settle which output formats can be summarized reliably and what passes through unchanged before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/terminalOutputCompressor.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/test/browser/terminalOutputCompressor.test.ts`, `src/vs/workbench/contrib/chat/test/browser/tools/toolResultCompressorService.test.ts`
- **Validation:** Extend the existing 'find / grep / tree filters' unit suite with exact-output fixtures for directory totals including entries beyond line 200, per-file grep counts, unchanged grep output below 10 lines, and tree noise removal with explicit omission accounting. Include pass-through cases for unsupported formats and retain compressor-service protection tests; run the targeted suites through scripts/test.sh after implementation.
- **Behavior:**

  > Large find results should expose directory-level counts covering the complete result set rather than only an initial slice. Grep summaries should expose total matches and per-file counts, while outputs below 10 lines remain unchanged. Tree output should remove agreed noise directories and explicitly account for any subsequent line cap near 80 lines. Acceptance checks must distinguish summarized information from retained match content and verify that unsupported output is not misleadingly interpreted.
- **Trace:**

  > In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/terminalOutputCompressor.ts, findFilter, grepFilter, and treeFilter currently share capLines with MAX_LIST_LINES = 200. grepFilter also matches rg, ack, and ag, whose flags can produce materially different output formats. The existing filter tests assert truncation, and ToolResultCompressorService preserves structured-output guards and adds compression banners. Contrary to the issue's premise, https://github.com/microsoft/vscode/pull/316500 closed without merging; plan against the current registered filters rather than assuming they need re-registration. Preserve unrelated filters, the compression enablement setting, and existing service safeguards. The unresolved boundary is which command/output variants can safely receive counts-only summaries without misrepresenting results.
- **Open decisions:**
  - Which find and grep-family output formats are supported for summarization, and should unsupported variants always pass through unchanged?
  - For large grep outputs, is replacing all match content with file counts acceptable, or must the summary retain representative matching text?
  - Which tree directories are considered removable noise, and how should stripped entries versus entries omitted by the line cap be reported?
