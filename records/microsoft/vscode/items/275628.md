# Issue #275628 — Every tool is selected after reloading if I open the tools list too early during startup

[https://github.com/microsoft/vscode/issues/275628](https://github.com/microsoft/vscode/issues/275628)

## Summary

The startup race remains present on current main: accepting a tools picker opened before extension tools register can replace the persisted selection with the picker’s incomplete snapshot, causing the missing tools to default to enabled. This team-authored Backlog bug should remain open.

## Change summary

Preserve disabled tool selections when the tools picker is opened before extension-contributed tools finish registering.

## Best solution

Committing the visible picker selection must preserve stored enablement for tools that were unavailable to that picker snapshot, while continuing to apply changes to tools the user could actually see and toggle.

- **Behavior:**

  > Opening and accepting Configure Tools before extension-contributed tools finish registering must not change the saved enablement of tools absent from that picker snapshot. Changes to visible tools must still persist normally. When an unavailable tool registers later, it must recover its previously stored enabled or disabled state rather than defaulting to enabled.
- **Trace:**

  > The picker in src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts calls `computeItems()` once and later derives its accepted result solely from `treePicker.itemTree`, so tools registered after opening are absent from the result. `ConfigureToolsAction` passes that partial result to `ChatSelectedTools.set()`. In src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts, `set()` replaces the entire profile-level `chat/selectedTools` memento, while `entriesMap` interprets missing IDs as enabled; this produces the reported reset. Keep the existing session/custom-agent/global precedence and the default-enabled behavior for genuinely new tools unchanged; the boundary is preserving prior state for entries omitted only because they were unavailable.

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts constructs the tree once in `computeItems()` when the picker opens and `collectResults()` returns only items present in that tree; there is no refresh when extension tools register later.
- **state loss:** src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts replaces the complete profile memento in `ChatSelectedTools.set()` with `ToolEnablementStates.fromMap(enablementMap)`. A partial startup snapshot therefore drops stored entries for unavailable extension tools, and `entriesMap` treats missing entries as enabled.
