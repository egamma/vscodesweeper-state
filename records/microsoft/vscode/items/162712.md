# Issue #162712 — Support `XDG_CONFIG_HOME` for the `argv.json` file

[https://github.com/microsoft/vscode/issues/162712](https://github.com/microsoft/vscode/issues/162712)

## Summary

The XDG-aware argv.json location remains unsupported on current main, with 74 upvotes and explicit maintainer support. Keep this accepted request open while the two linked, still-open implementation PRs are reviewed.

## Change summary

Respect XDG_CONFIG_HOME for the Linux argv.json location while preserving existing configuration and portable-mode behavior.

## Best solution

Review and reconcile the existing PRs to deliver consistent XDG-aware argv.json resolution in early startup and the environment service, with backward-compatible migration. Keep user-data-dir/extensions-dir configuration and shared-storage relocation separate from the maintainer-approved argv.json scope.

## Evidence

- **Current startup behavior:** src/mainImpl.ts:473–484, getArgvConfigPath(), honors VSCODE_PORTABLE but otherwise resolves argv.json under os.homedir() and product.dataFolderName, including the development suffix. It never checks XDG_CONFIG_HOME; readArgvConfigSync() and createDefaultArgvConfigSync() use that path.
- **Existing capability does not cover the request:** src/vs/platform/environment/common/environmentService.ts:95–101, argvResource, likewise uses the portable directory or userHome/product.dataFolderName/argv.json. src/vs/platform/environment/node/userDataPath.ts:98–99 already respects XDG_CONFIG_HOME for Linux user data, but that separate path does not relocate argv.json.
- **Maintainer-approved boundary:** In the supplied discussion at https://github.com/microsoft/vscode/issues/162712, bpasero supported XDG_CONFIG_HOME on 2022-12-07, explicitly separated user-data-dir configuration from this request, and called for preserving existing users through migration on 2022-12-30.
