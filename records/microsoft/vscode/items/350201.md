# Issue #350201 — Agent host: Branch changeset is fingerprinted twice per change; a refresh scheduled while the previous one has started runs a second, redundant pass

[https://github.com/microsoft/vscode/issues/350201](https://github.com/microsoft/vscode/issues/350201)

## Summary

The redundant fingerprint pass remains in current main: refreshes arriving after dequeue but before Git reads cannot join the running computation. Related fixes reduce work within a pass but do not address this scheduling gap.

## Change summary

Avoid repeating Branch Changes fingerprint reads for refreshes already covered by a successful running computation.

## Best solution

Make Branch refresh scheduling recognize requests covered by the running snapshot, while retaining subsequent changes, forced review refreshes, telemetry-bearing requests, and retries after unsuccessful computations.
