# Issue #350201 — Agent host: Branch changeset is fingerprinted twice per change; a refresh scheduled while the previous one has started runs a second, redundant pass

[https://github.com/microsoft/vscode/issues/350201](https://github.com/microsoft/vscode/issues/350201)

## Summary

The redundant fingerprint path remains in current source: an executing request leaves the pending array before reading Git inputs, so another refresh queues a second pass. Keep this open for bounded scheduling improvements that preserve genuinely newer changes.

## Change summary

Avoid redundant Branch changeset fingerprint passes for refreshes already covered by an executing computation.

## Best solution

Coalesce refreshes covered by the same Branch input read while retaining follow-up computations for newer changes and explicit forced refreshes. Preserve turn-completion telemetry attribution and changeset status behavior.
