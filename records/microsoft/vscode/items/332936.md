# Issue #332936 — Agents can not output more than 500 characters in task_complete

[https://github.com/microsoft/vscode/issues/332936](https://github.com/microsoft/vscode/issues/332936)

## Summary

Real, traceable behavior, but the root mechanism (spilling oversized tool output to a temp file) is owned by the underlying Copilot agent SDK, not VS Code's own orchestration code — VS Code's host only auto-approves reading those SDK-generated temp files back, it doesn't create or size-gate them, so this needs SDK-side or product-level follow-up rather than a quick core fix.

## Change summary

When a Copilot agent's task-completion summary exceeds ~500 characters, the underlying SDK treats it like any other oversized tool output and spills it to a temp file instead of surfacing it directly in the chat UI, making the user-facing summary hard to read.

## Best solution

Either have the Copilot agent SDK (or the Agent Host's task_complete handling) exempt the completion-summary parameter from the generic large-tool-output-to-file behavior, or expose a setting; this likely requires coordination with the SDK/agent-host team since the 500-char threshold and file-spill logic live in the SDK layer that copilotAgentSession.ts (see the `isCopilotSdkToolOutputTempFile` handling around line 3394) already treats as a fixed external contract.
