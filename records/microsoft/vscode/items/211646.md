# Issue #211646 — Certain Edit menus should not be active without a selection (macOS)

[https://github.com/microsoft/vscode/issues/211646](https://github.com/microsoft/vscode/issues/211646)

## Summary

The reported menu state remains present on current main: Cut and Copy have no enablement precondition, so the native macOS menu keeps them enabled without a selection. The issue is an accepted Backlog bug, and resolving it requires deciding how menu enablement should interact with VS Code's intentional copy/cut-current-line behavior.

## Change summary

Disable the macOS Edit menu's Cut and Copy items when the focused editor has no applicable selection.

## Best solution

Make the native Cut and Copy menu state accurately represent whether invoking the command will act on content, while preserving the intended `editor.emptySelectionClipboard` behavior and non-editor clipboard implementations. The maintainer must first decide whether an empty cursor remains an actionable selection for menu-state purposes.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/clipboard/browser/clipboard.ts`, `src/vs/workbench/electron-browser/parts/titlebar/menubarControl.ts`, `src/vs/workbench/test/browser/parts/titlebar/menubarControl.test.ts`
- **Validation:** Add targeted menubar-action coverage asserting the decided enabled state for Cut and Copy with an empty versus non-empty editor selection, then verify on macOS that the native Edit menu exposes the same state to menu automation.
- **Behavior:**

  > On macOS, the native Edit menu's Cut and Copy enabled states must accurately communicate whether those commands can act in the current focus context. A non-empty editor selection must keep both commands available, and unrelated clipboard implementations such as webviews and notebooks must retain their existing behavior. Acceptance must also cover an empty editor selection under the chosen `editor.emptySelectionClipboard` semantics and confirm that menu automation observes the resulting state.
- **Trace:**

  > `CutAction` and `CopyAction` in `src/vs/editor/contrib/clipboard/browser/clipboard.ts` have no precondition, so their menu actions remain enabled. `NativeMenubarControl.populateMenuItems` in `src/vs/workbench/electron-browser/parts/titlebar/menubarControl.ts` forwards disabled action state, and `Menubar.createMenuItem` in `src/vs/platform/menubar/electron-main/menubar.ts` applies it to Electron's native item. The defect is therefore source-reproducible, but `editor.emptySelectionClipboard` defaults to true and the clipboard and cursor paths intentionally operate on the current line when the selection is empty. Keep shortcut behavior, webview/notebook command overrides, and non-macOS menu behavior outside the scope unless the selected product semantics require otherwise.
- **Open decisions:**
  - When `editor.emptySelectionClipboard` is enabled and an empty cursor would copy or cut the current line, should the macOS Edit menu remain enabled to reflect that action, or be disabled to follow selection-only native menu semantics?
  - If the native menu is disabled for an empty selection, should the corresponding keyboard shortcuts continue performing the current-line operation?

## Evidence

- **current source:** `src/vs/editor/contrib/clipboard/browser/clipboard.ts` registers `editor.action.clipboardCutAction` and `editor.action.clipboardCopyAction` with `precondition: undefined`; their `MenubarEditMenu` entries likewise have no selection-dependent condition.
- **native menu propagation:** `src/vs/workbench/electron-browser/parts/titlebar/menubarControl.ts` serializes `MenuItemAction.enabled` into the native menubar data, and `src/vs/platform/menubar/electron-main/menubar.ts` creates the Electron menu item with that enabled state. With no command precondition, Cut and Copy remain enabled.
- **behavioral constraint:** `src/vs/editor/common/config/editorOptions.ts` defaults `editor.emptySelectionClipboard` to true, while `src/vs/editor/contrib/clipboard/browser/clipboard.ts` and `src/vs/editor/common/cursor/cursorDeleteOperations.ts` deliberately copy or cut the current line for an empty selection. Disabling the menu strictly on `editorHasSelection` would conflict with that shipped behavior.
