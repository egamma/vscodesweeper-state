# Issue #191052 — Inactive notebook editor does not indicate dirty state in this case

[https://github.com/microsoft/vscode/issues/191052](https://github.com/microsoft/vscode/issues/191052)

## Summary

The inactive-tab dirty-state gap remains in current source: the untitled notebook factory resolves a dirty model but returns an unresolved editor input that initially reports clean. Keep this open in the notebook area; the existing steps are sufficient.

## Change summary

Opening two new, path-associated notebooks from the command line leaves the inactive tab without its dirty indicator despite both working copies being dirty.

## Best solution

Ensure newly created notebook editor inputs accurately reflect their existing working copy's dirty state before activation, with regression coverage for two path-associated untitled notebooks. Preserve ordinary saved-notebook and scratchpad behavior.
