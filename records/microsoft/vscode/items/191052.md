# Issue #191052 — Inactive notebook editor does not indicate dirty state in this case

[https://github.com/microsoft/vscode/issues/191052](https://github.com/microsoft/vscode/issues/191052)

## Summary

Still reproduces on main: inactive notebook tabs don't show the dirty dot when opened from CLI. The `isDirty()` path in `NotebookEditorInput` returns `_defaultDirtyState` (false) before the model is resolved, so an unresolved background tab appears clean even when it should be dirty.

## Change summary

Opening two notebooks from the command line shows the dirty indicator only on the active tab, not on the inactive one.

## Best solution

Ensure `startDirty` is set correctly on the `NotebookEditorInput` options when opening notebooks from CLI that will be dirty (untitled with content), or resolve the model eagerly enough that `isDirty()` reflects the true state before the tab renders its decoration. Fix likely lives in the notebook editor input creation path and `notebookEditorInput.ts`.
