# Issue #317870 — Mermaid diagrams fail to render after 1.121 upgrade when bierner.markdown-mermaid is still installed

[https://github.com/microsoft/vscode/issues/317870](https://github.com/microsoft/vscode/issues/317870)

## Summary

The migration gap remains on current main: users who already have a Mermaid preview extension installed can encounter competing Markdown plugins and scripts with no warning. The legacy extension is now deprecated, but that does not address existing installations, so this should remain open in the Mermaid area.

## Change summary

Handle or clearly report conflicts between the built-in Mermaid Markdown renderer and previously installed Mermaid preview extensions after upgrading to VS Code 1.121.

## Best solution

Have the built-in Mermaid extension detect known conflicting preview providers and present actionable migration guidance instead of allowing diagrams to fail silently. The implementation should account for both `bierner.markdown-mermaid` and other extensions contributing Mermaid Markdown rendering.

## Evidence

- **confirmed behavior:** The reporter confirmed that uninstalling `bierner.markdown-mermaid` and restarting restores rendering; https://github.com/microsoft/vscode/issues/317870#issuecomment-4582898307 independently reports the same class of conflict with Mermaid Chart.
- **current source:** `extensions/mermaid-markdown-features/src/extension.ts` unconditionally exports `extendMarkdownIt`, while `extensions/mermaid-markdown-features/package.json` contributes both `markdown.markdownItPlugins` and `markdown.previewScripts`; there is no detection or migration handling for competing Mermaid extensions.
- **core migration:** Commit https://github.com/microsoft/vscode/commit/ea086aed286dc6554635ff51d70ff5f5ab00b778 moved `bierner.markdown-mermaid` into VS Code core, establishing that upgrade compatibility belongs to the built-in Mermaid integration.
- **partial mitigation:** The legacy extension was marked deprecated in https://github.com/mjbvz/vscode-markdown-mermaid/commit/9f4d37ded0cc7fdf05bbab17fb082a6fc118e269, but deprecation does not deactivate copies already installed before the upgrade.
