# Issue #349484 — Code asks to save ignored files when committing

[https://github.com/microsoft/vscode/issues/349484](https://github.com/microsoft/vscode/issues/349484)

## Summary

Keep open as Git prompt polish: the documented default checks any unsaved repository files, including ignored files. Existing settings suppress more prompts than requested, so they do not fully address the confusing warning.

## Change summary

Avoid asking users to save ignored files that cannot contribute to the pending commit.

## Best solution

Have the Git owner decide whether the default pre-commit prompt should exclude genuinely ignored, untracked files while retaining warnings for commit-relevant edits. Align the setting description and warning text with that decision.

- **Documented behavior and partial workarounds:** extensions/git/package.json:3617–3631 defaults git.promptToSaveFilesBeforeCommit to "always". extensions/git/package.nls.json:223–226 describes this as checking any unsaved files. "staged" checks only staged files, and "never" disables the check; neither preserves warnings for all eligible unstaged files while excluding ignored files.
- **Existing ignore capability:** extensions/git/src/repository.ts:2799 onward implements Repository.checkIgnore using git check-ignore. The pre-commit document selection does not call it.
