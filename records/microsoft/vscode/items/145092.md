# Issue #145092 — Improved CSV/TSV editing

[https://github.com/microsoft/vscode/issues/145092](https://github.com/microsoft/vscode/issues/145092)

## Summary

Keep open: this is accepted Backlog work with sustained community interest and an explicit positive maintainer response. Current main still lacks built-in CSV/TSV editing or delimiter-aware editor rendering, and no open canonical issue was found.

## Change summary

Add structured editing for CSV/TSV files, including quote-aware column alignment, delimiter selection, navigation, and consistent diff rendering.

## Best solution

Plan a reusable structured-text capability that preserves the ordinary text model while providing delimiter-aware visual alignment and navigation, with applicability to CSV/TSV and Markdown tables. The design should settle which parts belong in editor core versus an extension-facing API before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/viewModel/viewModelLines.ts`, `src/vs/editor/common/viewModel/viewModelImpl.ts`, `src/vs/editor/common/viewLayout/viewLineRenderer.ts`, `src/vs/editor/test/common/viewLayout/viewLineRenderer.test.ts`, `src/vs/editor/test/browser/viewModel/viewModelImpl.test.ts`
- **Validation:** End the plan with focused editor tests showing that quoted CSV and TSV rows align without changing model text or model/view coordinate behavior, edits recompute affected widths, non-delimited files render unchanged, and both sides of a diff use compatible column widths.
- **Behavior:**

  > Delimited text should remain ordinary editable text while displaying quote-aware columns in consistent visual alignment. Users must be able to navigate between rows and fields, and changing the delimiter or editing values must update alignment without altering file contents. CSV, TSV, quoted delimiters, and diff views need defined behavior; ordinary files and existing editor interactions must remain unchanged.
- **Trace:**

  > Current main does not register CSV or TSV as built-in languages; src/vs/workbench/services/languageDetection/browser/languageDetectionWebWorker.ts explicitly treats CSV as not built in. The model-to-view path runs through ViewModelLinesFromProjectedModel in src/vs/editor/common/viewModel/viewModelLines.ts and ViewModel._getViewLineRenderingData in src/vs/editor/common/viewModel/viewModelImpl.ts, then generic rendering in src/vs/editor/common/viewLayout/viewLineRenderer.ts. Those paths currently know about wrapping, tabs, decorations, and injected text but not delimiter parsing or cross-line column widths. The boundary is to preserve underlying text, selections, cursor/model coordinate mapping, and rendering for every non-delimited language. The uncertainty starts at whether this should be a core CSV mode, a reusable editor primitive exposed to extensions, or a combination; the maintainer comment at https://github.com/microsoft/vscode/issues/145092#issuecomment-1069372279 also expands the design target to Markdown tables.
- **Open decisions:**
  - Should VS Code own a built-in CSV/TSV language mode, expose a reusable delimiter-aware editor capability to extensions, or provide both?
  - Which delimiter-selection contract should users see: automatic detection with an explicit status-bar override, language-specific configuration, or separate CSV and TSV modes?
  - For large files, should displayed column widths be exact across the document or intentionally sampled from a bounded range, and how should that approximation be communicated?
  - Is the first supported scope limited to single-line quoted fields, or must multiline quoted values be part of the initial public behavior?
