# Issue #326263 — hovering over run buttons sometimes moves the gutter and prevents test run buttons from working

[https://github.com/microsoft/vscode/issues/326263](https://github.com/microsoft/vscode/issues/326263)

## Summary

Plausible intermittent race between test-decoration invalidation/re-render and the gutter mouse target after a test run finishes, but the reporter can't reliably reproduce it and I found no conclusive proof in source — this needs area-owner investigation, not a close.

## Change summary

After running/debugging a test via the gutter run button, hovering the button again to re-run sometimes shifts the gutter and the click no longer hits the run action, roughly 20% of the time.

## Best solution

Route to the testing area owners to investigate the decoration refresh path in src/vs/workbench/contrib/testing/browser/testingDecorations.ts — likely the 100ms debounced `invalidate()` triggered by `results.onTestChanged`/`onResultsChanged` recreating glyph-margin decorations shortly after a run finishes, which could shift the gutter glyph under an active hover/click.

## Evidence

- **click gating:** RunTestDecoration.click() (line 946) only acts when e.target.type === MouseTargetType.GUTTER_GLYPH_MARGIN with the matching glyphMarginLane; if the decoration/lane shifts between hover and click, the click would silently no-op, matching the reported 'run button stops working'.
- **no recent fix:** git log on testingDecorations.ts shows no recent commit addressing this race; only an unrelated markdown API version bump (97e7e43d).
