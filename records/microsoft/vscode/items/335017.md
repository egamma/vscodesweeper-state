# Issue #335017 — Support opening a PR directly in a browser instead of PR view in agents window

[https://github.com/microsoft/vscode/issues/335017](https://github.com/microsoft/vscode/issues/335017)

## Summary

This team-authored, under-discussion request identifies a real gap in the Agents Window pull-request picker: PR rows can open through the contributed in-window PR view, but they provide no explicit browser-opening action. It should remain open while maintainers choose the interaction.

## Change summary

Provide a way to open a pull request from the Agents Window pull-request pill directly in the system browser instead of the contributed PR view.

## Best solution

Give each pull-request entry an explicit, accessible “Open in Browser” path while retaining the useful in-window PR experience; maintainers should first decide whether browser opening is a secondary affordance or the row's primary behavior.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts`, `src/vs/sessions/contrib/chat/test/browser/sessionChatInputToolbar.test.ts`, `src/vs/sessions/contrib/github/browser/pullRequestActions.ts`, `src/vs/sessions/contrib/github/test/browser/pullRequestActions.test.ts`
- **Validation:** Add focused unit coverage asserting that a selected PR entry exposes the chosen browser-opening interaction and that it opens the PR URI externally without contributed-opener interception; run the Sessions chat-input-toolbar and pull-request-action unit suites.
- **Behavior:**

  > The Pull Requests status-pill UI must provide an explicit, discoverable way to open any listed pull request in the system browser without the GitHub Pull Requests extension redirecting it to the in-window PR view. The existing copy-URL action must remain available, and the new interaction must be keyboard accessible and clearly labeled. Multiple PR entries must each act on their own URI.
- **Trace:**

  > buildSessionPullRequestSections in src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts constructs the dropdown rows shown in the issue screenshot. Each row currently has a copy toolbar action, while its open callback invokes workbench.agentSessions.action.openPullRequest. OpenPullRequestAction in src/vs/sessions/contrib/github/browser/pullRequestActions.ts passes allowContributedOpeners: true, which intentionally enables the in-window PR experience established by https://github.com/microsoft/vscode/pull/334222 and https://github.com/microsoft/vscode-pull-request-github/pull/8922. Keep the scope to pull-request opening from the Agents Window picker; do not change global URL-opener behavior, issue-pill behavior, or copy semantics.
- **Open decisions:**
  - Should selecting the PR row continue opening the in-window PR view with “Open in Browser” as a secondary action, or should browser opening become the row's primary behavior?

## Evidence

- **current picker behavior:** In src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts, buildSessionPullRequestSections gives each PR row only a Copy pull request URL toolbar action; entry.open executes workbench.agentSessions.action.openPullRequest.
- **contributed opener path:** src/vs/sessions/contrib/github/browser/pullRequestActions.ts opens the PR URI with openExternal: true and allowContributedOpeners: true, permitting GitHub Pull Requests to intercept the URL and show its in-window PR view.
- **test coverage:** src/vs/sessions/contrib/github/test/browser/pullRequestActions.test.ts explicitly verifies that Open Pull Request allows contributed external URI openers, while src/vs/sessions/contrib/chat/test/browser/sessionChatInputToolbar.test.ts verifies the existing open and copy actions.
- **intentional existing integration:** https://github.com/microsoft/vscode/pull/334222 and https://github.com/microsoft/vscode-pull-request-github/pull/8922 intentionally established the contributed-opener path for opening the PR webview; they predate this request and do not provide the requested alternate browser action.
- **issue evidence:** The screenshot in https://github.com/microsoft/vscode/issues/335017 shows the multi-PR status-pill picker with PR rows and a copy affordance, matching the current source path.
