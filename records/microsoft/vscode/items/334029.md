# Issue #334029 — Agent host Copilot's built in shell tool does not respect vscode terminal profile

[https://github.com/microsoft/vscode/issues/334029](https://github.com/microsoft/vscode/issues/334029)

## Summary

Real, technically-grounded gap: with the SDK's built-in shell tool enabled (customTerminalTool.enabled=false), the agent host spawns a non-PTY child process that only partially inherits terminal-profile settings, not the full profile experience. Already correctly labeled (feature-request, chat-terminal, agent-host); keep open for the area owners to scope the remaining work.

## Change summary

When Copilot's agent host uses the SDK's own built-in shell tool instead of VS Code's PTY-backed terminal, it does not respect terminal profile settings like chat.tools.terminal.terminalProfile.<os>.

## Best solution

Have chatAgentTools/agentHost owners decide how much of the terminal-profile surface (args, env, cwd, not just the shell binary) should be forwarded into the SDK shell tool's root config, extending src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostTerminalContribution.ts and the AgentHostRootConfigForwarder alongside it.
