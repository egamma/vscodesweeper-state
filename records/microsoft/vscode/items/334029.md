# Issue #334029 — Agent host Copilot's built in shell tool does not respect vscode terminal profile

[https://github.com/microsoft/vscode/issues/334029](https://github.com/microsoft/vscode/issues/334029)

## Summary

Keep open: the current profile bridge configures host-managed terminals, but does not supply the preferred shell to Copilot's default SDK shell tool. This team-authored request has no verified fixing commit or older canonical covering the same symptom.

## Change summary

Make Copilot Agent Host's built-in SDK shell honor the configured chat terminal profile across operating systems.

## Best solution

Establish profile-selection parity for the SDK-owned shell through the Copilot provider integration, without requiring the custom PTY tool. Settle the configuration precedence and supported profile properties before implementation.

- **Validation:** After settling the contract, configure distinguishable supported shell profiles on Windows and a POSIX platform, leave chat.agentHost.customTerminalTool.enabled=false, and verify agent commands execute in the selected shell in fresh and resumed conversations. Add focused bridge/provider tests asserting the agreed shell selection reaches SDK configuration, with unchanged behavior when no explicit profile is configured.
- **Behavior:**

  > Moving from local chat to Copilot Agent Host should retain the user's configured agent-shell preference while using the built-in SDK shell tool. The acceptance contract must identify which setting selects that shell and which profile properties are supported. Verify selection with distinguishable shells on Windows and POSIX, including fresh and resumed conversations. Users should not need to enable the custom PTY tool to obtain the agreed behavior.
- **Trace:**

  > AgentHostTerminalContribution._resolveDefaultShell resolves terminal.integrated.agentHostProfile.<os> with default-profile fallback and forwards only profile.path as AgentHostConfigKey.DefaultShell. Copilot's host-managed shell tools consume terminalManager.getDefaultShell(), but CopilotSessionLauncher creates those tools only for the enabled custom-tool path on non-Windows platforms. The default SDK session configuration does not supply the resolved shell selection; CopilotAgentSession separately updates SDK shell initScripts, which is not executable-profile selection. The trace stops at the SDK boundary: support for selecting executable, args, and env has not been established. Preserve the default SDK execution model and existing permission/sandbox behavior; restoring PTY execution is not the requested outcome. Related https://github.com/microsoft/vscode/issues/313790 and https://github.com/microsoft/vscode/issues/313809 cover distinct profile concerns rather than this request.
- **Open decisions:**
  - When chat.tools.terminal.terminalProfile.<os> and terminal.integrated.agentHostProfile.<os> differ, which preference should select the Copilot SDK shell, and what fallback should apply?
  - Does profile parity cover only shell executable selection, or also profile arguments and environment variables, and what should users observe for unsupported shell/profile combinations?
