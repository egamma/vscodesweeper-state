# Issue #318565 — "Publish to GitHub" defaults to broken HTTPS remote instead of SSH

[https://github.com/microsoft/vscode/issues/318565](https://github.com/microsoft/vscode/issues/318565)

## Summary

HTTPS is the intentional default, and the existing github.gitProtocol setting already makes Publish to GitHub use SSH. This capability also exists in the reporter's exact build; the reported terminal authentication failure does not establish that HTTPS remotes are inherently broken.

## Change summary

Use SSH rather than HTTPS for the remote created by Publish to GitHub so subsequent terminal pushes use SSH authentication.

## Best solution

Keep the configurable HTTPS default and use "github.gitProtocol": "ssh" for an SSH-based workflow. Any authentication failure that persists with properly configured HTTPS credentials should be investigated separately with the actual Git error and terminal context.

  > Thanks for the report. Publish to GitHub already supports SSH: set `"github.gitProtocol": "ssh"` in your user settings before publishing. This setting is available in your reported version and makes the new `origin` use `git@github.com:...`.

  > HTTPS remains the intentional default and supports token authentication; SSH also requires configured keys. If HTTPS pushes still fail, please provide the exact Git error and whether the command runs in VS Code's integrated terminal or an external terminal so that authentication problem can be investigated separately.
