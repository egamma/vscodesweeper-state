# Issue #341504 — Markdown preview blank under WSL

[https://github.com/microsoft/vscode/issues/341504](https://github.com/microsoft/vscode/issues/341504)

## Summary

Thanks for the detailed report. Webviews that load local resources fail under WSL on 1.141.1, and a commenter's diagnosis (authority case mismatch, `wsl+Ubuntu` vs the lowercased `wsl+ubuntu` in the resource hostname) is plausible. The webview `loadResource` comparison on current main already uses the case-insensitive `isEqualAuthority`, but the checkout has no history to show when that changed, so I can't tie it to this regression. The report is complete and the steps suffice to retest on a newer build, but a fix is unconfirmed.

## Change summary

Markdown preview and other webviews are blank in a WSL remote window, with 401 responses for vscode-resource URLs.

## Best solution

Confirm where the remote authority is compared case-sensitively on the webview resource path (the local-resource-root check or `remoteOS` resolution) and make every such comparison case-insensitive. `isEqualAuthority` in src/vs/base/common/resources.ts already does this.
