# Issue #290374 — Extend Profile Isolation to AI Configuration Files (Copilot Instructions, AGENTS.md, Prompts)

[https://github.com/microsoft/vscode/issues/290374](https://github.com/microsoft/vscode/issues/290374)

## Summary

Keep open and route to profiles and chat customizations. Current main already isolates user prompt, instruction, and custom-agent files by profile, but profile export/import, global-versus-profile precedence, and pattern-based profile activation remain unresolved parts of the request.

## Change summary

Make AI customizations portable and isolated with profiles, define their precedence relative to workspace and global instructions, and optionally activate profiles from workspace or language patterns.

## Best solution

Complete the profile-customization model by preserving workspace rules as the project authority, retaining a distinct global-personal layer, and including profile-scoped prompts, instructions, and agents in profile export/import. Treat automatic activation and chat-history isolation as separately scoped decisions rather than coupling them implicitly to prompt storage.

## Plan brief

- **Likely files:** `src/vs/platform/userDataProfile/common/userDataProfile.ts`, `src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts`, `src/vs/workbench/services/userDataProfile/browser/userDataProfileManagement.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/service/promptsService.test.ts`
- **Validation:** End the plan with profile-service tests proving that switching profiles changes the discovered user prompt/instruction/agent set, profile export/import round-trips those files, and the chosen workspace/profile/global precedence is deterministic; add activation tests if pattern-based activation remains in scope.
- **Behavior:**

  > AI prompt, instruction, and custom-agent files associated with one profile must not appear as another profile's personal customizations. Exporting and importing a profile must preserve the selected AI customizations. Workspace-owned rules and any retained global-personal rules must combine according to a documented, deterministic precedence model without writing profile artifacts into the workspace. If automatic activation remains in scope, opening a matching workspace must select the expected profile with defined behavior for multiple matches.
- **Trace:**

  > Current main already gives every profile a promptsHome in src/vs/platform/userDataProfile/common/userDataProfile.ts. PromptFilesLocator uses the current profile's promptsHome for PromptsType.prompt, PromptsType.instructions, and PromptsType.agent, while workspace AGENTS.md and related project files are discovered through separate workspace paths. The profile import/export template and fetch/apply paths in src/vs/workbench/services/userDataProfile/browser/userDataProfileImportExportService.ts omit prompt resources, so profile-local files are not portable through that mechanism. UserDataProfileManagement.getProfileToUseForCurrentWorkspace supports only exact workspace associations, not pattern or language matching. Preserve existing workspace discovery and do not silently collapse profile-scoped and global-personal sources; the uncertainty begins at their precedence and at whether export, automatic activation, and chat-history isolation belong in one deliverable.
- **Open decisions:**
  - Should this issue's first deliverable cover only prompt, instruction, and custom-agent portability, or also include automatic activation and chat-history isolation?
  - What is the observable precedence among workspace-owned rules, profile-scoped customizations, and non-profile-specific global personal customizations?
  - Should profile export/import include every file under promptsHome automatically or expose individual customization categories for selection?
  - If automatic activation remains in scope, which match inputs are supported and how are multiple matching profiles resolved?

## Evidence
