# Issue #299599 — MCP and C# Dev Kit sign-in fails repeatedly when MSAL broker is enabled — auth prompt loops or silently drops session

[https://github.com/microsoft/vscode/issues/299599](https://github.com/microsoft/vscode/issues/299599)

## Summary

Keep open: current source still permits a successfully authenticated broker account to be omitted from immediate session enumeration. The older related reports do not establish a canonical for this race, and the later confirmation without a working workaround warrants separate diagnosis.

## Change summary

Successful Microsoft sign-in should make the account immediately available to MCP and C# Dev Kit instead of causing repeated prompts or an apparently missing session.

## Best solution

Make successful account-access persistence and immediate broker account enumeration consistent in the built-in Microsoft authentication provider, preserving account-change notifications, revocation, and storage-error behavior. Assess the MCP scope-reset allegation separately against its existing test contract, and distinguish the later non-broker failure before claiming the entire report is resolved.

## Evidence

- **Current-source race:** extensions/microsoft-authentication/src/common/accountAccess.ts: ScopedAccountAccess.setAllowedAccess() persists the new allowed-account array without assigning this.value or awaiting update(); isAllowedAccess() reads this.value. Only the asynchronous storage-change listener refreshes that value. Therefore awaiting setAllowedAccess() does not guarantee that the newly allowed account is visible.
- **Exact failing consumer path:** extensions/microsoft-authentication/src/node/cachedPublicClientApplication.ts: acquireTokenInteractive() awaits setAllowedAccess(result.account, true), immediately invokes _update(), and returns the authentication result. _update() filters getAllAccounts() through isAllowedAccess() when the broker is available. extensions/microsoft-authentication/src/node/authProvider.ts enumerates cachedPca.accounts in getSessions() and getAllSessionsForPca(), so delayed storage notification can leave a successfully created session temporarily invisible.
- **Confirmed user impact and workaround limits:** The complete body of https://github.com/microsoft/vscode/issues/299599 includes C# Dev Kit logs showing createSession returning successfully followed milliseconds later by zero sessions. https://github.com/microsoft/vscode/issues/299599#issuecomment-4315194808 independently confirms repeated MCP authentication. https://github.com/microsoft/vscode/issues/299599#issuecomment-4660469008 reports recurrence on 1.124.0 and says msal-no-broker does not help; the workaround must not be presented as universal.
