# Issue #333112 — Cannot open github copilot chat in new window

[https://github.com/microsoft/vscode/issues/333112](https://github.com/microsoft/vscode/issues/333112)

## Summary

Real, actively-confirmed regression: opening the Copilot Chat editor in a new (auxiliary) window throws 'Not allowed to create elements in child window JavaScript context', reported against 1.135.0 with two independent commenters confirming it worked in 1.134.0. I traced the guard mechanism but couldn't pin the exact offending call site without executing the app (shallow checkout, no version history to bisect), so this needs area-owner triage rather than an auto-fix.

## Change summary

Opening the Copilot Chat panel/editor in a new (auxiliary) window fails with a DOM 'child window JavaScript context' error, introduced between 1.134.0 and 1.135.0.

## Best solution

A chat area owner should reproduce moving the chat editor to a new window and bisect 1.134.0→1.135.0 chat changes; the guard (src/vs/workbench/services/auxiliaryWindow/browser/auxiliaryWindowService.ts, createContainer) throws whenever code calls `<auxWindow>.document.createElement` directly instead of routing element creation through the main window (the DOM helpers in src/vs/base/browser/dom.ts). Chat already has a precedent for this exact pitfall — see the 'parks the pet of an auxiliary window host in the main realm' test in src/vs/workbench/contrib/chat/test/browser/widget/chatPetWidgetService.test.ts — so a similarly un-guarded call in a newer chat editor/widget code path is the likely culprit and should be located and fixed the same way.
