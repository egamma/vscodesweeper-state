# Issue #203285 — "Emmet: Update Tag" selects and updates the wrong tag.

[https://github.com/microsoft/vscode/issues/203285](https://github.com/microsoft/vscode/issues/203285)

## Summary

Still reproduces on main: the `@emmetio/html-matcher` parser does not correctly handle JSX attribute expressions like `element={<Home/>}`, causing `getHtmlFlatNode` to resolve the cursor position to the parent `Route` node rather than the `Home` self-closing tag. No fix has been applied to `updateTag.ts` or the parsing utilities.

## Change summary

"Emmet: Update Tag" selects the wrong (parent) tag when the cursor is on a self-closing JSX component inside a JSX attribute expression.

## Best solution

The underlying issue is that `@emmetio/html-matcher` doesn't understand JSX attribute expressions containing JSX elements. A fix would need to either improve the flat-node resolution in `getFlatNode` / `getHtmlFlatNode` to account for JSX self-closing tags inside attribute values, or use a JSX-aware parser for TSX/JSX files. This is consistent with the `emmet-parse` label already on the issue.
