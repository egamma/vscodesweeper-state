# Issue #327685 — Browser content is dimmed when a tooltip or other control is shown above the browser area

[https://github.com/microsoft/vscode/issues/327685](https://github.com/microsoft/vscode/issues/327685)

## Summary

The dimming is by design — the overlay manager hides the native WebContentsView and shows a screenshot with a semi-transparent overlay when any VS Code UI element overlaps the browser area, to prevent the native surface from rendering on top. However, applying the full dim+screenshot swap for small, transient overlays like tooltips is arguably too aggressive and creates a jarring visual effect. This is a real polish opportunity.

## Change summary

The integrated browser content dims noticeably whenever a VS Code tooltip, menu, or other overlay partially covers the browser area.

## Best solution

Refine the overlay-pause behavior in `webContentsViewRendererFeature.ts` to distinguish transient, small overlays (tooltips/hovers) from larger blocking ones (menus, dialogs, notifications). For small transient overlays, either skip the screenshot-swap entirely (letting them render above the WCV natively if Electron supports it), or reduce/remove the dim overlay tint. The 15% background-color tint in `.browser-overlay-paused` (browser.css line 522) is the visual source of the dimming.

## Evidence

- **overlay manager:** src/vs/workbench/contrib/browserView/electron-browser/overlayManager.ts defines OVERLAY_DEFINITIONS including 'monaco-hover', 'editor-widget', 'context-view', 'monaco-menu-container' — all trigger the obscured state when they overlap the browser container.
- **screenshot swap:** src/vs/workbench/contrib/browserView/electron-browser/features/webContentsViewRendererFeature.ts lines 209-253: `_shouldShowPage()` returns false when `_overlayObscured` is true, causing the native WCV to be hidden and replaced with a screenshot.
- **dim overlay CSS:** src/vs/workbench/contrib/browserView/electron-browser/media/browser.css lines 511-534: `.browser-overlay-paused` applies `background-color: color-mix(in srgb, var(--vscode-editor-background) 15%, transparent)` which creates the visible dimming. When `.show-message` (notifications), it increases to 60%.
- **design rationale:** The behavior exists because Electron's WebContentsView is a native surface rendered above the DOM — without hiding it, tooltips/menus would appear behind the browser content. The dimming signals the page is paused.
