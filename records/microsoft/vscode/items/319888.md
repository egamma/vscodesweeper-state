# Issue #319888 — vscode snap fails to start podman due to database static dir mismatch

[https://github.com/microsoft/vscode/issues/319888](https://github.com/microsoft/vscode/issues/319888)

## Summary

Keep open: the supplied workaround avoids a repeatedly confirmed Podman storage-path mismatch, but does not establish that VS Code's Snap integration is fixed. The related reports are closed, so none provides an open canonical for consolidation.

## Change summary

Podman launched from VS Code's Snap environment fails after an update because its recorded storage directory contains an older Snap revision.

## Best solution

Determine where the revision-specific storage environment reaches Podman and ensure ordinary Podman invocations retain a stable storage location across Snap updates. Preserve the reporter's portable workaround without treating it as proof that the underlying integration problem is resolved.
