## Change summary

Pushing through Source Control fails when a pre-push hook opens Cypress, while pushing from the terminal succeeds.

- **Validation:** In a disposable macOS test repository with a working remote and Cypress installed, configure an executable pre-push hook invoking npx cypress open. Acceptance: the GUI opens Cypress and completes the push when the hook succeeds, while a deliberately nonzero hook still prevents pushing.
- **Behavior:**

  > A pre-push hook that opens Cypress succeeds from terminal git push but reportedly prevents pushing through Source Control. Retest this comparison on a current build using the same repository, remote, hook, and Cypress installation. Successful hooks must allow the push to complete after Cypress exits; failing hooks must continue to block the push. The terminal workflow must remain unchanged.
- **Trace:**

  > Source Control push runs through Repository.push and _push in extensions/git/src/repository.ts, then the low-level push and Git.spawn in extensions/git/src/git.ts. Git.spawn inherits the extension-host environment and ignores stdin by default; extensionHostProcess.ts explicitly sets ELECTRON_RUN_AS_NODE=1. These are concrete compatibility leads, but the checkout does not establish which, if either, causes the reported Cypress failure. Diagnosis must begin with reproducing the GUI-versus-terminal difference and observing the hook's output and exit status. Preserve authentication helpers, extension process.execPath behavior, and normal Git hook semantics; bypassing hooks is outside scope. The error-presentation issue at https://github.com/microsoft/vscode/issues/178175 is related but does not establish a duplicate.
