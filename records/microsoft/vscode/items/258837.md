# Issue #258837 — Snippets not showing up in terminal

[https://github.com/microsoft/vscode/issues/258837](https://github.com/microsoft/vscode/issues/258837)

## Summary

Keep open: terminal REPL suggestions still do not include the editor's snippet provider. The older terminal-snippets request is related, but does not establish coverage of this report's specific editor-to-REPL gap under the stronger re-review duplicate rule.

## Change summary

Make existing editor snippets available in terminal REPL suggestions for quick scripting.

## Best solution

Provide language-appropriate editor snippets in supported terminal REPLs, with explicitly defined expansion and acceptance behavior. Coordinate with the terminal-snippets work without treating shell-command aliases as equivalent to existing language snippets.

- **Validation:** Create a Python user snippet with a distinctive prefix and body, confirm it appears in a Python editor, then invoke terminal suggestions at that prefix in a shell-integrated Python REPL with the LSP provider enabled. Verify that the snippet appears and acceptance produces the agreed expansion behavior rather than its label or literal snippet syntax. Add targeted terminal suggestion tests for that contract and verify ordinary completion acceptance remains unchanged.
- **Behavior:**

  > Existing editor snippets are absent from terminal REPL suggestions even when language completions are available. The goal is to offer language-appropriate snippets in supported REPLs and make acceptance insert useful snippet content rather than the displayed prefix. Acceptance checks should compare the same snippet in an editor and a Python terminal REPL, covering a plain-text body and the agreed behavior for placeholders and multiline bodies. Existing non-snippet suggestions and their configured acceptance behavior must remain unchanged.
- **Trace:**

  > TerminalSuggestContribution._loadLspCompletionAddon in src/vs/workbench/contrib/terminalContrib/suggest/browser/terminal.suggest.contribution.ts enumerates the normal completion-provider registry for a virtual language document. SnippetsService registers SnippetCompletionProvider separately through setSnippetSuggestSupport, and the editor's provideSuggestionItems explicitly queries that separate provider; the terminal does not. LspCompletionProviderAddon.provideCompletions currently carries labels and documentation but not snippet insertion semantics, while SuggestAddon.acceptSelectedSuggestion emits inputData or label-derived terminal input. These source paths establish the missing capability without executing the checkout. Preserve ordinary language and shell completions; do not broaden the work into shell alias injection or configurable Fig specifications. https://github.com/microsoft/vscode/issues/210983 is related design context, and https://github.com/microsoft/vscode/pull/236592 is a closed, unmerged prototype, not a fix. The unresolved boundary is how editor placeholders and multiline snippet bodies should behave in a terminal REPL.
- **Open decisions:**
  - Should terminal REPL snippets support editable placeholder navigation, or expand to plain text using placeholder defaults without an interactive snippet session?
  - How should accepting a multiline snippet interact with REPL submission: stage it for editing, or submit its lines under defined execution behavior?
