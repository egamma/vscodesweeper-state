# Issue #296890 — Agent mode: sending message mid-response sometimes forks session into two parallel agents, causing conflicting edits and JSONL corruption

[https://github.com/microsoft/vscode/issues/296890](https://github.com/microsoft/vscode/issues/296890)

## Summary

Keep open: the report supplies sufficient steps and a malformed-session excerpt to retest, but concurrent execution and its connection to corruption remain unconfirmed on current main. Request handling now includes queuing and bounded cancellation waiting; the linked open persistence PR addresses only one related failure path.

## Change summary

Prevent overlapping independent agent executions when a message interrupts an active response, and prevent associated session-log corruption.

## Best solution

Establish whether interrupting an active agent can leave its tool execution running alongside a replacement turn, and preserve session durability through that transition. Review the existing persistence-hardening PR separately; its serializer fallback does not establish a fix for overlapping execution or interleaved writes.
