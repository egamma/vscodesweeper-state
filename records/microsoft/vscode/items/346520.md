# Issue #346520 — agentHost: SQLite database breaks on WEKAFS with WAL

[https://github.com/microsoft/vscode/issues/346520](https://github.com/microsoft/vscode/issues/346520)

## Summary

Current main still enables WAL on WekaFS despite the journal helper's explicit requirement for local storage. Keep this open while the linked fix PR is reviewed; the unsafe journal selection is confirmed from source, although actual corruption was not exercised.

## Change summary

Prevent Agent Host databases on shared WekaFS storage from using SQLite WAL across machines.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/346521 so WekaFS retains the rollback journal, while local filesystems retain WAL. Confirm journal selection for both fresh databases and databases previously opened in WAL mode.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/346520 reports database corruption when two Ubuntu hosts use Agent Host with shared WekaFS storage after the WAL change in https://github.com/microsoft/vscode/pull/345014.
- **Current source:** src/vs/platform/agentHost/node/agentHostSqliteJournal.ts omits WekaFS from LINUX_NETWORK_FILE_SYSTEM_TYPES. For Linux statfs type 0x18031977, canUseWriteAheadLog therefore returns true, and configureSqliteJournal requests PRAGMA journal_mode = WAL and synchronous = NORMAL. The helper documents that WAL's shared-memory index cannot be shared between machines.
- **Affected database paths:** AgentHostDatabase._ensureDatabase calls configureSqliteJournal in src/vs/platform/agentHost/node/agentHostDatabase.ts:4511; SessionDatabase._ensureDb uses the same helper in src/vs/platform/agentHost/node/sessionDatabase.ts:697.
- **Open implementation candidate:** The supplied timeline identifies https://github.com/microsoft/vscode/pull/346521 as open. Its retrieved diff adds WekaFS type 0x18031977 to the exclusions and a Linux WekaFS case expecting false in src/vs/platform/agentHost/test/node/agentHostSqliteJournal.test.ts. Those changes are absent from the checkout; the issue must remain open pending the existing PR.
- **Verification boundary:** Read-only source inspection confirms the unsafe journal-selection path, not observed corruption on a live WekaFS mount. Existing journal tests cover rollback mode on network storage and conversion of a database previously opened locally in WAL mode; no tests were executed.
