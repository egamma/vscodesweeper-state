# Issue #127703 — Add cursor stops around inlay hints

[https://github.com/microsoft/vscode/issues/127703](https://github.com/microsoft/vscode/issues/127703)

## Summary

Keep open: injected-text support provides visual positions around hints, but horizontal navigation still skips between them and no setting offers the requested alternative. Maintainers expressed interest in trying additional stops; their multicursor and wrapping concerns remain unresolved product decisions.

## Change summary

Allow intuitive cursor placement around inlay hints when navigating horizontally and editing adjacent code.

## Best solution

Agree on an inlay-hint navigation policy that makes prefix and suffix hints intuitive to edit around, potentially through an opt-in mode. Preserve existing document-position semantics and explicitly settle how additional visual stops interact with multiple cursors and wrapped lines.

- **Behavior:**

  > Visible inlay hints should not make keyboard placement beside the associated code feel direction-dependent or misleading. The remaining request is to visit both visual edges, or provide an agreed alternative attachment policy, without treating hint text as document content. Acceptance must specify left/right traversal for prefix and suffix hints, newline insertion beside parameter hints, and explicit annotation insertion beside return-type hints. Multiple cursors, wrapped lines, and asynchronously appearing hints must follow the policy agreed with the maintainer.
- **Trace:**

  > InlayHintsController in src/vs/editor/contrib/inlayHints/browser/inlayHintsController.ts creates injected label and padding decorations with Right/None cursor-stop values. MoveOperations.moveLeft and moveRight in src/vs/editor/common/cursor/cursorMoveOperations.ts normalize with directional affinity before advancing, and ModelLineProjectionData in src/vs/editor/common/modelLineProjectionData.ts resolves that affinity to the outer injection edge. Thus adding injected text or changing decoration stop values alone does not establish successive visits to both visual edges. EditorInlayHints in src/vs/editor/common/config/editorOptions.ts exposes no navigation policy. The maintainer discussion at https://github.com/microsoft/vscode/issues/127703#issuecomment-883184565 and https://github.com/microsoft/vscode/issues/127703#issuecomment-885046276 establishes deliberate multicursor and wrapping invariants but leaves the alternative behavior open. Keep document contents, language-provider contracts, and hint actions outside the navigation change; mouse snapping in https://github.com/microsoft/vscode/issues/326158 is separate work.
- **Open decisions:**
  - Should the editor offer successive stops at both hint edges, a fixed prefix/suffix attachment-side policy, or both—and should the existing behavior remain the default?
  - When multiple cursors encounter hints at different positions, may an arrow press advance only some model positions while others move between visual edges?
  - Should extra stops apply only to inlay hints, including hints spanning wrapped lines, or also change navigation at ordinary wrapped-line boundaries?
