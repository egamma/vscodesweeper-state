# Issue #331835 — Too many ways to pick mode for Claude harness

[https://github.com/microsoft/vscode/issues/331835](https://github.com/microsoft/vscode/issues/331835)

## Summary

Legitimate UX confusion report: VS Code's own chat mode picker (Agent/Plan/Ask/Edit) and Claude's provider-specific `permissionMode` picker (which includes its own 'Plan Mode' option) are both surfaced in the Agents window input area, and their overlapping 'Plan' terminology makes it unclear which control does what.

## Change summary

When using the Claude harness in the Agents window, there are two separate mode pickers shown side by side, and one of them has a 'Plan Mode' option that is easily confused with VS Code's own Agent/Plan chat mode selector.

## Best solution

Clarify or consolidate the two pickers so their scopes are visually distinct — e.g. rename/relabel Claude's `permissionMode: 'plan'` option (currently labeled 'Plan Mode' in src/vs/sessions/contrib/providers/agentHost/browser/agentHostClaudePermissionModePicker.ts) to avoid colliding with VS Code's built-in Plan chat mode, or restructure the input toolbar so the provider-specific approvals picker and the built-in mode picker are clearly separated. The interaction between the two is already coordinated in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostModeSynchronizer.ts, so this is squarely an Agent Sessions / agentHost UX design question for the team owning that surface.
