# Issue #75426 — Breakpoint moves with copy line up/down action

[https://github.com/microsoft/vscode/issues/75426](https://github.com/microsoft/vscode/issues/75426)

## Summary

Keep open as under discussion: maintainers confirmed that choosing whether line-associated state follows the original or copied line is an unresolved behavior decision, not a clearly broken contract. The Backlog Candidates milestone and low vote count do not establish a closing reason.

## Change summary

Decide whether Copy Line Up/Down should leave breakpoints and other line-associated state on the original line rather than moving them with the copied text.

## Best solution

The editor and debug owners should define one consistent semantic for tracked decorations during Copy Line Up/Down, then document and test that behavior; the decision must account for extension-owned state that core cannot generically duplicate.
