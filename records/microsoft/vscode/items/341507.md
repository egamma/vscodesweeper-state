# Issue #341507 — Sanboxing is very confusing when it needs additional policies

[https://github.com/microsoft/vscode/issues/341507](https://github.com/microsoft/vscode/issues/341507)

## Summary

Team-authored report, so it stays open. The sandbox failure message points users at `sandbox.userPolicy.network.allowLocalNetwork`, which is a managed-settings key and not a VS Code setting, and the model also suggests signing in with the integrated browser. The messaging and model guidance need to be clearer.

## Change summary

When the sandbox needs extra network policy, the guidance names a non-VS Code setting key and suggests signing in with the integrated browser, which confuses users.

## Best solution

Make sandbox-block guidance name the real, user-editable VS Code setting (`chat.agent.sandbox.network.allowLocalNetwork`) when it is not policy-managed, and say when it is managed. Also stop the agent from suggesting integrated-browser sign-in.
