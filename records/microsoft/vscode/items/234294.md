# Issue #234294 — Feature Request: Expose findWidget Actions State via API

[https://github.com/microsoft/vscode/issues/234294](https://github.com/microsoft/vscode/issues/234294)

## Summary

Keep open in the API backlog: extensions still cannot read the Find Widget toggles or set them through the toggle commands. The existing find-with-arguments command sets explicit values but opens and focuses Find, so it does not fully cover the requested selection workflow.

## Change summary

Expose the Find Widget's case-sensitive, whole-word, and regex state to extensions, or allow explicit state changes without disrupting editor selection.

## Best solution

Have the API owners decide whether to expose readable find state or provide deterministic option-setting commands that preserve editor focus and selection. Keep the custom Atom/Pulsar selection behavior in an extension; the core request is the integration contract it needs.

## Evidence

- **Public API gap:** src/vscode-dts/vscode.d.ts:690–731 defines TextEditorOptions with indentation, cursor style, and line-number options, but no find-state properties. Searching the stable and proposed declaration files found no corresponding Find Widget state API.
- **Toggle commands do not accept explicit state:** src/vs/editor/contrib/find/browser/findController.ts:1083–1127 registers toggleFindCaseSensitive, toggleFindWholeWord, and toggleFindRegex with handlers that invoke the controller's toggle methods without forwarding a requested boolean.
- **Existing capability is partial:** editor.actions.findWithArgs, identified in src/vs/editor/contrib/find/browser/findModel.ts:63 and implemented by StartFindWithArgsAction in findController.ts:618–674, accepts isRegex, matchWholeWord, and isCaseSensitive. However, it starts Find with shouldFocus set to FocusFindInput and reveals the widget; it neither returns current state nor provides a focus-preserving option setter for the reported Cmd+D workflow.
