# Issue #331493 — Chat session history randomly disappears from the Chat panel when the workspace folder is on a NAS (UNC path)

[https://github.com/microsoft/vscode/issues/331493](https://github.com/microsoft/vscode/issues/331493)

## Summary

Verified duplicate of the older open workspace-storage identity issue: both reports show Copilot chat sessions becoming inaccessible when different path spellings for the same physical folder produce separate workspace storage buckets.

## Change summary

Keep Chat session history associated with the same physical NAS workspace when it is opened through different UNC, hostname, IP, or mapped-drive spellings.

## Best solution

Consolidate the NAS evidence on https://github.com/microsoft/vscode/issues/313681 and resolve workspace identity there, preserving stable per-workspace state without changing how paths are presented to users.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/313681 is open, predates this report, and explicitly tracks raw-path-derived duplicate `workspaceStorage` buckets causing Copilot chat sessions and other per-workspace state to diverge for different spellings of the same physical folder.
- **same observable symptom:** The canonical describes Copilot chat sessions accumulating independently and silently diverging between buckets; this report observes the corresponding Chat history disappearance while the session data remains intact in another bucket. The NAS/UNC environment is unique evidence for the same user-visible failure.
- **source trace:** src/vs/platform/windows/electron-main/windowsMainService.ts passes the opened path and its stat to getSingleFolderWorkspaceIdentifier; src/vs/platform/workspaces/node/workspaces.ts hashes folderUri.fsPath plus birth time, so alternate UNC, hostname, IP, or mapped-drive spellings produce different IDs even for the same folder.
- **chat storage dependency:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts derives both the chatSessions directory and the WORKSPACE-scoped `chat.ChatSessionStore.index` from the current workspace ID, explaining why sessions remain on disk but disappear from the active history.
