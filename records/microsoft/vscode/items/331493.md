# Issue #331493 — Chat session history randomly disappears from the Chat panel when the workspace folder is on a NAS (UNC path)

[https://github.com/microsoft/vscode/issues/331493](https://github.com/microsoft/vscode/issues/331493)

## Summary

Traced the mechanism in source: workspace identity (and thus the per-workspace chat/session storage bucket) is a hash of the raw URI string (`getWorkspaceId` in workspaceIdentifier.ts), so any change in how the UNC path resolves (hostname vs IP, mapped drive vs UNC, transient unreachability) produces a different hash and a 'new' storage bucket, matching the reporter's observed dual-hash behavior. This is a real, if niche, defect, but the fix requires a deliberate identity-normalization design (the file explicitly warns 'DO NOT CHANGE. IDENTIFIERS HAVE TO REMAIN STABLE'), so it needs a maintainer/area-owner decision rather than an automatic patch.

## Change summary

Chat/session history for a NAS-hosted (UNC) workspace folder appears to vanish because the workspace identity hash changes when the same physical folder is accessed via a different path form, splitting storage across multiple `workspaceStorage` buckets.

## Best solution

Route to the workspaces/storage area owners to evaluate normalizing workspace identity for UNC/network paths (e.g. resolving hostname vs IP, mapped-drive vs UNC spelling) before hashing in src/vs/platform/workspaces/common/workspaceIdentifier.ts — likely in coordination with the related https://github.com/microsoft/vscode/issues/313681, which reports the same 'hash of raw path string' root cause for symlinked/OneDrive folders on macOS. Any fix must be designed carefully since workspace identifiers are documented as required to stay stable.
