# Issue #325647 — Agents window: SSH fails with "no matching host key format" on hosts using OpenSSH host certificates

[https://github.com/microsoft/vscode/issues/325647](https://github.com/microsoft/vscode/issues/325647)

## Summary

Confirmed from source: the Agents window SSH path uses the Node.js `ssh2` library directly, which does not support `*-cert-v01@openssh.com` host key types. The `ConnectConfig` built in `_connectSSH` sets no `algorithms` override, so negotiation fails on hosts presenting only certificate host keys. This is a real gap versus the Remote-SSH extension (which shells out to the system `ssh` binary).

## Change summary

Agents window SSH connection fails on hosts that present OpenSSH host certificates because the underlying `ssh2` library does not support certificate host key formats.

## Best solution

Either configure `ssh2`'s `algorithms.serverHostKey` to include the certificate types if an upstream release adds support, or — more robustly — offer a code path that delegates to the system `ssh` binary (like Remote-SSH does) for the transport/tunnel. The fix area is `src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts`, specifically `_connectSSH` and `_createSSHClient`. If the `ssh2` library cannot feasibly support host certificates, this may need an `upstream` dependency fix or a fallback architecture change.
