- **Intended voice behavior:** https://github.com/microsoft/vscode/issues/342070 explicitly requires voice answers to resolve the exact pending interaction through normal confirmation paths, and complete question answers to submit once. This is the test plan cited by the reporter, not a duplicate of this defect.
- **External answer path:** src/vs/workbench/contrib/chat/browser/voiceClient/voiceToolDispatchService.ts:495-549, VoiceToolDispatchService._answerCarousel, marks the carousel used through dismiss() or direct assignment and notifies the chat service. Unlike the local submission callback, this path does not directly clear the input carousel.
- **Renderer retains the resolved part:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts:2023-2028, hasSameContent, returns true for the same carousel object once carousel.isUsed is true, even when the response completes. This permits retention of the existing input part instead of rerunning the used-carousel cleanup in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:5263-5289.
- **Close-button symptom:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts:666-668, ignore(), immediately returns false when carousel.isUsed is true. A stale form already resolved by voice therefore cannot dismiss itself through that action; the duplicate-submission guard itself remains necessary.
