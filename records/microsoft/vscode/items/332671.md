# Issue #332671 — Korean IME composition text renders incorrectly in the integrated terminal when Modern UI is enabled

[https://github.com/microsoft/vscode/issues/332671](https://github.com/microsoft/vscode/issues/332671)

## Summary

Fresh, well-diagnosed report of a real Modern UI regression: the terminal's Modern UI padding CSS shifts `.xterm-helpers` down without any compensating change to xterm.js's internal composition-view coordinate math, which is exactly consistent with the reported cursor-detached IME overlay.

## Change summary

With `workbench.experimental.modernUI` enabled, Korean (and other) IME composition text in the integrated terminal renders detached from the actual cursor position.

## Best solution

In src/vs/workbench/contrib/modernUI/browser/media/padding.css, the rule that offsets `.xterm .xterm-helpers { top: var(--vscode-spacing-size80); }` to compensate for the `.xterm` padding-block added by Modern UI needs to be reconciled with xterm.js's own composition-view positioning, which computes the overlay position relative to the terminal's cell grid and does not account for this CSS-only shift — the terminal/xterm owners should either avoid shifting `.xterm-helpers` directly or find an offset approach that keeps `.composition-view` positioning correct.

## Evidence

- **modernUI padding rule:** src/vs/workbench/contrib/modernUI/browser/media/padding.css adds `.modern-ui...pane-body.integrated-terminal .xterm { padding-block: var(--vscode-spacing-size80); }` and `.xterm .xterm-helpers { top: var(--vscode-spacing-size80); }`, shifting the absolutely-positioned helpers container that hosts xterm.js's `.composition-view` overlay.
- **xterm.js base CSS:** src/vs/workbench/contrib/terminal/browser/media/xterm.css keeps `.xterm-helpers { position: absolute; top: 0; }` upstream — xterm.js's CompositionHelper computes `.composition-view` left/top from the cell grid assuming that baseline, so the Modern UI override introduces exactly the kind of offset mismatch the reporter describes.
- **reporter confirmation:** Reporter states the issue only appears with `workbench.experimental.modernUI` on, disappears when off, and reproduces even with English display language — consistent with a CSS/layout cause rather than IME/localization logic.
- **commit context:** The padding.css xterm rule was introduced together with the rest of the Modern UI padding module (current HEAD 79ee2233); no related fix exists yet.
