# Issue #309246 — NesXtabHistoryTracker stores many copies of really large documents

[https://github.com/microsoft/vscode/issues/309246](https://github.com/microsoft/vscode/issues/309246)

## Summary

Keep open: current source still retains full document versions in history bounded only by entry count, matching the reported memory-retention path. This team-authored report remains necessary; no verified fix or qualifying canonical duplicate was found.

## Change summary

Prevent NES cross-tab history from retaining hundreds of megabytes of full-document snapshots after opening and editing very large files.

## Best solution

Bound retained document content in NesXtabHistoryTracker across both edit and visible-range history while preserving useful history for ordinary documents. Cover oversized documents and repeated non-merging edits with focused retention-bound regression tests.
