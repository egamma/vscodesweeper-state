# Issue #309246 — NesXtabHistoryTracker stores many copies of really large documents

[https://github.com/microsoft/vscode/issues/309246](https://github.com/microsoft/vscode/issues/309246)

## Summary

Still reproduces on main: NesXtabHistoryTracker bounds history by entry count (50) but not by memory — each entry retains full StringText base/content for large documents, causing ~700MB retention for a 37MB file.

## Change summary

NesXtabHistoryTracker retains many full copies of large documents in memory because history is bounded only by entry count, not by total memory footprint.

## Best solution

Add a memory-aware eviction policy to NesXtabHistoryTracker (e.g. cap total retained bytes, skip or compress entries for very large documents, or avoid storing full StringText base when the document exceeds a size threshold). The fix lives in `extensions/copilot/src/platform/inlineEdits/common/workspaceEditTracker/nesXtabHistoryTracker.ts`.
