# Issue #262472 — Perf: showing Chat view on startup is slow

[https://github.com/microsoft/vscode/issues/262472](https://github.com/microsoft/vscode/issues/262472)

## Summary

Keep open as accepted performance debt: several targeted optimizations landed, but current source still synchronously constructs the sessions, welcome, and full Chat controls during secondary-sidebar startup, and later profiling continued to show substantial initial-render cost.

## Change summary

Reduce the 200–300 ms startup overhead caused by showing the Chat view in the secondary sidebar.

## Best solution

Establish a current startup budget for the Chat view, profile the remaining synchronous work in `createControls` and `createChatControl`, and reduce or defer nonessential sessions and welcome work while keeping the input promptly usable.

The chat input must become usable promptly, and welcome content and recent sessions must still appear correctly. Acceptance requires a before/after startup trace for the same workspace and configuration, with no regression in first-input availability or empty-chat rendering.
- **Trace:**

  > `ChatViewPane.createControls` in `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts` synchronously creates the sessions control, extension welcome controller, and Chat widget. `createSessionsControl` immediately instantiates `AgentSessionsControl`, while `ChatWidget.renderWelcomeViewContentIfNeeded` creates `ChatViewWelcomePart`, whose constructor can synchronously invoke the Markdown renderer. Earlier fixes reduced duplicate welcome rendering and eager suggest-widget setup, but January profiling still placed most of the 182 ms opening cost under `createChatControl`, and current source retains these eager paths. Preserve prompt-input availability and existing sessions/welcome behavior; the plan should first obtain a fresh component-level trace and identify which work is necessary before first interaction. Related long-history work at https://github.com/microsoft/vscode/issues/263896 is outside this initial empty-view boundary.
- **Open decisions:**

  - Which visible elements must be present before the input becomes interactive, and which welcome or recent-session content may appear afterward?

## Evidence

- **measured impact:** The issue includes perf-bot traces showing a 200–300 ms increase when Chat is shown in the secondary sidebar; later maintainer profiling still measured 182 ms to open it, with 97 ms under `createChatControl`.
- **current startup path:** `ChatViewPane.createControls` in `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts` synchronously calls `createSessionsControl`, creates `ChatViewWelcomeController`, and then calls `createChatControl`; `createSessionsControl` immediately instantiates `AgentSessionsControl` and its supporting toolbar/filter UI.
- **remaining welcome cost:** `ChatWidget.renderWelcomeViewContentIfNeeded` in `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts` still creates `ChatViewWelcomePart` for an empty chat, whose constructor in `src/vs/workbench/contrib/chat/browser/viewsWelcome/chatViewWelcomeController.ts` synchronously renders Markdown. The thread's January profile attributed about 15% of `createChatControl` to this path even when welcome content was not visible.
- **partial optimizations:** Merged PRs https://github.com/microsoft/vscode/pull/262611, https://github.com/microsoft/vscode/pull/262753, https://github.com/microsoft/vscode/pull/262762, and https://github.com/microsoft/vscode/pull/268023 reduced rerendering and eager setup, but the later measurements and current source show that they did not eliminate the overall startup debt.
- **related tracking:** The later performance tracker https://github.com/microsoft/vscode/issues/286610 explicitly listed https://github.com/microsoft/vscode/issues/262472 as unfinished "Slow initial render" work. The open https://github.com/microsoft/vscode/issues/263896 concerns long-history rendering rather than this issue's empty/initial Chat-view startup symptom, so it is not a canonical duplicate.
