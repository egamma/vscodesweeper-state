# Issue #253001 — Pickers that require a button to confirm should not close on focus lost

[https://github.com/microsoft/vscode/issues/253001](https://github.com/microsoft/vscode/issues/253001)

## Summary

Keep open: confirmation-dependent pickers still have a focus-loss gap, including the current tools picker. The discussion accepts case-by-case improvements, while changing the default for every multi-select picker would affect existing extension behavior.

## Change summary

Keep pending selections available when an explicit-confirmation picker loses focus, without changing pickers that persist selections immediately.

## Best solution

Apply the thread's case-by-case direction to confirmation-dependent built-in pickers, starting with Configure Tools, while preserving existing extension API defaults and immediate-persistence workflows. Establish which other callers have the same staged-selection behavior before considering a shared policy.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts`, `src/vs/platform/quickinput/browser/tree/quickTree.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** In Configure Tools, change several checkbox selections, move focus to the editor or another window, return, and confirm: pending choices must remain available and become effective only on acceptance. Explicit Escape cancellation must still discard pending choices. Add focused quick-input coverage for the agreed affected callers and verify that ordinary dismissal and immediate-persistence pickers retain their existing behavior.
- **Behavior:**

  > A picker that stages selections until explicit confirmation should not discard that pending decision merely because focus moves elsewhere. Configure Tools currently follows that acceptance-dependent model. Acceptance checks must cover retaining pending choices across focus loss, applying them on confirmation, and preserving explicit cancellation. Pickers that already persist each selection must retain their existing interaction contract.
- **Trace:**

  > Configure Tools is implemented in src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts and creates a QuickTree without overriding focus-loss behavior. QuickTree inherits QuickInput's false ignoreFocusOut default; QuickInputController hides it on blur, and the tools picker returns selections only after onDidAccept sets didAccept. The existing ignoreFocusOut API provides caller-level control but does not identify whether arbitrary consumers persist on acceptance or selection changes. The discussion at https://github.com/microsoft/vscode/issues/253001#issuecomment-3062577804 accepts case-by-case fixes; preserve extension API defaults rather than infer persistence from button presence. The unresolved technical scope is which additional built-in callers stage choices and require the same protection; that audit has not been completed.
