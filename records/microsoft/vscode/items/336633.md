# Issue #336633 — New Worktree checkbox should be remembered per folder

[https://github.com/microsoft/vscode/issues/336633](https://github.com/microsoft/vscode/issues/336633)

## Summary

Team-authored, freshly filed report with a clearly traced root cause: the remembered session-config values (including the Isolation/"New Worktree" toggle) are stored under a single global storage key, not per folder, so the toggle doesn't track per-folder habits as the author describes.

## Change summary

Remember the New Worktree checkbox state per folder instead of globally, falling back to the last session's value for brand-new folders.

## Best solution

Key the remembered session-config values (at least Isolation) by workspace folder rather than a single profile-wide blob, with a sensible fallback to the last-used value for a folder with no history yet — a maintainer should decide whether this applies only to Isolation or to all remembered keys, and how it behaves for multi-root workspaces.

## Evidence

- **global storage key:** baseAgentHostSessionsProvider.ts:78 defines STORAGE_KEY_REMEMBERED_SESSION_CONFIG_VALUES = 'sessions.agentHost.sessionConfigPicker.selectedValues', a single blob stored at StorageScope.PROFILE (not per-workspace/folder).
- **remember on set:** _rememberSessionConfigValue (baseAgentHostSessionsProvider.ts:4053-4065) writes any 'rememberable' property — including SessionConfigKey.Isolation, since isRememberedSessionConfigKey (line 292) only excludes Branch, SandboxEnabled, and unsafe keys — into that same global-scope blob via _storageService.store(..., StorageScope.PROFILE, StorageTarget.MACHINE).
- **read on new session:** getSessionConfig/newSession config seeding (around line 3905 and 5289) reads rememberedValues from the same global StorageScope.PROFILE key, so the last-set value anywhere (any folder) seeds every new session's Isolation default, matching the reported cross-folder bleed (e.g. vscode vs vscode-internalbacklog).
