# Issue #226936 — CodeLens - Actual Command Not Found Error

[https://github.com/microsoft/vscode/issues/226936](https://github.com/microsoft/vscode/issues/226936)

## Summary

The CodeLens command-lifetime gap remains in current source: an offscreen refresh can release commands that the retained widget still exposes when scrolled back into view. Keep this report open; the linked merged PR adds readonly annotations, not a behavioral fix.

## Change summary

Prevent CodeLens refreshes with delayed resolution from leaving clickable links whose backing commands have already been disposed.

## Best solution

Make CodeLens widget interactivity and backing command lifetimes consistent throughout refresh, viewport changes, and asynchronous resolution. Preserve working reference navigation and avoid fixing the error by permanently making lenses unclickable.

## Evidence

- **Exact failing source path:** In src/vs/editor/contrib/codelens/browser/codelensController.ts, a provider change schedules a replacement model and retains the previous model in _oldCodeLensModels. _renderCodeLensSymbols reuses same-line widgets through updateCodeLensSymbols. In codelensWidget.ts, that method replaces _data and decorations without clearing the content widget's existing command map.
- **Offscreen disposal and delayed click:** CodeLensWidget.computeIfNecessary returns null for offscreen lenses. CodeLensContribution._resolveCodeLensesInViewport clears _oldCodeLensModels immediately when toResolve is empty, or after resolving only the visible widgets. Consequently, an offscreen widget can retain an old command after its model is disposed; scrolling back exposes that command until delayed resolution calls updateCommands. This matches the report's five-second refresh, offscreen wait, and click within the three-second resolution window.
