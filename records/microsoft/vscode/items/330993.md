# Issue #330993 — Modern UI: Tab action buttons have gradient effects even if not overlaid

[https://github.com/microsoft/vscode/issues/330993](https://github.com/microsoft/vscode/issues/330993)

## Summary

Traced in source: the Modern UI tab-actions hover gradient in tabs.css is applied unconditionally on `:hover`/`:focus-within` with no check for whether the actions column is actually overlaying the label (via the `.tab-actions-reserve-space` class or the dirty/sticky reserved-padding classes), so it shows even when space is already reserved and nothing is overlaid.

## Change summary

The Modern UI editor tab hover gradient (meant to fade the filename under the overlaid action buttons) is drawn even when `tabActionReserveSpace` reserves space and the buttons don't actually overlay the label, needlessly dimming the tail of the filename.

## Best solution

In src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css, scope the `::before` gradient selectors (around lines 380-478) to only apply when the tab does NOT already reserve space for the actions column — i.e. exclude `.tab-actions-reserve-space` tabs and the dirty/sticky cases that get `padding-right`/`padding-left` reservation per the rules in the styleOverrides tabs.css (lines ~167-180).

## Evidence

- **gradient rule:** src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css:380-393 applies `.tab:not(.close-action-off):hover > .tab-actions::before` with a linear-gradient background unconditionally on hover, regardless of whether the tab reserves action space.
