# Issue #330993 — Modern UI: Tab action buttons have gradient effects even if not overlaid

[https://github.com/microsoft/vscode/issues/330993](https://github.com/microsoft/vscode/issues/330993)

## Summary

Traced in the checkout: the Modern UI tab-action hover gradient in tabs.css is applied unconditionally on hover/focus-within, without checking whether the tab already reserves space for the action button (via the `.tab-actions-reserve-space` class, or the dirty/sticky states that always reserve space per the same file's own comment). The gradient should be suppressed whenever the action button doesn't overlay the label.

## Change summary

In the experimental Modern UI (`workbench.experimental.modernUI`), hovering a tab shows a fading gradient over the label even when `tabActionReserveSpace` already keeps the action button from overlapping the filename.

## Best solution

Scope the gradient `::before` rules in src/vs/workbench/contrib/styleOverrides/browser/media/tabs.css (around lines 380-494) to only apply when the tab does NOT already reserve space for the action — i.e. exclude tabs matching `.tab-actions-reserve-space`, `.dirty:not(.dirty-border-top)`, and `.sticky:not(.pinned-action-off)`, mirroring the existing padding-reservation logic at lines 167-180 of the same file.
