# Issue #205175 — (Ctrl + Shift) Multi-text Selection: Incorrect Selection Relative to Selections

[https://github.com/microsoft/vscode/issues/205175](https://github.com/microsoft/vscode/issues/205175)

## Summary

Keep open: the report has concrete steps and an independent confirmation, while current main still lacks regression coverage for multi-cursor word-right selection and retains an asymmetric multi-cursor path. No fixing commit or canonical issue was found.

## Change summary

Ctrl+Shift+Right produces inconsistent word selections when several cursors are placed before quoted items on the same line.

## Best solution

Add a regression case for the reported selections and make word-right selection advance equivalent multi-cursors consistently while preserving established single-cursor word-navigation behavior.

- **Behavior:**

  > With cursors immediately before each opening quote in `["Tiers", "Users", "Videos"]`, one Ctrl+Shift+Right invocation should extend every selection according to the same word-boundary rule. No cursor should select a structurally different portion of its quoted item. Single-cursor Ctrl+Shift+Right behavior and unrelated word-navigation commands must remain unchanged.
- **Trace:**

  > The command is `CursorWordEndRightSelect` in src/vs/editor/contrib/wordOperations/browser/wordOperations.ts. `MoveWordCommand.runEditorCommand` maps the command over all selections and computes `hasMulticursor`, but `WordRightCommand._move` forwards only the position and navigation type to `WordOperations.moveWordRight` in src/vs/editor/common/cursor/cursorWordOperations.ts. That routine contains separator-skipping behavior for one-character separators followed by regular text. Commit dc8c2d019c806a06aa47a4e7a6bd147b5d68b27e added multi-cursor-specific handling only to word-left navigation, so it is related evidence rather than a fix for this report. The uncertainty begins at the exact selection endpoints shown in the recording and whether rightward separator handling should differ only in multi-cursor mode.
- **Open decisions:**
  - What exact selection endpoints should Ctrl+Shift+Right produce for each quoted item, particularly whether the opening quote is included?
  - Should multi-cursor word-right navigation suppress the single-separator shortcut, or should consistency be enforced elsewhere in the selection command path?
