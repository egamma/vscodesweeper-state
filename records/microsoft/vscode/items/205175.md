# Issue #205175 — (Ctrl + Shift) Multi-text Selection: Incorrect Selection Relative to Selections

[https://github.com/microsoft/vscode/issues/205175](https://github.com/microsoft/vscode/issues/205175)

## Summary

Still reproduces on main: the word-right multi-cursor desync was never fixed. Commit dc8c2d019c8 (PR #215523) fixed the analogous word-left bug (#169904) by adding a `hasMulticursor` guard, but the same guard was intentionally or accidentally omitted from `moveWordRight` — the `WordNavigationType.WordEnd` branch still unconditionally skips single-separator words, causing cursors to land at different positions depending on surrounding content.

## Change summary

Multi-cursor Ctrl+Shift+Right Arrow (word right select) produces inconsistent selections across cursors when they sit near different separator characters.

## Best solution

Apply the same `hasMulticursor` guard from `moveWordLeft` (line 230 of cursorWordOperations.ts) to the `WordEnd` branch of `moveWordRight` (lines 322-327), so the single-separator skip is disabled when multiple cursors are active. The fix in PR #215523 is the exact template — extend it to the right-direction counterpart.
