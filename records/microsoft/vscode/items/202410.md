# Issue #202410 — Aux window: xterm mouse tracking is broken in aux windows

[https://github.com/microsoft/vscode/issues/202410](https://github.com/microsoft/vscode/issues/202410)

## Summary

Still reproduces on main: xterm.js mouse tracking (drag/mouseup) breaks in auxiliary windows because `documentOverride` is hardcoded to the main window's document and never updated when the terminal moves to an aux window.

## Change summary

Terminal mouse tracking (SGR 1003/1006 mode) does not report mouse drag or mouse-up events after moving a terminal into an auxiliary window, breaking TUI apps that depend on mouse input.

## Best solution

Update the xterm.js `documentOverride` (or re-open the terminal) when the terminal is reparented to an auxiliary window, so that document-level mouse listeners (mouseup, mousemove/drag in `CoreBrowserTerminal`) attach to the correct document. The fix likely needs coordination between `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts` (which sets `documentOverride` at construction) and xterm.js itself (which binds drag/mouseup listeners to `this._document`).

## Evidence

- **documentOverride hardcoded:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts line 230: `documentOverride: layoutService.mainContainer.ownerDocument` — always the main window document, never updated for aux windows.
- **xterm.js binds mouse listeners to _document:** node_modules/@xterm/xterm/src/browser/CoreBrowserTerminal.ts lines 783-786: `this._document!.addEventListener('mouseup', ...)` and `this._document!.addEventListener('mousemove', ...)` — these go to the wrong document when the terminal is in an aux window.
- **open() called only once:** src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts lines 491-492: `if (!this._attached) { this.raw.open(container); }` — xterm's `_document` is set during `open()` (CoreBrowserTerminal.ts line 411) and never refreshed on reparent.
