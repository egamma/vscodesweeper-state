# Issue #343873 — VSIX cache cleanup skips abandoned temporary download files

[https://github.com/microsoft/vscode/issues/343873](https://github.com/microsoft/vscode/issues/343873)

## Summary

Keep open: current source confirms that interrupted VSIX downloads leave temporary files which startup cleanup never considers. The complete reproduction and recovery controls establish a distinct cache-recovery defect, not ordinary retention of completed packages.

## Change summary

Recover abandoned .<UUID> download files in CachedExtensionVSIXs without disrupting active downloads or completed-package retention.

## Best solution

Make the extension downloader's cache maintenance recover abandoned download artifacts safely across restarts and concurrent processes, preserving the existing retention behavior for completed VSIX packages.

## Evidence

- **Current-source defect:** In src/vs/platform/extensionManagement/node/extensionDownloader.ts, ExtensionsDownloader.downloadFile writes to `.${generateUuid()}` before renaming. Process termination bypasses its error cleanup. ExtensionsDownloader.cleanUp only selects .sigzip files and entries accepted by ExtensionKey.parse, so these abandoned temporary files never reach its deletion list.
- **Filename exclusion:** src/vs/platform/extensionManagement/common/extensionManagementUtil.ts defines ExtensionKeyRegex as a versioned extension identifier. A dot-prefixed UUID cannot match, and cleanUp has no recovery branch for that filename.
- **Complete reproduction and measured impact:** https://github.com/microsoft/vscode/issues/343873#issuecomment-6371285421 documents interruption immediately before rename on Windows and WSL, Stable and Insiders. Thirty-day-old temporary files survived recovery startups while older versioned control entries were deleted. Eight original temporary files occupied 375,463,849 bytes outside completed-package retention.
- **Related issue is distinct:** https://github.com/microsoft/vscode/issues/343871 is open but concerns abandoned extraction directories under the installed-extensions directory after extractUserExtension. This report concerns download files under CachedExtensionVSIXs and a different cleanup path; fixing either does not inherently fix the other.
- **Canonical and implementation search:** A public issue search for CachedExtensionVSIXs and temporary files found no other open matching report. The retrieved timeline contains the reporter's comment, labeling and assignment, with no linked implementation PR. Current downloader source still contains the reported omission; the available file history supplies no concrete fixing commit.
- **Bounded validation surface:** src/vs/platform/extensionManagement/test/node/extensionDownloader.test.ts already provides an in-memory file service and downloader fixture.
