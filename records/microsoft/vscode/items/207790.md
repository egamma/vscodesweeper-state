# Issue #207790 — Bring back caching of `NotebookEditorInput` if required in NotebookEditorInput class

[https://github.com/microsoft/vscode/issues/207790](https://github.com/microsoft/vscode/issues/207790)

## Summary

Keep this maintainer-authored lifecycle debt open: current source still creates uncached NotebookEditorInput instances, but that alone does not establish whether caching is required. Diff and interactive inputs already perform explicit cleanup; the remaining work is to establish the ownership contract across callers, not automatically restore the cache.

## Change summary

Determine whether NotebookEditorInput instances require caching and ensure their disposal is correct under the chosen ownership model.

## Best solution

Establish and test notebook input ownership across ordinary editors, diff editors, and interactive windows, preserving live consumers while releasing unused inputs and model references. Restore caching only if shared input identity is necessary; otherwise retain independent inputs with complete lifecycle ownership.

- **Validation:** Establish lifecycle tests covering repeated notebook/diff open-close cycles, concurrent consumers of the same resource, and disposal during pending resolution. Assert that closing one consumer leaves remaining consumers usable and that final cleanup releases inputs, listeners, and model references; also retain the repeated untitled-notebook creation scenario from https://github.com/microsoft/vscode/issues/207742.
- **Behavior:**

  > Notebook inputs must remain usable while an editor still owns them and release their listeners and model references when no longer needed. Opening and closing a diff must not invalidate another editor showing the same notebook. Repeated untitled-notebook creation and disposal must continue to work. Acceptance should cover ordinary, diff, multi-diff, and interactive ownership without assuming that caching is itself required.
- **Trace:**

  > NotebookEditorInput.getOrCreate in src/vs/workbench/contrib/notebook/common/notebookEditorInput.ts currently constructs a fresh input each time; input disposal releases its listener and model reference. NotebookDiffEditorInput.create constructs two inputs and its dispose explicitly releases both, while NotebookMultiDiffEditorInput inherits that lifecycle and InteractiveEditorInput registers its child input. NotebookProviderInfoStore in notebookServiceImpl.ts and the serializer and working-copy handler in notebook.contribution.ts are additional creation paths whose ownership handoff still needs tracing. The reference-counted approach from https://github.com/microsoft/vscode/pull/207529 was reverted, and https://github.com/microsoft/vscode/pull/207745 removed the static cache to fix untitled-notebook failures. No current retention defect or requirement for shared input identity was conclusively established; the planning session must finish that diagnosis before selecting a lifecycle model. Preserve existing notebook model sharing, live-editor behavior, and the untitled-notebook regression fix.
- **Open decisions:**
  - For simultaneous ordinary and diff editors of the same notebook resource and view type, is shared NotebookEditorInput identity part of the required contract, or are independently owned inputs sharing the underlying notebook model sufficient?

## Evidence

- **Current factory remains uncached:** src/vs/workbench/contrib/notebook/common/notebookEditorInput.ts: NotebookEditorInput.getOrCreate always calls createInstance; dispose releases its side-loaded listener and editorModelReference. resolve also releases redundant references and handles disposal during asynchronous resolution. These safeguards do not establish that every caller eventually disposes its input.
- **Existing composite ownership:** src/vs/workbench/contrib/notebook/common/notebookDiffEditorInput.ts: create constructs independent original and modified inputs, and dispose explicitly disposes both plus the cached diff model.
