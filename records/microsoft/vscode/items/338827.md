# Issue #338827 — Background terminal completion notification starts a new turn, dropping the model's reasoning mid-task

[https://github.com/microsoft/vscode/issues/338827](https://github.com/microsoft/vscode/issues/338827)

## Summary

Freshly filed, well-documented bug with an exact code citation that matches current main: the background-terminal completion notification is sent via `sendRequest` with `queue: Steering, isSystemInitiated: true`, which is architecturally a new chat request/turn rather than a continuation, and that causes prior-turn history (including reasoning) to be re-rendered and stripped for Chat Completions-style models. Too fresh and too architecturally significant to close.

## Change summary

A system-initiated background-terminal-completion notification starts a brand-new chat request, which re-renders earlier turns as history and strips their reasoning_text/reasoning_opaque for Chat Completions models mid-task.

## Best solution

Design a way for a system-initiated notification (queue: Steering, isSystemInitiated: true) to continue the in-flight task/turn context rather than being modeled as a fresh top-level request that forces history re-rendering; likely needs coordination between runInTerminalTool.ts's sendRequest call and how the agent-host/chat service decides when to re-serialize prior turns as history (related to the reasoning-stripping mechanism tracked in issue #338820).
