# Issue #340848 — Modern UI: Active tab filename is truncated when `tabSizing` is `"fit"` or `"shrink"` and `tabActionReserveSpace` is `false`

[https://github.com/microsoft/vscode/issues/340848](https://github.com/microsoft/vscode/issues/340848)

## Summary

The remaining active-tab truncation is supported by current source: fit widths preserve short names but not full long names, while shrink labels lose space whenever the active Close action is visible. Keep this open for the tabs owner to settle the filename-readability versus persistent-action trade-off; the earlier short-name improvement does not resolve the complete report.

## Change summary

Clean, non-sticky active tabs truncate filenames with Modern UI enabled, tabActionReserveSpace disabled, and fit or shrink sizing.

## Best solution

Define the active-tab readability contract when action space is not reserved, then make Modern UI sizing and action visibility honor it consistently. Preserve stable tab widths and accessible Close controls without treating the short-name fit improvement as completion of the long-name and shrink cases.

Acceptance must cover both sizing modes, short and long names, hover and keyboard focus, without introducing tab-width jitter.
- **Trace:**

  > MultiEditorTabsControl.layoutFitTabsWithoutReservedActions() and getFitTabWidth() in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts freeze natural fit widths and guarantee only a capped short-name allowance. src/vs/workbench/contrib/modernUI/browser/media/tabs.css then adds active-action padding for fit tabs and reduces max-width for active shrink labels; overflowing fit content is hidden. - **Open decisions:**
  - When tabActionReserveSpace is false, should a clean active tab retain a continuously visible Close action even if this truncates its filename, or should filename visibility take precedence?
