# Issue #340882 — Extension API: conditional WorkspaceConfiguration.update (write only if the value still equals an expected value)

[https://github.com/microsoft/vscode/issues/340882](https://github.com/microsoft/vscode/issues/340882)

## Summary

The conditional-write API remains missing, and the issue is already correctly routed to api/config in Backlog. Existing write serialization and file-conflict protections do not provide the requested comparison against the value previously shown by an extension.

## Change summary

Allow extensions to update a configuration target only when its current value or version matches an expected snapshot.

## Best solution

Have the configuration API owners evaluate an opt-in conditional-write contract, including target/language semantics and conflict reporting, while preserving unconditional updates. Any guarantee covering other windows and external file writers must extend beyond the local write queue.

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.d.ts defines WorkspaceConfiguration.update(section, value, configurationTarget?, overrideInLanguage?) without a precondition; inspect() exposes values but no version token. No corresponding conditional-write API was found in the proposed declarations.
- **Current implementation:** src/vs/workbench/api/common/extHostConfiguration.ts forwards update() to $updateConfigurationOption without an expected value. MainThreadConfiguration.writeConfiguration in src/vs/workbench/api/browser/mainThreadConfiguration.ts inspects configuration to select language-override behavior, not to check a caller's snapshot, then calls configurationService.updateValue.
- **Existing protections are narrower:** src/vs/workbench/services/configuration/common/configurationEditing.ts serializes writes through ConfigurationEditing.queue and protects against dirty configuration files and FILE_MODIFIED_SINCE save failures. These checks do not reject a write because a setting already changed after the extension displayed it but before the write operation began.
- **Earlier discussion is not a duplicate:** https://github.com/microsoft/vscode/issues/134803 is closed. The maintainer's comment at https://github.com/microsoft/vscode/issues/134803#issuecomment-942099275 recommends extension coordination and explains last-write-wins serialization; it neither supplies conditional writes nor declines this broader API request involving user edits, Settings Sync, and other windows.
