# Issue #322337 — Git: `isRepositoryHuge` flag set during transient clone/checkout permanently freezes stale git status with no recovery short of restart

[https://github.com/microsoft/vscode/issues/322337](https://github.com/microsoft/vscode/issues/322337)

## Summary

The huge-repository guard does suppress automatic refresh, but current source does not block manual Refresh and already resets the flag after a below-limit status result. Request current-build Git logs to establish why the reported manual recovery fails after re-cloning.

## Change summary

Source Control retains stale deleted-file entries after a large repository is re-cloned, reportedly even after manual Refresh.

## Best solution

Ensure explicit Refresh recovers accurate status after the repository is restored while preserving large-repository performance safeguards. First identify whether the failing path is repository disposal, watcher loss, a Git error, or another refresh failure rather than assuming the huge-repository flag blocks the command.
