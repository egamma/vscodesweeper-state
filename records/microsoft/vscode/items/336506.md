[https://github.com/microsoft/vscode/issues/336506](https://github.com/microsoft/vscode/issues/336506)

## Summary

Keep open: the report isolates selection loss to bare modifier events under the kitty keyboard protocol, and upstream xterm.js contains a matching selection-clearing path. Related shortcut reports do not establish an older canonical for this specific symptom.

## Change summary

Preserve terminal selections when bare modifiers are pressed under the kitty keyboard protocol so Cmd+C can copy selected text.

## Best solution

Correct xterm.js's classification of modifier-only protocol reports so they remain available to terminal applications without triggering selection-clearing user input. Adopt the upstream correction in VS Code and verify both bare-modifier selection preservation and Cmd+C copying with fish.

## Evidence

- **Reporter-confirmed reproduction:** https://github.com/microsoft/vscode/issues/336506 documents a clean-profile reproduction with fish --no-config: selecting hello and tapping Shift clears the selection. Disabling terminal.integrated.enableKittyKeyboardProtocol reverses the behavior; the reporter subsequently confirmed it on stable 1.138.0.
- **VS Code integration:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:604-609 enables the protocol by default. src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:280-282 and 622-625 pass that setting to xterm.js. TerminalInstance's custom keyboard handler at terminalInstance.ts:1157-1216 does not generally exclude bare modifiers, while XtermTerminal.copySelection at xtermTerminal.ts:848-869 checks the selection only when copying.
- **Matching upstream cause:** https://github.com/xtermjs/xterm.js/blob/8961a72d2d936bac273763e09136b5303bb8a7e9/src/browser/CoreBrowserTerminal.ts classifies modifier-only reports as non-user-input only when useWin32InputMode is true, in both _keyDown and _keyUp. Kitty reports therefore reach triggerDataEvent with wasUserInput=true when they produce a sequence. Upstream src/common/services/CoreService.ts fires onUserInput for that flag, and src/browser/services/SelectionService.ts:139-142 clears an existing selection on that event. This supports dependency ownership rather than a clipboard-command defect.
