# Issue #336506 — Terminal: a bare modifier keypress clears the selection when the kitty keyboard protocol is active, breaking Cmd+C copy

[https://github.com/microsoft/vscode/issues/336506](https://github.com/microsoft/vscode/issues/336506)

## Summary

Well-diagnosed report with a clean, isolated repro (bisected against a clean profile, ruled out extensions/keybindings/settings). The `kittyKeyboard` option VS Code sets on the xterm.js `Terminal` instance is just passed through (src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts, lines ~276/615); the actual selection-clear-on-key behavior lives inside the `@xterm/xterm` core library, which this repo bundles as a dependency but doesn't own, so this is upstream.

## Change summary

When the kitty keyboard protocol is negotiated (e.g. by fish 4.x), a bare modifier keypress (like a lone Shift tap) clears the terminal text selection, which makes Cmd+C fail to copy since the selection is gone by the time the copy command runs.

## Best solution

File or link the underlying defect against `@xterm/xterm` (the terminal emulator core VS Code bundles, currently `^6.1.0-beta.304` per package.json) — the fix belongs in xterm.js's key-event/selection handling so it distinguishes a modifier-only kitty-protocol key report from real input; VS Code's `xtermTerminal.ts` only forwards the `kittyKeyboard` config flag and doesn't itself decide to clear selection on keydown.
