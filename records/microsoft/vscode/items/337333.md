# Issue #337333 — Dictation first-run experience does not clearly indicate model download

[https://github.com/microsoft/vscode/issues/337333](https://github.com/microsoft/vscode/issues/337333)

## Summary

Team-authored feature request with a confirmed gap on main: the first-run onboarding banner's waveform (dictationOnboarding.ts) never wires into the model-download/preparing state, so nothing in that surface tells the user the on-device model is still downloading — only the toolbar mic icon's DictationDownloadRing does, which is easy to miss.

## Change summary

Show a clear downloading/preparing indicator in the dictation waveform UI during first-run model download instead of relying solely on the toolbar mic ring.

## Best solution

Hook DictationOnboardingBanner (and/or the main dictation session waveform) up to IChatSpeechToTextService.isPreparingModel / onDidChangePreparingModel and modelDownloadProgress, reusing the existing getDictationPreparingLabel() text (already used for the terminal placeholder and voice input mode aria-label) so the waveform area itself shows 'Downloading speech-to-text model… X%' until the model is ready.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/speechToText/dictationOnboarding.ts`, `src/vs/workbench/contrib/chat/browser/speechToText/dictationDownloadRing.ts`, `src/vs/workbench/contrib/chat/browser/speechToText/dictationSession.ts`
- **Validation:** A visible/aria-live indicator in the onboarding waveform card that updates from getDictationPreparingLabel()/modelDownloadProgress while isPreparingModel is true, verifiable via a dictationOnboarding test asserting the indicator text/element appears during preparing state and clears once ready.
- **Behavior:**

  > While the on-device dictation model is downloading or loading for the first time, the dictation waveform UI (the onboarding banner shown on first use, and ideally the main dictation session surface) must visibly communicate that state — e.g. the same 'Downloading speech-to-text model… X%' / 'Preparing…' / 'Connecting to dictation service…' text already produced by getDictationPreparingLabel() — rather than showing only a live waveform with no indication anything is happening. Once the model finishes preparing, the indicator clears and normal listening/waveform behavior resumes. Acceptance: a user starting dictation for the first time sees an explicit downloading/preparing message in the waveform area, not just the toolbar mic ring.
- **Trace:**

  > DictationOnboardingBanner in dictationOnboarding.ts constructs a MicrophoneWaveform bound only to live mic level (getLevel/isAvailable) — it never reads service.isPreparingModel, onDidChangePreparingModel, or modelDownloadProgress. Separately, dictationSession.ts (lines ~374-407) explicitly avoids showing any placeholder text while isPreparingModel is true, deferring entirely to the toolbar's DictationDownloadRing. The reusable label already exists: getDictationPreparingLabel() in dictationDownloadRing.ts, consumed today only by terminalVoice.ts and voiceInputModeActionViewItem.ts (hover/aria-label, not the waveform card itself). The boundary: do not change DictationDownloadRing's toolbar-icon rendering or the transcript-insertion logic in dictationSession.ts; scope the change to how/where the existing preparing-state text is surfaced in the waveform card.
- **Open decisions:**
  - Should the indicator replace the waveform visualization entirely while preparing, overlay it, or sit alongside it (e.g. as a caption under the bars)?
  - Should this only apply to the first-run onboarding banner, or also to the main dictation session UI (editor placeholder) once onboarding has been dismissed?

## Evidence

- **no hookup in onboarding banner:** src/vs/workbench/contrib/chat/browser/speechToText/dictationOnboarding.ts has zero references to isPreparingModel, onDidChangePreparingModel, modelDownloadProgress, or getDictationPreparingLabel — the waveform card is fully decoupled from download state.
- **existing infra elsewhere:** dictationDownloadRing.ts already exports getDictationPreparingLabel() (doc comment: "for surfaces without a progress ring (editor placeholder, terminal decoration)") and it's consumed by terminalVoice.ts and voiceInputModeActionViewItem.ts, but not by the onboarding waveform or the main dictation editor placeholder (dictationSession.ts explicitly withholds any placeholder while service.isPreparingModel is true, per its comment at lines 374-397).
- **toolbar-only signal today:** DictationDownloadRing (dictationDownloadRing.ts) renders a progress ring only on the toolbar mic icon, matching the reporter's complaint that 'the download treatment on the microphone icon... was easy to miss'.
