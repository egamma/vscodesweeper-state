## Summary

The chat request-editing path still permits synchronous focus-driven scrolling during a list render transaction, causing the reported exception. The older notebook reports reach the same guard through different callbacks and do not establish that this chat-specific case is redundant.

## Change summary

Prevent chat request rendering from throwing “Already in transaction” when restoring editor focus triggers list scrolling.

## Best solution

Make rendering an edited chat request safe when focus restoration scrolls the transcript, while preserving keyboard focus and visibility of the editing input. Retain the row-cache transaction invariant rather than suppressing the exception without resolving reentrant rendering.
