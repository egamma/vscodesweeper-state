## Summary

Same underlying defect as the open, better-diagnosed https://github.com/microsoft/vscode/issues/328986: RowCache.transact() in rowCache.ts throws 'Already in transaction' whenever a render() call is re-entered synchronously during another render's transaction — that issue was triggered via notebook cell reveal, this one via the new scrollToActiveElement focus handler, but it's the same shared-code failure mode.

## Change summary

Auto-filed error-telemetry report: ListView.render() re-enters RowCache.transact() (via focus → scrollToActiveElement → setScrollTop → onScroll → render) while a transaction is already open, throwing 'Already in transaction'.

## Best solution

Fix RowCache.transact() (src/vs/base/browser/ui/list/rowCache.ts) to tolerate or defer re-entrant calls instead of throwing, since multiple independent list/notebook code paths can synchronously trigger a nested render() during an active transaction; track and land that fix under the canonical issue https://github.com/microsoft/vscode/issues/328986.
