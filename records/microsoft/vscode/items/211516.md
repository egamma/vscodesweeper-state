# Issue #211516 — Go to line in relative to current cursor

[https://github.com/microsoft/vscode/issues/211516](https://github.com/microsoft/vscode/issues/211516)

## Summary

Keep this accepted feature request open: current Go to Line does not support cursor-relative navigation, and an open implementation proposal already exists. Maintainer feedback identifies preserving negative end-of-file indexing as a compatibility requirement.

## Change summary

Support entering a line displacement relative to the current cursor in Go to Line.

## Best solution

Review and revise https://github.com/microsoft/vscode/pull/246831 to provide cursor-relative navigation without changing existing absolute and end-relative inputs. Settle the relative-input syntax and cursor anchor semantics before landing it.

## Evidence

- **Existing capability check:** src/vs/workbench/contrib/codeEditor/browser/quickaccess/gotoLineQuickAccess.ts registers workbench.action.gotoLine and workbench.action.gotoOffset. In src/vs/editor/contrib/quickAccess/browser/gotoLineQuickAccess.ts, AbstractGotoLineQuickAccessProvider.parsePosition parses positive numbers as absolute lines and negative numbers as (maxLine + 1) + lineNumber; it does not use the cursor position. The :: mode navigates to buffer character offsets, not cursor-relative lines. These built-in modes do not satisfy the central request.
- **Compatibility contract:** src/vs/editor/contrib/quickAccess/test/browser/gotoLineQuickAccess.test.ts explicitly expects -1 to navigate to the last line and -5 to the first line of a five-line model. Reinterpreting signed inputs as cursor-relative movement would change established behavior.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/246831 is verified OPEN with mergedAt null and proposes changing signed line inputs to cursor-relative movement. It modifies the same provider and is cross-referenced from this issue; it is not a landed implementation.
- **Maintainer direction:** https://github.com/microsoft/vscode/pull/246831#issuecomment-3504118147 explicitly names this issue, explains that :-20 already means navigation from the end of the file, and suggests :c-20 as a potentially compatible alternative. The maintainer considers the submitted behavior unsuitable, not the feature itself out of scope.
