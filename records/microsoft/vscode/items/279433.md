# Issue #279433 — Mode selection targets the last active chat box.

[https://github.com/microsoft/vscode/issues/279433](https://github.com/microsoft/vscode/issues/279433)

## Summary

Team-authored bug about mode picker targeting the last-focused chat widget instead of the one whose dropdown was clicked. The mode picker code has been heavily refactored (82 commits since filing), and the current architecture now passes sessionResource explicitly and has a direct setMode fallback for session-less hosts — but no commit explicitly references this issue as fixed, and the scenario may still reproduce for chat editors opened with the legacy vscodeChatEditor scheme before session resolution completes.

## Change summary

Changing chat mode via the dropdown in a split-view chat editor applies the mode to the last-focused chat instance rather than the one whose picker was clicked.

## Best solution

Verify whether this still reproduces on current main after the extensive mode-picker refactoring (especially the sessionResource-based widget lookup in ToggleChatModeAction and the direct setMode path for session-less hosts). If fixed, close as completed; if not, the fix is to ensure the mode picker's delegate always carries a widget-scoped identity so the command never falls through to lastFocusedWidget.
