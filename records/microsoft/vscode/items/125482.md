# Issue #125482 — Touch feedback on actions does not go away after touch

[https://github.com/microsoft/vscode/issues/125482](https://github.com/microsoft/vscode/issues/125482)

## Summary

Keep open: the originating discussion explicitly confirms feedback remaining after touch and identifies this issue as the follow-up. Current source still warrants investigation, but neither a concrete fix nor an open canonical owning this symptom was established.

## Change summary

Action feedback sometimes remains highlighted after a touch interaction until another control is touched.

## Best solution

Restore transient pressed feedback for iPad action controls without leaving a hover-like highlight after release. First reproduce on current iPadOS and distinguish a retained active class from browser-synthesized hover before changing shared action handling.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/actionbar/actionViewItems.ts`, `src/vs/workbench/browser/media/style.css`
- **Validation:** On current VS Code web in iPadOS Safari, repeatedly tap an enabled toolbar action that leaves its control visible, then lift the finger without touching elsewhere. Verify pressed feedback returns to its resting appearance without a second tap, the action runs once, and desktop hover, mouse press, and keyboard focus feedback remain intact.
- **Behavior:**

  > An iPad touch on an enabled action can leave interaction feedback visible until another control is touched, as confirmed in the originating discussion. Touch feedback should end after release without requiring another interaction. Retest repeated taps on a control that remains visible and preserve normal action execution, keyboard focus indication, and desktop mouse feedback.
- **Trace:**

  > The originating report at https://github.com/microsoft/vscode/issues/121192#issuecomment-854388643 confirms the symptom, and https://github.com/microsoft/vscode/issues/121192#issuecomment-854473842 explicitly delegates it to this issue. BaseActionViewItem.render in src/vs/base/browser/ui/actionbar/actionViewItems.ts handles Tap separately from the mouse events that add and remove the active class. Shared styling in src/vs/workbench/browser/media/style.css independently paints :hover and active feedback. Source inspection cannot determine whether current iPadOS retains browser hover, misses active-state cleanup, or no longer reproduces the historical behavior. Establish that distinction on-device before choosing a bounded change; preserve mouse behavior, keyboard focus visibility, and the existing touch preserveFocus contract.
