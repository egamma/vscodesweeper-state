The screenshots identify the DeepSeek Responses API tool-follow-up failure addressed by merged commit 3dabe9b5512f025eb64934ce456f4867ec6a11c9. Propose closing as completed with instructions to set statefulResponses to false; the fix intentionally requires this per-model configuration.

## Change summary

DeepSeek custom-endpoint Responses API requests fail after a tool call with HTTP 400 stating that no matching tool call exists.

## Best solution

Use the implemented per-model statefulResponses: false option for DeepSeek so every follow-up includes the matching tool-call history. Preserve default response chaining for compliant servers; the separately reported intermittent HTTP 502 is not established as the same defect.
