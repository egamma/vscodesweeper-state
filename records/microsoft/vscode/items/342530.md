# Issue #342530 — Clicking on failed generated image just removes previous image and shows nothing

[https://github.com/microsoft/vscode/issues/342530](https://github.com/microsoft/vscode/issues/342530)

## Summary

Keep open for a failure-selection UX decision: current source explicitly clears the previous preview when a failed image is selected, and an existing test expects an empty preview. This is an improvement to established behavior rather than a confirmed implementation defect.

## Change summary

Make selecting a failed image in a mixed-success generation batch more informative than removing the previous image and leaving no preview.

## Best solution

Give failed selections an understandable presentation in the chat image batch while keeping their error details accessible. Decide whether the preview should show an explicit failure state or retain the last successful image with clearly distinguished failure details.

- **Behavior:**

  > In a batch containing successful and failed generations, selecting a failed thumbnail currently removes the successful preview and leaves only the failed tool row. The completed experience should make that selection understandable without implying that a failed generation produced an image. Acceptance should cover switching from success to failure and back, inspecting failure details, and equivalent mouse and keyboard selection.
- **Trace:**

  > ChatImageGenerationBatchPart.update() creates failed slots without an image part. Preserve successful-image navigation, error inspection, and distinctions between generation failure, cancellation, approval, and image-loading failure. The related report https://github.com/microsoft/vscode/issues/342529 concerns failed thumbnail positions and filtering; coordinate the observable selection decision without expanding this work into provider rate-limit handling.
