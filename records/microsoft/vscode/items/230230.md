# Issue #230230 — Markdown should not split up words in backticks that end in `/` when wrapping

[https://github.com/microsoft/vscode/issues/230230](https://github.com/microsoft/vscode/issues/230230)

## Summary

Current main still permits the awkward wrap shown in the report: `/` is a generic break-after character, so a Markdown inline-code path can leave its closing backtick alone on the next visual line. This remains valid, already-routed editor polish with no verified duplicate or fix.

## Change summary

Keep a Markdown inline-code path ending in `/` from wrapping immediately before its closing backtick.

## Best solution

Preserve the closing backtick with the preceding inline-code path when Markdown source wraps, without globally disabling useful slash breakpoints in paths and URLs or changing wrapping for other languages.

- **source trace:** src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts builds `WrappingCharacterClassifier` from the global character sets and `canBreak` accepts a break after `/`; the wrapping context receives raw line content and no Markdown token ranges, so the closing backtick is not kept with the code span.
- **existing capability gap:** Users can override `editor.wordWrapBreakAfterCharacters`, but removing `/` changes wrapping for every slash on the line and does not provide the requested inline-code-specific behavior.
