# Issue #317658 — Agents: Make mobile links clickable

[https://github.com/microsoft/vscode/issues/317658](https://github.com/microsoft/vscode/issues/317658)

## Summary

Mobile link activation remains broken: list touch handling suppresses native clicks, while rendered Markdown links have no gesture-tap activation handler. Keep this older, team-authored report open; the newer Android report supplies concrete reproduction steps and corroborating diagnosis.

## Change summary

Make links in the mobile Agents chat respond to taps.

## Best solution

Restore touch activation of chat links while preserving scrolling, desktop clicks, keyboard activation, and existing link-opening safeguards. Assess the shared Markdown renderer's consumers before choosing the scope of the correction.

- **Behavior:**

  > A short tap on a link in an Agents chat reply must open the intended destination exactly once. Dragging to scroll the conversation must not open links. Mouse and keyboard activation and existing link-opening safeguards must remain unchanged. The newer Android report provides a concrete end-to-end acceptance scenario.
- **Trace:**

  > ListView registers its rows container as a gesture target in src/vs/base/browser/ui/list/listView.ts. Gesture.onTouchEnd in src/vs/base/browser/touch.ts dispatches a synthetic Tap and prevents the native touch default, suppressing the browser-generated click. The link handlers in renderMarkdown in src/vs/base/browser/markdownRenderer.ts listen for click, auxclick, and keyboard input, not the synthetic Tap. This matches the diagnosis and reported reproduction at https://github.com/microsoft/vscode/issues/337932#issuecomment-5830908688. The unresolved scope is the shared renderer's other consumers and their gesture interactions; those were not enumerated during this review. Preserve list scrolling, existing activation semantics, and link trust handling, and do not expand this issue into fixing every small interactive control mentioned in the newer report.
