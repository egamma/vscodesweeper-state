# Issue #313070 — "Checking index status" stuck indefinitely in Codebase Semantic Index for non-git workspaces

## Change summary

Codebase Semantic Index initialization can remain on "Checking index status" indefinitely and repeatedly perform Git lookups in large non-Git workspaces.

## Best solution

Refresh and review https://github.com/microsoft/vscode/pull/313120 against the current networking and content-exclusion implementations, then land or supersede it with coverage for request timeout enforcement and negative non-Git lookup caching. The remaining 30-second Git initialization wait in `CodeSearchRepoTracker` should also be resolved or explicitly split into separately tracked work.

## Evidence

- **open fixing PR:** https://github.com/microsoft/vscode/pull/313120 is an open draft with `Fixes #313070`; it changes `baseFetchFetcher.ts`, `nodeFetcher.ts`, and `remoteContentExclusion.ts` to enforce request timeouts and cache negative Git lookups. It currently requires review and is reported as merge-conflicted.
- **hanging source path:** `extensions/copilot/src/platform/workspaceChunkSearch/node/workspaceChunkSearchService.ts` still awaits `_availableEmbeddingTypes.getPreferredType(silent)` in `tryInit()`, so a request that never settles prevents creation of the implementation and its index-state events.
- **timeout not enforced:** `extensions/copilot/src/platform/networking/node/baseFetchFetcher.ts` passes only `options.signal` to the underlying fetch and does not apply `options.timeout`; `extensions/copilot/src/platform/networking/node/nodeFetcher.ts` calls `req.setTimeout(60 * 1000)` without a callback that destroys or rejects the request.
- **negative lookup not cached:** `extensions/copilot/src/platform/ignore/node/remoteContentExclusion.ts` calls `getRepositoryFetchUrls(file)` whenever no cached repository matches, but caches only a resolved repository. The fallback non-Git metadata is not stored, so separate files can repeat the expensive lookup.
- **remaining delay:** `extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/repoTracker.ts` still waits up to 30 seconds for `onDidFinishInitialization` through `_initializedGitReposP`, including workspaces with no Git repository.
- **telemetry is not a fix:** https://github.com/microsoft/vscode/pull/313127 merged telemetry around `tryInit()` duration and outcome, but its diff only instruments initialization and does not terminate a stalled request.
- **canonical search:** https://github.com/microsoft/vscode/issues/254952 covered slow per-file Git lookups in large Git repositories and is closed; it does not own the same observable indefinite semantic-index status failure in non-Git workspaces.
