# Issue #148810 — Add filter to select box inside settings UI.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`, `src/vs/base/browser/ui/selectBox/selectBox.ts`, `src/vs/base/browser/ui/selectBox/selectBoxCustom.ts`, `src/vs/base/browser/ui/selectBox/selectBoxNative.ts`
- **Validation:** In the agreed Settings dropdowns, open a long enum list, enter a query, verify the visible choices narrow, select a result with the keyboard, and verify the correct setting value is saved. Clear the query to restore choices; verify Escape cancels without changing the value and screen-reader focus and selection announcements remain usable.
- **Behavior:**

  > Settings UI dropdowns should let users search their available choices rather than scan the entire list. Typing a query should narrow the displayed options, and selecting a result should save the corresponding original setting value. Clearing the query should restore the available choices, and cancelling should preserve the existing value. Keyboard navigation and screen-reader operation must remain usable.
- **Trace:**

  > SettingEnumRenderer.renderTemplate in src/vs/workbench/contrib/preferences/browser/settingsTree.ts creates the shared SelectBox. src/vs/base/browser/ui/selectBox/selectBox.ts chooses between native and custom delegates and exposes no filtering option. SelectBoxList.createSelectList in selectBoxCustom.ts builds the dropdown list, and onCharacter only jumps by the first typed character; it is not query filtering. SelectBoxNative in selectBoxNative.ts wraps an HTML select. The discussion at https://github.com/microsoft/vscode/issues/148810 suggests reusable Quick Pick functionality, but does not settle which controls should adopt it or how native selection should coexist with search. Preserve existing enum value mapping, descriptions, disabled options, and cancellation semantics; unrelated dropdown consumers are outside the initial acceptance boundary unless explicitly included.
- **Open decisions:**
  - Should search be available in every Settings enum dropdown or only in lists above an agreed size?
  - Should searchable Settings dropdowns use the same custom interaction on all platforms, or retain native selection with a separate search affordance where native controls are used?

## Evidence
