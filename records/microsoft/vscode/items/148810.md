# Issue #148810 — Add filter to select box inside settings UI.

[https://github.com/microsoft/vscode/issues/148810](https://github.com/microsoft/vscode/issues/148810)

## Summary

Settings dropdowns still lack an editable option filter; existing first-character navigation does not satisfy this request. Keep the accepted Backlog item open for shared-component design, consistent with the maintainers' discussion.

## Change summary

Allow users to search and filter the available values inside Settings UI dropdowns.

## Best solution

Provide an accessible, reusable searchable selection surface for Settings values, retaining option descriptions and correct value selection. Settle its relationship to existing select boxes and Quick Pick before implementation rather than introducing a Settings-only interaction.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/selectBox/selectBox.ts`, `src/vs/base/browser/ui/selectBox/selectBoxCustom.ts`, `src/vs/base/browser/ui/selectBox/selectBoxNative.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`, `src/vs/workbench/contrib/preferences/browser/settingsWidgets.ts`
- **Validation:** After the interaction is agreed, open an enum setting with many values, type a query, verify the displayed choices narrow, select a result, and confirm the correct underlying value is saved. Check clearing the query, no matches, cancellation, keyboard navigation, screen-reader labeling, and unchanged behavior for non-searchable selects.
- **Behavior:**

  > Users should be able to enter search text within a Settings value selector and narrow its available options instead of scrolling through the full list. Choosing a filtered result must save the corresponding original setting value and preserve relevant descriptions and default indicators. Acceptance should cover clearing the query, no results, keyboard selection, cancellation, and accessible announcements. The precise filtering and commit behavior must be agreed during planning.
- **Trace:**

  > SettingEnumRenderer in src/vs/workbench/contrib/preferences/browser/settingsTree.ts uses SelectBox and maps its emitted index into the original enum values. SelectBox in src/vs/base/browser/ui/selectBox/selectBox.ts delegates to native or custom implementations; SelectBoxList.createSelectList creates a listbox, and onCharacter provides only single-initial navigation. Settings object-value editors also consume SelectBox through settingsWidgets.ts. Source inspection confirms no editable filter on these paths, but does not settle how searchable selection should coexist with native controls or how broadly it should be adopted. Preserve enum value mapping, descriptions, disabled states, and existing non-searchable selection behavior. The maintainer discussion at https://github.com/microsoft/vscode/issues/148810 suggests reusable Quick Pick functionality rather than a Settings-specific widget.
- **Open decisions:**
  - Should searchable selection apply to every Settings enum dropdown or only larger option sets, and should the same interaction be available to other select-box consumers?
  - Should queries match option labels only or also underlying values and descriptions, and should matching use substring or Quick Pick-style fuzzy filtering?
  - Should filtering leave the saved value unchanged until explicit acceptance, and what should Escape restore?
  - Where a native select is currently used, should searchable selection replace it or remain an alternate interaction?
