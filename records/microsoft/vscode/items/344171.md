# Issue #344171 — Explore time-based flow control for terminal output instead of a fixed 100k char window

[https://github.com/microsoft/vscode/issues/344171](https://github.com/microsoft/vscode/issues/344171)

## Summary

Keep this exploration open in terminal-process: current main still uses fixed character thresholds, not an adaptive parsing budget. The related throughput reports provide motivation but do not settle the broader design; exploration issues are also protected from closure.

## Change summary

Explore terminal output backpressure based on measured parsing time rather than a fixed 100,000-character window.

## Best solution

Establish whether adaptive flow control improves throughput across content types and machine speeds without compromising shared-connection fairness, background-terminal progress, or Ctrl+C responsiveness. Keep this design exploration distinct from the narrower output-batching improvements in the linked reports.
