# Issue #113705 — Disallow navigating away from custom editors when retainContextWhenHidden is false and the backup has yet to run orfailed

[https://github.com/microsoft/vscode/issues/113705](https://github.com/microsoft/vscode/issues/113705)

## Summary

Feature request to prevent data loss in custom editors by blocking tab navigation when backup hasn't completed or has failed. No implementation found on current main; the request remains valid for custom editor extension authors dealing with large or slow-to-serialize data.

## Change summary

Block navigating away from custom editor tabs (retainContextWhenHidden: false) until backup completes or prompt save/discard on backup failure.

## Best solution

Implement a navigation guard in the custom editor input that either blocks tab switches until a pending backup resolves or shows a save/don't-save/cancel dialog when backup has failed. The change would likely live in `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts` and interact with the backup lifecycle. Given the niche audience (custom binary editor authors with large payloads), this could also be addressed by improving the postMessage transfer path (ArrayBuffer support) to make timely backups feasible.
