# Issue #270367 — Installing an extension from sources sometimes results in two same extensions being shown in Extensions view

[https://github.com/microsoft/vscode/issues/270367](https://github.com/microsoft/vscode/issues/270367)

## Summary

The current source still explains the duplicate and misleading restart state: location-installed extensions are deliberately excluded when matching Marketplace results. This team-authored Backlog bug remains necessary and has no linked fix or canonical issue.

## Change summary

Installing an extension from a source directory can show separate local and Marketplace entries whose actions operate on the same underlying extension.

## Best solution

Present the location-installed extension and its Marketplace counterpart as one coherent extension entry while keeping the source-directory installation authoritative and ensuring restart, enablement, and disablement actions reflect that entry consistently.

## Evidence

- **source trace:** src/vs/platform/extensionManagement/node/extensionManagementService.ts installs a directory-backed extension with metadata source `resource`. In src/vs/workbench/contrib/extensions/browser/extensionsWorkbenchService.ts, `getInstalledExtensionMatchingGallery` explicitly skips ID matching when `installed.local.source === 'resource'`, so `fromGallery` creates a separate Marketplace model for the same extension ID.
- **misleading runtime state:** The separate Marketplace model is considered uninstalled by `getExtensionState`; `getRuntimeState` then finds the running extension by the shared identifier and can assign `ExtensionRuntimeActionType.RestartExtensions`, matching the reported Marketplace-row action.
