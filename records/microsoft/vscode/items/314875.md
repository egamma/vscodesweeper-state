# Issue #314875 — Copilot CLI agent: all tools fail when CWD is a WSL path (\\wsl.localhost\...)

[https://github.com/microsoft/vscode/issues/314875](https://github.com/microsoft/vscode/issues/314875)

## Summary

The reported failure remains relevant: current main still passes a Windows `\\wsl.localhost\...` path directly to the Copilot CLI SDK as its working directory, with no UNC-to-WSL routing or compatibility guard. Route this to the Copilot CLI and WSL owners rather than closing it.

## Change summary

Copilot CLI tools fail before execution when a Windows-hosted session uses a WSL UNC path as its working directory.

## Best solution

Make Copilot CLI sessions support WSL-backed workspaces consistently, either by executing through the WSL environment or by ensuring the SDK tool runtime accepts and preserves valid WSL UNC working directories. Validate the same path across shell, file, search, and MCP-backed tools.
