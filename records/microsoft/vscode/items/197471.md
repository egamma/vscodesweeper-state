# Issue #197471 — Promote notebookKernelSource API proposal to stable

[https://github.com/microsoft/vscode/issues/197471](https://github.com/microsoft/vscode/issues/197471)

## Summary

Keep open: notebookKernelSource remains explicitly proposal-gated, so the requested stable access for third-party notebook extensions is still missing. The existing notebook-api and under-discussion labels fit; related requests do not supply an older, open duplicate canonical.

## Change summary

Finalize notebookKernelSource so third-party published extensions can participate in notebook kernel-source selection without proposed-API privileges.

## Best solution

Have the notebook API owners review and finalize a supported kernel-source provider contract for third-party extensions. Stable notebook controller creation alone does not provide the requested source-selection integration.

- **Behavior:**

  > Third-party published notebook extensions should be able to contribute supported kernel-source selection through stable VS Code APIs, without an extension-specific proposed-API allowance. Acceptance requires an extension compiled against stable declarations to register a source provider, display its source actions, and select the intended notebook controller. Existing notebook extensions must retain their supported selection behavior.
