## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCustomizationService.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts`, `src/vs/platform/agentHost/common/agentHostUri.ts`, `src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostCustomizationService.test.ts`
- **Validation:** On current VS Code, configure the same Atlassian HTTP MCP endpoint, establish the working editor connection, then invoke inline Authenticate and MCP: List Servers → Authenticate from an Agent Host session on Windows with WSL and in a standalone Windows window. Capture the complete renderer stack; verify sign-in starts when needed, successful authentication makes tools usable, and failures are visible rather than silent.
- **Behavior:**

  > An Atlassian MCP server can work in the editor connection while Copilot Agent Host still requires authentication. Activating either Agent Host Authenticate entry point should initiate the appropriate authentication flow, not fail with an authority/path URI exception or silently do nothing. Successful authentication should unblock tool use; cancellation or failure should not be represented as success. Acceptance covers Windows with WSL and the standalone Windows case recorded in the companion report.
- **Trace:**

  > MCP server-list authentication delegates through mcpCommands.ts to AgentHostCustomizationService.authenticateMcpServer, which starts the server and calls resolveMcpServerAuthentication in agentHostAuth.ts. The resolver discovers resource metadata, selects or creates an authentication provider/session, and forwards the credential to the owning target. Current source includes later discovery and failure-reporting changes, but the reported stack excerpt does not identify which URI construction originally threw. Commit c3cb54f9cdaa715e2754b92cf913f312847d2f53 fixes opaque-URI wrapping for snapshots; do not assume it fixes this click path without the complete stack. https://github.com/microsoft/vscode/issues/340483 tracks a distinct missing-metadata fallback, while https://github.com/microsoft/vscode/issues/342106 records the Windows-only confirmation. Preserve owning-session identity, existing editor authentication, and ordinary cancellation semantics; the first investigation step is current reproduction rather than a speculative URI patch.

Read-only inspection did not establish a current failing URI construction on this exact path.
