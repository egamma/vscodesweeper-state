# Issue #11462 — Debug console architecture

[https://github.com/microsoft/vscode/issues/11462](https://github.com/microsoft/vscode/issues/11462)

## Summary

The architectural question remains unresolved on current main, but several original limitations have since been addressed within the tree-based implementation. Keep this Backlog discussion open and classify it as under discussion until maintainers identify a remaining user-facing goal that warrants replacing or restructuring the console.

## Change summary

Reconsider whether the Debug Console should remain a virtualized tree or adopt an editor-based or custom architecture.

## Best solution

First reassess the architecture against current behavior: the tree now supports find, native text selection, filtering, word wrap, horizontal scrolling, and configurable fonts. If material gaps remain, define their observable requirements and prototype the smallest architecture that preserves expandable values, virtualization, accessibility, and debugger-provided rendering.

## Evidence

- **current architecture:** Current main still constructs the Debug Console output as `WorkbenchAsyncDataTree` in `src/vs/workbench/contrib/debug/browser/repl.ts`, with element-specific renderers implemented in `src/vs/workbench/contrib/debug/browser/replViewer.ts`; the proposed architectural replacement has not landed.
- **original limitations partly resolved:** `Repl.createReplTree` now enables `userSelection`, `findWidgetEnabled`, filtering, conditional horizontal scrolling, and dynamic heights for word wrapping. `src/vs/workbench/contrib/debug/browser/debug.contribution.ts` also exposes `debug.console.wordWrap`, `debug.console.fontFamily`, `debug.console.fontSize`, and `debug.console.lineHeight`.
- **related work is narrower:** https://github.com/microsoft/vscode/issues/127498 concerns sharing only the input widget, while https://github.com/microsoft/vscode/issues/173520 concerns editor-setting consistency and https://github.com/microsoft/vscode/issues/201772 concerns opening consoles as editors. All are younger and narrower than this architecture discussion, so none qualifies as the canonical duplicate under the re-review rule.
- **remaining tree-specific gaps:** Open reports such as https://github.com/microsoft/vscode/issues/268456 and https://github.com/microsoft/vscode/issues/322732 continue to describe selection/copy limitations, but they are specific bugs rather than proof that a wholesale architecture replacement is the required fix.
