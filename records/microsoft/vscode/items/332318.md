# Issue #332318 — [Auto v2] Pasted text attachment placeholder is scored instead of its content

[https://github.com/microsoft/vscode/issues/332318](https://github.com/microsoft/vscode/issues/332318)

## Summary

Confirmed by tracing the code: Auto v2's routing request builds `prompt` from `chatRequest.prompt.trim()` in `resolveAutoModeEndpoint` (extensions/copilot/src/platform/endpoint/node/automodeService.ts) with no resolution of pasted-text attachment references, so the literal `#attachment:Pasted text #N` placeholder is sent to `POST /auto` instead of the pasted content — exactly as the reporter's offline HYDRA replay shows.

## Change summary

When a long paste becomes a `#attachment:Pasted text #N` reference in Chat, Auto Mode v2 scores the placeholder string instead of the actual pasted content for model routing.

## Best solution

In `resolveAutoModeEndpoint` (automodeService.ts), before calling `_autoV2Fetcher.getAutoDecision`, resolve any pasted-text attachment placeholders in `prompt` using `chatRequest.references` (the same references array `hasImage()` already inspects for image attachments) so the routed prompt contains the actual pasted text, not the UI placeholder.
