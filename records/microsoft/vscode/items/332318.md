# Issue #332318 — [Auto v2] Pasted text attachment placeholder is scored instead of its content

[https://github.com/microsoft/vscode/issues/332318](https://github.com/microsoft/vscode/issues/332318)

## Summary

Real, well-diagnosed correctness bug in Auto v2 model routing (pasted-text attachments are scored as their placeholder string, not their content), but the maintainer's own comment shows this is an open cross-product design question, not something ready to close — keep it open for that discussion.

## Change summary

Auto v2 model routing scores the literal `#attachment:Pasted text #N` placeholder instead of the resolved pasted-text content, which can steer model selection with irrelevant capability scores.

## Best solution

Resolve as a cross-product decision between VS Code chat (which builds the Auto request) and CAPI's auto_handler/intent client — either VS Code should resolve pasted-text (and other attachment) content into the prompt sent to /auto, or the /auto contract needs to become attachment-aware; lramos15's comment notes this generalizes to any attachment (e.g. pasted markdown plans) and needs a cross-product answer before implementing.
