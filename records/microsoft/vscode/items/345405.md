# Issue #345405 — Initially collapsed TreeView stays blank for ~2 seconds: populated ListView retains a 0x0 viewport until delayed layout

[https://github.com/microsoft/vscode/issues/345405](https://github.com/microsoft/vscode/issues/345405)

## Summary

The initial-layout gap remains in current main: expansion can lay out the pane before creating its native tree, leaving the populated list without a viewport until the delayed message update. Keep this open for a bounded lifecycle fix.

## Change summary

An initially collapsed extension TreeView displays a blank body for approximately two seconds after its first expansion despite having populated data.

## Best solution

Ensure a newly created native tree receives the containing pane's valid dimensions promptly, without depending on message reassignment or changing the intentional activation delay.
