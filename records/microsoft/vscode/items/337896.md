# Issue #337896 — CLI spawns itself in an unbounded chain when more than one copy is on PATH

[https://github.com/microsoft/vscode/issues/337896](https://github.com/microsoft/vscode/issues/337896)

## Summary

Traced and confirmed on current main: `start_code()` in cli/src/bin/code/main.rs spawns a resolved desktop-CLI entrypoint with no depth guard, and `CodeVersionManager::try_get_entrypoint` in cli/src/desktop/version_manager.rs caches the first non-self PATH match without re-validating it against `current_exe()` on later runs — so once binary B's cache points at itself, every future invocation via that cache entry re-spawns B forever. This is a real, reproducible resource-exhaustion bug with a clean fix boundary.

## Change summary

With two copies of the `code` CLI binary on PATH, running a legacy editor command (e.g. `--list-extensions`) triggers an unbounded self-respawn loop that exhausts PIDs/threads instead of exiting cleanly.

## Best solution

Add a depth guard (an env var set before spawning and checked by the child) in start_code() in cli/src/bin/code/main.rs, and/or re-validate a cached entrypoint path against current_exe() in try_get_entrypoint (cli/src/desktop/version_manager.rs) before trusting it, so a self-referential cache entry can never be reused unconditionally.
