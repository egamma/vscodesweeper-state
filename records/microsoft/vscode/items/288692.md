# Issue #288692 — There's a naming collision: both `ChatContextKeys.chatSessionType` (line 65) and `ChatContextKeys.agentSessionType` (line 103) use the same context key string `'chatSessionType'`. This creates ambiguity and can lead to unexpected behavior. The `agentSessionType` export should use a different key string, such as `'agentSessionType'`.

[https://github.com/microsoft/vscode/issues/288692](https://github.com/microsoft/vscode/issues/288692)

## Summary

The naming collision remains in current main: both exports still identify the same context key. The linked fix PR was closed without merging, so the issue remains necessary.

## Change summary

Give chat-session type and agent-session-item type independent context-key identities.

## Best solution

Make the two context values independently addressable while preserving the existing chatSessionType identity and ensuring agent-session producers and predicates continue to agree. Pin their independence with a focused regression test.
