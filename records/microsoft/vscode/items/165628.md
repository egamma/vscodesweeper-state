# Issue #165628 — Please show base by default in the 3-way-merge editor

[https://github.com/microsoft/vscode/issues/165628](https://github.com/microsoft/vscode/issues/165628)

## Summary

The base view still starts hidden on current main; existing commands remember an explicit choice but do not satisfy the requested default. Keep this accepted request open for a maintainer decision on default visibility and discoverability.

## Change summary

Show the common ancestor by default in the merge editor, aligned horizontally with the two inputs while retaining the option to hide it.

## Best solution

Make the common ancestor readily discoverable during conflict resolution, with an explicit decision on whether new profiles should show it by default and in which position. Preserve users' saved layout choices and the ability to hide the base.

- **Trace:**

  > MergeEditorLayoutStore in src/vs/workbench/contrib/mergeEditor/browser/view/mergeEditor.ts initializes both fresh and legacy string layouts with showBase: false and persists layout objects in PROFILE storage under mergeEditor/layout. MergeEditor initializes its layout observable from that store and applies it when creating the editor control. ShowHideBase, ShowHideTopBase, and ShowHideCenterBase in browser/commands/commands.ts expose layout-dependent editor-title menu actions; their corresponding MergeEditor methods change visibility and placement. Existing manual controls therefore cover availability and persistence, not default visibility or discoverability. Preserve conflict-resolution semantics, explicit saved preferences, and the ability to hide the base. https://github.com/microsoft/vscode/issues/180710 has been consolidated here; https://github.com/microsoft/vscode/issues/162730 concerns layout orientation rather than the same request. The unresolved boundary is the intended initial visibility and placement, not whether base rendering is supported.
- **Open decisions:**
  - Should fresh profiles show the base immediately, or should this work improve discoverability while retaining the current hidden default?
  - If the base becomes visible by default, should the mixed layout place it between the inputs as requested or above them?
