# Issue #261697 — Feature Request: Customizable continuous actions per chat mode file

[https://github.com/microsoft/vscode/issues/261697](https://github.com/microsoft/vscode/issues/261697)

## Summary

A real customization gap remains: current main applies `chat.agent.maxRequests` globally and does not consume custom-agent metadata when selecting the tool-call iteration limit. The Backlog feature request should remain open while maintainers decide how a per-agent value interacts with the user's global safety limit.

## Change summary

Allow each custom agent file to specify how many agent requests may run before VS Code asks the user whether to continue.

## Best solution

Support a validated per-custom-agent request budget with an explicit precedence rule, while retaining `chat.agent.maxRequests` as the fallback and preserving the existing confirmation behavior.

- **Behavior:**

  > A custom agent can declare how many requests it may make in one turn before VS Code asks whether to continue. Different agents can use different budgets, while agents without the declaration retain the global `chat.agent.maxRequests` behavior. The existing continuation prompt and the user's ability to pause or continue remain unchanged. Acceptance must cover configured, omitted, and invalid per-agent values plus the selected interaction with the global setting.
- **Trace:**

  > On current main, custom-agent frontmatter is parsed under `src/vs/workbench/contrib/chat/common/promptSyntax/`; generic `advancedOptions` values become `IAgentInstructions.metadata` in `CustomAgent.fromParsedPromptFile`. That metadata reaches chat requests, but the local Copilot path in `extensions/copilot/src/extension/intents/node/agentIntent.ts` obtains `maxToolCallIterations` from accepted continuation data or `getAgentMaxRequests`, which reads only the global setting. No per-agent request-limit attribute or consumer exists. Keep the existing confirmation flow and continuation acceptance semantics unchanged; the uncertainty begins at whether an agent file may override the user's global value or only lower it.
- **Open decisions:**
  - Should a custom-agent request budget fully override `chat.agent.maxRequests`, or may it only impose a lower cap than the user's global value?
