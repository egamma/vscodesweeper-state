Keep open as a confirmed macOS native-dialog issue. The custom dialog provides a workaround, but neither a fix nor an older canonical covering the same filename-extension loss was established.

## Change summary

Preserve the full filename when selecting an existing file with an extension longer than four characters in the macOS Save As dialog.

## Best solution

## Evidence

- **Confirmed report:** https://github.com/microsoft/vscode/issues/203384 describes selecting test.htmlx in Save As and seeing only test in the filename field, with no installed extensions. In the supplied January 25, 2024 comment, bpasero confirms reproduction and reports similar behavior in other macOS applications.
- **Current native-dialog boundary:** src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts routes pickFileToSave through nativeHostService.showSaveDialog and forwards defaultPath and filters in toNativeSaveDialogOptions. src/vs/platform/dialogs/electron-main/dialogMainService.ts delegates to electron.dialog.showSaveDialog; its returned-path normalization only performs macOS Unicode normalization. These paths do not implement the native panel's filename-field updates when an existing file is clicked.
- **Filter behavior:** src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts:getPickFileToSaveDialogOptions constructs language-extension filters with All Files first. No four-character extension limit appears in this path; the precise native-panel cause remains unverified.
- **Workaround remains available:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers files.simpleDialog.enable, default false. FileDialogService.shouldUseSimplified selects the custom dialog when it is true. The reporter accepted this workaround in the supplied January 30, 2024 comment, but did not confirm that the native-dialog defect was fixed.
- **Canonical search:** Save-dialog and extension-loss searches did not establish an older open issue reporting the same symptom. https://github.com/microsoft/vscode/issues/102713 is closed and concerns rejection of a manually entered extension, not stripping an extension on selection. https://github.com/microsoft/vscode/issues/288672 is open but newer and concerns appending .text on save; it does not satisfy the re-review duplicate bar.

No concrete fixing commit was identified, and the confirmed historical reproduction should not be mistaken for proof of current runtime behavior.
