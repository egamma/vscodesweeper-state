# Issue #328677 — UriIdentityService retains stale canonical URI cache after path casing capability changes

[https://github.com/microsoft/vscode/issues/328677](https://github.com/microsoft/vscode/issues/328677)

## Summary

Confirmed on main: the capability-change listener in UriIdentityService compares `newIgnorePathCasingValue` to itself instead of the cached old value, so canonical URI cache invalidation never runs — but an open PR already fixes it, so this stays open pending merge rather than closing as completed.

## Change summary

UriIdentityService keeps returning a stale cached canonical URI after a filesystem provider's path-casing capability changes at runtime, because the invalidation check is tautological.

## Best solution

Land https://github.com/microsoft/vscode/pull/328679, which changes the comparison to `oldIgnorePathCasingValue === newIgnorePathCasingValue` and adds a regression test in uriIdentityService.test.ts; once merged this issue is fully resolved.
