# Issue #49925 — Add commands to outline elements

[https://github.com/microsoft/vscode/issues/49925](https://github.com/microsoft/vscode/issues/49925)

## Summary

Still an open gap on current main: the Outline pane has no per-element context menu and no extension contribution point for one, so symbol-level commands (rename, find references, breakpoints) remain unavailable from the view. With 94 upvotes, a team author, and a Backlog milestone, this stays open and is a good candidate for a design pass with a maintainer.

## Change summary

Offer commands on Outline elements (rename, find references, etc.) and open the element context menu to extension contributions.

## Best solution

Introduce a per-element context menu in the document-symbol Outline pane backed by a new contributable MenuId (mirroring the existing NotebookOutlineActionMenu), seeded with the symbol-level commands that already exist (rename, find all references) scoped by a symbol/language context key; drag-and-drop reordering is a separate, much larger ask and should not block the menu work.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/outline/browser/outlinePane.ts`, `src/vs/workbench/contrib/outline/browser/outlineActions.ts`, `src/vs/platform/actions/common/actions.ts`, `src/vs/workbench/services/actions/common/menusExtensionPoint.ts`
- **Validation:** With a prototype menu registered, right-clicking a symbol in the Outline view shows the contributed commands and invoking Rename/Find All References acts on that symbol's range; plus a unit test asserting the new MenuId resolves contributed items with the outline element context.
- **Behavior:**

  > Right-clicking (or pressing the context-menu key on) an element in the Outline view opens a menu with commands that act on that symbol — at minimum Rename Symbol and Find All References — and extensions can contribute their own entries through a documented `menus` contribution point, scoped by symbol kind and language. Invoking a command targets the symbol's range in the underlying document without requiring the cursor to be moved there first. Acceptance: the menu appears for document-symbol outlines, built-in entries operate on the right symbol, a contributed entry from a test extension shows up and receives the symbol as its argument, and the Outline view title actions (sort/filter/follow cursor) are unchanged.
- **Trace:**

  > On current main the Outline pane (src/vs/workbench/contrib/outline/browser/outlinePane.ts) injects IContextMenuService only for the tree widget plumbing, and src/vs/workbench/contrib/outline/browser/outlineActions.ts registers every action into MenuId.ViewTitle — nothing element-scoped. src/vs/platform/actions/common/actions.ts declares only NotebookOutlineFilter and NotebookOutlineActionMenu, so the notebook outline is the only existing precedent for an item-level menu and is the natural shape to mirror; menusExtensionPoint.ts has no outline item key, which is why https://github.com/microsoft/vscode/issues/67935 could not be satisfied. The boundary: do not change the IOutline/IOutlineService provider contract or the existing view-title actions, and keep notebook-outline behavior as-is. Uncertainty starts at the contribution surface — menu id naming, the context the command receives (symbol vs. document range vs. a URI+position), and which built-in commands ship by default. Drag-and-drop reordering requested in the thread implies document edits via a provider and is a separate design.
- **Open decisions:**
  - Which commands ship in the Outline element menu by default — only Rename Symbol and Find All References, or the broader editor symbol set?
  - What is the public contribution point and the argument contract extensions receive (symbol kind/name plus a URI+position, or a richer outline-element object)?
  - Is drag-and-drop/move refactoring in scope for this issue, or should it be split into its own request?
  - Should the menu also apply to non-document-symbol outline sources (e.g. notebook, breadcrumbs reuse), or stay limited to the document-symbol Outline pane?

## Evidence

- **gap on main:** src/vs/workbench/contrib/outline/browser/outlinePane.ts only injects IContextMenuService for the tree widget; outlineActions.ts registers exclusively into MenuId.ViewTitle (sort/filter/follow-cursor). No element-level menu or action is registered.
- **no contribution point:** rg over src/vs/platform/actions/common/actions.ts finds only NotebookOutlineFilter and NotebookOutlineActionMenu — no MenuId for document-symbol outline items, and menusExtensionPoint.ts exposes no `outline/item/context` key, so the extension ask in https://github.com/microsoft/vscode/issues/67935 is still unmet in core.
