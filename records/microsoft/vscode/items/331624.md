# Issue #331624 — Markdown editor (experimental): anchor links to headings do not navigate, in the same document or across files

[https://github.com/microsoft/vscode/issues/331624](https://github.com/microsoft/vscode/issues/331624)

## Summary

Real, well-diagnosed bug in the experimental hybrid Markdown editor: anchor/fragment links resolve correctly but the navigation is dropped because the underlying open path relies on a `selection` option that custom text editors never apply.

## Change summary

Clicking a `#fragment` link (same-document or cross-file) in the experimental Markdown editor fails to scroll to the target heading, while the same links work in Markdown Preview.

## Best solution

In extensions/markdown-language-features, have the openLink handling (src/util/openDocumentLink.ts, wired from src/preview/markdownEditorProvider.ts) explicitly reveal the resolved position inside the custom editor's webview — e.g. post a 'revealPosition' message to the target editor's webview — instead of relying on `vscode.open`'s `selection` option, which core only applies to text-model editors (see applyTextEditorOptions call sites) and is silently ignored by CustomTextEditor webviews.

## Evidence

- **link open path:** extensions/markdown-language-features/src/util/openDocumentLink.ts `MdLinkOpener.openDocumentLink` resolves the fragment/heading position via the language server and opens the target with `vscode.commands.executeCommand('vscode.open', uri, { selection: rangeSelection/resolved.position, ... })`.
- **custom editor call site:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts `case 'openLink'` (around line ~ the onMessage handler) calls this same opener for the experimental `vscode.markdown.editor` CustomTextEditorProvider; no code there consumes a selection/position to scroll the webview after opening.
- **selection is text-editor only:** `applyTextEditorOptions` (src/vs/workbench/common/editor/editorOptions.ts) is only invoked from text-model editor panes — textFileEditor.ts, mergeEditor.ts, codeEditorService.ts, comments — never from a webview/custom editor pane, so `TextDocumentShowOptions.selection` passed to `vscode.open` has no effect on the Markdown editor's webview.
- **webview has no reveal message:** extensions/markdown-language-features/markdown-editor-src/editor.ts posts 'openLink' to the extension host on click but there is no corresponding inbound message type to scroll to a position/heading after the document opens or is already active.
