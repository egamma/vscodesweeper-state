# Issue #344560 — Each subagent pill registers global listeners and a cross-session autorun; large chats hit listener-leak thresholds

[https://github.com/microsoft/vscode/issues/344560](https://github.com/microsoft/vscode/issues/344560)

## Summary

Keep open: current source confirms eager global subscriptions per subagent pill and repeated nested chat-catalog scans during availability tracking. The maintainer's CPU trace attributes 5.48 seconds to this path; the related issues do not own this specific defect.

## Change summary

Reduce listener fan-out and repeated backend-chat resolution when rendering restored conversations with many subagent pills.

## Best solution

Subagent-pill rendering and availability updates should avoid repeated full-catalog resolution for every pill, and completed pills should not each require idle global subscriptions. Preserve existing navigation, drag behavior, model and credit updates, and reduced-motion behavior without raising listener-warning thresholds.

- **Current availability path:** src/vs/sessions/contrib/providers/agentHost/browser/openSubagentChat.ts:55-75 implements findSubagentChat by reading activeSession and visibleSessions and scanning candidate sessions' chats, invoking backendChatOf for each candidate. Lines 108-114 install a separate trackEnabled autorun for each action view item. An owner match narrows the session search, but does not eliminate the repeated chat scans.
- **Nested backend resolution:** src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:6894-6918 resolves each candidate through getSessionChatResource. src/vs/platform/agentHost/common/state/sessionState.ts:965-971 performs an exact-resource scan followed by a getAgentHostChatId scan; that helper can parse and decode shaped chat URIs. Across P pills and C chats, this permits O(P × C²) catalog work, becoming cubic when pill and chat counts grow together.
