# Issue #329182 — Custom endpoint model gpt-5.6-luna fails with 400 invalid_prompt (prompt_cache_options injected)

[https://github.com/microsoft/vscode/issues/329182](https://github.com/microsoft/vscode/issues/329182)

## Summary

Confirmed in source: custom-endpoint (BYOK) models get their `family` set to the raw model id, so a family that happens to collide with a Copilot-internal name like `gpt-5.6-luna` unconditionally triggers `prompt_cache_options` injection meant only for Copilot's first-party GPT-5.6 models, breaking third-party Responses API upstreams. This is a real, localized bug worth a targeted fix; not a duplicate of the related truncated-input issue.

## Change summary

A custom-endpoint model whose id matches a Copilot-internal family name (e.g. `gpt-5.6-luna`) gets Copilot-only request fields injected, causing third-party Responses API servers to reject the request with 400 invalid_prompt.

## Best solution

In `createResponsesRequestBody` (responsesApi.ts), scope `modelSupportCacheBreakPoints`/`isGpt56` (and any other Copilot-specific capability checks keyed only on `family`) to first-party Copilot endpoints, not BYOK/custom endpoints — e.g. gate on `endpoint.modelProvider`/vendor being the Copilot provider before treating a BYOK model's `family` (which is just its user-supplied model id) as a Copilot-internal family match.
