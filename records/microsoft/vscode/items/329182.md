# Issue #329182 — Custom endpoint model gpt-5.6-luna fails with 400 invalid_prompt (prompt_cache_options injected)

[https://github.com/microsoft/vscode/issues/329182](https://github.com/microsoft/vscode/issues/329182)

## Summary

Confirmed on main: BYOK/custom-endpoint model capability detection derives `family` from the user-supplied model id (`family: modelId` in byokProvider.ts), so a custom endpoint named `gpt-5.6-luna` collides with the internal `isGpt56()` family check and picks up Copilot-only Responses API fields like `prompt_cache_options`, which third-party APIs reject with 400.

## Change summary

A custom-endpoint (BYOK) model whose id happens to match a Copilot-internal model family (e.g. `gpt-5.6-luna`) gets Copilot-specific request fields injected, causing third-party Responses API servers to reject the request with 400 invalid_prompt.

## Best solution

Scope family-based capability checks (starting with `modelSupportCacheBreakPoints`/`isGpt56` consumers used in extensions/copilot/src/platform/endpoint/node/responsesApi.ts) so they only fire for genuine Copilot-hosted models — e.g. gate on `modelProvider`/vendor (set from `modelMetadata.vendor`, 'copilot' for first-party) rather than trusting the BYOK-supplied `family` string alone — so a colliding custom-endpoint model id can't trigger Copilot-only request fields.
