# Issue #329182 — Custom endpoint model gpt-5.6-luna fails with 400 invalid_prompt (prompt_cache_options injected)

[https://github.com/microsoft/vscode/issues/329182](https://github.com/microsoft/vscode/issues/329182)

## Summary

Confirmed root cause on main: custom-endpoint models get their family set to the raw model id (in byokProvider.ts), so a model id colliding with the internal 'gpt-5.6-luna' family name triggers isGpt56()-gated logic and unconditionally injects prompt_cache_options in responsesApi.ts's createResponsesRequestBody, which third-party OpenAI-compatible Responses API servers reject. An open PR already targets this exact fix, so this should stay open pending merge.

## Change summary

Custom (BYOK) endpoint requests for a model id matching 'gpt-5.6-luna' get a Copilot-internal prompt_cache_options field injected, causing third-party Responses API servers to reject the request with 400 invalid_prompt.

## Best solution

Land https://github.com/microsoft/vscode/pull/329194, which adds a guard in extensions/copilot/src/extension/byok/node/openAIEndpoint.ts to prevent prompt_cache_options (and other Copilot-specific fields gated by isGpt56) from leaking into non-Copilot custom-endpoint requests whose model id happens to collide with an internal family name.
