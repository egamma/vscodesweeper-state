This supports the observed symptom, but does not confirm the reporter's worktree root-cause hypothesis or reproduce it on current main.
- **Current document-read path:** In extensions/copilot/src/extension/tools/node/readFileTool.tsx, ReadFileTool.getSnapshot creates a TextDocumentSnapshot from workspaceService.openTextDocument(uri). extensions/copilot/src/platform/workspace/vscode/workspaceServiceImpl.ts delegates that call to workspace.openTextDocument. This reads the editor document model; it does not establish that terminal commands and the tool are using different worktrees.
- **Save-conflict mechanism:** src/vs/workbench/services/textfile/common/textFileEditorModel.ts writes with the last resolved mtime and etag, and enters conflict mode on FILE_MODIFIED_SINCE. src/vs/workbench/contrib/files/browser/editors/textFileSaveErrorHandler.ts emits the exact reported warning for that error. The warning identifies a model/disk conflict, not its cause.
- **Worktree option is related, not canonical:** https://github.com/microsoft/vscode/issues/292787 is open but requests control over background-session worktree creation, not correction of divergent reads and save conflicts. A member comment at https://github.com/microsoft/vscode/issues/292787#issuecomment-4958931026 says new sessions can choose the current repository or a worktree; that option does not prove this bug is fixed.
