# Issue #211390 — Discard Changes and Stage Changes buttons are way to close together

[https://github.com/microsoft/vscode/issues/211390](https://github.com/microsoft/vscode/issues/211390)

## Summary

Keep open: the diff gutter still presents staging and reverting as compact adjacent actions, and existing settings do not provide safer separation while retaining both. The closest matching report is newer, so it cannot replace this re-reviewed issue as the canonical.

## Change summary

Make diff-editor staging and reverting harder to confuse or accidentally activate through safer placement, clearer hierarchy, or a deliberate discard interaction.

## Best solution

Agree on a safer interaction for the diff gutter that distinguishes routine staging from destructive reverting without compromising efficient hunk review. Use this older report to consolidate the matching spacing feedback, with icon changes treated as related but separate work.

- **Behavior:**

  > The diff editor places staging and reverting close together, making opposite actions easy to confuse; the reporter describes accidentally discarding code. The finished design should keep routine staging efficient while making accidental revert substantially harder through a clearly distinguishable interaction. Acceptance should cover whole hunks, selected ranges, short hunks, side-by-side and inline layouts, and keyboard access. The precise placement or protection mechanism remains a product decision.
- **Trace:**

  > DiffEditorGutter and DiffToolBar in src/vs/editor/browser/widget/diffEditor/features/gutterFeature.ts render primary actions in a compact shared vertical toolbar, with overflow behavior changing for short first-line hunks. The gutter styles in style.css provide compact action targets without an explicit inter-item gap. diffEditor.contribution.ts contributes primary revert actions, while extensions/git/package.json contributes staging actions to the same menus. RevertHunkOrSelection.runViaToolbarContext in commands.ts dispatches directly to DiffEditorWidget.revertRangeMappings. Existing renderGutterMenu configuration hides the entire surface and does not selectively protect revert. Preserve hunk/selection edit semantics, staging behavior, generic non-Git diff support, and the existing gutter visibility setting; Source Control file-discard behavior is outside this request. Related reports are https://github.com/microsoft/vscode/issues/213469 and https://github.com/microsoft/vscode/issues/238078; neither can supersede this older re-reviewed report. Source inspection establishes the interaction structure, but no live UI validation was performed.
- **Open decisions:**
  - Should revert remain directly visible with stronger separation from stage, or become a secondary menu action while stage remains directly accessible?
  - Should gutter revert require an additional deliberate interaction, such as confirmation or a modifier, or should improved placement and hierarchy alone provide protection?
