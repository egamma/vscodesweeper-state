# Issue #229826 — SCM Graph - Date ordering

[https://github.com/microsoft/vscode/issues/229826](https://github.com/microsoft/vscode/issues/229826)

## Summary

Keep open: the Source Control Graph still requests topological ordering without exposing a date-order option. This issue is the established request for that capability; the earlier as-designed decision explains the default but does not decline an optional alternative.

## Change summary

Offer chronological commit ordering in the Source Control Graph for merge-based workflows.

## Best solution

Provide an optional date-oriented graph ordering while preserving the existing topological default. Agree on author-date versus committer-date semantics and whether chronological ordering must retain child-before-parent constraints before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/historyProvider.ts`, `extensions/git/src/git.ts`, `src/vs/workbench/contrib/scm/browser/scm.contribution.ts`, `src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts`
- **Validation:** Using a repository with interleaved commits on two branches and a subsequent merge, verify that the selected date-oriented mode follows the agreed timestamp and ancestry rules across both branches. Verify unchanged default topological ordering, consistent load-more pagination, intact parent connections, and stable ordering when switching branches with the same reference filter.
- **Behavior:**

  > The current graph can place older commits on one branch above newer commits on another, which makes merge-based workflows harder to inspect. Users want an optional date-oriented ordering; changing the default is not required. Acceptance should demonstrate the chosen ordering on interleaved branch histories, preserve graph connections, and remain consistent across pagination and branch switches when the selected references are unchanged.
- **Trace:**

  > GitHistoryProvider.provideHistoryItems in extensions/git/src/historyProvider.ts passes selected references into repository.log, and Git.log in extensions/git/src/git.ts adds --topo-order whenever those references are present. The SCM graph configuration in src/vs/workbench/contrib/scm/browser/scm.contribution.ts has no ordering control; scmHistoryViewPane.ts owns the graph view and pagination surface. The request remains unimplemented on the inspected normal history path. Preserve the existing topological default and unrelated Git log consumers. https://github.com/microsoft/vscode/issues/218228 establishes why that default is intentional, while https://github.com/microsoft/vscode/issues/237083 was explicitly consolidated into this request. The uncertainty is the observable meaning of date ordering: Git's date-order modes retain ancestry constraints and are not equivalent to unrestricted timestamp sorting.
- **Open decisions:**
  - Should the optional chronological mode order by committer date, author date, or offer both?
  - Should date ordering retain child-before-parent ancestry constraints, as Git's date-order modes do, or satisfy strict timestamp ordering even when timestamps contradict ancestry?
