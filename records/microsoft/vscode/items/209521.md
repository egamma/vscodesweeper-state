# Issue #209521 — [Bug]: Incorrect indentation when object nested inline on the same line as parent object

[https://github.com/microsoft/vscode/issues/209521](https://github.com/microsoft/vscode/issues/209521)

## Summary

The reported indentation gap remains in current source: a closed inline child object prevents the indentation rule from recognizing the still-open parent object. Keep this team-authored bug open under its existing editor-autoindent routing.

## Change summary

Pressing Enter after `const a = { b : {}, ` fails to indent the next line inside the parent object.

## Best solution

Make JavaScript and TypeScript Enter indentation recognize the unmatched parent opening brace despite balanced child objects on the same line, while preserving existing string, comment, and bracket handling.

## Evidence

- **Current indentation rules:** extensions/javascript/javascript-language-configuration.json and extensions/typescript-basics/language-configuration.json both use `^.*(\{[^}]*|\([^)]*|\[[^\]]*)$` as increaseIndentPattern. For the supplied `const a = { b : {}, ` line, neither opening brace can match the curly-brace branch because a closing brace follows it; the other branches have no opening delimiter to match.
- **Enter path:** src/vs/editor/common/languages/autoIndent.ts:getIndentForEnter delegates to getInheritIndentForLine, whose indentation-increase branch depends on shouldIncrease or shouldIndentNextLine. The supplied object declaration matches neither configured rule. src/vs/editor/common/languages/supports/onEnter.ts also provides no fallback increase here: its generic opening-bracket rule requires the opening bracket to end the text apart from whitespace.
- **Preprocessing does not resolve this case:** src/vs/editor/common/languages/supports/indentationLineProcessor.ts:IndentationLineProcessor.getProcessedTokens removes brackets only from string, regular-expression, and comment tokens. The nested object braces are code tokens and remain in the text evaluated by the indentation rule.
- **Discussion and ownership:** At https://github.com/microsoft/vscode/issues/209521, the MEMBER author identifies the failing pattern and discusses bounded recursive matching in the 2024-04-04 follow-up. This is an accepted bug with a concrete example, not a support question or an insufficient-information report.

The older open https://github.com/microsoft/vscode/issues/193875 concerns closing-brace indentation after nested brace-less for statements, not missing indentation after an inline child object, so it does not meet the re-review duplicate bar.
