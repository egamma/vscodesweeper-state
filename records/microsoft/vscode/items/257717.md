# Issue #257717 — Expect scrollbar in commit message input box

[https://github.com/microsoft/vscode/issues/257717](https://github.com/microsoft/vscode/issues/257717)

## Summary

Keep open for SCM design discussion: current source still deliberately hides the commit-input scrollbar, leaving long messages without a scroll-position indicator. The maintainer discussion establishes the layout tradeoff and rejects replacing Commit as the primary action; this team-authored Backlog item has no verified factual closure.

## Change summary

Show a scrollbar in the Source Control commit-message input so users can judge the extent and scroll position of long messages.

## Best solution

Provide a usable scrollbar alongside the commit-input actions while preserving Commit as the primary action and keeping message generation separate from committing. Settle the scrollbar/action layout in the SCM input before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/scmInput.ts`, `src/vs/workbench/contrib/scm/browser/media/scm.css`
- **Validation:** After a design is agreed, open Source Control on Windows with a Git repository and enter a message exceeding scm.inputMaxLineCount. Verify the scrollbar indicates extent and position and can reach both ends; repeat with the generation/setup action visible, hidden, and with dropdown actions, including a narrow sidebar. Confirm controls do not obscure each other and that generation never commits without a separate Commit invocation.
- **Behavior:**

  > Long messages in the Source Control commit input currently require scrolling without a scrollbar indicating their extent or the current position. The finished experience should expose a usable scrollbar when the message exceeds the input height, including for generated messages. Commit remains the primary action, and generating or regenerating a message remains separate from committing. Acceptance includes inspecting and navigating the full message without collisions between the scrollbar and input actions.
- **Trace:**

  > SCMInputWidgetEditorOptions.getEditorConstructionOptions() in src/vs/workbench/contrib/scm/browser/scmInput.ts explicitly hides the vertical scrollbar; getEditorOptions() does not subsequently override it. SCMInputWidget.getContentHeight() caps auto-growth using scm.inputMaxLineCount, while layout() and getToolbarWidth() allocate space to the input toolbar. The .scm-editor flex layout and toolbar scroll-decoration styles live in src/vs/workbench/contrib/scm/browser/media/scm.css. This establishes the missing affordance from source without executing the UI. The discussion at https://github.com/microsoft/vscode/issues/257717 rejects combining generation with Commit; preserve that distinction, keyboard editing, and message content. The uncertainty is the observable arrangement of the scrollbar and secondary input actions, not whether a larger auto-growth limit substitutes for a scrollbar.
- **Open decisions:**
  - Should the scrollbar occupy a separate lane within the text editor beside the input toolbar, or should the input actions move to a different location to give the scrollbar the input's outer edge?

## Evidence

- **Current behavior:** src/vs/workbench/contrib/scm/browser/scmInput.ts:277–295, SCMInputWidgetEditorOptions.getEditorConstructionOptions(), explicitly sets scrollbar.vertical to 'hidden'. getEditorOptions() does not expose a scrollbar override, so the requested affordance remains absent.
- **Existing capabilities do not cover the request:** src/vs/workbench/contrib/scm/browser/scm.contribution.ts registers scm.inputMaxLineCount, default 10 and maximum 50. SCMInputWidget.getContentHeight() clamps the input height accordingly. Raising that limit reduces overflow for some messages but does not supply a scrollbar; disabling scm.showInputActionButton also leaves the scrollbar explicitly hidden.
- **Current layout boundary:** SCMInputWidget.layout() and getToolbarWidth() in src/vs/workbench/contrib/scm/browser/scmInput.ts reserve horizontal space for the input toolbar. src/vs/workbench/contrib/scm/browser/media/scm.css lays out .scm-editor with flex and adds a scroll-decoration shadow to its toolbar. These affordances do not indicate total message extent or provide a draggable scroll thumb.
- **Maintainer direction:** The supplied discussion at https://github.com/microsoft/vscode/issues/257717 explains that hiding the scrollbar was intentional to avoid conflicting with input actions. On 2025-12-11, the maintainer explicitly rejected combining generation and committing because Commit must remain primary and the sparkle also serves as a setup entry point.
