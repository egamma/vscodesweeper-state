# Issue #332434 — Agent Host: dispatchAction does validate not whether clients can dispatch that action

[https://github.com/microsoft/vscode/issues/332434](https://github.com/microsoft/vscode/issues/332434)

## Summary

Confirmed on current main: the dispatchAction handler in protocolServerHandler.ts still gates on action-family membership (isSessionAction/isChatAction/etc.) rather than per-type client-dispatchability, so server-owned action types within an allowed family pass through unvalidated.

## Change summary

The AHP protocol server's dispatchAction guard checks action family, not whether the specific action type is client-dispatchable, letting clients dispatch server-owned actions like automation/set or session/ready.

## Best solution

Replace the family-guard disjunction in protocolServerHandler.ts's dispatchAction notification handler with a per-type isClientDispatchable(action) check (expanding its parameter/return type to cover AutomationAction/AutomationRunAction as needed), rejecting non-client-dispatchable actions the same way UNSUPPORTED_CLIENT_ACTION_TYPES are rejected today.
