# Issue #320566 — Roo Code on Win11 - Codebase Indexing "Error - Failed during initial scan: Could not find ripgrep binary"

[https://github.com/microsoft/vscode/issues/320566](https://github.com/microsoft/vscode/issues/320566)

## Summary

The indexing failure comes from Roo Code 3.54.0 probing obsolete internal ripgrep paths, not from VS Code's own binary lookup. Propose closing as caused by this third-party extension; the discussion confirms that restoring those legacy paths temporarily restores functionality.

## Change summary

Restore Roo Code codebase indexing when its ripgrep lookup fails in a remote Linux workspace.

## Best solution

Roo Code should resolve or supply its ripgrep executable without depending on obsolete VS Code installation paths. Repeatedly modifying VS Code's installation is not a durable recovery procedure; this belongs with Roo Code rather than VS Code core.

## Evidence

- **Exact extension-owned failure path:** In the reported Roo Code v3.54.0, DirectoryScanner.scanDirectory calls listFiles: https://github.com/RooCodeInc/Roo-Code/blob/v3.54.0/src/services/code-index/processors/scanner.ts. listFiles obtains the executable through getRipgrepPath, which throws the exact 'Could not find ripgrep binary' error when getBinPath returns undefined: https://github.com/RooCodeInc/Roo-Code/blob/v3.54.0/src/services/glob/list-files.ts.
- **Hardcoded legacy paths:** https://github.com/RooCodeInc/Roo-Code/blob/v3.54.0/src/services/ripgrep/index.ts implements getBinPath by checking four filesystem paths under @vscode/ripgrep or vscode-ripgrep. It does not check @vscode/ripgrep-universal, explaining the failure when only the newer package is present.
- **Current VS Code boundary:** The checkout's package.json and remote/package.json depend on @vscode/ripgrep-universal. src/vs/base/node/ripgrep.ts obtains rgPath from that package rather than guessing its filesystem layout. src/vs/workbench/api/common/extHostRequireInterceptor.ts aliases legacy module names to the new package, but Roo Code's direct filesystem probes do not use module resolution.
- **Discussion corroborates diagnosis:** https://github.com/microsoft/vscode/issues/320566#issuecomment-4670072721 identifies the package-directory mismatch and supplies Windows/WSL workarounds. https://github.com/microsoft/vscode/issues/320566#issuecomment-5013388752 reports Ubuntu impact, and https://github.com/microsoft/vscode/issues/320566#issuecomment-5613841400 confirms symlinking works until another VS Code update. These are consistent with extension dependence on installation-internal paths, not solely the reporter's temporary-file deletion.
- **External ownership:** The installed extension is rooveterinaryinc.roo-cline, a third-party extension outside the VS Code-owned roster. Its verified repository is https://github.com/RooCodeInc/Roo-Code; GitHub currently marks that repository archived, so this review does not promise that a new issue can be filed there.
