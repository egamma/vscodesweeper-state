## Evidence

Pylance HTTP endpoints and a remote HTTPS server fail initialization, while REA and the built-in GitHub MCP server connected in an earlier session; this does not establish a universal MCP failure.
- **Complete follow-up distinguishes causes:** https://github.com/microsoft/vscode/issues/343108#issuecomment-6307162234 reports that the remote endpoint accepts TLS 1.3 but rejects TLS 1.2, and that a separate reqwest 0.13.5 native-tls client fails against it. The reporter explicitly identifies the runtime backend selection as an inference, excludes this explanation for the localhost failures, and notes that the reproduction client source and exact error output are not attached.
- **Current configuration boundary:** src/vs/platform/mcp/common/mcpCopilotConfiguration.ts::toCopilotMcpServerConfiguration forwards HTTP/SSE URLs and headers. src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts::toSessionConfigMcpServers combines root configuration and explicitly projected plugin servers for the SDK. These inspected paths do not establish which native TLS backend performs the connection.
- **Current initialization boundary:** src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts:1376-1382 documents lazy MCP initialization and starts servers through this._wrapper.session.rpc.mcp.list(). Source inspection did not conclusively reproduce the reported connection failure; no runtime execution was performed.
- **Endpoint caching is a lead, not proof:** src/vs/workbench/contrib/mcp/common/discovery/extensionMcpDiscovery.ts restores cached extension server definitions into a lazy collection, whose load path activates the extension and waits for initial provider promises. This warrants tracing endpoint refresh, but caching alone does not prove that the Copilot runtime received a stale Pylance URL.
- **Ownership remains unresolved:** A later observation that nothing listened on port 55260 does not establish whether the endpoint was already unavailable during initialization. Likewise, the Sequel Ace shim's failure to reach its own backend is not proof of a VS Code transport defect. Pylance involvement alone cannot justify closing the broader Copilot/MCP report as extension-caused.
