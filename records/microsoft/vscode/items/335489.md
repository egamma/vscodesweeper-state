# Issue #335489 — Git Clone in Agents Window: Offer to start new session in cloned repo

[https://github.com/microsoft/vscode/issues/335489](https://github.com/microsoft/vscode/issues/335489)

## Summary

The standard Git clone completion dialog still offers editor-oriented actions, not starting an Agents Window session. Keep this team-authored request open: the existing session-aware cloning paths cover different entry points, and no verified canonical owns this specific request.

## Change summary

Offer to start a new session in the cloned repository when Git Clone completes in the Agents Window.

## Best solution

Provide a session-aware post-clone action that opens a new-session composer targeting the cloned repository, while preserving normal clone completion behavior in the Editors window. The maintainer should settle whether the Agents Window retains the existing editor-opening choices alongside that action.

## Plan brief

- **Likely files:** `extensions/git/src/cloneManager.ts`, `extensions/git/src/commands.ts`, `src/vs/sessions/contrib/chat/browser/agentsWindowWorkspaceHandoff.ts`, `src/vs/sessions/services/sessions/browser/sessionsService.ts`
- **Validation:** Manually invoke Git: Clone in the Agents Window with git.openAfterClone set to prompt, clone a repository, and accept the session action: a new-session composer must target that repository without sending a prompt automatically. Canceling must leave existing sessions unchanged. Repeat in the Editors window and confirm its existing completion choices and behavior remain unchanged.
- **Behavior:**

  > After Git Clone succeeds in the Agents Window, its completion dialog should offer to start a new session using the cloned repository. Accepting should reveal a new-session composer targeting that repository, without automatically submitting a request. Declining should leave existing sessions unchanged. The Editors window should retain its current post-clone behavior.
- **Trace:**

  > The standard git.clone command in extensions/git/src/commands.ts delegates to CloneManager, whose doPostCloneAction in extensions/git/src/cloneManager.ts constructs the editor-oriented completion dialog. git.openAfterClone controls opening behavior but has no session action. Existing Sessions cloning paths explicitly suppress that dialog and consume the returned repository path, so they are precedent for repository selection, not coverage of this entry point. AgentsWindowWorkspaceHandoff.selectWorkspace in src/vs/sessions/contrib/chat/browser/agentsWindowWorkspaceHandoff.ts already coordinates new-session navigation and workspace selection, including preservation of user intent; the bridge from standard clone completion into Sessions remains to be designed. Preserve the Sessions-to-workbench layer direction, existing editor behavior, clone cancellation, and existing session contents. Related https://github.com/microsoft/vscode/issues/251644 addresses carrying existing chat state across workspace transitions, not starting a new session, and should remain outside this request's scope.
- **Open decisions:**
  - In the Agents Window completion dialog, should starting a new session replace the editor-oriented opening choices, or appear alongside them?
