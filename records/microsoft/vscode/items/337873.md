# Issue #337873 — Copilot Chat codebase index re-indexes on every reload and freezes the extension host

[https://github.com/microsoft/vscode/issues/337873](https://github.com/microsoft/vscode/issues/337873)

## Summary

Confirmed on current main: `ExternalIngestIndex.createFreshDatabase` opens the SQLite path with no `mkdirSync(dirname(...), {recursive:true})` guard, unlike sibling DB-open helpers in the same bundle, so a missing per-extension storage folder makes every reload silently fall back to an in-memory index and re-ingest the whole workspace, freezing the extension-host event loop for minutes.

## Change summary

The Copilot Chat codebase-index SQLite DB silently falls back to `:memory:` and re-indexes from scratch on every reload when the extension's per-workspace storage folder doesn't exist, pinning the extension host and freezing the window for minutes.

## Best solution

Create the parent directory before opening the on-disk database in `openOrCreateDatabase`/`createFreshDatabase` (extensions/copilot/src/platform/workspaceChunkSearch/node/codeSearch/externalIngestIndex.ts), matching the `mkdirSync(dirname(...), {recursive:true})` pattern already used by the other DB-open helpers in the same bundle so the on-disk index is created and reused instead of falling back to `:memory:`.
