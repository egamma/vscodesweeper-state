# Issue #335232 — vscode.dev/agents: opening a large Agent Host conversation repeatedly disconnects tunnel after >1 MB chat snapshot

[https://github.com/microsoft/vscode/issues/335232](https://github.com/microsoft/vscode/issues/335232)

## Summary

Traced conclusively in source: the browser-side tunnel WebSocket framer (`TunnelMessageSocket` in webSocketOverDuplex.ts) enforces a hard 1 MB per-frame ceiling with no fragmentation ever produced on the write side, so any single AHP message over ~1 MB is rejected as a `WebSocketFrameTooLargeError` and the transport is torn down and reconnected in a loop — exactly matching the reporter's numbers and console trace.

## Change summary

Opening a large Agent Host conversation over vscode.dev/agents + a VS Code tunnel causes a repeated transport disconnect/reconnect loop instead of loading.

## Best solution

Raise (or remove) the arbitrary `defaultMaxFramePayloadLength = 0x100000` frame ceiling in src/vs/platform/agentHost/common/webSocketOverDuplex.ts so it isn't lower than `defaultMaxMessagePayloadLength` (0x800000) — since this implementation never fragments outbound messages into continuation frames, the frame-level cap is functioning as a de-facto (and too low) message cap; align it with the message-level limit or implement real write-side fragmentation.
