# Issue #104154 — Allow blocked environment variables through if they're included explicitly in terminal launch configs

[https://github.com/microsoft/vscode/issues/104154](https://github.com/microsoft/vscode/issues/104154)

## Summary

The specific GOOGLE_API_KEY blocker was fixed in 2020 (commit 1248ddadb8c), and the current code already re-applies explicitly configured env vars after sanitization. However, the broader request — a more explicit allowlist/passthrough mechanism — may still have value for edge cases. Keeping open as a backlog feature request with `help wanted`.

## Change summary

Allow environment variables that match blocked patterns (ELECTRON_*, VSCODE_*) to pass through when explicitly set in terminal launch configurations.

## Best solution

The original GOOGLE_API_KEY problem is solved. For `terminal.integrated.env` and terminal profile `env`, explicitly set vars already survive sanitization because `mergeEnvironments` runs after `sanitizeProcessEnvironment` in `createTerminalEnvironment` (src/vs/workbench/contrib/terminal/common/terminalEnvironment.ts:295-299). The remaining gap, if any, is a more intentional preserve mechanism or documentation. A maintainer should verify whether the current implicit ordering is sufficient or if `sanitizeProcessEnvironment`'s `preserve` parameter should be used to explicitly pass through user-configured keys, then close if the current behavior is adequate.
