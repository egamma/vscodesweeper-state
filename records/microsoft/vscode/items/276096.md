# Issue #276096 — Debug API: `vscode.debug.breakpoints` returns duplicate breakpoints for the same line after deleting code blocks

[https://github.com/microsoft/vscode/issues/276096](https://github.com/microsoft/vscode/issues/276096)

## Summary

The current source still silently drops colliding breakpoints without notifying the extension host, leaving ghost entries in the debug API. Keep this open while the existing fixing PR is reviewed and landed.

## Change summary

Keep vscode.debug.breakpoints and its change events synchronized when editing code causes source breakpoints to collide.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/310779 after confirming that collision removals propagate through the debug API and that removing the surviving breakpoint leaves no ghost entries.

## Evidence

- **Confirmed reproduction in discussion:** The December 18 comment on https://github.com/microsoft/vscode/issues/276096 independently reproduces the problem by setting breakpoints on adjacent lines and deleting the lower line. Removing the remaining visible breakpoint, including through Remove All Breakpoints, leaves a ghost API entry.
- **Current model drops entries without removal events:** src/vs/workbench/contrib/debug/common/debugModel.ts:1836-1846 updates breakpoint positions, invokes sortAndDeDup(), and emits only changed entries. At lines 1945-1959, sortAndDeDup() discards duplicate URI/line/column entries without returning or reporting the removed breakpoint IDs.
- **Extension-host synchronization explains the symptom:** src/vs/workbench/api/browser/mainThreadDebugService.ts:148-166 forwards only the model event's explicit added/removed/changed fields. In src/vs/workbench/api/common/extHostDebugService.ts:738-802, changed entries update locations but only delta.removed deletes breakpoint IDs; the breakpoints getter at lines 313-316 returns every retained entry. Consequently, the silently discarded model breakpoint remains exposed by the API.
- **Existing open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/310779 is OPEN and explicitly says Fixes #276096. Its description addresses this exact silent-deduplication path by reporting dropped entries as removed; it is not a landed fix.
- **Canonical search:** An open-issue search for breakpoint duplicates found no verified canonical for this symptom. The supplied older lead, https://github.com/microsoft/vscode/issues/126257, is open but concerns excessive setBreakpoints requests when calling removeBreakpoints, not ghost API entries after editing-induced collisions.
