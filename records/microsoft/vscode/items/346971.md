## Evidence

- **Current source confirms the defect:** In extensions/git/src/timelineProvider.ts, GitTimelineProvider.provideTimeline requests limit + 1 commits, stores the extra commit's hash as cursor, and removes that commit with splice. It then calculates previousRef as commits[index + 1]?.hash ?? emptyTree. For the last displayed commit, this incorrectly selects emptyTree despite an earlier revision being available through the cursor.
- **Incorrect reference reaches the diff editor:** extensions/git/src/commands.ts:4804–4825, CommandCenter.resolveTimelineOpenDiffCommand, passes toGitUri(uri, item.previousRef) directly as the original document to vscode.diff.
- **Independent reproduction:** The supplied maintainer comment on https://github.com/microsoft/vscode/issues/346971 confirms the three-commit reproduction on Linux Insiders: the second commit compares against Git's empty tree, while the newest and genuine initial commits compare correctly.
- **Open implementation candidate:** The supplied related-item context identifies https://github.com/microsoft/vscode/pull/346973, titled "Preserve Git timeline page boundary diffs", as open.
