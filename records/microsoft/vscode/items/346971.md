# Issue #346971 — Git timeline shows whole-file additions at page boundaries

[https://github.com/microsoft/vscode/issues/346971](https://github.com/microsoft/vscode/issues/346971)

The page-boundary defect remains in current source and has a maintainer-confirmed reproduction. Keep this open while the linked fixing PR is reviewed and merged.

## Change summary

File Timeline page-boundary commits incorrectly compare against an empty document instead of their preceding revision.

Review and land https://github.com/microsoft/vscode/pull/346973 so boundary entries retain their preceding file revision while genuine initial commits still compare against the empty tree.

## Evidence

- **Current source defect:** In extensions/git/src/timelineProvider.ts, GitTimelineProvider.provideTimeline requests limit + 1 commits, stores the look-ahead hash as cursor, and removes that commit before assigning previousRef = commits[index + 1]?.hash ?? emptyTree. The last displayed commit therefore receives emptyTree despite an earlier revision being available.
- **Observable diff path:** extensions/git/src/commands.ts:4804–4824, resolveTimelineOpenDiffCommand, passes toGitUri(uri, item.previousRef) directly as the original document to vscode.diff. With timeline.pageSize = 2, opening version 2 consequently compares both existing lines against an empty document.
- **Independent confirmation:** The supplied discussion on https://github.com/microsoft/vscode/issues/346971 includes alexdima's Linux Insiders reproduction confirming the incorrect empty-tree comparison for the second entry and the correct empty-tree comparison for the genuine initial commit.
- **Open implementation candidate:** GitHub inspection confirms https://github.com/microsoft/vscode/pull/346973 is OPEN, has no merge commit, and explicitly says Fixes #346971. Its description identifies first-page and subsequent-page regression cases and the initial-commit control; these are reported PR results, not checks executed during this review.
