# Issue #336544 — Cannot create a workspace-less chat session for a remote agent host

[https://github.com/microsoft/vscode/issues/336544](https://github.com/microsoft/vscode/issues/336544)

## Summary

Confirmed gap in source: remote agent host providers don't opt into workspace-less ("quick chat") sessions the way the local provider does, so the picker can't offer a Chat session against a remote host — this is a real, unaddressed capability gap rather than something already covered.

## Change summary

The New Session picker only lets you create a workspace-less "Chat" session against the local/default agent host; selecting a remote agent host (SSH/WSL/devcontainer) forces you into a workspace-bound session.

## Best solution

Extend `RemoteAgentHostSessionsProvider` (and its `DevContainerAgentHostSessionsProvider` base in src/vs/sessions/contrib/providers/agentHost/browser/devContainerAgentHostSessionsProvider.ts / remoteAgentHostSessionsProvider.ts) to set `supportsQuickChats = true` and support workspace-less session creation the way `LocalAgentHostSessionsProvider` does — this likely needs design work on how a remote host handles a session with no resolved workspace/working directory.

## Evidence

- **supportsQuickChats gating:** src/vs/sessions/services/sessions/browser/sessionsManagementService.ts:327-338 — getQuickChatSessionTypes() only returns session types from providers where `provider.supportsQuickChats` is true, and this is what feeds the workspace-less 'Chat' entry in the picker (sessionTypePicker.ts:230,374).
- **local provider opts in:** src/vs/sessions/contrib/providers/agentHost/browser/localAgentHostSessionsProvider.ts:79 sets `readonly supportsQuickChats = true;`.
- **remote provider does not:** RemoteAgentHostSessionsProvider (src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostSessionsProvider.ts:133) extends DevContainerAgentHostSessionsProvider, and neither that class nor BaseAgentHostSessionsProvider (src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts) overrides `supportsQuickChats`, so it stays falsy — matching the reported behavior exactly.
