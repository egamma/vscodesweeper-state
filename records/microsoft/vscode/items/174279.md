# Issue #174279 — All extension network traffic breaks when system proxy settings are changed

[https://github.com/microsoft/vscode/issues/174279](https://github.com/microsoft/vscode/issues/174279)

## Summary

The original cache defect is only partially mitigated on current main: extension-host proxy entries are invalidated when network interfaces change, but changing the macOS system proxy without changing an interface can still leave the old proxy cached. Keep this open and classify it as upstream work in the VS Code-owned proxy-agent package.

## Change summary

Extension-host HTTP requests continue using a stale system proxy after proxy settings change while VS Code remains open.

## Best solution

Update `@vscode/proxy-agent` so its resolver cache is invalidated when the effective system proxy configuration changes, including changes that do not alter `os.networkInterfaces()`, while retaining caching for unchanged configurations; then adopt that release in VS Code.

## Evidence

- **confirmed original cause:** The reporter confirmed the failure on Insiders, and the maintainer identified per-URL proxy caching as the cause in https://github.com/microsoft/vscode/issues/174279#issuecomment-1459612785.
- **current source:** Current `@vscode/proxy-agent` 0.45.0, configured from `src/vs/workbench/api/node/proxyResolver.ts`, checks `os.networkInterfaces()` before returning a cached system proxy and clears the cache only when that snapshot changes; the default check interval is 300 seconds.
- **partial upstream mitigation:** https://github.com/microsoft/vscode-proxy-agent/commit/51694ca0798feac07330aa54a3ce6e0013218fea added cache flushing specifically for network-interface changes. VS Code adopted it through proxy-agent 0.35.0 in commit ff388f3ba8bea80402ffd1e477284779abb78f4d, but the upstream diff does not detect a system-proxy-only change such as stopping Proxyman.
- **canonical search:** Older open issue https://github.com/microsoft/vscode/issues/34385 concerns Marketplace installation behind a proxy, not extension-host traffic retaining a stale proxy after a live configuration change. The younger https://github.com/microsoft/vscode/issues/260297 concerns Chromium `ERR_NETWORK_CHANGED` in Chat and does not meet the stronger duplicate bar for this re-reviewed item.
