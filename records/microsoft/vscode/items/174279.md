# Issue #174279 — All extension network traffic breaks when system proxy settings are changed

[https://github.com/microsoft/vscode/issues/174279](https://github.com/microsoft/vscode/issues/174279)

## Summary

Still reproduces on main: the proxy-agent caches resolved proxy URLs indefinitely (up to 5000 entries) with no TTL or invalidation when system proxy settings change, breaking all extension network traffic after a proxy change.

## Change summary

Extension network traffic breaks permanently when system proxy settings change while VS Code is running, because the proxy resolution cache in @vscode/proxy-agent is never invalidated.

## Best solution

Add cache invalidation to @vscode/proxy-agent when system proxy settings change — either via a TTL on cached entries, or by listening for OS network-configuration-change events (e.g. via Electron's session proxy APIs or a periodic re-resolve). The fix lives in the @vscode/proxy-agent package (https://github.com/nicedoc/vscode-proxy-agent or microsoft/vscode-proxy-agent) and the integration point in src/vs/workbench/api/node/proxyResolver.ts.
