# Issue #335719 — Multi-diff editor retains disposed row DOM across input changes

[https://github.com/microsoft/vscode/issues/335719](https://github.com/microsoft/vscode/issues/335719)

## Summary

Traced and confirmed on main: disposed multi-diff row templates never remove their DOM root from the container, so repeatedly replacing the multi-diff editor's input leaks row DOM nodes past the intended 5-template pool cap. Already carries `bug`/`multi-diff-editor` labels and needs no triage change beyond routing to a fix.

## Change summary

Disposing/evicting a pooled DiffEditorItemTemplate in the multi-diff editor leaves its row DOM element attached to the container instead of removing it, so retained DOM grows unbounded across repeated input replacements.

## Best solution

In src/vs/editor/browser/widget/multiDiffEditor/diffEditorItemTemplate.ts, register removal of `_elements.root` from `_container` with the DiffEditorItemTemplate's own disposal lifetime (not with DiffEditorItemBinding.unbind, since bindings unbind without destroying pooled templates) so VirtualizedTemplatePool's eviction in virtualizedItemManager.ts actually clears the DOM.
