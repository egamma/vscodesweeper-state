# Issue #330588 — integrated browser doesn't automatic share new browse tab eg.  `target=_blank` or `window.open()`

[https://github.com/microsoft/vscode/issues/330588](https://github.com/microsoft/vscode/issues/330588)

## Summary

Confirmed in source: when a shared browser tab opens a new tab via `target=_blank`/`window.open()`, the child BrowserView is created with an empty audiences list rather than inheriting the parent's, so it is never automatically shared with the agent — this is not a hypothesis, there's a commented-out line in the exact code path that would fix it.

## Change summary

Links/buttons that open a new tab from an already agent-shared integrated-browser tab are not themselves shared with the agent, so the agent can't see or act on the new tab without the user manually re-sharing it.

## Best solution

A maintainer should decide whether to enable the already-sketched fix at src/vs/platform/browserView/electron-main/browserViewMainService.ts:456 (`// child.setAudiences(view.audiences);`), which would make child tabs inherit the parent's agent-sharing state — but since this controls what browser content becomes visible to the agent, it deserves a deliberate privacy/UX call (e.g. should this apply to all new tabs, only foreground ones, or require confirmation) rather than a blind re-enable.

## Evidence

- **sharing model:** src/vs/workbench/contrib/browserView/common/browserView.ts:511 sets a view's `_sharedWithAgent` purely from `initialState.audiences`, which for a freshly created child view defaults to `[]` (BrowserView._audiences initialized empty at electron-main/browserView.ts:62) unless explicitly set — confirming new tabs start unshared regardless of the parent's sharing state.
- **parentViewId is cosmetic only:** the `parentViewId` passed to the child (browserView.ts:209) is only consumed in browserViewWorkbenchService.ts:444-445 to pick an editor group, not to propagate sharing/audience state.
