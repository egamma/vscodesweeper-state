# Issue #317475 — Detached Copilot/Agent sessions persist after clearing all storage

[https://github.com/microsoft/vscode/issues/317475](https://github.com/microsoft/vscode/issues/317475)

## Summary

Keep open: the report provides concrete steps sufficient to retest, but source inspection does not establish why sessions survive removal of the reported storage. Session ownership and discovery have changed through the Agent Host migration since 1.120; neither a verified fix nor a canonical issue covering this exact trigger was found.

## Change summary

Detached agent sessions reappear after restarting VS Code despite manual removal of the listed session and application storage.

## Best solution

Establish which provider and authoritative storage supply the returning session, then ensure genuinely removed local sessions are not rediscovered. Distinguish resurrection from discovery of transcripts stored outside the cleared locations; clearing VS Code caches must not implicitly delete unrelated provider history.
