# Issue #334822 — Chat agent: prepareToolInvocation crashes with "Cannot read properties of undefined (reading 'replace')" when the model emits nested/malformed tool arguments

[https://github.com/microsoft/vscode/issues/334822](https://github.com/microsoft/vscode/issues/334822)

## Summary

Traced and confirmed on current main: `runInTerminalTool.prepareToolInvocation` calls `normalizeTerminalCommandForDisplay(args.command)`/`buildCommandDisplayText` without ever validating that `args.command` is a string, so a model emitting malformed/double-nested tool arguments (where `command` ends up `undefined`) throws a raw `TypeError` instead of a handled error.

## Change summary

run_in_terminal's prepareToolInvocation crashes with an uncaught TypeError instead of a graceful tool error when the model supplies malformed/nested tool-call arguments.

## Best solution

Add an explicit guard in runInTerminalTool.ts (mirroring the `!args.command || !args.command.trim()` check already present in sendToTerminalTool.ts:107) that validates `args.command` is a non-empty string before it reaches normalizeTerminalCommandForDisplay/buildCommandDisplayText in runInTerminalHelpers.ts, throwing a clear, descriptive Error instead of letting `.replace` on `undefined` blow up.
