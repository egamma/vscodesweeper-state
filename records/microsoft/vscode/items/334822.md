# Issue #334822 — Chat agent: prepareToolInvocation crashes with "Cannot read properties of undefined (reading 'replace')" when the model emits nested/malformed tool arguments

[https://github.com/microsoft/vscode/issues/334822](https://github.com/microsoft/vscode/issues/334822)

## Summary

Traced on main: `run_in_terminal`'s `prepareToolInvocation` reads `args.command` from unvalidated model-provided parameters and immediately calls `normalizeTerminalCommandForDisplay(args.command)`, which does `commandLine.replace(...)` — if the model emits malformed/nested arguments so `command` is undefined, this throws the exact reported TypeError. There's no schema validation of raw model tool-call parameters before `prepareToolInvocation`/`invokeTool` run (only `preToolUseHookResult.updatedInput` is validated via `_validateUpdatedInput`), so a real gap remains: worth a small guard so malformed args produce a clean, model-facing validation error instead of a raw TypeError.

## Change summary

When a model emits malformed/double-nested tool-call arguments for run_in_terminal, prepareToolInvocation throws an uncaught-looking TypeError instead of surfacing a clean validation error to the model.

## Best solution

Add a guard in runInTerminalTool.ts's prepareToolInvocation (or generically in languageModelToolsService.invokeTool, validating dto.parameters against the tool's inputSchema before calling prepareToolInvocation/invokeTool) so a missing/non-string `command` produces a clear 'invalid tool arguments' toolResultError the model can react to, instead of letting normalizeTerminalCommandForDisplay throw on undefined input.
