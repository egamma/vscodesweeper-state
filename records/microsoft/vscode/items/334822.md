# Issue #334822 — Chat agent: prepareToolInvocation crashes with "Cannot read properties of undefined (reading 'replace')" when the model emits nested/malformed tool arguments

[https://github.com/microsoft/vscode/issues/334822](https://github.com/microsoft/vscode/issues/334822)

## Summary

Traced on current main: run_in_terminal's prepareToolInvocation assumes `args.command` is always a valid string and calls normalizeTerminalCommandForDisplay(args.command) unguarded, which throws exactly the reported TypeError when a model sends malformed/undefined arguments; this is a real gap worth a small defensive fix.

## Change summary

A malformed/double-nested tool-call arguments payload from the model causes run_in_terminal's prepareToolInvocation to throw an uncaught TypeError instead of returning a handled tool error.

## Best solution

Add a guard in runInTerminalTool.ts prepareToolInvocation (and/or normalizeTerminalCommandForDisplay in runInTerminalHelpers.ts) that checks `typeof args.command === 'string'` before use, returning a clean 'invalid tool arguments' result instead of letting the TypeError propagate; more broadly, languageModelToolsService.invokeTool could validate dto.parameters against the tool's registered inputSchema before calling prepareToolInvocation/invoke, since today only preToolUse-hook-updated input is schema-validated (see _validateUpdatedInput).
