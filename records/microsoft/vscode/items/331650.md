# Issue #331650 — [Error] [GitHub.copilot-chat] unhandlederror-Workspace chunk search service not available

[https://github.com/microsoft/vscode/issues/331650](https://github.com/microsoft/vscode/issues/331650)

## Summary

Traced a real bug in source: the manual 'Build codebase semantic index' command throws a bare Error when the workspace chunk search service isn't initialized (no auth, or no available embedding type), and the command handler only checks the `Result.isError()` case — it never catches the thrown exception, so it surfaces as an unhandled rejection reported to error telemetry.

## Change summary

Users see an 'unhandlederror-Workspace chunk search service not available' telemetry entry when triggering codebase indexing while the workspace chunk search service can't initialize.

## Best solution

In src/extension/workspaceChunkSearch/vscode-node/commands.ts (buildRemoteIndexCommandId handler), wrap the `triggerIndexing` call in a try/catch (or change `WorkspaceChunkSearchService.triggerIndexing` to return a `Result` error instead of throwing when `tryInit` yields no impl, matching `enableExternalIngest`'s pattern) so users get the existing 'Could not build codebase semantic index' warning instead of an unhandled exception.
