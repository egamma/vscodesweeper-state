# Issue #331650 — [Error] [GitHub.copilot-chat] unhandlederror-Workspace chunk search service not available

[https://github.com/microsoft/vscode/issues/331650](https://github.com/microsoft/vscode/issues/331650)

## Summary

Traced on current main: `github.copilot.buildRemoteWorkspaceIndex` calls `WorkspaceChunkSearchService.triggerIndexing`, which throws a plain `Error('Workspace chunk search service not available')` whenever `tryInit` returns `undefined` (no Copilot auth token, or no available embedding type) — and the command handler in `commands.ts` has no try/catch, so the throw becomes an unhandled rejection that the telemetry dashboard reports as `unhandlederror`.

## Change summary

Users see an unhandled error 'Workspace chunk search service not available' when the workspace semantic index build command runs while the chunk search service isn't initialized (no auth/embedding type available), and reports of it spiked 7–30x in the 0.61.0 release.

## Best solution

In extensions/copilot/src/extension/workspaceChunkSearch/vscode-node/commands.ts, wrap the `triggerIndexing` call (or catch at the `withProgress` callback level) and surface a `showWarningMessage` the same way the existing `TriggerRemoteIndexingError` branch does, instead of letting the underlying `Error` propagate as an unhandled rejection from `workspaceChunkSearchService.ts`.
