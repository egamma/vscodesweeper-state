# Issue #331011 — Flexible Context Window & Custom Thinking Effort for BYOK

[https://github.com/microsoft/vscode/issues/331011](https://github.com/microsoft/vscode/issues/331011)

## Summary

Fresh, unlabeled feature request extending the open BYOK custom-endpoint tracking issue; part of the ask (per-model reasoning-effort levels) is already implemented, but selectable multi-size context windows are not, so a real gap remains worth routing to the BYOK area.

## Change summary

Add a selectable `availableContextWindow` list and a richer per-model `efforts`/`defaultEffort`/`useLegacyThinking` schema for BYOK custom endpoints, plus auto-saving the chosen values.

## Best solution

Route to the BYOK maintainers alongside https://github.com/microsoft/vscode/issues/325237 (the broader 'Better Custom Endpoint BYOK' tracking issue this was filed as an addition to); the reasoning-effort half is largely covered by the existing `supportsReasoningEffort`/`defaultReasoningEffort`/`reasoningEffortFormat` fields in extensions/copilot/src/extension/byok/common/byokProvider.ts, so the remaining gap is a user-selectable list of context-window sizes (today `contextWindow`/`maxInputTokens` is a single fixed value resolved by resolveModelTokenLimits) and the 'auto-save except Max effort' persistence behavior.
