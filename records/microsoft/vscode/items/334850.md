# Issue #334850 — VS Code doesn't handle KDE remap of Ctrl, Caps Lock properly

[https://github.com/microsoft/vscode/issues/334850](https://github.com/microsoft/vscode/issues/334850)

## Summary

The open Linux keyboard-remapping issue already covers remapped modifier keys being interpreted as both their physical key and Ctrl. Consolidate this report there, preserving the Fedora 44 / Plasma 6.7.4 configuration and the two-chord reproduction.

## Change summary

Honor KDE's Ctrl/Caps Lock swap so pressing the remapped modifier does not prematurely complete a keyboard chord as Ctrl+CapsLock.

## Best solution

Track the remaining remapped-modifier handling in https://github.com/microsoft/vscode/issues/23991, including this report's chord failure. Keep keyboard.dispatch=keyCode available as a workaround, without treating it as a completed fix.

- **current source trace:** src/vs/base/common/keyCodes.ts:560 assigns CapsLock an immutable mapping. src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts:414-425 makes it dispatchable, and resolveKeyboardEvent at lines 937-996 preserves the CapsLock scan code even when the event's logical keyCode is Ctrl, combining it with ctrlKey. AbstractKeybindingService._doDispatch in src/vs/platform/keybinding/common/abstractKeybindingService.ts:325-350 consumes that dispatchable key as the next chord and leaves chord mode when it does not match. This explains the reported Ctrl+CapsLock outcome without executing the KDE environment.
