# Issue #334850 — VS Code doesn't handle KDE remap of Ctrl, Caps Lock properly

[https://github.com/microsoft/vscode/issues/334850](https://github.com/microsoft/vscode/issues/334850)

## Summary

Thanks for the detailed report. The steps are complete (KDE Swap Ctrl and Caps Lock, then a chord such as Ctrl+K Ctrl+T), but this depends on keyboard and OS behavior, so I could not confirm it from source alone. The report stays open; the given steps suffice to retest on a current build.

## Change summary

With KDE's Swap Ctrl and Caps Lock enabled, the physical Caps Lock key acting as Ctrl is also reported as a CapsLock key press, which breaks the second step of a keybinding chord.

## Best solution

Confirm how the Linux key event reports the swapped key (scan code or key code vs. modifier state), then ignore a lone modifier-like CapsLock key press while a chord is pending, or resolve it through the keyboard layout mapping. Keep it as a Linux keyboard-handling bug unless Chromium or Electron turns out to own the behavior.
