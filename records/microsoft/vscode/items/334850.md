# Issue #334850 — VS Code doesn't handle KDE remap of Ctrl, Caps Lock properly

[https://github.com/microsoft/vscode/issues/334850](https://github.com/microsoft/vscode/issues/334850)

## Summary

Fresh, single, unconfirmed report of a keyboard-chord bug tied to a specific KDE Plasma setting (swap Ctrl/Caps Lock). The mechanism plausibly lives in how the native keymap layer reports the remapped key rather than in VS Code's own scan-code table, but that can't be traced from this checkout (native-keymap is an external native module), so I'm asking for confirmation rather than guessing at root cause or duplicate status.

## Change summary

On KDE with Ctrl and Caps Lock swapped at the OS level, using the (physically Caps Lock) Ctrl key in a two-key chord (e.g. Ctrl+K Ctrl+T) causes VS Code to read Caps Lock as both the Ctrl modifier and a distinct second key press.

## Best solution

Needs a reproduction/triage pass by someone who can test on KDE with the swap enabled (ideally distinguishing X11 vs Wayland) to see whether this is a manifestation of the long-standing keymap-remap gap tracked in https://github.com/microsoft/vscode/issues/23991, or a distinct chord-dispatch bug in the workbench keybinding service (src/vs/workbench/services/keybinding/browser/keybindingService.ts, src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts).
