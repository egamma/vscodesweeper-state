# Issue #331671 — Agents session from windows to linux wrong file path separator

[https://github.com/microsoft/vscode/issues/331671](https://github.com/microsoft/vscode/issues/331671)

## Summary

Traced a real defect on main: the Agent Host's Copilot session-state path helpers join a POSIX-style remote/WSL home directory using VS Code's platform-dependent `join` (base/common/path.js), which picks win32 vs. posix based on the executing process's `process.platform` rather than the target OS the home path actually belongs to — producing exactly the malformed `\home\user\...\plan.md` paths both reporters hit.

## Change summary

When the Agent Host session runs against a Linux/WSL remote from a Windows client, the plan.md / events.jsonl session-state file path is built with Windows backslashes over a POSIX home directory, so VS Code can't resolve it ('Unable to resolve nonexistent file').

## Best solution

In src/vs/platform/agentHost/common/copilotHome.ts (getCopilotHomePath/getCopilotRootPaths) and the call sites in src/vs/platform/agentHost/node/copilot/copilotAgent.ts (getSessionStateFile, the events.jsonl/import paths, _extensionHostCliSidecarPath) and copilotAgentSession.ts, choose the join style based on the shape of the incoming userHome path (or otherwise the target OS) instead of the local process's `process.platform`, so a POSIX-looking `userHome.fsPath` is never joined with backslashes.

## Evidence

- **root cause:** src/vs/base/common/path.ts:1579 — `export const join = (platformIsWin32 ? win32.join : posix.join)`, where `platformIsWin32 = process.platform === 'win32'` — i.e. join picks the separator of the executing process, not of the path's own OS.
- **buggy call sites:** src/vs/platform/agentHost/common/copilotHome.ts:getCopilotHomePath uses `join(userHomePath, '.copilot')`; src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2380,3134,3166 and copilotAgentSession.ts:378 all build `session-state/<id>/...` paths the same way from `this._environmentService.userHome.fsPath`.
- **reproduction match:** Running `path.win32.join('/home/alond', '.copilot', 'session-state', 'abc', 'plan.md')` in Node yields `\home\alond\.copilot\session-state\abc\plan.md` — character-for-character the same malformed path both reporters pasted in their error logs, confirming a Windows-mode `join` was applied to a POSIX remote/WSL home path.
- **corroboration:** A second reporter (ArilsonB) hit the identical failure with Windows + WSL/Ubuntu five days later, so this isn't a one-off environment quirk.
