# Issue #331671 — Agents session from windows to linux wrong file path separator

[https://github.com/microsoft/vscode/issues/331671](https://github.com/microsoft/vscode/issues/331671)

## Summary

Traced a real bug in the Agent Host plan-review path: when the agent runs on a remote SSH host, the plan file's URI is built with plain `URI.file()` (no remote authority), so the Windows client resolves it as a local path — which is why the file can't be found and shows up with backslashes.

## Change summary

On a Windows client connected to a Linux Remote-SSH host, the agent session's plan/comment file paths are shown/opened with Windows-style backslashes and fail to resolve.

## Best solution

In `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts` (around line 5178, `planUri: URI.file(planPath).toString()`), the remote-host path needs to be surfaced to the client as a `vscode-remote://` resource (or otherwise tagged with the connection's remote authority) instead of a bare `file:` URI, so the client's file service resolves it against the correct remote file system provider rather than the local Windows disk.
