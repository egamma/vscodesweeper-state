# Issue #331671 — Agents session from windows to linux wrong file path separator

[https://github.com/microsoft/vscode/issues/331671](https://github.com/microsoft/vscode/issues/331671)

## Summary

Real cross-platform path bug in the Agents/Sessions window: when the local VS Code client is Windows and the session/agent target is a Linux remote (SSH), some file paths surfaced back to the client are built with backslashes, so links to changed/commented files fail to resolve. A second commenter reproduces a related manifestation (a `plan.md` read failure with a backslash-separated path) with a full stack trace pointing into `sessions.desktop.main.js`, corroborating the same class of defect.

## Change summary

In an Agents session running against a Linux remote from a Windows client, file links/paths for agent comments are constructed with Windows-style backslashes and fail to resolve on the Linux remote filesystem.

## Best solution

Audit the sessions/agent-host code paths that build remote file references for OS-conditional separator use (e.g. `join()`/`path` helpers in `src/vs/platform/agentHost/node/copilot/copilotAgent.ts` and related sessions/changes-view code) and ensure paths destined for the remote (or for `URI`/`extUri` construction) always use POSIX separators or proper `URI`/`extUri.joinPath` APIs instead of native `path.join`, which follows the *local* (client) OS rather than the remote OS.
