# Issue #130082 — Add option to always open files at their canonical path

[https://github.com/microsoft/vscode/issues/130082](https://github.com/microsoft/vscode/issues/130082)

## Summary

This remains an accepted, highly supported Backlog request with a real unresolved gap in file identity across symlinked paths. It is already correctly routed and should remain the canonical discussion for resolving files to workspace-preferred paths.

## Change summary

Add an option that consistently opens files and folders through canonical paths so symlink aliases do not create duplicate editors or lose workspace integrations.

## Best solution

Use the asynchronous realpath capability at editor and workspace ingress points, then teach URI identity to map aliases to a stable workspace-preferred URI without eagerly resolving every URI supplied by extensions. The design should cover local and remote file-system providers and preserve intentional symlink-based workspace presentation.
