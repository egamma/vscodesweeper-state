# Issue #328927 — Agent Host customizations view doesn't show plugin skills nested under category folders (`skills/<category>/<skill>/SKILL.md`)

[https://github.com/microsoft/vscode/issues/328927](https://github.com/microsoft/vscode/issues/328927)

## Summary

Confirmed in source: skill discovery only descends one directory level under a skills root, so category-nested layouts (`skills/<category>/<skill>/SKILL.md`) are silently skipped while single-level ones work — matches the report exactly.

## Change summary

Skills nested two levels deep under a category folder aren't discovered by the Chat Customizations view, even though the plugin loads and slash commands still work.

## Best solution

Extend the skill directory walk in readSkills (src/vs/platform/agentPlugins/common/pluginParsers.ts) to recurse into one additional category level for non-AgentPlugin-manifest formats (Claude/OpenPlugin/Copilot), without touching the intentionally strict immediate-child-only behavior documented for the AgentPlugin manifest format's 'too deep' case.

## Evidence

- **one-level scan:** src/vs/platform/agentPlugins/common/pluginParsers.ts readSkills() (lines 890-955) only checks `dir/SKILL.md` and then, for each immediate child of `dir`, `child/SKILL.md` — there is no further recursion into a second-level child directory, so `skills/<category>/<skill>/SKILL.md` is never reached.
- **Claude scan uses same helper:** src/vs/platform/agentHost/node/claude/customizations/scan/claudeAgentSkillScan.ts calls `readSkills(skillsDir, [skillsDir], fileService)` for `.claude/skills`, inheriting the same one-level limitation.
- **existing test documents one-level intent for manifest plugins:** src/vs/platform/agentPlugins/test/common/pluginParsers.test.ts 'reads usable immediate-child skills permissively' explicitly asserts a doubly-nested `skills/nested/deeper/SKILL.md` is excluded as 'Too deep' — but that test targets the AgentPlugin manifest format (childDirectoriesOnly), not the Claude/local-plugin path the reporter is using, so it doesn't settle whether category nesting should be supported there.
- **reporter confirmation:** Reporter confirmed reproduction on both a local chat.pluginLocations directory and a Marketplace-installed plugin, and noted the control case (single-level skills/<name>/SKILL.md) works.
