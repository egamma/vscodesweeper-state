# Issue #323172 — BYOK CustomEndpoint Model only thinks, cannot parse or strip `delta.reasoning`

[https://github.com/microsoft/vscode/issues/323172](https://github.com/microsoft/vscode/issues/323172)

## Summary

Current main does parse vLLM-style `delta.reasoning` for BYOK OpenAI-compatible endpoints (stream.ts accumulates it and thinkingUtils maps it to a thinking delta), so the reported behavior may already be resolved — but the available checkout is a single-commit shallow clone with no history and `gh` is unavailable, so no fix commit can be cited and the implemented-on-main close bar is not met. The report is complete (versions, steps, a raw SSE sample), so it stays open rather than going to info-needed; the given steps are enough for a maintainer to retest on a current build with the model's `thinking` capability both on and off.

## Change summary

A reasoning model configured as a BYOK CustomEndpoint streams only reasoning: the `delta.reasoning` chunks are not turned into a visible response and the turn ends in an error.

## Best solution

Retest the vLLM-style `delta.reasoning` stream against current main for a CustomEndpoint model; if it is fixed, close it citing the commit that added `reasoning` to the accumulated fields in extensions/copilot/src/platform/networking/node/stream.ts, and if the failure persists only when the model entry omits `"thinking": true`, make the custom-endpoint path tolerate reasoning deltas from models that did not declare the capability (or surface that requirement in the configuration docs).
