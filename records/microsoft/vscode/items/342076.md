# Issue #342076 — MCP OAuth: `offline_access` is now always appended to the authorization request (since 1.142.0), breaking static clients that are not allowed to use it

[https://github.com/microsoft/vscode/issues/342076](https://github.com/microsoft/vscode/issues/342076)

## Summary

Keep open: current main still appends offline_access for non-Microsoft authorization servers without checking whether the client permits it, and switching authorization flows repeats the same scope request. The supplied Keycloak steps are actionable; the related scope-selection requests do not establish a duplicate of this regression.

## Change summary

Automatically adding offline_access blocks MCP sign-in for pre-registered OAuth clients that cannot request that scope.

## Best solution

Allow these clients to authenticate with their permitted resource scopes while preserving Entra refresh-token support and explicitly requested scopes. Settle the intended automatic offline_access behavior for other providers before changing the shared authorization flows.
