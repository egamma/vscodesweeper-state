# Issue #342076 — MCP OAuth: `offline_access` is now always appended to the authorization request (since 1.142.0), breaking static clients that are not allowed to use it

[https://github.com/microsoft/vscode/issues/342076](https://github.com/microsoft/vscode/issues/342076)

## Summary

Keep open: current main still adds offline_access based solely on server-wide metadata, including for static clients that cannot request it, and authorization rejection ends sign-in without a fallback. The report provides sufficient reproduction details; the remaining question is how to preserve refresh-token support without blocking these clients.

## Change summary

Prevent automatically added offline_access from blocking MCP authentication for pre-registered clients that are not permitted to request that scope.

## Best solution

Make MCP sign-in succeed for the reported Keycloak client while retaining working refresh-token acquisition for supported clients. Establish the intended non-Microsoft scope-selection behavior before changing the shared authorization paths and their existing expectations.

Acceptance includes the reported loopback sign-in and regression coverage for non-Microsoft and Microsoft authorization behavior.
- **Trace:**

  > DynamicAuthProvider._getRequestScopes in src/vs/workbench/api/common/extHostAuthentication.ts uses only the incoming scopes and server-wide metadata to append offline_access. The browser test 'authorization URL requests offline_access when advertised and omits resource for Microsoft auth' explicitly expects the added scope for nonMicrosoft, so this is not merely a missing Microsoft guard with an already-settled contract. - **Open decisions:**
