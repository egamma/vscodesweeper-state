# Issue #342076 — MCP OAuth: `offline_access` is now always appended to the authorization request (since 1.142.0), breaking static clients that are not allowed to use it

[https://github.com/microsoft/vscode/issues/342076](https://github.com/microsoft/vscode/issues/342076)

## Summary

The scope-injection regression remains in current main: a static client receives offline_access solely because the authorization server advertises it. Keep this open; the related scope-selection and client-registration issues do not resolve this distinct failure.

## Change summary

Prevent automatically added offline_access from blocking MCP sign-in for static clients that cannot request it.

## Best solution

Restore successful authentication with the resource-requested scopes while preserving Entra refresh-token support. Settle whether non-Microsoft providers should avoid automatic offline_access or retain it with a bounded scope-rejection fallback.
