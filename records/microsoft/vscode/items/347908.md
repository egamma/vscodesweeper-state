# Issue #347908 — Copilot command embeddings cache (16–19 MB) is rewritten on every window load, written twice on first load, and grows each time

[https://github.com/microsoft/vscode/issues/347908](https://github.com/microsoft/vscode/issues/347908)

## Summary

Keep open: current source confirms that flattening the persisted cache loses extension ownership, causing unnecessary downloads and large rewrites. The reporter's tested local fix is not evidence of a landed fix.

## Change summary

Avoid redundant command and setting embeddings cache writes, duplicate extension entries, and retention of uninstalled extensions.

## Best solution

Persist the extension-aware cache once when its contents change, preserving core/extension ownership and pruning removed extensions. Keep flattened results for callers and preserve the standalone remote cache behavior used by tools.

## Evidence

- **Current-source cache-hit defect:** extensions/copilot/src/platform/embeddings/common/embeddingsIndex.ts: EmbeddingsCache.getCache flattens persisted core/extensions records. RemoteEmbeddingsExtensionCache.getCache calls super.getCache, then wraps the flattened result as core with extensions: {}. Consequently every installed extension enters extensionIdsToFetch, triggering clearCache/updateCache on otherwise unchanged loads.
- **Double write and stale ownership:** In the same file, RemoteEmbeddingsCache.getCache writes refreshed core before the subclass fetches extensions and writes again. Previously flattened extension entries remain inside core, while the removal loop examines only currentCache.extensions; it cannot prune those retained entries. The reported sizes increase initially and then plateau, rather than demonstrating indefinite growth.
- **Affected consumers and compatibility boundary:** extensions/copilot/src/platform/embeddings/common/vscodeIndex.ts constructs RemoteEmbeddingsExtensionCache for both commandEmbeddings and settingEmbeddings. RelatedInformationProviderEmbeddingsIndex.provideRelatedInformation starts calculateEmbeddings, whose base implementation reads this cache. extensions/copilot/src/extension/tools/common/virtualTools/preComputedToolEmbeddingsCache.ts separately uses RemoteEmbeddingsCache.
- **Complete discussion and reported validation:** https://github.com/microsoft/vscode/issues/347908#issuecomment-6830005873 describes a local fix and reports three cache regression cases failing on main and passing with that fix, plus 38 passing embeddings tests. The proposed remoteEmbeddingsExtensionCache.spec.ts is not present in this checkout. No tests were executed during this read-only review.
