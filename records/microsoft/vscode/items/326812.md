# Issue #326812 — Renderer  UndoRedoService._editStacks & ResourceEditStack._past grows unboundedly and leaks memory over long sessions

[https://github.com/microsoft/vscode/issues/326812](https://github.com/microsoft/vscode/issues/326812)

## Summary

Current main confirms that active per-resource undo stacks grow without an element or memory bound, matching the reported multi-gigabyte retention. This should remain open and route to the undo/redo and memory-leak owners.

## Change summary

Repeated large-file edits can make the renderer retain gigabytes of undo history indefinitely.

## Best solution

Add memory-aware trimming for active ResourceEditStack histories while preserving workspace-element consistency and valid undo/redo ordering; cover large individual elements and repeated edits with focused undo-redo tests.
