# Issue #314661 — Final agent text hidden in tool call and double scrollbar in chat

[https://github.com/microsoft/vscode/issues/314661](https://github.com/microsoft/vscode/issues/314661)

## Summary

Keep open: a second maintainer independently confirmed the hidden-content failure, and current main still uses a nested scrolling viewport for the default thinking style. Later response-disclosure work likely covers part of the first symptom, but it neither references this team-authored issue nor resolves the separate scrolling concern.

## Change summary

Keep final agent markdown visibly separate from tool/thinking content and avoid an inner chat scrollbar intercepting transcript scrolling.

## Best solution

Confirm both scenarios against current main, retain a regression test proving trailing markdown remains outside collapsed work, and settle the fixed-scrolling interaction so wheel navigation does not become trapped in a nested viewport.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatThinkingContent.css`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatThinkingContentPart.test.ts`
- **Validation:** Add or extend chat renderer tests for a tool/file-edit followed by final markdown, asserting the markdown remains outside the completed-work disclosure, and add an interaction test for wheel propagation between the fixed-scrolling thinking viewport and the outer chat transcript.
- **Behavior:**

  > After an agent edits a file or invokes a tool and then emits concluding markdown, the conclusion remains visibly outside collapsed thinking or tool content. Scrolling the chat transcript over a fixed-height thinking section must not leave the user unexpectedly trapped in a competing scrollbar. Existing expansion and access to detailed thinking content must remain available.
- **Trace:**

  > The original report showed final markdown rendered inside the thinking/file-edit expando, and another maintainer independently reproduced the thinking-content failure. Current src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts now identifies the trailing markdown run through getFinalResponseStartIndex and places earlier work in completed-response-disclosure, likely covering the ordinary final-markdown case after https://github.com/microsoft/vscode/pull/327923. The separate nested-scroll path remains in ChatThinkingContentPart: fixedScrolling is the default, creates a DomScrollableElement capped at 200px, and enables wheel handling. Preserve final-answer visibility, disclosure accessibility, and explicit expansion; do not broaden this into redesigning unrelated chat rendering.
- **Open decisions:**
  - When the pointer is over a fixed-scrolling thinking viewport, should wheel input scroll that inner history until its boundary, or should transcript scrolling always take precedence while automatic scrolling preserves the latest thinking?
