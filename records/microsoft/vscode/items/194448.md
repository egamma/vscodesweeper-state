# Issue #194448 — Fuzzy searching is inconsistent between various pickers

[https://github.com/microsoft/vscode/issues/194448](https://github.com/microsoft/vscode/issues/194448)

## Summary

Keep open: Open Recent still uses a more limited matcher than Cmd+P, and a maintainer explicitly accepted aligning them. The related reports do not establish an older canonical covering the same full request.

## Change summary

Make Open Recent support fuzzy matching consistently with the Cmd+P file picker.

## Best solution

Align Open Recent's matching capabilities with the file picker while preserving recent-item ordering and existing opening actions. Keep text-search matching outside this issue, as the maintainer requested.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/windowActions.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/base/common/fuzzyScorer.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Add browser regression checks for Open Recent matching non-contiguous characters within a name and queries spanning a name and parent path, using agreed Cmd+P-equivalent query semantics. Verify matching retains recent-item order, highlights the matching fields, and leaves unrelated pickers unchanged; run the targeted quickinput browser suite through scripts/test.sh.
- **Behavior:**

  > Open Recent should find entries using the fuzzy queries that find equivalent file entries in Cmd+P, rather than requiring prefix, camel-case, or contiguous matches within an individual display field. Cover both non-contiguous name queries and queries involving the displayed parent path. Preserve recent-item ordering, existing item actions, and window-opening modifier behavior. Text-search matching is explicitly outside this request.
- **Trace:**

  > BaseOpenRecentAction in src/vs/workbench/browser/actions/windowActions.ts builds separate label and description fields and calls quickInputService.pick with description matching enabled and label sorting disabled. QuickInputList.filter in src/vs/platform/quickinput/browser/quickInputList.ts applies matchesFuzzyIconAware independently to each field; its default ultimately selects the limited matcher in src/vs/base/common/filters.ts. AnythingQuickAccessProvider in src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts instead uses prepareQuery and scoreItemFuzzy from src/vs/base/common/fuzzyScorer.ts, including non-contiguous file matching and multiple query pieces. The implementation boundary needs care because QuickInputList is shared with unrelated pickers whose behavior must not change accidentally. Preserve the existing recent-item order rather than importing file-result ranking wholesale. The accepted scope is recorded at https://github.com/microsoft/vscode/issues/194448#issuecomment-1741452013; https://github.com/microsoft/vscode/issues/184679 supplies the related cross-field regression, not a canonical for the whole request. The remaining uncertainty is how much of Cmd+P's query syntax, beyond fuzzy character matching, Open Recent should expose.
- **Open decisions:**
  - Should Open Recent also adopt Cmd+P's space-separated query pieces, quoted contiguous queries, and path-query semantics, or should parity be limited to non-contiguous character matching?
