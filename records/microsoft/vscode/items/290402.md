# Issue #290402 — Discarding file changes from SCM view should work as `undo` for Chat

[https://github.com/microsoft/vscode/issues/290402](https://github.com/microsoft/vscode/issues/290402)

## Summary

Keep open: current code recognizes some resets to Chat's original content, but SCM discard does not explicitly synchronize Chat's pending-edit state. This team-authored, accepted request has neither a verified same-symptom canonical nor an issue-referencing fix that would justify closing it.

## Change summary

Discarding a file's changes in SCM should resolve its pending Chat edits as undone rather than leave Keep/Undo controls showing +0/-0.

## Best solution

Make successful SCM file discard resolve the corresponding pending Chat edits without overwriting the content restored by Git. Establish how this works when Git's restore target differs from a Chat session's initial snapshot and when multiple sessions track the file.

- **Behavior:**

Acceptance checks cover a clean starting file, pre-existing uncommitted changes, an earlier manual edit, and multiple Chat sessions tracking the same file.
- **Trace:**

  > SCM file discard reaches Repository.clean in extensions/git/src/repository.ts, which performs checkout or deletion and clears AI contribution tracking without explicitly resolving Chat editing entries. Commit cleanup separately calls _chat.editSessions.accept, registered in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts and applied across editing sessions. ChatEditingModifiedDocumentEntry already marks an entry Rejected on a user-edit notification when its current content equals initialContent, while ChatEditingTextModelChangeService rebases ordinary edits and limits that notification with _didUserEditModelFired. These mechanisms provide partial coverage, but the remaining behavior depends on model reload timing, previous edits, and differing Git versus Chat baselines; those cases require diagnosis before implementation. Preserve Git discard content and existing commit acceptance semantics, and do not assume ordinary Chat rejection is equivalent to accepting an already-completed Git restore. Related acceptance work is tracked at https://github.com/microsoft/vscode/issues/253864, but it is not a verified duplicate of this request.
