# Issue #330764 — Inline toolset reference is replaced by its first child tool in the model-facing chat request

[https://github.com/microsoft/vscode/issues/330764](https://github.com/microsoft/vscode/issues/330764)

## Summary

Well-diagnosed, reproducible bug with an exact root cause and an open fixing PR already linked — keep open until the PR merges rather than closing now.

## Change summary

Inline toolset references (e.g. `#read`) are expanded so every child tool inherits the toolset's prompt range, letting the extension host mistake the first child tool for the explicitly referenced toolset in the model-facing request.

## Best solution

Land https://github.com/microsoft/vscode/pull/330767, which fixes this by using `toToolVariableEntry(t)` for expanded child entries in `ChatRequestParser.tryToParseVariable` (src/vs/workbench/contrib/chat/common/requestParser/chatRequestParser.ts) so only the `ChatRequestToolSetPart` itself retains `varRange`/`varEditorRange`.
