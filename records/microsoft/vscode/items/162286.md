# Issue #162286 — Feature Request: Allow hiding the "Open in Merge Editor" button

[https://github.com/microsoft/vscode/issues/162286](https://github.com/microsoft/vscode/issues/162286)

## Summary

The requested opt-out remains missing: the button is now called “Resolve in Merge Editor,” but disabling git.mergeEditor does not hide it. Keep this team-authored, accepted Backlog request open; it has 37 upvotes and no verified canonical duplicate or issue-referencing fix.

## Change summary

Allow users to hide the floating merge-editor button while retaining the existing inline conflict-resolution experience.

## Best solution

Provide a persistent way to suppress this specific editor-content action without disabling Git or inline conflict controls, while retaining an explicit command for opening the merge editor.

## Evidence

- **Current action visibility:** extensions/git/package.json contributes git.openMergeEditor to editor/content when Git is enabled, the editor is neither a diff nor merge editor, and the active resource has merge conflicts. Its visibility condition contains no opt-out and does not consult config.git.mergeEditor.
- **Existing setting does not cover the request:** extensions/git/package.json registers git.mergeEditor with default false; extensions/git/package.nls.json describes it as opening the merge editor for conflicted files. The same file names git.openMergeEditor “Resolve in Merge Editor.” This setting selects the opening experience rather than suppressing the floating action.
- **Shared toolbar does not provide hiding:** src/vs/editor/contrib/floatingMenu/browser/floatingMenu.ts renders MenuId.EditorContent actions at the bottom-right corner.
