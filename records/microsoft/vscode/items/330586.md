# Issue #330586 — [Windows] `network.meteredConnection: auto` ignores `NetworkCostType.Fixed`

[https://github.com/microsoft/vscode/issues/330586](https://github.com/microsoft/vscode/issues/330586)

## Summary

Traced in the checkout: `getIsBrowserConnectionMetered()` (src/vs/platform/meteredConnection/common/meteredConnection.ts, lines 58-69) only checks `navigator.connection.saveData/metered/effectiveType`, with no native Windows NetworkCostType query — so on systems where Chromium doesn't surface `Fixed` cost through that API, `auto` mode silently treats a metered connection as unmetered and lets background updates download.

## Change summary

On Windows, `network.meteredConnection: auto` fails to detect a connection Windows itself reports as `NetworkCostType.Fixed`, so the metered indicator doesn't show and automatic update downloads aren't skipped.

## Best solution

Add a native Windows-side check (main process, via WinRT `NetworkInformation.GetInternetConnectionProfile().GetConnectionCost()`) that feeds into `AbstractMeteredConnectionService`/`setIsBrowserConnectionMetered` alongside the Chromium `navigator.connection` signal, so `auto` mode also honors OS-reported cost state rather than relying solely on the Network Information API.
