# Issue #329955 — SDK `permissions`: Workspace path is not detected correctly

[https://github.com/microsoft/vscode/issues/329955](https://github.com/microsoft/vscode/issues/329955)

## Summary

Team-authored, well-diagnosed bug whose confirmed root cause lives in the `@github/copilot-sdk` runtime dependency, not in VS Code's own agentHost code — keeping open as upstream tracking until the SDK ships the fix and the version here is bumped.

## Change summary

Managed-settings `/...` workspace-path permission selectors (Edit/Read) don't match the real workspace root because the SDK runtime's path manager anchors them to an internal session-state directory instead, causing managed allow/deny rules to misfire.

## Best solution

Track this until a new `@github/copilot-sdk` release containing the fix (described in the reporter's own trace as anchoring `/...` selectors to the primary working directory) is picked up in package.json; verified `copilotSessionLauncher.ts` already forwards `workingDirectory.fsPath` correctly on the VS Code side, so no core code change is needed here — just the dependency bump plus a regression test in agentHostManagedSettings once the fix lands.
