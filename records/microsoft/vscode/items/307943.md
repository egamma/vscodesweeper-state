# Issue #307943 — Webview find widget reappears after being dismissed when switching tabs with retainContextWhenHidden

[https://github.com/microsoft/vscode/issues/307943](https://github.com/microsoft/vscode/issues/307943)

## Summary

Confirmed on current main: the ✕-button find-widget dismiss path bypasses OverlayWebview.hideFind(), leaving the _findWidgetVisible context key stale, so the restore logic incorrectly reopens the widget on tab switch. The Escape-key path is unaffected because it routes through OverlayWebview.hideFind().

## Change summary

Webview find widget reappears after ✕-button dismissal when switching tabs with retainContextWhenHidden, because the context key tracking widget visibility is not reset on the widget-internal close path.

## Best solution

In overlayWebview.ts, subscribe to the inner webview's onDidStopFind event (alongside the other forwarded events around line 236) and call this._findWidgetVisible?.reset() in the handler. This aligns the ✕-button path with the existing Escape-keybinding path that already goes through hideFind().
