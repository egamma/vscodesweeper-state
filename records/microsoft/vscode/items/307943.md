# Issue #307943 — Webview find widget reappears after being dismissed when switching tabs with retainContextWhenHidden

[https://github.com/microsoft/vscode/issues/307943](https://github.com/microsoft/vscode/issues/307943)

## Summary

The close-button defect remains in current source: dismissing the widget leaves the overlay's visibility context key true, so switching tabs restores it. Keep this team-authored report open; the comment correctly distinguishes Escape's working command path from the broken close-button path.

## Change summary

A dismissed webview find widget reappears after switching tabs when retainContextWhenHidden is enabled.

## Best solution

Keep actual find-widget visibility and the overlay's restoration state consistent so explicit dismissal survives tab switches, while an intentionally open widget still restores. Preserve the distinction between stopping a search and hiding the widget.

Its inner-webview event subscriptions do not synchronize widget dismissal, while hideFind() at lines 420–422 explicitly resets the key.
- **Discussion narrows the reproduction:** The May 22 confirmation on https://github.com/microsoft/vscode/issues/307943 reports the close-button failure in Claude Code webview tabs and says Escape survives tab switches. src/vs/workbench/contrib/webviewPanel/browser/webviewCommands.ts registers editor.action.webvieweditor.hideFind on Escape, consistent with the working OverlayWebview.hideFind() path.
