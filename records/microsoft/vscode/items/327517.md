# Issue #327517 — Text inside tooltip is cut off

[https://github.com/microsoft/vscode/issues/327517](https://github.com/microsoft/vscode/issues/327517)

## Summary

Current source confirms the terminal status tooltip can exceed the shared hover's height and be clipped without a usable scrollbar. Route this to the terminal and workbench-hover owners.

## Change summary

A long terminal environment-contribution tooltip is clipped and cannot be scrolled.

## Best solution

Constrain the shared hover's scrollable content rather than only its outer container, accounting for hover actions and asynchronous Markdown layout, and cover the behavior with a long-content hover test.

## Evidence

- **terminal flow:** src/vs/workbench/contrib/terminal/browser/environmentVariableInfo.ts builds the reported relaunch message, and terminalTooltip.ts includes it with hover actions in the terminal hover.
- **source defect:** src/vs/platform/hover/browser/hoverWidget.ts:591-611 applies maxHeight only to the outer hover. src/vs/platform/hover/browser/hover.css sets that container to overflow: hidden, while the inner DomScrollableElement remains unconstrained, allowing content to be clipped without becoming scrollable.
- **history:** https://github.com/microsoft/vscode/commit/bdf8dd00e410e94375bb607554a477b568266570 previously constrained the inner content to enable scrolling; https://github.com/microsoft/vscode/commit/d39c5a4757599dda2aff99608232c5dc3fd2785a later removed that constraint while adding asynchronous Markdown relayout.
