# Issue #283654 — Working set UI/render debt

[https://github.com/microsoft/vscode/issues/283654](https://github.com/microsoft/vscode/issues/283654)

## Summary

Keep open: current main still contains the DOM rebuilding, selector lookups, shared reference-list type, object pool, and large render path identified by this team-authored debt item. Its On Deck milestone and `debt` classification also represent accepted work rather than a candidate for a judgment close.

## Change summary

Clean up the chat working-set UI so it has a dedicated component, stable DOM and widget ownership, and purpose-built entry types.

## Best solution

Give the working-set UI a dedicated lifecycle-owning component that preserves its DOM and list across session updates, uses a working-set-specific item model, and retains the existing local/background-session behavior, navigation, focus, and changed-line statistics.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatReferencesContentPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`

- **Behavior:**

  > The chat working set must continue to show the correct changed files and added/removed line totals for local editing sessions and background sessions. Starting, updating, switching, or ending a session must update visibility and contents without recreating expensive working-set UI merely because state changed. Collapse state, keyboard focus, file opening, deletion handling, diff opening, selection reporting, toolbar actions, and the six-row overflow behavior must remain intact.
- **Trace:**

  > Current main keeps the working-set implementation in `ChatInputPart.renderChatEditingSessionState` and `renderChatEditingSessionWithEntries` at src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts:4787-5129. The empty path clears `chatEditingSessionWidgetContainer` and releases `_chatEditList`; the populated path locates owned children with repeated `querySelector` calls and obtains its list from `CollapsibleListPool`. Working-set rows are represented as `IChatCollapsibleListItem`, whose definition in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatReferencesContentPart.ts is shared with reference and warning rendering and places editing state on `IChatReferenceListItem`. The trace must cover both `IChatEditingSession.entries` and `IAgentSessionsService` file-change inputs, plus context-key/menu setup and editor-opening behavior. Preserve the observable product behavior and scope the work to the working-set UI; unrelated chat input widgets and general response reference rendering are outside this debt item. The original discussion and transfer confirmation are at https://github.com/microsoft/vscode-copilot/issues/10967 and https://github.com/microsoft/vscode-copilot/issues/10967#issuecomment-3657261923.
