## Summary

This member-authored debt remains present on current main: the working-set UI still lives in a large ChatInputPart rendering path, queries its own DOM, clears and recreates children, and reuses the generic chat-reference list model. The On Deck milestone is a holding bin, so the issue should remain open for the bounded cleanup.

## Change summary

Refactor the chat working-set UI into a dedicated component with stable DOM ownership and a purpose-built entry model.

## Best solution
