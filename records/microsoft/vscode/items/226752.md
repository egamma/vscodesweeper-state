# Issue #226752 — Show documentation when hovering on the autocompletion dropdown list item

[https://github.com/microsoft/vscode/issues/226752](https://github.com/microsoft/vscode/issues/226752)

## Summary

Keep this accepted Backlog request open: current completion documentation follows the focused suggestion, not the row under the mouse. The request has 26 community upvotes, and the canonical-search pass found no verified older issue owning the same hover interaction.

## Change summary

Show a completion item's documentation when the user hovers over its row in the autocomplete dropdown.

## Best solution

Support mouse-driven documentation previews in the editor suggest widget while retaining keyboard navigation and explicit completion acceptance. Decide whether hovering changes the active suggestion or previews documentation independently before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/suggest/browser/suggestWidget.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidgetDetails.ts`, `src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts`, `src/vs/editor/contrib/suggest/test/browser/suggestWidget.test.ts`
- **Validation:** Exercise a completion provider with two items carrying distinct documentation: hover each dropdown row without clicking and verify that the displayed documentation matches that row. Verify the chosen active-suggestion semantics with keyboard acceptance, delayed item resolution, mouse departure, widget dismissal, and existing keyboard-driven details toggling.
- **Behavior:**

  > Users should be able to inspect a completion item's documentation by hovering over its dropdown row without accepting the completion or clicking Read More. Moving between rows should display the corresponding item's documentation, including documentation supplied by completion-item resolution. Keyboard navigation, explicit acceptance, and existing documentation controls must remain usable. Acceptance must also establish which item a keyboard accept action inserts after the pointer previews another row.
- **Trace:**

  > In src/vs/editor/contrib/suggest/browser/suggestWidget.ts, SuggestWidget constructs its list with mouseSupport disabled and handles mouse-down/tap as completion selection through _onListMouseDownOrTap and _select. _onListFocus resolves the focused CompletionItem, and _showDetails renders the focused row rather than a hovered row. toggleDetails stores the documentation visibility preference under expandSuggestionDocs; src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts exposes a click-driven Read More control. The existing toggleSuggestionDetails command is registered in suggestController.ts, while editor.suggest.showInlineDetails governs detail text rather than hover documentation. Source inspection confirms the missing hover path, not a failure of the current focus-driven behavior. Preserve completion-provider contracts, keyboard accessibility, and explicit acceptance; the unresolved boundary is whether mouse previews also change the active completion.
- **Open decisions:**
  - Should hovering a completion row change the active suggestion that keyboard acceptance inserts, or preview that row's documentation independently of the keyboard-focused suggestion?
  - Should mouse departure restore the prior documentation visibility and focused-item content, or leave the hovered documentation open?
