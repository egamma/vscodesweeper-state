# Issue #337172 — allowUnsandboxedCommands should show the proper setting when on windows

[https://github.com/microsoft/vscode/issues/337172](https://github.com/microsoft/vscode/issues/337172)

## Summary

Confirmed from source: several `chat.agent.sandbox.*` setting descriptions (allowUnsandboxedCommands, allowNetwork, retryWithAllowNetworkRequests, allowAutoApprove, fileSystem settings) hardcode a reference to `chat.agent.sandbox.enabled`, but on Windows the effective gating setting is `chat.agent.sandbox.enabledWindows` — matching the screenshot. Routing to the terminal/chat area rather than closing.

## Change summary

On Windows, the description for `chat.agent.sandbox.allowUnsandboxedCommands` (and related sandbox settings) links to `chat.agent.sandbox.enabled` instead of the Windows-specific `chat.agent.sandbox.enabledWindows` that actually gates it.

## Best solution

Mirror the existing `getLocalSandboxEnabledSettingId()` pattern from permissionPickerActionItem.ts (which already picks `AgentSandboxWindowsEnabled` vs `AgentSandboxEnabled` based on `isWindows`) inside terminalChatAgentToolsConfiguration.ts so the affected markdownDescriptions reference the correct setting id per platform.
