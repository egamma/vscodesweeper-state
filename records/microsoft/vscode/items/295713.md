# Issue #295713 — API proposal: Allow ChatSessionContentProvider to provide a checkpoint handler

[https://github.com/microsoft/vscode/issues/295713](https://github.com/microsoft/vscode/issues/295713)

## Summary

Keep this API proposal open: provider-controlled checkpoint restoration remains absent from the current proposed API, and the linked implementation PR is still open. The api-proposal label independently requires leaving finalization or abandonment to the API owners.

## Change summary

Allow contributed chat-session providers to handle checkpoint restoration using their backend's conversation state.

## Best solution

Resolve the client-request-ID versus SDK-message-ID contract identified in the discussion, then review and reconcile https://github.com/microsoft/vscode/pull/294792 with the current session APIs. Keep this proposal tracking the API through finalization rather than treating implementation or existing fork support as completion.
