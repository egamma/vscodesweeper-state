# Issue #333885 — Chat session and history disappear when opening a folder/project in a window that started with an empty workspace

[https://github.com/microsoft/vscode/issues/333885](https://github.com/microsoft/vscode/issues/333885)

## Summary

Traced this in the checkout: the chat session migration logic only fires on the `enterWorkspace`/`onDidEnterWorkspace` path (used for `.code-workspace` files and 'Add Folder to Workspace'), but plain 'Open Folder' from an empty window never calls that API — it goes straight to `IHostService.openWindow`, so the new window's `ChatSessionStore` starts fresh against workspace-specific storage and never sees the session left in the shared `emptyWindowChatSessions` location.

## Change summary

Chat session/history from an empty-workspace window is not carried over (or exposed) when a folder is opened in that same window, even though the underlying session data isn't deleted.

## Best solution

Extend the workspace-transition chat-session migration in `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts` (currently only triggered via `IWorkspaceEditingService.onDidEnterWorkspace`) to also run for the plain 'Open Folder' path where an empty window transitions directly to a folder workspace, so the previously-open session is discoverable in the new workspace's history.

## Evidence

- **existing migration only covers enterWorkspace:** src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts lines 82-129 register `this.workspaceEditingService.onDidEnterWorkspace(...)` -> `handleWorkspaceTransition`, which migrates session files between the empty-window storage root (`emptyWindowChatSessions`, global per-profile) and the per-workspace `chatSessions` folder.
- **onDidEnterWorkspace only fires for .code-workspace transitions:** `fireDidEnterWorkspace` is only called from `enterWorkspace()` in src/vs/workbench/services/workspaces/browser/{workspaceEditingService.ts, electron-browser/workspaceEditingService.ts}, i.e. opening/creating a `.code-workspace` file or 'Add Folder to Workspace' via `updateFolders`/`createAndEnterWorkspace`. Plain 'Open Folder' does not route through this API.
- **shared empty-window storage explains reporter's observation:** Because `emptyWindowChatSessions` is a single global folder (joined from `defaultProfile.globalStorageHome`, not per-window), any *new* empty window can see the old session — matching the reporter's note that a fresh empty window shows the history, while the window that adopted a folder does not.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/314799 covers the 'Add Folder to Workspace' (multi-root, uses enterWorkspace) scenario and is still open/unresolved itself, so it doesn't obviously cover this plain single-folder-open trigger; keeping this open separately rather than folding it in without stronger confirmation that they're the same underlying defect.
