[https://github.com/microsoft/vscode/issues/344061](https://github.com/microsoft/vscode/issues/344061)

## Summary

Wildcard matching is not implemented in the current change detector. Keep this request open while the linked implementation candidate is reviewed; the open PR is not evidence of completion.

## Change summary

Support single-level and recursive wildcard patterns in CI change-detection rules while preserving directory-prefix and exact-file matching.

## Best solution

Review https://github.com/microsoft/vscode/pull/344063 for the desired glob semantics and backward compatibility before deciding whether to land it. Any accepted implementation should demonstrate correct single-level, recursive, and zero-directory matching without changing existing CI selection behavior.

## Evidence

- **Current capability:** .github/actions/detect-changes/detect.ts defines matchesAny using only a trailing-slash directory-prefix check or exact path equality. IChangeRule.paths documents those two forms, and the current rules contain no wildcard patterns; the requested glob capability remains absent.
- **Existing behavior boundary:** .github/actions/detect-changes/detect.ts separately uses isDocumentation and coreTestRules.canSkip for core-test selection. Its existing Markdown handling is not general wildcard support for IChangeRule.paths.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/344063 is verified open and unmerged through the GitHub API. Its body explicitly says Fixes #344061, and its diff modifies matchesAny in .github/actions/detect-changes/detect.ts.
- **Review concern:** The proposed regex conversion in https://github.com/microsoft/vscode/pull/344063 sequentially replaces ** with .* and then replaces every remaining *, including the star it just generated. The proposal therefore needs correctness review rather than being treated as a completed solution.
- **Existing checks:** build/lib/test/detectChanges.test.ts exercises directory/exact-path selection, rename handling, and fail-open behavior. The linked PR currently changes only the detector and adds no wildcard-specific tests.
