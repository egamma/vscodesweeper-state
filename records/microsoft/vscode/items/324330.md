# Issue #324330 — Start the agent host process earlier (prewarm) so local sessions appear quickly on window startup

[https://github.com/microsoft/vscode/issues/324330](https://github.com/microsoft/vscode/issues/324330)

## Summary

The process-prewarm portion was implemented by merged PR https://github.com/microsoft/vscode/pull/326768, but current main still registers both local session-list providers after the heavier AgentHostContribution. Because this team-authored issue explicitly tracks both startup and ordering work, it should remain open for the remaining startup-path optimization.

## Change summary

Start the local agent host during workbench restoration and register cached-session providers before heavier agent discovery and integration work.

## Best solution

Keep the existing BlockRestore prewarm and complete the remaining ordering work in both the editor and Agents-window contribution registries. Measure startup with cached local sessions first, then move hydration earlier only if registration ordering does not make the list available promptly enough.
