# Issue #228857 — Many output bugs when printing to both STDOUT and STDERR; "There are more than 500 outputs"

[https://github.com/microsoft/vscode/issues/228857](https://github.com/microsoft/vscode/issues/228857)

## Summary

The issue is still valid on main: the 500 output display limit remains hard-coded, and interleaving STDOUT/STDERR still creates multiple output items (one per stream switch), triggering the limit prematurely. An open PR (#325792) proposes making the limit configurable but hasn't merged.

## Change summary

When a notebook cell writes to both STDOUT and STDERR, each stream switch creates a new output item, prematurely hitting the hard-coded 500-output limit and showing a truncation message.

## Best solution

Two-part fix: (1) make the 500-item limit configurable via a setting (PR #325792 addresses this), and (2) consolidate adjacent same-stream outputs to avoid inflating the output count when STDOUT/STDERR interleave. The limit configurability lives in `src/vs/workbench/contrib/notebook/browser/viewModel/codeCellViewModel.ts`; the output-item creation logic is in the notebook kernel/execution layer.
