# Issue #174377 — Pressing enter on list view find widget doesn't navigate to next

[https://github.com/microsoft/vscode/issues/174377](https://github.com/microsoft/vscode/issues/174377)

## Summary

Keep open for a list-widget UX decision: the reported Enter behavior is intentional given the current focus-rendering model, but the later Explorer confirmation shows that the navigation inconsistency remains user-visible across list-backed views. The maintainer comment was only tentative, so it does not establish a sufficiently firm *as-designed close.

## Change summary

Keep keyboard focus in a list find widget and advance visibly to the next matching item when Enter is pressed.

## Best solution

Define consistent keyboard semantics for list find widgets: Enter should advance through matches while the find input remains usable, with an explicit visible indication of the active match that does not incorrectly imply DOM focus. Implement that behavior in the shared list find controller so Timeline, Explorer, and other list-backed views remain consistent.
