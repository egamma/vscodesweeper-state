# Issue #270672 — Remote agent picks incorrect repo from workspace with multiple repos

[https://github.com/microsoft/vscode/issues/270672](https://github.com/microsoft/vscode/issues/270672)

## Summary

The bug appears still present on main for the cloud delegation path: `extractRepoNwoFromSession` checks `chatModel.repoData` (the default/first workspace repo) before checking session options (the user's picker selection), so the user's choice is ignored when a local git repo exists. The agent-host path has a newer folder picker, but the cloud coding agent path may still be affected.

## Change summary

When delegating to the remote/cloud coding agent in a multi-repo workspace, the user's repository picker selection is ignored and the first repository is always used.

## Best solution

Fix the priority order in `CreateRemoteAgentJobAction.extractRepoNwoFromSession` (src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts): the user's explicit picker selection (session options, step 3) should take precedence over the ambient `chatModel.repoData` (step 1) when a picker selection exists.
