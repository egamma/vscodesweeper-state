[https://github.com/microsoft/vscode/issues/214242](https://github.com/microsoft/vscode/issues/214242)

## Summary

The requested context-menu and bulk relaunch capabilities remain missing; the existing active-terminal command only partially addresses the workflow. Keep this accepted, team-authored request open: a newer report independently requests the same improvement and is not an eligible canonical for this re-reviewed item.

## Change summary

Provide context-menu actions to relaunch an individual terminal and all terminals, including task terminals, with updated extension environment contributions.

## Best solution

Provide discoverable, keyboard-accessible relaunch actions in the terminal menus, targeting the chosen terminal rather than merely the active one, plus a bulk operation that correctly handles task terminals. Preserve existing launch configurations and task lifecycle behavior, and distinguish already-applied environment contributions from pending changes in the explanatory text.

- **Behavior:**

  > Users can relaunch a chosen terminal from its context menu without relying on a transient hover or killing and recreating it. A bulk action also supports task terminals and applies pending extension environment contributions. Individual relaunch must affect the chosen terminal even when another terminal is active. Acceptance checks cover keyboard invocation, updated environment values, preservation of launch configuration, and correct task execution state.
- **Trace:**

  > The existing workbench.action.terminal.relaunch registration in terminalActions.ts uses registerActiveInstanceAction, which resolves service.activeInstance; the neighboring registerContextualInstanceAction supports contextual terminal selections. terminalMenus.ts contains no relaunch entry, and no bulk relaunch command was found. TerminalInstance.relaunch in terminalInstance.ts copies the launch configuration, removes attachPersistentProcess, and delegates to reuseTerminal with reset enabled. Automatic environment-change relaunch has narrower eligibility conditions and does not satisfy the explicit bulk operation. The trace has not established how restarting a running task through this path interacts with task execution bookkeeping, so planning must inspect that boundary before treating this as a menu-only change. Preserve existing automatic-relaunch eligibility and unrelated task behavior. https://github.com/microsoft/vscode/issues/326096 corroborates the usability need but is newer than this report.
