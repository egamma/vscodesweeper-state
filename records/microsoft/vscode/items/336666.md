# Issue #336666 — Agent session context transfer truncates delegated results without a lossless handoff

[https://github.com/microsoft/vscode/issues/336666](https://github.com/microsoft/vscode/issues/336666)

## Summary

Current main confirms the gap: `get_session_context` deliberately clips each assistant response and reports only a generic `truncated` flag, with no continuation mechanism. Keep this team-authored request open and design a bounded, lossless handoff contract for delegated results.

## Change summary

Allow a requesting agent to retrieve the complete result of delegated work when session-context serialization truncates an individual response.

## Best solution

Keep each tool response bounded, but add message-level continuation to `get_session_context` so a caller can retrieve and losslessly reassemble a truncated assistant response. The contract should distinguish field truncation from unavailable older history and remain usable across Agent Host providers.

## Evidence

- **source reproduction:** On current main, `src/vs/platform/agentHost/node/shared/sessionServerTools.ts` defines fixed per-field caps: even `detail: "full"` limits assistant text to 2,000 characters, and `truncateText` irreversibly replaces the remainder with an ellipsis.
- **missing continuation contract:** The `getSessionContextInputSchema` accepts only `session`, `detail`, and `transcriptLimit`; `ISerializedSessionContext` returns only `transcript`, `hasMoreHistory`, and a boolean `truncated`. Neither side carries a message cursor, offset, artifact reference, or other retrieval handle.

Therefore one fully loaded turn with a response over 2,000 characters produces `truncated: true` while `hasMoreHistory: false`, exactly matching the report.
