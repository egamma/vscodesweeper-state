# Issue #332423 — Agent Host: failed transcript-less subagent blocks subsequent user turns

[https://github.com/microsoft/vscode/issues/332423](https://github.com/microsoft/vscode/issues/332423)

## Summary

Thanks for the detailed diagnostics and root-cause trace — this reproduces conclusively in source: `_resolvePeerChatsForTurnValidation` blocks a new parent-chat turn on resolving every unresolved peer chat, and a failed transcript-less subagent's resolver always throws, so `dispatchAction` rejects the whole new turn and the client is left indefinitely in-progress.

## Change summary

Restoring a session containing a failed, transcript-less subagent tool call causes any subsequent user message in the parent chat to hang with no assistant response or error.

## Best solution

In agentService.ts, make turn-owner peer-chat validation tolerant of an unresolvable failed/empty lazy subagent chat (e.g. treat a zero-turn resolver result as a terminal, still-catalogued failure rather than a thrown exception that aborts the whole `_resolvePeerChatsForTurnValidation` loop), and ensure a rejected async `chat/turnStarted` prelude always reaches the client as a terminal error rather than leaving the turn stuck in-progress.
