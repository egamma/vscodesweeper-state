# Issue #334437 — Copilot Chat cannot resolve installed custom skills

[https://github.com/microsoft/vscode/issues/334437](https://github.com/microsoft/vscode/issues/334437)

## Summary

Confirmed in source: skills beyond the 15000-char description budget are listed by name only (for prompt visibility) but are never added as `<skill><file>` entries in the customizations index, so `resolveSkillUri` in `skillTool.ts` can never resolve them — matching the reporter's exact symptom of skills being 'recognized by name' but failing invocation past roughly the 15th skill.

## Change summary

Copilot Chat's skill tool throws 'Skill not found' for installed custom skills once more than ~15 skills are registered, even though the skill is shown as available by name.

## Best solution

In `_buildCustomizationsIndex` (extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts) and the mirrored logic in computeAutomaticInstructions.ts, ensure every model-invocable skill gets a `<skill><file>` index entry (even a minimal one without a full description) once the character budget is hit for the descriptive listing, so the truncated 'invoke by name' skills remain resolvable by `resolveSkillUri`/`parseInstructionIndexFile`.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts`
- **Validation:** A test asserting that with >15 (budget-exceeding) skills registered, `parseInstructionIndexFile` still returns a resolvable URI for a skill named only in the truncated 'invoke by name' list, and `resolveSkillUri` succeeds for it.
- **Behavior:**

  > When more skills are registered than fit within the description character budget used to build the model-facing skills listing, every skill that is presented to the model as 'available (invoke by name)' must still be invocable via the skill tool — it must resolve to its SKILL.md URI, not throw 'not found'. Skills genuinely filtered out (no description, disableModelInvocation, wrong session type) should continue to be excluded as today.
- **Trace:**

  > The customizations index text built in `_buildCustomizationsIndex` (automaticInstructionsCollector.ts, ~line 500) and its counterpart in computeAutomaticInstructions.ts stop emitting `<skill><file>...</file></skill>` entries once SKILL_DESCRIPTION_CHAR_BUDGET (15000 chars) is exceeded, instead only appending skill names as a plain string. `InstructionIndexFile.skills` (customInstructionsService.ts ~line 552) parses only `<skill><file>` entries into a ResourceSet of URIs, so those truncated names have no corresponding URI. `resolveSkillUri` in skillTool.ts iterates that same set and throws when a name isn't present. Do not change the description char budget used for the prompt-visible skill listing (that manages prompt size for the model) — the fix should ensure the index used for tool resolution independently covers all model-invocable skills regardless of description truncation.
- **Open decisions:**
  - Should truncated skills get a minimal `<skill><file>` index entry (no description) alongside the plain name list, or should the index be built separately from the prompt-visible listing with its own (larger or absent) budget?
  - Should the SKILL_DESCRIPTION_CHAR_BUDGET be raised/removed entirely given skill counts can now exceed it in practice, or is per-skill description truncation preferable to keep prompt size bounded?

## Evidence

- **index truncation:** extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts lines 500-539: once accumulated `<skill>` entries exceed SKILL_DESCRIPTION_CHAR_BUDGET (15000 chars), remaining skills are only added as a plain-text name list ('Additional skills available (invoke by name): ...'), never as `<skill><file>` XML entries.
- **index parser:** extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts InstructionIndexFile.skills (lines 552-557) resolves skill URIs strictly from `<skill><file>` entries via getValuesInIndexFile — names outside the budget are invisible to it.
- **resolver:** extensions/copilot/src/extension/tools/node/skillTool.ts resolveSkillUri() (lines 226-251) iterates only indexFile.skills, so a skill present only in the truncated name list throws 'Skill "X" not found', reproducing the reporter's stack trace.
- **no fix on main:** git log on automaticInstructionsCollector.ts shows no related change addressing this truncation/resolution mismatch.
