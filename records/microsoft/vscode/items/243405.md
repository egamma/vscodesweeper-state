# Issue #243405 — Pre-optimize all TM grammars for performance

[https://github.com/microsoft/vscode/issues/243405](https://github.com/microsoft/vscode/issues/243405)

## Summary

Keep open: build-time optimization of Oniguruma patterns remains distinct from replacing the regex engine, and the inspected grammar-update and packaging paths do not deliver it. The request has 75 upvotes and was accepted into Backlog; neither related closed issue establishes completion or a duplicate.

## Change summary

Pre-optimize bundled TextMate grammar regexes to reduce their size and tokenization cost without changing highlighting behavior.

## Best solution

Evaluate a repeatable grammar-import optimization stage that preserves Oniguruma semantics and existing tokenization results. Establish representative VS Code performance measurements and compatibility coverage before adopting it across bundled grammars.

## Plan brief

- **Likely files:** `build/npm/update-all-grammars.ts`, `build/lib/extensions.ts`, `extensions/package.json`, `extensions/cpp/build/update-grammars.js`, `extensions/typescript-basics/build/update-grammars.mjs`, `extensions/vscode-colorize-tests/src/colorizer.test.ts`
- **Validation:** Compare original and optimized grammars through vscode-textmate/vscode-oniguruma using the existing colorization fixtures, checking token boundaries and scopes as well as rendered colors. Benchmark identical short, medium, and repeated C++ samples before and after optimization in VS Code's tokenization path, recording grammar size, initialization cost, and tokenization time; repeat across representative bundled languages.
- **Behavior:**

  > Bundled TextMate grammars should use smaller and, where possible, faster Oniguruma patterns without changing syntax-highlighting results. The goal is build-time or grammar-import optimization, not replacement of Oniguruma with JavaScript RegExp. Acceptance requires unchanged token boundaries, scopes, and colors across representative fixtures, reproducible grammar updates, and measured performance and size results in VS Code rather than assuming the reported Shiki gains transfer unchanged.
- **Trace:**

  > build/npm/update-all-grammars.ts dispatches extension-specific update-grammar scripts; extensions/cpp/build/update-grammars.js imports upstream grammars through vscode-grammar-updater, while extensions/typescript-basics/build/update-grammars.mjs also applies language-specific transformations. build/lib/extensions.ts:minifyExtensionResources only removes JSON formatting, so it does not cover regex optimization. No oniguruma-parser dependency was found in the root or extensions manifests and lockfiles. extensions/vscode-colorize-tests/src/colorizer.test.ts provides token-output fixture comparisons, but benchmark coverage and optimizer compatibility across grammar constructs remain unestablished. Preserve the regex engine, grammar scopes, captures, and extension-provided grammar behavior; runtime engine replacement is separate work described in https://github.com/microsoft/vscode/issues/237537. The trace has not established a shared integration point covering every individual grammar-update command or the behavior of the external updater dependency.
- **Open decisions:**
  - If a bundled grammar contains a pattern the optimizer cannot safely process, should its update fail, or should the original pattern remain with a visible diagnostic?
