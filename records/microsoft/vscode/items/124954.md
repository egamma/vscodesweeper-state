# Issue #124954 — Allow going inside graphemes (with an explicit gesture)

[https://github.com/microsoft/vscode/issues/124954](https://github.com/microsoft/vscode/issues/124954)

## Summary

This remains a valid Backlog feature request with 22 community upvotes. Current main preserves grapheme-aware navigation and offers only Go to Line/Column offset navigation as a workaround, not the requested explicit gesture.

## Change summary

Provide an explicit gesture or bindable command for positioning the editor cursor inside a Unicode grapheme cluster.

## Best solution

Add an opt-in, bindable editor command for navigating within a grapheme while preserving Unicode grapheme boundaries for ordinary Left/Right movement. The design should define whether navigation advances by Unicode code point or UTF-16 position and how an interior position is rendered.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorMoveCommands.ts`, `src/vs/editor/common/cursor/cursorMoveOperations.ts`, `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Extend the editor cursor unit tests with combining-mark and multi-code-point graphemes: ordinary Left/Right must continue crossing whole graphemes, while the selected explicit command must visit each specified interior boundary in both directions without splitting surrogate pairs.
- **Behavior:**

  > Ordinary cursor movement must continue treating Unicode grapheme clusters atomically. An explicit, bindable gesture should let users enter a grapheme and navigate its editable internal boundaries in both directions. The behavior must work for combining marks and multi-code-point scripts without permitting positions inside UTF-16 surrogate pairs. Go to Line/Column and normal selection behavior must remain unchanged.
- **Trace:**

  > Left/Right commands are registered in src/vs/editor/browser/coreCommands.ts and dispatch through CursorMoveCommands and MoveOperations in src/vs/editor/common/cursor. Current tests in src/vs/editor/test/browser/controller/cursor.test.ts assert that ordinary movement skips complete graphemes. The generic `cursorMove` command currently has no unit for inside-grapheme movement. Direct model-offset navigation already exists in AbstractGotoLineQuickAccessProvider, proving that interior model positions are representable, but ViewCursor._getGraphemeAwarePosition in src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts visually anchors such positions to the grapheme start. Preserve standards-compliant default movement and avoid changing deletion semantics; the uncertainty begins at the explicit command's movement unit and visual caret treatment.
- **Open decisions:**
  - Should the explicit gesture move between Unicode code points or every valid UTF-16 model column while always keeping surrogate pairs atomic?
  - Should inside-grapheme navigation be exposed as separate bindable commands, an additional `cursorMove` unit, or both?
  - How should the caret distinguish interior positions when combining marks have no independently measurable visual boundary?
  - Should selection-extension variants be included in the initial scope?
