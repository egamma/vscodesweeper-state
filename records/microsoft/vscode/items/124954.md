# Issue #124954 — Allow going inside graphemes (with an explicit gesture)

[https://github.com/microsoft/vscode/issues/124954](https://github.com/microsoft/vscode/issues/124954)

## Summary

This remains a valid, community-promoted feature request: current main deliberately moves by Unicode grapheme boundaries, and the existing Go to Line/Column workaround does not provide the requested explicit editing gesture. The request has 22 upvotes and is already in the Backlog, so it should remain open pending an editor interaction decision.

## Change summary

Provide an explicit gesture or bindable command for placing and moving the cursor inside a Unicode grapheme cluster without changing normal grapheme-aware navigation.

## Best solution

Preserve Unicode-compliant movement for ordinary arrow keys while exposing an intentional, discoverable command or gesture for code-point-level navigation and selection inside a grapheme. The editor owner should first settle how movement, selection, and deletion behave after entering a cluster.

## Plan brief

- **Likely files:** `src/vs/editor/browser/coreCommands.ts`, `src/vs/editor/common/cursor/cursorMoveCommands.ts`, `src/vs/editor/common/cursor/cursorMoveOperations.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** ./scripts/test.sh --grep "grapheme" with added coverage showing ordinary arrows still cross whole graphemes while the chosen explicit command can move and select between their constituent code points.
- **Behavior:**

  > Ordinary left/right movement must continue treating a Unicode grapheme as one user-visible character. An explicit, bindable gesture must allow users to place and move the cursor between the grapheme's constituent code points so they can edit those parts directly. Acceptance must cover combining marks and an Indic grapheme, including movement in both directions and selection, while preserving all existing grapheme-breaking assertions.
- **Trace:**

  > Core cursor commands in src/vs/editor/browser/coreCommands.ts delegate through CursorMoveCommands in src/vs/editor/common/cursor/cursorMoveCommands.ts. MoveOperations.moveLeft and moveRight in src/vs/editor/common/cursor/cursorMoveOperations.ts normalize positions with directional affinity, which keeps the cursor on grapheme boundaries; the cursorMove command schema offers no alternative unit. The existing grapheme test in src/vs/editor/test/browser/controller/cursor.test.ts confirms that this remains intentional default behavior. Go to Line/Column can address an interior model column, but it is only a manual workaround documented at https://github.com/microsoft/vscode/issues/124954#issuecomment-1012028291. Keep normal arrow behavior and Unicode boundary compliance unchanged; the uncertainty begins at the user-visible contract for the opt-in gesture and subsequent editing operations.
- **Open decisions:**
  - Should inside-grapheme navigation be exposed as dedicated bindable commands, a modifier applied to normal arrow commands, or both?
  - After the cursor enters a grapheme, should ordinary movement and selection continue from that interior position at code-point granularity, or should only the explicit gesture operate inside the cluster?
  - Should deletion from an interior position remove one code point, or should deletion remain grapheme-based unless a separate explicit command is used?
