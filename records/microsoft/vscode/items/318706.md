# Issue #318706 — VS Code Mac version -> Need to be able to open a Problems window in the new Agents window

[https://github.com/microsoft/vscode/issues/318706](https://github.com/microsoft/vscode/issues/318706)

## Summary

The requested workflow is now clear, and current main still lacks the Problems contribution in the Agents Window even though its Panel supports additional views. Keep this open as an Agents Window feature request and remove it from the information-needed lane.

## Change summary

Make the standard Problems view available beside agent chats so developers can monitor and navigate diagnostics without returning to the main VS Code window.

## Best solution

Expose the standard Problems view through the Agents Window panel picker and existing Problems commands, with diagnostics updating live and opening affected files in the Agents Window editor. The design should explicitly settle whether diagnostics follow the active session/worktree or the entire Agents Window workspace.

## Plan brief

- **Likely files:** `src/vs/sessions/sessions.common.main.ts`, `src/vs/sessions/browser/parts/panelPart.ts`, `src/vs/workbench/contrib/markers/browser/markers.contribution.ts`
- **Validation:** Open an Agents Window for a workspace containing known Flutter or TypeScript diagnostics, invoke “View: Problems” or Cmd+Shift+M, and verify that the Problems panel appears beside the chat, updates as diagnostics change, opens selected files in the Agents Window editor, and remains switchable with Terminal.
- **Behavior:**

  > Developers using the Agents Window can open the standard Problems view without switching to the main VS Code window. It displays live errors and warnings from the intended project scope, supports filtering and diagnostic navigation, and opens a selected diagnostic in the Agents Window editor. Terminal remains available as another panel view, and the existing Problems command and keybinding behave consistently with the main workbench.
- **Trace:**

  > The Agents Window already owns a generic PanelPart at src/vs/sessions/browser/parts/panelPart.ts and registers marker services in src/vs/sessions/sessions.common.main.ts. The latter loads Output and Terminal contributions but omits src/vs/workbench/contrib/markers/browser/markers.contribution.ts, which registers the Problems container, view, commands, and WindowEnablement.Both metadata. The layout specification permits “other panel views,” so no new workbench part is implied. The uncertainty begins at diagnostic scope: an Agents Window can host multiple sessions or worktrees, and the record does not establish whether Problems should follow the active session or aggregate the window workspace. Preserve the main workbench’s existing Problems behavior and do not alter diagnostic production by language extensions.
- **Open decisions:**
  - Should Problems show diagnostics for the currently active agent session/worktree, or aggregate diagnostics across the entire Agents Window workspace when multiple sessions are visible?
