# Issue #336153 — `github.copilot.chat.additionalReadAccessPaths` is bypassed when reading in-workspace symlinks pointing outside the workspace

[https://github.com/microsoft/vscode/issues/336153](https://github.com/microsoft/vscode/issues/336153)

## Summary

Confirmed by tracing the source: getFileExternalConfirmation in toolUtils.ts short-circuits into getWorkspaceFileExternalConfirmation for in-workspace symlinks and never checks additionalReadAccessPaths against the resolved real path, so the setting is silently bypassed for this common devcontainer/remote layout.

## Change summary

additionalReadAccessPaths is ignored when the file being read is an in-workspace symlink whose resolved target lives outside the workspace, so the external-file confirmation prompt still appears.

## Best solution

Thread the additionalReadAccessPaths check into getWorkspaceFileExternalConfirmation (or its caller) so that once the real path is resolved and found outside all workspace folders, it's also checked against the configured allow-list before deciding needsConfirmation, mirroring what getFileExternalConfirmation already does for non-symlink external paths.
