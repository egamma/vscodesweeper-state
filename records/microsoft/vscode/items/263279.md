# Issue #263279 — Agent Mode: Disable tools by default besides core tools

[https://github.com/microsoft/vscode/issues/263279](https://github.com/microsoft/vscode/issues/263279)

## Summary

Keep open as the canonical, team-authored feature request. Current main still enables previously unknown tools by default, and the maintainer discussion identifies unresolved usability and compatibility decisions rather than rejecting the request.

## Change summary

Make non-core agent tools disabled or easily disableable by default, persist that preference appropriately, and expose the enabled-tool count in the chat UI.

## Best solution

Provide an explicit core-tools-only default policy with a one-step picker action and visible enabled-tool count, while defining predictable persistence and behavior for newly discovered or workspace-configured tools.

- **Behavior:**

  > Users can establish a predictable core-tools-only selection without manually disabling every extension and MCP tool in each chat. Their selection follows the chosen persistence scope, and newly discovered tools follow a documented default instead of unexpectedly changing the effective selection. The chat input exposes how many tools are enabled and provides an easy way to return to the core-only selection. Existing workspace MCP configurations behave according to an explicitly chosen compatibility rule.
- **Trace:**

  > ChatSelectedTools in src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts computes effective enablement from session, custom-agent, and profile state; absent entries currently resolve to enabled for both individual tools and tool sets. ConfigureToolsAction in src/vs/workbench/contrib/chat/browser/actions/chatToolActions.ts opens the picker and records enabled/total counts only in telemetry, while src/vs/workbench/contrib/chat/browser/actions/chatToolPicker.ts groups tools by built-in, extension, and MCP source. The existing unit coverage is src/vs/workbench/contrib/chat/test/browser/widget/input/chatSelectedTools.test.ts. Preserve custom-agent tool declarations and explicit user selections; the uncertainty begins at the default and persistence contract, especially for newly added and workspace-configured MCP tools. The older https://github.com/microsoft/vscode/issues/256257 was consolidated into this canonical issue.
- **Open decisions:**
  - Should non-core tools become disabled for everyone by default, or should a setting opt users into the core-only default while preserving today's behavior initially?
  - At what scope should the default and subsequent overrides persist: profile, workspace, window, chat session, or some defined combination?
  - When an extension or workspace configuration contributes a new tool, should it inherit the user's default policy or be automatically enabled for compatibility with setup instructions?
  - Should the enabled-tool count represent individual effective tools, selected tool sets, or both, and where should it appear in the chat input?
