# Issue #314715 — OAuth state with literal `+` causes "State does not match" — VS Code emits raw `+` on /authorize but parses `+` as space on callback (asymmetric encoding)

[https://github.com/microsoft/vscode/issues/314715](https://github.com/microsoft/vscode/issues/314715)

## Summary

Keep open as an OAuth interoperability improvement. Current VS Code correctly encodes outgoing state; the confirmed failure arises when XSUAA emits an incorrectly encoded callback, but URL-safe state generation could prevent this compatibility problem.

## Change summary

Use URL-safe OAuth state values to avoid intermittent sign-in failures with providers that return literal plus characters in callback queries.

## Best solution

Consider URL-safe state generation in LoopbackAuthServer while preserving its randomness and exact callback-state comparison. Do not weaken state validation or change standard query decoding to accommodate malformed provider callbacks.
