# Issue #135432 — Debugger: runInTerminal request fails if the path has "ł" character in it

[https://github.com/microsoft/vscode/issues/135432](https://github.com/microsoft/vscode/issues/135432)

## Summary

Keep this open as the canonical tracker for PowerShell/PSReadLine corrupting Unicode paths passed by `runInTerminal`. A newer report reproduced the same observable failure across Python and Java and was explicitly closed as a duplicate of this issue.

## Change summary

Debug commands sent to Windows PowerShell lose Unicode characters that are unavailable in the active console code page, causing invalid working-directory and script paths.

## Best solution

Confirm the failure matrix on current Windows PowerShell, PowerShell 7, PSReadLine, and relevant code pages, then establish the exact upstream PSReadLine issue. Consume an upstream correction, or consider a bounded VS Code workaround only if the terminal execution path can bypass the lossy PSReadLine input handling without changing ordinary terminal input semantics.

## Evidence

- **DAP payload preserved:** The debugpy log in https://github.com/microsoft/vscode/issues/135432#issuecomment-947116487 shows both `cwd` and the script argument reaching VS Code with `ł` intact as `\u0142`, placing the corruption after the debug adapter request.
- **locale-specific confirmation:** The reporter confirmed the failure persisted in VS Code 1.73 and that the affected PowerShell session used code page 850: https://github.com/microsoft/vscode/issues/135432#issuecomment-1304549422 and https://github.com/microsoft/vscode/issues/135432#issuecomment-1306707150.
- **newer same-symptom reproduction:** https://github.com/microsoft/vscode/issues/235573 reproduced characters disappearing from debug paths in VS Code 1.88.1 with both Python and Java. Its report says the same loss occurs when a path is inserted into PowerShell outside the debug flow and stops when PSReadLine is not loaded; a maintainer closed that issue as a duplicate of https://github.com/microsoft/vscode/issues/135432.
- **current source path:** Current main builds the command in `src/vs/workbench/api/node/extHostDebugService.ts` and passes it through `terminal.shellIntegration.executeCommand(command)` or `terminal.sendText(command)`. `src/vs/workbench/contrib/debug/node/terminals.ts` only quotes the PowerShell arguments, while `src/vs/workbench/contrib/terminal/browser/terminalInstance.ts` forwards the resulting string to the process manager without removing Unicode code points.
- **related issue is not canonical:** https://github.com/microsoft/vscode/issues/83496 is older but concerns inherited terminal cwd discovery on macOS and was fixed by https://github.com/microsoft/vscode/pull/157377; it does not own this Windows PowerShell `runInTerminal` argument-corruption symptom.
- **no competing fix:** No open microsoft/vscode pull request referencing issue 135432 was found.
