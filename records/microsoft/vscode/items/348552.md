For the reported extended-length drive path, the drive colon follows the namespace prefix rather than appearing after the first character, so validation rejects both the bare path and its :1:1 form.
- **CLI entry point:** src/vs/code/node/cli.ts calls parseCLIProcessArgv, which delegates to parseAndValidate in src/vs/platform/environment/node/argvHelper.ts. The rejection occurs in core argument validation, before opening the file.

This supports the commenter's diagnosis that the initial validation is the immediate blocker; end-to-end Windows execution was not performed.
