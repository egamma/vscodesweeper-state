# Issue #310884 — Each time the remote server window is opened, the agent session becomes unread.

[https://github.com/microsoft/vscode/issues/310884](https://github.com/microsoft/vscode/issues/310884)

## Summary

The empty-window bug remains source-reproducible for cloud/background session providers that do not own read state: their fallback read timestamps are workspace-scoped, while each new empty window receives a new workspace identifier. Later fixes suppress the title-bar indicator or synchronize Agent Host sessions, but neither covers this remaining path.

## Change summary

Previously read agent sessions become unread again when the sessions list is opened in a new VS Code window without a workspace.

## Best solution

Keep fallback read state stable across empty-window workspace identities for providers without authoritative read-state support, without making unrelated workspace-local presentation state such as pinning or archiving global.
