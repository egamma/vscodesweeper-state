  > Thanks for the detailed report. A few things that may explain what you're seeing:
  > 
  > 1. **~/.bashrc sourcing**: VS Code resolves the shell environment by spawning your default shell as an interactive login shell (`bash -i -l -c ...`). An interactive login bash reads `/etc/profile` and then the first of `~/.bash_profile`, `~/.bash_login`, or `~/.profile` — it does **not** read `~/.bashrc` unless one of those files explicitly sources it (e.g. `. ~/.bashrc`). Could you check whether your `~/.profile` (or `~/.bash_profile` if you have one) contains a line that sources `~/.bashrc`?
  > 
  > 2. **Stale variables**: VS Code resolves and caches the shell environment once at startup. Changes to your shell config files won't take effect until you fully restart VS Code (not just reload the window).
  > 
  > 3. **CLI launch shortcut**: If you launch VS Code from a terminal (e.g. `code .`), VS Code inherits the terminal's environment directly and skips the shell resolution entirely — which is why `env | grep ENVTEST` in the terminal shows all five variables.
  > 
  > Please share the contents of your `~/.profile` and `~/.bash_profile` (if it exists) so we can confirm. Also, what is your default shell (`echo $SHELL`)?
