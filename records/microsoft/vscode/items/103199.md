# Issue #103199 — Preserve open documents word wrap settings on restart

[https://github.com/microsoft/vscode/issues/103199](https://github.com/microsoft/vscode/issues/103199)

## Summary

Keep this accepted, well-supported feature request open: current main still stores per-document word-wrap toggles only in memory. Persistent global and language-specific settings do not preserve individual open documents' overrides across restart.

## Change summary

Preserve each open document's word-wrap override when VS Code restarts.

## Best solution

Restore document-scoped wrapping overrides for reopened documents, consistently across all editors showing the same document, without changing global or language-specific defaults. Resolve persistence lifetime and configuration-change semantics with the editor owner before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/workbench/browser/parts/editor/editorWithViewState.ts`, `src/vs/workbench/browser/parts/editor/textCodeEditor.ts`
- **Validation:** In a development build, open two long-line files with editor.wordWrap off, toggle wrapping on for only one, show that document in two editor groups, then restart with both documents restored. Verify that its override survives and agrees across groups while the untouched file follows configuration. Repeat with editor.wordWrap on and a document toggled off; test explicit close/reopen and subsequent configuration changes against the agreed lifetime semantics.
- **Behavior:**

  > An open document whose wrapping was changed with Alt+Z should retain that document-specific choice when VS Code restarts and restores the document. All editors displaying the same document should agree, while documents without overrides continue to use their configured defaults. Acceptance covers both enabling wrapping over an off default and disabling it over an on default, including a document open in multiple groups. Persistence after explicit document closure and interaction with later configuration changes require an owner decision.
- **Trace:**

  > ToggleWordWrapAction.run in src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts writes transientWordWrapState through ICodeEditorService; ToggleWordWrapController applies the resulting wordWrapOverride2 and shares the model state across editors. AbstractCodeEditorService in src/vs/editor/browser/services/abstractCodeEditorService.ts keeps this state in ModelTransientSettingWatcher objects tied to model lifetime, with no restart persistence. AbstractEditorWithViewState in src/vs/workbench/browser/parts/editor/editorWithViewState.ts already persists group/resource view state, and textCodeEditor.ts obtains it from CodeEditorWidget.saveViewState, but the wrapping controller does not serialize contribution state. The maintainer explicitly distinguished document-wide wrapping from per-editor view state; preserve shared-document consistency, existing diff synchronization, and configuration defaults. https://github.com/microsoft/vscode/issues/139869#issuecomment-1009065843 confirms that this issue owns the persistence request. The uncertainty is the intended lifetime of restored overrides and their interaction with later settings changes, not whether persistent language defaults already solve this request.
- **Open decisions:**
  - Should remembered wrapping apply only to documents restored after restart, or also survive explicit closure and later reopening?
  - Should changing editor.wordWrap or its language-specific override clear remembered document overrides, or should those overrides continue to take precedence?
