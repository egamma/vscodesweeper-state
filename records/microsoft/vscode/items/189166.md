# Issue #189166 — Cannot launch new terminals in multi-root workspace on a remote machine unless 'terminal.integrated.cwd' is unset

[https://github.com/microsoft/vscode/issues/189166](https://github.com/microsoft/vscode/issues/189166)

## Summary

Still reproduces on current main: the remote terminal backend ignores the resolved CWD parameter (line 156 of remoteTerminalBackend.ts: `cwd: string, // TODO: This is ignored`) and the process manager passes an empty string for cwd in the remote path (line 318 of terminalProcessManager.ts: `'', // TODO: Fix cwd`). The multi-root workspace + `terminal.integrated.cwd` interaction remains broken for remote sessions.

## Change summary

Setting `terminal.integrated.cwd` in a multi-root remote workspace causes terminal launch failure because the CWD resolution does not properly handle the local-vs-remote path distinction.

## Best solution

Fix the CWD resolution in the remote terminal path: the `_launchLocalProcess`-style CWD resolution (via `terminalEnvironment.getCwd`) needs to also run for the remote backend call in `terminalProcessManager.ts`, and `remoteTerminalBackend.ts` should stop ignoring the `cwd` parameter. The TODO comments at both sites mark the exact fix locations. Issue https://github.com/microsoft/vscode/issues/142520 tracks closely related multi-root CWD issues and should be addressed together.
