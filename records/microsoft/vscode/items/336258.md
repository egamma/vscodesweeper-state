# Issue #336258 — `DocumentLink` click target is unpredictable when multiple providers return overlapping ranges — provider priority (score/isBuiltin/registration order) is not respected

[https://github.com/microsoft/vscode/issues/336258](https://github.com/microsoft/vscode/issues/336258)

## Summary

Traced the merge logic in getLinks.ts: LinksList._union only performs an adjacent-pair merge/dedup between the accumulated links and each new provider's links and never re-sweeps the whole result, so it does not reliably guarantee a single winner per overlapping span across more than a trivial pairwise case — matching the reporter's account and their working prototype fix. This stays open for a real code fix.

## Change summary

When two DocumentLinkProviders return overlapping/touching ranges, both links can survive the merge (duplicate hover entries) and the click target is decided by decoration-tree traversal order rather than provider priority (score/isBuiltin/registration time).

## Best solution

Apply the reporter's approach (or equivalent): tag each merged Link with its provider's priority and add a final global pass over the merged list that removes any remaining intersecting/touching duplicates, keeping only the highest-priority one, in src/vs/editor/contrib/links/browser/getLinks.ts.
