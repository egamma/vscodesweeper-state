# Issue #336258 — `DocumentLink` click target is unpredictable when multiple providers return overlapping ranges — provider priority (score/isBuiltin/registration order) is not respected

[https://github.com/microsoft/vscode/issues/336258](https://github.com/microsoft/vscode/issues/336258)

## Summary

Well-diagnosed bug: when two DocumentLinkProviders return overlapping/identical ranges, LinksList._union in getLinks.ts (src/vs/editor/contrib/links/browser/getLinks.ts) doesn't reliably dedupe by provider priority, and LinkDetector.getLinkOccurrence (links.ts) resolves the click target via raw interval-tree order rather than provider score — the reporter reproduced this on two current stable releases (1.134.0 and 1.137.0) with a minimal repro extension and traced the exact code paths.

## Change summary

DocumentLink click target and hover entries are non-deterministic/incorrect when multiple providers (e.g. a custom extension and markdown-language-features) return overlapping ranges for the same link.

## Best solution

Have a maintainer review the reporter's prototype fix (tag merged Link objects with provider priority and add a final pass that strips intersecting lower-priority links) in src/vs/editor/contrib/links/browser/getLinks.ts, and check whether LinkDetector.getLinkOccurrence in links.ts also needs to prefer the highest-priority decoration instead of the first interval-tree hit; land as a PR against this issue.
