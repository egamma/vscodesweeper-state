# Issue #132921 — Show underline warning in settings JSON file when value matches default

[https://github.com/microsoft/vscode/issues/132921](https://github.com/microsoft/vscode/issues/132921)

## Summary

Keep open: current settings diagnostics do not identify values equal to defaults, and the closest matching request is newer than this issue. The remaining design question is how to identify redundant values without flagging intentional overrides.

## Change summary

Identify explicitly configured values matching defaults in user and workspace settings JSON so users can reduce unnecessary configuration.

## Best solution

Provide a clear, non-disruptive indication in settings JSON, with comparison semantics that distinguish redundant entries from workspace values intentionally overriding user settings. Settle the comparison baseline and diagnostic presentation before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/preferencesRenderers.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`
- **Validation:** After settling semantics, add targeted preferences diagnostic tests for an equal-default user value, a genuinely redundant workspace value, a workspace value equal to the default but overriding a different user value, and language-specific defaults. Manually verify the chosen indication in both user and workspace settings JSON without altering their contents.
- **Behavior:**

  > Users editing settings JSON should be able to identify explicit entries matching the agreed comparison baseline without manually searching default settings. The indication must distinguish equality from invalid configuration and must not imply that removing an entry is behavior-preserving when it overrides another configuration level. Acceptance covers user, workspace, and language-specific settings, with no automatic deletion or value changes.
- **Trace:**

  > UnsupportedSettingsRenderer in src/vs/workbench/contrib/preferences/browser/preferencesRenderers.ts generates JSON settings markers and already distinguishes configuration targets, language overrides, policy, profiles, and trust; its inspected handlers contain no default-equality comparison. src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts uses configurationService.inspect and defaultValue for the graphical settings model, providing related configuration-inspection context rather than the requested JSON annotation. workbench.action.openRawDefaultSettings exposes manual comparison only. https://github.com/microsoft/vscode/issues/165589 repeats this request and records the changing-default caveat and interest in dimming; it is newer, so this older issue remains open. Preserve configuration precedence and intentional explicit values; broader graphical settings redesign and bulk removal are outside the original request. The unresolved boundary is whether the indication means literal equality with a default or actual redundancy after considering inherited configuration.
- **Open decisions:**
  - Should the indication identify literal equality with the current default, or only entries whose removal would leave the effective value unchanged?
  - Should valid equal-default entries receive the requested warning underline or a quieter informational or dimmed indication?
