# Issue #290730 — No indication in subagent that intervention is needed

[https://github.com/microsoft/vscode/issues/290730](https://github.com/microsoft/vscode/issues/290730)

## Summary

A distinct gap remains on current main: confirmation state suppresses the expanded-body spinner, but the classic collapsed header still presents the subagent as active. The newer broader visibility issue was filed after this re-reviewed item and cannot serve as its duplicate canonical.

## Change summary

Show a distinct indication when a collapsed subagent is waiting for user intervention instead of presenting it as actively working.

## Best solution

Give the classic collapsed subagent header the same explicit waiting-for-input semantics already available in the open-subagent pill, including a non-working visual state and an accessible status label, while preserving auto-expansion and normal running behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingStyleContentPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatSubagentContentPart.test.ts`
- **Validation:** Add a ChatSubagentContentPart unit test that transitions a child tool to WaitingForConfirmation, manually collapses the subagent, and asserts the header exposes the selected waiting visual state and accessible label without an active-working indicator; run the targeted ChatSubagentContentPart test suite.
- **Behavior:**

  > When a subagent is waiting for confirmation, authentication, or post-approval and the user collapses it, its header must indicate that input is required rather than implying ongoing work. The state must be conveyed both visually and through the accessible label. Auto-expansion for newly requested confirmation remains unchanged, normal running subagents retain their working presentation, and resolving the request restores the appropriate running or completed state.
- **Trace:**

  > ChatSubagentContentPart.trackToolState in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSubagentContentPart.ts already recognizes all three input-wait states, maintains toolsWaitingForConfirmation, auto-expands the block, and removes the body spinner. The collapsed header remains governed by isActive through updateTitle and ChatThinkingStyleContentPart.setThinkingActive/getThinkingIcon, so manually collapsing an awaiting subagent restores an active shimmer/status dot with no waiting distinction. The newer OpenSubagentChatActionViewItem in chatSubagentOpenChat.ts already has running/waiting/completed states and an accessible waiting label, providing a consistency reference rather than a complete fix. Preserve confirmation auto-expansion, carousel ownership, ordinary active-state rendering, and completion behavior.
- **Open decisions:**
  - Should the collapsed waiting state use a static warning/exclamation treatment, or reuse the newer pill's waiting-ring/count treatment?

## Evidence
