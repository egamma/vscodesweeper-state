# Issue #275944 — Figure out how to exclude custom editor based chat sessions from selectable context

[https://github.com/microsoft/vscode/issues/275944](https://github.com/microsoft/vscode/issues/275944)

## Summary

Keep open: current source still excludes Codex custom-editor sessions through a hardcoded URI scheme, rather than a general mechanism. This explicitly tracks the generalization left over from the original fix, and the related API requests do not establish a duplicate.

## Change summary

Replace provider-specific exclusions with a general way to keep custom-editor-based chat sessions out of selectable chat context.

## Best solution

Establish how custom-editor session providers identify resources that should not appear as file context, and honor that consistently in Add Context and file suggestions without excluding ordinary custom-editor documents.

- **Behavior:**

  > Custom-editor-based chat sessions should not appear as recently opened file attachments in Add Context or chat file suggestions. The behavior should not require adding a provider-specific scheme to VS Code's source. Ordinary custom-editor documents must remain available as context, and existing Codex and registered chat-session exclusions must continue to work.
- **Trace:**

  > The original report, https://github.com/microsoft/vscode/issues/273436, recorded session editors appearing in Add Context; its discussion explicitly deferred general custom-editor handling after a Codex-specific workaround. Current src/vs/workbench/contrib/chat/common/constants.ts retains 'openai-codex' in chatAlwaysUnsupportedFileSchemes, while isSupportedChatFileScheme also checks IChatSessionsService.getContentProviderSchemes(). AddContextAction in browser/actions/chatContextActions.ts and the editor-history completion loop in browser/widget/input/editor/chatInputCompletions.ts both use this scheme-only predicate. The unresolved boundary is how providers identify custom-editor chat sessions without suppressing legitimate custom-editor file context. Related https://github.com/microsoft/vscode/issues/254742 concerns richer context content, not necessarily exclusion; do not expand this cleanup into that broader API effort without an explicit decision.
- **Open decisions:**
  - Should context exclusion be declared for an entire URI scheme, a custom-editor view type, or individual session resources, including when a provider uses the same scheme for ordinary documents?
