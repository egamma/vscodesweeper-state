# Issue #328026 — Allow configuring the content width of the experimental Markdown editor

[https://github.com/microsoft/vscode/issues/328026](https://github.com/microsoft/vscode/issues/328026)

## Summary

Keep open: the rich Markdown editor still exposes no content-width configuration, and the discussion demonstrates a practical need for full-width technical documents. The related font-size and custom-stylesheet issues do not own this same observable request.

## Change summary

Allow users to configure the rich Markdown editor's content width, including an unlimited option, consistently across normal and Agents windows.

## Best solution

Provide a supported width preference for the built-in rich Markdown editor that preserves readable-width defaults and horizontal padding while allowing wider or full-width documents. Settle its public configuration contract without making arbitrary stylesheet injection a prerequisite.

Verify user/workspace precedence and the agreed behavior when configuration changes while the editor is open.
- **Behavior:**

  > The rich Markdown editor currently offers no supported way to use the available width for wide technical documents. Users should be able to retain the readable-width default or choose full-width content with reasonable horizontal padding; the request also proposes a wider numeric limit. The chosen preference should behave consistently in normal editor windows and the Agents window, in both Locked and Editing modes. Acceptance should cover wide tables, code blocks, diagrams, and resizing without changing the default experience.
- **Trace:**

  > MarkdownEditorProvider.#getHtml and #getEditorConfiguration in extensions/markdown-language-features/src/preview/markdownEditorProvider.ts initialize the webview with highlightActiveBlock but no width preference. Its configuration-change listener currently forwards changes to that preference only. src/preview/markdownEditorProtocol.ts defines the editor configuration schema with highlightActiveBlock alone, and markdown-editor-src/editor.ts constructs EditorView without a width override. The outer container already fills its available width in markdown-editor-src/markdownEditor.css; the reporter and independent commenter identify the inner content cap in shipped builds. The current dependency's width API and both window hosts still need inspection before choosing an implementation; no runtime reproduction was performed. Preserve document editing, default readability, padding, and traditional preview behavior. https://github.com/microsoft/vscode/issues/328116 discusses arbitrary stylesheet injection, but it is a separate, newer request and should not become a prerequisite for this narrower capability.
- **Open decisions:**
  - Should the public width preference support both numeric maximum widths and an unlimited value, or only readable-width versus full-width modes?
