# Issue #160702 — Fractional scaling makes cursor inaccurate on Chromebooks

[https://github.com/microsoft/vscode/issues/160702](https://github.com/microsoft/vscode/issues/160702)

## Summary

The monospace character-width optimization still exists on current main and is still susceptible to fractional-DPR drift on ChromeOS; the workaround (`editor.disableMonospaceOptimizations`) remains the only mitigation. No fix commit references this issue. However, reproduction is ChromeOS-only and hard to verify without hardware, so keeping open rather than escalating.

## Change summary

Cursor position drifts from actual text position on ChromeOS Chromebooks when display scaling produces a fractional devicePixelRatio, because the monospace width optimization accumulates rounding errors.

## Best solution

The monospace optimization in `src/vs/editor/browser/viewParts/viewLines/viewLineOptions.ts` (and the character-offset computation it feeds) needs to account for fractional DPR rounding, or automatically fall back to browser-measured positioning when the DPR is non-integer. The existing `disableMonospaceOptimizations` setting proves the fallback path works; the gap is detecting when it should engage automatically. Requires ChromeOS hardware or ChromeOS Flex to validate.
