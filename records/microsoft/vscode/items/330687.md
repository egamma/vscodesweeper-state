## Summary

Detailed, plausible report of a custom-agent default-model value getting stuck/cached across VS Code restarts, but I couldn't independently confirm the exact mechanism in this checkout — the agent frontmatter parsing/caching for delegator/subagent setups appears to be resolved by the agent host over its protocol rather than parsed directly in `src/vs`, so I can't cite a concrete source-level defect; asking for more detail before triaging further.

## Change summary

A custom agent's default model (set in the agent's frontmatter, e.g. `agent.yml`) does not update after restarting VS Code even after the file is edited, until the user re-opens and re-saves the file to force a re-parse.

## Best solution

Needs a maintainer/engineer with access to the agent-host implementation to trace how `AgentCustomization.model` is populated and whether it's being read from a stale on-disk/in-memory cache versus persisted chat model-selection storage (`src/vs/workbench/contrib/chat/common/chatSelectedModel.ts`); once localized, the fix is to ensure the frontmatter's current `model` value is treated as authoritative unless the user has made an explicit override.

- **protocol-level state:** AgentCustomization.model (src/vs/platform/agentHost/common/state/protocol/state.ts, referenced from src/vs/platform/agentHost/common/state/sessionState.ts) is populated from the agent host over its protocol; the actual frontmatter read/cache for custom agents wasn't found parsed directly in src/vs, so the root cause may live in the agent host process itself.
