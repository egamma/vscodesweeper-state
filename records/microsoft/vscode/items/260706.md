# Issue #260706 — Git - Make it easier to tell that the current window is a work tree

[https://github.com/microsoft/vscode/issues/260706](https://github.com/microsoft/vscode/issues/260706)

## Summary

Keep open for the Git owner's assessment: current main improves repository identity through a configurable title variable and SCM worktree icons, but does not establish complete coverage of the requested window and SCM distinction. This team-authored request has no verified full-scope duplicate or fixing commit explicitly referencing it.

## Change summary

Make worktree windows identify their originating repository and make the active worktree readily distinguishable in SCM.

## Best solution

Retain the improved repository-name title variable and worktree icons, then have the Git owner determine whether default window titles and standalone SCM repository labels need clearer repository/worktree context. The title-only reports do not absorb the broader SCM requirement.

## Evidence

- **Reported scope and discussion:** https://github.com/microsoft/vscode/issues/260706 requests both recognizable repository identity in worktree window titles and an obvious active-worktree indication in SCM. The author explicitly rejected the former activeRepositoryName behavior because it returned the worktree name; meaningful branch names were not an adequate solution.
- **Existing capability now partially covers the request:** extensions/git/src/repository.ts:996-999 sets SourceControl.activeRepositoryName from the originating repository path for worktrees. src/vs/workbench/contrib/scm/browser/activity.ts:116-122 consumes that override, and src/vs/workbench/browser/workbench.contribution.ts registers ${activeRepositoryName} and ${activeRepositoryBranchName} for window.title. A custom title can therefore provide repository and branch context.
- **Concrete landed improvement, not sufficient close provenance:** https://github.com/microsoft/vscode/commit/726405087726ba0986b234b4175047ea34997db4 adds the Git repository-name override and its SCM propagation. https://github.com/microsoft/vscode/pull/337960 is merged, but its closingIssuesReferences is empty and its commit message does not reference issue 260706. It improves the configurable-title path rather than changing default titles or SCM repository labels, so it does not justify a completed close of this team-authored request.
- **Remaining default-title and SCM boundary:** src/vs/workbench/browser/parts/titlebar/windowTitle.ts:41-51 still uses rootName rather than activeRepositoryName in default titles. extensions/git/src/repository.ts:974-994 supplies worktree or chat-sparkle icons and an optional parent relationship. src/vs/workbench/contrib/scm/browser/scmRepositoryRenderer.ts:150-160 adds the parent name only when the parent repository is available and explorer mode is enabled; otherwise the row uses provider.name. These are useful indicators but do not guarantee originating-repository context for a standalone worktree window.
