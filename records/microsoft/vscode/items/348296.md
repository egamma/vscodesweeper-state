# Issue #348296 — Tree view: one failing getTreeItem (or invalid tree item) empties every node of the same request batch, and a failing getTreeItem during a refresh drops the refresh silently

[https://github.com/microsoft/vscode/issues/348296](https://github.com/microsoft/vscode/issues/348296)

## Summary

Current source confirms both batch-wide failure propagation and cache invalidation before a failed targeted refresh. Keep open: these are VS Code error-isolation defects, not merely failures in an extension.

## Change summary

Isolate tree-provider failures so one invalid or rejected item does not erase unrelated children or leave refresh caches inconsistent.

## Best solution

Preserve valid children and unrelated batch results when an item fails, report the failure explicitly, and keep renderer and extension-host state consistent after a failed targeted refresh. Address these confirmed rejection paths without introducing provider timeouts or redesigning reveal behavior.
