# Issue #286271 — Allow creating Worktrees from branch context menu

[https://github.com/microsoft/vscode/issues/286271](https://github.com/microsoft/vscode/issues/286271)

## Summary

Keep open: the branch context menu still lacks worktree creation, although the separate worktree creation flow supports selecting an existing branch. This team-authored, accepted request remains distinct from the related Agents Window work.

## Change summary

Allow creating a worktree directly from a branch's context menu in the Source Control Repositories view.

## Best solution

Expose branch-specific worktree creation in the built-in Git extension, using the selected branch without requiring users to select it again. Preserve the existing destination selection and safeguards for branches already checked out.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/commands.ts`
- **Validation:** In a development build, enable scm.repositories.explorer and use single repository selection. Right-click an unused local branch and invoke worktree creation: confirm the selected branch is used without another branch picker and the resulting worktree appears in the Repositories view. Repeat with the current branch and a branch already used by another worktree to verify existing safeguards, and confirm cancellation and the Worktrees '+' flow remain unchanged.
- **Behavior:**

  > The Source Control Repositories view should allow users to create a worktree from a local branch's context menu. The selected branch supplies the operation's branch context without requiring another branch selection. Destination selection and cancellation should behave consistently with existing worktree creation. Branches already checked out in the current repository or another worktree must retain the existing safeguards.
- **Trace:**

  > extensions/git/package.json registers worktree creation on scm/artifactGroup/context for the Worktrees group, but not on branch entries in scm/artifact/context. GitArtifactProvider.provideArtifacts in extensions/git/src/artifactProvider.ts supplies local branch artifacts with refs/heads ids and branch names. In extensions/git/src/commands.ts, artifactGroupCreateWorktree calls _createWorktree, which always obtains the branch through getWorktreeCommitishAndBranch before selecting a destination. That picker also owns the current-branch warning and existing-worktree conflict handling, which must remain effective for contextual creation. The scope is the built-in Git extension's Repositories branch menu, not Agents Window session isolation or new worktree configuration. The related https://github.com/microsoft/vscode/issues/336620 concerns a different surface and does not absorb this request. The source establishes the missing entry point; interactive acceptance checks were not executed because the checkout is read-only.
