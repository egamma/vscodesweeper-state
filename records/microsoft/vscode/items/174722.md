# Issue #174722 — Deleted files move to another directory, not to trash

[https://github.com/microsoft/vscode/issues/174722](https://github.com/microsoft/vscode/issues/174722)

## Summary

Keep open as an upstream macOS/OneDrive integration issue: independent reproductions and Electron's investigation identify incorrect handling of the native trash operation. Current VS Code still delegates to Electron, and no verified behavioral fix or qualifying canonical duplicate was found.

## Change summary

Deleting files inside a OneDrive workspace should move them to Trash rather than the OneDrive root directory.

## Best solution

Resolve OneDrive's handling of the native macOS trash API and verify the original Explorer deletion scenario on an affected OneDrive installation. Preserve VS Code's recoverable-delete behavior; permanently deleting files is not an equivalent fix.

## Evidence

- **Confirmed symptom and environment:** https://github.com/microsoft/vscode/issues/174722 includes independent reports that deleting files beneath a OneDrive directory moves them to its root. Reports cover Intel and Apple Silicon Macs, with and without VS Code sandboxing; one commenter reports that Finder deletion works correctly.
- **Upstream reproduction:** https://github.com/electron/electron/issues/38541 documents the same symptom in a standalone Electron application. https://github.com/electron/electron/issues/38541#issuecomment-1573934608 further reproduces the incorrect destination using NSFileManager.trashItemAtURL, which reports success.
- **Upstream ownership, not a verified fix:** Electron's issue is closed, but the maintainer explanation at https://github.com/electron/electron/issues/38541#issuecomment-1584278194 attributes the defect to OneDrive's handling of the correctly invoked native API. That closure supplies no fixing commit and does not establish resolution.
- **Current VS Code deletion boundary:** src/vs/platform/files/electron-main/diskFileSystemProviderServer.ts: DiskFileSystemProviderChannel.delete normalizes the resource path and awaits shell.trashItem(filePath) when useTrash is enabled. It does not choose a OneDrive destination. This confirms the integration boundary, not present-day reproduction of OneDrive's behavior.
- **Workaround changes deletion semantics:** The thread suggests disabling files.enableTrash. src/vs/workbench/contrib/files/browser/files.contribution.ts:232-235 explicitly documents that disabling this setting permanently deletes files and folders; it does not restore the requested Trash behavior.
- **Canonical search:** Open-issue searches for OneDrive/trash and CloudStorage/delete found no older issue owning this same symptom. The related https://github.com/microsoft/vscode/issues/233967 is a newer Windows Explorer-deletion crash report, not the macOS OneDrive destination defect, and does not satisfy the re-review duplicate bar.

No application or reproduction was executed; the evidence does not establish either a current resolution or current non-reproduction.
