# Issue #174722 — Deleted files move to another directory, not to trash

[https://github.com/microsoft/vscode/issues/174722](https://github.com/microsoft/vscode/issues/174722)

## Summary

Keep open as an upstream macOS/OneDrive trash-integration issue. Multiple independent reports and a native API reproduction establish the problem, but there is no verified fixing commit or older open canonical that supports closing it.

## Change summary

Deleting files inside a OneDrive workspace should move them to macOS Trash rather than the OneDrive root directory.

## Best solution

Correct OneDrive's handling of the native trash API used by Electron, then verify that VS Code deletions reach macOS Trash. Preserve recoverable deletion semantics rather than treating permanent deletion as a fix.

## Evidence

- **Confirmed reported behavior:** The discussion at https://github.com/microsoft/vscode/issues/174722 contains independent confirmations on Intel and Apple Silicon Macs: deleting files within OneDrive moves them to its root. A commenter reports that Finder deletion works correctly, and the latest comment in December 2025 still requests a resolution.
- **Current source boundary:** src/vs/platform/files/electron-main/diskFileSystemProviderServer.ts, DiskFileSystemProviderChannel.delete, lines 40–49, delegates useTrash deletions directly to await shell.trashItem(normalize(resource.fsPath)). VS Code does not select a OneDrive destination. This establishes the current delegation path, not a runtime reproduction on the latest OneDrive/macOS versions.
- **Native reproduction and upstream diagnosis:** https://github.com/electron/electron/issues/38541#issuecomment-1573934608 reports that NSFileManager trashItemAtURL moves the file to the OneDrive root while returning success. https://github.com/electron/electron/issues/38541#issuecomment-1584278194 attributes this to OneDrive's implementation and states that Electron calls the correct API. The Electron issue is closed, but its discussion provides no fixing commit.
- **Workaround is not resolution:** The thread suggests disabling files.enableTrash. src/vs/workbench/contrib/files/browser/files.contribution.ts registers that setting with default true and explicitly warns that disabling it permanently deletes files/folders; this does not satisfy the requested recoverable deletion behavior.
- **Canonical search:** Repository searches for 'OneDrive trash' and 'CloudStorage delete' found no older open issue owning this symptom. https://github.com/microsoft/vscode/issues/177427 is closed and explicitly marked a duplicate of this issue. https://github.com/microsoft/vscode/issues/233967 is a newer Windows crash report, not the same reporter-observable macOS relocation symptom, and does not satisfy the re-review duplicate bar.
