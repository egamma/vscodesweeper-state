# Issue #325356 — Pinned models don't follow model-family upgrades — new versions get buried in "Other Models"

[https://github.com/microsoft/vscode/issues/325356](https://github.com/microsoft/vscode/issues/325356)

## Summary

Current main improves discovery by showing the latest model of each product line, but pins still store exact identifiers and superseded versions remain in Other Models. Keep this team-authored request open for the remaining family-following and price-tier semantics; the related exploration does not establish a same-symptom duplicate.

## Change summary

Allow model pins to follow same-price family upgrades and reduce superseded-version clutter while retaining search access.

## Best solution

Provide an explicit family-following pin contract that preserves price expectations and communicates upgrades, coordinated with latest-per-line recommendations. Settle how these pins interact with Featured entries and older-version discovery before implementation.

- **Behavior:**

  > Users should be able to follow newer same-price versions of their preferred model families without repeatedly unpinning and repinning. A family-following upgrade should be understandable, and superseded versions should remain discoverable through search without crowding the normal picker. Acceptance must distinguish exact-version pins from family-following pins and cover same-price, changed-price, and unavailable successors. The current latest-per-line shortlist already improves discovery and must not be mistaken for completion of pin migration.
- **Trace:**

  > LanguageModelsService in src/vs/workbench/contrib/chat/common/languageModels.ts persists pins as exact identifier strings; pinModel and getPinnedModelIds contain no family-upgrade resolution. buildModelPickerSections in modelPickerTabs.ts takes those exact pins first, then uses latestOfEachLine from modelPickerLineage.ts to populate recommendations, leaving superseded versions in other. The existing test 'a model superseded within its line falls through to the rest' confirms that placement contract. chat.defaultModel supports latest-family selection for new conversations but is not a multi-pin mechanism. Coordinate the product contract with https://github.com/microsoft/vscode/issues/317128 and the Bump List discussion at https://github.com/microsoft/vscode/issues/293875#issuecomment-3872046961; neither establishes a duplicate or an implemented family-pin contract. Preserve provider boundaries, availability restrictions, and explicit version selection; the unresolved boundary is what authorizes advancing a pin and suppressing its predecessors.
- **Open decisions:**
  - Do existing pins remain exact-version pins with an opt-in family-following mode, or should existing pins begin following compatible upgrades?
  - What defines a price-matching successor, and what should a following pin display when the newest family version changes price or is unavailable to the account?
  - Should a Featured successor automatically advance an opted-in pin or require confirmation, and what visible indication communicates the change?
  - Should superseded versions be absent from Other Models as well as recommendations, and which explicitly pinned or selected older versions remain visible outside search?
