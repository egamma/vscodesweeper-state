## Summary

Team-authored, freshly filed bug with a precise self-diagnosis; verified on current main that `_hydrateModelFromDraft` still calls `listener.clear()` one-shot, so the described divergence between the Sessions and Workbench model pickers still reproduces. No fix has landed yet, so this stays open for the author's own proposed 20-30 line change.

## Change summary

A model chosen in the Workbench chat picker doesn't keep syncing into `session.modelId` because the draft-model hydration observer stops listening after its first successful read.

## Best solution

Land the author's proposed fix in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts: stop clearing the listener in `_hydrateModelFromDraft`, add a guard so an echoed Sessions write doesn't loop, and record mirrored updates with `ChatModelSource.Restored` as outlined in the issue.
