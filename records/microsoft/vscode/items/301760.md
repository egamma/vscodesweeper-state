# Issue #301760 — Autopilot approving askQuestions after being disabled

[https://github.com/microsoft/vscode/issues/301760](https://github.com/microsoft/vscode/issues/301760)

## Summary

Still reproducible from current source: disabling Autopilot updates the live input state, but askQuestions decides whether to auto-answer from the permission level stamped on the original request. The issue remains necessary because a question raised later in that request is still answered as though Autopilot were enabled.

## Change summary

Disabling Autopilot during an active chat request should make subsequent askQuestions calls wait for the user instead of selecting recommended answers automatically.

## Best solution

Use the session's current permission level when askQuestions is invoked, while preserving auto-answering when Autopilot or the explicit auto-reply setting is currently enabled. Keep request-stamped permission metadata for request history and telemetry rather than treating it as the live control state.
