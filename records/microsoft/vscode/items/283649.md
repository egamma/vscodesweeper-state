# Issue #283649 — Extension tools should require confirmation by default if prepareInvocation is not implemented

[https://github.com/microsoft/vscode/issues/283649](https://github.com/microsoft/vscode/issues/283649)

## Summary

Team-authored issue (hard keep-open). The defect is still present on main: extension tools that do not implement `prepareInvocation` skip confirmation because `isToolEligibleForAutoApproval` defaults to `true` (line 1359 of `languageModelToolsService.ts`). The default confirmation fallback at line 1046 only fires when a tool is NOT eligible for auto-approval, so it never covers the common case.

## Change summary

Extension-contributed tools that don't implement `prepareInvocation` should require user confirmation by default, but currently they are auto-approved.

## Best solution

Change the default return value of `isToolEligibleForAutoApproval` from `true` to `false` for extension-contributed tools (or add a separate check for whether `prepareInvocation` is implemented) so that the default confirmation dialog at line 1046 fires. The setting-based override (`ChatConfiguration.EligibleForAutoApproval`) would still let users opt specific tools into auto-approval.
