# Issue #283649 — Extension tools should require confirmation by default if prepareInvocation is not implemented

[https://github.com/microsoft/vscode/issues/283649](https://github.com/microsoft/vscode/issues/283649)

## Summary

The insecure default remains traceable on current main: an extension tool without `prepareInvocation` produces no confirmation messages and is eligible for auto-approval by default. This security-sensitive, team-authored issue must remain open for maintainer handling.

## Change summary

Require confirmation when an extension-provided language model tool does not implement `prepareInvocation`.

## Best solution

Make third-party extension tools fail safe by synthesizing a generic, non-auto-approvable confirmation when `prepareInvocation` is absent, while preserving explicit confirmation behavior supplied by extensions.

## Evidence

- **current source:** In src/vs/workbench/api/common/extHostLanguageModelTools.ts, `$prepareToolInvocation` returns no prepared invocation when the registered extension tool lacks `prepareInvocation`.
- **confirmation path:** src/vs/workbench/api/browser/mainThreadLanguageModelTools.ts always registers a `prepareToolInvocation` proxy, so the workbench cannot distinguish an absent extension implementation from one that returned undefined.
- **unsafe default:** In src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts, `isToolEligibleForAutoApproval` defaults to true, default confirmation messages are added only for ineligible tools, and invocation waits only when `confirmationMessages.title` exists.
- **ported security report:** https://github.com/microsoft/vscode-copilot-issues/issues/106 documents the observable no-confirmation behavior for an extension tool capable of evaluating JavaScript and was transferred to this issue by a VS Code maintainer.
