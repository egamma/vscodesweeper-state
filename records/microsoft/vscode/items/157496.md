# Issue #157496 — Merge Editor: Diff Both Inputs Against Each Other

[https://github.com/microsoft/vscode/issues/157496](https://github.com/microsoft/vscode/issues/157496)

## Summary

Keep open: current source automatically resolves wholly equal changes, but does not generally factor common content out of differing inputs. The maintainer's counterexamples leave the desired conflict semantics unsettled; this team-authored Backlog request has no verified completed fix or eligible duplicate.

## Change summary

Use similarities between the two merge inputs to reduce conflicts containing shared edits or common content.

## Best solution

Have the merge-editor owner decide when shared content should be removed from conflicts without obscuring independent changes or breaking Accept Combination. Retain the existing base-relative interpretation until that policy is established, using the add/add example and the documented counterexamples as acceptance cases.

## Evidence

- **Current implementation and remaining gap:** src/vs/workbench/contrib/mergeEditor/browser/model/mergeEditorModel.ts constructs TextModelDiffs from base to each input and creates conflicts through ModifiedBaseRange.fromDiffs. In modifiedBaseRange.ts, isEqualChange compares complete base-relative edit lists; smartCombineInputs combines their range edits rather than computing an input-to-input diff. Thus wholly equal edits are covered, but differing add/add inputs with substantial shared content are not generally decomposed around that shared content.
- **Existing-capability check:** mergeEditorModel.ts reset and computeAutoMergedResult accept equal changes automatically. src/vs/workbench/contrib/mergeEditor/test/browser/model.test.ts contains 'auto-solve equal edits'. mergeEditor.contribution.ts registers mergeEditor.diffAlgorithm and the Compare Input With Base commands, but no conflict-style setting that implements the requested input-to-input factoring. These existing capabilities cover only part of the request.
