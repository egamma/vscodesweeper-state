# Issue #173259 — Incorrect Keyboard Shortcuts on Web Version of VSCode on Samsung Galaxy Tab S8 Ultra

[https://github.com/microsoft/vscode/issues/173259](https://github.com/microsoft/vscode/issues/173259)

## Summary

Keep open as an upstream browser-input issue: Android Blink browsers report the German layout and AltGr modifiers incorrectly, while Firefox works. Current VS Code still depends on browser keyboard events and `navigator.keyboard.getLayoutMap()`, so the underlying gap remains.

## Change summary

German keyboard shortcuts and AltGr combinations are misinterpreted in vscode.dev on Samsung Galaxy tablets with keyboard covers.

## Best solution

Track the browser-side keyboard-event/layout correction here and consolidate the narrower Android AltGr reports into this older, broader issue. VS Code should retain the explicit `keyboard.layout` escape hatch and document the Alt+digit keybinding workaround while the upstream behavior remains.

## Evidence

- **browser-specific behavior:** The discussion at https://github.com/microsoft/vscode/issues/173259 reports the failure in Brave but successful input in Firefox on the same Galaxy tablet, pointing to the browser keyboard-event implementation rather than the physical keyboard.
- **upstream precedent:** https://github.com/microsoft/vscode/issues/137389 documents the same Android Blink behavior: AltGr+Digit arrives as Alt+Digit, and a maintainer classified it as upstream after the reporter filed Chromium issue 1271496.
- **current confirmations:** The open reports https://github.com/microsoft/vscode/issues/197823 and https://github.com/microsoft/vscode/issues/197826 describe the same AltGr failure on Android keyboard covers; https://github.com/microsoft/vscode/issues/197823 includes confirmations through 2026 that removing Alt+Digit keybindings restores character input.
- **current source path:** src/vs/base/browser/keyboardEvent.ts derives modifiers directly from browser KeyboardEvent fields, while src/vs/workbench/services/keybinding/browser/keyboardLayoutService.ts detects layouts through navigator.keyboard.getLayoutMap() and cannot infer a layout from modified fallback events. An Android browser reporting AltGr as Alt therefore resolves the built-in Alt+Digit command.
- **partial existing workaround:** The `keyboard.layout` setting is registered in src/vs/workbench/services/keybinding/browser/keyboardLayoutService.ts. src/vs/workbench/services/keybinding/browser/keyboardLayouts/de.linux.ts contains the expected German KeyY/KeyZ swap and AltGr+8 `[` mapping, but selecting that layout cannot correct a browser that reports AltGr as Alt.
