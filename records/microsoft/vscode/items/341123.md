## Summary

Keep open: the earlier fix addressed rejected-token retry presentation, not successful end-to-end connector authorization. The supplied steps and gateway logs suffice to retest; the exported runtime's precise credential-routing cause remains unconfirmed.

## Change summary

WorkIQ and Kusto Sign In reports authentication success but subsequent connector requests still lack write:plugin_gateway_connections and return HTTP 403.

## Best solution

Establish which credential the managed connector actually sends after interactive Sign In, then ensure authorization updates that credential for the selected account. Authentication reporting should distinguish token delivery from gateway acceptance and successful tool discovery, while retaining rejected-token retry suppression.
