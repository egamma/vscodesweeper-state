# Issue #210654 — Weird keybindings with non-US layout

[https://github.com/microsoft/vscode/issues/210654](https://github.com/microsoft/vscode/issues/210654)

## Summary

The extra Control modifier comes from the current keyboard mapper: it treats Option-produced characters as Ctrl+Alt combinations on macOS as well as Linux. Keep this accepted keyboard-layout bug open; the reported mapping still follows that source path.

## Change summary

Split Editor acquires an unnecessary Control modifier on the macOS Latin American layout instead of resolving Cmd+backslash to Option+Cmd+[Minus].

## Best solution

Resolve macOS character-based defaults using the modifiers that actually produce the character, so Split Editor accepts Option+Cmd+[Minus] for the reported layout. Preserve Linux AltGr handling, explicit Control shortcuts, and US-layout defaults.
