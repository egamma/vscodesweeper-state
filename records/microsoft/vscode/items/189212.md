# Issue #189212 — [Bug] Unable to replace non-English regex match

[https://github.com/microsoft/vscode/issues/189212](https://github.com/microsoft/vscode/issues/189212)

## Summary

This is expected ECMAScript regular-expression behavior rather than a replacement defect: `\w` and `\W` are ASCII-based, while the Malayalam characters before these hyphens are Unicode combining marks.

## Change summary

Replace hyphens following non-English word characters while preserving the captured character.

## Best solution

Keep the editor's ECMAScript regex semantics and use Unicode property escapes for this replacement, including both letters and combining marks.

- **Proposed comment:**

  > Thanks for the report. Editor Find uses ECMAScript regular expressions, where `\w` only covers ASCII word characters even in Unicode mode. In this sample, the characters immediately before the hyphens are Malayalam combining marks rather than Unicode letters.
  > 
  > A Unicode-aware expression such as `((?!e)[\p{L}\p{M}\p{N}_])-"` with replacement `$1 -"` covers letters, combining marks, numbers, and underscore while retaining the exclusion of `e`. The replacement capture itself is working as designed, so this does not appear to be a VS Code defect.
