## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/282004 is open and predates this report. Its body explicitly clarifies Backspace, describes accidentally confirming the multi-file undo dialog while editing Chat input, and requests removing or hardening that destructive shortcut.
- **Current source:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts: ChatEditingDiscardAllAction still binds CtrlCmd+Backspace when Chat input is focused, empty, and has undecided edits. Its runEditingSessionAction calls discardAllEditsWithConfirmation, which invokes confirmation and then editingSession.reject().
- **Confirmed impact and workaround:** The supplied discussion on https://github.com/microsoft/vscode/issues/306770 includes an independent report of lost progress and a workaround removing the chatEditing.discardAllFiles binding from Ctrl+Backspace and assigning Ctrl+Shift+Backspace. This mitigates the trigger but does not change the default behavior.
- **Related reports:** https://github.com/microsoft/vscode/issues/317320 is a newer open report of the same empty-input trigger. https://github.com/microsoft/vscode/issues/280443 is closed; its maintainer comment retained the shortcut because other reports had not yet arrived, so it is not an open duplicate target or evidence of a fix.
