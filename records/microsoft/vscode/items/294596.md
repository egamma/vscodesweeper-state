# Issue #294596 — [FR] Allow callStackDown and callStackUp keyboard shortcuts to move through virtual environment

[https://github.com/microsoft/vscode/issues/294596](https://github.com/microsoft/vscode/issues/294596)

## Summary

The requested keyboard-navigation capability remains missing: the current commands deliberately skip deemphasized frames, independently of whether those frames can be selected in the Call Stack view. Keep this open for a debug-owner decision on navigation semantics; no verified open canonical was found.

## Change summary

Allow Navigate Up/Down Call Stack to visit selectable library frames when debugging Python with justMyCode disabled.

## Best solution

Provide a supported way for call-stack navigation commands to include selectable library frames without changing debug execution or adapter stepping behavior. Decide whether this changes the existing commands' default behavior or is an opt-in navigation mode.

- **Behavior:**

  > With Python justMyCode:false, library frames can be selected in the Call Stack view but are skipped by workbench.action.debug.callStackUp and workbench.action.debug.callStackDown. The goal is a supported keyboard-navigation path through those selectable frames. Acceptance must cover both directions, consecutive library frames, and wraparound without executing or stepping the debuggee. Whether inclusion becomes the default or requires explicit opt-in remains a product decision.
- **Trace:**

  > Both commands in src/vs/workbench/contrib/debug/browser/debugCommands.ts call navigateCallStack, which delegates selection to findNextVisibleFrame. That helper intentionally rejects every isFrameDeemphasized frame; the predicate in src/vs/workbench/contrib/debug/common/debug.ts recognizes 'deemphasize' and 'subtle' presentation hints. Mouse opening in src/vs/workbench/contrib/debug/browser/callStackView.ts instead focuses the selected StackFrame directly, and that view separately groups deemphasized frames. The source therefore establishes the keyboard/mouse policy difference, although the adapter hints in the reporter's live session were not captured. Preserve adapter stepping behavior, automatic stop-time frame selection, and existing paging behavior outside the agreed navigation scope. The ownership explanation is at https://github.com/microsoft/vscode-python-debugger/issues/952#issuecomment-3880039130; src/vs/workbench/contrib/debug/test/browser/callStack.test.ts provides existing stack-model fixtures.
- **Open decisions:**
  - Should the existing Navigate Up/Down Call Stack commands include selectable deemphasized frames by default, or should users explicitly opt into that behavior?
