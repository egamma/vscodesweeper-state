# Issue #335143 — Claude models missing from Agents window model picker in 1.136 (regression from 1.135)

[https://github.com/microsoft/vscode/issues/335143](https://github.com/microsoft/vscode/issues/335143)

## Summary

Real 1.136 regression, but it looks like one symptom within an already-active cluster of Claude/Agents-window model-availability bugs (SDK download deadlock, native-account gate rejecting keychain logins) rather than a distinct, fully diagnosed defect — I can't pin the exact root cause from the report alone, so routing rather than closing or claiming a specific duplicate.

## Change summary

In VS Code 1.136, the Agents window Claude model picker shows no models and 'Manage Language Model Access' no longer lists an Anthropic provider at all, for a user authenticated via Anthropic subscription OAuth; downgrading to 1.135 restores it immediately.

## Best solution

This likely shares a root cause with https://github.com/microsoft/vscode/issues/334405 (SDK-download deadlock: the pinned agent-SDK version changed in 1.136 and the only trigger to download it is a session that can't start because there are no models yet) and/or https://github.com/microsoft/vscode/issues/333738 (native account gate not recognizing certain first-party/subscription logins). A maintainer should correlate agenthost.log from this reporter against those two writeups to confirm which applies, then treat this as a duplicate of whichever one matches, or as its own fix if neither explains the missing provider entry in 'Manage Language Model Access'.

## Evidence

- **candidate root cause 1:** https://github.com/microsoft/vscode/issues/334405 is an open, team-assigned (TylerLeonhardt) issue with a detailed trace showing 1.136 pinned a new agent-SDK version, the exact-match cache lookup misses the old cached version, and the only download trigger (ensureAvailable via a started session, or a Command-Palette-invisible command) can never fire when signed in — producing Count: 0 models and a greyed-out Claude entry, exactly matching this report's 'No models available' symptom and the 1.135 downgrade workaround.
- **candidate root cause 2:** https://github.com/microsoft/vscode/issues/333738 (open, same assignee) traces isClaudeAccountSetUp rejecting a valid claude.ai subscription/keychain login because the gate only checks tokenSource/apiKeySource/apiProvider, never loggedIn/authMethod/subscriptionType — this reporter is also on an Anthropic subscription via OAuth, which is the exact population that gate excludes.
- **corroborating report:** https://github.com/microsoft/vscode/issues/334077 has multiple independent 1.136/1.137 confirmations of the same 'No models available' symptom, with a community workaround of manually placing the pinned SDK version + a `.complete` sentinel file in the sdk-cache directory, consistent with the download-deadlock theory.
- **distinguishing detail:** This report additionally states 'Manage Language Model Access' shows no Anthropic/Claude provider entry at all (not just zero models under an existing entry), which isn't explicitly addressed in either candidate writeup, so I can't confirm this is the identical defect rather than a related but separate provider-registration gap.
