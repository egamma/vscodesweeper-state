# Issue #242271 — [multi-diff-editor] Scroll up down in multiDiffEditor using the keyboard only

[https://github.com/microsoft/vscode/issues/242271](https://github.com/microsoft/vscode/issues/242271)

## Summary

Keep open: existing change-navigation shortcuts do not fully cover keyboard-only scrolling through long multi-file diffs. The maintainer's commands/keybindings collection includes this request, but does not establish that another issue owns its specific scrolling behavior.

## Change summary

Enable keyboard-only vertical scrolling through the multi-diff editor when reading long commit changes.

## Best solution

Provide keyboard control of the complete multi-diff viewport, including movement within long files and across file boundaries, without requiring jumps between change hunks. Coordinate the command and keybinding contract with https://github.com/microsoft/vscode/issues/282733 while preserving existing editor navigation.

- **Behavior:**

  > A user can read a long commit in the multi-diff editor by scrolling vertically using only the keyboard. Movement must support reading within long files and continuing across file boundaries, rather than requiring a jump to the next changed hunk. Acceptance should cover both directions, viewport boundaries, and preservation of existing change-navigation shortcuts.
- **Trace:**

  > The workbench command surface is in src/vs/workbench/contrib/multiDiffEditor/browser/actions.ts, which currently registers next/previous-change shortcuts. Embedded diff editor options hide their scrollbars, so their keyboard behavior cannot be assumed to provide complete outer-viewport scrolling.
