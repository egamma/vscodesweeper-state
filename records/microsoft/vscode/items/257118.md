- **Behavior:**

  > Notebook Markdown fences reportedly lose their background when a language is specified and show a disjointed background when it is omitted. Both variants should render a continuous, theme-appropriate code-block surface consistent with Markdown preview. Verify multiline content and blank lines, preserve language syntax highlighting, and leave inline code unaffected. Current-main reproduction is the first acceptance checkpoint.
- **Trace:**

  > The highlight callback in extensions/markdown-language-features/notebook/index.ts emits a div.vscode-code-block for language-tagged fences and escaped text otherwise. Its renderer clones shared default styles into a shadow root and contributes a pre code rule without a background. Language-tagged blocks subsequently receive tokenizer HTML through MarkdownCodeBlock in src/vs/workbench/contrib/notebook/browser/view/renderers/webviewPreloads.ts. By contrast, extensions/markdown-language-features/media/markdown.css places the background on pre and clears it on nested code. The related https://github.com/microsoft/vscode/pull/201748 predates this report and does not establish a fix. Inspection identified the relevant paths but did not establish the complete effective style cascade or reproduce the rendered result; preserve tokenization, inline-code styling, and ordinary notebook cell/output backgrounds.
