# Issue #179993 — Deleting a Cloud Change sometimes doesn't remove Tree Item completely and keeps around a GUID

[https://github.com/microsoft/vscode/issues/179993](https://github.com/microsoft/vscode/issues/179993)

## Summary

Still present on main: the delete-then-refresh sequence in editSessionsViews.ts has no optimistic removal of the deleted item from the tree, so eventual-consistency lag from the storage service can leave a raw GUID visible. No fix commit references this issue.

## Change summary

Deleting a Cloud Change (edit session) one-by-one sometimes leaves a GUID label in the tree instead of fully removing the item.

## Best solution

Add optimistic UI removal in the delete action (filter the deleted ref out of the data provider's local state before refreshing), or ensure `treeView.refresh()` only renders items whose data successfully resolves — the guard at line 209 skips null `sessionData`, but a race where `list()` still returns the ref while `read()` returns stale content would show the raw ref as a label.
