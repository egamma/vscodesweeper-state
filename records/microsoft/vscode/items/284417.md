# Issue #284417 — Copilot attempts writing files in windows format on linux remote host via ssh

[https://github.com/microsoft/vscode/issues/284417](https://github.com/microsoft/vscode/issues/284417)

## Summary

Verified duplicate of the older open issue https://github.com/microsoft/vscode/issues/280816: both report Copilot file tools rejecting remote Linux workspace paths while terminal operations work when `remote.extensionKind` forces Copilot onto the Windows UI side.

## Change summary

Make Copilot file tools handle Remote-SSH and Remote-WSL workspace paths when Copilot is forced to run in the local UI extension host.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/280816. Given the maintainer-confirmed requirement that Copilot run alongside the workspace filesystem, the practical end state is to detect this unsupported UI-side remote configuration and explain that file tools require workspace-side execution rather than emitting misleading path and permission errors.
