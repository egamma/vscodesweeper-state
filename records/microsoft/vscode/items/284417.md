# Issue #284417 — Copilot attempts writing files in windows format on linux remote host via ssh

[https://github.com/microsoft/vscode/issues/284417](https://github.com/microsoft/vscode/issues/284417)

## Summary

Still reproducible on main: `PromptPathRepresentationService.getFilePath()` calls `uri.fsPath` for `vscode-remote` URIs, which applies Windows backslash conversion when the UI runs on Windows — breaking all Copilot file tools in Remote-SSH to Linux. Four fix PRs were opened and all closed without merging; the bug remains.

## Change summary

Copilot agent file tools (read, write, create) fail silently in Remote-SSH workspaces from Windows to Linux because remote paths are converted to Windows backslash format.

## Best solution

Fix `PromptPathRepresentationService.getFilePath()` in `extensions/copilot/src/platform/prompts/common/promptPathRepresentationService.ts` to use `uri.path` instead of `uri.fsPath` when the URI scheme is `vscode-remote`, avoiding the OS-native backslash conversion. The same fix should be applied to the relative-path branch (line 57). `resolveFilePath` may also need adjustment to reconstruct remote URIs correctly.
