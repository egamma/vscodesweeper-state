# Issue #130122 — Line numbers are not restored if active window when exiting Zen mode is not a file.

[https://github.com/microsoft/vscode/issues/130122](https://github.com/microsoft/vscode/issues/130122)

## Summary

The confirmed Zen Mode restoration bug remains present on current main: exiting while a non-file editor is active restores line numbers only on currently visible text editor controls, leaving the previously visible file editor configured with line numbers off.

## Change summary

Restore a file editor's configured line-number display after exiting Zen Mode while a non-file editor is active.

## Best solution

Restore each affected editor's resource- and language-scoped line-number configuration when it becomes visible after Zen Mode exits, without retaining editor-control instances beyond their lifecycle.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`
- **Validation:** Launch Code OSS with `zenMode.hideLineNumbers` enabled, open a file with line numbers visible, enter Zen Mode, open Preferences: Open User Settings, exit Zen Mode, return to the file, and verify its configured line-number mode is restored; repeat with resource- or language-specific `editor.lineNumbers` overrides.
- **Behavior:**

  > Entering Zen Mode may hide line numbers according to `zenMode.hideLineNumbers`. After leaving Zen Mode, every file editor affected by that temporary override must return to its own resource- and language-scoped `editor.lineNumbers` value, even when a Settings or other non-file editor was active at exit. Editors opened or closed during the transition must not retain stale overrides or cause lifecycle errors.
- **Trace:**

  > The relevant path is Layout.toggleZenMode in src/vs/workbench/browser/layout.ts. While entering Zen Mode, `setLineNumbers('off')` updates `mainPartEditorService.visibleTextEditorControls` and an onDidVisibleEditorsChange listener applies the override to newly visible editors; exiting clears that listener and calls `setLineNumbers()` only for controls visible at that moment. Commit https://github.com/microsoft/vscode/commit/456651f286857abe79025c3eaefb7ae6f9786d68 removed the earlier set of affected editor controls because retaining those controls outside their lifecycle was considered unsafe, directly creating the reported gap. Preserve resource- and language-specific line-number configuration and do not reintroduce long-lived references to disposed or hidden editor widgets. No open canonical issue owns the same observable symptom.

## Evidence

- **current source:** In src/vs/workbench/browser/layout.ts, Layout.toggleZenMode applies `lineNumbers: 'off'` to visible text editor controls and registers onDidVisibleEditorsChange while Zen Mode is active, but on exit `setLineNumbers()` again visits only `mainPartEditorService.visibleTextEditorControls`. A file editor hidden behind the Settings editor is therefore absent from the restoration pass.
- **known regression:** Commit https://github.com/microsoft/vscode/commit/456651f286857abe79025c3eaefb7ae6f9786d68 deliberately removed the set of affected editor controls and changed restoration to visible controls only. Its discussion at https://github.com/microsoft/vscode/issues/119308#issuecomment-809328116 explicitly anticipated corner cases where line numbers would not be restored.
