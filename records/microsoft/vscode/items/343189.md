# Issue #343189 — Main process policy watchers permanently hold 2 of 4 libuv threads on macOS. Slow open() stalls file access in all windows

[https://github.com/microsoft/vscode/issues/343189](https://github.com/microsoft/vscode/issues/343189)

## Summary

Keep open for the assigned 1.145.0 milestone. A maintainer confirmed the thread-pool starvation and identified the native policy-watcher dependency as the fix location; increasing the global pool is explicitly not the accepted solution.

## Change summary

Prevent long-lived macOS policy watchers from occupying libuv workers and amplifying slow filesystem operations into cross-window file-access stalls.

## Best solution

Remove lifetime-long libuv worker occupation in the native policy-watcher module while preserving policy change delivery and disposal, then adopt the corrected dependency in VS Code. Validate the reduced-thread-pool startup reproduction and separately check responsiveness during slow extension-manifest reads; freeing watcher threads alone does not guarantee isolation from a saturated filesystem queue.
