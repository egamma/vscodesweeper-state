# Issue #337256 — Perf: Agent Host per-request diff observable re-parses every historical turn on every streamed token in a long chat

[https://github.com/microsoft/vscode/issues/337256](https://github.com/microsoft/vscode/issues/337256)

## Summary

Confirmed on current main: `_createDiffsObservable` unconditionally reads `responseFileEditsObs.read(reader)` before the changeset/branch-fallback early returns, so every historical request's file-edit observable stays wired to the live chat state and re-parses `responseParts` on every streamed token of the active turn, with no memoization. This is a real, precisely-diagnosed perf bug that should stay open for a fix.

## Change summary

In a long Agent Host chat, the per-request file-changes diff observable re-subscribes to the whole chat's live streaming state and re-parses every historical turn's response into diffs on every streamed token of the active turn, causing sustained renderer CPU spikes.

## Best solution

Memoize `_createFileEditDiffsObservable`'s result keyed on the resolved, reference-stable `turn` object (turns are only ever appended, never mutated, per the chat reducer's `endTurn`), and replace the per-request O(N) `chatState.turns.find` with one shared `Map<requestId, Turn>` built once per `ChatState` change, so settled historical requests short-circuit instead of re-parsing on every token.
