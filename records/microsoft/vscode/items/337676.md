# Issue #337676 — Setting or memory for the default agent harness in the main window (Welcome page / chat panel always start on Copilot)

[https://github.com/microsoft/vscode/issues/337676](https://github.com/microsoft/vscode/issues/337676)

## Summary

Well-diagnosed, accurate feature request: the main window has no equivalent to the Agents window's remembered last-used harness, and `chat.defaultToCopilotHarness` only toggles local vs. SDK harness, not which agent (Copilot/Claude/Codex) starts by default — but two viable designs differ in persistence semantics, so this needs a maintainer decision before implementation.

## Change summary

Let users choose or persist which agent harness (Copilot/Claude/Codex) new chats start with in the main window, mirroring the Agents window's remembered last-used session type.

## Best solution

A maintainer should pick a design: either a `chat.defaultHarness` setting, or extending the main window's chat widget to remember the last-used harness the way `sessions.quickChat.lastUsedSessionType` does for Agents window quick chats.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/constants.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/sessions/services/sessions/browser/sessionsManagementService.ts`
- **Validation:** A chat contribution test asserting that a new chat in the main window opens with the configured/remembered harness instead of always defaulting to Copilot.
- **Behavior:**

  > New chats opened from the Welcome page, chat panel, or chat editor in the main window should start with a user-chosen or previously-used agent harness (Copilot, Claude, Codex, etc.) instead of always defaulting to the local Copilot harness. Switching harness via the Local picker should persist across windows/restarts, or be settable explicitly via configuration. Acceptance: opening a new chat after selecting a non-Copilot harness (or setting the new option) starts on that harness in a new window/session.
- **Trace:**

  > `chat.defaultToCopilotHarness` (src/vs/workbench/contrib/chat/common/constants.ts:139) only distinguishes local-vs-SDK Copilot harness selection, and `chat.defaultModel` (constants.ts:127) only affects model choice — neither persists a chosen non-Copilot harness for the main window. The Agents window already solves the analogous problem via `sessions.quickChat.lastUsedSessionType` (src/vs/sessions/services/sessions/browser/sessionsManagementService.ts:37), which the main window's chat widget init path does not consult. The boundary is main-window new-chat harness initialization; do not touch the Agents window's existing quick-chat memory mechanism. Where the uncertainty starts: whether to add an explicit `chat.defaultHarness`-style setting or mirror the Agents window's storage-based 'last used' memory, and how the two interact if both exist.
- **Open decisions:**
  - Should the main window get an explicit `chat.defaultHarness` setting, remembered last-used state (like the Agents window), or both?
  - If both, which takes precedence — explicit setting override vs. remembered last-used harness?
  - Does this only apply to genuinely new chats, or also to restored/continued chat sessions?

## Evidence

- **existing setting is narrower:** `ChatConfiguration.DefaultToCopilotHarness = 'chat.defaultToCopilotHarness'` in src/vs/workbench/contrib/chat/common/constants.ts:139 only toggles between the local Copilot harness and the Copilot SDK agent host harness; it has no notion of Claude/Codex as a default.
- **defaultModel picks a model, not harness:** `ChatConfiguration.DefaultModel = 'chat.defaultModel'` in constants.ts:127 is a model-picker default, confirming the reporter's claim it does not control which harness starts.
- **Agents window has the analogous memory, main window doesn't:** `LAST_USED_QUICK_CHAT_SESSION_TYPE_STORAGE_KEY = 'sessions.quickChat.lastUsedSessionType'` in src/vs/sessions/services/sessions/browser/sessionsManagementService.ts:37 remembers the last-used harness for Agents window quick chats; no equivalent lookup exists for the main window Welcome page/chat panel/chat editor.
