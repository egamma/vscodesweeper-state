# Issue #92176 — API to collapse custom tree items

[https://github.com/microsoft/vscode/issues/92176](https://github.com/microsoft/vscode/issues/92176)

## Summary

Keep open: extensions still lack an API to collapse a specified tree item; the existing focused-item command only partially covers the request. This is also an api-proposal tracking issue, whose closure belongs to the API owners.

## Change summary

Expose an extension API for collapsing a specific custom tree item, complementing TreeView.reveal expansion.

## Best solution

Provide an API-owner-approved way to collapse an extension-specified tree item without requiring it to be focused. Preserve this issue as the API tracking record through finalization; focused-tree commands and checkbox-driven auto-collapse do not replace that contract.

## Evidence

- **Current API gap:** src/vscode-dts/vscode.d.ts:12144-12230 exposes onDidCollapseElement and reveal(element, options), but no method to collapse a specified element. src/vscode-dts/vscode.proposed.treeViewReveal.d.ts extends reveal to accept undefined, not to collapse nodes.
- **Expansion is not collapse:** src/vs/workbench/api/browser/mainThreadTreeViews.ts:161-203 maps reveal's expand:false to zero expansion iterations; it does not collapse an already-expanded item. The path expands ancestors and optionally the target, confirming that reveal is not the requested counterpart.
- **Existing command is partial coverage:** src/vs/workbench/browser/actions/listCommands.ts:411-429 implements list.collapseAllToFocus using lastFocusedList and getFocus(), then recursively collapses focus[0]. It does not accept an extension-selected item. https://github.com/microsoft/vscode/issues/157410 is the closed command-only request that the reporter explicitly split from this API request.
- **Maintainer consolidation:** https://github.com/microsoft/vscode/issues/78970 is closed as a duplicate of this issue, confirmed by https://github.com/microsoft/vscode/issues/78970#issuecomment-723932611. The supplied discussion explicitly favors a collapse API over honoring refreshed collapsibleState changes.
- **Canonical search:** An open-issue search for collapse/API/tree found no verified canonical owning this request. https://github.com/microsoft/vscode/issues/88219 is older and open, but explicitly requests collapsing the view container section, not items inside it, so it is not the same observable behavior.
- **Related implementation remains open:** https://github.com/microsoft/vscode/pull/282197 is open and unmerged. It references this issue while proposing checkbox-driven folder auto-collapse, not a general TreeView collapse API; it neither completes this request nor warrants a competing agent implementation.
- **Recent related request:** https://github.com/microsoft/vscode/issues/324498 describes the collapse counterpart as still missing and requests manually managed collapsibleState. It was closed by the community upvote process, not because this API was implemented or declined.
- **Protected API tracking:** https://github.com/microsoft/vscode/issues/92176 carries api-proposal. Under the review policy, API tracking issues remain open until the API owners finalize or explicitly abandon the proposal; age and the Backlog milestone do not justify closure.
