## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts`
- **Validation:** Capture a new performance recording of a Chat panel resize with expanded terminal output on current main/insiders and confirm UI-thread busy time / forced-reflow time is reduced versus the original 8.35s/99%-busy recording in the issue.
- **Behavior:**

  > Dragging the Chat panel divider while a terminal-output preview is expanded should stay smooth: the UI thread should not be pegged near 100% for the duration of the drag, and individual frame updates should not block input for hundreds of milliseconds. This is a continuation of prior work (PR #336345) that improved but did not fully fix the jank.
- **Trace:**

  > The terminal-output resize path lives in chatTerminalToolProgressPart.ts: _handleResize -> _layoutMirrorWidth (re-measures/relays out the detached terminal mirror) -> _layoutOutput (sets scrollable container height from row count) -> _scrollOutputToBottom, with _scheduleOutputRelayout batching via requestAnimationFrame. The current code already avoids some of the original clientHeight-based double-measurement (per the comment above _layoutOutput), which is consistent with PR #336345 having landed — but the reporter (lramos15) says lag remains, so either mirror.layout() itself (in DetachedTerminalCommandMirror) is still expensive per-frame, or another code path (e.g. the mirror's row-height-change handler at _handleMirrorRowHeightChange) is re-triggering measurement work during the same resize. The boundary: don't restructure the chat content-part rendering pipeline or non-terminal chat parts; scope to the terminal-output preview's resize/measurement path.
- **Open decisions:**
  - Is the remaining lag isolated to the terminal-output mirror's own layout cost (e.g. xterm's DOM measurement), or is it a second redundant measurement pass firing alongside the already-batched _layoutOutput — this determines whether the fix is throttling/coalescing further or optimizing the underlying terminal layout call itself.
