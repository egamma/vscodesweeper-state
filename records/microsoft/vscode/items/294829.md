# Issue #294829 — If the whole file is a single diff hunk, there should only be one keep/undo UI

[https://github.com/microsoft/vscode/issues/294829](https://github.com/microsoft/vscode/issues/294829)

## Summary

Keep open: current source independently renders hunk-level and file-level Keep/Undo controls without consolidating them when one hunk covers the entire file. Related reports do not establish an older canonical with the same symptom, and this team-authored item has no verified fixing commit.

## Change summary

Show only one Keep/Undo action pair when an agent-generated change consists of a single whole-file diff hunk.

## Best solution

Present one clearly scoped Keep/Undo pair for whole-file single-hunk review while preserving change navigation and multi-hunk review. Settle which existing review surface remains visible before implementing the consolidation.

Repeat with an existing file replaced by one whole-file hunk, then with multiple separated hunks; verify Keep and Undo affect the intended scope and navigation remains available.
- **Behavior:**

  > When an agent's pending edit is one diff hunk covering an entire file, the editor should display only one Keep/Undo pair rather than competing hunk-level and file-level pairs. Cover both newly created files and whole-file replacements. Keeping or undoing must retain its intended file scope, and multi-hunk review and change navigation must remain available.
- **Trace:**

  > ChatEditingCodeEditorIntegration._updateDiffRendering in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts creates a DiffHunkWidget for every change in review or diff mode, and the active hunk becomes visible when the cursor enters its range. Independently, src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorOverlay.ts shows ChatEditorOverlayWidget for Modified entries in global editing sessions and constructs its file-level toolbar. Neither path consolidates controls for a whole-file single hunk. chatEditingEditorActions.ts distinguishes file acceptance/rejection from nearest-hunk acceptance/rejection, so preserving action scope and navigation is essential. The remaining uncertainty is which visible action surface should represent the consolidated review; do not broaden this into globally hiding bulk actions or changing multi-hunk behavior. Related https://github.com/microsoft/vscode/issues/291072 concerns overlap, while https://github.com/microsoft/vscode/issues/337224 requests a separate persistent preference.
- **Open decisions:**
  - For a whole-file single hunk, should the sole Keep/Undo pair remain beside the hunk or in the file-level editor overlay, with navigation and other review controls preserved?
