# Issue #307542 — `github.copilot.chat.searchSubagent.model` rejects display names shown in the model picker with no validation or guidance

[https://github.com/microsoft/vscode/issues/307542](https://github.com/microsoft/vscode/issues/307542)

## Summary

The validation and guidance gap remains on current main: the setting accepts any string, while endpoint resolution expects an internal model ID rather than the display value users see. Runtime fallback now prevents the original hard failure, but an invalid value is still silently ignored without settings validation or actionable guidance.

## Change summary

Make the search-subagent model override accept or clearly expose valid model values instead of silently rejecting model-picker display names.

## Best solution

Use the same dynamically populated model-selection convention as the core Explore/Plan agent settings, restricted to tool-capable models, or explicitly define and validate a stable model-identifier format. The chosen value must resolve predictably, and invalid persisted values must be visible to the user rather than silently falling back.

## Evidence

- **unconstrained setting:** extensions/copilot/package.json declares `github.copilot.chat.searchSubagent.model` as a free-form string with no enum or validation, while extensions/copilot/package.nls.json describes it only as the model to use and does not document the required internal ID format.
- **source reproduction:** extensions/copilot/src/extension/prompt/node/searchSubagentToolCallingLoop.ts resolves configured values with `allEndpoints.find(e => e.model === modelName)` and then family lookup; it does not resolve the user-visible endpoint name or qualified picker label.
- **silent fallback:** The same `resolveEndpoint` path catches an unavailable configured model and falls back to the main-agent endpoint with only a log warning. The unit test in extensions/copilot/src/extension/prompt/test/node/searchSubagentToolCallingLoop.spec.ts explicitly verifies this fallback for `does-not-exist`, so the tool no longer necessarily fails but the invalid setting remains undisclosed to the user.
- **existing picker pattern:** src/vs/workbench/contrib/chat/browser/defaultModelContribution.ts dynamically populates configuration enums with stored identifiers, display labels, and descriptions; `chat.exploreAgent.defaultModel` already consumes this mechanism for tool-capable models.
