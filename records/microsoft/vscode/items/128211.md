# Issue #128211 — SCM - Support markdown tooltip in scm command contributions

[https://github.com/microsoft/vscode/issues/128211](https://github.com/microsoft/vscode/issues/128211)

## Summary

SCM command tooltips remain string-only on current main; ordinary status bar Markdown support does not satisfy this request. Keep this team-authored Backlog item open for an API decision about tooltips shared between the status bar and SCM toolbars.

## Change summary

Allow SCM command contributions to provide Markdown tooltips, as ordinary status bar items already can.

## Best solution

Provide a supported SCM API for rich status bar tooltips while retaining appropriate plain-text tooltips and accessible labels for toolbar representations. Settle the shared-versus-surface-specific tooltip contract before implementation; separating the command collections entirely is related but not necessary to assume here.

- **Behavior:**

  > SCM extensions should be able to provide formatted tooltip content for their contributed status bar commands, rather than being restricted to strings. Existing string-based contributions must remain compatible, and invoking a command must retain its current behavior. The same command's SCM toolbar representation and accessible label must remain readable without displaying raw Markdown or an object representation. Acceptance should cover both presentation surfaces using the API contract chosen by the maintainer.
- **Trace:**

  > SourceControl.statusBarCommands in src/vscode-dts/vscode.d.ts uses the shared Command interface, whose tooltip remains string-only. ExtHostSCM forwards these commands through CommandsConverter.toInternal in src/vs/workbench/api/common/extHostCommands.ts; that converter copies tooltip directly into ICommandDto. The SCM status bar path in src/vs/workbench/contrib/scm/browser/activity.ts interpolates the tooltip into a string used for both hover content and ariaLabel. RepositoryRenderer in src/vs/workbench/contrib/scm/browser/scmRepositoryRenderer.ts also consumes the same collection through StatusBarAction in browser/util.ts. Ordinary StatusBarItem already supports MarkdownString, but this does not extend the SCM contract. The unresolved boundary is whether rich tooltip content belongs on shared Command or an SCM-specific contract, and how its toolbar presentation is specified; preserve existing command placement and execution unless explicitly approved otherwise. https://github.com/microsoft/vscode/issues/214187 concerns separating presentation placement and is related, not a duplicate.
- **Open decisions:**
  - Should Markdown tooltip support extend the shared Command API or be exposed through an SCM-specific command contract?
  - Should toolbar tooltips use a plain-text rendering of the rich tooltip, or should providers supply separate plain-text and Markdown tooltip content?
