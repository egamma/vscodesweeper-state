# Issue #136927 — Provide a extension api option to set the word-wrap state of a document upon opening.

[https://github.com/microsoft/vscode/issues/136927](https://github.com/microsoft/vscode/issues/136927)

## Summary

Keep this accepted API request open: current showTextDocument options still cannot specify an initial word-wrap state, and settings or the toggle command do not provide equivalent behavior. The request has 32 upvotes and already reached Backlog; the older related API issue does not establish the same opening-time requirement strongly enough to justify a duplicate close on re-review.

## Change summary

Allow extensions to show a document with an explicitly chosen initial word-wrap state without changing persistent settings or requiring a subsequent toggle.

## Best solution

Provide a supported opening-time wrap override through the editor extension API, leaving existing behavior unchanged when omitted. API owners should settle its scope and lifetime in coordination with the related request for reading and changing wrap state.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTextEditors.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadEditors.ts`, `src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts`
- **Validation:** Use an extension-host test or sample extension to open long-line documents with explicit wrap on and off under opposite editor.wordWrap defaults; verify the first displayed state, preserveFocus behavior, unchanged persistent settings, and unchanged behavior when the option is omitted. Also check reopening and simultaneous views of the same document against the agreed lifetime contract.
- **Behavior:**

  > An extension can show an arbitrary document with wrapping explicitly enabled or disabled from its first display, without requiring the user to press Alt+Z or changing persistent configuration. Omitting the option preserves current behavior. Acceptance covers both opposite configuration defaults and preserveFocus, with no unintended changes to unrelated documents. Reopening and multiple views must follow an explicitly agreed override lifetime.
- **Trace:**

  > TextDocumentShowOptions and TextEditorOptions in src/vscode-dts/vscode.d.ts expose no word-wrap control. ExtHostEditors.showTextDocument serializes opening options through ITextDocumentShowOptions to MainThreadTextEditors.$tryShowTextDocument, and neither side transports a wrap override. The existing ToggleWordWrapAction in src/vs/workbench/contrib/codeEditor/browser/toggleWordWrap.ts stores transient state on the text model, while ToggleWordWrapController applies it through wordWrapOverride2; this establishes a model-scoped behavior that the API design must consider. The toggle is state-dependent, so executing it after opening is not an equivalent explicit initial-state contract. Internal ConfigurationTarget.MEMORY is not exposed through the public configuration enum. Coordinate with https://github.com/microsoft/vscode/issues/92177, but keep this opening-time requirement distinct; preserve existing settings, omitted-option behavior and manual toggle behavior.
- **Open decisions:**
  - Should the opening-time override follow the existing model-scoped Alt+Z behavior across all views of a document, or apply only to the editor view being shown?
  - Should this API cover only initial presentation through TextDocumentShowOptions, or also expose readable and mutable wrap state through TextEditorOptions as requested by the related API issue?
