# Issue #293758 — Shell integration breaks grml-zsh-config by setting ZDOTDIR

[https://github.com/microsoft/vscode/issues/293758](https://github.com/microsoft/vscode/issues/293758)

## Summary

Confirmed still present on main: the ZDOTDIR injection mechanism sets ZDOTDIR to a temp directory before zsh processes system rc files, so grml-zsh-config's `zrclocal()` (which reads `${ZDOTDIR:-$HOME}/.zshrc.local`) looks in the wrong place. The script restores ZDOTDIR before sourcing the user's `.zshrc` (line 29) but not before `/etc/zsh/zshrc` runs.

## Change summary

VS Code's shell integration ZDOTDIR injection causes grml-zsh-config (and similar ZDOTDIR-aware system configs) to skip loading `~/.zshrc.local` user customizations.

## Best solution

The shell integration script should ensure ZDOTDIR is unset or restored to USER_ZDOTDIR before system-level zsh rc files reference it. This likely requires changes to shellIntegration-rc.zsh's injection flow — possibly by creating a `.zshenv` in the temp ZDOTDIR that immediately restores the real ZDOTDIR after injection is triggered, or by symlinking expected user files into the temp directory. The fix is non-trivial given the zsh startup order constraints.
