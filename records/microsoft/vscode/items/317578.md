# Issue #317578 — Delayed Python environment auto-activation can corrupt active terminal input

[https://github.com/microsoft/vscode/issues/317578](https://github.com/microsoft/vscode/issues/317578)

## Summary

Real race condition at the boundary between VS Code's terminal API and the Python extension's delayed activation. The terminal already exposes `isInteractedWith` state, but there's no mechanism to prevent `sendText` from injecting into an active prompt buffer. Routing to terminal area for triage alongside the Python extension owner (already assigned).

## Change summary

The Python extension's delayed virtual environment activation can inject text into the terminal after the user has started typing, corrupting the command line.

## Best solution

VS Code core could provide an API-level guard — e.g., a `sendText` option that checks prompt emptiness via shell integration before injecting, or an event/state the Python extension can query to defer activation safely. The Python extension (microsoft/vscode-python) should also use the existing `terminal.state.isInteractedWith` signal to cancel or defer activation. Both sides likely need changes.
