# Issue #134370 — Git - Merge Conflict - Accept All Incoming/Current - Multiple Repositories

[https://github.com/microsoft/vscode/issues/134370](https://github.com/microsoft/vscode/issues/134370)

## Summary

Still reproduces on main: the merge-conflict extension's 'Accept All' commands operate only on the active editor's document and have no multi-repository awareness — no repo quick pick is shown, so the command silently does nothing when the active editor isn't in the conflicting repo. No fix has landed.

## Change summary

In a multi-repo workspace, 'Merge Conflict: Accept All Incoming/Current' from the command palette silently does nothing because the command lacks repository disambiguation.

## Best solution

Add a repository quick pick (consistent with how the built-in Git extension handles multi-repo commands) when the workspace contains multiple repositories, so the merge-conflict commands know which repo to operate on. The fix lives in `extensions/merge-conflict/src/commandHandler.ts`, specifically in the `registerTextEditorCommand` wrapper and the `acceptAll`/`acceptAllResources` methods.

  > In `extensions/merge-conflict/src/commandHandler.ts`, the `registerTextEditorCommand` wrapper (lines 43-50) falls back to `vscode.window.activeTextEditor` when invoked from the command palette (no resource URIs). In a multi-repo workspace, this means the command silently does nothing if the active editor isn't in the repo with merge conflicts. The fix should add repository disambiguation when the command is invoked without resource context: detect available repositories (via the Git extension API or workspace folders), and if multiple exist, show a `vscode.window.showQuickPick` to let the user select which repo to operate on — this is the established pattern used by the built-in Git extension for multi-repo commands (see `src/vs/workbench/contrib/scm/` for examples). The `acceptAll` method (line 258) should then scan the selected repo's conflicting files rather than only the active editor's document.
