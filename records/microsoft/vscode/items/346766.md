# Issue #346766 — Full screen loses the mouse cursor

[https://github.com/microsoft/vscode/issues/346766](https://github.com/microsoft/vscode/issues/346766)

## Summary

Keep open: another reporter confirms the invisible-but-functional pointer on 1.146.0 and reports that disabling hardware acceleration restores it. This supports investigating native-window/GPU rendering, but does not establish an upstream root cause or a completed fix.

## Change summary

The mouse pointer stops visibly tracking movement in full-screen mode on a Windows 4K display while mouse input continues working.

## Best solution

Restore visible pointer movement with hardware acceleration enabled. Investigate the Windows native-window and GPU path, first distinguishing F11 fullscreen from maximization because the reported title-bar double-click normally toggles maximization.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/mainImpl.ts`
- **Validation:** On an affected Windows 4K setup, test F11 fullscreen and title-bar maximization separately with hardware acceleration enabled, move the pointer across the window, and verify visible movement remains aligned with functional clicks. Compare after restarting with hardware acceleration disabled; the final fix must retain correct pointer rendering with acceleration enabled.
- **Behavior:**

  > On Windows with a 4K display, entering the reported full-screen state leaves mouse input functional but freezes or hides its visible pointer. Leaving that state restores visible movement, and another reporter confirms a hardware-acceleration workaround. The expected result is continuous visible pointer tracking with hardware acceleration enabled. Acceptance must cover both native fullscreen and maximization, without treating disabling acceleration as the completed fix.
- **Trace:**

  > In src/vs/platform/windows/electron-main/windowImpl.ts, toggleFullScreen() reaches Electron setFullScreen(), whereas handleTitleDoubleClick() toggles maximize()/unmaximize(). The report's exit gesture therefore leaves the exact native-window state uncertain. In src/mainImpl.ts, the reported argv.json flag invokes Electron app.disableHardwareAcceleration(), supporting investigation of the GPU/native presentation boundary. Confirmation comes from the issue discussion, not execution on the Linux checkout. The uncertainty starts at attribution among VS Code window handling, Electron/Chromium, Windows, and graphics drivers; no source-local defect or fixing commit was established. Preserve normal mouse input and existing fullscreen/maximization semantics. Reference: https://github.com/microsoft/vscode/issues/346766.
