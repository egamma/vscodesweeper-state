# Issue #331781 — Issue in `Sync setting`

[https://github.com/microsoft/vscode/issues/331781](https://github.com/microsoft/vscode/issues/331781)

## Summary

Keep open: multiple users confirmed repeated Settings Sync sign-in prompts, and the supplied Microsoft Authentication logs match a diagnosed MSAL refresh-token persistence defect that remains open upstream. No landed fix or verified older canonical covers this report.

## Change summary

Settings Sync requests authentication repeatedly after successful browser sign-in instead of retaining a usable Microsoft session.

## Best solution

Fix rejected refresh-token invalidation in MSAL's persistent cache, then adopt the corrected dependency in the built-in Microsoft Authentication extension. Preserve this report's cross-platform confirmations; transient network-failure recovery is separate work.

## Evidence

- **Confirmed symptom and authentication error:** https://github.com/microsoft/vscode/issues/331781#issuecomment-5492693168 confirms repeated sign-in prompts on Windows 1.135.0, alongside the original macOS 1.134.0 report. With the native broker disabled, scoped session lookups repeatedly reject the same May-issued refresh token with invalid_grant / bad_token / AADSTS700082 and return zero sessions.
- **Workaround confirmation:** The discussion links https://github.com/microsoft/vscode/issues/332126, and https://github.com/microsoft/vscode/issues/331781#issuecomment-5502673389 confirms that its cache-clearing workaround restored session lookup across a relaunch. This is evidence of the failure, not a shipped product fix.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode/issues/332126#issuecomment-5737544474 identifies repeated dead-token reuse as an MSAL persistence defect, corrects the earlier legacy-cache interpretation, and warns against clearing shared Windows TokenBroker state. https://github.com/microsoft/vscode/issues/335639#issuecomment-5735946272 reports independent reproduction in MSAL Node 5.4.0 and 6.0.1 without VS Code or a native broker.
- **Unresolved upstream defect:** https://github.com/AzureAD/microsoft-authentication-library-for-js/issues/8849 is open. Its reduced reproduction shows MSAL removing a rejected refresh token from memory without notifying the persistence plugin, allowing subsequent silent requests to reload and resubmit it.
