## Change summary

- **Behavior:**

  > An HTTP MCP App returning viewer data in CallToolResult._meta must receive that data unchanged in Copilot Agent Host sessions, as it does in Local sessions. The same payload must survive reopening and restarting the session. Absent metadata remains absent, and empty objects and metadata-only results remain distinguishable. Viewer metadata must not become model-facing content.
- **Trace:**

  > The reporter captured metadata at the HTTP server boundary but not immediately before app delivery. Current source already implements optional resultMetadata propagation in both Copilot completion producers and toMcpCallToolResult, matching merged https://github.com/microsoft/vscode/pull/344856. getSdkMcpResultMeta in mapSessionEvents.ts reads runtime result.mcpResultMeta, and that PR documents a prerequisite runtime change and validation with a local runtime build. The uncertainty starts at whether the pinned SDK/runtime emits that field for the reporter's HTTP MCP App call. Trace that boundary before treating this as another adapter omission. Preserve host-owned tool-call metadata and existing Local behavior; the structuredContent model-context concern is separate.
