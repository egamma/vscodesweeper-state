# Issue #324984 — Feature Request: Chat conversation outline & turn navigation (like Ophel Atlas)

[https://github.com/microsoft/vscode/issues/324984](https://github.com/microsoft/vscode/issues/324984)

## Summary

Current main now provides request-to-request navigation and a chat-editor outline, but the broader request remains partly unresolved: Agent/Edit auto-scroll is still hardcoded, the outline is limited to chat editors, and there is no response-specific navigation. Route this to the chat area for a product decision on those remaining gaps.

## Change summary

Provide controllable Agent/Edit auto-scroll, turn-level navigation, and an outline for long Copilot Chat conversations.

## Best solution

Retain the shipped prompt-navigation and chat-editor outline capabilities, then decide whether auto-scroll should become user-configurable, whether the outline should also cover the Chat view pane, and whether separate response navigation adds value beyond request-pair navigation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts`, `src/vs/workbench/contrib/chat/browser/chatOutlineCreator.ts`, `src/vs/workbench/contrib/chat/browser/chatOutline.ts`
- **Validation:** Add targeted chat tests proving the chosen auto-scroll policy controls scroll lock for Ask versus Agent/Edit modes, navigation focuses the intended request or response at boundaries, and the outline is available in every host selected by the plan; retain the existing ChatOutline tests.
- **Behavior:**

  > Long Copilot Chat conversations should remain readable while Agent/Edit responses stream and should offer predictable navigation between conversation turns. Existing previous/next user-prompt navigation and chat-editor Outline/Go to Symbol behavior must continue working. The plan must define whether users can configure automatic following, whether outline navigation also appears in the Chat view pane, and whether responses need independently addressable navigation. Accessibility help must describe any new commands or keybindings.
- **Trace:**

  > Current request navigation is implemented by `registerChatPromptNavigationActions` in src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts and is documented in chatAccessibilityHelp.ts. ChatOutline in src/vs/workbench/contrib/chat/browser/chatOutline.ts maps user requests to revealable entries, while ChatOutlineCreator only matches `ChatEditor`, leaving the view-pane surface outside that provider. Agent/Edit auto-scroll remains selected by hardcoded callbacks in chatEditor.ts and chatViewPane.ts and consumed by ChatWidget's scroll-lock and streaming-layout paths. The related https://github.com/microsoft/vscode/issues/300099 concerns collapsing-content scroll jumps and should remain the owner of that narrower behavior; do not fold generic list scrolling or that distinct smooth-scroll defect into this work. The uncertainty begins at the desired public configuration semantics and which chat hosts and turn types should expose navigation.
- **Open decisions:**
  - Should automatic following be configurable in all chat modes, or should the new policy apply only to Agent/Edit while Ask retains its current behavior?
  - Should the conversation outline be available only for chat sessions opened as editors, or also within the Chat view pane?
  - Should navigation expose separate previous/next response commands, or treat each request and its response as one navigable conversation turn?

## Evidence

- **existing turn navigation:** src/vs/workbench/contrib/chat/browser/actions/chatPromptNavigationActions.ts registers `workbench.action.chat.nextUserPrompt` and `workbench.action.chat.previousUserPrompt`, with Ctrl/Cmd+Alt+Down/Up keybindings, and focuses/reveals the selected request. src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts documents both commands.
- **existing outline:** src/vs/workbench/contrib/chat/browser/chatOutline.ts derives one navigable outline entry per user request and reveals/focuses the corresponding chat item. src/vs/workbench/contrib/chat/browser/chatOutlineCreator.ts exposes it through Go to Symbol, the Outline pane, and Breadcrumbs, but `matches` is limited to `ChatEditor`.
- **remaining auto-scroll gap:** src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditor.ts and widgetHosts/viewPane/chatViewPane.ts still pass `autoScroll: mode => mode !== ChatModeKind.Ask`; src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts uses that policy when setting scroll lock and following streamed content. No user-facing preference controls this policy.
- **related issue is narrower:** https://github.com/microsoft/vscode/issues/300099 is open and older, but it specifically tracks downward jumps when temporary thinking content collapses and smooth upward scrolling. It does not own configurable mode-based auto-scroll, conversation outlines, or turn-navigation commands, so it is not a canonical duplicate for this broader report.
