# Issue #66132 — autoclosing markdown preview when closing md file

[https://github.com/microsoft/vscode/issues/66132](https://github.com/microsoft/vscode/issues/66132)

## Summary

Keep open: the split Markdown preview still lacks automatic dismissal when its source closes or the user switches to a non-Markdown file. This accepted, team-authored request has 21 upvotes and remains the destination for related reports; no verified fix or older same-symptom canonical was found.

## Change summary

Automatically dismiss the side-by-side Markdown preview when closing its source or switching away from Markdown so it no longer occupies editor space.

## Best solution

Provide a supported source-following lifecycle for the built-in Markdown side preview, with explicit behavior for switching away, returning, and locked previews. Preserve this issue as the existing consolidation point rather than redirecting it to an extension.

Verify the chosen dismissal/restoration policy and reclamation of a preview-only split; repeat with a locked preview and with unrelated tabs in the preview group, ensuring those tabs remain open.
- **Behavior:**

  > A side-by-side Markdown preview currently remains visible after its source is closed or a non-Markdown file becomes active, leaving less space for unrelated editing. The requested experience releases that space when the preview is no longer relevant. Acceptance must cover source closure, switching away and back, locked previews, and a preview group containing unrelated tabs; unrelated editors must never be closed.
- **Trace:**

  > DynamicMarkdownPreview in extensions/markdown-language-features/src/preview/preview.ts creates an independent webview panel. Its active-editor handler at lines 791–802 follows another Markdown document when unlocked, but does nothing for non-Markdown editors or undefined active editors; it does not subscribe to source-tab closure. MarkdownPreviewManager in extensions/markdown-language-features/src/preview/previewManager.ts manages preview instances and restoration without a source-following dismissal policy. The registered settings and MarkdownPreviewConfiguration in previewConfig.ts contain no automatic-dismissal control. Existing lock semantics and standalone/custom-editor previews must not change accidentally. Maintainer discussion at https://github.com/microsoft/vscode/issues/91401#issuecomment-591708366 supports investigating this experience, but does not settle defaults or restoration. The extension suggested in the thread is a workaround, not a landed core implementation.
- **Open decisions:**
  - Should automatic dismissal become the default for side previews or require explicit opt-in?
  - When switching to a non-Markdown file, should returning to Markdown restore the previous side preview automatically, or should dismissal require reopening it manually?
  - Should locked previews remain independent when their source closes or the user switches away?
