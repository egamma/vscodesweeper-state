# Issue #321157 — Notebook: "Run Cells In Section" (notebook.section.runCells) does nothing when invoked via keybinding

[https://github.com/microsoft/vscode/issues/321157](https://github.com/microsoft/vscode/issues/321157)

## Summary

The older, open issue already explicitly reports that binding notebook.section.runCells to a key does nothing and requests execution of the active cell's enclosing section. It covers the same observable symptom and requested behavior, satisfying the stronger duplicate bar for this re-reviewed item.

## Change summary

Allow notebook.section.runCells to execute the active cell's enclosing section when invoked through a keyboard shortcut without menu context.

## Evidence

- **Verified older open canonical:** https://github.com/microsoft/vscode/issues/209653 is OPEN and was created on 2024-04-05, before this report. Its body explicitly says notebook.section.runCells has no effect when bound to a key and requests detecting the selected cell's enclosing section and executing it.
- **Same observable symptom confirmed in canonical discussion:** https://github.com/microsoft/vscode/issues/209653#issuecomment-2315758509 independently reports that the notebook.section.runCells shortcut does not work. https://github.com/microsoft/vscode/issues/209653#issuecomment-2077865876 clarifies that executing manually selected cells is not equivalent: the command must discover the enclosing section.
- **Current source matches the reported limitation:** src/vs/workbench/contrib/notebook/browser/controller/sectionActions.ts: NotebookRunCellsInSection extends Action2, accepts only outline-entry or notebook-cell context, and returns immediately when neither is supplied. Its run method does not resolve the active editor or cell. This directly explains the no-argument keyboard invocation described in the report.
- **Existing capability does not cover keyboard invocation:** NotebookRunCellsInSection registers outline, sticky-scroll, and cell-title menu entries, but no Command Palette entry or active-cell fallback. src/vs/workbench/contrib/notebook/browser/controller/coreActions.ts contains active-editor fallback handling in NotebookAction and NotebookMultiCellAction, which this action does not inherit. The remaining capability is the same work requested by the canonical, not a separate Jupyter-extension defect.
