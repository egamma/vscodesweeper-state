# Issue #179088 — Make history not remove entries for files that are quickly deleted and then restored

[https://github.com/microsoft/vscode/issues/179088](https://github.com/microsoft/vscode/issues/179088)

## Summary

A real gap remains: current main immediately removes navigation entries on external deletion events, even if the file promptly returns. The suggested duplicate is related but concerns debouncing editor selection events, so it does not clearly absorb this filesystem-specific behavior.

## Change summary

Preserve navigation history when a watched file is briefly reported as deleted and then restored.

## Best solution

In `src/vs/workbench/services/history/browser/historyService.ts`, defer cleanup for external deletion events briefly and verify that the resource remains absent before removing its history entries; explicit internal delete operations should remain immediate.
