# Issue #179088 — Make history not remove entries for files that are quickly deleted and then restored

[https://github.com/microsoft/vscode/issues/179088](https://github.com/microsoft/vscode/issues/179088)

## Summary

Keep open: current history handling still immediately removes navigation entries on watcher deletion events, without checking whether the files return. The suggested related issue concerns debounced editor-selection events, not this report's deletion-triggered loss of Go Back/Go Forward history.

## Change summary

Preserve editor navigation history when files or their containing folders are briefly reported deleted and then restored.

## Best solution

Make workbench history tolerate transient external deletion reports while still eventually removing entries for genuinely missing files. Establish the restoration grace period and permanent-deletion behavior before implementation; avoid conflating this with debouncing editor-selection events.
