[https://github.com/microsoft/vscode/issues/249634](https://github.com/microsoft/vscode/issues/249634)

## Summary

Keep this open and route it to extension management: current telemetry confirms the scan failure across multiple first-party extensions on Windows, with hundreds of affected users and repeated retries. No fixing commit, matching open canonical, or evidence that the failure has stopped was found.

## Change summary

Extension installation or update can leave VS Code unable to read the extension at the location it just attempted to scan, producing repeated ScanningExtension errors.

## Best solution

Determine why the extension location passed to `scanLocalExtension` is absent from the profile scan or cannot be scanned on Windows, then keep the installation/profile state consistent and prevent the observed retry loop while preserving errors for genuinely missing or invalid extension packages.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/node/extensionManagementService.ts`, `src/vs/platform/extensionManagement/common/extensionsScannerService.ts`
- **Validation:** Add a targeted extension-management test reproducing the identified Windows profile/location divergence and asserting that installing or updating the affected extension completes without a ScanningExtension error or repeated retry, while a genuinely absent extension still reports an error.
- **Behavior:**

  > Installing or updating an extension must leave its extracted location readable through the same profile and scanner state used to complete the operation. First-party extensions such as Copilot Chat and GitHub Pull Requests must not enter a repeated `Cannot read the extension from …` failure loop on Windows. A genuinely missing or invalid extension package must continue to produce an explicit failure.
- **Trace:**

  > The telemetry deminifies to `ExtensionManagementService.scanLocalExtension` in `src/vs/platform/extensionManagement/node/extensionManagementService.ts`. With a profile location, that method scans all user extensions and requires a URI-equal location match; without one, it scans the requested directory directly, and either miss produces the reported ScanningExtension error. The install path later scans the extracted location after adding it to the profile, but the available evidence does not yet identify which caller reaches the failing profile-aware path or why its location diverges. The issue records the same failure for Copilot Chat and GitHub Pull Requests on Windows, so investigation must remain in core extension management rather than either extension. Preserve explicit failures for truly absent or malformed packages, and do not fold this into https://github.com/microsoft/vscode/issues/245986 unless diagnosis proves the same physical-deletion root cause.
