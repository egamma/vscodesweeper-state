# Issue #329974 — Image attachments should expose the file path to the agent, not just pixel data

[https://github.com/microsoft/vscode/issues/329974](https://github.com/microsoft/vscode/issues/329974)

## Summary

The gap is real and traceable in source: unlike text-file attachments, local image attachments never surface their file path as textual context to the model — only as a UI citation. This is a reasonable, scoped enhancement request, not yet triaged by a maintainer.

## Change summary

When a local image file is attached to a chat prompt, the agent only receives the pixel data, not the source file path, unlike text-file attachments which include the path as text.

## Best solution

In extensions/copilot/src/extension/prompts/node/panel/image.tsx, the `Image` prompt element already receives a `reference` (URI) for file-backed images but only emits it via a UI-only `<references>` citation, never as text content. Extend `Image` to also emit the resolved file path (via `IPromptPathRepresentationService.getFilePath`, matching FileVariable's pattern) as a small text/attribute chunk in the `UserMessage` when the image originates from a local file (i.e. `reference` is set and it isn't a paste/URL/screenshot) — the existing `isPasted`/`isURL` flags on `IImageVariableEntry`/`ChatReferenceBinaryData` already distinguish this case.

## Evidence

- **converted to a UI-only reference, not text:** src/vs/workbench/api/common/extHostTypeConverters.ts:3649-3657 puts that URI into `ChatReferenceBinaryData.reference`, but extensions/copilot/src/extension/prompts/node/panel/image.tsx:127-132 only wraps it in a `<references>` PromptReference (a UI citation for the 'used references' panel), never as text content inside the `UserMessage` the model reads.
