# Issue #341685 — jsdoc Generics not showing in tooltip

[https://github.com/microsoft/vscode/issues/341685](https://github.com/microsoft/vscode/issues/341685)

## Summary

Thanks for the report. The cause is traceable in the source: the generic JSDoc tag text is appended to the hover markdown without escaping, so `<number>` and `<string>` read as HTML tags and get stripped. An open PR already targets this, so the issue stays open until it merges.

## Change summary

Hover tooltips for a JS variable with `@type {Promise<number> | Promise<string>}` show `Promise | Promise` because the generic arguments are dropped.

## Best solution

Land https://github.com/microsoft/vscode/pull/341735, or an equivalent change. The `@type` tag text should be escaped or rendered as code in the generic-tag path of `getTagDocumentation` in `extensions/typescript-language-features/src/languageFeatures/util/textRendering.ts`.

## Evidence

- **code path:** `getTagDocumentation` in extensions/typescript-language-features/src/languageFeatures/util/textRendering.ts falls through to the generic-tag path for `@type`. It returns the label plus the raw tag text (`getTagBodyText`), which is later rendered as markdown. Angle-bracketed generics such as `<number>` therefore get dropped as HTML.
