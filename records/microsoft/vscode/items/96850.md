# Issue #96850 — Git - "Revert selected ranges" doesn't work for staged chunks

[https://github.com/microsoft/vscode/issues/96850](https://github.com/microsoft/vscode/issues/96850)

## Summary

Keep open: current source scopes Revert Selected Ranges away from the Index diff, but does not provide the staged-change revert workflow accepted by the maintainer. The later unstage regression and its fix concern a different operation.

## Change summary

Allow selected staged changes to be discarded directly from the Index diff without manually unstaging them first.

## Best solution

Provide a staged-range discard operation in the built-in Git extension, preserving unrelated staged and unstaged changes. Agree on how overlapping working-tree edits are handled before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/staging.ts`, `extensions/git/src/repository.ts`, `extensions/git/package.json`
- **Validation:** In a temporary Git repository, commit a file, stage two separated changes, select one in the Index diff, and invoke the agreed discard action. Verify the selected change is removed from the index and working file while the other staged change and an unrelated unstaged edit remain; also verify the agreed behavior for overlapping unstaged edits and unchanged working-tree revert/unstage behavior.
- **Behavior:**

  > Users currently must unstage a selected staged change before discarding it. The desired workflow discards that change directly from the Index diff, rather than merely moving it to the working tree. Acceptance should cover removal of the selected staged change, preservation of unrelated staged and unstaged edits, and unchanged existing working-tree revert and unstage operations. Handling working-tree edits that overlap the staged selection requires a product decision.
- **Trace:**

  > CommandCenter.revertSelectedRanges in extensions/git/src/commands.ts consumes working-tree diff information and delegates to _revertChanges, which only accepts file documents and saves working-tree content without updating the index. The command registrations in extensions/git/package.json exclude git-scheme Index documents. getIndexDiffInformation in extensions/git/src/staging.ts identifies HEAD-to-index changes, and CommandCenter.unstageSelectedRanges demonstrates a separate index-update path through Repository.stage in extensions/git/src/repository.ts. These paths establish the missing capability without executing the application. Preserve existing unstage semantics and keep historical-commit reversion and finer line-versus-hunk granularity outside this feature's scope. The maintainer accepted the feature in https://github.com/microsoft/vscode/issues/96850#issuecomment-2550969555; https://github.com/microsoft/vscode/pull/289042 fixes a distinct diff-information regression. Uncertainty starts with the observable effect of staged discard when the working tree contains overlapping later edits.
- **Open decisions:**
  - When unstaged edits overlap the selected staged change, should direct discard preserve those later edits where possible, require confirmation, or refuse until the overlap is resolved?

## Evidence

- **Accepted direction and demand:** The maintainer explicitly classified this as an implementable feature request in https://github.com/microsoft/vscode/issues/96850#issuecomment-2550969555. Two earlier commenters describe the cumbersome unstage-then-revert workaround; the issue has eight upvotes and is accepted in Backlog.
- **Existing capability and remaining gap:** extensions/git/package.json scopes git.revertSelectedRanges in the command palette, editor context menu, and selection toolbar to resourceScheme == file; the Index diff uses resourceScheme == git. Thus the originally misleading menu exposure is now avoided, but direct reversion of staged selections remains unavailable.
- **Current implementation boundary:** extensions/git/src/commands.ts:1974–2036 implements revertSelectedRanges using getWorkingTreeDiffInformation and _revertChanges. The latter requires a file URI and edits/saves the working document against the '~' Git baseline; it does not update the index. extensions/git/src/staging.ts:210–227 separately identifies Index diffs as HEAD-to-index and working-tree diffs by '~' or empty refs.
- **Unstage is not discard:** extensions/git/src/commands.ts:2063–2121 implements git.unstageSelectedRanges by applying inverted selected Index changes and calling repository.stage; it does not discard their working-tree content. https://github.com/microsoft/vscode/issues/156748 was closed into this issue, not an open canonical that can absorb it.
