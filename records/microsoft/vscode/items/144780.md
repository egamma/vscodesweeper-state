# Issue #144780 — Git - repository auto-detection not working for junctions on windows

[https://github.com/microsoft/vscode/issues/144780](https://github.com/microsoft/vscode/issues/144780)

## Summary

Still reproduces on main: the `traverseWorkspaceFolder` method in the git extension filters subdirectories using `dirent.isDirectory()`, which returns `false` for Windows junctions (Node.js treats them as symbolic links). This means junctions are silently skipped during the initial workspace folder scan, so git repositories behind junctions are never auto-detected. The bug is real, confirmed by multiple reporters over several years, and the code path is unchanged on current main. Issue #273381 tracks a closely related junction problem (modified files not detected inside junctions) — both share the same root cause of missing symlink/junction handling in the git extension's folder traversal.

## Change summary

Git repository auto-detection skips Windows junction directories because the workspace folder traversal only checks `dirent.isDirectory()`, which returns false for junctions.

## Best solution

Fix `traverseWorkspaceFolder` in `extensions/git/src/model.ts` to also traverse entries where `dirent.isSymbolicLink()` is true (checking that the link target is a directory). This would fix both this issue and the related #273381. Consider consolidating #273381 as a duplicate of this one since both stem from missing junction/symlink support in the git extension's folder scanning.
