# Issue #106577 — Clicking on settings checkboxes sometimes dropped after changing another setting

[https://github.com/microsoft/vscode/issues/106577](https://github.com/microsoft/vscode/issues/106577)

## Summary

The settings editor has been significantly reworked since 2020 — the renderTree logic now proceeds immediately when a different setting is focused, and a 2026 stabilization commit (2170a512e50) added scroll anchoring. The original click-swallowing path appears addressed, but no commit directly references this issue. Requesting confirmation on the latest build.

## Change summary

Clicking a second settings checkbox shortly after changing another sometimes had no effect due to deferred tree refresh logic.

## Best solution

Confirm whether this still reproduces on the latest stable/insiders build. The scheduleRefresh mechanism in settingsEditor2.ts now only defers when the *same* setting key is focused, so the described cross-setting click-swallowing should no longer occur. If confirmed fixed, close as completed citing the stabilization work.
