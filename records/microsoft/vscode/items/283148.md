# Issue #283148 — Stage Selected Range the second time wipes out the first Staged Selected Range which was never shown as staged.

[https://github.com/microsoft/vscode/issues/283148](https://github.com/microsoft/vscode/issues/283148)

## Summary

Verified duplicate of the older, open sequential-staging report: the diff fails to refresh after staging one range, and staging another leaves only the latter staged. The canonical also documents the large-repository sensitivity and tab-switch workaround.

## Change summary

Successive Stage Selected Range operations can replace earlier staged selections when the editor's index comparison has not refreshed.

## Best solution

Consolidate the sequential-staging and stale-diff evidence in https://github.com/microsoft/vscode/issues/173437, and resolve the refresh/operation-ordering defect so each staging operation preserves previously staged ranges.
