# Issue #287947 — Implement built-in agents from Copilot CLI to Copilot Chat

[https://github.com/microsoft/vscode/issues/287947](https://github.com/microsoft/vscode/issues/287947)

## Summary

Current main partially implements the request with built-in Plan and Explore agents, but it does not register the requested Task or Code-review agents. The remaining parity work and its user-facing shape need a maintainer decision, so the issue should stay open under discussion.

## Change summary

Provide Copilot Chat with the Explore, Task, Plan, and Code-review built-in agents available in Copilot CLI.

## Best solution

Preserve the existing Plan and Explore providers, then decide whether Task and Code-review should be selectable agents, invocation-only subagents, or both. Reuse Copilot Chat's existing execution-subagent and review capabilities where their behavior matches the CLI agents rather than creating parallel implementations.

- **Behavior:**

  > Copilot Chat provides the approved equivalents of Copilot CLI's Task and Code-review agents in addition to its existing Explore and Plan agents. Task delegates command-heavy work such as tests and builds while returning concise success results and useful failure output; Code-review examines changes and reports actionable findings without modifying the workspace. Agent visibility and model-invocation behavior follow the maintainer's decision, and existing Plan, Ask, Explore, execution-subagent, and review workflows remain compatible.
- **Trace:**

  > PromptFileContribution in extensions/copilot/src/extension/agents/vscode-node/promptFileContrib.ts currently registers PlanAgentProvider, AskAgentProvider, and an experiment-gated ExploreAgentProvider. No Task or Code-review provider exists in that directory. Task-like execution already runs through ExecutionSubagentTool in extensions/copilot/src/extension/tools/node/executionSubagentTool.ts and is gated by getAgentTools in extensions/copilot/src/extension/intents/node/agentIntent.ts; review logic already exists under extensions/copilot/src/extension/review/node/. The plan should determine whether those capabilities satisfy the required semantics and how they should be surfaced, without replacing or changing existing Plan, Ask, Explore, general review, or execution-subagent behavior.
- **Open decisions:**
  - Should Task and Code-review be user-selectable Copilot Chat agents, model-invocable subagents, or available through both paths?
  - Should parity mean matching Copilot CLI's prompts and tool boundaries, or exposing Copilot Chat's existing execution and review behaviors under equivalent built-in agent roles?
