# Issue #338920 — Markdown links drop non-line fragments like #page=3 when opening files (PDF links always open on page 1)

[https://github.com/microsoft/vscode/issues/338920](https://github.com/microsoft/vscode/issues/338920)

## Summary

Confirmed on current main: openDocumentLink.ts only recovers a fragment via getLocationFragmentFromLinkText when it matches the line-range regex, so non-line fragments like #page=3 are dropped before the vscode.open call. A fix is already up as an open PR, so this should stay open pending review/merge rather than being closed now.

## Change summary

Markdown preview/editor links to non-text files with non-line URI fragments (e.g. file.pdf#page=3) lose the fragment when opened, so viewers that honor fragments (confirmed with mathematic.vscode-pdf) can't jump to the right location.

## Best solution

Land (or iterate on) the open fix in https://github.com/microsoft/vscode/pull/332661, which preserves non-line fragments for file-kind resolved links in extensions/markdown-language-features/src/util/openDocumentLink.ts while keeping existing L<line> behavior intact.
