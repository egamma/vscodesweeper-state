# Issue #91108 — Add a command to file an issue (bug) with relevant info

[https://github.com/microsoft/vscode/issues/91108](https://github.com/microsoft/vscode/issues/91108)

## Summary

The desktop shortcut remains missing: existing commands open the Issue Reporter rather than going directly to a prefilled GitHub draft. Keep this accepted Backlog request open; the related requests do not cover the same workflow.

## Change summary

Provide a palette command and keybinding that open a GitHub issue draft with system information, optionally excluding extensions, without first completing the Issue Reporter.

## Best solution

Offer an explicit desktop shortcut to a prefilled GitHub draft while preserving the normal Issue Reporter workflow. Reuse existing diagnostic formatting and oversized-body handling, with extension information omitted when requested.

Check that extension details are absent, oversized diagnostic content remains recoverable, and the existing Report Issue command still opens its normal UI.
- **Behavior:**

  > A desktop user can open a GitHub issue draft through a palette command or keybinding without first entering a title or description in the Issue Reporter. The draft includes system information and can omit extension information. Nothing is submitted automatically. Existing interactive issue reporting remains unchanged.
- **Trace:**

  > BaseIssueContribution in src/vs/workbench/contrib/issue/common/issue.contribution.ts registers both existing reporter commands and forwards their arguments to IWorkbenchIssueService.openReporter. NativeIssueService in src/vs/workbench/contrib/issue/electron-browser/issueService.ts routes to wizard or legacy UI; the locally inspected NativeIssueFormService confirms both branches display a reporter. BrowserIssueService has a direct GitHub path, but its static browser metadata does not provide the requested desktop diagnostics. IssueFormService in src/vs/workbench/contrib/issue/browser/issueFormService.ts already handles GitHub draft URLs and oversized bodies during submission, providing relevant existing behavior to investigate rather than duplicate. Preserve the interactive reporting path and do not automatically submit an issue. The goal is settled by https://github.com/microsoft/vscode/issues/91108; uncertainty remains around the exposed shortcut contract and diagnostic defaults.
- **Open decisions:**
  - Should bypassing the reporter be exposed as a separate palette command or as an explicit mode of the existing command?
  - Which diagnostic inclusion options should the shortcut expose, and should invoking it without arguments omit extensions as the original request suggests?
