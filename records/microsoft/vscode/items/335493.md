# Issue #335493 — Track native, mapped, and unsupported customization migration outcomes

[https://github.com/microsoft/vscode/issues/335493](https://github.com/microsoft/vscode/issues/335493)

## Summary

Keep open: this is a team-authored telemetry follow-up with an unresolved measurement contract, and the prototype PR was closed rather than merged. The maintainer comment identifies substantive ambiguity in when native, mapped, and unsupported outcomes apply.

## Change summary

Add bounded aggregate telemetry that tracks native, compatibility-mapped, and unsupported customization migration outcomes without delaying chat dispatch or repeatedly rescanning inventories.

## Best solution

Define the outcome taxonomy for each customization type with the customization and telemetry owners, then implement a deferred, cached inventory assessment keyed by logical target, workspace context, and inventory generation, with invalidation on customization changes.
