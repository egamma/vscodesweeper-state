## Summary

Keep open for notebook performance investigation: current source still schedules rendering of offscreen code-cell outputs on notebook attachment, although the reported potential freeze has not been established. This team-authored issue has neither a verified fixing commit nor an older canonical reporting the same observable symptom.

## Change summary

Investigate whether eagerly rendering offscreen image outputs causes avoidable work and poor responsiveness when reopening large notebooks.

Preserve accurate output sizing and responsive scrolling rather than treating renderer log messages alone as proof of a performance defect.

- **Current document-wide warmup:** src/vs/workbench/contrib/notebook/browser/contrib/viewportWarmup/viewportWarmup.ts schedules _warmupDocumentNow after view-model attachment. That method iterates every cell and calls _warmupCodeCell for code cells without testing viewport membership. _warmupCodeCell skips collapsed outputs but otherwise calls createOutput(viewCell, result, 0, true) for eligible outputs up to outputDisplayLimit.
- **Idle scheduling still performs rendering:** NotebookEditorWidget.createOutput in src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts:2847–2881 forwards warmup to BackLayerWebView.requestCreateOutputWhenWebviewIdle.
