# Issue #293127 — VS code integrated Terminal Line Continuation not working (Powershell) #269107

[https://github.com/microsoft/vscode/issues/293127](https://github.com/microsoft/vscode/issues/293127)

## Summary

Valid regression: enabling kitty keyboard protocol by default (commit 8c3168c967e, now default=true) breaks PowerShell line continuation on Windows unless win32 input mode is also enabled (still default=false/experimental). A team member engaged and confirmed the workaround, but no fix has landed to make the two modes interoperate correctly out of the box.

## Change summary

PowerShell backtick line continuation stopped working in VS Code's integrated terminal after kitty keyboard protocol was enabled by default.

## Best solution

The kitty keyboard protocol's encoding of the backtick key needs to be handled correctly by PowerShell's readline on Windows, or win32 input mode should be co-enabled by default when kitty keyboard is active on Windows with PowerShell. The fix likely lives in `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts` or the shell integration layer.
