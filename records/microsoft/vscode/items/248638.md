# Issue #248638 — Multiple taskbar icons for muliple VS Code windows

[https://github.com/microsoft/vscode/issues/248638](https://github.com/microsoft/vscode/issues/248638)

## Summary

Keep this accepted, 20-upvote request open: current source does not provide project-specific taskbar icons or grouping. The closest open requests are newer, so they cannot replace this re-reviewed issue as canonical; a maintainer should settle the identity and persistence model before implementation.

## Change summary

Allow different VS Code projects to have distinguishable, separately grouped taskbar icons for easier window switching.

## Best solution

Provide an opt-in native-window identity experience that distinguishes frontend and backend projects directly on the taskbar while preserving default grouping. Decide whether that identity belongs to a workspace or a profile, coordinating the related requests without treating global app-icon customization as equivalent.

## Plan brief

- **Likely files:** `src/vs/code/electron-main/app.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/userDataProfile/common/userDataProfile.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** On Windows, open frontend and backend folders concurrently, assign the chosen identities, and verify distinct taskbar icons and groups activate the correct windows. Reopen both projects to check the agreed persistence behavior; verify ordinary unconfigured windows retain existing grouping and pinned-shortcut behavior.
- **Behavior:**

  > The reporter opens frontend and backend projects in separate windows but cannot identify them directly from their shared taskbar icon. The desired outcome is distinguishable project icons and taskbar entries that make switching to the intended window reliable. Acceptance should cover both simultaneous windows, activation from their taskbar entries, persistence under the chosen identity model, and unchanged behavior for users who do not opt in.
- **Trace:**

  > src/vs/code/electron-main/app.ts sets the product-level Windows AppUserModelID during startup. CodeWindow construction in src/vs/platform/windows/electron-main/windowImpl.ts supplies a special Agents Window icon but no corresponding project/profile customization; its application-badge path handles notification overlays only. window.title in src/vs/workbench/browser/workbench.contribution.ts already supports workspace and profile names, but those labels do not solve native icon identity. The trace establishes the missing configuration surface, not the feasibility of every Windows grouping and pinning contract. Preserve existing default grouping, portable-install identity, notification badges, and Agents Window behavior. Coordinate https://github.com/microsoft/vscode/issues/285287 and https://github.com/microsoft/vscode/issues/307266; https://github.com/microsoft/vscode/issues/120604 is related global icon customization rather than an equivalent canonical.
- **Open decisions:**
  - Should icon and taskbar-group identity be attached to individual workspaces, shared profiles, or explicitly named user-defined groups?
  - Should the chosen identity persist when a project is reopened and be independently pinnable, or distinguish only currently open windows?
