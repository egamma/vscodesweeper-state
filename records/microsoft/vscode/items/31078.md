# Issue #31078 — Support large documents in extension host

[https://github.com/microsoft/vscode/issues/31078](https://github.com/microsoft/vscode/issues/31078)

## Summary

The extension-host limitation remains intentional but unresolved on current main. This Backlog request has 234 community upvotes and should remain open for API and performance design.

## Change summary

Allow extensions to operate on documents exceeding the extension-host model synchronization limit.

## Best solution

Design a bounded, opt-in API for large documents—such as lightweight editor metadata, partial access, or explicit synchronization with resource limits—rather than unconditionally copying entire models into the extension host. The implementation would likely span the text-model synchronization and workbench API layers.

- **Reason:** Closing this extension API gap supports powerful extensions while retaining explicit safeguards for extension-host performance.
- **Evidence:** The public roadmap emphasizes both “The power lives in extensions” and “Performance trumps functionality”; a bounded API can serve both values.

## Evidence

- **current source:** src/vs/editor/common/model/textModel.ts still sets TextModel._MODEL_SYNC_LIMIT to 50 MB and marks larger models as too large for synchronization.
- **extension-host boundary:** src/vs/workbench/api/browser/mainThreadDocuments.ts rejects extension requests for unsynchronized models with “Files above 50MB cannot be synchronized with extensions.”
- **intentional behavior:** Maintainer discussion explains that synchronization is deliberately suppressed to prevent large documents from stalling the extension host, while acknowledging that the limit is arbitrary and not configurable.
- **regression coverage:** src/vs/workbench/api/test/browser/mainThreadDocumentsAndEditors.test.ts explicitly tests that huge models and their editors are omitted from extension-host document/editor deltas.
- **community demand:** The issue is in the Backlog milestone with 234 community upvotes, well above the 20-upvote promotion threshold.
- **existing setting:** editor.largeFileOptimizations only controls memory-intensive editor features; it does not change the independent 50 MB extension-host synchronization limit.
