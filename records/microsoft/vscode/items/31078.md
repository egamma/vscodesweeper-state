# Issue #31078 — Support large documents in extension host

[https://github.com/microsoft/vscode/issues/31078](https://github.com/microsoft/vscode/issues/31078)

## Summary

Large-document extension-host support remains missing on current main, and the request has substantial community support. Keep this accepted Backlog item open while maintainers evaluate the linked, still-open implementation PR.

## Change summary

Allow extensions to access active text editors and documents that exceed the fixed model-synchronization limit.

## Best solution

Evaluate https://github.com/microsoft/vscode/pull/330849 and decide whether its configurable synchronization limit provides an acceptable opt-in while preserving default performance safeguards. Resolve this issue only after the chosen approach lands and covers extension access to large documents.

## Evidence

- **Current synchronization limit:** src/vs/editor/common/model/textModel.ts declares TextModel._MODEL_SYNC_LIMIT as 50 * 1024 * 1024 and, at line 368, sets _isTooLargeForSyncing when the initial buffer text length exceeds it. The limit measures model text length, rather than directly measuring disk bytes.
- **Extension-editor exclusion:** src/vs/editor/common/model.ts:1624–1627 excludes oversized models through shouldSynchronizeModel. MainThreadDocumentAndEditorStateComputer._updateState in src/vs/workbench/api/browser/mainThreadDocumentsAndEditors.ts:191–247 uses that predicate to exclude both documents and editor snapshots, leaving no active API editor for an excluded document.
- **Existing setting does not cover the request:** editor.largeFileOptimizations is registered in src/vs/editor/common/config/editorConfigurationSchema.ts:61–64. In TextModel's constructor it controls tokenization and heap-operation safeguards, but the synchronization-limit assignment is unconditional. Disabling this setting therefore does not enable extension-host access above the synchronization limit; editor.largeFileSizeLimit is absent from the inspected current model, model-service, and configuration-schema files.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/330849 was verified OPEN with mergedAt null. It proposes editor.largeFileSizeLimit, retaining a default of 50 and allowing zero to disable the limit. Comments dated 2026-08-14 and 2026-09-11 explicitly connect it to this issue and request maintainer feedback on the setting approach.
- **Demand and workaround boundaries:** https://github.com/microsoft/vscode/issues/31078 has 237 community upvotes and is accepted into Backlog. The discussion reports effects on filtering, navigation, bookmarks, and GLTF tooling. The vsc-lfs and Filter Line workarounds operate around the limitation; neither establishes general extension-host access to the original large document.
