# Issue #332910 — Save confirmation dialog shown if file is closed while save is in progress

[https://github.com/microsoft/vscode/issues/332910](https://github.com/microsoft/vscode/issues/332910)

## Summary

Current source confirms the race: a manually saving file remains dirty, but `FileEditorInput.isSaving()` deliberately ignores the pending-save state, so closing it enters the save-confirmation path. This should remain open and be routed to the editor/file-I/O owners.

## Change summary

Closing a file immediately after starting a slow explicit save can show a redundant unsaved-changes confirmation.

## Best solution

A close requested during an explicit save should wait for that save and close without another prompt when it succeeds; if the save fails or leaves the model dirty, the editor should remain open and use the existing confirmation/error behavior.

## Evidence

- **source reproduction:** `src/vs/workbench/contrib/files/browser/editors/fileEditorInput.ts` keeps `isDirty()` true during a manual save and explicitly does not consider `TextFileEditorModelState.PENDING_SAVE` in `isSaving()`.
- **confirmation path:** `src/vs/workbench/browser/parts/editor/editorGroupView.ts` calls `showSaveConfirm` whenever `editor.isDirty() && !editor.isSaving()`, which is exactly the state produced by the reported Ctrl+S/Ctrl+W race.
- **join capability:** `src/vs/workbench/services/textfile/common/textFileEditorModel.ts` exposes `joinState(TextFileEditorModelState.PENDING_SAVE)` and tracks the running operation through its save sequentializer, so the in-flight save can be awaited.
