# Issue #163432 — IntlBackslash swapped with Backquote on ISO keyboards on Chrome & Firefox

[https://github.com/microsoft/vscode/issues/163432](https://github.com/microsoft/vscode/issues/163432)

## Summary

Keep open as an upstream browser defect: Chrome and Firefox report the physical Backquote and IntlBackslash keys incorrectly on macOS ISO keyboards, and current VS Code web keybinding resolution necessarily consumes that browser-provided `KeyboardEvent.code` value.

## Change summary

On macOS with a British ISO keyboard, Chrome and Firefox swap Backquote and IntlBackslash scan codes, breaking code-dispatched shortcuts such as Ctrl+` in VS Code for the Web.

## Best solution

Chromium and Firefox should correct `KeyboardEvent.code` for macOS ISO keyboards. Keep this issue as the VS Code tracking item and verify vscode.dev after the browser fixes land; the `keyboard.dispatch: keyCode` setting remains an incomplete workaround because it loses the distinction between the two keys.

## Evidence

- **confirmed upstream behavior:** The reporter reproduced the swapped values directly with `window.onkeydown = (e) => console.log(e.code, e.key)` in Chrome and Firefox, outside VS Code; Safari produced the expected result.
- **Firefox upstream:** https://bugzilla.mozilla.org/show_bug.cgi?id=1755096 remains open and describes the same Backquote/IntlBackslash mapping on macOS ISO keyboards.
- **Chromium upstream:** The maintainer traced Chrome's behavior to Chromium's macOS keyboard conversion and linked https://issues.chromium.org/issues/40185924 (migrated from Chromium issue 1296783).
- **current source path:** src/vs/base/browser/keyboardEvent.ts assigns the browser's `KeyboardEvent.code` directly to `StandardKeyboardEvent.code`; src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts then converts that value with `ScanCodeUtils.toEnum(keyboardEvent.code)` in `resolveKeyboardEvent`.
- **expected layout:** src/vs/workbench/services/keybinding/browser/keyboardLayouts/en-uk.darwin.ts correctly defines Backquote as ` and IntlBackslash as §, so the bundled layout data is not the source of the swap.
- **no competing fix:** The live issue is open in the Backlog milestone, no open microsoft/vscode PR references it, and repository history contains no issue-linked VS Code fix.
