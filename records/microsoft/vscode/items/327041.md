# Issue #327041 — [agents window] Browsers get hidden in workspace-less chats

[https://github.com/microsoft/vscode/issues/327041](https://github.com/microsoft/vscode/issues/327041)

## Summary

Assigned to milestone 1.134.0, which is a real scheduling milestone, so this stays open regardless of other findings — but the reported behavior lines up with a real gap in the single-pane layout strategies for workspace-less (non-quick-chat) sessions.

## Change summary

In a standalone (workspace-less) chat, opening a browser and then switching away and back leaves the browser editor hidden with the auxiliary-bar/side-panel toggle disabled, with no way to bring it back.

## Best solution

Have a maintainer with agents-window/browser-integration context trace `SinglePaneDetailPanelStrategy._computeDetailTarget` in src/vs/sessions/contrib/layout/browser/singlePane/singlePaneDetailPanelStrategy.ts — it early-returns `DetailPanelTarget.Preserve` whenever `activeSession.workspace` is falsy (line ~110), before ever reaching the BrowserEditorInput handling at line ~137 that normally falls back to Changes/Files once the editor part is hidden. For workspace-less, non-quick-chat sessions that fallback never runs, so once something (e.g. SinglePaneSidePaneVisibilityStrategy's profile switch) hides the editor part while a browser is active, there's no path back to a visible detail/browser state; a fix likely needs to extend the browser-fallback branch to also apply when `workspace` is undefined but the session isn't a quick chat.
