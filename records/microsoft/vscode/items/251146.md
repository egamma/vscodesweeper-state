# Issue #251146 — Add full set of color tokens for chat panel

[https://github.com/microsoft/vscode/issues/251146](https://github.com/microsoft/vscode/issues/251146)

## Summary

A real theming API gap remains on current main: chat request backgrounds and line-change colors have dedicated tokens, but response backgrounds and request/response foreground roles still inherit generic workbench colors. The Backlog milestone records this as accepted work, so it should remain open while the remaining public token semantics are settled.

## Change summary

Provide dedicated, paired theme color tokens for chat request and response backgrounds, primary foregrounds, and secondary response text.

## Best solution

Define the remaining request/response color roles as a coherent public theme API, give them defaults that preserve the current appearance across standard and high-contrast themes, and apply them consistently to chat views, chat editors, and the Agents window.

- **Trace:**

  > The public chat colors are registered in src/vs/workbench/contrib/chat/common/widget/chatColors.ts. Current request bubbles consume --vscode-chat-requestBubbleBackground in src/vs/workbench/contrib/chat/browser/widget/media/chat.css, while response and subdued text still consume generic --vscode-foreground and --vscode-descriptionForeground. The existing chat.requestBackground token also has limited current usage, so the plan must distinguish the transcript-row role from chat.requestBubbleBackground rather than adding overlapping names blindly. https://github.com/microsoft/vscode/issues/237014 demonstrates the contrast failures caused by borrowing unrelated color pairs but tracks a broader observable problem. Preserve specialized colors for links, code blocks, diagnostics, and status elements; this request concerns the base request/response surfaces and their secondary text hierarchy.
- **Open decisions:**
  - Should the existing chat.requestBackground token represent the request turn surface, be superseded by chat.requestBubbleBackground, or remain a distinct public role with documented scope?
  - Which response elements count as secondary foreground content: response metadata and timestamps only, or all subdued response text such as progress and detail labels?
  - Must the new response tokens apply identically across the sidebar chat view, chat editor, and Agents window, or are any of those surfaces intentionally allowed separate color roles?
