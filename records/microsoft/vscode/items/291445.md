# Issue #291445 — Terminal timeout shouldn't count when waiting for user input

[https://github.com/microsoft/vscode/issues/291445](https://github.com/microsoft/vscode/issues/291445)

## Summary

Keep open: current terminal tooling handles input differently, but an enforced model timeout still measures elapsed time rather than execution time excluding human input waits. Existing settings do not deliver the requested semantics, and no verified canonical or issue-referencing fix was found.

## Change summary

Exclude time spent waiting for user input from terminal execution timeouts, with consistent prompt cleanup and command-result attribution.

## Best solution

Define input-wait semantics for the terminal tool so a human response delay cannot exhaust the command's execution budget. Retest the lingering prompt and previous-command exit-code observations separately against the current input-handling flow.

Retest the separately reported exit-code attribution when another command follows an interrupted execution.
- **Trace:**

  > RunInTerminalTool in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts creates a wall-clock timeout and races it against execution completion and other signals. OutputMonitor._handleIdleState in browser/tools/monitoring/outputMonitor.ts routes ordinary prompts to onDidDetectInputNeeded and sensitive prompts to onDidDetectSensitiveInputNeeded. Ordinary prompts now return control to the agent, whereas sensitive prompts leave the foreground race pending with a human-facing elicitation. Neither path supplies paused execution-budget accounting. Preserve the boundary that secrets are entered directly in the terminal, not sent through the model, and preserve explicit cancellation and background execution behavior. The lingering-prompt and exit-code observations have not been verified on current main. https://github.com/microsoft/vscode/issues/285703 concerns related UI cleanup but is closed; https://github.com/microsoft/vscode/issues/309370 concerns prompt-detection consistency rather than this timing contract.
- **Open decisions:**
  - Should exclusion from the execution budget apply only while VS Code explicitly awaits a human response, or also while an ordinary terminal prompt has handed control back to the agent?
  - For an ordinary prompt that needs the user's answer, should the terminal invocation remain pending until the answer is supplied, or retain the current early-return handoff with execution-budget accounting continuing across that handoff?
