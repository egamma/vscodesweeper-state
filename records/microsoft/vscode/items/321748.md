# Issue #321748 — Terminal auto-approval fails for git diff -- <path> despite "git diff" allow rule

[https://github.com/microsoft/vscode/issues/321748](https://github.com/microsoft/vscode/issues/321748)

## Summary

Still reproduces on main: tree-sitter command parsing of bare `--` (POSIX pathspec/end-of-options separator) produces either an empty sub-command list or differently shaped output, causing the auto-approve rule match to fail. A second reporter confirms the issue across various commands, not just `git diff`.

## Change summary

Terminal auto-approval fails for commands containing the `--` argument separator (e.g. `git diff -- file.txt`) even when a matching allow rule like `"git diff": true` exists.

## Best solution

Fix the tree-sitter command parser (or the auto-approve matching layer) so that the `--` end-of-options separator is treated as transparent for sub-command extraction — `git diff -- file.txt` should produce the same sub-command text as `git diff file.txt`. The fix likely lives in `treeSitterCommandParser.ts` (post-processing the tree-sitter output to strip `--` separators) or in the upstream tree-sitter grammars for bash and PowerShell. A workaround in the regex matching layer (`commandLineAutoApprover.ts`) is also viable but less clean.
