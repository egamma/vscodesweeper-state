# Issue #147830 — CompletionList.isIncomplete=true results in showing "stale" results when typing quickly due to cancelled requests

[https://github.com/microsoft/vscode/issues/147830](https://github.com/microsoft/vscode/issues/147830)

## Summary

Keep open for a completion-refresh design decision: current source still discards cancelled completion results and does not immediately refilter the displayed list when retriggering an incomplete provider. The related client-side filtering request is newer and does not qualify as a duplicate target for this re-reviewed item.

## Change summary

Keep incomplete completion suggestions responsive during rapid typing, potentially using intermediate responses while newer results are pending.

## Best solution

Define how incomplete completion sessions should present useful intermediate results without accepting invalid edits or letting older responses overwrite newer results. Coordinate this decision with https://github.com/microsoft/vscode/issues/168329 while retaining the distinction between reusing cancelled responses and filtering already displayed results.

- **Behavior:**

  > Incomplete completion lists should remain useful while the user types faster than the provider responds. The supplied sample distinguishes fresh results by including the request position in each label. Establish which intermediate results may appear, then verify that updates remain responsive, newer results are never replaced by older ones, and accepting a suggestion produces a valid edit. Explicitly dismissing suggestions must not allow a late response to reopen them.
- **Trace:**

  > provideSuggestionItems in src/vs/editor/contrib/suggest/browser/suggest.ts rejects completed provider results when their request token is cancelled. SuggestModel._onNewContext in suggestModel.ts retriggers incomplete providers before its ordinary local-refilter branch; trigger calls cancel, clearing _completionModel, and contexts received while the replacement is pending return early. SuggestController leaves the widget visible on retrigger cancellation. This establishes the relevant lifecycle, not an executed confirmation of the original timing sequence. https://github.com/microsoft/vscode/issues/168329 separately requests filtering already available results while waiting. Preserve explicit dismissal, provider grouping, complete-provider reuse, and insertion-range correctness; accepting arbitrary cancelled responses is not established as a safe contract.
- **Open decisions:**
  - Should a response from a superseded request be eligible for interim display when it remains applicable to the current completion session, or should cancelled responses remain unusable and responsiveness improvements be limited to filtering already accepted results?

## Evidence

- **Complete timing sample:** https://github.com/microsoft/vscode/issues/147830#issuecomment-1104907087 supplies a plaintext completion provider returning an incomplete list after 80 ms, typing every 60 ms, and position-labelled results. The provider deliberately returns despite cancellation; the report compares this with a 40 ms response.
- **Current cancellation behavior:** In src/vs/editor/contrib/suggest/browser/suggest.ts, provideSuggestionItems checks token.isCancellationRequested after awaiting providers, disposes their results, and rejects with CancellationError. Returning a result after cancellation therefore does not make it available as an intermediate suggestion list.
- **Current refresh boundary:** In src/vs/editor/contrib/suggest/browser/suggestModel.ts, _onNewContext retriggers incomplete providers before the branch that updates lineContext and emits onDidSuggest. trigger calls cancel, which clears _completionModel; subsequent contexts return early while that model is absent. In suggestController.ts, retrigger cancellation leaves the widget visible. These paths explain the missing immediate local refresh, but the original sustained 80 ms/60 ms timing sequence was not executed against this checkout.

They do not enable adoption of cancelled responses or bypass the incomplete-provider retrigger branch.
