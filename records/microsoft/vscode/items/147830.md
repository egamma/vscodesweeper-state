# Issue #147830 — CompletionList.isIncomplete=true results in showing "stale" results when typing quickly due to cancelled requests

[https://github.com/microsoft/vscode/issues/147830](https://github.com/microsoft/vscode/issues/147830)

## Summary

Still valid on current main — when isIncomplete triggers a re-request on each keystroke, the previous cancelled request's results are discarded (line 542 of suggestModel.ts calls cancel, line 603 checks _triggerState and drops late-arriving results), causing the completion list to appear stale until typing pauses. No fix has landed.

## Change summary

When typing faster than the completion provider responds with isIncomplete=true, cancelled request results are discarded rather than used as interim display, making completions feel sluggish.

## Best solution

Modify the suggest model's cancellation/retrigger logic in suggestModel.ts to accept late-arriving results from cancelled incomplete requests as interim display while the new request is in-flight. Related issue https://github.com/microsoft/vscode/issues/168329 covers client-side filtering of incomplete results — both are facets of the same UX gap but address distinct behaviors (this one: use cancelled results; that one: filter existing results locally). Both should remain open.
