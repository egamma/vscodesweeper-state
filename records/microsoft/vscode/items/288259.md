# Issue #288259 — Unable to see git worktree created by copilot

[https://github.com/microsoft/vscode/issues/288259](https://github.com/microsoft/vscode/issues/288259)

## Summary

Keep open as a request to make background-agent worktrees available in the normal Source Control workflow. Hiding is intentional, but the existing repository explorer workaround does not restore same-window review alongside other repositories; the verified same-symptom report is newer and cannot be this re-reviewed issue's canonical.

## Change summary

Allow users to review and manually edit Copilot-created worktrees through normal Source Control, alongside manually created worktrees.

## Best solution

Provide a supported way to include background-agent worktrees in the normal Changes view without switching workspaces. The Git/SCM owners should decide whether this is explicit per-worktree visibility or a change to the default, preserving background-session isolation.

- **Behavior:**

  > Users can review and manually edit changes in a background-agent worktree through the normal Source Control workflow without replacing the main repository's workspace. Manually created worktrees already support the requested alongside-the-parent workflow, while agent-created worktrees are intentionally excluded. The repository explorer workaround provides discovery and workspace opening, but not that same-window Changes experience. Acceptance should cover the chosen visibility default or opt-in action, reviewing and staging worktree edits, and behavior after reload.
- **Trace:**

  > Repository construction in extensions/git/src/repository.ts marks recognized agent worktrees hidden when their parent repository is open; SCMViewService in src/vs/workbench/contrib/scm/browser/scmViewService.ts filters those providers from repository and visible-repository lists. This behavior was deliberately introduced by https://github.com/microsoft/vscode/pull/284462. Git: Open Repository delegates to Model.openRepository, which returns for an existing repository and does not change visibility. GitArtifactProvider lists the worktrees in the experimental repository explorer, but its open commands switch or create a workspace. The remaining uncertainty is the user-facing visibility contract, not worktree creation or Git discovery. Preserve session isolation, trust checks, ordinary repository behavior, and the existing workspace-opening commands. https://github.com/microsoft/vscode/issues/298291 contains the same complaint and maintainer interest but is newer than this report.
- **Open decisions:**
  - Should background-agent worktrees appear in the normal Changes view by default, or only after an explicit user opt-in?
  - If visibility is opt-in, should it apply to individual worktrees or all agent worktrees, and should that choice survive a window reload?
