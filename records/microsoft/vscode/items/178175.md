# Issue #178175 — Git - pre-push and pre-commit git hooks are handled differently when errors occur

[https://github.com/microsoft/vscode/issues/178175](https://github.com/microsoft/vscode/issues/178175)

## Summary

The misleading pre-push failure message remains reproducible from current source: a generic Git failure footer is classified as a rejected push and produces unrelated Pull advice. Keep this open in the Git area; stdout logging provides a workaround for missing hook output, but does not fix the error classification.

## Change summary

Report failed pre-push hooks accurately instead of attributing them to remote changes that require pulling.

## Best solution

The built-in Git extension should distinguish hook failures from genuine remote-ref rejection, present useful failure details, and retain existing guidance for actual non-fast-forward and force-with-lease failures. Hook output should remain discoverable without requiring reporters to corrupt Git's error footer.
