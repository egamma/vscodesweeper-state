[https://github.com/microsoft/vscode/issues/332225](https://github.com/microsoft/vscode/issues/332225)

## Summary

Team-authored (MEMBER) report of confusing session-orchestration/child-session notification behavior, filed hours ago and still under active discussion by the author — hard keep-open rule for team-authored issues applies, and there is no fix commit to cite for a completed close.

## Change summary

Spawning a child session from a main session no longer surfaces the child's explanation to the user directly; instead the child reports back to the parent, the parent doesn't act on it, and a distracting system notification fires every time the child session goes idle.

## Best solution

A maintainer on the Agent Sessions team should clarify the intended orchestration model (parent-drives-child vs. standalone child sessions) and fix the system-notification spam tied to child idle events in the agentHostSessionHandler/session orchestration code; likely belongs with the existing delegated-child-sessions work already tracked in https://github.com/microsoft/vscode/issues/331554 and https://github.com/microsoft/vscode/issues/331541.
