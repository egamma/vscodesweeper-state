# Issue #111854 — Allow extensions to contribute a default when clause to be used when a user add a key binding for the command

[https://github.com/microsoft/vscode/issues/111854](https://github.com/microsoft/vscode/issues/111854)

## Summary

Keep open: current VS Code can carry command enablement into Command Palette keybinding configuration, but it still lacks an extension-contributed, editable keybinding default independent of command availability. The issue is accepted in Backlog, and no verified older canonical owns the remaining request.

## Change summary

Let extensions supply a suggested when clause that is populated when users assign a shortcut to a command without a default binding.

## Best solution

Define a supported contribution contract for suggested keybinding conditions, usable without assigning a default shortcut, and honor it when users configure bindings. Distinguish this editable suggestion from command-wide enablement and settle whether it also affects manually authored keybindings.

- **Behavior:**

  > An extension can supply a suggested keybinding condition without assigning a default shortcut or making that condition the command's general availability requirement. When a user creates a binding through Keyboard Shortcuts or Command Palette configuration, the suggested condition is presented and persisted according to the agreed contract. Existing bindings and commands without suggestions retain their current behavior. Acceptance includes configuring a command whose recommended shortcut condition distinguishes regular and diff-editor contexts.

- **Open decisions:**
  - Is the contributed condition only an editable suggestion used when creating a binding, or must manually authored keybindings that omit when also inherit it?
  - Should authors declare a distinct keybinding-default condition, reuse command enablement or Command Palette visibility, or support keyless binding templates? These expose different author contracts and can produce different conditions for the same command.
