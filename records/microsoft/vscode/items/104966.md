# Issue #104966 — Can't input backslash.

[https://github.com/microsoft/vscode/issues/104966](https://github.com/microsoft/vscode/issues/104966)

## Summary

Keep open for the maintainer-requested warning about shortcuts that consume printable characters. The original backslash problem was diagnosed, but the current shortcut recorder still lacks that preventive warning.

## Change summary

Warn when defining a keyboard shortcut that can intercept normal character input.

## Best solution

Provide a clear warning in the Keyboard Shortcuts recorder when a proposed binding may consume printable input, while preserving intentional character-key shortcuts. Follow the maintainer's printable-character detection guidance rather than warning indiscriminately for every key without modifiers.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/preferences/browser/keybindingWidgets.ts`, `src/vs/workbench/contrib/preferences/browser/keybindingsEditor.ts`
- **Validation:** Exercise the Keyboard Shortcuts recorder with an unmodified backslash, a shifted printable character, Ctrl+backslash, and F3. Verify that potentially character-consuming bindings receive the agreed warning, non-printable combinations do not, intentional bindings remain saveable, and changing or cancelling the recorded shortcut clears obsolete warnings.
- **Behavior:**

  > The Keyboard Shortcuts editor currently allows users to assign a printable character to a command without explaining that normal typing may be intercepted. Show a warning during shortcut definition when the proposed binding may consume character input. Preserve the ability to create intentional character-key shortcuts and leave non-printable combinations unaffected. Acceptance should include unmodified backslash, shifted printable input, a modified shortcut, and a function key, with correct warning updates and cancellation behavior.
- **Trace:**

  > The original report was traced to an unmodified oem_5 binding, not an extension-owned defect: https://github.com/microsoft/vscode/issues/104966#issuecomment-683400643. In src/vs/workbench/contrib/preferences/browser/keybindingWidgets.ts, KeybindingsSearchWidget.printKeybinding receives the keyboard event, resolves it, and emits recorded chords; DefineKeybindingWidget displays those chords and existing command conflicts without a printable-input warning. KeybindingsEditor.defineKeybinding in src/vs/workbench/contrib/preferences/browser/keybindingsEditor.ts saves the accepted result through updateKeybinding. WorkbenchKeybindingService.mightProducePrintableCharacter in src/vs/workbench/services/keybinding/browser/keybindingService.ts is the existing layout-aware helper explicitly recommended at https://github.com/microsoft/vscode/issues/104966#issuecomment-684031775. Preserve shortcut dispatch, legitimate unmodified bindings, existing conflict information, and JSON editing semantics. The remaining product question is whether the warning should also appear for bindings whose when-expression deliberately restricts them to a non-typing context.
- **Open decisions:**
  - Should all recorded printable-character bindings show the warning, including bindings restricted by a when-expression to a non-typing context, or should those context-restricted bindings be exempt?
