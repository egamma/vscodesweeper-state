# Issue #317971 — VSCode should allow opening a devcontainer by cloning instead of mounting a local clone

[https://github.com/microsoft/vscode/issues/317971](https://github.com/microsoft/vscode/issues/317971)

## Summary

This workflow is owned by the VS Code Dev Containers extension and should be moved, preserving the thread, to the team's microsoft/vscode-remote-release tracker. An existing alternate-repository configuration mechanism may already cover the central request, but its suitability should be confirmed there.

## Change summary

Allow cloning a repository into a container volume while applying a locally maintained devcontainer configuration instead of the repository's configuration.

## Best solution

Ensure that Clone Repository in Container Volume accepts the local configuration selected through `remote.containers.repositoryConfigurationPaths`, and make that workflow discoverable; if the existing setting already provides this behavior, document it clearly rather than adding another configuration path.
