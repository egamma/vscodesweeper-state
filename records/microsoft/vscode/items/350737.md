# Issue #350737 — P2 FsLinkProvider scans the whole document in the extension host on every link request (~260 ms per call on a 25 MB JSON) because git registers a FileSystemProvider

[https://github.com/microsoft/vscode/issues/350737](https://github.com/microsoft/vscode/issues/350737)

## Summary

The reported synchronous full-document scan remains in current main, including for documents containing no registered-scheme links. Keep this open in the extension-host performance area; the source confirms the costly path, although the reported CPU timings were not independently measured.

## Change summary

Reduce repeated extension-host blocking caused by automatic file-system document-link discovery in large documents.

## Best solution

Make FsLinkProvider's negative-match path substantially cheaper while preserving existing custom-scheme link discovery, ranges, and registration behavior. Address the automatic provider rather than disabling all editor links or excluding built-in schemes.
