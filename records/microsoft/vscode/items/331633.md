# Issue #331633 — MCP app webview CSP missing worker-src - blocks blob-based Web Workers (e.g. MapLibre)

[https://github.com/microsoft/vscode/issues/331633](https://github.com/microsoft/vscode/issues/331633)

## Summary

Confirmed in current source: the MCP app webview's injected CSP in chatMcpAppModel.ts has no worker-src directive, so per spec it falls back to script-src (no blob: scheme) and blocks blob-based Web Workers used by libraries like MapLibre GL JS. This is a real, well-diagnosed gap that should be fixed.

## Change summary

MCP app webviews' injected Content-Security-Policy lacks a worker-src directive, blocking blob:-based Web Workers spawned by MCP UI resources (e.g. MapLibre GL JS tile workers).

## Best solution

Add `worker-src 'self' blob:;` to the CSP string built in `_injectPreamble` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatMcpAppModel.ts, alongside the other directives.

- **Fix prompt:**

  > In src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatMcpAppModel.ts, the private method `_injectPreamble` builds a Content-Security-Policy string (the `cspContent` template literal, around lines 266-277) that is injected as a <meta http-equiv="Content-Security-Policy"> tag into MCP app webview HTML. The template currently sets default-src, script-src, style-src, connect-src, img-src, font-src, media-src, frame-src, object-src, and base-uri, but has no worker-src directive. Per the CSP spec, when worker-src is unset, browsers fall back to script-src for Worker creation — and script-src has no blob: scheme allowance, so any MCP app resource that spawns a Web Worker from a blob: URL (e.g. MapLibre GL JS's tile-parsing workers) is blocked, with the worker/basemap silently failing to render (confirmed by the reporter's DevTools console error: 'Creating a worker from blob:vscode-webview://... violates ... worker-src was not explicitly set, so script-src is used as a fallback'). Fix by adding a `worker-src 'self' blob:;` line to the cspContent template, consistent in style with the other directives (do not use csp?.resourceDomains for this one since worker-src doesn't need the resource domain allowlist — 'self' and blob: are what's needed for the reported scenario). Do not change any other directive or restructure _injectPreamble/cleanDomains. Validate by adding or extending a unit test for the CSP construction (there may already be tests for chatMcpAppModel.ts's preamble injection) asserting the generated CSP content string contains 'worker-src' with 'self' and blob: — the test should fail on current main and pass after the change. Related upstream reference (not required for this fix): the MCP Apps reference host implementation already unconditionally sets worker-src 'self' blob: in its example host (modelcontextprotocol/ext-apps repo, examples/basic-host/serve.ts).
