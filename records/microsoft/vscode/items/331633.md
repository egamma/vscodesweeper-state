# Issue #331633 — MCP app webview CSP missing worker-src - blocks blob-based Web Workers (e.g. MapLibre)

[https://github.com/microsoft/vscode/issues/331633](https://github.com/microsoft/vscode/issues/331633)

## Summary

Confirmed current bug with an open fixing PR: the MCP app webview CSP omits `worker-src`, so Chromium falls back to `script-src` and blocks blob-based workers. Keep the issue open while https://github.com/microsoft/vscode/pull/332264 is reviewed.

## Change summary

Allow MCP app webviews to create blob-based Web Workers so libraries such as MapLibre can render correctly.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/332264, which adds `worker-src 'self' blob:` plus configured resource domains to the CSP assembled by `ChatMcpAppModel._injectPreamble`.

## Evidence

- **current source:** On current main, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatMcpAppModel.ts` constructs CSP directives in `_injectPreamble` with `script-src`, `style-src`, and other resource directives but no `worker-src`, leaving blob workers subject to the restrictive `script-src` fallback.
- **confirmed reproduction:** The reporter confirmed the same CSP violation on VS Code 1.134.0 at https://github.com/microsoft/vscode/issues/331633#issuecomment-5342508715: creating a `blob:vscode-webview://…` worker is blocked because `worker-src` is absent.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/332264 remains open, explicitly uses `Fixes #331633`, and adds `worker-src 'self' blob: ${cleanDomains(csp?.resourceDomains)};` to the affected CSP construction path.
