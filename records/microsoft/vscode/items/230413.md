# Issue #230413 — Let compound launch configs be the default

[https://github.com/microsoft/vscode/issues/230413](https://github.com/microsoft/vscode/issues/230413)

## Summary

VS Code already allows a compound to appear first and become the selected launch entry through its `presentation` metadata, while persisting the user's selected compound across workspace sessions. The duplicate-name workaround is unsupported and unnecessary.

## Change summary

Allow a compound debug configuration to be the default or first entry in the launch configuration picker.

## Best solution

Keep the existing uniform configuration-selection model: give the compound a `presentation.order` or `presentation.group` that places it first, then select it normally so VS Code persists that selection for the workspace.

## Vision fit

- **Fit:** aligned
- **Reason:** Making compound debugging easy to launch supports the developer inner loop, while the existing shared presentation mechanism preserves a simple and uniform UI.
- **Evidence:** Durable themes: developer inner loop and workbench/core UX; value: simple, uniform UI and UI interactions.

## Evidence

- **existing ordering capability:** `src/vs/workbench/contrib/debug/common/debugSchemas.ts` exposes `presentation.group` and `presentation.order` on compounds, specifically for grouping and sorting entries in the debug configuration dropdown.
- **current selection behavior:** `src/vs/workbench/contrib/debug/browser/debugConfigurationManager.ts` includes compounds in `getConfigurationNames()`, sorts them with `getVisibleAndSorted()`, selects the first sorted entry when no valid selection exists, and persists the selected name in workspace storage under `debug.selectedconfigname`.
- **implemented feature:** https://github.com/microsoft/vscode/issues/82332 documents the completed support for applying `presentation` grouping and sorting to both launch configurations and compounds.
- **maintainer guidance:** https://github.com/microsoft/vscode/issues/230413#issuecomment-2392361943 states that configurations and compounds are not expected to have duplicate names; the duplicate `App: All` entry should be removed.
