# Issue #139197 — Notebook File/Cell Sace and Recover Problem

[https://github.com/microsoft/vscode/issues/139197](https://github.com/microsoft/vscode/issues/139197)

## Summary

Current notebook undo/redo intentionally tracks cell insertion and deletion as structural operations, and deleted cells are recoverable. Later fixes addressed the concrete recovery failures, leaving this broad clarity request covered by the designed behavior.

## Change summary

Make notebook cell/file undo and recovery behavior clearer, particularly after accidentally deleting a cell.

## Best solution

Keep structural cell operations in the notebook undo stack and direct users to Undo after deletion or Redo when Undo removed a newly added cell; `notebook.undoRedoPerCell` controls whether cell editing uses separate stacks.

- **Proposed comment:**

  > Thanks for the report. Notebook cell insertion and deletion are intentionally part of the notebook-level undo/redo history. If Undo removes a cell by reversing its insertion, Redo restores it; if a cell is explicitly deleted, Undo restores it. The `notebook.undoRedoPerCell` setting controls whether editing within individual cells uses separate undo/redo stacks. The concrete recovery failures discussed in https://github.com/microsoft/vscode/issues/144102 were subsequently fixed and verified, so the current behavior is working as designed.
