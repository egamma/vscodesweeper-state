# Issue #297756 — forking didn't submit the prompt

[https://github.com/microsoft/vscode/issues/297756](https://github.com/microsoft/vscode/issues/297756)

## Summary

The gap remains on current main: chat parses the text following `/fork`, but the fork command ignores it and only opens the new session. This member-authored UX feedback should stay open as bounded chat polish rather than receive a judgment close.

## Change summary

When `/fork` is followed by prompt text, create the fork and submit that text in the forked session instead of discarding it.

## Best solution

Honor non-empty text following `/fork` by submitting it exactly once after the forked session opens, while preserving the existing standalone `/fork` and checkpoint-fork behavior.
