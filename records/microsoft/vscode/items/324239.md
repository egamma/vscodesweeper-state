# Issue #324239 — Session Window: When a notification disappears after some seconds, there is no status bar to bring it back

[https://github.com/microsoft/vscode/issues/324239](https://github.com/microsoft/vscode/issues/324239)

## Summary

The recovery affordance is still missing on current main: the Agents Window hides the status bar and its custom title bar does not consume the standard notification-button contribution. Keep this team-authored, under-discussion UX gap open.

## Change summary

Provide a persistent way in the Agents Window to reopen notifications after their toast disappears.

## Best solution

Expose the existing Toggle/Show Notifications command through an accessible persistent affordance in the Agents Window chrome, with visibility and unread-state behavior chosen consistently with the window's intentionally status-bar-free design.

## Plan brief

- **Behavior:**

  > After a notification toast times out in the Agents Window, users must retain a discoverable, keyboard-accessible way to reopen the notification center. Activating the affordance shows the existing notification history without changing toast timing or notification contents. The behavior should remain available in the status-bar-free desktop layout and expose a localized accessible name.
- **Trace:**

  > The Agents Window deliberately hides the Status Bar in src/vs/sessions/browser/workbench.ts and src/vs/sessions/LAYOUT.md. `createNotificationsHandlers` still constructs NotificationsStatus, whose bell is added through IStatusbarService, so that recovery path is invisible. The shared notification contribution in src/vs/workbench/browser/parts/notifications/notificationsCommands.ts targets MenuId.TitleBar, whereas TitlebarPart renders Sessions-owned menus from src/vs/sessions/browser/menus.ts; layoutActions.ts currently contributes other persistent chrome actions to Menus.TitleBarRightLayout. Preserve the shared notification model, commands, toast timing, accessible notification view, and the intentional absence of the Agents Window status bar.
- **Open decisions:**
  - Should the Agents Window notification affordance remain visible at all times like the standard notification bell, or appear only while notifications are retained or unread?

## Evidence

- **missing recovery surface:** src/vs/sessions/LAYOUT.md states that the Agents Window omits the standard Status Bar, and src/vs/sessions/browser/workbench.ts adds LayoutClasses.STATUSBAR_HIDDEN while still instantiating NotificationsStatus; consequently its status-bar entry cannot provide the normal bell affordance.
- **separate title-bar menus:** src/vs/workbench/browser/parts/notifications/notificationsCommands.ts contributes the notification bell to MenuId.TitleBar, but src/vs/sessions/browser/parts/titlebarPart.ts renders Sessions-owned menus such as Menus.TitleBarRightLayout instead. No notification command is contributed to those menus on current main.
- **existing partial workaround:** The existing `workbench.action.showNotifications` command remains registered in the Command Palette, but that discoverability-only path does not provide the persistent recovery affordance requested after a toast disappears.
- **canonical search:** Repository searches for disappearing notifications and Agents Window notification recovery found no older open issue with the same observable symptom; https://github.com/microsoft/vscode/issues/183567 concerns broader screen-reader notification improvements rather than this missing Agents Window affordance.
