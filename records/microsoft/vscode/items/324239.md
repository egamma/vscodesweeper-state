# Issue #324239 — Session Window: When a notification disappears after some seconds, there is no status bar to bring it back

[https://github.com/microsoft/vscode/issues/324239](https://github.com/microsoft/vscode/issues/324239)

## Summary

The gap remains on current main: the Agents Window omits the Status Bar and its custom title bar does not expose the core notification bell. Notification history remains available through the Command Palette and keybinding, but there is no persistent, discoverable replacement affordance.

## Change summary

Provide a persistent way to reopen notification history after an Agents Window toast disappears.

## Best solution

Expose the existing notification center through a persistent Agents Window affordance, with unread and visibility behavior consistent with the main workbench. A maintainer should first decide how the Agents Window's always-statusbar-free layout interacts with the existing notification position and button settings.

- **Reason:** Making transient notifications recoverable improves notifications hygiene and the usability of the AI-focused Agents Window.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/layoutActions.ts`, `src/vs/sessions/browser/menus.ts`, `src/vs/sessions/browser/parts/titlebarPart.ts`, `src/vs/sessions/test/browser/layoutActions.test.ts`
- **Validation:** Add an Agents Window layout-action test proving that a persistent notification-center action is registered under the chosen conditions and invokes the existing notification-center command; retain the existing notification command and title-bar tests.
- **Behavior:**

  > After a notification toast disappears in the Agents Window, users must have a persistent and discoverable way to reopen notification history. Activating that affordance opens the existing notification center, and activating it while the center is open follows the established toggle behavior. Existing Command Palette and keybinding access must remain unchanged.
- **Trace:**

  > The Agents Window deliberately omits Parts.STATUSBAR_PART in src/vs/sessions/browser/workbench.ts, while createNotificationsHandlers still instantiates the shared NotificationsStatus and notification center. NotificationsStatus publishes its bell through IStatusbarService, so that entry has no visible host here. The alternate core bell is contributed to MenuId.TitleBar in src/vs/workbench/browser/parts/notifications/notificationsCommands.ts, but the custom title bar in src/vs/sessions/browser/parts/titlebarPart.ts renders Sessions-owned menus instead. The notification model and center should remain shared; the unresolved boundary is the Sessions-owned presentation and how it should honor existing notification settings. https://github.com/microsoft/vscode/issues/322931 is related broader design work, not a canonical report of this symptom.
- **Open decisions:**
  - Should the Agents Window always show a notification-history affordance because it never has a Status Bar, or should visibility continue to follow the existing notification position and notification-button settings?

## Evidence

- **current layout:** src/vs/sessions/LAYOUT.md specifies that the Agents Window omits the standard Status Bar, and src/vs/sessions/browser/workbench.ts returns false for Parts.STATUSBAR_PART.
- **notification path:** src/vs/sessions/browser/workbench.ts still creates NotificationsCenter, NotificationsToasts, and NotificationsStatus and registers the shared notification commands, so notification history exists even though its status-bar entry cannot be displayed.
- **missing title-bar bridge:** src/vs/workbench/browser/parts/notifications/notificationsCommands.ts contributes the top-right notification bell to MenuId.TitleBar, while src/vs/sessions/browser/parts/titlebarPart.ts renders only Sessions-owned title-bar menus such as Menus.TitleBarRightLayout; no notification action is contributed to those menus.
- **existing fallback:** The `notifications.showList` command remains available from the Command Palette and through its registered keybinding, but neither is the persistent visual affordance requested by the issue.
- **related design issue:** https://github.com/microsoft/vscode/issues/322931 is an older, open Agents Window design exploration that mentions progress notifications, but it does not report the same observable inability to recover dismissed notification toasts and therefore does not meet the stronger duplicate bar for this re-reviewed item.
