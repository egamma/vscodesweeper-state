# Issue #237394 — Safeguard from accidently expanding huge folders

[https://github.com/microsoft/vscode/issues/237394](https://github.com/microsoft/vscode/issues/237394)

## Summary

The large-directory freeze remains reproducible and current main still materializes every resolved child. An open PR proposes paging, but it has not merged and explicitly leaves the underlying directory enumeration unbounded, so the issue should remain open.

## Change summary

Prevent Explorer expansion and restored expansion state from freezing or crashing VS Code when a directory contains an extreme number of entries.

## Best solution

Review and land or supersede https://github.com/microsoft/vscode/pull/320536, validating that it bounds Explorer model and DOM work while preserving sorting and filtering. Track any remaining freeze during the initial directory enumeration and ensure restored expansion state cannot repeatedly strand the workspace.

## Evidence

- **confirmed reproduction:** A commenter reproduced the freeze with `seq 1000000 | xargs touch` followed by `code --disable-extensions .` on VS Code 1.100.2, and later commenters reported that the problem still occurs in current versions.
- **current source:** On current main, `ExplorerDataSource.getChildren` in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` returns the complete result of `ExplorerItem.fetchChildren`; `ExplorerItem.create` in `src/vs/workbench/contrib/files/common/explorerModel.ts` recursively creates an item for every entry in `raw.children`. No paging or entry limit is present.
- **open implementation:** https://github.com/microsoft/vscode/pull/320536 is open and references this issue while adding per-directory paging. Its description states that the directory is still fully resolved and that the OS-level `readdir` remains unbounded.
- **related issue:** https://github.com/microsoft/vscode/issues/281507 reports the same observable Explorer freeze but was created on 2025-12-05, after this issue's 2025-01-07 creation date; under the re-review rule it cannot serve as the canonical duplicate for this older report.
