# Issue #136384 — Expose preRestartTask

[https://github.com/microsoft/vscode/issues/136384](https://github.com/microsoft/vscode/issues/136384)

## Summary

The restart-task hooks still exist internally but are absent from the shared launch.json schema, so the requested public configuration remains missing. Keep this accepted Backlog request open for a decision on exposing the hooks; the related reports do not provide an older open canonical.

## Change summary

Expose restart-specific lifecycle tasks in launch.json so users can configure work such as rebuilding before a debugger restart.

## Best solution

Decide whether preRestartTask and postRestartTask should become supported launch.json properties, with clearly documented ordering and restart coverage. If approved, expose them consistently with the existing task properties without changing established debug lifecycle behavior.

With tasks that append distinct markers, check initial launch, manual restart and automatic restart, confirming the documented ordering and preserving existing preLaunchTask/postDebugTask behavior.
- **Behavior:**

  > Users want a supported, discoverable way to configure restart-specific tasks in launch.json, particularly to rebuild code when manually restarting debugging without a watch task. The schema currently exposes launch and end tasks but not the internally recognized restart hooks. Acceptance should establish which hooks are public, verify their completion and validation, and demonstrate their documented execution during supported restart flows without changing existing launch behavior.
- **Trace:**

  > IEnvConfig in src/vs/workbench/contrib/debug/common/debug.ts already declares preRestartTask and postRestartTask. DebugAdapterManager.updateDebugAdapterSchema in src/vs/workbench/contrib/debug/browser/debugAdapterManager.ts publishes preLaunchTask and postDebugTask but neither restart property. DebugService.restartSession in src/vs/workbench/contrib/debug/browser/debugService.ts contains the existing task sequence, skips it for automatic restarts, and handles correlated test runs separately. These observations establish an exposure gap, not a missing runtime implementation; preserve existing task ordering and adapter behavior unless a maintainer explicitly chooses a different public contract. The exposure decision remains unresolved between the positions recorded at https://github.com/microsoft/vscode/issues/136384#issuecomment-960279642 and https://github.com/microsoft/vscode/issues/136384#issuecomment-960305000. Related embedded reset requests concern different restart expectations and should not silently expand this request into a redesign.
- **Open decisions:**
  - Should preRestartTask alone, or both preRestartTask and postRestartTask, become supported public launch.json properties?
  - Should the public contract retain the current ordinary manual-restart coverage, excluding automatic restarts and correlated test reruns, or must those flows also support the exposed hooks?
