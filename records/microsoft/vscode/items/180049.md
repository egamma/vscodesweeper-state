# Issue #180049 — [Accessibility]: Support filtering symbol types in Document Sylbol View

[https://github.com/microsoft/vscode/issues/180049](https://github.com/microsoft/vscode/issues/180049)

## Summary

Keep this accepted Backlog request open: breadcrumbs already support persistent symbol-kind filtering through settings, but do not expose the Problems-style interactive type filters requested here. No verified open canonical was found.

## Change summary

Provide accessible, interactive filtering by symbol kind in the document-symbol navigation view.

## Best solution

Make symbol-kind filtering discoverable and keyboard-operable in the breadcrumbs document-symbol picker, building on the existing kind-filtering capability. Decide whether picker selections temporarily narrow navigation or update the existing language-overridable settings.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/breadcrumbsPicker.ts`, `src/vs/workbench/browser/parts/editor/breadcrumbs.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts`, `src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts`
- **Validation:** In a document containing classes, methods, functions, and variables, open the breadcrumbs symbol picker with Ctrl/Cmd+Shift+period. Using only the keyboard, select symbol kinds and verify that excluded kinds disappear, included symbols remain navigable, and a screen reader announces filter labels and states. Verify clearing the filter restores the eligible symbols and persistence follows the chosen contract.
- **Behavior:**

  > Users should be able to narrow the breadcrumbs document-symbol picker by symbol kind through discoverable, keyboard-operable controls, analogous to severity filtering in the Problems view. Filter controls must expose their names and selected states to screen readers, and the remaining symbols must remain navigable. Acceptance includes filtering a mixed-kind document and restoring the unfiltered list. Whether selections persist beyond the picker remains a product decision.
- **Trace:**

  > The related report https://github.com/microsoft/vscode/issues/163506 identifies the surface as breadcrumbs document-symbol navigation, not only the Go to Symbol quick pick. BreadcrumbsOutlinePicker._createTree in src/vs/workbench/browser/parts/editor/breadcrumbsPicker.ts consumes the outline's tree options. DocumentSymbolsOutline in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts supplies DocumentSymbolFilter with the breadcrumbs prefix; that filter maps SymbolKind to language-overridable breadcrumbs.show* settings registered in breadcrumbs.ts. Thus kind filtering already exists, but the inspected picker exposes no interactive kind-selection surface. Preserve existing configured exclusions, symbol navigation, and symbol-kind announcements; general text filtering and the completed announcement work are not substitutes for this request.
- **Open decisions:**
  - Should interactive symbol-kind selections apply only while navigating the picker, or persist by updating the existing language-overridable breadcrumbs.show* settings?

## Evidence

- **Requested surface:** https://github.com/microsoft/vscode/issues/180049 asks for filtering specific symbol types, similar to the Problems view. Its linked context, https://github.com/microsoft/vscode/issues/163506, identifies Document Symbol View as the breadcrumbs navigation opened with Ctrl/Cmd+Shift+period.
- **Existing capability and remaining gap:** src/vs/workbench/browser/parts/editor/breadcrumbs.ts registers language-overridable settings including breadcrumbs.showClasses, breadcrumbs.showMethods, breadcrumbs.showFunctions, and breadcrumbs.showVariables. DocumentSymbolFilter.filter in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsTree.ts reads these kind-specific settings; DocumentSymbolsOutline selects that filter for OutlineTarget.Breadcrumbs. These settings provide persistent filtering, but BreadcrumbsOutlinePicker._createTree in src/vs/workbench/browser/parts/editor/breadcrumbsPicker.ts exposes no interactive symbol-kind selection controls.
- **Related work is not completion:** https://github.com/microsoft/vscode/issues/163506 is closed and addressed announcing symbol kinds to screen readers. Its verification comments confirm spoken symbol information, not selecting which kinds appear, so it does not complete this request.
