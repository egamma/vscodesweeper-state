# Issue #344494 — Agent Bakeoff: compare workflows with and without a skill, or before and after skill changes

[https://github.com/microsoft/vscode/issues/344494](https://github.com/microsoft/vscode/issues/344494)

## Summary

Keep open: current Compare Models supports model and reasoning variants, but not isolated skill enablement or version comparisons. The closely overlapping newer request does not meet the stronger duplicate bar for this re-reviewed issue.

## Change summary

Compare skill states or versions on the same task while holding other execution conditions fixed and retaining reproducible comparison evidence.

## Best solution

Support explicitly identified, attempt-scoped customization conditions through the existing comparison workflow and provider-owned runtime configuration. Preserve actual skill exclusion and version provenance, rather than approximating either with prompt instructions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/sessions/common/sessionComparison.ts`, `src/vs/workbench/contrib/sessions/browser/sessionComparisonService.ts`, `src/vs/workbench/contrib/sessions/browser/chat/sessionComparisonModelSelection.ts`, `src/vs/workbench/contrib/sessions/test/browser/sessionComparisonService.test.ts`
- **Validation:** Extend the SessionComparisonService suite to verify identical prompt, model, reasoning configuration, and starting revision across differently identified customization conditions, including restoration. Add provider-backed acceptance checks proving the disabled attempt cannot discover or invoke the skill and a versioned attempt retains its selected content after the source is edited.
- **Behavior:**

  > Users can compare a task with a skill enabled and genuinely excluded, or with two versions of that skill. Model, reasoning settings, prompt, starting repository state, and unrelated customizations remain identical. Each attempt identifies its skill condition and retains results, changes, validation evidence, elapsed time, and available token usage. Editing the original skill after launch must not silently change the conditions attributed to an attempt, and a judged winner must not be presented as proof of consistent improvement.
- **Trace:**

  > SessionComparisonModelSelection currently produces model/configuration variants, while ISessionComparisonHarness carries no customization condition or version identity. SessionComparisonService.startComparison launches peer sessions with shared task inputs; _createOptions forwards model configuration, permission intent, worktree isolation, and branch through ISessionsManagementService. SESSION_COMPARISONS.md explicitly leaves referenced attachment contents unfrozen, so attaching a skill file does not establish an immutable version comparison. AI_CUSTOMIZATIONS.md assigns runtime consumption and enablement to harness providers; the review has not established an attempt-scoped exclusion or snapshot contract across those providers. Preserve provider-neutral orchestration, existing model comparisons, permissions, advisory judging, and original attempt worktrees. https://github.com/microsoft/vscode/issues/346386 is overlapping design context, not an eligible duplicate target for this re-reviewed older report.
- **Open decisions:**
  - What constitutes the reproducible skill version: an immutable content snapshot, a repository revision, or an explicit versioned artifact, including any bundled dependencies?
  - Should launch reject a comparison when a selected provider cannot guarantee skill exclusion and version isolation, or permit a clearly marked unsupported condition?

## Evidence

These model variants do not deliver skill-on/off or before/after comparisons.
