# Issue #252076 — Feature Request: Auto-Trigger Parameter Hints When Cursor Enters Parentheses

[https://github.com/microsoft/vscode/issues/252076](https://github.com/microsoft/vscode/issues/252076)

## Summary

Cursor-entry triggering remains missing on current main. The linked implementation was closed without merging because it hardcoded parentheses; that rejects the approach, not the accepted Backlog request.

## Change summary

Automatically show parameter hints when navigating into an existing argument list and hide them when leaving it.

## Best solution

Design language-provider-aware cursor-entry triggering in the parameter hints contribution, preserving support for signature help outside parenthesized calls. Settle activation and dismissal semantics before implementation rather than reviving the rejected parentheses scanner.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/parameterHints/browser/parameterHintsModel.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/languages.ts`, `src/vs/editor/contrib/parameterHints/test/browser/parameterHintsModel.test.ts`
- **Validation:** Extend ParameterHintsModel tests using mock signature-help providers to cover keyboard and mouse entry into an existing call, leaving its context, nested and multiline calls, and a provider whose signature-help context is not parentheses-based. Verify disabled-mode behavior and existing typed/manual triggers remain unchanged.
- **Behavior:**

  > Navigating into an existing argument list should make parameter help available without typing a trigger character or invoking a command. Leaving the relevant signature-help context should dismiss it. Acceptance must cover mouse and keyboard navigation, nested and multiline calls, and languages whose signature help is not delimited by parentheses. Activation defaults and the effect of explicitly dismissing hints need agreement before implementation.
- **Trace:**

  > ParameterHintsModel.onCursorChange in src/vs/editor/contrib/parameterHints/browser/parameterHintsModel.ts cancels on mouse movement and only retriggers keyboard navigation when hints are already active or pending. Existing enabled/cycle configuration in src/vs/editor/common/config/editorOptions.ts and editor.action.triggerParameterHints do not initiate hints on entry. SignatureHelpProvider in src/vs/editor/common/languages.ts supplies results at a position but exposes no enclosing argument-context range. https://github.com/microsoft/vscode/pull/309364 was closed unmerged, with https://github.com/microsoft/vscode/pull/309364#issuecomment-4241963122 explicitly rejecting a core parentheses scanner. Preserve typed and manual invocation, cancellation, and language-provider authority; uncertainty begins with language-neutral context detection and the observable activation policy.
- **Open decisions:**
  - Should cursor-entry triggering be enabled by default or offered as an opt-in setting?
  - After explicit dismissal, should hints remain suppressed within the current call until the cursor leaves and re-enters, or reopen on subsequent movement inside it?
  - Should cursor-entry support require providers to identify a valid signature-help context, potentially extending their contract, or work with existing providers through position-based requests?
