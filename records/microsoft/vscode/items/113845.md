# Issue #113845 — Provide a "declaration" icon overlay

[https://github.com/microsoft/vscode/issues/113845](https://github.com/microsoft/vscode/issues/113845)

## Summary

Keep open: current symbol and completion APIs still lack declaration metadata and icon overlays. The earlier duplicate target is closed and delivered only deprecated tags; the C/C++ changes provide text-based workarounds, not the requested capability.

## Change summary

Allow extensions to visually distinguish declarations from definitions using symbol and completion icon modifiers, including combinations with access modifiers.

## Best solution

Agree on a language-neutral metadata and presentation contract for declaration markers across symbol and completion surfaces, then expose it through VS Code's extension API. Preserve symbol names and sorting rather than requiring extensions to encode modifiers in labels.

Verify distinguishable declaration icons in Outline and applicable completion entries without changing names, sorting, navigation, or insertion; verify ordinary and deprecated entries retain their behavior and the distinction remains understandable with a screen reader.
- **Behavior:**

  > Extensions need to distinguish declarations from definitions visually without adding textual markers to symbol names. The supplied C++ example requires declaration status to remain distinguishable alongside access status. Acceptance should cover Outline and the agreed completion surfaces while preserving names, sorting, navigation, and completion insertion. Existing unmarked and deprecated items must remain compatible.
- **Trace:**

  > The public SymbolTag and CompletionItemTag enums in src/vscode-dts/vscode.d.ts contain only Deprecated; corresponding internal contracts are in src/vs/editor/common/languages.ts. suggestWidgetRenderer.ts selects the normal completion icon from the base kind, and documentSymbolsTree.ts does the same for Outline, with separate deprecated-label handling. https://github.com/microsoft/vscode/issues/23927 established tag infrastructure but did not supply declaration metadata. https://github.com/microsoft/vscode-cpptools/pull/7556 supplies text-based scope labels, not icon composition. The remaining uncertainty is the language-neutral public contract and presentation scope, not whether the existing text workaround covers the request. Preserve existing symbol kinds, label semantics, sorting, and deprecated behavior; do not treat this as a C/C++-only rendering feature.
- **Open decisions:**
  - Should the initial public contract expose declaration status alone, or also standardized access modifiers to support the combinations requested in the examples?
  - Should presentation use composable overlays or distinct declaration variants, and which symbol and completion surfaces must support the initial contract?
