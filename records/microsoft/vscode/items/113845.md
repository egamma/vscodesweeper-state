# Issue #113845 — Provide a "declaration" icon overlay

[https://github.com/microsoft/vscode/issues/113845](https://github.com/microsoft/vscode/issues/113845)

## Summary

A real API and rendering gap remains: extensions can mark symbols and completions as deprecated, but cannot distinguish declarations with an icon overlay. The existing feature-request and editor-symbols routing remain appropriate.

## Change summary

Allow language extensions to mark declarations so symbol and completion icons display a declaration overlay.

## Best solution

Extend the existing SymbolTag and CompletionItemTag APIs with a declaration annotation, then render it consistently in symbol and completion surfaces while preserving the current base-kind icons.

- **Fit:** aligned
- **Reason:** A reusable language API that improves extension-provided symbol information supports the extension ecosystem and developer inner loop without adding standalone product surface.

## Evidence

- **current API gap:** src/vscode-dts/vscode.d.ts defines only SymbolTag.Deprecated and CompletionItemTag.Deprecated; neither enum supports declarations or visibility modifiers.
- **current rendering:** src/vs/editor/contrib/suggest/browser/suggestWidgetRenderer.ts handles CompletionItemTag.Deprecated as strike-through styling, while src/vs/editor/contrib/symbolIcons/browser/symbolIcons.css only colors base symbol-kind icons and provides no declaration overlay.
- **previous issue:** https://github.com/microsoft/vscode/issues/23927 is closed after introducing the general tag API with only Deprecated, so it cannot serve as an open canonical issue for the still-missing declaration tag.
