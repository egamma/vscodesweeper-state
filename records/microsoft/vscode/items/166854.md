# Issue #166854 — Drag'n'drop code in Debug Watch list

[https://github.com/microsoft/vscode/issues/166854](https://github.com/microsoft/vscode/issues/166854)

## Summary

The request remains a real, unimplemented Debug Watch workflow improvement. The related issues are newer, narrower reports and cannot serve as canonicals under the re-review duplicate rule; the existing Add to Watch command is useful but does not provide the requested drag-and-drop interaction.

## Change summary

Allow selected editor text or text from another source to be dragged into the Debug Watch view to create a watch expression.

## Best solution

Support a standard text/plain drag payload from editor selections and consume it in the Debug Watch tree to create a watch expression, while retaining the existing Debug: Add to Watch command as the keyboard-oriented path.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/dnd/browser/dnd.ts`, `src/vs/workbench/contrib/debug/browser/watchExpressionsView.ts`
- **Validation:** Add focused drag-and-drop tests that verify an editor selection is exposed as text/plain and that dropping a text/plain payload on the Watch view creates exactly one watch expression with that text.
- **Behavior:**

  > When debugging is active, dragging selected editor text into the Watch view creates a watch expression containing that text. Text dropped from another source through a text/plain payload should behave the same way. Existing editor text movement, Watch editing, and the Debug: Add to Watch command must remain unchanged. Acceptance requires focused tests for both payload production and Watch expression creation.
- **Trace:**

  > The discussion traces editor selection dragging to DragAndDropController in src/vs/editor/contrib/dnd/browser/dnd.ts, which historically did not populate the native data transfer object. The Watch view integration belongs in src/vs/workbench/contrib/debug/browser/watchExpressionsView.ts and should consume text/plain through its tree drop handling. The existing editor.debug.action.selectionToWatch command is a workaround, not coverage of the requested interaction. The newer related reports https://github.com/microsoft/vscode/issues/195547 and https://github.com/microsoft/vscode/issues/195548 describe narrower drag sources and do not replace this broader request. Preserve normal editor drag behavior and avoid changing debugger evaluation semantics.
- **Open decisions:**
  - Should the Watch view accept text/plain from any external source, or only text originating from VS Code editor selections?
