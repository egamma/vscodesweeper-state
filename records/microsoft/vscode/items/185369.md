# Issue #185369 — Delayed pty host startup can cause terminal service connection state to stay connecting

[https://github.com/microsoft/vscode/issues/185369](https://github.com/microsoft/vscode/issues/185369)

## Summary

Keep open: backend initialization and readiness handling have changed since the report, but no verified fixing commit or open canonical was found. The supplied startup-delay steps are sufficient to retest whether terminal connection state and keyboard focus recover.

## Change summary

Creating a terminal during delayed pty-host startup can leave terminal connection state stuck at Connecting and prevent Ctrl+` from focusing the terminal.

## Best solution

Establish whether the delayed-startup race remains in TerminalService initialization and TerminalViewPane focus handling, then ensure successful backend connection restores both Connected state and normal terminal-toggle focus behavior.

## Evidence

- **Concrete reproduction:** https://github.com/microsoft/vscode/issues/185369 specifies terminal.integrated.developer.ptyHost.startupDelay=10000, a window reload, terminal creation before connection, and Ctrl+` after connection. The setting remains supported in src/vs/platform/terminal/electron-main/electronPtyHostStarter.ts:101-103 and src/vs/platform/terminal/node/ptyHostMain.ts:30-48.
- **Current connection path:** src/vs/workbench/contrib/terminal/browser/terminalService.ts:277-340 sets Connecting during _initializePrimaryBackend and calls _setConnected after the reconnection promise resolves. _setConnected at lines 446-449 sets Connected and fires the change event. This identifies the relevant path but does not conclusively establish the reported delayed-startup failure on current main.
- **Focus depends on connection state:** src/vs/workbench/contrib/terminal/browser/terminalView.ts:325-348 calls showPanel(true) immediately when Connected; otherwise it waits for onDidChangeConnectionState and conditionally restores focus. A terminal that remains Connecting would therefore take the deferred-focus path described in the report.
- **Related report consolidates here:** https://github.com/microsoft/vscode/issues/185365 is closed, and https://github.com/microsoft/vscode/issues/185365#issuecomment-1595104940 explicitly tracks its terminal-toggle focus failure in this issue. It is not an open duplicate target.
- **Timeout report is separate:** The reporter directed the comment about startup timeouts and unresponsiveness to https://github.com/microsoft/vscode/issues/130320#issuecomment-1593543637. That comment describes heartbeat timing, notification, and diagnostic changes, not a confirmed fix for this issue's stuck connection state.

Commit https://github.com/microsoft/vscode/commit/ed54d72d8c3e068055e57416d42c9cf5fc0921c3 adds backend readiness notification after the existing _setConnected call. Neither diff establishes that this report's trigger is resolved, and an explicit commit search for 185369 returned no matches.
