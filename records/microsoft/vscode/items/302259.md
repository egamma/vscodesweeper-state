# Issue #302259 — Confusing UX when you accidentally add args to `/yolo`

[https://github.com/microsoft/vscode/issues/302259](https://github.com/microsoft/vscode/issues/302259)

## Summary

Valid polish issue from a team member. The `/yolo` (and `/models`) slash commands are designed to execute immediately via the completion menu, but when a user manually types `/yolo say hi` and presses Enter, nothing visibly happens — no feedback, no error, no indication the command ran or that extra arguments are ignored. The confusing UX remains on current main.

## Change summary

Typing `/yolo say hi` (with extra text after the slash command) in the chat input and pressing Enter produces no visible feedback — nothing happens.

## Best solution

For `executeImmediately` slash commands that don't accept arguments, either strip trailing text and execute the command with visible feedback (e.g. a brief notification or status change), or prevent additional text entry after the command is accepted in the input. The fix likely lives in `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts` (input handling) and/or `src/vs/workbench/contrib/chat/browser/chatSlashCommands.ts` (command execution). A comment from the team also notes `/models` has the same issue.

## Evidence

- **executeImmediately path:** In src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts lines 162-167 and 211-217, `executeImmediately` commands clear the insertText and auto-submit via ChatSubmitAction. This only triggers when selected from the completion menu, not when the user manually types the command with extra text.
- **silent flag:** The /yolo command is registered with `silent: true` (chatSlashCommands.ts line 460), meaning it produces no visible response — so when manually submitted with extra args, the user sees literally nothing happen.
- **team confirmation:** Comment by @justschen confirms the issue and notes /models has the same problem — the design expects `/yolo` → Enter, not `/yolo and keep typing`.
- **no fix on main:** git log since the issue was filed shows no commits addressing the extra-arguments handling for executeImmediately slash commands.
