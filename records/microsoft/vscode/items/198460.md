## Summary

The reporter describes data loss from cloud changes resuming stale edits, but the report is from 2023, lacks reproduction steps, and the feature already has conflict detection for SCM-tracked changes. The edge case (external editor modifying files without VS Code's SCM awareness) is plausible but unconfirmed on current main.

## Change summary

Cloud Changes (edit sessions) can silently overwrite local file contents when changes were made by an external editor not tracked by VS Code's SCM service.

## Best solution

Confirm whether this still reproduces on current main. The conflict detection in `editSessions.contribution.ts` (line 635-651) relies on `scmService.repositories` to detect local changes — edits made entirely outside VS Code may not appear there. If confirmed, the fix would extend `willChangeLocalContents` to compare file content hashes against the stored cloud state regardless of SCM tracking.
