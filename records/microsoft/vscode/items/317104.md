# Issue #317104 — Testing with responses API leads to ZDP error

[https://github.com/microsoft/vscode/issues/317104](https://github.com/microsoft/vscode/issues/317104)

## Summary

The ZDP error is a real issue for BYOK users whose orgs enforce Zero Data Retention. A manual workaround exists (`zeroDataRetentionEnabled: true` in model config), and retry logic for invalid stateful markers was improved in c317ef008da, but no commit references this issue — and no automatic ZDP detection exists yet. Keeping open as a team-authored item.

## Change summary

Using the Responses API with an org that enforces Zero Data Retention fails with a 400 error because `previous_response_id` is sent despite the server refusing to retain responses.

## Best solution

Either auto-detect ZDP enforcement from the 400 error response and retry without `previous_response_id` (a graceful fallback in the endpoint layer), or surface a clearer error message guiding users to set `zeroDataRetentionEnabled`. The manual config workaround works but is not discoverable. The retry logic in `extensions/copilot/src/extension/byok/node/openAIEndpoint.ts` and the `InvalidStatefulMarker` response type already provide infrastructure for this.
