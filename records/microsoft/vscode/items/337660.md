# Issue #337660 — Agents Window: Unable to mark deleted file as viewed

[https://github.com/microsoft/vscode/issues/337660](https://github.com/microsoft/vscode/issues/337660)

## Summary

Confirmed source bug: the reviewed/viewed matching logic for changeset files still keys off `modifiedUri ?? originalUri`, which is `undefined`/a content-snapshot URI for deletions instead of the workspace path — so toggling review state on a deleted file throws and silently no-ops.

## Change summary

Toggling 'Viewed' on a deleted file in the Agents Window changes view has no effect.

## Best solution

Switch the three duplicated `modifiedUri ?? originalUri` lookups to resolve via `change.uri` for `IChatSessionFileChange2` (mirroring the existing `sessionFileChangeUri` helper), so deleted files can be matched and marked reviewed.

## Evidence

- **root cause: setReviewState:** src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionChangesets.ts:492-500 finds the changeset file via `isEqual(change?.modifiedUri, resource) || isEqual(change?.originalUri, resource)`. For deletions, diffToChange (agentHostDiffs.ts:42-74) sets `modifiedUri: undefined` and `originalUri` to a before-content snapshot URI, never the workspace path — so the find always fails and the method throws `Resource '...' is not part of changeset`.
- **resource identity:** The resource passed to the action is `getChangeResource(change)` (changesMultiDiffSourceResolver.ts:41-43), which is `change.uri` for IChatSessionFileChange2 — the very field the lookup omits.
- **documented convention:** agentHostSessionChangesets.ts:39-50 defines `sessionFileChangeUri()` with a comment explicitly warning that `modifiedUri` is absent and `originalUri` is a pre-edit snapshot for deletions, and that `uri` must be used instead — but this helper isn't used in `setReviewState`, nor in the two other reviewed-files computations.
- **duplicated bug:** The same `modifiedUri?.toString() ?? change.originalUri?.toString()` pattern is repeated in changesetReviewActions.ts:60-63 and changesViewService.ts:753-759, both feeding the 'toggled' UI state.
- **existing test harness:** src/vs/sessions/contrib/changes/test/browser/changesetReviewActions.test.ts already exercises ChangesetReviewAction with mocked IChangesViewService; extending it with an IChatSessionFileChange2-shaped deleted change (uri set, modifiedUri undefined) would pin the fix.
