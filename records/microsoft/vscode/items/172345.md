# Issue #172345 — Optimize IPC traffic when saving notebooks (large notebooks slow over Remote-SSH?)

[https://github.com/microsoft/vscode/issues/172345](https://github.com/microsoft/vscode/issues/172345)

## Summary

Keep open: the experimental extension-host save path addresses part of the IPC overhead, but subsequent reports describe severe delays even with it enabled. The discussion contains confirmed reproductions and sufficient steps to retest; neither full resolution nor an eligible canonical duplicate is established.

## Change summary

Reduce notebook save and output-synchronization traffic so large remote notebooks do not saturate the connection and delay subsequent cell execution.

## Best solution

Retest the documented large-output scenarios and distinguish save serialization traffic from notebook output synchronization, then address the remaining redundant transfers in the core notebook bridge. Preserve the extension-host save optimization rather than treating its initial implementation as completion of the broader performance problem.
