# Issue #273511 — Markdown - better handle command links that are not enabled

[https://github.com/microsoft/vscode/issues/273511](https://github.com/microsoft/vscode/issues/273511)

## Summary

Still unfixed on main: when a markdown hover specifies `enabledCommands`, command links not in that array are rendered as normal clickable links but silently do nothing on click. The openerService returns `true` at line 43 of `src/vs/editor/browser/services/openerService.ts` to suppress other openers, but no upstream rendering step distinguishes these disabled links visually. This is a valid polish issue — the author is a team member and it's in Backlog, so it stays open.

## Change summary

Command links not in a hover's `enabledCommands` array appear clickable but silently do nothing when clicked.

## Best solution

Either strip the link styling from command URIs not in `enabledCommands` during markdown rendering (so they appear as plain text), or render them with a distinct disabled style and a tooltip explaining the command is not available. The rendering change would likely live in the markdown-it token processing in `src/vs/base/browser/markdownRenderer.ts` or in the opener callback wiring in `src/vs/platform/markdown/browser/markdownRenderer.ts`.
