## Summary

Keep open: an independent commenter confirms missing inline per-hunk review in 1.148, and the reporter additionally documents missing working-set entries with the setting enabled. Existing review support does not establish that this failure is fixed, and no verified canonical absorbs the full report.

## Change summary

Copilot harness edits lack working-set entries and file/hunk Keep/Undo controls that appear for equivalent Local harness edits.

## Best solution

Restore the existing Agent Host review workflow for the reported edits, including the no-workspace case. Diagnose whether changes are absent from the host Working Set or lost during session resolution, preference binding, or editor entry synchronization.

- **Behavior:**

  > Fresh Copilot harness edits should participate in the existing pending-change review workflow, including edits to an opened disk file when no workspace is open. The working set should list recorded pending files, and supported text changes should expose inline file/hunk Keep and Undo. Decisions should synchronize between the editor and working set without losing unrelated user edits. Acceptance must cover both creation and a subsequent edit, with Local as the behavior comparison.
- **Trace:**

  > AgentHostSessionHandler combines the working-set configuration and the separately persisted Keep/Undo preference before attaching AgentHostEditReview to AgentHostSnapshotController. AgentHostEditReview resolves the session and subscribes to its advertised WorkingSet changeset, constructs review entries, and delegates file/hunk acceptance or discard to the host. The report establishes missing entries as well as missing controls, while the independent comment confirms the inline symptom on 1.148; source inspection did not identify which stage fails. First reproduce the no-workspace scenario and distinguish absent host change recording from session-resolution, preference, or entry-synchronization failures. Preserve host-owned decisions, advertised resource identity, and unrelated user edits. https://github.com/microsoft/vscode/issues/339363#issuecomment-6346982654 settles the intended review workflow; the multi-root report at https://github.com/microsoft/vscode/issues/346490 is related but not equivalent.
