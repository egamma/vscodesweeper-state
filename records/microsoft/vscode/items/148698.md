# Issue #148698 — Allow to restore all fullscreen windows

[https://github.com/microsoft/vscode/issues/148698](https://github.com/microsoft/vscode/issues/148698)

## Summary

Keep open as an upstream limitation: Electron's linked report remains open, and current VS Code explicitly prevents restoring multiple native fullscreen windows on the same macOS display. The existing fullscreen restoration setting does not cover this case.

## Change summary

Restore every previously fullscreen workspace window to fullscreen after restarting VS Code, including multiple windows on one macOS display.

## Best solution

Resolve the native fullscreen limitation tracked in electron/electron, then retire VS Code's one-fullscreen-window-per-display workaround once the adopted Electron behavior supports restoring all windows. Retest the separately reported Windows behavior rather than assuming the macOS diagnosis explains it.

## Evidence

- **Confirmed upstream ownership:** The discussion identifies https://github.com/electron/electron/issues/34367 as the cause. That issue is currently OPEN and provides a two-BrowserWindow reproduction where fullscreen: true is ignored for the second window. Its maintainer clarification says multiple fullscreen windows can restore on different displays: https://github.com/electron/electron/issues/34367#issuecomment-1217971130.
- **Current source retains the limitation:** src/vs/platform/windows/electron-main/windowsStateHandler.ts:150-154 explicitly documents the workaround for electron/electron issue 34367. In saveWindowsState(), lines 203-206 change a non-active native fullscreen window's saved mode to WindowMode.Normal when another fullscreen window occupies the same display on macOS. This directly preserves the reporter's restart outcome; it is not a completed fix.
- **Existing capability is insufficient:** window.restoreFullscreen is registered in src/vs/workbench/electron-browser/desktop.contribution.ts:197-201. WindowsStateHandler.getNewWindowState() permits fullscreen restoration when lifecycleMainService.wasRestarted or window.restoreFullscreen is true, but this cannot restore windows whose saved mode was already changed to Normal by the per-display workaround.
- **Maintainer intent:** https://github.com/microsoft/vscode/issues/158946#issuecomment-1226957317 explicitly states the desired end state is fixing this issue and the Electron limitation so the workarounds can disappear. Closing that narrower display-placement issue did not resolve or decline restoring all fullscreen windows.
- **Canonical search:** An open-issue search for fullscreen restoration and multiple windows found no verified older canonical owning this request. https://github.com/microsoft/vscode/issues/195449 is open but newer and concerns a fullscreen window restoring on the wrong display, not additional windows restoring windowed; it does not meet the re-review duplicate bar.
- **Related reports do not establish completion:** https://github.com/microsoft/vscode/issues/150790 concerns missing title-bar controls after the same restoration failure, not restoration of every fullscreen window. https://github.com/microsoft/vscode/issues/149655 reports Windows restoration behavior and was closed as a duplicate; the current macOS-only workaround does not establish its Windows root cause or resolution.
