# Issue #278104 — TypeError: items is not iterable

[https://github.com/microsoft/vscode/issues/278104](https://github.com/microsoft/vscode/issues/278104)

## Summary

The root-cause ordering bug in FromEventObservable.handleEvent is still present on main — only a call-site workaround was applied in the Copilot extension. The issue remains valid for the underlying observable infrastructure fix.

## Change summary

FromEventObservable.handleEvent sets _hasValue after notifying subscribers, allowing onLastObserverRemoved to reset _value to undefined mid-notification, causing 'items is not iterable' TypeError.

## Best solution

Fix the ordering in FromEventObservable.handleEvent (src/vs/base/common/observableInternal/observables/observableFromEvent.ts) by setting _hasValue = true before notifying subscribers, as detailed in the analysis in comment 5. This eliminates the race at its root rather than guarding each call site. Consider whether this issue or #314122 should be the canonical tracker for the root-cause fix.

- **Fix prompt:**

  > The bug is an ordering issue in FromEventObservable.handleEvent in src/vs/base/common/observableInternal/observables/observableFromEvent.ts. In the handleEvent method, when didChange is true and _hasValue is true, the code sets `this._value = newValue` (line ~110), then notifies subscribers via subtransaction (lines ~112-124), then sets `this._hasValue = true` (line ~125). If a subscriber's handleChange causes the last observer to unsubscribe, onLastObserverRemoved runs synchronously during the subtransaction, resetting `_value = undefined` and `_hasValue = false`. After the subtransaction returns, `_hasValue = true` executes, leaving _hasValue=true but _value=undefined — an inconsistent state. The next get() returns undefined, which crashes callers expecting an iterable. Fix: move `this._hasValue = true` to just after `this._value = newValue` and before the subtransaction block, so even if onLastObserverRemoved resets both fields during notification, the state remains consistent. Do NOT change onLastObserverRemoved's reset behavior or the subtransaction flow. Validate with a unit test in src/vs/base/test/common/observableInternal/ that creates a FromEventObservable, subscribes an autorun whose callback causes all observers to unsubscribe (triggering cleanup), fires the event, then re-subscribes and asserts the value is correct (not undefined). See also https://github.com/microsoft/vscode/issues/278104 comment 5 for the full analysis and https://github.com/microsoft/vscode/issues/314122 for the related regression.
