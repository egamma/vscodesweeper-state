# Issue #75835 — Allow QuickPicks to show right-aligned text like "recently opened" in the command palette

[https://github.com/microsoft/vscode/issues/75835](https://github.com/microsoft/vscode/issues/75835)

## Summary

Keep open: extensions can now supply right-aligned separator labels, but cannot independently place supplementary text at the right of an arbitrary selectable item. The reporter explicitly distinguished those capabilities, and a maintainer subsequently consolidated a description-alignment request into this issue.

## Change summary

Allow extensions to display right-aligned supplementary text on individual QuickPick items.

## Best solution

Provide a consistent, opt-in QuickPick item presentation contract for right-aligned supplementary information, preserving existing descriptions and section separators. Settle whether this means aligning the existing description or introducing independent item metadata before implementation.

- **Fit:** aligned
- **Reason:** Exposing a reusable presentation capability lets extensions use the built-in QuickPick consistently rather than inventing their own UI.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/workbench/api/common/extHostQuickOpen.ts`
- **Validation:** Exercise an extension-created QuickPick with multiple selectable items carrying different supplementary texts, with and without separators. Verify the chosen API renders that information at the right on each intended item, remains usable with filtering and narrow widths, and leaves existing descriptions and section labels unchanged when the option is absent.
- **Behavior:**

  > Extensions should be able to associate right-aligned supplementary text with individual selectable QuickPick items without representing that information as a section separator. Current separator support supplies group labels but does not cover the reporter's clarified item-level request. Acceptance should cover multiple independently annotated items, filtering, narrow picker widths, and unchanged default presentation.
- **Trace:**

  > QuickPickItem in src/vscode-dts/vscode.d.ts exposes label, description, detail, and kind, but no alignment or independent trailing-text contract. ExtHostQuickOpen in src/vs/workbench/api/common/extHostQuickOpen.ts serializes separator labels separately from ordinary item descriptions. QuickInputList.setElements in src/vs/platform/quickinput/browser/quickInputList.ts attaches buttonless separators to the following item, and its item renderer displays their labels separately from IconLabel descriptions. The reporter explicitly rejects equating section grouping with item metadata at https://github.com/microsoft/vscode/issues/75835#issuecomment-504981997; the description-alignment request https://github.com/microsoft/vscode/issues/199609 was subsequently consolidated here. Preserve existing separator semantics, default description placement, selection, and filtering. The uncertainty is the public presentation contract, not whether separator labels already exist.
- **Open decisions:**
  - Should extensions right-align the existing QuickPickItem.description, or supply separate trailing metadata that can coexist with the normal description?
