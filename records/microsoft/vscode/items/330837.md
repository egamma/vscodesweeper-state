# Issue #330837 — Agent Sessions: GitHub MCP tools lost permanently after a credential failure — no retry, no reset path, no error surfaced

[https://github.com/microsoft/vscode/issues/330837](https://github.com/microsoft/vscode/issues/330837)

## Summary

Detailed, methodical report (deliberately split from #327640) showing the Agent Host → headless Copilot CLI GitHub credential handoff has no retry/reset path and fails silently once it 401s — this is a real gap in the agent-host/copilot code, not the CLI or account.

## Change summary

After a GitHub token is invalidated once, the headless Copilot CLI process backing Agent Sessions permanently drops the built-in GitHub MCP server with no retry, no reset UI, and no visible error, even after re-auth.

## Best solution

In src/vs/platform/agentHost/node/copilot/copilotAgent.ts, the 401-driven `_handleCopilotSessionAuthRequired`/`_authenticationRequired` observable and `updateGitHubCredentials`/`authenticate` push path need to actually retry the GitHub MCP handoff for headless agent-session CLI processes (not just the interactive/model-refresh paths), and the resulting `AuthRequiredReason.Expired` state needs a real, working user-facing affordance — tying into the same gap already tracked by https://github.com/microsoft/vscode/issues/327640 for the notification link itself.

## Evidence

- **credential push path:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:1399-1455 (_applyGitHubToken/authenticate) pushes a new token via session.updateGitHubCredentials() only when the IDE-side GitHub session changes; it has no mechanism tied to a headless agent-session CLI subprocess retrying a 401'd MCP handoff on its own.
- **401 signal exists but is narrow:** copilotAgent.ts:1479-1484 _handleCopilotSessionAuthRequired sets an `_authenticationRequired` observable (AuthRequiredReason.Expired) only from isCopilotSdkAuthRejection in copilotAgentSession.ts:4404-4405 and from the interactive model-refresh 401 path (copilotAgent.ts:1692-1694) — no code path was found that reruns the initial GitHub MCP token handoff (_initialGitHubMcpToken, copilotAgentSession.ts:1999-2015) after such a signal fires for a headless/no-auto-login CLI process.
- **related issue:** https://github.com/microsoft/vscode/issues/327640 tracks the companion UI gap (the 'Authenticate' notification link being a no-op / silent completion) that this report was deliberately split off from to isolate the retry/reset/error-surfacing gap.
