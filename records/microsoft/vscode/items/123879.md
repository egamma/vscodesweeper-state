# Issue #123879 — Debugger: Smart Step Into

[https://github.com/microsoft/vscode/issues/123879](https://github.com/microsoft/vscode/issues/123879)

## Summary

Targeted stepping and source-range previews already exist, but the requested direct editor interaction and discoverability improvements remain unresolved. Keep this as the canonical request: related modifier-click work was explicitly consolidated here, and the later comments identify limitations beyond the shipped picker.

## Change summary

Make stepping into a selected call within a compound expression discoverable and efficient through source-level target selection.

## Best solution

Build on the existing DAP step-target support with an intentional, keyboard-accessible source-selection interaction that makes target locations clear without requiring context-menu navigation. Settle the activation gesture with the debug maintainers while preserving ordinary stepping and Go to Definition.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugCommands.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorActions.ts`, `src/vs/workbench/contrib/debug/browser/debugEditorContribution.ts`
- **Validation:** With an adapter reporting ranged step targets, pause before console.log(add(f1(), f2())) and verify the chosen interaction identifies and enters add without stopping inside f1 or f2. Repeat using keyboard-only selection, repeated call labels, cancellation, and an adapter without target-range support; verify ordinary Step Into and Go to Definition remain unchanged.
- **Behavior:**

  > Users debugging a compound expression should be able to identify and enter a particular call without navigating through unrelated argument calls or repeatedly opening context menus. Source locations should distinguish targets even when their labels repeat or are ambiguous. The chosen interaction must work with keyboard navigation and must not accidentally replace ordinary stepping or definition navigation. Acceptance should cover entering add in console.log(add(f1(), f2())), cancellation, and adapters lacking positional target information.
- **Trace:**

  > workbench.action.debug.stepIntoTarget in src/vs/workbench/contrib/debug/browser/debugCommands.ts already requests DAP targets, previews a selected target's source range, and steps using its ID. StepIntoTargetsAction in browser/debugEditorActions.ts provides cursor-position targeting with a context-menu fallback; ordinary Step Into remains separate. JavaScript adapter support landed in https://github.com/microsoft/vscode-js-debug/pull/1307, and the UI improvements in https://github.com/microsoft/vscode/pull/152131 cover only part of this request. https://github.com/microsoft/vscode/issues/153833 was consolidated into this issue specifically for modifier-click interaction. The uncertainty is the remaining user-facing activation and selection design, not target enumeration itself. Preserve capability gating, existing picker fallback, ordinary stepping, and definition navigation; earlier maintainers rejected implicit caret-based targeting as too surprising.
- **Open decisions:**
  - Should the remaining source-level interaction activate through an explicit target-selection command, a modifier-held mouse gesture, or both?
  - Should activation display all available target ranges for selection, or act directly on the target under the pointer or caret?
