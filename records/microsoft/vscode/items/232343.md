# Issue #232343 — Comments broken in markdown codeblock

[https://github.com/microsoft/vscode/issues/232343](https://github.com/microsoft/vscode/issues/232343)

## Summary

Keep this accepted editor-comments request open: current source still chooses the comment language at column 1 rather than where the code begins. No existing setting covers the requested behavior, and the related reports do not qualify as duplicate targets.

## Change summary

Make line-comment commands use TypeScript comments inside indented Markdown code fences instead of enclosing the code in HTML comments.

## Best solution

Have editor line-comment commands respect the embedded language of the code being commented while preserving Markdown indentation and existing mixed-language selection behavior. Retain the feature-request classification pending the area's decision on that behavior.

## Evidence

- **Current command path:** src/vs/editor/contrib/comment/browser/comment.ts routes editor.action.commentLine and editor.action.addCommentLine through LineCommentCommand. In src/vs/editor/contrib/comment/browser/lineCommentCommand.ts, _gatherPreflightCommentStrings and _gatherPreflightData query getLanguageIdAtPosition(startLineNumber, 1); _executeBlockComment also queries column 1 but inserts delimiters at the first non-whitespace column. This retains the language-selection/insertion-position mismatch described in https://github.com/microsoft/vscode/issues/232343.
- **Embedded-language boundary:** extensions/markdown-basics/syntaxes/markdown.tmLanguage.json defines fenced_code_block_ts with meta.embedded.block.typescript content and separately consumes list-continuation indentation in the lists rule. extensions/markdown-basics/package.json maps that embedded scope to typescript; extensions/markdown-basics/language-configuration.json supplies HTML block comments for Markdown. Leading Markdown whitespace therefore matters to the command's column-1 language lookup.
