# Issue #244166 — MCP: support server sessions connections per-edit session

[https://github.com/microsoft/vscode/issues/244166](https://github.com/microsoft/vscode/issues/244166)

## Summary

Team-authored feature request (connor4312, MEMBER) for per-chat-session MCP server connections — hard keep-open. Current main passes `vscode.conversationId` in `_meta` on tool calls and threads `chatSessionResource` through the gateway, but does not spin up separate server instances per chat session. The core ask (each chat gets its own sandbox/connection) remains unimplemented.

## Change summary

Support separate MCP server session connections per edit/chat session so that each chat can have its own isolated server sandbox.

## Best solution

Extend the MCP server lifecycle so a server definition can declare per-session isolation (e.g. a `sessionScope` flag), causing VS Code to spin up a dedicated server instance for each chat session rather than sharing one. The gateway already threads `chatSessionResource`; the missing piece is server-level lifecycle management in `src/vs/workbench/contrib/mcp/common/mcpServer.ts` and the surrounding service layer.
