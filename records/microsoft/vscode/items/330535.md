# Issue #330535 — Performance logging starts unexpectedly and keyboard shortcuts stop working

[https://github.com/microsoft/vscode/issues/330535](https://github.com/microsoft/vscode/issues/330535)

## Summary

Thanks for the report, but this is a single, one-day-old report with a thin repro and no confirmation of what actually triggered the profiling — needs more detail before it can be routed or closed.

## Change summary

A performance-logging notification appears unexpectedly (without the user starting a profiling session), and afterwards keyboard shortcuts stop responding until VS Code is restarted.

## Best solution

Likely explanation: VS Code's built-in `ExtensionsAutoProfiler` (src/vs/workbench/contrib/extensions/electron-browser/extensionsAutoProfiler.ts) automatically profiles the extension host when it detects it has become unresponsive — this is intentional diagnostic behavior, not an unprompted user-facing 'start profiling' action. The actual defect, if any, is likely that the Codex or Claude Code extension is blocking the extension host's event loop (hence shortcuts freezing), which is what triggers the auto-profiler. Ask the reporter to confirm on 1.133, capture the exact notification text, and check the Extensions view / Output for which extension the auto-profiler blamed.
