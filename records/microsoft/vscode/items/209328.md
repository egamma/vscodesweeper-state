# Issue #209328 — Diff Editor - moved code block indicator interferes with menu rendering

[https://github.com/microsoft/vscode/issues/209328](https://github.com/microsoft/vscode/issues/209328)

## Summary

Keep open: the current moved-block overlay still fails to account for the hunk-action gutter in its horizontal geometry, allowing it to obscure the menu. This issue is already correctly routed and is the maintainer-established canonical for an independently reported instance.

## Change summary

Prevent moved-code indicators and their background from obscuring diff-editor hunk actions.

## Best solution

Make moved-code indicators coexist with the hunk toolbar so stage and revert actions remain visible and usable. Address the overlay geometry and painting interaction in the diff editor without changing move detection or hunk-action semantics.

## Evidence

- **Current source geometry:** src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts:150–168 reserves both gutterWidth and movedBlocksLinesWidth between the editors. In features/movedBlocksLinesFeature.ts, MovedBlocksLinesFeature positions its SVG at the original editor's right edge and calculates arrow endpoints using scrollbar width, move-track width, and modified contentLeft, but receives no gutter width. Consequently, with the 35-pixel DiffEditorGutter present, the destination arrow and its background are displaced toward the toolbar.
- **Overlay painting:** features/gutterFeature.ts prepends the action gutter to the diff-editor root; features/movedBlocksLinesFeature.ts appends the SVG containing an 18-pixel-high arrow-rectangle. src/vs/editor/browser/widget/diffEditor/style.css fills that rectangle with editor-background and gives neither the SVG nor the gutter an explicit stacking priority that protects the toolbar. This preserves the reported overlap path on current main.
