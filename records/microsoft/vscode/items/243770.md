# Issue #243770 — Some macOS window tiling Keyboard Shorcuts not working properly even if remapped

[https://github.com/microsoft/vscode/issues/243770](https://github.com/microsoft/vscode/issues/243770)

## Summary

This is the same underlying issue as #228850 (closed): macOS window tiling shortcuts conflict with VS Code's default keybindings, and macOS App Shortcut remapping fails due to menu item name conflicts. The maintainer's position in #228850 is that this is how macOS keybinding registration works and VS Code won't change its defaults.

## Change summary

macOS Sequoia window tiling keyboard shortcuts (Center, Left, Right, Top, Bottom, Quarters) don't work in VS Code even when remapped via System Settings App Shortcuts.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/228850 — the maintainer explanation there applies directly: users must either remap VS Code's conflicting keybindings (e.g. scrollLineUp/scrollLineDown) or use fully qualified menu paths (e.g. 'Move & Resize > Left') in macOS App Shortcuts to avoid name collisions with VS Code menu items.
