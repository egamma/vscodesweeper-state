# Issue #271215 — Switch for Markdown Render in Copilot Chat Input

[https://github.com/microsoft/vscode/issues/271215](https://github.com/microsoft/vscode/issues/271215)

## Summary

This remains a valid, community-supported Backlog request: current main provides an editable plain-text chat input but no read-only rendered Markdown preview. No older issue with the same observable request was found, so the re-review duplicate bar is not met.

## Change summary

Add a toggle that lets users preview the Markdown rendering of a composed chat prompt before submitting it.

## Best solution

Provide an accessible preview mode within the chat input that renders the current draft without changing its submitted Markdown source, and lets users return to editing without losing content, selections, or attachments.

- **Behavior:**

  > Users composing a Markdown-formatted chat prompt can switch to a rendered, read-only preview before submission. Returning to edit mode preserves the exact draft, attachments, and relevant editor state, and submitting sends the original Markdown rather than rendered text. The preview must be keyboard operable and expose an appropriate accessible name and state. Existing prompt editing and submission behavior remains unchanged while preview is off.
- **Trace:**

  > ChatInputPart in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts owns the CodeEditorWidget used for prompt composition, the input toolbar backed by MenuId.ChatInput, draft restoration, and submission state. Current searches show no preview action or Markdown-rendered alternate surface on this path; existing Markdown renderers are used for responses and other content. The likely boundary is the chat input presentation and its action registration: do not alter the stored or submitted prompt text, response rendering, attachment semantics, or generic editor behavior. This request is tracked at https://github.com/microsoft/vscode/issues/271215 and has already met the Backlog upvote threshold.
- **Open decisions:**
  - Should preview mode persist when switching conversations or reloading the window, or always return each chat input to editable mode?
  - Should links and interactive Markdown elements be active in the read-only preview, or should the preview remain non-interactive except for returning to edit mode?
