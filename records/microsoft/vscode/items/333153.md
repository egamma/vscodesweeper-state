# Issue #333153 — Agent Debug Logs resolves Agent Host ID instead of Copilot SDK conversation ID

[https://github.com/microsoft/vscode/issues/333153](https://github.com/microsoft/vscode/issues/333153)

## Summary

Confirmed by tracing current main: the Agent Debug Logs provider derives events.jsonl location directly from the session/chat URI's raw id, while the Copilot provider itself (and the already-shipped 'Open Agent Host State File' action) resolve the real backing SDK conversation id first. The panel silently comes up empty whenever those two ids diverge.

## Change summary

Agent Debug Logs panel shows only client-side discovery events (no model/tool events) for Copilot Agent Host sessions whose SDK conversation id differs from the Agent Host session id.

## Best solution

Have AgentHostChatDebugContribution._resolveEventsUri (src/vs/workbench/contrib/chat/browser/chatDebug/agentHostChatDebugProvider.ts) resolve the events file the same way workbench.action.chat.openCopilotCliStateFile does — via IAgentHostConnectionsService.resolveSessionResource(...) + connection.getSessionStateFile(...) — instead of the raw path-only resolveEventsUri() in copilotCliEventsUri.ts, so the provider-owned sdkConversationId mapping (CopilotAgent.getSessionStateFile / _sdkConversationId in src/vs/platform/agentHost/node/copilot/copilotAgent.ts) is respected for local, remote, and migrated sessions alike.
