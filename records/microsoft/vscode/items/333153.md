# Issue #333153 — Agent Debug Logs resolves Agent Host ID instead of Copilot SDK conversation ID

[https://github.com/microsoft/vscode/issues/333153](https://github.com/microsoft/vscode/issues/333153)

## Summary

Confirmed on current main via the checkout: the debug panel resolves events.jsonl straight from the Agent Host URI path instead of the SDK-backed conversation id, even though the exact fix pattern (IAgentHostConnectionsService.resolveSessionResource + connection.getSessionStateFile) already ships elsewhere in the same feature area. Real, well-diagnosed, unrouted bug worth a maintainer session.

## Change summary

Agent Debug Logs shows only client-side Instructions/Hook Discovery rows for Copilot Agent Host sessions because it derives events.jsonl from the raw Agent Host session id rather than the backing SDK conversation id.

## Best solution

Have AgentHostChatDebugContribution resolve the events.jsonl location through the existing provider-owned seam (IAgentHostConnectionsService.resolveSessionResource + IAgentHostConnection.getSessionStateFile), the same pattern already used by workbench.action.chat.openCopilotCliStateFile in openAgentHostStateFileAction.ts, instead of copilotCliEventsUri.ts's local URI-path-based reconstruction.

- **provider already has the real mapping:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:2821 getSessionStateFile() resolves `sdkConversationId` (via `_sdkConversationId()`, chat backing lookup, or session fallback) before building the events.jsonl path — this is the authoritative id the debug provider needs but bypasses.
- **existing working precedent:** src/vs/workbench/contrib/chat/browser/actions/openAgentHostStateFileAction.ts already solves the identical problem for 'Open Agent Host State File' by calling `connectionsService.resolveSessionResource(sessionResource)` then `connection.getSessionStateFile(backendSession, chatTarget?.backendResource)`, which round-trips through the provider's real id resolution over IPC/AHP.
