# Issue #329431 — Agent Host: create_chat hangs when target session was evicted

[https://github.com/microsoft/vscode/issues/329431](https://github.com/microsoft/vscode/issues/329431)

## Summary

Well-diagnosed, source-confirmed race: createChat() targeting an evicted session skips restoreSession(), so AgentHostStateManager.addChat() silently drops registration and the subsequent turn is dispatched against an unregistered chat, hanging on unresolved permission requests.

## Change summary

create_chat against a session whose in-memory state was evicted creates a peer chat that never gets registered, causing the multi-chat UI/permission flow to hang.

## Best solution

In AgentService.createChat() (src/vs/platform/agentHost/node/agentService.ts, around line 1435-1516), call restoreSession(session) before invoking the provider when the session isn't present in the state manager, and treat a false/undefined return from stateManager.addChat() as an error (dispose the newly created provider chat rather than proceeding to dispatch the first turn). Add a regression test alongside the existing createChat tests that evicts the parent first.
