# Issue #329431 — Agent Host: create_chat hangs when target session was evicted

[https://github.com/microsoft/vscode/issues/329431](https://github.com/microsoft/vscode/issues/329431)

## Summary

Real, well-diagnosed bug confirmed against current main, and it also carries the real milestone `1.136.0` — a scheduling decision that blocks any close under the hard keep-open rules regardless of other evidence.

## Change summary

`create_chat` against an Agent Host session whose in-memory state was evicted creates the peer provider chat but never restores/registers the parent session, so the chat's turn dispatch and permission requests are silently dropped and the peer chat hangs.

## Best solution

In `AgentService.createChat()` (src/vs/platform/agentHost/node/agentService.ts, ~line 2746), call `restoreSession()` (or check/await `getSessionState`) before invoking the provider and before `this._stateManager.addChat(...)`; treat a failed/undefined `addChat` result as an error and dispose the newly created provider backing chat instead of proceeding to dispatch the first turn, following the reporter's own suggested fix.
