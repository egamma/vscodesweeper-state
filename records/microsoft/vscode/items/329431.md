# Issue #329431 — Agent Host: create_chat hangs when target session was evicted

[https://github.com/microsoft/vscode/issues/329431](https://github.com/microsoft/vscode/issues/329431)

## Summary

Traced and confirmed on current main: `createChat` never restores an evicted parent session before creating the peer chat, so `AgentHostStateManager.addChat` silently no-ops and the peer chat is dispatched against unregistered state — this can hang a permission-requiring turn. A real fix is needed; milestone 1.135.0 is assigned so this stays open for scheduling regardless.

## Change summary

`create_chat` targeting an evicted (but durable) session creates the peer chat but drops its state-manager registration, hanging the first turn/permission flow.

## Best solution

In `AgentService.createChat` (src/vs/platform/agentHost/node/agentService.ts, ~line 2040), restore the parent session (mirroring the `if (!this._stateManager.getSessionState(...)) await this.restoreSession(...)` pattern already used at line 794-795 and again around line 3069) before calling `_createChat`/`addChat`; treat a failed `addChat` as an error and dispose the newly-created provider backing rather than proceeding to `_startSessionPrompt`. Add a regression test alongside the existing eviction-restore suite (e.g. near `agentService.test.ts:8637` "restores an evicted session before applying a dispatched default-chat action").
