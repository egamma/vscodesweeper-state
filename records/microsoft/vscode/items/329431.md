# Issue #329431 — Agent Host: create_chat hangs when target session was evicted

[https://github.com/microsoft/vscode/issues/329431](https://github.com/microsoft/vscode/issues/329431)

## Summary

Real, well-diagnosed race confirmed on current main: `createChat()` never restores an evicted parent session before creating and registering the peer chat, so `addChat()` silently drops registration and the first turn is dispatched against an unregistered chat, hanging on an unresolved permission request. Milestone 1.134.0 is set, so per policy this is a scheduling decision and stays open regardless.

## Change summary

`create_chat` targeting a session whose in-memory state was evicted creates the peer chat but never registers it, so the first turn (and any permission request) is dropped and the UI hangs.

## Best solution

In `AgentService.createChat()` (src/vs/platform/agentHost/node/agentService.ts), call `restoreSession(session)` (or otherwise materialize the parent state) before invoking `_createChat`/`addChat` when `getSessionState(sessionKey)` is absent; treat a failed `addChat` as an error and dispose the newly-created provider chat rather than proceeding to `_startSessionPrompt`. Add a regression test alongside the existing `createChat` suite in agentService.test.ts that evicts the parent state and calls `createChat()` without an explicit prior restore.
