# Issue #329431 — Agent Host: create_chat hangs when target session was evicted

[https://github.com/microsoft/vscode/issues/329431](https://github.com/microsoft/vscode/issues/329431)

## Summary

Traced and confirmed on current main: AgentService.createChat() never restores an evicted parent session before asking the provider to create the peer chat, so AgentHostStateManager.addChat() logs 'addChat for unknown session' and drops registration, leaving the new chat's first turn (and any permission request) stuck unroutable. This is scheduled (milestone 1.137.0), so it stays open regardless.

## Change summary

create_chat hangs when the target session was evicted from memory: the peer SDK chat gets created but never registered, so its first turn and permission requests go nowhere.

## Best solution

In AgentService.createChat() (src/vs/platform/agentHost/node/agentService.ts, ~line 2907), call this.restoreSession(session) before this._createChat(...)/this._stateManager.addChat(...) — mirroring the exact precedent already used in _doRestoreSubagentChat (line ~6738-6741), which restores the parent before addChat for subagent chats. Also treat a failed/undefined addChat return as an error and dispose the just-created provider backing instead of proceeding to persist/dispatch the first turn.
