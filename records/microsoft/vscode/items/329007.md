# Issue #329007 — Agents window: sign-in modal flashes on reload before the conditional-auth gate resolves

[https://github.com/microsoft/vscode/issues/329007](https://github.com/microsoft/vscode/issues/329007)

## Summary

Real, well-diagnosed follow-up bug from a team member (author of the original fix in #328990); the described race is still present on main and not yet fixed.

## Change summary

With `chat.agentHost.allowSignedOutWhenUsable` enabled and Claude resolving to native mode, reloading the Agents window briefly flashes the non-dismissible GitHub sign-in modal before the conditional-auth gate resolves that sign-in isn't actually required.

## Best solution

Give `observeUsableWithoutGitHub` (src/vs/sessions/browser/sessionsAuthGate.ts) a third 'unresolved' state, mirroring `ConditionalAuthState`/`SessionTypeAuthRequirement`, and have `SessionsSetUpWidget._mustForceGitHubSignIn` (src/vs/sessions/browser/sessionsSetUpService.ts) treat 'unresolved' as 'don't show the modal yet' rather than 'force sign-in', with a bounded fallback if the agent host never reports.

## Evidence

- **gate is still boolean:** src/vs/sessions/browser/sessionsAuthGate.ts `observeUsableWithoutGitHub` returns a plain `IObservable<boolean>` derived from `getAllProviderSessionTypes()`, with no third 'not yet resolved' state — unlike the account-resolution race, which already got a three-state `ConditionalAuthState` (Unresolved/SignedIn/SignedOut) in the same file.
- **consumer treats unresolved as false:** src/vs/sessions/browser/sessionsSetUpService.ts:277-279 `_mustForceGitHubSignIn()` is simply `!this._usableWithoutGitHub.get()`; on a signed-out reload this reads `false` until the local agent host registers Claude at `WorkbenchPhase.AfterRestored`, so `_showWelcome(false)` takes the sign-in-dialog branch before the host has had a chance to report, exactly matching the reported repro.
- **correction path exists but only after the fact:** `_onUsableWithoutGitHub Changed` (sessionsSetUpService.ts ~124-144) does retract the dialog once the observable flips true, confirming the modal is shown transiently and then dismissed rather than being a permanent block — consistent with the issue's description of a 'flash'.
- **no fix commit found:** git log on src/vs/sessions/browser/sessionsAuthGate.ts and sessionsSetUpService.ts shows no commit addressing this since the file's introduction; the referenced follow-up PR for this issue has not landed.
