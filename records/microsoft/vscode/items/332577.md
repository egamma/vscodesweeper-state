# Issue #332577 — Extension API: Allow WebviewPanel to be programmatically pinned or unclosable

[https://github.com/microsoft/vscode/issues/332577](https://github.com/microsoft/vscode/issues/332577)

## Summary

Existing commands support programmatic pinning, but pinning is not an unclosable state and does not fully satisfy this request. Keep open for an API scope decision; no verified canonical or completed implementation covers the remaining requirement.

## Change summary

Allow extensions to protect persistent WebviewPanel tabs against accidental closure through a panel-specific API.

## Best solution

Distinguish ordinary tab pinning from preventing closure, and decide whether a panel-specific API is warranted beyond the existing pin command. Any accepted contract should preserve an explicit user escape hatch and respect the user's editor-close preferences.

- **Proposed comment:**

  > Thanks for the request. Extensions can already invoke `workbench.action.pinEditor` for an active webview panel, and `workbench.editor.preventPinnedEditorClose` controls protection against keyboard and middle-click closure. That does not make the panel unclosable, however, and there is no panel-specific pinning or close-prevention property today. The remaining API question is whether to expose ordinary pinning directly or introduce a stronger protection contract with an explicit way for users to close the view.

## Evidence

- **Existing programmatic pinning:** src/vs/workbench/browser/parts/editor/editorCommands.ts:1400–1412 registers workbench.action.pinEditor and calls group.stickEditor on the resolved editors. Extensions can invoke this command for an active panel, so the report's assertion that programmatic pinning is entirely unavailable is too broad.
- **Pinning does not forbid closure:** src/vs/workbench/browser/workbench.contribution.ts:286–296 registers workbench.editor.preventPinnedEditorClose, defaulting to keyboardAndMouse. Its protection concerns keyboard and middle-click closure; editorCommands.ts:788–800 explicitly permits closing sticky editors through context-menu invocation. This is partial coverage, not an unclosable-panel contract.
- **Panel-specific API remains absent:** src/vscode-dts/vscode.d.ts:10056–10186 exposes neither a fixed/pinned setter nor a cancellable close event on WebviewPanel.
