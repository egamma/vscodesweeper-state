# Issue #331754 — [Terminal][IME][Korean] Ghost duplicate preview of the in-progress (composing) Korean character appears diagonally below the cursor while typing

[https://github.com/microsoft/vscode/issues/331754](https://github.com/microsoft/vscode/issues/331754)

## Summary

Well-confirmed visual glitch (three independent reporters, Korean/Japanese/Chinese IMEs, all after 1.134.0) where the in-progress composition text is drawn twice in the integrated terminal; VS Code's terminal code has no IME/composition-hosting logic of its own, so the rendering path lives entirely inside the bundled xterm.js library — this looks like an upstream xterm.js regression surfaced by the recent version bump, not something fixable in this repo's own sources.

## Change summary

While composing CJK text (Korean/Japanese/Chinese IME) in the integrated terminal, a duplicate 'ghost' copy of the in-progress character is rendered offset from the real cursor until the composition is finalized.

## Best solution

Route to the terminal area for investigation against xterm.js's TextAreaHandler/composition-view positioning (the compositor logic lives in `@xterm/xterm`, currently pinned at `^6.1.0-beta.302` in package.json, not in `src/vs/workbench/contrib/terminal`); the actual fix likely needs to land in xtermjs/xterm.js and then be pulled into VS Code via a package bump. Also worth checking whether https://github.com/microsoft/vscode/issues/331903 (an older/related report, already assigned to a maintainer) is tracking the same regression so the two threads can be consolidated by a human.
