# Issue #331754 — [Terminal][IME][Korean] Ghost duplicate preview of the in-progress (composing) Korean character appears diagonally below the cursor while typing

[https://github.com/microsoft/vscode/issues/331754](https://github.com/microsoft/vscode/issues/331754)

## Summary

Credible, cross-confirmed report (Korean and Japanese IME both show a ghost duplicate of the in-progress composition text, offset below the cursor, in the Integrated Terminal only) that reproduces with extensions disabled — but the defect lives in xterm.js's own IME composition-textarea rendering, a dependency this repo bundles rather than authors, so it should be routed to the terminal area and relayed upstream rather than fixed here directly.

## Change summary

While composing CJK (Korean/Japanese) text in the Integrated Terminal, the in-progress (pre-finalized) composition string renders twice — once correctly at the cursor and once as an offset 'ghost' copy — until the character is confirmed.

## Best solution

A terminal maintainer should confirm whether this is a regression from the recent @xterm/xterm ^6.1.0-beta.292 bump (package.json bundles @xterm/xterm and @xterm/headless at that version) and, if so, file/track it against the xterm.js upstream project; VS Code's terminal code doesn't implement IME composition-preview rendering itself, so no local source fix is likely.
