[https://github.com/microsoft/vscode/issues/349566](https://github.com/microsoft/vscode/issues/349566)

## Summary

Keep open: current source preserves sender metadata internally but does not expose a message-bound return reference to the recipient. The existing origin alias addresses the saved creator, so it does not cover communication between independently existing chats.

## Change summary

Expose a validated, host-qualified reply reference bound to each incoming remote message and its exact sending chat.

## Best solution

Provide recipient-facing, message-bound reply addressing through the Agent Host session tools and remote message router, preserving exact nested-chat identity and existing creator-origin, approval, and trust semantics. The area owner should settle the model-facing contract before implementation.
