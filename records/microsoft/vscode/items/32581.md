# Issue #32581 — Add Opacity & Variable Height to Minimap

[https://github.com/microsoft/vscode/issues/32581](https://github.com/microsoft/vscode/issues/32581)

## Summary

Opacity customization is implemented, but the minimap still has a full-height interactive container rather than the requested content-height overlay. Keep this accepted, well-supported request open for the remaining sizing and interaction work.

## Change summary

Allow an opt-in translucent, content-height minimap that preserves usable editor space, including below the minimap's rendered content.

## Best solution

Retain the existing theme-based opacity controls and settle the remaining opt-in content-height overlay behavior in the editor minimap. The finished behavior should avoid invisible minimap clicks below short files while preserving normal minimap navigation and the default layout.

Add layout and mouse-target regression checks, then verify file growth, wrapping, resizing, and ordinary minimap navigation while confirming the default mode is unchanged.
- **Behavior:**

  > The requested opt-in behavior is a translucent minimap whose container grows with file content instead of occupying an interactive full-height column for short files. Opacity controls already exist and must remain usable. Empty space below the visible minimap should not unexpectedly navigate to the end of the file. Acceptance must include narrow split editors, long lines, file growth, and unchanged navigation within the visible minimap.
- **Trace:**

  > MinimapOptions in src/vs/editor/browser/viewParts/minimap/minimap.ts reads minimap.background and minimap.foregroundOpacity, but sets minimapHeight to the editor layout height. InnerMinimap._applyLayout keeps the container full height, and its pointer listener handles clicks throughout that container; proportional-mode clicks beyond content clamp to the last line. EditorLayoutInfoComputer in src/vs/editor/common/config/editorOptions.ts reserves minimap width, while proportional/fill/fit govern content scaling rather than an opt-in content-height overlay. Mouse-target classification in src/vs/editor/browser/controller/mouseTarget.ts recognizes the minimap fingerprint, so editor click behavior needs consideration alongside rendering and layout. https://github.com/microsoft/vscode/issues/32630 was explicitly consolidated here; https://github.com/microsoft/vscode/pull/132681 completed opacity only. Preserve existing opacity controls and default layout; uncertainty remains around how the requested overlay affects wrapping and usable editor width.
- **Open decisions:**
  - Should the opt-in overlay reclaim minimap width for text layout and wrapping, or retain the current wrapping width while exposing overflowing text beneath the shortened minimap?
