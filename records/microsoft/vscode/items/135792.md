# Issue #135792 — Deleted files from explorer should match styling from deletions on disk

[https://github.com/microsoft/vscode/issues/135792](https://github.com/microsoft/vscode/issues/135792)

## Summary

Still a valid gap on current main: the git extension's FileDecoration for deleted files does not include strikethrough because the extension API's FileDecoration class lacks a strikethrough property. The internal IDecorationData (used by textFileService for orphaned/disk-deleted files) does support strikethrough, creating the visual inconsistency this issue describes. The issue carries `help wanted` and `On Deck`, signaling team endorsement.

## Change summary

Deleted files opened from SCM should use the same strikethrough styling as files deleted from disk, instead of only showing a 'Deleted' badge.

## Best solution

Either expose a `strikethrough` property on the `FileDecoration` extension API so the git extension can set it for deleted resources, or handle the strikethrough internally in the SCM/decoration plumbing when resources are marked as deleted. The git extension already computes `strikeThrough` for the SCM tree view (`extensions/git/src/repository.ts` line 248); the missing piece is propagating it to the editor tab decoration via the `FileDecoration` / `IDecorationData` path.
