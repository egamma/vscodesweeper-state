# Issue #279829 — Feature Request: Add Rich Text Editor Support in Copilot Chat Window

[https://github.com/microsoft/vscode/issues/279829](https://github.com/microsoft/vscode/issues/279829)

## Summary

A real chat-composer capability remains missing on current main. Older open issues cover Markdown preview or composing in a separate editor, but neither fully owns this broader inline rich-text/WYSIWYG request, so the re-reviewed item should remain open under discussion.

## Change summary

Provide rich Markdown composition, preview, and formatting controls directly in the Copilot Chat input.

## Best solution

Define a focused chat-composition experience that makes structured Markdown readable before submission while preserving an efficient source-editing path, keyboard accessibility, and the existing request format. The chat area should first decide whether this is a source/preview toggle or direct rich-text editing and how inline images map to existing attachments.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatEditorInputContentProvider.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts`, `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/test/browser/widget/chatWidget.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/editor/chatPasteProviders.test.ts`
- **Validation:** The plan should end with targeted chat-widget tests and a manual keyboard/screen-reader check covering mode switching, Markdown round-tripping, rich HTML paste, code blocks, links, and submission of the intended underlying prompt text.
- **Behavior:**

  > Users composing long structured prompts should be able to see and edit Markdown formatting clearly before submission, including headings, emphasis, lists, links, code blocks, and tables. A source-oriented editing path must remain available, and switching representations must not alter the submitted prompt. Image insertion must have defined behavior consistent with chat attachments. Keyboard-only and screen-reader workflows must remain complete.
- **Trace:**

  > The current composer is a CodeEditorWidget created by ChatInputPart in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, backed by a `chatinput` text model from ChatInputBoxContentProvider. Rich HTML paste is already normalized to Markdown source by chatPasteProviders.ts, establishing Markdown text as part of the existing input path, but no rendered editing surface exists. https://github.com/microsoft/vscode/issues/271215 tracks a narrower read-only preview toggle, while https://github.com/microsoft/vscode/issues/266218 tracks composition in a separate editor tab; neither fully owns inline rich-text editing. Keep request submission, response rendering, chat history, and attachment transport behavior unchanged unless a product decision explicitly expands those contracts.
- **Open decisions:**
  - Should the composer provide direct WYSIWYG editing, separate source and preview modes, or both, and which representation is the default?
  - Should images inserted through the rich editor remain normal chat attachments or become inline Markdown references visible in the composed message?
  - Which Markdown features are editable directly versus preview-only, particularly tables and fenced-code syntax highlighting?

## Evidence

- **current implementation:** On current main, src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts constructs the composer as a CodeEditorWidget, while src/vs/workbench/contrib/chat/browser/widget/input/editor/chatEditorInputContentProvider.ts creates its model with the `chatinput` language. There is no rich-text or rendered-Markdown editing mode on this path.
- **partial capability:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatPasteProviders.ts converts meaningful pasted HTML to Markdown and inserts the Markdown source through the “Paste as Markdown” edit. This helps author formatted prompts but does not provide the requested rendered or WYSIWYG composition experience.
- **related preview request:** https://github.com/microsoft/vscode/issues/271215 is older and open, but it asks specifically for a read-only Markdown preview toggle. It is narrower than this issue's editable rich-text controls, syntax highlighting, links, images, and tables, so it cannot absorb the full request.
- **related editor request:** https://github.com/microsoft/vscode/issues/266218 is older and open and asks to compose messages in a separate Markdown editor tab. A maintainer acknowledged rich-text input ideas at https://github.com/microsoft/vscode/issues/266218#issuecomment-3641723778, but that issue describes a different user-visible surface and does not meet the stronger same-symptom duplicate bar for this re-reviewed item.
- **community signal:** The issue has no community upvotes after roughly ten months, so `under-discussion` is more appropriate than treating the broad UI proposal as implementation-ready.
