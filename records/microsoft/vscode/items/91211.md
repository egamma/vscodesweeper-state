# Issue #91211 — Find/replace icons are not intuitive

[https://github.com/microsoft/vscode/issues/91211](https://github.com/microsoft/vscode/issues/91211)

## Summary

Keep this accepted, community-supported request open: current source still uses icon-only find/replace controls, and the whole-word icon improvement does not deliver the requested self-explanatory labels. A maintainer explicitly consolidated the persistent-input-label request into this issue, making it the existing home for that work.

## Change summary

Make editor find/replace inputs, options, and actions understandable without interpreting ambiguous icons or consulting tooltips.

## Best solution

Design a visibly labeled find/replace surface that distinguishes search options from navigation and makes replacement actions discoverable, while retaining a usable compact layout. Settle the default presentation and narrow-editor behavior with the UX owner before implementation.

Exercise keyboard navigation, Match Case, Match Whole Word, regex, Find in Selection, Replace, and Replace All to confirm unchanged search semantics.
- **Behavior:**

  > Users should be able to identify editor find/replace inputs, search options, and replacement actions without guessing glyph meanings or hovering for explanations. Labels should remain understandable when input fields contain text. The design must remain usable in narrow editors and preserve keyboard access and existing search/replacement behavior. Acceptance includes distinguishing search options from result navigation and distinguishing one replacement from all replacements.
- **Trace:**

  > FindWidget._buildDomNode in src/vs/editor/contrib/find/browser/findWidget.ts constructs the find-actions cluster, replacement buttons, and disclosure control. SimpleButton uses the supplied label for ARIA and delayed hover content while displaying an icon; Find in Selection is appended beside navigation controls. Shared CaseSensitiveToggle, WholeWordsToggle, and RegexToggle in src/vs/base/browser/ui/findinput/findInputToggles.ts likewise use glyphs with tooltip titles. The registered editor.find settings in src/vs/editor/common/config/editorOptions.ts do not expose a labeled presentation. https://github.com/microsoft/vscode/issues/167870 was explicitly consolidated here and contributes the persistent-input-label requirement; https://github.com/microsoft/vscode/issues/54275 covers only the already-improved whole-word glyph. The remaining uncertainty is the user-visible presentation, not search semantics; shared find-input components have consumers beyond this editor widget, whose presentation must not change accidentally.
- **Open decisions:**

  - What presentation should narrow editors use while keeping the controls understandable and reachable?
  - Should Find in Selection be visibly grouped with search options rather than result-navigation controls?
