# Issue #335755 — Testing: Agent host dev container sessions cannot run terminal commands with sandboxing enabled

[https://github.com/microsoft/vscode/issues/335755](https://github.com/microsoft/vscode/issues/335755)

## Summary

Real, team-reported gap from active dogfood testing of the new Agent Host dev-container flow: sandboxing silently breaks all terminal tools in a stock dev container image, and current main has no devcontainer-specific provisioning or pre-flight detection to prevent that dead-end state.

## Change summary

A dev container Agent Host session with sandboxing enabled cannot run any terminal commands because the container lacks Bubblewrap/socat, and even after installing them the kernel disallows unprivileged user namespaces — leaving the agent able to edit files but unable to run/test/commit.

## Best solution

In the dev container Agent Host provisioning path, either bundle/install the sandbox runtime deps (bwrap, socat) and ensure the container supports nested user namespaces, or run the existing SandboxHelperService.checkSandboxDependencies() check up front and surface an immediate, actionable message/fallback (e.g. auto-disable sandboxing with a clear notice) instead of letting the session proceed into a broken state.
