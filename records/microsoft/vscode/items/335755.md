# Issue #335755 — Testing: Agent host dev container sessions cannot run terminal commands with sandboxing enabled

[https://github.com/microsoft/vscode/issues/335755](https://github.com/microsoft/vscode/issues/335755)

## Summary

Fresh, team-authored (MEMBER) test report filed today with a detailed first-hand reproduction: sandboxed terminal execution fails in a Dev Container Agent Host session because Bubblewrap/socat aren't provisioned and nested user namespaces aren't available, silently leaving the agent unable to run any shell command. No fix has landed yet, so this stays open.

## Change summary

Agent Host dev container sessions with sandboxing enabled cannot run any terminal commands because the container lacks Bubblewrap/socat and nested user namespaces, with no clear remediation surfaced to the user.

## Best solution

The Dev Container Agent Host provisioning path (likely under src/vs/platform/agentHost or the dev container startup/bootstrap logic) should either install/verify sandbox dependencies (bwrap, socat) and confirm nested namespace support during container setup, or detect the unsupported sandbox environment upfront and surface an actionable message/fallback instead of letting file tools succeed while all terminal tools silently fail.
