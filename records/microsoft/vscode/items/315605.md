# Issue #315605 — Can agents window open "new" vscode window with last used workspace

[https://github.com/microsoft/vscode/issues/315605](https://github.com/microsoft/vscode/issues/315605)

## Summary

The requested workspace restoration remains missing on current main: when no editor window exists, the Agents Window command explicitly opens an empty window. No older open issue with the same observable request was found, so this accepted Backlog feature should remain open.

## Change summary

When the Agents Window opens a new VS Code editor window, reopen the last used workspace instead of an empty window.

## Best solution

When no editor window is available to focus, reopen the most recent valid editor workspace while preserving the current focus-existing-window behavior and providing an empty-window fallback when no suitable workspace exists.

## Plan brief

- **Likely files:** `src/vs/sessions/electron-browser/actions/vscodeActions.ts`, `src/vs/sessions/test/electron-browser/vscodeActions.test.ts`, `src/vs/platform/workspaces/common/workspaces.ts`
- **Validation:** Extend the VS Code Actions unit suite and run scripts/test.sh --grep "VS Code Actions"; verify that no existing editor window causes the selected recent workspace to open, an existing editor window is still focused, and an unavailable recent workspace falls back safely.
- **Behavior:**

  > Invoking Open VS Code Window from the Agents Window should continue to focus an existing editor window when one is available. If none exists, it should reopen the last applicable workspace rather than presenting an unrelated empty window. If no valid prior workspace is available, opening an empty editor window remains a safe fallback. Acceptance should cover existing-window focus, workspace restoration, and fallback behavior.
- **Trace:**

  > OpenVSCodeWindowAction.run in src/vs/sessions/electron-browser/actions/vscodeActions.ts obtains the list of main windows, focuses the first window other than the Agents Window, and otherwise calls INativeHostService.openWindow() with no openable. The corresponding suite is src/vs/sessions/test/electron-browser/vscodeActions.test.ts; its current empty-window test establishes the present fallback. Recent workspace data is exposed by IWorkspacesService.getRecentlyOpened() in src/vs/platform/workspaces/common/workspaces.ts. Preserve the existing focus behavior and do not change the separate Open in Editor action, which intentionally derives folders from the active chat. The uncertainty starts at the product definition of which history entry qualifies as the last workspace, especially across folders, workspace files, remote authorities, profiles, and invalid entries.
- **Open decisions:**
  - Should "last used workspace" mean the most recent valid entry in workspace history, or specifically the workspace belonging to the last closed editor window?
  - Should restoration include remote workspaces and single-folder windows, or only local saved workspace files?
  - If the most recent workspace is unavailable, should the command try older history entries or immediately open an empty window?
