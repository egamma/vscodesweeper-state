# Issue #244273 — A single slow Code Action provider can affect all others

[https://github.com/microsoft/vscode/issues/244273](https://github.com/microsoft/vscode/issues/244273)

## Summary

Still present on main: `getCodeActions` in `src/vs/editor/contrib/codeAction/browser/codeAction.ts` uses `Promise.all` (line 163) to await all providers before showing any results, so a single slow provider blocks the entire lightbulb/quick-fix experience. The defect is architectural and valid — previous closures as `*caused-by-extension` addressed symptoms, not the root cause.

## Change summary

A single slow Code Action provider blocks all other providers' results from appearing, because VS Code awaits all providers via `Promise.all` before showing any Code Actions.

## Best solution

Refactor `getCodeActions` in `src/vs/editor/contrib/codeAction/browser/codeAction.ts` to yield results incrementally — show a lightbulb as soon as the first provider responds (for automatic triggers), and stream late-arriving actions into the menu. The consumer in `codeActionModel.ts` and the lightbulb/menu UI would need to accept an async iterable or observable rather than a single resolved `CodeActionSet`.
