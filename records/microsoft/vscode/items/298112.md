# Issue #298112 — Autosave feature for chats; ability to make imported chat the current chat

[https://github.com/microsoft/vscode/issues/298112](https://github.com/microsoft/vscode/issues/298112)

## Summary

A real chat-session continuity gap remains: ordinary local chats are persisted, but imported chats are deliberately excluded from persistence and open in an editor rather than becoming the current panel chat. The older related issue covers imported-chat retention but not the separate report that an existing conversation becomes unresponsive after several days, so the stronger re-review duplicate bar is not met.

## Change summary

Persist imported chats as resumable sessions and allow them to become the current chat, while preserving long-running conversations across breaks.

## Best solution

Treat imported chat data as a persistent local session that appears in chat history and can be resumed as the current panel chat; review and land the existing implementation in https://github.com/microsoft/vscode/pull/331738 if it satisfies that contract. The distinct long-running-session responsiveness symptom should be diagnosed separately rather than treating export/import as its autosave mechanism.

## Evidence

- **current persistence behavior:** src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts persists live local chats in saveState(), but shouldStoreSession() explicitly requires `!session.isImported`, so imported chats remain outside normal session persistence.
- **current import behavior:** src/vs/workbench/contrib/chat/browser/actions/chatImportExport.ts loads ordinary imports as exported data in a new ChatEditorInput in ACTIVE_GROUP; only callers supplying the programmatic `chatViewPane` target open the import in the current chat surface.
- **related canonical:** https://github.com/microsoft/vscode/issues/291986 is older and remains open for the imported-chat retention symptom, with multiple confirmations and a maintainer asking that imports behave like forks. It does not own the separate symptom here where a previously active conversation stops responding after several days.
- **open implementation:** https://github.com/microsoft/vscode/pull/331738 is open and proposes converting imported export data into a persistent local session for https://github.com/microsoft/vscode/issues/291986; it has not merged, so current main still contains the gap.
- **existing workaround:** The `/fork` command can turn imported history into a new persistent conversation, as documented in https://github.com/microsoft/vscode/issues/291986#issuecomment-4080833169, but this is an indirect workaround rather than import behaving as requested.
