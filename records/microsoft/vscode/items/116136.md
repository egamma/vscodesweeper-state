# Issue #116136 — Update close/dirty/pinned icons that are referenced by unicode characters

[https://github.com/microsoft/vscode/issues/116136](https://github.com/microsoft/vscode/issues/116136)

## Summary

The themeability debt still appears valid and the Backlog milestone does not block review, but the issue describes a cross-surface migration rather than a completed or duplicative item. Keep it open and consolidate the remaining raw-codepoint icon paths under the product-icon theming model.

## Change summary

Replace close, dirty, and pinned icons selected through hard-coded codicon Unicode content with theme-aware icon references while preserving hover-state behavior.

## Best solution

Define a reusable, theme-aware mechanism for state-dependent action icons, then migrate tabs, Open Editors, quick access, and other remaining raw codicon-content overrides without changing their click or hover semantics.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/media/tabstitlecontrol.css`, `src/vs/workbench/contrib/files/browser/views/media/openeditors.css`, `src/vs/workbench/browser/parts/editor/tabsTitleControl.ts`, `src/vs/workbench/services/decorations/browser/decorationsService.ts`
- **Validation:** Create a product icon theme that replaces close, circle-filled, pinned, and pinned-dirty; verify dirty and pinned editor tabs and Open Editors rows use those replacements both at rest and on hover, while clicking each state performs the same close or pin action as before.
- **Behavior:**

  > Product icon themes must control the close, dirty, pinned, and pinned-dirty glyphs instead of those states falling back to hard-coded codicon codepoints. A dirty unpinned item shows circle-filled at rest and close on hover; a pinned item shows pinned, while a dirty pinned item shows pinned-dirty at rest and pinned on hover. The same state transitions must remain consistent in editor tabs, Open Editors, and affected quick-access action rows. Clicking and hover affordances must retain their existing behavior.
- **Trace:**

  > The issue traces the original tab state selection to TabsTitleControl and lists CSS overrides in tabstitlecontrol.css and openeditors.css that replace `::before` content with raw codicon Unicode values; decorationsService.ts also emits a raw circle-filled codepoint. The maintainer discussion confirms that hover changes communicate the action that clicking will perform, so this is not a static icon substitution. The boundary is product-icon resolution and state presentation: do not change dirty tracking, pin semantics, editor closing, or action behavior. The later https://github.com/microsoft/vscode/issues/119192 is related evidence but is closed, newer, and narrower, so it is not a canonical duplicate.
- **Open decisions:**
  - Should state-dependent icons be resolved dynamically as ThemeIcons, or should VS Code expose a CSS-level themed-icon mechanism that preserves product-icon-theme substitutions across hover states?
