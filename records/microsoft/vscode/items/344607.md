# Issue #344607 — UX / UI: Model picker became difficult to use

[https://github.com/microsoft/vscode/issues/344607](https://github.com/microsoft/vscode/issues/344607)

## Summary

Keep open as the maintainer-selected consolidation point for model-picker usability feedback. Current source still hides inactive provider labels; cross-provider search and improved icons do not fully address mouse-driven discovery.

## Change summary

Make provider and model selection readily scannable without identifying icon-only tabs through tooltips or trial and error.

## Best solution

Agree on a model-picker presentation that makes provider identities discoverable before selection and accommodates many provider groups. Preserve cross-provider search and keyboard navigation while improving pointer-driven browsing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabbedWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerTabs.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/modelPicker/modelPickerTabbedWidget.test.ts`
- **Validation:** Extend modelPickerTabbedWidget.test.ts for the agreed provider-identification behavior and retained cross-provider search. Manually open the picker with more than six custom provider groups, including groups sharing an icon, and verify that every provider is identifiable and reachable without layout overflow.
- **Behavior:**

  > Users should be able to identify available providers and browse their models without guessing identical icons or waiting for tooltips. The browsing experience must remain usable with more than six provider groups. Cross-provider search, keyboard navigation, and selection of the intended provider's model must remain intact. Acceptance should cover both familiar named models and pointer-driven discovery of unfamiliar models.
- **Trace:**

  > TabbedModelPickerWidget supplies destination labels but explicitly requests tabLabels: 'active'; TabbedActionListWidget then hides inactive labels when an icon exists. buildModelPickerDestinations creates a separate destination for each provider group, and getProviderIconForIdentity can assign multiple custom groups the same generic sparkle. Search already spans destinations and activates on typing, so it is a useful existing capability rather than a complete answer to browsing discoverability. Preserve model identity, provider grouping semantics, accessible names, and existing search behavior; do not broaden changes to shared widget defaults without an established need. The reported overflow with more than six providers still needs a visual reproduction. A maintainer consolidated https://github.com/microsoft/vscode/issues/344216 into this report; https://github.com/microsoft/vscode/issues/317128 provides broader design context but does not replace it.
- **Open decisions:**
  - Should browsing retain provider tabs with persistently identifiable names, return to a vertically grouped model list, or adopt another presentation that exposes provider identities before selection?
  - Should search remain an explicitly activated mode or be visibly available and focused when the picker opens?
