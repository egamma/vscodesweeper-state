# Issue #169804 — Allow setting invert indent for `editor.wrappingIndent`

[https://github.com/microsoft/vscode/issues/169804](https://github.com/microsoft/vscode/issues/169804)

## Summary

Keep this accepted feature request open: current wrapping options do not provide a one-tab negative offset relative to the parent indentation. It reached 20 upvotes and entered the Backlog; the verified related issues do not provide an open canonical for this specific behavior.

## Change summary

Allow wrapped continuation lines to start one tab stop less indented than their parent line.

## Best solution

Support an opt-in negative relative wrapping indentation in the editor's existing wrapping configuration, preserving current modes and defaults. A maintainer should settle the configuration contract and behavior near the left margin before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts`, `src/vs/editor/browser/view/domLineBreaksComputer.ts`, `src/vs/editor/test/common/viewModel/monospaceLineBreaksComputer.test.ts`, `src/vs/editor/test/browser/view/domLineBreaksComputer.test.ts`
- **Validation:** Add focused wrapping tests for parent lines indented by one and multiple tab stops, mixed tabs/spaces, and indentation smaller than the requested negative offset. Run the monospace and DOM line-break suites through scripts/test.sh with targeted --run selectors; verify existing modes remain unchanged and manually compare Chinese paragraph wrapping under simple and advanced strategies.
- **Behavior:**

  > Provide an opt-in way for continuation lines to start one tab stop less indented than their parent, supporting the paragraph layout requested by the reporter. For a parent indented by multiple tab stops, continuation lines must retain the remaining indentation rather than always starting at column 1. Existing wrapping modes and defaults must remain unchanged. Acceptance should cover both wrapping strategies, tabs and spaces, and the agreed behavior when subtracting one tab stop would cross the left margin.
- **Trace:**

  > WrappingIndentOption in src/vs/editor/common/config/editorOptions.ts exposes four string modes and rejects other values; WrappingIndent contains no inverse mode. computeWrappedTextIndentLength in src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts preserves parent indentation and optionally adds one or two tab stops, while createLineBreaks in src/vs/editor/browser/view/domLineBreaksComputer.ts implements the corresponding DOM-measured behavior. This establishes the missing capability without executing code. Preserve existing mode semantics, narrow-width fallback behavior, and the screen-reader override to WrappingIndent.None. The reporter asks for a negative tab-relative offset, while a commenter suggests numeric values; the record does not settle that public contract. https://github.com/microsoft/vscode/issues/42203 is related numeric-configuration work, not a verified duplicate; language-aware wrapping in https://github.com/microsoft/vscode/issues/164267 is outside this request's narrow scope.
- **Open decisions:**
  - Should the public configuration expose a dedicated inverse-indent string mode or signed numeric values, and what units would numeric values represent?
  - When the parent indentation is less than one tab stop, should continuation indentation clamp to column 1 or leave the parent's indentation unchanged?

## Evidence

- **Existing capability check:** src/vs/editor/common/config/editorOptions.ts:5600-5665 defines editor.wrappingIndent exclusively as none, same, indent, or deepIndent. Its validator accepts neither a negative numeric value nor an inverse-indent mode. None starts every continuation at column 1; it does not generally subtract one tab stop from the parent's indentation.
- **Current wrapping implementations:** src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts:614-643 computes existing indentation and adds zero, one, or two tab stops. src/vs/editor/browser/view/domLineBreaksComputer.ts:69-71 likewise computes only nonnegative additional indentation. Neither implements the requested negative relative offset.
- **Accepted community request:** https://github.com/microsoft/vscode/issues/169804 has 20 body upvotes, the Backlog milestone, and a June 27, 2024 bot comment confirming promotion. The fully read policy at https://github.com/microsoft/vscode/wiki/Issues-Triaging identifies Backlog as accepted work and documents promotion after sufficient community support.
- **Closed predecessors are not canonicals:** https://github.com/microsoft/vscode/issues/152755 explicitly contemplated negative numeric indentation, and https://github.com/microsoft/vscode/issues/92840 requested first-line paragraph indentation. Both are closed because they failed the community voting threshold, not because the capability was implemented or explicitly rejected on technical grounds.
- **Open related requests have different scope:** https://github.com/microsoft/vscode/issues/42203 is older and open, but its body and comments request custom positive or fractional continuation indentation, not negative indentation. https://github.com/microsoft/vscode/issues/164267 is older and open but requests language-aware list and paragraph wrapping. Neither establishes the same observable requirement required for a duplicate close of this re-reviewed item.

Its description documents the tradeoff between paragraph and list indentation; it does not implement negative indentation in VS Code. https://github.com/microsoft/vscode/issues/219680 is a newer, closed first-line-indentation request and is not an eligible canonical.
