# Issue #347322 — Allow agents to clear PR associated with the session OR automatically detect that target branch changed

[https://github.com/microsoft/vscode/issues/347322](https://github.com/microsoft/vscode/issues/347322)

## Summary

Keep open: existing artifact-removal tools do not fully cover clearing an independently associated PR when a session moves to another branch. The automatic-versus-agent-controlled lifecycle needs a product decision.

## Change summary

Let a continuing session stop presenting its previous PR as current after switching branches, before a replacement PR exists.

## Best solution

Distinguish historical PR records from the current checkout's PR association so continued work does not retain misleading merged-PR status. Decide whether branch changes retire that association automatically or agents explicitly control it.

## Evidence

- **Requested workflow:** https://github.com/microsoft/vscode/issues/347322 describes continuing an existing session on another branch while the previous, possibly merged PR remains associated; retirement should not require creating another PR.
- **Existing capability and limitation:** src/vs/platform/agentHost/node/shared/artifactServerTools.ts exposes RemoveArtifactOrReference for records owned by the invoking chat. This removes a recorded entry and pending association, not arbitrary independently established repository associations; src/vs/platform/agentHost/test/node/sessionArtifactRemoval.test.ts explicitly tests preserving independent associations.
