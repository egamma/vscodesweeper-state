# Issue #248308 — Make extension signature verification mandatory on Linux Armhf platform

[https://github.com/microsoft/vscode/issues/248308](https://github.com/microsoft/vscode/issues/248308)

## Summary

Keep open: current main still explicitly exempts Linux Armhf from mandatory extension-signature enforcement. This team-authored Backlog debt records the unresolved follow-up to a temporary platform workaround.

## Change summary

Make failed extension-signature verification block extension installation on Linux Armhf, as it does on other built platforms.

## Best solution

Resolve the Armhf certificate-chain validation failure in the `@vscode/vsce-sign` verification path, then remove the platform exemption in `ExtensionManagementService` and cover Armhf enforcement with a regression test.

## Plan brief

- **Likely files:** `src/vs/platform/extensionManagement/node/extensionManagementService.ts`, `src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts`, `src/vs/platform/extensionManagement/test/node/extensionDownloader.test.ts`
- **Validation:** On a Linux Armhf build, install a correctly signed extension successfully, then verify that an extension producing an `Untrusted` signature result is rejected; add a targeted extension-management test asserting the Armhf platform no longer bypasses a failed verification result.
- **Behavior:**

  > Linux Armhf must enforce extension signatures consistently with other built Linux targets. A correctly signed extension must still install, while an invalid, untrusted, revoked, or otherwise unsuccessful signature result must prevent installation and remove the downloaded package. Acceptance requires both a successful signed-install check and a failed-verification check on Armhf.
- **Trace:**

  > Mandatory enforcement is decided in `ExtensionManagementService.downloadExtension` in `src/vs/platform/extensionManagement/node/extensionManagementService.ts`; its condition currently excludes `TargetPlatform.LINUX_ARMHF`. Verification itself is delegated by `ExtensionSignatureVerificationService.verify` in `src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts` to `@vscode/vsce-sign`. The exemption came from https://github.com/microsoft/vscode/pull/248291 after the Armhf certificate chains in https://github.com/microsoft/vscode/issues/248285 were reported as `NotTimeValid` and `Untrusted`. The boundary is Linux Armhf signature validation and enforcement: successful installs, unsigned-extension policy, other platforms, and the user-controlled verification setting must retain their existing behavior.
- **Open decisions:**
  - Should VS Code require a platform-level fix in `@vscode/vsce-sign` before restoring enforcement, or support a VS Code-owned Armhf trust configuration that produces the same certificate-validation contract?

## Evidence

- **current source:** `src/vs/platform/extensionManagement/node/extensionManagementService.ts:348-354` rejects unsuccessful verification only when the target platform is not `TargetPlatform.LINUX_ARMHF`, so the requested enforcement remains absent on current main.
