# Issue #263499 — Split individual chat response parts to list rows

[https://github.com/microsoft/vscode/issues/263499](https://github.com/microsoft/vscode/issues/263499)

## Summary

Keep open: current source still renders the contents of an individual response within one virtualized row, preserving the expensive path identified in the discussion. The newer performance tracking issues explicitly retain this work rather than superseding it.

## Change summary

Avoid eagerly rendering all response parts and embedded editors when opening a long coding-agent response.

## Best solution

Make rendering work within a long response proportional to the visible content while preserving response grouping, streaming, scrolling, and keyboard navigation. This needs a maintainer-led design pass over the chat view model and renderer rather than another isolated editor-rendering optimization.
