## Summary

Keep open: another reporter confirmed the same GHE-only model_not_supported failure, and the proposed authentication PR was closed without merging. Later agent-host work does not establish that this embedded CLI regression is fixed, and the older related reports describe different observable failures.

## Change summary

VS Code-launched Copilot CLI sessions reject every model for GHE users after upgrading from 1.118, while local chat and standalone CLI continue working.

## Best solution

Restore successful GHE-backed requests in the embedded Copilot CLI integration, with authentication and endpoint routing consistent with the working local-chat path. First distinguish this request-time regression from model-discovery failures and determine whether the remaining fix belongs in the integration or its SDK.

- **Behavior:**

  > GHE users report that delegating a VS Code chat to Copilot CLI fails with HTTP 400 model_not_supported for every tested model after upgrading from 1.118. - **Trace:**

  > CopilotCLISDK.getAuthInfo in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts obtains a GitHub session, calls SDK resolveAuthInfoFromToken, and falls back to token authentication with a github.com host. CopilotCLIModels consumes that auth result for model discovery; session creation separately runs through CopilotCLISessionService in node/copilotcliSessionService.ts. The inspected auth tests exercise github.com and proxy cases, not enterprise routing. https://github.com/microsoft/vscode/pull/314724 proposed a locally tested fix but never merged; its discussion identifies an SDK upstream lead and later agent-host work at https://github.com/microsoft/vscode/pull/324159.
