# Issue #329843 — Main process leaks all terminal output via Event.buffer on the localPty ProxyChannel — OOM-crashes the whole app silently

[https://github.com/microsoft/vscode/issues/329843](https://github.com/microsoft/vscode/issues/329843)

## Summary

Traced and confirmed in source: `ProxyChannel.fromService` wraps every `IPtyService` event (including `onProcessData`) in `Event.buffer` unless listed in `unbufferedEvents`, the `localPty` channel registration in `src/vs/code/electron-main/app.ts` passes no such list, and grepping the main-process/electron-main tree turns up no consumer of these events there — so in a default desktop session the buffer never flushes and grows unbounded, matching the reported heap-OOM crashes; independently reproduced by a second reporter.

## Change summary

The main-process `localPty` ProxyChannel buffers every pty event (notably high-frequency `onProcessData` terminal output) forever because no main-process listener ever attaches to drain it, causing an unbounded memory leak that OOM-crashes the whole app silently.

## Best solution

Register the `localPty` channel with `unbufferedEvents` covering the high-frequency/unconsumed pty events (at least `onProcessData`, and likely `onProcessReplay`/`onDidChangeProperty`/`onProcessExit` too, since none appear to have main-process consumers) — mirroring the existing `unbufferedEvents: ['onDidBlurMainWindow']` fix already applied to the `nativeHost` channel a few lines below in the same file (commit 72986a28). Also worth separately promoting the `[Event.buffer] potential LEAK detected` warning to production logging given how silent/unrecoverable this failure mode is.
