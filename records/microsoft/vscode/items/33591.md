# Issue #33591 — Option to allow quickSuggestions inside words

[https://github.com/microsoft/vscode/issues/33591](https://github.com/microsoft/vscode/issues/33591)

## Summary

Keep open: current source still prevents automatic quick suggestions at ordinary positions inside words, and existing settings do not provide the requested opt-in. This team-authored Backlog request remains necessary; the earlier duplicate target is closed and its claimed fix was explicitly disputed in the discussion.

## Change summary

Allow languages or users to opt into automatic quick suggestions while typing inside an existing word.

## Best solution

Provide an opt-in policy for mid-word quick suggestions in the editor suggestion configuration and triggering pipeline, preserving the current default. Settle whether language defaults, user settings, or completion-provider capabilities control that policy before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/suggest/browser/suggestModel.ts`, `src/vs/editor/contrib/suggest/test/browser/suggestModel.test.ts`
- **Validation:** Extend the suggestModel tests to cover typing inside a pre-existing word with the agreed opt-in enabled and disabled, then run scripts/test.sh --run src/vs/editor/contrib/suggest/test/browser/suggestModel.test.ts. Verify enabled mode automatically requests and displays completions, default mode retains existing triggering, and accepting a provider-supplied replacement range replaces the intended suffix.
- **Behavior:**

  > Users editing the middle of an existing word should be able to opt into automatic quick suggestions without explicitly invoking completion. Languages whose completion items replace the remaining symbol should be able to benefit from the agreed configuration contract. Without opting in, existing triggering behavior must remain unchanged, including the first-character-before-a-word exception. Acceptance covers automatic triggering in enabled mode, unchanged default behavior, and correct acceptance of completions with replacement ranges.
- **Trace:**

  > LineContext.shouldAutoTrigger in src/vs/editor/contrib/suggest/browser/suggestModel.ts rejects ordinary interior word positions, and _doTriggerQuickSuggest applies that restriction before consulting token-specific quick-suggestion settings. EditorQuickSuggestions in src/vs/editor/common/config/editorOptions.ts exposes token categories and display modes but no word-position policy; editor.suggest.insertMode governs acceptance rather than triggering. The existing assertAutoTrigger helper and Context - shouldAutoTrigger test in src/vs/editor/contrib/suggest/test/browser/suggestModel.test.ts provide a focused starting point for validation. https://github.com/microsoft/vscode/issues/32480#issuecomment-326294272 records the JSON language use case; the closed https://github.com/microsoft/vscode/issues/32201 does not resolve the remaining request. Preserve default behavior, explicit completion, trigger-character behavior, and existing replacement-range semantics. The unresolved boundary is how users and languages opt in, not whether the current automatic-trigger restriction exists.
- **Open decisions:**
  - Should mid-word triggering be controlled by a language-overridable user setting, a completion-provider capability, or both, and which takes precedence?
