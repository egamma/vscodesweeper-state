# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Real, actively-reproducing bug: Copilot agent-mode chat sessions disappear from the Sessions panel over Remote-SSH. The original report's events.jsonl theory doesn't match current main's architecture (listSessions enumerates AgentSessionRegistry, not raw events.jsonl presence — see AGENTS.md and node/agentService.ts), but comment 1's follow-up traces a plausible real cause: a workspace-identity mismatch between the persisted local path (e.g. `c:\Development\notebook`) and the synthesized `vscode-remote://ssh-remote+<host>/...` URI used when filtering the session list by workspace, so sessions get filtered out under one representation but not the other. Multiple independent reporters confirm this is still happening on 1.131–1.133.

## Change summary

Copilot 'Agent' mode chat sessions become unlisted/unopenable in the Sessions panel when working over Remote-SSH, especially after reload, even though the underlying session-store.db/events.jsonl data is intact.

## Best solution

Someone with the agent-host source needs to trace where the Sessions panel/session-list filters by workspace/working-directory identity (likely in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/, e.g. agentHostSessionListStore.ts or agentHostSessionWorkingDirectorySynchronizer.ts) and confirm whether a local-path vs. vscode-remote:// URI mismatch is silently excluding sessions from the list; fix should normalize/compare workspace identity consistently regardless of representation.
