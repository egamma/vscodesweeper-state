# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Real, actively-confirmed bug: agent-mode ('Copilot') chat sessions vanish from the Sessions panel on Remote-SSH, though the underlying transcript/registry data survives on the remote host. Multiple independent reporters (with concrete file/DB evidence) confirm the same symptom across recent stable releases, and the code shows a plausible mechanism — the CLI-backed session lister explicitly filters out agent-host-owned sessions, deferring their display to the Agent Host provider, whose workspace-scoping (Windows path vs. `vscode-remote://ssh-remote+...` URI) is a likely second contributing cause.

## Change summary

Agent-mode ('Copilot') chat sessions created over Remote-SSH stop appearing in the Sessions panel shortly after creation, even though their data still exists on the remote host.

## Best solution

Agent Host session enumeration for Remote-SSH needs to reconcile session workspace metadata (persisted as plain local paths) against the session provider's `vscode-remote://` workspace URI so it isn't excluded by an identity/workspace mismatch; likely touches src/vs/sessions/contrib/providers/agentHost/browser/localAgentHostSessionsProvider.ts and baseAgentHostSessionsProvider.ts, alongside the CLI-vs-agent-host session ownership split in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts (_getAllSessions). Given multiple contributing causes reported (missing events.jsonl correlation, workspace URI mismatch, SSH reconnect triggers), this likely needs a maintainer to consolidate the investigation before a fix lands.
