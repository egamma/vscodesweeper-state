# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Real, well-diagnosed bug in the agent-host chat sessions listing path — a second reporter independently confirmed it and even found the root cause is broader than the original report (a workspace-URI mismatch, not just a missing events.jsonl). No fix has landed on main yet, so this needs to go to the agent-host/sessions owners.

## Change summary

On Remote-SSH, chats created in normal Copilot (agent-host) mode disappear from the Sessions panel because the panel's listing logic only surfaces sessions backed by a CLI-style events.jsonl file, and a follow-up comment shows a related workspace-identity (path vs. vscode-remote:// URI) mismatch also hides sessions that do have events.jsonl.

## Best solution

The chat-sessions listing/enumeration code (extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts and the agent-host session providers under src/vs/workbench/contrib/chat/browser/agentSessions/) needs to stop gating visibility on events.jsonl presence and normalize workspace identity (local path vs. vscode-remote:// URI) consistently when filtering sessions for the active workspace — this is cross-cutting enough that it needs an agent-host/session-store owner to design the fix rather than a mechanical patch.

## Evidence

- **no matching fix on main:** git log for extensions/copilot/src/extension/chatSessions/ and src/vs/workbench/contrib/chat/browser/agentSessions/ since 2026-08-01 shows no commit addressing session enumeration or workspace-URI normalization; the only merged related PR (https://github.com/microsoft/vscode/pull/329723) fixes a different bug (agent-host settings loading at startup, https://github.com/microsoft/vscode/issues/329721), not session visibility.
- **second independent confirmation with broader root cause:** Reduce395's comment (2026-08-07) reproduces the disappearance even with a populated events.jsonl and valid session-store.db row, and traces it to a synthesized vscode-remote://ssh-remote+<host>/... URI not matching the persisted local workspace path — a second, related defect in the same subsystem.
