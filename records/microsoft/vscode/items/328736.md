# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Real, actively-confirmed bug: agent-mode ('Copilot') chat sessions disappear from the Sessions panel on Remote-SSH. Comment 7's code citation checks out — copilotcliSessionService.ts intentionally excludes `vscode-agent-host` clientName sessions from its own listing (by design, since the Agent Host owns those), but the actual Agent Host session enumeration over Remote-SSH appears to drop them, likely due to a local-vs-`vscode-remote://` workspace URI mismatch (per comment 1's counterexample with a fully populated events.jsonl still going missing). No fix has landed yet.

## Change summary

On Remote-SSH, chats created in 'Copilot' agent mode vanish from the Sessions panel shortly after creation, even though their data still exists on disk/in the registry.

## Best solution

Investigate the Agent Host session enumeration path for Remote-SSH workspaces (likely under src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/ or the platform agentHost session listing) to find where the `vscode-remote://ssh-remote+...` URI vs. the persisted local-style `cwd` causes a workspace-identity mismatch that filters out valid sessions, distinct from the already-by-design CLI-provider exclusion in copilotcliSessionService.ts.
