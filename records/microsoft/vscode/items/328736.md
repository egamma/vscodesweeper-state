# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Verified in source: the Copilot CLI session provider explicitly filters out any session whose `clientName` is `vscode-agent-host` before listing, so agent-mode ("Copilot") chats are never returned to the Sessions panel by that provider — they're expected to be listed by the Agent Host's own provider instead, which several commenters show fails to enumerate them correctly on Remote-SSH (workspace-URI mismatch between local path and `vscode-remote://` form). Multiple independent users confirm the symptom and root cause on recent stable builds; this is real and unresolved.

## Change summary

Agent-mode Copilot chat sessions vanish from the Sessions panel when working over Remote-SSH, even though their data is intact on disk/registry.

## Best solution

Fix the Agent Host's own session enumeration/listing path so it correctly surfaces sessions for Remote-SSH workspaces (matching normalized local vs. `vscode-remote://` URIs), since `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts` intentionally defers agent-host-owned sessions to that other provider (see the `AGENT_HOST_COPILOT_CLIENT_NAME` filter at lines 346 and 456-466).
