# Issue #328736 — Copilot chat sessions created in agent ("Copilot") mode disappear from the Sessions panel on Remote-SSH

[https://github.com/microsoft/vscode/issues/328736](https://github.com/microsoft/vscode/issues/328736)

## Summary

Genuine, actively-reproducing bug in the Agent Host session listing path, corroborated by multiple independent reporters (1.131–1.133) and grounded in code: agent-mode chats are stored via the SDK/registry `session.db` path without an `events.jsonl`, and downstream session listing has historically gated on that file's existence (per the explicit comment in `copilotChatSessions.contribution.ts`), while a later comment adds a second, distinct workspace-URI-normalization failure mode (`vscode-remote://...` vs raw path) for Remote-SSH. No fix has landed for either cause yet.

## Change summary

On Remote-SSH, chats created in normal Copilot (agent) mode vanish from the Sessions panel because they lack an events.jsonl file and/or their workspace identity doesn't match the synthesized remote URI used for lookup.

## Best solution

Agent Host / Sessions team should fix session enumeration to not require an events.jsonl for agent-mode (SDK-store) chats, and normalize workspace identity (local path vs `vscode-remote://` URI) consistently between session persistence and session-provider lookup — likely touching `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`, `src/vs/platform/agentHost/node/agentService.ts` (listSessions/registry overlay), and the CLI-backend session-listing gate referenced in `copilotChatSessions.contribution.ts`.
