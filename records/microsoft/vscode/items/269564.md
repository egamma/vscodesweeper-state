# Issue #269564 — Allow to import prompt/instruction/modes file via `vscode` link for files that need authentication

[https://github.com/microsoft/vscode/issues/269564](https://github.com/microsoft/vscode/issues/269564)

## Summary

Keep open for design: the existing prompt-install URL flow cannot fetch resources requiring organization-specific authentication, and a maintainer explicitly agreed this should be investigated. The request needs a security-conscious product decision around credential handling and trusted-source policy.

## Change summary

Allow `vscode:chat-prompt/install` links to import prompt, instruction, and mode files from internal HTTP(S) sources that require authentication.

## Best solution

Define a secure authenticated-fetch contract for chat customization imports, including which credential providers may participate and whether administrators or users can explicitly allow trusted origins, then apply it consistently to prompt, instruction, and mode installation links.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization`
- **Validation:** Exercise a `vscode:chat-prompt/install` URL against an authenticated test endpoint: an explicitly trusted origin should fetch and reach destination selection, while an untrusted origin and failed authentication must remain blocked with a clear error.
- **Behavior:**

  > Users should be able to install prompt, instruction, and mode files from approved internal HTTP(S) locations that require authentication. The flow must obtain authorization only through an explicitly supported mechanism, preserve the existing confirmation and destination-selection experience, and fail visibly without leaking credentials. Unapproved origins must remain blocked, and ordinary public GitHub imports must continue to work.
- **Trace:**

  > The issue reproduces through the `vscode:chat-prompt/install` URL handler: after user confirmation, fetching `http://localhost:8000/example.prompt.md` fails before the server observes a GET. Public GitHub-hosted imports work, so the uncertainty begins at how the import fetch should participate in authentication and origin trust rather than whether prompt installation itself exists. The owning surface is the chat customizations import path under `src/vs/workbench/contrib/chat/browser/aiCustomization`; preserve the existing external-URI confirmation and do not weaken general trusted-domain or credential protections. The Promptu extension linked in the discussion runs authenticated remote prompts but does not satisfy built-in file import.
- **Open decisions:**
  - Which authentication mechanisms may the import flow use: VS Code authentication providers, browser/session credentials, an explicit request configuration, or a narrower supported subset?
  - Is authorization granted per import, by a user-managed trusted-origin list, or through an administrator-manageable policy for organizational deployments?
  - Should authenticated remote imports be supported uniformly for prompt, instruction, and mode files, or begin with the existing prompt-install URI contract only?
