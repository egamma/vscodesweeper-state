# Issue #300579 — Debug events snapshot for Copilot CLI and Claude Agent

[https://github.com/microsoft/vscode/issues/300579](https://github.com/microsoft/vscode/issues/300579)

## Summary

Keep open as accepted backlog work. Current main has substantial Copilot CLI debug-log support, but the provider remains Copilot-specific and the requested Claude Agent and broader external-harness snapshot parity is not complete.

## Change summary

Expose Debug Events Snapshot and Agent Debug Logs data for Copilot CLI, Claude Agent, and other supported external agent harnesses.

## Best solution

Define a provider-neutral debug-event ingestion and snapshot contract, then adapt Copilot CLI and Claude Agent lifecycle, model, tool, and error data to it with consistent persistence, content-capture, and historical-session behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatDebug/agentHostChatDebugProvider.ts`, `src/vs/workbench/contrib/chat/browser/copilotCliEventsUri.ts`, `src/vs/workbench/contrib/chat/common/chatDebugService.ts`, `src/vs/platform/agentHost/common/otel/agentHostOTelService.ts`, `src/vs/platform/agentHost/node/claude/claudeAgentSession.ts`, `src/vs/workbench/contrib/chat/test/browser/agentHostChatDebugProvider.test.ts`
- **Validation:** Add provider-level tests proving representative Copilot CLI and Claude Agent sessions produce equivalent normalized lifecycle, model-turn, tool-call, and error events, and that a debug-events snapshot reopens the correct session with its timestamp filter.
- **Behavior:**

  > Supported Copilot CLI and Claude Agent sessions expose their lifecycle, model, tool, subagent, warning, and error events through Agent Debug Logs. Taking a debug-events snapshot associates it with the correct session and timestamp, and opening the attachment returns to the corresponding filtered event view. Content capture remains explicitly controlled, and historical-session behavior is consistent across the supported harnesses.
- **Trace:**

  > The current workbench provider in src/vs/workbench/contrib/chat/browser/chatDebug/agentHostChatDebugProvider.ts reads Copilot CLI events.jsonl and converts it to IChatDebugEvent records. URI resolution in src/vs/workbench/contrib/chat/browser/copilotCliEventsUri.ts is intentionally limited to Copilot CLI session schemes, while Claude supplies native SDK telemetry through IAgentHostOTelService from src/vs/platform/agentHost/node/claude/claudeAgentSession.ts. Chat Debug has no corresponding Claude session adapter in the current provider directory. Preserve existing Copilot CLI event conversion and content-capture controls; the plan must establish a provider-neutral boundary rather than teaching shared services to branch arbitrarily on provider IDs. Related ownership and parity context: https://github.com/microsoft/vscode/issues/299264 and https://github.com/microsoft/vscode-internalbacklog/issues/6995.
- **Open decisions:**
  - Should support cover only Copilot CLI and Claude Agent sessions hosted by VS Code Agent Host, or also independently launched external CLI and Claude processes?
  - Which event content is retained for snapshots when content capture is disabled, and should that policy be identical across harnesses?
  - Must snapshots and debug logs remain available after restart for every harness, or is live-session-only support acceptable for providers without a compatible persistent event stream?
