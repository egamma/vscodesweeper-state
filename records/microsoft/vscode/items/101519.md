# Issue #101519 — Git - File watcher events should respect `.gitignore`

[https://github.com/microsoft/vscode/issues/101519](https://github.com/microsoft/vscode/issues/101519)

## Summary

Keep open: current Git refresh handling still does not consult .gitignore, and the maintainer explicitly considered adding that behavior. The older file-watcher request is related, but does not establish the same observable Git-polling symptom required to close this re-reviewed item as a duplicate.

## Change summary

Prevent changes to gitignored database and build-output files from repeatedly triggering Git status refreshes.

## Best solution

Make Git auto-refresh disregard irrelevant ignored-file changes while retaining refreshes for tracked files and repository metadata. Start from the maintainer's suggested top-level .gitignore scope and establish the user-visible activation behavior before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/package.json`
- **Validation:** In a focused VS Code window with git.autorefresh enabled, use a repository whose top-level .gitignore excludes a database-output directory. Repeatedly modify untracked files there and inspect Git Trace output: ignore-aware refresh should avoid repeated status commands, while modifying a tracked file or changing branches must still update Source Control. Repeat with the repository root and a nested directory opened in a multi-root workspace.
- **Behavior:**

  > Continuous changes to ignored database or build-output files should not repeatedly refresh Git status when ignore-aware refresh is active. Tracked-file changes and repository metadata changes must still update Source Control automatically. Validate both repository-root and nested-folder workspace layouts, including multi-root workspaces. Decide whether the behavior applies by default or requires explicit opt-in.
- **Trace:**

  > In extensions/git/src/repository.ts, the constructor creates a repository-wide RelativePattern watcher and forwards working-tree and .git events to onFileChange. That method does not inspect the changed URI or Git ignore rules; it schedules status through eventuallyUpdateWhenIdleAndWait and updateWhenIdleAndWait. The maintainer suggested limiting ignore handling to the top-level .gitignore for performance: https://github.com/microsoft/vscode/issues/101519#issuecomment-652593563. Preserve tracked-file refresh, repository metadata handling, existing operation guards and refresh throttling; this is not a general rewrite of workbench file watching. The related global watcher request at https://github.com/microsoft/vscode/issues/62725 operates at a broader surface and is not a verified same-symptom canonical. Source inspection establishes the missing filtering, but runtime behavior and performance were not exercised in this read-only review.
- **Open decisions:**
  - Should ignore-aware Git auto-refresh become the default behavior, or be an opt-in setting that preserves today's refresh behavior unless enabled?

- **Current Git event path:** extensions/git/src/repository.ts:930-952 creates a repository-wide '**' watcher and filters working-tree events only to separate .git paths. At lines 3334-3373, onFileChange ignores its URI argument, checks autorefresh, repository size and operation state, then schedules status() through debounce/throttle handling. This path contains no ignore-file check; sustained ignored-file events can continue scheduling refreshes.
