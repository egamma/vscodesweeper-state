[https://github.com/microsoft/vscode/issues/282410](https://github.com/microsoft/vscode/issues/282410)

## Summary

Legitimate feature request that passed the community upvote threshold (22 votes) and was promoted to Backlog. Requests a low-resource default configuration for Remote-SSH in shared/HPC environments — no existing built-in capability fully addresses this, and no canonical open issue absorbs it.

## Change summary

Provide a resource-conservative default configuration or profile for VS Code Remote-SSH that minimizes background activities (file watching, indexing, language servers) in shared multi-user environments.

## Best solution

Implement a resource-constrained profile or setting bundle for the remote server that caps file watching scope, disables heavy indexing by default, and limits extension host resource usage. This likely belongs in the Remote-SSH extension's server-side configuration (microsoft/vscode-remote-release) or as a core remote platform feature exposing resource policy controls. The related #233842 (CPU limiting for extension host) was closed without resolution, suggesting this gap persists.
