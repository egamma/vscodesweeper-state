# Issue #164267 — Add support for language-aware word wrap

[https://github.com/microsoft/vscode/issues/164267](https://github.com/microsoft/vscode/issues/164267)

## Summary

Keep open: current wrapping settings still cannot give Markdown lists hanging indentation while leaving ordinary paragraphs unchanged. This accepted Backlog request has 66 upvotes, and the verified related issues do not provide an older open canonical covering the same behavior.

## Change summary

Support language-aware soft wrapping so Markdown list continuations align with their item text without adding indentation to ordinary paragraphs.

## Best solution

Provide syntax-aware continuation indentation through the editor wrapping infrastructure, with Markdown list support and consistent behavior across simple and advanced wrapping. Preserve existing wrapping modes and document the activation behavior before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/viewModel/viewModelLines.ts`, `src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts`, `src/vs/editor/browser/view/domLineBreaksComputer.ts`, `extensions/markdown-language-features/package.json`, `src/vs/editor/test/common/viewModel/monospaceLineBreaksComputer.test.ts`, `src/vs/editor/test/browser/view/domLineBreaksComputer.test.ts`
- **Validation:** After the activation contract is agreed, add focused wrapping tests for a Markdown document containing long ordinary paragraphs, unordered lists, numbered lists, and nested lists. Verify that list continuations align with item text, paragraph continuations retain their normal indentation, and results remain consistent after width changes under simple and advanced wrapping; existing wrapping modes must retain their behavior.
- **Behavior:**

  > Markdown source containing both long list items and ordinary paragraphs should support soft wrapping that aligns list continuations with the item text without adding a hanging indent to paragraphs. The behavior must remain correct when the editor is resized and must not insert hard line breaks or modify document text. Acceptance should cover unordered, numbered, and nested lists under both wrapping strategies while preserving existing explicit wrapping modes.
- **Trace:**

  > WrappingIndentOption in src/vs/editor/common/config/editorOptions.ts exposes only uniform indentation modes. computeWrappedTextIndentLength in src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts derives indentation from whitespace and tab stops; createLineBreaks in src/vs/editor/browser/view/domLineBreaksComputer.ts applies the same uniform policy through DOM measurement. ViewModelLinesFromProjectedModel.createLineBreaksComputer in src/vs/editor/common/viewModel/viewModelLines.ts supplies content and injected text but no language-aware policy. Source inspection establishes the missing capability, not a broken implementation of an existing syntax-aware mode. The boundary is visual soft wrapping: preserve document contents, existing modes, injected-text behavior, and wrapping performance. https://github.com/microsoft/vscode/pull/134171 addresses advanced wrapping's existing indentation support; https://github.com/microsoft/vscode/issues/171457 concerns table wrapping suppression and should not silently expand this feature's scope.
- **Open decisions:**
  - Should language-aware indentation be an opt-in wrapping mode, or become the default for Markdown while retaining an explicit way to select the existing behavior?
  - Should the initial public capability be Markdown-specific list indentation, or a language-extensible wrapping contract usable by other languages?

## Evidence

- **Existing capability does not cover the request:** src/vs/editor/common/config/editorOptions.ts:5624–5640 registers editor.wrappingIndent with only none, same, indent, and deepIndent. These modes apply a uniform indentation policy; extensions/markdown-language-features/package.json:1915–1917 enables editor.wordWrap for Markdown but supplies no syntax-aware continuation indentation.
- **Current wrapping implementation:** src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts:614–645 computes continuation indentation from leading whitespace plus zero, one, or two tab stops, without recognizing list markers. src/vs/editor/browser/view/domLineBreaksComputer.ts:68–140 similarly computes additional indentation from the shared WrappingIndent value. A top-level list and an ordinary paragraph therefore cannot receive the requested distinct treatment under one existing mode.
- **Language-context boundary:** src/vs/editor/common/viewModel/viewModelLines.ts:314–328 passes line content and injected text to the wrapping factories, together with one wrappingIndent value. This context does not currently expose language tokens or a syntax-specific indentation policy.
