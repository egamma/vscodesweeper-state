# Issue #85564 — Git - Git should be able to automatically track new files

[https://github.com/microsoft/vscode/issues/85564](https://github.com/microsoft/vscode/issues/85564)

## Summary

Keep this accepted, well-supported feature request open: Smart Commit does not cover automatically tracking newly created files for terminal commits. Current source still leaves that gap, and no verified older canonical issue was found.

## Change summary

Offer automatic Git tracking of newly created files so subsequent terminal git commit -a includes their latest saved contents.

## Best solution

Provide an opt-in workflow in the built-in Git extension that makes newly created, non-ignored files eligible for terminal git commit -a without requiring a VS Code commit. Settle which file-creation events qualify while preserving existing staging behavior when the option is disabled.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/repository.ts`, `extensions/git/src/git.ts`
- **Validation:** In a disposable Git repository with an initial commit, enable the proposed option, create and save a non-ignored file through VS Code, modify and save it again, then run git commit -a -m test in the terminal and verify git show HEAD:path contains the latest saved contents. Repeat with the option disabled and verify the new file remains untracked; verify ignored files are not added and unrelated tracked changes are not automatically staged. Add checks for externally created and pre-existing untracked files according to the agreed scope.
- **Behavior:**

  > Users who commit from the terminal can opt into automatic tracking of new files created through VS Code. After creating a file and subsequently editing and saving it, git commit -a must include its latest saved contents without a separate manual git add or a VS Code commit. Ignored files must remain excluded, and disabling the option must preserve current behavior. Acceptance should inspect both the Git index before committing and the resulting committed contents.
- **Trace:**

  > The central requirement is documented in https://github.com/microsoft/vscode/issues/85564: automatic tracking before terminal commits, not Smart Commit. git.enableSmartCommit and git.smartCommitChanges are registered in extensions/git/package.json and consumed by Commands.smartCommit in extensions/git/src/commands.ts; Repository.commit performs the associated add during a VS Code commit. Repository's watcher in extensions/git/src/repository.ts combines create, change and delete notifications, and onFileChange leads to status refresh without automatic tracking. That watcher does not distinguish editor-created files from files created by other tools, so using its event scope would affect more than the reporter's explicit case. Preserve manual staging, ignored-file behavior and existing commit commands; the broader request to auto-stage every modification is not part of this issue's central requirement. The initial staging-snapshot objection and the reporter's commit -a response belong in the design discussion.
- **Open decisions:**
  - Should the opt-in behavior track only files created or first saved through VS Code, or also files newly created by external tools while the repository is open?
