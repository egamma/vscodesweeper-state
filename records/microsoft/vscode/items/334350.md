# Issue #334350 — Control Agent Merge/ PR Autopilot per session

[https://github.com/microsoft/vscode/issues/334350](https://github.com/microsoft/vscode/issues/334350)

## Summary

A real UI and configuration gap remains: current main supports Agent Merge controls per active session/chat folder, but exposes them in the Changes title-bar dropdown rather than beside the chat input, and merged-session auto-archive remains application-scoped rather than configurable per session.

## Change summary

Expose Agent Merge/PR Autopilot and merged-session archival controls in a per-session dropdown beside the chat input.

## Best solution

Design a compact chat-input-adjacent control that reflects the active chat folder's Agent Merge state and determines whether the global merged-session cleanup policy can be overridden for an individual session.

- **Fit:** aligned
- **Reason:** Giving users clear, contextual control over autonomous pull-request behavior improves AI-assisted development and keeps the Agents Window interaction coherent.
- **Evidence:** Durable themes: AI-assisted development and simple, uniform Workbench UI interactions.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/agentMergeActions.ts`, `src/vs/sessions/browser/sessionAgentMerge.ts`, `src/vs/workbench/contrib/chat/browser/agentSessionsConfiguration.ts`, `src/vs/platform/agentHost/node/agentHostSessionLifecycle.ts`
- **Validation:** Add focused menu/action tests showing that switching active sessions updates the chat-input control and that changing one session's selections does not affect another; if per-session auto-archive is approved, add lifecycle tests proving its override precedence over the application default.
- **Behavior:**

  > Each eligible agent session should expose understandable Agent Merge/PR Autopilot controls beside its chat input, with displayed values following the active session or chat folder rather than leaking across sessions. Existing global defaults must remain available and existing pull-request operations must retain their behavior. If merged-session archival is included, the UI must clearly communicate whether the current session follows or overrides the global cleanup policy.
- **Trace:**

  > Current Agent Merge state is resolved through getSessionAgentMergeConfigurationObservable in src/vs/sessions/browser/sessionAgentMerge.ts and written through the provider methods used by src/vs/sessions/contrib/providers/agentHost/browser/agentMergeActions.ts. Those actions currently contribute to the Changes operations/title-bar menus rendered by src/vs/sessions/contrib/changes/browser/changesView.ts, not the chat-input toolbar. The chat-input extension surface is owned by src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts. Automatic merged-session cleanup is currently driven by application-scoped settings registered in src/vs/workbench/contrib/chat/browser/agentSessionsConfiguration.ts and consumed by the Agent Host lifecycle; preserve existing global behavior unless an explicit session override is chosen. Related completed global-cleanup work is https://github.com/microsoft/vscode/issues/334334 and https://github.com/microsoft/vscode/pull/334341.
- **Open decisions:**
  - Should the chat-input dropdown replace the existing Changes title-bar Agent Merge controls, or mirror them in both locations?
  - Should the control apply to the whole session or, matching current multi-folder behavior, to the active chat folder?
  - Should automatic archival offer a per-session inherit/on/off override, or remain an application-wide cleanup policy with only a direct archive action in this dropdown?

## Evidence

- **existing partial capability:** Commit ca8c602341cc7557ac3c95edfad647932ead3890 and https://github.com/microsoft/vscode/pull/332987 added session-scoped Agent Merge enablement, repair-action toggles, and merge choices, but explicitly placed them in the Changes title-bar operations dropdown; the PR predates this issue and does not reference https://github.com/microsoft/vscode/issues/334350.
- **current source:** src/vs/sessions/contrib/providers/agentHost/browser/agentMergeActions.ts registers Enable, Disable, Configure, and merge-policy actions in Menus.ChangesOperationsDropdown and Menus.ChangesAgentMerge; src/vs/sessions/contrib/changes/browser/changesView.ts renders that menu through the Changes view button bar.
- **archive scope gap:** src/vs/workbench/contrib/chat/browser/agentSessionsConfiguration.ts registers chat.agentSessions.autoMarkAsDoneMergedSessionsAfterDays with ConfigurationScope.APPLICATION, while src/vs/sessions/contrib/github/common/sessionLifecycleSettings.ts exposes only the global cleanup setting IDs; no per-session archival override is present.
- **linked work:** https://github.com/microsoft/vscode/issues/334334 was completed by https://github.com/microsoft/vscode/pull/334341 as global opt-in cleanup. It is closed and therefore cannot be a duplicate canonical for this remaining per-session UI/configuration request.
