# Issue #295947 — Browser: DevTools becomes blank on overlaps

[https://github.com/microsoft/vscode/issues/295947](https://github.com/microsoft/vscode/issues/295947)

## Summary

The docked DevTools placeholder gap remains in current source. A related stretching regression was fixed separately, and its maintainer explicitly retained this issue for the remaining blank DevTools behavior.

## Change summary

Preserve the appearance of docked Integrated Browser DevTools while overlapping workbench UI temporarily hides the native browser view.

## Best solution

Make the overlap placeholder represent both the page and docked DevTools without changing page-only screenshot behavior or including undocked DevTools windows.

Establish an automated check using the existing Integrated Browser harness where native capture can be observed.
- **Behavior:**

  > When workbench UI overlaps an Integrated Browser with docked DevTools, the temporary placeholder must retain the appearance and layout of both the page and DevTools rather than leaving DevTools blank. Removing the overlap must restore the live browser normally. Undocked DevTools must remain independent, and ordinary page screenshots must retain their existing content and geometry.
- **Trace:**

  > WebContentsViewHost in src/vs/workbench/contrib/browserView/electron-browser/webContentsViewHost.ts detects overlap, captures a placeholder, and hides the native view. BrowserView.captureScreenshot in src/vs/platform/browserView/electron-main/browserView.ts captures only the page webContents; DevTools uses separate webContents and is absent from that image. The shared capture path also supports page screenshots and chat attachments, so their existing semantics are outside the requested change. https://github.com/microsoft/vscode/issues/322208 documents an independently reproduced occurrence and explicitly distinguishes the stretching fix in https://github.com/microsoft/vscode/pull/324108 from this remaining defect. The trace establishes the missing imagery but not reliable native dock-state geometry or a runnable regression assertion; investigate those boundaries before implementation. The existing Integrated Browser smoke harness is test/smoke/src/areas/browserView/browserView.test.ts.
