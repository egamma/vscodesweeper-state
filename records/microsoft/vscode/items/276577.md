## Summary

The older, open report tracks the same observable failure: creating a native window tab from a non-final tab scrambles project tab names. Consolidate this report there, preserving its detailed diagnosis and the Positron workaround.

## Change summary

Creating a new macOS native window tab can swap the new tab's title with an existing project's title.

## Best solution

Track correct native-tab title association in https://github.com/microsoft/vscode/issues/205269, carrying over this report's automatic/manual tab-grouping diagnosis. Any eventual fix must preserve explicit New Window Tab behavior when the macOS tab preference is Never.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/205269 is OPEN and was created on 2024-02-15, before this report. Its reproduction opens several project windows, selects a middle native tab, and invokes Window → New Tab; the resulting tab names are incorrect. This matches the reporter-observable symptom and trigger, satisfying the stronger duplicate bar for a re-reviewed item.
- **Independent confirmations:** The canonical includes confirmation on a fresh installation without extensions at https://github.com/microsoft/vscode/issues/205269#issuecomment-2675377539 and a further report against VS Code 1.132.0 at https://github.com/microsoft/vscode/issues/205269#issuecomment-5272191829.
- **Complete diagnosis and behavioral boundary:** https://github.com/microsoft/vscode/issues/276577#issuecomment-3749882938 identifies simultaneous automatic grouping through tabbingIdentifier and manual grouping through addTabbedWindow(). It also explains why skipping manual grouping whenever window.nativeTabs is enabled breaks New Window Tab when the OS preference is Never.
- **Current source retains both paths:** src/vs/platform/windows/electron-main/windows.ts:204-207 sets tabbingIdentifier when window.nativeTabs is true. nativeHostMainService.ts:1107-1114 sets forceNewTabbedWindow for New Window Tab; windowsMainService.ts:1616-1620 then calls addTabbedWindow(), which windowImpl.ts:1240-1243 delegates to Electron. These paths remain present; no runtime reproduction was performed, and the checkout's shallow history cannot establish a comprehensive absence of fixes.
- **Downstream workaround, not a VS Code fix:** https://github.com/posit-dev/positron/pull/11367 is merged and disables automatic grouping while retaining manual grouping. Its diff explicitly references this issue, but adopts Positron-specific semantics that ignore the OS tab preference. Current VS Code still sets tabbingIdentifier, so the downstream merge does not establish that this report is fixed here.
