# Issue #332724 — Sessions summary showing most recent changes count even when they have been reviewed

[https://github.com/microsoft/vscode/issues/332724](https://github.com/microsoft/vscode/issues/332724)

## Summary

Reasonable report with clear steps and screenshots showing the sessions-list changes pill doesn't drop after changes are kept/reviewed; the reporter themselves is unsure whether this is a bug or an intentional recent design change, so this needs a maintainer/product call rather than a mechanical fix.

## Change summary

After 'Keep'-ing an agent's changes in a session, the session summary's file/insertion/deletion pill still shows the pre-review counts instead of updating.

## Best solution

A sessions-area maintainer should clarify the intended semantics of the changes pill (cumulative session-wide unreviewed changes vs. latest-turn diff) referenced in the linked docs, and if the current per-turn/provider-supplied `changesSummary` (see src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts and src/vs/sessions/services/sessions/common/sessionChangesStatsCache.ts) should instead reflect only unreviewed/pending changes, adjust how it is computed/reset on keep.
