# Issue #335492 — Workspace trust dialog should identify the remote agent environment and clarify trust scope

[https://github.com/microsoft/vscode/issues/335492](https://github.com/microsoft/vscode/issues/335492)

## Summary

The clarity gap remains on current main: remote-session trust requests show generic folder copy and a remote path without passing the available remote-environment identity or clearly distinguishing local trust persistence from remote execution. This is bounded Agents Window security UX polish and should remain open.

## Change summary

Make the workspace trust prompt for remote agent sessions identify the remote environment and explain the local and remote effects of granting trust.

## Best solution

Present the remote workspace and host as one clear identity, then state that VS Code stores the trust decision locally and uses it to permit the agent session to read, modify, and execute against that remote folder without implying a broader host-side trust change.
