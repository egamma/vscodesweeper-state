# Issue #158994 — Improvements to creating folders via simple picker

[https://github.com/microsoft/vscode/issues/158994](https://github.com/microsoft/vscode/issues/158994)

## Summary

Folder creation exists, but the picker still does not advertise it while entering a missing path, and the confirmation title names only the final folder segment. Keep this team-authored Backlog request open; the related newer requests do not establish an eligible canonical duplicate.

## Change summary

Make folder creation discoverable in the simple file picker and clearly identify the complete missing path before creation.

## Best solution

Explain the available creation action before acceptance and make the confirmation unambiguous for nested missing directories in SimpleFileDialog. Preserve the existing creation and cancellation behavior rather than treating creation support alone as completion of this UX request.

## Plan brief

- **Likely files:** `src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts`, `src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts`
- **Validation:** After agreeing on the interaction, exercise Save As with files.simpleDialog.enable enabled and a path containing multiple missing directory segments: verify that creation is discoverable before acceptance, the confirmation identifies the intended missing hierarchy, confirmation saves successfully, and cancellation creates nothing. Add focused simpleFileDialog tests for the agreed hint/action and confirmation text while preserving existing folder-only creation tests.
- **Behavior:**

  > When a user enters a nonexistent directory path in the simple save picker, the interface should explain that accepting can create the missing folders rather than presenting only an existence warning. For a nested missing path such as blah/foo/bar, the creation confirmation should clearly identify the hierarchy being created. Existing successful saves, overwrite confirmations, folder-only creation, and cancellation behavior must remain intact. Acceptance must cover both discoverability before confirmation and understandable nested-path confirmation.
- **Trace:**

  > SimpleFileDialog.tryUpdateItems in src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts assigns remoteFileDialog.badPath when a nonexistent path ends in a separator; that message still provides only an existence warning and home-directory navigation hint. SimpleFileDialog.validate already offers creation for missing save destinations and eligible folder-only open targets, but constructs the confirmation title from a basename. yesNoPrompt separately displays the full target path in its input, so distinguish improving the explanation from adding creation functionality that already exists. The relevant test suite is src/vs/workbench/services/dialogs/test/browser/simpleFileDialog.test.ts and already exercises nested folder-only creation. https://github.com/microsoft/vscode/issues/186511 concerns creation capability, while https://github.com/microsoft/vscode/issues/320384 concerns editing during confirmation; neither settles this issue's discoverability design. Preserve filesystem eligibility checks and creation/cancellation semantics; the unresolved boundary is the user-facing affordance before acceptance.
- **Open decisions:**
  - Should a creatable missing path be advertised through an inline message explaining Enter, or through an explicit selectable creation action in the picker?
