# Issue #340422 — Local chat harness sandbox: Unix sockets are allowed when allowNetwork is true (now by default)

[https://github.com/microsoft/vscode/issues/340422](https://github.com/microsoft/vscode/issues/340422)

## Summary

This describes a potential sandbox-escape/privilege concern — enabling general outbound network access (chat.agent.sandbox.network.allowNetwork) appears to also implicitly allow Unix domain sockets (e.g. the Docker daemon socket), which could let a sandboxed agent indirectly access host files via the Docker daemon. Security-sensitive reports are always kept open for a human to handle, never auto-closed.

## Change summary

Local harness sandbox: enabling chat.agent.sandbox.network.allowNetwork (now default true) also appears to allow access to local Unix sockets such as the Docker daemon socket, bypassing the fileSystem sandbox restrictions, and chat.agent.sandbox.network.allowLocalNetwork=false does not block it.

## Best solution

A maintainer with agent-host sandbox ownership should confirm whether allowNetwork intentionally grants Unix-socket access on macOS, decide whether Unix sockets should instead follow chat.agent.sandbox.fileSystem.* rules (or a dedicated allowUnixSockets/allowAllUnixSockets setting as already exposed in the advanced runtime config), and update the setting description and default accordingly — likely in src/vs/platform/agentHost/node/sessionSandbox.ts, copilotSandboxPolicy.ts, and sandboxConfigForSdk.ts.
