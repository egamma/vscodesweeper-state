# Issue #237861 — Fix `CompletionItem.command` deprecation for built-in js/ts

[https://github.com/microsoft/vscode/issues/237861](https://github.com/microsoft/vscode/issues/237861)

## Summary

The current source still falsely reports CompletionItem.command deprecation for unchanged built-in JavaScript/TypeScript completion commands. An open PR explicitly addresses this issue, so keep it open pending review and resolution of that candidate.

## Change summary

Stop reporting a command-change deprecation when resolving a JavaScript/TypeScript completion whose command was already supplied and remains unchanged.

## Best solution

Review and resolve https://github.com/microsoft/vscode/pull/332573 so unchanged completion commands do not generate deprecation reports while genuine command changes remain detectable. Preserve the built-in provider's command arguments and completion-application behavior.

## Evidence

- **Built-in trigger:** extensions/typescript-language-features/src/languageFeatures/completions.ts:813–817 sets item.command during provideCompletionItems with arguments: [item]. Its provider resolveCompletionItem at lines 892–897 resolves and returns that same item.
- **False-positive path on current main:** src/vs/workbench/api/common/extHostLanguageFeatures.ts:1217–1248 converts the completion before and after provider resolution, then reports CompletionItem.command deprecation when commandIdent differs. _convertCompletionItem maps CommandsConverter's $ident into that field.
- **Identity changes without command changes:** src/vs/workbench/api/common/extHostCommands.ts:367–407 allocates a fresh identifier using ++this._cachIdPool whenever a contributed command has nonempty arguments. Thus the built-in completion's unchanged command receives different identifiers across the two conversions, conclusively triggering the report without execution.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/332573 is currently OPEN, explicitly says Fixes #237861, and proposes replacing the DTO identity comparison with a command comparison plus a regression test. It is not a landed fix; its author also states that the test and type check were not run.
- **Original tracking context:** https://github.com/microsoft/vscode/issues/237857 tracks investigation of deprecated API usage through linked issues; it does not itself establish that this completion-specific defect is resolved.
- **Canonical search:** A repository issue search for CompletionItem.command found this report, an open request concerning textEdit.newText resolve support, and closed historical command reports; it did not establish an older open canonical owning this false-positive deprecation.
