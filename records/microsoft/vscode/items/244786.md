## Evidence

- **Reported trigger and recovery:** https://github.com/microsoft/vscode/issues/244786 describes Windows 11 24H2 build 26100.3476 with VS Code 1.98.2: tapping left Ctrl intermittently blocks keyboard and mouse input while the caret continues blinking; opening Start restores input. The reporter states that extensions are disabled; there are no independent confirmations.
- **Current keyboard event path:** src/vs/workbench/services/keybinding/browser/keybindingService.ts:274–305 registers window keydown and keyup listeners. They invoke _dispatch and _singleModifierDispatch respectively, conditionally preventing the individual keyboard event's default behavior. This inspected path does not establish why mouse input would also stop.
- **Modifier dispatch inspection:** src/vs/platform/keybinding/common/abstractKeybindingService.ts:237–340 handles composition, modifier-release tracking, and dispatch. Single-modifier tracking expires after 300 ms, and an undispatchable modifier keydown returns without preventing its default behavior. These paths do not conclusively reproduce the reported persistent input lockout or prove its absence.
