## Summary

Still reproducible from current source: invoking `workbench.action.chat.retry` from a keybinding or programmatically provides no response argument, so the handler returns without retrying. The footer button works because its menu invocation supplies that response context.

## Change summary

Make the Copilot Chat retry command work when invoked through a user-assigned keybinding or programmatically, not only from the response footer button.

## Best solution

Have the chat retry action resolve the applicable response from the active or last-focused chat widget when no menu context is supplied, while preserving explicit response-context behavior for footer actions.
