# Issue #73840 — New revealProblems property in task presentation options is missing from the API

[https://github.com/microsoft/vscode/issues/73840](https://github.com/microsoft/vscode/issues/73840)

## Summary

The extension API still lacks revealProblems, although tasks.json supports it. Keep this accepted API request open: the existing configuration surface does not cover extension-controlled presentation, and no verified canonical or completed fix was found.

## Change summary

Expose task problem-panel reveal behavior through TaskPresentationOptions so extensions can control it for contributed tasks.

## Best solution

Provide a supported, typed task presentation API for the existing always, onProblem, and never behaviors, preserving current defaults and terminal reveal semantics. Settle the public API contract with the tasks/API owners before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/shared/tasks.ts`, `src/vs/workbench/api/common/extHostTask.ts`, `src/vs/workbench/api/browser/mainThreadTask.ts`, `src/vs/workbench/contrib/tasks/common/tasks.ts`, `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts`
- **Validation:** Type-check an extension-created task using the agreed public property, then execute tasks with a problem matcher under always, onProblem, never, and omitted values. Verify always reveals the Problems panel at execution, onProblem reveals it when a match is found but not on a clean run, and never/omitted do not reveal it through this option; retain existing terminal reveal behavior. No execution was performed in this read-only review.
- **Behavior:**

  > Extensions can configure the existing problem-panel reveal modes through a supported TaskPresentationOptions property rather than undocumented assignments or per-task tasks.json overrides. The API delivers the same always, onProblem, and never behaviors as task configuration. Omitting the property preserves the current default. Acceptance covers both the public type declaration and execution of extension-created tasks with and without matched problems.
- **Trace:**

  > The public TaskPresentationOptions declaration in src/vscode-dts/vscode.d.ts and ITaskPresentationOptionsDTO in src/vs/workbench/api/common/shared/tasks.ts omit revealProblems. The extension-host conversion in extHostTask.ts passes presentation objects through; mainThreadTask.ts merges them with PresentationOptions.defaults. Internal tasks.ts already defines numeric RevealProblemKind values, and terminalTaskSystem.ts consumes those values to reveal the Problems view. The tasks.json schema instead exposes string values, so copying that shape into an undocumented API assignment does not establish supported behavior. Preserve tasks.json compatibility, existing defaults, and terminal presentation semantics; unrelated global-configuration and task-instance work is outside this request. The unresolved boundary is the public representation and API exposure contract, not the availability of the internal task behavior.
- **Open decisions:**
  - Should the public revealProblems property use a dedicated numeric enum consistent with existing task presentation APIs, or the string values used by tasks.json?
