# Issue #335168 — Agent Merge finish message is unclear

[https://github.com/microsoft/vscode/issues/335168](https://github.com/microsoft/vscode/issues/335168)

## Summary

Team-authored bug with no fix yet; traced the likely cause in the Agent Merge disable-notice path, where a PR being merged (success) and a PR being closed without merging both collapse into the same generic 'disabled' notice and icon, which reads as an error even when the outcome was a successful merge.

## Change summary

The message Agent Merge posts when it stops monitoring a pull request looks like an error even in the case where the PR was actually merged successfully.

## Best solution

In evaluateAgentMerge (src/vs/platform/agentHost/common/agentMerge.ts, ~line 637) the `core.value.state !== 'open'` check returns a single `{ kind: 'terminal' }` for both 'closed' and 'merged' states; agentMergeController.ts then always calls `agentMergeDisableReasons.pullRequestClosed()` with the generic AgentSystemNotificationKind.AgentMergeDisabled icon (circleSlash). Distinguish the merged case (e.g. surface it via the existing AgentMergePullRequestMerged icon/wording, or a new success-styled notice) from the closed-without-merge case so a successful outcome doesn't render like a failure.

## Evidence

- **terminal gate collapses merged/closed:** src/vs/platform/agentHost/common/agentMerge.ts:637 — `if (core.value.state !== 'open') { return { kind: 'terminal' }; }` treats 'closed' and 'merged' PR states identically.
- **controller always uses the generic disabled reason/icon:** src/vs/platform/agentHost/node/agentMergeController.ts:536 — `case 'terminal': this._disable(session, agentMerge, agentMergeDisableReasons.pullRequestClosed()); return;` uses the default `AgentSystemNotificationKind.AgentMergeDisabled` (circleSlash icon) regardless of whether the PR was merged or closed.
- **ambiguous wording:** src/vs/platform/agentHost/common/agentMerge.ts:295-296 — the notice text itself says "...disabled because its pull request is closed or merged", conflating the two outcomes.
- **separate success path exists but isn't reused here:** A distinct AgentSystemNotificationKind.AgentMergePullRequestMerged (gitMerge icon) already exists for when Agent Merge itself merges the PR (agentMergeController.ts:979-980), but it isn't used when the PR is merged by someone/something else and Agent Merge just observes the state change.
