# Issue #302990 — Source Control diff takes the file from disk and ignores .gitattributes filters (smudge / clean)

[https://github.com/microsoft/vscode/issues/302990](https://github.com/microsoft/vscode/issues/302990)

## Summary

The representation mismatch remains in current source and has an independent confirmation in the discussion. Keep this report open: the historical textconv implementation does not apply clean/smudge filters, and no verified canonical owns this same SCM preview symptom.

## Change summary

SCM unstaged diffs compare stored Git content against differently represented working-tree content without accounting for clean/smudge filters.

## Best solution

Make the built-in Git extension compare compatible representations so checkout formatting does not obscure actual edits. Settle whether unstaged previews display checkout-form or clean-form content, including the implications for editable diffs and selected-range staging.

Run the repository Git integration suite with ./scripts/test-integration.sh --suite git in an implementation workspace.
- **Behavior:**

  > A repository whose clean/smudge filters produce different stored and working-tree text should have useful SCM diffs that distinguish actual content edits from representation changes. The yamark example must not turn a small Markdown edit into a whole-file formatting diff. Staged comparisons must remain internally consistent, and selected-range staging must stage the intended content without corrupting surrounding text. The maintainer must first settle which representation the unstaged preview displays.
- **Trace:**

  > ResourceCommandResolver.getLeftResource/getRightResource in extensions/git/src/repository.ts pairs a '~' Git baseline with the working-tree file for Status.MODIFIED. GitFileSystemProvider in extensions/git/src/fileSystemProvider.ts resolves that baseline to the index or HEAD, then delegates through Repository.buffer to extensions/git/src/git.ts, where git show --textconv does not apply checkout filters. GitUriParams/GitUriOptions in extensions/git/src/uri.ts currently have no representation-selection option. The July 27 discussion at https://github.com/microsoft/vscode/issues/302990 supplies an independent Markdown reproduction and suggests checkout-form baselines; the original report instead describes matching git diff's clean-form comparison. Preserve unrelated textconv behavior, ordinary unfiltered diffs, staged comparisons, and selected-range staging semantics. https://github.com/microsoft/vscode/pull/327079 is a separate open quick-diff change, not a fix for this issue. The uncertainty is the user-visible representation contract, not whether the mismatch exists.
- **Open decisions:**
  - Should unstaged SCM previews compare checkout-form content while retaining the editable working-tree side, or display clean-form content like git diff, and what editing and selected-range staging behavior should that choice expose?
