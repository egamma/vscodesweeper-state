Run those targeted suites through scripts/test.sh, then retest the issue's 90-second command over a slow tunnel while another subscription remains responsive.
- **Behavior:**

  > A remote terminal producing output faster than its tunnel can deliver must not repeatedly disconnect the agent-host connection. Output should be throttled without introducing output loss, and unrelated chats and terminal subscriptions must remain usable. Once delivery capacity returns, terminal output must continue; removing a slow subscriber must not leave the PTY permanently paused. Verify sustained overload, recovery, and multiple subscribers.
- **Trace:**

  > AgentHostTerminalManager.createTerminal passes every PTY data event to _handlePtyData, which synchronously dispatches TerminalData through AgentHostStateManager. ProtocolServerHandler._broadcastAction forwards it to each subscribed client's AgentHostConnectionChannels; StateChannel.send queues it without propagating delivery pressure. AgentHostChannelDelivery.send bounds the backlog, and AgentHostChannelSubscription._failed closes the transport because state-channel policy has no resetMethod. The missing link is between connection-local queue pressure and the shared terminal producer, including subscription removal and reconnection; that lifecycle has not been fully designed in this review. Preserve action ordering, existing channel limits, non-terminal delivery behavior, and protocol compatibility. https://github.com/microsoft/vscode/pull/350550 already addresses immediate transport-close reporting and is not a terminal backpressure fix; https://github.com/microsoft/vscode/issues/350502 concerns a separate customization-transfer path.
