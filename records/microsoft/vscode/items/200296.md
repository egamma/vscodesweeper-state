# Issue #200296 — Unexpected behaviour in search and replace

[https://github.com/microsoft/vscode/issues/200296](https://github.com/microsoft/vscode/issues/200296)

## Summary

Still present on main: after notebook find-replace replaces a match, the cursor does not reliably advance to the next match — the `replaceOne` method performs the edit but does not explicitly navigate forward, relying on `_research()` decoration-restoration logic that can jump to the wrong position.

## Change summary

After replacing a match in notebook find/replace, the current match jumps to the first or second match instead of advancing to the next one.

## Best solution

After the `viewModel.replaceOne()` promise resolves in `notebookFindWidget.ts`, explicitly call `this._findModel.find({ previous: false })` to advance to the next match, similar to how the regular editor find-replace works. The fix belongs in `src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindWidget.ts` around line 238.
