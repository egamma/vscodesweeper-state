## Plan brief

- **Validation:** In a separate writable Windows investigation environment, repeatedly open small changed-file diffs from Source Control with third-party extensions disabled. Correlate click-to-display latency, Git Trace2 start/exit times, extension-host scheduling, process exit, and stdout/stderr closure; capture the intermittent five-second excess before the fix and verify it disappears afterward while diff contents and file metadata remain correct.
- **Behavior:**

  > Opening small changed files from Source Control intermittently takes approximately five seconds longer than normal on Windows, even with third-party extensions disabled. The recorded delay can affect either content retrieval or metadata retrieval, and Git's own trace can show a much shorter execution. Diff opening should not add this unexplained fixed-duration stall. Acceptance requires a correlated reproduction before the change and repeated equivalent openings afterward without the excess delay or incorrect diff contents.
- **Trace:**

  > GitFileSystemProvider.stat and readFile in extensions/git/src/fileSystemProvider.ts request metadata and content through Repository.getObjectDetails and buffer in extensions/git/src/repository.ts. In extensions/git/src/git.ts, getObjectDetails reaches lstree for HEAD metadata, while buffer streams show --textconv. The shared exec helper waits for process exit and closure of both output streams; _exec measures through that combined completion, while stream logs at process exit. This exposes useful diagnostic boundaries, not a proven stream-closure defect. Repository.updateWhenIdleAndWait contains a five-second post-status cooldown, but the inspected read paths do not directly await it, and the maintainer already rejected the initially suspected timeout. Preserve metadata accuracy, text conversion, and complete output collection; do not remove waits or serialize Git operations without causal evidence. The logs at https://github.com/microsoft/vscode/issues/184324#issuecomment-1855230646 and https://github.com/microsoft/vscode/issues/184324#issuecomment-1862852854 establish the historical symptom; uncertainty begins at reproducing it on current Windows builds and locating the delay.
