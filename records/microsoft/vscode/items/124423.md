# Issue #124423 — Allow defining save as file types for custom editors

[https://github.com/microsoft/vscode/issues/124423](https://github.com/microsoft/vscode/issues/124423)

## Summary

The API gap remains: custom editors cannot supply named file-type filters to the built-in Save As flow, which still populates the native dialog from registered languages. Keep this accepted Backlog request open; neither the existing dialog API nor the related closed extension-selection bug covers it.

## Change summary

Let custom editors replace language-derived Save As file types with their own named extension filters.

## Best solution

Provide an extension-facing contract for custom-editor Save As filters and honor it in the built-in save flow, preserving existing behavior for providers that do not opt in. Decide the public contract with the API owner before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/contrib/customEditor/common/extensionPoint.ts`, `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts`, `src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts`, `src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts`, `src/vs/workbench/services/dialogs/browser/fileDialogService.ts`
- **Validation:** Exercise built-in Save As with a custom editor declaring named PNG/JPEG formats: the native dialog should offer those formats rather than unrelated language filters, and the provider should receive the chosen destination. Cover providers without filter metadata retaining current behavior, cancellation, and the browser/simple-dialog paths; add focused tests for filter propagation and construction.
- **Behavior:**

  > A custom editor should be able to define named file types and extensions for its built-in Save As interaction without presenting unrelated language formats. An image editor should be able to offer formats such as PNG and JPEG through that interaction. Providers that do not declare formats should retain existing behavior, and cancellation should not invoke a save. This request concerns destination selection, not implementing image conversion inside VS Code.
- **Trace:**

  > CustomEditorInput.saveAs in src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts requests a destination through pickFileToSave before invoking the custom model's saveCustomEditorAs. AbstractFileDialogService.getPickFileToSaveDialogOptions derives filters from registered languages, and the desktop FileDialogService forwards them to the native dialog. The public CustomEditorProvider and registration options in src/vscode-dts/vscode.d.ts provide no filter metadata; customEditors selectors in src/vs/workbench/contrib/customEditor/common/extensionPoint.ts describe opening associations, not named output formats. SaveDialogOptions.filters supports separately opened extension dialogs but does not configure this built-in path. The motivating discussion is https://github.com/lunapaint/vscode-luna-paint/issues/69; the suffix fix discussed in https://github.com/microsoft/vscode/issues/147110 does not supply this capability. Preserve ordinary text-editor saving and existing provider defaults. Uncertainty begins at the public contract for declaring formats, rather than at whether the native path currently accepts them.
- **Open decisions:**
  - Should supported Save As formats be static metadata for a custom-editor type, or may a provider supply different formats for individual documents?

## Evidence

- **Current Save As path:** src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts:334-349 calls pickFileToSave(dialogPath, availableFileSystems) before saveCustomEditorAs. No provider-supplied filter metadata enters that call.
- **Native dialog still lists languages:** src/vs/workbench/services/dialogs/browser/abstractFileDialogService.ts:getPickFileToSaveDialogOptions builds filters from languageService.getSortedRegisteredLanguageNames(), alongside All Files, an extension match, and No Extension. src/vs/workbench/services/dialogs/electron-browser/fileDialogService.ts:pickFileToSave forwards those filters to the native save dialog.
- **Existing capability does not cover the request:** src/vscode-dts/vscode.d.ts exposes SaveDialogOptions.filters for window.showSaveDialog, but CustomEditorProvider.saveCustomDocumentAs receives an already-selected destination, and registerCustomEditorProvider has no save-filter option. The customEditors contribution schema in src/vs/workbench/contrib/customEditor/common/extensionPoint.ts likewise exposes no named save filters. A separately opened extension dialog is not configuration of the built-in Save As flow.
- **Motivating discussion and workaround:** https://github.com/lunapaint/vscode-luna-paint/issues/69 remains open.
