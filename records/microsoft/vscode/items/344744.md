# Issue #344744 — Webview view: "Found unexpected null" in hookupOnLoadHandlers when options and html are set back to back

[https://github.com/microsoft/vscode/issues/344744](https://github.com/microsoft/vscode/issues/344744)

## Summary

The reported stale-frame callback remains possible in current source: replacing a pending frame does not cancel its deferred initialization, which subsequently asserts on its null contentWindow. Keep this open for a bounded webview lifecycle fix; the reporter already provides sufficient reproduction details.

## Change summary

Prevent uncaught webview host errors when successive options and HTML updates replace a frame before its deferred initialization runs.

## Best solution

Superseded webview frames should stop participating in deferred initialization without throwing or disturbing the replacement frame's loading lifecycle, while the latest content continues to render and receive messages.
