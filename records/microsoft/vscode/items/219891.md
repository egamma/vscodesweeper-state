# Issue #219891 — I should be able to select multiple lines of python code and hit control F and it automatically imports it into the search box...

[https://github.com/microsoft/vscode/issues/219891](https://github.com/microsoft/vscode/issues/219891)

## Summary

The requested workflow remains only partially supported: a separate command seeds multiline searches, but Ctrl+F excludes multiline selections and Ctrl+H does not seed replacement text. Keep this open for an editor-find product decision; the matching open report is newer, and the older decline does not cover the replacement-field request.

## Change summary

Allow Ctrl+F to populate Find from a multiline selection and Ctrl+H to populate Replace from a subsequently selected passage.

## Best solution

Decide whether editor-find should support opt-in multiline seeding through the normal Find shortcut and a selection-to-replacement workflow, preserving existing search terms and replacement text unless explicitly requested. Consider the newer matching report together with this issue without treating it as this older report's canonical.

## Evidence

- **Existing setting does not cover multiline Ctrl+F:** src/vs/editor/common/config/editorOptions.ts registers editor.find.seedSearchStringFromSelection with never, always, and selection values. In src/vs/editor/contrib/find/browser/findController.ts, StartFindAction passes 'single' for either enabled value, and getSelectionSearchString excludes selections spanning multiple lines in that mode.
- **Partial built-in alternative:** StartFindWithSelectionAction in src/vs/editor/contrib/find/browser/findController.ts registers actions.findWithSelection ('Find with Selection') and passes seedSearchStringFromSelection: 'multiple'. It can seed multiline search text, but does not focus the Find input and does not provide the requested replacement-field seeding.
- **Replacement request remains distinct:** StartFindReplaceAction in src/vs/editor/contrib/find/browser/findController.ts explicitly permits only nonempty single-line selections to seed searchString. It chooses Find or Replace focus but does not populate replaceString from the editor selection. editor.find.autoFindInSelection controls search scope, not either requested input-seeding behavior.
- **Newer matching open report:** https://github.com/microsoft/vscode/issues/307720 is open and reports multiline selections not entering Find through Ctrl+F/Ctrl+H; https://github.com/microsoft/vscode/issues/307720#issuecomment-4186662791 confirms that symptom.
