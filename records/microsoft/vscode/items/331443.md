# Issue #331443 — Button missing a tooltip in the search panel

[https://github.com/microsoft/vscode/issues/331443](https://github.com/microsoft/vscode/issues/331443)

## Summary

Traced this to a real, if narrow, UX bug: the highlighted button is the 'Search only in Changed Files (Source Control)' toggle in the includes input (patternInputWidget.ts), which starts disabled until an SCM repo has pending changes — but disabled toggles use `pointer-events: none` in toggle.css, which blocks the hover delegate from ever firing, so the tooltip (and its explanation of how to enable it) never appears while disabled.

## Change summary

A toolbar button next to 'files to include' in the Search view shows no tooltip and gives no indication of what it does or how to enable it.

## Best solution

Fix belongs in the shared Toggle widget (src/vs/base/browser/ui/toggle/toggle.ts / toggle.css): since click/keydown handlers already gate on `this.enabled`, `pointer-events: none` on `.monaco-custom-toggle.disabled` isn't needed to block interaction and can be relaxed (or a native `title` fallback added) so disabled toggles still surface their tooltip on hover — this affects the 'Search only in Changed Files' and 'Search only in Open Editors' toggles in the search view specifically, but the root cause is in the shared widget.
