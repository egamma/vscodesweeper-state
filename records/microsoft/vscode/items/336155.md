# Issue #336155 — Agent skill frontmatter is not recognized when SKILL.md has a UTF-8 BOM

[https://github.com/microsoft/vscode/issues/336155](https://github.com/microsoft/vscode/issues/336155)

## Summary

Confirmed on current main: PromptsService.parseNew() reads raw file bytes via fileService.readFile when no text model is open, and PromptFileParser's frontmatter regex doesn't account for a leading U+FEFF BOM, so BOM-prefixed SKILL.md files silently lose their frontmatter and are omitted from the advertised skill list. An open PR (#336158) already targets this exact fix, so this stays open pending that PR rather than being assigned for independent implementation.

## Change summary

SKILL.md files saved with a UTF-8 BOM have their YAML frontmatter silently ignored, so the skill isn't advertised to the agent unless a text model happens to already be open for the file.

## Best solution

Land the fix in strip-BOM-before-parsing form already proposed in https://github.com/microsoft/vscode/pull/336158 (or an equivalent tweak to PromptFileParser's opening-delimiter regex / promptsServiceImpl's raw-read path); once merged this issue can close as implemented.
