# Issue #331003 — Copilot agent request can hang when WebSocket emits `error` without `close`

[https://github.com/microsoft/vscode/issues/331003](https://github.com/microsoft/vscode/issues/331003)

## Summary

Well-diagnosed hang: the active-socket `error` listener only stashes `_pendingErrorMessage`, and settlement only happens in the `close` listener, so a socket that errors without closing leaves the request permanently pending — this is confirmed in the current source and already has an open fixing PR, so it should stay open until that PR lands rather than being closed now.

## Change summary

A Copilot agent request can hang indefinitely when the WebSocket transport emits `error` without a following `close`, because request settlement only occurs in the `close` handler.

## Best solution

Land https://github.com/microsoft/vscode/pull/331004, which settles the active request directly from the `error` handler (mark closed, clear active request, call `handleConnectionClose`, close the socket) instead of relying on a subsequent `close` event.
