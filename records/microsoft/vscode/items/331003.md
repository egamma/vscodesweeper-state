# Issue #331003 — Copilot agent request can hang when WebSocket emits `error` without `close`

[https://github.com/microsoft/vscode/issues/331003](https://github.com/microsoft/vscode/issues/331003)

## Summary

Traced on current main: the WebSocket `error` listener in ChatWebSocketConnection only records `_pendingErrorMessage` and never settles the request; only the `close` listener calls `handleConnectionClose`. When Electron emits `error` without `close`, the request hangs exactly as described. A fixing PR is already open, so the issue stays open pending its review/merge.

## Change summary

An active Copilot agent WebSocket request can hang indefinitely if the socket emits `error` without a following `close` event, because settlement only happens in the `close` handler.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/331004, which settles the request directly from the `error` handler (via `handleConnectionClose(1006, '', errorMessage)`) instead of relying solely on a subsequent `close` event.

## Evidence

- **source trace:** extensions/copilot/src/platform/networking/node/chatWebSocketManager.ts lines 548-569: the `ws.addEventListener('error', ...)` handler computes `errorMessage` and only does `this._pendingErrorMessage ??= errorMessage;` — it never calls `handleConnectionClose` or clears `_activeRequest`. Settlement only happens in the `close` listener (lines ~530-546), confirming the reported hang path.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/331004 implements the exact fix described in the issue (settle via handleConnectionClose(1006, ...) from the error handler) but is not yet merged (git log shows no such change on main as of commit 7fee8151).
