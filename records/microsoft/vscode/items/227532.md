# Issue #227532 — [Accessibility] Remove unnecessary role="tree", role="treeitem" and related aria-aatributes of tree structure in Settings.

[https://github.com/microsoft/vscode/issues/227532](https://github.com/microsoft/vscode/issues/227532)

## Summary

The Settings editor uses a non-collapsible WorkbenchObjectTree that emits role="tree" and role="treeitem" by default; whether these roles are semantically correct for a flat settings list is a legitimate accessibility concern that needs team input.

## Change summary

The Settings editor renders settings in a tree widget that applies role="tree"/"treeitem" ARIA attributes, but the list is non-collapsible and behaves as a flat list, which may confuse assistive technologies.

## Best solution

The accessibility team should decide whether the Settings editor should override getWidgetRole/getRole in its accessibility provider to use role="list"/"listitem" (or similar) instead of the default tree roles, given the NonCollapsibleObjectTreeModel makes the structure behave as a flat list. The fix would be small — add getRole/getWidgetRole overrides to SettingsTreeAccessibilityProvider in src/vs/workbench/contrib/preferences/browser/settingsTree.ts.
