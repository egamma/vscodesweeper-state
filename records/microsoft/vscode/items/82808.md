# Issue #82808 — Minimap: Render overview ruler decorations (for extension support)

[https://github.com/microsoft/vscode/issues/82808](https://github.com/microsoft/vscode/issues/82808)

## Summary

Keep open: current source supports internal minimap decorations but still does not expose them through extension decorations or mirror extension overview-ruler markers. This accepted Backlog request has 54 upvotes, and the canonical search found no older open issue covering the same observable gap.

## Change summary

Allow extension-provided overview-ruler decorations to appear in the editor minimap.

## Best solution

Provide a supported way for extension markers, including bookmarks and colored regions, to appear in the minimap using the existing decoration renderer. Settle whether overview-ruler decorations are mirrored automatically or extensions explicitly opt into minimap rendering, while preserving existing overview-ruler behavior.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/editor/browser/services/abstractCodeEditorService.ts`, `src/vs/editor/common/model.ts`, `src/vs/editor/browser/viewParts/minimap/minimap.ts`
- **Validation:** After choosing the contract, exercise an extension that decorates a known range with overviewRulerColor and overviewRulerLane, plus any agreed minimap opt-in. Verify the marker appears at that range in proportional and fit minimaps, respects light/dark colors, disappears when the decoration is removed, and leaves overview-ruler rendering unchanged; add automated conversion/model assertions for the chosen contract.
- **Behavior:**

  > Extensions need a supported way to show their colored range markers in the minimap, including bookmark and colored-region use cases. Internal search and diagnostic markers do not satisfy this requirement. Acceptance should demonstrate extension markers at the correct ranges, correct theme colors, and removal when decorations are cleared, without regressing existing overview-ruler or built-in minimap decorations. Whether existing extensions gain this automatically or must explicitly opt in remains a product/API decision.
- **Trace:**

  > The public DecorationRenderOptions in src/vscode-dts/vscode.d.ts contains overview-ruler fields but no minimap fields. DecorationRenderOptions.from in src/vs/workbench/api/common/extHostTypeConverters.ts forwards those fields, and DecorationTypeOptionsProvider in src/vs/editor/browser/services/abstractCodeEditorService.ts creates overviewRuler metadata without minimap metadata. The editor already has IModelDecorationMinimapOptions in src/vs/editor/common/model.ts and a minimap-specific retrieval/rendering path in src/vs/editor/browser/viewParts/minimap/minimap.ts. Read-only inspection establishes the missing bridge, not a renderer defect. Preserve existing overview-ruler semantics and built-in minimap markers; replacing the scrollbar is a future possibility, not required scope here. https://github.com/microsoft/vscode/issues/75216 describes internal rendering, while https://github.com/microsoft/vscode/issues/83206#issuecomment-546024031 establishes this issue as the extension-support canonical.
- **Open decisions:**
  - Should existing extension overview-ruler decorations appear in the minimap automatically, or should rendering require an explicit opt-in by the extension or user?
  - If an explicit extension API is chosen, should it expose independent minimap colors and Inline/Gutter placement, or only reuse the existing overview-ruler marker styling?
