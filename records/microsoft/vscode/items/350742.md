# Issue #350742 — P2 Typing with many cursors: status bar does O(cursors²) range checks per keystroke (4k cursors: ~300 ms task), plus a full render per token batch

[https://github.com/microsoft/vscode/issues/350742](https://github.com/microsoft/vscode/issues/350742)

## Summary

Current source confirms the quadratic status-bar scan and unnecessary preparation of off-screen cursors. Keep this open for a bounded performance fix; token changes also invalidate the cursor layer without checking visibility, although the reported full-render timings were not independently verified.

## Change summary

Reduce status-bar range checking and off-screen cursor rendering work when typing with thousands of cursors.

## Best solution

Make status-bar updates scale non-quadratically with selection and change counts, and limit cursor rendering work to relevant visible content while preserving selection counts, cursor appearance, and scrolling behavior.
