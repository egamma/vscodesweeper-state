# Issue #219542 — Inline chat with sticky scroll looses top area

[https://github.com/microsoft/vscode/issues/219542](https://github.com/microsoft/vscode/issues/219542)

## Summary

Still open with no confirmed fix: the continuous-resize/reveal problem jrieken described (sticky scroll pushing the inline chat widget's top out of view as it grows) has no landed commit addressing it, and the prior review's implemented-on-main claim (commit c76e907f) was already refuted. The last comment is the reporter's own tentative guess, not a verification.

## Change summary

When inline chat is open with editor sticky scroll enabled, the widget's top content scrolls out of view as the response grows, because reveal/resize logic doesn't continuously account for the sticky scroll area height.

## Best solution

Confirm whether the newer 'inline2' chat implementation (referenced as deprecating InlineChatZoneWidget) actually fixes the continuous reveal/resize interaction with sticky scroll, then close with that specific commit cited — or keep tracking under the inline-chat rewrite work if the problem persists there.

- **Trace:**

  > Root cause is in InlineChatZoneWidget#reveal (src/vs/workbench/contrib/inlineChat/browser/inlineChatZoneWidget.ts:438-442): it computes a one-time reveal offset based on sticky scroll's maxLineCount only at initial positioning, not as the widget's height grows during streaming. jrieken noted two open problems: (1) initial reveal — mitigated by the min-bar fix in PR #234974 — and (2) continuous reveal/resize as content grows, which remains unaddressed and is the crux of this report. Do not assume the in-progress 'inline2' rewrite (see the @deprecated marker at line 120) already resolves this without verification.
