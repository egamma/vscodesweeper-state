# Issue #57687 — Allow to compare 3 files

[https://github.com/microsoft/vscode/issues/57687](https://github.com/microsoft/vscode/issues/57687)

## Summary

Keep open: comparing three or more arbitrary files remains distinct from the existing merge editor and multifile diff editor. This request has substantial community support, and a maintainer explicitly withdrew the earlier claim that it was implemented.

## Change summary

Allow three or more files to be compared together in an aligned diff view, accessible from file selection and potentially the CLI.

## Best solution

Provide a dedicated multi-input comparison experience with coordinated line alignment, without requiring a merge base or output file. Resolve the initial file-count scope and editing semantics with the diff-editor owner before implementation.

- **Behavior:**

  > Users want to compare at least three arbitrary files together, with corresponding unchanged lines aligned and differences visible across the selected versions. This must not require inventing a merge base or output file, and a collection of separate two-file diffs does not satisfy the central request. The issue also requests four/n-file support and includes an editable-middle workflow for splitting commits. Acceptance must cover independent insertions and deletions across three inputs, the agreed file-selection entry point, and preservation of existing two-file comparison.
- **Trace:**

  > In src/vs/workbench/contrib/files/browser/fileCommands.ts, COMPARE_SELECTED_COMMAND_ID accepts exactly two selected resources and constructs an original/modified editor input; its menus in fileActions.contribution.ts use double-selection conditions. The CLI registration in src/vs/platform/environment/node/argv.ts likewise advertises two-file --diff, while --merge has a distinct base/two-input/result contract. MultiDiffEditorInput in src/vs/workbench/contrib/multiDiffEditor/browser/multiDiffEditorInput.ts builds a collection of original/modified pairs, not a single multi-input comparison. The merge editor has potentially relevant alignment machinery in view/lineAlignment.ts:getAlignments and view/viewZones.ts, but it is coupled to ModifiedBaseRange, conflict actions, and result differences. The maintainer acknowledged this distinction at https://github.com/microsoft/vscode/issues/57687#issuecomment-1859857173 and described the remaining alignment problem at https://github.com/microsoft/vscode/issues/57687#issuecomment-1961709439. The trace establishes the missing entry-point contract and neighboring machinery, not a complete multi-input editor architecture; preserve existing merge semantics and ordinary pairwise comparisons.
- **Open decisions:**
  - Should the initial supported comparison contain exactly three files, or also cover the requested four/arbitrary-number file case?
  - Should differences be presented relative to one designated reference file, between adjacent versions, or through a user-selectable relationship?
  - Should the initial view be comparison-only, or support editing a middle file for commit-splitting workflows; if editable, which files may be changed?
