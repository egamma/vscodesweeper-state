# Issue #202373 — Cursor position is incorrect in selection when cursorStyle is "Block"

[https://github.com/microsoft/vscode/issues/202373](https://github.com/microsoft/vscode/issues/202373)

## Summary

This is a feature request for block cursor to align with modal-editing semantics (cursor-on-character rather than cursor-between-characters). VS Code's cursor model is intentionally between-character; block cursor is purely cosmetic. The prior requests (#97148, #2997) were closed for insufficient upvotes. The broader modal-editing support is tracked in the Backlog at #114851, but that issue is very different in scope. This issue has a clear, specific ask that stands on its own.

## Change summary

When cursorStyle is Block, the cursor should visually sit on the last character of a selection (matching `selection.active`), not one character past it.

## Best solution

This is a specific, well-articulated aspect of modal-editing support. The editor's cursor rendering in `src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts` would need to adjust block cursor placement relative to selections, or a new editor option (like a `selectionBehavior: character` mode) would need to be introduced so extensions can opt into cursor-on-character semantics. Worth keeping open for the editor team to evaluate as part of broader modal-editing support.
