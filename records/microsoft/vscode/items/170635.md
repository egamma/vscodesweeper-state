# Issue #170635 — Cache and restore window size/position when opening

[https://github.com/microsoft/vscode/issues/170635](https://github.com/microsoft/vscode/issues/170635)

## Summary

A real gap remains: VS Code restores windows from the previous session but does not retain each workspace's last bounds after that window leaves the active session. This is already the canonical, correctly routed Backlog request and should remain open.

## Change summary

Optionally remember and restore window size and position independently for each workspace or folder.

## Best solution

Extend the window-state persistence in `WindowsStateHandler` with a bounded workspace/folder-keyed cache, updating it whenever a window closes and consulting it when that workspace reopens. Keep this separate from the existing previous-session window list.

## Evidence

- **current source gap:** `src/vs/platform/windows/electron-main/windowsStateHandler.ts` lines 307–322 can restore workspace-specific bounds only when that workspace remains in `state.openedWindows`; lines 194–215 rebuild that list from currently open windows, while lines 238–247 only update an already-present entry and never cache a newly closed workspace.
- **existing settings are partial:** `window.newWindowDimensions` supports default, inherit, offset, maximized, and fullscreen behavior, while `window.restoreWindows` restores previous-session windows. Neither setting maintains persistent bounds per workspace.
- **canonical confirmation:** https://github.com/microsoft/vscode/issues/198834 contains a confirmed Windows/WSL reproduction and maintainer analysis identifying the missing per-workspace session state; it was closed explicitly as a duplicate of https://github.com/microsoft/vscode/issues/170635.
