# Issue #170635 — Cache and restore window size/position when opening

[https://github.com/microsoft/vscode/issues/170635](https://github.com/microsoft/vscode/issues/170635)

## Summary

Keep open: current window-state restoration does not retain independent geometry for every previously opened project. This is the accepted canonical request; existing settings cover session restoration or inherited dimensions, not the requested per-project cache.

## Change summary

Remember each project's window size and position when reopening it while other project windows remain open.

## Best solution

Provide durable per-folder and per-workspace window geometry restoration in the desktop window-state subsystem, independently of which windows were open at application exit. Preserve existing session-restoration and display-safety behavior.

## Plan brief

- **Likely files:** `src/vs/platform/windows/electron-main/windowsStateHandler.ts`, `src/vs/platform/windows/test/electron-main/windowsStateHandler.test.ts`, `src/vs/workbench/electron-browser/desktop.contribution.ts`
- **Validation:** Keep project A open, open project B in another window, change B's bounds, close B, and reopen B; verify its previous bounds return without changing A. Repeat after an application restart with B absent from the exit-time window set, for both single-folder and multi-root workspaces. Add lifecycle and persistence coverage in the Windows State Storing test area, and verify existing restoration modes and off-screen bounds handling remain intact.
- **Behavior:**

  > Reopening a project in a secondary window should restore that project's previously used size and position instead of defaulting to generic new-window bounds. The remembered geometry should remain available even when that project was closed before application exit. Acceptance includes independently sized projects, single-folder and multi-root workspaces, and safe restoration when the display configuration changes. Existing session reopening behavior must remain unchanged.
- **Trace:**

  > WindowsStateHandler in src/vs/platform/windows/electron-main/windowsStateHandler.ts restores project geometry only when the workspace or folder appears in the startup snapshot's openedWindows. onBeforeCloseWindow updates existing snapshot entries without adding a newly opened project's entry, and saveWindowsState persists a fresh open-window snapshot rather than a historical project cache. window.restoreWindows and window.newWindowDimensions in src/vs/workbench/electron-browser/desktop.contribution.ts address session reopening and generic window sizing, not independent project history. The maintainer diagnosis at https://github.com/microsoft/vscode/issues/198834#issuecomment-1824078194 confirms this distinction, and that report was consolidated into this issue. Existing serialization tests are in src/vs/platform/windows/test/electron-main/windowsStateHandler.test.ts. Preserve extension-development window handling, fullscreen rules, existing restoration modes, and display-safety behavior; the remaining uncertainty is the user-facing activation and retention contract.
- **Open decisions:**
  - Should per-project geometry restoration require an opt-in setting, as requested, or become the default for previously opened projects?
  - How long should a closed project's geometry remain remembered, and what user-visible action, if any, should clear it?
