# Issue #343412 — Feature Request: Add a Git History Graph View to the VS Code Agents Window

[https://github.com/microsoft/vscode/issues/343412](https://github.com/microsoft/vscode/issues/343412)

## Summary

The requested Git history graph remains absent from the Agents Window; the regular editor's graph does not cover this workflow. Keep this focused request open for design rather than folding it into broader Git/worktree feedback.

## Change summary

Expose an integrated Git history graph with commit inspection, diffs, reference filtering, and branch switching in the Agents Window.

## Best solution

Provide a Sessions-owned history surface that reuses existing SCM graph capabilities and follows the relevant session repository or worktree. Settle its placement and branch-switching semantics before implementation.

- **Reason:** Reusing an existing Git review capability reduces context switching during agent-assisted development without introducing a separate graph implementation.

## Plan brief

- **Likely files:** `src/vs/sessions/sessions.common.main.ts`, `src/vs/sessions/contrib/changes/browser/changes.contribution.ts`, `src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts`, `src/vs/workbench/contrib/scm/browser/scm.contribution.ts`
- **Validation:** In the Agents Window, open a repository containing branches, a merge, and a tag; inspect the graph, filter references, and open a historical file diff without opening another window. Switch between sessions using different repositories/worktrees and verify the agreed repository-selection behavior; verify branch switching against the agreed safety contract.
- **Behavior:**

  > Users can inspect Git commit history and branch relationships without leaving the Agents Window. The surface exposes commits, merges, tags, commit details, historical file diffs, and reference filtering. Its repository selection remains understandable when users move between sessions and worktrees. Branch switching must have explicit behavior when an agent is running or the worktree contains local changes.
- **Trace:**

  > The regular workbench registers SCMHistoryViewPane in src/vs/workbench/contrib/scm/browser/scm.contribution.ts. The Sessions entry point src/vs/sessions/sessions.common.main.ts loads SCM services and quick diff but not that view registration, and Sessions sources contain no graph integration. Its existing Changes contribution and SessionChangesService expose session changesets rather than repository history. Reuse investigation should start at SCMHistoryViewPane while preserving the normal editor's graph and the provider-neutral Sessions layer. src/vs/sessions/LAYOUT.md defines the relevant side-pane and focused-session ownership boundaries. https://github.com/microsoft/vscode/issues/336620 is related orientation work, not a duplicate canonical. The unresolved contracts are where history lives, which repository it follows, and whether branch mutations are safe in an active session.
- **Open decisions:**
  - Should history appear as a session Details view or as a separate repository-oriented surface?
  - Should the graph always follow the focused session's worktree, or permit an independently selected repository?
  - When an agent is running or local changes exist, should branch switching be unavailable, require confirmation, or create/select another session?

## Evidence

- **Existing-capability check:** src/vs/workbench/contrib/scm/browser/scm.contribution.ts registers HISTORY_VIEW_PANE_ID using SCMHistoryViewPane, with reference filtering implemented in scmHistoryViewPane.ts. However, src/vs/sessions/sessions.common.main.ts imports only SCM service and quick-diff contributions, not scm.contribution.ts; searching Sessions sources found no SCMHistoryViewPane or HISTORY_VIEW_PANE_ID integration.
- **Current Agents surface:** src/vs/sessions/contrib/changes/browser/changes.contribution.ts registers the Sessions-specific Changes view in the auxiliary bar. sessionChangesService.ts opens session changesets through diff editors; this does not provide repository commit topology, branches, merges, and tags.
- **Canonical search:** GitHub searches for Agents/Sessions graph, history, and Source Control requests found no verified canonical owning this exact capability. https://github.com/microsoft/vscode/issues/336620 concerns Git/worktree orientation, action semantics, and lifecycle, explicitly preserving narrower reports; https://github.com/microsoft/vscode/issues/335015 concerns CLI/chat parity rather than a Git history graph.
- **Demand and implementation ownership:** https://github.com/microsoft/vscode/issues/343412 has seven community upvotes and concrete workflow requirements. An open-PR search for its issue number returned no implementation candidate.
- **Layout boundary:** src/vs/sessions/LAYOUT.md assigns session details to the auxiliary bar and distinguishes session/chat-owned content from window-owned layout. A history surface needs an explicit repository-selection contract within that model.
