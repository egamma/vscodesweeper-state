# Issue #153039 — Inconsistent use of beaks in tooltip and hovers

[https://github.com/microsoft/vscode/issues/153039](https://github.com/microsoft/vscode/issues/153039)

## Summary

This is a valid design-consistency tracking issue filed by the VS Code design lead (miguelsolorio). The codebase now has a structured `HoverStyle.Pointer` system, but the inconsistency between surfaces that use beaks and those that don't remains a deliberate design decision to address over time — still open work.

## Change summary

Tooltip/hover beaks (pointers) appear inconsistently across VS Code surfaces — some (activity bar, status bar, command center) show them while others (editor hovers, tree views) do not.

## Best solution

A design pass to decide which hover surfaces should use `HoverStyle.Pointer` vs plain positioning, then migrate the remaining surfaces. The `showPointer` infrastructure in `src/vs/platform/hover/browser/hoverWidget.ts` already supports both modes — the remaining work is deciding and applying a consistent policy across all hover/tooltip call sites.
