# Issue #210719 — Config when-clauses: Support keys into settings objects

[https://github.com/microsoft/vscode/issues/210719](https://github.com/microsoft/vscode/issues/210719)

## Summary

The requested direct access to dotted properties inside settings objects remains unsupported; the author's setContext workaround resolves their immediate need, not the general capability. Keep this team-authored request open: no qualifying implementation or verified open duplicate was found.

## Change summary

Allow config when-clauses to read values such as "myfeature.enabled" inside an object-valued setting without requiring a separate flat setting or manually synchronized context key.

## Best solution

Retain setContext synchronization as the available workaround. Any general enhancement should define how literal dotted object properties are addressed and preserve configuration-change invalidation without eagerly expanding every settings object.

## Evidence

- **Current capability and remaining gap:** src/vs/platform/contextkey/browser/contextKeyService.ts, ConfigAwareContextValuesContainer.getValue, removes the config. prefix and delegates to IConfigurationService.getValue. ConfigurationModel delegates to getConfigurationValue in src/vs/platform/configuration/common/configuration.ts, which splits the entire path on dots. For the supplied object, this looks for advanced.myfeature.enabled as nested properties rather than advanced["myfeature.enabled"], so the central ask remains unmet.
- **Membership is not value access:** src/vs/platform/contextkey/common/contextkey.ts, ContextKeyInExpr.evaluate, checks object membership with hasOwnProperty.call(source, item); it does not evaluate the property's boolean value.
