# Issue #221826 — When replacing text in a large enough file, the old selection is incorrectly preserved

[https://github.com/microsoft/vscode/issues/221826](https://github.com/microsoft/vscode/issues/221826)

## Summary

The defect remains on current main: the optimized large replace-all path preserves the original selection across a full-document replacement instead of remapping it like the regular path. It is already correctly routed to editor find.

## Change summary

Replace All in a file with at least 19,999 matches can leave the former search selection covering unrelated text.

## Best solution

Make `FindModelBoundToEditorModel._largeReplaceAll` preserve cursor and selection semantics equivalent to `_regularReplaceAll`, including collapsing or remapping a selection whose text was replaced. Add a regression test exceeding `MATCHES_LIMIT` that deletes the selected match and checks the resulting selection.

## Evidence

- **current source:** `src/vs/editor/contrib/find/browser/findModel.ts` sets `MATCHES_LIMIT` to 19999 and sends larger replacements through `_largeReplaceAll`.
- **defective path:** `_largeReplaceAll` replaces the full model with one `ReplaceCommandThatPreservesSelection`, which tracks the original selection through that whole-document edit; the regular path instead applies individual match edits through `ReplaceAllCommand`.
- **missing regression coverage:** `src/vs/editor/contrib/find/test/browser/findModel.test.ts` covers replacement above the match limit but asserts only resulting text, not cursor or selection state.
