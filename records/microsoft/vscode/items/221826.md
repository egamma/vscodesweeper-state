# Issue #221826 — When replacing text in a large enough file, the old selection is incorrectly preserved

[https://github.com/microsoft/vscode/issues/221826](https://github.com/microsoft/vscode/issues/221826)

## Summary

The defect remains in current source: bulk replacement coalesces individual edits, allowing the tracked selection to retain obsolete offsets instead of following the removed text. The supplied recording contains enough matches to trigger this path, and no verified older canonical owns the same symptom.

## Change summary

Replace All in a file with many matches leaves the original selection highlighting unrelated text after the selected match is removed.

## Best solution

Make Find/Replace selection tracking consistent across ordinary and bulk replacements: removing the selected match should collapse the selection at its corresponding edited location. Preserve the bulk-edit memory safeguards and existing undo, search-scope, and unaffected-selection behavior.
