# Issue #236229 — Scroll glitch in resolve conflicts view

[https://github.com/microsoft/vscode/issues/236229](https://github.com/microsoft/vscode/issues/236229)

## Summary

Keep this as the canonical report for merge-editor conflict actions rendering incorrectly after opening conflicts from the PR view. Maintainers have confirmed the trigger and consolidated later reports here; no verified fixing commit was found.

## Change summary

Conflict-action controls become duplicated, misplaced, or stuck while scrolling merge editors opened through the PR view's Resolve Conflicts action.

## Best solution

Make conflict-action overlays remain correctly attached to the active merge input when resolving several files through the PR view. Diagnose the asynchronous input-switching and overlay lifecycle first, preserving the correctly working manual single-file opening flow.
