# Issue #337358 — Enhance error handling and robustness in ApiProviderNaming ESLint rule during package.json loading

[https://github.com/microsoft/vscode/issues/337358](https://github.com/microsoft/vscode/issues/337358)

## Summary

Legitimate robustness suggestion for the local ESLint plugin's `getModules()` helper, and there's already an open PR implementing the exact fix described — the issue should stay open until that PR lands or is otherwise resolved.

## Change summary

The `getModules()` helper in the local `code-amd-node-module` ESLint rule rethrows on a package.json read/parse failure, which can crash the whole ESLint run instead of degrading gracefully.

## Best solution

Land https://github.com/microsoft/vscode/pull/337359 (or an equivalent change) so the catch block logs the error and falls back to an empty Set instead of rethrowing.
