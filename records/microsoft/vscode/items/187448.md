## Summary

The cancellation race remains possible on main: `$cancelCells` requires a notebook document that may already have been removed. This team-authored Backlog issue has no explicitly referencing fix commit, so it should remain open.

## Change summary

Notebook cancellation can throw `NO notebook document` after the corresponding document has been removed from the extension host.

## Best solution

Make late cancellation tolerant of an already-closed notebook in `extHostNotebookKernels.ts`, with a regression test covering document removal before `$cancelCells` arrives.
