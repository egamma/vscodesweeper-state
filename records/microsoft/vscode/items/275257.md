# Issue #275257 — text overflows button container

[https://github.com/microsoft/vscode/issues/275257](https://github.com/microsoft/vscode/issues/275257)

## Summary

The overflow remains source-reproducible on current main: handoff labels are forced onto one line inside intrinsically sized, non-shrinking buttons. This team-authored Backlog item should remain open until narrow chat layouts keep long labels within their containers.

## Change summary

Long custom-agent handoff labels extend beyond their button containers when the Chat view is narrow.

## Best solution

Keep each handoff action within the available Chat view width while preserving readable wrapping and the separate continue-in dropdown target.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/media/chat.css`, `src/vs/workbench/contrib/chat/browser/widget/media/chatViewWelcome.css`
- **Validation:** In a development build, configure several handoffs with long labels, complete a response, narrow the Chat view to its minimum width, and verify every label remains readable inside its button while keyboard focus and the continue-in dropdown remain usable.
- **Behavior:**

  > After a custom-agent response completes, every handoff action must remain inside the available Chat view width. Long labels must remain readable rather than extending beyond the button, including at the minimum supported Chat width. Short labels, keyboard focus order, activation, and the continue-in dropdown must retain their current behavior.
- **Trace:**

  > ChatSuggestNextWidget in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSuggestNextWidget.ts renders handoff labels using the shared welcome-view prompt classes. In src/vs/workbench/contrib/chat/browser/widget/media/chatViewWelcome.css, the button is intrinsically sized and non-shrinking, its fixed height is 20px, and the title uses `white-space: nowrap`; that combination conclusively produces the reported overflow when the label exceeds the available width. The handoff-specific container in src/vs/workbench/contrib/chat/browser/widget/media/chat.css wraps buttons but does not constrain an individual button. Keep the scope to handoff/suggest-next layout behavior unless validation proves the shared welcome prompts need the same treatment; do not change handoff execution or dropdown semantics. The original expectation is recorded in https://github.com/microsoft/vscode/issues/274957.

## Evidence

- **source reproduction:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSuggestNextWidget.ts creates each handoff as `.chat-welcome-view-suggested-prompt` with its label in `.chat-welcome-view-suggested-prompt-title`.
- **overflowing layout:** src/vs/workbench/contrib/chat/browser/widget/media/chatViewWelcome.css lines 248-266 give the button `width: fit-content`, `flex: 0 0 auto`, and a fixed 20px height while forcing the title to `white-space: nowrap`; this prevents a long label from shrinking or wrapping within a narrow container.
- **expected behavior:** The linked test plan https://github.com/microsoft/vscode/issues/274957 explicitly requires long handoff labels to wrap readably without overflow, matching the reporter's narrow-chat reproduction.
- **canonical search:** https://github.com/microsoft/vscode/issues/291169 is younger and concerns tool-result content overlapping an approval widget, not handoff-label text overflowing its button, so it does not satisfy the stronger duplicate bar for this re-reviewed item.
