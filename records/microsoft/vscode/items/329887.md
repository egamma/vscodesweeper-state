# Issue #329887 — Decoration on inline terminal could provide functionality

[https://github.com/microsoft/vscode/issues/329887](https://github.com/microsoft/vscode/issues/329887)

## Summary

Keep open: inline terminal decorations currently provide status and hover text, but not the command-action menus available through terminal shell integration. This team-authored request remains a distinct UX gap; the appropriate actions need a product decision.

## Change summary

Make inline terminal command decorations expose useful actions comparable to shell-integration decorations.

## Best solution

Provide an accessible command-action entry point on inline terminal decorations, with actions appropriate to the command and available terminal/output data. Decide which shell-integration actions should also apply to restored or output-only Agent Host invocations before implementing parity.

Manually verify that invoking the decoration does not accidentally toggle the surrounding command card.
- **Behavior:**

  > Inline terminal command decorations should offer useful command actions rather than serving only as status indicators. The agreed actions must operate on the invocation represented by the decoration, not another command in the same terminal. Mouse and keyboard users should have equivalent access. Acceptance should cover completed commands, restored invocations and output-only Agent Host invocations, with unavailable actions handled according to the agreed product behavior.
- **Trace:**

  > TerminalCommandDecoration in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts attaches a status span and delayed hover, then updates exit-state styling and ARIA text; it has no command-action activation handlers. The surrounding ChatTerminalToolProgressPart toolbar covers focus, output visibility, background continuation and retained output, not shell-integration command menus. DecorationAddon._createContextMenu and _getCommandActions in src/vs/workbench/contrib/terminal/browser/xterm/decorationAddon.ts establish the existing terminal action vocabulary and command/output availability conditions. Preserve existing command attribution, terminal execution semantics and surrounding card interactions. The uncertainty is which of those actions should be offered when inline invocations have no live terminal or full ITerminalCommand. https://github.com/microsoft/vscode/issues/317789 supplies related command-state context, and https://github.com/microsoft/vscode/issues/315191 supplies broader integration context; neither is a verified duplicate.
- **Open decisions:**
  - Which shell-integration actions should inline decorations expose: command/output clipboard actions only, or also rerun and terminal-navigation actions?
  - For restored or output-only invocations without a live terminal, should unavailable actions be hidden or disabled, and should any execution action remain available?
