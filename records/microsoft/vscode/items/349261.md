# Issue #349261 — Highlight over-length body lines in `git-commit`

[https://github.com/microsoft/vscode/issues/349261](https://github.com/microsoft/vscode/issues/349261)

## Summary

Overlength body highlighting remains missing in the commit-message editor. Existing rulers and SCM input validation do not cover this request; the linked subject-length configuration issue is related but does not clearly own the full work.

## Change summary

Highlight commit-message body text exceeding the desired line-length limit in COMMIT_EDITMSG editors.

## Best solution

Provide consistent subject and body length feedback in the commit-message editor, coordinated with the existing validation settings and the related configurability request. Any static grammar enhancement should follow the grammar's documented upstream contribution process.

## Evidence

- **Current grammar:** extensions/git-base/syntaxes/git-commit.tmLanguage.json applies its line-too-long captures only through the subject rule, using the hardcoded expression \G.{0,50}(.{0,22}(.*))$. There is no corresponding body-line overflow rule.
- **Existing capabilities do not cover the editor:** extensions/git/package.json supplies git-commit editor rulers at columns 50 and 72. Its git.inputValidationLength and git.inputValidationSubjectLength settings default to 72 and 50, but extensions/git/src/diagnostics.ts restricts document-change validation to the vscode-scm scheme, not ordinary COMMIT_EDITMSG files.
- **Related request is not a verified canonical:** https://github.com/microsoft/vscode/issues/317766 is open and primarily requests configurable subject highlighting. It mentions a body-length setting as desirable, but does not explicitly request the missing body overflow highlighting; treating it as fully absorbing this request would overstate its scope.
- **Ruler work is distinct:** https://github.com/microsoft/vscode/issues/93150 is closed and requested rulers and visual guidance in the SCM input. Those capabilities do not supply body overflow highlighting in the commit-message editor.
- **Grammar ownership:** The grammar's contributor notice directs improvements to https://github.com/walles/git-commit-message-plus. extensions/git-base/build/update-grammars.js imports that grammar; this is a bundled VS Code feature, not an installed-extension ownership close.
