# Issue #333474 — Remote Agent Host MCP Apps route subrequests through the ambient host

[https://github.com/microsoft/vscode/issues/333474](https://github.com/microsoft/vscode/issues/333474)

## Summary

Confirmed defect: AhpMcpAppCallTransport routes MCP App subrequests through the ambient IAgentHostService rather than the connection that owns the session, breaking MCP App UI for non-ambient Remote Agent Hosts. An open PR (#333475) already targets this exact fix, so it should stay open for that PR to land rather than being closed or auto-fixed here.

## Change summary

MCP App subrequests (resources/read, tools/call, sampling) for sessions on a non-ambient Remote Agent Host fail with 'no active chat' because they're sent through the ambient host instead of the connection identified by connectionAuthority.

## Best solution

Land https://github.com/microsoft/vscode/pull/333475, which routes AhpMcpAppCallTransport subrequests through IAgentHostConnectionsService using the render data's connectionAuthority instead of the ambient IAgentHostService.
