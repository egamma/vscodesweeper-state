# Issue #341546 — Chat setup code overrides explicit user 'chat disabled' setting when default chat extension is enabled

[https://github.com/microsoft/vscode/issues/341546](https://github.com/microsoft/vscode/issues/341546)

## Summary

Thanks for the detailed report. The code does what you describe, but it looks like deliberate two-way syncing between the chat-disabled setting and the default chat extension's enablement, not an accidental overwrite. With no maintainer input yet, this is better treated as a design question than closed as as-designed.

## Change summary

Enabling or installing the default chat extension resets the chat-disabled setting to false, even if the user explicitly set it to true.

## Best solution

A maintainer decides whether enabling the extension should override an explicit disable. If not, the onChange handler should leave an explicit true value alone, or the extension should stay disabled while the setting is true.
