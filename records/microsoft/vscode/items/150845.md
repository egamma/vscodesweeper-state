# Issue #150845 — Column Selection: ragged line ends

[https://github.com/microsoft/vscode/issues/150845](https://github.com/microsoft/vscode/issues/150845)

## Summary

The older, verified-open column-selection issue already describes the same observable problem: dragging beyond uneven line endings does not place a cursor at each line end. Consolidate this request there, preserving the keyboard-boundary requirement and Mac laptop context.

## Change summary

Support selecting uneven line endings by column dragging and keeping horizontal selection movement within each line, optionally through virtual whitespace.

## Best solution

Resolve end-of-line column-selection behavior within https://github.com/microsoft/vscode/issues/5402, retaining this report's request that keyboard movement stop at line ends. Its virtual-whitespace alternative is also tracked by https://github.com/microsoft/vscode/issues/13960.

- **Same reporter-observable symptom:** https://github.com/microsoft/vscode/issues/5402#issuecomment-513819635 explicitly describes block-selecting past line ends to place a cursor at each end, while VS Code instead uses the starting line's column. https://github.com/microsoft/vscode/issues/5402#issuecomment-680740682 reiterates dragging anywhere to the right of the text to select every line ending and explains why keyboard workarounds are not equivalent. These establish the same symptom required for a duplicate on re-review.
- **Existing capability is only partial:** src/vs/editor/browser/coreCommands.ts registers cursorEnd and cursorEndSelect, including Cmd+Right and Cmd+Shift+Right on macOS, matching the thread's suggested workaround. They move existing cursors or selections to line ends; they do not make the initial mouse drag include every shorter line.
- **Current selection boundary:** In src/vs/editor/common/cursor/cursorColumnSelection.ts, ColumnSelection.columnSelect maps a shared visual-column range onto each line and skips lines outside that range. Its fallback places cursors at every line end only when result.length is zero, so mixed-length selections are not generally treated as an end-of-line gesture. This is source inspection, not an executed reproduction.
- **Alternative already tracked:** https://github.com/microsoft/vscode/issues/13960 is currently OPEN. Its maintainer-added description explicitly requests rectangular column selection with whitespace added on demand and links to https://github.com/microsoft/vscode/issues/5402. https://github.com/microsoft/vscode/issues/3932 instead concerns elastic tabstops and is not the canonical for this request.
