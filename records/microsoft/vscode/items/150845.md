## Evidence

- **Same observable symptom:** https://github.com/microsoft/vscode/issues/5402#issuecomment-386534014 explicitly requests dragging over unequal row endings to select all line endings. https://github.com/microsoft/vscode/issues/5402#issuecomment-513819635 describes block-selecting beyond text to place a cursor at each line end and contrasts VS Code's start-column-based behavior with Sublime. These match this report's central symptom, satisfying the stronger duplicate bar for a re-reviewed item.
- **Current capability is partial:** src/vs/editor/common/cursor/cursorColumnSelection.ts, ColumnSelection.columnSelect, skips lines whose visible endpoints do not intersect the requested column interval. It adds cursors at every line end only when the entire result is empty. Thus its beyond-all-lines fallback does not cover mixed-length selections where some longer lines intersect the rectangle and shorter lines are omitted.
- **Discussion workaround verified:** The comments suggest END, customizing cursorEnd, and Command+Right on macOS. src/vs/editor/browser/coreCommands.ts registers cursorEnd with Command+Right and cursorEndSelect with Command+Shift+Right on macOS; CursorMoveCommands.moveToEndOfLine handles each existing cursor independently. These commands reach line endings, but cannot restore shorter lines already omitted by mouse column selection.
- **Related alternative, not the preferred canonical:** https://github.com/microsoft/vscode/issues/13960 is OPEN and explicitly requests rectangular selection with whitespace added on demand, matching this report's optional padding solution. https://github.com/microsoft/vscode/issues/3932 concerns elastic tabstops rather than the same observable line-end selection symptom.
