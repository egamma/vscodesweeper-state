# Issue #283156 — Discussing file protocol triggers odd non-functional explorer buttons to show up

[https://github.com/microsoft/vscode/issues/283156](https://github.com/microsoft/vscode/issues/283156)

## Summary

Still reproduces on main: `renderFileWidgets` in `chatInlineAnchorWidget.ts` converts any `file://` link with empty visible text into a non-functional file explorer button, even when the URL appears in conversational (non-reference) context. No fix has landed since the Dec 2025 confirmation.

## Change summary

When chat responses discuss the `file://` protocol conceptually, non-functional explorer-style buttons appear instead of plain text or links.

## Best solution

Guard `renderFileWidgets` to distinguish intentional file references (empty-text links emitted by the model as resource anchors) from auto-linked bare `file://` URLs in prose. The fix likely lives in `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatInlineAnchorWidget.ts` around line 107, where `!linkText` unconditionally triggers widget rendering — it should validate that the URI points to a real local file or require a `vscodeLinkType` marker.
