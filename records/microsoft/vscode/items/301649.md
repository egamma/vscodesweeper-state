# Issue #301649 — Delete file from explorer jumps to random file

[https://github.com/microsoft/vscode/issues/301649](https://github.com/microsoft/vscode/issues/301649)

## Summary

A real Explorer UX gap remains: deletion does not explicitly preserve the viewport and select an adjacent surviving item. The exact older report was closed for backlog cleanup rather than resolved or rejected, and there is no open canonical issue to absorb this re-reviewed request.

## Change summary

After deleting a file in the Explorer, retain the surrounding tree position and select the next or previous surviving item instead of shifting the view elsewhere.

## Best solution

Define a consistent post-delete Explorer policy: preserve the visible tree position and move focus and selection to the next sibling, falling back to the previous sibling or parent when necessary. The behavior should work consistently for mouse and keyboard deletion without changing which editor remains active.
