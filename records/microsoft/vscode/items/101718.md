# Issue #101718 — "Add Selection To Previous Find Match" interferes with "Add Selection To Next Find Match"

[https://github.com/microsoft/vscode/issues/101718](https://github.com/microsoft/vscode/issues/101718)

## Summary

The bidirectional selection gap remains on current main, and this issue is the canonical report. Keep it open under discussion rather than closing a quiet Backlog feature request.

## Change summary

Allow next- and previous-find-match commands to expand one multicursor selection in both directions.

## Best solution

Update MultiCursorSession to maintain independent forward and backward search frontiers instead of deriving both directions from the last-added selection, with tests covering direction changes.

## Evidence

- **current source:** src/vs/editor/contrib/multicursor/browser/multicursor.ts:366-437 still makes both _getNextMatch and _getPreviousMatch search from allSelections[allSelections.length - 1]. After adding in one direction, reversing direction therefore finds an already-selected occurrence rather than expanding the opposite edge.
- **existing capability gap:** The commands editor.action.addSelectionToNextFindMatch and editor.action.addSelectionToPreviousFindMatch both exist in src/vs/editor/contrib/multicursor/browser/multicursor.ts, but their shared last-added-selection behavior does not cover bidirectional expansion.

- **confirmed behavior:** The original discussion contains an independent confirmation that switching command direction fails in either order.
