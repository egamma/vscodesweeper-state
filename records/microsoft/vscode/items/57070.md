# Issue #57070 — Add a command that redos the last command that was executed

[https://github.com/microsoft/vscode/issues/57070](https://github.com/microsoft/vscode/issues/57070)

## Summary

Keep this accepted Backlog request open: Command Palette history offers a workaround, but does not provide the requested standalone, bindable repeat command. The thread and 36 upvotes establish demand; command eligibility and replay context still need a maintainer decision.

## Change summary

Provide a command users can bind to repeat the previously executed VS Code command without reopening the Command Palette.

## Best solution

Define a predictable repeat-command contract covering invocation sources, arguments, and current versus previous context, then expose it through a standalone bindable command. Preserve ordinary command execution and distinguish VS Code actions from terminal shell history.

## Plan brief

- **Likely files:** `src/vs/workbench/services/commands/common/commandService.ts`, `src/vs/platform/commands/common/commands.ts`, `src/vs/platform/quickinput/browser/commandsQuickAccess.ts`, `src/vs/workbench/contrib/quickaccess/browser/quickAccess.contribution.ts`, `src/vs/workbench/services/commands/test/common/commandService.test.ts`
- **Validation:** After settling the replay contract, add targeted command-service/action tests for invoking repeat without opening the palette, argument handling, supported invocation sources, asynchronous failures, and consecutive repeats without self-recursion. Manually verify a user-assigned shortcut repeats an eligible editing action under the selected context policy.
- **Behavior:**

  > Users want a standalone VS Code command they can bind to repeat a previous action without reopening the Command Palette. Existing palette MRU selection is not sufficient, and the discussion requests coverage for keyboard-invoked actions and previously supplied arguments. Acceptance must demonstrate direct shortcut invocation and predictable treatment of context-dependent actions, failed executions, and consecutive repeats. Terminal shell-history repetition is a separate capability.
- **Trace:**

  > AbstractCommandsQuickAccessProvider.toCommandPick in src/vs/platform/quickinput/browser/commandsQuickAccess.ts updates palette history with a command ID; CommandsHistory retains ordering counters rather than argument-bearing replay records. CommandService in src/vs/workbench/services/commands/common/commandService.ts broadcasts IDs and arguments for execution but has no replay state, and its completion-named event precedes asynchronous settlement. ICommandMetadata in src/vs/platform/commands/common/commands.ts has no repeatability contract. The uncertainty is product semantics, not which helper to use: the related discussion at https://github.com/microsoft/vscode/issues/273349#issuecomment-3460293566 asks whether repeating should use current or original context and whether commands must opt in. Preserve ordinary execution, palette MRU behavior, and terminal history; do not assume every dispatched or nested command represents the user's last repeatable action.
- **Open decisions:**
  - Should repeat target the last palette-selected command, the last user-invoked action from any UI or keybinding, or the last eligible action while excluding typing and infrastructure commands?
  - Should context-dependent actions operate on the current editor and selection or replay their original target, and which previously supplied arguments should be reused?
  - Should commands require explicit repeatability opt-in, or be eligible by default with defined exclusions and safeguards for destructive actions?
