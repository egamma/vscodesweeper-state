# Issue #270617 — VS Code looks for local paths during remote sessions

[https://github.com/microsoft/vscode/issues/270617](https://github.com/microsoft/vscode/issues/270617)

## Summary

The error is emitted by the third-party `mkhl.direnv` extension when it tries to execute the configured local direnv path in the remote workspace extension host. This belongs in the extension's own tracker rather than VS Code core.

## Change summary

Prevent a locally configured direnv executable path from being used during Remote-SSH sessions.

## Best solution

The direnv extension should resolve `direnv.path.executable` appropriately for remote workspace extension hosts, or document how to override it in remote settings. Track that work at https://github.com/direnv/direnv-vscode/issues.

## Evidence

- **error ownership:** The installed `mkhl.direnv` 0.17.0 extension defines `CommandNotFoundError` with the exact `${path}: command not found` message and throws it when `child_process.execFile` returns ENOENT: https://github.com/direnv/direnv-vscode/blob/master/src/direnv.ts.
- **configured executable:** The extension reads `direnv.path.executable` and passes that value directly to `execFile`; its manifest declares the setting and identifies https://github.com/direnv/direnv-vscode as its repository.
- **remote execution:** The extension manifest declares `extensionKind: ["workspace"]`, so during Remote-SSH it runs in the remote workspace extension host; the missing `/home/linuxbrew/.linuxbrew/bin/direnv` executable is therefore an extension configuration/remote-handling issue.
