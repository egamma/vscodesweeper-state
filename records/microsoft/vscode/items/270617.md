# Issue #270617 — VS Code looks for local paths during remote sessions

[https://github.com/microsoft/vscode/issues/270617](https://github.com/microsoft/vscode/issues/270617)

## Summary

Decline close (out-of-scope) gated off: the issue carries the `bug` label — the owner already triaged it as accepted work. Original assessment: The error and local executable path come from the third-party `mkhl.direnv` extension, not VS Code core. This should be closed as caused by an extension and tracked with the extension owner.

## Change summary

Prevent a locally configured direnv executable path from being used when the direnv extension runs in a Remote-SSH workspace.

## Best solution

The direnv extension should resolve `direnv.path.executable` appropriately for its remote extension host, with users configuring a remote-specific value where necessary.
