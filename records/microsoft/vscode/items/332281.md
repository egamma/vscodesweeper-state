# Issue #332281 — Provide UI feedback for changes made outside of viewport

[https://github.com/microsoft/vscode/issues/332281](https://github.com/microsoft/vscode/issues/332281)

## Summary

Keep open: inline chat still lacks a viewport-aware indication of edits elsewhere in the file. Existing change navigation does not provide the requested discovery feedback, and no older canonical covering the same request was identified.

## Change summary

Show when inline chat edits occur outside the visible editor region and provide a way to navigate to the remaining changes.

## Best solution

Provide a restrained change indicator and navigation alongside inline chat's existing review controls, reusing the shared edit-review state. First settle whether its count represents offscreen changes, unresolved changes, or changes not yet viewed.

- **Validation:** In a long file, request inline-chat edits both inside and outside the viewport. Verify that the agreed indicator accurately reflects the remaining changes, navigation reveals changes above and below the chat, and scrolling plus individual Keep/Undo actions update it according to the chosen semantics without changing existing acceptance/rejection behavior.
- **Behavior:**

  > After inline chat edits separated regions of a long file, users can discover that additional changes exist beyond the visible editor region without manually searching the document. The review surface provides navigation to those changes while preserving existing per-region and whole-session Keep/Undo behavior. Acceptance includes edits above and below the viewport, scrolling, and resolving individual changes. Whether visibility alone marks a change as reviewed remains a product decision.
- **Trace:**

  > InlineChatEditReviewSession in src/vs/workbench/contrib/inlineChat/browser/inlineChatEditReviewSession.ts exposes shared modified-file entries and is explicitly non-global. InlineChatController enables review mode and observes entry.diffInfo, while InlineChatZoneWidget owns the inline status and termination toolbar. Shared next/previous edit commands already exist in chatEditingEditorActions.ts. ChatEditorOverlayWidget renders change counts, but its controller excludes non-global sessions, so that overlay does not satisfy this request. Source inspection established these boundaries without executing or modifying the checkout. Preserve existing review and acceptance semantics; the requested addition concerns discovery and navigation, not restricting where the agent can edit. The original request is https://github.com/microsoft/vscode/issues/332281, filed while testing https://github.com/microsoft/vscode/issues/332022.
- **Open decisions:**
  - Should the indicator count changes currently outside the viewport, all unresolved changes, or changes not yet viewed, and does scrolling a change into view count as reviewing it?
