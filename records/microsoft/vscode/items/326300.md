# Issue #326300 — Local options are available in the main IDE chat window but permanently disappear from the Agent window dropdown

[https://github.com/microsoft/vscode/issues/326300](https://github.com/microsoft/vscode/issues/326300)

## Summary

Multiple users confirmed that local/BYOK models remained available in the main Chat view but disappeared from the Agents Window through VS Code 1.135. Current main has relevant bridge and late-registration safeguards, but no identified commit conclusively fixes this exact picker-disappearance trigger, so the issue should remain open pending a current-build reproduction.

## Change summary

Keep local and custom model choices visible and usable in the Agents Window whenever the main Chat view still exposes them.

## Best solution

Reproduce the startup and reload sequence on current main while tracing the renderer BYOK snapshot, Agent Host bridge registry, and Sessions model snapshot. If the picker still loses the models, preserve the populated renderer catalog across Agents Window startup and ensure the provider republishes it without requiring reinstallation or an Agent Host restart.

The behavior must recover automatically when the populated renderer snapshot arrives, without reinstalling VS Code or restarting the Agent Host.
- **Trace:**

  > The renderer-to-host catalog crosses src/vs/platform/agentHost/common/agentHostClientByokLmChannel.ts and is aggregated by ByokLmBridgeRegistry in src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts. LocalAgentHostService registers that reverse channel for each window, while CopilotAgent._refreshByokModels publishes bridge models and BaseAgentHostSessionsProvider.getModelsSnapshot filters them for the active Agent Host target. Current tests already cover an Agents app connection publishing empty before an editor connection publishes models, and commit https://github.com/microsoft/vscode/commit/15013c0fdc889ded1e440224c38a72dae2c45de3 separately covers models arriving after an SDK session is restored. The uncertainty starts at the UI/provider boundary: confirm whether current main still loses the catalog itself, filters it under the wrong target, or only retains a stale picker snapshot; do not broaden the work to unrelated model configuration or remote-host providers.

## Evidence

- **current source safeguards:** Current main's src/vs/platform/agentHost/node/byokLmBridgeRegistry.ts prefers a populated renderer connection over an Agents Window connection that initially publishes an empty model list. src/vs/platform/agentHost/node/copilot/copilotAgent.ts::_refreshByokModels republishes bridge models and synchronizes them into live sessions, but source inspection alone does not prove that the reported picker row and provider-selection path now remain visible.
