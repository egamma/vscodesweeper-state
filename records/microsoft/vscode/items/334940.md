# Issue #334940 — Debugger UI does not display ErrorResponse from Variables Request

[https://github.com/microsoft/vscode/issues/334940](https://github.com/microsoft/vscode/issues/334940)

## Summary

Traced in the source: `ExpressionContainer.evaluateLazy()` in debugModel.ts has no error handling, unlike `fetchVariables()` (used for regular children) which catches errors and surfaces them as an inline Variable, and `Variable.setVariable()` which catches and stores `errorMessage`. Clicking a lazy variable that throws an ErrorResponse silently fails with no UI feedback, exactly as reported.

## Change summary

Clicking a lazy variable whose Variables request returns an ErrorResponse shows no feedback in the Variables view, unlike Watch expressions which display the error inline.

## Best solution

Wrap the `this.session!.variables(...)` call in `ExpressionContainer.evaluateLazy()` (src/vs/workbench/contrib/debug/common/debugModel.ts) in a try/catch and surface the error message (e.g. set `this._value` to the error message, similar to how `fetchVariables()` returns an error Variable), so it renders inline instead of silently doing nothing.
