# Issue #334940 — Debugger UI does not display ErrorResponse from Variables Request

[https://github.com/microsoft/vscode/issues/334940](https://github.com/microsoft/vscode/issues/334940)

## Summary

Real bug traced in source: `ExpressionContainer.evaluateLazy()` in debugModel.ts has no try/catch around the `variables` request, and its caller (`evaluateLazyExpression` in debugViewModel.ts, invoked from the lazy-button click handler in baseDebugView.ts) doesn't catch either — so a rejected 'variables' request just becomes a silent unhandled rejection unless the adapter set `showUser: true` on the error Message, in which case a toast fires instead of inline text.

## Change summary

Clicking a lazy variable whose Variables request returns an ErrorResponse shows no inline error (and no feedback at all unless the adapter sets showUser), unlike Watch expression evaluation which does show errors inline.

## Best solution

Wrap the `session.variables(...)` call in `ExpressionContainer.evaluateLazy()` (src/vs/workbench/contrib/debug/common/debugModel.ts) in a try/catch that sets `this._value`/`value` to the error message the same way `evaluateExpression`'s catch block and `fetchVariables`'s catch block already do, so the error renders inline consistently.
