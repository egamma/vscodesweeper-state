# Issue #334940 — Debugger UI does not display ErrorResponse from Variables Request

[https://github.com/microsoft/vscode/issues/334940](https://github.com/microsoft/vscode/issues/334940)

## Summary

Confirmed in source: unlike `fetchVariables` (used for tree expansion), `ExpressionContainer.evaluateLazy()` in debugModel.ts has no try/catch around the `session.variables()` call, and `evaluateLazyExpression` in debugViewModel.ts calls it without a `.catch`, so an ErrorResponse from a lazy variable's Variables request is silently swallowed with no inline display or toast (unless `showUser` is set).

## Change summary

Clicking a lazy variable whose Variables request returns a DAP ErrorResponse shows no feedback in the UI, unlike Watch expression errors which render inline.

## Best solution

Wrap the `session.variables()` call in `ExpressionContainer.evaluateLazy()` (src/vs/workbench/contrib/debug/common/debugModel.ts) in a try/catch mirroring `fetchVariables`, setting `this._value` (and `hasChildren`-relevant state) to the error message so it renders inline the same way watch-eval errors do.
