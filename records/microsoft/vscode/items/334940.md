# Issue #334940 — Debugger UI does not display ErrorResponse from Variables Request

[https://github.com/microsoft/vscode/issues/334940](https://github.com/microsoft/vscode/issues/334940)

## Summary

Confirmed on current main: `ExpressionContainer.evaluateLazy()` in debugModel.ts has no error handling around the `variables` DAP request, so an ErrorResponse there causes a silent (or toast-only) failure instead of the inline error rendering that `fetchVariables` already does for regular child expansion.

## Change summary

Clicking a lazy/expandable variable whose Variables request errors shows no inline feedback (or an undesirable toast if `showUser` is set), unlike Watch expressions which render the error inline.

## Best solution

Wrap `evaluateLazy()`'s `session.variables()` call in a try/catch (mirroring `fetchVariables`'s existing catch at debugModel.ts:176-178) and set the container's value/reference from the error message so the tree renders it inline consistently with Watch evaluation errors.
