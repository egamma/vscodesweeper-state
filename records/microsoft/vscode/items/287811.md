# Issue #287811 — edited file link widget opens a read-only file diff

[https://github.com/microsoft/vscode/issues/287811](https://github.com/microsoft/vscode/issues/287811)

## Summary

Keep open for the discoverability improvement suggested by the maintainer: historical chat diffs are intentional, but reaching the editable file from that editor remains awkward. Existing context-menu and changed-files-list actions provide alternatives without fully addressing that gap.

## Change summary

Provide a discoverable way to open the current editable file while reviewing a historical edit from a chat file link.

## Best solution

Preserve historical snapshot comparisons and provide a direct, discoverable transition from the diff editor to the current workspace file, consistent with the maintainer's suggested Open File toolbar action.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatMarkdownContentPart.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingTextModelContentProviders.ts`
- **Validation:** The plan should establish an executable action test that opens a historical chat diff, invokes its current-file navigation action, and asserts that the editor input targets the original workspace URI rather than a snapshot URI. Manually verify that editing the opened workspace file succeeds while the historical comparison remains unchanged, including when later agent edits exist.
- **Behavior:**

  > Reviewing an edit through an inline chat file pill must retain the historical comparison while making the current editable workspace file directly discoverable from the review editor. Opening that file must not modify the snapshot or require searching by filename or expanding the changed-files list. Check both the latest edit and an older edit followed by additional changes.
- **Trace:**

  > CollapsedCodeBlock.render and showDiff in chatMarkdownContentPart.ts obtain a request-specific comparison through getEntryDiffBetweenStops and open its snapshot resources. The existing chat.openFileUpdatedBySnapshot action in chatEditingActions.ts opens the real URI, but receives its context from the pill's context menu rather than the diff editor. ChatEditingSnapshotTextModelContentProvider.getOriginalFileURI can recover recorded origin scheme and authority, returning undefined for legacy snapshots without that metadata. The changed-files-list setting is consumed by chatChangesSummaryPart.ts and chatMultiDiffContentPart.ts, not by the reported pill path. Historical read-only semantics should remain intact, as explained in https://github.com/microsoft/vscode/issues/287811#issuecomment-3813499103. The remaining investigation is how an editor action receives the correct originating resource, including inactive editors, and which existing harness can validate that navigation without changing generic diff behavior.
