# Issue #277686 — A bug occurs when opening the Copilot chat window in the editor or in a new window.

[https://github.com/microsoft/vscode/issues/277686](https://github.com/microsoft/vscode/issues/277686)

## Summary

The reported editor-disposal race was fixed after this report by reference-counting chat models instead of unconditionally clearing the session when a chat editor closes. The exact throwing path no longer exists on current main, so this can be closed as completed.

## Change summary

Opening or moving Copilot Chat into an editor or auxiliary window could dispose the same local chat session twice and log an `Unknown session` error.

## Best solution

Keep the reference-counted ChatModel lifecycle introduced by commit bbdd097bd30f07d2edf98a8cef449353a320012b, where each chat surface owns a model reference and closing one surface releases only that reference.

- **root cause removed:** Before the fix, `ChatService.clearSession` in `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts` threw exactly `Unknown session: ${sessionResource}` when another surface had already cleared the model. The fixing commit replaced direct deletion with `ChatModelStore` acquisition and release semantics, so closing an editor or auxiliary window no longer clears a model still owned elsewhere.
- **current main:** Source inspection on current main finds no chat-editor disposal call to `clearSession`; the model-store lifecycle now owns disposal. Follow-up commit https://github.com/microsoft/vscode/commit/30cfcc9385eb6862964a079f6ec07a87fde56b2e also removed the remaining `forceClearSession` API and its identical unknown-session throw.
