# Issue #95992 — Can't click to set/clear breakpoint when a gutter decoration exists

[https://github.com/microsoft/vscode/issues/95992](https://github.com/microsoft/vscode/issues/95992)

## Summary

Partially addressed in 1.78 (glyph margin rendering improvements) and the author confirmed improvement, but the remaining gap — setting new breakpoints on lines with non-codicon gutter decorations — still exists in the current code. The `marginFreeFromNonDebugDecorations` guard in `breakpointEditorContribution.ts` blocks breakpoint setting when extensions use custom (non-codicon) glyph margin classes. Stays open as a real remaining gap.

## Change summary

Clicking in the glyph margin to set a breakpoint is blocked when an extension decoration (e.g. Bookmarks, GitLens heatmap) occupies the same line.

## Best solution

The remaining gap lives in `marginFreeFromNonDebugDecorations` in `src/vs/workbench/contrib/debug/browser/breakpointEditorContribution.ts`, which conservatively blocks breakpoint clicks when non-debug gutter decorations are present. Broader adoption of `GlyphMarginWidget` (https://github.com/microsoft/vscode/issues/185814) with per-lane click handling would be the clean fix — once decorations use widgets with explicit click handlers, the breakpoint handler can coexist. This issue is a downstream consequence of https://github.com/microsoft/vscode/issues/179725.
