# Issue #315191 — AHP/Copilot: rich terminal UI integration

[https://github.com/microsoft/vscode/issues/315191](https://github.com/microsoft/vscode/issues/315191)

## Summary

Keep this broader terminal-parity discussion open: some capabilities already exist, but they do not cover Copilot's default SDK shell path. A maintainer explicitly retained this issue for broader integration work, and the verified related issues cover narrower, newer requests.

## Change summary

Decide which local-agent terminal capabilities should be available through AHP/Copilot, including profiles, PTY rendering, input detection, freeform input, and auto-reply.

## Best solution

Establish an explicit capability contract for SDK-owned shell tools versus host-managed interactive terminals, identifying which local-agent features should carry across. Keep this issue as the broader scope decision and use narrower issues for implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/agentHostTerminalService.ts`, `src/vs/workbench/contrib/terminal/browser/agentHostPty.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostTerminalContribution.ts`, `src/vs/platform/agentHost/node/agentHostTerminalManager.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`
- **Validation:** After agreeing the capability matrix, exercise SDK-shell and host-managed terminal sessions separately: verify profile selection, streamed rendering, interactive input, and any selected input-detection or auto-reply behavior. Include Windows and a POSIX host, and confirm unsupported capabilities do not expose misleading controls.
- **Behavior:**

  > Local-agent terminal features are not uniformly available through AHP/Copilot. The planning session should establish which of profiles, PTY rendering, input detection, freeform input, and auto-reply are required for each terminal execution mode. Acceptance is an explicit supported-capability matrix with observable checks for each selected feature, rather than assuming every shell tool is an interactive terminal.
- **Trace:**

  > AgentHostTerminalService registers host profiles and creates or revives workbench terminals backed by AgentHostPty, which transports output, input, resize, and reduced command lifecycle state. AgentHostTerminalContribution forwards the resolved local shell, while AgentHostTerminalManager creates host-managed PTYs. CopilotSessionLauncher selects custom shell tools only when enabled outside Windows; CopilotAgentSession also streams SDK-owned shell output into non-PTY channels. This establishes partial coverage, but not the intended parity contract for the default SDK path. The maintainer closure note at https://github.com/microsoft/vscode/issues/314189#issuecomment-4483218903 retains this broader scope; https://github.com/microsoft/vscode/issues/317789 and https://github.com/microsoft/vscode/issues/334029 track narrower concerns. Preserve the distinction between output-only channels and interactive PTYs, and do not treat landed headless foundations as completion of the product decision.
- **Open decisions:**
  - Which of the named local-agent terminal features should be guaranteed for default Copilot SDK shell tools, and which should be available only for host-managed interactive terminals?
  - When an SDK-owned shell lacks interactive capabilities, should the UI provide an explicit interactive-terminal alternative or retain an output-only experience?
