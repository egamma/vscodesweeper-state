# Issue #149048 — White bar appears when using external keyboard on iPad

[https://github.com/microsoft/vscode/issues/149048](https://github.com/microsoft/vscode/issues/149048)

## Summary

Keep this as the existing upstream tracking issue: WebKit still lists the incorrect iPad visualViewport height as unresolved, and current VS Code continues to use that value. The documented alternatives sacrifice on-screen keyboard resizing or obscure the status bar.

## Change summary

Prevent unused space below the web workbench when an iPad external keyboard activates the floating keyboard toolbar.

## Best solution

Track the WebKit viewport correction while preserving resizing for the on-screen keyboard and visibility above the home indicator. Any optional VS Code workaround should explicitly account for the regressions already identified in the discussion.

## Evidence

- **Unresolved upstream defect:** https://bugs.webkit.org/show_bug.cgi?id=247410 remains NEW with no resolution. Its standalone reproduction records visualViewport.height falling from 727 to 658 when an external keyboard's floating autocomplete UI appears; https://bugs.webkit.org/show_bug.cgi?id=247410#c6 confirms continued occurrence in January 2025.
- **Current source path:** src/vs/base/browser/dom.ts:626–642, getClientArea, still returns visualViewport.width and visualViewport.height for an iOS body container, whereas non-body containers use clientWidth/clientHeight. src/vs/workbench/browser/layout.ts:1753–1759 obtains the workbench dimensions through this helper. This retains the diagnosed dependency on WebKit's reported height; source inspection alone cannot verify current iPad rendering.
- **Maintainer investigation and workaround limits:** The March 2023 investigation in https://github.com/microsoft/vscode/issues/149048 explains why github.dev's non-body container avoids the gap but obscures the status bar and fails to resize for the virtual keyboard. https://bugs.webkit.org/show_bug.cgi?id=247410#c3 independently documents the same clientHeight workaround limitation. Reporters also found that disabling iPad keyboard shortcuts can break mouse or trackpad scrolling.
