# Issue #336561 — CSS Bracket colorization error when } is inside of url

[https://github.com/microsoft/vscode/issues/336561](https://github.com/microsoft/vscode/issues/336561)

## Summary

Traced and confirmed on main: bracket pair colorization miscolors `}`/`;` characters inside quoted `url()` strings in CSS because the CSS grammar deliberately reclassifies `meta.function.url string.quoted` from `string` to `other` (to enable path completion), and bracket-pair colorization only skips brackets in non-`other` token types. This is a real, narrow bug that should be routed to the CSS grammar area.

## Change summary

A `}` (or `;`) inside a quoted `url('...')` string is colorized as if it were a real bracket, because the token is reclassified as `other` instead of `string`.

## Best solution

Add the `meta.function.url string.quoted` scope to `unbalancedBracketScopes` in extensions/css/package.json (the same mechanism already used by extensions/csharp, extensions/typescript-basics, etc. for scopes that are `other`-typed for completions/highlighting but should not participate in bracket matching), so brackets inside url() strings stop being treated as real brackets for colorization purposes.

## Evidence

- **grammar override:** extensions/css/package.json lines 37-39 sets `"meta.function.url string.quoted": "other"`, overriding the normal `string` classification for quoted strings inside `url(...)`.
- **why it exists:** Per the linked https://github.com/microsoft/vscode-css-languageservice/issues/481 discussion (and referenced commit c73fade / issue #46145), this override exists so path/quick-suggestions trigger inside url() strings, since quick suggestions are normally suppressed in string tokens.
- **bracket-pair logic:** src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/tokenizer.ts line 203 only treats a token as bracket-eligible when `TokenMetadata.getTokenType(...) === StandardTokenType.Other`; since the url() string is forced to `other`, its embedded `}`/`;` are matched as real brackets.
- **existing fix mechanism:** The grammar contribution point `unbalancedBracketScopes` (see extensions/csharp/package.json:44, extensions/typescript-basics/package.json:70) exists precisely to mark `other`-typed scopes as not containing balanced brackets, and extensions/css/package.json does not currently use it.
