# Issue #102043 — [Request] Provide file-specific onDidChangeSemanticTokens event

[https://github.com/microsoft/vscode/issues/102043](https://github.com/microsoft/vscode/issues/102043)

## Summary

The API gap remains on current main: semantic-token invalidation is still provider-wide rather than document-specific. This team-authored Backlog request should remain open because the available workaround does not provide the requested efficiency.

## Change summary

Allow semantic-token providers to invalidate tokens for a specific document without refreshing every open matching document.

## Best solution

Extend the semantic-token change event with a document URI while preserving provider-wide invalidation compatibility, propagate that URI through the extension-host protocol, and refresh only the matching model watcher.

- **Reason:** Targeted invalidation improves extension API hygiene and avoids unnecessary semantic-token computation.

## Evidence

- **current public API:** src/vscode-dts/vscode.d.ts still declares DocumentSemanticTokensProvider.onDidChangeSemanticTokens as Event<void>, so extensions cannot identify an affected URI.
- **extension-host bridge:** src/vs/workbench/api/common/extHostLanguageFeatures.ts discards the event argument, while src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts transports and fires only an undefined payload.
- **global refresh behavior:** src/vs/editor/contrib/semanticTokens/browser/documentSemanticTokens.ts handles a provider change by visiting every model watcher and scheduling requests for every model to which the provider applies.
- **workaround limitation:** https://github.com/microsoft/vscode-cpptools/pull/5814 added a semantic-token cache specifically as a workaround for https://github.com/microsoft/vscode/issues/102043; it did not implement the requested core API.
- **maintainer discussion:** https://github.com/microsoft/vscode/issues/102043#issuecomment-662746794 confirms the extension adopted the cache workaround but retained the request to avoid cache maintenance and unnecessary refresh processing.
