# Issue #34627 — Support symbolic link folders in areas like debug, extensions

[https://github.com/microsoft/vscode/issues/34627](https://github.com/microsoft/vscode/issues/34627)

## Summary

Keep this established Backlog request open and route it to file/editor/debug ownership. Current main exposes realpath resolution but still lacks a consistent canonical-identity policy across editors, debugging, SCM, and extensions.

## Change summary

Provide configurable, consistent handling of symlinked files and folders so one physical file is not treated as multiple resources by editors, debuggers, Git, and extensions.

## Best solution

Define a shared URI identity policy that can correlate real and symlink paths while preserving the user's preferred workspace presentation, then adopt it across editor opening, debugging, SCM, and extension-facing APIs. This issue should remain the broad tracker; the narrower https://github.com/microsoft/vscode/issues/130082 can inform the editor-specific design.
