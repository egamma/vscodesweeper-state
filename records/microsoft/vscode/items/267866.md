# Issue #267866 — Hide the 'Keep' 'Undo' and diff buttons on the working set until changes are complete

[https://github.com/microsoft/vscode/issues/267866](https://github.com/microsoft/vscode/issues/267866)

## Summary

Keep open for a product decision: this team-authored, under-discussion UX proposal remains unimplemented, while a later merged change deliberately made Keep/Undo available during active responses. The maintainer's scope question does not amount to abandoning the request, and the team-authored-item rule bars a judgment close.

## Change summary

Hide the working-set Keep, Undo, and diff controls while an agent is generating changes, then reveal them when the changes are ready for review.

## Best solution

Decide whether the working-set toolbar should prioritize a quiet generation state or preserve the global review actions introduced by https://github.com/microsoft/vscode/pull/268020. If the original direction remains desired, hide only the working-set controls during generation and restore them when the response completes without changing completed-change review behavior or per-file accessibility.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingService.test.ts`

- **Behavior:**

  > While an agent response is generating file changes, the working-set review controls must follow the maintainer-selected interaction model without showing misleading disabled actions or competing with tool confirmations. Once generation completes, Keep, Undo, and View All Edits must be available for the pending changes. Completed-change review, per-file controls, keyboard accessibility, and screen-reader discoverability must remain coherent with the selected model.
- **Trace:**

  > The working-set toolbar is populated from `MenuId.ChatEditingWidgetToolbar` in `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts` and instantiated by `ChatInputPart.renderChatEditingSessionWithEntries` in `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`. `ChatWidget` binds `hasUndecidedChatEditingResourceContextKey` from modified entries, but the toolbar actions no longer include `ChatContextKeys.requestInProgress` in their visibility or precondition expressions. Commit 70a213ed87a1c7be01370fba42db537d3a59e740 and https://github.com/microsoft/vscode/pull/268020 intentionally removed those preconditions so completed entries can be kept or undone while another entry streams. The plan must reconcile that behavior with this issue's quieter generation-state proposal; do not alter edit streaming, snapshot semantics, or the rule that actively streaming entries are excluded from global accept/reject.
- **Open decisions:**
  - During an active response, should the working-set Keep/Undo actions be hidden entirely as originally requested, or remain visible and actionable for completed entries as established by https://github.com/microsoft/vscode/pull/268020?
  - If the toolbar buttons are hidden during generation, should their commands and keybindings remain available for completed entries, or should action availability match the hidden UI until the response finishes?
