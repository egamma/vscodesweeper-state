# Issue #331483 — Multi-row tab layout should reserve space for modification icons

[https://github.com/microsoft/vscode/issues/331483](https://github.com/microsoft/vscode/issues/331483)

## Summary

Reasonable, freshly filed request specific to multi-row tab layout; already correctly labeled `workbench-tabs`, no duplicate or existing setting fully covers it, so it stays open for maintainer/community triage.

## Change summary

When using multi-row tabs, request that layout reserve fixed space for the modified-file dot icon so marking/saving a file doesn't shift tab width and trigger a row re-wrap that jerks the editor content up/down.

## Best solution

If pursued, this belongs in the wrapTabs layout logic in src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts / multieditortabscontrol.css — reserve a fixed-width placeholder for the dirty dot (or otherwise keep tab width constant across dirty/clean state) only when wrapTabs is active, so the mitigation settings (`highlightModifiedTabs`, `tabActionCloseVisibility`) aren't required to avoid row-count churn.
