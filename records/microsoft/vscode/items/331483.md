# Issue #331483 — Multi-row tab layout should reserve space for modification icons

[https://github.com/microsoft/vscode/issues/331483](https://github.com/microsoft/vscode/issues/331483)

## Summary

Fresh (1-day-old), well-diagnosed request already correctly labeled `workbench-tabs`/`modernization`; the underlying CSS behavior is real and traceable, but it's too new for maintainer or community signal, so it should stay open for a product decision on whether to reserve dirty-indicator space by default.

## Change summary

When multi-row tabs fill the row width and `workbench.editor.tabActionCloseVisibility` is off, a tab's width grows/shrinks as files are dirtied/saved (since the tab-actions container, which holds the dirty dot, is only shown when `.dirty`), causing row-count changes and vertical layout jumps.

## Best solution

In multieditortabscontrol.css, consider always reserving the `.tab-actions` width (or a smaller fixed gutter) when `close-action-off` is set, instead of toggling `display: none`/`padding-right: 0` based on the `.dirty` class (see lines 450 and 517) — a maintainer should weigh this against the extra always-on whitespace for clean tabs before deciding the default.
