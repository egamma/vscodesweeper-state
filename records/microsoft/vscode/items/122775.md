# Issue #122775 — Call Stack bounces when short-lived second requests start/stop

[https://github.com/microsoft/vscode/issues/122775](https://github.com/microsoft/vscode/issues/122775)

## Summary

Keep open: maintainers reproduced the core Call Stack state loss with Mock Debug, including after the attempted fix, and the latest maintainer investigation still describes the auto-expansion behavior as unsettled.

## Change summary

Preserve a paused debug session's expansion, focus, and navigation context when short-lived concurrent sessions appear or disappear in the Call Stack view.

## Best solution

Define the desired Call Stack behavior for session-count transitions, then preserve the user's expansion and focus state in the debug Call Stack tree rather than allowing automatic reveal/expansion to displace it.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/callStackView.ts`, `src/vs/workbench/contrib/debug/test/browser/callStackView.test.ts`
- **Validation:** Add or extend a Call Stack view test that starts with one paused session, introduces a second short-lived session, and removes it; verify the original session remains expanded and the selected/focused stack frame remains stable throughout.
- **Behavior:**

  > A paused debug session's visible stack frames and current selection must remain stable when another short-lived session starts, pauses or runs, and terminates. Transitioning between the single-session and multi-session Call Stack presentation must not collapse the existing paused session or lose the user's place. Acceptance should cover the exact two-session Mock Debug sequence from the issue and preserve existing behavior for an ordinary first paused session.
- **Trace:**

  > The issue is reproducible with Mock Debug using the steps in https://github.com/microsoft/vscode/issues/122775#issuecomment-832696897, so PHP Debug is not the sole cause. Maintainers confirmed reproduction after the attempted fix, and the latest trace points to the session auto-expansion/reveal handling in src/vs/workbench/contrib/debug/browser/callStackView.ts. The problematic transition is the Call Stack tree changing shape as the number and state of sessions changes; the boundary is expansion, reveal, selection, and focus behavior in that view, not debug-adapter session lifecycle semantics. The earlier fix predates the reopen and was explicitly found insufficient.
- **Open decisions:**
  - Should a newly paused thread or session automatically expand and take focus, or should the Call Stack always preserve the user's current expansion and focus unless they explicitly navigate?
  - When the view changes between its simplified single-session presentation and the multi-session tree, should expansion state be retained for the session even though its visible tree level changes?
