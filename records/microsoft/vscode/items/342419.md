# Issue #342419 — AgentHostFileMonitorService ignores files.watcherExclude and .gitignore


[https://github.com/microsoft/vscode/issues/342419](https://github.com/microsoft/vscode/issues/342419)

## Summary

This is the same agent-host recursive watcher exclusion defect already tracked by the older, open issue https://github.com/microsoft/vscode/issues/334248. Consolidate there, preserving this report's Yocto build-tree scale, reported ENOSPC failures, and additional request to consider .gitignore support.

## Change summary

Agent-host changeset monitoring recursively watches large build trees despite configured files.watcherExclude patterns, exhausting Linux watcher resources.

## Best solution

Resolve effective watcher exclusions under https://github.com/microsoft/vscode/issues/334248 so agent-host changeset monitoring respects configured exclusions without losing relevant change notifications. Carry the optional .gitignore behavior request into that discussion rather than treating Git ignore semantics as an already-established watcher contract.

- **Current source confirms the shared defect:** src/vs/platform/agentHost/node/agentHostChangesetFileMonitorCoordinator.ts: ChangesetFileMonitorCoordinator._ensureRootWatcher explicitly passes DEFAULT_AGENT_HOST_WATCH_EXCLUDES. In src/vs/platform/agentHost/node/agentHostFileMonitorService.ts, acquire uses only the supplied excludes and _createEntry passes them directly to IFileService.watch with recursive: true. The defaults exclude Git metadata and Watchman cookies, not user-configured build directories; no watcherExclude reference exists under src/vs/platform/agentHost.
- **Configuration is not inherited downstream:** src/vs/platform/files/common/fileService.ts: watch/doWatch forwards the supplied options to provider.watch without merging configuration. By contrast, src/vs/workbench/contrib/files/browser/workspaceWatcher.ts explicitly resolves resource-scoped files.watcherExclude and refreshes its watches when that configuration changes. Thus the normal workspace watcher does not supply exclusions to the independent agent-host watch.
- **Same root cause with additional evidence:** https://github.com/microsoft/vscode/issues/342419 adds a Linux Yocto repository with over one million files, reported ENOSPC failures affecting other watchers, and build directories excluded both through files.watcherExclude and .gitignore. These details expose the same fixed-exclude recursive watch, not a separate provider-specific failure. Automatic or opt-in .gitignore support is an additional proposed remedy to retain in the canonical discussion.
