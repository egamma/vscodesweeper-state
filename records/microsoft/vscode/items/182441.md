# Issue #182441 — Regression: TextEditorEdit.replace does not select empty selection anymore

[https://github.com/microsoft/vscode/issues/182441](https://github.com/microsoft/vscode/issues/182441)

## Summary

Still reproduces on main: `TextEditorEdit.replace` on an empty range uses `forceMoveMarkers: false`, so the cursor lands after the inserted text without selecting it — inconsistent with non-empty range replacement behavior. No fix has been committed.

## Change summary

Calling `TextEditorEdit.replace` with an empty selection inserts text but does not select it, unlike when replacing a non-empty selection.

## Best solution

The fix should ensure that `replace` on an empty range produces a selection encompassing the inserted text, matching the non-empty-range behavior. The likely approach is either changing `forceMoveMarkers` to `true` in the `replace` path (which may have side effects), or providing a custom `endCursorState` in `mainThreadEditor.ts` `applyEdits` that computes the correct post-edit selection. The fix touches `src/vs/workbench/api/common/extHostTextEditor.ts` and possibly `src/vs/workbench/api/browser/mainThreadEditor.ts`.
