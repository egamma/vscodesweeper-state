# Issue #182441 — Regression: TextEditorEdit.replace does not select empty selection anymore

[https://github.com/microsoft/vscode/issues/182441](https://github.com/microsoft/vscode/issues/182441)

## Summary

Current behavior is intentional: an initially empty selection remains collapsed at the end of inserted text rather than expanding around it. Restoring the earlier behavior would reverse the verified fix for collapsed cursors recovering from marker changes.

## Change summary

Restore the former behavior where replacing an empty selection leaves the inserted text selected.

## Best solution

Keep the current collapsed-cursor behavior; extensions that need the inserted text selected should explicitly update `TextEditor.selection` after awaiting the edit or use snippet placeholder selection semantics.

## Evidence

- **intentional behavior change:** Commit https://github.com/microsoft/vscode/commit/14f54b128dd5955db7a69e0aac760731d343e54b explicitly added `Cursor.readSelectionFromMarkers` logic to collapse an expanded tracked range to its end when the original selection was empty, under the change title "Avoid selecting text when recovering from markers".
- **verified originating fix:** The change fixed https://github.com/microsoft/vscode/issues/111513, which is closed with `verified` and `insiders-released` labels after reporting that edits at an empty cursor unexpectedly selected inserted text.
- **current source:** `src/vs/editor/common/cursor/oneCursor.ts` still checks `this.modelState.selection.isEmpty() && !range.isEmpty()` and returns `range.collapseToEnd()`, conclusively producing the behavior reported here on current main.
- **regression coverage:** `src/vs/editor/test/browser/commands/sideEditing.test.ts` explicitly asserts that replacing at a collapsed selection with `something ` leaves the cursor collapsed after the inserted text.
- **existing guidance:** In https://github.com/microsoft/vscode/issues/141946#issuecomment-1026975970, the editor API maintainer states that controlling this through `TextEditorEdit` is not supported and recommends snippet cursor placement or explicitly resetting the editor selection.
