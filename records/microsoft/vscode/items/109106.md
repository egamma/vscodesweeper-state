# Issue #109106 — Use safer test for Location in argument processor

[https://github.com/microsoft/vscode/issues/109106](https://github.com/microsoft/vscode/issues/109106)

## Summary

Still open on main: the Location duck-type check in `extHostCommands.ts` line 100 is unchanged — any object with `uri` (URI) and `range` (IRange) properties gets silently converted to a Location, stripping other properties. Team-authored, keeping open.

## Change summary

The argument processor's duck-type check for `Location` is too broad: any object with `uri` and `range` properties is converted and has other properties stripped.

## Best solution

Add a stricter check — either a marker property on `modes.Location` (as jrieken suggested), or an own-property-count guard that rejects objects with additional properties beyond `uri` and `range`. The fix lives in `src/vs/workbench/api/common/extHostCommands.ts` around line 100.
