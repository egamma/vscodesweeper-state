# Issue #57939 — Allow to set a file association for files with no extension

[https://github.com/microsoft/vscode/issues/57939](https://github.com/microsoft/vscode/issues/57939)

## Summary

Keep this accepted Backlog request open: current file-association syntax still lacks a general selector for filenames containing no dots. Exact-name mappings and wildcard overrides do not cover the request, and the related reports consolidate here rather than provide a replacement canonical.

## Change summary

Allow a configured language association to match arbitrary extensionless filenames while excluding dotted filenames, including dotfiles.

## Best solution

Provide a documented extensionless-file selector in the language-association configuration without overriding associations for dotted filenames. A maintainer should first choose the public configuration syntax; preserve existing association behavior for users who do not opt in.

## Evidence

- **Requested boundary:** https://github.com/microsoft/vscode/issues/57939 explicitly requires matching somefilename but not somefilename.txt or .somefilename. The reporter confirmed that exact-name mappings work but do not address arbitrary extensionless filenames.
- **Current configuration path:** src/vs/workbench/contrib/files/browser/files.contribution.ts registers files.associations as glob-pattern-to-language mappings. WorkbenchLanguageService.updateMime in src/vs/workbench/services/language/common/languageService.ts registers each key as a filepattern; there is no extensionless selector in this path. files.defaultLanguage concerns new files, not a general association for existing extensionless files.
- **Existing glob capability does not cover the ask:** src/vs/base/common/glob.ts parseRegExp supports ordinary wildcards, brace alternatives and negated single-character classes, but not negative extglobs such as !(*.*). The documented syntax at https://code.visualstudio.com/docs/editor/glob-patterns agrees. [!.] excludes a dot for one character only; a subsequent * can still consume dots. Repeating that class enumerates fixed filename lengths rather than expressing the requested general selector.
- **Wildcard workaround changes unrelated files:** getAssociations in src/vs/editor/common/services/languagesAssociations.ts checks configured mappings before platform mappings and first-line detection. Consequently, a configured * or **/* association overrides installed-language associations for dotted files too. The thread's workaround manually restores individual extensions and therefore does not satisfy the central request.
