# Issue #236401 — remote-cli `code` command works in bash, but zsh or tmux

[https://github.com/microsoft/vscode/issues/236401](https://github.com/microsoft/vscode/issues/236401)

## Summary

Still reproduces on main: the remote-cli PATH is injected only via the extension host process environment (extensionHostConnection.ts:51–60), but zsh and tmux login shells re-source profile files that reset PATH, losing the remote-cli entry. No fix or shell-integration-level workaround has been added.

## Change summary

The `code` remote-cli command is unavailable in zsh and tmux terminals on SSH remotes because those shells reset PATH during initialization, losing the remote-cli directory.

## Best solution

The shell integration scripts for zsh (shellIntegration-rc.zsh / shellIntegration-login.zsh) should re-inject the remote-cli bin folder into PATH, similar to how other VS Code environment variables are preserved. Alternatively, the terminal creation path could ensure the remote-cli PATH entry survives shell re-initialization. The fix likely touches `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-rc.zsh` and/or `src/vs/server/node/extensionHostConnection.ts`.
