# Issue #211501 — InlineCompletionItem Multiline Replace Range

[https://github.com/microsoft/vscode/issues/211501](https://github.com/microsoft/vscode/issues/211501)

## Summary

The stable inline-completion API still does not support the requested multiline replacement. Keep this accepted Backlog request open: proposed inline-edit capabilities are related, but do not establish that the stable API gap is resolved.

## Change summary

Allow inline completion providers to replace across line boundaries so accepting a completion can incorporate an existing closing brace and add a trailing semicolon without duplicating the brace.

## Best solution

Have the inline-completions API owner decide how extensions should provide this multiline replacement through a supported public contract. The finished behavior should preview and accept the complete replacement, including the existing closing brace, rather than requiring a follow-up command or duplicated delimiter.

## Evidence

- **Stable API limitation remains:** src/vscode-dts/vscode.d.ts:5341-5347 still documents InlineCompletionItem.range with "Must begin and end on the same line." Multiline insertText is not equivalent to replacing an existing brace on a subsequent line.
- **Ghost-text rendering boundary:** In src/vs/editor/contrib/inlineCompletions/browser/model/computeGhostText.ts, computeGhostText removes a common prefix and then returns undefined when the remaining replacement spans multiple lines. It also rejects diff changes that remove existing characters. These restrictions explain why removing the API documentation constraint alone would not deliver the requested preview.
- **Proposed capability is not stable coverage:** src/vscode-dts/vscode.proposed.inlineCompletionsAdditions.d.ts adds InlineCompletionItem.isInlineEdit. In src/vs/workbench/api/common/extHostLanguageFeatures.ts:1484-1486, that property is forwarded only when the extension enables the inlineCompletionsAdditions proposed API; otherwise isInlineEdit is false. This is not a supported stable replacement for the central ask.
- **Discussion and accepted scope:** At https://github.com/microsoft/vscode/issues/211501, the maintainer described the single-line rule as an API precondition preserving refactoring freedom, not an explicit rejection of extending the API. The reporter then clarified that multiline ranges produce no ghost text. The existing Backlog milestone records accepted, unscheduled work and does not justify a decline close.
- **Related reports do not establish a canonical:** https://github.com/microsoft/vscode/issues/200565 is closed and concerns showing suggestions on a line other than the cursor line; its maintainer comments distinguish multiline suggestion text from single-line replacement ranges. https://github.com/microsoft/vscode/issues/124024 is also closed and tracks the original Inline Completions API. Neither is an open canonical for this re-reviewed request, and searches for multiline inline completions and replacement ranges did not verify one.
