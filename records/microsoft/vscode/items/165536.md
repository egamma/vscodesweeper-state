# Issue #165536 — Register custom css variables within .monaco-workbench 

[https://github.com/microsoft/vscode/issues/165536](https://github.com/microsoft/vscode/issues/165536)

## Summary

The cleanup remains incomplete on current main: sash defaults and dynamically registered z-index variables are still emitted at `:root`, while only parts of the original work were completed. The accepted On Deck debt should remain open while the intended scope and standalone-widget compatibility are clarified.

## Change summary

Scope workbench-owned CSS custom properties beneath `.monaco-workbench` so embedding VS Code does not leak those properties into the host document.

## Best solution

Define workbench-owned custom properties within the workbench container while preserving appropriate defaults for standalone base/editor widgets. First establish which entries from the broader variable inventory are genuinely workbench-owned and whether embedded consumers require a compatibility path.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/sash/sash.css`, `src/vs/workbench/contrib/sash/browser/sash.ts`, `src/vs/platform/layout/browser/zIndexRegistry.ts`, `src/vs/workbench/contrib/notebook/browser/notebookEditorWidget.ts`
- **Validation:** Embed a workbench in a host document with sentinel values for the affected custom-property names and verify the host root remains unchanged while workbench sashes and notebook z-index layers retain their current sizing and stacking; also verify a standalone sash retains usable defaults.
- **Behavior:**

  > Embedding the VS Code workbench must not install workbench-owned CSS custom properties on the host document root. Sash sizing and notebook stacking inside `.monaco-workbench` must remain unchanged. Standalone base/editor widgets that do not live beneath `.monaco-workbench` must retain their documented default appearance. Acceptance includes an embedding check for host-property isolation and a standalone sash compatibility check.
- **Trace:**

  > Current `src/vs/base/browser/ui/sash/sash.css` places sash defaults at `:root`, although `SashSettingsController` in `src/vs/workbench/contrib/sash/browser/sash.ts` scopes configured overrides to `.monaco-workbench`. `ZIndexRegistry.updateStyleElement` in `src/vs/platform/layout/browser/zIndexRegistry.ts` also writes every registered variable to `:root`; the current registrations are primarily notebook layers from `notebookEditorWidget.ts` and `notebookDiffEditor.ts`. https://github.com/microsoft/vscode/pull/165534 completed the notebook-find portion, while https://github.com/microsoft/vscode/pull/166710 renamed sash properties without removing their root defaults. The boundary must preserve standalone sash/editor consumers and avoid broad changes to unrelated editor-owned `:root` properties. The uncertainty begins at deciding which variables are workbench-owned and what fallback contract standalone consumers require.
- **Open decisions:**
  - Should this debt cover only the remaining sash and z-index checklist entries, or every workbench-owned custom property in the broader inventory referenced by the maintainer?
  - What public styling contract should standalone sash/editor consumers receive when they are not descendants of `.monaco-workbench`?
