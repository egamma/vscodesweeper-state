# Issue #139175 — Can't delete row from setting

[https://github.com/microsoft/vscode/issues/139175](https://github.com/microsoft/vscode/issues/139175)

## Summary

Still reproduces on main: the general problem of deleting default-value rows from object settings is unsolved — only `workbench.editor.customLabels.patterns` is special-cased via `objectSettingSupportsRemoveDefaultValue`. The underlying design tension (merge-strategy semantics vs. user intent to clear a key) remains open.

## Change summary

Users cannot delete rows representing default values from object-type settings in the Settings editor UI, because the merge strategy silently re-introduces them.

## Best solution

Generalize the remove-default-value support (currently hardcoded to one setting in `settingsTreeModels.ts`) so that any object setting whose schema supports nullable values allows the user to explicitly set a key to `null` to override the default. This likely involves changes to `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts` and `settingsTree.ts` to make the removability logic schema-driven rather than key-name-driven.
