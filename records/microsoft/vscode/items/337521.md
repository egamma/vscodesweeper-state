# Issue #337521 — Terminal title and inline actions dont show if hidden terminals are detected

[https://github.com/microsoft/vscode/issues/337521](https://github.com/microsoft/vscode/issues/337521)

## Summary

Traced to source: `TerminalContextKeys.shouldShowViewInlineActions` (src/vs/workbench/contrib/terminal/common/terminalContextKey.ts) and the equivalent Focus/Split ViewTitle menu item (src/vs/workbench/contrib/terminal/browser/terminalMenus.ts) both hard-negate on `TerminalContribContextKeyStrings.ChatHasHiddenTerminals`, so the split/kill actions and single-terminal title disappear whenever ANY hidden chat/tool terminal exists — even with multiple visible terminals — rather than adjusting the visible-terminal count. This is real and fresh (filed today, no maintainer triage yet), so it stays open rather than closing.

## Change summary

When Copilot creates a hidden terminal (tool session), the terminal view's inline split/kill actions and single-terminal title/focus menu item vanish entirely, instead of just excluding the hidden terminal from the visible-terminal count.

## Best solution

Exclude chat-hidden terminals from the group/terminal counts that drive `shouldShowViewInlineActions` and the Focus/Split menu item (e.g. a visible-group-count context key), rather than blanket-suppressing those actions whenever any hidden terminal exists.

## Evidence

- **guard causing suppression:** src/vs/workbench/contrib/terminal/common/terminalContextKey.ts:147-166 — `shouldShowViewInlineActions` includes `ContextKeyExpr.not(TerminalContribContextKeyStrings.ChatHasHiddenTerminals)`, unconditionally hiding split/kill icons whenever a hidden chat terminal exists.
- **same pattern in Focus/Split menu item:** src/vs/workbench/contrib/terminal/browser/terminalMenus.ts:449-471 has the identical `ContextKeyExpr.not(TerminalContribContextKeyStrings.ChatHasHiddenTerminals)` guard on the single-terminal title/Focus command.
- **hidden context key source:** src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatService.ts:400-405 sets `_hasHiddenToolTerminalContext` true whenever `getToolSessionTerminalInstances(true).length > 0`, i.e. any single hidden chat-created terminal flips this for the whole view regardless of how many other visible terminals/groups exist.
- **group count includes hidden groups:** src/vs/workbench/contrib/terminal/browser/terminalGroupService.ts:73-74 binds `TerminalContextKeys.groupCount` to `this.groups.length`, which appears to include chat-hidden groups, so the intended 'only one terminal' conditions are already skewed by hidden terminals independent of the extra negation.
