# Issue #263027 — feature request for editor cursor

[https://github.com/microsoft/vscode/issues/263027](https://github.com/microsoft/vscode/issues/263027)

## Summary

This remains a valid Backlog feature request with the required 20 community upvotes. Current main supports a separate overtype cursor shape, but not the requested overtype color or inactive-editor cursor style.

## Change summary

Allow users to configure a distinct overtype cursor color and an outline-style cursor for inactive editors.

## Best solution

Provide opt-in cursor appearance controls for overtype and inactive states while preserving the current cursor color and hidden inactive cursor as defaults.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/core/editorColorRegistry.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts`
- **Validation:** In a split-editor smoke test, configure distinct insert/overtype cursor colors and an inactive outline style; toggling overtype must change color without changing unrelated cursor behavior, moving focus between editors must leave only the unfocused editor's outline visible, and default settings must retain today's cursor behavior.
- **Behavior:**

  > Users can opt into a distinct cursor foreground while the editor is in overtype mode and an outline cursor for an inactive editor. Insert-mode coloring, multi-cursor behavior, cursor blinking, and the default hidden inactive cursor remain unchanged unless the new controls are configured. Acceptance should cover switching input modes and moving focus between two visible editors.
- **Trace:**

  > EditorOption.overtypeCursorStyle and EffectiveCursorStyle in src/vs/editor/common/config/editorOptions.ts already select a shape from the input mode. Cursor colors are registered in src/vs/editor/common/core/editorColorRegistry.ts and consumed by the theming participant in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts without input-mode state. The same ViewCursors class tracks `_editorHasFocus`, but `_getCursorBlinking` currently hides the cursor whenever focus is lost. Keep multi-cursor color semantics and existing defaults outside the requested state-specific customization unchanged. No open canonical issue was found; the uncertainty starts at the precise public meaning of an inactive editor.
- **Open decisions:**
  - Should “inactive” mean any editor without text focus, including editors in inactive groups and windows, or only a visible editor pane that loses focus to another pane in the same window?

## Evidence

- **backlog acceptance:** The issue has 20 body upvotes, carries the Backlog milestone, and the triage bot confirmed promotion at https://github.com/microsoft/vscode/issues/263027#issuecomment-3555538443.
- **existing partial capability:** src/vs/editor/common/config/editorOptions.ts registers `editor.overtypeCursorStyle` and computes `effectiveCursorStyle`, so overtype mode can use a distinct shape but has no corresponding foreground color option.
- **missing color state:** src/vs/editor/common/core/editorColorRegistry.ts registers only the general `editorCursor.foreground` and multi-cursor variants; src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts applies those colors without considering insert versus overtype mode.
- **inactive behavior:** ViewCursors._getCursorBlinking in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts unconditionally returns Hidden when `_editorHasFocus` is false, and there is no inactive cursor-style editor option.
- **canonical search:** Repository issue searches for overtype cursor color and inactive editor cursor style found no open issue that clearly owns both requested controls.
