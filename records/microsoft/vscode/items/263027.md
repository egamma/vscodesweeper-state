# Issue #263027 — feature request for editor cursor

[https://github.com/microsoft/vscode/issues/263027](https://github.com/microsoft/vscode/issues/263027)

## Summary

This accepted Backlog request remains necessary: current main supports a distinct overtype cursor shape, but not a distinct overtype color or a visible configurable inactive-editor cursor. Its 20 community upvotes rule out a staleness close.

## Change summary

Allow separate editor cursor coloring in overtype mode and a configurable outline-style cursor when the editor is inactive.

## Best solution

Define coherent state-specific cursor customization for overtype and inactive editors, including theme-token fallback behavior and clear focus semantics, while preserving existing defaults.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/core/editorColorRegistry.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursors.css`
- **Validation:** Exercise insert, overtype, focused, and unfocused editor states with default and customized settings; verify state-specific color/style selection while existing cursor defaults, multi-cursor colors, blinking, and high-contrast rendering remain unchanged.
- **Behavior:**

  > Users can visually distinguish overtype input from insert input using a separately configurable cursor color. They can also choose an outline cursor for an inactive editor instead of the cursor always disappearing. Existing configurations retain their current appearance by default, and focused cursor blinking, multi-cursor rendering, and high-contrast behavior remain intact.
- **Trace:**

  > Current input-mode switching is computed by `EffectiveCursorStyle` in src/vs/editor/common/config/editorOptions.ts, which selects `overtypeCursorStyle` versus `cursorStyle`. Cursor theming in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts has single, primary-multicursor, and secondary-multicursor colors but no overtype token. The same class hides all cursors by returning `TextEditorCursorBlinkingStyle.Hidden` when `_editorHasFocus` is false, while outline rendering already exists through the `cursor-block-outline-style` rule in viewCursors.css. The boundary is editor cursor rendering and configuration; terminal cursor behavior and existing default cursor visuals must not change.
- **Open decisions:**
  - Should overtype and inactive customization be delivered as one cursor-state model or as independent settings?
  - Should an inactive cursor appear whenever editor text focus is lost, or only when focus moves to another editor or terminal?
  - What fallback chain should new state-specific theme colors use for single and multiple cursors?

## Evidence

- **accepted demand:** The issue has 20 community upvotes and https://github.com/microsoft/vscode/issues/263027#issuecomment-3555538443 confirms that it was promoted to the Backlog.
- **overtype gap on main:** src/vs/editor/common/config/editorOptions.ts defines `editor.overtypeCursorStyle`, and `EffectiveCursorStyle` switches cursor shape by input mode, but src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts applies the same `editorCursor.foreground` theme color to insert and overtype cursors.
- **inactive gap on main:** In src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts, `ViewCursors._getCursorBlinking()` returns `TextEditorCursorBlinkingStyle.Hidden` whenever the editor lacks focus. There is no editor inactive-cursor style option or theme token; `cursorStyleInactive` exists only for the integrated terminal.
- **canonical search:** The broader https://github.com/microsoft/vscode/issues/93185 was closed by the former insufficient-upvotes process without a fixing PR, so it is neither an open canonical nor evidence that this request was implemented.
