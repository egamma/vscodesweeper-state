# Issue #338958 — MCP: Allow users to disable all workspace servers while keeping user servers enabled

[https://github.com/microsoft/vscode/issues/338958](https://github.com/microsoft/vscode/issues/338958)

## Summary

This is a distinct, still-unimplemented MCP source-control request: existing controls operate per server, while the related bulk requests either suppress user servers or disable every server. Route it to MCP and AI Customizations for a cross-harness design.

## Change summary

Add a user-owned preference that disables workspace-origin MCP servers by default while retaining user/global servers and allowing explicit workspace opt-in.

## Best solution

Use one user-owned source policy across local and Agent Host harnesses: filter workspace-origin servers before runtime handoff, retain user/global servers, persist workspace exceptions outside repository settings, and expose the effective state and override in the MCP management UI without replacing per-server enablement.

- **Behavior:**

  > Users can globally default repository/workspace MCP configurations off while continuing to use their user/global MCP servers. A trusted workspace can be explicitly opted in through state the repository cannot set or overwrite, and the MCP management UI clearly shows and reverses that decision. Existing per-server global, workspace, and session controls continue to compose with the source-wide preference, and local, Copilot, Claude, and Codex harnesses produce the same effective server set.
- **Trace:**

  > The local harness assembles enabled servers in McpWorkbenchService.getEnabledLocalMcpServers() at src/vs/workbench/contrib/mcp/browser/mcpWorkbenchService.ts:625-666, where source scopes are already separated but all enabled scopes are returned. Agent Host publishes source provenance through readMcpServerSource()/withMcpServerSourceMeta() in src/vs/platform/agentHost/common/meta/mcpCustomizationMeta.ts, then applies only per-customization decisions in resolveCustomizationEnablement() and getSdkMcpServerEnablement() in src/vs/platform/agentHost/node/shared/customizationEnablementGate.ts. Per-server durable decisions are stored by AgentHostCustomizationEnablementService, and mcpListWidget.ts exposes only individual global/workspace/session actions. The plan must establish one authoritative user-owned source policy across those paths and preserve the existing session > workspace > global per-server precedence. Do not fold this into https://github.com/microsoft/vscode/issues/329475 or https://github.com/microsoft/vscode/issues/337335: those requests suppress the opposite source or all sources, respectively.
