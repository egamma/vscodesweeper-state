# Issue #329726 — Commit Message Editor Fails when moved to different window

[https://github.com/microsoft/vscode/issues/329726](https://github.com/microsoft/vscode/issues/329726)

## Summary

Traced conclusively in source: moving the commit-message editor tab to another window/group fires a spurious tab-close event for its old location, prematurely completing the git.useEditorAsCommitInput wait and handing git an as-yet-unedited (empty) message file.

## Change summary

Moving the auto-opened commit message editor to a separate window causes the commit to fail with "empty commit message" even after writing and saving a message.

## Best solution

In extensions/git/src/gitEditor.ts GitEditor.handle(), stop treating any 'closed' tab event matching the commit-message URI as done editing — cross-group/cross-window moves are implemented as close+reopen, so a genuine completion check must confirm the URI is no longer open in any tab group before resolving.

- **Fix prompt:**

  > extensions/git/src/gitEditor.ts's GitEditor.handle() opens the commit-message document and waits via `window.tabGroups.onDidChangeTabs`, resolving its promise (and thus letting GIT_EDITOR exit 0) the first time `tabs.closed` contains a TabInputText tab whose URI matches the commit-message path. This is wrong when the user moves that tab to a different editor group or a new auxiliary window: per src/vs/workbench/browser/parts/editor/editorGroupView.ts `doMoveOrCopyEditorAcrossGroups()`, a cross-group move is implemented as an open in the target group followed by a real `doCloseEditor(..., { context: EditorCloseContext.MOVE })` in the source group, which src/vs/workbench/api/browser/mainThreadEditorTabs.ts forwards as an ordinary EDITOR_CLOSE (no move-coalescing exists for cross-group moves, only for same-group index reordering) — so the extension sees a spurious 'closed' event for the URI while the user is still mid-edit in the new window, resolves the IPC call early, and git then reads an empty COMMIT_EDITMSG, aborting with 'Aborting commit due to empty commit message' (matches extensions/git/src/git.ts's handleCommitError regex). Fix the `handle()` listener so it does not resolve merely because the URI appeared in `tabs.closed`: after that event, check whether the same URI is still present in any tab across `window.tabGroups.all` (it will be, in the new group/window, since the move opens it there before closing the old one) and only resolve `c(true)` when the URI is genuinely gone everywhere. Do not change the surrounding IPC protocol, the git.ts commit flow, or unrelated document-link logic in this file. Validate with a new integration test in extensions/git/src/test/ that simulates a tab move (split or new-window) and asserts the wait does not complete, then closes the tab for real and asserts it does.

## Evidence

- **wait-for-close logic:** extensions/git/src/gitEditor.ts GitEditor.handle() resolves the GIT_EDITOR IPC call as soon as window.tabGroups.onDidChangeTabs reports the commit-message URI in `tabs.closed`, with no check for whether it re-opened elsewhere.
- **cross-group move = close+open:** src/vs/workbench/browser/parts/editor/editorGroupView.ts doMoveOrCopyEditorAcrossGroups() opens the editor in the target group then calls this.doCloseEditor(editor, ..., { context: EditorCloseContext.MOVE }) on the source group — a real EDITOR_CLOSE for the source group.
- **no move coalescing at API layer:** src/vs/workbench/api/browser/mainThreadEditorTabs.ts only special-cases GroupModelChangeKind.EDITOR_MOVE for same-group index reordering (isGroupEditorMoveEvent); cross-group moves go through the ordinary EDITOR_OPEN/EDITOR_CLOSE branches, so extHostEditorTabs.ts $acceptTabOperation emits a genuine TAB_CLOSE for the old location, which extensions observe as `tabs.closed`.
- **consequence:** extensions/git/src/git.ts commit() with opts.useEditor relies on git itself reading the saved file after GIT_EDITOR exits 0; if git-editor-main.js exits before the user actually writes/saves, git's own empty-message check fires (extensions/git/src/git.ts handleCommitError matches /Aborting commit due to empty commit message/), matching the reporter's exact notification.
