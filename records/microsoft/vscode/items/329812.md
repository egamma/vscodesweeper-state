# Issue #329812 — apply_patch rejects multiple update blocks for the same file, which openai models try to do a lot

[https://github.com/microsoft/vscode/issues/329812](https://github.com/microsoft/vscode/issues/329812)

## Summary

The rejection remains directly reproducible from current source: the parser rejects a second update block for the same path, while Copilot's own patch instructions explicitly recommend repeating that header. Keep this open to resolve the tool/instruction mismatch; no verified canonical or landed fix was identified.

## Change summary

Accept independent, non-overlapping update blocks targeting the same file within one apply_patch invocation, while rejecting conflicting edits explicitly.

## Best solution

Make repeated update blocks for independent regions work consistently with the advertised patch format, without dropping edits or weakening conflict detection. Preserve existing single-block, multi-file, and file-operation behavior.

## Evidence

- **Exact failure in current source:** In extensions/copilot/src/extension/tools/node/applyPatch/parser.ts, Parser.parse() stores the first update in this.patch.actions[path], then unconditionally throws `Update File Error: Duplicate Path` upon encountering another update for that path. The reporter's two independent replacements therefore fail before the second region is examined.
- **Contradiction with intended behavior:** extensions/copilot/src/extension/prompts/node/agent/defaultAgentInstructions.tsx:457 explicitly instructs models to repeat the `*** Update File` header for multiple regions in the same file. ApplyPatchInstructions.render() includes these instructions when the simplified-instruction branch is not selected. This establishes a repository-owned behavior mismatch, not merely a request for a new patch syntax.
- **Tool call path and mitigation limits:** ApplyPatchTool.buildCommit() in extensions/copilot/src/extension/tools/node/applyPatchTool.tsx calls processPatch(), which loads documents, invokes Parser.parse(), and constructs the commit. buildCommitWithHealing() can request a model-generated replacement patch after a DiffError, but reparses that replacement with the same parser; healing does not provide native support for repeated update blocks.
- **Existing capability is only a workaround:** Parser.parse_update_file() already supports multiple hunks within one update block. That permits independent edits under a single header, but does not accept the repeated-header form described by the reporter and recommended by ApplyPatchFormatInstructions.
- **Related external work is not a VS Code fix:** https://github.com/xyTom/coding-tools-mcp/issues/65 explicitly cites this report while describing duplicate-update normalization in its own MCP patch frontend. Its closed state does not establish adoption or a fix in VS Code.

The checkout is shallow, so local history cannot establish full fix provenance; the current parser nevertheless retains the exact rejection.
