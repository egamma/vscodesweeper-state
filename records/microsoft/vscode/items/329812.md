# Issue #329812 — apply_patch rejects multiple update blocks for the same file, which openai models try to do a lot

[https://github.com/microsoft/vscode/issues/329812](https://github.com/microsoft/vscode/issues/329812)

## Summary

Traced this in current main: `Parser.parse()` in the apply_patch implementation hard-throws `Update File Error: Duplicate Path` the moment a second `*** Update File:` block targets a path already present in `patch.actions`, so an agent that emits two independent hunks for the same file in one patch always fails. This is a real, still-open gap (mirroring OpenAI's reference implementation) that a maintainer should decide how to relax, so I'm routing it rather than closing.

## Change summary

apply_patch rejects a patch that contains two separate `*** Update File:` blocks for the same path, even when the edit regions don't overlap, which OpenAI models (especially gpt-5.6-luna/terra) frequently emit and which then stalls the agent flow.

## Best solution

In extensions/copilot/src/extension/tools/node/applyPatch/parser.ts, when `parse()` hits a second `Update File` block for a path that already has an UPDATE action, merge the newly parsed chunks into the existing action's chunk list (sorted by `origIndex`) instead of throwing, and only surface a specific conflict error when the delete/context regions actually overlap. `_get_updated_file` already applies a chunk list in order, and the existing `multipleSections` fixture shows multiple `@@` chunks within one `Update File` block already work — the gap is specifically across two separate blocks for the same path.
