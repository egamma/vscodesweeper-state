# Issue #146799 — Make test message be able to toggle between 'verbose' and 'simple' mode.

[https://github.com/microsoft/vscode/issues/146799](https://github.com/microsoft/vscode/issues/146799)

## Summary

Keep open: current testing APIs support structured stack traces and collapsing stack frames, but not two extension-authored message variants with a verbosity switch. This team-authored Backlog request still has a distinct API/UX gap; no qualifying canonical or referenced fix was found.

## Change summary

Allow test extensions to supply concise and verbose failure messages that users can switch between in the test peek view.

## Best solution

Settle the Testing API contract for concise versus detailed failure content, accounting for the existing structured stack-trace UI. The resulting experience should let users reduce framework noise without losing access to full diagnostics.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/contrib/testing/common/testTypes.ts`, `src/vs/workbench/contrib/testing/browser/testResultsView/testResultsViewContent.ts`, `src/vs/workbench/contrib/testing/browser/testingOutputPeek.ts`
- **Validation:** Use a test extension that reports a failed test with distinct concise and verbose diagnostics. Verify that the peek can switch both ways without rerunning the test, preserves full diagnostic content, and leaves existing single-message, structured-stack, and expected/actual diff presentations unchanged.
- **Behavior:**

  > A test extension can provide a concise failure explanation and fuller diagnostics for the same failure. Users can switch between them in the test peek without rerunning the test or losing the detailed information. Existing extensions that supply only one message retain their current behavior. Acceptance includes switching both ways on a long Java-style stack trace while preserving navigation and existing diff presentation.
- **Trace:**

  > TestMessage in src/vscode-dts/vscode.d.ts and ITestErrorMessage in src/vs/workbench/contrib/testing/common/testTypes.ts currently represent one message plus optional structured stackTrace data. TestResultsViewContent builds a message frame followed by structured call frames; testing.collapsePeekStack collapses those frames rather than selecting alternate message content. The testing configuration exposes no equivalent verbosity control. This establishes a remaining gap, but does not settle whether the contract should support arbitrary alternate messages or specifically filtered stack traces. Preserve existing single-message, diff, and stack navigation behavior. Related https://github.com/microsoft/vscode/issues/195920 concerns a separate multiline diff-message presentation problem, not this switch.
- **Open decisions:**
  - Should concise/verbose mode select arbitrary extension-authored message variants, or be limited to filtered versus complete structured stack traces?
  - Which mode should appear initially, and should a user's selection persist across failures or remain local to the displayed message?
