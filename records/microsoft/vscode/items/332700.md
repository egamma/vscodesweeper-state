# Issue #332700 — Copilot AH should not access files in non-trusted folders

[https://github.com/microsoft/vscode/issues/332700](https://github.com/microsoft/vscode/issues/332700)

## Summary

Keep open for human handling: this team-authored report concerns a workspace-trust boundary and is therefore protected as security-sensitive. Current main forwards VS Code's trusted-folder state to Agent Host, but the Copilot session launch path does not apply that state when enabling SDK configuration discovery.

## Change summary

Prevent Copilot Agent Host sessions from discovering or reading customization files in folders that VS Code has not trusted.

## Best solution

Make Copilot SDK session creation honor VS Code Workspace Trust, using session-scoped trust for an eligible working directory and excluding untrusted ancestor, sibling, and additional-root customizations. Coordinate the remaining multi-root and runtime trust-escalation contract work with https://github.com/microsoft/vscode/issues/336425.
