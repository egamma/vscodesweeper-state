# Issue #297342 — completion speculative request never causes an NES speculative request

[https://github.com/microsoft/vscode/issues/297342](https://github.com/microsoft/vscode/issues/297342)

## Summary

Keep open: current source still separates completion speculation from NES speculation, and the request to bridge or replace those paths needs a product decision. The related completion-cache report describes a different symptom, not a verified duplicate.

## Change summary

Allow speculation after a displayed completion to anticipate NES edits, including distant edits, rather than stopping at an empty speculative completion.

## Best solution

Define whether completion-triggered speculation should use NES directly or retain completion speculation with an NES fallback, then support the chosen behavior in the inline-suggestion pipeline. Preserve ordinary completion behavior and avoid redundant speculative requests.
