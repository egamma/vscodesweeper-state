# Issue #341177 — Respect Copilot CLI's enabled/disabled state for plugins discovered from ~/.copilot/installed-plugins/

[https://github.com/microsoft/vscode/issues/341177](https://github.com/microsoft/vscode/issues/341177)

## Summary

Keep open for the remaining user-settings integration: current main already inherits disabled state from installedPlugins in ~/.copilot/config.json, but the discovery path does not read enabledPlugins in ~/.copilot/settings.json. The existing implementation therefore covers part, not all, of the request.

## Change summary

Use Copilot CLI's user-level plugin enablement as the default for CLI-discovered plugins while preserving explicit VS Code overrides.

## Best solution

Complete user-level enablement inheritance in the workbench plugin discovery service, preserving explicit VS Code decisions and enterprise policy. Establish precedence between settings.json and legacy config.json state without reopening the separately tracked repository-settings work.
