# Issue #339041 — The `preserveInput` options are not working

[https://github.com/microsoft/vscode/issues/339041](https://github.com/microsoft/vscode/issues/339041)

## Summary

Confirmed on main: the preserveInput settings only restore the last *accepted* (Enter/selected) filter value, never the value typed before dismissing the quick pick by clicking away — which is exactly the reported repro.

## Change summary

With workbench.commandPalette.preserveInput / workbench.quickOpen.preserveInput / search.quickAccess.preserveInput enabled, typed text is not restored if the picker is closed by losing focus instead of accepting.

## Best solution

In QuickAccessController (src/vs/platform/quickinput/browser/quickAccess.ts), also capture the typed value when the picker hides without an accept (not only in the onDidAccept listener), so lastAcceptedPickerValues reflects the last typed text regardless of how the picker was dismissed.

- **Behavior:**

  > When a quick access provider reports `defaultFilterValue === DefaultQuickAccessFilterValue.LAST` (driven by workbench.commandPalette.preserveInput / workbench.quickOpen.preserveInput / search.quickAccess.preserveInput), the last typed filter text must be restored the next time that same quick access is opened, regardless of whether the previous session ended by accepting an item or by the picker losing focus/being dismissed. Acceptance: type text, dismiss without accepting (e.g. click away or Escape), reopen — the text reappears, matching today's behavior when accepting with Enter.
- **Trace:**

  > QuickAccessController.registerPickerListeners (src/vs/platform/quickinput/browser/quickAccess.ts) only writes `this.lastAcceptedPickerValues.set(descriptor, picker.value)` inside a `picker.onDidAccept` callback (~lines 230-234); the `Event.once(picker.onDidHide)` handler in doShowOrPick (~lines 151-161) tears down disposables/cancels the token but never touches `lastAcceptedPickerValues`. `defaultFilterValue` consumers (CommandsQuickAccessProvider.defaultFilterValue in workbench/contrib/quickaccess/browser/commandsQuickAccess.ts, AnythingQuickAccessProvider.defaultFilterValue in workbench/contrib/search/browser/anythingQuickAccess.ts, and the text search quick access) all read from this same map. The boundary: do not change behavior when `preserveInput` is off (defaultFilterValue undefined) or when a value IS accepted — only extend the capture to the hide-without-accept path, and keep in mind cases where the picker closes with the value equal to the bare prefix (e.g. empty input) which arguably should not overwrite a prior good value — that choice is left to the implementer.
