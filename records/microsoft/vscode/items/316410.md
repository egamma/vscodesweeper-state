# Issue #316410 — Implement a policy-settings mechanism for approving/blocking agent market-places

[https://github.com/microsoft/vscode/issues/316410](https://github.com/microsoft/vscode/issues/316410)

## Summary

Already implemented on main: two enterprise policies now cover this use case — `ChatExtraMarketplaces` (add enterprise-managed marketplaces via policy) and `ChatStrictMarketplaces` (allowlist that restricts which marketplace sources are trusted). Both were added after this issue was filed.

## Change summary

Add an enterprise policy mechanism for controlling which agent plugin marketplaces VS Code loads from.

## Best solution

Keep the shipped policies (`ChatExtraMarketplaces` for additive enterprise marketplaces, `ChatStrictMarketplaces` for restrictive allowlisting). The reporter's use case — restricting plugin discovery to approved org registries — is directly served by `ChatStrictMarketplaces`.

- **Proposed comment:**

  > Thanks for the detailed request. This is now covered on current `main` — two enterprise policies were added in https://github.com/microsoft/vscode/commit/b24c5e38423 (PR #318623, shipping from VS Code 1.122):
  > 
  > - **`ChatExtraMarketplaces`** — adds enterprise-managed marketplace entries (unioned with `chat.plugins.marketplaces`), so you can push your org's registries via policy without touching user settings.
  > - **`ChatStrictMarketplaces`** — an allowlist: when set, only marketplaces matching an entry are trusted; an empty array blocks all marketplaces entirely.
  > 
  > Together these cover your use case of restricting agent plugin discovery to approved org sources. The existing `ChatEnabledPlugins` policy also provides per-plugin enable/disable control.
  > 
  > Please open a new issue if the shipped policies don't fully cover your scenario.
