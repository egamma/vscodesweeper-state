# Issue #337891 — Agents Customization window: Improve UX for configuring plugin enabled/disabled state across global and workspace scope

[https://github.com/microsoft/vscode/issues/337891](https://github.com/microsoft/vscode/issues/337891)

## Summary

Current main already offers scope-specific enablement actions and scope-aware labels, but the inline switch remains binary and cannot select all requested states from one control. Keep this open as a UX feature request; the related issues examined do not establish an older canonical with the same observable problem.

## Change summary

Provide one plugin control that distinguishes enabled, workspace-disabled, and globally-disabled states and lets users select their scope explicitly.

## Best solution

Make effective plugin enablement and its scope understandable and selectable together in the shared customizations UI. A maintainer should decide the interaction model while preserving existing workspace-enable overrides, profile semantics, and organization-managed states rather than assuming three states cover the complete model.
