# Issue #337891 — Agents Customization window: Improve UX for configuring plugin enabled/disabled state across global and workspace scope

[https://github.com/microsoft/vscode/issues/337891](https://github.com/microsoft/vscode/issues/337891)

## Summary

Much of the underlying ask is already shipped: the plugin enablement model is a real four-state model (EnabledProfile/DisabledProfile/EnabledWorkspace/DisabledWorkspace) and the UI already surfaces scope via a status badge ("Included/Excluded from Workspace" vs "...for Profile") and scope-aware aria labels/tooltips on the toggle. What remains is a specific visual-design ask (fold that distinction into the toggle control itself as a true three-state switch) rather than a missing capability, so it's a design call, not a gap in function.

## Change summary

Replace the binary enable/disable toggle for plugins in the Agents Customization window with a three-state control that visually distinguishes enabled, workspace-disabled, and globally-disabled.

## Best solution

Have the Chat Customizations editor owners decide whether the existing badge-text + tooltip scope indicator (src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationPresentation.ts `getPluginInclusionLabel`) is sufficient, or whether the toggle itself in pluginListWidget.ts should be redesigned as a visual three-state control (and, for consistency, whether the same should apply to mcpListWidget.ts, which shares the same ContributionEnablementState model).
