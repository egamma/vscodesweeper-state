# Issue #327404 — Workspace agent plugin recommendations are ignored in VS Code

[https://github.com/microsoft/vscode/issues/327404](https://github.com/microsoft/vscode/issues/327404)

## Summary

Real, source-verified bug already correctly labeled bug + agent-plugins: two separate defects explain both symptoms — `directory`-sourced workspace marketplaces aren't parsed at all, and the built-in `awesome-copilot` marketplace has no short display name, so `enabledPlugins` keys referencing it as `@awesome-copilot` never match. Keeping open for a maintainer/area owner to design the fix.

## Change summary

Workspace `enabledPlugins`/`extraKnownMarketplaces` recommendations (both a local `directory`-source marketplace and the built-in `awesome-copilot` marketplace) never surface under `@agentPlugins @recommended`.

## Best solution

Two fixes needed in src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts and src/vs/base/common/managedSettings.ts: (1) add `directory`/`file` source support to `parseMarketplaceObjectEntry` and `IExtraKnownMarketplaceEntry` (currently only `github`/`git` are handled, so a `directory` entry silently returns `undefined` and is dropped), and (2) give the default `chat.plugins.marketplaces` entries a resolvable short name (or teach `enabledPlugins` key matching to accept the short marketplace name) so `plugin@awesome-copilot` matches `github/awesome-copilot#marketplace`, whose `displayLabel` is the full raw shorthand today.

  > 
  > 1. **Local `directory` marketplaces are unsupported.** `parseMarketplaceObjectEntry` (marketplaceReference.ts) and the underlying `IExtraKnownMarketplaceEntry` type (managedSettings.ts) only handle `source: 'github'` and `source: 'git'`.   > 
  > Both would need design work (directory-source resolution/trust semantics, and a naming scheme for default marketplaces) rather than a one-line fix. Leaving this open under `agent-plugins` for an owner to pick up.

## Evidence

- **directory source unsupported:** src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts `parseMarketplaceObjectEntry` only handles `sourceType === 'github'` or `'git'` — a `{source: 'directory', path: '.'}` entry falls through and returns `undefined`, so `parseExtraMarketplaces` in workspacePluginSettingsService.ts silently drops it (logs 'Could not parse marketplace reference').
- **policy type also lacks directory:** src/vs/base/common/managedSettings.ts `IExtraKnownMarketplaceEntry` union only has `github`/`git` variants; `directory` only appears as an allowed source in the unrelated `IStrictMarketplaceSource` (strictKnownMarketplaces allowlist), not in the entry format used for `extraKnownMarketplaces`.
- **default marketplace name mismatch:** chat.shared.contribution.ts line ~1292 defines `chat.plugins.marketplaces` default as plain strings `['github/copilot-plugins', 'github/awesome-copilot#marketplace']` with no `name`; parseMarketplaceReference sets `displayLabel: rawValue`, so `plugin.marketplace` becomes the literal string `github/awesome-copilot#marketplace`, not `awesome-copilot` — confirmed by pluginMarketplaceService.test.ts using `parseMarketplaceReference('github/awesome-copilot#marketplace')` throughout. `recommendedPlugins`/`@recommended` matching in agentPluginsView.ts builds keys as `${marketplace.name}@${marketplace.marketplace}`, so a workspace key of `plugin@awesome-copilot` can never match.
- **notification path also depends on this:** claudePluginRecommendations.ts `_checkForRecommendedPlugins` builds `knownKeys` from fetched marketplace plugins using the same `plugin.marketplace` field, so the same mismatch also explains why no notification appears.
