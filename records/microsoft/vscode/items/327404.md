# Issue #327404 — Workspace agent plugin recommendations are ignored in VS Code

[https://github.com/microsoft/vscode/issues/327404](https://github.com/microsoft/vscode/issues/327404)

## Summary

The defect is traceable on current main: workspace recommendations are read, but the supplied local marketplace source is discarded and the public marketplace recommendation uses an identity that cannot match the default marketplace entry.

## Change summary

Workspace `enabledPlugins` entries from `.github/copilot/settings.json` do not surface as recommended agent plugins.

## Best solution

Resolve recommendation IDs against stable marketplace names or aliases, support documented workspace-relative directory marketplaces, and ensure one invalid marketplace cannot suppress otherwise valid recommendations. Add coverage for the exact mixed local-and-public configuration.

## Evidence

- **workspace settings reader:** src/vs/workbench/contrib/chat/common/plugins/workspacePluginSettingsService.ts reads `enabledPlugins` and `extraKnownMarketplaces` from `.github/copilot/settings.json`, confirming this is an intended core path.
- **directory source unsupported:** src/vs/workbench/contrib/chat/common/plugins/marketplaceReference.ts:106-135 parses object-form marketplaces only for `github` and `git`; the reported nested `source: "directory"` entry returns undefined and is ignored.
- **public recommendation identity mismatch:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts configures the default marketplace as `github/awesome-copilot#marketplace`. marketplaceReference.ts preserves that raw value as `displayLabel`, while agentPluginsView.ts:446-452 requires an exact `<plugin>@<displayLabel>` match, so `testing-automation@awesome-copilot` cannot match.
- **feature history:** Workspace recommendation support originated in commit 2ecee7ee916ff73615b552ef35f49b45a09a3582; current main still contains the mismatching paths and no fixing change was found.
