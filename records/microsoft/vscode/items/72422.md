# Issue #72422 — [folding] selecting first line of folded range does not select full folded range

[https://github.com/microsoft/vscode/issues/72422](https://github.com/microsoft/vscode/issues/72422)

## Summary

Consolidate the folded-line selection request into the older, open canonical issue. Both describe selecting a folded header without selecting its hidden contents; the later Enter-key discussion is separately tracked.

## Change summary

Selecting the full header line of a collapsed array should include its hidden contents so copying captures the whole array.

## Best solution

Track full-fold selection in https://github.com/microsoft/vscode/issues/59657, preserving this report's array-copy example and related copy/move reports. Keep the distinct Enter-at-end-of-header behavior tracked in https://github.com/microsoft/vscode/issues/91600.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/59657 is OPEN and was created on 2018-09-28, before this report's 2019-04-16 creation. Its reproduction selects a folded line through the margin and obtains only the first line rather than the whole fold—the same observable selection failure underlying this report's incomplete array copy.
- **Maintainer intent:** The supplied 2019-04-17 comment explicitly calls current behavior intentional but retains the requested improvement for votes. In https://github.com/microsoft/vscode/issues/59657#issuecomment-426187734, the folding maintainer likewise acknowledges selecting the full folded range through the line number. This supports feature-request classification and consolidation, not an as-designed decline.
- **Existing capability does not satisfy the request:** In src/vs/editor/common/cursor/cursorMoveCommands.ts, CursorMoveCommands.line initially selects through position.lineNumber + 1, while expandLineSelection also advances by model line rather than the collapsed range. In src/vs/editor/common/viewModel/viewModelImpl.ts, getPlainTextToCopy copies nonempty model ranges with model.getValueInRange without extending them over folded content. Selecting through the next visible line remains a workaround, not automatic full-fold selection.
- **Preserve copy and move evidence:** https://github.com/microsoft/vscode/issues/90427#issuecomment-587011376 and https://github.com/microsoft/vscode/issues/93832#issuecomment-606479356 explicitly consolidate related move/delete reports into this issue; https://github.com/microsoft/vscode/issues/146884#issuecomment-1090068669 does the same for copying. These are useful supporting examples to retain when consolidating into the older canonical.
- **Distinct follow-up already tracked:** https://github.com/microsoft/vscode/issues/91600 remains OPEN and specifically covers pressing Enter at the end of a folded header inserting inside and expanding the fold. Its discussion distinguishes cursor placement from line selection, so this later comment does not require keeping a second full-fold selection issue open.
