# Issue #329475 — Allow a workspace to opt out of user-level MCP servers for reproducible AI environments

[https://github.com/microsoft/vscode/issues/329475](https://github.com/microsoft/vscode/issues/329475)

## Summary

Reasonable parity request (MCP lacks the workspace-only opt-out that agents/skills/instructions/hooks already have via their *Locations settings), and the author has already opened an implementation PR — keep open for review of that PR rather than closing.

## Change summary

Add a way for a workspace to exclude user-level MCP servers from resolution, mirroring the workspace-only *Locations pattern used for chat.agentFilesLocations, chat.agentSkillsLocations, chat.instructionsFilesLocations, and chat.hookFilesLocations.

## Best solution

Review and land (or iterate on the naming/shape of) the author's own PR https://github.com/microsoft/vscode/pull/329478, which proposes a `chat.mcp.userServersEnabled`-style setting; a maintainer who owns MCP settings should weigh in on naming before merge.
