# Issue #329475 — Allow a workspace to opt out of user-level MCP servers for reproducible AI environments

[https://github.com/microsoft/vscode/issues/329475](https://github.com/microsoft/vscode/issues/329475)

## Summary

Genuine, currently-unimplemented gap: there is no way for a workspace to bulk-exclude user-level MCP servers, unlike the parity already shipped for agents/skills/instructions/hooks via their *Locations settings. Discussion is active and productive (a maintainer and the reporter are converging on a design), and an open PR already targets part of this, so this should stay open rather than be closed.

## Change summary

Add a workspace-level way to opt out of user-scope MCP servers, mirroring the *Locations resolution pattern used for agents/skills/instructions/hooks.

## Best solution

Let this play out as an active design discussion: PR https://github.com/microsoft/vscode/pull/329478 covers only the Local harness (filtering in McpWorkbenchService.getEnabledLocalMcpServers()); the AH-based harnesses (Copilot/Claude/Codex) need a workspace-scope decision expressed at the new enablement gate from PR https://github.com/microsoft/vscode/pull/330566 (src/vs/platform/agentHost/node/shared/customizationEnablementGate.ts / agentHostCustomizationEnablementService.ts), which currently resolves session>workspace>global per individual server but has no bulk 'exclude all user-scope servers' decision yet.
