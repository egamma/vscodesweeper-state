Existing Local and Copilot session-management behavior must remain unchanged.
- **Trace:**

  > DeleteAgentSessionAction in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts already exposes Delete for agent-host session items and calls AgentHostSessionListController.deleteChatSessionItem through the chat sessions service. The Agents-window action in sessionsViewActions.ts is capability-gated, and BaseAgentHostSessionsProvider.deleteSessions calls connection.disposeSession. AgentService performs provider teardown and durable registry tombstoning; ClaudeAgent._disposeChat drops runtime/backing state while retaining native transcripts, whereas the SDK deleteSession API is already used by truncation. This establishes menu availability for the agent-host path, not completion across every originally reported session surface. Related reports https://github.com/microsoft/vscode/issues/313072 and https://github.com/microsoft/vscode/issues/325673 describe distinct historical failures, and current tombstoning means their symptoms cannot be assumed unchanged. Preserve provider-neutral orchestration, non-destructive idle release, and existing session identities; planning should first establish remaining surface coverage and the native-transcript contract.
- **Open decisions:**
  - Should Delete permanently remove the underlying Claude SDK transcript, including transcripts created outside VS Code, or durably remove only the VS Code session entry?
