# Issue #187440 — F5 starts debugging when inactive, but refreshes the page when active

[https://github.com/microsoft/vscode/issues/187440](https://github.com/microsoft/vscode/issues/187440)

## Summary

The bug remains present on current main: VS Code claims F5 only while debugging is inactive or stopped, so during running or initializing states the web keybinding service leaves the event to the browser, which can reload the page and terminate the session.

## Change summary

Keep F5 from refreshing the browser while a web debug session is running or initializing.

## Best solution

Ensure the web workbench consumes F5 throughout an active debug session while preserving its existing Start behavior when inactive and Continue behavior when stopped.

- **Trace:**

  > The debug state key is defined in src/vs/workbench/contrib/debug/common/debug.ts with inactive, initializing, stopped, and running values. In src/vs/workbench/contrib/debug/browser/debugCommands.ts, CONTINUE_ID claims F5 only for stopped and DEBUG_START_COMMAND_ID claims it only for inactive, leaving running and initializing unmatched. AbstractKeybindingService returns false for an unmatched key, and WorkbenchKeybindingService consequently does not call preventDefault(), allowing the browser refresh. The maintainer reached the same diagnosis in https://github.com/microsoft/vscode/issues/187440#issuecomment-1709348279. ## Evidence

- **current source:** src/vs/workbench/contrib/debug/browser/debugCommands.ts registers F5 for workbench.action.debug.start only when debugState == 'inactive' and for workbench.action.debug.continue only when debugState == 'stopped'; there is no F5 rule for 'running' or 'initializing'.
- **browser behavior:** src/vs/platform/keybinding/common/abstractKeybindingService.ts returns false for a keypress with no matching keybinding, and src/vs/workbench/services/keybinding/browser/keybindingService.ts calls preventDefault() only when dispatch returns true. Thus F5 reaches the browser in the uncovered debug states.
- **maintainer diagnosis:** The maintainer confirmed the state gap and suggested consuming F5 in the remaining states: https://github.com/microsoft/vscode/issues/187440#issuecomment-1709348279.
- **canonical search:** No open issue found by the F5/web-refresh/debug searches owns this same observable symptom. https://github.com/microsoft/vscode/issues/181792 is closed and concerns F10 Step Over behavior, not F5 reloading during an active session.
