# Issue #181566 — 'Switch Output' dropdown closes when a new item is added

[https://github.com/microsoft/vscode/issues/181566](https://github.com/microsoft/vscode/issues/181566)

## Summary

The confirmed defect remains present on current main: adding an output channel refreshes the panel toolbar, which disposes the open select view item and closes its dropdown. This should remain open in the Backlog for an action-bar lifecycle fix.

## Change summary

Keep the Switch Output dropdown open and update its choices when extensions register new output channels.

## Best solution

Toolbar action updates should preserve compatible action view items and their transient UI state while updating their actions, so a newly registered output channel appears without closing the open selector.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/actionbar/actionbar.ts`, `src/vs/base/browser/ui/toolbar/toolbar.ts`, `src/vs/platform/actions/browser/menuEntryActionViewItem.ts`, `src/vs/base/test/browser/ui/toolbar/toolbar.test.ts`
- **Validation:** Add a toolbar browser test that opens a stateful selection view item, updates the action collection with the same selection action plus a new option, and verifies that the view item is not disposed, the dropdown remains open, and the new option is available; then manually repeat the issue steps with an extension registering an output channel.
- **Behavior:**

  > While the Switch Output dropdown is open, registering another output channel must not close it. The new channel must become available without losing focus or the current selection, and selecting existing or newly added channels must continue to switch output normally. Other toolbar additions, removals, reordering, overflow behavior, and context-key updates must continue to render correctly.
- **Trace:**

  > OutputContribution in src/vs/workbench/contrib/output/browser/output.contribution.ts registers one submenu action per output channel and adds more from IOutputChannelRegistry.onDidRegisterChannel. The resulting title-action update reaches CompositePart.collectCompositeActions in src/vs/workbench/browser/parts/compositePart.ts and WorkbenchToolBar.setActions. ToolBar.setActions in src/vs/base/browser/ui/toolbar/toolbar.ts unconditionally calls clear(), while ActionBar.clear in src/vs/base/browser/ui/actionbar/actionbar.ts disposes every view item; disposal of SubmenuEntrySelectActionViewItem and its SelectBox closes the context view. The issue comments confirm this exact stack on https://github.com/microsoft/vscode/issues/181566#issuecomment-1569882918 and identify the shared action-bar lifecycle as the root cause at https://github.com/microsoft/vscode/issues/181566#issuecomment-1571779264. The boundary is shared toolbar reconciliation: preserve existing behavior for genuinely removed, replaced, reordered, hidden, and overflowed actions rather than special-casing the Output view.

## Evidence

- **confirmed diagnosis:** The maintainer trace at https://github.com/microsoft/vscode/issues/181566#issuecomment-1569882918 shows that output-channel registration reaches ToolBar.setActions, disposes the select action view item, and hides the custom dropdown.
- **maintainer assessment:** https://github.com/microsoft/vscode/issues/181566#issuecomment-1571779264 confirms this as an old action-bar bug: action changes dispose every view item rather than applying a minimal collection diff.
- **current source:** src/vs/workbench/contrib/output/browser/output.contribution.ts dynamically adds Switch Output submenu actions in onDidRegisterChannel; src/vs/workbench/browser/parts/compositePart.ts calls WorkbenchToolBar.setActions after title-action updates.
- **current disposal path:** On current main, src/vs/base/browser/ui/toolbar/toolbar.ts begins every setActions call with clear(), and src/vs/base/browser/ui/actionbar/actionbar.ts clear() disposes all view items. The selection submenu is still a SubmenuEntrySelectActionViewItem backed by a disposable SelectBox in src/vs/platform/actions/browser/menuEntryActionViewItem.ts.
- **canonical search:** Searches for open issues describing an output dropdown closing when menu items or output channels change found no older issue with the same reporter-observable symptom.
