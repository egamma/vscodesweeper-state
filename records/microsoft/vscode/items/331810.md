# Issue #331810 — Remote Tunnel Access is broken

[https://github.com/microsoft/vscode/issues/331810](https://github.com/microsoft/vscode/issues/331810)

## Summary

The reporter's log directly shows the bundled code-tunnel.exe rejecting `--user-data-dir` for the plain `tunnel` command, which the editor's TunnelProcessCoordinator unconditionally passes — this is a confirmed failure in the shipped 1.134.0 build, not a vague report.

## Change summary

Enabling Remote Tunnel Access fails to start because code-tunnel.exe rejects the `--user-data-dir` argument the editor passes, expecting `--server-data-dir` instead.

## Best solution

Reconcile the args the editor passes in src/vs/platform/remoteTunnel/node/tunnelProcessCoordinator.ts (lines ~315-320, which push `--user-data-dir`) against what the release-built code-tunnel CLI actually accepts for the top-level `tunnel` command; on current main source, cli/src/commands/args.rs already defines a hidden `user_data_dir` field on `TunnelServeArgs` (flattened into `TunnelArgs`), so this looks like a version-skew between the shipped 1.134.0 CLI binary and the editor's newer spawn args rather than a permanent design gap — worth confirming the CLI/editor build pairing for 1.134.0 and whether a hotfix CLI needs to reship.
