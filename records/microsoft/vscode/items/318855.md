# Issue #318855 — Chat session observation API for extension-owned evaluation and tooling

[https://github.com/microsoft/vscode/issues/318855](https://github.com/microsoft/vscode/issues/318855)

## Summary

Valid feature request from a team member for a read-only chat session observation API. No such API exists on main — the existing surfaces (`chatSessionsProvider`, `chatParticipantPrivate`) cover the provider/write side and limited active-session signals, but not session enumeration, structured history reads, or lifecycle events for third-party extensions. Keeping open for API design discussion.

## Change summary

Extensions need a supported read-only API to enumerate chat sessions, read structured history, and observe session lifecycle events, instead of parsing private JSONL storage.

## Best solution

Design and ship a proposed API surface (likely a new `vscode.proposed.chatSessionObserver.d.ts`) that complements the existing `chatSessionsProvider` (write/provider side) with a read/observer side: session enumeration, structured history access via `ChatRequestTurn`/`ChatResponseTurn`, and create/change/end lifecycle events. The implementation would live in `src/vs/workbench/api/` (extHost + mainThread chat modules). Route to the chat/AI area owner for API design review.
