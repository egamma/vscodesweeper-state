# Issue #325506 — Markdown editor association is ignored when opening an .md file from Windows Explorer on cold startup

[https://github.com/microsoft/vscode/issues/325506](https://github.com/microsoft/vscode/issues/325506)

## Summary

Plausible timing/race bug where the custom Markdown preview editor association isn't honored for a file opened from Windows Explorer on a cold VS Code start, but works once the window is already running; a second user independently confirmed the same symptom, and I couldn't fully pin the root cause without running the app.

## Change summary

workbench.editorAssociations pointing *.md to vscode.markdown.preview.editor is ignored when a .md file is double-clicked in Explorer while no VS Code instance is running, but is honored once a window is already open.

## Best solution

Investigate whether the editor-resolver/custom-editor registration (src/vs/workbench/services/editor/browser/editorResolverService.ts, src/vs/workbench/contrib/customEditor/browser/customEditors.ts) races with extension-host startup/extension-point parsing when the initial file-to-open comes from the OS shell on a cold launch, versus the already-running-window path in src/vs/workbench/electron-browser/window.ts (onOpenFiles); a maintainer with a running repro would need to confirm the exact race.
