# Issue #329777 — Debug: "Add to Chat" on a stack frame with column 0 (per-spec "unknown") corrupts Range and permanently poisons the chat session

[https://github.com/microsoft/vscode/issues/329777](https://github.com/microsoft/vscode/issues/329777)

## Summary

Traced the reported defect conclusively on current main: raw DAP `column: 0` (a spec-defined 'unknown, should be ignored' sentinel) flows unvalidated into an editor `Range`, and later conversion to a `vscode.Position` (0-based) throws on the resulting negative character, poisoning the whole chat session for every subsequent turn.

## Change summary

Add-to-Chat on a debug stack frame with DAP column 0 builds an invalid Range whose 0-based conversion throws, breaking all future chat turns in the session.

## Best solution

In Thread.getCallStackImpl() (src/vs/workbench/contrib/debug/common/debugModel.ts) clamp/normalize a spec-legal column:0 (and line:0) to a safe 1-based value before constructing the Range, and/or harden createPausedLocationEntry() in debugChatIntegration.ts to guard startColumn < 1 the same way it already guards an empty range.
