# Issue #323244 — Version mismatch between API and downloaded version

[https://github.com/microsoft/vscode/issues/323244](https://github.com/microsoft/vscode/issues/323244)

## Summary

This is a scripting/API interpretation question rather than a VS Code defect. The script takes the first version in the raw Marketplace response, while VS Code deliberately selects the newest stable version compatible with the current platform and VS Code engine.

## Change summary

Determine and install the newest extension version that VS Code can use, rather than comparing against the first version returned by the raw Marketplace API.

## Best solution

Use the supported `code --update-extensions` command, which performs the compatibility and release-channel filtering, instead of parsing the first `version` field from the Marketplace response.

## Evidence

- **CLI behavior:** src/vs/platform/extensionManagement/common/extensionManagementCLI.ts implements `updateExtensions()` by querying the gallery with `{ compatible: true }`, then installs only a newer compatible result; src/vs/code/node/cliProcessMain.ts exposes this as `code --update-extensions`.
- **installation filtering:** src/vs/platform/extensionManagement/common/extensionManagementCLI.ts:getGalleryExtensions obtains the current target platform and passes it to the gallery query before installation.
- **gallery filtering:** src/vs/platform/extensionManagement/common/extensionGalleryService.ts:getValidRawGalleryExtensionVersionFromLatestVersions and `isValidVersion` distinguish release from pre-release versions and reject versions incompatible with the target platform or current VS Code engine.
- **reported script:** The issue's `grep -oP '"version":"\K[^"]+' | head -n 1` ignores Marketplace pre-release metadata, target-platform metadata, and `Microsoft.VisualStudio.Code.Engine`, so its `latest` value is not necessarily the version VS Code should install.
