# Issue #222202 — Support 'Panel position' setting under 'Customize layout' button

[https://github.com/microsoft/vscode/issues/222202](https://github.com/microsoft/vscode/issues/222202)

## Summary

This remains a real layout-polish gap on current main: Customize Layout offers panel visibility and alignment but not panel position, and its panel icon is fixed to the bottom-panel glyph. The related issue is younger and proposes relocating layout controls rather than the same picker behavior, so it does not meet the re-review duplicate bar.

## Change summary

Expose panel position in Customize Layout and make the panel visibility indicator reflect its current top, bottom, left, or right placement.

## Best solution

Choose a compact, keyboard-accessible presentation for the four panel positions, then ensure the picker communicates the active position and uses a panel visibility indicator consistent with that position without making the layout menu noisy.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/layoutActions.ts`, `src/vs/workbench/browser/parts/panel/panelActions.ts`
- **Validation:** Launch Code OSS and, using only the keyboard, open Customize Layout with the panel successively at top, bottom, left, and right; verify each position is selectable, the active state and accessible label are correct, the visibility indicator matches the current placement, and selecting an entry moves the panel without closing the picker unexpectedly.
- **Behavior:**

  > Customize Layout should make the panel's top, bottom, left, and right positions discoverable and selectable. It should accurately communicate the active position, and the panel visibility indicator should not imply a bottom panel when the panel is elsewhere. Existing panel visibility, alignment, reset, keyboard navigation, and screen-reader labeling must continue to work.
- **Trace:**

  > The picker is assembled by `CustomizeLayoutAction.getItems()` in src/vs/workbench/browser/actions/layoutActions.ts. It currently includes `ToggleVisibilityActions`, `MoveSideBarActions`, and `AlignPanelActions`; the Panel visibility row always uses the fixed `panelIcon`, although `PanelPositionContext` is already imported. The four underlying commands are registered from `PositionPanelActionConfigs` in src/vs/workbench/browser/parts/panel/panelActions.ts. The uncertainty starts at presentation: the maintainer comment at https://github.com/microsoft/vscode/issues/222202#issuecomment-2331225031 notes that four direct rows make the picker scroll and suggests a secondary “More...” surface, while also questioning the icon treatment. Keep panel alignment semantics and unrelated layout controls unchanged; https://github.com/microsoft/vscode/issues/232798 concerns relocating title-bar controls and is outside this bounded picker behavior.
- **Open decisions:**
  - Should all four panel positions appear directly in Customize Layout, accepting a taller or scrolling picker, or should they be revealed through a secondary “More...” entry?
  - Should the Panel visibility row use distinct location-aware on/off glyphs for all four positions, or should position be communicated separately while retaining one neutral panel glyph?

## Evidence

- **current source gap:** src/vs/workbench/browser/actions/layoutActions.ts defines `MoveSideBarActions` and `AlignPanelActions`, and `CustomizeLayoutAction.getItems()` exposes Primary Side Bar Position and Panel Alignment sections, but no panel-position section or position actions.
- **fixed icon:** src/vs/workbench/browser/actions/layoutActions.ts registers `panelIcon` from `Codicon.layoutPanel` and always passes that icon to the Panel visibility item; unlike the side bars, it does not select an icon from `PanelPositionContext`.
- **existing commands:** src/vs/workbench/browser/parts/panel/panelActions.ts already registers top, left, right, and bottom panel-position commands, so the missing behavior is primarily the Customize Layout presentation and state representation.
- **maintainer design question:** https://github.com/microsoft/vscode/issues/222202#issuecomment-2331225031 confirms interest but leaves an observable UX choice unresolved: four direct entries would make the picker scroll, while a “More...” entry could preserve its compact presentation; distinct top/on/off icon states may also be needed.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/232798 is open but was created after this issue and asks to relocate layout controls to their respective corners. It references this report's icon concern, but does not own the same Customize Layout picker request and cannot be its canonical under the re-review rule.
- **no implemented fix:** No commit referencing this issue was found, and current main still lacks panel-position entries in `CustomizeLayoutAction.getItems()`.
