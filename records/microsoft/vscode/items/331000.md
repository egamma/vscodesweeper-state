# Issue #331000 — Unable to return multiple window titles for windows across multiple screens / desktops

[https://github.com/microsoft/vscode/issues/331000](https://github.com/microsoft/vscode/issues/331000)

## Summary

This isn't a VS Code defect — it's an inherent limitation of Windows' single main-window-per-process model that PowerShell's `Get-Process`/`MainWindowTitle` relies on, and VS Code's multiple windows are top-level BrowserWindows under one process. Proposing to close as a support question, since there's no VS Code code path to fix.

## Change summary

Reporter wants to enumerate window titles for all open VS Code windows (across screens/virtual desktops) via PowerShell `Get-Process`, but only the most recently active window's title is returned.

## Best solution

Explain that Windows Explorer/.NET's `Process.MainWindowHandle`/`MainWindowTitle` only exposes one top-level window per process by design, and VS Code's multiple editor windows share a single Electron main process (confirmed in src/vs/platform/windows/electron-main/windowsMainService.ts, which opens each window as a separate electron.BrowserWindow under the same process). To enumerate all VS Code window titles, the reporter needs `EnumWindows`/`GetWindowThreadProcessId`-style enumeration rather than `Get-Process`, which is outside VS Code's control.

  > Thanks for the detailed report and for digging into this from the PowerShell side. This isn't a VS Code bug: on Windows, `Get-Process`/`.MainWindowTitle` only surfaces the single top-level window that .NET/Win32 associates with a process's main thread. VS Code's multiple windows (one per folder/workspace) are separate Electron `BrowserWindow`s running under the same Code.exe process, so `Get-Process` will only ever show you one of them via `MainWindowTitle` — that's the same limitation you found affects Firefox. To enumerate all of them you'd need lower-level window enumeration (e.g. `EnumWindows` + `GetWindowThreadProcessId`) rather than `Get-Process`, which is outside what VS Code can influence. Closing as a question since there's no code change on our side that would address this.

## Evidence
