# Issue #318208 — Files in files.exclude appear as untracked in the explorer

[https://github.com/microsoft/vscode/issues/318208](https://github.com/microsoft/vscode/issues/318208)

## Summary

Current main still gives Git's untracked decoration priority over the Explorer's excluded-item decoration, so an excluded-but-open file appears green instead of using the intended deemphasized styling.

## Change summary

Files matched by `files.exclude` appear with a green untracked Git decoration after being opened.

## Best solution

Preserve the intentional behavior of revealing an excluded file while it is open, but ensure its Explorer presentation remains deemphasized rather than being overridden by the Git untracked color; non-excluded Git decorations must remain unchanged.

## Evidence

- **source reproduction:** `FilesFilter.isVisible` in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` sets `stat.isExcluded = true` but deliberately returns visible for a matching visible editor. `provideDecorations` in `explorerDecorationsProvider.ts` then supplies `listDeemphasizedForeground` without a weight.
- **decoration precedence:** `src/vs/workbench/api/browser/mainThreadDecorations.ts` assigns extension-provided decorations weight 10, while `DecorationStyles.asDecoration` in `src/vs/workbench/services/decorations/browser/decorationsService.ts` sorts decorations by descending weight. The built-in Git extension supplies the untracked color through that extension-provider path, so it outranks the weight-0 Explorer deemphasis color.
- **intended behavior:** https://github.com/microsoft/vscode/issues/92090 documents the intended behavior: excluded files are temporarily shown while visible in an editor but use a dimmed color.
