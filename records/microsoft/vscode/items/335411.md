# Issue #335411 — Source Control Repositories view re-expands repositories with submodules on every visibility change

[https://github.com/microsoft/vscode/issues/335411](https://github.com/microsoft/vscode/issues/335411)

## Summary

Traced and confirmed on current main: the Repositories view discards the tree's live view state and unconditionally re-expands submodule parents on every visibility toggle, exactly as described — a real, localized bug worth fixing, and the reporter already has a patch ready.

## Change summary

In the SCM Repositories view (with submodules and single-selection mode), a manually collapsed parent repository re-expands every time the Source Control view container is hidden and shown again.

## Best solution

Fix `scmRepositoriesViewPane.ts`: capture `tree.getViewState()` on hide and reuse it as the input state on show (instead of the state loaded once in `renderBody`), and only expand a parent repository in `updateParentRepository` when it gains its first child, not on every re-registration via `onDidAddRepository`. The reporter has a patch ready — inviting them to open the PR is the fastest path.

## Evidence

- **stale view state reused on show:** src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts renderBody() loads `viewState` once via loadTreeViewState() and reuses that same captured `viewState` object in `tree.setInput(this.scmViewService, viewState)` inside the visibility-change handler every time the view becomes visible again — it is never refreshed from `tree.getViewState()` when the view hides.
