# Issue #335411 — Source Control Repositories view re-expands repositories with submodules on every visibility change

[https://github.com/microsoft/vscode/issues/335411](https://github.com/microsoft/vscode/issues/335411)

## Summary

Confirmed in source: the Repositories view collapse state for submodule parents can't stick because `renderBody` captures `viewState` once and reuses it on every `setInput` when the view becomes visible, while `onDidAddRepository`/`updateParentRepository` unconditionally re-expands the parent on every re-registration. This is a real, narrow bug worth fixing; the author says they have a patch ready.

## Change summary

In the SCM Repositories view, a collapsed parent repository with submodules re-expands every time the Source Control view container regains visibility, because parent expansion runs unconditionally on repository re-registration and the tree's view state isn't refreshed from the live tree before re-render.

## Best solution

Fix scmRepositoriesViewPane.ts: capture `tree.getViewState()` when the view is hidden (not just on `onWillSaveState`) and use that as the input state on re-show, and change `updateParentRepository` to only call `expand()` the first time a parent gains a child rather than on every re-registration/history-ref change. The author has offered a PR — a maintainer should invite and review it.
