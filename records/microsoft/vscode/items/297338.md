# Issue #297338 — Ctrl+scroll wheel zoom jumps around

[https://github.com/microsoft/vscode/issues/297338](https://github.com/microsoft/vscode/issues/297338)

## Summary

This remains a credible editor bug: the reporter supplied two recordings and another user confirmed similar Logitech-mouse behavior on macOS. Current main still routes wheel scrolling and mouse-wheel zoom through separate listeners on the same editor node, so the issue should remain open for diagnosis rather than being closed as non-reproducible.

## Change summary

Repeated Ctrl+wheel font zooming can cumulatively move the editor viewport, eventually jumping thousands of lines toward the top or bottom.

## Best solution

Ensure a wheel gesture handled as editor font zoom cannot also affect the editor scroll position, while preserving the visible document location across repeated zoom-in and zoom-out cycles.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/mouseHandler.ts`, `src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts`, `src/vs/editor/browser/view.ts`, `src/vs/editor/common/viewModel/viewModelImpl.ts`
- **Validation:** On a long file with editor.mouseWheelZoom enabled and a physical Logitech-style stepped wheel, start fully zoomed out, repeatedly zoom in three notches and zoom out more than three notches while holding Ctrl on Windows and Cmd on macOS, and verify the visible document location does not cumulatively drift or jump; ordinary unmodified wheel scrolling must remain unchanged.
- **Behavior:**

  > With editor.mouseWheelZoom enabled, a modified physical-wheel gesture changes editor font zoom without also scrolling or cumulatively displacing the visible document location. Repeated zoom-in and zoom-out cycles from the minimum zoom level must not jump toward either end of a long file. Unmodified wheel scrolling and trackpad zoom behavior must remain unchanged.
- **Trace:**

  > Current zoom handling is in MouseHandler._setupMouseWheelZoomListener in src/vs/editor/browser/controller/mouseHandler.ts. EditorScrollbar separately listens for wheel events on the same view DOM node in src/vs/editor/browser/viewParts/editorScrollbar/editorScrollbar.ts, and src/vs/editor/browser/view.ts constructs the scrollbar before PointerHandler. Zoom updates EditorZoom, recomputes editor options through src/vs/editor/browser/config/editorConfiguration.ts, and invokes stable-viewport recovery in ViewModel._onConfigurationChanged in src/vs/editor/common/viewModel/viewModelImpl.ts. The recordings and an independent macOS report confirm the observable defect, but source inspection alone does not distinguish ordinary wheel handling from viewport recovery as the dominant contributor. Keep the boundary to modified-wheel editor zoom and do not change normal scrolling, terminal zoom, or generic scrollbar behavior without separate evidence.

The hardware-dependent interaction among these paths remains unresolved on current main.
