# Issue #218210 — minimap does not show conflicting changes when the change are empty lines

[https://github.com/microsoft/vscode/issues/218210](https://github.com/microsoft/vscode/issues/218210)

## Summary

The bug remains visible in current source: empty merge-conflict regions are deliberately omitted from the decoration ranges that provide overview-ruler markers. The issue is already routed to the appropriate minimap area and should remain open.

## Change summary

Show the location of a merge conflict in the minimap or overview ruler when either side of the conflict contains no lines.

## Best solution

Represent every conflict side in the overview ruler even when its content range is empty, while avoiding an incorrect whole-line background on an adjacent conflict delimiter.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/mergeDecorator.ts`, `extensions/merge-conflict/src/mergeConflictParser.ts`
- **Validation:** Open a text fixture containing one conflict with an empty current side and another with an empty incoming side; verify that both locations appear in the minimap or overview ruler, delimiter lines retain their existing styling, and non-empty conflict decorations remain unchanged.
- **Behavior:**

  > A merge conflict remains discoverable in the minimap or overview ruler when its current or incoming side is empty. Empty current and empty incoming regions must both receive a visible location marker without coloring the wrong delimiter line. Existing backgrounds and markers for non-empty conflict regions must remain unchanged.
- **Trace:**

  > MergeConflictParser.scanItemTolMergeConflictDescriptor in extensions/merge-conflict/src/mergeConflictParser.ts creates an empty `decoratorContent` range when two relevant conflict delimiters are adjacent. MergeDecorator.applyDecorations in extensions/merge-conflict/src/mergeDecorator.ts filters out that range before calling `setDecorations`; the filtered decoration type is also where `overviewRulerColor` is configured. This conclusively preserves the reported omission on current main. The boundary is the built-in merge-conflict decoration path: conflict parsing, acceptance commands, non-empty region backgrounds, and delimiter styling must not change.
- **Open decisions:**
  - Which delimiter-adjacent line should anchor the marker for an empty current or incoming side?
  - Should empty-side overview markers use a separate decoration type so they do not apply the content decoration's whole-line background?

## Evidence

- **source-visible defect:** In extensions/merge-conflict/src/mergeDecorator.ts, MergeDecorator.applyDecorations only adds current, incoming, and common-ancestor content decorations when `decoratorContent.isEmpty` is false. Those same decoration types carry `overviewRulerColor`, so an empty side contributes no location marker.
- **empty-range construction:** extensions/merge-conflict/src/mergeConflictParser.ts constructs `decoratorContent` between each conflict delimiter and the following token; consecutive delimiters therefore produce the empty range rejected by MergeDecorator.
- **history and canonical search:** No commit referencing https://github.com/microsoft/vscode/issues/218210 or open canonical issue for empty merge-conflict minimap markers was found, and the skipping logic remains on current main.
