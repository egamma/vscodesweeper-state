# Issue #338242 — Thinking Effort selector caps at "High", missing `xhigh`/`max` supported by underlying models

[https://github.com/microsoft/vscode/issues/338242](https://github.com/microsoft/vscode/issues/338242)

## Summary

Already fixed and merged: PR #335276 (merged 2026-09-28) changed OpenRouterLMProvider.resolveModelCapabilities to derive the supported-effort list from the model's own `reasoning.supported_efforts` (falling back to low/medium/high only when the model omits it) instead of always hard-coding three tiers, and to forward `reasoning.default_effort`. Current main's openRouterProvider.ts already contains exactly this logic.

## Change summary

The BYOK Thinking Effort dropdown for OpenRouter-hosted models (e.g. GPT-6 Luna Pro, Claude Opus 5.5) only ever offered Low/Medium/High, never surfacing the xhigh/max tiers those models actually support.

## Best solution

Keep the shipped fix in extensions/copilot/src/extension/byok/vscode-node/openRouterProvider.ts (merge commit 9ae5e965fdd41026cd7bb60f232a339ea3c61761, PR #335276) — no further change needed; confirm on the latest Insiders/stable build.
