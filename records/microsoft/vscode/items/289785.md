# Issue #289785 — Search result navigation does not provide target selection/range to custom editors (webview editors)

[https://github.com/microsoft/vscode/issues/289785](https://github.com/microsoft/vscode/issues/289785)

## Summary

Valid feature request: the custom editor resolve path (`$resolveCustomEditor`) has no mechanism to pass selection/range info from search result navigation. No fix or API extension has landed on main. The gap is real and still needs design/implementation.

## Change summary

Clicking a search result that opens in a custom editor does not communicate the match location (line/column/range) to the custom editor provider.

## Best solution

Extend the custom editor resolve protocol to pass selection/range context when the editor is opened with a target location (e.g. from search results). This likely involves adding an options parameter to `$resolveCustomEditor` in the ext-host protocol and surfacing it through a new or extended API on `CustomTextEditorProvider`/`CustomEditorProvider`. The work spans `src/vs/workbench/api/common/extHostCustomEditors.ts` and the main-thread custom editor input/contribution.
