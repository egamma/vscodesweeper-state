# Issue #315405 — Copilot CLI session provider keeps refreshing/logging when CLI is disabled by org policy

[https://github.com/microsoft/vscode/issues/315405](https://github.com/microsoft/vscode/issues/315405)

## Summary

Valid bug: when Copilot CLI is disabled by org policy (403), the CopilotCLIChatSessionContentProvider continues refreshing and logging `listSessions` entries with no short-circuit. No fix has landed on main.

## Change summary

The Copilot CLI session provider keeps refreshing and emitting info-level `listSessions` log entries even after the feature is known to be unauthorized due to org policy.

## Best solution

After the initial 403 from model-fetch, the `refreshSessions` path in `CopilotCLIChatSessionContentProvider` (in both `copilotCLIChatSessions.ts` and `copilotCLIChatSessionsContribution.ts`) should check the entitlement/authorization state and bail out early — suppressing both the repeated `getAllSessions` calls and the info-level log line. The guard could key off the same entitlement signal that surfaces the 403 in `CopilotCLISession.fetchModels`.
