# Issue #315405 — Copilot CLI session provider keeps refreshing/logging when CLI is disabled by org policy

[https://github.com/microsoft/vscode/issues/315405](https://github.com/microsoft/vscode/issues/315405)

## Summary

Keep open: both current CLI session-provider implementations still emit the reported info-level timing message without consulting model-fetch authorization failures. Provider registration has evolved since the report, but the supplied policy-disabled account steps suffice to retest; no verified fix or canonical duplicate was found.

## Change summary

Avoid repeated CLI session-refresh work and routine info-level logging when Copilot CLI is unavailable because of organization policy.

## Best solution

Make the built-in CLI integration handle confirmed feature unavailability without repeated background noise, while preserving normal Copilot Chat and recovery after account or policy changes. Establish whether existing local session history should remain accessible before deciding to hide or disable the provider.
