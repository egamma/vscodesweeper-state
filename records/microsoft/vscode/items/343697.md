# Issue #343697 — DiffEditorWidget.setModel never disposes the view model it creates

[https://github.com/microsoft/vscode/issues/343697](https://github.com/microsoft/vscode/issues/343697)

## Summary

The reference leak is confirmed in current source: replacing an internally created diff view model leaves its initial reference alive, retaining listeners and background diff work. Keep this open while the linked fixing PR is reviewed.

## Change summary

Dispose widget-created diff view models after replacement without taking ownership of caller-provided view models.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/343699 after checking that replacement and widget disposal release internally owned view models while caller-owned view models remain usable.

## Evidence

- **Current source confirms the leaked reference:** src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts:571-576 creates a RefCounted wrapper for this.createViewModel(model), calls setDiffModel(vm), and never disposes that initial reference. At lines 600-608, setDiffModel creates its own stored reference and temporarily retains the previous value during replacement; releasing those references cannot release the abandoned initial reference.
- **Reference-count semantics:** src/vs/editor/browser/widget/diffEditor/utils.ts:469-509 initializes BaseRefCounted._refCount to 1, increments it in createNewRef, and disposes the wrapped object only when _decreaseRefCount reaches zero. Consequently, setModel(pair), followed by setModel(null) or another pair, leaves the original widget-created view model undisposed.
- **Retained work and listeners:** src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts:88-92 registers cancellation on disposal and a 200ms RunOnceScheduler. Lines 225-262 register content-change listeners on both text models that schedule further diff computation; these remain registered when disposal never occurs.
