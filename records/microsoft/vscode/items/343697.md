# Issue #343697 — DiffEditorWidget.setModel never disposes the view model it creates

## Evidence

- **Source-confirmed ownership leak:** src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts:571-575 creates a RefCounted wrapper for an internally created view model but never releases its initial reference. setDiffModel at lines 600-607 acquires a separate stored reference and later releases the replaced reference, leaving the initial reference outstanding after setModel(null) or replacement.
- **Reference-count semantics:** src/vs/editor/browser/widget/diffEditor/utils.ts:469-509 initializes BaseRefCounted._refCount to 1, increments it in createNewRef, and disposes the underlying object only when the count reaches zero. The unreleased initial reference therefore prevents view-model disposal.
- **Retained work:** src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts:88-91 registers cancellation on disposal and a 200ms scheduler; lines 225-258 retain original/modified content listeners, and lines 294-300 compute diffs using the uncancelled token. This supports the reported detach, edit, and reattach accumulation without executing the code.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/343699 is OPEN with mergedAt null and explicitly states Fixes #343697. Its diff releases setModel's reference and adds a disposal test in src/vs/editor/test/browser/widget/diffEditorWidget.test.ts. The PR author states that the test has not been run locally.
- **Related, not a verified duplicate:** https://github.com/microsoft/vscode/issues/315291 is open and reports an Illegal value for lineNumber error in normalizeRangeMapping. It does not establish the same observable listener-retention/model-disposal symptom, so it does not satisfy the stronger duplicate bar for this re-reviewed issue.
