# Issue #335005 — Agents window: allow rebinding submit key in new-session composer (Ctrl+Enter)

[https://github.com/microsoft/vscode/issues/335005](https://github.com/microsoft/vscode/issues/335005)

## Summary

Confirmed on main: the Agents window new-session composer sends via a raw `onKeyDown` handler in `newChatInput.ts` rather than a rebindable command, exactly as described, so `Ctrl+Enter` (or any custom submit keybinding) can't reach it before a session exists. Valid, well-diagnosed request — routing to the sessions area; the `stale` label looks like a bot misfire on an 8-day-old, clearly-still-relevant report.

## Change summary

Expose the Agents window new-session composer's submit/background-submit actions as commands bound to a context key (e.g. `inChatComposer`) instead of a hardcoded onKeyDown handler, so users can rebind the submit key (e.g. to Ctrl+Enter) as they can in the in-session chat input.

## Best solution

Register the composer's send/send-in-background actions as real commands scoped to the existing `inChatComposer` context key (or similar) in `src/vs/sessions/contrib/chat/browser/newChatInput.ts`, replacing the hardcoded `onKeyDown` Enter/Alt+Enter checks, so keybindings.json rebindings apply consistently before and after a session starts.
