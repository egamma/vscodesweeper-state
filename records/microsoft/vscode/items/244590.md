# Issue #244590 — Git - Bad git diff handling for UTF-16 LE file

[https://github.com/microsoft/vscode/issues/244590](https://github.com/microsoft/vscode/issues/244590)

## Summary

Still present on main: the git extension's diff path does not handle UTF-16 LE encoded files — `diffWithHEAD()` runs `git diff` which outputs garbled text for non-UTF-8 files, and the file system provider returns raw bytes without encoding-aware conversion, causing both the false-modified status and garbage diff display.

## Change summary

UTF-16 LE encoded files in git repos are shown as modified when they aren't, and the diff view displays garbage/Chinese characters instead of the actual file content.

## Best solution

The git extension needs encoding-aware diff handling for UTF-16 files. The `detectObjectType` method in `extensions/git/src/git.ts` already detects UTF-16 LE/BE via BOM, but that detection is not used in the diff or file-content paths. The fix should either convert UTF-16 content to UTF-8 before diffing, or use `.gitattributes` `working-tree-encoding` awareness to let git handle the conversion. The `fileSystemProvider.ts` `readFile()` and the `diffWithHEAD()`/`diffIndexWithHEAD()` paths both need attention.
