# Issue #138324 — Dynamic scaling of codelens font size different from 90%

[https://github.com/microsoft/vscode/issues/138324](https://github.com/microsoft/vscode/issues/138324)

## Summary

Keep open: current CodeLens sizing supports absolute pixels or a hardcoded 90% of the editor font size, not a configurable relative size. This accepted Backlog request still describes a real gap, and the related reports do not provide an open canonical for it.

## Change summary

Allow CodeLens font size to remain a configurable percentage of the editor font size as that size changes.

## Best solution

Provide configurable relative CodeLens sizing while preserving existing absolute-pixel values and the default 90% behavior. Settle the public configuration syntax before implementation.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/codelens/browser/codelensController.ts`
- **Validation:** After choosing the configuration contract, verify a 75% relative size with editor.fontSize values 16 and 20: CodeLens should resolve to 12px and 15px and update when the editor font changes. Check that an absolute value of 14 remains 14px and that 0 retains the existing 90% behavior; verify CodeLens view-zone height remains consistent with the rendered font.
- **Behavior:**

  > Users can choose a CodeLens font size relative to the editor font, rather than being limited to the default 90% ratio. A selected 75% ratio follows changes to the editor font size without requiring manual adjustment of CodeLens settings. Existing absolute-pixel configurations and the default 90% behavior remain compatible. Acceptance includes changing editor.fontSize from 16 to 20 and observing relative CodeLens sizing change from 12px to 15px without overlap or clipping.
- **Trace:**

  > src/vs/editor/common/config/editorOptions.ts declares codeLensFontSize as number-only and registers an integer-valued pixel setting. CodeLensContribution._getLayoutInfo() in src/vs/editor/contrib/codelens/browser/codelensController.ts supplies the only relative behavior through a hardcoded 0.9 multiplier and derives view-zone height from the resulting size. Configuration changes already trigger _updateLensStyle(), which updates CSS font sizing and existing lens heights. Source inspection establishes the missing configurable ratio; no build or runtime validation was performed in this read-only review. Preserve current numeric settings, default behavior, and CodeLens provider semantics; same-line placement and inlay-hint sizing are outside this request. The unresolved boundary is the public representation of relative sizing, not the internal choice of helper or calculation.
- **Open decisions:**
  - Should configurable relative sizing use percentage strings in editor.codeLensFontSize, fractional numeric values as suggested by the reporter, or a separate ratio setting, while preserving existing absolute-pixel configurations?
