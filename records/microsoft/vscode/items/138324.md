# Issue #138324 — Dynamic scaling of codelens font size different from 90%

[https://github.com/microsoft/vscode/issues/138324](https://github.com/microsoft/vscode/issues/138324)

## Summary

The proportional sizing gap remains on main: CodeLens supports a fixed pixel size or a hardcoded 90% default, but no configurable relative value. Keep this accepted Backlog request open for a product decision and classify it as under discussion.

## Change summary

Allow CodeLens font size to remain proportional to the editor font at a user-selected percentage rather than only 90%.

## Best solution

If maintainers accept another appearance control, extend the editor option with a backward-compatible relative-size representation and apply it consistently to CodeLens, merge-conflict actions, and testing decorations. Otherwise retain the current fixed-pixel-or-90% model rather than adding a CodeLens-specific percentage setting.

## Vision fit

- **Fit:** rejected
- **Reason:** A narrowly scoped visual sizing option adds configuration complexity and cuts against the preference for uniform UI mechanisms.
- **Evidence:** Values and guardrails: UI consistency should take precedence over per-feature customization, and the default experience should avoid configuration sprawl.

## Evidence

- **current option:** src/vs/editor/common/config/editorOptions.ts registers `codeLensFontSize` as an integer and documents only fixed pixels or 0 for 90% of `editor.fontSize`.
- **current implementation:** src/vs/editor/contrib/codelens/browser/codelensController.ts computes `(editor.fontSize * .9) | 0` whenever the configured size is unset or below 5; no configurable ratio exists.
- **other consumers:** src/vs/workbench/contrib/mergeEditor/browser/view/conflictActions.ts and src/vs/workbench/contrib/testing/browser/testingDecorations.ts independently use the same hardcoded 90% calculation.
