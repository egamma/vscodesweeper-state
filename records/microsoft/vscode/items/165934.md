# Issue #165934 — New Color customization option editor.activeBackground

[https://github.com/microsoft/vscode/issues/165934](https://github.com/microsoft/vscode/issues/165934)

## Summary

Keep this accepted, community-supported request open: current source still uses the same editor background regardless of activation, and tab or empty-group colors do not cover the ask. No eligible open canonical was found; a maintainer-led design should settle whether the highlight follows editor-group activation or actual keyboard focus.

## Change summary

Add a theme color customization that distinguishes the active editor's content background from other visible editors.

## Best solution

Provide an optional theme-level active-editor background override while preserving existing appearance when unset. Define its activation semantics and supported editor surfaces before implementation; workspace-membership coloring is a separate request.

## Plan brief

- **Likely files:** `src/vs/platform/theme/common/colors/editorColors.ts`, `src/vs/workbench/browser/parts/editor/editorGroupView.ts`, `src/vs/editor/browser/widget/codeEditor/editor.css`, `src/vs/workbench/common/theme.ts`
- **Validation:** In a development build, open two populated text-editor groups, configure distinct normal and active background colors, and switch between groups using both mouse and keyboard. Verify only the selected activation target changes its content background; check the agreed behavior when focus moves to the sidebar or Find widget, theme switching, and restoration of existing appearance when the override is removed.
- **Behavior:**

  > Users want to distinguish the active editor by its content background rather than its tab color. An optional color customization should provide that distinction across visible editor groups without changing default appearance when absent. Acceptance includes switching the target through mouse and keyboard navigation and honoring the agreed behavior when keyboard focus leaves the editor. Coloring files by workspace membership is outside this request's activation-based scope.
- **Trace:**

  > EditorGroupView.setActive() in src/vs/workbench/browser/parts/editor/editorGroupView.ts tracks group activation and refreshes styles, but updateStyles() uses the same editorBackground for every populated editor container. The text-editor surfaces in src/vs/editor/browser/widget/codeEditor/editor.css independently use --vscode-editor-background, so container styling alone is not sufficient. The shared background token is registered in src/vs/platform/theme/common/colors/editorColors.ts; neighboring tab and empty-group tokens live in src/vs/workbench/common/theme.ts and do not supply the requested behavior. Source inspection establishes the missing capability, not a runtime reproduction. Preserve existing defaults, focus/navigation behavior, and standalone editor behavior unless explicitly included in the design. Historical discussion at https://github.com/microsoft/vscode/issues/50686 and https://github.com/microsoft/vscode/issues/2352 distinguishes broader focus indication from this customization; both issues are closed. The remaining uncertainty is whether active means the active workbench group or actual keyboard focus, and which non-text editor surfaces participate.
- **Open decisions:**
  - Should the background follow the active editor group even while focus is in the sidebar or Find widget, or apply only while the editor itself has keyboard focus?
  - Is the initial customization limited to text editors, or must it also distinguish active diff, notebook, and other editor surfaces?
