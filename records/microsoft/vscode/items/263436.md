# Issue #263436 — Find history does not work as a most recent stack

[https://github.com/microsoft/vscode/issues/263436](https://github.com/microsoft/vscode/issues/263436)

## Summary

Keep this accepted feature request open: current Find history still does not promote an entry recalled through history navigation, and the linked implementation PR was closed without merging. The request has 24 upvotes and remains a meaningful keyboard-accessibility improvement.

## Change summary

Make reused Find history entries most-recently-used so they are quickly accessible on subsequent searches.

## Best solution

Support MRU recall in the editor Find widget without disrupting Up/Down traversal or introducing duplicate entries. Settle whether this replaces the existing behavior or is opt-in before implementation.

- **Validation:** Using the agreed MRU behavior, populate Find history with at least three distinct terms, recall the oldest using Up, use it to search, then reopen Find and verify it is the first recalled prior term. Verify uninterrupted Up/Down traversal before accepting a selection, no duplicate entry after repeated reuse, correct workspace-history restoration, and unchanged legacy ordering if an opt-in mode is chosen.
- **Behavior:**

  > Reusing an older Find query should make it quickly accessible the next time the user recalls search history, including queries containing Braille characters. The user must still be able to traverse older entries without the history continually reshuffling underneath navigation. Acceptance includes reuse becoming the most-recent entry, no duplicate entries, and preservation of the existing workspace-history storage controls. Whether MRU becomes the default or an optional mode requires a maintainer decision.
- **Trace:**

  > FindWidget._updateHistory in src/vs/editor/contrib/find/browser/findWidget.ts calls HistoryInputBox.addToHistory without a force argument. In src/vs/base/browser/ui/inputbox/inputBox.ts, addToHistory suppresses insertion when the input equals the navigator's current value, which is the case after history recall; HistoryNavigator.add in src/vs/base/common/history.ts already supports delete-and-reinsert promotion. Existing editor.find.history and editor.find.replaceHistory settings in src/vs/editor/common/config/editorOptions.ts govern storage rather than ordering. Preserve shared input-box consumers, keyboard traversal, and existing storage semantics rather than treating every history-navigation step as a committed selection. https://github.com/microsoft/vscode/pull/265941 is a closed, unmerged implementation attempt, not an active competing PR or a landed fix. https://github.com/microsoft/vscode/issues/23099 concerns a dropdown presentation and does not own this MRU request.
- **Open decisions:**
  - Should MRU ordering replace the current editor Find history behavior by default, or be an opt-in mode preserving legacy ordering?
