# Issue #268095 — Use @mode_name to specify your mode.

[https://github.com/microsoft/vscode/issues/268095](https://github.com/microsoft/vscode/issues/268095)

## Summary

A real mode-selection UX gap remains on current main: custom agents are available through the picker, but chat input completions do not expose them as textual mode selectors. The team-authored issue must remain open, and the maintainer discussion leaves the user-facing syntax undecided.

## Change summary

Allow users to select a custom chat mode by typing its name instead of repeatedly searching the mode dropdown.

## Best solution

Provide a keyboard-first invocation surface for selecting a named custom agent, with the chosen agent visibly becoming the active mode for the next request. First settle whether that contract uses slash commands, quick access, or mentions while chat participants are being retired.

- **Behavior:**

  > A user with many custom agents can select one by typing its name through a keyboard-first chat-input surface rather than opening and searching the mode dropdown. Selection visibly updates the active mode, and the next submitted request uses that custom agent's instructions. Existing dropdown selection remains available. Agent chaining and context handoff are outside this issue and remain tracked by https://github.com/microsoft/vscode/issues/268096.
- **Trace:**

  > ChatModes.refreshCustomPromptModes in src/vs/workbench/contrib/chat/common/chatModes.ts obtains user-invocable agents from ICustomizationHarnessService and represents them as custom modes. ModePickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts currently turns those modes into dropdown actions that invoke ToggleAgentModeActionId. Chat input completion providers in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts independently expose prompt/skill slash commands and IChatAgentService participants, but not custom modes. The technical boundary is top-level mode selection: do not expand this work into nested agent execution or context handoff, which is the distinct request at https://github.com/microsoft/vscode/issues/268096.
- **Open decisions:**
  - Should named custom-agent selection use slash commands, quick access, or @ mentions, given that these choices produce different visible syntax and @ participants are planned for retirement?
