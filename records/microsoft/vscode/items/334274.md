# Issue #334274 — Custom terminal tool can run with a weaker sandbox policy

[https://github.com/microsoft/vscode/issues/334274](https://github.com/microsoft/vscode/issues/334274)

## Summary

This describes a sandbox-policy bypass: enabling the experimental custom terminal tool routes shell execution through a path that enterprise-managed `sandbox.*` policy doesn't govern. That's a security/policy-enforcement concern, so this must stay open for a human to handle regardless of any other evidence.

## Change summary

When Agent Host's experimental custom terminal tool is enabled, managed sandbox policy (enablement, bypass, filesystem/network rules) is not applied to that tool's execution path, unlike the built-in SDK shell tool.

## Best solution

Either gate the custom terminal tool off whenever managed sandbox policy is active, or thread the effective managed policy into the terminal sandbox engine so both shell paths enforce the same rules; a maintainer (anthonykim1) has already proposed disabling the custom tool under managed policy as the near-term fix, which is a reasonable direction for the agent-sandbox area.
