# Issue #250787 — Avoid individual indent guides in trees

[https://github.com/microsoft/vscode/issues/250787](https://github.com/microsoft/vscode/issues/250787)

## Summary

This performance debt remains on current main: every rendered tree row still creates a separate DOM element for each ancestor indent guide. The older related issues describe broader deep-tree rendering and scrolling problems, not the same indent-transition symptom required for a duplicate close on re-review.

## Change summary

Replace the per-ancestor indent-guide elements created for every rendered tree row with a more scalable representation.

## Best solution

Redesign the shared tree renderer so indent guides require a bounded amount of DOM per visible row while preserving active-ancestor highlighting, hover behavior, theming, and reduced-motion behavior. Validate the design with a deeply nested tree case that checks DOM growth and records rendering or interaction performance.

- **Behavior:**

  > Deeply nested trees must retain the existing visual hierarchy, active-ancestor highlighting, hover behavior, theme colors, and reduced-motion behavior. Rendering visible rows must no longer create one DOM node for every ancestor of every row. Acceptance requires bounded indent-guide DOM growth in an automated browser test and a repeatable deep-tree interaction profile without the indent-guide-related long tasks.
- **Trace:**

  > TreeRenderer._renderIndentGuides in src/vs/base/browser/ui/tree/abstractTree.ts walks from each rendered node to the root, creates an `.indent-guide` div per ancestor, and tracks every guide for active-state updates. src/vs/base/browser/ui/tree/media/tree.css transitions each guide's opacity. Commit https://github.com/microsoft/vscode/commit/8cfe3ee7fe11a6104fa9101f1323dc29a5d517eb moved the transition from border color to opacity but retained the depth-times-visible-rows DOM structure. The uncertainty starts at the replacement representation and its efficient active-guide update strategy; the boundary is the shared tree renderer and its styling, without changing tree model traversal, sticky scrolling, or feature-specific tree data providers. The broader reports https://github.com/microsoft/vscode/issues/235890 and https://github.com/microsoft/vscode/issues/213839 should be treated as related performance baselines, not duplicate ownership.

## Evidence

- **current source:** In src/vs/base/browser/ui/tree/abstractTree.ts, TreeRenderer._renderIndentGuides walks every ancestor and creates an `.indent-guide` HTMLDivElement for each one, then registers each element in renderedIndentGuides. The requested bounded representation has not been implemented.
- **current styling:** src/vs/base/browser/ui/tree/media/tree.css still applies an opacity transition to every `.monaco-tl-indent > .indent-guide`, so deeply nested visible rows retain the per-guide animation workload.
