## Summary

Verified duplicate: the older open issue reports the same Copilot Chat failure after laptop sleep—transient fetch and DNS failures leave Chat without an effective retry or recovery path. This report adds valuable WSL2 frequency data and likely failure mechanisms, which should be carried into the canonical issue.

## Change summary

Make Copilot Chat recover automatically when token and model initialization requests encounter transient network failures after host suspend.

## Best solution

Consolidate recovery work in https://github.com/microsoft/vscode/issues/286284: transient authentication and model-fetch failures should retry after connectivity returns, reset stale connections where supported, and leave Chat usable without reloading the window.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/286284 is open, predates this report, and records the same reporter-observable sequence: closing a laptop is followed by node-fetch, Electron, and node-http DNS failures, a failed Copilot token refresh, and no usable retry path.
- **same recovery gap:** Both reports concern Copilot Chat failing to recover after a brief post-suspend network/DNS outage; the canonical title explicitly requests a retry for `fetch failed`, while this report supplies the stronger WSL2 evidence that the transient failure can persist in the UI until reload.
- **current source:** extensions/copilot/src/platform/authentication/node/copilotTokenManager.ts enables immediate fetcher fallbacks for token requests, but extensions/copilot/src/platform/networking/node/fetcherFallback.ts has no delayed retry after every fetcher fails.
- **connection reset gap:** extensions/copilot/src/platform/networking/node/baseFetchFetcher.ts implements disconnectAll() as a no-op, and extensions/copilot/src/platform/networking/node/nodeFetchFetcher.ts uses a process-level lazy undici Agent without overriding that method; current source therefore does not recreate that pool after EAI_AGAIN or ECONNRESET.
- **unique evidence to preserve:** This report contributes measurements from 151 WSL extension-host instances, including 186 EAI_AGAIN, 30 ECONNRESET, and 22 ETIMEDOUT occurrences, plus the observation that affected windows remain stuck while sibling windows recover.
