# Issue #315412 — Copilot Chat does not recover from transient outbound failures (host suspend / EAI_AGAIN); silent token refresh leaves UI stuck until   window reload

[https://github.com/microsoft/vscode/issues/315412](https://github.com/microsoft/vscode/issues/315412)

## Summary

The report identifies a real resilience gap in Copilot's networking layer: `EAI_AGAIN` (DNS transient failure) is absent from `canRetryOnceNetworkError`, and the silent token-refresh / `fetchKnownModelList` paths lack retry-with-backoff, so a brief DNS outage on host resume can leave the chat UI permanently stuck. Commit b4312bc039c partially mitigated model-list clearing but the core retry gap remains on main.

## Change summary

Copilot Chat enters an unrecoverable stuck state after transient DNS/network errors during host suspend/resume because silent background fetches have no retry logic for `EAI_AGAIN` and related errors.

## Best solution

Add `EAI_AGAIN` (and possibly `ENOTFOUND`) to `canRetryOnceNetworkError` in `src/vs/../networking/common/networking.ts`. Additionally, wrap the silent `fetchKnownModelList` catch path in `modelMetadataFetcher.ts` with a retry-with-backoff so a single transient failure doesn't leave `_lastFetchError` set permanently. The token-refresh path in `copilotTokenManager.ts` should similarly retry on transient network errors before returning `RequestFailed`.

## Evidence

- **EAI_AGAIN missing from retry list:** `canRetryOnceNetworkError` in `extensions/copilot/src/platform/networking/common/networking.ts:552` lists ECONNRESET, ETIMEDOUT, etc. but does NOT include EAI_AGAIN or ENOTFOUND — DNS transient failures are not retried.
- **modelMetadataFetcher no retry:** `extensions/copilot/src/platform/endpoint/node/modelMetadataFetcher.ts:313` catches fetch errors and sets `_lastFetchError` / `_lastFetchTime = 0` with no retry loop — a single transient failure blocks model resolution.
- **copilotTokenManager no retry on fetch throw:** `extensions/copilot/src/platform/authentication/node/copilotTokenManager.ts:175-177` catches fetch errors and returns `{ kind: 'failure', reason: 'RequestFailed' }` with no retry — a transient DNS error permanently fails the auth refresh.
- **partial mitigation merged:** Commit https://github.com/microsoft/vscode/commit/b4312bc039c (2026-05-08) stopped clearing the model family map on auth change when the token is still present, but does not add retry logic for transient network failures.
- **nodeFetchFetcher confirms EAI_AGAIN is a network error:** `extensions/copilot/src/platform/networking/node/nodeFetchFetcher.ts:55` lists ENOTFOUND in its `isNetworkError` check, but this is not used by the retry path in `canRetryOnceNetworkError`.
