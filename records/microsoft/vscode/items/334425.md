# Issue #334425 — Switching an LM Studio model in a reused chat retains the previous model identity and system prompt

[https://github.com/microsoft/vscode/issues/334425](https://github.com/microsoft/vscode/issues/334425)

## Summary

Traced the BYOK/custom-endpoint code: the registered model id (e.g. `prism-ml/bonsai-27b`) is a static configuration value baked into the endpoint at registration time (extensions/copilot/src/extension/byok/vscode-node/openAIProvider.ts), and VS Code never re-probes the backend mid-session to see if the server swapped which model actually answers requests — so debug logs and the cached system prompt legitimately keep referencing the originally configured model. This is a real, narrow gap (detecting external model drift on a reused BYOK chat), not a maintainer-confirmed intentional limitation, so it stays open rather than closing on my own read.

## Change summary

When the backend model behind a custom/BYOK (LM Studio) endpoint is swapped without reconfiguring VS Code, the reused chat session keeps sending the stale model identity and system prompt to the new model.

## Best solution

Either document that BYOK/custom-endpoint model identity is fixed per VS Code configuration (and a model swap on the server requires starting a new chat or reselecting the model), or add an opt-in check (e.g. re-querying /v1/models) that invalidates the cached system prompt/tools snapshot when the endpoint's served model no longer matches — likely in extensions/copilot/src/extension/byok/vscode-node/openAIProvider.ts and the conversation/system-prompt caching path that keys off model+agent identity (extensions/copilot/src/extension/chat/vscode-node/chatDebugFileLoggerService.ts uses a similar model+mode key for when to regenerate system_prompt files).
