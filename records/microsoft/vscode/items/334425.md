# Issue #334425 — Switching an LM Studio model in a reused chat retains the previous model identity and system prompt

[https://github.com/microsoft/vscode/issues/334425](https://github.com/microsoft/vscode/issues/334425)

## Summary

Keep open: current source derives request identity and identity instructions from the registered model, which can explain the reported mismatch after a server-side model replacement, but does not establish a reused-session caching defect. The supplied steps suffice to retest against the current provider implementation; no specific fixing commit or matching canonical was verified.

## Change summary

Changing the model served by LM Studio leaves subsequent outer and subagent requests identifying and instructing the model as the previously registered model.

## Best solution

Establish how the OpenAI-compatible provider exposes a server-side model replacement, then make the identity mismatch explicit and prevent obsolete model-specific instructions from silently governing subsequent requests. Distinguish the requested model from the model reported by the server rather than assuming a chat reset discovers the replacement.
