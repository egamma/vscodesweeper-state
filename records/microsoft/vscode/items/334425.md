## Summary

The reported identity mismatch needs investigation, but the available evidence does not establish a reused-chat caching defect. The provider constructs requests from the registered model descriptor, and switching the model only inside LM Studio may leave that descriptor unchanged.

## Change summary

After switching the backing LM Studio model, a reused chat reportedly retains the previous model's diagnostic identity and model-specific instructions.

- **Registered descriptor controls the endpoint:** extensions/copilot/src/extension/byok/vscode-node/customEndpointProvider.ts: getAllModels uses explicitly configured model IDs when configuration.models is supplied; createOpenAIEndPoint derives identity and capabilities from model.id, model.name, and configuration. In abstractLanguageModelChatProvider.ts:126-128, each response constructs an endpoint from the supplied descriptor rather than proving an endpoint is cached for the conversation. URL-based discovery is a separate path through getModelsFromEndpoint.
- **Identity instructions follow the prompt endpoint:** extensions/copilot/src/extension/prompts/node/base/copilotIdentity.tsx:18-21 and 37-40 instruct the model to identify itself using promptEndpoint.name. An unchanged registered endpoint name can therefore explain the Bonsai instruction without establishing that an old rendered prompt was reused.
- **Snapshot reuse is not proof of prompt reuse:** extensions/copilot/src/extension/chat/vscode-node/chatDebugFileLoggerService.ts:716-742 writes a new system-prompt snapshot only when a key composed of the request model and instruction length changes; request model takes precedence over response model. A single system_prompt_0.json is therefore insufficient to establish that subsequent outgoing prompts were cached or identical.
