# Issue #255408 — "Could not build remote workspace index. Could not check the remote index status for this repo"

[https://github.com/microsoft/vscode/issues/255408](https://github.com/microsoft/vscode/issues/255408)

## Summary

Still reproduces on main: the GitHub code search status endpoint returns 404 for repos without remote indexing support (likely a plan/entitlement limitation for free-tier users), and the error surfaces as a generic unhelpful message with no guidance on what went wrong or what to do.

## Change summary

Running 'Build Remote Workspace Index' on a public GitHub repo with a free Copilot SKU returns a vague error instead of explaining that remote indexing may not be available for the user's plan or repo.

## Best solution

Improve the error handling in `GithubCodeSearchService.getRemoteIndexState` (extensions/copilot/src/platform/remoteCodeSearch/common/githubCodeSearchService.ts) to distinguish a 404 from other failures — a 404 likely means the repo/plan doesn't support remote indexing, so surface a clear message explaining that and suggesting the local index as an alternative. Related to https://github.com/microsoft/vscode/issues/294099 which tracks local-index fallback when remote indexing fails.
