# Issue #346464 — Per-model settings are written to the wrong provider group when two custom endpoint groups expose the same model id

[https://github.com/microsoft/vscode/issues/346464](https://github.com/microsoft/vscode/issues/346464)

## Summary

The wrong-group write remains source-reproducible on current main: an existing sibling setting wins before the selected model's owning group is checked. Keep this open; the earlier different-model-id fix does not cover this collision.

## Change summary

Keep per-model settings independent when multiple custom endpoint groups expose the same raw model id.

## Best solution

Persist each grouped model's edits to its owning provider group, including repeated edits and resets, while preserving configuration-only behavior for groupless providers.
