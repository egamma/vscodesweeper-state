# Issue #346464 — Per-model settings are written to the wrong provider group when two custom endpoint groups expose the same model id

[https://github.com/microsoft/vscode/issues/346464](https://github.com/microsoft/vscode/issues/346464)

## Summary

Confirmed in current source: an existing settings entry in a sibling provider group takes precedence over the selected model's owning group. Keep open; the earlier different-model-id regression test does not cover this collision.

## Change summary

Per-model configuration changes overwrite another provider group's settings when both groups expose the same raw model id.

## Best solution

Persist each grouped model's configuration exclusively to its owning provider group, preserving independent sibling settings and the existing configuration-only behavior for groupless vendors.
