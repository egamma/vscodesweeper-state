# Issue #212802 — Show sticky inline items for list items when horizontal scrolling is enabled

[https://github.com/microsoft/vscode/issues/212802](https://github.com/microsoft/vscode/issues/212802)

## Summary

Keep open: current Test Explorer rendering still places inline actions after horizontally scrollable labels rather than anchoring them inside the viewport. A maintainer explicitly accepted this as a feature request; the existing scrolling setting and the related call-stack request do not cover its full scope.

## Change summary

Keep list-row inline actions visible on hover or focus while long labels remain horizontally scrollable, including in Test Explorer.

## Best solution

Provide viewport-anchored inline actions without disabling horizontal label scrolling or changing which actions each renderer contributes. Establish the supported renderer scope first, using Test Explorer and its long-title case as concrete acceptance scenarios.

- **Behavior:**

  > With horizontal scrolling enabled, long test names can push row actions outside the visible Test Explorer viewport. Hovering or keyboard-focusing an actionable row should expose its actions without requiring a horizontal scroll, while retaining access to the full label through scrolling. Acceptance includes very long titles and all horizontal scroll positions, including the reporter's case where scrolling to the end still did not reveal the buttons. Existing action visibility, targeting, and behavior with horizontal scrolling disabled must remain intact.
- **Trace:**

  > TestingExplorerViewModel constructs TestingObjectTree without overriding the shared horizontal-scrolling setting in src/vs/workbench/contrib/testing/browser/testingExplorerView.ts. Source inspection establishes the absent viewport anchoring, but no UI was executed and the extreme-title scroll-limit symptom remains unverified. Preserve horizontal scrolling, contributed action semantics, keyboard focus, and continuous-run indicators.
