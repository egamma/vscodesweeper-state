# Issue #213849 — Allow Developer to get command description from API

[https://github.com/microsoft/vscode/issues/213849](https://github.com/microsoft/vscode/issues/213849)

## Summary

The public extension API still exposes command IDs without their descriptions, so the central request remains unmet. This accepted Backlog item has 22 upvotes, and the related command-description work does not replace the requested API.

## Change summary

Allow extensions to retrieve human-readable descriptions of registered commands programmatically.

## Best solution

Define a supported command-metadata retrieval API for extensions, with clear semantics for localized descriptions and commands without metadata. Reuse existing command metadata without requiring every command to acquire a description.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHost.api.impl.ts`, `src/vs/workbench/api/common/extHostCommands.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadCommands.ts`, `src/vs/platform/commands/common/commands.ts`
- **Validation:** An extension API test should retrieve a known command's agreed human-readable metadata, exercise a command without metadata and an unknown ID, and verify that existing getCommands() still returns command IDs with unchanged internal-command filtering.
- **Behavior:**

  > Extensions can obtain a command's human-readable description through a supported API rather than infer it from its identifier or scrape the Command Palette. The contract must specify what callers receive when a command has no description or does not exist, and whether text follows the UI locale. Acceptance should cover a described command, an undescribed command, and an unknown identifier while preserving existing command enumeration and execution behavior.
- **Trace:**

  > The public commands namespace in src/vscode-dts/vscode.d.ts and its implementation in src/vs/workbench/api/common/extHost.api.impl.ts expose getCommands() as an ID list. ExtHostCommands.getCommands forwards through MainThreadCommandsShape to MainThreadCommands.$getCommands, which returns CommandsRegistry keys and discards metadata. ICommandMetadata.description already exists in src/vs/platform/commands/common/commands.ts; the internal _generateCommandsDocumentation path aggregates some metadata but only logs Markdown. https://github.com/microsoft/vscode/issues/209511 concerns authoring descriptions, not exposing them, while https://github.com/microsoft/vscode/issues/160263 is a closed earlier metadata API proposal. The remaining uncertainty is the supported public contract, not whether the current ID-list API satisfies the request. Preserve existing enumeration, activation, and execution semantics, and do not expand this work into requiring descriptions for all commands.
- **Open decisions:**
  - Should the public API return only a command's description, or a metadata object also covering its display title, arguments, and return documentation?
  - Should descriptions follow the current UI locale, expose original text, or offer both?
  - How should callers distinguish an unknown command from a registered command with no description?

## Evidence

- **Public API gap:** src/vscode-dts/vscode.d.ts:10976–11033 declares registration, execution, and getCommands(filterInternal?: boolean): Thenable<string[]> in the commands namespace; no description-retrieval API is declared. src/vs/workbench/api/common/extHost.api.impl.ts:415–417 likewise exposes only the ID-list operation.
- **Existing internal capability is not public coverage:** src/vs/platform/commands/common/commands.ts defines optional ICommand.metadata and ICommandMetadata.description. MainThreadCommands.$getCommands in src/vs/workbench/api/browser/mainThreadCommands.ts returns only registry keys. Its internal _generateCommandsDocumentation command aggregates metadata and logs Markdown, returning no usable metadata result to extensions; ExtHostCommands.$getContributedCommandMetadata is an internal RPC, not a public API.
- **Related open issue is distinct:** https://github.com/microsoft/vscode/issues/209511 was verified open and predates this report, but asks maintainers to author better core command descriptions for Command Palette matching. It does not request extension API access to those descriptions, so it does not meet the re-reviewed-item duplicate bar.
