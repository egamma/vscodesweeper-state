# Issue #331566 — Agent file tools incorrectly prompt "Allow reading file outside of workspace?" for the current workspace in WSL

[https://github.com/microsoft/vscode/issues/331566](https://github.com/microsoft/vscode/issues/331566)

## Summary

Fresh MEMBER-filed regression: the agent's outside-of-workspace read prompt fires even when the resolved path is exactly the WSL workspace root (or when the path is omitted and defaults to it). The reporter confirms it reproduces consistently on Insiders 1.135.0 but not on 1.134.0, pointing to a recent regression in how the WSL working directory is compared against the tool's requested path.

## Change summary

In a WSL remote workspace, Copilot agent file-search/read tools trigger the 'Allow reading file outside of workspace?' prompt even though the resolved target path is identical to (or defaults to) the active workspace root.

## Best solution

Bisect the working-directory/path comparison used for the Copilot permission classification between 1.134.0 and current Insiders (src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts and the `@github/copilot-sdk` permission-request path in copilotToolDisplay.ts) to find where a WSL-resolved workspace root path stops matching the tool's requested/default path, likely a case, symlink-resolution, or scheme/authority mismatch specific to the WSL remote.
