# Issue #331566 — Agent file tools incorrectly prompt "Allow reading file outside of workspace?" for the current workspace in WSL

[https://github.com/microsoft/vscode/issues/331566](https://github.com/microsoft/vscode/issues/331566)

## Summary

Confirmed bug: agent-host permission checks incorrectly classify the active workspace as 'outside the workspace' in remote sessions (WSL and Remote-SSH both confirmed), most likely a URI-scheme mismatch between the stored working-directory URI and the plain `URI.file()`-wrapped tool-supplied path in the containment check.

## Change summary

Agent tools reading/searching inside the current remote workspace trigger an unnecessary 'Allow reading file outside of workspace?' confirmation prompt.

## Best solution

Trace the containment check in src/vs/platform/agentHost/node/sessionPermissions.ts (_isReadAutoApproved / _isResourceInDirectory, using extUriBiasedIgnorePathCase.isEqualOrParent) against how remote working directories are represented (AGENT_HOST_SCHEME wrapping in src/vs/platform/agentHost/common/agentHostUri.ts) versus the plain URI.file(e.permissionPath) built from the tool's reported path, and make the scheme/authority normalization consistent before comparing.
