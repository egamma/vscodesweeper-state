# Issue #235419 — `Search Service` does not use `asCanonicalUri` 

[https://github.com/microsoft/vscode/issues/235419](https://github.com/microsoft/vscode/issues/235419)

## Summary

The URI-canonicalization gap remains in current SearchService: provider matches reach progress callbacks and completed results without asCanonicalUri. Keep this team-authored debt open; the older URI-comparison issue is related but does not establish the same remaining work.

## Change summary

Ensure search-result URIs entering the workbench use the URI identity service's canonical representation.

## Best solution

Establish canonical resource identity consistently for streamed and completed search results at the workbench search boundary, preserving case-sensitive providers and existing result-merging behavior. Treat this as identity normalization, not a requirement to uppercase Windows drive letters.
