# Issue #329943 — agentHost: a transient git failure can permanently freeze a folder-isolated session's project

[https://github.com/microsoft/vscode/issues/329943](https://github.com/microsoft/vscode/issues/329943)

## Summary

Confirmed by tracing current main: `getWorktreeRoots` (src/vs/platform/agentHost/node/agentHostGitService.ts) collapses any git failure — timeout, EAGAIN, index-lock contention, or a genuine non-worktree — into an empty array via `_runGit`'s `resolve(undefined)` path, and `resolveGitProject`/`CopilotAgent._storeSessionMetadata` then persist the checkout-root fallback with `projectResolved: true`, with no later re-derivation for folder-isolated sessions. This is a real, well-diagnosed defect worth routing to the agent-host owners rather than closing.

## Change summary

A transient git failure during worktree-root resolution gets persisted as a confirmed project for folder-isolated agent sessions, permanently mis-grouping them with no repair path.

## Best solution

Apply the same certified-vs-fallback discipline that #329932 introduced for worktree-isolated sessions: have `tryResolvePrimaryWorktreeRoot`/`resolveGitProject` return a typed `{ root, confirmed }` and have `CopilotAgent._storeSessionMetadata` only set `projectResolved` when `confirmed` is true, leaving unconfirmed folder-isolated projects unpersisted so a later attempt can settle them.
