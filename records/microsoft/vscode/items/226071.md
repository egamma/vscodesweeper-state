# Issue #226071 — Unable to pass `target: Workspace`  to `workbench.action.openSettings2` command

[https://github.com/microsoft/vscode/issues/226071](https://github.com/microsoft/vscode/issues/226071)

## Summary

The reported limitation remains in current source: the UI command discards target arguments and the preferences service forces user scope. Keep this accepted backlog bug open; the suggested workspace command still does not force the UI when the user prefers JSON.

## Change summary

Allow an extension to open the Settings UI at workspace scope with a search query, independently of the user's preferred settings editor.

## Best solution

Provide a supported command argument contract that combines workspace scope, a query, and forced UI presentation. Settle the externally accepted target representation before implementation rather than exposing the internal configuration enum accidentally.
