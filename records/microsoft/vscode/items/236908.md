# Issue #236908 — Cmd+\ does not register

[https://github.com/microsoft/vscode/issues/236908](https://github.com/microsoft/vscode/issues/236908)

## Summary

VS Code's bundled keyboard layouts lack a definition for macOS 'British - PC' (com.apple.keylayout.British-PC), causing incorrect key mapping when Cmd+\ is pressed — the physical key position differs from the standard British layout.

## Change summary

Cmd+\ does not trigger Split Editor on macOS when the 'British - PC' input source is selected, because VS Code maps the wrong physical key.

## Best solution

Add a keyboard layout definition for `com.apple.keylayout.British-PC` in `src/vs/workbench/services/keybinding/browser/keyboardLayouts/en-uk.darwin.ts` (or a new file), capturing the correct scancode-to-character mapping for that layout — or add it as a `secondaryLayouts` entry if the mapping is identical to an existing registered layout.
