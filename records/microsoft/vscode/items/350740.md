# Issue #350740 — P2 Overview ruler re-queries, converts and sorts every overview-ruler decoration on each cursor move before deciding nothing changed (≈17 ms/move in a 100k-line file; 3 s while opening a 2,000-hunk diff)

[https://github.com/microsoft/vscode/issues/350740](https://github.com/microsoft/vscode/issues/350740)

## Summary

Current main confirms the unnecessary full decoration query and sort on cursor-only renders. Keep this open in editor-rendering; the performance defect is bounded and ready for implementation.

## Change summary

Avoid rebuilding unchanged overview-ruler decoration inputs on cursor movement and redundant render passes.

## Best solution

Separate decoration-input freshness from cursor-marker repainting in DecorationsOverviewRuler, preserving all existing invalidation and rendering behavior. Coalesce decoration changes through the existing rendering scheduler rather than introducing a separate scheduling system.
