# Issue #210045 — Search occurrence containing block cursor is badly highlighted

[https://github.com/microsoft/vscode/issues/210045](https://github.com/microsoft/vscode/issues/210045)

## Summary

The visual conflict remains in the current rendering path: a solid block cursor independently paints over part of the active find-match decoration. This team-authored, correctly routed bug should remain open because no explicitly linked fix or verified duplicate exists.

## Change summary

Keep the active search occurrence visually coherent and legible when a solid block cursor overlaps one of its characters.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/find/browser/findDecorations.ts`, `src/vs/editor/contrib/find/browser/findWidget.css`, `src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts`
- **Validation:** With Dark+ and `editor.cursorStyle` set to `block`, search for repeated text and navigate between matches; verify that every active occurrence remains visually coherent while the cursor location stays clearly distinguishable, including when it overlaps each character in the match.
- **Behavior:**

  > When a solid block cursor overlaps the active in-editor search match, the entire occurrence must remain recognizable as the active match and its text must remain legible. The cursor position must also remain unambiguous. Other cursor styles, inactive matches, selections, syntax colors, and theme customization must retain their existing behavior.
- **Trace:**

  > FindDecorations in src/vs/editor/contrib/find/browser/findDecorations.ts applies `currentFindMatch` to the selected occurrence, whose background and border are defined in src/vs/editor/contrib/find/browser/findWidget.css. ViewCursor in src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts separately renders the grapheme inside the block cursor, while the theming participant in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts assigns independent cursor colors. This causes the cursor layer to replace one character's find-match appearance. Keep the scope to interactions between solid block cursors and find decorations; do not alter cursor positioning, search navigation, or general syntax token rendering.
- **Open decisions:**
  - When a solid block cursor overlaps the active find match, should the cursor retain its normal filled appearance while the match remains continuous, or use a distinct outline/contrast treatment for that overlap state?

## Evidence
