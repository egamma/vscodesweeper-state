# Issue #210045 — Search occurrence containing block cursor is badly highlighted

[https://github.com/microsoft/vscode/issues/210045](https://github.com/microsoft/vscode/issues/210045)

## Summary

The conflicting current-match and block-cursor rendering paths remain on current main, and no canonical issue owns this specific interaction. This team-authored editor-rendering bug should remain open while the intended visual treatment is determined.

## Change summary

Find navigation produces a poorly highlighted current occurrence when the editor uses a block cursor.

## Best solution

Make the current-find-match decoration and block cursor visually coexist without changing find navigation or selection semantics, with acceptable contrast in Dark+ and high-contrast themes.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/find/browser/findWidget.css`, `src/vs/editor/contrib/find/browser/findWidget.ts`, `src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts`
- **Validation:** Using Dark+ with `editor.cursorStyle` set to `block`, search repeated text and navigate between matches; confirm the active occurrence and cursor remain individually legible, then repeat in high-contrast themes and with the default line cursor to verify existing rendering is unchanged.
- **Behavior:**

  > With a block cursor enabled, navigating between editor find results must leave both the active occurrence and cursor clearly distinguishable. The current match must retain its stronger highlight relative to other matches, without border, padding, or cursor colors producing a malformed overlap. Default line-cursor rendering and find navigation semantics must remain unchanged. Validate in Dark+, a light theme, and both high-contrast themes.
- **Trace:**

  > FindModel._setCurrentFindMatch in src/vs/editor/contrib/find/browser/findModel.ts selects the match, so the active cursor is rendered at the selection endpoint. FindDecorations assigns `currentFindMatch` and `currentFindMatchInline` in src/vs/editor/contrib/find/browser/findDecorations.ts; src/vs/editor/contrib/find/browser/findWidget.css paints that range with background, border, and padding. Independently, ViewCursor._prepareRender in src/vs/editor/browser/viewParts/viewCursors/viewCursor.ts copies the grapheme beneath a block cursor, and the theming participant in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts colors it solely from cursor theme tokens. The uncertainty is which visual layer should adapt when these treatments meet; selection ranges, find traversal, non-block cursor behavior, and unrelated editor decorations must not change.
- **Open decisions:**
  - Should the current-match decoration avoid the block cursor geometrically, or should cursor colors adapt while intersecting or adjoining the active match?
  - Can the interaction be covered by an existing editor screenshot/fixture harness, or should acceptance remain a focused manual theme matrix?
