# Issue #210122 — Unable to operate other files in the file manager when having a png floating window

[https://github.com/microsoft/vscode/issues/210122](https://github.com/microsoft/vscode/issues/210122)

## Summary

Keep open: the recordings and independent reports establish incorrect Explorer targeting when a webview steals focus. Current focus handling has changed, but no verified fix or eligible older duplicate was found; the supplied steps suffice for a current-build retest.

## Change summary

With a PNG editor in a floating window, right-clicking Explorer file B incorrectly targets active file A and disrupts operations such as Rename.

## Best solution

Ensure Explorer context-menu actions remain associated with the clicked file and Rename retains input focus while a floating image webview is open. Reproduce the auxiliary-window case on current VS Code before selecting a fix in webview focus tracking or editor focus restoration.

- **Trace:**

  > The report and independent Linux and macOS reports establish historical context-menu-induced focus stealing, but no current-main failure was conclusively traced. src/vs/workbench/contrib/webview/browser/pre/index.html trackFocus polls document.hasFocus together with the webview context-menu class and emits did-focus/did-blur messages. WebviewElement handles those messages and currently sets context-menu-visible=true only for its own did-context-menu event. WebviewEditor.focus also installs host-focus restoration conditioned on the active editor pane and editor-part focus. The uncertainty starts at which, if any, of these paths still reactivates a floating image editor during an Explorer context-menu interaction. Preserve webview-local menu focus and clipboard behavior; do not assume removing the polling condition fixes this report.
