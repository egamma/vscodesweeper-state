# Issue #189784 — [Accessibility] problems.decorations.enabled setting must equally benefit screen reader users

[https://github.com/microsoft/vscode/issues/189784](https://github.com/microsoft/vscode/issues/189784)

## Summary

Still reproduces on main: the Explorer's accessibility provider returns only the file name with no decoration info, so screen readers never announce error/warning counts. The infrastructure for dynamic aria labels now exists but the Explorer hasn't been wired up to use it for problem decorations.

## Change summary

Screen reader users cannot hear error/warning decoration info (e.g. '3 errors') on files/folders in the Explorer view because the tree row aria-label contains only the file name.

## Best solution

Update `FilesExplorerFocusCondition`/`ExplorerDelegate`'s `getAriaLabel` in `src/vs/workbench/contrib/files/browser/views/explorerViewer.ts` to return an `IObservable<string>` that includes the decoration tooltip (error/warning count) from `IDecorationsService`, leveraging the dynamic aria-label infrastructure added in commit 74c0f87b5ef. The decoration tooltip is already computed in `src/vs/workbench/browser/labels.ts` (lines 694–700) and can be queried from `IDecorationsService.getDecoration()`.
