# Issue #189784 — [Accessibility] problems.decorations.enabled setting must equally benefit screen reader users

[https://github.com/microsoft/vscode/issues/189784](https://github.com/microsoft/vscode/issues/189784)

## Summary

The accessibility defect remains source-reproducible on current main: Explorer tree rows expose only the resource name, while problem-decoration details are attached to a child label that screen readers do not read. The issue should remain open for the accepted accessibility fix.

## Change summary

Expose Explorer problem decorations, including warning/error information and counts, to screen-reader users.

## Best solution

Ensure each affected Explorer tree row's accessible name tracks its current resource-decoration tooltip without requiring a full tree rerender, while preserving existing visual decoration and Explorer update behavior.

- **Behavior:**

  > When Explorer problem decorations are enabled, focusing a file or folder with problems must expose the same warning/error information conveyed visually, including its count, in the tree row's accessible name. Undecorated resources and configurations with decorations disabled must retain their existing accessible names. Existing visual decorations and normal Explorer navigation must remain unchanged.
- **Trace:**

  > FilesRenderer.getAriaLabel in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts currently returns only ExplorerItem.name. ResourceLabelWidget in src/vs/workbench/browser/labels.ts receives decoration changes and adds IDecoration.tooltip to its title, but the screen reader consumes the parent tree row rather than that child label; this is why the pre-reopen fix in https://github.com/microsoft/vscode/pull/189856 did not resolve the report. The current list/tree accessibility contract supports IObservable<string> labels, and AbstractTree updates row aria-label attributes when those observables change. IDecorationsService exposes both the computed decoration and a resource-scoped change event. Keep the work bounded to making Explorer row accessibility reflect existing decoration data; do not alter diagnostic production, visual badge rendering, or force full-tree rerenders.
