# Issue #115397 — Git - clicking on a path segment for a file on git index opens empty picker

[https://github.com/microsoft/vscode/issues/115397](https://github.com/microsoft/vscode/issues/115397)

## Summary

The empty breadcrumb picker remains reproducible from current source: parent git URIs resolve as files without children. Keep this confirmed Git-provider bug open; the linked PR was closed without merging, and no verified canonical supersedes it.

## Change summary

Clicking a directory breadcrumb in a staged-file editor opens an empty picker instead of usable directory navigation.

## Best solution

Make Git-backed directory navigation resolve the appropriate directory and its children rather than the original file. Preserve existing revision-specific file reads and normal breadcrumb behavior for other filesystem providers.

- **Current source reproduces the trigger:** BreadcrumbsModel._initFilePathInfo in src/vs/workbench/browser/parts/editor/breadcrumbsModel.ts builds ancestor URIs using dirname. src/vs/base/common/resources.ts changes only the URI path, preserving its query. - **Provider root cause:** extensions/git/src/uri.ts: fromGitUri reads the original file path from the unchanged query. FileService.toFileStat in src/vs/platform/files/common/fileService.ts enumerates children only for directories. Consequently, clicking an ancestor breadcrumb still resolves the original staged file and produces no picker entries.
