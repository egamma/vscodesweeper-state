# Issue #74891 — Expect minimap functionality and similar to xcode 11

[https://github.com/microsoft/vscode/issues/74891](https://github.com/microsoft/vscode/issues/74891)

## Summary

Keep this accepted feature request open: current minimap headers support comments and named regions, not automatic function and method labels. The 26 upvotes and renewed contribution interest justify an editor/minimap design discussion; the verified older outline-location request does not cover the same observable behavior.

## Change summary

Display function and method names in the minimap so users can locate definitions quickly without adding manual section comments.

## Best solution

Agree on an optional, language-aware minimap presentation using existing document symbols, then extend the core minimap behavior without changing existing region/comment headers or adding symbol-request overhead when disabled. Resolve labels versus highlighting and their interaction with existing headers before inviting implementation.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/sectionHeaders/browser/sectionHeaders.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/viewParts/minimap/minimap.ts`, `src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts`
- **Validation:** After agreeing on presentation, use a fake document-symbol provider returning functions and methods, including a nested method, to verify their minimap representation and updates after edits. Verify zero new symbol-provider requests when the feature is disabled, unchanged existing MARK/region headers, and a manual minimap check with densely spaced definitions and a complex C function signature.
- **Behavior:**

  > Users should be able to identify function and method definitions in the minimap without inserting MARK comments or regions. The thread proposes automatic names and alternatively unobtrusive highlighting; an editor owner must settle the presentation before acceptance criteria are finalized. Validate the chosen representation against document symbols, including nested methods and complex signatures, while preserving existing region/comment headers. The proposed opt-in behavior must leave the current default experience unchanged and avoid symbol-request overhead while disabled.
- **Trace:**

  > SectionHeaderDetector in src/vs/editor/contrib/sectionHeaders/browser/sectionHeaders.ts creates options from folding rules and minimap settings, then asks the editor worker to find section headers. src/vs/editor/common/services/findSectionHeaders.ts supports region markers and regex-derived comment headers; updateDecorations filters the latter to comment tokens, so custom regexes do not provide automatic function labels. InnerMinimap._renderSectionHeaders in src/vs/editor/browser/viewParts/minimap/minimap.ts renders core section-header decorations, while src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts provides existing symbol infrastructure not consumed by this detector. Preserve current MARK/region behavior and avoid requesting symbols solely for this feature when disabled. https://github.com/microsoft/vscode/issues/74891#issuecomment-5460484645 offers a focused contribution but asks for owner guidance; https://github.com/microsoft/vscode-cpptools/issues/14717 confirms the core ownership boundary. https://github.com/microsoft/vscode/issues/50047 is related outline-placement work, not a canonical for minimap overlays. The remaining uncertainty is product presentation and coexistence with existing headers, not whether a comment regex fully satisfies the request.
- **Open decisions:**
  - Should automatic function/method markers show readable symbol names, highlight definition locations without names, or expose both presentations?
  - How should automatic function/method markers coexist with existing region and MARK headers when their positions are close enough to overlap?
