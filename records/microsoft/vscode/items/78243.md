# Issue #78243 — String Settings UI: Multiple edits loses data on Save

[https://github.com/microsoft/vscode/issues/78243](https://github.com/microsoft/vscode/issues/78243)

## Summary

The bug appears to still exist on main — the settings tree uses virtualized rendering and template recycling, so when one list widget commits (triggering a re-render via `template.onChange`), other widgets in edit mode lose their uncommitted input. No fix commit references this issue.

## Change summary

Editing multiple string array settings simultaneously in the Settings UI causes uncommitted data to be lost when one edit is committed.

## Best solution

Either prevent multiple list-setting widgets from being in edit mode simultaneously (cancel other edits when a new 'Add Item' is clicked), or preserve uncommitted edit state across re-renders in the settings tree. The fix would live in `src/vs/workbench/contrib/preferences/browser/settingsTree.ts` and/or `settingsWidgets.ts`.
