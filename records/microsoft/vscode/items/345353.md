# Issue #345353 — Agents window renderer OOM: _resolvePathUncached walks every parent of a huge tool-call path

[https://github.com/microsoft/vscode/issues/345353](https://github.com/microsoft/vscode/issues/345353)

## Summary

Keep open: current main still admits oversized tool-input paths and retains every parent prefix during customization resolution. The traced allocation path, together with the reported 12 matching renderer crashes and restart loop, warrants urgent attention.

## Change summary

Prevent customization-reference extraction from exhausting renderer memory when tool input contains an enormous path-like token.

## Best solution

Make customization path processing and retained resolution metadata bounded for pathological tool input, while preserving ordinary customization matching and cache invalidation. Address this in the shared chat customization resolver rather than plugin synchronization or the model provider.
