[https://github.com/microsoft/vscode/issues/162081](https://github.com/microsoft/vscode/issues/162081)

## Summary

The central mismatch remains on main: the command is universally available, but its storage path only gathers changes reported by SCM repositories. A notification now reports that no changes were stored, so the failure is no longer silent, but the invalid command affordance remains.

## Change summary

Avoid offering Store Working Changes in Cloud when an opened folder has no source-control repository whose changes can be stored.

## Best solution

Add an SCM-aware precondition to `workbench.editSessions.actions.storeCurrent`, while preserving the existing no-changes notification for repositories with no pending changes.
