# Issue #32856 — Inline text adornments break word wrapping

[https://github.com/microsoft/vscode/issues/32856](https://github.com/microsoft/vscode/issues/32856)

## Summary

A meaningful wrapping gap remains for inline adornments whose rendered width is not represented during line-break computation. This accepted Backlog request has 218 upvotes and is already routed correctly.

## Change summary

Make word wrapping account for the visual width of inline text adornments so decorated lines do not overflow horizontally.

## Best solution

Extend the editor's line-projection contract so every layout-affecting adornment declares its footprint before wrapping, building on injected text without regressing wrapping performance. Cover CSS-generated before/after decorations as well as native inlay hints and color decorators.

## Evidence

- **current source gap:** src/vs/editor/common/viewModel/inlineDecorations.ts adds `beforeContentClassName` and `afterContentClassName` decorations after model-to-view projection, so their CSS-rendered width is not available to the wrapping calculation.
- **partial capability:** src/vs/editor/common/viewModel/monospaceLineBreaksComputer.ts applies `LineInjectedText` before computing break offsets, and src/vs/editor/common/modelLineProjectionData.ts explicitly models wrapping after injections. This covers declared injected text but not arbitrary CSS adornment width.
- **partial implementation:** https://github.com/microsoft/vscode/pull/126582 introduced injected text in commit 74dbd028059aa8bc82d1cee24f49dc24692d77d2; commit 8b0ea7ddd9140e7893c7ef902f57d598771c2dda later migrated built-in color decorators to it, but neither references or fully resolves this broader issue.
