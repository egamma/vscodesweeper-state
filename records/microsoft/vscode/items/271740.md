# Issue #271740 — Freeze on "Summarizing conversation history"

[https://github.com/microsoft/vscode/issues/271740](https://github.com/microsoft/vscode/issues/271740)

## Summary

Keep this open as the canonical summarization performance bug. Multiple users confirmed pauses around 100 seconds, and current main still has a path that waits for an in-progress compaction request without a local completion deadline.

## Change summary

Long-running agent conversations can become unresponsive for roughly 100 seconds or longer while conversation history is summarized.

## Best solution

Ensure conversation compaction normally completes in the background and define bounded foreground behavior when it is still running at prompt-budget exhaustion, so a slow model response cannot leave the agent apparently frozen.

- **Behavior:**

  > After a long conversation reaches the compaction threshold, a slow summarization request must not leave the agent indefinitely blocked with only a compaction status. When compaction finishes promptly, the summarized context is applied normally. When it remains slow, the agent follows the maintainer-selected bounded fallback behavior, while explicit cancellation continues to stop the request. Acceptance requires a deterministic deferred-promise test for both prompt completion and cancellation.
- **Trace:**

  > Conversation rendering in extensions/copilot/src/extension/intents/node/agentIntent.ts starts background compaction before the context budget is exhausted. If rendering later raises `BudgetExceededError` while that compaction is still in progress, lines 924-934 await `BackgroundSummarizer.waitForCompletion()` before proceeding. That method in extensions/copilot/src/extension/prompts/node/agent/backgroundSummarizer.ts awaits the model-backed promise without its own deadline, matching the reported long pause when the single summarization request is slow. The uncertainty starts at the foreground fallback contract once the budget is exhausted. Keep summary-content quality, successful fast compaction, manual compaction, and ordinary request cancellation outside the behavioral change; https://github.com/microsoft/vscode/issues/285511 separately tracks richer progress feedback.
- **Open decisions:**
  - When compaction is still running at prompt-budget exhaustion, should the foreground turn continue waiting for full summarized context, or switch after a bounded interval to a truncation or other reduced-context fallback?
  - What maximum foreground pause should users observe before that fallback takes effect?
