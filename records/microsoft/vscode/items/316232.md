# Issue #316232 — sessions: move remote host options out of providers layer

[https://github.com/microsoft/vscode/issues/316232](https://github.com/microsoft/vscode/issues/316232)

## Summary

The reported layering violation remains on current main: the workspace picker still imports four remote-host helpers from provider internals under an ESLint suppression. Keep this accepted architectural cleanup open; the maintainer discussion supports a generic connection abstraction, but the migration boundary still needs design.

## Change summary

Remove the workspace picker's dependency on remote-agent-host provider internals while preserving host status and management behavior.

## Best solution

Have shared picker code consume provider-neutral connection information and contributed management actions, with transport-specific management remaining provider-owned. Follow the maintainer's agreement that connection can be a generic provider concept without exposing agent-host-specific details through the shared contracts.
