## Summary

Team-authored debt issue; the layering violation is still present on current main (the eslint-disable suppression and the direct import from `contrib/providers/remoteAgentHost/` remain in `sessionWorkspacePicker.ts`). Keep open for the team to resolve.

## Change summary

Move remote host option utilities out of the providers layer so that `sessionWorkspacePicker.ts` no longer violates the sessions contrib layering rules.

## Best solution

Refactor by either (a) moving the utility functions (`getStatusHover`, `getStatusLabel`, `removeRemoteHost`, `showRemoteHostOptions`) behind the `ISessionsProvider` contract or a generic service, or (b) having the `remoteAgentHost` provider contribute its UI via menus/commands rather than exporting functions consumed by the chat feature layer. The team discussion leans toward bringing connection-state concepts into `ISessionsProvider` as a generic concept.
