# Issue #339088 — Tool grouping/virtual tools broken for custom endpoints

[https://github.com/microsoft/vscode/issues/339088](https://github.com/microsoft/vscode/issues/339088)

## Summary

Plausible but unverified: the tool-grouping/virtual-tools pipeline (extensions/copilot/src/extension/tools/common/virtualTools) has several designed safeguards against exceeding the 128-tool limit (deterministic trimming in toolGrouping.ts, a client-side validation error in chatMLFetcher.ts, and a fallback to non-embedding grouping when the embedding model is unavailable), so I can't pin down from source alone why a BYOK/custom endpoint session would bypass all of them — more detail is needed before this can be diagnosed further.

## Change summary

On Insiders 1.140/1.141, starting a new chat session with a custom BYOK endpoint (OpenRouter, DeepSeek) immediately fails with a 128-tool-limit error, while hosted Copilot models work fine.

## Best solution

A maintainer or an agent session with BYOK test credentials should reproduce against a custom endpoint and trace whether `supportsToolSearch`/the embedding-availability check in `toolEmbeddingsComputer.ts` and `_processToolset` in `virtualToolGrouper.ts` behaves differently for BYOK models versus hosted ones — if grouping silently throws or is skipped for BYOK, add the same fallback/guard used for hosted endpoints.

## Evidence

- **trim safeguard:** extensions/copilot/src/extension/tools/common/virtualTools/toolGrouping.ts `_doCompute` trims tool count down to HARD_TOOL_LIMIT (128) every compute, independent of model/endpoint.
- **client-side guard:** extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts `isValidChatPayload` rejects (with a friendlier message) requests whose `tools.length > HARD_TOOL_LIMIT && !endpoint.supportsToolSearch`, which should also apply to BYOK endpoints unless they use a different send path.
- **embedding fallback:** extensions/copilot/src/extension/tools/common/virtualTools/virtualToolGrouper.ts `_processToolset` falls back to `_createFallbackTools` (deterministic grouping) when `isEmbeddingModelAvailable()` is false, which is the likely state for a non-Copilot-entitled BYOK session — so grouping shouldn't be skipped outright.
- **literal error text:** The reported message "You may not include more than 128 tools in your request" doesn't match either of VS Code's own guard messages, suggesting the request may be reaching the custom provider's API directly without VS Code's client-side tool-count validation — needs confirmation with debug logs.
