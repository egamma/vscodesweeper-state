# Issue #344935 — Copilot harness: in-Chat terminals are more difficult to follow and cancel by default

[https://github.com/microsoft/vscode/issues/344935](https://github.com/microsoft/vscode/issues/344935)

## Summary

Keep open: foreground command cancellation and terminal-like output remain meaningful gaps, especially on Windows where the suggested terminal override is unsupported. Related issues cover portions of the request but do not establish a same-symptom canonical for its full scope.

## Change summary

Make Copilot harness commands easier to follow live, cancel individually, and inspect in VS Code.

## Best solution

Provide reliable live command output and discoverable per-command cancellation in the default Copilot terminal experience, including Windows. Establish the intended interactive-terminal contract with the SDK before implementing parity changes.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/node/copilot/copilotNonPtyShellTerminals.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostBackgroundShells.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`
- **Validation:** On Windows with default Copilot terminal settings, compare a long-running Nx command with Local: observe output before completion and exercise individual command cancellation. Also check a periodically printing command such as ping -n 10 127.0.0.1, and verify existing background-shell Stop behavior remains unchanged.
- **Behavior:**

  > Copilot commands should be followable while running and individually stoppable without cancelling unrelated work. The reporter compares Local's interactive terminal with Copilot's default shell and reports absent live output and no convenient foreground cancellation on Windows. Acceptance must cover the default Windows experience rather than relying on an unsupported opt-in override; process visibility is a secondary part of the request.
- **Trace:**

  > CopilotAgentSession forwards SDK partial-result snapshots and shell-output chunks into NonPtyShellTerminalStreams, which projects output-only terminal channels. The existing stopBackgroundWork path resolves published background-shell metadata and calls the SDK tasks.cancel RPC; it does not establish a foreground per-command cancellation contract. The experimental chat.agentHost.customTerminalTool.enabled setting is default-off and explicitly unsupported on Windows. The trace establishes host plumbing but not whether Nx buffers because of non-PTY execution or whether the SDK exposes sufficient foreground control. Preserve background-shell behavior and unrelated command execution. https://github.com/microsoft/vscode/issues/315191 supplies broader parity context; https://github.com/microsoft/vscode/issues/316976 and https://github.com/microsoft/vscode/issues/317789 cover related output problems, not proven duplicates of this whole request.
- **Open decisions:**
  - Should default Copilot commands provide interactive terminal semantics comparable to Local, or remain output-only with explicit individual cancellation controls?
  - Should stopping a foreground command end only that process and let the agent continue, or also stop the current agent turn?
