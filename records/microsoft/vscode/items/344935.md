# Issue #344935 — Copilot harness: in-Chat terminals are more difficult to follow and cancel by default

[https://github.com/microsoft/vscode/issues/344935](https://github.com/microsoft/vscode/issues/344935)

## Summary

Keep open: current source supports streamed shell output and background-shell stopping, but these do not deliver foreground per-command cancellation or interactive terminal parity on Windows. The latest contributor response leaves the Nx output behavior unresolved, and the related issues do not absorb the full request.

## Change summary

Make Copilot-harness commands easier to follow live and cancel individually, with terminal interaction comparable to the Local harness.

## Best solution

Provide discoverable command-level cancellation and dependable live output in the default Copilot harness, including Windows. Diagnose the Nx output difference separately from transport streaming, and coordinate terminal visibility with the existing background-shell proposal without losing foreground requirements.

- **Behavior:**

  > Users should be able to follow a running Copilot command and cancel that individual command through a discoverable control, including on Windows without the unsupported custom-terminal override. Preserve existing background-shell stopping and ordinary completed-command output. Acceptance should establish live rendering with a deterministic periodic-output command and isolate whether Nx's different presentation comes from non-TTY execution or output handling. Read-only background-shell visibility alone does not satisfy foreground cancellation.
- **Trace:**

  > CopilotAgentSession forwards SDK onToolShellOutput events to NonPtyShellTerminalStreams, which supplies output-only terminal channels rather than PTYs. Foreground commands are excluded from _toBackgroundWork, while stopBackgroundWork targets only published background entries through session.rpc.tasks.cancel; the workbench background-shell control consumes those stop handles. CopilotSessionLauncher explicitly excludes Windows from chat.agentHost.customTerminalTool.enabled, so the suggested workaround cannot address the reporter's environment. The current source establishes streaming support but does not establish the cause of Nx's observed output difference or the SDK contract needed for foreground cancellation. Preserve existing background-stop behavior, provider-neutral addressing, and current execution protections; do not assume output-only channels accept Ctrl+C. Coordinate with https://github.com/microsoft/vscode/issues/349269 for background visibility and https://github.com/microsoft/vscode/issues/315191 for broader integration, without treating either as completion of this request.
- **Open decisions:**
  - Should foreground command cancellation be offered as a standalone stop control on the existing non-PTY shell surface, or is interactive terminal input part of the required user-facing contract?
