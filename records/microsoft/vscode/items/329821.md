# Issue #329821 — Feature: Enhance server CLI argument error handling and strict exit codes in server.main.ts

[https://github.com/microsoft/vscode/issues/329821](https://github.com/microsoft/vscode/issues/329821)

## Summary

This is a valid, currently unrouted feature request for fail-fast server CLI validation. Current main intentionally reports malformed arguments and recovers, but the record does not establish that fatal errors and dedicated exit codes have been rejected as designed.

## Change summary

Make duplicate or empty VS Code Server CLI arguments terminate startup with explicit exit codes and clearer diagnostic categories.

## Best solution

Define a consistent server CLI validation contract covering which malformed arguments are fatal, whether distinct exit codes are stable public behavior, and whether the same policy applies to both server startup and the spawned server CLI before implementing it with parser-level tests.

## Evidence

- **current source:** src/vs/server/node/server.main.ts defines an ErrorReporter that logs duplicate, empty, unknown, and deprecated options, then continues with the result of parseArgs.
- **parser behavior:** src/vs/platform/environment/node/argv.ts deliberately recovers from duplicate string options by retaining the last value and from disallowed empty values by removing them, while reporting both conditions through callbacks.
- **existing precedent:** Commit 80d30e41d790c774230b00dd480895d55451d967 implemented https://github.com/microsoft/vscode/issues/150714 by adding warnings for empty arguments, including the server CLI. That proves the current recovery behavior is deliberate, but it does not settle the newer request for a strict mode or exit-code contract.
- **cross-surface consistency:** src/vs/server/node/server.cli.ts uses the same recover-and-log behavior, so changing only server.main.ts could give the two server CLI entry paths inconsistent validation semantics.
- **routing:** The existing microsoft/vscode labels `server` and `workbench-cli` cover the affected server startup and command-line behavior; the issue currently has no labels.
