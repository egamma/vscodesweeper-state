# Issue #50840 — Support folding ranges inside a line

[https://github.com/microsoft/vscode/issues/50840](https://github.com/microsoft/vscode/issues/50840)

## Summary

Inline folding remains unsupported by the current folding API and editor pipeline. Keep this accepted Backlog request open: it has 172 upvotes, and an open implementation PR references it but explicitly leaves additional work.

## Change summary

Support character-position folding ranges so extensions can collapse portions of a line, including Markdown link destinations.

## Best solution

Provide native character-range folding with correct cursor movement and model-to-view mapping, exposed to extension folding providers. Review the partial implementation in https://github.com/microsoft/vscode/pull/170447 and determine the remaining work before treating this request as completed.

## Evidence

- **Current API limitation:** src/vscode-dts/vscode.d.ts:5735–5769 documents FoldingRange as line-based and exposes only start/end line numbers and kind; no character positions are available.
- **Current editor limitation:** src/vs/editor/contrib/folding/browser/syntaxRangeProvider.ts, collectSyntaxRanges, accepts only ranges with r.end > r.start, rejecting single-line ranges. src/vs/editor/common/viewModel/viewModelLines.ts:178–180 normalizes hidden areas through normalizeLineRanges, retaining the line-based hiding model.
- **Existing capability check:** The folding settings registered in src/vs/editor/common/config/editorOptions.ts include editor.folding, editor.foldingStrategy, editor.foldingHighlight, editor.foldingImportsByDefault, editor.foldingMaximumRegions and editor.showFoldingControls. These control line folding and do not enable character-range folding.
- **Maintainer position and workaround:** In the discussion at https://github.com/microsoft/vscode/issues/50840, aeschli explains that hidden character ranges require extending the view model for rendering and cursor movement, and confirms in August 2022 that native support must be implemented in core. The Inline Fold and TypeScript Fold extensions cited by commenters are decoration-based workarounds, not native FoldingRange support.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/170447 is OPEN. Its description explicitly references this issue as work it partially advances, introduces startColumn and collapsedText, and states that its inline ranges currently fold only to the end of a line. It does not claim to complete arbitrary inline folding.
- **Canonical search:** An open-issue search for inline folding returned this issue and related narrower requests. Verified https://github.com/microsoft/vscode/issues/3352 is open, but it asks to bring closing braces onto the folded opening line; it does not cover hiding arbitrary same-line ranges such as Markdown URLs and therefore does not satisfy the re-reviewed-item duplicate bar.
- **Accepted demand:** https://github.com/microsoft/vscode/issues/50840 carries feature-request and editor-folding, is assigned to Backlog, and has 172 community upvotes. Neither inactivity nor the existence of extension workarounds supports declining this accepted core capability.
