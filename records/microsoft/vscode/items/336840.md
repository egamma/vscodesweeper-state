# Issue #336840 — Ensure enterprise Copilot OTel settings override environment variables

[https://github.com/microsoft/vscode/issues/336840](https://github.com/microsoft/vscode/issues/336840)

## Summary

Exact duplicate of https://github.com/microsoft/vscode/issues/336839, filed by the same bot 5 seconds earlier from the same Slack thread with byte-identical title and body, and already assigned there — closing this one and consolidating on the original.

## Change summary

Enterprise-managed Copilot OTel settings (enablement, endpoint, protocol, content capture, service name, attributes/headers) can be overridden by process environment variables because the resolver feeds policy-backed defaults through the ordinary `setting*` inputs instead of the `policy*` inputs to `resolveOTelConfig`.

## Best solution

Track and land the fix on the canonical https://github.com/microsoft/vscode/issues/336839 (already assigned): change `resolveOTelConfigFromSettings` in extensions/copilot/src/platform/otel/common/otelConfigResolution.ts to pass `read()` results through the `policy*` fields of `OTelConfigInput` when `hasEnterpriseSettings` is true, so `resolveOTelConfig`'s existing policy>env precedence in otelConfig.ts actually applies.
