# Issue #248962 — Bad tab sizing with Editor Tab Wrap enabled

[https://github.com/microsoft/vscode/issues/248962](https://github.com/microsoft/vscode/issues/248962)

## Summary

The screenshot matches current wrapped-tab sizing: the last fit-sized tab on each non-final row deliberately expands into the remaining space. This is established behavior, but the existing bug classification bars an as-designed close without a later maintainer decision, so the workbench-tabs owner should reassess the visual tradeoff.

## Change summary

Keep fit-sized editor tabs near their content width when wrapping instead of stretching row-ending tabs across unused space.

## Best solution

The workbench-tabs owner should decide whether `workbench.editor.tabSizing: "fit"` should preserve content-based widths on every wrapped row or retain the current gap-filling treatment. If changed, keep `shrink` and `fixed` sizing semantics unaffected and cover the chosen row-width behavior in the editor tab layout tests.

- **historical design:** https://github.com/microsoft/vscode/issues/113801 documents the tradeoff and commit https://github.com/microsoft/vscode/commit/3c62a8f898b79dfe2ce384d3c333fb06486119db intentionally limited expansion to the last tab of each non-final row to avoid uneven gaps.
- **remaining gap:** `workbench.editor.tabSizing: "shrink"` avoids this expansion but changes sizing semantics and can truncate labels, so it does not fully satisfy the request for content-sized wrapped tabs.
