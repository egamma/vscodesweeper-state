# Issue #248962 — Bad tab sizing with Editor Tab Wrap enabled

[https://github.com/microsoft/vscode/issues/248962](https://github.com/microsoft/vscode/issues/248962)

## Summary

The reported stretching is intentional: VS Code expands the final tab of each completed wrapped row to avoid uneven gaps. Maintainers previously reviewed this exact visual behavior and kept the current layout by design.

## Change summary

Avoid making tabs substantially wider than their labels when editor tabs wrap onto multiple rows.

## Best solution

Keep the existing row-filling behavior as the default; users wanting more compact tabs can set `workbench.editor.tabSizing` to `shrink`.

## Evidence

- **maintainer decision:** https://github.com/microsoft/vscode/issues/194109 reports the same overly wide wrapped-tab symptom; maintainers closed it as `*as-designed`, explaining that filling completed rows avoids a zig-zag pattern of uneven gaps.
- **current implementation:** src/vs/workbench/browser/parts/editor/media/multieditortabscontrol.css intentionally applies `flex-grow: 1` to `.sizing-fit.last-in-row:not(:last-child)` while wrapping, with a comment stating that this creates a more homogeneous appearance.
- **design history:** Commit 3c62a8f898b79dfe2ce384d3c333fb06486119db implemented the current compromise for https://github.com/microsoft/vscode/issues/113801: completed rows fill their remaining width, while the final row does not.
- **existing option:** src/vs/workbench/browser/workbench.contribution.ts registers `workbench.editor.tabSizing`; its `shrink` value allows tabs to become smaller, and the corresponding CSS caps them at their content width.
