## Summary

The current source confirms that dropped file paths bypass bracketed paste even when the terminal application enables it. Route to the terminal area and keep open while the linked implementation PR is reviewed.

## Change summary

Non-executing file drops should respect enabled bracketed paste mode without appending Enter.

Review https://github.com/microsoft/vscode/pull/347648 for the narrowly scoped path-insertion fix, preserving executing paths and ordinary terminal key sequences.

## Evidence

- **Current source confirms the failing path:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1297–1300 handles file drops with sendPath(path, false). At lines 1447–1449, sendPath calls sendText without its third argument; lines 1418–1423 require that argument plus xterm.raw.modes.bracketedPasteMode to emit paste delimiters. Consequently, the reporter's file-drop trigger cannot receive those delimiters through this path.
- **Existing non-executing insertion policy:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1073–1075 explicitly opts runCommand into bracketed paste for non-executing text. The analogous sendPath insertion omits that opt-in.
- **Reproduction evidence:** https://github.com/microsoft/vscode/issues/347647 supplies an extension-disabled byte-capture reproduction contrasting an unbracketed dropped path with bracketed clipboard input. This review confirmed the source path without executing tests or modifying the checkout.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/347648 is open and targets non-executing sendPath insertions, with proposed coverage for bracketed paste enabled/disabled and insert/execute behavior. It is not a landed fix; the issue should remain open and no competing agent implementation is appropriate.
- **Historical regression boundary:** https://github.com/microsoft/vscode/pull/154958 reverted unconditional bracketed paste after https://github.com/microsoft/vscode/issues/154863 reported broken terminal key sequences. Its maintainer explanation calls for optional application; that precedent does not reject this narrower non-executing file-insertion case.
