# Issue #312363 — RunInTerminalTool hangs forever when trackIdleOnPrompt is stuck in Executing state

[https://github.com/microsoft/vscode/issues/312363](https://github.com/microsoft/vscode/issues/312363)

## Summary

The described hang — state machine stuck in Executing with both schedulers cancelled — has been fixed on main through a series of commits culminating in an `executingFallbackScheduler` that fires after 30s of data-idle in Executing state, plus a hard-cap safety net. The original PR #312375 was closed, but the fix landed via PR #312387 (64e09196a3e) and subsequent hardening in #312854 (8894b02366e) and #313312 (ade6340a22b).

## Change summary

RunInTerminalTool hangs forever when shell integration fails to emit a prompt sequence after a command finishes, leaving the trackIdleOnPrompt state machine stuck in Executing state with no recovery path.

## Best solution

Keep the shipped fixes; the `executingFallbackScheduler` (30s data-idle fallback in Executing state) and hard-cap scheduler (5min wall-clock safety net) directly address the reported dead state. No further change needed.
