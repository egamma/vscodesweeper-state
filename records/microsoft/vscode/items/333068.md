# Issue #333068 — Session artifact pills - Show references as a separate item in the response body/footer, instead of as an artifact pill

[https://github.com/microsoft/vscode/issues/333068](https://github.com/microsoft/vscode/issues/333068)

## Summary

Current main still presents session references as persistent pills above the prompt, while response-level reference UI already exists elsewhere in chat. This team-authored design item should remain open because placement and attribution semantics are unresolved.

## Change summary

Move session references out of the artifact-oriented prompt-box pill row and present them with the response body or footer.

## Best solution

Keep generated artifacts as the leading actionable pills while presenting consulted files and websites as quieter response-level supporting information, preserving open, removal, keyboard, and screen-reader behavior.

- **Behavior:**

  > References consulted by an agent should support a response rather than compete with generated artifacts in the prompt-box pill row. Generated artifacts must remain prominent and actionable. The selected response-level presentation must expose referenced files, websites, commits, pull requests, and issues with their existing open and removal behavior, and it must remain keyboard and screen-reader accessible in both session chat surfaces.
- **Trace:**

  > SessionArtifacts in src/vs/sessions/contrib/chat/browser/sessionArtifacts.ts already partitions entries by `isArtifact` into `sections` and `referenceSections`. SessionChatInputToolbar and AgentHostSessionInputPills currently feed `referenceSections` into `StandardChatInputPillSources`, which places them above the prompt. ChatUsedReferencesListContentPart provides an existing response-level collapsible-reference presentation, but ChatListRenderer suppresses response `references` for default non-Ask agents, and session metadata currently describes a session-wide collection rather than an obvious per-turn collection. Keep artifact, pull-request, issue, browser, and changes pills unchanged; the scope is the presentation and attribution of entries whose `isArtifact` value is false. The broader UX tracker is https://github.com/microsoft/vscode/issues/333071.
- **Open decisions:**
  - Should a recorded reference appear on the specific response that introduced it, or should the response footer expose the session-wide reference set?
  - Should references use an inline/collapsible section in the response body or a compact response-footer control?
  - When the same reference is used by multiple responses, should it appear on each response or only at its first occurrence?
