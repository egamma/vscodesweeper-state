# Issue #341825 — Restored terminal editors on remotes reattach by saved process ID only

[https://github.com/microsoft/vscode/issues/341825](https://github.com/microsoft/vscode/issues/341825)

## Summary

Keep open: current main still restores remote terminal editors by their saved persistent ID without consulting revival mappings or checking the saved PID. The WSL confirmation supports the reported cross-window attachment symptom, and the source establishes the missing remote safeguards.

## Change summary

Restored remote terminal editors can attach to another window's live terminal when persistent process IDs are reused after a remote pty-host restart.

## Best solution

Remote terminal editor restoration should resolve workspace-scoped revived process identities and apply the existing saved-PID fallback semantics used locally. Preserve ordinary terminal attachment and create a fresh terminal when the saved process identity no longer matches.
