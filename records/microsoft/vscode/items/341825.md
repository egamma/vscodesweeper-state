# Issue #341825 — Restored terminal editors on remotes reattach by saved process ID only

[https://github.com/microsoft/vscode/issues/341825](https://github.com/microsoft/vscode/issues/341825)

## Summary

Confirmed in current source: the remote branch of TerminalProcessManager.createProcess calls attachToProcess(id) without the revived-ID or pid check, and RemoteTerminalBackend.attachToRevivedProcess is unused and its channel arguments don't match PtyService. This is a real follow-up to the local-only fix and stays open.

## Change summary

Restored terminal editors on remotes reattach by saved persistent process ID only, so they can attach to the wrong terminal after a remote server restart.

## Best solution

Route remote terminal editors through attachToRevivedProcess(id, pid). Make RemoteTerminalBackend match LocalTerminalBackend, and fix the channel client to send [workspaceId, id] for getRevivedPtyNewId and [id, pid] for attachToProcess. Add remote backend tests.
