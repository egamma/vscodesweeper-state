Traced VS Code's built-in link detector and it structurally cannot flag a `//`+asterisks line as a link, so `editor.links` core code isn't the culprit; the reporter's own hover text ('shows an include member') plus their installed mainframe language extensions point to an extension-contributed link provider instead.

## Change summary
