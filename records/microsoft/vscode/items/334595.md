# Issue #334595 — *'s being interpreted as a link

[https://github.com/microsoft/vscode/issues/334595](https://github.com/microsoft/vscode/issues/334595)

## Summary

Core's built-in link detector only matches http://, https://, and file:// prefixed text, so it cannot be flagging a bare line of `*` characters as a link — traced in src/vs/editor/common/languages/linkComputer.ts. Links shown in the editor are the union of that detector and any language-specific DocumentLinkProvider (src/vs/editor/contrib/links/browser/getLinks.ts uses a LanguageFeatureRegistry<LinkProvider>), and the reporter's own hover text ("shows an include member") plus their installed extensions (IBM Z Open Editor, Rexx/OPS-REXX language support, Zowe Explorer — all mainframe COPY/INCLUDE copybook tooling) point to one of those extensions' link providers misfiring on comment-asterisk lines.

## Change summary

A line consisting only of `//` followed by asterisks is underlined and offered as a followable link, even though it contains no URL or path.

## Best solution

Ask the reporter to confirm with the mainframe-related extensions (IBM Z Open Editor, Rexx/OPS-REXX Language Support, Zowe Explorer) disabled, and if the false link disappears, file it against that extension's own repository — core's link detector requires an http/https/file scheme prefix and cannot produce this match on its own.
