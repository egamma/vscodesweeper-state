## Summary

The false link isn't from VS Code's built-in link detector — the hover text 'include member' is a custom tooltip that only a language-contributed DocumentLinkProvider can supply, and the installed extensions include mainframe-language tools (IBM Z Open Editor, Rexx Language Support, OPS/REXX) that model COPY/INCLUDE members; core's own link computer only matches http(s)/file schemes and would never flag a bare comment line of asterisks.

## Evidence

- **core link computer scope:** src/vs/editor/common/languages/linkComputer.ts's state machine (getStateMachine()) only recognizes links starting with http://, https://, or file:// — a line of `//` plus asterisks with no such prefix can never enter State.Accept, so the default provider would not flag it.
- **custom tooltip requires a provider:** src/vs/editor/contrib/links/browser/links.ts:362-368 (getHoverMessage) only shows non-generic text when `link.tooltip` is set by the DocumentLink itself; the generic core message is just 'Follow link' with a keybinding hint, never 'include member'. That specific wording is domain vocabulary (COPY/INCLUDE members) from a mainframe-language extension's own DocumentLinkProvider, aggregated in via getLinks() alongside the default provider (links.ts:135).
- **installed extensions:** The reporter's extension list includes IBM Z Open Editor, Rexx Language Support (BroadcomMFD), and OPS/REXX Language Support (broadcomMFD) — all of which implement COBOL/PL1/REXX 'COPY'/'%INCLUDE' member navigation and are plausible sources of a buggy link/hover for an asterisk-comment line. None of these are VS Code-team-owned extensions.
