# Issue #297309 — CTRL-F freezes terminal with large history on initial search

[https://github.com/microsoft/vscode/issues/297309](https://github.com/microsoft/vscode/issues/297309)

## Summary

Still reproduces on main: terminal find calls xterm's SearchAddon.findNext synchronously on each keystroke with no debouncing or cancellation, so short patterns against large scrollback (100k lines) trigger a UI freeze from mass highlighting. No fix found in git history.

## Change summary

CTRL-F in the terminal freezes the UI when searching large scrollback buffers with short (1–3 character) patterns due to synchronous search and highlight of thousands of matches.

## Best solution

Add input debouncing and/or a minimum-character threshold before triggering findNext on the xterm SearchAddon when scrollback is large; alternatively, investigate whether xterm's addon-search can perform highlighting incrementally or with a match-count cap. The fix likely lives in `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts` (the `findNext`/`findPrevious` passthrough) or as an upstream xterm.js enhancement.
