# Issue #275411 — Some of the links in the codex chat session response don't appear to work and they should probably not be linkified.

[https://github.com/microsoft/vscode/issues/275411](https://github.com/microsoft/vscode/issues/275411)

## Summary

Still a valid polish issue. The inline-code symbol linkifier can resolve non-project tokens like `powershell.exe` to spurious dead links. Related improvements (e.g. the natural-language skip in 87e70edaa27) address multi-word phrases but not single-word system executables. No commit references this issue.

## Change summary

Inline-code tokens like `powershell.exe` in chat responses are linkified as clickable symbols even though they don't resolve to anything in the workspace, producing no-op links.

## Best solution

Extend the linkifier's skip logic (in `extensions/copilot/src/extension/linkify/vscode-node/inlineCodeSymbolLinkifier.ts`) to avoid linkifying tokens that don't actually resolve to a navigable location — e.g. skip when `tryResolveSymbol` returns no locations, or filter out well-known system executable patterns. The fix lives in the Copilot linkify layer.
