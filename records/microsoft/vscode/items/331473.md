# Issue #331473 — Dark 2026: ordinary variables are visually indistinguishable from plain text - looks like syntax highlighting is not applied

[https://github.com/microsoft/vscode/issues/331473](https://github.com/microsoft/vscode/issues/331473)

## Summary

Verified against the theme source: `variable.other` is set to `#c9d1d9` (extensions/theme-defaults/themes/2026-dark.json:432-434) while `editor.foreground` is `#BBBEBF` (line 109) — a real, near-imperceptible contrast for one of the most common token classes. This sits in the middle of active, unresolved discussion about Dark 2026 variable coloring, so it should be routed to that ongoing conversation rather than closed.

## Change summary

In the Dark 2026 theme, ordinary (mutable, non-const) variables render in a color so close to the general editor foreground that they look unstyled/unhighlighted.

## Best solution

Fold this into the ongoing Dark 2026 variable-color discussion (https://github.com/microsoft/vscode/issues/322000, https://github.com/microsoft/vscode/issues/326875, tracking issue https://github.com/microsoft/vscode/issues/295783) rather than treating it in isolation — the theme owners need to settle on one hue for mutable variables that both reads on a dark background and doesn't overstyle everyday code (the #320953 orange attempt was reverted in #322108 for being too aggressive). A tweak to the `variable.other` foreground in extensions/theme-defaults/themes/2026-dark.json is the likely fix once a hue is agreed.
