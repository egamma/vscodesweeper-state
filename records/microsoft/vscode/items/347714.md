# Issue #347714 — Bug: Shell initialization setting is ignored in Agents Window for local Copilot Harness sessions

[https://github.com/microsoft/vscode/issues/347714](https://github.com/microsoft/vscode/issues/347714)

## Summary

The difference is explicitly intentional in current source and covered by a dedicated test. Agents Window parity would extend the feature, although the setting description does not clearly explain this restriction.

## Change summary

Make the shell initialization setting load ~/.bashrc for new local Copilot sessions in the Agents Window.

## Best solution

Preserve the existing editor-window ownership of initialization scripts and clarify that limitation in the setting description. Supporting independent initialization in the Agents Window would require a deliberate change to that ownership contract.

- **Proposed comment:**

  > Thanks for the detailed report. This difference is intentional in the current implementation: `chat.agentHost.shellTool.initScript.enabled` enables initialization scripts published by the editor window, while the Agents Window deliberately does not publish them. A new session created there therefore does not load `~/.bashrc` through this feature.
  > 
  > The setting's “Local windows only” description does not make that restriction clear. Agents Window parity would be an extension of the current behavior rather than a failure to read your user setting.

## Evidence

- **Explicit Agents Window exclusion:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostShellInitSynchronizer.ts, AgentHostShellInitSynchronizer._publish: folder resolution requires !this._environmentService.isSessionsWindow; with the setting enabled and no qualifying folder, publication returns immediately. The adjacent comment explicitly says the Agents Window never publishes a non-empty script.
- **Intended behavior pinned by test:** src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostShellInitSynchronizer.test.ts contains 'does not publish a script from the Agents window even when it owns the session folder', asserting no dispatch with enabled: true and sessionsWindow: true. This establishes intentional behavior rather than an accidentally dropped setting.
- **Why the reported variable is absent:** src/vs/platform/agentHost/common/shellInitScript.ts, createBashInitScript, generates the command sourcing ~/.bashrc. src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, _applyEffectiveShellInitScripts, reads the session's ShellInitScripts payload and treats an absent payload as an empty list; enabling the root setting alone does not generate profile-loading commands.
- **Setting description ambiguity:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.agentHost.shellTool.initScript.enabled as an experimental, application-scoped setting with the description 'Local windows only.' It does not disclose the additional editor-window publication restriction.
