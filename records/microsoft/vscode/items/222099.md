# Issue #222099 — Persistent keys are not handled correctly on Windows

[https://github.com/microsoft/vscode/issues/222099](https://github.com/microsoft/vscode/issues/222099)

## Summary

VS Code reads modifier state directly from Chromium/Electron's KeyboardEvent properties (ctrlKey, altKey, etc.) at src/vs/base/browser/keyboardEvent.ts:148-151. When Windows Sticky Keys latches modifiers sequentially, Chromium may not propagate the latched state into subsequent key events — this is likely an upstream Chromium/Electron issue rather than something VS Code can fix in its own keybinding layer.

## Change summary

Windows Sticky/Persistent Keys modifier state is not reflected in VS Code keybinding detection when keys are pressed sequentially.

## Best solution

Investigate whether Chromium/Electron correctly sets ctrlKey/altKey on KeyboardEvents when Windows Sticky Keys are active. If it's a Chromium bug, file upstream; if not, VS Code could potentially use getModifierState() or track modifier latch state manually in StandardKeyboardEvent, but this would be a significant architectural change to the keybinding system.
