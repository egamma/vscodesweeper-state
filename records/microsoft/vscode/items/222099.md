# Issue #222099 — Persistent keys are not handled correctly on Windows

[https://github.com/microsoft/vscode/issues/222099](https://github.com/microsoft/vscode/issues/222099)

## Summary

Keep open: the report supplies sufficient Windows settings and keystrokes to retest, but source inspection cannot establish how Windows Sticky Keys reaches current Electron keyboard events. The input pipeline has changed since 1.91.1, and a related Sticky Keys failure was reconfirmed on 1.127.0; neither establishes that this exact case is fixed.

## Change summary

Sequential Ctrl, Alt, and Arrow Down with Windows Sticky Keys enabled should resolve like the same keys pressed simultaneously.

## Best solution

Reproduce the specified Sticky Keys configuration on current Windows VS Code and compare received, converted, and resolved keyboard events for sequential versus simultaneous input. Establish whether modifier state is lost before VS Code receives the event or within its keybinding pipeline, then address the responsible layer.

## Plan brief

- **Likely files:** `src/vs/base/browser/keyboardEvent.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/workbench/services/keybinding/common/windowsKeyboardMapper.ts`
- **Validation:** On Windows, enable Sticky Keys, enable modifier locking on double press, and disable turning Sticky Keys off when two keys are pressed together. With keyboard shortcut troubleshooting enabled, press and release Ctrl, then Alt, then Arrow Down; compare received/converted/resolved events and editor behavior with simultaneous Ctrl+Alt+Arrow Down. Both must resolve the same shortcut, and ordinary simultaneous shortcuts and modifier release behavior must remain unchanged.
- **Behavior:**

  > With the reported Windows Sticky Keys options enabled, pressing and releasing Ctrl, Alt, and Arrow Down sequentially is reported as Arrow Down alone, while simultaneous input registers the modifiers. Both input methods should resolve the same shortcut and produce the same editor behavior. Acceptance requires checking the shortcut recorder or troubleshooting output as well as the editor action on Windows. Normal modifier release and simultaneous shortcuts must remain unchanged.
- **Trace:**

  > WorkbenchKeybindingService._registerKeyListeners in src/vs/workbench/services/keybinding/browser/keybindingService.ts wraps each keydown in StandardKeyboardEvent, logs the original and converted events, and dispatches it. StandardKeyboardEvent in src/vs/base/browser/keyboardEvent.ts takes Ctrl/Alt state from the browser event; source inspection cannot determine whether Windows/Electron supplies the expected latched state. Keyboard resolution subsequently delegates to the platform mapper; the Windows implementation is src/vs/workbench/services/keybinding/common/windowsKeyboardMapper.ts. First establish the event boundary at which the two input methods diverge rather than assuming VS Code must synthesize sticky state. Preserve ordinary keyboard and single-modifier chord behavior. The related https://github.com/microsoft/vscode/issues/159275 concerns sequential Shift/F10 context-menu activation and has a recent confirmation, but equivalence to this case is not established.
