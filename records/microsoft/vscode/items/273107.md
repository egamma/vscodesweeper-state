## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/241529 is currently open and was created on 2025-02-21, before this report. Its reproduction sets PHP language mode and pastes `<a onclick="myfunc(<?php echo "'$owner'"; ?>)"></a>`, producing incorrect PHP quote coloring and corruption of the closing HTML attribute boundary.
- **Same observable symptom:** https://github.com/microsoft/vscode/issues/241529#issuecomment-2683133517 explicitly identifies mismatched colors on the PHP double quotes and highlighting bleeding into the onclick attribute's closing delimiter. This matches the supplied str_replace example: double quotes within PHP prematurely interrupt highlighting inside a double-quoted HTML event handler. The canonical is not merely a general tokenization tracking issue.
- **Current source path:** extensions/php/package.json registers text.html.php for PHP files; extensions/php/syntaxes/html.tmLanguage.json includes text.html.derivative and injects PHP into source.js. In extensions/html/syntaxes/html.tmLanguage.json:196-225, double-quoted event-handler contents are matched in chunks excluding double quotes and retokenized as source.js through captures. Consequently, the embedded PHP tokenizer receives a chunk ending before the PHP string's first double quote, while the enclosing HTML rule recognizes that quote as its attribute terminator. This traces the reported boundary failure without executing code.
- **Discussion and evidence to preserve:** The supplied discussion clarifies that PHP runs correctly and that server-side PHP parsing must take precedence until the closing PHP tag. This report adds Linux/VS Code 1.105.1 evidence and a str_replace("a", "the", $str) reproduction to the older Windows example; neither implies a distinct platform-specific defect.
- **Related report is not the canonical:** https://github.com/microsoft/vscode/issues/279756 is closed, newer, and was marked a duplicate of this issue by a maintainer at https://github.com/microsoft/vscode/issues/279756#issuecomment-3605802219. It cannot serve as a duplicate target.
