# Issue #216653 — VS Code does not send code action to LSP server on save when running on a notebook file

[https://github.com/microsoft/vscode/issues/216653](https://github.com/microsoft/vscode/issues/216653)

## Summary

Confirmed bug: the notebook save participant uses `CodeActionTriggerType.Invoke` instead of `CodeActionTriggerType.Auto`, causing LSP servers to filter out code actions on save. An open community PR (https://github.com/microsoft/vscode/pull/259762) addresses this. Keeping open for the PR to land.

## Change summary

Notebook code actions on save use the wrong trigger type (`Invoke` instead of `Auto`), preventing LSP servers like Ruff from responding to save-time code action requests.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/259762, which changes the trigger type for non-notebook-prefixed code actions to `CodeActionTriggerType.Auto` to match the regular editor save participant behavior. The fix is in `src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts`.

## Evidence

LSP servers like Ruff filter actions based on trigger type and won't return code actions for `Invoke`.
