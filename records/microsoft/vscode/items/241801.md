# Issue #241801 — WebView editor can dispatch keybinding when workbench does already

[https://github.com/microsoft/vscode/issues/241801](https://github.com/microsoft/vscode/issues/241801)

## Summary

Keep open: double editor navigation was confirmed by a maintainer and subsequent macOS reports, and no verified fix covers the reported shortcuts. The issue already has the appropriate webview and keybindings labels.

## Change summary

A single editor-navigation shortcut can advance two tabs when a webview is involved on macOS.

## Best solution

Ensure one physical editor-navigation keypress invokes its command exactly once across webview forwarding, workbench handling, and native menu accelerators. First reproduce on current main and distinguish the original workbench/webview race from the later accelerator-path reports.

- **Behavior:**

  > On macOS, one physical press of an editor-navigation shortcut must move exactly one editor, including when a webview has focus or focus changes during navigation. The original reproduction uses the same image in two editor groups and several text editors in one group, with Ctrl+Tab and Ctrl+Shift+Tab bound to editor cycling. Later reports also identify nextEditorInGroup and previousEditorInGroup with an additional native accelerator dispatch. Acceptance requires correlating physical input with exactly one command invocation while retaining ordinary text-editor navigation, menu commands, and intentional repeated input.
- **Trace:**

  > The maintainer-confirmed original reproduction records two workbench command stacks, one passing through ElectronWebviewElement.handleKeyEvent: https://github.com/microsoft/vscode/issues/241801#issuecomment-2684272856. Current handleInnerKeydown in src/vs/workbench/contrib/webview/browser/pre/index.html forwards navigation keydowns without consuming the real event; WebviewElement.handleKeyEvent in src/vs/workbench/contrib/webview/browser/webviewElement.ts replays an authenticated event only while the webview is active. Separately, menubar.ts attaches native accelerators and sends vscode:runKeybinding, which window.ts dispatches through the keybinding service. The uncertainty starts at whether current focus guards suppress the original race and whether the later accelerator double dispatch reproduces under the same setup. https://github.com/microsoft/vscode/pull/328022 was not merged and explicitly excludes these navigation shortcuts. Preserve event-authentication and focus guards, webview editing behavior, direct menu invocation, and web behavior; a blanket suppression of forwarded keyboard events is not an acceptable outcome.
