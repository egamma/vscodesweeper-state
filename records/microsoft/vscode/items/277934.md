# Issue #277934 — GitHub Copilot fails to process workspace when multiple identical copilot-instructions.md files are present

[https://github.com/microsoft/vscode/issues/277934](https://github.com/microsoft/vscode/issues/277934)

## Summary

The clarified report identifies a credible multi-root correctness bug, and current main still attaches every instruction file independently by URI even when their contents are identical. The issue is already routed to chat customizations and should remain open for a scoped design and fix.

## Change summary

A multi-root workspace with roughly 13 or more identical copilot-instructions.md files overwhelms Copilot's workspace context, causing answers to repeat instruction content instead of inspecting the workspace.

## Best solution

Avoid sending repeated instruction payloads while retaining the workspace-root applicability and relative-reference semantics of every file. The chat customizations owner should decide whether this is content deduplication or a shared-content representation before implementation.

A companion case with distinct contents must retain each distinct instruction payload.
- **Behavior:**

  > A multi-root workspace may contain the same copilot-instructions.md content in many repositories without repeatedly consuming request context or preventing Copilot from using workspace tools. Every workspace root covered by that content must still receive the instructions, including correct handling of relative references. Instruction files with genuinely different contents must remain distinct. Acceptance includes a multi-root regression test for identical files and a control case for distinct files.
- **Trace:**

  > PromptsService.listAgentInstructions in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts discovers one candidate per root and only deduplicates symlink targets. ComputeAutomaticInstructions._addAgentInstructions in src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts always adds every candidate. toPromptFileVariableEntry and ChatRequestVariableSet in src/vs/workbench/contrib/chat/common/attachments/chatVariableEntries.ts deduplicate by URI-derived ID, so byte-identical files at different roots survive as separate request variables. Existing tests cover individual instruction discovery but do not cover repeated identical files across many roots. The boundary is instruction collection and request representation; workspace-folder discovery and distinct instruction semantics must not change.
- **Open decisions:**
  - Should identical instructions be attached once globally, or represented once with an explicit set of applicable workspace roots so relative references and root-specific applicability remain observable?
  - Should the first change deduplicate only byte-identical copilot-instructions.md files, or establish the same contract for all always-applied agent instruction file types?
