# Issue #257888 — Allow sovereign cloud Azure Openai deployments as custom models

[https://github.com/microsoft/vscode/issues/257888](https://github.com/microsoft/vscode/issues/257888)

## Summary

Sovereign-cloud support remains incomplete: current Azure BYOK URL inference still rejects Azure Government base URLs, while explicit API URLs provide only a workaround. Keep this accepted, team-authored request open; a maintainer recently consolidated another sovereign-cloud report here.

## Change summary

Allow sovereign-cloud Azure OpenAI deployments, including Azure Government endpoints, to be configured and used as Copilot Chat custom models.

## Best solution

Make sovereign Azure deployments usable through the Azure BYOK provider without requiring a hand-expanded API URL, preserving commercial-cloud behavior. Coordinate URL recognition and sovereign Entra authentication with the narrower related issues while retaining this request's broader deployment-support scope.

## Evidence

This matches the reporter's configuration failure.
- **Existing workaround is partial coverage:** The January 2026 commenter reported success after appending /chat/completions. Current customOAIProvider.ts: hasExplicitApiPath accepts explicit /chat/completions or /responses paths, and azureProvider.ts preserves those URLs. openAIEndpoint.ts: getExtraHeaders selects api-key for URLs containing openai.azure, including Gov hosts.
