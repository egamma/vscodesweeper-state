# Issue #334149 — "MISSING inline chat edit tools" when having agents disabled and trying to fix a lint issue

[https://github.com/microsoft/vscode/issues/334149](https://github.com/microsoft/vscode/issues/334149)

## Summary

Traced this in current main: when chat.agent.enabled is false, LanguageModelToolsService#isPermitted only carves out an exception for internal, non-referenceable infrastructure tools (e.g. inline_chat_exit) — it does not exempt the extension-contributed edit tools (copilot_editFile / copilot_replaceString / copilot_applyPatch / copilot_multiReplaceString) that inline chat's edit flow (including the quick-fix 'Fix' action) needs, so those still vanish from vscode.lm.tools and InlineChatToolCalling#_getAvailableTools throws 'MISSING inline chat edit tools'. This is a real, still-reproducible gap, not a duplicate of a closed issue.

## Change summary

Using the Quick Fix 'Fix' action on a lint diagnostic throws 'MISSING inline chat edit tools' when chat.agent.enabled is set to false.

## Best solution

Extend the agent-mode-disabled exception in src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts (isPermitted, ~lines 257-284) so inline-chat's required edit tools remain available even when chat.agent.enabled is false, mirroring the existing carve-out already made for the internal exit tool — this is the same root cause as the closed/locked issue #292935, just for a different tool set (edit tools instead of the exit tool).
