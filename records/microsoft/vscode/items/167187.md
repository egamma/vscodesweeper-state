# Issue #167187 — Diffrenciate between read vs write references

[https://github.com/microsoft/vscode/issues/167187](https://github.com/microsoft/vscode/issues/167187)

## Summary

This is a valid, well-supported feature request (77 upvotes, well past the 20-vote backlog threshold) to differentiate read vs write references in the references view. The capability does not exist on current main — the ReferenceProvider API returns plain Location[] with no access-kind metadata.

## Change summary

Decorate and filter references by read/write usage in the references view/peek widget.

## Best solution

Extend the ReferenceProvider API (or add a new provider interface) to return access-kind metadata (read/write/declaration) alongside locations, then surface filtering and visual grouping in the references view and peek widget. This depends on upstream language servers (e.g. TypeScript — microsoft/TypeScript#29462) providing the data, but some LSP servers already support it via DocumentHighlightKind semantics.
