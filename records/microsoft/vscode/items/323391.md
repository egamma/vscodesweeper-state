# Issue #323391 — Search "Files to Include" behaves incorrectly when workspace root and nested file patterns are specified together

[https://github.com/microsoft/vscode/issues/323391](https://github.com/microsoft/vscode/issues/323391)

## Summary

The root-plus-nested include defect remains visible in current source: merging search paths replaces an unrestricted root with narrower patterns. Keep this open; the multi-root bare './' case additionally conflicts with an explicitly tested convention and needs a maintainer decision.

## Change summary

Combining an unrestricted workspace-root include with a nested include unexpectedly removes search results outside the nested path.

## Best solution

Preserve union semantics when unrestricted root selections and nested selections are combined, regardless of order. Resolve whether bare './' in multi-root workspaces should select every root or retain its existing ignored-token semantics before addressing the full reproduction matrix.

- **Trace:**

In src/vs/workbench/services/search/common/queryBuilder.ts, expandOneSearchPath produces an unrestricted root entry for single-folder './' and multi-root './rootName'; expandSearchPathPatterns merges entries by URI and adds nested patterns even when that root was previously unrestricted, while a later unrestricted entry does not clear existing restrictions. getFolderQueryForSearchPath passes the resulting restrictive expression through as includePattern. - **Open decisions:**

## Evidence
