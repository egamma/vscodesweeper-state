# Issue #242891 — Killing tasks does not actually kill them

[https://github.com/microsoft/vscode/issues/242891](https://github.com/microsoft/vscode/issues/242891)

## Summary

Still an open, reproduced problem: the prior implemented-on-main close citing commit cfebe6aeafb38d979dda4aa9b580e513d270c73d was refuted, and comments continue through April 2026 confirming the workaround (enabling `terminal.integrated.windowsUseConptyDll`) is still needed, plus newer reports on macOS suggest the leaked-process problem isn't fully explained by the Windows conpty root cause alone.

## Change summary

Terminating a task (via the kill button or Terminate Task) removes it from the running-tasks list but leaves the underlying child process (e.g. a vite/node dev server) running and holding its port.

## Best solution

Keep this open under the terminal-conpty investigation; current main already defaults `terminal.integrated.windowsUseConptyDll` to `true` (src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:495-499), matching meganrogge's proposed direction in the thread, but recent comments (Dec 2025 macOS, Mar/Apr 2026) still describe the underlying symptom, so the fix isn't confirmed complete — needs a focused repro pass (ideally against the capc0 repro repo linked in the thread) to determine whether the remaining leak is the same conpty/node-pty root cause or a separate process-tree-kill gap on non-Windows platforms.
