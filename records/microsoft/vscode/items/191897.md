# Issue #191897 — [css] Wrong selector hover when using :has() 

[https://github.com/microsoft/vscode/issues/191897](https://github.com/microsoft/vscode/issues/191897)

## Summary

The incorrect preview remains in the current CSS language service: functional pseudo-selectors such as `:has()` are rendered as empty HTML-like attributes without interpreting their selector arguments. This should remain open and be classified as upstream work in the CSS language service.

## Change summary

Render a meaningful selector-hover HTML example for relational `:has()` selectors instead of outputting `<article :has>`.

## Best solution

Update selector printing in `microsoft/vscode-css-languageservice` so `:has()` arguments contribute a representative descendant or relative element structure, with selector-printing tests covering `article:has(.alert)` and combinator variants.
