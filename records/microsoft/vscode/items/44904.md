# Issue #44904 — SCM: Align next/previous commands between diff and regular editor

[https://github.com/microsoft/vscode/issues/44904](https://github.com/microsoft/vscode/issues/44904)

## Summary

Default shortcuts are now aligned, but the regular-editor and diff-editor navigation commands remain separate and context-specific. Keep this accepted Backlog request open for command-level alignment; no verified canonical or completed fix covers that remaining work.

## Change summary

Make next/previous-change commands work consistently in both regular editors and diff editors.

## Best solution

Provide context-sensitive change navigation that follows SCM changes in a regular editor and the displayed comparison in a diff editor, preserving existing command bindings. Decide how the unified behavior should appear in the Command Palette without adding duplicate entries.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts`, `src/vs/workbench/browser/parts/editor/diffEditorCommands.ts`, `src/vs/workbench/browser/parts/editor/diffEditorCommandsService.ts`
- **Validation:** With a tracked file containing multiple separated changes, invoke the agreed next/previous command pair from the Command Palette and a custom keybinding in a regular editor, an inline diff, and a side-by-side diff with either side focused. Verify navigation follows the relevant changes, reveals the destination, and preserves existing Alt+F5/Shift+Alt+F5 behavior and legacy bindings. Include a comparison whose baseline differs from the SCM baseline to detect navigation against the wrong diff.
- **Behavior:**

  > Users should be able to invoke the same next/previous-change commands in a regular editor and a diff editor. Regular-editor navigation follows SCM changes; diff-editor navigation follows the comparison currently displayed, including comparisons against a non-SCM baseline. Both directions must reveal their destination in inline and side-by-side comparisons. Existing default shortcuts and user bindings must remain compatible.
- **Trace:**

  > GotoNextChangeAction and GotoPreviousChangeAction in src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts register the workbench.action.editor command pair, exclude active diff editors, and navigate QuickDiffModel changes. src/vs/workbench/browser/parts/editor/diffEditorCommands.ts registers a separate workbench.action.compareEditor pair with identical labels and default shortcuts. DiffEditorCommandsService.navigateInDiffEditor in src/vs/workbench/browser/parts/editor/diffEditorCommandsService.ts uses TextDiffEditor.getControl().goToDiff, so the navigation engines operate against different baselines. The remaining gap is command-level interoperability, not missing default shortcuts. Preserve regular-editor SCM semantics, displayed-comparison semantics, existing bindings, and separate Show Next/Previous Change peek behavior; cross-file and multi-file navigation are outside this request. The direction is documented at https://github.com/microsoft/vscode/issues/7717#issuecomment-369860832, and https://github.com/microsoft/vscode/issues/48964 was explicitly consolidated here. The unresolved product choice is the Command Palette surface for the aligned commands.
- **Open decisions:**
  - Should the Command Palette expose one context-sensitive next/previous pair while retaining existing command IDs for compatibility, or retain separately discoverable regular-editor and comparison entries with aligned behavior?
