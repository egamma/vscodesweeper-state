# Issue #162788 — Separated select and focus on delete in file explorer

[https://github.com/microsoft/vscode/issues/162788](https://github.com/microsoft/vscode/issues/162788)

## Summary

The focus/selection split remains possible on current main through the reported Explorer context-menu deletion path. This team-authored polish item should stay open for a bounded tree-state consistency fix.

## Change summary

Keep Explorer focus and selection on the same surviving entry after deleting a multi-selection from a context menu opened on a selected but previously unfocused file.

## Best solution

After the selected resources are removed, reconcile the Explorer's focus and selection fallback so both identify the same surviving row, while preserving multi-selection command targeting before deletion and existing behavior when the context-menu target was already focused.
