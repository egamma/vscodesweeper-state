# Issue #205598 — Invoking deltaDecorations recursively could lead to leaking decorations.

[https://github.com/microsoft/vscode/issues/205598](https://github.com/microsoft/vscode/issues/205598)

## Summary

The recursive deltaDecorations guard is still present on current main (textModel.ts:1728–1731), and the code path from suggest-accept → snippet-insert → model-content-change → cursor-update → deltaDecorations remains structurally possible. No fix commit references this issue. Keeping open as a real, team-authored error-telemetry bug.

## Change summary

Accepting a suggestion can trigger recursive deltaDecorations calls via the cursor/decoration update chain, risking leaked decorations.

## Best solution

Break the recursive decoration chain — either defer the inner deltaDecorations call triggered by cursor state updates during an outer deltaDecorations transaction, or restructure the cursor dispose/setStates path so it does not synchronously call deltaDecorations while one is already in flight. The fix likely touches `src/vs/editor/common/model/textModel.ts` (the guard site) and `src/vs/editor/common/cursor/cursor.ts` (the re-entrant caller).
