# Issue #270444 — Add a submenu to the snooze option

[https://github.com/microsoft/vscode/issues/270444](https://github.com/microsoft/vscode/issues/270444)

## Summary

The requested simplification remains absent on current main, and the thread records maintainer support but an unresolved UX choice. This team-authored feature request must remain open while that choice is made.

## Change summary

Expose common inline-suggestion snooze durations directly from the NES gutter menu instead of always opening a separate quick pick.

## Best solution

Choose between a hover submenu of common durations and a one-click default duration with the command palette retaining the full picker, then implement the chosen interaction with keyboard-accessible navigation in the NES gutter menu.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/inlineCompletions/browser/view/inlineEdits/components/gutterIndicatorMenu.ts`, `src/vs/editor/browser/services/inlineCompletionsService.ts`
- **Validation:** In a development workbench, trigger an NES completion, open the gutter menu, and verify the chosen Snooze interaction exposes common durations without relocating focus to the existing quick pick; verify mouse and keyboard selection set the requested duration, while the command-palette Snooze action still offers all durations and Custom.
- **Behavior:**

  > The NES gutter Snooze action should let users select a common snooze duration without opening a separate picker elsewhere on screen. The interaction must work with mouse and keyboard, visibly preserve menu focus, and apply the selected duration. The full Snooze command must continue supporting all predefined and custom durations.
- **Trace:**

  > GutterIndicatorMenuContent in src/vs/editor/contrib/inlineCompletions/browser/view/inlineEdits/components/gutterIndicatorMenu.ts constructs a custom observable hover menu and currently treats Snooze like every other option, executing editor.action.inlineSuggest.snooze with no arguments. SnoozeInlineCompletion in src/vs/editor/browser/services/inlineCompletionsService.ts consequently opens its quick pick, but already interprets a numeric command argument as minutes. The custom option renderer supports hover, click, Enter, and active styling but no nested menu. Preserve the command-palette picker and the snooze service semantics; the scope is the NES gutter interaction introduced by https://github.com/microsoft/vscode/pull/270420.
- **Open decisions:**
  - Should the gutter expose a hover submenu of durations, or perform a one-click five-minute snooze while leaving longer durations to the command-palette picker?
  - If a submenu is chosen, should it show only a short set of common durations plus More, or every predefined duration?
