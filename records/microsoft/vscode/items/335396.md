# Issue #335396 — Agents window: support window.title (or equivalent) for the center title bar text

[https://github.com/microsoft/vscode/issues/335396](https://github.com/microsoft/vscode/issues/335396)

## Summary

This is a recent, clearly scoped Agents window feature request parked in the Backlog. The current implementation intentionally omits the normal `window.title` rendering, and no verified canonical issue, shipped equivalent, or maintainer scope decision supports closing it.

## Change summary

Allow users to add profile- or instance-specific text to the center title bar of an Agents window, through `window.title` or an Agents-specific equivalent.

## Best solution

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/titlebarPart.ts`, `src/vs/sessions/common/theme.ts`
- **Validation:** Exercise an Agents window under two profiles with distinct configured labels and verify that the center title area distinguishes them while the existing session/repository picker remains usable; also verify the default configuration leaves the current title unchanged.
- **Behavior:**

  > An Agents window should optionally display a user-configured profile or instance identifier in its center title area while retaining the existing session/repository picker. Distinct profiles or user-data directories must be visually distinguishable through that text, and users who do not configure the capability must see the current title behavior unchanged. The label must remain readable with the existing Agents window theme tokens.
- **Trace:**

  > The relevant surface is the Agents window title bar in src/vs/sessions/browser/parts/titlebarPart.ts. Its `windowTitle` path is deliberately lazy because this title bar does not currently render the regular `window.title`; the center is occupied by the `Menus.CommandCenter` session/repository picker described in the report. Agents shell colors are separately defined in src/vs/sessions/common/theme.ts, so color customization does not provide the requested textual identity. Keep the scope within the Agents window and preserve the picker and the normal workbench `window.title` behavior. The uncertainty begins at the public contract: whether Agents windows consume the existing template and variables or expose a narrower Agents-specific label setting, and how that text composes with the picker.
- **Open decisions:**
  - Should the Agents window honor the existing `window.title` template and its variables, or expose a dedicated Agents-window label setting?
  - Should the configured text appear before or after the existing session/repository picker content?
