# Issue #87204 — Add a command to add multicursors to all Highlight Occurences

[https://github.com/microsoft/vscode/issues/87204](https://github.com/microsoft/vscode/issues/87204)

## Summary

The semantic multicursor command remains missing: Change All Occurrences still selects textual matches, while symbol highlighting provides navigation only. Keep this accepted Backlog request open; the discussion supports a separate command that preserves existing commands.

## Change summary

Add a command that places cursors at corresponding positions in all document highlights for the current symbol.

## Best solution

Provide a separate editor command for simultaneous editing of the current document's highlighted symbol occurrences, excluding unrelated textual matches. Preserve the existing textual-selection commands and decide any default shortcut change separately.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/wordHighlighter/browser/wordHighlighter.ts`, `src/vs/editor/contrib/wordHighlighter/test/browser/wordHighlighter.test.ts`, `src/vs/editor/contrib/multicursor/browser/multicursor.ts`
- **Validation:** Add editor-action coverage using a DocumentHighlightProvider that returns three occurrences while omitting an unrelated same-spelling identifier. Verify invocation from fir|st creates corresponding cursors only in those three ranges, typing updates those occurrences together, and existing textual-selection commands retain their behavior.
- **Behavior:**

  > A separate command creates multiple cursors from the current symbol's document highlights in the active document. For the issue's fir|st example, each cursor occupies the corresponding position within first, enabling simultaneous edits as the user types. Identically spelled identifiers outside the provider's highlight set must remain untouched. Existing Change All Occurrences and Select All Occurrences of Find Match retain their textual behavior; any default shortcut reassignment is a separate decision.
- **Trace:**

  > In src/vs/editor/contrib/multicursor/browser/multicursor.ts, SelectHighlightsAction and CompatChangeAll both call MultiCursorSelectionController.selectAll, which works from textual find matches. In src/vs/editor/contrib/wordHighlighter/browser/wordHighlighter.ts, getOccurrencesAtPosition requests document highlights, _getSortedHighlights reads displayed ranges, and WordHighlighterContribution exposes next/previous navigation but no multicursor action. The current source therefore establishes the missing command, not a defect in existing textual commands. LinkedEditingContribution uses a different provider contract and does not fill this gap. The discussion at https://github.com/microsoft/vscode/issues/87204 supports a third command rather than replacing existing commands. Planning should establish behavior when highlights are unavailable or still pending; keep cross-document editing and unrelated rename/snippet changes outside this request.
- **Open decisions:**
  - When document highlights are unavailable or still pending, should the new command obtain fresh highlights before acting, or be available only once highlights have been produced?
