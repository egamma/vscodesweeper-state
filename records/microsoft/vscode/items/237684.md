# Issue #237684 — VSCode claims no JSON formatter installed, but 5 seconds later formats the document just fine

[https://github.com/microsoft/vscode/issues/237684](https://github.com/microsoft/vscode/issues/237684)

## Summary

Keep open: current source still treats an unregistered formatter during startup as an uninstalled formatter, matching the reported JSON startup race. The older related report concerns unsupported unsaved C++ documents, not this startup symptom, so it does not meet the duplicate bar.

## Change summary

Avoid claiming that no JSON formatter is installed when the bundled formatter is still initializing.

## Best solution

Make the formatting action distinguish initialization from genuine formatter absence without changing normal formatting or installation guidance. Decide whether an early invocation should wait for readiness or explain the temporary state.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/format/browser/formatActionsNone.ts`, `src/vs/editor/contrib/format/browser/formatActions.ts`, `extensions/json-language-features/client/src/jsonClient.ts`
- **Validation:** Cold-launch VS Code with JSON formatting enabled, immediately create an untitled document, paste JSON, and invoke Format Document as soon as JSON is detected. Repeat with deliberately delayed JSON initialization: the invocation must not claim the bundled formatter is uninstalled, and formatting must work after readiness. Also verify that a language with no installed formatter retains installation guidance and that disabled JSON formatting remains respected.
- **Behavior:**

  > An immediate Format Document invocation after cold startup can claim that no JSON formatter is installed, although the bundled formatter becomes usable seconds later. Initialization must not be presented as missing installation. Acceptance must cover the cold-start sequence, successful formatting after readiness, genuine formatter absence, and intentionally disabled JSON formatting. Whether the initial command waits or presents temporary initialization feedback remains a product decision.
- **Trace:**

  > The fallback action editor.action.formatDocument.none in src/vs/workbench/contrib/format/browser/formatActionsNone.ts equates zero currently registered providers with no installed formatter. The bundled JSON extension activates on the JSON language, and startClientWithParticipants in extensions/json-language-features/client/src/jsonClient.ts awaits client.start() before updateFormatterRegistration registers its provider. The normal editor.action.formatDocument in src/vs/editor/contrib/format/browser/formatActions.ts requires an available formatting provider. These paths confirm the registration window, but the trace has not established a suitable extension-readiness contract or a bounded regression-test seam. Preserve provider selection, explicit formatting-disable settings, and genuine missing-formatter guidance. https://github.com/microsoft/vscode/issues/150948 concerns a different file-scheme restriction and is related rather than canonical.
- **Open decisions:**
  - Should Format Document invoked during formatter initialization wait and fulfill the original request, or return with temporary initialization feedback requiring a retry?

## Evidence

- **Reported trigger and discussion:** https://github.com/microsoft/vscode/issues/237684 describes a cold launch, immediate paste into an untitled document, and Format Document immediately after JSON detection; retrying 5–10 seconds later succeeds. The supplied discussion identifies extension-host or extension startup as the likely cause and suggests recognizing extensions that are still starting.
- **Current false-absence path:** src/vs/workbench/contrib/format/browser/formatActionsNone.ts: the editor.action.formatDocument.none action reads the current documentFormattingEditProvider count and immediately displays "There is no formatter for '{0}' files installed." when it is zero. It performs no extension-startup or activation-readiness check before making that claim.

An invocation before that registration reaches the false-absence path; registration subsequently makes formatting available. This establishes the race from source, without executing the application.
