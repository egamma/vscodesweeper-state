# Issue #331148 — Run and Debug Breakpoints Section disappears

[https://github.com/microsoft/vscode/issues/331148](https://github.com/microsoft/vscode/issues/331148)

## Summary

Traced this in the current source: the Breakpoints view's visibility is deliberately gated by `CONTEXT_BREAKPOINTS_EXIST || CONTEXT_DEBUG_UX == 'default' || CONTEXT_HAS_DEBUGGED` — the 'simple' debug UX intentionally hides the panel once the last breakpoint is removed and no launch configuration/debug session exists yet, matching exactly what's reported.

## Change summary

The Breakpoints view (and its entry in the Run and Debug view picker) disappears after removing the only breakpoint, when no launch configuration exists and no debug session has started yet.

## Best solution

Keep the current 'simple debug UX' behavior — it's intentional decluttering for users without a configured debugger; if the community wants the Breakpoints panel to stay visible after it's been shown once in a session, that'd be a new `feature-request` against src/vs/workbench/contrib/debug/browser/debug.contribution.ts's view `when` clause, not a bug fix.

## Evidence

- **view visibility condition:** src/vs/workbench/contrib/debug/browser/debug.contribution.ts:473 registers BREAKPOINTS_VIEW_ID with `when: ContextKeyExpr.or(CONTEXT_BREAKPOINTS_EXIST, CONTEXT_DEBUG_UX.isEqualTo('default'), CONTEXT_HAS_DEBUGGED)` — the panel is hidden unless one of these three is true.
- **debugUx computation:** src/vs/workbench/contrib/debug/browser/debugService.ts:173 sets debugUx to 'default' only when a debug session is active or state's configuration list is non-empty and a debugger is enabled; otherwise it's 'simple'.
- **hasDebugged only set on session start:** src/vs/workbench/contrib/debug/browser/debugService.ts:362 sets CONTEXT_HAS_DEBUGGED only inside `startDebugging()`, not when a breakpoint is merely set — so a user who only toggles a breakpoint (no launch.json, no session run) has all three conditions false once the breakpoint is removed, exactly reproducing the report.
