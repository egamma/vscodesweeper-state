# Issue #330034 — Managed settings confirmations should say why confirmation is triggered

[https://github.com/microsoft/vscode/issues/330034](https://github.com/microsoft/vscode/issues/330034)

## Summary

Fresh, team-authored polish request: managed-settings/permission-driven confirmations don't currently surface why a confirmation was triggered by policy, and current source confirms the gap. This is a legitimate, unimplemented request from an active tester, so it stays open for follow-up work.

## Change summary

When an enterprise 'managed settings' permission rule (e.g. a Shell 'ask' rule) forces a tool confirmation, the dialog should explain that the confirmation was triggered by that policy.

## Best solution

Extend the permission-based confirmation path (ILanguageModelToolsConfirmationService.getPreConfirmAction / the ConfirmedReason plumbed through languageModelToolsService.ts) to attach a human-readable reason (e.g. the matching permission rule) to confirmationMessages, similar to how the PreToolUse hook path already does via forceConfirmationReason/hookReason (see resolveAutoConfirmFromHook, lines ~848-921 of languageModelToolsService.ts).
