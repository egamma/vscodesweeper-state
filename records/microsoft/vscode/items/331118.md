# Issue #331118 — Agent Host: first-turn config refresh leaves new chat permanently active

[https://github.com/microsoft/vscode/issues/331118](https://github.com/microsoft/vscode/issues/331118)

## Summary

Well-diagnosed, source-confirmed bug: the exact log strings and destroy→resume path the reporter traced are present verbatim in current main, and the existing hang watchdog only emits telemetry rather than recovering the turn, so the described permanent-hang outcome is plausible as described.

## Change summary

When a worktree-isolated session's first send races a customization-bundle republish, CopilotAgent destroys the just-created provisional SDK session and falls back to createSession with the same id; the Copilot CLI runtime then reports a disposed CompactionProcessorHandle with no terminal SDK event, leaving the AHP turn permanently active with no recovery.

## Best solution

Two independent, complementary fixes: (1) in src/vs/platform/agentHost/node/copilot/copilotAgent.ts `_sendMessageOnce`, avoid the destroy-then-resume-same-id path for a session that was materialized during this same first send (reconcile the final customization snapshot before creating the SDK session rather than after), and (2) wire AgentHostTurnTracker's existing no-progress watchdog (already telemetry-only per src/vs/platform/agentHost/node/agentHostTurnTracker.ts) into an actual recovery action (emit a terminal chat/error) so a lost provider turn cannot stay active indefinitely, as backstop regardless of root-cause fix #1. The CompactionProcessorHandle disposal itself lives in the external Copilot CLI runtime and is out of this repo's direct control.
