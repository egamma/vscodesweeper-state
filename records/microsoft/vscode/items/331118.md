# Issue #331118 — Agent Host: first-turn config refresh leaves new chat permanently active

[https://github.com/microsoft/vscode/issues/331118](https://github.com/microsoft/vscode/issues/331118)

## Summary

Thanks for the detailed report and root-cause trace. Current `main` confirms the described code path: `_sendMessageOnce` in `copilotAgent.ts` calls `activeClient.requiresRestart()`, and on a structural config change destroys the just-created live session (`_destroyLiveSession`) before attempting `_resumeSession` on the same SDK id — matching the destroy→resume→fallback-createSession sequence in the logs. No fix exists yet on main, so this stays open for a maintainer to pick a mitigation.

## Change summary

On a worktree-isolated session's first turn, a mid-send customization republish triggers a same-ID session destroy/recreate that leaves the chat turn permanently 'active' with no terminal event.

## Best solution

Fix belongs in `src/vs/platform/agentHost/node/copilot/copilotAgent.ts` (`_sendMessageOnce`/`_resumeSession`) or the runtime's same-ID recreate handling — either avoid destroy→resume for a session that was never actually used yet, or wire the existing `AgentHostTurnTracker` no-progress watchdog (`agentHostTurnTracker.ts`) into an actual recovery/terminal-event path so a lost provider turn can't hang forever.
