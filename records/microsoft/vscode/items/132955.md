# Issue #132955 — Support `highContrast` attribute on `DecorationRenderOptions`

[https://github.com/microsoft/vscode/issues/132955](https://github.com/microsoft/vscode/issues/132955)

## Summary

The requested high-contrast decoration override remains absent from the current API and renderer. Existing theme-color support covers colors, but not arbitrary decoration styling; neither the linked light high-contrast theme issue nor the older theme-color access request owns this gap.

## Change summary

Allow extensions to specify high-contrast-specific styling through DecorationRenderOptions alongside its light and dark overrides.

## Best solution

Have the editor API owners decide a decoration override contract that accounts for both dark and light high-contrast themes, including fallback behavior. Preserve existing light/dark behavior for extensions that do not opt in.

## Evidence

- **Current API gap:** src/vscode-dts/vscode.d.ts:1174–1201 declares DecorationRenderOptions with only light and dark overrides. ColorThemeKind at lines 8676–8693 separately recognizes HighContrast and HighContrastLight.
- **Current rendering behavior:** src/vs/workbench/api/common/extHostTypeConverters.ts:581–613 transports only light and dark overrides. src/vs/editor/browser/services/abstractCodeEditorService.ts:689–744 builds those two override sets and applies light styling to .vs/.hc-light and dark styling to .vs-dark/.hc-black, with no independent high-contrast override.
- **Existing capabilities are partial:** Decoration properties accept ThemeColor, and src/vs/workbench/services/themes/common/colorExtensionPoint.ts supports contributed color defaults named highContrast and highContrastLight. These cover color values, not independent gutter icons, borders, font styling, or other decoration options. window.onDidChangeActiveColorTheme and ColorThemeKind permit extensions to manage separate decoration types themselves, but do not provide the requested declarative override.
