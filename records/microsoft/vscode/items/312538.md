# Issue #312538 — Pressing Esc in extensions search should clear the search term

[https://github.com/microsoft/vscode/issues/312538](https://github.com/microsoft/vscode/issues/312538)

## Summary

Current main still lacks the requested keyboard behavior: the Extensions clear-search command exists, but it has no Escape keybinding or search-focus context. Route this focused consistency polish to the Extensions area.

## Change summary

Make Escape clear a non-empty Extensions search while focus is in the Extensions search input.

## Best solution

Match the Settings search interaction by making Escape invoke `workbench.extensions.action.clearExtensionsSearchResults` only while the Extensions search input is focused and contains text, without overriding Escape handling for an open suggestion widget.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsViewlet.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`
- **Validation:** Open Extensions, type a query, and verify Escape clears it while retaining search focus; verify Escape outside the search input does not clear it, and that an open suggestion widget receives Escape before the query is cleared.
- **Behavior:**

  > When the Extensions search input is focused and contains text, pressing Escape clears the query and search results while keeping focus in the input. Escape must not clear the query when focus is elsewhere in the Extensions view. If the search suggestion widget is open, its normal Escape dismissal behavior must remain higher priority.
- **Trace:**

  > The clear operation already exists as `workbench.extensions.action.clearExtensionsSearchResults` in `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, but its registration has no keybinding. `ExtensionsViewPaneContainer` in `src/vs/workbench/contrib/extensions/browser/extensionsViewlet.ts` tracks only whether the normalized query has text through `SearchHasTextContext`; it does not publish whether the search input itself is focused. The Settings implementation in `src/vs/workbench/contrib/preferences/browser/preferences.contribution.ts` provides the intended interaction precedent by scoping Escape to its search-focus context. Keep the boundary to Extensions search keyboard behavior: do not change clearing semantics, list navigation, or Escape behavior in other sidebar controls. The planning uncertainty is validation infrastructure, because the existing Extensions test suites have no clear-search keybinding or focus-context coverage.
