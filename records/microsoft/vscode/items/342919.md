# Issue #342919 — Outline view for Markdown Preview

[https://github.com/microsoft/vscode/issues/342919](https://github.com/microsoft/vscode/issues/342919)

## Summary

Keep open: current source provides outline integration for Markdown Editor, but not equivalent integration for Markdown Preview. The existing editor capability does not satisfy the requested reading workflow, and no verified canonical covers the full remaining work.

## Change summary

Show Markdown headings in the Outline view while Markdown Preview is active, with navigation into the rendered document.

## Best solution

Connect the built-in Markdown Preview to the existing document-symbol outline experience while preserving its read-only scrolling and keyboard navigation. Account for both the standalone preview panel and the preview opened as a custom editor.

- **Validation:** Open a Markdown document with nested headings in standalone Markdown Preview and in the custom-editor preview. With each preview active, verify that Outline shows the same heading hierarchy as the text editor and selecting a heading navigates within the preview. Verify ordinary preview scrolling and keyboard navigation remain unchanged, and existing text-editor and Markdown Editor outlines still work.
- **Behavior:**

  > Markdown Preview currently lacks the Outline information available when reading the same document in the text editor or Markdown Editor. The requested outcome is the same heading hierarchy and navigation while remaining in the read-only preview. Acceptance covers both standalone and custom-editor previews without requiring an active source editor. Existing preview keyboard navigation and scrolling must remain intact.
- **Trace:**

  > DocumentSymbolsOutlineCreator in src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts recognizes code editors and custom editors with navigation; OutlineService selects a matching creator. MarkdownEditorProvider supplies the navigation bridge for Markdown Editor, but MarkdownPreviewManager does not supply an equivalent bridge for StaticMarkdownPreview. DynamicMarkdownPreview instead uses vscode.window.createWebviewPanel, so custom-text-editor support alone does not cover the full request. The trace establishes the missing connections but not a complete integration design across both preview representations. Preserve existing source-editor and Markdown Editor behavior rather than treating switching editors as the solution. https://github.com/microsoft/vscode/issues/327247 is related CustomTextEditor infrastructure, not a verified canonical for both preview paths.
