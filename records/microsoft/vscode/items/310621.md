# Issue #310621 — Resume copilot conversation from cli into VSCode

[https://github.com/microsoft/vscode/issues/310621](https://github.com/microsoft/vscode/issues/310621)

## Summary

A real bidirectional session-handoff gap remains, so this should stay open and be routed to the Copilot CLI and Agent Host areas. The newer tracking issue covers the design, but cannot be the duplicate canonical for this re-reviewed, older report.

## Change summary

Allow users to continue Copilot conversations between the CLI and VS Code without losing the existing conversation history.

## Best solution

Complete the full session-porting work tracked by https://github.com/microsoft/vscode/issues/323970: support importing a CLI session as an active VS Code conversation and continuing a VS Code conversation in the CLI, with explicit identity and history-fidelity semantics.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/importLocalConversationToAgentSession.ts`, `src/vs/platform/agentHost/node/agentService.ts`, `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts`
- **Validation:** Extend extensions/copilot/test/e2e/cli.stest.ts with a persisted CLI session that is opened and continued through VS Code, and extend src/vs/platform/agentHost/test/node/protocol/copilotImportSession.integrationTest.ts to verify the VS Code-to-CLI direction preserves resumable turns.
- **Behavior:**

  > A user can take an existing Copilot CLI conversation into VS Code and continue with its prior history available to the active agent. A VS Code Copilot conversation can likewise continue in the CLI without the CLI responding as though the history were unavailable. The chosen handoff behavior must remain coherent after reopening the resulting session and must clearly define whether the source session remains independent.
- **Trace:**

  > Existing CLI sessions are exposed by CopilotCLIChatSessionItemProvider and loaded by provideChatSessionContentForExistingSession in extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts, but existing content has no request handler; the separate resume action only invokes the terminal CLI with --resume. The reverse local-VS-Code-to-Copilot-CLI path was implemented by https://github.com/microsoft/vscode/pull/324858 through chatContinueInAction.ts, importLocalConversationToAgentSession.ts, and the Agent Host importConversation path. https://github.com/microsoft/vscode/pull/323773 provides session history as an attachment, not as an active imported session. Full porting and its unresolved state-mapping questions are tracked by https://github.com/microsoft/vscode/issues/323970. Keep attachment-as-context behavior distinct from session porting, and do not regress ordinary terminal --resume behavior.
- **Open decisions:**
  - Should moving a conversation perform a one-time handoff, or keep the CLI and VS Code views synchronized afterward?
  - Should a CLI-to-VS Code handoff preserve the original session identity or create a new linked VS Code session?
  - Which history artifacts must remain interactive after transfer—tool calls, file edits, approvals, and model metadata—or is transcript fidelity sufficient for some source session types?

## Evidence

- **current source gap:** extensions/copilot/src/extension/chatSessions/vscode-node/copilotCLIChatSessionsContribution.ts loads existing CLI history in provideChatSessionContentForExistingSession, but returns requestHandler: undefined; resumeCopilotCLISessionInTerminal only launches the terminal with --resume. This does not provide a fully active CLI-to-VS Code conversation transfer.
- **partial implementation:** https://github.com/microsoft/vscode/pull/324858, merged as commit 93e415a00fdddf71126bccb4a046cf0f014dd840, implements the opposite local-VS-Code-to-Agent-Host-Copilot-CLI direction by importing editable turns through src/vs/workbench/contrib/chat/browser/actions/chatContinueInAction.ts and importLocalConversationToAgentSession.ts.
- **tracking issue:** https://github.com/microsoft/vscode/issues/323970 is open and explicitly tracks full session porting, including Copilot CLI events.jsonl, workbench chat state, session identity, tool results, edits, approvals, and partial-session behavior.

- **attachment is not porting:** https://github.com/microsoft/vscode/pull/323773 only forwards a Copilot CLI events.jsonl trajectory as attached context; its scope explicitly distinguishes that from making the prior session the active conversation.
