# Issue #98218 — Touch screen on chromebook

[https://github.com/microsoft/vscode/issues/98218](https://github.com/microsoft/vscode/issues/98218)

## Summary

Keep open in the Backlog: touch-drag scrolling remains unsupported in reported Chromebook, Linux, and web editor scenarios, and the request has 35 community upvotes. This issue is also the oldest and most established tracker for that gap.

## Change summary

Support touch-based cursor movement and drag scrolling in the code editor on Chromebooks and other touch-enabled Linux or web devices.

## Best solution

Make the editor consume touch or pointer gestures consistently on desktop-class touch devices, likely in `src/vs/editor/browser/controller/pointerHandler.ts`, without requiring users to launch Chromium or Electron with `--touch-events`. Preserve this issue as the canonical scrolling request while narrower touch interactions remain separately tracked.

## Evidence

- **current source gap:** `src/vs/editor/browser/controller/pointerHandler.ts` implements touch scrolling through gesture translation, but selects `PointerEventHandler` only for iOS or mobile Android; other devices fall back to `TouchHandler` only when `mainWindow.TouchEvent` is exposed, otherwise they use `MouseHandler`.
- **current reports:** The 2025 comment confirms the editor still cannot touch-scroll on https://vscode.dev/ and https://github.dev in Chrome 137 or Firefox 138 on Ubuntu, while read-only Markdown previews do scroll.
- **workaround evidence:** Multiple commenters report that launching Code or Chrome with `--touch-events` restores editor touch scrolling, indicating the central capability remains dependent on non-default event exposure.
- **canonical status:** https://github.com/microsoft/vscode/issues/111294 was explicitly closed as a duplicate of this issue, and later reports including https://github.com/microsoft/vscode/issues/176955 were closed while pointing back to this tracker.
