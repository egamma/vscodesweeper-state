## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/287867 is OPEN. Its body explicitly requests URI addressing for terminal lines, hover previews for selection attachments, and clicking attachments to highlight the referenced terminal region. This encompasses the URI-backed selection and preview requested here.
- **Existing capability is partial:** In src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/terminal.chatAgentTools.contribution.ts, workbench.action.terminal.chat.addTerminalSelection now captures activeInstance.selection as a generic attachment with a timestamp ID, the fixed label 'Terminal Selection', and a string value. It no longer attaches the selection tool, but supplies neither a resource URI nor command-relative range metadata, so the full request remains unimplemented.
- **Command attachments are distinct:** src/vs/workbench/contrib/chat/common/attachments/chatVariableEntries.ts defines the terminalCommand attachment with a resource URI, command, output, and exit code. src/vs/workbench/contrib/chat/browser/actions/chatContext.ts resolves those attachments through command detection. That existing surface handles whole commands, not arbitrary selections spanning command boundaries.
- **Original discussion and related work:** https://github.com/microsoft/vscode/pull/272366#issuecomment-3437027334 distinguishes actual attachments and previews from terminalSelection/terminalLastCommand tool calls. The PR is closed without merging. The sibling command-attachment request, https://github.com/microsoft/vscode/issues/272902, is closed; the verified open selection issue owns the remaining work.
- **Consolidation preserves unique examples:** https://github.com/microsoft/vscode/issues/272905 supplies command-relative range examples, including a selection starting within ls output and ending within npm run build output. These refine the canonical's line-addressing design rather than establish a separate capability.
