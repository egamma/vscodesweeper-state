# Issue #328116 — Markdown editor (preview) doesnt use stylesheet like markdown preview

[https://github.com/microsoft/vscode/issues/328116](https://github.com/microsoft/vscode/issues/328116)

## Summary

Keep open: custom Markdown styling remains unsupported in the rich editor, and a maintainer has explicitly reopened the design discussion. This is the canonical stylesheet request; its community-review window started on October 9, not when the issue was originally filed.

## Change summary

Allow customization of heading colors and independent inline-code and code-block colors in the rich Markdown editor, comparable to Markdown preview stylesheet support.

## Best solution

Define a supported styling contract for the rich Markdown editor that addresses the documented readability needs while preserving editing behavior and consistent defaults. Decide whether that contract reuses markdown.styles or exposes narrower customization before accepting implementation work.

## Evidence

- **Existing capability does not cover the request:** extensions/markdown-language-features/package.json registers markdown.styles under preview configuration, and package.nls.json explicitly describes it as applying to Markdown preview. src/preview/documentRenderer.ts:198–207 emits configured code-user-style stylesheet links, while src/preview/markdownEditorProvider.ts:1124–1171 emits only the bundled editor.css stylesheet and does not consume markdown.styles.
- **Current rich-editor styling:** At checkout commit 959031245ebb1fe077e0d512e1397c0ae82006e4, extensions/markdown-language-features/markdown-editor-src/editor.ts imports @vscode/markdown-editor/themes/vscode-default.css and initializes the editor with md-theme-vscode-default. Existing theme integration does not load the reporter's configured Markdown preview stylesheet; using the separate preview remains a workaround, not coverage of rich-editor customization.
- **Maintainer design discussion:** https://github.com/microsoft/vscode/issues/328116#issuecomment-6078194577 asks to revisit JS/CSS injection because the Markdown editor is more complicated than the preview, and requests concrete use cases. https://github.com/microsoft/vscode/issues/328116#issuecomment-6082786247 supplies independent inline-code text and code-block text/background customization as a readability use case. This establishes an unresolved product contract, not an implementation defect with a settled fix.
