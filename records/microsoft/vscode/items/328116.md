# Issue #328116 — Markdown editor (preview) doesnt use stylesheet like markdown preview

[https://github.com/microsoft/vscode/issues/328116](https://github.com/microsoft/vscode/issues/328116)

## Summary

The rich Markdown Editor still lacks a supported custom-stylesheet path on current main. Because `markdown.styles` is explicitly scoped to the traditional preview, extending it to this separate editor is a feature request that should be routed to the Markdown Editor owners.

## Change summary

Allow users to customize rendered content, including heading colors, in the rich Markdown Editor similarly to the traditional Markdown preview.

## Best solution

The Markdown Editor owners should define a supported styling contract, either by safely applying `markdown.styles` to the rich editor or by introducing an editor-specific mechanism whose selectors and lifecycle match its editable DOM.

## Evidence

- **current source:** extensions/markdown-language-features/src/preview/markdownEditorProvider.ts#getHtml links only the bundled markdown-editor-out/editor.css stylesheet; it does not load configured user styles.
- **preview implementation:** extensions/markdown-language-features/src/preview/documentRenderer.ts#getStyles calls #computeCustomStyleSheetIncludes and injects every configured markdown.styles entry into the traditional preview.
- **setting scope:** extensions/markdown-language-features/package.json registers markdown.styles in the Preview configuration section, and package.nls.json describes it specifically as stylesheets for the Markdown preview, so parity with the separate rich editor is not currently promised behavior.
- **related issue:** https://github.com/microsoft/vscode/issues/332732 is open and documents the same general styling-injection gap for font variables, but it covers only font configuration and does not absorb this broader custom-stylesheet request.
