# Issue #323726 — Agents, /code-review command conflicts with Claude Agent SDK

[https://github.com/microsoft/vscode/issues/323726](https://github.com/microsoft/vscode/issues/323726)

## Summary

Real bug: VS Code's built-in `/code-review` action (registered in `codeReview.contributions.ts`) intercepts the identically-named Claude Agent SDK slash command. The popup shows the harness command, but Enter dispatches the VS Code action instead — a command-routing priority conflict in the Agents window.

## Change summary

When using Claude Agent SDK in the Agents window, the `/code-review` slash command resolves to VS Code's built-in code review action instead of Claude's own code-review flow.

## Best solution

The slash command dispatch in the Agents window chat widget needs to give harness-provided commands priority over (or properly disambiguate from) VS Code's built-in `/code-review` action. The fix likely involves the command resolution logic in the chat widget's slash command handling, ensuring that when an agent host harness registers a command with the same name, the harness command wins or the user sees a disambiguation. Related issue https://github.com/microsoft/vscode/issues/323728 covers a broader slash-command-blocking problem in the same area.
