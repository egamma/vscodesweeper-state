# Issue #319243 — Custom models disappear when opening a Dev Container

[https://github.com/microsoft/vscode/issues/319243](https://github.com/microsoft/vscode/issues/319243)

## Summary

The reporter's follow-up comment clarifies the core ask: BYOK/custom model configuration is stored per-profile (via `userDataProfileService.currentProfile.languageModelsResource`), so switching profiles — which Dev Containers can trigger — hides previously configured models. This is a feature request for application-scoped (cross-profile) model configuration, not a bug in the current design.

## Change summary

BYOK/OpenRouter model configuration disappears when switching VS Code profiles or opening a Dev Container because model config is stored per-profile.

## Best solution

Consider making the `chatLanguageModels.json` configuration application-scoped (or adding an option to share it across profiles), so BYOK provider groups persist regardless of active profile. The relevant storage is in `src/vs/workbench/contrib/chat/browser/languageModelsConfigurationService.ts`, which reads from `userDataProfileService.currentProfile.languageModelsResource`. Area owners for `model-byok` and profiles should decide the right scoping.
