# Issue #329625 — Markdown editor loses scroll position when switching tabs

[https://github.com/microsoft/vscode/issues/329625](https://github.com/microsoft/vscode/issues/329625)

## Summary

Keep open: a maintainer confirmed that tab switching reflows the retained Markdown editor and changes its scroll position, and the implicated layout and persistence paths remain on main. The related open webview PR is an implementation candidate, not a completed fix.

## Change summary

Preserve the Markdown editor's reading and editing position when switching to another file and back, independently of Markdown Preview.

## Best solution

Resolve retained-webview viewport instability and ensure Markdown preserves its last stable visible scroll state. Evaluate the related webview PR against the inner document viewport and scroll offset, then isolate any remaining Windows-specific focus contribution.

- **Confirmed reproduction and causal control:** https://github.com/microsoft/vscode/issues/329625#issuecomment-5273086003 reports reproduction on the exact reported commit df53daabb18cd157bdb08c7f01c34df936cf12f4 using a 2,598-line Markdown document. Switching tabs changed the retained inner viewport from 844x675 to 300x150 and scrollTop from 12000 to 31866.5; freezing the hidden viewport dimensions eliminated the jump. The static macOS case eventually recovered, while persistent displacement and the suspected Windows focus contribution remain less certain.
- **Current shared layout path:** src/vs/workbench/contrib/webview/browser/overlayWebview.ts still hides retained content using CSS visibility in release(), calls _show() before rebinding saved anchor state in claim(), and unconditionally reveals the overlay in _show(). src/vs/base/browser/overlayLayoutElement.ts uses anchor-size(width) and anchor-size(height) without a retained-size fallback. These are the paths identified by the maintainer; no runtime reproduction was attempted in this read-only review.
- **Current Markdown persistence path:** extensions/markdown-language-features/src/extension.shared.ts registers the Markdown custom editor with retainContextWhenHidden: true. In markdown-editor-src/editor.ts, lines 532–556 persist native scroll events and rely on document.visibilityState for hiding; lines 599–602 restore scroll during view creation. Ordinary CSS-hidden tab transitions are not explicitly distinguished from user scrolling.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/326482 is open and unmerged. It targets early retained-webview reveal and closes https://github.com/microsoft/vscode/issues/323890, not this issue. Its discussion includes the same tab-return scroll symptom, but its principal reproduction locks the source editor to a previous preview position, including after preview closure and with scroll synchronization disabled. That record does not establish that it owns the independently confirmed retained custom-editor reflow reported here; the cross-reference describes it as possibly related.

Their discussions do not establish coverage of this retained Markdown editor defect. https://github.com/microsoft/vscode/issues/323890 describes the shared viewport flash, but does not explicitly own stable Markdown scroll persistence or the possible separate focus contribution.
