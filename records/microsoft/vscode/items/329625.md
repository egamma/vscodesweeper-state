Keep open: a maintainer confirmed tab-switch scroll jumps caused by retained webview resizing, and the implicated layout and scroll-persistence paths remain on main. Coordinate with the existing webview fix attempt; the related Markdown source-editor report is not established as the same defect.

## Change summary

Preserve the Markdown editor's reading position when switching between its tab and another editor.

- **Confirmed reproduction and causal control:** https://github.com/microsoft/vscode/issues/329625#issuecomment-5273086003 reports reproduction on the exact affected commit using Darwin arm64 and a 2,598-line document. Hiding the retained editor changed its inner viewport from 844x675 to 300x150 and scrollTop from 12000 to 31866.5; freezing the hidden viewport eliminated the jump. The static macOS case eventually recovered, while persistent Windows displacement and a possible focus contribution remain less certain.
- **Current retained-webview path:** At checkout f9350396c419d4361a509aec6cef791196ca2704, src/vs/workbench/contrib/webview/browser/overlayWebview.ts:178-197 still hides retained content through CSS visibility without preserving resolved dimensions. claim() calls _show() before reapplying the saved anchor. src/vs/base/browser/overlayLayoutElement.ts:56-62 still sizes content with anchor-size(width/height), without an explicit fallback size.
