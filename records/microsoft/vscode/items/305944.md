# Issue #305944 — configurationSchema is invalid, and causes duplicate models in the custom model list

[https://github.com/microsoft/vscode/issues/305944](https://github.com/microsoft/vscode/issues/305944)

## Summary

Keep open: an April fix addressed this exact configuration-created duplicate path, but a later independent comment reproduced the issue on VS Code 1.130.0, so that commit is not sufficient evidence for a completed close.

## Change summary

Selecting a configurationSchema option for a custom LanguageModelChatProvider creates duplicate model entries and still sends the schema default instead of the selected value.

## Best solution

Reproduce the custom-provider flow on current main with a minimal provider, including a model ID containing spaces and a slash, then ensure persisted per-model settings apply to the original model registration without causing another provider-group registration.
