# Issue #251081 — Text editor shows unmonospaced Japanese Hiragana when using Noto Sans JP font

[https://github.com/microsoft/vscode/issues/251081](https://github.com/microsoft/vscode/issues/251081)

## Summary

Still open and unresolved: the reporter confirmed the misaligned Hiragana on Insiders and on vscode.dev at a maintainer's request, and nothing on current main changes how per-glyph advance widths are produced, so this stays open for the font-rendering owners; a decline close is also barred because the team applied the `bug` label.

## Change summary

With `editor.fontFamily` falling back to Noto Sans JP (or Yu Gothic), most Japanese characters line up on the monospace grid but a few Hiragana (notably っ/て) render with a narrower advance, breaking column alignment.

## Best solution

Have the font-rendering owners determine whether the narrow glyphs come from Chromium's per-character fallback picking a different family than the one VS Code measured, or from the JP font's own proportional advances; if it is the former, the fix belongs in how the editor builds/measures its font stack (src/vs/editor/browser/config/fontMeasurements.ts and the view-line rendering path). If it turns out to be the font's intrinsic metrics, the honest outcome is documenting that non-monospace CJK families cannot be grid-aligned.
