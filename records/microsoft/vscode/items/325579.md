# Issue #325579 — Asking about another session doesn't give accurate information

[https://github.com/microsoft/vscode/issues/325579](https://github.com/microsoft/vscode/issues/325579)

## Summary

The accuracy gap remains visible in current source: long sessions default to a heavily truncated ten-turn summary, leaving the model without facts it may nevertheless infer. This team-authored bug is under active maintainer investigation and should stay open while the long-session context contract is designed.

## Change summary

Asking an agent about another long session can produce inaccurate claims because only a compact, partial transcript is provided by default.

## Best solution

Make `get_session_context` preserve or retrieve enough relevant evidence from long sessions for grounded answers, while clearly preventing conclusions from omitted history. The owner should settle whether this uses richer adaptive defaults, escalation, or stronger model-facing treatment of elision before implementation.

- **Behavior:**

  > When an agent is asked about another long session, its answer must remain grounded in that session's actual conversation rather than inventing details from a compact recent window. Relevant facts outside the newest ten turns must either be made available through an appropriate retrieval path or treated explicitly as unavailable. Short-session behavior and explicit `summary`, `digest`, `full`, and `transcriptLimit` requests must remain coherent. Acceptance should cover a long transcript whose decisive fact occurs before the current default window.
- **Trace:**

  > The model-facing tool is defined and implemented in src/vs/platform/agentHost/node/shared/sessionServerTools.ts. `getSessionContextArgs` defaults to `detail: 'summary'` and ten turns; `contextCaps.summary` limits messages and replies and excludes tool calls; `serializeSessionContext` keeps only the newest turns while setting `truncated`. Unit coverage in src/vs/platform/agentHost/test/node/sessionServerTools.test.ts verifies these truncation semantics, while src/vs/platform/agentHost/test/node/e2e/suites/serverToolsSuite.ts covers provider use of the tool but not grounded answers from long histories. The uncertainty begins at the default/adaptive contract for long sessions and how the model must react when history remains elided.
- **Open decisions:**
  - For an unspecified-detail request about a long session, should the tool automatically return richer or broader context, require a follow-up escalation, or provide a compact semantic representation of the omitted history?
