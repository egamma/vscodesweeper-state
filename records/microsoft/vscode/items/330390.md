# Issue #330390 — Chat view does not show active file indicator when opening a file in Markdown Editor Mode

[https://github.com/microsoft/vscode/issues/330390](https://github.com/microsoft/vscode/issues/330390)

## Summary

The defect remains present on current main: Markdown Editor Mode uses a custom webview editor whose backing document is not converted into implicit chat context. The issue should remain open for a scoped design decision and fix.

## Change summary

Opening a Markdown document directly in Markdown Editor Mode does not surface that document as the active file in Chat.

## Best solution

Treat the Markdown custom text editor's backing document as active-file chat context immediately upon opening it, while preserving the provider-controlled behavior of webviews that do not represent text documents.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts`, `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts`, `extensions/markdown-language-features/src/extension.shared.ts`, `extensions/markdown-language-features/package.json`
- **Validation:** With a fresh Chat view and no previous implicit attachment, open a `.md` file directly in Markdown Editor Mode and verify its active-file indicator appears immediately; switch between Markdown Editor and Text Editor modes and verify the indicator remains correct without inheriting an unrelated prior file.
- **Behavior:**

  > Opening a Markdown file directly in Markdown Editor Mode must show that document as the active file in Chat without requiring a temporary switch to Text Editor mode. Switching between the two editor modes must keep the indicator associated with the same document. Unrelated webview editors must not become file context merely because they expose an internal resource.
- **Trace:**

  > MarkdownEditorProvider in extensions/markdown-language-features/src/preview/markdownEditorProvider.ts implements CustomTextEditorProvider and is registered from extension.shared.ts under `vscode.markdown.editor`. Its workbench input is CustomEditorInput, a webview-backed input that retains the source document URI. ChatImplicitContextContribution in src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts reads active text-editor models directly, but its WebviewInput path only accepts context returned by IChatContextService; Markdown registers no matching provider. The contribution's preserve-existing-value branch accounts for the reported text-editor-then-Markdown workaround. Keep generic webviews and browser editors outside the active-file behavior unless they explicitly provide shareable context.
- **Open decisions:**
  - Should every custom text editor backed by a text document automatically expose that backing document as active-file chat context, or should only Markdown Editor Mode opt in through a view-type context provider?

## Evidence

- **source reproduction:** extensions/markdown-language-features/src/extension.shared.ts registers MarkdownEditorProvider as a CustomTextEditorProvider with view type `vscode.markdown.editor`; src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts shows that this becomes a webview-backed CustomEditorInput with an accessible backing resource.
- **missing context path:** src/vs/workbench/contrib/chat/browser/attachments/chatImplicitContext.ts obtains ordinary active files from a code-editor model, but for WebviewInput it assigns context only when IChatContextService returns a registered resource context. The Markdown extension does not register a chat tab/resource context provider, so opening the Markdown editor directly leaves `newValue` undefined.
- **observed toggle explained:** The same contribution deliberately preserves an existing implicit-context value while a non-code editor is active. This explains why opening the file first in Text Editor mode establishes the indicator and switching back to Markdown Editor mode leaves it visible.
- **canonical search:** A symptom-level search found no older open issue reporting the same missing active-file indicator for Markdown Editor Mode; the mechanically suggested related items concern different chat/session behaviors.
