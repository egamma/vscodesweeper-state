# Issue #281575 — SCM: Stashes, branches and tags show multiple times when using worktrees

[https://github.com/microsoft/vscode/issues/281575](https://github.com/microsoft/vscode/issues/281575)

## Summary

Team-authored issue reporting duplicate stashes, branches, and tags in the SCM Repositories view when using git worktrees. Hard keep-open applies (author is MEMBER). The bug appears to still be present on main — no targeted fix was found in the git extension or SCM contribution code.

## Change summary

When a git worktree is created, the SCM Repositories view shows duplicate entries for stashes, branches, and tags across the main and worktree repositories.

## Best solution

The git extension's model (extensions/git/src/model.ts) opens worktree repositories as separate SCM providers, which causes shared git objects (stashes, branches, tags) to appear once per provider. The fix should deduplicate these shared refs across worktree-linked repositories — likely in the SCM history/repository view data source or in the git extension's repository provider layer. This also impacts the 'continue in background' flow.
