# Issue #346203 — Git: a worktree deleted from Source Control stays open until a git command fails with "spawn git.exe ENOENT"

[https://github.com/microsoft/vscode/issues/346203](https://github.com/microsoft/vscode/issues/346203)

## Summary

The deleted worktree remains registered in the Git model on current main: disposal removes its UI without removing the repository or notifying API consumers. Route this confirmed lifecycle defect to Git; the related reports do not establish the same observable symptom required for a duplicate close on re-review.

## Change summary

Deleting a worktree through Source Control should immediately remove it from repository pickers and the Git API, without requiring a subsequent failing command.

## Best solution

Complete the deleted worktree's model lifecycle when deletion succeeds, keeping Source Control, repository pickers, and Git API close events consistent. Failed or cancelled deletion must leave the repository available.
