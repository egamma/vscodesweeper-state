# Issue #228696 — Change the global `fetch` available in local extension hosts to be the one from Electron

[https://github.com/microsoft/vscode/issues/228696](https://github.com/microsoft/vscode/issues/228696)

## Summary

The requested default remains deliberately disabled on current main, so a real compatibility decision is still outstanding. This team-authored backlog item must remain open; no post-reopen commit completes it.

## Change summary

Use Electron's `net.fetch` as the global Fetch API for local extension hosts instead of the patched Node.js implementation.

## Best solution

Reassess Electron fetch against the now-established Node fetch proxy support, then either enable Electron fetch by default with compatible fallbacks or document that the patched Node implementation remains the supported default.

- **Validation:** Exercise a local extension-host networking matrix through the default global `fetch`: direct and authenticated-proxy requests, redirects including `redirect: 'manual'`, data/blob URLs, integrity requests, unsafe request headers, response URL/type properties, and system certificates must retain the agreed Fetch API behavior.
- **Behavior:**

  > Local extensions should receive the selected default global Fetch implementation without losing proxy authentication, system-certificate handling, or web-compatible response behavior. Existing uses of manual redirects, data/blob URLs, integrity metadata, request headers, and response properties must continue to behave according to the compatibility contract. The opt-out or fallback behavior, if retained, must be explicit and covered by the networking matrix.
- **Trace:**

  > `connectProxyResolver` calls `patchGlobalFetch` in `src/vs/workbench/api/node/proxyResolver.ts`. That function currently wraps global fetch, reads `http.electronFetch`, routes supported requests to `electron.net.fetch`, and keeps the patched Node implementation for known unsupported Electron cases; `useElectronFetchDefault` is still false. `src/vs/platform/request/common/request.ts` independently registers the setting with a false default and enables additional Node fetch proxy/certificate support by default. Commit https://github.com/microsoft/vscode/commit/2e65b7574c3328f1d7f232babaf62d194db965ab disabled Electron fetch after the initial experiment, while https://github.com/microsoft/vscode/issues/228697 delivered the Node alternative that the maintainer wanted evaluated. Preserve remote extension-host behavior and unrelated HTTP/WebSocket module patching; the unresolved boundary is the local extension host's default Fetch contract.
- **Open decisions:**
  - Should local extension hosts now default to Electron `net.fetch`, or should the proxy-enabled Node fetch remain the supported default?
  - If Electron fetch becomes the default, are per-request fallbacks for unsupported Fetch features part of the public compatibility contract, or should extensions observe Electron's native limitations?
