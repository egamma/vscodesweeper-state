# Issue #225719 — conpty process blocked update on Windows

[https://github.com/microsoft/vscode/issues/225719](https://github.com/microsoft/vscode/issues/225719)

## Summary

Keep open: the February 2025 fix was followed by a reopen, and an August 2026 stable report documents an orphan OpenConsole.exe blocking update cleanup. The remaining shutdown defect needs diagnosis across VS Code's terminal lifecycle and node-pty; no verified later fix or eligible canonical was found.

## Change summary

Orphaned bundled OpenConsole.exe processes survive VS Code shutdown and prevent Windows updates from replacing or cleaning up installation files.

## Best solution

Ensure update-triggered shutdown releases the bundled console processes and their installation-file locks, including terminals restored through persistent-session revival. Establish whether the remaining failure belongs to VS Code's shutdown sequencing or node-pty/ConPTY cleanup before choosing a fix.

Acceptance requires successful update replacement or old-directory cleanup without manually terminating console processes, while terminal restoration remains usable.
- **Trace:**

  > The issue has a maintainer-confirmed historical reproduction and a detailed August 2026 stable recurrence at https://github.com/microsoft/vscode/issues/225719#issuecomment-5285879860. PtyHostService._disposePtyHost sends shutdownAll without awaiting it before clearing the host store; PtyService disposal requests terminal shutdown, and TerminalProcess.shutdown intentionally schedules Windows termination rather than killing synchronously. PtyHostMain also disposes PtyService from a process exit listener. The revival path is PtyService._reviveTerminalProcess, while PersistentTerminalProcess.attach produces the warning quoted in the recent report; that warning is not itself proof of a native orphan. The unresolved boundary is whether shutdown terminates the host before native cleanup completes or whether remaining native clients/handles keep OpenConsole alive independently. https://github.com/microsoft/node-pty/pull/755 and https://github.com/microsoft/node-pty/pull/759 describe competing cleanup behavior, but their pre-reopen changes cannot establish resolution. Preserve intended terminal persistence, reconnection, and trailing-output behavior; do not treat blanket process-name termination or disabling persistence as the acceptance contract.

- **Current shutdown path:** In src/vs/platform/terminal/node/ptyHostService.ts, _disposePtyHost sends shutdownAll without awaiting completion and clears the host store. PtyService.shutdownAll in src/vs/platform/terminal/node/ptyService.ts disposes the service, whose cleanup calls shutdown(true) on its terminals. TerminalProcess.shutdown in src/vs/platform/terminal/node/terminalProcess.ts deliberately queues shutdown on Windows; _kill awaits startup before invoking node-pty kill. These are relevant sequencing boundaries, not conclusive proof of the reported native leak.
