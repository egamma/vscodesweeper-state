# Issue #117327 — An extension spamming console.log will take a lot of CPU time in the render process

[https://github.com/microsoft/vscode/issues/117327](https://github.com/microsoft/vscode/issues/117327)

## Summary

The core protection requested in comment 14 (throttling/rate-limiting console.log forwarding from the extension host to the renderer) was never implemented. The console forwarder in `extHostConsoleForwarder.ts` still forwards every call unbounded, and the renderer-side handler in `mainThreadConsole.ts` has no throttling either. The specific triggering extension fixed its own logging, but VS Code remains vulnerable to any extension that spams console.log.

## Change summary

An extension calling console.log at high frequency in the extension host floods the renderer process with IPC messages, causing UI freezes.

## Best solution

Add rate-limiting or throttling in the console forwarding path — either in `AbstractExtHostConsoleForwarder._handleConsoleCall` (ext host side) or in `MainThreadConsole.$logExtensionHostMessage` (renderer side) — to cap the number of console messages forwarded per time window, dropping or batching excess messages with a summary count.
