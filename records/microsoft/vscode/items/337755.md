# Issue #337755 — Agent plugin sources (agent-plugins/<org>/<project>/_git/<repo>) are not auto-synced before a chat session starts

[https://github.com/microsoft/vscode/issues/337755](https://github.com/microsoft/vscode/issues/337755)

## Summary

Traced on main: the plugin discovery classes (e.g. ConfiguredAgentPluginDiscovery in agentPluginServiceImpl.ts) read plugin files straight from the local checkout with no freshness check — only the install/update flow in pluginMarketplaceService.ts refreshes on an 8h/24h cadence, so a request for session-start sync (or a drift warning) is a real, currently-missing capability, not a design bug.

## Change summary

Agent-plugin git checkouts backed by a remote (e.g. ADO `_git` repos) are read as-is at session start with no fetch/pull and no drift warning, so sessions can silently run on stale instructions/skills.

## Best solution

If pursued, likely belongs in agentPluginRepositoryService.ts / agentPluginServiceImpl.ts as a lightweight remote-HEAD check (not necessarily a full pull) wired into session start, surfaced as a UI hint in the chat/plugin view — but needs a maintainer call given the project's 'no performance-for-features' guardrail around extra network calls on every session start.
