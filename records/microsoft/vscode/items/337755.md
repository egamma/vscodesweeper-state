# Issue #337755 — Agent plugin sources (agent-plugins/<org>/<project>/_git/<repo>) are not auto-synced before a chat session starts

[https://github.com/microsoft/vscode/issues/337755](https://github.com/microsoft/vscode/issues/337755)

## Summary

Confirmed gap on main: the agent-plugin sync path copies files from the local git working tree as-is and never fetches/pulls first, so a stale checkout silently feeds stale instructions into a session. This is a real, narrow feature request distinct from the two open bugs about the marketplace update mechanism itself being broken.

## Change summary

Request that VS Code auto-fetch/pull (or at least check remote HEAD and warn) for git-backed agent-plugin checkouts before a chat session loads their content, instead of relying on a human having run `git pull` in that folder.

## Best solution

Have AgentPluginManager.syncCustomizations (src/vs/platform/agentHost/node/agentPluginManager.ts) or its caller check/refresh the source git checkout against its remote before copying into the nonce cache, or at minimum surface a 'plugin checkout is behind origin' warning in the chat UI — a maintainer should decide which (see open decisions).

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentPluginManager.ts`, `src/vs/platform/agentHost/common/agentPluginManager.ts`
- **Validation:** A test asserting that when the source checkout's local HEAD differs from its remote tracking branch, syncCustomizations either refreshes it first or reports a drift/warning status before the session uses the content.
- **Behavior:**

  > When a chat session starts with an agent whose customizations come from a git-backed local checkout, the session should not silently operate on a checkout that is behind its remote tracking branch. Either the checkout is refreshed (fetch/pull) before load, or the user/session is warned that the local copy is behind origin.
- **Trace:**

  > AgentPluginManager.syncCustomizations/_syncPlugin (src/vs/platform/agentHost/node/agentPluginManager.ts) treats the source plugin URI purely as a filesystem tree to copy (via IFileService.copy) into a nonce-keyed cache dir; it has no notion of git remotes at all. The only existing 'update' concept, PluginAutoUpdate (src/vs/workbench/contrib/chat/browser/pluginAutoUpdate.ts) + IPluginInstallService.updateAllPlugins, operates on marketplace-installed plugin repos on a ~daily timer, not on session start, and is a separate install path from the ad-hoc `_git/<repo>/ref_<branch>` checkouts described here. Do not conflate the two: fixing the marketplace update bugs (#328856, #335460) will not address this report.
- **Open decisions:**
  - Should the checkout be auto-fetched/pulled synchronously before every session start (with the network/latency cost that implies), or should it just compare local vs. remote HEAD and warn without mutating the checkout?
  - If auto-refreshed, should this apply only to plugin sources recognized as git checkouts under the agent-plugins cache, or to any local-folder plugin source?
  - Where should drift be surfaced — a chat UI banner, a notification, or only a log entry?

## Evidence

- **sync copies, doesn't fetch:** AgentPluginManager._syncPlugin (src/vs/platform/agentHost/node/agentPluginManager.ts) does `this._fileService.copy(pluginUri, destDir, true)` from the plugin's source URI straight into the per-session cache — no git fetch/pull call anywhere in this file.
- **existing auto-update is periodic, not session-scoped:** PluginAutoUpdate (src/vs/workbench/contrib/chat/browser/pluginAutoUpdate.ts) only reacts to IPluginMarketplaceService.marketplacesWithUpdates, which is checked ~once/24h per AGENTS_PLUGINS.md — it is not invoked at session start and is a different mechanism (marketplace-managed plugins) than the ad-hoc `agent-plugins/<org>/_git/<repo>/ref_<branch>` checkout path this report describes.
- **related but distinct:** https://github.com/microsoft/vscode/issues/328856 and https://github.com/microsoft/vscode/issues/335460 are bugs about the existing marketplace update mechanism failing for git-subdir plugins; this report asks for a new session-start refresh behavior, which is a different (currently nonexistent) code path.
