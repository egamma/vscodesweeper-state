This matches the persistent review controls reported here; switching branches and restarting are additional persistence evidence rather than an established separate cause.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode/issues/284873#issuecomment-3711661402 distinguishes terminal commits from the existing SCM integration, and https://github.com/microsoft/vscode/issues/284873#issuecomment-3711690788 discusses detecting the affected resources after terminal commands.
- **Current integration boundary:** extensions/git/src/repository.ts invokes _chat.editSessions.accept from Repository.add and commitOperationCleanup. These acceptance hooks belong to Git-extension operations; they do not establish that independently executed terminal commits resolve chat review state.
- **Persistence and overlay path:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts persists entry snapshots in _getStoredState and restores them through _init/_initEntries. chatEditingEditorOverlay.ts displays the review controls for entries whose state remains Modified, without a branch condition in that display path.
- **Intent and report-specific evidence:** The reporter's follow-up says clearing the unresolved suggestion finally removed the condition; restarting and asking the agent to stop had not. A maintainer also explains in https://github.com/microsoft/vscode/issues/311222#issuecomment-4281806915 that pending chat changes are intentionally separate from Git state, supporting classification as workflow polish rather than a demonstrated violation of the current contract.
