# Issue #318793 — Agents: Consider removing some options from file context menu

[https://github.com/microsoft/vscode/issues/318793](https://github.com/microsoft/vscode/issues/318793)

## Summary

This accepted, team-authored Backlog cleanup remains necessary: current main still exposes the identified actions in Agents-window editor context menus without Agents-window-specific gating. The older related report covers non-working chat commands only and does not absorb this issue's broader Explain and Share scope.

## Change summary

Remove or adapt editor context-menu actions that do not work or make sense while reviewing files in the Agents window.

## Best solution

Define an Agents-window-specific context-menu policy: make actions target the active session when that behavior is useful, and suppress actions that have no meaningful Agents-window behavior. Preserve the normal editor context menu, and gate only the vscode.dev share provider rather than the entire Share submenu if other providers remain applicable.

- **Behavior:**

  > When reviewing a file from the Changes or Files tab in the Agents window, the editor context menu should contain only actions that have meaningful behavior in that window. Commands selected for suppression must be absent, while any retained chat command must operate on the active session rather than silently doing nothing. Context menus in ordinary VS Code windows must remain unchanged.
- **Trace:**

  > Add File to Chat and Add Selection to Chat are contributed from src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts without an Agents-window condition. Explain is contributed to `editor/context` from extensions/copilot/package.json, also without that condition. The Share submenu is registered in src/vs/editor/contrib/clipboard/browser/clipboard.ts, and its Copy vscode.dev Link provider comes from extensions/github/src/shareProviders.ts. `IsSessionsWindowContext` already exists as the `isSessionsWindow` context key in src/vs/workbench/common/contextkeys.ts. The uncertainty starts at product policy: https://github.com/microsoft/vscode/issues/315677 treats non-working chat commands as bugs, whereas this issue proposes hiding them; preserve normal-window behavior and avoid suppressing useful Share providers unnecessarily.
- **Open decisions:**
  - Should Add File to Chat and Add Selection to Chat be hidden in the Agents window, or should they attach to the active Agents-window session?
  - Should Explain be hidden, or should its response be routed into the active session?
  - Should the Agents window suppress only Copy vscode.dev Link, or the entire Share submenu?
  - Should the policy apply only to files opened from Changes and Files, or to every editor surface in the Agents window?
