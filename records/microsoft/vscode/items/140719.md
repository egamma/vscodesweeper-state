# Issue #140719 — C symbol names are not displayed in the Disassembly view

[https://github.com/microsoft/vscode/issues/140719](https://github.com/microsoft/vscode/issues/140719)

## Summary

The request remains valid: VS Code's Disassembly view still receives the DAP `symbol` field but does not render it. This re-reviewed issue has no older canonical with the same observable symptom, so it should remain open and be classified as under discussion.

## Change summary

Display DAP `DisassembledInstruction.symbol` values in the Disassembly view alongside the corresponding instructions.

## Best solution

Define a compact symbol-row presentation in the core Disassembly view and render non-empty `DisassembledInstruction.symbol` values without changing the DAP contract or requiring debug-adapter-specific formatting.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/disassemblyView.ts`, `src/vs/workbench/contrib/debug/browser/media/disassemblyView.css`, `src/vs/workbench/contrib/debug/common/debugModel.ts`
- **Validation:** Use a DAP test adapter that returns `DisassembledInstruction` entries with and without `symbol`; open the Disassembly view and verify each non-empty symbol appears with its instruction while symbol-less rows, source interleaving, instruction navigation, and breakpoint behavior remain unchanged.
- **Behavior:**

  > When a debug adapter returns a non-empty DAP `DisassembledInstruction.symbol`, the Disassembly view should visibly associate that symbol with the corresponding instruction. Instructions without symbols must retain their current layout, and source-line interleaving, navigation, and breakpoint behavior must remain unchanged. Acceptance requires exercising the view with a DAP adapter response containing both symbol-bearing and symbol-less instructions.
- **Trace:**

  > The DAP result is retained as `DebugProtocol.DisassembledInstruction` by DisassembledInstructionEntry in src/vs/workbench/contrib/debug/common/debugModel.ts. The renderer in src/vs/workbench/contrib/debug/browser/disassemblyView.ts creates address, instruction-bytes, instruction-text, and source-location elements but never reads the `symbol` property; current CSS is in src/vs/workbench/contrib/debug/browser/media/disassemblyView.css. This confirms a presentation gap rather than an adapter-ownership problem. Preserve the DAP contract and the existing address/breakpoint/source mapping behavior. The related https://github.com/microsoft/vscode/issues/284771 is newer and covers syntax highlighting, not this observable omission.
- **Open decisions:**
  - Should symbols be rendered as separate label rows before their first instruction, or inline in each instruction row that carries the DAP `symbol` value?

## Evidence
