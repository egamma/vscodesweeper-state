# Issue #129400 — Syntax highlighting stops in minified code

[https://github.com/microsoft/vscode/issues/129400](https://github.com/microsoft/vscode/issues/129400)

## Summary

Still reproduces on current main: the CSS grammar's `@charset` rule uses a `\A` (beginning-of-string) anchor that never matches when CSS is embedded in an HTML `<style>` block, causing the tokenizer to misparse `@charset` declarations and break subsequent highlighting. The upstream CSS grammar at microsoft/vscode-css has not been patched.

## Change summary

Syntax highlighting breaks for CSS embedded in HTML `<style>` tags when the CSS contains `@charset`, because the grammar's `\A` anchor doesn't match in an embedded context.

## Best solution

Fix the `@charset` rule in the upstream CSS grammar (microsoft/vscode-css) so it either does not use the `\A` anchor or handles the embedded-in-HTML case gracefully — the rule at line 34 of `extensions/css/syntaxes/css.tmLanguage.json` needs its `begin` pattern adjusted. Alternatively, the HTML grammar's CSS-embedding pattern could strip or neutralize `@charset` before delegating.

- **no fix on main:** git log on extensions/css/syntaxes/css.tmLanguage.json shows no charset-related fix; the `\A` anchor is still present. The upstream grammar version is microsoft/vscode-css commit 9a07d76.
