# Issue #246465 — Cannot resize or move window with Custom Title bar on Linux via MobaXterm

[https://github.com/microsoft/vscode/issues/246465](https://github.com/microsoft/vscode/issues/246465)

## Summary

This is a known Electron limitation with X-forwarded frameless windows, previously triaged as out-of-scope in #62613 with a documented workaround (native title bar). The same verdict applies here.

## Change summary

Custom title bar prevents window resize and drag when VS Code is X-forwarded via MobaXterm on Linux.

## Best solution

Keep using `"window.titleBarStyle": "native"` as the documented workaround. The root cause is in Electron's frameless window implementation over X11 forwarding, not in VS Code's code. Any fix would need to come from the Electron project.

  > Thanks for the report, @stijnfranssen. This is a known limitation in Electron's frameless (custom title bar) window implementation when the window is X-forwarded — the X server on the receiving end (in this case MobaXterm on Windows) doesn't support the operations Electron uses for drag and resize on frameless windows.
  > 
  > This was previously triaged in https://github.com/microsoft/vscode/issues/62613 and is documented in our [Linux setup guide](https://code.visualstudio.com/docs/setup/linux#_cannot-move-or-resize-the-window-while-x-forwarding-a-remote-window). The recommended workaround is the one you've already found: `"window.titleBarStyle": "native"`.
  > 
  > Since this is an Electron/X11 protocol limitation rather than something VS Code can fix on its own, closing this as out of scope — but the workaround should give you full functionality. You may also want to consider using VS Code's [Remote - SSH extension](https://marketplace.visualstudio.com/items?itemName=ms-vscode-remote.remote-ssh) as an alternative to X forwarding, which avoids this class of issue entirely.
