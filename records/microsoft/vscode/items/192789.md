# Issue #192789 — Quick pick: Support searching hangul treating last character as partially formed

[https://github.com/microsoft/vscode/issues/192789](https://github.com/microsoft/vscode/issues/192789)

## Summary

Partial Hangul matching remains missing from Command Palette search. Keep this accepted backlog item open: the merged alternate-keyboard support addresses a different problem, and no qualifying canonical duplicate was found.

## Change summary

Allow the final Hangul character in a quick-pick query to match a partially composed target syllable.

## Best solution

Support composition-aware matching of the final query character against Korean command labels, preserving existing word-boundary matching and highlight positions. Settle the supported composition cases before extending the shared matcher.

  > AbstractCommandsQuickAccessProvider.WORD_FILTER in src/vs/platform/quickinput/browser/commandsQuickAccess.ts combines matchesBaseContiguousSubString and matchesWords. In src/vs/base/common/filters.ts, _matchesWordsCompute accepts exact character or separator matches and otherwise expands only the query character through getAlternateCodes; it never compares a partial Hangul query with the composition of a target syllable. getKoreanAltChars in src/vs/base/common/naturalLanguage/korean.ts supplies keyboard-key representations, while tryNormalizeToBase in src/vs/base/common/normalization.ts avoids length-changing decomposition. - **Open decisions:**
