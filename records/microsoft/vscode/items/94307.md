# Issue #94307 — Better support for case sensitive macOS

[https://github.com/microsoft/vscode/issues/94307](https://github.com/microsoft/vscode/issues/94307)

## Summary

The case-sensitive-volume gap remains on current main, but an open PR directly references and implements #94307. Keep the issue open while that human-owned fix is reviewed and tested.

## Change summary

Detect case-sensitive macOS and Windows filesystem locations so Explorer preserves and displays entries whose names differ only by case.

## Best solution

Review and validate https://github.com/microsoft/vscode/pull/330940 on case-sensitive APFS and per-directory case-sensitive NTFS, then land it if the provider probing and Explorer indexing correctly preserve case-distinct entries without changing behavior on case-insensitive filesystems.

## Evidence

- **current source:** On current main, src/vs/platform/files/node/diskFileSystemProvider.ts advertises FileSystemProviderCapabilities.PathCaseSensitive only when isLinux, so a case-sensitive APFS volume is still treated as case-insensitive.
- **observable source path:** src/vs/workbench/contrib/files/common/explorerModel.ts indexes children through getPlatformAwareName(), which lowercases names whenever the provider lacks PathCaseSensitive; therefore names such as Figures and figures collide in Explorer.
- **current confirmation:** https://github.com/microsoft/vscode/issues/321689 reproduced the same missing-Explorer-entry symptom with extensions disabled on VS Code 1.124.2 and was closed specifically as a duplicate of this issue.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/330940 is open, contains “Fixes #94307,” adds per-resource case-sensitivity probing through FileService and the disk provider, updates Explorer child indexing, and adds targeted FileService and ExplorerModel tests.
- **maintainer direction:** https://github.com/microsoft/vscode/issues/94307#issuecomment-898171103 and https://github.com/microsoft/vscode/issues/94307#issuecomment-898233696 identify filesystem-provider case-sensitivity registration as the required direction while noting that the assumption appears in multiple places.
- **demand:** The issue has 57 community upvotes, remains in the Backlog milestone, and includes a July 2026 confirmation that the case-sensitive APFS behavior persists.
