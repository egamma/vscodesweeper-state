## Evidence

- **Reported trigger and missing confirmation:** https://github.com/microsoft/vscode/issues/298314 reports that setting remote.extensionKind.github.copilot-chat to ["ui"] breaks PATH on a Linux remote using tcsh, while ["workspace"] works. There are no confirming comments, actual PATH captures, environment-contribution details, or sanitized tcsh startup files.
- **Remote environment construction:** src/vs/server/node/remoteTerminalChannel.ts:194-273 constructs the remote environment through buildUserEnvironment, merges terminal configuration, and then applies extension environment collections. src/vs/server/node/extensionHostConnection.ts:26-74 inherits the server/user environment and prepends remote-cli to PATH; this trace does not conclusively explain PATH becoming only '.'.
- **Configuration remains in the launch path:** src/vs/workbench/contrib/terminal/browser/remoteTerminalBackend.ts:175-180 forwards terminal.integrated.env.linux. src/vs/workbench/contrib/terminal/common/terminalEnvironment.ts:244-305 merges that configuration into the terminal environment before the remote channel applies extension contributions. The claim that environment settings have no effect requires launch-environment evidence.
- **Warnings do not establish PATH corruption:** src/vs/platform/terminal/node/terminalEnvironment.ts:145-276 handles supported Linux/macOS shells and returns UnsupportedShell for tcsh and sh, emitting the quoted warning. Unsupported shell integration alone is not proof that the terminal's inherited PATH was removed.
- **Related issues verified, not established duplicates:** https://github.com/microsoft/vscode/issues/277958 and https://github.com/microsoft/vscode/issues/286553 are open and describe Windows-local PATH entries and semicolon separators corrupting Linux remote terminals. The independent diagnosis at https://github.com/microsoft/vscode/issues/277958#issuecomment-5265282656 confirms that cross-platform case, not this Linux-to-Linux PATH collapse. Current extensions/copilot/src/platform/terminal/vscode/terminalServiceImpl.ts:126-173 prepends or appends contributions using the extension-host delimiter; on Linux this is ':', so the documented Windows separator mechanism does not establish the same root cause here.
- **Shell integration request is distinct:** https://github.com/microsoft/vscode/issues/321763 is open and requests native tcsh/csh shell integration for agent command execution. It does not own the separate requirement that ordinary terminals retain PATH without shell integration.
