# Issue #298314 — Integrated terminal loses PATH in tcsh when Copilot/Copilot Chat are forced to UI via `remote.extensionKind`

## Summary

Keep open: the supplied Linux-to-Linux Remote-SSH steps suffice to retest the PATH loss, but current source does not establish its cause or resolution. Terminal environment handling has changed since the reported build; the unsupported-shell warnings alone do not explain the missing PATH.

## Change summary

Opening a remote tcsh terminal with Copilot Chat forced to the UI extension host loses standard executable directories and remote-cli from PATH.

## Best solution

Identify where PATH first changes between remote environment construction, extension contributions, and tcsh initialization, then preserve the inherited remote executable paths. Treat Copilot Chat as in-scope and keep this separate from cross-platform PATH corruption unless reproduction establishes the same root cause.
