# Issue #241088 — Add LocalServerFlow in Microsoft Authentication for Seamless Login in Remote Environments

[https://github.com/microsoft/vscode/issues/241088](https://github.com/microsoft/vscode/issues/241088)

## Summary

Keep open under discussion: custom redirect support remains missing, and the maintainer's final comment explicitly entertained that capability despite earlier reservations. The authentication redirect security boundary and public API contract need owner review, not a decline close.

## Change summary

Allow extensions using their own Microsoft app registration to complete authentication through a custom remote callback without manually copying an authorization code.

## Best solution

Resolve whether the built-in Microsoft authentication provider should accept a per-request registered redirect URI, and define its callback and security contract if accepted. Preserve the existing trusted redirect behavior for VS Code's app registration and Settings Sync.

This later comment prevents treating the earlier unsupported-client explanation as a final rejection of the clarified request.
- **Existing capability does not cover the request:** extensions/microsoft-authentication/src/common/scopeData.ts supports clientId and authorizationServer inputs plus VSCODE_CLIENT_ID and VSCODE_TENANT scopes, but does not extract a custom redirect URI. Its scope filter removes all VSCODE_ entries before sending scopes, so supplying VSCODE_REDIRECT_URI currently does not enable the proposed behavior. package.json exposes no equivalent redirect setting.
- **Current authentication flow boundary:** extensions/microsoft-authentication/src/node/authProvider.ts:createSession obtains callbackUri through env.asExternalUri and selects getMsalFlows using isSupportedClient. In src/node/flows.ts, DefaultLoopbackFlow excludes remote extension hosts; UrlHandlerFlow excludes unsupported clients and constructs UriHandlerLoopbackClient with https://vscode.dev/redirect. Existing local loopback authentication therefore does not supply the requested remote custom-redirect flow.

The clarified request concerns separate app registrations, not removing these protections.
