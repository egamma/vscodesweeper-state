# Issue #319234 — Using a non-string for `contributes.commands[*].enablement` silently breaks extension commands

[https://github.com/microsoft/vscode/issues/319234](https://github.com/microsoft/vscode/issues/319234)

## Summary

The defect remains on current main: validation rejects truthy non-string enablement values but accidentally accepts boolean `false`, which is then passed to the string-only context-key parser and aborts command contribution processing.

## Change summary

A command contribution with boolean `enablement: false` prevents commands from subsequently processed extensions from being registered.

## Best solution

Ensure command contribution validation rejects every defined non-string `enablement` value before context-key parsing, while allowing later extensions' valid commands to continue registering. Cover boolean `false` and a following valid contribution with a regression test.
