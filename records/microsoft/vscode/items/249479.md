# Issue #249479 — Support multiple LSP based completion provider

[https://github.com/microsoft/vscode/issues/249479](https://github.com/microsoft/vscode/issues/249479)

## Summary

Keep open: current main still limits terminal LSP integration to Python, and the merged cleanup explicitly deferred PowerShell support. This team-authored, accepted request has a concrete remaining gap; the related terminal completion API issue does not establish a duplicate.

## Change summary

Extend terminal suggestions backed by language servers beyond Python, starting with PowerShell and potentially supporting Node, Julia, and other language servers.

## Best solution

Extend the terminal LSP integration to additional language environments, starting with PowerShell, with correct completion edits and an explicit coexistence policy for shell-native suggestions. Establish how extensions can opt additional language servers into this integration without requiring language-specific changes in core.

- **Validation:** After the maintainer chooses the supported environments and coexistence policy, add focused terminal-suggest tests for non-Python provider selection, completion replacement ranges, trigger handling, and provider aggregation or selection. Manually verify PowerShell suggestions at an empty prompt and with text after the cursor, acceptance without corrupting surrounding text, and unchanged Python and shell-native behavior.
- **Behavior:**

  > Terminal suggestions should be able to use language-server completions in supported environments beyond Python, with PowerShell as the first concrete target. Suggestions must appear in the intended prompt contexts and insert the correct text without damaging content after the cursor. Existing Python suggestions and shell-native completion behavior must remain usable. Acceptance must exercise the chosen coexistence policy and more than one applicable completion provider where that policy permits it.
- **Trace:**

  > TerminalSuggestContribution._loadLspCompletionAddon in src/vs/workbench/contrib/terminalContrib/suggest/browser/terminal.suggest.contribution.ts gates initialization through getTerminalLspSupportedLanguageObj; lspTerminalUtil.ts currently lists only Python. LspCompletionProviderAddon independently restricts shellTypes to Python and derives edits through createCompletionItemPython, while LspTerminalModelContentProvider supplies the virtual document and command history. The contribution enumerates matching editor completion providers, but their identical registration keys overwrite one another in TerminalCompletionService. https://github.com/microsoft/vscode/pull/258137 was preparatory cleanup, and its review at https://github.com/microsoft/vscode/pull/258137#pullrequestreview-3098177976 records unresolved PowerShell conflicts and prompt-context failures. Preserve existing Python behavior and do not treat enabling the lsp setting as sufficient language support. https://github.com/microsoft/vscode/issues/224505 is related extension-API work, not a verified duplicate; the uncertainty is the observable provider coexistence policy and the contract for opting additional language environments into the bridge.
- **Open decisions:**
  - When PowerShell LSP suggestions are enabled, should they replace the shell-native provider, coexist with it, or be selected through an explicit user preference?
  - Should additional language environments initially be a core-maintained supported list, or should extensions be able to opt language servers into terminal LSP integration through an explicit contract?

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/terminalContrib/suggest/browser/lspTerminalUtil.ts defines terminalLspSupportedLanguages with only Python. TerminalSuggestContribution._loadLspCompletionAddon in terminal.suggest.contribution.ts returns before creating providers for any shell absent from that list; LspCompletionProviderAddon.shellTypes also contains only GeneralShellType.Python.
- **Settings are not broader language support:** src/vs/workbench/contrib/terminalContrib/suggest/common/terminalSuggestConfiguration.ts exposes terminal.integrated.suggest.providers.lsp, disabled by default. Enabling it controls existing provider use, not language registration, and does not bypass the Python-only support gate.
- **Merged preparation, not implementation:** https://github.com/microsoft/vscode/pull/258137 merged as 57352f3d9d3a7bb49222f8c67b50c26875971a0a. Its description explicitly leaves PowerShell LSP support, conflicts with the existing PowerShell provider, completion conversion, and trigger-character handling to separate PRs. https://github.com/microsoft/vscode/pull/258137#pullrequestreview-3098177976 identifies conflicts and missing suggestions at an empty prompt or with content after the cursor, and requests restoring the Python-only supported-language list.
- **Remaining technical boundary:** LspCompletionProviderAddon.provideCompletions still uses createCompletionItemPython for replacement ranges. TerminalSuggestContribution loops over matching editor completion providers but registers each under the same extension/provider key ('lsp', 'lsp'); TerminalCompletionService.registerTerminalCompletionProvider stores providers with Map.set(id, provider), so that loop alone does not establish working simultaneous provider aggregation.
