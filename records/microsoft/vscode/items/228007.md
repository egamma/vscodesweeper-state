# Issue #228007 — Expose Walkthrough Media in Accessible view.

[https://github.com/microsoft/vscode/issues/228007](https://github.com/microsoft/vscode/issues/228007)

## Summary

Keep open: the walkthrough accessible view still omits media content, and a maintainer explicitly agreed that markdown should be included. The existing provider covers step descriptions, not the requested image/SVG alternative text or markdown media.

## Change summary

Include image and SVG alternative text and markdown media contents in the walkthrough accessible view.

## Best solution

Make each step's accessible content include its media's meaningful text while preserving step navigation and existing actions. Define how markdown media containing embedded HTML or interactive controls should be represented before implementation.

- **Validation:** Add walkthrough accessible-content tests for image alt text, SVG alt text, and markdown media across initial/next/previous steps, including localized file content and registry-provided media. Manually open those walkthrough steps, enable screen reader mode, invoke Open Accessible View, and verify media text, unchanged step actions, navigation, and focus restoration.
- **Behavior:**

  > A walkthrough step's Accessible View should expose its image or SVG alternative text and the meaningful contents of its markdown media in addition to the existing title and description. The content must follow the selected step when navigating forward and backward. Existing step actions and focus restoration must remain available. Acceptance must cover built-in and extension-provided media, including localized markdown; the representation of embedded HTML and interactive controls needs agreement.
- **Trace:**

  > GettingStartedAccessibleView obtains the active walkthrough and constructs GettingStartedAccessibleProvider in src/vs/workbench/contrib/welcomeGettingStarted/browser/gettingStartedAccessibleView.ts. The provider's _getContent ignores step.media, and all three content entry points call it. IWalkthroughStep in gettingStartedService.ts already carries image/SVG altText, while markdown carries a resource URI. GettingStartedDetailsRenderer in gettingStartedDetailsRenderer.ts asynchronously obtains markdown through a built-in content registry or localized files and renders it for a webview; that content is currently separate from the accessible provider. Built-in theme_picker.ts demonstrates that markdown media can include HTML and interactive controls, so raw source and readable content are not equivalent. Preserve existing walkthrough filtering, completion behavior, actions, and focus restoration; video media is outside the stated request. The maintainer agreed to markdown exposure at https://github.com/microsoft/vscode/issues/226642#issuecomment-2334386675, and https://github.com/microsoft/vscode/issues/229460 explicitly retained this media gap as known remaining work.
- **Open decisions:**
  - Should markdown media appear as source markup or as readable textual content, and how should embedded HTML controls expose their labels and state in that representation?
