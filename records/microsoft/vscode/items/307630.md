# Issue #307630 — Feature request: per-agent skill scoping (skills property in .agent.md frontmatter)

[https://github.com/microsoft/vscode/issues/307630](https://github.com/microsoft/vscode/issues/307630)

## Summary

A real per-agent skill-isolation gap remains on current main. This issue should stay open as the canonical scoping request, but the public contract needs design because `skills` now means preloading skills into a subagent rather than restricting their availability.

## Change summary

Allow custom agents to restrict which discovered skills are advertised, invocable, and shown in the slash-command UI.

## Best solution

Define an unambiguous per-agent skill-availability contract that preserves the existing `skills` preload meaning, then apply it consistently to model-visible catalogs, user-invocable skill UI, and invocation enforcement without changing global skill discovery.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts`, `extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts`
- **Validation:** Extend the prompt parser and automatic-instructions suites to cover omitted, empty, wildcard, and selected allowlists; add UI/invocation coverage proving excluded skills are absent from the active agent's slash-command surface and cannot be invoked while remaining available to other agents.
- **Behavior:**

  > A custom agent can declare which discovered skills are available to it without changing global skill discovery or other agents. Omitting the restriction preserves today's behavior, an empty allowlist exposes no skills, and a selected allowlist exposes only matching skills. The chosen contract must state whether exclusion covers the model catalog, the slash-command menu, and direct invocation; preload behavior must remain independently expressible and backward compatible.
- **Trace:**

  > Current core catalog construction in src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts starts from every skill returned by `findAgentSkills()` and has no active-agent scope. The parallel Copilot path in extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts also advertises every qualifying skill. `ICustomAgent` in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts carries tool and subagent restrictions but no skill restriction. The `skills` attribute is already presented in promptFileAttributes.ts as startup preloading, and https://github.com/microsoft/vscode/pull/328237 was closed unmerged specifically because its allowlist interpretation conflicted with that contract. Keep global discovery, standalone skill metadata, and preload behavior out of scope; the uncertainty begins at the public name and the strength of availability enforcement.
- **Open decisions:**
  - Should per-agent availability use a new frontmatter field such as `allowedSkills`, preserving `skills` exclusively for preload semantics, or should `skills` be redesigned to represent both behaviors?
  - Does excluding a skill hide only the model-invocable catalog, or must it also remove the slash-command entry and reject direct invocation for that agent?
  - Does the public allowlist match stable skill names only, or also support directory/path glob patterns with different multi-root resolution semantics?

## Evidence

- **current source gap:** On current main, src/vs/workbench/contrib/chat/common/promptSyntax/computeAutomaticInstructions.ts obtains the complete set from `findAgentSkills()` and filters only description, model-invocation, session-type, and troubleshooting conditions; it has no active-agent allowlist.
- **extension path gap:** extensions/copilot/src/platform/promptFiles/node/automaticInstructionsCollector.ts similarly calls `getSkills()` and advertises all qualifying skills without per-agent filtering.
