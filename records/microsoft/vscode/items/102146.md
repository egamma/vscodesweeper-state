# Issue #102146 — Open remote settings GUI when extension executes workbench.action.openSettings with query in remote session

[https://github.com/microsoft/vscode/issues/102146](https://github.com/microsoft/vscode/issues/102146)

## Summary

Still valid: the `workbench.action.openSettings` command does not expose the `target` option to extensions, so remote sessions open to the User tab instead of Remote. The internal infrastructure (`target?: ConfigurationTarget` on `ISettingsEditorOptions`) exists but `sanitizeOpenSettingsArgs` doesn't pass it through. No fix found on main.

## Change summary

Allow extensions calling `workbench.action.openSettings` with a query to open the Remote settings tab in a remote session.

## Best solution

Extend `sanitizeOpenSettingsArgs` to accept and forward a `target` (ConfigurationTarget) option, or auto-detect the remote context when a remote extension invokes the command. The plumbing already exists in `ISettingsEditorOptions.target` — it just needs to be exposed through the public command interface in `src/vs/workbench/contrib/preferences/browser/preferences.contribution.ts`.
