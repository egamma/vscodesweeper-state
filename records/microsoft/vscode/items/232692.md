# Issue #232692 — Cut/paste broken for CodeMirror editor in extension webview after updating VSCode

[https://github.com/microsoft/vscode/issues/232692](https://github.com/microsoft/vscode/issues/232692)

## Summary

Keep open: the supplied sample and independent confirmations establish a real webview clipboard regression, and current source still uses the implicated execCommand path. Newer migration work is related, but neither a verified fix nor an older canonical covering this specific symptom was established.

## Change summary

Restore cut and paste in CodeMirror editors embedded in extension webviews, where clipboard events stopped arriving after VS Code 1.94.

## Best solution

Restore reliable clipboard-event delivery to embedded CodeMirror editors without requiring extensions to monkey-patch document.execCommand. Coordinate with the webview migration work in https://github.com/microsoft/vscode/issues/239228 while retaining this report's concrete regression sample.

- **Behavior:**

  > A CodeMirror editor hosted directly in an extension webview must support cut and paste without replacing document.execCommand. The reported regression suppresses clipboard events despite the same editor working in VS Code 1.94. Acceptance requires working keyboard and menu operations on macOS, with paste inserting text once and cut updating both the editor and clipboard. Existing plain-input editing and other editing commands must remain functional.
- **Trace:**

The reporter and downstream https://github.com/ajthinking/data-story/pull/431 bypass this operation with synthetic clipboard events, but this does not isolate the exact current browser failure. Existing webviewShellMessaging.test.ts exercises focus restoration using a mocked command, not actual clipboard dispatch.
