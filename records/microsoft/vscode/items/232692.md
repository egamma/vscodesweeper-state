# Issue #232692 — Cut/paste broken for CodeMirror editor in extension webview after updating VSCode

[https://github.com/microsoft/vscode/issues/232692](https://github.com/microsoft/vscode/issues/232692)

## Summary

Still present on main: VS Code's webview clipboard handling uses the deprecated `document.execCommand()` API, which doesn't properly dispatch clipboard events to CodeMirror's contenteditable elements. No fix has landed. The reporter's workaround (polyfilling execCommand) confirms the root cause is in how VS Code bridges clipboard operations into the webview iframe.

## Change summary

Cut/copy/paste commands fail to reach CodeMirror's contenteditable div inside extension webviews because VS Code's webview uses `document.execCommand()` which doesn't fire the expected ClipboardEvents.

## Best solution

Modernize the webview clipboard bridge in `src/vs/workbench/contrib/webview/browser/pre/index.html` and `webviewElement.ts` to use the Clipboard API (`navigator.clipboard`) and dispatch proper `ClipboardEvent`s instead of relying on the deprecated `document.execCommand()`. This would fix compatibility with CodeMirror and other modern contenteditable frameworks. The reporter's polyfill in comment 1 demonstrates a viable approach.
