# Issue #328642 — Multi-diff editor is in a random order, not the same as the list of files in the changes view

[https://github.com/microsoft/vscode/issues/328642](https://github.com/microsoft/vscode/issues/328642)

## Summary

Confirmed in source: the multi-diff editor's SCM resolver doesn't apply the same ordering as the Changes (SCM) view tree, so the two surfaces can show files in different orders — routing to the scm/multi-diff-editor owners for a fix.

## Change summary

When opening the multi-diff editor from an SCM resource group, the file order doesn't match the (possibly sorted) order shown in the Source Control / Changes view.

## Best solution

Have ScmResolvedMultiDiffSource (scmMultiDiffSourceResolver.ts) sort/derive its MultiDiffEditorItem list using the same comparator logic as SCMTreeSorter in scmViewPane.ts (viewSortKey: Name/Path/Status, and List vs Tree grouping), instead of using the raw, unsorted `this._group.resources` order.
