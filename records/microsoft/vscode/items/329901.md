# Issue #329901 — Native dialogs on Windows are auto-closing

[https://github.com/microsoft/vscode/issues/329901](https://github.com/microsoft/vscode/issues/329901)

## Summary

Actively investigated by maintainers with a confirmed repro and traced root cause; two open PRs are in flight, no fix has landed on main, and a collaborator explicitly said it won't ship in 1.133 — this must stay open.

## Change summary

Native dialogs (Help > About, confirmation/warning dialogs) on Windows close immediately without user interaction, accompanied by a system ding.

## Best solution

Land one of the open fixes (https://github.com/microsoft/vscode/pull/330128 or https://github.com/microsoft/vscode/pull/330602) that validates/bounds native dialog button-id responses before mapping them, per the upstream Electron issue; until then point affected users at the `window.dialogStyle: custom` workaround already confirmed by a maintainer in this thread.

## Evidence

- **collaborator root-cause analysis:** Comment by dmitrivMS (COLLABORATOR) traces this to electron/electron#52747: on Windows the #32770 window class overloads message 0x0466 between CDM_GETFOLDERPATH and TDM_CLICK_BUTTON, so third-party software (DLP/endpoint agents) enumerating file dialogs can send a button-click message that Electron misinterprets as a click on a nonexistent button id, silently closing the dialog.
- **repro confirmed:** dmitrivMS: 'FYI - verified the repro above works' (2026-08-10T23:38:27Z), and deepak1556 is collecting further diagnostic logs (dialogcapture.ps1) from other reporters to confirm the same root cause.
- **open fix PRs, not yet merged:** https://github.com/microsoft/vscode/pull/330128 ('dialogs: recover from unexpected native responses') and https://github.com/microsoft/vscode/pull/330602 ('Fix: validate native dialog responses to prevent silent auto-close') are both still open; git log on main shows no related commit landed yet.
- **maintainer status update:** deepak1556 (2026-08-13T03:21:49Z): 'It won't be fixed in 1.133, we are in the process of analyzing the logs from users, will update here when we [have] a fix timeline.' Workaround: `"window.dialogStyle": "custom"` (verified this is a real setting, used in src/vs/workbench/browser/parts/dialogs/dialog.ts and src/vs/workbench/electron-browser/parts/dialogs/dialog.contribution.ts).
- **duplicate cluster:** Many related reports (e.g. https://github.com/microsoft/vscode/issues/330091, https://github.com/microsoft/vscode/issues/330436, https://github.com/microsoft/vscode/issues/330427) already closed/consolidated around this same root cause per the timeline; this issue itself is under active maintainer ownership and is not a satellite duplicate — it is one of the tracked reports being used to confirm the pattern.
