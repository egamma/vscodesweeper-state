# Issue #329901 — Native dialogs on Windows are auto-closing

[https://github.com/microsoft/vscode/issues/329901](https://github.com/microsoft/vscode/issues/329901)

## Summary

This is the well-diagnosed canonical issue for a real, confirmed defect: third-party software (observed to be WPS Office) sends a stray SendMessage to the shared #32770 dialog window class that Electron misinterprets as a button click, auto-closing native VS Code dialogs. Root cause and fix live in Electron (electron/electron#52747, fixed upstream in electron/electron#52812), which has not yet been bumped into VS Code's .npmrc (still target="42.8.1" on current main) — nothing has shipped to close this yet.

## Change summary

Native Windows dialogs (About, confirmation prompts, etc.) close themselves immediately with a system ding, apparently triggered by interference from other software polling/inspecting the shared dialog window class.

## Best solution

Keep open and tracked as `upstream` until VS Code bumps its bundled Electron past the version containing electron/electron#52812's button-id range-check fix; a defensive bounds check on `buttonIndeces[result.response]` in src/vs/platform/dialogs/electron-main/dialogMainService.ts could also be considered as a VS Code-side mitigation, but two prior attempts at that (PRs #330128 and #330602) were closed without merging, so the collaborator-preferred fix path is the upstream Electron runtime change plus the documented `"window.dialogStyle": "custom"` workaround in the meantime.

## Evidence

- **root cause trace:** Collaborator dmitrivMS traced the bug to electron/electron#52747: on Windows, both file dialogs and task dialogs share the #32770 window class, and third-party software (confirmed as WPS Office's wpscloudsvr.exe by ETW trace in comment 8) sends message 0x0466 which Electron's message box misreads as a button click, closing the dialog with an out-of-range response id.
- **upstream fix status:** The Electron-side fix merged as electron/electron#52812 ("fix: add button id range check for message boxes on windows"), but current main's .npmrc still pins target="42.8.1" (unchanged in the latest commit 79ee2233), which is one of the versions confirmed still vulnerable per the linked electron issue — the fix has not been picked up yet.
- **no local fix landed:** src/vs/platform/dialogs/electron-main/dialogMainService.ts line ~162 still does `response: buttonIndeces[result.response]` with no bounds guard; both prior attempts to patch this in VS Code (PR #330128, PR #330602) are listed as closed, not merged.
- **reproduction confirmed:** dmitrivMS confirmed the repro works (comment 4), and reporter FeelLiao confirmed killing WPS Office processes restored normal dialog behavior (comment 9).
- **workaround documented:** Collaborator deepak1556 gave the interim workaround `"window.dialogStyle": "custom"` (comment 7), and is actively collecting ETW traces from affected users to confirm root cause before committing to a fix approach.
