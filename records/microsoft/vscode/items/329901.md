# Issue #329901 — Native dialogs on Windows are auto-closing

[https://github.com/microsoft/vscode/issues/329901](https://github.com/microsoft/vscode/issues/329901)

## Summary

Root cause is confirmed upstream in Electron's Windows message-box handling (electron/electron#52747/#52812); no fix has landed on vscode's main yet — both proposed workaround PRs (#330128, #330602) were closed unmerged and the Electron version bump (#332863) is still open. Milestone 1.136.0 is assigned, so this stays open regardless.

## Change summary

Native message-box/task dialogs on Windows (About, sign-out, confirmation prompts) silently auto-close, sometimes with a system ding, when certain third-party software (e.g. WPS Office) sends a conflicting Windows message to the shared #32770 dialog window class.

## Best solution

Land the Electron version bump in https://github.com/microsoft/vscode/pull/332863 (or an equivalent) once it includes the upstream button-id range check from https://github.com/electron/electron/pull/52812, and close this once that ships; in the interim the workaround `"window.dialogStyle": "custom"` avoids the native path entirely.

## Evidence

- **root cause trace:** Collaborator dmitrivMS traced this to electron/electron#52747: Windows message 0x0466 is ambiguous between CDM_GETFOLDERPATH and TDM_CLICK_BUTTON on the shared #32770 window class; Electron doesn't bound-check button ids >=100, so a stray message (e.g. wParam=520) is misread as a button click and the dialog closes with an invalid response index.
- **confirmed trigger:** Collaborator deepak1556 confirmed via ETL trace from a reporter that WPS Office's cloud service (wpscloudsvr.exe) sends a SendMessage to every #32770-class dialog owned by VS Code 40-50ms before each close; another reporter (FeelLiao) confirmed killing WPS processes resolved the issue.
- **no fix on main yet:** PRs https://github.com/microsoft/vscode/pull/330128 and https://github.com/microsoft/vscode/pull/330602 are both closed with merged_at=null (per GitHub API); the Electron bump PR https://github.com/microsoft/vscode/pull/332863 (42.10.0) is still open; current checkout's .npmrc still pins target="42.8.1", the version confirmed vulnerable.
- **milestone gate:** Issue carries milestone 1.136.0, a real scheduling milestone (not Backlog/Backlog Candidates/On Deck), which per policy blocks any close proposal.
