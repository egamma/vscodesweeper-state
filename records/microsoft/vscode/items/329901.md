# Issue #329901 — Native dialogs on Windows are auto-closing

[https://github.com/microsoft/vscode/issues/329901](https://github.com/microsoft/vscode/issues/329901)

## Summary

Actively being worked on by VS Code collaborators — a real, root-caused interop bug (third-party software like WPS Office sending conflicting Windows messages to Electron dialogs, tied to electron/electron#52747) with no fix landed yet, so this must stay open.

## Change summary

Native (task/message-box) dialogs on Windows unexpectedly auto-close with a system ding, apparently triggered by third-party software probing dialog windows.

## Best solution

Land the Electron-side runtime fix that deepak1556 said they'd prepare (bounding/validating the button response id so a spurious `0x0466` message from another process can't be misread as a valid button click), and in the meantime point affected users at the documented `"window.dialogStyle": "custom"` workaround.

- **Rationale:** Root cause lives in Electron's native dialog response handling (a missing upper-bound check on custom button ids feeding into VS Code's response mapping); the maintainer who traced it says a runtime fix is still being prepared, so this isn't a small localized VS Code-only change ready for an automatic fix.

## Evidence

- **root cause traced:** Comment by dmitrivMS (COLLABORATOR) traces this to electron/electron#52747: Windows message 0x0466 is ambiguous between CDM_GETFOLDERPATH and TDM_CLICK_BUTTON on #32770-class windows, and Electron doesn't bound-check button ids >=100, so a stray message from another process is misread as a button click and the dialog force-closes.
- **confirmed 3rd-party trigger:** Comment by deepak1556 (COLLABORATOR) analyzed an ETL trace from a reporter showing WPS Office's cloud service (wpscloudsvr.exe) sending SendMessage to VS Code's dialog windows 40-50ms before each close; reporter FeelLiao confirmed killing WPS processes fixed the issue.
- **fix not yet landed:** Both candidate PRs referenced in the timeline, https://github.com/microsoft/vscode/pull/330128 and https://github.com/microsoft/vscode/pull/330602, were closed without merging (verified via `gh pr view`); deepak1556 states on 2026-08-13 'It won't be fixed in 1.133 ... will update here when we [have] a fix timeline', and on 2026-08-13 'I will prepare fix in the runtime based on this info' — work is in progress, not shipped.
- **documented workaround:** Collaborators recommend `"window.dialogStyle": "custom"` as a temporary mitigation while the root cause is fixed in the Electron/runtime layer.
