# Issue #167612 — Reopen in Local Folder has no validation

[https://github.com/microsoft/vscode/issues/167612](https://github.com/microsoft/vscode/issues/167612)

## Summary

Keep open: the local-folder picker still accepts an arbitrary folder without warning, and unmatched cloud changes can be skipped with only a log message. This team-authored, accepted backlog request remains distinct from existing identity checks and overwrite confirmations.

## Change summary

Warn when Continue Working On targets an empty or unrelated local folder that cannot receive the stored working changes.

## Best solution

Make the local-folder continuation flow explain when the selected folder cannot receive the working changes and give the user an opportunity to reconsider. Preserve repository-identity matching and stored changes rather than treating an empty folder as a clone or forcing unrelated changes into it.
