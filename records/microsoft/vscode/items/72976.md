# Issue #72976 — Source Control: "Accept All Incoming" for "deleted by them" should delete the file from working copy and stage the change

[https://github.com/microsoft/vscode/issues/72976](https://github.com/microsoft/vscode/issues/72976)

## Summary

The requested behavior remains missing on current main: “Accept All Incoming” only processes textual conflict markers, while a “Deleted By Them” resource is resolved separately through the staging prompt. With 27 community upvotes and no older canonical covering this exact symptom, the request should remain open.

## Change summary

Make “Accept All Incoming” resolve a “Deleted By Them” conflict by deleting the working-copy file and staging that deletion.

## Best solution

Define consistent Source Control semantics for accepting incoming deletion conflicts, so the action resolves the selected resource without requiring the separate Stage Changes prompt while preserving normal text-conflict behavior.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/commandHandler.ts`, `extensions/git/src/commands.ts`, `extensions/merge-conflict/package.json`
- **Validation:** Using a Git fixture with a `DELETED_BY_THEM` conflict, invoke “Accept All Incoming” from the Source Control resource context menu and verify that the working-copy file is removed, the deletion is staged, and no unresolved merge resource remains; existing text-conflict Accept All behavior must remain unchanged.
- **Behavior:**

  > For a file modified locally and deleted by the incoming side, invoking “Accept All Incoming” from Source Control should accept the deletion rather than report that no merge conflicts were found. The file should be removed from the working copy and the conflict should leave the unresolved Merge Changes group. Acceptance must also confirm the intended index state and that ordinary marker-based text conflicts continue to be handled as before.
- **Trace:**

  > The Source Control menu contribution in extensions/merge-conflict/package.json invokes `merge-conflict.accept.all-incoming`. In extensions/merge-conflict/src/commandHandler.ts, `acceptAllIncomingResources` reaches `acceptAllResources`, which only applies edits returned by the document conflict-marker tracker; deletion conflicts contain no markers and are skipped. The Git extension separately recognizes `Status.DELETED_BY_THEM` in extensions/git/src/commands.ts and resolves it through `_stageDeletionConflict`, including `repository.rm` when the user chooses deletion. Commit https://github.com/microsoft/vscode/commit/039a49a5eab688800b0226cf2c4addc797c94a86 added multi-resource text-conflict handling but did not bridge this deletion path. Preserve current behavior for normal text conflicts and for “Deleted By Us”; the uncertainty begins at whether accepting an incoming deletion should also stage automatically or only resolve the working-tree choice consistently with other Accept All operations.
- **Open decisions:**
  - Should “Accept All Incoming” stage an accepted deletion immediately, as requested here, even though accepting ordinary text conflicts currently leaves saving and staging as separate actions?

## Evidence

- **current source:** extensions/merge-conflict/src/commandHandler.ts registers `merge-conflict.accept.all-incoming`; `acceptAllResources` opens each document and skips resources for which the conflict-marker tracker returns no conflicts, so a deletion conflict is not resolved.
- **existing workaround:** extensions/git/src/commands.ts handles `Status.DELETED_BY_THEM` only in `_stageDeletionConflict`, where Stage Changes prompts between “Keep Our Version” and “Delete File” and calls `repository.rm` for deletion. This matches the workaround documented in https://github.com/microsoft/vscode/issues/72976#issuecomment-1916364671 but does not satisfy the requested Accept All Incoming behavior.
