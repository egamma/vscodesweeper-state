# Issue #72976 — Source Control: "Accept All Incoming" for "deleted by them" should delete the file from working copy and stage the change

[https://github.com/microsoft/vscode/issues/72976](https://github.com/microsoft/vscode/issues/72976)

## Summary

Valid feature request with 27 upvotes (above backlog threshold). The 'Accept All Incoming' action in the diff editor doesn't handle deletion conflicts — it should delete the file and stage the change instead of showing 'No merge conflicts found'. The staging path via right-click already handles this (with a keep/delete dialog in `_stageDeletionConflict`), but the editor-level accept action does not.

## Change summary

When a file is 'deleted by them' during a merge, clicking 'Accept All Incoming' in the diff editor should delete the file and stage the change, instead of showing a confusing 'No merge conflicts found' warning.

## Best solution

Extend the merge/diff editor's 'Accept Incoming' flow to detect deletion conflicts (DELETED_BY_THEM / DELETED_BY_US status) and handle them the same way `_stageDeletionConflict` in `extensions/git/src/commands.ts` does — either auto-delete/stage when accepting incoming for a 'deleted by them' conflict, or present the keep/delete dialog. The git extension's `openMergeEditor` command already skips deleted files, so the fix likely needs to intercept the open/accept flow earlier for deletion-type conflicts.
