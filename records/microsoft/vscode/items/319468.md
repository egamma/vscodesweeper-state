# Issue #319468 — [Error] unhandlederror-potential listener LEAK detected, popular

[https://github.com/microsoft/vscode/issues/319468](https://github.com/microsoft/vscode/issues/319468)

## Summary

Still reproduces on main: when a webview extension loads hundreds of resources concurrently, each `readFileStream` call creates a `CancellationTokenSource(token)` that registers a listener on the shared `_resourceLoadingCts` parent token, breaching the listener threshold and triggering sustained high CPU in the ServiceWorker thread.

## Change summary

Webview resource loading triggers a listener leak warning and sustained ~100% CPU when an extension loads hundreds of JS/CSS assets concurrently, because each `fileService.doReadFileStream` creates a `CancellationTokenSource` that registers a listener on the shared parent cancellation token.

## Best solution

The prior fix in https://github.com/microsoft/vscode/commit/38c9d8e83c2 (#312367) removed per-stream `onCancellationRequested` listeners in the ReadableStream setup but left the deeper path untouched: `fileService.doReadFileStream` (fileService.ts:596) still creates `new CancellationTokenSource(token)` for every call, each registering a listener on the same parent. The fix should either (a) raise the listener threshold on the `_resourceLoadingCts` emitter to accommodate high-fan-out webview loads, (b) avoid passing the shared token into `readFileStream` and instead manage cancellation at the webview layer, or (c) throttle/batch concurrent resource loads to stay under the threshold. The webview team (mjbvz) owns this area.
