# Issue #285287 — Separate Taskbar Icons (Groups) for Multiple vscode Instances

[https://github.com/microsoft/vscode/issues/285287](https://github.com/microsoft/vscode/issues/285287)

## Summary

Keep this accepted, community-supported request open: current taskbar identity does not support grouping several coding windows separately from a note-taking window. Related requests exist, but none verified here fully owns the requested user-defined, many-windows-to-one-group behavior.

## Change summary

Allow multiple VS Code windows to form separate logical taskbar groups that can be selected with Super+Number.

## Best solution

Provide opt-in taskbar grouping for distinct working contexts while preserving the default shared application identity. Decide whether groups follow profiles or an independent grouping concept, coordinating the design with the related taskbar-icon requests.

## Plan brief

- **Likely files:** `src/vs/code/electron-main/app.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/environment/node/argv.ts`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** On Windows, open two coding windows and one note-taking window, assign the agreed grouping identities, and verify exactly two taskbar groups with both coding windows together and the note-taking window separate. Verify Win+Number targets those groups, default unconfigured windows retain existing grouping, and reopening preserves the agreed persistence behavior.
- **Behavior:**

  > Users running several VS Code windows should be able to organize them into logical taskbar groups rather than one shared group or one group per window. The motivating case is two or more coding windows in one group and a note-taking window in another, navigable through Super+Number. Acceptance requires preserving ordinary unconfigured grouping and verifying the chosen persistence behavior after reopening. Custom icon artwork and independent Jump Lists are related requests, not explicit requirements of this report.
- **Trace:**

  > CodeApplication.startup in src/vs/code/electron-main/app.ts:705-710 assigns a process-level Windows AppUserModelID from the product identity, distinguishing portable mode only. The CLI registrations in src/vs/platform/environment/node/argv.ts support profiles and separate user-data directories without using either to select that taskbar identity; window.title in src/vs/workbench/browser/workbench.contribution.ts changes titles rather than grouping. Native window handling lives in src/vs/platform/windows/electron-main/windowImpl.ts, where the searched source exposes no grouping identity customization. The investigation establishes the missing configuration path, not a tested per-window implementation; native identity, shortcuts and grouping interactions need design verification. Preserve default installation identity and existing portable separation. Coordinate with https://github.com/microsoft/vscode/issues/248638 and https://github.com/microsoft/vscode/issues/307266 without assuming their icon or Jump List requirements are part of this issue.
- **Open decisions:**
  - Should logical taskbar groups follow VS Code profiles, or should users be able to group windows independently of their profiles?
  - Should group membership persist across reopening, and if so should it belong to a workspace, a profile, or a separately named group?
  - Is the initial scope Windows taskbar grouping, or should the Super+Number workflow also be supported on Linux desktops?
