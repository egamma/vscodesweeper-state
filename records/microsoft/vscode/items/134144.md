# Issue #134144 — Explorer does not refresh when previously removed root is coming back

[https://github.com/microsoft/vscode/issues/134144](https://github.com/microsoft/vscode/issues/134144)

## Summary

The bug remains source-reproducible on current main: Explorer handles added children but ignores an added event for the workspace root itself, leaving the missing-root state visible until the window-focus fallback refreshes it. This team-authored Backlog bug should remain open.

## Change summary

Restore the Explorer tree immediately when a removed workspace root or symbolic-link target reappears while its VS Code window is unfocused.

## Best solution

Have the Explorer recognize a file-added event matching a missing model root and refresh that root without broadening ordinary child-event refreshes or relying on window focus.

- **Behavior:**

  > When a workspace root has disappeared and an external operation restores that same root, Explorer updates without requiring the user to focus the window. The same must hold when the root is reached through a symbolic link whose target disappears and returns. Ordinary additions below the root and the existing focus-refresh fallback must remain unchanged, and unrelated root updates must not cause unnecessary whole-tree refreshes.
- **Trace:**

  > ExplorerService queues IFileService.onDidFilesChange events in src/vs/workbench/contrib/files/browser/explorerService.ts. Its ADDED-event path searches the model for dirname(resource), which works for children of a workspace root but returns no model item when resource is the root itself; shouldRefresh therefore remains false. The IHostService focus listener later performs a full refresh, explaining why focusing the window masks the defect. Existing focused unit coverage is in src/vs/workbench/contrib/files/test/browser/explorerService.test.ts and already uses TestFileService.fireFileChanges with fake timers. Keep the boundary to restoration of a missing root; do not turn every root-level update into an unconditional refresh or remove the focus fallback.
