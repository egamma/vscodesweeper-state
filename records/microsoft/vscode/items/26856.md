# Issue #26856 — See git diff of two files in horizontal layout

[https://github.com/microsoft/vscode/issues/26856](https://github.com/microsoft/vscode/issues/26856)

## Summary

Keep this accepted Backlog request open: current source still lacks a top/bottom layout for the original and modified panes within one diff editor. Its 81 upvotes and related duplicate establish sustained demand; inline view and ordinary editor splitting do not satisfy the request.

## Change summary

Allow the two panes of a text diff editor to be stacked top/bottom instead of left/right.

## Best solution

Provide an optional top/bottom two-pane layout in the shared text diff editor, retaining existing comparison, navigation, editing, and accessibility behavior. Decide how users select and persist the orientation before implementation; automatic monitor-based switching is a separate enhancement.

The acceptance check should also open a Git text diff in a tall editor, switch between supported layouts, resize the divider, navigate changes, and confirm the agreed persistence behavior.
- **Behavior:**

  > Users can compare the original and modified versions in separate panes stacked top/bottom within one text diff editor. This is not inline diff rendering and must preserve access to both versions, existing editing permissions, diff navigation, and keyboard accessibility. Acceptance checks cover switching layouts, resizing the divider, and comparing wide code in a portrait-shaped editor. Existing left/right and inline modes remain available; automatic monitor-orientation detection is outside the central request.
- **Trace:**

  > TextDiffEditor in src/vs/workbench/browser/parts/editor/textDiffEditor.ts constructs DiffEditorWidget rather than the ordinary SideBySideEditor that supports workbench.editor.splitInGroupLayout. DiffEditorWidget._layoutInfo partitions width and gives both inner editors the full height; DiffEditorSash fixes its sash orientation to vertical and uses X-coordinate movement. DiffEditorCommandsService.setViewMode currently selects inline, sideBySide, or automatic inline fallback, with no stacked mode. DiffEditorViewZones coordinates scrolling and alignment between both editors, so the design must account for those behaviors rather than treating this as a sash-only change. Preserve existing modes, model identities, editing permissions, and comparison semantics. https://github.com/microsoft/vscode/issues/66962 was explicitly consolidated into https://github.com/microsoft/vscode/issues/26856; the unresolved product boundary is how orientation is selected and persisted.
- **Open decisions:**
  - Should top/bottom orientation be a persistent user/workspace preference, a per-diff-editor selection, or both?

## Evidence

- **Current layout limitation:** src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts:138–197 computes originalLeft, modifiedLeft, and pane widths, then lays out both editors at fullHeight. Its two-pane branch divides width, not height. src/vs/editor/browser/widget/diffEditor/components/diffEditorSash.ts constructs a fixed Orientation.VERTICAL sash and handles horizontal pointer movement.
- **Existing settings and commands are partial alternatives:** src/vs/editor/common/config/editorConfigurationSchema.ts registers diffEditor.renderSideBySide as a boolean selecting side-by-side versus inline; diffEditor.useInlineViewWhenSpaceIsLimited and diffEditor.renderSideBySideInlineBreakpoint select inline fallback. toggle.diff.renderSideBySide and DiffEditorCommandsService.setViewMode offer inline, sideBySide, and automatic modes, not a top/bottom two-pane layout.
