# Issue #328730 — Add file context menu actions to the Agent Sessions Changes view

[https://github.com/microsoft/vscode/issues/328730](https://github.com/microsoft/vscode/issues/328730)

## Summary

Keep open: current source provides per-file toolbar operations, including provider-supported discard, but does not wire the requested file context menu. This team-authored request remains actionable; the related newer reports do not qualify as duplicate canonicals.

## Change summary

Expose applicable file actions, especially Discard Changes, from the Agent Sessions Changes list context menu.

## Best solution

Make supported per-file operations discoverable through the Changes list context menu, preserving provider capabilities, confirmation, enablement, and session targeting. Establish which familiar SCM actions apply rather than exposing repository-specific actions indiscriminately.

- **Behavior:**

  > Files in the Agent Sessions Changes list should expose applicable file operations through a context menu, including Discard Changes or an equivalent revert operation when supported. Users should be able to act on a file without leaving the session review surface. Existing destructive-action confirmation and operation enablement must remain intact. Acceptance should cover mouse and keyboard invocation, correct session/file targeting, and the agreed multi-selection behavior.
- **Trace:**

  > ChangesViewPane.createChangesTree in src/vs/sessions/contrib/changes/browser/changesView.ts creates both the main tree and embedded sidebar tree without a file context-menu handler. ChangesTreeRenderer in changesViewRenderer.ts already renders AgentsChangeInlineToolbar, and ChangesViewActionRunner passes session resource, checkpoint reference, and selected file URIs to menu actions. ChangesetOperationsActionControllerContribution in changesActions.ts separately exposes provider-neutral resource operations through inline and multi-diff toolbars. The Copilot CLI contribution also provides a gated discard command through agents/change/inline, so introducing a new revert implementation is not established as necessary. Preserve provider capability boundaries and existing confirmation/enablement semantics; do not assume every SCM action applies to every session. The unresolved scope is which additional actions and selection semantics the menu should expose. Related design context is https://github.com/microsoft/vscode/issues/336620; the distinct undo failure is https://github.com/microsoft/vscode/issues/336800.
- **Open decisions:**
  - Should the context menu expose only operations already supported by the session's file toolbar, or also familiar file actions such as opening, revealing, and copying paths?
  - Should destructive context-menu actions apply to all selected files, and should folder rows offer equivalent recursive actions?
