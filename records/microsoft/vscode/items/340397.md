# Issue #340397 — Touch scrolling in the editor stops, and momentum stops working, once the touched line scrolls out of view

[https://github.com/microsoft/vscode/issues/340397](https://github.com/microsoft/vscode/issues/340397)

## Summary

Clean, well-diagnosed bug confirmed in current source: Gesture in touch.ts listens for touchmove/touchend only on document and matches events via target.contains(initialTarget), so once the editor removes the originally-touched DOM node (e.g. a scrolled-out line), later touch events for that touch are lost, leaving it stuck in activeTouches and breaking momentum for the next swipe.

## Change summary

Touch scroll/momentum in the Monaco editor breaks once the touched DOM node is removed mid-drag (e.g. the line scrolls out of view), because Gesture's document-level listeners and target.contains(initialTarget) matching can't reach events whose original target node is gone.

## Best solution

Apply the reporter's proposed fix in src/vs/base/browser/touch.ts: additionally listen for a touch's own touchmove/touchend on the node it started on (used only while that node has been removed), and resolve a touch's gesture dispatch targets once at touchstart instead of re-checking containment on every later event and at inertia start.

- **Trace:**

  > In src/vs/base/browser/touch.ts, Gesture's constructor attaches touchstart/touchmove/touchend listeners only to `window.document` (not the originating node), and both `dispatchEvent()` and the inertia dispatch-target lookup in `onTouchEnd()` gate on `target.contains(event.initialTarget)`/`t.contains(data.initialTarget)`.
