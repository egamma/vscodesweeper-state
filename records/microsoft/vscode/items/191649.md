# Issue #191649 — Moved lines aren't indicated to screen reader users

[https://github.com/microsoft/vscode/issues/191649](https://github.com/microsoft/vscode/issues/191649)

## Summary

Keep open: change navigation still does not announce detected code moves, and the existing overlay captions do not cover that interaction. Maintainers explicitly agreed to address this accessibility gap before enabling move detection by default.

## Change summary

Expose detected code moves to screen reader users through change-navigation announcements, keyboard comparison access, and accessibility help.

## Best solution

Make moved-code relationships discoverable during next/previous-change navigation, with meaningful source and destination ranges and a keyboard-accessible comparison action. Document the supported interaction in diff-editor accessibility help when move detection is enabled.

- **Validation:** With diffEditor.experimental.showMoves enabled, open a side-by-side diff containing a detected moved block and use Go to Next/Previous Change with VoiceOver or NVDA. Verify meaningful move-range announcements, keyboard entry into the corresponding comparison, Escape exit with restored editor focus, and discoverable accessibility help; ordinary changes and disabled move detection must retain existing behavior.
- **Behavior:**

  > Screen reader users must be able to discover that a navigated diff represents moved code and understand its source and destination ranges. The discussion establishes next/previous-change navigation as a required announcement trigger. Users should be able to compare the identified move without using a mouse and discover that interaction through accessibility help when move detection is enabled. Existing ordinary-change navigation and disabled move detection must remain unchanged.
- **Trace:**

  > DiffEditorWidget.goToDiff in src/vs/editor/browser/widget/diffEditor/diffEditorWidget.ts navigates mappings and emits only insertion, deletion, or modification signals. MovedBlocksLinesFeature in src/vs/editor/browser/widget/diffEditor/features/movedBlocksLinesFeature.ts already locates movedTexts from cursor positions, while MovedBlockOverlayWidget displays source/destination captions and changes movedTextToCompare through its Compare action. src/vs/editor/browser/widget/diffEditor/commands.ts exposes Escape through diffEditor.exitCompareMove but no active-move comparison entry command, and the existing diffEditorAccessibilityHelp.ts does not explain moves. This establishes the missing navigation feedback without executing a screen reader. Preserve move detection algorithms, its opt-in default, ordinary diff signals, and existing comparison semantics. https://github.com/microsoft/vscode/issues/191640 concerns a separate Tab-order defect and should not be absorbed into this work. The remaining design uncertainty is the user-visible announcement scope and keyboard entry contract, not how to locate move metadata.
- **Open decisions:**
  - Should move announcements occur only during explicit next/previous-change navigation, or also once when ordinary cursor navigation enters a moved block?
  - Should comparison entry be exposed as an unbound discoverable command, or also receive a default keybinding scoped to an active moved block?
