# Issue #276469 — Add API to detect the source of onDidOpenTextDocument

[https://github.com/microsoft/vscode/issues/276469](https://github.com/microsoft/vscode/issues/276469)

## Summary

Keep open in the Backlog: the extension API still exposes document-open events without their source, and the request earned 30 community upvotes. Existing visibility and tab APIs only partially address the use case and cannot identify Peek or other opening contexts.

## Change summary

Expose metadata indicating whether a text document was opened through Explorer, navigation, Peek, Quick Open, a URI, or an extension.

## Best solution

Design a narrowly scoped API event carrying a stable opening context, with at least enough distinction for background model loads, normal editor visibility, Peek, and extension-initiated opens. The implementation would span the workbench editor-to-extension-host protocol and the public API declaration.

## Evidence

- **current public API:** src/vscode-dts/vscode.d.ts exposes workspace.onDidOpenTextDocument as Event<TextDocument> at line 14277; its documentation explicitly notes that documents may be opened without being shown, but supplies no opening context.
- **extension-host protocol gap:** src/vs/workbench/api/common/extHost.protocol.ts defines IDocumentsAndEditorsDelta with added/removed documents and editors plus the active editor, but no source or reason metadata; mainThreadDocumentsAndEditors.ts forwards that unchanged.
- **partial existing capability:** window.onDidChangeVisibleTextEditors and window.tabGroups in src/vscode-dts/vscode.d.ts expose visibility and main editor tabs, but neither identifies why a model was loaded nor represents Peek as an opening source.
- **prior reports:** https://github.com/microsoft/vscode/issues/38431 and https://github.com/microsoft/vscode/issues/89374 document older variants and visibility-based workarounds, but both are closed and do not own this accepted broader API request.
