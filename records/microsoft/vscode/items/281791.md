# Issue #281791 — GitHub Copilot agents should remember models on a per-agent basis.

[https://github.com/microsoft/vscode/issues/281791](https://github.com/microsoft/vscode/issues/281791)

## Summary

A real gap remains on current main: model selection is remembered by chat location and session-model target, while entering a custom agent with a declared model changes the shared selection without preserving the model previously used by the outgoing agent. The Backlog feature request is correctly routed and should remain open for a persistence and precedence design.

## Change summary

Remember the most recently selected model separately for each built-in or custom agent and restore it when switching back.

## Best solution

Maintain a last-used model selection per agent or chat mode, restoring it when that mode becomes active. A custom agent's declared `model` should provide a well-defined initial preference without destroying another mode's remembered selection.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/common/chatSelectedModel.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/chatInputModelSelectionController.test.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/chatInputModelUtils.test.ts`
- **Validation:** Add a chat-input model-selection test covering Agent on model A -> custom Reviewer declaring model B -> Agent restoring model A -> Reviewer restoring the agreed model, plus a persistence test for the chosen reload scope.
- **Behavior:**

  > Switching from a built-in Agent using one model to a custom agent with another model must not erase the built-in Agent's previous selection. Switching back restores the model last associated with the built-in Agent, and subsequent switches restore each agent's selection according to the agreed declared-model precedence. Model compatibility filtering and session-specific model pools must continue to reject unavailable models. Acceptance includes the reported Agent -> Reviewer -> Agent flow and behavior after reload under the chosen persistence scope.
- **Trace:**

  > In src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts, an autorun observes `_currentModeObservable`; when the incoming mode has `IChatMode.model`, it calls `switchModelByQualifiedName`, while a mode with no declared model leaves the shared `_currentLanguageModel` unchanged. Explicit picks are persisted through `storeSelectedModel`, whose key in src/vs/workbench/contrib/chat/common/chatSelectedModel.ts contains only chat location and optional session-model target, not mode identity. `IChatMode` in src/vs/workbench/contrib/chat/common/chatModes.ts exposes the declared model but no per-mode remembered selection. Existing mode-model tests only exercise qualified-name matching. Keep session-type model-pool isolation, configured-default behavior, and conversation-owned model restoration unchanged; the uncertainty begins at persistence scope and whether a declared model seeds or permanently overrides that mode's remembered selection.
- **Open decisions:**
  - Should each agent's remembered model persist only for the current conversation or workspace, or profile-wide across windows and reloads?
  - After a user manually changes the model while using a custom agent with a declared `model`, should the declaration apply every time the agent is entered or only seed that agent until its own last-used selection exists?
  - Should the per-agent behavior cover all built-in and custom modes uniformly, or only custom agents that declare a model?

## Evidence

- **current mode behavior:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts observes `IChatMode.model` and calls `switchModelByQualifiedName` whenever the mode changes; a mode without a declared model performs no corresponding restoration.
- **persistence scope:** src/vs/workbench/contrib/chat/common/chatSelectedModel.ts builds storage keys as `chat.currentLanguageModel.{location}[.{modelTarget}]`; neither the custom-mode ID nor built-in mode is part of the key, so the existing persisted preference cannot remember separate selections per agent.
- **mode model contract:** src/vs/workbench/contrib/chat/common/chatModes.ts exposes one optional declared model list on `IChatMode`, but no last-used model state keyed by mode.
