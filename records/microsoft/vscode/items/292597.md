# Issue #292597 — Consider removing apply-in-editor

[https://github.com/microsoft/vscode/issues/292597](https://github.com/microsoft/vscode/issues/292597)

## Summary

The legacy action remains on current main, and removing it requires a product decision about whether agentic editing fully replaces this manual code-block workflow. This team-authored request should remain open for that decision.

## Change summary

Consider removing the legacy Apply in Editor action from chat code blocks now that agentic workflows can make edits directly.

## Best solution

Decide whether agentic editing fully supersedes code-block mapping, then remove or scope the action without disrupting Copy, Insert at Cursor, notebook handling, or non-agentic chat participants.

- **Trace:**

  > SmartApplyInEditorAction in src/vs/workbench/contrib/chat/browser/actions/chatCodeblockActions.ts registers `workbench.action.chat.applyInEditor` globally on MenuId.ChatCodeBlock for non-shell code blocks and assigns the same primary keybinding as Insert at Cursor. It delegates to ApplyCodeBlockOperation in src/vs/workbench/contrib/chat/browser/actions/codeBlockOperations.ts, which selects or creates a target, invokes the code mapper, previews text or notebook edits, and reports telemetry. The distinct Apply and Insert workflows originated in https://github.com/microsoft/vscode/commit/9702b852e24a2d079eed22dc90699ec7ef06a133. Preserve Copy, Insert at Cursor, terminal-specific actions, and extension-provided chat code-block behavior; the uncertainty begins at which chat locations still need manual mapped application.
- **Open decisions:**
  - Should Apply in Editor be removed from every chat code block, or only from agentic chat contexts while remaining available for non-agentic participants and responses?
