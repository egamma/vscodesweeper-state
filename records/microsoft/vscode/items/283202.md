[https://github.com/microsoft/vscode/issues/283202](https://github.com/microsoft/vscode/issues/283202)

Keep open: no existing chat spellchecking setting or verified canonical was found. Current source exposes the input model but excludes its editor from extension-facing editor tracking, so extension compatibility needs investigation rather than assuming this is already supported.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/api/browser/mainThreadDocumentsAndEditors.ts`, `src/vs/workbench/contrib/codeEditor/browser/simpleEditorOptions.ts`
- **Validation:** With Code Spell Checker enabled, type a known misspelling in the Copilot prompt and verify an inline spelling diagnostic and usable correction; verify corrected text is submitted unchanged and ordinary editor spellchecking and active-editor behavior remain intact.
- **Behavior:**

  > Users want spelling extensions to identify misspelled words directly in the Copilot prompt before submission. A supported integration should display spelling squiggles and allow corrections without requiring users to compose prompts in a separate file. Existing prompt submission and ordinary editor behavior must remain unchanged.
- **Trace:**

  > ChatInputPart creates a chatSessionInput model with isForSimpleWidget=false, so shouldSynchronizeModel in src/vs/editor/common/model.ts does not exclude it on that basis. The input editor uses getSimpleCodeEditorWidgetOptions(), whose isSimpleWidget=true causes MainThreadDocumentAndEditorStateComputer._updateState to omit it from extension-facing editor tracking. This establishes a document/editor distinction, not a confirmed root cause: investigate the spellchecking extension's selectors and activation assumptions, diagnostic rendering, and correction path before attributing the gap to editor visibility. Preserve the existing behavior of other simple widgets and normal active-editor tracking. The originating extension discussion is https://github.com/streetsidesoftware/vscode-spell-checker/issues/4480.
- **Open decisions:**
  - Should chat prompts support spelling diagnostics and corrections while remaining outside normal visible/active TextEditor tracking, or should extensions receive a broader editor contract for the prompt?
