# Issue #304197 — Implementation leaks when using 'Show and Focus Terminal'

[https://github.com/microsoft/vscode/issues/304197](https://github.com/microsoft/vscode/issues/304197)

## Summary

The implementation-detail leak remains on current main and a maintainer confirmed the underlying limitation. Keep this under discussion because hiding the sandbox wrapper while retaining a revealable, interactive terminal requires an explicit execution-design choice.

## Change summary

Revealing a sandboxed run-in-terminal session exposes the internal sandbox wrapper command instead of presenting only the command requested by the agent.

## Best solution

Preserve access to useful terminal output and interaction while ensuring the revealed terminal presents the user-intended command rather than VS Code's sandbox bootstrap command. The terminal and sandbox owners should first choose whether that requires changing command invocation, terminal presentation, or the reveal behavior.

- **Validation:** Add a targeted run-in-terminal test covering sandboxed execution and the revealable terminal, then manually verify that Show and Focus Terminal exposes the intended command without exposing the sandbox bootstrap while sandbox restrictions and terminal interaction still work.
- **Behavior:**

  > When a sandboxed `run_in_terminal` invocation is shown and focused, the terminal should present the command the agent intended to run rather than VS Code's internal sandbox bootstrap command. The command must remain sandboxed, its output and exit status must remain correct, and users must retain the intended terminal interaction. Unsandboxed commands and the existing chat-card display must remain unchanged.
- **Trace:**

  > CommandLineSandboxRewriter in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/commandLineRewriter/commandLineSandboxRewriter.ts produces a sandbox wrapper as `rewritten` and preserves the requested command as `forDisplay`. RunInTerminalTool in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts stores the wrapper as `toolEdited` and executes it in the real terminal, while SandboxedCommandLinePresenter cleans only the chat-facing presentation. ChatTerminalToolProgressPart.focusTerminal in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts reveals and focuses that actual terminal instance. The maintainer confirmation at https://github.com/microsoft/vscode/issues/304197#issuecomment-4113292329 establishes that this is inherent in the current real-terminal approach; uncertainty starts at whether execution should move behind a shell invocation, the terminal should gain separate display metadata, or reveal semantics should change. Do not weaken sandbox restrictions, alter unsandboxed execution, or hide command output.
- **Open decisions:**
  - Should sandboxed commands continue running directly in a revealable terminal, or move behind a shell invocation such as `bash -c`?
  - If the real terminal remains, can its displayed command safely differ from the executed command without breaking shell integration, command detection, history, or user interaction?
  - Should Show and Focus Terminal remain available when VS Code cannot conceal the sandbox wrapper?
