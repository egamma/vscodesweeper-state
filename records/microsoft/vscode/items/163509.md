# Issue #163509 — Pin in "File: Open Recent..." and in "Command palette..." - as in Tasks from VSCode version 1.72

[https://github.com/microsoft/vscode/issues/163509](https://github.com/microsoft/vscode/issues/163509)

## Summary

Keep this accepted request open: current source still lacks user-controlled pinning in both Open Recent and the Command Palette. Related command-pinning reports were explicitly consolidated here, and the existing history and suggested-command features do not satisfy the request.

## Change summary

Allow users to pin entries in File: Open Recent and the Command Palette alongside their recent items, using the task picker's interaction model.

## Best solution

Provide persistent, user-selected favorites within these two existing pickers rather than requiring separate extension panels. Settle their ordering relative to recent entries and their persistence scope before implementation, preserving existing search, command availability, and opening behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/actions/windowActions.ts`, `src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts`, `src/vs/platform/quickinput/browser/commandsQuickAccess.ts`, `src/vs/platform/quickinput/browser/quickPickPin.ts`, `src/vs/workbench/test/browser/quickAccess.test.ts`
- **Validation:** After agreeing the contracts, manually pin and unpin a command and an Open Recent project/file, reopen both pickers, reload the window, and switch workspaces to verify persistence and ordering. Confirm filtering, context-dependent command availability, keybinding configuration, recent-item removal, and modified-key window opening remain correct; add targeted automated checks for the agreed pinning contracts.
- **Behavior:**

  > Users should be able to pin and unpin entries directly in File: Open Recent and the Command Palette, keeping favorites accessible alongside recent items without a separate extension panel. Changing recency must not erase the user's favorite selection. Acceptance must cover reopening the pickers and the agreed reload and workspace-switch persistence behavior. Searching, executing available commands, and opening recent entries must retain their existing semantics.
- **Trace:**

  > BaseOpenRecentAction in src/vs/workbench/browser/actions/windowActions.ts constructs recent folder/workspace and file picks and currently handles only removal and workspace-state buttons. CommandsQuickAccessProvider in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts supplies keybinding-configuration buttons, while AbstractCommandsQuickAccessProvider in src/vs/platform/quickinput/browser/commandsQuickAccess.ts owns MRU sorting, grouping, execution, and history removal. showWithPinnedItems in src/vs/platform/quickinput/browser/quickPickPin.ts supplies task-picker prior art, but stores pins per workspace and formats an initial item snapshot; suitability for these surfaces remains to be designed. Preserve command context gating, existing search behavior, recent-resource identity, and window-opening modifiers; do not expand this into welcome-page or operating-system jump-list redesign. https://github.com/microsoft/vscode/issues/169091#issuecomment-1351721328 discusses alternative command ordering without settling this request's contract, and https://github.com/microsoft/vscode/issues/258202#issuecomment-3134185966 confirms this issue owns the command-pinning work.
- **Open decisions:**
  - Should Command Palette pins appear before all recent commands, or after the most recently executed command to preserve first-item muscle memory?
  - Should favorites be shared across workspaces and windows, scoped to a profile, or workspace-specific, and should they synchronize between machines?
  - Should pinned Open Recent entries survive removal or eviction from recent history, remaining available until explicitly unpinned?
