## Evidence

- **transport precedence:** src/vs/platform/agentHost/node/claude/claudeTransportMode.ts `resolveClaudeTransportMode`: returns 'proxy' whenever `allowSignedOutWhenUsable` is false (default) OR `hasGitHubToken` is true, before ever considering `hasExistingSetup` (native). A signed-in GitHub user on a bare/model-less Claude session always lands on proxy and needs the GitHub-routed proxy handle.
- **experimental flag default off:** src/vs/platform/agentHost/common/agentHostCustomizationConfig.ts: `AllowSignedOutWhenUsable` schema property defaults to `false` and is explicitly documented as 'Experimental'.
- **per-model override exists:** src/vs/platform/agentHost/node/claude/claudeAgent.ts `_ensureAuthenticated` calls `resolveClaudeSessionTransport({ model, defaultMode })` — a provider-qualified native-Anthropic model bypasses the default and routes native directly regardless of GitHub sign-in state; the report doesn't indicate which model was selected.
- **native env path:** src/vs/platform/agentHost/node/claude/claudeSdkOptions.ts `buildSubprocessEnv(false)` inherits `process.env` (including `CLAUDE_CODE_OAUTH_TOKEN`) for native mode, so once native transport is actually selected, the container's existing CLI credentials should be usable — the failure described is at the transport-selection step, before this code runs.
- **related merged PR:** https://github.com/microsoft/vscode/pull/323037 (fixed https://github.com/microsoft/vscode/issues/314952) introduced native BYOK transport; it originally required an explicit per-session host setting to force native, confirming this is an opt-in path rather than automatic detection of working CLI credentials.
