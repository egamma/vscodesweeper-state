# Issue #320335 — Can't turn on Chat Session Sync (`chat.sessionSync.enabled`)

[https://github.com/microsoft/vscode/issues/320335](https://github.com/microsoft/vscode/issues/320335)

## Summary

Still reproduces on main: the `chat.sessionSync.enabled` setting is gated by a policy that reads `cloud_session_storage_enabled` from the Copilot entitlements endpoint. When that field is `false` (as it is for Copilot Free, BYOK, and some other plans), the VS Code policy mechanism kicks in and the settings editor shows "Managed by organization" — even though no actual org policy is set. The misleading label and the disabled checkbox are both still present in the current source.

## Change summary

The `chat.sessionSync.enabled` setting incorrectly shows "Managed by organization" and is locked for users without any org policy, because the entitlements-based policy gate is indistinguishable from an org-level policy in the settings UI.

## Best solution

Either (a) the entitlements endpoint should not return `cloud_session_storage_enabled: false` for non-enterprise users (server-side fix), or (b) the policy UI should distinguish entitlement-gated settings from organization-managed settings and show different wording (e.g. "Requires Copilot Pro" or similar), or (c) use a different mechanism than the policy system for entitlement gating so the settings editor doesn't display the misleading "Managed by organization" badge. The policy value function in `chat.shared.contribution.ts` line 596 and the settings indicator in `settingsEditorSettingIndicators.ts` line 359 are the key touchpoints.
