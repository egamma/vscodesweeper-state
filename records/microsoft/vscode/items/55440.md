# Issue #55440 — Disable undo menu item when there is no more history available

[https://github.com/microsoft/vscode/issues/55440](https://github.com/microsoft/vscode/issues/55440)

## Summary

The requested menu enablement remains absent on current main: Undo and Redo are registered without preconditions, while the existing editor-local context keys do not provide the global, continuously updated state needed by the menu. This accepted Backlog request should remain open for design across the command's multiple implementations.

## Change summary

Disable Edit > Undo and Edit > Redo whenever the currently targeted surface has no corresponding history.

## Best solution

Make the Edit menu reflect whether the surface that would receive the global Undo or Redo command can perform that operation, updating after history and focus changes. The design should account for text editors and the command's workbench-specific implementations without changing keyboard-command behavior.

## Plan brief

- **Likely files:** `src/vs/editor/browser/editorExtensions.ts`, `src/vs/editor/common/editorContextKeys.ts`, `src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts`, `src/vs/platform/undoRedo/common/undoRedo.ts`, `src/vs/platform/undoRedo/common/undoRedoService.ts`
- **Validation:** Add an Edit-menu integration test that begins with Undo and Redo disabled, enables Undo after an edit, enables Redo after undoing, updates both when switching active editors, and verifies the chosen behavior for supported non-text-editor command targets.
- **Behavior:**

  > Edit > Undo and Edit > Redo should be disabled when invoking the corresponding command on the currently targeted surface would do nothing. Their state should update after edits, undo/redo operations, and focus or active-editor changes. Keyboard shortcuts and explicit command execution must retain their existing dispatch behavior. Acceptance should cover a fresh editor, editing, undoing, redoing, and switching between editors with different history states.
- **Trace:**

  > UndoCommand and RedoCommand are registered without preconditions in src/vs/editor/browser/editorExtensions.ts, so their MenubarEditMenu entries are always enabled. EditorContextKeys.canUndo/canRedo exist in src/vs/editor/common/editorContextKeys.ts and are bound by EditorContextKeysManager in src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts, but the manager recomputes them only for model/configuration changes and they remain scoped to an editor context. The platform undo service exposes canUndo/canRedo in src/vs/platform/undoRedo/common/undoRedo.ts but no stack-change event. Global commands also dispatch to Explorer, notebook, custom-editor, and webview implementations, so the uncertainty starts at defining which target determines menu enablement. Keep standalone editor behavior and command/keybinding dispatch unchanged; this work concerns accurate menu state. Related reports https://github.com/microsoft/vscode/issues/91373 and https://github.com/microsoft/vscode/issues/183153 identify this issue as the canonical tracker.
- **Open decisions:**
  - Should Edit > Undo/Redo reflect only the focused text editor's history, or every surface currently eligible to receive the global command, including notebooks, custom editors, webviews, and Explorer file operations?

## Evidence

- **current registration:** On current main, src/vs/editor/browser/editorExtensions.ts:646-700 registers UndoCommand and RedoCommand with `precondition: undefined`; their MenubarEditMenu entries therefore remain enabled independently of available history.
- **partial context support:** src/vs/editor/common/editorContextKeys.ts defines `canUndo` and `canRedo`, and src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts:2243-2293 binds them locally, but `_updateFromModel` is wired to model/configuration changes rather than every undo-stack mutation and the keys are not used by the menu registrations.
- **multiple command targets:** UndoCommand and RedoCommand have additional implementations for custom editors, webviews, notebooks, notebook multicursor, and Explorer operations, including src/vs/workbench/contrib/customEditor/browser/customEditors.ts, src/vs/workbench/contrib/notebook/browser/contrib/undoRedo/notebookUndoRedo.ts, and src/vs/workbench/contrib/files/browser/files.contribution.ts.
