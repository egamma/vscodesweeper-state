# Issue #236298 — variable -> Rename symbol -> ctrl+enter (Preview); doesn't work, collides with Cell Execution shortcut

[https://github.com/microsoft/vscode/issues/236298](https://github.com/microsoft/vscode/issues/236298)

## Summary

The reported Ctrl+Enter collision between Rename Symbol Preview and notebook cell execution cannot be confirmed in VS Code core on any platform — the keybindings use different modifier keys. Requesting info to clarify.

## Change summary

Ctrl+Enter for Rename Symbol Preview allegedly collides with a notebook cell execution shortcut in .ipynb files.

## Best solution

Determine the reporter's OS and whether the collision reproduces with extensions disabled. Core keybindings don't collide: `acceptRenameInputWithPreview` uses `CtrlCmd+Enter` (Ctrl on Win, Cmd on Mac), while Execute Cell uses `WinCtrl+Enter` (Ctrl on Mac, Win key on Win) with a `win:` override of `Ctrl+Alt+Enter`. If the collision comes from the Jupyter extension's own keybinding, redirect to microsoft/vscode-jupyter.

## Evidence

- **rename preview keybinding:** `acceptRenameInputWithPreview` in src/vs/editor/contrib/rename/browser/rename.ts:438 uses `KeyMod.CtrlCmd | KeyCode.Enter` (Ctrl on Windows, Cmd on Mac) with weight EditorContrib+99 (199).
- **execute cell keybinding:** Execute Cell in src/vs/workbench/contrib/notebook/browser/controller/executeActions.ts:268 uses `KeyMod.WinCtrl | KeyCode.Enter` (Ctrl on Mac, Meta on Linux) with `win: { primary: KeyMod.CtrlCmd | KeyMod.Alt | KeyCode.Enter }` (Ctrl+Alt+Enter on Windows), weight 100.
- **insert cell below keybinding:** Insert Code Cell Below in insertCellActions.ts:115 uses `CtrlCmd+Enter` but its `when` clause negates `InputFocusedContext`, so it cannot fire while the rename widget is open.
- **no platform collision in core:** On Windows: rename preview = Ctrl+Enter, execute cell = Ctrl+Alt+Enter. On Mac: rename preview = Cmd+Enter, execute cell = Ctrl+Enter. Different keys on both platforms.
- **Jupyter extension is external:** The Jupyter extension (microsoft/vscode-jupyter) is not part of this repo. If it registers its own Ctrl+Enter binding for cell execution, that would be `*caused-by-extension`.
