# Issue #214871 — [css] look for variables in all open documents

[https://github.com/microsoft/vscode/issues/214871](https://github.com/microsoft/vscode/issues/214871)

## Summary

A real gap remains: CSS custom-property completions still use only the active document, so language-server results suppress the broader textual suggestions that initially expose variables from other open files. This issue should remain the canonical request for adding open-document awareness.

## Change summary

Offer CSS custom properties declared in other open CSS documents when completing var() expressions.

## Best solution

Extend CSS completion so variables found across open CSS documents remain available alongside current-document language-server proposals, without scanning closed workspace files or following imports.

## Plan brief

- **Likely files:** `extensions/css-language-features/server/src/cssServer.ts`, `extensions/css-language-features/server/src/test/completion.test.ts`
- **Validation:** Add a CSS language-server completion test with two simultaneously open documents: after the active document already contains a local custom property, var() completion must include custom properties from both documents; after closing the declaring document, its proposals must disappear. Run npm run test --prefix extensions/css-language-features/server.
- **Behavior:**

  > When multiple CSS documents are open, completing inside var() offers custom properties declared in any of those open CSS documents, including after the active document has produced its own language-server proposals. All discovered custom-property declarations are eligible regardless of selector, as settled in the maintainer discussion. Closing a document removes properties contributed only by that document. Existing CSS completions and the behavior for closed or unrelated workspace files remain unchanged.
- **Trace:**

  > The completion handler in extensions/css-language-features/server/src/cssServer.ts retrieves the active document from TextDocuments, parses only its stylesheet, and calls LanguageService.doComplete2 with that single-document model. TextDocuments already tracks all synchronized open documents, but the completion path never consults documents.all(). The existing extensions/css-language-features/server/src/test/completion.test.ts exercises the CSS language service directly with one document, so the plan must determine the narrowest server-level test seam for multiple open documents. The issue does not request import traversal or workspace-wide indexing; keep closed files and unrelated documents outside the scope. https://github.com/microsoft/vscode/issues/214831 confirms the same behavior and identifies this issue as its canonical tracker.

## Evidence

- **maintainer diagnosis:** A maintainer explained that textual suggestions inspect all open editors but disappear once the CSS language server returns any result; the language server currently knows only the active document. The maintainer then identified looking through all open CSS editors as the intended direction.
- **current source:** extensions/css-language-features/server/src/cssServer.ts:198-205 retrieves only the requested document and passes that document and its stylesheet to LanguageService.doComplete2; no other entries from the TextDocuments collection participate.
- **existing capability check:** extensions/css-language-features/package.json exposes css.customData for explicitly configured JSON metadata, but there is no setting or command that automatically contributes custom properties from other open CSS documents.
- **canonical search:** https://github.com/microsoft/vscode/issues/162030 is older but concerns completion for @property declarations rather than variables disappearing from var() suggestions across files, so it does not meet the same-observable-symptom bar for this re-reviewed item.
