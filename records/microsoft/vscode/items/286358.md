## Summary

Keep open as an accepted but unscheduled feature request: the reporter and maintainer converged on organization-level skills as the intended way to distribute agents with auxiliary scripts and assets, but that capability is not yet available.

## Change summary

Make organization-managed agent dependencies such as scripts, templates, and reusable assets available locally and predictably alongside the agent.

## Best solution

Support organization- and enterprise-level agent skills once the required API is available, using a skill bundle to distribute auxiliary files rather than adding a separate general-purpose agent-file caching mechanism.

Acceptance requires an organization-managed agent to invoke a bundled helper script and read a bundled template without manually copying either file or fetching it externally at runtime.
- **Trace:**

  > The issue initially asks for arbitrary associated files from `.github-private` to be cached with an agent. The reporter and a VS Code maintainer subsequently converged on organization-level skills as the intended bundling abstraction; the maintainer states that VS Code will investigate support when the required API is available at https://github.com/microsoft/vscode/issues/286358#issuecomment-3952650035. The uncertainty begins at the unavailable upstream organization-skills contract and its synchronization, trust, and local-materialization semantics. Preserve the existing agent hot-reload behavior and avoid creating a parallel arbitrary-file caching contract unless the skills API cannot represent the required assets.
