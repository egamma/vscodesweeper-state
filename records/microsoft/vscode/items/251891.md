- **Behavior:**

  > The reported macOS workflow leaves multiple VS Code windows showing blinking editor carets after switching windows. The AltTab maintainer also observed the symptom during mouse-based switching in the supplied video. An active caret should correspond to the editor receiving keyboard input, without stale active carets in inactive windows. Acceptance compares AltTab, native switching, and mouse activation across two windows and verifies both caret presentation and the destination of typed input.
- **Trace:**

  > ViewCursors.onFocusChanged and _getCursorBlinking in src/vs/editor/browser/viewParts/viewCursors/viewCursors.ts make caret visibility depend on _editorHasFocus. The textarea path forwards TextAreaInput focus/blur through TextAreaEditContext to viewModel.setHasFocus; NativeEditContext forwards FocusTracker changes to the same model. Source inspection establishes this contract but does not identify a missed event or prove the reported failure on current main. Begin by reproducing and comparing native-window, DOM-input, and editor-model focus; preserve normal editor switching, composition, and accessibility behavior.
