# Issue #116445 — find not working correctly for regular expression containing asterisk wildcard

[https://github.com/microsoft/vscode/issues/116445](https://github.com/microsoft/vscode/issues/116445)

## Summary

The navigation defect remains traceable on main, and an open PR explicitly fixes this issue. Keep it open while that human-owned fix is reviewed or superseded.

## Change summary

Regex find-next skips later matches on a line when the expression contains `^` inside a character class and can produce empty matches.

## Best solution

Rebase and review https://github.com/microsoft/vscode/pull/116823, adding coverage for `[^	]*` navigation; separately decide whether the empty-match filtering proposed by https://github.com/microsoft/vscode/pull/116821 is desirable.

## Evidence

- **source trace:** `src/vs/editor/contrib/find/browser/findModel.ts:361-380` treats any `^` in a regex as a line-boundary assertion, including the negation marker in `[^	]*`; when skipping an empty match, `_nextSearchPosition` consequently advances to the next line and bypasses the second field.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/116823 remains open, explicitly fixes https://github.com/microsoft/vscode/issues/116445, and changes line-boundary detection so `^` inside a character class does not trigger whole-line advancement.
- **maintainer confirmation:** A VS Code maintainer confirmed that skipping the remaining matches on the line is unintended, while preserving the regex engine's legitimate empty matches remained a separate design question.
- **related PR:** https://github.com/microsoft/vscode/pull/116821 remains open and proposes filtering empty matches adjacent to non-empty matches, but that behavior is separable from the confirmed navigation bug.
