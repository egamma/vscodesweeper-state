# Issue #116445 — find not working correctly for regular expression containing asterisk wildcard

[https://github.com/microsoft/vscode/issues/116445](https://github.com/microsoft/vscode/issues/116445)

## Summary

The reported navigation defect remains in current source: a negated character class is mistaken for a line-boundary assertion, causing Next to skip later matches on the same line. Keep this open and review the two existing implementation proposals; neither PR has merged.

## Change summary

Regex Find navigation should reach subsequent tab-delimited fields instead of skipping them when an adjacent zero-length match is encountered.

## Best solution

Correct editor Find navigation so character-class negation does not trigger a jump to another line. Review https://github.com/microsoft/vscode/pull/116823 for that correction and resolve the separate empty-match filtering proposal in https://github.com/microsoft/vscode/pull/116821 without conflating regex matching semantics with navigation.

## Evidence

- **Current-source defect:** src/vs/editor/contrib/find/browser/findModel.ts:361–402: _nextSearchPosition treats any occurrence of '^' or '$' in the regex text as a line stop. For the reporter's [^\t]* query, _moveToNextMatch encounters the empty match immediately after f1 and calls this helper, which advances to the next line rather than the next column.
- **Navigation consequence:** src/vs/editor/contrib/find/browser/findDecorations.ts:251–270: matchAfterPosition selects the first decoration starting at or after the supplied position. Once _nextSearchPosition moves to the next line, the second-column match on the original line is excluded. _prevSearchPosition in findModel.ts uses the same overly broad assertion detection.
- **Discussion establishes intended behavior:** The discussion on https://github.com/microsoft/vscode/issues/116445 confirms that Select All Matches finds both columns, while Previous/Next navigation skips matches. Maintainer comments on February 12 and February 16, 2021 explicitly recognize navigation as behavior VS Code controls and skipping the rest of a line as unintended; removing legitimate empty matches was not conclusively approved.
