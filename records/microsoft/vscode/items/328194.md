# Issue #328194 — zoom menus are not properly formated

[https://github.com/microsoft/vscode/issues/328194](https://github.com/microsoft/vscode/issues/328194)

## Summary

The inline shortcut is the intentional fallback for custom keybindings that Electron cannot represent as native menu accelerators; native-compatible shortcuts remain right-aligned.

## Change summary

Right-align custom zoom shortcuts consistently with native shortcuts in the macOS menu.

## Best solution

Keep the existing fallback so unsupported layout-dependent shortcuts remain visible; users who require native alignment must choose an Electron-compatible keybinding.

- **Proposed comment:**

  > Thanks for the additional keyboard-layout details. Native-compatible shortcuts are passed to Electron as menu accelerators and appear right-aligned. When a custom, layout-dependent shortcut cannot be represented safely as an Electron accelerator, VS Code intentionally appends it to the menu label so it remains visible. That is the fallback shown here, so this is working as designed.

## Evidence

- **native menu implementation:** src/vs/platform/menubar/electron-main/menubar.ts:821-842 explicitly assigns native bindings to Electron's accelerator field and appends non-native bindings to the menu label because Electron cannot display them as accelerators.
- **keyboard-layout handling:** src/vs/workbench/services/keybinding/common/macLinuxKeyboardMapper.ts:872-912 returns no Electron accelerator when a layout-dependent scan code cannot be mapped safely.
- **established behavior:** The fallback was introduced in https://github.com/microsoft/vscode/commit/60e8c7c2d0fc8aa696c35ae90f1a85f0f99a896c and is covered by keyboard-mapper expectations for unsupported accelerators.
- **reporter configuration:** The reporter confirmed that the affected entries use custom shortcuts on a European Portuguese keyboard layout, while the normally aligned entries retain standard shortcuts.
