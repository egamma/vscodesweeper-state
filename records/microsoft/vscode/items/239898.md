# Issue #239898 — [Bug] `filesExplorer.paste` is not working when pasting from finder to vscode file explorer

[https://github.com/microsoft/vscode/issues/239898](https://github.com/microsoft/vscode/issues/239898)

## Summary

The bug remains on current main: the default Cmd+V binding permits a native paste event carrying Finder files, while another binding invokes `filesExplorer.paste` without that file list and therefore finds nothing to paste.

## Change summary

Make `filesExplorer.paste` paste files copied from macOS Finder when invoked through a custom keybinding.

## Best solution

Give custom bindings for `filesExplorer.paste` the same native-file clipboard behavior as Cmd+V, without changing Explorer-internal copy and cut operations or causing the default binding to paste twice.

## Evidence

- **current source:** src/vs/workbench/contrib/files/browser/fileActions.contribution.ts registers the default binding as `^filesExplorer.paste`; the caret lets the native Cmd+V event continue, but a user binding directly to `filesExplorer.paste` invokes only the command.
- **failing path:** src/vs/workbench/contrib/files/browser/views/explorerView.ts passes `event.clipboardData.files` to `filesExplorer.paste` only from the native DOM paste event. In src/vs/workbench/contrib/files/browser/fileActions.ts, `getFilesToPaste` falls back to `IClipboardService.readResources()` when that argument is absent.
- **clipboard boundary:** src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts reads resources only from VS Code's private `code/file-list` clipboard format, so Finder-copied files are unavailable to the direct command path.
- **original implementation context:** A comment on https://github.com/microsoft/vscode/issues/130036#issuecomment-1203482137 identified custom `filesExplorer.paste` bindings as a case requiring special handling, but merged PR https://github.com/microsoft/vscode/pull/195730 implemented native files through the DOM paste event used by Ctrl/Cmd+V.
- **related issue:** https://github.com/microsoft/vscode/issues/164 broadly tracks cross-application clipboard integration, but its native-to-Explorer paste item is already marked complete and does not specifically own custom-keybinding parity.
