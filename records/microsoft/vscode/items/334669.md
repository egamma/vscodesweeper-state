# Issue #334669 — agentHost: Require explicit SDK download on metered connections

[https://github.com/microsoft/vscode/issues/334669](https://github.com/microsoft/vscode/issues/334669)

## Summary

Keep open: current SDK loading still downloads on a cache miss without checking metered-connection state. The existing network setting and explicit Download action provide useful infrastructure, but neither delivers the requested protection.

## Change summary

Require an explicit Download action before fetching a missing or outdated Claude or Codex SDK on a metered connection.

## Best solution

Make automatic SDK acquisition respect metered-connection state while preserving cached SDK use and explicit downloads for both providers. Explain the blocked download in setup UI, with an actionable Download button rather than treating prior consent or sending a message as fresh download approval.

- **Behavior:**

  > On a metered connection, using Claude or Codex must not automatically fetch a missing or outdated SDK, even when prior download-on-use consent exists. The user must receive an explanation and an explicit Download action for the affected SDK. Selecting that action permits acquisition while metered. Cached current-version SDKs remain usable without a download, and unmetered download-on-use behavior remains unchanged.
- **Trace:**

  > AgentSdkDownloader.loadSdkRoot routes cache misses through _resolveOrDownload directly to _download, with no metered-state input. ClaudeAgentSdkService and CodexAgent._resolveSdkRoot both reach this shared path. AgentSdkSetupChannel publishes downloadOnUse based on remembered consent, and the workbench notification suppresses the download offer for that status; explicit requests already flow through AgentSdkSetupService.requestDownload and AgentSdkSetupChannel._handleRequest. network.meteredConnection and IMeteredConnectionService exist, but the trace found no integration with SDK acquisition. The unresolved boundary is which connection state governs an SDK fetched by a remote or standalone host and how that state becomes available before acquisition. Preserve cache resolution, provider-specific explicit requests, existing consent persistence, and download deduplication; broader completion and telemetry metering are outside this issue. https://github.com/microsoft/vscode/pull/334316 establishes the existing consent/setup behavior, while https://github.com/microsoft/vscode/issues/336679 tracks separate telemetry work.
- **Open decisions:**
  - For a remote Agent Host, should automatic SDK acquisition follow the client's metered state, the downloading host's state, or block when either is metered?
  - If a host cannot determine metered state, should automatic download-on-use remain available or require an explicit Download action?
