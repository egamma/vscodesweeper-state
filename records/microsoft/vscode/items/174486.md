# Issue #174486 — VS Code reports incorrect size of the terminal until the terminal is manually resized

[https://github.com/microsoft/vscode/issues/174486](https://github.com/microsoft/vscode/issues/174486)

## Summary

Still a valid bug: when a terminal is restored on VS Code startup, the initial dimensions passed to the shell process may be incorrect (defaulting to 80×30 or stale values) until the terminal container is laid out and a manual resize triggers the correct dimensions. The `help wanted` label and Backlog milestone indicate this is accepted work. No fixing commit references this issue.

## Change summary

The integrated terminal reports incorrect COLUMNS/LINES to the shell on startup until the terminal is manually resized.

## Best solution

The fix likely lives in the terminal creation/restore flow in `terminalInstance.ts` — specifically ensuring that `_initDimensions()` is called with accurate container dimensions before `createProcess()` passes cols/rows to the shell. The race between container layout and process creation (the `WaitForContainerThreshold` of 100ms) may need to be reworked so that the shell process is not started until real dimensions are available, or an explicit resize is sent once layout completes. The `help wanted` label is appropriate — this is a good candidate for a community contribution.
