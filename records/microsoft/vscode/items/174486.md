# Issue #174486 — VS Code reports incorrect size of the terminal until the terminal is manually resized

[https://github.com/microsoft/vscode/issues/174486](https://github.com/microsoft/vscode/issues/174486)

## Summary

Restored shells can still read the previous session's terminal dimensions during startup, even though a later resize corrects them automatically. Keep this open while the linked fix PR is reviewed; it has not merged.

## Change summary

Ensure restored terminal shells receive current dimensions before startup code reads COLUMNS or stty size.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339514 after resolving its Windows replay concerns. Preserve running-process reattachment behavior and explicitly track the remaining remote-terminal limitation.

- **Current source:** src/vs/platform/terminal/node/ptyService.ts recreates restored processes using terminal.replayEvent.events[0].cols and .rows. In src/vs/workbench/contrib/terminal/browser/terminalProcessManager.ts, createProcess attaches to the revived local process and calls newProcess.start() without first supplying current dimensions. TerminalProcess.resize in src/vs/platform/terminal/node/terminalProcess.ts performs resizing only when _ptyProcess exists, so a pre-spawn resize does not update spawn dimensions.
