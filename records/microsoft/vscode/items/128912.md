# Issue #128912 — [folding] Allow to fold all method bodies

[https://github.com/microsoft/vscode/issues/128912](https://github.com/microsoft/vscode/issues/128912)

## Summary

This remains a well-supported feature gap: current folding APIs distinguish comments, imports, and regions, but not function or method bodies. The older automatic-folding request is related but does not meet the stronger duplicate bar because it asks for cursor-driven folding rather than the same explicit semantic command.

## Change summary

Add a semantic folding-range kind and command that can fold all function and method bodies regardless of nesting level.

## Best solution

Define a stable body folding kind across the editor and extension APIs, expose a “Fold All Bodies” command, and let language providers identify qualifying ranges. A maintainer should first settle the public kind’s scope and whether automatic folding belongs in this issue.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/languages.ts`, `src/vs/workbench/api/common/extHostTypes.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Add API-conversion coverage for the chosen body kind and an editor folding test proving the new command collapses body-tagged ranges at different nesting levels while leaving comments, regions, imports, classes, and ordinary blocks unchanged.
- **Behavior:**

  > Language folding providers can classify function and method body ranges with a standardized semantic kind. Running “Fold All Bodies” collapses every range of that kind regardless of nesting depth, without collapsing unrelated blocks, comments, imports, regions, or enclosing declarations. Existing folding commands and untyped folding ranges retain their current behavior. If default folding is accepted into scope, opening a document with that setting enabled applies the same semantic selection rather than folding by indentation level.
- **Trace:**

  > The public enum in src/vscode-dts/vscode.d.ts and its runtime counterpart in src/vs/workbench/api/common/extHostTypes.ts currently contain only Comment, Imports, and Region. src/vs/workbench/api/common/extHostTypeConverters.ts explicitly converts only those values, while the internal src/vs/editor/common/languages.ts FoldingRangeKind can represent arbitrary strings but standardizes only the same three. Type-specific folding actions in src/vs/editor/contrib/folding/browser/folding.ts already use setCollapseStateForType for comments and regions, establishing the command-side pattern. The boundary is semantic range classification and folding selection; indentation-based Fold Level behavior must not change. https://github.com/microsoft/vscode/issues/33449 concerns automatic cursor-driven folding and should remain related rather than absorbing this explicit command request.
- **Open decisions:**
  - Should the public contract define one broad `body` kind for function and method bodies only, or standardized kinds for additional declaration categories such as classes, types, and modules?
  - Is the initial scope limited to an explicit “Fold All Bodies” command, or must it also include the requested setting that folds body ranges when a document opens?
  - Should VS Code introduce the kind in its extension API independently, or wait for and align with a corresponding standardized Language Server Protocol folding kind?

## Evidence

- **missing API capability:** On current main, src/vscode-dts/vscode.d.ts and src/vs/workbench/api/common/extHostTypes.ts expose only Comment, Imports, and Region in FoldingRangeKind; src/vs/workbench/api/common/extHostTypeConverters.ts maps only those three kinds.
- **missing command:** src/vs/editor/contrib/folding/browser/folding.ts registers type-specific actions for block comments and marker regions, but no action for function or method bodies.
- **maintainer confirmation:** A maintainer confirmed that the folding infrastructure lacks a way for providers to communicate method bodies and agreed that another FoldingRangeKind value is the expected API direction: https://github.com/microsoft/vscode/issues/128912#issuecomment-921729473 and https://github.com/microsoft/vscode/issues/128912#issuecomment-923605415.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/33449 is older and open, but its central behavior is automatic cursor-driven expansion and refolding. This issue's observable request is an explicit semantic “Fold All Bodies” operation, so the re-review duplicate bar is not met.
