# Issue #127932 — Custom keyboard layouts does not works properly on ozone wayland only mode

[https://github.com/microsoft/vscode/issues/127932](https://github.com/microsoft/vscode/issues/127932)

## Summary

Keep open: native Wayland keyboard-layout discovery still depends on an X11-only native-keymap backend. The discussion establishes a real shortcut-mapping problem, and neither the documented workarounds nor the related closed reports establish a fix.

## Change summary

Resolve keyboard shortcuts using the active Linux keyboard layout under native Wayland, including Programmer Dvorak and other non-US layouts.

## Best solution

Provide Wayland-aware layout discovery in native-keymap or an equivalent supported input path, and have VS Code consume the compositor's actual mapping rather than missing or unrelated X11 layout data. Preserve this issue as the VS Code integration report alongside the upstream dependency issue.

## Evidence

- **Reported trigger and confirmed workaround:** https://github.com/microsoft/vscode/issues/127932#issuecomment-873459260 shows the same physical Ctrl+Shift+Equal event opening the terminal under Xorg but invoking zoom under native Wayland. The maintainer acknowledged the missing layout path at https://github.com/microsoft/vscode/issues/127932#issuecomment-873978131; the reporter confirmed that supplying the correct hard-coded mapping fixed their build at https://github.com/microsoft/vscode/issues/127932#issuecomment-874055012.
- **Current VS Code dependency path:** src/vs/platform/keyboardLayout/electron-main/keyboardLayoutMainService.ts still obtains both mapping and layout exclusively through native-keymap.getKeyMap() and getCurrentKeyboardLayout(). src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayoutService.ts forwards that data without a Wayland-specific replacement.
- **Upstream ownership verified:** https://github.com/microsoft/node-native-keymap/issues/17 remains open for Wayland support. Its current binding.gyp selects src/keyboard_x.cc on Linux; GetKeyMapImpl and GetCurrentKeyboardLayoutImpl call XOpenDisplay and return an empty mapping or null layout when no X display is available. See https://github.com/microsoft/node-native-keymap/blob/master/src/keyboard_x.cc and https://github.com/microsoft/node-native-keymap/blob/master/binding.gyp.
- **Existing dispatch options do not supply the missing layout:** src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts uses FallbackKeyboardMapper when keyboard.dispatch is keyCode or the native mapping is empty. Changing dispatch therefore does not provide Wayland layout discovery. Reports at https://github.com/microsoft/vscode/issues/127932#issuecomment-2416528768 and https://github.com/microsoft/vscode/issues/127932#issuecomment-3499696113 describe Neo2 and ABNT2 failures; manual shortcut overrides remain partial workarounds.
