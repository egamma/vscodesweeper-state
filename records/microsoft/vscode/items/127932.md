# Issue #127932 — Custom keyboard layouts does not works properly on ozone wayland only mode

[https://github.com/microsoft/vscode/issues/127932](https://github.com/microsoft/vscode/issues/127932)

## Summary

The issue remains necessary: several reports through November 2025 confirm that native Wayland sessions expose the wrong keyboard layout to VS Code, while X11/Xwayland works. The root capability is owned by Electron/Chromium and node-native-keymap's Linux backend, so this should remain open as an upstream-tracking issue.

## Change summary

Native Wayland sessions use an incorrect US-oriented key map for shortcuts when the active Linux layout is Programmer Dvorak, Neo2, German dead keys, ABNT2, or another remapped layout.

## Best solution

Track and adopt an upstream Wayland-capable keyboard-layout source in Electron/Chromium or node-native-keymap, then verify that VS Code's native keyboard-layout service receives the compositor's active layout and maps shortcuts identically to X11/Xwayland without requiring per-user keybinding overrides.
