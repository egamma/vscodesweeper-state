# Issue #326166 — Plugins hooks on devcontainers can't call upon plugin location

[https://github.com/microsoft/vscode/issues/326166](https://github.com/microsoft/vscode/issues/326166)

## Summary

Confirmed root cause in current main: agent plugin hooks are executed with the plugin's local (host-side) file path even when the actual shell process runs in a devcontainer/WSL remote, so the plugin's own files (skills, scripts) are unreachable — a real, unresolved architecture gap, not something already fixed.

## Change summary

Hooks defined by an agent plugin can't find files that live inside the plugin's own directory when the workspace is a devcontainer, because the plugin root path injected into the hook command/env doesn't exist in the container's filesystem.

## Best solution

In `executeHookCommand`/`interpolateHookPluginRoot` (src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts and src/vs/platform/agentPlugins/common/pluginParsers.ts), the plugin root used for `${PLUGIN_ROOT}`/`CLAUDE_PLUGIN_ROOT` interpolation needs to resolve to a path valid in the same environment where the hook shell actually spawns (remote/container), not the host-side `agentPluginsHome`; this likely requires either mirroring/mounting plugin files into the remote context or resolving the plugin root through the remote file system rather than a bare local `fsPath` — a design decision beyond a one-line fix.

  > Thanks for the report, and to kilianpaquier and rjra100 for confirming. Tracing the code, this is a real gap: the hook runner (`executeHookCommand` in copilotPluginConverters.ts) spawns the hook shell with the plugin's local/host path injected as `${CLAUDE_PLUGIN_ROOT}`/`cwd`, but agent plugins are stored in a host-side profile directory (`agentPluginsHome`) that isn't automatically available inside a devcontainer or WSL remote. So any hook that needs its own plugin files (not just running an external command) will fail. This needs a design decision on how plugin files get made available to hooks running remotely (mount/sync vs. resolving via the remote filesystem) rather than a one-line fix — routing to the chat/agent-plugins area.
