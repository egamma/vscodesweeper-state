# Issue #326166 — Plugins hooks on devcontainers can't call upon plugin location

[https://github.com/microsoft/vscode/issues/326166](https://github.com/microsoft/vscode/issues/326166)

## Summary

Traced this in source: hook commands interpolate the plugin's *client/host-side* install path (`agentPluginsHome`/`pluginUri.fsPath`) into `CLAUDE_PLUGIN_ROOT` and the shell command, with no translation for remote/devcontainer execution contexts, so the injected path doesn't exist inside the container's filesystem — the same root cause as the closed WSL duplicate #313201, just for devcontainers.

## Change summary

Agent-plugin hooks that reference `${CLAUDE_PLUGIN_ROOT}`/`${PLUGIN_ROOT}` fail inside a devcontainer because the interpolated plugin path points at the local host install location, not a path reachable from the container's shell.

## Best solution

In src/vs/platform/agentPlugins/common/pluginParsers.ts (`interpolateHookPluginRoot`/`shellQuotePluginRootInCommand`) and the plugin install-location resolution in src/vs/workbench/contrib/chat/browser/agentPluginRepositoryService.ts, either install/mirror the plugin into a path reachable inside the remote/devcontainer execution context before hooks run, or resolve `pluginUri` against the remote authority so `CLAUDE_PLUGIN_ROOT` reflects a container-local path — the same fix class needed for the closed WSL duplicate https://github.com/microsoft/vscode/issues/313201, which was never given a canonical replacement.
