# Issue #214906 — Issue reporter doesn't create issues - Safari - Codespaces Web

[https://github.com/microsoft/vscode/issues/214906](https://github.com/microsoft/vscode/issues/214906)

## Summary

Still appears reproducible on main: the issue reporter's `submitIssue` flow performs async work (file uploads, clipboard writes) before calling `openerService.open`, which breaks the user-activation chain Safari requires for `window.open` — no Safari-specific handling or workaround has been added.

## Change summary

The "Create Issue" button in the Issue Reporter does nothing in Safari on Codespaces Web because Safari's popup blocker prevents the `window.open` call that follows async operations.

## Best solution

Pre-open the target window synchronously on the user click (e.g. `window.open('about:blank')`) before the async upload/clipboard work, then navigate it to the final GitHub URL once the body is ready. The fix would touch `src/vs/workbench/contrib/issue/browser/issueFormService.ts` (`submitIssue` method). Alternatively, detect when `window.open` returns `null` and fall back to a visible link the user can click.
