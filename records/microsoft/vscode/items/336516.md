# Issue #336516 — C# errors are shown in the Explorer but the editor does not highlight the error line.

[https://github.com/microsoft/vscode/issues/336516](https://github.com/microsoft/vscode/issues/336516)

## Summary

The reporter clarified that the request is for quick navigation to errors without opening Problems. Built-in Next/Previous Problem commands already provide this, including navigation across files and entries in the Go menu.

## Change summary

Provide a quick way to jump directly to a C# diagnostic without manually searching tabs or opening the Problems panel.

## Best solution

Use the existing Go > Next Problem command (F8), which opens the affected file and navigates to its diagnostic. No additional navigation feature is necessary for the clarified request.

- **Existing commands and UI:** src/vs/editor/contrib/gotoError/browser/gotoError.ts registers editor.action.marker.nextInFiles on F8 and editor.action.marker.prevInFiles on Shift+F8, with Next Problem and Previous Problem entries in MenuId.MenubarGoMenu. It also registers editor.action.marker.next on Alt+F8 for navigation within the current file.
- **Navigation behavior:** MarkerController.navigate in src/vs/editor/contrib/gotoError/browser/gotoError.ts selects the diagnostic and opens another affected file with its marker range as the selection when necessary; otherwise it displays the diagnostic through MarkerNavigationWidget.showAtMarker. This does not require opening the Problems panel.
- **Diagnostic coverage and limits:** src/vs/editor/contrib/gotoError/browser/markerNavigationService.ts reads Error, Warning and Info markers from IMarkerService and cycles through them across resources. The existing commands therefore cover quick access to reported diagnostics; source inspection does not establish why the original report mentioned an absent underline.
