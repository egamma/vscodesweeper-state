- **Likely files:** `src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`
- **Validation:** Remove the skip and repeatedly run `npm run test-browser-no-install -- --browser chromium --grep "fireItemHeightChange defers a mid-render measurement and delivers it after the render pass"`; every run must pass while preserving the existing assertions.
- **Behavior:**

  > The browser regression test for a height measurement received during a ChatListRenderer render pass must run deterministically rather than remain skipped. It must verify that the mid-render measurement neither updates stored height nor notifies the tree, and that the deferred next-frame re-measure emits and stores the row's actual height. Repeated Chromium runs must pass without relaxing those behavioral guarantees.
- **Trace:**

  > The test in src/vs/workbench/contrib/chat/test/browser/widget/chatListRenderer.test.ts renders a real chat row, waits two animation frames, records its DOM height, simulates a stale stored height, and invokes the private `fireItemHeightChange` path. CI observed different final heights, including 86 and 114, while production code in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts schedules a fresh measurement on the next animation frame when `reconcileChatItemHeight` returns `deferReMeasure`. PR https://github.com/microsoft/vscode/pull/327406 skipped the test, and https://github.com/microsoft/vscode/pull/338064 retained and documented that skip. The uncertainty starts at which outstanding renderer, ResizeObserver, font/layout, or animation-frame activity changes the row between the baseline measurement and deferred assertion. Preserve the production contract established for https://github.com/microsoft/vscode/issues/326952; do not make the test accept stale or arbitrarily varying heights merely to suppress the flake.
