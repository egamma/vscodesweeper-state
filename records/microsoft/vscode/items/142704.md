# Issue #142704 — Can Quickpick Separator be displayed when scrolling down? - aka sticky separators

[https://github.com/microsoft/vscode/issues/142704](https://github.com/microsoft/vscode/issues/142704)

## Summary

Keep open: sticky scrolling exists for internal section headers, but ordinary extension-provided Quick Pick separators still scroll away. This team-authored, accepted request has maintainer support, and no verified canonical issue or issue-referencing fix was found.

## Change summary

Keep the current Quick Pick group's separator label visible while scrolling through its items.

## Best solution

Provide persistent group context for ordinary API-created Quick Picks in the quick-input list, without requiring separator buttons. Agree on a compact header presentation that preserves list density and existing selection behavior.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Use an extension-created Quick Pick with two labeled, buttonless separator groups exceeding the viewport. Scroll within each group and across their boundary: the visible context must identify the current group and switch correctly. Verify filtering, keyboard selection, and existing button-bearing headers remain correct; add browser regression coverage in src/vs/platform/quickinput/test/browser/quickinput.test.ts.
- **Behavior:**

  > An extension-created Quick Pick containing ordinary labeled separators should retain the current group's label when its original separator scrolls above the viewport. The displayed context should change when scrolling into the next group. Separators must not become selectable results, and filtering and keyboard selection must retain their existing behavior. Acceptance should cover long buttonless groups, group boundaries, and existing headers with actions.
- **Trace:**

  > In src/vs/workbench/api/common/extHostQuickOpen.ts, the items setter transfers API separators as type and label without buttons. QuickInputList.setElements in src/vs/platform/quickinput/browser/quickInputList.ts renders those separators as part of the following item, whereas separators with a buttons property become QuickPickSeparatorElement parents. _setElementsToTree supplies those parents and their children to WorkbenchObjectTree, which inherits the existing workbench.tree.enableStickyScroll setting. Thus internal header stickiness is available, but ordinary API separators cannot participate in it. Preserve existing selection, filtering, accessibility, and separator-action semantics; do not extend this into permanently pinned selectable actions requested by https://github.com/microsoft/vscode/issues/131128. The remaining design uncertainty is how sticky context for compact, buttonless separators should appear without unnecessarily reducing list density.
- **Open decisions:**
  - Should buttonless separators retain their compact inline appearance until scrolling makes their context sticky, or use dedicated section-header rows throughout the list?
