# Issue #315841 — Deadlock in extension host activation blocks tunnels auth

[https://github.com/microsoft/vscode/issues/315841](https://github.com/microsoft/vscode/issues/315841)

## Summary

The merged fix (PR #316386) applied a Promise.race workaround at the auth layer, but a team member confirmed the deadlock still reproduces on Insiders 1.121.0 (which includes that fix). The underlying `_getExtensionRegistrySnapshotWhenReady` deadlock path in `abstractExtensionService.ts` remains, and the issue carries the `important` label — must stay open.

## Change summary

Connecting to a remote tunnel deadlocks because the webworker extension host waits on `_installedExtensionsReady` (which requires a remote connection) during its handshake, while the remote connection needs auth from that same activation path.

## Best solution

The root deadlock in `_getExtensionRegistrySnapshotWhenReady` (line 1074 of `abstractExtensionService.ts`) still blocks the webworker extension host handshake. The webworker host should be aligned with the local process host approach — using the scanner to find its extensions directly rather than waiting on `_installedExtensionsReady` — or `_performHandshake` should avoid calling `_getExtensionRegistrySnapshotWhenReady` before the remote is connected.
