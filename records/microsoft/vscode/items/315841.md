# Issue #315841 — Deadlock in extension host activation blocks tunnels auth

[https://github.com/microsoft/vscode/issues/315841](https://github.com/microsoft/vscode/issues/315841)

## Summary

Team-authored issue with the `important` label — hard keep-open. A fix landed in PR #316386 (commit 184d76ec601, shipped 1.121.0), but a team member confirmed the deadlock still reproduces on Insiders 1.121.0-insider after the fix, and the related issue #321626 remains open, indicating the fix is incomplete.

## Change summary

Connecting to a remote tunnel deadlocks because the webworker extension host waits on `_installedExtensionsReady` (which requires a remote connection) while auth activation is blocked waiting for all extension hosts.

## Best solution

Investigate why the `Promise.race` fix in commit 184d76ec601 did not fully resolve the deadlock — pierceboggan confirmed reproduction on a build that includes the fix. The remaining deadlock path likely still involves the webworker extension host's `_getExtensionRegistrySnapshotWhenReady` blocking on `_installedExtensionsReady`. Consider aligning the webworker extension host's extension discovery with the local process extension host's scanner-based approach, as connor4312 suggested.
