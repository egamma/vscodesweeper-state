- **Likely files:** `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatService.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/runInTerminalHelpers.ts`, `src/vs/platform/agentHost/node/sessionPermissions.ts`, `src/vs/platform/agentHost/node/commandAutoApprover.ts`
- **Validation:** In Agent Host Copilot under default approvals, approve one otherwise-unmatched command for the session and repeat it: only the matching command should stop prompting. Verify unrelated commands and a separate session still prompt, persistent exact-command actions still work, and managed or sandbox-bypass confirmations retain their restrictions.
- **Behavior:**

  > Users should be able to approve a specific terminal command or command combination for the applicable session without approving unrelated shell commands. Repeating the matching command should not prompt again, while a separate session should not inherit the grant. Existing user/workspace exact-command approvals must remain available. Any allow-all option must accurately describe and enforce its agreed scope without silently overriding managed or sandbox restrictions.
- **Trace:**

  > TerminalChatService.getAutoApproveActions in src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatService.ts deliberately excludes workbench session rules and passes skipSessionScoped to generateAutoApproveActions. SessionPermissionManager._evaluateShellAutoApproval consumes root terminal rules, while handleToolCallConfirmed stores allow-session as a tool-name permission rather than a command-specific grant. These source paths confirm the remaining capability gap without runtime execution. https://github.com/microsoft/vscode/pull/327947 restored only persistent actions; https://github.com/microsoft/vscode/issues/326766 tracks broader convergence. Preserve existing persistent-rule behavior, dialect handling, deny rules, and managed/sandbox confirmation boundaries. The unsettled contract is which chats and restored lifetimes share a session grant, and whether allow-all is terminal-only or a broader permission-mode transition.
- **Open decisions:**
  - Does a command-specific session grant apply only to the current chat or to every chat in its Agent Host session, and does it survive session restoration?
  - Should an Allow All Commands in This Session action grant terminal-only approval or change the broader session permission mode, or remain outside this issue?
