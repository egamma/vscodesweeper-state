# Issue #188397 — VS Code not responding on launching

[https://github.com/microsoft/vscode/issues/188397](https://github.com/microsoft/vscode/issues/188397)

## Summary

Keep this open as the canonical upstream keyring-startup issue. Recent confirmations show that Chromium's synchronous Linux password-store initialization can still freeze VS Code when GNOME Keyring is unavailable or locked.

## Change summary

VS Code becomes unresponsive during startup while Chromium waits for a Linux keyring backend.

## Best solution

Track the Chromium/Electron password-store initialization behavior here until it no longer blocks VS Code's main process, while retaining `--password-store=basic` as the documented workaround.

## Evidence

- **current confirmations:** https://github.com/microsoft/vscode/issues/188397#issuecomment-2550592659 reports the freeze on VS Code 1.95.2 when GNOME Keyring is locked after fingerprint login; https://github.com/microsoft/vscode/issues/188397#issuecomment-2911179939 confirms it on Ubuntu 24.04.
- **canonical status:** https://github.com/microsoft/vscode/issues/195070 was closed into this issue after maintainers confirmed the same `--password-store=basic` workaround, making this the established canonical report.
