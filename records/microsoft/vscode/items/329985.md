# Issue #329985 — timeout connecting to re-used dev tunnel

[https://github.com/microsoft/vscode/issues/329985](https://github.com/microsoft/vscode/issues/329985)

## Summary

Fresh, well-diagnosed bug in the agent host's dev tunnel reuse/adoption path; a maintainer (connor4312) is already engaged and asked for trace logs, so this should stay open pending that follow-up rather than being closed or flagged as stale.

## Change summary

Reconnecting an agent host tunnel after the previous host dies sometimes adopts a stale tunnel record whose live host never actually forwards the agent host port, causing a 30s connect timeout.

## Best solution

Once trace logs are provided, investigate whether `stopHosting()`'s decision to leave adopted tunnels in place (in src/vs/platform/agentHost/node/tunnelHostMainService.ts) combined with the `hostConnectionCount === 0` adoption check in `startHosting()` can race against a still-connected ordinary tunnel host, and add a check that verifies the adopted tunnel's live host actually reports the agent host port before reusing it instead of creating a new tunnel.
