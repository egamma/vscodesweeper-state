# Issue #80820 — "editor font zoom" does not persist

[https://github.com/microsoft/vscode/issues/80820](https://github.com/microsoft/vscode/issues/80820)

## Summary

The persistence gap remains on current main: editor font zoom is held only in process memory and resets to zero on restart. This issue is the established canonical request and is parked in the On Deck milestone, so it should remain open for a persistence-scope decision.

## Change summary

Persist the editor-specific font zoom level across VS Code restarts instead of resetting it when the process exits.

## Best solution

Provide a persistent, profile-aware editor font zoom value that restores the user's effective editor zoom after restart while preserving `editor.fontSize` as the underlying base size. Maintainers should first decide whether this is an explicit setting or persisted UI state and whether its scope is application-wide, per profile, or per workspace.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorZoom.ts`, `src/vs/editor/contrib/fontZoom/browser/fontZoom.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/test/browser/config/editorConfiguration.test.ts`
- **Validation:** Add automated coverage that changes editor font zoom, recreates the persistence owner to simulate a restart, and verifies the same effective zoom is restored; also verify reset persists zero and existing zoom-bound tests continue to pass.
- **Behavior:**

  > After a user increases or decreases editor font size with the editor font zoom commands or mouse-wheel zoom, the selected editor zoom remains effective after restarting VS Code. Reset Editor Font Size restores the configured base size and that reset also survives restart. The behavior must remain separate from workbench window zoom and must continue respecting the current editor zoom bounds.
- **Trace:**

  > Current main stores the value only in the module-level `EditorZoom` singleton in src/vs/editor/common/config/editorZoom.ts, whose `_zoomLevel` starts at 0 for every process. Commands in src/vs/editor/contrib/fontZoom/browser/fontZoom.ts and mouse handling in src/vs/editor/browser/controller/mouseHandler.ts update that singleton directly. The existing test in src/vs/editor/test/browser/config/editorConfiguration.test.ts verifies bounds but not persistence. The editor common layer does not own workbench storage, so uncertainty begins at the persistence boundary: configuration-backed state versus a workbench contribution that restores and saves the singleton. Do not conflate this value with `window.zoomLevel` or change the meaning of `editor.fontSize`. https://github.com/microsoft/vscode/issues/166236 was explicitly consolidated into this issue.
- **Open decisions:**
  - Should editor font zoom be exposed as a user-facing configuration value or persisted as UI state?
  - Should the persisted value be application-wide, profile-scoped, or workspace-scoped?
  - Should command and mouse-wheel zoom share exactly the same persisted value, including fractional levels?

## Evidence

- **current source:** src/vs/editor/common/config/editorZoom.ts initializes `EditorZoom._zoomLevel` to 0 and only retains updates in the singleton's in-memory field; it has no configuration or storage integration.
- **command path:** src/vs/editor/contrib/fontZoom/browser/fontZoom.ts implements `editor.action.fontZoomIn`, `editor.action.fontZoomOut`, and `editor.action.fontZoomReset` solely through `EditorZoom.getZoomLevel()` and `setZoomLevel()`.
- **existing coverage:** src/vs/editor/test/browser/config/editorConfiguration.test.ts tests zoom bounds and values within one process but contains no restart or persistence coverage.
- **canonical ownership:** https://github.com/microsoft/vscode/issues/166236 was closed as a duplicate with the maintainer direction "Let's track in #80820", confirming this issue owns the persistent/configurable editor zoom request.
- **existing workaround:** https://github.com/microsoft/vscode/issues/75397 documents `editor.fontSize` as a persistent absolute-size workaround, but that does not preserve the independently adjusted editor zoom multiplier requested here.
