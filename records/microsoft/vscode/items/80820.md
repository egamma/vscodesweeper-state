# Issue #80820 — "editor font zoom" does not persist

[https://github.com/microsoft/vscode/issues/80820](https://github.com/microsoft/vscode/issues/80820)

## Summary

Editor font zoom still resets on restart: the commands update an in-memory multiplier, not persisted configuration. Keep this accepted accessibility request open; a maintainer explicitly consolidated a related request here, and no older open canonical was verified.

## Change summary

Preserve editor font zoom changes across closing and restarting VS Code.

## Best solution

Provide persistent editor-only zoom without requiring users to manually edit their base font settings. Agree on its persistence scope and reset semantics before implementation, retaining consistent scaling of font size and line height.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorZoom.ts`, `src/vs/editor/contrib/fontZoom/browser/fontZoom.ts`, `src/vs/editor/common/config/fontInfo.ts`, `src/vs/editor/test/browser/config/editorConfiguration.test.ts`
- **Validation:** In a disposable VS Code profile, invoke editor.action.fontZoomOut, close and restart the application, and verify the adjusted editor text size is retained while workbench zoom is unchanged. Repeat with fontZoomIn and fontZoomReset, and verify new-window and workspace-switch behavior against the agreed persistence scope.
- **Behavior:**

  > Editor font zoom changes made through Increase Editor Font Size and Decrease Editor Font Size should survive closing and restarting VS Code. Retention must not require manually changing the base editor.fontSize setting or zooming the entire workbench. Acceptance checks should cover both commands, restart, and Reset Editor Font Size. The maintainer must settle how retained zoom behaves across windows, workspaces, and profiles.
- **Trace:**

  > src/vs/editor/contrib/fontZoom/browser/fontZoom.ts routes all three editor font zoom commands to the EditorZoom singleton in src/vs/editor/common/config/editorZoom.ts. That singleton starts at zero, clamps changes to -5 through 20, and emits updates without persistence; production workbench searches found no save/restore integration for it. src/vs/editor/common/config/fontInfo.ts applies the multiplier to both font size and line height, so base font settings are a workaround rather than persistence of command-driven zoom. src/vs/editor/test/browser/config/editorConfiguration.test.ts already exercises zoom bounds and fractional values, but does not establish restart persistence. Keep Monaco's standalone editor behavior and workbench window zoom outside the requested change unless explicitly agreed. https://github.com/microsoft/vscode/issues/166236#issuecomment-1345658179 consolidates a related request here; uncertainty starts at the persistence scope and reset contract, not at whether current state survives restart.
- **Open decisions:**
  - Should retained editor zoom be shared across all windows in a profile, or remembered separately for each workspace/window?
  - Should Reset Editor Font Size clear the retained zoom preference for its persistence scope, or reset only the current window?

## Evidence

- **Current command behavior:** src/vs/editor/contrib/fontZoom/browser/fontZoom.ts implements editor.action.fontZoomIn, editor.action.fontZoomOut, and editor.action.fontZoomReset solely through EditorZoom.setZoomLevel; these commands do not update persisted settings.
- **Persistence gap:** src/vs/editor/common/config/editorZoom.ts initializes _zoomLevel to 0 and retains changes only in memory. Production workbench searches found no integration that saves or restores this text-editor EditorZoom state.
- **Existing capability is a workaround:** editor.fontSize and editor.lineHeight provide configurable base sizing, while src/vs/editor/common/config/fontInfo.ts applies the separate zoom multiplier to both. Editing the base settings does not preserve adjustments made with the reported zoom commands.
