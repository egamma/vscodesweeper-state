# Issue #334999 — Race condition between large PreToolUse hook and cmd output.

[https://github.com/microsoft/vscode/issues/334999](https://github.com/microsoft/vscode/issues/334999)

## Summary

Traced a real race on current main: when a tool's result is disk-cached and a PreToolUse/PostToolUse hook adds `additionalContext`, the two resulting text parts of the same tool call are written to disk concurrently and collide on the same `content.txt` filename, so one write silently clobbers the other.

## Change summary

Large PreToolUse hook output and large command output for the same tool call can race when both get written to the same on-disk `content.txt`, corrupting the tool result the model reads back.

## Best solution

In `PrimitiveToolResult.render()` (extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx), the per-part `onText` calls run concurrently via `Promise.all`, and `appendHookContext` pushes extra `LanguageModelTextPart`s (PreToolUse/PostToolUse context) onto the same `toolResult.content` array — each part independently triggers `ChatDiskSessionResources.ensure(sessionId, toolCallId, ...)` which always writes a fixed `content.txt` name keyed only by sessionId+toolCallId. Fix by giving each part its own file name/subpath (e.g. thread a part index or content-hash suffix into `ensure`) so concurrent writes for the same tool call never share a path.
