# Issue #334999 — Race condition between large PreToolUse hook and cmd output.

[https://github.com/microsoft/vscode/issues/334999](https://github.com/microsoft/vscode/issues/334999)

## Summary

Traced this on main and it's a real race: the tool's own output and a PreToolUse hook's additionalContext are pushed as separate text parts on the same tool result, and ToolResult.render() processes all parts concurrently, each independently disk-caching to the same fixed filename for that toolCallId — so two large parts can clobber each other.

## Change summary

When both a large PreToolUse hook additionalContext and a large tool command output get disk-cached for the same tool call, their concurrent writes can race and one overwrites the other's content.txt/content.json.

## Best solution

In extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx, give each content part written via ToolResult.onText a distinct filename (e.g. suffix by part index) when disk-caching, so concurrent large parts for the same toolCallId no longer collide in ChatDiskSessionResources.ensure.
