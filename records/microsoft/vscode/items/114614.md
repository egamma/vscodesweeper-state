# Issue #114614 — Can't update the collapse state in the references-viewlet

[https://github.com/microsoft/vscode/issues/114614](https://github.com/microsoft/vscode/issues/114614)

## Summary

Keep open: the references-view API still lacks an explicit way to reset retained tree state when replacing its input. Maintainers acknowledged this API gap; the ID workaround and related closed issues do not establish that it was implemented.

## Change summary

Allow references-view API consumers to replace an input and apply its initial collapse states without inheriting state from matching previous items.

## Best solution

Provide a supported reset contract for references-view consumers while retaining existing state-preservation behavior for consumers that do not request a reset. Decide separately whether the later lazy-leaf proposal belongs in that contract or in its own TreeView API request.

Later comments additionally request removing expansion affordances after discovering empty children; that is a separate scope decision.
