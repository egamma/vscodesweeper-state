## Plan brief

- **Likely files:** `build/win32/code.iss`, `src/vs/platform/update/electron-main/updateService.win32.ts`
- **Validation:** In an isolated Windows VM with system setup, retain installer logs and file-operation traces while exercising update failure with Code running in another session. Establish a repeatable failing transition, then verify that failure or cancellation leaves the active version's out/cli.js and out/main.js present and that code --disable-extensions --version succeeds.
- **Behavior:**

  > The reported system installation loses its active version's compiled application directory, preventing CLI startup and breaking worker processes in existing sessions. A pending update must not damage the active installation, and a failed installation or rollback must leave a usable version. Diagnosis must distinguish the downloaded update from the installer process that actually changed files. Acceptance requires a captured failing transition followed by successful CLI startup and intact active application resources after the corrected failure path.
- **Trace:**

  > In src/vs/platform/update/electron-main/updateService.win32.ts, system setup reaches State.Ready after download without running the user-only background application path. In build/win32/code.iss, InstallDelete removes out for the installer's target VersionedResourcesFolder when IsNotBackgroundUpdate is true, and CurStepChanged invokes version-folder garbage collection after non-background installation. Neither observation explains why the older active commit directory was damaged in this occurrence; installer identity, target version, and file-operation attribution are the diagnosis boundary. https://github.com/microsoft/vscode/issues/224571#issuecomment-2490419769 documents a related cross-session locked-file rollback failure, while https://github.com/microsoft/vscode/issues/111107 tracks explicit cancellation leaving an unusable installation. Preserve the distinction between those established historical scenarios and this report's unverified initiating transition; do not change user-background update behavior merely because it shares installer infrastructure.
