## Summary

The missing webview entries in the auto-lock settings UI are already tracked by the older, open issue https://github.com/microsoft/vscode/issues/133229. Its discussion explicitly asks for extension-provided webview types and names in this same setting, so consolidating this request preserves the remaining work.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/133229 is currently open and was created on 2021-09-16, before this report. Its body identifies unregistered webview editors and the hardcoded workaround in editorConfiguration.ts.
- **Same observable gap:** https://github.com/microsoft/vscode/issues/133229#issuecomment-921461444 explicitly requests a list of extension-provided webview editors and their names so the auto-lock setting can list them. This matches the missing settings checkboxes reported here, satisfying the stronger duplicate bar for a re-reviewed item.
- **Contribution mechanism already discussed:** https://github.com/microsoft/vscode/issues/133229#issuecomment-974538591 states that webview types lack a package.json contribution and discusses runtime registration or caching as alternatives. This issue's manifest contribution proposal is an implementation option for that same capability, not a separate remaining behavior.
- **Current capability remains partial:** src/vs/workbench/browser/parts/editor/editorConfiguration.ts constructs the auto-lock settings properties from editorResolverService.getEditors() plus AUTO_LOCK_EXTRA_EDITORS, with additionalProperties: false. The named hardcoded entries do not provide general discovery of extension-created webview panels.
- **Manual configuration follow-up:** The supplied 2024-11-25 comment reports that using the extension's manifest webview name did not lock the group. src/vs/workbench/api/browser/mainThreadWebviewPanels.ts prefixes panel types with mainThreadWebview-, and webviewEditorInput.ts exposes that type as editorId; editor.ts reads enabled IDs and editorGroupView.ts checks them only for a newly opened first editor with multiple groups. Manual configuration therefore does not replace the requested discoverable, named settings entries.
