# Issue #19621 — Copy line does not work properly with multi-cursor

[https://github.com/microsoft/vscode/issues/19621](https://github.com/microsoft/vscode/issues/19621)

## Summary

Keep this accepted editor-multicursor request open: current main copies the line contents, but multi-cursor empty-selection copy/paste still lacks consistent whole-line insertion and can introduce extra blank lines. The related open reports are newer and cannot replace this previously reviewed issue as canonical duplicates.

## Change summary

Make copying with multiple empty cursors and pasting elsewhere insert the copied lines rather than an empty line.

## Best solution

Deliver consistent whole-line clipboard behavior for multiple empty cursors, preserving copied content without extra separator lines. Review the overlapping implementation candidate at https://github.com/microsoft/vscode/pull/286895 and verify this issue's paste-at-an-arbitrary-destination scenario separately before considering it completed.

## Evidence

- **Reported operation:** https://github.com/microsoft/vscode/issues/19621 describes Insert Cursor Above/Below, copying with empty selections, and pasting at an arbitrary destination. The reporter explicitly clarified that copying means Ctrl+C/Cmd+C, not the Copy Line Up/Down duplication commands.
- **Existing capability and remaining gap:** src/vs/editor/common/config/editorOptions.ts registers editor.emptySelectionClipboard, enabled by default, and editor.multiCursorPaste. In src/vs/editor/common/viewModel/viewModelImpl.ts:1005-1056, getPlainTextToCopy collects complete lines with trailing newlines for empty cursors. However, src/vs/editor/browser/controller/editContext/clipboardUtils.ts marks isFromEmptySelection only when there is one selection and joins multiple copied entries with another newline. For lines 'a' and 'b', this yields 'a\n\nb\n' for a single destination cursor, not a contiguous block of copied lines.
- **Paste behavior:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts:728-788 distributes matching multicursorText entries using ordinary ReplaceCommand operations at the cursor positions. Whole-line insertion at column 1 is confined to the pasteOnNewLine branch, which also rejects text containing more than one newline. The existing settings therefore do not fully cover consistent multi-line empty-selection paste behavior.
- **Related merged change is incomplete coverage:** https://github.com/microsoft/vscode/pull/256083 merged on 2025-12-18 to address https://github.com/microsoft/vscode/issues/256039. Its description explicitly leaves whole-line paste placement unresolved. It fixes distribution to multiple destination cursors, not all of this report's arbitrary-destination behavior.
