# Issue #120460 — [Gutter] Git Decorations bounding box and appearing

[https://github.com/microsoft/vscode/issues/120460](https://github.com/microsoft/vscode/issues/120460)

## Summary

A real gutter interaction gap remains on current main: hover visibility is activated by the entire editor margin rather than the Source Control decoration strip. Click handling attempts to avoid folding collisions, but the repeated report indicates its geometry needs live verification before changing it.

## Change summary

Restrict Source Control gutter decoration hover and click behavior so it does not interfere with adjacent folding controls.

## Best solution

The diff marker should appear and open its peek view only when the pointer is over its visible strip, while the folding control retains its full reliable target. Preserve the existing `always`/`hover` visibility and `diff`/`none` action settings.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/scm/browser/media/dirtydiffDecorator.css`, `src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts`, `src/vs/editor/browser/viewParts/linesDecorations/linesDecorations.ts`
- **Validation:** With `scm.diffDecorationsGutterVisibility` set to `hover` and `scm.diffDecorationsGutterAction` set to `diff`, use a modified foldable line: hovering or clicking the folding control must affect only folding, while hovering and clicking the visible diff strip must reveal and open the quick-diff view.
- **Behavior:**

  > On a modified line that also has a folding control, the folding control must fold or unfold reliably without opening the Source Control peek view. With gutter visibility set to `hover`, the diff marker should become visible only over its own decoration region. Clicking the visible marker should continue to open quick diff, and the existing `always` and `none` setting variants must remain unchanged.
- **Trace:**

  > Dirty-diff visibility is currently controlled by the broad `.monaco-editor .margin:hover` selector in src/vs/workbench/contrib/scm/browser/media/dirtydiffDecorator.css. QuickDiffController.onEditorMouseDown in src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts filters clicks using target type, class name, and a -3..3 pixel offset intended to avoid folding collisions. LinesDecorations in src/vs/editor/browser/viewParts/linesDecorations/linesDecorations.ts renders decoration elements at the full configured decorations width, so actual DOM hit geometry must be checked in a running editor. The boundary is gutter pointer behavior: folding semantics, quick-diff contents, and non-hover visibility modes must not change.
- **Open decisions:**
  - Should hover activation be scoped through decoration DOM geometry or through pointer-coordinate tracking in the quick-diff controller?
  - What target width should apply consistently to added, modified, and deleted markers without shrinking the folding control's usable area?
  - Can the gutter interaction be covered by an existing browser/UI harness, or should acceptance rely on the explicit manual scenario?

## Evidence

- **hover path on main:** src/vs/workbench/contrib/scm/browser/media/dirtydiffDecorator.css uses `.monaco-editor .margin:hover` for dirty-diff visibility, so hovering folding, line-number, or other margin regions reveals the marker.
- **click path on main:** QuickDiffController.onEditorMouseDown in src/vs/workbench/contrib/scm/browser/quickDiffWidget.ts accepts GUTTER_LINE_DECORATIONS events and applies a -3..3 pixel offset guard explicitly documented as avoiding a folding collision; the 2023 confirmation indicates this guard or its target geometry may remain insufficient.
- **shared decoration geometry:** src/vs/editor/browser/viewParts/linesDecorations/linesDecorations.ts renders each lines decoration across the configured decorations width, while folding controls and dirty-diff markers occupy this adjacent margin surface.
- **workaround:** `scm.diffDecorationsGutterAction: none` prevents the inline diff peek action, but it disables the desired interaction rather than resolving the overlapping target and broad hover behavior.
