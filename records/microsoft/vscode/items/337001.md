# Issue #337001 — Mention network domain allow/deny lists are not supported on Windows

[https://github.com/microsoft/vscode/issues/337001](https://github.com/microsoft/vscode/issues/337001)

## Summary

Confirmed on main: the Windows terminal sandbox (MXC container) only forwards a coarse `allowNetwork` boolean to `IWindowsMxcTerminalSandboxRuntime.createConfig` and never passes the resolved allowed/denied domain lists, while macOS/Linux get the full `{ allowedDomains, deniedDomains }` object — so the reporter's observation is accurate and the settings text should say so.

## Change summary

The `chat.agent.allowedNetworkDomains` / `deniedNetworkDomains` settings don't mention that domain-level allow/deny filtering isn't enforced by the Windows sandbox (only network on/off is), which is confusing on Windows.

## Best solution

Either implement domain-aware filtering for the Windows MXC sandbox runtime, or (the smaller ask actually requested) add a platform caveat to the `markdownDescription` of `AgentNetworkDomainSettingId.AllowedNetworkDomains`/`DeniedNetworkDomains` in chat.shared.contribution.ts noting that only network on/off is enforced on Windows today.
