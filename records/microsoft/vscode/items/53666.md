# Issue #53666 — Use code editor for rename input box

[https://github.com/microsoft/vscode/issues/53666](https://github.com/microsoft/vscode/issues/53666)

## Summary

Keep open: the rename prompt still uses a native text input rather than a code editor, leaving the requested editor-style subword navigation unsupported. This accepted Backlog request has 36 upvotes; the related open navigation issue is newer and cannot replace it under the re-review rules.

## Change summary

Support editor-style subword navigation and editing in the F2 Rename Symbol input.

## Best solution

Provide editor-backed editing in the rename widget so word-part commands act on the proposed name, while preserving single-line input, rename suggestions, preview, cancellation, and accessible focus behavior.

Also exercise Enter, preview acceptance, rename-suggestion navigation, and accessible focus announcements.
- **Behavior:**

  > The F2 Rename Symbol prompt should support the user's editor word-part navigation and editing commands on the proposed symbol name. For fooBar, moving left by a word part from the end should stop between foo and Bar; selection and deletion variants should target the input rather than the underlying document. Input remains single-line, and accepting, previewing, cancelling, and choosing rename suggestions retain their existing behavior.
- **Trace:**

  > RenameWidget in src/vs/editor/contrib/rename/browser/renameWidget.ts owns InputWithButton, which creates a native HTMLInputElement rather than an editor. The widget reads and writes its value and selection directly, applies editor font information, and coordinates focus with rename suggestions. Word-part commands are registered in src/vs/editor/contrib/wordPartOperations/browser/wordPartOperations.ts as editor commands; this input supplies no editor model for those operations. Rename acceptance, cancellation, preview, and suggestion commands are registered in src/vs/editor/contrib/rename/browser/rename.ts. The trace establishes the missing editor-backed surface, but not the embedded-editor lifecycle and command-targeting integration needed to preserve those interactions. Keep general non-editor-input support outside this request's scope; https://github.com/microsoft/vscode/issues/76762 tracks that broader limitation. A maintainer previously consolidated the editor-widget request here from https://github.com/microsoft/vscode/issues/32753.
