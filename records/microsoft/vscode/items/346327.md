# Issue #346327 — Let me expand long agent questions to a larger view

[https://github.com/microsoft/vscode/issues/346327](https://github.com/microsoft/vscode/issues/346327)

## Summary

Keep open: the question carousel still lacks a larger reading-and-answering mode. Existing collapse and focus controls do not satisfy this request, and the related layout and compactness reports cover different work.

## Change summary

Allow users to enlarge overflowing agent questions and answer options without navigating two constrained scroll areas.

## Best solution

Provide an accessible, user-invoked larger question view in the shared chat question carousel, consistent with confirmation expansion. Agree the initial presentation and session-persistence scope before implementation, preserving answers and submission behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatQuestionCarouselPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/media/chatQuestionCarousel.css`, `src/vs/workbench/contrib/chat/common/model/chatProgressTypes/chatQuestionCarouselData.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatQuestionCarouselPart.test.ts`
- **Validation:** Extend ChatQuestionCarouselPart browser tests and run scripts/test.sh --run src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatQuestionCarouselPart.test.ts. Manually check a 768px-tall Agents window with a multi-paragraph question and at least five options: larger-mode access, unified scrolling, keyboard restoration, retained answers, unchanged submission, and accessible expanded state.
- **Behavior:**

  > Users answering an overflowing askQuestions card can access a larger presentation without losing draft answers or changing which carousel receives submission. Long question text and options should be readable without two competing internal scroll areas in that presentation. Short questions retain the compact default. Keyboard users can restore the compact presentation without inadvertently dismissing the question, and assistive technologies receive the presentation state.
- **Trace:**

  > ChatQuestionCarouselPart sets --chat-question-carousel-max-height in its constructor and independently repeats the same fixed budget in layoutQuestionSections. renderCurrentQuestion creates a separate DomScrollableElement for answers and schedules section allocation through resize observers. The existing collapse button only toggles visibility; Escape currently calls ignore when allowSkip is true. Tool confirmation expansion provides a neighboring interaction precedent in chatToolConfirmationCarouselPart.ts. Draft answers, current index, and collapsed state are retained through ChatQuestionCarouselData, but there is no larger-presentation state. Preserve question navigation, validation, Markdown trust handling, and submission semantics; the related layout and density requests at https://github.com/microsoft/vscode/issues/345574 and https://github.com/microsoft/vscode/issues/336708 are not substitutes for this capability.
- **Open decisions:**
  - Should the initial larger presentation be inline expansion only, or include a separate modal/editor presentation?
  - Should the remembered size choice apply only to the current carousel or to subsequent question cards throughout the agent session?
