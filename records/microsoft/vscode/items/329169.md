# Issue #329169 — chat.useCustomizationsInParentRepositories does not discover agent skills through Git submodule .git files

[https://github.com/microsoft/vscode/issues/329169](https://github.com/microsoft/vscode/issues/329169)

## Summary

Confirmed real bug: `findParentRepoFolders` in promptFilesLocator.ts treats a `.git` file (submodule/worktree marker) the same as a `.git` directory, so discovery stops at the submodule boundary instead of continuing to the superproject root. An open PR already fixes this but hasn't merged yet — keep the issue open until it lands.

## Change summary

When a VS Code workspace folder is a Git submodule (`.git` is a file, not a directory), `chat.useCustomizationsInParentRepositories` fails to discover skills/customizations in the enclosing superproject repository.

## Best solution

Land the fix in the open PR (or an equivalent) that treats `.git` as a repo-root marker only when it's a directory and continues walking up when it's a file, per the traced logic in findParentRepoFolders.

## Evidence

- **root cause traced:** src/vs/workbench/contrib/chat/common/promptSyntax/utils/promptFilesLocator.ts lines 133-160: findParentRepoFolders() calls `this.fileService.exists(joinPath(current, '.git'))` without checking whether `.git` is a directory or file. For a Git submodule, `.git` is a file (`gitdir: ...`), so `exists()` returns true, `isRepoRoot` becomes true, and the walk stops at the submodule itself instead of continuing to the actual containing repository root.
- **not fixed on main:** git log shows the last change to promptFilesLocator.ts is commit f3104ae5b1f (#327749), unrelated to this fix; the buggy exists()-only check is still present on current main.
- **linked fixing PR (open):** https://github.com/microsoft/vscode/pull/330041 'fix(chat): discover parent repos from Git submodules' contains 'Fixes #329169' in its body, modifies exactly this file (promptFilesLocator.ts) to check .git is a directory and continue walking when it's a file, plus adds a regression test in promptFilesLocator.test.ts. It is still OPEN (not merged), so the issue should stay open until it lands.
