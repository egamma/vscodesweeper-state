# Issue #297622 — Allow agent/chat to access images in the terminal

[https://github.com/microsoft/vscode/issues/297622](https://github.com/microsoft/vscode/issues/297622)

## Summary

Keep open: terminal image rendering exists, but the inspected chat tools do not expose protocol-rendered terminal images as model context. This team-authored request has neither a verified fixing commit nor an older canonical covering the same capability.

## Change summary

Allow chat and agents to access images rendered inside the integrated terminal, alongside terminal text.

## Best solution

Provide bounded, model-consumable access to terminal image content through the terminal/chat integration. First settle whether access is explicitly requested or automatic, and which images belong to a given terminal context or command result.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts`, `src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/getTerminalOutputTool.ts`
- **Validation:** In a supported environment with terminal.integrated.enableImages enabled, render a Kitty or Sixel image without printing an image file path. Through the chosen chat/agent access mechanism, verify that image bytes reach model-facing context and can be interpreted. Check mixed text/image output, disabled image support, repeated retrieval, and image-count/byte limits.
- **Behavior:**

  > Chat and agents should be able to consume images rendered inside the integrated terminal, not only text or image filenames printed to stdout. Acceptance must include a protocol-rendered image whose file path is absent from textual output and verification that image content reaches the model. Existing text retrieval and terminal rendering should remain unchanged. The maintainer must define the access trigger and image-selection scope before those acceptance cases can be finalized.
- **Trace:**

  > XtermTerminal._refreshImageAddon in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts enables image rendering, while getContentsAsText serializes text buffer cells. GetTerminalOutputTool.invoke in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/getTerminalOutputTool.ts returns text-only execution output. RunInTerminalTool._extractImagesFromOutput in src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts reads image filenames from stdout and creates user-audience data parts; this is distinct from extracting rendered terminal graphics for model context. Inspection establishes the gap in these paths, but not the intended image-selection contract or the complete extraction API available from the addon. Preserve existing graphics-protocol support and text behavior. Consider the resource-bound concerns in https://github.com/microsoft/vscode/issues/332145 without folding this request into that newer, different report.
- **Open decisions:**
  - Should terminal images enter model context automatically with terminal output, or only through an explicit user attachment or agent request?
  - Should image access cover the current command's output, the visible terminal viewport, or retained terminal scrollback?
