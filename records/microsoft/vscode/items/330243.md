# Issue #330243 — Webview resources stream corrupted (every 256 KiB chunk delivered twice) when a second-instance CLI folder open lands during startup; corrupted response is then cached

[https://github.com/microsoft/vscode/issues/330243](https://github.com/microsoft/vscode/issues/330243)

## Summary

Detailed, well-instrumented report of webview resource corruption tied to a second-instance CLI open racing startup, with an independent commenter (enihcam) reproducing related symptoms (duplicate window1 domain, unmatched RequestStore replies, terminated extension hosts) via an A/B test isolating `--process-per-site`. The reporter's own root-cause attribution (webview service-worker RequestStore double-registration) doesn't quite match the code — the log line quoted (`RequestStore#acceptReply was called without receiving a matching request`) only exists in `src/vs/platform/terminal/common/requestStore.ts`, not in the separate `RequestStore` class inside `service-worker.js`, which has no such logging — so the actual mechanism needs a maintainer with window/webview internals to pin down, but the empirical byte-level doubling evidence is solid and worth routing.

## Change summary

When a second-instance CLI folder-open races the first instance's startup, webview resources loaded via the vscode-resource CDN get every ~256 KiB chunk delivered twice, corrupting scripts and other resources; the corrupted response is then cached by the webview service worker and replayed in later sessions.

## Best solution

Needs owner-level investigation into what actually duplicates during a second-instance open landing mid-startup — likely in the window/second-instance handling path (`src/vs/platform/windows/electron-main`) and/or the webview resource loading pipeline (`webviewElement.ts` load-resource/did-load-resource-chunk handling, `service-worker.js`), since the reporter's specific RequestStore citation doesn't match current source. Given the independent confirmation and its impact on webview-based extension testing (vscode-extension-tester), this is worth an area maintainer's look rather than a quick fix.
