# Issue #330292 — Agent Host should coordinate overlapping sessions

[https://github.com/microsoft/vscode/issues/330292](https://github.com/microsoft/vscode/issues/330292)

## Summary

Keep open: the session-management tools exist, but current Agent Host prompt guidance does not establish the requested check-before-editing coordination workflow. The linked implementation PR was closed without merging, and no verified canonical absorbs this request.

## Change summary

Have agents discover and coordinate potentially overlapping active work across worktrees before editing code or creating another session.

## Best solution

Provide a lightweight overlap-discovery workflow in Agent Host guidance that examines project-wide session metadata, reads context only for plausible overlaps, and coordinates ownership or sequencing when needed. Preserve independent progress when work does not conflict, and assess model behavior before adopting the guidance.

- **Behavior:**

  > Before making code changes or creating another session, an agent should discover relevant active work in the same project or repository, including other worktrees. It should inspect conversation context for plausible overlaps and coordinate ownership or sequencing when appropriate, preferring existing work over duplication. Acceptance should cover both an overlapping-task case and a non-conflicting case, with independent work proceeding without unnecessary waiting.
- **Trace:**

  > The shared session tools already expose discovery metadata, current-session identity, conversation context and asynchronous messaging in src/vs/platform/agentHost/node/shared/sessionServerTools.ts. Current Copilot universal guidance in toolInstructions.ts has no overlap workflow; promptRegistry.ts composes that guidance into the launch-time system message used by copilotSessionLauncher.ts. The prompt context's hasTool predicate sees client tools, not these server tools, so tool availability cannot be inferred from a client-tool-name check. https://github.com/microsoft/vscode/pull/330289 contains the earlier proposal but was closed unmerged; it is design evidence, not shipped behavior. Preserve existing session/chat identity, delegation relationships, permissions and unrelated-work progress. The trace establishes the missing host-authored guidance, not how reliably each model would follow it or whether provider-native behavior already covers some cases.
- **Open decisions:**

  - Should the initial behavior target Copilot Agent Host sessions only, or provide the same explicit coordination contract across all Agent Host providers?
