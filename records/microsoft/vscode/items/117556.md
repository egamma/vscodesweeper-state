# Issue #117556 — Onboard shared process to --prof-start

[https://github.com/microsoft/vscode/issues/117556](https://github.com/microsoft/vscode/issues/117556)

## Summary

The profiling gap remains on current main: `--prof-startup` captures the main, renderer, and extension-host processes but not the increasingly important shared process. Keep this open for prioritization as a valid performance-tooling request.

## Change summary

Include the shared process in the CPU profiles collected by `code --prof-startup`.

## Best solution

Extend the startup-profiler orchestration in `src/vs/code/node/cli.ts` with a fourth inspector port and profile session, passing that port through the existing shared-process inspection path in `src/vs/platform/sharedProcess/electron-main/sharedProcess.ts`.
