# Issue #335002 — Virtualized customization lists (#334366) make most sections unusably tiny

[https://github.com/microsoft/vscode/issues/335002](https://github.com/microsoft/vscode/issues/335002)

## Summary

Traced the water-filling allocation in `layoutVirtualizedSections()` and confirmed the reporter's diagnosis: since each section's minimum is a single row (`ITEM_HEIGHT` = 44px), any page with several sections collapses most of them to one-row slivers before any section can grow to its full content height. This is a real, recently introduced regression that needs a design decision on the right per-section minimum and scroll fallback, so it stays open.

## Change summary

The AI customization editor's virtualized section layout shrinks most sections to a single-row minimum when a page has several sections, instead of showing a few taller, browsable lists.

## Best solution

Increase the per-section minimum allocation (e.g. a handful of rows) in `layoutVirtualizedSections()`/`aiCustomizationListWidget.ts` before falling back to the page-level scroll/overflow path, so common multi-section pages like Skills don't collapse every section to one row; needs a maintainer decision on the right minimum row count and whether the equal-share algorithm should instead prioritize fewer, taller sections.
