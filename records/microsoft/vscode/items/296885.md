# Issue #296885 — Notifying user when Copilot CLI terminal is waiting for user response via chat UI

[https://github.com/microsoft/vscode/issues/296885](https://github.com/microsoft/vscode/issues/296885)

## Summary

Keep open: external-session discovery and chat confirmation notifications now exist, but the inspected paths do not establish live waiting-for-input notifications for a session still running in the standalone CLI. This team-authored, accepted request needs its remaining scope evaluated against the newer Agent Host architecture.

## Change summary

Notify users through the chat UI when a terminal-hosted Copilot CLI session needs input, without presenting stale history or creating a diverging conversation.

## Best solution

Provide an authoritative attention indicator for the running CLI session, with a response destination that preserves its conversation ownership. Evaluate the current Agent Host integration first, then settle whether responding returns users to the terminal or requires supported live attachment.

Verify chat indicates that live request without starting another conversation; answering in the owning surface clears the indication. Repeat with the session visible in two VS Code windows, then disconnect or exit the CLI and verify no stale actionable indication remains.
- **Behavior:**

  > Users should be able to notice in the chat UI that a Copilot CLI session running in a terminal requires input. The indication must reflect the owning runtime rather than infer liveness from saved history. Following the indication must not silently start an independent conversation or imply that histories are synchronized when they are not. Acceptance includes clearing resolved requests and handling multiple windows and CLI termination without stale actionable state.
- **Trace:**

  > ChatWindowNotifier in src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts observes requestNeedsInput on live workbench chat models, while AgentHostSessionListController maps host InputNeeded status to NeedsInput. CopilotAgent._discoverCopilotChats in src/vs/platform/agentHost/node/copilot/copilotAgent.ts discovers provider-native external sessions through SDK catalog metadata; the inspected discovery payload does not establish live pending-input state. CopilotCLISessionTracker can identify a local terminal for a connected session, but this alone does not synchronize the running conversation. External discovery and continuation are already covered by https://github.com/microsoft/vscode/pull/330541 and https://github.com/microsoft/vscode/issues/331122. The uncertainty starts at obtaining an authoritative input-needed signal from an independently running CLI and choosing its response destination; the linked https://github.com/github/copilot-sdk/issues/536 could not be inspected. Preserve existing discovery filters, session identities, and conversation ownership; do not equate discovery or continuation with live attachment.
- **Open decisions:**
  - Should the attention action return users to the owning terminal, or must this feature support answering in chat through an authoritative live attachment to that same running conversation?
