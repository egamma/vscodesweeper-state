# Issue #80889 — Ability to disable language features provided by extensions

[https://github.com/microsoft/vscode/issues/80889](https://github.com/microsoft/vscode/issues/80889)

## Summary

A real capability gap remains on current main, and the existing extensions/under-discussion classification is appropriate while provider-selection semantics are designed.

## Change summary

Allow users to disable individual language features from selected extensions while leaving their other features enabled.

## Best solution

Design a centralized, language-scoped provider preference mechanism that can identify extensions and selectively exclude their providers while preserving today's enable-all default. The design must account for features with different aggregation semantics, including diagnostics outside the standard provider registries.

- **Evidence:** The public values emphasize that “the power lives in extensions” while also favoring a lightweight default experience and cautioning against configuration sprawl.

## Evidence

- **current source gap:** src/vs/editor/common/languageFeatureRegistry.ts stores selector/provider entries and returns every matching provider from all() and ordered(); it has no user-configured extension or feature exclusion mechanism.
- **registration path:** src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts registers hover, definition, completion, and other extension providers directly into the shared registries without consulting a provider-disable preference.
- **existing partial capability:** src/vs/workbench/contrib/format/browser/formatActionsMultiple.ts registers editor.defaultFormatter, but that preference is specific to formatting and does not cover hover, definition, completion, symbols, or diagnostics.
