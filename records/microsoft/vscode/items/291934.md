# Issue #291934 — Add visual indicator in chat UI when auto-allow/YOLO mode is enabled with quick toggle

[https://github.com/microsoft/vscode/issues/291934](https://github.com/microsoft/vscode/issues/291934)

## Summary

A real gap remains: current chat UI exposes and highlights session permission levels, but it does not clearly surface the effective global auto-approve setting or provide a direct way to disable that setting. This team-authored request must remain open because no commit or linked closing PR explicitly references it.

## Change summary

Show a persistent warning in chat while global auto-approve is enabled and provide a quick action to change that state.

## Best solution

Integrate the global override into the existing chat permissions control so the effective approval state is always visible and users can disable global auto-approve without leaving chat, while clearly distinguishing global and session-scoped permissions.

- **Reason:** Making unrestricted agent execution conspicuous and reversible advances both AI-assisted development and VS Code's durable security direction.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/permissionPickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/chatInputPickerActionItem.test.ts`
- **Validation:** Add a browser unit test showing that chat.tools.global.autoApprove=true produces a persistent elevated-state indication even when the stored session level is Default, and that the exposed disable action updates the setting; manually verify the state remains visible across chat sessions and window reloads.
- **Behavior:**

  > When global auto-approve is enabled, every affected chat surface must continuously communicate that tools can run without approval, even if the session's stored permission level says Default. The indication must expose a direct, accessible way to leave the elevated state and must update immediately when configuration changes. Session-only Allow all and Autopilot states must remain distinguishable from the global override.
- **Trace:**

  > The local-chat permission control is rendered by PermissionPickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/permissionPickerActionItem.ts from delegate.currentPermissionLevel. ChatInputPart in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts observes ChatConfiguration.GlobalAutoApprove, but its handler reapplies the unchanged session level, and input-state restoration deliberately skips permission synchronization while the global setting is enabled. Consequently, the visible picker can report Default permissions while global auto-approve still determines tool confirmation. Agent-host sessions also have a session-scoped picker under src/vs/workbench/contrib/chat/browser/agentSessions/agentHost, so the design must preserve the distinction between global configuration, local-session permission state, and provider-specific session permissions. Preserve enterprise-policy restrictions, existing elevated-permission confirmation dialogs, and session permission persistence.
- **Open decisions:**
  - Should the global override appear as a distinct persistent warning state in the existing permissions control, or as a separate non-dismissible banner alongside it?
  - Should the quick action directly disable chat.tools.global.autoApprove for all chats, or offer both a global disable action and a separately labeled session-level permission choice?

## Evidence

- **current session UI:** src/vs/workbench/contrib/chat/browser/widget/input/permissionPickerActionItem.ts renders the current session permission level, applies warning/info styling, and lets users select Default, Allow all, or Autopilot.
- **global-state gap:** src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts listens for chat.tools.global.autoApprove changes but only reapplies the existing session permission level; PermissionPickerActionItem renders delegate.currentPermissionLevel rather than the effective global setting. A globally enabled override can therefore remain visually represented as Default permissions.
