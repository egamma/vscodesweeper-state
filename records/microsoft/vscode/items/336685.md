# Issue #336685 — files.candidateGuessEncodings fails on short non-UTF8 files (fallback to invalid UTF-8 instead of next candidate)

[https://github.com/microsoft/vscode/issues/336685](https://github.com/microsoft/vscode/issues/336685)

## Summary

Confirmed real defect: jschardet-based guessing in encoding.ts silently falls back to UTF-8 (corrupting bytes) when a short/sparse non-UTF-8 buffer yields low statistical confidence, instead of validating the buffer against strict UTF-8 rules and preferring a configured candidate encoding. A maintainer has already opened a fix PR that references this issue, so this should stay open pending that PR, not be closed or handed to an agent.

## Change summary

With files.autoGuessEncoding=false and files.candidateGuessEncodings set, short non-UTF-8 files (e.g. an 8-byte Big5/CP950 sample) are misdecoded as UTF-8 with U+FFFD replacement characters instead of falling back to the candidate encoding.

## Best solution

Land and review https://github.com/microsoft/vscode/pull/337268 (already titled 'files: fix encoding fallback for short non-UTF-8 files' and marked 'Fixes #336685'), which should add stricter UTF-8 validation/ordering before jschardet's low-confidence guess is trusted.
