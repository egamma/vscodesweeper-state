# Issue #336685 — files.candidateGuessEncodings fails on short non-UTF8 files (fallback to invalid UTF-8 instead of next candidate)

[https://github.com/microsoft/vscode/issues/336685](https://github.com/microsoft/vscode/issues/336685)

## Summary

Real, well-diagnosed limitation: `guessEncodingByBuffer` in encoding.ts hands buffers straight to jschardet's statistical detector with no strict UTF-8 validity check first, so short or ASCII-diluted non-UTF8 files return low/zero confidence and silently fall back to `files.encoding` even when `files.candidateGuessEncodings` names the right codepage — but fixing this well requires a design call, not a one-line patch.

## Change summary

With `files.autoGuessEncoding` on and `files.candidateGuessEncodings` set, short or mostly-ASCII files containing a few non-UTF-8 multi-byte characters (e.g. Big5/CP950) are misdetected as UTF-8 and rendered with U+FFFD replacement characters instead of falling back to the configured candidate encoding.

## Best solution

Add a strict UTF-8 validity pre-check (or raise jschardet's confidence handling) in `guessEncodingByBuffer`/`detectEncodingFromBuffer` in src/vs/workbench/services/textfile/common/encoding.ts so that when the buffer is provably invalid UTF-8, detection prefers a supplied `candidateGuessEncodings` entry over silently falling back to `files.encoding`.

- **Open decisions:**

## Evidence

- **no strict UTF-8 pre-check:** src/vs/workbench/services/textfile/common/encoding.ts:322-358 (`guessEncodingByBuffer`) passes the raw buffer straight to `jschardet.detect(...)` with only `candidateGuessEncodings` as a restriction hint — there is no RFC 3629 UTF-8 validity check anywhere in this path before or alongside the statistical guess.
- **known jschardet limitation acknowledged in code:** encoding.ts:325 already comments on a jschardet buffer-size caveat (https://github.com/aadsm/jschardet/issues/53), showing the statistical detector's confidence issues on small/short buffers are a known constraint, not something the current code guards against.
- **reporter's own diagnosis:** Comments 2–3 on the issue show the same jschardet-only fallback failing both on an 8-byte file and on a 4947-byte file with sparse non-ASCII content, consistent with the code path traced above.
