# Issue #299515 — Cmd+C with no selection leaks bare "c" into TUI input on 1.110.0 (selection path works)

[https://github.com/microsoft/vscode/issues/299515](https://github.com/microsoft/vscode/issues/299515)

## Summary

Fixed on main: commit 7b17c65f78d intercepts all Meta-modified key events before xterm.js when the kitty keyboard protocol is active, preventing the exact leak described here. Shipped in 1.113.0.

## Change summary

Cmd+C with no selection leaks a bare 'c' character into TUI input in the integrated terminal on macOS when the kitty keyboard protocol is enabled.

## Best solution

Keep the shipped fix in commit 7b17c65f78d (1.113.0); no further change needed. The fix ensures VS Code intercepts all meta key events before xterm.js processes them under the kitty keyboard protocol, which resolves the Cmd+C leak and the broader class of meta-key issues.

  > Thanks for the detailed report and investigation — the keyboard troubleshooting logs were especially helpful in diagnosing this.
  > 
  > The root cause was that when the kitty keyboard protocol is active (which became the default), xterm.js encodes Meta-modified keys as CSI u sequences and consumes them via `preventDefault`, so VS Code never sees them to handle clipboard copy. This was fixed in https://github.com/microsoft/vscode/commit/7b17c65f78d (shipped in 1.113.0), which intercepts all Meta-modified key events before xterm.js processes them when kitty keyboard is active.
  > 
  > If you're still seeing this on the latest stable (1.117+), please open a new issue with updated details.
