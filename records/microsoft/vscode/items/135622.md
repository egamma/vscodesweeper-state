# Issue #135622 — Enable to comment out an entire block by simply placing the cursor on the first line of the block

[https://github.com/microsoft/vscode/issues/135622](https://github.com/microsoft/vscode/issues/135622)

## Summary

The requested first-line, whole-code-block commenting capability remains absent from the current command. This accepted Backlog request has 22 upvotes; the linked implementation was closed without merging, and the older related request concerns uncommenting an existing comment rather than commenting a code block.

## Change summary

Allow commenting an entire code block with the cursor on its first line, without manually selecting the block.

## Best solution

Provide a deliberate block-aware commenting operation in the editor-comments area that identifies the intended code block from its first line. Settle its activation and block-boundary semantics before implementation, preserving precise selected-range commenting.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/comment/browser/comment.ts`, `src/vs/editor/contrib/comment/browser/blockCommentCommand.ts`, `src/vs/editor/contrib/comment/test/browser/blockCommentCommand.test.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`
- **Validation:** After choosing the command contract, add targeted editor-comment tests for a caret on the first line of a multiline code block, asserting that exactly the intended block is commented. Cover nested blocks, no matching block, explicit selections, cursor state, and preservation of the existing empty-comment behavior wherever the new operation is not activated.
- **Behavior:**

  > A user can comment an entire code block with the cursor on its first line, without manually selecting its contents. The operation must include the intended block and leave neighboring code unchanged. Acceptance checks should cover nested blocks and lines with no identifiable block, while preserving existing explicit-selection commenting. The supported block forms and activation mechanism must be agreed before implementation.
- **Trace:**

  > BlockCommentAction.run in src/vs/editor/contrib/comment/browser/comment.ts forwards unchanged selections to BlockCommentCommand. _createAddBlockCommentOperations in src/vs/editor/contrib/comment/browser/blockCommentCommand.ts wraps a nonempty range or inserts an empty comment at the caret; the existing 'empty selection wraps itself' test pins the latter behavior. Existing smart-selection and bracket-selection commands can assist selection but do not perform the requested first-line commenting operation. https://github.com/microsoft/vscode/pull/135533 attempted curly-brace matching from the first line but closed without merging and also changed explicit-selection boundaries, which is separate from this request. https://github.com/microsoft/vscode/issues/32541 concerns uncommenting an existing multiline comment and is related rather than a duplicate. Preserve explicit-selection semantics and language-specific comment delimiters; uncertainty remains about the new operation's activation and which language block structures it recognizes.
- **Open decisions:**
  - Should first-line block inference be a separate command or an opt-in behavior of Toggle Block Comment, preserving the existing empty-comment insertion by default?
  - Should the operation initially recognize matched brace-delimited blocks only, or also indentation- and language-defined blocks, and what should happen when the first line contains multiple candidate blocks?
