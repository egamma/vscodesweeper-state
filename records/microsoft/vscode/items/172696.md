# Issue #172696 — Increase maximum problems per file (or allow customization)

[https://github.com/microsoft/vscode/issues/172696](https://github.com/microsoft/vscode/issues/172696)

## Summary

The requested capability remains missing: current source still caps diagnostics sent to the workbench at 1000 per file per collection, with no configurable override on that path. This accepted Backlog request has 24 upvotes; the related reports do not provide an eligible canonical duplicate.

## Change summary

Allow more than 1000 diagnostics for an individual file, either through a higher limit or a configurable limit.

## Best solution

Provide a performance-bounded way to expose more diagnostics in the Problems view and its filtering. Decide whether to increase the fixed cap or offer an opt-in setting, while treating editor-decoration limits as a separate scope decision.

## Plan brief

- **Likely files:** `src/vs/workbench/api/common/extHostDiagnostics.ts`, `src/vs/workbench/api/test/browser/extHostDiagnostics.test.ts`, `src/vs/editor/common/services/markerDecorationsService.ts`
- **Validation:** Extend the extHostDiagnostics capping tests to verify the chosen higher limit forwards diagnostics beyond index 1000, preserves severity ordering and accurate omission signaling, and respects the chosen batch budget. Manually publish more than 1000 distinct diagnostics for one file and verify that Problems filtering finds a diagnostic previously omitted; check editor responsiveness and the agreed decoration behavior.
- **Behavior:**

  > A file with more than 1000 diagnostics should have a supported way to expose diagnostics beyond the current cap in the Problems view and filtering. The issue permits either a higher fixed limit or customization; it does not settle the default or the maximum supported value. Acceptance should include a diagnostic beyond the old cutoff being visible and searchable, accurate omission reporting when the new limit is exceeded, and preserved responsiveness.
- **Trace:**

  > ExtHostDiagnostics in src/vs/workbench/api/common/extHostDiagnostics.ts supplies fixed per-file and total limits to DiagnosticCollection. DiagnosticCollection.set keeps all diagnostics in its local data but caps the markers sent through $changeMany, prioritizes severity, and appends an omission marker; its batch budget is derived from the per-file constant. Existing capping tests in src/vs/workbench/api/test/browser/extHostDiagnostics.test.ts cover these distinctions. Editor squiggles have an independent take: 500 cap in src/vs/editor/common/services/markerDecorationsService.ts, so greater Problems coverage must not be mistaken for greater decoration coverage. Preserve collection retrieval, severity ordering, and unrelated diagnostic behavior. Related reports https://github.com/microsoft/vscode/issues/186604 and https://github.com/microsoft/vscode/issues/200206 provide context for the decoration boundary, not duplicate ownership.
- **Open decisions:**
  - Should users receive a higher fixed cap or an opt-in configurable cap, and what default and supported maximum should apply?
  - Should the increased limit affect only diagnostics available in Problems, or also editor decorations?

## Evidence
