# Issue #173411 — Make history service work with debounced editor events

[https://github.com/microsoft/vscode/issues/173411](https://github.com/microsoft/vscode/issues/173411)

## Summary

The performance gap remains on current main: history processes selection events synchronously and later derives state from the editor pane. The issue is already correctly routed and explicitly marked `keep`.

## Change summary

Allow history-service editor events to be debounced without recording stale editor or selection state.

## Best solution

Capture immutable editor identity and selection data when each event fires, then debounce history processing without querying mutable editor-pane state. Preserve event ordering and add navigation-history regression coverage for rapid editor and selection changes.

- **Fit:** aligned
- **Reason:** Reducing synchronous work on common editor input events directly advances VS Code's longstanding performance goals.
- **Evidence:** Public values and durable themes explicitly state “Performance trumps functionality” and prioritize editor latency.
