# Issue #40115 — indent back to line start after enter newline and press up

[https://github.com/microsoft/vscode/issues/40115](https://github.com/microsoft/vscode/issues/40115)

## Summary

Keep open: the existing settings provide a useful workaround, but do not restore contextual indentation on whitespace-free lines while retaining whitespace cleanup. The request has 44 upvotes, and the verified related issues do not establish a same-symptom canonical.

## Change summary

Keep the cursor at the contextual indentation when returning to an empty line after pressing Enter.

## Best solution

Define contextual blank-line cursor behavior in the editor's indentation and movement paths without requiring users to retain trailing whitespace. Coordinate with the related trimming and virtual-space requests, while preserving this issue's Enter-then-Up acceptance case.

## Plan brief

- **Likely files:** `src/vs/editor/common/model/textModel.ts`, `src/vs/editor/common/cursor/cursorMoveOperations.ts`, `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add a cursor-controller acceptance test for Enter followed by Up inside an indented block, asserting the resulting cursor column and exact buffer contents. Cover trimAutoWhitespace enabled and disabled, tabs and spaces, and navigation to a blank line after whitespace removal.
- **Behavior:**

  > After creating a new line inside an indented block and moving Up to the preceding blank line, the cursor should return to a useful contextual indentation rather than column one. Disabling whitespace cleanup is only a partial workaround, particularly after formatting or saving removes indentation. Acceptance must specify both the visible cursor position and whether navigating to the line changes the document, with tabs and spaces respected.
- **Trace:**

  > TextModel._pushEditOperations in src/vs/editor/common/model/textModel.ts removes tracked auto-inserted whitespace on subsequent edits; its newline-after-line exception allows the preceding blank line to be trimmed. MoveOperations.moveUp and vertical in src/vs/editor/common/cursor/cursorMoveOperations.ts resolve movement against existing model columns, without contextual indentation reconstruction. editor.trimAutoWhitespace=false preserves newly inserted whitespace, while files.trimTrailingWhitespace=true removes it on save, leaving the revisiting-empty-lines requirement unresolved. Related https://github.com/microsoft/vscode/issues/209939 addresses selective trimming, and https://github.com/microsoft/vscode/issues/13960 addresses general virtual space; neither verified body establishes a same-symptom duplicate. Preserve existing explicit whitespace-cleanup controls and ordinary movement on nonblank lines. The unresolved boundary is whether contextual cursor placement requires real buffer indentation or a non-mutating virtual position.
- **Open decisions:**
  - Should returning to an empty line materialize indentation and potentially dirty the document, or place the cursor at a virtual indentation without modifying its contents?
  - Should contextual placement apply only to recently auto-indented lines, or also to whitespace-free blank lines encountered after formatting, saving, or reopening a file?
