# Issue #40115 — indent back to line start after enter newline and press up

[https://github.com/microsoft/vscode/issues/40115](https://github.com/microsoft/vscode/issues/40115)

## Summary

Keep open: disabling automatic whitespace trimming preserves newly inserted indentation, but does not cover the thread's request to retain indentation while still cleaning whitespace. The related requests do not satisfy the stronger duplicate bar for this re-reviewed item.

## Change summary

Preserve the expected indentation position when returning to an empty line after pressing Enter, without abandoning whitespace cleanup.

## Best solution

Define empty-line indentation behavior in the editor's autoindent and cursor movement paths, including its interaction with whitespace cleanup. Coordinate with the selective-trimming request without treating formatting, rectangular selection, and Enter-then-Up navigation as interchangeable requirements.

- **Behavior:**

  > Returning to an empty line after pressing Enter should preserve the expected indentation position. Disabling all automatic whitespace cleanup is only a partial workaround for users who still want cleanup elsewhere. Acceptance must cover tabs and spaces and establish whether the indentation survives saving, formatting, or reopening a file.
- **Trace:**

  > TextModel._pushEditOperations in src/vs/editor/common/model/textModel.ts can remove all tracked auto-inserted whitespace when a newline is inserted at the end of that line. MoveOperations.moveUp and vertical in src/vs/editor/common/cursor/cursorMoveOperations.ts subsequently navigate using the destination line's actual contents. editor.trimAutoWhitespace disables that deletion but does not synthesize indentation after other operations remove it. The thread accepts further selective-trimming work at https://github.com/microsoft/vscode/issues/209939; formatting-specific preservation is separately discussed at https://github.com/microsoft/vscode/issues/49661. Preserve ordinary cursor movement, tabs-versus-spaces conventions and undo semantics; the unresolved boundary is whether indentation remains document text or exists only as a navigation/typing affordance.
- **Open decisions:**
  - Should returning to an empty line preserve literal indentation in the document, or provide an indentation position without retaining trailing whitespace?
  - Should the behavior apply only to recently autoindented lines, or also to empty lines encountered after formatting, saving or reopening?
