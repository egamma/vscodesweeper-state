# Issue #299365 — "$$n" doesn't replace by literal "$n" in Regex replace (Workspace search only)

[https://github.com/microsoft/vscode/issues/299365](https://github.com/microsoft/vscode/issues/299365)

## Summary

The workspace replacement parser still leaves `$$0` unchanged instead of producing literal `$0`. Two open PRs explicitly target this issue; keep it open while those implementation candidates are reviewed.

## Change summary

Make workspace regex replacement interpret `$$` as a literal dollar sign, consistently with in-editor replacement.

Review https://github.com/microsoft/vscode/pull/326451 and https://github.com/microsoft/vscode/pull/341892, land one implementation that restores escaped-dollar semantics, and consolidate the competing fix attempts. Keep the separate case-converted capture defect tracked independently.

## Evidence

- **Current-source defect:** In src/vs/workbench/services/search/common/replace.ts, ReplacePattern.parseReplaceString advances past both dollars in `$$0` without recognizing an escape or setting _hasParameters. getReplaceString consequently returns the unchanged replacement template through buildReplaceString, producing `$$0` for the reporter's regex search for `some_line`.
- **Editor behavior:** src/vs/editor/contrib/find/browser/replacePattern.ts explicitly recognizes consecutive CharCode.DollarSign characters and emits one static dollar through result.emitStatic('$', i + 1). This confirms the reported workspace/editor inconsistency.
- **Discussion confirmation:** The supplied discussion on https://github.com/microsoft/vscode/issues/299365 includes RedCMD's independent confirmation for `$$1` and dobbydobap's diagnosis of the missing `$$` handling in parseReplaceString. The reporter also reproduced with extensions disabled.
