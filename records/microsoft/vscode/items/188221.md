Its broader request for persistent panel layouts covers the same new-workspace loss of expansion state.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/156160#issuecomment-1279308901 proposes storing the most recently used workspace state globally to provide sensible defaults for new workspaces. https://github.com/microsoft/vscode/issues/156160#issuecomment-3263330395 explicitly includes collapsed/expanded state in the requested persistence.
- **Current persistence boundary:** src/vs/workbench/services/views/common/viewContainerModel.ts:90-122 stores collapsed state in StorageScope.WORKSPACE, while profile-level state stores visibility and order but not collapse state. initialize() and add() fall back to the descriptor's collapsed default when the new workspace has no stored expansion state. This explains why expansion in one worktree is not inherited by another.
- **Manifest-default explanation:** src/vs/workbench/api/browser/viewsExtensionPoint.ts:153-165 documents that contributed views in explorer, SCM, and debug start collapsed regardless of visibility. Descriptor construction at line 527 and showCollapsed() at lines 637-644 explicitly enforce that SCM default. The reported package.json behavior therefore does not establish a separate failure to apply supported defaults.
- **Extension ownership evidence:** https://github.com/gitkraken/vscode-gitlens/issues/2781#issuecomment-1641138485 states that GitLens cannot control this behavior beyond contributing defaults and links this VS Code report. The persistence boundary is in VS Code, not an established GitLens defect.
