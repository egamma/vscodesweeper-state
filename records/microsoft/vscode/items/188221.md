# Issue #188221 — View state doesn't seem to be initialized/restored properly anymore

[https://github.com/microsoft/vscode/issues/188221](https://github.com/microsoft/vscode/issues/188221)

## Summary

Verified duplicate: the older open issue https://github.com/microsoft/vscode/issues/156160 owns the broader request to use a global view-layout baseline for new workspaces, including collapsed and expanded state. The alternative request to honor extension defaults in SCM is established as intentional behavior by https://github.com/microsoft/vscode/issues/121189.

## Change summary

Restore the previous view layout, or extension-declared defaults, when opening a new workspace instead of collapsing every contributed SCM view.

## Best solution

Consolidate the GitLens/SCM example on https://github.com/microsoft/vscode/issues/156160 and design a global default layout for newly opened workspaces while retaining workspace-specific customization.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/156160 is open, predates this report, and asks for panel/view layouts to be saved globally instead of requiring rearrangement for every new folder.
- **maintainer diagnosis:** In https://github.com/microsoft/vscode/issues/156160#issuecomment-1279308901, a maintainer identifies the same state split and proposes storing the most recently used workspace state globally to provide defaults for new workspaces.
- **current source:** src/vs/workbench/services/views/common/viewContainerModel.ts stores collapsed state and size in StorageScope.WORKSPACE, so a new workspace does not inherit those values from another workspace.
- **intentional SCM default:** src/vs/workbench/api/browser/viewsExtensionPoint.ts explicitly makes extension-contributed Explorer, SCM, and Debug views collapsed by default; https://github.com/microsoft/vscode/issues/121189 was closed as designed with the rationale that these built-in containers should avoid opening every contributed view.
- **unique example:** https://github.com/gitkraken/vscode-gitlens/issues/2781 records the concrete GitLens impact: its SCM views start collapsed in each newly opened workspace, and GitLens cannot control the persisted host layout.
