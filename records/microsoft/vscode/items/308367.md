Reporter can no longer reproduce the original multi-root path-resolution bug and revised their theory to stale diagnostics not clearing when referenced files are restored. ## Change summary

The prompt validator reports false 'File not found' errors for relative .md links in multi-root workspaces, possibly because diagnostics are not re-validated when referenced files are created or restored on disk.

## Best solution

The `ModelTracker` in `src/vs/workbench/contrib/chat/browser/promptSyntax/promptFileContributions.ts` only re-validates on content changes and tool/mode/model changes — it has no file-system watcher for referenced files. Adding a re-validation trigger when an editor gains focus (as aeschli suggested) or when workspace file events fire would address stale diagnostics. The issue needs the reporter to confirm the revised scenario (stale diagnostics after file restore) on a current build before investing in the fix.
