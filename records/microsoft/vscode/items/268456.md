# Issue #268456 — Copy selection from Debug console

[https://github.com/microsoft/vscode/issues/268456](https://github.com/microsoft/vscode/issues/268456)

## Summary

Keep open: an independent reporter confirmed the failure in 1.113.0 and identified context-menu copying, rather than Linux middle-click selection pasting, as the trigger. Current source exposes a plausible selection-lifetime failure, but no verified fixing commit or qualifying older duplicate was found.

## Change summary

Copying selected Debug Console text through the context menu truncates the copied selection to the currently displayed portion.

## Best solution

Preserve the complete selected Debug Console text when opening its context menu and invoking Copy, including selected rows outside the viewport. Investigate the interaction between REPL copying and shared list selection lifetime while preserving virtualization and ordinary selection clearing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/base/browser/ui/list/listView.ts`
- **Validation:** On Linux, produce enough numbered Debug Console lines to span several viewports, select across a viewport boundary, right-click the selection, choose Copy, and paste into an editor. Verify that the exact selected range survives, including off-screen lines and partial-line endpoints; compare keyboard copying and middle-click pasting. Establish an automated regression check for the confirmed selection-lifetime sequence, and verify that ordinary clicks still clear selection and unselected rows remain virtualized.
- **Behavior:**

  > Selecting Debug Console output across multiple viewports and invoking context-menu Copy must copy the entire selected text, not only the portion remaining on screen or the clicked log entry. Preserve partial-line selection endpoints. Keyboard copying and Linux middle-click pasting must remain functional, and Copy All must retain its separate meaning.
- **Trace:**

  > The independent confirmation at https://github.com/microsoft/vscode/issues/268456#issuecomment-4178970513 isolates context-menu copying from Linux primary-selection pasting. Repl.onContextMenu in src/vs/workbench/contrib/debug/browser/repl.ts passes the clicked element, while debug.replCopy reads the live DOM Selection only when the action runs. The REPL uses a WorkbenchAsyncDataTree with userSelection enabled. In src/vs/base/browser/ui/list/listView.ts, onPotentialSelectionStart clears the existing selection store on mousedown; its disposal clears currentSelectionBounds and rerenders, while getRenderRange uses those bounds to retain selected off-screen rows. Establish whether right-click teardown explains the reported truncation on current main and where native context-menu focus affects that sequence; the runtime behavior was not exercised in this read-only review. Shared list selection affects consumers beyond the REPL, so preserve their selection clearing, scrolling, and virtualization behavior rather than treating this as an isolated clipboard substitution. The newer macOS report at https://github.com/microsoft/vscode/issues/322732 is related evidence, not a qualifying duplicate canonical.
