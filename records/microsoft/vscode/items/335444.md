# Issue #335444 — Provide a stable, documented enterprise download package for on-device dictation

[https://github.com/microsoft/vscode/issues/335444](https://github.com/microsoft/vscode/issues/335444)

## Summary

Keep open: local-package import exists, but it does not provide the supported, stable model distribution contract requested here. The current documentation still omits a package download link, and the earlier disconnected-install work explicitly left stable distribution unresolved.

## Change summary

Provide a supported first-party CPU dictation-model package with a stable download URL, version and integrity metadata, licensing, allowlisting guidance, and unattended deployment instructions.

## Best solution

Establish a supported distribution and deployment contract for the compatible CPU model, then document its versioned download location, integrity and licensing metadata, required network endpoints, and offline installation procedure. Treat the existing importer and native-runtime CDN as supporting infrastructure, not as completion of model distribution.

- **Behavior:**

  > Administrators can obtain the VS Code-compatible CPU dictation model through a stable, supported first-party HTTPS location without resolving a temporary registry-generated download URL. Published information identifies the package version, supported platforms, integrity hash, licensing, and required network hosts and paths. A documented unattended procedure provisions managed devices so on-device dictation works without access to the model registry. Existing interactive local-package installation remains supported.
- **Trace:**

  > The current voice documentation describes local-package installation but provides no package source. InstallDictationModelAction in src/vs/workbench/contrib/chat/electron-browser/actions/installDictationModelAction.ts requires an interactive picker and delegates to importFoundryLocalModel in src/vs/platform/localTranscription/node/foundryLocalModelImport.ts, which already understands ZIP, OCI, and prepared-directory inputs. LocalTranscriptionService separately provisions the native runtime and calls model.download() when the selected model is not cached. build/dictation-runtime/common.ts publishes native runtime payloads, not model weights; do not conflate those artifacts or replace the existing importer unnecessarily. The earlier implementation summary at https://github.com/microsoft/vscode/issues/328154#issuecomment-5134831056 explicitly identifies the absence of a stable model URL contract. The unresolved boundary is the supported publishing, versioning, and administrator-facing deployment contract, including how the separate runtime is provisioned offline.
- **Open decisions:**
  - Which first-party publishing owner and endpoint will provide a supported, versioned CPU model package, and what compatibility and retention guarantees will administrators receive?
  - Will unattended deployment use a supported cache-preparation procedure or a new noninteractive installation interface, and how will that contract provision the separately required native runtime?
