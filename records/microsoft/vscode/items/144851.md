# Issue #144851 — Align editor find widget with the notebook find widget

[https://github.com/microsoft/vscode/issues/144851](https://github.com/microsoft/vscode/issues/144851)

## Summary

The requested alignment remains missing: editor Find in Selection still sits outside the input, while notebook filters sit inside it. Keep this as the existing design issue; a maintainer explicitly consolidated the later filters-dropdown proposal here.

## Change summary

Align editor find scope controls with the notebook find input to accommodate additional filters.

## Best solution

Give editor search scopes a consistent home alongside the find input options, preserving existing selection-search behavior and keyboard access. Agree whether that home is an inline selection toggle or a filters dropdown before implementation; additional comments/strings search functionality is separate work.

- **Validation:** After agreeing the design, exercise editor Find with and without a selection: activate and deactivate selection scope using mouse and keyboard, verify match bounds and active-state indication, and verify Tab/Shift+Tab navigation with Replace both hidden and visible. Check narrow widget layouts and light, dark, and high-contrast themes against the notebook input arrangement.
- **Behavior:**

  > Editor Find exposes search scope controls in a location consistent with the notebook find input, rather than as an unrelated navigation action. Existing Find in Selection behavior, command access, and automatic-scoping settings remain intact. The scope control must be keyboard accessible, communicate its active state, and remain usable with Replace visible and in narrow layouts. Adding actual comments/strings filtering is not required to complete this placement work.
- **Trace:**

  > FindWidget in src/vs/editor/contrib/find/browser/findWidget.ts appends _toggleSelectionFind to the external find-actions container after the navigation buttons. NotebookFindInput in src/vs/workbench/contrib/notebook/browser/contrib/find/notebookFindReplaceWidget.ts instead appends its filter button to the input controls and accounts for its width in input padding. The shared FindInput in src/vs/base/browser/ui/findinput/findInput.ts already supports additional toggles, but an inline toggle and a dropdown have different user interactions. https://github.com/microsoft/vscode/issues/158598 supplies the dropdown alternative and was explicitly consolidated into https://github.com/microsoft/vscode/issues/144851. Preserve existing searchScope semantics, selection normalization, keybindings, and automatic-scoping settings; do not expand this into syntax-aware search. The unresolved boundary is the intended scope-control interaction, not whether current placement already satisfies the request.
- **Open decisions:**
  - Should editor Find in Selection remain a directly accessible toggle inside the input, or become an entry in an input-level filters dropdown as proposed in the consolidated issue?
