The reported focus inversion would be a core chat/input bug, but the intermittent “use Copilot for a while” reproduction does not identify the trigger or provide enough detail to verify it on current main. Request a focused reproduction before routing or implementation.

## Change summary

After prolonged Copilot use on macOS, clicking the chat input or text editor can leave keyboard input directed to the other surface until the window is restarted.

## Best solution

Determine which chat transition first desynchronizes DOM focus from the clicked editor—such as a question, confirmation, session switch, or completed request—then preserve the user's clicked focus through that transition. A screen recording and minimal sequence leading to the first misdirected keystroke are needed to identify the responsible chat-input path.
