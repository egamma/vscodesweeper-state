## Summary

The error path in `changeLanguage` (line 59 on current main) is unchanged — the throw fires when an extension calls `vscode.languages.setTextDocumentLanguage()` on a URI whose document isn't tracked. The Bicep extension triggers this with its custom `bicep-extsrc:` scheme. No fix or related commit references this issue.

## Change summary

Calling `vscode.languages.setTextDocumentLanguage()` on a Bicep virtual document (`bicep-extsrc:` URI) throws 'document NOT found' because the document isn't in the extension host's document map.

## Best solution

Either the Bicep extension should ensure the document is opened/tracked before calling `changeLanguage`, or the `changeLanguage` API in `extHostLanguages.ts` should handle the missing-document case more gracefully (e.g. re-fetch from `_documents` after the proxy call settles, or surface a clearer error). The `*caused-by-extension` label would be natural but this is a MEMBER-filed telemetry item — a human should decide whether to route to the Bicep team or harden the API.
