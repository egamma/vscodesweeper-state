# Issue #275053 — Agent file editing - missing potential fix

[https://github.com/microsoft/vscode/issues/275053](https://github.com/microsoft/vscode/issues/275053)

## Summary

A real quick-fix gap remains on current main: the diagnostic for an unavailable `github/*` tool reference offers enable/install actions but no action to remove the reference. This team-authored Backlog request should remain open while maintainers settle the removal behavior.

## Change summary

Offer a potential fix that removes an unavailable `github/*` reference from a custom agent's `tools` attribute.

## Best solution

Extend the prompt-file code actions with a removal option for the `MissingGithubMcpServer` diagnostic, preserving valid neighboring tool references and producing a valid header when the reference is the only entry.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptCodeActions.ts`, `src/vs/workbench/contrib/chat/test/browser/promptSyntax/languageProviders/promptCodeActions.test.ts`
- **Validation:** Extend the PromptCodeActionProvider unit suite to assert the chosen removal action and resulting workspace edit for `github/*` both among other tools and as the only tool entry.
- **Behavior:**

  > When an agent file references `github/*` but the GitHub MCP server is unavailable, the available fixes should include a way to remove that unusable reference in addition to enabling or installing the server. Applying the removal must leave syntactically valid frontmatter and preserve every other configured tool. Acceptance must cover both a mixed tools list and a tools attribute containing only `github/*`.
- **Trace:**

  > PromptValidator.validateVSCodeTools in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts emits MissingGithubMcpServer for an unavailable `github/*` reference. PromptCodeActionProvider.getEnableMcpServerCodeActions in src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptCodeActions.ts maps that marker to enable and install commands but creates no text edit. The existing test in src/vs/workbench/contrib/chat/test/browser/promptSyntax/languageProviders/promptCodeActions.test.ts asserts only those two actions. Keep the scope to prompt-file quick fixes: do not alter tool availability detection, MCP installation behavior, or handling of valid references. The uncertainty starts at the user-visible result when removal empties the tools list.
- **Open decisions:**
  - When `github/*` is the only configured tool, should the quick fix remove only the sequence item and leave an empty `tools` value, or remove the entire `tools` attribute?
  - Should removal be offered alongside enable/install for this specific missing-server diagnostic, or generalized to every unnecessary unknown tool reference?

## Evidence

- **diagnostic path:** src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts emits MissingGithubMcpServer specifically when `github/*` is unavailable, marking the reference unnecessary.
