# Issue #193416 — Various providers (and LSP messages) that are passed a position should be passed a range instead.

[https://github.com/microsoft/vscode/issues/193416](https://github.com/microsoft/vscode/issues/193416)

## Summary

Keep open for API design discussion: current provider contracts still cannot convey the requested input range, particularly for calls without an active editor. The concrete C++ use case remains relevant, but selection-aware resolution needs agreement on cross-language consistency and compatibility.

## Change summary

Allow definition, type-definition, and declaration requests to carry an explicit input range through extension APIs and corresponding LSP requests.

## Best solution

Agree on a backward-compatible contract for explicit range context that works for both editor navigation and programmatic requests without an open editor. Resolve how that context affects symbol selection while preserving predictable position-only behavior across languages.
