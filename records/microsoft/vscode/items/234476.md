# Issue #234476 — Settings Defaults gets very confused when updating extensions.

[https://github.com/microsoft/vscode/issues/234476](https://github.com/microsoft/vscode/issues/234476)

## Summary

Still reproducible on main: when an already-activated extension updates, `canRemoveExtension` returns false (because its activation has started), so `_deltaExtensions` skips it in the removal list. The old configuration schema is never unregistered and the new one may not fully register, so the settings editor shows stale data until a full restart.

## Change summary

Settings editor shows stale extension configuration (wrong count of settings) after an extension update until VS Code is fully restarted.

## Best solution

When an extension updates, the configuration extension point contributions need to be refreshed even when the extension was already activated. The fix likely belongs in `src/vs/workbench/services/extensions/common/abstractExtensionService.ts` — the delta path should still re-handle the `configuration` extension point (which is declarative and doesn't require the extension host) even when the extension cannot be fully removed/re-added due to activation state.
