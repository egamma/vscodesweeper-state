# Issue #329693 — Component fixture screenshots render codicons as tofu — harness installs icon content rules but never the codicon @font-face

[https://github.com/microsoft/vscode/issues/329693](https://github.com/microsoft/vscode/issues/329693)

## Summary

Confirmed on current main: the component fixture harness (fixtureUtilsCss.ts) installs only the codicon content-rule stylesheet and never the codicon @font-face, so most fixture screenshots render icons as tofu; this is a real, well-diagnosed test-infra bug, not something to close.

## Change summary

Component fixture harness installs codicon content rules globally but never the codicon @font-face, so ~53 of 63 fixtures render codicons as tofu in screenshot baselines.

## Best solution

Install the @font-face once in the shared harness (fixtureUtilsCss.ts's ensureGlobalStylesInstalled, alongside getIconsStyleSheetCached()) — either by importing codiconStyles.js or adding an explicit @font-face rule in fixtures.css pointing at node_modules/@vscode/codicons/dist/codicon.ttf, which also sidesteps the gitignored .ttf/CI-copy-step disagreement between local and CI renders — then remove the now-redundant per-fixture codiconStyles.js imports and refresh the affected screenshot baselines in one isolated commit.
