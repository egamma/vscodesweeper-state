# Issue #227936 — Closing a terminal that was reopen in a new window doesn't dispose the terminal object

[https://github.com/microsoft/vscode/issues/227936](https://github.com/microsoft/vscode/issues/227936)

## Summary

The missing terminal-close notification after moving a terminal editor is already tracked by an older open issue. Consolidate this report there, preserving the auxiliary-window return-and-close reproduction.

## Change summary

Closing an API-created terminal after moving it through an auxiliary window leaves its extension API object listed without an exit status.

## Best solution

Resolve terminal-editor movement and subsequent close notification together in https://github.com/microsoft/vscode/issues/206735, including this auxiliary-window reproduction. Returning an active terminal to the main window should preserve it, but subsequently terminating it must remove its API object and update its exit status.

Its reproduction specifically describes moving a terminal editor and then closing it without onDidCloseTerminal firing: https://github.com/microsoft/vscode/issues/206735#issuecomment-1978177786 and https://github.com/microsoft/vscode/issues/206735#issuecomment-1988859123. A later independent report confirms the same movement-and-close symptom on macOS: https://github.com/microsoft/vscode/issues/206735#issuecomment-3888950878.
- **Current-source notification loss:** src/vs/workbench/browser/parts/editor/editorGroupView.ts:1471-1508 moves an editor by opening it in the target group and closing it in the source with EditorCloseContext.MOVE. TerminalEditorService's onDidCloseEditor handler in src/vs/workbench/contrib/terminal/browser/terminalEditorService.ts removes the instance without distinguishing a move; _removeInstance disposes its onDisposed forwarding subscription. The onDidVisibleEditorsChange handler can add the moved instance back to instances and _editorInputs, but does not restore those subscriptions.
- **Same reporter-observable failure:** MainThreadTerminalService._onTerminalDisposed in src/vs/workbench/api/browser/mainThreadTerminalService.ts:385-387 sends $acceptTerminalClosed. ExtHostTerminalService.$acceptTerminalClosed in src/vs/workbench/api/common/extHostTerminalService.ts:618-634 removes the terminal from _terminals, sets exitStatus, and fires onDidCloseTerminal. Losing the disposal forwarding subscription therefore explains both the canonical's missing close event and this report's stale terminals array and undefined exit status.
- **Auxiliary-window detail:** src/vs/workbench/browser/parts/editor/auxiliaryEditorPart.ts closes non-confirming editors and merges remaining confirming editors into the main part through mergeGroupsToMainPart. This explains the reported return of a running terminal and uses the same cross-group movement path implicated by the canonical. The distinct auxiliary-window steps should be retained there; they do not establish a separate API-notification defect.
- **Linked extension PR is not a core fix:** https://github.com/espressif/vscode-esp-idf-extension/pull/1289 merged on 2024-09-10 and changes ESP-IDF monitor terminal reuse and extension-side lifecycle handling. It fixes that extension's issue 1132, not VS Code's terminal-editor disposal forwarding, and supplies no fixing commit for this core report.
