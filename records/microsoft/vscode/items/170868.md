Keep open: current source still selects Bash integration by executable name and runs Bash-only code without checking whether the interpreter is BusyBox ash. Three open fix candidates already exist; maintainer review should resolve those before closing this reopened report.

## Change summary

## Evidence

- **Current injection path:** src/vs/platform/terminal/node/terminalEnvironment.ts:getShellIntegrationInjection derives the shell from path.basename(shellLaunchConfig.executable). Its Linux/macOS case 'bash' selects Bash integration without checking interpreter identity; shellIntegrationArgs supplies --init-file and shellIntegration-bash.sh.
- **Current incompatible script:** src/vs/workbench/contrib/terminal/common/scripts/shellIntegration-bash.sh:6–22 has no non-Bash guard before builtin return, array assignments such as vsc_env_keys=(), BASH_VERSINFO indexing, and read -ra with a here-string. A BusyBox ash interpreter entering this script reaches unsupported Bash constructs, matching the reported startup errors.
- **Confirmed scope and workaround:** The discussion on https://github.com/microsoft/vscode/issues/170868 confirms BusyBox lacks builtin and still errors after removing the .bashrc loading and builtin calls. Selecting /bin/ash avoids the problem, but the terminal maintainer explicitly accepted detecting BusyBox before injection or at script entry rather than treating that workaround as completion.
- **Prior partial fix:** https://github.com/microsoft/vscode/pull/170870 merged on 2023-01-09 with merge commit 408fc00570861c120f3f2ad00d6a2c8ec91bfd94 and addressed checking whether .bashrc exists.
