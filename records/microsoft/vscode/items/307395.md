# Issue #307395 — github_repo tool in Copilot Chat does not index .yml files from repositories

[https://github.com/microsoft/vscode/issues/307395](https://github.com/microsoft/vscode/issues/307395)

## Summary

This remains a credible remote-indexing gap: the VS Code client does not exclude YAML and cannot return content absent from the GitHub semantic-search response. Keep it open while the service-side index behavior for `.yml` files is investigated.

## Change summary

Make the Copilot `github_repo` tool retrieve indexed content from YAML files, including GitHub Actions workflows.

## Best solution

The GitHub semantic indexing service should ingest `.yml` files and return matching chunks through the existing embeddings code-search endpoint, with coverage for `.github/workflows/*.yml`; the VS Code client should then consume those results without special-casing YAML.

## Evidence

- **current source path:** `extensions/copilot/src/platform/remoteCodeSearch/common/githubCodeSearchService.ts` sends the query and repository scope to `RequestType.EmbeddingsCodeSearch`; file contents are supplied by the remote response rather than indexed by the tool locally.
- **no YAML exclusion in client:** `parseGithubCodeSearchResponse` in `extensions/copilot/src/platform/remoteCodeSearch/common/githubCodeSearchService.ts` filters returned chunks only through Copilot ignore rules and requested glob patterns; it has no `.yml` or YAML exclusion.
- **local index comparison:** `extensions/copilot/src/platform/workspaceChunkSearch/node/workspaceFileIndex.ts` defines explicit excluded binary/media extensions, but YAML is not excluded, further isolating the report to the remote repository index rather than a general VS Code file-type policy.
- **reported scope:** The reporter observed the same omission with multiple query strategies and repositories while `.tf`, `.tfvars`, and `.md` content remained searchable, which is consistent with a service-side file-type indexing limitation.
