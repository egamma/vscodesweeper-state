# Issue #135531 — SCM - Add description tooltip to automatic source control button

[https://github.com/microsoft/vscode/issues/135531](https://github.com/microsoft/vscode/issues/135531)

## Summary

Keep this accepted SCM request open: current tooltips explain sync's pull/push counts, but publishing still largely repeats the button label and sync does not describe the configured rebase behavior. The request has 23 upvotes, and no verified canonical owns the remaining explanatory work.

## Change summary

Explain what the automatic SCM Publish and Sync buttons will do before the user invokes them.

## Best solution

Provide concise, operation-specific explanations in the built-in Git action-button tooltips, including the effect of publishing and the relevant sync integration mode. Preserve the existing branch names, incoming/outgoing counts, and progress feedback.

## Plan brief

- **Likely files:** `extensions/git/src/actionButton.ts`, `extensions/git/src/repository.ts`, `extensions/git/src/commands.ts`
- **Validation:** In a disposable Git repository, hover Publish Branch before establishing an upstream and confirm it explains publishing rather than only repeating the label. With an upstream configured, exercise incoming-only, outgoing-only, and diverged histories; inspect Sync Changes with git.rebaseWhenSync false and true, confirming the agreed explanations, branch/count details, and unchanged command behavior. These manual acceptance checks were not run during this read-only review.
- **Behavior:**

  > Users should understand the operation offered by the automatic SCM Publish or Sync button before clicking it. Current sync tooltips already expose incoming/outgoing counts, but publishing remains unexplained and the configured rebase mode is not described. Acceptance should cover publishing a branch without an upstream and syncing incoming-only, outgoing-only, and diverged histories with git.rebaseWhenSync both disabled and enabled. Existing action selection, command execution, counts, branch identification, and progress feedback must remain unchanged.
- **Trace:**

  > ActionButton.getPublishBranchActionButton and getSyncChangesActionButton in extensions/git/src/actionButton.ts supply the command tooltips. Sync delegates its text to Repository.syncTooltip in extensions/git/src/repository.ts, which branches on ahead/behind counts and remote read-only state but does not inspect the integration setting. Commands.sync in extensions/git/src/commands.ts reads git.rebaseWhenSync and passes it to _sync. SCMActionButton.setButton in src/vs/workbench/contrib/scm/browser/scmViewPane.ts already renders command.tooltip, so a new tooltip API is not required. Repository.syncTooltip is also consumed by extensions/git/src/statusbar.ts, making shared wording changes observable there as well. Source inspection establishes the content gap, not runtime behavior; the uncertainty is the desired explanatory scope and wording, not whether a tooltip surface exists.
- **Open decisions:**
  - Should the descriptions provide a short plain-language explanation of each operation, or enumerate the Git operations and relevant integration mode?
  - Should the fuller sync explanation also appear in the status-bar tooltip that shares Repository.syncTooltip, or remain specific to the SCM action button?
