# Issue #228009 — Editor goes berserk and start scrolling on mouse movements

[https://github.com/microsoft/vscode/issues/228009](https://github.com/microsoft/vscode/issues/228009)

## Summary

Still present on main. The editor's drag-over handler in codeEditorWidget.ts calls revealPosition on every dragover event, and on KDE/Wayland the drag state can get stuck (no dragend/dragleave/drop fires to clean up), leaving the editor permanently scrolling to follow the mouse with a lingering drop-indicator decoration.

## Change summary

Editor enters an unusable state on KDE/Wayland where it continuously scrolls following the mouse cursor, with a dotted drop-indicator caret visible, because the drag-over state never terminates.

## Best solution

Add a defensive timeout or secondary escape hatch in the DragAndDropObserver or the editor's onDragOver handler so that if no drag-end/drop/leave fires within a reasonable window, the drop indicator is removed and the drag state is reset. The fix likely touches src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts (showDropIndicatorAt / the onDragOver callback) and possibly src/vs/base/browser/dom.ts (DragAndDropObserver). This may also be partially upstream (Electron/Chromium Wayland drag event delivery), but a VS Code-side guard is warranted regardless.
