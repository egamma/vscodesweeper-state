# Issue #228009 — Editor goes berserk and start scrolling on mouse movements

## Summary

The evidence identifies this as a KWin/Wayland drag-and-drop session remaining active after the physical drag ends, rather than a VS Code editor defect. Keep it open as upstream until affected users confirm whether KDE Plasma 6.5's drag-and-drop fixes resolved it.

## Change summary

On KDE Wayland, a stale drag-and-drop state causes mouse movement over the editor to display a dotted insertion marker and continuously scroll the document.

## Best solution

Confirm the behavior on KDE Plasma 6.5 or newer and consolidate the result with the KWin Wayland drag-and-drop report. If it persists, the upstream report needs a current recording and reproducible sequence; VS Code should retain its normal drag-over behavior unless a safe defensive recovery can be established.

## Evidence

- **cross-application evidence:** The reporter observed the same stuck drag state simultaneously in Chrome, Gimp, and KDE's task manager, while every confirmation in this issue identifies KDE/Wayland environments; this rules against a VS Code-only editor state.
- **upstream report:** https://bugs.kde.org/show_bug.cgi?id=498764 is filed against KWin's "Wayland drag-and-drop" component with the matching cross-application behavior. KDE maintainers reported drag-and-drop fixes in Plasma 6.5 and requested confirmation there; the report later auto-closed as WORKSFORME without that confirmation.
- **source trace:** src/vs/editor/browser/widget/codeEditor/codeEditorWidget.ts handles browser `dragover` events by calling `showDropIndicatorAt`, which installs the `dnd-target` decoration and calls `revealPosition`; src/vs/editor/contrib/dnd/browser/dnd.css renders that target as the reported dotted caret. It is removed only after `drop`, `dragleave`, or `dragend`, matching an upstream drag session that never delivers its terminating event.
- **workaround consistency:** Multiple commenters report that initiating another real file or editor-tab drag clears the behavior, consistent with resetting a stale compositor drag-and-drop session rather than changing editor configuration.
