# Issue #15899 — Highlight matching quotes, double quotes and backticks

[https://github.com/microsoft/vscode/issues/15899](https://github.com/microsoft/vscode/issues/15899)

## Summary

Keep open: current bracket matching does not cover matching string quotes or backticks, and the related issues address different capabilities. The request has community support and needs a decision on delimiter-highlighting behavior before implementation.

## Change summary

Highlight matching single quotes, double quotes, and backticks, using an underline to distinguish them from bracket matches.

## Best solution

Provide language-aware matching-delimiter highlighting that handles escaped quotes and template literals without changing structural bracket matching. Decide whether string delimiters should use the existing match decoration or the requested distinct underline.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts`, `src/vs/editor/contrib/bracketMatching/browser/bracketMatching.css`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/tokenizer.ts`, `src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts`, `src/vs/editor/contrib/bracketMatching/test/browser/bracketMatching.test.ts`
- **Validation:** The plan should end with editor tests for matching single quotes, double quotes, and multiline backticks, including escaped delimiters and template interpolation, plus unchanged structural-bracket tests. Manually verify the agreed decoration and cursor activation behavior in JavaScript using 'text', "text", and template literals containing ${...}.
- **Behavior:**

  > Users should be able to identify both delimiters of a quoted string or backtick template literal through matching highlights. Escaped quote characters must not be treated as string boundaries, and interpolation must not confuse the outer backtick pair with structural braces. The requested presentation is an underline distinct from bracket outlines, although the thread explicitly questions that styling. Acceptance should cover all three delimiter types, multiline templates, and unchanged existing bracket highlighting.
- **Trace:**

  > BracketMatchingController._recomputeBrackets in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts delegates matching to model.bracketPairs and renders its returned ranges. JavaScript's language configuration lists quote characters for auto-closing and surrounding only, so those capabilities do not feed matching highlights. Current tree tokenization excludes ordinary string tokens, and BracketTokens stores one token per delimiter text rather than distinguishing the roles of symmetric delimiters. These source observations establish that this is more than a missing decoration rule; the trace does not establish a complete language-aware quote-matching design. Preserve structural bracket matching, auto-closing, wrapping, and their existing performance boundaries. The related requests at https://github.com/microsoft/vscode/issues/38352 and https://github.com/microsoft/vscode/issues/123600 do not absorb this capability.
- **Open decisions:**
  - Should quote and backtick matches use a distinct underline as requested, or the existing bracket-match presentation?
  - Should matching string delimiters activate only next to a delimiter, or also anywhere inside the string when editor.matchBrackets is set to always?
  - Should initial support be limited to languages with reliably identifiable string boundaries, or should the feature promise matching across all language modes?

## Evidence

- **Existing capability does not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.matchBrackets for matching brackets and editor.autoClosingQuotes for inserting closing quotes. In extensions/javascript/javascript-language-configuration.json, single quotes, double quotes, and backticks appear in autoClosingPairs and surroundingPairs, but not in brackets; insertion and wrapping do not provide matching-quote highlighting.
- **Current matching path:** BracketMatchingController._recomputeBrackets in src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts obtains decorations exclusively from model.bracketPairs.matchBracket/findEnclosingBrackets. The bracket-pair tree tokenizer in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/tokenizer.ts searches only tokens classified as StandardTokenType.Other with balanced-bracket metadata; src/vs/editor/common/languages/supports.ts also explicitly excludes string tokens from legacy bracket matching.
- **Symmetric delimiters need distinct handling:** BracketTokens.createFromLanguage in src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts stores opening tokens and then closing tokens in a map keyed by delimiter text. Identical opening and closing characters would share a key, so adding quote pairs to language bracket configuration alone does not establish correct string-delimiter matching.
