# Issue #15899 — Highlight matching quotes, double quotes and backticks

[https://github.com/microsoft/vscode/issues/15899](https://github.com/microsoft/vscode/issues/15899)

## Summary

A real editor gap remains: current bracket matching cannot identify symmetric quote delimiters. The request is already accepted into the Backlog and has no verified canonical duplicate.

## Change summary

Highlight paired single quotes, double quotes, and backticks, optionally with styling distinct from bracket matches.

## Best solution

Extend editor matching to derive string boundaries from language tokenization rather than treating quotes as ordinary brackets, then render a consistent quote-pair decoration in the bracket-matching contribution.

## Evidence

- **current implementation:** src/vs/editor/contrib/bracketMatching/browser/bracketMatching.ts obtains matches exclusively through model.bracketPairs.matchBracket and renders the bracket-match decoration; editor.matchBrackets is documented only as highlighting matching brackets.
- **architectural gap:** src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/brackets.ts stores one Token per delimiter text, with closing tokens overwriting opening tokens when both delimiters are identical. The tokenizer also considers bracket metadata only in StandardTokenType.Other tokens, not string tokens.
- **related request:** https://github.com/microsoft/vscode/issues/230854 requested navigation between matching quotes and was closed by the feature-request upvote process; its discussion independently notes that the bracket-pair algorithm cannot handle identical opening and closing characters. Because it is closed, it cannot be the canonical duplicate.
- **distinct related items:** https://github.com/microsoft/vscode/issues/38352 concerns configurable auto-closing pairs, while https://github.com/microsoft/vscode/issues/123600 concerns asymmetric bracket-border rendering; neither owns quote-pair highlighting.
- **existing workaround:** The issue discussion reports that the suggested Subtle Brackets extension did not accept single- or double-quote pairs, so it does not cover the central request.
