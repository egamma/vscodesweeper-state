# Issue #198287 — Add terminal highlighting support

[https://github.com/microsoft/vscode/issues/198287](https://github.com/microsoft/vscode/issues/198287)

## Summary

Keep this accepted, 24-upvote request open: current terminal search highlighting does not provide automatic, configurable keyword coloring of output. No verified open canonical owns the same request; the earlier decline predates this issue's acceptance into Backlog.

## Change summary

Provide optional MobaXterm-style terminal output highlighting with default keyword patterns and user-configurable regular expressions.

## Best solution

Design an opt-in terminal output highlighting capability that remains independent of terminal Find and preserves normal application-controlled coloring when disabled. Settle its interaction with ANSI colors and the default pattern set before implementation, with explicit rendering-performance limits.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`, `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts`, `src/vs/workbench/contrib/terminal/common/terminalColorRegistry.ts`, `src/vs/workbench/contrib/terminalContrib/find/browser/terminalFindWidget.ts`
- **Validation:** After the design is agreed, emit plain output with printf 'warning: sample [-Wunused-variable]\nordinary output\n' and verify approved default rules highlight only their matches without opening Find. Verify a custom regex on newly arriving output, ANSI-colored output under the agreed precedence, disabling the feature, and independent terminal Find behavior; include a sustained-output performance comparison.
- **Behavior:**

  > Users can optionally highlight recognizable keywords and patterns in terminal output even when the producing program emits no colors. The request includes default patterns and configurable regular expressions, with compiler warnings and filtered logs as representative use cases. Highlighting must work independently of the Find widget and must not change terminal behavior when disabled. Acceptance must cover custom rules, streaming output, the agreed interaction with ANSI colors, and rendering responsiveness.
- **Trace:**

  > XtermTerminal in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts exposes search-addon decorations through findNext/findPrevious and theme-derived find colors. TerminalFindWidget in src/vs/workbench/contrib/terminalContrib/find/browser/terminalFindWidget.ts supplies the search regex and clears decorations on hide, so this existing mechanism does not deliver persistent keyword highlighting. Terminal configuration registrations inspected in src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts contain no matching output-rule setting. The reporter acknowledges application-color interference raised in https://github.com/microsoft/vscode/issues/192671 and requests optional behavior; later Backlog acceptance on https://github.com/microsoft/vscode/issues/198287 establishes demand but does not settle precedence or defaults. Preserve normal ANSI rendering, terminal Find, and disabled-feature performance. The trace establishes the missing capability, not a settled rendering design.
- **Open decisions:**
  - When a configured pattern matches text already colored by the application, should highlighting override that color or apply only to otherwise uncolored output?
  - Which default patterns should be supplied, and should enabling highlighting activate those defaults immediately or require selecting a preset?
