# Issue #196373 — Notebook cell: shift + enter scroll my cell out of view

[https://github.com/microsoft/vscode/issues/196373](https://github.com/microsoft/vscode/issues/196373)

## Summary

Still valid on main: the default for `notebook.scrolling.revealNextCellOnExecute` remains `fullCell`, which scrolls the executing cell out of view when pressing Shift+Enter on a long cell. Team-authored polish request — keeping open.

## Change summary

Shift+Enter in a notebook cell with long content scrolls the executed cell out of view when revealing the next cell, making it impossible to see the output.

## Best solution

Change the default behavior of the execute-and-select-below action so that scroll position remains stable enough for the user to see the output of the executed cell. This could mean changing the default of `notebook.scrolling.revealNextCellOnExecute` to `firstLine` or `none`, or implementing smarter reveal logic in `ExecuteCellSelectBelow` (src/vs/workbench/contrib/notebook/browser/controller/executeActions.ts) that considers whether the executing cell's output area is still visible.
