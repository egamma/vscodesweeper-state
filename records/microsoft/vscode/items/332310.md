# Issue #332310 — File links use Windows paths in non-Local multi-root sessions on Remote WSL

[https://github.com/microsoft/vscode/issues/332310](https://github.com/microsoft/vscode/issues/332310)

## Summary

Detailed, self-consistent bug report (with actual renderer log output showing the ENOPRO failure) about file links rendering as Windows paths and failing to open in non-Local multi-root agent sessions under Remote - WSL; this is a very new/experimental code path (chat.agentHost.copilotAgent.multiRootEnabled) I could not conclusively trace to a single fix location from the checkout, so it needs routing to the agent-sessions/remote owners rather than a close.

## Change summary

In a Remote - WSL multi-root chat session not delegated to Local, file links in chat responses are converted to Windows-style paths (backslashes) and fail to open; an explicit vscode-remote URI with a `+` in the authority (`wsl+ubuntu`) also fails because it gets percent-encoded to `wsl%2Bubuntu`, which no filesystem provider resolves.

## Best solution

Someone with a WSL test environment should trace how file links are constructed/serialized for non-Local multi-root agent sessions (likely in the agentHost session link/path handling and the vscode-remote authority round-trip for `+`-containing authorities like `wsl+ubuntu`) and fix the path-separator/authority-encoding mismatch so links match the Local-delegated behavior.
