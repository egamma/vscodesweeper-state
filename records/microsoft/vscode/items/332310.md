# Issue #332310 — File links use Windows paths in non-Local multi-root sessions on Remote WSL

[https://github.com/microsoft/vscode/issues/332310](https://github.com/microsoft/vscode/issues/332310)

## Summary

Traced a plausible root cause in the agent-host URI plumbing that matches every symptom in the report; this looks like a real, unlabeled bug in the experimental multi-root chat feature and should stay open for a maintainer to confirm and fix.

## Change summary

In a Remote-WSL window, file links produced by a non-Local (ambient) multi-root chat session render with Windows-style backslashes and fail to open, while links from a session explicitly delegated to Local work correctly.

## Best solution

Investigate src/vs/platform/agentHost/common/agentHostUri.ts (`wrapAgentHostUri`) together with src/vs/platform/agentHost/common/agentHostConnectionsService.ts's `AMBIENT_AGENT_HOST_AUTHORITY`/`isAmbient` design: the window's ambient connection is always tagged with the reserved authority string `'local'` even when, per that file's own comment, 'the ambient host is itself remote' (a Remote-WSL window). `wrapAgentHostUri` special-cases `connectionAuthority === 'local'` to leave `file:` URIs unwrapped, which is only safe when the ambient host is genuinely the client machine — for a remote ambient host this produces a bare `file://` URI that the client's label/link rendering appears to treat as a literal local (Windows) path. This needs a maintainer with full context on the ambient/ authority design to fix without breaking the documented invariants in agentHost/AGENTS.md.

## Evidence

- **ambient authority is reused for a remote ambient host:** src/vs/platform/agentHost/common/agentHostConnectionsService.ts:26-33 documents that `AMBIENT_AGENT_HOST_AUTHORITY = 'local'` is used for the window's ambient host 'even when attached to a remote authority ... the ambient host is itself remote'.
- **wrap bypass for 'local' authority:** src/vs/platform/agentHost/common/agentHostUri.ts:108-111 `wrapAgentHostUri` returns the original `file:` URI unwrapped whenever `connectionAuthority === 'local'`, without distinguishing a genuinely local ambient host from a remote one carrying the same reserved string.
- **only 'local' gets a native-OS label formatter:** src/vs/workbench/services/agentHost/common/agentHostFileSystemService.ts:53-56 registers a Windows-aware label formatter (backslashes) only for the reserved `LOCAL_AGENT_HOST_AUTHORITY`, using the client process's `OS`; every other/unknown authority uses the lossless '/' fallback (`AGENT_HOST_LABEL_FORMATTER`), consistent with only the ambient-labeled links showing backslashes.
- **connectionAuthority usage confirms the overload:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostCustomizationService.ts:574 and other call sites pass `AMBIENT_AGENT_HOST_AUTHORITY` as the `connectionAuthority` for the window's default/ambient chat, which is the same code path that builds markdown file links (`rewriteLinkTokenRaw` / `toAgentHostUri` in stateToProgressAdapter.ts).
- **second independent report:** A second commenter (osczha01) reports the identical backslash-conversion symptom against a remote Linux workspace over SSH, suggesting the defect is not WSL-specific but applies to any remote ambient agent host.
