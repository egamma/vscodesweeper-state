# Issue #332617 — Notebook markdown renderer emits duplicate heading ids

[https://github.com/microsoft/vscode/issues/332617](https://github.com/microsoft/vscode/issues/332617)

## Summary

Confirmed in the current source: addNamedHeaderRendering only records the base slug in slugCounter, never the generated `-N` id, so a later duplicate can reuse an already-emitted suffixed id. An open PR already fixes this, so it should stay open for that PR to land rather than being closed now.

## Change summary

Notebook markdown heading id generation can emit the same `-N` suffixed id twice when duplicate headings interleave with an already-suffixed title, breaking anchor-link scrolling.

## Best solution

Land https://github.com/microsoft/vscode/pull/332627 ("Notebook renderer: make heading slug dedupe collision free"), which appears to address exactly this collision in extensions/markdown-language-features/notebook/index.ts's addNamedHeaderRendering; close the issue once that PR merges.

## Evidence

- **source trace:** extensions/markdown-language-features/notebook/index.ts lines 355-385: slugCounter.set(slug, 0) only ever registers the base slug key; the generated `slugify(slug + '-' + (count+1))` id is never added to slugCounter, so a subsequent duplicate of the base title can regenerate and reuse that same suffixed id.
- **repro trace:** For titles Foo, Foo-1, Foo: 1st -> id=foo (registers 'foo'); 2nd (title 'Foo-1') -> slug='foo-1', not in map, registers 'foo-1' as its own base key with count 0; 3rd (title 'Foo') -> 'foo' count bumped to 1, emits 'foo-1' again, colliding with the 2nd heading's id.
