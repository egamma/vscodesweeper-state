# Issue #287518 — VS Code crashes with Open File in a Snap installation due to missing `'user-home-symbolic-ltr` icon

[https://github.com/microsoft/vscode/issues/287518](https://github.com/microsoft/vscode/issues/287518)

## Summary

Keep open in the Snap area: the report and independent confirmation establish a GTK image-loading crash specific to the packaged environment. No verified fix or older canonical covering this exact file-chooser failure was found.

## Change summary

Opening a native file or folder chooser in the Snap installation aborts VS Code when GTK cannot decode its fallback icon.

## Best solution

Ensure the Snap's GTK libraries, pixbuf loaders, and generated loader cache work together so native file choosers open without terminating VS Code. Diagnose the packaged runtime on affected Ubuntu versions before assuming an icon installation or Snap base upgrade resolves it.

## Evidence

- **reported trigger:** https://github.com/microsoft/vscode/issues/287518 reports File > Open File and File > Open Folder aborting in VS Code 1.108.0 on Ubuntu 24.04.3 with extensions disabled; the .deb installation works. GTK fails to decode its fallback image with gdk-pixbuf-error-quark code 3, so the missing home icon alone does not establish the root cause.
- **independent confirmation:** https://github.com/microsoft/vscode/issues/287518#issuecomment-3764854847 confirms the same GTK ensure_surface_for_gicon abort on a fresh Ubuntu 25.10 installation during an extension sign-in action. The fallback PNG exists and is identified as valid by file; switching to the .deb avoids the crash. This corroborates the image-loading failure, although the trigger differs.
- **current packaging path:** resources/linux/snap/snapcraft.yaml still uses base: core20, stages libgtk-3-0, excludes usr/share/icons, and launches through electron-launch. resources/linux/snap/electron-launch overrides GDK_PIXBUF_MODULE_FILE and GDK_PIXBUF_MODULEDIR and generates a cache using the packaged gdk-pixbuf-query-loaders. These are concrete diagnostic surfaces, not conclusive proof of which library or loader fails.
