# Issue #333979 — Copilot Agent Mode does not respect terminal.integrated.defaultProfile.linux environment

[https://github.com/microsoft/vscode/issues/333979](https://github.com/microsoft/vscode/issues/333979)

## Summary

Plausible and traceable: the agent-host terminal shell resolution in agentHostTerminalContribution.ts only forwards the resolved profile's executable path, dropping its args/env — which would explain why a custom profile that wraps commands (e.g. `apptainer exec <image> bash -lc "..."`) isn't respected by Copilot Agent Mode even though the integrated terminal (which uses the full profile) works correctly. Not certain this is exactly the code path the reporter hit, so this needs a maintainer look rather than a close.

## Change summary

Copilot Agent Mode executes commands outside the container/environment configured via terminal.integrated.defaultProfile.linux, even though the regular integrated terminal correctly launches into it.

## Best solution

In src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostTerminalContribution.ts, `_resolveDefaultShell()` resolves a full `ITerminalProfile` via `getDefaultProfile({ allowAgentHostShell: true })` but only returns `profile.path`, discarding `profile.args`/env — a maintainer should confirm whether Copilot Agent Mode in this scenario goes through the agent-host runtime, and if so extend the forwarded config to include args/env so wrapped-shell profiles (containers, apptainer, etc.) are honored end-to-end.
