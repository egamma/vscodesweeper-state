# Issue #333979 — Copilot Agent Mode does not respect terminal.integrated.defaultProfile.linux environment

[https://github.com/microsoft/vscode/issues/333979](https://github.com/microsoft/vscode/issues/333979)

## Summary

This is by design: the run-in-terminal tool intentionally resolves its own profile rather than inheriting `terminal.integrated.defaultProfile.linux`, and there's already a dedicated, supported setting for exactly the workaround the reporter is asking for.

## Change summary

Copilot Agent Mode's run-in-terminal tool doesn't inherit the environment set up by the configured `terminal.integrated.defaultProfile.linux` terminal profile (e.g. an Apptainer container shell).

## Best solution

Point the reporter at `chat.tools.terminal.terminalProfile.linux` (and the macOS/Windows equivalents), which lets them set a `path`/`args`/`env` specifically for the chat agent's terminal tool — e.g. wrapping the shell in `apptainer exec <image.sif> bash -lc` — independent of the regular integrated-terminal default profile.

  > Thanks for the detailed report. This is intentional rather than a bug: the run-in-terminal tool used by Agent Mode resolves its own shell profile rather than always inheriting `terminal.integrated.defaultProfile.linux`, so it won't automatically pick up a custom profile like an Apptainer-wrapped shell.
  > 
  > There is already a supported way to configure this independently: set `chat.tools.terminal.terminalProfile.linux` (and the `.osx`/`.windows` variants) to a profile with `path`, `args`, and `env` for the chat agent's terminal tool specifically — for example pointing `path`/`args` at a wrapper that runs `apptainer exec <image.sif> bash -lc "..."`. That lets you control the environment Agent Mode's terminal commands run in without needing it to fall back to your interactive default profile.

## Evidence

- **tool profile resolution:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/browser/tools/runInTerminalTool.ts `getCopilotProfile()` (~line 3502) checks `_getChatTerminalProfile(os)` first, then falls back to `terminalProfileResolverService.getDefaultProfile(...)` — it does not pass any option that forces `terminal.integrated.defaultProfile.linux` to be honored verbatim.
- **dedicated setting exists:** src/vs/workbench/contrib/terminalContrib/chatAgentTools/common/terminalChatAgentToolsConfiguration.ts defines `chat.tools.terminal.terminalProfile.linux/osx/windows` (enum in the same file, line 45: `TerminalProfileLinux = 'chat.tools.terminal.terminalProfile.linux'`), described as "The terminal profile to use on Linux for chat agent's run in terminal tool", accepting `path`, `args`, and `env` via `terminalProfileBaseProperties` (src/vs/platform/terminal/common/terminalPlatformConfiguration.ts, line 36) — this is exactly the 'supported mechanism to specify the shell/environment' the reporter asks for.
- **related agent-host setting:** There's also `terminal.integrated.agentHostProfile.<os>` (src/vs/platform/terminal/common/terminalPlatformConfiguration.ts, ~line 173) used when `allowAgentHostShell` is set, explicitly for 'shells launched by AI agent tools', which falls back to `defaultProfile` only if unset — reinforcing that agent shell resolution is deliberately decoupled from the interactive-terminal default profile.
