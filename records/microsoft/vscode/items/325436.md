# Issue #325436 — BYOK custom endpoint (Responses API) sends truncated input to servers that do not store responses

[https://github.com/microsoft/vscode/issues/325436](https://github.com/microsoft/vscode/issues/325436)

## Summary

Confirmed on main: BYOK Responses API records a stateful marker unconditionally and only later strips a non-resp_ previous_response_id, so truncation and chaining decisions disagree for servers that don't persist responses. A well-scoped fix PR (#325437) already exists and cites this exact issue, so it should be reviewed/landed rather than closed now.

## Change summary

BYOK custom endpoints using the Responses API against a server that doesn't store responses send truncated, unanswerable follow-up requests because the stateful marker is recorded regardless of the server's `store: false`.

## Best solution

Review and merge https://github.com/microsoft/vscode/pull/325437, which makes `OpenAIResponsesProcessor` skip emitting the stateful marker when `response.store === false` and validates the marker shape before truncation in the BYOK Responses branch of `OpenAIEndpoint.createRequestBody`.

## Evidence

- **unconditional marker emission:** extensions/copilot/src/platform/endpoint/node/responsesApi.ts:1340-1344 — the `response.completed` handler calls `onProgress({ statefulMarker: chunk.response.id, ... })` with no check on `chunk.response.store`, so a `store: false` response still records a marker.
- **truncation happens before the resp_ guard:** extensions/copilot/src/extension/byok/node/openAIEndpoint.ts:264-282 — `super.createRequestBody(options)` (which internally truncates `messages` to post-marker items via `rawMessagesToResponseAPI` in responsesApi.ts:365-368) runs first; only afterward does the code strip `body.previous_response_id` when it doesn't start with `resp_` (line 279-282), leaving the input truncated with no `previous_response_id` to chain from.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/325437 ("Fixes #325436") implements exactly this: skip marker emission on `store: false`, and validate marker shape before body construction so truncation and previous_response_id agree.
- **not yet merged:** git log on extensions/copilot/src/platform/endpoint/node/responsesApi.ts shows the tip commit is unrelated (Markdown code block editor API version bump); the fix is not on main yet.
- **additional confirmation:** Comment from jamesliu69 reports the same 400 invalid_prompt failure pattern with a BYOK Responses-API custom endpoint, consistent with the same root cause.
