- **Remaining persistence mismatch:** extensions/copilot/src/platform/endpoint/node/responsesApi.ts:1483-1486 emits a statefulMarker according to canResumeResponses(chunk.response.id), without checking chunk.response.store. OpenAIEndpoint.canResumeResponses in extensions/copilot/src/extension/byok/node/openAIEndpoint.ts:285-289 checks zeroDataRetentionEnabled, supportsStatefulResponses, and the resp_ prefix, but not the server's declared persistence. A store:false response with a resp_ ID can therefore still become a chaining marker.
- **History truncation path:** extensions/copilot/src/platform/endpoint/node/responsesApi.ts:333-339 resolves a saved marker into previousResponseId and markerIndex; the serialization path at lines 381-385 then slices messages after that marker. This relies on retained server state to supply the omitted conversation.
- **Original foreign-ID path has changed:** Current OpenAIEndpoint.canResumeResponses rejects non-resp_ response IDs, and OpenAIEndpoint.createRequestBody at extensions/copilot/src/extension/byok/node/openAIEndpoint.ts:299-303 rebuilds the body with ignoreStatefulMarker:true when an existing foreign marker is encountered. These safeguards address the original report's non-resp_ trigger, but do not establish that its broader store:false handling is completed.

Its zeroDataRetentionEnabled:true workaround question is consistent with current code disabling marker emission and chaining under that configuration.
