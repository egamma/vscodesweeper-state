# Issue #325436 — BYOK custom endpoint (Responses API) sends truncated input to servers that do not store responses

[https://github.com/microsoft/vscode/issues/325436](https://github.com/microsoft/vscode/issues/325436)

## Summary

Confirmed via source: the stateful marker is emitted unconditionally on `response.completed` (line 1352 of responsesApi.ts) without checking whether the server honored `store`, and the BYOK endpoint strips the non-`resp_` `previous_response_id` (line 263 of openAIEndpoint.ts) only after input was already truncated to post-marker items (line 364 of responsesApi.ts). An open PR (#325437) addresses this — keeping open for that PR to land.

## Change summary

BYOK Responses API against a stateless server unconditionally records a stateful marker, causing the next turn's input to be truncated and then the chaining id stripped, resulting in a malformed request.

## Best solution

Land https://github.com/microsoft/vscode/pull/325437, which should condition the stateful-marker emission on the response's `store` field and reconcile the truncation/stripping order so they agree. The fix touches `extensions/copilot/src/platform/endpoint/node/responsesApi.ts` (marker emission) and likely `extensions/copilot/src/extension/byok/node/openAIEndpoint.ts` (strip-after-truncation ordering).

## Evidence
