# Issue #199416 — Nope emoji in quotes breaks cursor position 

[https://github.com/microsoft/vscode/issues/199416](https://github.com/microsoft/vscode/issues/199416)

## Summary

Still reproduces on main: the editor's column model assigns a fixed width (2 columns) to ZWJ emoji sequences via `CursorColumns._nextVisibleColumn`, but the browser-rendered width can differ, causing cursor misalignment. No fix commit references this issue.

## Change summary

Cursor position becomes misaligned when a line contains the 🙅‍♂️ ZWJ emoji sequence, because the computed column width does not match the rendered glyph width.

## Best solution

The cursor positioning code in `src/vs/editor/common/core/cursorColumns.ts` (`_nextVisibleColumn`) needs to account for the actual rendered width of multi-codepoint ZWJ emoji sequences rather than using a fixed 2-column assumption based on the first code point. This likely requires measuring rendered glyph widths for complex emoji, possibly leveraging the font measurement infrastructure in `src/vs/editor/browser/config/charWidthReader.ts`.
