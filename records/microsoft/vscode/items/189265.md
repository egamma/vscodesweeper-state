# Issue #189265 — VsCode does not recognise the "U" key ("unknown" key in shortcut)

[https://github.com/microsoft/vscode/issues/189265](https://github.com/microsoft/vscode/issues/189265)

## Summary

This is a well-documented upstream issue: on Linux, Ctrl+Shift+U is intercepted by the GTK/IBus input method for Unicode character entry before the key event reaches Electron/VS Code, causing the key to appear as 'unknown'. This has been tracked and closed as upstream/mitigated across multiple issues (#48480, #56473, #117966, #121266). Requesting info on whether the known IBus workaround resolves it and whether it persists on the latest build.

## Change summary

Ctrl+Shift+U shows as 'ctrl+shift+unknown' in the keybinding recorder on Linux because GTK/IBus intercepts the key combination for Unicode character input.

## Best solution

This is a platform-level issue owned by GTK/IBus, not VS Code. The established workaround is to disable the Unicode input shortcut in IBus settings (`ibus-setup` → Emoji tab → delete the shortcut) or set `GTK_IM_MODULE=ibus` before launching VS Code. If the reporter confirms the workaround resolves it, this can be closed as upstream/not-reproducible.

## Evidence

- **upstream root cause:** Ctrl+Shift+U on Linux is consumed by GTK's built-in Unicode input method (GtkIMContextSimple) before Electron receives the key event. This is documented at https://unix.stackexchange.com/questions/394655/ctrlshifte-causes-beeping/394767
- **prior closures:** This exact problem has been filed and closed as upstream/mitigated multiple times: https://github.com/microsoft/vscode/issues/48480 ('[mitigated] Linux: Ctrl+Shift+E cannot be used as keybinding anymore'), https://github.com/microsoft/vscode/issues/56473, https://github.com/microsoft/vscode/issues/117966, https://github.com/microsoft/vscode/issues/121266 — all closed as upstream or duplicate of upstream.
- **known workaround:** Disabling the Unicode input shortcut in IBus settings (ibus-setup → Emoji tab → delete shortcut) or launching with GTK_IM_MODULE=ibus resolves the issue, as confirmed by multiple reporters in the prior issues.
- **second commenter different scenario:** The comment from Mat1212fr describes a different issue (AZERTY keyboard on github.dev in Firefox with keyCode 0) — a browser-level key handling problem, not the same Linux GTK/IBus interception.
