# Issue #324758 — Native EditContext: focusing the editor scrolls natively-scrolling ancestors (missing the textarea path's scroll-preservation guard)

[https://github.com/microsoft/vscode/issues/324758](https://github.com/microsoft/vscode/issues/324758)

## Summary

Keep open while the existing fix PR is reviewed: current main still focuses the native EditContext node without preserving ancestor scroll positions. The discussion includes an independent workbench reproduction with an EditContext on/off comparison, extending the original Monaco embedder report.

## Change summary

Focusing an unfocused native EditContext editor can jump ancestor scroll positions and place the cursor on a different line than the one clicked.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/324763 after checking scroll preservation and clicked-line accuracy in the supplied Chromium harness. Also verify the reported side-by-side workbench case rather than assuming the impact is limited to embedders.

## Evidence

- **Current source:** src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts:372-373 delegates NativeEditContext.focus() to FocusTracker.focus(). In nativeEditContextUtils.ts:63-66, that method still calls this._domNode.focus() and refreshFocusState() without preventScroll or ancestor scroll preservation.
- **Existing textarea behavior:** src/vs/editor/browser/controller/editContext/textArea/textAreaEditContextInput.ts:784-791 explicitly saves parent scroll positions before textarea focus and selection changes and restores them afterward. src/vs/base/browser/dom.ts:1318-1334 supplies the shared saveParentsScrollTop and restoreParentsScrollTop helpers.
- **Confirmed reproduction:** https://github.com/microsoft/vscode/issues/324758 provides a complete Chromium/Monaco 0.55.1 harness measuring ancestor scrollTop changing from 400 to 0 with EditContext, versus remaining at 400 with the textarea path. The September 16 comment independently reports the scroll jump and incorrect clicked line in VS Code 1.137.0 on macOS when returning focus to a visible side-by-side editor; disabling editor.editContext and reloading removes the failure. No runtime reproduction was performed during this read-only review.
