# Issue #331892 — Add a customer-facing toggle to enable Fast mode models

[https://github.com/microsoft/vscode/issues/331892](https://github.com/microsoft/vscode/issues/331892)

## Summary

Keep open as a team-authored feature request with an unresolved service contract and UX decision. Current main can select fast variants already returned by the provider, but it cannot let an eligible customer enable unavailable fast models.

## Change summary

Let eligible customers enable Fast mode from the model picker, with credit disclosure, eligibility feedback, immediate refresh, synchronization, and accessible interaction.

## Best solution

Expose model-level Fast mode eligibility and enablement through the Copilot provider contract, then present an accessible control in each applicable model's picker details. Successful enablement should refresh the provider's model catalogue immediately, while failures and ineligibility leave the displayed state accurate and explain the reason.

- **Behavior:**

  > An eligible signed-in customer can discover and enable Fast mode from the model picker after seeing its usage-credit implications, then use the newly available fast model without restarting or signing out. The control accurately reflects service-provided state after reload and subsequent provider refreshes; ineligible users receive a clear disabled reason. Keyboard operation and screen-reader labeling must expose the same state and outcome. A failed enablement must surface an actionable error and leave the UI consistent with the service.
- **Trace:**

  > Current main recognizes separate standard and `-fast` model IDs in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerVariants.ts, collapses each pair into one row, and renders Standard/Fast choices through ModelPickerCard._renderSpeedSection. This only works after both models have been returned by the provider; ILanguageModelChatMetadata in src/vs/workbench/contrib/chat/common/languageModels.ts carries no Fast eligibility or enablement contract. ModelMetadataFetcher refreshes the server catalogue and LanguageModelAccess republishes it, which is the relevant post-enablement refresh path. The maintainer discussion at https://github.com/microsoft/vscode/issues/331892#issuecomment-5370935650 establishes that backend availability is model-level, but does not settle whether the picker should expose one global control or controls attached to applicable models. Preserve ordinary model selection, speed-pair collapsing, BYOK providers, and Auto mode behavior; the boundary is Copilot Fast eligibility and enablement.
- **Open decisions:**
  - Should customers enable Fast mode once at the Copilot provider level, with unsupported models visibly excluded, or independently on each applicable model as implied by the model-level backend contract?
