# Issue #115150 — Adjust cell diff editor height based on viewport size

[https://github.com/microsoft/vscode/issues/115150](https://github.com/microsoft/vscode/issues/115150)

## Summary

The notebook diff view still sizes source editors from their full content and caps raw-output editors at a fixed 1440px rather than the viewport. The newer multi-diff infrastructure provides relevant prior art, but its existence does not establish that the reported rich notebook diff path is fixed.

## Change summary

Make embedded notebook diff editor rendering viewport-aware to avoid oversized Monaco instances and inaccessible nested scrollbars.

## Best solution

Bring viewport-aware rendering and coordinated scrolling to the notebook diff view while preserving access to all source and output content. Assess the existing multi-diff implementation before designing a separate solution for the rich notebook diff path.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/diff/diffComponents.ts`, `src/vs/workbench/contrib/notebook/browser/diff/diffElementViewModel.ts`, `src/vs/workbench/contrib/notebook/browser/diff/notebookDiffEditor.ts`, `src/vs/workbench/contrib/notebook/browser/diff/notebookDiffList.ts`, `src/vs/editor/browser/widget/multiDiffEditor/compressedVirtualizedScrollLayout.ts`, `src/vs/editor/browser/widget/multiDiffEditor/diffEditorItemTemplate.ts`
- **Validation:** Compare two notebooks containing a long changed cell and large changed JSON output in the rich notebook diff view. Expand source and raw output, resize the viewport below 1440px, and scroll through both. Check that embedded editor rendering is bounded by the viewport, every line remains reachable, selection/editing stays responsive, and scrolling does not introduce an inaccessible nested scrollbar; repeat after enlarging the window and collapsing/re-expanding sections.
- **Behavior:**

  > Large source and raw-output sections in a notebook diff should not require rendering a Monaco editor taller than the visible notebook viewport. All content must remain reachable through coherent scrolling, including after resizing the window. Selection, editing, output folding, and rich-output rendering must retain their existing behavior. Establish a current performance baseline and verify the same scenario after the change.
- **Trace:**

  > The original report came from rich notebook output testing in https://github.com/microsoft/vscode/issues/114969. In diffComponents.ts, source DiffEditorWidgets adopt their full content height, while raw-output editors pass content height through the fixed 1440px cap in DiffElementViewModel.rawOutputHeight. The multi-diff editor already separates full logical content height from viewport-capped rendering and editor-local scrolling; NotebookMultiTextDiffEditor uses that infrastructure on a separately selected path. The remaining uncertainty is how equivalent rendering integrates with the rich notebook diff list, section offsets, and outer scrolling without changing content reachability. Preserve rich outputs, folding, diff alignment, and selection semantics; a smaller constant alone does not satisfy the report.
