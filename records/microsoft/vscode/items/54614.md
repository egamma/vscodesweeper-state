# Issue #54614 — Rectangle commands for large file editing

[https://github.com/microsoft/vscode/issues/54614](https://github.com/microsoft/vscode/issues/54614)

## Summary

A real scalability gap remains: the configurable cursor limit helps files up to 100,000 selections, but current column selection still creates one cursor per line. Keep this Backlog request open for a decision on scalable rectangular editing.

## Change summary

Add rectangle-based editing commands that can modify very large line ranges without creating a cursor for every line.

## Best solution

Represent rectangular edits as range operations rather than materialized per-line cursors, while preserving existing column-selection behavior. Coordinate the interaction design with https://github.com/microsoft/vscode/issues/5402 without treating that UX-focused request as a full replacement for this scalability work.

## Evidence

- **current implementation:** src/vs/editor/common/cursor/cursorColumnSelection.ts constructs a SingleCursorState for each selected line, so rectangular selection remains proportional to line count.
- **remaining limit:** src/vs/editor/common/config/editorOptions.ts defines editor.multiCursorLimit with a maximum of 100,000, and src/vs/editor/common/cursor/cursor.ts truncates generated states to that configured limit.
- **partial existing capability:** Commit https://github.com/microsoft/vscode/commit/b954f5061a4cc3b2e23d3d9b1b0179b2105d1aac added editor.multiCursorLimit and shipped in 1.74.0, resolving the original fixed 10,000 ceiling only within the new 100,000 maximum.
- **related request:** https://github.com/microsoft/vscode/issues/5402 remains open and covers column-selection interaction and virtual whitespace, but not editing arbitrarily large rectangles without per-line cursors.
