# Issue #335815 — Transient window always resets the setting to true

[https://github.com/microsoft/vscode/issues/335815](https://github.com/microsoft/vscode/issues/335815)

## Summary

Team-authored report where the reporter already suspects as-designed behavior, and the code confirms it: --transient always mints a brand-new user-data-dir (src/vs/code/node/cli.ts lines 247-261), so the APPLICATION-scoped sessions.useWorktree setting (default true, src/vs/sessions/contrib/sessions/browser/sessions.contribution.ts:115-124) can never persist across transient launches. Since this is a team-authored issue, an *as-designed judgment close isn't available without an explicit maintainer decision — keeping it open for that call.

## Change summary

In a --transient Agents window, the 'New Worktree' checkbox always shows checked (true) regardless of the user's sessions.useWorktree setting, because --transient always uses a fresh temp user-data-dir.

## Best solution

A maintainer should decide whether this is accepted as-designed (transient windows intentionally ignore persisted user settings) and document it, or whether transient windows should still read the user-level sessions.useWorktree value from the real user-data-dir before falling back to a fresh temp profile for everything else — the relevant code is src/vs/code/node/cli.ts (--transient handling) and src/vs/sessions/contrib/sessions/browser/sessions.contribution.ts (the setting registration).
