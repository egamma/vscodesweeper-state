# Issue #262313 — Copilot Chat checkpoint restore intermittently fails - data loss risk

[https://github.com/microsoft/vscode/issues/262313](https://github.com/microsoft/vscode/issues/262313)

## Summary

Keep open: current main still has a source-confirmed partial-restore failure mode, and several independent reports describe failed, incomplete, or over-broad restores with potential loss of unrelated work. The narrower related reports do not absorb this older, broader reliability issue.

## Change summary

Copilot Chat checkpoint restoration can fail silently, restore only part of a multi-file checkpoint, or revert unrelated work.

## Best solution

Make checkpoint restoration failure-safe across the complete affected file set: either complete the restore or preserve/recover the pre-restore state, while presenting a clear per-file failure result and retry or recovery path. Cover long, multi-request sessions and mixed create, delete, rename, text, and notebook operations with failure-injection tests.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCheckpointTimelineImpl.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingCheckpointTimeline.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingActions.test.ts`
- **Validation:** Add failure-injection tests where a later operation in a multi-file restore throws; verify the workspace is not left in an undocumented partial state, the timeline remains consistent, and the user receives the selected recovery result. Retain successful round-trip coverage for text, notebook, create, delete, and rename operations.
- **Behavior:**

  > Restoring a Copilot Chat checkpoint must produce a deterministic result across every affected file. A failure must not silently leave the workspace partially restored or discard unrelated user work; the user must receive a clear outcome and a usable recovery or retry path. Acceptance includes multi-request, multi-folder sessions and failures occurring after one or more files have already been processed.
- **Trace:**

  > The restore command flows through restoreSnapshotWithConfirmationByRequestId in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts, ChatEditingSession.restoreSnapshot, and ChatEditingCheckpointTimelineImpl.navigateToCheckpoint. _applyFileSystemOperations mutates files sequentially, then _reconstructAllFileContents applies reconstructed contents in parallel; either phase can reject after earlier mutations have completed, with no rollback transaction. The action path has no local user-facing handling for that partial outcome. Existing tests cover successful timeline navigation extensively but do not inject a delegate failure midway through a multi-file restore. Preserve intentional checkpoint semantics and explicit removal warnings; the boundary is failure atomicity, state consistency, diagnostics, and recovery rather than replacing checkpoint storage with Git.
- **Open decisions:**
  - If any file cannot be restored, should VS Code return every already-processed file to its pre-restore state, or retain successful restorations and present a per-file partial result with retry controls?

## Evidence

- **current source failure mode:** On current main, ChatEditingCheckpointTimelineImpl._applyFileSystemOperations in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCheckpointTimelineImpl.ts applies file operations sequentially. If a later delegate operation or reconstruction throws, earlier filesystem mutations remain applied, _navigateToEpoch does not update the epoch, and there is no rollback transaction.
- **silent action path:** restoreSnapshotWithConfirmationByRequestId in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingActions.ts awaits session.restoreSnapshot directly without local error handling or a user-facing partial-restore result. ChatEditingSession.restoreSnapshot in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts likewise delegates directly to timeline navigation.
- **independent impact reports:** Multiple commenters report never-successful restores, unexpected reversion of unrelated files, and lost work; https://github.com/microsoft/vscode/issues/262313#issuecomment-3534373549 specifically describes unrelated files being reverted.
- **related reproducible case:** https://github.com/microsoft/vscode/issues/276353 is a younger, narrower report with a screen recording showing that a multi-request restore reverted only one of two files. It supports the failure class but does not absorb this issue's broader intermittent, silent, and unrelated-file symptoms.
- **canonical search:** https://github.com/microsoft/vscode/issues/293377 concerns restore actions that leave chat history unchanged, while https://github.com/microsoft/vscode/issues/320828 is tied to a specific Codebase-permission/history-corruption trigger.
