# Issue #348170 — Terminal of Agent is not avaialble anymore

[https://github.com/microsoft/vscode/issues/348170](https://github.com/microsoft/vscode/issues/348170)

## Summary

Keep open: current source deliberately renders native SDK shell commands as output-only chat content, so restoring interactive access requires a product decision rather than a terminal-revival guard. Existing output viewing and an experimental terminal override do not fully cover the requested default experience.

## Change summary

Restore user control over agent-run commands, including interruption, live output inspection, and access to the same shell context.

## Best solution

Provide a discoverable way to inspect and interrupt agent commands, with an explicitly supported interactive handoff where the execution backend permits it. Decide how that handoff preserves the agent's actual shell context without changing execution permissions or sandbox guarantees.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts`, `src/vs/workbench/contrib/terminal/browser/agentHostTerminalService.ts`, `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`
- **Validation:** On macOS with the default Copilot SDK shell path, run a command that emits stdout and stderr periodically and then waits. Verify live output remains inspectable and the agreed interruption control stops that command; if interactive handoff is supported, verify commands execute in the same shell context after it changes directory and exports a variable. Confirm existing PTY terminals and execution permissions remain unchanged.
- **Behavior:**

  > Agent-run commands must have discoverable output inspection and interruption controls. The reporter also wants to enter the same shell to inspect or adjust its working directory and environment, rather than use an unrelated terminal. Acceptance must distinguish native output-only commands from interactive PTY commands and verify the supported handoff behavior without silently substituting a fresh shell.
- **Trace:**

  > AgentHostSessionHandler._reviveTerminalIfNeeded branches on terminalContent.isPty: native non-PTY content attaches AgentHostOutputChannel, while PTY content revives a terminal instance. ChatTerminalToolProgressPart._ensureTerminalInstance and focusTerminal intentionally reject non-PTY content, explaining why ordinary terminal reveal cannot restore this access. Live output and read-only full-output viewing already exist. CopilotSessionLauncher can install a host shell override through chat.agentHost.customTerminalTool.enabled, but that experimental alternative does not prove attachment to the reporter's native SDK shell. Preserve existing PTY behavior, permission enforcement, and the distinction between captured output and an interactive process. The remaining uncertainty is the supported user-facing interruption and handoff contract, not where to place a guard.
- **Open decisions:**
  - Should default native SDK commands support interactive access to their existing shell, or remain output-only with explicit interruption and context-inspection controls?
  - Should interrupting an individual command preserve the running agent turn, or cancel the turn as well?
