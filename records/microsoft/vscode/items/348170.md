# Issue #348170 — Terminal of Agent is not avaialble anymore

[https://github.com/microsoft/vscode/issues/348170](https://github.com/microsoft/vscode/issues/348170)

## Summary

Keep open for interactive-terminal parity in the Agent Host experience. Current source explicitly distinguishes interactive terminals from output-only commands; existing reveal controls do not cover the latter.

## Change summary

Restore shared access to agent terminals so users can inspect output, interrupt commands, complete interactive authentication, and continue in the same shell environment.

## Best solution

Provide a discoverable way to inspect and take over supported agent command sessions, including interruption and interactive input. Establish the intended shell-state continuity contract across commands rather than treating output expansion alone as sufficient.

- **Behavior:**

Acceptance includes inspecting ongoing output, interrupting a stuck command, and completing a command that waits for interactive input. The agreed behavior must explain whether subsequent manual and agent commands share cwd and environment state. Expanding a read-only output preview alone does not meet the request.

  > AgentHostSessionHandler._reviveTerminalIfNeeded in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts branches on terminalContent.isPty: PTY content gets an instance, while non-PTY content gets attachOutputTerminal. AgentHostTerminalService.attachOutputTerminal registers only an output channel. - **Open decisions:**
