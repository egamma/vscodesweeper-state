# Issue #332313 — Add a minimize/collapse action for long-running progress notifications

[https://github.com/microsoft/vscode/issues/332313](https://github.com/microsoft/vscode/issues/332313)

## Summary

Fresh (3-day-old, 1 upvote) feature request just entered the Backlog Candidates 60-day window — too early to close on quiet/age grounds. There's already a related mechanism (hiding the notification switches its progress to a status-bar window indicator), but no discoverable per-notification minimize button exists, so a real UI gap remains.

## Change summary

Add an explicit minimize/collapse action on long-running progress notification toasts that moves the progress display to the status bar while the operation keeps running, with a way to expand it again later.

## Best solution

Consider exposing the existing 'hide-to-status-bar' progress mechanism (src/vs/workbench/services/progress/browser/progressService.ts's `createWindowProgress`, triggered today only via `onDidChangeVisibility` when toasts are hidden/notification center opened) as an explicit, discoverable per-toast minimize action, since the close/clear action is currently suppressed for progress notifications (notificationsViewer.ts: `if (!notification.hasProgress) actions.push(closeNotificationAction)`).
