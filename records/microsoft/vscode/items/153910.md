# Issue #153910 — Click on titlebar to close command center.

[https://github.com/microsoft/vscode/issues/153910](https://github.com/microsoft/vscode/issues/153910)

## Summary

The dismissal gap remains visible in current source: the desktop title bar uses a native draggable region that receives no ordinary mouse events, while the Command Center only observes Quick Input visibility. This issue should remain open as the canonical report for making mouse-driven dismissal consistent without breaking window dragging.

## Change summary

Clicking the draggable title-bar area should dismiss an open Command Center or Quick Pick, as clicking elsewhere outside it already does.

## Best solution

Define and implement desktop title-bar interaction semantics that dismiss the Quick Input on an outside click while preserving normal window dragging once the picker is gone.

- **Validation:** On Windows with the custom title bar, open the Command Center Quick Pick and click an otherwise empty draggable title-bar area: the picker must close. Then verify that dragging the title bar still moves the window when no picker is open, and confirm that editor clicks and Escape retain their existing dismissal behavior.
- **Behavior:**

  > An open Command Center or Quick Pick closes when the user clicks an otherwise empty area of the custom title bar, matching clicks elsewhere outside the picker. Normal title-bar dragging remains available after dismissal, and interactive title-bar controls continue to work. Acceptance requires validating the behavior on Windows, where native draggable regions do not emit ordinary mouse events, without regressing Escape or editor-click dismissal.
- **Trace:**

  > BrowserTitlebarPart creates `div.titlebar-drag-region` in src/vs/workbench/browser/parts/titlebar/titlebarPart.ts, and titlebarpart.css marks it `-webkit-app-region: drag`; the issue thread confirms that this prevents mouse events on Windows. CommandCenterControl in src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts tracks Quick Input show/hide state but has no outside-click path for the drag region. The existing title-bar unit suite covers DOM and styling behavior but cannot reproduce native Electron drag-region event suppression. Keep the scope to Quick Input dismissal and title-bar interaction; do not alter generic Quick Input dismissal semantics or interactive title-bar controls. https://github.com/microsoft/vscode/issues/154258 is related layering work, while https://github.com/microsoft/vscode/issues/154541 confirms this issue is the canonical dismissal report.
- **Open decisions:**
  - When the Quick Input is open, should the first title-bar interaction only dismiss it, or should that same pointer gesture also begin moving the window?

## Evidence

- **current source:** src/vs/workbench/browser/parts/titlebar/titlebarPart.ts creates `div.titlebar-drag-region`, and src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css assigns it `-webkit-app-region: drag`; no dismissal handler is attached to that region.
- **Command Center path:** src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts observes `IQuickInputService.onShow` and `onHide` only to update Command Center visibility; it does not intercept title-bar clicks or call Quick Input dismissal.
- **confirmed limitation:** A maintainer explained that Windows native draggable title-bar areas provide no mouse events, and proposed a non-draggable blocking element beneath the Quick Pick as a possible interception mechanism.
- **canonical status:** https://github.com/microsoft/vscode/issues/154541 reported the same observable symptom and was closed as a duplicate of this issue, reinforcing this older report as the canonical item.
- **related but distinct:** https://github.com/microsoft/vscode/issues/154258 is younger and tracks menu layering below a Quick Pick; its discussion references this dismissal problem but explicitly notes that the Windows title-bar case is not fully addressed.
