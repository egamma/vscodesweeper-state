# Issue #300269 — expose open terminal UI even when terminal command is collapsed

[https://github.com/microsoft/vscode/issues/300269](https://github.com/microsoft/vscode/issues/300269)

## Summary

Keep open: current main partially improves this flow for running background terminals, but the action remains inside the terminal wrapper nested under the collapsed thinking group. The team-authored issue also cannot be closed as implemented because the partial implementation does not reference this issue.

## Change summary

Expose a direct way to reveal a terminal command without expanding both its containing thinking step and the terminal-output disclosure.

## Best solution

Provide a keyboard-accessible terminal affordance at the collapsed thinking/tool-group level without promoting every terminal command into top-level chat content. The design should define how that affordance behaves when the group contains multiple terminals and whether completed terminals remain available.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatTerminalToolProgressPart.test.ts`
- **Validation:** Add a focused chat widget test that constructs a collapsed thinking group containing terminal invocations and verifies the chosen terminal affordance is visible and keyboard-operable without expanding either disclosure, including the decided behavior for multiple and completed terminals.
- **Behavior:**

  > A user viewing a collapsed thinking step can reveal the relevant agent-created terminal without first expanding the thinking step and then the terminal command. The affordance must be reachable and operable by keyboard, and activating it must reveal and focus the correct terminal. Terminal output can remain collapsed, and unrelated tool calls must not gain terminal actions.
- **Trace:**

  > Terminal invocations are grouped into ChatThinkingContentPart by `ChatListItemRenderer.shouldPinPart()` and `thinkingPart.appendItem()` in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts. The terminal-specific action bar is created inside ChatTerminalToolProgressPart, so it is unavailable while the containing thinking group is collapsed. ChatTerminalThinkingCollapsibleWrapper now adds a Show link for active background commands, from https://github.com/microsoft/vscode/pull/316279, but `_updateShowLink()` requires `_isRunningInBackground` and `markComplete()` removes it. The boundary is collapsed-chat discoverability: do not promote every terminal invocation to top-level content, change terminal execution semantics, or automatically focus the terminal.
- **Open decisions:**
  - When a collapsed thinking group contains multiple terminal commands, should its affordance reveal the currently running terminal, the most recent terminal, or present a choice?
  - Should the shortcut remain available for completed commands, or only while their terminal process is still running?

## Evidence

- **maintainer direction:** A maintainer agreed that the current flow takes too many clicks and suggested surfacing a button near the tool call: https://github.com/microsoft/vscode/issues/300269#issuecomment-4049823408.
- **current grouping path:** src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts keeps terminal tool invocations pinned inside ChatThinkingContentPart when ChatConfiguration.TerminalToolsInThinking is enabled, then appends them through thinkingPart.appendItem; their controls therefore remain behind the outer thinking disclosure.
- **partial implementation:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts adds a keyboard-accessible Show link to ChatTerminalThinkingCollapsibleWrapper only while `_isRunningInBackground` is true; `_updateShowLink()` omits it otherwise and `markComplete()` removes it.
- **related merged work:** https://github.com/microsoft/vscode/pull/316279 added the background-terminal Show link, but its scope is still-running background commands and its closingIssuesReferences are empty; it does not reference https://github.com/microsoft/vscode/issues/300269 or establish completion of this team-authored request.
- **existing validation:** src/vs/workbench/contrib/chat/test/browser/widget/chatContentParts/chatTerminalToolProgressPart.test.ts explicitly verifies that the Show action disappears after `markComplete()`, confirming that current behavior does not provide a durable shortcut for every collapsed terminal command.
