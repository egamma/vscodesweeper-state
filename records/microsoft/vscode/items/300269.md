# Issue #300269 — expose open terminal UI even when terminal command is collapsed

[https://github.com/microsoft/vscode/issues/300269](https://github.com/microsoft/vscode/issues/300269)

## Summary

Keep open: current UI offers partial shortcuts, but does not consistently expose the requested command-specific terminal access outside collapsed thinking groups. The team-authored request also has explicit maintainer support, with no verified fixing commit or older canonical covering the same symptom.

## Change summary

Make selected agent-command terminals easier to open without expanding nested thinking and command-output sections.

## Best solution

Provide discoverable, command-specific terminal access from the collapsed chat presentation while keeping routine commands compact. Decide how that access should behave when a thinking group contains several terminals, building on the existing terminal reveal actions.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts`, `src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatActions.ts`
- **Validation:** After choosing the interaction, verify in a local workbench that a response containing multiple terminal commands permits opening the intended live terminal without expanding its thinking group or output. Check mouse and keyboard access, correct command targeting, completed versus running commands, and unchanged compact presentation for routine commands.
- **Behavior:**

  > Agent users should be able to open an interesting command's live terminal without navigating nested thinking and command-output expanders. Routine commands should remain compact rather than all being promoted into top-level chat content. Acceptance should cover multiple terminals in one thinking group, keyboard operation, and unavailable terminals without misleading actions.
- **Trace:**

  > ChatTerminalToolProgressPart._updateToolbarActions in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatTerminalToolProgressPart.ts already provides per-instance terminal reveal actions. Its ChatTerminalThinkingCollapsibleWrapper._updateShowLink exposes a Show link on the inner command header only while a background command is running; ChatThinkingContentPart in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatThinkingContentPart.ts groups tool content beneath another collapsible presentation. ShowChatTerminalsAction in src/vs/workbench/contrib/terminalContrib/chat/browser/terminalChatActions.ts offers a separate hidden-terminal picker, and chat.tools.terminal.outputLocation can automatically reveal output, but neither supplies the requested selective transcript affordance in all collapsed states. Preserve command execution, terminal ownership, and the existing output-location preference. The uncertainty is the user-facing selection interaction for several terminals behind one collapsed group, not the mechanics of revealing an instance. https://github.com/microsoft/vscode/issues/290977 concerns terminal cleanup and should not absorb this request.
- **Open decisions:**
  - When a collapsed thinking group contains several terminals, should its terminal affordance open a command picker or expose individual command targets?
  - Should collapsed-group access include every still-available command terminal, or only terminals whose commands are currently running?
