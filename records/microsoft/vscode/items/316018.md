# Issue #316018 — voice over and braille display on mac os

## Summary

Traced to an upstream Chromium/macOS Accessibility API bug (AXLineForIndex/AXRangeForLine misreporting lines in text fields) that exactly matches the reported braille/VoiceOver line-sync symptom; it's fixed upstream and the fix is already included in VS Code's current bundled Electron target, but the project should not close an upstream-rooted accessibility issue without confirmation, and part of the report (sidebar/console "group"/"?" announcements) is a separate, unaddressed problem.

## Change summary

## Evidence

- **upstream root cause:** electron/electron#53403 documents the exact symptom (braille display shows the previous line merged with the current one, or goes blank, after moving the caret in a multi-line textarea/div[role=textbox] on macOS) and traces it to Chromium's accessibilityLineForIndex: using std::lower_bound (so any non-line-start index maps to the next line) and AXRangeForLine: returning nil for any line but 0 — this issue (#316018) and https://github.com/microsoft/vscode/issues/319725 are cited there as affected apps.
- **upstream fix shipped:** Chromium fix landed at crbug 423048796 (commit 36ac8f31796a392340f7914d1018c3a885fc183f), first in Chromium 152/Electron 44, and backported to the 43-x-y line via electron/electron#53428, merged 2026-09-03.
- **VS Code already on a fixed Electron:** electron/electron releases show v43.6.0 published 2026-09-04 (first 43-x-y release after the backport); the checkout's .npmrc targets Electron 43.7.7 (released 2026-09-30), which post-dates that backport, so the upstream fix should already be present in VS Code's bundled runtime.
- **VS Code call site:** src/vs/editor/browser/controller/editContext/native/screenReaderSupport.ts and textAreaEditContext.ts expose editor content to screen readers through a native textarea/contenteditable DOM node — the exact element type the Chromium AX bug affects — so the fix applies automatically once Electron is bumped, no VS Code code change needed.
- **maintainer treats this as canonical:** https://github.com/microsoft/vscode/issues/323246 (same VoiceOver/braille symptoms, including the sidebar 'group' readout) was closed by @meganrogge on 2026-07-07 with 'We are tracking issues with VoiceOver and cursor movement already here https://github.com/microsoft/vscode/issues/316018', confirming this is the tracking issue, not a duplicate of something else.
