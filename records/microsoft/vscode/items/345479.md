# Issue #345479 — Copilot harness: every custom agent is listed twice in the subagent list, once by its own name and once as vscode-agent-<sha1>

[https://github.com/microsoft/vscode/issues/345479](https://github.com/microsoft/vscode/issues/345479)

## Summary

Keep open: duplicate executable registrations are distinct from the earlier picker-label problem. Current main separates native plugin selection from forwarded definitions, but still forwards discovered directory agents; the supplied steps suffice to retest the runtime catalog.

## Change summary

Prevent the Copilot task tool from exposing both native and forwarded registrations of the same custom-agent source.

## Best solution

Ensure each agent source has one effective executable registration while preserving distinct same-named agents from different sources and their authored configuration. Investigate the discovery-to-SDK handoff rather than reverting collision-safe names or treating picker disambiguation as the fix.

- **Current forwarding path:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:getCopilotCustomAgents combines plugin agents and discoveredAgents, excluding built-in names but not comparing native source identities. The launcher converts these definitions with toSdkCustomAgents and includes them alongside built-in agents in SessionConfig.customAgents.
- **Discovery and conversion:** src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts:discoverAgents obtains native SDK agent IDs and paths. src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts:getSdkCustomAgentName generates URI-derived vscode-agent- hashes; toSdkCustomAgents also converts an empty tools array to null. These paths support the reported identity/configuration divergence, but do not alone prove the runtime merges both catalogs.
- **Existing native-plugin distinction:** src/vs/platform/agentHost/node/copilot/copilotAgent.ts:_resolveCustomizations keeps discovered plugin children in nativeAgents separately from discovered directory agents and explicit plugin definitions. This prevents assuming every plugin is necessarily forwarded twice; catalog-level verification is still needed.
