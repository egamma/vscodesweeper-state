# Issue #331777 — microsoft-authentication: an account with a terminally expired refresh token is never pruned, so signing in cannot recover it

[https://github.com/microsoft/vscode/issues/331777](https://github.com/microsoft/vscode/issues/331777)

## Summary

Fresh, carefully diagnosed report with a concrete code trace: the catch block in getAllSessionsForPca (extensions/microsoft-authentication/src/node/authProvider.ts, lines 530-540) treats every silent-acquisition failure identically and never prunes an account with a terminally expired refresh token, so the sign-in the badge offers cannot converge.

## Change summary

An account whose refresh token has terminally expired (AADSTS700082/invalid_grant) is never pruned from the MSAL cache, so re-signing in via the Accounts badge only fixes the one scope set it was invoked with and every other scope set keeps failing indefinitely.

## Best solution

In getAllSessionsForPca's catch block, branch on the MSAL error's errorCode/subError: for a terminal invalid_grant/bad_token, either drop the account from the PCA cache or route the interactive sign-in to fully re-consent that account's identity across all its scope sets, instead of silently `continue`-ing forever. This needs a maintainer/owner decision on which remedy to take before implementing.
