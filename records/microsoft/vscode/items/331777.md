# Issue #331777 — microsoft-authentication: an account with a terminally expired refresh token is never pruned, so signing in cannot recover it

[https://github.com/microsoft/vscode/issues/331777](https://github.com/microsoft/vscode/issues/331777)

## Summary

Confirmed against current main: `getAllSessionsForPca`'s catch block in extensions/microsoft-authentication/src/node/authProvider.ts (lines 530-540) treats every silent-acquisition failure identically, with no branch on `errorCode`/`subError`, so a terminally expired refresh token is logged, telemetered, and retried forever instead of being pruned — matches the report exactly.

## Change summary

A Microsoft account whose refresh token has terminally expired (AADSTS700082/invalid_grant/bad_token) is never removed from the MSAL cache, so every scope set except the one just re-authenticated keeps failing indefinitely, and the only working remedy (full sign-out) isn't what the UI's sign-in prompt suggests.

## Best solution

In the catch of getAllSessionsForPca, branch on the MSAL error (ServerError.errorCode/subError for invalid_grant/bad_token) and either drop the account via cachedPca.removeAccount(account) or otherwise force a full re-consent instead of silently retrying a dead credential forever; this needs a maintainer/authentication-team call on which remedy (drop vs. flag-for-reconsent) to take, plus new test coverage since authProvider.ts currently has no direct unit tests for this path.
