# Issue #291269 — class names aren't (internal) API

[https://github.com/microsoft/vscode/issues/291269](https://github.com/microsoft/vscode/issues/291269)

## Summary

Valid debt item — the integrated browser overlay manager still relies on CSS class names (e.g. `suggest-details-container`, `monaco-hover`) as an implicit contract to detect when overlays appear. The fragile coupling remains on current main; the requested proper event-based API has not been implemented.

## Change summary

The integrated browser uses CSS class names to detect overlay show/hide, creating a fragile implicit API that can break silently when class names change.

## Best solution

Replace the class-name-based overlay detection in `src/vs/workbench/contrib/browserView/electron-browser/overlayManager.ts` with a proper event/API mechanism — e.g. have the code editor widget and overlay components emit show/hide/layout events that the browser overlay manager listens to, rather than scanning the DOM for specific class names.
