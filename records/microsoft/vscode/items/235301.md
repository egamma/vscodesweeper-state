# Issue #235301 — Reduce space taken up by cached data

[https://github.com/microsoft/vscode/issues/235301](https://github.com/microsoft/vscode/issues/235301)

## Summary

Current source still retains up to 20 extension archives without an age or byte-size limit, so the disk-footprint concern remains. The maintainer-created cleanup issue is now closed with a wont-fix label, but provides neither a fixing commit nor an explanation sufficient to dispose of this report.

## Change summary

Reduce disk space occupied by cached extension VSIX archives after installation.

## Evidence

- **Current retention behavior:** src/vs/platform/extensionManagement/node/extensionDownloader.ts sets this.cache = 20 and invokes cleanUp() during construction. cleanUp() removes older versions, excess distinct archives, signature archives, and trash, but has no age-based or byte-size eviction. Twenty large archives can therefore retain substantial disk space.
- **Existing capability is partial:** The downloader reuses existing VSIX downloads, explaining why archives are retained. The existing count-based cleanup does not guarantee a small disk footprint; inspection of src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts found no cache-budget setting or cache-clearing command.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/235301#issuecomment-2520796531 explicitly created https://github.com/microsoft/vscode/issues/235413 for regular CachedExtensionVSIXs cleanup. This establishes maintainer interest rather than grounds for a judgment-based close.
- **Closed follow-up is not a verified fix:** https://github.com/microsoft/vscode/issues/235413 closed on 2025-12-17 with labels debt, extensions, and wont-fix. Its timeline contains no closing commit and its thread has no explanatory comments. It cannot serve as an open duplicate canonical or proof of implementation.
- **Startup cache workaround:** https://github.com/microsoft/vscode/issues/235301#issuecomment-2518866080 explains that CachedData improves startup performance and documents code --no-cached-data and manual removal of obsolete commit directories. That advice concerns a separate cache and does not disable retained extension VSIX downloads.
