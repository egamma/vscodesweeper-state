# Issue #279957 — Tool picker/dropdown should be configurable from the outside

[https://github.com/microsoft/vscode/issues/279957](https://github.com/microsoft/vscode/issues/279957)

## Summary

The architectural debt remains on current main: inline-chat model eligibility is still inferred inside shared chat-input filtering rather than supplied by the owning surface. The accepted callback design is bounded and should be routed to the chat and inline-chat owners.

## Change summary

Allow chat-widget consumers to configure which language models appear in their model picker instead of hardcoding surface-specific eligibility inside the shared input component.

## Best solution

Expose a model-filter callback through `IChatWidgetViewOptions`, propagate it to the input model-selection pipeline, and have inline chat supply its tool-capability requirement while preserving all shared session, mode, visibility, and hidden-model filtering.

## Evidence

- **missing external option:** `IChatWidgetViewOptions` in `src/vs/workbench/contrib/chat/browser/chat.ts` and `IChatInputPartOptions` in `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts` expose no model-filter callback; `ChatWidget.createInput` therefore has no consumer-provided filter to propagate.
- **consumer boundary:** `src/vs/workbench/contrib/inlineChat/browser/inlineChatZoneWidget.ts` and `inlineChatController.ts` already construct the widget with `chatWidgetViewOptions`, providing the natural boundary for inline chat to declare its model eligibility.
