# Issue #108256 — resources#relativePath does not honour path casing strategy

[https://github.com/microsoft/vscode/issues/108256](https://github.com/microsoft/vscode/issues/108256)

## Summary

The casing-strategy mismatch remains in current source: file URIs bypass the configured strategy and use host-platform path semantics. Keep this open; the previous implementation attempt was closed without merging, and its caller-compatibility concerns still need investigation.

## Change summary

Make ExtUri.relativePath honor its configured path-casing strategy for file URIs rather than implicitly using the host platform's strategy.

## Best solution

Make relative-path calculations consistent with the ExtUri casing contract, including IUriIdentityService's filesystem-capability-based strategy, while preserving valid Windows drive and UNC handling. Establish the compatibility boundary for existing callers before changing the shared utility.

## Evidence

- **Current source confirms bypass:** src/vs/base/common/resources.ts:249–271 returns early for Schemas.file through paths.relative(originalFSPath(from), originalFSPath(to)); _ignorePathCasing(from) is consulted only after that return. Consequently, a case-insensitive ExtUri on macOS computes '../BAR/somefile.txt' rather than 'somefile.txt' for the thread's /foo/bar → /foo/BAR/somefile.txt example.
