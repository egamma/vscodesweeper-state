# Issue #336338 — Custom agent invoked as subagent cannot write files despite edit tool and Allow All permissions

[https://github.com/microsoft/vscode/issues/336338](https://github.com/microsoft/vscode/issues/336338)

## Summary

The control test isolates a current Agents window bug to the custom-subagent invocation path: the same agent can write when invoked directly but is effectively read-only when delegated. This should remain open and be routed to the Agents window owners.

## Change summary

Custom agents invoked through another custom agent should retain their configured edit tools and the parent session's workspace-write permissions.

## Best solution

Make delegated custom-agent sessions derive effective tool availability and write permissions from the selected agent definition and parent permission level, while preserving normal approval boundaries and sandbox restrictions.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost`, `src/vs/sessions`, `extensions/copilot`
- **Validation:** Add an agent-host end-to-end scenario that invokes a workspace custom agent with edit capability through a coordinator under Allow All, then asserts that the subagent creates, reads, modifies, and rereads a workspace file; retain a direct-invocation control.
- **Behavior:**

  > A workspace custom agent configured with read and edit tools must have the same declared file-edit capability when invoked as a subagent as when invoked directly, subject to the active VS Code permission model. Under Allow All, a delegated agent must be able to create and modify files inside the workspace without an invocation-level read-only override. Acceptance should compare direct and delegated invocation of the same agent and require both to complete create/read/modify/read successfully.
- **Trace:**

  > The reporter's control test isolates the failure to delegation: the same Architect definition uses `apply_patch` successfully when selected directly, but reports an effective write prohibition when invoked by the Project Manager through the `agent` tool. The failure survives explicit prompt authorization and Allow All, so diagnosis should trace how the Agents window publishes custom-agent tools and permissions into the nested agent-host invocation. Relevant boundaries are likely under src/vs/platform/agentHost, src/vs/sessions, and extensions/copilot; preserve normal approval behavior for Manual permissions and do not broaden filesystem access beyond the workspace. https://github.com/microsoft/vscode/issues/304574 is related but describes a different third-party-agent path.
