# Issue #32267 — [GRIPE] "editor.mouseWheelScrollSensitivity" setting is not respected while making a text selection

[https://github.com/microsoft/vscode/issues/32267](https://github.com/microsoft/vscode/issues/32267)

## Summary

Selection auto-scrolling now uses distance-dependent speeds, but the requested control over sensitivity remains absent. Keep this open as a configuration request; the related completed improvement does not fully deliver that capability.

## Change summary

Provide a setting to control auto-scroll speed while extending a text selection beyond the editor viewport.

## Best solution

Decide whether selection auto-scrolling should expose an independent sensitivity control while preserving existing mouse-wheel behavior and the current distance-dependent acceleration.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/controller/dragScrolling.ts`, `src/vs/editor/browser/controller/mouseHandler.ts`
- **Validation:** Compare selection auto-scrolling at two approved sensitivity values in a document spanning several viewports, holding the pointer at the same distance beyond each viewport edge. Verify that the lower value scrolls more slowly, the default preserves existing behavior, and ordinary mouse-wheel scrolling remains unchanged.
- **Behavior:**

  > Users selecting text beyond the visible editor should be able to control selection auto-scroll sensitivity. Current distance-dependent acceleration improves the original experience but does not supply the requested configuration. Acceptance should compare scrolling rates at identical pointer distances under different sensitivity values and verify that ordinary wheel scrolling remains unchanged. The setting's scope and default behavior need approval before implementation.
- **Trace:**

  > MouseDownOperation._onMouseDownThenMove in src/vs/editor/browser/controller/mouseHandler.ts dispatches outside-editor selection tracking to TopBottomDragScrolling or LeftRightDragScrolling. Their operations in src/vs/editor/browser/controller/dragScrolling.ts derive scrolling speed from pointer distance, viewport dimensions, and font metrics, then apply elapsed-time-scaled deltas through deltaScrollNow. editor.mouseWheelScrollSensitivity in src/vs/editor/common/config/editorOptions.ts explicitly governs wheel events and is not read by these operations. https://github.com/microsoft/vscode/pull/161378 addressed excessive default vertical speed for https://github.com/microsoft/vscode/issues/40890 but did not add configurable sensitivity. Preserve ordinary wheel behavior, existing default acceleration, and selection semantics; the unresolved boundary is the public scope of a new selection-scrolling control.
- **Open decisions:**
  - Should selection auto-scrolling expose an independent sensitivity setting?
  - Should that control affect both horizontal and vertical selection auto-scrolling, or only vertical scrolling?

## Evidence

- **existing setting boundary:** src/vs/editor/common/config/editorOptions.ts:6494–6497 defines editor.mouseWheelScrollSensitivity specifically as a multiplier for mouse-wheel deltaX and deltaY. editor.smoothScrolling controls animation, not selection auto-scroll sensitivity; neither setting delivers the requested control.
- **remaining source gap:** src/vs/editor/browser/controller/mouseHandler.ts:426–432 starts TopBottomDragScrolling or LeftRightDragScrolling when selection tracking reaches outside the editor. In src/vs/editor/browser/controller/dragScrolling.ts, both _getScrollSpeed methods calculate fixed distance-dependent rates from viewport dimensions and font metrics without a configurable sensitivity multiplier.
- **related improvement, not complete coverage:** https://github.com/microsoft/vscode/issues/40890 is closed through merged https://github.com/microsoft/vscode/pull/161378, whose merge commit is 83d7b8ecf760a39babd9c3fb20bd2a2854b3fedb. The diff introduces distance-dependent vertical scrolling with hardcoded minimum rates of 30, 60, and 200 lines per second; it does not introduce a sensitivity setting. Those formulas remain in current source.
- **discussion evidence:** https://github.com/microsoft/vscode/issues/40890#issuecomment-1038290167 explicitly links this report as related. https://github.com/microsoft/vscode/issues/40890#issuecomment-827475718 explains why smooth scrolling is not an adequate substitute, and https://github.com/microsoft/vscode/issues/40890#issuecomment-1281187140 confirms the later improvement changed default behavior rather than adding a setting.
- **canonical search:** Open-issue searches for selection sensitivity, dragging speed, and selection scrolling found no verified canonical owning this configuration request. https://github.com/microsoft/vscode/issues/317783 concerns Shift-held drag-and-drop speed, while https://github.com/microsoft/vscode/issues/218248 concerns the upward scrolling activation threshold; neither absorbs configurable text-selection auto-scroll sensitivity.
