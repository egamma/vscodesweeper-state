# Issue #243625 — Extensions should be able to open new documents wich are not dirty

[https://github.com/microsoft/vscode/issues/243625](https://github.com/microsoft/vscode/issues/243625)

## Summary

A real extension API gap remains: content-backed untitled documents are always dirty, while the existing clean-document API is read-only. The request reached the Backlog with 27 upvotes and is already correctly routed.

## Change summary

Allow extensions to open a named, in-memory text document with initial content without marking it dirty.

## Best solution

Define an extension API for a clean, content-backed document with an associated filename, including explicit editability, save, close, and content-lifecycle semantics. Preserve `TextDocumentContentProvider` for read-only virtual documents.
