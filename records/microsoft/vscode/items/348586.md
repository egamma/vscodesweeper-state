# Issue #348586 — Let the agent's browser tools reach chat canvases (canvas views can't be shared with the agent)

[https://github.com/microsoft/vscode/issues/348586](https://github.com/microsoft/vscode/issues/348586)

## Summary

Keep open as a feature request: current source confirms that chat canvases lack agent audiences and do not expose the browser-tab sharing control. Enabling access requires a deliberate authorization and policy-compatible storage design, not merely exposing the canvas ID.

## Change summary

Allow agents to inspect and interact with their chat canvases through browser tools without reopening the page in a separate tab.

## Best solution

Provide a supported canvas-access path that preserves session ownership, sharing consent, and network-policy enforcement. Maintainers should decide whether access follows canvas creation automatically or requires explicit user sharing.

## Evidence

- **Canvas creation path:** src/vs/workbench/contrib/canvases/electron-browser/canvasService.ts:360 calls createExternalBrowserView with the owning chat as networkOwner. In src/vs/workbench/contrib/browserView/electron-browser/browserViewWorkbenchService.ts:525–558, that argument selects networking, while the actual view remains user-owned, unlisted, ephemeral, and initialized with initialAudiences: [].
- **Automation visibility:** src/vs/platform/browserView/electron-main/browserViewGroup.ts:_reconcileView selects views using their audiences and sandbox-session compatibility. An owning-chat network argument does not grant automation visibility.
- **Existing capability does not cover canvases:** Share with Agent is implemented by BrowserEditorChatFeatures in src/vs/workbench/contrib/browserView/electron-browser/features/browserEditorChatFeatures.ts. BrowserViewWorkbenchService skips automatic registration of unlisted views at lines 231–244; createExternalBrowserView separately creates their model without supplying the normal browser-editor sharing surface. Sharing another tab therefore remains a workaround, not access to the original canvas.
- **Policy boundary:** src/vs/platform/browserView/electron-main/browserViewMainService.ts:209–225 validates agent access before adding an agent audience. src/vs/platform/browserView/common/browserView.ts:630–631 permits only Agent storage scope when network filtering is enabled. BrowserViewModel.setSharedWithAgent currently handles incompatible storage by opening a separate isolated tab, which does not satisfy the requested same-canvas behavior.
- **Canonical search:** Public GitHub searches for open canvas/browser-tool reports did not establish a canonical issue owning this capability. https://github.com/microsoft/vscode/pull/345703 concerns remote canvas discovery and lifecycle management; its description does not establish coverage of browser-tool access to canvas views.
