# Issue #260188 — Copilot Chat: chat summarization makes broken and bad edits

[https://github.com/microsoft/vscode/issues/260188](https://github.com/microsoft/vscode/issues/260188)

## Summary

Keep open: this team-authored report has no explicit fixing commit or verified duplicate, and current main still relies on model-generated summaries plus an advisory transcript hint rather than guaranteeing that authoritative file context is restored before editing. The original failure was credibly corroborated, but the substantially changed compaction path needs a fresh current-main reproduction.

## Change summary

Prevent an agent from making stale or fabricated file edits after conversation compaction removes relevant working context.

## Best solution

Reproduce the long-session edit flow against the current background-compaction implementation, then define and enforce a post-compaction safety contract that prevents edits until the agent has authoritative content for the target file. Preserve the existing strategy of selective context loading rather than automatically reattaching every full file.

- **Behavior:**

  > After conversation compaction, the agent must not edit a file using stale, omitted, or fabricated target content. Before the first post-compaction edit, it must have authoritative context sufficient to identify the intended location and preserve the user's active task and constraints. Long-running conversations should continue without unrelated edits or loss of the current work plan. Existing conversations that still have sufficient authoritative context should not incur unnecessary full-file attachments.
- **Trace:**

  > Current compaction is implemented by `SummarizedConversationHistory` and `SummaryPrompt` in extensions/copilot/src/extension/prompts/node/agent/summarizedConversationHistory.tsx. Earlier rounds are replaced by model-generated summary text; `appendTranscriptHintToSummary` supplies an advisory path to the uncompacted transcript, but does not require the model to consult it. Background results are applied and persisted by `AgentIntentInvocation` in extensions/copilot/src/extension/intents/node/agentIntent.ts, after which the ordinary tool loop resumes without a traced hard pre-edit refresh gate. Existing tests in extensions/copilot/src/extension/prompts/node/agent/test/summarization.spec.tsx cover summary rendering and transcript hints, not the reported end-to-end stale-edit outcome. The boundary is conversation compaction and the first subsequent edit: do not automatically attach every complete historical file or redesign unrelated edit tools. https://github.com/microsoft/vscode/issues/262858 addressed a narrower custom-instruction attachment path and does not establish that this broader behavior is fixed.
- **Open decisions:**
  - Should every first edit after compaction require an authoritative reread of its target file, or may the edit proceed when the retained post-compaction context contains verifiably exact target content?
  - When authoritative target context is missing, should the product automatically restore it, instruct the model to retrieve it, or reject the edit attempt until the model does so?
