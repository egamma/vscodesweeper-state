# Issue #130297 — Suggestion Preview: Support previews that don't just insert text

[https://github.com/microsoft/vscode/issues/130297](https://github.com/microsoft/vscode/issues/130297)

## Summary

Keep open: current suggestion previews still cannot represent replacing typed characters, including lowercase `p` with `PermissionError`. This issue already owns several maintainer-confirmed duplicates; the remaining work needs a presentation decision, not a staleness close.

## Change summary

Support suggestion previews whose acceptance replaces or deletes existing text rather than only inserting text.

## Best solution

Provide a non-destructive preview of replacement-based IntelliSense suggestions that clearly distinguishes existing text from the proposed outcome without disruptive text movement. Resolve the presentation and enablement contract before implementation, retaining this issue as the canonical request.

- **Behavior:**

  > With suggestion preview enabled, selecting a completion that replaces typed text should show its proposed outcome before acceptance, including `p` becoming `PermissionError`. The preview must not modify the document or misrepresent the text acceptance will insert. Fuzzy matches and snippet expansions requiring replacement belong to the same capability. Acceptance and dismissal must preserve existing completion semantics, and ordinary insertion-only previews must remain unchanged. Presentation and whether this capability requires separate opt-in remain to be decided.
- **Trace:**

  > The selected-suggestion path in src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts obtains a text edit and passes it to computeGhostText. In src/vs/editor/contrib/inlineCompletions/browser/model/computeGhostText.ts, any diff consuming original characters returns undefined, so case replacement cannot produce a preview in any existing mode. GhostTextReplacement and its renderer exist, but that does not demonstrate use by this path. The current computeGhostText tests explicitly encode rejection of non-insertion edits. Keep the boundary on suggestion presentation; do not change completion ranking, document contents before acceptance, or acceptance semantics. https://github.com/microsoft/vscode/issues/132287#issuecomment-913214129 identifies text jumping as a design constraint, while https://github.com/microsoft/vscode/issues/147068 contains related presentation alternatives. The uncertainty begins at the user-visible representation and enablement contract, not at whether the current preview path rejects replacements.
- **Open decisions:**

  - Should replacement previews be included whenever `editor.suggest.preview` is enabled, or require a separate opt-in?
