# Issue #341514 — Claude custom endpoint (Messages API): 400 "thinking block bound to a different conversation" mid-turn in long agent tool loops

[https://github.com/microsoft/vscode/issues/341514](https://github.com/microsoft/vscode/issues/341514)

## Summary

Thanks for the detailed report. It carries concrete steps, versions, the exact API error, and logs, but I did not trace the Messages API history replay in the checkout. This needs a maintainer to look at how thinking blocks are replayed in long tool loops on a custom endpoint. The only bot comment suggests updating to 1.141.1, which is a minor patch bump and unlikely to change the behavior.

## Change summary

On a custom Messages API endpoint with thinking enabled, a long agent tool loop fails with a 400 because replayed thinking-block signatures no longer match the conversation history, and the automatic retries resend the same body.

## Best solution

Make the Messages API history replay keep the prior assistant content (thinking blocks and surrounding content) byte-identical to what was originally sent. As a fallback, on this specific 400 retry once with the rejected thinking blocks stripped rather than resending the same body. Look at the Messages API request builder in the Copilot Chat extension and the retry path in ToolCallingLoop.
