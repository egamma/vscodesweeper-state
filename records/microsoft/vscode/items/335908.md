# Issue #335908 — Webview can go blank when an earlier mount finishes after a remount

[https://github.com/microsoft/vscode/issues/335908](https://github.com/microsoft/vscode/issues/335908)

## Summary

Traced the race in current main: WebviewElement.mountTo has no guard against a stale _encodedWebviewOriginPromise, so an earlier mount's origin-hash callback can still fire after a remount and reset the iframe src, leaving it blank. Reporter's account matches the code path exactly; keeping open for a fix.

## Change summary

When a webview is remounted before the first mount's async origin-hash resolves, the stale first completion still calls _initElement and resets the iframe, leaving it blank even though a newer mount is now current.

## Best solution

Guard WebviewElement.mountTo (src/vs/workbench/contrib/webview/browser/webviewElement.ts) so the origin-hash `.then()` callback checks it is still the current mount's promise before calling _initElement or assigning _encodedWebviewOrigin, discarding stale completions from superseded mounts.
