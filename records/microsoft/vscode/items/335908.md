# Issue #335908 — Webview can go blank when an earlier mount finishes after a remount

[https://github.com/microsoft/vscode/issues/335908](https://github.com/microsoft/vscode/issues/335908)

## Summary

Confirmed on current main: `WebviewElement.mountTo` (src/vs/workbench/contrib/webview/browser/webviewElement.ts) stores a fresh `_encodedWebviewOriginPromise` on each mount but the `.then` callbacks don't check that the promise is still the current one, so a stale (first) mount's completion can overwrite `_encodedWebviewOrigin` and re-run `_initElement`, resetting the iframe src of a webview that already remounted successfully. This is a real, unaddressed race.

## Change summary

A webview can go blank when an earlier mount's async origin-hash resolution completes after a later remount has already connected, because the stale completion still resets the iframe.

## Best solution

Guard both `.then` callbacks in `mountTo` (lines ~483-488) so a completion is ignored unless it belongs to the currently-active `_encodedWebviewOriginPromise`/mount, matching the reporter's proposed patch.
