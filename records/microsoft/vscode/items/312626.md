# Issue #312626 — Add a setting to disable auto-scrolling in the chat panel during response generation

[https://github.com/microsoft/vscode/issues/312626](https://github.com/microsoft/vscode/issues/312626)

## Summary

A real chat UX gap remains: current main disables streaming auto-scroll in Ask mode but provides no explicit opt-out for agent-mode responses. Route this to the chat area as a feature request; the older related issue no longer owns this request, while the newer overlapping proposal should be consolidated into this discussion.

## Change summary

Add an explicit control that prevents the chat transcript from following streamed response content automatically.

## Best solution

Provide a clearly exposed chat auto-scroll preference or per-session reading mode while retaining a way to reach the latest content. The chat owners should decide whether actionable permission prompts override the reading preference and whether the choice is global or session-scoped.

- **Behavior:**

  > Users can opt out of the chat transcript following streamed response content. With the opt-out active, incremental text and progress updates do not move the reading position, while an accessible action remains available to jump to the latest content. The existing follow-latest behavior remains the default unless maintainers decide otherwise. Acceptance must also cover the chosen behavior when a permission or confirmation prompt appears.
- **Trace:**

  > Chat surfaces pass a mode-dependent `autoScroll` option into ChatWidget; the panel implementation in src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts enables it for every mode except Ask. ChatWidget in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts applies that option to the list scroll lock on submission and scrolls to the end during streaming layout updates. No corresponding user preference is registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts. Existing list behavior already exposes a scroll-to-bottom button and preserves user scroll intent after manual movement, so those behaviors must not regress. https://github.com/microsoft/vscode/issues/274099 records why confirmations may need special treatment; https://github.com/microsoft/vscode/issues/330811 presents the alternative per-chat reading-mode design.
- **Open decisions:**
  - Should the opt-out be a global user setting, a per-chat session mode, or both, and how should that choice persist?
  - When auto-scroll is disabled, should permission and confirmation prompts remain completely non-scrolling or be revealed as an exception because they require immediate user action?

## Evidence

- **current behavior:** src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts configures `autoScroll: mode => mode !== ChatModeKind.Ask`, so Ask mode does not follow streaming output but other chat modes do.
- **streaming path:** src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts sets the list scroll lock from `viewOptions.autoScroll` when submitting a request and calls `scrollToEnd()` during rendering when that mode option is enabled.
- **missing capability:** The chat configuration registrations in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts include sticky-scroll and progress settings but no user-facing setting that disables response auto-scroll.
- **related older issue:** https://github.com/microsoft/vscode/issues/274099 discusses several chat scrolling problems, but its author withdrew the request to remove agent auto-scroll after a maintainer raised the need to reveal confirmation prompts; its remaining work does not own this explicit opt-out request.
- **related newer issue:** https://github.com/microsoft/vscode/issues/330811 proposes a younger, overlapping per-chat reading mode with a limited preview. Because this issue predates it and asks for the central opt-out behavior, the newer issue is not a valid canonical for closing this one.
