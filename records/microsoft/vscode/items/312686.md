# Issue #312686 — Copilot Chat auto-steers In Progress on new message instead of queueing to To Do

[https://github.com/microsoft/vscode/issues/312686](https://github.com/microsoft/vscode/issues/312686)

## Summary

The requested queue-first behavior is already configurable: set `chat.requestQueuing.defaultAction` to `queue`. Steering remains the default and an explicitly selectable alternative, so the current behavior is intentional.

## Change summary

Make new Copilot Chat messages wait until the active request finishes instead of steering it by default.

## Best solution

Use the existing `chat.requestQueuing.defaultAction` setting with value `queue`; this makes the primary send action add the message to the queue while preserving explicit steering through the alternate action.

## Evidence

- **existing setting:** `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts` registers `chat.requestQueuing.defaultAction` with `queue` and `steer`; `queue` is documented as sending after the current request completes, while the intentional default is `steer`.
- **behavior:** `src/vs/workbench/contrib/chat/browser/widget/input/chatQueuePickerActionItem.ts` maps that setting to either “Add to Queue” or “Steer with Message”; the queue action explicitly lets the current response finish uninterrupted.
