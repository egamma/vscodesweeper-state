# Issue #338692 — New line in auto-closing pair moves cursor to the line below

[https://github.com/microsoft/vscode/issues/338692](https://github.com/microsoft/vscode/issues/338692)

## Summary

Confirmed on main: the auto-closing-pair cursor placement math (`columnDeltaOffset = -closeCharacter.length` in TypeWithAutoClosingCommand) assumes the close string is single-line, so a close containing `\n` misplaces the cursor on the line below instead of before `end`. The reporter themselves raises an open design question — fix the offset math, or stop auto-inserting a newline into the close text at all and rely on onEnter rules — so this isn't a pure bounded bug fix yet.

## Change summary

When an autoClosingPairs close string contains a newline (e.g. `begin`/`\nend`), typing the open text places the cursor on the line below instead of right before the close text.

## Best solution

Either (a) make the cursor-offset computation in TypeWithAutoClosingCommand/ReplaceCommandWithOffsetCursorState newline-aware so it correctly lands before a multi-line close, or (b) decide multi-line autoClosingPairs close text shouldn't be auto-inserted at all and defer to onEnter rules instead — a maintainer should pick the direction before implementation.
