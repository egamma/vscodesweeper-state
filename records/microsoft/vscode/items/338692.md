# Issue #338692 — New line in auto-closing pair moves cursor to the line below

[https://github.com/microsoft/vscode/issues/338692](https://github.com/microsoft/vscode/issues/338692)

## Summary

Reproducible edge case: a multi-line `close` string in `autoClosingPairs` (containing `\n`) causes the cursor to jump to the inserted closing line instead of staying after the typed `open` text, and onEnter rules aren't applied to the new line — but this is a narrow, rarely-used configuration (multi-line close strings), and even the reporter now suggests a different design (require Enter, not auto-insert) rather than a straight bug fix.

## Change summary

Typing an auto-closing pair whose `close` string spans multiple lines (via `\n`) moves the cursor to the inserted line below instead of leaving it after the opening text, and onEnter rules don't run for the new line/pair.

## Best solution

A maintainer should decide the intended behavior for multi-line auto-closing `close` strings — likely integrating with onEnter rules so the closing text is only inserted on Enter rather than immediately after typing `open`, as the reporter themselves proposed.
