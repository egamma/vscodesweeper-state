# Issue #211443 — OSC 8 terminal hyperlinks don't work properly in Remote - WSL

[https://github.com/microsoft/vscode/issues/211443](https://github.com/microsoft/vscode/issues/211443)

## Summary

Still reproduces on main: when an OSC 8 hyperlink with `file://` scheme is clicked in a remote terminal (WSL/SSH), `TerminalUrlLinkOpener._openFileSchemeLink` stats the raw `file://` URI without converting it to `vscode-remote://`, so the stat fails and the link doesn't open in the editor.

## Change summary

OSC 8 terminal hyperlinks with `file://` scheme fail to open in Remote - WSL/SSH because the URI scheme isn't converted to `vscode-remote://` before file resolution.

## Best solution

In `TerminalUrlLinkOpener._openFileSchemeLink`, when `this._isRemote` is true, convert the `file://` URI to a `vscode-remote://` URI (using the remote authority from the environment service) before calling `_fileService.stat()` — mirroring the same conversion that `TerminalLinkResolver.resolveLink` already does at detection time.
