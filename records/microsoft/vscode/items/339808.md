# Issue #339808 — managed settings: stricter user setting not followed

[https://github.com/microsoft/vscode/issues/339808](https://github.com/microsoft/vscode/issues/339808)

## Summary

This is a real bug in managed sandbox policy resolution — a stricter local setting is being overridden by a more permissive managed policy, which contradicts the project's own documented invariant that 'managed permission never widens a local restriction.' The resolution logic itself runs inside the external Copilot SDK runtime, not in VS Code's own code, so this should stay open and be routed to the Agent Host/Copilot SDK owners rather than fixed here.

## Change summary

When a managed policy allows outbound network (`allowOutbound: true`) but the user's local setting disallows it (`chat.agent.sandbox.network.allowNetwork: false`), the sandbox still permits outbound network access instead of honoring the stricter local setting.

## Best solution

Fix belongs in the Copilot Agent Host SDK's managed-settings resolution (the logic that produces the `session.managed_settings_resolved` event): it must ensure a managed policy explicitly allowing an action never overrides an explicit, stricter local user setting, per the documented invariant in src/vs/platform/agentHost/AGENTS.md ('managed permission never widens a local restriction'). VS Code's own code (`projectCopilotSandboxPolicy` in copilotSandboxPolicy.ts) only forwards and projects whatever the SDK already resolved — it does not itself compute the merge.

## Evidence
