## Evidence

- **Confirmed symptom and workaround:** The discussion at https://github.com/microsoft/vscode/issues/170345 distinguishes two-finger tapping, which opens both menus, from physically clicking the trackpad, which avoids the problem. Commenters confirmed persistence on iPadOS 16.6 and 17.2; the February 2025 comment corroborates the workaround, not a complete fix.
- **Current editor cancellation path:** src/vs/editor/contrib/contextmenu/browser/contextmenu.ts, ContextMenuController._onContextMenu, calls e.event.preventDefault() and e.event.stopPropagation() before showing the custom menu for ordinary editor text. This matches the reporter's minimal cancellation example; source inspection alone cannot establish current iPadOS gesture behavior.
- **Open upstream regression:** https://bugs.webkit.org/show_bug.cgi?id=260722 is currently NEW and explicitly describes the native menu appearing over web-app menus, including vscode.dev. Its initial report and comment 4 document contextmenu preventDefault() failing, while comment 12 confirms reproduction in VSCode.dev, WKWebView and Google Docs.
- **Earlier upstream fix is insufficient:** https://bugs.webkit.org/show_bug.cgi?id=260722#c9 states that the earlier WebKit issue https://bugs.webkit.org/show_bug.cgi?id=244149 was fixed in iOS 16.2. Subsequent confirmations in this VS Code thread and the open upstream regression prevent treating that earlier fix as resolving the full report.
- **Canonical search:** https://github.com/microsoft/vscode/issues/170498 is open but newer and broadly evaluates iPad support; https://github.com/microsoft/vscode/issues/70764 requests iPad availability. An open-issue search for iPad context menus found https://github.com/microsoft/vscode/issues/125310, whose body concerns when a long-touch menu opens, not simultaneous native and editor menus.
