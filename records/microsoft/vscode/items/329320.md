# Issue #329320 — [Copilot Agent] Explicitly selected read toolset is omitted from tools passed to a third-party language model provider

[https://github.com/microsoft/vscode/issues/329320](https://github.com/microsoft/vscode/issues/329320)

## Summary

Detailed, forensic-quality repro (wire dumps, persisted-state inspection across two sessions) pointing to a real interaction bug between explicit toolset expansion and the virtual-tool grouping/trimming pipeline in the built-in Copilot extension; the mechanism is plausible in current main but I could not pin the exact faulty line, so this needs the tool-grouping owner to trace further rather than an automatic fix.

## Change summary

An explicitly `#read`-referenced toolset/tool is sometimes missing from the tools list handed to a third-party LanguageModelChatProvider on the initial Agent turn, though it appears correctly on later turns in some sessions.

## Best solution

Have the virtual-tools owner (extensions/copilot/src/extension/tools/common/virtualTools/toolGrouping.ts, defaultIntentRequestHandler.ts) trace why ensureExpanded()/ToolGroupingService session caching sometimes fails to surface an explicitly-referenced tool on the first compute — likely a name-matching or per-session-cache staleness issue between `ChatLanguageModelToolReference.name` and the tool tree built from `getAvailableTools()`.
