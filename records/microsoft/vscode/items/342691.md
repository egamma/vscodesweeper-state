# Issue #342691 — Shell init scripts for Copilot harness sessions don't work in remote windows

[https://github.com/microsoft/vscode/issues/342691](https://github.com/microsoft/vscode/issues/342691)

## Summary

Remote shell initialization remains unsupported on current main. This is a request to extend an explicitly local-only capability, not a regression; keep it open for an Agent Host design decision.

## Change summary

Allow remote Copilot harness shell commands to load the remote host's shell initialization when explicitly enabled.

## Best solution

Provide opt-in shell initialization on the executing remote host, using its platform and filesystem rather than the renderer's. Preserve existing local behavior and runtime permission enforcement.

- **Trace:**

  > AgentHostShellInitSynchronizer.register() returns immediately for remoteAuthority, while its shell and Python activation variable are selected from renderer isWindows. Its existing test explicitly expects no remote publication. AgentHostSessionHandler registers initialization only for LOCAL_AGENT_HOST_AUTHORITY and reconciles before dispatching turns. CopilotAgentSession._applyEffectiveShellInitScripts() materializes session-provided scripts and forwards them through shell.initScripts, but generates no profile-loading fallback when configuration is absent. The source conclusively establishes the local-only boundary, not the runtime's reported BASH_ENV filtering. https://github.com/microsoft/vscode/issues/334389 verifies local behavior only; https://github.com/microsoft/vscode/issues/334582 is a distinct sandbox visibility problem. Preserve host/client URI boundaries, local initialization, and runtime authorization; the remote support contract remains undecided.
- **Open decisions:**
