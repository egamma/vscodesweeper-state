# Issue #335460 — Updating external plugins broken for manual and AutoUpdates

[https://github.com/microsoft/vscode/issues/335460](https://github.com/microsoft/vscode/issues/335460)

## Summary

Thanks for the detailed report — the described gaps are confirmed by reading the current source in `pluginInstallService.ts`, `pluginMarketplaceService.ts`, and `pluginSources.ts`: external plugin repositories are never checked directly, the git-source update path skips cloning when a ref/sha change points at a not-yet-cached directory, and a `path` change updates content but leaves the installed-plugin index keyed on the old URI. This is a real, code-verified defect in a very recently added feature (agent plugin marketplace/auto-update), so it should stay open and be routed to the owning area rather than closed.

## Change summary

Manual and automatic plugin updates silently fail to update plugins whose source is an external Git repository (as opposed to the marketplace repo itself).

## Best solution

In `src/vs/workbench/contrib/chat/browser/pluginInstallService.ts` and `pluginSources.ts` (`AbstractGitPluginSource`), have the periodic check also poll each unique external source (not just the marketplace repo), allow `update()` to clone when the ref/sha-derived cache directory doesn't yet exist, and recompute the installed-plugin URI (via `getPluginSourceInstallUri`) instead of reusing `entry.pluginUri` when re-registering after an update so `installed.json` doesn't go stale.

## Evidence

- **marketplace-only check:** src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts `_doRunUpdateCheck` (around line 894-911) only calls `this._pluginRepositoryService.fetchRepository(ref)` on the marketplace reference itself; it never fetches the individual plugin's external git source, matching the report's claim #1.
- **no-clone-on-new-dir bug:** src/vs/workbench/contrib/chat/browser/pluginSources.ts `AbstractGitPluginSource.update()` (line 111-118) computes `repoDir` from the (possibly new ref/sha) descriptor and, if `!repoExists`, logs a warning and returns `false` without ever cloning — confirming claim #3.
- **gate + force:** src/vs/workbench/contrib/chat/browser/pluginInstallService.ts line 453 `if (!livePlugin || !hasSourceChanged(...)) continue;` gates ALL non-package updates on `hasSourceChanged`, and `options.force` is only consulted later for npm/pip version bumps (line 459), never to bypass this gate for git sources — confirming claim #2.
- **stale installed URI:** pluginInstallService.ts line 480 calls `addInstalledPlugin(entry.pluginUri, livePlugin)` reusing the OLD pluginUri after a successful git update, instead of recomputing via `getPluginSourceInstallUri(livePlugin.sourceDescriptor)` as the package-plugin path does at line 500-501 — confirming claim #4 about `path` changes leaving `installed.json` stale.
