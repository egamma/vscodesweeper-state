# Issue #280918 — Detect and handle when a Copilot terminal has been interacted with by the user in such a way that breaks command execution

[https://github.com/microsoft/vscode/issues/280918](https://github.com/microsoft/vscode/issues/280918)

## Summary

Keep the accepted terminal-recovery request open. Current source has prompt waiting and alternate-buffer detection, but neither establishes safe handling of a user-started interactive program in a reused agent terminal; both linked fix attempts closed without merging.

## Change summary

Detect when user interaction leaves an agent terminal unable to accept shell commands, and handle subsequent agent execution safely.

## Best solution

Provide explicit handling of user-occupied terminals in the chat terminal execution path without blindly sending shell commands into an interactive application. The terminal owner should settle whether execution waits, reports the conflict, or uses another terminal; the reported crash also needs retesting with the supplied ncdu scenario.
