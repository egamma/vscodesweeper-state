# Issue #288450 — Git actions fail to work when Git for Windows is installed with Use external OpenSSH option

[https://github.com/microsoft/vscode/issues/288450](https://github.com/microsoft/vscode/issues/288450)

## Summary

The native Windows OpenSSH incompatibility remains in current source: Git UI operations force an SSH askpass helper that is a shell script, matching the reported executable-format failure. The matching older report was closed without a fix, so it is not a duplicate target.

## Change summary

Git push and pull fail through Source Control when Git for Windows uses native Windows OpenSSH, although the same commands succeed in the terminal.

## Best solution

Make the built-in Git authentication integration compatible with native Windows OpenSSH while preserving bundled Git OpenSSH and HTTPS authentication. Establish Windows coverage for native askpass invocation and Windows ssh-agent authentication before landing the change.

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `extensions/git/src/askpassManager.ts`, `extensions/git/src/ssh-askpass.sh`, `extensions/git/src/main.ts`, `extensions/git/src/test/askpassManager.test.ts`
- **Validation:** On Windows 11, install Git for Windows with external OpenSSH, confirm the selected ssh.exe and working terminal authentication, then perform Source Control pull and push against an SSH remote. Require successful authentication without CreateProcessW error 193; cover an agent-loaded key and a passphrase prompt, and repeat with Git's bundled OpenSSH and an HTTPS remote to check preserved behavior.
- **Behavior:**

  > Source Control push and pull must work when Git for Windows uses native Windows OpenSSH and the same repository authenticates successfully from the terminal. VS Code must not force an authentication helper that native OpenSSH cannot execute. Acceptance should cover Windows ssh-agent authentication and a passphrase-protected key requiring interaction. Existing bundled OpenSSH and HTTPS authentication must remain functional.
- **Trace:**

  > Askpass in extensions/git/src/askpass.ts forces SSH_ASKPASS_REQUIRE and supplies a helper path ending in ssh-askpass.sh. getAskpassPaths() in extensions/git/src/askpassManager.ts preserves that shell-script format even when copying files into Windows user storage. extensions/git/src/main.ts passes the environment into Git, whose spawn() in extensions/git/src/git.ts applies it to UI operations; terminal environments omit these SSH overrides. The identical native Windows executable-format failure was independently diagnosed at https://github.com/microsoft/vscode/issues/172674#issuecomment-1489630187. This establishes the incompatible launch boundary, but Windows execution and compatibility coverage remain to be designed and exercised. Preserve HTTPS handling, bundled OpenSSH behavior, and existing askpass storage guarantees; unrelated FIDO prompt parsing in https://github.com/microsoft/vscode/pull/299382 is outside this defect.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/288450 reports selecting Git for Windows' external OpenSSH option and then pushing or pulling an SSH remote. The reporter confirmed failure on 1.108.1 with CreateProcessW error 193 and ssh_askpass: posix_spawnp, while the identical terminal command succeeds.
- **Current source path:** extensions/git/src/askpass.ts constructs SSH_ASKPASS from askpassPaths.sshAskpass and sets SSH_ASKPASS_REQUIRE='force'; getEnv() includes both when integrated askpass is enabled. extensions/git/src/main.ts passes that environment to Git, and Git.spawn() in extensions/git/src/git.ts merges it into subprocess environments.
- **Incompatible helper remains:** extensions/git/src/askpassManager.ts returns ssh-askpass.sh on both installed-Windows and fallback paths. extensions/git/src/ssh-askpass.sh begins with #!/bin/sh and invokes shell utilities; it is not a native Windows executable. Copying it to stable storage does not change that executable-format incompatibility. getTerminalEnv() omits the SSH overrides, explaining the UI/terminal difference.
- **Independent matching diagnosis:** https://github.com/microsoft/vscode/issues/172674#issuecomment-1489630187 reproduces the same CreateProcessW error 193 with native Windows OpenSSH and records SSH_ASKPASS pointing at VS Code's ssh-askpass.sh, identifying ERROR_BAD_EXE_FORMAT. That issue was automatically closed for missing information, not fixed or substantively declined: https://github.com/microsoft/vscode/issues/172674#issuecomment-1627687353.
- **Canonical search:** Searches for external OpenSSH, CreateProcessW error 193, and Windows SSH_ASKPASS found no verified open canonical for this symptom. https://github.com/microsoft/vscode/issues/164402 is open and older, but concerns FIDO/U2F prompts being misclassified as host-authenticity dialogs, not native Windows failure to launch the helper; it does not satisfy the re-review duplicate bar.
- **Related implementation is distinct:** https://github.com/microsoft/vscode/pull/299382 is open and addresses keyboard-interactive prompt parsing inside handleSSHAskpass(), referencing https://github.com/microsoft/vscode/issues/276691. It does not reference this issue or address launching the shell helper through native Windows OpenSSH.
- **Inspection limits:** The checkout is shallow, so its local log cannot establish historical fix provenance. Inspection was read-only; no Windows execution or tests were performed, and the checkout remained clean. The matching independent diagnosis and unchanged helper wiring establish the source-level defect, not a newly executed Windows reproduction.
