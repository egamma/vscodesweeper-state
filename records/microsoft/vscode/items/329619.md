# Issue #329619 — AHP listSessions ignores limit and cursor pagination parameters

[https://github.com/microsoft/vscode/issues/329619](https://github.com/microsoft/vscode/issues/329619)

## Summary

Real, source-confirmed bug: the AHP `listSessions` handler drops the typed `limit`/`cursor` params entirely and always returns the full catalogue, contradicting the documented paginated protocol. A maintainer comment confirms the impact and notes a full fix needs SDK-level support, so this should be routed to the agent-host-protocol area rather than auto-fixed.

## Change summary

AHP `listSessions` accepts `limit`/`cursor` per the documented protocol but the server handler ignores both and always returns every session with no `nextCursor`.

## Best solution

Implement pagination in `ProtocolServerHandler.listSessions` (bounding the wire response first), then thread `limit`/`cursor` through `IAgentService.listSessions()` and its providers so the full catalogue isn't always enumerated — as connor4312 notes, at minimum a fast first-page load would help large session stores.
