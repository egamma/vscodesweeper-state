# Issue #331054 — Applying a directory C&P feature inside the editor

[https://github.com/microsoft/vscode/issues/331054](https://github.com/microsoft/vscode/issues/331054)

## Summary

This is a valid Explorer feature request, but current VS Code already covers path copying and persistent collections of selected folders; the remaining request is a distinct, system-wide filesystem tree that needs Explorer-area product review.

## Change summary

Add an optional Explorer surface for browsing the entire filesystem, copying directory paths, and persisting collections of directories between sessions.

## Best solution

Preserve the workspace-scoped Explorer model and evaluate whether any remaining navigation gap warrants a lightweight addition or extension API. Existing multi-root `.code-workspace` files should remain the primary way to persist and revisit selected project directories.

## Vision fit

- **Fit:** rejected
- **Reason:** Bundling a second, system-wide file manager for a niche workflow cuts against the lightweight default experience and duplicates capabilities already provided through workspaces and the operating system.
- **Evidence:** Values and guardrails: “Out of the box, VS Code is a text editor: lightweight and fast” and “The power lives in extensions.”

  > Thanks for the request. VS Code currently supports copying the active file path, adding multiple roots with **Add Folder to Workspace...**, and saving those roots in a `.code-workspace` file. The remaining proposal—a persistent Explorer tree for the entire filesystem—is distinct from those workspace-scoped features and should be evaluated by the Explorer area.

## Evidence

- **existing path commands:** src/vs/workbench/contrib/files/browser/fileActions.contribution.ts registers “Copy Path,” “Copy Relative Path,” and “Copy Path of Active File,” including Copy Path in the editor-title context menu.
- **existing multi-root workflow:** src/vs/workbench/browser/actions/workspaceCommands.ts registers `addRootFolder` as “Add Folder to Workspace...” and permits selecting multiple folders for the Explorer.
- **existing persistence:** src/vs/workbench/browser/actions/workspaceActions.ts registers `workbench.action.saveWorkspaceAs`, while the workspace service persists selected roots in `.code-workspace` files.
- **remaining gap:** The existing commands expose chosen workspace roots rather than a continuously browsable whole-system filesystem tree, so they are substantial coverage but not full implementation of the request.
- **canonical search:** Repository searches for an entire-filesystem Explorer found no open canonical issue owning this full request; https://github.com/microsoft/vscode/issues/43188 concerns opening multiple workspaces in one window and does not cover a global filesystem tree.
