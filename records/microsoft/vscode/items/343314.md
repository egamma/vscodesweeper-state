## Summary

The service-install argument mismatch is confirmed in current main: the editor passes --user-data-dir where the Rust CLI does not accept it. Keep this open for a bounded correction; the session-tunnel fallback does not deliver the requested persistent service.

## Change summary

## Best solution

Make the editor's service-install invocation conform to the Rust CLI contract, while preserving user-data-directory handling for session tunnels and fallback behavior for genuine installation failures. Cover the caller/parser boundary so a mocked successful spawn cannot conceal unsupported arguments.
