# Issue #343314 — Remote Tunnel: "Turn on for all sessions (install as a service)" fails because _installService passes unsupported --user-data-dir flag

[https://github.com/microsoft/vscode/issues/343314](https://github.com/microsoft/vscode/issues/343314)

## Summary

The service-install failure remains source-reproducible on current main: the coordinator supplies --user-data-dir after the install subcommand, whose parser does not accept it. Keep this open as a bounded core Remote Tunnel bug.

## Change summary

Installing Remote Tunnel Access for all sessions fails argument parsing and silently loses the requested persistent-service behavior through an in-session fallback.

## Best solution

Make the desktop service-install invocation compatible with the Rust CLI contract, with regression coverage that checks parser acceptance rather than only mocked arguments. Preserve session-only directory selection and fallback behavior for genuine installation failures.
