# Issue #343314 — Remote Tunnel: "Turn on for all sessions (install as a service)" fails because _installService passes unsupported --user-data-dir flag

[https://github.com/microsoft/vscode/issues/343314](https://github.com/microsoft/vscode/issues/343314)

## Summary

The service-install argument mismatch remains on current main: selecting installation for all sessions passes an option the install subcommand does not accept. Keep this team-authored report open; no fixing commit or verified canonical was found.

## Change summary

Installing Remote Tunnel Access as a service fails on an unsupported --user-data-dir argument and falls back to an in-session tunnel.

## Best solution

Make the desktop service-install invocation conform to the Rust CLI argument contract while preserving in-session user-data-directory handling and genuine installation-failure fallback. Regression coverage should check CLI acceptance, not merely assert the mocked argument list.
