# Issue #328536 — C: `restrict` coloured wrong twice

[https://github.com/microsoft/vscode/issues/328536](https://github.com/microsoft/vscode/issues/328536)

## Summary

The current vendored C TextMate grammar can misclassify `restrict` as a probable parameter. This is an upstream grammar defect that should remain open and be routed to basic language support.

## Change summary

Color the C `restrict` qualifier consistently as a language keyword rather than as an identifier.

## Best solution

Fix the parameter heuristic in jeff-hykin/better-c-syntax so it excludes C keywords without breaking declarations such as `void *restrict (p);`, then update VS Code's vendored C grammar.
