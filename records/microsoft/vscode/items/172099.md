# Issue #172099 — Variables `relativeFile` and `relativeFileDirname` use backslashes in WSL when used in keyboard shortcuts

[https://github.com/microsoft/vscode/issues/172099](https://github.com/microsoft/vscode/issues/172099)

## Summary

Confirmed bug still present on main: the sendSequence command resolves variables in the renderer process using the local platform's path module, so `relativeFile`/`relativeFileDirname` get Windows backslashes even in WSL sessions. An open PR (#310771) is attempting to fix this.

## Change summary

Variables `relativeFile` and `relativeFileDirname` produce backslash-separated paths in WSL terminal sessions because variable resolution uses the local (Windows) path separator rather than the remote (Linux) one.

## Best solution

Land or iterate on the open PR https://github.com/microsoft/vscode/pull/310771, which should ensure the variable resolver uses posix path separators when the terminal session targets a non-Windows remote (WSL/SSH). The alternative approach noted by @alexr00 — resolving variables in the extension host (which runs on the remote) rather than the renderer — would also fix this more generally.
