# Issue #129178 — Unable to use shortcuts like Cmd+A, Cmd+C, Cmd+V inside an iframe inside a webview on macOS

[https://github.com/microsoft/vscode/issues/129178](https://github.com/microsoft/vscode/issues/129178)

## Summary

Still reproduces on main. On macOS, `setIgnoreMenuShortcuts(true)` suppresses native Cmd+shortcuts when a webview has focus, and VS Code's `execCommand` dispatch targets only the top-level webview content document — never reaching user-created nested iframes. The keyboard interception and command dispatch paths are unchanged.

## Change summary

Keyboard shortcuts like Cmd+A, Cmd+C, Cmd+V do not work inside iframes nested within webviews on macOS because VS Code intercepts them and dispatches execCommand only to the top-level webview content frame.

## Best solution

When VS Code dispatches `execCommand` back to the webview (line ~1266 of `pre/index.html`), the command targets `target.contentDocument` — the VS Code-managed content iframe. On macOS this is the only path for copy/paste/selectAll since native menu shortcuts are suppressed. The fix needs to either (a) forward the `execCommand` to the currently focused nested iframe (cross-origin restrictions make this hard) or (b) avoid calling `setIgnoreMenuShortcuts(true)` for these specific shortcuts so the OS can deliver them natively into the focused nested iframe — similar to the non-Electron path at line 600–601. The `help wanted` label is appropriate given the complexity.

## Evidence

- **macOS interception path:** src/vs/workbench/contrib/webview/electron-browser/windowIgnoreMenuShortcutsManager.ts calls `setIgnoreMenuShortcuts(true)` on webview focus (line 31), preventing macOS from delivering Cmd+shortcuts natively to the focused element.
- **execCommand target:** src/vs/workbench/contrib/webview/browser/pre/index.html line 1261–1266: the `execCommand` handler targets `getActiveFrame().contentDocument` — the VS Code-managed content iframe, not any user-created nested iframe inside it.
- **handleInnerKeydown:** pre/index.html lines 590–607: on Electron, `isCopyPasteOrCut(e)` calls `e.preventDefault()` (line 599), blocking browser-native handling; on non-Electron the browser handles it (line 601), which is why the web version works.
- **no fix on main:** git log on the webview pre/index.html and webviewElement.ts shows no commits addressing nested-iframe keyboard dispatch; the interception and dispatch paths are unchanged.
