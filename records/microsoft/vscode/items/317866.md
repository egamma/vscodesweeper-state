# Issue #317866 — Multiple vcode server services running after SSH connection.

[https://github.com/microsoft/vscode/issues/317866](https://github.com/microsoft/vscode/issues/317866)

## Summary

This is a Remote SSH extension issue — orphaned server processes after disconnect are owned by the Remote Development extension, which has its own active tracker at microsoft/vscode-remote-release. The issue should be moved there, where a closely related report (vscode-remote-release#10730) is already open.

## Change summary

VS Code Remote SSH leaves orphaned server processes (powershell, code-server) on the remote Windows machine after disconnecting, accumulating with each reconnect.

## Best solution

Move this issue to https://github.com/microsoft/vscode-remote-release where the Remote SSH team owns process lifecycle management. The reporter's scenario is closely related to https://github.com/microsoft/vscode-remote-release/issues/10730 (zombie/lingering server processes), which tracks the same class of cleanup failures. The Remote team can evaluate whether to consolidate or track the Windows-specific variant separately.
