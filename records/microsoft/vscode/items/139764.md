# Issue #139764 — Build does not wait for files to save

[https://github.com/microsoft/vscode/issues/139764](https://github.com/microsoft/vscode/issues/139764)

## Summary

The defect remains on current main: debug startup waits for the initial save attempt but discards its unsuccessful result, then continues while an elevated retry runs separately. The issue should remain open pending a maintainer decision on whether failed saves abort, prompt, or suspend and resume debugging.

## Change summary

Prevent build and debug startup from proceeding against stale editor contents while a permission-denied save awaits an elevated retry.

## Best solution

Define one consistent save-failure policy for debug start and restart so pre-launch tasks never run against stale contents unless the user explicitly chooses to continue, with well-defined behavior for elevated retry and cancellation.

- **Behavior:**

  > Starting or restarting debugging with dirty editors must not silently build and run stale contents after a save fails. A permission-denied save must reach an explicit user outcome before pre-launch tasks or the debug adapter proceed. Successful saves and `debug.saveBeforeStart: none` must retain their existing behavior. Cancellation or dismissal must have a defined result and must not leave an indefinitely pending debug start.
- **Trace:**

  > `saveAllBeforeDebugStart` in src/vs/workbench/contrib/debug/common/debugUtils.ts awaits `IEditorService.saveAll()` but discards its structured `success` result. The helper is used by initial startup and restart paths in debugService.ts and by the F5 command in debugCommands.ts, after which execution continues. The elevated retry in StoredFileWorkingCopy.doHandleSaveError is launched later from a notification action and is not part of the original save promise. Commit https://github.com/microsoft/vscode/commit/42a43ebbd9a15cdf17a7ad577750981829a46490 fixed failure propagation but not these callers. Preserve successful-save behavior, untitled-editor handling, configuration reload, and the `debug.saveBeforeStart: none` opt-out; uncertainty begins at the user-visible policy for an unsuccessful save.
- **Open decisions:**
  - When the pre-debug save fails, should VS Code abort startup, ask whether to start anyway, or keep startup pending and resume only after a successful retry?
  - If startup waits for an elevated retry, what should happen when the save notification is dismissed or elevation is canceled?
  - Should the selected policy apply identically to initial start, explicit restart, and command-driven start paths?
