# Issue #138546 — [json] open definition in JSON document to navigate to the schema definition

[https://github.com/microsoft/vscode/issues/138546](https://github.com/microsoft/vscode/issues/138546)

## Summary

The requested JSON instance-to-schema navigation remains unimplemented on current main, and a maintainer explicitly endorsed the experience. The Backlog milestone is a holding bin rather than a close blocker, but the concrete source gap and lack of an older canonical support keeping this feature request open.

## Change summary

Provide Go to Definition from a property in a JSON document to the corresponding property declaration in its associated JSON schema.

## Best solution

Implement definition resolution in microsoft/vscode-json-languageservice, then advertise and handle the LSP definition capability in the built-in JSON language server. A design pass should first settle ambiguous-schema behavior and whether reverse schema-to-instance navigation belongs in the initial scope.

## Plan brief

- **Likely files:** `extensions/json-language-features/server/src/jsonServer.ts`, `extensions/json-language-features/server/package.json`
- **Validation:** Add definition-resolution tests in microsoft/vscode-json-languageservice covering a property backed by a local schema and a property reached through `$ref`, then add or extend a JSON language-server protocol test asserting that textDocument/definition returns the schema URI and property range.
- **Behavior:**

  > Go to Definition on a property name in a JSON instance associated with a schema should navigate to that property's declaration in the schema. The target must identify the schema resource and the declaration range, including definitions reached through `$ref`. Documents with no matching schema declaration should return no definition without affecting validation, hover, completion, or existing document-link behavior. The plan must define the observable result when multiple schemas match and decide whether reverse schema-to-instance navigation is part of this issue.
- **Trace:**

  > The built-in server in extensions/json-language-features/server/src/jsonServer.ts creates `vscode-json-languageservice`, but its advertised capabilities omit `definitionProvider` and it has no `connection.onDefinition` handler. The dependency's public `LanguageService` interface already exposes `findDefinition`, yet https://github.com/microsoft/vscode-json-languageservice/blob/main/src/jsonLanguageService.ts currently implements it as an empty result, so wiring the server alone cannot satisfy the request. The work therefore crosses the language-service repository and the dependency integration in this checkout. Existing `$ref` document links, validation, hover, and completion behavior must remain unchanged. No older canonical issue or open fixing PR was identified.
- **Open decisions:**
  - When `anyOf`, `oneOf`, `allOf`, or multiple associated schemas produce several matching property declarations, should Go to Definition return every valid target or choose one preferred target?
  - Should the initial feature cover only JSON instance-to-schema navigation described by the title and reproduction, or also schema-to-instance navigation requested later in the discussion?

## Evidence

- **maintainer position:** In https://github.com/microsoft/vscode/issues/138546, a VS Code maintainer states that JSON document-to-schema navigation is not available and twice describes it as a desirable experience.
- **current server gap:** extensions/json-language-features/server/src/jsonServer.ts does not advertise `definitionProvider` in its server capabilities and registers no `connection.onDefinition` handler, while the neighboring HTML and CSS language servers do.
- **language-service gap:** The current microsoft/vscode-json-languageservice API declares `findDefinition`, but its implementation is still the no-op `findDefinition: () => Promise.resolve([])` in https://github.com/microsoft/vscode-json-languageservice/blob/main/src/jsonLanguageService.ts.
- **canonical search:** Searches for JSON schema navigation, Go to Definition, schema definitions, and cross-navigation found no older open microsoft/vscode issue reporting the same observable request; the supplied candidate issues are unrelated.
- **existing capability check:** The JSON extension contributes validation, completion, hover, symbols, links, formatting, colors, folding, and selection ranges, but neither extensions/json-language-features/package.json nor the server registration exposes definition navigation.
