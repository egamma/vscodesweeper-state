# Issue #171040 — Automatic enter indentation in offside folding languages

[https://github.com/microsoft/vscode/issues/171040](https://github.com/microsoft/vscode/issues/171040)

## Summary

Legitimate feature request: VS Code's auto-indent engine does not leverage the `offSide` folding property for Enter-key indentation in indentation-based languages like Python. The `offSide` flag exists in `FoldingRules` but is only consumed by folding and indent-guide code, not by `autoIndent.ts`. This is a real gap, not a bug — the auto-indent system was designed around bracket-based languages. Stays open as a feature request.

## Change summary

Auto-indentation on Enter should infer the correct indent level in offside-rule languages (e.g. Python) based on surrounding indentation context, similar to how it works in bracket-based languages like TypeScript.

## Best solution

Extend the auto-indent logic in `src/vs/editor/common/languages/autoIndent.ts` to consult `FoldingRules.offSide` when computing inherited indentation on Enter, so that pressing Enter inside an indentation-scoped block infers the correct indent level from surrounding lines. The broader tree-sitter indentation effort (https://github.com/microsoft/vscode/issues/208985) would also solve this but is a much larger undertaking. In the meantime, Pylance's format-on-type provider serves as a workaround for Python specifically.

## Evidence

- **offSide not used in autoIndent:** `rg -n offSide src/vs/editor/common/languages/autoIndent.ts` returns zero hits — the offSide folding property is defined in `languageConfiguration.ts` but only consumed by folding (`indentRangeProvider.ts`) and indent guides (`guidesTextModelPart.ts`), not by the auto-indent engine.
- **related broader effort:** https://github.com/microsoft/vscode/issues/208985 tracks declarative tree-sitter-based indentation rules, which would broadly improve indentation for languages like Python but is a larger architectural change.
- **current workaround:** The Python extension (Pylance) provides indentation corrections via format-on-type for the Enter key, as described in issue #208985's body — a practical but imperfect workaround.
- **classification:** Labeled `bug` but this is a feature gap: the auto-indent engine was designed for bracket-based languages and never claimed to handle offside languages. Should be reclassified as `feature-request`.
