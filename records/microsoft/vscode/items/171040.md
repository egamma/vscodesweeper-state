# Issue #171040 — Automatic enter indentation in offside folding languages

[https://github.com/microsoft/vscode/issues/171040](https://github.com/microsoft/vscode/issues/171040)

## Summary

Keep open: existing auto-indent modes do not infer indentation from the surrounding offside block when Enter is pressed on an unindented blank line. The source still shows this capability gap, and the older related requests inspected do not report the same observable behavior.

## Change summary

Infer indentation when pressing Enter on an unindented blank line inside an offside-language block that continues below the cursor.

## Best solution

Make Enter indentation recognize blank lines within continuing offside blocks in the editor's indentation handling, while preserving the ability to start a dedented block after the existing block ends.

## Evidence

- **Reported scope:** https://github.com/microsoft/vscode/issues/171040 specifically requests Enter indentation on an unindented blank line when another indented statement continues the block below; it explicitly distinguishes this from blank lines after a block.
- **Current Python configuration:** extensions/python/language-configuration.json declares folding.offSide=true and an onEnterRules rule for block headers ending in a colon, but no indentationRules. An empty line does not match that header rule.
- **Current Enter path:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts:589-665, TypeOperations._enter, first consults getEnterAction and then getIndentForEnter. src/vs/editor/common/languages/autoIndent.ts:305-355 returns null when the language lacks indentationRules; the remaining fallback copies the current line's indentation. For the bundled Python configuration, an unindented empty line therefore remains unindented rather than consulting the following statement.
- **Existing-capability check:** src/vs/editor/common/config/editorOptions.ts:6158-6173 registers editor.autoIndent with full as the default and maximum strategy; it combines existing language rules rather than offering offside-block inference. src/vs/editor/common/model/guidesTextModelPart.ts:471-590 already considers content above and below whitespace lines for indentation guides, but the inspected Enter path does not use that inference.
