# Issue #334574 — Agent shell tool sandbox fails with "bwrap: setting up uid map: Permission denied"

[https://github.com/microsoft/vscode/issues/334574](https://github.com/microsoft/vscode/issues/334574)

## Summary

Fresh, team-authored bug report (filed same day, testing a related sandboxing issue) with no fix yet on main — keep open regardless of staleness per the team-authored protection rule; no reproduction was attempted here since it depends on a specific Linux user-namespace/apparmor environment.

## Change summary

Enabling agent shell tool sandboxing on Linux causes bwrap to fail with 'setting up uid map: Permission denied', blocking the sandboxed command from starting at all.

## Best solution

Have the sandbox capability check (SandboxHelperService._probeBubblewrap / _resolveAppArmorRestriction in src/vs/platform/sandbox/node/sandboxHelper.ts) and TerminalSandboxEngine's dependency gate (src/vs/platform/sandbox/common/terminalSandboxEngine.ts) also catch this uid-map failure mode before attempting the real run, and decide on a graceful fallback (skip sandboxing with a warning, or surface a clear error) rather than letting the raw bwrap stderr propagate to the user.
