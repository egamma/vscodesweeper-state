# Issue #334574 — Agent shell tool sandbox fails with "bwrap: setting up uid map: Permission denied"

[https://github.com/microsoft/vscode/issues/334574](https://github.com/microsoft/vscode/issues/334574)

## Summary

Current main already has dedicated handling for exactly this failure mode (AppArmor-restricted unprivileged user namespaces breaking bwrap's uid map setup), including a prereq check that surfaces a remediation instead of the raw bwrap crash and an automatic 'weaker nested sandbox' fallback on retry — but this is a team-authored test issue, and without deeper git history (shallow checkout, single commit) I can't cite a fix commit that references #334574, so the completion close bar isn't met.

## Change summary

Enabling agent shell tool sandboxing on Linux distros that restrict unprivileged user namespaces (AppArmor `apparmor_restrict_unprivileged_userns=1`, common on Ubuntu 23.10+/24.04, Debian, RHEL, Arch) makes bwrap fail with 'setting up uid map: Permission denied', so the sandboxed command never runs.

## Best solution

Confirm the existing TerminalSandboxEngine.checkForSandboxingPrereqs() flow (apparmorRestrictsUnprivilegedUserNamespaces detection → Bubblewrap remediation surfaced to the user → automatic enableWeakerNestedSandbox fallback on retry) actually resolves this exact repro end-to-end on an AppArmor-restricted box, then close with a cited commit once confirmed.
