# Issue #336440 — Allow configuring the maximum number of concurrent subagents

[https://github.com/microsoft/vscode/issues/336440](https://github.com/microsoft/vscode/issues/336440)

## Summary

Real request, but the concurrency cap and the API to unlock it (TaskRegistry, setSubAgentLimiter, updateSubAgentMaxConcurrent) live in the external @github/copilot-sdk / copilot-cli runtime that the Agent Host's Copilot provider wraps — not in this repo — so this is upstream rather than something VS Code core can fix alone.

## Change summary

Expose a setting to raise the hardcoded cap of concurrently running Copilot subagents (currently 4, global across the whole agent tree).

## Best solution

The fix belongs primarily in @github/copilot-sdk / github/copilot-cli: honor a configurable concurrency limit and relax the billing-tier gate that currently clamps it even when users raise `subagents.maxConcurrency` in `~/.copilot/settings.json`. Once that lands, VS Code could add a passthrough setting alongside the existing `chat.subagents.*` options in chat.shared.contribution.ts.
