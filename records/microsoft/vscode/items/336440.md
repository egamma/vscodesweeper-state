# Issue #336440 — Allow configuring the maximum number of concurrent subagents

[https://github.com/microsoft/vscode/issues/336440](https://github.com/microsoft/vscode/issues/336440)

## Summary

This is a distinct, currently unsupported subagent configuration request. Route it to the chat-subagents area to decide the limiter's scope, safe range, and SDK plumbing.

## Change summary

Allow users to configure the Copilot CLI runtime's maximum concurrent subagent count instead of always using its plan-derived limit of four.

## Best solution

Expose a bounded advanced setting while preserving the current default, pass it through the Copilot CLI session-manager boundary, and document whether the configured budget applies process-wide, per session, or per agent tree. Invalid or excessive values should have explicit, predictable behavior rather than silently changing the effective limit.

- **Likely files:** `extensions/copilot/src/platform/configuration/common/configurationService.ts`, `extensions/copilot/package.json`, `extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts`, `extensions/copilot/src/extension/chatSessions/copilotcli/node/test/copilotCliSessionService.spec.ts`

- **Behavior:**

  > Users can configure the maximum number of concurrently running Copilot CLI subagents, while installations without the setting retain today's effective limit. The setting has a documented supported range and predictable handling for invalid or excessive values. Its scope—process-wide, per session, or per agent tree—is explicit, and unrelated sessions behave according to that contract. Acceptance includes tests for the default, a non-default valid value, and boundary values.
- **Trace:**

  > Current main exposes subagent settings through src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts and ChatConfiguration, but none controls concurrency. The Copilot CLI integration constructs internal.LocalSessionManager and creates SDK sessions in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts; createSessionsOptions() currently passes no concurrency option or limiter. Extension-owned settings are declared through ConfigKey.Advanced in extensions/copilot/src/platform/configuration/common/configurationService.ts and contributed in extensions/copilot/package.json. The exact TaskRegistry limiter implementation is inside the @github/copilot SDK dependency rather than this checkout, so the plan must confirm the supported SDK API before settling the plumbing. Do not conflate this request with the local runSubagent nesting-depth implementation or the live-panel work in https://github.com/microsoft/vscode/issues/288048.
- **Open decisions:**
  - Should the configured concurrency budget apply process-wide, independently per chat session, or independently per agent tree?
  - What minimum and maximum values are supported, and should an out-of-range value be rejected with an error or clamped with a visible warning?
  - Should changing the setting update active session managers immediately or apply only to sessions created afterward?
  - Should the public setting live under the core chat.subagents namespace or the Copilot CLI-specific github.copilot.chat.cli namespace?
