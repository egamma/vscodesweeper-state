## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalProcessManager.ts`, `src/vs/workbench/contrib/terminal/browser/terminalService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalGroup.ts`, `src/vs/workbench/contrib/terminal/browser/terminalEditorSerializer.ts`, `src/vs/workbench/contrib/terminal/browser/agentHostPty.ts`, `src/vs/workbench/contrib/terminal/test/browser/terminalService.test.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-terminal/actions.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-terminal/state.ts`
- **Validation:** Retain the existing 'persistent title and icon updates' tests in terminalService.test.ts. For each audited backend path requiring a change, add executable coverage with a custom PTY that has a numeric id but no pty-host registration, asserting it does not address that id through the normal backend; paired regular-terminal cases must preserve existing metadata and persistence behavior. If icon synchronization is approved, include protocol-to-client update coverage and compatibility checks.
- **Behavior:**

  > A custom PTY's numeric process identifier must not imply that the normal pty host owns that process. Backend-only operations must respect actual ownership, while regular workbench terminal metadata updates and persistence continue unchanged. The audit must distinguish already-safe paths from paths requiring changes rather than treating every identifier use as a defect. Dynamic Agent Host icon behavior needs an explicit decision about whether updates remain client-local or propagate between host and clients.
- **Trace:**

  > TerminalProcessManager.persistentProcessId returns the child process id for both backend-created and custom processes, while createProcess bypasses backend creation for customPtyImplementation. AgentHostPty supplies an instance id to BasePty and opts out of persistence. TerminalService._updateTitle and _updateIcon already exclude custom PTYs following https://github.com/microsoft/vscode/pull/316482; preserve that behavior and its paired regular/custom tests. TerminalService._saveState, TerminalGroup.getLayoutInfo, and TerminalEditorSerializer are identified identifier consumers for further ownership analysis, not confirmed defects. AgentHostPty consumes TerminalTitleChanged, but the generated terminal protocol state/actions expose no corresponding icon contract. Any protocol work must originate in the source protocol repository and be synchronized, not edited directly in generated files. Do not conflate this audit with archived-session shell retention tracked by https://github.com/microsoft/vscode/issues/329316.
- **Open decisions:**
  - Should dynamic Agent Host terminal icons remain client-local, or become host/client-synchronized terminal metadata through an explicit protocol contract?
