# Issue #278657 — Clicking on path in exception traceback shows error on remote Windows

[https://github.com/microsoft/vscode/issues/278657](https://github.com/microsoft/vscode/issues/278657)

## Summary

Still reproduces on main: the notebook output link detection uses the client's navigator.userAgent to choose between Windows and POSIX path regexes, so when SSH'ing from macOS to a Windows remote, Windows paths in tracebacks are either not linkified or incorrectly handled.

## Change summary

Clicking on Windows file path links in notebook exception tracebacks fails when connected to a remote Windows server from a non-Windows client.

## Best solution

The PATH_LINK_REGEX in extensions/notebook-renderers/src/linkify.ts should match both Windows and POSIX paths regardless of the client platform (or the remote OS info should be passed in). The link handler also needs to construct a proper vscode-remote URI for the path rather than setting href to the raw filesystem path.
