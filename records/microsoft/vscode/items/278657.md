# Issue #278657 — Clicking on path in exception traceback shows error on remote Windows

[https://github.com/microsoft/vscode/issues/278657](https://github.com/microsoft/vscode/issues/278657)

## Summary

Keep open: the current notebook link handler interprets Windows drive paths using the macOS client's path rules, leaving a source-confirmed failure in this cross-platform remote scenario. The linked older report is closed and does not establish that remote Windows navigation was fixed.

## Change summary

Open Windows traceback file links on the remote host when a notebook is accessed from macOS over SSH.

## Best solution

Notebook output navigation should resolve the traceback's Windows file path against the remote filesystem and open the referenced line, without treating its drive letter as a URI scheme. Preserve existing local, relative-path, notebook-cell, and external-link behavior.
