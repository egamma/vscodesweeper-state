# Issue #232364 — Git - Jump between previous and next version in git

[https://github.com/microsoft/vscode/issues/232364](https://github.com/microsoft/vscode/issues/232364)

## Summary

Keep open: Timeline provides file-history comparisons, but the inspected commands do not provide editor-context navigation between successive file revisions. The Git maintainer explicitly reopened this request for consideration, and it is accepted in Backlog despite its low upvote count.

## Change summary

Provide bindable commands to navigate backward and forward through a file's Git revisions without requiring GitLens.

## Best solution

Expose lightweight previous/next file-revision navigation in the built-in Git extension, using existing file-history capabilities. Agree on whether navigation presents individual snapshots or adjacent-revision comparisons before implementation; default keyboard bindings are not necessary to satisfy the clarified request.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/src/commands.ts`, `extensions/git/src/timelineProvider.ts`, `extensions/git/src/repository.ts`
- **Validation:** In a temporary repository with three commits modifying one file, bind the proposed commands to custom shortcuts and verify backward/forward traversal visits the expected file revisions in order. Check both history endpoints, invocation from the working file and a historical editor, and that navigation does not modify working-tree contents. Confirm existing Timeline comparisons still work.
- **Behavior:**

  > A user can bind commands to move backward and forward through the active file's Git history without installing GitLens or selecting Timeline entries manually. Successive invocations visit the expected revisions in order and offer a corresponding forward path. Navigation must leave working-tree contents unchanged, handle history endpoints predictably, and preserve existing Timeline behavior. The request does not require assigning default shortcuts.
- **Trace:**

  > GitTimelineProvider.provideTimeline in extensions/git/src/timelineProvider.ts obtains per-file history through Repository.logFile with follow:true and attaches ref/previousRef to GitTimelineItem entries. CommandCenter.timelineOpenDiff and resolveTimelineOpenDiffCommand in extensions/git/src/commands.ts consume a selected item and URI to open vscode.diff; they do not infer adjacent history entries from an active editor. Repository.logFile in extensions/git/src/repository.ts delegates the underlying history query. The similarly named scm.viewPreviousCommit/scm.viewNextCommit handlers in src/vs/workbench/contrib/scm/browser/scm.contribution.ts navigate commit-message input history and are outside this feature's boundary. https://github.com/microsoft/vscode/issues/232364 establishes maintainer interest and accepts manually assigned shortcuts, but does not settle whether the resulting editor shows a snapshot or comparison. Preserve Timeline selection/comparison semantics and avoid changing Git checkout state; no implementation or runtime validation was performed during this review.
- **Open decisions:**
  - Should previous/next navigation display individual historical file snapshots or comparisons between adjacent revisions?
