# Issue #247968 — MCP client should validate tool descriptions for prompt injections and freeze them.

[https://github.com/microsoft/vscode/issues/247968](https://github.com/microsoft/vscode/issues/247968)

## Summary

Keep open for human security/design review: current MCP tool normalization and server trust checks do not provide the requested description scanning or content locking. The discussion leaves unresolved how to detect malicious changes while preserving legitimate dynamic tool discovery; the security-sensitive scope independently bars a cleanup close.

## Change summary

Validate MCP tool descriptions for prompt injection and detect or constrain subsequent changes to previously validated tool definitions.

## Best solution

Have the MCP and security owners define the protection contract for tool-description changes, including whether locking is opt-in and what happens when validation fails. Preserve legitimate dynamic tool discovery and avoid prompting users for every ordinary tool-list update, as requested in the maintainer discussion.
