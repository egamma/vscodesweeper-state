# Issue #242448 — cursor moves to the wrong spot when `editor.quickSuggestions.other` is set to `"inline"` and completion includes a text edit that adds an import

[https://github.com/microsoft/vscode/issues/242448](https://github.com/microsoft/vscode/issues/242448)

## Summary

The defect remains in current main: accepting an inline completion applies an import edit above the cursor, then restores an unadjusted pre-import position. Keep this older report as the canonical issue.

## Change summary

Accepting an inline quick suggestion with an additional auto-import edit places the cursor on the wrong line.

## Best solution

Transform the intended post-completion cursor or snippet position through all additional text edits in the inline-completion acceptance path, and consolidate the newer https://github.com/microsoft/vscode/issues/326730 report here.

## Evidence

- **source trace:** src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts:956-983 applies the primary and additional edits together, but computes and restores selections from only the primary edits. - **snippet path:** The snippet branch in inlineCompletionsModel.ts:956-963 likewise applies additional edits before setting the original snippet range start, without transforming that position through an import inserted above it.
