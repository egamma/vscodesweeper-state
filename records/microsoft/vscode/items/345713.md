# Issue #345713 — Windows agent sandbox blocks named pipes, breaking dotnet restore and build and other local IPC tools

[https://github.com/microsoft/vscode/issues/345713](https://github.com/microsoft/vscode/issues/345713)

## Summary

Keep open: an independent commenter confirms that sandboxed multi-project .NET builds fail and that single-node builds work. Named-pipe access crosses a sandbox isolation boundary, so any allowance needs human review rather than an automated cleanup close.

## Change summary

Sandboxed Windows processes cannot connect to their own named pipes, breaking multi-node MSBuild and other local IPC tools.

## Best solution

Establish a supported same-sandbox named-pipe communication contract and restore .NET build coordination without exposing host pipes. Confirm the failure in the Windows sandbox runtime and identify whether runtime enforcement or VS Code integration needs changing.
