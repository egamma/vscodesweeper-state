# Issue #345713 — Windows agent sandbox blocks named pipes, breaking dotnet restore and build and other local IPC tools

[https://github.com/microsoft/vscode/issues/345713](https://github.com/microsoft/vscode/issues/345713)

## Summary

Keep open: another user confirms multi-project dotnet builds fail under the Windows sandbox, and no verified fix or same-symptom canonical was found. The requested IPC allowance changes a sandbox security boundary and needs human review.

## Change summary

Windows agent sandbox named-pipe connection failures prevent multi-process .NET builds and other local IPC workflows.

## Best solution

Restore communication between processes inside the same sandbox while preserving isolation from host pipes. Treat explicitly authorized host endpoints, such as Docker Desktop, as a separate permission-design question rather than implicitly granting them with sandbox-internal IPC.
