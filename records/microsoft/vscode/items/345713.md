# Issue #345713 — Windows agent sandbox blocks named pipes, breaking dotnet restore and build and other local IPC tools

[https://github.com/microsoft/vscode/issues/345713](https://github.com/microsoft/vscode/issues/345713)

## Summary

Keep open for investigation of Windows sandbox IPC compatibility. The supplied restore steps and access-denied observations suffice to retest; current source exposes sandbox configuration forwarding but does not establish whether the underlying pipe restriction has changed.

## Change summary

Sandboxed Windows .NET commands fail when connecting to named pipes, including pipes created within the sandbox.

## Best solution

Establish the Windows runtime's same-sandbox named-pipe contract and restore required local IPC without granting access to unrelated host pipes. Investigate enforcement with the sandbox owners rather than treating filesystem or local-network allowances as equivalent pipe permissions.
