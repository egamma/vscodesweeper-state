# Issue #252145 — SCM - Quick Diff Decorations for Staged Changes Disappear When Adding Lines Before or After Staged Code

[https://github.com/microsoft/vscode/issues/252145](https://github.com/microsoft/vscode/issues/252145)

## Summary

Keep open: current source still suppresses an entire secondary diff hunk when an adjacent unstaged insertion overlaps it. The issue already has the correct SCM routing, and no verified canonical or completed fix was found.

## Change summary

Preserve staged-change gutter decorations when unstaged lines are inserted immediately before or after staged code.

## Best solution

Retain secondary decorations on unaffected staged lines while preserving primary decorations for unstaged edits. Establish regression coverage for adjacent insertions without changing the existing precedence for edits to staged lines themselves.

- **Behavior:**

  > Staged additions currently lose their gutter highlighting when an unstaged line is inserted immediately before or after them. Unaffected staged lines should retain their secondary decorations, while newly inserted unstaged lines retain primary decorations. Removing an insertion should restore the original staged display. Editing a staged line itself must continue to honor the established primary-decoration precedence.
- **Trace:**

  > Repository registers GitQuickDiffProvider and StagedResourceQuickDiffProvider in extensions/git/src/repository.ts; their baselines are the index and HEAD respectively. QuickDiffModel.diff() in src/vs/workbench/contrib/scm/browser/quickDiffModel.ts compares each baseline against the editor buffer, so adjacent staged and unstaged additions can form one combined secondary hunk. QuickDiffDecorator.onDidChange() in src/vs/workbench/contrib/scm/browser/quickDiffDecorator.ts discards that entire hunk when its modified range intersectsOrTouches any primary range. This directly explains the reported disappearance without requiring a theme or extension failure. Preserve provider visibility controls, full quick-diff API results, and the staged-line overlap behavior documented in https://github.com/microsoft/vscode/issues/247396. The remaining uncertainty is how to pin the rendering outcome in an executable regression test: the inspected SCM browser tests have no dedicated quick-diff decorator harness. No product decision is needed for the reported adjacent-insertion case.

## Evidence

- **Current-source failure path:** extensions/git/src/repository.ts:1001-1002 registers the working-tree and secondary providers. In extensions/git/src/quickDiffProvider.ts, the working-tree provider returns the index baseline and StagedResourceQuickDiffProvider returns HEAD. QuickDiffModel.diff() in src/vs/workbench/contrib/scm/browser/quickDiffModel.ts compares both baselines against the current editor buffer. Adding an unstaged line immediately adjacent to staged additions therefore produces a combined HEAD-to-buffer secondary hunk containing the primary insertion.
- **Whole-hunk suppression:** QuickDiffDecorator.onDidChange() in src/vs/workbench/contrib/scm/browser/quickDiffDecorator.ts skips the entire non-primary change whenever any primary modified range intersectsOrTouches its modified range. src/vs/editor/common/core/ranges/lineRange.ts:170-172 includes touching boundaries in that predicate. Consequently, the combined secondary hunk is omitted rather than retaining decorations on its unaffected staged lines. This was traced without executing or modifying the checkout.
- **Independent confirmation:** The discussion on https://github.com/microsoft/vscode/issues/252145 includes an independent Linux reproduction on VS Code 1.106.2, in addition to the original macOS report on 1.101.1. Both describe staged highlighting disappearing after further modifications.
- **Existing overlap contract:** https://github.com/microsoft/vscode/issues/247396 explicitly tests modifying a staged line and expects only the edited line's decoration to remain. That established behavior must be preserved; removing overlap suppression wholesale would not be an adequate fix for adjacent insertions.

Searches for staged decorations, staged gutter behavior, and quick-diff disappearance found no verified older open issue with the same observable symptom. https://github.com/microsoft/vscode/issues/247683 is closed and concerns incorrect decorations after unstaging selected ranges, a different trigger.
