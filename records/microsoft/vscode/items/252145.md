# Issue #252145 — SCM - Quick Diff Decorations for Staged Changes Disappear When Adding Lines Before or After Staged Code

[https://github.com/microsoft/vscode/issues/252145](https://github.com/microsoft/vscode/issues/252145)

## Summary

Still reproduces on main. The overlap detection between primary and secondary quick diff decorations is too aggressive — when a line is added adjacent to a staged chunk, the primary change range expands and `intersectsOrTouches` suppresses the secondary (staged) decorations entirely. Confirmed by a second reporter on 1.106.2; no fix has landed.

## Change summary

Quick diff gutter decorations for staged changes disappear when adding lines immediately before or after a staged chunk.

## Best solution

Fix the overlap detection in `quickDiffDecorator.ts` (line 150) and/or `quickDiffModel.ts` (lines 292–317) so that secondary (staged) decorations are preserved when a primary change partially or adjacently overlaps them. The `intersectsOrTouches` guard needs to be refined to distinguish genuinely redundant overlaps from adjacent-but-distinct changes, or the secondary range should be split to show the non-overlapping portion.

## Evidence

- **overlap guard (decorator):** src/vs/workbench/contrib/scm/browser/quickDiffDecorator.ts line 150: `if (quickDiff.kind !== 'primary' && primaryQuickDiffChanges.some(c => c.change2.modified.intersectsOrTouches(change.change2.modified)))` — skips ALL secondary decorations whose modified range touches a primary change, even when the secondary represents a distinct staged portion.
- **overlap guard (model):** src/vs/workbench/contrib/scm/browser/quickDiffModel.ts lines 292–317: secondary diffs are pushed to `secondaryDiffs` (excluded from displayed `changes`) when they have equal modified ranges and matching content as a primary diff. After adding adjacent lines, the diff engine produces a combined range — so the equality check fails, but the decorator's `intersectsOrTouches` still suppresses it.
- **secondary provider design:** extensions/git/src/quickDiffProvider.ts line 116: `StagedResourceQuickDiffProvider` returns `toGitUri(uri, 'HEAD')` as the original resource — the same baseline as the primary provider. Both compute HEAD-vs-working-copy diffs, so adjacent changes merge ranges identically.
- **no fix on main:** git log --grep and git log on quickDiffDecorator.ts/quickDiffModel.ts since 2025-06-23 show no commit addressing this overlap issue; the logic is unchanged.
- **second confirmation:** Comment by @iambpn on 2025-11-25 confirms the same behavior on VS Code 1.106.2 (Linux x64).
