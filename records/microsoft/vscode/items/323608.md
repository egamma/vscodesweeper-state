# Issue #323608 — Different progress indicators between main and child-chats

[https://github.com/microsoft/vscode/issues/323608](https://github.com/microsoft/vscode/issues/323608)

## Summary

The visual inconsistency remains in current source: session-level progress uses the animated pixel indicator while child-chat tabs use a spinning codicon and a static warning dot. This team-authored UX issue must remain open because there is no referenced fixing commit or verified older canonical, and the newer progress-consolidation discussion introduces a design choice that should be resolved first.

## Change summary

Make progress and input-needed states consistent between the main session indicator and child-chat tabs.

## Best solution

Settle a unified status hierarchy with https://github.com/microsoft/vscode/issues/326128, then make child-chat progress and input-needed states follow that design while suppressing indicators that are redundant for the active or sole chat.

## Plan brief

- **Likely files:** `src/vs/sessions/browser/parts/chatCompositeBar.ts`, `src/vs/sessions/browser/parts/media/chatCompositeBar.css`, `src/vs/sessions/browser/sessionStatusIcon.ts`, `src/vs/sessions/test/browser/chatCompositeBar.test.ts`, `src/vs/sessions/test/browser/sessionStatusIcon.test.ts`
- **Validation:** Add focused ChatCompositeBar browser tests covering InProgress and NeedsInput for active, inactive, sole, and multiple child chats, plus reduced-motion coverage for any shared animation; verify the rendered indicator modes and ARIA status labels.
- **Behavior:**

  > Main-session and child-chat status indicators should form one understandable visual system for in-progress and input-needed states. Users must be able to identify which inactive child needs attention without redundant motion around the active or sole chat. The result must preserve the existing spoken status labels and provide a non-animated reduced-motion presentation.
- **Trace:**

  > SessionHeaderBar feeds the aggregate session status into SessionStatusIcon, whose InProgress and NeedsInput paths use pixel-spinner grid and ring variants in src/vs/sessions/browser/sessionStatusIcon.ts. ChatCompositeBar independently maps each chat status to tab classes and renders a spinning loading codicon for InProgress, while chatCompositeBar.css renders NeedsInput as a warning-colored dot. The relevant later discussion is https://github.com/microsoft/vscode/issues/326128, which favors reducing redundant progress affordances and suppressing per-chat indication for the active or sole chat. Keep unread-state semantics, ARIA labels, reduced-motion behavior, and non-status tab actions unchanged; the uncertainty is the intended visible hierarchy, not the status data flow.
- **Open decisions:**
  - Should inactive child chats reuse the session-level pixel animation, or use a quieter child-specific treatment under the progress-consolidation design?
  - Should the active or sole child chat hide its tab-level progress and input-needed indicator when the same state is already visible in the session or conversation body?
