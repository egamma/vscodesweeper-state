# Issue #278968 — Response Type of "unknown" almost never emits a /response event for GPT-5 and other models

[https://github.com/microsoft/vscode/issues/278968](https://github.com/microsoft/vscode/issues/278968)

## Summary

Keep open: current main still has a source-confirmed telemetry blind spot when a successful HTTP response produces no chat completions. The referenced meta issue concerns the user-visible “no response” symptom rather than this specific missing telemetry event, and the stronger duplicate bar for this re-reviewed item is not met.

## Change summary

Ensure requests classified as an unknown response emit matching response telemetry instead of appearing only in panel.request telemetry.

## Best solution

Make the empty-completion outcome emit one response.error event carrying the unknown response type and request correlation fields, while preserving the existing returned ChatFetchResponseType.Unknown behavior and avoiding duplicate events for failures already covered by the failed-response path.
