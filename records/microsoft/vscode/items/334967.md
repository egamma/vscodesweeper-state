# Issue #334967 — Allow privately signed ssl certs for custom AI providers.

[https://github.com/microsoft/vscode/issues/334967](https://github.com/microsoft/vscode/issues/334967)

## Summary

Legitimate request with no per-provider TLS option on main, but it sits in Backlog Candidates under the 60-day community upvote process, so it stays open; the supported path today is trusting the self-signed CA via the OS store (`http.systemCertificates` / `http.systemCertificatesNode`), which the extension host already injects into Node TLS and fetch.

## Change summary

Add a per-custom-AI-provider option to ignore TLS certificate errors so self-hosted model endpoints with privately signed certs can be used.

## Best solution

Prefer documenting/strengthening the CA-trust path over an ignore-errors switch: the extension host already loads OS certificates into the TLS and fetch patches (src/vs/workbench/api/node/proxyResolver.ts), so a self-signed CA added to the OS store works today. If a BYOK-specific affordance is wanted, scope it to supplying a CA bundle per provider group in extensions/copilot/src/extension/byok rather than disabling verification.
