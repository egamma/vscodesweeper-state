# Issue #331876 — chat.tools.terminal.autoApprove

[https://github.com/microsoft/vscode/issues/331876](https://github.com/microsoft/vscode/issues/331876)

## Summary

This is an opinion that storing `chat.tools.terminal.autoApprove` rules in the regular settings file is a bad idea, not a report of broken behavior — VS Code settings, including this one, are always persisted in `settings.json` at whatever scope (user/workspace/folder) the user chooses, which is the standard configuration mechanism across the whole product.

## Change summary

Reporter objects to chat auto-approve terminal rules being saved as a normal setting in the user settings.json file.

## Best solution

Keep the current design — auto-approve rules are a standard configuration property (`TerminalChatAgentToolsSettingId.AutoApprove` in terminalChatAgentToolsConfiguration.ts) like any other setting; users who are uncomfortable with it in their synced user settings can scope it to workspace settings instead, or exclude it from Settings Sync.
