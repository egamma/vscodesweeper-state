# Issue #308400 — Invoking a .prompt.md file via /command permanently locks the chat session to Ask mode

[https://github.com/microsoft/vscode/issues/308400](https://github.com/microsoft/vscode/issues/308400)

## Summary

The prompt-command mode-switch race was fixed on main: prompt metadata now waits for the requested agent mode before enabling tools and submitting the request.

## Change summary

Invoking an agent-mode `.prompt.md` slash command from Ask mode submitted without tools and left the session's displayed mode inconsistent with its effective capabilities.

## Best solution

Keep the mode-switch sequencing introduced by commit 66a1aa1d010781ed0d6a9619e69d0cd8a5f1e197, which makes prompt execution wait for the requested agent mode before configuring tools and sending.

## Evidence

- **original trigger:** The reported trigger is submitting a `.prompt.md` slash command containing `mode: agent` while the chat is in Ask mode; the prompt parser maps both `agent` and legacy `mode` metadata through `PromptHeader.agent` in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts.
- **fix commit:** https://github.com/microsoft/vscode/commit/66a1aa1d010781ed0d6a9619e69d0cd8a5f1e197 changed `_applyPromptMetadata` in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts to await `_switchToAgentByName` before checking `currentModeKind` and applying prompt tools. Previously the unawaited switch let submission continue while the effective mode was still Ask.
- **current main:** Current main retains the corrected sequence: `_applyPromptFileIfSet` awaits `_applyPromptMetadata`; `_applyPromptMetadata` awaits `_switchToAgentByName`; only afterward does it enable tools when `currentModeKind === ChatModeKind.Agent`.
- **release:** Shipped in 1.119.0 — the earliest release tag containing 66a1aa1d01 (verified against the repo's release tags).
