# Issue #261438 — Consider adopting a new Python grammar

[https://github.com/microsoft/vscode/issues/261438](https://github.com/microsoft/vscode/issues/261438)

## Summary

Keep open: VS Code still bundles MagicPython, and the recently announced Pylance replacement does not replace the built-in grammar. This team-authored Backlog request remains relevant; no qualifying fix or canonical duplicate was established.

## Change summary

Consider replacing the apparently unmaintained bundled Python grammar with a maintained syntax-highlighting implementation.

## Best solution

Choose a maintained baseline Python highlighting implementation that works without Pylance, then assess modern Python syntax coverage, theme compatibility, and tokenization performance before adoption.

## Plan brief

- **Likely files:** `extensions/python/package.json`, `extensions/python/cgmanifest.json`, `extensions/python/syntaxes/MagicPython.tmLanguage.json`, `extensions/python/syntaxes/MagicRegExp.tmLanguage.json`
- **Validation:** Compare baseline Python tokenization with Pylance disabled before and after the candidate adoption: include Python 3.12 type aliases and generic declarations, nested f-strings, raw strings, regex highlighting, and representative existing Python files. Verify expected token scopes and theme rendering, and compare tokenization performance on large files.
- **Behavior:**

  > Python files should receive maintained baseline syntax highlighting without requiring Pylance. Evaluate coverage of modern Python syntax and compatibility with existing themes and regex highlighting. Acceptance should demonstrate that the selected implementation addresses the maintenance gap without materially regressing established highlighting or tokenization performance.
- **Trace:**

  > extensions/python/package.json contributes the bundled Python and regex TextMate grammars and updates them from MagicStack/MagicPython. extensions/python/cgmanifest.json and the generated grammar identify the existing upstream revision. The linked https://github.com/microsoft/pylance-release/issues/5824 now reports a replacement implemented through Pylance semantic tokens, explicitly limited to Pylance, so it does not replace this baseline. General Tree-sitter infrastructure is explored in https://github.com/microsoft/vscode/issues/210475, but the inspected editor configuration registers no Python Tree-sitter preference. The unresolved boundary is which baseline implementation to adopt and what highlighting compatibility it must preserve; do not treat the Pylance-only improvement as completion of the built-in work.
- **Open decisions:**
  - Should the built-in Python baseline adopt a maintained TextMate replacement or wait for a core Tree-sitter-based implementation?
  - Which existing token-scope and raw-string/regex-highlighting behaviors must remain compatible, and which user-visible changes are acceptable when adopting the replacement?

## Evidence

Its update-grammar script still targets MagicStack/MagicPython; extensions/python/cgmanifest.json pins that project's commit 7d0f2b22a5ad8fccbd7341bc7b7a715169283044.
