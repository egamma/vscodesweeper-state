# Issue #320063 — "Open New External Terminal" does not correctly work with GNOME's default terminal emulator `ptyxis` . Fails to open window  that is navigated to the directory

[https://github.com/microsoft/vscode/issues/320063](https://github.com/microsoft/vscode/issues/320063)

## Summary

The current Linux external-terminal launcher invokes Ptyxis without arguments, which activates the application rather than requesting a terminal in the selected directory. Keep this open and route it to the terminal area; the source confirms a bounded launch-integration defect.

## Change summary

Opening an Explorer directory in external Ptyxis should create a terminal at that directory instead of activating an existing window or opening the default directory.

## Best solution

Make the Linux external-terminal launch integration honor Ptyxis's window-creation and working-directory contract while preserving other terminal emulators' existing behavior.

## Evidence

- **Explorer passes the correct directory:** src/vs/workbench/contrib/externalTerminal/browser/externalTerminal.contribution.ts, registerOpenTerminalCommand, resolves the selected directory and calls externalTerminalService.openTerminal(config.terminal.external, cwd). The directory is not lost in the Explorer command.
- **Current launch defect:** src/vs/platform/externalTerminal/node/externalTerminalService.ts, LinuxExternalTerminalService.spawnTerminal, supplies working-directory arguments only for Ghostty. With linuxExec set to ptyxis, it calls spawn('ptyxis', [], { cwd, env }); there is no request to create a window or tab.
- **Ptyxis CLI contract:** https://gitlab.gnome.org/chergert/ptyxis/-/blob/main/src/ptyxis-application.c registers --new-window and --working-directory/-d around lines 1147–1159. In ptyxis_application_command_line, the --new-window branch applies cwd_uri to a new tab, whereas the argument-free fallback around lines 664–669 calls g_application_activate without applying that directory. This explains the reported activation/default-directory behavior without executing either application.
- **Configuration is not an argument list:** terminal.external.linuxExec is registered as an executable string in src/vs/workbench/contrib/externalTerminal/electron-browser/externalTerminal.contribution.ts and passed directly to spawn. The reporter's 'ptyxis --new-window -d' ENOENT therefore reflects an unsupported executable-plus-arguments value, not a working configuration workaround.
