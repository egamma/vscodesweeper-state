# Issue #305778 — Sessions: Expect Merge Changes to default to merging on branch I'm using for session

[https://github.com/microsoft/vscode/issues/305778](https://github.com/microsoft/vscode/issues/305778)

## Summary

Keep open to establish a predictable merge-back contract: current code supplies the session's base branch, but that alone does not prove the agent stops reconsidering main as the target. This team-authored, previously reviewed request has neither a verified qualifying duplicate nor an issue-referencing fix.

## Change summary

Make Merge Changes reliably integrate a worktree session into the branch it started from without unnecessarily reconsidering the repository's default branch.

## Best solution

Merge back into the recorded session base branch and clearly identify that destination, preserving necessary Git safety checks without reopening target selection in a clean, straightforward case. Establish explicit behavior when the original checkout has switched branches since session creation.
