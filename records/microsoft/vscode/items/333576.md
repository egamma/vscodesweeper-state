# Issue #333576 — The Interactive button has two tabstops

[https://github.com/microsoft/vscode/issues/333576](https://github.com/microsoft/vscode/issues/333576)

## Summary

Fresh, credible team-authored bug from testing the redesigned new-session chat input (a testplan item for #333209): the mode chip ("Interactive" etc.) has two tab stops because the wrapping action-view-item container and its own inner trigger element are both independently made focusable, and only the inner one has a working keyboard handler.

## Change summary

The 'Interactive' agent-mode chip below the agent button in the new-session chat input exposes two tab stops instead of one, and only one of them responds to Enter/Space.

## Best solution

In src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionConfigPicker.ts, stop `PickerActionViewItem` from participating in the ActionBar's roving-tabindex focus management (it should not itself become a tab stop) since the wrapped picker's own trigger element (agentHostModePicker.ts) already owns focus/keyboard handling for the chip.
