# Issue #251607 — UI decoration on files that AI will ignore

[https://github.com/microsoft/vscode/issues/251607](https://github.com/microsoft/vscode/issues/251607)

## Summary

The requested Explorer indication remains absent on current main: Copilot enforces local and remote content exclusions but does not register a file-decoration provider. The Backlog request should remain open while the visible treatment and exclusion scope are designed.

## Change summary

Decorate files in the Explorer when Copilot will exclude them from AI context.

## Best solution

Expose a clear, accessible Explorer decoration and tooltip derived from Copilot's effective ignore decision, updating when local ignore files, authentication enablement, workspace folders, or remote exclusion rules change without making Explorer rendering depend on repeated expensive network-backed checks.

## Plan brief

- **Likely files:** `extensions/copilot/src/platform/ignore/common/ignoreService.ts`, `extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts`, `extensions/copilot/src/platform/ignore/vscode-node/ignoreService.ts`, `extensions/copilot/src/extension/extension/vscode/extension.ts`
- **Validation:** Add an extension-host or provider-level test with a mocked ignore service that verifies an ignored resource receives the approved decoration, an allowed resource does not, and changing ignore rules invalidates affected decorations.
- **Behavior:**

  > Files that Copilot will exclude from AI context have a recognizable, accessible indication in Explorer, including a tooltip that explains the state. Allowed files remain visually unchanged. Decorations update after relevant ignore configuration changes without requiring a reload, and Explorer performance remains responsive in large workspaces.
- **Trace:**

  > The effective decision is centralized in `BaseIgnoreService.isCopilotIgnored` in extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts, which combines local `.copilotignore` patterns and remote content exclusions. `VsCodeIgnoreService` in extensions/copilot/src/platform/ignore/vscode-node/ignoreService.ts already observes local ignore-file mutations, but `IIgnoreService` in extensions/copilot/src/platform/ignore/common/ignoreService.ts exposes no general invalidation event. No production code under extensions/copilot/src currently registers a `FileDecorationProvider`. Keep the behavior within the Copilot extension and the standard VS Code file-decoration API; do not alter exclusion enforcement or reveal the text of organization-managed rules.
- **Open decisions:**
  - Should the same decoration represent both local `.copilotignore` matches and organization-managed remote content exclusions, or should those user-visible states be distinguishable?
  - Should ignored folders receive an aggregate decoration when only some descendants are excluded, or should decoration remain file-specific?
  - What icon, color treatment, and tooltip wording communicates exclusion without conflicting with source-control and diagnostic decorations?

## Evidence

- **current ignore path:** extensions/copilot/src/platform/ignore/node/ignoreServiceImpl.ts implements `BaseIgnoreService.isCopilotIgnored`, combining `.copilotignore` decisions with `RemoteContentExclusion`, but it provides no file-decoration integration.
- **missing UI capability:** A current-main search under extensions/copilot/src finds no production use of `registerFileDecorationProvider`; the only matches are generated test fixtures, so there is no shipped Explorer decoration covering the request.
- **update lifecycle gap:** extensions/copilot/src/platform/ignore/vscode-node/ignoreService.ts watches saved, deleted, and renamed `.copilotignore` files, while extensions/copilot/src/platform/ignore/common/ignoreService.ts exposes queries but no public change event suitable for invalidating file decorations.
- **canonical search:** Repository issue searches found no older open issue with the same reporter-observable request; https://github.com/microsoft/vscode/issues/253136 concerns failed chat requests and does not own Explorer decoration work.
