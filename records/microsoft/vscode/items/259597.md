## Change summary

Restore VS Code startup when virtualized Windows profile directories incorrectly return ENOENT during filesystem operations.

Resolve the GetFileInformationByName incompatibility in the profile-layering software or the Node.js/libuv runtime shipped through Electron, retaining this report until its FSLogix and Omnissa cases are accounted for. For the FSLogix case, establish whether the vendor-fixed version resolves the failure; coordinate the remaining Omnissa work with https://github.com/microsoft/vscode/issues/339964.

## Evidence

- **Reported trigger and workaround:** https://github.com/microsoft/vscode/issues/259597 reports VS Code 1.102.3 exiting during startup on Windows 11 Azure VDI after ENOENT creating the profile's .vscode/extensions directory. Disabling extensions and GPU does not help; relocating both user-data and extension directories to C:\Temp permits launch.
- **Confirmed persistence:** Mehinkle1's September 23, 2025 comment confirms reproduction on VS Code 1.104.1 with Omnissa App Volumes writable volumes and successful rollback to 1.100.3. dpitel's December 31, 2025 comment confirms continued failure on VS Code 1.107.1 with FSLogix 3.25.626.21064.
- **Maintainer runtime diagnosis:** https://github.com/microsoft/vscode/issues/251448#issuecomment-3102845215 records a maintainer's reproduction and bisect to Node.js 22.12.0 adopting libuv's GetFileInformationByName fast path in https://github.com/libuv/libuv/commit/4e310d0f90af29e699e2dedad5fa0dcee181a7cc. Profile-directory stat operations returned false ENOENT results. This is the introducing change, not a fixing commit.
- **Limited historical workaround:** https://github.com/microsoft/vscode/issues/251448#issuecomment-3105859398 shows the temporary fallback was conditional on HKLM\SOFTWARE\FSLogix. That issue is CLOSED, with verification of the FSLogix workaround; it does not establish resolution of this report's later Omnissa and FSLogix failures.
- **Later FSLogix guidance:** https://github.com/microsoft/vscode/issues/283754#issuecomment-3675373269 identifies the profile API defect as FSLogix-owned and states that FSLogix 3.25.822.19044 is needed for VS Code >= 1.107 after removal of the temporary runtime workaround. This explains the reported older FSLogix version but does not resolve the Omnissa case.
