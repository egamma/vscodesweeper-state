# Issue #107343 — Asynchronously show completion items from different sources or extensions!

[https://github.com/microsoft/vscode/issues/107343](https://github.com/microsoft/vscode/issues/107343)

## Summary

Keep open: current completion collection still waits for every provider in the selected priority group before publishing suggestions. This issue already owns several duplicate reports, and the maintainer's incremental-display proposal remains relevant.

## Change summary

Display completion results incrementally so a slow provider does not block suggestions from faster providers.

## Best solution

Deliver incremental updates in the editor suggest pipeline, using the maintainer's recorded baseline: wait for the first non-simple provider, append subsequent results without reordering existing entries, and rerank when the prefix changes. Preserve word-based fallback and provider-priority semantics while designing cancellation and selection stability.

Cover cancellation before the late result and preserve existing provider-priority, fallback, and final-result behavior for non-widget consumers. Run these targeted suites through scripts/test.sh in an implementation workspace; no tests were executed in this read-only review.
- **Behavior:**

  > A slow completion provider currently delays results from a faster provider participating in the same priority group. Under the maintainer's proposed baseline, suggestions become visible after the first non-simple provider responds, and later results extend the list without moving existing entries or the selected suggestion. Further prefix typing permits reranking. Word-based suggestions remain supported, and cancelled or superseded requests must not update the current list. Acceptance should use controlled provider timing rather than wall-clock latency assertions.
- **Trace:**

  > provideSuggestionItems in src/vs/editor/contrib/suggest/browser/suggest.ts collects results behind a per-group Promise.all, preserves priority-group fallback, and returns a single sorted model after snippets finish. SuggestModel.trigger in src/vs/editor/contrib/suggest/browser/suggestModel.ts waits for that model and WordDistance before constructing CompletionModel and publishing through _onNewContext. This source trace establishes that incremental provider arrivals are not exposed on the widget path. The maintainer's baseline is recorded at https://github.com/microsoft/vscode/issues/107343#issuecomment-699907614 and clarified at https://github.com/microsoft/vscode/issues/107343#issuecomment-700491741; do not reopen the rejected removal of word-based suggestions. The unresolved technical design concerns incremental model updates, stable selection, provider-group fallback, and request lifetime across late arrivals. Collection is shared with inline completions, completion-provider commands, and the breakpoint widget, whose existing final-result behavior must remain intact.

## Evidence

- **Current aggregation barrier:** src/vs/editor/contrib/suggest/browser/suggest.ts, provideSuggestionItems, awaits Promise.all for each equal-priority provider group, stops after a group produces results, awaits snippetCompletions, and returns one sorted CompletionItemModel. A deliberately delayed provider in the same group therefore still delays the faster provider's results, matching the original trigger.
- **Publication path:** src/vs/editor/contrib/suggest/browser/suggestModel.ts:582–639 waits for both provideSuggestionItems and WordDistance before constructing CompletionModel and calling _onNewContext; this path does not publish individual provider arrivals.
- **Existing capabilities do not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.snippetSuggestions for ordering or hiding snippets and editor.tabCompletion with an onlySnippets mode. These address snippet presentation or insertion, not incremental display of results from multiple completion providers; editor.quickSuggestionsDelay changes the trigger delay, not the provider-completion barrier.
- **Maintainer direction and boundary:** https://github.com/microsoft/vscode/issues/107343#issuecomment-699907614 proposes waiting for the first non-simple provider, updating as more results arrive, and reranking only when more prefix text is typed. https://github.com/microsoft/vscode/issues/107343#issuecomment-700491741 confirms that updates mean appending. https://github.com/microsoft/vscode/issues/107343#issuecomment-698819863 explicitly rejects removing word-based completions.
