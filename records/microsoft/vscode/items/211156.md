# Issue #211156 — Use different templates for issue reporting vs performance vs features

[https://github.com/microsoft/vscode/issues/211156](https://github.com/microsoft/vscode/issues/211156)

## Summary

The requested type-specific template contract remains absent on current main: extension-contributed reports still provide one `issueBody`, while selecting Bug, Performance Issue, or Feature Request changes only built-in guidance. This team-authored Backlog request was explicitly accepted by a maintainer and should remain open for API and interaction design.

## Change summary

Allow issue-reporter integrations to provide different description templates for bug, performance, and feature reports.

## Best solution

Define a type-aware issue-template contract for contributed issue reports and make category changes apply the corresponding template without overwriting user-authored text.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/issue/common/issue.ts`, `src/vs/workbench/contrib/issue/common/issue.contribution.ts`, `src/vs/workbench/contrib/issue/browser/issueReporterOverlay.ts`, `src/vs/workbench/contrib/issue/test/browser/issueReporterOverlay.test.ts`
- **Validation:** Add issue-reporter unit coverage that supplies distinct Bug, Performance Issue, and Feature Request templates, switches among all three categories, and verifies the corresponding text appears without losing user-authored content; run the targeted IssueReporterOverlay unit suite.
- **Behavior:**

  > An issue-reporter integration can associate different description templates with Bug, Performance Issue, and Feature Request. Selecting a category presents the matching template rather than irrelevant prompts from another category. Switching categories must not silently discard text the user has authored. Existing integrations that provide only one `issueBody` continue to behave compatibly.
- **Trace:**

  > The command surface in `src/vs/workbench/contrib/issue/common/issue.contribution.ts` and the internal data contract in `src/vs/workbench/contrib/issue/common/issue.ts` currently carry one `issueBody`. `IssueReporterOverlay.createStep1Describe` copies that value into the textarea, while `updateDescriptionGuidance` changes only the surrounding guidance for the selected `IssueType`. Extension contributions reach this path through `IssueFormService.sendReporterMenu` in `src/vs/workbench/contrib/issue/browser/issueFormService.ts`. Preserve compatibility for callers using the existing single body and keep diagnostics/system-information behavior outside the scope of this request. The uncertainty begins at the externally observable template shape and how category changes interact with edited text.
- **Open decisions:**
  - Should the reporter contract expose one fallback body plus optional per-type templates, or replace the single body with a type-keyed contract while retaining backward compatibility?
  - When the user changes category after editing the description, should VS Code replace only an untouched generated template, append the new template, or leave the edited text unchanged?

## Evidence

- **current contract:** `src/vs/workbench/contrib/issue/common/issue.contribution.ts` exposes only one `issueBody?: string` in `OpenIssueReporterArgs` and command metadata; `src/vs/workbench/contrib/issue/common/issue.ts` likewise has a single `IssueReporterData.issueBody`.
- **current behavior:** `src/vs/workbench/contrib/issue/browser/issueReporterOverlay.ts` initializes the description from the single `data.issueBody`; `updateDescriptionGuidance()` varies explanatory guidance by `IssueType` but does not select a contributed template by type.
- **extension path:** `src/vs/workbench/contrib/issue/browser/issueFormService.ts::sendReporterMenu` runs the selected extension's `issue/reporter` contribution and returns one `IssueReporterData` object, leaving no type-to-template mapping.
- **maintainer direction:** A maintainer explicitly agreed that type-specific templates make sense and could be added: https://github.com/microsoft/vscode/issues/211156#issuecomment-2086361812.
- **canonical search:** Repository searches for issue-reporter templates and bug/performance/feature variants found no older open issue owning this same request; https://github.com/microsoft/vscode/issues/210874 is a closed test-plan item, not a canonical implementation issue.
