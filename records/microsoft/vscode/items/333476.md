# Issue #333476 — Remote Agent Host artifacts cannot be opened from the local client

[https://github.com/microsoft/vscode/issues/333476](https://github.com/microsoft/vscode/issues/333476)

## Summary

Freshly filed, well-diagnosed gap: clicking a file/resource artifact from a remote Agent Host session tries to open the server-side path directly on the local client, which has no such filesystem — the code confirms there is no URI remapping or transfer path for remote artifacts.

## Change summary

File/resource artifacts recorded by a remote Agent Host session point at paths on the remote host's filesystem, which the local client cannot open as-is.

## Best solution

Give remote Agent Host artifacts a client-openable representation — either transfer/download the file content through the existing agent host protocol (the node-side `IFileService` access already used in src/vs/platform/agentHost/node/agentService.ts) into a local temp/virtual resource, or resolve the URI through a remote-aware filesystem provider — wired into src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionArtifacts.ts and the `openResource` handler in src/vs/sessions/contrib/chat/browser/sessionArtifacts.ts.
