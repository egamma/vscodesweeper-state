# Issue #232230 — The last pressed key is printed in some chord key-bindings

[https://github.com/microsoft/vscode/issues/232230](https://github.com/microsoft/vscode/issues/232230)

## Summary

Legitimate bug report about chord keybindings with Ctrl+Alt where the second chord key's character leaks into the editor. No fix found on current main; the intermittent nature and Ctrl+Alt/AltGr interaction suggest a timing issue in keyboard event suppression. Keeping open as the reporter provides enough detail to investigate, but a reliable reproduction path on a standard layout would help.

## Change summary

When using multi-chord keybindings starting with Ctrl+Alt (e.g. `ctrl+alt+t t`), the final key's character is sometimes typed into the editor alongside the command execution.

## Best solution

Investigate the race between the OS-level character production from Ctrl+Alt (AltGr equivalent) and the keybinding service's preventDefault on the second chord. The fix likely belongs in the keyboard dispatch path in `src/vs/platform/keybinding/common/abstractKeybindingService.ts` or the editor's input handling, ensuring that when chord mode resolves, any pending `beforeinput`/`input` event from the same keypress is suppressed.
