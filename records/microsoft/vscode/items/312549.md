# Issue #312549 — Linux (Snap) + Copilot Chat cannot type Chinese with IBus (can paste Chinese only)

[https://github.com/microsoft/vscode/issues/312549](https://github.com/microsoft/vscode/issues/312549)

## Summary

Confirmed in source: the Snap `electron-launch` wrapper unconditionally appends `--ozone-platform=x11` on its final line, overriding any user-supplied Wayland flags and breaking CJK IME composition in webview-based surfaces like Copilot Chat. The forced x11 was introduced intentionally to work around GPU crashes (commit 4b19907cc8c), so the fix requires balancing Wayland IME support with GPU stability.

## Change summary

The Snap packaging wrapper forces `--ozone-platform=x11` unconditionally, overriding Wayland flags and breaking IME composition for CJK input in Copilot Chat (and likely other webview surfaces).

## Best solution

Make the `--ozone-platform` flag in `resources/linux/snap/electron-launch` conditional on the `wayland_available` variable already computed earlier in the script — use `wayland` when a Wayland socket is detected (the script already sets `GDK_BACKEND=wayland` in that case) and fall back to `x11` otherwise. The GPU crash workaround (commit 4b19907cc8c) that motivated the forced x11 should be re-evaluated against current Electron/Chromium versions to confirm it is still needed.
