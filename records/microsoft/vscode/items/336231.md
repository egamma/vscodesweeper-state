# Issue #336231 — Integrated browser: window.open opens a detached window that cannot communicate with its opener

[https://github.com/microsoft/vscode/issues/336231](https://github.com/microsoft/vscode/issues/336231)

## Summary

Fresh report with clear repro steps; source trace shows a plausible architectural cause (new-window `window.open()` calls are routed through a full auxiliary VS Code window rather than a lightweight popup), but confirming whether `window.opener`/`postMessage` actually breaks requires runtime Electron behavior I can't execute here, so this stays open for verification/decision.

## Change summary

In the integrated browser, `window.open()` calls that use the 'new-window' disposition spawn a detached window whose opener relationship (and thus `window.postMessage()`) with the original page doesn't appear to work.

## Best solution

Investigate in src/vs/platform/browserView/electron-main/browserView.ts whether wrapping the new-window disposition in an auxiliary VS Code window (via IAuxiliaryWindowsMainService) breaks Electron's opener linkage for the returned webContents; either preserve the opener relationship for this path or, per the reporter's fallback suggestion, surface a clear signal/warning to the agent that opener communication isn't supported for these detached windows.
