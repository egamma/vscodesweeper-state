# Issue #93031 — Replace in search Editor

[https://github.com/microsoft/vscode/issues/93031](https://github.com/microsoft/vscode/issues/93031)

## Summary

Keep open: current Search Editors still lack workspace replacement, and this accepted Backlog request has 119 upvotes. Existing editor commands modify the results document, not the source files; related reports explicitly consolidate this work here.

## Change summary

Add a replacement field and workspace replace operation to Search Editors, preferably with replacement previews.

## Best solution

Provide a query → replacement pattern → replace workflow inside Search Editors that updates the matching source files, with behavior consistent with Search view. Treat arbitrary edits to result/context lines as a separate scope decision rather than a prerequisite for basic replacement.

Verify saving a .code-search document retains its existing meaning and does not implicitly apply workspace edits; validate the selected preview behavior separately.
- **Behavior:**

  > Users cannot currently enter a workspace replacement pattern and apply it from a Search Editor. The requested baseline is a query → replacement pattern → replace workflow that updates matching source files, including regex capture substitutions. Acceptance should establish correct multi-file targeting, exclusions, cancellation, and undo while preserving search-results document saving. Replacement previews are requested as a bonus; applying arbitrary edits to result/context lines is a broader capability discussed in the thread.
- **Trace:**

  > SearchEditor.createQueryEditor in src/vs/workbench/contrib/searchEditor/browser/searchEditor.ts creates SearchWidget with _hideReplaceToggle: true; the inspected wiring handles searching rather than workspace replacement. searchEditor.contribution.ts contains no replacement setting or command covering the request, and constants.ts defines search configuration without a replacement pattern. SearchEditorInput.save/saveAs in searchEditorInput.ts write the serialized results document, while selectAllSearchEditorMatchesCommand in searchEditorActions.ts only selects result matches. SearchView.replaceAll in src/vs/workbench/contrib/search/browser/searchView.ts demonstrates the existing confirmation and searchResult.replaceAll behavior; adoption by Search Editors and result refresh semantics still require design. Preserve editable/exportable result documents and do not turn ordinary Save into implicit workspace mutation. The thread distinguishes basic replacement from applying arbitrary edits, and https://github.com/microsoft/vscode/issues/208894#issuecomment-2030004730 explicitly directs replacement work here.
- **Open decisions:**
  - Should the first delivery provide pattern-based replacement only, leaving arbitrary result/context-line edits unapplied, or also support applying those edits to source files?
  - Should the first delivery include replacement diff previews, or is Search view-style confirmation sufficient before modifying source files?
