# Issue #330464 — Claude no longer available

[https://github.com/microsoft/vscode/issues/330464](https://github.com/microsoft/vscode/issues/330464)

## Summary

Real regression in the 1.133.0 Claude BYOK detection: users who authenticate Claude Code via subscription OAuth (not an env-based credential in `~/.claude/settings.json`) are no longer recognized as having a usable native setup, so the agent host silently falls back to the Copilot-routed proxy and gates them behind a subscription. A team member (TylerLeonhardt) is already engaged and multiple independent reporters confirmed both the regression and a workaround, so this is not just noise — it needs a maintainer decision on how to detect these setups, not an automated fix.

## Change summary

After updating to VS Code 1.133.0, Claude is unavailable (grayed out, 'Upgrade to Copilot Pro') for users who authenticate Claude Code via subscription/OAuth or BYOK configs (Bedrock, custom base URL) that aren't captured by the new native-setup detection.

## Best solution

Extend or revisit `detectExistingClaudeSetup`/`hasNativeClaudeEnv` in src/vs/platform/agentHost/node/claude/claudeTransportMode.ts so it also recognizes a working `claude login`/subscription-OAuth setup (not just the four env keys it currently checks), or otherwise ships more explicit guidance/UI for this class of user; this needs a maintainer call on what counts as a trustworthy native-setup signal.
