# Issue #275021 — When the active branch is not the main branch the main branch is rendered below the other branches

[https://github.com/microsoft/vscode/issues/275021](https://github.com/microsoft/vscode/issues/275021)

## Summary

Keep open: the Repositories explorer still has no main-branch-first ordering, and existing sorting settings do not cover this request. This team-authored item needs an ordering decision, not a judgment close.

## Change summary

Keep the main branch at the top of the Repositories explorer's branch list even when another branch is checked out.

## Best solution

Provide stable main/default-branch prominence in the Repositories explorer without changing checkout behavior or unrelated branch pickers. First settle how that branch is identified and whether its precedence overrides branch folders.

## Plan brief

- **Likely files:** `extensions/git/src/artifactProvider.ts`, `src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts`
- **Validation:** In a disposable test repository, enable scm.repositories.explorer and single selection, create main plus newer root-level and slash-containing branches, and check out a non-main branch. Verify that the agreed preferred branch remains first before and after checkout and refresh; also check a repository with a non-main default branch and one without a detectable default. Branch actions, active-branch icons, and tag ordering must remain unchanged.
- **Behavior:**

  > The Repositories explorer currently allows main to appear below other branches when a different branch is active. The requested outcome is stable first-position placement for the main branch independent of checkout state and commit recency. Acceptance must cover both root-level branches and branch folders, with the intended default-branch identification agreed before implementation. Checkout actions, active-branch indicators, and unrelated artifact ordering remain unchanged.
- **Trace:**

  > The surface is established by https://github.com/microsoft/vscode/issues/274788, referenced in https://github.com/microsoft/vscode/issues/275021. GitArtifactProvider.provideArtifacts in extensions/git/src/artifactProvider.ts obtains local branches sorted by descending creatordate and applies sortRefByName, which prioritizes directory-shaped names without recognizing main or the repository default branch. Repository.getRefs in extensions/git/src/repository.ts keeps that explicit sort, so git.branchSortOrder does not change this path. The artifact-group data source in src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts projects the sequence into a ResourceTree without adding branch priority. The gap is confirmed in the current source, but the existing code does not settle preferred-branch identity or precedence over folders. Keep the scope to Repositories explorer branch presentation; do not change checkout pickers, tags, worktrees, or repository ordering.
- **Open decisions:**
  - Should first-position priority apply specifically to the branch named main, or to the repository's detected default branch, including repositories whose default has another name?
  - Should the preferred branch appear above all branch folders, overriding the current folders-first presentation?

## Evidence

- **Current ordering:** extensions/git/src/artifactProvider.ts: GitArtifactProvider.provideArtifacts('branches') requests refs/heads with sort='creatordate', then applies sortRefByName. - **Ordering reaches the view:** src/vs/workbench/contrib/scm/browser/scmRepositoriesViewPane.ts builds branch folders from the provider's artifact sequence and returns ResourceTree children. It introduces no main-branch-first precedence.
