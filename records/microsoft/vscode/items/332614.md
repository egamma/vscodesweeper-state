# Issue #332614 — affectsConfiguration misses changes when a longer sibling key precedes the changed key

[https://github.com/microsoft/vscode/issues/332614](https://github.com/microsoft/vscode/issues/332614)

## Summary

Confirmed on main: `ConfigurationChangeEvent.affectsConfiguration` scans only the first occurrence of the padded section string and bails out if that occurrence fails the boundary check, so a longer sibling key preceding the real changed key masks the change — order-dependent and wrong. An open PR already fixes this, so it should stay open for that PR to land.

## Change summary

`affectsConfiguration(section)` returns false when a longer sibling key (e.g. `workbench.editorAssociations`) appears in the affected-keys string before the actual changed child key (e.g. `workbench.editor.showTabs`), because the scan stops at the first failed boundary check instead of continuing to later occurrences.

## Best solution

Land the fix in https://github.com/microsoft/vscode/pull/332624, which changes the single `indexOf` boundary check in `affectsConfiguration` (src/vs/platform/configuration/common/configurationModels.ts) into a loop that advances through occurrences of the padded section until one passes the boundary check.

## Evidence
