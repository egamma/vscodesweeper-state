# Issue #326602 — Clicking migrate on Ollama deprectaed setting leads to an error

[https://github.com/microsoft/vscode/issues/326602](https://github.com/microsoft/vscode/issues/326602)

## Summary

Team-authored bug report about the Ollama deprecation "Migrate" link in the Manage Models view failing to open the Extensions view. The deprecation link (`vscode:extension/Ollama.ollama`) is rewritten via `resolveProviderDeprecationLink` to match the build's `urlProtocol`, but the opener/URL-handler pipeline fails — likely because the extension identifier doesn't resolve in the marketplace or the URL handler drops the request silently. No fix on current main.

## Change summary

Clicking the "Migrate" link on the deprecated Ollama provider in the Manage Models view produces an error instead of opening the Ollama extension in the Extensions view.

## Best solution

Debug the opener pipeline for the resolved `code-oss:extension/Ollama.ollama` URI in `chatModelsWidget.ts`. The `Link` component (line 563) calls `resolveProviderDeprecationLink` and passes the result as an `href` string. The `ExtensionsWorkbenchService.handleURL` handler expects a URI with path `extension/<id>` — verify the URI is parsed correctly by the opener service and that the extension identifier `Ollama.ollama` resolves in the gallery. If the extension is not yet published, the handler should gracefully fall back to showing the extension search, not an error.
