# Issue #297354 — Store plans isn't clickable

[https://github.com/microsoft/vscode/issues/297354](https://github.com/microsoft/vscode/issues/297354)

## Summary

Keep open: response linkification still treats virtual memory paths as filesystem paths, so a stored session plan can remain inaccessible from its reference. Experimental artifacts provide an alternative affordance, but do not resolve the default response behavior.

## Change summary

Make a plan referenced as /memories/session/plan.md directly openable from chat through a working link or plan affordance.

## Best solution

Expose the actual stored plan from the originating chat session without requiring users to locate its backing storage directory. Coordinate this with the existing artifact work, preserving session-specific resolution and normal file-link behavior.

## Evidence

- **Current-source failure path:** In extensions/copilot/src/extension/linkify/common/filePathLinkifier.ts, FilePathLinkifier.linkify matches inline-code paths, but resolvePathText first stats /memories/session/plan.md as a literal file URI, then searches workspace folders. If those physical files do not exist, it returns undefined and preserves the unclickable text. LinkifierContext in extensions/copilot/src/extension/linkify/common/linkifyService.ts supplies requestId and references, not a chat session resource or memory-path resolver.
- **Actual memory storage:** extensions/copilot/src/extension/tools/node/resolveMemoryFileUriTool.tsx resolves /memories/session/... under workspace storage at memory-tool/memories/<sessionId>/..., using options.chatSessionResource and extractSessionId. The virtual path therefore does not identify the physical file checked by ordinary response linkification.
- **Existing capabilities are partial:** Chat: Show Memory Files, command github.copilot.chat.tools.memory.showMemories, opens session files through a quick pick in extensions/copilot/src/extension/tools/vscode-node/tools.ts. src/vs/workbench/contrib/chat/common/chatArtifactExtraction.ts extracts plan artifacts from memory writes, and browser/chatArtifactPillSource.ts resolves their memory URIs before opening them. However, browser/chat.shared.contribution.ts registers chat.artifacts.enabled with default false, and ChatArtifactPillSource suppresses these plan artifacts when disabled. Neither capability makes the reported inline virtual path directly openable by default.
