# Issue #343989 — Engineering - macOS Sign jobs restore the full node_modules cache that codesigning doesn't use

[https://github.com/microsoft/vscode/issues/343989](https://github.com/microsoft/vscode/issues/343989)

## Summary

Keep open as release-engineering debt: current main still runs the full dependency-cache setup in both macOS Sign jobs. The source supports the reported optimization opportunity, but the timing savings and artifact equivalence require product-mode validation.

## Change summary

Reduce macOS Sign job preparation to the dependencies and quality metadata needed for packaging, signing, and notarization.

## Best solution

Give the x64 and arm64 Sign jobs a dependency-minimal preparation path while preserving quality-specific product metadata, artifact outputs, signing, and notarization behavior. Require product-mode validation of both architectures; treat any removal of zip notarization as a separate release-owner decision.

## Evidence

- **Current pipeline still performs the reported work:** build/azure-pipelines/darwin/product-build-darwin.yml invokes steps/product-build-darwin-setup.yml for macOS_<arch>_Sign before downloading compilation artifacts and packaging. That setup restores and extracts .build/node_modules_cache/cache.tgz, or runs the full npm installation and distro dependency mixin on a cache miss.
- **Signing dependency boundary:** build/darwin/sign.ts imports @electron/osx-sign and @malept/cross-spawn-promise; build/darwin/sign-server.ts and build/darwin/create-dmg.ts also import the spawn helper. build/package.json declares @electron/osx-sign and the Azure/publishing dependencies, whereas root package.json declares deemon, which product-build-darwin-package.yml invokes through npx for both detach and attach.
- **Transitive publishing imports must remain available:** build/azure-pipelines/darwin/codesign.ts imports e from ../common/publish.ts. That module has runtime imports of @azure/cosmos, @azure/msal-node, @azure/storage-blob, jws, and yauzl, so a slim setup cannot assume codesigning needs only the direct signing packages.
- **Quality metadata remains necessary:** build/darwin/sign.ts and build/darwin/create-dmg.ts read repository-root product.json. build/azure-pipelines/distro/mixin-quality.ts merges the quality-specific product definition into that file; omitting this preparation without an equivalent source of metadata could change app-path resolution.
- **Notarization is a separate behavioral decision:** build/azure-pipelines/darwin/codesign.ts independently calls codesignAndNotarize for the client zip and DMG, and additionally for server and web artifacts on non-universal builds. The issue explicitly separates possible zip-notarization removal from the dependency-cache optimization; no evidence here establishes that removal is safe.
- **Impact and validation limits:** https://github.com/microsoft/vscode/issues/343989 reports approximately 4.2 minutes median cache restoration/extraction across eight official Insiders builds and specifies product-mode signature and Gatekeeper checks before landing. Those measurements were not independently rerun; the checkout was inspected read-only.
- **Protected maintainer-authored work:** The author association is COLLABORATOR. Current source confirms the requested cleanup remains relevant, and no concrete fixing commit or verified duplicate was established; there is no basis for a factual close.
