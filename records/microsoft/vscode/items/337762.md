# Issue #337762 — Copilot Chat repeatedly fails with attachment 404 after browser screenshot tool completes

[https://github.com/microsoft/vscode/issues/337762](https://github.com/microsoft/vscode/issues/337762)

## Summary

Well-diagnosed, multiply-confirmed bug: enabling `github.copilot.chat.responsesApi.promptCacheBreakpoint.enabled` causes the CAPI backend to lose access to attached image URLs (view_image/browser screenshot), producing a 400/upstream-404 on the next request. A mitigation (flipping the default to false) already merged via PR #338265 and is present on current main, but the underlying defect lives in the CAPI service, so this must stay open pending the upstream fix.

## Change summary

After the browser screenshot tool (or view_image) attaches an image, the very next Copilot Chat request fails with a CAPI 400 / upstream 404 because the image URL is no longer resolvable, when the prompt-cache-breakpoint setting is enabled.

## Best solution

Keep open until the root cause is fixed on the CAPI side (tracked at https://github.com/github/copilot-api/issues/38931); the local mitigation of defaulting `github.copilot.chat.responsesApi.promptCacheBreakpoint.enabled` to false already shipped via https://github.com/microsoft/vscode/pull/338265, confirmed present on current main (extensions/copilot/package.json, default: false as of commit 4fbdaab4).
