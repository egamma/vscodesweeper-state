# Issue #155794 — Adopt argsCanBeInterpretedByShell for external terminals

[https://github.com/microsoft/vscode/issues/155794](https://github.com/microsoft/vscode/issues/155794)

## Summary

This team-authored debt remains on current main: VS Code advertises `argsCanBeInterpretedByShell` support, but the external-terminal path drops the flag and retains separate, less precise argument handling. The source path is bounded and has no open canonical issue or fixing PR.

## Change summary

Make debug sessions launched in external terminals honor the DAP `argsCanBeInterpretedByShell` argument-handling contract on Linux and Windows.

## Best solution

Bring Linux and Windows external-terminal command construction in line with the shell-aware argument handling already used for integrated debug terminals, while preserving the existing macOS helper behavior.

- **Behavior:**

  > A debug adapter can request an external terminal with `argsCanBeInterpretedByShell`. On Linux and Windows, false or omitted preserves every argument as literal program input, including shell metacharacters; true allows the supplied shell syntax to be interpreted. Existing macOS external-terminal behavior remains unchanged. Acceptance requires focused command-construction tests for both flag states on Linux and Windows.
- **Trace:**

  > DebugSession in src/vs/workbench/contrib/debug/browser/debugSession.ts advertises `supportsArgsCanBeInterpretedByShell`, and the integrated branch of ExtHostDebugService.$runInTerminal forwards the flag to `prepareCommand`. The external branch enters `runInExternalTerminal` in src/vs/workbench/api/node/extHostDebugService.ts, where the flag is omitted because IExternalTerminalService.runInTerminal in src/vs/platform/externalTerminal/common/externalTerminal.ts has no corresponding parameter. WindowsExternalTerminalService and LinuxExternalTerminalService then construct shell commands using independent quoting logic in src/vs/platform/externalTerminal/node/externalTerminalService.ts; the Linux helper only detects spaces, while Windows always wraps joined arguments. The issue discussion explicitly limits the needed alignment to Linux and Windows and treats the macOS AppleScript quoting as adequate, so macOS behavior and ordinary non-debug `openTerminal` calls are outside the change boundary. The originating behavior is documented at https://github.com/microsoft/vscode/issues/149910.
