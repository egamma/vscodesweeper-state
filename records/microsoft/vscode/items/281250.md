# Issue #281250 — Support private Marketplace for On-Premise Github Enterprises without need of github.copilot.advanced.authProvider setting

[https://github.com/microsoft/vscode/issues/281250](https://github.com/microsoft/vscode/issues/281250)

## Summary

The coupling still exists on current main: Private Marketplace obtains its GitHub identity through the default-account service, which selects GitHub Enterprise only when the Copilot advanced auth-provider setting names `github-enterprise`. This maintainer-authored Backlog request therefore remains necessary and must stay open.

## Change summary

Allow an on-premises GitHub Enterprise account to authenticate to Private Marketplace without configuring `github.copilot.advanced.authProvider`.

## Best solution

Give Private Marketplace an explicit, Copilot-independent way to select and use the configured `github-enterprise` authentication provider, while preserving the existing GitHub.com and Microsoft authentication paths.

## Plan brief

- **Likely files:** `src/vs/workbench/services/accounts/browser/defaultAccount.ts`, `src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts`, `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, `src/vs/workbench/services/extensionManagement/test/electron-browser/extensionGalleryManifestService.test.ts`
- **Validation:** Add a marketplace account-service test proving that a configured `github-enterprise` session can make a private marketplace available while `github.copilot.advanced.authProvider` is unset, and retain coverage for the existing GitHub.com and Microsoft provider paths.
- **Behavior:**

  > An administrator configuring a private Marketplace and `github-enterprise.uri` can authenticate with the corresponding on-premises GitHub Enterprise account without setting a Copilot-specific authentication option. Existing GitHub.com and Microsoft Marketplace authentication behavior remains unchanged. The selected provider must survive restart through a documented application-scoped configuration contract.
- **Trace:**

  > Private Marketplace constructs `GitHubGalleryAccountProvider` in src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts, and that provider obtains identity and entitlement from `IDefaultAccountService`. In src/vs/workbench/services/accounts/browser/defaultAccount.ts, the enterprise provider is selected only when the configuration key derived from `defaultChatAgent.completionsAdvancedSetting` equals `github-enterprise`; otherwise it selects GitHub.com. The gallery-specific `extensions.gallery.authProvider` registration in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts currently exposes only `github` and `microsoft`. The boundary is Marketplace authentication selection: do not change Copilot's own provider-selection behavior or the existing Microsoft Marketplace path. The originating workaround and maintainer intent are documented at https://github.com/microsoft/vsmarketplace/issues/1495.
- **Open decisions:**
  - Should Private Marketplace infer GitHub Enterprise from `github-enterprise.uri`, or should `extensions.gallery.authProvider` expose an explicit `github-enterprise` value?
  - When both GitHub.com and GitHub Enterprise sessions exist, which account should Private Marketplace select by default and how should administrators make that choice deterministic?

## Evidence

- **current source gap:** src/vs/workbench/services/accounts/browser/defaultAccount.ts derives `enterpriseProviderConfig` from `${defaultChatAgent.completionsAdvancedSetting}.authProvider` and `getDefaultAccountAuthenticationProvider()` selects the enterprise provider only when that Copilot-derived setting equals `github-enterprise`.
- **marketplace dependency:** src/vs/workbench/services/extensionManagement/electron-browser/extensionGalleryAccountService.ts implements the GitHub marketplace path through `IDefaultAccountService.getDefaultAccount()`, so it inherits the Copilot setting dependency rather than independently selecting the configured GitHub Enterprise provider.
- **missing provider option:** src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts currently limits `extensions.gallery.authProvider` to `github` and `microsoft`; it has no `github-enterprise` option despite product.json defining that authentication provider.
- **originating report:** https://github.com/microsoft/vsmarketplace/issues/1495 records that `github.copilot.advanced.authProvider: github-enterprise` was the successful workaround and that the maintainer opened this issue because the setting should not be required.
- **related but not canonical:** https://github.com/microsoft/vscode/issues/296917 is newer and concerns GitHub Enterprise Cloud subscription entitlement detection, not the same on-premises provider-selection symptom; under the re-review duplicate rule it cannot replace this issue as canonical.
- **user impact:** A commenter reports that the missing support blocks an enterprise-scale Private Marketplace rollout for approximately 5,000 developers.
