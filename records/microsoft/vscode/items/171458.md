# Issue #171458 — Leaving duplicate workspace nodes When refreshing

[https://github.com/microsoft/vscode/issues/171458](https://github.com/microsoft/vscode/issues/171458)

## Summary

The teardown race remains visible in current source: removing an extension-provided filesystem during page reload causes ExplorerService to discard its children and rerender the tree immediately before the workbench exits. This is a confirmed, bounded visual bug rather than a duplicate or completed issue.

## Change summary

Refreshing a vscode.dev GitHub workspace briefly replaces the populated Explorer tree with an unresolved or duplicate workspace root.

## Best solution

Keep the existing response to filesystem-provider changes during normal operation, but prevent Explorer from rebuilding its tree when provider removal is caused by workbench shutdown or reload.
