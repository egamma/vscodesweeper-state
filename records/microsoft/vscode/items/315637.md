# Issue #315637 — Add a 'Enable in Agent window` in extensions view

[https://github.com/microsoft/vscode/issues/315637](https://github.com/microsoft/vscode/issues/315637)

## Summary

A real UI gap remains: extensions can be opted into the Agents window through settings, but the Extensions view has no equivalent action. This team-authored Backlog request should remain open for a product decision on how the override interacts with extension-declared support.

## Change summary

Add an Extensions view action that enables an installed extension for use in the Agents window.

## Best solution

Expose a clearly scoped Agents-window enablement action for eligible installed extensions, backed by `extensions.supportAgentsWindow`, while distinguishing user overrides from extensions that declare native Agents-window support.

## Vision fit

- **Fit:** aligned
- **Reason:** Making extension enablement discoverable in the agent-focused UI supports both AI-assisted development and the extension ecosystem without adding unrelated core capability.
- **Evidence:** Durable themes: “AI-assisted development” and “Extension ecosystem”; the request also supports the value that “The power lives in extensions.”

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts`, `src/vs/workbench/contrib/extensions/browser/extensionEditor.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsActions.test.ts`, `src/vs/sessions/contrib/extensions/browser/extensions.contribution.ts`
- **Validation:** Add focused extension-action tests verifying the action's visibility and enabled state for supported and unsupported installed extensions, and that invoking it produces the chosen `extensions.supportAgentsWindow` user override without changing ordinary global/workspace enablement.
- **Behavior:**

  > An installed extension that is not currently available in the Agents window exposes a discoverable action to enable it there. Invoking the action updates Agents-window availability without changing the extension's normal global or workspace enablement. Extensions already supported in the Agents window must not show a misleading enable action. Acceptance must cover extensions enabled by default, enabled by manifest capability, and enabled through the user override.
- **Trace:**

  > `ExtensionManifestPropertiesService.canExecuteOnSessionsWindow` in `src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts` resolves `extensions.supportAgentsWindow` before manifest-declared support and fallback restrictions. The setting schema remains in `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts`, while the experimental capability flag is Sessions-owned in `src/vs/sessions/contrib/extensions/browser/extensions.contribution.ts`. Extension detail and manage actions are assembled by `EnableDropDownAction`, `ManageExtensionAction`, and `extensionEditor.ts`; none currently represents Agents-window support. Preserve ordinary global/workspace enablement and the manifest capability path; this request concerns only the per-extension Agents-window override. The originating test workflow is documented at https://github.com/microsoft/vscode/issues/315249.
- **Open decisions:**
  - Should a user action be allowed to override an extension that explicitly declares `capabilities.agentsWindow.supported: false`, or only opt in extensions that have not declared support?
  - After a user override is set, should the UI offer a paired Disable action that writes `false`, or a reset action that removes the override and returns to manifest/default behavior?
  - Should this action appear only in the Agents window's Extensions surface, or in every Extensions view with Agents-window-specific labeling?

## Evidence

- **existing setting:** `src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts` registers `extensions.supportAgentsWindow` as an application-scoped per-extension override, so the underlying enablement mechanism already exists.
- **missing Extensions action:** `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts` composes global/workspace enablement actions in `EnableDropDownAction` and `ManageExtensionAction`, but contains no Agents-window enablement action or update of `extensions.supportAgentsWindow`.
- **current capability model:** `src/vs/workbench/services/extensions/common/extensionManifestPropertiesService.ts` checks the user override first, then an extension's proposed `capabilities.agentsWindow.supported` declaration, and otherwise restricts executable extensions.
- **ongoing ownership:** Commit a1db225078bb4b859c0b23f9ea2c4b1b775632d3 moved registration of the experimental Agents-window capability flag into `src/vs/sessions/contrib/extensions/browser/extensions.contribution.ts`, confirming that this remains an active Sessions-owned concern without implementing the requested UI action.
- **maintainer demand:** The issue was filed by a repository member while executing the extension-support test plan at https://github.com/microsoft/vscode/issues/315249; the requested action removes the need to edit the override object manually during testing.
