# Issue #341547 — onDidEndTerminalShellExecution never fires and read() never ends when the terminal is closed while a shell-integration command is running

[https://github.com/microsoft/vscode/issues/341547](https://github.com/microsoft/vscode/issues/341547)

## Summary

Thanks for the detailed report. The source confirms it: on terminal close, the extension host only disposes the shell integration object and never ends the running execution or fires the end event, so `read()` never completes.

## Change summary

Closing a terminal while a shell-integration command runs leaves onDidEndTerminalShellExecution unfired and read() hanging.

## Best solution

In extHostTerminalShellIntegration.ts, end the current, pending-ending and pending executions with an undefined exit code, flush the data stream, and fire the end event before disposing. Then document 'terminal closed' as a reason for an undefined exitCode in vscode.d.ts.
