# Issue #227580 — [Accessibility] The Explorer section view needs role and name information.

[https://github.com/microsoft/vscode/issues/227580](https://github.com/microsoft/vscode/issues/227580)

## Summary

The accessibility defect remains in current source: the active-view switcher uses tab semantics, but the corresponding Explorer composite has no tabpanel role or reciprocal naming/control relationship. No older open canonical reports this same Explorer symptom, so the re-review duplicate bar is not met.

## Change summary

Expose Explorer and other pane composites as named tabpanels associated with their active-view switcher tabs.

## Best solution

Complete the existing tab pattern for pane composites by associating each view-switcher tab with its panel and exposing the visible panel with an accessible role and name. Preserve the intentionally presentation-only outer workbench part and existing keyboard navigation.

## Evidence

- **current tab semantics:** src/vs/workbench/browser/parts/compositeBar.ts creates the Active View Switcher with `ariaRole: 'tablist'`; src/vs/workbench/browser/parts/compositeBarActions.ts assigns each item `role="tab"` and updates `aria-selected`, but neither file assigns `aria-controls`.
- **missing panel semantics:** src/vs/workbench/browser/parts/compositePart.ts creates each view container as `.composite` with the composite ID and appends it in `showComposite`, but assigns no `tabpanel` role, accessible name, or `aria-labelledby` relationship.
- **outer role is intentional:** src/vs/workbench/browser/workbench.ts still creates `workbench.parts.sidebar` with `role="none"`, alongside a source comment explaining that presentation-only roles on these outer parts reduce screen-reader verbosity; the panel semantics therefore belong on the inner composite rather than by replacing this outer role.
- **no canonical duplicate:** The adjacent audit reports https://github.com/microsoft/vscode/issues/227496 and https://github.com/microsoft/vscode/issues/227510 are closed and concern editor tabs and bottom-panel tabs respectively; neither is an open canonical for the Explorer/sidebar symptom required by the re-review duplicate rule.
