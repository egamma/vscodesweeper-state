# Issue #267028 — Shell integration leaks variables

[https://github.com/microsoft/vscode/issues/267028](https://github.com/microsoft/vscode/issues/267028)

## Summary

Confirmed on current main: the five reported variables are defined at global scope in shellIntegration-bash.sh and never unset after use. The issue is still valid — these should be cleaned up.

## Change summary

Shell integration bash script leaks five helper variables (bash_major_version, envVarsToReport, use_associative_array, vsc_env_keys, vsc_env_values) into the user's shell environment.

## Best solution

Add `unset` calls for the five leaked variables after their last use in shellIntegration-bash.sh. The `bash_major_version` and `use_associative_array` vars are consumed only during setup (lines 13–28) and in `__vsc_update_env`, so they could be replaced with inline checks or prefixed with `__vsc_` and unset. The array vars (`vsc_env_keys`, `vsc_env_values`, `envVarsToReport`) persist for the env-reporting functions and need careful scoping — either namespace-prefix them with `__vsc_` or restructure the env-reporting helpers to avoid leaking.
