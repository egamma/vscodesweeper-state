# Issue #260871 — Explorer/Editor: Copy-pasting multiple files shows new file as selected but editor stays on original

[https://github.com/microsoft/vscode/issues/260871](https://github.com/microsoft/vscode/issues/260871)

## Summary

The inconsistent state remains on current main: multi-file paste selects the first copied target in Explorer but deliberately opens it only when exactly one target was pasted. The reporter reconfirmed the behavior on a newer build, and the exact earlier report is closed, so there is no open canonical to absorb this issue.

## Change summary

After pasting multiple files, Explorer presents a copied file as selected while the editor remains on its original source file.

## Best solution

Keep Explorer selection and the active editor unambiguous after multi-file paste. A maintainer should choose whether the focused copied file becomes active or whether the existing active file retains the primary selection while the pasted target receives only operation focus.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/files/browser/fileActions.ts`, `src/vs/workbench/contrib/files/test/browser/fileActions.test.ts`
- **Validation:** Add a Files - Paste unit test that pastes at least two files and asserts the maintainer-selected contract between explorerService.select and editorService.openEditor; run the targeted Files - Paste suite.
- **Behavior:**

  > After multiple files are pasted, VS Code must not present a copied file as the active Explorer selection while the editor remains on its original source. The Explorer and editor should communicate consistently which file is active, without opening every pasted file. Single-file paste behavior must remain unchanged. Acceptance should cover at least two pasted files and verify both Explorer selection and editor activation.
- **Trace:**

  > pasteFileHandler in src/vs/workbench/contrib/files/browser/fileActions.ts collects pasted target URIs, always calls explorerService.select(firstTarget), and calls editorService.openEditor only under targets.length === 1. This directly reproduces the reported multi-file mismatch in current source. The same symptom was documented in https://github.com/microsoft/vscode/issues/122586, while https://github.com/microsoft/vscode/issues/120882 explains why opening every pasted file is not acceptable. Keep the boundary to post-paste selection/editor behavior; do not alter copy destination resolution, bulk-edit semantics, incremental naming, or the established single-file behavior.
- **Open decisions:**
  - For a multi-file paste, should the focused copied file become the active editor, or should the existing active file retain the primary Explorer selection while a pasted target receives only non-active operation focus?

## Evidence

- **current source:** In src/vs/workbench/contrib/files/browser/fileActions.ts:1268-1276, pasteFileHandler always calls explorerService.select(firstTarget), but editorService.openEditor is guarded by targets.length === 1. A multi-file paste therefore takes exactly the inconsistent path reported.
- **current confirmation:** The reporter confirmed on 2025-12-10 that the behavior was still present after a maintainer asked them to retry on the latest VS Code: https://github.com/microsoft/vscode/issues/260871#issuecomment-3639551267
