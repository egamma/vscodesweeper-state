# Issue #328722 — Unable to collapse an expanded sbagent

[https://github.com/microsoft/vscode/issues/328722](https://github.com/microsoft/vscode/issues/328722)

## Summary

Keep open: multiple commenters reproduced the inability to collapse an active subagent, including on a September 2026 Insiders build. This is also a team-authored issue, and no explicitly referencing fix or older canonical satisfies the protected-item close bar.

## Change summary

Collapsing an expanded subagent while it is still working briefly changes the disclosure state but leaves or restores the expanded content.

## Best solution

Preserve a user's collapsed state while active subagent progress updates are streamed or regrouped, with a regression test that collapses a running subagent and then delivers another child update.

- **Behavior:**

  > An active subagent can be expanded and collapsed at any time. After the user collapses it, subsequent progress, tool, or title updates must leave its details hidden and its disclosure state collapsed. Completion must not be required before collapse works, while confirmation-driven expansion behavior should remain unchanged.
- **Trace:**

  > The direct disclosure mechanism is `ChatCollapsibleContentPart.toggleExpanded` in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatCollapsibleContentPart.ts, and isolated click tests show it can set the collapsed state. Active subagent child updates are grouped through `ChatListRenderer.handleSubagentToolGrouping` in src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts, while broader streaming rebuild paths can dispose and replace rendered content parts. `ChatSubagentContentPart` initializes each instance collapsed and keeps manual-expansion flags locally, so replacement or an update-triggered expansion can discard the user's state. Determine which update occurs immediately after the collapse before bounding the implementation. Preserve confirmation auto-expansion and completed-response disclosure behavior.
