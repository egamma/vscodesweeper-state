# Issue #315209 — $env:ComSpec = 'pwsh.exe' broke startup

[https://github.com/microsoft/vscode/issues/315209](https://github.com/microsoft/vscode/issues/315209)

## Summary

The startup error follows replacing the Windows batch-command interpreter with PowerShell, rather than a demonstrated defect in VS Code. Propose answering how to restore ComSpec and closing as a support question.

## Change summary

Launching `code .` fails when ComSpec points to pwsh.exe instead of cmd.exe.

## Best solution

Keep ComSpec pointing to the Windows cmd.exe interpreter while continuing to use PowerShell as the interactive shell; no VS Code launcher change is established as necessary.

- **Proposed comment:**

  > Thanks for the report. `code` on Windows uses a `.cmd` launcher, which requires cmd.exe; ComSpec is not an interchangeable interactive-shell preference. In your PowerShell session, restore it with `$env:ComSpec = "$env:SystemRoot\System32\cmd.exe"`, then run `code .` again. You can continue using PowerShell as your interactive shell without changing ComSpec.

- **Current launcher:** resources/win32/bin/code.cmd and resources/win32/versioned/bin/code.cmd are cmd.exe batch scripts using `@echo off`, `setlocal`, `%~dp0`, and `%*`. Both quote the executable and cli.js paths. PowerShell is not a compatible interpreter for these scripts, and changing quoting inside them cannot repair their initial invocation by an incompatible interpreter.
- **Windows execution contract:** https://learn.microsoft.com/en-us/windows/win32/api/processthreadsapi/nf-processthreadsapi-createprocessw explicitly states that running a batch file requires starting cmd.exe with `/c` and the batch filename.
