[https://github.com/microsoft/vscode/issues/257972](https://github.com/microsoft/vscode/issues/257972)

## Summary

Keep open: the supplied update-and-reconnect steps suffice to retest both the forgotten preference and the required service restart. Current main contains automatic CLI respawn machinery, but inspection does not establish that it resolves this report, and related reports do not cover both symptoms.

## Change summary

Remote CLI updates repeatedly prompt despite choosing "Always update" and leave the tunnel unusable until its systemd user service is manually restarted.

## Best solution

Make the tunnel update flow remember the selected update policy and restore connectivity using the updated CLI without requiring shell access to the host. First reproduce a service-hosted update and establish whether preference persistence and restart failure have separate causes.
