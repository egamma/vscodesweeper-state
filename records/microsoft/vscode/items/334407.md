# Issue #334407 — Add macOS Touch Bar status and quota display features.

[https://github.com/microsoft/vscode/issues/334407](https://github.com/microsoft/vscode/issues/334407)

## Summary

This Claude Code-specific status and quota display belongs in the Claude Code extension rather than VS Code core. Existing Touch Bar extension support and directly comparable maintainer precedent support an *extension-candidate close.

## Change summary

Show Claude Code task status, quota usage, and related information on the macOS Touch Bar.

## Best solution

Implement the experience in the Claude Code extension, which owns the task and quota data, using VS Code's Touch Bar contribution point where sufficient. Any unavailable capability should be reduced to a concrete extension-API gap rather than adding Claude-specific behavior to core.

## Vision fit

- **Fit:** rejected
- **Reason:** A provider-specific integration for uncommon hardware is better delivered by the extension that owns the underlying data than bundled into the lightweight core.
- **Evidence:** Values and guardrails: “The power lives in extensions” and capabilities that can be built through the extension API generally belong in extensions.

  > Thanks for the request. Claude Code owns the task and quota data, while VS Code already exposes the `menus.touchBar` contribution point for extensions; similar feature-specific Touch Bar additions have been treated as extension candidates in https://github.com/microsoft/vscode/issues/108504, and a broader Touch Bar API was declined in https://github.com/microsoft/vscode/issues/35164. ## Evidence

- **extension contribution point:** src/vs/workbench/services/actions/common/menusExtensionPoint.ts exposes `menus.touchBar` to extensions as the macOS Touch Bar menu.
- **current implementation boundary:** src/vs/workbench/electron-browser/window.ts builds the Touch Bar from contributed command actions, while src/vs/platform/windows/electron-main/windowImpl.ts renders each action as a labeled or icon-based Touch Bar segment.
- **direct precedent:** https://github.com/microsoft/vscode/issues/108504 was closed with `*extension-candidate`; a maintainer explicitly confirmed that feature-specific Touch Bar commands can be implemented by extensions.
- **API precedent:** https://github.com/microsoft/vscode/issues/35164 requested a richer first-class Touch Bar API and was closed `*out-of-scope`, establishing that core does not intend to expose the broader Electron Touch Bar surface.
- **ownership:** Task state and quota usage are Claude Code provider data, not state owned by VS Code core; the issue identifies no provider-independent extension API gap.
