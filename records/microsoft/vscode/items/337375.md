# Issue #337375 — Chat session persists only its kind:0 snapshot — no ops ever appended, session silently vanishes from chat list and cannot be resumed

[https://github.com/microsoft/vscode/issues/337375](https://github.com/microsoft/vscode/issues/337375)

## Summary

Well-evidenced report of a real gap in chat session persistence: writes to `chatSessions/*.jsonl` are only flushed via `saveState()`, itself only triggered by the storage service's periodic/shutdown `onWillSaveState` event (or an explicit rename), not per-turn — so if that event is skipped or delayed for a live window, an entire session's ops silently never reach disk, matching the reporter's stub-file evidence exactly. No fix commit exists yet; this is unrouted (no labels) so proposing it go to the chat area for further diagnosis.

## Change summary

Long chat sessions sometimes never get any ops appended past the initial snapshot, so the index marks them isEmpty and they vanish from the chat list with no error or recovery path.

## Best solution

Chat area owners should investigate why `onWillSaveState`-driven `saveState()` can fail to fire/complete for a session's entire lifetime (remote/SSH connectivity is the reporter's working theory, corroborated by sibling issue #337278), and consider surfacing write failures to the user and/or triggering saves more proactively (e.g., after each turn) rather than relying solely on periodic storage flushes.
