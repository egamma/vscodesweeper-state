# Issue #323888 — Support `.worktreeinclude`

[https://github.com/microsoft/vscode/issues/323888](https://github.com/microsoft/vscode/issues/323888)

## Summary

Keep open: current worktree creation supports configured include patterns, but does not automatically read `.worktreeinclude`, and the file is not registered with the Ignore language. No verified older canonical issue covers both requests.

## Change summary

Automatically honor `.worktreeinclude` when creating worktrees and recognize it as an Ignore-language file.

## Best solution

Evaluate repository-local `.worktreeinclude` support alongside `git.worktreeIncludeFiles`, with explicit semantics for combining the two sources and consistent behavior across Git and agent-created worktrees. Recognize the file through the existing Ignore language so compatible icon themes can associate it appropriately.

## Evidence

- **Existing capability does not cover automatic discovery:** extensions/git/package.json registers git.worktreeIncludeFiles with an empty-array default. In extensions/git/src/repository.ts:2154–2172, Repository._getWorktreeIncludePaths reads only that setting, returns immediately when its patterns are empty, and otherwise writes those patterns to a temporary file; it does not read a repository .worktreeinclude file.
- **Documented workaround:** https://code.visualstudio.com/docs/sourcecontrol/branches-worktrees#_include-files-when-creating-a-worktree documents git.worktreeIncludeFiles for copying ignored files into new worktrees. This requires VS Code-specific configuration, which is precisely the limitation the reporter wants removed.
- **Language recognition remains missing:** extensions/git-base/package.json:75–85 registers the Ignore language for .gitignore_global, .gitignore, and .git-blame-ignore-revs, but not .worktreeinclude.
- **Related icon discussion:** https://github.com/vscode-icons/vscode-icons/issues/4146#issuecomment-4856355306 explains that registering .worktreeinclude with the Ignore language would allow vscode-icons to use its Git icon. The reporter closed that external request in favor of this VS Code issue: https://github.com/vscode-icons/vscode-icons/issues/4146#issuecomment-4856603519. Its closure is not evidence that VS Code implemented the request.
- **Related merged PR is not the requested capability:** https://github.com/microsoft/vscode/pull/337942 is merged and changes git.worktreeIncludeFiles matching to .gitignore syntax. Its described changes and the current source retain setting-based inclusion rather than automatically discovering .worktreeinclude; it also does not modify the git-base language registration.
- **Canonical search:** GitHub searches for worktreeinclude, including pull requests, and worktree/include title terms found no verified older canonical covering the same request. https://github.com/microsoft/vscode/issues/332096 concerns copying performance for configured patterns, was created after this issue, and does not cover file discovery or language recognition.
- **Demand and decision status:** The supplied context records three upvotes, no comments, and no maintainer acceptance or assigned milestone. This is a valid remaining feature gap, but automatic file adoption and its interaction with explicit settings still need product agreement.
