# Issue #296532 — Background: asking to keep changes when archiving worktree session is weird

[https://github.com/microsoft/vscode/issues/296532](https://github.com/microsoft/vscode/issues/296532)

## Summary

The requested distinction between archiving an isolated session and deciding its edits remains unresolved: current source still explicitly prompts on archive. Related reports discuss the same lifecycle, but none verified here meets the stronger duplicate bar for this re-reviewed item.

## Change summary

Allow archiving a background worktree session without requiring a keep-or-undo decision on its changes.

## Best solution

Define archive semantics that preserve recoverable worktree-session changes without forcing an edit-review decision. Coordinate that behavior with worktree cleanup and restoration, while retaining appropriate safeguards for changes in the user's main workspace.
