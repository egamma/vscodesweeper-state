# Issue #203767 — click to expect the hover display information to be dynamically updated without refreshing the hover.

[https://github.com/microsoft/vscode/issues/203767](https://github.com/microsoft/vscode/issues/203767)

## Summary

Keep open: current hover commands and provider APIs do not offer general-purpose, in-place refresh after an extension command changes the underlying data. Expandable hovers address a narrower interaction, and no verified canonical issue absorbs this request.

## Change summary

Allow extension-controlled hover content to update after clicking a command link without dismissing and reopening the hover.

## Best solution

Define a supported refresh or invalidation contract for extension-provided hovers that updates the visible content without a hide/show cycle, preserving existing Show or Focus Hover behavior. Explicitly settle how that contract applies to completion documentation, which the reporter also identified.

Include an equivalent completion-documentation check if that surface is included in the contract.
- **Behavior:**

  > An extension author needs to update a visible hover after a command link changes the data represented by that hover. The new content should appear without moving the pointer or cursor and without dismissing and reopening the widget. Repeated interactions should continue to work at the original hovered location. Existing Show or Focus Hover and expandable-hover interactions must remain intact; completion-documentation coverage must be explicitly defined.
- **Trace:**

  > ShowOrFocusHoverAction.run in src/vs/editor/contrib/hover/browser/hoverActions.ts normally focuses an already-visible hover. Its alternative show path reaches ContentHoverWidgetWrapper.startShowingAtRange, where _startShowingOrUpdateHover reuses a result at the same anchor and _startHoverOperationIfNecessary also suppresses matching-anchor requests. HoverProvider in src/vscode-dts/vscode.d.ts has no change-notification event. markdownHoverParticipant.ts supports replacing rendered contents for provider-supported verbosity changes, but that is a distinct contract rather than arbitrary invalidation. The reporter distinguishes this partial capability in https://github.com/microsoft/vscode/issues/203767; https://github.com/microsoft/vscode/issues/195394 documents the narrower verbosity work. The remaining uncertainty is the extension-facing refresh contract and its coverage of completion documentation, not whether default show/focus behavior should be silently repurposed.
- **Open decisions:**
  - Should extensions explicitly request a one-shot refresh through a command, or publish provider-data invalidation through an event that refreshes visible hovers automatically?
  - Should the supported contract also refresh completion-item documentation, as requested in the thread, or initially cover editor hovers only?
