# Issue #185904 — feature request: structured logging console

[https://github.com/microsoft/vscode/issues/185904](https://github.com/microsoft/vscode/issues/185904)

## Summary

This remains a valid, community-backed debug-console feature request: it exceeded the backlog threshold with 42 upvotes, and no evidence shows that current VS Code provides structured parsing and field-aware querying of program output.

## Change summary

Add structured-log parsing and richer querying to the Debug Console, including support for hiding noisy fields such as timestamp prefixes.

## Best solution

Define a structured debug-output model or adapter-facing metadata contract, then let the Debug Console filter or hide recognized fields while preserving today's plain-text output and filtering behavior for unstructured messages.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/browser/replViewer.ts`, `src/vs/workbench/contrib/debug/common/debugModel.ts`, `src/vs/workbench/contrib/debug/common/debugProtocol.d.ts`
- **Validation:** Add Debug Console tests using plain-text and representative structured messages, confirming field-aware filtering or hiding works for supported structured input while existing text filtering and rendering remain unchanged.
- **Behavior:**

  > The Debug Console recognizes explicitly supported structured log records and lets users query or hide fields, including suppressing timestamp prefixes from the visible message. Plain-text output and unsupported formats continue to render exactly as they do today. Acceptance should cover at least one agreed structured format, field-aware filtering, timestamp-field hiding, and unchanged existing include/exclude filtering for unstructured lines.
- **Trace:**

  > The current issue targets the Debug Console and potentially Output, but the first design boundary should remain the debug contribution under src/vs/workbench/contrib/debug. Debug-adapter output enters the debug model and is rendered by the REPL viewer; the current request does not settle whether structure is conveyed through a protocol contract or inferred from text. The existing plain-text path and behavior for adapters that do not opt into structure must not change. https://github.com/hashicorp/terraform-ls/issues/1271 is related only as producer-side logging context and does not own this feature.
- **Open decisions:**
  - Should structured fields be supplied explicitly by debug adapters through a public protocol contract, inferred by VS Code from selected text formats, or both?
  - Which formats or field schema are supported initially, and is timestamp recognition configurable or fixed?
  - Does the first scope cover only the Debug Console, or must the same structured-query behavior also be available in Output channels?
  - Should hidden fields affect only presentation, or also copying, persistence, and search results?
