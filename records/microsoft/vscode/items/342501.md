# Issue #342501 — MCP migrate: offer a Migrate code action

[https://github.com/microsoft/vscode/issues/342501](https://github.com/microsoft/vscode/issues/342501)

## Summary

Keep open as a request for contextual migration navigation. The migration page already exists, but the inspected MCP editor contribution does not offer a Migrate code action; manually opening Customizations does not cover that entry-point request.

## Change summary

Offer a Migrate code action in MCP configuration files that opens the existing migration page.

## Best solution

Provide a contextual entry point into the existing Customizations migration review, rather than executing migration directly from the editor. Preserve the current review and confirmation flow and establish which session supplies the migration context.

- **Behavior:**

  > Users editing a legacy MCP configuration should be able to invoke Migrate and reach the existing MCP migration review without finding Customizations manually. Invoking the navigation action must not itself rewrite or remove configuration. Acceptance includes correct session targeting and consistent availability when migration or AI features are disabled.
- **Trace:**

  > McpLanguageFeatures in src/vs/workbench/contrib/mcp/browser/mcpLanguageFeatures.ts provides MCP editor code lenses, inlay hints, and diagnostics, but no migration navigation or code-action registration. The existing aiCustomization.openManagementEditor handler in aiCustomizationManagement.contribution.ts accepts migration, migrationCategory, and session context through the target contract in aiCustomizationManagement.ts. The linked test plan https://github.com/microsoft/vscode/issues/342409 assumes migration is enabled and Copilot is active. The broader direction in https://github.com/microsoft/vscode/issues/332083 supports contextual links into one migration home, not a separate execution flow. Keep conversion, confirmation, and file-writing behavior unchanged. The unresolved boundary is how this editor entry point behaves when there is no eligible session to supply its migration context.
- **Open decisions:**
