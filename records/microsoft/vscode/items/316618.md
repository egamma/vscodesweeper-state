# Issue #316618 — WSL path handling in Copilot Chat does not appear to support automatic path translation

[https://github.com/microsoft/vscode/issues/316618](https://github.com/microsoft/vscode/issues/316618)

## Summary

Consolidate with the older, open remote-path report: it covers failed file edits and apparently successful writes that do not reach the remote filesystem, including WSL confirmations. Removing the extension-host override is a workaround, not evidence that the wrong-destination behavior is fixed.

## Change summary

Copilot Chat apply_patch can fail to edit WSL files or target the Windows filesystem instead of the connected WSL workspace.

## Best solution

Track the remote file-path round-trip defect in https://github.com/microsoft/vscode/issues/284417, preserving this report's apply_patch and Windows-destination details. Remote workspace edits should retain their filesystem identity rather than becoming local Windows edits.

## Evidence

- **Verified older canonical:** https://github.com/microsoft/vscode/issues/284417 is currently OPEN and was created on 2025-12-19, before this report. Its body describes Windows-hosted Copilot file tools failing against remote Linux paths and reporting successful creation without creating the remote file; https://github.com/microsoft/vscode/issues/284417#issuecomment-3682167240 confirms the same issue in Remote-WSL.
- **Same observable failure and broader scope:** The canonical covers remote file reads, edits, and creation when Copilot runs on the Windows UI host. This report's failed apply_patch edits and writes to Windows instead of WSL are manifestations of that same destination-identity problem, not the separate CLI working-directory failure described in https://github.com/microsoft/vscode/issues/314875.
- **Current source path:** extensions/copilot/src/platform/prompts/common/promptPathRepresentationService.ts: PromptPathRepresentationService.getFilePath returns uri.fsPath for vscode-remote URIs, and resolveFilePath defaults to Schemas.file. extensions/copilot/src/extension/tools/node/toolUtils.ts: resolveToolInputPath calls that resolver without a remote scheme or authority. ApplyPatchTool uses the resulting URI at extensions/copilot/src/extension/tools/node/applyPatchTool.tsx:276-277 and emits text edits for it at lines 423-424. Consequently, a bare remote path round-trips to a local file URI when the extension is forced onto the Windows host; this conditional defect is visible in source, without executing a WSL session.
- **Reporter workaround and closed related report:** The reporter's 2026-05-27 comment links https://github.com/microsoft/vscode/issues/262460 and says deleting similar settings resolved the problem, while retaining concern about wrong-destination writes. That related issue is CLOSED, so it is not a duplicate target. https://github.com/microsoft/vscode/issues/262460#issuecomment-3213257065 explains that Copilot runs as a workspace extension; https://github.com/microsoft/vscode/issues/262460#issuecomment-3239447564 records resolution after restoring workspace execution.
