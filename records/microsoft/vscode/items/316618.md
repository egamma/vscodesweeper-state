In https://github.com/microsoft/vscode/issues/262460#issuecomment-3213257065, a maintainer explains that Copilot must run as a workspace extension; https://github.com/microsoft/vscode/issues/262460#issuecomment-3239447564 confirms that workspace execution resolved that report. That closed issue is workaround evidence, not a duplicate target.
- **Current source confirms the targeting mismatch:** extensions/copilot/src/platform/prompts/common/promptPathRepresentationService.ts returns uri.fsPath for both file and vscode-remote URIs; resolveFilePath defaults to the file scheme. extensions/copilot/src/extension/tools/node/toolUtils.ts:resolveToolInputPath calls it without a remote scheme or authority. Thus a remote path represented as an absolute filesystem string resolves to a local file URI when the extension runs locally.
- **apply_patch uses the same failing path:** extensions/copilot/src/extension/tools/node/applyPatchTool.tsx:274-275 resolves patch targets through resolveToolInputPath. Its ADD branch at lines 325-330 inserts content into that resolved URI. This connects the report's local-Windows creation case directly to the canonical's remote file-targeting defect; no separate apply_patch-specific cause is established.
