# Issue #323263 — cmd+shift+A doesn't take me to the correct window

[https://github.com/microsoft/vscode/issues/323263](https://github.com/microsoft/vscode/issues/323263)

## Summary

The defect remains source-reproducible on current main: Cmd+Shift+A selects the first non-Agents main window without checking which editor window belongs to the active session. This team-authored issue should remain open and be routed to the Agents Window area.

## Change summary

Cmd+Shift+A from an active Agents Window session can focus an unrelated editor window when multiple editor windows are open.

## Best solution

The command should resolve and focus the editor window associated with the active session rather than whichever main window appears first, with an explicit fallback when that window no longer exists.

- **Behavior:**

  > From a session in the Agents Window, Cmd+Shift+A must focus the editor window belonging to that session even when multiple editor windows are open. It must not focus an unrelated window merely because that window appears first in the native window list. The agreed behavior must also be deterministic when the associated editor window has closed.
- **Trace:**

  > OpenVSCodeWindowAction.run in src/vs/sessions/electron-browser/actions/vscodeActions.ts implements Cmd+Shift+A. It obtains all main windows, excludes the current Agents window, and focuses the first remaining entry, so its result depends on list order and cannot identify the active session's destination. The nearby openSessionInVSCode path can derive workspace folders and a chat-session resource from ISessionsService.activeSession, but it always opens a forced new window rather than selecting an existing associated one. IOpenedMainWindow in src/vs/platform/window/common/window.ts exposes workspace identity, though the review did not establish that workspace identity alone uniquely represents the originating editor window. Existing tests in src/vs/sessions/test/electron-browser/vscodeActions.test.ts provide the focused test surface. Preserve the generic no-target behavior and avoid changing unrelated system-wide keybinding ownership.
- **Open decisions:**
  - Should the target be the exact editor window from which the session originated, or may any currently open editor window for the same workspace satisfy the command?
  - When the session's associated editor window no longer exists, should Cmd+Shift+A open a new session-bound editor window or focus the most recently active editor window?
