- **Configuration-dependent reproduction remains:** https://github.com/microsoft/vscode/issues/334211#issuecomment-6109477011 confirms the crash in VS Code 1.141.0's standalone archive. Removing appmenu-gtk-module from GTK settings restores startup; regenerating the entry restores the failure. This is a local workaround, not evidence that VS Code fixed the regression.
- **Verified upstream ownership:** https://github.com/electron/electron/issues/54782 is open and explicitly includes this report. Its headless bare-Electron bisect identifies 42.9.3 as working and 42.10.0 as crashing. The reported culprit sets gtk-modules to an empty string in GtkUi::Initialize(), unloading appmenu-gtk-module before a queued GIO name-watch callback executes.
- **Existing thread diagnosis and workaround:** https://github.com/microsoft/vscode/issues/334211#issuecomment-6068400302 connects the libgio backtrace to the Electron regression and Chromium's revert. https://github.com/microsoft/vscode/issues/334211#issuecomment-6054007907 reports successful startup using UBUNTU_MENUPROXY=0 code.
