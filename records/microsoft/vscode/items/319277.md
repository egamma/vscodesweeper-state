It also documents successful direct Messages requests using API-key and Entra authentication.
- **canonical owns protocol support:** The canonical discussion explicitly identifies that AzureBYOKModelProvider only supports OpenAI-compatible models: https://github.com/microsoft/vscode/issues/294841#issuecomment-3919567195. https://github.com/microsoft/vscode/issues/294841#issuecomment-4038527860 explains that relaxing the hostname check alone is insufficient because Claude requires anthropic/v1/messages. Its scope therefore includes the protocol adaptation requested here, not merely URL acceptance.
- **current source confirms remaining gap:** extensions/copilot/src/extension/byok/vscode-node/azureProvider.ts imports hasExplicitApiPath from customOAIProvider.ts, which recognizes /responses and /chat/completions but not /messages. resolveAzureUrl consequently rejects the reported services.ai.azure.com endpoint; azureSupportedEndpointsForUrl only adds Responses support. The API-key path constructs OpenAIEndpoint, while the Entra path constructs AzureOpenAIEndpoint, neither providing the custom endpoint's unconditional Messages routing.
- **existing capability is a workaround:** extensions/copilot/package.json registers vendor: "customendpoint" with Messages support, and customEndpointProvider.ts implements Messages request shaping and headers. A reporter supplied a working customendpoint configuration at https://github.com/microsoft/vscode/issues/294841#issuecomment-4660680689. This does not satisfy the explicit Azure-provider request or its integrated Entra authentication, so it is not grounds for an implemented or as-designed close.
