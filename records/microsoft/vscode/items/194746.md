# Issue #194746 — Show Notebook Execution Status in tabs 

[https://github.com/microsoft/vscode/issues/194746](https://github.com/microsoft/vscode/issues/194746)

## Summary

Keep open: current notebook execution progress is an editor-group indicator, not a status attached to each notebook tab. The request remains distinct, has maintainer interest, and no verified older canonical was found.

## Change summary

Show notebook execution status on its tab without requiring users to activate the notebook, optionally notifying on completion or error.

## Best solution

Provide an accessible, per-notebook execution indicator that remains identifiable on inactive tabs, using the notebook execution-state service and existing workbench tab conventions. Decide whether completed/error states persist and whether optional notifications belong in this scope before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/notebook/browser/contrib/execute/executionEditorProgress.ts`, `src/vs/workbench/contrib/notebook/common/notebookExecutionStateService.ts`, `src/vs/workbench/contrib/notebook/common/notebookEditorInput.ts`, `src/vs/workbench/browser/parts/editor/multiEditorTabsControl.ts`
- **Validation:** Open two notebooks and a text file; start a long-running cell in one notebook, then activate the text file. Verify that the executing notebook's inactive tab remains distinguishable from the idle notebook, updates when execution ends, and follows the agreed success/error lifetime. Repeat with concurrent execution in both notebooks and verify accessible status identification without confusing execution with dirty/saving state.
- **Behavior:**

  > Users with several open notebooks should be able to identify which notebook is executing without activating it. Status must belong to the individual notebook rather than the currently active editor group, and concurrent notebook executions must remain distinguishable. Completion and failure should follow an explicitly agreed status-lifetime policy. Completion/error notifications are a secondary request whose inclusion and default behavior remain undecided.
- **Trace:**

  > ExecutionEditorProgressController._update in src/vs/workbench/contrib/notebook/browser/contrib/execute/executionEditorProgress.ts already reads per-notebook execution state but presents it through NotebookEditorWidget.showProgress. That method uses editor-group progress; EditorProgressIndicator.registerListeners in src/vs/workbench/services/progress/browser/progressIndicator.ts hides it on active-editor changes, and NotebookEditorWidget restores it when focused. INotebookExecutionStateService in src/vs/workbench/contrib/notebook/common/notebookExecutionStateService.ts exposes execution changes, last-run failure changes, and per-notebook execution queries. NotebookEditorInput currently has no execution-status wiring, while MultiEditorTabsControl.redrawTabLabel supports resource decorations but does not itself aggregate notebook execution. Preserve dirty/saving semantics and existing cell/editor progress behavior; the gap is identifying execution on inactive notebook tabs. The related https://github.com/microsoft/vscode-jupyter/issues/11585 concerns output clearing and is not this feature's owner. No code was executed; the remaining uncertainty is the presentation and lifetime contract, not whether the inspected progress path supplies per-tab status.
- **Open decisions:**
  - Should tabs indicate only active execution, or retain success/error status after execution finishes, and when should retained status clear?
  - Should completion/error notifications be included in this feature, and if so, under what opt-in and focus conditions?
