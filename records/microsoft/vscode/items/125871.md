# Issue #125871 — Resolve file with same name as folder as index

[https://github.com/microsoft/vscode/issues/125871](https://github.com/microsoft/vscode/issues/125871)

## Summary

Custom editor labels now address much of the filename-display request, but search results still use actual basenames. Keep this accepted Backlog item open to settle the remaining cross-surface presentation scope; neither linked issue covers the full request.

## Change summary

Make generic entry-point filenames such as index.tsx and __init__.py contextually meaningful across file-navigation and result displays.

## Best solution

Complete a consistent, configurable presentation of generic entry-point filenames, building on existing custom editor labels rather than introducing a new module-resolution convention. Decide how search results and VS Code debugging displays should participate while preserving real file paths and identities.

- **Behavior:**

  > Projects with many generic entry-point filenames should expose enough filename context to distinguish their modules without renaming files or altering imports. Acceptance should cover the agreed additional surfaces, distinguish two different folders' entry points, and retain access to the original resource path. Unconfigured files must preserve their existing presentation and navigation.
- **Trace:**

  > CustomEditorLabelService in src/vs/workbench/services/editor/common/customEditorLabelService.ts expands glob-matched templates containing parent-folder and extension variables. Search-result file rendering in src/vs/workbench/contrib/search/browser/searchResultsView.ts instead calls ResourceLabelWidget.setFile(), whose implementation in src/vs/workbench/browser/labels.ts uses the resource basename. This establishes a search-display gap, not a module-resolution defect.
