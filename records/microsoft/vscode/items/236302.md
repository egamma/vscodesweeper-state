# Issue #236302 — Command Center should shrink when not enough space

[https://github.com/microsoft/vscode/issues/236302](https://github.com/microsoft/vscode/issues/236302)

## Summary

The title-bar allocation still reproduces this layout defect on current main: the center region retains disproportionate width while localized or otherwise long menu bars overflow. This issue should remain open as the canonical report; later reports were explicitly closed into it.

## Change summary

Allow the Command Center to yield horizontal space before title-bar menu entries are forced into overflow.

## Best solution

Define responsive title-bar priorities so the Command Center remains usable but shrinks before the main menu collapses at ordinary window widths, without compromising right-side controls or the menu's accessible overflow behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css`, `src/vs/workbench/browser/parts/titlebar/titlebarPart.ts`, `src/vs/workbench/test/browser/parts/titlebar/titlebarPart.test.ts`
- **Validation:** Launch Code OSS with the custom title bar at 1366x720 in English and Spanish, with and without the Agents title-bar control; verify all File-through-Help menu entries remain visible at the agreed normal-width threshold, the workspace title truncates accessibly, and further narrowing retains a reachable menu overflow control.
- **Behavior:**

  > At an ordinary usable window width, the complete main menu should remain visible even when localization produces longer labels. The Command Center may truncate its workspace text and reduce its width before menu entries overflow. At genuinely narrow widths, the existing accessible menu-overflow behavior must remain available, and right-side window and title-bar controls must remain usable.
- **Trace:**

  > The current layout in src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css assigns the `.titlebar-left`, `.titlebar-center`, and `.titlebar-right` regions approximately 20% / 60% / 20%; `.command-center-center` separately requests 38vw with a 600px maximum. The menubar in src/vs/base/browser/ui/menu/menubar.ts correctly derives overflow from its container's available width, so the constrained left-region allocation causes the observable collapse rather than the menu rendering path itself. Maintainers confirmed the desired direction in https://github.com/microsoft/vscode/issues/236302#issuecomment-2552336074, and later reports were consolidated here. Preserve keyboard access, overflow-menu semantics, right-side controls, and usable Command Center text; do not redesign the menubar overflow algorithm.
- **Open decisions:**
  - At what normal-window threshold must all main-menu entries take priority, and how far may the Command Center shrink before the menu begins overflowing?
  - Must the Command Center remain geometrically centered while yielding space asymmetrically to localized menu labels and right-side controls?
