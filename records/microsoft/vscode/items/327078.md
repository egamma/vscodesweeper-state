## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/324310 is open, predates this report, and explicitly requests BYOK custom endpoints working independently of Copilot entitlement. It identifies isClientBYOKAllowed as the provider-registration gate and includes subsequent confirmations from users without an active Copilot subscription.
- **Current entitlement gate:** extensions/copilot/src/extension/byok/common/byokProvider.ts:223-233 explicitly permits signed-out users but denies signed-in users without a Copilot token. BYOKContrib._applyPolicy in extensions/copilot/src/extension/byok/vscode-node/byokContribution.ts applies this gate to all bundled BYOK providers, including CustomEndpointBYOKModelProvider, and unregisters them when access is denied.
- **Configuration does not bypass registration:** LanguageModelsConfigurationService.configureLanguageModels in src/vs/workbench/contrib/chat/browser/languageModelsConfigurationService.ts can open the configuration file without checking Copilot entitlement. However, src/vs/workbench/contrib/chat/common/languageModels.ts checks for a registered provider in _resolveAllLanguageModels and warns when none exists; manually editing the file therefore does not restore models denied registration.
- **Classification and scope:** extensions/copilot/src/extension/byok/common/test/byokProvider.spec.ts:174-205 explicitly expects denial when signed in without a Copilot token and for managed users without the enabling policy flag. The requested independence changes an intentional gate, so this is classified as a feature request rather than a demonstrated deviation from current intended behavior; no decline close is proposed.
- **Distinct related work:** https://github.com/microsoft/vscode/issues/329667 references this report but specifically concerns optional authentication for Copilot Agent Host sessions with usable BYOK models. It does not replace the provider-registration and configuration work owned by https://github.com/microsoft/vscode/issues/324310.
- **Evidence to preserve:** https://github.com/microsoft/vscode/issues/327078 adds Linux reproduction context on 1.131.0-insider and reports that manually updating chatLanguageModels.json leaves models inaccessible through the UI, preventing the reporter from entering required secrets.
