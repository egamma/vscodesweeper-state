# Issue #176402 — Settings editor doesn't support settings with very long descriptions well like terminal.integrated.commandsToSkipShell

[https://github.com/microsoft/vscode/issues/176402](https://github.com/microsoft/vscode/issues/176402)

## Summary

Keep open: current source still truncates long setting descriptions without an in-editor reveal control, matching the gap identified in the discussion. The overlapping open report is newer, so it is not a valid duplicate target for this re-reviewed, team-authored issue.

## Change summary

Allow users to read complete long setting descriptions within the Settings editor instead of switching to default settings JSON.

## Best solution

Provide an accessible in-editor reveal interaction for truncated descriptions while keeping ordinary settings rows compact. Preserve the terminal setting's additive/subtractive customization semantics rather than expanding its actual default value.

- **Behavior:**

- **Trace:**

  > SettingsTreeSettingElement.initSettingDescription in src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts truncates description arrays after 20 entries and appends '[...]'. The common renderer in src/vs/workbench/contrib/preferences/browser/settingsTree.ts renders only that shortened element.description; the inspected path has no reveal control. Preserve the existing additive/subtractive terminal configuration contract and avoid unrelated setting-value changes. The maintainer suggested an in-editor reveal at https://github.com/microsoft/vscode/issues/176402#issuecomment-2533197508; https://github.com/microsoft/vscode/issues/272480 supplies a newer report of the same limitation. The remaining planning concerns are the user-visible lifetime and reversibility of the revealed state, not whether long descriptions need to be readable.
- **Open decisions:**
