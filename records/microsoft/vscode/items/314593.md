# Issue #314593 — Feature Request: Language Models – Model Picker – Native ChatGPT Sign-In for Codex

[https://github.com/microsoft/vscode/issues/314593](https://github.com/microsoft/vscode/issues/314593)

## Summary

Main now provides native ChatGPT sign-in, subscription model inventory, source labeling, and per-session Codex routing, but it does not fulfill the broader request across the Language Model API and general chat surfaces. Keep this open under discussion to decide whether ChatGPT-backed Codex models should become general-purpose language models or remain scoped to Codex Agent Host sessions.

## Change summary

Make ChatGPT subscription authentication and Codex models first-class, consistently selectable language-model sources across VS Code chat experiences and the Language Model API.

## Best solution

Provide a coherent ChatGPT account-backed model source whose eligible models are both selectable and usable in every supported surface, including a documented Language Model API contract, while retaining clear subscription-versus-API billing indicators and provider-qualified routing.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLanguageModelProvider.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts`, `src/vs/workbench/contrib/chat/common/languageModels.ts`, `src/vs/workbench/api/browser/mainThreadLanguageModels.ts`, `src/vs/workbench/services/agentHost/browser/codexAccountService.ts`, `src/vs/platform/agentHost/node/codex/codexAgent.ts`
- **Validation:** Extend the AgentHostLanguageModelProvider and Language Model API tests to verify the chosen contract: ChatGPT-backed Codex models appear only in the intended surfaces, a selected supported model can complete a request rather than throwing, provider-qualified selections route through the ChatGPT subscription, and Copilot/API-key routing remains unchanged.
- **Behavior:**

  > A user can sign in with ChatGPT and see clearly labeled subscription-backed Codex models in every product surface the project decides to support. Selecting one must result in usable model requests, not merely discoverable entries that fail when invoked, and subscription-backed versus separately billed API models must remain distinguishable. Model selection and capability filtering should behave consistently across the supported Chat, inline, Agent, and extension API contexts without changing existing Copilot-backed selections.
- **Trace:**

  > Commit https://github.com/microsoft/vscode/commit/a12a57df529dde769eeb660fb3340b51f9d32b99 and https://github.com/microsoft/vscode/pull/328461 implemented ChatGPT account actions, subscription usage, additive model inventories, and per-session Codex provider routing. AgentHostContribution in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts registers those models with ILanguageModelsService, while AgentHostLanguageModelProvider assigns targetChatSessionType to the Codex session type. The remaining boundary starts at AgentHostLanguageModelProvider.sendChatRequest, which always throws, so extension callers that discover these entries through selectChatModels cannot use them as ordinary language models. Preserve existing per-session provider-qualified Codex routing and Copilot behavior; the plan must first settle whether the public API and non-Codex chat surfaces should participate.
- **Open decisions:**
  - Are ChatGPT subscription-backed Codex models supported only inside Codex Agent Host sessions, or must normal Chat, inline chat, and extension Language Model API callers be able to invoke them?
  - If extensions may invoke subscription-backed models, what user-visible authorization and billing-source disclosure must occur before an extension can consume the user's ChatGPT subscription?
  - Should model selection remain independently persisted per Codex session, or should any selection be shared across the other supported chat surfaces?

## Evidence

- **partial implementation:** https://github.com/microsoft/vscode/pull/328461 merged as commit https://github.com/microsoft/vscode/commit/a12a57df529dde769eeb660fb3340b51f9d32b99 on 2026-08-04. It added ChatGPT identity, sign-in/sign-out, subscription usage, additive ChatGPT model inventories in the shared picker, and per-Codex-session provider routing.
- **current account surface:** src/vs/workbench/services/agentHost/browser/codexAccountService.ts exposes the native "Sign in to ChatGPT" action, while src/vs/sessions/contrib/accountMenu/browser/account.contribution.ts shows the ChatGPT account, manages ChatGPT models, displays subscription usage, and supports sign-out.
- **current model picker:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostChatContribution.ts registers ChatGPT subscription source presentation, and AgentHostLanguageModelProvider publishes the Codex inventory into ILanguageModelsService with a targetChatSessionType.
- **remaining API gap:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLanguageModelProvider.ts explicitly throws from sendChatRequest with "Agent-host models do not support direct chat requests". Extensions can discover models through selectChatModels, but cannot invoke these ChatGPT-backed Agent Host models through the normal Language Model API.
- **remaining surface boundary:** The current provider metadata scopes these models to the Codex Agent Host session type rather than making them generally usable by normal Chat, inline chat, and arbitrary extension Language Model API callers, so a meaningful part of the requested behavior remains undecided.
- **additional current-main history:** Later commits https://github.com/microsoft/vscode/commit/b44b4db8848c71c57cd2a9b0522821e9adbfd305 and https://github.com/microsoft/vscode/commit/308b341a2fa494b7157156df88a31344bdc4b8fe improved trusted ChatGPT source presentation and labels. These polish model identification but do not remove the direct-request limitation.
