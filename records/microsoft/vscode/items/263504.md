# Issue #263504 — Restored integrated terminal sessions not using workspace profile

[https://github.com/microsoft/vscode/issues/263504](https://github.com/microsoft/vscode/issues/263504)

## Summary

Confirmed bug still present on main: when a restored terminal's pty process can no longer be reattached (e.g. after a full restart), the fallback creates a new process using the resolved default profile but the workspace-specific profile args from the original shellLaunchConfig are lost in the reconnect path.

## Change summary

Restored integrated terminal sessions fall back to the global profile instead of the workspace-specific profile when the persistent pty process cannot be reattached after a VS Code restart.

## Best solution

When the attach to a persistent process fails in `terminalProcessManager.ts` (lines 289–297), the original profile information (path and args) should be preserved from the `attachPersistentProcess` data or the serialized state, rather than falling through to `resolveShellLaunchConfig` with an empty shellLaunchConfig. The `IPtyHostAttachTarget` interface should carry the original profile name or shell args so the correct workspace profile can be re-resolved on fallback.
