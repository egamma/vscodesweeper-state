# Issue #320882 — Use WebView2 instead of Electron V8 on the Windows platform.

[https://github.com/microsoft/vscode/issues/320882](https://github.com/microsoft/vscode/issues/320882)

## Summary

Propose closing against the established maintainer decision not to migrate VS Code to WebView2, which explicitly covers an optional Windows backend. This is not a duplicate close or a judgment based on inactivity.

## Change summary

Allow Windows users to select WebView2 instead of Electron, potentially making WebView2 the Windows default.

## Best solution

Retain the existing Electron desktop runtime under the documented maintainer decision. Evaluate concrete performance or rendering defects independently rather than treating an alternative runtime as a demonstrated fix.

## Evidence

- **Maintainer architecture decision:** https://github.com/microsoft/vscode/issues/118308#issuecomment-1362215823 explicitly names WebView2 among alternative frameworks being followed, states that VS Code is not considering runtime migration, and explains its desktop integration with Chromium and Node.js.
- **Performance claim addressed:** In the closed WebView2 performance request https://github.com/microsoft/vscode/issues/206711, the maintainer states that switching to WebView2 does not guarantee a performance gain because the underlying rendering architecture remains the same: https://github.com/microsoft/vscode/issues/206711#issuecomment-2024224679.
