# Issue #187784 — No way to copy full value from debugger console (repl)

[https://github.com/microsoft/vscode/issues/187784](https://github.com/microsoft/vscode/issues/187784)

## Summary

The merged partial improvement does not satisfy the full request: evaluated expressions can be copied through a clipboard-context re-evaluation, but values emitted by console output still lack a protocol path for retrieving an untruncated representation. The Backlog milestone permits judging the item on its merits, and a real gap remains.

## Change summary

Make Copy in the Debug Console place the complete underlying object or array value on the clipboard instead of its truncated displayed text.

## Best solution

Define a DAP capability for requesting a clipboard-formatted representation of a console variable or value, then have the core Debug Console Copy action use it while retaining the existing re-evaluation path for expression results.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/replViewer.ts`, `src/vs/workbench/contrib/debug/common/debugModel.ts`, `src/vs/workbench/contrib/debug/common/debugProtocol.d.ts`
- **Validation:** Add Debug Console tests covering both an evaluated expression and a console-emitted structured value whose displayed preview is truncated; Copy must return the complete clipboard representation when the debug adapter advertises support, while existing adapters retain current fallback behavior.
- **Behavior:**

  > Copying a structured value from the Debug Console should copy its complete value rather than the truncated preview shown in the tree. This should work both for user-evaluated expressions and values emitted independently by the debuggee, such as console.log output. Existing debug adapters that do not support the new capability must continue to behave compatibly, without breaking normal text selection and copy.
- **Trace:**

  > The issue discussion establishes that core owns the Debug Console copy path. https://github.com/microsoft/vscode/pull/187951 added a partial path for evaluation results by re-evaluating in the DAP `clipboard` context, but maintainer analysis says arbitrary console-emitted values have no expression that core can re-evaluate and therefore no way to request an untruncated clipboard representation. The remaining uncertainty begins at the DAP contract: the protocol needs to identify a console value and return a clipboard representation, with capability negotiation and a compatibility fallback. Keep the existing evaluated-expression behavior and JavaScript `copy(<expression>)` helper out of scope except as compatibility paths.
- **Open decisions:**
  - Should DAP expose clipboard formatting as a new request for a variable/value reference, or extend an existing evaluate/variables contract with a clipboard context?
  - When an adapter does not advertise support, should Copy retain the current displayed-text fallback or be unavailable for structured console values?
