# Issue #187784 — No way to copy full value from debugger console (repl)

[https://github.com/microsoft/vscode/issues/187784](https://github.com/microsoft/vscode/issues/187784)

## Summary

Keep open: the merged PR improves copying evaluated expressions, but current source still falls back to display text for logged objects. The remaining capability is explicitly acknowledged by a maintainer and by a TODO referencing this issue.

## Change summary

Allow Debug Console Copy to retrieve complete object and array values rather than their truncated display representations.

## Best solution

Provide adapter-backed clipboard representations for logged values as well as evaluated expressions, coordinating any necessary DAP support. Preserve selected-text copying and existing evaluation-based copying.

- **Behavior:**

  > Copying an object or array from Debug Console output should provide its complete value rather than only the truncated display text, including values printed by console.log. Copying explicitly selected text must continue to copy exactly that selection. Existing evaluated-expression copying must remain functional, and adapters without additional clipboard support must retain usable fallback behavior.
- **Trace:**

  > The debug.replCopy action in src/vs/workbench/contrib/debug/browser/repl.ts calls tryEvaluateAndCopy, which accepts only ReplEvaluationResult and evaluates originalExpression in the clipboard context. Logged ReplOutputElement and ReplVariableElement instances instead reach the toString fallback; their representations are defined in src/vs/workbench/contrib/debug/common/replModel.ts. This boundary is directly visible in current source, including a TODO referencing https://github.com/microsoft/vscode/issues/187784. The merged partial implementation at https://github.com/microsoft/vscode/pull/187951 and the maintainer discussion explicitly leave arbitrary logged values unresolved. The trace stops at the missing adapter-backed retrieval contract: a plan must establish the DAP and adapter integration before treating this as a core implementation task. Do not substitute generic recursive object serialization for an adapter-defined clipboard representation or change selected-text semantics.

## Evidence

- **Maintainer-confirmed remaining scope:** In https://github.com/microsoft/vscode/issues/187784, the July 14, 2023 maintainer comment distinguishes re-evaluating user-entered expressions from copying console.log output, for which a clipboard representation cannot currently be requested from the adapter.
- **Merged PR is a partial implementation:** https://github.com/microsoft/vscode/pull/187951 is merged as 5eb82ae6c400e8ff5eb3ab89809a4669c6b05bd5. Its body explicitly says a complete solution needs DAP methods; its diff limits clipboard-context evaluation to ReplEvaluationResult rather than arbitrary console output.
- **Existing capability and its boundary:** src/vs/workbench/contrib/debug/browser/repl.ts:1176-1222 registers debug.replCopy. Selected text is copied directly; otherwise tryEvaluateAndCopy only accepts ReplEvaluationResult and requires a focused frame, session, and supportsClipboardContext. Other elements fall back to element.toString(). The helper still contains the TODO to expand DAP for more types, referencing this issue.
- **Logged values retain display-text fallback:** In src/vs/workbench/contrib/debug/common/replModel.ts, ReplOutputElement.toString returns its output text, and ReplVariableElement.toString delegates to its expression's string representation. Neither is a ReplEvaluationResult, so the Copy action does not request an adapter-provided clipboard representation for these elements.
- **Workaround does not cover the whole request:** The maintainer's JavaScript copy(<expression>) workaround in https://github.com/microsoft/vscode/issues/187784 requires an expression the user can evaluate; it does not make Copy retrieve full values from arbitrary existing logged output.
