# Issue #211577 — Add selection to next find match (CTRD + D) does not check current selection when changing focus back from editor to find widget

[https://github.com/microsoft/vscode/issues/211577](https://github.com/microsoft/vscode/issues/211577)

## Summary

The defect remains source-reproducible on current main: when the find widget owns the search term, Ctrl+D appends the next match without validating or replacing the unrelated editor selection. The issue is already correctly classified and routed to the multicursor area.

## Change summary

When focus returns to the find widget, Add Selection to Next Find Match should discard an existing editor selection that does not match the active find query.

## Best solution

Align multicursor session initialization with the active find query so an unrelated pre-existing selection is not retained, while preserving matching selections and the normal editor-focused Ctrl+D flow. Cover the find-widget-focused transition with a focused multicursor unit test.
