# Issue #211577 — Add selection to next find match (CTRD + D) does not check current selection when changing focus back from editor to find widget

[https://github.com/microsoft/vscode/issues/211577](https://github.com/microsoft/vscode/issues/211577)

## Summary

The report provides a credible cross-platform reproduction on OSS dev and stable builds: after focus returns to the Find widget, Ctrl+D adds a find match without removing the editor's unrelated selection. The expected selection semantics need an editor-owner decision before implementation.

## Change summary

When Add Selection to Next Find Match is invoked from the Find input, discard an existing editor selection that does not match the active search criteria instead of retaining it in the multicursor set.

## Best solution

Define and test the transition from an unrelated editor selection to find-driven multicursor selections when `editor.action.addSelectionToNextFindMatch` is invoked with focus in the Find widget, then implement the agreed behavior in the editor find/multicursor action path without changing normal editor-focused Ctrl+D behavior.

- **Behavior:**

  > With an active Find query, selecting unrelated text in the editor and then invoking Add Selection to Next Find Match from the focused Find input currently retains that unrelated selection alongside newly added matches. The expected behavior must be chosen explicitly: if the command is find-driven in this focus state, the resulting selection set should contain only selections consistent with the active query. Acceptance should cover an unchanged query with a nonmatching selection, a matching selection, and a query edited after focus returns to the widget.
- **Trace:**

  > The reported sequence crosses the Find widget focus path and the editor command `editor.action.addSelectionToNextFindMatch`; changing the query updates the editor selection, while focus alone leaves stale selection state that the multicursor action then preserves. The likely boundary is the interaction between `FindController` in src/vs/editor/contrib/find/browser/findController.ts and the selection-match actions in src/vs/editor/contrib/multicursor/browser/multicursor.ts, with regression coverage in the find controller tests. The reporter linked the work context to https://github.com/microsoft/vscode/pull/211550. Normal editor-focused Ctrl+D behavior, multiple matching selections, and the existing query-change behavior must remain unchanged.
- **Open decisions:**
  - When the Find input owns focus, should Add Selection to Next Find Match always normalize the editor's current selections to the active query, or only discard selections that do not match it?
  - If several editor selections exist and only some match the active query, should nonmatching selections be removed individually or should the command restart from the current Find match?
