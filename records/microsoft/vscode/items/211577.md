# Issue #211577 — Add selection to next find match (CTRD + D) does not check current selection when changing focus back from editor to find widget

[https://github.com/microsoft/vscode/issues/211577](https://github.com/microsoft/vscode/issues/211577)

## Summary

Still reproduces on main. When focus moves from the editor to the find widget, the multicursor session ends. On the next Ctrl+D, a new session is created using the find widget's search string, but `addSelectionToNextFindMatch` blindly concatenates all existing editor selections (including non-matching ones) with the next match, instead of filtering out selections whose text doesn't match the search criteria.

## Change summary

Ctrl+D (Add Selection to Next Find Match) retains non-matching selections when invoked after clicking the find widget input, because the new session does not validate existing selections against the search string.

## Best solution

In `MultiCursorSession.addSelectionToNextFindMatch()` (or when beginning a new session from the find widget path in `MultiCursorSession.create`), filter out existing editor selections whose text does not match the session's `searchText` before concatenating the next match. The fix is localized to `src/vs/editor/contrib/multicursor/browser/multicursor.ts`.
