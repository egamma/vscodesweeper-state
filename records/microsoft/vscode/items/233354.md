# Issue #233354 — Support file icons similar to treeview item icon path in terminal icon path

[https://github.com/microsoft/vscode/issues/233354](https://github.com/microsoft/vscode/issues/233354)

## Summary

The terminal API still lacks TreeItem-style resource-based file icons; existing image URI and codicon support does not cover the request. Keep this team-authored Backlog item open for terminal API design; the related discussion explicitly separated terminal work from QuickPick work.

## Change summary

Allow extensions to give terminals resource-associated icons resolved through the active file icon theme.

## Best solution

Provide a terminal API contract for resource-based file icons consistent with TreeItem semantics, while preserving existing product-icon and custom-image behavior. Settle the public contract and terminal presentation scope before implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTerminalService.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadTerminalService.ts`, `src/vs/platform/terminal/common/terminal.ts`, `src/vs/workbench/contrib/terminal/browser/terminalIcon.ts`, `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`
- **Validation:** Using a development extension, create terminals associated with representative resource names and compare their icons with TreeItems using the same resources and ThemeIcon.File. Switch file icon themes, including a theme without file icons, and verify consistent results while existing codicon and light/dark custom-image terminals remain unchanged.
- **Behavior:**

  > Extensions should be able to associate a terminal with a resource and display the same file icon that the active file icon theme supplies for that resource in a TreeItem. This enables file-specific and Python environment-manager terminals without bundling theme-specific images. Acceptance should compare terminal and TreeItem icons for matching resources across theme changes and verify that existing product icons and custom image icons retain their behavior.
- **Trace:**

  > TerminalOptions and ExtensionTerminalOptions in src/vscode-dts/vscode.d.ts expose iconPath but no resource association equivalent to TreeItem.resourceUri. ExtHostTerminalService.asTerminalIcon forwards image URIs or ThemeIcon id/color; the terminal protocol and platform TerminalIcon types likewise carry no resource-based file-icon request. In terminalIcon.ts, getUriClasses handles image URIs and getIconId returns product-icon IDs; TerminalTabsList builds an inline icon label using those helpers and the terminal's internal resource. The related discussion at https://github.com/microsoft/vscode/issues/232439#issuecomment-2457660836 deliberately separates this terminal gap from QuickPick support. Preserve existing image, product-icon, color, and terminal identity semantics; uncertainty starts at the public resource-association contract and which terminal presentations must honor it.
- **Open decisions:**
  - Should terminals expose a separate resourceUri with TreeItem-style ThemeIcon.File semantics, or a different public resource-based icon contract?
  - Must the resource-derived icon appear consistently in terminal tabs, terminal editor tabs, and terminal selection surfaces, or is the initial API scoped to terminal tabs?
