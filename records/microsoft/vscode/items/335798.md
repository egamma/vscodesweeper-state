# Issue #335798 — session counter changes to a dot, and doesn't seem to come back

[https://github.com/microsoft/vscode/issues/335798](https://github.com/microsoft/vscode/issues/335798)

## Summary

Keep open: team testing confirmed that a transient attention dot can replace the Agents Window application-badge count, hiding the remaining sessions that need input. Current source explicitly intends counts to outrank the dot, but the existing tests do not cover the cross-component interaction that failed.

## Change summary

Keep the application-icon session count visible when another session finishes or requests window attention, until no configured sessions need attention.

## Best solution

Reproduce the application-badge and FocusMode.Notify interaction on the affected desktop platform, identify which lifecycle update clears the count, and add regression coverage ensuring an attention dot cannot displace a nonzero session count.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts`, `src/vs/sessions/contrib/sessions/test/electron-browser/sessionsApplicationBadge.test.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`
- **Validation:** Re-run the #335561 desktop scenario with multiple needs-input sessions while another session completes and triggers window attention; the badge must retain the numeric count. Add a regression covering simultaneous nonzero session count and FocusMode.Notify attention, and run the targeted SessionsApplicationBadge tests.
- **Behavior:**

  > When one or more configured sessions need attention, the application icon shows their numeric count. A different session finishing, notifying, or requesting focus must not replace that count with a generic dot. Focusing the Agents Window and navigating away must preserve or restore the count until the underlying sessions no longer match the configured badge categories.
- **Trace:**

  > The report was confirmed during https://github.com/microsoft/vscode/issues/335561 and concerns the application icon, not the in-window sidebar badge. SessionsApplicationBadge in src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts derives the session count and sends it through INativeHostService.setApplicationBadge. BaseWindow and DockBadgeManager in src/vs/platform/windows/electron-main/windowImpl.ts combine that count with the generic attention badge acquired by FocusMode.Notify, with a documented count-over-dot invariant. The existing SessionsApplicationBadge tests cover state changes and serialization but not this native attention interaction; uncertainty starts at the cross-process ordering or lifecycle that removes the count despite the manager's intended precedence. Preserve the generic attention-dot behavior when no numeric session count exists, and do not broaden the work into changing which badge categories are enabled by default.

## Evidence

- **confirmed test failure:** The VS Code team-authored report https://github.com/microsoft/vscode/issues/335798 records the failure while executing the application-badge test plan at https://github.com/microsoft/vscode/issues/335561: several needs-input sessions produced a count, then another session finishing changed it to a dot and the count did not reliably return.
- **intended arbitration:** src/vs/platform/windows/electron-main/windowImpl.ts:90-140 documents and implements DockBadgeManager with the invariant that a nonzero application count wins over the transient FocusMode.Notify attention dot.
- **current badge path:** src/vs/sessions/contrib/sessions/electron-browser/sessionsApplicationBadge.ts derives the configured count from observable session state and forwards every change through INativeHostService.setApplicationBadge; with the default options, remaining SessionStatus.NeedsInput sessions should preserve a nonzero count.
- **coverage gap:** src/vs/sessions/contrib/sessions/test/electron-browser/sessionsApplicationBadge.test.ts covers session-state count transitions and IPC serialization, but it does not exercise the interaction between SessionsApplicationBadge and DockBadgeManager.acquireBadge used by FocusMode.Notify.
