# Issue #206725 — Ctrl + Q keybind isn't keyboard-layout aware.

[https://github.com/microsoft/vscode/issues/206725](https://github.com/microsoft/vscode/issues/206725)

## Summary

Still a valid open bug — keyboard layout dispatch on Linux with non-Latin layouts (Hebrew in this case) incorrectly resolves the physical Q key to Ctrl+Q instead of respecting the layout-mapped character. No fix found on main; the quit keybinding is still registered as KeyCode.KeyQ without layout awareness on Linux.

## Change summary

Ctrl+physical-Q fires the quit action on Linux even when the active keyboard layout maps that key to a different character (e.g. '/' on Hebrew layout).

## Best solution

The keybinding dispatch on Linux needs to respect the active keyboard layout's character mapping when resolving shortcuts. This is part of a broader class of keyboard-layout bugs (see issues #283981, #207058, #210654). The fix likely lives in the Linux keyboard layout resolver in src/vs/workbench/services/keybinding/.
