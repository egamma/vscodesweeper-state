# Issue #339377 — `code --update-extensions` is a no-op in a remote SSH workspace

[https://github.com/microsoft/vscode/issues/339377](https://github.com/microsoft/vscode/issues/339377)

## Summary

Confirmed via source trace: `--update-extensions` run inside a reused Remote-SSH window (the `cliPipe` path in server.cli.ts) is silently dropped — the pipe payload and every downstream type/handler for extension management never carry an `update` field, so the request never reaches `ExtensionManagementCLI.updateExtensions`. Needs-info is unnecessary here; the defect is traced in code, not just reported.

## Change summary

`code --update-extensions` run from an integrated terminal in a Remote-SSH window does nothing and reports `null` instead of updating extensions.

## Best solution

Add an `update` flag through the whole remote-CLI pipe chain (server.cli.ts → ExtensionManagementPipeArgs → CLIServerBase.manageExtensions → ManageExtensionsArgs → `_remoteCLI.manageExtensions`) so it calls `RemoteExtensionManagementCLI.updateExtensions()` the same way list/install/uninstall are already wired.
