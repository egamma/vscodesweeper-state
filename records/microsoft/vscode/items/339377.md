# Issue #339377 — `code --update-extensions` is a no-op in a remote SSH workspace

[https://github.com/microsoft/vscode/issues/339377](https://github.com/microsoft/vscode/issues/339377)

## Summary

Traced the exact defect on main: `--update-extensions` is never wired through the Remote-SSH CLI pipe protocol, so it silently does nothing and prints `null` — this is a real, bounded bug worth keeping open and fixing.

## Change summary

`code --update-extensions`, run from a terminal in a Remote-SSH workspace, is a no-op: it prints `null`, exits 0, and installed extensions remain outdated.

## Best solution

Wire `update-extensions` through the CLI pipe path: add an `update`/`updateAll` flag to `ExtensionManagementPipeArgs`/`ManageExtensionsArgs`, forward it in `src/vs/server/node/server.cli.ts` (around line 322-328) and `extHostCLIServer.ts`'s `manageExtensions()`, and call `cliService.updateExtensions()` in the `_remoteCLI.manageExtensions` handler in `mainThreadCLICommands.ts`.

## Evidence

- **Receiving types have no update field:** `ExtensionManagementPipeArgs` (src/vs/workbench/api/node/extHostCLIServer.ts lines 39-45) and `ManageExtensionsArgs` (src/vs/workbench/api/browser/mainThreadCLICommands.ts lines 48-53) only declare `list`/`install`/`uninstall`/`force` — there is no `update` concept anywhere on this path.
