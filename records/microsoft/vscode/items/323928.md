# Issue #323928 — Command line parameter to make VS Code window maximized on startup regardless to window.newWindowDimensions parameter

[https://github.com/microsoft/vscode/issues/323928](https://github.com/microsoft/vscode/issues/323928)

## Summary

This is a valid gap, but prior maintainer decisions consistently place command-line control of native window state outside VS Code's scope and with the operating system's window manager.

## Change summary

Add a command-line flag that forces the launched VS Code window to start maximized, overriding saved state and window.newWindowDimensions.

## Best solution

Keep native window placement and one-shot state overrides with platform window-management tools; use window.newWindowDimensions when persistent maximization of subsequent windows is sufficient.

## Vision fit

- **Fit:** rejected
- **Reason:** A niche flag for overriding native window-manager state adds core CLI surface for behavior previously assigned to platform tooling.
- **Evidence:** Values and guardrails: keep the default editor lightweight and avoid configuration sprawl for specialized workflows.

- **Proposed comment:**

  > Thanks for the request. VS Code currently supports persistent behavior through `window.newWindowDimensions`, but a one-shot CLI override for native window state falls on the same side of the product boundary as https://github.com/microsoft/vscode/issues/83170 and https://github.com/microsoft/vscode/issues/22841. Maintainers previously assigned command-line window sizing and fullscreen control to platform window-management tools, so I propose keeping that boundary here.

## Evidence

- **maintainer precedent:** In https://github.com/microsoft/vscode/issues/83170, a maintainer explicitly classified command-line control of window size and position as window-manager functionality outside the application's scope.
- **equivalent prior request:** https://github.com/microsoft/vscode/issues/22841 requested a CLI flag for launching fullscreen and was closed with *out-of-scope.
- **current capability:** src/vs/platform/environment/node/argv.ts registers no global maximize/fullscreen option; its `maximize` option belongs only to the `chat` subcommand and maximizes the chat view.
- **setting limitation:** src/vs/workbench/electron-browser/desktop.contribution.ts documents that window.newWindowDimensions does not affect the first window, while src/vs/platform/windows/electron-main/windowsStateHandler.ts restores the first window's saved state.
