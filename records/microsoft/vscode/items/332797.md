# Issue #332797 — Custom editor (e.g. Markdown preview) missing bottom border

[https://github.com/microsoft/vscode/issues/332797](https://github.com/microsoft/vscode/issues/332797)

## Summary

Real, already-confirmed layout bug: the border around custom-editor containers (drawn by the experimental Modern UI editor-frame CSS, and mirrored by the Agents Window's own card styling) is missing on the bottom edge wherever a webview-hosted custom editor (Markdown preview, Agents Window) is shown. Two maintainers (lramos15, hediet) independently reproduced it in a second surface, so this isn't a one-off report.

## Change summary

The bottom border of a custom editor's frame (e.g. Markdown preview) is not rendered, while the top/left/right borders are, in both the Markdown editor and the Agents Window.

## Best solution

Track down why the overlay webview's positioning/clip region (src/vs/base/browser/overlayLayoutElement.ts, used via src/vs/workbench/contrib/webviewPanel/browser/webviewEditor.ts's `_clippingContainer`/`setAnchorElement`) ends up painting over the bottom edge of the anchor container's border-box specifically, and adjust the anchor/clip geometry (or inset the editor-frame border in editorBorder.css) so the webview no longer overlaps the drawn frame; this is a shared custom-editor/webview-overlay issue, not markdown-specific.

- **editor frame border:** src/vs/workbench/contrib/modernUI/browser/media/editorBorder.css draws a full 1px border-box border around `.part.editor` (behind `workbench.experimental.modernUI`); comment explicitly says it 'mirrors the card-like editor treatment used in the Agents window (src/vs/sessions/browser/media/style.css)', tying both surfaces to the same visual frame.
- **overlay webview positioning:** Webviews are not DOM children of the editor; src/vs/workbench/contrib/webviewPanel/browser/webviewEditor.ts sets `_clippingContainer` to the EDITOR_PART container and calls `webview.setAnchorElement(..., clippingContainer)`, which in src/vs/base/browser/overlayLayoutElement.ts anchors the overlay root's top/left/width/height to the clipping container's box via CSS anchor positioning (`anchor()`/`anchor-size()`) and only clips with `clip-path: content-box` on the overlay root itself — plausible mechanism for the overlay bleeding over the anchor's own border on one edge, though the exact top/left/right-vs-bottom asymmetry needs live layout inspection to pin down precisely.
