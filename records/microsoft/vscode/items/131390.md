# Issue #131390 — [FR] Option to open the `settings.json` to the side when opening the settings UI editor

[https://github.com/microsoft/vscode/issues/131390](https://github.com/microsoft/vscode/issues/131390)

## Summary

Keep this accepted feature request open: current settings options do not provide an automatically paired UI and JSON editor with synchronized scope and lifetime. It has 39 upvotes, and the older split-JSON discussion does not cover the same requested behavior.

## Change summary

Offer an opt-in settings UI and JSON pairing with search focus preserved, synchronized settings targets, editor reuse, independent navigation, optional TOC hiding, and coordinated closing.

## Best solution

Design an opt-in companion JSON workflow in the preferences area that satisfies the stated pairing requirements while preserving ordinary independent editors and existing JSON/default-settings modes. Plan the editor-group and lifecycle integration before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/services/preferences/browser/preferencesService.ts`, `src/vs/workbench/contrib/preferences/browser/settingsEditor2.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/services/preferences/test/browser/preferencesService.test.ts`, `src/vs/workbench/contrib/preferences/test/browser/settingsEditor2.test.ts`
- **Validation:** Plan targeted PreferencesService and SettingsEditor2 coverage, plus a workbench acceptance scenario: enable pairing, invoke workbench.action.openSettings repeatedly, verify one companion JSON editor on the right and focus in UI search, switch User to Workspace and verify the companion resource changes, navigate between the two editors, hide the TOC without searching, and close either editor to verify coordinated closing. Existing unpaired and split-JSON modes must remain unchanged.
- **Behavior:**

  > An opt-in workflow opens settings.json to the right of the settings UI while leaving focus in the UI search field. Changing the UI settings target updates the companion JSON resource, and repeated Open Settings invocations reuse the pair rather than accumulating JSON editors. The two editors remain independently navigable, either can close the pair, and the TOC can stay hidden without an active search. Acceptance must cover these behaviors and preserve existing behavior when the option is disabled.
- **Trace:**

  > PreferencesService.openSettings2 currently opens only the cached UI input and requests search focus; doOpenSettingsJson and createSplitJsonEditorInput implement separate JSON-only modes. SettingsEditor2.openSettingsFile resolves the selected User, Remote, Workspace, or Folder target, but onDidSettingsTargetChange only refreshes the UI model. TOC hiding in SettingsEditor2.layout is search-dependent. PreferencesService.getEditorGroupFromOptions also handles side groups, explicit source groups, and modal editors, with existing routing tests in preferencesService.test.ts. The requested behavior is clear, but this review has not established the shared editor lifecycle integration needed to pair closing and replacement safely; planning should finish that trace without changing ordinary editor close/save behavior or existing JSON modes. The motivating maintainer suggestion is https://github.com/microsoft/vscode/issues/125952#issuecomment-881119108.
