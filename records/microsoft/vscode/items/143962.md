# Issue #143962 — Replace `resourceUriProvider` web api with a descriptive/template variant

[https://github.com/microsoft/vscode/issues/143962](https://github.com/microsoft/vscode/issues/143962)

## Summary

The requested worker-usable resource mapping remains absent: current source retains the callback API and explicitly rejects workers created from remote extension URIs. Keep this accepted, team-authored request open; the related worker-support issue is newer and cannot serve as a duplicate target for this re-reviewed item.

## Change summary

Provide a descriptive or template-based resource URI mapping that child web workers can use without invoking a main-thread callback.

## Best solution

Define a transferable resource-mapping contract for web embedders and carry it through extension-host initialization and child-worker resource loading. Coordinate the observable worker support with https://github.com/microsoft/vscode/issues/144235 while preserving existing embedder behavior through an agreed compatibility policy.

- **Behavior:**

  > A web extension served from a remote server can create a child web worker and load its extension resources without requiring the child to invoke a main-thread-only resource callback. Resource URLs must follow the embedder's configured mapping rather than assuming a particular server endpoint. Acceptance should cover worker startup and subsequent resource loads, alongside existing HTTPS-served extensions. The compatibility behavior for embedders using the current callback API must be agreed before implementation.
- **Trace:**

  > WorkbenchOptions.resourceUriProvider and IResourceUriProvider in src/vs/workbench/browser/web.api.ts expose a synchronous function. web.main.ts passes the selected callback into RemoteAuthorityResolverService, which installs it through RemoteAuthorities.setDelegate. ExtHostExtensionService._loadCommonJSModule in src/vs/workbench/api/worker/extHostExtensionService.ts obtains browser URIs through main-thread RPC. The Worker wrapper in src/vs/workbench/api/worker/extensionHostWorker.ts explicitly rejects vscode-remote: URLs and identifies templating as the missing mechanism; its stringified bootstrap cannot capture surrounding functions. The unresolved boundary is the public mapping contract and migration semantics; existing callback embedders, connection-token resolution ordering, and local/HTTPS resource behavior must remain accounted for.
- **Open decisions:**
