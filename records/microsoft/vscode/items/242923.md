# Issue #242923 — Searching from the beginning instead of the selected position

[https://github.com/microsoft/vscode/issues/242923](https://github.com/microsoft/vscode/issues/242923)

## Summary

Still reproduces on main: when opening the notebook find widget with a selection that seeds the search string, `refreshCurrentMatch` is skipped because the `!searchStringUpdate` guard on line 309 of notebookFindWidget.ts is false, so the match position falls back to the first match at/after the focused cell rather than the selected occurrence.

## Change summary

Opening notebook find with selected text jumps to the first match in the notebook instead of the match at the current selection.

## Best solution

In `notebookFindWidget.ts` `show()`, call `refreshCurrentMatch` (or equivalent positioning logic) even when the search string is being updated from a selection seed — the `!searchStringUpdate` guard on line 309 incorrectly excludes the initial-seed case. The `_research()` path also only considers cell-level granularity (`getFocus().start`), not the within-cell cursor range, which should be addressed for the initial match positioning.
