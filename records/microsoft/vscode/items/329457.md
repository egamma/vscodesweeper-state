## Change summary

In a multi-root .code-workspace with several independent git repos, the SCM activity-bar count badge never appears even though changes exist and are visible in the SCM panel.

## Best solution

Worth a maintainer trace through src/vs/workbench/contrib/scm/browser/scmViewService.ts's previous-state restoration logic (onDidAddRepository / didSelectRepository, around lines 350-425) against SCMActiveRepositoryController._countBadgeRepositories in activity.ts — the badge is computed only from scmViewService.visibleRepositories, and multi-root workspaces add several repositories asynchronously at startup, which is exactly the path that selection-restoration logic is most likely to mis-handle (ending up with an empty or stale visible set). Confirming reproduction with actual logs/repro workspace would make this actionable.
