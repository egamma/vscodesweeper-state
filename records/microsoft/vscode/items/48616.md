# Issue #48616 — Add support for bulk actions in extensions list view

[https://github.com/microsoft/vscode/issues/48616](https://github.com/microsoft/vscode/issues/48616)

## Summary

The requested bulk extension actions remain absent on current main. A maintainer deliberately reopened and accepted this into the Backlog, most recently marking it team-low-hanging, so it should remain open for implementation planning.

## Change summary

Allow users to enable, disable, or uninstall multiple selected extensions in one operation.

## Best solution

Support multi-selection in the Extensions list and make its enable, disable, and uninstall actions operate on the selected extensions while respecting each extension's eligibility, workspace/global scope, profile, and extension-management server.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/extensionsViewer.ts`, `src/vs/workbench/contrib/extensions/browser/extensionsActions.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsViews.test.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionsActions.test.ts`
- **Validation:** Add extension-list/action tests selecting multiple installed extensions and verify that bulk enable, disable, and uninstall affect the intended eligible set while single-selection behavior remains unchanged; run the targeted extensions view and action unit tests.
- **Behavior:**

  > Users can select multiple installed extensions and invoke enable, disable, or uninstall once for the selection. Every eligible selected extension receives the operation, while ineligible extensions are handled predictably and communicated rather than silently producing a partial result. Single-extension actions and workspace/global enablement behavior remain unchanged. Acceptance covers homogeneous and mixed selections, cancellation of uninstall confirmation, and extensions installed on different management servers.
- **Trace:**

  > ExtensionsList in src/vs/workbench/contrib/extensions/browser/extensionsViewer.ts explicitly disables multiple selection and builds its context menu from only the event element. The underlying actions in src/vs/workbench/contrib/extensions/browser/extensionsActions.ts hold one `extension`, although IExtensionsWorkbenchService already accepts extension collections for enablement and handles uninstall constraints in the service layer. Existing global Enable All/Disable All commands in src/vs/workbench/contrib/extensions/browser/extensions.contribution.ts are not substitutes because they target every eligible installed extension rather than the user's selection. Preserve single-item context menus, extension dependency checks, workspace/global scope, profile behavior, and local/remote server boundaries. The earlier same-symptom issue https://github.com/microsoft/vscode/issues/44508 is closed; https://github.com/microsoft/vscode/issues/48616 is the active accepted item.
- **Open decisions:**
  - For a mixed selection containing ineligible extensions, should a bulk action operate on the eligible subset with a summary, or remain unavailable until every selected extension supports it?
  - Should bulk uninstall use one confirmation describing the full batch, or retain per-extension confirmations and dependency prompts?
  - May one bulk operation span local and remote extension-management servers, or should selection and actions be constrained to one server at a time?

## Evidence

- **current source:** src/vs/workbench/contrib/extensions/browser/extensionsViewer.ts constructs ExtensionsList with `multipleSelectionSupport: false`; its `onContextMenu` resolves actions for only `e.element`, so current main cannot apply contextual actions to a selection.
- **single-item actions:** src/vs/workbench/contrib/extensions/browser/extensionsActions.ts implements UninstallAction, EnableGloballyAction, and DisableGloballyAction against one `this.extension`; no selected-extension action path exists.
- **maintainer triage:** The timeline at https://github.com/microsoft/vscode/issues/48616 shows sandy081 reopened the issue into the Backlog on 2024-01-05 and added `team-low-hanging` on 2025-12-11, explicitly preserving it as accepted work.
- **previous canonical:** https://github.com/microsoft/vscode/issues/44508 is older and describes the same limitation, but it has been closed since 2018 and therefore cannot serve as a duplicate canonical; this issue was reopened after that closure because the requested bulk behavior remained missing.
