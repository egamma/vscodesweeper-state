# Issue #317003 — [Bug] Incomplete Sanitization in htmlContent.ts (Core): Unescaped '<' Passes Raw HTML to MarkdownString

[https://github.com/microsoft/vscode/issues/317003](https://github.com/microsoft/vscode/issues/317003)

## Summary

The behavior is intentional and explicitly acknowledged via CodeQL suppression markers. The project's security model relies on rendering-time sanitization (DOM sanitizer in markdownRenderer.ts), which the reporter themselves acknowledges — this is as-designed defense-in-depth.

## Change summary

The `appendText()` method in htmlContent.ts does not escape `<`, allowing raw HTML open tags in the intermediate MarkdownString value before rendering-time sanitization.

## Best solution

Close as designed. The security boundary is at the renderer (`markdownRenderer.ts` uses `domSanitize.safeSetInnerHtml` with a sanitizer config), not at MarkdownString construction. The team explicitly suppressed this CodeQL finding with `[SM02383] The Markdown is fully sanitized after being rendered`. No code change needed.

  > Thanks for the thorough report and for noting the existing CodeQL suppression. This is intentionally as-designed: `appendText()` builds an intermediate Markdown string, and the security boundary is at the rendering layer — `src/vs/base/browser/markdownRenderer.ts` applies DOM sanitization (via `domSanitize.safeSetInnerHtml` with a sanitizer config) before any content reaches the DOM. The `<` character is not escaped at construction time because the renderer's sanitizer handles it, and escaping it earlier would break legitimate Markdown content flows. The CodeQL `[SM02383]` suppression documents this architectural choice.
