Keep open: current registry discovery still lacks the requested OAuth flow, and the registry specification now explicitly supports authenticated subregistries. The existing area labels are appropriate; related authentication issues do not own this discovery capability.

## Change summary

Provide standards-aligned OAuth authentication for registry discovery and metadata retrieval, preserving anonymous access to public registries and existing registry-only enforcement. Plan the user-facing sign-in behavior and cross-process authentication integration with the authentication and MCP management owners.

## Plan brief

- **Likely files:** `src/vs/platform/mcp/common/mcpGalleryService.ts`, `src/vs/platform/mcp/common/mcpGalleryManifestService.ts`, `src/vs/workbench/services/mcp/browser/mcpGalleryManifestService.ts`, `src/vs/platform/mcp/test/common/mcpGalleryService.test.ts`
- **Validation:** Extend src/vs/platform/mcp/test/common/mcpGalleryService.test.ts with a simulated registry that returns a 401 OAuth challenge and succeeds only after authentication; verify discovery, pagination, and metadata retrieval, plus cancellation and unchanged public-registry access. Finish with a manual private-registry browse/sign-in check, including token expiry and registry-only enforcement.
- **Behavior:**

  > Users can discover and inspect servers from an OAuth-protected MCP registry without deploying a proxy or manually maintaining bearer tokens. A registry's authentication challenge leads to standards-aligned authentication and a successful authenticated retry after the user authorizes access. Subsequent pages and metadata requests retain access, including renewal when tokens expire. Public registries continue to work anonymously, cancellation remains usable, and authentication failure does not bypass registry-only restrictions.
- **Trace:**

  > McpGalleryService.queryRawGalleryMcpServers in src/vs/platform/mcp/common/mcpGalleryService.ts sends a plain GET and treats 401 as an unsuccessful query; getMcpServer has the same missing authentication capability for metadata retrieval. McpGalleryManifestService.checkVersion in src/vs/platform/mcp/common/mcpGalleryManifestService.ts performs unauthenticated version probes, so the boundary includes registry initialization as well as browsing. WorkbenchMcpGalleryManifestService in src/vs/workbench/services/mcp/browser/mcpGalleryManifestService.ts selects the configured endpoint and forwards the manifest to a remote connection, but does not establish authentication. The existing gallery test suite provides request-service fakes, but authentication-provider integration and process ownership were not fully traced. Preserve public-registry behavior, endpoint validation, cancellation, and registry-only enforcement; do not conflate registry discovery with MCP server execution authentication. https://github.com/modelcontextprotocol/registry/pull/756 supplies the registry authorization guidance, while https://github.com/microsoft/vscode/issues/248775 is related provider-mapping work rather than a duplicate.
- **Open decisions:**
  - Should a protected-registry challenge during automatic discovery initiate interactive sign-in, or should sign-in require an explicit user action while background requests remain non-interactive?
