# Issue #77769 — Scrolling can be improved

[https://github.com/microsoft/vscode/issues/77769](https://github.com/microsoft/vscode/issues/77769)

## Summary

Precision scrollbar dragging remains missing: current dragging scales with document length, and existing scroll-sensitivity settings affect mouse-wheel input instead. Keep this accepted Backlog request open; a later related report includes maintainer interest but is closed and cannot serve as a duplicate target.

## Change summary

Allow modifier-assisted, slower scrollbar-thumb dragging for precise navigation in long files.

## Best solution

Provide a deliberate precision-drag interaction that allows small movements through long files while retaining ordinary dragging for coarse navigation. Agree on its sensitivity and activation behavior before implementation in the shared scrollbar surface.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts`, `src/vs/base/browser/ui/scrollbar/scrollbarState.ts`, `src/vs/base/test/browser/ui/scrollbar/scrollbarState.test.ts`
- **Validation:** Manually compare equal thumb-drag distances in short and very long editor documents, with and without the agreed precision modifier; precision mode must allow controlled small movements without abrupt jumps when the modifier changes. Preserve ordinary dragging, track clicks, mouse-wheel settings, and Windows orthogonal drag-reset behavior; use the ScrollbarState suite to verify any changed position calculations.
- **Behavior:**

  > Dragging the scrollbar thumb in a long file currently moves through too much content for small pointer movements. The requested precision interaction lets the user hold Ctrl while dragging to navigate substantially more slowly, without requiring the pointer to remain aligned with the thumb. Ordinary dragging must retain its existing coarse-navigation behavior. Acceptance should compare identical pointer movements across different document lengths and verify continuous positioning when precision mode is entered or exited.
- **Trace:**

  > AbstractScrollbar._sliderPointerDown in src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts snapshots the initial pointer position and ScrollbarState, then maps raw pointer displacement through ScrollbarState.getDesiredScrollPositionFromDelta. In src/vs/base/browser/ui/scrollbar/scrollbarState.ts, that mapping divides by a ratio that shrinks as the document grows; there is no precision-modifier branch. Existing editor sensitivity settings are consumed by the wheel-event path in scrollableElement.ts and do not change this interaction. The scrollbar implementation is shared beyond the editor, so the interaction's scope must be agreed rather than assumed. Preserve ordinary dragging, track-click navigation, wheel behavior, and Windows orthogonal drag reset. The later related report https://github.com/microsoft/vscode/issues/240890 contains maintainer support for improving precise mouse manipulation, but it is closed and supplies no landed implementation.
- **Open decisions:**
  - Should precision dragging use a reduced proportional sensitivity or a document-length-independent movement rate, and what observable rate should users expect?
  - Should the interaction apply only to editor scrollbars or consistently to all surfaces using the shared scrollbar?
  - Should Ctrl activation be determined at drag start or change dynamically while dragging, including the corresponding behavior on macOS?

## Evidence

- **Current drag behavior:** src/vs/base/browser/ui/scrollbar/abstractScrollbar.ts:240–265, AbstractScrollbar._sliderPointerDown, passes the unmodified pointer displacement to getDesiredScrollPositionFromDelta without checking Ctrl or another precision modifier. src/vs/base/browser/ui/scrollbar/scrollbarState.ts computes the slider ratio from viewport and document sizes and divides displacement by that ratio, explaining why small drags traverse more content in larger files.
- **Existing capabilities do not cover the request:** src/vs/editor/common/config/editorOptions.ts registers editor.mouseWheelScrollSensitivity and editor.fastScrollSensitivity. Their application in src/vs/base/browser/ui/scrollbar/scrollableElement.ts:475–508 scales mouse-wheel deltas, including Alt-assisted scrolling, not scrollbar-thumb dragging. editor.scrollbar.scrollByPage changes track-click behavior rather than drag precision.
- **Related report and maintainer interest:** https://github.com/microsoft/vscode/issues/240890 reports the same long-file scrollbar imprecision.
