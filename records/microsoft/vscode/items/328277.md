# Issue #328277 — Changing the reasoning effort causes overwrite of provider entry in chatLanguageModels.json

[https://github.com/microsoft/vscode/issues/328277](https://github.com/microsoft/vscode/issues/328277)

## Summary

Keep open: current source still replaces every provider entry sharing the selected entry's vendor and name, which can erase a different model's configuration when reasoning effort is changed. The related older settings-collision report does not describe this same overwrite symptom and is not a verified canonical.

## Change summary

Changing reasoning effort for one Azure model replaces another provider entry with the same vendor and name, losing its distinct model definition.

## Best solution

Make model-setting persistence preserve every unrelated provider entry, including manually configured entries with identical vendor/name pairs. Pin the reported configuration-loss case with a regression exercising the real configuration persistence service.
