# Issue #334409 — Remote SSH: Copilot incorrectly requests external-file permission for workspace paths involving symlinks

[https://github.com/microsoft/vscode/issues/334409](https://github.com/microsoft/vscode/issues/334409)

## Summary

Traced a genuine bug in the Copilot Chat extension's external-file permission check: when the workspace root itself is reached through a symlink or bind mount (typical for Remote SSH containers/junctions), the containment check resolves the requested file's full real path but compares it against the *unresolved* workspace-folder URI, so it never matches and every in-workspace file is wrongly flagged as external.

## Change summary

Copilot's read_file tool prompts for external-file permission on files that are actually inside the workspace, whenever the workspace root is opened through a symlink or bind-mounted path (common with Remote SSH).

## Best solution

In extensions/copilot/src/extension/tools/node/toolUtils.ts, getWorkspaceFileExternalConfirmation should account for the workspace folder root itself being reached via a symlink — e.g. resolve the workspace folder's own real path once and compare the resolved file path against that, instead of comparing against the raw (unresolved) workspace folder URI from WorkingDirectory/IWorkspaceService.
