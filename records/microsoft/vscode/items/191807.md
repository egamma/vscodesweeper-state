# Issue #191807 — Settings UI doesn't respect custom `title` for extension configuration option

[https://github.com/microsoft/vscode/issues/191807](https://github.com/microsoft/vscode/issues/191807)

## Summary

Valid feature request with partial infrastructure already in place — ISetting.title and initLabels() exist but parseSetting() never wires through the property's title. Team members acknowledged and suggested design refinements; community demand is consistent (8 upvotes, multiple +1 comments from extension authors). On Deck milestone is appropriate.

## Change summary

Extension-contributed configuration properties with a custom `title` field in package.json should display that title in the Settings UI instead of the auto-generated label derived from the setting key.

## Best solution

Wire `prop.title` through `parseSetting()` in `src/vs/workbench/services/preferences/common/preferencesModels.ts` so it populates `ISetting.title`, which `initLabels()` in settingsTreeModels.ts already checks. Consider the design question raised by rzhao271 about naming clarity (e.g. `customSettingTitle`) and whether a custom category label should also be supported at the same time.
