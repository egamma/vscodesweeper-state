# Issue #331018 — AI edit diff becomes unreadable for single-line long content (Markdown/Word Wrap)

[https://github.com/microsoft/vscode/issues/331018](https://github.com/microsoft/vscode/issues/331018)

## Summary

Traced a concrete, distinct root cause on main: the chat/AI-edit inline review renders the original (deleted) line content with an empty line-break array, so long lines never wrap regardless of the editor's word-wrap setting — unlike the standalone diff editor, which computes real line breaks for the same rendering path.

## Change summary

When reviewing an AI/chat edit inline in the editor, a long single line of original content is rendered unwrapped and unreadable, even though the file has word wrap on.

## Best solution

In chatEditingCodeEditorIntegration.ts, compute real line-break data for the deleted-code view zone (mirroring diffEditorViewZones.ts's `deletedCodeLineBreaksComputer` pattern) instead of passing an empty array to `LineSource`, so the inline chat-edit diff wraps the same way the standalone diff editor does.

## Evidence

- **root cause:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts:367 constructs `new LineSource(originalRange.mapToLineArray(...), [], ...)` — the second argument (lineBreakData) is hardcoded to an empty array, so `renderLines` (src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/renderLines.js) never wraps the deleted-content view zone for AI edits.
- **contrast with working diff editor:** src/vs/editor/browser/widget/diffEditor/components/diffEditorViewZones/diffEditorViewZones.ts:167-193 computes `deletedCodeLineBreaksComputer` via `this._editors.modified._getViewModel()?.createLineBreaksComputer(context)` and calls `.finalize()` to get real `lineBreakData`, which is why the same visual mechanism wraps correctly in the standalone diff editor's inline/unified view.
- **current commit:** File last touched at 7fee81510403f95dff38c5f4a528dbc4bd4d4298; no fix for this gap present on main.
- **related but distinct:** https://github.com/microsoft/vscode/issues/199341 (open) tracks a different diff-editor bug — word-wrap override not reapplied to one side after a resize toggle in the side-by-side diff editor — which is a different code path (wordWrapOverride1/2 in diffEditorEditors.ts) than the chat-edit view-zone rendering gap found here, so this is not proposed as a duplicate.
