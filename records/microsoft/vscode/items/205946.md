# Issue #205946 — Setting editor.find.seedSearchStringFromSelection to Selection still seed the Find Widget from not selected words

[https://github.com/microsoft/vscode/issues/205946](https://github.com/microsoft/vscode/issues/205946)

## Summary

The defect remains in current source, but the verified open issue https://github.com/microsoft/vscode/issues/300085 covers the same command, settings, and unexpected search-term replacement. Consolidate there, where an open implementation candidate already addresses both selection and never modes.

## Change summary

Find Next Selection replaces the previous search term with the unselected word at the cursor despite selection-only or disabled search seeding.

Consolidate the reports under https://github.com/microsoft/vscode/issues/300085 and review https://github.com/microsoft/vscode/pull/300086, preserving this report's Linux reproduction and coverage of the never setting. The canonical issue should remain open until the fix lands.

- **Defect confirmed in current source:** src/vs/editor/contrib/find/browser/findController.ts:935-945: SelectionMatchFindAction.run calls getSelectionSearchString(editor, 'single', false) unconditionally and overwrites the controller's search string. At lines 43-67, the helper returns the word at an empty selection when that final argument is false. This directly explains steps 4-5 regardless of the configured selection or never value.
- **Verified canonical:** https://github.com/microsoft/vscode/issues/300085 is currently OPEN and explicitly reports editor.action.nextSelectionMatchFindAction and editor.action.previousSelectionMatchFindAction ignoring editor.find.seedSearchStringFromSelection. Its selection-only reproduction replaces the previous search term with the word at the cursor, exactly the observable defect here. Although newer, it diagnoses the shared cause and owns an active fix candidate; this report introduces no separate required behavior.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/300086 is OPEN and unmerged, uses Fixes #300085, and addresses the same SelectionMatchFindAction.run path. Its documented behavior covers both selection-only seeding and never seeding; it is not evidence that the defect is already fixed.
- **Reporter evidence to preserve:** https://github.com/microsoft/vscode/issues/205946 supplies explicit reproduction steps on Linux snap, confirms the issue with extensions disabled, and reports persistence after upgrading from 1.86.1 to 1.86.2.
