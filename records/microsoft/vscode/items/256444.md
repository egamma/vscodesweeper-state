# Issue #256444 — Drag&Drop within extension from one webview to the other not working with vscode > 1.90.0

[https://github.com/microsoft/vscode/issues/256444](https://github.com/microsoft/vscode/issues/256444)

## Summary

Confirmed bug: the shift-to-drop overlay appears unnecessarily when dragging from a tree view to a webview within the same extension, because the drag-into-editor detection uses only `e.shiftKey` without checking whether the drag payload is an editor-openable resource. A maintainer acknowledged the issue and an open community PR (#321275) proposes a fix.

## Change summary

Dragging items from an extension tree view to a webview within the same extension incorrectly triggers the 'hold Shift to drop into editor' overlay, degrading the DnD experience.

## Best solution

Review and land (or iterate on) the open PR https://github.com/microsoft/vscode/pull/321275, which updates the `isDragIntoEditorEvent` logic in `editorDropTarget.ts` and the shift-key gating in `webviewWindowDragMonitor.ts` to only require Shift when the drag payload contains internal URI data that could open as an editor.
