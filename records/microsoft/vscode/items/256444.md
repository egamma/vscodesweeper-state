## Summary

Keep open: the discussion confirms that tree-to-webview dropping remains broken after correcting the sample extension, and current source still gates webview drag handling on Shift. An explicitly linked fix PR remains open and should be reviewed rather than starting a competing implementation.

## Change summary

Allow extension tree items that cannot be opened as editor resources to reach a webview drop target without requiring Shift.

- **Independent reproduction:** https://github.com/microsoft/vscode/issues/256444#issuecomment-3667676444 supplies a TreeDragAndDropController and reports that webview event handlers begin firing only after Shift is pressed. https://github.com/microsoft/vscode/issues/256444#issuecomment-4698931418 independently describes the same tree-palette workflow and provides a demonstration.
- **Current source path:** src/vs/workbench/contrib/webview/browser/webviewWindowDragMonitor.ts:41-54 calls windowDidDragStart for drag and dragover events without Shift, regardless of dragged MIME types. In src/vs/workbench/contrib/webview/browser/webviewElement.ts:785-793, that starts blocking iframe drag events; windowDidDragEnd removes the blocking. src/vs/workbench/browser/parts/editor/editorDropTarget.ts:39-40 also classifies dragging into an editor solely by shiftKey.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/321275 is OPEN, has no merge timestamp, and explicitly says Fixes #256444. Its diff changes both the editor drop-target predicate and webview drag monitor to distinguish resource-bearing drags. The author requests review of the MIME-based distinction, so this is an implementation candidate, not a landed fix.
- **Canonical search:** An open-issue search for webview drag Shift surfaced https://github.com/microsoft/vscode/issues/237958. Its full report concerns file drags opening editors and says holding Shift still does not deliver events, unlike this report's non-resource tree-item workflow where Shift enables delivery. It does not establish the same observable symptom required to close this re-reviewed item as a duplicate.
- **Intended behavior:** https://github.com/microsoft/vscode/issues/256444#issuecomment-3633945011 explains that the overlay selects between opening an editor and dropping into its contents; it is not a security prompt. The maintainer proposes avoiding the message when dragged data cannot be opened as an editor, so an as-designed decline would contradict the accepted direction.
