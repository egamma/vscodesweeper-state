# Issue #25401 — Drop cursor missing if drop location === current cursor location

## Summary

Keep open as an editor drag-and-drop polish request: the current source does not establish that drop feedback takes precedence over a coincident caret. This team-authored Backlog item has neither a verified same-symptom canonical nor an issue-referencing fix that would justify closure.

## Change summary

Prefer the drop-location indicator over the normal text caret when both occupy the same position.

## Best solution

Make valid drop targets clearly distinguishable when they coincide with the caret, while preserving intentional suppression over invalid targets inside the dragged selection. Confirm the original gesture against current editor rendering before choosing the scope of the change.
