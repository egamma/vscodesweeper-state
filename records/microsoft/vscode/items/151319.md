# Issue #151319 — [html] `html.autoCreateQuotes` is not instant

[https://github.com/microsoft/vscode/issues/151319](https://github.com/microsoft/vscode/issues/151319)

## Summary

The request remains valid: the HTML quote insertion delay is acknowledged as intentional, but the discussion identifies disruptive fast-typing behavior that the existing setting does not address. As a re-reviewed feature request in the Backlog with no verified older canonical issue, it should remain open for an HTML-language-feature design decision.

## Change summary

Make `html.autoCreateQuotes` insert quotes without losing or disrupting them when an attribute value is typed within the current 100 ms completion delay.

## Best solution

Adjust the HTML auto-quote completion behavior so fast typing produces a correctly quoted attribute without cursor displacement or duplicated delimiters, while preserving cancellation when the user intentionally continues with syntax that should not be quoted.

## Plan brief

- **Likely files:** `extensions/html-language-features/client/src/htmlClient.ts`, `extensions/html-language-features/server/src/htmlServer.ts`
- **Validation:** Add an HTML language-feature integration test that types an attribute assignment and value without pausing and verifies the final text and cursor position, including the existing cancellation case that the 100 ms delay protects.
- **Behavior:**

  > With `html.autoCreateQuotes` enabled, rapidly typing an HTML attribute assignment such as `id=test` should not leave the document unquoted or insert a delayed closing quote that displaces the cursor. The accepted behavior must be deterministic across typing speeds and preserve valid editing flows where automatic quotes should be cancelled. Acceptance should cover final document text and cursor placement for both rapid attribute-value entry and the cancellation scenario.
- **Trace:**

  > The issue discussion establishes that HTML auto-quotes use a 100 ms wait so a quick completion request can be cancelled. The central unresolved behavior is the race between continued typing and delayed insertion: users report both missing quotes and a late ending quote that moves the cursor. The relevant boundary is the built-in HTML language feature and its completion/edit application path; Emmet, generic editor auto-closing pairs, and unrelated language modes must not change. https://github.com/microsoft/vscode/issues/140698 is related in the thread but is not verified here as a qualifying canonical duplicate.
- **Open decisions:**
  - When the user starts typing the attribute value during the 100 ms window, should VS Code immediately wrap the typed value in quotes, or should it cancel auto-quote insertion without later cursor movement?
  - Which continued-input patterns should intentionally cancel automatic quotes rather than be incorporated into a quoted attribute value?
