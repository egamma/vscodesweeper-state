# Issue #330875 — [Error] unhandlederror-TreeError [AgentSessionsView] Tree element not found: [object Object]

[https://github.com/microsoft/vscode/issues/330875](https://github.com/microsoft/vscode/issues/330875)

## Summary

Real, source-traceable race: `updateCollapseContextKeys` in listService.ts calls `tree.getNode(focus)` synchronously inside the `onDidChangeFocus` handler, and when focus is set (e.g. via `focusFirst()` after an AgentSessionsView data refresh) before the compressed tree model has registered the new/removed node, `getCompressedNode` throws `TreeError: Tree element not found`, which surfaces as an unhandled error to 157 stable users.

## Change summary

AgentSessionsView throws an unhandled `TreeError [AgentSessionsView] Tree element not found` when the tree's focus changes during a data refresh.

## Best solution

Guard `updateCollapseContextKeys` in src/vs/platform/list/browser/listService.ts so a stale/mid-refresh focused element (one no longer present in the tree model) doesn't throw — wrap the `tree.getNode(focus)` call in a try/catch or a `hasNode`/`hasElement`-style existence check, matching the same defensive pattern already used in asyncDataTree.ts's `refreshAndRenderNode` ("missing nodes are fine, this could've resulted from parallel refresh calls").
