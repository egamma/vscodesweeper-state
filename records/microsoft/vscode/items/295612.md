# Issue #295612 — Prevent distro from `release/xyz` pointing to a commit from `main`

[https://github.com/microsoft/vscode/issues/295612](https://github.com/microsoft/vscode/issues/295612)

## Summary

Valid engineering-process request to add a build-time guard against release branches referencing wrong distro commits. Carries `important`, still open with an unresolved implementation question from a team member — stays open.

## Change summary

Add a CI check during product build to ensure `release/xyz` branches reference a distro commit from the matching release branch, not `main`.

## Best solution

Implement a build-pipeline check (likely in `build/azure-pipelines/` or a pre-build script) that, for `release/*` branches, verifies the distro SHA in `package.json` is reachable from the corresponding `release/*` branch of vscode-distro, failing the build otherwise. The implementation challenge noted by alexdima — distinguishing a fresh branch-off (where `main` is expected) from a recovery release — needs a design decision first.
