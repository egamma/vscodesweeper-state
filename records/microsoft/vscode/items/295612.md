# Issue #295612 — Prevent distro from `release/xyz` pointing to a commit from `main`

[https://github.com/microsoft/vscode/issues/295612](https://github.com/microsoft/vscode/issues/295612)

## Summary

Keep open: the existing distro check only warns about branch-head mismatches and cannot enforce the requested release provenance. A maintainer must settle how to distinguish legitimate initial branching from recovery releases before making this a build failure.

## Change summary

Fail release product builds when the pinned vscode-distro commit violates the release branch's provenance requirements.

## Best solution

Define the allowed distro provenance during initial branching and recovery releases, then enforce that contract in the shared product-build checks. Preserve legitimate initial release builds and avoid treating every pin behind the distro branch head as invalid.

Newly created release branches must retain their legitimate initial build workflow. Acceptance checks must distinguish an allowed release pin, an invalid main-only recovery pin, and the agreed initial-branch exception; the invalid recovery case must fail the product build.

  > checkDistroCommit in build/azure-pipelines/common/checkDistroCommit.ts compares package.json.distro with the matching remote branch head, warns on inequality, and exits zero; it skips branches it cannot resolve. Keep unrelated feature-branch builds and normal main builds outside the new release restriction.
- **Open decisions:**

## Evidence

- **Existing capability does not satisfy the request:** build/azure-pipelines/common/checkDistroCommit.ts resolves the matching distro branch head and compares it for exact equality with package.json.distro. A mismatch emits warning and SucceededWithIssues logging commands, then exits successfully; unresolved branches skip the check. It neither verifies branch ancestry nor rejects a main-only release pin.
- **Pipeline remains nonblocking:** build/azure-pipelines/product-quality-checks.yml invokes checkDistroCommit.ts for publishing builds with continueOnError: true. build/azure-pipelines/distro/download-distro.yml checks out the pinned SHA without enforcing release-branch provenance.
- **Unsettled release contract:** https://github.com/microsoft/vscode/issues/295612#issuecomment-3978057784 explains that newly branched vscode release builds legitimately start with a distro main commit and asks how to distinguish that case from recovery releases. The discussion does not settle this observable acceptance policy.
- **Related PR repairs an input, not the safeguard:** https://github.com/microsoft/vscode-distro/pull/1324 was merged on 2026-02-16 and backports the chatHooks proposal to release/1.109. Its body identifies the erroneous main pin, but it does not implement the requested product-build rejection.
