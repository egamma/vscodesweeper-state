# Issue #295612 — Prevent distro from `release/xyz` pointing to a commit from `main`

[https://github.com/microsoft/vscode/issues/295612](https://github.com/microsoft/vscode/issues/295612)

## Summary

The release-safety gap remains on current main: the build detects a mismatched distro commit but deliberately reports only a warning and exits successfully. The issue should stay open while maintainers define when a newly created release branch becomes subject to blocking validation.

## Change summary

Make product builds fail when a VS Code release branch references a vscode-distro commit that does not belong to the corresponding release branch.

## Best solution

Turn the existing distro validation into a blocking release safeguard once the corresponding vscode-distro release branch is authoritative, while preserving the valid initial branch-off transition. The validation should distinguish branch membership from exact branch-head equality and cover recovery releases explicitly.

## Plan brief

- **Likely files:** `build/azure-pipelines/common/checkDistroCommit.ts`, `build/azure-pipelines/product-quality-checks.yml`
- **Validation:** Extend the build-script test coverage and run `npm run test-build-scripts`, covering main, initial release branch-off, valid recovery-release ancestry, and a release branch pinned to a main-only distro commit.
- **Behavior:**

  > A publish build from `release/x.y` must not succeed when package.json references a vscode-distro commit outside the corresponding `release/x.y` history. The normal initial branch-off transition must remain supported until the corresponding distro release branch is authoritative. Valid main builds and valid recovery releases must continue without false failures.
- **Trace:**

  > The existing check is in build/azure-pipelines/common/checkDistroCommit.ts and runs from build/azure-pipelines/product-quality-checks.yml. It resolves the matching remote branch and compares the pinned commit with that branch's exact HEAD, but mismatches become `SucceededWithIssues`, the script exits zero, and the pipeline step has `continueOnError: true`. The warning implementation originated in https://github.com/microsoft/vscode/pull/293104 and predates this issue. The uncertainty begins at the release lifecycle boundary identified in https://github.com/microsoft/vscode/issues/295612#issuecomment-3978057784: a newly cut VS Code release branch may legitimately still point at vscode-distro main, whereas a recovery build must not. Do not disrupt main-branch distro-update automation or reject valid older commits that belong to the matching release branch merely because they are not its current HEAD.
- **Open decisions:**
  - What observable state marks the transition from a valid initial branch-off reference to mandatory use of the corresponding vscode-distro release branch?
  - Should validity mean that the pinned commit is reachable from the matching release branch, or must it equal that branch's current HEAD?
  - Should missing corresponding distro branches remain non-blocking, or fail for specific publish and recovery build modes?

## Evidence

- **current source:** build/azure-pipelines/common/checkDistroCommit.ts compares package.json#distro with the matching vscode-distro branch head, but its mismatch path emits `task.complete result=SucceededWithIssues` and ultimately calls `process.exit(0)`.
- **pipeline behavior:** build/azure-pipelines/product-quality-checks.yml runs the check with `continueOnError: true`, so even an execution failure does not block the product build.
- **existing partial implementation:** https://github.com/microsoft/vscode/commit/e32b285afcf4315a14d392dfb0e654591d445426 introduced the intentionally non-blocking warning in https://github.com/microsoft/vscode/pull/293104 before this issue was filed; it does not satisfy the requested fail-fast behavior.
- **incident correction:** https://github.com/microsoft/vscode-distro/pull/1324 corrected the release/1.109 distro revision involved in the incident, but it does not add the requested preventive build enforcement.
- **open design question:** https://github.com/microsoft/vscode/issues/295612#issuecomment-3978057784 identifies the unresolved boundary between the valid initial branch-off state and a recovery release, where a wrong-branch reference must be rejected.
