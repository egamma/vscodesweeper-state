# Issue #284873 — Regression: Copilot Undo reverts git-committed changes (similar to #3492)

[https://github.com/microsoft/vscode/issues/284873](https://github.com/microsoft/vscode/issues/284873)

## Summary

Keep open for terminal-aware acceptance of committed agent edits. Maintainers identified this as missing auto-keep functionality, and current source still distinguishes SCM-driven acceptance from terminal-triggered status refresh.

## Change summary

Prevent Chat Undo from reverting agent edits already committed through integrated-terminal Git commands while retaining undo for uncommitted edits.

## Best solution

Make chat edit acceptance recognize terminal-created commits without accepting unrelated or uncommitted changes, including partially committed files. Retain this concrete report alongside the broader Keep/Undo redesign discussion.

- **Validation:** On Windows with review mode enabled, have the agent edit existing File A, run git add/commit/push for A in the integrated terminal, then edit uncommitted Files B and C. Invoke the reported Chat Undo action and confirm A remains identical to HEAD while B and C revert and the displayed affected-file count matches the operation. Repeat with only some changes in A committed; verify committed content survives and remaining uncommitted edits retain the agreed review/undo behavior.
- **Behavior:**

  > Agent edits committed through integrated-terminal Git commands must not subsequently be removed by the reported Chat Undo operation. Uncommitted agent edits must remain reviewable and undoable. The affected-file presentation must accurately describe which files the operation will change. Acceptance must cover a fully committed file followed by edits to other files, and establish safe behavior for a file containing both committed and uncommitted edits.
- **Trace:**

  > The reporter's terminal-only workflow is confirmed at https://github.com/microsoft/vscode/issues/284873#issuecomment-3711764132. Repository.add and commitOperationCleanup in extensions/git/src/repository.ts invoke _chat.editSessions.accept, while TerminalShellExecutionManager in extensions/git/src/terminal.ts only refreshes repository status after successful recognized Git commands. The command in chatEditingActions.ts accepts whole resources across editing sessions, and ChatEditingModifiedDocumentEntry._doReject can undo and save tracked contents without consulting Git. The report's confirmation dialog may involve request restoration rather than only entry rejection, so planning must identify the exact Undo action before defining its acceptance boundary. Preserve uncommitted edits and existing SCM behavior; do not substitute timer-based auto-acceptance or remove the entire review model. https://github.com/microsoft/vscode/issues/262495 is broader redesign context, and the newer https://github.com/microsoft/vscode/issues/285507 concerns CLI staging. No runtime reproduction was attempted; uncertainty begins at partial-commit semantics and the relationship between acceptance and request-level checkpoint restoration.
- **Open decisions:**
  - Should terminal staging automatically keep the staged edits, matching current SCM staging behavior, or should automatic acceptance require a successful commit?
  - For partially committed files, should only committed ranges become accepted while remaining ranges stay pending, and should explicit request/checkpoint restoration honor that same committed-content boundary?
