# Issue #330093 — Regression: Shell integration is disabled on Windows 10 build 17763 (1809) even though ConPTY is supported

[https://github.com/microsoft/vscode/issues/330093](https://github.com/microsoft/vscode/issues/330093)

## Summary

Confirmed on current main: getShellIntegrationInjection() in terminalEnvironment.ts still gates shell integration behind Windows build 18309, while ConPTY (CreatePseudoConsole) is documented as available since build 17763 — the code comment itself misattributes the ConPTY requirement to 18309. Already correctly labeled terminal; no maintainer rationale for the higher threshold is visible in source history or related issues.

## Change summary

VS Code disables terminal shell integration on Windows 10 build 17763 (1809) due to a hard-coded minimum build check of 18309, even though ConPTY is available since 17763.

## Best solution

Lower (or justify) the windowsBuildNumber threshold in getShellIntegrationInjection() (src/vs/platform/terminal/node/terminalEnvironment.ts:79); since agentHostTerminalManager.ts calls the same shared function, no second edit is needed there. If 18309 was chosen deliberately due to known ConPTY bugs in the 17763–18308 range, that reasoning should be captured in the code comment instead of silently retained.
