# Issue #330093 — Regression: Shell integration is disabled on Windows 10 build 17763 (1809) even though ConPTY is supported

[https://github.com/microsoft/vscode/issues/330093](https://github.com/microsoft/vscode/issues/330093)

## Summary

The reported code (an 18309 build gate in getShellIntegrationInjection, with the comment mislabeling it as ConPTY support) checks out exactly as described, but a terminal-team contributor is already engaging (suggesting windowsUseConptyDll) and there's a real wrinkle the reporter's suggested fix misses — terminalProcess.ts gates actual ConPTY usage at the same 18309 build separately, so lowering only the shell-integration check wouldn't enable a working ConPTY-backed terminal on 17763 anyway.

## Change summary

Shell integration injection is skipped on Windows 10 build 17763 (1809) due to a hard-coded minimum build check of 18309, even though the reporter argues ConPTY's CreatePseudoConsole API is available since 17763.

## Best solution

A maintainer needs to decide whether the 18309 threshold is a historical safety margin for early, buggy ConPTY builds or genuinely obsolete now; if lowered, both the shell-integration gate in src/vs/platform/terminal/node/terminalEnvironment.ts and the actual conpty-enablement gate in src/vs/platform/terminal/node/terminalProcess.ts (and the agent host equivalent) would need to move together, with real-hardware/VM validation on 1809 before any change ships.
