# Issue #251037 — Extension signature verification fails under Linux if file size limits are in effect

[https://github.com/microsoft/vscode/issues/251037](https://github.com/microsoft/vscode/issues/251037)

## Summary

The failure remains present in the dependency shipped by current main: VS Code invokes a .NET 9.0.9 NativeAOT vsce-sign binary whose runtime still truncates the double-mapping memfd to 2 TiB. The runtime fix exists upstream but has not been adopted on this code path, so the issue should remain open and be classified as upstream.

## Change summary

Extension installation fails on Linux when RLIMIT_FSIZE is below 2 TiB because the signature-verification process terminates with SIGXFSZ.

## Best solution

Publish the Linux vsce-sign binaries using a .NET runtime that contains dotnet/runtime commit f4a4d5c3d2f86cf7be266377989355dea74a632b, adopt those binaries in VS Code, and verify extension installation under a representative finite RLIMIT_FSIZE.

## Evidence

- **current dependency path:** src/vs/platform/extensionManagement/node/extensionSignatureVerificationService.ts imports @vscode/vsce-sign and calls its verify function. Current build/package-lock.json resolves the Linux x64 platform binary to @vscode/vsce-sign-linux-x64 2.0.6.
- **runtime still affected:** The packaged @vscode/vsce-sign-linux-x64 2.0.6 binary identifies its embedded runtime as .NET 9.0.9. Current dotnet/runtime release/9.0 source still calls ftruncate(fd, MaxDoubleMappedSize), where the reported limit is 2 TiB.
- **upstream fix not adopted:** https://github.com/dotnet/runtime/commit/f4a4d5c3d2f86cf7be266377989355dea74a632b changes doublemapping.cpp to cap the mapping using physical memory, RLIMIT_AS, and RLIMIT_FSIZE before ftruncate, directly addressing the reporter's trigger. It merged to runtime main, while the embedded .NET 9 runtime does not contain it.
- **recent confirmation:** The reporter confirmed at https://github.com/microsoft/vscode/issues/251037 that VS Code 1.106.3 and 1.107.0 still terminate the shipped vsce-sign executable with 'File size limit exceeded' under the stated ulimit.
- **canonical search:** https://github.com/microsoft/vscode-cpptools/issues/13768 is newer and concerns a different debugger executable, while https://github.com/microsoft/vscode/issues/321731 is also newer and reports SIGILL on ARM rather than SIGXFSZ under RLIMIT_FSIZE; neither meets the re-review duplicate bar.
