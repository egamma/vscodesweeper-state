# Issue #335546 — Agent Host: Codex steering with attached context stays pending after consumption

[https://github.com/microsoft/vscode/issues/335546](https://github.com/microsoft/vscode/issues/335546)

## Summary

Confirmed in source: Codex steering matching compares the original message text against the SDK's echoed resolved input (which appends attachment context), so a steering message with attachments never matches and its pending entry never clears. A fix is already up as an open PR, so this should stay open for that PR to land rather than being auto-fixed.

## Change summary

Codex steering messages with attached context (browser context, files, selections) keep showing as pending even after Codex consumes and responds to them.

## Best solution

Land the linked fix in https://github.com/microsoft/vscode/pull/335547, which should change `_takeMatchingPendingSteering`/`setPendingMessages` in codexAgent.ts to match against the resolved input (from `resolveCodexInput`) while still displaying the original message text.
