# Issue #335546 — Agent Host: Codex steering with attached context stays pending after consumption

[https://github.com/microsoft/vscode/issues/335546](https://github.com/microsoft/vscode/issues/335546)

## Summary

Confirmed in source: `_takeMatchingPendingSteering` (codexAgent.ts:3110-3117) matches Codex's echoed userMessage against the original `PendingMessage.message.text` by exact string equality, but `setPendingMessages` sends `resolveCodexInput(text, attachments)`'s expanded input (codexAgent.ts:6077), which appends attachment context — so a steering message with attached context never matches and its pending bubble sticks. An open PR (#335547) already targets this exact fix, so per policy the issue stays open pending that PR rather than being auto-fixed here.

## Change summary

When a Codex steering message includes attached context (browser context, file selection, etc.), Codex answers it but the pending 'Steering' entry in the UI never clears because the echo-matching logic can't correlate the (text-only) original message with the (attachment-expanded) echoed text.

## Best solution

Land #335547 (or an equivalent fix) that matches on the exact resolved input actually sent to Codex while retaining the original PendingMessage for display, per the reporter's proposed approach.
