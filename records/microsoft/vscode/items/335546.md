# Issue #335546 — Agent Host: Codex steering with attached context stays pending after consumption

[https://github.com/microsoft/vscode/issues/335546](https://github.com/microsoft/vscode/issues/335546)

## Summary

Traced the defect conclusively in current main: the pending-steering matcher compares raw text while the actual input sent to Codex includes appended attachment context, so a steered message with attachments never clears its pending bubble via the normal promotion path. An open PR from the same author already targets this fix, so the right move is to review/land that PR rather than close or auto-fix here.

## Change summary

A Codex steering message with a text-bearing attachment (browser context, file, selection) stays stuck under 'Steering' in the chat UI even after Codex has consumed and responded to it.

## Best solution

Land (or iterate on) the fix in https://github.com/microsoft/vscode/pull/335547, which should make `_takeMatchingPendingSteering` compare against the exact resolved input sent to Codex (from `resolveCodexInput`) while still displaying the original message text.
