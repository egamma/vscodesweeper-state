## Summary

Legitimate feature request for cross-remote multi-root workspaces — mixing folders from different tunneled/remote devices in one window. This hits a deep architectural constraint (single remote authority per window) and has no canonical issue that fully owns the ask. Keeping open for community traction.

## Change summary

Allow workspace folders from different remote/tunneled devices to coexist in a single multi-root workspace window.

## Best solution

This requires architectural changes to VS Code's remote model, which currently binds one remote authority per window. The request likely belongs in the remote development tracker (microsoft/vscode-remote-release) since the tunnel/remote orchestration lives there, but the underlying single-authority-per-window constraint is core.
