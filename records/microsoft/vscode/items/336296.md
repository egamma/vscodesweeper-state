# Issue #336296 — Allow downloading generated images from remote agent sessions

[https://github.com/microsoft/vscode/issues/336296](https://github.com/microsoft/vscode/issues/336296)

## Summary

A real discoverability and interaction-parity gap remains for generated images in remote agent sessions. The response tile already supports Save through its toolbar and context menu, but Images Preview has no save context action, and synthetic embedded images do not expose a meaningful source path to copy.

## Change summary

Provide discoverable save/download and applicable path-copying actions for generated images throughout remote agent session previews.

## Best solution

Keep the existing generated-image Save action, add Save As for the current image in Images Preview, and expose Copy Path only when the generated result references a real remote file URI. Embedded image data should remain downloadable without presenting its synthetic chat-resource URI as an original path.

## Evidence

- **existing response action:** On current main, src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatGeneratedImageResultSubPart.ts renders generated results through ChatResourceGroupWidget. src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatResourceGroupWidget.ts registers chat.toolOutput.save in both ChatToolOutputResourceToolbar and ChatToolOutputResourceContext, so right-clicking the generated-image tile already offers Save.
- **download path:** ChatResourceGroupWidget's SaveResourcesAction copies the generated ChatResponseResource URI to a user-selected local URI. src/vs/workbench/contrib/chat/common/widget/chatResponseResourceFileSystemProvider.ts resolves embedded base64 output and referenced remote files, so the original bytes are available for saving.
- **remaining carousel gap:** src/vs/workbench/contrib/imageCarousel/browser/imageCarouselEditor.ts implements navigation and zoom but has no context-menu, Save As, download, or copy-path action. ChatImageCarouselService passes in-memory image data into the carousel, so saving from that surface remains unavailable.
- **path semantics:** src/vs/workbench/contrib/chat/browser/widget/chatContentParts/toolInvocationParts/chatGeneratedImageResultSubPart.ts creates synthetic ChatResponseResource URIs for embedded outputs while preserving output.uri only for ref outputs. Copy Path is therefore meaningful only for referenced remote files, not every generated image.
- **canonical search:** Searches of open microsoft/vscode issues for generated-image downloads and image-carousel downloads found no older issue reporting the same observable request.
