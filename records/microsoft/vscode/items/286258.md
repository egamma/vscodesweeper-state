# Issue #286258 — Opening a Worktree should still have a mention of the workspace in the window title

[https://github.com/microsoft/vscode/issues/286258](https://github.com/microsoft/vscode/issues/286258)

## Summary

Keep open for a decision on worktree title semantics. Current source provides an opt-in repository-name variable, but the reported rootName-based template still loses the originating workspace identity; no issue-referencing fix was established for this team-authored request.

## Change summary

Retain recognizable originating workspace identity in the window title when opening a worktree in a new window.

## Best solution

Make repository/worktree windows distinguishable while preserving intentional custom title templates and the distinction between repository identity and workspace identity. Decide whether the existing activeRepositoryName variable is sufficient or whether opening a worktree should also retain originating workspace context.

- **Trace:**

  > The Repositories-view action artifactOpenWorktreeInNewWindow in extensions/git/src/commands.ts opens the artifact folder directly through vscode.openFolder; it does not carry the originating workspace identity. WindowTitle.getWindowTitle in src/vs/workbench/browser/parts/titlebar/windowTitle.ts derives rootName from the newly opened workspace, and LabelService.doGetSingleFolderWorkspaceLabel in src/vs/workbench/services/label/common/labelService.ts uses its basename. This already supports an opt-in repository-plus-worktree template where repository metadata is available, but does not recover arbitrary source workspace identity. The unresolved boundary is the public title-variable contract, not how to concatenate labels. Preserve non-worktree labeling and distinguish repository names from workspace names. Related discussion: https://github.com/microsoft/vscode/issues/251596.
- **Open decisions:**
  - Should existing rootName-based templates automatically retain originating workspace identity after opening a worktree, or should repository identity remain opt-in through activeRepositoryName?
