# Issue #314414 — Enforce `extensions.allowed` policy from the Remote (Server) side during Remote - SSH sessions

[https://github.com/microsoft/vscode/issues/314414](https://github.com/microsoft/vscode/issues/314414)

## Summary

Well-articulated enterprise feature request with strong community support (25 upvotes, promoted to Backlog). The current `AllowedExtensionsService` reads policy exclusively from the local client's configuration — no mechanism exists to consult or enforce the remote server's policy during Remote-SSH sessions. This is a real gap for VDI/cloud-workstation deployments.

## Change summary

Enforce the remote machine's `extensions.allowed` policy for remote extension installations during Remote-SSH sessions, independently of the local client's policy.

## Best solution

The `RemoteExtensionManagementService` (and/or the server-side extension management) needs a way to read the remote machine's `extensions.allowed` policy and either merge it with or apply it alongside the local policy for the remote extension context. The remote `AllowedExtensionsService` instance on the server should communicate its policy constraints back to the client during the remote handshake, so `extensionManagementChannelClient.ts` can enforce both local and remote policies. This likely touches `src/vs/workbench/services/extensionManagement/common/remoteExtensionManagementService.ts`, `src/vs/platform/extensionManagement/common/extensionManagementIpc.ts`, and the server-side extension management service.
