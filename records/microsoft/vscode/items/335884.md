# Issue #335884 — MCP migration blocks same-name servers in different workspace roots

[https://github.com/microsoft/vscode/issues/335884](https://github.com/microsoft/vscode/issues/335884)

## Summary

Team-authored, freshly-filed bug with precise source citations; verified in current main that findCrossRootConflicts rejects any same-name server across roots without checking whether the configurations are actually identical or would collide on disk. Real gap remains, so this should stay open and route to the MCP/AI-customizations area for a fix.

## Change summary

MCP server migration blocks migrating a same-named server that exists in another workspace root, even when each root's copy would land in its own independent .mcp.json without overwriting the other.

## Best solution

Fix findCrossRootConflicts in src/vs/workbench/contrib/chat/browser/aiCustomization/mcpServerCustomizationMigration.ts to only block migration when the cross-root name collision would actually cause an overwrite or runtime precedence ambiguity (per the sessionMcpDiscovery merge-by-name behavior noted in the issue), rather than rejecting on name match alone.
