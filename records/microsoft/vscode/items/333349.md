# Issue #333349 — "Window Is Not Responding" Dialog Steals Keyboard Focus and Shuts Down the Window on a Keystroke, Destroying Unsaved State

[https://github.com/microsoft/vscode/issues/333349](https://github.com/microsoft/vscode/issues/333349)

## Summary

Traced this in the checkout: the 'window is not responding' dialog's default (Enter-key) button really is the destructive 'Reopen' action, not the safe 'Keep Waiting' one, because massageMessageBoxOptions always hardcodes defaultId to the first button and windowImpl.ts's unresponsive-dialog call never overrides it — this is a real, narrow defect worth fixing, not a close.

## Change summary

When the renderer is unresponsive, the native 'window is not responding' dialog binds Enter to the destructive 'Reopen' button instead of the safe 'Keep Waiting' option, so a stray keystroke while typing can discard state.

## Best solution

Let massageMessageBoxOptions honor an explicit caller-supplied `defaultId` instead of always forcing button index 0, then have the unresponsive-window dialog in windowImpl.ts pass `defaultId` pointing at 'Keep Waiting' so Enter can't accidentally trigger a destructive reopen/close while the user is unaware the window ever froze.
