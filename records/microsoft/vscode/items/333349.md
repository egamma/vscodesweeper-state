# Issue #333349 — "Window Is Not Responding" Dialog Steals Keyboard Focus and Shuts Down the Window on a Keystroke, Destroying Unsaved State

[https://github.com/microsoft/vscode/issues/333349](https://github.com/microsoft/vscode/issues/333349)

## Summary

Traced the actual code path for the 'window is not responding' dialog: it's a native Electron message box shown from CodeWindow.onWindowError with buttons Reopen/Close/Keep Waiting and no explicit defaultId/cancelId, so a stray Enter keystroke delivered right as the dialog opens can activate a button the user never consciously chose. Real, narrow race-condition concern; no fix exists on main yet, and the exact default-button behavior needs maintainer verification before deciding what to change.

## Change summary

The unresponsive-window dialog can receive a keystroke meant for the editor and trigger Reopen/Close, discarding state that hadn't yet been backed up while the renderer was frozen.

## Best solution

In src/vs/platform/windows/electron-main/windowImpl.ts (onWindowError, WindowError.UNRESPONSIVE branch, ~line 1029), a maintainer should decide whether to set an explicit defaultId/cancelId (e.g. defaulting to 'Keep Waiting' instead of relying on Electron's implicit button 0) and/or add a short input grace period before the dialog starts accepting keyboard activation, so an in-flight keystroke from typing can't silently trigger Reopen or Close.
