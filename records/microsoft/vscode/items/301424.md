# Issue #301424 — Sessions: seeing terminal error popping up when working with multiple sessions on `vscode`

[https://github.com/microsoft/vscode/issues/301424](https://github.com/microsoft/vscode/issues/301424)

## Summary

Still unfixed on main. The race condition between task terminal reveal and background-session disposal remains: `_handleInstancePolicy` calls `revealTask` → `setActiveInstance` → `_getIndexFromId`, which throws when the terminal was already disposed by a session switch. Only diagnostic logging was added (78f58709a4c), not a guard.

## Change summary

Starting multiple agent sessions rapidly in the sessions window causes an error when the task system tries to reveal a terminal that was already disposed by a session switch.

## Best solution

Guard `revealTask` in `terminalTaskSystem.ts` (or the `_handleInstancePolicy` caller in `abstractTaskService.ts`) so that `setActiveInstance` is not called when the terminal instance is no longer in the group's instances list. The `isTaskVisible` check already verifies the terminal exists, but `_handleInstancePolicy` calls `revealTask` after the terminal may have been removed by a concurrent session background transition. A defensive check (or catching the throw) at the `revealTask`/`setActiveInstance` boundary would resolve this.
