# Issue #319757 — Session time stamp off by 9 hours (Redmond time instead of local time?)

[https://github.com/microsoft/vscode/issues/319757](https://github.com/microsoft/vscode/issues/319757)

## Summary

Team-authored bug — session timestamps appear to be off by a timezone offset (9 hours, matching CEST-to-PST). The defect is still present on main; no fixing commit found. Keeping open for investigation.

## Change summary

Session timestamps in the sessions list show a time offset matching the difference between the user's local timezone and US Pacific time.

## Best solution

Investigate the timestamp chain from the Copilot API / SDK through to the sessions list UI. The most likely culprits are: (1) the cloud API (`sessionItem.created_at`) returning ISO strings without a `Z` suffix, causing `new Date(date)` in `validateISOTimestamp` (copilotCloudSessionsProvider.ts ~line 1288) to interpret them as local time instead of UTC; or (2) the SDK's `LocalSessionMetadata.startTime`/`modifiedTime` (consumed in copilotcliSessionService.ts ~line 521/604) using a naive date. The fix likely belongs in `extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts` or upstream in the `@github/copilot/sdk` package.

## Evidence

- **timezone offset:** Reporter is in CEST (UTC+2) and the timestamp is off by ~9 hours, exactly matching the offset to US Pacific time (UTC−7 in PDT).
- **timestamp chain — cloud path:** In extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts ~line 1283-1291, `validateISOTimestamp` parses `sessionItem.created_at` via `new Date(date).getTime()`. If the API returns an ISO string without a `Z` suffix (e.g. `2026-06-03T06:14:55` in PST), `new Date()` interprets it as local time, shifting the epoch value.
- **timestamp chain — local/CLI path:** In extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts lines 521/604, `metadata.startTime.getTime()` and `metadata.modifiedTime.getTime()` are used. These `Date` objects come from the SDK's `LocalSessionMetadata` — if the SDK constructs them from naive date strings the same offset would appear.
- **rendering is correct:** The `fromNow` function in src/vs/base/common/date.ts simply computes `Date.now() - date` — this is timezone-agnostic and correct. The bug is in the timestamp value, not in how it's displayed.
- **no fix on main:** git log since 2026-06-01 shows no timezone-related fixes in the session or copilot chat-sessions paths.
