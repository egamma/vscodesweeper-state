# Issue #295647 — Chat: "Background" in chat output should be "Worktree"

[https://github.com/microsoft/vscode/issues/295647](https://github.com/microsoft/vscode/issues/295647)

## Summary

Current main no longer says “Background,” but it replaced that label with “Copilot CLI,” not the requested worktree and branch identity. Keep this open because worktree-backed and workspace-backed Copilot CLI sessions now need a deliberate, context-sensitive presentation.

## Change summary

Identify worktree-backed sessions in chat output as worktrees and expose enough worktree and branch information to distinguish parallel sessions.

## Best solution

Show persistent location identity for worktree-backed chat output, including a concise worktree and branch label, without calling workspace-mode Copilot CLI sessions worktrees. Keep provider identity available separately where it remains useful.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessions.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/sessionSummaryHover.ts`
- **Validation:** Add focused presentation tests asserting that a worktree-backed Copilot CLI session is identified with its worktree and branch in chat output, while a workspace-mode session is not labeled as a worktree.
- **Behavior:**

  > Chat output for a session running in an isolated Git worktree should identify that location as a worktree and expose its branch so users can match parallel sessions to Git history. Multiple worktree sessions must be distinguishable without relying solely on the generic provider name. A Copilot CLI session running directly in a workspace must not be presented as a worktree.
- **Trace:**

  > The extension contributes the `copilotcli` session label through extensions/copilot/package.json, while src/vs/workbench/contrib/chat/browser/agentSessions/agentSessions.ts supplies a core fallback label. Both currently say “Copilot CLI.” The shared hover model in src/vs/workbench/contrib/chat/browser/agentSessions/sessionSummaryHover.ts already accepts and renders worktree and branch fields, establishing that this metadata is available on at least some session presentation paths. The uncertainty starts at how much of that location identity should be persistent in chat output versus hover-only, and how it should coexist with provider identity now that Copilot CLI supports both workspace and worktree isolation. The broader cross-surface design is discussed in https://github.com/microsoft/vscode/issues/336620; this issue should remain focused on the chat-output presentation.
- **Open decisions:**
  - Should the chat-output heading primarily identify the provider (“Copilot CLI”) or the actual execution location (“Worktree” or “Workspace”), and where should the secondary identity appear?
  - Should the worktree path and branch be shown persistently in the output or placed behind a compact disclosure/hover while remaining discoverable and accessible?
