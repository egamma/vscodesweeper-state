# Issue #167801 — Wrong string replacement result

[https://github.com/microsoft/vscode/issues/167801](https://github.com/microsoft/vscode/issues/167801)

## Summary

The result matches the deliberately limited preserve-case heuristic; supporting structurally different qualified expressions would require expanding that heuristic, and maintainers have already declined this broader polish.

## Change summary

Preserve Case should keep `uuidv4()` lowercase when replacing the title-cased qualified expression `Utils.uuidv4()`.

## Best solution

Retain the current whole-match casing rules rather than adding increasingly semantic alignment heuristics for structurally different search and replacement strings.

- **Proposed comment:**

  > Thanks for the report. Preserve Case currently recognizes a limited set of whole-match casing patterns. Because `Utils.uuidv4()` begins with an uppercase letter, the title-case rule intentionally changes the replacement to `Uuidv4()`; it does not semantically align the removed `Utils.` qualifier with the replacement. Expanding these heuristics for structurally different strings was considered in https://github.com/microsoft/vscode/issues/144539 and https://github.com/microsoft/vscode/issues/78204, but was closed as out of scope.
