# Issue #330475 — Agent Host (Claude): first message fails with `No conversation found with session ID` when the Claude SDK downloads lazily during the first turn

[https://github.com/microsoft/vscode/issues/330475](https://github.com/microsoft/vscode/issues/330475)

## Summary

Traced conclusively on main: the Claude session's rematerializer (attachRematerializer closure in claudeAgentSession.ts) hardcodes `isResume: true` on every rebind, and the first-send pre-flight (`send()` checking `toolDiff.hasDifference`) can trigger that rebind before the pipeline has ever seen an SDK `system:init` — i.e. before Claude Code has actually created the on-disk conversation. A slow lazy SDK download widens the race window (more client-tool/customization registrations land before the first real turn), making this reliably reproduce on cold-cache environments.

## Change summary

First message in a brand-new Claude Agent Host session fails with 'No conversation found with session ID' when the Claude SDK downloads lazily during that first turn.

## Best solution

In claudeAgentSession.ts's rematerializer (around line 676), stop hardcoding `isResume: true` and instead derive it from whether the pipeline has ever observed a `system:init` message (`pipeline.isResumed`, tracked in claudeSdkPipeline.ts:203-204/668-673). A rebind that fires before any turn has run should still build a fresh (create) session, not a resume.
