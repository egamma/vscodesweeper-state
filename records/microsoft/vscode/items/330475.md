# Issue #330475 — Agent Host (Claude): first message fails with `No conversation found with session ID` when the Claude SDK downloads lazily during the first turn

[https://github.com/microsoft/vscode/issues/330475](https://github.com/microsoft/vscode/issues/330475)

## Summary

Team-authored bug report (author eleanorjboyd, MEMBER) with a detailed, code-grounded trace of a real race between lazy Claude SDK download and session materialize/resume logic; no commit or PR references #330475, so under the team-authored hard keep-open rule this stays open regardless of technical depth.

## Change summary

On a fresh machine where the Claude agent SDK hasn't been downloaded yet, the first message in a brand-new Agent Host session fails with `No conversation found with session ID`, because the session gets rebuilt as a resume instead of a create once the lazily-triggered SDK download finishes.

## Best solution

Fix belongs in src/vs/platform/agentHost/node/claude/claudeAgent.ts (`_resolveOrResumeChatSessionLocked`'s `isResume: !!sdkInfo` decision) and/or claudeAgentSession.ts's rematerializer path so a session that has never actually created an SDK conversation cannot be rebuilt in resume mode while its SDK download was still in flight during the first turn.
