- **Validation:** In a clean current build, create a CSS file, enter .example { justify-content: }, accept the property completion, and type stretch at the value position. Inspect the matching entries and their providers; verify that equivalent stretch suggestions are not repeated and accepting the remaining suggestion inserts the correct value. If the language service itself duplicates the item, add a completion assertion requiring exactly one stretch match.
- **Behavior:**

  > The reporter sees stretch more than once when completing justify-content in a CSS class. Reproduce the supplied property-then-value completion sequence and determine whether the entries are equivalent suggestions or intentionally different completion kinds. The acceptance check is that equivalent stretch proposals are not duplicated, while accepting the value still produces valid CSS and other valid completions remain available.
- **Trace:**

  > extensions/css-language-features/server/src/cssServer.ts registers connection.onCompletion and forwards CSS requests to vscode-css-languageservice.doComplete2. The checked-in dependency is 7.0.0-next.2; its published webCustomData.js contains only one stretch entry for justify-content, so duplicate static values alone do not explain this report. The uncertainty starts at the actual completion response and the editor's combination of completion providers. extensions/css-language-features/server/src/test/completion.test.ts already asserts uniqueness by label for selected expected items. Do not infer that unrelated duplicate color-function work in https://github.com/microsoft/vscode-css-languageservice/pull/532 resolves this case, and do not apply blanket label deduplication without identifying the two entries' semantics.
