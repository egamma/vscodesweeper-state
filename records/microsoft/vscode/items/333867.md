# Issue #333867 — Rethink agent response rendering with custom backgrounds

[https://github.com/microsoft/vscode/issues/333867](https://github.com/microsoft/vscode/issues/333867)

## Summary

The visual concern remains on current main: custom backgrounds deliberately place each assistant response in a distinct neutral container, while plain chats remain unboxed. Route this to the Agents Window and chat-background owners for a product-design decision rather than closing it as fixed.

## Change summary

Redesign Agents Window response presentation so custom backgrounds retain a calm, coherent hierarchy without exposing every response as a separate large card.

## Best solution

Define a unified custom-background transcript hierarchy that keeps user messages distinct and preserves readability for agent text, tools, checkpoints, and status content without making every response a competing card. Capture the chosen hierarchy in the existing themed component fixture before changing the Sessions-owned presentation.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/media/chatView.css`, `src/vs/sessions/contrib/chat/browser/chatView.ts`, `src/vs/sessions/contrib/chat/test/browser/chatView.fixture.ts`, `src/vs/sessions/contrib/chat/test/browser/chatView.test.ts`
- **Validation:** Render the themed component fixture `sessions/chat/view/chatView/AssistantResponseBackground` with representative Markdown, code, tools, checkpoint controls, and status content; compare it with `AssistantResponsePlain`, update the blocks-CI screenshot baseline, and verify light, dark, and high-contrast presentation.
- **Behavior:**

  > With an Agents Window custom background enabled, a conversation should read as a calm, continuous hierarchy rather than a sequence of mismatched translucent or neutral cards. User messages remain visually distinct, while assistant text, questions, tool output, checkpoints, and status rows form an intentional response hierarchy. Content must remain readable over busy images, and the no-background transcript must retain its established unboxed presentation.
- **Trace:**

  > The custom-background branch is owned by src/vs/sessions/contrib/chat/browser/media/chatView.css: `.has-chat-background` adds response padding and an `interactive-response::before` neutral surface, while plain responses remain unboxed. The renderer width reservation is synchronized in `ChatView` through `getSessionChatItemHorizontalPadding`, so any changed horizontal treatment must remain consistent with embedded editor, tool, and diff layout. https://github.com/microsoft/vscode/pull/335201 introduced the current bubble and the `AssistantResponseBackground`/`AssistantResponsePlain` visual fixtures. Keep the scope in the Sessions presentation: do not change ordinary workbench chat, user-message distinction, keyboard behavior, or high-contrast borders. The uncertainty begins at the visual grouping model and at which rich response parts need independent opacity over a custom image.
- **Open decisions:**
  - Should custom-background assistant content use one continuous transcript lane, per-turn grouping with quieter boundaries, or another hierarchy that avoids the current large response cards?
  - Which response parts—such as code, tools, checkpoints, questions, and status rows—must retain independent opaque surfaces for readability, and which should visually inherit the shared lane?
  - How closely should the custom-background hierarchy match the default unboxed transcript versus using a distinct presentation to guarantee contrast over busy images?

## Evidence

- **current source:** src/vs/sessions/contrib/chat/browser/media/chatView.css applies extra padding and an `interactive-response::before` surface under `.has-chat-background`; the pseudo-element uses `editorWidget.background` and a medium-radius container, so the reported per-response card structure remains present on current main.
- **current visual contract:** src/vs/sessions/contrib/chat/test/browser/chatView.fixture.ts defines `AssistantResponseBackground` as a “distinct neutral assistant bubble,” while `AssistantResponsePlain` explicitly expects an unboxed response. This confirms the custom-background divergence is deliberate and still current.
- **later implementation:** https://github.com/microsoft/vscode/pull/335201 merged after this report and replaced the prior side fade with a neutral response bubble. It does not reference this issue and does not satisfy the report's central request to avoid putting every response in a large bubble, so it is design context rather than an implemented-on-main fix.
- **canonical search:** https://github.com/microsoft/vscode/issues/3429 concerns TextMate token background colors, and https://github.com/microsoft/vscode/issues/295788 is a general UI-refresh tracker. The newer https://github.com/microsoft/vscode/issues/337716 concerns sticky user-message spacing and sash obstruction; none reports the same response-hierarchy symptom or owns this work.
