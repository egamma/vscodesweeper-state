# Issue #106131 — Provide an option for TextEdit to respect the indentation level

[https://github.com/microsoft/vscode/issues/106131](https://github.com/microsoft/vscode/issues/106131)

## Summary

The API gap remains on current main: completion additional edits are still literal `TextEdit[]` operations without indentation control. Keep this Backlog request open for API design discussion.

## Change summary

Allow completion additional text edits to opt into indentation adjustment at their insertion location.

## Best solution

Design a per-edit indentation mode for completion additional edits, likely through a snippet-aware edit type or explicit edit metadata, while preserving literal `TextEdit` behavior and backward compatibility.

## Evidence

- **current API:** `CompletionItem.additionalTextEdits` remains `TextEdit[]` in src/vscode-dts/vscode.d.ts, while `CompletionItem.keepWhitespace` controls only the primary completion insertion.
- **current application path:** src/vs/editor/contrib/suggest/browser/suggestController.ts applies synchronous and asynchronous additional edits through literal `executeEdits` operations, without the primary insertion's whitespace-adjustment option.
- **partial existing capability:** Commit 8f4b28aedd64cf149961f620405765ae3356b42a added `SnippetTextEdit.keepWhitespace` for workspace edits, but `CompletionItem.additionalTextEdits` cannot contain `SnippetTextEdit`, so it does not satisfy this request.
- **related behavior:** https://github.com/microsoft/vscode/issues/101773 documents `CompletionItem.keepWhitespace` for the primary edit; https://github.com/microsoft/vscode/issues/32158 explains why ordinary code-action text edits remain literal. Neither provides opt-in adjustment for completion additional edits.
