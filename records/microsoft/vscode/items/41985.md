# Issue #41985 — Support reading/writing chunks in remote fs

[https://github.com/microsoft/vscode/issues/41985](https://github.com/microsoft/vscode/issues/41985)

## Summary

Keep open: chunked provider operations exist on main but remain behind the proposed fsChunks API. This api-proposal tracks unfinished API finalization and must not be closed merely because its proposed implementation exists.

## Change summary

Support incremental reads and writes in remote filesystem providers without materializing entire files in memory.

## Best solution

Have the filesystem API owners settle and finalize the provider-side chunked I/O contract, preserving incremental reads and snapshot-backed writes. Coordinate with the related consumer-stream proposal without treating it as a replacement for this older provider proposal.

- **Existing capability remains proposed:** src/vscode-dts/vscode.proposed.fsChunks.d.ts declares optional FileSystemProvider.open, close, read and write methods with positions, offsets and lengths. src/vs/workbench/api/common/extHostFileSystem.ts:161-165 explicitly requires checkProposedApiEnabled(extension, 'fsChunks') before advertising FileOpenReadWriteClose capability.
- **Incremental path is wired:** src/vs/workbench/api/browser/mainThreadFileSystem.ts:266-281 forwards open/close/read/write across the extension-host bridge. src/vs/platform/files/common/fileService.ts:413-424 selects buffered writing for capable providers and readable/stream inputs; doWriteBuffered and its provider.write loop support incremental writes. This establishes proposed functionality, not stable API availability.
- **Related finalization did not cover chunks:** The closed https://github.com/microsoft/vscode/issues/47475 explicitly leaves its chunked read/write checklist item unchecked and delegates it to https://github.com/microsoft/vscode/issues/41985. The closed https://github.com/microsoft/vscode/issues/71200 concerns open-mode options, not finalization of the complete chunk API.
- **Related proposal is not a duplicate target:** https://github.com/microsoft/vscode/issues/84515 is open and was created on 2019-11-11, later than this re-reviewed issue. Although its discussion includes chunk primitives, https://github.com/microsoft/vscode/issues/84515#issuecomment-1210825041 explicitly distinguishes the POSIX-primitives proposal from the stream-writing proposal. It therefore does not justify consolidating this older report as a duplicate.
- **Remaining user need:** The supplied 2023-07-24 comment reports imposing a 5 MB limit in a remote filesystem to avoid expensive whole-file transfers. Current source still gates provider chunk operations as proposed; their presence does not establish general stable-extension access.
