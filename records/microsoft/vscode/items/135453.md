# Issue #135453 — LSP `textDocument/documentSymbol` is delayed by ~350ms

[https://github.com/microsoft/vscode/issues/135453](https://github.com/microsoft/vscode/issues/135453)

## Summary

Keep open under discussion: current source still imposes a 350 ms minimum outline debounce even for fast providers. The remaining question is whether greater responsiveness warrants changing the deliberate request-rate and UI-stability tradeoff; neither the existing adaptive debounce nor the related protocol proposals resolves that request.

## Change summary

Allow fast document-symbol providers to refresh the outline with less than the current minimum debounce delay.

## Best solution

Have the outline owner decide whether to permit a lower debounce floor for fast providers while retaining protection against request floods and unstable outlines during incomplete edits. Keep document-color scheduling separate, as requested in the discussion.

## Evidence

- **Current minimum remains:** src/vs/editor/contrib/documentSymbols/browser/outlineModel.ts:426 constructs DocumentSymbols debounce information with { min: 350 }; getDebounceValue returns that information's delay.
- **Exact scheduling path:** src/vs/workbench/contrib/codeEditor/browser/outline/documentSymbolsOutline.ts:199-204 handles document content changes by obtaining getDebounceValue(model) and scheduling _createOutline(event) through TimeoutTimer.cancelAndSet. In src/vs/editor/common/services/languageFeatureDebounce.ts, FeatureDebounceInformation clamps measured averages to the configured minimum, so fast responses cannot reduce the built-product delay below 350 ms.
- **Existing capability does not satisfy the request:** The adaptive debounce already measures provider response time but retains the minimum. Outline configuration registrations in src/vs/workbench/contrib/outline/browser/outline.contribution.ts provide presentation and filtering options, not a refresh-delay control; the development-mode debounce branch also returns min * 1.5 rather than eliminating the minimum.
- **Maintainer rationale and scope:** https://github.com/microsoft/vscode/issues/135453#issuecomment-947454985 explains that debouncing protects extensions and prevents unstable outlines during invalid intermediate syntax. https://github.com/microsoft/vscode/issues/135453#issuecomment-947490080 leaves timeout changes undecided and explicitly separates document colors from this discussion.
- **Protocol proposals are related, not fixes:** https://github.com/microsoft/language-server-protocol/issues/1367 is closed with ServerCancelled suggested instead of an idle notification, but the reporter explains that retry signaling does not short-circuit the initial debounce. https://github.com/microsoft/language-server-protocol/issues/2069 remains open and requests documentSymbol server-cancellation support for requests arriving before parsing finishes, rather than removal of this client's minimum delay.
- **Canonical search:** Repository issue searches for outline debounce and documentSymbol delay found no verified older open issue with the same symptom. https://github.com/microsoft/vscode/issues/144541 concerns debugger-inflated adaptive delays; https://github.com/microsoft/vscode/issues/161627 requests less frequent updates; https://github.com/microsoft/vscode/issues/61104 concerns off-cycle push updates. These closed reports do not establish a canonical duplicate or a decision covering the full request here.
