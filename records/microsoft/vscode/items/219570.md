## Change summary

## Plan brief

- **Likely files:** `extensions/git/src/askpass.ts`, `src/vs/workbench/contrib/terminal/browser/remoteTerminalBackend.ts`, `src/vs/platform/terminal/node/terminalProcess.ts`
- **Validation:** On a Linux client, connect through Remote-SSH to a Windows OpenSSH host, open PowerShell, and push a test commit to a Linux SSH Git remote using keys. Require the command to exit successfully and the remote ref to match the pushed commit; compare with ordinary SSH PowerShell and locally launched Windows VS Code using the same Git executable, repository, and SSH configuration.
- **Behavior:**

  > A Git push initiated in a Windows PowerShell terminal reached through VS Code Remote-SSH from Linux should complete as it does through ordinary SSH or locally launched Windows VS Code. The reporter confirmed the remote-terminal failure on two Insiders versions, and the attached SSH trace shows successful public-key authentication. First establish whether current builds still exhibit the failure. Acceptance requires successful command exit and an updated destination ref, not merely successful SSH login.
- **Trace:**

  > The reported operation is a typed terminal command, not the Git extension's Source Control push action. Askpass.getTerminalEnv() in extensions/git/src/askpass.ts contributes Git askpass variables, while getEnv() separately includes SSH askpass variables; removing the reporter's listed VS Code variables did not fix the problem. RemoteTerminalBackend.createProcess in src/vs/workbench/contrib/terminal/browser/remoteTerminalBackend.ts delegates launch to the remote channel, and TerminalProcess in src/vs/platform/terminal/node/terminalProcess.ts supplies Windows pseudoterminal options. The trace at https://github.com/user-attachments/files/16057017/gitlog.txt reaches authentication and git-receive-pack, but does not identify whether Git, SSH, or terminal I/O remains blocked. Root cause and current-build reproduction remain unconfirmed; do not change authentication defaults or assume extension ownership without isolating the working and failing launch paths.
