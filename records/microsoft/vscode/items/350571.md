## Evidence

- **Verified canonical:** https://github.com/microsoft/vscode/issues/227281 is currently OPEN. Its original report explicitly says each SHA-256 commit appears as a separate branch, covering the same observable graph defect.
- **Maintainer-established scope:** https://github.com/microsoft/vscode/issues/227281#issuecomment-2569747518 expands the canonical issue to the Git extension's multiple assumptions that commit hashes are 40 characters long. https://github.com/microsoft/vscode/issues/227281#issuecomment-2564300829 specifically identifies truncation to the last 40 characters.
- **Exact source diagnosis:** extensions/git/src/git.ts:943-975 uses an unanchored 40-character commitRegex. For the reporter's 64-character %H output, it captures the final 40 characters as Commit.hash while preserving full parent hashes. extensions/git/src/historyProvider.ts:318-319 forwards these mismatched values as id and parentIds.
- **Graph consequence:** src/vs/workbench/contrib/scm/browser/scmHistory.ts:317-357 compares lane IDs directly with historyItem.id and retains unmatched parent lanes. Full 64-character parent IDs cannot match truncated commit IDs, explaining disconnected commits and accumulating lanes in the supplied linear-history reproduction.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/327494 is OPEN and explicitly fixes the canonical issue. It proposes SHA-256-aware object-ID parsing, including commit-parser cases; it has not merged and is not evidence of a completed fix.
