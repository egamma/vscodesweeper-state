## Evidence

- **Verified canonical:** https://github.com/microsoft/vscode/issues/227281 is OPEN. Its original report includes 'Each commit shown as if it is separate branch'; the maintainer explicitly expanded its scope to all Git-extension assumptions that hashes are 40 characters long: https://github.com/microsoft/vscode/issues/227281#issuecomment-2569747518.
- **Source-confirmed truncation:** extensions/git/src/git.ts:943-975 uses an unanchored 40-character commitRegex in parseGitCommits. A 64-character commit ID therefore matches its last 40 characters, while parents are retained at full length by parents.split(' '). This confirms the reporter's proposed explanation for the five-commit linear SHA-256 reproduction.
- **Graph data path:** extensions/git/src/historyProvider.ts:276-319 obtains repository.log results and exposes commit.hash as the history item's id and commit.parents as parentIds. The truncated IDs cannot equal their full-length parent references, explaining the disconnected lanes.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/327494 is OPEN, has not merged, and explicitly says 'Fixes #227281'. Its proposed changes cover the affected Git parsers; it is not evidence that the defect is already fixed.
- **Distinct reproduction retained:** https://github.com/microsoft/vscode/issues/350571 supplies a minimal git init --object-format=sha256 reproduction with five empty commits on Linux and VS Code 1.148.0, plus confirmation that git log emits full parent IDs. These details strengthen the canonical report without identifying a separate defect.
