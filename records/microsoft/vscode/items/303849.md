[https://github.com/microsoft/vscode/issues/303849](https://github.com/microsoft/vscode/issues/303849)

## Summary

Keep open: two users reproduced a first-turn Copilot request exceeding the selected model's input limit, including after disabling the suspected Foundry and Azure MCP servers. Current source has tool grouping and count limits, but it does not establish which model or payload component caused this report, and no citable fixing commit was found.

## Change summary

A short first chat question fails as input-too-large while interaction-required MCP servers and an unexpectedly selected GitHub GPT-5 model are present.

## Best solution

Trace model selection and the complete first-turn token budget, then ensure Copilot Chat cannot dispatch a request whose instructions, context, and tool definitions exceed the selected model's prompt limit; the interaction-required MCP notice must not inflate or otherwise break an unrelated request.

- **Trace:**

  > The failure appears after the MCP interaction notice and the "Optimizing tool selection" phase. DefaultIntentRequestHandler.getAvailableTools in extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts chooses between endpoint-native tool search and ToolGrouping; ToolGrouping in extensions/copilot/src/extension/tools/common/virtualTools/toolGrouping.ts primarily enforces the 128-tool count threshold. AgentIntent in extensions/copilot/src/extension/intents/node/agentIntent.ts separately counts tool tokens and derives a message budget from the endpoint's modelMaxPromptTokens. The source does not establish whether this report came from wrong endpoint metadata, an unexpectedly selected model, oversized eager tool schemas, or another first-turn context component; diagnosis should begin by capturing those values for the reported fresh-chat path. ## Evidence

- **independent reproduction:** The reporter reproduced the failure on VS Code 1.112.0 with Copilot Chat 0.40.1, and a second user confirmed the same input-too-large symptom on 2026-07-22 after disabling Foundry, Foundry Toolkit, and Azure MCP Server.
- **current request path:** extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts:getAvailableTools obtains every available tool and either relies on endpoint tool search or reduces the surface through ToolGrouping before dispatch.
- **budget handling:** extensions/copilot/src/extension/intents/node/agentIntent.ts counts tool-schema tokens and derives the message budget from the model prompt limit, while extensions/copilot/src/extension/tools/common/virtualTools/toolGrouping.ts reduces non-tool-search endpoints only to the 128-tool count limit; neither fact alone proves this report is fixed.
- **related newer report:** https://github.com/microsoft/vscode/issues/329040 confirms that large aggregate tool definitions can exceed a model context budget, but it was filed after this re-reviewed issue and reports a silent failure rather than the same visible input-too-large error, so it does not meet the stronger duplicate bar.
- **non-canonical MCP reports:** https://github.com/microsoft/vscode/issues/300260 and https://github.com/microsoft/vscode/issues/268882 concern intentional MCP interaction/start behavior, not a short first request exceeding the selected model's input limit; both are also closed.
