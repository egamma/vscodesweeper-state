# Issue #289355 — Copilot Chat: Org-wide Custom agents do not work with base roles

[https://github.com/microsoft/vscode/issues/289355](https://github.com/microsoft/vscode/issues/289355)

## Summary

The bug is still present on main. The org custom agent provider in `githubOrgCustomAgentProvider.ts` calls `getOrganizationRepositories` and `getCustomAgents`, both of which require a "permissive" GitHub auth session via `_getPermissiveSession`. When a user has only org base-role access (not explicit repo collaborator access), the permissive session token apparently lacks the necessary scopes to access the agents repo, causing a `PermissiveAuthRequiredError` — while GitHub.com's native Copilot Chat handles this correctly.

## Change summary

Org-wide custom Copilot agents fail for members who access the agents repo only via org base role (not explicit collaborator access), despite working on GitHub.com.

## Best solution

Investigate whether the permissive auth session's OAuth scopes need broadening or whether the API calls in `OctoKitService.getCustomAgents`/`getOrganizationRepositories` need to use a different auth strategy that respects org base roles. The fix likely lives in `extensions/copilot/src/platform/github/common/octoKitServiceImpl.ts` or the authentication layer that provides the permissive session. The GitHub.com parity gap should be closed so org base-role members can use org custom agents without explicit repo access.
