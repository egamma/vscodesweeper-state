# Issue #281922 — Make showing delay take precedence over hiding delay

[https://github.com/microsoft/vscode/issues/281922](https://github.com/microsoft/vscode/issues/281922)

## Summary

Keep open: current hover scheduling still waits for the hiding delay before starting the showing delay, so the requested precedence remains missing. This team-authored follow-up owns a distinct improvement split from the original report; no qualifying open duplicate or fixing commit was found.

## Change summary

Let a new editor hover appear after its showing delay without first waiting out the previous hover's hiding delay.

## Best solution

Make editor hover transitions honor independent showing and hiding deadlines: moving to another target must not add the delays together, and a shorter showing deadline should replace the old hover. Preserve sticky-hover interaction and keep the separate non-sticky hiding-delay request outside this issue.

- **Behavior:**

  > Showing and hiding delays should run independently when moving between editor hover targets. With an existing hover visible, hidingDelay=2000 and editor.hover.delay=1000, a new target with immediately available content replaces the old hover after 1000 ms. Moving to empty space respects the hiding delay, while entering an interactive sticky hover continues to preserve it.
