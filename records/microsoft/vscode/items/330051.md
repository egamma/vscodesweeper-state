# Issue #330051 — Automations: Cannot use Undo or Redo in Prompt input

[https://github.com/microsoft/vscode/issues/330051](https://github.com/microsoft/vscode/issues/330051)

## Summary

Traced the exact cause on main: the Automations dialog's global keydown handler blocks Undo/Redo in the prompt editor because those commands aren't in its allowlist — a small, well-localized fix.

## Change summary

Cmd+Z/Cmd+Y (Undo/Redo) don't work while editing text in the Automations dialog's prompt input.

## Best solution

Add 'undo' and 'redo' to `automationDialogAllowableCommands` in src/vs/sessions/contrib/automations/browser/automationDialogService.ts so the dialog's keyEventProcessor lets those commands reach the embedded ChatInputPart editor.

The editor core commands 'undo' (Cmd+Z) and 'redo' (Cmd+Y / Cmd+Shift+Z on mac) are registered with precondition: undefined in src/vs/editor/browser/editorExtensions.ts (UndoCommand/RedoCommand, lines ~646-700), so they always resolve and always get blocked before reaching the embedded editor. Fix: add 'undo' and 'redo' to the `automationDialogAllowableCommands` Set defined in src/vs/sessions/contrib/automations/browser/automationDialogService.ts (currently lines 33-56, alongside copy/cut/paste/selectAll/etc.). Do NOT touch the shared `defaultDialogAllowableCommands` in src/vs/workbench/browser/parts/dialogs/dialog.ts — that's the default for all workbench dialogs (most of which have no embedded text editor), so the change should stay scoped to the Automations dialog's own allowlist. Do not alter the dialog's other keyboard handling (Escape, Enter, Cmd+D, Alt, Space) in src/vs/base/browser/ui/dialog/dialog.ts.
