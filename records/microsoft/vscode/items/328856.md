# Issue #328856 — Extensions: Check for Extension Updates does not update private git-subdir agent plugins

[https://github.com/microsoft/vscode/issues/328856](https://github.com/microsoft/vscode/issues/328856)

## Summary

Confirmed in source: for git-based agent-plugin sources tracking a branch (no pinned `sha`), `updateAllPlugins` in pluginInstallService.ts gates the per-plugin update on `hasSourceChanged`, which only compares `ref`/`sha`/`path` — so new commits on the same branch never trigger an update attempt, even with the Force command, even though `AbstractGitPluginSource.update()` (which does the real `git pull`) works fine once called.

## Change summary

Agent Plugin update commands (and the reporter's original 'Check for Extension Updates' attempt) never pull new commits for a git/git-subdir plugin source that still points at the same branch ref, so branch-tracked private plugins silently go stale.

## Best solution

In pluginInstallService.ts `updateAllPlugins`, stop gating GitHub/GitUrl-sourced plugins on `hasSourceChanged` when the source has no pinned `sha` (branch-tracking case) — always call `_pluginRepositoryService.updatePluginSource(...)` for those and let `AbstractGitPluginSource.update()` (which already does a real `git pull`/fetch+checkout and returns whether HEAD moved) decide whether anything changed; this also fixes the reporter's second finding that 'Update Plugins (Force)' doesn't help either, since `force` isn't consulted in that gate.
