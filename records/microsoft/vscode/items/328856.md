# Issue #328856 — Extensions: Check for Extension Updates does not update private git-subdir agent plugins

[https://github.com/microsoft/vscode/issues/328856](https://github.com/microsoft/vscode/issues/328856)

## Summary

Traced this to a real bug in the Agent Plugins update logic: `hasSourceChanged` gates whether a git-based plugin source (GitHub/GitUrl, which is what `git-subdir` maps to) is re-pulled, but for branch-tracked sources (a `ref` like `main` with no pinned `sha`), the source descriptor never changes even when new commits land — so the actual `git pull` is silently skipped. The report's command name ("Extensions: Check for Extension Updates") is a misnomer — that command doesn't touch Agent Plugins at all, the real one is `workbench.agentPlugins.checkForUpdates` ("Chat: Update Plugins") — but the underlying defect is genuine and confirmed in source, so this stays open under the right area.

## Change summary

Agent Plugins installed from a `git-subdir` (or plain git URL) source tracking a branch ref never get updated by the plugin update flow, even when the upstream branch and `plugin.json` version have moved on.

## Best solution

In `pluginInstallService.ts`'s `updateAllPlugins`, don't gate the per-plugin git update solely on `hasSourceChanged` for GitHub/GitUrl sources that track a `ref` without a pinned `sha` — always attempt `updatePluginSource` (which performs the real `fetch`/`pull` and reports whether HEAD moved) for those, since the whole point of ref-tracking is that upstream can change without the descriptor changing.
