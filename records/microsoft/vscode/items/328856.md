# Issue #328856 — Extensions: Check for Extension Updates does not update private git-subdir agent plugins

[https://github.com/microsoft/vscode/issues/328856](https://github.com/microsoft/vscode/issues/328856)

## Summary

Traced a real, confirmed gap in the agent-plugin update path: for git-tracked (branch, non-sha-pinned) sources such as `git-subdir`, `updateAllPlugins` only re-clones/pulls a plugin when `hasSourceChanged()` reports the descriptor itself changed (ref/sha/path), but that comparison can't detect new commits pushed to an already-tracked branch, so the underlying git pull is silently skipped even when the marketplace catalog and plugin.json version have both moved forward.

## Change summary

Running the agent-plugin update flow does not pull new commits for an installed `git-subdir` plugin when only the tracked branch's content changed (ref/path unchanged), leaving the plugin stuck on a stale commit despite a bumped `plugin.json` version.

## Best solution

In `PluginInstallService.updateAllPlugins` (src/vs/workbench/contrib/chat/browser/pluginInstallService.ts, ~line 445), stop gating the per-plugin update solely on `hasSourceChanged` for GitHub/GitUrl (including `git-subdir`) kinds; also attempt the pull whenever the source isn't pinned to a full commit SHA, so branch-tracked sources are always checked against upstream (mirroring what `AbstractGitPluginSource.update()` already does correctly once invoked).
