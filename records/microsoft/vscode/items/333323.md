# Issue #333323 — Moving Chat editor to a new window fails with "Not allowed to create elements in child window JavaScript context"

[https://github.com/microsoft/vscode/issues/333323](https://github.com/microsoft/vscode/issues/333323)

## Summary

Confirmed on current main: ChatPetWidgetCoordinator.createDormantHost() in chatPetWidgetService.ts builds the parked host's container with the ambient `dom.$('div')` (bare `document.createElement`), which resolves to whatever window realm is executing — the auxiliary window's own document when a chat host is first activated there. Auxiliary windows patch `document.createElement` to always throw (auxiliaryWindowService.ts:413-418), producing exactly the reported error.

## Change summary

Dragging a Chat editor tab out into a new auxiliary window throws "Not allowed to create elements in child window JavaScript context" and fails to open, unlike regular file editors.

## Best solution

In src/vs/workbench/contrib/chat/browser/widget/chatPetWidgetService.ts, have createDormantHost() build its placeholder `parent` div via `mainWindow.document.createElement('div')` (importing `mainWindow` from base/browser/window.js) instead of the ambient `dom.$('div')`, matching the pattern used everywhere else in the codebase (e.g. chatPetAccessoryRig.fixture.ts, screenshotAnnotation.ts) for guaranteed main-realm element creation.
