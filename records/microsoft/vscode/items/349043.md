# Issue #349043 — Extension install: HTTP error on the VSIX asset is not surfaced; error body is saved as the VSIX and only a generic failure is shown

[https://github.com/microsoft/vscode/issues/349043](https://github.com/microsoft/vscode/issues/349043)

## Summary

The reported failure path is confirmed in current source: an unsuccessful fallback response is written as an archive, losing the HTTP failure and potentially producing a false download-success notification. Keep open for a bounded fix covering asset validation, retry classification, and error presentation.

## Change summary

Reject unsuccessful VSIX and signature-archive responses while preserving actionable HTTP diagnostics and avoiding retries of non-retryable refusals.

## Best solution

Extension downloads should distinguish HTTP refusals from transport and archive failures, never save an HTTP error response as a successful download, and expose the status to the user. Preserve working CDN fallback and transient-failure recovery.
