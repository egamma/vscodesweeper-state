# Issue #142796 — Task that runs on folderOpen also always opens new terminal

## Summary

Keep open: maintainers confirmed the extra non-task shell, and a recent extensions-disabled reproduction confirms it persists. Current source still allows restored terminal-view initialization to create a shell before automatic tasks start; the hide-on-startup setting is a workaround, not a default-behavior fix.

## Change summary

Reopening a workspace with a folderOpen task and a previously visible terminal panel creates an unwanted ordinary shell alongside the task terminal.

## Best solution

Coordinate terminal startup and automatic-task initialization so reopening this workspace produces only the expected task terminal, while preserving legitimate persistent sessions and explicit terminal creation. Address the related hide-on-startup flashing separately without treating it as a replacement for this report.
