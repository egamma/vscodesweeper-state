# Issue #142796 — Task that runs on folderOpen also always opens new terminal

[https://github.com/microsoft/vscode/issues/142796](https://github.com/microsoft/vscode/issues/142796)

## Summary

Keep open: maintainers confirmed the unwanted extra shell, and an August 2026 reproduction with extensions disabled confirms it persists. Current source retains the independent terminal-view initialization and automatic-task startup paths; the newer panel-flash report covers a different symptom of the workaround.

## Change summary

Reopening a workspace with a folderOpen task and a previously visible terminal panel creates an unwanted ordinary shell alongside the task terminal.

## Best solution

Coordinate terminal-view startup with automatic-task startup so restoring the task's panel does not create an unrelated shell. Preserve genuine persistent sessions, explicit terminal creation, task permissions, and the normal no-task startup behavior.

## Evidence

- **Confirmed reproduction:** https://github.com/microsoft/vscode/issues/142796#issuecomment-5460282891 reports reproduction in VS Code 1.135.0 on macOS 14.6.1 with extensions disabled. Reopening the supplied workspace after closing its window with the task terminal visible creates an empty shell and the dedicated task terminal; hiding the panel before closing avoids it.
- **Discussion resolves the reported symptom:** https://github.com/microsoft/vscode/issues/142796#issuecomment-1524255534 distinguishes the unwanted shell from duplicate task execution: restoring the visible terminal panel starts a shell before automatic tasks launch. Maintainers independently reproduced the problem in the supplied discussion, and the issue was reopened after the November 2023 resolution claim.
- **Current terminal initialization:** src/vs/workbench/contrib/terminal/browser/terminalView.ts, TerminalViewPane._initializeTerminal, creates a default panel terminal when the view is visible, the terminal service is connected, no groups exist, and hideOnStartup is 'never'. Visibility and connection-state listeners invoke this path; it does not wait for pending folderOpen tasks.
- **Independent automatic-task startup:** src/vs/workbench/contrib/tasks/browser/runAutomaticTasks.ts, RunAutomaticTasks._tryRunTasks, separately waits for task reconnection and task-system information, discovers folderOpen tasks, and checks permission before running them. src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts maintains task-specific terminal reuse and creates a terminal with task launch configuration when needed.
- **Existing setting is a workaround:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:571-580 registers terminal.integrated.hideOnStartup with default 'never'. Setting it to 'always' suppresses the extra shell according to the latest reproduction, but changes startup visibility and has a separately reported panel-flash problem; it does not establish that the default startup defect is fixed.

It was created in August 2026 and concerns the panel showing, hiding, and showing again with hideOnStartup='always', rather than an extra shell under default settings. It is newer and symptomatically distinct, so it fails both requirements for closing this re-reviewed issue as its duplicate.
