# Issue #325742 — Hook-denied (PreToolUse deny) tool calls are invisible in the chat UI — add a way to surface them

[https://github.com/microsoft/vscode/issues/325742](https://github.com/microsoft/vscode/issues/325742)

## Summary

The visibility gap remains on current main and a maintainer confirmed the shared presentation blind spot. Hook-denied invocations are deliberately marked hidden even though their cancelled state already contains a localized denial reason suitable for the chat UI.

## Change summary

Surface PreToolUse-denied tool calls and their permission reason in chat instead of making the invocation completely invisible.

## Best solution

Show a compact, accessible cancelled-tool entry containing the tool identity and hook denial reason, while preserving the existing behavior that prevents execution. Coordinate the presentation rule with the related forced-confirmation case so hook-generated user feedback cannot be suppressed by a tool's hidden presentation.

- **Trace:**
