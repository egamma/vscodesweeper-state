# Issue #337226 — serve-web: blank page when an edge proxy rewrites inline scripts (CSP nonce regression vs 1.130.0)

[https://github.com/microsoft/vscode/issues/337226](https://github.com/microsoft/vscode/issues/337226)

## Summary

The reporter's actual ask — 'surface an actionable error instead of a silent blank page' — is now implemented on main: a startup-fallback UI was merged that shows an error message when the bootstrap scripts never run (e.g. blocked/rewritten by a proxy). The underlying CSP/nonce hardening itself is confirmed intentional by a maintainer and the reporter explicitly isn't contesting it.

## Change summary

code serve-web shows a permanently blank page with no diagnostic when an edge proxy (e.g. Cloudflare Rocket Loader) rewrites the bootstrap inline scripts, because the per-request CSP nonce/hash regression from commit 90c5812 blocks them silently.

## Best solution

Keep the shipped fix — commit 4e7c9de2c (PR #338474) adds a 10s-delayed fallback message ('The editor failed to load... Check the browser developer tools console for Content Security Policy errors.') that now appears whenever the bootstrap script is blocked or rewritten, directly answering 'possible improvement #1' in the report. The CSP/nonce behavior itself stays as designed per aeschli's comment (security fix, no reinstating the static nonce); optional docs coverage for proxy incompatibility (improvement #2) can be tracked separately if wanted.
