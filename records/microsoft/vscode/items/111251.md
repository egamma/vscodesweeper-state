# Issue #111251 — Change rulers on Editor via extension API

[https://github.com/microsoft/vscode/issues/111251](https://github.com/microsoft/vscode/issues/111251)

## Summary

A real extension API gap remains on current main, and this Backlog request has 110 community upvotes. It is already correctly routed to the API/editor API areas.

## Change summary

Allow extensions to set rulers for an individual text editor, enabling tools such as EditorConfig to visualize file-specific maximum line lengths.

## Best solution

Design a composable per-editor ruler API that preserves user-configured rulers and avoids extensions overwriting one another. The earlier implementation attempt in https://github.com/microsoft/vscode/pull/124879 is closed and should inform a replacement API proposal.

- **Evidence:** The public roadmap states that “The power lives in extensions”; its extension-ecosystem theme also supports API hygiene and enabling extensions without bundling specialized behavior into core.

## Evidence

- **current API:** src/vscode-dts/vscode.d.ts defines TextEditorOptions with tabSize, indentSize, insertSpaces, cursorStyle, and lineNumbers, but no rulers option.
- **API bridge:** src/vs/workbench/api/common/extHost.protocol.ts likewise exposes no rulers field in ITextEditorConfigurationUpdate or IResolvedTextEditorConfiguration.
- **prior implementation:** https://github.com/microsoft/vscode/pull/124879 explicitly proposed fixing this issue, but it was closed without merging on 2024-07-15; discussion identified unresolved composition conflicts between extensions.
- **dependent extensions:** Open requests in https://github.com/editorconfig/editorconfig-vscode/issues/272 and https://github.com/microsoft/vscode-eslint/issues/1597 remain blocked on an extension API for file-specific rulers.
