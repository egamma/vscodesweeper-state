# Issue #111251 — Change rulers on Editor via extension API

[https://github.com/microsoft/vscode/issues/111251](https://github.com/microsoft/vscode/issues/111251)

## Summary

The per-editor ruler API remains missing: existing configuration updates change persisted settings rather than a particular editor's options. Keep this accepted, well-supported request open; the earlier implementation PR closed without merging, and extension-composition semantics still need an API decision.

## Change summary

Allow extensions such as EditorConfig to set a particular editor's rulers from per-file max_line_length values.

## Best solution

Provide a supported per-editor ruler API that does not require rewriting user or workspace settings. Settle how extension-provided rulers interact with configured rulers and other extensions before revisiting the earlier implementation.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTextEditor.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadEditor.ts`, `src/vs/workbench/api/test/browser/extHostTextEditor.test.ts`
- **Validation:** Extend the ExtHostTextEditorOptions tests to verify the chosen ruler contract and RPC payload. In an extension-host check, open two same-language files with different max_line_length values, apply distinct rulers, and verify editor isolation, unchanged persisted settings, and the agreed behavior when another extension contributes or the override ends.
- **Behavior:**

  > An extension can control rulers for a particular text editor so files with different EditorConfig max_line_length values display the corresponding column guides. Applying this behavior must not require changing persisted user or workspace settings or unintentionally alter another editor. Acceptance checks should cover two same-language editors with different ruler values and the agreed interactions with user settings, competing extensions and override removal.
- **Trace:**

  > The editor already supports ruler rendering and the editor.rulers configuration in src/vs/editor/common/config/editorOptions.ts, but TextEditorOptions, ExtHostTextEditorOptions and the editor-configuration RPC interfaces expose no ruler property. Existing WorkspaceConfiguration.update writes configuration rather than providing an editor-local override. The relevant main-thread endpoint is MainThreadTextEditor.setConfiguration in src/vs/workbench/api/browser/mainThreadEditor.ts; the existing ExtHostTextEditorOptions test suite exercises option-update RPC payloads. https://github.com/microsoft/vscode/pull/124879 attempted this exact capability but closed unmerged, with unresolved discussion about multiple extensions replacing ruler values. Keep the scope on the extension API and editor-local behavior, not built-in EditorConfig parsing or the separate decoration-offset request at https://github.com/microsoft/vscode/issues/164670.
- **Open decisions:**
  - Should an extension's per-editor rulers replace configured rulers, or contribute alongside user settings and other extensions' rulers?
  - What is the override lifetime, and how should clearing it or deactivating its owning extension restore the effective rulers?

## Evidence
