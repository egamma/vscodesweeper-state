# Issue #346547 — Debugger does not auto-select source-less stopped frame unless stop reason enables instruction-pointer selection

[https://github.com/microsoft/vscode/issues/346547](https://github.com/microsoft/vscode/issues/346547)

## Summary

The source-less frame selection failure remains traceable in current main: ordinary stop reasons yield no focused frame despite a valid instruction pointer. Keep this open; automatic disassembly opening is a separate policy decision.

## Change summary

Select a valid source-less stopped frame without requiring the adapter to misreport an instruction breakpoint.

## Best solution

Make stopped-frame debug context available while retaining the accurate stop reason and existing source-frame preferences. Decide separately whether a source-less stop should automatically open disassembly when supported and editor focus is requested.
