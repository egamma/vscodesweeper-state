# Issue #346547 — Debugger does not auto-select source-less stopped frame unless stop reason enables instruction-pointer selection

[https://github.com/microsoft/vscode/issues/346547](https://github.com/microsoft/vscode/issues/346547)

## Summary

The source-less frame selection gap remains in current main and should reach the debug area owner. Automatic disassembly opening is a separate observable policy choice that should be settled before expanding editor behavior.

## Change summary

Select a stopped frame with an instruction pointer even when source is unavailable, without requiring an inaccurate instruction-breakpoint stop reason.

## Best solution

Allow accurate stop reasons to retain a usable selected frame while preserving existing source-frame preferences and focus hints. Decide separately whether ordinary source-less stops should automatically open disassembly.

## Evidence

- **Current selection restriction:** src/vs/workbench/contrib/debug/common/debugModel.ts: Thread.getTopStackFrame() accepts instruction-pointer-only frames for instruction breakpoints or instruction stepping; otherwise it requires available source. For the supplied single-frame stack, ordinary stopped, pause, entry, and breakpoint reasons return undefined.
- **Automatic focus path:** src/vs/workbench/contrib/debug/browser/debugSession.ts: handleStop() refreshes the stack and calls focusStackFrame(undefined, thread, ...). In debugService.ts, getStackFrameThreadAndSessionToFocus() delegates to thread.getTopStackFrame(), and focusStackFrame() passes that result to viewModel.setFocus(). Thus the reported frame remains unselected on this path.
- **Separate editor policy:** src/vs/workbench/contrib/debug/common/debugModel.ts: StackFrame.openInEditor() automatically opens disassembly only for instruction breakpoints, instruction stepping, or an already-active disassembly editor. Selecting a source-less frame and automatically opening an editor are distinct behaviors.
- **Accurate stop explanation:** Thread.stateLabel in debugModel.ts uses stoppedDetails.description or stoppedDetails.reason. Sending an instruction-breakpoint reason as a focus workaround therefore changes the displayed explanation, as described in https://github.com/microsoft/vscode/issues/346547.
