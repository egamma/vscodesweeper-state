# Issue #332619 — Gesture handler never releases touches cancelled by touchcancel

[https://github.com/microsoft/vscode/issues/332619](https://github.com/microsoft/vscode/issues/332619)

## Summary

Confirmed in source: Gesture only listens for touchstart/touchmove/touchend, never touchcancel, so cancelled touches leak in activeTouches and can wedge single-finger inertia scrolling. An open PR (#332629) already fixes this, so the right move is reviewing/landing that PR rather than closing the issue.

## Change summary

The touch Gesture handler in src/vs/base/browser/touch.ts never listens for touchcancel, so touches cancelled by the browser (system gestures, palm rejection) are never removed from activeTouches, leaking DOM references and eventually breaking single-finger inertia scrolling.

## Best solution

Land the linked PR https://github.com/microsoft/vscode/pull/332629 ("Touch: forget cancelled touches in the gesture handler"), which should add a touchcancel listener that clears the corresponding activeTouches entry without dispatching Tap/Contextmenu/inertia — mirroring the cleanup in onTouchEnd but silent.
