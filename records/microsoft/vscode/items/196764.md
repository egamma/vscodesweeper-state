# Issue #196764 — allow configuring the ghost text style

[https://github.com/microsoft/vscode/issues/196764](https://github.com/microsoft/vscode/issues/196764)

## Summary

Keep open: existing font-family and color customization only partially cover this accessibility request; ghost-text italics remain hardcoded. This team-authored issue has neither a verified open canonical nor an explicitly linked fix that would justify closing it.

## Change summary

Allow users to customize ghost-text styling so suggestions remain readable and distinguishable from actual source code.

## Best solution

Agree on a supported ghost-text font-style customization contract in the editor inline-completions area, retaining the existing default and reusing existing color controls. Define how that customization interacts with syntax-highlighted suggestions and suggestion previews before implementation.

- **Validation:** After agreeing on the contract, run a browser check with single-line and multiline inline completions and suggestion previews: the selected style must apply consistently, resetting it must restore the current default, and accepted source text must remain unaffected. Repeat with syntax highlighting enabled and disabled and with light, dark, and high-contrast themes.
- **Behavior:**

  > Users need a supported way to make ghost text readable and visually distinguishable from actual source code, beyond the existing font-family and color controls. Current ghost text is italic without a dedicated font-style setting. The agreed customization should affect pending suggestions without altering accepted source text, preserve the current default when unset, and behave consistently for single-line and multiline suggestions. Acceptance must cover syntax-highlighted suggestions and suggestion previews as defined by the maintainer-approved contract.
- **Trace:**

  > IInlineSuggestOptions and InlineEditorSuggest in src/vs/editor/common/config/editorOptions.ts expose fontFamily and syntaxHighlightingEnabled but no font-style option. InlineSuggestionsView in src/vs/editor/contrib/inlineCompletions/browser/view/inlineSuggestionsView.ts observes fontFamily and applies it through a generated stylesheet. src/vs/editor/contrib/inlineCompletions/browser/view/ghostText/ghostTextView.css hardcodes italics for ghost-text decorations and suggestion-preview ghost text; GhostTextView in the adjacent ghostTextView.ts constructs tokenized suggestion content when syntax highlighting is enabled. Existing editorGhostText color tokens already cover foreground, background, and borders, so color customization is not wholly missing. Keep suggestion generation, acceptance behavior, and ordinary source-text styling outside this work. The remaining uncertainty is the supported user-facing styling scope, not whether the hardcoded rule exists; the private audit's detailed requirements were unavailable. Related font-family work is https://github.com/microsoft/vscode/issues/201307, and the later accessibility request is https://github.com/microsoft/vscode/issues/246248.
- **Open decisions:**
  - Should the supported capability be limited to selecting normal versus italic ghost text, or expose additional font-style choices?
  - Should the chosen style override syntax-token font styling and apply equally to inline completions and suggestion previews?
