# Issue #57225 — Feature Request: Hotkey Support for QuickInputButton

[https://github.com/microsoft/vscode/issues/57225](https://github.com/microsoft/vscode/issues/57225)

## Summary

Keep open: customizable quick-input navigation shortcuts do not provide hotkeys for arbitrary QuickInputButtons. A maintainer explicitly identified this issue as the remaining button-shortcut work after completing the related navigation changes.

## Change summary

Allow extension-defined quick-input buttons to have user-customizable shortcuts active while their InputBox or QuickPick is shown.

## Best solution

Define a supported button-to-keybinding contract for extension-created quick inputs, preserving existing button events and keyboard navigation. Decide how users identify and rebind individual button actions, including whether the contract also covers QuickPick item buttons.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputActions.ts`, `src/vs/platform/quickinput/browser/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/quickInputUtils.ts`, `src/vs/workbench/api/common/extHostQuickOpen.ts`, `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`
- **Validation:** After the API contract is agreed, exercise an extension-created InputBox and QuickPick with two custom buttons: invoke each through its assigned shortcut, rebind one in Keyboard Shortcuts, and verify that only the intended action occurs while that input is active. Check hiding, disposal, and switching to another quick input, and preserve Tab activation and predefined Back behavior. Add corresponding event-dispatch and lifecycle coverage to the quick-input and extension-host quick-input suites.
- **Behavior:**

  > Extension authors want direct keyboard shortcuts for custom buttons in multi-step InputBox and QuickPick workflows, with user overrides through the normal keybinding system. Activating a shortcut should perform the same button action as keyboard or mouse activation and must not target a hidden or unrelated quick input. Acceptance includes independent shortcuts for multiple buttons, user rebinding, and unchanged existing navigation and Back behavior. The later request for shortcuts on item-level remove buttons requires an explicit scope decision.
- **Trace:**

  > QuickInputButton in src/vscode-dts/vscode.d.ts has no command or shortcut identity, and ExtHostQuickOpen transfers visual metadata and session-local handles through the main-thread bridge. QuickInput builds local button actions through quickInputButtonsToActionArrays in src/vs/platform/quickinput/browser/quickInputUtils.ts and fires onDidTriggerButton when those actions run. The existing quickInput commands in src/vs/platform/quickinput/browser/quickInputActions.ts operate on navigation and input state, while workbench.action.quickInputBack dispatches only the predefined Back button. These paths establish the missing capability, but do not settle a public identity or rebinding contract. Preserve existing input navigation, button events, and focus behavior; the closed navigation issue https://github.com/microsoft/vscode/issues/98479 explicitly identifies https://github.com/microsoft/vscode/issues/57225 as separate remaining work.
- **Open decisions:**
  - What stable public identity should users bind to: an extension command associated with a button, or a quick-input button identifier targeted by a built-in command?
  - Should the initial contract cover only InputBox and QuickPick widget buttons, or also QuickPick item buttons; if item buttons are included, which item does a shortcut target?

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.d.ts:13355-13385 defines QuickInputButton with iconPath, tooltip, location, and toggle, but no shortcut or command association. QuickPick and InputBox expose onDidTriggerButton, not a public method for invoking an arbitrary button through a keybinding.
- **Existing commands provide partial coverage:** src/vs/platform/quickinput/browser/quickInputActions.ts registers navigation, acceptance, hiding, checkbox, and hover commands, but no arbitrary-button invocation command. workbench.action.quickInputBack in src/vs/workbench/browser/actions/quickAccessActions.ts:111-122 invokes QuickInputController.back(), which specifically fires the predefined back button in src/vs/platform/quickinput/browser/quickInputController.ts:963-965.
- **Button actions lack stable keybinding identity:** src/vs/platform/quickinput/browser/quickInputUtils.ts constructs local actions using positional IDs such as left-button-0. src/vs/platform/quickinput/browser/quickInput.ts connects these actions to onDidTriggerButton, while src/vs/workbench/api/common/extHostQuickOpen.ts transfers button metadata and session-local handles without a command or shortcut association.
- **Related issue explicitly leaves this work here:** https://github.com/microsoft/vscode/issues/98479 is closed and concerns overriding existing hardcoded navigation shortcuts. In https://github.com/microsoft/vscode/issues/98479#issuecomment-3276794791, a maintainer states that those shortcuts are now overridable but that shortcuts for remove/delete buttons belong to https://github.com/microsoft/vscode/issues/57225. Its completion is therefore not evidence that this request was implemented.
- **Discussion distinguishes accessibility from direct shortcuts:** The supplied discussion confirms that title buttons can be reached with Tab, but also requests right-arrow events and keyboard activation of an item's remove button. Tab accessibility does not satisfy the original request for direct, user-customizable button shortcuts.
