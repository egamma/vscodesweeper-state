# Issue #323102 — Copilot Chat: agent request crashes with "Cannot read properties of undefined (reading 'type')" in countToolTokens when a tool input schema uses top-level JSON-Schema if/then (BYOK / custom model)

[https://github.com/microsoft/vscode/issues/323102](https://github.com/microsoft/vscode/issues/323102)

## Summary

Still present on main: BPETokenizer.countMessageObjectTokens (used for BYOK endpoints) misinterprets JSON Schema objects as chat message content parts, and tokenLength has no null guard — any MCP tool with an unusual schema structure can crash the token counter before the request is sent. No fix has been applied.

## Change summary

Agent-mode requests crash with a TypeError in countToolTokens when an MCP tool's input schema contains top-level if/then keywords and a BYOK custom model is selected.

## Best solution

Make BPETokenizer.countObjectTokens / countMessageObjectTokens robust against arbitrary object shapes by removing the chat-message-specific type checks (casted.type === 'text' / 'image_url') from the JSON Schema walking path, or add a null guard in tokenLength. The sibling ExtensionContributedChatTokenizer._countObjectTokens in extChatTokenizer.ts already handles this correctly and could serve as a model. Additionally, consider running tool schema normalization before token counting so stripped keywords don't reach the tokenizer at all.
