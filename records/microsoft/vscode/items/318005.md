# Issue #318005 — Customizations loader doesn't validate path or available file system provider

[https://github.com/microsoft/vscode/issues/318005](https://github.com/microsoft/vscode/issues/318005)

## Summary

The defect remains source-reproducible on main: restored Copilot sessions without repository metadata expose an `unknown:///` workspace, while customization discovery attempts several filesystem-backed loads and logs each failure separately. No issue-linked fix or open fixing PR was found, so this team-authored issue should remain open.

## Change summary

Avoid loading workspace customizations when a restored session has an unknown workspace or a workspace URI whose scheme has no filesystem provider.

## Best solution

Treat unsupported session workspace URIs as unavailable before customization enumeration, while preserving user-level customization discovery and all behavior for workspace schemes with registered providers.
