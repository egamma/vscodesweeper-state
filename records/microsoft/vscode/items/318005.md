# Issue #318005 — Customizations loader doesn't validate path or available file system provider

[https://github.com/microsoft/vscode/issues/318005](https://github.com/microsoft/vscode/issues/318005)

## Summary

Team-authored bug report about missing validation in the customizations loader when the workspace scheme is 'unknown' or has no matching file system provider. No fix has been committed referencing this issue; the defect appears to remain on current main.

## Change summary

Opening an old session in the agents window with an 'unknown' workspace scheme triggers errors because the customizations loader attempts file system operations without first checking whether the scheme has a registered file system provider.

## Best solution

Add a guard in the customizations/prompts loading path to skip discovery when the workspace URI scheme has no registered file system provider or when the workspace is 'unknown'. The fix likely touches the prompts service folder resolution (src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts) or the agent host customization content expander (which already has a partial `canHandleResource` guard in agentCustomizationContentExpander.ts).
