# Issue #275529 — Enable option to set sort order of projects in "Window" menu

[https://github.com/microsoft/vscode/issues/275529](https://github.com/microsoft/vscode/issues/275529)

## Summary

Keep this accepted Backlog request open: current source exposes no independent Window-menu ordering option, and no older open canonical was found. Title customization offers a workaround, but does not provide the requested sorting control or creation-order mode.

## Change summary

Allow open project windows to be ordered by project name or opening order instead of their changing active-file titles.

## Best solution

Provide stable, opt-in ordering for the macOS Window menu while preserving existing title customization and default behavior. First establish which ordering modes to support and how they can coexist with the native window-list behavior.

## Plan brief

- **Likely files:** `src/vs/platform/menubar/electron-main/menubar.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/parts/titlebar/windowTitle.ts`
- **Validation:** On macOS, open distinct projects Zeta, Alpha, and Beta in that order. With project-name ordering selected, verify Alpha, Beta, Zeta remains unchanged when switching active files and dirtying or saving editors. If opening-order mode is included, verify Zeta, Alpha, Beta remains unchanged under those same actions. Verify selecting each menu entry focuses the correct window and the default mode retains existing behavior.
- **Behavior:**

  > The native macOS Window menu currently lists project windows by titles that change with the active editor, making their positions unpredictable. Users should be able to select stable project-name ordering; the report also requests opening-order sorting as an alternative. Changing the active file or its dirty state must not reorder distinct projects in a stable-order mode. Existing window titles and default menu behavior should remain unchanged unless the user opts in.
- **Trace:**

  > The macOS menu is created in src/vs/platform/menubar/electron-main/menubar.ts with Electron role 'window'; setMacWindowMenu() appends standard actions, not a VS Code-owned enumeration of window entries. That establishes the native-menu boundary but does not establish whether Electron exposes the necessary independent ordering control. window.title is registered in src/vs/workbench/browser/workbench.contribution.ts, and WindowTitle.getWindowTitle() in src/vs/workbench/browser/parts/titlebar/windowTitle.ts supplies workspace-name variables, so workspace-first titles are an existing workaround rather than a separate sorting mode. Preserve title-template semantics, native window actions, and native-tab behavior. https://github.com/microsoft/vscode/issues/278170 was explicitly consolidated into this report; the older requests at https://github.com/microsoft/vscode/issues/65198 and https://github.com/microsoft/vscode/issues/134569 provide additional demand but no implementation proof.
- **Open decisions:**
  - Should the initial supported stable ordering include both project-name and opening-order modes, or project-name ordering only?
