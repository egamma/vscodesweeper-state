# Issue #134475 — WSL: process explorer does not show CPU usage properly in remote

[https://github.com/microsoft/vscode/issues/134475](https://github.com/microsoft/vscode/issues/134475)

## Summary

Keep open: the discussion independently confirms misleading remote CPU reporting in WSL, and current source still contains a plausible sampling discrepancy. The supplied reproduction is sufficient for a focused WSL retest; neither a concrete fix nor a verified canonical duplicate was found.

## Change summary

Process Explorer underreports CPU usage for remote WSL processes that Linux monitoring tools show consuming substantial CPU.

## Best solution

Make remote process CPU reporting reliably expose sustained busy processes, with clearly defined percentage semantics. Investigate the shared Linux sampler and compare matching PIDs over matching intervals before deciding whether the discrepancy is normalization, sampling, or WSL-specific accounting.

- **Trace:**

  > ProcessMainService.resolveProcesses() in src/vs/platform/process/electron-main/processMainService.ts requests remote process diagnostics, and getDiagnosticInfo in src/vs/server/node/remoteAgentEnvironmentImpl.ts invokes listProcesses(process.pid). The renderer in src/vs/workbench/contrib/processExplorer/browser/processExplorerControl.ts displays the resulting load without further normalization. - **Open decisions:**
