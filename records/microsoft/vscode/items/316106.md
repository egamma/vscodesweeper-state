# Issue #316106 — Agent defaults to partial scope execution on multi-file operations, producing incomplete migrations, regressions, and wasted compute time

[https://github.com/microsoft/vscode/issues/316106](https://github.com/microsoft/vscode/issues/316106)

## Summary

The central multi-file completeness defect remains possible on current main: standard Agent mode accepts a model's successful final response without independently checking that the requested scope was completed. The report should stay open, with its separate session-history concern split or consolidated into the session-persistence issue cluster.

## Change summary

Agent mode can complete only a subset of an explicitly requested multi-file migration and stop without discovering or verifying the full target set.

## Best solution

Establish a completion contract for multi-target Agent requests and evaluate it across supported models: all discoverable targets must be handled or explicitly reported as remaining before the turn completes. Keep the independent chat-session disappearance concern in the session-persistence issue cluster rather than coupling it to agent task completion.

## Plan brief

- **Validation:** Add a repeatable multi-file agent scenario with several discoverable occurrences of a migration pattern; assert every target is updated, a second search finds zero old occurrences, and the session cannot report completion while any target remains.
- **Behavior:**

  > When a user requests a migration across all matching files, Agent mode must discover the complete target set and either update every target or explicitly report any target it could not update. It must not present the task as complete while matching old constructs remain. Acceptance requires a repeatable multi-file scenario in which every seeded target is migrated and a post-operation search returns zero remaining matches.
- **Trace:**

  > The reported session changed only subsets of four Svelte files and then stopped, producing a concrete regression. On current main, extensions/copilot/src/extension/intents/node/toolCallingLoop.ts ends a standard Agent turn after a successful model response with no tool calls; the additional goal-completion check is restricted to Autopilot. The Anthropic and default prompts already instruct models to finish the full request, so prompt intent alone does not enforce the invariant. extensions/copilot/test/e2e/cli.stest.ts has a neighboring multi-file diagnostic scenario, but no coverage for workspace-wide target discovery and zero-remainder verification. Keep chat-session persistence outside this implementation boundary; it is a separate symptom related to https://github.com/microsoft/vscode/issues/309284.
- **Open decisions:**
  - Should standard Agent mode independently evaluate completion of explicit all-target requests, or should deterministic completion enforcement remain exclusive to Autopilot with standard Agent relying on model compliance?
