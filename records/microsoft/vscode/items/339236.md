# Issue #339236 — VS Code very slow to install on Windows arm64 due to x86 emulation on the installer

[https://github.com/microsoft/vscode/issues/339236](https://github.com/microsoft/vscode/issues/339236)

## Summary

Keep open: current main still lacks the requested x64 installer architecture, and an open PR explicitly addresses this issue. Review that implementation together with the compiler upgrade needed to activate it.

## Change summary

Build Windows x64 and arm64 installers as x64 executables to avoid slower x86 emulation on Windows on Arm.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/339238 together with adoption of an Inno Setup 7 compiler. Verify actual installation and upgrades on Windows arm64 and x64; the proposed version-guarded directive alone does not change output with the currently pinned compiler.

## Evidence

- **Current installer configuration:** build/win32/code.iss [Setup] specifies ArchitecturesAllowed and ArchitecturesInstallIn64BitMode but has no SetupArchitecture directive. These existing directives select supported installation architectures, not an x64 setup executable.
- **Compiler and adoption path:** package.json requests innosetup ^6.4.1, and package-lock.json resolves 6.4.1. build/gulpfile.vscode.win32.ts resolves that package's bin/ISCC.exe and invokes it from packageInnoSetup for the x64 and arm64 user/system setup builds.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/339238 is OPEN and unmerged. Its body references https://github.com/microsoft/vscode/issues/339236 and proposes SetupArchitecture=x64 guarded by an Inno Setup 7 version check. The author reports x64 output for all four architecture/target combinations with compiler 7.1.0, but unchanged x86 output with 6.4.1; end-to-end installation and upgrade checks remain outstanding.
- **Open compiler prerequisite:** Verified https://github.com/joaomoreno/node-innosetup-compiler/pull/1 is OPEN and unmerged. It proposes bundling Inno Setup 7.1.0 and explicitly links the VS Code issue and implementation PR. This supplies the compiler capability; VS Code still needs to adopt it and enable the setup directive.
- **Community process:** The October 5 comment places the request in the 60-day Backlog Candidates voting process. Its current zero upvotes do not justify ending that process early, and the linked open implementation PR independently requires keeping the issue open.
