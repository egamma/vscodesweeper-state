# Issue #334504 — [Remote-SSH / Auth] PendingMigrationError: navigator is now a global in nodejs during extension initialization

[https://github.com/microsoft/vscode/issues/334504](https://github.com/microsoft/vscode/issues/334504)

## Summary

This is a satellite of the older, broader tracking issue for the same root cause: VS Code's extension host intentionally traps global `navigator` access (added so extensions relying on Node's pre-v21 behavior get flagged), and various bundled/remote extensions (GitHub Authentication, Remote-SSH, Copilot Chat) haven't finished migrating away from touching it. https://github.com/microsoft/vscode/issues/252077 already tracks exactly this and is open, so consolidating there.

## Change summary

GitHub Authentication and Remote-SSH extensions throw PendingMigrationError for accessing the now-global `navigator` during extension-host startup over Remote-SSH, breaking Copilot/auth initialization.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/252077 (already labeled debt/remote/ssh) which tracks the same navigator-global compatibility issue; the real fix is in the affected extensions/dependencies (github-authentication, remote-ssh, copilot) migrating off touching `navigator`, not a change to the intentional core trap in extensionHostProcess.ts.
