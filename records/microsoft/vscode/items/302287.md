# Issue #302287 — McpResourceManagementService: race condition in initialize() — reads file before provider data is available

[https://github.com/microsoft/vscode/issues/302287](https://github.com/microsoft/vscode/issues/302287)

## Summary

The race remains in current main, but the open PR https://github.com/microsoft/vscode/pull/302295 directly addresses it and closes this issue. Keep the issue open while that human-owned fix is reviewed.

## Change summary

MCP workspace servers can fail to load in remote scenarios when initialization reads mcp.json before its file-system provider is registered.

## Evidence

- **current source:** In src/vs/platform/mcp/common/mcpManagementService.ts, AbstractMcpResourceManagementService.initialize() immediately calls populateLocalServers(), which invokes scanMcpServers() without first waiting for a provider for mcpResource.scheme.
- **user-visible trigger:** The reported trigger is opening a Remote SSH workspace while its custom-scheme provider is not yet registered; initialization reads the workspace mcp.json on that path, so configured MCP servers fail to load.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/302295 remains open, contains `Fixes #302287`, adds the missing whenProviderRegistered() wait, and adds a test that calls getInstalled() before registering a custom-scheme provider.
- **maintainer response:** https://github.com/microsoft/vscode/issues/302287#issuecomment-4085976603 asks for the user-facing symptom; the issue body identifies Remote SSH workspace MCP servers failing to load and supplies deterministic provider-registration steps.
