# Issue #134040 — `acceptSuggestionOnCommitCharacter` with ghost text

[https://github.com/microsoft/vscode/issues/134040](https://github.com/microsoft/vscode/issues/134040)

## Summary

Keep open: commit-character acceptance still inserts the selected completion rather than its full inline augmentation. This team-authored, accepted backlog request needs a product decision about combined acceptance; no verified older canonical or qualifying fix was found.

## Change summary

Consider accepting both the selected completion and its inline augmentation with a commit character, without inserting a duplicate trailing semicolon.

## Best solution

Decide whether commit characters should accept the full inline augmentation when the suggest widget is visible, and under what conditions. If adopted, preserve ordinary completion acceptance and ensure a trailing semicolon is inserted exactly once.

- **Behavior:**

  > With the suggest widget open and a selected completion that is a prefix of visible inline text, typing a commit character currently accepts only the selected completion. The requested capability is one-keystroke acceptance of that completion and its full inline augmentation. If combined acceptance is approved, a semicolon already supplied at the end of the augmentation must not be duplicated. Acceptance checks must also preserve ordinary completion behavior and respect disabled commit-character acceptance.
- **Trace:**

  > CommitCharacterController in src/vs/editor/contrib/suggest/browser/suggestCommitCharacters.ts reacts to onWillType and passes the selected item to SuggestController._insertSuggestion in src/vs/editor/contrib/suggest/browser/suggestController.ts. That method inserts the selected completion text. SuggestWidgetAdaptor forwards the insertion notification to InlineCompletionsModel.handleSuggestAccepted, which records partial acceptance of the augmentation rather than applying the remainder. The existing editor.acceptSuggestionOnCommitCharacter setting is a boolean, and the separate inline acceptance action does not make typing ';' accept both surfaces. The original scenario is documented in https://github.com/microsoft/vscode/issues/133907; the product question remains open in https://github.com/microsoft/vscode/issues/134040. Keep standalone inline acceptance, ordinary completion insertion, and unrelated inline-edit behavior outside this request. The Suggest Widget Model suite provides an existing keyboard-driven harness; no tests were executed in this read-only review.
- **Open decisions:**
  - When a selected completion has a visible inline augmentation, should commit characters accept the full augmentation by default, require an opt-in, or retain selected-completion-only behavior?
  - Should combined acceptance apply to every commit character declared by the selected completion, or only to statement-ending characters such as ';'?
