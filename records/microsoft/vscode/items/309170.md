# Issue #309170 — Provide an option to suppress GitHub access prompts from extensions

[https://github.com/microsoft/vscode/issues/309170](https://github.com/microsoft/vscode/issues/309170)

## Summary

Keep open as a feature request: VS Code already stores per-account extension access decisions, but those decisions do not provide persistent suppression of subsequent authentication prompts. The older Copilot report is related, not a canonical for this broader extension-wide permission-management request.

## Change summary

Provide a persistent, manageable per-extension denial of GitHub authentication requests without disabling GitHub authentication globally.

## Best solution

Extend the workbench authentication permission experience so users can suppress an extension's future GitHub access requests and later reverse that decision centrally, while leaving other extensions and GitHub accounts usable. Settle how this differs from existing account-specific access revocation before implementation.

## Evidence

- **Existing permission management:** src/vs/workbench/contrib/authentication/browser/actions/manageTrustedExtensionsForAccountAction.ts registers `_manageTrustedExtensionsForAccount`, also exposed through Accounts management. Its picker persists selected and deselected extensions through setAccessAllowed, but operates on existing accounts and recorded extension entries rather than providing a general prompt-suppression control.
- **Persistent denial is already partially supported:** src/vs/workbench/services/authentication/browser/authenticationAccessService.ts stores allowed:false in application storage keyed by provider and account. AuthenticationExtensionsService.showGetSessionPrompt also persists the Deny choice. These mechanisms deny account access, which is only part of the requested behavior.
- **Remaining prompt-suppression gap:** In src/vs/workbench/api/browser/mainThreadAuthentication.ts, doGetSession treats denied sessions as unavailable, then still invokes loginPrompt for createIfNone or forceNewSession. For nonsilent passive requests it still calls requestSessionAccess or requestNewSession; those methods in authenticationExtensionsService.ts create Accounts menu requests and badges without consulting a persistent suppression decision. loginPrompt offers Allow and cancellation, not a persistent denial option.
- **Related older issue is narrower:** https://github.com/microsoft/vscode/issues/277949 was verified open and was created on 2025-11-17. It concerns Copilot codebase search repeatedly requesting GitHub permissions despite Never Ask Again, including interrupted chat turns. Its discussion identifies a tool-specific authentication-upgrade path and disabling codebase search as a workaround. It does not own general per-extension GitHub denial and centralized permission management, so it does not satisfy the duplicate bar for this re-reviewed request.
- **Canonical search and demand:** Repository issue searches covering authentication denial, suppression, repeated prompts, and extension sign-in controls found no verified older canonical covering the full request. This issue has one upvote and no maintainer discussion; its age alone does not justify closing it.
