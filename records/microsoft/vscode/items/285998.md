The reporter subsequently confirmed that a process task invoking powershell.exe with 'npm run compile' works; manually executing the command does not establish that the original task launcher works.
- **Linked PowerShell report:** https://github.com/microsoft/vscode/issues/285729 is open and reports a specific Set-Location parameter-binding error involving -Command, with a shell-to-process workaround confirmed at https://github.com/microsoft/vscode/issues/285729#issuecomment-3709896187. This issue supplies no matching error or shell arguments, so a shared root cause is plausible but not verified.
- **Current shell launch path:** src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts:1220-1333 obtains the default profile with allowAutomationShell enabled, inherits its arguments, applies task shell overrides, and appends the command line. Windows powershell.exe/pwsh.exe normally receive -Command when no explicit shell executable is supplied. The report omits the profile and overrides needed to trace its effective invocation conclusively.
- **Waiting notification is not a diagnosis:** src/vs/workbench/contrib/debug/browser/debugTaskRunner.ts:258-318 runs the task and schedules the 'Waiting for preLaunchTask' notification after terminal acquisition. That notification establishes an unresolved task, not why its command failed to execute.
