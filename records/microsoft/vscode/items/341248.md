# Issue #341248 — Browser: openBrowserPage fails with 'Page not found' after choosing "Yes, share" on an existing tab; agent only sees 'Unknown error'

[https://github.com/microsoft/vscode/issues/341248](https://github.com/microsoft/vscode/issues/341248)

## Summary

Thanks for the detailed report. The source supports the first problem. `_shareExistingPage` calls `getSummary`, which does not wait for the newly shared page to be registered on the Playwright side. `_openNewPage` does wait, through `waitForPageAndGetSummary`. The second problem, the lost error text, is a separate gap with no merged fix.

## Change summary

After choosing 'Yes, share' on an existing tab, openBrowserPage fails with 'Page not found', and the agent only sees 'Unknown error'.

## Best solution

After sharing an existing tab, wait for Playwright page discovery before building the summary, as the open-new-page path does. Separately, make sure the client-tool error message reaches the agent instead of 'Unknown error'.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts`, `src/vs/platform/browserView/node/playwrightService.ts`
- **Validation:** A playwrightService test that shares an existing view and calls the summary path before the page is discovered; it should succeed rather than throw 'not found'. Otherwise follow the manual steps in the issue.
- **Behavior:**

  > After the user picks 'Yes, share' for an existing tab, openBrowserPage returns the page snapshot, matching the forceNew path. If a client tool fails, the agent receives the real error message instead of 'Unknown error'.
- **Trace:**

  > `_shareExistingPage` in openBrowserTool.ts calls `getSummary(sessionId, id)`, which maps to `PlaywrightSession._getSummary` and then `_getPage`. `_getPage` does not poll, unlike `_waitForPage`, which is used by `waitForPageAndGetSummary` in the open-new-page path. The change should stay on the share path and leave the open-new-page behavior alone. The error-propagation problem lives in the agent-host client-tool result handling, which I did not trace. The earlier attempt was PR 330709, closed without merging. Related: https://github.com/microsoft/vscode/issues/335378.

## Evidence

- **share path:** src/vs/workbench/contrib/browserView/electron-browser/tools/openBrowserTool.ts `_shareExistingPage` calls `playwrightService.getSummary` right after `setSharedWithAgent(true)`.
- **no wait:** src/vs/platform/browserView/node/playwrightService.ts `getSummary` goes straight to `_getSummary`, then `_getPage`, which throws `Page "id" not found` if the view isn't yet in `_viewIdToPage`. `waitForPageAndGetSummary` uses `_waitForPage`, which polls until the page is discovered. The open-new-page path uses that variant and the share path does not.
