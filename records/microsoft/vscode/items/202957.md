# Issue #202957 — Allow to move workspace state

[https://github.com/microsoft/vscode/issues/202957](https://github.com/microsoft/vscode/issues/202957)

## Summary

Keep open in the Backlog: this remains a real workspace-lifecycle gap and has 110 community upvotes. Current main still derives workspace storage identity from its path and provides no general relocation or relinking workflow.

## Change summary

Provide an official way to preserve or migrate workspace state when a workspace file or project folder moves.

## Best solution

Add an explicit move/relink workflow that transfers the old workspace-storage bucket to the new workspace identity while re-evaluating workspace trust. This likely belongs across the workspace editing, workspace identity, and storage services.

- **storage layout:** src/vs/platform/storage/electron-main/storageMain.ts stores state at workspaceStorageHome/<workspace.id>/state.vscdb and records the original folder or workspace URI in workspace.json; it contains no relocation or relinking path.
- **existing capability gap:** src/vs/workbench/services/workspaces/electron-browser/workspaceEditingService.ts migrates state only while entering another workspace in the active window; it does not recover state after an externally moved folder or workspace file.
