# Issue #281984 — Git - generate commit message in editor

[https://github.com/microsoft/vscode/issues/281984](https://github.com/microsoft/vscode/issues/281984)

## Summary

Keep open: the generation command still writes to the SCM input box, not the commit-message editor. This remains an accepted, team-authored feature request; neither the existing capability nor the related issues covers its central ask.

## Change summary

Support generating a commit message directly in the editor used to author a Git commit.

## Best solution

Make commit-message generation available within the Git commit editor, targeting its repository and document while preserving the existing SCM generation workflow. Settle how generated text interacts with an existing draft before implementation.

- **Validation:** In an extension-host check with deterministic generated text, enable git.useEditorAsCommitInput, stage a change, open the commit editor through Git: Commit All, and invoke generation. Verify the generated message reaches the correct commit document, follows the agreed existing-draft behavior, and leaves the editor open for review. Repeat with two repositories and verify existing SCM generation still targets the selected repository.
- **Behavior:**

  > Users authoring a Git commit in the full text editor can invoke commit-message generation and receive the result in that commit document rather than the SCM input box. Generation must target the repository associated with the commit editor and leave acceptance or cancellation of the commit under user control. Existing SCM generation must continue to work. Acceptance checks should cover an empty commit draft, an existing draft under the agreed insertion policy, and a workspace containing two repositories.
- **Trace:**

  > extensions/copilot/src/extension/conversation/vscode-node/conversationFeature.ts registers github.copilot.git.generateCommitMessage and always writes the returned text to repository.inputBox.value. GitCommitMessageServiceImpl in extensions/copilot/src/extension/prompt/vscode-node/gitCommitMessageServiceImpl.ts resolves a repository and generates from staged changes, falling back to working-tree changes; it has no commit-document output destination. extensions/copilot/package.json exposes the command in scm/inputBox, while GitEditor.handle in extensions/git/src/gitEditor.ts opens the commit-message document and waits for its tab to close. Commit-editor acceptance and discard are handled separately in extensions/git/src/commands.ts. The maintainer explicitly separated editor support from the fixed keybinding problem at https://github.com/microsoft/vscode/issues/204301#issuecomment-1946258307. Preserve SCM behavior, Git commit acceptance, templates, and repository isolation; the unresolved product contract is how generation treats an existing editor draft.
- **Open decisions:**
  - When the commit editor already contains a draft, should generation replace the authored message, insert at the current selection, or present a suggestion for explicit acceptance?
