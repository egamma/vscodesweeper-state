# Issue #253207 — Trigger Next Edit suggestion should take next error into account even if this is further away

[https://github.com/microsoft/vscode/issues/253207](https://github.com/microsoft/vscode/issues/253207)

## Summary

Keep open: existing extended-range and diagnostic-fix support does not establish that manually triggering NES targets the next distant error. The maintainer discussion suggests a fallback after an empty response, but that user-visible behavior still needs a decision; no qualifying fix or older canonical was established.

## Change summary

Make manually triggered next edit suggestions consider the next error even when it lies far from the cursor.

## Best solution

Define and deliver diagnostic-aware targeting for manually triggered NES in the inline-edits provider, preserving its general-purpose suggestions. Resolve whether distant errors are targeted immediately or only after the initial request returns no edit, as suggested in the discussion.
