# Issue #281045 — Built-in git blame editor decorations are not applied when diff editor is opened via third-party extension (e.g. Git Graph / GitLens)

[https://github.com/microsoft/vscode/issues/281045](https://github.com/microsoft/vscode/issues/281045)

## Summary

Built-in blame still excludes extension-provided diff resources on current main. Keep this accepted Git bug open while maintainers evaluate the existing fix PRs; none has merged.

## Change summary

Built-in blame decorations and status-bar information are missing when viewing historical diffs opened through Git Graph or GitLens.

## Evidence

- **Current-source exclusion:** In extensions/git/src/blame.ts, isResourceSchemeSupported accepts only file and git URIs. GitBlameController._updateTextEditorBlameInformation clears blame information and returns for other schemes, explaining absent annotations for extension-owned historical documents.
- **Additional historical-diff restrictions:** The same controller accepts git URI refs only when they are full 40-character hashes, HEAD, ~, or the empty index ref; other refs throw Unexpected ref. For file resources, extensions/git/src/staging.ts:getWorkingTreeDiffInformation requires an original git URI with ref ~ or an empty ref. Historical comparisons outside those cases therefore cannot follow the ordinary working-tree blame path.
- **Open implementation candidates:** GitHub reads confirmed that https://github.com/microsoft/vscode/pull/287965, https://github.com/microsoft/vscode/pull/305524, and https://github.com/microsoft/vscode/pull/338454 are OPEN with mergedAt null and each references this issue. Their proposed approaches differ: diff-information handling, scheme acceptance, and arbitrary git refs respectively. These are candidates for review, not evidence of a completed fix.
- **Closed PR did not land:** https://github.com/microsoft/vscode/pull/306050 is CLOSED with mergedAt null. Its proposed custom-scheme and revision parsing changes cannot establish implementation on main.

The missing behavior is in the built-in Git blame controller; opening the editor through a third-party extension alone does not justify a caused-by-extension close.
