# Issue #174616 — Allow adjusting search text box width in title bar to accommodate long path and file names.

[https://github.com/microsoft/vscode/issues/174616](https://github.com/microsoft/vscode/issues/174616)

## Summary

The requested Command Center width control remains absent on current main, and this accepted Backlog request has 69 community upvotes. Older related issues concern either the separate quick-input popup or making the Command Center narrower, so neither clears the re-review duplicate bar.

## Change summary

Allow users to widen the title-bar Command Center so long custom window titles and file paths remain visible.

## Best solution

Provide a responsive, user-adjustable Command Center width that can expose long custom window titles without crowding menus, layout controls, or window controls at narrower window sizes. A maintainer should first choose whether adjustment is exposed through direct resizing, a setting, or both, and define how the selected width persists.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts`, `src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css`, `src/vs/workbench/browser/workbench.contribution.ts`
- **Validation:** Validate in a Code OSS window with a custom `window.title` containing `${activeEditorLong}`: increase the Command Center width and confirm the longer title becomes visible, the choice survives according to the selected persistence contract, and narrow-window layouts still preserve menus, layout controls, and window controls.
- **Behavior:**

  > Users with a long custom `window.title` can increase the title-bar Command Center width enough to read more of the active file path. The chosen behavior remains responsive: at narrow window widths, essential title-bar and window controls remain usable without overlap. Existing default sizing remains unchanged for users who do not adjust it. Acceptance includes both a wide-window long-path case and a constrained-window layout case.
- **Trace:**

  > CommandCenterControl in src/vs/workbench/browser/parts/titlebar/commandCenterControl.ts places `WindowTitle.getWindowTitle()` into `.search-label` when a custom title format is active. src/vs/workbench/browser/parts/titlebar/media/titlebarpart.css constrains the containing `.command-center-center` to `38vw` and at most `600px`, then ellipsizes the label. src/vs/workbench/browser/workbench.contribution.ts exposes only the boolean `window.commandCenter` setting. Preserve default sizing and the responsive title-bar behavior tracked by https://github.com/microsoft/vscode/issues/156377 and https://github.com/microsoft/vscode/issues/236302; do not broaden this into resizing the separate quick-input popup tracked by https://github.com/microsoft/vscode/issues/85374.
- **Open decisions:**
  - Should users adjust the width through direct drag resizing, an explicit setting, or both?
  - Should an adjusted width persist globally, per profile, per workspace, or only for the current window session?
  - Should persisted sizing use an absolute width, a percentage of the window, or a bounded responsive value?

## Evidence
