# Issue #277097 — Show widget when there is new entry in Copilot model list

[https://github.com/microsoft/vscode/issues/277097](https://github.com/microsoft/vscode/issues/277097)

## Summary

This remains an accepted Backlog feature request with explicit maintainer interest, and current main still lacks new-model tracking or badges. The newer related issue covers only the model-picker-visible subset and cannot be the canonical duplicate for this re-reviewed, older, broader request.

## Change summary

Surface an accessible, dismissible indicator when a newly available Copilot model is not visible in the normal picker, including models disabled by enterprise policy.

## Best solution

Consolidate the model-awareness design around this older issue, covering both visible new models and models hidden by policy, then settle the indicator location, definition of "new," and dismissal lifetime before implementation. Coordinate the narrower picker-row work in https://github.com/microsoft/vscode/issues/298198 with that design rather than closing this broader item.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItems.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerItemSections.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerBadges.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatAccessibilityHelp.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/input/modelPicker/modelPickerItems.test.ts`
- **Validation:** Add model-picker tests that introduce a Copilot model after an initial catalog snapshot and verify the chosen accessible indicator appears for both visible and enterprise-disabled cases, is announced through the accessibility provider, and disappears only at the selected dismissal point without reappearing after the agreed persistence boundary.
- **Behavior:**

  > When VS Code learns about a newly available Copilot model, users receive a restrained and accessible indication even if enterprise policy prevents that model from appearing as selectable. The indicator identifies the relevant new model when the chosen surface permits it and does not mark BYOK catalog churn as new. It clears according to one documented interaction and persistence rule, does not appear for a first-time user merely because every model is initially unknown, and does not conflict with other chat tips.
- **Trace:**

  > ModelPickerWidget in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWidget.ts already observes ILanguageModelsService.onDidChangeLanguageModels and owns IStorageService, but currently only rerenders labels and picker contents. createManageModelsAction in modelPickerItems.ts is static, while grouped rendering in modelPickerItemSections.ts places that action in the Other Models toolbar; neither carries new-model state. getModelBadge in modelPickerBadges.ts has no New category, although getModelPickerAccessibilityProvider already incorporates item badges into accessible labels. The narrower https://github.com/microsoft/vscode/issues/298198 covers visible model rows, while this issue additionally requires awareness for policy-hidden models. Preserve BYOK exclusion, existing retirement/promotion badge precedence, first-run behavior, keyboard operation, and accessible announcements; the uncertainty starts at which surfaces receive the indicator and what event records it as seen.
- **Open decisions:**
  - Should new-model awareness appear only inside the picker on Other Models and model rows, or also on the top-level model-picker control for users who do not open the picker?
  - Is a model considered new by comparing locally persisted catalog snapshots, by server-provided release metadata, or by another explicit catalog signal?
  - What user-observable event dismisses the indicator, and across what scope should that dismissal persist: opening the picker, seeing the specific model, opening Manage Models, or moving focus back to chat?
  - For an enterprise-disabled new model, should the picker expose a disabled row explaining the policy or show only an aggregate new-model indicator leading to Manage Models?
