# Issue #332972 — Files opened read-only by "ReadOnly Include" cannot be made writable via "Reset Active Editor Read-Only In Session"

[https://github.com/microsoft/vscode/issues/332972](https://github.com/microsoft/vscode/issues/332972)

## Summary

Traced in filesConfigurationService.ts: 'Reset Active Editor Read-Only In Session' clears any session override and falls back to the configured `files.readonlyInclude` state (which still matches), so the file stays locked — that's the command's intended semantics, not a bug. The command the reporter actually wants, 'Set Active Editor Writeable in Session', already exists and does force the file writable because a session override with value `false` is checked before the include matcher and always wins.

## Change summary

Files locked via `files.readonlyInclude` cannot be unlocked with the 'Reset Active Editor Read-Only In Session' command; edits are still rejected after running it.

## Best solution

No code change needed: point the reporter at the existing 'Set Active Editor Writeable in Session' command (workbench.action.files.setActiveEditorWriteableInSession), which sets an explicit session override that outranks `files.readonlyInclude` in FilesConfigurationService.isReadonly. 'Reset' is meant to clear overrides back to the configured default, not to force writable.

Both commands are available from the same context, so it should be a drop-in swap for your workflow. Closing as as-designed, but please reopen if that command doesn't behave as expected.
