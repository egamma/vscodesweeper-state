# Issue #332972 — Files opened read-only by "ReadOnly Include" cannot be made writable via "Reset Active Editor Read-Only In Session"

[https://github.com/microsoft/vscode/issues/332972](https://github.com/microsoft/vscode/issues/332972)

## Summary

The behavior is intentional: 'Reset Active Editor Read-only in Session' clears any session override and falls back to the config-computed readonly state (still readonly per files.readonlyInclude), it isn't meant to force a file writable. The exact per-file interactive unlock the reporter wants already exists as 'Set Active Editor Writeable in Session'.

## Change summary

Files marked read-only via `files.readonlyInclude` cannot be unlocked using `Reset Active Editor Read-Only In Session`.

## Best solution

No code change needed — point the reporter at the existing `workbench.action.files.setActiveEditorWriteableInSession` command ('Set Active Editor Writeable in Session'), which sets an explicit session override that wins over `files.readonlyInclude` and gives exactly the case-by-case unlock they're asking for.

This is actually the intended distinction between the two session commands: **Reset Active Editor Read-only in Session** clears any manual override and falls back to whatever `files.readonlyInclude`/`files.readonlyExclude` compute for the file — since your file still matches `readonlyInclude`, it stays read-only after a reset.
