# Issue #197160 — Git - Auto Stash handles submodules incorrectly

[https://github.com/microsoft/vscode/issues/197160](https://github.com/microsoft/vscode/issues/197160)

## Summary

The bug report describes a real interaction problem between VS Code's auto-stash sync flow and submodule state, and no fix has landed on main. However, the exact failing code path depends on git version and the precise submodule state, making reproduction unclear without a live environment. Keeping open — the milestone is On Deck (a holding bin), and this is a legitimate git integration edge case.

## Change summary

VS Code's Synchronize Changes with auto-stash enabled incorrectly handles submodule state — either stashing/popping submodule changes it shouldn't, or producing a spurious 'No stash entries found' error.

## Best solution

Investigate whether the `maybeAutoStash` manual stash path (git < 2.27.0) or the `--autostash` flag path (git >= 2.27.0) is the culprit. For the manual path, the `createStash`/`popStash` cycle in `extensions/git/src/repository.ts` (line 3150) likely needs to exclude submodule-only changes. For the native flag path, the issue may be that submodule pointer changes are treated as dirty working-tree state by `git stash`, and the pop reapplies them incorrectly after pull updates the pointer — this may need a workaround that saves and restores submodule state separately.
