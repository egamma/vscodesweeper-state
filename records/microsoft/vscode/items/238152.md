# Issue #238152 — Linux Rocky 9.4, new instances of code open in same (gnome) workspace

[https://github.com/microsoft/vscode/issues/238152](https://github.com/microsoft/vscode/issues/238152)

## Summary

Keep open: an independent RHEL 9/GNOME report confirms the workspace-switching problem, and the linked 2020 fix predates this recurrence. Investigation should distinguish new-window placement from existing-window activation on the affected Linux desktop.

## Change summary

New VS Code windows launched from another GNOME workspace appear on the first instance's workspace and switch the user there.

## Best solution

Ensure an explicitly requested new window opens on the invoking GNOME workspace without activating an unrelated existing window. First reproduce on Rocky/RHEL 9 and isolate whether VS Code's launch/window handling or Electron/GNOME placement owns the regression.

These paths identify the investigation boundary but do not conclusively explain GNOME workspace placement.
