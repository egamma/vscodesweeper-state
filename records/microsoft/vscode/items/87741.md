# Issue #87741 — Auto save & new line prevents undo from working

[https://github.com/microsoft/vscode/issues/87741](https://github.com/microsoft/vscode/issues/87741)

## Summary

The underlying behavior remains on current main: inserting the final newline is still a separate save-participant edit, so the first Undo targets that edit instead of the user's input. A later throttle mitigated the auto-save loop but did not provide the single-step Undo behavior reported here.

## Change summary

With delayed auto-save and `files.insertFinalNewline` enabled, Undo first removes the automatically inserted newline rather than reverting the user's preceding edit.

## Best solution

Preserve final-newline enforcement while ensuring users can reach their preceding edit without racing auto-save. A maintainer should first decide whether the final-newline edit belongs with the preceding user undo element or whether save-participant edits need another undo treatment.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts`, `src/vs/workbench/contrib/codeEditor/test/browser/saveParticipant.test.ts`, `src/vs/workbench/services/textfile/common/textFileEditorModel.ts`
- **Validation:** Add an automated save-participant test covering delayed auto-save with `files.insertFinalNewline`: after typing at EOF and allowing auto-save to insert the newline, one Undo must restore the document state before the user edit without entering a newline remove/reinsert loop; run it with `scripts/test.sh --grep "Save Participants"`.
- **Behavior:**

  > With `files.autoSave` set to `afterDelay` and `files.insertFinalNewline` enabled, typing or pasting at the end of a file and waiting for auto-save must not make Undo stall on an automatically reinserted newline. Undo should reach the preceding user edit predictably without requiring repeated input within a timing window. Final-newline enforcement during ordinary saves must remain intact.
- **Trace:**

  > `FinalNewLineParticipant.doInsertFinalNewLine` in `src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts` applies the newline as an editor-model edit, which is therefore encountered by Undo before the preceding user edit. `TextFileEditorModel.doSaveSequential` in `src/vs/workbench/services/textfile/common/textFileEditorModel.ts` contains the mitigation from https://github.com/microsoft/vscode/commit/69fd7afc56b4c4f793981d6b0cfbeb06cc1ae613: auto-save participants wait up to 500ms after Undo, allowing another Undo before the newline is reinserted. That mitigation addresses the infinite timing loop but not the requested one-step semantics, and the reporter confirmed the remaining behavior afterward. The boundary is save-participant undo handling; explicit-save behavior, formatter undo semantics, and final-newline persistence must not regress.
- **Open decisions:**
  - Should the final-newline save edit be grouped with the preceding user edit, omitted from user-facing undo history, or handled through a final-newline-specific mechanism?
  - Should the chosen behavior apply only to `FinalNewLineParticipant`, or consistently to other deterministic save participants?
  - How should explicit saves differ from delayed auto-saves when defining the undo boundary?

## Evidence

- **current source:** `FinalNewLineParticipant.doInsertFinalNewLine` in `src/vs/workbench/contrib/codeEditor/browser/saveParticipants.ts` still applies the newline through `editor.executeEdits('insertFinalNewLine', ...)` or `model.pushEditOperations(...)`, leaving it as an editor-model edit encountered by Undo.
- **partial mitigation:** Commit https://github.com/microsoft/vscode/commit/69fd7afc56b4c4f793981d6b0cfbeb06cc1ae613 delays auto-save participants for 500ms after Undo, specifically addressing https://github.com/microsoft/vscode/issues/102542. It gives users time to issue another Undo but does not make one Undo revert the preceding user edit.
- **post-fix confirmation:** The reporter confirmed the problem still occurred in VS Code 1.51 after commit 69fd7afc56b4c4f793981d6b0cfbeb06cc1ae613 had landed: https://github.com/microsoft/vscode/issues/87741#issuecomment-725331740.
- **design constraint:** The discussion on https://github.com/microsoft/vscode/issues/102542 records that save-participant edits were deliberately kept separate from manual edits because combining formatter changes with user edits could change expected Undo semantics.
- **no canonical:** The related https://github.com/microsoft/vscode/issues/41115 and https://github.com/microsoft/vscode/issues/90100 are closed and cover other save participants; the current issue explicitly records that `files.insertFinalNewline` remained unresolved.
