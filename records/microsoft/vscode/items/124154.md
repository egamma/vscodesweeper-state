# Issue #124154 — Calling `TextEditorEdit.replace` to replace a line of text introduces a partial selection of the new text

[https://github.com/microsoft/vscode/issues/124154](https://github.com/microsoft/vscode/issues/124154)

## Summary

Still reproduces on main: the extension API's `TextEditorEdit.replace` creates a partial selection because `mainThreadEditor.ts#applyEdits` calls `executeEdits` without providing `endCursorState`, so the editor's default cursor computation selects the delta between old and new text length.

## Change summary

Calling `TextEditorEdit.replace` to replace text with longer text introduces an unwanted partial selection of the new text.

## Best solution

In `src/vs/workbench/api/browser/mainThreadEditor.ts`, the `applyEdits` method should pass a suitable `endCursorState` to `executeEdits` that collapses selections to their active end after the edit, preserving cursor position without introducing a selection. The workaround of resetting the selection after the edit (as shown in the comments) works but should not be needed.
