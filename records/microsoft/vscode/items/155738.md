# Issue #155738 — Support CompletionList.isIncomplete=true on empty lists (or at least, clearly document current behaviour)

[https://github.com/microsoft/vscode/issues/155738](https://github.com/microsoft/vscode/issues/155738)

## Summary

The requested capability remains absent: current source derives incomplete-provider state from completion items, so an empty list cannot preserve it. Keep this open for a decision on supporting empty incomplete results versus explicitly documenting the limitation; the related open issue concerns cancellation, not this symptom.

## Change summary

Honor CompletionList.isIncomplete for empty completion lists, or clearly document that empty lists do not preserve incomplete-provider retriggering.

## Best solution

Resolve the completion-provider contract for empty incomplete results in the editor suggestion pipeline and align vscode.d.ts documentation with that decision. Supporting retriggering without requiring visible dummy suggestions would address the reported Dart and other language-provider workflows.

- **Behavior:**

  > A provider currently loses automatic incomplete-result retriggering when it returns an empty list, even though additional typing could yield useful completions. A nonempty list whose items are filtered out behaves differently, encouraging fake-item workarounds. Decide whether empty incomplete lists should retain retriggering eligibility or whether this restriction should remain and be explicitly documented. If support is approved, manually invoking completion with no prefix and then typing must allow the provider to return real suggestions without inserting a dummy item.
