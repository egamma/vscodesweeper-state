# Issue #252371 — Copy and paste not working

[https://github.com/microsoft/vscode/issues/252371](https://github.com/microsoft/vscode/issues/252371)

## Summary

Keep open: the intermittent clipboard failure remains active after the attempted workarounds were rolled back, with multiple recent confirmations and current source still identifying the underlying Electron clipboard behavior. This is the established canonical investigation and should remain open while VS Code moves away from the unreliable Electron/execCommand path.

## Change summary

Copy or paste intermittently stops working in the editor, sometimes reporting that the clipboard command does not exist, until focus or window state changes.

## Best solution

Replace the fragile execCommand/webContents clipboard flow with a Clipboard API-based path that preserves VS Code's rich clipboard metadata, then remove the temporary Electron workarounds once copy, cut, and paste behavior is reliable across Windows and Linux.

## Evidence

- **reopened regression:** The issue was reopened because the problem persisted. A maintainer explained on 2026-01-16 that the copy/paste workarounds had to be rolled back after causing double pastes and that a proper fix requires moving to the Clipboard API.
- **current confirmations:** Independent reports through 2026-09-17 still confirm intermittent copy or paste failure, including correlations with high CPU/RAM use and temporary recovery after closing the integrated terminal.
- **source path:** Current main still routes editor copy through `document.execCommand('copy')` and paste through `clipboardService.triggerPaste` in src/vs/editor/contrib/clipboard/browser/clipboard.ts. The copy helper explicitly describes the missed clipboard event as a suspected Electron bug and retains a plaintext-only fallback.
- **attempted fixes:** https://github.com/microsoft/vscode/pull/280300 and https://github.com/microsoft/vscode/pull/283571 added workarounds; https://github.com/microsoft/vscode/pull/284961 addressed resulting duplicate pastes. The discussion records that these changes did not provide a durable solution.
- **upstream diagnosis:** A contributor traced unresolved/interleaved `webContents.paste()` calls through src/vs/workbench/services/clipboard/electron-browser/clipboardService.ts and src/vs/platform/native/electron-main/nativeHostMainService.ts and identified Electron as the underlying owner.
- **canonical search:** https://github.com/microsoft/vscode/issues/239500 and https://github.com/microsoft/vscode/issues/293314 describe overlapping symptoms, but maintainers routed the earlier report toward this issue, while this thread contains the profiles, diagnosis, workaround history, 111 upvotes, and ongoing investigation.
