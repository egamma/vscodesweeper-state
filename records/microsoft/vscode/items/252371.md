The finished behavior must retain supported rich clipboard content and must not break clipboard operations in other inputs. Existing commenter reproductions are credible, but the remaining failure must first be captured on a current build.
- **Trace:**

  > Editor copy runs through registerExecCommandImpl and executeClipboardCopyWithWorkaround in src/vs/editor/contrib/clipboard/browser/clipboard.ts; paste checks editor focus and invokes NativeClipboardService.triggerPaste, which reaches NativeHostMainService.triggerPaste and Electron webContents.paste(). The source still contains a plaintext copy fallback, but that alone does not prove the reported failures are resolved. Separately, extension overrides explain some missing-command cases, not necessarily the extension-disabled failures. The older related report https://github.com/microsoft/vscode/issues/239500 points back here for investigation.
