# Issue #201840 — Changing selection of just after text insertion messes up the undo stack [jsx]

[https://github.com/microsoft/vscode/issues/201840](https://github.com/microsoft/vscode/issues/201840)

## Summary

The undo corruption remains possible on current main: linked editing handles undo/redo model changes like ordinary edits and can schedule a mirrored edit while the undo operation is restoring text. The existing workaround avoids that path, but the default behavior should preserve the undo stack.

## Change summary

Changing text and moving the selection while linked editing is active can cause a subsequent undo to insert stale mirrored tag text and corrupt redo history.

## Best solution

Ensure linked editing does not create stale mirror edits during undo or redo, while preserving normal linked-tag synchronization and edit grouping. Add a regression test covering an external edit followed by selection movement and undo.
