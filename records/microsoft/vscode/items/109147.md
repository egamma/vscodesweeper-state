# Issue #109147 — Dispatching KeyboardEvent on Webview fails to work only on Windows.

[https://github.com/microsoft/vscode/issues/109147](https://github.com/microsoft/vscode/issues/109147)

## Summary

Still reproduces on main: webview keyboard event forwarding relies on `e.keyCode` for modifier-key detection (e.g. `isNewWindow`, `isSaveEvent`), which is 0 for synthetic events dispatched without it. The workaround (include `keyCode`) is documented in comments but no code fix exists.

## Change summary

Dispatching synthetic KeyboardEvents from within webview iframes fails to trigger VS Code shortcuts on Windows when `keyCode` is not explicitly set.

## Best solution

The detection functions in `src/vs/workbench/contrib/webview/browser/pre/index.html` (lines 646–729) should fall back to `e.code` or `e.key` when `e.keyCode` is 0, so that synthetic events without `keyCode` still match correctly. This is a small, localized fix in the webview preload script.
