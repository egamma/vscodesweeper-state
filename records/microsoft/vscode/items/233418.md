# Issue #233418 — File Search/Replace replacing multiple times (incorrectly) when double-clicking

[https://github.com/microsoft/vscode/issues/233418](https://github.com/microsoft/vscode/issues/233418)

## Summary

Keep open: the current replacement queue serializes repeated requests for the same search match but does not reject them, allowing a rapid second click to apply the stale replacement again. The existing search label is appropriate, and no verified canonical owns this double-click symptom.

## Change summary

Prevent rapid repeated clicks on a search-result Replace action from replacing the same occurrence more than once.

## Best solution

Make replacement of an individual search-result occurrence safe against overlapping invocations while preserving legitimate replacements of distinct occurrences and normal result navigation.

- **Current action path:** src/vs/workbench/contrib/search/browser/searchActionsRemoveReplace.ts registers ReplaceAction, whose run method calls performReplace. That function captures the target elements, awaits focus calculation, and calls SearchResultImpl.batchReplace without marking those occurrences as pending. src/vs/workbench/contrib/search/browser/searchTreeModel/searchResult.ts:82–104 forwards each match to its parent's replace method without rejecting overlapping requests.
- **Source-confirmed repeated replacement:** src/vs/workbench/contrib/search/browser/searchTreeModel/fileMatch.ts:269–275 appends every replace(toReplace) call to replaceQ and unconditionally invokes replaceService.replace(toReplace). Two invocations holding the same match therefore execute twice, even after the first updates the result list. src/vs/workbench/contrib/search/browser/replaceService.ts constructs each edit from that match's range and replacement text without a model-version constraint; serialization alone does not make the stale second edit safe.
