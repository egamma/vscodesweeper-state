# Issue #168329 — Filter completion client-side even if the LSP returns incomplete results

[https://github.com/microsoft/vscode/issues/168329](https://github.com/microsoft/vscode/issues/168329)

## Summary

Valid feature request to apply client-side filtering on existing incomplete completion results while awaiting the server's updated response. Still unimplemented on main and distinct from the related #147830 (which is about stale results from cancelled requests). Both remain under discussion.

## Change summary

Apply client-side filtering to already-received completion items while waiting for the server to respond to an incomplete-results retrigger, showing a loading indicator until final results arrive.

## Best solution

In `suggestModel.ts`, when retriggering for incomplete completions, keep the existing items visible and filter them client-side (same as the non-incomplete path) while showing a loading state. Update with the server's response when it arrives. This would live in the suggest contribution alongside the existing incomplete-retrigger logic around line 769.
