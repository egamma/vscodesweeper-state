# Issue #298359 — Integrated Browser: Install Extensions

[https://github.com/microsoft/vscode/issues/298359](https://github.com/microsoft/vscode/issues/298359)

## Summary

Keep open: the integrated browser still has no identified Chromium-extension installation capability, and this issue already serves as the destination for a duplicate request. The debugging and company-authentication use cases merit a feasibility and scope decision rather than a staleness close.

## Change summary

Allow installing browser extensions in the integrated browser, including Xdebug Helper and company-specific authentication extensions.

## Best solution

Establish whether a deliberately scoped browser-extension capability can support these workflows within Electron's compatibility limits and VS Code's session isolation. Define the supported installation sources, extension capabilities, and persistence semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/browserView/electron-main/browserSession.ts`, `src/vs/platform/browserView/common/browserView.ts`, `src/vs/workbench/contrib/browserView/electron-browser/browserView.contribution.ts`
- **Validation:** The plan should end with a runnable desktop acceptance scenario that installs a supported browser extension, verifies its observable behavior on an integrated-browser page, checks the chosen reload/persistence contract, and confirms it is unavailable in sessions outside its selected scope. Use Xdebug Helper as the concrete compatibility target; do not assume support for enterprise authentication extensions without a representative sample.
- **Behavior:**

  > Users want browser extensions to operate inside the integrated browser rather than switching to an external browser. The original target is Xdebug Helper for PHP debugging; another user needs company-specific authentication extensions. Acceptance must demonstrate installation and useful extension behavior on an actual page, with documented compatibility limits and predictable persistence and session scope. Opening DevTools or installing a VS Code extension does not satisfy the request.
- **Trace:**

  > The desktop browser contribution entry point is src/vs/workbench/contrib/browserView/electron-browser/browserView.contribution.ts; its registered features contain no browser-extension installation surface. BrowserEditorDevToolsContribution and ToggleDevToolsAction expose DevTools only. BrowserSession in src/vs/platform/browserView/electron-main/browserSession.ts owns separate Electron sessions for global, workspace, ephemeral, and agent storage, making it a relevant boundary for extension availability. Targeted source searches found no extension-loading integration, but Electron compatibility with the requested extensions has not been established by execution. Preserve existing session isolation and browser permission boundaries; do not assume extensions should become available to agent sessions. https://github.com/microsoft/vscode/issues/299159 was closed as a duplicate pointing here, so retain this issue as the installation request rather than redirecting it to that newer closed report.
- **Open decisions:**
  - Should the initial capability support explicitly selected unpacked extensions, packaged extensions, or Chrome Web Store installation, and what compatibility promise should users receive?
  - Should installed extensions apply globally or to a selected browser storage scope, and what should persist across reloads or be available in ephemeral and agent sessions?

## Evidence

- **Existing-capability check:** At checkout 4e4b35ed9330baeaf99146a1ad40621c5a288529, src/vs/workbench/contrib/browserView/electron-browser/browserView.contribution.ts registers navigation, storage, permissions, DevTools, emulation, and other browser contributions, but no browser-extension management contribution. Targeted searches of the browserView platform and workbench sources found no loadExtension, installExtension, Chrome Web Store, or chrome-extension integration.
- **Debugging is not extension installation:** src/vs/workbench/contrib/browserView/electron-browser/features/browserDevToolsFeature.ts registers ToggleDevToolsAction and delegates to model.toggleDevTools(); this exposes developer tools, not installation or execution of the Xdebug Helper browser extension requested in https://github.com/microsoft/vscode/issues/298359.
- **Session boundary:** src/vs/platform/browserView/electron-main/browserSession.ts creates distinct global, workspace, ephemeral, and agent Electron sessions through BrowserSession factory methods. Supporting browser extensions would require an explicit decision about their installation scope and persistence; existing browser storage settings do not supply extension installation.
- **Verified related duplicate:** https://github.com/microsoft/vscode/issues/299159 is closed. Its discussion links this issue as the existing request, followed by a duplicate command and the bot's duplicate closure: https://github.com/microsoft/vscode/issues/299159#issuecomment-3996269097 and https://github.com/microsoft/vscode/issues/299159#issuecomment-3996662890. - **Canonical search:** Read-only GitHub searches for browser extensions, integrated-browser Chrome support, and Chromium extensions found no verified older open issue owning this installation request. Requests for exposing browser URLs to VS Code extensions or opening URLs externally do not deliver Chromium-extension installation.
- **Demand and remaining scope:** The supplied context records 14 upvotes, a PHP-debugging use case in the body, and a second user's company network/VPN authentication use case. The latter currently requires an external browser. These are distinct motivations for the same missing capability, not evidence of a fixed defect or a maintainer decision to decline it.
