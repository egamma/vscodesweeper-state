# Issue #334869 — Automations Modal: Pressing `esc` should close the context menu and not the modal

[https://github.com/microsoft/vscode/issues/334869](https://github.com/microsoft/vscode/issues/334869)

## Summary

Fresh, credible bug report (with video) against the new Automations modal, filed by a project contributor and already assigned to an engineer as backup — a genuine gap in the modal's Escape-suppression logic, not something to close.

## Change summary

In the Automations modal, pressing Escape while a dropdown/context menu is open closes the whole modal instead of just the popup.

## Best solution

Fix belongs in src/vs/sessions/contrib/automations/browser/automationDialog.ts: `isAutomationDialogPopupTarget` already special-cases `.context-view`, `.monaco-menu-container`, `.quick-input-widget`, `.monaco-hover(-content)`, and `.suggest-widget`, but a plain native `<select>` (rendered by `SelectBoxNative` when `hasNativeContextMenu()` is true, used for the schedule interval/time pickers via `useCustomDrawn`) isn't matched by any of those selectors, so its native OS dropdown's Escape keyup isn't suppressed and falls through to the base `Dialog` widget's own Escape-keyup close handler in src/vs/base/browser/ui/dialog/dialog.ts.
