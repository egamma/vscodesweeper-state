# Issue #329752 — Customizations editor: &quot;Open&quot; does not open extension/plugin-provided files read-only (extractSource reads a property that is never set)

[https://github.com/microsoft/vscode/issues/329752](https://github.com/microsoft/vscode/issues/329752)

## Summary

Confirmed on main: `extractSource()` in aiCustomizationManagement.contribution.ts reads `context.storage`, but the widget only ever sets `context.source` — so the read-only guard for extension/plugin-provided files never fires and the Open command's context menu item has no `when` clause to hide/gate it for those items.

## Change summary

Opening an extension- or plugin-provided chat customization file via the Customizations editor's Open action opens it fully editable instead of read-only, because a property name mismatch makes the source-detection function always return undefined.

## Best solution

Fix `extractSource()` (line 154) to read `context.source` instead of `context.storage`, and drop the unused `storage?: PromptsStorage` field from the `AICustomizationContext` type (line 127) to match what `aiCustomizationListWidget.ts` actually sends (`element.source` at lines 438/856).
