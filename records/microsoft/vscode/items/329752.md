# Issue #329752 — Customizations editor: &quot;Open&quot; does not open extension/plugin-provided files read-only (extractSource reads a property that is never set)

[https://github.com/microsoft/vscode/issues/329752](https://github.com/microsoft/vscode/issues/329752)

## Summary

Confirmed on main: extractSource() reads context.storage, a field never populated anywhere, instead of context.source which is set by aiCustomizationListWidget.ts — the read-only guard for extension/plugin files in Open is dead code, and the same bug makes the Delete action's defense-in-depth guards unreachable.

## Change summary

The Customizations editor's 'Open' action does not open extension- or plugin-provided files read-only, letting users edit files whose changes are silently discarded on extension update.

## Best solution

Fix extractSource() in aiCustomizationManagement.contribution.ts to read context.source instead of context.storage, and drop the unused storage?: PromptsStorage field from AICustomizationContext (reconciling its type with AICustomizationSource) as suggested in the report.
