# Issue #44056 — When A grammar injects to B, grammars embedding B should get A's injection

[https://github.com/microsoft/vscode/issues/44056](https://github.com/microsoft/vscode/issues/44056)

## Summary

The requested transitive injection behavior remains absent on current main: injections targeting an embedded grammar are not automatically registered for its host grammar. The accepted Backlog request should remain open while maintainers decide the inheritance contract and whether it belongs in VS Code's adapter or vscode-textmate.

## Change summary

Make an injection targeting grammar B also apply when another grammar embeds B.

## Best solution

Define safe transitive injection semantics for composite TextMate grammars, then implement them in vscode-textmate or the VS Code grammar adapter so extension authors do not need to enumerate every possible host grammar.

## Plan brief

- **Likely files:** `src/vs/workbench/services/textMate/common/TMGrammarFactory.ts`, `src/vs/workbench/services/textMate/common/TMGrammars.ts`, `package.json`, `package-lock.json`
- **Validation:** Create synthetic A, B, and C TextMate grammars where A injects into B and C embeds B; tokenizing C must apply A inside the embedded B region while leaving unrelated scopes and direct B tokenization unchanged.
- **Behavior:**

  > When injection grammar A targets grammar B, the injection should remain effective wherever B is embedded by host grammar C, without requiring A to know every possible host. Direct use of B must continue to work, and A must not affect unrelated portions of C. Acceptance requires a synthetic A/B/C tokenization test covering both the inherited injection and isolation from unrelated scopes.
- **Trace:**

  > VS Code records `injectTo` contributions in TMGrammarFactory._injections and passes them through the vscode-textmate Registry.getInjections callback in src/vs/workbench/services/textMate/common/TMGrammarFactory.ts. The callback receives the loaded root scope and returns injections registered for that scope or its dotted parents; it does not traverse grammars included by the root. The same limitation and explicit-host workaround were documented at https://github.com/microsoft/vscode/issues/87496#issuecomment-576645129. The uncertainty starts at ownership and contract semantics: vscode-textmate currently collects injections at grammar construction, while VS Code owns the extension contribution mapping. Preserve explicit `injectTo` behavior and avoid applying an injection outside the embedded B scope.
- **Open decisions:**
  - Should injections targeting an embedded grammar propagate automatically into every host grammar, or should host grammars explicitly opt in to avoid unexpected third-party injections and tokenization cost?

## Evidence

- **current source:** src/vs/workbench/services/textMate/common/TMGrammarFactory.ts:62-69 resolves contributed injections only for the scope name requested by vscode-textmate (plus dotted parent scopes); it does not discover injections targeting grammars embedded by that root grammar.
- **current contribution contract:** src/vs/workbench/services/textMate/common/TMGrammars.ts defines `injectTo` as an explicit list of target scope names, with no transitive or embedded-grammar inheritance option.
