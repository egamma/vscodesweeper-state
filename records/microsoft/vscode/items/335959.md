# Issue #335959 — [macOS] Enterprise Deployment using DMG-installer via Intune/JAMF: "An update is ready to install. Code is trying to add a new helper tool."

[https://github.com/microsoft/vscode/issues/335959](https://github.com/microsoft/vscode/issues/335959)

## Summary

Credible, well-documented enterprise-deployment bug: MDM (Intune/JAMF) DMG installs apparently leave the app bundle with different file permissions/ownership than a manual DMG install, which triggers macOS's native 'add a helper tool' authorization prompt during Squirrel.Mac auto-update. No fix or related change found on main, and the root cause (deployment-tool permission handling vs. the updater's helper-tool requirements) can't be verified from source alone, so this stays open for the install-update team.

## Change summary

On macOS, VS Code deployed via MDM (Intune/JAMF) DMG install shows an OS prompt about adding a new helper tool when checking for updates, unlike a manually-installed DMG.

## Best solution

Install-update/macOS owners should investigate whether the auto-updater's permission/ownership expectations for the app bundle can be relaxed or repaired automatically, or document the permission structure MDM tooling must preserve for Squirrel.Mac helper-tool installation to succeed silently.
