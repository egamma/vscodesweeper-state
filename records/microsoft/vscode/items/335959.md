# Issue #335959 — [macOS] Enterprise Deployment using DMG-installer via Intune/JAMF: "An update is ready to install. Code is trying to add a new helper tool."

[https://github.com/microsoft/vscode/issues/335959](https://github.com/microsoft/vscode/issues/335959)

## Summary

The macOS auto-updater in VS Code delegates entirely to Electron's `autoUpdater` (Squirrel.Mac), which is the component that decides when a privileged-helper install prompt is shown; that decision is driven by the on-disk ownership/permissions of the installed .app bundle, which is exactly what the reporter says Intune/JAMF DMG deployment changes — so the root cause sits upstream in Electron/Squirrel.Mac's privileged-helper logic reacting to non-standard install permissions, not in VS Code's own update code.

## Change summary

On Macs where the VS Code DMG is deployed via Intune/JAMF (rather than a manual drag-and-drop install), the app repeatedly shows a macOS 'trying to add a new helper tool' authorization prompt when it applies its own auto-update.

## Best solution

For MDM-managed fleets, the practical fix is on the admin side: use the documented `update.mode` enterprise policy (e.g. set to `none`) to disable VS Code's built-in auto-updater on centrally managed devices and push updates through Intune/JAMF instead, avoiding the ownership/permission mismatch that triggers Squirrel.Mac's helper-tool prompt.
