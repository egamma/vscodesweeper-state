# Issue #297308 — Chat: It's easy to accidentally enable editing all sensitive files

[https://github.com/microsoft/vscode/issues/297308](https://github.com/microsoft/vscode/issues/297308)

## Summary

Multiple hard keep-open rules apply: the issue carries both `important` and `security` labels, and active team discussion is ongoing. The UX concern — that the default button silently escalates from a single-file approval to a blanket session-wide approval for all sensitive files — is a real security/UX gap that needs a maintainer decision.

## Change summary

The default 'Allow in Session' button for sensitive-file editing approves ALL sensitive files for the session, not just the one being asked about, with no disclaimer or granularity.

## Best solution

Rework the approval UX so that 'Allow in Session' is scoped to the specific file (or at minimum clearly discloses what is being approved), and keep 'Allow Once' as the default/primary button. The team discussion in comments 2–3 converges on separating the two buttons with 'Allow Once' as the prominent default — that direction addresses both the ambiguity and the accidental escalation risk.
