# Issue #333284 — Agent Host session listing can starve under catalog invalidation and repeated Git probes

[https://github.com/microsoft/vscode/issues/333284](https://github.com/microsoft/vscode/issues/333284)

## Summary

Team-authored, freshly filed performance report with detailed logs tracing a real feedback loop between expensive listSessions computation (Git subprocess spawning) and catalog-epoch invalidation; no fix exists yet, so this stays open for the Agent Host team to address — not eligible for any judgment close per the team-authored protection rule anyway.

## Change summary

Agent Host's listSessions can loop on expensive Git-probing scans for minutes because catalog invalidation restarts in-flight enrichment work and allows overlapping duplicate scans.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts, avoid restarting/duplicating the git-project enrichment work on catalog invalidation (e.g. reuse in-flight results, debounce epoch bumps, or lazily resolve git project info instead of eagerly probing for all registered sessions) and short-circuit AgentHostGitService.getRepositoryRoot for known-non-git paths to cut the volume of failed `git rev-parse` probes.
