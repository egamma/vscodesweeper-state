# Issue #294099 — Local index isn't built for GitHub repos with no auth or index errors?

[https://github.com/microsoft/vscode/issues/294099](https://github.com/microsoft/vscode/issues/294099)

## Summary

Valid feature request for a purely local semantic index fallback when the remote GitHub index is inaccessible (due to auth restrictions or service errors). The existing 'external ingest' feature partially addresses this but still requires auth and a service connection; no purely offline fallback exists on current main.

## Change summary

Build and use a local semantic index when the remote GitHub code search index is unavailable due to auth refusal or service errors.

## Best solution

Evaluate whether the workspace chunk search pipeline can fall back to a purely local embeddings index (computed and stored on-device) when the remote code search service is NotAuthorized or in error. This would live in the copilot extension's workspaceChunkSearch layer alongside the existing CodeSearchChunkSearch and ExternalIngestIndex strategies. The external ingest feature is a step toward this but still requires a service round-trip; a fully offline path would serve users who decline broad GitHub scopes.

- **Reason:** A local index fallback aligns with the durable AI-assisted development theme and the current agent-experience priorities — workspace understanding is core to agent quality, and gating it behind broad auth scopes or remote service health creates a gap.
