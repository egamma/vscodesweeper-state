# Issue #251894 — macOS Sequoia steals second keystroke of ⌘ K ⌘ M chord – window minimises instead of language picker

[https://github.com/microsoft/vscode/issues/251894](https://github.com/microsoft/vscode/issues/251894)

## Summary

Real bug: the native Electron menu registers `Command+M` as an accelerator for Minimize (src/vs/platform/menubar/electron-main/menubar.ts:604), which fires at the OS/Electron level even when VS Code's keybinding resolver is in chord mode expecting the second part of ⌘K ⌘M. The fix likely involves suppressing or temporarily removing the native accelerator during chord mode.

## Change summary

Pressing ⌘K followed by ⌘M minimises the window instead of triggering the Change Language Mode chord keybinding, because the native menu accelerator intercepts ⌘M before the chord resolver.

## Best solution

During chord mode, VS Code should suppress or temporarily unregister native accelerators that conflict with pending chord second-parts. The Minimize menu item at src/vs/platform/menubar/electron-main/menubar.ts:604 hardcodes `accelerator: 'Command+M'`; the same issue likely affects ⌘K ⌘H (hide). A fix would involve IPC from the renderer to the main process on chord-mode entry/exit to disable conflicting native accelerators, or using Electron's `before-input-event` to intercept the keystroke before the menu accelerator fires.
