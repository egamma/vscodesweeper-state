# Issue #153081 — Reverse the visual logic of text link decorators

[https://github.com/microsoft/vscode/issues/153081](https://github.com/microsoft/vscode/issues/153081)

## Summary

Keep open for the remaining design decision: accessibility.underlineLinks now provides opt-in underlining, but it does not make underlining the default or remove it on hover as requested. No verified older open canonical was found.

## Change summary

Underline text links by default and remove the underline on hover instead of relying on color to identify links at rest.

## Best solution

Have the accessibility and UX owners decide whether inline prose links should be underlined by default and whether hover should retain that identifying cue. Build on accessibility.underlineLinks rather than introducing another setting, while preserving high-contrast and keyboard-focus affordances.
