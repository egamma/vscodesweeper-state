# Issue #339716 — Reference hover: Single files missing rich hover

[https://github.com/microsoft/vscode/issues/339716](https://github.com/microsoft/vscode/issues/339716)

## Summary

Fresh, team-filed bug (chrmarti, found while testing #339392) about agent-session reference/artifact pills; tracing the source shows plain file/resource entries never get a `pillHover`, so a single-file pill falls back to a plain tooltip instead of the richer hover commit/GitHub entries get — this stays open as a real, still-unfixed defect.

## Change summary

In the agent sessions chat window, hovering a single file reference pill shows a plain tooltip instead of the rich hover (with action links) shown when the same file appears inside a multi-entry collection pill.

## Best solution

Give plain resource/file pill entries a `pillHover` (as the Commit and GitHub-resource branches already do) so `ChatResourcePillActionViewItem.getHoverContents()` renders the same rich hover instead of falling back to `super.getHoverContents()`; likely needs a small reusable 'generic resource hover' builder shared across the few call sites that build file entries.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/sessionArtifacts.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts`, `src/vs/workbench/browser/chatResourcePill.ts`
- **Validation:** A componentFixture or chatPills test asserting a single-entry file/resource pill's hover renders the same rich content (location + hoverActions) as its dropdown-row counterpart.
- **Behavior:**

  > Hovering a chat pill that represents exactly one plain file reference should show the same rich hover (path, action links such as Copy URI/Copy Relative Path) that the same file gets when it's one of several entries in a collection pill. Currently the single-file pill shows only a plain tooltip.
- **Trace:**

  > Plain resource/file entries (SessionArtifactKind.Resource in src/vs/sessions/contrib/chat/browser/sessionArtifacts.ts, and the file-reference branches in agentHostSessionInputPills.ts) are built via `getChatPillResourceLocation`/`sessionArtifactLocation`, which set `hover`, `tooltip`, `hoverActions` but never `pillHover`. `ChatResourcePillActionViewItem.getHoverContents()` (src/vs/workbench/browser/chatResourcePill.ts) uses `entry?.pillHover ?? super.getHoverContents()`, so without `pillHover` it falls back to the generic hover. The Commit and GitHub-resource branches in the same files build and set `pillHover` via `createHover('default')`, which is why those show a rich hover. Do not touch the dropdown-row `hover` path (collections), which already works; the gap is specific to the single-entry pill path.
- **Open decisions:**
  - Should plain files get a brand-new lightweight 'resource hover' component, or should the existing location/tooltip content simply be wrapped into a pillHover with the same action-link footer used elsewhere?

## Evidence

- **missing pillHover for files:** src/vs/sessions/contrib/chat/browser/sessionArtifacts.ts, SessionArtifactKind.Resource branch (~line 272-287), sets toolbarActions/sessionArtifactLocation but never `pillHover`, unlike the Commit branch a few lines above (line ~263-266) which sets both `hover` and `pillHover` via createHover('default')/createHover('compact').
- **fallback path:** src/vs/workbench/browser/chatResourcePill.ts getHoverContents() returns `entry?.pillHover ?? super.getHoverContents()` — without pillHover this falls back to the plain base hover, matching the reported 'missing rich hover' for a single file.
- **same gap elsewhere:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts lines ~954 and ~1033 build file-reference entries via getChatPillResourceLocation() with hoverActions but likewise no pillHover, so the gap isn't isolated to one call site.
