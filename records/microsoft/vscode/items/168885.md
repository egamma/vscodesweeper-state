# Issue #168885 — ability to open vscode from `code` command line that focuses integrated terminal

[https://github.com/microsoft/vscode/issues/168885](https://github.com/microsoft/vscode/issues/168885)

## Summary

Keep this accepted, community-supported request open: current CLI options do not let users reveal a file while retaining integrated-terminal focus. The discussion-linked standalone-terminal issue does not cover the same observable behavior.

## Change summary

Allow CLI-opened files to appear for reference without interrupting input in the integrated terminal.

## Best solution

Provide an opt-in CLI focus behavior for reference-only file opening while preserving normal editor focus by default. Settle whether the option preserves the existing focused control or explicitly focuses the integrated terminal before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/environment/common/argv.ts`, `src/vs/platform/environment/node/argv.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`, `src/vs/platform/window/common/window.ts`, `src/vs/workbench/electron-browser/window.ts`, `src/vs/workbench/contrib/terminal/electron-browser/terminalNativeContribution.ts`
- **Validation:** In an existing window with its integrated terminal focused, invoke the agreed opt-in CLI form to open two different files successively, including a --goto location. Each file must become visible at the requested location while keyboard input remains in the terminal, without closing the editor or using a focus shortcut. Repeat without the option to confirm normal editor focus remains unchanged, and verify existing --wait focus restoration still works.
- **Behavior:**

  > Julia call-tree navigation repeatedly invokes code to reveal method source, currently moving keyboard focus from the integrated terminal to the editor. An opt-in invocation should reveal the requested source while allowing the user to continue terminal interaction immediately. Acceptance covers successive file opens and line navigation without closing those files or manually restoring focus. Ordinary CLI opens and existing --wait behavior must remain unchanged.
- **Trace:**

  > The current CLI option registry in src/vs/platform/environment/node/argv.ts offers window reuse, line navigation, and waiting, but no requested focus control. WindowsMainService forwards native file requests through vscode:openFiles; NativeWindow.onOpenFiles/openResources in src/vs/workbench/electron-browser/window.ts opens the resources without such a focus policy. TerminalNativeContribution._onOpenFileRequest restores terminal focus only after --wait editors close, which does not satisfy viewing source while continuing traversal. The trace establishes the existing-window file path; fresh-window and folder-opening semantics remain unspecified. Keep default file-opening behavior and wait-marker handling unchanged. https://github.com/microsoft/vscode/issues/34442 concerns standalone terminal windows rather than this focus contract, and the closed https://github.com/microsoft/vscode/issues/93826 is not a duplicate target.
- **Open decisions:**
  - Should the opt-in CLI behavior preserve whichever workbench control currently has focus, or explicitly focus the integrated terminal?
  - Should the initial contract cover only file opening in an existing window, or also folder/fresh-window opening; if the latter, should it create and focus a terminal when none exists?
