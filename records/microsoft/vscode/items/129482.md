# Issue #129482 — Imported modules not idenfied in subsequent Notebook Cells

[https://github.com/microsoft/vscode/issues/129482](https://github.com/microsoft/vscode/issues/129482)

## Summary

Still an open gap: TypeScript notebook cells with `import` statements become isolated modules, breaking cross-cell IntelliSense. No fix has landed on main, the issue has 21 upvotes and active community interest, and the underlying architectural challenge (single-document vs. multi-document model for notebook cells) remains unresolved.

## Change summary

TypeScript notebook cells that use `import` statements don't share declarations with other cells because the import turns the cell into an isolated module.

## Best solution

The TS language service needs a way to construct a unified document view from notebook cells that preserves cross-cell symbol visibility even when cells contain imports — likely requiring changes in `extensions/typescript-language-features/src/tsServer/bufferSyncSupport.ts` and coordination with the TS server's module resolution. This is a design problem (noted in comment 1) that needs a UX proposal for how to handle conflicting declarations across cells.
