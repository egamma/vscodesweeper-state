## Summary

Widely and repeatedly confirmed across macOS and Windows through the latest stable (1.134–1.136.1), with a maintainer already engaged and a repro that persists after the 'fixes in this space' comment — this is a real, active bug in the GitHub/Copilot auth-session flow, not a candidate for closing yet since no fix commit exists on main.

## Change summary

Opening a new native tab/window repeatedly shows the 'Sign in to use GitHub Copilot' prompt even though the user is already signed in to GitHub.

## Best solution

Root-cause why the GitHub Copilot entitlement/session check re-triggers on new-tab/new-window instead of reusing the cached authentication session — likely in the chat setup / auth flow around src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupContributions.ts and chatSetupRunner.ts, or in the GitHub authentication provider's session refresh path; the sign-out/sign-in workaround reported by several commenters suggests a stale or invalid cached session token is the trigger.
