# Issue #336892 — editor.formatOnPaste is not respected when a DocumentPasteEditProvider provides edits to the paste

[https://github.com/microsoft/vscode/issues/336892](https://github.com/microsoft/vscode/issues/336892)

## Summary

Traced through the source: `editor.formatOnPaste` only fires from `onDidPaste`, which is only emitted by the plain-text paste path — not by the `DocumentPasteEditProvider`/bulk-edit path — so it's silently skipped whenever a paste provider supplies edits. This is a real gap, but whether formatOnPaste should always auto-fire after provider edits (vs. providers opting in) is a design call for a maintainer.

## Change summary

editor.formatOnPaste is never triggered when a DocumentPasteEditProvider (rather than the plain-text handler) supplies the pasted content.

## Best solution

Decide whether the paste-provider path should also fire the format-on-paste range formatter after applying its edit (and over what range, given possible multi-cursor/multi-edit sessions), then wire that trigger into PostEditWidgetManager.applyEditAndShowIfNeeded alongside the existing onDidPaste-based flow.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/dropOrPasteInto/browser/postEditWidget.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts`, `src/vs/editor/contrib/format/browser/formatActions.ts`
- **Validation:** A test asserting that pasting content through a DocumentPasteEditProvider (with editor.formatOnPaste enabled and a registered documentRangeFormattingEditProvider) results in the range formatter being invoked over the pasted range.
- **Behavior:**

  > When editor.formatOnPaste is enabled and a document range formatter is registered, pasting text should trigger range formatting over the pasted region regardless of whether the paste was handled by the default text handler or by a DocumentPasteEditProvider. Currently only the default handler triggers it. Acceptance: a paste routed entirely through a custom DocumentPasteEditProvider still invokes the range formatter once, over the edited range(s).
- **Trace:**

  > FormatOnPaste (src/vs/editor/contrib/format/browser/formatActions.ts) subscribes to `editor.onDidPaste`, which CodeEditorWidget only fires from its internal `_paste()` method (codeEditorWidget.ts:1207-1221) for the plain-text/`Handler.Paste` path. When a DocumentPasteEditProvider supplies edits, CopyPasteController.doPasteInline (copyPasteController.ts) instead calls PostEditWidgetManager.applyEditAndShowIfNeeded (postEditWidget.ts:172-246), which applies the resolved edit via `IBulkEditService.apply(...)` and never goes through `_paste()`. The boundary: do not touch the default-paste (`applyDefaultPasteHandler`) path, which already works correctly; the fix should hook into the provider-edit apply path without altering how multi-provider paste-selector (pasteAs) behaves.
- **Open decisions:**
  - Should formatOnPaste always fire automatically after any DocumentPasteEditProvider edit, or should providers be able to opt out (e.g. because they already perform their own whitespace/format cleanup)?
  - When the provider's edit spans multiple cursors/ranges or is later swapped via the paste-selector widget, which range(s) should the range formatter be invoked over?
