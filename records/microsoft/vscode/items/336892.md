# Issue #336892 — editor.formatOnPaste is not respected when a DocumentPasteEditProvider provides edits to the paste

[https://github.com/microsoft/vscode/issues/336892](https://github.com/microsoft/vscode/issues/336892)

## Summary

Confirmed in source: when a DocumentPasteEditProvider supplies an edit, the paste is applied via IBulkEditService in postEditWidget.ts rather than through Handler.Paste, so the editor's onDidPaste event never fires and FormatOnPaste (formatActions.ts) — which only listens on onDidPaste — never runs, silently ignoring editor.formatOnPaste.

## Change summary

editor.formatOnPaste is not honored when a DocumentPasteEditProvider (rather than the default paste path) supplies the pasted content.

## Best solution

Have CopyPasteController/PostEditWidgetManager fire (or otherwise trigger) the same format-on-paste flow after applying a paste-edit-provider edit, e.g. by emitting onDidPaste (or invoking the format trigger directly) once the bulk edit in postEditWidget.ts's applyEditAndShowIfNeeded completes successfully.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/dropOrPasteInto/browser/postEditWidget.ts`, `src/vs/editor/contrib/dropOrPasteInto/browser/copyPasteController.ts`, `src/vs/editor/contrib/format/browser/formatActions.ts`
- **Validation:** A test (or manual repro) registering a DocumentPasteEditProvider and a DocumentRangeFormattingEditProvider with editor.formatOnPaste enabled should show the range-formatting provider invoked after the paste-edit-provider's edit is applied.
- **Behavior:**

  > When editor.formatOnPaste is enabled and a DocumentPasteEditProvider supplies the edit for a paste (instead of the default text paste), the registered DocumentRangeFormattingEditProvider should still run over the pasted range afterward, just as it does for a plain/default paste. Acceptance: format-on-paste fires for both default and provider-supplied pastes when the setting is on.
- **Trace:**

  > FormatOnPaste (src/vs/editor/contrib/format/browser/formatActions.ts, class FormatOnPaste, `_update`/`_trigger`) subscribes only to `editor.onDidPaste`, which CodeEditorWidget only fires from `_paste()` (codeEditorWidget.ts ~line 1207) when the paste goes through `Handler.Paste`. CopyPasteController.doPasteInline (copyPasteController.ts) only calls `applyDefaultPasteHandler` (which triggers `Handler.Paste`) when no non-default paste edit exists; when a DocumentPasteEditProvider's edit is used, it instead calls `_postPasteWidgetManager.applyEditAndShowIfNeeded` (postEditWidget.ts), which applies the edit via `IBulkEditService.apply` and never fires `onDidPaste`. The boundary: don't change the default-paste path (Handler.Paste / onDidPaste semantics) or the paste-edit-provider selection/resolve flow; the fix should hook the successful bulk-edit application to also invoke format-on-paste (or fire the same event) for the resulting edit range.
- **Open decisions:**
  - Should the paste-edit-provider path fire the existing onDidPaste event (so any onDidPaste consumer benefits) or should format-on-paste be triggered directly/separately for this path?
  - What range should be formatted when the paste-edit-provider's edit spans multiple/disjoint ranges (unlike the single contiguous range from a default paste)?
