# Issue #291791 — Expose git.closeRepository and git.openRepository commands for programmatic use

[https://github.com/microsoft/vscode/issues/291791](https://github.com/microsoft/vscode/issues/291791)

## Summary

The requested programmatic repository management already exists: git.openRepository accepts a filesystem path, and the close command is named git.close and also accepts a path. No new command is needed for the described workflow.

## Change summary

Allow extensions and tools to close and reopen selected Git repositories programmatically without removing their files.

## Best solution

Use the existing git.close and git.openRepository commands with the repository's filesystem path. Preserve the existing command IDs rather than adding an alias solely to deliver behavior already available.

- **Proposed comment:**

  > Thanks for the request. Both operations are already callable by extensions through `vscode.commands.executeCommand`: use `await vscode.commands.executeCommand('git.close', repositoryPath)` to close a currently open repository, and `await vscode.commands.executeCommand('git.openRepository', repositoryPath)` to open or reopen it. The close command is named `git.close`, not `git.closeRepository`; supplying the filesystem path of an open repository avoids the repository picker, and closing leaves its files on disk.
