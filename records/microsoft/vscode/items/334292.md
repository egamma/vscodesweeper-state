# Issue #334292 — [security] chat fetch allow/deny behavior different based upon grouping of requests

[https://github.com/microsoft/vscode/issues/334292](https://github.com/microsoft/vscode/issues/334292)

## Summary

This is a security-sensitive report — the reporter describes chat fetch approval/deny behavior differing based on whether URLs are fetched individually vs. grouped, which could bypass a user's `chat.tools.urls.autoApprove` deny setting. Per policy, security-sensitive reports are never proposed for closing regardless of other evidence, so this stays open pending maintainer/security investigation.

## Change summary

Chat fetch tool confirmation (allow/deny per `chat.tools.urls.autoApprove`) behaves inconsistently: a URL with `approveRequest: false` was auto-approved when fetched alone, but triggered a confirmation dialog (which also lumped in an already-fully-approved URL) when fetched together with another URL.

## Best solution

Needs a security-minded maintainer to trace both code paths (the batched `internal_fetch_webpage` tool in src/vs/workbench/contrib/chat/common/tools/builtinTools/chatUrlFetchingConfirmation.ts, which uses `urls.every(...)` over `isUrlApproved` in chatUrlFetchingPatterns.ts, versus whatever path handles a lone fetch — possibly a different/extension-side tool) to find where a `approveRequest:false` URL can slip through without confirmation when fetched individually, and confirm the dialog only ever names URLs that actually still need approval.
