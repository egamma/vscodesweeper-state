# Issue #334292 — [security] chat fetch allow/deny behavior different based upon grouping of requests

[https://github.com/microsoft/vscode/issues/334292](https://github.com/microsoft/vscode/issues/334292)

## Summary

Security-sensitive and real: the batched fetch confirmation logic in chatUrlFetchingConfirmation.ts requires ALL URLs in a single tool call to be fully approved before skipping the dialog, so a mixed batch (one fully-approved URL, one partially-approved URL) always falls back to the generic multi-URL prompt — which also explains why an already-approved domain is shown as needing review. The second phenomenon (the same GFM URL apparently succeeding without confirmation when fetched alone despite `approveRequest: false`) is not yet independently confirmed from source. This stays open per the security-sensitive hard keep-open rule regardless.

## Change summary

Report that fetch-tool URL approval behaves inconsistently depending on whether multiple URLs are requested together or individually, so the same URL can require confirmation in one case and not another.

## Best solution

Rework `_checkApproval`/`_getConfirmActions` in chatUrlFetchingConfirmation.ts to evaluate each URL in a batch independently (auto-approve the ones that are fully approved, only prompt for the unapproved subset) instead of requiring `urls.every(...)` to pass before any auto-approval kicks in; also confirm/reproduce the individual-vs-batched discrepancy for `approveRequest: false` entries before deciding on the request-approval semantics.
