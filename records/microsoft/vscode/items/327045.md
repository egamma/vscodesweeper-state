# Issue #327045 — Ctrl+/ (and possibly other editor keybindings) silently fail under native Wayland ozone platform; works when forced to X11

[https://github.com/microsoft/vscode/issues/327045](https://github.com/microsoft/vscode/issues/327045)

## Summary

A plausible keybinding dispatch failure under native Wayland with clear reproduction steps and a working workaround (forcing X11). Needs area owner investigation to determine if it's upstream (Chromium Wayland input) or caused by the recently-added GlobalShortcutsPortal feature flag.

## Change summary

Ctrl+/ (Toggle Line Comment) keybinding dispatch silently fails under native Wayland ozone platform while the same command works via Command Palette; forcing X11 resolves it.

## Best solution

Area owner should determine whether the GlobalShortcutsPortal Chromium feature (enabled unconditionally on Linux in src/main.ts since dd6118537b9) is intercepting the keystroke even without system-wide keybindings opted in. If so, scope the flag to only activate when the user has enabled system-wide keybindings. If it's a Chromium/Electron Wayland input bug independent of that flag, classify as upstream and file against Electron.
