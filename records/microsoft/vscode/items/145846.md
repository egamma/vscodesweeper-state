## Summary

The integration-test gap remains on current main: only a few Tabs API scenarios run end to end, while mutation and property tests are still commented out under a TODO referencing this issue. Keep this accepted On Deck debt open and plan a deterministic coverage expansion.

## Change summary

## Plan brief

- **Likely files:** `extensions/vscode-api-tests/src/singlefolder-tests/window.test.ts`, `src/vs/workbench/api/test/browser/extHostEditorTabs.test.ts`, `src/vs/workbench/api/test/browser/mainThreadEditorTabs.test.ts`
- **Validation:** ./scripts/test-integration.sh --grep "Tabs -" completes with the expanded Tabs API scenarios enabled and passing without retries introduced to mask races.
- **Behavior:**

  > The public Tabs API must report every tab and group event and property consistently before and after supported editor mutations. Integration coverage should exercise opening, closing, moving, activation, label, pinned/preview/sticky, dirty/saved, supported input kinds, and empty groups with workbench.editor.closeEmptyGroups disabled. Each test must target an identifiable tab or use an unambiguous isolated setup rather than relying on whichever editor happens to be active. Acceptance requires the filtered Tabs API integration suite to pass with the previously commented core state scenarios enabled and without race-masking retries.
- **Trace:**

  > The end-to-end Tabs API tests live in extensions/vscode-api-tests/src/singlefolder-tests/window.test.ts. Current main has three active scenarios around lines 409-529, followed by a TODO for https://github.com/microsoft/vscode/issues/145846 and disabled state tests around lines 531-641; older move and close examples around lines 646-729 are also block-commented. ExtHostEditorTabs model behavior is covered separately in src/vs/workbench/api/test/browser/extHostEditorTabs.test.ts, and selected workbench-to-extension-host updates are covered in src/vs/workbench/api/test/browser/mainThreadEditorTabs.test.ts. The uncertainty starts at the deterministic driver for each remaining end-to-end mutation: current stable TabGroups API offers targeted close operations, while pinning, preview conversion, and some activation flows still rely on workbench commands whose implicit target can race. Preserve the public API contract and existing unit-test boundary; the plan should inventory current coverage and identify a non-ambiguous driver for each missing integration case before adding tests.
