# Issue #292390 — Should we unify the workspace dropdown and add context widget on welcome page

[https://github.com/microsoft/vscode/issues/292390](https://github.com/microsoft/vscode/issues/292390)

## Summary

Keep open for a welcome-page design decision: current source still separates target-workspace selection from context attachments, so the reported discoverability concern remains relevant. No verified older canonical covers this same concern, and this team-authored request has no issue-referencing fix establishing completion.

## Change summary

Consider a unified welcome-page affordance for selecting a project target and attaching chat context.

## Best solution

Resolve whether Add Context should also expose project-target selection, while keeping the distinction between the execution workspace and reference attachments understandable. Apply the chosen interaction consistently to the welcome-page chat input without making an attached folder silently change the execution target.

- **Validation:** After choosing the interaction, open the Agent Sessions welcome page in an empty window with recent trusted workspaces. Verify that selecting a project target through the agreed affordance visibly identifies the execution target and submits into that workspace, while attaching a file or folder only adds reference context. Repeat with an existing workspace and verify keyboard access and accessible identification of the target versus attachments.
- **Behavior:**

  > Welcome-page users should understand where a chat request will execute and which items are only reference context, without guessing between the workspace dropdown and Add Context. User feedback specifically suggests looking in Add Context to choose the project target. Acceptance should demonstrate the agreed target-selection interaction, a visible selected target, and no unintended target change when adding reference attachments.
- **Trace:**

  > AgentSessionsWelcome constructs workspacePickerDelegate independently of the chat attachment model in src/vs/workbench/contrib/welcomeAgentSessions/browser/agentSessionsWelcome.ts; its selection feeds handleWorkspaceSubmission, which opens the selected workspace with a stored prompt. OpenWorkspacePickerAction in chatExecuteActions.ts registers the welcome-specific picker, and WorkspacePickerActionItem calls the delegate to select a target. AttachContextAction in chatContextActions.ts instead adds reference entries through attachmentModel.addContext. Current source therefore exposes two semantically distinct paths rather than proving that the requested unification has shipped. Preserve the distinction between execution target and reference context, and do not broaden this into the separate cross-provider repository-list/navigation work at https://github.com/microsoft/vscode/issues/290561. The remaining uncertainty is the desired user-facing relationship between the two controls, not a confirmed implementation defect.
- **Open decisions:**
  - Should Add Context expose target-workspace selection alongside reference attachments, replacing the standalone workspace dropdown, or should both controls remain with clearer differentiation?
