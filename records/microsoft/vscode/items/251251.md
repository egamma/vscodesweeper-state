# Issue #251251 — Feature Request: Add Temperature for Custom Agent Profiles

[https://github.com/microsoft/vscode/issues/251251](https://github.com/microsoft/vscode/issues/251251)

## Summary

A real capability gap remains: current main supports a global agent temperature and per-model BYOK sampling options, but custom agent profiles cannot select their own temperature. With 85 upvotes and Backlog promotion, this should remain open while maintainers decide whether sampling belongs in agent frontmatter or a model/workspace-level configuration.

## Change summary

Allow shareable custom agent profiles to select task-appropriate model temperature or equivalent sampling options.

## Best solution

Define a validated, opt-in sampling configuration with explicit precedence over global and model defaults, then make it selectable per custom agent if maintainers accept profile-level ownership. The design must avoid sending unsupported parameters to models and leave profiles without an override unchanged.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/chatModes.ts`, `extensions/copilot/src/extension/intents/node/agentIntent.ts`
- **Validation:** Extend the prompt parser/validator and chat mode service tests so the selected configuration survives custom-agent loading, then add an agent request test showing two profiles using the same model produce their configured sampling values while a profile without an override retains existing behavior.
- **Behavior:**

  > Users can maintain task-specific, shareable agent configurations whose selected sampling behavior differs even when they use the same model. Switching agents changes the sampling option used for subsequent requests, while agents without an override retain today's default behavior. Invalid values are diagnosed before a request, and models that cannot accept the configured parameter are handled according to the contract chosen by the maintainer. Acceptance includes two profiles producing distinct request options and an unconfigured profile remaining unchanged.
- **Trace:**

  > Current custom-agent parsing starts in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts, validation and completion metadata live under promptSyntax/languageProviders, and parsed data is represented by ICustomAgent in promptsService.ts before CustomChatMode carries it into chat requests. None of those custom-agent structures currently contains temperature, although reasoning effort already follows a similar profile-scoped path. In the Copilot extension, AgentIntent.getIntentHandlerOptions in extensions/copilot/src/extension/intents/node/agentIntent.ts obtains temperature only from the global ConfigKey.Advanced.AgentTemperature setting. BYOK model configuration separately supports `modelOptions.temperature`, so the plan must preserve model-level configuration and resolve precedence rather than treating the closed BYOK compatibility bug https://github.com/microsoft/vscode/issues/254675 as this request. The boundary is custom-agent sampling selection and its request propagation; do not redesign model discovery or general BYOK transport.
- **Open decisions:**
  - Should task-specific sampling be a custom-agent frontmatter contract, a workspace/model configuration selected by the agent, or both?
  - When profile, global agent, per-model, and explicit per-request values conflict, which observable precedence order should users be able to rely on?
  - Should the public contract expose only temperature or a bounded set of sampling options, and should unsupported options be omitted with a diagnostic or reject the request before it is sent?

## Evidence

- **current source gap:** On current main, src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts defines custom-agent `model` and `reasoning-effort` attributes but no temperature attribute; src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts exposes the same limited custom-agent schema, and ICustomAgent in src/vs/workbench/contrib/chat/common/promptSyntax/service/promptsService.ts has no sampling field.
- **existing global control:** extensions/copilot/package.json registers the advanced `github.copilot.chat.agent.temperature` setting, and extensions/copilot/src/extension/intents/node/agentIntent.ts reads ConfigKey.Advanced.AgentTemperature for every agent request. This permits global tuning but not the requested quick switching between profile-specific values.
- **existing model control:** extensions/copilot/package.json now permits `modelOptions.temperature` and `modelOptions.top_p` for configured custom models. That addresses model-level BYOK defaults, not different temperatures for multiple custom agents using the same model.
