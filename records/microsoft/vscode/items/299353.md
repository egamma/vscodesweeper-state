# Issue #299353 — [Keybinding] Ctrl+Enter in Find/Replace invokes `editor.action.replaceOne` twice (Windows 11, Korean IME)

[https://github.com/microsoft/vscode/issues/299353](https://github.com/microsoft/vscode/issues/299353)

## Summary

The duplicate-dispatch path remains in current source, and an independent commenter reproduced the behavior on macOS as well. Keep this open while the existing fix proposal is reviewed; the linked PR has not merged.

## Change summary

A single Ctrl+Enter in the Replace input executes a user-bound replace-one command twice.

## Best solution

Review and land a suitable fix through https://github.com/microsoft/vscode/pull/301635 so a handled Ctrl+Enter invokes its command once, while preserving multiline input behavior when no command matches.

## Evidence

- **Current source confirms double dispatch:** src/vs/editor/contrib/find/browser/findWidget.ts:932–940 handles Ctrl+Enter in _onReplaceInputKeyDown by calling _keybindingService.dispatchEvent(e, e.target), then preventDefault(), without stopping propagation. src/vs/workbench/services/keybinding/browser/keybindingService.ts:274–290 registers a window keydown listener that dispatches the bubbling event again without checking defaultPrevented. AbstractKeybindingService.dispatchEvent delegates directly to _dispatch in src/vs/platform/keybinding/common/abstractKeybindingService.ts:143–145. This matches the reporter's two command invocations for one key press.
- **Existing implementation candidate:** https://github.com/microsoft/vscode/pull/301635 is OPEN with no merge commit, and its body explicitly says 'Fix #299353'. Its diff adds stopPropagation() to the Ctrl+Enter handling branches in both Find and Replace inputs. This is an active fix candidate, not evidence that the issue is completed.
- **Reproduction and workaround in discussion:** The discussion on https://github.com/microsoft/vscode/issues/299353 records reproduction on a fresh profile with VS Code 1.110.0, an independent reproduction on macOS with 1.112.0-insider, and a working Alt+Enter remapping. The source's special Ctrl+Enter branch explains why changing the modifier avoids the extra dispatch; the evidence does not establish a Korean-IME-only defect.
