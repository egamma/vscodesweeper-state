# Issue #299353 — [Keybinding] Ctrl+Enter in Find/Replace invokes `editor.action.replaceOne` twice (Windows 11, Korean IME)

[https://github.com/microsoft/vscode/issues/299353](https://github.com/microsoft/vscode/issues/299353)

## Summary

Confirmed bug with an open fix PR (#301635) from a contributor — the replace input's Ctrl+Enter handler dispatches the command but doesn't stop event propagation, allowing a second dispatch. Keeping open pending the PR.

## Change summary

Ctrl+Enter in the Find/Replace widget's replace input invokes `editor.action.replaceOne` twice due to missing event propagation stop.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/301635 which adds `stopPropagation()` on the Enter key in find/replace inputs — the fix is in the right area (`_onReplaceInputKeyDown` in `findWidget.ts` line 934). Ensure it doesn't break multiline-insert behavior for Ctrl+Enter when no keybinding matches.

## Evidence

The event bubbles and gets dispatched a second time through the editor's key dispatch path.
- **contributor reproduction:** tamuratak (CONTRIBUTOR) confirmed reproduction on macOS with Insiders 1.112.0 (comment 4).

- **reporter workaround:** Remapping to Alt+Enter avoids the double dispatch, confirming it's specific to the Ctrl+Enter dispatch path.
