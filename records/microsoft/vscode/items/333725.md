# Issue #333725 — Support opening an Agents Window chat for a folder from the CLI

[https://github.com/microsoft/vscode/issues/333725](https://github.com/microsoft/vscode/issues/333725)

## Summary

This team-authored Backlog request remains necessary: `--agents` opens the Agents Window, but the startup path does not resolve or forward the positional folder to the new-session composer. The existing `folderUri` handoff provides most of the downstream capability, leaving a focused CLI integration gap.

## Change summary

Allow `code ./foo --agents` to open the Agents Window's New Chat view with `./foo` selected as its workspace.

## Best solution

Make the Agents Window CLI entry point interpret a folder operand and open a fresh composer scoped to that folder, using the existing workspace handoff consistently in Stable and Insiders. Define predictable behavior for unsupported or multiple positional operands rather than silently ignoring them.

## Plan brief

- **Likely files:** `src/vs/code/electron-main/app.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`, `src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts`, `src/vs/sessions/contrib/chat/test/electron-browser/agentsWindowWorkspaceHandoff.test.ts`
- **Validation:** Add a focused main-process or CLI integration test for parsed arguments equivalent to `code ./foo --agents`, asserting that the resolved folder URI reaches `openAgentsWindow`; retain a workspace-handoff test proving the Agents Window opens a fresh composer with that folder selected. Manually verify the same command with both Stable and Insiders launchers.
- **Behavior:**

  > Running `code ./foo --agents` or `code-insiders ./foo --agents` opens or focuses the Agents Window, presents the New Chat composer, and selects `./foo` as that chat's workspace. The command must not open `./foo` as a normal editor window or silently discard the folder. Invalid or unsupported operands should produce predictable behavior, and ordinary `code ./foo` plus folderless `code --agents` behavior must remain unchanged.
- **Trace:**

  > The `--agents` option is registered in src/vs/platform/environment/node/argv.ts. In src/vs/code/electron-main/app.ts, `openFirstWindow` handles it before the normal window-open flow and calls `IWindowsMainService.openAgentsWindow` without translating positional `args._`, so the folder is lost. `WindowsMainService.openAgentsWindow` in src/vs/platform/windows/electron-main/windowsMainService.ts already carries an optional `folderUri` over `vscode:selectAgentsFolder`; `SelectAgentsFolderContribution` and `AgentsWindowWorkspaceHandoff` under src/vs/sessions/contrib/chat then support selecting that workspace in a fresh composer. The boundary is CLI intent translation and its handoff: preserve normal editor-window path opening, protocol-link behavior, existing-session precedence, and occupied-draft protection. The broader and younger https://github.com/microsoft/vscode/issues/335015 is related parity context, not a canonical duplicate.
- **Open decisions:**
  - When `--agents` receives multiple folder operands or a workspace-file operand, should the command reject the input, select one folder, or create a multi-folder session?

## Evidence

- **CLI gap on main:** In src/vs/code/electron-main/app.ts, `openFirstWindow` detects `args['agents']` and calls `windowsMainService.openAgentsWindow(...)` without resolving or passing `args._`; consequently the positional `./foo` operand is not supplied as `folderUri`.
- **existing downstream capability:** src/vs/platform/windows/electron-main/windowsMainService.ts already accepts `folderUri` in `openAgentsWindow` and sends it through `vscode:selectAgentsFolder`; src/vs/sessions/contrib/chat/electron-browser/chat.contribution.ts and `AgentsWindowWorkspaceHandoff` can open a new session composer and select that folder.
- **existing CLI path resolver:** src/vs/platform/windows/electron-main/windowsMainService.ts `doExtractPathsFromCLI` already resolves positional paths and `--folder-uri`, but the `--agents` early path in `openFirstWindow` bypasses that normal open flow.
