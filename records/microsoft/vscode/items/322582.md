# Issue #322582 — Typed Text Doesn't Show Up in Separate Terminal Window When Main Window is Minimized

[https://github.com/microsoft/vscode/issues/322582](https://github.com/microsoft/vscode/issues/322582)

## Summary

Legitimate rendering bug: terminal text in an auxiliary (floating) window stops painting when the main VS Code window is minimized on Windows 11. Likely caused by Electron/Chromium background-throttling the renderer process when its main BrowserWindow is minimized. No fix found on current main. Related to but distinct from #317487 (which is about process execution throttling, not rendering). Routing to terminal-rendering and workbench-auxwindow.

## Change summary

Typed text in a separate terminal window is invisibly buffered and not rendered until the main VS Code window is unminimized on Windows.

## Best solution

Investigate whether the auxiliary window's rendering is blocked by Chromium's page-visibility or background-throttling policy when the main window is minimized. VS Code already has `noBackgroundThrottling` infrastructure for auxiliary windows (used by the agents voice window) but doesn't apply it to terminal auxiliary windows. A possible mitigation is opting terminal auxiliary windows into `noBackgroundThrottling`, or setting `backgroundThrottling: false` on the main window's webPreferences. If the root cause is deeper in Electron/Chromium's process-level throttling (Windows 11 efficiency mode), an upstream Electron issue may be needed. See also https://github.com/microsoft/vscode/issues/317487 for a related but broader throttling report.
