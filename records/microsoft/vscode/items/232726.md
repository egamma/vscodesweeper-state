# Issue #232726 — Hover: Consider changing defaults

[https://github.com/microsoft/vscode/issues/232726](https://github.com/microsoft/vscode/issues/232726)

## Summary

The hover defaults remain inconsistent on current main: compact and pointer defaults depend on the API path and whether callers select a HoverStyle. Keep this open for a coordinated design decision with the broader hover API cleanup.

## Change summary

Standardize whether workbench hovers are compact and show a pointer by default, reducing per-consumer appearance configuration.

## Best solution

Define one documented workbench-hover style policy with compact presentation as the common default, then apply it consistently across direct, delayed, mouse-positioned, and legacy delegate paths while retaining non-compact rendering only if a concrete use case requires it.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/hover/hover.ts`, `src/vs/platform/hover/browser/hover.ts`, `src/vs/platform/hover/browser/hoverService.ts`, `src/vs/platform/hover/browser/hoverWidget.ts`, `src/vs/platform/hover/test/browser/hoverService.test.ts`
- **Validation:** Extend src/vs/platform/hover/test/browser/hoverService.test.ts to assert the chosen compact and pointer defaults for direct, delayed, mouse-positioned, styled, and explicitly overridden hovers, then run that browser unit-test suite.
- **Behavior:**

  > Equivalent simple workbench hovers should use a consistent compact presentation without every consumer repeating appearance options. Element-targeted and mouse-positioned hovers should follow a documented pointer policy, while explicit supported overrides remain effective. Acceptance should cover each public IHoverService entry point and verify that rich or non-compact hovers behave according to the maintainer-selected scope.
- **Trace:**

  > WorkbenchHoverDelegate.showHover in src/vs/platform/hover/browser/hover.ts always supplies `compact: true`. HoverWidget in src/vs/platform/hover/browser/hoverWidget.ts applies compact and pointer defaults only when HoverStyle.Pointer or HoverStyle.Mouse is present, while setupDelayedHoverAtMouse in src/vs/platform/hover/browser/hoverService.ts does not inject a style; callers consequently produce different presentation from equivalent APIs. Commit 6e2189943e5f47c4dcf15e1f4d5b77d4f8c5ce76 and https://github.com/microsoft/vscode/pull/270313 introduced the partial HoverStyle abstraction. The broader follow-up https://github.com/microsoft/vscode/issues/243348 confirms that compact and pointer policy remains unsettled. Keep the boundary to workbench hover appearance defaults: do not alter hover timing, positioning, persistence, focus handling, or editor-language hover behavior.
- **Open decisions:**
  - Should every workbench hover default to compact presentation with non-compact styling removed, or should rich/direct hovers retain an explicit non-compact mode?
  - Should element-targeted delayed hovers show a pointer by default, or only when the caller explicitly selects HoverStyle.Pointer?

## Evidence

- **current source:** src/vs/platform/hover/browser/hoverWidget.ts defaults `compact` for HoverStyle.Pointer and HoverStyle.Mouse and defaults `showPointer` only for HoverStyle.Pointer, but leaves both unset when no style is supplied.
- **API inconsistency:** src/vs/platform/hover/browser/hoverService.ts setupDelayedHoverAtMouse does not assign HoverStyle.Mouse or compact appearance; current callers therefore mix explicit `appearance: { compact: true }` with omitted appearance options.
- **legacy path:** src/vs/platform/hover/browser/hover.ts WorkbenchHoverDelegate.showHover independently forces `compact: true`, so behavior differs between legacy and newer IHoverService paths.
- **partial implementation:** https://github.com/microsoft/vscode/pull/270313 introduced HoverStyle and style-dependent defaults in commit 6e2189943e5f47c4dcf15e1f4d5b77d4f8c5ce76, but did not make compact the unconditional IHoverService default or remove non-compact styling.
- **related design work:** https://github.com/microsoft/vscode/issues/243348 remains open and explicitly records that `compact: true` needs clear guidelines and that element hovers may default to `showPointer: true`; it is broader but newer than this re-reviewed issue, so it is not a valid duplicate canonical.
- **maintainer direction:** https://github.com/microsoft/vscode/issues/232726#issuecomment-2470174356 supports compact as the default, while https://github.com/microsoft/vscode/issues/232726#issuecomment-2470308147 indicates openness to removing non-compact workbench hover styling entirely.
