# Issue #169749 — Relative line numbers should change while folding (like in VIM). 

[https://github.com/microsoft/vscode/issues/169749](https://github.com/microsoft/vscode/issues/169749)

## Summary

Keep open: current relative numbering still counts hidden model lines, with no user setting for fold-aware counting. This accepted Backlog request has 22 upvotes, and the earlier implementation was reverted rather than made optional.

## Change summary

Provide optional relative numbering that counts a collapsed region as one line, matching fold-preserving Vim navigation.

## Best solution

Offer opt-in fold-aware relative numbering in the editor while preserving today's default for existing yank/delete workflows. Keep extension-specific Vim motion and operator behavior separate from the core numbering contract.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** The plan should define an automated rendering check plus a manual acceptance case: collapse lines 2–10, place the cursor on line 1, and verify line 11 shows relative distance 2 in the opt-in mode and 10 in the existing mode. Repeat above the cursor, after expanding the fold, and with wrapping enabled; existing numbering modes must remain unchanged.
- **Behavior:**

  > Users can opt into relative distances that exclude hidden lines inside collapsed regions, with each collapsed region contributing one line. Expanding or collapsing a region updates the displayed distances on either side of the cursor. Existing relative numbering remains the default so model-line-based workflows retain their current behavior. Acceptance includes folded regions above and below the cursor, fold expansion, and an explicitly agreed wrapping contract.
- **Trace:**

  > LineNumbersOverlay._getLineRenderLineNumber in src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts converts each view row to a model position and subtracts model line numbers; it also suppresses numbers on wrapped continuation rows. EditorRenderLineNumbersOption in src/vs/editor/common/config/editorOptions.ts exposes no fold-aware mode. https://github.com/microsoft/vscode/pull/155970 previously introduced folded-region skipping, and https://github.com/microsoft/vscode/pull/159236 reverted it after the workflow concerns in https://github.com/microsoft/vscode/issues/157282. Preserve the current default and do not assume numbering changes implement Vim motions or whole-fold operators; https://github.com/VSCodeVim/Vim/issues/8775 tracks that extension-side mismatch. The distinct wrapped-row request at https://github.com/microsoft/vscode/issues/323238 should inform, but not silently broaden, this feature's contract.
- **Open decisions:**
  - Should the opt-in mode count only unfolded logical lines, retaining blank wrapped continuation gutters, or count visual rows and number wrapped continuations as well? The latter overlaps the separate request at https://github.com/microsoft/vscode/issues/323238.
