[https://github.com/microsoft/vscode/issues/332295](https://github.com/microsoft/vscode/issues/332295)

## Summary

Reasonable feature request with no existing capability on main — SDK versions for Claude/Codex are bundled and bumped manually via a deliberate, gated process (private-feed quarantine, protocol regeneration), not something to auto-track to 'latest'. No duplicate or precedent found, so this stays open for product discussion.

## Change summary

Automatically pick the latest @anthropic-ai/claude-agent-sdk or @openai/codex-sdk version (or allow a user-specified local SDK path) instead of requiring a manual bundled-version bump PR.

## Best solution

This needs a maintainer decision: bundled SDK versions are pinned deliberately (build/agent-sdk/agents/claude/package.json, package.json for @openai/codex) and bumped via a controlled process (see .agents/skills/update-codex-sdk, which selects versions from a private feed with a 7-day quarantine and regenerates the protocol client) — 'auto-pick latest' would bypass that safety net. A narrower ask (e.g. a settings override for a local SDK path for development/testing) might be more tractable than always-latest in production.
