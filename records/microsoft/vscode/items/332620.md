# Issue #332620 — Editor group restore scrambles MRU order and preview editor when an editor fails to deserialize

[https://github.com/microsoft/vscode/issues/332620](https://github.com/microsoft/vscode/issues/332620)

## Summary

Confirmed in current source: EditorGroupModel.deserialize compacts this.editors via coalesce() but then indexes the original serialized data.mru/data.preview into that already-compacted array, so MRU order and preview can point at the wrong editor whenever a dead editor is skipped. An open PR already targets this exact fix, so the issue should stay open for review rather than being closed or auto-fixed.

## Change summary

When a group has a dead (undeserializable) editor, restoring the group scrambles MRU recency order and the preview editor because indices aren't remapped after coalescing.

## Best solution

Land (or continue reviewing) https://github.com/microsoft/vscode/pull/332630, which remaps data.mru and data.preview through an old-to-new index map built during the coalesce pass in src/vs/workbench/common/editor/editorGroupModel.ts.
