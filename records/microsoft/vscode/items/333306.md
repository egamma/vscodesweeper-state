# Issue #333306 — terminal.integrated.hideOnStartup: "always" shows, hides, then re-shows the terminal panel when a workspace with a folderOpen task is reopened while VS Code is frontmost

[https://github.com/microsoft/vscode/issues/333306](https://github.com/microsoft/vscode/issues/333306)

## Summary

Traced conclusively in current source: TerminalViewPane._initializeTerminal calls hidePanel() unconditionally for hideOnStartup='always' before checking whether a folderOpen task already created and revealed a terminal, producing the show-hide-reshow flash the reporter describes; this needs a maintainer decision on how 'always' should interact with task-created terminals, so keeping open rather than closing.

## Change summary

With terminal.integrated.hideOnStartup set to 'always', reopening a workspace whose folderOpen task reveals a terminal shows the panel, hides it, then re-shows it — a visible flash — when VS Code is already frontmost.

## Best solution

In src/vs/workbench/contrib/terminal/browser/terminalView.ts, only call hidePanel() for the 'always' case after (or conditioned on) the shouldCreate/groups-already-exist check used for 'whenEmpty', so a task-populated panel isn't hidden and then immediately re-shown; the exact semantics (should 'always' still hide restored persistent sessions but not freshly task-created terminals?) need a maintainer call given the setting's documented 'even when persistent sessions are restored' behavior.
