# Issue #288838 — [Feature Request] Add frontmatter option to open .prompt.md files in a new chat session

[https://github.com/microsoft/vscode/issues/288838](https://github.com/microsoft/vscode/issues/288838)

## Summary

This remains a valid Backlog feature request with 23 community upvotes. Current main supports explicit modifier-based execution in a new chat, but prompt frontmatter cannot declaratively request that behavior.

## Change summary

Allow a `.prompt.md` file to declare that invoking it should start and run in a fresh chat session.

## Best solution

Define invocation semantics for a boolean prompt-file attribute, then honor it at the prompt invocation boundary while preserving current-chat behavior when the attribute is absent or false. The design should cover both command-driven execution and slash-command invocation without losing prompt arguments or attachments.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptValidator.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/promptSyntax/languageProviders/promptValidator.test.ts`
- **Validation:** Extend prompt validator tests to cover an accepted boolean `newChat` attribute and add a prompt invocation test proving `newChat: true` creates a fresh session before submission while absent or false metadata retains the current session.
- **Behavior:**

  > A prompt file can declare that invoking it starts a fresh chat session before its content is submitted. Prompt files without the attribute, or with it set to false, continue in the current chat exactly as today. Prompt arguments and any invocation context that the chosen contract preserves must arrive in the new session, and the existing explicit Run Prompt In New Chat action must remain functional.
- **Trace:**

  > Current explicit new-chat execution is implemented in RunPromptBaseAction.execute and RunSelectedPromptAction in src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts by running `ACTION_ID_NEW_CHAT` before resolving and submitting the slash command. PromptHeaderAttributes in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts has no `newChat` key, and the prompt attribute registry and validator likewise omit it. Typed slash commands are resolved later by ChatWidget._applyPromptFileIfSet in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts, after the user has already submitted within a session; that path establishes where the design uncertainty begins. Preserve existing behavior for absent or false metadata and avoid changing agent handoff semantics tracked separately by https://github.com/microsoft/vscode/issues/301044.
- **Open decisions:**
  - Should `newChat: true` apply to every prompt invocation, including a slash command typed and submitted inside an existing conversation, or only to Run Prompt commands and picker actions?
  - When invocation moves to a new session, which caller state must be preserved: prompt arguments only, or also attachments and other pending input context?
  - If the prompt is already being invoked in an empty new session, should the implementation reuse that session or always create another one?

## Evidence

- **backlog demand:** The issue has 23 community upvotes and was explicitly moved to the Backlog by the triage bot on 2026-01-24, exceeding the 20-upvote promotion threshold.
- **existing partial capability:** src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts implements `Run Prompt In New Chat` and Ctrl/Cmd-modified prompt selection by executing `ACTION_ID_NEW_CHAT` before submitting the prompt, but this requires an invocation-time UI choice.
