# Issue #167306 — Gutter for local history modification

[https://github.com/microsoft/vscode/issues/167306](https://github.com/microsoft/vscode/issues/167306)

## Summary

Keep this accepted Backlog request open: current local history supports snapshot comparisons, but not Git-independent gutter markers with reset controls. It has 25 upvotes, and the related quick-diff API proposal enables potential implementations rather than delivering this behavior.

## Change summary

Provide local-history change gutters outside Git repositories, with a reset command and configurable reset on workspace reopening.

## Best solution

Provide an opt-in, Git-independent change-marker experience integrated with local history, preserving existing SCM gutters and stored history. Agree on the comparison baseline and reset semantics before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/localHistory/browser/localHistory.contribution.ts`, `src/vs/workbench/contrib/localHistory/browser/localHistoryCommands.ts`, `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/contrib/scm/common/quickDiffService.ts`
- **Validation:** After agreeing on baseline semantics, open a file in a workspace without Git, enable the feature, and make additions, modifications, and deletions; verify gutter markers match the baseline before and after saving. Invoke reset and confirm markers clear without deleting history or changing file contents. Reopen the workspace with automatic reset enabled and disabled and verify the agreed persistence behavior; confirm existing Git gutters remain unchanged.
- **Behavior:**

  > Users editing files outside a Git repository can opt into local-history change markers in the ordinary editor gutter. They can reset those markers explicitly and choose whether reopening the workspace resets them automatically. Acceptance must cover additions, modifications, deletions, saves, manual reset, and both reopening modes. Resetting markers must not alter file contents or erase local-history snapshots, and existing SCM behavior must remain unchanged.
- **Trace:**

  > Current local history is exposed through LocalHistoryTimeline in src/vs/workbench/contrib/localHistory/browser/localHistoryTimeline.ts and snapshot commands in localHistoryCommands.ts; compareWithFile opens a separate diff editor. The settings in src/vs/workbench/browser/workbench.contribution.ts cover snapshot recording and retention, not gutter baselines. QuickDiffService in src/vs/workbench/contrib/scm/common/quickDiffService.ts supplies comparison resources from registered providers, with no inspected local-history registration. https://github.com/microsoft/vscode/issues/169012 tracks a related proposed extension API, not this end-user capability, and is younger than this issue. The remaining uncertainty is which original contents the markers compare against and how that baseline survives saves and workspace reopening. Preserve snapshot retention, restoration, and existing SCM gutter behavior; the file list identifies starting surfaces rather than a prescribed patch.
- **Open decisions:**
  - What establishes the initial comparison baseline: file contents when first opened, a selected local-history snapshot, or another defined point?
  - Should saving preserve accumulated markers until explicit or workspace-reopen reset, or advance the comparison baseline?
