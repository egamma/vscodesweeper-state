# Issue #332151 — Add a mechanism to prevent infinite loops for Agent

[https://github.com/microsoft/vscode/issues/332151](https://github.com/microsoft/vscode/issues/332151)

## Summary

A total-request limit already bounds Agent runs, but current main has no mechanism for detecting repeated tool-call cycles before that limit. The broader early-loop-detection request remains valid and is not absorbed by the older model-specific reports.

## Change summary

Detect recurring Agent tool-call or response patterns and interrupt them before they consume the full request allowance.

## Best solution

Add a repeat-aware circuit breaker to the Agent tool-calling loop while preserving the existing `chat.agent.maxRequests` limit as the final safety bound. The design should distinguish genuine non-progress cycles from legitimate repeated commands and define whether detection stops automatically or asks the user to continue.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/intents/node/toolCallingLoop.ts`, `extensions/copilot/src/extension/intents/test/node/toolCallingLoopAutopilot.spec.ts`
- **Validation:** Add focused tool-calling-loop tests showing that a selected repeated non-progress pattern is interrupted before `chat.agent.maxRequests`, while progressive calls and legitimate repeated operations continue normally.
- **Behavior:**

  > Agent runs should identify recurring tool-call or response cycles that make no progress and interrupt them before exhausting the normal request allowance. Legitimate repetition, such as running the same command after relevant state changes, must remain possible. The existing `chat.agent.maxRequests` safety limit and its continuation behavior must continue to work for runs that do not trigger loop detection.
- **Trace:**

  > The top-level Agent receives `maxToolCallIterations` from `getAgentMaxRequests` in extensions/copilot/src/extension/intents/node/agentIntent.ts. `DefaultIntentRequestHandler` passes it into `ToolCallingLoop`, whose `_runLoop` in extensions/copilot/src/extension/intents/node/toolCallingLoop.ts currently tracks rounds and stops only when the aggregate count reaches `toolCallLimit`; no repeated-round analysis exists. Existing reports at https://github.com/microsoft/vscode/issues/330633, https://github.com/microsoft/vscode/issues/303378, and https://github.com/microsoft/vscode/issues/335214 show model-specific variants of the same broad failure mode. The boundary is Agent loop control: preserve individual tool execution semantics, provider behavior, and the existing maximum-request fallback.
- **Open decisions:**
  - Which observable pattern constitutes a loop: identical tool name and arguments, identical results as well, or a recurring multi-round sequence?
  - When a loop is detected, should Agent stop automatically or present the existing continue-or-cancel confirmation?
  - Should the safeguard initially cover only the Copilot Chat tool-calling loop, or all provider-backed Agent experiences exposed by VS Code?

## Evidence

- **existing safety bound:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.agent.maxRequests` as the per-turn request limit, with defaults of 50 generally and 1000 in the Agents Window.
- **current loop behavior:** extensions/copilot/src/extension/intents/node/toolCallingLoop.ts `_runLoop` checks only the aggregate `toolCallLimit`; normal Agent runs ask whether to continue, while Autopilot can extend up to its hard cap. No repeated tool name, arguments, result, or recurring-round sequence is examined.
- **related older report:** https://github.com/microsoft/vscode/issues/330633 is open and reports Kimi K3 entering text-generation or tool-calling loops, but it is a model-specific defect report and does not own this broader cross-model prevention mechanism.
- **additional reports:** https://github.com/microsoft/vscode/issues/303378 reports an older same-information loop, while https://github.com/microsoft/vscode/issues/335214 provides a newer concrete example of identical file searches recurring under Gemini 3.8; together they support a cross-model safeguard without making either report a canonical duplicate for this broader request.
