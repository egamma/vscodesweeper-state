# Issue #230425 — Cannot set working directory when opening a new terminal when using vscode remotes (WSL and SSH)

[https://github.com/microsoft/vscode/issues/230425](https://github.com/microsoft/vscode/issues/230425)

## Summary

Still reported as reproducing on 1.108.2 (Jan 2026) — the cwd picker flow sends shellLaunchConfig.cwd through the remote DTO correctly, but something in the WSL remote path drops it. No fixing commit found on main. The reporter confirms it works locally but not via WSL or SSH remotes in multi-root workspaces. Keeping open for terminal team investigation.

## Change summary

Selecting a working directory from the multi-root workspace picker when opening a new terminal in WSL/SSH remote is ignored — the terminal opens in the home directory instead.

## Best solution

The terminal team (likely @Tyriar or @meganrogge) should reproduce on WSL with a multi-root workspace and trace why the cwd from the picker is lost between the client-side DTO serialization and the server-side `getCwd()` call in `src/vs/server/node/remoteTerminalChannel.ts`. The `shellLaunchConfig.cwd` appears to be sent correctly, so the issue may be in URI transformation or workspace folder resolution on the remote side.
