# Issue #230425 — Cannot set working directory when opening a new terminal when using vscode remotes (WSL and SSH)

[https://github.com/microsoft/vscode/issues/230425](https://github.com/microsoft/vscode/issues/230425)

## Summary

Keep open: the reporter reconfirmed that selecting a workspace folder opens the terminal in the remote home directory on both WSL and SSH. The apparent resolution was withdrawn, and the related older reports do not establish a same-symptom duplicate.

## Change summary

New terminals in remote multi-root workspaces should start in the folder selected in the working-directory picker rather than the remote home directory.

## Best solution

Restore reliable propagation of the selected remote working directory through terminal creation and shell startup. First distinguish an incorrect launch directory from a shell startup script changing directories; the current source preserves the selection on the inspected path, so the failing boundary remains unidentified.
