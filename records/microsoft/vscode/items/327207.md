# Issue #327207 — MCP model access permissions fail silently, making working servers appear broken

[https://github.com/microsoft/vscode/issues/327207](https://github.com/microsoft/vscode/issues/327207)

## Summary

Confirmed on main: the ModelMatch.NotAllowed path in McpSamplingService throws McpError.notAllowed() with no user-facing notification, unlike the sibling NoMatchingModel path which does prompt — a real discoverability gap worth routing to the MCP area owner; the reporter has already traced it precisely and volunteered a focused PR.

## Change summary

When an MCP server's sampling request is denied because the selected model isn't allowlisted, VS Code should surface an actionable message/prompt instead of failing silently.

## Best solution

Extend `_getMatchingModel` in src/vs/workbench/contrib/mcp/common/mcpSamplingService.ts so the `ModelMatch.NotAllowed` branch (currently just `throw McpError.notAllowed()` at line 162) shows a notification/contextual prompt with a 'Configure Model Access' action, mirroring the existing `NoMatchingModel` handling at lines 163-176; the reporter's proposed PR direction looks sound and could be reviewed.
