# Issue #265401 — Endless `git rev-parse --show-toplevel` output when copilot is enabled

[https://github.com/microsoft/vscode/issues/265401](https://github.com/microsoft/vscode/issues/265401)

## Summary

Still reproduces on main: the git extension's `openRepository` spawns `git rev-parse --show-toplevel` for every candidate path without caching negative results, causing thousands of redundant process spawns when Copilot triggers discovery on non-git folders. An open PR (#313856) exists to fix this but has not yet merged.

## Change summary

Opening a non-git folder that contains git repos in subfolders triggers thousands of repeated `git rev-parse --show-toplevel` calls, making VS Code and the system unresponsive for ~10 minutes.

## Best solution

Land https://github.com/microsoft/vscode/pull/313856, which adds a fast-path in `Model.openRepository` (extensions/git/src/model.ts) to skip `rev-parse` for paths already inside an opened repository. This directly addresses the hot loop traced in the source.

## Evidence

- **hot path on main:** extensions/git/src/model.ts:617 calls `getRepositoryRoot(repoPath)` which calls `this.git.getRepositoryRoot()` at extensions/git/src/git.ts:505, spawning `git rev-parse --show-toplevel`. When the path is not a git repo, the error is thrown and caught but no negative result is cached — the next call for the same or a sibling path repeats the spawn.
- **open fix PR:** https://github.com/microsoft/vscode/pull/313856 ('Avoid unnecessary git rev parse calls') on branch dev/dmitriv/git-rev-parse-perf adds a fast-path to skip rev-parse for paths inside already-opened repositories. Still open, not merged to main.
- **team engagement:** Team member @lszomoru asked about workspace indexing in comment 1; team member @halflumi confirmed the impact in comment 3.
- **community confirmation:** Comment 6 by @luluu9 provides a detailed reproduction: opening a parent folder that is not a git repo but contains a git subfolder triggers the loop. Disabling `git.enabled` stops the spam, confirming the calls go through the built-in git extension.
