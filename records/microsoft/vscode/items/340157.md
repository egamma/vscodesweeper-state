# Issue #340157 — Agent Host: first-turn materialization waits ~8.5s after SDK initialization

[https://github.com/microsoft/vscode/issues/340157](https://github.com/microsoft/vscode/issues/340157)

## Summary

A thorough, well-diagnosed performance report on first-turn Agent Host materialization. I verified in the checkout that `AgentHostGitService.getRepositoryRoot` (src/vs/platform/agentHost/node/agentHostGitService.ts) serializes same-directory lookups via `SequencerByKey` and caches only successful roots in the `LRUCache`, never negative results — exactly the amplification mechanism the reporter describes — but the reporter themselves say attribution to this specific 8.45s delay (git queueing vs. the persistence sequencer in `_materializeProvisional`) is not yet confirmed, so a fix can't be scoped safely yet.

## Change summary

First-turn Agent Host session materialization in non-Git folders can take ~8.5s after SDK initialization before provider dispatch, suspected to be caused by serialized/uncached negative Git repository-root probes.

## Best solution

Add the instrumentation the reporter proposes (Git operation IDs, enqueue/queue-entry/subprocess timings, persistence-await timings) to confirm whether `getRepositoryRoot`'s negative-lookup queueing or the metadata persistence sequencer is the actual bottleneck, then fix the confirmed cause (e.g. cache negative Git lookups with a short TTL) in agentHostGitService.ts / copilotAgent.ts.

## Evidence

- **no negative caching:** src/vs/platform/agentHost/node/agentHostGitService.ts `getRepositoryRoot`: on a failed `git rev-parse --show-toplevel` the catch block returns `undefined` without ever writing to `this._repositoryRoots` (the LRUCache), so every call for a non-repo directory re-spawns git.
- **per-key serialization:** `SequencerByKey.queue` (src/vs/base/common/async.ts:338) chains all calls for the same key through `.then()`, so concurrent lookups for one directory run strictly sequentially, matching the reporter's 8-caller/8-probe experiment.
- **call site:** `_materializeProvisional` (src/vs/platform/agentHost/node/copilot/copilotAgent.ts:4622) starts `projectFromCopilotContext` alongside SDK launch and awaits it before persisting metadata — matching the reported milestone ordering.
