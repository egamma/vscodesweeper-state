# Issue #139652 — Support no value for editorSuggestWidget.selectedIconForeground

[https://github.com/microsoft/vscode/issues/139652](https://github.com/microsoft/vscode/issues/139652)

## Summary

Keep open: current theme customization can reset a color to its registered default, but cannot explicitly disable the selected-icon override while retaining each completion kind's color. No verified open canonical or concrete fixing commit was found.

## Change summary

Allow completion icons to retain their per-kind colors when the suggestion is selected.

## Best solution

Provide a supported theme-level way to preserve per-kind suggestion icon colors on selection, without changing existing selection defaults or high-contrast behavior. Settle whether this is a general color-unsetting contract or a suggest-specific capability before implementation.

Removing the opt-out and setting an explicit selected-icon color must preserve existing behavior; check both high-contrast themes separately.
- **Behavior:**

  > Users want selected completion icons to retain their ordinary per-kind colors, such as purple methods and blue fields, rather than acquiring a uniform selection color. The capability must work through supported customization, not theme-file edits. Acceptance should compare selected and unselected icons across multiple completion kinds in Monokai and Default Dark+, while preserving explicit selected-color overrides and existing high-contrast defaults.
- **Trace:**

  > The focused-row rule in src/vs/editor/contrib/suggest/browser/media/suggest.css overrides the per-kind rules in src/vs/editor/contrib/symbolIcons/browser/symbolIcons.css. The selected token is registered in suggestWidget.ts and follows quick-input/list icon defaults in ordinary themes. colorUtils.ts permits hexadecimal values and "default"; ColorThemeData.overwriteCustomColors ignores null, while getColor resolves registered defaults. This source inspection establishes the missing explicit opt-out, not a runtime reproduction. https://github.com/microsoft/vscode/issues/128062 delivered default-reset semantics, which are not the same contract; https://github.com/microsoft/vscode/issues/162526 corroborates the user goal but is closed. Preserve existing explicit overrides, selection styling, and high-contrast behavior; the unresolved boundary is whether suppression belongs to the shared theme contract or only the suggest widget.
- **Open decisions:**
  - Should users be able to suppress a color token through a general theme-customization value, or should retaining per-kind colors be a capability limited to suggestion icons?

## Evidence

- **Current selected-icon behavior:** src/vs/editor/contrib/suggest/browser/media/suggest.css:128-130 applies editorSuggestWidget.selectedIconForeground to focused-row codicons. The more specific focused-row selector overrides the per-kind symbolIcon colors defined in src/vs/editor/contrib/symbolIcons/browser/symbolIcons.css.
- **Existing capability does not fully cover the request:** src/vs/platform/theme/common/colorUtils.ts:168-184 accepts hexadecimal colors or the string "default", not null. ColorThemeData.overwriteCustomColors in src/vs/workbench/services/themes/common/colorThemeData.ts:446-454 ignores null; getColor at lines 152-170 resolves "default" through registered defaults rather than expressing an explicit absence of color.
- **Default reset remains theme-dependent:** src/vs/editor/contrib/suggest/browser/suggestWidget.ts:47 defaults the selected icon color to quickInputList.focusIconForeground in ordinary themes, which references list.activeSelectionIconForeground. extensions/theme-defaults/themes/dark_vs.json and light_vs.json explicitly set that latter token to white. Resetting editorSuggestWidget.selectedIconForeground alone therefore does not guarantee preservation of per-kind colors.
- **Prior unsetting feature has a narrower contract:** https://github.com/microsoft/vscode/issues/128062 is closed. The maintainer explains at https://github.com/microsoft/vscode/issues/128062#issuecomment-2151603374 that "default" resets a theme-changed color to its default; it does not establish arbitrary null suppression. Subsequent discussion still reports selected icons becoming white.
- **Canonical search:** https://github.com/microsoft/vscode/issues/162526 requests the same preservation of completion icon colors, but was closed for insufficient community votes, not implementation or a substantive scope decision. https://github.com/microsoft/vscode/issues/186905 remains open but concerns nested notebook list CSS suppressing icon colors, a distinct problem rather than a canonical for this customization request.
