# Issue #348672 — Consider adding a shortcut to screenshot capture

[https://github.com/microsoft/vscode/issues/348672](https://github.com/microsoft/vscode/issues/348672)

## Summary

Keep open: a shortcut exists for capturing another app, but it does not invoke the VS Code window/area capture flow covered by the linked test plan.

## Change summary

Provide a keyboard shortcut to start screenshot capture for a chat attachment.

## Best solution

Expose the existing Screenshot Window selection flow as a keyboard-invokable chat action, preserving whole-window capture, area selection, cancellation, and attachment to the intended chat.

- **Reason:** Keyboard access to an existing chat capture flow improves interaction consistency without adding a separate capture feature.

## Evidence

- **Report context:** https://github.com/microsoft/vscode/issues/348672 requests a capture shortcut while testing https://github.com/microsoft/vscode/issues/348214. That test plan distinguishes Screenshot Window, including area selection, from screenshots of other apps.
- **Existing shortcut covers another target:** src/vs/workbench/contrib/chat/electron-browser/actions/chatAppWindowScreenshotActions.ts:305-329 registers workbench.action.chat.attachAppWindowScreenshot with Ctrl+Alt+Shift+S, or Ctrl+Cmd+S on macOS. Its description explicitly targets another app's window, not the current VS Code window/area selector.
- **Remaining capability gap:** src/vs/workbench/contrib/chat/browser/actions/chatContext.ts:540-559 exposes Screenshot Window as a context value pick without a command ID. DesktopScreenshotContextValuePick.asAttachment in src/vs/workbench/contrib/chat/browser/actions/chatScreenshotContextPicker.ts invokes IScreenshotToolService.capture for the chat widget's window, but declares no keyboard action.
- **Partial programmatic alternative:** src/vs/workbench/contrib/chat/browser/actions/chatActions.ts supports an attachScreenshot argument when opening chat, but calls hostService.getScreenshot directly. This does not invoke the interactive window/area selection flow and therefore does not fully cover the request.
