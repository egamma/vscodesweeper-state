# Issue #339857 — Grid actions were difficult to find in command palette

[https://github.com/microsoft/vscode/issues/339857](https://github.com/microsoft/vscode/issues/339857)

## Summary

Legitimate, freshly-filed UX feedback on the new Agents window command palette: already correctly labeled `polish`/`agents-window`, with no maintainer discussion yet — this stays open for a design decision on what to trim, not a mechanical fix.

## Change summary

In the Agents window, searching "layout"/"grid" in the command palette surfaces unrelated generic editor-group "View: ..." commands, and the Agents-specific "Session Layout" menu (Move/Resize/Arrange Sessions) has many entries that feel like overkill, especially the four manual resize commands.

## Best solution

A maintainer should decide (a) whether to `when`-gate the generic editor-group grid/layout commands (registered in src/vs/workbench/browser/parts/editor, e.g. editorActions.ts/editorCommands.ts) out of the command palette when `IsSessionsWindowContext` is true, and (b) whether the four resize commands (sessions.narrowSession/widenSession/shortenSession/heightenSession in sessionsActions.ts) should keep `f1: true` at all versus relying on auto-sizing and the context-menu/keybinding paths only.

- **Trace:**

  > Session-grid commands (focus/move/resize x4 + Arrange Sessions) are registered with `category: SessionsCategories.Sessions` and `f1: true` in src/vs/sessions/contrib/sessions/browser/sessionsActions.ts:2010-2123, gated by `sessionGridWhen` (line 1993) which already includes `IsSessionsWindowContext`. The generic 'View: Grid Editor Layout ...' commands living in src/vs/workbench/browser/parts/editor/{editorActions.ts,editorCommands.ts} have no such gating today, so they still surface in the Agents window's palette.
