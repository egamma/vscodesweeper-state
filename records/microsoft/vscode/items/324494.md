# Issue #324494 — Add a setting to disable the integrated Git worktrees UI (Source Control listing + branch checkout prompts)

[https://github.com/microsoft/vscode/issues/324494](https://github.com/microsoft/vscode/issues/324494)

## Summary

The requested opt-out remains missing: existing settings control automatic repository discovery or hide all repository artifacts, but do not disable worktree-aware checkout prompts. Keep this request open for Git-area design review; the older repository-reopening report does not cover its full scope.

## Change summary

Provide an opt-out from worktree listings and cross-worktree checkout interactions for users who keep each worktree in a separate window.

## Best solution

Provide a coherent Git configuration contract for window-local worktree behavior, covering both the worktree artifact listing and checkout conflict interactions while preserving Git's refusal to check out an already-used branch. Keep automatic repository discovery and unrelated repository artifacts independently configurable.

## Plan brief

- **Likely files:** `extensions/git/package.json`, `extensions/git/package.nls.json`, `extensions/git/src/model.ts`, `extensions/git/src/artifactProvider.ts`, `extensions/git/src/commands.ts`
- **Validation:** With a primary repository and a sibling linked worktree on another branch, open only the primary folder and enable repository artifacts. Verify that the approved opt-out removes worktree listings and that selecting the sibling's occupied branch neither opens its repository nor offers cross-window navigation, while still reporting Git's checkout refusal. Verify that branches, tags, stashes, and current-window changes remain available, and disabling the opt-out preserves existing behavior.
- **Behavior:**

  > Users who deliberately manage each Git worktree in a separate window need an opt-out from integrated cross-worktree UI. Under that opt-out, the Source Control worktree listing is absent and branch checkout does not offer navigation to another worktree or open its repository. An occupied branch may still be refused by Git; the request does not authorize overriding that safety restriction. Other repository artifacts and normal current-window branch operations should remain unchanged.
- **Trace:**

  > Model.open in extensions/git/src/model.ts uses git.detectWorktrees and git.detectWorktreesLimit only for automatic repository scanning. GitArtifactProvider in extensions/git/src/artifactProvider.ts independently registers the worktrees group and loads its artifacts. Commands._checkout in extensions/git/src/commands.ts handles WorktreeBranchAlreadyUsed through handleWorktreeBranchAlreadyUsed and handleWorktreeConflict, which opens the other repository before offering worktree navigation. scm.repositories.explorer hides all artifacts and is therefore only a partial workaround. https://github.com/microsoft/vscode/issues/313526 tracks a separate closed-repository reopening problem and should remain distinct. The unresolved boundary is whether the opt-out governs only these Git UI surfaces or also prevents non-current worktree repositories from being opened through other callers; do not alter Git's branch-use checks or agent worktree creation as incidental changes.
- **Open decisions:**
  - Should the requested UI opt-out be a separate setting, preserving git.detectWorktrees as a discovery-only control, or should the existing setting's documented contract expand?
  - Should the opt-out suppress only the worktrees artifact group and checkout navigation prompts, or also prevent non-current worktree repositories from appearing when another component explicitly opens them?
