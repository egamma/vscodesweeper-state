# Issue #319905 — Please add menu to resize font size (zoom in/out) to new Copilot Agents window

[https://github.com/microsoft/vscode/issues/319905](https://github.com/microsoft/vscode/issues/319905)

## Summary

Confirmed gap: the new Agents (Sessions) window has no interactive zoom command, keybinding, or menu entry — it only applies a one-time persisted zoom level at startup — unlike the main workbench window which registers workbench.action.zoomIn/zoomOut/zoomReset. Prior review (2026-08-03) kept this open; no canonical in the candidate list covers the same symptom (the window-level zoom gap), so it stays open rather than being closed as a duplicate.

## Change summary

The separate Agents/Sessions window lacks Ctrl+=/Ctrl+-/zoom-reset commands and menu entries that the main VS Code window has, making text hard to read and the font-size setting unresponsive there.

## Best solution

Register equivalent zoom-in/zoom-out/zoom-reset Action2 commands (f1: true, with keybindings) for the sessions electron-browser window, reusing the existing platform-layer applyZoom()/ApplyZoomTarget helper from src/vs/platform/window/electron-browser/window.ts so the Agents window gets the same zoom behavior as the main workbench.

## Plan brief

- **Likely files:** `src/vs/sessions/electron-browser/actions/vscodeActions.ts`, `src/vs/sessions/electron-browser/sessions.desktop.contribution.ts`
- **Validation:** Add zoom-in/zoom-out/zoom-reset Action2 registrations for the sessions window and a test (e.g. alongside src/vs/sessions/test/electron-browser/vscodeActions.test.ts) asserting the commands exist and call applyZoom with the expected target/level; the test should fail before the commands are registered and pass after.
- **Behavior:**

  > In the Agents (Sessions) window, the user can zoom in, zoom out, and reset zoom via command palette (and ideally the same default keybindings as the main window: Ctrl/Cmd+=, Ctrl/Cmd+-, Ctrl/Cmd+Numpad0). Zoom level changes take effect immediately in that window, honoring the same window.zoomLevel/window.zoomPerWindow settings the main workbench already respects. No change to the main workbench's existing zoom behavior.
- **Trace:**

  > The sessions (Agents) window bootstraps separately from the main workbench (src/vs/sessions/electron-browser/sessions.main.ts) and only applies a persisted zoom level once at startup via applyWindowZoomLevel()/webFrame.setZoomLevel (src/vs/sessions/electron-browser/sessions.ts lines ~80-81) — there is no registered Action2 command, keybinding, or menu entry to change zoom afterward, confirmed by searching src/vs/sessions for zoom-related code. The main workbench's workbench.action.zoomIn/zoomOut/zoomReset (src/vs/workbench/electron-browser/actions/windowActions.ts) call a reusable applyZoom()/ApplyZoomTarget helper that already lives in the platform layer (src/vs/platform/window/electron-browser/window.ts), so it can be called from sessions code without a layering violation. The boundary: register analogous commands scoped to the sessions window (following the existing pattern of Action2 with f1: true in src/vs/sessions/electron-browser/actions/vscodeActions.ts); do not touch the main workbench's zoom actions or settings schema.

## Evidence

- **zoom actions are workbench-only:** workbench.action.zoomIn/zoomOut/zoomReset are defined in src/vs/workbench/electron-browser/actions/windowActions.ts and registered via src/vs/workbench/electron-browser/desktop.contribution.ts, which is not part of the sessions window bundle.
- **sessions window only sets zoom once:** src/vs/sessions/electron-browser/sessions.main.ts calls applyWindowZoomLevel(configurationService) once at startup (line ~128/150) and src/vs/sessions/electron-browser/sessions.ts sets webFrame.setZoomLevel from persisted config (line ~80-81); there is no registered command, menu, or keybinding to change it interactively.
- **no zoom actions registered for sessions:** rg for 'zoomIn'/'zoomOut'/'ZoomLevel' across src/vs/sessions/**/*.ts turns up only the startup-apply code paths listed above; the actions files (src/vs/sessions/electron-browser/actions/vscodeActions.ts, src/vs/sessions/browser/actions/vscodeActions.ts) contain no zoom/font-size commands.
- **reusable helper exists at the right layer:** applyZoom() and ApplyZoomTarget live in src/vs/platform/window/electron-browser/window.ts (platform layer), so the sessions window can call it without a layering violation; sessions actions already use Action2 with f1: true and KeybindingWeight (e.g. src/vs/sessions/electron-browser/actions/vscodeActions.ts line ~106), matching the pattern needed.
- **related but distinct:** https://github.com/microsoft/vscode/issues/320205 (Panel-specific zoom controls for chat/sidebar views) is a different, narrower ask about per-panel zoom inside the main workbench, not the Agents window's missing window-level zoom; https://github.com/microsoft/vscode/issues/519 is a much older, broader font-customization request unrelated to this specific regression.
