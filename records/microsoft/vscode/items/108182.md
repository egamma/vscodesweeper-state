# Issue #108182 — Support for Apple Pencil scribble

[https://github.com/microsoft/vscode/issues/108182](https://github.com/microsoft/vscode/issues/108182)

## Summary

Keep this accepted Backlog request open: the inspected input paths do not establish full-editor Apple Pencil Scribble support, and no qualifying older canonical issue was found. The remaining work needs platform investigation and a decision about handwriting versus selection gestures.

## Change summary

Support Apple Pencil Scribble text entry in VS Code through Sidecar, with predictable handwriting, scrolling, and selection behavior.

## Best solution

Establish what Sidecar exposes to the macOS editor separately from native iPad browser input, then define a supported handwriting interaction that preserves ordinary selection and scrolling. The later request for explicit Scribble and Scroll + Select modes needs a maintainer decision rather than an assumed new setting.

## Plan brief

- **Likely files:** `src/vs/editor/browser/controller/pointerHandler.ts`, `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts`, `src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** On a Mac using an iPad and Apple Pencil through Sidecar, compare handwriting in a standard text field with handwriting near the VS Code cursor and elsewhere in the editor. Verify recognized text insertion, Scribble editing gestures, and ordinary selection/scrolling without unintended edits; test Safari on iPad separately if included in the agreed scope.
- **Behavior:**

  > The original goal is Apple Pencil handwriting text entry in VS Code while using Sidecar, where the reporter currently gets mouse-like behavior. The later discussion asks for handwriting throughout the editor without accidental scrolling, and a navigation mode without accidental Scribble edits. Acceptance must demonstrate the agreed handwriting behavior on the actual supported platform while preserving normal mouse, keyboard, touch, and pen navigation.
- **Trace:**

  > PointerEventHandler in src/vs/editor/browser/controller/pointerHandler.ts tracks pen input and routes change gestures to selection, while touch changes scroll. PointerHandler chooses its handler using the host platform, so the iPad-specific branch cannot be assumed to describe a macOS window displayed through Sidecar. TextAreaEditContext constructs a separate textarea, and editor.editContext selects an alternative input API rather than an explicit handwriting mode. These source paths do not establish OS Scribble availability or complete coverage of the request. https://github.com/microsoft/vscode/issues/108182#issuecomment-705735342 preserves the request pending understanding of the platform; https://github.com/microsoft/vscode/issues/108182#issuecomment-1279808481 proposes user-visible modes without a recorded maintainer decision. Investigate Sidecar separately from Safari on iPad and preserve existing input behavior outside the agreed handwriting interaction.
- **Open decisions:**
  - Should the supported feature cover macOS Sidecar, Safari on iPad, or both, given their different input hosts?
  - Should handwriting and navigation coexist automatically, or should users explicitly choose Scribble versus Scroll + Select modes?
