# Issue #309881 — run_in_terminal cancellation can hang indefinitely in basic and none execute strategies under continuous terminal output

[https://github.com/microsoft/vscode/issues/309881](https://github.com/microsoft/vscode/issues/309881)

## Summary

The core defect remains on current main: `waitForIdle` still has no cancellation path, and the basic/none execute strategies still call it without integrating the cancellation token into the race. The safety-net fallbacks added to `trackIdleOnPrompt` help adjacent paths but do not directly address this issue's identified gap.

## Change summary

The `waitForIdle` helper in terminal execute strategies has no cancellation path, so cancellation can hang indefinitely under continuous terminal output in basic and none shell-integration modes.

## Best solution

Add a `CancellationToken` parameter to `waitForIdle` (and `waitForIdleWithPromptHeuristics`) that races the deferred promise against `token.onCancellationRequested`, and wire the token through in the basic and none strategies' race calls so cancellation unwinds immediately.
