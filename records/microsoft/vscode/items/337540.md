# Issue #337540 — Agent Host: never auto-approve tools an admin marked ineligible

[https://github.com/microsoft/vscode/issues/337540](https://github.com/microsoft/vscode/issues/337540)

## Summary

Fresh team-authored tracking item (0 days old) describing a real, unaddressed gap: the Agent Host's managed-settings bridge only maps `chat.tools.eligibleForAutoApproval` onto the coarse session-wide bypass lock, and the module's own comments acknowledge there is no per-tool enforcement in assisted approval or saved/session approvals. Nothing to close here — this is open engineering work the author is tracking.

## Change summary

Ensure the Agent Host permission layer never auto-approves a tool an admin marked ineligible via `ChatToolsEligibleForAutoApproval`, across assisted approval and saved/session approvals (not just the Allow-All bypass lock).

## Best solution

Extend enforcement beyond the existing bypass-lock fallback in agentHostManagedSettings.ts so assisted-approval and saved/resumed session approvals also consult tool eligibility before auto-approving — likely requiring either a host-side check ahead of the SDK's rule grammar or a future SDK tool-name family, as the code comments themselves anticipate.

## Evidence

- **coarse fallback only:** src/vs/platform/agentHost/common/agentHostManagedSettings.ts:236-253 (`contributeEligibleForAutoApprovalRestriction`) maps any tool marked ineligible onto `disableBypassPermissionsMode: 'disable'` — a session-wide bypass lock, not a per-tool `ask` rule — because the SDK's `ManagedRuleFamily` has no tool-name family (module comment, lines 29-40).
- **no eligibility check in session/command approval paths:** grep for 'eligib' in src/vs/platform/agentHost/node/sessionPermissions.ts and commandAutoApprover.ts returns no hits, consistent with the issue's claim that assisted approval and saved/session approvals do not consult tool eligibility today.
- **classic chat surface has real enforcement:** src/vs/workbench/contrib/chat/browser/tools/languageModelToolsService.ts:1064-1092 already gates `allowAutoConfirm` on `isToolEligibleForAutoApproval`, showing the intended per-tool behavior exists elsewhere but is not yet mirrored in the Agent Host's own permission layer.
