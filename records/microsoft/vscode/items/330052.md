# Issue #330052 — Terminal: expose xterm.js `mouseEventsRequireAlt` as a setting so mouse reporting never costs text selection

[https://github.com/microsoft/vscode/issues/330052](https://github.com/microsoft/vscode/issues/330052)

## Summary

Well-researched, actionable request confirmed against current main: xterm.js's `mouseEventsRequireAlt` option is never wired up anywhere in the terminal construction/update code, so there's genuinely no way today to keep text selection working when an app arms mouse reporting.

## Change summary

Add a `terminal.integrated.mouseEventsRequireModifier` setting that passes xterm.js's `mouseEventsRequireAlt` option through, so plain-drag selection survives app-initiated mouse reporting.

## Best solution

Add the setting to terminalConfiguration.ts alongside the other xterm mouse-behavior settings (e.g. macOptionClickForcesSelection, rightClickBehavior) and wire it into the `new xtermCtor({...})` options and `updateConfig()` in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts, mirroring how altClickMovesCursor/rightClickSelectsWord are already threaded through.
