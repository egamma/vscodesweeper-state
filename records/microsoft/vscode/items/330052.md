# Issue #330052 — Terminal: expose xterm.js `mouseEventsRequireAlt` as a setting so mouse reporting never costs text selection

[https://github.com/microsoft/vscode/issues/330052](https://github.com/microsoft/vscode/issues/330052)

## Summary

The requested selection-first mouse policy is still missing from current main; existing modifier-based selection settings do not cover it. Keep this request open for discussion rather than closing it for limited traction.

## Change summary

Expose an opt-in terminal preference that preserves ordinary mouse selection while requiring Alt for application mouse clicks, drags, and movement.

## Best solution

If accepted, provide a backward-compatible, opt-in selection-first policy through the terminal configuration and XtermTerminal initialization/update paths. Document the Alt requirement and macOS selection-option precedence, while keeping code-server clipboard handling outside this request.

## Evidence

- **Missing configuration and wiring:** Current main has no mouseEventsRequireAlt or mouseEventsRequireModifier reference in src/vs/workbench/contrib/terminal or src/vs/platform/terminal. XtermTerminal initializes mouse options in src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts:245–280 and refreshes them in updateConfig():597–625, but neither path exposes the requested policy.
- **Existing capabilities are partial workarounds:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:143–163 registers terminal.integrated.macOptionClickForcesSelection, terminal.integrated.altClickMovesCursor, and terminal.integrated.copyOnSelection. These respectively force selection with Option on macOS, reposition the cursor, or copy an existing selection; none makes ordinary unmodified dragging select while mouse reporting is enabled. Shift+drag is also a workaround, not the requested persistent preference.
- **Upstream option contract:** https://github.com/xtermjs/xterm.js/blob/master/typings/xterm.d.ts defines mouseEventsRequireAlt: clicks, drags, and movement reach the application only while Alt is held; wheel events are unaffected, and the option takes precedence over macOptionClickForcesSelection. This supports treating the missing VS Code exposure as a feature request, not an upstream defect.
- **Related downstream report:** https://github.com/coder/code-server/issues/7938 is open, was created after this issue, and explicitly tracks this upstream request. Its maintainer recommends implementing the capability in VS Code at https://github.com/coder/code-server/issues/7938#issuecomment-5639552811. It is not an older canonical duplicate, and its additional clipboard claims were not independently verified.
