# Issue #17901 — Add extension point for custom "prefix behaviors" in command palette

[https://github.com/microsoft/vscode/issues/17901](https://github.com/microsoft/vscode/issues/17901)

## Summary

The extension-API gap remains: built-in Quick Access providers support prefixes, but extensions cannot register their own through the public API. Keep this accepted Backlog request open; no verified canonical or implementation was found.

## Change summary

Allow extensions to register custom prefix-triggered providers in the shared Quick Access picker.

## Best solution

Provide an extension-facing contract for custom Quick Access prefixes, subject to API-owner agreement on prefix ownership and provider lifecycle. Standalone extension Quick Picks are a workaround, not equivalent integration with the shared picker.

## Evidence

- **Existing internal capability:** src/vs/platform/quickinput/common/quickAccess.ts defines IQuickAccessRegistry.registerQuickAccessProvider and prefix-based provider selection. Registrations require an internal provider constructor; this is a workbench registry, not an extension-facing API.
- **Built-in registrations:** src/vs/workbench/contrib/quickaccess/browser/quickAccess.contribution.ts registers HelpQuickAccessProvider, ViewQuickAccessProvider, and CommandsQuickAccessProvider through the internal registry. These demonstrate the requested interaction without exposing custom prefix registration to extensions.
- **Public API does not cover the ask:** src/vscode-dts/vscode.d.ts exposes window.showQuickPick and window.createQuickPick. src/vs/workbench/api/common/extHost.api.impl.ts delegates createQuickPick to ExtHostQuickOpen, while src/vs/workbench/api/browser/mainThreadQuickOpen.ts creates a separate Quick Pick. These APIs do not register a prefix in the shared Quick Access picker.
- **Related report corroborates the boundary:** https://github.com/microsoft/vscode/issues/289595#issuecomment-3814089847 describes the same extension limitation: implementing Git-filtered results requires a separate command/keybinding because extensions cannot extend Ctrl+P directly. That issue is closed, newer, and narrower, so it is not a duplicate canonical.
- **Canonical search:** GitHub searches for Quick Open prefix support, Quick Access APIs, and extension providers found no verified open canonical owning this request. https://github.com/microsoft/vscode/issues/3380 concerns configuring existing prefixes, not registering extension providers, and is closed.
