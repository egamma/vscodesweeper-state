# Issue #293109 — Display Context Window Information Immediately After Model Selection in GitHub Copilot

[https://github.com/microsoft/vscode/issues/293109](https://github.com/microsoft/vscode/issues/293109)

## Summary

Current main partially addresses the request: model picker details expose maximum context immediately, and the usage widget updates its denominator on model selection when prior usage exists. A fresh session still hides the usage widget until a response arrives, so the requested persistent post-selection presentation remains an open UX decision.

## Change summary

Show a selected model's context-window capacity immediately, without waiting for a Copilot response.

## Best solution

Make context capacity discoverable as soon as a model is selected while keeping capacity distinct from measured session usage. Maintainers should decide whether the existing picker details are sufficient or whether the context widget needs a defined pre-request state.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatContextUsageWidget.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/test/browser/widgetHosts/viewPane/chatContextUsageWidget.test.ts`
- **Validation:** Extend chatContextUsageWidget.test.ts with a selected-model-before-any-response case that asserts the maintainer-chosen pre-request presentation, while preserving existing response-usage and model-switch tests.
- **Behavior:**

  > After selecting a concrete model, users can immediately determine that model's context-window capacity without sending a request. Capacity must not be presented as measured token usage when no response usage exists. Switching models must update the displayed capacity, while existing sessions continue to show their actual usage accurately. Auto-routing models must not claim a concrete capacity until one can be resolved.
- **Trace:**

  > ChatInputPart already forwards current model changes to ChatContextUsageWidget.setSelectedModel in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts. ChatContextUsageWidget resolves selected-model capacity, but setSelectedModel only calls updateFromResponse when a previous response exists, while update(undefined) clears and hides the widget. The model picker independently exposes maximum context through modelPickerCard.ts and modelPickerHover.ts, so the uncertainty is presentation scope rather than metadata availability. Preserve the distinction between model capacity and response-derived prompt/completion usage, and preserve the existing Auto-model fallback behavior. Related UX discussion: https://github.com/microsoft/vscode/issues/293125#issuecomment-3855287285.
- **Open decisions:**
  - Should selecting a model before the first request reveal a zero-usage context widget, or should immediate capacity remain available only in the model picker?
  - If the usage widget appears before a response, should it display a percentage at all or use a capacity-only state that cannot be mistaken for measured usage?
