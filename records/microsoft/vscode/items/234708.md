# Issue #234708 — VSCode will silently never auto-update if it is not explicitly moved from the "Downloads" directory to "Application"

[https://github.com/microsoft/vscode/issues/234708](https://github.com/microsoft/vscode/issues/234708)

## Summary

Keep open: current macOS update handling still suppresses background installation errors, leaving affected users without an actionable warning. The DMG installer improves new installations but does not resolve this reporting gap for existing installations.

## Change summary

Make persistent macOS auto-update failures visible and provide accurate recovery guidance instead of silently leaving users on old versions.

## Best solution

Surface persistent read-only/translocation update failures through the existing update UI, with clear installation guidance that also accounts for applications already in Applications. Preserve suppression of transient background failures and avoid treating removal of macOS quarantine protections as the default remedy.

## Evidence

- **Current source confirms silent failure:** In src/vs/platform/update/electron-main/updateService.darwin.ts, DarwinUpdateService.doCheckForUpdates(false) enters CheckingForUpdates with explicit=false. When Electron emits an error, onError logs it but supplies an error message to State.Idle only for an explicit check. Thus the reporter's background read-only-volume error is discarded from the user-visible state. This establishes the silence from source; native macOS translocation itself was not executed.
- **Existing error presentation is insufficient:** In src/vs/workbench/contrib/update/browser/updateTitleBarEntry.ts, onStateChange shows the Idle error tooltip only when state.error is present. src/vs/workbench/contrib/update/browser/updateTooltip.ts renders that error in renderIdle. These existing surfaces cannot display the background failure discarded by DarwinUpdateService.
- **Recovery is not merely a folder move:** The discussion at https://github.com/microsoft/vscode/issues/234708 includes independent reports of failed updates from both /Applications and ~/Applications, recurrence after an automatic update, and a cache-clearing workaround that was subsequently retracted. The final commenter reports success after reinstalling from a DMG. Guidance stating that moving to Applications always fixes the problem would not cover this evidence.
- **DMG work does not complete this issue:** https://github.com/microsoft/vscode/issues/213909 is closed. The maintainer's https://github.com/microsoft/vscode/issues/213909#issuecomment-3846581047 explains that DMG distribution replaces the proposed move-on-launch feature, while archive downloads remain available. That decision does not establish a fix for silent updater failures in already-installed applications; no concrete fixing commit for this behavior was identified.
- **This report already owns related update failures:** Maintainer comments on the closed reports https://github.com/microsoft/vscode/issues/237398#issuecomment-3633054523, https://github.com/microsoft/vscode/issues/236669#issuecomment-3633080808, and https://github.com/microsoft/vscode/issues/251810#issuecomment-3636485545 all point to this issue. The canonical-search pass found no verified older open issue owning the same silent-failure symptom. The related move-to-Applications issue is closed and narrower.
