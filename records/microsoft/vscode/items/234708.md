# Issue #234708 — VSCode will silently never auto-update if it is not explicitly moved from the "Downloads" directory to "Application"

[https://github.com/microsoft/vscode/issues/234708](https://github.com/microsoft/vscode/issues/234708)

## Summary

The issue has two asks: (1) improve the error message in `preprocessError` to explicitly say 'move from Downloads to Applications', and (2) surface a notification proactively when auto-update fails silently instead of only on manual 'Check for Updates'. Both remain unaddressed on current main — the error text in `updateUtils.ts` is unchanged, and `updateService.darwin.ts` only surfaces the error when the check was explicit (line 92). Worth keeping open as a polish item for the macOS update experience.

## Change summary

Improve the macOS update error message to explicitly say 'move from Downloads to Applications' and proactively notify users when auto-update silently fails due to quarantine/read-only volume.

## Best solution

Update the error message in `src/vs/workbench/contrib/update/common/updateUtils.ts` (the `preprocessError` function) to explicitly instruct users to move VS Code from Downloads to Applications. Consider also surfacing a notification in `src/vs/platform/update/electron-main/updateService.darwin.ts` when a background auto-update fails due to read-only volume, rather than silently swallowing the error (line 87–93 currently only shows the message for explicit checks).
