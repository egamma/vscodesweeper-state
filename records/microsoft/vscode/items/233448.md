# Issue #233448 — webviewPanel.viewColumn set incorrectly

[https://github.com/microsoft/vscode/issues/233448](https://github.com/microsoft/vscode/issues/233448)

## Summary

Confirmed bug: the webview is opened before its handle is registered, so the resolved viewColumn is never pushed to the extension host. An open PR (#315506) already addresses this — keeping open until it lands.

## Change summary

webviewPanel.viewColumn returns undefined instead of the resolved column when created with ViewColumn.Beside.

## Best solution

Land the open PR https://github.com/microsoft/vscode/pull/315506, which adds an explicit `updateWebviewViewStates` call after registering the handle in `$createWebviewPanel`, so symbolic view columns resolve immediately.

## Evidence

- **source trace:** In src/vs/workbench/api/browser/mainThreadWebviewPanels.ts, `$createWebviewPanel` calls `_webviewWorkbenchService.openWebview()` at line 167 (which fires editor events and triggers `updateWebviewViewStates`), then calls `addWebviewInput(handle, …)` at line 176. Because the handle isn't registered yet when the events fire, `getHandleForInput` returns undefined and the resolved column is never sent to the ext-host.
- **ext-host getter:** src/vs/workbench/api/common/extHostWebviewPanels.ts lines 123-131: the `viewColumn` getter returns `undefined` for any negative symbolic value (like -2 for Beside), expecting it to be resolved later — but that resolution never arrives due to the ordering bug.
- **open PR:** https://github.com/microsoft/vscode/pull/315506 is an open PR that fixes this exact issue by calling `updateWebviewViewStates` after `addWebviewInput`.
