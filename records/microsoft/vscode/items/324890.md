# Issue #324890 — Utility model routing should follow the selected BYOK/local model, not only a global setting

[https://github.com/microsoft/vscode/issues/324890](https://github.com/microsoft/vscode/issues/324890)

## Summary

A well-reasoned feature request for per-provider/per-model utility model routing instead of a single global setting. The reporter answered the team member's clarifying questions, the community process is active (9/20 upvotes, within the 60-day window), and the request represents a genuine gap in the current BYOK model configuration surface. Should stay open for the backlog-candidates process.

## Change summary

Allow utility model selection to be configured per provider or per model entry rather than only via a single global setting.

## Best solution

Extend the utility model configuration so that `chatLanguageModels.json` entries (or equivalent per-provider config) can declare their own utility/utility-small model preferences, with special values like `mainAgent` for local setups. The global `chat.byokUtilityModelDefault` would remain as a fallback. This belongs in the BYOK model configuration layer under `src/vs/workbench/contrib/chat/browser/utilityModelContribution.ts` and the model resolution path.
