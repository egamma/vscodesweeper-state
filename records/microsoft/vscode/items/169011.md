# Issue #169011 — Don't initialize with "Manual Resolution"

[https://github.com/microsoft/vscode/issues/169011](https://github.com/microsoft/vscode/issues/169011)

## Summary

Keep this as the canonical merge-editor initialization bug: maintainers have consolidated several confirmed reports here, and current source still recomputes initial acceptance state from independently generated result diffs. No qualifying fix or older canonical covering the same symptom was found.

## Change summary

Opening a merge for the first time can incorrectly label untouched conflicts as "Manual Resolution" and hide their accept actions.

## Best solution

Initialize merge-editor conflict states consistently with the generated result, without falsely treating untouched conflicts as manual edits. Preserve recognition of genuine pre-existing resolutions and subsequent user edits.
