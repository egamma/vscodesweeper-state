# Issue #337658 — Git: Allow merging the current branch's upstream from the merge picker

[https://github.com/microsoft/vscode/issues/337658](https://github.com/microsoft/vscode/issues/337658)

## Summary

Valid, well-scoped feature request with a concrete precedent already in the codebase — the rebase picker recently gained a dedicated upstream entry, but the merge picker still filters it out via `skipCurrentBranchRemote: true`. No labels yet, so routing to the git area for maintainer consideration.

## Change summary

Add the current branch's local upstream remote-tracking ref as a selectable entry in the `Git: Merge...` quick pick, without triggering a fetch.

## Best solution

Mirror the existing `RebaseUpstreamItem` pattern from `git.rebase` in `git.merge`: surface the current branch's upstream ref (labeled '(upstream)') at the top of the merge picker, sourced from the already-fetched local remote-tracking ref, while still excluding the current branch itself.

## Vision fit

- **Fit:** aligned
- **Reason:** This is a small, symmetry-restoring UX improvement to the Git SCM integration, one of VS Code's durable inner-loop themes, and it reuses an existing UI pattern rather than adding new surface area.
- **Evidence:** Durable theme: 'Developer inner loop — editor, terminal, SCM/GitHub integration, testing, debugging.' Also aligns with the 'Simple, uniform UI and UI interactions' value, since it would make the merge picker consistent with the rebase picker's already-shipped upstream entry.

## Evidence

- **current exclusion:** extensions/git/src/commands.ts: the `git.merge` command's `getQuickPickItems` passes `{ skipCurrentBranch: true, skipCurrentBranchRemote: true }` to `RefItemsProcessor`, filtering out the current branch's upstream remote-tracking ref.
- **existing precedent:** extensions/git/src/commands.ts defines `class RebaseUpstreamItem extends RebaseItem` (description '(upstream)') and `git.rebase`'s picker explicitly re-adds the upstream ref at the top via `quickPickItems.splice(0, 0, new RebaseUpstreamItem(upstreamRef, ...))` when `repository.HEAD?.upstream` exists — the same capability the reporter wants for merge does not exist for `MergeItem`.
- **prior discussion:** Reporter cites https://github.com/microsoft/vscode/issues/250066 as the prior decision to exclude upstream from merge, and argues a distinct fetch-review-merge workflow not served by Pull.
