# Issue #243755 — Scroll state should not be shared between walkthrough steps

[https://github.com/microsoft/vscode/issues/243755](https://github.com/microsoft/vscode/issues/243755)

## Summary

The current source still carries one walkthrough step's scroll offset into another: Markdown steps reuse a webview whose content-update path restores the previous document's scroll position. Keep this open; no canonical issue owning the same symptom was found.

## Change summary

Switching walkthrough steps should show the destination step's top or its own saved position, not the previous step's offset.

## Best solution

Give walkthrough step changes independent scroll behavior in GettingStartedPage's media lifecycle, while preserving scroll retention for updates to the same step and other webview consumers.
