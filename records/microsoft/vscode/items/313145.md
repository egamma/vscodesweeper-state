# Issue #313145 — agent app- switch branches

[https://github.com/microsoft/vscode/issues/313145](https://github.com/microsoft/vscode/issues/313145)

## Summary

The branch picker can still change its popup geometry when filtering reduces the results to zero, matching the reported jumping behavior. This team-authored Backlog issue should remain open; no explicitly linked fix or valid older canonical was found.

## Change summary

Keep the Agents Window branch picker spatially stable when the entered branch name has no matching results.

## Best solution

The branch picker should preserve a stable anchor and predictable empty-result presentation while filtering, without changing branch selection, tracked-upstream focus, or unrelated Action Widget consumers.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionConfigPicker.ts`, `src/vs/sessions/contrib/providers/agentHost/test/browser/agentHost/agentHostSessionConfigPicker.test.ts`, `src/vs/platform/actionWidget/browser/actionList.ts`, `src/vs/platform/actionWidget/test/browser/actionList.test.ts`
- **Validation:** Add a browser-level Action Widget or branch-picker test that filters from multiple branch rows to zero results and verifies the popup anchor and intended geometry remain stable; manually repeat by typing a nonexistent branch name in the Agents Window branch picker.
- **Behavior:**

  > While typing into the Agents Window branch picker, reducing the results to no matching branches must not make the popup jump relative to its trigger. The picker should present a clear, stable empty-result state and recover normally when the query again matches a branch. Existing branch selection, tracked-upstream focus, and keyboard navigation must remain unchanged.
- **Trace:**

  > The Agents Window branch picker is built in src/vs/sessions/contrib/providers/agentHost/browser/agentHostSessionConfigPicker.ts. Its dynamic filter path calls filterBranchPickerItems and can return an empty item array for an unmatched query. src/vs/platform/actionWidget/browser/actionList.ts then replaces the visible items and requests popup layout when the visible row count changes, which can resize and re-anchor the widget. Existing tests cover filtering and upstream focus but not geometry when the result count reaches zero. Keep the scope to popup stability for branch filtering; do not alter checkout semantics, completion matching, or focus behavior for valid branches, and avoid changing unrelated Action Widget consumers unless the shared behavior is intentionally selected.
- **Open decisions:**
  - When no branch matches, should the picker retain its normal result height with an explicit empty-state row, or use a compact empty state while preserving the popup's anchor position?
