# Issue #346197 — Agent selector is gone in 1.145.0

[https://github.com/microsoft/vscode/issues/346197](https://github.com/microsoft/vscode/issues/346197)

## Summary

The reported selection-dependent visibility is intentional behavior controlled by an experimental setting. Explicitly disabling that setting restores the persistent toolbar selector.

## Change summary

Keep the agent selector visible in the toolbar when the default Agent is selected.

## Best solution

Use the existing setting sessions.chat.experimental.agentsPickerInAttachContextMenu=false to retain the toolbar selector for all agent selections; no code change is needed for the requested behavior.

  > Thanks for the report. This is intentional behavior controlled by the experimental setting `sessions.chat.experimental.agentsPickerInAttachContextMenu`: the default Agent moves into Add Context, while other selections remain in the toolbar. Set it explicitly to `false` to keep the selector visible for every selection. Cmd+. continues to open the picker on macOS.

- **Toolbar and keyboard behavior:** src/vs/workbench/contrib/chat/browser/actions/chatExecuteActions.ts:464-509 intentionally excludes OpenModePickerAction from the toolbar when chatAgentPickerInAttachContext is true, while retaining workbench.action.chat.openModePicker on Cmd+. for macOS. This matches the reporter's second comment.
- **Existing behavioral assertions:** src/vs/workbench/contrib/chat/test/browser/widget/input/modePickerActionItem.test.ts:187-213 explicitly asserts that default Agent is relocated only with the setting enabled, custom selections remain visible, and disabling the setting keeps the picker in the toolbar. Tests were inspected, not executed.
