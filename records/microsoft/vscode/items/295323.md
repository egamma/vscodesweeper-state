# Issue #295323 — image cant upload more than 10，and pdf or docx cant interpretted

[https://github.com/microsoft/vscode/issues/295323](https://github.com/microsoft/vscode/issues/295323)

## Summary

A real capability gap remains, although current main now handles part of the report: PDF attachments work with supported models, while DOCX is not interpreted and Gemini requests remain capped at 10 images. The older document-format issue covers only part of this combined request, and a maintainer is already investigating the request-specific image limit, so this should stay open.

## Change summary

Allow Copilot Chat to process more than 10 attached images and interpret PDF and DOCX documents.

## Best solution

Make attachment handling accurately reflect each model's capabilities: accept higher image counts where the service supports them, clearly enforce unavoidable limits, and provide a supported document path for DOCX alongside the existing model-gated PDF path. The general document-format work should be coordinated with https://github.com/microsoft/vscode/issues/265184.

## Evidence

- **current image limits:** src/vs/workbench/contrib/chat/common/attachments/chatVariableEntries.ts defines model-specific limits in getImageAttachmentLimit: 10 images for Gemini, 20 for Claude/Anthropic, and no UI-enforced count for other model families.
- **partial PDF support:** extensions/copilot/src/extension/prompts/node/panel/fileVariable.tsx now recognizes PDF files, validates their magic bytes, and emits a Document part when modelSupportsPDFDocuments permits it; extensions/copilot/src/platform/endpoint/node/responsesApi.ts and messagesApi.ts serialize application/pdf.
