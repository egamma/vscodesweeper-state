## Evidence

- **Independent confirmations:** The discussion at https://github.com/microsoft/vscode/issues/308359 includes confirmations after extension updates, during startup and installation, and without voice commands. Two commenters report recreation after deletion; others report successful removal or reinstall workarounds. These confirm the historical symptom, not a current-main reproduction.
- **Established dialog origin:** In https://github.com/microsoft/vscode/issues/304313#issuecomment-4127889015, a maintainer traced the dialog to inno_updater garbage collection encountering a literal NUL file in the application directory. This distinguishes the dialog's origin from the still-unverified process creating the file.
- **Earlier fix and remaining boundary:** Merged https://github.com/microsoft/vscode-copilot-chat/pull/4748 replaces the bare Windows 'NUL' exporter path with node:os devNull. Current extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotcliSessionService.ts:213-225 adopts that corrected path before constructing LocalSessionManager. The diff changes future exporter writes; it contains no removal of existing installation-directory NUL files and does not establish resolution of this later report.
- **Deletion versus recreation:** https://github.com/microsoft/vscode/issues/304313#issuecomment-4197374887 documents a reporter initially mistaking failed Explorer deletion for file recreation. That makes verified deletion and subsequent file-creation tracing important here, without disproving this issue's independent recurrence reports.
- **Current updater path:** src/vs/platform/update/electron-main/updateService.win32.ts:148-207 invokes collectGarbage during postInitialize and launches inno_updater.exe with --gc for eligible user installations. Startup can therefore trigger updater cleanup independently of the voice workflow. The checkout provides the updater executable, not its garbage-collection implementation, so its handling of NUL cannot be conclusively traced here.
