# Issue #228367 — Multifile diff editor leaks models and editor after closing and hiding

[https://github.com/microsoft/vscode/issues/228367](https://github.com/microsoft/vscode/issues/228367)

## Summary

Still reproduces on main: when the Refactor Preview is dismissed via Discard, `_done()` clears `_sessionDisposables` (releasing model references) but does not close the opened multi-diff editors or dispose their underlying `vscode-bulkeditpreview-editor` models. The preview models and editors remain alive and visible via the extension API.

## Change summary

Closing the Refactor Preview (Discard) leaks preview text models and leaves ghost editors in `visibleTextEditors`.

## Best solution

Ensure `BulkEditPane._done()` (or the `BulkEditPreviewContribution._previewEdit` finally-block) explicitly closes all editors with the `vscode-bulkeditpreview-multieditor` scheme and disposes the `vscode-bulkeditpreview-editor` models before resolving. The partial leak fix in commit 45a35b80493 (Feb 2026) added `_sessionDisposables.dispose()` on pane disposal but did not address the mid-session discard path. The coordination between `_done()` and `UXState.restore()` needs to guarantee editors are closed before model references are released.

## Evidence

- **source trace:** In `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditPane.ts` line 276–281, `_done()` clears `_sessionDisposables` (disposing `BulkEditPreviewProvider` and its model references) and sets `_currentInput = undefined`, but does NOT close editors. Editor closing is deferred to `UXState.restore()` in `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEdit.contribution.ts` line 51–78, which runs asynchronously in the `finally` block of `_previewEdit()`.
- **model leak path:** In `src/vs/workbench/contrib/bulkEdit/browser/preview/bulkEditPreview.ts` lines 420–449, `BulkEditPreviewProvider._getOrCreatePreviewModel()` creates models via `_modelService.createModel()` and takes a self-reference via `_textModelResolverService.createModelReference()` added to `_disposables`. When `_disposables` is disposed, the self-reference is released, but if an open editor also holds a reference, the model survives.
- **partial fix only:** Commit 45a35b80493 (Feb 2026) fixed a leak on pane disposal by adding `_sessionDisposables.dispose()` in `dispose()`, but did not address the mid-session discard flow where `_done(false)` only calls `_sessionDisposables.clear()` and relies on external editor closing.
- **maintainer confirmation:** https://github.com/microsoft/vscode/issues/228367#issuecomment-2353427371 — @jrieken confirmed the bug and tagged @hediet: 'closing the preview editor doesn't reset it, e.g all editors and its models are still around'.
