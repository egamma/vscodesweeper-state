# Issue #201772 — Allow "Debug Console" editors

[https://github.com/microsoft/vscode/issues/201772](https://github.com/microsoft/vscode/issues/201772)

## Summary

Keep open: the built-in Debug Console remains a view rather than an editor, so the requested interactive console in floating editor windows is still missing. The request has 34 upvotes and is accepted into the Backlog; related layout requests do not fully cover its editor and multiple-instance requirements.

## Change summary

Allow interactive Debug Consoles to open as editors that can be moved into auxiliary windows.

## Best solution

Provide a built-in Debug Console editor retaining evaluation input, expandable results, and normal editor-window placement. Decide how concurrent console instances share input and select debug sessions before implementation, coordinating with the related multi-session debugging work.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/contrib/debug/common/replModel.ts`
- **Validation:** Open a built-in Debug Console editor, move it into a floating window, evaluate an expression, and expand an object result. Open a second console, switch between two debug sessions, and verify the agreed input/session semantics; confirm the existing panel console still works and the agreed layout state survives reload.
- **Behavior:**

  > Users can open an interactive built-in Debug Console as an editor and move it to an auxiliary window without losing evaluation input or expandable output. Multiple console presentations must behave predictably when typing expressions and switching debug sessions. Acceptance includes working evaluation in the floating window, preserved panel functionality, and explicit reload/restoration behavior.
- **Trace:**

  > debug.contribution.ts registers REPL_VIEW_ID as a panel-backed Repl view; no Debug Console editor registration was found in the debug contribution. Repl in repl.ts combines output rendering, evaluation input, view lifecycle, and focused-session tracking, and its input model uses one static URI. These establish the relevant boundary but do not settle concurrent-editor semantics. Preserve existing panel behavior and debug-session output handling; making every debug view floatable is outside this request. Coordinate with https://github.com/microsoft/vscode/issues/225483 without treating that newer multi-session proposal, or the general panel-detachment request at https://github.com/microsoft/vscode/issues/193267, as a duplicate canonical.
- **Open decisions:**
  - Should each console editor follow the globally focused debug session, or can it remain pinned to a particular session?
  - When several consoles are open, should unfinished evaluation input be shared or independent between presentations?
  - What console identity and session association should be restored with an editor layout after reload?

## Evidence

- **Existing-capability check:** src/vs/workbench/contrib/debug/browser/debug.contribution.ts:426–449 registers the Debug Console as a panel-backed Repl view with canMoveView and workbench.debug.action.toggleRepl. Its editor-pane registration at lines 479–482 is for DisassemblyView, not the console. The debug.console settings control presentation, history, and output limits, not editor placement.
- **Multiple-instance boundary:** src/vs/workbench/contrib/debug/browser/repl.ts defines Repl as a FilterViewPane, uses the static DEBUG_SCHEME:replinput model URI, and subscribes to the debug service's focused-session changes. The FOCUS_REPL_ID action opens REPL_VIEW_ID through IViewsService. These paths need design work before multiple editor-hosted consoles can have well-defined input and session behavior.
- **Reported workaround is incomplete:** The discussion on https://github.com/microsoft/vscode/issues/201772 identifies georgejames.searchable-debug-console as a movable editor workaround, but reports that it lacks evaluation input and does not restore its placement. It therefore does not deliver the central interactive-console request.
