# Issue #201772 — Allow "Debug Console" editors

[https://github.com/microsoft/vscode/issues/201772](https://github.com/microsoft/vscode/issues/201772)

## Summary

Keep this open: the requested Debug Console editor/floating-window capability remains a meaningful gap, has 35 community upvotes, and is parked in the Backlog rather than scheduled for closure. The related reports are newer and broader or session-oriented, so they do not satisfy the stronger duplicate bar for this re-reviewed item.

## Change summary

Allow the Debug Console to open as an editor so it can be moved into an auxiliary window, with its placement restored across sessions.

## Best solution

Define a first-class Debug Console editor input that preserves the existing REPL and evaluation behavior, supports multiple debug sessions where necessary, participates in editor serialization/restoration, and can be moved into an auxiliary window like terminal and output editors.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugConsoleView.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`, `src/vs/workbench/contrib/debug/common/debug.ts`, `src/vs/workbench/common/editor`
- **Validation:** Add workbench tests that open a Debug Console as an editor, move it to an auxiliary editor group, verify evaluation targets the intended debug session, and confirm its editor placement restores after workspace reload.
- **Behavior:**

  > Users can open the Debug Console in the editor area and move that editor into an auxiliary window, while retaining the normal evaluation input and console output behavior. The surface should integrate with editor layout restoration so its placement survives a workspace reload. Existing panel-based Debug Console behavior must remain available, and console input/output must stay associated with the intended debug session.
- **Trace:**

  > The current request is specifically about giving the Debug Console editor semantics comparable to existing terminal and output editors, not making every Debug view floatable. The partial Searchable Debug Console extension cited in the thread demonstrates the editor/auxiliary-window interaction but lacks the built-in evaluation bar and placement restoration, so it does not satisfy the request. The work likely crosses the debug console view/contribution and workbench editor input/serialization paths; the uncertainty starts at whether one editor follows the active session or separate editors bind to individual sessions. https://github.com/microsoft/vscode/issues/225483 is related session-oriented debug UI work but does not replace this request. Preserve the existing panel Debug Console and avoid expanding scope to Watch, Call Stack, or arbitrary panel floating.
- **Open decisions:**
  - Should one Debug Console editor follow the active debug session, or should users be able to open a separately bound editor for each session?
  - When both panel and editor Debug Consoles are open, do they mirror the same selected session and evaluation context or maintain independent selections?
  - Should editor placement restore per workspace only, or participate in a broader window-layout profile across workspaces?
