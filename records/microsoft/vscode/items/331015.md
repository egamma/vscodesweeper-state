# Issue #331015 — Built-in SQL language mode is displayed as "MS SQL", even though it's generic and dialect-agnostic

[https://github.com/microsoft/vscode/issues/331015](https://github.com/microsoft/vscode/issues/331015)

## Summary

Confirmed on main: extensions/sql/package.json lists `aliases: ["MS SQL", "T-SQL"]` for the generic `sql` language, so every `.sql` file shows "MS SQL" in the status bar/language picker regardless of dialect. The grammar itself (extensions/sql/syntaxes/sql.tmLanguage.json) is generic keyword/bracket highlighting sourced from microsoft/vscode-mssql's SQL.plist, with no dialect-specific logic, so the naming is misleading as described. This is a naming/polish call for the language maintainers, not an obvious bug — routing to the language area rather than closing.

## Change summary

Rename the built-in `sql` language's display alias from "MS SQL" to something dialect-neutral like "SQL", since the built-in grammar is generic and not Microsoft SQL Server/T-SQL specific.

## Best solution

A maintainer should decide whether to change the primary alias in extensions/sql/package.json from "MS SQL" to "SQL" (keeping "T-SQL" as a secondary alias if desired) — it's a one-line change, but renaming a long-standing built-in language name/id-adjacent string can affect existing settings (e.g. language-specific settings keyed by display name in some UI) and search history, so it needs an owner's sign-off rather than an automatic edit.
