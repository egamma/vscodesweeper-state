# Issue #86308 — [themes] Minimal icon theme should use icon font

[https://github.com/microsoft/vscode/issues/86308](https://github.com/microsoft/vscode/issues/86308)

## Summary

The requested capability remains missing on current main: the bundled Minimal icon theme still uses SVGs, and file icon themes cannot reference registered codicons. This team-authored Backlog request is protected from judgment closes and should remain open for a file-icon-theme contract decision.

## Change summary

Allow the bundled Minimal file icon theme to render its file, folder, and workspace icons from the codicon font instead of SVG assets.

## Best solution

Define a supported way for file icon theme definitions to reference registered product icons or codicons, then migrate the bundled Minimal theme while preserving existing third-party theme behavior.

## Plan brief

- **Likely files:** `extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json`, `src/vs/workbench/services/themes/browser/fileIconThemeData.ts`, `src/vs/workbench/services/themes/common/fileIconThemeSchema.ts`, `src/vs/workbench/services/themes/test/browser/fileIconThemeData.test.ts`
- **Validation:** Extend the FileIconThemeData tests to load the selected codicon-reference format and assert that generated CSS uses the resolved icon font and glyph without a theme-relative font declaration; also verify that the Minimal theme no longer emits SVG-backed rules for its standard file and folder icons.
- **Behavior:**

  > When the bundled Minimal file icon theme is selected, its standard file, folder, expanded-folder, root-folder, and expanded-root-folder icons render through the shared icon font rather than SVG backgrounds. The icons remain distinguishable in light, dark, and high-contrast themes and continue to appear in Explorer, Search, and other file-icon consumers. Existing image-based and custom-font file icon themes continue to render unchanged.
- **Trace:**

  > The current Minimal theme at extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json maps all standard definitions to SVG files. FileIconThemeLoader.processIconThemeDocument in src/vs/workbench/services/themes/browser/fileIconThemeData.ts supports `iconPath` or glyph data from fonts declared in the file icon theme, while src/vs/workbench/services/themes/common/fileIconThemeSchema.ts has no registered product-icon reference. The existing unit boundary is src/vs/workbench/services/themes/test/browser/fileIconThemeData.test.ts, which currently covers only image rendering. The scope should remain the file icon theme contract, loader, bundled Minimal theme, and direct tests; existing third-party SVG/custom-font behavior and unrelated product-icon consumers must not change. Related discussion: https://github.com/microsoft/vscode/issues/91973.
- **Open decisions:**
  - Should registered icon references become a public file-icon-theme capability available to extensions, or an internal mechanism limited to bundled themes?
  - Should a referenced codicon follow the active product icon theme's replacement and font, or always resolve to the built-in codicon glyph?
  - Should the migrated Minimal icons inherit the current foreground color, or preserve the theme's existing light/dark icon colors?

## Evidence

- **current theme:** extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json still defines every file, folder, and root-folder icon through an SVG `iconPath`.
- **missing contract:** src/vs/workbench/services/themes/common/fileIconThemeSchema.ts permits an image path or a `fontCharacter`/`fontId`; its `fonts` entries require theme-relative font files and expose no registered codicon or product-icon reference.
- **loader path:** FileIconThemeLoader in src/vs/workbench/services/themes/browser/fileIconThemeData.ts resolves image paths and theme-declared font glyphs into CSS, but has no path that resolves an icon definition through the product icon registry.
- **maintainer intent:** The discussion explicitly identifies support for referencing codicons in file icon themes as the prerequisite: https://github.com/microsoft/vscode/issues/86308#issuecomment-943761532.
- **related request:** The narrower follow-up https://github.com/microsoft/vscode/issues/91973 was created after this issue and closed by the feature-request lifecycle without an implementation; it is neither an open canonical nor evidence that the original team-authored Backlog item was completed.
