# Issue #86308 — [themes] Minimal icon theme should use icon font

[https://github.com/microsoft/vscode/issues/86308](https://github.com/microsoft/vscode/issues/86308)

## Summary

The shipped Minimal file icon theme still uses SVGs, so the requested font migration remains outstanding. Keep this team-authored, accepted backlog item open; the related closed issues do not establish completion or a valid duplicate.

## Change summary

Render the built-in Minimal theme’s file, folder, and workspace-root icons using an icon font instead of SVG images.

## Best solution

Complete the Minimal theme’s font migration while preserving its file/folder distinctions and light, dark, and high-contrast behavior. Resolve the intended codicon-reference contract first, and verify the rendering benefit on current VS Code rather than assuming the original LCD-rendering motivation still holds.

## Plan brief

- **Likely files:** `extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json`, `src/vs/workbench/services/themes/common/fileIconThemeSchema.ts`, `src/vs/workbench/services/themes/browser/fileIconThemeData.ts`, `src/vs/workbench/services/themes/test/browser/fileIconThemeData.test.ts`
- **Validation:** Select Minimal in a multi-root workspace and inspect file, collapsed/expanded folder, and root-folder icons in Explorer and Search across light, dark, and high-contrast themes and representative zoom levels. Verify that these icons use font glyphs without losing their distinctions; exercise existing SVG and custom-font themes to check compatibility, and add targeted fileIconThemeData tests for any new reference contract.
- **Behavior:**

  > The built-in Minimal file icon theme should render its file, folder, and workspace-root icons using an icon font. Their distinctions and theme-variant behavior must remain recognizable in Explorer and Search, including expanded folders and multi-root workspaces. Acceptance includes confirming the font-backed rendering and assessing visual quality on current supported platforms; font use alone must not be treated as proof of LCD antialiasing.
- **Trace:**

  > Minimal is registered as vs-minimal in extensions/theme-defaults/package.json and remains entirely SVG-backed in extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json. FileIconThemeData processes iconPath as an image and separately supports fontCharacter/fontId with declared fonts; fileIconThemeSchema exposes those existing fields but no named codicon-reference mechanism. The thread asks for codicon-reference support, but does not settle its public syntax or compatibility contract. https://github.com/microsoft/vscode/issues/91973 was declined rather than implemented, and https://github.com/microsoft/vscode/issues/90911 separated this work from bundled-extension adoption. Preserve third-party SVG/custom-font themes and do not expand this into unrelated SCM or editor-action antialiasing fixes.
- **Open decisions:**
  - Should this migration add a supported named-codicon reference contract for all file icon theme authors, or use existing font definitions for Minimal without extending the public theme format?

## Evidence

- **Current capability gap:** extensions/theme-defaults/package.json still contributes the vs-minimal theme. extensions/theme-defaults/fileicons/vs_minimal-icon-theme.json defines all ten file, folder, expanded-folder, and workspace-root variants with SVG iconPath entries; it contains no font definitions or font characters.
- **Existing font support is not adoption:** src/vs/workbench/services/themes/common/fileIconThemeSchema.ts supports fonts, fontCharacter, and fontId. src/vs/workbench/services/themes/browser/fileIconThemeData.ts:392–445 loads declared fonts and renders font characters, but Minimal takes the iconPath image branch instead. Neither the inspected schema nor that rendering branch provides named codicon-reference resolution.
