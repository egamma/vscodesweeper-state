# Issue #142922 — Debug Console Filter is a bit confusing

[https://github.com/microsoft/vscode/issues/142922](https://github.com/microsoft/vscode/issues/142922)

## Summary

Keep this accepted Backlog request open: current source provides a Find command, but filter visibility, a dedicated clear-filter control, and retaining context when clearing the filter remain unresolved. Maintainers explicitly consolidated related visibility reports here; the newer Find issues cover only part of this request.

## Change summary

Make active Debug Console filtering obvious, distinguish clearing the filter from clearing output, and support searching without losing surrounding context.

## Best solution

Make filtering apparent beside the console output and provide an unmistakable way to clear only the filter, preserving existing filter syntax and persistence. Coordinate context-preserving search with the existing Debug Console Find work rather than treating its current tree-find command as complete coverage.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/repl.ts`, `src/vs/workbench/browser/parts/views/viewFilter.ts`, `src/vs/workbench/browser/parts/views/viewPane.ts`, `src/vs/workbench/contrib/debug/browser/media/repl.css`, `src/vs/workbench/contrib/debug/test/browser/repl.test.ts`
- **Validation:** In a debug session producing identifiable messages before and after a target string, apply filters matching some messages, no messages, and all messages; check active-filter discoverability at wide and narrow panel sizes and after reload. Clear only the filter and verify output is not deleted. Use Find to locate the target and verify surrounding output and navigation meet the agreed context-preservation behavior.
- **Behavior:**

  > Users should be able to recognize that the Debug Console is filtered without mistaking missing messages for failed debugging. Clearing the filter must be visibly distinct from deleting console output and must leave the output intact. Searching for a string should let users inspect nearby output without copying the console into an editor. Acceptance should cover partial matches, zero matches, narrow panels, persisted filters, and the agreed behavior for preserving the located context.
- **Trace:**

  > Repl in src/vs/workbench/contrib/debug/browser/repl.ts restores the workspace filter value, passes it to FilterViewPane, and refilters the tree before scrolling to the last element on every filter change. Its count badge depends on differing visible and total counts, not merely on an active query. The shared FilterWidget in src/vs/workbench/browser/parts/views/viewFilter.ts has no dedicated clear-input action in its construction; FilterViewPane in viewPane.ts changes placement responsively. A separate repl.action.find already opens the tree find widget, but https://github.com/microsoft/vscode/issues/225417 and https://github.com/microsoft/vscode/issues/226716 track remaining output-search and navigation capabilities. The maintainer consolidated visibility feedback from https://github.com/microsoft/vscode/issues/132995 here and favored retaining persistence in https://github.com/microsoft/vscode/issues/141682. Preserve existing filter syntax, persistence, and explicit clear-console behavior; changes to the shared widget must account for its other consumers. The unresolved boundary is the visible active-filter presentation and whether preserving context is required when clearing a filter or supplied through the separate Find experience.
- **Open decisions:**
  - Should the active-filter indication appear whenever a query is nonempty, including when every message matches, or only when output is actually hidden, and should it remain visible beside the output independently of the filter input?
  - Should clearing a filter preserve the located message and surrounding context, or should context-preserving navigation be provided exclusively through the separate Find experience?
