[https://github.com/microsoft/vscode/issues/20005](https://github.com/microsoft/vscode/issues/20005)

## Summary

## Change summary

Allow additional space between editor lines without proportionally enlarging the caret and current-line highlight.

The plan should identify executable rendering coverage for those geometry assertions.
- **Behavior:**

  > The reporter wants more space between text lines without making the caret and current-line highlight proportionally taller. Existing editor.lineHeight plus editor.cursorHeight partially covers the line-caret case, but the highlight remains full-row height. Acceptance should demonstrate greater separation between text baselines with independently controlled caret and highlight geometry, while preserving existing behavior for users who do not opt in. The exact configuration and supported cursor-style contract need agreement before implementation.
- **Trace:**

  > editorOptions.ts registers lineHeight, cursorHeight, and renderLineHighlight, but no separate inter-line-spacing or highlight-height option was found. ViewCursor._prepareRender in viewCursor.ts reads the per-line layout height, clamps the requested line-cursor height, and centers it within that row. CurrentLineHighlightOverlay builds the highlight markup, and currentLineHighlight.css gives both content and gutter highlights height: 100%, so the highlight still follows row geometry. This establishes partial coverage and the remaining design boundary without executing the editor. Preserve default cursor/highlight behavior and keep notebook cell/output spacing outside this issue's scope. https://github.com/microsoft/vscode/issues/28409 describes closely matching work but is newer; https://github.com/microsoft/vscode/issues/175295 concerns notebook layout instead. Uncertainty starts at the intended public configuration contract and which cursor/highlight variants should participate.
- **Open decisions:**
  - Should users receive a distinct inter-line-spacing option, or retain editor.lineHeight and editor.cursorHeight with an additional opt-in control for current-line-highlight geometry?
  - Should the opt-in behavior apply to all cursor styles and both content/gutter highlights, or only to explicitly supported variants?
