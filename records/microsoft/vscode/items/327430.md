# Issue #327430 — Color picker dimisses on its own when mouse is outside while still dragging

[https://github.com/microsoft/vscode/issues/327430](https://github.com/microsoft/vscode/issues/327430)

## Summary

Confirmed on current main: `_shouldKeepHoverWidgetVisible()` (used by mouse-down/mouse-leave/mouse-move handlers) lacks the color-picker-drag check that `_shouldKeepCurrentHover()` already has, so the picker dismisses when the drag exits the widget bounds while still held. An open PR fixes this exact root cause, so keep the issue open for that PR to land rather than closing it now.

## Change summary

Dragging the color picker's saturation/value box past its own bounds while the mouse button is still held closes the picker and discards the change.

## Best solution

Land https://github.com/microsoft/vscode/pull/327575, which adds a shared `_isMaybeChoosingColor()` check into `_shouldKeepHoverWidgetVisible()` in contentHoverController.ts so all three affected call sites treat an in-progress color drag consistently.
