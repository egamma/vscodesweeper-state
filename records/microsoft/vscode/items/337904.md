# Issue #337904 — Claude agent host: steering messages sent mid-turn are never shown in the conversation

[https://github.com/microsoft/vscode/issues/337904](https://github.com/microsoft/vscode/issues/337904)

## Summary

Traced and confirmed on main: when Claude consumes a steering message mid-turn, agentSideEffects only dispatches `ChatPendingMessageRemoved` (clearing the pending bubble) and never creates a turn/request for the steered text, so it's dropped from the transcript entirely — while Codex's `_beginSteeringTurn` explicitly starts a fresh turn carrying the steering message, confirming the asymmetry the reporter describes.

## Change summary

Steering messages sent mid-turn to a Claude agent-host session vanish from the transcript instead of appearing as a user turn.

## Best solution

In the Claude steering path (claudeSdkPipeline.ts's `injectSteering` / the `steering_consumed` signal handled in agentSideEffects.ts around line 656), dispatch a turn-start action carrying the steering message as its user content — mirroring Codex's `_beginSteeringTurn` in codexAgent.ts — instead of only removing the pending-message bubble.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentSideEffects.ts`, `src/vs/platform/agentHost/node/claude/claudeSdkPipeline.ts`, `src/vs/platform/agentHost/node/claude/claudeAgent.ts`, `src/vs/platform/agentHost/common/state/protocol/channels-chat/reducer.ts`
- **Validation:** A test in agentSideEffects.test.ts or claudeAgent.test.ts asserting that after `steering_consumed` fires, the chat model contains a visible user-message entry for the steered text (not just an absence of the pending bubble).
- **Behavior:**

  > When a user sends a steering message while a Claude turn is running, that message must appear in the conversation transcript — either as its own turn or folded visibly into the running turn's history — both while the turn is still running and after it completes. Today it disappears entirely: no user-message record exists anywhere in the transcript once `steering_consumed` fires, even though the agent host log confirms the SDK received and acted on it. Acceptance: after a steer, re-reading the session (live or after reload) shows the steered text attributed to the user at the point it was sent.
- **Trace:**

  > Claude's `ClaudePromptQueue`/`ClaudeSdkPipeline.injectSteering` (claudeSdkPipeline.ts:452-486) enqueues the steering SDK message and fires a `steering_consumed` `AgentSignal` the moment the iterable yields it to the SDK (line ~269). `AgentSideEffects._handleAgentSignal` (agentSideEffects.ts:656-663) handles that signal by dispatching only `ChatPendingMessageRemoved` (kind: Steering), which the reducer (reducer.ts:862-867) uses solely to clear `state.steeringMessage` — no chat turn/request is ever created or appended. Contrast with Codex's `_beginSteeringTurn` (codexAgent.ts:3233-3257), which starts a fresh turn whose user message is the steering content, so Codex steering is visible. CONTEXT.md for the Claude pipeline documents that Claude folds steering into the *current* turn rather than starting a new one (M10 invariant), which is why simply copying Codex's new-turn approach may not fit — the boundary is: do not disturb the M10 folding invariant for turn-completion signaling (steering-consumed drains still must not fire `ChatTurnComplete` early); only add the missing visible-message record.
- **Open decisions:**
  - Should a Claude steering message become its own turn (like Codex), or remain folded into the currently running turn but still rendered as a visible user message within it (consistent with the M10 'steering folds into turn' invariant)?
  - If folded into the running turn, where in the existing turn/request model does an intra-turn user message attach, and does the existing chat renderer already support rendering a mid-turn user message, or does that also need UI work?
