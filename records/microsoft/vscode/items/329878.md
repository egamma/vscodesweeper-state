# Issue #329878 — Voice mode glow shows up on questions widget

[https://github.com/microsoft/vscode/issues/329878](https://github.com/microsoft/vscode/issues/329878)

## Summary

Team-authored bug report on a brand-new feature (voice mode ambient glow), filed hours ago with no fix yet — traced the exact defect in source: the glow's `confirmationPending` check is never gated by whether voice mode is actually connected, so any pending question/tool-input (the questions carousel/widget) lights up the ambient glow even with voice off, and keeps the RAF loop running idle, explaining the reported CPU use.

## Change summary

The audio-reactive voice mode glow renders around the chat input whenever a question/tool-confirmation is pending, even when voice mode isn't in use, and appears to burn CPU while idle.

## Best solution

In both src/vs/workbench/contrib/chat/browser/widgetHosts/viewPane/chatViewPane.ts and src/vs/workbench/contrib/chat/browser/voiceClient/voiceInputDecorations.ts, gate the `confirmationPending`-driven glow (and the RAF loop it keeps alive) on the voice session actually being connected/owned, not just on the presence of a pending tool confirmation for the current session — so the questions carousel no longer triggers the ambient voice glow or an idle animation loop when voice mode is off.
