# Issue #339239 — Selected custom endpoint can silently auto-route to another paid model

[https://github.com/microsoft/vscode/issues/339239](https://github.com/microsoft/vscode/issues/339239)

## Summary

Thanks for the report — the reporter explicitly says they lack reliable repro steps, and a second commenter only confirmed seeing 'the same auto route issue' without new detail, so there's no concrete reproduction to verify against main yet. There is a plausible mechanism in the code (the silent rate-limit auto-switch-to-Auto path doesn't check model vendor), but confirming it needs more from the reporters.

## Change summary

A selected custom (BYOK) endpoint model intermittently and silently gets replaced by an auto-routed GitHub-hosted model (seen: Claude Opus 5.5, GPT-6 Luna) while the UI still shows the custom endpoint selected, potentially consuming paid/premium requests.

## Best solution

If confirmed, the fix likely belongs in chatParticipants.ts's switchToAutoModel/shouldAutoSwitchToAuto path: switchToBaseModel already refuses to touch non-'copilot'-vendor (BYOK) requests, but switchToAutoModel has no such guard, so a rate-limited custom endpoint whose error body happens to carry a capiError.code starting with 'user_model_rate_limited' (and chat.rateLimitAutoSwitchToAuto enabled) could silently flip to Auto. That gap should be closed by adding the same vendor check, but first the reporters should confirm this is really what they're hitting.

## Evidence

- **vendor guard asymmetry:** extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts: switchToBaseModel (line ~293) early-returns when `request.model.vendor !== 'copilot'` (BYOK), but switchToAutoModel (line ~326) has no equivalent vendor check before switching the request to the shared 'auto' model and firing `workbench.action.chat.changeModel`.
- **silent auto-switch trigger:** extensions/copilot/src/extension/prompt/node/defaultIntentRequestHandler.ts (~line 514-524): on a RateLimited fetch result with `capiError.code` starting with 'user_model_rate_limited' and `ConfigKey.RateLimitAutoSwitchToAuto` (github.copilot.chat.rateLimitAutoSwitchToAuto, default false) enabled, `shouldAutoSwitchToAuto` is set, which chatParticipants.ts then acts on with only a stream.warning, no confirmation.
- **BYOK shares the same error shape:** extensions/copilot/src/extension/byok/node/openAIEndpoint.ts `hydrateBYOKErrorMessages` passes through `response.capiError` unchanged for RateLimited BYOK responses, and extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts's generic HTTP 429 handler sets `capiError: jsonData` from whatever JSON body the endpoint returned — so if a custom endpoint's 429 body happens to carry a matching code, the same silent-switch path could fire for BYOK, but this is unconfirmed for this reporter's endpoint.
- **setting default:** ConfigKey.RateLimitAutoSwitchToAuto (extensions/copilot/src/platform/configuration/common/configurationService.ts:1082) defaults to false, and is normally flipped by the user clicking 'Switch to Auto (always)' on a rate-limit confirmation button — so reproducing this requires knowing whether that setting is already on.
