# Issue #337193 — BYOK Responses API works for text but fails on tool calls

[https://github.com/microsoft/vscode/issues/337193](https://github.com/microsoft/vscode/issues/337193)

## Summary

Real, distinct gap: the retry logic that falls back off a stale/invalid `previous_response_id` only recognizes OpenAI's exact `previous_response_not_found` error code, so third-party Responses-API BYOK providers (here DeepSeek) that report the same underlying condition with a different code/message (`"No tool call found for tool output with call_id ..."`, `code: "invalid_request_error"`) never trigger the fallback and every tool-call turn fails with a 400.

## Change summary

BYOK custom endpoints configured with `apiType: "responses"` fail every tool-call request with a 400 `No tool call found for tool output with call_id ...` error, even though plain text works.

## Best solution

Broaden the invalid-previous-response detection in chatMLFetcher.ts (currently keyed solely on `jsonData?.code === 'previous_response_not_found'`) to also recognize this equivalent error signature from non-OpenAI Responses-API providers, so the existing `ignoreStatefulMarker: true` retry path (already used for the native case) kicks in for BYOK endpoints too.
