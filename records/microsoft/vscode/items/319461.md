[https://github.com/microsoft/vscode/issues/319461](https://github.com/microsoft/vscode/issues/319461)

## Summary

Keep open: marketplace discovery still produces installation-error notifications when a repository clone fails, and subsequent searches can repeat the attempt. The linked managed-settings test discussion independently confirms the repeated errors; no verified canonical or fixing commit establishes that this report is resolved.

## Change summary

Prevent repeated plugin-marketplace searches from generating intrusive clone-failure notifications under managed settings.

## Best solution

Keep marketplace discovery failures visible within the customizations search surface without repeated global installation-error notifications or excessive automatic retries. Preserve actionable errors for explicitly requested plugin installations and leave enterprise policy enforcement unchanged.

- **Trace:**

  > The report references https://github.com/microsoft/vscode/issues/319025, whose discussion independently confirms repeated errors and excessive clone attempts. Legacy PluginListWidget search methods call fetchMarketplacePlugins; the newer PluginCustomizationMarketplaceProvider.query calls queryMarketplacePlugins and returns source warnings. Both reach PluginMarketplaceService._fetchFromClonedRepo, then AgentPluginRepositoryService.ensureRepository and _cloneRepository for an uncached source. _cloneRepository emits a global installation-error notification before discovery catches the failure, and unsuccessful initial clones do not gain the successful repository cache entry that limits later requests. The remaining uncertainty is the observable retry/recovery contract and how discovery errors should be presented consistently across the old and new search surfaces.
