# Issue #342539 — powershellflags in settings.json not affecting powershell host in Copilot harness in vs code

[https://github.com/microsoft/vscode/issues/342539](https://github.com/microsoft/vscode/issues/342539)

## Summary

Current main already provides an explicit opt-in for loading user PowerShell profiles before Copilot SDK shell commands: chat.agentHost.shellTool.initScript.enabled. This addresses the reported local VS Code workflow without changing the process's -NoProfile argument or relying on agent instructions.

## Change summary

Provide deterministic PowerShell profile initialization for Copilot harness commands so user-defined tool paths and PATH ordering are available.

## Best solution

Use chat.agentHost.shellTool.initScript.enabled for the local editor-window Copilot SDK shell. Keep profile loading explicit through initialization scripts rather than assuming that standalone CLI PowerShell flags configure VS Code's harness.

- **Proposed comment:**

  > Thanks for the report. For the local VS Code editor window, enable `"chat.agentHost.shellTool.initScript.enabled": true`. This explicitly loads your current-user PowerShell profiles before each Copilot SDK shell command, including PATH initialization, without relying on agent instructions. The process can still show `-NoProfile` because the profiles are loaded by a separate initialization script.
  > 
  > This setting applies to the SDK built-in shell; it does not apply to remote-development windows or the custom terminal override.
