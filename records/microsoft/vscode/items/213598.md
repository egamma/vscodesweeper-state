# Issue #213598 — Move Line Up and Move Line Down breaks indentation in Javascript/Typescript files

[https://github.com/microsoft/vscode/issues/213598](https://github.com/microsoft/vscode/issues/213598)

## Summary

Keep open: current source still applies an extra indentation level to successive case labels when moving a statement down through the switch. A maintainer explicitly confirmed that the previously linked regression fix did not resolve this report.

## Change summary

Moving a JavaScript or TypeScript statement through a switch progressively corrupts the indentation of the surrounding case labels and statements.

## Best solution

Correct the move-lines indentation calculation so the supplied switch retains its surrounding indentation while the selected statement moves. Preserve existing automatic indentation for legitimate moves across block boundaries.

- **Current source failure:** In src/vs/editor/contrib/linesOperations/browser/moveLinesCommand.ts, getEditOperations calls matchEnterRule for the neighboring line being swapped upward during a downward move. Once the selected console.log sits between case 0 and case 1, matchEnterRule evaluates Enter at the end of case 0. parseEnterResult applies the returned extra indentation to case 1, even though that line is another case label.
- **Why the case-label guard fails:** extensions/typescript-basics/language-configuration.json:214-224 and extensions/javascript/javascript-language-configuration.json:196-205 indent after a case label unless afterText begins with case or default. src/vs/editor/common/languages/enterAction.ts evaluates afterText within the requested range's line; matchEnterRule requests an empty range at end of line, so afterText is empty rather than the neighboring case label. The guard therefore does not prevent the erroneous indentation.
