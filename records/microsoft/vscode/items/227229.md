# Issue #227229 — When "comment" text box is focused and "Review Pull Request" panel is in a sidebar, `sideBarFocus` does not get set to `true`

[https://github.com/microsoft/vscode/issues/227229](https://github.com/microsoft/vscode/issues/227229)

## Summary

Still reproduces on main: webview views in the sidebar don't propagate focus to the sidebar's FocusTracker because iframe focus/blur events don't cross the iframe boundary. The `sideBarFocus` context key never gets set when a webview view (e.g. PR comment box) receives focus. The `help wanted` label is already applied.

## Change summary

When a webview view in the sidebar is focused, the `sideBarFocus` context key is not set to `true`, breaking keybindings conditioned on it.

## Best solution

Bridge the webview's `onDidFocus`/`onDidBlur` events in `WebviewViewPane` to call `refreshState()` on the sidebar's `FocusTracker`, or dispatch synthetic focus/blur events on the webview view's container element so the existing `FocusTracker` in `PaneCompositePart` picks them up. The fix likely touches `src/vs/workbench/contrib/webviewView/browser/webviewViewPane.ts` and possibly the overlay webview's focus forwarding.
