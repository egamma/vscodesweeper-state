# Issue #227229 — When "comment" text box is focused and "Review Pull Request" panel is in a sidebar, `sideBarFocus` does not get set to `true`

[https://github.com/microsoft/vscode/issues/227229](https://github.com/microsoft/vscode/issues/227229)

## Summary

Keep open: current source still tracks sidebar focus through its DOM subtree, while webview views render in a separate workbench-root overlay. This leaves the reported sidebar-scoped shortcut without the expected focus context; the existing webview-views routing is appropriate.

## Change summary

Make sideBarFocus reflect focus inside a webview view's comment input when that view is hosted in the primary sidebar.

## Best solution

Ensure logical focus in a sidebar-hosted webview participates in the containing sidebar's focus context, including clearing that context when focus leaves. Preserve editor-webview and other workbench-region focus semantics.
