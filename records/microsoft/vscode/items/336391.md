# Issue #336391 — Chat panel hangs indefinitely when the Copilot backend process dies without automatic restart

[https://github.com/microsoft/vscode/issues/336391](https://github.com/microsoft/vscode/issues/336391)

## Summary

Well-investigated, first-hand report: the reporter confirmed by manually killing the Copilot CLI backend process that the Chat panel then hangs indefinitely with no error, and that Developer: Restart Extension Host is the only recovery. The actual process spawn/liveness/reconnect logic lives entirely inside the external `@github/copilot-sdk` package (used from src/vs/platform/agentHost/node/copilot/copilotSessionWrapper.ts and copilotAgentSession.ts), so I can't verify from this checkout whether the SDK already has (or lacks) a heartbeat/reconnect mechanism — this needs Copilot Chat/Agent Host team attention.

## Change summary

When the headless Copilot CLI backend process dies without a clean SDK shutdown, VS Code's Chat/Agent Host integration doesn't detect the dead connection or restart it, so an in-progress or new conversation hangs indefinitely with a spinner and no error.

## Best solution

Add liveness detection for the Copilot backend's stdio transport (or surface the SDK's own detection, if any) in copilotSessionWrapper.ts/copilotAgentSession.ts, and either auto-restart the backing session or surface an actionable error/notification instead of an infinite spinner — this is an Agent Host / Copilot Chat area decision, not something verifiable purely from this checkout since the process lifecycle is owned by @github/copilot-sdk.
