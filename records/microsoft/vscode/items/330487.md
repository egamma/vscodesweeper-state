# Issue #330487 — Chat sessions: expose provider-defined sticky session details in the chat editor

[https://github.com/microsoft/vscode/issues/330487](https://github.com/microsoft/vscode/issues/330487)

## Summary

The provider-defined presentation gap remains: current session APIs expose metadata and list-oriented descriptions, but not structured, dynamically updated sticky details in the chat editor. Keep this team-authored request open for API and UX design; no qualifying older canonical or concrete implementation was identified.

## Change summary

Let session providers publish structured details in a collapsible, persistent chat-editor header that updates independently of conversation turns.

## Best solution

Provide an explicit, provider-owned session-details contract and a compact optional editor surface, keeping arbitrary metadata opaque. Settle the supported content and interaction contract before implementation, while retaining the requested per-session collapse state and accessible narrow-width behavior.

- **Behavior:**

  > A session provider can explicitly publish structured session-level information that remains visible above the scrolling transcript and changes without adding conversation turns or recreating the session. Users can collapse the section, and that state survives reopening the same session. Sessions without details show no section. Arbitrary metadata remains opaque, and supported content and actions follow existing chat trust rules while remaining accessible at narrow editor widths.
- **Trace:**

  > ChatSessionItem in src/vscode-dts/vscode.proposed.chatSessionsProvider.d.ts and IChatSessionItem in src/vs/workbench/contrib/chat/common/chatSessionsService.ts expose metadata and list-oriented fields but no structured details collection. ExtHostChatSessions and MainThreadChatSessions already carry item updates across the extension-host boundary; the new presentation contract would need to remain consistent across that boundary and the editor/widget consumer.
