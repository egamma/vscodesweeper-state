# Issue #101064 — Allow us to change the font type and size of find-replace widget

[https://github.com/microsoft/vscode/issues/101064](https://github.com/microsoft/vscode/issues/101064)

## Summary

Keep this accepted accessibility request open: current source still lacks persistent font-family and font-size controls for the editor Find/Replace inputs. The related search-input request is newer, and maintainers explicitly distinguished the two surfaces.

## Change summary

Allow persistent customization of the editor Find/Replace input font family and size to improve readability.

## Best solution

Provide supported, persistent typography customization for both editor Find/Replace inputs, with layout that accommodates larger text and unchanged defaults. Coordinate the public configuration contract with the related search-input request without making global window zoom or developer-console overrides the solution.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/find/browser/findWidget.ts`, `src/vs/editor/contrib/find/browser/findWidget.css`, `src/vs/editor/contrib/find/test/browser/findController.test.ts`
- **Validation:** Using the agreed settings, configure a distinguishable monospace font and a larger size, open editor Find/Replace, and verify both inputs reflect them immediately and after window reload. Check long and multiline expressions, narrow editor widths, visible buttons, and unclipped text; restoring defaults must restore existing appearance and search behavior.
- **Behavior:**

  > Users need a supported way to persistently select the font family and size of text entered into the editor Find and Replace inputs. Horizontal resizing and whole-window zoom do not provide that independent customization. Both inputs must remain readable and operable at larger sizes, including multiline content and narrow editor layouts. Configuration must survive window reload, and users who do not opt in must retain the current appearance and behavior.
- **Trace:**

  > IEditorFindOptions and EditorFind in src/vs/editor/common/config/editorOptions.ts currently expose no typography settings. FindWidget._buildDomNode in src/vs/editor/contrib/find/browser/findWidget.ts creates ContextScopedFindInput and ContextScopedReplaceInput without font options; findWidget.css supplies fixed typography, and the shared input box inherits font family. FindWidget._getHeight uses measured input heights, and both inputs have flexible-height limits, so acceptance must cover measurement and layout rather than only textarea styling. scm.inputFontFamily and scm.inputFontSize provide existing configuration precedent but do not affect this surface. https://github.com/microsoft/vscode/issues/152518 tracks the separate search inputs, and its maintainer discussion explicitly preserves both issues. The remaining product decision is whether typography customization is editor-specific or shared with workspace-search inputs; do not change matching semantics, regex validation, history, or keyboard navigation.
- **Open decisions:**
  - Should persistent font-family and font-size preferences apply only to editor Find/Replace, or use a shared configuration contract that also governs workspace-search inputs?
