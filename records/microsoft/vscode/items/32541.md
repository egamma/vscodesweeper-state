# Issue #32541 — Toggle the block comment without having to select it

[https://github.com/microsoft/vscode/issues/32541](https://github.com/microsoft/vscode/issues/32541)

## Summary

Keep open: current source still lacks whole-block uncommenting from a caret on an interior line, and an open PR explicitly targets this request. The issue has 40 upvotes and already serves as the canonical report for this capability.

## Change summary

Allow editor.action.blockComment to remove an enclosing multiline block comment without selecting the comment first.

## Best solution

Deliver enclosing-block uncommenting through the existing Toggle Block Comment command while preserving selection-based toggling and normal comment insertion. Review the implementation candidate at https://github.com/microsoft/vscode/pull/309332 before commissioning competing work.

## Evidence

- **Current command behavior:** src/vs/editor/contrib/comment/browser/comment.ts passes each existing selection directly to BlockCommentCommand. In blockCommentCommand.ts, _createOperationsForBlockComment searches for opening and closing delimiters only on the selection's start and end lines. A collapsed selection on an interior line of a multiline comment therefore cannot find the enclosing delimiters and takes the comment-insertion path.
- **Existing-capability check:** editor.action.blockComment is the built-in command requested here. The EditorComments configuration in src/vs/editor/common/config/editorOptions.ts exposes editor.comments.insertSpace and editor.comments.ignoreEmptyLines, neither of which enables enclosing-block detection. Existing same-line removal and selection-based removal do not cover the central multiline request.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/309332 was verified OPEN with mergedAt null and a closing reference to this issue. Its description specifically proposes removing the enclosing block comment when the selection is collapsed inside it; the work is not completed.
- **Canonical ownership:** https://github.com/microsoft/vscode/issues/29004 is CLOSED as a duplicate of this issue, with the maintainer's explicit direction at https://github.com/microsoft/vscode/issues/29004#issuecomment-948668413. It is not an eligible canonical target; this issue owns that same request.
- **Related but distinct work:** https://github.com/microsoft/vscode/issues/133843 was verified OPEN and concerns invalid overlapping comments produced by Toggle Line Comment in JSX, HTML, and CSS. That is distinct from removing an enclosing block with an unselected caret. An open-issue search for block comments and cursor behavior did not identify a replacement canonical for this request.

The discussion links Gruntfuggly.bettercomment and AlexMunteanu.toggle-block-comments, including initial failures and later extension improvements; these are external workarounds, not evidence that the built-in command now satisfies the request.
