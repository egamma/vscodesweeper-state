# Issue #267086 — Support cursor rules

[https://github.com/microsoft/vscode/issues/267086](https://github.com/microsoft/vscode/issues/267086)

## Summary

The central interoperability request is only partially covered on current main: configured agent plugins can load `.cursor/rules/*.mdc` with Cursor-style glob metadata, but `chat.instructionsFilesLocations` still accepts only `*.instructions.md`, `.txt` rules remain unsupported, and the setting is now deprecated. Keep this open while maintainers decide whether Cursor compatibility should be automatic or exposed through the supported plugin/customization path.

## Change summary

Allow teams to reuse Cursor rule files from `.cursor/rules`, including their applicability globs, as VS Code chat instructions.

## Best solution

Provide a documented, supported compatibility path for `.cursor/rules` that preserves Cursor `globs` and `alwaysApply` semantics across agent harnesses, preferably through agent-plugin/customization discovery rather than extending the deprecated `chat.instructionsFilesLocations` setting. Maintainers should decide whether discovery is automatic and whether plain `.txt` files belong in that contract.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/plugins/agentPluginServiceImpl.ts`, `src/vs/platform/agentPlugins/common/pluginParsers.ts`, `src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts`, `src/vs/workbench/contrib/chat/test/common/plugins/agentPluginFormatDetection.test.ts`
- **Validation:** Extend the agent-plugin format-detection tests to create a `.cursor/rules` fixture with scoped and always-on rules, then verify the selected discovery contract exposes exactly the supported files and preserves `globs`/`alwaysApply` metadata.
- **Behavior:**

  > Teams can keep compatible rule files under `.cursor/rules` and have VS Code discover them through a supported customization mechanism. Cursor-style `globs` and `alwaysApply` metadata retain their applicability semantics. Existing `.instructions.md`, `.md`, agent-plugin, and native customization discovery remain unchanged. Acceptance must explicitly cover the chosen behavior for `.mdc`, `.md`, and `.txt` files.
- **Trace:**

  > The legacy path starts at `chat.instructionsFilesLocations`, registered in src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts, and filters files through the `.instructions.md` checks in promptFileLocations.ts and extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts. That setting is deprecated and limited to the Local agent harness. The supported plugin path is closer to the requested capability: ConfiguredAgentPluginDiscovery accepts workspace-relative plugin roots through `chat.pluginLocations`, pluginParsers.ts defaults rules to the plugin's `rules/` directory and parses Cursor-compatible `globs`/`alwaysApply`, and AgentPluginService._readRules accepts `.mdc`, `.md`, and `.instructions.md`. Therefore `{ "chat.pluginLocations": { ".cursor": true } }` covers `.cursor/rules/*.mdc` today, but there is no automatic `.cursor` discovery and no `.txt` support. Keep changes within customization/plugin discovery; do not revive or expand the deprecated local-harness setting unless maintainers explicitly choose that contract.
- **Open decisions:**
  - Should VS Code automatically discover `.cursor/rules`, or require users to register `.cursor` through `chat.pluginLocations` and document that compatibility path?
  - Should plain `.txt` files in the rules directory be accepted, or should the compatibility contract remain limited to structured Markdown/MDC formats?
  - Should Cursor-rule compatibility apply to every agent harness, or only harnesses that consume agent-plugin rules?
