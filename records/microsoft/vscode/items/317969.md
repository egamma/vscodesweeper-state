# Issue #317969 — Terminal renders as solid color blocks after switching macOS Spaces; text becomes visible only when selected

[https://github.com/microsoft/vscode/issues/317969](https://github.com/microsoft/vscode/issues/317969)

## Summary

Confirmed terminal WebGL rendering bug on macOS: the existing `onDidResumeOS` handler in `terminalNativeContribution.ts` calls `forceRedraw()` on sleep/wake, but macOS Space switching does not fire that event, leaving the WebGL framebuffer stale. A second reporter confirms the issue persists on 1.124.2.

## Change summary

Terminal content renders as solid color blocks (no glyphs) after switching macOS Spaces or waking from sleep; text reappears only when selected or scrolled.

## Best solution

Add a `visibilitychange` (or equivalent Electron window-focus) listener in `terminalNativeContribution.ts` that triggers `forceRedraw()` (and possibly `forceRefresh()`) when the window regains visibility after a macOS Space switch — the existing `onDidResumeOS` path only covers sleep/wake. The xterm.js WebGL addon's `clearTextureAtlas()` alone may also be insufficient; a full `raw.refresh(0, rows - 1)` may be needed to force the WebGL renderer to repaint its framebuffer.
