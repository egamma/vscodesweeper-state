# Issue #333907 — The **OPEN EDITORS** section should occupy all the available space

[https://github.com/microsoft/vscode/issues/333907](https://github.com/microsoft/vscode/issues/333907)

## Summary

The Open Editors pane is intentionally sized from its configured visible-slot limits rather than automatically filling all remaining Explorer space. The exact resizing request has previously been declined as designed, with settings available to reserve more space.

## Change summary

Make the Open Editors pane consume all available vertical space and allow its lower border to be dragged.

## Best solution

Keep the current dynamic sizing model and use `explorer.openEditors.minVisible` to reserve additional editor slots or `explorer.openEditors.visible` to control the initial visible capacity.

  > Thanks for the context. The Open Editors pane is intentionally sized from `explorer.openEditors.visible` and `explorer.openEditors.minVisible` rather than behaving like a freely resizable view; this avoids continuously moving the other Explorer views as editors open and close. Setting `explorer.openEditors.minVisible` to a larger value reserves more of the available space, so this matches the existing design documented in https://github.com/microsoft/vscode/issues/196470#issuecomment-1778003033.
