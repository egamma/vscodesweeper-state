# Issue #328589 — Claude session refresh repeatedly opens historical repositories and overloads file watching

[https://github.com/microsoft/vscode/issues/328589](https://github.com/microsoft/vscode/issues/328589)

## Summary

Team-authored (roblourens, MEMBER) performance bug describing a real feedback loop, confirmed by tracing the code; no fix commit or open PR exists yet, so this stays open for someone to pick up — team-authored items are protected from judgment closes anyway, and no mechanical implemented-on-main evidence exists.

## Change summary

The extension-host Claude session provider refreshes the entire session list on every Git repository open/close, force-opening every historical session's repository (including deleted ones) and never caching failed lookups, amplifying into repeated full O(sessions) repository scans and file-watcher overload.

## Best solution

In extensions/copilot's Claude chat-session code, switch historical-item rendering to a non-forcing repository lookup (getRepository2 already exists and takes forceOpen=false), cache negative getRepository lookups in ClaudeWorkspaceFolderService with explicit invalidation, and debounce/dedupe the onDidOpenRepository/onDidCloseRepository-triggered _refreshItems calls in claudeChatSessionContentProvider.ts so a single repository event doesn't cascade into a full session-list rescan.

## Evidence

- **refresh loop:** extensions/copilot/src/extension/chatSessions/vscode-node/claudeChatSessionContentProvider.ts registers onDidOpenRepository/onDidCloseRepository handlers that both call `void this._refreshItems(CancellationToken.None)` unconditionally on every event.
- **eager per-session lookup:** The same file's session-item builder calls `this._claudeWorkspaceFolderService.getWorkspaceChanges(session.cwd, ...)` for every historical session with a cwd, regardless of whether that repository is already open.
- **forceOpen default:** extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts: `getRepository(uri, forceOpen = true)` defaults to opening the repository via `gitAPI.openRepository(uri)` when not already tracked, matching the issue's described root cause.
- **no negative caching:** extensions/copilot/src/extension/chatSessions/vscode-node/claudeWorkspaceFolderServiceImpl.ts `_computeAndCacheChanges` returns `[]` early when `computeRepositoryChanges` finds no repository, without populating `_cache`, so failed/deleted-repo lookups are retried on every refresh — confirmed by reading the method.
- **non-forcing alternative exists:** gitServiceImpl.ts already exposes `getRepository2(uri)` which calls `_getRepository(uri, false)` (no forced open) — a plausible fix path to avoid the forced opens for historical/rendering-only lookups.
