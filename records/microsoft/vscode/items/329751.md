# Issue #329751 — Built-in skills cannot be disabled from the Customizations UI in the Agents window

[https://github.com/microsoft/vscode/issues/329751](https://github.com/microsoft/vscode/issues/329751)

## Summary

Confirmed on current main: the Disable action in the Customizations Skills view writes to `IPromptsService`'s disabled-prompt-files store, but `enumerateLocalCustomizationsForHarness` only consults `ICustomizationSyncProvider.isDisabled()`, and the Agents-window item model uses `PureItemProviderItemSource` which never reads the prompts-service store either — so disabling a built-in skill is silently a no-op.

## Change summary

Disabling a built-in skill from the Agents window Customizations UI is persisted but never read back, so the skill stays enabled and keeps being sent to the agent host.

## Best solution

Make `enumerateLocalCustomizationsForHarness` (agentHostLocalCustomizations.ts) also consult `promptsService.getDisabledPromptFiles(type)` when computing `disabled`, and update the Agents-window item source (aiCustomizationItemsModel.ts / aiCustomizationItemSource.ts) to merge built-in skills in from the prompts service directly so a disabled built-in skill remains visible (with Enable available) instead of disappearing from the bundle-derived list — coordinated with the related two-store consolidation in https://github.com/microsoft/vscode/issues/329753.
