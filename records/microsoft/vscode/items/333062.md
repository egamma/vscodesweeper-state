# Issue #333062 — "Reindent Lines" doesn't work correctly with square brackets

[https://github.com/microsoft/vscode/issues/333062](https://github.com/microsoft/vscode/issues/333062)

## Summary

Confirmed in source: Rust's built-in language configuration omits square brackets from its indentation-rule regexes, even though `[`/`]` are declared as a bracket pair, so Reindent Lines fails to increase/decrease indent around `vec![...]`-style macro calls.

## Change summary

Reindent Lines collapses/misindents content inside square-bracket blocks (e.g. `vec![...]`) in Rust files.

## Best solution

Add `\[` to `increaseIndentPattern` and `\]` to `decreaseIndentPattern` in extensions/rust/language-configuration.json, mirroring how extensions/cpp/language-configuration.json already handles all three bracket types.

- **Fix prompt:**

  > In extensions/rust/language-configuration.json, the `indentationRules` block (lines ~66-69) declares `increaseIndentPattern": "^.*\\{[^}\"']*$|^.*\\([^\\)\"']*$"` and `decreaseIndentPattern": "^\\s*(\\s*\\/[*].*[*]\\/\\s*)*[})]"`. These only account for `{`/`(` and `}`/`)`, but the `brackets` array in the same file also lists `[`/`]` as a valid pair. Because src/vs/editor/common/languages/supports/indentRules.ts (`IndentRulesSupport.shouldIncrease`/`shouldDecrease`) tests these exact regexes line-by-line, a line ending in `vec![` (or any other `[`-ending line) never registers as an indent-increasing line, and a line starting with `]` never registers as indent-decreasing — this is exactly what produces the collapsed/misindented output reported in https://github.com/microsoft/vscode/issues/333062 when running Reindent Lines over a `vec![...]` block. Fix by adding an alternative for `[` to `increaseIndentPattern` (e.g. `|^.*\\[[^\\]\"']*$`) and adding `\\]` to the character class in `decreaseIndentPattern` (making it `[)}\\]]` or similar), following the pattern already used in extensions/cpp/language-configuration.json which handles `{`, `(`, and `[` uniformly. Do not change the `brackets`, `autoClosingPairs`, `surroundingPairs`, `folding`, or `onEnterRules` sections — only the two indentationRules regex strings. Validate with a unit test (using IndentRulesSupport directly, or an autoIndent/reindent test fixture loaded with the rust language configuration) asserting that a line ending in `vec![` returns true from shouldIncrease and a line consisting of `];` or starting with `]` returns true from shouldDecrease.

## Evidence

- **root cause file:** extensions/rust/language-configuration.json lines 67-68: `increaseIndentPattern": "^.*\\{[^}\"']*$|^.*\\([^\\)\"']*$"` and `decreaseIndentPattern": "^\\s*(\\s*\\/[*].*[*]\\/\\s*)*[})]"` — neither pattern tests for `[` or `]`, unlike the `brackets`/`autoClosingPairs` sections in the same file which do include `[`,`]`.
- **comparison:** extensions/cpp/language-configuration.json's increaseIndentPattern includes `\\[[^\\]]*` and decreaseIndentPattern includes `\\]`, showing the expected pattern for bracket-aware indentation.
- **consumer:** src/vs/editor/common/languages/supports/indentRules.ts `IndentRulesSupport.shouldIncrease/shouldDecrease` directly test these regexes against the line text, so a line ending in `vec![` never triggers `shouldIncrease`, explaining the observed flattening of the bracketed content.
