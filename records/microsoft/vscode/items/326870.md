In extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts, getRepository defaults forceOpen to true, and _getRepository calls gitAPI.openRepository when the lookup misses, without checking workspace membership.
- **Discovery-boundary bypass confirmed:** extensions/git/src/api/api1.ts:499-505 calls model.openRepository(root.fsPath, true, true). In extensions/git/src/model.ts:635 and :666, those flags bypass the outside-workspace and explicitly closed-repository checks. The same model separately honors git.detectWorktrees when opening repositories, explaining why opening the main checkout can amplify the unwanted activation. Inspection was read-only; no runtime reproduction was executed.
- **Distinct reproduction evidence to preserve:** https://github.com/microsoft/vscode/issues/326870 supplies macOS instrumentation showing one repository after initial discovery, followed by Copilot-originated opens of sibling worktrees and the main checkout. Unlike the canonical's closed-worktree scenario with git.detectWorktrees disabled, this reproduction keeps worktree detection enabled and requires discovery to remain functional in a separate main-checkout window.
