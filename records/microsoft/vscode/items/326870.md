# Issue #326870 — Copilot Chat startup force-opens historical repositories outside the current workspace

[https://github.com/microsoft/vscode/issues/326870](https://github.com/microsoft/vscode/issues/326870)

## Summary

Traced and confirmed on current main: GitServiceImpl._getRepository unconditionally opens repositories outside the current workspace via the Git extension's forced-open API path, which is exactly what the reporter documented and what a prior related issue's suggested fix #2 left unaddressed.

## Change summary

Opening a single Git worktree as the workspace causes Copilot Chat's Git service to force-open historical/out-of-workspace repositories (main checkout, sibling worktrees), which in turn triggers built-in Git's detectWorktrees on those repos and pollutes the current window's Source Control repository list.

## Best solution

Guard the forceOpen fallback in extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts (_getRepository, lines 154-189) so `gitAPI.openRepository(uri)` is only called when the uri is inside a current workspace folder (or no workspace folders are open) — the reporter's tested patch does exactly this and is a small, well-scoped change.
