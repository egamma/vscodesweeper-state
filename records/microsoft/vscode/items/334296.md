# Issue #334296 — Remote-SSH: a stale 'code agent host' supervisor keeps serving new windows, so no agent session ever loads

[https://github.com/microsoft/vscode/issues/334296](https://github.com/microsoft/vscode/issues/334296)

## Summary

Fresh, team-authored bug report with a complete, code-confirmed diagnosis: a stale standalone agent-host supervisor is reused indefinitely because the registry never records/checks the build commit or protocol version, causing AHP negotiation to fail and leaving the session list silently empty. Author already confirmed the root cause and a manual workaround (killing the stale process); this is real, unfixed work — keep open.

## Change summary

A Remote-SSH agent host connection silently fails forever because the CLI reuses a stale, version-incompatible standalone supervisor from the registry without checking commit/protocol compatibility, and the client never retries after the failed handshake.

## Best solution

Two follow-ups belong on this: (1) extend the local agent-host endpoint registry schema to record the build commit and refuse to reuse a mismatched one in `cli/src/tunnels/agent_host.rs` (`classify_agent_host`/`agent_host_registry`), and (2) surface the `AHP_UNSUPPORTED_PROTOCOL_VERSION` failure to the user with a recovery action, plus add a reconnect path in `EditorRemoteAgentHostServiceClient` so a repaired remote doesn't require a window reload. Likely tracked together with or split from https://github.com/microsoft/vscode/issues/333175, which the author explicitly calls out as the same underlying registry gap.
