# Issue #287040 — When pressing Ctrl + '/', the system triggers Ctrl + '.' instead.

[https://github.com/microsoft/vscode/issues/287040](https://github.com/microsoft/vscode/issues/287040)

## Summary

Thanks for the report. Ctrl+/ resolves to the wrong key on Linux with a secondary layout (Russian) or a mismatched locale, and a commenter says it goes away under X11. That points to a keyboard-layout mapping problem that depends on the environment. I did not execute anything, and the report has enough detail to retest, so it stays open.

## Change summary

On Linux with multiple keyboard layouts, Ctrl+/ is interpreted as Ctrl+. (or Ctrl+;), which breaks the comment-line shortcut.

## Best solution

Find where the Linux keyboard layout mapping in the keyboard layout service resolves the key code for '/' under a secondary layout or a mismatched locale, and fix it so Ctrl+/ stays Ctrl+/. Compare with the related Wayland report, which may share the root cause.
