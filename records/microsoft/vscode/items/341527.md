# Issue #341527 — Image preview Copy is intermittently delayed by 1–7 seconds

[https://github.com/microsoft/vscode/issues/341527](https://github.com/microsoft/vscode/issues/341527)

## Summary

Thanks for the detailed measurements. The report is complete and the likely cause is Blink's idle-time `canvas.toBlob()` encoding in the image preview webview, which can fall back to a 1–7s watchdog when no idle period starts. I could not run it here, so the report stays open as likely upstream (Chromium), with a possible in-repo mitigation.

## Change summary

Copy from the built-in image preview intermittently takes 1–7s to put the image on the clipboard because PNG encoding in `canvas.toBlob()` is delayed.

## Best solution

Confirm on Insiders and with extensions disabled. Then either report or track the Chromium idle-encoding behavior, or have the media-preview Copy avoid the idle-dependent `toBlob` path. One option is to use the original image blob when it is already a PNG, or to fetch and re-encode it differently.
