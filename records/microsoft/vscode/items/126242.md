# Issue #126242 — Custom emmet snippets and issues with template languages

[https://github.com/microsoft/vscode/issues/126242](https://github.com/microsoft/vscode/issues/126242)

## Summary

The missing default suggestions were addressed in Emmet Helper, but the separate Pug custom-snippet inheritance problem remains in the helper source. Keep this open for that remaining dependency-owned work; the supplied reproduction is sufficient to retest.

## Change summary

Show custom and default Emmet snippets together in template languages, and expand shared HTML abbreviations using native Pug syntax.

## Best solution

Make Emmet Helper honor the documented inheritance of HTML custom abbreviations in Pug without mapping Pug to HTML output. Preserve the existing merged default/custom suggestion behavior and verify both parts using the supplied reproduction.

## Evidence

- **Complete reproduction:** https://github.com/BassOfBass/vscode-emmet-repro supplies a workspace with emmet.extensionsPath pointing to ./config/emmet, a jinja-html-to-html mapping, and HTML custom abbreviations including button:b and button:button. The report separately describes missing default suggestions and failure to use those custom abbreviations in Pug.
- **Partial fix:** https://github.com/microsoft/vscode-emmet-helper/commit/5cddea69d0d134ae9a0a57a355bc6c9f0ff47769 changes doComplete to merge getDefaultSnippets(syntax) with customSnippetsRegistry[syntax], rather than selecting one registry, and removes the custom-only snippetKeyCache assignment. This addresses the reported disappearance of default and colon-qualified suggestions, but does not change Pug inheritance.
- **Fix adoption:** https://github.com/microsoft/vscode/commit/8919d390ebbf9c4cf3a5f0a6d283bb3b4c8b1a42 adopted Emmet Helper 2.8.1 for https://github.com/microsoft/vscode/issues/130868. Current extensions/emmet/package.json depends on @vscode/emmet-helper ^2.8.8, and DefaultCompletionItemProvider.provideCompletionItemsInternal in extensions/emmet/src/defaultCompletionProvider.ts calls helper.doComplete directly. The dependency bump is delivery evidence, not the behavioral fix itself.
- **Remaining helper gap:** https://github.com/microsoft/vscode-emmet-helper/blob/v2.8.8/src/emmetHelper.ts selects customSnippetsRegistry[syntax] for markup expansion, without the base-syntax fallback used for stylesheets. updateSnippets merges HTML snippets into another markup syntax only when that syntax already has its own snippets entry. The reproduction defines only html, so native pug receives no custom registry; the same logic remains in the helper's current main source.
- **Mapping explains HTML output:** extensions/emmet/src/util.ts:getEmmetMode normally maps the VS Code jade language ID to Emmet pug. Setting emmet.includeLanguages to jade:html instead selects html before DefaultCompletionItemProvider passes the syntax to helper.doComplete, explaining the reported HTML output. This mapping is not a solution to native Pug custom-snippet support.
- **Documented expectation:** https://code.visualstudio.com/docs/languages/emmet#_html-emmet-snippets explicitly states that HTML custom snippets expressed as abbreviations apply to Pug and other markup flavors with the appropriate output transformation. The reproduction uses abbreviations, not literal HTML, so this expectation applies.
- **Canonical search:** Searches for custom Emmet snippets, colon suggestions, and Pug found no verified open canonical covering the full remaining problem. https://github.com/microsoft/vscode/issues/130868 is closed and covers only default-suggestion loss; https://github.com/microsoft/vscode/issues/157738 concerns completion disappearing during typing, and https://github.com/microsoft/vscode/issues/197890 concerns a different custom abbreviation failing to expand.
