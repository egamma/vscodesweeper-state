# Issue #342124 — Allow extensions to hide individual editor groups via `vscode.setEditorLayout`

[https://github.com/microsoft/vscode/issues/342124](https://github.com/microsoft/vscode/issues/342124)

## Summary

The extension-facing capability remains missing: current layout commands cannot hide one group while retaining multiple visible groups. Keep this open for an editor-area owner's decision; the closed UI requests do not establish a rejection of this narrower API proposal.

## Change summary

Allow extensions to hide individual editor groups without closing or moving their editors, and round-trip their visibility through the layout commands.

## Best solution

Evaluate a supported, opt-in layout capability that preserves group contents and restores hidden groups on activation, without adding built-in UI. Decide the public contract before accepting the reporter's contribution.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/grid/grid.ts`, `src/vs/workbench/browser/parts/editor/editorPart.ts`, `src/vs/workbench/services/editor/common/editorGroupsService.ts`, `src/vs/workbench/browser/parts/editor/editorCommands.ts`
- **Validation:** In an Extension Development Host, create three groups and hide only the rightmost through the supported layout command. Verify the other two remain visible, group/editor identities and undo state survive, visibility round-trips, activation restores the group, and reload and maximize/restore preserve the intended layout.
- **Behavior:**

  > Extensions should be able to temporarily hide a reference group while continuing to work in two other groups. Hiding must not close or relocate editors, discard undo history, or prompt to save. The proposal requests visibility round-tripping and reveal-on-activation without new built-in UI; these semantics require owner approval.
- **Trace:**

  > GroupLayoutArgument currently describes only sizes and nesting. EditorPart.applyLayout reconstructs the grid through createSerializedGrid, while getLayout strips leaf serialization down to size. Grid.setViewVisible provides internal visibility support, but descriptor construction does not expose it. Existing maximization is a different operation and must retain its default behavior. The reporter's branch is a contribution candidate, not evidence of implementation on main; this review did not execute or validate it.
- **Open decisions:**
  - Should the supported layout commands adopt the proposed leaf visibility contract, including round-tripping, reveal-on-activation, active-group fallback, and ignoring requests to hide every group?

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/services/editor/common/editorGroupsService.ts:84–99 defines GroupLayoutArgument with size and groups only. src/vs/workbench/browser/parts/editor/editorPart.ts:517–594 merges surplus groups when applying smaller layouts and returns only size for leaf groups; toggleMaximizeGroup uses single-view maximization rather than selective hiding.
