## Evidence

- **Task names are command arguments:** src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts:589–622 registers workbench.action.tasks.runTask with a string argument representing the task label/filter, or an object with type and task properties. The missing task identity is therefore an instance of the canonical issue's argument-visibility gap.
- **Existing-capability check:** In src/vs/workbench/services/preferences/browser/keybindingsEditorModel.ts, toKeybindingEntry derives commandLabel from registered command metadata through getCommandLabel, without incorporating command arguments. KeybindingItemMatches searches command IDs, labels, when clauses, sources and shortcuts, but not command arguments. The current model therefore does not deliver the requested task-name display or filtering.
- **Preserve specific acceptance requirement:** https://github.com/microsoft/vscode/issues/325612 adds a concrete task-binding use case: distinguish entries otherwise labeled Tasks: Run Task and find them by task name. Carry this display-and-search requirement into https://github.com/microsoft/vscode/issues/84072 rather than losing it in consolidation.
