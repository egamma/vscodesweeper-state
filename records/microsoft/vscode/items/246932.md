# Issue #246932 — Add config to control alpha/contrast of syntax highlighted completion suggestions (big copilot blocks can be jarring)

[https://github.com/microsoft/vscode/issues/246932](https://github.com/microsoft/vscode/issues/246932)

## Summary

Keep open: syntax-highlighted inline suggestions still use fixed opacity rather than a user-controlled value. Disabling highlighting is an existing workaround, but does not deliver the requested combination of syntax colors and adjustable dimming.

## Change summary

Allow users to reduce the visual prominence of syntax-highlighted inline completions without disabling syntax highlighting.

## Best solution

Provide a theme-consistent way to adjust highlighted completion opacity while preserving syntax colors and the distinction between suggested and accepted code. Decide whether this follows editorGhostText.foreground alpha or uses an independent control, without weakening high-contrast defaults.

- **Trace:**

  > GhostTextView in src/vs/editor/contrib/inlineCompletions/browser/view/ghostText/ghostTextView.ts tokenizes suggestions and adds the syntax-highlighted class. ghostTextView.css gives that class fixed opacity: 0.7, while applying editorGhostText.foreground only when syntax highlighting is absent. InlineEditorSuggest in src/vs/editor/common/config/editorOptions.ts exposes a highlighting toggle but no opacity control; ghost color registrations live in src/vs/editor/common/core/editorColorRegistry.ts. The missing capability was established by source inspection, not runtime execution.
