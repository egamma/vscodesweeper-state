## Evidence

- **Exact workspace-source symptom:** https://github.com/microsoft/vscode/issues/129425#issuecomment-2345721249 explicitly reproduces this report's workspace launch section plus .vscode/launch.json arrangement: flipping justMyCode resets the Run and Debug selector from the workspace configuration to the folder configuration. This establishes the same reporter-observable symptom, not merely a related root cause, satisfying the stronger re-review duplicate bar.
- **Current source confirms selection replacement:** In src/vs/workbench/contrib/debug/browser/debugConfigurationManager.ts, registerListeners() calls selectConfiguration(undefined) whenever launch configuration changes. selectConfiguration() resolves an undefined launch from the last active workspace folder or the first launch with configurations, assigns it to selectedLaunch, and falls back to that launch's first configuration when selectedName is absent there. It does not preserve the previously selected workspace launch, explaining both the reported reset and why an existing selection in the preferred folder can remain unchanged.
- **Evidence to preserve:** https://github.com/microsoft/vscode/issues/270016 supplies Windows 11 / VS Code 1.104.3 reproduction steps, reports occurrence with extensions disabled, and links https://github.com/FMorschel/vscode-repro-launch. The reporter's follow-up notes that selecting a second configuration within the first folder source does not trigger a reset.
