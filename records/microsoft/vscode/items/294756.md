# Issue #294756 — wrong active file highlighted

[https://github.com/microsoft/vscode/issues/294756](https://github.com/microsoft/vscode/issues/294756)

## Summary

The Explorer intentionally retains the selected list item, and the existing global `workbench.colorCustomizations` setting already lets users neutralize its active and inactive colors across themes.

## Change summary

Add a global setting that prevents themes from visually highlighting the selected Explorer item.

## Best solution

Keep the standard list/tree selection behavior and use unscoped `workbench.colorCustomizations` entries when a user wants the selected row to match the surrounding Explorer colors across every theme.

## Vision fit

- **Fit:** rejected
- **Reason:** A dedicated toggle for one list-selection treatment would add configuration and component-specific behavior where the existing theme-token mechanism already provides customization.
- **Evidence:** Values and guardrails: simple, uniform UI and UI interactions; UI consistency beats per-feature customization.

  > Thanks for the report. The highlighted row is the Explorer's selected list item and is intentional shared list/tree behavior. `workbench.colorCustomizations` already overrides the selected theme globally: remove the `[Monokai Pro]` wrapper from your working customization and place `list.activeSelectionBackground`, `list.activeSelectionForeground`, `list.inactiveSelectionBackground`, and `list.inactiveSelectionForeground` directly in the object so the values apply across themes.

## Evidence

- **existing global capability:** `src/vs/workbench/services/themes/common/themeConfiguration.ts` defines `workbench.colorCustomizations` as overriding colors from the currently selected theme; no `[Theme Name]` scope is required.
- **override precedence:** `src/vs/workbench/services/themes/common/colorThemeData.ts` loads unscoped custom colors into `customColorMap`, and `getColor` returns those custom values before the selected theme's `colorMap`.
- **selection tokens:** `src/vs/platform/theme/common/colors/listColors.ts` defines `list.activeSelectionBackground`, `list.activeSelectionForeground`, `list.inactiveSelectionBackground`, and `list.inactiveSelectionForeground` specifically for selected list/tree items.
- **maintainer precedent:** In https://github.com/microsoft/vscode/issues/98986#issuecomment-638961366 and https://github.com/microsoft/vscode/issues/98986#issuecomment-639307900, maintainers explain that persistent list/tree selection is shared behavior and has existed since the initial implementation.
- **reporter workaround:** The reporter confirmed that overriding the four active/inactive selection color tokens neutralizes the highlight; removing the `[Monokai Pro]` wrapper makes those same overrides global rather than theme-specific.
