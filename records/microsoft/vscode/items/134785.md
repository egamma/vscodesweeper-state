# Issue #134785 — Git - merge-conflict cannot resolve binary files

[https://github.com/microsoft/vscode/issues/134785](https://github.com/microsoft/vscode/issues/134785)

## Summary

Keep open: the advertised Source Control actions still depend on text conflict markers and cannot select a binary file's incoming or current version. The discussion confirms that users can subsequently commit the wrong version; no qualifying canonical duplicate or landed fix was established.

## Change summary

Accept All Current and Accept All Incoming fail to resolve binary files selected under Merge Changes.

## Best solution

Provide byte-preserving selection of the appropriate Git conflict side for binary resources in Source Control, with explicit failure feedback. Preserve text-editor conflict-block resolution and ensure subsequent staging records the selected binary version.

- **Behavior:**

  > Selecting Accept All Incoming or Accept All Current for a conflicted binary file must leave the working file byte-for-byte equal to the selected Git conflict side. Subsequent staging must record that selected version rather than silently retaining the other side. Failures must be visible to the user. Acceptance checks cover both choices, a mixed text/binary resource selection, and preservation of existing text-editor conflict-block resolution.
- **Trace:**

  > The Source Control menu entries in extensions/merge-conflict/package.json invoke CommandHandler.registerTextEditorCommand, which forwards resourceUri arguments to acceptAllResources in extensions/merge-conflict/src/commandHandler.ts. That method opens text documents and edits parsed conflict ranges; DocumentMergeConflictTracker.getConflictsOrEmpty and MergeConflictParser.containsConflict reject marker-free content. This conclusively explains the binary no-op without executing the application. Git integration lives in extensions/git/src/commands.ts and repository.ts; the exported API in api/api1.ts and api/git.d.ts exposes show as a string result and checkout as a treeish operation, so a safe binary-resolution integration has not been established by this trace. Preserve text-editor block semantics and do not infer binary conflict status from text markers. The related maintainer discussion at https://github.com/microsoft/vscode/issues/66950#issuecomment-458044420 supports Git-level side selection; https://github.com/microsoft/vscode/issues/102857 is related bulk/large-file work, not a verified duplicate for this re-review. Planning must complete the binary-safe repository boundary and identify an executable regression harness before implementation.
