# Issue #128565 — [semantic highlighting] Source language suffix should be added to semantic token fallback scopes when looked up

[https://github.com/microsoft/vscode/issues/128565](https://github.com/microsoft/vscode/issues/128565)

## Summary

Valid, unimplemented feature request from a team member. The semantic token fallback scope resolution in `colorThemeData.ts` still does not append language-specific suffixes when probing TextMate scopes, so language-specific theme rules (e.g. `storage.type.cpp`) are not matched during semantic token fallback. Keeping open as a Backlog item.

## Change summary

When VS Code looks up fallback TextMate scopes for semantic tokens, it should append the source language ID suffix so that language-specific theme colorization rules are applied.

## Best solution

In `src/vs/workbench/services/themes/common/colorThemeData.ts` around line 229, when probing `rule.defaults.scopesToProbe`, also generate language-suffixed variants of each scope (e.g. `entity.name.type` → `entity.name.type.cpp`) so that language-specific theme rules match. The language-to-TM-suffix mapping noted by aeschli (language ID ≠ TM scope suffix, e.g. `typescript` vs `.ts`) would need a new mechanism, possibly in the `semanticTokenScopes` contribution point.
