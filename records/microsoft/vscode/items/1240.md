# Issue #1240 — Support contributing different keybindings based on keyboard layout

[https://github.com/microsoft/vscode/issues/1240](https://github.com/microsoft/vscode/issues/1240)

## Summary

Keep this accepted, well-supported request open: current layout detection translates existing bindings, but does not provide layout-specific default keymaps. The maintainer explicitly endorsed layout-specific exceptions, and the related open reports do not replace this older, broader request.

## Change summary

Select keyboard-layout-specific default shortcuts at runtime so commands remain ergonomic without occupying combinations needed for character entry.

## Best solution

Support layout-aware default keybinding contributions in the core keybinding infrastructure, including the endorsed Polish character-entry exception and optimized Swiss shortcuts. Agree on the contribution contract and fallback behavior before implementation, preserving explicit user overrides.

- **Behavior:**

  > VS Code should choose appropriate default shortcuts for the active keyboard layout without requiring manual remapping. The request includes an ergonomic Swiss commenting shortcut and the maintainer-endorsed exception that leaves Polish Alt+Z available for character entry. Changing layouts should update applicable defaults while preserving explicit user overrides. Acceptance must cover known layouts, an unrecognized or custom layout, and unchanged behavior on unaffected layouts.
- **Trace:**

  > KeyboardLayoutService in src/vs/workbench/services/keybinding/electron-browser/nativeKeyboardLayout.ts already detects layout changes and creates a keyboard mapper. KeybindingsRegistry in src/vs/platform/keybinding/common/keybindingsRegistry.ts selects OS-specific rules, and WorkbenchKeybindingService._getResolver/_resolveKeybindingItems in src/vs/workbench/services/keybinding/browser/keybindingService.ts translates those defaults through the active mapper. The extension contribution schema exposes OS variants but no layout-specific variant; existing dispatch settings are not a substitute for optimized defaults. The accepted Polish behavior is recorded at https://github.com/microsoft/vscode/issues/1240#issuecomment-420647915. Preserve user overrides and existing dispatch semantics; the latest character-based dispatch request is not automatically part of this feature. The trace establishes the missing selection/contribution surface, but not a settled public contract for layout identifiers, fallback, or the initial shipped keymaps.
- **Open decisions:**
  - What stable layout identity or matching contract should built-in and extension keybinding contributions use, including custom layouts?
  - Which layout-specific defaults should ship initially beyond the endorsed Polish exception and requested Swiss shortcut?
  - For unknown layouts or unavailable layout information, should VS Code retain current OS defaults or apply any character-entry conflict exclusions?
