# Issue #337910 — Agents: cached tunnels trigger repeated GitHub sign-in loop

[https://github.com/microsoft/vscode/issues/337910](https://github.com/microsoft/vscode/issues/337910)

## Summary

Team-authored, freshly filed bug (author is a VS Code collaborator) with an exact, verified root-cause trace in current main; no fix has landed yet, so it stays open — team-authored items are only closed with a concrete referencing fix commit, which doesn't exist here.

## Change summary

Cached Dev Tunnels with no saved gateway-location preference each force interactive GitHub sign-in during automatic startup reconciliation, and since several tunnels reconcile near-simultaneously, completing one queued sign-in immediately triggers the next — an apparent endless sign-in loop.

## Best solution

Split the single `userInitiated` flag into a separate authentication-interaction flag (always false during automatic reconciliation) and a gateway-selection-interaction flag (may still prompt when no location preference exists), across both the electron-browser and browser tunnel connection factories; consider coalescing concurrent auth requests for the same provider/scopes as defense in depth.

- **Open decisions:**
  - When a cached tunnel has no saved gateway-location preference and reconciles automatically, should gateway selection still prompt interactively, silently defer connection until the user acts, or fall back to a default gateway — while authentication itself must never become interactive during this automatic path?
