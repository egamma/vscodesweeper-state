# Issue #326318 — Allow Go Back/Go Forward to skip closed editors

[https://github.com/microsoft/vscode/issues/326318](https://github.com/microsoft/vscode/issues/326318)

## Summary

Genuine, unimplemented request: the editor navigation stack in historyService.ts only drops an entry when the underlying EditorInput fully disposes (not simply when the tab is closed), and there's no existing GoFilter option to skip entries whose editor is no longer open. Still early in its 60-day Backlog Candidates window with 0 upvotes, so per policy this stays open as under-discussion rather than closing for being quiet.

## Change summary

Add an option so Go Back/Go Forward navigation skips history entries whose editor has since been closed, instead of reopening it.

## Best solution

Belongs in src/vs/workbench/services/history/browser/historyService.ts (EditorNavigationStack/goBack/goForward) — track open/closed state per stack entry (or check editorService for a matching open editor) and add a filter/setting to skip closed ones during navigation; needs a maintainer design decision on default behavior before implementation.
