# Issue #130880 — Allow key bindings to work on tree view items

[https://github.com/microsoft/vscode/issues/130880](https://github.com/microsoft/vscode/issues/130880)

## Summary

This is a valid, unimplemented feature request for making tree view item context (viewItem, selected items) available to keybindings. The discussion includes thoughtful design input from team members. It sits on the On Deck milestone, which does not block a close but the request remains genuinely unaddressed — no code change has landed.

## Change summary

When a keybinding triggers a command while a tree view item is focused, the tree item should be passed as a command argument (and viewItem context should be matchable in when clauses), just as it is from the context menu.

## Best solution

Implement a mechanism so that when a tree view has focus, the focused/selected item's contextValue is set as a persistent context key (not just an overlay for context menus), and the selected tree items are passed as arguments to commands triggered via keybindings. This likely involves changes in `src/vs/workbench/browser/parts/views/treeView.ts` (where `viewItem` is currently only set as an overlay in `getElementOverlayContexts`) and the keybinding resolution layer. The design discussion in comments 4–7 and 9 outlines possible approaches — an `activeTree`-aware keybinding resolution, or promoting `viewItem` to a real context key on focus.
