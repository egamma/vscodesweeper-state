# Issue #203539 — Workspace Trust - Workspace trust should not default to true when hitting enter?

[https://github.com/microsoft/vscode/issues/203539](https://github.com/microsoft/vscode/issues/203539)

## Summary

The current source confirms that bare Enter accepts the first, trust-granting action. This remains an accepted Backlog security/UX decision under discussion, with no older open canonical owning the same observable behavior.

## Change summary

Make bare Enter on the startup Workspace Trust dialog preserve Restricted Mode instead of trusting the workspace.

## Best solution

Choose a fail-safe keyboard behavior for the startup trust prompt: either Enter should select Restricted Mode or it should require an explicit button choice, while deliberate keyboard and pointer activation of the trust action remains available.

Acceptance must cover initial focus, Enter, Tab/Shift+Tab, and explicit activation of both choices.
- **Trace:**

  > WorkspaceTrustUXHandler.doShowModal in src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts supplies the trusted action as the first prompt button and completes the request with true when it runs. Keep the scope to the startup Workspace Trust prompt: do not globally change default-button semantics for unrelated dialogs, and preserve deliberate mouse, mnemonic, and keyboard access to both trust choices.
- **Open decisions:**
