# Issue #342382 — Agent Host: an unresponsive window blocks every send in a chat indefinitely (retryFailedClientSyncIfNeeded has no timeout)

[https://github.com/microsoft/vscode/issues/342382](https://github.com/microsoft/vscode/issues/342382)

## Summary

The indefinite wait remains possible on current main: sending awaits every contributing client's plugin sync, while unanswered reverse requests have no deadline. Existing cancellation support does not provide automatic recovery from a connected but unresponsive window.

## Change summary

Prevent an unresponsive window's plugin synchronization from indefinitely blocking messages sent by another window sharing the chat's configuration scope.

## Best solution

Bound customization preparation so a stalled client produces a recoverable, explicit outcome rather than indefinitely occupying the chat queue. Decide whether an incomplete customization sync should fail the send or allow it to proceed with clearly reported unavailable customizations, preserving enablement and access restrictions.
