# Issue #234513 — Poor/pathological multi-cursor performance

[https://github.com/microsoft/vscode/issues/234513](https://github.com/microsoft/vscode/issues/234513)

## Summary

The pathological growth remains possible on current main: Add Cursor Below/Above produces two states for every existing cursor and relies on overlap normalization to remove duplicates. When overlapping-cursor merging is disabled, repeated commands grow the cursor collection exponentially until the 10,000-cursor limit, explaining the reported freeze.

## Change summary

Repeatedly adding cursors above or below can exponentially duplicate cursor states and freeze the editor.

## Best solution

Make Add Cursor Below and Add Cursor Above add only the new unique frontier cursors required by the command, without relying on the global overlapping-cursor merge setting, while preserving word-wrap and end-of-document behavior.

  > Repeated Add Cursor Below or Add Cursor Above actions must grow the cursor set linearly rather than doubling it, including when editor.multiCursorMergeOverlapping is false. - **Trace:**

  > InsertCursorBelow.run and InsertCursorAbove.run in src/vs/editor/contrib/multicursor/browser/multicursor.ts pass every current cursor to CursorMoveCommands.addCursorDown/addCursorUp. Those methods in src/vs/editor/common/cursor/cursorMoveCommands.ts return the original and translated state for each input cursor, so each action creates 2N candidates. Cursor.setStates in src/vs/editor/common/cursor/cursor.ts materializes those candidates before CursorCollection.normalize runs, and normalize deliberately performs no merging when editor.multiCursorMergeOverlapping is false. This makes repeated actions double the collection until editor.multiCursorLimit is reached. Keep the boundary to these multicursor insertion commands: do not change the global semantics of editor.multiCursorMergeOverlapping or unrelated selection normalization. The related https://github.com/microsoft/vscode/issues/123303 concerns a different command and should not be treated as covering this regression.
