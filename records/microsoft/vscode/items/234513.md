# Issue #234513 — Poor/pathological multi-cursor performance

[https://github.com/microsoft/vscode/issues/234513](https://github.com/microsoft/vscode/issues/234513)

## Summary

Still reproduces on current main: `addCursorDown` in `cursorMoveCommands.ts` iterates over all existing cursors and doubles the state array each invocation. With `multiCursorMergeOverlapping: false`, this causes genuine exponential growth (1→2→4→8→…) leading to a freeze. Even with the default `true`, the algorithm wastefully creates O(2n) states before normalize merges duplicates.

## Change summary

Using Add Cursor Below repeatedly causes VS Code to freeze because the cursor array doubles on each invocation, and deduplication only happens downstream.

## Best solution

Fix `addCursorDown` (and `addCursorUp`) in `src/vs/editor/common/cursor/cursorMoveCommands.ts` to only add a new cursor below the bottom-most (or above the top-most) existing cursor rather than duplicating every existing cursor. This avoids the exponential blowup regardless of the `multiCursorMergeOverlapping` setting and eliminates the wasteful create-then-destroy cycle in `normalize`.
