# Issue #334575 — Agent host: a local slash command's output is never shown, leaving an empty turn

[https://github.com/microsoft/vscode/issues/334575](https://github.com/microsoft/vscode/issues/334575)

## Summary

Well-traced report: both the live Claude dispatch path and the replay mapper drop `local_command`/`local-command-stdout` content entirely, so any local slash command with real output (e.g. `/code-review`) ends its turn empty. This is a legitimate, currently-unfixed gap, not something to close.

## Change summary

A local slash command's stdout/stderr output is discarded instead of shown, leaving the assistant turn empty in the Agent Host UI even though the command ran and produced content.

## Best solution

In `claudeReplayMapper.ts`, split `local-command-stdout`/`local-command-stderr` out of `CLI_ECHO_MARKER_PATTERN` so their payload text is surfaced as a response part on the active turn (while still dropping `command-name`/`command-args`/`local-command-caveat`), and add the mirrored live-path handling for the `SDKLocalCommandOutputMessage`/`local_command` system subtype in the extension-host dispatcher — this needs a maintainer decision on which response-part shape to reuse (e.g. `SystemNotification` vs. a new kind) before implementing both sides consistently.
