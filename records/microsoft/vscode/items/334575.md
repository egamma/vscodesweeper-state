# Issue #334575 — Agent host: a local slash command's output is never shown, leaving an empty turn

[https://github.com/microsoft/vscode/issues/334575](https://github.com/microsoft/vscode/issues/334575)

## Summary

Confirmed in source: both the replay and live Claude mappers drop `local_command` system output entirely, so a local slash command's stdout/stderr is never surfaced as a response part — the turn renders empty even though the command produced real output.

## Change summary

A local slash command's stdout/stderr is silently discarded instead of being shown as the turn's response, leaving an empty assistant bubble.

## Best solution

In claudeReplayMapper.ts, add `local_command` handling that extracts `<local-command-stdout>`/`<local-command-stderr>` text and emits a response part (e.g. reuse SystemNotification or a dedicated kind) while still dropping the echo/caveat markers via the existing CLI_ECHO_MARKER_PATTERN path; mirror the same extraction in the live path (claudeMapSessionEvents.ts's system-message handling) so live and replay behave consistently.
