# Issue #325265 — Webview resources fail silently with ERR_INSUFFICIENT_RESOURCES when a webview loads thousands of files (Linux renderer keeps default 1024 nofile soft limit)

[https://github.com/microsoft/vscode/issues/325265](https://github.com/microsoft/vscode/issues/325265)

## Summary

The reported resource-exhaustion trigger is addressed on current main by a merged fix that limits concurrent webview response bodies throughout their streaming lifetime. Propose closing as completed; the fix implements the report's throttling alternative rather than raising renderer limits.

## Change summary

Prevent large concurrent webview resource bursts from exhausting Linux renderer file descriptors and leaving extension views unable to initialize.

## Best solution

Retain the response-body concurrency limiter introduced in commit 17d3b86b9361cba49d8d0238787d9aa590e657ca, which addresses the reported startup failure without requiring users to change desktop-session limits.
