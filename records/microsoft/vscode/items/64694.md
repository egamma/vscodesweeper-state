# Issue #64694 — Allow to configure cursor keys for input fields

[https://github.com/microsoft/vscode/issues/64694](https://github.com/microsoft/vscode/issues/64694)

## Summary

Keep this accepted feature request open: current command routing still does not make configurable cursor movement and word deletion operate on focused native input fields. It has 36 upvotes, and the related reports do not provide an older, open canonical covering its full scope.

## Change summary

Allow configurable cursor movement, selection, and basic deletion shortcuts to act consistently on focused input fields rather than the active editor.

## Best solution

Provide a supported set of focus-aware editing commands for native inputs used by Search, Find, and Quick Open, while preserving existing editor behavior and native input editing semantics. Plan the shared command contract and cross-widget validation before implementation.

  > Users can configure a supported set of cursor movement, selection, and deletion shortcuts for core text-entry fields. The requested initial command set needs to be made explicit.
- **Trace:**

  > InputBox in src/vs/base/browser/ui/inputbox/inputBox.ts creates native HTML inputs or textareas. cursorLeft in src/vs/editor/browser/coreCommands.ts and deleteWordLeft in src/vs/editor/contrib/wordOperations/browser/wordOperations.ts use EditorCommand; its dispatcher in src/vs/editor/browser/editorExtensions.ts selects a focused or active code editor, not the active native input. This establishes the capability gap, but not a bounded implementation across all consumers of shared input and editor command infrastructure.
