# Issue #317967 — Show file names more clearly in compare editor

[https://github.com/microsoft/vscode/issues/317967](https://github.com/microsoft/vscode/issues/317967)

## Summary

Keep open: existing tab labels can identify both files, but do not provide the persistent, pane-local identification requested here. The request has supporting feedback and needs a UX decision rather than a bug fix.

## Change summary

Display clearly associated file names or relative paths above each side of the compare editor.

## Best solution

Provide quiet, readable identification of the original and modified files next to their respective panes in the workbench text diff editor. Agree on visibility defaults and long-path handling before implementation, preserving the current comparison layout and editing behavior.

- **Behavior:**

  > Users comparing similarly named files should be able to identify which file occupies each side without hovering over a shared tab. Each visible identifier must remain associated with the correct comparison input when inputs change or are swapped. Acceptance should cover names differing only at the end, identical basenames in different folders, and long paths at narrow widths. Existing editing and diff navigation must remain unchanged.
- **Trace:**

  > TextDiffEditor in src/vs/workbench/browser/parts/editor/textDiffEditor.ts creates DiffEditorWidget directly and sets its comparison model in setInput(); the inspected path does not construct pane-local file titles. DiffEditorInput.computeLabels() in src/vs/workbench/common/editor/diffEditorInput.ts already has both input identities but combines them for the shared editor label and title. workbench.editor.labelFormat and workbench.editor.tabSizing improve that shared label rather than supplying the requested per-pane surface. The boundary is ordinary workbench text comparison: do not redesign merge editors, multi-diff editors, or global tab behavior. The remaining uncertainty concerns the visibility default and readable treatment of long or otherwise ambiguous paths. https://github.com/microsoft/vscode/issues/285547 concerns Explorer truncation and is related context, not a duplicate canonical.
- **Open decisions:**
  - Should pane-local file identifiers be visible by default in ordinary side-by-side comparisons, or require an opt-in setting?
  - Should identifiers always show relative paths, or show basenames with path disambiguation when necessary, and how should long identifiers remain readable without hovering?
