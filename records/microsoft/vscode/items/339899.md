# Issue #339899 — Long lines in code blocks are cut off

[https://github.com/microsoft/vscode/issues/339899](https://github.com/microsoft/vscode/issues/339899)

## Summary

Confirmed in source: fenced code blocks in the Markdown preview always get the `hljs` class, which makes them miss the `overflow: auto` rule entirely (the CSS only applies it via `pre:not(.hljs)` or a dead `pre.hljs code > div` selector that nothing in the renderer actually produces), so long lines are clipped with no scrollbar. Reporter confirmed the bug is specific to triple-backtick code blocks (not indented ones), which matches the traced root cause exactly.

## Change summary

Long single lines inside fenced (```) code blocks in the Markdown preview are cut off and cannot be scrolled to, unlike indented code blocks which scroll fine.

## Best solution

Fix the CSS in extensions/markdown-language-features/media/markdown.css so `overflow: auto` applies to all `<pre>` blocks regardless of the `.hljs` class (e.g. merge `pre:not(.hljs)` and the dead `pre.hljs code > div` rule into a single `pre { overflow: auto; }`), restoring horizontal scrolling for fenced code blocks.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/media/markdown.css`
- **Validation:** Open a Markdown file with a fenced (```) code block containing a line much wider than the preview pane, switch to preview, and confirm a horizontal scrollbar appears on the `<pre>` and the full line is reachable — matching the already-working behavior of an indented (non-fenced) code block with the same long line.
- **Behavior:**

  > Long single lines inside fenced (triple-backtick) code blocks in the Markdown preview should be horizontally scrollable (or wrapped, depending on the word-wrap preview setting) just like indented code blocks are today, instead of being silently clipped with no way to reach the rest of the line. Acceptance: a fenced code block with a long line shows a scrollbar (or wraps) and all its content is reachable in the preview.
- **Trace:**

  > extensions/markdown-language-features/src/markdownEngine.ts `#addFencedRenderer` (~lines 263-276) adds the `hljs` class to essentially every real fenced code block's `<pre>`, regardless of whether highlighting actually occurred. extensions/markdown-language-features/media/markdown.css lines 414-419 splits the overflow rule into `pre:not(.hljs) { overflow: auto }` and `pre.hljs code > div { overflow: auto }`; the latter targets a `<code> > div` structure that is never produced anywhere in the renderer (checked preview-src and markdownEngine.ts — highlight.js output here is inline spans directly in `<code>`, no wrapping div). Net effect: fenced blocks (always `.hljs`) match neither rule and never get `overflow: auto`, while indented blocks (no `.hljs`) do. Boundary: don't touch `body.wordWrap pre { white-space: pre-wrap }`, the copy-button styling, or the `pre` background/border theming rules — only the overflow selector logic needs to change.

## Evidence

- **class always added:** extensions/markdown-language-features/src/markdownEngine.ts `#addFencedRenderer` (~lines 263-276) does `token.attrJoin('class', 'hljs')` for any fenced block with `token.map?.length`, independent of whether a language was recognized or highlighted.
- **dead CSS selector:** extensions/markdown-language-features/media/markdown.css lines 414-419: `pre:not(.hljs) { overflow: auto }` and `pre.hljs code > div { overflow: auto }`. Since real fenced blocks always carry `.hljs`, they never match the first selector; a search of preview-src and markdownEngine.ts shows nothing ever wraps `<code>` content in a child `<div>`, so the second selector never matches either — `overflow: auto` is effectively dead code for fenced blocks.
- **reporter follow-up:** Robin-w151's second comment (https://github.com/microsoft/vscode/issues/339899#issuecomment, 2026-10-06) clarifies the cut-off only happens when the text is in a fenced/triple-backtick code block, consistent with the `.hljs`-class gap.
