# Issue #339899 — Long lines in code blocks are cut off

[https://github.com/microsoft/vscode/issues/339899](https://github.com/microsoft/vscode/issues/339899)

## Summary

Traced in source: fenced code blocks in the Markdown preview always get the `hljs` class added (markdownEngine.ts `#addFencedRenderer`), but the CSS rule that grants horizontal scrolling (`overflow: auto`) only targets `pre:not(.hljs)` — so ordinary fenced code blocks lose scroll/overflow handling and long lines get clipped with no way to reach the rest of the text.

## Change summary

Long lines inside a fenced Markdown code block are clipped in the preview and cannot be scrolled to.

## Best solution

Extend the overflow/scroll CSS rule in markdown.css to also cover `pre.hljs` (not just `pre:not(.hljs)` and the narrow `pre.hljs code > div` case), so any fenced code block with a long line gets a horizontal scrollbar.

## Plan brief

- **Likely files:** `extensions/markdown-language-features/media/markdown.css`
- **Validation:** Open a Markdown file with a fenced code block containing a line longer than the preview width, open the Markdown Preview, and confirm a horizontal scrollbar appears on the code block and all text (including the previously clipped portion) is reachable by scrolling; repeat for a code block with a recognized language (hljs-highlighted) and one without.
- **Behavior:**

  > A fenced Markdown code block containing a line too long to fit the preview's width should show a horizontal scrollbar on the code block (or otherwise allow the full line to be scrolled into view), for both plain and syntax-highlighted fenced blocks. Non-fenced (indented) code blocks and non-code content are unaffected. Acceptance: manually verified per the validation steps above in the Markdown preview webview.
- **Trace:**

  > `#addFencedRenderer` in extensions/markdown-language-features/src/markdownEngine.ts always adds the `hljs` class to a fenced block's `<pre>` when the token has a source map. The overflow-handling CSS rule in extensions/markdown-language-features/media/markdown.css (around lines 414-419) is `pre:not(.hljs), pre.hljs code > div { ...; overflow: auto; }`, so it never grants `overflow: auto` to the `<pre>` of a normal fenced block, only to a `<div>` nested in `<code>` that highlight.js rarely produces. The fix should extend this rule (or the surrounding selectors) to cover `pre.hljs` directly; do not change the `#addFencedRenderer`/hljs-class logic itself, the `body.wordWrap pre` word-wrap behavior, or indented-code-block styling (`pre:not(.hljs)` already works for those).

## Evidence

- **class always added:** extensions/markdown-language-features/src/markdownEngine.ts, `#addFencedRenderer` (~line 263-277): every fenced token with `token.map?.length` gets `token.attrJoin('class', 'hljs')`, regardless of whether a language was recognized.
- **overflow rule excludes hljs:** extensions/markdown-language-features/media/markdown.css lines 414-419: `pre:not(.hljs), pre.hljs code > div { ... overflow: auto; }` — the first selector never matches a fenced block (since it always has `.hljs`), and the second only matches if highlight.js wraps the highlighted output in a `<div>`, which it normally does not for plain/simple highlighted text.
- **repro matches:** Reporter's plain long line inside a fenced block (no special highlighting wrapper) falls into the gap: no `pre` in the chain gets `overflow: auto`, so the line is clipped with nothing to scroll.
