# Issue #144513 — Remote extension fails to activate in web worker extension host 

[https://github.com/microsoft/vscode/issues/144513](https://github.com/microsoft/vscode/issues/144513)

## Summary

Partially fixed by commit 448ada023 (CORS headers on VS Code's own server), but verification failed — the root cause in third-party embedders (Codespaces, Gitpod) where the service worker doesn't intercept cross-origin requests remains unaddressed. The issue is still valid and appropriately on the backlog.

## Change summary

Remote extensions fail to activate in the web worker extension host due to CORS errors when running in embedders like Codespaces or Gitpod.

## Best solution

Implement the approach alexdima described in comment 6: route extension-fetching requests through the main thread (via the existing `$asBrowserUri` / proxy pattern) specifically for embedder scenarios where the service worker on the main origin cannot intercept cross-origin fetches from the web worker extension host. The fix likely touches `src/vs/workbench/api/worker/extHostExtensionService.ts` and possibly the service worker registration in the server layer.
