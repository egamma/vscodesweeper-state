# Issue #330136 — GitHub Copilot: Allow switching between GitHub and GitHub Enterprise accounts without manually changing authProvider

[https://github.com/microsoft/vscode/issues/330136](https://github.com/microsoft/vscode/issues/330136)

## Summary

Keep open as a feature request: account preferences remain provider-specific and do not select Copilot's active authentication provider. Existing setup and configuration handling partially support provider changes, but do not establish the requested switch-between-authenticated-accounts experience.

## Change summary

Provide a UI or command to switch Copilot between authenticated GitHub.com and GitHub Enterprise accounts within the same profile and workspace.

## Best solution

Offer an explicit Copilot account/provider selection that updates the active provider and account together, without requiring manual settings edits or a window reload. Preserve separate account preferences for each provider and leave Settings Sync account selection independent.

## Evidence

- **Existing account-preference command does not switch the active provider:** src/vs/workbench/contrib/authentication/browser/actions/manageAccountPreferencesForExtensionAction.ts registers `_manageAccountPreferencesForExtension`. Its run method can offer providers previously used by an extension, then lists accounts within the chosen provider. Its _accept method calls provider(providerId).extension(extensionId).setPreferredAccount(account); it does not change Copilot's authProvider configuration.
- **Copilot still selects its provider through configuration:** extensions/copilot/src/platform/authentication/common/authentication.ts:376–382 selects github versus github-enterprise from ConfigKey.Shared.AuthProvider. src/vs/workbench/services/accounts/browser/defaultAccount.ts:1586–1596 independently selects the default-account provider from the corresponding authProvider setting.
- **Partial current capability:** extensions/copilot/src/platform/authentication/vscode-node/authenticationService.ts:34–43 observes provider configuration changes, clears cached sessions and tokens, and refreshes authentication. src/vs/workbench/contrib/chat/browser/chatSetup/chatSetupController.ts:305–363 changes the provider during setupWithProvider and forces sign-in. These paths are partial support, not proof of a dedicated already-authenticated account switch; the reported reload requirement was not verified by execution.
