# Issue #304443 — copilot-cli sessions trigger save right on startup

[https://github.com/microsoft/vscode/issues/304443](https://github.com/microsoft/vscode/issues/304443)

## Summary

Still unfixed on main: the `_doAccept` path in `chatEditingModifiedDocumentEntry.ts` runs save participants (explicit save without `skipSaveParticipants`) when restoring a copilot-cli session via `loadRemoteSession`, causing unnecessary ESLint/TS work at startup. The `important` label also bars any close.

## Change summary

Restoring a stale copilot-cli session at startup triggers file saves with save participants on worktree files, causing visible ESLint progress notifications and unnecessary extension work.

## Best solution

When `loadRemoteSession` replays and re-accepts file changes during session restore, the accept path in `chatEditingModifiedDocumentEntry.ts` should skip save participants (pass `skipSaveParticipants: true`) — the same guard already used in the auto-save and discard paths. The fix is localized to the restore flow in `_doAccept` or the caller that drives it during restore.
