# Issue #304443 — copilot-cli sessions trigger save right on startup

[https://github.com/microsoft/vscode/issues/304443](https://github.com/microsoft/vscode/issues/304443)

## Summary

Keeping open — the issue carries `important` and the bug is still present on main. The `_doAccept` path unconditionally triggers an explicit save with save participants during copilot-cli session restore, which is the reported problem.

## Change summary

Restoring a stale copilot-cli session at startup triggers file saves and save participants (e.g. ESLint) for every file in the session's worktree.

## Best solution

Guard the `_doAccept` save path in `chatEditingModifiedDocumentEntry.ts` (line 274) to skip save-participant invocation when the accept is happening during session restore rather than interactive use. The `loadRemoteSession` call chain in `chatServiceImpl.ts` should propagate a flag indicating restore context, so that file accepts during restore do not trigger `SaveReason.EXPLICIT` saves.
