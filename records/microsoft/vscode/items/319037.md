# Issue #319037 — Custom Endpoint Models (Messages API) Never Send `thinking` Parameter

[https://github.com/microsoft/vscode/issues/319037](https://github.com/microsoft/vscode/issues/319037)

## Summary

Confirmed on current main: the `copilotLanguageModelWrapper` in `languageModelAccess.ts` (line 774) builds `modelCapabilities` with only `reasoningEffort` — it never passes `enableThinking`, so the Messages API body builder in `messagesApi.ts` (line 156) skips the entire thinking-config block for custom endpoint models. The BYOK Anthropic provider has its own path that handles thinking correctly, but the custom endpoint / Messages API path does not.

## Change summary

Custom endpoint models configured with `apiType: "messages"` never send the `thinking` parameter in the request body because `enableThinking` is not passed through `modelCapabilities`.

## Best solution

In `copilotLanguageModelWrapper` (`extensions/copilot/src/extension/conversation/vscode-node/languageModelAccess.ts`), add `enableThinking` to the `modelCapabilities` object, derived from the endpoint's thinking support flags. Additionally, ensure `messagesApi.ts` has a fallback when `supportsAdaptiveThinking` is false and no explicit budget is configured (the reporter's analysis of Issue 2 — the missing else clause). Related issue https://github.com/microsoft/vscode/issues/319794 covers a similar gap for extension-contributed providers and may share part of the fix.
