# Issue #23099 — Add dropdown for search input history

[https://github.com/microsoft/vscode/issues/23099](https://github.com/microsoft/vscode/issues/23099)

## Summary

Keep open: current Find and Search inputs support stepping through history, but not the requested visible history dropdown. The existing keyboard shortcuts and placeholder hints do not address seeing several previous searches before choosing one; 59 upvotes support retaining this accepted Backlog request.

## Change summary

Provide a discoverable dropdown of previous search values that users can browse and select in Find and Search inputs.

## Best solution

Provide a consistent, keyboard- and mouse-accessible history picker for Find and Search fields, reusing existing history storage and navigation behavior. Settle whether browsing the picker previews searches or changes the query only after selection, particularly to avoid moving the editor cursor through unwanted intermediate searches.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/inputbox/inputBox.ts`, `src/vs/platform/history/browser/contextScopedHistoryWidget.ts`, `src/vs/editor/contrib/find/browser/findWidget.ts`, `src/vs/workbench/contrib/search/browser/searchWidget.ts`, `src/vs/workbench/contrib/search/browser/patternInputWidget.ts`
- **Validation:** Record three distinct queries in editor Find and workspace Search, then open the proposed history picker and verify multiple entries are visible and selectable with keyboard and mouse. Check that browsing and cancellation follow the agreed preview/commit behavior, selecting an entry restores the exact query, existing arrow-key history still works, and include/exclude inputs behave consistently if included in the agreed scope.
- **Behavior:**

  > Users can view multiple recent search values together and choose one without repeatedly stepping through intermediate queries. The interaction must be discoverable and usable with keyboard, mouse, and assistive technology in editor Find and workspace Search. Existing history contents, persistence settings, and keyboard navigation remain available. Acceptance includes exact restoration of previous expressions and predictable cancellation without unintended query or cursor changes.
- **Trace:**

  > HistoryInputBox in src/vs/base/browser/ui/inputbox/inputBox.ts already exposes stored values through getHistory() and implements single-entry navigation, but does not render a history picker. The history.showPrevious and history.showNext commands in src/vs/platform/history/browser/contextScopedHistoryWidget.ts invoke that navigation directly. FindWidget, SearchWidget, and PatternInputWidget supply the relevant histories and hints; the shared input is also used outside search, so those other consumers must not acquire unintended behavior. https://github.com/microsoft/vscode/pull/129324 addressed hint discoverability only. The discussion at https://github.com/microsoft/vscode/issues/23099 establishes why sequential query changes are not equivalent to browsing a list. Preserve existing history storage and persistence contracts; uncertainty starts at whether highlighting a picker entry should execute a preview or wait for explicit commitment.
- **Open decisions:**
  - Does highlighting a history entry preview its search immediately, or leave the active query and editor cursor unchanged until the user explicitly selects it?
