# Issue #123352 — API to represent dead / inactive code

[https://github.com/microsoft/vscode/issues/123352](https://github.com/microsoft/vscode/issues/123352)

## Summary

Keep open for the dedicated inactive-region API supported by maintainers. Existing diagnostics and decorations provide fading and whole-line styling, but do not supply the shared region contract discussed here; no older open canonical or concrete completing fix was identified.

## Change summary

Provide an API for language extensions to represent dead or inactive code regions independently of semantic token classification.

## Best solution

Define a dedicated inactive-region contract outside semantic tokens, preserving independent syntax and semantic highlighting. Settle whether its initial scope is presentation alone or also exposes regions for folding, using existing diagnostics and decorations as interim mechanisms.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/services/markerDecorationsService.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/common/core/editorColorRegistry.ts`
- **Validation:** After agreeing the contract, use a test extension to publish inactive ranges for a complete #if-disabled branch and a partial-line unreachable statement. Verify the agreed presentation, continued independent semantic highlighting, range updates after edits, removal when the branch becomes active, and high-contrast behavior; add automated coverage for the chosen provider and rendering paths.
- **Behavior:**

  > Language extensions should be able to identify inactive preprocessor branches and unreachable code independently of semantic tokens. Whole-line inactive regions should support consistent presentation across the line, while partial-line regions must not mark unrelated active code inactive. Existing semantic highlighting must remain usable within these regions. Acceptance checks should cover changing activity after edits, removing stale regions, and the agreed behavior in high-contrast themes.
- **Trace:**

  > Current src/vscode-dts/vscode.d.ts exposes DiagnosticTag.Unnecessary for diagnostic-based fading and DecorationRenderOptions.isWholeLine for extension-controlled whole-line styling, but no dedicated inactive-region declaration was found in stable or proposed API files. MarkerDecorations._createDecorationOption in src/vs/editor/common/services/markerDecorationsService.ts maps unnecessary markers to inline fading; editor.showUnused and editorUnnecessaryCode theme colors govern that existing path. Maintainers explicitly chose a separate API rather than semantic-token modifiers in https://github.com/microsoft/vscode/issues/123352#issuecomment-856255318. The merged https://github.com/clangd/vscode-clangd/pull/193 demonstrates an extension-specific rendering workaround, not adoption of a shared region contract. Preserve current diagnostic behavior and independent semantic token classification. The uncertainty begins at the public contract and whether its initial consumers include folding as well as presentation; the full cross-layer implementation path has not been established.
- **Open decisions:**
  - Should the initial inactive-region API expose presentation only, or also make the regions available for folding?
  - What default presentation should dedicated inactive regions receive, and should existing unused-code visibility and theme controls govern them or remain diagnostic-specific?
