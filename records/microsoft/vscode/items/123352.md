# Issue #123352 — API to represent dead / inactive code

[https://github.com/microsoft/vscode/issues/123352](https://github.com/microsoft/vscode/issues/123352)

## Summary

A real API gap remains: current APIs can visually dim ranges but cannot semantically represent inactive regions for richer editor behavior. Keep this accepted Backlog request open for API design and classify it as under discussion.

## Change summary

Add an editor API for language providers to identify dead or inactive code regions independently of semantic tokens.

## Best solution

Design a dedicated inactive-region provider separate from semantic tokens and diagnostics, initially supporting fading while leaving room for whole-line styling, backgrounds, and folding behavior.

- **existing partial capability:** src/vscode-dts/vscode.d.ts defines DiagnosticTag.Unnecessary, which only marks diagnostic ranges for fading; src/vs/editor/common/services/markerDecorationsService.ts applies the corresponding inline decoration.
- **remaining gap:** Current main contains no dedicated or proposed inactive/dead-code region API. TextEditorDecorationType supports isWholeLine, but decorations do not convey inactive-code semantics or enable editor-owned folding and presentation choices.
- **prior API:** https://github.com/microsoft/vscode/issues/51104 delivered DiagnosticTag.Unnecessary for unused-code fading, but the present request explicitly covers broader inactive regions and editor behaviors.
