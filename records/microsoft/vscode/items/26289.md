# Issue #26289 — [json] use the schemastore catalog

[https://github.com/microsoft/vscode/issues/26289](https://github.com/microsoft/vscode/issues/26289)

## Summary

This remains a well-supported feature gap: current main does not consume the SchemaStore catalog, and the latest implementation PR was closed unmerged. Keep the accepted Backlog request open while maintainers settle the catalog, trust, refresh, and opt-out policies.

## Change summary

Automatically use SchemaStore catalog associations for JSON files that lack a user- or extension-provided schema association.

## Best solution

Provide SchemaStore associations as a fallback behind clear trust and opt-out behavior, preserving explicit user settings and extension contributions as higher-priority sources. A maintainer-led plan should first settle the catalog configurability, exclusion, and refresh contracts.

## Plan brief

- **Likely files:** `extensions/json-language-features/client/src/jsonClient.ts`, `extensions/json-language-features/client/src/test/schemaRequests.test.ts`, `extensions/json-language-features/package.json`, `extensions/json-language-features/package.nls.json`
- **Validation:** Extend the JSON extension tests to cover catalog matching, explicit user/extension precedence, trust handling, refresh behavior, and the selected opt-out contract; compile the extension and run its `Launch Tests` configuration (or `npm run test-extension -- --extensionDevelopmentPath=extensions/json-language-features --extensionTestsPath=extensions/json-language-features/client/out/test`).
- **Behavior:**

  > When a JSON document has no explicit user-selected, `json.schemas`, or extension-contributed association, VS Code can obtain a matching schema from the approved SchemaStore catalog and use it for validation, completion, and hover information. Explicit user and extension associations always take precedence. Incorrect automatic associations can be disabled through the maintainer-selected opt-out contract, and network access obeys the selected trust and refresh policies. Acceptance tests must verify a matching catalog entry, precedence over fallback associations, disabling an unwanted association, and catalog refresh behavior.
- **Trace:**

  > In extensions/json-language-features/client/src/jsonClient.ts, `computeSchemaAssociations` currently combines only `getSchemaExtensionAssociations` and `getSchemaRegistryAssociations`, then sends the result through `json/schemaAssociations`. extensions/json-language-features/server/src/jsonServer.ts adds those associations to the JSON language service configuration alongside explicit `json.schemas`; the precedence requirement must be verified because overlapping matches may otherwise combine. Existing request trust, download gating, caching, and cache clearing live in the JSON client and are exercised by extensions/json-language-features/client/src/test/schemaRequests.test.ts. The closed implementation attempt https://github.com/microsoft/vscode/pull/327628 touched only the client and extension configuration, but its design was not accepted. Preserve existing explicit schema behavior, extension contribution behavior, workspace trust, and schema-download controls; uncertainty starts at the user-visible catalog configuration, exclusion, trust, and refresh contracts.
- **Open decisions:**
  - Should VS Code always use the official https://www.schemastore.org/api/json/catalog.json endpoint, or expose a setting that permits another catalog URL?
  - Should users disable SchemaStore globally, exclude individual catalog entries, exclude file patterns, or have both global and granular controls?
  - Is the official catalog and its SchemaStore-hosted schemas trusted by default, while external schema references continue through the existing trusted-domain flow, or should first use require confirmation?
  - What refresh and cache lifetime should apply to the catalog and referenced schemas, and which user action forces an immediate refresh?
