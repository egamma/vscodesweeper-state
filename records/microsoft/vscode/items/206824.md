# Issue #206824 — Git - git doesn't find anymore the config from my home which is on a remote server

[https://github.com/microsoft/vscode/issues/206824](https://github.com/microsoft/vscode/issues/206824)

## Summary

Keep open: two independent commenters confirm that Git operations in the GUI miss network-home configuration while terminal operations succeed. Current source does not establish a fix; the next step is to diagnose the Windows process-environment difference.

## Change summary

Git GUI operations fail to locate global configuration and SSH keys in a Windows domain user's network home.

## Best solution

Make built-in Git operations respect the user's effective Git home configuration without requiring copies under USERPROFILE. First establish whether the divergence originates in the extension-host environment, shell initialization, or Git for Windows home resolution; resolving only the askpass error would not address the missing commit identity.

## Plan brief

- **Likely files:** `extensions/git/src/git.ts`, `extensions/git/src/main.ts`, `extensions/git/src/terminal.ts`, `extensions/git/src/askpass.ts`
- **Validation:** On a Windows domain account with a mapped network home, keep .gitconfig and .ssh only there and use the same Git executable for GUI and terminal operations. Compare effective home variables and `git config --global --show-origin --list`, then verify GUI commit obtains the configured identity and explicit GUI fetch authenticates successfully without copying files to USERPROFILE. Repeat with a normal local-home account to check unchanged behavior.
- **Behavior:**

  > Windows users whose Git configuration and SSH keys reside in their domain network home should be able to commit and fetch through VS Code's built-in Git UI without copying those files into the local user profile. The reported discrepancy is that terminal Git succeeds while GUI Git reports missing identity or authentication failure. Acceptance must cover both commit identity and SSH fetch, using the same Git executable, and preserve normal local-home behavior. First confirm the scenario on a current Windows build.
- **Trace:**

  > Git.spawn in extensions/git/src/git.ts inherits process.env and adds Git-specific overrides before invoking cp.spawn. extensions/git/src/main.ts supplies askpass, Git editor, and IPC environment providers; extensions/git/src/terminal.ts configures terminal authentication separately, so terminal success does not establish identical child environments. The reporter and two independent commenters confirm network-home versus local-profile behavior at https://github.com/microsoft/vscode/issues/206824. The source trace stops at the inherited extension-host environment: it does not establish whether shell initialization, Windows launch environment, or Git for Windows home resolution introduces the discrepancy. The askpass exception is secondary to investigate, not proof of the home-selection cause; the missing commit identity must remain part of acceptance. Preserve explicitly configured home behavior and avoid broad changes to unrelated terminal or authentication semantics.
