# Issue #219898 — Allowing resolving ChatResponseAnchorPart async

[https://github.com/microsoft/vscode/issues/219898](https://github.com/microsoft/vscode/issues/219898)

## Summary

The requested async resolve capability for ChatResponseAnchorPart has been implemented. The proposed `chatParticipantAdditions` API now includes a `resolve?(token: CancellationToken): Thenable<void>` method on the anchor part, and the full resolve pipeline (ext host → main thread → chat model update) is wired up.

## Change summary

Allow ChatResponseAnchorPart to be resolved asynchronously so extensions can fill in symbol link details after the initial chat response stream.

## Best solution

Keep the shipped implementation. The `resolve` method on `ChatResponseAnchorPart` in the proposed `chatParticipantAdditions` API delivers the exact flow described in the issue (create anchor → kick off async validation → update the anchor with resolved URI/title). No further change needed beyond eventual API finalization.
