# Issue #334576 — Plan - Start Plan With Autopilot doesn't go into agent mode reliably

[https://github.com/microsoft/vscode/issues/334576](https://github.com/microsoft/vscode/issues/334576)

## Summary

Multiple independent reporters (across 1.136–1.138) confirm that after Plan Mode + Autopilot finishes planning, the UI shows Agent mode but the agent stays stuck and doesn't proceed to implementation until the user manually toggles modes — a real, recurring reliability bug, but the root cause (model-dependent, seen mostly with GPT models, rare with Claude) isn't traceable to a single fix point in this checkout.

## Change summary

Clicking "Start Plan with Autopilot" intermittently leaves the agent stuck showing Agent mode in the UI without actually resuming/implementing, requiring a manual mode toggle to unstick it.

## Best solution

Needs an owner from the chat/agent-mode team to trace why the post-plan-review transition into implementation (see confirmAutopilot() in chatPlanReviewPart.ts and the agent host mode-switch path) doesn't reliably fire depending on the underlying model's response shape.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatPlanReviewPart.ts`, `src/vs/platform/agentHost/node/copilot/copilotAgent.ts`, `src/vs/platform/agentHost/node/codex/codexAgent.ts`
- **Validation:** A repro that reliably shows the stuck state with a given model, then a mode-switch test confirming the UI's displayed mode matches the agent's actual running mode after autopilot planning completes.
- **Behavior:**

  > After a user starts Plan Mode with Autopilot enabled and planning finishes, the agent should reliably transition into Agent mode and begin implementation. Instead, some model backends leave the agent effectively idle/stuck in a plan-like state while the mode indicator still shows Agent mode; toggling to Plan and back to Agent by hand unsticks it. Acceptance: with an affected model, the agent resumes implementation automatically after plan approval without manual mode toggling.
- **Trace:**

  > confirmAutopilot() in chatPlanReviewPart.ts (line 955) is the UI-side trigger for the autopilot handoff; the actual resume/implementation kickoff happens through the agent host session (copilotAgent.ts / codexAgent.ts) which reacts to the model's response. Reporters note the stall correlates with specific models (GPT 5.6/6 family) versus Claude, suggesting the model's response format or a missing tool-call/signal isn't reliably driving the mode transition on the agent-host side. No related fix commit was found via git log on these files. The open question is where exactly the transition depends on model output shape — that diagnosis needs to happen before any bounded change can be scoped.
