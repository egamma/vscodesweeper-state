# Issue #334673 — workspace.createFileSystemWatcher(RelativePattern) prevents renaming the watched directory's parent on Windows

[https://github.com/microsoft/vscode/issues/334673](https://github.com/microsoft/vscode/issues/334673)

## Summary

Fresh, team-authored, clearly-described Windows-specific bug (0 days old, still triage-needed) — a RelativePattern file watcher rooted in a nested subdirectory appears to hold a handle that blocks renaming an ancestor directory. No fix exists yet; route to the files/watcher area rather than close.

## Change summary

On Windows, creating a `vscode.workspace.createFileSystemWatcher` with a `RelativePattern` rooted at a nested directory (e.g. `a/b/c`) prevents renaming an ancestor directory (`a/b`) while the watcher is active.

## Best solution

Investigate whether VS Code's native file watcher (`@parcel/watcher`, using `ReadDirectoryChangesW` on Windows) opens directory handles without `FILE_SHARE_DELETE`/rename-friendly sharing flags when watching a `RelativePattern` rooted below the workspace root; fix may need to land upstream in `@parcel/watcher` or in how VS Code configures/recycles watcher handles in `src/vs/platform/files`.
