# Issue #334673 — workspace.createFileSystemWatcher(RelativePattern) prevents renaming the watched directory's parent on Windows

[https://github.com/microsoft/vscode/issues/334673](https://github.com/microsoft/vscode/issues/334673)

## Summary

Team-authored, well-diagnosed report (also team-protected from judgment closes) — root cause is Windows-native handle-locking behavior in the @parcel/watcher dependency's Windows backend, not core VS Code code, so this stays open and tracked as upstream.

## Change summary

On Windows, creating a RelativePattern file-system watcher rooted in a nested directory prevents renaming that directory's parent folder until the watcher is disposed.

## Best solution

Track/report upstream against parcel-bundler/watcher (the Windows ReadDirectoryChangesW backend used by src/vs/platform/files/node/watcher/parcel/parcelWatcher.ts) for opening watched-directory handles with FILE_SHARE_DELETE or equivalent so ancestor renames aren't blocked; VS Code can bump the dependency once fixed upstream.
