# Issue #334673 — workspace.createFileSystemWatcher(RelativePattern) prevents renaming the watched directory's parent on Windows

[https://github.com/microsoft/vscode/issues/334673](https://github.com/microsoft/vscode/issues/334673)

## Summary

Well-documented, team-authored bug report (author is a VS Code MEMBER) with a precise minimal reproduction (a linked sample extension) showing that watching a nested RelativePattern directory via the file-system watcher API blocks renaming an ancestor directory on Windows while the watcher is alive. Team-authored issues get factual, not judgment, closes, and there's no cited fix commit referencing this issue, so this stays open.

## Change summary

On Windows, creating a vscode.workspace.createFileSystemWatcher() with a RelativePattern rooted in a nested subdirectory prevents renaming that directory's parent while the watcher is active.

## Best solution

Trace how the recursive watcher backend (src/vs/platform/files/node/watcher/parcel/parcelWatcher.ts, which wraps the native @parcel/watcher module) opens directory handles on Windows for a RelativePattern rooted below the workspace root, and determine whether the handle/flags used (e.g. lack of FILE_SHARE_DELETE-equivalent semantics or backend choice) can be changed to avoid locking ancestor directories — this likely needs a Windows repro plus possibly an upstream fix in @parcel/watcher.
