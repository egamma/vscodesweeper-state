# Issue #172722 — Git - provide action `push --set-upstream` when remote ref is delete

[https://github.com/microsoft/vscode/issues/172722](https://github.com/microsoft/vscode/issues/172722)

## Summary

Keep open: Sync Changes still lacks the requested recovery action when its upstream branch has been deleted. Git: Publish Branch provides a separate workaround, but does not cover recovery from the sync error.

## Change summary

Offer an explicit push-and-set-upstream action when Sync Changes fails because the configured remote branch no longer exists.

## Best solution

Provide an opt-in recovery action in the Git sync error flow that publishes the current branch and establishes its upstream without force-pushing. Settle the destination policy for multi-remote workflows before implementation.

## Plan brief

- **Likely files:** `extensions/git/src/commands.ts`, `extensions/git/src/git.ts`, `extensions/git/src/repository.ts`
- **Validation:** In a disposable test repository outside this read-only checkout, publish a topic branch to a bare origin, delete that branch directly on origin while retaining local upstream configuration, add a local commit, and invoke Sync Changes. Verify an explicit recovery action is offered; accepting it recreates the current branch remotely and establishes upstream, while dismissing it performs no push. Also check ordinary sync, authentication failures, and the chosen multi-remote policy.
- **Behavior:**

  > When a published topic branch is deleted remotely and the user subsequently invokes Sync Changes with additional local work, the failure should offer an explicit way to publish the current branch and establish its upstream. Recovery must require user consent and must not force-push. Dismissing the action must leave the remote unchanged. Ordinary sync and unrelated failures must retain their existing behavior; multi-remote destination semantics require agreement.
- **Trace:**

  > CommandCenter._sync and sync in extensions/git/src/commands.ts send branches with existing upstream configuration to Repository._sync in extensions/git/src/repository.ts. That path pulls the upstream before pushing, so a missing remote ref aborts sync. getGitErrorCode in extensions/git/src/git.ts uses a case-sensitive uppercase expression that misses the lowercase error identified at https://github.com/microsoft/vscode/issues/172722#issuecomment-6040020620, and the command error handler has no recovery action even for NoRemoteReference. CommandCenter.publish already provides separate push-and-set-upstream behavior and selects a remote when several exist. Keep automatic sync, ordinary pull failures, read-only remote handling, and force-push semantics unchanged. Missing-ref errors can also arise from configuration mismatches, as documented in https://github.com/microsoft/vscode/issues/70136, so they should not silently trigger branch recreation. The unresolved product boundary is destination selection when the pull upstream and intended push remote differ.
- **Open decisions:**
  - In multi-remote or triangular workflows, should recovery publish to the failed pull's upstream remote or the configured push remote, and when should the user be asked to choose?
