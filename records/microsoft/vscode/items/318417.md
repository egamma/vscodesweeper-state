# Issue #318417 — BYOK UI: Last model should not be selected after removing BYOK models

[https://github.com/microsoft/vscode/issues/318417](https://github.com/microsoft/vscode/issues/318417)

## Summary

Keep open: the removal-and-reload steps suffice to retest the stale selected-model label. Current main has shared selection reconciliation, vendor-cache eviction, and newer picker availability states, but the inspection does not establish that this exact mismatch is fixed.

## Change summary

After removing BYOK models and reloading, the chat input should not display the removed model while the picker offers a different selection.

## Best solution

Make the chat input's displayed selection agree with the usable catalog after BYOK removal and reload, including when no replacement model exists. First reproduce against the current picker and distinguish conclusively removed models from providers still loading.
