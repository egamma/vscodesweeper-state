## Summary

The behavior is intentional and explicitly documented in-code: the function only escapes backticks by design, and the Markdown output is fully sanitized after rendering by the downstream MarkdownRenderer. The reporter themselves notes the existing `known-accepted` CodeQL suppression.

## Change summary

escapeMarkdownSyntaxTokensForCode() only escapes backticks, leaving other Markdown syntax characters unescaped in JSDoc hover text.

## Best solution

Keep shipped behavior — the function intentionally escapes only backticks (for code span formatting), and downstream Markdown rendering sanitizes the output before display. No code execution is possible; visual formatting from JSDoc is within acceptable design boundaries.
