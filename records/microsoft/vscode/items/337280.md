# Issue #337280 — Agent Host: Branch Changes reports files changed but opens empty “No files changed” editor

[https://github.com/microsoft/vscode/issues/337280](https://github.com/microsoft/vscode/issues/337280)

## Summary

Thanks for the detailed report — this looks like a real inconsistency between the changed-files count/summary and the multi-file Branch Changes editor, but I couldn't confirm the exact defect from source alone (it likely involves a race between two separate change-computation paths), so I'd like to see it confirmed as reproducible before triaging further.

## Change summary

The Branch Changes button reports a nonzero file count, but opening it shows an empty multi-file diff editor, while individual file diffs and the Source Control view show the changes correctly.

## Best solution

Reconcile the two independent change-computation paths involved here: the chat input pill's own changeset subscription (src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts, `changesetFiles`/`changes`) versus the Agents window's `ChangesMultiDiffSourceResolver` (src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts), which separately gates its resolved resources on `activeSessionResourceObs` matching the session and can fall back to an empty/stale cached list during a transient mismatch. A maintainer session should reproduce this live (ideally in a remote/VS Code Server setup) to pin down which of the two paths is actually involved before changing code.

## Evidence

- **split implementations:** The 'Branch Changes' pill in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionInputPills.ts computes `changes`/`changeStats` from its own changeset-file subscription and opens a multi-diff editor via `openChatFileChanges` with an explicit `resources` array (editorChatResponseFileChangesService.ts), while the Agents window's Changes tab (src/vs/sessions/contrib/changes/browser/sessionChangesEditorInput.ts) instead relies purely on a `multiDiffSource` resolved asynchronously via `ChangesMultiDiffSourceResolver`.
- **candidate race:** ChangesMultiDiffSourceResolver.resolveDiffSource (src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts) falls back to an empty/stale cached list whenever `activeSessionLoadingObs` is true or `activeSessionResourceObs` doesn't (yet) match the target session — a plausible source of a transiently empty multi-diff editor that wouldn't affect the pill's own count, which is computed independently.
- **possibly related report:** https://github.com/microsoft/vscode/issues/265170 ('Chat remote session diff editor opens empty') reports a similar remote-session empty-diff symptom, but it's over a year old, tagged for the separate 'chat-cloud-agent' feature, and not clearly the same code path, so I'm not treating it as a verified duplicate.
