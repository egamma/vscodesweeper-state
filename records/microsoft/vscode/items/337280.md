# Issue #337280 — Agent Host: Branch Changes reports files changed but opens empty “No files changed” editor

[https://github.com/microsoft/vscode/issues/337280](https://github.com/microsoft/vscode/issues/337280)

## Summary

Well-diagnosed report with a plausible source-level explanation: the Branch Changes pill count and the multi-diff editor's changeset are computed from two independent code paths that can disagree, matching exactly what the reporter observed. Keeping open pending confirmation of why the two paths diverge in this remote-workspace scenario.

## Change summary

The Branch Changes button reports a nonzero file count, but opening it shows an empty 'No Changed Files' multi-diff editor, even though individual diffs and Source Control show the changes correctly.

## Best solution

Make the multi-diff resolver and the pill count derive the changed-files list from the same source (or otherwise guarantee they can never disagree) in src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts and src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts, after determining why activeSessionResourceObs fails to track the owning session in this case.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts`, `src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts`, `src/vs/sessions/contrib/changes/common/changesViewService.ts`
- **Validation:** A resolver/service test (alongside changesMultiDiffSourceResolver.test.ts) asserting the multi-diff editor's resolved changes match the pill's reported count for the same session, once the divergence is fixed.
- **Behavior:**

  > Opening the Branch Changes multi-diff editor for a session must always show the same set of changed files that the Branch Changes pill's count reflects — the two must never disagree. If the pill shows N changed files for a session, the editor must show exactly those N files (not an empty placeholder), regardless of workspace type (local or remote) or whether another session is currently focused elsewhere in the UI.
- **Trace:**

  > Two independent code paths compute 'changed files' for the same session: the pill count in computeSessionInputPillStats (src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts, ~line 256) reads chat.changesets directly, while the multi-diff editor's resolver (ChangesMultiDiffSourceResolver.resolveDiffSource, src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts, ~lines 78-92) requires changesViewService.activeSessionResourceObs to equal the session resource encoded in the editor's URI before it will surface changesViewService.activeSessionChangesObs; on mismatch it falls back to the last cached value (often empty), which the multi-diff widget renders as 'No Changed Files' (src/vs/editor/browser/widget/multiDiffEditor/multiDiffEditorWidgetImpl.ts:271). The equality gate exists deliberately to avoid showing a stale row from a different session mid-switch — do not simply delete it without understanding what stale-row scenario it protects against. What's still unknown: why activeSessionResourceObs would fail to equal the target session resource when the user is looking at that session's own Branch Changes button in a remote workspace — that needs to be reproduced/traced (e.g. authority/URI normalization differences between remote and local session resources, or a race in updating the 'active' session observable) before a safe fix can be designed.
- **Open decisions:**
  - Why does changesViewService.activeSessionResourceObs fail to match the session whose own Branch Changes button was clicked, specifically in remote workspaces — is it a URI/authority normalization mismatch, or a timing race in how 'active session' is tracked?
  - Should ChangesMultiDiffSourceResolver key its resolution off the session identity embedded in the multi-diff URI directly (removing the global 'active session' dependency), and if so what replaces the stale-row protection that dependency currently provides?

## Evidence

- **divergent count source:** computeSessionInputPillStats in src/vs/sessions/contrib/chat/browser/sessionChatInputToolbar.ts (line ~256) computes the pill's file count via readChatChangesStats(chat, reader, getChangesPillChangesetId(workspace)), reading the chat model's own changesets directly.
- **gated resolver:** ChangesMultiDiffSourceResolver.resolveDiffSource in src/vs/sessions/contrib/changes/browser/changesMultiDiffSourceResolver.ts (lines ~78-92) only returns changesViewService.activeSessionChangesObs when activeSessionResourceObs strictly equals the session resource embedded in the editor's URI; otherwise it falls back to `lastValue ?? { changeset: undefined, changes: [] }`, which renders as the multiDiffEditorWidgetImpl.ts 'No Changed Files' placeholder (line 271) when items.length === 0.
