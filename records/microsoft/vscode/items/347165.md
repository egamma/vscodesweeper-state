# Issue #347165 — Should we open agents window instead of editor window?

[https://github.com/microsoft/vscode/issues/347165](https://github.com/microsoft/vscode/issues/347165)

## Summary

Keep open as a feature request about the destination of Copilot CLI handoff. Opening the editor window matches the documented test scenario, but that does not settle whether an Agents Window destination should also be offered.

## Change summary

Allow Copilot CLI session handoff to open the Agents Window instead of the editor window.

## Best solution

Have the handoff owners decide whether the Agents Window should be an explicit destination or the default. Preserve session continuity and existing editor-window handoff behavior unless a default change is intentionally approved.

## Evidence

- **Referenced scenario:** https://github.com/microsoft/vscode/issues/342466 explicitly tests /code-insiders opening the current CLI session in the Chat view of its folder's editor window. This supplies the scenario omitted from the short report.
- **Current handoff implementation:** src/vs/workbench/contrib/chat/browser/copilotCliSessionLink.ts: CopilotCliSessionLinkOpener.openInAgentHost imports the CLI session and calls chatWidgetService.openSession(resource, ChatViewPaneTarget); this path does not choose the Agents Window.
- **Existing capability is partial:** src/vs/workbench/contrib/chat/electron-browser/agentSessions/agentSessionsActions.ts provides Agents Window opening actions, and src/vs/workbench/contrib/chat/common/constants.ts defines workbench.action.openAgentsWindow. A workbench command is not evidence of a separate CLI slash command or direct CLI-session handoff to that window.
- **Original implementation scope:** https://github.com/microsoft/vscode/pull/342120 describes /code and /code-insiders handing sessions to the editor window's Chat view. That documented behavior does not implement the alternative destination requested here.
