# Issue #127521 — [linked editing] does not work right after enter

[https://github.com/microsoft/vscode/issues/127521](https://github.com/microsoft/vscode/issues/127521)

## Summary

The confirmed timing bug remains possible on current main: moving into an HTML tag and editing immediately can beat the debounced linked-range update, leaving the closing tag unchanged. No older issue with the same observable symptom or open fixing PR was found.

## Change summary

Linked editing fails to synchronize the closing HTML tag when the opening tag is edited immediately after pressing Enter and moving back to it.

## Best solution

Make linked editing establish or preserve the applicable ranges soon enough for the first edit after entering a tag, without restoring stale-range highlighting while the cursor is elsewhere. Cover the Enter, cursor-move, and immediate-edit sequence with a timing-sensitive editor unit test.

- **current source path:** src/vs/editor/contrib/linkedEditing/browser/linkedEditing.ts schedules cursor-driven range discovery through a Delayer in `triggerRangeUpdate`, while model edits synchronize only when `_currentDecorations` already contains a reference range.
