# Issue #339686 — Agent file edits are applied directly with no Keep/Undo review workflow

[https://github.com/microsoft/vscode/issues/339686](https://github.com/microsoft/vscode/issues/339686)

## Summary

Genuine product-direction feedback about Agent Host applying edits directly with no blocking review/approval step, echoing a cluster of recent complaints about the loss of the old per-hunk Keep/Undo workflow. There's a closely related open issue (#337279, assigned to a maintainer, labeled agent-host) that covers per-hunk review bookkeeping, but it explicitly disclaims being about pre-apply approval, which is part of what this reporter wants — so I'm not confident it fully absorbs this report's scope; keeping both open rather than forcing a duplicate close.

## Change summary

Reporter wants a blocking review step (approve/reject) for agent-made file edits instead of changes being applied directly to the working tree.

## Best solution

A maintainer should decide whether the Agent Host editing UX needs a restored/explicit per-change (or per-hunk) accept/undo review gate; if so, consolidate design discussion with https://github.com/microsoft/vscode/issues/337279 and https://github.com/microsoft/vscode/issues/315310, which track closely overlapping regressions in the same area.
