# Issue #221495 — Search editor shows the wrong results when running multiple

[https://github.com/microsoft/vscode/issues/221495](https://github.com/microsoft/vscode/issues/221495)

## Summary

Keep open: the reported steps suffice to retest, and current source still couples per-input search completion promises to a mutable, pane-owned search model. Search-model organization and lifecycle cleanup have changed since the report, but no verified fix or canonical duplicate was found.

## Change summary

Overlapping searches in separate Search Editor tabs can display the same results despite having different queries.

## Best solution

Ensure each Search Editor retains results belonging to its own query when searches overlap and tabs are switched. First reproduce the completion-order race, then establish a regression check around search-result ownership in the Search Editor lifecycle.

- **Validation:** In a large workspace containing distinct matches for queries A and B, set search.mode=newEditor, start A, then start B before A finishes. Switch between their tabs during and after completion and repeat with reversed query order. Each editor must retain its own query's matches, counts, and match ranges. Establish a deterministic browser regression check using controlled search completions before considering the fix complete.
- **Behavior:**

  > Two Search Editors with different queries must not acquire each other's results when searches overlap or the user switches tabs. Each editor's displayed matches, counts, and navigation ranges must correspond to its own query. Acceptance includes both completion orders and revisiting a tab whose search completed while it was inactive. Existing single-editor search and rerun behavior must remain unchanged.
- **Trace:**

  > SearchEditor in src/vs/workbench/contrib/searchEditor/browser/searchEditor.ts owns a single SearchModelImpl, while SearchEditorInput in src/vs/workbench/contrib/searchEditor/browser/searchEditorInput.ts retains an ongoingSearchOperation promise. doRunSearch captures the starting input, but onSearchComplete serializes the pane's current searchModel.searchResult; setInput can attach another completion handler when restoring an input with a retained operation. SearchModelImpl.search and cancelSearch in src/vs/workbench/contrib/search/browser/searchTreeModel/searchModel.ts mutate and cancel pane-owned search state, so cancellation and callback ordering need to be established before claiming the exact root cause. Preserve query options, result serialization, and ordinary rerun semantics; unrelated search-tree or UI redesign is outside this report.
