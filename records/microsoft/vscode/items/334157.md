# Issue #334157 — Cached skill not updated

[https://github.com/microsoft/vscode/issues/334157](https://github.com/microsoft/vscode/issues/334157)

## Summary

Team-authored bug (kept open regardless), and current source shows a real defect: the plugin nonce used to decide whether a `chat.pluginLocations` skill needs re-syncing is based only on the plugin root directory's mtime, which does not change when a file nested two levels down (e.g. `skills/<name>/SKILL.md`) is edited — exactly the scenario in the report.

## Change summary

A skill under a `chat.pluginLocations` folder keeps serving its old contents to new Agents-window sessions after being edited, with no way to force a refresh.

## Best solution

In `resolveCustomizationRefs` / `addPluginRef` (agentHostLocalCustomizations.ts), replace the single top-level `fileService.stat(plugin.uri).mtime` nonce with one derived from a recursive walk of the plugin directory (relative path + mtime + size per file, similar to what `SyncedCustomizationBundler`/`collectDirectoryFiles` already does for loose files), so edits to nested skill files change the nonce and `AgentPluginManager._syncPlugin` re-copies instead of treating it as a cache hit.

## Evidence

- **nonce source:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostLocalCustomizations.ts:250 computes `nonce = (await fileService.stat(plugin.uri)).mtime` — stat of the plugin *root* only, not its contents.
- **cache-hit gate:** src/vs/platform/agentHost/node/agentPluginManager.ts:142 (`_syncPlugin`) skips re-copying whenever `ref.nonce` matches a cached entry and the nonce-keyed directory already exists — so an unchanged root mtime means the sync is skipped even if nested files changed.
