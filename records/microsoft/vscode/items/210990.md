# Issue #210990 — API to provide a terminal for use with `run-in-terminal` request

[https://github.com/microsoft/vscode/issues/210990](https://github.com/microsoft/vscode/issues/210990)

## Summary

The requested debug-session terminal handoff remains absent from current source; existing terminal profiles and shell-initialization waits do not provide it. Keep this team-authored, On Deck request open for debug API owner consideration; no qualifying canonical or fixing commit was established.

## Change summary

Allow an extension to supply an activated integrated terminal for a debug session's DAP runInTerminal request before the debug command executes.

## Best solution

Have the debug API owners settle a debug-type-scoped terminal-provider contract that supports asynchronous activation and defines terminal reuse and ownership. Preserve existing integrated-terminal fallback and external-terminal behavior.

## Evidence

- **Current debug terminal path:** src/vs/workbench/api/node/extHostDebugService.ts:76–212 implements $runInTerminal by checking out a pooled terminal or calling createTerminalFromOptions, waiting for shell initialization, and executing prepareCommand's result through shellIntegration.executeCommand or sendText. There is no extension terminal-provider callback or awaitable extension activation handoff on this path.
- **Existing capability does not cover the request:** src/vscode-dts/vscode.d.ts:8223–8229 defines TerminalProfileProvider.provideTerminalProfile(token) for terminals launched through the UI or commands, without a debug-session argument. The debug registration APIs at lines 17364–17384 cover configuration providers, adapter factories, and trackers, not terminal providers. debug.terminal.clearBeforeReusing in src/vs/workbench/contrib/debug/browser/debug.contribution.ts controls clearing, not terminal selection or activation.
- **Full discussion establishes the missing ordering contract:** https://github.com/microsoft/vscode/issues/210990#issuecomment-2097260667 explains that environment-variable injection alone is insufficient: activation may run scripts, establish aliases, and select an interpreter dynamically per folder or file. The reported gap is ensuring activation finishes before the DAP client sends its launch command.
- **Maintainer API direction:** https://github.com/microsoft/vscode/issues/210990#issuecomment-2073652585 sketches registerDebugTerminalProvider(debugType, provider), explicitly limited to integrated terminals, while asking whether other extensions need it. This is an API design lead, not an implemented capability or a rejection.
- **Related activation workaround is not completion:** https://github.com/microsoft/vscode/issues/291736 is closed and concerns AI-agent terminals. https://github.com/microsoft/vscode/issues/291736#issuecomment-3823404785 recommends Python Environments shellStartup activation, but does not establish a debug-session-specific terminal handoff or completion of this API request.
