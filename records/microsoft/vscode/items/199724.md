# Issue #199724 — Trying to populate a `DiagnosticCollection` progressively results in excessive calls to CodeAction provider.

[https://github.com/microsoft/vscode/issues/199724](https://github.com/microsoft/vscode/issues/199724)

## Summary

A real API and performance gap remains on current main: diagnostic updates replace the resource's complete set and every marker-change event retriggers automatic code actions. This team-authored Backlog request should remain open.

## Change summary

Support progressive diagnostic updates without repeatedly requesting code actions for unchanged diagnostics.

## Best solution

Preserve code actions for unchanged diagnostics by diffing marker updates or carrying incremental diagnostic changes through the diagnostics pipeline; consider additive/removal operations on `DiagnosticCollection` if required.

## Evidence

- **extension-host implementation:** `src/vs/workbench/api/common/extHostDiagnostics.ts` replaces the stored resource array and sends the complete marker array through `$changeMany` for each update.
- **code-action refresh path:** `src/vs/editor/contrib/codeAction/browser/codeActionModel.ts` listens to every marker change affecting the current model and calls `_tryAutoTrigger`, without checking whether diagnostics at the cursor actually changed.
