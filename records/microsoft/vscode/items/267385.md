# Issue #267385 — Support pnpm's minimumReleaseAge configuration when suggesting npm version ranges.

[https://github.com/microsoft/vscode/issues/267385](https://github.com/microsoft/vscode/issues/267385)

## Summary

Keep this accepted, well-supported request open: package.json completions still use the latest package version without consulting pnpm's minimumReleaseAge. The existing settings do not cover the request, and the related pnpm catalog-hover issue tracks a different capability.

## Change summary

Make package.json dependency-version suggestions respect minimumReleaseAge configured in pnpm-workspace.yaml.

## Best solution

The built-in npm completion provider should suggest version ranges based on releases eligible under the applicable pnpm release-age configuration, while preserving existing behavior for projects without that configuration. Plan configuration discovery and version-metadata handling across the desktop and web lookup paths before implementation.
