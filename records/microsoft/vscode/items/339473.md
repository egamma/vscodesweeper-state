## Change summary

Request that VS Code Profiles maintain separate authentication/sign-in state per profile instead of sharing global authentication sessions.

## Best solution

Needs a maintainer/architecture decision: authentication sessions are currently stored globally (via secret storage) independent of profiles — see src/vs/workbench/services/authentication/browser/authenticationService.ts and common/authentication.ts, neither of which is profile-aware.
