# Issue #339473 — Allow VS Code Profiles to Maintain Separate Authentication States

[https://github.com/microsoft/vscode/issues/339473](https://github.com/microsoft/vscode/issues/339473)

## Summary

Keep open as a feature request: current account preferences do not provide independent authentication states per profile. The related account-preference request covers part of this proposal, but not its full sign-in/sign-out isolation requirement.

## Change summary

Allow profiles to retain separate authenticated accounts and automatically use their associated identities when switching profiles.

## Best solution

Decide whether profiles should offer optional authentication isolation, including provider sessions and sign-out behavior, while preserving shared accounts for users whose profiles represent languages rather than identities. Coordinate the account-preference portion with https://github.com/microsoft/vscode/issues/240700 without treating that narrower proposal as full coverage.

## Evidence

- **Existing capability and remaining gap:** The command _manageAccountPreferencesForExtension in src/vs/workbench/contrib/authentication/browser/actions/manageAccountPreferencesForExtensionAction.ts manages extension account preferences for the current workspace. In src/vs/workbench/services/authentication/browser/authenticationExtensionsService.ts:237–273, updateAccountPreference writes WORKSPACE and APPLICATION storage, and getAccountPreference reads the workspace value before the application fallback. This supports workspace-specific selection, not independently signed-in accounts per profile.
- **Shared secret storage:** src/vs/platform/secrets/common/secrets.ts stores secrets using APPLICATION or APPLICATION_SHARED scope rather than PROFILE scope. Profile-specific account preferences alone would not establish the independent authentication-state boundary requested here.
- **Verified related issue, not full-scope canonical:** https://github.com/microsoft/vscode/issues/240700 is open. Its discussion explicitly includes work/personal Copilot accounts, but the maintainer-endorsed direction is profile-specific extension account preferences: https://github.com/microsoft/vscode/issues/240700#issuecomment-2772959164 and https://github.com/microsoft/vscode/issues/240700#issuecomment-2782511063. That proposal does not establish isolated provider sessions or profile-local sign-out, so it does not fully absorb this request.
- **Product boundary already discussed:** https://github.com/microsoft/vscode/issues/240700#issuecomment-2659702091 explains why accounts and profiles are currently independent, including Settings Sync and language-oriented profiles. Later comments support improving profile account preferences rather than rejecting all changes; this history warrants a scope decision, not an as-designed close.
- **Additional canonical search:** A repository issue search for authentication and profiles also found https://github.com/microsoft/vscode/issues/317808, which requests matching browser profiles during authentication, and https://github.com/microsoft/vscode/issues/164558, which reports sign-in prompts for an extension absent from the active profile. Both were read and verified open; neither owns independent authentication states across profiles.
- **Request is not billing support:** https://github.com/microsoft/vscode/issues/339473 requests a product capability for work/personal identity separation. Purchasing another Copilot subscription is motivation, not a charge, refund, quota, or account-support complaint.
