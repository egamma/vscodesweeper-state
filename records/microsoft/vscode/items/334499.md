# Issue #334499 — Bundled Copilot CLI repeatedly opens a GitHub sign-in popup when CLI access is disabled by organization policy

[https://github.com/microsoft/vscode/issues/334499](https://github.com/microsoft/vscode/issues/334499)

## Summary

Fresh report with no maintainer response yet; source tracing confirms a real gap — the bundled Copilot CLI's model-fetch and MCP-server startup path has no check for org-level CLI entitlement/policy, matching the reported repeated sign-in popup and 403 for a business seat with CLI disabled.

## Change summary

When an org disables Copilot CLI via policy but Copilot Chat remains usable, VS Code's bundled Copilot CLI still starts its MCP server and attempts model fetch/auth, repeatedly showing a GitHub sign-in popup on every restart.

## Best solution

Gate CLI initialization (CopilotCLIModels._fetchAndCacheModels and CopilotCLIContrib._startMcpServer) on an entitlement/policy check for CLI access, not just hasCopilotTokenSource, so the feature stays dormant (no MCP server, no repeated auth prompt) when the org has disabled it — likely in extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCli.ts and .../vscode-node/contribution.ts.

## Evidence

- **unconditional MCP server start:** extensions/copilot/src/extension/chatSessions/copilotcli/vscode-node/contribution.ts CopilotCLIContrib always calls _startMcpServer() in its constructor with no entitlement/policy gate; registered unconditionally from chatSessions.ts (both registerCopilotCLIServices and V1).
- **user-tried settings don't help:** Reporter already disabled `github.copilot.chat.backgroundAgent.enabled` and `github.copilot.chat.cli.mcp.enabled`; neither setting is checked in the CopilotCLIContrib startup path (CLIMCPServerEnabled is only read in mcpHandler.ts, a separate in-process chat MCP handler, not the CLI's own server/model init).
- **logged symptom:** Reporter's log shows `[CopilotCLISession] Failed to fetch models: Error: 403 "unauthorized: not authorized to use this Copilot feature"`, consistent with the CLI attempting model fetch despite org policy disabling CLI.
