# Issue #325906 — Azure BYOM gpt-5.6-luna is capped at 256K context despite 1,050K Foundry context window

[https://github.com/microsoft/vscode/issues/325906](https://github.com/microsoft/vscode/issues/325906)

## Summary

The BYOK infrastructure supports arbitrary context windows via the `contextWindow` config property, and `resolveModelTokenLimits` has no hardcoded cap. The 256K limit likely comes from the remotely-fetched known models list (`copilotChat.json`), which is data external to this repo. The request is reasonable: either update the known-models data for gpt-5.6-luna or auto-detect the deployment's context window from the Azure API.

## Change summary

Azure BYOM deployment of gpt-5.6-luna displays 256K context cap instead of the deployment's actual 1,050K context window.

## Best solution

Two paths: (1) Update the known-models list at `https://main.vscode-cdn.net/extensions/copilotChat.json` to reflect gpt-5.6-luna's actual context window — this is a data change outside this repo. (2) For a more robust solution, have the Azure BYOK provider query the deployment's model capabilities from the Azure API to auto-discover context limits rather than relying on a static list. The user can also work around this now by explicitly setting `contextWindow` in their model configuration. Route to the BYOK / Copilot area for triage.
