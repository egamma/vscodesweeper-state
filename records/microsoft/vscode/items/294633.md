# Issue #294633 — Missing folder from Windows Explorer

[https://github.com/microsoft/vscode/issues/294633](https://github.com/microsoft/vscode/issues/294633)

## Summary

Keep open: current installer code includes a conditional repair for missing folder context menus, but its applicability to this report is unverified. The reported update, Windows version, missing folder registry entry, and working file action provide enough information to begin retesting.

## Change summary

An automatic update removes Windows Explorer folder-opening integration while single-file integration remains available.

## Best solution

Establish which installer and shell-registration path loses folder integration, then preserve previously enabled folder actions across automatic updates without changing unrelated installation preferences.

## Plan brief

- **Likely files:** `build/win32/code.iss`
- **Validation:** On Windows 11, enable file and folder integration, confirm both actions work, then perform a background update. Check folder, folder-background, and file actions afterward, recording installer logs and registry/AppX state; compare default modern menus with forced classic menus.
- **Behavior:**

  > Previously enabled Windows Explorer folder integration must remain usable after an automatic VS Code update. The reported failure leaves file integration working while the folder action disappears. Acceptance checks must exercise an actual background update on Windows 11 and verify both actions afterward. Installation preferences that intentionally omit integration must remain respected.
- **Trace:**

  > build/win32/code.iss registers legacy folder commands through ShouldInstallLegacyFolderContextMenu and modern integration through ShouldUseWindows11ContextMenu. ShouldRepairFolderContextMenu covers only background updates with forced classic menus, existing legacy file integration, and missing legacy folder integration. CurStepChanged also removes registration belonging to the other shell-menu mode. These paths were inspected, but the reporter's menu mode and the point at which registration is lost remain unconfirmed. Do not infer a fix from absent legacy keys on a modern-menu installation or broaden repair to override intentional preferences. Related reports https://github.com/microsoft/vscode/issues/303103 and https://github.com/microsoft/vscode/issues/316870 describe different registration scenarios that should remain distinct unless reproduction establishes equivalence.

## Evidence

- **Reported regression:** https://github.com/microsoft/vscode/issues/294633 reports folder context-menu integration disappearing after updating to 1.109.2 on Windows build 26100, with file integration still working and folder registry entries missing. Subsequent comments request updates but do not confirm resolution.
- **Current conditional repair:** build/win32/code.iss:1590–1606 implements ShouldRepairFolderContextMenu only for background updates on Windows 11 with forced classic menus, an existing legacy file command, and a missing legacy folder command. The report does not establish that forced-classic-menu condition, so this repair cannot be assumed to resolve it.
- **Registration paths:** build/win32/code.iss:1283–1295 separates modern menu registration from legacy file, directory, directory-background, and drive commands. Lines 1829–1839 remove the AppX package for forced classic menus or delete legacy keys when modern integration is selected; registry absence alone therefore does not establish the failing path.
