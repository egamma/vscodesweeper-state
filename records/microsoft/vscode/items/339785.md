# Issue #339785 — Status bar items not vertically centered in modern ui with default density

[https://github.com/microsoft/vscode/issues/339785](https://github.com/microsoft/vscode/issues/339785)

## Summary

Traced a plausible concrete mechanism on main: the status bar's floating-panels/modern-UI mode adds symmetric vertical padding to `.part.statusbar`, but `.statusbar-item` still assumes a fixed `line-height: 22px` from the base stylesheet that isn't adjusted for the resulting smaller content box, which would push the glyph content up against the bar's `overflow: hidden` clip rather than truly centering it — consistent with the reporter's measured offset.

## Change summary

In the Modern UI floating-panels layout (default density), status bar item icons/text sit visibly above the bar's vertical center instead of being centered.

## Best solution

Reconcile the fixed 22px `line-height` on `.statusbar-item` (src/vs/workbench/browser/parts/statusbar/media/statusbarpart.css) with the vertical padding floating-panels/modern-ui mode adds to `.part.statusbar` (src/vs/workbench/browser/media/floatingPanels.css), e.g. by centering content via flex alignment instead of a hardcoded line-height, or by only reducing visible glyph height without disturbing other densities.

- **Behavior:**

  > In Modern UI's floating-panels layout at default density, status bar items (icons and text, e.g. Errors/Warnings) should be vertically centered within the status bar's visible band, with equal empty space above and below the glyph ink, matching the expected behavior described in the issue and already working correctly in the non-floating-panels layout.
- **Trace:**

  > `.monaco-workbench.floating-panels .part.statusbar` (src/vs/workbench/browser/media/floatingPanels.css ~L351) adds `padding-top`/`padding-bottom: var(--vscode-spacing-size20)` to the bar, shrinking its content box under the fixed `height: 22px; box-sizing: border-box` from the base rule (src/vs/workbench/browser/parts/statusbar/media/statusbarpart.css ~L6-13). `.statusbar-item` (same file, ~L57-63) still has a hardcoded `line-height: 22px; height: 100%`, unaware of the new padding, and `.part.statusbar` clips overflow (`overflow: hidden`). The boundary: do not change status bar height/behavior for the non-floating-panels (classic) layout, and do not alter horizontal padding/margin rules already present for first/last visible items and background-colored items in the same files.
- **Open decisions:**
  - Should centering be fixed by changing `.statusbar-item`'s line-height/height model (e.g. flex align-items: center) globally, or only inside `.floating-panels` contexts, to avoid regressing the classic status bar's current pixel-perfect layout?
  - Does the same fix also need to account for `modern-ui-compact` density, which uses a different horizontal padding but the same vertical padding variable?

## Evidence

- **padding source:** src/vs/workbench/browser/media/floatingPanels.css ~L351-355 adds `padding-top`/`padding-bottom: var(--vscode-spacing-size20)` to `.monaco-workbench.floating-panels .part.statusbar`, shrinking the content box within the fixed 22px, border-box height.
- **line-height not adjusted:** src/vs/workbench/browser/parts/statusbar/media/statusbarpart.css ~L57-63 sets `.statusbar-item { line-height: 22px; height: 100%; }` unconditionally — not overridden for the floating-panels/modern-ui padded case, so the item's line box no longer matches the reduced content height.
- **DOM/flex structure:** statusbarPart.ts creates `.left-items.items-container`/`.right-items.items-container` as the direct flex children of `.part.statusbar` (which is itself `display:flex`), and `.part.statusbar` carries `overflow: hidden` — an oversized line box inside a shrunk flex cross-axis would be clipped asymmetrically rather than centered, matching the reported top-heavy offset.
