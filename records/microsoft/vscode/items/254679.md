# Issue #254679 — Enable save participants for files during edit sessions

[https://github.com/microsoft/vscode/issues/254679](https://github.com/microsoft/vscode/issues/254679)

## Summary

Keep open: current edit-session saves still explicitly skip save participants, while Keep triggers them separately. This team-authored Backlog request remains necessary, and a later maintainer comment explicitly identifies it as the canonical home for automatic formatting during agent edits.

## Change summary

Run configured save participants during ongoing agent edits without invalidating the file contents the model uses for subsequent edits.

## Best solution

Support participant-processed editor and disk contents during agent editing while preserving reliable subsequent edits and coherent diagnostics. Plan the model-visible content lifecycle in the chat editing pipeline, preserving existing Keep, Discard, and user-edit behavior.

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingTextModelChangeService.ts`
- **Validation:** Exercise two consecutive agent edits with a formatter and a code action on save that change text and line positions. Before Keep, verify that editor and disk contain participant-processed contents, the second edit succeeds against the intended model-visible representation, and diagnostics reference the correct content version. Repeat with an intervening user or external edit, then verify Keep and Discard retain their existing semantics.
- **Behavior:**

  > Configured save-time cleanup should run during agent editing rather than only when the user keeps changes. The editor and on-disk file should expose processed contents without causing subsequent agent edits to fail because formatting changed their expected text. Intervening user or external edits must not be overwritten by stale internal contents. Acceptance should cover consecutive edits, position-changing cleanup, diagnostic freshness, and existing Keep and Discard behavior.
- **Trace:**

  > ChatEditingModifiedDocumentEntry.acceptAgentEdits delegates to ChatEditingTextModelChangeService.acceptAgentEdits and then explicitly suppresses participants when saving completed edits; its separate save() method suppresses them too. _doAccept() performs an explicit save that allows participants, so acceptance-time cleanup is existing behavior, not the missing feature. ChatEditingTextModelChangeService computes edits against modifiedModel and applies them through _applyEdits; the inspected path does not establish the proposed independent model-visible content lifecycle. The author settles the visibility boundary in https://github.com/microsoft/vscode/issues/254679#issuecomment-3049615248: non-agent consumers should see formatted contents, but diagnostics may no longer match the agent's internal representation. The remaining trace must follow tool reads, edit matching, and diagnostic delivery before selecting a design. Preserve Keep, Discard, user edits, and existing save configuration; removing acceptance UI as requested in https://github.com/microsoft/vscode/issues/262495 is outside this issue.
- **Open decisions:**
  - When diagnostics refer to participant-processed contents that differ from the agent's internal representation, should the agent receive an outdated-content indication requiring a reread, or diagnostics translated to its current representation?
