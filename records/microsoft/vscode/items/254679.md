# Issue #254679 — Enable save participants for files during edit sessions

[https://github.com/microsoft/vscode/issues/254679](https://github.com/microsoft/vscode/issues/254679)

## Summary

Keep this team-authored design request open: edit sessions still need a safe way to run save participants without invalidating the agent's edit coordinates, and the discussion identifies an unresolved diagnostics-consistency question.

## Change summary

Run save participants during agent edit sessions while retaining an unformatted shadow model for subsequent model-authored edits.

## Best solution

Design the agent-editing pipeline so the user-facing text model can receive formatting and other save-participant edits while agent tools continue from a synchronized shadow representation, with an explicit stale-content signal when diagnostics no longer correspond to the agent's coordinates.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedFileEntry.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingTextModelContentProvider.ts`
- **Validation:** Add an agent-editing test that applies sequential edits around a formatting save participant and verifies the visible model is formatted while subsequent edits remain correctly anchored; also verify the chosen stale-diagnostics behavior.
- **Behavior:**

  > During an agent edit session, save participants such as formatters should be able to update the user-visible file after each model edit without causing later model edits to fail because their offsets were computed against pre-format content. Editors, hovers, and diagnostics outside the edit tools should observe the formatted model. If formatting makes diagnostic locations unreliable from the model's perspective, the model must receive a defined stale-content signal or equivalent behavior rather than silently consuming mismatched locations.
- **Trace:**

  > The issue proposes maintaining an unformatted shadow model for agent edit application, copying each result into the real model, then running save participants on the real model. The chat editing implementation is centered in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts and its modified-file/model-provider collaborators. The boundary is agent edit-session state: normal save-participant behavior and non-agent editor consumers must remain unchanged. The related https://github.com/microsoft/vscode/issues/252415 and https://github.com/Dart-Code/Dart-Code/issues/5785 provide adjacent motivation but do not replace this design item. Uncertainty begins at how diagnostics and other coordinate-bearing results are represented to the model after the visible and shadow models diverge.
- **Open decisions:**
  - When formatting causes diagnostics to refer to coordinates that differ from the shadow model, should diagnostic context be withheld and marked stale, remapped to shadow coordinates, or force the agent to re-read and resynchronize the file?
  - Which save participants are safe to run during an edit session: all registered participants, or only deterministic text transformations such as formatting and code actions?
