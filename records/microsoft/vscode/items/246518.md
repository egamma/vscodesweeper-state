# Issue #246518 — MCP: Input preview can be confused with looking like in-file configuration

[https://github.com/microsoft/vscode/issues/246518](https://github.com/microsoft/vscode/issues/246518)

## Summary

Keep open: current MCP input hints still present saved values without explicitly identifying them as previews rather than file contents. The maintainer discussion identifies a UX improvement, and neither a referenced fix nor a verified canonical supports closing this team-authored issue.

## Change summary

Make MCP saved-input previews clearly distinguishable from configuration text persisted in mcp.json.

## Best solution

Make the saved-value annotation explain its non-file provenance while retaining the standard inlay-hint interaction and existing input-management actions. Agree on the visible presentation with the MCP/UX maintainers before implementation.

  > McpLanguageFeatures registers an inlay-hint provider in src/vs/workbench/contrib/mcp/browser/mcpLanguageFeatures.ts. _provideInlayHints obtains saved values through IMcpRegistry.getSavedInputs, and annotateServers and annotateInputs both feed pushAnnotation. The remaining uncertainty is the visible UX treatment, not the source of the annotations. Keep the scope to preview clarity; do not change input storage, secret handling, or unrelated editor-wide inlay-hint behavior.
