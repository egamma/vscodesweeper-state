## Summary

Keep open while the linked relaunch fix is reviewed. Current source still calls Electron's app.relaunch(), and the discussion provides independent confirmation of inherited NoNewPrivs restrictions after a native Linux package upgrade.

## Change summary

Prevent application relaunch after a package upgrade from introducing NoNewPrivs restrictions that block sudo in integrated terminals.

## Best solution

Review https://github.com/microsoft/vscode/pull/296711 as the existing implementation candidate for avoiding Electron/Chromium relaunch restrictions on Linux. Preserve normal shutdown, veto handling, and sandbox protections, and check whether the reported persistence after restarting represents an additional launch-path problem.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/vscode/issues/253204 describes upgrading the native APT package while VS Code is running, opening another window, and choosing Relaunch VS Code from the extension-host version-mismatch notification. The resulting terminal reports no_new_privs and sudo refuses privilege elevation.
- **Independent confirmation:** The supplied August 7, 2026 comment reports the same sudo restriction on Debian 13 with native APT-installed VS Code 1.132.0 following an upgrade. /proc/$$/status shows NoNewPrivs: 1, and process ancestry traces inheritance through Code's utility process into zsh; container and remote-session indicators are absent. The commenter also reports that restarting did not clear the flag, which remains an unresolved detail.
- **Current relaunch path:** src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts:164-175 connects the version-mismatch notification's Relaunch VS Code action to IHostService.restart(). NativeHostService.restart() delegates to the native relaunch service, which reaches LifecycleMainService.relaunch() in src/vs/platform/lifecycle/electron-main/lifecycleMainService.ts:681-710. Its quit listener still invokes electron.app.relaunch({ args }) at line 701.
- **Open implementation candidate and upstream diagnosis:** GitHub confirms https://github.com/microsoft/vscode/pull/296711 is OPEN, has not merged, and contains Fixes #253204. Its diff attributes the restriction to Electron's app.relaunch() using Chromium's base::LaunchProcess(), and proposes a Linux-specific Node spawn path. This identifies an upstream mechanism and a proposed VS Code workaround, not a landed fix; Electron's native implementation was not independently inspected.
- **Related reports are not duplicate targets:** The reporter-linked https://github.com/microsoft/vscode/issues/242781, https://github.com/microsoft/vscode/issues/221718, and https://github.com/microsoft/vscode/issues/90725 were all verified CLOSED.
