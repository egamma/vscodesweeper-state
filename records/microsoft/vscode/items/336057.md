# Issue #336057 — Add a right-side fixed per-line annotation gutter API for extensions

[https://github.com/microsoft/vscode/issues/336057](https://github.com/microsoft/vscode/issues/336057)

## Summary

This is a valid extension API gap: current decorations can occupy the left gutter or follow line content, but cannot render per-line metadata in a fixed right-side lane. No older issue was found that owns the same extension-facing capability, so it should remain open as a feature request pending API and layout design.

## Change summary

Expose an extension API for text or icon annotations in a fixed right-side editor gutter without modifying document content.

## Best solution

Provide a first-class, theme-aware right-side annotation lane whose layout composes predictably with wrapping, the minimap, scrollbars, diff editors, accessibility, and annotations from multiple extensions. The API should support per-line content and interaction without affecting text geometry or cursor positions.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/editor/common/editorCommon.ts`, `src/vs/workbench/api/common/extHostTypeConverters.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/view.ts`, `src/vs/editor/test/browser/config/editorLayoutProvider.test.ts`
- **Validation:** The plan should end with `scripts/test.sh --grep "Editor ViewLayout - EditorLayoutProvider"` covering right-lane geometry with minimap-left, minimap-right, wrapping, and scrollbar combinations, plus an extension API test showing per-line annotations stay at one fixed horizontal position without changing document text or cursor positions.
- **Behavior:**

  > Extensions need to display text or icons for individual model lines in a stable right-side editor column, independent of each line's content length. The annotations must not alter document text, cursor positions, or edits, and must remain correctly positioned with wrapping, minimaps, scrollbars, and diff editors. Theme colors, hover information, keyboard-accessible interaction, and multiple annotation producers must behave predictably. Existing inline and left-gutter decorations must remain unchanged.
- **Trace:**

  > The public surface in src/vscode-dts/vscode.d.ts offers `gutterIconPath` and inline `before`/`after` attachments only; src/vs/workbench/api/common/extHostTypeConverters.ts maps exactly those options into the internal decoration contract. EditorLayoutInfo in src/vs/editor/common/config/editorOptions.ts reserves only left-side glyph, line-number, and line-decoration widths before calculating content width. Those overlays are registered in src/vs/editor/browser/view.ts, with rendering implemented by the line-number and line-decoration view parts. The uncertainty begins at the public behavior contract: where the lane sits relative to minimap and scrollbar, how competing extensions share it, and whether wrapped model lines render one annotation or one per visual line. https://github.com/microsoft/vscode/issues/335854 may share underlying layout infrastructure but requests built-in line-number positioning and must not replace this API requirement.
- **Open decisions:**
  - Should the right annotation lane sit inside the text viewport, between the text and minimap, or outside the minimap when it is on the right?
  - When multiple extensions contribute annotations to the same line, does the public contract provide ordered lanes, a shared fixed-width column, or independently sized columns?
  - For a wrapped model line, should its annotation appear once beside the first visual line, once beside the last visual line, or beside every wrapped segment?
  - Which interactions are part of the initial contract: hover only, command activation by pointer and keyboard, or both?

## Evidence

- **current public API:** src/vscode-dts/vscode.d.ts exposes `gutterIconPath` for the existing gutter and `before`/`after` attachments; it has no fixed right-side per-line lane. `after` remains attached to decorated text.
- **extension-host boundary:** src/vs/workbench/api/common/extHostTypeConverters.ts forwards gutter icons and before/after attachment options but contains no right-side annotation representation.
- **editor layout:** src/vs/editor/common/config/editorOptions.ts models glyph margin, line numbers, and line decorations as left-positioned regions and computes content width without a right annotation lane; src/vs/editor/browser/view.ts registers only the corresponding left-margin overlays.
- **related issue:** https://github.com/microsoft/vscode/issues/335854 is older and related, but asks to move VS Code's built-in line numbers. It does not own the broader public API for arbitrary extension-provided per-line metadata, so it does not meet the stronger duplicate bar for this re-review.
- **existing-capability check:** The public decoration surface provides inline attachments, left-gutter icons, and overview-ruler markers, but none supplies a stable right-aligned column independent of line length.
