# Issue #300651 — [Feature Request] Copilot Chat: "New chat with context" command to recover from corrupted conversations

[https://github.com/microsoft/vscode/issues/300651](https://github.com/microsoft/vscode/issues/300651)

## Summary

The requested recovery workflow already exists as “Fork Conversation”: users can fork from the checkpoint before a corrupted turn, preserving earlier context while excluding the bad request and response.

## Change summary

Provide a way to recover an unusable Copilot Chat session by carrying its valid context into a new conversation.

## Best solution

Keep the existing checkpoint-based Fork Conversation workflow as the recovery mechanism. Any reproducible path that creates invalid whitespace-only content should be reported separately as a bug with logs, rather than adding another session-copy command.

  > Thanks for the request. This workflow is already available through **Fork Conversation**: use the checkpoint on the request immediately before the corrupted turn to open a new chat containing the earlier conversation context while excluding the failing turn. The feature was added in https://github.com/microsoft/vscode/pull/296093 and is also available as `/fork` when forking the current conversation from its end.

## Evidence

- **existing capability:** https://github.com/microsoft/vscode/pull/296093 merged before this issue was filed and added “Fork Conversation” to chat checkpoints plus the `/fork` command.
- **implementation:** Commit https://github.com/microsoft/vscode/commit/eadcfc2413831fcafa29506858a38410ec7eb352 added `workbench.action.chat.forkConversation` in `src/vs/workbench/contrib/chat/browser/actions/chatForkActions.ts`; the checkpoint path slices serialized requests through the selected safe point, gives the copy a new session ID, and opens it as a new chat.
- **recovery path:** On current main, selecting Fork Conversation at the request checkpoint immediately before the failing turn preserves all earlier requests and responses while excluding that request and its potentially malformed response—the central “new chat with context” behavior requested here.
