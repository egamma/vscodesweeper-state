# Issue #231474 — Zen mode does not exit when leaving fullscreen after restart

[https://github.com/microsoft/vscode/issues/231474](https://github.com/microsoft/vscode/issues/231474)

## Summary

The restart-specific bug should remain open: the report identifies lost Zen/fullscreen transition provenance, the relevant logic remains on main, and no merged fix or older canonical issue owns the same symptom. A rejected PR addressed the broader non-restart behavior instead and was closed because that behavior is intentional.

## Change summary

After Zen Mode and fullscreen are restored across a restart, leaving fullscreen can fail to exit Zen Mode because the original fullscreen transition state is not honored correctly.

## Best solution

Preserve and restore whether Zen Mode originally caused the fullscreen transition, then exit Zen Mode when that restored fullscreen session ends. Retain the intentional behavior where Zen Mode remains active if the user entered fullscreen independently before enabling Zen Mode.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/layout.ts`
- **Validation:** With `zenMode.restore` and `zenMode.fullScreen` enabled, start windowed, enter Zen Mode so it causes fullscreen, quit and reopen, then leave fullscreen and verify Zen Mode exits. As a control, enter fullscreen manually before enabling Zen Mode and verify that leaving fullscreen does not exit Zen Mode, both before and after restart.
- **Behavior:**

  > Zen Mode must remember across restart whether entering it caused the window to enter fullscreen. If Zen Mode caused fullscreen, leaving fullscreen after reopening must also exit Zen Mode. If fullscreen was entered independently before Zen Mode, leaving fullscreen must keep Zen Mode active. Validate both paths before and after restart.
- **Trace:**

  > `Layout.onFullscreenChanged` in `src/vs/workbench/browser/layout.ts` exits Zen Mode only when `LayoutStateKeys.ZEN_MODE_EXIT_INFO.transitionedToFullScreen` is true. `toggleZenMode` records that flag on a normal transition but deliberately does not rewrite it while restoring, and `LayoutStateModel` saves the workspace-scoped object from the storage-service save callback. The issue reports that the value nevertheless does not survive the restart path; no post-report commit changes that flow. https://github.com/microsoft/vscode/pull/233952 removed the guard entirely and was rejected because doing so changes the intentional manually-entered-fullscreen behavior, which must remain outside the fix.

## Evidence

- **reported diagnosis:** https://github.com/microsoft/vscode/issues/231474 provides concrete restart steps and identifies `zenModeExitInfo.transitionedToFullScreen` as the state that is not remembered correctly; the issue is classified `bug` and `workbench-zen`.
- **current source:** On current main, `src/vs/workbench/browser/layout.ts` still gates automatic Zen Mode exit in `onFullscreenChanged` on `ZEN_MODE_EXIT_INFO.transitionedToFullScreen`; startup restores Zen Mode through `toggleZenMode(false, true)`, while the exit information is workspace state saved through `onWillSaveState`.
