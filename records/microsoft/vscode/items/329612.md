# Issue #329612 — Git SCM: Hidden commit input should still support editor-first template authoring before commit

[https://github.com/microsoft/vscode/issues/329612](https://github.com/microsoft/vscode/issues/329612)

## Summary

Keep open for discussion: the existing editor setting does not guarantee an editor-first review when the hidden SCM input contains template text. The related open issues inspected do not cover this specific behavior.

## Change summary

Allow SCM Commit to require editing and reviewing a template-backed message before finalizing when the commit input is hidden.

## Best solution

Consider an opt-in editor-first workflow in the built-in Git extension that preserves template content and requires explicit completion in the commit editor, while leaving existing direct-commit behavior unchanged for other workflows.

## Evidence

- **Existing capability is conditional:** extensions/git/package.json:3528–3532 registers git.useEditorAsCommitInput with default true. extensions/git/package.nls.json explicitly describes editor authoring as applying whenever no message is provided in the commit input box; it does not promise editor-first handling of an existing template-backed message.
- **Hidden input still supplies the commit message:** extensions/git/src/repository.ts:1051 changes inputBox.visible for git.showCommitInput. Commands.commitWithAnyInput in extensions/git/src/commands.ts:2576–2609 reads repository.inputBox.value without checking visibility, and smartCommit passes that message to repository.commit.
- **Nonempty messages bypass editor invocation:** extensions/git/src/git.ts:2082–2148 passes a nonempty message through --file - and does not add --edit when opts.useEditor is true. Consequently, enabling git.useEditorAsCommitInput does not force review of text already present in the hidden input. Repository.commitOperationCleanup at extensions/git/src/repository.ts:1489–1492 can repopulate the input with the template after a message-bearing commit.
- **Visibility alone does not establish unconditional coverage:** src/vs/workbench/contrib/scm/browser/scmInput.ts:507–522 skips template insertion while the input is hidden. This can allow an initially empty hidden input to take the existing editor flow, but does not guarantee that the input remains empty after previous authoring or commit cleanup.
