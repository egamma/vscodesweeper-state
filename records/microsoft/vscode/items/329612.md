# Issue #329612 — Git SCM: Hidden commit input should still support editor-first template authoring before commit

[https://github.com/microsoft/vscode/issues/329612](https://github.com/microsoft/vscode/issues/329612)

## Summary

Traced the flow on main: `git.useEditorAsCommitInput` only forces the editor when the input box is empty, but when `git.showCommitInput` is false the commit template still auto-populates `inputBox.value`, so `commitWithAnyInput` sees a non-empty message and commits it directly without ever opening the editor. No existing setting produces the requested 'hidden input, but always review in editor before finalizing' mode, so this is a genuine gap worth routing to the git extension owners.

## Change summary

Request a new mode/setting so that when `git.showCommitInput` is false, clicking Commit always opens the commit-message editor (using the template as a starting point) instead of finalizing immediately from the auto-populated template text.

## Best solution

Have the git extension owners decide on a new setting (or an extension to `useEditorAsCommitInput`'s semantics) in extensions/git/src/commands.ts (`commitWithAnyInput`/`getCommitMessage`, around line 2573) so that a non-empty but template-sourced message doesn't bypass the editor when the input box is hidden; this is a product/UX decision, not a mechanical fix.
