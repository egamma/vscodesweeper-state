# Issue #333132 — Copilot Chat: custom agents vanish from the dropdown after "renderer closed the MessagePort" (InstantiationService has been disposed)

[https://github.com/microsoft/vscode/issues/333132](https://github.com/microsoft/vscode/issues/333132)

## Summary

This remains a distinct, source-supported teardown bug: an abnormal renderer MessagePort closure can dispose the Copilot service graph while an agent invocation is still running, after which the affected window loses extension-provided custom agents until reload.

## Change summary

Cancel in-flight Copilot agent requests cleanly and restore custom-agent registrations when an affected extension host terminates and restarts.

## Best solution

Coordinate extension-host teardown, chat-request cancellation, and automatic host recovery so no request re-enters a disposed Copilot InstantiationService and the restarted host re-registers custom agents without requiring a window reload.

## Plan brief

- **Likely files:** `src/vs/workbench/api/node/extensionHostProcess.ts`, `src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts`, `src/vs/workbench/api/common/extHostChatAgents2.ts`, `extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts`, `extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts`
- **Validation:** Add an extension-host lifecycle integration test that closes the renderer MessagePort while `$invokeAgent` is pending, then verifies that the request is cancelled without a disposed-service error and that custom-agent registrations are available after automatic host restart.
- **Behavior:**

  > If the renderer connection closes while a Copilot agent request is running, the request must terminate cleanly without invoking services after their lifecycle has ended. When VS Code automatically restarts the affected extension host, extension-provided custom agents must be registered in the dropdown again without a window reload. Other windows and normal extension-host shutdowns must remain unaffected.
- **Trace:**

  > The reported sequence begins at the MessagePort `close` handler in src/vs/workbench/api/node/extensionHostProcess.ts. The workbench observes the unexpected exit and restarts the local host through NativeExtensionService, while `$invokeAgent` in src/vs/workbench/api/common/extHostChatAgents2.ts can still be awaiting the Copilot participant task. Copilot's ChatParticipantRequestHandler continues asynchronous intent processing and later calls endpoint or instantiation services; its shared InstantiationService throws once extension teardown has disposed it. The trace establishes both the stale in-flight request and missing post-restart registration symptoms, but it does not establish whether the primary missing lifecycle signal is request cancellation, host-manager cleanup, contribution reactivation, or a combination. Preserve normal cancellation semantics, normal window shutdown, and isolation between windows.

## Evidence

- **reported trace:** The issue provides a timestamped extension-host log where `renderer closed the MessagePort` is immediately followed by two `InstantiationService has been disposed` failures from the active `$invokeAgent`; 25 normal renderer terminations in the same log sample did not produce the error.
- **termination path:** src/vs/workbench/api/node/extensionHostProcess.ts registers the MessagePort `close` event to call `onTerminate('renderer closed the MessagePort')`.
- **in-flight invocation path:** src/vs/workbench/api/common/extHostChatAgents2.ts keeps `$invokeAgent` awaiting the extension participant task and only removes its in-flight record in `finally`; the path has no teardown-specific guard before or during extension code execution.
- **disposed service re-entry:** extensions/copilot/src/extension/conversation/vscode-node/chatParticipants.ts creates ChatParticipantRequestHandler through the shared InstantiationService, and extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts performs further service creation and endpoint lookup after asynchronous intent handling. extensions/copilot/src/util/vs/platform/instantiation/common/instantiationService.ts deliberately throws when those operations occur after disposal.
- **recovery path:** src/vs/workbench/services/extensions/electron-browser/nativeExtensionService.ts automatically restarts a crashed local extension host, but the reported window remained without custom-agent registrations until `Developer: Reload Window`, indicating incomplete recovery.
