# Issue #333132 — Copilot Chat: custom agents vanish from the dropdown after "renderer closed the MessagePort" (InstantiationService has been disposed)

[https://github.com/microsoft/vscode/issues/333132](https://github.com/microsoft/vscode/issues/333132)

## Summary

Well-diagnosed but single, non-deterministic occurrence: the reporter's own log correlation (1 abnormal MessagePort closure out of 26 terminations, 2 disposal errors) is solid evidence of a real extension-host teardown race, but it hasn't been confirmed by anyone else or reproduced on demand, so this needs a confirmation/repro request rather than a keep-open parking.

## Change summary

When the extension host terminates via 'renderer closed the MessagePort' while a Copilot Chat `$invokeAgent` request is in flight, the request hits a disposed `InstantiationService`, and the affected window's agent dropdown loses custom agents until a manual reload.

## Best solution

If confirmed, the fix likely belongs in the chat agent invocation path — either cancelling in-flight `$invokeAgent` calls when the extension host begins disposal (src/vs/workbench/api/common/extHostChatAgents2.ts) or making Copilot Chat's agent-discovery/endpoint resolution resilient to a disposed instantiation service — but this needs a second occurrence or maintainer trace before committing to that shape, since the current evidence is a single non-deterministic capture.
