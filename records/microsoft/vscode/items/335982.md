# Issue #335982 — Terminal replay can drop acknowledgements for live output and leave the PTY paused

[https://github.com/microsoft/vscode/issues/335982](https://github.com/microsoft/vscode/issues/335982)

## Summary

Traced this in the current source: LocalPty.acknowledgeDataEvent() and the pty-host-side PersistentTerminalProcess.acknowledgeDataEvent() both unconditionally drop acknowledgements while `_inReplay` is true, but BasePty.handleData() still forwards live data through the same onProcessData path during that window (triggerReplay() clears unacknowledged chars and lets live output flow before the replay's writePromise resolves). That's a real race that can permanently pause a terminal's pty.

## Change summary

During terminal session replay (e.g. after a window reload), live output delivered while replay is still in-flight can have its flow-control acknowledgement silently dropped, permanently inflating the unacknowledged character count and leaving the pty paused.

## Best solution

Buffer live handleData() events received while _inReplay is true (in BasePty/LocalPty and the mirrored pty-host logic in ptyService.ts) and flush them in order after clearing the replay flag, so their acknowledgements are never dropped; the reporter's own local patch is a reasonable template for the fix.
