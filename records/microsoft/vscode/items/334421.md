# Issue #334421 — Copilot Agent repeatedly invokes disabled task_complete, causing tool loop and Extension Host CPU/RAM growth

[https://github.com/microsoft/vscode/issues/334421](https://github.com/microsoft/vscode/issues/334421)

## Summary

Thanks for the detailed report and logs. The exact log strings the reporter quotes still exist verbatim in current main, and the code confirms a real inconsistency: in autopilot mode `ensureAutopilotTools` unconditionally force-injects `task_complete` into the model's tool schema even when the user has disabled it, but the actual invocation check elsewhere still rejects the call as disabled — producing the repeated add/fail/re-add pattern described. This is a genuine Copilot Chat (core) bug, not yet fixed on main, and needs a maintainer decision on how autopilot should reconcile forced completion signaling with a user-disabled tool.

## Change summary

In autopilot mode, when `task_complete` is disabled by the user, the agent repeatedly re-adds and invokes it, hitting a 'disabled by the user' error each time and driving sustained Extension Host CPU/RAM growth over a long session.

## Best solution

In extensions/copilot/src/extension/intents/node/toolCallingLoop.ts, `ensureAutopilotTools` (lines ~962-978) should not silently append `task_complete` to the model-facing tool list when the tool is disabled/unavailable per the user's actual enabled-tools set — or the disabled-tool check in extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx (~line 282-284) should recognize autopilot-injected completion tools as a distinct, allowed case. Either way the loop should stop or fall back cleanly on the first disabled-tool failure instead of repeating it across turns.

- **disabled-tool rejection:** extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx line 284: invocation throws 'Tool ${name} is currently disabled by the user, and cannot be called.' when the tool isn't in `promptContext.tools.availableTools` — the same wording the reporter's logs show, indicating the forcibly-injected tool and the invocation-time enabled-tools set are out of sync.
