# Issue #336548 — Multi-diff empty-side models are prematurely disposed by comment document references

[https://github.com/microsoft/vscode/issues/336548](https://github.com/microsoft/vscode/issues/336548)

## Summary

Freshly filed, team-authored bug report with a detailed traced code path showing synthetic empty-side models in the multi-diff editor being disposed by an unrelated comment-prefetch reference lifecycle; carries a real milestone (1.139.0), so it stays open regardless.

## Change summary

Comment-range prefetch acquires a resolver reference to a multi-diff's synthetic empty-side model; when that reference expires/evicts, the model is destroyed even though the multi-diff still owns it, causing blank diff regions and a latched render failure.

## Best solution

Give synthetic diff sides a long-lived resolver reference tied to the shared diff view model's lifetime (per the reporter's traced fix direction) instead of a raw model created independently of the resolver, in multiDiffEditorViewModel.ts / textModelResolverService.ts / mainThreadDocuments.ts; this is a multi-file ownership-model fix, not a quick patch.
