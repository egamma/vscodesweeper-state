# Issue #337538 — Agent Host: forward network domain lists to the sandbox

[https://github.com/microsoft/vscode/issues/337538](https://github.com/microsoft/vscode/issues/337538)

## Summary

Team-authored, security-relevant tracking issue for a real, still-open gap: current main confirms admin network domain allow/deny lists are not forwarded to the Agent Host sandbox, so filtered network policy is silently dropped in favor of allow-all/deny-all.

## Change summary

Forward `chat.agent.allowedNetworkDomains` / `deniedNetworkDomains` into the sandbox SDK's `userPolicy.network.allowedHosts` / `blockedHosts` instead of collapsing to all-or-nothing network access.

## Best solution

Extend `buildSandboxConfigForSdk` in src/vs/platform/agentHost/node/copilot/sandboxConfigForSdk.ts (and the `SandboxNetworkPolicy` type) to carry host allow/deny lists once the SDK supports them, mirroring the CLI-side scaffolding already present (currently gated off via `hostListsEnforceable = false`) in copilotcliSessionService.ts.
