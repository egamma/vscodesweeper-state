# Issue #302261 — Terminal Issue: terminal.integrated.automationProfile.windows does not respect "env" object

[https://github.com/microsoft/vscode/issues/302261](https://github.com/microsoft/vscode/issues/302261)

## Summary

Still reproduces on main: the debug integrated terminal (RunInTerminal) extracts only shell path and args from the automation profile, ignoring its `env` property. The task system handles it correctly, but the debug path does not.

## Change summary

When launching a debug session with an integrated terminal, the `env` object from `terminal.integrated.automationProfile.windows` is not applied to the terminal environment.

## Best solution

Add an `env` getter (or pass the full profile env) in the debug terminal creation path in `src/vs/workbench/api/node/extHostDebugService.ts` — mirror how `src/vs/workbench/contrib/tasks/browser/terminalTaskSystem.ts` already passes `defaultProfile.env` at line 1246. The ext host terminal service needs a `getDefaultEnv(useAutomationShell)` method or similar.
