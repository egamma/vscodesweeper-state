# Issue #48754 — Allow programatically un-selecting an item in a contributed tree

[https://github.com/microsoft/vscode/issues/48754](https://github.com/microsoft/vscode/issues/48754)

## Summary

Keep open: current main still lacks an extension API to clear contributed-tree selection, and an open PR proposes that capability. Review the existing proposal rather than starting a competing implementation; the request has 21 upvotes and sustained extension-author demand.

## Change summary

Allow extensions to programmatically clear a contributed TreeView's selection when no item corresponds to the current editor or cursor state.

## Best solution

Review and resolve the API contract in https://github.com/microsoft/vscode/pull/331847, then land an accepted selection-clearing API. Existing reveal options and identity-changing refresh workarounds do not deliver the requested operation.

## Evidence

- **Existing API does not cover the request:** src/vscode-dts/vscode.d.ts:12144–12231 defines TreeView.selection as readonly and exposes reveal(element, options), but no selection-clearing method. In src/vs/workbench/api/browser/mainThreadTreeViews.ts:161–187, reveal calls setSelection([item]) only when select is true; select:false leaves the previous selection unchanged.
- **Undefined reveal is not deselection:** src/vscode-dts/vscode.proposed.treeViewReveal.d.ts permits an undefined element. ExtHostTreeView.reveal in src/vs/workbench/api/common/extHostTreeViews.ts:522–540 forwards that case, but MainThreadTreeViews.$reveal at src/vs/workbench/api/browser/mainThreadTreeViews.ts:75–87 opens the view and skips item handling when itemInfo is undefined; it does not clear selection.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/331847 is OPEN with mergedAt:null. Its body explicitly references this issue and proposes TreeView.clearSelection() under treeViewClearSelection, preserving focus and not opening the view. This is an unmerged proposal, not a completed fix.
- **Maintainer-linked fix addresses a different behavior:** The maintainer reference https://github.com/microsoft/vscode/issues/174811#issuecomment-1479992492 describes removing ghost focus with focus:false, not clearing selection. Current MainThreadTreeViews.reveal separately calls setFocus() for focus:false, confirming that focus and selection are distinct operations.
- **Related report preserves this issue as the original:** https://github.com/microsoft/vscode/issues/180394 is CLOSED. In https://github.com/microsoft/vscode/issues/180394#issuecomment-1520034746, the maintainer explicitly chose to reopen the original request. Searches for open tree clear-selection, deselect, and unselect requests found no alternative canonical issue; this newer closed report is not a valid duplicate target.
- **Demand and workaround limitations:** The supplied discussion records 21 body upvotes and multiple extension authors requesting this capability. Comments describe clearing or rewriting TreeItem IDs followed by onDidChangeTreeData refreshes, with visible re-rendering, unstable identity, and command-execution problems; these workarounds do not replace a supported selection API.
