# Issue #296374 — Feature Request: Add settings to disable "Upload" and "Download" in File Explorer context menu

[https://github.com/microsoft/vscode/issues/296374](https://github.com/microsoft/vscode/issues/296374)

## Summary

Keep open as a security-sensitive feature request. Current main exposes upload and download without configuration or policy checks, leaving managed remote environments without an enforceable VS Code UI control.

## Change summary

Add administrator-controllable settings that disable File Explorer uploads and downloads in remote environments.

## Best solution

Provide machine-scoped, policy-capable controls for upload and download, hide the corresponding Explorer actions, and enforce the controls in the command handlers so direct command invocation cannot bypass them. Preserve existing transfer behavior by default.

## Evidence

- **current menu registration:** src/vs/workbench/contrib/files/browser/fileActions.contribution.ts registers explorer.download and explorer.upload based only on platform, resource scheme, folder, writability, and browser file-system support; there is no configuration or policy condition.
- **unguarded execution:** src/vs/workbench/contrib/files/browser/fileActions.ts registers explorer.download and explorer.upload with handlers that invoke FileDownload or BrowserFileUpload without checking an enablement setting, so hiding menu entries alone would not enforce the restriction.
- **existing setting is insufficient:** src/vs/workbench/contrib/files/browser/files.contribution.ts defines explorer.enableDragAndDrop but no upload/download controls. FileDragAndDrop reads that setting in src/vs/workbench/contrib/files/browser/views/explorerViewer.ts, while the context-menu command paths remain independent.
- **canonical search:** Repository issue searches for disabling Explorer upload/download and remote file transfer found no older open issue with the same observable request; the only matching open result was https://github.com/microsoft/vscode/issues/296374 itself.
- **security boundary:** The requested controls are intended to reduce data exfiltration and infiltration in managed sandboxed environments, making this security-sensitive and therefore protected from an automated close.
