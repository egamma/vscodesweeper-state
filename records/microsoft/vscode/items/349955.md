# Issue #349955 — Think about model routers in AHP

[https://github.com/microsoft/vscode/issues/349955](https://github.com/microsoft/vscode/issues/349955)

## Summary

Keep this team-authored protocol-design discussion open: routers already appear as advertised models, but whether their semantics belong in standard AHP remains undecided. The existing router implementation does not settle that interoperability question.

## Change summary

Decide whether model routers need a shared AHP representation rather than provider-specific model identifiers and metadata.

## Best solution

Agree on what conforming clients should understand about router selections, using existing AHP model constructs where sufficient and defining any genuine protocol gap with the protocol owners. Preserve compatibility with clients and hosts that ignore optional router metadata.
