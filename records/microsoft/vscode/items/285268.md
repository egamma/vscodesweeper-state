# Issue #285268 — Allow upvoting feature requests after 60 days

[https://github.com/microsoft/vscode/issues/285268](https://github.com/microsoft/vscode/issues/285268)

## Summary

The 60-day lock on feature requests that don't reach sufficient upvotes is a deliberate policy choice by the VS Code team to manage backlog scale; this is the triage system working as designed.

## Change summary

Allow upvoting or reviving feature-request issues after the 60-day community lock window closes.

## Best solution

This is an intentional part of VS Code's community-driven feature-request lifecycle. The process encourages filing fresh issues when old locked ones resurface — this consolidates signal on what's currently desired rather than accumulating stale votes. The team has chosen this trade-off deliberately to keep the backlog manageable at scale.
