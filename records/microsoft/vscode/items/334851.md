# Issue #334851 — Distinguish remote workspaceless chats in the Agent Sessions list

[https://github.com/microsoft/vscode/issues/334851](https://github.com/microsoft/vscode/issues/334851)

## Summary

Current main still renders local and remote workspaceless chats identically even though the remote provider already exposes its host name and address. This team-authored, bounded Sessions-list polish should remain open.

## Change summary

Expose the owning remote connection on workspaceless chat rows so users can distinguish remote sessions from local ones before opening them.

## Best solution

Show the remote provider's user-facing host label on remote quick-chat rows, using its address fallback, and include the same origin in the row's accessible name while leaving local chats and workspace-backed sessions unchanged.

- **Fit:** aligned
- **Reason:** Making mixed local and remote agent sessions identifiable improves both the agent experience and the clarity of a core workbench navigation surface.
