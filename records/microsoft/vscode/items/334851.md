# Issue #334851 — Distinguish remote workspaceless chats in the Agent Sessions list

[https://github.com/microsoft/vscode/issues/334851](https://github.com/microsoft/vscode/issues/334851)

## Summary

The requested distinction is still missing on current main: remote and local workspace-less chats render identically in the Sessions list, although remote host identity is available to the renderer. Keep this team-authored request open for a compact row-presentation decision.

## Change summary

Expose the owning remote host on workspace-less chat rows so users can distinguish remote sessions from local ones before opening them.

## Best solution

Give remote workspace-less chat rows a quiet but persistent host-origin label across regular and compact layouts, while preserving session-title hierarchy and including the same identity in the row's accessible label.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts`
- **Validation:** Extend the Sessions list unit test to render local and remote quick chats in regular and compact modes, asserting that only remote rows expose the configured host name visually and in the row ARIA label, including after the provider label changes.
- **Behavior:**

  > Workspace-less chats owned by a remote Agent Host must be distinguishable from local chats before they are opened. The remote connection's configured name, with its authority/address fallback, must be available in both the visible row presentation and the accessible row label. Local quick-chat rows must retain their existing presentation, and remote identity must remain discoverable in both regular and compact list layouts.
- **Trace:**

  > SessionItemRenderer in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts renders quick chats with a generic "No workspace" badge and deliberately omits all details for compact quick-chat rows. SessionsAccessibilityProvider in the same file likewise omits provider identity. The renderer already receives ISessionsProvidersService, and getSessionSummaryHoverData in src/vs/sessions/contrib/sessions/browser/sessionHoverContent.ts proves that session.providerId plus remoteConnectionStatus can resolve the remote provider label. RemoteAgentHostSessionsProvider supplies a configured display name with the remote address as fallback and signals name changes through onDidChangeSessionTypes. Preserve local rows, existing status presentation, grouping, and session-title prominence; this work is row presentation and focused tests, not a change to list placement or provider ownership.
- **Open decisions:**
  - Across regular and compact quick-chat rows, should the host name replace the generic workspace detail or appear as an additional secondary label?
