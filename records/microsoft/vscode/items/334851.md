# Issue #334851 — Distinguish remote workspaceless chats in the Agent Sessions list

[https://github.com/microsoft/vscode/issues/334851](https://github.com/microsoft/vscode/issues/334851)

## Summary

Team-authored request describing a real gap: the Agents window's sessions list has no per-item indication of which host (local vs. remote/tunnel) owns a workspaceless chat. No fix is present on main and the item stayed open in the prior review with no canonical duplicate found, so it stays open.

## Change summary

Workspaceless chats created via a remote VS Code Server/tunnel look identical to local ones in the Agent Sessions list; there's no way to tell them apart before opening.

## Best solution

Add a host/authority indicator (label, icon, or description suffix) to workspaceless session rows in the sessions list renderer, likely in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts and the model built by sessionsListModelService.ts, sourced from the session's remote authority metadata.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/services/sessions/browser/sessionsListModelService.ts`, `src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts`
- **Validation:** A sessionsList component test asserting a workspaceless session created against a remote authority renders a distinguishable label/icon (e.g. host name) different from a local workspaceless session.
- **Behavior:**

  > When a workspaceless chat originates from a remote VS Code Server/tunnel connection, its entry in the Agent Sessions list should visibly differ from a local workspaceless chat entry — e.g. by showing the remote connection name or authority as part of the row's label/description. Local sessions are unaffected. Acceptance: a component test can distinguish rendered rows for local vs. remote workspaceless sessions by asserted text/icon.
- **Trace:**

  > The `workspaceless` boolean already exists on session metadata (readSessionWorkspaceless/withSessionWorkspaceless in src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts, lines ~244-321), but neither src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts nor sessionsListModelService.ts currently reads or renders any authority/remote-host context per row — confirmed via targeted grep across both files (no matches for 'authority', 'hostName', 'remoteAuthority'). The boundary: do not change how local sessions are grouped/labeled today, and don't touch the underlying workspaceless persistence logic — only add a display-time indicator. Where the uncertainty starts: whether the indicator is a label suffix, a separate description line, or an icon/badge, and which string source (remote label service vs. raw authority) to use — these are product/UI calls for a maintainer.
- **Open decisions:**
  - Should the remote indicator be a text label (e.g. connection/authority name) appended to the row, a separate description line, or an icon/badge?
  - Which string should represent the remote host — the user-facing remote connection name (via IRemoteAuthorityResolverService/label service) or the raw authority string?
  - Should this indicator also apply to non-workspaceless remote sessions, or is it scoped strictly to workspaceless chats as described in the issue?
