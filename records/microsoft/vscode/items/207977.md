# Issue #207977 — Split View does not account for 1px border

[https://github.com/microsoft/vscode/issues/207977](https://github.com/microsoft/vscode/issues/207977)

## Summary

The visual defect remains directly traceable on current main: the split-view separator is absolutely positioned inside the second view, allowing that view's content and active-state styling to overlap it. No open canonical issue or fixing commit was found, so this should remain open.

## Change summary

Split editor groups can display an inconsistent one-pixel divider because the split-view separator overlaps the second view's content area.

## Best solution

Make the generic SplitView separator occupy the boundary between adjacent views rather than the second view's content area, preserving consistent rendering for horizontal and vertical layouts without changing allocated view sizes.

## Evidence

- **current source:** src/vs/base/browser/ui/splitview/splitview.css positions the separator pseudo-element on each non-first `.split-view-view` at `top: 0; left: 0` with a 1px width or height and `z-index: 5`, placing it inside that view.
- **layout path:** src/vs/base/browser/ui/splitview/splitview.ts sets each HorizontalViewItem's `left` and full allocated `width`, and each VerticalViewItem's `top` and full allocated `height`; no space is reserved for the separator.
- **confirmed diagnosis:** The maintainer comment at https://github.com/microsoft/vscode/issues/207977#issuecomment-2003210632 confirms the problem on web and desktop and identifies the same absolute-positioning overlap.
