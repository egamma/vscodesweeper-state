# Issue #332326 — Terminal: dead-key shortcut no longer fires when terminal is focused (regression in 1.132.0)

[https://github.com/microsoft/vscode/issues/332326](https://github.com/microsoft/vscode/issues/332326)

## Summary

Traced conclusively in current main: dead-key keydowns are normalized to KEY_IN_COMPOSITION in keyboardEvent.ts, and abstractKeybindingService.softDispatch() (used by terminalInstance.ts) treats any KEY_IN_COMPOSITION event as IME-owned and bails out before resolving the keybinding, so the accent character leaks into the shell instead of firing the command. Real regression, worth routing to the terminal/keybindings owners; not confident enough yet to fold into the Linux report as a verified duplicate given the differing regression version.

## Change summary

On macOS with a dead-key keyboard layout, a keybinding whose chord includes a dead-key character (e.g. cmd+shift+´ for Create Terminal) no longer fires when the terminal is focused; the raw accent is inserted into the shell instead, since 1.132.0.

## Best solution

In src/vs/platform/keybinding/common/abstractKeybindingService.ts (softDispatch) and/or src/vs/base/browser/keyboardEvent.ts, distinguish a single dead-key accent keystroke (which never opens a real multi-candidate IME session) from genuine multi-key IME composition, so the terminal can still claim keybindings for the former; this needs a maintainer/terminal-team decision on how to detect that distinction safely across platforms before any fix lands.

## Evidence

- **composition normalization:** src/vs/base/browser/keyboardEvent.ts:162 sets `this.keyCode = e.isComposing ? KeyCode.KEY_IN_COMPOSITION : extractKeyCode(e)` — any composing keydown, including a macOS dead-key press, becomes KEY_IN_COMPOSITION.
- **soft dispatch bails on composition:** src/vs/platform/keybinding/common/abstractKeybindingService.ts:151-157 — `if (isKeyInComposition(e)) { ...; return NoMatchingKb; }`, matching the reporter's troubleshooting log line "Keyboard event is part of an IME composition".
- **terminal calls softDispatch:** src/vs/workbench/contrib/terminal/browser/terminalInstance.ts:1150 calls `this._keybindingService.softDispatch(standardKeyboardEvent, ...)`, so a dead-key keydown while terminal-focused is dropped there and the character is written to the shell instead.
- **related report, different platform/version:** https://github.com/microsoft/vscode/issues/282752 ("Shortcuts with dead keys broken in Linux since 1.107.0") is already labeled bug/upstream/keybindings/regression by the team and describes the same symptom (dead-key backtick breaks the Create Terminal shortcut), but its regression window (1.107.0, Linux) differs from this report's (1.132.0, macOS), so I'm not confident enough to assert they share one exact root cause without maintainer input.
