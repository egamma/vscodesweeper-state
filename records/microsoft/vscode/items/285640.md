# Issue #285640 — Terminal suggest doesn't get content from the actual terminal session.

[https://github.com/microsoft/vscode/issues/285640](https://github.com/microsoft/vscode/issues/285640)

## Summary

Keep this accepted Backlog request open: current terminal suggestions still discover PowerShell commands in a separate process, so functions created in the active session remain unavailable. The request has 21 upvotes and maintainer interest; no verified older canonical covers the same observable limitation.

## Change summary

Include functions created in the active PowerShell session in terminal suggestions without requiring users to dismiss or disable the suggestion widget.

## Best solution

Provide session-aware PowerShell function suggestions while retaining client-side filtering and avoiding the large completion transfers that previously stalled PowerShell. Plan the shell-to-suggestion data flow and its performance validation before implementation.

## Plan brief

- **Likely files:** `extensions/terminal-suggest/src/terminalSuggestMain.ts`, `extensions/terminal-suggest/src/shell/pwsh.ts`, `extensions/terminal-suggest/src/shell/common.ts`, `src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1`
- **Validation:** In a PowerShell terminal with terminal suggestions enabled, execute `function Invoke-SweeperSessionProbe { 'ok' }`, type `Invoke-SweeperSession`, and explicitly invoke terminal suggestions. Verify the function appears, Tab accepts its name, and executing it prints `ok`; repeat after suggestions have already populated. Repeat with many existing commands while checking prompt responsiveness and update cost, and verify existing executable, file, and argument suggestions remain functional.
- **Behavior:**

  > Terminal suggestions should include a PowerShell function created in the active terminal session, including one defined after the suggestion list has already been populated. Users should be able to select and execute that function without first dismissing or disabling terminal suggestions. The terminal must remain responsive when the shell already exposes thousands of commands. Existing executable, file, and argument suggestions must continue to work.
- **Trace:**

  > In extensions/terminal-suggest/src/terminalSuggestMain.ts, provideTerminalCompletions combines PATH executables with getShellGlobals results; the globals cache identifies a machine, remote authority, and shell type, not an individual session. getPwshGlobals/getCommands in extensions/terminal-suggest/src/shell/pwsh.ts runs Get-Command through execHelper in extensions/terminal-suggest/src/shell/common.ts, which launches a separate process and cannot observe functions defined in the existing terminal. Global:Prompt in src/vs/workbench/contrib/terminal/common/scripts/shellIntegration.ps1 currently reports cwd and selected environment variables, with no function reporting path. Clearing cached globals therefore does not address this request. https://github.com/microsoft/vscode/issues/285640#issuecomment-3704963389 establishes the performance boundary: retain client-side filtering and avoid repeating the large completion transfers that stalled PowerShell. The trace establishes the missing capability, but the transport, receiving consumers, and measurable performance budget still need investigation during planning; unrelated history suggestions, snippets, and keybinding changes are outside this request.

## Evidence

This supports an enhancement rather than reclassifying the intentional limitation as a bug.
- **Current command discovery:** extensions/terminal-suggest/src/terminalSuggestMain.ts:85–175 obtains shell globals through getShellGlobals/fetchAndCacheShellGlobals, using a cache keyed by machine, remote authority, and shell type rather than terminal session. extensions/terminal-suggest/src/shell/pwsh.ts:getPwshGlobals/getCommands enumerates Get-Command through execHelper; extensions/terminal-suggest/src/shell/common.ts:execHelper calls node:child_process.exec. Functions defined only in the existing terminal process cannot be discovered by that separate PowerShell process.
