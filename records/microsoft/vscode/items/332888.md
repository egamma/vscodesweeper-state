# Issue #332888 — Support Ctrl+scroll wheel zoom for text in the Markdown preview

[https://github.com/microsoft/vscode/issues/332888](https://github.com/microsoft/vscode/issues/332888)

## Summary

Preview-only font sizing already exists through markdown.preview.fontSize, but the requested Ctrl+wheel interaction remains missing. Keep this accessibility-oriented request open; neither the newer WYSIWYG request nor historical backlog closures establishes a valid duplicate or scope-based close.

## Change summary

Allow Ctrl+mouse wheel to resize Markdown preview text without changing the rest of the window.

## Best solution

Provide a consistent preview-local text zoom interaction in the built-in Markdown extension, preserving normal scrolling and independent window zoom. Decide its enablement and persistence semantics before implementation; markdown.preview.fontSize remains an available settings-based workaround.

Verify ordinary wheel scrolling remains unchanged, existing diagram gestures still work, and preview refresh, reopening, and multiple previews follow the agreed persistence semantics.
- **Behavior:**

  > Users need a quick mouse gesture to enlarge or reduce rendered Markdown preview text independently of the surrounding workbench. Ctrl+wheel over preview prose should adjust its text size, while ordinary scrolling and existing diagram interactions retain their behavior. Acceptance includes independent source-editor and workbench sizing, plus explicitly agreed behavior across preview refresh, reopening, and multiple previews. This request does not include the WYSIWYG editor.
- **Trace:**

  > The existing font-size path starts at markdown.preview.fontSize in extensions/markdown-language-features/package.json, is read by MarkdownPreviewConfiguration in src/preview/previewConfig.ts, and is emitted by documentRenderer.ts through #getSettingsOverrideStyles as --markdown-font-size. media/markdown.css applies that variable to preview text. preview-src/index.ts owns preview interaction and saved scroll state, but contains no wheel-based text zoom path. This was established through read-only source inspection, not runtime execution. Preserve window zoom, source-editor sizing, normal scrolling, and diagram-specific gestures. https://github.com/microsoft/vscode/issues/332889 covers a newer, distinct editing surface; https://github.com/microsoft/vscode/issues/10011 is the historical same-gesture request closed for backlog traction rather than a substantive scope decision.
- **Open decisions:**
  - Should preview Ctrl+wheel follow editor.mouseWheelZoom, have independent opt-in behavior, or be enabled by default?
  - Should the adjustment be local to each preview, persist per document, or update markdown.preview.fontSize and therefore affect other previews in that configuration scope?
