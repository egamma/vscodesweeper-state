# Issue #332560 — Code Agent Host client protocol and server protocol version mismatch (0.7.0 vs ^0.8.0)

[https://github.com/microsoft/vscode/issues/332560](https://github.com/microsoft/vscode/issues/332560)

## Summary

A VS Code collaborator already flagged this as a duplicate of #326440, and the report is the same recurring bug class (published CLI's advertised AHP protocol version lags the auto-updated Agent Host's accepted version, causing the initialize handshake to fail) — just observed at a later version pairing (0.7.0 vs 0.8.0/1.0.0 instead of 0.4.0 vs 0.6.0).

## Change summary

The `code agent ps`/`code agent host` CLI fails with an AHP initialize "-32005" protocol mismatch because the installed CLI's advertised protocol version (0.7.0) is older than the auto-updated Agent Host server's accepted version (^0.8.0, later ^1.0.0).

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/326440, which tracks the same root cause: CLI and Agent Host protocol versions drift apart during rollout because the two are not published atomically. The current main registry (`src/vs/platform/agentHost/common/state/protocol/version/registry.ts`) already keeps a fallback `SUPPORTED_PROTOCOL_VERSIONS` list (1.0.0 down to 0.5.1) which is the direction any real fix should extend, but that belongs on the canonical issue's thread.
