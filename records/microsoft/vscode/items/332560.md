# Issue #332560 — Code Agent Host client protocol and server protocol version mismatch (0.7.0 vs ^0.8.0)

[https://github.com/microsoft/vscode/issues/332560](https://github.com/microsoft/vscode/issues/332560)

## Summary

Verified duplicate of an older, better-diagnosed open issue tracking the same package-parity defect: the bundled `code agent` CLI stays pinned to an older AHP version while the bundled Agent Host server advances, so a build's own management CLI can't talk to its own server.

## Change summary

`code agent ps`/`code agent host` fail with an AHP protocol-version mismatch because the CLI (0.7.0) and the Agent Host server (0.8.0, now 1.0.0 on main) are out of sync even within the same VS Code build.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/326440 (assigned to a maintainer) — the durable fix is keeping the bundled Rust CLI's `ahp`/`ahp-types` crate pins (currently 0.7.0 in cli/Cargo.toml) in lockstep with the Agent Host protocol registry, and having the CLI offer the SDK's full supported-version list at initialize instead of a single version.

- **recurrence pattern:** #326440's comments trace this across three separate protocol bumps (0.6.0, 0.8.0, and now 1.0.0 per PR https://github.com/microsoft/vscode/pull/331999), matching #332560's own escalation from 0.8.0 to 1.0.0 in its second comment — same root cause, not a one-off.
