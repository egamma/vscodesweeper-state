# Issue #340112 — Git: kill() of a failed git spawn sends SIGTERM to the whole VS Code process group (macOS, deleted worktree)

[https://github.com/microsoft/vscode/issues/340112](https://github.com/microsoft/vscode/issues/340112)

## Summary

Confirmed in source: every `child.kill()` call site in extensions/git/src/git.ts (lines ~258, 1691, 2847, 2872) calls kill() unconditionally after spawn, with no guard for a child whose pid was never assigned (failed spawn, e.g. ENOENT from a deleted cwd). The reporter traced this precisely to an Electron utility-process quirk where kill() on such a child becomes kill(0), SIGTERM'ing the whole VS Code process group, and provided a minimal Electron-only repro confirming plain Node does not do this.

## Change summary

On macOS, deleting a git worktree and then triggering a Source Control git spawn that fails before `error` is handled causes the extension host's kill() call to SIGTERM the entire VS Code process group, killing all windows.

## Best solution

Guard against killing a child with no pid in extensions/git/src/git.ts — ideally centralized in the `Git.spawn()` wrapper (or `stream()`) so all four kill() call sites are covered by one fix, e.g. only calling kill() when `child.pid !== undefined`. The Electron-level kill(0) behavior for pid-less children in utility processes is a separate, deeper issue that should also be reported to Electron, but the extension-side guard fully prevents the crash regardless of root cause.
