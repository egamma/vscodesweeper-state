# Issue #335885 — Voice mode responses are sometimes not read aloud on insiders.vscode.dev

[https://github.com/microsoft/vscode/issues/335885](https://github.com/microsoft/vscode/issues/335885)

## Summary

Team-authored bug with a real version milestone (1.141.0) assigned — hard keep-open rule applies. A linked fix PR (#335886) targeted exactly the described context-key mismatch but was closed without merging, so the underlying gap remains on main; also, the PR's own description flags that the actual audio-readback failure (vs. just the button UI) may have a separate, unconfirmed mobile-browser audio-lifecycle cause.

## Change summary

Voice mode's segmented control sometimes shows a disconnected/inactive state (and skips reading responses aloud) while the underlying voice session is still active, especially on insiders.vscode.dev via mobile browsers.

## Best solution

Land a fix (or a revised version of the closed #335886 approach) so `SegmentedVoiceInputModePillActive`/the connected context key account for the reconnecting state, and separately investigate whether mobile browser audio autoplay/lifecycle restrictions are independently suppressing readback.
