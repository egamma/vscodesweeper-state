# Issue #335885 — Voice mode responses are sometimes not read aloud on insiders.vscode.dev

[https://github.com/microsoft/vscode/issues/335885](https://github.com/microsoft/vscode/issues/335885)

## Summary

Confirmed on main: `SegmentedVoiceInputModePillActive` in voiceInputModeContextKeys.ts is gated only on `AGENTS_VOICE_CONNECTED`, with no term for `AGENTS_VOICE_RECONNECTING`, so the pill (and whatever reads off it) reports an inactive/disconnected state during a transient reconnect even though voice mode never deactivated — this matches the reported symptom exactly. The one PR that attempted this fix (https://github.com/microsoft/vscode/pull/335886) was closed without merging, so the gap remains open.

## Change summary

Voice-mode buttons sometimes show as deactivated, and chat responses are sometimes not read aloud, while voice mode is still logically active (observed on insiders.vscode.dev, notably on mobile).

## Best solution

Extend `SegmentedVoiceInputModePillActive` (src/vs/workbench/contrib/chat/browser/voiceInputMode/voiceInputModeContextKeys.ts) to treat `AGENTS_VOICE_RECONNECTING` the same as connected/connecting, mirroring how voiceInputModeActionViewItem.ts already folds `isReconnecting` into its `connecting`/`voiceOn` computation — then re-open or re-submit a version of PR #335886's test coverage.
