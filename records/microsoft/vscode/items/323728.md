# Issue #323728 — slash command blocks input - Copilot Chat with Agent Host, Claude Agent SDK

[https://github.com/microsoft/vscode/issues/323728](https://github.com/microsoft/vscode/issues/323728)

## Summary

The Agent Host slash command defect is confirmed, and the maintainer discussion establishes that built-in Claude skills are represented with nonexistent resources that the prompt resolution path then tries to read. The issue should remain open while maintainers decide whether built-ins should leave the customization API or gain a new resource-free representation.

## Change summary

Sending `/code-review` as the entire Copilot Chat input with Claude Agent SDK is blocked because VS Code tries to read a nonexistent resource for the built-in skill.

## Best solution

Ensure built-in Agent Host skills can participate in slash-command completion and invocation without requiring a file-backed customization resource, while preserving correct presentation in the customization UI.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotSlashCommandCompletionProvider.ts`
- **Validation:** Add an Agent Host chat test that provides a resource-free built-in `code-review` skill, sends `/code-review` as the complete prompt, and verifies that submission succeeds without any file read for `vscode-agent-host://local/skill/code-review`; also verify the chosen completion and customization-UI behavior.
- **Behavior:**

  > With Claude Agent SDK selected, entering a built-in skill such as `/code-review` as the entire chat input must submit and invoke the skill rather than leaving the input blocked. No attempt may be made to read a nonexistent file-backed resource for that built-in skill. Slash-command completion must continue to offer the skill, and its highlighting/customization-UI visibility must follow the maintainer-selected contract.
- **Trace:**

  > The confirmed failure reaches `resolvePromptSlashCommand`, which reads the synthetic `vscode-agent-host://local/skill/code-review` URI and fails because Claude's built-in skill has no underlying file. The maintainer discussion identifies the current boundary: the customization API assumes every customization and container has a resource, while `src/vs/platform/agentHost/node/copilot/copilotSlashCommandCompletionProvider.ts` offers a resource-independent completion path. Keep ordinary resource-backed customizations and provider-owned on-demand loading unchanged. The uncertainty begins at whether built-in skills remain customizations with a new resource-free/in-memory API representation or are exposed only as completion-provider commands, which also determines customization UI and highlighting behavior.
- **Open decisions:**
  - Should provider-built-in skills be represented as resource-free or in-memory customizations, or exposed only through `IAgentHostCompletionItemProvider`?
  - If built-in skills are completion-only, should they remain visible in the customization UI and receive the same slash-command highlighting as resource-backed skills?

## Evidence

- **confirmed reproduction:** A VS Code member reproduced the failure and captured `Unable to resolve nonexistent file 'vscode-agent-host://local/skill/code-review?...'` while `resolvePromptSlashCommand` handled an input consisting only of `/code-review`.
- **root cause:** https://github.com/microsoft/vscode/issues/323728#issuecomment-4879983194 confirms that `code-review` is a built-in Claude skill with no underlying resource, while the current customization API assumes resource-backed customizations and containers.
- **open product contract:** The maintainer thread records two observably different directions: expose built-in skills only through `IAgentHostCompletionItemProvider`, which excludes them from customization-based highlighting/UI, or extend the customization API to represent built-in or in-memory skills without file resources.
