# Issue #191053 — Multiple untitled notebook editors with same name but different associated path do not distinguish

[https://github.com/microsoft/vscode/issues/191053](https://github.com/microsoft/vscode/issues/191053)

## Summary

Still reproduces on main: the `getDescription` method in `NotebookEditorInput` returns `undefined` for untitled notebooks with associated file paths when the model hasn't resolved yet, because it depends on `editorModelReference?.object.hasAssociatedFilePath()` which is `undefined` before resolution.

## Change summary

Opening multiple untitled notebooks with same name but different associated paths (e.g., `code ~/foo/new.ipynb ~/bar/new.ipynb`) shows identical tab labels without distinguishing descriptions until the inactive tab is clicked.

## Best solution

In `NotebookEditorInput.getDescription()`, fall back to checking `this.preferredResource` when `editorModelReference` is not yet resolved — if the preferred resource scheme differs from `untitled`, it has an associated path and should delegate to `super.getDescription()`. This avoids the race with model resolution.
