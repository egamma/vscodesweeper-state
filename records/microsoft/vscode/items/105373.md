# Issue #105373 — Allow snippets to target standard token types

[https://github.com/microsoft/vscode/issues/105373](https://github.com/microsoft/vscode/issues/105373)

## Summary

Keep open: snippets still cannot declare which standard token types they target. Existing suggestion settings do not cover the per-snippet capability proposed in the maintainer discussion, and no verified older canonical was found.

## Change summary

Allow snippet definitions to restrict availability by standard token type, such as excluding comments and strings while retaining suggestions in code.

## Best solution

Provide opt-in token-type targeting in snippet definitions, preserving existing behavior for definitions without restrictions. Settle whether those restrictions govern only IntelliSense or also explicit snippet insertion and tab completion before implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts`, `src/vs/workbench/contrib/snippets/browser/snippetsFile.ts`, `src/vs/workbench/contrib/snippets/browser/snippetCompletionProvider.ts`, `src/vs/workbench/contrib/snippets/browser/tabCompletion.ts`, `src/vs/workbench/contrib/snippets/test/browser/snippetFile.test.ts`, `src/vs/workbench/contrib/snippets/test/browser/snippetsService.test.ts`
- **Validation:** Extend snippet-file parsing and SnippetsService completion tests to cover token-restricted and unrestricted definitions across comment, string, regex, and ordinary-code tokens, including CompletionTriggerKind.TriggerCharacter with a .hasownprop prefix. Manually verify in JavaScript that a restricted snippet does not appear after typing a period inside an excluded comment/string but remains available in allowed code; verify explicit invocation and tab completion against the agreed contract. No tests were executed during this read-only review.
- **Behavior:**

  > Users should be able to declare the standard token contexts in which an individual snippet is available. A snippet excluded from comments or strings should not appear there merely because its prefix starts with a trigger character such as a period, while it should remain available in permitted contexts. Snippets without restrictions should retain their existing behavior, and unrelated language completions should remain unchanged. Acceptance must cover the token categories and the agreed behavior for manual IntelliSense, explicit insertion, and tab completion.
- **Trace:**

  > The supplied maintainer discussion at https://github.com/microsoft/vscode/issues/105373 confirms the original trigger-character behavior and proposes token-type targeting as a new capability. Current snippets.contribution.ts and snippetsFile.ts expose language and file targeting but no standard-token targeting. SnippetCompletionProvider.provideCompletionItems matches prefixes without token eligibility, while SuggestModel._updateTriggerCharacters includes snippet support independently of the quick-suggestion token checks. TabCompletionController in tabCompletion.ts is a separate language/resource-and-prefix consumer. Existing SnippetsService tests construct models and call the completion provider, providing a focused validation surface. Preserve unrestricted snippets and the broader trigger-character policy; the uncertainty is the user-visible definition contract and whether explicit snippet actions obey the same restrictions.
- **Open decisions:**
  - Should snippet definitions express allowed token types, excluded token types, or both, and what serialized property names form that public contract?
  - Should token-type restrictions apply only to IntelliSense suggestions, or also to explicit Insert Snippet and tab completion?

## Evidence

- **Maintainer diagnosis and accepted direction:** In the supplied discussion for https://github.com/microsoft/vscode/issues/105373, jrieken confirmed reproduction, explained that trigger characters override quick-suggestion suppression, and proposed extending snippets to enumerate standard token types. The reporter accepted that direction and subsequently reported the same interference inside strings.
- **Existing capability check:** src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts defines snippet properties for prefix, body, description, file templates, and file include/exclude patterns; global scope names languages, not token types. src/vs/workbench/contrib/snippets/browser/snippetsFile.ts likewise has no token-type field in JsonSerializedSnippet or Snippet.
- **Current completion path:** SnippetCompletionProvider.provideCompletionItems in src/vs/workbench/contrib/snippets/browser/snippetCompletionProvider.ts selects snippets by language/resource and matches prefixes, including trigger-character prefixes, without checking the standard token type. _getLanguageIdAtPosition tokenizes for language selection, not comment/string eligibility.
- **Settings are partial workarounds:** src/vs/editor/contrib/suggest/browser/suggestModel.ts applies standard-token checks in the quick-suggestion path, while _updateTriggerCharacters includes snippet support alongside language completion providers. In src/vs/editor/common/config/editorOptions.ts, editor.suggestOnTriggerCharacters disables trigger-character suggestions generally, and editor.suggest.showSnippets or editor.snippetSuggestions disables snippets generally; none provides per-snippet token targeting.
- **Related report is not a canonical:** https://github.com/microsoft/vscode/issues/185142 is closed and newer. Its discussion ultimately identifies Python triple-quoted docstrings as strings and accepts disabling quick suggestions in strings as a workaround; that does not implement token-type targeting for custom snippets.
- **Canonical search and precedent:** Open-issue searches for snippets with comments, strings, scope, and token types found no verified older issue owning this same request. https://github.com/microsoft/vscode/issues/37166 is closed and concerns snippets failing to appear after a dot, explaining the trigger-character history rather than providing a duplicate target.
- **Additional consumer boundary:** src/vs/workbench/contrib/snippets/browser/tabCompletion.ts retrieves snippets by language/resource and matches selected text or prefixes independently of SnippetCompletionProvider. Whether token restrictions apply to that explicit completion surface is not settled in the supplied discussion.
