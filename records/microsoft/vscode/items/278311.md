# Issue #278311 — Auto-indent mangles JSON files due to URL misinterpretation

[https://github.com/microsoft/vscode/issues/278311](https://github.com/microsoft/vscode/issues/278311)

## Summary

The reported URL-triggered comment insertion is fixed on current main: the JSON continuation rule now requires line-leading or whitespace-separated slashes, so it no longer matches https://example.com.

## Change summary

Pressing Enter inside an empty JSON object whose key is a URL incorrectly inserts a comment marker before the closing brace.

## Best solution

Close as completed by commit 9b43a71f039f715c06b2e8ed4a454be3591f5b40; current main retains its exclusion of URL slashes while preserving continuation of actual comments.

## Evidence

- **Exact trigger and fixing diff:** The reporter presses Enter between the braces in `"https://example.com": {}` and gets `// }`. https://github.com/microsoft/vscode/commit/9b43a71f039f715c06b2e8ed4a454be3591f5b40 changes extensions/json/language-configuration.json at the onEnterRules hunk beginning near line 69: beforeText changes from `\/\/.*` to `^\s*//|\s//\s`. The old expression matches the URL; neither alternative of the replacement matches slashes preceded by a colon.
- **Current-main source trace:** extensions/json/package.json registers extensions/json/language-configuration.json for JSON and JSONC. Tracing EnterOperation._enter in src/vs/editor/common/cursor/cursorTypeEditOperations.ts through getEnterAction and OnEnterSupport.onEnter shows that this rule cannot append `// ` for the supplied line. With editor.autoIndent set to none, _enter directly inserts a newline without consulting continuation rules. This was a source-only reproduction attempt; no editor execution or tests were run.
