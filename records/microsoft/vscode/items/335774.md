# Issue #335774 — Inline suggestions (ghost text) never trigger for documents from third-party FileSystemProvider schemes (e.g. Code for IBM i "member:" scheme)

[https://github.com/microsoft/vscode/issues/335774](https://github.com/microsoft/vscode/issues/335774)

## Summary

Plausible and well-diagnosed: Copilot's completions-core library hardcodes an allowlist of URI schemes it treats as real filesystem paths, which appears to be exactly what excludes third-party FileSystemProvider schemes like Code for IBM i's `member:` from ghost text — but this looks like a deliberate architectural constraint (the engine needs direct fs reads for ignore-list/git/related-files logic), not an oversight, so it's a feature/extensibility request rather than a plain bug.

## Change summary

Inline suggestions (ghost text) never fire for editable documents opened through third-party FileSystemProvider schemes (e.g. IBM i's `member:` scheme), even though the document is fully editable with a correct language ID.

## Best solution

Either extend the extension's internal scheme allowlist (extensions/copilot/src/extension/completions-core/vscode-node/lib/src/util/uri.ts, `fsSchemes` set) to cover more virtual-fs schemes, or design a documented opt-in path for third-party FileSystemProviders (and document the current limitation in the meantime) — this needs an explicit product/architecture decision from the Copilot completions team, not a mechanical patch.

- **internal scheme allowlist found:** extensions/copilot/src/extension/completions-core/vscode-node/lib/src/util/uri.ts:81 defines `const fsSchemes = new Set(['file', 'notebook', 'vscode-notebook', 'vscode-notebook-cell'])`, and `fsPath()` (line 90-92) throws `Copilot currently does not support URI with scheme: ${uri.scheme}` for anything else — this matches the reporter's own diagnosis almost exactly, though I could not fully trace whether/where this exception aborts the ghost-text request path for a `member:` document within this review.
