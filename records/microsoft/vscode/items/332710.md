# Issue #332710 — VSCode spawning whoami.exe triggers security alerts

[https://github.com/microsoft/vscode/issues/332710](https://github.com/microsoft/vscode/issues/332710)

## Summary

Confirmed on current main: `applyWindowsOwnerOnlyAcl` in the Agent Host metadata plumbing shells out to `whoami.exe` (and then `icacls.exe`) on every Windows launch with AI Chat/Agent Host features enabled, to look up the current user's SID before locking down the local endpoint metadata directory. In EDR/canary-token-monitored environments this is a legitimate false-positive trigger, but replacing it needs a maintainer decision on an alternative SID-lookup approach, not a mechanical patch.

## Change summary

Applying an owner-only ACL to the local Agent Host endpoint metadata requires the current user's SID, which is currently obtained by spawning whoami.exe (and icacls.exe) via child_process.execFile on every launch.

## Best solution

Investigate a way to obtain the current user's SID (and apply the restrictive ACL) without spawning whoami.exe/icacls.exe — e.g. a native Win32 binding (no such dependency exists in package.json today) or a Node API that avoids new process creation — in src/vs/platform/agentHost/node/localAgentHostMetadata.ts (`applyWindowsOwnerOnlyAcl`, `runWindowsCommand`). This needs a platform/security-team decision on whether to add a native dependency, not a quick swap.
