# Issue #332710 — VSCode spawning whoami.exe triggers security alerts

[https://github.com/microsoft/vscode/issues/332710](https://github.com/microsoft/vscode/issues/332710)

## Summary

Confirmed on current main: on Windows, preparing the local agent host endpoint directories always shells out to whoami.exe to fetch the current user's SID for an ACL, which is a legitimate-but-noisy pattern that trips EDR/canary-token detections in locked-down environments. Real, reproducible in source, but the right fix (an in-process way to get the SID) needs investigation, not a mechanical patch.

## Change summary

On Windows, VS Code spawns whoami.exe on every launch (when AI Chat/agent host features are active) to compute the current user's SID for locking down the agent host metadata directories, which triggers EDR/canary-token security alerts.

## Best solution

Replace the whoami.exe /user spawn in applyWindowsOwnerOnlyAcl (src/vs/platform/agentHost/node/localAgentHostMetadata.ts) with an in-process way to resolve the current user's SID — e.g. via the already-bundled @vscode/windows-registry native module or an equivalent Win32 token-info call — so the ACL can still be applied without spawning a monitored recon-flagged binary.
