# Issue #332710 — VSCode spawning whoami.exe triggers security alerts

[https://github.com/microsoft/vscode/issues/332710](https://github.com/microsoft/vscode/issues/332710)

## Summary

The Windows agent-host startup path still launches whoami.exe; the reporter confirmed the alerts persist in 1.134.0. Keep this security-sensitive improvement open for human review of a process-free alternative that preserves endpoint permissions.

## Change summary

Avoid spawning whoami.exe during Windows agent-host startup because it triggers security-monitoring alerts in sensitive environments.

## Best solution

Resolve the current Windows user's SID without a subprocess while preserving the local endpoint registry's existing access restrictions and explicit failure handling. The CLI's native Win32 implementation provides relevant precedent, but the editor's Node path does not use it.
