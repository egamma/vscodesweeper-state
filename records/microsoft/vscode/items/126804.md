# Issue #126804 — Using left/right arrow keys to jump between wrapped lines causes cursor to skip a character

[https://github.com/microsoft/vscode/issues/126804](https://github.com/microsoft/vscode/issues/126804)

## Summary

Keep open: the editor behavior is intentional today, but maintainers explicitly reopened this as a feature request and identified a possible single-cursor behavior change. Because the team-authored issue remains a product decision involving multicursor consistency, a judgment close is not appropriate.

## Change summary

Make horizontal cursor movement across wrapped-line boundaries stop at the visual wrap position for a single cursor while preserving predictable multicursor behavior.

## Best solution

Decide whether single-cursor navigation should expose both visual positions that map to the same model position, while continuing to skip that extra stop for multiple cursors and applying the same rule consistently to injected text.

## Plan brief

- **Likely files:** `src/vs/editor/common/controller/cursorCommon.ts`, `src/vs/editor/common/controller/cursorMoveCommands.ts`, `src/vs/editor/test/common/controller/cursorMoveCommand.test.ts`

- **Behavior:**

  > With a single cursor, horizontal arrow navigation across a soft-wrapped boundary should behave consistently regardless of which direction approaches the boundary, without appearing to skip a visual position. Multiple-cursor movement must remain deterministic and must not create ambiguous duplicate model positions. The agreed rule must also cover injected text and preserve ordinary movement on non-wrapped lines.
- **Trace:**

  > The issue discussion establishes that two visual positions at a wrap boundary map to one model position and that current horizontal movement deliberately skips the duplicate visual stop. Maintainers identified a possible split policy: retain skipping for multiple cursors, but expose the stop for a single cursor and use the same semantics for injected text. The likely path is the editor cursor movement/controller code and its movement tests; the uncertainty begins at defining the exact affinity and round-trip behavior when two view positions share one model position. Do not change model positions, whitespace content, or non-wrapped cursor semantics.
- **Open decisions:**
  - Should a single cursor retain visual affinity at both sides of a wrap boundary even though both positions map to the same model position?
  - Exactly when should multiple cursors skip the duplicate visual stop, including selections or cursors that collapse onto the same model position?
  - Should injected-text boundaries use precisely the same affinity and arrow-key rules as soft-wrap boundaries?
