# Issue #293630 — Option to remove/detach copilot chat window from sessions bar

[https://github.com/microsoft/vscode/issues/293630](https://github.com/microsoft/vscode/issues/293630)

## Summary

The central request remains a real gap on current main: Agent Sessions can be opened in editors or windows, but the sessions list is still hosted by the Chat view and cannot remain as an independent sidebar after that view is closed. This should stay open as a feature request for an explicit product decision.

## Change summary

Allow the Agent Sessions list to remain available independently of the Chat panel and preserve an explicitly selected editor or window location for sessions.

## Best solution

Provide an independently hosted Agent Sessions surface in the regular workbench, or otherwise let the Chat view's conversation surface be hidden while retaining its sessions list. Explicitly opening a session as an editor or separate window should also remain authoritative during subsequent interaction.

- **Reason:** Separating session navigation from conversation placement supports flexible workbench layouts for AI-assisted development without requiring another always-visible chat surface.

## Evidence

- **current configuration:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers `chat.viewSessions.enabled`, but its description only controls whether sessions appear within the Chat view; it does not provide an independent sessions host.
- **current sidebar implementation:** ShowAgentSessionsSidebar and HideAgentSessionsSidebar in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts only switch the AgentSessionsViewer orientation and resize the part containing ChatViewPane, so closing that Chat view still removes the sessions surface.
- **partial existing capability:** src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts provides `workbench.action.chat.openSessionInEditorGroup` and `workbench.action.chat.openSessionInNewWindow`, which cover moving an individual session but not retaining the sessions list independently of Chat.
- **default opening behavior:** openSessionDefault in src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsOpener.ts targets ChatViewPaneTarget unless an explicit side-by-side option is supplied, confirming that ordinary sessions-list activation remains coupled to the Chat view.
- **related discussion:** https://github.com/microsoft/vscode/issues/298639 requested an Agent Sessions sidebar alongside editor-hosted chat, but it was filed after this re-reviewed issue and closed with a resize workaround; it therefore cannot be the older canonical and does not fully satisfy the request for an independent sessions surface.
