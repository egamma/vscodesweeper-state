# Issue #342922 — Agents Window: support Compare Agents in Dev Containers

[https://github.com/microsoft/vscode/issues/342922](https://github.com/microsoft/vscode/issues/342922)

## Summary

Keep open: current source still intentionally excludes Dev Container comparisons, while the requested lifecycle integration remains missing. The merged Environment picker PR implements the interim safeguard, not this follow-up.

## Change summary

Support isolated Compare Agents runs in Dev Containers across attempts, Judge retries, synthesis, restoration, and cleanup.

## Best solution

Retain the current exclusion until isolation, evidence access, identity handoff, and failure recovery are supported end to end.

- **Behavior:**

  > A supported Dev Container comparison runs every attempt, Judge, retry, and synthesis participant with explicit container execution and independent worktree isolation. Container execution intent and participant configuration survive handoff and reload, and the Judge can inspect the correct attempt evidence. Unsupported combinations, including currently unsupported sample-worktree combinations, remain unavailable and fail explicitly without source-host or shared-folder fallback. Partial failures and cancellation preserve successful work and clean up resources according to existing lifecycle rules.
- **Trace:**

The remote provider specification documents an existing source-worktree-to-container handoff with provider-owned worktree handles and cleanup. The unresolved work spans execution-intent persistence, all participant creation paths, identity migration, and Judge evidence accessibility; the trace does not establish those cross-provider contracts as complete. Preserve existing non-container comparison behavior and the interim container rejection until support is complete. https://github.com/microsoft/vscode/pull/342686 deliberately leaves this integration to https://github.com/microsoft/vscode/issues/342922.
