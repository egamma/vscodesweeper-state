# Issue #93470 — Event for onWill|DidRename|Create|Delete should indicate what caused the event (explorer vs workspace edit)

[https://github.com/microsoft/vscode/issues/93470](https://github.com/microsoft/vscode/issues/93470)

## Summary

The API gap remains on current main: file-operation events expose affected files but not whether an operation came from the Explorer or a workspace edit. This older, broader issue is the best canonical item for that work.

## Change summary

Expose the origin of create, delete, and rename operations in workspace file-operation events.

## Best solution

Add stable source metadata to the file-operation event API and thread it through the working-copy, main-thread, and extension-host bridges, allowing extensions to avoid recursively handling operations caused by workspace edits.
