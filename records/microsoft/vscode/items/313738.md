# Issue #313738 — Agents new-chat input doesn't support `@` or `#` syntax

[https://github.com/microsoft/vscode/issues/313738](https://github.com/microsoft/vscode/issues/313738)

## Summary

The `#` portion is implemented on current main, but the Agents new-chat composer still lacks the regular Chat `@` completion path. This team-authored Backlog item should remain open while maintainers decide how much extension-provided chat functionality is available before a session starts.

## Change summary

Bring regular Chat-style `@` syntax support to the Agents Window new-chat input.

## Best solution

Provide applicable `@` completions in the Agents new-chat composer with behavior consistent with regular Chat, while keeping the adaptation Sessions-owned. First settle whether pre-session completion should activate and expose all extension-provided chat participants and global commands or a narrower set.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/newChatInput.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts`, `src/vs/sessions/contrib/chat/test/browser/newChatInput.test.ts`
- **Validation:** Add a Sessions completion test using a `sessionsChatInput` model that types `@`, verifies the approved participant/command suggestions, accepts one, and confirms existing `#` completion behavior remains unchanged.
- **Behavior:**

  > Typing `@` in the Agents Window new-chat input should offer the approved participant or command choices before the first message is sent, consistent with regular Chat. Selecting an entry should insert the expected syntax and preserve normal submission behavior. Existing slash commands and `#` file, folder, session, and agent-host completions must remain unchanged. Acceptance should cover triggering, filtering, and accepting an `@` suggestion in a `sessionsChatInput` model.
- **Trace:**

  > NewChatInputWidget in src/vs/sessions/contrib/chat/browser/newChatInput.ts owns a Monaco model using the `sessionsChatInput` scheme and explicitly installs each completion handler. Current main installs slash, `#`, session-reference, and agent-host handlers but no regular Chat agent handler. Regular Chat's `@` providers live in src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts and depend on an existing `IChatWidget` and view model, which the pre-session composer does not have. The issue discussion confirms that exposing `@` also crosses into extension-provided language/chat features. Keep the adaptation Sessions-owned and do not regress the existing provider-neutral completion paths; uncertainty begins at which extension-provided entries should exist before session creation.
- **Open decisions:**
  - Which regular-Chat `@` entries should be available before an Agents session exists: extension-provided chat participants, global commands, or both?
  - Should opening `@` completions activate the required extension-provided chat features in the Agents Window, or should the pre-session list be limited to entries already available without that activation?

## Evidence

- **remaining gap on main:** src/vs/sessions/contrib/chat/browser/newChatInput.ts creates a `sessionsChatInput` model and registers slash, `#file`/folder, `#session`, and agent-host completion handlers around lines 1085 and 1247-1262, but it registers no regular Chat `@` participant completion handler.
- **regular Chat implementation:** src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputCompletions.ts registers providers triggered by `chatAgentLeader` (`@`) and resolves suggestions through `IChatWidgetService`, `IChatAgentService`, and the widget view model. That widget-bound path does not serve the Sessions pre-session input.

- **hash support:** The earlier `#` request https://github.com/microsoft/vscode/issues/299057 is closed and verified; current main also contains `VariableCompletionHandler` and `SessionReferenceCompletionHandler` for the Sessions new-chat input.
