# Issue #249974 — [Feature Request] Support for Multiple Changelists like IntelliJ IDEs

[https://github.com/microsoft/vscode/issues/249974](https://github.com/microsoft/vscode/issues/249974)

## Summary

Keep this accepted Git feature request open: named, independently committable changelists remain missing, and the request has 98 upvotes plus maintainer interest. Existing staging commands provide selective commits, but not multiple visible working-directory change groups.

## Change summary

Support multiple named changelists in Source Control, with movable changes and independent commits while retaining all changes in one working directory.

## Best solution

Design named change groups in the built-in Git provider that remain visible together and support committing one group without including another. Settle membership granularity and persistence semantics before implementation, preserving ordinary staging and Git's single-index behavior.

- **Behavior:**

  > Users need several named changelists in the Source Control view for independent tasks within one branch and working directory. They can create lists, move changes between them, and see the lists together without stashing or creating worktrees. Committing one list must exclude changes belonging to other lists and leave those edits available in the working directory. Acceptance must cover list creation and movement, simultaneous visibility, commit isolation, and compatibility with existing staging; granularity and reload behavior need a maintainer decision.
