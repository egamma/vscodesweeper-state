# Issue #323167 — Memory tool corrupts files via recursive self-duplication (str_replace/insert re-injects the entire file body many times)

[https://github.com/microsoft/vscode/issues/323167](https://github.com/microsoft/vscode/issues/323167)

## Summary

The corruption remains source-reproducible on current main: memory str_replace interprets dollar replacement tokens instead of writing the supplied text verbatim. An independent commenter confirms the exact minimal trigger; keep this issue open for a bounded fix.

## Change summary

Memory str_replace silently corrupts stored content when replacement text contains JavaScript dollar replacement tokens.

## Best solution

Make memory str_replace preserve replacement text literally while retaining its unique-match requirement, with regression checks against the persisted file contents. Keep insert/create behavior and memory-loading policy unchanged; the inspected insert/create paths do not share this replacement-token defect.
