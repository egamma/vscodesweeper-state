# Issue #323167 — Memory tool corrupts files via recursive self-duplication (str_replace/insert re-injects the entire file body many times)

[https://github.com/microsoft/vscode/issues/323167](https://github.com/microsoft/vscode/issues/323167)

## Summary

Confirmed on current main: the memory tool's str_replace passes user content directly as the replacement argument to String.prototype.replace(), causing `$`-sequences in new_str to be interpreted as replacement tokens (e.g. `$\`` expands to pre-match text). This corrupts memory files containing dollar signs.

## Change summary

The memory tool's str_replace command corrupts files when new_str contains `$` characters, because JavaScript's replace() interprets `$`-sequences as special replacement tokens.

## Best solution

Fix line 628 of extensions/copilot/src/extension/tools/node/memoryTool.tsx to use a function replacer (`content.replace(params.old_str, () => params.new_str)`) which treats the replacement as a literal string, bypassing `$`-token interpretation.
