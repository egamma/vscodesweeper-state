# Issue #339399 — Agents window: clarify sessionEnd lifecycle when it fires after every completed Copilot turn

[https://github.com/microsoft/vscode/issues/339399](https://github.com/microsoft/vscode/issues/339399)

## Summary

Team-authored investigation into Agent Host's sessionEnd lifecycle; VS Code's own code (copilotPluginConverters.ts) is a thin passthrough to the Copilot SDK's onSessionEnd hook, and the per-turn firing pattern appears to originate in the bundled copilot-runtime/Copilot SDK rather than in VS Code's orchestration — stays open pending upstream clarification or a VS Code-side decision on how to interpret/forward the event.

## Change summary

Clarify why Agent Host's sessionEnd fires after every completed Copilot turn instead of only at actual session close, and whether workspace hooks need a different signal for true end-of-conversation cleanup.

## Best solution

Pin down with the Copilot SDK/copilot-runtime team whether per-turn sessionEnd is intentional for hosted execution; if confirmed as an SDK quirk, VS Code's copilotPluginConverters.ts (onSessionEnd handling) may need to filter or relabel the event, or Agent Host may need to document/expose a distinct end-of-conversation signal for hook authors.
