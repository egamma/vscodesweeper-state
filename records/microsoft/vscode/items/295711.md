# Issue #295711 — Clone Repository button is not showing in New Window

[https://github.com/microsoft/vscode/issues/295711](https://github.com/microsoft/vscode/issues/295711)

Keep open: another reporter confirmed the same missing Explorer button with Copilot Chat enabled, and the source explains how unexpected repository registration hides it. The related report is newer, so it cannot replace this re-reviewed issue as the canonical.

## Change summary

Opening a new empty window briefly shows and then hides Clone Repository while Git unexpectedly discovers a repository from another window.

## Best solution

## Evidence

- **Reported regression:** https://github.com/microsoft/vscode/issues/295711 describes Windows 11 with 1.110.0-insider: File > New Window makes Clone Repository appear briefly and disappear. The reporter confirms that the same workflow works in stable 1.109.4; the Insiders Git log starts with zero repositories and subsequently opens the previous window's repository.
- **Independent confirmation:** https://github.com/microsoft/vscode/issues/299706 is open and independently reports that enabling Copilot Chat removes Clone Repository from Explorer, while disabling it restores the button. https://github.com/microsoft/vscode/issues/299706#issuecomment-4092634325 confirms persistence in VS Code 1.112.0 with Copilot Chat 0.40.1. These are historical confirmed reproductions, not an executed check of current main.
- **Current visibility condition:** extensions/git/package.json:4377-4386 contributes Explorer's Clone Repository and learn-more content only when config.git.enabled && git.state == initialized && scm.providerCount == 0. Registering an SCM provider therefore removes this entry point even when the window has no workspace folder.
- **Discovery boundary:** extensions/git/src/model.ts, Model.onDidChangeVisibleTextEditors, can discover repositories from visible file editors independently of workspace folders. extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts, GitServiceImpl._getRepository, can explicitly call gitAPI.openRepository(uri) when forceOpen is true. These are relevant paths, but inspection did not establish which caller supplies the unrelated repository in this report.
