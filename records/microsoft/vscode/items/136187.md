# Issue #136187 — Extension provided tasks are not recognized in workspace settings file only in .vscode/launch.json (for instance)

[https://github.com/microsoft/vscode/issues/136187](https://github.com/microsoft/vscode/issues/136187)

## Summary

Verified duplicate of the older open issue tracking the same observable failure: a launch configuration in a `.code-workspace` file cannot resolve an extension-provided pre-launch task. The canonical issue fully owns the required workspace-to-folder task resolution work.

## Change summary

Allow debug configurations stored in a workspace file to resolve extension-provided tasks referenced by `preLaunchTask`.

## Best solution

Consolidate the task-scope design and implementation in https://github.com/microsoft/vscode/issues/93149, including this report's direct extension-provided-task case.

## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/93149 is open, predates this report, and describes the same user-visible symptom: a `preLaunchTask` in a `.code-workspace` launch configuration cannot find an extension-defined task.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/93149#issuecomment-602477170 explains that extension-defined task types need folder context that workspace-file configurations do not currently provide.
- **current source:** On current main, `WorkspaceLaunch.workspace` remains undefined in src/vs/workbench/contrib/debug/browser/debugConfigurationManager.ts, so src/vs/workbench/contrib/debug/browser/debugService.ts passes the whole `IWorkspace` to `DebugTaskRunner.runTaskAndCheckErrors`. In src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts, `getTask` filters contributed tasks by an exact workspace-folder key, leaving folder-scoped extension tasks unmatched when the requested scope is the workspace.
- **corroborating report:** https://github.com/microsoft/vscode-remote-release/issues/6015 records the same failure for a launch configuration supplied through machine settings and explicitly links this issue as the corresponding core bug.
