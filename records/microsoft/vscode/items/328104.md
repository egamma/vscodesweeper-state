# Issue #328104 — Claude: forking a chat silently drops the source provider context

[https://github.com/microsoft/vscode/issues/328104](https://github.com/microsoft/vscode/issues/328104)

## Summary

Keep open and classify as a bug: current Claude anchor resolution still confuses client-assigned turn IDs with SDK envelope UUIDs, allowing a fork to succeed without inherited provider history. The merged related PR corrected documentation, not behavior.

## Change summary

Claude chat forks should preserve the selected source conversation's provider context rather than silently start a fresh conversation.

## Best solution

Make Claude provider-backed forks honor valid client-assigned source turn IDs while preserving the existing behavior for genuinely unknown turns and side-chat history visibility. Successful creation must not conceal failure to inherit required source context.
