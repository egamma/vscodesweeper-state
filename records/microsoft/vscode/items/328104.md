# Issue #328104 — Claude: forking a chat silently drops the source provider context

[https://github.com/microsoft/vscode/issues/328104](https://github.com/microsoft/vscode/issues/328104)

## Summary

Confirmed Claude-specific fork defect: client-assigned AHP turn IDs can fail anchor resolution, silently creating a fresh chat without inherited provider context. The merged related PR documents the defect but explicitly does not fix it.

## Change summary

Preserve Claude provider history when forking or creating a side chat from a client-assigned turn ID, or fail explicitly when the anchor cannot be resolved.

## Best solution

Maintain a reliable mapping from AHP turn IDs to persisted Claude SDK envelope UUIDs, use it for fork, side-chat, and truncation anchors, and replace the fresh-chat fallback with an explicit error for unresolved requested forks. Enable the existing Claude fork E2E gate once inherited user and assistant history reaches the model request.
