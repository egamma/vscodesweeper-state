# Issue #331073 — VS Code Portable - GitHub Copilot SKILLS: SKILLS dialogue & user generated SKILLS ignores `COPILOT_HOME` (`.copilot/`) env variable

[https://github.com/microsoft/vscode/issues/331073](https://github.com/microsoft/vscode/issues/331073)

## Summary

Confirmed in source: the AI Customization 'Skills' scanner (and agents/instructions/hooks scanning under `~/.copilot/*`) always joins against the OS-level `_userHome`, never the `COPILOT_HOME`-aware path — so portable installs setting `COPILOT_HOME` don't get their user-level customizations picked up by this scan, even though `#314917` added `COPILOT_HOME` support for CLI session state elsewhere.

## Change summary

User-level Skills (and agents/instructions/hooks) discovery ignores the `COPILOT_HOME` environment variable and always scans `<OS home>/.copilot/...` instead of the configured Copilot home.

## Best solution

In `src/vs/platform/agentHost/node/copilot/sessionCustomizationDiscovery.ts`, the `.copilot`-prefixed entries in `searchRoots.user` / `fixedDiscoveryFiles.user` are always joined onto `this._userHome` (see `scan()` calling `this._scanRoot(this._userHome, root, ...)` for every `searchRoots.user` entry, and `getHooksDiscoveryPaths`/`_scanFixedDiscoveryFiles` doing the same). `copilotAgent.ts` (`SessionDiscoveredEntry`/`_discoveredEntry()`) passes `this._parent.getUserHome()` — plain `this._environmentService.userHome` — as that base, instead of routing `.copilot`-prefixed roots through `getCopilotHomePath()` (already used correctly for session-state/log paths at lines 2772/2804 of the same file). The fix should resolve the `.copilot`-rooted paths against `getCopilotHomePath(userHome.fsPath, process.env)` while leaving `.agents`/`.claude`-rooted paths anchored to the real OS home.
