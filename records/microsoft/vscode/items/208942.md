## Evidence

- **canonical issue:** https://github.com/microsoft/vscode/issues/164 is open, predates this report, and explicitly tracks native file data transfer when dragging files from VS Code into other applications.
- **same observable symptom:** https://github.com/microsoft/vscode/issues/115438 reported the identical behavior—select two Explorer files, drag them into the OS file manager, and only one is copied—and a maintainer explicitly closed it as a duplicate of https://github.com/microsoft/vscode/issues/164.
- **current source limitation:** src/vs/workbench/browser/dnd.ts documents the Chromium limitation and deliberately writes only uriListEntries.slice(0, 1) to the standard text/uri-list transfer type; its DownloadURL path likewise supports only a single file. Internal VS Code transfer types retain the full list, but external applications cannot consume those types.
- **unique evidence retained:** This report confirms the same symptom on Windows 11 with VS Code 1.87.2 and includes a recording showing a multi-selection producing a single externally copied file.
