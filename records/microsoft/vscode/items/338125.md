# Issue #338125 — Explorer rename input closes when switching input sources on GNOME Wayland

[https://github.com/microsoft/vscode/issues/338125](https://github.com/microsoft/vscode/issues/338125)

## Summary

Confirmed on current main: the rename-input blur handler in explorerViewer.ts checks ownerDocument.hasFocus() before checking whether the input remains the active element, so a page-focus loss (e.g. GNOME input-source switching on Wayland) finishes the rename prematurely. An open PR (#338126) already targets this exact fix, so this should stay open and be reviewed there rather than closed or reassigned to an agent.

## Change summary

On GNOME Wayland, switching input sources causes VS Code's Explorer rename input to lose page focus and prematurely commit/close, even though DOM focus never left the input.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/338126, which reorders the blur-handler check to look at activeElement before hasFocus(); the issue can close once that PR merges.
