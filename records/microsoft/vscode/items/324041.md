# Issue #324041 — Copy button in Copilot Chat includes unrelated text from previous user message

[https://github.com/microsoft/vscode/issues/324041](https://github.com/microsoft/vscode/issues/324041)

## Summary

The defect remains on current main: the shared Copy action can substitute a stale selection from anywhere in the chat widget for the response associated with the clicked button. The issue should remain open and be routed to Chat.

## Change summary

Copying a Copilot response can include text selected from an earlier user message instead of copying only the targeted response.

## Best solution

Constrain selection-aware copying to the targeted chat item so a selection in another request or response cannot override that item's copy operation, while preserving intentional copying of a selection within the target response.

- **Trace:**

  > CopyItemAction in src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts resolves the targeted item from the action context, but then checks only whether window.getSelection() is non-empty and the active element is somewhere inside widget.domNode. It does not associate the selection with the targeted item, so focusing a later response's footer can make an earlier row's retained selection win before stringifyItem(item, false) runs. This selection behavior originated in commit 2f6b1d56c9ee0c3d65136017f5405c873f8445a3 and remains present on current main. Keep selection-aware copying for the target response and do not alter Copy All, Copy Final Response, code-block copying, or response serialization.

## Evidence

- **source trace:** In src/vs/workbench/contrib/chat/browser/actions/chatCopyActions.ts, CopyItemAction reads window.getSelection() and copies it whenever the active element is anywhere under widget.domNode; it never verifies that the selection belongs to the IChatResponseViewModel passed by the clicked footer button.
- **trigger and outcome:** A selection retained in an earlier user-message row remains eligible when a later response footer receives focus, so clicking that response's Copy button can write the unrelated selection instead of stringifyItem(item, false).
- **origin:** Commit 2f6b1d56c9ee0c3d65136017f5405c873f8445a3 introduced the widget-wide selection check in Chat copy polish; the same unchecked path remains on current main.
