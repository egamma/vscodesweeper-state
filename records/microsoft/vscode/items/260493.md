# Issue #260493 — "settingsSync.ignoredSettings" entries display as invalid if they're settings from disabled extensions

[https://github.com/microsoft/vscode/issues/260493](https://github.com/microsoft/vscode/issues/260493)

## Summary

Valid polish issue: the `settingsSync.ignoredSettings` JSON schema enum is built dynamically from currently registered configuration properties (only enabled extensions), so entries referencing disabled extension settings produce spurious validation warnings. Still reproduces on main; no fix found.

## Change summary

Settings from disabled extensions listed in `settingsSync.ignoredSettings` produce invalid-value warnings in `settings.json` because the schema enum only includes currently registered (enabled) settings.

## Best solution

The schema registration in `src/vs/platform/userDataSync/common/userDataSync.ts` (line ~128–136) should either allow `additionalItems` (relaxing the enum constraint to permit unknown setting IDs) or the JSON validation for this specific setting should suppress warnings for unrecognized keys. The fix belongs in the settings sync configuration registration logic.
