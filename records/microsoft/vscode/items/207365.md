# Issue #207365 — Rendering paused for long line for performance reasons. This can be configured via `editor.stopRenderingLineAfter`.

[https://github.com/microsoft/vscode/issues/207365](https://github.com/microsoft/vscode/issues/207365)

## Summary

Confirmed bug still present on main: the long-line hover warning fires based on model column position without considering whether word wrap makes the full line visible, so it shows when word wrap is ON (rendering is fine) but not when wrap is OFF (rendering is actually truncated).

## Change summary

The 'Rendering paused for long line' hover incorrectly appears when word wrap is enabled (line fully visible) and fails to appear when word wrap is disabled (line actually truncated).

## Best solution

The condition at `src/vs/editor/contrib/hover/browser/markdownHoverParticipant.ts:120` should account for word wrap: when word wrap is ON the renderer splits the line into segments, so `stopRenderingLineAfter` doesn't actually truncate — the hover should be suppressed. Conversely, when wrap is OFF the hover should appear but the cursor can't reach column 10000 in the truncated line, so a different UX may be needed (e.g. showing the warning at the truncation point).
