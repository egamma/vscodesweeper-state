# Issue #331178 — serve-web: /web-extension-resource always returns 403, so no web extension can be installed from the Extensions panel

[https://github.com/microsoft/vscode/issues/331178](https://github.com/microsoft/vscode/issues/331178)

## Summary

Traced and confirmed in current main: WebClientServer.handle strips only the /web-extension-resource prefix (not the following slash) before calling _handleWebExtensionResource, so the leading slash survives into the authority/path split and every request gets a 403 regardless of the URL. This breaks installing any web extension from the Extensions panel in self-hosted serve-web/serve-local deployments.

## Change summary

The /web-extension-resource proxy endpoint on the web server always returns 403 Forbidden, so web extensions can never be installed from the Extensions panel.

## Best solution

In src/vs/server/node/webClientServer.ts, pass `pathname.substring(WEB_EXTENSION_PATH.length + 1)` into `_handleWebExtensionResource` (mirroring the existing `+ 1` used for STATIC_PATH would be inconsistent — STATIC_PATH doesn't add +1 either, but its downstream `join()` absorbs the leading slash harmlessly; only the extension-resource branch needs the explicit +1) so the authority/path split resolves to the real host and path instead of an empty authority.
