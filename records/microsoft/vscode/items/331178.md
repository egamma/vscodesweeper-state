# Issue #331178 — serve-web: /web-extension-resource always returns 403, so no web extension can be installed from the Extensions panel

[https://github.com/microsoft/vscode/issues/331178](https://github.com/microsoft/vscode/issues/331178)

## Summary

The defect remains conclusively traceable on current main: the route passes a slash-prefixed resource path, causing authority validation to reject every web-extension resource before any outbound request. This is a bounded server bug that should remain open for implementation.

## Change summary

Self-hosted serve-web and serve-local deployments return 403 for every web-extension marketplace resource, preventing installation from the Extensions panel.

## Best solution

Ensure the web-extension-resource route passes an authority-first relative path to its handler, and cover the public route with a regression test that verifies the expected marketplace URL reaches the request service.
