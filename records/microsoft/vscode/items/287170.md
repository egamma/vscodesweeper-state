# Issue #287170 — Option for Copilot handoff buttons to force a new chat session to avoid context rot

[https://github.com/microsoft/vscode/issues/287170](https://github.com/microsoft/vscode/issues/287170)

## Summary

The requested configurable fresh-session handoff remains absent from current source. Keep this open: existing context-reset requests overlap, but do not clearly own the requirement to create a separate conversation while retaining the original history and transferring only curated context.

## Change summary

Allow custom-agent handoff buttons to start a new chat with the target agent and limited, explicitly chosen context instead of inheriting the entire conversation.

## Best solution

Provide an opt-in fresh-session handoff that preserves the source conversation, selects the destination agent, and carries a clearly defined context packet. Settle the context-transfer contract before implementation, while retaining existing same-session handoff behavior by default.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/languageProviders/promptFileAttributes.ts`, `src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/service/promptFileParser.test.ts`
- **Validation:** Verify that an opted-in custom-agent handoff creates a distinct session, retains the source transcript, selects the specified agent and model, and transfers only the agreed context packet. Exercise send:true and send:false, verify ordinary handoffs remain in the original session, and add parser coverage for the agreed configuration.
- **Behavior:**

  > A custom-agent handoff can opt into starting a separate chat rather than continuing the source conversation. The original conversation remains available, and the destination starts with the specified agent and only the agreed summary or selected artifacts—not the full transcript. Existing handoffs remain same-session by default, and the existing send flag controls whether the destination prompt is submitted automatically. Acceptance must distinguish genuinely separate sessions from clearing the source chat.
- **Trace:**

  > PromptFileHeader.handOffs in src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts recognizes no session-boundary or context-transfer fields. ChatWidget.executeHandoff in src/vs/workbench/contrib/chat/browser/widget/chatWidget.ts switches mode and submits within the current session for ordinary custom-agent handoffs. The standalone new-session action in src/vs/workbench/contrib/chat/browser/actions/chatNewActions.ts creates a session and clears attachments, but does not supply the requested transfer contract. Preserve default same-session behavior, agent/model selection, and send semantics; delegated background/cloud handoffs are a separate path and are not automatically covered by this request. Coordinate context-policy design with https://github.com/microsoft/vscode/issues/281116 and the newer overlapping request https://github.com/microsoft/vscode/issues/301044. The unresolved boundary is which previous response content and explicit artifacts become destination context, rather than whether send-on-click is supported.
- **Open decisions:**
  - Should a fresh-session handoff automatically include the last assistant response, require an explicitly authored handoff packet, or expose both as selectable transfer policies?
  - How should the handoff declare or let the user select transferred files and artifacts, and should existing source attachments be excluded unless explicitly selected?
