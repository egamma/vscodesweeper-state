# Issue #328360 — Agent: act on feedback processes all comments

[https://github.com/microsoft/vscode/issues/328360](https://github.com/microsoft/vscode/issues/328360)

## Summary

Traced in source: the built-in `act-on-feedback` skill and its server-side `listComments` tool return/act on every non-created comment — including ones already marked `resolved: true` — so the agent reprocesses feedback the user already resolved, matching the reported token waste.

## Change summary

Running /act-on-feedback causes the agent to act on all listed feedback comments, including ones already marked resolved, instead of only the still-open ones.

## Best solution

Either have `listComments` (src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts, `listableAnnotations`) filter out `resolved: true` items by default, or tighten the built-in skill prompt (src/vs/sessions/skills/act-on-feedback/SKILL.md, step 2) to explicitly skip comments whose `resolved` field is true before acting — a maintainer should pick which layer owns the filter since resolved comments are currently serialized on purpose for context.

## Evidence

- **listComments includes resolved items:** src/vs/platform/agentHost/node/shared/agentFeedbackServerTools.ts:286-299 `listableAnnotations` only excludes annotations still in the `created` state; a `resolved: true` comment has effectiveState 'resolved' which is `!== 'created'`, so it is still returned by the `listComments` tool (line 417-420).
- **each comment carries a resolved flag:** `serializeComment` includes `resolved` per item (confirmed by the existing unit test at src/vs/platform/agentHost/test/node/agentFeedbackServerTools.test.ts:66-84), so the tool result does distinguish resolved vs open comments.
- **skill prompt doesn't filter by resolved:** src/vs/sessions/skills/act-on-feedback/SKILL.md step 2 says to 'act on all of the listed comments' with no instruction to skip ones already marked resolved, so nothing currently stops the agent from reprocessing resolved feedback.
