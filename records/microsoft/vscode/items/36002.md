# Issue #36002 — [folding] allow defining folding regions in user settings and/or extensions

[https://github.com/microsoft/vscode/issues/36002](https://github.com/microsoft/vscode/issues/36002)

## Summary

This remains the canonical request for user-configurable folding markers. Current main supports markers supplied by language configurations and custom extension folding providers, but it still has no user setting for folding markers; with 53 upvotes and a Backlog milestone, it should remain open.

## Change summary

Allow users or extensions to define custom start and end markers for folding regions without modifying each language extension.

## Best solution

Add per-language user configuration for folding markers through the existing language-configuration customization path, with explicit semantics for whether user markers augment or replace language defaults and whether they participate alongside syntax folding providers.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/common/languages/languageConfigurationRegistry.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/syntaxRangeProvider.ts`, `src/vs/editor/contrib/folding/test/browser/indentRangeProvider.test.ts`, `src/vs/editor/contrib/folding/test/browser/syntaxFold.test.ts`
- **Validation:** Extend the language-configuration and folding unit tests to set custom marker regular expressions through configuration and verify folding for a language without a syntax provider and, according to the chosen semantics, for one with a syntax provider; run the targeted editor folding test suites with scripts/test.sh.
- **Behavior:**

  > Users can configure custom folding-region start and end markers for a language without editing or replacing its extension. A matching marker pair produces a region folding range and configuration changes take effect without restarting VS Code. Existing language folding, indentation folding, and extension-provided folding retain the precedence or merge behavior selected by the maintainer. Invalid configuration must be rejected or ignored consistently with other language configuration settings.
- **Trace:**

  > LanguageConfigurationService in src/vs/editor/common/languages/languageConfigurationRegistry.ts already overlays user-configured bracket pairs onto extension language configuration, but its customization keys do not include folding rules. The editor configuration schema in src/vs/editor/common/config/editorConfigurationSchema.ts consequently exposes bracket customization but no folding-marker equivalent. IndentRangeProvider consumes `FoldingRules.markers`, while FoldingController in src/vs/editor/contrib/folding/browser/folding.ts selects SyntaxRangeProvider whenever syntax providers exist; SyntaxRangeProvider uses indentation and marker ranges only as an all-providers-null fallback. The extension API already supports custom FoldingRangeProvider implementations, so the remaining gap is native settings and their composition semantics. Keep initial-collapse behavior tracked by https://github.com/microsoft/vscode/issues/40338 out of scope.
- **Open decisions:**
  - Should user-configured folding markers replace the language configuration's marker pair or augment it, potentially requiring support for multiple marker pairs?
  - Should user-configured marker ranges be merged with non-null syntax folding provider results, or apply only when indentation fallback is active?
  - Should the setting support only language-specific overrides, or also a wildcard/default marker pair for every language?

## Evidence

- **current source gap:** src/vs/editor/common/languages/languageConfigurationRegistry.ts customizes only `editor.language.brackets` and `editor.language.colorizedBracketPairs` from user configuration; folding rules are not included in `customizedLanguageConfigKeys` or `getCustomizedLanguageConfig`.
- **existing configuration model:** src/vs/editor/common/languages/languageConfiguration.ts defines language-specific `FoldingRules.markers`, and src/vs/workbench/contrib/codeEditor/common/languageConfigurationExtensionPoint.ts loads those rules from extension language-configuration files rather than user settings.
- **provider interaction:** src/vs/editor/contrib/folding/browser/folding.ts constructs an IndentRangeProvider from language folding rules, but switches to SyntaxRangeProvider when language folding providers exist. src/vs/editor/contrib/folding/browser/syntaxRangeProvider.ts uses the indentation provider only when all syntax providers return null, so marker behavior alongside syntax providers requires an explicit product decision.
- **partial extension workaround:** src/vscode-dts/vscode.d.ts exposes `languages.registerFoldingRangeProvider`, and SyntaxRangeProvider merges ranges from registered providers. This permits extension-based custom folding but does not provide the requested native user setting.
- **canonical ownership:** https://github.com/microsoft/vscode/issues/119802 was closed by a maintainer as a duplicate of this issue after requesting additional folding regions in settings.json. The broader https://github.com/microsoft/vscode/issues/102574 was created later and explicitly links folding-marker configuration back to this issue, so it is not an older canonical for this re-reviewed item.
- **community demand:** The issue has 53 community upvotes, remains assigned to the Backlog milestone, and later comments continue to request native custom markers despite available extensions.
