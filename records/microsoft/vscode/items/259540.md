# Issue #259540 — Support rollback and review code change suggestion in github copilot of vscode

[https://github.com/microsoft/vscode/issues/259540](https://github.com/microsoft/vscode/issues/259540)

## Summary

The checkpoint implementation restores file contents but deliberately preserves an already accepted entry as accepted, so it does not restore the line-level Keep/Undo review state requested here. This remains valid chat-editing polish with no verified open canonical.

## Change summary

Allow undoing or restoring after Keep to reopen the agent’s changes for line-level review and selective acceptance or rejection.

## Best solution

Make the selected rollback interaction reconstruct the pending review state, including the original-versus-suggested diff and actionable line-level Keep/Undo controls, without changing ordinary rollback behavior for unreviewed edits.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCheckpointTimelineImpl.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedDocumentEntry.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingService.test.ts`, `src/vs/workbench/contrib/chat/test/browser/chatEditing/chatEditingCheckpointTimeline.test.ts`
- **Validation:** Add a chat-editing test that creates agent edits, accepts the file, invokes the chosen rollback interaction, and asserts that the entry returns to Modified with the original-versus-suggested diff available for line-level Keep/Undo; retain passing checkpoint content-navigation tests.
- **Behavior:**

  > After an agent changes a file and the user keeps those changes, the supported rollback interaction should reopen the same suggestions for review rather than only changing file contents. The original and suggested lines must be shown again with enabled line-level Keep and Undo actions. The user must be able to keep or undo individual restored changes, while ordinary checkpoint restoration remains correct for files that were never accepted.
- **Trace:**

  > The checkpoint path runs through ChatEditingCheckpointTimelineImpl.navigateToCheckpoint and its filesystem delegate in ChatEditingSession._getTimelineDelegate. setContents applies reconstructed content as agent edits, but snapshots the entry's prior state and immediately calls entry.accept() when that state was not Modified, deliberately retaining Accepted/Rejected resolution. ChatEditingModifiedDocumentEntry and ChatEditingTextModelChangeService own the original/modified models needed for actionable hunks; simply changing the state enum may therefore be insufficient because Keep has already reconciled those models. Preserve normal timeline content reconstruction, file creation/deletion handling, and behavior for entries still in Modified state. The related closed report is https://github.com/microsoft/vscode/issues/248284; it confirms the missing control restoration but is not a canonical target.
- **Open decisions:**
  - Should this contract apply to standard Ctrl/Cmd+Z after Keep, checkpoint Restore, or both interactions?
  - When reopening review, should rollback preserve the accepted file contents as the suggested side of the diff, or first restore the pre-agent file contents and present the suggestions separately?

## Evidence

- **current source:** In src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts, the checkpoint timeline delegate's setContents implementation records restored content as agent edits, then calls entry.accept() whenever the entry was already accepted or rejected. The accompanying comment explicitly says an accepted file should not become modified again, which prevents the review controls from returning.
- **review-state lifecycle:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedFileEntry.ts permits accept/reject only while Modified and transitions Keep to Accepted; src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts gates file and hunk review actions on an active modification.
- **checkpoint scope:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCheckpointTimelineImpl.ts navigateToCheckpoint reconstructs filesystem content by epoch, but does not itself reconstruct the accepted entry's prior review-state models.
- **maintainer context:** A maintainer initially pointed to checkpoints at https://github.com/microsoft/vscode/issues/259540#issuecomment-3161152423, after which the reporter clarified at https://github.com/microsoft/vscode/issues/259540#issuecomment-3174702538 that the missing capability is restoring selective line-level review, not merely restoring contents.
- **related report:** https://github.com/microsoft/vscode/issues/248284 described the same observable expectation, and a contributor acknowledged that undo still did not bring back Keep/Undo buttons. That issue is closed after an info-needed timeout, so it cannot be a duplicate canonical.
- **canonical search:** Searches for open issues describing undo of accepted hunks or restoration of Keep/Undo controls found no older open issue with the same reporter-observable symptom.
