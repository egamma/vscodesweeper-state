# Issue #166944 — [css] Please add an option to switch to using line-by-line comments

[https://github.com/microsoft/vscode/issues/166944](https://github.com/microsoft/vscode/issues/166944)

## Summary

This backlog request remains necessary: CSS still falls back to one block comment for a multi-line selection, and VS Code has no setting or dedicated command for line-by-line block comments. It has 22 community upvotes, while the multi-cursor workflow and Marketplace extension are workarounds rather than coverage of the requested built-in behavior.

## Change summary

Provide an option or dedicated command that comments each selected CSS line separately instead of wrapping the selection in one block comment.

## Best solution

Add a first-class editor operation for line-by-line use of block-comment delimiters in languages such as CSS, while preserving the existing block-selection behavior unless the user explicitly selects the new mode. A maintainer should first decide whether this is exposed as a separate command or a configurable behavior of Toggle Line Comment.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/comment/browser/comment.ts`, `src/vs/editor/contrib/comment/browser/lineCommentCommand.ts`, `src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** Extend the editor comment unit tests to select multiple lines under a block-comment-only language configuration and assert that the chosen opt-in command or mode produces one `/* ... */` pair per non-empty line, toggles those comments back off, and leaves the existing whole-selection fallback unchanged by default.
- **Behavior:**

  > For a language such as CSS that provides block-comment delimiters but no line-comment token, users can explicitly comment a multi-line selection line by line, producing an independent `/* ... */` comment on every selected non-empty line. Invoking the same operation on those lines removes the independent comments. Existing Toggle Line Comment behavior remains unchanged by default unless the maintainer chooses a configurable mode, and languages with native line-comment tokens retain their current behavior.
- **Trace:**

  > CSS declares only block comments in extensions/css/language-configuration.json. CommentLineAction in src/vs/editor/contrib/comment/browser/comment.ts constructs LineCommentCommand, whose `_gatherPreflightCommentStrings` returns null without a line-comment token; src/vs/editor/contrib/comment/browser/lineCommentCommand.ts then calls `_executeBlockComment`, wrapping the entire selected range. The existing fallback is covered by the `Editor Contrib - Line Comment As Block Comment` tests in src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts. Current editor comment configuration in src/vs/editor/common/config/editorOptions.ts has no style selector. Preserve native line-comment handling, the default whole-block fallback, indentation, empty-line handling, and the explicit Toggle Block Comment command. https://github.com/microsoft/vscode/issues/184666 is related but newer and concerns corruption around nested comment delimiters rather than the public command/configuration choice here.
- **Open decisions:**
  - Should line-by-line block commenting be exposed as a separate keybindable command, or as a per-language `editor.comments` setting that changes Toggle Line Comment behavior?

## Evidence

- **current source behavior:** extensions/css/language-configuration.json defines only `blockComment: ["/*", "*/"]`; src/vs/editor/contrib/comment/browser/lineCommentCommand.ts therefore delegates a multi-line Toggle Line Comment selection to `_executeBlockComment`, which wraps the whole selected range.
- **no existing option:** src/vs/editor/common/config/editorOptions.ts exposes only `editor.comments.insertSpace` and `editor.comments.ignoreEmptyLines`; there is no comment-style option for applying block delimiters independently to each selected line.
