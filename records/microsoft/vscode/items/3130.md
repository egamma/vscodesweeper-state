# Issue #3130 — Allow customization of mouse shortcuts

[https://github.com/microsoft/vscode/issues/3130](https://github.com/microsoft/vscode/issues/3130)

## Summary

Keep open: current mouse settings cover selected gestures, not general mouse-plus-modifier customization. With 1,929 upvotes and an accepted Backlog placement, this remains a well-supported request requiring input-system design.

## Change summary

Allow users to customize mouse-button and modifier gestures rather than relying on predefined mouse actions.

## Best solution

Provide a coherent, context-aware mouse-binding capability that preserves existing defaults and integrates with command customization. Agree on supported gestures and interaction semantics before extending the shared binding infrastructure and individual surfaces.

## Plan brief

- **Likely files:** `src/vs/base/common/keybindingParser.ts`, `src/vs/base/common/keybindings.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts`
- **Validation:** The plan should define executable parser/resolver and interaction tests for supported mouse bindings, modifier matching, context conditions, and unchanged defaults. Acceptance should include configuring a mouse-plus-modifier gesture for Go to Implementation and checking that unbound selection, link activation, dragging, and context-menu behavior remain unchanged on supported desktop and web platforms.
- **Behavior:**

  > Users want to assign mouse-button and modifier gestures to actions beyond the predefined multicursor and middle-click options. Existing settings only partially meet that goal, and editor-only support does not address the terminal-link use case raised in the discussion. The finished capability should honor user bindings in their supported contexts while preserving existing behavior when no custom binding applies. Acceptance must cover a custom Go to Implementation gesture and regression checks for ordinary selection, dragging, links, and context menus.
- **Trace:**

  > KeybindingParser in src/vs/base/common/keybindingParser.ts produces keyboard key-code or scan-code chords, and WorkbenchKeybindingService::_registerKeyListeners in src/vs/workbench/services/keybinding/browser/keybindingService.ts dispatches keyboard events. Editor mouse link gestures are handled separately by ClickLinkMouseEvent and createOptions in src/vs/editor/contrib/gotoSymbol/browser/link/clickLinkGesture.ts, using the limited settings registered in src/vs/editor/common/config/editorOptions.ts. Source inspection establishes the missing general capability but does not finish the design across other mouse consumers. Preserve current defaults and existing settings compatibility; the boundary requiring a maintainer decision is which gestures and surfaces the initial public binding contract supports. https://github.com/microsoft/vscode/pull/154465 is closed and unmerged, while https://github.com/microsoft/vscode/issues/266045 covers only the existing middle-click feature. https://github.com/microsoft/vscode/issues/302645 supplies a related terminal requirement rather than a duplicate canonical.
- **Open decisions:**
  - Should the initial capability cover editor gestures only, or also workbench and terminal interactions?
  - Which gestures belong in the initial public contract: button clicks with modifiers, double clicks, wheel gestures, or mixed keyboard/mouse chords?
  - Should customization use keybindings.json and its context conditions, and what precedence should custom bindings have over built-in selection, dragging, link activation, and context-menu gestures?

## Evidence

- **Existing capability and remaining gap:** src/vs/editor/common/config/editorOptions.ts:6511–6534 registers editor.multiCursorModifier with alt/ctrlCmd choices and editor.mouseMiddleClickAction with default/openLink/ctrlLeftClick choices. These provide limited remapping, not arbitrary button-plus-modifier bindings to commands such as Go to Implementation.
- **Shared binding infrastructure:** src/vs/base/common/keybindingParser.ts parses modifier combinations into KeyCodeChord or ScanCodeChord. src/vs/workbench/services/keybinding/browser/keybindingService.ts::_registerKeyListeners dispatches keyboard keydown/keyup events; the inspected paths do not provide a general mouse-binding mechanism.
