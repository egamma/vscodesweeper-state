# Issue #221614 — Provide a "withoutFormatting" option for `document.save` and `workspace.save`

[https://github.com/microsoft/vscode/issues/221614](https://github.com/microsoft/vscode/issues/221614)

## Summary

The requested per-call save option is still missing from both public APIs; the existing Save without Formatting command does not cover arbitrary document saves. Keep this accepted, 25-upvote request open: the related API request is newer and cannot replace it under the re-review rules.

## Change summary

Allow extensions to save a document or workspace resource without invoking configured format-on-save and code-actions-on-save behavior.

## Best solution

Provide a consistent, opt-in save contract for TextDocument.save and workspace.save that preserves ordinary save behavior by default. API owners should settle whether the bypass excludes only formatting and code actions or all save participants, including extension pre-save callbacks.

- **Behavior:**

  > Extensions need to save a specified document or workspace resource without configured format-on-save and code-actions-on-save transformations. The opt-in operation must work without activating the target editor or changing user settings. Calls without the option must retain their existing behavior, return values and failure semantics. Acceptance should cover a non-active target and distinguish the agreed treatment of other save participants.
- **Trace:**

  > TextDocument.save flows through ExtHostDocumentData._save and MainThreadDocuments.$trySaveDocument into ITextFileService.save; workspace.save flows through extHost.api.impl.ts, ExtHostWorkspace.save and MainThreadWorkspace.$save into IEditorService.save. Neither public path transports a bypass option. Internally, TextFileEditorModel.doSaveSequential already gates the entire participant pipeline using ISaveOptions.skipSaveParticipants, and the Save without Formatting command uses that flag for selected or active editors. The pipeline also includes extension pre-save participation through mainThreadSaveParticipant.ts, so the uncertainty is the public bypass contract, not whether an internal bypass exists. Preserve ordinary saves, resource targeting and editor focus; changing user configuration is not equivalent coverage. https://github.com/microsoft/vscode/issues/245405 supplies an additional non-active-document use case but is newer than this issue.
- **Open decisions:**
  - Should the public option match Save without Formatting by skipping all save participants, including whitespace cleanup and onWillSaveTextDocument callbacks, or bypass only configured formatting and save code actions?
