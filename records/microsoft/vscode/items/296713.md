# Issue #296713 — [BYOK Agent Mode] Gemini 3.1 Pro returns 400 "Function call is missing a thought_signature" — OpenAI-compatible client strips required field

[https://github.com/microsoft/vscode/issues/296713](https://github.com/microsoft/vscode/issues/296713)

## Summary

Still reproduces on main: the BYOK OpenAI translation layer strips non-standard fields from tool calls (including Gemini's `extra_content.google.thought_signature`), breaking multi-turn tool calling with Gemini 3.1 Pro. No fix has landed.

## Change summary

BYOK Agent Mode with Gemini 3.1 Pro fails on the second turn with a 400 error because the `thought_signature` field is stripped from tool calls during OpenAI-to-bridge translation.

## Best solution

Extend `IByokLmToolCall` and `IByokLmChatMessage` in `src/vs/platform/agentHost/common/agentHostByokLm.ts` to carry an opaque vendor-extension bag (e.g. `extra?: Record<string, unknown>`), and round-trip it through `toBridgeToolCalls` / `bridgeResultToSseFrames` in `byokOpenAiTranslation.ts`. This preserves any vendor-specific fields across the bridge without needing per-provider special-casing. The secondary URL-construction issue (`/v1/chat/completions` appended to a base that already ends with `/v1beta/openai/`) should also be investigated.
