# Issue #134461 — VSCode requests bluetooth access on startup

[https://github.com/microsoft/vscode/issues/134461](https://github.com/microsoft/vscode/issues/134461)

## Summary

Keep open: the unwanted Linux BlueZ activation remains an acknowledged Electron runtime issue. Both linked fix attempts were closed without merging because the proposed Bluetooth flag has no runtime implementation.

## Change summary

Prevent VS Code startup from requesting activation of org.bluez when Bluetooth is disabled or unavailable.

## Best solution

Provide a supported Electron runtime control for Bluetooth initialization, then adopt it in VS Code's early startup configuration. Adding an unsupported command-line switch alone does not address the reported activation request.

## Evidence

- **Confirmed trigger and runtime ownership:** https://github.com/microsoft/vscode/issues/134461 reports org.bluez activation immediately after startup with bluetooth.service stopped and extensions disabled. A maintainer identified Electron's BlueZ initialization at https://github.com/electron/electron/blob/22ae945311a96080b83566f40c8576b700ee339a/shell/browser/electron_browser_main_parts.cc#L482-L484 and supported making it configurable.
- **Independent confirmations:** The discussion confirms the behavior on Arch Linux, a clean Ubuntu VM, and the Snap package, including empty-window and fresh-profile checks. The January 29, 2026 report confirms org.bluez activation on NixOS with VS Code 1.108.1; the preceding non-reproduction report does not establish resolution.
- **First fix attempt rejected:** https://github.com/microsoft/vscode/pull/322212 is closed and unmerged. The maintainer explicitly states that the proposed flag is not valid in the runtime: https://github.com/microsoft/vscode/pull/322212#issuecomment-5279510238.
- **Second fix attempt rejected:** https://github.com/microsoft/vscode/pull/330448 is also closed and unmerged. The maintainer explains that declaring the flag is insufficient without a parallel runtime change: https://github.com/microsoft/vscode/pull/330448#issuecomment-5279469250.
- **Current checkout:** src/main.ts delegates to src/mainImpl.ts. configureCommandlineSwitchesSync in src/mainImpl.ts configures runtime switches and feature lists, but contains no Bluetooth initialization control. The checkout has only one available history commit, e3c23162, so local history cannot establish a fixing commit. No runtime reproduction was executed.
- **Canonical search:** Open-issue searches for BlueZ and Bluetooth found no verified older canonical owning this symptom. https://github.com/microsoft/vscode/issues/59162 describes the same historical activation request but is closed following the original reporter's 2019 non-reproduction. https://github.com/microsoft/vscode/issues/247469 is newer and reports Bluetooth being switched off when launched from the dock, not the same observable symptom; neither qualifies as a duplicate target.
- **Related crash is not equivalent:** https://github.com/microsoft/vscode/issues/171431 is closed and reports a crash during GitHub authentication with additional gfloat errors. Its BlueZ log entries do not establish that it owns or resolves the startup activation request.
