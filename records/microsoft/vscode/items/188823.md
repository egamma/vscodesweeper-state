## Summary

The remote-SVG failure has a concrete explanation in current source: desktop request filtering blocks SVG image responses outside approved contexts, including Quick Pick backgrounds. Keep this team-authored, accepted issue open for an owner decision on the supported icon URI contract rather than declining it as designed.

## Change summary

An HTTPS SVG supplied as QuickPickItem.iconPath fails to display, while the equivalent PNG and a local SVG work.

## Best solution

Resolve the mismatch between QuickPickItem.iconPath's URI support and desktop SVG filtering: establish whether remote SVG icons should be supported through a safe loading path or explicitly document the restriction and supported alternatives. Preserve the existing request-safety boundary rather than broadly allowing remote SVG responses.
