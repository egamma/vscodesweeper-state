Keep open: the stale hyperlink underline has a credible reproduction and an upstream xterm.js invalidation path that still appears relevant. Both linked fix attempts were closed without merging, so neither establishes that the report is resolved.

## Change summary

Clear the previous multiline hyperlink underline when scrolling under a stationary pointer changes the hovered link.

## Best solution

Resolve scroll-driven link invalidation in xterm.js, then verify the adopted dependency against this exact stationary-pointer, multiline-link scenario in VS Code. Tooltip dismissal fixes should not be treated as proof that underline decorations are corrected.

## Evidence

- **Reported trigger and confirmation:** https://github.com/microsoft/vscode/issues/207956 describes scrolling upward while hovering a multiline hyperlink without moving the mouse, leaving its underline shape behind until mouse movement. The reporter supplied a screenshot, and Tyriar confirmed reproducing it once in the supplied December 18, 2024 comment.
- **Upstream proposals were not merged:** GitHub reports merged=false and state=closed for https://github.com/xtermjs/xterm.js/pull/5026 and https://github.com/xtermjs/xterm.js/pull/5029. Both explicitly identify this report; the latter was closed with a stale comment at https://github.com/xtermjs/xterm.js/pull/5029#issuecomment-5231718902.
- **Relevant upstream condition remains:** Current https://github.com/xtermjs/xterm.js/blob/master/src/browser/Linkifier.ts retains the onRenderedViewportChange condition requiring the current link's entire buffer range to fit within the invalidation interval. On upward scrolling, a previously hovered link can extend below that interval and bypass _clearCurrentLink and link reevaluation. The unmerged diff in https://github.com/xtermjs/xterm.js/pull/5029 specifically broadens the end bound when e.start is zero; the current upstream source still uses ydisp + 1 + e.end.
- **VS Code integration boundary:** The checkout's package.json declares @xterm/xterm ^6.1.0-beta.304. src/vs/workbench/contrib/terminalContrib/links/browser/terminalLinkManager.ts registers providers through _xterm.registerLinkProvider, while terminalLink.ts supplies ILink decorations. Underline lifecycle is delegated to xterm.js; the newer dependency version alone does not prove resolution, and no runtime reproduction was attempted in this read-only review.
- **Canonical search and distinct related symptom:** Repository searches for terminal underline scrolling and terminal underline did not establish an older open canonical for this exact symptom. https://github.com/microsoft/vscode/issues/190176 is older but closed and concerns a tooltip remaining after command output, not a multiline underline remaining after upward scrolling. Its related upstream tracker, https://github.com/xtermjs/xterm.js/issues/4661, remains open; neither establishes a policy-valid duplicate close for this re-reviewed item.
