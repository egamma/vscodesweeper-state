# Issue #339905 — Tooltip is wrong on 3 models pill

[https://github.com/microsoft/vscode/issues/339905](https://github.com/microsoft/vscode/issues/339905)

## Summary

Team-authored, freshly filed bug report (0 days old) from a VS Code core maintainer testing the new model-comparison feature; traced the root cause in source — the model-picker hover always reads the single `selectedModel`, ignoring the active comparison workflow, so the tooltip never lists the compared models.

## Change summary

After using the compare-agent picker to select multiple models, hovering the resulting "N models"/"N Attempts" pill shows a tooltip naming only one model instead of all selected models.

## Best solution

Extend the model-picker hover to reflect the active workflow's full committed model set (not just the single `selectedModel`) when a comparison/workflow is active, likely by exposing the committed model ids on `IModelPickerWorkflow` for `_getHoverContents` to resolve and list.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWorkflow.ts`, `src/vs/sessions/contrib/chat/browser/sessionComparisonModelSelection.ts`
- **Validation:** A test (e.g. extending src/vs/sessions/contrib/chat/test/browser/sessionComparisonModelSelection.test.ts or a new modelPickerActionItem test) asserting that once a comparison is finished, the hover/tooltip text includes the display names of all selected attempt models rather than just one.
- **Behavior:**

  > Hovering the model-picker pill while a multi-model workflow (e.g. the Compare Models setup) is committed must show a tooltip that names every model involved in that workflow, not just a single model. When no workflow is active, the existing single-model hover behavior is unchanged. Acceptance: hovering a "3 Attempts"-style pill shows all 3 (or N) compared model names somewhere in the tooltip text.
- **Trace:**

  > `_getHoverContents()` in src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerActionItem.ts (lines 213-237) only reads `this._pickerWidget.selectedModel` (a single `ILanguageModelChatMetadataAndIdentifier`) to build the hover string; it has no awareness of `this.delegate.workflow`. Meanwhile `_renderLabel()` in modelPickerWidget.ts already switches the *visible* pill text to `workflow.summary.get()` when a workflow is active — so the label and hover diverge. `IModelPickerWorkflow` (modelPickerWorkflow.ts) currently exposes `summary`, `state` (undefined once committed), `label`, but no committed model-id list; `SessionComparisonModelSelection` (sessionComparisonModelSelection.ts) is the sole implementer and already tracks `attemptModelIds`/`judgeModelId`/`synthesizerModelId` internally. Boundary: do not change the pill's visible label rendering, the comparison setup dropdown, or non-workflow (single-model) hover behavior — only the hover-content path for an active workflow needs to surface the full model list.
- **Open decisions:**
  - Should the tooltip list only the attempt models, or also the Judge/Synthesizer models when configured?
  - How should the tooltip read when many models (up to 10) are selected — full comma-separated list, or a truncated "+N more" style, matching conventions elsewhere in the model picker (e.g. the existing "{0} more models" pattern)?

## Evidence

- **root cause:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerActionItem.ts `_getHoverContents()` (lines 213-237) builds the tooltip purely from `this._pickerWidget.selectedModel` — a single model — and never consults `this.delegate.workflow`, even though the visible pill label (`_renderLabel` in modelPickerWidget.ts) switches to `workflow.summary.get()` (e.g. "3 Attempts") when a workflow like model comparison is active.
- **feature under test:** The referenced #339373 and src/vs/sessions/contrib/chat/browser/sessionComparisonModelSelection.ts implement the new "Compare Models" picker workflow (the only current implementer of IModelPickerWorkflow), whose `summary`/`attemptModelIds` drive the pill label but have no path into the hover.
- **interface gap:** src/vs/workbench/contrib/chat/browser/widget/input/modelPicker/modelPickerWorkflow.ts's IModelPickerWorkflow has no field exposing the committed/selected model ids for hover use once the setup draft is finished (its `state` observable returns undefined after `finish()`).
