# Issue #225808 — window.innerHeight is way larger than the actual window height on macOS

[https://github.com/microsoft/vscode/issues/225808](https://github.com/microsoft/vscode/issues/225808)

## Summary

Keep open for the renderer documentation work explicitly accepted in the discussion. The oversized iframe is intentional, and the widget has a confirmed workaround, but neither establishes completion of the documentation follow-up.

## Change summary

Document notebook output sizing so renderer authors do not mistake the output iframe's innerHeight for the visible VS Code window height.

## Best solution

Document the notebook webview's scrolling geometry and safe canvas-sizing guidance for output renderer authors. Explain that window.screen.availHeight describes available screen space, not the actual notebook viewport, and preserve the existing isolation and scrolling design.
