## Summary

The workspace trust startup dialog uses `disableCloseAction: true`, intentionally preventing Escape and cmd+w. A maintainer called it as-designed, but the reporter and a later commenter raised valid accessibility concerns (no keyboard-only way to dismiss the dialog). The `under-discussion` label is appropriate — this is a UX/accessibility design discussion, not resolved.

## Change summary

The workspace trust modal dialog blocks cmd+w (close window) and has no keyboard-accessible dismiss path, trapping keyboard-only users.

## Best solution

The discussion should resolve whether (a) cmd+w should close the window even with the modal open, or (b) Escape should dismiss the dialog into restricted mode, or (c) both. The fix would be in `src/vs/workbench/contrib/workspace/browser/workspace.contribution.ts` — changing `disableCloseAction: true` or adding a cancel handler that maps to 'don't trust'. The accessibility concern from the latest comment strengthens the case for at least one keyboard dismiss path.
