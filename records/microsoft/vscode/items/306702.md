# Issue #306702 — Updating extension to newly published version picks the universal VSIX instead of platform one

[https://github.com/microsoft/vscode/issues/306702](https://github.com/microsoft/vscode/issues/306702)

## Summary

This is a real, unfixed bug with significant user impact (21 upvotes, multiple platforms affected). The `filterLatestExtensionVersionsForTargetPlatform` function in current main has replacement logic for preferring platform-specific over universal versions with the same version number, but the issue persists — likely because the marketplace resource API does not return all platform variants, or the ordering is inconsistent. No fix commit references this issue, and no duplicate was found.

## Change summary

When updating an extension that newly publishes a universal VSIX alongside platform-specific ones, VS Code picks the universal VSIX instead of the platform-specific one.

## Best solution

Investigate whether the marketplace resource API (`getLatestRawGalleryExtension`) returns all target-platform variants for a given version number. If it doesn't, the client-side replacement logic in `filterLatestExtensionVersionsForTargetPlatform` never gets the chance to prefer the platform-specific build. The fix likely belongs in `src/vs/platform/extensionManagement/common/extensionGalleryService.ts` — either by ensuring the API request includes a target-platform hint, or by falling back to the query API when the resource API returns a universal version but platform-specific builds are known to exist (via `allTargetPlatforms`).
