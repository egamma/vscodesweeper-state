# Issue #326765 — High CPU usage (infinite loop) When Incorrect Proxy URL is Set

[https://github.com/microsoft/vscode/issues/326765](https://github.com/microsoft/vscode/issues/326765)

## Summary

Credible report of unbounded rapid-retry behavior when an HTTP-protocol proxy URL points at a SOCKS proxy, causing 100% CPU. The strace evidence is strong, but the root cause likely lives in `@vscode/proxy-agent` or in how multiple VS Code services retry failed outgoing connections without aggregate rate limiting. Related to but distinct from https://github.com/microsoft/vscode/issues/241201 (which reports a clear error message rather than an infinite loop). Keeping open for investigation.

## Change summary

Setting `http.proxy` to an `http://` URL that actually points at a SOCKS proxy causes VS Code's node service to spin at 100% CPU due to unbounded rapid connection retries.

## Best solution

Investigate whether `@vscode/proxy-agent` or VS Code's own connection-retry logic needs a backoff/cap when the proxy connection repeatedly fails immediately. The `nodeRequest` retry in `src/vs/platform/request/node/requestService.ts` is bounded (3 retries with backoff), but the tight loop likely comes from `@vscode/proxy-agent`'s patched `http`/`https`/`net` modules reconnecting without delay, amplified by multiple services making outgoing requests simultaneously. A fix might involve adding exponential backoff or a circuit-breaker in the proxy agent layer, or validating the proxy URL protocol against expected proxy types. The `proxy` area label applies.
