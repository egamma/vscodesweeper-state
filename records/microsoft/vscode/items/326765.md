# Issue #326765 — High CPU usage (infinite loop) When Incorrect Proxy URL is Set

[https://github.com/microsoft/vscode/issues/326765](https://github.com/microsoft/vscode/issues/326765)

## Summary

Keep open to track adoption of the upstream Undici fix. Current main locks Undici 7.29.1, whose ProxyAgent still lacks the error handling that stops this reconnect loop.

## Change summary

An HTTP proxy URL pointing to a SOCKS server causes repeated failed CONNECT attempts and sustained high CPU usage.

## Best solution

Adopt the upstream tunnel-establishment fix in the Undici implementations used by VS Code's proxy-enabled request paths, then verify that the reported HTTP-to-SOCKS mismatch fails promptly rather than reconnecting indefinitely. Track this here until that integration is established.

## Evidence

- **Reported trigger:** https://github.com/microsoft/vscode/issues/326765 describes setting http.proxy to http://127.0.0.1:15891 while that port serves SOCKS. The supplied strace repeatedly shows HTTP CONNECT writes, immediate socket closure, and new connections.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode/issues/326765#issuecomment-5539332965 identifies https://github.com/nodejs/undici/issues/3897 and states that it is fixed in Undici 8.6.0.
- **Verified upstream fix:** https://github.com/nodejs/undici/pull/5441 merged as https://github.com/nodejs/undici/commit/445522ba1bc22bcef2971bfdc30c883531e84e84. Its lib/dispatcher/proxy-agent.js diff wraps UND_ERR_SOCKET during CONNECT establishment in ProxyConnectionError, making the queued request fail instead of triggering repeated reconnects. This directly addresses the reported socket-close trigger.
- **Fix absent from locked dependency:** Current package-lock.json:20042-20045 locks Undici 7.29.1; extensions/copilot/package-lock.json also resolves 7.29.1. In https://github.com/nodejs/undici/blob/v7.29.1/lib/dispatcher/proxy-agent.js#L221-L227, the CONNECT catch handles ERR_TLS_CERT_ALTNAME_INVALID specially but passes other errors through unchanged; the upstream UND_ERR_SOCKET fix is absent.
- **VS Code integration boundary:** src/vs/workbench/api/node/proxyResolver.ts reads http.proxy in connectProxyResolver, wraps global fetch through proxyAgent.createFetchPatch, and patches loaded Undici modules through proxyAgent.patchUndici. The locked npm dependency alone does not establish the version or behavior of every runtime-provided fetch implementation; no execution was performed in this read-only review.
