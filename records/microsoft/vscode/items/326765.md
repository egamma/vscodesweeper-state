# Issue #326765 — High CPU usage (infinite loop) When Incorrect Proxy URL is Set

[https://github.com/microsoft/vscode/issues/326765](https://github.com/microsoft/vscode/issues/326765)

## Summary

Real defect, but the runaway CPU loop happens inside Chromium's native network stack once a malformed http.proxy value is handed to it — VS Code's own code just forwards the setting unvalidated, so this is best tracked as an upstream Electron/Chromium networking issue rather than something fixable in this repo's TypeScript.

## Change summary

Setting http.proxy to an http:// URL that actually points at a SOCKS proxy causes VS Code's network process to spin at 100% CPU retrying the connection with no backoff or retry limit.

## Best solution

Consider adding basic validation/sanitization of the http.proxy value in src/vs/platform/windows/electron-main/windowImpl.ts (around the 'Proxy' config-change handler, lines ~1113-1141) before it's passed to session.setProxy/app.setProxy — e.g. warn or reject unsupported proxy-scheme combinations — but the actual infinite-retry-without-backoff behavior lives in Chromium's net:: proxy/connection stack (mojo NodeService), which is outside this repo's control.
