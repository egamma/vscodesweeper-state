# Issue #338497 — Private plugin marketplace doesn't refresh on sign out

[https://github.com/microsoft/vscode/issues/338497](https://github.com/microsoft/vscode/issues/338497)

## Summary

Team-authored bug report (self-tested by the author while validating #338068), and no fix commit references this issue yet, so it stays open per the hard keep-open rule for team-authored items. Source review confirms a real gap: the plugin marketplace pipeline has no auth-session invalidation at all, and a failed 'refresh' silently falls back to the stale on-disk clone/cache by design.

## Change summary

After signing out of the account backing a private plugin marketplace, its plugins keep appearing in AI Customizations, and 'Refresh Marketplace' doesn't clear them.

## Best solution

Decide (with a maintainer) what sign-out should do to private-marketplace content — stop serving it immediately vs. only stop refreshing it — then wire an auth-session-change listener into the plugin marketplace/repository services to enforce that, since neither currently reacts to authentication state at all.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts`, `src/vs/workbench/contrib/chat/browser/agentPluginRepositoryService.ts`
- **Validation:** A test asserting that after an auth session ends for a marketplace's credentials, its plugins are no longer returned by fetchMarketplacePlugins/queryMarketplacePlugins (or that ensureRepository/refresh distinguishes an auth failure from a network failure).
- **Trace:**

  > pluginMarketplaceService.ts's persisted GitHub cache (_gitHubMarketplaceCache, GITHUB_MARKETPLACE_CACHE_STORAGE_KEY) and agentPluginRepositoryService.ts's on-disk clone are keyed only by marketplace canonical id and TTL, never by account/session. _refreshRepository() explicitly swallows pull errors and still returns the stale directory, so after sign-out a private marketplace's plugins keep showing even via an explicit 'Refresh Marketplace' action. Where the uncertainty starts: should sign-out purge/hide the private marketplace's content immediately, or only stop it from refreshing further (leaving already-installed plugins visible)? That product choice, and which auth event should trigger it, needs a maintainer's call before implementation.
- **Open decisions:**
  - Should signing out immediately hide/remove plugins sourced from a private marketplace, or only stop further updates while leaving already-fetched entries visible until explicitly removed?
  - Should a pull/fetch failure be classified as auth-related (403/401) vs. transient network failure, with different fallback behavior for each?
  - Does this apply only to the GitHub-repo marketplace path, or also to the cloned/private-clone marketplace path and installed-plugin metadata cache?

## Evidence

- **no auth wiring:** src/vs/workbench/contrib/chat/common/plugins/pluginMarketplaceService.ts and src/vs/workbench/contrib/chat/browser/agentPluginRepositoryService.ts contain no reference to IAuthenticationService/onDidChangeSessions — nothing invalidates marketplace state on sign-out or sign-in.
- **cache persists past sign-out:** pluginMarketplaceService.ts keeps a persisted GitHub marketplace cache (GITHUB_MARKETPLACE_CACHE_STORAGE_KEY, TTL-based, keyed only by canonicalId) with no dependency on account state.
- **refresh silently serves stale content by design:** agentPluginRepositoryService.ts's _refreshRepository() doc comment states it 'never throws — a marketplace that cannot be refreshed still serves its cached contents'; a pull failing due to revoked auth after sign-out is treated the same as a transient network failure, so 'Refresh Marketplace' still returns the old clone's contents.
