- **Behavior:**

  > The study found that developers could not locate project files or confidently verify a successful clone at the start of a session. On first clone or open, users should see their project tree and understand where the files reside without researcher assistance or shell commands. Reassess those tasks on the current desktop layout, which already presents Files for workspace-backed drafts. Acceptance must cover both first use and the agreed treatment of remembered layout preferences.
- **Trace:**

  > DesktopDockedTabsCoordinator opens Files first for workspace-backed drafts when the editor group is empty; DesktopDraftSessionStrategy reveals Files details while hiding redundant editor content. The existing desktop layout tests explicitly cover entering a new-session view with Empty Files. Files also has a default auxiliary-bar container, a command-palette action, and an Add Tab entry, so this is not a missing file-tree implementation. NewChatWidget's clone path calls git.clone with postCloneAction 'none', receives the local repository path, and selects that workspace; the remaining uncertainty is whether the resulting presentation adequately communicates success and location to a first-time user. Preserve unrelated editor, session-switch, and workspace-less behavior. https://github.com/microsoft/vscode/issues/302122 and https://github.com/microsoft/vscode/issues/303018 provide related onboarding and project-creation context, not duplicate ownership.
- **Open decisions:**
  - Should successful clone/open reveal Files only for first use, or also override an explicitly remembered hidden Files pane on subsequent project opens?
  - Is the selected workspace plus visible Files tree sufficient clone confirmation, or should successful cloning produce additional explicit feedback?
