# Issue #334453 — Copilot Git remote fallback fails for linked worktrees

[https://github.com/microsoft/vscode/issues/334453](https://github.com/microsoft/vscode/issues/334453)

## Summary

Team-authored bug report with a precise, verified root cause: the .git/config fallback path in gitServiceImpl.ts does not handle linked worktrees, where .git is a file pointing at a gitdir with an optional commondir. Confirmed still present on current main; no fix has landed yet.

## Change summary

Copilot's remote-discovery fallback fails with ENOTDIR for linked Git worktrees because it assumes `.git/config` is always a directory path, instead of resolving the worktree's `gitdir`/`commondir` indirection.

## Best solution

In extensions/copilot/src/platform/git/vscode-node/gitServiceImpl.ts's getRepositoryFetchUrls, before reading `<repositoryRoot>/.git/config`, check if `.git` is a file; if so, parse its `gitdir:` pointer, then read an optional `commondir` file inside that gitdir (relative path, default `../..` semantics) to locate the shared `config`, and read remotes from there while preserving the existing regular-repository path.
