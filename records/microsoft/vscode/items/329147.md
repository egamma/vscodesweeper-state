# Issue #329147 — `git.worktreeIncludeFiles` copies tracked files into a new worktree

[https://github.com/microsoft/vscode/issues/329147](https://github.com/microsoft/vscode/issues/329147)

## Summary

Traced and confirmed in current source (HEAD a6162282): the upward directory-walk in `_getWorktreeIncludePaths()` adds non-ignored ancestor folders to the copy set, so a recursive copy overwrites tracked files in the new worktree with the parent worktree's content. An open PR (#329148, 'Fixes #329147') already implements a fix, so this stays open pending that PR landing rather than being closed now.

## Change summary

`git.worktreeIncludeFiles` is documented to copy only gitignored files matching the glob, but the implementation's ancestor-directory walk pulls in whole (non-ignored) top-level folders, so tracked files get recursively overwritten with the parent worktree's versions when a new worktree is created.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/329148, which replaces the ancestor-walk with a pattern-based approach (only `**`-terminated folder patterns that are themselves git-ignored get coalesced; everything else copies matched files individually) — this matches the documented contract and fixes the data-loss reproduction described here.

## Evidence

- **source trace:** extensions/git/src/repository.ts _getWorktreeIncludePaths() (around L2060-L2073) walks up from each gitignored file and adds ancestor directories to gitIgnoredPaths even when those directories are not themselves gitignored; filePatternBases.has(dir) is checked only after the add, and for `**/...` patterns the base is always this.root, so the walk reaches the top-level folder before stopping.
- **recursive copy:** _copyWorktreeIncludeFiles() (around L2107) does `cp(sourceFile, targetFile, { recursive: true, ... })` on every entry in the resulting set, so a wrongly-included top-level folder gets fully copied, overwriting tracked files with the parent worktree's version.
- **current main unaffected:** Repo HEAD is a61622829b436d1714f647da5c9f6cfad4dd37fe; no recent commits touch repository.ts's worktree-include logic, so the defect is still present.
- **linked fix PR:** https://github.com/microsoft/vscode/pull/329148 is open, titled 'fix: do not copy tracked files into a new worktree', body says 'Fixes #329147', and replaces the traversal with a per-pattern approach that only folds in a folder when the pattern ends in `**` and the folder itself is git-ignored.
