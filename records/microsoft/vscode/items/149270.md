# Issue #149270 — Allow parameter hints and completion documentation to appear in a docked panel instead of floating over the code

[https://github.com/microsoft/vscode/issues/149270](https://github.com/microsoft/vscode/issues/149270)

## Summary

Keep this accepted, well-supported request open: current parameter hints and completion documentation remain editor overlays, and the suggested extension does not cover the full request. The older positioning issue covers only parameter hints, while a later docking request was explicitly closed as a duplicate of this one.

## Change summary

Allow live parameter hints and completion documentation to appear in dockable views without obscuring the code being edited.

## Best solution

Provide an opt-in, language-independent docked documentation experience that follows the active invocation and focused completion item while preserving the default popup workflow. Decide whether that experience is built into the workbench or enabled through extension APIs before implementation.

- **Validation:** In a language with signature help and completion documentation, dock the documentation surface in the sidebar and bottom panel. Type a multi-argument invocation and navigate completion items with the keyboard: signature and active-parameter information must update, completion documentation must follow the focused item, and code must remain unobscured. Disable the optional presentation and verify the existing popup workflow still works.
- **Behavior:**

  > Users can read live parameter hints and completion documentation outside floating editor popups while continuing to type and compare their code with the signature. Documentation follows the active invocation and focused completion item rather than substituting hover information or retaining unrelated stale text. Acceptance covers sidebar and bottom-panel placement, keyboard completion navigation, active-parameter changes and unchanged default popup behavior. The reporter's later clarification also asks that hover and invocation information remain distinguishable and viewable together.
- **Trace:**

  > ParameterHintsController in src/vs/editor/contrib/parameterHints/browser/parameterHints.ts receives ParameterHintsModel.onChangedHints and renders through ParameterHintsWidget, whose getPosition in parameterHintsWidget.ts anchors a content widget above or below the cursor. SuggestWidget in src/vs/editor/contrib/suggest/browser/suggestWidget.ts resolves the focused completion item and renders its documentation through SuggestDetailsOverlay in suggestWidgetDetails.ts; placement stays relative to the completion popup. Existing editor settings control enablement, cycling and inline details, not workbench docking. Provider-query commands in src/vs/workbench/api/common/extHostApiCommands.ts offer hover and signature retrieval, but the trace does not establish an extension contract for following the complete focused-item documentation lifecycle. https://github.com/microsoft/vscode/issues/33752 addresses narrower popup positioning, and https://github.com/microsoft/vscode/issues/212433 was consolidated into this request. Preserve language-provider semantics, cancellation of stale documentation requests, keyboard behavior and the default popup experience; uncertainty begins at the product boundary between a built-in docked view and extension-enabled presentation.
- **Open decisions:**
  - Should VS Code supply the docked documentation views itself, or expose the live documentation state through an extension API so extensions supply those views?
  - Should the first supported experience include separately dockable hover information alongside parameter hints and completion documentation, as requested in the reporter's later clarification?
