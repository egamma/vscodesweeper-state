# Issue #336164 — Renaming MCP server in JSON appends it to MCP list

[https://github.com/microsoft/vscode/issues/336164](https://github.com/microsoft/vscode/issues/336164)

## Summary

The defect remains source-reproducible on current main: renaming a JSON-configured MCP server adds the new list item but the installed-view merge retains the old ID. This team-authored issue should remain open for a bounded list-reconciliation fix.

## Change summary

Renaming an MCP server key in JSON leaves the former name in the installed-server list alongside the new name.

## Best solution

Make the installed MCP view reconcile its model with the current local server identities so a rename replaces the old entry while preserving normal updates and ordering.

## Evidence

- **source reproduction:** src/vs/platform/mcp/common/mcpManagementService.ts detects a renamed JSON key as one removed server plus one added server and emits uninstall/install events from AbstractMcpResourceManagementService.updateLocal.
- **root cause:** src/vs/workbench/contrib/mcp/browser/mcpServersView.ts McpServersListView.mergeChangedMcpServers inserts the new ID, but removes a missing old ID only when another current server has the old server's name. After a rename that name no longer exists, so the former entry remains in the displayed model.
- **service state:** src/vs/workbench/contrib/mcp/browser/mcpWorkbenchService.ts removes the old local server in onDidUninstallMcpServer and adds the renamed server through onDidInstallMcpServers, confirming that the stale item is confined to the view-model merge rather than the authoritative local-server collection.
