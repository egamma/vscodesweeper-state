# Issue #174667 — Wrong indent level after `break;` in a switch statement PHP

[https://github.com/microsoft/vscode/issues/174667](https://github.com/microsoft/vscode/issues/174667)

## Summary

The PHP indentation gap remains in current source: Enter after a switch-case break inherits the statement indentation rather than returning to the case-label level. Keep this reopened report open; the newer matching report corroborates it but cannot replace it as the canonical issue.

## Change summary

Return the cursor to case-label indentation when Enter is pressed after a break statement terminating a PHP switch case.

## Best solution

Make PHP switch-case editing preserve sibling case alignment without changing the indentation of the break statement itself or misidentifying breaks inside nested loops. Coordinate this with the syntax-aware indentation direction already identified by a maintainer.

- **Behavior:**

  > In a PHP switch, pressing Enter after a break that terminates a case should position the next line at the sibling case-label indentation. The break statement itself must remain indented inside its case. Typing successive cases must not accumulate indentation, and breaks within nested loops must not incorrectly move the cursor to the enclosing switch's case-label level.
- **Trace:**

  > The built-in PHP extension registers extensions/php/language-configuration.json, whose regex indentation and Enter rules do not model switch-case termination. OnEnterSupport.onEnter has no matching action for an ordinary case-body break; getInheritIndentForLine and getIndentForEnter in src/vs/editor/common/languages/autoIndent.ts consequently preserve its indentation. The existing PHP typing suite in src/vs/editor/contrib/indentation/test/browser/indentation.test.ts provides a regression harness and uses shared PHP rule fixtures. The unresolved technical boundary is how to obtain enough enclosing-language context to distinguish a case-terminating break from a nested-loop break; a blanket break-based outdent does not establish that distinction. Preserve unrelated languages, comment handling, and existing single-line control-statement behavior. Coordinate with the maintainer's syntax-aware direction at https://github.com/microsoft/vscode/issues/244021#issuecomment-2750776042 rather than assuming that work has already shipped.
