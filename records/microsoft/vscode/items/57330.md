# Issue #57330 — Settings UI lacks concept of inherited default value

[https://github.com/microsoft/vscode/issues/57330](https://github.com/microsoft/vscode/issues/57330)

## Summary

The core request — settings declaring their default is inherited from another setting, with the UI resolving and displaying that value — remains unimplemented on main. The existing `defaultValueSource` infrastructure only tracks extension-provided overrides, not cross-setting inheritance. Keeping open as a valid backlog item.

## Change summary

Settings UI should display the resolved inherited default (e.g. the editor font size) instead of the raw sentinel value (e.g. 0) when one setting's default depends on another.

## Best solution

Add schema metadata (e.g. `defaultDependsOn: 'editor.fontSize'`) to setting registrations so the settings editor can resolve and display the real effective default. This extends the existing `defaultValueSource` machinery in `src/vs/platform/configuration/common/configurationRegistry.ts` and the rendering in `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`.
