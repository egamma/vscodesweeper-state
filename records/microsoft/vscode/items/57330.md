# Issue #57330 — Settings UI lacks concept of inherited default value

[https://github.com/microsoft/vscode/issues/57330](https://github.com/microsoft/vscode/issues/57330)

## Summary

The requested capability is still missing: Settings displays the numeric sentinel rather than the effective value inherited from another setting. The added descriptions explain the fallback but do not implement it; retain this accepted Backlog request for settings-owner design.

## Change summary

Let Settings represent defaults inherited from another setting, showing the effective editor font size instead of the suggest widget's internal zero sentinel.

## Best solution

Define a consistent way to display a setting's effective inherited value and its source without turning inheritance into an explicit override. Start with editor.suggestFontSize and editor.suggestLineHeight, preserving existing JSON values and runtime fallback behavior.

## Plan brief

- **Likely files:** `src/vs/platform/configuration/common/configurationRegistry.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTreeModels.ts`, `src/vs/workbench/contrib/preferences/browser/settingsTree.ts`
- **Validation:** After agreeing on presentation, set editor.fontSize to 20 with editor.suggestFontSize unset and verify Settings communicates the effective size 20 and its inherited source. Change the editor font size and verify the inherited presentation updates without writing an override; explicitly configure a suggest font size and verify it wins, then reset and verify inheritance returns. Cover the agreed semantics with settings model/renderer tests and repeat for suggest line height.
- **Behavior:**

  > Settings currently shows 0 for an unset suggest font size although the suggest widget uses the editor font size. The requested experience makes the effective inherited value understandable without requiring knowledge of the sentinel. Explicit overrides must remain distinguishable from inheritance, and inspecting an inherited value must not create an override. Acceptance includes changing the source setting, explicitly overriding the dependent setting, and resetting it back to inheritance.
- **Trace:**

  > editorOptions.ts registers the suggest size and line-height options with numeric default 0 and explanatory markdown descriptions. SettingsTreeSettingElement.update in settingsTreeModels.ts selects the inspected default, and SettingNumberRenderer in settingsTree.ts renders that number directly; suggestWidget.ts separately resolves zero to fontInfo.fontSize at runtime. IConfigurationPropertySchema currently has no general metadata for a default derived from another setting. Preserve existing JSON sentinel compatibility and runtime fallback semantics; configuration-scope inheritance in https://github.com/microsoft/vscode/issues/58038 and https://github.com/microsoft/vscode/issues/341044 is separate work. The remaining uncertainty is the user-facing representation and editing contract, not whether the existing descriptions satisfy the request.
- **Open decisions:**
  - Should an inherited setting show its effective number in the editable input, or retain an explicit inheritance state with the effective number displayed alongside it?
  - When an inherited value is displayed, what user interaction creates an explicit override equal to that value, and how should Reset communicate the return to inheritance?
