# Issue #200609 — Improve settings UI for array based setting types

[https://github.com/microsoft/vscode/issues/200609](https://github.com/microsoft/vscode/issues/200609)

## Summary

Keep open: the Settings UI still accepts literal array entries without explaining how they differ from JSON examples in setting descriptions. Both maintainers acknowledged this core UI improvement; no verified canonical or covering implementation was found.

## Change summary

Clarify that array-setting inputs accept individual literal values rather than JSON property declarations or JSON string syntax.

## Best solution

Make array-entry guidance distinguish literal UI input from settings.json examples while preserving legitimate quotes in string values. Agree on whether shared UI guidance suffices or extension authors need separate descriptions for the two editing surfaces.

Manually check the guidance with keyboard navigation and a screen reader.
- **Behavior:**

  > A user editing an array-of-strings setting should understand that each UI row takes one literal value, whereas a full property declaration belongs in settings.json. For the reported example, entering --disable=C0111 should produce one array element without requiring the setting name, brackets, or JSON delimiter quotes. Guidance must not imply that quotes are forbidden within valid string content. Existing JSON editing and literal-value persistence must remain unchanged.
- **Trace:**

  > ListSettingWidget.renderEdit and renderInputBox in src/vs/workbench/contrib/preferences/browser/settingsWidgets.ts display a generic Item... placeholder and forward inputBox.value unchanged. AbstractSettingRenderer.renderSettingElement in src/vs/workbench/contrib/preferences/browser/settingsTree.ts displays the contributed description, while SettingArrayRenderer.computeNewList preserves the entered text as an array element. The description schema inspected in src/vs/workbench/api/common/configurationExtensionPoint.ts does not distinguish UI instructions from JSON instructions. The maintainers at https://github.com/microsoft/vscode/issues/200609 agreed that the confusion belongs to the shared Settings UI, not Pylint. Preserve literal string semantics rather than interpreting pasted JSON or stripping quotes. The remaining uncertainty is the user-facing guidance contract, not the persistence path.
- **Open decisions:**
  - Should shared array-entry guidance explain the UI-versus-JSON distinction for all settings, or should configuration contributors be able to supply separate descriptions for the Settings UI and settings.json?
