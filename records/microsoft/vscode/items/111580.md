# Issue #111580 — Align upload & download progress between desktop and web

[https://github.com/microsoft/vscode/issues/111580](https://github.com/microsoft/vscode/issues/111580)

## Summary

Keep open: current main still gives native downloads and external imports only generic progress, while the web path reports byte-level detail. An open PR implements the native-download portion, so it should be reviewed rather than competing with another implementation.

## Change summary

Align desktop upload and download progress with the detailed byte, size, rate, and file-count reporting available in web.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/331673 for native download byte progress, then retain this issue for the remaining upload/import alignment and a general file-service progress contract shared across file operations.

## Evidence

- **upload/import gap:** ExternalFileImport.importResources in src/vs/workbench/contrib/files/browser/fileImportExport.ts delegates copies through ExplorerService.applyBulkEdit with only a generic “Copying” progress label; it has no equivalent of the browser upload path's byte-level progress calculation.
- **open implementation:** https://github.com/microsoft/vscode/pull/331673 is open and explicitly addresses the native-download portion of https://github.com/microsoft/vscode/issues/111580 by propagating buffered cross-provider copy progress through FileService, working-copy, and bulk-edit layers.
