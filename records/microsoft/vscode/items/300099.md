# Issue #300099 — Only smooth upwards scrolling

[https://github.com/microsoft/vscode/issues/300099](https://github.com/microsoft/vscode/issues/300099)

## Summary

Keep open: current main now preserves the viewport when temporary thinking or tool content collapses, but automatic chat scrolling still lacks the requested smooth upward motion. This issue remains the canonical report for that unfinished UX work.

## Change summary

Prevent chat progress sections from causing downward viewport jumps when they collapse, and animate subsequent automatic upward scrolling smoothly.

## Best solution

Retain the scroll-height reservation used for automatic progress collapses, then make chat auto-follow transitions move smoothly upward while preserving user scroll intent and respecting reduced-motion preferences.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts`, `src/vs/workbench/contrib/chat/test/browser/widget/chatListWidget.test.ts`, `src/vs/workbench/test/browser/componentFixtures/chat/chatScrollAnchoring.fixture.ts`
- **Validation:** Extend the chat-list scrolling tests or component fixture to sample viewport position across animation frames: automatic movement must never move downward, must settle at the intended content, must stop when the user scrolls away, and must avoid animation under reduced motion.
- **Behavior:**

  > When temporary thinking or tool progress collapses, visible transcript content must not jump downward. Subsequent automatic following should advance smoothly upward so streamed text remains readable. User scrolling must suspend auto-follow, and reduced-motion mode must retain stable positioning without animation.
- **Trace:**

  > Automatic collapse anchoring is already present in ChatListWidget through preserveScrollPosition, _scrollHeightReservation, and updateBottomPadding in src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts; its behavior is covered in chatListWidget.test.ts. Commit 97574e8ef9c8b1c4bb5e55cb953fbab438480a9d introduced the reservation, and https://github.com/microsoft/vscode/pull/337759 subsequently stabilized it. The remaining path is revealLastItem and the other callers that repeatedly reveal the bottom while dynamic row heights change. The related maintainer investigation at https://github.com/microsoft/vscode/issues/274099#issuecomment-3764890853 reports that list smooth scrolling was canceled or desynchronized by those updates. Preserve the existing collapse reservation, auto-scroll holds, explicit Scroll to Bottom behavior, and reduced-motion behavior; the uncertainty is in coordinating the animation with dynamic layout rather than in the requested outcome.

## Evidence

- **current source:** src/vs/workbench/contrib/chat/browser/widget/chatListWidget.ts uses preserveScrollPosition and updateBottomPadding to reserve collapse space, while revealLastItem still follows content through an ordinary tree reveal without a chat-specific smooth-scroll path.
