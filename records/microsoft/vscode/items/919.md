# Issue #919 — Don't activate dirty file indicator if the file state matches the previous written state

[https://github.com/microsoft/vscode/issues/919](https://github.com/microsoft/vscode/issues/919)

## Summary

Keep open: current main clears dirty state when undo returns to the saved model version, but not when independent edits produce identical content. This Backlog request has 67 community upvotes and remains the canonical issue for that gap.

## Change summary

Clear the dirty-file indicator whenever the editor content equals the last saved content, including after no-op extension edits or manually reversed changes.

## Best solution

Extend text-file dirty tracking with a low-overhead content-equality mechanism that handles equivalent content outside the normal undo path, without comparing or hashing the entire buffer after every edit.
