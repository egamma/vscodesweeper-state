# Issue #919 — Don't activate dirty file indicator if the file state matches the previous written state

[https://github.com/microsoft/vscode/issues/919](https://github.com/microsoft/vscode/issues/919)

## Summary

The central request remains unmet: current dirty-state tracking recognizes returning to a saved undo version, not independently editing back to identical saved contents. Keep this accepted, well-supported request open for a performance-conscious design.

## Change summary

Make the dirty indicator reflect differences from saved contents rather than edit-history identity, including edits that restore identical text.

## Best solution

Provide content-equivalence-aware dirty tracking in the text-file model without degrading typing latency or weakening save safety. Settle whether this changes the default behavior or is opt-in before implementation.
