# Issue #211063 — Verbose Hover: Hover jumps when there is not enough space

[https://github.com/microsoft/vscode/issues/211063](https://github.com/microsoft/vscode/issues/211063)

## Summary

Keep open: current hover layout still recalculates placement when expanded content grows, and the maintainer explicitly reopened this request after the earlier fix caused a regression. A placement policy that keeps verbosity controls stable remains unresolved.

## Change summary

Prevent expanding a verbose hover from moving it across the hovered line and displacing the repeatedly used verbosity controls.

## Best solution

Agree on how expanded editor hovers should balance stable placement, available space, and access to large content, then implement that behavior in the hover layout path without reintroducing the previous regression.

- **Behavior:**

  > Expanding a verbose hover can move it from above the hovered line to below it, displacing controls the user is repeatedly clicking. The finished interaction should keep verbosity controls predictably reachable while retaining access to expanded content. Acceptance must cover expansion and collapse at different viewport positions, both hover-side preferences, and content larger than the available space. The intended clipping, placement, and editor-scrolling behavior must be agreed before implementation.
- **Trace:**

  > ContentHoverWidget.handleContentsChanged in src/vs/editor/contrib/hover/browser/contentHoverWidget.ts measures updated content and recalculates _positionPreference. ResizableContentWidget._findPositionPreference in src/vs/editor/contrib/hover/browser/resizableContentWidget.ts chooses a side from the current height and available space; editor.hover.above is only a preference. ContentHoverWidgetWrapper supplies the content-change callback to the rendered hover. The maintainer confirms the interaction problem at https://github.com/microsoft/vscode/issues/211063#issuecomment-2072270023, but leaves the user-visible policy open. Preserve ordinary hover behavior and content accessibility; changing default verbosity or unrelated diagnostic hover behavior is outside the central request.
- **Open decisions:**
