# Issue #206365 — Menubar disappears, wrong fullscreen detection

[https://github.com/microsoft/vscode/issues/206365](https://github.com/microsoft/vscode/issues/206365)

## Summary

The false fullscreen detection remains present on current main and directly hides the classic menubar on a full-size secondary display. A later report of the same defect was closed out of scope, but this issue's accepted `bug` classification bars that decline close without a later maintainer decision in this thread.

## Change summary

On vscode.dev under Linux, maximizing the window on a secondary display without a taskbar is mistaken for fullscreen and hides the classic menubar.

## Best solution

Distinguish confirmed browser fullscreen from the full-screen-sized-window heuristic, or prevent guessed fullscreen state from controlling titlebar and menubar visibility. A maintainer should first reconcile that work with the later out-of-scope decision on https://github.com/microsoft/vscode/issues/229058.

## Evidence

- **current source path:** src/vs/base/browser/dom.ts still makes `detectFullscreen` return browser fullscreen when a Linux window's outer dimensions equal its screen dimensions; the adjacent comment explicitly acknowledges that a hidden taskbar can make this a false-positive guess.
- **observable consequence:** src/vs/workbench/services/host/browser/browserHostService.ts publishes `!!detectFullscreen(window)` after viewport resize, while src/vs/workbench/services/layout/browser/layoutService.ts hides a `classic` custom titlebar when `isFullscreen(window)` is true and the menubar is not toggled.
- **confirmed matching report:** https://github.com/microsoft/vscode/issues/229058 reports the same fullscreen false positive and menubar disappearance. A maintainer confirmed the no-dock/no-title-area behavior at https://github.com/microsoft/vscode/issues/229058#issuecomment-2365034414.
