# Issue #167702 — Proper fix for line endings

[https://github.com/microsoft/vscode/issues/167702](https://github.com/microsoft/vscode/issues/167702)

## Summary

Valid feature request to handle corrupted CR+CR+LF sequences as a single line ending. The text buffer correctly treats CR and CRLF as separate line terminators per spec — this asks for heuristic recovery from malformed FTP transfers. No work has been done on main, no duplicate exists, and it earned its Backlog placement with 20 upvotes.

## Change summary

When opening a file containing CR+CR+LF sequences (from buggy FTP servers), VS Code interprets them as two line endings instead of one, doubling blank lines.

## Best solution

Add optional heuristic detection in the text buffer builder (pieceTreeTextBufferBuilder.ts) that recognizes CR+CR+LF as a corrupted single line ending and normalizes it, likely behind a setting. The fix touches EOL detection in `src/vs/editor/common/model/pieceTreeTextBuffer/pieceTreeTextBufferBuilder.ts`. This is a niche scenario so a setting gate is appropriate.
