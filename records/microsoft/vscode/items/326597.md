# Issue #326597 — Extension-contributed language model providers lose historical thinking needed for vLLM preserve_thinking

[https://github.com/microsoft/vscode/issues/326597](https://github.com/microsoft/vscode/issues/326597)

## Summary

The public-history reconstruction path still discards thinking on current main, so a real gap remains. Related historical-thinking improvements do not establish that this path is fixed, and the newer overlapping report cannot replace this re-reviewed issue.

## Change summary

Preserve historical assistant thinking when Copilot reconstructs public chat history and sends subsequent requests to extension-contributed language model providers.

## Best solution

Preserve structured reasoning through Copilot's public-history reconstruction and subsequent prompt rendering, with an end-to-end provider-request check. Cover both reconstructed and cached turns while retaining existing model-identity and protocol-specific replay restrictions.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts`, `extensions/copilot/src/extension/prompt/common/conversation.ts`, `extensions/copilot/src/extension/prompts/node/panel/conversationHistory.tsx`, `extensions/copilot/src/extension/prompts/node/panel/toolCalling.tsx`, `extensions/copilot/src/platform/endpoint/vscode-node/extChatEndpoint.ts`
- **Validation:** Use a recording contributed provider that emits identifiable thinking and visible text, then inspect its next request after a follow-up. Exercise both cached-turn reuse and public-history reconstruction without a cached Turn; assert preserved reasoning text and metadata on eligible same-model history, unchanged visible text, and unchanged model-switch/protocol exclusions. Add executable reconstruction-to-provider regression coverage; no tests were run during this read-only review.
- **Behavior:**

  > A contributed provider's historical reasoning must not disappear solely because Copilot reconstructs its conversation from public response history. On a same-model follow-up eligible for reasoning replay, the provider should receive the prior reasoning as structured LanguageModelThinkingPart content, with its associated metadata intact. Cached and reconstructed histories should agree for equivalent input. Visible assistant text and existing restrictions on replaying foreign or incompatible reasoning must remain unchanged.
- **Trace:**

  > addHistoryToConversation in extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts first attempts findExistingTurnFromVSCodeChatHistoryTurn, then falls back to createTurnFromVSCodeChatHistoryTurns. The fallback flattens selected response parts into text and drops ChatResponseThinkingProgressPart, whose fields are value, id and metadata. In panel/conversationHistory.tsx, plain history renders responseMessage text, whereas tool-aware history can consume result metadata's toolCallRounds. panel/toolCalling.tsx additionally gates reasoning by model identity and protocol capabilities; extChatEndpoint.ts can already emit outgoing LanguageModelThinkingPart when supplied a thinking envelope. The remaining investigation is how reconstructed structured reasoning reaches the active prompt consumer without duplicating existing round metadata, and when the reporter's normal follow-up enters the fallback rather than cached reuse. Preserve existing protocol and model-switch boundaries. https://github.com/microsoft/vscode/issues/332870 covers related but newer history-loss paths; https://github.com/microsoft/vscode/issues/246993 supplies API-contract context, not a demonstrated fix.

## Evidence

- **Current source confirms reconstruction loss:** extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts: addHistoryToConversation invokes createTurnFromVSCodeChatHistoryTurns when no cached Turn is found. Its response mapping handles markdown, file trees, content and anchors, but drops other parts and joins the remainder into a string before setResponse.
- **Thinking part does not enter the content fallback:** src/vs/workbench/api/common/extHostTypes.ts: ChatResponseThinkingProgressPart contains value, id and metadata, not content. It therefore reaches the null branch of the reconstruction mapping, losing both reasoning and its structured metadata.

Restoring thinking at reconstruction alone needs verification against the actual consuming prompt path.
