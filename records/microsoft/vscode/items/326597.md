# Issue #326597 — Extension-contributed language model providers lose historical thinking needed for vLLM preserve_thinking

[https://github.com/microsoft/vscode/issues/326597](https://github.com/microsoft/vscode/issues/326597)

## Summary

Confirmed from source: `createTurnFromVSCodeChatHistoryTurns` in the Copilot extension reconstructs historical turns but does not handle `ChatResponseThinkingProgressPart`, so extension-contributed language model providers never receive prior reasoning tokens. The bug is still present on current main.

## Change summary

Extension-contributed language model providers lose historical thinking/reasoning parts when Copilot reconstructs conversation history for follow-up requests.

## Best solution

Add a `ChatResponseThinkingProgressPart` case to the response-part mapping in `createTurnFromVSCodeChatHistoryTurns` (extensions/copilot/src/extension/prompt/node/chatParticipantRequestHandler.ts, lines 420-432) so that thinking parts are preserved in the reconstructed `Turn` and forwarded to extension-contributed providers on subsequent requests.
