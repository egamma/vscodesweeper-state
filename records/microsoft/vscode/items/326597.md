# Issue #326597 — Extension-contributed language model providers lose historical thinking needed for vLLM preserve_thinking

[https://github.com/microsoft/vscode/issues/326597](https://github.com/microsoft/vscode/issues/326597)

## Summary

Confirmed on current main: `createTurnFromVSCodeChatHistoryTurns` in chatParticipantRequestHandler.ts flattens `ChatResponseTurn.response` parts to plain text and has no branch for `ChatResponseThinkingProgressPart`, so reconstructed history loses structured reasoning — matching the reporter's diagnosis exactly.

## Change summary

Extension-contributed language model providers never receive historical `LanguageModelThinkingPart` on follow-up turns, because Copilot's chat-history-to-internal-Turn reconstruction discards thinking parts, breaking providers (e.g. vLLM with `preserve_thinking`, Qwen3.6, GLM5.2) that require prior reasoning echoed back.

## Best solution

Extend the internal `Turn`/`TurnMessage` model (extensions/copilot/src/extension/prompt/common/conversation.ts) to optionally carry structured thinking data (reusing the existing `ThinkingData` shape in src/platform/thinking/common/thinking.ts), populate it in `createTurnFromVSCodeChatHistoryTurns` when a response part is `ChatResponseThinkingProgressPart`, and thread it through to the generic LM endpoint's history-to-message conversion so contributed providers can rebuild `LanguageModelThinkingPart`.
