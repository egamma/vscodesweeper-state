# Issue #340976 — Renderer livelocks in `fallocate` EINTR loop when automatic renderer profiling (`application.experimental.rendererProfiling`) starts — Settings editor freezes

[https://github.com/microsoft/vscode/issues/340976](https://github.com/microsoft/vscode/issues/340976)

## Summary

Thanks for the detailed diagnosis. The report is complete (strace, perf, a working workaround) but depends on the environment (Linux, software compositing, snap) and can't be confirmed from source. The most likely root cause is in Chromium, where fallocate is retried on EINTR under SIGPROF, and the auto-profiler is what triggers it. Keeping this open.

## Change summary

On Linux with hardware acceleration disabled, the automatic renderer profiler starts after a long task and the renderer livelocks in a fallocate/EINTR loop.

## Best solution

Confirm the livelock and, if confirmed, report it upstream to Chromium. In VS Code, mitigate by lowering the sampling rate, skipping auto-profiling when GPU compositing is disabled on Linux, or defaulting the setting to off on Linux. The workaround for now is to set application.experimental.rendererProfiling to false.
