# Issue #247592 — NES accessibility - aria announcement order

[https://github.com/microsoft/vscode/issues/247592](https://github.com/microsoft/vscode/issues/247592)

## Summary

Team-authored bug, still present on main. The ARIA announcement order for NES is wrong because `playSignal` announces 'Next Edit Suggestion' via `status()`, then `_provideScreenReaderUpdate` immediately calls `alert()` with the accessible-view hint — the `alert` interrupts/preempts the `status`, so the hint is heard first.

## Change summary

When a NES suggestion appears, the screen reader announces the accessible-view hint before the 'Next Edit Suggestion' label, reversing the expected order.

## Best solution

In `_provideScreenReaderUpdate` (inlineCompletionsController.ts ~line 420), combine the signal announcement message and the hint into a single `alert()` call with the correct order, or reverse the call sequence so the hint `alert()` fires after the signal announcement has been processed. The NES branch (line 348) passes empty content, so the hint is the only text — but the signal service also announces via `status()` on line 342, creating two competing ARIA live-region updates.
