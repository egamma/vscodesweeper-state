# Issue #247592 — NES accessibility - aria announcement order

[https://github.com/microsoft/vscode/issues/247592](https://github.com/microsoft/vscode/issues/247592)

## Summary

Still reproduces on main: for NES, the accessibility signal announcement ('Next Edit Suggestion') and the screen reader alert ('Inspect this in the accessible view') are fired independently, and the hint alert wins the screen reader queue, producing an inverted announcement order. No commit references this issue and the code path is unchanged.

## Change summary

When a Next Edit Suggestion appears, the screen reader announces 'Inspect this in the accessible view (Alt+F2)' before 'Next Edit Suggestion' — the order should be reversed.

## Best solution

In `_provideScreenReaderUpdate` (inlineCompletionsController.ts ~line 427), for the NES case where `content` is empty, prepend the signal's announcement message before the hint so a single `alert()` call delivers both in the correct order, rather than relying on two independent announcement mechanisms racing each other.
