## Change summary

## Best solution

Establish whether current Modern UI still regresses interaction latency against the classic layout on the reported Windows configuration, then address any remaining measured bottleneck in workbench styling or layout. ## Evidence

- **Reported trigger and corroboration:** https://github.com/microsoft/vscode/issues/328757 reports resizing and typing stutter in 1.131.0 on Windows 10 with an RTX 3080, eliminated by disabling workbench.experimental.modernUI and reloading. The first two comments on 2026-08-03 independently corroborate the Modern UI-associated slowdown. These confirm the historical report, not its persistence on current main.
- **Related measured regression:** https://github.com/microsoft/vscode/issues/328394#issuecomment-5144757263 diagnoses Modern UI resize traces dominated by style recalculation: repeated pane-header getComputedStyle reads and list-row :has() selectors. This is strong supporting evidence for a core performance defect, but does not independently diagnose this reporter's typing slowdown.
- **Landed related fix:** https://github.com/microsoft/vscode/pull/328462 merged on 2026-08-04 as 86c1d284d3aafa83b03b3d8116d1a77775cc7e0b and fixes https://github.com/microsoft/vscode/issues/328394. Its paneview.ts diff removes resolveHeaderSize's computed-style read and per-layout cache invalidation, replaces header sizing with globalPaneHeaderSize, and replaces agent-session relational row selectors. Its stated scope and verification concern resize and startup; it does not demonstrate resolution of this report's complete resizing-and-typing symptoms.
- **Current source differs from reported build:** src/vs/base/browser/ui/splitview/paneview.ts:129-130 now reads globalPaneHeaderSize directly, and Pane.layout at lines 308-318 does not resolve header size through getComputedStyle. src/vs/workbench/contrib/modernUI/browser/modernUI.contribution.ts applies that global size and registers at BlockRestore. The diagnosed older pane-header bottleneck is therefore absent from current source.
- **Performance improvements are not proof of complete resolution:** src/vs/workbench/contrib/modernUI/CSS_PERFORMANCE.md documents an August CSS audit, no active :has() selectors in Modern UI styles, and an executable resize/tab/panel benchmark. It explicitly says the retained audit changes have no statistically isolated benefit in its measured workbench scenario. Neither this documentation nor source inspection verifies this reporter's Windows interaction latency.
