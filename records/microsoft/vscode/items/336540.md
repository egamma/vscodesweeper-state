# Issue #336540 — Allow TreeItem.command to declare an alternative command for modifier-click

[https://github.com/microsoft/vscode/issues/336540](https://github.com/microsoft/vscode/issues/336540)

## Summary

The extension API still lacks an alternative command for tree-row activation; existing inline actions and editor-opening behavior only partially cover the request. Keep this Backlog Candidates item open for the community process: the older related request concerns QuickPick, not the same observable tree-row interaction.

## Change summary

Allow extensions to declare an alternative tree-item command invoked by modifier-click without globally changing ordinary clicks.

## Best solution

Define an opt-in tree activation API with consistent platform modifier and keyboard semantics, preserving existing selection and editor-opening behavior. Review the public interaction contract before implementation rather than treating inline action buttons or global folder-opening settings as equivalent coverage.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTreeViews.ts`, `src/vs/workbench/common/views.ts`, `src/vs/workbench/browser/parts/views/treeView.ts`
- **Validation:** After agreeing the API contract, exercise a sample TreeDataProvider with distinct primary and alternative commands. Verify ordinary activation, the agreed modifier-click and keyboard activation, unchanged behavior without an alternative, preservation of tree multi-selection, and existing vscode.open/vscode.diff opening semantics on supported platforms.
- **Behavior:**

  > Extensions need a per-activation alternative to a tree item's primary command, such as opening a project in another window, without changing the global default. Ordinary activation must retain its existing behavior, and items without an alternative must remain unaffected. Acceptance should verify the agreed mouse and keyboard gestures, command arguments, and compatibility with tree selection and built-in editor opening.
- **Trace:**

  > TreeItem in src/vscode-dts/vscode.d.ts and ITreeItem in src/vs/workbench/common/views.ts expose one command. src/vs/workbench/api/common/extHostTreeViews.ts:957 converts extensionTreeItem.command into that internal representation. The onDidOpen listener and resolveCommand in src/vs/workbench/browser/parts/views/treeView.ts:799–843 execute that command; only built-in editor-opening commands receive the open event as additional context. menus.alt already exists in src/vs/workbench/services/actions/common/menusExtensionPoint.ts, but applies to menu actions rather than row activation. Preserve existing multi-selection, lazy command resolution, command enablement, and editor-opening conventions. https://github.com/microsoft/vscode/issues/18064 concerns QuickPick acceptance and is related design context, not a canonical for this tree-row request. The remaining uncertainty is the public gesture/API contract, not whether the current single-command path exists.
- **Open decisions:**
  - Which modifier activates the alternative on each platform, and how should that gesture coexist with existing tree multi-selection and open-to-side gestures?
  - What keyboard activation should invoke the alternative, and should keyboard support be part of the initial public contract?
