# Issue #317445 — Agents view fails to connect to SSH hosts using ProxyJump, while main editor's SSH works

[https://github.com/microsoft/vscode/issues/317445](https://github.com/microsoft/vscode/issues/317445)

## Summary

Confirmed from source: the Agents window SSH implementation connects directly via the ssh2 library using only hostname/port, without honoring ProxyJump or ProxyCommand directives from ~/.ssh/config. The ISSHAgentHostConfig interface has no proxy fields, parseSSHGOutput does not extract them, and _connectSSH builds a direct ConnectConfig with no proxy/tunnel support. This is a real gap — the standard editor's Remote-SSH extension shells out to the system ssh binary which handles these directives natively.

## Change summary

Agents view SSH connections fail with EHOSTUNREACH when the SSH config uses ProxyJump or ProxyCommand, because the agent host's ssh2-based connection ignores these directives.

## Best solution

Extend the agent host SSH connection path to support ProxyJump/ProxyCommand. Options: (1) parse proxyjump/proxycommand from `ssh -G` output in parseSSHGOutput, add the fields to ISSHAgentHostConfig, and implement chained ssh2 connections (for ProxyJump) or child_process-based tunnels (for ProxyCommand) in _connectSSH; or (2) use the system ssh binary as a transport (like Remote-SSH does) instead of ssh2 for hosts that need proxy support. The fix lives in src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts and src/vs/platform/agentHost/common/sshConfigParsing.ts.
