## Evidence

- **Reported trigger and clipboard payload:** https://github.com/microsoft/vscode/issues/122050 supplies steps for copying JavaScript on Kubuntu 20.04 into LibreOffice, AbiWord, WPS Office, and TextMaker, with extensions disabled. Its Linux HTML contains ordinary indentation spaces under white-space: pre, whereas the Windows payload contains non-breaking space entities.
- **Independent confirmation and workaround:** https://github.com/microsoft/vscode/issues/122050#issuecomment-977939332 confirms the problem on Ubuntu GNOME. https://github.com/microsoft/vscode/issues/122050#issuecomment-1056839419 reports that copying through Google Docs preserves formatting when subsequently pasted into LibreOffice; this is a workaround, not direct-copy coverage.
- **Current source:** src/vs/editor/common/viewModel/viewModelImpl.ts:1099-1136 builds HTML with white-space: pre and calls tokenizeLineToHTML with useNbsp set to platform.isWindows. src/vs/editor/common/languages/textToHtmlTokenizer.ts emits non-breaking spaces for spaces and expanded tabs only when useNbsp is true, so Linux still relies on the receiving editor honoring CSS whitespace preservation. No receiving application was executed during this read-only review.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/338029 was verified OPEN with no merge commit and explicitly says Fixes #122050. Its diff changes the useNbsp argument from platform.isWindows to !platform.isMacintosh in viewModelImpl.ts and notebook cellDragRenderer.ts. This is an unmerged fix attempt, not evidence of completion.
- **Destination-specific symptoms:** https://github.com/microsoft/vscode/issues/122050#issuecomment-841831177 clarifies that macOS Word and TextEdit preserve formatting while Teams does not. https://github.com/microsoft/vscode/issues/122050#issuecomment-1007688463 reports different results between Teams chat and channels. These observations do not invalidate the independently reported Linux word-processor failures.
