# Issue #122050 — Copy-Paste Formatted Code Doesn't Work Properly On Linux (Works On Windows)

[https://github.com/microsoft/vscode/issues/122050](https://github.com/microsoft/vscode/issues/122050)

## Summary

The Linux clipboard interoperability defect remains present on main: VS Code emits ordinary spaces on non-Windows platforms, and multiple rich-text consumers discard that indentation. Keep this open in editor clipboard for a cross-platform solution.

## Change summary

Preserve syntax highlighting and indentation when formatted code copied on Linux is pasted into rich-text applications.

## Best solution

Make the editor's HTML clipboard representation preserve visible indentation across common rich-text consumers without introducing non-breaking spaces into subsequently copied source text. The implementation belongs in the editor clipboard HTML renderer and must account for the opposing Windows behavior tracked by https://github.com/microsoft/vscode/issues/88178.

## Evidence

- **current source:** src/vs/editor/common/viewModel/viewModelImpl.ts still calls tokenizeLineToHTML(..., platform.isWindows), so non-Windows clipboard HTML receives ordinary spaces despite relying on `white-space: pre`.
- **renderer behavior:** src/vs/editor/common/languages/textToHtmlTokenizer.ts emits `&#160;` only when useNbsp is true; otherwise indentation is serialized as literal spaces.
- **regression origin:** Commit b6138b95268aea0768f77ae8e4eacbcc0621bf07 introduced the platform split to fix https://github.com/microsoft/vscode/issues/80825, creating the non-Windows compatibility tradeoff described here.
- **confirmed impact:** The issue discussion independently confirms the malformed paste behavior on clean Linux and macOS installations and across LibreOffice, WPS Office, AbiWord, SoftMaker, and Teams.
- **related tradeoff:** https://github.com/microsoft/vscode/issues/88178 remains open for the inverse Windows problem, where non-breaking spaces preserve presentation but alter copied source text.
