# Issue #205013 — VSCode terminal seems to construct environment in a strange way

[https://github.com/microsoft/vscode/issues/205013](https://github.com/microsoft/vscode/issues/205013)

## Summary

The current server environment-building path explains the reported overwrite independently of terminal shell arguments or shell integration. Keep this accepted bug open: a terminal-level opt-out exists, but the suggested server-level bypass is still unavailable through serve-web, and no verified fix or canonical duplicate was found.

## Change summary

Preserve explicitly exported launch-environment variables in terminals opened through code serve-web instead of unexpectedly replacing them with login-shell values.

## Best solution

Establish whether terminal.integrated.inheritEnv=false fully satisfies the reported workflow on a fresh server. If server-wide environment resolution also needs to be bypassed, provide an explicit serve-web control without silently changing login-shell initialization for existing users.

## Evidence

- **Reported trigger and confirmation:** https://github.com/microsoft/vscode/issues/205013 reports launching code serve-web with TMP_VARIABLE=3 while /etc/profile.d assigns 10, then observing 10 in bash --noprofile --norc. The reporter's February 16, 2024 reply confirms the same outcome with shell integration disabled.
- **Current environment precedence:** src/vs/server/node/remoteTerminalChannel.ts:217 passes useShellEnvironment to buildUserEnvironment. src/vs/server/node/extensionHostConnection.ts:26-47 resolves a user shell environment when requested and spreads it after process.env, so login-shell values overwrite explicitly inherited values.
- **Separate login-shell resolution:** src/vs/platform/shell/node/shellEnv.ts:getResolvedShellEnv and doResolveUnixShellEnv spawn the system shell with -i -l -c for bash and cache its environment. This happens before the configured terminal shell starts; its --noprofile and --norc arguments therefore do not prevent the earlier profile evaluation. This is a source trace, not an executed Linux/WSL reproduction.
- **Existing terminal-level control:** src/vs/platform/terminal/common/terminalPlatformConfiguration.ts:395-400 documents terminal.integrated.inheritEnv, default true, as potentially sourcing a login shell. src/vs/workbench/contrib/terminal/browser/terminalProfileResolverService.ts:150-153 maps it to useShellEnvironment; setting it false bypasses user-shell resolution in buildUserEnvironment while retaining the server process environment. The thread contains no result for this maintainer-suggested setting.
- **Server-level bypass remains unwired:** The February 19, 2024 maintainer comment at https://github.com/microsoft/vscode/issues/205013 suggests --force-disable-user-env but notes CLI forwarding is missing. The server still recognizes that option in src/vs/server/node/serverEnvironmentService.ts, and shellEnv.ts honors it, but cli/src/commands/serve_web.rs:start_version does not forward it.
