# Issue #205013 — VSCode terminal seems to construct environment in a strange way

[https://github.com/microsoft/vscode/issues/205013](https://github.com/microsoft/vscode/issues/205013)

## Summary

Still reproduces on main: the shell environment resolution in buildUserEnvironment() spreads the resolved login-shell env after process.env, causing profile-sourced values to override the user's actual session variables when using `code serve-web`. The `--force-disable-user-env` workaround exists but isn't forwarded from the CLI.

## Change summary

When launching `code serve-web` with custom environment variables, the integrated terminal's environment resolves a fresh login shell that overrides user-exported variables with values from profile scripts.

## Best solution

Either ensure `VSCODE_CLI` is set when `code serve-web` is launched from a terminal (so shell env resolution is skipped, matching desktop behavior), or fix the merge order in `buildUserEnvironment` so that process.env takes precedence over the resolved shell env for variables that already exist. The `--force-disable-user-env` flag should also be properly forwarded through the CLI to the server.
