# Issue #326160 — Dead key used as a shortcut or first key of a chord leaves dead-key composition active

[https://github.com/microsoft/vscode/issues/326160](https://github.com/microsoft/vscode/issues/326160)

## Summary

Valid bug: when a dead key is consumed as the first key of a chord keybinding, `preventDefault()` suppresses the character but does not clear the browser/OS dead-key composition state, causing the next keypress to produce composed characters or stray text insertion. The keybinding service has no mechanism to cancel pending composition after matching a dead-key chord.

## Change summary

Dead key used as a shortcut or first chord key leaves the OS composition state active, causing unintended composed characters or text insertion on the next keypress.

## Best solution

After the keybinding service matches and consumes a dead-key chord, it should programmatically cancel any pending IME/dead-key composition — likely by signaling the editor's input handler (textAreaEditContext or nativeEditContext) to reset composition state. The fix would touch `src/vs/workbench/services/keybinding/browser/keybindingService.ts` (where `shouldPreventDefault` is acted on) and potentially the editor input context layer. This is distinct from #282752 (Linux Electron regression) and #307895 (macOS French layout) — those are about dead-key shortcuts not firing at all; this one is about residual composition state after a successful match.
