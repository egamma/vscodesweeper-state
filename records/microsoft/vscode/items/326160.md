# Issue #326160 — Dead key used as a shortcut or first key of a chord leaves dead-key composition active

[https://github.com/microsoft/vscode/issues/326160](https://github.com/microsoft/vscode/issues/326160)

## Summary

This is a well-supported keybinding bug that remains relevant on current main: VS Code executes the dead-key shortcut but does not cancel the browser's pending composition, allowing subsequent composition text into the editor. Route it to the keybindings area for investigation rather than consolidating it with reports where the shortcut never dispatches.

## Change summary

Consuming a dead key as a shortcut or first chord key should also clear its pending text-composition state.

## Best solution

Ensure that a successfully consumed dead-key binding cancels its pending composition across the editor input implementations, while preserving ordinary dead-key typing and active IME behavior.

## Plan brief

- **Likely files:** `src/vs/platform/keybinding/common/abstractKeybindingService.ts`, `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts`, `src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts`, `src/vs/base/common/ime.ts`
- **Validation:** On Windows with the Finnish layout, bind `[BracketRight]` and `[BracketRight] d`: each command must execute without inserting text or affecting the next keypress; unbound dead-key composition such as `¨` followed by `e` must still produce `ë`, and ordinary IME composition must remain functional.
- **Behavior:**

  > When a dead key is consumed as a complete shortcut or the first key of a chord, the command executes and that keystroke contributes no text to the editor. The pending dead-key state must also be cleared, so the next key behaves normally rather than composing with the consumed dead key. Unbound dead keys and normal IME input must retain their existing composition behavior.
- **Trace:**

  > The issue's troubleshooting log confirms that WorkbenchKeybindingService resolves both chord keys and invokes the command, after which composition text reaches the editor without another keydown. src/vs/workbench/services/keybinding/browser/keybindingService.ts only prevents the consumed keydown's default action. Chord entry in src/vs/platform/keybinding/common/abstractKeybindingService.ts calls IME.disable(), whose implementation in src/vs/base/common/ime.ts only broadcasts an enabled-state change; the native editor reacts by moving focus to its IME textarea. src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts and the textarea implementation independently accept composition updates, with no consumed-keybinding cancellation path. The boundary is dead-key composition associated with a successfully consumed binding; do not weaken the existing guard against dispatching keys that belong to an active IME or change normal unbound composition.

## Evidence

- **confirmed behavior:** The report provides a repeatable Windows/Finnish-layout case with extensions disabled. Its troubleshooting log shows both chord keys resolving and workbench.action.showCommands being invoked, while the composed text is delivered afterward without another keydown.
- **current source path:** src/vs/workbench/services/keybinding/browser/keybindingService.ts dispatches the global keydown and calls preventDefault when the binding is consumed, but exposes no operation for cancelling an already-started dead-key composition.
- **composition path:** src/vs/editor/browser/controller/editContext/native/nativeEditContext.ts forwards EditContext textupdate events into editor typing and tracks compositionstart/compositionend, but has no path tied to a consumed keybinding that discards the pending composition.
- **chord handling:** src/vs/platform/keybinding/common/abstractKeybindingService.ts disables the editor IME abstraction while waiting for another chord, but IME.disable() only changes focus/input handling; src/vs/base/common/ime.ts does not cancel the platform composition state.
- **distinct related reports:** https://github.com/microsoft/vscode/issues/282752 and https://github.com/microsoft/vscode/issues/307895 concern dead-key bindings that fail to dispatch on Linux/Wayland or macOS. Here the binding dispatches successfully and leaves composition active, so neither issue owns the same defect.
