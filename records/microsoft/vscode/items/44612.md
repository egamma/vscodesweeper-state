# Issue #44612 — [razor] comment out razor code with @* *@

[https://github.com/microsoft/vscode/issues/44612](https://github.com/microsoft/vscode/issues/44612)

## Summary

A real capability gap remains on current main: Razor recognizes `@* ... *@`, but its language configuration exposes only HTML block comments, so editor comment commands cannot select Razor comments contextually. The issue is already correctly classified and parked in the Backlog, with no verified canonical duplicate.

## Change summary

Make comment commands use HTML comments for HTML markup and Razor comments for Razor constructs in `.cshtml` and `.razor` files.

## Best solution

Define the contextual behavior for pure Razor, embedded C#, HTML, and mixed selections, then teach the Razor/comment-command integration to emit the corresponding delimiter without changing comment behavior in other languages.

## Plan brief

- **Likely files:** `extensions/razor/language-configuration.json`, `extensions/razor/syntaxes/cshtml.tmLanguage.json`, `src/vs/editor/contrib/comment/browser/lineCommentCommand.ts`, `src/vs/editor/contrib/comment/browser/blockCommentCommand.ts`, `src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts`, `src/vs/editor/contrib/comment/test/browser/blockCommentCommand.test.ts`
- **Validation:** Add targeted editor comment-command tests for Razor-tokenized HTML, Razor constructs, embedded C#, uncommenting, and mixed selections, then run `scripts/test.sh --grep "Commenting code in Razor"`.
- **Behavior:**

  > In `.cshtml` and `.razor` documents, comment commands should use `<!-- ... -->` for HTML markup and `@* ... *@` for content classified as Razor. Repeating the command should remove the delimiter it inserted. Existing C# commenting inside Razor code blocks and comment behavior in all other languages must remain unchanged. The plan must define and test what happens when one selection spans more than one syntactic region.
- **Trace:**

  > The built-in Razor extension registers `.cshtml` and `.razor` through extensions/razor/package.json. Its language configuration in extensions/razor/language-configuration.json exposes only the HTML block-comment pair, although extensions/razor/syntaxes/cshtml.tmLanguage.json tokenizes `@* ... *@` as a Razor comment. BlockCommentCommand in src/vs/editor/contrib/comment/browser/blockCommentCommand.ts resolves one comment configuration at the selection start; LineCommentCommand in src/vs/editor/contrib/comment/browser/lineCommentCommand.ts resolves at the line start and falls back to that configuration's block comment. Existing embedded-language coverage in src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts demonstrates context-sensitive handling for JSX, but Razor's desired region semantics are not represented. Preserve HTML comments for markup, C# comments inside C# regions, and behavior for every non-Razor language; uncertainty begins at how Razor and mixed-region selections should be classified.
- **Open decisions:**
  - Which Razor constructs should receive `@* ... *@`: Razor expressions/directives only, or any selection containing a Razor transition?
  - When a selection spans HTML and Razor regions, should one Razor comment wrap the whole selection, should each region receive its native delimiter, or should the existing start-position behavior remain?
  - Inside explicit Razor C# blocks, should the command preserve C# `//` or `/* ... */` comments rather than wrapping the selection in a Razor comment?

## Evidence

- **current Razor configuration:** extensions/razor/language-configuration.json declares only `blockComment: ["<!--", "-->"]`; it has no configuration that causes the comment commands to emit Razor's `@* ... *@` delimiters.
- **comment command path:** src/vs/editor/contrib/comment/browser/blockCommentCommand.ts selects one language configuration from `model.getLanguageIdAtPosition` at the selection start, while src/vs/editor/contrib/comment/browser/lineCommentCommand.ts uses the language at the start of the line and falls back to that language's block-comment pair.
- **Razor grammar:** extensions/razor/syntaxes/cshtml.tmLanguage.json contains the `razor-comment` rule and recognizes `@* ... *@` as `comment.block.razor`, so the syntax is understood for tokenization but is not available to the commenting command through the language configuration.
- **current confirmation:** A 2026 commenter confirmed that the current comment shortcut still produces `<!-- ... -->` in a Razor page: https://github.com/microsoft/vscode/issues/44612#issuecomment-4320036263.
- **related report:** The older https://github.com/microsoft/vscode/issues/24693 concerns the inverse behavior inside embedded C# blocks and is closed; it is not an open canonical duplicate for contextual Razor comments.
