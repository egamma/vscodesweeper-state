# Issue #283560 — "Chat took too long to get ready" - Remote setups (WSL, Dev Containers, Remote SSH)

[https://github.com/microsoft/vscode/issues/283560](https://github.com/microsoft/vscode/issues/283560)

## Summary

Active tracking issue for proxy misconfiguration in remote setups (WSL, Dev Containers, SSH) causing Copilot Chat timeout. A team member (TylerLeonhardt) explicitly designated this as the canonical tracking issue and routed it to chrmarti. Root cause is confirmed but no core fix has landed — only user-side workarounds exist. Should remain open.

## Change summary

Copilot Chat fails with 'took too long to get ready' in remote setups (WSL, Dev Containers) because the host's localhost proxy is unreachable from the remote side.

## Best solution

The proxy resolver in `src/vs/workbench/api/node/proxyResolver.ts` should detect when a localhost proxy is unreachable from the remote side and either skip it, fall back to direct connections, or surface a clearer diagnostic. Recent commits (e.g., proxy telemetry in `ac3c7f9168d`, proxy type recording in `3cc09c02ef5`) show ongoing investment but no fix for the core 127.0.0.1 reachability problem. The `http.useLocalProxyConfiguration` setting workaround exists but is not discoverable enough when the failure occurs.
