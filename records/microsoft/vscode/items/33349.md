# Issue #33349 — Search bar input field very narrow

[https://github.com/microsoft/vscode/issues/33349](https://github.com/microsoft/vscode/issues/33349)

## Summary

Keep open: a maintainer confirmed the Italian-locale reproduction, and current source still retains the match-count width reservation implicated in the report. The shorter translation and manual resizing are mitigations, not proof that the accepted input-readability problem is resolved.

## Change summary

Prevent long localized find-result labels from squeezing the editor find input until its search text is barely readable.

## Best solution

Make the editor find widget preserve a usable search input alongside localized result information. Retest the confirmed Italian no-results-to-results sequence before choosing the responsive layout behavior.

Manual resizing must not be required to recover a readable input in an otherwise sufficiently wide editor. First establish whether current Italian localization still exhibits the reported compression and agree on a measurable usable-input threshold. Acceptance must cover both result states and avoid regressing narrow-editor layouts or find controls.
- **Trace:**

FindWidget._updateMatchesCount in src/vs/editor/contrib/find/browser/findWidget.ts applies a minimum result-label width and monotonically increases MAX_MATCHES_COUNT_WIDTH, retaining the mechanism described in the discussion. _tryUpdateWidgetWidth responds primarily to editor width, while src/vs/editor/contrib/find/browser/findWidget.css assigns remaining flex space to the input without an explicit usable-width floor.
