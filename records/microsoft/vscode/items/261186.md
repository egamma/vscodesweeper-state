# Issue #261186 — Shortcuts inside Quick Open does not work for editor picker. Shortcuts inside editor picker?

[https://github.com/microsoft/vscode/issues/261186](https://github.com/microsoft/vscode/issues/261186)

## Summary

Keep open: Quick Open commands and the inQuickOpen context already reach the editor picker, but its acceptance handler ignores modifiers, so the requested open-to-side behavior remains missing. No verified older canonical owns this same request.

## Change summary

Support Quick Open's alternative-accept shortcut for opening an editor-picker selection in a split editor.

## Best solution

Make alternative acceptance useful in the edt editor picker while preserving ordinary acceptance into the selected editor's existing group and background-opening behavior. Reuse the existing Quick Open command and context rather than introducing parallel shortcut infrastructure.

## Evidence

- **Existing context support:** src/vs/workbench/services/quickinput/browser/quickInputService.ts sets InQuickPickContextKey on show and resets it on hide. src/vs/workbench/browser/quickaccess.ts defines that key as inQuickOpen; editor.contribution.ts additionally registers inEditorsPicker for edt, edt active, and edt mru. The source does not support the claim that inQuickOpen is unavailable inside the editor picker.
- **Remaining capability gap:** src/vs/workbench/browser/actions/quickAccessActions.ts registers workbench.action.alternativeAcceptSelectedQuickOpenItem with inQuickOpen and passes ctrlCmd: true to IQuickInputService.accept. PickerQuickAccessProvider forwards picker.keyMods to the selected item's accept callback, but BaseEditorQuickAccessProvider.doGetEditorPickItems in src/vs/workbench/browser/parts/editor/editorQuickAccess.ts ignores keyMods and always calls the selected editor's existing group.openEditor. Alternative acceptance therefore does not select a side group.
- **Partial existing alternative:** src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts supports SIDE_GROUP in openAnything based on modifiers and workbench.editor.enablePreview behavior. This serves the file/history picker, not the edt picker restricted to opened editors, so it does not fully satisfy the request.
- **Canonical search:** GitHub searches for editor picker, edt, alternativeAcceptSelectedQuickOpenItem, and Quick Open split/keybinding terms found no verified older issue with the same observable symptom. https://github.com/microsoft/vscode/issues/18064 is open but requests modifier information for extension-provided commands/Quick Picks; https://github.com/microsoft/vscode/issues/128874 is open but requests a deduplicated, group-agnostic editor list. Neither owns this editor-picker alternative-accept behavior.
- **Related shortcut precedent:** https://github.com/microsoft/vscode/issues/149945#issuecomment-1132411504 identifies alternativeAcceptSelectedQuickOpenItem as the customizable Open to the Side command for the file picker. That issue is closed and also concerned removing history entries; it is neither an open duplicate target nor a decision declining this edt-specific capability.
