## Evidence

- **Current command registration:** src/vs/editor/browser/coreCommands.ts:2047–2094 registers deleteLeft and deleteRight as CoreEditingCommand instances with editor text-input keybinding conditions and editor-only deletion implementations. Unlike Undo, Redo, and SelectAll, they do not use EditorOrNativeTextInputCommand.
- **Reporter trigger and dispatch:** The reporter binds Ctrl+H to deleteLeft without a when clause, then invokes it in Find or the command palette. src/vs/editor/browser/editorExtensions.ts:302–333 resolves EditorCommand execution to getFocusedCodeEditor() or getActiveCodeEditor(), without dispatching to the focused native input; this explains why the remapped command can edit the previously active editor.
- **Existing capability is partial:** src/vs/editor/browser/coreCommands.ts:305–350 already provides focused input/textarea dispatch through EditorOrNativeTextInputCommand, but deleteLeft and deleteRight do not participate. Native Backspace behavior therefore does not establish coverage for arbitrary keybindings invoking these command IDs.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/313699 was verified OPEN with mergedAt null and contains Fixes #147218. It proposes native-input dispatch for deleteLeft and deleteRight, so the issue should remain open pending review and merge.
- **Additional scope in discussion:** The reporter's June 2, 2022 comment on https://github.com/microsoft/vscode/issues/147218 also identifies deleteWordLeft and deleteWordRight. Those commands remain editor commands in src/vs/editor/contrib/wordOperations/browser/wordOperations.ts; the linked PR explicitly excludes them and incorrectly states that the issue mentions only character deletion.
