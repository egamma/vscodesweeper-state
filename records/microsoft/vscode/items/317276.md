# Issue #317276 — Custom agent selection silently reverts to generic Agent mid-session; chat dropdown still shows the stale (correct) selection while the runtime has switched

[https://github.com/microsoft/vscode/issues/317276](https://github.com/microsoft/vscode/issues/317276)

## Summary

Keep open: current main still permits the selected custom agent and runtime state to diverge silently. Agent selection failures are logged but swallowed before the turn continues, matching the reported generic-agent fallback across both Local and Copilot CLI harnesses.

## Change summary

Keep a manually selected custom agent active for the session and prevent turns from silently continuing under the generic Agent when runtime selection fails.

## Best solution

Make the selected agent authoritative through turn dispatch and session restoration, and never send a turn under the generic Agent after custom-agent activation fails without visibly reconciling the picker and notifying the user.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/agentSideEffects.ts`, `src/vs/platform/agentHost/test/node/agentSideEffects.test.ts`, `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`
- **Validation:** Extend the `handleAction — chat/turnStarted agent selection` tests in src/vs/platform/agentHost/test/node/agentSideEffects.test.ts with a rejecting `changeAgent`; assert that the turn cannot silently reach `sendMessage` as the generic Agent and that the chosen visible failure contract is emitted. Add a session-mode regression check showing a selected custom mode remains synchronized across successive turns and late customization refreshes.
- **Behavior:**

  > A custom agent selected by the user remains active for the lifetime of the chat session until the user changes it. Every subsequent turn either runs with that agent or presents a visible selection error; it must never continue silently as the generic Agent while the picker still indicates the custom agent. The behavior must hold for both Local and Copilot CLI harnesses and after customization lists or session state refresh.
- **Trace:**

  > AgentHostSessionHandler in src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts copies the current custom-mode URI onto each turn message. AgentSideEffects in src/vs/platform/agentHost/node/agentSideEffects.ts applies that selection before sending, but its `changeAgent` rejection handler only logs the error and allows `sendMessage` to continue, creating the reported silent divergence. ChatInputPart restores a persisted custom mode when custom modes load late, so picker persistence alone does not guarantee runtime agreement. The related https://github.com/microsoft/vscode/issues/320993 is a younger Agents Window variant, not a duplicate target. Preserve normal generic-Agent turns and explicit user deselection; the plan should isolate why valid agents become temporarily unresolvable and define the visible failure contract before implementation.
- **Open decisions:**
  - If activating the selected custom agent fails, should the turn be blocked with the custom selection retained for retry, or should VS Code visibly clear the selection and require user confirmation before continuing with the generic Agent?
