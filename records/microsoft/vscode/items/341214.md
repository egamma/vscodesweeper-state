# Issue #341214 — Agent Host: duplicate managed-plugin warnings when background preparation fails during turn admission

[https://github.com/microsoft/vscode/issues/341214](https://github.com/microsoft/vscode/issues/341214)

## Summary

Thanks for the detailed report. The source matches your analysis: a failure reported while a turn is pending admission is emitted immediately, with nothing to coalesce a second one. A fix is open and still needed.

## Change summary

Two identical managed-plugin preparation warnings appear in one turn when a background preparation failure and the message's own preparation failure both arrive before admission.

## Best solution

Make a managed-plugin failure for a pending turn supersede or deduplicate an earlier failure already shown for that turn, so the turn shows a single warning. Add a regression test for the sequence: background start, send, background failure, preparation failure, user.message.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts`, `src/vs/platform/agentHost/test/node/copilotAgentSession.test.ts`
- **Validation:** Add a test in copilotAgentSession.test.ts beside the existing 'background warning -> send -> preparation warning -> user.message' regression, replaying background start, send, background failure, preparation failure and user.message, and assert exactly one ManagedPluginPreparationFailure notification for the turn. It must fail before the change and pass after.
- **Behavior:**

  > A single turn that is pending admission shows at most one managed-plugin preparation warning, even if a background preparation failure and the message's own preparation failure both arrive before the root user.message echo. The failure from the message's own preparation takes precedence. Idle-held failures and the existing background-warning, send, preparation-warning, user.message flow behave as before.
- **Trace:**

  > _reportManagedPluginFailure and _emitManagedPluginFailure in copilotAgentSession.ts (around lines 9087-9130) emit each failure immediately for a pending turn. The failure handler is wired near line 9606 for session.warning of type managed_plugins. Where it is uncertain: the warning is a system notification already dispatched to the turn, so superseding may mean retracting or replacing it, while deduplication needs only per-turn state. The boundary is to leave the held-failure behaviour for turns that are not pending unchanged, and leave managed_plugins_complete handling unchanged. Related: https://github.com/microsoft/vscode/issues/340362 and https://github.com/microsoft/vscode/issues/340992.
- **Open decisions:**
  - When the two failures differ in text, should the later one replace the earlier warning, or should both be shown and only identical text be suppressed?
  - Should this be one warning per turn with the latest message, or should the earlier failure's warning be removed from the transcript once the turn's own preparation fails?

## Evidence

- **handler:** In src/vs/platform/agentHost/node/copilot/copilotAgentSession.ts, _reportManagedPluginFailure (around line 9106) clears _unshownManagedPluginFailure and calls _emitManagedPluginFailure(turn, message) whenever _getManagedPluginAdmissionTurn() returns a pending turn. It does no per-turn deduplication, so two failures that both arrive after the send starts each produce a warning. The `_unshownManagedPluginFailure` hold only covers a failure that arrived while no turn was pending.
- **reporter timeline:** Two managed_plugins warnings with identical text arrive at +2.7 s and +22.9 s, both before the user.message echo at +23.0 s. The persisted history shows only the intended user prompts and an `OK` answer, so this is not a duplicate submission.
- **docs:** src/vs/platform/agentHost/AGENTS.md says a failure is shown 'unless that message's own preparation reports a newer failure'. That describes the idle-held case and does not cover two failures arriving during the pending window.
