# Issue #332635 — Editor group restore keeps phantom sticky editors when several sticky editors fail to deserialize

[https://github.com/microsoft/vscode/issues/332635](https://github.com/microsoft/vscode/issues/332635)

## Summary

Confirmed on current main: EditorGroupModel.deserialize compares each dead editor's raw index against the already-mutated `data.sticky` value, so the decrement can be skipped once earlier dead slots have already lowered it, leaving phantom sticky editors after restore. An open PR already fixes it, so this stays open for that PR to land rather than closing now.

## Change summary

When several sticky editors in a serialized group fail to deserialize, the sticky index isn't decremented correctly, leaving phantom sticky editors (or a sticky count > 0 on an empty group) after restore.

## Best solution

Land https://github.com/microsoft/vscode/pull/332636, which decrements sticky against the captured incoming index instead of the mutated `data.sticky`, fixing both failure modes described (with round-trip unit tests already added in editorGroupModel.test.ts).
