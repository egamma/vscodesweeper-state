# Issue #348798 — Allow restarting a remote agent host (SSH/WSL/Dev Container) from the UI

[https://github.com/microsoft/vscode/issues/348798](https://github.com/microsoft/vscode/issues/348798)

## Summary

Keep open: current source exposes local restart and remote reconnection, but not an equivalent remote process restart. The linked Claude defect motivates recovery tooling but does not subsume this feature request.

## Change summary

Provide UI recovery for remote agent hosts without requiring a reset of the entire remote VS Code server.

## Best solution

Provide explicitly targeted remote agent-host recovery with transcript restoration and clear interruption semantics, without restarting unrelated remote services. Decide whether host restart or session-scoped recovery is the appropriate supported contract.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/electron-browser/actions/restartAgentHostAction.ts`, `src/vs/workbench/contrib/sessions/providers/remoteAgentHost/browser/remoteHostOptions.ts`, `src/vs/platform/agentHost/common/remoteAgentHostService.ts`, `src/vs/platform/agentHost/browser/remoteAgentHostServiceImpl.ts`
- **Validation:** On SSH, WSL, and Dev Container targets, invoke the agreed recovery UI and verify that a subsequent prompt completes and persisted conversation history remains available. For host restart, verify a changed agent-host process identity; confirm unrelated remote services and other hosts remain running, and unsupported hosts expose no misleading recovery action.
- **Behavior:**

  > Users need a UI recovery path when remote agent-host process state remains wedged across reconnections. Recovery should preserve persisted conversations and avoid resetting the entire remote VS Code server. Acceptance must distinguish genuine process restart from reconnection and document any interruption to other sessions sharing that host.
- **Trace:**

  > RestartLocalAgentHostAction delegates to IAgentHostService.restartAgentHost() and is restricted to local windows. Remote management options are assembled by buildRemoteHostOptionItems in remoteHostOptions.ts; reconnectRemoteHost delegates to provider.connect() or IRemoteAgentHostService.reconnect(). RemoteAgentHostService.reconnect() rebuilds a connection, while the separate upgrade path only restarts when an upgrade actually starts. No general remote restart surface was found; transport-specific process ownership and restart support remain to be traced. The motivating Claude failure is separately tracked at https://github.com/microsoft/vscode/issues/347909 and should not be conflated with this recovery capability. Preserve existing reconnect behavior and compatibility with hosts that do not support process management.
- **Open decisions:**
  - Should recovery restart the selected host, interrupting its other active sessions, or provide session-scoped recovery instead?
  - If host-wide restart is supported, what confirmation and interruption warning should users receive when other sessions or clients share that host?
