# Issue #346991 — Deleting a shared chat-created file leaks or prematurely disposes its entry

[https://github.com/microsoft/vscode/issues/346991](https://github.com/microsoft/vscode/issues/346991)

## Summary

The current source confirms mismatched reference ownership during deletion of shared chat-created files. Keep this open while the existing fixing PR is reviewed; it has not merged.

## Change summary

Deleting or undoing creation of a file shared by local chat sessions leaks a reference or prematurely disposes the shared entry.

## Best solution

Review and land https://github.com/microsoft/vscode/pull/346995 after confirming both deletion regressions preserve per-session reference ownership and release the original model and watcher.

## Evidence

- **Shared ownership:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingServiceImpl.ts:148-158 acquires a reference when another local editing session borrows an existing entry. AbstractChatEditingModifiedFileEntry.dispose() decrements the reference count and disposes resources only at zero.
- **Ordinary deletion leak:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingSession.ts:1188-1200 removes the entry from each session but calls entry.dispose() only when !existingExternalEntry. The borrowing session therefore drops its working-set entry without releasing its acquired reference.
- **Undo double release:** ChatEditingSession._getTimelineDelegate().deleteFile removes and disposes the creating session's entry before applying the file deletion. Its onDidDelete callback subsequently releases that same reference again without checking current ownership, potentially disposing the shared entry while the borrowing session still retains it.
- **Resource lifetime:** src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingModifiedFileEntry.ts:125-130 registers the file watcher and deletion listener on the reference-counted entry, explaining why an unreleased reference retains the watcher.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/346995 is verified open and unmerged, explicitly states Fixes #346991, and changes the deletion callback to release only an entry currently owned by the session. Its proposed tests exercise ordinary deletion and undo through local chat sessions; their reported results were not independently executed in this read-only review.
