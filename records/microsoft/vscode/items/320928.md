# Issue #320928 — Webview resource cache grows unboundedly: media-preview cache-busts with Date.now(), service worker never evicts (21+ GB observed)

[https://github.com/microsoft/vscode/issues/320928](https://github.com/microsoft/vscode/issues/320928)

## Summary

Confirmed on current main: media-preview uses Date.now() for cache-busting (line 181 of imagePreview/index.ts), and the service worker caches every response without eviction or old-version cleanup. An open PR (#321358) addresses part of this but has not merged.

## Change summary

The webview resource cache grows unboundedly because media-preview cache-busts with Date.now() on every render and the service worker never evicts cached entries or cleans up old cache versions.

## Best solution

Land https://github.com/microsoft/vscode/pull/321358 (fix media-preview to use file mtime instead of Date.now()), and additionally add eviction logic to the service worker's activate handler (delete old VERSION caches) and optionally an LRU/size cap on the current cache.
