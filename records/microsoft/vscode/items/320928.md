## Evidence

- **Current image-preview trigger:** extensions/media-preview/src/imagePreview/index.ts:180–182 generates Date.now().toString() each time getWebviewContents runs; getResourcePath at lines 222–231 appends that value as the version query parameter for resources without an existing query. Reopening an unchanged image therefore produces another request URL.
- **Persistent cache path:** src/vs/workbench/contrib/webview/browser/pre/service-worker.js:520–527 stores eligible GET responses with an ETag using cache.put(event.request, responseForCache), while lines 538–540 look up the full request. Timestamp-distinct URLs do not reuse the same entry. The activate handler at lines 402–404 only claims clients, and the file contains no cache eviction or deletion logic. Current VERSION is 6, rather than the reported 5; that version change does not remove the mechanism.
- **Open fixing PR:** https://github.com/microsoft/vscode/pull/321358 is verified OPEN with mergedAt null and explicitly says Fixes #320928. It proposes stable resource versions derived from mtime and size across image, audio, and video previews. This requires review rather than a completed-close proposal or a competing agent implementation.
