# Issue #280500 — Unable to drag an editor into a split editor

[https://github.com/microsoft/vscode/issues/280500](https://github.com/microsoft/vscode/issues/280500)

## Summary

This is a valid, accepted-but-unscheduled feature request: current Shift-drag behavior intentionally inserts the file path, while replacing one side of an existing diff editor remains unsupported. The Backlog milestone and existing drag-and-drop area labels already route it appropriately.

## Change summary

Allow an externally dragged file to replace the targeted side of a diff editor, particularly one created by Compare New Untitled Text Files.

## Best solution

Let users replace either editable side of an existing diff editor with a dragged file while preserving the other side and retaining a clear, non-conflicting gesture for the existing drop-into-editor behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/editor/editorDropTarget.ts`, `src/vs/workbench/browser/parts/editor/textDiffEditor.ts`, `src/vs/workbench/common/editor/diffEditorInput.ts`
- **Validation:** Open Compare New Untitled Text Files, use the chosen gesture to drop an external file onto each side in turn, and verify only the targeted side adopts the file while the other side remains unchanged; also verify Shift-drag into a normal text editor retains the established Insert Path behavior.
- **Behavior:**

  > An external file can be dropped onto a chosen editable side of an existing diff editor so that side displays the file while the opposite side remains unchanged. The interaction must clearly distinguish replacing a diff input from the existing Shift-drag operation that inserts a URI or path into text. It must work for both sides of a diff created by `workbench.files.action.compareNewUntitledTextFiles` and must not alter ordinary editor-group splitting or normal text-editor drop behavior.
- **Trace:**

  > The compare command in src/vs/workbench/contrib/files/browser/fileActions.ts opens a diff with separate untitled original and modified inputs. `EditorDropTarget` in src/vs/workbench/browser/parts/editor/editorDropTarget.ts returns early for Shift-drag, allowing `DropIntoEditorController` and the default URI-list provider to insert the path into the targeted code editor. Non-Shift external drops are handled as resource drops at the editor-group level, not as replacement of one child of `DiffEditorInput`. `DiffEditorInput` in src/vs/workbench/common/editor/diffEditorInput.ts owns the original and modified inputs, while `TextDiffEditor` in src/vs/workbench/browser/parts/editor/textDiffEditor.ts resolves them into the two editor controls. Preserve the global Shift drop-into-editor contract, ordinary file opening, editor-group splitting, and the non-targeted diff side. The uncertainty begins at the user-facing gesture and at whether side replacement applies only to untitled editable inputs or more broadly to existing diff inputs.
- **Open decisions:**
  - Which drag gesture should replace a diff side without conflicting with Shift-drag's established Insert Path behavior?
  - Should side replacement be limited to editable untitled sides, or should it also replace file-backed sides in other diff editors?

## Evidence

- **intentional current behavior:** src/vs/editor/common/config/editorOptions.ts documents `editor.dropIntoEditor.enabled` as using Shift to drop a file into the text editor instead of opening it.
- **current drop path:** src/vs/workbench/browser/parts/editor/editorDropTarget.ts treats Shift as a drop-into-editor event and yields to the code editor rather than handling the file as a workbench editor drop.
- **observed path result:** src/vs/editor/contrib/dropOrPasteInto/browser/defaultProviders.ts registers the default URI-list drop provider with “Insert Path” and “Insert Uri” edits, matching the reporter's inserted full path.
- **diff model boundary:** src/vs/workbench/common/editor/diffEditorInput.ts models a diff as separate original and modified editor inputs, but the current workbench drop target only opens dropped resources in an editor group and has no operation for replacing one constituent input.
