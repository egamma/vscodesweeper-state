# Issue #280500 — Unable to drag an editor into a split editor

[https://github.com/microsoft/vscode/issues/280500](https://github.com/microsoft/vscode/issues/280500)

## Summary

Current behavior is intentional: Shift+Drop is the designed modifier for 'drop into editor' (insert content as text), not for splitting. Ctrl+Drop (Windows) is the modifier for opening in a split. The reporter is using the wrong modifier key.

## Change summary

Reporter expects Shift+Drop from Windows Explorer to open a file in a split editor panel, but Shift triggers text insertion instead.

## Best solution

Close as designed. The Shift modifier deliberately triggers 'drop into editor' (text insertion) per `isDragIntoEditorEvent()` in `editorDropTarget.ts`. To open in a split, the user should hold Ctrl (on Windows) during the drop. If the team wants to improve discoverability, a hint overlay already appears during drag — that's the existing UX for communicating modifier keys.
