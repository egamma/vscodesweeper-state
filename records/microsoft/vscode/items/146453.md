## Evidence

- **Current source excludes strings:** In src/vs/editor/common/model/bracketPairsTextModelPart/bracketPairsTree/tokenizer.ts, NonPeekableTextBufferTokenizer.read searches for brackets only when TokenMetadata.containsBalancedBrackets is true and the token type is StandardTokenType.Other. String tokens fail that condition. ColorizedBracketPairsDecorationProvider.getDecorationsInRange consumes this model's bracket results.
- **Existing-capability check:** src/vs/editor/common/config/editorOptions.ts exposes editor.bracketPairColorization.enabled and editor.bracketPairColorization.independentColorPoolPerBracketType. src/vs/editor/common/config/editorConfigurationSchema.ts exposes editor.language.colorizedBracketPairs, which selects bracket pairs but does not override token-type exclusion. These settings do not cover colorization inside tokens classified as strings.
- **Reload observation explained by source:** The November 2024 comment reports briefly seeing colored brackets after reload before string coloring takes over. BracketPairsTree initially permits a FastTokenizer tree without token information, then switches to its token-aware tree when background tokenization completes. That transition is consistent with the observation, not evidence that persistent string colorization is available.
- **Demand and accepted scope:** https://github.com/microsoft/vscode/issues/146453 has 31 body upvotes, a Backlog milestone, and multiple supporting comments.
