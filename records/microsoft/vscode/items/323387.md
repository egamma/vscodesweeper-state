# Issue #323387 — Renderer process crashes (`reason: crashed, code: 5`) — built-in agent sessions cache (`agentSessions.model.cache`) imported from `~/.claude` grows unbounded (~140 MB) and cannot be disabled

[https://github.com/microsoft/vscode/issues/323387](https://github.com/microsoft/vscode/issues/323387)

## Summary

Keep this open: oversized-cache restoration remains unbounded in current source, and an independent report confirms the same renderer-crash scenario. The issue was reopened after the existing mitigations landed; neither a subsequent complete fix nor an older canonical covering this behavior was established.

## Change summary

Prevent large imported agent-session histories and cached change lists from crashing the renderer, and make external-history discovery controllable.

## Best solution

Make session-cache persistence and startup restoration resource-bounded, including recovery from already oversized entries, without deleting underlying CLI history. Establish which current provider owns external-history discovery and ensure its disabling control stops discovery rather than merely hiding the sessions view.
