# Issue #349058 — A webview closed while it loads keeps its resource slots for 30 s, so the next webviews of its view type stay blank

[https://github.com/microsoft/vscode/issues/349058](https://github.com/microsoft/vscode/issues/349058)

## Summary

The resource-slot leak remains in current source. Keep this open while its explicitly linked fix PR is reviewed; the older report describes the same underlying defect.

## Change summary

Closing resource-heavy webviews leaves shared response slots occupied, delaying subsequently opened webviews until the 30-second timeout.

## Best solution

Review and land or otherwise resolve https://github.com/microsoft/vscode/pull/349091, preserving the concurrency limit while promptly releasing abandoned requests. Coordinate that work with https://github.com/microsoft/vscode/issues/346625 and retain this report's minimal Linux reproduction.

- **Disposal removes the response destination:** src/vs/workbench/contrib/webview/browser/webviewElement.ts:354-375 removes the frame and disposes resource loading. loadResource at lines 852-884 returns when disposed, including after its asynchronous resource read, without sending a resource response.

- **Verified older overlapping report:** https://github.com/microsoft/vscode/issues/346625 is open and describes the same shared semaphore retaining requests after webview closure, blocking subsequent panels on Windows.
