# Issue #337277 — Automations: support script-first actions with optional AI continuation

[https://github.com/microsoft/vscode/issues/337277](https://github.com/microsoft/vscode/issues/337277)

## Summary

Team-authored feature request (hediet, MEMBER) proposing script-first automation actions with optional AI continuation; the current blueprint schema only supports a `prompt` field that always starts an AI session, so this is a real, unimplemented design proposal that must stay open — team-authored items get closed only on mechanical evidence, and none exists here.

## Change summary

Let an automation run a script first (deterministic work/checks) and decide independently whether to start a new AI session, covering all four success/failure × continue/no-continue combinations.

## Best solution

Design and land a script action alongside prompt in the automation blueprint (e.g. `IAutomationBlueprint` in src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts) with a structured signaling contract for the AI-continuation decision, run before AI session creation and recorded in automation run history.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts`, `src/vs/workbench/contrib/chat/common/automations/automation.ts`, `src/vs/workbench/contrib/chat/common/automations/automationService.ts`
- **Validation:** A blueprint-parsing/execution test asserting each of the four script-result × AI-continuation combinations produces the documented run-history outcome (script-only success, script-only failure, script success + AI follow-up, script failure + AI follow-up).
- **Behavior:**

  > An automation can define a script action that runs before any AI session is created. The script's exit/output independently determines (a) success or failure of the script step and (b) whether a new AI session should be started, covering all four combinations in the issue body. Script output, errors, and exit status are preserved in automation run history even when no AI session is created. When AI continuation is requested, the configured prompt and script output/context are passed to the new session. Invalid/missing control output is surfaced explicitly rather than silently ignored.
- **Trace:**

  > IAutomationBlueprint (src/vs/workbench/contrib/chat/common/automations/automationBlueprint.ts) currently models only a single required `prompt` string that automationService.ts always turns into an AI session; there is no script step, no execution-before-AI concept, and no signaling channel distinguishing script status from the continuation decision. The scope should stay inside the automations subsystem (blueprint parsing, automationService execution, run-history recording) and must not change how existing prompt-only automations behave. Do not touch chat's tool-invocation infrastructure — the issue explicitly asks for a pre-session script, not a tool call inside an already-started session.
- **Open decisions:**
  - What is the structured signaling contract for expressing script success/failure and AI-continuation independently (special exit code, stdout marker, dedicated control channel/file)?
  - How is a configured prompt and the script's output/context passed into the new AI session when continuation is requested?
  - How does an AI follow-up after a failed script affect the overall automation run status shown in history?

## Evidence

- **no related PR/fix:** git log on automationBlueprint.ts shows only an unrelated recent merge (9c8b8c2b); no commit implements script-first actions.
