# Issue #336987 — Agent Host cannot use a team skills library (second git repo) — extra-location settings deprecated with no live-pointer replacement

[https://github.com/microsoft/vscode/issues/336987](https://github.com/microsoft/vscode/issues/336987)

## Summary

Thanks for the detailed request. Agent Host sessions don't read the extra-location settings (`chat.agentSkillsLocations` and siblings), and the only documented replacement is a one-time copy. A live shared-library pointer is a real gap that no existing issue clearly owns, so this stays open for a maintainer decision.

## Change summary

Let Agent Host sessions load skills, agents, hooks and instructions live from a second git clone while the workspace stays the product repo.

## Best solution

Have the agent host honor a configured extra-location or library-root setting, resolving paths in place so scripts next to SKILL.md still work. Alternatively, keep the Local-only settings from being deprecated until an equivalent ships.

- **Trace:**

  > The extra-location settings are consumed by the workbench prompt-file locator (promptFilesLocator.ts and config.ts). They are not wired into agent host customization discovery. The uncertainty starts at how the host should discover customizations and enforce trust for an out-of-workspace root.
