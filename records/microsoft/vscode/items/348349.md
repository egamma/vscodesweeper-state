## Evidence

- **Concurrent reference overwrite:** At checkout HEAD d03edc4b18d687c45af067195bad9544b5b07475, src/vs/workbench/contrib/notebook/browser/viewModel/baseCellViewModel.ts:682-695 checks ownership before awaiting createModelReference, then unconditionally assigns the arriving reference to _textModelRef. Two pending calls can therefore overwrite one another without disposing the displaced reference.
- **Late resolution after disposal:** BaseCellViewModel.resolveTextModel():684-686 installs the reference before checking _isDisposed and returns without releasing it. dispose():730-743 releases only the reference present at disposal time; detachTextEditor():348-352 likewise releases only the currently retained reference.

This supports the reported retention mechanism, but source inspection alone does not establish the full stale-content reopening outcome.
