# Issue #169923 — Merge conflict: save the file when choosing "accept all"

[https://github.com/microsoft/vscode/issues/169923](https://github.com/microsoft/vscode/issues/169923)

## Summary

The current source still loads every selected conflict as a text document and applies a workspace edit without saving, leaving the resolved files dirty. The issue remains necessary because no open older canonical owns this exact save behavior.

## Change summary

Accepting all current or incoming changes for selected SCM resources should persist the resolutions without leaving the files open and unsaved.

## Best solution

Make the SCM resource command complete only after the selected conflict resolutions are persisted, without displaying or retaining unnecessary editor entries, while surfacing any save failure. A maintainer should first confirm that this command intentionally overrides the ordinary dirty-document workflow rather than relying on Auto Save.

## Plan brief

- **Likely files:** `extensions/merge-conflict/src/commandHandler.ts`
- **Validation:** In an Extension Development Host, create at least two conflicted files, select both under SCM Merge Changes, run Accept All Current and then Accept All Incoming in separate runs, and verify that every resolution is persisted, no dirty editor entries remain, and save failures are reported.
- **Behavior:**

  > When multiple files under SCM Merge Changes are selected and Accept All Current or Accept All Incoming is invoked, all selected conflicts are resolved and persisted without requiring the user to open or manually save each file. The operation must not leave dirty editor entries behind. If any file cannot be saved, the operation must report that failure instead of appearing successful.
- **Trace:**

  > The SCM menu commands are contributed by extensions/merge-conflict/package.json and dispatched through CommandHandler in extensions/merge-conflict/src/commandHandler.ts. `acceptAllResources` opens each resource as a TextDocument, computes conflict replacements, and calls `vscode.workspace.applyEdit`, but it does not await that promise or save the resulting dirty documents. This path originated in commit 039a49a5eab688800b0226cf2c4addc797c94a86 for https://github.com/microsoft/vscode/issues/63621. That issue's maintainer comment explicitly retained manual-save/Auto Save behavior, so the uncertainty starts at whether this SCM bulk operation should now force persistence independently of the user's Auto Save configuration. Keep staging behavior out of scope; that separate request is tracked by https://github.com/microsoft/vscode/issues/250857.
- **Open decisions:**
  - Should the SCM Accept All Current/Incoming resource commands always save the resolved files immediately, or preserve the normal dirty-document and Auto Save semantics?

## Evidence

- **current source:** extensions/merge-conflict/src/commandHandler.ts:275-293 implements `acceptAllResources` by calling `vscode.workspace.openTextDocument` for every selected resource and then `vscode.workspace.applyEdit(edit)`; it neither awaits the edit result nor saves the modified documents.
- **historical implementation:** Commit 039a49a5eab688800b0226cf2c4addc797c94a86 added the multi-resource path for https://github.com/microsoft/vscode/issues/63621, but deliberately stopped at applying an in-memory WorkspaceEdit.
