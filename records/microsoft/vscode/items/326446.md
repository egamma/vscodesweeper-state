# Issue #326446 — get_errors tool returns "No errors found" when filePaths targets a Kotlin file with diagnostics, but global query works

[https://github.com/microsoft/vscode/issues/326446](https://github.com/microsoft/vscode/issues/326446)

## Summary

Current source confirms a Windows path-comparison defect in the file-filtered `get_errors` flow: it uses an always-case-sensitive URI comparer, while the unfiltered flow does not. The issue should stay open for a bounded Copilot core fix and regression test.

## Change summary

Make `get_errors` return diagnostics for explicitly targeted Kotlin files on Windows when the same diagnostics appear in the global query.

## Best solution

Align the filtered diagnostic lookup with VS Code's platform-aware URI identity rules in the Copilot `get_errors` tool, while preserving directory filtering and the existing global-query behavior.
