# Issue #98125 — Allow extensions to fully control workspace symbol search (matching and highlights)

[https://github.com/microsoft/vscode/issues/98125](https://github.com/microsoft/vscode/issues/98125)

## Summary

Keep open: the workspace-symbol API still does not let extensions control matching and highlights, and the current picker can discard language-server results for qualified queries. This accepted Backlog request has 83 upvotes, maintainer support, and corroborating reports; the broader quick-open tracking issue does not replace its specific API work.

## Change summary

Allow workspace-symbol providers to supply language-specific matching and highlight information without VS Code filtering away valid results.

## Best solution

Define a backward-compatible workspace-symbol API contract for provider-controlled matching and highlights, retaining existing fuzzy behavior for providers that do not opt in. Settle how provider-controlled results participate in combined results from multiple providers before implementation.

  > WorkspaceSymbolProvider in src/vscode-dts/vscode.d.ts currently returns SymbolInformation and documents editor-owned scoring and highlighting. NavigateTypeAdapter in src/vs/workbench/api/common/extHostLanguageFeatures.ts converts provider results into the DTO contract in extHost.protocol.ts; the internal IWorkspaceSymbol contract in contrib/search/common/search.ts has no match metadata. - **Open decisions:**
