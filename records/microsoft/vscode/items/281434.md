# Issue #281434 — Agents: Preserve Independent Drafts Across Sessions and Workspaces

[https://github.com/microsoft/vscode/issues/281434](https://github.com/microsoft/vscode/issues/281434)

## Summary

Keep open: current source preserves a single new-session draft, but does not provide multiple independent, durable drafts across workspaces. The maintainer's expanded workflow remains actionable, and the related open reports do not own its full scope.

## Change summary

Let multiple new and existing agent sessions retain independent unsent drafts across navigation, workspace changes, and reopening.

## Best solution

Support independently addressable, durable drafts in the Agents Window, preserving each draft's input and workspace association. Extend the draft lifecycle and restoration contract without regressing existing conversation input isolation.

- **Validation:** Extend the sessionsManagementService and newChatInput test suites to retain two unsent drafts associated with different workspaces, switch between them without input transfer, and restore both through a fresh storage-backed lifecycle. Manually verify the same workflow in the Agents Window, including closing/reopening and existing-session replies; submitting one draft must not clear the other.
- **Behavior:**

  > Users can prepare multiple unsent agent requests concurrently, including requests associated with different workspaces. Each new or existing session restores its own unsent text when revisited, without borrowing another session's input. Closing and reopening the relevant session or workspace preserves the draft and its workspace association. Acceptance includes two distinct drafts surviving switching and reopening, and sending either draft leaving the other unchanged.
- **Trace:**

  > The current Agents Window has a singleton pending new-session model in SessionsManagementService._newSession. Its createNewSession method replaces that model and deletes the previous provider draft, while ISessionsService.openNewSession documents returning to the existing pending composer. newChatDraftState.ts persists one workspace-scoped IChatDraft, and NewChatInput restores and saves that value. Existing conversations already bind their own input models through ChatView, so retain their input isolation rather than treating all input handling as missing. The unresolved technical boundary is how multiple unsent session identities participate in navigation, provider resource disposal, and durable workspace-aware restoration; a complete design was not established by this inspection. The maintainer's required behavior is recorded at https://github.com/microsoft/vscode/issues/281434#issuecomment-5035978914; the narrower reports https://github.com/microsoft/vscode/issues/319074 and https://github.com/microsoft/vscode/issues/324149 are related, not replacement canonicals.
