# Issue #117822 — [product icon themes] theme icons support for vscode.show(Information|Warning|Error)Message

[https://github.com/microsoft/vscode/issues/117822](https://github.com/microsoft/vscode/issues/117822)

## Summary

Theme icons in extension-provided notification messages are intentionally unsupported to preserve the Info/Warning/Error hierarchy and prevent misleading icon use. Native modal dialogs also accept plain strings and cannot consistently render VS Code theme icons.

## Change summary

Allow `$(icon)` theme-icon syntax in messages passed to `showInformationMessage`, `showWarningMessage`, and `showErrorMessage`.

## Best solution

Keep extension message text icon-free and retain the standard severity icon selected by `showInformationMessage`, `showWarningMessage`, or `showErrorMessage`; extensions should express additional context clearly in the message text.

## Vision fit

- **Fit:** rejected
- **Reason:** Per-extension inline icons would weaken the uniform notification hierarchy and create inconsistent behavior between custom web dialogs and native desktop dialogs.
- **Evidence:** Values and guardrails: “Simple, uniform UI and UI interactions” and UI consistency over per-feature customization.

  > Thanks for the request. The existing plain-text behavior is therefore by design.

## Evidence

- **maintainer decision:** In https://github.com/microsoft/vscode/issues/145722#issuecomment-1075510935, the notification owner states that icons were deliberately disallowed in notifications to avoid abuse; https://github.com/microsoft/vscode/issues/145722#issuecomment-1076128986 reiterates that notification messages cannot use codicons.
- **notification hierarchy:** The discussion at https://github.com/microsoft/vscode/issues/153990#issuecomment-1185902634 explains that custom icons could confuse the established Info > Warning > Error hierarchy.
- **current API path:** src/vs/workbench/api/common/extHostMessageService.ts and src/vs/workbench/api/browser/mainThreadMessageService.ts still transport message and detail as plain strings; non-modal messages go to INotificationService while modal messages go to IDialogService.
- **current rendering:** src/vs/workbench/browser/parts/notifications/notificationsViewer.ts renders ordinary notification message nodes as text or links, without codicon/theme-icon expansion.
- **platform constraint:** The issue discussion notes that desktop defaults use native OS dialogs, while custom dialogs are primarily used on web, so Markdown/theme-icon rendering would not be consistent across platforms.
