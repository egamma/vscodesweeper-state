# Issue #265912 — MCP servers added via McpServerDefinitionProvider should display in the MCP Servers list

[https://github.com/microsoft/vscode/issues/265912](https://github.com/microsoft/vscode/issues/265912)

## Summary

The exact Extensions-sidebar gap remains on current main: its installed MCP view still reads only locally installed servers. A newer customization-management surface does include extension-provided servers, so the remaining product decision is whether to update the legacy view or direct users consistently to the newer surface.

## Change summary

Show MCP servers registered through McpServerDefinitionProvider alongside other installed servers in the MCP management UI.

## Best solution

Provide one consistent MCP inventory that includes extension-contributed servers and identifies their source. Maintainers should decide whether the Extensions-sidebar list remains a supported management surface or is replaced by the newer Chat Customizations MCP view without leaving a misleading partial inventory.

- **Behavior:**

  > Users must be able to discover every available MCP server, including servers registered through McpServerDefinitionProvider, from the canonical MCP management experience. Extension-contributed entries must identify their extension source and must not be presented as user-installed servers that can be uninstalled independently. Acceptance requires an extension-provided server to appear after registration, update when its definitions change, and disappear when its provider is disposed, while existing user and workspace server behavior remains unchanged.
- **Trace:**

  > The legacy Extensions-sidebar view in src/vs/workbench/contrib/mcp/browser/mcpServersView.ts obtains its model from IMcpWorkbenchService.queryLocal(), so provider-backed runtime definitions are absent. The newer McpListWidget in src/vs/workbench/contrib/chat/browser/aiCustomization/mcpListWidget.ts already merges mcpService.servers that are absent from the workbench-local list, maps collection sources through IMcpRegistry, and groups non-Copilot extension entries under Extensions. Older reports https://github.com/microsoft/vscode/issues/258549 and https://github.com/microsoft/vscode/issues/260778 were consolidated into this issue. Preserve the distinction between extension-provided and user/workspace-installed servers, especially uninstall and configuration actions; the uncertainty begins at which management surface VS Code intends to keep canonical.
- **Open decisions:**
  - Should extension-contributed servers also appear in the legacy Extensions-sidebar MCP Servers list, or should that partial inventory be retired or redirected in favor of the Chat Customizations MCP view?
