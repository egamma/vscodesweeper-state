# Issue #328339 — API: Allow extensions to specify initial selection state for MCP server tools

[https://github.com/microsoft/vscode/issues/328339](https://github.com/microsoft/vscode/issues/328339)

## Summary

Clean, well-scoped API gap: there's no way for an MCP server definition provider to mark a discovered tool as unchecked-by-default in the Configure Tools UI while remaining invocable programmatically — nothing in the current proposed or stable MCP API surface covers this, so it should be routed to the MCP/API owners for a design call between the two proposed options.

## Change summary

Extend the McpServerDefinitionProvider API so extensions can set a tool's default Configure Tools selection state (checked/unchecked) at registration or afterward, while keeping it invocable via vscode.lm.invokeTool().

## Best solution

A maintainer (likely @connor4312, who owns the MCP proposed APIs in src/vscode-dts/vscode.proposed.mcpServerDefinitions.d.ts and vscode.proposed.mcpToolDefinitions.d.ts) should decide between Option A (a `defaultToolSelection` field on McpStdioServerDefinition/McpHttpServerDefinition or their metadata) and Option B (a standalone `setMcpToolEnabled` API), then land it as a new proposed API guarded by a proposal name.

## Vision fit

- **Fit:** aligned
- **Reason:** This extends the MCP/agent tooling API surface that VS Code's current priorities emphasize (agent host tool parity, precision context management for tool selection) rather than adding new core UI surface.
