# Issue #313689 — Allow CustomTextEditor to Handle Extension-Textualized Binary Files

[https://github.com/microsoft/vscode/issues/313689](https://github.com/microsoft/vscode/issues/313689)

## Summary

This is a restatement of the previously closed #106916 ("Allow decoding, editing and re-encoding of binary files"), which was closed as *out-of-scope after community process. The core request — letting extensions provide a textual representation of binary files for the native text editor — is the same work. Proposing duplicate close.

## Change summary

Allow extensions to provide a text representation of binary files so they can be opened in the native text editor with full editor features.

## Best solution

Consolidate on https://github.com/microsoft/vscode/issues/106916 which already captures this exact request and was closed as out-of-scope. The workaround is to use a custom FileSystemProvider as a proxy (as described in that issue's discussion) or use a CustomEditorProvider with a webview.

## Vision fit

- **Fit:** rejected
- **Reason:** The VS Code values emphasize that 'the power lives in extensions' and that capabilities buildable via the extension API belong in extensions — a virtual filesystem provider can already proxy binary files as text content today.
- **Evidence:** Value: 'The power lives in extensions.' A custom FileSystemProvider already enables extensions to present binary files as text at a custom URI scheme, making this a core-extension boundary question the team has already declined.
