# Issue #313689 — Allow CustomTextEditor to Handle Extension-Textualized Binary Files

[https://github.com/microsoft/vscode/issues/313689](https://github.com/microsoft/vscode/issues/313689)

## Summary

This is a feature request for an API to let extensions provide a textual representation of binary files and use the native text editor. Prior related issues (#106916 closed as *out-of-scope, #2582 closed as *extension-candidate) suggest maintainers have previously declined this, but the workaround (FileSystemProvider) is acknowledged as janky. Keeping open for community traction and maintainer re-evaluation rather than preemptively closing.

## Change summary

Extensions cannot provide a textualized view of binary files to leverage native text editor features (diff, syntax highlighting, navigation) because registerTextDocumentContentProvider skips binary files and registerCustomEditorProvider requires a full webview.

## Best solution

The maintainers have previously declined essentially the same request in https://github.com/microsoft/vscode/issues/106916 (*out-of-scope) and https://github.com/microsoft/vscode/issues/2582 (*extension-candidate), suggesting a custom FileSystemProvider as a proxy workaround. If the team's position hasn't changed, this should be closed as *out-of-scope with the same reasoning. If the team wants to reconsider given the API gap (FileSystemProvider is a heavy workaround), route to the custom-editors / api area for a product decision.
