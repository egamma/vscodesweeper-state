# Issue #336736 — Custom endpoints can send unsupported sampling parameters

[https://github.com/microsoft/vscode/issues/336736](https://github.com/microsoft/vscode/issues/336736)

## Summary

The reported precedence (per-request sampling values override configured `modelOptions`) is explicitly documented as intentional in the settings schema, so this isn't a bug — but there's genuinely no way today to declare a model's sampling parameters as a hard constraint that always wins, which is a real, undelivered feature request worth keeping open for design input.

## Change summary

Custom-endpoint models with fixed/required sampling parameters can still receive incompatible temperature/top_p values from generic agent request options, because configured `modelOptions` are only defaults, not enforced constraints.

## Best solution

Add an opt-in mechanism (e.g. a new schema field or a per-key 'locked' flag) that lets a `customendpoint` model declare sampling values as non-overridable, applied at the final request-body boundary in `_applyConfiguredModelOptions`, while leaving today's override-by-request-value default behavior unchanged for ordinary models.
