# Issue #165684 — Support manual align in merge editor

[https://github.com/microsoft/vscode/issues/165684](https://github.com/microsoft/vscode/issues/165684)

## Summary

Keep open: current merge-editor controls do not provide manual hunk alignment, and a maintainer has endorsed the capability and supplied another concrete example. The related two-way diff request and newer diffing umbrella do not replace this merge-specific request.

## Change summary

Allow users to override merge-editor line or hunk alignment before combining changes from both inputs.

## Best solution

Provide a discoverable, reversible way to constrain merge alignment so Accept Combination uses the intended correspondence rather than incorrectly split automatic hunks. Design the interaction and alignment lifetime with the merge-editor maintainer, keeping ordinary two-way diff support separate as requested in the discussion.

- **Behavior:**

  > Users can correct an unwanted correspondence between merge inputs before accepting both changes. The correction must affect conflict grouping and combination semantics, not merely vertical scrolling or spacer placement. For the added/added example, accepting both after correction preserves the intended complete blocks without interleaving a split function. Manual alignment is reversible, and merges without manual constraints retain existing behavior.
- **Trace:**

  > MergeDiffComputer.computeDiff in src/vs/workbench/contrib/mergeEditor/browser/model/diffComputer.ts obtains automatic whole-model mappings. MergeEditorModel in browser/model/mergeEditorModel.ts derives modifiedBaseRanges from its base-to-input TextModelDiffs; ModifiedBaseRange.fromDiffs and smartCombineInputs in browser/model/modifiedBaseRange.ts determine grouping and combination from these mappings. ViewZoneComputer.computeViewZones in browser/view/viewZones.ts only adds display spacers, so visual alignment alone would not deliver the request. The existing model test suite provides projection and result assertions suitable for acceptance checks. - **Open decisions:**
