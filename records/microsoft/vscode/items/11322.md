# Issue #11322 — Remove whitespace and indent to the right spot when the line has more whitespace than necessary

[https://github.com/microsoft/vscode/issues/11322](https://github.com/microsoft/vscode/issues/11322)

## Summary

The requested Tab behavior is still missing: current source and explicit tests retain extra indentation rather than normalizing it. Keep this maintainer-authored request open; neither the related closed work nor the verified older candidates subsumes it.

## Change summary

Make Tab normalize a whitespace-only line to its contextual indentation even when it already contains the full indentation or excess whitespace.

## Best solution

Extend contextual Tab indentation to address already-indented whitespace-only lines without preventing deliberate further indentation. Agree on the cursor-position and repeated-Tab behavior first, since existing tests explicitly preserve indentation growth in these cases.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Extend the cursor-controller tests with whitespace-only lines below, at, and beyond contextual indentation, with the cursor inside and at the end of the whitespace, using tabs and spaces. Check the agreed text and cursor results after the first and repeated Tab presses, then run scripts/test.sh --run src/vs/editor/test/browser/controller/cursor.test.ts.
- **Behavior:**

  > Tab currently adds indentation when a whitespace-only line already contains its contextual indentation or more; the request is to bring that line to the contextual position instead. The finished interaction must address both excess whitespace and cursor placement while retaining a deliberate way to indent further. Acceptance checks should cover underindented, exactly indented, and overindented lines, cursor positions within and at the end of whitespace, repeated Tab presses, and both tabs and spaces.
- **Trace:**

  > TabOperation.getCommands in src/vs/editor/common/cursor/cursorTypeEditOperations.ts computes contextual indentation through _goodIndentForLine, but skips whole-line replacement when the existing line starts with that indentation. It then calls _replaceJumpToNextIndent, which inserts whitespace at the cursor. The third and fourth whitespace-only-line tests in src/vs/editor/test/browser/controller/cursor.test.ts explicitly expect further indentation for the full and excess cases. The maintainer separated this work from the original improvement in https://github.com/microsoft/vscode/issues/2938#issuecomment-243819420. Separate reindent commands exist, but do not implement this Tab interaction. Preserve non-whitespace typing, selection indentation, and the existing underindented-line behavior; the unresolved boundary is when Tab normalizes versus intentionally indents further.
- **Open decisions:**
  - When the cursor is already at the end of an exactly indented whitespace-only line, should Tab retain its current indent-further behavior or remain at the contextual indentation?
  - After Tab removes excess whitespace and places the cursor at contextual indentation, should a subsequent Tab indent further, and should normalization depend on whether the cursor initially lies inside or at the end of the whitespace?
