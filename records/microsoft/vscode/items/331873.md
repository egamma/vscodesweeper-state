# Issue #331873 — Claude hangs after invoking extension-provided language model tools

[https://github.com/microsoft/vscode/issues/331873](https://github.com/microsoft/vscode/issues/331873)

## Summary

Traced a concrete race in the Claude client-tool completion bridge that matches the reported symptom exactly: Claude's `completeClientToolCall` uses `PendingRequestRegistry.respond()`, which silently drops the result if the workbench's completion envelope arrives before the SDK's MCP tool handler calls `register()` — leaving that `register()` promise parked forever, so the tool call never resolves and the turn hangs on "Processing". Copilot hit the identical race and already fixed it with `respondOrBuffer()`; Claude's bridge was never updated to match.

## Change summary

Extension-provided (client) language model tools invoked during a Claude chat show "Canceled" and the chat then hangs indefinitely on "Processing", while the same tools work fine with Copilot and Codex.

## Best solution

Switch `ClaudeAgentSession.completeClientToolCall` (src/vs/platform/agentHost/node/claude/claudeAgentSession.ts:1357-1359) to use `_pendingClientToolCalls.respondOrBuffer()` instead of `.respond()`, mirroring the fix already applied for the same race in Copilot's bridge (`copilotAgentSession.ts` lines 1976/1982/4487), so an early completion is buffered rather than dropped when it beats the SDK handler's `register()` call in `claudeSdkOptions.ts:222`.
