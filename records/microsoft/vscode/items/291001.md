# Issue #291001 — [proposal] Support ProviderId in vscode.TextEditor.edit (Source Edit Tracking)

[https://github.com/microsoft/vscode/issues/291001](https://github.com/microsoft/vscode/issues/291001)

## Summary

Valid API proposal to tag TextEditor.edit() calls with the calling extension's identity for edit source tracking. The proposed textDocumentChangeReason API (488d6df7955) covers the observation side but not the TextEditor.edit() tagging path. An open demo PR exists and team members have engaged — keeping open.

## Change summary

Allow vscode.TextEditor.edit() to propagate the calling extension's identity so edit source tracking can attribute edits to their originating extension.

## Best solution

Extend the existing edit source tracking infrastructure (commit 488d6df7955, proposed API textDocumentChangeReason) to also tag edits flowing through the TextEditor.edit() → mainThreadEditors.$tryApplyEdits path with the calling extension's identity. The open PR https://github.com/microsoft/vscode/pull/291863 demonstrates one approach; hediet owns the area and jrieken suggested bringing a cleaned-up API proposal to API sync.
