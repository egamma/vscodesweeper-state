# Issue #337672 — Agents: per-session background activity view (async shells + background subagents)

[https://github.com/microsoft/vscode/issues/337672](https://github.com/microsoft/vscode/issues/337672)

## Summary

Well-reasoned, freshly filed request for a per-session background-activity view in the Agents window, explicitly grounded in a maintainer's own acknowledgment of the gap (roblourens on issue #336472) — worth keeping open for design/product input, not enough evidence yet for a decisive close or a ready-to-implement bug fix.

## Change summary

Add a per-session UI surface in the Agents window listing background async shells and background subagents with their state, elapsed time, and actions (open/stop).

## Best solution

Design a 'Background activity' surface (pill/panel/session-detail) in src/vs/sessions surfacing async shell and subagent state; likely blocked until the underlying SDK exposes background/detached shell output and state (referenced as github/copilot-sdk#2351), so this needs a maintainer product decision on where the UI lives and how it composes with the existing Subagents pill before any implementation.

## Plan brief

- **Likely files:** `src/vs/sessions`
- **Validation:** A UI test or manual check confirming that running background shells and subagents both surface in a single session view with correct running/completed/failed state and elapsed time, once the SDK subscription data is available.
- **Behavior:**

  > In an Agents window session, a user should be able to see, in one place, all background work: async shell commands and background subagent runs, each with kind, label, state (running/completed/failed), elapsed time, exit code, and actions to open output/chat or stop. Today async shells are invisible outside per-tool-card transcript output, and subagents are only visible via a separate Subagents pill.
- **Trace:**

  > The Agent Host already tracks background tasks via rpc.tasks.list() and the session.background_tasks_changed event but currently only uses that data to reconcile subagent state, not to surface async shell activity; the Subagents pill (src/vs/sessions area) shows subagents grouped In Progress/Completed as of #337237 but has no equivalent for async shells. Full data plumbing for shell output/state additionally depends on github/copilot-sdk#2351, which is outside this repo and not yet landed. Do not conflate this with the Subagents pill redesign; the open question is whether background shells join that same surface or get a new one.
- **Open decisions:**
  - Should background shells and subagents share one unified 'Background activity' surface, or should the existing Subagents pill be extended with a separate shells section?
  - Where should this surface live — a pill, a panel section, or per-session detail view?
  - Should this wait until github/copilot-sdk#2351 lands, or can a partial UI ship first using only currently available subagent data?
