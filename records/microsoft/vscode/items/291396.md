## Plan brief

- **Validation:** On current vscode.dev in Firefox, hover an Explorer file and an editor tab, move the pointer into the editor, and verify each tooltip disappears after the normal dismissal delay; also run the platform hover browser tests to preserve sticky, interactive, and delayed-hover behavior.
- **Behavior:**

  > In Firefox, a non-sticky tooltip shown for an Explorer entry or editor tab must disappear after the pointer leaves its hover boundary, matching behavior in Chromium-based browsers. Delayed tooltips must not appear after the pointer has already left. Sticky and interactive hovers must remain usable. Acceptance requires confirming both Explorer and editor-tab scenarios on current vscode.dev in Firefox.
- **Trace:**

  > Both affected surfaces use the shared workbench hover implementation. HoverService in src/vs/platform/hover/browser/hoverService.ts starts delayed hovers from MOUSE_OVER; HoverWidget and CompositeMouseTracker in src/vs/platform/hover/browser/hoverWidget.ts track MOUSE_OVER/MOUSE_LEAVE and debounce dismissal for 200 ms. The report and https://github.com/coder/code-server/issues/6719 establish the Firefox symptom, but the exact event sequence on current main remains untraced. Recent hover fixes address resize suppression and explicit cancellation rather than this pointer-exit case. Keep the boundary within shared hover lifecycle behavior; do not alter tooltip content, global hover-delay semantics, or sticky-hover interaction.
