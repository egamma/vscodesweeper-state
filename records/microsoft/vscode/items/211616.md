# Issue #211616 — Soft Assertion Failed

[https://github.com/microsoft/vscode/issues/211616](https://github.com/microsoft/vscode/issues/211616)

## Summary

Keep open: current source still admits invalid unchanged-region visibility counts, and later telemetry reports the same assertion path. The newer replacement report cannot serve as a duplicate canonical for this re-reviewed, older issue.

## Change summary

Updating a diff editor's unchanged regions can produce invalid visibility counts and emit Soft Assertion Failed.

## Best solution

Preserve valid top and bottom visibility counts when edits shrink an unchanged region, without losing the user's expanded context. Keep this older issue as the tracking record and associate the newer telemetry evidence with it.

## Evidence

- **Original confirmation:** The provided maintainer comment dated 2024-07-17 confirms over 200 occurrences on 1.92 Insiders. The original stack reaches UnchangedRegion construction through updateUnchangedRegions in src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts.
- **Current source defect:** In src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts:174-186, updateUnchangedRegions transfers visibility after decoration ranges change. It clamps the top count to the new length but computes the bottom limit using the old top count. For an old top count of 5, bottom count of 0, and new length of 3, it constructs UnchangedRegion with top=3 and bottom=-2. The constructor at lines 524-528 normalizes bottom to 0 and necessarily emits the bottom-count soft assertion. This is a source trace, not an executed reproduction.
- **Additional assertion path:** The unchanged-region autorun in src/vs/editor/browser/widget/diffEditor/diffEditorViewModel.ts:108-116 reconstructs regions using updated decoration lengths and unchanged visibility counts without accounting for shrinkage. A new length smaller than the previous top count reaches the constructor's top-count assertion.
