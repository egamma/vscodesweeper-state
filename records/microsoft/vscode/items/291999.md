# Issue #291999 — GitHub Copilot Connection Pool Issue with Forticlient VPN

[https://github.com/microsoft/vscode/issues/291999](https://github.com/microsoft/vscode/issues/291999)

## Summary

Well-diagnosed report of stale connection pool sockets causing Copilot timeouts behind Forticlient VPN. The issue is specific to a particular VPN product's aggressive firewall state cleanup, making it niche but real. The reporter's analysis is detailed, but no independent reproduction or commenter confirmation exists, and the root cause sits at the boundary of Node.js undici, the VPN's NAT behavior, and VS Code's request layer — making it hard to verify from source alone. Keeping open for area routing.

## Change summary

Copilot requests fail with UND_ERR_CONNECT_TIMEOUT after short idle periods when using Forticlient VPN, because the connection pool reuses sockets that the VPN's firewall has silently dropped.

## Best solution

The request service in `src/vs/platform/request/node/requestService.ts` does not expose connection pool idle-timeout or keep-alive configuration. The best path is either (a) adding a connection pool max-idle-time setting (e.g. `http.connectionPool.maxIdleTime`) so users behind aggressive firewalls can tune it, or (b) having the Copilot extension catch `UND_ERR_CONNECT_TIMEOUT` and retry with a fresh connection. The Copilot team should evaluate which layer owns the retry.
