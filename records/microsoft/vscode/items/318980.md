# Issue #318980 — npm run export-policy-data is not reliable

[https://github.com/microsoft/vscode/issues/318980](https://github.com/microsoft/vscode/issues/318980)

## Summary

Real bug, still present on main. The export-policy-data script runs `code.sh --export-policy-data` without forcing the workbench window type, so if the last session was an agents window, VS Code opens that instead — and the policy export contribution misses settings contributions not loaded in the agents window. Team-authored and labeled `important`; keeping open.

## Change summary

The `npm run export-policy-data` command unreliably exports policies because it opens whichever window type VS Code last used (workbench or agents), rather than always opening the full workbench.

## Best solution

Pass a CLI flag (e.g. `--force-window-type=workbench` or an equivalent mechanism) from `build/lib/policies/exportPolicyData.ts` when invoking `code.sh --export-policy-data` to guarantee the full workbench loads, ensuring all configuration contributions are registered. Alternatively, the `PolicyExportContribution` could be moved or duplicated into a layer shared by both window types, though forcing the workbench is simpler and more robust.
