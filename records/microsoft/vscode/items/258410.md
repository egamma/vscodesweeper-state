# Issue #258410 — Incorrect value of resource parameter is sent during authentication when two MCP servers have the same host

[https://github.com/microsoft/vscode/issues/258410](https://github.com/microsoft/vscode/issues/258410)

## Summary

Already fixed and shipped. The auth provider matching was made resource-specific so that MCP servers on the same host each get their own authentication session with the correct `resource` parameter.

## Change summary

When two MCP servers share the same host, VS Code incorrectly reuses the first server's auth session (and its `resource` parameter) for the second server.

## Best solution

Keep the shipped fix in commit 3fe7649e8a9 (1.107.0); the `matchesProvider` function now checks the `resourceServer` URI, and dynamic auth providers are keyed by both authorization server and resource. No further change is needed.
