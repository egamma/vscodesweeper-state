# Issue #250042 — macOS: New setting for always opening new windows in native tabs

[https://github.com/microsoft/vscode/issues/250042](https://github.com/microsoft/vscode/issues/250042)

## Summary

Keep this accepted, 45-upvote request open: current source still lacks a VS Code-specific preference for automatically opening new windows as native tabs independently of the macOS-wide setting. Existing commands only partially cover the request, and no verified canonical or landed VS Code implementation was found.

## Change summary

Add a VS Code-specific preference for opening newly created macOS windows in native tabs without changing the system-wide tab preference.

## Best solution

Provide an opt-in automatic native-tab preference in the window configuration and creation path, preserving current behavior for users who do not enable it. Settle the setting contract before implementation and account for the separately reported native-tab title-swapping behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/electron-browser/desktop.contribution.ts`, `src/vs/platform/window/common/window.ts`, `src/vs/platform/windows/electron-main/windowsMainService.ts`, `src/vs/platform/windows/electron-main/windows.ts`, `src/vs/platform/windows/electron-main/windowImpl.ts`, `src/vs/platform/native/electron-main/nativeHostMainService.ts`
- **Validation:** On macOS, enable native tabs and the agreed automatic-tab preference, fully restart, and set the system tab preference to Never, In Full Screen outside full-screen mode, and Always in turn. With an existing window, exercise File: New Window, opening a recent folder into a new window, and code --new-window <folder>; each should create a correctly titled native tab. Disable the new preference and verify existing OS-dependent behavior and the explicit New Window Tab command remain unchanged. Check the title-swapping scenario documented at https://github.com/microsoft/vscode/issues/276577.
- **Behavior:**

  > Users should be able to opt into automatically grouping newly created VS Code windows as macOS native tabs without changing the system-wide preference for other applications. The behavior should apply across window-opening actions, not only New Window Tab. Users who do not opt in should retain existing behavior, and window reuse should remain distinct from creating a new tab. Acceptance includes the macOS preference matrix, correct tab titles, and unchanged explicit native-tab commands.
- **Trace:**

  > window.nativeTabs is registered in src/vs/workbench/electron-browser/desktop.contribution.ts and enables tabbingIdentifier in src/vs/platform/windows/electron-main/windows.ts. WindowsMainService.openInBrowserWindow in src/vs/platform/windows/electron-main/windowsMainService.ts creates the window and attaches it to the last active window only when forceNewTabbedWindow is supplied. NativeHostMainService.newWindowTab in src/vs/platform/native/electron-main/nativeHostMainService.ts supplies that flag for the explicit empty-window command, and CodeWindow.addTabbedWindow in src/vs/platform/windows/electron-main/windowImpl.ts delegates to Electron on macOS. These paths confirm the missing automatic preference, not a defect in the current boolean contract. Preserve window reuse, non-macOS behavior, and existing behavior for users who do not opt in. https://github.com/posit-dev/positron/issues/8731 demonstrates a different product's choice to change the existing boolean semantics; it does not settle VS Code's contract. https://github.com/microsoft/vscode/issues/276577 records a separate title-swapping concern on the explicit attachment path that validation should distinguish.
- **Open decisions:**
  - Should automatic native-tab grouping be a separate opt-in preference, as requested for backward compatibility, or should enabling window.nativeTabs itself imply automatic grouping?
