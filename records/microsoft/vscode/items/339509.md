# Issue #339509 — Agent-host sessions switch model after their first turn because no agent-host model is declared default

[https://github.com/microsoft/vscode/issues/339509](https://github.com/microsoft/vscode/issues/339509)

## Summary

Confirmed on main: AgentHostLanguageModelProvider publishes every model with isDefaultForLocation: {} (no declared default), so after the first turn the chat input falls back to the alphabetically-first non-BYOK model instead of the agent's actual default — causing an unwanted model switch or a failure when that model isn't available. An open PR already proposes the fix, so this should stay open pending review/merge of that PR rather than being closed now.

## Change summary

A new agent-host session (e.g. Codex) silently switches away from its default model after the first turn because the agent host never declares which model is the default.

## Best solution

Land PR #339510 (https://github.com/microsoft/vscode/pull/339510), which has AgentHostLanguageModelProvider declare the agent's real default model so ChatInputModelSelectionController's fallback matches it instead of sorting alphabetically.
