# Issue #212167 — Debugger: Collapse multiline values in variable pane preview

[https://github.com/microsoft/vscode/issues/212167](https://github.com/microsoft/vscode/issues/212167)

## Summary

The requested debugger polish remains unimplemented on current main, and a maintainer explicitly supported a collapsed preview that visibly represents newlines. The related PR was closed without merging because its CSS-only approach did not provide those markers.

## Change summary

Render multiline debugger variable values as informative single-line previews that expose newline boundaries and use the available horizontal space.

## Best solution

Keep collapsed debug values on one row, represent embedded newlines with a clear accessible separator, and preserve the original multiline value in the rich hover, copy, and editing paths.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugExpressionRenderer.ts`, `src/vs/workbench/contrib/debug/browser/variablesView.ts`, `src/vs/workbench/contrib/debug/test/browser/baseDebugView.test.ts`
- **Validation:** Extend the Debug - Base Debug View unit tests to assert that a multiline Variable gets a one-row preview with the selected newline indicator while generic/full-value rendering retains the original newline characters.
- **Behavior:**

  > A multiline DAP variable value has an informative one-row preview: text after each newline remains visible when space permits, and every removed line boundary is represented explicitly. Horizontal overflow still produces an ellipsis. The rich hover, copied value, and variable-editing value retain the original multiline text.
- **Trace:**

  > VariablesRenderer in src/vs/workbench/contrib/debug/browser/variablesView.ts delegates collapsed values to DebugExpressionRenderer.renderVariable in src/vs/workbench/contrib/debug/browser/debugExpressionRenderer.ts. renderVariable currently delegates the unchanged DAP value to renderValue, while debug.contribution.css and debugViewlet.css preserve embedded newlines with `white-space: pre`, causing the row to expose only the first line. renderValue is shared with REPL and hover paths, and its local `value` is reused for rich-hover content, so the boundary is the collapsed preview rather than the underlying Variable value or every renderValue consumer. The existing test in src/vs/workbench/contrib/debug/test/browser/baseDebugView.test.ts confirms that generic rendering preserves `render \n me`; that behavior must not regress. The CSS-only attempt at https://github.com/microsoft/vscode/pull/212168 was closed because it collapsed whitespace without visibly representing newlines.
- **Open decisions:**
  - Which visible and accessible representation should replace LF, CRLF, and CR line boundaries in a collapsed preview, including any surrounding spacing?
  - Should this behavior apply only to the Variables pane requested here, or consistently to other collapsed DebugExpressionRenderer variable previews such as Watch and nested REPL variables?

## Evidence

- **maintainer direction:** A debug maintainer supported the change but required newline boundaries to remain visible in the collapsed value: https://github.com/microsoft/vscode/issues/212167#issuecomment-2099724140
- **current source:** src/vs/workbench/contrib/debug/browser/debugExpressionRenderer.ts passes the raw value through linkify/ANSI rendering for the inline preview and separately reuses it for the rich hover; there is no collapsed-preview newline representation.
- **current styling:** src/vs/workbench/contrib/debug/browser/media/debug.contribution.css and debugViewlet.css still apply `white-space: pre` to debug expressions and values, so an embedded newline ends the visible first-line preview without a truncation indicator.
- **closed implementation attempt:** https://github.com/microsoft/vscode/pull/212168 only removed the two `white-space: pre` declarations and was closed unmerged after the maintainer requested visible newline markers.
- **existing test surface:** src/vs/workbench/contrib/debug/test/browser/baseDebugView.test.ts already exercises DebugExpressionRenderer.renderValue and renderVariable, including preservation of a raw multiline value.
