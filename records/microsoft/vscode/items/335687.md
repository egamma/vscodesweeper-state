# Issue #335687 — Agent Host downloads Claude SDK 0.3.239 / Claude Code 2.1.239, but Fable 5.1 requires >= 2.1.251

[https://github.com/microsoft/vscode/issues/335687](https://github.com/microsoft/vscode/issues/335687)

## Summary

The exact version gap reported here is gone on current main — package.json now pins @anthropic-ai/claude-agent-sdk 0.3.281, whose npm metadata lists claudeCodeVersion 2.1.281, comfortably above Fable 5.1's stated 2.1.251 minimum — but I can't cite a genuine fix commit (this checkout is a 1-commit shallow clone, so the visible HEAD commit touching package.json is an unrelated feature PR, not the real bump), and the thread itself shows the underlying problem recurs with every new model (Opus 5.5 needed 2.1.280 against a then-pinned 2.1.258). Keeping open as the chronic 'Agent Host's pinned Claude SDK lags newly-exposed models' issue.

## Change summary

Agent Host's pinned/downloaded Claude Agent SDK bundles a Claude Code build too old for a model already shown in the picker (Fable 5.1 needs 2.1.251+, the downloaded SDK 0.3.239 only had 2.1.239), and the resulting error doesn't point at the Agent Host runtime as the thing needing an update.

## Best solution

Two parts: (1) the immediate Fable 5.1 vs 2.1.251 gap is already closed by routine SDK version bumps (main pins 0.3.281 / Claude Code 2.1.281); (2) the structural ask remains — either gate model availability in the picker on the Agent Host-managed runtime's actual bundled Claude Code version, or make the incompatibility error explicitly name the Agent Host SDK cache (not the user's system Claude Code / extension) as what needs updating, so users don't chase the wrong binary as in this report.
