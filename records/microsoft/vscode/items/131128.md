# Issue #131128 — Allow quick pick items to always be visible and sticky

[https://github.com/microsoft/vscode/issues/131128](https://github.com/microsoft/vscode/issues/131128)

## Summary

Keep open: existing separators and recent-command pinning do not provide a selectable action group that remains visible while scrolling. The earlier pinning PR preceded the reopening, and no verified canonical owns the remaining request.

## Change summary

Expose a Quick Pick API for visually separated, scroll-sticky items that remain searchable through normal filtering.

## Best solution

Design an opt-in Quick Pick API for keeping a small group of selectable actions visible independently of list scrolling, preserving ordinary text filtering and keyboard selection. Resolve the public grouping contract before implementing the renderer and extension API integration.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/platform/quickinput/common/quickInput.ts`, `src/vs/platform/quickinput/browser/quickInputList.ts`, `src/vs/workbench/api/common/extHostQuickOpen.ts`, `src/vs/workbench/api/browser/mainThreadQuickOpen.ts`
- **Validation:** Exercise an extension-created quick pick with enough ordinary items to overflow and a designated sticky action group: scroll through the list and verify the group remains visible; type matching and nonmatching queries and verify normal filtering; select a matching action using the keyboard and verify the accepted item. Include regression checks that quick picks without the opt-in retain their existing scrolling, filtering, and selection behavior.
- **Behavior:**

  > Extensions should be able to designate a small, visually separated group of selectable Quick Pick actions that remains visible when the ordinary list scrolls. These actions should participate in normal text filtering, allowing users to find and accept them by typing rather than traversing the entire list. Acceptance must cover an overflowing list, matching and nonmatching queries, and keyboard selection. Existing quick picks must retain their current behavior unless they opt in.
- **Trace:**

  > QuickPickItem in src/vscode-dts/vscode.d.ts offers separators and alwaysShow, but no scroll-sticky placement contract. QuickInputList.setElements and filter in src/vs/platform/quickinput/browser/quickInputList.ts build and filter one tree containing ordinary items and separator groups. showWithPinnedItems in src/vs/platform/quickinput/browser/quickPickPin.ts duplicates favorites into a leading section; it does not keep them visible during scrolling. ExtHostQuickOpen serializes item fields and label-only separators in src/vs/workbench/api/common/extHostQuickOpen.ts, with main-thread handling in src/vs/workbench/api/browser/mainThreadQuickOpen.ts. The remaining uncertainty is the public API's grouping contract and its interaction with constrained picker height, not whether alwaysShow satisfies this request. Preserve ordinary filtering and existing non-opt-in picker behavior; do not expand this into persisted favorites or custom result sorting. https://github.com/microsoft/vscode/pull/158037 predates the reopening, and https://github.com/microsoft/vscode/issues/149057 supplies related design discussion rather than proof of completion.
- **Open decisions:**
  - Should the public API designate individual sticky items or a separator-delimited sticky group, determining how extensions express membership and placement?
  - When the requested sticky group cannot fit alongside the ordinary list, what visible overflow behavior should the picker guarantee?
