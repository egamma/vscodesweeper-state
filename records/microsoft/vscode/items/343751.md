# Issue #343751 — Agent sandbox: `allowRead` ancestor of an `allowWrite` path shadows the write bind — workspace becomes read-only (`EROFS`) in sandboxed terminal

[https://github.com/microsoft/vscode/issues/343751](https://github.com/microsoft/vscode/issues/343751)

## Summary

Keep open: the reporter confirmed the failure after upgrading, and the sandbox-runtime source still contains the ancestor/descendant exception gap described in the report. The fix belongs in the runtime dependency, with adoption verified on VS Code's sandboxed-terminal path.

## Change summary

Preserve workspace write access when an allowRead ancestor overlaps an allowWrite descendant beneath a denied home directory.

## Best solution

Correct the Linux mount ordering in microsoft/vscode-sandbox-runtime so readable ancestors do not shadow explicitly writable descendants, while preserving explicit deny restrictions. Adopt the corrected runtime in VS Code and verify the reported WSL scenario; a rebase alone is not evidence that this behavior is fixed.
