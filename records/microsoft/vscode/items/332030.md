# Issue #332030 — chat status doesn't update when connection is lost

## Summary

Fresh, first-hand bug report from a VS Code team member: the chat/agent session status UI keeps showing as active/working even after the remote connection has actually dropped, only surfacing the truth when exporting debug logs. No fix exists yet, so this should be routed to the right area owner.

## Change summary

The chat/agent session status indicator doesn't update to reflect that the underlying remote connection has been lost, leaving a stale 'working' appearance.

## Best solution

Have the agent session / agent host status UI (e.g. the title bar status widget or chat status entry) subscribe to actual connection-liveness signals from the agent host/remote layer instead of only reflecting the last-known session state, so a dropped remote connection is reflected promptly instead of only being discoverable via exported debug logs.
