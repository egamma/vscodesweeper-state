# Issue #309447 — Feature Request: Allow `task.allowAutomaticTasks` to be set at the workspace level

[https://github.com/microsoft/vscode/issues/309447](https://github.com/microsoft/vscode/issues/309447)

## Summary

The workspace-level control remains missing: the setting and Manage Automatic Tasks command still apply globally. Keep this accepted, 33-upvote backlog request open for human review of the automatic-execution consent boundary; the security concerns also preclude a cleanup close.

## Change summary

Allow workspace-specific automatic-task preferences to override the global task.allowAutomaticTasks setting independently of Workspace Trust.

## Best solution

Provide independent per-workspace automatic-task control in the tasks contribution while preserving Workspace Trust enforcement. A maintainer must settle whether repository-authored settings may authorize execution or whether enabling automatic tasks requires separately recorded user consent.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/tasks/browser/task.contribution.ts:537-548 registers task.allowAutomaticTasks with ConfigurationScope.APPLICATION, default 'off', and restricted: true. Workspace settings therefore do not provide the requested override.
- **Command and permission flow remain global:** In src/vs/workbench/contrib/tasks/browser/runAutomaticTasks.ts, ManageAutomaticTaskRunning uses command ID workbench.action.tasks.manageAutomaticRunning and writes ConfigurationTarget.USER. _showPrompt likewise writes USER settings and explicitly asks about allowing tasks in all trusted workspaces. Its workspace-scoped storage records whether a prompt was shown, not workspace-specific authorization.
- **Trust is a separate existing gate:** RunAutomaticTasks._tryRunTasks returns when isWorkspaceTrusted() is false; _runWithPermission runs discovered folderOpen tasks when the effective global setting is 'on'. The requested distinction between trusting a workspace and enabling its automatic tasks is not currently represented by a workspace-specific preference.
- **Accepted community demand:** https://github.com/microsoft/vscode/issues/309447 has 33 community upvotes and the Backlog milestone. The supplied April 17 bot comment confirms promotion after reaching the community threshold. The fully read https://github.com/microsoft/vscode/wiki/Issues-Triaging describes Backlog as accepted, unscheduled work.
