# Issue #309447 — Feature Request: Allow `task.allowAutomaticTasks` to be set at the workspace level

[https://github.com/microsoft/vscode/issues/309447](https://github.com/microsoft/vscode/issues/309447)

## Summary

The workspace-level control remains missing: both the permission prompt and Manage Automatic Tasks command still change the global setting. Keep this accepted, community-supported request open for a human security/design review of per-workspace authorization.

## Change summary

Allow workspace-specific automatic-task preferences to override the global task.allowAutomaticTasks setting.

## Best solution

Provide per-workspace control over automatic task execution independently of Workspace Trust, with explicit user authorization that repository-authored configuration cannot silently grant itself. The tasks owner should settle how workspace preferences interact with global defaults and consent before implementation.

## Evidence

- **Existing capability does not cover the request:** src/vs/workbench/contrib/tasks/browser/task.contribution.ts registers TaskSettingId.AllowAutomaticTasks with scope: ConfigurationScope.APPLICATION, default: 'off', and restricted: true. It does not expose the requested workspace override.
- **Permission and command paths remain global:** In src/vs/workbench/contrib/tasks/browser/runAutomaticTasks.ts, RunAutomaticTasks._showPrompt explicitly asks about all trusted workspaces and writes ConfigurationTarget.USER for both Allow and Disallow. ManageAutomaticTaskRunning.run also writes ConfigurationTarget.USER; its command ID is workbench.action.tasks.manageAutomaticRunning. The workspace-scoped HAS_PROMPTED_FOR_AUTOMATIC_TASKS value records prompt history, not separate workspace authorization.
- **Trust and security boundary:** RunAutomaticTasks._tryRunTasks rejects untrusted workspaces before evaluating automatic-task permission. The report explicitly concerns automated code execution and least privilege, and the September 7 comment raises a malware concern. This is security-sensitive design work: keep it open for human review rather than proposing a close or an agent implementation.
