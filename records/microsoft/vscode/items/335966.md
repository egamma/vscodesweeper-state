# Issue #335966 — Multi-diff editor disposal hangs as rendering replenishes the template pool

[https://github.com/microsoft/vscode/issues/335966](https://github.com/microsoft/vscode/issues/335966)

## Summary

Well-traced, source-verified bug: current main's VirtualizedTemplatePool.dispose() iterates the live `_used` Set while template.dispose() can synchronously trigger re-render/acquire, adding new items to the same Set and extending (or indefinitely prolonging) the teardown loop. Already correctly labeled bug/multi-diff-editor, so this stays open for the assigned maintainer.

## Change summary

Disposing a MultiDiffEditor whose input/view model is still live can hang because pool teardown races with in-flight rendering that keeps acquiring replacement templates.

## Best solution

Fix VirtualizedTemplatePool.dispose (and the widget's registration of rendering consumers in multiDiffEditorWidgetImpl.ts) so acquisition/rendering is stopped or the used-template set is snapshotted before iterating, per the reporter's own fix direction; add the suggested clear/rebind/direct-dispose regression test.
