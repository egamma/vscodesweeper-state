# Issue #334569 — MCP tool calls intermittently rejected "disabled by the user" while cache shows enabled and server log shows execution

[https://github.com/microsoft/vscode/issues/334569](https://github.com/microsoft/vscode/issues/334569)

## Summary

Confirmed on current main: MCP tools (tags=['mcp']) only enter ask-mode's availableTools via a static toolReferences snapshot taken at request-parse time, so tools registered after that snapshot (slow/async server discovery, multi-window stale state) get rejected as "disabled by the user" even though they're enabled — but a PR already targets this fix, so it should be reviewed/landed rather than closed here.

## Change summary

Ask-mode MCP tool calls intermittently fail with a misleading "disabled by the user" error because tool availability is computed from a stale snapshot rather than live registration state.

## Best solution

Land the more conservative fix (scoping newly-registered MCP tools to the referenced server, PR https://github.com/microsoft/vscode/pull/334657) into askAgentIntent.ts / chatRequestParser.ts rather than the broader mcp_-prefix version (PR https://github.com/microsoft/vscode/pull/334641, already closed) to avoid widening the authorization boundary across servers.
