# Issue #334569 — MCP tool calls intermittently rejected "disabled by the user" while cache shows enabled and server log shows execution

[https://github.com/microsoft/vscode/issues/334569](https://github.com/microsoft/vscode/issues/334569)

## Summary

Well-diagnosed bug confirmed in current source: ask-mode MCP tool availability is computed from a static toolReferences snapshot at request-parse time, so tools registered after that moment are rejected as 'disabled by the user' even though they're enabled — an open PR already targets the fix, so this should stay open for maintainer review rather than close.

## Change summary

MCP tool calls in ask mode are intermittently rejected as 'disabled by the user' when the tool registers asynchronously after the request's tool-reference snapshot is taken, even though the tool is actually enabled and the server executes it.

## Best solution

Land (or select between) the two competing fixes already proposed: PR #334657 (scope availability to referenced servers, preserving authorization boundaries) is the safer option per the reporter's own comparison versus PR #334641 (broad mcp_ prefix allow-list, which widens exposure across MCP servers) — a maintainer should review and merge the preferred one in askAgentIntent.ts / chatRequestParser.ts.
