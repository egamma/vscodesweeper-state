# Issue #334569 — MCP tool calls intermittently rejected "disabled by the user" while cache shows enabled and server log shows execution

[https://github.com/microsoft/vscode/issues/334569](https://github.com/microsoft/vscode/issues/334569)

## Summary

Well-diagnosed, source-verified bug: ask mode builds MCP tool availability from a static toolReferences snapshot taken at request-parse time, so tools registered after async server discovery completes get wrongly rejected as 'disabled by the user'. Two competing fix PRs are open/closed already, so this should stay open pending a maintainer decision on which fix to land, not be closed by this review.

## Change summary

MCP tool calls in Copilot Chat ask mode are intermittently rejected as 'disabled by the user' even though the tool is enabled and the server actually executes it, due to a race between async MCP tool discovery and a static tool-availability snapshot taken at request parse time.

## Best solution

Land one of the two proposed fixes to extensions/copilot/src/extension/intents/node/askAgentIntent.ts (and chatRequestParser.ts) — the scoped variant in https://github.com/microsoft/vscode/pull/334657 is the safer choice since it preserves per-server authorization boundaries, versus the looser https://github.com/microsoft/vscode/pull/334641 which was already closed.
