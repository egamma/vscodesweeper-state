# Issue #338680 — Agent Host (Copilot): hooks from marketplace-installed agent plugins are never invoked since 1.139

[https://github.com/microsoft/vscode/issues/338680](https://github.com/microsoft/vscode/issues/338680)

## Summary

Well-documented, fresh regression report (0 days old, no maintainer response yet); current source confirms the architectural boundary the reporter describes, but the actual failure point (native hook invocation for pluginDirectories) lives inside the pinned @github/copilot-sdk dependency, which this checkout cannot execute or inspect, so the exact fix location is not yet certain.

## Change summary

Hooks declared by marketplace-installed agent plugins (hooks.json) stop being invoked in Copilot Agent Host sessions since VS Code 1.139 / Copilot Chat 0.67.0, even though the plugin and its skills still load correctly.

## Best solution

Diagnose whether the regression is in the pinned @github/copilot-sdk (1.0.15-preview.4) native pluginDirectories hook-invocation path, or whether VS Code's own launcher needs to fall back to explicitly wiring hooks for on-disk plugins (in copilotSessionLauncher.ts) instead of relying entirely on the SDK; a maintainer should weigh the duplicate-invocation risk of the latter before choosing.

## Plan brief

- **Likely files:** `src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts`, `src/vs/platform/agentHost/node/copilot/copilotPluginConverters.ts`
- **Validation:** An Agent Host e2e/integration test asserting that a plugin installed with an on-disk pluginDir and a hooks.json has its userPromptSubmitted/preToolUse/postToolUse hooks actually invoked during a session (not just discovered/loaded).
- **Behavior:**

  > A Copilot plugin installed from a marketplace (with its own hooks.json at the plugin root) should have its declared hooks (userPromptSubmitted, preToolUse, postToolUse) invoked during a Copilot Agent Host session, exactly as it was on 1.138. Currently the plugin loads and its skills work, but none of its hooks fire — a silent regression with no error surfaced to the user.
- **Trace:**

  > copilotSessionLauncher.ts's _buildSessionConfig only explicitly wires plugin hooks into the SDK's `hooks:` option for `pluginsWithoutDirs` (plugins lacking a file-scheme pluginDir) at line ~1063 via toSdkHooks(); plugins with an on-disk directory are instead passed via `pluginDirectories` (line ~1086) and are documented (comment at line ~927) as relying entirely on the SDK's own native discovery to register and invoke their hooks. The reporter's trace (hook.start/hook.end events show only built-in hooks; a wrapper around the plugin's own hook command never logs an invocation) is consistent with that native path failing to fire for on-disk plugins since the @github/copilot-sdk dependency bump between the 1.138 and 1.139 releases (package.json pins 1.0.15-preview.4). The uncertainty starts at whether the native SDK path itself regressed (fix belongs upstream in @github/copilot-sdk, not this repo) or whether VS Code should add an explicit hook-wiring fallback for on-disk plugins similar to pluginsWithoutDirs (which would risk duplicate hook invocation once/if the SDK's native path is fixed).
- **Open decisions:**
  - Is the native pluginDirectories hook-invocation regression confirmed to live in @github/copilot-sdk, and if so, should VS Code wait for an upstream SDK fix/bump rather than change its own wiring?
  - If VS Code should mitigate locally, should hooks for on-disk plugins be projected explicitly (like pluginsWithoutDirs) even at the risk of duplicate invocation once the SDK's native path works again, or should some other guard be added?
  - Should a warning/telemetry signal be surfaced when a plugin's hooks are silently never invoked, given the security/compliance implications called out by the reporter?

## Evidence

- **deliberate design boundary:** src/vs/platform/agentHost/node/copilot/copilotSessionLauncher.ts:927-933 explicitly documents relying on the SDK to discover agents/skills/hooks from `pluginDirectories` for on-disk plugins, only projecting hooks explicitly for `pluginsWithoutDirs` (plugins with no file-scheme pluginDir).
- **explicit hook wiring is the exception, not the rule:** toSdkHooks(pluginsWithoutDirs.flatMap(p => p.hooks), ...) at copilotSessionLauncher.ts:1063 only merges hooks for plugins lacking an on-disk directory; a marketplace-installed plugin (which does have a synced pluginDir) is excluded from this explicit path, matching the reporter's trace showing hook.start/hook.end never firing for the plugin's commands.
- **pinned SDK dependency:** package.json:102 pins "@github/copilot-sdk": "1.0.15-preview.4" — the native hook invocation for pluginDirectories-supplied plugins is implemented inside this external, closed-source package, not in this repository, so the regression between 1.138 and 1.139 cannot be confirmed or fixed purely from this checkout.
- **distinguished from a candidate canonical:** Reporter explicitly checked and ruled out https://github.com/microsoft/vscode/issues/330114 (a UI-discovery gap in sessionCustomizationDiscovery.ts's discoverHooks(), unrelated to actual invocation) and https://github.com/microsoft/vscode/issues/338571 (custom-agent frontmatter hooks, not plugin hooks.json); neither appears to own this regression.
- **no open issue found:** Reporter references a closed, unmerged PR (#337811) as matching the root cause but could not find an open tracking issue for it.
