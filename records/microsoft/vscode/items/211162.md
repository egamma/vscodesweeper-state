# Issue #211162 — I misunderstood yieldTo

[https://github.com/microsoft/vscode/issues/211162](https://github.com/microsoft/vscode/issues/211162)

## Summary

Still valid on main: the `sortEditsByYieldTo` topological sort is input-order-dependent, so edits without `yieldTo` that appear later in the array sort below edits they should rank above. The API owner acknowledged the unexpected behavior but no fix or doc clarification has landed.

## Change summary

When a provider returns multiple paste edits where only some use `yieldTo`, the sort result depends on array position rather than purely on the yield graph, producing a confusing ordering.

## Best solution

Fix the topological sort in `src/vs/editor/contrib/dropOrPasteInto/browser/edit.ts` so that non-yielding edits rank above yielding edits regardless of input order, and clarify the `yieldTo` docstring in `vscode.d.ts` to document the expected ordering semantics. Add a test case in `editSort.test.ts` covering the mixed-yieldTo scenario from this report.
