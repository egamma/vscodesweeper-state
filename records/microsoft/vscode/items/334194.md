# Issue #334194 — Debug Console: The Hyperlink annotation is missing a port.

[https://github.com/microsoft/vscode/issues/334194](https://github.com/microsoft/vscode/issues/334194)

## Summary

Confirmed root cause in source: the debug console splits ANSI-styled text into per-style segments and runs link detection independently on each segment (appendStylizedStringToContainer → linkDetector.linkify), so a URL whose port is highlighted in a different SGR style than the rest (e.g. Vite bolds just the port digits) gets truncated at the style boundary — the hyperlink (and its href) stops before the port instead of covering the full URL.

## Change summary

In the Debug Console, a URL split across an ANSI style boundary (e.g. Vite bolding just the port number) is only partially recognized as a hyperlink, dropping the port and trailing path from both the underline and the link target.

## Best solution

Detect links against the full logical line (with ANSI codes stripped) before splitting into per-style spans in handleANSIOutput/appendStylizedStringToContainer, then render the resulting link as one anchor spanning the differently-styled sub-runs, rather than linkifying each style segment in isolation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugANSIHandling.ts`, `src/vs/workbench/contrib/debug/browser/linkDetector.ts`
- **Validation:** Add a debugANSIHandling.test.ts case feeding ANSI text equivalent to Vite's `http://localhost:` + bold(`5173`) + `/` and asserting a single anchor's href/text covers the full 'http://localhost:5173/' instead of stopping at the style boundary.
- **Behavior:**

  > When Debug Console output contains a URL that spans an ANSI style change mid-string (e.g. only the port digits are bold while the rest of the URL is a plain color), the rendered hyperlink must still cover and link to the entire URL, not just the portion before the style change. Non-styled or uniformly-styled URLs must continue to render as they do today.
- **Trace:**

  > handleANSIOutput (src/vs/workbench/contrib/debug/browser/debugANSIHandling.ts) parses the raw text char-by-char, and on every SGR escape sequence it flushes the accumulated `buffer` via appendStylizedStringToContainer using the *previous* style, then resets `buffer`. appendStylizedStringToContainer (same file, ~line 405) calls `linkDetector.linkify(stringContent, ...)` (src/vs/workbench/contrib/debug/browser/linkDetector.ts) on only that flushed substring in isolation. Confirmed with node that WEB_LINK_REGEX (linkDetector.ts:30) matches 'http://localhost:5173/' fully when given the whole string, so the defect is purely about segment-splitting, not the regex. The boundary: do not change WEB_LINK_REGEX/PATH_LINK_REGEX matching semantics or general non-split-URL rendering; the fix must operate on how link ranges interact with the per-style buffering.
- **Open decisions:**
  - Should link detection run over the fully de-ANSI'd line up front (and then style-splitting respects link boundaries), or should adjacent style runs be coalesced/re-checked whenever a partial link match touches a run boundary?
  - How should a single link that spans multiple distinct styles (e.g. bold vs non-bold within the same color) be rendered — one anchor with nested styled spans inside it, or does the anchor need to pick one style?

## Evidence

- **regex works in isolation:** WEB_LINK_REGEX in src/vs/workbench/contrib/debug/browser/linkDetector.ts:30 correctly matches the whole 'http://localhost:5173/' string when tested standalone (verified with node).
- **per-segment linkify:** handleANSIOutput in src/vs/workbench/contrib/debug/browser/debugANSIHandling.ts flushes `buffer` and calls appendStylizedStringToContainer (line ~66/111) on every ANSI style change; appendStylizedStringToContainer (line 405) calls `linkDetector.linkify(stringContent, ...)` on just that isolated substring.
- **Vite's actual output styling:** Vite's printServerUrls (packages/vite/src/node/logger.ts) wraps the whole URL in cyan but additionally bolds only the port: `url.replace(/:(\d+)\//, (_, port) => `:${colors.bold(port)}/`)`, producing 3 separate ANSI-styled runs ('http://localhost:', '5173', '/') — exactly matching the reporter's screenshot where only 'http://localhost' is underlined.
