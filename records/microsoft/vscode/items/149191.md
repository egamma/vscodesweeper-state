# Issue #149191 — Increase max height for the hover widget?

[https://github.com/microsoft/vscode/issues/149191](https://github.com/microsoft/vscode/issues/149191)

## Summary

Partially addressed but not fully: the hover widget became manually resizable (PR #185540), yet the max size is still capped to the visible editor viewport, so a very tall image still can't be shown uncropped without scrolling. A prior review's implemented-on-main close citing that same merge commit was already refuted, so this stays open rather than re-asserting that fix.

## Change summary

Allow the hover widget's maximum height/width to exceed its current viewport-bound cap so large hover content (e.g. an image preview from an extension) isn't cropped with scrollbars.

## Best solution

Decide whether the resizable hover (already shipped) should be allowed to grow beyond the editor's visible viewport (e.g. overlay the whole window) or whether the current viewport-bound cap is intentional; if the latter, this can become *as-designed`, otherwise raise the cap in `_findMaximumRenderingHeight`/`_findMaximumRenderingWidth` in src/vs/editor/contrib/hover/browser/contentHoverWidget.ts.

- **Trace:**

  > ContentHoverWidget (src/vs/editor/contrib/hover/browser/contentHoverWidget.ts) is resizable since PR https://github.com/microsoft/vscode/pull/185540, but `_updateResizableNodeMaxDimensions` sets `_resizableNode.maxSize` from `_findMaximumRenderingHeight()`/`_findMaximumRenderingWidth()`, both of which clamp to `_findAvailableSpaceVertically()` (space within the editor's visible area) — confirmed by reading current main, no setting overrides it. The boundary: do not change general content-widget positioning/z-order; the open question is whether the hover should ever be allowed to overlay beyond the editor viewport.

## Evidence

- **remaining cap:** src/vs/editor/contrib/hover/browser/contentHoverWidget.ts `_findMaximumRenderingHeight()` (and `_findMaximumRenderingWidth()`) still bounds `_resizableNode.maxSize` to `_findAvailableSpaceVertically()`, i.e. the available space in the editor viewport — so the hover cannot be resized taller than the visible editor area.
