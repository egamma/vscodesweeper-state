# Issue #330693 — Experimental Modern UI enabled by default without user consent - unacceptable

[https://github.com/microsoft/vscode/issues/330693](https://github.com/microsoft/vscode/issues/330693)

## Summary

Real, widely-shared concern about the Modern UI experiment being auto-enabled for Stable users without an explicit opt-in or heads-up, distinct from the many 'I dislike the new look' reports already open — this is a process/consent request, not a bug, and no single canonical issue clearly owns exactly this ask.

## Change summary

Request that experimental UI redesigns (like the Modern UI A/B rollout) stay opt-in on Stable, with clear notice and an easy revert path when a major default does change.

## Best solution

Route to the workbench/UX owners as a process/policy feedback item: consider a stronger convention for staging experimental defaults (opt-in + release-notes callout + easy revert) rather than silent A/B promotion to Stable; the existing `modernization` label already surfaces the topic, but this specific consent/process framing is not covered by the aesthetic-focused duplicates.
