# Issue #330693 — Experimental Modern UI enabled by default without user consent - unacceptable

[https://github.com/microsoft/vscode/issues/330693](https://github.com/microsoft/vscode/issues/330693)

## Summary

Legitimate product-process complaint about an experimental workbench setting (Modern UI) reaching Stable via A/B rollout without an explicit opt-in, echoing a wave of similar reports; no maintainer decision exists yet on the rollout policy itself, so this needs human product judgment rather than a mechanical close.

## Change summary

Requests that experimental UI redesigns stay opt-in on Stable, that major default changes come with clear notice and an easy revert, and more broadly that VS Code's release cadence stop silently altering established workspaces.

## Best solution

A maintainer should weigh in on the A/B-experiment rollout policy for experimental settings like `workbench.experimental.modernUI` — this is a release-process question, distinct from (and broader than) the purely aesthetic complaints in the sibling Modern UI issues, so it shouldn't be folded into any of them; route to the workbench/release-process owners for a policy response.
