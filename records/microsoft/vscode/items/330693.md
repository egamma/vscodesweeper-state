# Issue #330693 — Experimental Modern UI enabled by default without user consent - unacceptable

[https://github.com/microsoft/vscode/issues/330693](https://github.com/microsoft/vscode/issues/330693)

## Summary

Real, actively-discussed complaint (26 upvotes in 5 days) about the Modern UI experiment being auto-enabled on Stable via the setting's `experiment: { mode: 'auto' }` A/B rollout mechanism, which the reporter never opted into; this is a policy/process request, not a code bug, and several sibling threads on the same rollout are open with no maintainer decision yet.

## Change summary

Requests that experimental UI redesigns like Modern UI stay opt-in on Stable, that VS Code stop silently changing established workspaces via A/B rollout, and that any forced default change come with clear notice and an easy revert.

## Best solution

A maintainer decision is needed on the A/B experiment policy for `workbench.experimental.modernUI` (src/vs/workbench/browser/workbench.contribution.ts, `experiment: { mode: 'auto' }`) — either restrict auto-rollout to Insiders, add explicit notice/opt-out UX for Stable A/B experiments, or explain the intended experiment scope; this issue and its several siblings (Modern UI feedback/performance/theming) should likely be consolidated by the team once a canonical thread is chosen.
