# Issue #341502 — Restored terminal editor attaches to a running terminal of another open window (persistent process IDs reused after pty host restart)

[https://github.com/microsoft/vscode/issues/341502](https://github.com/microsoft/vscode/issues/341502)

## Summary

Thanks for the detailed report and log analysis. The mechanism holds up in current source: pty IDs restart at 1 per pty host and attachToProcess attaches to any live pty with that ID, without checking whether another window already owns it. Keeping open as a terminal bug.

## Change summary

A restored terminal editor attaches by stored persistent ID to a different, still-attached terminal of another window after the pty host restarted and reused the ID.

## Best solution

Make attach reject (or require confirmation for) a pty that is still attached to a live window, and/or validate stored pid against the pty before reattaching, so the restored editor falls back to a fresh terminal.

## Plan brief

- **Likely files:** `src/vs/platform/terminal/node/ptyService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalEditorSerializer.ts`
- **Validation:** A ptyService test: create a pty, do not detach it, then call attachToProcess from a second window's context and assert it is rejected (or that a stored-pid mismatch fails the attach).
- **Behavior:**

  > Reopening a folder whose stored terminal editors reference persistent IDs must never attach to a terminal that is currently attached to another open window. The restored editor should fail or start a fresh terminal, and the other window's terminal is left untouched.
- **Trace:**

  > PtyService._lastPtyId resets to 0 on pty host start (ptyService.ts ~121, 336). attachToProcess -> PersistentTerminalProcess.attach() (~826) only warns when no disconnect runner is scheduled and then attaches anyway. Stored editor state records id and pid (terminalEditorSerializer.ts). Uncertainty: how to detect 'owned by another window' (the pty host has no per-window ownership) and the reattach-for-reload flow must keep working. Related: https://github.com/microsoft/vscode/issues/196264.
- **Open decisions:**
  - When the stored ID points to a pty still attached elsewhere, should restore fail silently, start a new terminal, or prompt?
  - Should the stored pid be treated as authoritative for rejecting reattach, given that pids can also be reused?

## Evidence

- **ID reuse:** src/vs/platform/terminal/node/ptyService.ts line 121 initializes _lastPtyId = 0 and line 336 does ++this._lastPtyId, so IDs restart per pty host.
- **unchecked attach:** attachToProcess (line 367) calls _throwIfNoPty(id).attach(); attach() (line 826) only warns 'had no disconnect runners but was an orphan' and proceeds, so a pty still owned by another window is attached.
