# Issue #137260 — Scope Emmet custom snippets to their respective workspaces

[https://github.com/microsoft/vscode/issues/137260](https://github.com/microsoft/vscode/issues/137260)

## Summary

Keep open: current Emmet configuration still loads custom snippets through shared helper state rather than isolating them by workspace folder. The linked maintainer discussion explicitly supports folder scoping, and the canonical search found no verified open issue that supersedes this request.

## Change summary

Restrict workspace-folder Emmet custom snippets to documents belonging to that folder in multi-root workspaces.

## Best solution

Make custom-snippet completion and expansion respect the document's workspace folder, consistently across Emmet commands. Preserve explicitly shared user snippets and establish their interaction with folder-local snippets before implementation.

Add equivalent extension-host regression coverage; no execution was performed during this read-only review.
- **Behavior:**

  > In a multi-root workspace, a custom Emmet snippet belonging to folder A must not become available in folder B, and vice versa. Both completion suggestions and explicit abbreviation expansion must respect that isolation when switching between documents. Acceptance checks must cover distinct local snippets, conflicting local abbreviation names, and snippet-file updates. The treatment of deliberately shared user-level snippet paths must be settled without silently removing their existing utility.
- **Trace:**

  > extensions/emmet/src/util.ts maintains one _emmetHelper and one _currentExtensionsPath; updateEmmetExtensionsPath reads configuration without a resource and supplies all workspace roots in one helper update. extensions/emmet/src/emmetCommon.ts invokes that shared update at activation, configuration changes, and snippet saves. DefaultCompletionItemProvider consumes the shared helper for completions, while abbreviationActions.ts:expandAbbr obtains expansion options without document context. These source paths establish that the current extension has no folder-specific selection boundary; they do not establish whether @vscode/emmet-helper can support isolated snippet contexts without changes. Preserve built-in snippets, language mappings, and unrelated Emmet preferences. The accepted direction is recorded at https://github.com/microsoft/vscode/issues/117519#issuecomment-952397804; uncertainty starts at shared-path semantics and the helper API needed to honor them.
- **Open decisions:**
  - Should absolute snippet paths configured at user or workspace level remain shared across all roots, with only folder-local paths isolated, and which definition wins when a shared and a folder-local snippet use the same abbreviation?
