# Issue #36809 — Have Shift+Tab remove whitespace within a line

[https://github.com/microsoft/vscode/issues/36809](https://github.com/microsoft/vscode/issues/36809)

## Summary

Inline whitespace removal remains distinct from the current line-leading outdent behavior; neither rebinding Outdent nor toggling Tab Moves Focus supplies it. Keep this team-authored request open for a compatibility-conscious design decision.

## Change summary

Allow Shift+Tab to remove whitespace at the caret within a line, as an inverse of inline Tab insertion.

## Best solution

Provide caret-local whitespace removal while retaining an explicit whole-line outdent operation and existing selection and focus-navigation behavior. Decide the new behavior's activation and fallback semantics before implementation.

- **Behavior:**

  > Users want to reverse inline Tab insertion without changing the indentation at the start of the line. The capability must handle both literal tabs and spaces inserted to an indentation stop, and must not delete neighboring non-whitespace text. Acceptance checks should demonstrate restoration of text and caret after inline Tab insertion, undo behavior, and preservation of explicit whole-line outdent and keyboard focus navigation. Activation and behavior when no removable inline whitespace is adjacent remain product decisions.
- **Trace:**

  > CoreEditingCommands.Outdent in src/vs/editor/browser/coreCommands.ts handles Shift+Tab and calls TypeOperations.outdent in src/vs/editor/common/cursor/cursorTypeOperations.ts. That constructs ShiftCommand, whose getEditOperations in src/vs/editor/common/commands/shiftCommand.ts exclusively edits leading indentation. TabOperation in src/vs/editor/common/cursor/cursorTypeEditOperations.ts separately inserts whitespace at the caret, so the two operations are not inverses within a line. DeleteOperations.getDeleteLeftRange in src/vs/editor/common/cursor/cursorDeleteOperations.ts provides tab-stop deletion only in leading indentation; ordinary Backspace is partial coverage, not the requested inline space-group operation. OutdentLinesAction in src/vs/editor/contrib/linesOperations/browser/linesOperations.ts delegates to the same core command, creating a compatibility boundary for explicit whole-line outdent. The closed related report https://github.com/microsoft/vscode/issues/1692 documents reliance on existing Shift+Tab behavior; it is not a duplicate target. Preserve selection-based indentation and the editorTabMovesFocus gate; no patch or runtime validation was performed.
- **Open decisions:**
  - Should caret-local removal become the default Shift+Tab behavior, or require an explicit opt-in command or binding while retaining today's default?
  - When the caret is inside a line but no removable whitespace is immediately before it, should Shift+Tab retain whole-line outdent or leave the line unchanged?
