# Issue #346200 — Support Chat Debug View for Copilot Agent

[https://github.com/microsoft/vscode/issues/346200](https://github.com/microsoft/vscode/issues/346200)

## Summary

Agent-host sessions already have opt-in debug-view support, but the current provider does not expose the complete model request, including the system prompt. Keep this request open for the remaining inspection parity rather than treating partial support as completion.

## Change summary

Expose Copilot Agent request details, including system prompts, skills, and attached-file context, in the chat debug view.

## Best solution

Provide request-inspection parity in the existing Agent Debug Logs surface, building on the agent-host provider rather than adding another view. Distinguish loaded customizations from the actual context sent with each model request.

## Evidence

- **Existing capability:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts registers chat.agentHost.agentDebugLog.enabled, defaulting to false. AgentHostChatDebugContribution is registered there and supplies agent-host events to the existing debug service. workbench.action.chat.openAgentDebugPanel opens the shared view.
- **Remaining request-detail gap:** In src/vs/workbench/contrib/chat/browser/chatDebug/agentHostChatDebugProvider.ts, convertAgentHostEventsToDebugEvents maps user.message to User Request and optional transformedContent to Full Prompt. assistant.message resolves model-turn details to Response and Reasoning sections; system.message is explicitly not surfaced. These paths do not provide the complete system-prompt/model-request inspection requested here.
- **Partial skills support:** The same provider records customization snapshots and surfaces skill.invoked, including its content when available. That supplies useful skill diagnostics but does not establish which complete prompt and attachment context reached each model request.
- **Related issue is narrower:** https://github.com/microsoft/vscode/issues/344920 is open and concerns active agent-host sessions showing no events until restart despite logging being enabled. It does not own the broader request for full request-content inspection.
- **Export report is distinct:** https://github.com/microsoft/vscode/issues/345716 is open and reports Local-session response content disappearing during debug-log export/import, not Copilot Agent request-inspection parity.
