# Issue #316336 — Agent worktree merge-back is unsafe for small changes with existing local edits

[https://github.com/microsoft/vscode/issues/316336](https://github.com/microsoft/vscode/issues/316336)

## Summary

Keep open: current main provides deterministic merge operations and normal diff review, but those do not deliver selective file/hunk application into a workspace with existing local edits. No verified older canonical owns that remaining requirement.

## Change summary

Provide a direct, reviewable way to apply selected agent-worktree files or hunks to the current workspace while preserving unrelated staged and unstaged edits.

## Best solution

Offer selective patch application from the Agents Changes/diff surface, independently of whole-branch merging or an agent turn. Preserve unrelated working-tree and index state, and make overlapping changes an explicit conflict rather than an instruction to commit unrelated work.

- **Validation:** End the plan with an executable Git-backed integration check: create a parent checkout containing independent staged and unstaged edits, create agent changes in a linked worktree, and apply only a selected file or hunk without a model turn. Verify selected content arrives, unselected agent changes do not, unrelated index entries and working-tree edits remain unchanged, and no parent commit is created. Include an overlapping-edit case asserting the agreed conflict behavior.
- **Behavior:**

  > Users can review agent-worktree changes with the normal diff experience and apply selected files or hunks to their current checkout without asking the agent to merge. Applying a non-overlapping selection preserves unrelated staged and unstaged edits and does not require committing them. Unselected agent changes remain unapplied. Overlapping edits must not be silently overwritten; the product must specify how the user resolves them.
- **Trace:**

  > SessionChangesEditor provides MultiDiffEditorWidget-based review, while changesViewActions.ts supplies the Changes surface actions. AgentHostMergeOperationContribution exposes a whole-changeset merge; AgentHostMergeOperationHandler.invoke rejects dirty parent repositories, commits all dirty source-worktree content, and merges the source branch. The separately registered chatEditing.applyChangesToParentRepo command also merges a whole branch and has a disabled menu contribution, so its name does not establish selective application. No selective file/hunk transfer path was found in the inspected sessions or Agent Host registrations. Preserve existing whole-branch merge safety and folder-mode behavior; model selection and lint execution are outside this request. Related design context is https://github.com/microsoft/vscode/issues/336620, and merge-button work is discussed at https://github.com/microsoft/vscode/issues/317937; neither replaces this older selective-application request.
- **Open decisions:**
  - Should selected agent changes arrive as unstaged working-tree edits or staged index changes, while preserving the user's existing staging choices?
  - When selected hunks overlap local edits, should application stop without modifying the checkout or offer an explicit conflict-resolution preview?
