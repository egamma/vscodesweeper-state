## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/72976 is OPEN and predates this report. It explicitly covers Source Control's Accept All Incoming action failing to resolve a deleted-by-them conflict, requesting deletion and staging of the file.
- **Current source confirms the resolution gap:** extensions/merge-conflict/package.json:113-123 exposes merge-conflict.accept.all-incoming on Git merge entries without excluding deletion conflicts. In extensions/merge-conflict/src/commandHandler.ts:275-295, acceptAllResources only applies edits to textual conflict ranges; documents without such ranges are skipped, with no Git deletion or staging operation.
- **Staging independently requests a decision:** extensions/git/src/commands.ts:396-411 categorizes deleted-by-them conflicts separately. stage invokes _stageDeletionConflict, whose implementation at lines 1595-1627 asks whether to keep or delete the file. The incoming acceptance command never communicates a deletion resolution to this path. This confirms the unresolved-state gap, although the reporter's exact warning wording was not independently reproduced.
- **Canonical discussion includes the staging workaround:** https://github.com/microsoft/vscode/issues/72976#issuecomment-1916440118 explains that Stage Changes prompts whether to delete or retain the file. This matches the extra decision encountered after the ineffective incoming-deletion action.
