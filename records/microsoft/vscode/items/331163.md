# Issue #331163 — Should jump to splitted window instead of open a new window

[https://github.com/microsoft/vscode/issues/331163](https://github.com/microsoft/vscode/issues/331163)

## Summary

Real gap: when editors are split across separate OS windows (auxiliary windows), go-to-definition doesn't check other windows for an already-open editor before opening a new copy/window. This is freshly in the 'Backlog Candidates' holding bin with the standard 60-day upvote bot comment just posted 1 day ago, so it should stay open for the community process rather than be judged on quietness.

## Change summary

When a symbol's definition is already open in a different (split-off/auxiliary) VS Code window, Go to Definition (F12) opens a brand-new window/copy instead of focusing the window that already has it open.

## Best solution

Extend the editor group/window resolution logic (src/vs/workbench/services/editor/common/editorGroupFinder.ts and the auxiliary-window group lookup used by IEditorService.openEditor) to search across existing auxiliary windows for a group already showing the target resource before creating a new editor input, and if found, reveal/focus that window's group instead.
