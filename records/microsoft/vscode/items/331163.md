# Issue #331163 — Should jump to splitted window instead of open a new window

[https://github.com/microsoft/vscode/issues/331163](https://github.com/microsoft/vscode/issues/331163)

## Summary

This is existing, configurable behavior: the `workbench.editor.revealIfOpen` setting already does exactly what's requested — reveal an already-open editor in another visible group instead of opening a duplicate in the active group. It defaults to `false` because VS Code's default is to prefer opening in the currently active group.

## Change summary

Go to Definition (F12) opens a duplicate copy of a file that is already open in another split group, instead of revealing the existing one.

## Best solution

Point the reporter to enabling `workbench.editor.revealIfOpen` in settings, which routes exactly this scenario (and Go to Definition specifically) through the reveal-in-visible-group path; no code change needed.

  > Thanks for the report. This is actually a supported, opt-in behavior: the `workbench.editor.revealIfOpen` setting does exactly what you're describing — when enabled, if the target file is already open in another visible split group, VS Code reveals that editor instead of opening a duplicate in the currently active group (this applies to Go to Definition as well, since it goes through the same editor-opening path). It defaults to off so the default stays "open in the active group," but turning it on should give you the behavior you want.
