# Issue #350739 — P2 Replace All in a large file freezes the renderer ~2s after the edit: TextMate setTokensAndStates recounts EOLs of all pending changes twice per worker reply

[https://github.com/microsoft/vscode/issues/350739](https://github.com/microsoft/vscode/issues/350739)

## Summary

The redundant full-text scanning remains in current main and directly matches the reported post-edit slowdown. Keep this open for a bounded tokenization performance fix; the supplied reproduction is sufficient.

## Change summary

Large-file Replace All repeatedly scans the same pending replacement text while processing queued TextMate worker replies.

## Best solution

Make pending-change line metadata preparation independent of the number of stale worker replies, preserving token filtering, state mapping, and version acknowledgement semantics. Keep the initial Replace All cost and bracket-pair rebuilding outside this fix.
