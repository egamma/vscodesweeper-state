# Issue #315978 — Sessions: Allow to see Changes and Files in one view, stacked

[https://github.com/microsoft/vscode/issues/315978](https://github.com/microsoft/vscode/issues/315978)

## Summary

Keep open: current Agents Window details still select either Changes or Files, rather than showing both stacked. This team-authored Backlog request remains a real layout gap; no qualifying fix or canonical duplicate was established.

## Change summary

Allow the Changes list and workspace Files explorer to be visible simultaneously, stacked in one Agents Window view.

## Best solution

Provide a supported stacked composition of Changes and Files within the Sessions-owned details surface, preserving session-aware content and existing file/diff navigation. Agree with the maintainer how users select that composition and whether it changes the default.

  > Users should be able to inspect session Changes and browse workspace Files simultaneously in one vertically stacked details surface, without switching between mutually exclusive views. Acceptance should cover concurrent visibility, session switching, details hide/show, and keyboard access to both sections. The default composition and how users select stacked mode remain to be agreed.
- **Trace:**

  > Changes and Files are registered in separate AuxiliaryBar containers by src/vs/sessions/contrib/changes/browser/changes.contribution.ts and src/vs/sessions/contrib/files/browser/files.contribution.ts; both disable moving their views. DesktopDetailPanelCoordinator in src/vs/sessions/contrib/layout/browser/desktop/desktopDetailPanelCoordinator.ts serializes selection of one container through distinct DetailPanelTarget values. Existing add-tab actions choose Files or Changes rather than combining their lists. src/vs/sessions/LAYOUT.md establishes Sessions ownership of this side-pane composition and a singleton main editor. Preserve provider-neutral session data, existing navigation, and phone behavior; do not broaden this into general editor-group support. The older https://github.com/microsoft/vscode/issues/310853 is related presentation feedback, not a verified duplicate. The remaining uncertainty is the user-facing composition choice, not whether the current source already supplies the requested capability.
- **Open decisions:**
  - Should stacked Changes and Files be an optional composition alongside the existing separate views, or become the default details composition?
  - If optional, should users select stacked composition through a dedicated combined view or through a layout choice on the existing details surface?
