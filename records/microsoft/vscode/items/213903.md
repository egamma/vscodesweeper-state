# Issue #213903 — Improve VSCode SecretStorage documentation to highlight capablities and limitations

[https://github.com/microsoft/vscode/issues/213903](https://github.com/microsoft/vscode/issues/213903)

## Summary

Partial documentation improvements have landed (a vscode-docs PR and a small vscode.d.ts wording change), but the core asks — explicit extension-isolation boundaries and the Linux unencrypted-fallback risk — are still not reflected in the current `SecretStorage` doc comment on main, and the prior review's fix-commit citation was already refuted, so this stays open.

## Change summary

Expand the `SecretStorage` API documentation to explain its real security properties, per-OS differences, and the Linux fallback to weaker/unencrypted storage.

## Best solution

Extend the `SecretStorage` TSDoc in src/vscode-dts/vscode.d.ts (and/or the extension API docs site) to state plainly that secrets are isolated per-extension but not protected from other local processes or malicious extensions reading disk directly, and to flag the Linux libsecret/weak-encryption fallback — building on the engagement already started by @TylerLeonhardt in the thread.
