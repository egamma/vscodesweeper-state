# Issue #306414 — Command Shift P and F1 do not work in vsode.dev

[https://github.com/microsoft/vscode/issues/306414](https://github.com/microsoft/vscode/issues/306414)

## Summary

Still reproduces on main: the preload script's `defaultPrevented` check fires in the Electron isolated world before the page's main-world handlers run, so vscode.dev's `preventDefault()` is never seen. The attempted fix PR was closed without merging; no subsequent commit addresses this race.

## Change summary

Cmd+Shift+P and F1 in the integrated browser open the host VS Code command palette instead of vscode.dev's own palette, because the preload key-forwarding fires before the page can call preventDefault().

## Best solution

Defer the `defaultPrevented` check in `src/vs/platform/browserView/electron-browser/preload-browserView.ts` to a microtask (as the closed PR #307471 proposed) so the page's main-world handlers have a chance to call `preventDefault()` before the event is forwarded to the host workbench. The fix is small and localized to the preload script's keydown listener.

  > In `src/vs/platform/browserView/electron-browser/preload-browserView.ts`, the keydown listener (around line 50) checks `event.defaultPrevented` synchronously at line 55. Because the preload runs in Electron's isolated world (worldId 999), this check fires before the page's main-world handlers, so `defaultPrevented` is always `false` even when the page (e.g. vscode.dev) would call `preventDefault()`. Fix: capture a snapshot of the event properties (key, keyCode, code, ctrlKey, shiftKey, altKey, metaKey, repeat) synchronously, then defer the `defaultPrevented` check and the `ipcRenderer.send('vscode:browserView:keydown', ...)` call into a `queueMicrotask()` callback — a microtask runs after all synchronous handlers across all worlds complete, so `defaultPrevented` will reflect the page's final decision. Also defer `event.preventDefault()` and `event.stopPropagation()` into the microtask (only call them if the event was NOT already defaultPrevented). The closed PR https://github.com/microsoft/vscode/pull/307471 shows this approach. Do not change the filtering logic (modifier checks, native shortcut allow-lists) — only the timing of the defaultPrevented guard and the IPC send. Add a test in a new or existing test file validating that when a page handler calls preventDefault() on a keydown, the event is not forwarded.
