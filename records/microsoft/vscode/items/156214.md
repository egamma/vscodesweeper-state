# Issue #156214 — Git - make staged file editable

[https://github.com/microsoft/vscode/issues/156214](https://github.com/microsoft/vscode/issues/156214)

## Summary

Keep open: staged diffs remain intentionally read-only, and existing Open File actions do not provide the requested transition when typing in that view. This accepted Backlog request already serves as a maintainer-selected canonical for related editing friction.

## Change summary

Provide a clearer way to resume editing from a staged Git diff, potentially offering an explicit or automatic unstage action.

## Best solution

Provide a discoverable transition from reviewing staged content to editing, with explicit semantics for whether the existing index snapshot is preserved or unstaged. Keep staged-content previews truthful rather than silently displaying working-tree edits as staged changes.

## Plan brief

- **Likely files:** `extensions/git/src/repository.ts`, `extensions/git/src/commands.ts`, `extensions/git/src/fileSystemProvider.ts`, `extensions/git/package.json`
- **Validation:** After agreeing on the interaction, manually stage a modified text file, open its staged diff, and attempt to type. Verify the chosen edit transition, inspect git diff and git diff --cached to confirm the agreed index semantics, and repeat with a partially staged file to ensure previously staged and unstaged hunks remain correctly represented. Existing Open File and ordinary working-tree editing must continue to work.
- **Behavior:**

  > A user reviewing a staged file should have a clear way to resume editing without hunting for the file or encountering an unexplained read-only dead end. Existing Open File actions allow working-tree editing, but the request concerns the interaction when editing is attempted in the staged view. Acceptance must distinguish the staged snapshot from working-tree content and verify the agreed behavior for fully and partially staged files.
- **Trace:**

  > ResourceCommandResolver in extensions/git/src/repository.ts selects HEAD and index git URIs for staged diffs, while its working-tree paths select file URIs. GitFileSystemProvider in extensions/git/src/fileSystemProvider.ts registers git resources as read-only. CommandCenter.openFile in extensions/git/src/commands.ts already resolves a git URI to its working-tree path, and extensions/git/package.json registers staged-entry Open File actions and git.openDiffOnClick. Source inspection establishes that editing the actual file does not require unstaging; the unresolved question is which transition the product should offer from the read-only view. Preserve accurate staged previews and ordinary Git index semantics outside the explicitly chosen interaction. A maintainer consolidated https://github.com/microsoft/vscode/issues/169386 into this issue; https://github.com/microsoft/vscode/issues/263110 supplies additional demand but is newer.
- **Open decisions:**
  - When editing is attempted in a staged diff, should the interaction open the working-tree file while preserving staged content, offer an explicit unstage-and-edit action, or support editing the index itself?
  - If automatic unstaging is supported, should it require an explicit opt-in, and should a partially staged file lose all staged hunks or only the affected range?

## Evidence

- **Current staged-diff behavior:** In extensions/git/src/repository.ts, ResourceCommandResolver.getLeftResource uses HEAD for staged modifications, while getRightResource uses toGitUri(resource.resourceUri, '') for staged content. resolveChangeCommand opens those resources with vscode.diff. extensions/git/src/fileSystemProvider.ts:57 registers the git scheme with isReadonly: true; staged views are snapshots, not editable working files.
- **Existing capabilities provide only a workaround:** extensions/git/src/commands.ts:1300-1380 implements git.openFile and git.openFile2, opening the working-tree file without unstaging. extensions/git/package.json:2532-2535 exposes an inline Open File action for staged entries; git.showInlineOpenFileAction defaults to true, and setting git.openDiffOnClick to false makes ResourceCommandResolver.resolveDefaultCommand open the working file.
