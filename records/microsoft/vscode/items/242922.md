# Issue #242922 — Enterprise support for Windows: Enable possibility to set managed settings via Intune (Setting Catalogs & OMA-URI)

[https://github.com/microsoft/vscode/issues/242922](https://github.com/microsoft/vscode/issues/242922)

## Summary

Still a valid open request. While recent work added a GitHubCopilot MDM namespace for Copilot-specific managed settings, the core VS Code policies (AllowedExtensions, UpdateMode) still use the `Software\Policies\Microsoft\VSCode` registry path blocked by Intune for ADMX ingestion. The central ask — native Intune Settings Catalog or OMA-URI support for core VS Code policies — remains unimplemented.

## Change summary

Enable enterprise admins to manage core VS Code policies (AllowedExtensions, UpdateMode, etc.) via Intune Settings Catalog or OMA-URI, since the current ADMX approach is blocked by Intune's prohibited registry path restrictions.

## Best solution

Either move VS Code's core policies to a non-prohibited registry path that Intune allows for ADMX ingestion, or register VS Code policies with the Windows Settings Catalog CSP (similar to what Visual Studio did). This likely requires coordination with the Intune team to allow the `Software\Policies\Microsoft\VSCode` path or provide a CSP-based alternative. The new GitHubCopilot namespace pattern (commit fa3887d085e) could serve as a template for a parallel delivery channel for core policies.
