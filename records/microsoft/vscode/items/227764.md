# Issue #227764 — [html] highlighting does not detect end script tag in string literals

[https://github.com/microsoft/vscode/issues/227764](https://github.com/microsoft/vscode/issues/227764)

## Summary

Keep open: the bundled grammars still allow a JavaScript string to consume an HTML script closing tag, matching the maintainer's diagnosis. The older embedded-grammar issue is related, but its documented examples do not establish the identical string-literal symptom required to close this re-reviewed report as a duplicate.

## Change summary

Recognize HTML script closing tags inside JavaScript string literals so highlighting matches the browser's script boundary.

## Best solution

Provide HTML-aware embedded JavaScript grammar rules that respect script termination inside strings while preserving standalone JavaScript highlighting and TextMate compatibility. Coordinate the grammar work with the upstream HTML bundle and the related embedded-grammar discussion.

## Evidence

- **Reporter trigger:** https://github.com/microsoft/vscode/issues/227764 supplies an HTML document containing </script><svg onload=alert(1111)> inside a double-quoted JavaScript string. The reported mismatch is syntax highlighting continuing the string where the browser terminates the script.
- **Maintainer diagnosis:** https://github.com/microsoft/vscode/issues/227764#issuecomment-2339826089 confirms that the embedded JavaScript grammar does not recognize </script> as a stop token inside strings and identifies HTML-specific JavaScript rules as the possible remedy.
- **Current bundled grammar:** extensions/html/syntaxes/html.tmLanguage.json:1899-1937 defines an outer script-end lookahead, adds script-end handling for JavaScript comments, and then includes source.js without equivalent string handling. extensions/javascript/syntaxes/JavaScript.tmLanguage.json:4686-4707 defines qstring-double with quote/newline termination and escape patterns, but no HTML script terminator. Consequently the reporter's inline closing tag remains inside the nested string rule; this was inspected without executing tokenization.
- **Upstream ownership:** extensions/html/build/update-grammar.mjs imports the HTML grammar from https://github.com/textmate/html.tmbundle, Syntaxes/HTML.plist. Its local patches adjust scope names and derivative tag matching, not embedded string termination.
- **Canonical search:** Verified https://github.com/microsoft/vscode/issues/20488 is open and was created in 2017. Its body reports CSS escaping an embedded style boundary; its discussion covers nested grammar states and inline script boundaries, but does not document this same JavaScript string-literal symptom. It is related rather than a verified duplicate under the stronger re-review rule. An additional open-issue title search for script and string found no other matching report.
- **Compatibility boundary:** https://github.com/microsoft/vscode/issues/20488#issuecomment-281033051 and https://github.com/microsoft/vscode/issues/20488#issuecomment-281061135 explain that nested rules suppress outer end matching under TextMate semantics and favor embedding-aware grammars over changing tokenizer compatibility.
