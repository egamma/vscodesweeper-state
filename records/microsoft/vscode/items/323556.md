# Issue #323556 — confusing sorting order for workspaces

[https://github.com/microsoft/vscode/issues/323556](https://github.com/microsoft/vscode/issues/323556)

## Summary

Keep open for a workspace-ordering UX decision. Current main explains the confusing result—workspace sections default alphabetically, but dragging one creates a profile-persisted manual position with no reset affordance—and this member-authored report has no mechanical fix or duplicate that permits closing it.

## Change summary

Make the Agents Window workspace-section ordering understandable when a manually moved workspace remains above more recently used workspaces.

## Best solution

Preserve intentional drag-and-drop ordering while making that manual state discoverable and providing a clear way to reset workspace sections to their default order; the maintainer should first confirm whether the desired default remains alphabetical or should follow workspace activity.

- **Behavior:**

  > Workspace sections in the Agents Window must have an ordering users can understand after drag-and-drop. A manually moved workspace should either remain visibly user-ordered with an accessible reset-to-default action, or follow the maintainer-selected automatic ordering contract. Resetting must restore that documented default without changing session timestamps, groups, pins, or session membership, and the result must persist across window reloads.
- **Trace:**

  > Workspace grouping is built by groupByWorkspace in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts, which alphabetizes workspace labels. SessionsList then calls ISessionSectionOrderService.resolveOrder, allowing profile-persisted manual positions to override that default; reorderSection records dragged workspaces as promoted. SessionSectionOrderService in src/vs/sessions/services/sessions/browser/sessionSectionOrderService.ts owns the persisted order and currently exposes no reset operation. The persistence itself was required by https://github.com/microsoft/vscode/issues/323084, so do not remove drag ordering or alter provider timestamps. The uncertainty begins at the user-visible default and recovery contract, not at code placement.
- **Open decisions:**
  - Should untouched workspace sections remain alphabetical, sort by their most recently updated session, or follow another automatic order?
  - After a workspace is dragged, should it remain manually positioned until an explicit reset, and how should the UI communicate that state?
  - Should reset restore all workspace/group section ordering or allow resetting only workspace sections while preserving custom-group order?
