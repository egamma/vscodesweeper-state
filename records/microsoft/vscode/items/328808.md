# Issue #328808 — Why are there 3 commands for Dictation in the Editor/Terminal/Chat?

[https://github.com/microsoft/vscode/issues/328808](https://github.com/microsoft/vscode/issues/328808)

## Summary

Keep open: current source still has separate dictation entry points rather than one command targeting the focused surface. A maintainer explicitly supported improving this behavior; neither a covering implementation nor a verified canonical duplicate was found.

## Change summary

Provide one focus-aware Start Dictation command so dictation targets the user's current editor, terminal, or chat input.

## Best solution

Offer a consistent focus-aware dictation entry point across editor, terminal, and chat without unexpectedly inserting text into an unfocused editor. Settle command-palette target selection and compatibility with existing surface-specific commands before implementation.

- **Behavior:**

  > Users should be able to start dictation through one entry point that targets their focused editor, terminal, or chat input. Invoking it from the terminal must not insert text into an unfocused editor at its previous cursor position. Acceptance checks cover all three surfaces, invocation through both a shortcut and the command palette, and the agreed behavior when no supported input is focused. Existing dictation lifecycle behavior remains unchanged except where the maintainer explicitly chooses a different contract.
- **Trace:**

  > EditorDictationStartAction in src/vs/workbench/contrib/codeEditor/browser/dictation/editorDictation.ts remains a separate EditorAction2 command whose shortcut lacks an editor-focus condition. EditorAction2.run in src/vs/editor/browser/editorExtensions.ts falls back from the focused code editor to the active code editor, explaining the reported targeting surprise. registerTerminalVoiceActions in src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoiceActions.ts independently starts TerminalVoiceSession; ToggleChatSpeechToTextAction in src/vs/workbench/contrib/chat/browser/actions/chatSpeechToTextActions.ts independently resolves a chat widget. The legacy StartVoiceChatAction in src/vs/workbench/contrib/chat/electron-browser/actions/voiceChatActions.ts is chat-specific despite using a focused target. The maintainer endorsed improvement at https://github.com/microsoft/vscode/issues/328808#issuecomment-5171234404, but did not settle palette focus semantics or retention of the existing commands. Keep backend selection, transcription, and session takeover behavior outside this command-consolidation scope; https://github.com/microsoft/vscode/issues/328759 separately reports session-transfer failures.
- **Open decisions:**
  - Should the unified command supplement existing surface-specific commands or replace their discoverable entries while preserving their command IDs?
  - When invoked through the command palette, should dictation target the previously focused supported input, and what should happen when that input is unsupported or no longer available?
