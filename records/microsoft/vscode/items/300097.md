# Issue #300097 — Raptor Mini is not usable

[https://github.com/microsoft/vscode/issues/300097](https://github.com/microsoft/vscode/issues/300097)

## Summary

Transient Copilot service-side error: the backend was sending model metadata that advertised `xhigh` reasoning effort for gpt-5-mini, which the model's API endpoint rejected. The supported effort levels are server-driven (model metadata → `reasoning_effort` array), and the client correctly uses whatever the server advertises. This was a backend configuration issue, not a client code defect.

## Change summary

Copilot chat requests to gpt-5-mini failed with HTTP 400 because the `xhigh` reasoning effort value was not supported by that model.

## Best solution

This was a transient service-side configuration mismatch — the Copilot backend advertised reasoning effort levels that the downstream model API rejected. The client code correctly consumes the server-provided `reasoning_effort` array from model metadata and builds the picker from it. If the issue persists on the latest VS Code + Copilot extension, a new issue with current version details would be appropriate.
