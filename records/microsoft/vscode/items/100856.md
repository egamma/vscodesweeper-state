# Issue #100856 — Extension doesn't activate after install

[https://github.com/microsoft/vscode/issues/100856](https://github.com/microsoft/vscode/issues/100856)

## Summary

The requested activation-failure diagnostics remain absent on current main, and this team-authored Backlog item is protected from judgment closes. The existing decision to suppress generic failure notifications does not resolve the narrower request for an accurate Running Extensions state and command error.

## Change summary

Show that an extension failed during activation and avoid reporting its contributed commands only as “not found.”

## Best solution

Preserve the intentional suppression of generic notifications for installed-extension failures, while recording activation failures in extension status and presenting that state in Running Extensions and relevant command errors.

## Evidence

- **current activation handling:** On current main, `AbstractExtensionService._onDidActivateExtensionError` in `src/vs/workbench/services/extensions/common/abstractExtensionService.ts` emits telemetry only; it does not store the error in `ExtensionStatus` or fire an extension-status update.
- **current Running Extensions UI:** `src/vs/workbench/contrib/extensions/browser/abstractRuntimeExtensionsEditor.ts` includes every extension whose activation started, but when `activationTimes` is absent it displays “Activating...” / “Extension is activating...”; `IExtensionsStatus` has no activation-failure field, so a failed activation cannot be represented accurately.
- **current command error:** `CommandService._tryExecuteCommand` in `src/vs/workbench/services/commands/common/commandService.ts` still rejects missing contributed commands with only `command '<id>' not found`, without identifying a preceding extension activation failure.
- **notification precedent:** A maintainer explained in https://github.com/microsoft/vscode/issues/101242#issuecomment-725529173 that suppressing popup notifications for failures from normally installed extensions is intentional, to avoid making VS Code appear broken because an extension misbehaved. That closed report does not address status-view or command-error diagnostics.
