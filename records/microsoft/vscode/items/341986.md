# Issue #341986 — `MCP: Open Remote User Configuration` configures itself in the incorrect location

[https://github.com/microsoft/vscode/issues/341986](https://github.com/microsoft/vscode/issues/341986)

## Summary

Thanks for the detailed report. The inconsistency is real in the source: the migration flow points users at ~/.copilot/mcp-config.json, but the command still opens the VS Code profile mcp.json. No open PR, duplicate, or fix exists, so this stays open for a maintainer decision.

## Change summary

After MCP config migration in a remote window, `MCP: Open Remote User Configuration` still opens the old VS Code mcp.json, with no command for the new Copilot config and no explanation of the two formats.

## Best solution

Add an explicit command or entry for the migrated Copilot MCP config. Make the existing command titles and the migration messaging say which file is the VS Code profile config and which is the Copilot config. Also say whether each file lives on the local machine or the remote.

  > After migration, the user can open the migrated Copilot MCP config directly. The command names and migration messaging distinguish the VS Code profile config from the Copilot config and say whether each is local or remote. The messaging explains when the original format is still needed.
- **Trace:**

  > OpenRemoteUserMcpResourceCommand and OpenUserMcpResourceCommand in mcpCommands.ts always resolve to profile.mcpResource. mcpMigration.ts invokes them after migrating to ~/.copilot/mcp-config.json. Do not change migration semantics or the profile mcp.json format. Uncertainty starts at what the right entry points are.
- **Open decisions:**
  - Add a separate command for the Copilot config, or redirect the existing commands after migration?

## Evidence

- **command:** OpenRemoteUserMcpResourceCommand in src/vs/workbench/contrib/mcp/browser/mcpCommands.ts (~line 1563) returns remoteProfile.mcpResource, the VS Code profile mcp.json. It never considers the Copilot config.
- **migration:** src/vs/workbench/contrib/mcp/browser/mcpMigration.ts (~line 106) picks OpenRemoteUserMcp or OpenUserMcp as the command after migration. The Copilot file's path comes from src/vs/platform/mcp/common/mcpCopilotGlobalConfiguration.ts.
