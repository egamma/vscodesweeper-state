# Issue #304175 — Apply/try action from the customization

[https://github.com/microsoft/vscode/issues/304175](https://github.com/microsoft/vscode/issues/304175)

## Summary

Keep open: current prompt-running actions cover only part of the request, not a direct handoff from editing an agent or instruction to using it in chat. This team-authored request has explicit support in the discussion, and no verified canonical or completed implementation was found.

## Change summary

Provide an action or shortcut to leave the customization editor and use the newly created or edited customization in chat without navigating selectors.

## Best solution

Provide a customization-to-chat handoff in the shared management editor, reusing existing prompt execution and agent selection behavior. First settle what applying an instruction means and whether the handoff prepares chat or immediately submits a request.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts`, `src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagement.contribution.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/runPromptAction.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`
- **Validation:** After agreeing on semantics, create or edit a custom agent in Chat Customizations and invoke the handoff by mouse and keyboard: the management surface closes, chat is focused, and the intended agent is selected without dropdown navigation. Repeat for prompts and instructions under the agreed contract in the editor workbench and Agents Window; verify existing prompt Run behavior and unsent chat input are not changed unintentionally.
- **Behavior:**

  > Users should be able to move directly from creating or editing a customization to using it in chat through an action or shortcut. For a custom agent, the resulting chat should have that agent selected without requiring manual dropdown navigation. The management surface should close and focus should move to chat. Acceptance must also cover prompts and instructions once their activation and submission semantics are agreed, with no unintended loss of unsent input.
- **Trace:**

  > The shared management editor lives in src/vs/workbench/contrib/chat/browser/aiCustomization/aiCustomizationManagementEditor.ts; handleEditorActionButton currently returns to the list or saves an override rather than handing off to chat. aiCustomizationManagement.runPrompt in aiCustomizationManagement.contribution.ts delegates to workbench.action.chat.run.prompt.current and is offered only for prompt items. RunPromptBaseAction.execute in browser/promptSyntax/runPromptAction.ts reveals chat and immediately submits a slash command, while ChatInputPart.setChatMode in browser/widget/input/chatInputPart.ts provides existing mode-selection behavior. These establish reusable capabilities but not complete coverage of https://github.com/microsoft/vscode/issues/304175. Preserve existing prompt execution, customization storage, and harness/session boundaries. The uncertainty is product semantics for non-mode customizations and whether the new handoff prepares or submits chat; https://github.com/microsoft/vscode/issues/264631 is related management work, not a verified duplicate.
- **Open decisions:**
  - For instructions, does Apply explicitly attach the instruction to the destination chat, or rely on its existing automatic applicability without changing scope?
  - Should the handoff prepare and focus chat without sending a request, or execute immediately for prompts while only selecting agents and applying instructions?
  - Should the handoff target the current compatible chat or create a new session when the edited customization belongs to a different harness?
