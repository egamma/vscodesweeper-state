# Issue #137632 — With `md.supportHtml = true` and VS Code Remote SSH, a single img tag on compleition items cannot be loaded

[https://github.com/microsoft/vscode/issues/137632](https://github.com/microsoft/vscode/issues/137632)

## Summary

The bug appears to still exist on current main: when `supportHtml = true` and the extension runs as a workspace extension over Remote SSH, raw `<img src>` tags rely on `massageHref` which attempts `FileAccess.uriToBrowserUri` on the parsed URI, but the URI may not be properly rewritten for the remote→local tunnel because it's not registered in `markdown.uris` (unlike markdown image syntax which is tracked during MarkdownString construction). No fix commit references this issue.

## Change summary

A single `<img>` tag in a completion item's MarkdownString with `supportHtml = true` fails to load when the extension runs as a workspace extension over Remote SSH.

## Best solution

Ensure that raw HTML `<img>` URIs in MarkdownString with `supportHtml = true` go through the same URI rewriting/tunneling as markdown image syntax (`![](...)`) when rendered in a remote context. The fix likely belongs in `src/vs/base/browser/markdownRenderer.ts` in the `rewriteRenderedLinks` function or in how the suggest widget passes `transformUri` options.
