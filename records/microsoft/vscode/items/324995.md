## Summary

Valid team-filed bug: invoking the rubber duck agent (which uses a different model) causes the session's model picker to show the subagent's model instead of the user's original selection. No fix commit references this issue on main.

## Change summary

After using the rubber duck slash command in a session, the model picker incorrectly shows the rubber duck subagent's model instead of the session's original model.

## Best solution

The model persistence logic (chatModelSelectionLogic.ts / chatInputPart.ts) should not record model changes driven by subagent invocations like /rubber-duck as the session's selected model. The shouldPersistModelSelection guard likely needs to account for subagent-driven model switches.
