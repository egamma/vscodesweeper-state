# Issue #338100 — Chat context auto adds env file after unchecking it

[https://github.com/microsoft/vscode/issues/338100](https://github.com/microsoft/vscode/issues/338100)

## Summary

Keep open for human handling: current main conclusively forwards disabled active-editor context in Agent Host sessions, potentially exposing credentials from files such as `.env`. This is security-sensitive because an explicit context opt-out is ignored, so the hard keep-open rule applies.

## Change summary

Deselecting the active `.env` file from chat context does not prevent Agent Host chat from sending that file as context.

## Best solution

Ensure Agent Host active-editor forwarding honors the per-entry disabled state set by the context UI, with a regression test proving that an unchecked active file is absent from the outgoing message attachments while enabled context continues to work.

- **root cause:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:6461-6508 iterates every `implicitContext.values` entry in `_appendActiveEditorAttachments` and converts it into an outgoing attachment without checking `entry.enabled`; only the global `chat.implicitContext.includeActiveEditor` setting is checked.
- **outgoing path:** src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostSessionHandler.ts:6445-6451 always invokes `_appendActiveEditorAttachments` after converting the request variables, so the disabled active file can be reintroduced even when the UI excluded it from submitted variables.
- **test gap:** src/vs/workbench/contrib/chat/test/browser/agentSessions/agentHostChatContribution.test.ts tests the global active-editor setting and enabled implicit context, but does not cover an individual implicit entry whose `enabled` field is false.
- **security sensitivity:** The reported trigger uses a `.env` file and states that credentials appeared in model context after the reporter explicitly deselected the file; this is potential credential exposure and therefore requires human security-sensitive handling.
