# Issue #53554 — Editor/terminal only anti aliasing

[https://github.com/microsoft/vscode/issues/53554](https://github.com/microsoft/vscode/issues/53554)

## Summary

Keep open: current settings still do not let users disable smoothing independently in the editor and terminal while retaining smooth workbench text. The terminal now has a limited macOS grayscale override, but it does not satisfy the bitmap-font request; verified related issues do not own the full remaining scope.

## Change summary

Allow independent font-antialiasing policies for editor text, terminal text, and workbench UI.

## Best solution

Provide independently scoped text-rendering controls where the platform and renderer support them, preserving existing defaults and workbench readability. Establish the supported platforms and renderer behavior with the maintainer before implementation, distinguishing grayscale smoothing from genuinely unsmoothed bitmap text.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/browser/workbench.ts`, `src/vs/workbench/browser/media/style.css`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/browser/gpu/raster/glyphRasterizer.ts`, `src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts`, `src/vs/workbench/contrib/terminal/browser/xterm/terminalFontRendering.ts`, `src/vs/workbench/contrib/terminal/browser/xterm/terminalFontRendering.css`, `src/vs/workbench/contrib/terminal/browser/xterm/xtermTerminal.ts`
- **Validation:** On each supported platform and renderer, use a bitmap-style font at its intended size and compare editor text, terminal text, sidebar, and command palette. Independently changing editor or terminal smoothing must leave the other surfaces unchanged; an unsmoothed mode must visibly disable smoothing rather than substitute grayscale antialiasing. Verify unchanged default rendering and existing terminal image-transparency behavior.
- **Behavior:**

  > Users choosing a bitmap-style editor or terminal font should not have to disable smoothing throughout the workbench to obtain sharp text. Editor and terminal policies should be independently controllable while sidebar and command-palette text retain their existing rendering. Acceptance must distinguish genuinely unsmoothed glyphs from grayscale-smoothed glyphs and verify that defaults remain unchanged. The supported platform and renderer matrix must be explicit.
- **Trace:**

  > Workbench.updateFontAliasing in src/vs/workbench/browser/workbench.ts applies a macOS-only setting to the main workbench container, with global smoothing rules in src/vs/workbench/browser/media/style.css. The existing terminal.integrated.fontRendering setting in src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts offers only inherit and grayscale on macOS; updateTerminalFontRendering is called during attachment and configuration updates in xtermTerminal.ts, and its CSS override is limited to high-DPI displays. The GPU editor GlyphRasterizer chooses its canvas antialiasing policy by operating system and explicitly lacks complete workbench.fontAliasing support. Source inspection establishes the missing independent controls, but does not establish that every renderer can disable antialiasing. Preserve default rendering, terminal image transparency, unrelated typography, and workbench UI behavior. https://github.com/microsoft/vscode/issues/36249 concerns following the global policy, whereas https://github.com/microsoft/vscode/issues/337208 concerns a narrower terminal grayscale capability; neither absorbs this issue. The uncertainty begins at the public control contract and the feasible platform/renderer support matrix.
- **Open decisions:**
  - Should independent editor and terminal policies be exposed as separate settings or as a structured replacement for the workbench-wide setting, and how should existing workbench.fontAliasing values be inherited?
  - Which platforms and editor/terminal renderers should support genuinely disabled antialiasing, and what user-visible behavior should apply where only grayscale or system-default rendering is available?

## Evidence

- **Requested behavior and demand:** https://github.com/microsoft/vscode/issues/53554 explicitly clarifies that Terminus editor and terminal text should use no antialiasing while the command palette and sidebar retain smoothing. Subsequent comments confirm the need on macOS and request independently controlled editor and terminal rendering on Windows; the body has three upvotes.
- **Existing workbench capability:** src/vs/workbench/browser/workbench.contribution.ts:727-739 registers workbench.fontAliasing with default, antialiased, none, and auto, included only on macOS. - **Partial terminal capability:** src/vs/workbench/contrib/terminal/common/terminalConfiguration.ts:183-194 registers terminal.integrated.fontRendering, but its only modes are inherit and grayscale, and it is macOS-only. updateTerminalFontRendering in src/vs/workbench/contrib/terminal/browser/xterm/terminalFontRendering.ts toggles a terminal-specific class and clears the texture atlas; terminalFontRendering.css applies grayscale smoothing only on high-DPI displays.
