# Issue #156630 — Can the inputbox show a red outline for invalid filenames?

[https://github.com/microsoft/vscode/issues/156630](https://github.com/microsoft/vscode/issues/156630)

## Summary

The invalid-filename UX gap remains on current main: the New File quick pick accepts every non-empty value and opens the OS save dialog without validation. This team-authored, accepted polish item must remain open, with the invalid-option interaction settled before implementation.

## Change summary

Validate filenames in the New File quick pick, show error styling and a message for invalid names, and prevent Enter from opening the save dialog.

## Best solution

Apply platform-aware filename validation before the New File quick pick invokes the file command, using the quick input's existing error decoration and message support. Invalid input should remain in the quick pick for correction but must not reach the OS save dialog.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts`, `src/vs/workbench/contrib/files/browser/fileActions.ts`
- **Validation:** Exercise the New File quick pick with a Windows-invalid name such as `foo?.txt`: it must display an error decoration and message, and pressing Enter must not execute workbench.action.files.newFile; a valid name must still open the save dialog.
- **Behavior:**

  > Typing a filename that is invalid for the current platform in New File shows an error outline and explanatory message while leaving the text editable. Pressing Enter while that value is invalid does not open the OS save dialog or create a file. Valid filenames and selection of ordinary file-template entries continue to work unchanged.
- **Trace:**

  > NewFileTemplatesManager.selectNewEntry in src/vs/workbench/contrib/welcomeViews/common/newFile.contribution.ts creates a synthetic file item for every non-empty input value, then onDidAccept hides the picker and executes its command without validation. The command in src/vs/workbench/contrib/files/browser/fileCommands.ts constructs a default URI from that value and immediately opens the save dialog. QuickInput already exposes validationMessage and severity for the requested feedback, while the files contribution already has platform-aware filename validation used by Explorer edits. Keep the boundary to typed filename creation in this quick pick: template selection, Explorer rename/create behavior, and native save-dialog validation must not change. The originating Windows behavior is documented at https://github.com/microsoft/vscode/issues/155731#issuecomment-1198594918.
- **Open decisions:**
  - While typed input is invalid, should the synthetic "Create New File" option remain visible but non-accepting, or be removed from the result list while the validation message is shown?
