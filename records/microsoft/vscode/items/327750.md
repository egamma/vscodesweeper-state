# Issue #327750 — Proposal: add an extension events for symbol rename (onDidRenameSymbol / onWillRenameSymbol)

[https://github.com/microsoft/vscode/issues/327750](https://github.com/microsoft/vscode/issues/327750)

## Summary

Keep open as an extension API feature request: current APIs do not provide reliable observation of symbol renames performed by another provider. The older related request was closed after its reporter found a provider-based workaround, not because a general rename event was implemented.

## Change summary

Expose symbol rename lifecycle events so extensions can keep their stored metadata synchronized with user-initiated renames.

## Best solution

Have the extension API owners assess a symbol-rename notification contract, including event payload and completion semantics around preview and cancellation. Existing rename providers and generic document-change events do not fully cover passive observation.

## Evidence

- **Existing API boundary:** src/vscode-dts/vscode.d.ts defines RenameProvider.provideRenameEdits and prepareRename for producing rename edits, workspace.onDidChangeTextDocument for generic document changes, and onWillRenameFiles/onDidRenameFiles for file operations. Searching the stable and proposed declarations found no onWillRenameSymbol or onDidRenameSymbol event.
- **Provider registration is not passive observation:** src/vs/editor/contrib/rename/browser/rename.ts:103-119 asks rename providers sequentially and returns the first successful result. A separately registered provider is therefore not a reliable observer of renames handled by another provider.
- **Rename execution path:** src/vs/editor/contrib/rename/browser/rename.ts:284-326 computes edits and applies them through IBulkEditService, with optional preview and internal EditSources.rename metadata. This internal operation context does not itself expose the requested extension-facing symbol lifecycle event.
- **Older related request is not a canonical duplicate:** https://github.com/microsoft/vscode/issues/189606 requested a symbol rename event for synchronizing related metadata. It is closed; its reporter concluded that acting as the selected rename provider satisfied their particular use case at https://github.com/microsoft/vscode/issues/189606#issuecomment-1666059065. That workaround does not establish general observation of another provider's renames, and the closed issue cannot be a duplicate target.
- **Demand and canonical search:** The supplied thread has no comments, maintainer commitment, or community upvotes. Searches for symbol rename events, notifications, observers, and the proposed event names did not establish an older open canonical owning this request; age alone does not justify closing it.
