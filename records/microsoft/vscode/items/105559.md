# Issue #105559 — Windows Magnifier not following active menuitem

[https://github.com/microsoft/vscode/issues/105559](https://github.com/microsoft/vscode/issues/105559)

## Summary

Keep open for a Windows accessibility investigation: multiple commenters confirmed that Magnifier fails to follow focused custom menu items, including context-menu items displayed over the panel. Current source still explicitly focuses menu items, but neither a fixing commit nor an older open canonical covering this symptom was established.

## Change summary

Make Windows Magnifier follow keyboard focus through custom dropdown menus and context-menu items rendered outside the editor area.

## Best solution

Restore Magnifier tracking for custom menus without requiring users to switch to native menus. First retest the supplied scenarios on current Windows builds and inspect native accessibility focus events and element bounds to determine whether the remaining defect belongs to VS Code, Electron, or Windows Magnifier.

## Plan brief

- **Likely files:** `src/vs/base/browser/ui/menu/menubar.ts`, `src/vs/base/browser/ui/menu/menu.ts`
- **Validation:** On Windows with Magnifier configured to follow keyboard focus and custom menus enabled, press Alt, navigate menubar headings, open a dropdown, and arrow through its enabled items; Magnifier must follow each focused item. Repeat with an editor context menu positioned over the panel, and compare native menus and browser-hosted VS Code as controls.
- **Behavior:**

  > Windows Magnifier should follow keyboard focus from menubar headings into custom dropdown menu items as the user navigates with arrow keys. The discussion also confirms lost tracking for editor context-menu items displayed over the panel. Acceptance requires both scenarios to keep the focused item visible through Magnifier on current Windows builds, without requiring native menus. Existing keyboard navigation and focus restoration must remain intact.
- **Trace:**

  > MenuBar.showCustomMenu in src/vs/base/browser/ui/menu/menubar.ts positions a dropdown holder beneath the heading, appends it to the heading button, constructs Menu, and focuses the widget. In src/vs/base/browser/ui/menu/menu.ts, Menu uses a menu-role ActionBar and its action view item focus override explicitly focuses the item element, contradicting the reporter's aria-activedescendant hypothesis. https://github.com/microsoft/vscode/issues/105559#issuecomment-767470409 expands the confirmed failure to context-menu items overlapping the panel; the thread also reports browser and ZoomText differences. Source inspection cannot establish how Windows Magnifier receives the native focus event or focused element bounds, so the investigation must begin with a current Windows retest. Preserve native-menu behavior and unrelated editor caret tracking; the closed https://github.com/microsoft/vscode/issues/105558 does not establish resolution of this menu symptom.
