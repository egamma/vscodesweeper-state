# Issue #291700 — Agents control should not just write into storage to change the filter

[https://github.com/microsoft/vscode/issues/291700](https://github.com/microsoft/vscode/issues/291700)

## Summary

The reported ownership violation remains on current main: the title-bar widget still reads and writes AgentSessionsFilter's private storage key directly. Keep this open for the bounded API cleanup suggested in the discussion.

## Change summary

Have the agents title-bar control change session filters through the owning component rather than directly manipulating its persisted state.

## Best solution

Make AgentSessionsFilter own filter-state access and mutation for the title-bar control as well as the existing session surfaces, preserving badge toggling, saved-filter restoration, and synchronization. Assess the isStoringExcludes follow-up against multiple same-window filter instances rather than assuming all remaining storage events are external.
