# Issue #123605 — Applying multiple valid workspace edits and then awaiting after can fail unexpectedly.

[https://github.com/microsoft/vscode/issues/123605](https://github.com/microsoft/vscode/issues/123605)

## Summary

The behavior is still present on main — concurrent applyEdit calls both capture the same document version, and the second fails when the first increments it. The under-discussion label is appropriate: whether to add automatic queuing in the extension host is an unresolved design question with real trade-offs (correctness vs. convenience).

## Change summary

Concurrent vscode.workspace.applyEdit calls (fired without awaiting) fail on the second edit due to version mismatch.

## Best solution

Decide whether ExtHostBulkEdits.applyWorkspaceEdit should queue concurrent edits per-document so that each captures the post-application version. The trade-off (higher application rate vs. risk of stale edits when another source mutates the document) needs a maintainer call. If accepted, the queue would live in src/vs/workbench/api/common/extHostBulkEdits.ts.
