# Issue #120587 — Non-executable notebook code cells

[https://github.com/microsoft/vscode/issues/120587](https://github.com/microsoft/vscode/issues/120587)

## Summary

A real capability gap remains: current notebook cells are still limited to markup or executable code semantics. The unsupported-language workaround prevents execution but does not provide the requested annotation-cell UX.

## Change summary

Support syntax-highlighted notebook cells that are neither executable code cells nor rendered Markdown cells.

## Best solution

Decouple cell presentation and language from executability in the notebook model/API, allowing extensions to create syntax-highlighted annotation cells and optionally contribute renderers. This needs notebook API and UX design rather than a localized fix.

## Evidence

- **language-picker limitation:** src/vs/workbench/contrib/notebook/browser/controller/editActions.ts:465-539 limits choices to the active kernel's supported languages plus Markdown, preserving the limitation described in the report.
- **cell-kind coupling:** src/vs/workbench/contrib/notebook/browser/controller/editActions.ts:596-613 converts non-Markdown markup cells into code cells, so syntax highlighting cannot remain independent of code-cell presentation.
- **partial workaround:** src/vs/workbench/contrib/notebook/browser/services/notebookExecutionServiceImpl.ts:70-77 skips cells whose language is unsupported by the kernel, preventing execution but leaving them represented as code cells.
- **related issue is distinct:** https://github.com/microsoft/vscode/issues/121313 remains open but requests the inverse capability—executing Markdown cells—so it does not absorb this request.
