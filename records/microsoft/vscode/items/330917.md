# Issue #330917 — agent host: stop deleting enablement decisions against a mutable client base

[https://github.com/microsoft/vscode/issues/330917](https://github.com/microsoft/vscode/issues/330917)

## Summary

Team-authored (MEMBER) debt follow-up describing a real, still-present architectural hazard in the enablement overlay model; no fix has landed yet, so this stays open — team-authored items are protected from judgment closes and there's no cited fix commit to justify implemented-on-main.

## Change summary

Stop deleting a persisted host enablement decision whenever it matches the client's mutable global value; persist explicit decisions unconditionally and only clear them on explicit user action.

## Best solution

Rework `_setPersistentDecision`/`_setGlobalEnablement` in src/vs/platform/agentHost/node/agentHostCustomizationEnablementService.ts so persistence never keys off the mutable `_clientGlobalEnablement` base — always store the explicit decision, use the client global purely as the read-time inheritance root, and delete only on explicit clear/reset — with regression coverage around `replaceEnablement` → republish → `applyClientGlobalEnablement`.
