- **Additional evidence to preserve:** https://github.com/microsoft/vscode/issues/328920 reports the Search-tab fast-drag case with a video; raphschru's September 16 comment independently confirms Find and Replace, including selection stopping when the pointer moves above or below the fields.
- **Current source boundary:** src/vs/workbench/contrib/search/browser/searchWidget.ts constructs SearchFindInput with flexibleHeight enabled; src/vs/editor/contrib/find/browser/findWidget.ts similarly constructs ContextScopedFindInput. Both use the shared FindInput/HistoryInputBox path, and src/vs/base/browser/ui/inputbox/inputBox.ts creates a native textarea for flexible-height inputs. This establishes a shared input surface, not a conclusive source-level diagnosis or current-main runtime reproduction.
- **Related but distinct report:** https://github.com/microsoft/vscode/issues/176523 is also open, but describes dragging out of the editor find box transferring the caret into the document. That narrower focus/drop behavior is not the canonical for the selection-freezing symptom; https://github.com/microsoft/vscode/issues/324675 documents the exact reported failure.
