# Issue #274816 — Terminal keeps scrolling up when typing, leaving a mostly blank panel.

[https://github.com/microsoft/vscode/issues/274816](https://github.com/microsoft/vscode/issues/274816)

## Summary

Confirmed bug still present on main: terminal scroll position resets to bottom on keypress after maximizing the panel with Git Bash on Windows. The recently added `reflowCursorLine` option (commit b564a177443, March 2026) addresses a related reflow issue but only when conpty dll is enabled, and does not reference this issue — the reported behavior likely persists for Git Bash users.

## Change summary

After maximizing the terminal panel and scrolling up to view history, any keypress scrolls the viewport back to the cursor, hiding history — even though the cursor is already visible with blank space below.

## Best solution

The xterm.js reflow/scroll-to-cursor logic needs to account for the enlarged viewport after panel maximize. The `reflowCursorLine` enablement (b564a177443) is adjacent but gated on conpty dll and doesn't address the scroll-on-input behavior for Git Bash. The fix likely belongs in the terminal scroll-on-input path or the reflow handling in `terminalInstance.ts`, ensuring scroll-to-cursor doesn't over-scroll when the viewport grew.
