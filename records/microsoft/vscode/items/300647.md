# Issue #300647 — Incorrect GitHub repository is targeted when user is attempting to publish branch to a non-writable repository with a name containing period/dot

[https://github.com/microsoft/vscode/issues/300647](https://github.com/microsoft/vscode/issues/300647)

## Summary

The defect remains in current main: the built-in GitHub push-error handler truncates repository names at the first period and uses the truncated name for the fork request. Keep this older report open; the independently confirmed related report is newer and cannot be its duplicate canonical under the re-review rules.

## Change summary

Publishing a branch to a non-writable GitHub repository with periods in its name offers to fork, and can actually fork, a different repository.

## Best solution

The built-in GitHub permission-denied flow should preserve the complete repository name in its confirmation and fork request, removing only an optional terminal .git transport suffix. Cover HTTPS and SSH remotes without changing ordinary publishing or fork setup behavior.

## Evidence

- **Current source proves the reported defect:** In extensions/github/src/pushErrorHandler.ts, GithubPushErrorHandler.handlePushError extracts the repository with the capture group ([^\/.]+), which stops at the first period. For name/name.github.io, it captures repo=name; handlePermissionDeniedError then interpolates that value into the confirmation and passes it to octokit.repos.createFork({ owner, repo }). An optional .git suffix does not prevent the truncation.
- **Publish Branch reaches this built-in handler:** extensions/git/src/commands.ts:4357–4396 publishes a branch in an existing single-remote repository through repository.pushTo. extensions/git/src/repository.ts:2834–2852 dispatches push failures to registered handlers, and extensions/github/src/extension.ts:106 registers GithubPushErrorHandler. This is code shipped in microsoft/vscode, not evidence of a third-party extension defect.
- **Existing parser preserves dotted names:** extensions/github/src/util.ts:getRepositoryFromUrl already parses HTTPS and git@github.com SSH URLs with a complete repository-name capture and an optional terminal .git suffix. The failing handler instead uses its own period-excluding expression; the existing capability therefore does not currently protect the reporter's flow.
