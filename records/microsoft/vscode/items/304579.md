# Issue #304579 — Rebase from worktree window operates on wrong worktree and wrong branch, causing data loss

[https://github.com/microsoft/vscode/issues/304579](https://github.com/microsoft/vscode/issues/304579)

## Summary

The reported cross-worktree operations and lost edits warrant investigation, but the reflogs do not establish which commands VS Code dispatched or why. Request precise UI steps and Git output before diagnosing a core defect; the related editor-window reports do not cover this symptom.

## Change summary

Rebasing from a worktree window reportedly targets the wrong branch and modifies unrelated worktrees, with loss of uncommitted edits.

## Best solution

Establish the repository selected by each checkout and rebase command, then ensure the built-in Git workflow preserves the intended worktree and its current branch without modifying unrelated worktrees. A disposable reproduction and command logs are needed to identify where that contract breaks.
