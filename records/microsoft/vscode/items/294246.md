Keep this team-authored issue open for maintainer reconciliation: the verified implementation commit does not reference this issue, and the adoption PR that does reference it was closed without merging.

## Change summary

Allow chat session extensions to choose their real session resource URI instead of receiving a core-generated untitled URI.

## Best solution

Retain the agreed newChatSessionItemHandler flow, which returns an extension-created ChatSessionItem before loading the real session content, rather than adding a competing resource override to ChatSession. Have the owner confirm that this satisfies the original request and distinguish any remaining untitled-session cleanup.
