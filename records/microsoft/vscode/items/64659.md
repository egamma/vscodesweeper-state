# Issue #64659 — Support multiple lineComments in a language config to allow "Remove Line Comment" to work more reliably

[https://github.com/microsoft/vscode/issues/64659](https://github.com/microsoft/vscode/issues/64659)

## Summary

The requested capability remains missing: current language configuration and comment commands support only one line-comment marker. With 23 upvotes, multiple language use cases, and a newer duplicate pointing here, this remains a useful canonical request rather than a closure candidate.

## Change summary

Allow languages to declare multiple line-comment markers so Remove Line Comment removes the complete matching marker, including documentation-comment prefixes.

## Best solution

Support multiple recognized line-comment markers across language configuration and editor comment commands while preserving existing single-marker behavior. Before implementation, settle the public configuration shape and whether adding or toggling comments should cycle markers or retain a preferred default.

- **Behavior:**

  > A language can declare more than one recognized line-comment marker. Remove Line Comment removes the complete longest matching configured marker, so uncommenting a triple-slash example does not leave a stray slash. Mixed selections containing different configured markers are handled consistently, while existing single-marker configurations retain their behavior. Add Line Comment and Toggle Line Comment must follow explicitly agreed default or cycling semantics rather than accidentally changing documentation-comment behavior.
- **Trace:**

  > CommentRule in src/vs/editor/common/languages/languageConfiguration.ts and the public comment contract in src/vscode-dts/vscode.d.ts represent one marker only. LanguageConfigurationFileHandler._extractValidCommentRule in src/vs/workbench/contrib/codeEditor/common/languageConfigurationExtensionPoint.ts accepts a string or a single comment object; ResolvedLanguageConfiguration in src/vs/editor/common/languages/languageConfigurationRegistry.ts resolves this to one lineCommentToken. LineCommentCommand._gatherPreflightCommentStrings copies that token and length to selected lines, _analyzeLines checks its prefix, and _createRemoveLineCommentsOperations deletes that length, explaining the leftover slash without running the editor. The existing createTestCommandHelper in src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts provides command-level validation. Preserve single-marker behavior, existing whitespace and noIndent semantics, and block-comment fallback; arbitrary trailing-comment parsing and Specman's outside-code regions are separate capabilities. https://github.com/microsoft/vscode/issues/121371 is a newer closed report pointing to this issue, not a replacement canonical. The remaining uncertainty is the user-visible configuration contract and the author's follow-up suggestion to cycle markers when adding comments.
- **Open decisions:**
  - Should multiple markers be exposed as an array-valued lineComment or as additional markers alongside a primary marker, and how should the existing noIndent object form be represented?
  - Should Add Line Comment and Toggle Line Comment retain a preferred insertion marker or cycle among configured markers as suggested by the author?
