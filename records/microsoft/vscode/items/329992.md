# Issue #329992 — Remote SSH in agents window doesn't seem to be working

[https://github.com/microsoft/vscode/issues/329992](https://github.com/microsoft/vscode/issues/329992)

## Summary

Real, freshly-filed bug from a core maintainer testing the new Agents-window SSH remote flow; traced a plausible concrete root cause in the auth code, so this should be routed to the agent-host/remote area rather than closed.

## Change summary

Connecting to an SSH remote from the Agents window workspace picker fails with "all authentication methods failed" against a password-authenticated host, even though connecting to the same host works fine from a normal editor window.

## Best solution

In src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts, `_buildAuthAttempts()` for `SSHAuthMethod.Agent` (the mode used when resolving a workspace from an SSH config host/picker, see remoteAgentHostActions.ts's `connectFromSSHConfigHost`) only falls back to a `keyboard-interactive` attempt for password-less servers. `makeAuthHandler`/`isMethodAllowedByServer` then filters that attempt out entirely when the server advertises only `password` (common for minimal/dropbear sshd in containers) and not `keyboard-interactive`, so the auth queue empties and ssh2 reports total failure without ever prompting the user. The fix likely needs an interactive `password`-method fallback (prompted via the renderer, similar to the existing `kbiHandler`) alongside `keyboard-interactive` in the Agent-mode attempt list.

## Evidence

- **auth attempt building:** src/vs/platform/agentHost/node/sshRemoteAgentHostService.ts `_buildAuthAttempts()`: for `SSHAuthMethod.Agent` the only password-capable fallback pushed is `{ type: 'keyboard-interactive', username }` — there is no plain `password`-type attempt unless the user explicitly picked the manual 'Password' auth method in `promptForCredentialsAndConnect`.
- **server-side filtering:** Same file, `makeAuthHandler`/`isMethodAllowedByServer`: attempts not present in the server-advertised `methodsLeft` are skipped with a log line 'Skipping ... — server only allows ...'; when a minimal/password-only sshd doesn't advertise `keyboard-interactive`, the queue empties and ssh2 calls back with `false`, surfacing as a total auth failure — matching the reporter's exact symptom.
- **picker flow forces Agent mode:** src/vs/sessions/contrib/providers/remoteAgentHost/browser/remoteAgentHostActions.ts `connectFromSSHConfigHost` (around line 396) always builds `config.authMethod = SSHAuthMethod.Agent` when a username is resolvable from ssh config, never offering the manual password picker that exists in `promptForCredentialsAndConnect`.
