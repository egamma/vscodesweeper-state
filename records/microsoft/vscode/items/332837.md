# Issue #332837 — NES: cold-start flicker before supportsUnifiedCompletions resolves on fetched /models path

[https://github.com/microsoft/vscode/issues/332837](https://github.com/microsoft/vscode/issues/332837)

## Summary

Genuine, well-diagnosed follow-up to PR #332802: on the fetched /models deployment path, supportsUnifiedCompletions resolves asynchronously via onModelListUpdated with no disk cache, so a real ~100ms cold-start window exists before the separate completions provider is excluded. Milestone 1.135.0 is assigned, which is a real scheduling milestone, so this stays open regardless.

## Change summary

Brief cold-start flicker/race where the legacy github.copilot completions provider isn't yet excluded before the async /models fetch resolves supportsUnifiedCompletions.

## Best solution

Add a disk-persisted cache of the last-resolved /models config in ProxyModelsService (extensions/copilot/src/platform/proxyModels/node/proxyModelsService.ts) so warm starts hydrate supportsUnifiedCompletions synchronously, closing the race window described in jointInlineCompletionProvider.ts's observableFromEvent on onModelListUpdated.
