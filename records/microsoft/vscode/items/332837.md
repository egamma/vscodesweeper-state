# Issue #332837 — NES: cold-start flicker before supportsUnifiedCompletions resolves on fetched /models path

[https://github.com/microsoft/vscode/issues/332837](https://github.com/microsoft/vscode/issues/332837)

## Summary

Real, still-open gap: milestone 1.135.0 is assigned, so this stays open regardless of merits, but the underlying report also checks out in the code — `_supportsUnifiedCompletions` is derived from the async `onModelListUpdated` event with no persisted/cached value, exactly the cold-start window described.

## Change summary

Brief cold-start window where the separate github.copilot completions provider isn't yet excluded because supportsUnifiedCompletions resolves asynchronously on the fetched /models path, with no disk cache to hydrate synchronously.

## Best solution

Add a small disk-backed cache to ProxyModelsService (extensions/copilot/src/platform/proxyModels/node/proxyModelsService.ts) so the last-resolved /models config can be hydrated synchronously at startup, closing the excludes window before onModelListUpdated fires; this is real follow-up design/implementation work for the NES team, tracked against 1.135.0.
