# Issue #335677 — Work from Repository: Early pasting into repo picker does not show Clone from URL

[https://github.com/microsoft/vscode/issues/335677](https://github.com/microsoft/vscode/issues/335677)

## Summary

Confirmed via source: the repo picker's initial (unfiltered) repository fetch resolves with a hardcoded empty search value and can overwrite the quick pick's items after a paste-triggered debounced search already added the 'Clone from URL' entry, so a fast paste right after opening (or even after the busy indicator clears) can lose that entry to the slower stale fetch.

## Change summary

Pasting a repository URL immediately after opening the cloud-session repo picker doesn't show a 'Clone from URL' entry.

## Best solution

In openRepositoryCommand (extensions/copilot/src/extension/chatSessions/vscode-node/copilotCloudSessionsProvider.ts, around lines 706-742), guard against the initial repositories fetch overwriting items set by a later value-driven search — e.g. track a request generation/sequence number (or re-check quickPick.value at completion time) and skip applying stale fetch results.

Whichever resolves last wins and overwrites `quickPick.items`, so a stale initial-fetch resolution after the paste can erase the Clone-from-URL item that getRepositoryQuickPickItems (lines 286-302) had added. The fix must not change getRepositoryQuickPickItems's matching logic (already covered by tests in copilotCloudSessionsProvider.spec.ts) — only the ordering/staleness handling around the two `quickPick.items =` assignments. Where the uncertainty starts: whether to guard with a monotonically increasing request id compared at assignment time, or to simply re-derive items using `quickPick.value` at the moment each fetch resolves; and how to add a deterministic timing test given the command closure isn't currently exported and QuickPick isn't mocked in the existing spec file.

## Evidence

- **race condition:** In openRepositoryCommand (copilotCloudSessionsProvider.ts:694-772), the initial `fetchAllRepositoriesFromGitHub()` call (line 710) sets `quickPick.items = getRepositoryQuickPickItems(repos, '', ...)` with a hardcoded empty value once it resolves. If the user pastes a URL while this initial fetch is still in flight, `onDidChangeValue` (line 730) schedules a 300ms-debounced second fetch that correctly includes the 'Clone from URL' item (via getRepositoryQuickPickItems, line 296) — but if the first (unfiltered) fetch resolves afterward, it silently clobbers those items with the stale empty-value list, hiding the Clone entry even after the busy indicator stops.
- **Clone from URL logic:** getRepositoryQuickPickItems (copilotCloudSessionsProvider.ts:286-302) only injects the 'Clone from URL' item when `value` looks like a URL/SSH string; the initial fetch's callback ignores the live `quickPick.value` and always passes `''`, which is the root of the clobber.
