# Issue #152806 — API: allow an extension to change the environment variables

[https://github.com/microsoft/vscode/issues/152806](https://github.com/microsoft/vscode/issues/152806)

## Summary

Keep this API proposal open: current environment-variable collections still do not provide the requested general extension-host environment support. The api-proposal label independently prohibits a cleanup close, and the discussion establishes demand beyond vcpkg while leaving lifecycle and user-consent decisions unresolved.

## Change summary

Provide a supported extension API for applying workspace toolchain environment changes to the extension host, not only integrated terminals.

## Best solution

Revisit a general, workspace-scoped environment API with the API and extension-host owners, resolving startup timing and environment-change UX before implementation. Preserve terminal-only defaults and avoid requiring toolchain extensions to integrate separately with every consuming extension.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostTerminalService.ts`, `src/vs/workbench/api/browser/mainThreadTerminalService.ts`, `src/vs/workbench/contrib/terminal/common/environmentVariableService.ts`, `src/vs/workbench/services/extensions/electron-browser/localProcessExtensionHost.ts`, `src/vs/workbench/services/extensions/common/remoteExtensionHost.ts`
- **Validation:** After agreeing the API contract, use a producer test extension to contribute workspace-specific PATH and CC changes and an independent consumer extension to resolve and launch the contributed tool. Verify initial activation, subsequent changes, reload persistence, removal, isolation between two workspace windows, and unchanged terminal-only defaults; verify remote hosts if included in the agreed scope.
- **Behavior:**

  > An environment-manager extension should be able to make workspace toolchain variables available to other extensions through a supported VS Code contract, without requiring users to launch Code from an activated shell or configure each consumer separately. A consumer extension should resolve the same contributed toolchain as the workspace terminal. Acceptance must cover first activation, later environment changes, persistence and removal, workspace isolation, and the agreed user-visible restart or update behavior.
- **Trace:**

  > EnvironmentVariableCollection in src/vscode-dts/vscode.d.ts currently exposes terminal-oriented persistence and scoping, with no extension-host target. Changes flow through MainThreadTerminalService.$setEnvironmentVariableCollection to EnvironmentVariableService, which restores and persists collections in workspace storage; TerminalProcessManager._resolveEnvironment consumes the merged collection. LocalProcessExtensionHost._start instead constructs its environment from the shell environment and development overrides, without consuming those collections. Remote resolver extensionHostEnv is a separate, specialized mechanism and does not cover ordinary local workspace extensions. https://github.com/microsoft/vscode/issues/152806#issuecomment-1208222057 records lifecycle and UX concerns and the interim opt-in integration approach; https://github.com/microsoft/vscode/pull/153019 closed without merging. Preserve existing terminal-only behavior and environment sanitization; do not assume a reload API or live process.env mutation has been approved. The uncertainty begins at the public contract for first activation, subsequent changes, and which host processes receive them.
- **Open decisions:**
  - Should extension-host environment changes take effect through a user-approved host restart, or through live updates with a notification contract for consuming extensions?
  - On first workspace activation, should dependent extensions wait for environment preparation, or start immediately with an explicitly communicated degraded state until the environment is ready?
  - Should the initial API cover only the workspace extension host, or also local and remote extension hosts when both participate in a workspace?
