# Issue #208227 — Inconsistent padding in tab switcher

[https://github.com/microsoft/vscode/issues/208227](https://github.com/microsoft/vscode/issues/208227)

## Summary

The padding inconsistency still traces through on current main: the tab switcher uses the quick-input widget's hidden-input mode, and the bottom padding stacks from two separate rules (container + inner list) while the top only gets a small margin, so the bottom genuinely ends up larger than the top — matching the report. The prior review's cited fix commit was refuted and I found no other fix on main, so this stays open.

## Change summary

In the Ctrl+Tab editor/tab switcher (a hidden-input quick pick), the bottom padding below the last item is noticeably larger than the top padding above the first item, unlike other quick-pick lists (e.g. Quick Open file search) which look evenly padded.

## Best solution

Align the hidden-input quick-pick bottom spacing with the top: either reduce `.quick-input-list .monaco-list`'s `padding-bottom: 7px` for the hidden-input case or drop the extra `.quick-input-widget.hidden-input .quick-input-list { padding-bottom: 4px }` so the two rules don't stack, in src/vs/platform/quickinput/browser/media/quickInput.css.
