[https://github.com/microsoft/vscode/issues/236576](https://github.com/microsoft/vscode/issues/236576)

Keep this consolidation issue open: current source still implements dimming through editor-specific CSS selectors rather than a shared workbench capability. It explicitly tracks further development across multiple editor types, so the umbrella protection also rules out closing it.

## Change summary

Make unfocused dimming a shared workbench capability instead of maintaining CSS overrides for individual editor types.

## Evidence

- **Consolidation and protection:** https://github.com/microsoft/vscode/issues/236576 explicitly consolidates ten earlier reports to track further development of dimming. This is an umbrella issue, which the review policy requires keeping open.
- **Existing capability does not cover the request:** src/vs/workbench/contrib/accessibility/browser/accessibilityConfiguration.ts registers accessibility.dimUnfocused.enabled and accessibility.dimUnfocused.opacity. These already provide opt-in dimming, but the enabled setting explicitly documents exceptions for iframe-based editors; the request concerns robust shared support, not merely adding a dimming toggle.
- **Current implementation:** UnfocusedViewDimmingContribution in src/vs/workbench/contrib/accessibility/browser/unfocusedViewDimmingContribution.ts still constructs separate filter: opacity(...) rules for terminal wrappers, Monaco editors, breadcrumbs, settings, keybindings, placeholders, and welcome editors. Its comment explains that filter placement can affect editor hover behavior; a shared editor capability has not replaced this selector-specific implementation.
- **Original design discussion:** https://github.com/microsoft/vscode/issues/191757 requested built-in editor support instead of external CSS patching and was explicitly merged into this issue. https://github.com/microsoft/vscode/issues/191757#issuecomment-1698796563 suggests an inactive-part overlay; https://github.com/microsoft/vscode/issues/191757#issuecomment-1699036951 records hover-positioning and iframe constraints. These are design leads, not evidence of completion.
- **Recent missing-editor case belongs here:** https://github.com/microsoft/vscode/issues/311894 reports chat editors escaping dimming. The maintainer comment at https://github.com/microsoft/vscode/issues/311894#issuecomment-5080870942 identifies the CSS allowlist gap and closes that report as a duplicate of this canonical tracker, not as fixed.
