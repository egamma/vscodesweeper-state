# Issue #304715 — Opening the following file automatically when staging

[https://github.com/microsoft/vscode/issues/304715](https://github.com/microsoft/vscode/issues/304715)

## Summary

Keep open as a feature request: current staging does not automatically open the next remaining file's diff. The cited focus regression is narrower, and neither closed predecessor provides a verified duplicate target or a decision covering the full request.

## Change summary

After staging an individual file, automatically select and open the next remaining file in the same resource group, falling back to the new last file when staging the bottom entry.

## Best solution

Provide a deliberate sequential-review workflow in the SCM/Git surface, keeping navigation within the original resource group. Decide whether automatic diff opening is opt-in or the default, separately from restoring list focus.

Repeat with automatic navigation disabled if an opt-in mode is chosen, confirming existing behavior remains unchanged.
- **Behavior:**

  > The requested workflow lets a user review and stage files consecutively without clicking the next filename after every stage operation. After staging a file, the next remaining entry in the same resource group is selected and its diff is opened; staging the bottom entry instead opens the new last entry. When the group becomes empty, no staged file or resource from another repository is opened automatically. Acceptance must distinguish automatic diff opening from merely retaining keyboard focus.
- **Trace:**

  > CommandCenter.stage in extensions/git/src/commands.ts ends by calling repository.add and contains no successor-navigation behavior. Resource changes refresh the SCM tree through SCMViewPane.updateChildren in src/vs/workbench/contrib/scm/browser/scmViewPane.ts; SCMViewPane.open separately dispatches resource editor commands. git.openDiffOnClick configures resource clicks, while scm.autoReveal follows active-editor changes into tree selection; neither supplies post-stage navigation. https://github.com/microsoft/vscode/issues/207066 addresses focus preservation and must not be treated as covering automatic editor opening. https://github.com/microsoft/vscode/issues/163164 records earlier demand for the editor-opening behavior but was closed by the community process. Preserve staging correctness, repository/group boundaries, and unrelated bulk or background operations. The remaining uncertainty is the user-visible default and which staging invocation surfaces activate automatic navigation.
- **Open decisions:**
  - Should automatic successor diff opening be the default behavior or an explicitly enabled review mode?
  - Should automatic navigation apply only to the inline '+' action, or also to keyboard and editor staging commands?
