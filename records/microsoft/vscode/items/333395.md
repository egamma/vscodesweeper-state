# Issue #333395 — Copilot memory tool: str_replace with empty old_str causes an infinite loop (100% CPU, unbounded memory growth) until RangeError

## Change summary

Reject an empty `old_str` in the Copilot memory tool's `str_replace` command instead of entering an unbounded occurrence scan.

Review and land https://github.com/microsoft/vscode/pull/333399, which adds an empty-pattern guard and a regression test verifying that the operation fails promptly without modifying the memory file.

## Evidence

- **source-confirmed defect:** On current main, extensions/copilot/src/extension/tools/node/memoryTool.tsx:606-615 repeatedly calls `content.indexOf(params.old_str, searchStart)` and advances `searchStart`, but has no empty-string guard. For an empty pattern, `indexOf` clamps positions beyond the content length to `content.length`, so the loop never reaches its `idx === -1` exit.
- **concrete impact:** The report includes a real Copilot Chat invocation with an empty `old_str`, approximately 21 minutes of stalled execution, 100% CPU usage, unbounded array growth, and eventual `RangeError: Invalid array length`.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/333399 is open, explicitly says `Fixes #333395`, and changes extensions/copilot/src/extension/tools/node/memoryTool.tsx plus its test suite to reject an empty `old_str` and verify that the file remains unchanged.
