# Issue #166161 — Issue with "reopen editor with" -> Jupyter notebook

[https://github.com/microsoft/vscode/issues/166161](https://github.com/microsoft/vscode/issues/166161)

## Summary

Still reproducible on main: when an untitled file is reopened as a Jupyter Notebook, the cell URIs lack the notebook-type query string, so the debugger (and likely other URI-based navigation) cannot resolve the cell back to the correct notebook editor. The untitled fallback discussed in comment 11 was never implemented for this path.

## Change summary

Debugging (Run By Line) in a notebook opened via 'Reopen Editor With' on an untitled file opens a plain text editor instead of the notebook cell, because the cell URI lacks the notebook-type query parameter.

## Best solution

Add an untitled fallback in the notebook service's editor resolution path so that when a `vscode-notebook-cell:` URI arrives without a notebook-type query and the notebook document is already open, the resolver looks up the open notebook model to determine the correct provider. The fix likely touches `notebookServiceImpl.ts` (the `_registerContributionPoint` factory and `getContributedNotebook`) and possibly `CellUri.parse` to handle the missing query gracefully.

- **untitled fallback exists but is scoped to document URIs:** src/vs/workbench/contrib/notebook/browser/services/notebookServiceImpl.ts:406-408 has a fallback for Schemas.untitled in getContributedNotebook, but cell URIs use Schemas.vscodeNotebookCell, which doesn't benefit from this fallback.
