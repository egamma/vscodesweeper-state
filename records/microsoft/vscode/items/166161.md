# Issue #166161 — Issue with "reopen editor with" -> Jupyter notebook

[https://github.com/microsoft/vscode/issues/166161](https://github.com/microsoft/vscode/issues/166161)

## Summary

The accepted notebook bug remains source-reproducible on current main: a cell URI backed by an extensionless untitled resource does not match the provider-specific cell registration, allowing editor resolution to fall back to a text editor.

## Change summary

Debug navigation from an untitled file reopened as a Jupyter notebook opens the stopped cell in a plain text editor instead of revealing its existing notebook editor.

## Best solution

Make notebook editor resolution recognize cells belonging to an already-open untitled notebook and reuse that notebook's view type and editor input, while preserving normal provider selection for saved notebooks.

- **Behavior:**

  > When an extensionless untitled text resource has been reopened as a notebook, navigating to one of its cell URIs must reveal that cell in the existing notebook editor rather than opening a plain text editor. Saved notebooks and untitled resources that have not been opened with a notebook provider must retain their existing resolution behavior.
- **Trace:**

  > NotebookProviderInfoStore._registerContributionPoint in src/vs/workbench/contrib/notebook/browser/services/notebookServiceImpl.ts registers each notebook provider's cell editor against a provider-specific glob. The reported `vscode-notebook-cell:Untitled-1#...` URI parses back to an extensionless untitled notebook, so it misses Jupyter's filename matcher even though `canSupportResource` accepts the cell scheme; the resolver can consequently choose the default text editor. The generic untitled fallback in getContributedNotebook applies only when the incoming URI itself has the `untitled` scheme and therefore does not cover this cell URI. Maintainers established the required behavior in https://github.com/microsoft/vscode/issues/166161#issuecomment-1343123105. Keep the boundary within notebook editor/provider resolution: do not add notebook knowledge to the debugger, rename the untitled resource, or alter saved-notebook matching.
