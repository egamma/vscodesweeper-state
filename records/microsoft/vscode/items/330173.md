# Issue #330173 — Gopls ui sematic tokens makes it very difficult to read (it's still tied to the old default theme

[https://github.com/microsoft/vscode/issues/330173](https://github.com/microsoft/vscode/issues/330173)

## Summary

Traced a real root cause in the theme source: the new 2026 Dark theme only overrides the generic `keyword` TextMate scope, not the more specific `keyword.control` (and similar type scopes) it inherits from dark_plus.json, so semantic-highlighting's default fallback mapping resolves to the old Dark+ purple/teal colors instead of the refreshed palette.

## Change summary

With semantic highlighting enabled under the 2026 Dark theme, Go keywords render in the old Dark+ purple and types in the old teal/green instead of the new theme's red/adjusted palette.

## Best solution

Add explicit `semanticTokenColors` (or more specific TextMate scope) overrides for standard semantic types like `keyword` (which falls back to `keyword.control`) and `type` (falls back to `entity.name.type`/`support.type`) in extensions/theme-defaults/themes/2026-dark.json (and likely 2026-light.json), so semantic highlighting matches the new palette rather than inheriting dark_plus.json's colors through the include chain.
