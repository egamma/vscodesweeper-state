# Issue #330173 — Gopls ui sematic tokens makes it very difficult to read (it's still tied to the old default theme

[https://github.com/microsoft/vscode/issues/330173](https://github.com/microsoft/vscode/issues/330173)

## Summary

Real, well-documented bug: the 2026 Dark theme doesn't define its own `semanticTokenColors`, so semantic highlighting (used by gopls) falls back to scope-derived colors from the included Dark Modern/Dark+ chain instead of the 2026 palette, producing the purple/green colors the reporter sees instead of the new red/etc. Already labeled `2026-themes`, so it just needs theme-owner attention rather than re-routing.

## Change summary

With semantic highlighting enabled and the new 2026 Dark theme active, Go (gopls) keywords/types render in the old Dark+ purple/green palette instead of the theme's intended colors, and colors change noticeably when semantic highlighting is toggled off.

## Best solution

Add explicit `semanticTokenColors` (or complete the `tokenColors` overrides for more specific scopes like `keyword.control`, `entity.name.type`, `storage.type`) to extensions/theme-defaults/themes/2026-dark.json and 2026-light.json so semantic-highlighted tokens resolve to the new palette instead of falling through the `dark_modern.json` -> `dark_plus.json` include chain.

## Evidence

- **theme file:** extensions/theme-defaults/themes/2026-dark.json sets `semanticHighlighting: true` but has no `semanticTokenColors` key, and only overrides a handful of generic TextMate scopes (e.g. `keyword` -> #ff7b72).
- **include chain:** 2026-dark.json includes ./dark_modern.json, which in turn includes ./dark_plus.json — the original Dark+ TextMate rules (with the old purple/green palette) remain in the merged tokenColors set for more specific scopes not re-overridden by 2026-dark.json.
- **no dedicated semantic mapping:** `git grep -n semanticTokenColors` in the theme directory turns up nothing for the 2026 themes, so semantic-highlighted tokens (like gopls's `keyword`/`type` token types) resolve via VS Code's scope-matching fallback against the merged, only-partially-overridden TextMate rules rather than the new palette.
