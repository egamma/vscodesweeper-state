# Issue #332988 — Hooks with matcher field do not filter by tool

[https://github.com/microsoft/vscode/issues/332988](https://github.com/microsoft/vscode/issues/332988)

## Summary

Confirmed on current main: the `matcher` field on Claude-style nested hook entries is parsed and then discarded, with no field anywhere downstream to carry it, so PostToolUse/PreToolUse hooks always fire for every tool regardless of matcher — this is a real, unfixed bug that should be routed to the chat/hooks area.

## Change summary

Hooks defined with a `matcher` (e.g. `{ matcher: 'Read', hooks: [...] }`) fire for every tool call instead of only tools matching the matcher.

## Best solution

Add a `matcher` field to `IParsedHookCommand` (src/vs/platform/agentPlugins/common/pluginParsers.ts) and its editor-layer counterpart `IHookCommand` (hookSchema.ts), preserve it through `extractHookCommands`/`extractHookCommandsFromItem` instead of discarding it, and filter by tool name at hook-invocation time in the extension's hook execution path (extensions/copilot/src/platform/chat/common/hookExecutor.ts and chatHookService.ts) before running PreToolUse/PostToolUse commands.
