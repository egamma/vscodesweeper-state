# Issue #332988 — Hooks with matcher field do not filter by tool

[https://github.com/microsoft/vscode/issues/332988](https://github.com/microsoft/vscode/issues/332988)

## Summary

Traced on main: the `matcher` field is completely discarded during parsing (both the platform and workbench hook parsers), and hook execution never checks tool name against any matcher — so every PostToolUse/PreToolUse hook fires for every tool call, exactly as reported.

## Change summary

Hooks configured with a `matcher` field (e.g. `{ matcher: "Read", hooks: [...] }`) fire for every tool call instead of only matching tools.

## Best solution

Add a `matcher` property to `IParsedHookCommand`/`IHookCommand`, capture it in `extractHookCommands`/`extractHookCommandsFromItem` (src/vs/platform/agentPlugins/common/pluginParsers.ts, src/vs/workbench/contrib/chat/common/promptSyntax/hookSchema.ts), and filter by tool name (matching Claude's glob/exact semantics) in `executeHook` in extensions/copilot/src/extension/chat/vscode-node/chatHookService.ts before invoking commands.
