# Issue #328393 — Title: OTEL telemetry (github-copilot service) stopped emitting session ID and billable-model chat spans since v0.59.0 (VS Code 1.130)

[https://github.com/microsoft/vscode/issues/328393](https://github.com/microsoft/vscode/issues/328393)

## Summary

Detailed, well-evidenced telemetry regression report, but tracing the actual defect requires more from the reporter: VS Code ships two separate OTel pipelines (the extension's own `github.copilot.chat.otel.*` config and the Agent Host's `chat.agentHost.otel.*` native-provider bridge), and it isn't clear which one is in play, so I can't localize the missing session-id/billable-span behavior from source alone.

## Change summary

Since copilot-chat 0.59.0 (VS Code 1.130), OTEL spans emitted under service.name `github-copilot` are missing session-correlation attributes (`copilot_chat.session_id`, `copilot_chat.chat_session_id`, `gen_ai.conversation.id`) and billable-model chat spans no longer appear at all, breaking downstream usage/billing pipelines.

## Best solution

Ask the reporter to confirm which OTel pipeline they use (extension vs. Agent Host) and whether the gap still reproduces on the current copilot-chat build (0.61.0+), then trace the session-id injection path — extensions/copilot/src/extension/chatSessions/copilotcli/node/copilotCliBridgeSpanProcessor.ts only injects `copilot_chat.chat_session_id`/`gen_ai.conversation.id` for traces registered via `registerTrace()` in copilotcliSession.ts, and it's worth confirming that registration still fires for all session/model paths, including billable models.
