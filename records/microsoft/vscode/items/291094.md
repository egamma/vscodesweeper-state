# Issue #291094 — custom agent model - unexpected fallback to Auto when model is unavailable

[https://github.com/microsoft/vscode/issues/291094](https://github.com/microsoft/vscode/issues/291094)

## Summary

Current source still reproduces the reported fallback path: when a custom agent's selected model disappears, model-list reconciliation selects the general default, while the agent's ordered model list is not reevaluated until the mode changes. This member-authored test-plan follow-up should remain open.

## Change summary

When the first model in a custom agent's prioritized model list becomes unavailable, select the next available listed model instead of Auto.

## Best solution

Preserve the active custom agent's ordered model preference across language-model catalog changes, selecting the first currently available entry before falling back to the general default.

- **Behavior:**

  > A custom agent may declare an ordered list of preferred models. If its selected model becomes unavailable while that agent remains active, VS Code selects the first remaining available model from the declared list. Auto or the general default is used only when none of the custom agent's preferred models are available. Explicit user model choices and model selection for other agents remain unchanged.
- **Trace:**

  > The custom mode autorun in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts reads the mode's model list and calls switchModelByQualifiedName, which correctly chooses the first available qualified name. That autorun depends on mode metadata, not the language-model catalog, so removing the selected model does not rerun the ordered lookup. ChatInputModelSelectionController.reconcileModelListChange in src/vs/workbench/contrib/chat/browser/widget/input/chatInputModelSelectionController.ts consequently resets the missing programmatic selection through selectDefault(), producing Auto; changing agents invalidates the mode autorun and then selects the next listed model. Keep the boundary to custom-agent programmatic preferences during catalog changes: do not alter explicit user selections, ordinary remembered selections, or general default-model semantics. The expected behavior is documented by https://github.com/microsoft/vscode/issues/290562.
