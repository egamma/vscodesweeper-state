# Issue #330138 — Agent stops early after creating a session

[https://github.com/microsoft/vscode/issues/330138](https://github.com/microsoft/vscode/issues/330138)

## Summary

Team-authored bug filed hours ago; traced the likely cause in the checkout — the `create_session` tool's confirmation string explicitly instructs the model to reply with only one short sentence, which plausibly overrides the user's own instructions to keep working. No fix exists yet, so this stays open and gets routed to the agent-host area.

## Change summary

After the agent uses the create_session tool, the constrained one-sentence confirmation instruction in the tool result causes the model (gpt-5.6 Sol) to stop early instead of continuing the user's task.

## Best solution

In src/vs/platform/agentHost/node/shared/sessionServerTools.ts, reconsider the wording of the tool-result strings (e.g. `Session created (...). Reply with one short sentence confirming the session was created; do not print the URL or mention a button.`) so models don't interpret the brevity instruction as a signal to stop the overall turn — e.g. explicitly note that the agent should continue with any remaining user-requested work after the confirmation.
