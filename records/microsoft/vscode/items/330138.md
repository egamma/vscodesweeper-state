# Issue #330138 — Agent stops early after creating a session

[https://github.com/microsoft/vscode/issues/330138](https://github.com/microsoft/vscode/issues/330138)

## Summary

Team-authored bug (roblourens, MEMBER) with a real version milestone (1.135.0), so it's protected from closing regardless of judgment; the code path it describes is unfixed and unchanged on main, so it stays open and correctly labeled/routed already.

## Change summary

After the agent host's create_session tool returns its result, some models (e.g. GPT-5.6 Sol) treat the terse confirmation instruction as a signal to stop the turn entirely, even when the user asked for more work afterward.

## Best solution

Revisit the wording/strength of the instruction appended in formatCreateSessionResult (src/vs/platform/agentHost/node/shared/sessionServerTools.ts) — it currently tells the model to reply with 'one short sentence' and not print the URL, which some harnesses over-generalize into 'end the turn.' Likely needs either a clearer boundary in the instruction text or per-provider tuning, validated against the e2e capture in src/vs/platform/agentHost/test/node/e2e/captures/copilotcli-server-tool-create-session-*.yaml.
