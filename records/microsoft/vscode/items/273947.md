# Issue #273947 — Commands picker: putting in an identifier should not show similar commands

[https://github.com/microsoft/vscode/issues/273947](https://github.com/microsoft/vscode/issues/273947)

## Summary

Keep open: current source still combines exact command-ID matches with similarity results, and an open PR explicitly targets this request. Review that implementation against the maintainer's proposed internal search-mode distinction before considering completion.

## Change summary

Suppress similar commands when the Command Palette input exactly matches a command identifier.

## Best solution

Provide focused exact-ID results while preserving normal command-search behavior. Review https://github.com/microsoft/vscode/pull/274405 against the maintainer's guidance on communicating search mode across result sources, and keep this issue open until an accepted implementation lands.

## Evidence

- **Current exact-ID behavior:** In src/vs/platform/quickinput/browser/commandsQuickAccess.ts, AbstractCommandsQuickAccessProvider._getPicks adds an exact identifier match at lines 120–122, but independently evaluates TF-IDF similarity for other commands at lines 125–137. It also requests additional picks without distinguishing exact-ID input. The requested focused-result behavior remains absent.
- **Existing settings do not cover the request:** src/vs/workbench/browser/workbench.contribution.ts registers workbench.commandPalette.experimental.enableNaturalLanguageSearch and workbench.commandPalette.showAskInChat. These control additional natural-language results and the chat action in src/vs/workbench/contrib/quickaccess/browser/commandsQuickAccess.ts; neither conditionally suppresses the base provider's TF-IDF matches when an exact ID is entered.
- **Maintainer direction:** https://github.com/microsoft/vscode/issues/273947#issuecomment-3474414877 explains that multiple result sources currently contribute together and proposes an internal distinction between exact-ID matching and normal search, without a visible mode switch. This is an accepted improvement direction, not grounds for an as-designed decline.
- **Open implementation candidate:** Verified https://github.com/microsoft/vscode/pull/274405 is OPEN and unmerged, with Fixes microsoft/vscode#273947 in its body. It proposes suppressing TF-IDF and additional AI results on exact-ID input. The issue should remain open, and a separate agent implementation must not compete with this candidate.
- **Earlier attempt did not land:** Verified https://github.com/microsoft/vscode/pull/274380 is CLOSED with mergedAt and mergeCommit both null. Its proposed exact-ID similarity suppression is not evidence of a landed fix.
- **Canonical search:** The older open https://github.com/microsoft/vscode/issues/200702 requests floating exact command-label matches above recently used results, rather than suppressing similar results for a pasted identifier. It does not own the same observable symptom required for a duplicate close of this re-reviewed item. https://github.com/microsoft/vscode/issues/257547 concerns JavaScript completion auto-imports, not the Command Palette.
