# Issue #140905 — Multiple line commenting does not work for languages like XML/HTML

[https://github.com/microsoft/vscode/issues/140905](https://github.com/microsoft/vscode/issues/140905)

## Summary

Keep this accepted Backlog request open: current line-comment commands still wrap a multiline HTML selection in one block, rather than commenting each line separately. The request has 25 upvotes; multicursor commenting is a workaround, and the older related issue concerns a different observable problem.

## Change summary

Support commenting each selected XML/HTML line separately with block-comment delimiters through a built-in commenting workflow.

## Best solution

Provide a supported per-line commenting workflow for block-comment-only languages, with one undo operation for the selection. The editor-comments owner should decide whether this changes the existing line-comment commands or is an opt-in behavior or separate command.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/comment/browser/comment.ts`, `src/vs/editor/contrib/comment/browser/lineCommentCommand.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts`
- **Validation:** After choosing the interaction contract, add targeted commenting tests for a block-comment-only language with a multiline selection, checking separate delimiters on each line and the agreed uncomment behavior. Manually verify an HTML/XML selection through the chosen command or setting, confirming one Undo restores the entire selection and existing default behavior remains as agreed.
- **Behavior:**

  > The requested workflow comments each selected XML/HTML line independently instead of enclosing the entire selection in one block. Today, an ordinary multiline selection does not provide this behavior; separate cursors can approximate it. Acceptance should cover a three-line selection producing three comment pairs, the agreed toggle/removal behavior, and one Undo restoring the original text. Existing commenting behavior for languages with line-comment tokens must remain unchanged.
- **Trace:**

  > CommentLineAction.run in src/vs/editor/contrib/comment/browser/comment.ts creates a LineCommentCommand for each selection and brackets the batch with undo stops. LineCommentCommand.getEditOperations in src/vs/editor/contrib/comment/browser/lineCommentCommand.ts falls back to _executeBlockComment when the language lacks a line-comment token; that fallback wraps a nonempty multiline selection in one range. extensions/html/language-configuration.json provides only block-comment delimiters, and EditorComments in src/vs/editor/common/config/editorOptions.ts has no per-line fallback option. Existing fallback coverage lives in src/vs/editor/contrib/comment/test/browser/lineCommentCommand.test.ts. Preserve true line-comment behavior and avoid expanding this request into semantic handling of nested comments, which is separately discussed at https://github.com/microsoft/vscode/issues/133843. The unresolved boundary is the user-facing interaction contract, not the location of a guard or helper.
- **Open decisions:**
  - Should per-line block comments replace the existing line-comment fallback by default, or be exposed through an opt-in setting or separate command while retaining the current default?
