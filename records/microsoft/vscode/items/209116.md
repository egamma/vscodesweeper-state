# Issue #209116 — Problems tab errors claim background preLaunchTask has errors

[https://github.com/microsoft/vscode/issues/209116](https://github.com/microsoft/vscode/issues/209116)

## Summary

The report has a detailed cross-environment reproduction and maintainer confirmation of the faulty behavior. The bug remains actionable: debug checks all workspace markers after a background pre-launch task because the task service does not expose which markers that task produced.

## Change summary

Background pre-launch tasks are reported as having errors when unrelated files already contribute markers to the Problems view.

## Best solution

Add task-system plumbing that lets the debug pre-launch flow determine whether the specific background task produced error markers, then base the launch warning on that scoped result rather than all markers in the workspace.

- **Behavior:**

  > A background preLaunchTask must be considered erroneous only when that task's own problem matcher produces an error. Existing Problems entries from unrelated files, language services, or extensions must not trigger the preLaunchTask error prompt. A genuine error emitted by the background task must continue to block or prompt according to the existing debug behavior. Acceptance should cover both unrelated pre-existing markers and a task-owned marker.
- **Trace:**

  > The issue's reproduction is confirmed by maintainer discussion: the debug pre-launch path runs the task and queries IMarkerService globally, which conflates unrelated workspace markers with task output. TaskTerminalStatus in src/vs/workbench/contrib/tasks/browser/taskTerminalStatus.ts has a terminalMap associating terminals, tasks, and problem matchers, and problem collectors in src/vs/workbench/contrib/tasks/common/problemCollectors.ts retain matcher markers, but that task-scoped information is not exposed to the debug caller. The relevant consumer is the pre-launch task handling in src/vs/workbench/contrib/debug/browser/debugTaskRunner.ts. Preserve ordinary foreground-task exit-code behavior and the warning for actual errors produced by the selected task. The older open issues https://github.com/microsoft/vscode/issues/6209 and https://github.com/microsoft/vscode/issues/70283 do not report the same user-visible symptom and are not duplicate canonicals under the re-review rule.
- **Open decisions:**
  - Should task-scoped error reporting include only markers emitted during the current run, or all still-present markers owned by that task's configured problem matcher?
