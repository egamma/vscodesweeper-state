# Issue #295575 — Source Control: missing “View as Tree / View as List” toggle in Changes view (no way to switch to tree)

[https://github.com/microsoft/vscode/issues/295575](https://github.com/microsoft/vscode/issues/295575)

## Summary

Tree/list switching is available, but the discussion establishes a remaining discoverability problem: restoring the toolbar toggle requires finding a right-click customization menu and enabling both states separately. Keep this as SCM UX polish rather than a missing-capability bug.

## Change summary

Make switching Source Control Changes between tree and list readily discoverable without knowing the toolbar customization mechanism.

## Best solution

Preserve the existing tree/list behavior and workspace preference while making the switch easier to discover in the Changes view. An SCM UX decision should settle whether to restore a default toolbar toggle or improve discovery of the existing customization.

- **Trace:**

  > SetListViewModeAction and SetTreeViewModeAction in src/vs/workbench/contrib/scm/browser/scmViewPane.ts register View & Sort actions with f1: false. Their navigation variants are separately registered and hidden by default, so users must promote each state independently. WorkbenchToolBar in src/vs/platform/actions/browser/toolbar.ts moves hidden actions to overflow and exposes visibility toggles through a separate contextmenu handler; the final commenter confirms this path works. SCMViewPane.getViewMode restores workspace scm.viewMode ahead of scm.defaultViewMode, which is existing persistence behavior, not evidence that tree switching is broken. The boundary is discoverability and presentation: preserve rendering, saved preferences, and unrelated toolbar customization. https://github.com/microsoft/vscode/issues/295554 documents the same workaround, while https://github.com/microsoft/vscode/issues/309821 is a newer related report.
