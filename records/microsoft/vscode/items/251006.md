# Issue #251006 — Feature Request:  tasks get inputs from nodejs or shell

[https://github.com/microsoft/vscode/issues/251006](https://github.com/microsoft/vscode/issues/251006)

## Summary

Keep this accepted feature request open: current task inputs support static choices or registered VS Code commands, but not directly generating a picker from Node.js or shell output. It has 28 upvotes, is already correctly routed to tasks, and the canonical search found no verified issue covering the same request.

## Change summary

Allow task input choices to be generated dynamically by a Node.js or shell script before the task executes.

## Best solution

Provide a supported task-input workflow that generates fresh choices from a script and substitutes the selected value into the task. Agree on the script-output contract and execution environment before implementing it, while preserving existing static and command inputs.

- **Behavior:**

  > A task can obtain its selectable input choices from a Node.js or shell script rather than a static options array. Choices reflect the script's current output before the task starts, and the selected value replaces the corresponding input variable. Acceptance should cover changing candidates between invocations, selection, cancellation, and script failure. Existing promptString, static pickString, and registered-command inputs retain their behavior.
- **Trace:**

  > The shared inputsSchema in src/vs/workbench/services/configurationResolver/common/configurationResolverSchema.ts and ConfiguredInput in configurationResolver.ts expose only promptString, pickString, and command. BaseConfigurationResolverService.showUserInput constructs pickString entries from the configured array and executes command inputs through ICommandService, accepting a string result rather than a candidate list. Tasks import this schema in jsonSchema_v2.ts and call resolveWithInteraction from terminalTaskSystem.ts. Existing input and cancellation tests live in configurationResolverService.test.ts. The source establishes the missing capability, but not a script-output format or process-execution contract across local and remote workspaces; preserve existing input behavior and avoid unintentionally changing debug inputs that share this resolver. Related https://github.com/microsoft/vscode/issues/68397 concerns structured static values, not candidate generation.
- **Open decisions:**
  - What script-output format defines candidates: newline-delimited values or structured entries with separate display labels and substituted values?
  - Where should an input-generating script execute in a remote workspace, and what working directory and environment should it inherit?
