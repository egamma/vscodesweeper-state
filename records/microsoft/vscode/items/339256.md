# Issue #339256 — Git: Stash messages appear garbled when i18n.logOutputEncoding is set

[https://github.com/microsoft/vscode/issues/339256](https://github.com/microsoft/vscode/issues/339256)

## Summary

Confirmed on current main: `getStashes()` in extensions/git/src/git.ts is the one remaining caller of `exec()` for log-like output that doesn't pass `-c i18n.logOutputEncoding=UTF-8`, unlike the sibling `log`, `blame`, and `show` calls that were already fixed for the same class of bug (issue #331086 / PR #331087). Stays open for a small, well-scoped fix.

## Change summary

Stash messages are garbled (Mojibake) in the Source Control Stashes view when a repository sets `i18n.logOutputEncoding`/`i18n.commitEncoding` to a non-UTF-8 encoding, because `getStashes()` doesn't force UTF-8 output like the other git log-reading code paths do.

## Best solution

Add `-c i18n.logOutputEncoding=UTF-8` to the `git stash list` invocation in `Repository.getStashes()` (extensions/git/src/git.ts), mirroring the pattern already used for `log`, `blame`, and `show` in the same file.

- **Trace:**

  > `Repository.getStashes()` in extensions/git/src/git.ts (around line 3074) runs `this.exec(['stash', 'list', '--format=' + STASH_FORMAT, '-z'])` without forcing Git's output encoding. `exec()` always decodes stdout as UTF-8 (`bufferResult.stdout.toString('utf8')`), so when Git itself writes the stash message in a different encoding (per `i18n.logOutputEncoding`), the bytes are misinterpreted. The same class of bug was already fixed for `log`, `logFile`, `blame2`, `getCommit`, and `showChanges` by prepending `-c i18n.logOutputEncoding=UTF-8` (see lines 1461, 1528, 2671, 3362, 3372, 3385) — follow-up to https://github.com/microsoft/vscode/issues/331086 and https://github.com/microsoft/vscode/pull/331087, which this issue reports missed `getStashes`. Boundary: only the `stash list` exec invocation needs the flag added; do not touch `parseGitStashes` or other exec call sites.
