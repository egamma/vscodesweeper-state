# Issue #97780 — Tab key when indenting with spaces does not insert correct number of spaces

[https://github.com/microsoft/vscode/issues/97780](https://github.com/microsoft/vscode/issues/97780)

## Summary

This is a real feature request for Tab key behavior when the cursor is in leading whitespace on a non-empty line. The current behavior (insert spaces to the next tab stop from cursor position) is by design; the request is for a different behavior where pressing Tab anywhere in leading indentation increases the whole line's indentation to the next level. Already correctly labeled as feature-request; stays open in backlog.

## Change summary

When the cursor is inside leading whitespace on a non-empty line, pressing Tab should increase the line's indentation to the next full tab stop rather than inserting spaces from the cursor column.

## Best solution

Modify `TabOperation.getCommands` in `src/vs/editor/common/cursor/cursorTypeEditOperations.ts` to detect when the cursor is within leading whitespace of a non-empty line and, in that case, increase the line's overall indentation to the next tab stop level (like Xcode/TextMate). This could be gated behind a new setting or an extension of `editor.useTabStops` behavior. The change is localized to the tab-handling code path around line 781–792.

## Evidence

- **code path:** TabOperation.getCommands in src/vs/editor/common/cursor/cursorTypeEditOperations.ts lines 775–812: when cursor is on a non-empty line with an empty selection, it calls _replaceJumpToNextIndent which inserts spaces from cursor column to next tab stop — this is the behavior the reporter finds incorrect.
- **_replaceJumpToNextIndent:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts line 856–870: computes `spacesCnt = indentSize - (visibleColumnFromColumn % indentSize)` — purely column-based, no awareness of whether cursor is in leading whitespace.
- **related closed issue:** https://github.com/microsoft/vscode/issues/80129 was the original filing, closed as *caused-by-extension. This issue (#97780) re-filed it confirming it reproduces with extensions disabled.
- **related feature:** https://github.com/microsoft/vscode/issues/2798 ('Navigate Soft Tabs As If They Are Hard Tabs') was implemented for cursor navigation but did not change Tab insertion behavior in leading whitespace.
