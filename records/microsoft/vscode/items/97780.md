# Issue #97780 — Tab key when indenting with spaces does not insert correct number of spaces

[https://github.com/microsoft/vscode/issues/97780](https://github.com/microsoft/vscode/issues/97780)

## Summary

A real editor-behavior gap remains on current main: Tab calculates insertion from the cursor column even when the cursor is inside leading indentation. The request is already classified in the Backlog and is not fully covered by the newer sticky-tab-stop option.

## Change summary

When Tab is pressed anywhere inside leading space indentation, advance the whole line to the next indentation stop and place the cursor at the end of that indentation.

## Best solution

Define consistent line-level Tab behavior inside leading indentation, including cursor placement and mixed-whitespace cases, while preserving ordinary Tab insertion after the first non-whitespace character.

## Plan brief

- **Likely files:** `src/vs/editor/common/cursor/cursorTypeEditOperations.ts`, `src/vs/editor/test/browser/controller/cursor.test.ts`
- **Validation:** Add and run a targeted cursor unit test covering Tab at every interior column of a four-space leading indent, asserting eight resulting spaces and a cursor at the indentation end; retain coverage for Tab after non-whitespace and with editor.stickyTabStops enabled and disabled.
- **Behavior:**

  > On a line beginning with one or more complete indentation levels, pressing Tab while the cursor is anywhere inside that leading whitespace should advance the line to the next full indentation stop and leave the cursor at the end of the resulting indentation. Tab after the first non-whitespace character must retain ordinary insertion behavior. Acceptance should cover every interior cursor column, mixed tabs and spaces, and multiple cursors.
- **Trace:**

  > TabOperation.getCommands in src/vs/editor/common/cursor/cursorTypeEditOperations.ts routes an empty selection to _replaceJumpToNextIndent, which derives spaces from the cursor's visible column and inserts them at that position without considering the line's complete leading indentation. This directly produces the reported seven-space result. editor.stickyTabStops, implemented through mouse snapping in src/vs/editor/browser/controller/mouseTarget.ts, partially avoids interior cursor positions but is disabled by default and does not guarantee that the cursor ends after all indentation. Existing general Tab tests live in src/vs/editor/test/browser/controller/cursor.test.ts. The boundary is leading-whitespace indentation behavior; Tab insertion in line content and language-specific auto-indentation must not change.
- **Open decisions:**
  - Should line-level indentation apply whenever the cursor is inside leading whitespace, only when editor.useTabStops is enabled, or only under editor.stickyTabStops?
  - For mixed tabs and spaces or multiple cursors, should every affected line advance independently to its next indent stop while each cursor moves to that line's indentation end?

## Evidence

- **current source behavior:** src/vs/editor/common/cursor/cursorTypeEditOperations.ts:868-881 implements TabOperation._replaceJumpToNextIndent by calculating spaces solely from the cursor's visible column and inserting them at the selection. On a four-space-indented line with the cursor at column 2, this inserts three spaces and leaves seven, matching the report.
- **partial existing capability:** The editor.stickyTabStops setting is registered as false by default in src/vs/editor/common/config/editorOptions.ts:6189-6192. src/vs/editor/browser/controller/mouseTarget.ts:548-555 snaps mouse positions to the nearest soft-tab boundary when enabled, but it does not guarantee the requested cursor-at-end behavior when a click snaps to the beginning of existing indentation.
- **related implementation:** https://github.com/microsoft/vscode/pull/107126 added the sticky-tab-stop capability in merge commit fb80c0e44af034df58e329e0f946a9a722ab297c and closed https://github.com/microsoft/vscode/issues/2798, which focused on atomic navigation and selection rather than this Tab insertion behavior.
- **distinct related request:** https://github.com/microsoft/vscode/issues/228286 is open but asks for fixed-width indentation when editor.useTabStops is disabled. It does not own this issue's requested behavior when tab stops are enabled and the cursor is inside existing indentation.
