# Issue #53454 — [json] don't suggest top level snippet if there's already an object

[https://github.com/microsoft/vscode/issues/53454](https://github.com/microsoft/vscode/issues/53454)

## Summary

The request remains valid on current main: both user-snippet schemas still unconditionally contribute a whole-document “Empty snippet” completion. The Backlog milestone and maintainer agreement support keeping it open, but completion filtering requires design and dependency-level investigation.

## Change summary

Avoid offering a whole-document snippet template when a user-snippets JSON file already contains a root object.

## Best solution

Reserve the whole-document “Empty snippet” proposal for an actually empty document and provide only context-appropriate property completions inside an existing snippet object, without changing ordinary JSON schema completions.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts`, `extensions/json-language-features/server/src/jsonServer.ts`
- **Validation:** Add or extend JSON language-service completion coverage to assert that the whole-document “Empty snippet” is offered for an empty snippet document but not when a root object already exists, while valid property completions remain available.
- **Behavior:**

  > In a user-snippets JSON file, the whole-document “Empty snippet” proposal is available only when it can produce a valid top-level document. Once the document already contains a root object, accepting completion must not insert a second top-level object. Existing schema-driven completions inside snippet definitions must remain available.
- **Trace:**

  > The language-specific and global schemas in src/vs/workbench/contrib/snippets/browser/snippets.contribution.ts register the same unconditional whole-object `defaultSnippets` shape. Completion requests flow through extensions/json-language-features/server/src/jsonServer.ts to `vscode-json-languageservice` without VS Code-side filtering. The uncertainty starts at whether the schema vocabulary can express document-state applicability or whether the language service needs a context-aware default-snippet rule. Keep the scope limited to snippet-schema default proposals; ordinary JSON schema completions and snippet expansion behavior outside user-snippets files must not change.

## Evidence
