# Issue #276764 — Support color customization of quickpick description

[https://github.com/microsoft/vscode/issues/276764](https://github.com/microsoft/vscode/issues/276764)

## Summary

Keep open: current quick-pick styling does not provide independent description-color customization, and maintainers have actively discussed improving label/description separation. The remaining decision is whether to deliver theme customization, a uniform spacing improvement, or both.

## Change summary

Allow theme authors to distinguish quick-pick descriptions from primary labels more clearly, especially in Light Modern.

## Best solution

Agree on a quick-pick treatment that makes secondary descriptions clearly distinguishable without sacrificing contrast or introducing visual noise. Resolve whether increased spacing satisfies the request or whether independent theme-color customization is also required, keeping the treatment scoped to quick picks.

- **Behavior:**

  > Quick-pick descriptions should read as secondary information with a clear boundary from the primary label, including in Light Modern. The request specifically asks for independent theme-color customization, while the discussion also considers a uniform spacing treatment. Acceptance must cover default, hover, and focused rows in light, dark, and high-contrast themes, preserve readable contrast, and retain usable truncation for long labels and descriptions. If customization is selected, a theme author must be able to change description color without changing the primary label.
- **Trace:**

  > QuickInputList in src/vs/platform/quickinput/browser/quickInputList.ts renders ordinary item labels and descriptions through IconLabel.setLabel. Shared styling in src/vs/base/browser/ui/iconLabel/iconlabel.css supplies the description margin, smaller type, and light-theme opacity of 0.95; current quick-input CSS does not replace this with independent description coloring. src/vs/platform/theme/common/colors/quickpickColors.ts exposes overall and focused foreground colors, while QuickInputController.updateStyles applies descriptionForeground only to separator items. The contrast history at https://github.com/microsoft/vscode/issues/88752 explains why reducing opacity alone is not a safe resolution. The latest discussion at https://github.com/microsoft/vscode/issues/276764#issuecomment-3578166235 suggests spacing, but does not settle whether it replaces the customization request. - **Open decisions:**
  - Should this deliver independent description-color customization, a uniform spacing improvement instead, or both?
  - If description color becomes customizable, should ordinary descriptions reuse descriptionForeground or expose a quick-pick-specific color, and should focused rows retain their existing foreground override?
