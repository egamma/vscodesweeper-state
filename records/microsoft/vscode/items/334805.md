# Issue #334805 — Tool call's `explanation` is misleading due to truncated arguments

[https://github.com/microsoft/vscode/issues/334805](https://github.com/microsoft/vscode/issues/334805)

## Summary

Confirmed in source: the tool-risk-assessment prompt truncates the serialized JSON arguments with a flat byte-count slice, so relevant fields (e.g. an `issue_number` appearing late in the object) can be cut off, causing the mini-model's `explanation` to reference the wrong target — exactly what the reporter observed and logged.

## Change summary

When a tool call's arguments are large, the risk-assessment prompt's naive JSON truncation drops or shifts key fields, so the generated confirmation `explanation` can misdescribe which resource the tool call actually targets.

## Best solution

In `serializeParameters()` (src/vs/workbench/contrib/chat/browser/tools/chatToolRiskAssessmentService.ts), avoid blindly slicing the full JSON string — either truncate individual long string field values while preserving all top-level keys, or serialize with short/identifying fields (ids, issue numbers, paths) emitted first so they survive truncation.
