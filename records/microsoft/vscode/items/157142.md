# Issue #157142 — Introduce command palette overlay focus

[https://github.com/microsoft/vscode/issues/157142](https://github.com/microsoft/vscode/issues/157142)

## Summary

Keep this accepted request open: current quick input styling does not provide the requested optional workbench-dimming overlay. A newer design exploration discusses the same visibility problem, but cannot serve as the canonical duplicate for this re-reviewed, older report.

## Change summary

Provide an optional translucent overlay behind the Command Palette and Quick Open to reduce surrounding UI distractions.

## Best solution

Design a theme-aware, opt-in backdrop for Command Palette and Quick Open that improves visual hierarchy without changing keyboard focus or dismissal behavior. Coordinate with https://github.com/microsoft/vscode/issues/237637 to settle whether other quick-input surfaces should participate.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/services/quickinput/browser/quickInputService.ts`, `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/platform/theme/common/colors/quickpickColors.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** Extend the quick-input browser tests to check that an enabled backdrop appears only while an eligible picker is visible and disappears on acceptance, Escape and dismissal. Manually compare Command Palette and Quick Open with the option enabled and disabled in light, dark and high-contrast themes, checking unchanged typing, navigation, focus restoration and workbench.quickOpen.closeOnFocusLost behavior.
- **Behavior:**

  > Users can opt into dimming the surrounding workbench while the Command Palette or Quick Open is visible, so the active picker is the visual center of attention. The picker itself remains readable, and disabling the option preserves the existing presentation. The treatment ends when the picker closes and must not change command execution, file selection, keyboard navigation or existing focus-loss behavior. Acceptance includes theme contrast and consistent cleanup across acceptance, Escape and dismissal.
- **Trace:**

  > QuickInputController in src/vs/platform/quickinput/browser/quickInputController.ts creates, displays and focuses a shared picker widget; its current show path has no surrounding dimming surface. The overlay class in that controller is for anchored input alignment, not a backdrop. The workbench QuickInputService supplies focus-loss configuration, while workbench.contribution.ts registers the existing Command Palette and Quick Open settings. quickInput.css supplies widget elevation and animations, and quickpickColors.ts supplies picker colors; these improve separation without delivering the requested backdrop. Preserve existing focus and dismissal contracts, and do not assume anchored or extension-created pickers should become visually modal. https://github.com/microsoft/vscode/issues/237637 provides relevant maintainer discussion but leaves the treatment and broader scope unsettled.
- **Open decisions:**
  - Should the opt-in backdrop apply only to Command Palette and file Quick Open, or also to other unanchored quick picks and input prompts?
