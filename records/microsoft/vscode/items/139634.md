# Issue #139634 — `code` CLI still opens duplicate VSCode instance in the macOS dock

[https://github.com/microsoft/vscode/issues/139634](https://github.com/microsoft/vscode/issues/139634)

## Summary

Still reproduces on current main: the `code` CLI launches a second Electron process that briefly shows a duplicate dock icon on macOS before the single-instance lock redirects to the running instance. A prior fix attempt (ab8380f0706) was reverted (220c355619d). The issue is valid, has significant community interest (30 upvotes), and remains in the Backlog with `help wanted`.

## Change summary

Running `code <file>` from Terminal on macOS when VS Code is already running causes a duplicate dock icon to appear briefly, slowing perceived startup.

## Best solution

The second Electron process needs to hide its dock icon before it becomes visible — the reverted approach (app.dock.hide/show in `src/vs/code/electron-main/main.ts`) was on the right track but caused regressions. A refined approach could set `LSUIElement` dynamically or use `app.dock.hide()` earlier in the second-instance startup path, before the window server registers the icon. The `help wanted` label is appropriate given the macOS-specific complexity.
