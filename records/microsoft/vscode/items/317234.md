[https://github.com/microsoft/vscode/issues/317234](https://github.com/microsoft/vscode/issues/317234)

Include checks that excluded user edits remain uncommitted and existing checkpoint/diff behavior is preserved.
- **Behavior:**

  > The requested outcome is that eligible Agent Host edit turns leave their changes committed on the working branch without a separate user commit action. Private checkpoint objects alone do not satisfy this requirement. Acceptance should verify working-branch history after an edit turn and ensure clean turns do not create redundant commits. The maintainer must first define enablement, eligible turn outcomes and which changes automation may include.
- **Trace:**

  > CheckpointAndChangesetContribution.onTurnEnd in src/vs/platform/agentHost/node/chatContributions/checkpointAndChangeset/checkpointAndChangesetContribution.ts currently invokes checkpoint capture and changeset refresh. AgentHostCheckpointService._captureTurnCheckpoint writes private checkpoint refs using commit-tree; it does not advance the working branch. AgentHostCommitOperationHandler._invoke provides explicit branch commits, and AgentHostGitService.commitAll stages all repository changes, making pre-existing user edits an important product boundary. The Copilot CLI auto-commit setting is consumed by the extension-host worktree path, not the inspected Agent Host lifecycle. Preserve private checkpoints, turn comparisons and existing explicit commit/PR behavior; do not expand this request into smart commit stacking. Coordinate with https://github.com/microsoft/vscode/issues/313548, which discusses the broader workflow but does not settle Agent Host per-turn semantics.
- **Open decisions:**
  - Should Agent Host per-turn auto-commit be enabled by default or require explicit opt-in?
  - Should automation apply only to isolated worktrees, or also to sessions using an existing workspace checkout?
  - Should only successful turns auto-commit, or should failed and cancelled turns that leave edits also qualify?
  - Should commits include only changes attributable to the turn, or all outstanding changes in the eligible checkout?
