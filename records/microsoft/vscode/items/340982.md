# Issue #340982 — Renderer OOM ("ran out of reservation") while persisting large chat sessions: every write deep-clones every request's `result`

[https://github.com/microsoft/vscode/issues/340982](https://github.com/microsoft/vscode/issues/340982)

## Summary

Thanks for the detailed report. The source confirms the write path extracts (and deep-clones via JSON stringify/parse) every request's value fields on each write; `sealed` only skips diffing, not extraction. The crash relates to prior OOM issues, so it stays open.

## Change summary

Persisting very large chat sessions deep-clones every request's result on each write, causing renderer V8 OOM crashes.

## Best solution

Avoid re-extracting unchanged sealed requests on each write (cache or skip), and reduce persisted duplication/size of result.metadata.toolCallResults, so large sessions degrade gracefully instead of crashing.
