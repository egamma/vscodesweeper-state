# Issue #334161 — Markdown Editor: Allow for comment annotations in VS Code as well as remote tunnel web

[https://github.com/microsoft/vscode/issues/334161](https://github.com/microsoft/vscode/issues/334161)

## Summary

This remains a real capability gap: feedback annotations are loaded only by the desktop Agents Window, while the web Agents Window explicitly substitutes a no-op service, and the standard VS Code workbench does not expose the Sessions-owned contribution. The request is broader than the related hybrid Markdown report and has no verified canonical.

## Change summary

Make Markdown range comments for agent review available in standard VS Code and in the remote-tunnel web experience, including phone use.

## Best solution

Provide a shared, provider-neutral annotation workflow usable from both the standard workbench and the web Agents Window, with an explicit rule for selecting the receiving agent session and a touch-appropriate presentation on phones.

## Plan brief

- **Likely files:** `src/vs/sessions/sessions.web.main.ts`, `src/vs/sessions/sessions.desktop.main.ts`, `src/vs/sessions/contrib/agentFeedback/browser/agentFeedback.contribution.ts`, `src/vs/sessions/contrib/agentFeedback/browser/nullAgentFeedbackService.contribution.ts`, `src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackEditorInputContribution.ts`, `src/vs/sessions/contrib/agentFeedback/browser/agentFeedbackService.ts`
- **Validation:** Add focused browser tests proving the real feedback service and Add Feedback action are available in each approved host, then exercise a tunnel-hosted web client at a phone viewport to add a Markdown range comment and submit it to the selected agent session.
- **Behavior:**

  > A user reviewing Markdown in each approved surface can select a range, add an anchored comment, review the collected comments, and submit them to the intended agent conversation. The workflow must work in standard desktop VS Code and in a tunnel-hosted web client at a phone-sized viewport. Existing desktop Agents Window annotation behavior must remain unchanged.
- **Trace:**

  > The complete feature is registered only from src/vs/sessions/sessions.desktop.main.ts through agentFeedback.contribution.ts. The web entry point instead loads nullAgentFeedbackService.contribution.ts under an explicit TODO, so web actions and persistence are unavailable by construction. AgentFeedbackEditorInputContribution obtains its target through AgentFeedbackService.getFeedbackSessionResource(), while AgentFeedbackService derives scope from ISessionsService and ISessionsManagementService. The standard workbench cannot directly import this Sessions-owned implementation because the documented layer direction permits `vs/sessions` to import `vs/workbench`, not the reverse. The uncertainty starts at the user-visible ownership of comments in a normal workbench window and the intended editor scope. https://github.com/microsoft/vscode/issues/329494 is related to the hybrid Markdown surface but does not cover this request's full desktop-and-web scope.
- **Open decisions:**
  - In standard VS Code, which agent conversation receives a comment when there is no active Agents Window session or several sessions could own the file?
  - Should this capability be limited to Markdown and the Hybrid Markdown editor, or be available in every text editor associated with an agent session?
  - Should comments created in the standard workbench persist with an Agent Host session and synchronize to the web client, or remain local draft context for the next submitted turn?

## Evidence

- **web capability gap:** src/vs/sessions/sessions.web.main.ts contains `TODO: support agent feedback in web` and loads src/vs/sessions/contrib/agentFeedback/browser/nullAgentFeedbackService.contribution.ts, whose service reports no feedback and performs no annotation operations.
- **desktop-only implementation:** src/vs/sessions/sessions.desktop.main.ts loads src/vs/sessions/contrib/agentFeedback/browser/agentFeedback.contribution.ts, which registers the editor input, overlays, attachments, review commands, and the real AgentFeedbackService.
- **ownership boundary:** The implementation is under src/vs/sessions/contrib/agentFeedback and AgentFeedbackService resolves comments through ISessionsService and ISessionsManagementService. src/vs/sessions/README.md states that workbench code cannot import from the higher `vs/sessions` layer, so standard VS Code support requires an ownership/integration design rather than merely enabling the existing contribution.
- **related but narrower issue:** https://github.com/microsoft/vscode/issues/329494 is older and reports the missing Add Comment action in the Hybrid Markdown editor, but it does not cover the remote-tunnel web and phone requirement, so it cannot absorb this broader request under the re-review duplicate rules.
