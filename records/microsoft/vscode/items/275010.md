## Evidence

- **Trace-backed upstream diagnosis:** In https://github.com/microsoft/vscode/issues/275010#issuecomment-3612854954, the maintainer attributes the freeze to an unresponsive Windows toast service blocking an application COM request on the UI thread. The cited Electron mitigation is https://github.com/electron/electron/commit/90e338df507f7dc7ef0cac1a09b62d2c97c95f72; the comment explicitly distinguishes that mitigation from the remaining OS defect. The reporter's keyboard-hook explanation is not established by this diagnosis.
- **Confirmed persistence after mitigation:** https://github.com/microsoft/vscode/issues/275010#issuecomment-3793680676 reports consistent Ask and Agent mode freezes on VS Code 1.108.2 with blocked COM/message-wait threads. https://github.com/microsoft/vscode/issues/275010#issuecomment-3800682667 independently reports the same unfocused-window trigger on VS Code 1.108.2 and Electron 39.2.7. The merged dependency bump https://github.com/microsoft/vscode/pull/283786 is therefore not proof that this reopened report was fixed.
- **OS fix awaits reporter confirmation:** https://github.com/microsoft/vscode/issues/275010#issuecomment-4404869059 identifies KB5086672, Windows builds 26200.8117 and 26100.8117, as containing the OS fix and asks reporters to confirm. The linked Microsoft update page confirms the cumulative update, but the issue has no subsequent confirmation of resolution. This is an upstream resolution lead, not an observed current-main non-reproduction.
- **Current notification path:** src/vs/workbench/contrib/chat/browser/chatWindowNotifier.ts routes input-required and completed-response transitions through _notifyIfNeeded and _notifyIdleIfNeeded to IHostService.showToast. src/vs/workbench/services/host/electron-browser/nativeHostService.ts delegates to nativeHostService.showToast, and src/vs/platform/native/electron-main/nativeHostMainService.ts constructs an Electron Notification and calls toast.show(). This confirms the relevant native-notification boundary, but source inspection cannot establish whether the environment-dependent Windows hang still occurs.
- **Workaround is not resolution:** The reporter confirmed that disabling chat.notifyWindowOnConfirmation helped, while another reporter found that insufficient. In https://github.com/microsoft/vscode/issues/275010#issuecomment-3800960429, the maintainer recommends disabling both chat notification settings and task completion notifications. Suppressing the trigger does not demonstrate that notifications work without freezing.
- **Canonical search:** An open-issue search for notification freezes found https://github.com/microsoft/vscode/issues/312542, created 2026-04-25, describing the same background Windows-notification freeze, and https://github.com/microsoft/vscode/issues/281743, created 2025-12-07, describing KDE freezes. Both are younger than this 2025-11-04 report and cannot be duplicate canonicals under the re-review rule. No older canonical owning this symptom was verified.
