# Issue #102574 — User settings for language configurations

[https://github.com/microsoft/vscode/issues/102574](https://github.com/microsoft/vscode/issues/102574)

## Summary

Keep open: current settings expose only part of language configuration, not the requested cross-language control over pairs, indentation rules, and folding. Maintainers have supported settings-based customization and designated this issue as the canonical for the broader request.

## Change summary

Allow users to override language-contributed autoclosing, surrounding, indentation, and folding configuration through settings rather than editing each language extension.

## Best solution

Provide a coherent user-settings contract for language-configuration overrides, preserving existing language behavior when unset. Decide the precedence and folding-composition semantics before implementation, coordinating the narrower pairing and folding requests without folding this broader issue into either.

## Plan brief

- **Likely files:** `src/vs/editor/common/config/editorConfigurationSchema.ts`, `src/vs/editor/common/languages/languageConfigurationRegistry.ts`, `src/vs/editor/common/languages/supports/characterPair.ts`, `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/indentRangeProvider.ts`
- **Validation:** After agreeing the settings contract, add language-configuration tests showing the same global overrides apply to two differently configured languages, explicit per-language overrides follow the agreed precedence, and unset settings preserve current behavior. Add folding tests for custom markers combined with indentation and, if accepted, language-provider ranges. Use the existing src/vs/editor/test/common/modes/languageConfiguration.test.ts and src/vs/editor/contrib/folding/test/browser/indentRangeProvider.test.ts suites; no tests were executed during this read-only review.
- **Behavior:**

  > Users should be able to establish consistent autoclosing, surrounding, indentation, and folding behavior across languages through settings without modifying installed extensions. Existing strategy switches alone do not satisfy customization of the actual pairs and rules. Acceptance should cover two languages with different contributed configurations, settings updates, and unchanged behavior when overrides are absent. The finished contract must explicitly define precedence and whether indentation folding supplements or replaces language-specific folding.
- **Trace:**

  > LanguageConfigurationService combines registered language configuration with getCustomizedLanguageConfig in src/vs/editor/common/languages/languageConfigurationRegistry.ts; the latter currently supplies only brackets and colorizedBracketPairs. Their schemas are registered in src/vs/editor/common/config/editorConfigurationSchema.ts. CharacterPairSupport retains explicit autoClosingPairs and surroundingPairs, so changing brackets alone cannot deliver the central pairing request. IndentRangeProvider consumes language folding markers and offSide, while FoldingController selects syntax providers or indentation with a fallback rather than offering an explicit additive strategy. Preserve current language defaults and provider behavior when customization is unset. https://github.com/microsoft/vscode/issues/38352 and https://github.com/microsoft/vscode/issues/36002 cover narrower portions; https://github.com/microsoft/vscode/issues/153209 was explicitly consolidated into this issue. The unresolved boundary is the user-visible override contract, not the existence of the missing capability.
- **Open decisions:**
  - Should global language-configuration overrides take precedence over language-specific defaults and settings, or should explicit per-language user settings remain more specific?
  - Should user-supplied pair lists and indentation/folding rules replace the corresponding language definitions or merge with them?
  - Should indentation folding only combine with configurable markers, or also supplement language-provider ranges; if both produce overlapping ranges, which ranges should users see?

## Evidence

- **Maintainer-supported direction:** https://github.com/microsoft/vscode/issues/102574#issuecomment-944347881 proposes allowing language configurations in settings.json. The issue is accepted in Backlog; its age and 14 upvotes do not justify declining it.
- **Existing capability is partial:** src/vs/editor/common/config/editorConfigurationSchema.ts:161-196 registers editor.language.brackets and editor.language.colorizedBracketPairs. src/vs/editor/common/languages/languageConfigurationRegistry.ts:146-164 reads only those two customization keys, not autoClosingPairs, surroundingPairs, indentationRules, or folding.
- **Pair controls do not override pair definitions:** src/vs/editor/common/config/editorOptions.ts:6090-6199 exposes editor.autoClosingBrackets, editor.autoClosingQuotes, editor.autoIndent, and editor.autoSurround as strategy controls. In src/vs/editor/common/languages/supports/characterPair.ts:20-39, explicit language autoClosingPairs take precedence over the brackets fallback, and explicit surroundingPairs take precedence over autoclosing pairs. Consequently, editor.language.brackets does not generally replace language-defined pairing behavior.
- **Folding remains only partially covered:** editor.foldingStrategy supports selecting indentation instead of language-specific providers, but does not define custom folding rules or an additive provider mode. src/vs/editor/contrib/folding/browser/indentRangeProvider.ts:29-33 obtains offSide and markers from the resolved language configuration; src/vs/editor/contrib/folding/browser/folding.ts:280-293 selects indentation or syntax providers with an indentation fallback. The reporter explicitly requested indentation together with open/close tags.
- **Verified related issues are narrower:** https://github.com/microsoft/vscode/issues/38352 is open and predates this issue, but covers configurable autoclosing pairs. https://github.com/microsoft/vscode/issues/36002 is also open and older, but covers configurable folding markers. Both were linked by the maintainer at https://github.com/microsoft/vscode/issues/102574#issuecomment-659237815; neither owns the full combined request.
- **Broader canonical ownership:** https://github.com/microsoft/vscode/issues/153209 requested exposing all language-configuration settings and was closed as a duplicate of this issue by a maintainer at https://github.com/microsoft/vscode/issues/153209#issuecomment-1173766462. Additional searches for language configuration/settings and user-configurable indentation did not establish an older open canonical covering the full scope.
