# Issue #323238 — Option to display relative line numbers for virtual/wrapped lines

[https://github.com/microsoft/vscode/issues/323238](https://github.com/microsoft/vscode/issues/323238)

## Summary

Current main still leaves wrapped continuation lines blank, and no existing setting provides the requested visual-line numbering. The request has 58 upvotes and was explicitly promoted to the Backlog, so it should remain open for an editor-rendering design decision.

## Change summary

Add an opt-in way to display relative line numbers beside soft-wrapped visual lines.

## Best solution

Provide an opt-in editor setting or line-number mode that calculates relative distances over wrapped view lines while preserving the current model-line behavior by default. The design should define how numbering behaves when the cursor itself is on a wrapped continuation and remain separate from folded-line semantics.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts`, `src/vs/editor/common/config/editorOptions.ts`
- **Validation:** Add a focused LineNumbersOverlay browser test with wrapped text that verifies the opt-in mode renders the expected relative number on every visible wrapped segment, updates when the cursor moves between segments, and leaves the existing disabled/default output unchanged.
- **Behavior:**

  > When relative line numbers and the new opt-in behavior are enabled, every visible soft-wrapped segment has a gutter value representing its visual distance from the cursor. Moving the cursor between physical or wrapped lines updates those values consistently. With the option disabled, existing relative, absolute, interval, and custom line-number behavior remains unchanged.
- **Trace:**

  > LineNumbersOverlay._getLineRenderLineNumber in src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts receives a view line but converts it to a model position and returns empty output whenever the mapped column is not 1, so wrapped continuations are deliberately omitted. Its cursor handler receives the primary view position but stores only the converted model position, and relative distance is calculated from model line numbers. EditorRenderLineNumbersOption in src/vs/editor/common/config/editorOptions.ts exposes no wrapped-line mode or companion setting. The boundary should remain within editor view-line rendering and configuration: do not alter folding semantics tracked separately by https://github.com/microsoft/vscode/issues/169749, custom line-number callback semantics, or existing default output.
- **Open decisions:**
  - Should relative distance be measured strictly between view-line indices, including when the cursor is on a wrapped continuation, and what should every segment of the cursor's physical line display?
  - Should this be a boolean companion to editor.lineNumbers: relative or a new editor.lineNumbers mode?
  - Should the first segment retain the physical line number while continuation segments show visual distances, or should all segments use one uniform visual-distance scheme?
