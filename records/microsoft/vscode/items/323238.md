# Issue #323238 — Option to display relative line numbers for virtual/wrapped lines

[https://github.com/microsoft/vscode/issues/323238](https://github.com/microsoft/vscode/issues/323238)

## Summary

This remains a valid, well-supported editor-rendering request: it passed the community threshold with 58 upvotes and was explicitly promoted to the Backlog. The requested per-wrapped-line gutter indicators are not provided by the current physical-line-based relative-number behavior.

## Change summary

Display relative line-number indicators for visual lines created by soft wrapping, enabling precise wrapped-line navigation.

## Best solution

Design native editor support for visual-line-relative gutter indicators in the Monaco view/layout layer, including clear semantics when the cursor itself is on a wrapped continuation line. Preserve the existing `editor.lineNumbers: "relative"` behavior by default and expose the visual-line mode through an explicit option.

## Plan brief

- **Likely files:** `src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts`, `src/vs/editor/common/config/editorOptions.ts`, `src/vs/editor/test/browser/viewParts/lineNumbers/lineNumbers.test.ts`
- **Validation:** Add editor rendering tests for a wrapped model line with relative numbering, covering visual rows above and below the cursor and preserving existing output when the new option is disabled.
- **Behavior:**

  > When the visual-line relative-number mode is enabled, every visible row created by word wrapping has a gutter indicator that reflects its visual distance from the cursor row. The behavior must support keyboard workflows that move by wrapped line, while the existing physical-line relative-number behavior remains unchanged by default. Acceptance should cover a multi-row wrapped line above and below the cursor, a cursor on a wrapped continuation row, and no-wrap behavior.
- **Trace:**

  > The request belongs to the editor rendering pipeline rather than an extension: line-number rendering is handled in src/vs/editor/browser/viewParts/lineNumbers/lineNumbers.ts, while editor option contracts are registered in src/vs/editor/common/config/editorOptions.ts. The existing issue evidence establishes that wrapped continuation rows have no model-line gutter number and that the desired unit is the visual row. The boundary is line-number presentation and its configuration; cursor movement semantics, model line numbering, wrapping layout, and Vim-extension behavior must not change. Uncertainty begins at the public semantics for counting from a cursor positioned within a wrapped model line and how visual numbering should coexist with the physical line's displayed number.
- **Open decisions:**
  - When the cursor is on a wrapped continuation row, should distance zero be anchored to that visual row or to the physical model line's first row?
  - Should the physical line containing the cursor continue to display its absolute model-line number while its continuation rows receive visual relative distances?
  - Should visual-line numbering be a separate boolean option layered onto relative numbering, or a new `editor.lineNumbers` mode with a distinct public configuration value?
