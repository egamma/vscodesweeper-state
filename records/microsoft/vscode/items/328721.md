Verify that unrelated branches and ordinary commit attachments retain their existing behavior.
- **Behavior:**

  > Developers working on a chain of dependent PRs should understand the dependency order and PR status without manually reconstructing the stack. They should be able to invoke supported cascading updates from the editor and provide Copilot with the dependencies relevant to the selected development target. Official stack creation and presentation already exist, so acceptance must distinguish those capabilities from the additional Source Control and AI integration. The plan must settle the intended presentation and context behavior before implementation.
- **Trace:**

  > The discussion links https://github.com/microsoft/vscode-pull-request-github/issues/8887, now completed; its implementation is documented in extension changelog 0.168.0 and exercised by https://github.com/microsoft/vscode-pull-request-github/issues/9011. That repository's src/github/pullRequestStack.ts orders dependent PRs, and src/github/updateStackBranches.ts implements cascading rebases and leased pushes. In this checkout, extensions/git/src/api/git.d.ts exposes the supporting Git operations, while SCM history.ts represents commit ancestry and scmHistoryChatContext.ts supplies selected-commit attachments. These traced core paths do not establish a PR-stack presentation or full stack-aware chat context. Preserve existing stack operations, ordinary Git commands, and commit-attachment behavior; do not build a parallel GitHub stack model. Uncertainty starts at the intended Source Control surface and the context contract between the GitHub integration and Copilot.
- **Open decisions:**
  - Should PR dependencies appear in the existing Source Control Graph, a dedicated Source Control view, or remain in the GitHub Pull Requests surface with navigation from Source Control?
  - Should Copilot receive stack dependencies automatically for the selected PR, only through an explicit attachment, or through an opt-in workflow, and what dependency information should that context contain?
