# Issue #301688 — feat: display agent name in chat list (overview)

[https://github.com/microsoft/vscode/issues/301688](https://github.com/microsoft/vscode/issues/301688)

## Summary

A real presentation gap remains on current main: session rows do not display the selected agent, although the session model carries mode identity. Keep this open for a product decision about agent-name semantics and placement.

## Change summary

Show the agent associated with each conversation in the chat or Sessions overview list.

## Best solution

Give session rows a provider-neutral, human-readable agent label that updates consistently when agent selection changes and is included in the row's accessible presentation. Maintainers should first decide whether this represents the currently selected agent or the agent that handled the latest request.

## Plan brief

- **Likely files:** `src/vs/sessions/services/sessions/common/session.ts`, `src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts`, `src/vs/sessions/contrib/sessions/test/browser/sessionsList.test.ts`, `src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts`
- **Validation:** Extend the Sessions list renderer tests with sessions using default and custom agents, asserting that the human-readable agent label is rendered, updates when the relevant agent state changes, and is represented in the row's accessible label without removing existing workspace, status, or timestamp details.
- **Behavior:**

  > Each conversation row in the chat or Sessions overview identifies the agent associated with it using a human-readable name rather than an internal identifier. The label remains accurate when agent selection changes and is available to screen-reader users. Existing title, workspace, status, change-count, and timestamp presentation remains intact.
- **Trace:**

  > The provider-neutral ISession contract in src/vs/sessions/services/sessions/common/session.ts exposes mode as only an id and kind. The Copilot sessions adapter in src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts propagates that observable, while the row renderer in src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts does not consume it and currently renders only workspace/type, changes, status, and time. The uncertainty begins at resolving a stable display name across providers and deciding which agent a row represents after agent changes within a conversation. Keep the behavior provider-neutral and do not make the shared Sessions list depend directly on a provider implementation.
- **Open decisions:**
  - Should the row show the agent currently selected for the conversation or the agent that handled its most recent request when those differ?
  - Should the default built-in agent be named on every row, or should the additional label appear only for custom or non-default agents?
  - Should the agent name appear persistently in the details row or only in secondary presentation such as the hover and accessible label?

## Evidence

- **current model:** src/vs/sessions/services/sessions/common/session.ts defines ISession.mode as an observable containing only an agent/mode id and kind; it does not provide a provider-neutral display label.
- **current renderer:** src/vs/sessions/contrib/sessions/browser/views/sessionsList.ts renders the title plus workspace/type badge, diff statistics, status description, and timestamp, but never reads element.mode or renders an agent name.
- **provider evidence:** src/vs/sessions/contrib/providers/copilotChatSessions/browser/copilotChatSessionsProvider.ts propagates primaryChat.mode into ISession, confirming that identity data reaches the list model but is not presented.
