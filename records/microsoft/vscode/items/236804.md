# Issue #236804 — SCM Graph - does not detect changes in the cloud when working for a remote source (SSH)

[https://github.com/microsoft/vscode/issues/236804](https://github.com/microsoft/vscode/issues/236804)

## Summary

Request a current reproduction distinguishing graph refresh from fetching remote commits. The reporter confirmed persistence after upgrading to 1.96.2, but the record does not establish whether the SSH checkout had fetched the missing commits.

## Change summary

The SCM Graph in an SSH workspace does not show new remote commits until the reporter synchronizes the repository.

## Best solution

Ensure the graph reflects fetched commits in SSH workspaces without requiring synchronization. First establish whether fetching alone updates the remote-tracking refs and whether the graph still omits those commits afterward; differing autofetch settings between the two workspaces could explain the reported comparison.

The reporter confirmed the same behavior after upgrading from 1.96.0 to 1.96.2, but supplied no fetch-only reproduction or effective autofetch settings.
- **Refresh does not fetch:** In src/vs/workbench/contrib/scm/browser/scmHistoryViewPane.ts, workbench.scm.action.graph.refresh calls SCMHistoryViewPane.refresh(); _refresh() clears graph state and reloads children without initiating a Git fetch. extensions/git/src/historyProvider.ts reads repository refs and history, so graph refresh alone cannot discover commits absent from the checkout.
