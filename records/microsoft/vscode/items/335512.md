# Issue #335512 — diff editor not auto switching to side-by-side layout

[https://github.com/microsoft/vscode/issues/335512](https://github.com/microsoft/vscode/issues/335512)

## Summary

The recording matches the intentional resize behavior introduced by the linked PR: enlarging a diff that starts narrow preserves a temporary inline layout, while a gesture that starts wide can restore side-by-side. The apparent inconsistency follows the gesture's starting state rather than an unconditional width threshold.

## Change summary

Automatically restore side-by-side diff layout whenever an editor becomes sufficiently wide after resizing.

## Best solution

Retain the deliberate-resize behavior and explain its temporary inline state. Selecting Diff View → Automatic with command diffEditor.setViewMode.automatic clears that state and immediately reapplies width-based layout.

- **Proposed comment:**

  > Thanks for the report and recording. This is intentional behavior introduced by https://github.com/microsoft/vscode/pull/334245: dragging wider from a narrow inline diff preserves an “Inline (Temporary)” layout. A resize gesture that starts wide can instead return to side-by-side, which explains the different results.
  > 
  > To restore width-based switching immediately, select Diff View → Automatic (`diffEditor.setViewMode.automatic`). Selecting Side by Side keeps that layout regardless of width.
