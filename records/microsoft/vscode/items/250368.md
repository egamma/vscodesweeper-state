# Issue #250368 — Smart task suggestion depending on user's project setup

[https://github.com/microsoft/vscode/issues/250368](https://github.com/microsoft/vscode/issues/250368)

## Summary

Keep open for a maintainer-led decision on contextual task and terminal discoverability. Existing rerun commands and suggestions address repeated execution, but do not fully cover the proposed contextual guidance; the discussion has not settled which experience to pursue.

## Change summary

Offer unobtrusive, project-aware guidance that helps users turn repeatedly executed commands into reusable tasks or discover equivalent terminal features.

## Best solution

Agree on whether contextual guidance should introduce task creation or existing terminal reuse features, then define eligibility, dismissal, and onboarding behavior. Preserve shell integration and avoid creating shared tasks.json entries without explicit user consent.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminalContrib/history/browser/terminal.history.contribution.ts`, `src/vs/workbench/contrib/terminalContrib/inlineHint/browser/terminal.initialHint.contribution.ts`, `src/vs/workbench/contrib/terminalContrib/suggest/common/terminalSuggestConfiguration.ts`, `src/vs/workbench/contrib/tasks/browser/task.contribution.ts`, `src/vs/workbench/contrib/tasks/browser/abstractTaskService.ts`
- **Validation:** After selecting the experience, exercise repeated execution of a Python command with custom arguments in workspaces with and without tasks.json. Verify eligible guidance appears under the agreed conditions, dismissal prevents repeated interruptions, accepting guidance reaches the intended reusable-command or task flow, and declining never writes tasks.json. Confirm existing Run Recent Command and terminal suggestions remain usable.
- **Behavior:**

  > Users repeatedly executing a command should be able to discover a reusable execution workflow without intrusive recurring prompts. The record leaves open whether that workflow should introduce tasks or existing terminal history and suggestion features. Acceptance must cover the selected eligibility and dismissal rules, commands containing custom arguments, and explicit consent before creating workspace task configuration.
- **Trace:**

  > TerminalHistoryContribution in src/vs/workbench/contrib/terminalContrib/history/browser/terminal.history.contribution.ts receives command-finished events and records nonempty commands, while its runRecent method opens the existing reuse picker. TerminalInitialHintContribution in src/vs/workbench/contrib/terminalContrib/inlineHint/browser/terminal.initialHint.contribution.ts provides startup guidance but excludes terminals that already have recorded commands. Task commands and provider auto-detection settings are registered in src/vs/workbench/contrib/tasks/browser/task.contribution.ts; task configuration creation is handled in abstractTaskService.ts. These surfaces establish available building blocks, not a completed repeated-command onboarding flow. Preserve existing command execution, shell integration, and user control over shared task configuration. Related work at https://github.com/microsoft/vscode/issues/239244 and https://github.com/microsoft/vscode/issues/252001 addresses history suggestions and existing-task execution respectively, not this full goal. The uncertainty starts at the user-facing choice between task creation and terminal reuse, before implementation design.
- **Open decisions:**
  - Should this experience introduce task creation, guide users toward terminal history and suggestions, or offer both with distinct eligibility?
  - Should guidance be limited to workspaces without tasks.json, and what repeated-command or project conditions should qualify?
  - Should guidance appear proactively or only through an explicit discovery action, and how persistently should dismissal suppress it?
