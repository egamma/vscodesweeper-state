# Issue #112134 — Respect the system setting for mouse scroll speed

[https://github.com/microsoft/vscode/issues/112134](https://github.com/microsoft/vscode/issues/112134)

## Summary

Keep this accepted, well-supported request open: the existing sensitivity settings provide manual multipliers, not automatic adherence to system scrolling preferences. This issue already owns the consolidated request; the related macOS scaling fix does not establish that the Windows system-setting behavior is implemented.

## Change summary

Make mouse-wheel scrolling respect the operating system's configured scroll speed without requiring separate VS Code sensitivity adjustments.

## Best solution

Deliver system-consistent scrolling through the shared wheel-event and scrollbar paths while retaining explicit sensitivity controls. First establish how current Windows wheel events encode system preferences and assess compatibility with trackpads, display scaling, and browser-hosted VS Code.

- **Behavior:**

  > Changing Windows mouse scroll speed should affect mouse-wheel scrolling in VS Code without manually retuning editor or workbench sensitivity. The reported acceptance scenario is a long text file scrolled with the same physical wheel input at minimum and maximum system settings. Explicit VS Code sensitivity settings should remain useful as user overrides. Validation should distinguish following system preferences from merely reducing a fixed scroll multiplier.
- **Trace:**

  > StandardWheelEvent in src/vs/base/browser/mouseEvent.ts prioritizes legacy wheelDeltaY over modern deltaY and deltaMode. AbstractScrollableElement._onMouseWheel in src/vs/base/browser/ui/scrollbar/scrollableElement.ts applies the sensitivity multiplier and a fixed scroll-distance conversion. The source establishes these transformations, but whether current Windows events preserve the system preference before normalization remains unconfirmed. This is the canonical accepted request: https://github.com/microsoft/vscode/issues/7640#issuecomment-957904225 explicitly consolidates the older report here. Preserve explicit multipliers, trackpad handling, horizontal scrolling, and existing device-scale-factor compensation; do not broaden the work into unrelated scrolling regressions.
