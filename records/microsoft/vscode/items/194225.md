# Issue #194225 — Pick a forever theme color for the quick fix highlight and allow styling both background and borders

[https://github.com/microsoft/vscode/issues/194225](https://github.com/microsoft/vscode/issues/194225)

## Summary

A real theming gap remains on current main: the quick-fix highlight still borrows find-match background and border colors, so themes cannot style the two concepts independently. The Backlog request should remain open while the editor owners choose the stable color contract.

## Change summary

Give the quick-fix range highlight a stable theme-color contract supporting both background and border styling without unwanted conflicts with active find highlights.

## Best solution

Define a stable semantic treatment for code-action range highlights, preferably independently customizable background and border colors with defaults that remain distinguishable when find or selection highlights are active.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/codeAction/browser/codeActionController.ts`, `src/vs/platform/theme/common/colors/editorColors.ts`
- **Validation:** Use a test color theme that assigns visibly distinct background and border colors to find matches and the chosen quick-fix color contract; open a quick-fix list while editor find highlights are active and verify both highlight types retain their respective background and border styling, including in a high-contrast theme.
- **Behavior:**

  > When focus moves through the code-action list, the affected range has a stable, theme-aware highlight supporting both background and border treatment. Theme authors can style that semantic highlight without unintentionally changing ordinary find-match highlights if independent tokens are selected. Find, selection, diagnostic, and high-contrast decorations must remain distinguishable when they overlap.
- **Trace:**

  > CodeActionController creates decorations using the `quickfix-edit-highlight` class in src/vs/editor/contrib/codeAction/browser/codeActionController.ts. Its theming participant currently maps that class directly to `editorFindMatchHighlight` and `editorFindMatchHighlightBorder`, whose registrations live in src/vs/platform/theme/common/colors/editorColors.ts. Commit https://github.com/microsoft/vscode/commit/5c4daed6a3dd71229120341252277f2cbf7475b5 introduced this coupling before the issue and therefore is not a post-reopen fix. The broader range API was tracked by https://github.com/microsoft/vscode/issues/199608, but this issue remains the separate theming-contract decision. Keep the change scoped to code-action range decoration colors; do not alter find-match color semantics or the CodeAction range API.
- **Open decisions:**
  - Should the public theme contract reuse the existing find-match background and border tokens permanently, or expose dedicated quick-fix/code-action highlight tokens so themes can distinguish simultaneous find and action ranges?
