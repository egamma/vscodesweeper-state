# Issue #282523 — Wrong error message extraction when Git hooks fail

[https://github.com/microsoft/vscode/issues/282523](https://github.com/microsoft/vscode/issues/282523)

## Summary

Valid bug with a linked open PR from the reporter. The error message extraction at commands.ts:5647-5654 uses a naive first/last-line heuristic that can surface misleading output from multi-hook pipelines. Keeping open — the open PR should be reviewed on its merits.

## Change summary

When Git hooks fail, VS Code displays misleading error messages by naively picking the first or last non-empty line of hook output rather than the actual failure line.

## Best solution

Review and iterate on the linked PR https://github.com/microsoft/vscode/pull/282524, which proposes smarter extraction logic in `extensions/git/src/commands.ts` (the `default` branch of the commit-error switch around line 5646). The fix should prioritize lines indicating failure (e.g. containing 'Failed', 'error', exit-code info) over informational lines, while keeping the fallback to first/last line when no failure-indicating line is found.
