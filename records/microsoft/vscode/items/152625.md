# Issue #152625 — Git - warn the user when closing a window with uncommitted/unpushed source control changes

[https://github.com/microsoft/vscode/issues/152625](https://github.com/microsoft/vscode/issues/152625)

## Summary

Keep this accepted Git feature request open: existing close confirmations do not depend on uncommitted or unpushed changes. The request has 31 upvotes, and no verified older open canonical or landed implementation was found.

## Change summary

Offer an optional warning before closing a window or replacing its workspace when Git changes remain uncommitted or unpushed.

## Best solution

Provide an opt-in, repository-aware reminder integrated with window shutdown and workspace replacement, without automatically committing or pushing. A maintainer should first settle which repository states trigger it and how users select those conditions.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/workbench.contribution.ts`, `src/vs/workbench/electron-browser/window.ts`, `src/vs/workbench/services/lifecycle/common/lifecycle.ts`, `src/vs/workbench/contrib/scm/common/scm.ts`, `extensions/git/src/api/git.d.ts`, `extensions/git/package.json`
- **Validation:** After deciding trigger semantics, manually exercise window close, application quit, and Ctrl+R workspace replacement with clean repositories, staged/unstaged changes, and commits ahead of an upstream. Verify enabled matching conditions warn, cancellation preserves the current workspace, proceeding succeeds, and disabled or nonmatching conditions do not add a warning; include a multi-repository workspace.
- **Behavior:**

  > Users who opt in receive a reminder before leaving a workspace containing Git state that meets the chosen uncommitted/unpushed conditions. The reported transitions are closing the window and switching workspaces through Ctrl+R. Cancelling keeps the current workspace open; proceeding does not automatically commit or push. Clean repositories and users who have not enabled the feature retain their existing behavior. Acceptance should distinguish changes saved to disk from changes committed or pushed.
- **Trace:**

  > window.confirmBeforeClose is registered in src/vs/workbench/browser/workbench.contribution.ts and currently selects always, keyboardOnly, or never; NativeWindow.onBeforeShutdown in src/vs/workbench/electron-browser/window.ts does not consult Git state. BeforeShutdownEvent in src/vs/workbench/services/lifecycle/common/lifecycle.ts supports vetoing shutdown. The built-in Git API declares RepositoryState change collections and optional Branch.ahead/upstream in extensions/git/src/api/git.d.ts, while the workbench SCM provider contract is in src/vs/workbench/contrib/scm/common/scm.ts. The trace establishes those surfaces, not a complete state-to-shutdown integration design. Preserve existing unsaved-editor protections and generic close-confirmation behavior, and avoid introducing automatic Git operations. https://github.com/microsoft/vscode/issues/159710 is a younger closed report; its cloud-edit-session workaround does not satisfy this reminder.
- **Open decisions:**
  - Should users select uncommitted changes, unpushed commits, or either condition independently, and what should enabling the feature select initially?
  - Should untracked files and local commits on branches without an upstream count as warning conditions?
