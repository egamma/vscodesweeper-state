# Issue #326544 — Web: webview service worker intermittently loses interception; requests escape to vscode-cdn.net via real DNS and the retry flood crashes the shared render process, freezing every same-site tab

[https://github.com/microsoft/vscode/issues/326544](https://github.com/microsoft/vscode/issues/326544)

## Summary

This remains a webview-core robustness bug: current main limits concurrent host-backed response bodies only on Electron, leaving web deployments exposed to the reported resource exhaustion and renderer crash.

## Change summary

High-concurrency webview resource loading can lose service-worker interception and exhaust the shared web renderer, freezing all same-site tabs.

## Best solution

The webview area should add safe backpressure for web deployments and recover or fail visibly when the service-worker controller is lost. Web integration coverage should exercise hundreds of concurrent resources and verify that interception and the renderer remain healthy.
