# Issue #194568 — File nesting breaks when moving files

[https://github.com/microsoft/vscode/issues/194568](https://github.com/microsoft/vscode/issues/194568)

## Summary

The stale Explorer nesting state remains possible on current main, and an open PR already attempts to fix this issue. Keep the issue open while that PR is reviewed, revised, or closed.

## Change summary

Moving one nested file into a subdirectory can leave its former nesting parent expanded but visually empty until VS Code reloads.

## Best solution

Correct the Explorer model/view refresh for the old nesting parent and source directory when a nested child moves, with a regression test covering multiple nested children. Review or rework https://github.com/microsoft/vscode/pull/198645 rather than closing the issue before its fix attempt is resolved.

## Evidence

- **current source path:** In src/vs/workbench/contrib/files/browser/explorerService.ts, the MOVE path saves `oldNestedParent`, calls `modelElement.move(...)`, then refreshes `oldNestedParent` and `oldParent` non-recursively while only the destination receives `shouldDeepRefresh`. This can leave the expanded source nest out of sync after its children are recomputed.
- **model behavior:** In src/vs/workbench/contrib/files/common/explorerModel.ts, `ExplorerItem.move` removes the item from both `nestedParent` and its directory parent; `removeChild` clears `nestedChildren`. The subsequent non-recursive view refresh does not guarantee that the surviving nested child is rendered beneath the already-expanded nesting parent.
- **open fix attempt:** https://github.com/microsoft/vscode/pull/198645 remains open and explicitly targets https://github.com/microsoft/vscode/issues/194568. A maintainer noted that its proposed FileService event change breaks many tests, so it is not a landed fix and the issue must remain open.
- **canonical search:** The supplied candidate https://github.com/microsoft/vscode/issues/3884 concerns VS Code application-data folder structure and does not report the same Explorer file-nesting symptom; it is not a duplicate canonical.
