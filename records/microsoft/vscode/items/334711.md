# Issue #334711 — Ignore parser treats literal exclamation marks as negation

[https://github.com/microsoft/vscode/issues/334711](https://github.com/microsoft/vscode/issues/334711)

## Summary

Confirmed in current source: `IgnoreFile.parseIgnoreFile` in `ignoreFile.ts` classifies any line containing `!` anywhere as a negation and strips every `!` via `line.replace(/!/g, '')`, so literal exclamation marks in filenames (or escaped/character-class uses) are mishandled — a real, narrow parser bug. An open PR already targets the fix, so this should stay open for that PR to land rather than be closed or auto-fixed independently.

## Change summary

The shared gitignore parser treats any `!` in a pattern as a negation prefix and strips all exclamation marks, mishandling literal exclamation marks in filenames, escaped leading `!`, and negated character classes like `[!a]`.

## Best solution

Land the fix in the linked PR https://github.com/microsoft/vscode/pull/334712 (or an equivalent), which reworks `parseIgnoreFile`/`gitignoreLineToGlob` in src/vs/workbench/services/search/common/ignoreFile.ts to only treat a leading unescaped `!` as negation, matching git's documented pattern format.
