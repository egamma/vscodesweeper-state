## Summary

The deep-tree hang remains actionable and has a concrete reproduction plus a performance trace. The older related issue https://github.com/microsoft/vscode/issues/213839 describes the same observable deep-tree rendering hang, but because this item was previously reviewed and that issue is not older than this report, the stronger re-review duplicate rule requires keeping this issue open.

## Change summary

Rendering and scrolling a roughly 500-level nested tree in Outline or breadcrumbs can freeze the window, with tree sticky scroll increasing the cost.

## Best solution

Profile and bound the work performed per visible row and ancestor depth in the shared tree widget, including sticky-scroll and indent-guide rendering, then add a deep-nesting benchmark or regression test covering Outline and breadcrumbs consumers.
