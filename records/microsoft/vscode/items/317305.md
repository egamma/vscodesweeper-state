Keep open as a request for predictable keyboard navigation after staging. Current source does not provide stage-and-advance semantics, and no verified older canonical issue or concrete fixing commit was found.

## Change summary

Support staging the focused SCM resource and continuing through sibling changes without losing the keyboard navigation position.

## Best solution

Define a predictable SCM-local stage-and-advance interaction, including behavior when the last change disappears. Decide whether this should change ordinary staging focus or be an explicit command, without changing focus recovery for unrelated workbench trees.
