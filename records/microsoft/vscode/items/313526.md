# Issue #313526 — "Close Other Repositories" is non-functional for worktrees — they reappear immediately

[https://github.com/microsoft/vscode/issues/313526](https://github.com/microsoft/vscode/issues/313526)

## Summary

The close/reopen defect has multiple confirmed reproductions, and current source still permits API callers to bypass the user's closed-repository state. Route to Git ownership and keep open while the linked fixing PR is reviewed.

## Change summary

Honor manually closed worktree repositories without background Git or Copilot activity silently reopening them, and provide an effective worktree-discovery opt-out.

## Best solution

Review https://github.com/microsoft/vscode/pull/313612 against both automatic discovery and API-triggered reopening; its discovery filtering must not leave the confirmed Copilot path unresolved. Preserve explicit user-requested reopening while ensuring background repository lookups respect closure and the existing git.detectWorktrees setting.
