# Issue #213684 — Inconsistent behavior of opening custom editor via ctrl+p 

[https://github.com/microsoft/vscode/issues/213684](https://github.com/microsoft/vscode/issues/213684)

## Summary

Still reproduces on main: when a custom editor with priority "option" is opened and closed, history stores the custom editor's viewType as the `override` option, causing Ctrl+P to reopen the file with the custom editor instead of the default text editor.

## Change summary

Reopening a file via Ctrl+P after closing a custom editor (priority "option") incorrectly opens the custom editor instead of the default text editor.

## Best solution

The fix should ensure that when a custom editor with `option` priority is serialized to history via `toUntyped()`, the override is either omitted or the history/quick-open path respects the user's `editorAssociations` and the editor's declared priority. The likely fix locations are `customEditorInput.ts` (its `toUntyped()` method at line ~396 unconditionally sets `override: this.viewType`) and/or the history replay path in `anythingQuickAccess.ts` (lines ~1136-1142 which blindly propagates the stored override).
