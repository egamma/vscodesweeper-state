# Issue #213684 — Inconsistent behavior of opening custom editor via ctrl+p 

[https://github.com/microsoft/vscode/issues/213684](https://github.com/microsoft/vscode/issues/213684)

## Summary

The reported inconsistency remains traceable on current main: Quick Open restores the historical custom-editor override, while Explorer resolves the current default. Keep this accepted bug open; historical maintainer discussion explicitly supported restoring the last editor, so changing that behavior needs a product decision.

## Change summary

Reopening a closed file through Ctrl+P selects its previous optional custom editor instead of the default text editor used by Explorer, even with an explicit default association.

## Best solution

Establish the precedence between historical editor choice and current editor associations for Quick Open, then make that contract predictable without disrupting explicit Reopen Closed Editor restoration. The decision should account for the previously intentional last-editor behavior rather than removing history overrides indiscriminately.
