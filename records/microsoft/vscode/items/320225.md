# Issue #320225 — Unsaved image preview tab can't be closed (and is buggy)

[https://github.com/microsoft/vscode/issues/320225](https://github.com/microsoft/vscode/issues/320225)

## Summary

Confirmed bug: reopening an unsaved untitled file with a readonly custom editor (e.g. Image Preview) creates a permanently stuck dirty tab that cannot be closed, saved, or reverted. The root cause is traceable in the source and remains unfixed on main.

## Change summary

Reopening an unsaved untitled file via "Reopen Editor With…" into a CustomReadonlyEditorProvider (Image Preview) produces a tab that is permanently dirty and cannot be closed.

## Best solution

The custom editor input and model need to handle the case where a readonly custom editor is opened on an untitled resource with pending document data. Either prevent 'Reopen Editor With…' from offering readonly custom editors for dirty untitled files, or ensure the dirty state is cleared / the revert path works correctly for non-editable custom editor models. The fix touches `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts` (the `_defaultDirtyState` / `isDirty` / `revert` path) and possibly `src/vs/workbench/api/browser/mainThreadCustomEditors.ts` (the `MainThreadCustomEditorModel` readonly+startDirty interaction). Related open issue https://github.com/microsoft/vscode/issues/186359 covers a similar untitled custom editor lifecycle gap but is scoped to shutdown behavior, not the inability to close.

## Evidence

- **source trace: dirty state on readonly editor:** In `src/vs/workbench/api/browser/mainThreadCustomEditors.ts` line 579, `_isDirtyFromContentChange` is set to `true` when `startDirty` is true (untitled doc data present). But the model is non-editable (`_editable: false`) since Image Preview registers as `CustomReadonlyEditorProvider`. The working copy is NOT registered (line 581 guard), so the save/revert working copy flow is broken.
- **source trace: save fails silently:** In `src/vs/workbench/contrib/customEditor/browser/customEditorInput.ts` line 282–297, `save()` delegates to `_modelRef.object.saveCustomEditor()` which throws 'Document is not editable' for readonly models (line 709). The save returns `undefined` (cancelled), so the tab stays dirty and open.
- **source trace: revert doesn't clear model dirty:** `CustomEditorInput.revert()` (line 318) calls `_modelRef.object.revert()` which for non-editable models (line 749) returns without clearing `_isDirtyFromContentChange`, so the model stays dirty forever.
- **related issue:** https://github.com/microsoft/vscode/issues/186359 tracks a related but distinct problem (reverted custom editors for untitled files staying open after shutdown). The current issue is about being unable to close the tab at all.
- **recent related fix:** Commit b3d27f5db68 (2026-05-08) fixed a related data-loss issue with 'Reopen Editor With…' on dirty untitled docs (https://github.com/microsoft/vscode/issues/315243), but that fix addresses the text model side, not the readonly custom editor dirty-state deadlock.
