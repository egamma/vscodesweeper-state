# Issue #318095 — [feat] Allow Terminal in panel and Secondary Side Bar simultaneously

[https://github.com/microsoft/vscode/issues/318095](https://github.com/microsoft/vscode/issues/318095)

## Summary

Keep open: current source still provides one movable Terminal view, not independent terminal views in the panel and Secondary Side Bar. This request has 30 upvotes, and a maintainer has explicitly consolidated a matching report here.

## Change summary

Allow independent terminal tabs in the bottom panel and a side bar simultaneously.

## Best solution

Support simultaneous terminal hosts in the panel and side bar, with independent tab collections and reliable layout restoration. Establish command targeting and focus semantics before extending the current shared terminal-view model.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminal.contribution.ts`, `src/vs/workbench/contrib/terminal/browser/terminalGroupService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalService.ts`, `src/vs/workbench/contrib/terminal/browser/terminalView.ts`, `src/vs/workbench/contrib/terminal/browser/terminalActions.ts`, `src/vs/workbench/contrib/terminal/browser/terminal.ts`, `src/vs/platform/terminal/common/terminal.ts`, `src/vs/workbench/contrib/terminal/test/browser/terminalService.test.ts`
- **Validation:** With persistent sessions enabled, create shell terminals in the bottom panel and an agent terminal in the Secondary Side Bar; verify both remain visible with independent tab collections, creating or selecting a tab in one does not replace the other, and reload restores each terminal to its host. Add targeted terminal service tests for host assignment and restoration, and verify existing panel/editor terminal behavior remains unchanged.
- **Behavior:**

  > Users can keep ordinary shell terminals in the bottom panel while a long-running CLI terminal remains in the Secondary Side Bar, without consuming an editor group. Each location has its own terminal tabs, and manipulating one collection does not relocate the other. With persistent sessions enabled, reload reliably restores the terminal-to-location assignment. Existing panel and editor terminal workflows remain available.
- **Trace:**

  > src/vs/workbench/contrib/terminal/browser/terminal.contribution.ts registers one movable TERMINAL_VIEW_ID, and src/vs/platform/terminal/common/terminal.ts distinguishes only Panel and Editor targets. TerminalService.getInstanceHost and _createTerminal send all non-editor terminals to one TerminalGroupService, whose groups, activeGroupIndex and container represent a shared host. TerminalService._saveState and _recreateTerminalGroups persist and restore that shared collection. The default-location setting and editor/new-window commands do not provide simultaneous panel and side-bar terminal views. https://github.com/microsoft/vscode/issues/318570 was closed explicitly as a duplicate of this request. The design boundary includes host-local tabs, focus, command targeting and restoration; preserve existing editor-terminal and terminal-process behavior. The source establishes the missing capability, but does not settle how existing globally targeted commands should behave when multiple terminal views coexist.
- **Open decisions:**
  - When panel and side-bar terminal views coexist, should existing New Terminal, Focus Terminal and Toggle Terminal commands target the last-focused terminal host or retain a designated default host?
