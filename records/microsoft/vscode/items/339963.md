# Issue #339963 — Connected tabs: customized active background exposes shoulder join artifacts

[https://github.com/microsoft/vscode/issues/339963](https://github.com/microsoft/vscode/issues/339963)

## Summary

Well-documented visual bug in the experimental modernUI connected-tabs feature; traced the shoulder-paint CSS and it plausibly produces the described seam when a customized active tab background differs from the editor body color, but this needs design input (two coupled concerns: color-mismatch masking and the HC non-color selection indicator) before implementation, so it's not a clean agent-implement task yet.

## Change summary

When a connected tab's active background is customized to differ from the editor background, the curved shoulder joins show a visible seam, and in high contrast the multi-selection outline's bottom stroke makes the join look closed.

## Best solution

Design a shoulder/mask treatment that stays clean regardless of the active-tab vs. editor-background color delta, and rework the HC multi-selection indicator so it doesn't read as a bottom border at the join — likely in connectedEditorTabs.css alongside the HC outline rules in tabs.css.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/modernUI/browser/media/connectedEditorTabs.css`, `src/vs/workbench/contrib/modernUI/browser/media/tabs.css`
- **Validation:** Visual check in Component Explorer scenes editor/tabs/Colors/TabAndActionCustomizations/SingleRow/Dark and .../DarkHighContrast: no visible shoulder seam with a customized `modernEditorTab.activeBackground` differing from the editor background, and the HC multi-selection indicator no longer reads as a closed bottom border.
- **Behavior:**

  > With `modernEditorTab.activeBackground` customized to a color different from the editor background, the active connected tab's bottom shoulder joins must render cleanly (no visible seam) in both regular and high-contrast themes. In HC, the active tab's multi-selection indicator must remain distinguishable without implying the connection is closed off by a horizontal bottom stroke. Default (non-customized) connected tab geometry must be unchanged.
- **Trace:**

  > The shoulder is painted via a `box-shadow` sized to `--modern-ui-connected-tab-shoulder-radius` and colored by `--modern-ui-connected-tab-current-background`/`--modern-ui-connected-tab-active-background` (connectedEditorTabs.css ~lines 300-436), with a clip-path mask erasing the straight-edge stroke; this assumes the surrounding editor background matches, which breaks when the active background is customized away from the editor body color. https://github.com/microsoft/vscode/issues/339028 previously changed the shoulder radius/mask dimensions (changing exact appearance but not this root cause per the author's comparison); https://github.com/microsoft/vscode/issues/338796 added the custom-color Component Explorer scene used in this report. Boundary: do not alter the default (uncustomized) connected-tab shoulder geometry or focused/unfocused group behavior.
- **Open decisions:**
  - How should the shoulder mask/paint handle an active tab background that differs from the editor body background — extend the custom color into the mask, blend at the seam, or redesign the join geometry entirely?
  - How should the HC active multi-selection outline be reshaped so it doesn't visually close off the bottom join, while still satisfying non-color selection-indication requirements (per https://github.com/microsoft/vscode/issues/326833)?
