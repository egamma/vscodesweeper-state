Keep open pending a Windows reproduction: closing all windows with an update pending is a concrete retest scenario, but the updater has changed since 1.101.2 and the unexpected relaunch is not confirmed on current main. ## Change summary

VS Code unexpectedly reopens after all windows are closed using their X buttons, briefly displaying an update window while the user is preparing to shut down Windows.

## Best solution

Ensure ordinary window closure with a pending Windows update leaves VS Code closed, while an explicit Restart to Update still relaunches it. First reproduce the reported sequence and distinguish ordinary application closure from an actual Windows session-ending event.

- **Validation:** On Windows with a genuine pending background update, close every VS Code window using X without invoking Restart to Update and verify that Code does not reopen after installation completes. Separately invoke Restart to Update and verify that Code does reopen; also check actual Windows shutdown with an update pending.
- **Behavior:**

  > Closing all VS Code windows using X must leave the application closed even when a background update completes afterward. An explicit Restart to Update must continue to reopen VS Code. Reproduce the reported update-progress-then-relaunch sequence on Windows and verify both ordinary closure and actual operating-system shutdown as distinct cases.
- **Trace:**

  > Win32UpdateService in src/vs/platform/update/electron-main/updateService.win32.ts creates a background-update flag and passes its path to the installer; doQuitAndInstall removes that flag when restarting explicitly. In build/win32/code.iss, LockFileExists and ShouldRunAfterUpdate encode the distinction between ordinary closure and an accepted restart, while SessionEndFileExists separately handles operating-system shutdown. Source inspection establishes the intended contract but does not establish why this reporter observed a relaunch or whether it persists today. The similar report at https://github.com/microsoft/vscode/issues/230960 was later reported resolved without a cited fix. Preserve explicit restart behavior and do not broaden the work into unrelated updater or lifecycle changes.
