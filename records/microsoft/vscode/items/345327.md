# Issue #345327 — About vscode copilot agent default selection

[https://github.com/microsoft/vscode/issues/345327](https://github.com/microsoft/vscode/issues/345327)

## Summary

Existing settings support starting new chats with Local rather than the Copilot SDK, and separate settings control default permissions. The requested Local-versus-Copilot default does not require a new capability.

## Change summary

Configure a workspace's default chat harness and permissions instead of changing them for every new session.

## Best solution

Use the existing harness settings to retain Local for new chats, with the appropriate default-permissions setting. Preserve organization-managed restrictions rather than bypassing them.

- **Fit:** aligned
- **Reason:** Configurable defaults support consistent chat workflows without introducing another competing control.

- **Proposed comment:**

  > Thanks for the request. To keep Local as the default in a workspace, set `chat.defaultToCopilotHarness` and `chat.editor.preferCopilotHarness` to `false`, leave `chat.editor.localAgent.enabled` enabled, and select Local. An organization policy can override these choices.
  > 
  > Default permissions are configured with `chat.permissions.default` for Local chats, or `chat.defaultConfiguration.approvals` for Copilot agent sessions. These existing settings cover the defaults requested here.

- **Permission defaults already supported:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:757–823 registers chat.permissions.default for new Local chats and chat.defaultConfiguration, including approvals, for new agent sessions.
