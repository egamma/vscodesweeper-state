# Issue #193443 — Disposed language status item comes back if modified after disposing

[https://github.com/microsoft/vscode/issues/193443](https://github.com/microsoft/vscode/issues/193443)

## Summary

Still reproduces on main: the disposed-item guard in extHostLanguages.ts uses a shared ID set rather than a per-item flag, so modifying a disposed item after a new item reuses the same ID bypasses the guard and re-registers the old handle, duplicating the status bar entry.

## Change summary

Modifying a disposed LanguageStatusItem after another item reuses the same ID causes the disposed item to reappear, duplicating the status bar entry.

## Best solution

Replace the shared `ids.has(fullyQualifiedId)` disposed guard in `updateAsync()` with a per-item `disposed` boolean flag set in `dispose()`. This ensures modifications to a disposed item are dropped even when a new item has re-registered the same ID.
