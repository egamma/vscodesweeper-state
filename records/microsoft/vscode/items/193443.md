# Issue #193443 — Disposed language status item comes back if modified after disposing

[https://github.com/microsoft/vscode/issues/193443](https://github.com/microsoft/vscode/issues/193443)

## Summary

The supplied reproduction still follows a defective path on current main: reusing an ID makes the disposed item's update guard pass, allowing its old handle to be registered again. Keep this open for a bounded lifecycle fix; the existing area labels are appropriate.

## Change summary

Prevent a disposed language status item from reappearing when its ID is reused and an asynchronous callback modifies the original item.

## Best solution

A disposed LanguageStatusItem must remain inactive independently of subsequently created items with the same ID. Preserve the current rejection of simultaneously active duplicate IDs and the replacement item's normal updates.
