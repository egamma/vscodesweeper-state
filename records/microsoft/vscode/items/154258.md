# Issue #154258 — Menu appears below quick pick

[https://github.com/microsoft/vscode/issues/154258](https://github.com/microsoft/vscode/issues/154258)

## Summary

The overlap remains possible on current main: command-center quick inputs sit above the title bar, and persistent quick inputs do not close when the menubar opens. The accepted bug should stay open while maintainers choose whether title-bar interaction dismisses the quick input or is blocked.

## Change summary

Opening a title-bar menu while a persistent quick pick is visible renders the menu underneath the quick pick.

## Best solution

Establish one modal interaction contract for quick inputs over the title bar: either dismiss the quick input before opening a menu or intercept title-bar interaction until the quick input closes, ensuring a menu is never rendered underneath it.

## Plan brief

- **Likely files:** `src/vs/platform/quickinput/browser/quickInputController.ts`, `src/vs/platform/quickinput/browser/media/quickInput.css`, `src/vs/base/browser/ui/menu/menubar.ts`, `src/vs/platform/quickinput/test/browser/quickinput.test.ts`
- **Validation:** With the command center enabled, open the remote/simple Open Folder picker and activate each title-bar menu with mouse and keyboard; verify that no menu is visible underneath the picker and that the chosen dismissal-or-blocking behavior is consistent. Repeat with the command center disabled and add a browser test covering the selected interaction contract.
- **Behavior:**

  > A title-bar menu must never open visually underneath an active quick input. With the command center enabled and a persistent Open Folder picker visible, activating the menubar must produce the selected consistent outcome: dismiss the picker before showing the menu, or prevent menu activation while the picker remains open. The same contract must work for mouse and keyboard activation and must not regress non-command-center quick-input placement.
- **Trace:**

  > On current main, Layout.computeContainerOffset in src/vs/workbench/browser/layout.ts places command-center quick inputs at the top of the title bar. The quick-input widget has z-index 2550, above the menubar menu holder, and SimpleFileDialog sets `ignoreFocusOut = true`; QuickInputController therefore does not hide it when focus changes. MenuBar's mousedown path in src/vs/base/browser/ui/menu/menubar.ts opens the menu directly, while no quick-input blocking layer intercepts title-bar interaction. ContextMenuHandler in src/vs/platform/contextview/browser/contextMenuHandler.ts demonstrates the existing blocking-layer behavior mentioned by the maintainer. Preserve ordinary click-outside dismissal and non-command-center placement; the uncertainty is limited to the intended title-bar interaction while a persistent quick input overlays it. Related discussion: https://github.com/microsoft/vscode/issues/153910.
- **Open decisions:**
  - When a persistent quick input overlays the title bar, should activating a menubar item dismiss the quick input and open the menu, or should title-bar interaction remain blocked until the quick input closes?

## Evidence

- **current source path:** src/vs/workbench/browser/layout.ts sets `quickPickTop` to 6 when the command center is visible, deliberately positioning the quick input over the title bar; src/vs/platform/quickinput/browser/media/quickInput.css gives the quick-input widget z-index 2550, while src/vs/base/browser/ui/menu/menubar.css gives menubar menu holders z-index 2000.
- **persistent trigger:** The reported Open Folder flow uses src/vs/workbench/services/dialogs/browser/simpleFileDialog.ts, where the file picker sets `ignoreFocusOut = true`, so moving focus into the menu does not dismiss it.
- **interaction trace:** src/vs/base/browser/ui/menu/menubar.ts opens a menu directly from the menu button's mousedown handler and prevents the event's default behavior; src/vs/platform/quickinput/browser/quickInputController.ts otherwise hides on blur only when `ignoreFocusOut` is false. No blocking layer analogous to ContextMenuHandler's `context-view-block` exists for ordinary quick inputs.
- **maintainer direction:** A maintainer proposed either listeners that dismiss the quick pick or a non-draggable blocking element beneath it in https://github.com/microsoft/vscode/issues/154258#issuecomment-1192839022, confirming the behavior is unintended while leaving the user-visible interaction choice open.
- **related issue:** https://github.com/microsoft/vscode/issues/153910 is older and related to title-bar clicks not dismissing quick picks, but it does not report the same observable menu-under-quick-pick symptom required for a duplicate close on this re-reviewed item.
