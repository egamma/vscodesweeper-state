# Issue #147718 — Markdown preview resets when switching tabs

[https://github.com/microsoft/vscode/issues/147718](https://github.com/microsoft/vscode/issues/147718)

## Summary

Keep open: current source still allows edited preview content to revert when its tab is hidden and restored. An open PR addresses that original defect; the newer scroll-position reports describe a separate behavior that must not be mistaken for resolved content.

## Change summary

Markdown preview should preserve updated content across tab switches instead of restoring an older rendered document.

## Best solution

Review and land a suitable fix from the existing PRs, particularly https://github.com/microsoft/vscode/pull/334681, covering both dynamic and custom-editor previews. Evaluate the independent preview scroll-position reports separately rather than assuming a content-refresh fix resolves them.

In extensions/markdown-language-features/src/preview/preview.ts:301–360, visible same-resource updates use renderBody and advance #currentVersion; at lines 421–442, those updates send updateContent without replacing webview.html. A subsequent non-forced refresh can return at the unchanged-version check, leaving the stored HTML stale.
- **Hidden-panel lifecycle:** DynamicMarkdownPreview.create in extensions/markdown-language-features/src/preview/preview.ts:723–726 does not enable retainContextWhenHidden. Restoring a discarded webview therefore exposes the older stored HTML.
