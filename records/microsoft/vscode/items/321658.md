## Evidence

- **Verified open canonical:** https://github.com/microsoft/vscode/issues/2809 is open and requests variable resolution in settings, explicitly naming `typescript.tsdk`. Its discussion also includes `${workspaceFolder}` remaining literal: https://github.com/microsoft/vscode/issues/2809#issuecomment-420441715. This report is a specific instance of that missing capability.
- **Current SDK configuration path:** In extensions/typescript-language-features/src/configuration/configuration.electron.ts, readGlobalTsdk and readLocalTsdk read `js/ts.tsdk.path` with fallback to `typescript.tsdk`; fixPathPrefixes expands only a leading home-directory shorthand. No `${workspaceFolder}` substitution occurs.
- **Literal path handling:** DiskTypeScriptVersionProvider.loadVersionsFromSetting in extensions/typescript-language-features/src/tsServer/versionProvider.electron.ts passes nonabsolute settings through RelativeWorkspacePathResolver and then loadTypeScriptVersionsFromPath. The resolver in src/utils/relativePathResolver.ts recognizes workspace-folder-name prefixes, not variables, so the reported placeholder remains a literal path component.
- **Existing supported alternative:** extensions/typescript-language-features/package.nls.json documents `./node_modules/typescript/lib` as a supported SDK path, which the version provider resolves relative to workspace roots. This accommodates the reported location without a variable, but does not implement the requested substitution.
