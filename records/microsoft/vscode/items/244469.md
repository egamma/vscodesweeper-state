# Issue #244469 — Repair out-of-bound line number variables / other inconsistent state, but log and notify

[https://github.com/microsoft/vscode/issues/244469](https://github.com/microsoft/vscode/issues/244469)

## Summary

Team-authored (MEMBER) engineering-debt proposal for a systematic approach to handling inconsistent internal state — repair and log instead of throwing. The example PR (#244627) merged, but the broader strategy outlined here (console.error logging, breakpoint hooks, insider notifications, error telemetry for auto-repairs) has not been systematically implemented. Keeping open per hard keep-open rule and because the design work remains.

## Change summary

Establish a consistent pattern for repairing inconsistent internal state (e.g. out-of-bound line numbers) instead of throwing, while still logging, sending error telemetry, and notifying insider users.

## Best solution

Define and document the repair-and-log pattern in the editor core — a utility or convention that auto-repairs invalid state, logs via console.error, fires error telemetry (using the onUnexpectedError / BugIndicatingError-without-throw pattern), and optionally shows insider notifications with snooze. Then incrementally adopt it in hotspots like Range, Position, and line-number validation paths in src/vs/editor/common/.
