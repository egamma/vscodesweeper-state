[https://github.com/microsoft/vscode/issues/282024](https://github.com/microsoft/vscode/issues/282024)

## Summary

Keep open: current source still contains a path that reads the user auto-approve value instead of the enforced policy value, then offers a Disable action that policy prevents from saving. This concerns an enterprise approval boundary and needs human review rather than an automated close.

## Change summary

An enterprise policy disabling global auto-approval should override a conflicting user setting without repeatedly showing the YOLO opt-in dialog or offering an ineffective Disable action.

## Best solution

Ensure the tool-invocation auto-approval path consistently honors the enterprise policy before consulting user configuration or showing the opt-in dialog. Preserve normal opt-in behavior when no restrictive policy applies.
