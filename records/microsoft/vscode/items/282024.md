# Issue #282024 — Investigate global auto approve policy not working properly

[https://github.com/microsoft/vscode/issues/282024](https://github.com/microsoft/vscode/issues/282024)

## Summary

Still reproduces on current main: the per-tool config-based auto-approve path in `shouldAutoConfirm` reads raw user/application config values (`userLocalValue`, `applicationValue`) that bypass the enterprise policy, so a user setting of `true` overrides a policy of `false`, causing the yolo prompt to appear and the Disable button to be ineffective when the policy prevents the write.

## Change summary

When an enterprise policy disables global auto-approve (`ChatToolsAutoApprove`), having the user setting set to `true` still triggers the yolo confirmation prompt, and clicking Disable has no effect.

## Best solution

Add an `_isAutoApprovePolicyRestricted()` guard at the top of the config-reading path in `shouldAutoConfirm` (around line 1386) so that when the enterprise policy disables global auto-approve, the per-tool config-based auto-approve path is skipped entirely — mirroring the existing guard at line 1370 for session-level auto-approve. The same guard should be added to the `shouldAutoConfirmPostExecution` path around line 1420.
