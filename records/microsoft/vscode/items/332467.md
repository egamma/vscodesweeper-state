# Issue #332467 — Java: Create Java Project fails in empty workspace because terminal launch is blocked

[https://github.com/microsoft/vscode/issues/332467](https://github.com/microsoft/vscode/issues/332467)

## Summary

Traced to an intentional safety guard in terminalInstance.ts that blocks terminal creation with a non-userHome cwd in an empty workspace, which also blocks legitimate first-run flows like Java project creation — a real tension worth the terminal team's attention, not a clean core defect or an extension-only issue.

## Change summary

"Java: Create Java Project" (via Maven archetype) fails in an empty workspace because VS Code's terminal guard rejects the cwd the extension requests.

## Best solution

Terminal/platform owners should decide whether trusted, extension-initiated commands like project scaffolding warrant an exception to the empty-workspace cwd guard in src/vs/workbench/contrib/terminal/browser/terminalInstance.ts (around the `workspaceEmptyCreateTerminalCwd` check), e.g. via an explicit opt-in API rather than loosening the guard broadly.
