# Issue #333297 — Agents Window: suggest next user message as ghost text in the chat input

[https://github.com/microsoft/vscode/issues/333297](https://github.com/microsoft/vscode/issues/333297)

## Summary

Keep open: the inspected input completions and follow-up affordances do not deliver response-generated, Tab-accepted next-message suggestions. This team-authored request also explicitly owns the related quick-replies discussion; no qualifying fix or older open canonical was found.

## Change summary

Suggest the next user message as ghost text in the empty, focused Agents Window chat input, with Tab inserting editable text without sending it.

## Best solution

Plan a Sessions-owned next-message suggestion capability that honors the specified focus, empty-input, dismissal, and non-submission behavior without competing with existing follow-ups. Establish the generation source and lifecycle before implementation, preserving provider-neutral Sessions boundaries.

## Plan brief

- **Likely files:** `src/vs/sessions/contrib/chat/browser/newChatInput.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts`, `src/vs/workbench/contrib/chat/browser/widget/input/editor/chatInputEditorContrib.ts`
- **Validation:** End the plan with focused input tests using a deterministic suggestion source: after response completion, display a suggestion only in the empty focused Agents Window input; Tab inserts editable text without submitting; typing, focus loss, session changes, or existing follow-up content suppress stale or competing suggestions. Confirm ordinary chat outside the Agents Window remains unchanged.
- **Behavior:**

  > After an agent response finishes in the Agents Window, offer one natural next user message generated from that final response. Show it only while the input is empty and focused, and dismiss it when the user starts typing. Tab accepts the suggestion as editable input and never submits it. Existing agent-provided follow-up content must take precedence; suggestions are not persisted, synchronized, or shown outside the Agents Window.
- **Trace:**

  > The shared ChatInputPart in src/vs/workbench/contrib/chat/browser/widget/input/chatInputPart.ts already hosts InlineCompletionsController and supplied follow-ups, but the inspected code does not establish a final-response-to-next-message generation path. ChatSuggestNextWidget in src/vs/workbench/contrib/chat/browser/widget/chatContentParts/chatSuggestNextWidget.ts renders configured mode handoffs, while src/vs/sessions/contrib/chat/browser/agentHostInputCompletions.ts supplies command/reference completions and argument hints rather than this capability. src/vs/sessions/contrib/chat/browser/newChatInput.ts is a Sessions input integration lead, not a confirmed owner for completed-turn suggestions. The trace stops before identifying a provider-neutral generation contract and completed-turn lifecycle owner. Keep the feature Sessions-scoped and avoid changing handoff, follow-up submission, or ordinary editor completion semantics. The related discussion was explicitly consolidated here at https://github.com/microsoft/vscode/issues/305023#issuecomment-5459291758.
- **Open decisions:**
  - Should next-message generation work across all Agents Window providers, or initially be available only for providers that explicitly supply a suggestion?
