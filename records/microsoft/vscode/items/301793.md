## Evidence

- **confirmed reports:** Multiple users reproduced inaccessible chat history after saving or changing a workspace, including a detailed recovery report showing that the session files remain on disk while their workspace association/index is lost.
- **source trace:** On current main, src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts handles onDidEnterWorkspace after the workspace storage switch, copies the session files, clears indexCache, and calls flushIndex(); internalGetIndex() then reads chat.ChatSessionStore.index from the new storage scope, which can be empty.
- **open fixing PR:** https://github.com/microsoft/vscode/pull/305109 is open, explicitly carries Fixes #301793, changes ChatSessionStore migration, and adds a session-index preservation regression test. A maintainer reviewed the approach and requested scope adjustments, so the implementation is actively owned but not yet merged.
- **related scope:** https://github.com/microsoft/vscode/issues/305818 is open but covers the broader feature of discovering and recovering sessions orphaned by moved, renamed, or deleted workspaces; it is not an older canonical with the same narrowly observable Save Workspace As failure.
- **recoverability:** The documented workaround recovers the sessions from workspaceStorage, indicating metadata association/index loss rather than physical deletion of the JSONL session data.
