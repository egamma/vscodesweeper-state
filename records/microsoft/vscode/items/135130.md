- **WebKit issue remains open:** https://bugs.webkit.org/show_bug.cgi?id=98951 is NEW with no resolution: 'Events should be dispatched to nodes inside a sandboxed iframe.' Its REST record reports the latest change as 2022-02-11.
- **Firefox evidence is narrower:** https://bugzilla.mozilla.org/show_bug.cgi?id=1736717 was resolved WORKSFORME on 2022-10-27. The final comments explain that the minimal example attached its listener to a window replaced during iframe navigation; attaching to the sandboxed document worked in their testing. This is not a cited fix for the complete VS Code report or Safari.
- **Current source still uses the implicated boundary:** src/vs/workbench/contrib/extensions/browser/extensionEditor.ts:697-750 renders extension markdown in a webview without enabling scripts and opens external URLs through onDidClickLink. src/vs/workbench/contrib/webview/browser/pre/index.html:1037-1045 conditionally enables sandbox scripts, :1194 attaches handleInnerClick to contentWindow, and :548-576 forwards intercepted links through did-click-link. This still depends on click delivery from the sandboxed content; source inspection cannot establish current browser behavior.

That fallback runs after the opener is invoked and therefore does not establish that clicks suppressed at the sandbox-event boundary reach it.
