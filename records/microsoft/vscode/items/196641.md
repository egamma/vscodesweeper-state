# Issue #196641 — Installation trigger for Python extension when Python language is detected in an untitled file 

[https://github.com/microsoft/vscode/issues/196641](https://github.com/microsoft/vscode/issues/196641)

## Summary

Keep open: current main only recommends language extensions from an auto-detected untitled buffer after it exceeds 1,000 characters, so the requested early-typing flow remains unsupported. This is also a team-authored Backlog request, and no commit or closing PR explicitly references it.

## Change summary

Prompt users to install the Python extension when VS Code detects Python in an unsaved untitled editor, without requiring language-picker or status-bar interaction.

## Best solution

Define a product-approved confidence policy that can recommend the Python extension early in an untitled buffer when detection is sufficiently reliable, while avoiding the premature false-positive prompts addressed by https://github.com/microsoft/vscode/issues/208434.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/extensions/browser/fileBasedRecommendations.ts`, `src/vs/workbench/contrib/extensions/test/electron-browser/extensionRecommendationsService.test.ts`, `src/vs/workbench/common/editor/textEditorModel.ts`
- **Validation:** With the Python extension absent, create an untitled editor and type a short, unambiguous Python sample under 1,000 characters; after Python is auto-detected, verify the approved install-prompt behavior without using the language picker or status bar. Also type an ambiguous short sample such as `class A` and verify that the false-positive behavior from https://github.com/microsoft/vscode/issues/208434 is not reintroduced.
- **Behavior:**

  > When an unsaved untitled editor contains enough unambiguous Python code for VS Code to detect Python confidently, users should be offered the Python extension without saving the file, selecting a language, or clicking the status-bar hint. Ambiguous or low-confidence short content must not generate premature language-extension prompts. Explicit language selection and recommendations for saved files must remain unchanged.
- **Trace:**

  > BaseTextEditorModel.doAutoDetectLanguage in src/vs/workbench/common/editor/textEditorModel.ts already changes the model language when automatic detection succeeds. FileBasedRecommendations.promptImportantRecommendations in src/vs/workbench/contrib/extensions/browser/fileBasedRecommendations.ts listens for language changes and can prompt language-specific recommendations, but allowLanguageMatch suppresses auto-detected untitled matches until model.getValueLength() exceeds untitledFileRecommendationsMinLength (1,000). That threshold came from https://github.com/microsoft/vscode/pull/269776 for https://github.com/microsoft/vscode/issues/208434, where short content such as `class A` caused an unwanted C# recommendation. The explicit-selection scenario is separate and already tracked by https://github.com/microsoft/vscode/issues/196640; do not regress that path or saved-file recommendations. Uncertainty starts at the product rule for when an automatic detection is reliable enough to justify an install prompt before 1,000 characters.
- **Open decisions:**
  - What user-observable confidence rule should permit an extension recommendation for auto-detected untitled content below 1,000 characters while suppressing ambiguous detections such as `class A`?

## Evidence
