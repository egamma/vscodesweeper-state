# Issue #199354 — Hold shift to drop into editor?

[https://github.com/microsoft/vscode/issues/199354](https://github.com/microsoft/vscode/issues/199354)

## Summary

Keep open: current source still permits the Shift hint over an errored editor that cannot accept resource insertion. The thread establishes that misleading feedback, rather than failed dropping under Parallels, is the remaining problem.

## Change summary

Show the Shift-to-drop hint only when the target editor can actually accept resource insertion, not over empty groups or errored editors.

## Best solution

Make the editor drop feedback reflect the actual target pane's ability to accept insertion, preserving the existing Shift behavior for working text editors. Retest the documented auxiliary-window sequence separately; the current empty-group guard does not establish that every reported case is fixed.
