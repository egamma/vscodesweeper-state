# Issue #331963 — Enabling Github Copilot Chat causes VS code freeze

[https://github.com/microsoft/vscode/issues/331963](https://github.com/microsoft/vscode/issues/331963)

## Summary

The attached unresponsive-window samples show a real hang path, not just a vague complaint: chat's prompt-file/agent discovery (`computeAgentDiscoveryInfo` → `computeListPromptFiles` → `getExtensionPromptFiles` → `_listFromProviders`) fires editor `updateReadonly`/group-model-change events that cascade into `mainThreadEditorTabs`'s `_updateTabsModel`/`_createTabsModel`, which synchronously serializes and RPCs the tab model to the extension host. This is worth routing to the chat/workbench-tabs owners rather than closing on a single report.

## Change summary

User reports VS Code becomes unresponsive ("window not responding") intermittently after enabling Copilot Chat on a large WSL-remote workspace.

## Best solution

Have the chat prompt-file discovery and editor-tabs owners look at whether repeated readonly/group-model-change events during agent/prompt-file discovery are triggering excessive synchronous `_createTabsModel`/`$acceptEditorTabModel` RPC calls (src/vs/workbench/api/browser/mainThreadEditorTabs.ts) — batching or debouncing that update, or avoiding readonly-state churn during discovery in promptsServiceImpl.ts, looks like the likely fix area; needs a maintainer with profiling access to confirm before committing to a specific change.
