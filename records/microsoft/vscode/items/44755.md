# Issue #44755 — Support environment variables for paths in .code-workspace files

[https://github.com/microsoft/vscode/issues/44755](https://github.com/microsoft/vscode/issues/44755)

## Summary

Keep this accepted, well-supported request open: current workspace loading still treats folder paths literally rather than expanding environment variables. The related settings-variable requests do not replace this distinct workspace-folder capability.

## Change summary

Support environment-variable substitution in .code-workspace folders[].path so shared workspaces can reference machine-specific directories.

## Best solution

Provide noninteractive ${env:NAME} expansion for workspace folder paths while preserving the expressions in the shared workspace file. Agree on local-versus-remote environment selection and unresolved-variable behavior before implementation; general settings interpolation and platform-specific folder definitions are separate work.

- **Behavior:**

  > A shared .code-workspace file can use ${env:NAME} in folders[].path to locate directories whose roots differ between machines. Opening and reloading the workspace should resolve a defined variable to the intended directory without requiring a generated local workspace file. Existing literal paths and folder names remain compatible, and saving the workspace preserves its portable expressions. Acceptance must cover the chosen behavior for missing variables and local versus remote workspaces; arbitrary setting-value interpolation is outside the central request.
- **Trace:**

  > WorkspaceConfigurationModelParser.doParseRaw retains the folders array in src/vs/workbench/services/configuration/common/configurationModels.ts. WorkspaceService.createMultiFolderWorkspace and onWorkspaceConfigurationChanged in src/vs/workbench/services/configuration/browser/configurationService.ts pass that array to toWorkspaceFolders in src/vs/platform/workspaces/common/workspaces.ts, which resolves each path literally through ExtUri.resolvePath. AbstractVariableResolverService in src/vs/workbench/services/configurationResolver/common/variableResolver.ts already provides environment-variable semantics, but is not used on this loading path. Workspace serialization and relocation also run through workspaces.ts and must not replace portable expressions with machine-specific paths. Existing tests in src/vs/platform/workspace/test/common/workspace.test.ts cover absolute/relative conversion, raw-path preservation, and deduplication. The remaining design uncertainty is which environment supplies variables during workspace initialization and what users observe when a variable is absent; general settings interpolation at https://github.com/microsoft/vscode/issues/2809 and OS-specific folder definitions remain separate scope.
- **Open decisions:**
  - For a remote workspace, should folder-path variables resolve from the local client environment or the remote host environment?
  - When a referenced environment variable is missing, should the folder remain unresolved with a diagnostic, be omitted with a diagnostic, or follow the existing resolver's empty-string substitution behavior?
