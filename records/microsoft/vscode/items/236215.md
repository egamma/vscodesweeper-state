# Issue #236215 — [css] `:after' suggested inside comment

[https://github.com/microsoft/vscode/issues/236215](https://github.com/microsoft/vscode/issues/236215)

## Summary

The defect remains valid, but the CSS maintainer identified its root cause and fix location in the CSS language service. Both VS Code fix attempts were closed without merging, so the issue should stay open while the upstream language-service change is pursued.

## Change summary

CSS trigger-character completion suggests `:after` while the cursor is inside a comment despite comment quick suggestions being disabled.

## Best solution

Add comment-position detection and suppression of completions in `microsoft/vscode-css-languageservice`, starting with a regression test around `cssCompletion.ts`; then consume the updated language service in VS Code.
