# Issue #330531 — Agent Host: client subscribes to a session it never created on the backend (-32001 "Session not found on backend"), and the turn hangs forever

[https://github.com/microsoft/vscode/issues/330531](https://github.com/microsoft/vscode/issues/330531)

## Summary

Freshly filed, extremely well-diagnosed regression from a team member with matched hung/healthy population evidence and wire logs; the race is traceable in current source (multiple async gates in _startNewSessionBackend/eagerCreate around workspace-trust and activeClientScope resolution vs. a mutable _newSessions map), so this stays open for the Agent Host owners to fix.

## Change summary

A new Agent Host chat can hang forever on "Working..." because the client subscribes to a backend session that was never created, after a race drops the eager createSession call.

## Best solution

Agent Host owners should close the race in baseAgentHostSessionsProvider.ts so that subscribe/materialize can never proceed without a completed (or promptly-failed) createSession — likely by re-validating/retrying eagerCreate at subscribe time, or making resolveSessionConfig and eagerCreate share one cancellation-safe checkpoint instead of two independent async gates (trust await and activeClientScope.whenResolved()).

## Evidence

- **race window in eagerCreate:** src/vs/sessions/contrib/providers/agentHost/browser/baseAgentHostSessionsProvider.ts:1987-2001 — eagerCreate awaits `this._activeClientScope?.whenResolved()` before calling `connection.createSession(...)`, checking `this._backendUri` for staleness only after that await, layered on top of the workspace-trust await in `_startNewSessionBackend` (lines 2899-2929).
- **matching bail-out path:** _startNewSessionBackend (lines 2899-2929) awaits `getUriTrustInfo` and bails via `if (this._newSessions.get(newSession.sessionId) !== newSession) return;` without calling eagerCreate — exactly matches the failing wire signature (resolveSessionConfig fired, createSession never sent).
