# Issue #340336 — Sessions: orphaned "Session" entries load, then disappear when opened

[https://github.com/microsoft/vscode/issues/340336](https://github.com/microsoft/vscode/issues/340336)

## Summary

Keep open: current main suppresses unconfirmed provisional sessions during fresh listing, but that does not establish that an already-visible orphan is explained when opening fails. The sanitized restore sequence and existing-entry steps suffice to retest; the original orphan-creation trigger remains unknown.

## Change summary

Prevent orphaned placeholder sessions from appearing openable and explain failed opens instead of silently removing the selected entry.

## Best solution

Verify the cached-list-to-restore flow across Agent Host and the Sessions provider, ensuring unconfirmed placeholders are not presented as ordinary conversations and an explicit failed open produces an understandable explanation. Preserve conversation storage and distinguish authoritative absence from temporary provider unavailability.
