# Issue #132873 — Bug: "Emmet: Go to Matching Pair" doesn't work when the closing tag contains whitespace

[https://github.com/microsoft/vscode/issues/132873](https://github.com/microsoft/vscode/issues/132873)

## Summary

Still reproduces on main: the root cause is in the upstream @emmetio/html-matcher (v0.3.3) which fails to parse closing tags containing whitespace. The upstream issue remains open and unfixed.

## Change summary

"Emmet: Go to Matching Pair" fails when the closing tag contains whitespace (e.g. `</tag >`) because the parser doesn't recognize it.

## Best solution

Either update @emmetio/html-matcher once the upstream fix lands (https://github.com/emmetio/html-matcher/issues/13), or apply a local workaround in VS Code's emmet extension (similar to the existing html-matcher override pattern from commit c7dbab59ff4) to handle whitespace in closing tags during parsing.
