# Issue #218078 — Show removed entries in the settings editor

[https://github.com/microsoft/vscode/issues/218078](https://github.com/microsoft/vscode/issues/218078)

## Summary

The Settings editor still hides disabled files.exclude entries, so the requested visibility remains missing. Keep this team-authored, accepted backlog request open; no verified canonical or fixing commit was found.

## Change summary

Show removed object-setting entries in the Settings editor, including entries disabled by extension-contributed defaults.

## Best solution

Represent disabled object entries distinctly from active entries in the Settings editor without changing configuration merging or their effective values. Settle the presentation and available row actions before implementation.

- **Behavior:**

  > An object-setting entry disabled through configuration should remain discoverable in the graphical Settings editor instead of silently disappearing. Cover files.exclude entries disabled by the user and by extension-contributed defaults. The displayed state must distinguish inactive entries from active exclusions without changing which files are excluded. Acceptance should cover both origins, preservation of stored values during unrelated edits, and accessible identification of inactive rows.
- **Trace:**

  > getIncludeExcludeDisplayValue in src/vs/workbench/contrib/preferences/browser/settingsTree.ts merges defaults with the selected scope and filters out every falsy entry, conclusively explaining why false-valued exclusions disappear. SettingIncludeExcludeRenderer.onDidChangeIncludeExclude writes false when removing a default entry and deletes the override when restoring it; these configuration semantics must remain unchanged. In src/vs/workbench/contrib/preferences/browser/settingsWidgets.ts, IIncludeExcludeDataItem carries a key, sibling condition and source, while ExcludeSettingWidget describes every displayed row as an active exclusion. The issue arose while testing merged extension defaults in https://github.com/microsoft/vscode/issues/217238. The source establishes the files.exclude gap; presentation and action semantics across other object-setting renderers remain to be designed, not inferred from their existing removal controls.
- **Open decisions:**
  - Should removed entries appear inline with an explicit inactive state, or in a separate discoverable removed-entries section?
  - Should removed rows be informational only or offer restoration/editing actions, and how should those actions behave when an extension supplies the disabled default?

## Evidence

- **Current source confirms the missing visibility:** src/vs/workbench/contrib/preferences/browser/settingsTree.ts:83-115, getIncludeExcludeDisplayValue, merges default and scoped values and then applies .filter(key => !!data[key]). A files.exclude entry set to false is omitted whether the false value comes from the selected scope or the merged defaults.
- **Removal and display are separate:** src/vs/workbench/contrib/preferences/browser/settingsTree.ts:1697-1718, SettingIncludeExcludeRenderer.onDidChangeIncludeExclude, removes a default entry by writing false and restores a default by deleting its override.
