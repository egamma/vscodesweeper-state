The current source still allows cached TypeScript symbols to survive document closure and reopening with changed content. Keep this open while the linked fix PR is reviewed.

## Evidence

- **Current-source defect:** extensions/typescript-language-features/src/tsServer/cachedResponse.ts stores only document.uri.toString() and document.version. CachedResponse.matches therefore accepts a distinct reopened document with the same URI and version, and execute returns the previous response without invoking the new resolver.
- **Document-symbol path:** extensions/typescript-language-features/src/languageProvider.ts creates a shared cachedNavTreeResponse during provider registration. extensions/typescript-language-features/src/languageFeatures/documentSymbol.ts uses that cache for navtree requests, so reopening the externally changed file at version 1 can return original instead of updated.
- **Reproduction evidence:** https://github.com/microsoft/vscode/issues/347026 supplies concrete public-API steps, explicitly waits for actual document closure, and reports the stale symbol with updated public document text in installed VS Code 1.145.2 on macOS arm64. Source inspection confirms the collision; no runtime validation was performed.
- **Open implementation candidate:** The public GitHub API confirms https://github.com/microsoft/vscode/pull/347028 is open and unmerged. Its body explicitly says Fixes #347026 and describes weak document-identity matching with cache and document-symbol regression coverage. An open fixing PR is not evidence that the issue is completed.
