# Issue #316994 — Copilot Chat title rename reverts

[https://github.com/microsoft/vscode/issues/316994](https://github.com/microsoft/vscode/issues/316994)

## Summary

Keep open: current source still permits renaming an unloaded conversation without persisting its custom title in the transcript. A maintainer already designated this issue as the consolidation target, and the discussion adds a sidebar-versus-editor title inconsistency that needs investigation.

## Change summary

Preserve user-assigned Copilot conversation titles when switching sessions, reopening conversations, and displaying editor tabs.

## Best solution

Make explicit session names durable regardless of whether the conversation is loaded, and keep sidebar and editor identities consistent. Retain this issue as the existing consolidation target while distinguishing persistence failures from editor-only title failures.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentSessionsActions.ts`, `src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts`, `src/vs/workbench/contrib/chat/common/model/chatSessionStore.ts`, `src/vs/workbench/contrib/chat/browser/widgetHosts/editor/chatEditorInput.ts`, `src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts`
- **Validation:** Extend the existing ChatSessionStore tests to store an original custom title, rename the session without a live model, and assert readSession returns the new customTitle; run scripts/test.sh --run src/vs/workbench/contrib/chat/test/common/model/chatSessionStore.test.ts after implementation. Also rename two conversations, open both as editors, switch and continue chatting, then reload; verify names remain consistent in the sidebar and tabs. These checks were not executed during this read-only review.
- **Behavior:**

  > An explicit conversation rename must survive switching away, reopening, and window reload, whether or not the conversation was active when renamed. The sidebar and editor tabs must identify the same conversation by its user-assigned name. Automatic title generation must not replace that explicit name. Acceptance includes a persisted-transcript round trip for an unloaded session and the two-conversation editor workflow described in the discussion.
- **Trace:**

  > RenameAgentSessionAction reaches ChatService.setChatSessionTitle for local sessions. That method updates customTitle only when the model is registered; ChatSessionStore.setSessionTitle changes the index, while saveState writes only live models. acquireOrRestoreLocalSession subsequently restores transcript data containing the earlier customTitle, and ChatEditorInput.getKnownTitle prefers that model over index metadata. This conclusively explains the unloaded-session case and the active-conversation workaround. The November sidebar/editor discrepancy may involve another session type or title synchronization path; establish that boundary before treating the persistence fix as complete. Preserve existing title-generation behavior for unnamed conversations and avoid changing unrelated provider contracts. https://github.com/microsoft/vscode/issues/335707 already consolidates into this issue; https://github.com/microsoft/vscode/pull/344967 addresses a different restored-tab fallback case.
