# Issue #332235 — terminal dictation icon out of sync

[https://github.com/microsoft/vscode/issues/332235](https://github.com/microsoft/vscode/issues/332235)

## Summary

Real, maintainer-acknowledged rough edge in terminal dictation's mic-icon positioning; the area owner (meganrogge) confirms the experience isn't great but says it's low priority, so this stays open rather than closing.

## Change summary

The terminal dictation mic/ghost-text decoration can drift out of sync with the cursor and overlap text, and dictation doesn't auto-stop/clear when moving to a new prompt.

## Best solution

Belongs with the terminal voice/dictation code in src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts — the decoration's x-position is computed once per recognizing event from cursorX + inputLength without accounting for line wrap or subsequent cursor movement (e.g. shell echo), and there's no handling to auto-stop dictation on a new prompt; needs a maintainer design pass rather than a quick patch given it bundles two asks and is already deprioritized.

## Evidence

- **positioning logic:** src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts _createDecoration() computes `xPosition = xterm.buffer.active.cursorX + inputLength` once per recognizing event; this doesn't account for line wrap when input exceeds `xterm.cols`, or for cursor movement from concurrent shell output, which would misplace the decoration over existing text.
- **no prompt-change handling:** The class listens for `onDidChangeActiveInstance` and `onDidDisposeInstance` to stop, but there is no listener for the shell moving to a new prompt (e.g. via shell integration command-finished events) to auto-clear/stop an in-progress dictation, matching the second ask in the report.
