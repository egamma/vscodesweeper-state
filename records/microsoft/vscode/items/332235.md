# Issue #332235 — terminal dictation icon out of sync

[https://github.com/microsoft/vscode/issues/332235](https://github.com/microsoft/vscode/issues/332235)

## Summary

Fresh, specific report against the actively-developed terminal dictation feature; the code path is plausible (decoration position is computed once at creation and only recreated on discrete recognition events, not continuously tracked against cursor movement), so this is worth routing to the terminal/dictation owners rather than closing.

## Change summary

The terminal dictation mic icon decoration can drift out of sync with the actual cursor/text position, and an in-progress dictation isn't automatically stopped/cleared when the user moves to the next shell prompt.

## Best solution

Have the terminal/dictation owners investigate `TerminalVoiceSession` in src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts: `_createDecoration`/`_updateDecoration` compute the mic icon's x position from `cursorX + inputLength` only at (re)creation time, and the session isn't tied to prompt-boundary detection, which plausibly explains both the drift and the missing auto-stop-on-new-prompt behavior.

## Evidence

- **decoration positioning:** src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts:376-403 (`_createDecoration`) computes `xPosition = xterm.buffer.active.cursorX + inputLength` once when the decoration is (re)created, and the row is fixed to `onFirstLine ? 0 : -1`; it is not continuously repositioned as text/cursor changes between recreation events.
- **decoration lifecycle:** src/vs/workbench/contrib/terminalContrib/voice/browser/terminalVoice.ts:438-446 (`_updateDecoration`) only tears down and recreates the decoration on discrete `Recognizing`/`Recognized` speech events, not on general cursor/prompt movement, which is consistent with the reported drift and no automatic stop when moving to a new prompt.
