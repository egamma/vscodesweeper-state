# Issue #338894 — Chat sessions are not shared between VS Code clients connected to the same Remote SSH host

[https://github.com/microsoft/vscode/issues/338894](https://github.com/microsoft/vscode/issues/338894)

## Summary

Real, well-documented request that current code confirms: chat sessions are indexed and stored under `environmentService.workspaceStorageHome` (client-local workspaceStorage), so two clients connected to the same Remote SSH host and workspace each see their own independent chat history. The reporter's cited precedent (#307885) was closed as 'duplicate' with state_reason duplicate but no visible canonical issue was ever linked, and is now locked — so a `*duplicate` close can't be verified here; a maintainer (connor4312) commented that it 'is something we're working on and tracking', suggesting active but non-public work.

## Change summary

Chat session history for a Remote SSH workspace is stored per local client rather than shared/persisted per remote workspace, so different machines connecting to the same remote host see different chat histories.

## Best solution

A maintainer should either link the actual (possibly internal) tracking issue for this remote-shared-chat-session work so the community discussion consolidates there, or confirm this is the public issue to track it going forward; the underlying fix would move (or additionally persist) chat session index/state to a remote-workspace-scoped location instead of purely client-local `workspaceStorageHome`.
