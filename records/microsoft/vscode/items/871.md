# Issue #871 — Macro like keybindings

[https://github.com/microsoft/vscode/issues/871](https://github.com/microsoft/vscode/issues/871)

## Summary

The built-in runCommands command covers sequential execution, but a maintainer explicitly retained this issue for first-class macro keybindings. Current source still rejects command arrays, so the remaining product scope should be decided rather than treating the request as completed.

## Change summary

Allow a keyboard shortcut to directly declare an ordered sequence of commands.

## Best solution

Define the remaining first-class keybinding experience beyond runCommands, including its JSON representation and Keyboard Shortcuts editor behavior. Preserve runCommands as the existing supported way to execute command sequences, and keep recording and unrelated command-specific failures separate.

## Plan brief

- **Likely files:** `src/vs/workbench/services/keybinding/browser/keybindingService.ts`, `src/vs/workbench/services/keybinding/common/keybindingIO.ts`, `src/vs/workbench/contrib/commands/common/commands.contribution.ts`
- **Validation:** After agreeing the contract, add keybinding IO and editing tests for the accepted sequence representation and its round-trip behavior. Verify that one shortcut executes the declared commands in order, honors the binding's when clause, preserves existing single-command bindings and runCommands, and behaves consistently in the Keyboard Shortcuts editor.
- **Behavior:**

  > A user should be able to associate one shortcut with an explicitly ordered command sequence as a first-class keybinding. Sequential execution already exists through runCommands; this request remains about the experience beyond that wrapper. Acceptance must cover the agreed JSON form, execution order, binding-level when conditions, and editing or display in Keyboard Shortcuts without regressing existing bindings.
- **Trace:**

  > RunCommands.run in src/vs/workbench/contrib/commands/common/commands.contribution.ts already awaits commands sequentially and supports arguments. The keybinding schema in src/vs/workbench/services/keybinding/browser/keybindingService.ts explicitly rejects command arrays, and KeybindingIO.readUserKeybindingItem in src/vs/workbench/services/keybinding/common/keybindingIO.ts accepts only string commands. The maintainer retained first-class support at https://github.com/microsoft/vscode/issues/871#issuecomment-1494347652. The unmerged proposal https://github.com/microsoft/vscode/pull/176974 documents editor and contribution boundaries but does not settle the current product contract. Preserve existing runCommands and single-command behavior; macro recording, undo grouping, per-command conditions, and individual command failures are not automatically part of this work.
- **Open decisions:**
  - What first-class JSON contract should be supported beyond runCommands: the requested array-valued command field, a separate sequence field, or another user-facing representation?
  - How should command sequences appear and be edited in Keyboard Shortcuts, and should the same contract support extension-contributed bindings?
