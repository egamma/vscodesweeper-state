# Issue #209166 — Notebook>Outline: Show Code Cell Markdown

[https://github.com/microsoft/vscode/issues/209166](https://github.com/microsoft/vscode/issues/209166)

## Summary

The requested capability remains missing: notebook outline entries come from cell source and code symbols, not Markdown generated in cell outputs. Keep this accepted Backlog request open; the existing settings do not cover it, and no verified older canonical was found.

## Change summary

Include headings from Markdown generated by code-cell execution in the notebook Outline.

## Best solution

Support generated Markdown headings in the core notebook outline, with defined behavior for hierarchy, navigation, and updates when outputs change or are cleared. Preserve the existing source-heading and code-symbol behavior.

## Evidence

- **Current capability gap:** In src/vs/workbench/contrib/notebook/browser/viewModel/notebookOutlineEntryFactory.ts, NotebookOutlineEntryFactory.getOutlineEntries parses headings only when cell.cellKind is CellKind.Markup, using cell.getText(). Code cells contribute their source preview and cached document symbols; their output Markdown is not inspected.
- **Existing settings do not satisfy the request:** src/vs/workbench/contrib/notebook/browser/contrib/outline/notebookOutline.ts registers notebook.outline.showMarkdownHeadersOnly, notebook.outline.showCodeCells, and notebook.outline.showCodeCellSymbols. These filter source-derived entries; enabling code cells or their symbols does not extract headings from outputs.
- **Output-update boundary:** NotebookOutline.initializeOutline in src/vs/workbench/contrib/notebook/browser/contrib/outline/notebookOutline.ts listens for ChangeCellContent, ChangeCellInternalMetadata, Move, and ModelChange to recompute entries. Its content-change filter does not include output-change events, so supporting dynamic headings also requires considering output lifecycle updates.
