# Issue #287715 — Ability to add Copilot-targeted comments on diffs

[https://github.com/microsoft/vscode/issues/287715](https://github.com/microsoft/vscode/issues/287715)

## Summary

Keep open: the classic Copilot edit-hunk toolbar still lacks the requested targeted-feedback action, and the linked implementation PR was closed without merging. Existing selection attachments and Agents-window feedback provide related capabilities, but do not establish completion of this team-authored request.

## Change summary

Allow users to send Copilot feedback about a specific generated change directly from its diff-hunk toolbar, with the relevant code context attached automatically.

## Best solution

Provide a hunk-targeted feedback entry point in the chat-editing toolbar that carries the selected change into the associated conversation. Preserve existing selection attachments and distinguish this classic-workbench workflow from the Agents-window feedback implementation.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts`, `src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts`, `src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts`, `src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts`
- **Validation:** Have Copilot generate multiple separated hunks, invoke the new feedback entry point on one hunk without manually selecting code, and verify that the associated conversation receives context identifying that change. Repeat for a deletion-only hunk and confirm that existing Keep, Undo, Toggle Diff, and Add Selection to Chat behavior remains unchanged.
- **Behavior:**

  > Users reviewing Copilot-generated edits should be able to target feedback at one particular change directly from its hunk toolbar, without manually describing its location or selecting its code. The resulting conversation must receive enough context to identify that change among multiple edits. Acceptance should cover ordinary modifications and deletion-only changes while preserving existing review controls.
- **Trace:**

  > The classic workbench hunk menu is registered in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingEditorActions.ts and currently offers Keep/Undo and Toggle Diff, but no feedback attachment action. DiffHunkWidget in src/vs/workbench/contrib/chat/browser/chatEditing/chatEditingCodeEditorIntegration.ts holds the change mapping, while IModifiedFileEntryChangeHunk in src/vs/workbench/contrib/chat/common/editing/chatEditingService.ts exposes only accept and reject. AttachSelectionToChatAction in src/vs/workbench/contrib/chat/browser/actions/chatContextActions.ts demonstrates existing file-range attachments but requires manual selection. https://github.com/microsoft/vscode/pull/288378 attempted a toolbar attachment implementation and was closed without merging; its description is a design lead, not evidence of shipped behavior. Agents-window feedback is separate and must not be mistaken for coverage of the classic toolbar. The remaining product uncertainty is the feedback/context contract, particularly whether identifying only the modified range adequately represents a deleted change.
- **Open decisions:**
  - Should the toolbar action attach the hunk to the existing chat input for a follow-up message, or open an inline comment composer?
  - Should the attached context contain the original and modified diff, including deleted text, or only a reference to the modified file range?
