# Issue #328110 — tree-sitter PowerShell grammar cannot parse ~8% of realistic agent commands, blocking auto-approve suggestions

[https://github.com/microsoft/vscode/issues/328110](https://github.com/microsoft/vscode/issues/328110)

## Summary

Well-diagnosed, still-open gap: traced in the current source that the PowerShell parse-error gate (`shouldRequireConfirmationForAutoApproveParse`) blocks auto-approve for any `hasError` parse, and the only existing workaround (`maskPwshFlagEquals` in treeSitterCommandParser.ts) masks `--flag=value` only, not the bare `--` separator or `./path`-at-command-position cases this issue reports — no fix has landed for either trigger.

## Change summary

The bundled tree-sitter PowerShell grammar fails to parse ~8% of realistic agent command lines (bare `--` separator, `./path` at command position), so those commands get no auto-approve option at all in the terminal confirmation UI.

## Best solution

Extend the existing `maskPwshFlagEquals`-style regex workaround in treeSitterCommandParser.ts (and the parallel logic in commandAutoApprover.ts) to also neutralize a bare `--` separator and leading `./path` tokens before parsing, matching the precedent set for issue #294010 — or file/track the real grammar fix upstream in tree-sitter-powershell if that path is preferred.
