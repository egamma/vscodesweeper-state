# Issue #328828 — Allow distrusting copilot extension to revoke its access to Github Copilot cloud models

[https://github.com/microsoft/vscode/issues/328828](https://github.com/microsoft/vscode/issues/328828)

## Summary

Confirmed in source: extensions listed in product.json's trustedExtensionAuthAccess (which includes Copilot Chat) are always marked `trusted: true` and rendered disabled in the 'Manage Trusted Extensions' picker, so a signed-in user genuinely cannot revoke just Copilot's access to their GitHub account without signing out entirely — a real, unaddressed gap.

## Change summary

Allow users to revoke a first-party/Microsoft-trusted extension's (e.g. Copilot Chat) access to an authentication account without fully signing out of that account.

## Best solution

Extend the account/extension trust model (authenticationAccessService.ts, manageTrustedExtensionsForAccountAction.ts) so hardcoded product.json trust can be user-overridden per-extension, letting Copilot lose GitHub session access while other GitHub-authenticated extensions keep it.

## Evidence

- **trust source:** src/vs/workbench/services/authentication/browser/authenticationAccessService.ts reads `productService.trustedExtensionAuthAccess` and marks matching extensions `trusted: true`, always merging them into the allow-list regardless of user preference.
- **UI disabled for trusted extensions:** src/vs/workbench/contrib/authentication/browser/actions/manageTrustedExtensionsForAccountAction.ts sets `disabled = true` and a 'trusted by Microsoft' tooltip whenever `extension.trusted` is true, so the picker item can't be unchecked — matching the reporter's screenshot.
- **sign-out is account-scoped, not extension-scoped:** src/vs/workbench/browser/parts/globalCompositeBar.ts only exposes '_signOutOfAccount' per account/provider, with no per-extension detach, confirming there's no existing path to keep the GitHub account signed in for other extensions while cutting off Copilot alone.
- **related but distinct issue:** https://github.com/microsoft/vscode/issues/324310 is about BYOK being wrongly blocked by GitHub sign-in without a Copilot entitlement — a different bug in BYOKContrib gating logic, not a duplicate of this trust-revocation request.
