# Issue #197772 — About menu shortcuts

[https://github.com/microsoft/vscode/issues/197772](https://github.com/microsoft/vscode/issues/197772)

## Summary

The Spanish menu mnemonic collisions remain present in current translations, and the custom menu bar still lets the later menu overwrite the earlier shortcut. Keep this accepted localization bug open; the maintainers should settle whether mnemonic assignments remain locale-defined or become runtime-generated.

## Change summary

Spanish Alt+A and Alt+E menu shortcuts open Help and Run instead of uniquely addressing File and Edit.

## Best solution

Provide distinct, correctly advertised Spanish top-level menu mnemonics across native and custom menu bars. Resolve the thread's fixed-translation versus runtime-assignment direction before changing the user-visible shortcut contract.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/titlebar/menubar.contribution.ts`, `src/vs/workbench/browser/parts/titlebar/menubarControl.ts`, `src/vs/base/browser/ui/menu/menubar.ts`, `src/vs/workbench/contrib/debug/browser/debug.contribution.ts`
- **Validation:** On Windows with the Spanish language pack, check both native and custom title bars: hold Alt to inspect advertised mnemonics, then invoke every top-level menu shortcut. Each advertised shortcut must open its own menu, with File/Help and Edit/Run independently reachable. Repeat after reload and verify English menu shortcuts remain unchanged.
- **Behavior:**

  > Spanish File and Help currently share Alt+A, while Edit and Run share Alt+E; the later menu wins. Every top-level menu should advertise an unambiguous mnemonic that opens that menu in both native and custom title bars. Acceptance includes independently reaching all four affected menus, consistency between displayed and handled shortcuts, and unchanged English behavior.
- **Trace:**

  > The current Spanish resource at https://github.com/microsoft/vscode-loc/blob/main/i18n/vscode-language-pack-es/translations/main.i18n.json contains both duplicate assignments. In this checkout, menubar.contribution.ts registers localized mnemonicTitle values, menubarControl.ts consumes those titles, and MenuBar.push/registerMnemonic in src/vs/base/browser/ui/menu/menubar.ts reduces each letter to one menu index; the Alt handler opens that index. This conclusively explains the custom-menu symptom from source, while the native-menu symptom is confirmed in the maintainer discussion at https://github.com/microsoft/vscode/issues/197772#issuecomment-1865312981. Actual Spanish translation edits belong to the separate vscode-loc resource, not an invented translation file here. Preserve ordinary command keybindings and unrelated submenu behavior. The uncertainty is the user-visible assignment policy, not whether the current collisions exist.
- **Open decisions:**
  - Should top-level mnemonics remain stable, explicitly assigned shortcuts per locale, or be generated at runtime with shortcuts that may change when the available menu set changes?
