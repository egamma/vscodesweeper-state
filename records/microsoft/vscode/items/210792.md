# Issue #210792 — Persistent error : Could not find pty on pty host

[https://github.com/microsoft/vscode/issues/210792](https://github.com/microsoft/vscode/issues/210792)

## Summary

Legitimate open bug with 19 upvotes and reports spanning April 2024 through November 2025. The race condition in pty lifecycle management (pty removed from the map on process exit while pending RPC calls like updateTitle/updateIcon still reference it) remains unaddressed on main. The `confirmation-pending` label is outdated given the volume of independent confirmations. Keeping open — no fix commit exists.

## Change summary

Remote SSH sessions throw 'Could not find pty on pty host' errors due to a race between pty process exit cleanup and pending RPC calls (updateTitle, updateIcon), causing extension activation failures and disconnects.

## Best solution

The race is in `src/vs/platform/terminal/node/ptyService.ts`: `onProcessExit` deletes the pty from `_ptys` (line 349) while in-flight RPC calls to `updateTitle`/`updateIcon` (lines 378–384) still reference the now-gone id via `_throwIfNoPty`. The fix should either guard those RPC methods to silently return when the pty is already gone (the title/icon update is harmless to skip on a dead process), or deferred-delete the pty entry until pending calls drain. The `confirmation-pending` label should be removed given the many independent confirmations.
