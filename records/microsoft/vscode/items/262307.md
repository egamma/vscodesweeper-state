This clears the re-review requirement of an older canonical reporting the same symptom in the same surface, rather than merely related ranking work.
- **Current source path:** src/vs/workbench/contrib/search/browser/anythingQuickAccess.ts:464-468 sorts file results with compareItemsByFuzzyScore. In src/vs/base/common/fuzzyScorer.ts, prepareQuery splits Api Adm Testin into independent pieces; doScoreItemFuzzy enables filename preference because the query contains no path separator; doScoreItemFuzzyMultiple adds each piece's score. doScoreItemFuzzySingle assigns filename matches base scores of 65536 or 131072, while description/path matches receive only the character score. Consequently, weaker filename matches for multiple pieces can outweigh Testing.php's filename-prefix match plus its strong Api/Adm directory matches.
- **Workaround is not resolution:** The current scorer disables filename-only preference when the query contains a path separator. The canonical discussion recommends slash-separated queries at https://github.com/microsoft/vscode/issues/25925#issuecomment-2550449979, but the reporter explains at https://github.com/microsoft/vscode/issues/25925#issuecomment-2550459964 that this does not resolve the inconsistent ranking of space-separated queries.
