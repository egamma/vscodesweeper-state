# Issue #336200 — Renderer OOM in JSON.stringify / serializeRequestArguments when invoking agent with large chat history

[https://github.com/microsoft/vscode/issues/336200](https://github.com/microsoft/vscode/issues/336200)

## Summary

Well-documented crash-dump analysis with a traced code path: chat history is forwarded to `$invokeAgent` and serialized via `JSON.stringify`/`serializeRequestArguments` with no size bound, and a ~500MB session with multi-megabyte tool results can exhaust the V8 cage. Real, unrouted bug — should go to the chat/RPC area owners.

## Change summary

A renderer can OOM and crash when invoking a chat agent with an extremely large accumulated chat history, because the RPC argument serialization path (`serializeRequestArguments` / `JSON.stringify`) has no size bound or streaming/chunking for large history payloads.

## Best solution

Bound or externalize large chat-agent invocation history before RPC serialization — e.g. cap/truncate `result.metadata` and stale tool-result content in `getHistoryEntriesFromModel` (src/vs/workbench/contrib/chat/common/chatService/chatServiceImpl.ts) and/or make `MessageIO.serializeRequestArguments` (src/vs/workbench/services/extensions/common/rpcProtocol.ts) resilient to oversized payloads rather than a single unbounded `JSON.stringify` call.
