# Issue #310807 — Feature Request: Allow user prompt files / skills / custom instructions to drive the SCM "Review Changes" button

[https://github.com/microsoft/vscode/issues/310807](https://github.com/microsoft/vscode/issues/310807)

## Summary

A real customization gap remains: current SCM review consumes only a limited instruction subset and provides no way to bind prompt files or skills. The older related issues cover instruction discovery or mode filtering but not this request's full scope, so the re-reviewed item should remain open for a product decision.

## Change summary

Let users bind prompt files, instruction files, or skills to the SCM staged, unstaged, aggregate, and per-file review commands.

## Best solution

Define a single review-customization contract used consistently by every SCM review entry point, with deterministic review-specific instructions and an explicit policy for prompt and skill selection. Coordinate it with the broader mode-filtering design in https://github.com/microsoft/vscode/issues/260672 without collapsing this broader artifact-binding request into the narrower instruction issues.

## Plan brief

- **Likely files:** `extensions/copilot/src/extension/review/node/githubReviewAgent.ts`, `extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts`, `extensions/copilot/package.json`, `extensions/copilot/src/extension/review/node/test/githubReviewAgent.spec.ts`
- **Validation:** Extend the githubReviewAgent unit tests to verify that the chosen customization is included for staged/unstaged diff review and per-file review, while unrelated instructions or skills are excluded; retain coverage for existing copilot-instructions.md and reviewSelection.instructions behavior.
- **Behavior:**

  > Every SCM code-review entry point should apply the review customization selected by the user, including aggregate, staged, unstaged, and per-file reviews. Project instruction applicability must remain deterministic for the reviewed files, and existing copilot-instructions.md behavior must continue to work. Prompt or skill bindings must not silently affect ordinary chat sessions or unrelated commands.
- **Trace:**

  > The SCM commands registered in extensions/copilot/src/extension/inlineChat/vscode-node/inlineChatCommands.ts create ReviewSession, which reaches fetchComments in extensions/copilot/src/extension/review/node/githubReviewAgent.ts. That path serializes review inputs and coding-guideline references, but loadCustomInstructions only pulls getAgentInstructions() plus legacy settings; getAgentInstructions() in extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts only discovers the two copilot-instructions.md locations. The customization service separately recognizes instruction locations and skills, but the review pipeline does not consume those collections or expose a command binding. Keep the existing review transport, change collection, and ordinary chat customization semantics outside scope. Related design records are https://github.com/microsoft/vscode/issues/299447 and https://github.com/microsoft/vscode/issues/260672.
- **Open decisions:**
  - Should review customization be selected through command-specific configuration, through generalized instruction metadata such as applyToMode, or through an invocation-time picker?
  - When a skill is bound to code review, should its full skill workflow and supporting resources be available, or should only its textual review guidance be sent as coding guidelines?

## Evidence

- **current source gap:** extensions/copilot/src/extension/review/node/githubReviewAgent.ts calls loadCustomInstructions for SCM reviews, but that function only reads getAgentInstructions() and legacy instruction settings; it has no prompt-file or skill binding path.
- **limited instruction discovery:** extensions/copilot/src/platform/customInstructions/common/customInstructionsService.ts implements getAgentInstructions() using workspace .github/copilot-instructions.md and personal ~/.copilot/copilot-instructions.md only, despite the service separately knowing about skills and external instruction locations.
- **existing partial configuration:** extensions/copilot/package.json contributes github.copilot.chat.reviewSelection.instructions, but githubReviewAgent.ts applies CodeFeedbackInstructions only to selection reviews; diff-based staged, unstaged, aggregate, and per-file reviews instead receive CodeGenerationInstructions.
- **related narrower issue:** https://github.com/microsoft/vscode/issues/299447 is older and open, but it specifically tracks automatic discovery of .github/instructions/*.instructions.md. It does not own prompt-file or skill binding, so it cannot absorb this re-reviewed request.
- **related design discussion:** https://github.com/microsoft/vscode/issues/260672 is older and open; its maintainer discussion establishes a need for deterministic code-review instruction selection, but its proposed applyToMode contract does not cover binding prompt files or skills to SCM review commands.
