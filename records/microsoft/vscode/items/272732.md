## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParser.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileParserV2.ts`, `src/vs/workbench/contrib/chat/common/promptSyntax/promptFileVariables.ts`, `src/vs/workbench/contrib/chat/test/common/promptSyntax/promptFileParser.test.ts`
- **Validation:** Add parser/resolution tests showing that a declared `${{ var.VAR }}` in an `.agent.md` body resolves to its configured value, while undefined variables follow the chosen contract and existing prompt variables remain unchanged.
- **Behavior:**

  > An `.agent.md` body can reference supported variables using `${{ var.VAR }}` and receives the resolved value when the agent definition is loaded. Undefined variables produce a deterministic, documented result rather than being silently invented. Existing prompt-file variables and agent files without substitutions remain unchanged. Acceptance should cover successful resolution, missing values, and any approved environment or input namespace.
- **Trace:**

  > The request belongs to the existing chat-customizations path and is already labeled `chat-customizations`. Relevant parsing and variable-resolution surfaces are under `src/vs/workbench/contrib/chat/common/promptSyntax/`, including `promptFileParser.ts`, `promptFileParserV2.ts`, and `promptFileVariables.ts`, with parser coverage under `src/vs/workbench/contrib/chat/test/common/promptSyntax/`. The review establishes the requested agent-body syntax but not its declaration source, namespace set, resolution lifecycle, or missing-value semantics. Keep the change scoped to customization parsing/resolution; do not rely on the model running shell commands or guessing values, as the issue discussion identifies that as incidental model behavior rather than support for the feature.
- **Open decisions:**
  - Where are `var` values declared and at what scope are they available to an agent file?
  - Which namespaces are part of the public contract: declared variables only, environment variables, interactive input variables, or a defined subset?
  - What user-visible behavior should occur when a referenced variable is undefined or unavailable?
  - Are substitutions resolved once when the agent is loaded or for each invocation?
