# Issue #332352 — Agents: Disconnecting tunnel leaves /agents stuck on "No Host" after reload

[https://github.com/microsoft/vscode/issues/332352](https://github.com/microsoft/vscode/issues/332352)

## Summary

Confirmed on current main: the tunnel-agent-host entry list filters out any tunnel whose ID is in `autoConnectSuppressedTunnels`, so a manually-disconnected tunnel disappears entirely from the UI (not just from auto-connect) and `/agents` is stuck on 'No Host' even though the tunnel is online. A fix (#332527) was proposed by the reporter but closed unmerged without explanation, so the gap remains.

## Change summary

Disconnecting a tunnel in the Agents window persists it to `tunnelAgentHost.autoConnectSuppressedTunnels`, which is then used to filter the tunnel out of the available-hosts entry list entirely, leaving no way to manually reconnect after a reload.

## Best solution

Distinguish 'suppress auto-connect' from 'hide from entry list' in the tunnel entry derivation (browserTunnelAgentHostService.ts and webTunnelAgentHostService.ts both share the same `.filter(tunnel => !autoConnectSuppressedTunnels.includes(...))` pattern) so a suppressed tunnel still surfaces as a manually-selectable host; a maintainer should also weigh in on why the reporter's own PR #332527, which implemented roughly this approach, was closed instead of merged.
