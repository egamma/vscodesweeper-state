# Issue #332352 — Agents: Disconnecting tunnel leaves /agents stuck on "No Host" after reload

[https://github.com/microsoft/vscode/issues/332352](https://github.com/microsoft/vscode/issues/332352)

## Summary

Genuine bug, confirmed by tracing the source: `_getProviderTunnels()` in tunnelAgentHost.contribution.ts filters out any tunnel with an active auto-connect suppression, so after a Disconnect + reload the provider for that tunnel is never even created, leaving `/agents` stuck on 'No Host' with no manual-reconnect entry point.

## Change summary

Disconnecting a tunnel from the Agents view sets a persisted auto-connect suppression flag; after reloading `/agents`, the tunnel disappears entirely (shows 'No Host') instead of appearing as an available, manually-reconnectable host.

## Best solution

In `_getProviderTunnels()` (src/vs/sessions/contrib/providers/remoteAgentHost/browser/tunnelAgentHost.contribution.ts:210-212), stop excluding auto-connect-suppressed tunnels from the provider list — suppression should only gate the automatic `_connectTunnel(..., { userInitiated: false })` path (already handled at lines 333-336 and 930-932), not whether a provider/UI entry exists at all. Providers for suppressed tunnels should still be created and shown as available/disconnected so the user can manually reconnect via `connectOnDemand`.
