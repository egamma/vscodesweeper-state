# Issue #309849 — Extension 'github.copilot-chat' is a built-in extension and not allowed to be updated in the current product quality 'insider'

[https://github.com/microsoft/vscode/issues/309849](https://github.com/microsoft/vscode/issues/309849)

## Summary

The failure path remains reproducible from source when Remote-SSH requests installation of the now-bundled Copilot Chat extension. This belongs with the VS Code-owned Remote Development family and should be moved to microsoft/vscode-remote-release rather than closed.

## Change summary

Connecting through Remote-SSH can fail after an update because server startup attempts to install the bundled github.copilot-chat extension and treats the intentional installation rejection as fatal.

## Best solution

Remote-SSH should avoid requesting installation of github.copilot-chat when the matching extension is already bundled, or otherwise ensure this expected rejection cannot prevent the remote extension host from starting. The built-in extension version guard should remain intact.

## Evidence

- **connection failure path:** src/vs/server/node/remoteExtensionsScanner.ts processes extensions supplied through the server's install-extension arguments and reports github.copilot-chat as failed when the built-in guard rejects it and no user-installed copy exists.
- **confirmed remote trigger and precedent:** https://github.com/microsoft/vscode/issues/313728#issuecomment-4386136512 identifies remote.SSH.defaultExtensions as a trigger for the same Remote-SSH connection failure after Copilot Chat became built in; multiple reporters confirmed that removing the entry restored connectivity.
- **guard is intentional:** https://github.com/microsoft/vscode/issues/313728#issuecomment-4852751591 confirms that rejecting independent installation or downgrade of the bundled github.copilot-chat version is by design, leaving Remote-SSH's handling of that rejection as the actionable defect.
