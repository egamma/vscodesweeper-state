# Issue #186043 — Support opening links in a new window from within webviews

[https://github.com/microsoft/vscode/issues/186043](https://github.com/microsoft/vscode/issues/186043)

## Summary

Keep open: current webview sandboxing still blocks the requested nested-frame link behavior, and the postMessage workaround does not cover unmodified third-party content. The maintainer's native-UI concerns and the reporter's subsequent clarification about confirmation-mediated external browsing need reconciliation before treating this accepted backlog request as declined.

## Change summary

Support target="_blank" and window.open links from embedded webview frames through VS Code's external-link confirmation flow without modifying the embedded site.

## Best solution

The webview owner should explicitly decide whether external-browser navigation from nested frames can use VS Code's existing link-opening safeguards without enabling arbitrary native dialogs or unrestricted popups. Preserve the sandbox boundary until that decision is settled; extension-controlled message passing remains a partial workaround, not fulfillment of this request.
