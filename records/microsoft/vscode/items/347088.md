# Issue #347088 — First impression of Inbox mode shows nothing

[https://github.com/microsoft/vscode/issues/347088](https://github.com/microsoft/vscode/issues/347088)

## Summary

Keep open for first-use UX design: historical sessions intentionally start in Done, but the current empty state does not explain that placement or how to resume triage. This team-authored feedback identifies a usability gap, not grounds for an as-designed close.

## Change summary

Make first-time Inbox Mode understandable when existing sessions, including work with draft PRs, initially appear under Done.

## Best solution

Provide discoverable first-use guidance explaining Inbox attention versus unfinished project work, historical placement in Done, and Return to Inbox. Decide whether historical sessions with draft PRs should retain the current initial placement before changing classification.

Verify that users can discover why sessions appear in Done and how to return one to Inbox without archiving it; verify keyboard access, reload behavior, and preservation of explicit triage. Add focused Sessions view/list tests for the agreed first-use presentation.
- **Behavior:**

  > Selecting Inbox Mode for the first time with existing session history should explain the attention-oriented workflow even when the primary Inbox is empty. Users should understand that Done placement does not necessarily mean their PR or project work is finished, and should be able to discover how to return a session to Inbox. Existing sessions and organization must remain intact.
- **Trace:**

  > SessionsView.setGrouping in src/vs/workbench/contrib/sessions/browser/views/sessionsView.ts persists the grouping and refreshes the list without onboarding. The desktop empty primary region in src/vs/workbench/contrib/sessions/browser/views/sessionsList.ts displays 'Your inbox is clear'. Historical completion originates in InboxNotificationsService and becomes done through SessionsListModelService.getInboxState; src/vs/sessions/SESSIONS_LIST.md and https://github.com/microsoft/vscode/issues/346666 explicitly establish this initial-placement behavior. Accessible help already describes it and Return to Inbox, so the remaining gap is contextual discovery, with uncertainty over whether draft-PR history should receive different placement. Preserve explicit triage, archival semantics, and organization when switching modes; do not treat the original Inbox implementation as a fix for this later feedback.
- **Open decisions:**
  - Should first-use explanation appear automatically on entering Inbox Mode, or remain persistently discoverable in its empty state?
  - Should historical sessions with open draft PRs still start in Done with clearer explanation, or should that work receive different initial placement?
