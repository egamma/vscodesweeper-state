# Issue #221571 — Wrong syntax coloring in PHP with string 'AND ['

[https://github.com/microsoft/vscode/issues/221571](https://github.com/microsoft/vscode/issues/221571)

## Summary

Still reproduces on current main. The PHP grammar's embedded SQL detection (`sql-string-single-quoted` / `sql-string-double-quoted` patterns) triggers on any string beginning with `AND` (plus other SQL keywords), incorrectly treating ordinary PHP strings as SQL and breaking syntax highlighting for the rest of the file.

## Change summary

PHP strings starting with SQL keywords like `AND` are incorrectly highlighted as embedded SQL, breaking syntax coloring for the remainder of the file.

## Best solution

Fix the embedded SQL detection heuristic in the upstream grammar (KapitanOczywisty/language-php). The `begin` pattern for `sql-string-single-quoted` and `sql-string-double-quoted` in `extensions/php/syntaxes/php.tmLanguage.json` (lines 3234, 3308) includes `AND` and `WITH` as trigger keywords, which are far too common in regular PHP strings. Removing `AND` and `WITH` from the lookahead — or requiring a stronger SQL-statement signal (e.g. `SELECT`, `INSERT`, `UPDATE`, `DELETE` only) — would fix the false positives. The fix should land upstream at https://github.com/KapitanOczywisty/language-php and then be pulled in via a grammar update.

## Evidence

- **root cause in grammar:** extensions/php/syntaxes/php.tmLanguage.json lines 3234 and 3308: the `begin` patterns for `sql-string-single-quoted` and `sql-string-double-quoted` include `AND` in the keyword list `(SELECT|INSERT|UPDATE|DELETE|CREATE|REPLACE|ALTER|AND|WITH)`, so any string starting with ` AND` is treated as embedded SQL.
- **still present on main:** The latest grammar update (commit 84f7ab5aa01) does not change these patterns; `AND` is still in the SQL trigger list on current main.
- **upstream grammar source:** The PHP grammar is sourced from https://github.com/KapitanOczywisty/language-php (cgmanifest.json, commit cd607a522b79c457fe78bf7a1b04511d1c49f693).
- **upstream issues:** Multiple related issues exist upstream: KapitanOczywisty/language-php#8 (closed, partial fix for `N`-ending strings), #11, #21, #22, #23, #31 — all related to embedded SQL detection being too aggressive.
