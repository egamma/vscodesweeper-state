# Issue #221571 — Wrong syntax coloring in PHP with string 'AND ['

[https://github.com/microsoft/vscode/issues/221571](https://github.com/microsoft/vscode/issues/221571)

## Summary

Keep open as an upstream PHP grammar integration defect: the current bundled rules still allow SQL bracket scopes to swallow a PHP string's closing quote. The supplied examples are sufficient, and neither the older HTML embedding issue nor the newer PHP report justifies closing this re-reviewed issue as a duplicate.

## Change summary

Prevent embedded SQL highlighting triggered by leading AND from consuming PHP string delimiters and corrupting subsequent PHP highlighting.

## Best solution

Correct PHP/SQL embedding boundaries in the upstream PHP grammar and incorporate the correction into VS Code's bundled grammar. Preserve intentional SQL highlighting and PHP interpolation while ensuring SQL constructs cannot extend beyond their containing PHP string.

## Evidence

- **Current trigger:** extensions/php/syntaxes/php.tmLanguage.json:3233-3359 defines sql-string-double-quoted and sql-string-single-quoted with a leading-keyword lookahead containing AND followed by a word boundary. The strings repository at lines 3426-3447 selects these before ordinary PHP string rules. This explains why ' AND [' enters SQL mode while ' ANDRE [' and 'abc AND abc [' do not.
- **Current delimiter escape:** Both PHP SQL-string rules include source.sql. In extensions/sql/syntaxes/sql.tmLanguage.json:15-35, '[' opens a text.bracketed scope whose end is only ']'; it has no PHP quote boundary. Consequently, in the supplied '$value = \' AND [\' . $test;' example, the PHP closing quote is consumed inside the nested SQL scope. This conclusion comes from source inspection, not an executed tokenizer test.
- **Upstream ownership:** extensions/php/syntaxes/php.tmLanguage.json:2-7 identifies https://github.com/KapitanOczywisty/language-php as the grammar source, currently at d94fd6b7dff1613d34bc0d36328f9982e65bd545, and directs grammar corrections upstream. extensions/php/build/update-grammar.mjs imports grammars/php.cson from that repository; extensions/php/package.json registers the grammar as built-in PHP support.
- **Discussion and precedent:** The supplied discussion includes a maintainer diagnosis of embedded SQL in PHP strings and another reporter's concrete example of highlighting leaking into subsequent PHP. An earlier bracket report, https://github.com/microsoft/vscode/issues/195149, received the same upstream-grammar diagnosis at https://github.com/microsoft/vscode/issues/195149#issuecomment-1782135970; that issue is closed and cannot serve as a duplicate canonical.
- **Older canonical checked:** https://github.com/microsoft/vscode/issues/20488 is open, but its report concerns CSS escaping HTML style boundaries and its discussion addresses general TextMate embedding semantics. It does not establish the same PHP AND/string-bracket symptom required for a duplicate close of this re-reviewed item.
- **Newer related report:** https://github.com/microsoft/vscode/issues/332897 is open and reports PHP SQL highlighting leaking after an unmatched '[' on VS Code 1.136.0-insider. It corroborates the bracket-boundary problem, but was created on 2026-08-27, after this issue, and therefore cannot be its duplicate canonical under the re-review rules.
