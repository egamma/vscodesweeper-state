# Issue #333794 — Codex provider blocks creating a new session without a worktree

[https://github.com/microsoft/vscode/issues/333794](https://github.com/microsoft/vscode/issues/333794)

## Summary

Assigned to milestone 1.137.0, so this is barred from any close regardless of other evidence; the underlying report also checks out against current source, so it should stay open for a maintainer/engineering fix rather than a triage close.

## Change summary

When the active provider is Codex, the `create_session` server tool rejects a request to create a session without a worktree, and the fallback `get_current_session`/list-sessions path also fails because Codex can't enumerate its native session catalog, leaving the agent with no way to satisfy the request.

## Best solution

In src/vs/platform/agentHost/node/agentService.ts, the create_session/list_sessions server-tool path needs a Codex-specific fallback that doesn't depend on `_enumerateLegacyProviderSessions`/`ProviderCatalogUnavailableError` when no worktree isolation is requested — likely in the session-creation validation in shared/sessionServerTools.ts and the isolation-resolution logic in agentService.ts's `_resolveIsolationConfig`/`createSession` path.
