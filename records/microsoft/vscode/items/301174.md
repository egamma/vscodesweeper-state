# Issue #301174 — Add #chatHistory tool `vscode-copilot-chat` so the agent can use, search, ground, get insights from prior chat sessions

[https://github.com/microsoft/vscode/issues/301174](https://github.com/microsoft/vscode/issues/301174)

## Summary

A real gap remains: VS Code has chat-session persistence and related history work, but the provided record does not establish an existing agent tool that searches prior local conversations. The request should remain open for a privacy, consent, and retrieval-design decision.

## Change summary

Add a user-invoked chat-history tool that searches local prior session transcripts and returns relevant excerpts as agent context.

## Best solution

Design a core, permission-aware retrieval capability over locally available session history, with explicit invocation, clear availability boundaries, bounded context disclosure, and behavior consistent with existing session persistence and history search.

## Plan brief

- **Likely files:** `extensions/copilot/package.json`
- **Validation:** Exercise a desktop agent session with several stored prior chats and verify that an explicit history invocation returns relevant excerpts, excludes unavailable session types, respects the chosen consent and retention boundaries, and does not expose history implicitly.
- **Behavior:**

  > Users can explicitly ask a local VS Code agent to find prior chat work by topic, file, commit, PR, or decision and receive grounded excerpts from eligible stored sessions. Prior history is not injected without the chosen user-consent mechanism, unavailable session types do not advertise a nonfunctional tool, and results disclose enough provenance to identify the source session. Acceptance should cover relevant retrieval, no-match behavior, access boundaries, and exclusion of unsupported remote or cloud histories.
- **Trace:**

  > The request targets persisted local chat transcripts and proposes exposing retrieval as a language-model tool through the Copilot contribution surface under extensions/copilot. Human-facing history search in https://github.com/microsoft/vscode/issues/254027 is related but does not satisfy agent-consumable retrieval. The newer orphan-recovery report https://github.com/microsoft/vscode/issues/305818 addresses discoverability after workspace changes, not semantic grounding from prior conversations. The boundary must remain prior-chat retrieval: do not turn this into automatic cross-session memory or a hosted identity service.
- **Open decisions:**
  - Must every history lookup be explicitly invoked by the user, or may the agent request access subject to a permission prompt?
  - Which locally persisted session types and retention windows are eligible for search?
  - What source-session provenance and redaction controls must accompany excerpts returned to the model?
