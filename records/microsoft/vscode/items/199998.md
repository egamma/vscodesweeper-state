## Evidence

- **Current source:** src/vs/base/browser/dom.ts:2016-2018 unconditionally calls ModifierKeyEmitter.resetKeyStatus() on window blur; resetKeyStatus and doResetKeyStatus clear all modifier flags and notify listeners. Entering the preview iframe therefore discards the held Alt state described in the report.
- **Webview event forwarding:** src/vs/workbench/contrib/webview/browser/webviewElement.ts:260-265 forwards did-keydown/did-keyup through handleKeyEvent; lines 756-771 redispatch those events to the host window. Subsequent keyboard events can restore modifier state, but entering the preview while continuously holding Alt supplies no new keydown to undo the blur reset.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/327497 is OPEN, has no mergedAt timestamp, and explicitly declares Fixes #199998. It changes dom.ts and dom.test.ts to distinguish iframe focus from application focus loss. Its author reports manually verifying repeated Alt-click source/preview toggling on macOS; this is supporting PR evidence, not an execution performed during this review.
