# Issue #210332 — Git - Lose "File History" after Git mv

[https://github.com/microsoft/vscode/issues/210332](https://github.com/microsoft/vscode/issues/210332)

## Summary

Keep this accepted Backlog request open: Timeline already follows committed renames, but rename support is incomplete. The report describes missing history entries, whereas the verified related issues describe entries whose historical contents cannot be opened; that distinction prevents a confident duplicate or completed close.

## Change summary

Preserve access to a file's Git history after moving or renaming it with git mv.

## Best solution

Make built-in Git Timeline history usable across file moves and renames. First establish whether this report concerns missing entries before committing the move or inaccessible historical contents afterward; the latter is already tracked by https://github.com/microsoft/vscode/issues/205244.

## Evidence

- **Existing capability:** extensions/git/src/timelineProvider.ts:140-150 requests logFile with follow: true. extensions/git/src/git.ts:1527-1564 translates this into git log --follow against uri.fsPath. extensions/git/package.json:3965-3989 exposes date, author, and uncommitted-change Timeline settings, not a follow-renames filter.
- **Capability predates this report:** https://github.com/microsoft/vscode/pull/187174 merged on 2023-12-08 and introduced following committed renames, before this report's 2024-04-14 creation. A maintainer confirmed the original capability in https://github.com/microsoft/vscode/issues/133606#issuecomment-1847156234. This does not establish that the later report was resolved.
- **Remaining source limitation:** extensions/git/src/repository.ts:1170-1172 forwards the selected URI unchanged to logFile; the Git log query uses that current path without resolving an uncommitted rename back to its committed path. Separately, extensions/git/src/commands.ts:4804-4824 constructs both historical diff URIs from the same current URI, so following commit history does not provide rename-aware historical content resolution.
- **Verified related issues, not full-scope canonicals:** https://github.com/microsoft/vscode/issues/205244 is open and explicitly reports visible pre-rename entries with blank diffs. https://github.com/microsoft/vscode/issues/275318 and https://github.com/microsoft/vscode/issues/309877 are also open and describe historical file-opening failures. The confirmed move reproduction at https://github.com/microsoft/vscode/issues/275318#issuecomment-4994064078 supports that remaining defect, but does not confirm this report's missing-entry symptom.
- **Report's external reference:** https://github.com/gitkraken/vscode-gitlens/issues/2828 concerns missing file-history entries and interactions between all-branches filtering and following renames. Its maintainer describes the GitLens change at https://github.com/gitkraken/vscode-gitlens/issues/2828#issuecomment-1760432288. That extension-specific fix is context, not evidence of a VS Code fix.
- **Conservative boundary:** The issue is classified feature-request and accepted into Backlog. No runtime reproduction was performed in the read-only checkout, and neither the report nor its discussion specifies whether the move was committed. The canonical search found related historical-content failures, not a verified canonical covering the complete missing-history claim.
