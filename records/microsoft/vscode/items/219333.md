# Issue #219333 — Formatting notebook cells with Black leads to random blank lines

[https://github.com/microsoft/vscode/issues/219333](https://github.com/microsoft/vscode/issues/219333)

## Summary

Still open and unfixed — the notebook formatting infrastructure may be passing cell content to the formatter in a way that causes Black to apply module-level PEP 8 spacing (2 blank lines before top-level functions). Issue #235768 was closed as a duplicate of this one, confirming ongoing relevance. No fix commit references this issue.

## Change summary

Formatting notebook cells with Black on save adds an extra blank line between comments and function definitions, despite Black CLI reporting the file as unchanged.

## Best solution

Investigate whether the notebook formatting save participant or cell model introduces trailing/leading newlines in the content sent to the formatter provider, causing Black to interpret cell content differently than a standalone `.py` file. The fix likely lives in `src/vs/workbench/contrib/notebook/browser/contrib/saveParticipants/saveParticipants.ts` or in how cell URIs resolve their text model content. If the root cause is in the Black Formatter extension's notebook cell handling, move the issue to `microsoft/vscode-black-formatter`.
