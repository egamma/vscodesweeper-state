# Issue #329724 — Expose large shell output artifact paths through the Copilot SDK

[https://github.com/microsoft/vscode/issues/329724](https://github.com/microsoft/vscode/issues/329724)

## Summary

Confirmed via checkout: the interim fix (PR #329725) shipped and only reads the large-output path out of tool completion display text, leaving an explicit TODO in the code for the exact SDK gap this issue describes — the request is real and still open.

## Change summary

Add a structured artifact path/URI field to the shell_exit wire contract and generated SDK types so VS Code doesn't have to parse the large-output file location out of prose, and update Agent Host to consume it.

## Best solution

Land the SDK-side wire contract change (shell_exit gains an artifact path/URI with lifetime semantics), then update src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/stateToProgressAdapter.ts (getTerminalOutput, around the TODO at line 1299) and src/vs/platform/agentHost/node/copilot/mapSessionEvents.ts (appendSdkToolResultContent's shell_exit handling, which currently only maps exitCode/outputPreview/outputTruncated) to read the structured field instead of stripLegacyTerminalExitMarkers-style text parsing.
