# Issue #327879 — Model picker should surface when an enterprise-managed default model overrides user selection

[https://github.com/microsoft/vscode/issues/327879](https://github.com/microsoft/vscode/issues/327879)

## Summary

A real UX gap remains: managed defaults intentionally seed new conversations, but the model picker does not explain that policy-driven override. This team-authored item should remain open for model-picker polish.

## Change summary

Indicate when enterprise policy chooses the default chat model instead of the user's remembered selection.

## Best solution

Detect when `chat.defaultModel` comes from policy and surface that state in the picker button or menu with localized explanatory text, while preserving per-conversation model switching. The likely implementation belongs around `chatInputPart.ts` and `chatModelPicker.ts`.
