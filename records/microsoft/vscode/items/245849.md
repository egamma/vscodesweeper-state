# Issue #245849 — [folding] folding gets messed up after Copilot edits a file

[https://github.com/microsoft/vscode/issues/245849](https://github.com/microsoft/vscode/issues/245849)

## Summary

This remains a valid folding bug: bulk edits can leave tracked collapsed ranges out of sync with newly computed provider ranges. Reports across multiple languages, edit providers, operating systems, and current versions show that the issue is not limited to the original HTML/PHP scenario.

## Change summary

Copilot and other bulk-edit operations can leave folding markers and collapsed regions attached to incorrect lines until folding state is reset.

## Best solution

Make folding-state reconciliation discard or safely remap stale recovered ranges after bulk edits while preserving collapsed state for provider ranges that still represent the same code block.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/browser/foldingRanges.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`, `src/vs/editor/contrib/folding/test/browser/foldingRanges.test.ts`
- **Validation:** Extend the Folding Model tests with a folded range followed by a bulk edit that changes its provider boundary; run `scripts/test.sh --grep "Folding Model"` and verify that no stale folding marker remains while unchanged provider ranges retain their collapsed state.
- **Behavior:**

  > After Copilot or another bulk edit changes the structure of a folded document, every visible folding marker and hidden range must correspond to a folding range produced for the updated document. A collapsed block whose provider range remains logically valid should retain its collapsed state. A stale range must not fold unrelated lines or remain until the user toggles folding. Acceptance should cover a moved or replaced folded block and an unaffected folded block in the same document.
- **Trace:**

  > FoldingController.onDidChangeModelContent in src/vs/editor/contrib/folding/browser/folding.ts schedules fresh provider computation after edits. FoldingModel.update in src/vs/editor/contrib/folding/browser/foldingModel.ts reads the decorations for previously collapsed ranges and passes those tracked positions to FoldingRegions.sanitizeAndMerge in src/vs/editor/contrib/folding/browser/foldingRanges.ts. When a collapsed provider range no longer has the same start as a newly computed range, sanitizeAndMerge promotes it to FoldSource.recovered; recovered ranges can then survive and displace overlapping current provider ranges. Recreating FoldingModel by toggling folding clears that state, which matches the reported workaround. Preserve ordinary collapse-state continuity and explicit user-defined folding behavior; the uncertainty is limited to how provider ranges invalidated by structural bulk edits should be represented.
- **Open decisions:**
  - When a structural bulk edit removes or moves a collapsed provider range, should VS Code expand and discard that state immediately, or remap the collapse to a newly computed provider range when a reliable logical match can be established?

## Evidence

- **current source path:** src/vs/editor/contrib/folding/browser/folding.ts recomputes ranges after every model-content change, then FoldingModel.update in src/vs/editor/contrib/folding/browser/foldingModel.ts merges them with decorations tracking previously collapsed ranges.
- **stale-range mechanism:** FoldingRegions.sanitizeAndMerge in src/vs/editor/contrib/folding/browser/foldingRanges.ts converts a previously collapsed provider range with no matching new start line into FoldSource.recovered and lets it take precedence over overlapping provider ranges. The existing sanitizeAndMerge2/sanitizeAndMerge4 tests explicitly preserve this behavior.
- **workaround correspondence:** Toggling editor folding recreates FoldingModel through FoldingController.onModelChanged and therefore removes recovered ranges, matching the workaround confirmed by two commenters.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/231717 documents the analogous failure after a bulk indentation conversion; a maintainer attributed it to preserving existing folded ranges. That earlier report was declined when it appeared to be a single corner case, whereas this issue now contains independent reports involving Copilot, ChatGPT edits, HTML/PHP, PowerShell, and multiple platforms.

The older https://github.com/microsoft/vscode/issues/241344 reports the same Copilot-edit folding symptom but is closed, so there is no verified open older canonical suitable for a duplicate close under the re-review rule.
