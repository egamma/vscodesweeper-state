# Issue #311373 — Text Rendering in large files is broken

[https://github.com/microsoft/vscode/issues/311373](https://github.com/microsoft/vscode/issues/311373)

## Summary

The experimental editor GPU renderer still uses inconsistent vertical coordinates at large scroll offsets, explaining the disappearing text. Keep this open while the linked fix PR is reviewed; it has not merged.

## Change summary

Text disappears when scrolling far into a large file with experimental editor GPU acceleration enabled.

## Best solution

Review the large-scroll coordinate correction in https://github.com/microsoft/vscode/pull/340836 and confirm that text remains visible across scroll-origin transitions, including on the reported Windows configuration. Keep this issue open until the fix lands.

## Evidence

- **Reporter and independent confirmation:** In https://github.com/microsoft/vscode/issues/311373, the reporter confirms the failure on 1.116 and identifies 1.94 as the regression boundary. An independent commenter reports the same issue on Windows 11 with an AMD Radeon RX 9070 XT and isolates editor.experimentalGpuAcceleration.
- **Current-source coordinate mismatch:** src/vs/editor/common/viewLayout/linesLayout.ts reduces relativeVerticalOffset by bigNumbersDelta once the viewport passes 500,000 pixels. In src/vs/editor/browser/gpu/renderStrategy/viewportRenderStrategy.ts, update() derives glyph positions from those reduced offsets, but onScrollChanged() uploads the unreduced scrollTop. src/vs/editor/browser/gpu/renderStrategy/fullFileRenderStrategy.wgsl.ts subtracts that scroll offset when positioning glyphs, moving them outside the viewport after the origin changes. The full-file strategy also uploads unreduced scrollTop. This explains why the disappearance threshold varies with line height and file layout.
- **Open implementation candidate:** https://github.com/microsoft/vscode/pull/340836 is verified OPEN and explicitly references this issue as its large-scroll blanking target. Its proposed correction subtracts the same bigNumbersDelta from GPU scroll coordinates and invalidates full-file cached positions when the origin changes. The PR reports before/after large-file captures and regression checks, but those are contributor evidence, not checks executed during this read-only review.
- **Canonical search:** Searches for GPU scrolling, text disappearance, and large-file rendering found no verified canonical owning this exact defect. https://github.com/microsoft/vscode/issues/221145 is an open renderer-development umbrella, not the same defect. https://github.com/microsoft/vscode/issues/325040 describes zoom-triggered atlas exhaustion and black rectangles in a roughly 700-line file, a distinct reported trigger and failure mechanism.
