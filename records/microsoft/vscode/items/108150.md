# Issue #108150 — Inconsistencies with Trigger (full) completions when (incomplete) completions are already active

[https://github.com/microsoft/vscode/issues/108150](https://github.com/microsoft/vscode/issues/108150)

## Summary

Keep open for the suggest owner's decision on cross-provider retriggering after a completion session starts outside a word. The current source retains the distinction identified in the discussion; neither the predecessor's fix nor existing suggestion settings fully covers this case.

## Change summary

Allow ordinary IntelliSense providers to participate when typing a word after another provider has opened completions on whitespace or punctuation.

## Best solution

Define when entering a word from a non-word-triggered completion session should query additional providers, while preserving member-completion behavior after a dot. Validate that contract with isolated completion providers rather than depending on Kite.

- **Behavior:**

  > A provider can open suggestions on whitespace or punctuation before a word begins. The reporter wants ordinary IntelliSense suggestions to join when the following word is typed, without disabling those triggers or manually invoking suggestions. Acceptance must cover the reported space and '[' transitions and ensure that typing a member name after '.' does not introduce unrelated suggestions.
- **Trace:**

  > In src/vs/editor/contrib/suggest/browser/suggestModel.ts, _updateTriggerCharacters restricts the initial request to providers registered for the typed trigger. _onNewContext expands provider participation when the current word starts later than the initial context's word; starting a word at the same column instead reaches the incomplete-provider-only refresh path. The existing test for https://github.com/microsoft/vscode/issues/99504 begins on an existing word and does not exercise this boundary. The owner identified this distinction at https://github.com/microsoft/vscode/issues/108150#issuecomment-715266227 and explicitly warned about member completion after '.'. The remaining uncertainty is the intended observable rule distinguishing these contexts; do not broaden provider participation indiscriminately or change ordinary incomplete-list refresh semantics.
- **Open decisions:**
  - Which non-word-triggered sessions should query previously uninvolved providers when the first word character is typed, and which must remain restricted to preserve contextual completion such as member access after '.'?
