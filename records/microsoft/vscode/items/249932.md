# Issue #249932 — Disassembly Viewer: disassemble by specified function/line

[https://github.com/microsoft/vscode/issues/249932](https://github.com/microsoft/vscode/issues/249932)

## Summary

The requested function/source-line navigation remains missing: the editor command opens disassembly around the focused stack frame, not the selected source location. Older address-navigation requests cover related infrastructure, but not the same observable capability, so this accepted Backlog request should remain open.

## Change summary

Open disassembly for a selected function or source line and follow function targets from within disassembled instructions.

## Best solution

Support debugger-backed navigation from source functions and lines into their corresponding instructions, plus navigation to function targets inside disassembly. Establish the supported debugger contract and unsupported-target behavior before implementation; accepting a memory reference programmatically is useful infrastructure but does not alone satisfy the source-navigation request.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/debug/browser/debugEditorActions.ts`, `src/vs/workbench/contrib/debug/browser/disassemblyView.ts`
- **Validation:** With a supporting debug adapter stopped in function A, invoke disassembly on a call to and definition of function B, then on a source line inside B; verify navigation targets B and the best available corresponding instruction rather than A's program counter. Follow a function target from disassembly and verify the destination. Retest ordinary stack-frame navigation and explicitly exercise an unresolved target.
- **Behavior:**

  > Users should be able to open disassembly for a function selected in source, rather than always seeing the focused stack frame's instructions. Invoking the action on a line within a function should navigate near its corresponding instructions on a best-effort basis under optimization. Following a function target inside disassembly should navigate to that function. Existing stack-frame navigation must remain available, and unsupported or unresolved targets must not be mistaken for successful target navigation.
- **Trace:**

  > OpenDisassemblyViewAction in src/vs/workbench/contrib/debug/browser/debugEditorActions.ts opens a singleton editor without a source location or memory-reference argument. DisassemblyView in src/vs/workbench/contrib/debug/browser/disassemblyView.ts initializes from focusedInstructionReference and follows focused-stack-frame changes; its goToInstructionAndOffset method already handles supplied instruction references internally. InstructionRenderer displays instruction text without function-target links, while displayed source supports reverse navigation into source files. The unresolved boundary is how source locations and function targets become adapter-valid instruction references across debuggers; inspecting the existing view does not establish that contract. Preserve existing stack-frame behavior and opaque reference handling. Related address-entry work is tracked at https://github.com/microsoft/vscode/issues/175770 and https://github.com/microsoft/vscode/issues/129762, but address entry alone does not fulfill this request.
