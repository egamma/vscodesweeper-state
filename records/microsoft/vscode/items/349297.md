# Issue #349297 — Markdown files show error `link.no-such-file` for a link to an existing folder after a file inside that folder is deleted

[https://github.com/microsoft/vscode/issues/349297](https://github.com/microsoft/vscode/issues/349297)

## Summary

Keep open: current source still turns direct-child filesystem events into events for the linked folder itself. A maintainer independently confirmed the exact failure on Linux Insiders, complementing the Windows report.

## Change summary

Prevent deleting a linked folder's direct child from incorrectly marking the existing folder link as missing.

## Best solution

Ensure Markdown link watchers distinguish changes to the watched target from changes to its children, while preserving diagnostics updates when the target or an ancestor actually disappears or reappears.

## Evidence

- **Current watcher path:** extensions/markdown-language-features/src/client/fileWatchingManager.ts: FileWatcherManager.create uses RelativePattern(uri, '*') and registers callbacks directly. Those callbacks accept no event URI, so events for a linked directory's direct children are not distinguished from events for the target.
- **Incorrect protocol attribution:** extensions/markdown-language-features/src/client/client.ts: the fs_watcher_create handler's sendWatcherChange always sends { id, uri: params.uri, kind }.
