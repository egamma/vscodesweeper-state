# Issue #47976 — Feature: Settable "keyboard.chords.mode"

[https://github.com/microsoft/vscode/issues/47976](https://github.com/microsoft/vscode/issues/47976)

## Summary

A real accessibility-motivated configuration gap remains: current main has no global setting to disable or alter chord handling. Keep this Backlog request open for design discussion rather than closing it for age or limited votes.

## Change summary

Provide a configurable keyboard chord mode, including an option to disable chorded keybindings globally.

## Best solution

Design an accessible, application-scoped chord policy in the keybinding service, preserving the default behavior while offering an opt-out and documenting how it interacts with contributed keybindings.

## Evidence

- **current configuration:** src/vs/platform/keyboardLayout/common/keyboardConfig.ts registers only `keyboard.dispatch` and `keyboard.mapAltGrToCtrlAlt`; there is no chord-mode or global chord-disable setting.
- **current behavior:** src/vs/platform/keybinding/common/abstractKeybindingService.ts enters multi-chord mode whenever resolution returns `MoreChordsNeeded`, unconditionally consuming the first keypress.
- **partial workaround:** src/vs/platform/keybinding/common/keybindingResolver.ts supports removing individual default bindings through `-commandId` rules, but this does not provide the requested global policy and requires users to identify each conflicting binding.
- **related request:** https://github.com/microsoft/vscode/issues/140226 remains open and discusses dispatching a single-key binding after an incomplete chord, but it does not fully cover disabling chords or selecting the proposed interaction mode.
