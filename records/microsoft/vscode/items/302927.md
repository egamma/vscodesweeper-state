# Issue #302927 — To Do Tool items show unchecked on reload until you expand thinking block

[https://github.com/microsoft/vscode/issues/302927](https://github.com/microsoft/vscode/issues/302927)

## Summary

The defect remains source-reproducible on current main: restored todo state is populated only when its lazily grouped tool invocation is rendered, so a collapsed thinking block leaves the previously stored unchecked state visible until expansion.

## Change summary

After reloading a chat, completed todo items appear unchecked until the collapsed thinking block containing their tool result is expanded.

## Best solution

Restore the latest todo-list state from serialized response content independently of whether grouped thinking content has been expanded, while retaining lazy DOM rendering for the tool details.
