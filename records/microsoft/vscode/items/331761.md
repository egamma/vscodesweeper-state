# Issue #331761 — `workbench.action.editor.changeLanguageMode` silently falls back to Plain Text when invoked programmatically with a language id string argument

[https://github.com/microsoft/vscode/issues/331761](https://github.com/microsoft/vscode/issues/331761)

## Summary

Confirmed in source: when `workbench.action.editor.changeLanguageMode` is invoked with a string arg, the code builds a pick object with only a `label` set (no `id`), so `languageService.createById(pick.id)` receives `undefined` and silently falls back to Plain Text.

## Change summary

Programmatic invocation of workbench.action.editor.changeLanguageMode with a language id string argument silently sets the language to Plain Text instead of the requested language.

## Best solution

In ChangeLanguageAction.run in src/vs/workbench/browser/parts/editor/editorStatus.ts, when `languageMode` is a string, resolve it to a real language id (checking both `isRegisteredLanguageId` and `getLanguageIdByLanguageName`) and populate `pick.id` accordingly, instead of only setting `label`.
