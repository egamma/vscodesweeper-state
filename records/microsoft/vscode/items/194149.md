# Issue #194149 — Make terminal tab toolbar configurable

[https://github.com/microsoft/vscode/issues/194149](https://github.com/microsoft/vscode/issues/194149)

## Summary

The terminal tab list still lacks individually hideable toolbar actions, and the existing setting controls a different toolbar. Keep this accepted Backlog request open; the previous implementation attempt was closed without merging, and no verified canonical owns the same request.

## Change summary

Allow users to hide individual terminal tab toolbar buttons, especially Split, through the toolbar context menu.

## Best solution

Give terminal tab row actions the standard workbench hide-and-restore interaction demonstrated by search results, while preserving terminal selection, action targeting, and narrow-tab behavior.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts`, `src/vs/workbench/contrib/terminal/browser/terminalActions.ts`
- **Validation:** With multiple terminals and text-visible tabs, right-click a row toolbar and hide Split: its button and reserved space disappear while Kill remains usable. Restore Split through the standard toolbar interaction. Check action targeting for selected and unselected rows, row recycling, narrow layouts, and keyboard access; the plan should establish executable coverage for these interactions.
- **Behavior:**

  > Users can hide Split independently of Kill in terminal tab list toolbars, preventing accidental split clicks and freeing the corresponding toolbar space. Hidden actions can be restored through the standard workbench toolbar interaction. Remaining actions continue to affect the same terminal or selected terminals as before. The separate panel-title toolbar and its existing visibility setting retain their behavior.
- **Trace:**

  > TerminalTabsRenderer.renderTemplate in src/vs/workbench/contrib/terminal/browser/terminalTabsList.ts creates a plain ActionBar, and fillActionBar supplies ordinary Action objects rather than menu-backed hideable actions. The renderer also includes shellLaunchConfig.tabActions and uses _runForSelectionOrInstance to preserve selection-sensitive targeting and focus. WorkbenchToolBar in src/vs/platform/actions/browser/toolbar.ts requires menu-backed hideActions metadata for its hiding interaction; src/vs/workbench/contrib/search/browser/searchResultsView.ts demonstrates the row-toolbar precedent recommended in the discussion. SplitActiveTab and KillActiveTab registrations exist in terminalActions.ts, but their presence alone does not make these renderer-created buttons configurable. Preserve contributed tab actions, disposal and row-recycling behavior, selection semantics, and narrow-width suppression. https://github.com/microsoft/vscode/pull/195255 was abandoned without merging. The source establishes the missing capability, but no existing terminal tab renderer test was located; planning should establish interaction validation rather than reopen the already accepted product goal.
