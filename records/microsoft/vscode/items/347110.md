## Evidence

- **Current source confirms the defect:** extensions/git/src/git.ts:3114-3163 routes getWorktrees() directly to getWorktreesFS(). Both main and linked worktrees read filesystem HEAD, remove the 'ref: ' prefix, and derive detached solely from that prefix. Consequently, the reported 'ref: refs/heads/.invalid' placeholder produces ref 'refs/heads/.invalid' and detached false, including for a genuinely detached reftable worktree.
- **Existing reftable handling does not cover worktrees:** extensions/git/src/git.ts:2963-3004 explicitly recognizes the .invalid placeholder in getHEAD() and falls back to Git symbolic-ref or rev-parse. The independent getWorktreesFS() path does not use this handling.
- **Affected consumers:** extensions/git/src/repository.ts:1896-1917 consumes worktree.detached and worktree.ref for branch and commit metadata. extensions/git/src/commands.ts:3622 matches existing worktrees by ref, so the placeholder affects behavior beyond presentation.
