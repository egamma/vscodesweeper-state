# Issue #347110 — Reftable worktrees expose placeholder refs and incorrect detached state

[https://github.com/microsoft/vscode/issues/347110](https://github.com/microsoft/vscode/issues/347110)

## Summary

The worktree scanner still interprets reftable compatibility HEAD placeholders as real branch references, producing incorrect refs and detached state. Keep this open while the linked fixing PR is reviewed; it remains open and unmerged.

## Change summary

Report actual branch references or detached commit hashes for reftable worktrees through the built-in Git extension API.

## Evidence

- **Current source confirms the defect:** extensions/git/src/git.ts:3114–3175 routes getWorktrees() directly to getWorktreesFS(). Both main and linked worktrees read filesystem HEAD, remove the 'ref: ' prefix, and derive detached from that prefix. Given the reported 'ref: refs/heads/.invalid' placeholder, both paths necessarily return ref='refs/heads/.invalid' and detached=false without resolving the actual Git reference.
- **Existing reftable handling does not cover worktrees:** extensions/git/src/git.ts:2963–3005 detects the '.invalid' placeholder in getHEAD() and falls back to symbolic-ref or rev-parse. getWorktreesFS() independently reads HEAD files and does not use that handling.
- **Observable downstream impact:** extensions/git/src/commands.ts:253 derives the worktree description from ref and detached; commands.ts:3622 matches existing worktrees by ref. extensions/git/src/repository.ts:1903–1917 also separates attached and detached worktrees using these fields, so incorrect API state affects actual consumers.
