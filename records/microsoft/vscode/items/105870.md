# Issue #105870 — Add streaming support in vscode

[https://github.com/microsoft/vscode/issues/105870](https://github.com/microsoft/vscode/issues/105870)

## Summary

Keep open: current workspace-symbol and reference paths still wait for completed provider results, so the requested incremental language-feature experience remains missing. This team-authored Backlog request has 27 upvotes and substantial language-team demand; neither the closed predecessor nor the newer, narrower workspace-symbol report is a valid duplicate target.

## Change summary

Support LSP partial results through VS Code's language-provider APIs and navigation UI so users can act on early results before a search finishes.

## Best solution

Design an end-to-end partial-result contract and stable incremental navigation experience, starting with workspace symbols as requested by maintainers in the thread. Preserve this issue's broader references and call-hierarchy requirements rather than treating incremental completion of separate workspace-symbol providers as full streaming support.

## Plan brief

- **Likely files:** `src/vscode-dts/vscode.d.ts`, `src/vs/workbench/api/common/extHostLanguageFeatures.ts`, `src/vs/workbench/api/common/extHost.protocol.ts`, `src/vs/workbench/api/browser/mainThreadLanguageFeatures.ts`, `src/vs/workbench/contrib/search/common/search.ts`, `src/vs/workbench/contrib/search/browser/symbolsQuickAccess.ts`, `src/vs/editor/contrib/gotoSymbol/browser/goToSymbol.ts`
- **Validation:** After agreeing on the contract, use a controlled workspace-symbol provider that emits an early batch and delays its final response, alongside a second delayed provider. Verify early results are visible and actionable before either full search completes, later batches appear without changing the selected item's identity, cancellation or a changed query rejects stale batches, and existing non-streaming providers retain their final results. Include an extension-host-to-workbench integration check; a Promise.all aggregation unit test alone cannot establish end-to-end streaming.
- **Behavior:**

  > Users searching workspace symbols should be able to navigate to early matches while language servers continue computing further matches, rather than waiting for the slowest complete response. Workspace symbols are the thread's preferred first increment, not a replacement for the broader references and call-hierarchy request. Acceptance requires early actionable results, later-result delivery, reliable cancellation and query replacement, and stable user interaction while the list changes. Existing non-streaming providers must remain supported.
- **Trace:**

  > IWorkspaceSymbolProvider and the public WorkspaceSymbolProvider currently return complete arrays, with no incremental-result parameter. NavigateTypeAdapter.provideWorkspaceSymbols awaits the extension provider, and MainThreadLanguageFeatures.$registerNavigateTypeSupport awaits one RPC response before returning symbols. getWorkspaceSymbols then waits for all providers, and SymbolsQuickAccessProvider.doGetSymbolPicks only creates picks after that aggregate resolves. The reference path similarly awaits array results through getReferencesAtPosition and getLocationLinks. These source paths establish the missing capability without executing the product; upstream LSP support alone cannot make these consumers incremental. Preserve existing provider compatibility, cancellation, deduplication, lazy symbol resolution, and navigation behavior; the design must establish how those guarantees apply to partial results. https://github.com/microsoft/vscode/issues/140298 captures a narrower multi-provider symptom, while https://github.com/microsoft/vscode/issues/20010#issuecomment-277742428 documents the interaction-stability concerns that remain relevant.
- **Open decisions:**
  - What public provider contract should expose partial results while preserving existing array-returning providers and defining how partial batches relate to the final response?
  - When new matches rank above visible or selected matches, should the list reorder with viewport compensation or freeze an interacted-with region, and what interaction triggers that guarantee?
