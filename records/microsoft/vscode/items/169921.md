# Issue #169921 — Add API to reopen document with specific CustomTextEditor

[https://github.com/microsoft/vscode/issues/169921](https://github.com/microsoft/vscode/issues/169921)

## Summary

The core request — a seamless editor-switch API that preserves undo history — remains unimplemented. The recent `forceReplaceDirty` improvement (fdf2e9ad7f4) addresses the save-dialog friction but not undo-history continuity or a proper extension API surface for programmatic editor switching.

## Change summary

Request an extension API to switch a document's active editor type (e.g. from text to CustomTextEditor) without losing dirty state or undo history.

## Best solution

Expose a first-class extension API (or enhance `vscode.openWith`) that replaces the current editor for a resource in-place, preserving the text model's undo stack. The internal `reopenActiveEditorWith` command already avoids the save prompt for text-backed custom editors (as of fdf2e9ad7f4), but undo history preservation requires deeper model-sharing work in the custom-editor contribution.
