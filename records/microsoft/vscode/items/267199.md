# Issue #267199 — ERR_HTTP2_PROTOCOL_ERROR

[https://github.com/microsoft/vscode/issues/267199](https://github.com/microsoft/vscode/issues/267199)

## Summary

This is the canonical tracking issue for ERR_HTTP2_PROTOCOL_ERROR in Copilot Chat — a team member (chrmarti) has been closing duplicates into it, and there is an open internal backlog issue (microsoft/vscode-internalbacklog#5985). Multiple users confirm the problem persists, especially with Zscaler proxies and Claude/Opus models. The client-side retry delay (~10 minutes) compounds the pain. Keeping open as the active canonical issue.

## Change summary

Copilot Chat requests fail with ERR_HTTP2_PROTOCOL_ERROR, and the client takes ~10 minutes before retrying or falling back, leaving users stalled.

## Best solution

Two tracks: (1) server-side — reduce or eliminate the HTTP2 protocol errors causing RST_STREAM resets, which appear correlated with longer-running model responses (Opus/Claude); (2) client-side — shorten the retry/fallback delay in `extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts` so that ERR_HTTP2_PROTOCOL_ERROR triggers a near-immediate retry or fetcher fallback instead of the current ~10-minute wait. The internal tracking issue (microsoft/vscode-internalbacklog#5985) owns this work.
