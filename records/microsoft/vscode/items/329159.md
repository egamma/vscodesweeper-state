# Issue #329159 — new switch editor type dropdown in breadcrumbs only appears in agents window not editor

[https://github.com/microsoft/vscode/issues/329159](https://github.com/microsoft/vscode/issues/329159)

## Summary

Real bug, and it already carries a real scheduled milestone (1.135.0), so this stays open regardless — but tracing the source shows a concrete, narrow cause: the editor-type breadcrumb dropdown is wired up in one breadcrumbs creation site and missing in another.

## Change summary

The new `breadcrumbs.showEditorType` dropdown appears in the agents/sessions window's editor breadcrumbs but not in the regular editor window's breadcrumbs.

## Best solution

Add `showEditorTypePicker: true` to the `BreadcrumbsControlFactory` options passed in src/vs/workbench/browser/parts/editor/singleEditorTabsControl.ts (around the `if (!this.breadcrumbsInHeader)` block, line ~57), matching the option already passed in editorHeaderControl.ts, so the picker is available in single-tab/no-header editor layouts too.

- **missing option:** src/vs/workbench/browser/parts/editor/singleEditorTabsControl.ts:57-64 creates its own BreadcrumbsControlFactory (used only when `!breadcrumbsInHeader`, i.e. the default single-tab, no-header editor window) and never sets `showEditorTypePicker`, so `_updateEditorTypeControl` in breadcrumbsControl.ts:527 always treats it as disabled there.
- **consistent with report:** This explains the reporter's exact symptom (works in agents window header-based breadcrumbs, missing in the plain editor window) for a config using single-tab breadcrumbs; the CSV/image-vs-markdown discrepancy from a commenter using multi-tab mode is a separate, unresolved wrinkle (getAvailableEditorTypes in editorTypePicker.ts, which likely just has no alternate editor registered for markdown in that path).
