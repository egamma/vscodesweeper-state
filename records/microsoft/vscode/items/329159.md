# Issue #329159 — new switch editor type dropdown in breadcrumbs only appears in agents window not editor

[https://github.com/microsoft/vscode/issues/329159](https://github.com/microsoft/vscode/issues/329159)

## Summary

Milestone 1.133.0 is already assigned, which is a real scheduling milestone and a hard keep-open rule, so no close is proposed regardless of findings; the underlying report looks plausible and worth a closer look by whoever owns the fix for this milestone.

## Change summary

The new `breadcrumbs.showEditorType` dropdown (Reopen With picker in the breadcrumbs bar) shows up in the Agents window but not in the regular editor window for the same markdown file.

## Best solution

Have the assignee for 1.133.0 confirm root cause before landing a fix: `src/vs/workbench/browser/parts/editor/singleEditorTabsControl.ts` never passes `showEditorTypePicker: true` to `BreadcrumbsControlFactory` (only `editorHeaderControl.ts` does, and by design per the comment on `IBreadcrumbsControlOptions.showEditorTypePicker` in breadcrumbsControl.ts, which says it's only meant for the below-tabs bar, not single-tab breadcrumbs). Separately, `src/vs/sessions/browser/parts/singlePaneEditorPart.ts` force-enables `showTabs: 'multiple'` for the Agents window regardless of the user's `workbench.editor.showTabs` setting, and the dropdown itself only renders when `editorResolverService.getEditors(resource)` returns more than one entry (`editorTypePicker.ts`) — so the discrepancy could be either a real gap in single-tab mode or simply that the Agents window happens to register/see more than one editor for the resource while the main window doesn't. Either way, the fix belongs in the breadcrumbs/editor-header code paths named above.

## Evidence

- **single-tab breadcrumbs omit the picker by design:** src/vs/workbench/browser/parts/editor/singleEditorTabsControl.ts:57-64 creates its BreadcrumbsControlFactory without `showEditorTypePicker`, while src/vs/workbench/browser/parts/editor/editorHeaderControl.ts:64-71 sets `showEditorTypePicker: true`; the option's doc comment in breadcrumbsControl.ts:225-230 states it's 'Only makes sense for the dedicated breadcrumbs bar below tabs, not the inline single-tab breadcrumbs.'
- **Agents window forces multi-tab mode:** src/vs/sessions/browser/parts/singlePaneEditorPart.ts:89-90: 'The docked tab bar always shows multiple tabs, ignoring `workbench.editor.showTabs` (single/none)' — `this._register(this.enforcePartOptions({ showTabs: 'multiple' }));`
- **dropdown requires >1 registered editor for the resource:** src/vs/workbench/browser/parts/editor/editorTypePicker.ts getAvailableEditorTypes() returns undefined when `editorResolverService.getEditors(resource).length <= 1`, so the picker is invisible whenever only the default text editor is registered for the file — this could also explain a window-specific difference if the two windows see different registered editors for the same resource.
- **default showTabs is 'multiple' in both windows:** src/vs/workbench/browser/parts/editor/editor.ts:32-33 sets DEFAULT_EDITOR_PART_OPTIONS.showTabs = 'multiple', matching what the Agents window enforces, so a simple showTabs mismatch alone likely isn't the full explanation and needs live verification.
