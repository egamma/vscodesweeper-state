# Issue #171137 — Terminal - vscode.dev - remote tunnels - No shell integration in default terminal that is opened

[https://github.com/microsoft/vscode/issues/171137](https://github.com/microsoft/vscode/issues/171137)

## Summary

Valid bug — no fix referencing this issue found on main. The default terminal opened when connecting to a remote tunnel via vscode.dev lacks shell integration (quick fixes, command detection) because it was started before the web client attached. A newly opened terminal works fine. Keeping open as a real gap in the reconnection flow.

## Change summary

The initial terminal opened automatically when connecting to a remote tunnel via vscode.dev does not have shell integration, while a second manually opened terminal does.

## Best solution

The terminal reconnection path in `src/vs/workbench/contrib/terminal/browser/remoteTerminalBackend.ts` and the pty host need to ensure shell integration scripts are injected (or re-injected) for persisted/reconnected terminal processes, not just newly created ones. The `forceShellIntegration` propagation fix (commit 8bba0669d95) addressed a related but distinct issue. The remaining gap is likely in how reconnected terminals skip the shell integration injection that new terminals receive.
