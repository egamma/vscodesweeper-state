# Issue #348208 — Agent-host Copilot sessions add `Co-authored-by: Copilot` by default: silently introduced `chat.agentHost.copilot.includeCoAuthoredBy` defaults to on, overriding `git.addAICoAuthor: off`

[https://github.com/microsoft/vscode/issues/348208](https://github.com/microsoft/vscode/issues/348208)

## Summary

Keep open for an agent-host attribution product decision. Current source deliberately preserves default-on attribution independently of the Git UI setting; the existing opt-out does not satisfy the requested default, consent, and unified-setting behavior.

## Change summary

Make agent-created commit attribution opt-in, respect existing attribution preferences, and document consistent behavior across session lifecycles and subagents.

## Best solution

Establish a consistent consent and opt-out contract for Git UI and agent-host commits, with discoverable documentation and runtime-supported subagent inheritance. Resolve setting precedence and compatibility with maintainers before implementation.

- **Behavior:**

- **Trace:**

  > chat.shared.contribution.ts registers the application-scoped agent-host setting with default true, and copilotCliConfig.ts repeats that default in the host schema. copilotSessionLauncher.ts forwards its root-config value directly as SDK coauthorEnabled, whereas Repository.appendAICoAuthorTrailer in extensions/git/src/repository.ts separately observes git.addAICoAuthor and chat.disableAIFeatures. The existing launcher test establishes option forwarding, not final commit metadata or consent. https://github.com/microsoft/vscode/pull/339437 explicitly deferred the default and consent product decisions, documents shared-host configuration scope, and identifies subagent inheritance as runtime-owned work at https://github.com/github/copilot-cli/issues/4576. Preserve the distinction between host-owned preferences and runtime enforcement; do not assume changing a host default proves subagent behavior or retroactively updates running sessions. The uncertainty starts at the cross-path preference and consent contract, not at how to forward the existing SDK option.
- **Open decisions:**
  - Should git.addAICoAuthor become authoritative for agent-host commits, and how should its resource-scoped values interact with the application-scoped setting shared by connected host clients?

  - What constitutes attribution consent for agent-host sessions, and should changing the preference affect running sessions immediately or only on creation and resume?
