# Issue #11838 — Trigger language auto detection mechanism

[https://github.com/microsoft/vscode/issues/11838](https://github.com/microsoft/vscode/issues/11838)

## Summary

The user-facing detection flow now exists, but extensions still lack a silent API that returns the detected language. The issue remains the canonical API request and is already routed to the appropriate areas.

## Change summary

Expose an extension API for detecting a document's language from its content.

## Best solution

Expose a non-UI `vscode.languages` API backed by `ILanguageDetectionService.detectLanguage` that returns the detected language ID and optionally accepts supported languages. Extensions can then apply it through `languages.setTextDocumentLanguage` without invoking an active-editor command or producing notifications.

## Evidence

- **remaining API gap:** Current main exposes `languages.setTextDocumentLanguage` in src/vscode-dts/vscode.d.ts, but exposes no corresponding content-detection API.
- **internal capability:** src/vs/workbench/services/languageDetection/browser/languageDetectionWorkerServiceImpl.ts implements `detectLanguage(resource, supportedLangs)`, showing that the requested operation already exists internally.
- **UI-only workaround:** src/vs/workbench/contrib/languageDetection/browser/languageDetection.contribution.ts registers `editor.detectLanguage` for the active editor and displays an “Unable to detect editor language” warning on failure; it does not provide a silent result-oriented extension API.
- **partial implementation:** Automatic editor detection landed in https://github.com/microsoft/vscode/commit/8f88009816c7dfa8f3a4d3f711429360ada7efa3, and `workbench.editor.languageDetection` now defaults to true, covering the user-facing paste scenario but not extension-controlled detection.
- **canonical status:** The related https://github.com/microsoft/vscode/issues/58933 explicitly points to this issue for language detection, while https://github.com/microsoft/vscode/issues/80303 concerns extension-provided language-selection rules rather than invoking VS Code's detector.
