# Issue #189802 — [json] validation not working for a large enough number

[https://github.com/microsoft/vscode/issues/189802](https://github.com/microsoft/vscode/issues/189802)

## Summary

The precision gap remains in the JSON language service used by current main. Large numeric literals are converted to JavaScript numbers before `multipleOf` validation, so the fractional portion can disappear and an invalid value can be accepted.

## Change summary

JSON Schema `multipleOf` validation silently accepts sufficiently large decimal values after JavaScript numeric precision is exhausted.

## Best solution

Fix the numeric parsing and validation behavior in `microsoft/vscode-json-languageservice`, either by retaining the source lexeme for precision-sensitive checks or by diagnosing values that cannot be represented precisely. VS Code should then consume the corrected language-service release.

## Evidence

- **VS Code delegation:** `extensions/json-language-features/server/src/jsonServer.ts` creates `vscode-json-languageservice` and returns `languageService.doValidation(...)`; `extensions/json-language-features/server/package.json` currently depends on `vscode-json-languageservice` 6.0.0-next.4.
- **upstream root cause:** Current https://github.com/microsoft/vscode-json-languageservice/blob/main/src/parser/jsonParser.ts parses each numeric token with `JSON.parse(tokenValue)` into a JavaScript `number`; `_validateNumberNode` then performs `multipleOf` arithmetic on that already-rounded value. For `1234567890123456.001`, the fractional component is lost before validation.
- **current validation gap:** The upstream `multipleOf` tests cover ordinary floats and scientific notation but not numeric literals beyond JavaScript's precise representation range, and current upstream history contains no later precision fix.
- **canonical search:** No older open issue with the same observable large-number validation symptom was found. https://github.com/microsoft/vscode/issues/125422 concerns configuration-service handling of invalid settings and does not own this defect.
