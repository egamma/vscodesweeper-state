## Change summary

Extension authors want to toggle (focus/unfocus and close) their contributed view container or panel, via a `<panel>.toggle` command or lower-level APIs for locating a panel's container and focus history.

## Plan brief

- **Likely files:** `src/vs/workbench/browser/parts/views/viewPaneContainer.ts`, `src/vs/workbench/browser/parts/panel/panelActions.ts`, `src/vs/workbench/services/views/browser/viewsService.ts`
- **Validation:** A viewsService test asserting that toggling a focused contributed view container closes it (or returns focus to the previous container) and that toggling an unfocused one opens and focuses it.
- **Behavior:**

  > Running the toggle for a contributed view container opens and focuses it when it is not focused. When it is focused, it closes the container or restores focus to the previous one in that location. Existing `<container>.focus` commands are unchanged.
- **Trace:**

  > Contributed view containers get an auto-registered `<id>.focus` command, but no toggle counterpart. The relevant code is in the views service and the view-container registration in src/vs/workbench/services/views/browser/viewsService.ts and src/vs/workbench/browser/parts/views/. This trace is not completed: it does not establish where the container-location and history state lives. The boundary is that the existing focus command semantics must not change.
- **Open decisions:**
  - Add a built-in `<container>.toggle` command, or expose new extension API for container location and history?
  - When the focused container is toggled and there is no history, should it close the part or fall back to a default container?
