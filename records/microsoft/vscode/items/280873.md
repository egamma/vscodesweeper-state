# Issue #280873 — bad api doc continuations for rust

[https://github.com/microsoft/vscode/issues/280873](https://github.com/microsoft/vscode/issues/280873)

## Summary

Keep open as an accepted languages-basic feature request. Current main still continues Rust documentation comments with `//` rather than preserving `///`, and the maintainer applied `feature-request` and the Backlog milestone after discussing extension ownership.

## Change summary

Continue Rust `///` API documentation comments with the same documentation-comment marker when Enter is pressed.

## Best solution

Teach the built-in Rust language configuration to continue `///` as `/// ` while preserving the existing behavior for ordinary `//` comments and avoiding changes to editor-wide comment handling.

## Plan brief

- **Likely files:** `extensions/rust/language-configuration.json`
- **Validation:** Open a Rust file using only the built-in language support and verify that pressing Enter within a non-empty `///` comment produces `/// `, an ordinary `//` comment still produces `// `, and non-comment lines remain unchanged.
- **Behavior:**

  > When Enter is pressed within a Rust outer documentation comment beginning with `///`, the next line should begin with `/// ` rather than `// `. Ordinary Rust `//` continuation must retain its current behavior, and unrelated text must not gain a comment prefix. Acceptance should cover both documentation and ordinary line comments using the built-in Rust language support.
- **Trace:**

  > The built-in configuration at extensions/rust/language-configuration.json defines only a generic `onEnterRules` entry with `appendText: "// "`, which explains the reported result on current main. The analogous C# configuration at extensions/csharp/language-configuration.json already distinguishes `///` documentation comments from ordinary `//` comments. Keep the scope within built-in Rust language configuration; do not change editor-wide Enter handling or behavior supplied by external Rust extensions. The issue was deliberately classified as `feature-request`, `languages-basic`, and Backlog after the maintainer discussed the external-extension distinction.

## Evidence

- **current source:** extensions/rust/language-configuration.json:76-86 has one `onEnterRules` entry whose static `appendText` is `// `, so a matched `///` line cannot retain its documentation-comment marker.
- **existing precedent:** extensions/csharp/language-configuration.json:103-121 places a documentation-comment-specific `///` continuation rule before the generic `//` rule, demonstrating an established built-in configuration pattern.
