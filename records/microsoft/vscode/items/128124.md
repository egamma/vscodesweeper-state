# Issue #128124 — [FR] `editor.emmet.action.updateTag` fragment support

[https://github.com/microsoft/vscode/issues/128124](https://github.com/microsoft/vscode/issues/128124)

## Summary

The requested JSX/TSX fragment conversion is still missing: Update Tag explicitly rejects empty prompt input and retains a fragment-support TODO. Keep this accepted On Deck request open; the maintainer discussion identifies attribute removal and updating existing fragments as additional requirements.

## Change summary

Allow Emmet Update Tag to convert JSX/TSX elements into shorthand fragments by accepting an empty tag name.

## Best solution

Support valid JSX/TSX fragment conversion without leaving attributes behind, and allow existing fragments to be renamed back to elements. Preserve cancellation and ordinary HTML tag-renaming behavior.

- **Behavior:**

  > In JSX and TSX, accepting an empty name in Emmet Update Tag should convert the selected element into a valid shorthand fragment while preserving its children. Attributes must not remain on the fragment, and cancelling the prompt must leave the document unchanged. Existing fragments should also be usable as Update Tag targets. Ordinary named-tag updates and HTML behavior must remain unchanged.
- **Trace:**

  > extensions/emmet/src/updateTag.ts explicitly rejects empty showInputBox results and retains a JSX/TSX fragment TODO; getRangesFromNode edits tag names only, so accepting an empty string alone cannot handle attributes. The public command in extensions/emmet/src/emmetCommon.ts also treats an empty argument as absent. Target discovery runs through getHtmlFlatNode in extensions/emmet/src/util.ts and getRootNode in extensions/emmet/src/parseDocument.ts, which delegates to @emmetio/html-matcher; current fragment-node discovery was not established by this review. The maintainer discussion at https://github.com/microsoft/vscode/issues/128124 confirms both attribute and existing-fragment concerns. Plan around those boundaries and the existing extension-host tests in extensions/emmet/src/test/tagActions.test.ts; do not broaden this into HTML fragment support, general abbreviation updates, or syntax-highlighting changes.

## Evidence

- **Current command rejects empty input:** extensions/emmet/src/updateTag.ts: updateTag awaits showInputBox, then returns false for !tagName, treating an accepted empty string like cancellation. The adjacent TODO explicitly says 'Accept fragments for JSX and TSX'.
- **Command arguments do not provide an escape hatch:** extensions/emmet/src/emmetCommon.ts: the editor.emmet.action.updateTag registration forwards only truthy string arguments; an empty string instead opens the prompt. extensions/emmet/package.json registers this command but exposes no fragment-specific alternative.
- **Conversion requires more than accepting empty input:** extensions/emmet/src/updateTag.ts: getRangesFromNode selects only the opening tag's name and the closing tag's name. Applying an empty replacement directly to an attributed element would retain the opening attributes rather than produce a valid shorthand fragment.
- **Maintainer investigation and language boundary:** The supplied discussion at https://github.com/microsoft/vscode/issues/128124 distinguishes valid JSX/TSX fragments from invalid HTML syntax. The maintainer's 2021-10-06 comment reports that allowing an empty name still leaves attributes behind and cannot update existing fragment tags; this is an acknowledged capability gap, not grounds for a decline close.
- **Existing related command is not equivalent:** extensions/emmet/src/removeTag.ts deletes the surrounding tags and can reindent their contents. It does not retain the fragment wrapper requested here, so editor.emmet.action.removeTag does not satisfy the central ask.
- **Parser and validation boundary:** extensions/emmet/src/parseDocument.ts: getRootNode delegates markup parsing to @emmetio/html-matcher; updateTag locates targets through getHtmlFlatNode in extensions/emmet/src/util.ts. Existing tests in extensions/emmet/src/test/tagActions.test.ts cover named HTML tags, multiple cursors, whole-node selections, and templates, but contain no fragment cases. No execution was performed in the read-only checkout.
- **Canonical and implementation search:** GitHub searches for Emmet fragments, updateTag, and JSX renaming found no verified older open canonical covering fragment conversion and no open PR referencing this issue. https://github.com/microsoft/vscode/issues/139331 is open but newer and concerns abbreviation input such as #test, not fragments; it does not meet the re-review duplicate bar.
