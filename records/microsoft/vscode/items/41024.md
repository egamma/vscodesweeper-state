# Issue #41024 — macOS: alt+i always inserts '^' character

[https://github.com/microsoft/vscode/issues/41024](https://github.com/microsoft/vscode/issues/41024)

## Summary

Confirmed upstream Chromium bug (issues.chromium.org/issues/41416180) that remains unresolved — macOS dead keys (Option+i, Option+n, Option+u, Option+e, Option+`) insert combining characters even when preventDefault() is called on the keydown event. The issue is correctly labeled and tracked; it should stay open until Chromium fixes the underlying platform behavior or VS Code finds a workaround.

## Change summary

On macOS, keyboard shortcuts using Option+<dead key> (e.g., Option+i, Option+n, Option+u) insert the dead key character (ˆ, ˜, ¨) in addition to or instead of triggering the bound command.

## Best solution

This remains blocked on Chromium fixing dead key handling when preventDefault() is called (chromium issue 41416180). A potential VS Code-side workaround could be a global setting similar to `terminal.integrated.macOptionIsMeta` that suppresses Option-as-dead-key behavior across the editor, but that would require significant investigation into what Electron/Chromium APIs are available. Keep tracking the upstream fix.
