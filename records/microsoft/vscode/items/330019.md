# Issue #330019 — Chat sticky scroll: No ellipsis in banner to indicate multi-line prompt

[https://github.com/microsoft/vscode/issues/330019](https://github.com/microsoft/vscode/issues/330019)

## Summary

The original sticky banner still drops subsequent prompt lines without indicating truncation. Main now defaults to a different, tree-based sticky surface, but the original banner remains selectable; no issue-referencing fix was established for this team-authored report.

## Change summary

Show an ellipsis when the sticky prompt banner omits additional lines of a multi-line prompt.

## Best solution

Keep the original banner's single-line presentation while visibly indicating omitted prompt content. Evaluate the newer tree-based surface separately rather than treating its adoption as proof that the retained banner is fixed.

A prompt such as 'First line\nSecond line' therefore becomes 'First line' without any continuation indicator.
- **Banner rendering path:** PromptTimelineModel._requestPreview and _recompute store that shortened text; activePrompt passes it through PromptTimelineWidgetContrib._createStickyHeader to PromptTimelineStickyHeader.update. The header renders the supplied text unchanged. promptTimeline/media/promptTimeline.css:182-187 adds text-overflow: ellipsis only for horizontal overflow, which cannot indicate lines already removed by the model.
- **Current surface boundary:** src/vs/workbench/contrib/chat/browser/chat.shared.contribution.ts:677-682 defaults ExperimentalStickyScrollEnabled to true. promptTimelineWidgetContrib.ts:isStickyPromptHeaderShown retains the original banner when that experimental option is false and chat.stickyScroll.enabled is true. The source-confirmed defect concerns this retained banner, not a claim that the default tree-based surface reproduces identically.
