# Issue #340493 — Copilot Agent Host does not appear to respect the selected GitHub account when multiple accounts are signed in

[https://github.com/microsoft/vscode/issues/340493](https://github.com/microsoft/vscode/issues/340493)

## Summary

Thanks for the detailed report. Agent Host session resolution in agentHostAuth.ts has no hook for the Copilot extension's account preference and takes the first eligible GitHub session, which matches the suspected cause. A second user's logs show the same trigger: with 5 stored sessions the picker resolved zero models. Keeping open; the main open question is how the Agent Host should honor the extension account preference.

## Change summary

With multiple GitHub accounts signed in, the Agent Host model picker uses a different account than the one chosen in the Copilot extension account preferences.

## Best solution

Make Agent Host GitHub token resolution use the account the user selected for Copilot, via the extension account preference or a shared selection mechanism, and fall back to the first eligible session only when no preference exists.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/agentSessions/agentHost/agentHostAuth.ts`
- **Validation:** A unit test in the agentHostAuth tests with two GitHub sessions and a stored account preference, asserting the preferred session's token is used.
- **Behavior:**

  > With two GitHub accounts signed in and one selected for Copilot in Manage Extension Account Preferences, the Agent Host authenticates and lists models for that account. The picker should match the account the Copilot extension uses. With no preference, behavior is unchanged.
- **Trace:**

  > agentHostAuth.ts resolves GitHub sessions with getSessions and selects the first candidate or best scope superset. It never consults the Copilot extension account preference, and the preference lookup that exists is MCP-only. The preference is keyed by extension ID in the authentication extension service. Not yet established: whether any other path pushes a token to the Agent Host. A second report shows zero models resolved with 5 stored sessions, so multi-session handling may have a further failure mode.
- **Open decisions:**
  - Should the Agent Host honor the Copilot extension's account preference, or have its own account selection UI?
  - When the preferred account has no valid session, should the Agent Host fall back to another account or show an error?
