# Issue #332077 — Defensive sanitizer output appears to trigger repeated cyber_policy false positives in Agent mode

[https://github.com/microsoft/vscode/issues/332077](https://github.com/microsoft/vscode/issues/332077)

## Summary

Real, traceable gap in the Copilot Chat client's handling of 422 cyber_policy rejections — the underlying over-classification is an upstream model-provider policy call VS Code can't fix, but the client-side diagnostics and retry behavior are in this repo's code and worth improving.

## Change summary

A benign ASan/UBSan diagnostic transcript in Agent mode repeatedly trips the model provider's cyber_policy filter (HTTP 422), and the client retries the unchanged, already-rejected payload multiple times without surfacing the specific error code or request ID.

## Best solution

In extensions/copilot/src/extension/prompt/node/chatMLFetcher.ts, the generic `response.status === 422` handler (around line 1736) should retain the parsed `jsonData` (code/message) as structured `data`, the way the 402/429 handlers already do, so the specific `cyber_policy` code and request ID can reach the UI instead of being buried in a raw text blob; separately, Agent mode's auto-continue should avoid blindly resubmitting an unchanged, already-filtered payload.

## Evidence

This means the `cyber_policy` code and request ID aren't carried as structured data for this path.
- **downstream mapping:** processFailedResponse (line 2089) turns `ChatFailKind.ContentFilter` into `ChatFetchResponseType.PromptFiltered` without forwarding any capiError/code, consistent with the reporter's observation that the specific code isn't surfaced distinctly.
- **retry path not confirmed:** The auto-retry-with-augmented-message logic (`FilteredRetry`, enableRetryOnFilter) only fires for response-level content filtering (finish_reason === ContentFilter, line 1912), not for this prompt-level 422 path — so the reported repeated auto-resubmission of an unchanged payload likely originates in Agent mode's orchestration/auto-continue logic outside this file, which I could not trace with equal confidence.
