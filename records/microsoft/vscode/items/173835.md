# Issue #173835 — Dragging view container with hidden views into another view container makes all visible

[https://github.com/microsoft/vscode/issues/173835](https://github.com/microsoft/vscode/issues/173835)

## Summary

This remains source-reproducible on current main: merging a dragged view container explicitly moves every view and defaults the batch to expanded and visible, including views hidden in the source container.

## Change summary

Dragging a view container into another container makes all of the source container's hidden views visible.

## Best solution

Preserve each moved view's visibility when merging containers, while keeping the existing behavior for explicitly moving an individual view, and cover the full-container drag case with a view descriptor service regression test.

- **Behavior:**

  > When a user drags one view container onto another, all views move but each view retains whether it was visible or hidden in the source container. - **Trace:**

  > The composite-drop handler in src/vs/workbench/browser/parts/views/viewPaneContainer.ts obtains `allViewDescriptors`, so both visible and hidden views enter the move. It invokes `IViewDescriptorService.moveViewsToContainer` without a visibility argument. In src/vs/workbench/services/views/browser/viewDescriptorService.ts, `moveViewsWithoutSaving` therefore uses `ViewVisibilityState.Expand`, and `addViews` writes every moved descriptor as visible and expanded. The existing `storage change move views and retain visibility state` test covers storage-driven moves, not this direct full-container move. Keep the boundary to preserving per-view state during an existing container merge; do not alter drop-target semantics tracked by https://github.com/microsoft/vscode/issues/232232.
