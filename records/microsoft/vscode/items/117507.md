# Issue #117507 — Add json schema for emmet snippets file

[https://github.com/microsoft/vscode/issues/117507](https://github.com/microsoft/vscode/issues/117507)

## Summary

Keep open: the built-in Emmet extension still lacks a schema contribution for custom snippets files. Existing snippet loading and ordinary user-snippet schemas do not provide the requested editing assistance, and no verified open canonical was found.

## Change summary

Provide JSON-schema-based IntelliSense and validation while editing custom Emmet snippets files.

## Best solution

Provide schema-backed editing assistance for Emmet's supported custom-snippet format without applying that format to unrelated snippets.json files. Establish the supported schema contract and association scope before implementation.

- **Behavior:**

  > Editing an Emmet custom-snippets file should offer structural IntelliSense and identify invalid configuration using a JSON schema. Supported custom snippets must remain valid and continue expanding normally. Acceptance should cover markup and stylesheet definitions, malformed entries, and isolation from ordinary VS Code snippet files and unrelated files with the same basename.
- **Trace:**

  > extensions/emmet/package.json exposes emmet.extensionsPath but contains no jsonValidation contribution. updateEmmetExtensionsPath in extensions/emmet/src/util.ts hands configured locations to @vscode/emmet-helper; extensions/emmet/src/emmetCommon.ts refreshes those definitions when snippets*.json is saved. Ordinary snippet-schema associations in extensions/configuration-editing/package.json describe a different format and do not satisfy this request. https://github.com/microsoft/vscode/issues/53499#issuecomment-414461970 records maintainer interest, while https://github.com/microsoft/vscode/issues/53499#issuecomment-708531904 identifies format stability as a concern. The trace establishes the missing extension contribution, but not the helper's complete current accepted grammar or the intended association contract. Preserve snippet expansion, existing save-to-refresh behavior, and ordinary user-snippet semantics.
- **Open decisions:**
  - Should schema assistance attach automatically only to files loaded through emmet.extensionsPath, or also be available through explicit schema selection for Emmet snippet files outside those locations?
  - Should validation strictly describe a documented supported format, or tolerate legacy and unknown fields accepted by the helper for compatibility?

## Evidence
