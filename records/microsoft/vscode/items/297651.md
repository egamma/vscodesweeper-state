# Issue #297651 — [FEATURE REQUEST]: Include Copilot Chat Tools in Settings Sync

[https://github.com/microsoft/vscode/issues/297651](https://github.com/microsoft/vscode/issues/297651)

## Summary

The requested capability remains absent on current main: global Chat tool selections are machine-local, and Settings Sync has no dedicated Chat Tools category. Keep the request open for product and synchronization design under the community feature-request process.

## Change summary

Add a Settings Sync category that synchronizes the globally enabled and disabled Copilot Chat tools across devices.

## Best solution

Provide an independently selectable Chat Tools sync resource that round-trips global tool and tool-set enablement while leaving session-only selections and custom-agent-owned tool declarations unchanged.

- **Reason:** Synchronizing Chat configuration across devices supports both AI-assisted development and settings fidelity without adding an always-visible workbench surface.

- **Behavior:**

  > Settings Sync offers a separately selectable Chat Tools category. When enabled, globally configured tool and tool-set enablement follows the user across devices; when disabled, those choices remain local. Session-only selections are never synchronized, and tool declarations owned by custom agents continue to use their existing prompt/customization synchronization path.
- **Trace:**

  > Global selections flow through `ChatSelectedTools` in src/vs/workbench/contrib/chat/browser/widget/input/chatSelectedTools.ts and are persisted under `chat/selectedTools` as machine-targeted profile state. `GlobalStateSynchroniser` in src/vs/platform/userDataSync/common/globalStateSync.ts serializes only user-targeted storage, while `getConfigureSyncQuickPickItems` in src/vs/workbench/contrib/userDataSync/browser/userDataSync.ts has no Chat Tools entry. Existing dedicated `SyncResource.Mcp` and `SyncResource.Prompts` paths provide neighboring synchronization patterns, but neither carries global tool enablement. The boundary is global enablement state only: do not synchronize per-session overrides or duplicate custom-agent tool declarations.
