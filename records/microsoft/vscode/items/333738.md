# Issue #333738 — Agent window: Claude account with a keychain `claude login` reads as "not set up" (1.135, macOS)

[https://github.com/microsoft/vscode/issues/333738](https://github.com/microsoft/vscode/issues/333738)

## Summary

Confirmed on current main: `isClaudeAccountSetUp` in `src/vs/platform/agentHost/node/claude/claudeTransportMode.ts` only treats an account as set up when `apiProvider` is a non-`firstParty` value or when `tokenSource`/`apiKeySource` is present, but a `claude login` keychain subscription reports `apiProvider: 'firstParty'` with neither field ever populated (per the second commenter's traced SDK response) — so it is misclassified as not set up. An open PR (#334233) already targets this exact gate, so this should stay open for review/merge rather than being auto-triaged as fixed.

## Change summary

On macOS, a Claude account signed in via `claude login` (credential stored in the macOS keychain, no env/API-key credential) is reported as "not set up" by the agent host's native account check, hiding native Claude models and blocking native sessions despite an active subscription.

## Best solution

Land (or iterate on) https://github.com/microsoft/vscode/pull/334233, which proposes accepting claude.ai keychain logins in `isClaudeAccountSetUp` — the fix needs a case for a `firstParty` account with `loggedIn: true`/`authMethod: 'claude.ai'` and no token/apiKey fields, in `src/vs/platform/agentHost/node/claude/claudeTransportMode.ts`, with coverage added to `claudeTransportMode.test.ts`.
