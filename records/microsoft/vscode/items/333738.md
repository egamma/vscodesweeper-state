# Issue #333738 — Agent window: Claude account with a keychain `claude login` reads as "not set up" (1.135, macOS)

[https://github.com/microsoft/vscode/issues/333738](https://github.com/microsoft/vscode/issues/333738)

## Summary

Well-diagnosed, fresh report: on macOS, a keychain-backed `claude login` credential isn't surfacing through the native model-enumeration query's `accountInfo()`, so `isClaudeAccountSetUp` correctly computes `false` from the inputs it's given — but those inputs (`tokenSource`/`apiKeySource` both fully absent, not `'none'`) suggest the SDK subprocess isn't reaching keychain resolution at all rather than resolving it and finding nothing.

## Change summary

A subscription Claude account signed in via `claude login` (macOS keychain credential) is reported as not set up in the Agents window, hiding native Anthropic models even though the CLI itself sees the login.

## Best solution

Needs a maintainer/SDK-side investigation into why the throwaway enumeration query (claudeAgent.ts:_fetchNativeModels, options built by claudeSdkOptions.ts:buildModelEnumerationOptions/buildSubprocessEnv) doesn't reach macOS Keychain resolution the same way the interactive `claude` CLI does — possibly a code-signing/entitlement or subprocess-context difference between the CLI and the SDK-spawned binary. Until that's understood, `isClaudeAccountSetUp` is doing the right thing with what it's told.
