# Issue #159045 — Use edit sessions for hot exit

[https://github.com/microsoft/vscode/issues/159045](https://github.com/microsoft/vscode/issues/159045)

## Summary

Keep open: Cloud Changes can transfer working changes, but it saves editors first rather than carrying unsaved hot-exit state between environments. The request remains distinct from the existing functionality and is already correctly routed.

## Change summary

Carry unsaved editor changes from web to desktop through edit sessions without requiring them to be saved.

## Best solution

Extend Cloud Changes to preserve and restore unsaved working-copy state during environment transitions, without implicitly saving those edits. Retain the existing saved-file transfer behavior and decide the scope and activation of backup transfer before implementation.

Add edit-session tests for capture/restore of dirty state and retain existing saved-file transfer coverage; extend checks to any additional backup types approved in the plan.
- **Behavior:**

  > An unsaved edit made in a web workspace should remain available when the user continues that workspace on desktop, without requiring or implicitly performing a save. The destination should preserve the distinction between saved file contents and pending edits. Acceptance includes unchanged source filesystem contents, restored destination editor contents with unsaved state, and unchanged behavior for existing saved working-tree transfers.
- **Trace:**

  > In src/vs/workbench/contrib/editSessions/browser/editSessions.contribution.ts, the Continue Working On action calls storeEditSession(), which saves editors, enumerates SCM resources, and reads filesystem contents. Resume applies those contents through fileService.writeFile(), so neither side currently represents dirty working-copy state independently of saved files. BrowserWorkingCopyBackupService in src/vs/workbench/services/workingCopy/browser/workingCopyBackupService.ts maintains a separate workspace backup location. The cloud auto-store setting excludes web shutdown, so it does not cover automatic web hot exit either. The originating test context is https://github.com/microsoft/vscode/issues/158798. Preserve existing saved-file transfer, conflict handling, and local backup behavior; the uncertainty starts at which backup types and lifecycle events should participate in cross-environment restoration.
- **Open decisions:**
  - Should unsaved-state transfer occur only during an explicit Continue Working On transition, or also through automatic cloud-backed hot exit?
  - Should the initial capability cover only existing workspace files, or also untitled editors and non-text working copies?
  - Should unsaved-state transfer use existing Cloud Changes consent and settings, or require a separate opt-in?
