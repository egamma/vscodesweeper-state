# Issue #248384 — [MacOs] Pin projects in recent items on Mac Dock icon

[https://github.com/microsoft/vscode/issues/248384](https://github.com/microsoft/vscode/issues/248384)

## Summary

Keep open: current macOS Dock integration exposes recent projects but does not let users pin favorites. This accepted Backlog request has 30 upvotes, and the related issues do not provide a valid duplicate target.

## Change summary

Allow users to pin favorite folders or workspaces in the macOS Dock menu so they remain accessible independently of recent-history churn.

## Best solution

Provide persistent favorite-project access from the macOS Dock, retaining ordinary recent-project access. Agree on the pinning interaction and its relationship to in-app project favorites before implementation.

## Plan brief

- **Likely files:** `src/vs/platform/menubar/electron-main/menubar.ts`, `src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts`, `src/vs/platform/workspaces/common/workspaces.ts`, `src/vs/workbench/browser/actions/windowActions.ts`
- **Validation:** On macOS, pin a folder and a saved workspace, open enough other projects to exceed the ordinary Dock recent-history limit, and restart VS Code. Both favorites must remain reachable from the Dock and open the correct project; unpinning must remove their protected status while ordinary recents and New Window continue working.
- **Behavior:**

  > Users want favorite projects to remain available from the macOS Dock even after other projects displace them from recent history. Both folders and saved workspaces should reopen correctly from this surface. Acceptance should exercise history churn, application restart, and unpinning, while preserving normal recent-project and New Window behavior. The later request for a Recent Projects submenu is relevant presentation input, but a recent-only submenu would not satisfy the original pinning goal.
- **Trace:**

  > The custom Dock menu in src/vs/platform/menubar/electron-main/menubar.ts currently contains only New Window. WorkspacesHistoryMainService.updateMacOSRecentDocuments in src/vs/platform/workspaces/electron-main/workspacesHistoryMainService.ts separately rebuilds the native recent-document list from local existing paths with seven-workspace and ten-total-entry caps. The inspected recent-history contracts and serialization in src/vs/platform/workspaces/common/workspaces.ts have no pin state; OpenRecentAction in src/vs/workbench/browser/actions/windowActions.ts supplies in-app recent navigation rather than Dock favorites. The gap is established by read-only source inspection, not runtime testing; macOS interaction feasibility remains to be evaluated. Preserve existing native recents and Windows Jump List behavior, and do not expand this request into remote-workspace parity without agreement. Coordinate any shared favorites contract with https://github.com/microsoft/vscode/issues/163509; https://github.com/microsoft/vscode/issues/324487 tracks a distinct Dock recent-workspace capability.
- **Open decisions:**
  - Where should users pin and unpin projects: within the Dock menu, through an in-app control, or both?
  - Should pinned projects be Dock-specific favorites or share one favorites state with File: Open Recent and other in-app project surfaces?
