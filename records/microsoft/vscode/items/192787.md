# Issue #192787 — Output channel names are not being localized on the remote side

[https://github.com/microsoft/vscode/issues/192787](https://github.com/microsoft/vscode/issues/192787)

## Summary

Remote-generated channel names still inherit English localization, while the renderer localizes only the remote suffix. Keep this with l10n-platform; the separate webworker fix does not resolve the remote pty-host path.

## Change summary

Display built-in remote output channel names in the client's configured language instead of mixing English names with localized remote suffixes.

## Best solution

Make built-in remote log-channel labels respect the viewing client's locale without changing shared-server behavior or extension-provided names. Investigate the localization boundary between server bootstrap, pty-host logger creation, and workbench log-channel registration.

## Plan brief

- **Likely files:** `src/server-main.ts`, `src/bootstrap-esm.ts`, `src/vs/platform/terminal/node/nodePtyHostStarter.ts`, `src/vs/platform/terminal/node/ptyHostMain.ts`, `src/vs/workbench/contrib/logs/common/logs.contribution.ts`, `src/vs/server/node/serverServices.ts`
- **Validation:** Use a packaged build with a non-English language pack, connect to a remote workspace, create a terminal, and inspect the Output channel selector: the remote Pty Host base name and remote suffix must use the client language. Compare local and remote labels, repeat after reconnect, and check two clients with different locales connected to the same server. Inventory and check any remaining remote request/server channel labels; preserve extension-provided names.
- **Behavior:**

  > A client using a non-English display language currently receives an English remote Pty Host channel name even though the remote suffix can be translated. Built-in remote channel names should follow the viewing client's display language consistently. Acceptance includes opening a remote terminal, inspecting its Output channel label, and retaining correct localization after reconnect. Clients with different display languages must not change one another's labels, and extension-provided channel names must remain unchanged.
- **Trace:**

  > src/server-main.ts initializes the server's NLS configuration as English, and NodePtyHostStarter.start in src/vs/platform/terminal/node/nodePtyHostStarter.ts launches its child through an IPC Client that inherits the server environment. src/bootstrap-esm.ts loads that NLS configuration before src/vs/platform/terminal/node/ptyHostMain.ts creates the localized ptyhost logger name. registerLogChannel in src/vs/workbench/contrib/logs/common/logs.contribution.ts preserves the received name and translates only the remote suffix. By contrast, buildUserEnvironment in src/vs/server/node/extensionHostConnection.ts receives the client's language and installs a corresponding NLS configuration. The source confirms the pty-host path, but the full set of affected server-created channels and the safe boundary for shared-server localization have not been established. Preserve shared-process semantics, logger identity, log contents, and extension-provided names; the webworker-only resolution in https://github.com/microsoft/vscode/issues/192808 does not cover this path.
