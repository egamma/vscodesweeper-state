# Issue #325539 — Extend `chat.tools.terminal.autoApprove` to deny tool calls

[https://github.com/microsoft/vscode/issues/325539](https://github.com/microsoft/vscode/issues/325539)

## Summary

The same automatic-denial-and-steering configuration was previously declined by the terminal maintainer. Propose closing consistently with that decision, rather than treating this as a duplicate of an open issue.

## Change summary

Allow terminal command rules to automatically reject tool calls and optionally return a steering message to the agent.

## Best solution

Keep chat.tools.terminal.autoApprove focused on whether commands require confirmation, consistent with the decision in https://github.com/microsoft/vscode/issues/282798. Agent instructions provide preferred-command guidance; existing PreToolUse hooks offer programmatic denial with a reason without extending this setting.

- **Proposed comment:**

  > Thanks for the request. Automatic command denial with a steering message was considered in https://github.com/microsoft/vscode/issues/282798 and declined in favor of agent instructions rather than another configuration mechanism. Following that decision, this extension of `chat.tools.terminal.autoApprove` is out of scope; its `false` rules require confirmation rather than reject execution. For programmatic rejection with an explanatory message, existing `PreToolUse` hooks support a `deny` decision and `permissionDecisionReason`.
