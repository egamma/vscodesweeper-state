# Issue #277562 — Add Null State for User Generated Custom Agent Drop Down.

[https://github.com/microsoft/vscode/issues/277562](https://github.com/microsoft/vscode/issues/277562)

## Summary

Keep open: current main still lacks an empty state for custom agents and retains the “Configure Custom Agents...” wording. This team-authored request has supporting maintainer direction, and no older same-symptom canonical or implemented fix was found.

## Change summary

Make custom agents discoverable before users create one by adding an empty state to the mode picker and renaming the management action.

## Best solution

The mode picker should explain the custom-agent capability when none exist, provide an accessible route to their management surface, and use “Manage Custom Agents” consistently while preserving normal built-in mode selection.

## Plan brief

- **Likely files:** `src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts`, `src/vs/workbench/contrib/chat/browser/promptSyntax/chatModeActions.ts`
- **Validation:** In a development window with no user-created custom agents, open the chat mode picker and verify that keyboard and screen-reader users can discover the custom-agent explanation and management route; create an agent and verify that the empty state is replaced by the selectable agent while built-in modes and policy-disabled behavior remain unchanged.
- **Behavior:**

  > When no user-created custom agents exist, the chat mode picker should make the capability discoverable and explain its purpose without implying that an agent already exists. The management action should use “Manage Custom Agents” and open the existing Agents management surface. After an agent is created, the empty state should give way to the normal selectable agent entry. The discovery content and management route must remain keyboard- and screen-reader-accessible.
- **Trace:**

  > ModePickerActionItem in src/vs/workbench/contrib/chat/browser/widget/input/modePickerActionItem.ts groups `currentChatModes` into built-in and custom actions, but currently contributes nothing for an empty custom group. Its action bar reads MenuId.ChatModePicker; src/vs/workbench/contrib/chat/browser/promptSyntax/chatModeActions.ts contributes the existing “Configure Custom Agents...” action and routes it to the Agents section of the AI Customization Management editor. Preserve built-in mode selection, target-filtered session behavior, ChatContextKeys gating, and the policy-disabled path. https://github.com/microsoft/vscode/issues/272502 and https://github.com/microsoft/vscode/issues/277547 are adjacent prompt-layout and icon work, not owners of this empty-state behavior. The uncertainty begins with whether the empty state is a disabled explanatory row plus a separate management action, an actionable create/manage row, or primarily explanatory hover content, and whether proactive prompt-based nudges belong in this issue.
- **Open decisions:**
