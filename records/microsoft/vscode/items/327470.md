# Issue #327470 — runNotebookCell a cell that generates audio takes up a lot of context

[https://github.com/microsoft/vscode/issues/327470](https://github.com/microsoft/vscode/issues/327470)

## Summary

Valid bug: the RunNotebookCellOutput component's size limit is proportional to the model's token budget, so on large-context models (like DeepSeek V4 Flash), base64-encoded audio HTML output passes the threshold and bloats context by ~80k tokens. An absolute cap or mime-type filter for non-text-meaningful content (audio, video) would prevent this.

## Change summary

Running a notebook cell that produces audio output (via `display(Audio(...))`) causes base64-encoded audio data to be fed into the LLM context, consuming ~80k+ tokens.

## Best solution

Add an absolute byte-size cap or a mime-type-aware filter in `RunNotebookCellOutput` (extensions/copilot/src/extension/tools/node/runNotebookCellTool.tsx) so that `text/html` outputs containing large base64 data URIs (audio/video) are summarized rather than passed verbatim. The fallback message 'Output is too large to be used as context' should trigger for these cases regardless of token budget.
