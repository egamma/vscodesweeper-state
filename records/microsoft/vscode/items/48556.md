# Issue #48556 — [folding] fold all but comments

[https://github.com/microsoft/vscode/issues/48556](https://github.com/microsoft/vscode/issues/48556)

## Summary

A real capability gap remains: current bulk-fold commands collapse comment ranges along with code. This issue should remain open as the older canonical; three later reports were closed in its favor, while the newer open request cannot become its canonical under the re-review rules.

## Change summary

Provide a configurable bulk-folding behavior that collapses code while leaving documentation and block comments expanded.

## Best solution

Define one consistent comment-exclusion behavior for bulk folding without duplicating every existing folding command, then apply it across the agreed Fold All and/or Fold Level commands. Preserve ordinary manual comment folding and the existing dedicated Fold All Block Comments command.

## Vision fit

- **Fit:** aligned
- **Reason:** Keeping documentation visible while collapsing implementations improves navigation in the core editor and supports the developer inner loop.
- **Evidence:** Durable themes: “Developer inner loop” and “Workbench & core UX”; the simple, uniform UI guardrail also favors one coherent mechanism over duplicating the folding command set.

## Plan brief

- **Likely files:** `src/vs/editor/contrib/folding/browser/folding.ts`, `src/vs/editor/contrib/folding/browser/foldingModel.ts`, `src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts`
- **Validation:** Extend the editor folding unit tests with typed comment and untyped language-configuration cases, asserting that the selected bulk-fold operation collapses code ranges while comment ranges stay expanded and existing ordinary Fold All behavior remains covered according to the chosen configuration.
- **Behavior:**

  > Users can invoke the agreed bulk-folding behavior and collapse code while documentation and block-comment ranges remain visible. Comments remain manually foldable, and the dedicated Fold All Block Comments command retains its existing behavior. Acceptance must cover nested code and comment ranges and at least one provider that supplies comment kinds; behavior for providers without kinds must follow the maintainer's decision.
- **Trace:**

  > On current main, FoldAllAction in src/vs/editor/contrib/folding/browser/folding.ts calls setCollapseStateLevelsDown in src/vs/editor/contrib/folding/browser/foldingModel.ts, whose filter does not inspect region types. FoldAllBlockCommentsAction already handles both typed FoldingRangeKind.Comment ranges and a language-configuration regex fallback. Existing helper coverage is in src/vs/editor/contrib/folding/test/browser/foldingModel.test.ts. Preserve manual folding, region folding, import folding, Fold All Except Selected, and the existing Fold All Block Comments command. The uncertainty starts at the public behavior: whether exclusion is a persistent option or a separate command, which bulk-fold commands honor it, and how untyped providers behave.
- **Open decisions:**
  - Should comment exclusion be a persistent editor setting that changes existing bulk-fold commands, or a separate command that leaves their current behavior unchanged?
  - Should the behavior apply only to Fold All, or also to Fold Level and other bulk-fold operations?
  - When a folding provider does not classify ranges as comments, should VS Code infer block comments from the language configuration, or limit exclusion to explicitly typed comment ranges?
