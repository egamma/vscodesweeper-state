# Issue #331580 — `cancelSelection` interferes with extension API `registerCommand("type")`

[https://github.com/microsoft/vscode/issues/331580](https://github.com/microsoft/vscode/issues/331580)

## Summary

Detailed, video-documented bug report describing a race between the built-in `cancelSelection` command and an extension's overridden `"type"` command handler; keeping open for investigation since the exact code path hasn't been traced conclusively from the checkout alone.

## Change summary

After executing `cancelSelection` via keybinding, the very next character typed sometimes bypasses the extension's `registerCommand("type", ...)` override, gets literally typed into the document, and partially deletes the prior selection.

## Best solution

Investigate whether keybinding-triggered commands (dispatched fire-and-forget via `this._commandService.executeCommand(...).then(...)` in src/vs/platform/keybinding/common/abstractKeybindingService.ts, around line 394) can race with the next keystroke's dispatch through the overwritten `Handler.Type` command (registered in src/vs/editor/browser/coreCommands.ts via `registerOverwritableCommand(Handler.Type, ...)`), so that a stale/native path types the character before the extension's override runs; the input controller paths in src/vs/editor/browser/controller/editContext/textArea/textAreaEditContext.ts and nativeEditContext.ts are the likely places the race surfaces.

## Evidence

- **reporter video + detailed steps:** Issue includes a screen recording and precise repro (select left-to-right, press a key mapped to cancelSelection, then a key mapped to cursorDown) showing partial deletion plus stray typed characters.
- **overwritable type command:** src/vs/editor/browser/coreCommands.ts calls registerOverwritableCommand(Handler.Type, ...), which lets extensions override the built-in 'type' command via CommandsRegistry — this is the API surface being interfered with.
- **fire-and-forget keybinding dispatch:** src/vs/platform/keybinding/common/abstractKeybindingService.ts (~line 394) dispatches keybinding-bound commands like cancelSelection via `this._commandService.executeCommand(...).then(undefined, err => ...)`, not awaited before the dispatch loop returns, which is consistent with the reporter's observation that a subsequent fast keystroke behaves differently than after a synchronous-feeling Escape.
- **asymmetry noted by reporter:** Reporter notes Escape (native, likely a different sync path) does not reproduce the bug, while cancelSelection (a regular editor command invoked through the extension's remapped keybinding) does — supporting a timing/race explanation tied to command dispatch rather than a simple logic bug.
