# Issue #331580 — `cancelSelection` interferes with extension API `registerCommand("type")`

[https://github.com/microsoft/vscode/issues/331580](https://github.com/microsoft/vscode/issues/331580)

## Summary

Keep open for an editor-input investigation: the report supplies sufficient steps to retest the selection-dependent interception failure. Native EditContext synchronization changed after the report, and source inspection identifies a possible alternate command path but does not establish whether the current build reproduces the defect.

## Change summary

Canceling a forward single-line selection through an overridden type command reportedly makes subsequent ordinary typing modify text instead of invoking the extension's mapping.

## Best solution

Determine whether cancelSelection leaves native input state inconsistent and causes ordinary keystrokes to be dispatched as replacement or composition input. Preserve legitimate composition behavior and distinguish a core synchronization regression from the extension's incomplete command interception before choosing a fix or documenting a workaround.

Capture type, replacePreviousChar, and compositionType dispatch to distinguish native-state corruption from missing extension interception.
- **Behavior:**

  > With vimspired mapping a to cancelSelection and j to cursorDown, canceling a forward single-line selection must not cause the next ordinary keystroke to delete or insert text unexpectedly. The reported acceptance case is a then j producing an empty selection and downward cursor movement without document changes. Reproduce on current macOS first and compare the non-failing Escape, reverse-selection, and multiline-selection cases. Legitimate IME composition and replacement input must retain their existing behavior.
- **Trace:**

  > CancelSelection in src/vs/editor/browser/coreCommands.ts changes cursor states using CursorMoveCommands.cancelSelection, which collapses at the active position without editing text. NativeEditContext._emitTypeEvent computes replacement counts and positionDelta from cached selection offsets and browser text-update events; _onType chooses compositionType when those values are nonzero. CodeEditorWidget._createView routes that branch to replacePreviousChar or compositionType rather than type. The pinned vimspired implementation intercepts only type and awaits command execution; https://github.com/microsoft/vscode/issues/102291#issuecomment-661758632 documents additional interception and serialization responsibilities. The exact native event sequence for this report remains unknown, and commit 03c51d4aaab1601681c7edc84832f32e7eb85e25 subsequently changed synchronization timing without proving a fix. Diagnose the reported ordinary-key selection case before changing either command contracts or composition handling; unrelated performance and IME behavior are outside the fix boundary.
