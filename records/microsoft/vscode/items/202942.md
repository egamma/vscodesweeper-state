Its full body supplies a C++ example where documentation-comment whitespace makes Detect Indentation from Content select four spaces instead of the code's three; removing either comment restores the correct result.
- **Same observable symptom and scope:** https://github.com/microsoft/vscode/issues/202942 reports the same detection failure, with two-space JSON inside PHP comments overriding four-space code. The canonical explicitly requests that comment indentation not determine the detected code indentation; this report supplies another instance of that work, not a distinct PHP formatting or on-type indentation defect. The canonical predates this re-reviewed item.
- **Current source path:** src/vs/editor/common/model/textModel.ts calls guessIndentation from both resolveOptions and detectIndentation. In src/vs/editor/common/model/indentationGuesser.ts, guessIndentation accepts only the text buffer and indentation defaults, examines up to 10,000 lines, and scores whitespace differences without identifying comment tokens or language. Comment lines therefore participate in the same scores as code, and two-space differences can win over four-space differences.
- **Configuration is a workaround, not a fix:** src/vs/editor/common/config/editorConfigurationSchema.ts documents that editor.detectIndentation overrides editor.tabSize and editor.insertSpaces. Disabling detection can preserve the configured four spaces, but does not address either report's request for accurate automatic detection.
