# Issue #285481 — code cli command create a new log folder each time when it launched

[https://github.com/microsoft/vscode/issues/285481](https://github.com/microsoft/vscode/issues/285481)

## Summary

The defect remains traceable on current main, and the open draft PR https://github.com/microsoft/vscode/pull/288408 already owns a targeted fix attempt. Keep the issue open while that PR is reviewed rather than competing with the existing implementation.

## Change summary

Repeated `code` CLI invocations create timestamped log directories for short-lived secondary instances, cluttering the retained logs and potentially evicting useful diagnostic folders.

## Best solution

Review and land or revise https://github.com/microsoft/vscode/pull/288408 so secondary instances do not eagerly create log directories, while preserving the maintainer-required capture of CLI launch failures and access to the primary instance's log location.

## Evidence

- **current source:** On current main, src/vs/code/electron-main/main.ts calls initServices() before claimInstance(); initServices() eagerly creates environmentMainService.logsHome, so a secondary process creates its timestamped directory before discovering the existing primary instance.
- **CLI logging path:** src/vs/code/node/cliProcessMain.ts constructs LoggerService with environmentService.logsHome and immediately creates the `cli` logger; src/vs/platform/log/common/log.ts maps that logger to cli.log under logsHome.
- **maintainer diagnosis:** https://github.com/microsoft/vscode/issues/285481#issuecomment-3717725758 confirms that the folders correspond to temporary secondary instances and identifies eager CLI logging, while requiring launch failures to remain captured.
- **independent confirmation:** https://github.com/microsoft/vscode/issues/285481#issuecomment-3707153910 reports the same symptom and traces repeated CLI launches to terminal completion invoking `code --list-extensions --show-versions`.
- **open fix PR:** https://github.com/microsoft/vscode/pull/288408 is an open draft linked with closing syntax for this issue; its patch moves logsHome directory creation until after claimInstance() succeeds.
