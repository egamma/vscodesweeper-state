# Issue #247570 — Refine alt text: Does not like to read from img.shield.io

[https://github.com/microsoft/vscode/issues/247570](https://github.com/microsoft/vscode/issues/247570)

## Summary

The shields.io failure remains source-reproducible on current main: remote SVGs bypass image attachment handling and are submitted as generic files. This team-authored, accepted bug should remain open while the SVG handling boundary is designed.

## Change summary

Refining alt text for an img.shields.io SVG badge reports that the image cannot be read and may edit the Markdown in the wrong location.

## Best solution

Make Refine Alt Text consume remote SVG badges through a safe, model-supported representation and update only the selected image's alt-text span. If the SVG cannot be processed, the action should fail explicitly without changing the document.

- **Validation:** Add a targeted attachment test using an HTTPS `.svg` response with `image/svg+xml`, then verify Refine Alt Text receives usable image data and changes only the selected Markdown alt-text span; also verify an unreadable SVG produces no document edit.
- **Behavior:**

  > Running Refine Alt Text on a Markdown image backed by a remote SVG badge must read the badge and replace only that image's existing alt text. The link destination and surrounding Markdown must remain unchanged. If the SVG cannot be processed safely, the command must report the failure without generating or applying an unrelated edit. Existing raster-image behavior must remain unchanged.
- **Trace:**

  > The Copilot command in extensions/copilot/src/extension/inlineChat/vscode-node/inlineChatCommands.ts passes the remote URI through `vscode.editorChat.start`. InlineChatController adds that URI through `ChatAttachmentModel.addFile`, whose raster-only extension check classifies `.svg` as a generic file; the shared web image extractor independently rejects `image/svg+xml`, and `CHAT_ATTACHABLE_IMAGE_MIME_TYPES` has no SVG entry. The reported shields.io endpoint still returns SVG content, so this path is source-reproducible. The placement-corruption reports https://github.com/microsoft/vscode/issues/247564 and https://github.com/microsoft/vscode/issues/253075 are related, but this issue must retain coverage of the distinct remote-SVG read failure. Do not broaden the work to arbitrary SVG execution or unrelated inline-chat editing behavior.
- **Open decisions:**
  - Should safe SVG-to-supported-image handling apply to every chat URI attachment, or only to the Generate/Refine Alt Text workflow?
  - When an SVG cannot be safely converted or read, should the alt-text action be unavailable up front or remain available and return an explicit no-edit failure?

## Evidence

- **source trace:** extensions/copilot/src/extension/inlineChat/vscode-node/inlineChatCommands.ts passes the parsed shields.io URI directly to `vscode.editorChat.start` as an attachment; src/vs/workbench/contrib/inlineChat/browser/inlineChatController.ts forwards it to `ChatAttachmentModel.addFile`.
- **unsupported SVG path:** src/vs/workbench/contrib/chat/browser/attachments/chatAttachmentModel.ts recognizes only png/jpeg/gif/bmp/webp paths as images, while src/vs/workbench/contrib/chat/common/model/chatModel.ts likewise excludes SVG from `CHAT_ATTACHABLE_IMAGE_MIME_TYPES`. The reported `.svg` URL therefore becomes a generic remote file attachment.
