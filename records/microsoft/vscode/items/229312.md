# Issue #229312 — Do not present ghost text when code is deleted or undone

[https://github.com/microsoft/vscode/issues/229312](https://github.com/microsoft/vscode/issues/229312)

## Summary

Keep open: current inline-completion behavior still permits suggestions to return after deletion or undo, and existing controls do not selectively address this editing loop. Maintainer feedback supports exploring rejection-aware suppression, but distinguishes it from intentionally restoring previously ignored suggestions.

## Change summary

Prevent automatic ghost text from restoring unwanted code after deletion, de-indentation, or undo and intercepting the next Tab intended for indentation.

## Best solution

Define rejection-aware behavior for Copilot inline completions that protects deliberate deletion and undo without removing useful suggestion recovery. Address provider-generated replacements and retained editor suggestions together; blanket suppression after every undo is not settled by the discussion.

- **Behavior:**

  > Deliberately deleting or undoing unwanted suggested text should not repeatedly restore it as an automatic suggestion that intercepts Tab intended for indentation. Cover selection deletion, Backspace while a completion is visible, and Markdown de-indentation, including fast input before a provider response arrives. The discussion also identifies intentional undo-based recovery of ignored suggestions, so acceptance must specify which recovery remains available rather than assuming every undo rejects suggestions.
- **Trace:**

  > InlineCompletionsModel in src/vs/editor/contrib/inlineCompletions/browser/model/inlineCompletionsModel.ts preserves completions for Undo/Redo and refetches on text changes. Its _didUndoInlineEdits guard covers immediate undo of accepted inline edits, not ordinary ghost-text completion or general deletion. Existing tests explicitly expect ghost text after partial-acceptance undo and retained text before a replacement after Backspace. The Copilot adapter in extensions/copilot/src/extension/completions-core/vscode-node/extension/src/vscodeInlineCompletionItemProvider.ts delegates to ghostTextProvider; GhostText.getInlineCompletions in lib/src/inlineCompletion.ts processes provider results, but the full rejection-history path was not established. The provider-side responsibility is corroborated by https://github.com/microsoft/vscode/issues/249257#issuecomment-2929943941. Preserve ordinary typing completions, explicit invocation, and agreed recovery semantics; do not conflate the suggest-widget commit-character issue with this ghost-text behavior.
- **Open decisions:**
  - Should deletion and de-indentation suppress all automatic inline suggestions, or only suggestions that restore text the user removed?
  - Which undo actions constitute rejection, and when should undo still restore a previously ignored suggestion?
  - When should automatic suggestions resume after a rejection: subsequent typing, a cursor move, or explicit invocation?
