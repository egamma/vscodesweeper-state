## Summary

Keep open for the repeated-word announcement, which the reporter attributed to Chromium without identifying its fixing commit. A later report confirms the same symptom on newer versions, so the claimed upstream fix is not sufficient evidence of resolution.

## Change summary

## Best solution

Establish whether Chromium's accessibility handling still causes the repeated speech with the current editor input implementations, and identify the upstream behavioral fix and its adoption if so. Treat automatic line-number announcements separately: the reporter withdrew that requirement, and current VS Code provides an on-demand cursor-position command.
