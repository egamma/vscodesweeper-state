# Issue #340503 — Chat sticky scroll clips messages starting with bullet points

[https://github.com/microsoft/vscode/issues/340503](https://github.com/microsoft/vscode/issues/340503)

## Summary

Confirmed in source: the sticky-scroll clamp CSS in chat.css only targets `p:first-child`, so a request whose markdown renders a list (`ul`) as its first block is never clamped and instead gets abruptly clipped by the sticky row's fixed height — matches the reporter's exact diagnosis.

## Change summary

In the Agents window, a sticky-scrolled chat request that starts with a bullet list is hard-clipped instead of being clamped to two lines with an ellipsis.

## Best solution

Generalize the sticky-row clamp selectors in chat.css (currently `> p:first-child`) to also match a leading `ul`/`ol` block, so list-first messages get the same 2-line clamp, hidden-siblings, and ellipsis treatment as paragraph-first messages.

## Evidence

- **root cause:** src/vs/workbench/contrib/chat/browser/widget/media/chat.css lines 4110-4130: the 2-line clamp (`line-clamp: 2`), the sibling-hiding rule (`p:first-child ~ *`), and the `::after` ellipsis all key off `> p:first-child` only — there is no equivalent selector for a leading `ul`/`ol`.
- **JS toggle is generic:** src/vs/workbench/contrib/chat/browser/widget/chatListRenderer.ts:2770 toggles `chat-request-has-more` based on `firstBlock.nextElementSibling` for any element type, so the JS side already works for lists — only the CSS selectors are paragraph-specific.
- **no existing fix:** No commit or related CSS change found addressing list-first sticky rows; the paragraph-only clamp predates this report (per issue, back to #296433) and the recent resize work in #340147 did not touch this selector.
