# Issue #239019 — arguments suggested for mkdir command seems to be invalid

[https://github.com/microsoft/vscode/issues/239019](https://github.com/microsoft/vscode/issues/239019)

## Summary

Keep open: current source still supplies a single mkdir spec containing implementation-specific options, matching the maintainer's acknowledged limitation. The related configurable-spec request is newer and does not establish a same-symptom canonical for this re-reviewed, team-authored item.

## Change summary

Make terminal argument suggestions reflect the options supported by the actual mkdir implementation rather than a universal spec.

## Best solution

Terminal completion specs should account for command implementation and version differences without removing valid options from environments that support them. Establish the automatic-selection versus user-configuration contract with the terminal owner, coordinating with https://github.com/microsoft/vscode/issues/240240.

## Plan brief

- **Likely files:** `extensions/terminal-suggest/src/terminalSuggestMain.ts`, `extensions/terminal-suggest/src/upstreamSpecs.ts`, `extensions/terminal-suggest/src/completions/upstream/mkdir.ts`, `extensions/terminal-suggest/src/test/completions/upstream/mkdir.test.ts`
- **Validation:** Extend the mkdir completion suite with cases representing BSD mkdir and GNU mkdir: for 'mkdir |', unsupported --context/-Z options must be absent for BSD and supported options must remain available for GNU. Verify directory suggestions remain intact and test the agreed fallback when implementation identification is unavailable.
- **Behavior:**

  > Terminal suggestions currently offer mkdir options that the user's command may reject, including --context on implementations without SELinux support. The desired outcome is implementation-appropriate argument suggestions while retaining valid options and directory completion. Acceptance should cover BSD and GNU mkdir, including different implementations on the same operating system, and explicitly define the behavior when the implementation cannot be identified.
- **Trace:**

  > extensions/terminal-suggest/src/completions/upstream/mkdir.ts defines one unconditional option list, exported by upstreamSpecs.ts and included in availableSpecs in terminalSuggestMain.ts. The completion provider passes that collection to getCompletionItemsFromSpecs; the mkdir test suite currently expects --context and -Z without implementation distinctions. The maintainer confirmed that OS checks alone do not resolve binary/version differences at https://github.com/microsoft/vscode/issues/239019#issuecomment-2648107798 and classified the work as a feature request at https://github.com/microsoft/vscode/issues/239019#issuecomment-3448227495. https://github.com/microsoft/vscode/issues/240240 tracks custom specs as a related capability, not an eligible duplicate. Preserve valid GNU options and existing directory completion; a blanket removal or macOS-only exclusion would not satisfy the full problem. The unresolved boundary is how users obtain implementation-appropriate specs and what suggestions remain when identification is inconclusive.
- **Open decisions:**
  - Should implementation-appropriate suggestions be selected automatically, selected through user configuration, or support both behaviors?
  - When the command implementation cannot be identified, should suggestions retain the current comprehensive option list or expose only a conservative common subset?
